Topic

This article applies to BIG-IP ASM 10.1.0 through 10.2.4.

F5 and WhiteHat Security provide another way for you to secure your web applications. WhiteHat Sentinel is a scanner that scans your web applications for vulnerabilities. You can configure WhiteHat Sentinel to automatically update a BIG-IP ASM security policy to protect against the specific issues that Sentinel finds.

Note: For information about configuring the WhiteHat Sentinel with BIG-IP ASM 9.4.x, refer to K9254: Integrating the WhiteHat Sentinel Scanner with BIG-IP ASM versions 9.4.5 through 9.4.8.

This solution describes the general steps you need to follow to configure and establish the connection between WhiteHat Sentinel and the BIG-IP ASM system:

Integration requirements

The BIG-IP ASM system needs to have been installed and configured according to the BIG-IP Systems: Getting Started Guide and BIG-IP ASM release notes.

To perform the integration steps, you need the following:

  • Valid BIG-IP ASM login credentials (with administrative rights)
  • Trusted BIG-IP ASM certificate on the BIG-IP system
  • Up-to-date WhiteHat Sentinel subscription and valid login credentials
  • Latest version of Adobe Flash Player (10,0,12,36 or later)
  • Up-to-date browser (Internet Explorer 7 or 8, FireFox, or Safari)

When logging into the BIG-IP ASM system, ensure that you add the BIG-IP ASM certificate to your browser.

Note: If your certificate is not fully trusted, or does not match the BIG-IP ASM name, you can open two tabs in your browser. Use one tab to log onto the BIG-IP ASM and accept the trusted BIG-IP ASM certificate. Once logged on, use the other tab to log on to your WhiteHat Sentinel account.

Setting up the BIG-IP ASM

Set up the BIG-IP ASM system first so when you log on the WhiteHat Sentinel, you can establish a connection between the two systems.

  1. Install the BIG-IP system as documented in the BIG-IP Systems: Getting Started Guide and BIG-IP ASM release notes.
  2. Log on to the BIG-IP ASM system from your web browser.
  3. Perform basic configuration of the BIG-IP ASM system as documented in the Performing Basic Configuration Tasks chapter of the BIG-IP Application Security Manager: Getting Started Guide.
  4. Click Classes and create an application security class with the name of the application you want to protect. Refer to the Performing Basic Configuration Tasks chapter of the BIG-IP Application Security Manager: Getting Started Guide.

Remain logged on to BIG-IP ASM.

Creating the WhiteHat Sentinel Baseline security policy

Next, you can use the WhiteHat Sentinel Baseline template to create a security policy in the BIG-IP ASM system that can be updated directly from WhiteHat Sentinel.

  1. In BIG-IP ASM, click Web Applications.
  2. In the list of web applications, click Configure Security Policy next to the application security class you created.
  3. For Deployment Scenario, select Manual Deployment and then click Next.
  4. For Application Language, specify the language encoding of the application.
  5. Next to Application-Ready Security Policy, select WhiteHat Sentinel Baseline.
    The security policy name changes to Whitehat-baseline_n where n is 1, 2, 3, and so on.
  6. Use the default values for the other settings and click Next.
    A Policy Configuration summary is displayed.
  7. Click Finish.

You now have a basic security policy in the BIG-IP ASM system that you can connect to from WhiteHat Sentinel.

Qualified vulnerability classes

BIG-IP ASM 10.1.0 and 10.2.0 can mitigate the following vulnerability classes:

  • Cross-site scripting
  • SQL injection
  • OS command injection
  • XPath injection
  • Predictable resource
  • Directory traversal
  • HTTP response splitting

When you run a scan in WhiteHat Sentinel and view the list of vulnerabilities, these are the ones that the BIG-IP ASM security policy can protect against. The BIG-IP ASM adds parameters, URLs, and attack signatures (on parameters or globally for HTTP response splitting) to the policy, depending on the potential vulnerability that WhiteHat Sentinel discovers.

Setting up WhiteHat Sentinel

Next, create a BIG-IP ASM account in WhiteHat Sentinel. You can add more than one BIG-IP ASM account if you need to, for example using a fully-qualified domain name (FQDN) and an IP address. In cases where the FQDN does not work, the IP address may work.

  1. Log on to WhiteHat Sentinel.
  2. Click the Account tab.
  3. Click the Manage F5 Credentials link.
  4. Click New Credential.
    The Create F5 Address form is displayed.
  5. Type your BIG-IP ASM account information (Host Name or IP address, Username, and Password).

    Note: These are the same credentials used to log directly on to BIG-IP ASM.
  6. Click Create.
  7. Click List to show the credential that you added.
Scheduling a scan

You need to first schedule a scan in Sentinel to see a list of potential vulnerabilities you need to protect against.

  1. From the Schedule tab, select a site from the list of sites shown.
  2. Click the drop-down in the Scan Schedule column and select one of the options:
    • Choose Continuous to allow scanning at all times. This is the recommended option.
    • Choose Nights and Weekends to allow scanning between 8 p.m. and 6 a.m. during weekdays, and continuously during weekends. You will need to choose a corresponding time zone to determine exactly when 8 p.m. is in that geography. (This defaults to the time zone you picked for your account.)
    • Choose Weekly to perform a weekly scan.
    • Choose Customize to create a custom schedule, then click Schedule.
  3. Make sure sufficient time has passed for the scan to occur.

 

Reviewing vulnerabilities

After running a scan, you can review the vulnerabilities associated with the sites configured in your WhiteHat Sentinel account.

  1. In WhiteHat Sentinel, click the Findings tab.
    The Findings page displays a complete list of vulnerabilities on every site in your account. See Qualified vulnerability classes for the ones you can add to the policy.
  2. Point to the Details column (far right)for the vulnerability you want to protect against, then click the Details icon.
    The Vulnerability Viewer page opens. Leave it open on the screen.

 

Connecting to BIG-IP ASM and applying the security policy

You can log on to the BIG-IP ASM through Sentinel through the Vulnerability Viewer associated with the vulnerability. You can then configure the BIG-IP ASM security policy to mitigate the vulnerability.

Vulnerabilities that BIG-IP ASM can protect against will have an area called F5 WAF Management on the Vulnerability Viewer.

  1. In the F5 WAF Management area of the Vulnerability Viewer, select the WAF Address of the BIG-IP ASM you want to configure.
  2. On the far right of the WAF Address line, click Login. If the connection is successful, you see a Success message. When you are connected to the BIG-IP ASM using the Sentinel UI, you can start blocking the qualified vulnerabilities.

    Note: If you see a Failed to contact WAF message, make sure that you can connect to the IP address directly in another browser instance without certificate warnings and add certificates, if necessary. See Troubleshooting tips for more information.
  3. Click the name of the web application in the first column.
    Security policies associated with the application appear in the Policy Name table, and parameters that will be added to the policy are listed on the right.
  4. In the Policy Name table, select the Whitehat-baseline policy.

    Note: The web application policy that you choose must be associated with the virtual server and target web application that WhiteHat Security is scanning to be able to block the vulnerability.
  5. Select additional check box options as needed:
    • Do NOT Apply Policy: Configure the policy to mitigate the vulnerability but do not enforce the security policy.
    • Set to Transparent or Set to Blocking: Sets the security policy to transparent or blocking. If set to transparent, no requests are blocked. If set to blocking, the system blocks requests that violate the security policy, such as including the parameters specified in the vulnerability. You only need to set this once for the entire policy.
    • Stage Only (10.2.x only): Add the parameters to the policy putting them in staging, and report instances of the vulnerabilities only; do not block requests with this vulnerability. The policy will not mitigate this vulnerability.
  6. Click Apply Changes to implement changes concerning this vulnerability to the security policy.
  7. Go back to the Findings tab and handle each of the remaining qualified vulnerabilities, adding parameters or suggestions to the Whitehat-baseline security policy.

 

Testing a blocking policy

As a final step, you can run a vulnerability retest from the Findings tab. You can retest all (or selected) vulnerabilities:

  1. In WhiteHat Sentinel, click the Findings tab.
  2. Under the list, click Check all or in the Retest column, select the vulnerabilities you want to retest.
  3. Click Retest Vulnerabilities.
    Sentinel sends traffic to the application web site through ASM. If the policy is properly set, the Status changes from Open to Mitigated by WAF.

You can also retest specific vulnerabilities one at a time:

  1. In WhiteHat Sentinel, click the Findings tab.
  2. Click the Details icon for the vulnerability you want to test.
    The Vulnerability Viewer shows the Current Status is Open.
  3. Click Retest Now to check that security policy is protecting against that vulnerability.
    Sentinel sends traffic to the application web site through ASM. If the policy is properly set, the Current Status changes from Open to Mitigated by WAF.

Mitigated by WAF means that the security policy is configured to protect against that vulnerability. Note that the ASM policy only blocks attacks when the policy is set to blocking, and a real attack occurs. If you put any of the parameters in staging, you need to remove them from staging after you have removed any false positives if you want them to be blocked. When you are ready to put the security policy into production, you should make sure that it is set to blocking to mitigate against the vulnerabilities.

You can check whether the security policy is set to transparent or blocking in the F5 WAF Management section of the Vulnerability Viewer.

When you run a scan, the BIG-IP ASM system logs do not report WhiteHat scans because the scans do not include malicious patterns. Therefore, vulnerabilities that a scan detects do not necessarily indicate a real attack. They only indicate a potential vulnerability that you need to protect against.

 

Troubleshooting tips

Certificate problems

When attempting to connect to the BIG-IP ASM system through Sentinel, you may receive a message indicating certificate problems such as Failed to contact WAF. Make sure that you have valid certificates on the web application web site and the BIG-IP ASM system. If using Firefox or Safari, accept the certificates when you browse to the web sites. If using Internet Explorer, choose Tools > Internet Options, click the Advanced tab, then clear Warn about certificate address mismatch, and restart the browser.

Incomplete configuration

When connecting to the BIG-IP ASM system through Sentinel, you may see a message that says WAF request failed; SOAP Response cannot be decoded... This may indicate that you created an application security class but forgot to create the WhiteHat baseline security policy. Refer to Creating the WhiteHat Sentinel Baseline security policy for details about how to create the policy.
