Description

Some virtual servers are down after failover.

Pool members associated to that virtual servers are marked down by health monitors.

Environment

BIG-IP - HA

Cause

On a new standby unit, one of the traffic-group-local-only self ip address is same as a SNAT IP which is a floating ip.

For example :

net self /Common/172.16.1.101 { ---> !!

address 172.16.1.101 /24

allow-service {

default

}

app-service none

description none

floating disabled

fw-enforced-policy none

fw-rules none

fw-staged-policy none

inherited-traffic-group false

partition Common

traffic-group /Common/traffic-group-local-only --->!!

unit 0

vlan /Common/VLAN_Prod

}

 

ltm snat-translation /Common/172.16.1.101 {

address 172.16.1.101 

traffic-group /Common/traffic-group-1

}

 

If a standby unit has matching self ip address of traffic-group-local only with floating snat-IP, arp will be resolved on active unit.

Due to that health monitor traffic will fail which in turn cause virtual servers to go down.

Recommended Actions 

Once you identify there is conflict between traffic-group-local-only ip and SNAT IP . Perform either of the below changes to get this resolved.

  •  Remove/change SNAT IP configuration where it doesn't have conflicting ip addresses
Or
  • Change a non-floating self ip address to a different ip that doesn't conflict with existing ip addresses and then refresh arp table.
