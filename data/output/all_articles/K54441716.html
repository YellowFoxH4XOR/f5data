Description
When a CSV backup file is used to restore users, a problem can occur if you have multiple instances and users with common usernames.
Users in local DB have disappeared, and the local user database has become corrupted.

Environment

  • BIG-IP APM
  • Authentication
  • local user DB

Cause
Incorrect CVS files was used to restore the local user DB.

Recommended Actions

To correct the issue refer to the following:  K51010941: Users unable to login with the correct password when using localDB authentication
 

Additional Information

In a situation where you have 2 isolated systems, with common usernames on each system, but in difference instances you should take care to restore the correct CSV file.
The problem occurs because each users details are held across multiple tables in a database. One table stored the users login details, ie username , password, login expiry, login failure count, id. The other table contains personal details, ie, first name, last name, email, phone, id. The common element between the tables is the user-id.

If a CSV is restored, but this is for the incorrect instance, and then the correct CSV is restored, the following events occur.
The user login information is saved, and the entry is considered as unique by the username+instance.
The user personal details are saved and the entry is considered as unique by the user-id, which matches the id in the table for the users login credentials.
Then when the second CSV is restored, the login information is saved, and is unique because although it is the same username, the instance is different, but the id is the same for that user.
So the personal details that are saved overwrite the entry with the same user-id.

When the incorrect details are deleted from the local user db, the cleanup process will remove the username+instance combination, and then also remove the entry for the users personal details that matches the user-id. This action then leaves an entry with the correct username+instance, but it no longer has a matching user-id in the personal details table.
Thus when the information is displayed in the local user manager, nothing is displayed, as the users are only displayed if a matching combination of user login details is found with matching personal details based on the used-id
