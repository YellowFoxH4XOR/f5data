Description

When a user is prompted to change their password on the GUI login screen, because their password has expired, the Audit logs shows as if the change was done by the primary admin user. For example, a user "testuser" changed their password due to expiry, but a log in /var/log/audit is written as if the "admin" user performs the change.

Jul 25 01:10:30 test.bigip.com notice mcpd[7881]: 01070417:5: AUDIT - client Unknown, user admin - transaction #167448-2 - object 0 - modify { userdb_entry { userdb_entry_name "testuser" userdb_entry_description "testuser" userdb_entry_passwd "***" userdb_entry_is_crypted 0 userdb_entry_gecos "testuser" userdb_entry_shell "/bin/bash" } } [Status=Command OK]

This may raise some concerns when reviewing the audit logs, as some might expect "testuser" to be shown as the user performing the action, instead of "admin".

Environment

  • BIG-IP all versions
  • User password expires
  • GUI prompts user to change password upon login:

Cause

This is expected behavior.

Recommended Actions

The earlier logs associated with the action may confirm it is indeed the user themselves who performed the change. The example logs below are logged when "testuser" is prompted to change its password due to password expiry. The first two logs indicate that it is "testuser" who performed the action, while the last one is written as "user admin".

Jul 25 01:01:24 test.bigip.com info httpd(pam_audit)[2272]: 01070417:6: AUDIT - user testuser - RAW: httpd(pam_audit): user=testuser(testuser) partition=[All] level=Administrator tty=(unknown) host=172.16.123.123 attempts=1 start="Sat Jul 25 01:01:24 2024" end="Sat Jul 25 01:01:24 2024".

Jul 25 01:01:25 test.bigip.com info rest(pam_audit)[3254]: 01070417:6: AUDIT - user testuser - RAW: rest(pam_audit): user=testuser(testuser) partition=[All] level=Administrator tty=(unknown) host=172.16.123.123 attempts=1 start="Sat Jul 25 01:01:24 2024" end="Sat Jul 25 01:01:25 2024".

Jul 25 01:01:25 test.bigip.com notice mcpd[7881]: 01070417:5: AUDIT - client Unknown, user admin - transaction #167448-2 - object 0 - modify { userdb_entry { userdb_entry_name "testuser" userdb_entry_description "testuser" userdb_entry_passwd "***" userdb_entry_is_crypted 0 userdb_entry_gecos "testuser" userdb_entry_shell "/bin/bash" } } [Status=Command OK]

Additional Information

If the default "admin" user is disabled and another primary admin user is set, it may show the configured primary admin instead of "admin".

You may check what the primary admin user is by running the following tmsh command:

tmsh list /sys db systemauth.primaryadminuser value
