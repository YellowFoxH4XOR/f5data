Description

Remote syslog server reports below error log.

err syslog-ng<PID>: Error opening file for writing; filename='/var/log/boot.log', error='Permission denied (13)'
err syslog-ng<PID>: Error opening file for writing; filename='/var/log/tomcat/catalina.out', error='Permission denied (13)' 

On BIG-IP, below error logs are recorded at the same time on /var/log/auditd/audit.log:

type=AVC msg=audit(2021-01-26T18:02:04CST:126716): avc: denied { getattr } for pid=<PID> comm="syslog-ng" path="/var/log/boot.log" dev="dm-3" ino=94 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file
type=AVC msg=audit(2021-01-26T18:02:04CST:126717): avc: denied { append } for pid=<PID> comm="syslog-ng" name="boot.log" dev="dm-3" ino=94 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file
type=AVC msg=audit(2021-01-26T18:02:04CST:126718): avc: denied { getattr } for pid=<PID> comm="syslog-ng" path="/var/log/boot.log" dev="dm-3" ino=94 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file
type=AVC msg=audit(2021-01-26T18:02:04CST:126719): avc: denied { getattr } for pid=<PID> comm="syslog-ng" path="/var/log/tomcat/catalina.out" dev="dm-3" ino=2501858 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file
type=AVC msg=audit(2021-01-26T18:02:04CST:126720): avc: denied { append } for pid=<PID> comm="syslog-ng" name="catalina.out" dev="dm-3" ino=2501858 scontext=system_u:system_r:syslogd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file

Environment

  • BIG-IP 
  • Remote syslog server

Cause

The Access Vector Cache (as seen in the "avc: denied" message) is where SELinux caches permissions for the kernel,  so far we don't know how system run into this situation and how SELinux permission changes. Root cause is under investigation.

Recommended Actions
Please run below command on the affected BIG-IP device to fix this issue.

#restorecon -Rv /var

Additional Information

Please use below command to check the SELinux permission. Example below comes from a healthy system.

# ls -Z /var/log/boot.log

-rw-------. root root system_u:object_r:var_log_t:s0   /var/log/boot.log

# ls -Z /var/log/tomcat/catalina.out

-rw-------. root tomcat system_u:object_r:var_log_t:s0   /var/log/tomcat/catalina.out
