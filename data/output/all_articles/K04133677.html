Description

The scriptd process cored while running the f5.automated_backup iApp script.

Messages observed in /var/log/ltm:

err scriptd[9105]: 014f0004:3: script has exceeded its time to live, terminating the script
notice sod[7973]: 01140041:5: Killing /usr/bin/scriptd pid 9105
warning sod[7973]: 01140029:4: HA daemon_heartbeat scriptd fails action is restart.

This usually happens when saving a UCS of a large configuration that takes longer than 5 minutes.

Environment

  • scriptd
  • iApps

Cause

Bug ID 842193: Scriptd coring while running f5.automated_backup script

The script terminates after exceeding the default max-script-run-time of 5 minutes.

sys scriptd {
    max-script-run-time 300
}

The scriptd process continues to run and becomes unresponsive, at which point it's killed by sod due to daemon-ha heartbeat failure.

Recommended Actions

First, you can check the max-script-run-time value by entering the following command:

#tmsh list sys scriptd 

e.g:
#tmsh list sys scriptd
sys scriptd {
    max-script-run-time 300
}

Increasing the max-script-run-time may help avoid this issue:

#tmsh modify sys scriptd max-script-run-time 900

Then check the value again:

#tmsh list sys scriptd
sys scriptd {
    max-script-run-time 900
}

Note: This may not fix the issue in all cases. If the UCS save stalls and never completes, it should be investigated.
