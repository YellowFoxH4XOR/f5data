Description

After an upgrade while the BIG-IP might seem to be in sync and the configuration loaded, the asm configuration might not have finished loading. It is likely it is still be coming up in the background. The GUI and CLI may show the BIG-IP online, but that is in regards to the Data Plane. ASM/AdvWAF runs on the Control/Analysis Plane.

If the device becomes active before ASM/AdvWAF loads its configuration, it can result in legitimate connections being dropped by ASM/AdvWAF. The ASM/AdvWAF configuration can take several minutes to load in the new version depending on the size of it.

Logs such as the ones below can be seen in /var/log/ts/bd.log
 

IO_PLUGIN|ERR  |Nov 16 22:13:37.637|6721|io_plugin.c:4870|TMEVT_REQUEST: did not receive policy configuration after 600 seconds
IO_PLUGIN|ERR  |Nov 16 22:13:37.638|6721|io_plugin.c:4725|TMEVT_REQUEST: Request has an unknown HTTP selector: '/Common/CEE2020Homepage' (crc:6712855472166751227)

Environment

  • Software upgrade or reboot
  • ASM configuration

Cause

ASM configuration has not been fully loaded.

Recommended Actions

1) Verify that the ASM/AdvWAF configuration has been loaded before making the device active.

A command can be run to check that ASM/AdvWAF is up. 

zgrep "LoadComplete::load_complete" /var/log/ts/asm_config_server.log

The output will look similar to this:

12:35:06.772|27195|F5::ASMConfig::Handler::LoadComplete::load_complete,,populating data into mcp
asm_config_server.pl|INFO|Oct 21 12:35:06.778|27195|F5::ASMConfig::Handler::LoadComplete::load_complete,,populating completed successfully

At that point ASM/AdvWAF should be up fully.

2) If expect there maybe issues then to verify this, grep for "load_complete" looking for errors in /var/log/ts/asm_config_server.log and review any errors after this line.

zgrep -A 50 "load_complete" /var/log/ts/asm_config_server* | grep error

Additional Information

Check the following log files for errors:

  • /var/log/ts/dcc.log
  • /var/lib/mysql/mysqld.err
  • /var/log/mysql.out
