Description

This article explains why ICMP-based tools (ping, traceroute) are not reliable indicators of connectivity when traffic is delivered through F5 Distributed Cloud, and provides guidance on proper connectivity validation methods. Customers may observe high ping packet loss or timeouts to F5 Distributed Cloud Points of Presence (POPs) while application traffic continues to function normally.

Environment

  • F5 Distributed Cloud

  • HTTP LB

Cause

When traffic is delivered through F5 Distributed Cloud, ICMP-based tools such as ping or traceroute are not a reliable indicator of connectivity for the following reasons:

  1. Architecture Design: The F5 Distributed Cloud platform is designed to proxy and secure traffic at Layer 4 (TCP/UDP) and Layer 7 (HTTP/HTTPS), while ICMP operates outside of the application data path.

  2. ICMP Rate Limiting: ICMP packets may be rate-limited or dropped for security reasons at the F5 Distributed Cloud edge.

  3. Different Traffic Paths: Even when ICMP responses are received, they do not necessarily represent the same path Application traffic follows the proxied and secured path through the F5 Distributed Cloud infrastructure, while ICMP packets may take a different route or be handled differently by network devices.

  4. Security Posture: Dropping or limiting ICMP is a common security practice to prevent reconnaissance and certain types of attacks.

Answer/Recommended Actions

1. Use Application-Level Testing

Instead of relying on ping or traceroute, validate connectivity using application-level testing with cURL or similar HTTP/HTTPS tools. 

A curl request exercises the same complete flow that real users experience:

  • DNS resolution
  • TCP connection establishment
  • TLS/SSL handshake
  • HTTP/HTTPS request and response
  • Application policy enforcement

This provides actionable results that directly reflect application reachability and the effectiveness of F5 Distributed Cloud policies.

2. Monitor Application Performance

Use F5 Distributed Cloud's built-in monitoring and analytics:

  • Review HTTP Load Balancer metrics in the F5 Distributed Cloud Console
  • Check request success rates, latency, and error codes
  • Analyze traffic patterns and performance trends
  • Verify Load Balancer configuration and origin pool health
  • Check origin server accessibility from F5 Distributed Cloud
  • Review security policies and WAF rules
  • Examine DNS resolution
  • Analyze application logs and F5 Distributed Cloud request logs
