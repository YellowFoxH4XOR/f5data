Description

SSL handshakes that rely on Luna HSM start failing after failover.

 

The following problem indications can be observed in ltm log:

Oct 17 16:09:08 <hostname> err pkcs11d[7470]: 01680048:3: C_Sign: pkcs11_rv=0x000000e0, CKR_TOKEN_NOT_PRESENT        .

Oct 17 16:09:08 <hostname> warning tmm[19543]: 01260009:4: ....: Connection error: ssl_hs_vfy_sign_srvkeyxchg:14775: alert(80) sign_srvkeyxchg

 

Note that TCP connectivity to HSMs is established (verify with netstat command). It's the pkcs11d that is losing connectivity to the HSM on the application level.

 

Environment

  • Platform: BIG-IP
  • Version: 15.1.x, 16.1.x, 17.x
  • HSM: Thales Luna HA pair

 

Cause

Root cause is unknown, but configuration of Luna client as per Recommended Actions sections helps to mitigate the problem.

 

Recommended Actions

HSM vendor provided the following configuration changes that helped to overcome the issue:

 

In BIG-IP shell, run:

lunacm

 

Then run the following commands:

hagroup retry -count -1

hagroup interval -i 120

hagroup recoveryMode -mode activeEnhanced

exit

 

Then once back in BIG-IP shell run:

bigstart restart pkcs11d

 

Note that, just restarting pkcs11d (without changing the configuration as above) will remediate the problem, but it will re-occur on subsequent failover.
