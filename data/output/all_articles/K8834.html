Topic

You can determine whether the Request Logs, Forensics, or Traffic Learning entries have been cleared by a user, or if the system is currently not recording information.

To determine if the Request Logs and Forensic entries have been cleared, look for the following entry in the /var/log/asm file:

log_manager[3235]: 01310019:5: [USER_ACTIVITY] User admin cleared all illegal requests that were associated with <Name of Web Application> Web Application from IP: <Source IP of user that cleared entries>.

Note: The all illegal requests entry is misleading; all requests are cleared from the database when a user clicks the Clear All button, which is located under Web Applications -> Forensics for BIG-IP ASM version 9.4.1 and earlier, and under Application Security -> Learning -> Requests for BIG-IP ASM version 9.4.2 and later.

Note: In BIG-IP ASM versions 9.2.x and 9.3.x, the Traffic Learning logs are automatically cleared when the Forensics entries are cleared. Beginning in BIG-IP ASM version 9.4, the Traffic Learning logs are treated as a separate entity and are no longer cleared when the Forensics/Request Logs are cleared.

To determine if Traffic Learning violations have been cleared by a user in BIG-IP ASM version 9.4.2 and later, look for the following entries in the /var/log/asm file:

Note: Versions prior to BIG-IP ASM 9.4.2 did not log any messages when Traffic Learning logs are cleared.

perl[7779]: 01310028:6: ASM subsystem info (clear_lrn_objects.pl,Logger::info): Starting ...
perl[7779]: 01310028:6: ASM subsystem info (clear_lrn_objects.pl,Logger::info): Completed ...

Note: By default the BIG-IP ASM system retains log files for eight days before rotating them. For more information, refer to K7115: Managing log files on the BIG-IP system.
