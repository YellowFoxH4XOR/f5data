Topic

You should consider using this procedure under the following condition:

  • You want to backup and / or restore a User Configuration Set (UCS) file using the Traffic Management Shell (tmsh).

Description

This article describes how to back up and restore your iWorkflow configuration data by using a UCS configuration archive. The UCS archive, by default, contains all of the files that the system requires to restore your current configuration to a new system, including configuration files, the product license, local user accounts, and Secure Sockets Layer (SSL) certificate/key pairs.

File names and location

By default, unless you include the extension in the file name, the iWorkflow system saves the UCS archive file with a .ucs extension. You can also specify a full path to the archive file, and the system saves the archive file to that specified location. If you do not include a path, the system saves the file to the default archive directory, /var/local/ucs.  Archives located in a directory other than the default do not appear when you use the tmsh utility list function for UCS archives. To easily identify the file, F5 recommends that you include the iWorkflow host name and current time stamp as part of the file name.

The system does not manage UCS archive files that you create using the tmsh utility. As a result, the iWorkflow administrator is responsible for cleaning-up and managing these archives.

Secure storage

A typical UCS archive contains user accounts, passwords, critical system files, and SSL private keys. It is important to store the backup UCS archives that contain sensitive information in a secure location. You can exclude SSL private keys from a UCS archive during the backup process.

Licensing

The iWorkflow license is associated with a specific image serial number. The UCS archive contains the license file of the system where the configuration was saved. You should restore the UCS archive to the same system from which it was saved. If you want to restore a UCS archive to a system other than the original source, you will have to either re-license the device or back up the original license file from the destination, and replace the file after the restore is complete.

Considerations when restoring a UCS file

  • F5 recommends that you restore the UCS archive to a system running the same version of iWorkflow as the source used to create the UCS archive. 
  • The iWorkflow license is associated with the serial number of the source system. If you restore a UCS file from one system to different system, you will have to re-license the iWorkflow instance. Alternatively, you may be able to replace the license file with the original license file from the destination device.
  • The network settings are included in the UCS archive, so if you restore the UCS file to another system, the destination server will acquire the source network settings.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • iWorkflow must be running 2.0.x or later.
  • You must have root access to the iWorkflow instance.

Procedures

Backing up the configuration data using the tmsh utility

As the iWorkflow administrator, you can manually back up the system configuration using the tmsh utility. You can then store these files, locally or remotely, based on the needs of the environment. To back up the iWorkflow configuration using the tmsh utility, perform the following steps:

Impact of procedure: Ensure that there is adequate local storage available to create the UCS file. You are responsible for the Lifecycle management for the archive files.  

  1. Log in to the iWorkflow command line.
  2. Log in to the tmsh utility by typing the following command:

    tmsh

  3. To create the UCS archive, use the following command syntax:

    save /sys ucs {new-ucs-file}

    For example:

    save /sys ucs iwf-1-09092016

    By default, this creates a new UCS file in the /var/local/ucs directory. The file extension, by default, is .ucs.  You can list all the UCS archive files on the system of which the tmsh utility is aware by typing the following command:

    list /sys ucs

    Note: If you used the Configuration utility to create UCS files, the system will not display the files when you use this command, as the system saves the files, by default, in the /shared/ucs_backups directory.

  4. Optional: If you would like to save the UCS file to another location, prepend the path to the filename using the following command syntax:

    save /sys ucs /path/to/{new-ucs-file}

    For example:

    Save /sys ucs /var/run/iwf-2-09092016

  5. Optional: If you want to encrypt the UCS archive with a passphrase, use the following command syntax.

    save /sys ucs /path/to/{new-ucs-file} passphrase <password>

    In the previous example note the following:

    • Replace <path/to/{new-ucs-file}> with the full path to the UCS archive file.
    • Replace <password> with the passphrase you want to use to encrypt the UCS archive.

    For example:

    save /sys ucs /var/local/ucs/iwf-2-09092016 passphrase password

  6. Optional: If you want to exclude the SSL private keys from the UCS archive, use the following command syntax.  

    Save /sys ucs /path/to/{new-ucs-file} no-private-key

    In the previous example, note the following:

    • Replace <path/to/{new-ucs-file}> with the full path to the UCS archive file.

    For example:

    Save /sys ucs /var/local/ucs/iwf-2-09092016 no-private-key

  7. As a best practice, copy the UCS file to a remote, secure system and storage location.

Restoring configuration data use the Configuration utility

You should first copy remote archive files back to the destination iWorkflow device before you continue with the restore process.

Important: When you restore a backup to an iWorkflow cluster, you must evict all peers from the cluster, leaving a standalone instance before you restore the iWorkflow system. Once the system has completed the restore, you should re-create the cluster using the previously-removed peers. The backed up iWorkflow version will then replicate to the other peers in the cluster. 

Impact of procedure: Ensure that you have a backup, or that you do not need a backup of the destination system before continuing with the restore process. The local system partition is active during the restore process, and the system will entirely replace the partition with the data stored in the archive file.  The iWorkflow system will not be available for remote users or standard iWorkflow functions during the restore process.

  1. Log in to the iWorkflow command line.
  2. Log in to the tmsh utility by typing the following command:

    tmsh

  3. To restore the UCS archive file, use the following syntax.   

    load /sys ucs /path/to/{ucs-archive-file}

    In the previous command syntax, note the following:

    • Replace /path/to/{ucs-archive-file} with the full path of the UCS archive file you want to restore.

    For example:

    load /sys ucs /var/local/ucs/iwf-2-09092016.ucs

    If the UCS archive was encrypted with a passphrase during the backup, you will be prompted to enter the passphrase during this step.

  4. Optional: If you want to restore the backup without the license, which may be the case if you are restoring to a host other than the UCS source, use the following command syntax:

    load /sys ucs /path/to/{ucs-archive-file} -no-license

    For example:

    load /sys ucs /var/local/ucs/iwf-2-09092016.ucs -no-license

  5. To restart the system, type the following command:

    reboot
