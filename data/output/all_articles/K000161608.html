K000161608: AS3 Declaration Fails with "double quotes are not balanced" Error When Using Encrypted Passphrase in Cookie Persistence

Support Solution
Published
2026-06-05
Updated
2026-06-05
Applies to
  • F5 Automation and Orchestration
  • BIG-IP
  • F5 Application Services 3 Extension
  • BIG-IP APM
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161608

Description

When posting an AS3 declaration that includes a cookie persistence profile with an encrypted passphrase, the deployment fails with a 500 response error.

The error message references a RADIUS server object and a syntax error, which may appear unrelated to the actual configuration issue.

Error message observed:

{
  "code": 500,
  "message": "POST .../mgmt/tm/ltm/auth/radius-server/ response=400 body={\"code\":400,\"message\":\"double quotes are not balanced\",\"errorStack\":[],\"apiError\":26214401}"
}

 

The declaration passes schema validation but fails during deployment. Declarations without the passphrase field, or using a plain base64-encoded passphrase, deploy successfully.

Environment

  • Product: BIG-IP LTM
  • BIG-IP Version: 17.5.x
  • AS3 Version: 3.5x
  • Configuration:
    • AS3 declaration containing a Persist object with persistenceMethod: cookie
    • encrypt: true enabled on the cookie persistence profile
    • passphrase object set with the following fields
      • ciphertext: containing SecureVault-encrypted binary data (not a plain base64 string)
      • protected: set to eyJhbGciOiJkaXIiLCJlbmMiOiJub25lIn0 (default value, indicating enc=none)

Cause

A mismatch between the protected field and the ciphertext field in the AS3 declaration's passphrase object

  • The protected field was set to its default value eyJhbGciOiJkaXIiLCJlbmMiOiJub25lIn0 which base64 decodes to {"alg":"dir","enc":"none"} indicating the ciphertext is a plain base64-encoded string
  • However, the ciphertext value contained SecureValue-encrypted binary data, not plaintext base64 string
  • This mismatch caused AS3 to generate malformed TMSH configuration resulting in the "double quotes are not balanced" syntax error when attempting to create the RADIUS server object used internally while the declaration is processed

Answer/Recommended Actions

Choose the appropriate option based on the type of data in the ciphertext field:

Option A - If ciphertext contains SecureVault-encrypted binary data:

  1.  Update the protected field in the passphrase object to indicate SecureVault encryption:

        The value eyJhbGciOiJkaXIiLCJlbmMiOiJub25lIn0 decodes to {"alg":"dir","enc":"f5sv"} indicating SecureVault encryption

 

"passphrase": {
  "ciphertext": "4zqHHA5CeGyvDPYTPDO81ohFlCZ98kFiNDGPAV6sWPR7",
  "protected": "eyJhbGciOiJkaXIiLCJlbmMiOiJmNXN2In0"
}

   2. Re-POST the updated declaration to AS3 declare endpoint

Option B - If the passphrase is a plaintext secret (not SecureVault-encrypted);

  1. Base64-encode the plaintext passphrase value. For example:

       

echo <your_passphrase> | base64

   

    2.  Use the resulting base64 string as the ciphertext value and leave the protected field at it's default value of eyJhbGciOiJkaXIiLCJlbmMiOiJub25lIn0 or omit it entirely:

 

"passphrase": {
  "ciphertext": "<base64_encoded_passphrase>"
}

     3. Re-POST the updated declaration to AS3

Additional Information

If you encounter this error, review your AS3 declaration and ensure the "protected" field in the passphrase object matches the encoding of the "ciphertext" value.

The protected field in the AS3 passphrase object is a JOSE header marker that tells AS3 how to interpret the ciphertext value:

  • eyJhbGciOiJkaXIiLCJlbmMiOiJub25lIn0 → enc=none → ciphertext is a plain base64url-encoded string
  • eyJhbGciOiJkaXIiLCJlbmMiOiJmNXN2In0 → enc=f5sv → ciphertext is a base64url-encoded SecureVault cryptogram

F5 recommends leaving the protected field either empty or the default value unless the ciphertext has been encrypted with SecureVault

The error message referencing a RADIUS server /mgmt/tm/ltm/auth/radius-server/ is misleading - It does not indicate a RADIUS configuration problem. 

This is an internal AS3 endpoint used during declaration processing
