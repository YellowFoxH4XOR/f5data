Topic

Beginning in BIG-IP version 4.0, you can prevent BIG-IP from responding to Address Resolution Protocol (ARP) requests for specific IP addresses. By disabling ARP requests, you can also stop BIG-IP from sending gratuitous ARP broadcasts when these IP addresses are configured, or when the BIG-IP changes its failover status. You can disable ARP for the following objects:
  • Virtual servers (VIPs)
  • NATs
  • SNATs
  • SSL Proxies

Note: This feature is similar to the vipnoarp feature in BIG-IP versions 1.8.3 - 3.3.1. However, the vipnoarp feature disabled ARP for VIPs only, and it consisted of only a global on/off setting. Starting with version 4.0, BIG-IP allows you to disable ARP at an individual object level. For more information about implementation of the vipnoarp feature on previous versions of BIG-IP, refer to K270: Configuring BIG-IP not to respond to arp requests for virtual servers.

When should I prevent BIG-IP from responding to ARP requests?

When ARP is disabled for VIPs, NATs, SNATs and/or SSL Proxies, the objects respond to network traffic for their IP addresses as normal; however, BIG-IP does not generate any ARP traffic for those IP addresses. This includes replies to ARP requests and gratuitous ARP broadcasts.

This feature is best suited for those customers who are running thousands of VIPs and have the flexibility to add a route to their router. Preventing BIG-IP from responding to ARP requests provides the following advantages:

  • BIG-IP does not waste time adding and deleting IP addresses for each VIP.

    Note: Adding an IP address also prompts BIG-IP to perform a gratuitous ARP.

  • The external network is not congested with ARP traffic, because the routers do not need to ARP for the VIP addresses.

When running a smaller number of VIPs, the time it takes for BIG-IP to add IP addresses when it becomes active is negligible.

With a higher number of VIPs, (for example, 8000) adding IP addresses could take as long as 90 seconds. During that time, BIG-IP is unresponsive and this condition is not consistent with the design objective for BIG-IP, which is seemingly instantaneous failover.

Note: The feature is a complement, not a substitute, for the bigpipe alias command, which prevents pinging thousands of node IP addresses.

How do I disable BIG-IP from responding to ARP requests?

Before disabling ARP requests on BIG-IP, you must first configure the router on the BIG-IP's external interface to go through the IP address for the BIG-IP (or, in a redundant configuration, the shared IP address) as the gateway for all the VIP addresses.

For example, if you had a network topology that appeared as follows:

bigip1_vlan0 11.0.0.11
 bigip2_vlan0 11.0.0.12
 bigip_ext 11.0.0.100 # floating self ip
 vip1 11.0.1.50
 vip2 11.0.1.51
 vip3 11.0.1.52

You would configure the router to get to network 11.0.1.0 through gateway 11.0.0.100. If the router is UNIX-based, the command to configure the static route would be as follows:

route add -net 11.0.1.0 gw 11.0.0.100

Note: Check with your router vendor for specific instructions about how to add static routes.

You can then prevent BIG-IP from responding to ARP requests from the Configuration utility or through the command line.

Disabling ARP requests from the Configuration utility

To disable ARP requests for a VIP, NAT, SNAT, or SSL Proxy, perform the following steps:

  1. Go to the property screen for the object (VIP, NAT, SNAT, or SSL Proxy).
  2. Uncheck the box next to Enable ARP.
  3. Click Apply.

Disabling ARP requests from the command line

To disable ARP requests for a VIP, NAT, SNAT, or SSL Proxy, type the following command:

bigpipe <vip | nat | snat | proxy> <ip_address>[:service] arp disable

For more detailed instructions on the commands used for disabling ARP, refer to the BIG-IP Reference Manual.
