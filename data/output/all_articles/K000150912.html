Description

When using OSPFv3 on BIG-IP LTM, the routing table may display multiple external (E2) routes for the same IPv6 prefix, even when these routes have different metrics. This is unexpected because only the route with the lowest metric should be installed. Example routing table output:

 

#imish
#enable
#configure terminal
#show ipv6 route ospf 

O E2   ::/0 [110/500] via fe80::250:56ff:febd:241, Internal
                   [110/600] via fe80::250:56ff:febd:b3c4, Internal

 

The OSPFv3 routes confirms that the same prefix is being advertised by different neighbors with different metrics, this can also be observed on the OSPFv3 database with the command show ipv6 ospf database

Environment

  • BIG-IP Advanced Routing
  • OSPFv3 E2 routes
  • OSPFv3 route metrics
  • Default ECMP (Equal-Cost Multi-Path) settings
  • Multiple OSPFv3 neighbors announcing routes with different metrics

Cause

By default, ECMP is enabled on BIG-IP for OSPFv3. This allows installation of multiple next-hops for the same prefix even if those OSPFv3 E2 routes have different metrics resulting in multiple entries for a single prefix in the routing table.

Recommended Actions

To ensure only the best (lowest metric) OSPFv3 E2 route is installed in the routing table, disable ECMP for OSPFv3 by limiting maximum paths to one:

1. Enter imish:

#imish
#enable
#configure terminal

2. Enter configuration mode and set maximum-paths to 1:

#configure terminal #maximum-paths 1 #write memory

After applying this configuration, only the route with the lowest metric will be installed per prefix

Additional Information

  • If changes are not reflected immediately, restart the OSPFv3 process or tmrouted process to force recalculation:

#bigstart restart tmrouted

Important: This will temporarily disrupt routing.

  • Verify both the OSPFv3 database and routing table after making changes to confirm expected behavior.
