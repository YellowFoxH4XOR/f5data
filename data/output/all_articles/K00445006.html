Description

Not able to download PDF files larger than 50KB
  • Error in /var/log/ltm logs
    011f0016:3: <process> - Invalid action:<code> Server sends too much data. serverside (<ss_connection>) 
    clientside (<cs_connection>) (Server side: vip=<vs_name> profile=<profile_name> pool=<pool_name> server_ip=<pool_member_IP>)

Environment

  • Virtual Server with HTTP profile applied
  • Downloading large PDF files (size may vary depending on your specific environment)
  • Server sends more data than declared by the Content-Length header

Cause
Pool member response not compliant with HTTP rfc for large PDF resources. The server sends more data than declared by the Content-Length header.

Recommended Actions

You can configure the pool member to be RFC compliant and not send more data than specified by the HTTP: Content-Length header.

Alternatively, to work around this issue on the BIG-IP system, you can configure the affected virtual server to use an iRule that disables the HTTP profile for PDF files. For example, you can use an iRule similar to the following:

when HTTP_RESPONSE {
    if { [HTTP::header "Content-Type"] contains "application/pdf" }  {
        HTTP::disable
   }
}

Note: This will disable the HTTP profile for the connection. Additional requests using the same connection may fail.
