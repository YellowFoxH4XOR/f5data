Known Issue

BIG-IP APM may experience network access lease pool IP exhaustion.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM configuration includes a network access profile that references a lease pool.
  • The lease pool is configured with a limited amount of IP addresses.
  • The network access profile is configured for Datagram Transport Layer Security (DTLS).
  • The access policy includes a full desktop.
  • Users establish network access sessions.
  • Users toggle between launching and disconnecting the network access resource, multiple times, in short succession without logging off from their access session.

Impact

Users cannot launch the network access resource.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Repeating log messages, similar to the following example, are logged to the /var/log/apm file:

    notice tmm[<pid>]: 01490505:5: 8f003f60: IPv4 Allocation failure: leasepool /<partition>/<access policy name> is out of addresses
    notice tmm[<pid>]: 01490505:5: 8f003f60: IPv4 Allocation failure: leasepool /<partition>/<access policy name> is out of addresses
    notice tmm[<pid>]: 01490505:5: 8f003f60: IPv4 Allocation failure: leasepool /<partition>/<access policy name> is out of addresses
    notice tmm[<pid>]: 01490505:5: 9ddd9479: No leasepool assigned
    notice tmm1[<pid>]: 01490501:5: 9ddd9479: Session deleted due to user logout request.
    notice tmm1[<pid>]: 01490521:5: 9ddd9479: Session statistics - bytes in: <numeric value>, bytes out: <numeric value>
  • Modifying the network access profile lease pool, and increasing the number of IP addresses, allows users to successfully launch the network access resource.

Workaround

To work around this issue, you can increase the amount of lease pool IP addresses.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
