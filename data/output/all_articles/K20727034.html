Known Issue

The bigd process may leak memory when making configuration changes to the monitored fully-qualified domain name (FQDN) nodes.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has multiple bigd processes running.

    Note: On a VIPRION system, you may have a bigd process running across multiple blades or multiple bigd processes running on a single blade.

  • Configuration changes are applied to the existing FQDN nodes on the system.

Impact

The BIG-IP system may mark down available pool members.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system incorrectly marks down available pool members.
  • The memory usage on the non-primary bigd process (for example, bigd.1) is significantly higher than the primary bigd process (for example, bigd.0). You can use the top command to view memory usage on the BIG-IP system. The output with regards to the bigd processes may appear similar to the following example:

      PID USER      PR  NI  VIRT  RES  SHR S %CPU %MEM    TIME+  COMMAND          
    12345 root      20   0 50552  21m  14m S  0.0  0.0   1:47.17 bigd.0 -P 3 -I 0
    12346 root      20   0 2546m 1.7g  14m S  0.0  3.6   1:50.60 bigd.1 -P 3 -I 1

  • The bigd process restarts and creates a core file in the /shared/core directory.
