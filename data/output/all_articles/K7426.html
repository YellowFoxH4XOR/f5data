Known Issue

This is the result of a known issue. If a user belonging to a FirePass master group that authenticates to Active Directory attempts to change their Active Directory password, they will receive the following error message in the FirePass logon box:

The Active Directory refused to change your password

This issue typically occurs when the Active Directory domain administrative account configured in the user's FirePass master group authentication is a member of a large number of Active Directory groups (typically 100 or more). This account is configured in the Domain admin name field of the Users: Groups: Master Groups page for the Active Directory master group.

For the FirePass user to change their password, the domain administrative account configured in the FirePass master group must obtain a Kerberos ticket from the Active Directory domain controller. If the administrative account belongs to a large number of Active Directory groups, the ticket size can be too large to fit into the UDP packet used for the Kerberos response. Instead of returning the ticket, the domain controller returns the following response to the FirePass controller:

KRB5KRB_ERR_RESPONSE_TOO_BIG

Normally, this response prompts the FirePass controller to switch to TCP packets, which can accommodate the larger ticket size, as is the case with a standard FirePass login for a user who belongs to a large number of Active Directory groups. However, when the user login first requires a password change, a bug in the KPASSWD routine of the SAMBA package used in the FirePass software causes the FirePass controller not to switch to TCP, and instead to display the error message to the user.

You can determine whether a particular instance of this error message is the result of this issue by noting the following:

  • All users who belong to the FirePass master group using Active Directory authentication will receive this error message when required to change their password.
  • A network packet trace between the FirePass controller and the domain controller will display a UDP packet from the domain controller containing a KRB5KRB_ERR_RESPONSE_TOO_BIG error (error code 52 decimal, 34 hexadecimal). The FirePass controller will not send a Kerberos response after the packet with the error code. (The packet trace should be displayed with a tool such as Wireshark/Ethereal that is capable of decoding the Kerberos protocol).

    F5 Product Development tracked this issue as CR69628 and it is fixed in FirePass versions 6.0.1. For information about upgrading, refer to the FirePass release notes.

    Workaround

    You can work around this issue by deleting unneeded Active Directory groups from the domain administrative account used in the FirePass master group. To do so, consult documentation for the Microsoft Active Directory Users and Computers tool, or equivalent tool for instructions.

    The administrative account may be associated with large numbers of groups due to a migration of the account, which may retain the security IDs (SIDs) of the old state as well as having current SIDs for group associations. In this case, the number of current groups may be small, but the number of SIDs, which are incorporated into the Kerberos ticket, are large. For a discussion of this issue and remediation steps, refer to the following website:

    http://www.microsoft.com/downloads/details.aspx?familyid=
    22DD9251-0781-42E6-9346-89D577A3E74A&displaylang=en

    Alternatively, you can work around this issue by creating a different domain administrative account in the Active Directory, used only for the FirePass master group. To do so, select a new name that is unique to your domain, and then add a user with this name in your Active Directory domain. Add only the necessary groups to permit the account to manage user authentication. Consult the documentation for the Microsoft Active Directory Users and Computers tool, or equivalent tool for instructions. Then use this account name in the Domain admin name field of the Users: Groups: Master Groups page for the Active Directory master group.
