K40165336: POST processed by BIG-IP ASM with HTTP Expect: 100-continue fail

Description

When sending a POST to a virtual server configured with a BIG-IP ASM security policy the POST fails when the destination server requires an HTTP "Expect: 100-continue".

Environment

  • BIG-IP ASM
  • Pool member server requires "Expect: 100-continue" header to be present

Cause

This is caused by the BIG-IP ASM removing the "Expect: 100-continue" header before forwarding the request to the pool member server.

In v15.x the BIG-IP ASM behavior relating to POST requests with "Expect: 100-continue" header changed. Prior to this version the BIG-IP would forward the request to the pool member server. The new behavior is that BIG-IP ASM will respond with "HTTP/1.1 100" and wait for the client to send the request data. Once the request data is received and inspected by BIG-IP ASM, the BIG-IP forwards the request to the pool member server but removes the "Expect: 100-continue" header. This can cause problems if the pool member server requires the "Expect: 100-continue" header to be present.

Recommended Actions

You can enable the BIG-IP ASM to include the Expect: 100-continue" header with the following commands:

  1. Log on to the command line of the affected BIG-IP ASM system.
  2. Run the following command to enable the Expect: 100-continue header:

    /usr/share/ts/bin/add_del_internal add answer_100_continue 0

  3. Restart the BIG-IP ASM asm service with the following TMSH command:

    tmsh restart sys service asm

 Impact of workaround: Restarting the BIG-IP ASM process disrupts traffic processing and causes the BIG-IP ASM system to fail over to the remaining members of the device group.
