Known Issue

This is the result of a known issue. When handling clients using a slow connection, BIG-IP ASM erroneously buffers the entire server response rather than immediately proxying the responses. This behavior will result in excessive memory usage.

This behavior occurs with all virtual servers that have a BIG-IP ASM enabled HTTP class. Additionally, this behavior occurs even if an iRule is associated with the virtual server that disables BIG-IP ASM for all requests.

This behavior is most relevant in environments where clients with slow connections are downloading large files. You may observe the following effects:

  • Large memory consumption

    The buffering of many large responses can consume excessive amounts of memory. Configuring RAM Cache for use with the BIG-IP ASM system can help alleviate excessive memory consumption due to buffering, by allowing BIG-IP ASM to cache and serve files from the RAM Cache.

    For more information, refer to K8216: Configuring RAM Cache for use with a BIG-IP ASM enabled virtual server.
  • Connection timeouts

    If downloading files to BIG-IP ASM is fast, but the server is unable to handle the rate at which the file is being received, the server will reset the connection and the client-side connection will be reset.

    Configuring a OneConnect profile for use with the virtual server can help alleviate this behavior. This configuration disassociates the client and server side from one another, and prevents resets on the server side from affecting the client-side connection.

F5 Product Development tracked this issue as CR98920 and it was fixed in BIG-IP ASM 9.4.5. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in Hotfix BIG-IP-9.4.3-HF4 issued for BIG-IP 9.4.3, and in Hotfix BIG-IP-9.4.4-94.0-HF3 issued for BIG-IP 9.4.4. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
