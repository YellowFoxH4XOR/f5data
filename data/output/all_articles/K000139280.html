Description

QKViews are failing to process on iHealth with no visible explanation, but only from certain vCMP guests.

Environment

  • VIPRION Host
  • BIG-IP vCMP guest spanning multiple blades.
  • QKView file is large, but still within the 4GB size limit.
  • Several thousand configuration objects (Virtual Servers, Monitors, Nodes, and Pools).

Cause

iHealth is not able to process extremely large numbers of configuration objects.

Recommended Actions

Remove any unnecessary configuration objects prior to generating a QKView.

OR

Remove the guest system from one or more blades to reduce the number of sub-QKViews created. (Not recommended)

Additional Information

When generating a QKView on a vCMP guest, an additional QKView is generated for each blade the guest uses. Each of these QKViews contain copies of all of the configuration objects, and all of those objects in each copy must be processed by iHealth. A vCMP guest spanning over 3 blades with 20,000 configuration objects will generate a QKView with 60,000 configuration objects to process.
