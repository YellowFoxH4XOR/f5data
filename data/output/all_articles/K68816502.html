Security Advisory Description

A BIG-IP LTM policy referencing an external data group may not match traffic.

This issue occurs when the following conditions are met:

  • The virtual server is configured with a BIG-IP LTM policy and an external data group.
  • The BIG-IP system reboots or the Traffic Management Microkernel (TMM) restarts.

Impact

BIG-IP LTM policies may be unable to execute the appropriate action on a successful matching condition, leading to a range of traffic-impacting consequences.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After a system reboot or TMM restart, BIG-IP LTM policies referencing an external data group may not execute correctly, regardless of a successful matching condition. This can cause a wide range of issues, including the following:
    • Mis-routed traffic
    • Unshaped traffic
    • Disabled or bypassed traffic processing for BIG-IP Advanced WAF / ASM.
    • Complete traffic failure (based on the policy actions).

Note: If a virtual server references multiple BIG-IP LTM policies, and only some of those policies reference an external data-group, all BIG-IP LTM policies attached to the virtual server will be affected.

Mitigation

To mitigate this issue, you can remove and re-add the affected policy to the virtual server. Alternatively, to fix a wider number of affected policies, you can reload the system configuration. To do so, perform one of the following procedures:

Note: The following procedures do not mitigate the issue for BIG-IP 13.1.x.

  • Remove and re-add the affected policy to the virtual server you want.
  • Perform a configuration reload

Remove and re-add the affected policy to the virtual server you want

If your BIG-IP system has a small number of affected policies, you can mitigate this issue by removing and re-adding the affected policies to the virtual servers. To do so, perform the following steps:

Impact of action: Performing the following procedures should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server with the affected BIG-IP LTM policy.
  4. Select Resources.
  5. In the Policies section, select Manage.
  6. In the Resource Management section, move the affected policy from Enabled to Available.
  7. Select Finished.
  8. In the Policies section, select Manage.
  9. In the Resource Management section, move the affected policy from Available to Enabled.
  10. Select Finished.
  11. Repeat steps 2-10 for each affected policy.

Perform a configuration reload

If your BIG-IP system has a large number of affected LTM policies, you can mitigate this issue by reloading the configuration. To do so, perform the following steps:

Impact of action: Performing a configuration reload on an active system may cause a temporary service disruption. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the TMOS shell (tmsh) by entering the following command:

    tmsh

  2. To reload the system configuration, enter the following command:

    load /sys config
