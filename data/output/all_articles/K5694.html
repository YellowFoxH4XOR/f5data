Topic

Note: BIG-IP ASM 11.2.1 or later, when you first create a security policy, you can configure whether the security policy treats file types, URLs, and parameters as case sensitive or not. For more information, refer to Viewing whether a security policy is case-sensitive section of the Manual Chapter : Changing Security Policy Settings.
BIG-IP ASM security policy elements are case sensitive. BIG-IP ASM distinguishes between uppercase and lowercase characters for security policy elements such as file types (object types in version 9.x), URLs (web objects in version 9.x, and flows. If the web application being protected by a BIG-IP ASM policy is not case sensitive, the following two options can help you account for variations in case:

  • If the BIG-IP ASM security policy contains a small number of file types (object types in 9.x), you can create multiple file types in the security policy to account for variations in case.
  • If the BIG-IP ASM security policy contains a large number of file types (object types in 9.x), you can create an iRule that sets the URI path to lowercase before the BIG-IP ASM receives the request.

Creating multiple file types in the security policy in ASM version 10.x

If the security policy contains a small number of file types, you can create multiple file types in the security policy to account for variations in case. For example, if a file type of .ext is required in the security policy, you would define an file type of uppercase .EXT and create a second file type of lowercase .ext.

To create multiple file types in the version 10.x security policy, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Security Policies.
  4. Click Policy List.
  5. Click the security policy you want to edit.
  6. Click File Types.
  7. Click Create.
  8. Enter an object type for lowercase .ext.
  9. Repeat Steps 1 through 8, adding an object type for uppercase .EXT.

Creating multiple object types in the security policy in ASM version 9.x

If the security policy contains a small number of object types, you can create multiple object types in the security policy to account for variations in case. For example, if an object type of .ext is required in the security policy, you would define an object type of uppercase .EXT and create a second object type of lowercase .ext.

To create multiple object types in the security policy, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Application Security.
  3. Click the Web Applications.
  4. On the Web Applications page, click the active policy for the web application you want to edit.
  5. On the Security Policy page, click the Objects Type tab.
  6. Click Create.
  7. Enter an object type for lowercase .ext.
  8. Repeat steps 1 through 7, adding an object type for uppercase .EXT.
Creating an iRule that sets the URI path to lowercase before the BIG-IP ASM receives the request

If the security policy contains a large number of file types (object types in 9.x), it may not be practical to create multiple file/object types for each case. Alternatively, you can create an iRule that sets the URI path to lowercase before the BIG-IP ASM receives the request. This procedure eliminates the need to define multiple file/object types in the security policy by setting the URI to lowercase.

To create an iRule that sets the URI path to lowercase before the BIG-IP ASM receives the request, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic Manager.
  3. Click iRules.
  4. On the iRules page, click Create.
  5. Type a name for the iRule.
  6. In the Definition field, paste the following iRule example:

    when HTTP_REQUEST {

    HTTP::path [string tolower [HTTP::path]]

    }
