Description

The Virtual Server is not passing traffic to backend server.

Environment

  • BIG-IP LTM configured
  • Virtual Server is configured
  • Pool configured with monitor 
  • Monitor marks pool member up or available

Cause

There is no TMM route to the pool member. 

Recommended Actions
Diagnose:

  1. Verify the BIG-IP knows how to route to the pool member.
    Open an SSH session to the BIG-IP. Run the following command from Bash to verify if the BIG-IP will be routing traffic to the pool member via a TMM interface or the management interface.

    ip route get x.x.x.x

    Example:

    [root@BIG-IP-01:Active] config # ip route get 10.20.4.31
    10.20.4.31 dev internal_vlan  src 10.20.4.5                               <======= the route to this node is via my internal vlan
        cache

    [root@BIG-IP-01:Active:] config # ip route get 10.154.191.254
    10.154.191.254 dev mgmt  src 10.154.149.115                              <======= the route to this node is via my mgnt interface and will no work for load balanced traffic.
        cache
     
  2. Verify the traffic is reaching the virtual server and being passed by the BIG-IP.
    Start the packet capture by connecting the BIG-IP via SSH and running a command similar the one below.

    Example:
    tcpdump -s0 -nni 0.0:nnn -w/var/tmp/example.pcap host <virtual server ip> or host <pool_mbr_IP> -v

    Attempt to connect to the Virtual Server:

    The packet capture of the traffic will show the BIG-IP reset the connection for the reason of No route to host.
    03:32:59.447544 IP 10.10.10.100 https > 10.10.10.10.58913: Flags [R.], seq 148, ack 1142, win 0, length 0 out slot1/tmm0 lis=/Lab/VS_Example flowtype=64 flowid=56000219BE00 peerid=0 conflags=100200004800024 inslot=14 inport=2 haunit=1 priority=3 rst_cause="[0x2b2abfc:5262] No route to host" peerremote=00000000:00000000:00000000:00000000 peerlocal=00000000:00000000:00000000:00000000 remoteport=0 localport=0 proto=0 vlan=0
Resolve:
You will need to add a route to the new pool members. The following document will guide you through this task: K13833: Managing static routes in BIG-IP and BIG-IQ
 

Additional Information

BIG-IP Monitors can use the management interface to check the status of a pool member. However the BIG-IP cannot us the management interface to route load balanced traffic. This results in the monitor marking the pool member up and available yet not having a route to route the actual traffic being handled by the virtual server.
