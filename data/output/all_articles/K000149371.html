Description

You want to understand and interpret the different terms in the output, after running the following command in CLI.

system_check -d | grep -E "Units|_fan"

The example output is as follows,

Column Breakdown

  • Key: Identifier for the specific fan or voltage sensor.
    • 1/bld_cpu_fan: the blade CPU fan.
    • cha_fan1_volt, cha_fan2_volt: Voltage readings for chassis fans.
    • cha_fan_1, cha_fan_2, cha_fan_3, cha_fan_4: Chassis fans.
  • Sys: System number or identifier
  • Data: The measurement value.
    • E.g., 4928 RPM for CPU fan speed, 12065 mV for chassis fan voltage.
  • Unit: The unit of the data value.
    • RPM: Revolutions per minute.
    • mV: Millivolts.
  • Sta: Status; 1 suggests normal status.
  • Cur: Current state; NORM implies normal.
  • Tbl, #, Type, Range, Value, Hyst: These columns likely represent additional parameters or thresholds for the sensors, possibly including:
    • Tbl: Table or criteria used for evaluation.
    • #: Index or identifier.
    • Type: Type of measurement or sensor.
    • Range: Acceptable range for values.
    • Value: Current value.
    • Hyst: Hysteresis value, indicating a tolerance range before triggering an alert.
  • Sev: Severity; CRIT indicates critical status, suggesting that the measured value is outside acceptable limits or ranges.

Output Interpretation

From the output, we can infer the following:

  • The CPU fan speed is 4928 RPM for 1/bld_cpu_fan, which is marked as critical.
  • Multiple voltage readings for chassis fans (cha_fan1_volt, cha_fan2_volt) are critical.
  • Several chassis fans (cha_fan_1 to cha_fan_4) have RPM values around 2882 to 2906 RPM, all marked as critical.

The CRIT severity indicates that these values are outside the normal operating range and may require immediate attention to prevent potential hardware failure or to ensure proper system function.

 ​​​​​​​If an error message of critical severity is logged repeatedly in the system check that you’ve performed, you should perform an End-User Diagnostic (EUD) to identify any related hardware issues. For more information about performing an EUD, refer to the End-User Diagnostics Release Note.
