Topic

You should consider using this procedure under the following condition:

  • You want to generate credentials and utilize iHealth APIs on the new iHealth system (iHealth.f5.com).

Description

F5 is releasing a new iHealth system and adopting the newly created API Token Service. In order to utilize iHeath APIs provided by ihealth-api.f5.com, you must generate API tokens with Client ID and Client Secret issued from the iHealth API token service.

Note: If using Ansible to generate iHealth API credentials, take into account that currently the iHealth API token service does not support the uri module. As a workaround you can use the curl command with the shell module.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the new F5 iHealth system.

Procedures

Generating new iHealth API credentials using iHealth API token service

To generate Client ID and Client Secret for acquiring iHealth API bearer tokens using iHealth API token service, perform the following procedure:

  1. To generate a new Client ID and Client Secret, go to https://ihealth.f5.com/qkview-analyzer/settings, and under API Token, select Generate New Credentials.

    Note: You can also reach the Settings page by selecting Settings link on the top menu bar of the iHealth main page.

  2. A pop-up window appears with a newly generated Client ID and Client Secret. Any previously generated Client ID and Client Secret are invalidated and replaced with new ones. Be sure to copy the Client ID and Client Secret for future reference as they are not shown in iHealth again. iHealth stores the Client ID in a database for validation. Client ID and Client Secret are valid for six months, at which time you must return to the settings page and regenerate new ones.
  3. Copy and paste the (curl) authentication call that is supplied in the pop-up window in the terminal to generate a bearer token. The curl call can be saved for reusing it to generate a new token and any time when needed (for example, after a token expires in 30 minutes). You can always form your own curl POST request, for example:

    curl --request POST --url https://idp.identity.f5.com/oauth/token -H "Content-Type:application/json" --data "{\"client_id\": \"<your client ID>\", \"client_secret\": \"<your client secret>\", \"audience\": \"api://ciam-api-ihealth\", \"grant_type\": \"client_credentials\"}"

  4. Use the returned bearer token as part of the authorization header (-H "authorization: Bearer <authToken>") in order to access the API at ihealth-api.f5.com. For further details, refer to the iHealth API documentation. For example:
    curl -H "Authorization: Bearer <your auth token>" -H "Accept: application/vnd.f5.ihealth.api" --user-agent "MyGreatiHealthClient" -o - https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews
  5. The auth token is valid for 30 minutes, after which you would need to request a new bearer token with the original Client ID and Client Secret.
