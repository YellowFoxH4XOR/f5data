Description

This article guides you to install multi-cluster Aspen Mesh on two separate EKS clusters deployed in two different AWS regions. Primarily each EKS clusters must have two different, dedicated networks for Nodes and Pods. E.g., Node CIDR 10.0.0.0/24 and Pods are on 70.0.0.0/24 subnet.

Secondarily, we install the same version of Aspen Mesh on each EKS cluster. The selected AM Deployment Model type is Multi Primary Different Network, which is quite similar and inherited from Istio deployment. 

Finally, we deploy sample applications on each cluster to verify cross cluster communication.  

Environment

  • AWS EKS, Kubernetes: 1.17x - 1.23.x
  • Aspen Mesh: 1.6.x, 1.9.x, 1.11.x, 1.14.x

N/A

Recommended Actions

EKS deployment 

  • This is one of the prerequisites. To find more details about different EKS cluster implementation methods, refer to Creating an Amazon EKS cluster.
  • EKS CNI custom networking for deploying different Pod subnet, please keep in mind Node subnet and Pods subnet should be associated with different CIDRs as shown under the Description section of this article.
  • Verify that the EKS cluster instances have separate, dedicated CIDR’s.  One for Nodes and another for Pods. For quick check about AWS-EKS via GUI and CLI, refer to Connect using EC2 Instance Connect. 

Aspen Mesh multi-cluster deployment

  • Once EKS clusters deployed successfully region wise, Follow Aspen Mesh article K14643443: Install multi-cluster Aspen Mesh on KOPS Cluster for Multi cluster deployment. 

Performing cross cluster applications accessibility test

  • By now, EKS cluster along with Aspen Mesh are deployed and running propitiously in AWS environment. It's time to spin a couple of sample applications to test cross cluster service communication. For more information, refer to Verify the installation.
