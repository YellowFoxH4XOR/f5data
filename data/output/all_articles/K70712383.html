Description

Copying APM ACLs from one BIG-IP unit to another

Environment

  • BIG-IP APM
  • ACL - Access Control List.
  • Both BIG-IP APMs have to be running the same version.

Cause

None

Recommended Actions

Note :  Before doing any changes/activities, create a fresh UCS of the BIG-IP devices in question and copy it to a remote and secure connection as a precautionary measure; see the article below:  
K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

There are two methods to perform this task. 

Using GUI
The ACL comes along when Access Profile is exported.
For example, to export all "ACLs
 

  1. Export all Access Profiles with ACL.
  2. Test one Access Profile at a time
  3. Import one Access Profile (use a new and unique name).
  4. Apply this change.


If you do not want to retain the Access Profile but want to keep the ACL, perform these steps.

  1. Edit the imported Access Policy that contains an ACL Resource.
  2.  In the ACL Resource, untick all ACLs.  Apply the changes.
  3. Delete the corresponding Access Profile
  4. Check the new ACL in "Access  ››  Access Control Lists : User-defined ACLs"


Using TMSH

  1. Copy the existing ACL from the bigip.conf, example below:

    apm acl /Common/my_acl {
        acl-order 21
        entries {
            {
                action discard
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
            {
                action allow
                dst-end-port 23
                dst-start-port 23
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
        }
    }
     
  2. Rename the above acl and place a new and unique "acl-order" number (not conflicting to the existing ACL order numbers.
    You can use a higher no.) example: 
    apm acl /Common/new_acl {
        acl-order 121
        entries {
            {
                action discard
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
            {
                action allow
                dst-end-port 23
                dst-start-port 23
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
        }
    }
  3. Start tmsh:tmsh
  4.  Run in tmsh the following command:
    Note: You cannot run "tmsh load sys config merge from-terminal" in bash else you will get an error of :
    "Data Input Error: from-terminal only works in interactive mode."

    load sys config merge from-terminal
  5. Paste the edited ACL, e.g. item 2 
  6. Press CTRL-D to submit
    (To cancel, press CTRL+C)
  7. Check the new entry in tmsh

    # list apm acl new-acl
    apm acl new-acl {
        acl-order 121
        entries {
            {
                action discard
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
            {
                action allow
                dst-end-port telnet
                dst-start-port telnet
                dst-subnet 0.0.0.0/0
                paths /*
                scheme http
                src-subnet 0.0.0.0/0
            }
        }
    }


You can check this as well in the GUI "Access  ››  Access Control Lists : User-defined ACLs"
