K000152458: Configuration load failure after upgrading from AFM v16.1.x to 17.5.x due to duplicate state in DoS vectors.

Type
Support Solution
Published
2025-07-14
Updated
2025-07-16
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000152458

Description

During an upgrade of a BIG-IP AFM from v16.1.x to v17.5.x, the device fails to come online and enters an offline state. Error logs indicate the configuration cannot be loaded due to a syntax error:

(cfg-sync Standalone)(Offline)(/Common)(tmos)# load sys config verify
Validating system configuration...
<snip>
  /defaults/integrated_auth.conf
Validating configuration...
Loading schema version: 16.1.5
  /config/bigip_base.conf
  /config/bigip_user.conf
Loading schema version: 17.5.0
  /config/bigip.conf
Syntax Error:(/config/bigip.conf at line: 12239) "state" may not be specified more than once

 

An example from the affected configuration in bigip.conf after upgrade:

tcp-flags-uncommon {
    ...
    state detect-only
    state disabled
}

 

Environment

This issue occurs when all of the following conditions are met:

  • BIG-IP system is provisioned with AFM.
  • One or more of these vectors - Bad TCP Flags(All Flags Set and All Cleared), TCP flags - Bad URG, TCP SYN ACK Flood, TCP PUSH Flood or TCP BADACK Flood - are set to a state other than Mitigate on v16.1.x.
  • Device is upgraded from v16.1.x to v17.5.x.
  • On a VIPRION system, the non-primary slots may start to flap quorum states between RUNNING and QUORUM

 

Cause

The affected DoS vectors (e.g., tcp-ack-ts, tcp-flags-uncommon, and bad-tcp-flags-malformed) are introduced or altered in v17.1, but the upgrade process does not properly transition them to v17.5.x when their state is other than Mitigate in v16.1.x. As a result, duplicate state lines appear in the configuration, and cause the system to fail to come online. F5 is tracking this issue as ID1974869.

 

Recommended Actions

If you have not upgraded yet:

  • Set the relevant DoS vector states(listed in the Environment section) to Mitigate before upgrading. After the upgrade, you can modify the state as required.

If the system is already inoperable after upgrade:

  • Manually edit /config/bigip.conf to remove any duplicate state lines, leaving only the intended state (for example, either state detect-only or state disabled, but not both), and save the changes.
  • Validate the configuration using:

tmsh load sys config verify

  • If the validation is successful, load the configuration with:

tmsh load sys config
