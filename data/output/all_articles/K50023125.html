K50023125: Configuring the maximum number of SSL renegotiation attempts for a connection

Applies to

Topic

You should consider using this procedure under the following condition:

  • You want to configure the maximum number of Secure Sockets Layer (SSL) renegotiation attempts for a connection.

Description

The SSL protocol allows either party in the SSL transaction to renegotiate the SSL handshake using new cryptographic parameters. Renegotiation occurs when an SSL session is established and one of the parties in the transaction needs to change the parameters of the SSL connection. For example, a user establishes an SSL session and anonymously browses an online shopping site. When the user logs in (authenticates) to purchase an item, the client and server must renegotiate the SSL handshake using new cryptographic parameters.

By default, the Client SSL profile limits SSL renegotiation attempts for a connection to five attempts per minute. You can change or further limit the number of SSL renegotiation attempts for a connection. To do so, use one of the following methods:

  • Configuring the maximum number of SSL renegotiation attempts for a virtual server connection

    The Max Renegotiations SSL profile setting allows you to configure the maximum number of SSL renegotiation attempts for virtual server connections that the system can receive in one minute. A client with three connections may have a maximum number of SSL renegotiation attempts equal to three times the configured maximum renegotiation value. After the system receives this number of SSL renegotiation records, it closes the connection. The default setting is five renegotiation attempts.

  • Configuring the maximum number of SSL renegotiation attempts for a TMM instance

    The tmm.ssl.maxaggregaterenegotiationperminute database variable allows you to configure the maximum number of SSL renegotiation attempts that a Traffic Management Microkernel (TMM) instance can receive for a connection in one minute. By default, the setting is disabled.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the Configuration utility.
  • You have access to the TMOS Shell (tmsh).

Procedures

Configuring the maximum number of SSL renegotiation attempts for a virtual server connection

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Select the Client SSL profile that is associated with the appropriate virtual server.
  4. From the Configuration menu, select Advanced.
  5. Next to Max Renegotiations, select the Custom check box.
  6. In the Max Renegotiations box, enter the desired value.
  7. Click Update.

Configuring the maximum number of SSL renegotiation attempts for a TMM instance

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Set the tmm.ssl.maxaggregaterenegotiationperminute database key by using the following command syntax:

    modify /sys db tmm.ssl.maxaggregaterenegotiationperminute value <max renegotiation per minute>

    For example, you can set the maximum number of SSL renegotiation attempts that a TMM instance can receive in one minute to 5 by typing the following command:

    modify /sys db tmm.ssl.maxaggregaterenegotiationperminute value 5
