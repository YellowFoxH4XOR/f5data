Description

Virtual Server not passing traffic

 

Environment

  • The virtual server is configured and showing available
  • tcpdump
  • curl

 

Cause

Traffic not coming from upstream device

 

Recommended Actions

Determine whether or not the client is able to exchange traffic with the virtual server

  1. Start the packet captures on both ends, the client and the BIG-IP.
    Example for the BIG-IP:
    tcpdump -s0 -vnni 0.0:nnn -w /var/tmp/example.pcap host <virtual server ip address>

     
  2. Attempt to connect from the client to the Virtual Server:
    Example for the client:
    • Any virtual server listening to TCP:
      telnet <virtual server ip address> <port>

       
    • The Virtual server configured for HTTP:
      curl -v http://<virtual server ip address>:<port>/

       
    • The virtual server configured for HTTPS:
      curl -vk https://<virtual server ip address>:<port>/

       
  3. If the packets captured on the BIG-IP do not match the packets seen on the client, then the packets are either not reaching the BIG-IP or the client.
    lease track the affected packets hop by hop in the network devices (such as firewalls, edge devices, routers, switches) along the path.

 

Additional Information

Correlation among the packets captured on the BIG-IP and the packets seen on the client can be performed following the approach outlined in K62404483: Verifying a FastL4 virtual server is forwarding traffic correctly
