Topic

You should consider using this procedure under the following condition:

  • You want to protect the web application from open redirection attacks. 

Description

One commonly used exploit is called open redirect. A web application is vulnerable to open redirects when parameter values in a GET request allow the request to be redirected to a new location without any validation of the target site. Depending on the vulnerable web application, the open redirection can occur after a certain action, such as a login.

For example, if a web application fails to validate a parameter value to make sure the location is valid, an attacker could change the parameter to send the users to a nefarious site such as https://www.xyz.com/redirect.php?url=http://nefarious.com.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Configure HTTP redirection protection

To configure HTTP redirection protection and protect the web application from open redirection attacks, perform one of the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

17.x and later

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy.
  4. Go to HTTP Message Protection > Headers.
  5. For Redirection Protection select Enabled.
  6. To add Allowed Redirection Domains, select either Exclude Sub-Domains or Include Sub-Domains and enter the name of the domain, or IP address, where users are allowed to be directed.
  7. In the Allowed Redirection Domains section, in the Domain Name box, enter the domain name or IP address where users can be redirected.
    Note: The default is enabled but the wildcard (*) is configured as an allowed domain. This means that the default is no enforcement. To add enforcement, add explicit domain names and remove the wildcard.
  8. Select Add.
  9. Select Save.
  10. Select Apply Policy.

16.x and earlier

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Headers > Redirection Protection.
  3. Verify that the security policy in the Current edited security policy list is the one you want to work on.
  4. Select the Redirection Protection check box.
  5. In the Allowed Redirection Domains section, in the Domain Name box, enter the domain name or IP address where users can be redirected.
    • If no domains are configured, then only relative URIs are allowed (for example, /login.php).
    • If you want users to be able to be redirected to sub-domains of the specified domain, select Include Sub-domains.
    • If you are using the Policy Builder for automatic policy building, the system will replace the * wildcard domain name with the redirection domain names when the tightening period is complete.
  6. Select Add.
  7. Select Save.
  8. Select Apply Policy.
