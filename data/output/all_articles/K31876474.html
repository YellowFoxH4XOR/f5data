Description
After creating a wildcard forwarding virtual server or adding a DNS resolver and BIG-IP AFM network firewall rules to accept, reject, or drop traffic based on the Fully Qualified Domain Name (FQDN), the network firewall rules do not work as expected.

Name resolution on the system works. When doing a DNS lookup with a tool such as nslookup or dig, queries for the FDQN return valid DNS records.

Output of the following command shows a stale date for the last successful refresh, or "Never":
tmsh show security firewall fqdn-info fqdn <FQDN used in policy>

For example:
tmsh show security firewall fqdn-info fqdn example.com
---------------------------
Firewall FQDN Mapping Info:
---------------------------
Total records returned: 1

  FQDN:                     example.com
  Last Refresh:             Feb 5 2020 23:49:59
  Next Refresh:             Feb 5 2020 23:59:59
  Last Successful Refresh:  Jan 01 2020 01:23:45
  DNS Records Valid Until:  Jan 01 2020 01:33:45
  IP Addresses:
                            10.0.0.1

The following tcpdump command captures packets for each FQDN once per refresh interval. This traffic to the DNS servers is sourced from a local loopback IP address.
tcpdump -ni 0.0 port 53 and net 127.0.0.0/8 and host <dns resolver forward zone nameserver IP address>

Environment

  • BIG-IP AFM
  • Your BIG-IP system uses a wildcard forwarding virtual server.
  • You create a DNS resolver with a forward zone, and the zone contains a DNS server address that matches the forwarding virtual server network.
  • You create a network firewall policy that restricts traffic based on fully-qualified domain name (FQDN).

Cause
Bug ID 672491

Recommended Actions

  1. Review the following article for a description of the known issue and upgrade to a fixed version
    K10990182: The net resolver may use an internal IP address as a source address for DNS queries
