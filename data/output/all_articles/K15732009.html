Description
You see traffic going through an HTTP or HTTPS virtual server contains multiple X-Forwarded-For header values

Environment

  • BIG-IP LTM
  • Virtual Server
  • HTTP Profile

Cause
Devices upstream from the BIG-IP can potentially insert additional X-Forwarded-For headers into the request if configured improperly

Recommended Actions

Use an iRule to verify whether inbound connections contain multiple XFF headers and to remove and replace the headers with one written by the BIG-IP.  The example iRule below shows how you might structure an iRule to log and replace XFF headers.

when RULE_INIT { ## Set variable to non-zero value to enable
    set static::xff_logging_debug 1
    set static::header_replace_enable 0
}
when HTTP_REQUEST {
    if { $static::xff_logging_debug } { log local0. "ClientIP: [IP::remote_addr] XFF header: [HTTP::header values X-Forwarded-For]" }
    if { $static::header_replace_enable } {
        if { $static::xff_logging_debug } { log local0. "Replacing XFF Header values with [IP::remote_addr]" }
        HTTP::header remove X-Forwarded-For
        HTTP::header insert X-Forwarded-For [IP::remote_addr]
    }
}

Note: This iRule is provided as an example and has not been tested for functionality. It should not be used in production without previous testing and adjustments to match your use case.
