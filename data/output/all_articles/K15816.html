Known Issue

The BIG-IP system cannot establish a high availability (HA) device trust using IPv6 addresses.

When establishing a device trust, you are required to enter the device IP address for the BIG-IP peer. If you attempt to utilize an IPv6 for the device IP address, the BIG-IP system will fail to communicate with the peer.

Impact

The BIG-IP system is unable to discover the peer BIG-IP using IPv6 IP addresses.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP Configuration utility displays a message similar to the following example, when attempting to add the peer:

    java.io.IOException: Could not read response from server: ParseError at [row,col]:[1,150] Message: The reference to entity "destaddr" must end with the ';' delimiter.
  • The Traffic Management Shell (tmsh) displays a message similar to the following example, when attempting to add the peer:

    Unexpected Error: Could not add ca-device (error from devmgmtd): [evConnection.cpp:162 tryConnect] evConnect(m_ev, fd, (void *) &destaddr, sizeof(destaddr), &::evOutgoingConnection, this, &m_connId): Network is unreachable
  • The system logs a message that appears similar to the following example to the /var/log/ltm file:

    err devmgmtd[6444]: 015a0000:3: getBrowserCert failed: [evConnection.cpp:162 tryConnect] evConnect(m_ev, fd, (void *) &destaddr, sizeof(destaddr), &::evOutgoingConnection, this, &m_connId): Network is unreachable

Workaround

To work around this issue, you can temporarily add IPv4 self IP addresses for your BIG-IP systems, which you can use to discover the peers. Once the device trust has been established, you can use the IPv6 addresses for normal operation. To do so, perform the following procedures:

Configure an IPv4 formatted self IP address

Ensure that you have a properly configured IPv4 formatted IP address within your HA VLAN, configured for each of the BIG-IP systems you intended to join in the device trust.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Important: The IPv4 formatted self IP addresses are not intended to replace your current IPv6 formatted IP addresses. These IPv4 addresses are only added temporarily, to facilitate discovery of peer devices.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Click Create.
  4. Enter the desired Name, IPv4 formatted IP Address and Netmask.
  5. Select either Allow All, or Allow Default, from the Port Lockdown drop-down menu.
  6. Click Finished.
  7. Repeat this procedure for each BIG-IP system.

Note: Verify that the IPv4 addresses are reachable from each BIG-IP system, using network tools such as ping. If you are not able to reach each BIG-IP system, stop here and review your configuration.

Add the peer BIG-IP systems using the IPv4 addresses

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Device Management > Device Trust > Peer List.
  3. Click Add.
  4. Enter the IPv4 formatted Device IP Address, Administrator Username and Administrator Password for the BIG-IP system you want to add.
  5. Click Retrieve Device Information.
  6. Click Finished.
  7. Repeat this procedure for each BIG-IP system you want to add to the Device Trust.

Remove the IPv4 formatted IP addresses (optional)

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Important: Ensure that you do not remove the IPv6 formatted self IP addresses.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Select the box to the left of the IPv4 address you want to remove.
  4. Click Delete.
  5. Repeat this procedure on each BIG-IP system.
