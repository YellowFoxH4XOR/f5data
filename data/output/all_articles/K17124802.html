Known Issue

An iRule that uses a Message Routing Framework (MRF) command to reference a transport-config object fails validation.

This issue occurs when all of the following conditions are met:

  • An iRules command refers to a transport-config object.

    For example:

    ltm rule example {
        when MR_INGRESS {
            MR::message route config example-transport-config pool example-pool 
        }
    }

  • The BIG-IP system validates the iRule when you apply it to the transport-config object

Impact

You are unable to directly refer to a transport-config from an iRules command.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you attempt to add the rule to a transport-config, the operation fails with an error message that appears similar to the following example:

    01070151:3: Rule [/Common/example] error: Unable to find pool (/Common/example-pool) referenced at line 2: [MR::message config /Common/example-transport-config pool /Common/example-pool]

Workaround

To work around this issue, you can load the name of the transport-config into a Tool Command Language (TcL) variable and use it to indirectly refer to the transport-config object.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your environment.

Using the example iRule from the conditions previous example, you can change the iRule to appear as follows:

ltm rule example {
    when MR_INGRESS {
        set tc example-transport-config
        MR::message route config $tc pool example-pool 
    }
}
