Topic

You should consider using these procedures under the following condition:

  • You want to increase the disk space on a BIG-IQ Virtual Edition (VE) system that does not have sufficient disk space for the following tasks:
    • Keeping more user configuration set (UCS) backup files from your managed devices or adding more software installation images
    • Increasing the BIG-IQ system logging volume
    • Accommodating BIG-IQ system database or index growth

Description

The BIG-IQ VE image is available in two sizes for the supported hypervisors. If you have deployed a BIG-IQ VE system using one of these images and find the disk size inadequate to perform various tasks, you can resize the BIG-IQ VE system disk size. The following table describes typical situations in which you may need to increase the disk space.

You want to keep more UCS backup files from your managed devices or add more software installation images.The /shared file system is
    shared across all installation volumes. It includes managed devices and the BIG-IQ UCS backup files as well as software installation images. Depending on your environment, you should consider increasing the disk size for the /shared file system when the utilization exceeds 70%.
    There is an increased volume of BIG-IQ system logging, and the default log rotation policy may not be able to handle the increase.The /var/log file system is
      shared across all installation volumes and includes system logs, such as restjavad logs, database logs, configuration search index logs, and data collection device logs.

        not shared across all installation volumes and is specific to each installation volume. It includes the restjavad configuration data, as well as search indexes and the data collection device indexes. Depending on your environment, you should consider increasing the disk size for the /var file system when the utilization exceeds 70%.

        When you use the resizevol tool in the file system that is not shared across all installation volumes, a resize action occurs on all installation volumes, active and inactive. For example, the BIG-IQ VE system has installation volumes HD1.1 (active) and HD1.2 (inactive). When the /var file system on installation volume HD1.1 is being resized, the /var partition file system across all installation volumes (HD1.1 and HD1.2) is resized at the same time.

        Note: In BIG-IQ 8.0.0, the resizevol command alerts that it is deprecated, and recommends you to use the replacement command tmsh modify sys disk directory <directory_name> new-size <size>. However, if you need to use the resizevol tool again, you can download it from the F5_Networks_Disk_Size_Tools.tar file as discussed in the article K14532110: Using the BIG-IQ disk sizing tools to prepare for an upgrade.

        Before you increase the disk size of individual directories in the BIG-IQ VE system, you must first increase the disk size in the hosting hypervisor configuration. For information on how to increase the disk size in the hosting hypervisor, refer to the documentation from your hypervisor vendor. Depending on your hypervisor, you may have to restart the BIG-IQ VE system for the disk size increase to take effect at the hypervisor level.

        Note: Increasing the disk size beyond 1.9 TB may render the system unbootable. F5 recommends the extended disk space should not exceed 1.9 TB.

        In addition, the BIG-IQ software upgrade does not preserve the new size configuration on the disk directories (that is, file system partitions) when upgrading. F5 recommends that you view and check the image plan hard-coded on each version's ISO file prior to upgrading and compare it with the existing disk usage if you have performed any upsizing on the existing software slot. For more details about tasks to perform before an upgrade, refer to What disk size tasks should I perform before an upgrade? in BIG-IQ Centralized Management Disk Space Management.

        Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

        The procedures described in this article are suitable if you are planning to increase the disk directory volumes on the current active software volume. However, if you are doing an upgrade and require to increase the disk directory volumes on the active and inactive software volumes, refer to the article that describe the considerations and resizing procedures in K14532110: Using the BIG-IQ disk sizing tools to prepare for an upgrade.

        Prerequisites

        You must meet the following prerequisites to use these procedures:

        • You have deployed the BIG-IQ VE system using a BIG-IQ VE 5.4.0 or later image on your hypervisor.
        • You have provisioned sufficient disk resources for the BIG-IQ VE guest on your hypervisor to accommodate the amount of disk space increase you want.
        • You have administrative access to the BIG-IQ VE system.

        Procedures

        • Check the disk size on the BIG-IQ VE system
        • Resize the /shared file system for keeping more UCS backup files or adding more software images
        • Resize the /var/log file system for increased volume of the BIG-IQ system logging
        • Resize the /var file system for database or index growth

        Check the disk size on the BIG-IQ VE system

        Before resizing the file system, you should check if there is sufficient physical disk space on the BIG-IQ VE system. To do so, perform the following procedure:

        Impact of procedure: The following procedure should not have a negative impact on your system.

        1. Log in to the command line of the BIG-IQ VE system.
        2. To check the current size of the directories, enter the following command:

          tmsh show sys disk directory

          The output appears similar to the following example:

          Directory Name                  Current Size    New Size
          --------------                  ------------    --------
          /config                         503808          -
          /shared                         31744000        -
          /var                            26214400        -
          /var/log                        7168000         -

        3. To determine how much disk space is available on the BIG-IQ VE system, enter the following command:

          pvs

          The amount of free disk space is listed under PFree. For example, the following command output shows 103 GB of free disk space:

            PV         VG        Fmt  Attr PSize   PFree
            /dev/sda3  vg-db-sda lvm2 a--  103.78g 103.55g

        Note: If the free disk space does not meet your resizing requirement, you must first increase the disk size in the hosting hypervisor configuration. For information on how to increase the disk size in the hosting hypervisor, refer to the documentation from your hypervisor vendor.

        Resize the /shared file system for keeping more UCS backup files or adding more software images

        To accommodate more UCS backup files or more software installation images on the BIG-IQ VE system, you may have to resize the /shared file system. To do so, perform the following procedure:

        Impact of procedure: F5 recommends that you perform this procedure during a suitable maintenance window. Reminder: the BIG-IQ software upgrade does not preserve the new size configuration on the disk directory volumes. Increasing the disk directory size on the BIG-IQ VE is irreversible because F5 does not support disk shrinking.

        1. Log in to the command line of the BIG-IQ VE system.
        2. To resize the /shared file system depending on the BIG-IQ version: 
          • For BIG-IQ 8.0.0 and later, use the following tmsh command syntax:

            tmsh modify sys disk directory /shared new-size <size in kilobytes>

            For example, to resize the /shared file system to 50 GB using the size in KB, use the following command:

            tmsh modify sys disk directory /shared new-size 52428800

            The BIG-IQ system requires restarting to activate the new size configured. To restart the BIG-IQ system, use the following command:

            reboot

          • For earlier BIG-IQ versions, use the following resizevol command syntax:

            resizevol /shared <new size in kilobytes>

            For example, to resize the /shared file system to 50 GB using the size in KB, use the following command:

            resizevol /shared 52428800

        3. Verify the /shared file system is successfully resized by entering the following command:

          df -k /shared

          Alternatively, you can use the tmsh command to verify if the new size is active:

          tmsh show sys disk directory

        Resize the /var/log file system for increased volume of the BIG-IQ system logging

        To accommodate an increased volume of BIG-IQ system logging, you may have to resize the /var/log file system. To do so, perform the following procedure:

        Impact of procedure: F5 recommends that you perform this procedure during a suitable maintenance window. Reminder: the BIG-IQ software upgrade does not preserve the new size configuration on the disk directory volumes. Increasing the disk directory size on the BIG-IQ VE is irreversible because F5 does not support disk shrinking.

        1. Log in to the command line of the BIG-IQ VE system.
        2. To resize the /var/log file system depending on the BIG-IQ version:
          • For BIG-IQ 8.0.0 and later, use the following tmsh command syntax:

            tmsh modify sys disk directory /var/log new-size <size in kilobytes>

            Note: Using the tmsh command to modify the disk directory requires a system restart to enabled the new size.

            For example, to resize the /var/log file system to 10 GB using the size in KB, use the following command:

            tmsh modify sys disk directory /var/log new-size 10485760

            The BIG-IQ system requires restarting to activate the new size configured. To restart the BIG-IQ system, use the following command:

            reboot

          • For earlier BIG-IQ versions, use the following resizevol command syntax:

            resizevol /var/log <new size in kilobytes>

            For example, to resize the /var/log file system to 10 GB using the size in KB, use the following command:

            resizevol /var/log 10485760

        3. Verify the /var/log file system is successfully resized by entering the following command:

          df -k /var/log

          Alternatively, you can use the tmsh command to verify if the new size is active:

          tmsh show sys disk directory
