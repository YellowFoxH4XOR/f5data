K000163287: BIG-IP ASM False Positives When Inspecting JWT Authorization Headers

Type
Support Solution
Published
2026-09-10
Updated
2026-09-10
Status
Final
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000163287

Description

BIG-IP ASM can block valid requests containing JWT tokens in the Authorization HTTP header when attack signatures match content revealed after header decoding, even though the original encoded header does not contain the signature pattern.


Observed signatures include:


200018080 — Trailing Space in Header Name

200001175 — HTML entity - &#x... (Headers)

200101537 — Shell command processor (ash/bash) access (Header)

etc.

 

Environment

  • Product: BIG-IP ASM
  • Requests containing JWT tokens in the Authorization HTTP header
  • Attack signature inspection enabled for the relevant security policy

Cause

A fix associated with Bug ID785873 changed how BIG-IP ASM processes the Authorization header. ASM can inspect decoded header content for attack signatures. Characters or sequences revealed during decoding can therefore match signatures that do not match the original encoded header value.


Answer/Recommended Actions

1. Identify the attack signatures matching the valid request:

2. Confirm that the matches occur in the Authorization HTTP header containing the valid JWT token.

3. Override or disable only the affected signatures for the relevant Authorization header context in the applicable ASM security policy.

4. Do not disable the signatures globally unless a separate security assessment confirms that global deactivation is appropriate.

5. Retest the valid JWT requests and confirm that unrelated headers and request components remain protected by the attack signatures.

 

Additional Information

The observed matches can be an expected side effect of ASM inspecting decoded Authorization header content and do not indicate that the fix associated with Bug ID785873 is absent.
