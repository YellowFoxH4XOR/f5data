K000163089: BIG-IP SMTP Monitor Segments HELO/QUIT Commands into Multiple TCP Segments

Source

Description

The BIG-IP LTM SMTP monitor can transmit SMTP commands across multiple TCP segments. For example, HELO or QUIT may be split across segments. SMTP commands are valid when the TCP byte stream is reassembled and the command is terminated with <CRLF>. However, some SMTP server implementations may not correctly process SMTP monitor connection causing the monitor to be marked DOWN.

Environment

  • Product: BIG-IP LTM
  • Feature: SMTP monitor

Cause

Behavior is described by Bug ID 539939 - SMTP Tcl monitor segments traffic sent to monitored servers. 

Answer/Recommended Actions

  1. Verify that the SMTP server complies with RFC 5321, including Sections 2.3.7 and 2.3.8.
  2. If the SMTP server does not correctly handle commands split across TCP segments, consult the SMTP server vendor for an implementation-specific update or configuration recommendation.
  3.  If the SMTP vendor cannot provide resolution, use an alternative monitor (ICMP gateway, TCP half open, or TCP monitor, for example).

No specific server-side configuration is generally required for a RFC 5321-compliant SMTP server, but this depends on the SMTP server implementation.

Additional Information

  • SMTP commands and replies are transmitted as lines terminated by <CRLF>.
  • TCP packet boundaries must not be used as SMTP command boundaries.
  • An RFC 5321-compliant SMTP server should correctly handle SMTP commands when command bytes span multiple TCP segments.
  • Details of specific SMTP server products or releases that may mishandle segmented commands are not documented.
