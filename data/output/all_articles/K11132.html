Known Issue

This is the result of a known issue. If you change the value of the CPU temperature threshold using the bigpipe db platform.cpu.temperature.threshold command, the setting will revert back to the default value within minutes.

Additionally, if audit logging is enabled for the mcpd process, the BIG-IP system erroneously logs messages similar to the following example every two minutes to the /var/log/audit file:

Note: The log messages are a related issue, and occur regardless of whether the bigpipe db platform.cpu.temperature.threshold command is issued.

mcpd[3486]: 01070417:5: AUDIT - user Unknown - transaction #205492-1 - object 0 - create_if { db_variable { db_variable_name "platform.cpu.temperature.threshold" db_variable_value "75" db_variable_default "0" db_variable_sync_type "private_internal" db_variable_data_type "Integer" db_variable_minimum "0" db_variable_maximum "65535" db_variable_display_name "platform.cpu.temperature.threshold" } }
mcpd[3486]: 01070417:5: AUDIT - user Unknown - transaction #205493-1 - object 0 - create_if { db_variable { db_variable_name "platform.cpu.fanspeed.threshold" db_variable_value "3000" db_variable_default "0" db_variable_sync_type "private_internal" db_variable_data_type "Integer" db_variable_minimum "0" db_variable_maximum "65535" db_variable_display_name "platform.cpu.fanspeed.threshold" } }
mcpd[3486]: 01070417:5: AUDIT - user Unknown - transaction #205494-1 - object 0 - create_if { db_variable { db_variable_name "platform.chassis.temperature.threshold" db_variable_value "55" db_variable_default "0" db_variable_sync_type "private_internal" db_variable_data_type "Integer" db_variable_minimum "0" db_variable_maximum "65535" db_variable_display_name "platform.chassis.temperature.threshold" } }
mcpd[3486]: 01070417:5: AUDIT - user Unknown - transaction #205495-1 - object 0 - create_if { db_variable { db_variable_name "platform.chassis1.temperature.threshold" db_variable_value "75" db_variable_default "0" db_variable_sync_type "private_internal" db_variable_data_type "Integer" db_variable_minimum "0" db_variable_maximum "65535" db_variable_display_name "platform.chassis1.temperature.threshold" } }
mcpd[3486]: 01070417:5: AUDIT - user Unknown - transaction #205496-1 - object 0 - create_if { db_variable { db_variable_name "platform.chassis2.temperature.threshold" db_variable_value "75" db_variable_default "0" db_variable_sync_type "private_internal" db_variable_data_type "Integer" db_variable_minimum "0" db_variable_maximum "65535" db_variable_display_name "platform.chassis2.temperature.threshold" } }

These logs messages do not indicate a problem, and may be safely ignored.

Note: The issues described in this article affect all hardware platforms except for the VIPRION platform.

F5 Product Development tracked this issue as ID 243394 (formerly CR136576) and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WAN Optimization, or Edge Gateway Release Notes.

Workaround

Although there is no workaround for setting the CPU temperature threshold, there are several workarounds for preventing the threshold log messages described in this article. To prevent the threshold log messages, perform one of the following procedures:

  • Disabling audit logging for the mcpd process
  • Configuring a syslog filter to prevent the messages from being logged to the /var/log/audit file
  • Configuring a syslog filter to prevent the messages from being logged to a remote log server

Disabling audit logging for the mcpd process

Note: By default, audit logging is disabled for mcpd.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs.
  3. Click the Options menu.
  4. In the Audit Logging section, select Disable from the MCP drop-down menu.
  5. Click Update.

Configuring a syslog filter to prevent the messages from being logged to the /var/log/audit file

  1. Log in to the BIG-IP command line.
  2. Using a text editor, such as vi, create the /tmp/syslog.inc file.
  3. Enter the following lines:

    syslog include "
    filter f_audit {
    facility(local0) and match(\"AUDIT\")
    and not match(\"platform.cpu.fanspeed.threshold\")
    and not match(\"platform.cpu.temperature.threshold\")
    and not match(\"platform.chassis.temperature.threshold\")
    and not match(\"platform.chassis1.temperature.threshold\")
    and not match(\"platform.chassis2.temperature.threshold\");
    };"
  4. Save and exit the file.
  5. Run the following command to import the syslog filter you created:

    bpsh < /tmp/syslog.inc

Configuring a syslog filter to prevent the messages from being logged to a remote log server

Important: Remote logging will be briefly interrupted while this procedure is performed.

  1. Log in to the BIG-IP command line.
  2. Using a text editor, such as vi, create the /tmp/syslog.inc file.
  3. Enter the following lines, replacing <udp|tcp> with either udp or tcp, <IP> with the IP address of the remote syslog server, and <port> with the port number of the remote syslog service:

    Note: Typically, the syslog service runs on port 514.

    syslog include "
    filter f_myaudit {
    not match(\"platform.cpu.fanspeed.threshold\")
    and not match(\"platform.cpu.temperature.threshold\")
    and not match(\"platform.chassis.temperature.threshold\")
    and not match(\"platform.chassis1.temperature.threshold\")
    and not match(\"platform.chassis2.temperature.threshold\");
    };

    destination d_loghost {
    <udp|tcp>(\"<IP>\" port(<PORT>));
    };

    log {
    source(s_syslog_pipe);
    filter(f_myaudit);
    destination(d_loghost);
    };"

    For example, if you have a remote log server at 10.0.0.1 that listens on TCP port 514, and a remote log server at 10.0.0.2 that listens on UDP port 514, you would enter the following lines:

    syslog include "
    filter f_myaudit {
    not match(\"platform.cpu.fanspeed.threshold\")
    and not match(\"platform.cpu.temperature.threshold\")
    and not match(\"platform.chassis.temperature.threshold\")
    and not match(\"platform.chassis1.temperature.threshold\")
    and not match(\"platform.chassis2.temperature.threshold\");
    };

    destination d_loghost {
    tcp(\"10.0.0.1\" port(514));
    udp(\"10.0.0.2\" port(514));
    };

    log {
    source(s_syslog_pipe);
    filter(f_myaudit);
    destination(d_loghost);
    };"
  4. Save and exit the file.
  5. Enter the following command to delete the current remote syslog configuration:

    Important: This step disables all remote logging.

    bigpipe syslog remote server none
  6. Run the following command to import the new syslog configuration:

    bpsh < /tmp/syslog.inc
