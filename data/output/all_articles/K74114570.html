A cross-site request forgery (CSRF) vulnerability in the APM webtop, may allow attacker to force an APM webtop session to log out and require re-authentication. (CVE-2018-15334)

Impact

A remote attacker may be able to force a BIG-IP APM webtop session to log out and require reauthentication.

Mitigation

BIG-IP 15.x and earlier

There is no mitigation for BIG-IP APM 15.x and earlier versions.

BIG-IP 16.x and later

In BIG-IP APM 16.0.0 and later versions, users can mitigate this vulnerability by setting the samesite cookie option to strict under the affected access profile. This mitigation applies only if all domains of the servers involved are subdomains of the same parent domain. For example, in the federation use case, the IDP and the SP should be subdomains of the same parent domain for the samesite cookie to work. To set the samesite cookie option to strict, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative effect on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Profiles / Policies.
  3. Select the access profile.
  4. Select SSO / Auth Domains.
  5. In the Cookie Options section, select Samesite and then select Strict from the list.
  6. Select Update.
