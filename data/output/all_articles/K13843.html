Known Issue

Performance HTTP virtual connections may use the BIG-IP non-floating self IP address as the source address when connecting to pool members.

This issue occurs when the following conditions are met:

  • The virtual server is configured to use a FastHTTP profile.

Performance HTTP is a virtual server type that combines SNAT and OneConnect functionality to process all connections to the pool members. By design, the system should use a SNAT pool or the BIG-IP floating self IP address as the source address when connecting to pool members. This issue causes the system to incorrectly use the BIG-IP non-floating self IP address as the source address when connecting to pool members.

Impact

You may encounter traffic disruption during failover, as the connections are not processed using the floating self IP address.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You may encounter traffic disruption during failover as the connections are not processed using the floating self IP address.
  • Packet captures may indicate that Performance HTTP connections to the pool members originate from the BIG-IP non-floating self IP address.
  • You may encounter port exhaustion, depending on the self IP configuration. For example, if multiple floating self IP addresses and only one non-floating self IP address are configured on the VLAN, the system may experience port collisions during heavy traffic conditions.

Workaround

You can work around this issue by changing the virtual server type to Standard and associating an HTTP profile with the virtual server.
