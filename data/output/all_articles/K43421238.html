Description

After upgrading the device, some virtual server getting disconnections or reset from F5. Below logs will be found under /var/log/ltm logs:
May 24 00:19:18 bigip.hostname.com err tmm1[11965]: 01480024:3: Can't bind the flow, waiting for config response on channel mem://bd0
May 24 00:19:18 bigip.hostname.com err tmm3[11965]: 01480024:3: Can't bind the flow, waiting for config response on channel mem://bd4
 

Environment

  • Upgraded device
  • Few virtual servers having connectivity issues 
  • Multiple device provisioned but System > resource provisioning shows only LTM
  • ASM policies configured 
     

Cause

For unknown reasons, ASM does not show provisioned after upgrade. Since ASM policies are configured, bd process gets confused and throw above error and can result in bd core. 
 

Recommended Actions

  • Confirm if ASM configuration is required and should be enabled on the system.
    • If yes, then provision the ASM module by going to System > Resource Provisioning and set the appropriate provisioning option for Application Security (ASM).
  • If ASM configuration is not supposed to be enabled, then remove ASM policies from virtual servers.
    • To do so, go to Local Traffic > Virtual Servers > Virtual Server List > <virtual server name> > Security and set Application Security Policy to disabled.
