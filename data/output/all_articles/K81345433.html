Description

Before the BIG-IP APM system can establish itself as an Active Directory Federated Services (ADFS) Proxy, it must establish and maintain a certificate based trust between itself and ADFS. This article intends to explain the requirements and flows involved in establishing, reestablishing, and renewing an ADFS trust on the BIG-IP APM system. To begin, the ADFS environment must be configured correctly for a ADFS proxy server. For more information, refer to Planning Federation Server Proxy Placement and Best practices for securing Active Directory Federation Services.

Environment

The ADFS configuration environment on the BIG-IP APM system consists of the following:

  • A BIG-IP LTM pool of ADFS pool members: The AD FS servers must be configured to support AD FS proxy.
  • Client and Server SSL Profiles: The server SSL profile's Server Name attribute needs to be configured with the ADFS fully qualified domain name (FQDN). To discover the correct ADFS FQDN to use, on ADFS run the following PowerShell command syntax:

    Get-ADFSProperties | Select-Object -Property HostName

  • A virtual server: Configure a virtual server that as the ADFS proxy on the BIG-IP APM system.
    • The Service Port matches the one used on ADFS, which is 443 by default.
    • Implement pool and SSL profile objects explained previously.
    • Implement an HTTP profile.
    • Enable ADFS Proxy in the Access Policy section (when enabled the Establish Trust button appears).
  • An ADFS username and password.
  • A certificate.

Establishing trust

To establish ADFS trust for the first time within a BIG-IP APM ADFS proxy virtual server, perform the following procedure:

  1. Log in to the Configuration Utility
  2. Go to Local Traffic > Virtual Servers.
  3. Select the appropriate virtual server.
  4. Under Access Policy, for ADFS Proxy, select the Enabled check box
  5. Select Establish Trust.

    Note: If it reads Trust Certificate: none to the left of the Establish Trust button, trust has not been established yet.

  6. Provide credentials in UPN format (domain\username or username@domain.com).
  7. Enter an arbitrary value for certificate name.

    Note: This name is used to name the self-signed SSL certificate and key that is dynamically created and configured in the server SSL profile specified in the virtual server. Therefore, you must provide the name of a certificate that does not already exist on the BIG-IP system. If a certificate with the same name exists, the trust establishment fails.

  8. Click OK.

After you click OK, the resulting workflow follows:

  1. The BIG-IP system dynamically creates a 2048 bit self-signed RSA certificate and key with an immutable 20-day validity period.
  2. The BIG-IP system attempts to register the certificate with ADFS using the ADFS pool configured on the BIG-IP APM ADFS proxy virtual server.
  3. If ADFS accepts the certificate registration request, then the BIG-IP system links the certificate and key to the server SSL profile configured on the BIG-IP APM ADFS proxy virtual server, disassociating, but not removing from the system, any existing certificate and key.

    Note: If ADFS rejects the certificate registration request, the BIG-IP system displays the message returned from ADFS.

  4. When trust establishment is successful, the virtual server's ADFS proxy attribute displays the name of the trust certificate and its expiration date along with a Reestablish Trust button.

Reestablishing trust

Selecting Reestablish Trust from the virtual server's ADFS Proxy attribute is the same process and workflow as establishing trust. 

Note: Beginning in BIG-IP 14.0.0, using the fix for ID 699118, the certificate name value is not required for trust reestablishment.

Renewing trust

When the ADFS trust certificate's remaining validity period is six days or less, the BIG-IP APM system automatically attempts to renew ADFS trust using HTTP POST and TLS authentication. Refer to Proxy Trust Renewal. If automatic ADFS trust renewal fails, the BIG-IP APM system logs the failed event in /var/log/apm and automatically attempts trust renewal every minute until trust is renewed.

Additional Information

You can also enable ADFS proxy on a virtual server using the TMOS Shell (tmsh). To do so, use the following command syntax:

tmsh modify ltm virtual <VS-name> profiles add { adfs_proxy }

To establish trust, use the following command syntax:

tmsh establish-adfs-trust --vs <VS-name> --cert <trust-cert-name> --username <name> [ --password <password> ]
