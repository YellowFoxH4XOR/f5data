Introduction

When an App or other configuration is deployed from Central Manager to a Next instance, the configuration validation may fail. Central Manager may provide an ambiguous reason for the failure, or in rare cases the configuration validation may fail without Central Manager knowing. This article provides some pointers to monitoring for and resolving such cases.

 

Environment

Central Manager web UI or API deploying Apps or other configuration to BIG-IP Next. 

 

Symptoms

  • An App is deployed but does not work.
  • An App or other configuration is deployed but the response indicates the deployment failed.

 

Collect Data

Logs must be reviewed. There are two methods, either via a qkview or by directly accessing the system hosting the Next instance.

 

qkview

In many cases, it may not be possible to login to the Next host system or access logfiles. In which case, collecting a qkview via Central Manager is the simplest approach.

Generate a QKView diagnostic file for a BIG-IP Next instance using BIG-IP Next Central Manager

Find the f5-fsm-tmm and f5-csm-icb logfiles in the qkview by extracting the qkview tar archive, or uploading to iHealth.

The pod logs in the qkview tar are found in qkview/subpackages/host-qkview/qkview/filesystem/var/log/pods/:

$ ls -l ./qkview/subpackages/host-qkview/qkview/filesystem/var/log/pods/default_f5-fsm-tmm-*/f5-fsm-tmm/
total 462
-rw-r----- 1 moffatt users 2891134 Apr 18 03:13 0.log

$ ls -l ./qkview/subpackages/host-qkview/qkview/filesystem/var/log/pods/default_f5-csm-icb-*/f5-csm-icb/
total 607
-rw-r----- 1 moffatt users 2934053 Apr 18 03:13 0.log

Or, after uploading the qkview to iHealth browse to "Files -> subpackage-logs" and look for the files starting with f5-fsm-tmm-* and f5-csm-icb-*

Analysing

The f5-fsm-tmm pod log will drop log messages from tmm-dpvd, which validates data before it is sent to deployed to tmm.

Here is an example failure:

2024-01-01T00:00:01.000000001Z stdout F tmm-dpvd 2024/01/01 00:00:00.000002 Error: vs_validation.go:132 Configured application /app/tenant<string>:application1/stack/tenant<string>:application1:<name1> has conflicting traffic matching criteria with application /app/tenant<string>:application2/stack/tenantjtIcjihnRVuKRU0IC0ysVg:application2:<name2> 

The error from tmm-dpvd says that the application being deployed conflicts with a second application. The resolution would be to undeploy the new application and fix the conflict - in this case traffic matching criteria indicates that there is an IP and port overlap.

The f5-csm-icb pod takes care of updating the configuration database. Errors here will mean that the configuration is not updated correctly to the saved configuration.

2024-06-20T12:56:27.810856944Z stdout F 2024/06/20 12:56:27.810772 Info: f5-csm-jp-jobmanager: jobmanager.go:780  Writing error message: &{14432-00201 declareJobErrorGeneric {"14432-00201":["[Error on SaveL1Network([{"id":"3bfc0231-cfa7-4792-b4a7-f31dde14a97c","l1Link":{"linkType":"Interface","name":"1.2"},"name":"External-interface","vlans":[{"name":"External","selfIps":[{"address":"10.107.1.1/29","deviceName":"1.1"}]}]},{"id":"b6bdc33a-307a-4f2a-b78c-6ecda81348a4","l1Link":{"linkType":"Interface","name":"1.1"},"name":"Internal-interface","vlans":[{"name":"Internal","selfIps":[{"address":"10.107.1.9/29","deviceName":"1.2"}]}]},{"l1Link":{"linkType":"Interface","name":"1.3"},"name":"ha-dp","vlans":[{"name":"ha-dp","selfIps":[{"address":"10.107.1.25/29","deviceName":"1.4"}]}]},{"l1Link":{"linkType":"Interface","name":"1.4"},"name":"ha-cp","vlans":[{"name":"ha-cp","selfIps":[{"address":"10.107.1.16/29","deviceName":"1.3"}]}]}]). The error seen here is:

Error writing to tables: ERROR: duplicate key value violates unique constraint "KEY_internal_self-ip_uniqueName" (SQLSTATE 23505)"

Problems such as this are indicative of a procedural issue. A part of the existing configuration may need to be deleted or changed before the desired configuration can be made. If Central Manager deploys config that results with errors in this log, a support case may need to be opened.

 

Summary

The f5-fsm-tmm and f5-csm-icb are the first logs to consult suspected configuration validation problems on a Next instance. They provide greater insight into error conditions that may not be well explained by the result returned to Central Manager or via the API.
