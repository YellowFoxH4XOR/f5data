Description

When attempting to perform a backup of a BIG-IP device from BIG-IQ, the operation fails with an HTTP 500 error. The error message returned is:

status:500, body:{ "servlet":"com.f5.rest.app.RestServerServlet-51cdd8a", "message":"AsyncContext timeout", "url":"/mgmt/tm/shared/sys/backup", "status":"500" }

This issue may occur even when other similar devices back up successfully.

Environment

  • BIG-IQ 
  • BIG-IP 17.x or later
  • Backup initiated via iControl REST API

Cause

The cause may be insufficient management or Java memory allocation for iControl REST asynchronous backup tasks, or device-specific conditions such as high API load, large configuration, or accumulated REST state.

Answer/Recommended Actions

Increase management and Java memory allocation on the affected BIG-IP device. Step 2 is necessary only if the BIG-IP system has default memory allocation settings (500 MB or less—the "Large" value in the GUI). The recommended below values are only applicable when BIG-IP has only one module provisioned - LTM, GTM, etc. For more information please refer to the related content below.

 

  • Schedule a maintenance window, as increasing management memory will cause a TMM restart and possible failover.
  • Run the following commands:
  1. Verify management and Java memory: 

 

  • tmsh list sys db provision.extramb

and

 

  • tmsh list sys db provision.restjavad.extramb

       2. Increase management memory if needed:

 

  • tmsh modify /sys db provision.extramb value 1280
  • tmsh save /sys config partitions all

       3. Increase restjavad memory:

 

  • tmsh modify sys db provision.restjavad.extramb value 768
  • bigstart restart restjavad

Note: Management memory (provision.extramb) should be at least 125% of the Java memory (provision.restjavad.extramb).

If the issue persists, review the device for:

 

  • High number of concurrent API calls or asynchronous tasks
  • Large or complex configuration objects
  • Accumulated REST state or stale tasks.
  • Increase slightly the values of memory provisioning

Additional Information

  • The issue may be device-specific, even among otherwise identical devices in a sync group.
  • Memory and Java heap settings are not synchronized between HA peers; each device must be configured individually.
  • Increasing restjavad memory does not impact traffic, but increasing management memory does.
