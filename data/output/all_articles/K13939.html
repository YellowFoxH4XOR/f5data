Known Issue

The SSL::profile command fails to search for the partition or path of a specified SSL profile.

An iRule command that specifies other objects, such as virtual servers and pools, will search for the partition or path of the specified object.

Impact

The affected iRule will fail to load. In addition, any virtual servers using the affected iRule will not process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When the affected iRule fails to load, a TCL error message may be logged in the /var/log/ltm file. The error message may use the following syntax:

    01220001:3: TCL error: /Common/{iRule_Name} <CLIENT_ACCEPTED> - command returned bad code: 18 while executing "SSL::profile {SSL_Profile_Name}"

    For example:

    01220001:3: TCL error: /Common/example_irule <CLIENT_ACCEPTED> - command returned bad code: 18 while executing "SSL::profile example_ssl_profile"
  • Virtual servers using the affected iRule are not able to process traffic.

Workaround

To work around this issue, you can amend the iRule to include the administrative partition path in the SSL profile name. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Select the name of the affected iRule.
  6. In the Definition text box, locate the line that begins with the following:

    SSL::profile

  7. Amend this line to include the administrative partition path to the SSL profile name.

    For example, the example_ssl_profile SSL profile is configured in the /Common administrative partition. Before modification, the stanza may appear as follows:

    when CLIENT_ACCEPTED {
    SSL::profile example_ssl_profile
    }

    After modification, the stanza may appear as follows:

    when CLIENT_ACCEPTED {
    SSL::profile /Common/example_ssl_profile
    }

  8. To save the modification, click Update.
