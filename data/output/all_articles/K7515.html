Known Issue

This is the result of a known issue. Disabling the DEFAULT or native ciphers in a Server SSL profile causes the Traffic Management Microkernel (TMM) to crash when the Server SSL profile finishes the handshake.

For example, if the default ciphers list in the Server SSL profile is configured as DEFAULT, this optimizes the SSL stack used by the SSL profile. Changing the ciphers from DEFAULT to ALL:!NATIVE disables the optimized SSL stack. As a result, the SSL session is handled by OpenSSL and a session is not established, which causes TMM to crash.

F5 Product Development tracked this issue as CR79616, and it was fixed in BIG-IP LTM 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.
