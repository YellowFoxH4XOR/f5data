K000151551: CSR does not include "Subject Alternative Name (SAN)" or "Key Usage" parameters when CSR is created on GUI with "Issuer : Certificate Authority" option.

Type
Support Solution
Published
2025-05-28
Updated
2025-05-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000151551

Description

While creating CSR (which is to be signed by external Certificate Authority) with "Issuer: Certificate Authority" option on GUI, "Subject Alternative Name" and "Key Usage" options are not set on the generated CSR.

On the following example, while creating CSR, "Subject Alternative Name" is set to "DNS:shopping.f5ss.local" and "Key Usage" is set to "nonRepudiation,digitalSignature,keyEncipherment".

 

Figure: CSR generation GUI screen

 

After pressing "Finished" button and created CSR, the generated CSR shows empty "Subject Alternative Name" and "Key Usage" parameters, as shown below.

 

Figure: GUI generated CSR

 

Additionally, if SAN is set with invalid prefix "dns:" (small character), expected behavior is to receive an error "Invalid Subject Alternative Name.", as shown below. However, on 17.5.0, no error is thrown.

 

Figure: error message while setting SAN with invalid prefix character

 

Environment

  • Running software version with Bug ID 1600853 fix (as of article publication, 17.5.0 only).
  • "Subject Alternative Name" or "Key Usage" value is set while creating CSR with "Issuer: Certificate Authority" option on GUI.

 

Cause

Bug ID 1959629 (regression of Bug ID 1600853 fix).

 

Recommended Actions

Workaround is to generate CSR by TMSH. Here is example TMSH command to generate private key and CSR.

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# create sys crypto key web501.f5ss.local key-type rsa-private key-size 2048

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# create sys crypto csr web501.f5ss.local key web501.f5ss.local common-name web005.f5ss.local organization "F5SS" ou "IT dept" city "Minato-ku" state "Tokyo" country "JP" key-usage "nonRepudiation,digitalSignature,keyEncipherment" subject-alternative-name "DNS:shopping.f5ss.local"

 

After created CSR by TMSH, generated CSR should have "Subject Alternative Name" and "Key Usage" parameters, as shown below.

Figure: CSR generated by TMSH
