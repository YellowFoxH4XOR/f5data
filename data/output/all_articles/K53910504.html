Issue

Description

Correctly configuring the BIG-IP ASM system in a high-availability (HA) environment can help you avoid problems such as the following:

  • Inappropriately or unexpectedly overwritten policies
  • Lost learning suggestions
  • Unpredictable policy states

Environment

This article is for anyone using BIG-IP ASM in an HA environment but is most relevant if:

  • You are running two or more traffic groups.
  • You are using Automatic Policy Builder (APB).
  • Your BIG-IP ASM sync group is set to autosync.

Cause

BIG-IP ASM replicates its policies using database replication and has no understanding of traffic groups, network objects (such as self IPs, virtual servers, or pools), or standard sync/failover groups.  When APB updates a BIG-IP ASM policy and you have set your sync group to autosync, these changes are pushed to the peer device, along with copies of all the other policies on that BIG-IP ASM system.  If you have learning suggestions or changes to a policy on the peer, those are lost, even if they are in a different policy from the one that APB changed.  If you have APB enabled on both BIG-IP ASM systems, you can create a race condition where each system is attempting to update its peer while simultaneously receiving updates from that peer.

Recommended Actions

  • For simplicity, It is best to have the failover group also be the BIG-IP ASM sync group.  In some situations, such as offsite mirroring of the BIG-IP ASM policies for disaster recovery, this may not be possible or desirable.  For more information, refer to the Automatically Synchronizing Application Security Configurations chapter of the BIG-IP Application Security Manager: Implementations manual.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.
     
  • APB should only be enabled on a single BIG-IP ASM at a time, regardless of the number of traffic groups.
  • You should create and delete policies on one device and push to the peers. You should do this on the same BIG-IP ASM system that is running APB.
Additional Information

For central management of policies and to allow multiple BIG-IP ASM systems to run APB, consider using BIG-IQ 5.4 or later.  This is the only way to run APB on multiple BIG-IP ASM systems in the same sync group.  For more information, refer to the Managing Application Security Policies in Web Application Security chapter of the F5 BIG-IQ Centralized Management: Security manual.
