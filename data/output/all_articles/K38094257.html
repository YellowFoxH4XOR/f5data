K38094257: Changing the connection.vlankeyed database key causes some asymmetrically routed connections to fail

Type
Known Issue
Published
2017-03-08
Updated
2025-02-06
Applies to

Source

Known Issue

When you modify the connection.vlankeyed database key, some asymmetrically routed connections unexpectedly fail.

This issue occurs when the following condition is met:

  • You modify the connection.vlankeyed database key.

    For example, you set the database key value to disable. For more information, refer to K13558: Allowing asymmetrically routed connections across multiple VLANs (11.x - 12.x).

Impact

Some connections using asymmetrical routing do not reach their destination.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Traffic Management Microkernel (TMM) process drops some asymmetrically routed sessions.
  • When you restart the TMM process, the system correctly routes all sessions.

Workaround

To work around this issue, you can restart the TMM process. To do so, perform the following procedure:

Impact of workaround: You should perform the workaround during a maintenance window, as it interrupts traffic.

  • You can type the following command from the Advanced Shell (bash) on a BIG-IP system:

    bigstart restart tmm

  • You can type the following command from the Advanced Shell (bash) on a VIPRION host or VIPRION-based vCMP guest:

    clsh bigstart restart tmm
