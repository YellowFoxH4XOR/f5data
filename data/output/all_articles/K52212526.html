Known Issue

The BIG-IP ASM system may fail to apply a security policy completely.

This issue occurs when all of the following conditions are met:

  • The Policy Builder utility applies a security policy either manually or automatically.
  • You restart the BIG-IP ASM bd or bd_agent process while the utility applies the security policy.

Impact

The security policy does not apply completely and appears to stop responding.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The security policy appears to stop responding and continuously logs a message in the /ts/log/asm_config_server.log file that appears similar to the following example:

    F5::SetActive::Impl::send_update_core,,Still waiting for response from bd_agent (XXX seconds)

  • The asm_config_server process displays high CPU usage during the application of the security policy.

Workaround

There is no workaround for this issue. However, you can recover from this issue by performing either of the following procedures:

  • Restarting BIG-IP ASM processes
  • Manually killing the asm_config_server process

Restarting BIG-IP ASM processes

Impact of workaround: Traffic processing will be disrupted during the restart.

  1. Log in to the Traffic Management Shell (tmsh).
  2. Restart the BIG-IP ASM processes by typing the following command:

    restart /sys service asm

Manually killing the asm_config_server process

Impact of workaround: Configuration utility access to the policy configuration will be disrupted while the asm_config_server is killed.

  1. Log in to the BIG-IP ASM command line.
  2. Manually kill the asm_config_server process by typing the following command:

    pkill -f asm_config_server
