K000161839: TMM Restart Loop and [INOPERATIVE:Standalone] State After Upgrading BIG-IP DNS to 17.5.1.4

Type
Support Solution
Published
2026-06-22
Updated
2026-06-22
Applies to

  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161839

Description

After upgrading a standalone BIG-IP DNS Virtual Edition from version 17.5.1.3 to 17.5.1.4, the system may enter a persistent TMM (Traffic Management Microkernel) restart loop across all TMM instances. This results in the device remaining in an [INOPERATIVE:Standalone] state, with dependent services unable to start and no traffic processing possible. The issue is accompanied by repeated SIGSEGV (segmentation fault) errors and core dumps for TMM processes. Log messages may include:

  • Killing tmm.0 pid <pid>
  • HA daemon_heartbeat tmm fails action is go offline down links and restart
  • SIGSEGV errors in TMM logs
  • Device status flipping between online/offline, throughput dropping to zero

 

Environment

  • Product: BIG-IP DNS
  • Version: 17.5.1.4 (upgrade from 17.5.1.3)
  • Standalone deployment (not in a cluster)
  • DNS cache enabled and actively used

 

Cause

Software bug 2197377 in BIG-IP DNS.

 

Answer/Recommended Actions

  1. 1. Download and apply the Engineering Hotfix (EHF) for BIG-IP DNS 17.5.1.4 as provided by F5 Support. The other option is to upgrade to 17.5.1.6 as described in K000160945.
  2. 2. Install the EHF together with the base image of 17.5.1.4, then boot into the updated volume.
  3. 3. Verify TMM stability and normal traffic processing after applying the EHF.
  4. 4. The same EHF can be applied to other BIG-IP DNS platforms running 17.5.1.4 to prevent recurrence.

 

Additional Information

This is also described in K000160945.
