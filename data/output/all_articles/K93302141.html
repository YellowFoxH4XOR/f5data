Topic

You should consider using this procedure under the following conditions:
  • You want to validate the Infineon Trusted Platform Module (TPM) chip certificates on a compatible F5 device.
  • You want to to perform manual attestation of the TPM chain of custody using the Platform Configuration Register (PCR) values, which the BIG-IP system computes for the BIOS, to confirm that the BIOS firmware is unmodified.

Description

A certificate or PCR validation failure may indicate a breach of the BIG-IP system, in which case take appropriate action to isolate the system until you confirm that the BIOS firmware has not been modified.

Important: In the event of a breach you, consult your security team immediately.

Note: A breached system does not qualify it for Return Materials Authorization (RMA).

You may also want to perform the following procedures after each reboot to track whether the BIOS firmware or Infineon TPM chip certificates change.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have one of the following BIG-IP platforms:
    • i850, i2x00, i4x00, HRC-i2800
    • i5x00, i5x00-D, i5820-DF, i7x00, i7x00-D, i7820-DF, i10x00, i11x00, i11x00-DS, HRC-i5800, HRC-i10800
    • i15x00, i15820-DF
    • B4450N

Procedures

Validating Infineon TPM certificates

Use the following procedure to check the Infineon TPM chip certificates on the platform. You must download the appropriate Infineon root and intermediate certificates to validate the certificates.

Impact of Procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Advanced Shell (bash) as an administrative user.
  2. Change to the /var/tmp/ directory by entering the following command:

    cd /var/tmp

  3. Download the Infineon TPM Elliptic Curve Cryptography (ECC) root certificate, located at the following link to the device:
    • http://www.infineon.com/cms/en/product/promopages/optiga_tpm_certificates/#root_certificates

      Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

  4. Download the Infineon TPM ECC manufacturing certificates (011, 029, 036), located at the following link to the device:
    • https://www.infineon.com/cms/en/product/promopages/optiga_tpm_certificates/#SLB9665xx2.0
  5. Convert the root certificate to BIG-IP PEM format by entering the following command

    openssl x509 -in Infineon-TPM_ECC_Root_CA-C-v01_00-EN.cer -inform der -out Infineon_TPM_ECC_ROOT_CA.pem

  6. Convert the manufacturing certificates to BIG-IP PEM format by entering the following commands:

    openssl x509 -in Infineon-OPTIGA\(TM\)_ECC_Manufacturing_CA_011.crt-C-v01_00-EN.crt -inform der -out OptigaECCMfrCA011.pem
    openssl x509 -in "Infineon-OPTIGA\(TM\) ECC Manufacturing CA 029 Issued by RootCA-C-v01_00-EN.crt" -inform der -out OptigaECCMfrCA029.pem
    openssl x509 -in Infineon-OPTIGA-ECC-Manufacturing-CA_036-Issued_by_RootCA.crt-C-v01_00-EN.crt -inform der -out OptigaECCMfrCA036.pem

  7. Create the certificate chain file with root and manufacturing certificates by entering the following commands:

    cat OptigaECCMfrCA011.pem OptigaECCMfrCA029.pem OptigaECCMfrCA036.pem Infineon_TPM_ECC_ROOT_CA.pem > TPM_bundle.pem

  8. To gather the TPM certificate from the Infineon chip, which you must do in multiple parts, enter the following commands:

    tpm2_nvlist

    Locate the value of the dataSize variable for the 0x1c0000a entry in the output. The following example from an i5800 platform shows the value of its dataSize variable to be 781:

      1. NV Index: 0x1c0000a
      {
        Hash algorithm(nameAlg):11
         The Index attributes(attributes):0x62072001
         The size of the data area(dataSize):781
       }

    Note: The dataSize value varies between platforms and is needed when performing a tpm2_nvread operation for the second certificate.

    tpm2_nvread -x 0x1c0000a -a 0x40000001 -s 512 | xxd -r -p > cert1.bin

    Subtract 512 from the value of the dataSize variable and replace <cert2size> with the resultant value in the following command syntax:

    tpm2_nvread -x 0x1c0000a -a 0x40000001 -s <cert2size> -o 512 | xxd -r -p > cert2.bin

    Using the previous example of 781 for the dataSize, the resultant command should be:

    tpm2_nvread -x 0x1c0000a -a 0x40000001 -s 269 -o 512 | xxd -r -p > cert2.bin

    cat cert1.bin cert2.bin > tpm_ecc_cert.bin

  9. Convert the TPM certificate to BIG-IP PEM format by entering the following command:

    openssl x509 -in tpm_ecc_cert.bin -inform der -out tpm_ecc_cert.pem

  10. Verify the TPM certificate by entering the following command:

    openssl verify -CAfile TPM_bundle.pem tpm_ecc_cert.pem

    The system output appears similar to the following example:

    tpm_ecc_cert.pem: OK

Validating platform integrity

Use the following procedure to validate platform integrity by gathering the PCR values that the TPM chip calculates and comparing them with known, good, published values.

Note: PCR values write to the /var/log/pcr file each time you turn on the system. To track PCR values over time, refer to the hash values PCR_00, PCR_01, and PCR_02 of the TPM_ALG_SHA256(0x000b) block located in the /var/log/pcr file.

Impact of Procedure: Performing the following procedure will not have a negative impact on your system.

  1. Log in to the BIG-IP command line as an administrative user.
  2. To verify your BIOS version, enter the following command:

    tmsh show /sys hardware | grep -i bios

    The system output appears similar to the following example:

    BIOS Revision  OBJ-0645-xx BIOS: 3.04.279.0 ME: 6.0.50.1252 04/04/2017

  3. To gather the PCR values for your BIOS, enter the following command:

    tpm2_listpcrs -L 0xb:0,1,2

  4. Locate the block of hash values for PCR_00, PCR_01, and PCR_02. The system output appears similar to the following example:
