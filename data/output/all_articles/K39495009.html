Known Issue

The Traffic Management Microkernel (TMM) process may restart when the connection between the mcpd process and TMM is lost.

This issue occurs when the following condition is met:

  • The Multipath TCP (MPTCP) option is enabled in the TCP profile.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restarting. If configured as part of a high-availability group, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system restarts the TMM process, but does not generate a core file.
  • The BIG-IP system logs error messages to the /var/log/ltm file that appear similar to the following example:

     crit tmm3[12345]: 01010020:2: MCP Connection expired, exiting  notice tmm.start: /etc/bigstart/scripts/tmm.start caught SIGCHILD,  sending SIGTERM to all remaining tmms
     notice promptstatusd[6464]: 01460006:5: semaphore tmm.running(1) held
     warning tmm2[12345]: 01230002:4: Interface 0.3: link is down
     warning tmm3[12345]: 01230002:4: Interface 0.4: link is down
     warning tmm[12345]: 01230002:4: Interface 0.1: link is down
     warning tmm1[12345]: 01230002:4: Interface 0.2: link is down

  • In the /var/log/daemon.log file, you observe a message similar to the following example:

     emerg logger: Re-starting tmm

Workaround

To work around this issue, you can disable the MPTCP option in your TCP profile. To do so, perform the following procedure:

Impact of workaround: Modifying your profile configuration may have additional effects on traffic processing. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > TCP.
  3. Click the name of the TCP profile you want to modify.
  4. Clear the check box next to Multipath TCP.
  5. Click Update.
