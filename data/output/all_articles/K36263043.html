Server-side request forgery (SSRF)

Server-side request forgery (SSRF) flaws occur whenever a web application is fetching a remote resource without validating the user-supplied URL. The vulnerable web application will often have privileges to read, write, or import data using a URL. To execute an SSRF attack, the attacker abuses the functionality on the server to read or update internal resources. The attacker can then force the application to send requests to access unintended resources, often bypassing security controls.

Successful SSRF attacks can result in the following:

  • Exposure and theft of data that may include sensitive personal or corporate information
  • Unauthorized manipulation of sensitive data
  • Hijack of a vulnerable system to use its trust relationship with other systems to launch further attacks

SSRF attack scenario

In the following scenario, an attacker exploits an application that makes calls to an internal resource on the same network.

  1. The attacker identifies an application that is vulnerable to SSRF attacks.
  2. The attacker sends a forged request to the vulnerable application and targets the internal resource that resides on the same network.

    For example, the following forged request targets 192.0.2.100, which resides on the internal network:

    GET /index.php?url=http://192.0.2.100/admin/ HTTP/1.1
    Host: example.com

  3. The application sends the forged request to the internal resource and receives a response with the requested data.
  4. The application sends the data back to the attacker, bypassing detection.

Secure your applications against SSRF with F5 products

To protect your applications against SSRF attacks, best practices recommend that you employ the principle of least privilege when setting up and configuring your environment. In addition, use the following controls in F5 products to secure your applications.

Use BIG-IP APM to mitigate SSRF

When you are using a BIG-IP APM virtual server, you should enable the following controls to protect against SSRF attacks.

Table 10.1 BIG-IP APM controls that protect against SSRF
BIG-IP APM protectionRecommendationsResource
Network access VPNFor front-end servers with dedicated and manageable user groups, use BIG-IP APM Network Access VPN to protect your internal network. Network access VPN provides remote, secure access to corporate applications and data through standard web browsers or the BIG-IP Edge Client.
  • K15830166: VPN for business continuity | Chapter 1: Guide contents
  • The BIG-IP Access Policy Manager: Network Access manual
Access control list (ACL)Use ACLs to enforce user restrictions to host and port combinations by configuring access control entries (ACEs). An ACL can apply to Layer 4 (the protocol layer), Layer 7 (the application layer) and used with network VPN access, application access, and web access connections. F5 recommends that you assign an ACL that rejects all other connections and place it last in the ACL order before configuring ACEs for individual application access.The Configuring Access Control Lists chapter of the BIG-IP Access Policy Manager: Network Access manual
