K36506401: Deprecation of SHA-1 SSL certificates

Knowledge
Published
2016-01-26
Updated
2025-04-02
Applies to

Topic

Secure Hash Algorithm 1 (SHA-1) is considered cryptographically weak and not secure enough for ongoing use. Beginning as late as January 2017 and as early as June 2016, browser developers such as Microsoft and Google began warning users when users visit web sites that use SHA-1 signed Secure Socket Layer (SSL) certificates. Servers that use SSL certificates signed using an SHA-1 signature need to obtain new SHA-2 signed SSL certificates to avoid these web browser SSL certificate warnings.

Description

Web browser warnings

Web browsers validate website SSL certificates and issue pop-up warnings under any of the following conditions:

  • The SSL certificate has expired or is not yet valid.
  • The SSL certificate is not signed by a trusted Certificate Authority (CA).
  • The website domain name does not match the SSL certificate's Common Name.

Once a browser developer deprecates SHA-1, the web browser issues an additional pop-up warning when a website is using an SHA-1 SSL certificate. Depending on which browser you are using when you are presented with an SHA-1 SSL certificate, you observe error messages similar to the following examples:

  • There is a problem with this website’s security certificate.
  • This Connection is Untrusted.
  • Your connection is not private.

To avoid the SHA-1 pop-up warnings, you need to replace any SHA-1 signed SSL certificate with an SHA-2 SSL certificate.

Note: The SHA-2 family contains the following hash functions:

SHA-224
SHA-256 
SHA-384 
SHA-512 
SHA-512/224
SHA-512/256

Finding SHA-1 certificates on the BIG-IP system

You can use the following procedure to verify which SSL certificates are signed using SHA-1:

  1. Log in to the command line of the BIG-IP system.
  2. To navigate to the SSL certificate directory in the filestore, use the following command syntax:

    cd /config/filestore/files_d/<partition>_d/certificate_d

    For example, to navigate to the default partition /Common, type the following command:

    cd /config/filestore/files_d/Common_d/certificate_d

  3. To find all SHA-1 signed SSL certificates, type the following command:

    for i in `ls * | grep -iv bundle | awk -F ':' '{print $3}'`; do echo $i && openssl x509 -in :Common:$i -text | grep -m1 -i sha1; done

    example1.crt_16529_1
    Signature Algorithm: sha1WithRSAEncryption
    example2.crt_91262_1
    Signature Algorithm: sha1WithRSAEncryption

    The BIG-IP system has appended each object in the BIG-IP system filestore with a unique _<number>_1 identifier. The system does not reveal this identifier when you use the BIG-IP Configuration utility or TMSO Shell (tmsh) to view the SSL certificates. In the previous example, when you view the certificates using the Configuration utility or tmsh, the system names the SSL certificates example1.crt and example2.crt.

    Note: F5 expects the BIG-IP system files default.crt and f5-irule.crt to be signed using SHA-1.

Recommendations

When you plan to depreciate SHA-1, you should consider the following:

  • Read recent announcements from popular browser developers such as Microsoft, Google, and Firefox to obtain the exact SHA-1 deprecation date.
  • There are no specific steps required when generating a new Certificate Signing Request (CSR). Most CAs have already begun signing SSL certificates using SHA-2. Before you purchase a new SSL certificate, simply verify with your CA that they intend to sign the certificate using SHA-2.
  • The BIG-IP system's Configuration utility has a self-signed SSL certificate.
  • The BIG-IP system began signing certificates using SHA-2 in BIG-IP 11.5.0, when issuing self-signed certificates and creating CSRs.
