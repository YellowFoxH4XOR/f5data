Description
Users could notice a previously-working remote authentication (to BIG-IP administrative interfaces) is failing all of a sudden and cannot log into the BIG-IP system using LDAP server authentication.

  • You may observe logs similar to the following under /var/log/ltm

Dec 25 15:17:51 bigip1 err httpd[24183]: pam_ldap(httpd:auth): error reading from nslcd: Connection reset by peer
Dec 25 15:17:51 bigip1 warning httpd[24183]: pam_unix(httpd:auth): check pass; user unknown
Dec 25 15:17:51 bigip1 notice httpd[24183]: pam_unix(httpd:auth): authentication failure; logname= uid=48 euid=48 tty= ruser= rhost=192.168.4.47 Dec 25 15:17:54 bigip1 info httpd(pam_audit)[24183]: User=santa tty=(unknown) host=192.168.4.47 failed to login after 1 attempts (start="Mon Dec 25 15:16:55 2020" end="Mon Dec 25 15:17:54 2020").
Dec 25 15:17:54 bigip1 info httpd(pam_audit)[24183]: 01070417:6: AUDIT - user santa - RAW: httpd(pam_audit): User=santa tty=(unknown) host=192.168.4.47 failed to login after 1 attempts (start="Mon Dec 25 15:16:55 2020" end="Mon Dec 25 15:17:54 2020").

Environment

  • BIG-IP LTM
  • LDAP / Active Directory
  • TACACS
  • RADIUS
  • DNS 

Cause

  • BIG-IP system was failing to resolve the DNS name of the LDAP server to its IP address
  • Path between BIG-IP and Authentication sever was not secure. 

Recommended Actions

  1. Please make sure DNS resolution is properly working on the BIG-IP system.
  2. Configure BIG-IP remote authentication server to an IP address instead of the hostname.
  3. Disable SSL, if the path between BIG-IP and Authentication is not secure.
