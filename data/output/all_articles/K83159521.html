Description

The BIG-IP packet filter feature provides an easy, compact and efficient method to create network filters, firewall rules, traffic shaping, and traffic policies based on libpcap's filter syntax. Libpcap's syntax is easy to read and manage and delivers more compact firewall rules.

When using packet filters as a production firewall, the number of packet filter rules can grow very large. Managing a large amount of packet filter rules is known to cause the following problems:
  1. Administrators may experience an unresponsive GUI when displaying a large number of packet filter rules.
    The following log message can be seen in the tomcat logfile /var/log/tomcat/catalina.out when tomcat restarts:

    INFO: Server startup in 8080 ms
    #
    # java.lang.OutOfMemoryError: Java heap space
    # -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat"
    #   Executing /bin/sh -c "/usr/bin/restart_tomcat"...
    Thu Sep 09 11:15:25 SGT 2021: START... [Ljava.lang.String;@3c855e
    Thu Sep 09 11:15:25 SGT 2021: Calling command 1 with args: " restart tomcat"
    Thu Sep 09 11:15:30 SGT 2021: DONE: com.f5.util.ContainerManager$Result@2dc38
     
  2. Users may experience errors when adding a packet filter rule larger than 65520 characters.
    The following error message can be seen in the GUI or in /var/log/ltm

    Sep  9 11:38:29 bigip13 err mcpd[8361]: 01070712:3: Caught configuration exception (0), Max string size exceeded during update of attribute:expression type:packet_filter_rule max:65520 received:72019.
     
  3. Administrators may experience errors when defining packet filter names that is longer than 29 characters.
    You may see errors similar to this log message in /var/log/ltm:

    Sep  9 11:26:52 bigip13 err mcpd[8361]: 01070087:3: Packet filter rule '/Common/longpfname012345678901234567890123456789012345678901234567890123456789012345678901234567890123456789': rule matches all traffic and action is not "continue"
     
Environment
  • BIG-IP
  • Manage a large number of packet filters
  • Use complex and long packet filter rules

Cause
  1. One reason the GUI becomes unresponsive is because the tomcat not having control-plane memory to display and manage all the packet filter rules.
     
  2. Creating a packet filter rule that is longer than 65520 characters is rejected by the mcp database. This is caused by the mcp (master configuration) database schema limitation, which also applies to other configuration strings like irules and data groups.
    K9204: iRules are limited to 65,520 characters
    K12112: The maximum size for a single string in a class or data group is 65,520 characters
     
  3. Packet filter names cannot be more than 29 characters.
    Refer to K9597: Some configured packet filter rules or rate classes may not work as expected

Recommended Actions

Actions or recommended steps to mitigate the issues:
  1. Increase control-plane memory allocation for tomcat using the provision.tomcat.extramb db key 
    For large amounts of packet filter rules (ie. 3000 rules and above) consider adding 100MB of extra memory for tomcat.
    To increase the memory allowance of the tomcat daemon, refer to the procedure outlined in K9719: Error Message: java.lang.OutOfMemoryError
     
  2. Limit packet filter rules to less than 65520 characters long
     
  3. Limit packet filter rule names to 29 characters or less

The maximum number of packet filter rules that you can manage on the BIG-IP is dynamic, which includes, but not limited to the following factors:
  • tomcat memory allowance and java runtime conditions
    You can get around the java.lang.OutOfMemoryError by increasing the host memory provisioned for tomcat.
  • tomcat user interface and/or mcp query processing time
  • GUI speed and usability may slow down when the number of packet filter rules becomes very large.
    You can get around this issue by using tmsh to manage packet filter rules.
