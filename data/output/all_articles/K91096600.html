Description
Hardware SYN cookie protection requires Auto Lasthop to correctly function as described in K16887. Generally when Auto Lasthop is disabled, BIG-IP software detects the configuration and prevents the system to be in hardware SYN cookie mode. Due to a known issue, BIG-IP may enter hardware SYN cookie mode even if Auto Lasthop is disabled. This can break configurations that are using asymmetric routing.

For example, SYN/ACK packet sent back from BIG-IP to client device may have unexpected destination MAC address.

  • When SYN cookie is generated by hardware, SYN/ACK packet will have a destination MAC address, which is the same as the source MAC address in SYN packet.
  • When SYN cookie is generated by software, SYN/ACK packet will be sent back based on TMM's ARP table.

Environment

  • Auto Lasthop is disabled
  • iSeries platforms (excluding i2xxx/i4xxx) and B4450 blades

Cause
The issue is due to ID 691219.

Recommended Actions
Explicitly disable hardware SYN cookie to prevent the system to be in hardware SYN cookie mode. Once the db key is modified, reboot the appliance to apply the config.

  # tmsh modify sys db pvasyncookies.enabled value false
  # tmsh save sys config
  # reboot
