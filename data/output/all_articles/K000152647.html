Description

How to enable cookie persistence on Distributed Cloud load balancer to choose the same IP within origin pool for a specific client all the time. 

Environment

  • F5 Distributed Cloud 
  • Persistence
  • Cookie stickiness
  • Multiple origin servers

Cause

None

Recommended Actions

To enable cookie persistence:

  1. Go to LB settings. 
  2. Find section "Other Settings"
  3. Change "Load Balancing Algorithm" to "Cookie based stickiness" 
     
  4. Provide name for the persistence cookie
  5. Fill rest of the details if needed:
    TTL - time for how long cookie will be valid in milliseconds. If value is different than "0", we add "Max-Age" parameter to cookie with provided TTL value.  
    Path - if not empty, we will add "Path" parameter to the cookie with provided value. 
    SameSite / Secure / HttpOnly - drop down list to tune cookie parameters if needed. 

Additional Information

Multiple origin pools problem

Cookie-based persistence (stickiness) ensures a client is consistently directed to the same server within a given origin pool, but it does not extend across multiple origin pools. If the load balancer logic switches traffic to a different origin pool, the cookie won’t force the client back to the original pool. 

LB first choose origin pool, then checks cookie and it's hash inside chosen origin pool. Because of that, you can observe that requests from one client with stickiness cookie enabled can be load balanced to multiple origin pools. 
To avoid that, you can use one origin pool with multiple IPs instead of multiple origin pools. 

 

Handling requests without stickiness cookies

Cookie-based stickiness is implemented using Ring Hash.

For the initial request, when no persistence cookie exists, the hash input is computed using the client's Source IP + Source Port. The Ring Hash algorithm is then applied to this computed value to select a backend in the origin pool. XC generates the persistence cookie in the response and returns it to the client.

For subsequent requests, the persistence cookie is used as the hash input, and Ring Hash consistently routes the requests to the same backend.
