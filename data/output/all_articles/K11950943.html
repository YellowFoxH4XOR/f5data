Issue

Error Message

01070712:3: Failed: name (<filename>) Cache path (<path>:<filename>_<revision number>) <message>

  • <filename> is the name of the file.
  • <path> is the location where the file should be stored.
  • <revision number> is the version of the file as specified in the configuration file.
  • <message> is the message indicating that the file to restore cannot be found in either the <path> location or the trash.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when a configuration is loaded and a configuration file specifies a version or revision of a file (such as the dtca-bundle.crt file) that is no longer in the filestore. When this happens, the BIG-IP system attempts to restore the missing version of the file from the trash. However, if the trash does not contain the file, the system cannot restore the missing version, the configuration fails to load, and the system logs the error message. A file stored in the filestore can become out-of-sync with the version or revision specified in the configuration file as a result of any of the following conditions:

  • The filestore file name revision number increments during an upgrade and no longer matches the file name specified in the bigip_base.conf file.
  • A user manually edits or deletes certificate files from the configuration or filestore.
  • When saving the configuration, the system encounters a timing issue that allows the dtca-bundle.crt file in the filestore to become out-of-sync with the configuration file. For more information about this issue, refer to Bug ID 428876 in F5 Bug Tracker.

Impact

If the BIG-IP system configuration references an object or file that it cannot locate, the system checks the trash to see if the file can be recovered. In the event that the file is not found, the system fails to load the configuration and logs the error message.

Recommended Actions

If you have a user configuration set (UCS) file available, restore the file from a date prior to the filestore and configuration becoming out-of-sync. For information about loading UCS archives, refer to K4423: Overview of UCS archives and K13132: Backing up and restoring BIG-IP configuration files with a UCS archive. Alternatively, you can modify the affected configuration file so that the file name version or revision number matches the version of the file in the filestore.

Note: When you modify a configuration object that also has a checksum specified, for example the dtca-bundle.crt configuration object in the /config/bigip_base.conf file, the checksum entry is for the missing file so you must remove or comment out (#) the checksum entry.
