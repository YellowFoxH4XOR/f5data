Description

When you import the security policy to BIG-IP ASM/Advanced WAF systems, the system checks the security policy to ensure that it is in proper UTF-8 format.
If it is not, the import operation will fail and you may see an error similar to the one below within the Configuration Utility.

The security policy file does not conform to the schema and cannot be imported. (line xxxx: parser error : Input is not proper UTF-8, indicate encoding ! .......)

Environment

  • BIG-IP ASM/Advanced WAF

  • Import security policy

Cause

The BIG-IP ASM/Advanced WAF system validates the security policy first before importing it to system.
If the security policy file is not in proper UTF-8 format, the system cannot parse it properly, as the result of this, the system cannot validate the security policy file, which causes an import failure.

Recommended Actions

Depending on which parts of the policy are in the incorrect encoding, you may be able to use a text file editor, such as Notepad++, to open the security policy file (if it is in .xml format), locate the line xxxx as shown in the error message, where the improper UTF-8 format exists, and change it with proper UTF-8 format content, and import it again.

If there are many non UTF-8 portions of the policy (especially explicit parameters and/or URI's) it is likely that the policy has been built with Automatic Policy builder for an application that is NOT UTF-8.  Such a policy would need to be rebuilt with the appropriate encoding that matches the actual Application.
