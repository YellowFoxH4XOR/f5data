Source
https://my.f5.com/manage/s/article/K50403941

Description

  • The afm_cmi.py process is using 100% CPU.
  • Random CPU spikes 100%
  • The afm_cmi.py process appear as top CPU consumer when the spikes occur

Environment

  • BIG-IP
  • AFM provisioned
  • High CPU

Cause

Seen behavior is caused by a know issue tracked with the Bug ID 818705

Recommended Actions

Upgrade to an unaffected version or as a workaround you can terminate the AFM data synchronization process:

1. Connect to CLI
2. Run the below command to terminate the offending script:
For single blade appliances: 
# kill -9 $(pgrep afm_cmi.py)
For multi-blade appliance like Viprion, please login to the specific blade where this spike is seen due to this script and then run the command 
# ssh slot 4
# kill -9 $(pgrep afm_cmi.py)

Note: In the above example, it's assumed that the spike was seen only on slot 4.

Additional Information

You can run the following command to confirm if afm_cmi.py is a top CPU consumer

find /shared/tmstat/snapshots/blade*/public/3600/ -type f | sort | xargs -I {} sh -c 'echo "\n{}\n"; tmctl -f {} proc_pid_stat -s proc_name,processor,modules,cpu_usage_recent,cpu_usage_1min,cpu_usage_5mins,pid,command_line -OK cpu_usage_5mins  -L5 2>/dev/null | head -5'
