Known Issue

This is the result of a known issue. If your BIG-IP ASM configuration contains a custom defined attack signature or a parameter regular expression that appears in more than one security policy, when the configuration is loaded (during a configsync operation), or when the security policy is applied, error messages that appear similar to the following example are logged to the /var/log/asm file:

perl[26692]: 01310027:2: ASM subsystem error (prepare_files.pl,PrepareFiles::read_cfg_file): !!! Not allowed activity - two identical records (1718507541,^[fF][rR]$|^[eE][nN]$|^[dD][eE]$|^[nN][lL]$|^[iI][tT]$|^[eE][sS]$|^[dD][kK]$,0) in /ts/files/site_1/config/full/account_param_reg_exps.cfg
perl[26692]: 01310027:2: ASM subsystem error (prepare_files.pl,PrepareFiles::read_cfg_file): !!! Not allowed activity - two identical records (1718507541,^[fF][rR]$|^[eE][nN]$|^[dD][eE]$|^[nN][lL]$|^[iI][tT]$|^[eE][sS]$|^[dD][kK]$,0) in /ts/files/site_1/config/fresh/account_param_reg_exps.cfg

These error messages are cosmetic and can be safely ignored.

F5 Product Development tracked this issue as CR94867 and it was fixed in BIG-IP 9.4.5. For information about upgrading, refer to the BIG-IP ASM Release Notes.
