Known Issue

You can configure virtual servers with mutually exclusive profiles, which creates an invalid configuration.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is licensed with the BIG-IP AAM module.
  • You configure a virtual server with an iSession profile in the server context, and configure a OneConnect profile.
  • You reboot the BIG-IP system.
  • The system sends connection requests to the virtual server of the rebooted device.

Impact

The virtual server does not respond to the connection request.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The virtual server processes the connection request that you configured with the invalid configuration; however, when you reboot the BIG-IP system, the virtual server does not respond to connection requests.
  • In /var/tmm, you observe log messages similar to the following example:

    notice ISESSION: <ip address>.<port> ! <ip address>.<port>: connection error: isession_setup_ssl:1645: server-side SSL hudfilter replacement failed: ERR_NOT_FOUND

Resolution

Status

F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, you can verify which server-side connection profile is valid for your deployment, and configure the virtual server to use only one of the profiles. 

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
