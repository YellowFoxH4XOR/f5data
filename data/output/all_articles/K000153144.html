K000153144: How to extend Graceful Shutdown Time for NGINX worker Process during Configuration Reload

Description

  • You deployed NGINX Plus Ingress Controller (NIC)
  • You now want to stress test your deployment using tools like wrk.
  • You perform, additional test while updating NIC configuration via VirtualServer or Ingress resources.
  • During the test, however, you noticed socket errors as shown below, implying impact to application traffic.

  • Given, socket errors occur during load test while editing existing resource, you want to know how to improve performance, even at heavy load.

  • You want how to eliminate the effect of configuration update to application traffic. 

Environment

  • NGINX Plus Ingress Controller (NIC)
  • Kubernetes
  • wrk
  • Ingress resource
  • VirtualServer resources
  • "keepalive_min_timeout" directive

Cause

  • When a configuration change is applied to the NGINX Ingress Controller, a reload is triggered that causes a new worker processes creation and the old worker processes gracefully terminated.
  • If keepalive directive is in use, NGINX would close these connections after notifying the client its intention to close.
  • However, in high load environment, the client may NOT receive the intention to close existing connection in time before it generates and sends a new request.
  • This in turn may results in mid-air mismatch between the state of a connection at the worker process and client.
  • This mismatch in state can result in Socket errors

Recommended Actions

  • To prevent socket errors during configuration reloads under load, extend the worker process termination time using the keepalive_min_timeout directive.
  • This allows existing keepalive connections to complete gracefully before old worker processes are terminated.

Steps to implement:

  • Enable NGINX configuration snippets:
    • Add the -enable-snippets command-line argument to your NGINX Ingress Controller deployment.
    • Reference: NGINX Ingress Controller Command-Line Arguments
  • Add the keepalive_min_timeout directive:
    • Use the nginx. org/server-snippets annotation in your Ingress resource:
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
    nginx. org/server-snippets: |
      keepalive_min_timeout 300;
    • This sets a minimum time (in seconds) that worker processes will wait before terminating, allowing active keepalive connections to close gracefully.
  • Apply the updated Ingress resource:
    • Deploy your changes and re-run your load tests to verify that socket errors no longer occur during configuration reloads.
  • Global application:
    • To apply this setting globally across all resources, use an appropriate ConfigMap entry for your NGINX Ingress Controller deployment.
