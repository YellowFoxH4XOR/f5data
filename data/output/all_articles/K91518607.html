Description

Failure for ASM signature upload to Live-updates:

  • Cannot upload ASM signature file
  • An upload file with the same file location already exits (Error)

Environment

 

  • ASM
  • Live-update
  • ASM signature update

Cause

None

Recommended Actions

  1. Make a UCS backup of the device.
  2. Backup data for live-update:
        # tar zcvf /var/tmp/$HOSTNAME-live-update-backup.tar.gz /var/lib/hsqldb/live-update/*
  3. Rebuild steps for live-update

    # cd /var/lib/hsqldb/live-update

    # bigstart stop tomcat

    # rm -rf *

    # mkdir nsyncd update-files

    # chmod 777 nsyncd update-files

    # chown tomcat:tomcat /var/lib/hsqldb/live-update/nsyncd/

    # chown tomcat:tomcat /var/lib/hsqldb/live-update/update-files/

    # chmod 755 /var/lib/hsqldb/live-update/nsyncd/ /var/lib/hsqldb/live-update/update-files/

    Note: For FIPS devices the genesis files must be retained of the device could become inoperable. The Genesis files must be put back into the "update-files" folder. The files needed can be determined by reviewing the "/etc/live-update-genesis.yaml" file.

    Recover the genesis files from the tarball created above or back them up separately.

    Create a backup location:
    # mkdir /shared/tmp/K91518607

    Decompress tarball:
    # cd /shared/tmp/K91518607; tar -xzvf /var/tmp/$HOSTNAME-live-update-backup.tar.gz

    Copy the files to the backup location:
    # cp $(awk '/genesisFileName/ {print "var/lib/hsqldb/live-update/update-files/"$NF}' ORS=' ' /etc/live-update-genesis.yaml) /shared/tmp/K91518607/

    Verify the files are there:
    # ls -l /shared/tmp/K91518607/

    ASM-AttackSignatures_20221103_124845.im
    BehavioralWAF_20200129_072049.im
    BotSignatures_20221103_084557.im
    BrowserChallenges_20251009_101859.im
    ServerTechnologies_20221103_124845.im

    Copy the above files to their original folder /var/lib/hsqldb/live-update/update-files/ 
    # cp *.im /var/lib/hsqldb/live-update/update-files 

     

    # bigstart start tomcat
  4. Tail the logs.

    # tail -f /var/log/tomcat/liveupdate.log 

    # tail -f /var/log/tomcat/live_update_upload.log

Additional Information

After rebuilding the database then either download the signature files or upload to live updates and the files should be able to install to update signatures for ASM.

These steps will remove the history of the previous files that were installed for ASM in live-updates.  You will still retain the updates for your signature files previously since this is updated in MySql for ASM signatures.

Also, the backup for live-updates that was done can be deleted after you are able to update your signatures and this is located in /var/tmp for the backup file at your convenience.
