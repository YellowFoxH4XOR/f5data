Topic

This article applies to BIG-IP LTM 11.x through 15.x. For information about other versions, refer to the following article:

  • K3393: Overview of compression settings for the HTTP profile

When you configure an HTTP Compression profile and assign it to a virtual server, the BIG-IP system reads the Accept-Encoding header of a client request and determines what content encoding method the client prefers. The BIG-IP system then removes the Accept-Encoding header from the request and passes the request to the server. Upon receiving the server response, the BIG-IP system inserts the Content-Encoding header, specifying either the gzip or deflate, based on the compression method that the client specifies in the Accept-Encoding header.

Note: In BIG-IP 11.x, the compression feature of the HTTP profile was moved into its own separate profile, HTTP Compression. Prior to BIG-IP 11.x, compression configuration is managed through the HTTP profile.

Description

SettingValueDescription
Selective CompressionEnabled or DisabledWhen selected (enabled), the system performs HTTP compression only when a configured iRule contains the COMPRESS::enable command. When cleared (disabled), the system performs compression according to the other compression settings specified in the HTTP Compression profile.

Note: Data compression only compresses HTTP server responses and not client requests.

URI CompressionURI List or Not ConfiguredSpecifies whether to compress HTTP content for responses matching values included in the URI List
URI ListInclude List: Lists the defined URIs whose HTTP content the system considers for compression operations.

Exclude List: Lists the defined URIs whose HTTP content the system does consider for compression operations.

Note: The Exclude List must be a subset of URIs in the Include List.

Specifies the URIs that you want the BIG-IP system to include or exclude from compression operations

Note: The string that you specify in the URI List setting can be either a pattern string or a regular expression. List types are case-sensitive for pattern strings. For example, the system treats the pattern string www.f5.com/test differently than the pattern string www.f5.com/TEST. You can override this behavior by using the appropriate Linux regexp command. For example, to specify a case insensitive match for the URI path /test, use the following in your include list: (?i)/test.

Note: In BIG-IP 11.0.0 through 11.1.0, if you remove all URI / content types from the URI / Content List box in the HTTP compression profile, the BIG-IP system compresses all HTTP content. To disable compression for a virtual server using an HTTP compression profile in 11.0.0 through 11.1.0, you must disassociate the profile from the virtual server. In BIG-IP 11.2.0 and later, if you remove all URI / Content types from the URI / Content List boxes in the HTTP compression profile, the BIG-IP system does not compress any HTTP content. To clarify, both the URI list and Content list must be enabled.

Content CompressionContent ListSpecifies whether the system compresses the type of HTTP content found in the Content-Type header of a response.
Content ListInclude List: Lists the defined content types which the system compresses.

Exclude List: Lists the defined content types which the system does not compress.

Specifies content type for either inclusion or exclusion.

Note: The string that you specify in the Content List setting can be either a pattern string or a regular expression. List types are case-sensitive for pattern strings. For example, the system treats the pattern string application/pdf differently than the pattern string application/PDF. You can override this behavior by using the appropriate Linux regexp command.

Preferred MethodGzip or DeflateSpecifies the preferred compression method for this profile.
Minimum Content LengthNumber of bytesSpecifies the minimum length of a server response that the system considers for compression.
Compression Buffer SizeNumber of bytesSpecifies the maximum compressed bytes that the system buffers before deciding whether to preserve a Keep-Alive connection and rewrite the Content-Length header.
gzip Compression LevelA preset, or a value between 1 and 9.Specifies the level of compression the system uses when gzip is the preferred compression method. The lowest value is 1 and the highest value is 9. You can select values 1, 6, or 9 from the list; however,  clicking Other allows you to input any value between 1 and 9.

A lower number provides a lesser but faster compression ratio. A higher number provides a higher compression ratio but requires more processing, which makes compression slower.
Note: Using the gzip compression level settings when the preferred method is set to deflate can modify the compression level for deflate. However, the level settings are not a one-to-one match with gzip compression levels. Modifying the gzip compression level only increments compression for deflate using levels 1 - 5. Setting the gzip compression level to a value greater than 5 generally uses the same maximum deflate compression level reached as when you use compression level 5.
Note: Different platforms will have different amounts of compression depending on the specific hardware used for compression.  

gzip Memory Level1 - 256 kilobytes

This value specifies the amount of memory that the compression library (zlib) uses for its internal compression buffers. The default (8 kilobytes) is the optimal setting for the most common cases. However, sites that primarily serve larger files may benefit from increasing this value. You must take into consideration the average size of the files the system is compressing when you change this setting.

Note: Increasing the gzip memory level value can increase the speed of the compression process but doing so comes at the expense of using more memory per connection.

gzip Window Size1 - 128 kilobytesThis setting dictates the amount of memory that the system uses for the compression history buffer. This value is similar to gzip Memory Level, but zlib uses the value differently. Like the gzip Memory Level setting, sites that primarily serve larger files may benefit from increasing this value. You must take into consideration the average size of the files that are being compressed when you change this setting.
Vary HeaderEnabled or DisabledWhen enabled, specifies that the system inserts the Vary: Accept-Encoding header into compressed server responses, regardless of what the content type is set to. If the Vary header already exists in the response, the system appends the Accept-Encoding value to that header.
HTTP/1.0 RequestsEnabled or DisabledWhen enabled, specifies that the system may compress responses to HTTP/1.0 client requests if the server responds with a Connection: Close header and the response content is no greater than the value of the Compression Buffer Size setting.
Keep Accept EncodingEnabled or DisabledWhen enabled, specifies that the system leaves the Accept-Encoding header in the HTTP request, allowing the target server to perform the compression, rather than the system doing so. Normal behavior is for the system to strip the Accept-Encoding header from the HTTP request.
Browser WorkaroundsEnabled or DisabledWhen enabled, specifies that the BIG-IP system uses built-in workarounds for several common browser issues that occur when compressing content. Specifically, the system checks the following conditions and, if found, prevents compression of server responses:
  • The client browser is Netscape version 4.0x.
  • The client browser is Netscape versions 4.10 and higher and the Content-Type header of the server response is not set to text/html or text/plain.
  • The client browser is Microsoft Internet Explorer (any version), the Content-Type header of the server response is set to either text/css or application/x-javascript, and the client connection uses SSL.
  • The client browser is Microsoft Internet Explorer (any version), the Content-Type header of the server response is set to either text/css or application/x-javascript, and the Cache-Control header of the server response is set to no-cache.
Note: The Browser Workarounds option is not included in BIG-IP 13.x and later.
CPU SaverEnabled or DisabledWhen enabled, specifies that the system monitors the percent CPU usage and adjusts the compression rates automatically when the CPU usage reaches either the CPU Saver High Threshold or the CPU Saver Low Threshold.
CPU Saver High ThresholdPercentageSpecifies the amount of CPU usage that causes the system to change the amount of content it compresses and the amount of compression it applies. For example, when the configured percentage of CPU usage has been reached:
  • Each connection is evaluated individually to determine whether compression is at that time.
  • The compression level is changed to the lowest value (fastest).
CPU Saver Low ThresholdPercentageSpecifies the amount of CPU usage that causes the system to revert back to user-defined compression values.
