Known Issue

The BIG-IP system may fail to appropriately detach the server-side connection for some virtual server flows.

This issue occurs when the following conditions are met:

  • The virtual server is configured with HTTP and OneConnect profiles.
  • The client sends an HTTP HEAD request.
  • The server response does not contain a Content-Length header.

In some cases, this issue may result in the BIG-IP system sending persistent connections to the incorrect pool member resource. The following sequence describes how this may occur:

  • The virtual server is configured with HTTP, OneConnect, and cookie persistence profiles.
  • The client sends an HTTP HEAD request with a cookie that persists to poolmember-1.
  • The server responds with an HTTP 200 OK and no Content-Length header.
  • The BIG-IP system fails to detach the server-side connection to poolmember-1.
  • The client sends a second HTTP GET request with a cookie that persists to poolmember-2.
  • The BIG-IP system incorrectly sends the request to poolmember-1.

RFC 2616 indicates that a Content-Length header is not necessary to determine the end of the message that is in response to an HTTP HEAD request.

Impact

Session persistence may fail for the virtual server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system sends persistent connections to the incorrect pool member.

Workaround

To work around this issue, you can create an iRule that detaches the flow following an HTTP HEAD request. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. In the Definition field, enter the following iRule:

    when HTTP_REQUEST {
    set headreq 0
    if { [HTTP::method] == "HEAD" } {
    # We are a head request. Set the flag for checking in the response.
    set headreq 1
    }
    }

    when HTTP_RESPONSE {
    if { $headreq } {
    # Response to HEAD request. Detach after done.
    ONECONNECT::detach enable
    ONECONNECT::reuse enable
    }
    }
  7. Click Finished.
  8. Associate the iRule with the virtual server.
