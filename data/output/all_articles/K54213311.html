Description
Using an IPv4 /31 subnet (255.255.255.254) with a self-IP is not supported. When this subnet is used, it can result in any of the following:

  • Inability to create a static route when the self-IP used is the first host in the /31 subnet. For example, creating a static route via a next-hop which belongs to a connected /31 subnet would result in an error (in this example the self-IP is 10.1.1.2 and the gateway is 10.1.1.3):

    root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# create net route MyTestDefault network default gw 10.1.1.3
    01070712:3: Cannot create static route: 0.0.0.0/0 gw 10.1.1.3 on interface  in rd0 - netlink error: 22 (Invalid argument)

  • Route learned dynamically which has a next-hop belonging to a connected /31 subnet would not be injected in the kernel routing table.

    [root@bigip1:Active:Standalone] config # tmsh show net route
    ----------------------------------------------------------------------------------
    Net::Routes
    Name                Destination         Type       NextHop               Origin
    ----------------------------------------------------------------------------------
    192.0.2.2/31          192.0.2.2/31          interface  /Common/External      connected
    default             default             gw         192.0.2.3               dynamic

    [root@bigip1:Active:Standalone] config # route -n
    Kernel IP routing table
    Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
    0.0.0.0         10.1.2.3        0.0.0.0         UG    9      0        0 mgmt
    192.0.2.2         0.0.0.0         255.255.255.254 U     0      0        0 External
    10.201.0.0      0.0.0.0         255.255.0.0     U     0      0        0 mgmt

    Notice the missing tmm default route with next hop of 192.0.2.3 (shown from show net route ) when checking output of Linux kernel route using route -n.

Environment

  • BIG-IP
  • Self-IP
  • Advanced Routing

Cause

  • Starting v11.4, use of self-IPs belonging to /31 subnet is no longer supported. The BIG-IP online help also specifies this restriction when navigating Network > Self IPs, and then clicking Help, and then Netmask. The special use case for /31 subnets is described in RFC 3021.

Recommended Actions

  • The smallest subnet size you can use is a /30 (255.255.255.252) subnet. Use /30 or larger subnets (/29, /28, /27 and so on) for self-IPs.
