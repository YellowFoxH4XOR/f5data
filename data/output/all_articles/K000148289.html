K000148289: An Error Occurs When Configuring HA Auto Failover for BIG-IQs With Remote Authentication for CLI/SSH

Type
Support Solution
Published
2024-10-28
Updated
2026-06-28
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000148289

Description

When BIG-IQ CMs and Quorum (DCD) are configured with remote authentication for CLI (TMSH/SSH) access, configuring automatic HA failover returns an error similar to the following during quorum setup:

 

"An error occurred while adding the BIG-IQ: Error: ha-secondary: Username and/or password is incorrect Error: ha-quorum: Username and/or password is incorrect Error: ha-primary: Username and/or password is incorrect"

 

Environment

 

  • BIG-IQ CM and (Quorum) DCD
  • BIG-IQ HA Auto Failover

 

Cause

 

Authentication for user 'hacluster' is being sent to remote server instead of being authenticated locally from within the BIG-IQ CMs and Quorum (DCD) devices.

 

This is being tracked through ID1696741.

 

Recommended Actions

 

Check if the CMs and Quorum (DCD) /var/log/secure log file contains entries similar to the following:

 

Feb 26 22:00:11 bigiq-cm1 notice ruby[6520]: pam_tacplus: pam_tacplus: user hacluster not authenticated

Feb 26 22:00:11 bigiq-cm1 notice unix_chkpwd[6802]: password check failed for user (hacluster)

Feb 26 22:00:11 bigiq-cm1 notice ruby[6520]: pam_unix(pcsd:auth): authentication failure; logname= uid=0 euid=0 tty= ruser= rhost= user=hacluster

 

The workaround is to add 'hacluster' into /config/bigip/auth/localusers of the BIG-IQ CMs and Quorum (DCD).

 

Additional Information

Note that adding a user into /config/bigip/auth/localusers will not survive a reboot or upgrade. Create a script that will add 'hacluster' user into /config/bigip/auth/localusers, and ensure that the script will get called from /config/startup. See K11333640 and K11948.
