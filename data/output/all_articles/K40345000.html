Topic

This article applies to BIG-IP ASM 12.1.0 and later. For information about other versions, refer to the following articles:

  • K17411: Bypassing the BIG-IP ASM system for connections that use RPC over HTTP (11.4.0 - 12.0.0)
  • K7869: Bypassing the BIG-IP ASM system for connections that use RPC over HTTP (9.2.0 - 11.3.0)

Purpose

You should consider using this procedure under the following condition:

  • You want to bypass the BIG-IP ASM system for connections that use remote procedure call (RPC) over HTTP.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to your BIG-IP ASM system.
  • You have basic working knowledge of either iRules or the Local Traffic Policy feature.
  • You have an existing BIG-IP ASM virtual server.

Description

The BIG-IP ASM system does not currently support RPC over HTTP. Some Microsoft Outlook implementations use RPC over HTTP to facilitate connections to the Microsoft Exchange server. Typically, these requests can be identified by the following unique HTTP attributes:

  • HTTP path/URI: /rpc/rpcproxy.dll
  • HTTP methods: RPC_IN_DATA or RPC_OUT_DATA

The BIG-IP ASM system will block these requests and log the following violation:

Request blocked, violations: Illegal method.

Note: Because the RPC data payload is in binary form, there is minimal security benefit for the BIG-IP ASM system to perform security enforcement on the RPC message data over HTTP.

Procedures

You can configure a local traffic policy rule to bypass the BIG-IP ASM system for connections that use RPC over HTTP. To do so, perform the following procedure:

Configuring Local Traffic Policy rules to bypass the BIG-IP ASM system for RPC traffic

You can modify the existing BIG-IP ASM-enabled local traffic policy by adding new rules to bypass BIG-IP ASM for the RPC over HTTP requests. When you complete the procedure, the local traffic policy should contain rules with the following logic:

  • Disable BIG-IP ASM when the URI contains /rpc/rpcproxy.dll
  • Disable BIG-IP ASM when the HTTP method is RPC_IN_DATA
  • Disable BIG-IP ASM when the HTTP method is RPC_OUT_DATA
  • Enable BIG-IP ASM for all remaining traffic

To create local traffic policy rules that disable BIG-IP ASM for connections that use RPC over HTTP, perform the following procedure:

Impact of procedure: The default BIG-IP ASM-enabled local traffic policy uses the first-match strategy. Therefore, reordering rules in an incorrect priority may yield unexpected results. Ensure that the order of the rules meets the requirements for your application environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the BIG-IP ASM-enabled virtual server.
  4. Click the Resources tab.
  5. For Policies, click the name of the BIG-IP ASM-enabled local traffic policy.
  6. Click Create Draft.
  7. For Draft Policies, click the name of the local traffic policy that was moved to draft state.
  8. For Rules, click Create.
  9. For Rule Name, type a name for the rule to disable BIG-IP ASM for URIs containing /rpc/rpcproxy.dll. For example, URI-rpc.
  10. For Match all of the following conditions, click the plus symbol (+).
  11. Add the conditions for HTTP URI path, /rpc/rpcproxy.dll. To do so, select or enter the following:
     
    • HTTP URI
    • Path
    • Contains
    • any of
    • /rpc/rpcproxy.dll
  • Click Add to add the URI value you entered.
  • For Do the following when the traffic is matched, click the plus symbol.
  • Select the following to disable BIG-IP ASM:
    • Disable
    • asm
       
  • Click Save.
  • For Rules, click Create.
  • For Rule Name, type a name for the rule to disable BIG-IP ASM for the RPC_IN_DATA HTTP method. For example, RPC_IN_DATA.
  • For Match all of the following conditions, click the plus symbol.
  • Add the conditions for the RPC_IN_DATA method. To do so, select or enter the following options:
    • HTTP Method
    • is
    • any of
    • RPC_IN_DATA
  • To add the HTTP method value you entered, click Add.
  • For  Do the following when the traffic is matched, click the plus symbol.
  • Select the following to disable BIG-IP ASM:
    • Disable
    • asm
  • Click Save.
  • For  Rules, click Create.
  • For  Rule Name, type a name for the rule to disable BIG-IP ASM for the RPC_OUT_DATA HTTP method. For example, RPC_OUT_DATA.
  • For  Match all of the following conditions, click the plus symbol.
  • Add the conditions for the RPC_OUT_DATA method. To do so, select or enter the following:
    • HTTP Method
    • is
    • any of
    • RPC_OUT_DATA
  • Click Add to add the HTTP method value you entered.
  • For  Do the following when the traffic is matched, click the plus symbol.
  • Select the following to disable BIG-IP ASM:
    • Disable

  • For  Rules, drag the BIG-IP ASM bypass rules that you created to prioritize them over the default rule for the BIG-IP ASM-enabled local traffic policy.
  • Click Save Draft.
  • On the Policies List page, select the check box for the local traffic policy in the Draft Policies and click Publish.

Configuring an iRule to bypass the BIG-IP ASM system for RPC traffic

You can configure an iRule and associate it with the BIG-IP ASM-enabled virtual server to bypass the BIG-IP ASM system for RPC over HTTP requests. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. For Name, type a name for the iRule.
  7. For Definition, type the following iRules syntax.

    Note: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any changes in an appropriate environment.

    when HTTP_REQUEST {
    if { ([HTTP::path] eq "/rpc/rpcproxy.dll") and \
    (([HTTP::method] equals "RPC_IN_DATA") or ([HTTP::method] equals "RPC_OUT_DATA"))}{
    ASM::disable
    log local0. "ASM disabled."
    } else {
    ASM::enable /Common/MyASMpolicy
    log local0. "ASM enabled. Current ASM policy is [ASM::policy]"
    }
    }

  8. Click Finished.
  9. Click Local Traffic.
  10. Click Virtual Servers.
  11. Click Virtual Server List.
  12. Under Resources for the BIG-IP ASM-enabled virtual server, click Edit.
  13. In iRules, click Manage.
  14. In the Available box, click the iRule that you created in the previous procedure.
  15. Move the iRule to the Enabled box.
  16. Click Finished.
