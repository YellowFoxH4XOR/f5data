Description

When adding a Rewrite Profile to a Virtual Server, the BIG-IP adds a Transfer-Encoding header and end of chunk data to a response that cannot have a body. For example an HTTP 304 Not Modified response, and the connection fails right after.

On a packet capture you can see a similar output on the response the BIG-IP sends to the client:

HTTP/1.1 304 Not Modified
Accept-Ranges: bytes
ETag: "0d393e3f580d71:0"
Server: Microsoft-IIS/10.0
Access-Control-Allow-Origin: *
Date: Mon, 20 May 2021 08:40:00 GMT
Set-Cookie: Cookie_name=R44444444;Path=/
Transfer-Encoding: chunked        → Transfer-Encoding header added

0                             → End of chunk data added

Environment

  • When adding a rewrite profile to a Virtual Server
  • HTTP response

Cause

If BIG-IP is obliged to rechunk a response (eg: the presence of a rewrite profile) and the response cannot have a body (eg: HEAD request or 304 Not Modified response), then a Transfer-Encoding: chunked header is inserted and an end of chunk (terminating chunk) "0x300d0a0d0a" is inserted. This can cause the client to generate an error. Typical clientside erroneous response.

This issue is tracked with Bug-ID 1024761 "HTTP adds Transfer-Encoding and terminating chunk to responses that cannot have a body".

Recommended Actions

An Engineering Hotfix can be provided by F5 support to resolve this issue on affected versions.
