Description

A Virtual Server which is UP (green status) but not responding to ARP broadcast, SYN nor ICMP from upstream.

This issue only happens to one Virtual Server. Other Virtual Server (even those who have the same subnet address) is working as expected.

BIG-IP ARP table shows that it is able to resolved the upstream device (gateway or client).

A packet capture on the BIG-IP will show that ARP request is received from the upstream but the BIG-IP does not send a ARP response. For example, the Virtual IP of the Virtual Server is 10.1.1.200 and the upstream device is 10.1.1.1, you will see the following packet capture example.
    1  21.828975 21.828975 3146 00:00:5E:00:53:00 → Broadcast       ARP IN  s1/tmm0 : Who has 10.1.1.200? Tell 10.1.1.1
    2  23.840365 2.011390 3146 00:00:5E:00:53:00 → Broadcast       ARP IN  s1/tmm0 : Who has 10.1.1.200? Tell 10.1.1.1
    3  27.840452 4.000087 3146 00:00:5E:00:53:00 → Broadcast       ARP IN  s1/tmm0 : Who has 10.1.1.200? Tell 10.1.1.1

However, on the gateway or client machine's ARP table, the Virtual IP of the Virtual Server is not resolvable.

You have Enabled ARP for the Virtual Address.

If a static ARP is configured on the upstream device (gateway or client) for the mentioned Virtual IP, SYN or ICMP will be sent to the Virtual Server but the Virtual Server will not respond accordingly.

It is also noticed that this Virtual Server has Enabled VLAN and Tunnel Traffic.

Environment

  • BIG-IP LTM
  • Virtual Server is receiving ARP broadcast, SYN and ICMP but not responding to them
  • No issue with other Virtual Servers
  • ARP has been Enabled for the Virtual Address
  • Virtual Server's VLAN and Tunnel Traffic is Enabled

Cause
This issue occurs due to one or both of the following causes:

  • The Virtual Server's VLAN and Tunnel Traffic is not configured correctly.
  • On BIG-IP VE, the hypervisor interface to VLAN mapping is not configured correctly.

Recommended Actions

You will need to re-configure VLAN and Tunnel Traffic.

  1. Login to the Configuration Terminal
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List
  3. Click on the Virtual Server
  4. Under VLAN and Tunnel Traffic change to All VLANs and Tunnels
  5. Or if you know the correct VLAN, Select the correct VLAN under VLANs and Tunnels
  6. Click Update
