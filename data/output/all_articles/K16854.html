Issue

Old Behavior

In versions prior to BIG-IP 11.5.0, 11.4.1 HF4, 11.4.0 HF6, and 11.2.1 HF11, the BIG-IP system attempts to preserve the originating Session Initiation Protocol (SIP) source port from the client. However, in some cases where a source port is already in use, the BIG-IP system changes the SIP monitor source port from 5060 to an ephemeral port, and then sends SIP monitor traffic from that port. Under these circumstances, the BIG-IP system does not update the sent-by value in the top VIA header field with the new source port. As a result, the receiving server uses the incorrect source port when responding to the SIP monitor, and the BIG-IP LTM system marks the server down.

New Behavior

Beginning in BIG-IP 11.5.0, 11.4.1 HF4, 11.4.0 HF6, and 11.2.1 HF11, the BIG-IP system always uses an ephemeral port for SIP monitor requests (to avoid conflicts with virtual server traffic), and the sent-by value is updated in the top VIA header field with the new source port.

Impact

This change in behavior improves Clustered Multiprocessing (CMP) compatibility for SIP monitor traffic and the reliability of that monitor, so collisions in the Traffic Management Microkernel (TMM) can be avoided. Monitors are now reliable, more robust, and more evenly distributed across TMMs.
