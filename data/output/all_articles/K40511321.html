K40511321: Using netcat to test remote ports for accessibility

Published
2022-06-29

Description
To determine if a TCP port is available to receive network connections network utilities can be used to attempt a connection to a specific IP and port.  The netcat utility (nc) is a networking utility that can be used to test if a network device is listening on a particular IP and port.

Environment

BIG-IP (any network device with TCP listeners)

Cause
N/A

Recommended Actions

   nc -v -z -w 5 <IP address> <port>

   nc options:
       -v : verbose
       -z : zero I/O, no data will be passed to the receiver, essentially for TCP this is a 3-way handshake.  The connection will close immediately after the 3-way handshake. (Not available on all version of netcat.)
       -w 5 : wait 5 seconds for a response, then time out (use 1 second when scanning a large number of ports to reduce the wait time)

  Working example:
    $ nc -v -z -w 1 198.51.100.20 80
  Connection to 198.51.100.20 80 port [tcp/http] succeeded!

  Failing example:
    $ nc -v -z -w 1 198.51.100.20 81
   nc: connect to 198.51.100.20 port 81 (tcp) failed: Connection timed out


  NOTE:  There are a number of implementations of the original netcat utility, e.g. OpenBSD, GNU.  Some versions of netcat (including some versions on BIG-IPs) do not have the -z option.  If the version of nc does not have the -z option the I/O timeout (-i <integer>) can be set to 1 second or junk text can be passed to the nc command, for example:

   nc -v -i 1 -w 1 198.51.100.20 443

   Example output:
      Ncat: Version 6.40 ( http://nmap.org/ncat )
     Ncat: Connected to 198.51.100.20:443.
     Ncat: Idle timeout expired (1000 ms).

   or
   
   echo "" | nc -v -w 1 198.51.100.20 443

   Example output:
     Ncat: Version 6.40 ( http://nmap.org/ncat )
     Ncat: Connected to 198.51.100.20:443.
     Ncat: 1 bytes sent, 0 bytes received in 0.01 seconds.

  Suggestion:  Test connectivity using nc with an address and port that is known to work, i.e. has an active TCP listener.

  If the connection times outs or is refused when using netcat then a connection cannot be established between your device and the destination IP address and port.  This could be due to a number of reasons:
  • No listener exists on the destination IP address and port,
  • Lack of a route to the destination IP address, or
  • Firewall rules or access lists prevent traffic from your device reaching the end point
  Scanning Multiple Hosts
    On a Unix host a scan of multiple IP addresses can be performed using a one-liner with a while loop by listing all IP addresses in a file:

  Example file named ip_list.txt:
     198.51.100.20
     198.51.100.21
     198.51.100.22
     198.51.100.23
     198.51.100.24

  Example scan command:
      for i in $(cat ip_list.txt) ; do echo $i ; nc -v -z -w 1 $i 443 ;  done

      198.51.100.20
      Connection to 198.51.100.20 443 port [tcp/https] succeeded!
      198.51.100.21
      Connection to 198.51.100.21 443 port [tcp/https] succeeded!
      198.51.100.22
      Connection to 198.51.100.22 443 port [tcp/https] succeeded!
      198.51.100.23
      Connection to 198.51.100.23 443 port [tcp/https] succeeded!
      198.51.100.24
      Connection to 198.51.100.24 443 port [tcp/https] succeeded!

      Replace the nc command options as necessary for your version of nc.
