Issue

The BIG-IP ASM Application Language setting specifies the default character encoding set for the web application. The language encoding determines how the security policy processes the character sets. The default language encoding determines the default character sets for headers, objects, parameter names, and parameter values.

When the BIG-IP ASM system processes a request for a security policy, it attempts to convert the character strings contained in the request. If the BIG-IP ASM system is able to convert the character string using the default language encoding defined in the security policy, it will then identify the value of the string to determine whether it is defined in the security policy.

If the BIG-IP ASM system is unable to convert the character string using the default language encoding defined in the security policy, it will attempt to decode the character using other encodings in the same language. If conversion fails for all appropriate encodings, the BIG-IP ASM system will report the following error message in the /var/log/asm file:

Failed to convert character

Note: Forensic information will not report what character failed to be converted and there is no option to define a fallback language scheme for use by the security policy. In order to determine the cause of the error message, the administrator will need to review the entire request to determine if any of the characters within the request are not covered in the language encoding scheme assigned to the security policy.

Note: Metacharacters should always be sent using the ASCII character set regardless of the encoding scheme defined in the security policy.
