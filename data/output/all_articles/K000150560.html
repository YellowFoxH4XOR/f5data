K000150560: Automating field entry while generating a Self-Signed SSL Certificate

Description

You want to generate a self-signed SSL certificate using OpenSSL while automating the inclusion of required fields and Subject Alternative Names (SANs).

Environment

  • BIG-IP system.

Cause

Manual entry of certificate fields during SSL generation with OpenSSL can result in errors or inconsistencies. Automating the process with SAN definitions ensures accuracy, consistency, and avoids user mistakes during the generation process. 

Recommended Actions

Note: This is not an official F5 procedure but rather a general guidance for managing OpenSSL configurations and automating self-signed certificate creation on your BIG-IP device.

  1. Generate Self-Signed SSL Certificate and Key: To automate the field input process and include Subject Alternative Names (SANs), use the following OpenSSL command:openssl req -nodes -x509 -sha256 -newkey rsa:4096 \
      -keyout server.key \
      -out server.crt \
      -days 3650 \
      -subj "/C=NL/ST=Zuid Holland/L=Rotterdam/O=ACME Corp/OU=IT Dept/CN=example.org" \
      -extensions san \
      -config <( \
      echo '[req]'; \
      echo 'distinguished_name=req'; \
      echo '[san]'; \
      echo 'subjectAltName=DNS:localhost,DNS:example.org')
  • Replace the subject value:/C=NL/ST=Zuid Holland/...with the corresponding values.
  • Modify the DNS value in:subjectAltNameTo match the required domain names.

2. Backup Existing Certificate and Key: It is a best practice to backup existing SSL certificate and key files before replacing them. This ensures recovery if rollback is needed.

3. Replace SSL Certificate and Key Files: Move the newly generated SSL certificate and key files into the appropriate configuration directories:

mv server.key /config/httpd/conf/ssl.key/server.key  
mv server.crt /config/httpd/conf/ssl.crt/server.crt  

4. Restart HTTPD Service: To apply the new certificate and key pair, restart the HTTPD service: 

bigstart restart httpd  

5. Validate and Verify: Validate that the web application or system is using the updated SSL certificate. This can be verified by:

  • Checking SSL details in the browser
  • Monitoring logs for errors related to SSL
  • Using tools like openssl s_client or other SSL validation tools
