Topic

You should consider using this procedure under the following conditions:

  • You have deployed or plan to deploy an IBM Tealeaf (Tealeaf) server.
  • You want to clone traffic processed by a BIG-IP virtual server to the Tealeaf server.

Description

The IBM Tealeaf product is designed to monitor and analyze inbound and outbound network traffic. You can use the BIG-IP Clone Pool feature to duplicate the client or server-side traffic for virtual servers to the Tealeaf device.

Clone pools

Clone pools are designed to copy traffic to a destination device. Clone pools are configured on the virtual server on which you want to duplicate the client-side or server-side traffic to send to the Tealeaf server.

Clone pool and Tealeaf server configuration considerations

  • You can configure clone pools to copy client-side traffic or server-side traffic.

    Note: A client-side clone pool clones client-side traffic to the clone pool member, and a server-side clone pool clones server-side traffic to the clone pool member.

  • Clone pools are not compatible with asymmetric routing, so you should configure Tealeaf server so that it is adjacent to the BIG-IP system.

    For more information refer to K17567: Clone pool members require L2 FDB entries.

  • Verify that the maximum transmission unit (MTU) setting of your Tealeaf server is equal to or greater than the BIG-IP VLAN MTU setting used by the clone pool member.

    Note: After you upgrade the BIG-IP device or the Tealeaf server, F5 recommends that you review the MTU settings.

  • The TCP Segmentation Offload (TSO) feature of BIG-IP system can adversely affect packet processing between the BIG-IP system and the Tealeaf server. For more information, refer to K16780: The BIG-IP system may drop TSO packets and K10191: Troubleshooting packet drops.
  • The BIG-IP virtual server port setting Preserve Strict is not compatible with clone pools.
  • For non-standard virtual servers (FastL4) configured with clone pools, F5 recommends that you disable ePVA for the virtual server. To disable ePVA acceleration use the following TMOS Shell (tmsh) command to modify the associated FastL4 profile:
    • tmsh modify /ltm profile fastl4 <fastL4 profile name> pva-acceleration none

    Note: For more information regarding the ePVA feature refer to K12837: Overview of the ePVA feature.

  • You should configure your BIG-IP device with a self IP address on the VLAN that is used for clone traffic and that is in the same network range as the destination Tealeaf server.
  • You should add the Tealeaf server MAC address and IP address to the BIG-IP system static Address Resolution Protocol (ARP) Forwarding Database (FDB).

    Important: Use of a broadcast or multicast MAC address for a Tealeaf server in the BIG-IP network static FDB will prevent clone traffic from being forwarded. F5 recommends that broadcast or multicast MAC addresses not be used for clone pool members.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the Configuration utility, tmsh, or the iControl REST interface.
  • You have deployed and configured your Tealeaf server and made sure the BIG-IP system can access it on the network.

Procedures

To configure the BIG-IP system to send traffic to the Tealeaf server, perform the following procedures:

  • Adding the Tealeaf server MAC address and IP address to the static ARP FDB
  • Creating and verifying VLAN settings of the Tealeaf server VLAN
  • Configuring clone pools for the Tealeaf
  • Saving the configuration
  • Recommended tcpdump syntax to view cloned traffic

Adding the Tealeaf server MAC Address and IP address to the static ARP FDB

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Network > ARP > Static List.
  3. Click Create.
  4. Enter the Name of the Tealeaf server static entry.
  5. Enter the IP Address of the Tealeaf server.
  6. Enter the associated MAC Address of the Tealeaf server.

    Note : When you enter the MAC address, use a colon to separate the hexadecimal numbers. For example, 00:00:5E:00:53:00.

  7. Click Save.

tmsh

To create a static ARP entry for the Tealeaf server using tmsh, use the following command syntax:

create /net arp <entry name> ip-address <tealeaf server ip address> mac-address <tealeaf server mac address>

For example:

create /net arp cp_test ip-address 192.168.1.70 mac-address 00:00:5E:00:53:00

iControl REST API

To create a static ARP entry for the Tealeaf server using the iControl REST API, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/net/arp -d '{"name":"<static arp name>","ipAddress":"<ip address>","macAddress":"<mac address>"}'

For example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https:// 192.168.0.100mgmt/tm/net/arp -d '{"name":"tealeaf_one","ipAddress":"192.168.1.70","macAddress":" 00:00:5E:00:53:00"}'

Creating and verifying VLAN settings of the Tealeaf server VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You only need to create a new VLAN if your Tealeaf server does not reside on an existing previously configured VLAN of the BIG-IP device.

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Network > VLANs.
  3. Click Create.
  4. Type the Name of the VLAN.
  5. Enter the Tag value if you are configuring the VLAN to match an existing tagged VLAN on your network.
  6. Under Resources, for interface click the appropriate BIG-IP interface and For Tagging, click the appropriate tagging preference.
  7. Under Configuration, ensure that the MTU setting is compatible with the MTU configured on the Tealeaf server.
  8. Click Add.
  9. Click Finished.

tmsh

To create a network VLAN for the Tealeaf server using tmsh, use the following command syntax:

create /net vlan tealeaf interfaces add { <interface> { <tagging preference> } } tag <numeric value> mtu <numeric value>)

For example, use the following command for a tagged VLAN:

create /net vlan tealeaf interfaces add { 1.3 { tagged } } tag 888 mtu 1356

For example, use the following command for an untagged VLAN:

create /net vlan tealeaf interfaces add { 1.3 } tag 888 mtu 1356

To view VLAN MTU configuration setting, use the following command syntax:

list /net vlan <vlan name> mtu

For example:

list /net vlan tealeaf mtu

iControl REST API

To create a network VLAN for the Tealeaf server using the iControl REST API, use the following command syntax:

Impact of procedures: Using the following commands should not have a negative impact on your system.

To create a new tagged VLAN specifying the interface, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/net/vlan -d '{"name":"<vlan name>","tag":"<numeric value","interfaces":[{"name":"<interface>","tagged":true}]}'

For example, to create the new Tealeaf VLAN with a tagged ID of 900 on interface 1.3, enter the following command:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/net/vlan -d '{"name":"tealeaf","tag":"900","interfaces":[{"name":"1.3","tagged":true}]}'

Note: The tagged statement does not use the string quoted syntax; the value of true should not have quotes.

To create a new untagged VLAN specifying the interface, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/net/vlan -d '{"name":"<vlan name>","tag":"<numeric value>","tagged":"<numeric value>","interfaces":"<interface>"}'

For example, to create the Tealeaf VLAN with an untagged ID of 900 on interface 1.3, enter the following command:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/net/vlan -d '{"name":"tealeaf","tag":"900","tagged":"900","interfaces":"1.3"}'

Configuring clone pools for the IBM Tealeaf product

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: When you use clone pools with a Forwarding or Performance Layer 4 (L4) type virtual server, you need to configure the client-side clone pool in a separate VLAN from the virtual server if the Preserve Strict source port setting is enabled for the virtual server or if address or port translation is disabled for the virtual server. Failure to do so results in connections being reset with a Port in use message.

To configure a clone pool, perform the following tasks:

  • Creating a clone pool with the Tealeaf server as the member IP address
  • Modifying a virtual server to reference the clone pool

Creating a pool with the Tealeaf server as the pool member IP address

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools.
  3. Click Create.
  4. Type a name for the pool.
  5. Under Resources, in New Members, for Address, enter the IP address of the Tealeaf server.
  6. For Service Port, enter the port number.
  7. Click Add.
  8. Click Finished.

tmsh

To create a pool that contains the Tealeaf server IP address using tmsh, use the following command syntax:

tmsh create /ltm pool <clone pool name> members add { <tealeaf ip address>:<port> }

iControl REST

To create a pool that contains the Tealeaf server IP address using the iControl REST API, use the following command syntax.

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/ltm/pool/ -d '{"name":"<pool name>","partition":"<partition name>","members":["<node name>:<port>"}]}'

For example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/ltm/pool/ -d '{"name":"tealeaf_clone_pool","partition":"Common","members":[{"name":"tealeaf_one:80"}]}'

Modifying a virtual server to reference the new clone pool

To modify the virtual server to reference the clone pool using the Configuration utility, perform the following procedure:

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the virtual server to which you want to assign the clone pool.
  4. For Configuration, click Advanced.
  5. For Clone Pool (Client) or Clone Pool (Server), click the pool you created in the previous procedure that contains the IDS device.
  6. Click Update.

tmsh

To modify a virtual server to reference the clone pool using tmsh, use the following command syntax:

tmsh modify /ltm virtual <virtual_name> clone-pools add { <clone pool name> {context clientside | serverside } }

iControl REST API

To modify a virtual server to reference the clone pool using the iControl REST API, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X PATCH https://<ip address>/mgmt/tm/ltm/virtual/~<partition>~<virtual server name> -d '{"clonePools": [{"context":"serverside","partition":"<partition name>","name":"<clone pool name>"}]}'

For example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X PATCH https://192.168.0.100/mgmt/tm/ltm/virtual/~Common~asm_vs -d '{"clonePools": [{"context":"serverside","partition":"Common","name":"tealeaf_clone_pool"}]}'

Saving the configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Depending on the method you used to create and modify the configuration objects, you may need to manually save the configuration. The Configuration utility automatically saves the configuration objects, but if you used tmsh or the iControl REST API to create the configuration, save your configuration with one of the following commands:

tmsh

To save the configuration using tmsh, use the following command from the command line of the BIG-IP device:

tmsh save /sys config partitions all

iControl REST API

To save your configuration using the iControl REST API, use the following command syntax:

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/sys/config -d '{"command":"save","partition":["<partition name>","<partition name>"]}'

For example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/sys/config -d '{"command":"save","partition":["Common","QA"]}'

Note: The iControl REST API does not have a method to save the configuration to all configured partitions. When you're configuring a BIG-IP device with multiple partitions, you need to specify each partition for which you intend to save the configuration objects.

For BIG-IP devices that only have the default Common partition, or when all the configured objects you want to save reside in the Common partition, you can use the following command syntax.

curl -s -k -u <username>:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/sys/config -d '{"command":"save"}'

For example:

curl -s -k -u admin:default -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/sys/config -d '{"command":"save"}'

Using the recommended tcpdump syntax to view cloned traffic

Impact of procedure: Performing the following procedure should not have a negative impact on your system; however, viewing high volume traffic may impact performance.

When you attempt to view traffic sent to clone pool members, note that the BIG-IP system duplicates the virtual server traffic and does not modify the source and destination addresses. Therefore, there is no traffic directly sent to the Tealeaf server IP address.

You can view the clone traffic in the same way you view the traffic on the clone pool-configured virtual server.

To do so, use the following tcpdump syntax:

tcpdump -Xnes0 -i <vlan name>:nnnn <any tcpdump filters relating to connections as processed by the virtual server>

Note : <vlan name> is the name of the VLAN on which the Tealeaf server resides.
