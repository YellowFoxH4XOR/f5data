K000158900: F5 Access Android 3.2.0 Fails to Prompt for Credentials

Type
Support Solution
Published
2025-12-23
Updated
2026-04-21
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000158900

Description

When using F5 Access for Android 3.2.0, the VPN connection to BIG-IP APM may stay stuck at “Loading” and never display the credential/web-logon prompt (embedded browser flow). This prevents completion of SAML/OIDC authentication when an external Identity Provider (IdP) redirect is required.

Common client log indicators include:

  • EXCEPTION - wrong response HTTP code, 404
  • EXCEPTION caught
  • JNU_ThrowSessionException: Throwing session exception, Exception: error downloading configuration
  • PrelogonRunnable: error fetching client policy: Exception: error downloading configuration
  • com.f5.edge.client_ics.session.EdgeSessionException: Exception: error downloading configuration

Environment

  • BIG-IP APM (example version observed: 17.1.2)
  • APM Access Profile using SAML/OIDC authentication with redirect to a 3rd-party IdP URL (example profile observed: ap_connect.cps.edu_SAML)
  • F5 Access client:
    • Android/ChromeOS running F5 Access 3.2.0 (issue)
    • F5 Access 3.2.1 from Google Play Store (fix)

Cause

  • Bug ID 2182401

Recommended Actions

  1. Upgrade F5 Access for Android to version 3.2.1 from the Google Play Store.
  2. Re-test the VPN connection and confirm the web-logon/credential prompt launches and authentication completes.
  3. If further troubleshooting is required after upgrading, collect:
    1. F5 Access client logs from the affected device.
    2. APM logs from the BIG-IP (including debug logging, if enabled).
    3. A fresh qkview from the BIG-IP.
  4. (Optional) Packet capture on the BIG-IP during authentication attempts, for example:
  5. Identify the client IP used for testing.
  6. Run tcpdump -nnei 0.0:nnnp host <client ip> --f5 ssl -s0 -w /var/tmp/samlauth.pcap
  7. Reproduce the issue and stop the capture.

Additional Information

  • Observed behavioral difference:
    • F5 Access 3.1.3 continued the web-logon flow even after encountering an HTTP 404 during the redirect process (continued/“continue weblogon” behavior).
    • F5 Access 3.2.0 encountered an HTTP 404 during redirect handling and then failed during pre-logon with “error downloading configuration,” preventing the credential/web-logon prompt from launching.
  • The fix in 3.2.1 corrects the redirect/web-logon handling introduced in the 3.2.0 OIDC implementation when redirecting to a 3rd-party IdP URL.
