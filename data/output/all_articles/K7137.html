K7137: Changing the renegotiate period of a serverssl profile from the command line does not display the value correctly

Known Issue

This is the result of a known issue. Changing or updating the renegotiate period of a serverssl profile from the command line does not display the value correctly when the profile is viewed from the command line.

For example:

Changing the renegotiate period of the serverssl profile, my_serverssl, provides output similar to the following example when viewed from the command line:

# b profile serverssl my_serverssl renegotiate period 888

Viewing the serverssl profile, my_serverssl, after making the change above, provides output similar to the following example when viewed from the command line:

# b profile my_serverssl list
profile serverssl my_serverssl {
defaults from serverssl
key "default.key"
cert "default.crt"
chain none
ca file none
ciphers "DEFAULT"
passphrase none
options none
modssl methods disable
renegotiate period 138649428 <---- Incorrect
renegotiate size indefinite
peer cert mode ignore
unclean shutdown enable
strict
resume disable
handshake timeout 60
alert timeout 60
cache size 20000
cache timeout 3600
}

When the serverssl profile is viewed through Configuration utility, it correctly displays the renegotiate period entered. If the configuration is reloaded or the system is rebooted, the incorrect value is loaded into memory for use, because the command line utility writes the information to the /config/bigip.conf file.

This issue also occurs if the Configuration utility is used to change the renegotiate period. The Configuration utility will display the new entry, but the same incorrect entry is written to /config/bigip.conf file.

F5 Networks Product Development tracked this issue as CR45656 and it was fixed in BIG-IP LTM version 9.1.3. For information about upgrading, refer to the BIG-IP LTM Release Notes.
