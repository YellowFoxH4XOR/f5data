Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when a classification profile is configured on a BIG-IP ASM virtual server.

This issue occurs when all of the following conditions are met:

  • A classification profile is configured on a virtual server.
  • You have a high volume of Secure Sockets Layer (SSL), FTP, RTP, or Session Initiation Protocol (SIP) flows being processed by this virtual server.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high availability (HA) pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails over to the standby system if your device is configured as an HA pair.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you can remove the classification profile from the virtual server. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To remove the classification profile from the affected virtual server, use the following command syntax:

    modify ltm virtual <virtual-server-name> profiles delete { classification }

    Note: <virtual-server-name> is the name of the affected virtual server.

  3. To save the change, type the following command:

    save /sys config
