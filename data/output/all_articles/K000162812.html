Overview

During BIG-IP AFM device import into BIG-IQ, the Declare Management Authority (DMA) process may fail with:

Failed to copy configuration to working-config

The BIG-IQ restjavad log may report:

java.lang.IllegalArgumentException: The vector TCP RST Flood (Flood) doesn't support suspicious feature.

This occurs when an AFM DoS attack vector that does not support the suspicious property is configured with:

suspicious true

This behavior is documented in Bug ID987801, which describes BIG-IQ AFM discovery or import failure when an unsupported DoS vector contains the suspicious feature.

Applicable Environment

  • BIG-IQ: 8.4.0
  • BIG-IP AFM: 17.5.1.3
  • Affected configuration: AFM DoS device configuration
  • Example vector: tcp-rst-flood

Cause

The suspicious property is not supported by every AFM DoS attack vector. BIG-IQ validates the imported AFM configuration and rejects a vector when this property is enabled on a vector that does not support it.

In the reported case, the configuration contained:

tcp-rst-flood { suspicious true }

BIG-IQ consequently returned:

The vector TCP RST Flood (Flood) doesn't support suspicious feature.

This is a BIG-IQ AFM import-validation defect documented in Bug ID987801.  Changing the affected vector to suspicious false allows the BIG-IP devices to be integrated successfully into BIG-IQ.

Understanding the Suspicious Property

The suspicious property is disabled by default. When enabled, it allows the applicable attack vector to be triggered when a packet does not belong to an existing flow.

Therefore, disabling the property on an unsupported vector is required for BIG-IQ import compatibility.

Resolution

Set the suspicious property to false for each affected DoS vector.

For the TCP RST Flood vector, run:

tmsh modify /security dos device-config dos-device-config dos-device-vector { tcp-rst-flood { suspicious false } }

Verification

  1. Display the DoS device configuration: 
    tmsh list security dos device-config | grep -A 30 "tcp-rst-flood"
  2. Confirm that the affected vector contains: 
    suspicious false
  3. Repeat the BIG-IP device import or rediscovery from BIG-IQ.
  4. Confirm that the DMA import completes successfully.

Important Considerations

  • The validation error identifies the specific vector that must be corrected.
  • Other vectors may produce the same error if they containsuspicious true
  • This article addresses only the unsupported DoS vector behavior.
