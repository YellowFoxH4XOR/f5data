Description

In the Event logs, the Violation details show that the Parameter Location is "Form Data", however, the request is JSON.
 

Environment

  • Content-Type: application/json
  • Attack Signatures are triggered on wildcard ( * ) parameter
  • The request URL is configured in the Allowed URL list
  • Configured URL has JSON profile attached


Cause

Even with the JSON profile applied, ASM is unable to see the request payload as JSON and it is likely the application request body has a customised JSON schema.

Therefore, ASM applies the closest matching header-based content profile to the payload it inspects; Form-Data.

However, BIG-IP ASM is not designed to provide protection for binary uploads. Therefore, if the request contains PUT or POST containing binary data, F5 recommends that you do not configure the BIG-IP ASM system to enforce any parameter checking on those elements.


Recommended Actions

Disable Attack Signature checking on the wildcard ( * ) parameter.
 

Additional Information

It is possible to create a JSON profile with a custom schema.

For more information refer to Manual Chapter : Adding JSON Support to an Existing Security Policy (BIG-IP v15+)
