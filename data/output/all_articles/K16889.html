Known Issue

Conflicting content type indicators may cause an incorrect rewrite byte order marker.

This issue occurs when all of the following conditions are met:

  • Users access a destination resource through a BIG-IP access session.
  • Content HTTP returned from the destination resource has the content type of utf-8.

    An example Content-Type header:

    Content-Type: text/html; charset=utf-8

  • The content payload contains a meta tag that specifies content as utf-16.

    An example meta tag:

    <META http-equiv="Content-Type" content="text/html; charset=utf-16">

  • The content type is utf-8.

Impact

The BIG-IP APM system rewrites the content, setting the byte order marker (BOM) as utf-16.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The content does not render correctly.

Workaround

To work around this issue, you can correct the content returned by the destination resource or create and apply a specially crafted iRule to correct the erroneous utf-16 meta tag.

Impact of workaround: F5 recommends that you perform the application iRules during a scheduled maintenance window.
