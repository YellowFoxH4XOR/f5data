K73552073: iRule not being processed when a LTM Policy rule is processed first on BIG-IP

Support Solution

2021-07-27

2023-02-21
Applies to

  • BIG-IP Platforms
  • Public Cloud
  • BIG-IP
  • BIG-IP LTM: 15.1.X, 15.0.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.X.X, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 15.1.2
Source

Description

iRule is not being processed and does not show custom error pages instead it returns specific HTTP status codes

Environment

  • BIG-IP LTM 15.1.2.1
  • Virtual Server has LTM Policy Applied
  • Virtual Server has client and server side profile
  • iRule is using ifile for custom status code page
  • Applied iRule to show custom error page but it is returning the default status code 

Cause

When using "switch [HTTP::status]" followed by double qoute like "*403*" though it does not generate an error,  "switch switch [HTTP::status]" will look for an HTTP status in string format *403* but by design it is looking for an integer value 403.

Recommended Actions

  1. Instead of using this iRule if your matching string to the patterns, use glob-style matching (i.e. the same as implemented by the string match command).

    Before:
    when HTTP_RESPONSE {
        switch [HTTP::status] {
             "*400*" { HTTP::respond 200 content [ifile get "400.png"] }
             "*401*" { HTTP::respond 200 content [ifile get "401.png"] }
             "*403*" { HTTP::respond 200 content [ifile get "403.png"] }
             "*404*" { HTTP::respond 200 content [ifile get "404.png"] }
             "*500*" { HTTP::respond 200 content [ifile get "500.png"] }
            default { return }
            }
    }
    After:
    when HTTP_RESPONSE {
       switch -glob [HTTP::status] {
             "*400*" { HTTP::respond 200 content [ifile get "400.png"] }
             "*401*" { HTTP::respond 200 content [ifile get "401.png"] }
             "*403*" { HTTP::respond 200 content [ifile get "403.png"] }
             "*404*" { HTTP::respond 200 content [ifile get "404.png"] }
             "*500*" { HTTP::respond 200 content [ifile get "500.png"] }
            default { return }
            }
    }

Additional Information

Or if you just lookup for the HTTP error code simply use the below iRule without the -glob

switch [HTTP::status] {
         400 { HTTP::respond 200 content [ifile get "400.png"] }
         401 { HTTP::respond 200 content [ifile get "401.png"] }
         403 { HTTP::respond 200 content [ifile get "403.png"] }
         404 { HTTP::respond 200 content [ifile get "404.png"] }
         500 { HTTP::respond 200 content [ifile get "500.png"] }
        default { return }
    }
