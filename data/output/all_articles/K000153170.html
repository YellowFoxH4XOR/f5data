K000153170: NGINX Plus R33 and later Returns "503 Service Temporary Unavailable" After Upgrade Due to Usage Reporting Configuration

Type
Support Solution
Published
2025-10-25
Updated
2025-11-21
Applies to
  • NGINX Products
  • NGINX Plus: R35, R33, R34
Source
https://my.f5.com/manage/s/article/K000153170

Description

You have upgraded NGINX Plus instance to R33+ in a disconnected, air gaped environment

After that, all users encountered the following error when accessing the website (via browser) running on the NGINX Plus instance

503 Service Temporary Unavailable

Error logs on NGINX Plus instance include messages as:

[emerg] <pid>: cannot send usage report; traffic processing has been stopped
[error] <pid>: connect() failed (110: Connection timed out) during usage report to <IP>:443

The NGINX Plus Instance is managed by a NGINX Instance Manager (NIM), and the NGINX Plus instance shows "online" status on the NIM dashboard

Environment

  • Product: NGINX Plus, NGINX Instance Manager (NIM)
  • Version: R33 and later
  • Network: Disconnected or restricted environments, or limited outbound internet access

Cause

Even though the NIM displayed the instance as "online", but the NGINX Plus instance will not process traffic. These errors indicate that NGINX Plus has stopped processing traffic because it was unable to submit the initial license usage report required for subscription validation.

 

Recommended Actions

1. Ensure the NGINX Plus JWT license is valid and placed under /etc/nginx directory as license.jwt. 

2. Ensure the NGINX Plus instance managed by NIM includes the following block in its nginx.conf file, under the main block:

mgmt { usage_report endpoint=<NIM-FQDN>; }

Where <NIM-FQDN> is to be replaced with your actual NIM server address.

Block example as follows:

http {
}
stream {
}
mgmt {
     usage_report endpoint=<NIM-FQDN>;
}

3. Reload NGINX:

After updating the configuration, reload the service:

systemctl reload nginx

4. Grace Period Option:

To temporarily postpone enforcement of initial reporting (for up to 180 days), add:

mgmt { enforce_initial_report off; }
