K14132823: BIG-IQ how to view permissions for built-in user roles using the REST API

Type
Support Solution
Published
2021-08-11
Updated
2025-04-01
Applies to
  • Virtual Editions
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K14132823

Description
This article describes how to use the BIG-IQ REST API to view permissions granted by built-in user roles. 

Environment

  • REST API  run locally on the BIG-IQ CLI

Cause
None

Recommended Actions
Note: The following commands are run locally on the BIG-IQ CLI

  1. Make a request to list all built-in user roles and the roleTypeReference links

    restcurl shared/authorization/roles | jq '.items[] | {displayName, roleTypeReference}'

  2. Find the roleTypeReference link for the name of the user role that you want to inspect the permissions. Copy the roleTypeReference link URI, left to right, starting at shared and excluding the quotation mark.
    See the example below:
    {
      "displayName": "Local Traffic & Network Manager",
      "roleTypeReference": {
        "link": "https://localhost/mgmt/shared/authorization/role-types/b4ec9c36-dd74-3b1f-aa4e-ee74ec161130"
      }
  3. Use URI copied in step #2 to make a request to see the endpoint permisions for the user role.

    restcurl shared/authorization/role-types/<UUID>

    Example using the role shown in step #2:
    restcurl shared/authorization/role-types/b4ec9c36-dd74-3b1f-aa4e-ee74ec161130
    {
      "id": "b4ec9c36-dd74-3b1f-aa4e-ee74ec161130",
      "kind": "shared:authorization:role-types:roletypestate",
      "name": "ADC_Manager_RoleType",
      "isPublic": true,
      "selfLink": "https://localhost/mgmt/shared/authorization/role-types/b4ec9c36-dd74-3b1f-aa4e-ee74ec161130",
      "isBuiltIn": true,
      "generation": 1,
      "description": "Perform all tasks for managing Local Traffic \u0026 Network, including creating, viewing, modifying, and deleting Local Traffic \u0026 Network objects.",
      "displayName": "Local Traffic \u0026 Network Manager",
      "permissions": [
        {
          "actions": [
            "read",
            "edit",
            "create",
            "delete"
          ],
          "itemKind": "cm:adc-core:tasks:snapshot-config:snapshottaskstate"
        },
    ...
    Note: The output of the request is very long and the above example shows only the first set of permission out of many.
