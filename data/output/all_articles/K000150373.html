Description

SNMP is only reachable from the localhost and not accessible from an external network. When attempting to use snmpwalk from an external IP, you can receive a timeout message. You can also receive "udp port snmp unreachable" while gathering traffic with a tcpdump command.

Environment

  • BIG-IP LTM
  • SNMP

Cause

The self IP associated with the VLAN used for SNMP communication was configured with a port lockdown setting of allow-service none or the custom one which doesn't allow port 161. In option "allow-service none" configuration blocks almost all traffic, preventing SNMP responses on UDP/TCP port 161.

Recommended Actions

Modify Port Lockdown Settings for the Self IP by updating the self IP configuration to allow SNMP traffic by changing the port lockdown settings. This can be done via either the Web UI or TMSH (command-line interface).

  1. Using Web UI:
    Navigate to: Network ›› Self IPs ›› <Self_IP>
    Under the "Port Lockdown" option, select one of the following based on your requirements:
    Allow Default: Allows predefined ports including UDP/TCP port 161 for SNMP.
    Allow Custom: Manually add UDP/TCP port 161 for SNMP traffic.
    Avoid using Allow All unless absolutely necessary as it opens all ports regardless of protocol or service.

  2. Using TMSH
    Run the following command to update the self IP configuration:
    modify net self <Self_IP> allow-service default
    Or specify custom services:
    modify net self <Self_IP> allow-service add { udp:161 tcp:161 }
