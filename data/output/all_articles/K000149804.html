K000149804: Upgrading to 1.8.0 modified sshd_config which is not rollback after downgrade

Type
Support Solution
Published
2025-03-28
Updated
2025-04-11
Applies to
  • F5OS
  • F5OS-A: 1.8.0
Source
https://my.f5.com/manage/s/article/K000149804

Description

The following behavior was observed when SSH connection was made as root user.

F5OS 1.5.2: Log in with plain password
F5OS 1.8.0: Log in with keyboard interactive (challenge response) authentication
Downgraded from F5OS 1.8.0 to F5OS 1.5.2: Log in with keyboard interactive (challenge response) authentication

Environment

F5OS

Cause

In F5OS-A 1.8.0 "PasswordAuthentication" is set to "no". Rollback using rpm-ostree does not work after upgrade to F5OS-A 1.8.0. Upgrading result in the modification of sshd_config to disable the "PasswordAuthentication" configuration.


Downgrading ver1.8.0 to ver1.5.2:

# grep -ai -e "ChallengeResponse" -e "PasswordAuthentication" /etc/ssh/sshd_config | grep -v ^#
PasswordAuthentication no
ChallengeResponseAuthentication yes

Clean install ver1.5.2:

# grep -ai -e "ChallengeResponse" -e "PasswordAuthentication" /etc/ssh/sshd_config | grep -v ^#
PasswordAuthentication yes
ChallengeResponseAuthentication no

Recommended Actions

Modify the sshd_config to match the F5OS-A 1.5.2 sshd_config.

# vi /etc/ssh/sshd_config

From

PasswordAuthentication no
ChallengeResponseAuthentication yes

To

PasswordAuthentication yes
ChallengeResponseAuthentication no


After setting PasswordAuthentication to yes and ChallengeResponseAuthentication to no, save sshd_config.

Then restart sshd via systemctl.

# systemctl restart sshd


You can determine that the plaintext password authentication is enabled:

ssh -v root@<F5OS IP address>
OpenSSH_for_Windows_9.5p1, LibreSSL 3.8.2
debug1: Connecting to <F5OS IP address> [<F5OS IP address>] port 22.
*
<snip>
*
debug1: Next authentication method: password <----!!!!
root@<F5OS IP address>'s password:
