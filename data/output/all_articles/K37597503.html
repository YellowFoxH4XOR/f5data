Topic

You should consider using this procedure under the following condition:

  • You have configured Route Health Injection (RHI) for virtual server addresses and you want the BIG-IP system to delay the withdrawal of RHI routes for a defined period of time.

Description

Enabling RHI for a virtual address allows the BIG-IP system to advertise the availability of the address as a host route. When the virtual address is available, the BIG-IP system sends the address information to the neighboring router device, which periodically propagates the virtual address availability according to the RHI information it receives.

When you configure the BIG-IP systems as part of a HA device group and a failover event occurs, the BIG-IP device that transitions from active to standby state sends a message to the upstream router to withdraw the route. In some cases, the router withdraws the route several seconds before receiving the route advertisement message from the newly active BIG-IP device. This results in short route flaps due to the short period during failover when both devices are in a standby state.

For example, BIG-IP-1 (active) and BIG-IP-2 (standby) are configured as part of a HA device group. When a failover incident occurs, BIG-IP-1 transitions from active to standby state and sends a BGP update message to the upstream BGP neighbor to withdraw the route. The BGP neighbor may withdraw the route several seconds before receiving the BGP route advertisement message from BIG-IP-2, the newly active BIG-IP device.

You can mitigate short route flap conditions during failover events by configuring the BIG-IP systems to delay the withdrawal of RHI routes when operation status changes. Doing so temporarily delays the BIG-IP device transitioning from active to standby state from sending the route withdrawal message for the defined number of seconds.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Your BIG-IP system is licensed to include an advanced routing protocol.

Procedures

Delaying the withdrawal of RHI routes

To delay withdrawal of RHI routes, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To set the amount of seconds to delay withdrawal of RHI routes, use the following syntax:

    modify /sys db tmrouted.rhifailoverdelay value <delay_in_seconds>

    For example, to delay withdrawal of RHI routes for 30 seconds, enter the following command:

    modify /sys db tmrouted.rhifailoverdelay value 30

The BIG-IP system now delays the withdrawal of RHI routes by the number of seconds that you specified.
