Topic

You should consider using this procedure under the following conditions:

  • You are familiar with iControl REST API commands.
  • You want to use the iControl REST API to delete an access profile and policy and supporting components.

Description

Deleting an access profile and access policy and supporting configuration components

To delete an access profile an associated access policy and supporting components using iControl REST requires multiple API calls. You can only delete access policy configuration components (components that are created outside of the access policy) when you first delete the access profile. Only then can you delete the access policy.

Deleting the access policy deletes most access policy-related configuration components, such as agents and customizations specifically related to the access policy. For supporting configuration components created outside of the access policy such as authentication, SSO, customization components (images), and resource components (lease pools, application tunnels, and portal access profiles), you need to delete them using specific iControl REST API calls.

If you attempt to delete components of the access policy when they are in use by a virtual server or prior to deletion of the access policy, the deletion fails. For example, to remove an access policy application tunnel component along with the associated configuration items, you must delete the access policy configured with the specific application tunnel profile before you can delete the application tunnel component. (Deleting the component automatically removes the configured application tunnel items.) To delete an access profile and access policy requires that you delete the supporting configuration components in separate API calls.

Important: Instructions for using iControl REST API calls to delete configured components for API Protection, Federation, and Secure Web Gateway are not covered in this article.

Typographic conventions

The following typographic conventions are used in the command syntax examples:

Note:  For example, to run <GET> /mgmt/tm/apm/policy/access-policy/~Common~simple-vpn| jq -M, you enter curl -sk -u admin:<password> GET https://<big-ip apm address>/mgmt/tm/apm/policy/access-policy/~Common~simple-vpn| jq -M, replacing <password> and <big-ip apm address> with the appropriate administrative password and BIG-IP APM management IP address.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You are familiar with the F5 iControl REST API syntax.
  • You have administrative access to the BIG-IP APM Configuration utility.
  • You have the exact access profile name and the partition location of the access profile configuration.
  • You have the exact names of supporting configuration components used by the access policy.
  • Your BIG-IP APM system is licensed, provisioned, and configured with a management IP address.
  • You have command line access to a Linux system (or an alternate BIG-IP system) with the cURL and jq (command line JSON processor) utilities installed.

Viewing configured components

You can view configured BIG-IP APM components using HTTP GET.

To view a list of possible URLs you can send a GET request to the base URL /mgmt/tm/apm. In the JSON output, you can find reference links that point to additional configuration information.

The following example command obtains a list of all configured BIG-IP APM components for each component type. Note that lines that start with "link": change the destination from localhost to the hostname or IP address of your BIG-IP APM system and send a GET request to the URL, which retrieves specific configuration information for that URL configuration components.

curl -sk -u admin:admin -H "Content-Type: application/json" -X GET  https://10.95.0.55/mgmt/tm/apm/aaa/radius | jq -M .

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To view a specific configuration type component use the following syntax:

    <GET> /mgmt/tm/apm/<component_type>/<component_name> | jq -M .

  • To expand the subcollections for a configuration component, you can append the statement ?expandSubcollections=true to the following query:

    <GET> /mgmt/tm/apm/<component_type>/<component_name>?expandSubcollections=true | jq -M .

  • To view a specific configuration component that resides in a non-default partition, include the partition name prefixed and suffixed with the tilde (~) character:

    <GET> /mgmt/tm/apm/<component_type>/~<partition_name>~<component_name> | jq -M .

  • To view all current established access sessions, use the following syntax:

    <GET> /mgmt/tm/apm/access-info | jq -M .

Note: Change <component_type> to one of the following component types: aaa, client, configuration, ephemeral-auth, epsec, ntlm, oauth, policy, profile, report, resource, saml, sso, acl, apm-avr-config, application, application-family, application-filter, log-setting, risk-class, session, swg-content-type, or url-filter. Replace <partition_name> with the BIG-IP administrative partition name for the configuration component. Replace <component_name> with the name of the configuration component you want to view.

Deleting an Access profile

Profile components include access, oauth, vdi, connectivity, oauthplugin, webssh, eca, ping-access, exchange, and remote-desktop.

Impact of procedure: Performing the following procedure deletes the Access profile from the BIG-IP APM configuration leaving the access policy without an Access profile reference.

<DELETE> /mgmt/tm/apm/profile/access/~<partition_name>~<profile_name>

Note: Replace <partition_name> with the partition on which the component resides and replace <profile_name> with the configured name of the profile.

<DELETE> /mgmt/tm/apm/profile/access/~Common~simple_vpn

Deleting an access policy

The access policy defines acceptable methods of connecting to an internal network. In BIG-IP APM, it is an object in which you define criteria for granting access to various servers, applications, and other resources on your network.

Policy components include access-policy.

Impact of procedure: Performing the following procedure deletes the access policy, policy agents, items, and customizations from the BIG-IP APM configuration.

To delete the access policy, use the following command syntax:

<DELETE> /mgmt/tm/apm/policy/access-policy/~<partition_name>~<profile_name>

Note: Replace <partition_name> with the partition the component resides and replace <profile_name> with the configured name of the profile.

For example:

<DELETE> /mgmt/tm/apm/policy/access-policy/~Common~simple_vpn

Deleting a Connectivity profile

The Connectivity profile specifies client connection settings for the access session.

Profile components included: None.

Impact of procedure: Performing the following procedure deletes the access profile from the BIG-IP APM configuration leaving the access policy without an Access profile reference.

<DELETE> /mgmt/tm/apm/profile/connectivity/~<partition_name>~<profile_name>

Note: Replace <partition_name> with the partition the component resides, and replace <profile_name> with the configured name of the profile.

For example:

<DELETE> /mgmt/tm/apm/profile/connectivity/~Common~simple-vpn_profile

Deleting the Resource Assign agent component

The access policy uses the Resource Assign agent to assign specific resources to an access session. Resources include ACLs, Network Access configurations, Portal Access configurations, App Tunnel configurations, Static Pools, Webtop, Webtop Links, Webtop Sections configurations, and WebSSH configurations.

Resource Assign components include app-service, partition, rules, and type.

Impact of procedure: Performing the following procedure deletes the specified resource from the BIG-IP APM configuration and the Resource Assign agent becomes no longer available for use with future configurations.

<DELETE> /mgmt/tm/apm/policy/agent/resource-assign/~<partition_name>~<profile_name><resource assign agent suffix used at creation>

Note: Replace <partition_name> with the partition the component resides and replace <profile_name> with the name of the configured profile followed by the resource assign agent suffix (in the example _access_act_full_resource_assign).

For example:

<DELETE> /mgmt/tm/apm/policy/agent/resource-assign/~Common~simple_vpn_access_act_full_resource_assign

Deleting an Authentication component

Authentication components include active-directory, oauth-provider, active-directory-trusted-domains, oauth-request, crldp, oauth-server, endpoint-management-system, ocsp, f5-mfa-configuration, okta-connector, f5-service-connector, ping-access-properties-file, http, radius, http-connector-request, rsa-aa, http-connector-transport, saml, kerberos, saml-idp-automation, kerberos-keytab-file, saml-idp-connector, ldap, securid, localdb, and tacacsplus.

Impact of procedure: Performing the following procedure deletes the authentication resource from the BIG-IP APM configuration and the resource becomes no longer be available for use with future configurations.

<DELETE> /mgmt/tm/apm/aaa/<component>/~<partition_name>~<aaa_profile_name>

Note: Replace <component> with the matching authentication type used by the component (for example, active-directory, kerberos, ldap, localdb, radius, or tacacsplus), replace <partition_name> with the partition where the component is located, and replace <aaa_profile_name> with the name used to create the profile.

For example:

<DELETE> /mgmt/tm/apm/aaa/radius/~Common~simple_vpn_act_radius_auth

Deleting a Resource component

Resource components support the access policy by processing functions that reside outside of the access policy.

Resource components include: app-tunnel, portal-access, client-rate-class, sandbox, client-traffic-classifier, webssh-resource, ipv6-leasepool, webtop, leasepool, webtop-link,, network-access, and webtop-section.

Impact of procedure: Performing the following procedure delete the resource from the BIG-IP APM configuration and the resource becomes no longer available for use with future configurations.

<DELETE> /mgmt/tm/apm/resource/<component>/~<partition_name>~<resource_name>

Note: Replace <component> with the resource component name, replace <partition_name> with the partition the component resides, and replace <resource_name> with the name of the configured resource.

For example:

<DELETE> /mgmt/tm/apm/resource/network-access/~Common~simple_vpn_netaccess_profile
<DELETE> /mgmt/tm/apm/resource/leasepool/~Common~simple_vpn-vpn-leasepool
<DELETE> /mgmt/tm/apm/resource/webtop/~Common~simple_vpn

Deleting an ACL component

The BIG-IP system uses ACL (access control list) components to allow or disallow network level (L4 ports and protocols and L7 paths and URIs) connections from established network access tunnels. By default, network access tunnels are set to Allow.

ACL components included: None

Impact of procedure: Performing the following procedure deletes the ACL configuration from the BIG-IP APM configuration and the ACL configuration becomes no longer available for use with future configurations.

<DELETE> /mgmt/tm/apm/acl/~<partition_name>~<acl_name>

Note: Replace <partition_name> with the partition the component resides and replace <acl_name> with the name of the ACL configuration.

For example:

<DELETE> /mgmt/tm/apm/acl/~Common~simple_vpn_blockports

Scripting

The following BASH shell script syntax demonstrates how to combine the iControl REST API delete calls into a script to expedite the deletion of an access profile, access policy, and supporting components.

The script searches a list of configuration URLs for component names that include the specified search string. When using the script, F5 recommends to write the search string to use the partition and component name syntax <partition>~<search string> (For example: Common~simple_vpn). This searches for a string match starting with the partition and starting with the specified string to avoiding matching the string in non-related components.

When creating a configuration, the script assumes that configuration components use a base name (the string). Always carefully review found components prior to deleting them.

Important: The search string must be a complete word containing no spaces between characters.

Impact of procedure: Performing the following procedure may delete components that contain the search string.

  1. Place the stanza of the BASH shell script in a file on a BIG-IP system or Linux device that has cURL and jq installed. Mark the script file as executable (chmod 755).
  2. Run the script by entering <script_name> <big-ip_ip_address> <search_string>.
  3. Replace <script_name> with the name of the file in which you saved the script stanza.
  4. Replace <bigip_ip_address> with the IP address of the destination BIG-IP APM system.
  5. Replace <search_string> with the expected component base name. F5 recommends using <partition>~<search_string> (for example: Common~simple_vpn). Make sure to insert the tilde character (~)between the partition name and the search string.

#!/bin/bash
echo -n "Enter the password for the \"admin\" user for ${1} : ";read -s password;echo ""
#The following list will walk the BIG-IP APM configuration components and select components that include the search string value.
LIST="
/mgmt/tm/apm/profile
/mgmt/tm/apm/profile/access
/mgmt/tm/apm/profile/connectivity
/mgmt/tm/apm/policy
/mgmt/tm/apm/policy/agent/resource-assign
/mgmt/tm/apm/aaa/active-directory
/mgmt/tm/apm/aaa/active-directory-trusted-domains
/mgmt/tm/apm/aaa/crldp
/mgmt/tm/apm/aaa/endpoint-management-system
/mgmt/tm/apm/aaa/f5-mfa-configuration
/mgmt/tm/apm/aaa/f5-service-connector
/mgmt/tm/apm/aaa/http
/mgmt/tm/apm/aaa/http-connector-request
/mgmt/tm/apm/aaa/http-connector-transport
/mgmt/tm/apm/aaa/kerberos
/mgmt/tm/apm/aaa/kerberos-keytab-file
/mgmt/tm/apm/aaa/ldap
/mgmt/tm/apm/aaa/localdb
/mgmt/tm/apm/aaa/oam
/mgmt/tm/apm/aaa/oauth-provider
/mgmt/tm/apm/aaa/oauth-request
/mgmt/tm/apm/aaa/oauth-server
/mgmt/tm/apm/aaa/ocsp
/mgmt/tm/apm/aaa/okta-connector
/mgmt/tm/apm/aaa/ping-access-properties-file
/mgmt/tm/apm/aaa/radius
/mgmt/tm/apm/aaa/rsa-aa
/mgmt/tm/apm/aaa/securid
/mgmt/tm/apm/aaa/tacacsplus
/mgmt/tm/apm/ephemeral-auth/access-config
/mgmt/tm/apm/ephemeral-auth/auth-config
/mgmt/tm/apm/resource/app-tunnel
/mgmt/tm/apm/resource/network-access
/mgmt/tm/apm/resource/portal-access
/mgmt/tm/apm/resource/webtop
/mgmt/tm/apm/acl
"
### Walk the known configured virtual server profiles for the search string.
echo "Checking virtual server profiles for references to \"${2}\"."
curl -sk -u admin:${password} -H Content-Type: application/json -X GET https://${1}/mgmt/tm/ltm/virtual | jq -M . | grep profiles | grep https | awk '{print $2}' | cut -d\? -f1 | cut -d\/ -f4-100 1>> ./vsLIST
VSLIST=`cat ./vsLIST`
for VAL in ${VSLIST}
do
VSname=`echo "${VAL}" | cut -d\~ -f2-99 | cut -d\/ -f1`
curl -sk -u admin:${password} -H "Content-Type: application/json" -X GET https://${1}/${VAL} | jq -M . |  cut -d \~ -f2-100 | cut -d\? -f1 | grep -v : | grep ${2} 1>/dev/null  && {
vsMapped="yes";echo "${VSname}" >> ./vsFOUND
 }
done
test "${vsMapped}" = "yes" && {
#### When a virtual server profile contains the search string exit.
tput rev;echo -n "Exiting:";tput sgr0;echo " It appears that the search name \"${2}\" is used in a virtual server configuration(s): "
tput rev;
cat ./vsFOUND | sort -u
tput sgr0
rm -f ./vsFOUND
exit 0
}

echo "Creating component deletion list."
for VAL in ${LIST}
do
# Each URI is queried for the search string and component URIs that include /policy-item /customization-group /items /apps /domain-groups /client-policy /optimized-app are excluded.
curl -sk -u admin:${password} -H "Content-Type: application/json" -X GET https://${1}${VAL}?expandSubcollections=true | jq -M . | grep ${2} | egrep -i link | grep https| sed s'/"link": "https:\/\/localhost//'g |sed s'/"selfLink": "https:\/\/localhost//'g | cut -d\? -f1 | uniq -u |  egrep -v '/customization-group|/items|/policy-item|/apps|/domain-groups|/client-policy|/optimized-app|_resource_assign_ag' | grep \~ |sed s'/ //'g | uniq -u |  tee -a  ./DelLIST 
done
# Should no configuration components be found that contain the search string the process is ended.
test -s ./DelLIST 2>&- || {
echo "No configuration objest found containing the search word \"${2}\"."
rm -f ./DelLIST
exit 0
}
tput rev; echo -n " *** Warning *** "
tput sgr0; echo " Review this list carefully, be sure that ALL components found share the same partition and intended component name based on \"${2}\"."
echo -n "Delete items in component deletion list? {n/y} ";read DoIT
test "${DoIT}" = "y" 2>&1- && {
DLIST=`cat ./DelLIST | uniq -u`
for ITEM in ${DLIST}
do
echo "${ITEM}" |  grep -sq apm && {
echo "<DELETE> ${ITEM}" 
curl -sk -u admin:${password} -H "Content-Type: application/json" -X DELETE  https://${1}${ITEM} | jq -M . 
}
done
}
rm -f ./DelLIST ./vsFOUND
