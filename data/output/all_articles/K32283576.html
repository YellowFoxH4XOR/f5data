Topic

This article describes the need to always sync from the Active BIG-IP unit to the Standby BIG-IP unit in a BIG-IP SSL Orchestrator high availability (HA) pair. 

Description

You should avoid performing a reverse sync from a standby BIG-IP unit to an active unit, as doing so can break BIG-IP SSL Orchestrator deployments.

BIG-IP SSL Orchestrator is an add-on Configuration utility that runs concurrently with the BIG-IP Change Management Infrastructure (CMI). The CMI, also known as configuration synchronization (ConfigSync), governs configuration synchronization. As they are two systems rather than one, their interaction is complex, compared to the CMI acting alone.

The following describes possible problems that can arise when you perform a ConfigSync from a standby BIG-IP unit to an active one:

  • Transient states can be copied in the wrong direction
  • You might encounter timing problems
  • Dependency interactions might occur with other configuration objects

Recommendations

You might observe the following situations on the BIG-IP system:

  • The Changes Pending message appears on the Configuration utility
  • Traffic is working normally
  • CMI recommends that you sync from the standby BIG-IP unit to the active unit, because the standby unit has a newer configuration

If you observe the previous situations, perform the following tasks:

  1. Verify and correct the Network Time Protocol (NTP) clock synchronization on both units.
  2. On the active BIG-IP SSL Orchestrator system, do the following:
    • Make a small configuration change in any deployment (such as a description)
    • Deploy the configuration

CMI should now recommend that you sync from the active unit to the standby unit.

There may be rare situations, such as an outage on the currently active unit, where you want to sync the CMI from the standby to the active. In these situations, F5 recommends that you force the active unit to Force Offline and allow the standby unit that has the latest configuration you want, to take over.
