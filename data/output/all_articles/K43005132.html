Known Issue

The Traffic Management Microkernel (TMM) may produce a core file and restart when processing mirrored connections.

This issue occurs when all of the following conditions are met:

  • The BIG-IP device is configured for mirroring.
  • The BIG-IP device 's configuration includes a virtual server that uses a non-default lasthop configuration. (For example, the BIG-IP system is configured to use lasthop pools, or auto-lasthop is disabled.)
  • The virtual server is configured with connection mirroring.
  • The BIG-IP device is in standby for an extended period of time.
  • The active BIG-IP device mirrors connection information to the standby BIG-IP device.

Impact

The TMM process produces a core file and restarts.

Note: Traffic processed by the active BIG-IP device is not impacted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process restarts and generates a TMM core file to the /shared/core directory.
  • The BIG-IP system logs a message similar to the following example to /var/log/tmm at the time of the event:

    notice panic: ../net/nexthop.c:165: Assertion "nexthop ref valid" failed. 
    notice ** SIGFPE **
