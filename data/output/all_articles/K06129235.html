Known Issue

The rewrite process may not rewrite some RSS XML file links.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured with a portal access profile.
  • Content processed through the portal access includes RSS XML files.
  • The RSS XML file(s) contains additional XML namespaces.

    For example:

    <rss xmlns:a10="http://www.w3.org/2005/Atom" version="2.0">
    <channel>
    <a10:author> author </a10:author>
    <link> http://example.com </link>

    Note: In this example, the content of the <link> tag may not be appropriately rewritten.

Impact

The rewrite process does not rewrite the RSS XML link, and it points to the original destination.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When analyzing the XML file links, not all links are appropriately rewritten for portal access.
  • Accessed links that are not rewritten direct the user to resources located outside of the portal.

Workaround

To work around this issue, you can craft a content-specific iRule to rewrite RSS XML file links.

Impact of workaround: F5 recommends implementing the custom iRule during a scheduled maintenance window. 

In some scenarios, you can create an iRule to recognize a specific server response URL pattern. The iRule can then rewrite the URLs that contain the pattern, replacing the response content with the appropriate URL BIG-IP APM format.

In the following example, the iRule searches for URLs that contain some.rss and then rewrites the hostname to a hexadecimal value by appending the hexadecimal value and original path of the URL to the statically configured BIG-IP APM virtual server hostname.

The content rewrite of the pattern is http://some.host.to.replace.com/ (the search pattern is 31 characters long). The URL search pattern is then rewritten to a hexadecimal value and appended to the statically set BIG-IP APM virtual server hostname, along with the original URL path that occurs after the search pattern:

https://bigip.host.name.com/f5-w-687474703a2f2f736f6d652e686f73742e746f2e7265706c6163652e636f6d$$/some/path

Example iRule stanza:

when REWRITE_REQUEST_DONE {
  if { [ HTTP::path ] contains "some.rss" } {
    set RSS_patch 1
  }
}

when HTTP_RESPONSE {
 if { [info exist RSS_patch] } {
    if { [HTTP::header exists "Content-Length"] and \
         [HTTP::header "Content-Length"] > 0 and \
         [HTTP::header "Content-Length"] <= 500000 } {
      HTTP::collect [HTTP::header Content-Length]
    } else {
      HTTP::collect 500000
    }
  }
}

when HTTP_RESPONSE_DATA {
 if { [info exist RSS_patch] } {
    unset RSS_patch
    set start [HTTP::payload length]
    while { 1 } {
      set start [string last {http://some.host.to.replace.com/some/path} [HTTP::payload] $start]
      if { $start < 0  ||  $start >= [ expr { [HTTP::payload length] - 31 } ] } { break }
      HTTP::payload replace $start 31 { https://bigip.host.name.com/f5-w-687474703a2f2f736f6d652e686f73742e746f2e7265706c6163652e636f6d$$/some/path}
    }    
  }
}

Note: bigip.host.name.com is the statically set hostname of the BIG-IP APM virtual server.
