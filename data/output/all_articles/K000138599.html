K000138599: HTTP2 PING frame are not forwarded to server side.

Support Solution

2024-02-14
Applies to

Source

Description

HTTP2 PING frames from client side are not forwarded to server side.

HTTP2 PING frames from server side are not forwarded to client side.


This is an expected behavior.

Environment

HTTP2 full Proxy Configuration.

Cause

In the HTTP/2 protocol, the Stream ID 0 is reserved for the connection flow control windows and other connection-wide communication. It's used for frames that apply to the entire HTTP/2 connection rather than a specific stream.

Internally TMM has a client side connection and a server side connection associated to each other but not sharing all the parameters of HTTP/2 protocol. TMM terminates the client side connection and handles all the connection wide frames line PING, GOAWAY and WINDOW_UPDATE with stream ID 0 locally. 


Additional Information

HTTP/2 defines several frame types that can be associated with Stream ID 0.

  1. SETTINGS: This frame type is used to communicate configuration parameters for the HTTP/2 connection. It applies to the entire connection, hence it uses Stream ID 0.
  2. WINDOW_UPDATE: This frame type is used to implement flow control. It allows either the client or server to update the flow control window for the entire connection.
  3. PING: The PING frame is used for measuring the round-trip time between endpoints and checking if the peer is still alive. It applies to the entire connection.
  4. GOAWAY: The GOAWAY frame is sent by one endpoint to gracefully shut down a connection. It is sent from one peer to another and applies to the entire connection.
  5. SETTINGS_ACK: This frame acknowledges the SETTINGS frame, indicating that the peer has received the settings.
