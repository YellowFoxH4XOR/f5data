K24168272: Down-level login requires four backslashes in AS3 declarations

Type
Support Solution
Published
2022-05-09
Updated
2023-02-21
Applies to
  • F5 Automation and Orchestration
  • F5 Application Services 3 Extension
Source
https://my.f5.com/manage/s/article/K24168272

Description

When using down-level login syntax (i.e., DOMAIN\username) in an AS3 declaration, you may see login failures despite having ensured that the username, domain, and password are all correct.  This problem will manifest if an AS3 declaration is being used to publish, say, a monitor that requires authentication.

Environment

  • AS3, any version

Cause

AS3 requires one to put no fewer than four back-slashes when using an AS3 template that, itself, requires authentication against an active directory environment (i.e., DOMAIN\\\\username).  The reason is because of the way this part of the declaration is handled:

  • The AS3 template itself is fed to a parser; that parser will see the four backslashes, and consider the first and third backslash to "escape" the second and fourth backslashes - that is, treat them as literal backslashes - per UNIX conventions.  This results in the target reading "DOMAIN\\\\username", and returns with "DOMAIN\\username"
  • When the template arrives on the Big IP, it will then feed that information to a shell script that itself requires the escaped backslash - where we now have "DOMAIN\\username", that second backslash is going to remain because the first backslash tells bash that, for all intents, the very next character must be treated as precisely what is presented.  Therefore, "DOMAIN\\username" is parsed as "DOMAIN\username" by the shell itself.

Recommended Actions

When using down-level authentication syntax for logging into AD domain controllers via an AS3 declaration, use four backslashes to separate the domain and username.
