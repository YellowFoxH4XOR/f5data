Description

You may need to run userland applications (such as ssh, curl, ftp, ping, ip route get) against a node or a pool member that does not reside in the default route domain of the BIG-IP system. BIG-IP supports and enforces route domain separation. For example, traffic in route domain 1 (RD1) will operate within RD1 only. Traffic will not be seen in any other route domains, including the default route domain 0 (RD0). This includes traffic-generating commands that are run in the bash shell. This behavior is by design. As a result, you can run userland applications against a node or pool member that resides in a non-default route domain by using the following utilities:

  • rdexec
  • rdsh

Environment

  • BIG-IP
  • Host/userland utilities
  • Route domains

Procedures

The rdexec utility

The rdexec utility allows you to perform a single command for the specified route domain. Use the following syntax:

rdexec <route domain id> <command> [<arguments>]

In this command, note the following:

  • <route domain id> is the route domain in which you want to run the command
  • <command> [<arguments>] is the userland application

For example:

  • rdexec 10 ssh 10.0.0.2
  • rdexec 10 ip route get 10.0.0.2

The rdsh utility

The rdsh utility allows you to change the shell to the specified route domain. This utility provides a similar effect of adding the specified route domain notation to all addresses that are used as arguments with the userland applications until you exit the shell. This is useful if you want to perform a series of commands for only a specific route domain without having to run the rdexec utility for every command.

Use the following syntax:

rdsh <route domain id>

In this command, note the following:

  • <route domain id> is the route domain to which you want to change shell

For example, you change shell to route domain 10 by entering the following command:

rdsh 10

You can then run commands in that route domain. For example:

  • ssh 10.0.0.2
  • ip route get 10.0.0.2

Type exit to leave the rdsh session.

Recommended Actions

Use the rdexec and rdsh utilities as described in this article when you want to run userland applications on BIG-IP.
