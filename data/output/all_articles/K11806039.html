Known Issue

The Configuration utility may erroneously allow the resource administrator role to set the Install Configuration option when activating an alternate boot location.

This issue occurs when all of the following conditions are met:

  • You are assigned the resource administrator role on your BIG-IP system.
  • You attempt to use the Configuration utility's Boot Locations menu to reboot the BIG-IP system from an alternate boot location.
  • You select an alternate boot location (for example HD1.1) and activate the boot location by setting the Install Configuration option to Yes.

The resource administrator role does not include the permissions necessary to roll forward the BIG-IP configuration to the selected boot location. The resource administrator role should not be able to configure the Install Configuration option.

Note: Regardless of your assigned role, you cannot install a configuration when activating a boot location on VIPRION platforms. Additionally, if you attempt to use as the configuration source a version of the boot location that is earlier than the selected version of the boot location, the activation fails and the BIG-IP system displays an error message which appears similar to the following example:

info: New version (11.x.x) is not >= originating version (12.x.x); configuration is not compatible. configuration roll-forward desired but not compatible.

Impact

The BIG-IP system fails to reboot from the desired boot location.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you click Activate to restart the BIG-IP system from an alternate boot location, the Configuration utility indefinitely displays the reboot status page.
  • The reboot operation fails and the BIG-IP system logs an error message in the /var/log/ltm file which appears similar to the following example:

    err tmsh[18720]: 01420006:3: unexpected argument "reboot"

Workaround

To work around this issue, you can use the Configuration utility to establish a new session, navigate to System > Software Management > Boot Locations, select an alternate boot location, and then set the Install Configuration option to No before attempting to reboot.

Impact of workaround: On a standalone device, the suggested workaround disrupts traffic processing while the BIG-IP system reboots. If the device is configured as part of a high availability (HA) pair, it may fail over. F5 recommends that you perform this procedure during a scheduled maintenance window.
