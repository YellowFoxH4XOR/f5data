K65524212: Big-IQ backup schedule failed with error: com.f5.rest.workers.storage.KeyNotFoundException: Get document for key: shared/authz/users/<user> returned nothing

Description

Big-IQ scheduled backup suddenly fails with error message:

[WARN][22 Aug 2023 03:30:00 AEST][] Unable to fetch updated user reference (and possibly execute a task). Ex: com.f5.rest.workers.storage.KeyNotFoundException: Get document for key: shared/authz/users/backup_user returned nothing
    at com.f5.rest.workers.storage.postgres.PgRequestProcessor.sendGet(PgRequestProcessor.java:269)
    at com.f5.rest.workers.storage.TransactionRunnable.dispatch(TransactionRunnable.java:570)
    at com.f5.rest.workers.storage.TransactionRunnable.run(TransactionRunnable.java:488)
    at java.util.concurrent.ThreadPoolExecutor.runWorker(ThreadPoolExecutor.java:1149)
    at java.util.concurrent.ThreadPoolExecutor$Worker.run(ThreadPoolExecutor.java:624)
    at java.lang.Thread.run(Thread.java:748)

 

Environment

  • Big-IQ
  • Big-IP
  • UCS

Cause

The user that was logged in when backup schedule was initially created is link as userReference in the backup properties. Hence, if this user no longer exist or the user changed to a role that is no longer allowed to create backups, above error is seen.

Recommended Actions

1. Recreate local user with the same user name as indicated in the failed backup and make sure it has admin role to allow backup creation. For instance from above errors, recreate "backup_user"

or

2. Delete and recreate backup that's failing while logged in as local admin.
