Topic

This document discusses the network connectivity requirements for the BIG-IQ system to access remote BIG-IP devices and peer BIG-IQ high availability (HA) devices.

Description

The BIG-IQ system requires network connectivity to discover, manage, and monitor remote BIG-IP devices, BIG-IQ Data Collection Devices (DCDs) and peer BIG-IQ devices. If you do not specify the required network communication routes among the devices, device discovery fails and the system cannot manage devices or configure them as HA peers. To help determine network connectivity among your BIG-IQ and its peers, DCDs, and BIG-IP systems in your environment, you can use the f5-bigiq-connectivityChecks tool. For installation and usage instructions, refer to the F5 BIG-IQ PM Team GitHub repository.

The following sections discuss the necessary interfaces and service ports required for successful communication among devices.

  • Requirements for BIG-IQ management
  • Requirements for BIG-IP device discovery, management, and monitoring
  • Requirements for HA BIG-IQ peers
  • Requirements for BIG-IQ Data Collection Devices

F5 recommends that you isolate the traffic between BIG-IQ cluster nodes for performance and improved security. For more information, refer to the Planning a BIG-IQ Centralized Management Deployment chapter of the Planning and Implementing a BIG-IQ Centralized Management Deployment manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Requirements for BIG-IP device discovery, management, and monitoring

For BIG-IQ 4.x through 5.x, your remote BIG-IP devices must be running 11.3.0 HF6 or later to be discoverable and manageable. 

For BIG-IQ 6.0 and later, your remote BIG-IP devices must be running BIG-IP 12.1.0 or later to be discoverable and manageable.

The BIG-IQ system uses token-based authentication on TCP port 443. During the device discovery phase, the system bases the first communication that happens on administrative user and password authentication. The BIG-IQ and BIG-IP devices establish the token by cryptographically secure mechanism, and each end stores the relevant information. Subsequent connections use the token, which is apparent in the API calls made over TLS.

While the username and password are passed in the initial authentication request as JSON key/value pairs, they are not subsequently needed because the system uses the token. The system encrypts all token-based communications to prevent attackers accessing credential and token information.

The IPv4 and IPv6 dual stack is not supported currently for the BIG-IQ management. You can assign either IPv4 or IPv6 addresses to the management interface, but you cannot assign both IPv4 and IPv6 addresses.

Requirements for BIG-IQ HA peers

BIG-IQ hosts discover and form trust relationships only within HA configurations on devices running the same version.

Note: Beginning in version 5.2.0, BIG-IQ systems in an HA configuration must use either a self IP address or the management IP address and chosen address must be the same as discovery ip. If you experience errors when attempting to add a secondary BIG-IQ system, refer to K20171509: Error Message: An error occurred while adding the BIG-IQ Device: (primary) connects as to (secondary).

Note: Beginning in version 5.0.0, all BIG-IQ systems in an HA configuration must use the same master key. If you experience master key errors when adding a BIG-IQ HA peer, refer to K10799025: Error Message: Master Keys differ between this BIG-IQ and the one you are attempting to discover.

BIG-IQ 4.5.0 - 5.1.0You can use either a self IP address or the management port address. The preferred communication method is the management port address.

Requirements for BIG-IQ Data Collection Devices (DCD)

The BIG-IQ system establishes trust to BIG-IP and DCD devices using administrative credential over TLS to exchange device certificates. After the exchange of certificates, the mutually trusted devices use these certificates for secure communication (mutual authentication using certificates).

IPv6 is supported for DCD communications, but not in dual stack mode. The IPv4/IPv6 addresses must be split into dedicated Zones or VLANs.
