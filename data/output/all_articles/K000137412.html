Description

An error has been reported when attempting to access Moodle course platforms through the F5 BIG-IP Access Policy Manager (APM) portal. Specifically, there is an error when trying to access a lesson within a course. Browser console logs indicate issues related to "cache-fm.js" with an unsafe header "F5_Origin" and a Cross-Origin Resource Sharing (CORS) error due to the 'Access-Control-Allow-Origin' header configuration.

Environment

  • BIG-IP APM

  • Portal Access

  • Moodle

  • CORS

Cause

This is caused by an injected JavaScript file '/private/fm/cache-fm.js' within the Moodle application, which overrides the 'fetch' function by adding the 'include' credential. This action leads to a CORS error, as the browser expects specific headers to be present when credentials mode is 'include'. The issue is observed when accessing the Moodle platform through APM but not when using the application directly within the internal network.

Recommended Actions

To fix these issues, you can follow the steps described above:

  1. Modify the bypass list entries within the APM rewrite profile to correct the Content-Security-Policy (CSP) entries, ensuring that external hosts are added to the CSP headers set by BIG-IP.
  2. Apply an iRule to the APM Virtual Server to prevent rewriting of specific content within HTML files that could be causing the issue. The iRule should target the specific paths that are known to generate problematic requests.
  3. If necessary, adjust the iRule to accommodate additional course paths by using pattern matching to identify the relevant URLs.
  4. Clear the browser cache before testing these changes to ensure that old data does not interfere with the new configuration.
  5. Test the application from a user perspective to confirm that the issues are resolved and that there are no visible negative impacts.

Note: You may need to open a support case with F5 Networks Support for additional assistance.

Additional Information

It is important to note that the iRule used may need to be tailored to the specific environment and application architecture. Further testing may be required to identify all the course URLs that require this treatment. For any additional issues or troubleshooting, customers are encouraged to contact F5 technical support for further assistance

Refer to F5 knowledge base article K13907 for detailed instructions on using the <apm_do_not_touch> HTML tags to prevent APM from rewriting specific HTML content.
