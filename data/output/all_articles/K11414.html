Known Issue

Note: This Solution applies to the BIG-IP 6900 and 8900 platforms only.

Note: This Solution discusses mirrored volume sets. For more information, refer to K10856: Overview of hard drive mirroring.

This is the result of a known issue. The BIG-IP system experiences a kernel panic when the following conditions are met:

  • A BIG-IP 6900 or 8900 system is running a manufacturing or clean installation of version 10.1.0 or later. The volumes disk-formatting scheme was chosen during the installation, resulting in the creation of mirrored volume sets only (MD1.1, MD1.2, and MD1.3).
  • A new non-mirrored (single-disk) volume set is created (for example, HD1.1).
  • BIG-IP version 10.0.x is installed on the new volume set.
  • The BIG-IP system is booted from the new volume set.

When attempting to boot the BIG-IP system from the 10.0.x installation, the system displays a series of error messages indicating that some logical volumes could not be activated. This behavior causes the BIG-IP system to fail to mount the root file system and experience the following kernel panic:

Mounting root filesystem
mount: error 2 mounting ext3
pivotroot: pivot_root(/sysroot,/sysroot/initrd) failed: 2
umount /initrd/proc failed: 2
Kernel panic: No init found.  Try passing init= option to kernel. Rebooting in 1 second..

This issue occurs because of a constraint in the logical volume management (LVM) implementation running on the BIG-IP system.

F5 Product Development is tracking this issue as ID 223585 (formerly CR130702).

Workaround

You can avoid this issue by ensuring that no more than one mirrored volume set exists prior to installing version 10.0.x on a non-mirrored volume set on the same system.

If you have already encountered the issue described in this Solution, perform the following procedure to recover the BIG-IP system:

  1. Connect to the BIG-IP system serial console.

    Note: For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system.
  2. Power cycle the BIG-IP system.
  3. When the GRUB menu displays, select the 10.1.0 or later installation.
  4. Press enter to boot the system.
  5. When the system has completed booting, log on to the command line.
  6. At this point, the 10.0.x boot location is the default boot location. Using the switchboot utility, set the version 10.1.0 boot location as the default boot location.

    For example, to set MD1.1 as the default boot location, you would enter the following command:

    switchboot -b MD1.1

    Important: This step is necessary because the Configuration utility assumes that the system was booted from the default boot location. In Step 3 of this procedure, you have booted the system from a boot location other than the default location. You will not be able to complete the remaining steps if the default boot location is not set to the current boot location.
  7. Log on to the Configuration utility.
  8. Navigate to System > Software Management > Volume Management.

    If Step 5 was executed correctly, the Configuration utility should report the boot location you selected in Step 3 as the active boot location. If the non-mirrored volume set is reported active, you have not executed Step 5 correctly.
  9. Select all inactive mirrored volume sets.

    For example:
     
    MD1.2
    MD1.3
  10. Click the Delete button.

The BIG-IP system should now feature one mirrored volume set (currently active and running version 10.1.0 or later), and one non-mirrored volume set (inactive and imaged with version 10.0.x).
