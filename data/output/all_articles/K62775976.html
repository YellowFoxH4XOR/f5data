Known Issue

The SSL Orchestrator may fail to send HTTP traffic to the Internet Content Adaptation Protocol (ICAP) server.

This issue occurs when all of the following conditions are met:

  • The HTTP traffic is not using standard ports, such as 80, 443, or 8080.
  • Only the ICAP service is configured in the affected service chain.

Impact

The system fails to forward the affected traffic to the ICAP server. As a result, the ICAP server will not monitor the affected traffic.

Note: This issue does not prevent the SSL Orchestrator from forwarding the affected traffic to the destination web server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The ICAP server has no record of the affected traffic; as a result, the ICAP server does not generate errors or redirects for traffic that should have been marked for errors or redirects.
  • Connections that should fail or be redirected appear to be successful, while the SSL Orchestrator logs incorrectly show them as successful.
  • When debug logging is enabled on the SSL Orchestrator, the /var/log/ltm log file does not show traffic being forwarded to the ICAP server.

Resolution

Status

Workaround

To work around this issue, you should ensure that there are at least two services configured in the service chain that handles HTTP traffic, not using the standard ports. For more information about creating additional services in a service chain, refer to the Creating Services Service Chains and Classifier Rules chapter of the F5 Herculon SSL Orchestrator: Setup manual.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Impact of workaround: Depending on your application environment, as well as the additional service configured, the additional traffic generated may introduce some performance impact for the SSL Orchestrator.
