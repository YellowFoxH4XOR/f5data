K000141160: Faster recovery for HSB FCS errors conditions on BIG-IP unit

Type
Support Solution
Published
2024-09-24
Updated
2025-05-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.1.X, 17.1.1
Source
https://my.f5.com/manage/s/article/K000141160

Description

If BIG-IP experiencing high number of FCS errors, HSB will try to reset itself before reboot (the behaviour is tracked by ID 930825).

 

You might see logs similar to the following in var/log/tmm:

 

notice HSB XLMAC phy reset due to fcs errors on HG links on bus X.

notice HSBEX 1 disable XLMAC TX/RX at runtime.

notice HSBEX 1 enable XLMAC TX/RX at runtime.

 

You may also see internal interface between switchboard and HSB going up/down.

 

Environment

  • BIG-IP LTM
  • HSB XLMAC errors

Cause

 

It is unknown under what conditions the XLMAC errors occur.

 

Recommended Actions

By default, the number of times BIG-IP tries to reset HSB is 11 times. This number is controlled by the following db-key:

 

sys db tmm.hsb.xlmachaaction {

default-value "11"

scf-config "true"

value "11"

value-range "unsigned_integer min:0 max:100"

}

 

tmm.hsb.xlmachaaction controls how many times we are going to try to restore the channel before taking HA action, by default it is set to '11'.

You can decrease it to allow for a faster failover (note: '0' disables the recovery mechanism.)

 

Change tmm.hsb.xlmachaaction to a lower number for a faster failover:

tmsh modify sys db tmm.hsb.xlmachaaction value <x>

 

Additional Information

Bug ID 748443: HiGig MAC recovery mechanism may fail continuously at runtime
