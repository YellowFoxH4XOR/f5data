K10510: The BIG-IP GTM system does not support discovery of virtual servers configured in non-default route domains

Topic

Note: Beginning BIG-IP version 10.2.2, the BIG-IP GTM system supports discovery of virtual servers configured in non-default route domains. For more information, refer to K12977: Change in Behavior: BIG-IP GTM now supports discovery and monitorin of BIG-IP virtual server objects that are associated with route domains. For information about configuring this functionality, refer to K12969: Configuring BIG-IP GTM to discover and monitor BIG-IP virtual servers that are associated with route domains

In versions prior to 10.2.2, if Virtual Server Discovery is enabled for a BIG-IP LTM system that is being added to the configuration of a BIG-IP GTM system, and the BIG-IP LTM system features at least one virtual server configured in a non-default route domain, the BIG-IP GTM system may fail validating the new configuration and log an error message to the /var/log/gtm file that appears similar to the following example:

ERROR, recvMCPreply: Got bad result: 01070973:3: Route Domain 10 does not exist for address (172.16.20.20%10).

Note: This issue does not occur if the BIG-IP system is licensed for both BIG-IP LTM and GTM, and is configured with the same route domains as the remote BIG-IP LTM system that is being added to the BIG-IP GTM configuration.

If you experience this issue, you may find that the BIG-IP GTM system Configuration utility stops displaying some or all virtual servers, including those that may have been previously discovered correctly and are configured in the default route domain. This behavior occurs because after the BIG-IP GTM system attempts to discover a virtual server configured in a non-default route domain, the system fails to parse the configuration until a BIG-IP Administrator manually fixes the configuration. You can verify the validity of the BIG-IP GTM configuration from the command line interface by running the following command:

gtmparse -l

This configuration should fail similar to the following example:

gtmparse: Initializing ...
/usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
/usr/local/gtm/include/base_region.ISP: SUCCESS
/config/gtm/wideip.conf: SUCCESS
gtmparse: SUCCESS
ERROR, recvMCPreply: Got bad result: 01070973:3: Route Domain 10 does not exist for address (172.16.20.20%10).

To restore your BIG-IP GTM configuration to a working state, you must disable Virtual Server Discovery for the BIG-IP LTM system that is advertising a virtual server in a non-default route domain, and edit the wideip.conf file to remove the virtual server in the non-default route domain. To do so, perform the following procedures:

  • Disabling Virtual Server Discovery
  • Removing the virtual server statement from the wideip.conf file

Disabling Virtual Server Discovery

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Expand the Global Traffic section.
  3. Click Servers.
  4. Click the BIG-IP LTM server that is advertising a virtual server in a non-default route domain.
  5. Click the Virtual Servers tab.
  6. Using the drop-down box, change Virtual Server Discovery to Disabled.
  7. Click the Update button.

Removing the virtual server statement from the wideip.conf file

  1. Log in to the BIG-IP GTM command line.
  2. Change directories to the /config/gtm/ directory by typing the following command:

    cd /config/gtm/

  3. Back up the current wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.backup

  4. Using a text editor, edit the /config/gtm/wideip.conf file.
  5. Scroll down the file until you find the server that advertised a virtual server in a non-default route domain.
  6. Remove the virtual server that is not configured in the default route domain.

    For example, you would need to delete the following lines in the case of 172.16.20.20%10:

       vs {
          name            "main_http"
          address         2610:0:c10:f501:0:a:ac10:1414.80 // http
       }

    Note: All virtual servers configured in non-default route domains are written to the wideip.conf file using their IPv6 notation, which all start with 2610:0:c10:f501:0 (in BIG-IP versions prior to 10.1.0) or 2620:0:c10:f501:0 (in BIG-IP versions 10.1.0 or later). For more information about converting the IP%ID notation to an equivalent IPv6 address, refer to K10467: Userland applications on a BIG-IP system cannot connect to hosts in non-default route domains and K10511: The BIG-IP system uses the wrong IPv6 address range for the Route Domain feature.

    Note: If more than one virtual server configured in a non-default route domain is advertised to the BIG-IP GTM system, you will need to remove all of them.

  7. Save the wideip.conf file.
  8. Quit the text editor.
  9. Using the gtmparse -l command, reload the BIG-IP GTM configuration and verify that no errors are returned.

    For example:

    gtmparse: Initializing ...
    /usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
    /usr/local/gtm/include/base_region.ISP: SUCCESS
    /config/gtm/wideip.conf: SUCCESS
    gtmparse: SUCCESS



    All virtual servers configured in the default route domain should now appear in the BIG-IP GTM Configuration utility.

If you have a BIG-IP LTM system that features some virtual servers in the default route domain and other virtual servers in non-default route domains, you should manually add the virtual servers in the default route domain to your BIG-IP GTM configuration.

Note: For more information about adding virtual servers manually, refer to the Managing Virtual Servers section in the Configuration Guide for BIG-IP Global Traffic Management.

Alternatively, if you do not want to do this step because you must manually add a large number of virtual servers, allow the BIG-IP GTM system to discover all virtual servers, and then fail validating the new configuration. After this action has occurred, perform the two procedures described above to fix your BIG-IP GTM configuration.

F5 Product Development tracked an enhancement request regarding discovery of virtual servers in non-default route domains as ID 221998 (formerly CR107402) and the feature was added in BIG-IP GTM version 10.2.2. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this feature was added in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
