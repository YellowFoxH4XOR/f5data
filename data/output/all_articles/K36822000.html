Description

When trying to load a BIG-IP UCS in a platform migration scenario, if an error occurs during the loading process, the system may incorrectly report a Symmetric Unit Key decrypt failure error. This occurs even if there is another validation error preventing the configuration load and the master key has been updated in the destination device to match the master key from the source device.

In a normal situation different errors can occur in the loading, you can go to the configuration files and edit them to get the load to be successful, but if you don't know what the error is, you won't know how to fix it. This is the issue. If the error happens just after a successful symmetric key validation (master key updated) the error value is not updated so the error presented to the user is the Symmetric Unit Key decrypt failure.

Environment

  • Platform migration
  • Loading UCS from a different BIG-IP
  • Master Key correctly copied
  • The UCS archive does not contain a .unitkey file.

Cause

Bug ID 1043141: Misleading 'Symmetric Unit Key decrypt failure - decrypt failure' when loading UCS from another BIG-IP
 

Recommended Actions

Run the command tmsh load sys config verify by following the steps below or examine /var/log/ltm for error messages from MCPD during the config load other than the Symmetric Unit Key decrypt failure. The errors are usually right before or right after the error in the log and are most commonly related to network interfaces.

  1. Log into the BIG-IP command line.
  2. Run a test load of the configuration by typing the following:
    tmsh load sys config verify
  3. Review output to determine the error that is preventing the configuration from loading.
  4. Manually edit the appropriate configuration file to resolve the error. For more information refer to the Determine the configuration objects causing the load failure and investigate a resolution section in K02091043: Error Message: The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
  5. Attempt to load the configuration again using the platform-migrate option:
    tmsh load sys config platform-migrate

Note: The system may not always show all errors at one time, as the config load fails after just one error is noticed. For example, if there is a problem with two interfaces, the system may only show a problem with one. After you fix that one and attempt to migrate, only then will it show the second one.

If there are multiple errors listed in the tmsh load sys config verify output or /var/log/ltm log file, or there aren't any that seem relevant, follow these steps:

  1. Restart MCPD:
    bigstart restart mcpd
  2. Attempt to load the configuration again using the platform-migrate option:
    tmsh load sys config platform-migrate
