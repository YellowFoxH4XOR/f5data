Known Issue

A rare race condition causes the following Traffic Management Microkernel (TMM) assertion: tcp_set_persist: retransmit pending. Then, the BIG-IP system restarts and generates a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a Transmission Control Protocol (TCP) setting that causes TMM to use the performance TCP stack.
  • The persistence timer and retransmission timer in the TCP stack are active simultaneously.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily fails to process traffic as it recovers from a TMM restart.
  • When the BIG-IP device is configured for HA, it fails over to a configured peer device.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.

Workaround

To work around this issue, you can configure the BIG-IP system to use the default TCP IPv4 stack by using the default TCP profile.

Impact of workaround: The impact of the suggested workaround will depend on your specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
