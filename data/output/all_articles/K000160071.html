K000160071: OCSP stapling using a proxy server sends malformed HTTP host header to OCSP server

Type
Support Solution
Published
2026-03-04
Updated
2026-03-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160071

Description

Setting up System  ››  Certificate Management : Traffic Certificate Management : OCSP   

  • Correctly setting up an OCSP responder to monitor a traffic certificate fails.
  • Capture data shows F5 sending the full URL and path in the OCSP request HTTP host: header.
    • Example of non-compliant host header:
      • GET /alpine/v3.18/main/x86_64/APKINDEX.tar.gz HTTP/1.1
      • Host: my.ocsp.server/ocsp 
  • Backend OCSP server sends HTTP 400 BAD REQUEST in response as HTTP host header is not RFC compliant and contains a URi.

Environment

Use https://my.f5.com/manage/s/article/K75106155 to configure an OCSP responder for monitoring of an SSL certificate.

OCSP responder is then configured with:

  • "Use Proxy Server" checked.
  • The "responder URL" has a path after the host (ex. http://my.ocsp.server:80/ocsp)

Cause

This issue is tracked in Bug ID 2220009. The HTTP/1.1 OCSP request is malformed as the HOST header contains the host plus the path after it.

Answer/Recommended Actions

If you encounter it, please open a support case and request an engineering hotfix to resolve it.
