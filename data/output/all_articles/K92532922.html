Issue

Description

Event correlation displays a list of incidents (suspected attacks on the web application). Requests become incidents when at least two illegal requests are sent to the web application within 15 minutes, and the system groups them according to criteria. The criteria concern illegal requests for a specific URL, a specific parameter, or a specific source IP address.

Environment

  • BIG-IP ASM

Cause

The limits for event correlation are defined in the /etc/ts/correlation/correlation.cfg file. When the number of unique sessions for an incident is reached, the referenced ASM event logs are generated in the /var/log/asm file. The event logs appear similar to the following:

ControlPlane.CorrelationEngine[359]: ControlPlane.CorrelationEngine`CRIT`Sep 03 21:04:19.742`396 `[update_incident() at CorrelationEngine.cpp:2358] Limit of unique sessions for this incident reached"

New violating requests continue to accumulate for this incident; however, the counter of unique sessions is limited to prevent excessive memory usage. For example:
[root@BIGIP-02:Standalone] config # more /etc/ts/correlation/correlation.cfg
[General]
// CountLimit - limit of unique sessions / users / IPs for each real incident in memory
CountLimit=1000

Recommended Actions

The limit of unique sessions may exceed if the activity is suspicious or a false positive violations. In the event of Limit of unique sessions for this incident reached is observed, application requests and event correlation pages are places you can start your investigation.

  • Security > Event Logs > Application > Requests 
  • Security > Event Logs  > Application > Event Correlation

Ways to analyze a request

  1. If the event correlation criteria entry says N/A:
    • Review the application requests for the reference time frame. Using the Time Period filter when you observe the actual Limit of unique sessions for this incident reached message.
    • Reviewing the actual violation and fine tuning the security policy. If the violation is a false positive, this helps to reduce the number of requests BIG-IP ASM that trigger a violation.
       
  2. To see if any violations have recently occurred, you can examine the event log called the Requests List. It is a good idea to look for spikes and irregular behavior in the this log because this behavior usually indicates suspicious activity.
