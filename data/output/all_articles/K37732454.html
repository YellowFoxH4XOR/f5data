Description

This article describes how to change the device discovery IP from the management IP to the self IP.

Environment

  • BIG-IQ
  • Device Discovery IP

Cause

During the initial setup of BIG-IQ, there is an option to set a discovery address as a self IP address; however, this is only possible if the VLAN and self IP have been pre-configured through the CLI before using the Wizard in the GUI. At times, the management IP might be selected as a discovery address instead and this cannot be changed through the GUI.

Recommended Actions

To change the device discovery IP from the management IP to a self IP, follow the steps below:

  1. Verify if the transport address (device discovery IP) is set as the management address.

    On the BIG-IQ CLI, run:
    restcurl cm/shared/esmgmt/cluster

    Example output:
    "transportAddress": "m.m.m.m"

  2. To change this to a self IP, use a PATCH request. On the BIG-IQ CLI, from the command in step 1, COPY the whole "nodes": [] array block. You will modify the transportAddress value to the self IP in step 3.

  3. Construct the PATCH command as below. Make sure you add your "nodes":[] details correctly, matching all the brackets. Execute the following PATCH request:
    a. replace XXXXX with your admin password,
    b. replace s.s.s.s with the self IP, 
    c. Replace the UUIDs below in the URL, "id", and "machineId" with the values you obtained in the output from step 1.
    d. Replace a number "79c9b2a0-b3c0-4b38-8fd8-54589df987ef" on begining of the command with a id number as well.

    restcurl -u admin:XXXXX -X PATCH /cm/shared/esmgmt/cluster/79c9b2a0-b3c0-4b38-8fd8-54589df987ef -d '{ "id": "79c9b2a0-b3c0-4b38-8fd8-54589df987ef", "isOriginator": true, "nodes": [ { "machineId": "c865042f-19fb-4424-bcd8-d5bd248ee2d7", "allowData": false, "allowMaster": true, "httpAddress": "127.0.0.1", "httpPort": "9200", "transportAddress": "s.s.s.s", "transportPort": "9300", "zone": "default", "mlockall": false, "repo": "/var/config/rest/elasticsearch/data", "generation": 0, "lastUpdateMicros": 0 } ] }'

  4. In the previous PATCH request the following changes the transportAddress to be the discovery address: "transportAddress": "s.s.s.s". Once the PATCH command is executed, verify that everything works by running the following command: 
    restcurl cm/shared/esmgmt/cluster

  5. Restart restjavad and elasticsearch.
    a. Run the following on all the devices in the cluster:

    bigstart restart restjavad

    b. Wait for the restjavad daemon to start on all the devices then run:

    bigstart restart elasticsearch

    Wait for the elasticsearch daemon to start.

  6. To verify if the change has been applied, run the following commands:
    restcurl cm/shared/esmgmt/cluster
    curl localhost:9200/_cat/nodes
    curl localhost:9200/_cluster/health?pretty

    Note: When adding a DCD, use only the discovery address. Your cluster should be healthy and working without using the management IP.
