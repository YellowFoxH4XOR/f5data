Known Issue

Note: This issue does not occur in BIG-IP versions 10.1.0 and later.

This is the result of a known issue. When one or more SNMP trap destination is defined on the BIG-IP system, both the default generic authentication warning messages and the audit log warning messages are logged for the same authentication trap event. As a result of these multiple log messages regarding the same event, the BIG-IP system generates and sends duplicate SNMP traps to its defined trap destinations for each authentication trap event.

F5 Product Development is tracking this issue as ID 334374 (Formerly CR123139).

Workaround

You can work around this issue by suppressing the default generic log messages which duplicate the SNMP traps. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /etc/alertd directory by typing the following command:

    cd /etc/alertd

  3. Back up the existing alert.conf file by typing the following command:

    cp alert.conf alert.conf.SOL10321

  4. Change the file permissions to allow editing by typing the following command:

    chmod 644 alert.conf

  5. Using a text editor, open the alert.conf file.
  6. Locate the following heading near the bottom of the file:

    /*********************************************************************/
    /* ADD any new alerts above this section */
    /*********************************************************************/
    /*
    * trap according to log level (CR38231)
    * #define LOG_EMERG 0 // system is unusable
    * #define LOG_ALERT 1 // action must be taken immediately
    * #define LOG_CRIT 2 // critical conditions
    * #define LOG_ERR 3 // error conditions
    * #define LOG_WARNING 4 // warning conditions
    * #define LOG_NOTICE 5 // normal but significant condition
    * #define LOG_INFO 6 // informational
    * #define LOG_DEBUG 7 // debug-level messages
    */


    Below this heading, you will see the following entries:

    alert BIGIP_LOG_EMERG "^[0-9]{8}:0: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.29"
    }
    alert BIGIP_LOG_ALERT "^[0-9]{8}:1: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.30"
    }
    alert BIGIP_LOG_CRIT "^[0-9]{8}:2: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.31"
    }

    /* we not alert those two until we make sure the log level for
    each message is accurate.
    alert BIGIP_LOG_ERR "^[0-9]{8}:3: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.32"
    }
    alert BIGIP_LOG_WARNING "^[0-9]{8}:4: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.33"
    }
    */

  7. Disable the BIGIP_LOG_EMERG, BIGIP_LOG_ALERT, and BIGIP_LOG_CRIT alert entries by using the following syntax:

    /* <-- Start of comment
    * <-- Comment wildcard
    */ <-- End of comment

    This section of the file should appear similar to the following example after the comment characters (in bold) have been inserted:

    /* alert BIGIP_LOG_EMERG "^[0-9]{8}:0: (.*)" {
    * snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.29"
    *}
    *alert BIGIP_LOG_ALERT "^[0-9]{8}:1: (.*)" {
    * snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.30"
    *}
    *alert BIGIP_LOG_CRIT "^[0-9]{8}:2: (.*)" {
    * snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.31"
    *}
    */
    /* we not alert those two until we make sure the log level for
    each message is accurate.
    alert BIGIP_LOG_ERR "^[0-9]{8}:3: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.32"
    }
    alert BIGIP_LOG_WARNING "^[0-9]{8}:4: (.*)" {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.33"
    }
    */

  8. Save the changes you made to the file.
  9. Restore the file permissions to read-only by typing the following command:

    chmod 444 alert.conf

  10. Restart the alertd process to load the file changes by typing the following command:

    bigstart restart alertd
