Consider using this procedure under the following conditions:
  • Your application is under a Remote File Inclusion attack.
  • Your system has BIG-IP ASM / AWAF 14.x or later installed.

A remote file inclusion attack is designed to cause the web application to retrieve and include a remote file through the manipulation of server-side parsed user input. Potential consequences of this range from sensitive information disclosure and Cross Site Scripting (XSS) through to Remote Code Execution if the file retrieved is executed within the context of the running application.

Such attacks are usually specific to the language or framework that the web application is written in.

Prerequisites

You should consider the following prerequisites before performing the following procedure:

  • BIG-IP ASM or AWAF are licensed and provisioned on your system.
  • A security policy is assigned to the virtual server.
  • The BIG-IP ASM request log is enabled by default to illegal request.
  • Default configuration is defined.

    Note: Default configuration means any of the BIG-IP ASM template with transparent and staging period on for the policy.

Procedures

BIG-IP ASM and AWAF can mitigate Remote File Inclusion attacks with the attack signatures or with defined metacharacters. This procedure lists the steps needed to mitigate such an attack using the attack signatures since this is the fastest and easiest configuration.

The procedure below includes how to assign the relevant attack signature set, enable it and configure it in blocking mode so that the Remote File Inclusion attacks can be mitigated. The final step is the mitigation verification where the admin can see the Remote File Inclusion attack being blocked.

Impact of procedure: Adding attack signatures to the security policy can generate false positives. In such case false positives should be removed using the learning page. Adding the Remote File Inclusion set includes signatures applicable to various types of application architecture rather than specific to the architecture in use, which may trigger false positives that require further tuning.
  • Add the Remote File Inclusion signatures
  • Enable and enforcing the Remote File Inclusion
  • Switch the enforcement mode to blocking
  • Verify that the Remote File Inclusion is being blocked
Add the Remote File Inclusion signatures
  1. Log in to the Configuration utility
  2. Go to Security >  Application Security > Policy Building > Learning and Blocking Settings.
  3. For General Settings, select Advanced. 
  4. Expand Attack Signatures.
  5. Select Change. 
  6. For Select Policy Attack Signature Sets, select the Remote File Include Signatures check box.
  7. Select Change.
  8. Verify that the signature set has Learn, Alarm, and Block enabled
  9. Select Save.
  10. Select Apply Policy. 
Enable and enforcing the Remote File Inclusion
  1. Log in to the Configuration utility
  2. Go to Security >  Application Security > Policy Building > Learning and Blocking Settings.
  3. For General Settings, select Advanced. 
  4. Expand Attack Signatures.
  5. For Remote File Include Signatures, select Enforcing and Enabling all Attack Signatures in the Signature Set.
  6. Clear the Enable signatures staging check box.
  7. Select Save.
  8. Select Apply Policy. 
 Switch the enforcement mode to blocking
  1. Log in to the Configuration utility
  2. Go to Security >  Application Security > Policy Building > Learning and Blocking Settings.
  3. For General Settings, select Advanced. 
  4. Under General Settings, for Enforcement Mode, select Blocking.
  5. Select Save.
  6. Select Apply Policy.
Verifying that the Remote File Inclusion is being blocked
  1. Go to Security > Event logs.
  2. Select the filter icon.
  3. Select the IP / Username / URL tab.
  4. For Attack Type, enter Remote File Include, then select Apply Filter.
  5. The blocked request should be listed in the request log.
  6. The violation name in the request log is shown as Attack Signature Detected.
