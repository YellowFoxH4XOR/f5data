K000092821: Using CPU type 'kvm64' instead of 'host' on Proxmox (KVM hypervisor) for BIG-IP VE can result in poor CPU performance

Description

Proxmox (KVM) hypervisor allows an admin to select the CPU type which the guest (Big-IP VE) will see and use when it boots up. Unfortunately, selecting the 'kvm64' CPU type can cause much worse performance than if 'host' is selected by the admin - typically seen when attaching an SSL Profile to a VS results in much higher CPU usage than expected (with 'host' type CPU).

Environment

  • BIG-IP VE on Proxmox (KVM)

Cause

The kvm64 CPU type presents a limited set of instructions to the Big-IP VE, which will greatly limit performance in some cases - most commonly used on things like SSL decryption/encryption functions on the Big-IP, so a typical scenario would be that the Big-IP VE's throughput becomes highly CPU-limited when an SSL profile is attached to a VS (so, when SSL decryption/encryption functions are required). There will likely also be other use cases where the CPU usage on kvm64 type CPU will be far higher than 'host', depending on the 'host' CPU capabilities.

Recommended Actions

Where possible, use the host CPU type in Proxmox (KVM) rather than kvm64.

Additional Information

The kvm64 cpu type is discouraged by QEMU: https://qemu-project.gitlab.io/qemu/system/qemu-cpu-models.html

However, the trade-off is that if the VMs are being run in a cluster, this can decrease VM portability across the cluster since all the hosts might not have the exact same CPU type - selecting 'kvm64' hides these differences from the guests, so an admin can seamlessly migrate VMs across the Proxmox (KVM) cluster.
