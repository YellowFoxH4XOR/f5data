Topic

You should consider using this procedure under the following conditions:

  • You are using a remote client authentication profile.
  • You require BIG-IP ASM Brute Force Protection to be enabled for authentication attempts.

Description

When the BIG-IP ASM is configured to remotely authenticate application traffic and to protect against brute force attacks, the authentication sessions are resolved before the BIG-IP ASM Brute Force Detection component processes traffic. As a result, the Brute Force Protection engine inspects only successfully authenticated sessions, and the BIG-IP ASM cannot detect brute force authentication attempts.

To have the BIG-IP ASM Brute Force Protection occur prior to client authentication processing, it is necessary to use two virtual servers. Depending on the resources available, this may be achieved using either of the following configurations:

  • A virtual server targeting a second virtual server on the same BIG-IP ASM device
  • A virtual server on a BIG-IP ASM device targeting a second virtual server on a second BIG-IP device

In both configurations, the BIG-IP ASM-enabled virtual server processes traffic first, and is able to block requests that meet the Brute Force Protection criteria. Connection requests that the BIG-IP ASM passes through are then sent to the second virtual server, which is configured to communicate with the authentication server. Once the remote authentication server successfully authenticates a connection, the second virtual server passes the original request to the origin web server (OWS).

Prerequisites

You must meet the following prerequisite to use this procedure:

  • A correctly-configured remote client authentication profile and server.
  • An existing BIG-IP ASM web application correctly configured with Brute Force Protection enabled in the security policy.

Procedures

A virtual server targeting a second virtual server on the same BIG-IP ASM device

The client-facing virtual server is configured with an HTTP Class profile, a BIG-IP ASM web application with Brute Force Protection enabled, and an iRule that targets requests to the second virtual server. The second virtual server is configured with a remote authentication profile and a load balancing pool containing the OWS for the web application.

An example stanza from the /config/bigip.conf file for each of the required objects for this configuration are listed below:

  • HTTP Class Profile to enable BIG-IP ASM Brute Force Protection, assigned to the client-facing virtual server:

    profile httpclass ASMClass {
    defaults from httpclass
    asm enable
    }

  • OWS configured as a member of a load balancing pool:

    pool OWS_pool {
    monitor all http
    members 10.2.2.1:http {}
    }

  • iRule assigned to the client-facing virtual server, targeting traffic to the authentication virtual server:


    rule forward_to_auth_vip_rule {
    when CLIENT_ACCEPTED {
    virtual authentication_virtual
    }
    }

  • Client-facing virtual server:

    virtual ClientFacingVirtual1 {
    destination 10.10.10.1:http
    ip protocol tcp
    rules forward_to_auth_vip_rule
    httpclass ASMClass
    profiles {
    http {}
    tcp {}
    }
    }

  • Authentication virtual server, targeting the OWS load balancing pool:

    virtual authentication_virtual {
    snat automap
    pool OWS_pool
    destination 10.10.10.2:http
    ip protocol tcp
    auth ldap
    profiles {
    http {}
    tcp {}
    }
    }

A virtual server on a BIG-IP ASM device targeting a second virtual server on a second BIG-IP device

In this configuration, the client-facing virtual server on the BIG-IP ASM device is configured with an HTTP Class Profile, a BIG-IP ASM web application with Brute Force Protection enabled, and a load balancing pool. The pool member is the virtual server address of the second BIG-IP device. The virtual server on the second BIG-IP device is configured with a remote authentication profile, and a load balancing pool containing the OWS for the web application.

An example stanza from the /config/bigip.conf file for each of the required objects on the BIG-IP ASM for this configuration is listed below:

  • HTTP Class Profile to enable BIG-IP ASM Brute Force Protection, assigned to the client-facing virtual server:

    profile httpclass ASMClass {
    defaults from httpclass
    asm enable
    }

  • Load balancing pool, with the virtual server on the second BIG-IP device configured as a pool member:

    pool BIG-IP-2-Pool {
    monitor all http
    members 10.10.10.2:http {}

  • Client-facing virtual server targeting the load balancing pool:

    virtual ClientFacingVirtual1 {
    pool BIG-IP-2-Pool
    destination 10.10.10.1:http
    ip protocol tcp
    httpclass ASMClass
    profiles {
    http {}
    tcp {}
    }
    }

An example stanza from the /config/bigip.conf file for each of the required objects on the second BIG-IP device for this configuration are listed below:

  • OWS configured as a member of a load balancing pool:

    pool OWS_pool {
    monitor all http
    members 10.2.2.1:http {}
    }

  • Authentication virtual server, targeting the OWS load balancing pool:

    virtual authentication_virtual {
    snat automap
    pool OWS_pool
    destination 10.10.10.2:http
    ip protocol tcp
    auth ldap
    profiles {
    http {}
    tcp {}
    }
    }
