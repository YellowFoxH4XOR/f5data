Description

When CSRF protection is enabled in BIG-IP ASM, requests to certain URLs may be unexpectedly blocked, even if those URLs are explicitly configured with a relaxed enforcement setting (for example, enforcement action set to None).


Environment

  • Product: BIG-IP ASM
  • CSRF Protection: Enabled
  • CSRF Protection URL list includes:
  • Specific URL entries
  • A wildcard entry (*) 

Cause

The root cause is the order of entries in the CSRF Protection URL list.


Unlike standard URL matching behavior in ASM, CSRF Protection evaluates the URL list in a strict top-down order. The first matching entry is applied, regardless of specificity.


As a result:

  • If a wildcard entry (*) appears before a specific URL,
  • The wildcard rule is matched first and enforced,
  • The specific URL configuration is never evaluated,

This leads to unexpected CSRF violations even when the specific URL is configured with relaxed enforcement.


Answer/Recommended Actions

To ensure correct behavior:

  • Review the CSRF Protection URL list order.
  • Place specific URLs above any wildcard entries (*).
  • Ensure that URLs requiring exceptions or relaxed enforcement are evaluated first.
  • Apply and save the policy changes.
  • Re-test to confirm expected behavior.

Additional Information

  • CSRF protection is typically enforced only when:
    • A session cookie is present, and
    • The request lacks proper validation signals (e.g., missing or invalid Origin/Referer headers).
  • This behavior is by design and ensures protection against cross-site request forgery attacks, but requires careful configuration of the URL list.
  • The key distinction to remember:

CSRF Protection URL matching is order-based, not specificity-based.
