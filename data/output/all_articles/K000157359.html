Description

When attempting to upgrade BIG-IP LTM Virtual Edition (VE), the installation process may fail with errors indicating insufficient disk space on the /config partition, even after increasing its size. 

The liveinstall log specifically reports that the /config partition does not have enough free space for the upgrade, despite apparent expansion.

Example from the liveinstall log:

info: Extracting manifest: /var/local/ucs/config.ucs 
info: /config: Not enough free space  
info:     3997739008 bytes required 
info:     2210521088 bytes available 
info: /var/local/ucs/config.ucs: Not enough free disk space to install! 
info: Operation aborted. 
info: >---- 
Terminal error: Not enough free disk space: 
 
*** Live install end at 2025/10/19 22:12:03: failed (return code 255) ***

Environment

  • VE License types: "large" or "tiny".
  • AS3 (Application Services 3 Extension) is actively used with frequent configuration changes.
  • Multiple partitions and numerous configuration files present due to AS3 usage and partitioning.

Cause

The /config partition size is hard-coded by the VE license type. 

  • for a "large" VE license, the maximum usable size is capped at 3.8G
  • for a "tiny" VE license (LTM Only) the maximum usable size is capped at 500Mb.

Note: This is regardless of manual resizing efforts. If expanded beyond this limit, BIG-IP ignores any additional space above the cap.

Important: A frequent cause of this are AS3 declarations. These generate .diff files and other artifacts in /config, causing it to fill up quickly and preventing successful upgrades or installations.

Recommended Actions

  • Review and delete, or move to /var/tmp, unnecessary files in.../config/.diffVersions/config for each partition.
    • Focus on subdirectories where bigip.conf files exist for each partition.
    • For the space needed refer to the liveinstall log entry.
  • The following command will show the 20 largest files. Those should be reviewed and any deemed unnecessary should be removed.find /config/ -xdev -type f -exec du {} \; | sort -rn | head -20
    • If APM is in use and there are EPSEC files present in most cases most of those can be removed. K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system
  • Do not attempt to shrink /config below its current size; reducing disk size once it has been created is not supported.
  • If the size of /config is less than the limits it can be increased to the caps. However, it is still recommended to clean out old files first and only increase the size if needed.
  • For environments using AS3 with frequent changes Appendix A: Schema Reference >> AS3 :
    • Set AS3's persist option to false during batch operations to reduce excessive .diff file creation.
    • After all declarations are complete, manually save the configuration using this REST API endpoint:

      {
        "command": "run",
        "utilCmdArgs": "-c 'tmsh save sys config'"
      }

    • This prevents saving after every declaration and reduces file buildup.
  • If issues persist after cleanup:
    • Verify that no historical or unnecessary files remain in /config.
    • Confirm that no other partitions (/var or /shared) are full.

Additional Information

  • Specifically for AS3 ID2143277 Large and frequent AS3 declaration exhausts /config/.diffVersions very quickly has been created.
  • By default (persist=true), AS3 saves configuration after every declaration—this can rapidly fill up storage if many changes occur frequently.
  • Bug ID 1045277: The /var partition may also become full under certain conditions requiring manual intervention.
