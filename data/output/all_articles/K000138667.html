Description

How to recover the root password on RAID-capable BIG-IP platforms.

Environment

  • BIG-IP 14.1.0 and later
  • BIG-IP platforms: i7xxx, i15xxx
  • Console access to BIG-IP

Cause

You should consider using this procedure under the following conditions:

  • You need to reset root account on BIG-IP v14.1.0 and later.
  • You have a RAID-capable BIG-IP platform listed.

Recommended Actions

During boot the BIG-IP pauses at the GRUB menu and counts down before continuing the boot process.

  1. Before the countdown expires, use the Up Arrow and Down Arrow to select the appropriate boot image.
  2. Press e to edit the current entry. A new GRUB menu screen displays.
  3. Use the Up Arrow and Down Arrow to select the line that appears similar to the following
module /boot/2/vmlinuz ro root=UUID=c90e3f25-57a4-4370-aac3-xxxxxxxxxxxxx console=ttyS0 panic=1 platform=C117 quiet
4. Press the keyboard E to start editing at the end of the line.5. Append the following to the end of the line. For the C117 platform, the line may appear similar to the following 
rd.break
  6. Press the Ctrl-x keyboard sequence to boot to the modified config.
  7. After the boot sequence completes, the following command-line prompt appears: 
localhost login:
   8. the login user is: root

NOTE: You have 5 minutes to complete the task before the BIG-IP reboots

    9. You will now be on the switch_root:/# prompt
    10. type the following to verify that you are on the volume you had selected to edit in the GRUB menu 
switch_root:/# mount | grep mapper

The following shows that the volume in use is 1 based on the g--db--cpmirror-set.1.X.

/dev/mapper/vg--db--cpmirror-set.1.root on /sysroot type ext3 (ro,relatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
/dev/mapper/vg--db--cpmirror-set.1._usr on /sysroot/usr type ext3 (ro,noatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
11. Mount the _config and _var volumes. The mount command may appear similar to the following example: 
switch_root:/# mount /dev/mapper/vg--db--cpmirror-set.1._config /sysroot/config
switch_root:/# mount /dev/mapper/vg--db--cpmirror-set.1._var /sysroot/var
12. Now verify that you have the new volumes are mounted 
switch_root:/# mount | grep mapper
/dev/mapper/vg--db--cpmirror-set.1.root on /sysroot type ext3 (ro,relatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
/dev/mapper/vg--db--cpmirror-set.1._usr on /sysroot/usr type ext3 (ro,noatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
/dev/mapper/vg--db--cpmirror-set.1._config on /sysroot/config type ext3 (rw,relatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
/dev/mapper/vg--db--cpmirror-set.1._var on /sysroot/var type ext3 (rw,relatime,errors=continue,user_xattr,acl,barrier=0,data=ordered)
13. Mount /sysroot/config and /sysroot/var partitions. Depending on the platform, the mount command may appear similar to the following example: 
switch_root:/# mount /dev/mapper/vg--db--cpmirror-set.1._config /sysroot/config
switch_root:/# mount /dev/mapper/vg--db--cpmirror-set.1._var /sysroot/var
14. For any partitions mounted as "ro" (read only) you must remount with read write mode enabled. To remount /sysroot and /sysroot/usr partitions to read write: 
switch_root:/# mount -o remount,rw /sysroot
switch_root:/# mount -o remount,rw /sysroot/usr
15. Change the root file system to / using chroot 
switch_root:/# chroot /sysroot

The prompt displays

sh-4.2#
16. Change root password using passwd  
sh-4.2# passwd
Changing password for user root.
New BIG-IP password:
Retype new BIG-IP password:
Changing password for user root.
passwd.bin: all authentication tokens updated successfully.
17. Force SELinux to relabel context on next boot 
sh-4.2# touch /.autorelabel
18. Type exit and then reboot to leave to the shell environments and reboot 
sh-4.2# exit
switch_root:/# reboot
