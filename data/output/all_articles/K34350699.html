Known Issue

You are unable to import a BIG-IP ASM security policy.

This issue occurs when all of the following conditions are met:

  • You create a security policy from a custom policy template and export the policy in binary format.
  • You attempt to import the policy on a device where the custom policy template does not exist.

Impact

You are unable to import the security policy into BIG-IP ASM.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Importing the security policy results in error messages in the Configuration utility. The error messages appear similar to the following example:
Unknown error after running import policy script.
Could not import the Security Policy; Error: DBD::mysql::db do failed: Cannot add or update a child row: a foreign key constraint fails.

Resolution

Status

F5 Product Development has assigned ID 507640 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can export and import the security policy in XML format instead of binary format.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
