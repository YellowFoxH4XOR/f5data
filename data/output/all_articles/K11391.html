Known Issue

This is the result of a known issue. A global server VIP may remain in Starting state after a failover. This issue may occur when a volume for the VIP is enabled, but the volume does not contain enabled shares. The show virtual service command output displays the state of the VIP similar to the following example:

Switch   ARX1
------------------------
  Global Server           Virtual IP Address      Service     State
  ------------------------------------------------------------------------
  TEST68                  10.104.252.68           CIFS        Ready
  TEST66                  10.104.252.66           CIFS        Ready
  TEST67                  10.104.252.67           CIFS        Starting

F5 Product Development tracked this issue as ID 37422 and it was fixed in ARX versions 5.1.7 and 5.2.0. For information about upgrading, refer to the ARX release notes.

Workaround

To prevent the global server VIP from remaining in Starting state after failover, you can either enable a share for the volume or disable the volume.

Note: For information about using the enable commands to enable a share or disable a volume, refer to the ARX CLI Reference Guide.
