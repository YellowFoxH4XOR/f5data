Topic

Summary

Beginning in ARX 6.0.0, a license check date in the software is verified against the service check date in the license file. When you upgrade a system, the installation script verifies the service check date with the license check date of the version being installed. If the service check date is missing or is earlier than the license check date, the upgrade does not continue.

Description

The ARX uses a static date built into the software to ensure customers have an active service contract that entitles them to receive software upgrades. When the original license is activated, a service check date is recorded. This date contains either the license activation date or the service contract date, whichever date is earlier.

The license date used for comparison is in the following table:

ARX versionLicense date
6.4.019-Mar-2013
6.3.01-Oct-2012

Service check date


The service check date is located in the license. It is the date the license was last activated or the date the service contract for the device expires, whichever date is earlier. For example, if you have an active service contract that ends on December 31, and you license a device on June 30, the service check date is set to June 30.

Note: The service check date in the license is updated each time the license is reactivated.

Recommendations

To prevent a delay during the upgrade process, F5 recommend manually verifying the date in the show active-license command output with the license dates to determine if license activation is necessary.  Additionally, licensing prior to performing the upgrade will also ensure the most accurate license data available.
