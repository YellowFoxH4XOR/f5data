Description

Starting in BIG-IP 15.1.0, the webhook provides a configurable mechanism to provide an alternative to polling for an update. A service will subscribe to notifications and when a notification is ready it will push the update back to the URL that was specified to receive the update. Common use-cases are used with services like GitHub / Slack for handling things like notifications when code is committed and sending a message to a Slack channel. For example, when ASM policy receives one illegal request, then sends a notification to the Slack channel, you have config the webhook, but you find the Slack channel unable to receive the notification, you may find the following error message in the /var/log/asm. 
crit perl[<PID>]: 01310027:2: ASM subsystem error (asmcrond,(eval)): Failed to send webhook:
crit perl[<PID>]: 01310027:2: ASM subsystem error (asmcrond,(eval)): 400 Bad Request
crit perl[<PID>]: 01310027:2: ASM subsystem error (asmcrond,(eval)): Failed to send webhook:
crit perl[<PID>]: 01310027:2: ASM subsystem error (asmcrond,(eval)): 400 Bad Request

Environment

  • Webhook
  • 400 Bad Request
  • ASM subsystem error

Cause

This is a config issue, it indicates the HTTP request is bad when sending to webhook, so you need to check the HTTP request body format on the webhook setting.

 Recommended Actions

You can refer to the following content to modify the Body format at Menu Security  ››  Application Security : Webhooks:  ››  Webhook Properties. 
Conteny-Type: application/json
Body: {"type":"message", "text":"This message was sent from ASM_policy_NAME of HOSTNAME due to illegal request"}
