K000160040: Issue with array parameters though Swaggerfile

Description

When using BIG-IP ASM and an OpenAPI (Swagger) specification file to define array parameters for file uploads, requests with multipart/form-data and parameter names using the "[]" array notation (e.g., "billingFiles[]") may be blocked. Violations include "Illegal parameter [billingFiles[]]" and "HTTP protocol compliance failed: Forbidden NULL in multipart parameter: billingFiles[]". This occurs due to a mismatch between OpenAPI/Swagger array parameter naming and ASM enforcement, where ASM expects the parameter name without brackets.

Environment

  • Product: BIG-IP ASM
  • Security Policy: Created using OpenAPI/Swagger file (OpenAPI 3.0.0)
  • Scenario: File upload endpoint defined as an array parameter in OpenAPI spec ("billingFiles" of type array, items of type string/binary)
  • Request: multipart/form-data POST with parameter name "billingFiles[]"
  • ASM Policy: Parameter imported as "billingFiles" (no brackets) from Swagger/OpenAPI

Cause

ASM enforces parameter names exactly as defined in the OpenAPI/Swagger file. When clients use the "[]" array notation, ASM does not recognize the parameter and flags it as illegal. Multipart requests with binary data may also trigger protocol compliance violations if the parameter is not configured to accept file uploads.

Recommended Actions

  • Manually add both "billingFiles" and "billingFiles[]" as allowed parameters of type File Upload in the ASM security policy.
  • Ensure both parameter names are set to accept file uploads (Data Type: File Upload) to prevent blocking of legitimate requests.
  • Review client request formats and update the ASM policy for compatibility with common HTTP clients using the "[]" array notation.
  • Consider upgrading to a newer version if additional multipart/form-data handling issues are observed.
  • Monitor release notes for future improvements in OpenAPI/Swagger array parameter handling in ASM.

Additional Information

  • This behavior is expected but may be considered for future enhancement.
  • The workaround is required for compatibility with HTTP clients that use the "[]" array notation.
