Known Issue

The BIG-IP LTM system may send an incorrect HTTP response to the client.

This issue occurs when all of the following conditions are met:

  • A BIG-IP virtual server is configured with an HTTP2 profile.
  • The origin web server (OWS) sends a response with a Transfer-Encoding: chunked header and a zero-size chunk (empty body; for example, 0\r\n\r\n).

Impact

Browsers may not be able to handle the incorrect HTTP response properly.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The page redirect does not perform on some browsers, causing an incorrect page rendering on the client.

Workaround

To work around this issue, you can force the BIG-IP LTM system to redirect the page correctly using the following example iRule:

Impact of workaround: You may need to modify the example iRule to suit your specific environment. F5 recommends that you perform this procedure during a scheduled maintenance window.

when HTTP_RESPONSE {
  if {[HTTP::header exists "Transfer-Encoding"] && [HTTP::status] eq 301} {
    HTTP::respond 301 -version 1.1 noserver Location [HTTP::header Location] Date [HTTP::header Date] Content-Type [HTTP::header Content-Type] Connection [HTTP::header Connection]
  }
}
