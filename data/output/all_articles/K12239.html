Topic

Delegation is a means by which a server is configured to pass along a client's identity and credentials to a second server, accessing a resource or service on behalf of the client.

Description

Starting in ARX 5.2.0, the ARX software supports constrained delegation, in which identity and credentials are passed along for only explicitly specified servers or services.

Note: For detailed information about configuring constrained delegation, including domain controller and user account requirements, refer to the Constrained Delegation Support section of the Configuring Front-End Services chapter in the ARX CLI Storage-Management Guide. Additionally, the Constrained Delegation Support section provides instructions about switching an existing CIFS service to constrained delegation.

Previous versions of ARX software allowed the ARX system to delegate its CIFS services to any filer, and the ARX Secure Agent software was required to support NTLM and NTLMv2 authentication. Constrained delegation allows more granular control over the delegation, so that a domain administrator can configure to which filers the ARX CIFS service may delegate. Additionally, when using constrained delegation, the ARX Secure Agent software is no longer required to support NTLM and NTLMv2 authentication.

To use constrained delegation, the following requirements must be met:

  • The functional level of the Windows domain must be set to Windows 2003 or later.
  • All of the filers associated with the CIFS service must be joined to the same Windows domain as the CIFS service itself.
  • All of the filers associated with the CIFS service must support Kerberos authentication.
  • To use NTLM or NTLMv2 authentication (not Kerberos), the CIFS service name cannot exceed 15 characters. For example, with an FQDN name of prodsystem.corp.com, the prodsystem portion cannot exceed 15 characters.

You specify the type of delegation (constrained, unconstrained, or none) when joining a CIFS service to a domain using the domain-join command. For example:

domain-join example.com delegation constrained

Note: For more information about the domain-join command, refer to the Constrained Delegation Support section of the Configuring Front-End Services chapter in the ARX CLI Storage-Management Guide.

After specifying constrained delegation using the domain-join command, obtain a list of filers associated with the CIFS service using the following command syntax:

probe delegate-to <CIFS service> user <username> domain <domainname>

Replace <CIFS service> with the name of the CIFS service as configured on the ARX system, <username> with a domain user account, and <domainname> with the Windows domain name.

probe delegate-to cifs1.example.com user jsmith domain example.com

Note: For more information about the probe delegate-to command, refer to the Constrained Delegation Support section of the Configuring Front-End Services chapter in the ARX CLI Storage-Management Guide.

On the domain controller, configure delegation on the computer account associated with the ARX system. To do so, perform the following procedure:

  1. On the domain controller, open the properties of the computer account associated with the ARX system.
  2. Select the Delegation tab.
  3. Select the Trust this computer for delegation to specified services only option.

    Note: On a Windows 2008 domain controller, this option should already be enabled if the constrained parameter was specified in the domain-join command. On a Windows 2003 domain controller, this option must be changed from Do not trust this computer for delegation.

  4. Select the Use any authentication protocol option.
  5. For each filer listed in the output of the probe delegate-to command, click Add and add a service with the following parameters:

    User or Computer: <filer>
    Service Type: cifs

    Replace <filer> with the object name of the filer as configured in Active Directory.

Note: The domain administrator will need to repeat the previous procedure each time a new filer is added to the domain, if the filer will be accessed through the ARX system.

Recommendations

It is important that all filers in the managed volume are added to the delegation list on the KDC. If the clients fail to authenticate correctly after the configuration is complete, ARX syslog may contain error messages that appear similar to the following examples:

  • STATUS_LOGON_FAILURE
  • Failed to obtain authentication credentials for host
    'cifs1@EXAMPLE.COM' on behalf of principal
    'principle@CORP.EXAMPLE.COM' at IP address 10.10.10.10 to CIFS service
    'filershare.example.com'. The Kerberos error message is 'KDC can't
    fulfill requested option' (KRB5KDC_ERR_BADOPTION, -1765328371).

These error messages are typically due to the filer not being in the KDCs delegation list. F5 recommends that you verify the filer is in the delegation list and complete the steps outlined above again. Once completed, confirm that delegation has been configured correctly for each filer with the probe delegate-to command.
