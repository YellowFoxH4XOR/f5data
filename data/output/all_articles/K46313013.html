Description
In some configurations it will require that you utilize Kerberos SSO when using SAML Authentication 

Environment

  • BIG-IP APM
  • BIG-IP as SAML SP
  • Kerberos SSO Configured and working
  • Kerberos SSO object applied to APM policy

Cause
For Kerberos SSO to work correctly, the username and domain must be pulled from the SAML data and reassigned for Kerberos SSO to function 

Recommended Actions

Create iRule to assign variables.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create to create a new iRule.
  6. In the Name field, enter a name for the iRule.
For Example:
saml_kerberos_sso
  1. In the Definition field, enter the iRule with the proper values.
    Note: Check your session variable attributes and ensure they are populated to reassign them.
when ACCESS_POLICY_COMPLETED {
                ACCESS::session data set session.sso.token.last.username "[ACCESS::session data get "session.saml.last.attr.name.username"]"
                ACCESS::session data set session.ad.last.actualdomain "[ACCESS::session data get "session.saml.last.attr.name.actualdomain"]"
}    
  1. Click the Finished button to save the iRule.
  2. Under Local Traffic, click Virtual Servers.
  3. Click the name of the virtual server to which the access policy will be applied.
  4. Select the Resources tab.
  5. Next to iRules, click Manage.
  6. In the Available box, highlight the name of the iRule you just created.
  7. Click the << button.

    The iRule moves to the Enabled box.

  8. Click Finished.
