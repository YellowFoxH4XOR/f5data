K96658370: BIG-IP doesn't reply to ARP requests for overlay VXLAN IP address

Type
Support Solution
Published
2021-07-21
Updated

Applies to

Source

Description
BIG-IP doesn't respond to ARP for overlay Self-IP configured on VXLAN tunnel.

You may encounter this while setting up F5 Container Ingress Services with OpenShift or Kubernetes in a ClusterIP Deployment.

Environment

  • VXLAN configured with flooding-type multipoint
    • this is the recommended configuration for ClusterIP Deployments using F5 CIS
  • No virtual tunnel endpoints (VTEPs) are defined for the VXLAN tunnel
    • on BIG-IP these are defined under net fdb tunnel
    • when F5 CIS is used in a ClusterIP deployment, it manages VTEPs for container nodes automatically
  • If using F5 CIS:
    • CIS has not yet been started on the container orchestration system, or
    • CIS is not configured for ClusterIP mode

Cause
In multipoint mode, BIG-IP only transmits VXLAN frames to known VTEPs, which must be statically configured. If there are no VTEPs defined, BIG-IP cannot transmit an ARP reply.

F5 CIS interrogates the container orchestration network and automatically manages VETPs on the BIG-IP system to ensure cluster member nodes are reachable.

Recommended Actions

If using F5 CIS:
  1. Ensure CIS is configured correctly for your environment
  2. Ensure CIS is started and functioning
If not using F5 CIS:
  1. Configure VTEPs as required
