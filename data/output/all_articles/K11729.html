Known Issue

This is the result of a known issue. Reactivating the BIG-IP license fails when the /shared partition is at 100 percent capacity. This issue occurs because the BIG-IP system attempts to temporarily write the license file to the /shared/tmp directory before copying it to the /config/bigip.license active license location. When the /shared partition is full, the system repeatedly attempts and fails to write the license to the /shared/tmp directory, often resulting in multiple empty bigip.license files being written to the /shared/tmp directory.

When this issue occurs, you will most likely experience the following symptoms:

  • Attempts to reactivate the license fail
  • The configuration reports the following message when attempting to reactivate the license:

    The license for this device is not operational
  • Extraneous bigip.license files are generated to the /shared/tmp directory.

    For example:

    # ls -las /shared/tmp
    4 -rw-r--r-- 1 tomcat tomcat 0 Jun 21 17:31 bigip.license.0
    4 -rw-r--r-- 1 tomcat tomcat 0 Jun 21 17:31 bigip.license.1
    4 -rw-r--r-- 1 tomcat tomcat 0 Jun 21 17:31 bigip.license.10
    4 -rw-r--r-- 1 tomcat tomcat 0 Jun 21 17:31 bigip.license.11
  • The system logs one or more of the following licensing error messages to the /var/log/ltm file:

    err mcpd[4292]: 01070171:3: License file read fails: Unknown error 4126537205.

    emerg mcpd[4292]: 01070608:0: License is not operational (expired or digital signature does not match contents).
  • The system logs error messages related to no disk space in the /shared partition that appear similar to the following examples:

    err diskmonitor: 011d0004: Disk partition shared has only 0% free

    warning diskmonitor: 011d0006: Disk partition shared exceeded growth limit 5%
  • The df command indicates that the /shared partition is at 100 percent capacity.

    For example,

    # df -h /shared
    Filesystem Size Used Avail Use% Mounted on
    /dev/mapper/vg--db--hdc-dat.share.1 3.7G 3.7G 0.0G 100% /shared

F5 Product Development is tracking this issue as ID 291614 (formerly CR124786).

Workaround

You can work around this issue by clearing disk space in the /shared partition before attempting to reactivate the system license.

Note: The BIG-IP system will not generally utilize 100 percent of the /shared partition. However, the system uses the partition to store core files, qkview files, and serves as the repository for software and hotfix images. In addition, BIG-IP administrators working from the BIG-IP command line are encouraged to use the /var/tmp directory, which is a symlink to the /shared/tmp directory, as temporary storage for scripts.

Before attempting to clear disk space, you should investigate the /shared partition for any extraneous large files stored or written to the partition. For example, the following find command displays the 20 largest files contained in the /shared partition.
