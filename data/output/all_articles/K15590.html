Known Issue

The BIG-IP system may erroneously retransmit diameter requests that have been dropped by the DIAMETER::drop iRule command. This issue occurs when all of the following conditions are met:

  • Your system uses a diameter virtual server that has an associated iRule that contains the DIAMETER::drop iRule command in the DIAMETER_INGRESS iRule event.
  • The diameter virtual server is associated with a diameter profile that has the following options set to a value greater than 0 (zero):
    • Maximum Retransmit Attempts (default value is 1)
    • Retransmit Timeout (default value is 10)

Impact

Retransmitted diameter messages may disrupt the diameter connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H478806 on the Diagnostics > Identified > High screen.
  • Diameter connections fail on the BIG-IP system.
  • A tcpdump capture of the affected traffic shows the BIG-IP system retransmitting the dropped diameter request messages to the server.

Workaround

To work around this issue, you can disable diameter retransmission for the affected diameter virtual server by configuring the Maximum Retransmit Attempts setting and the Retransmit Timeout setting in the associated diameter profile to 0. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Diameter.
  3. Click the name of the diameter profile associated with the affected diameter virtual server.
  4. Select the Maximum Retransmit Attempts check box if it is not already selected, and set the value to 0.
  5. Select the Retransmit Timeout check box if it is not already selected, and set the value to 0.
  6. To save the changes, click Update.
  7. If the system is a member of a device group, ensure that the configuration is synchronized between the members by performing the appropriate procedure described in K13920: Performing a ConfigSync using the Configuration utility.
