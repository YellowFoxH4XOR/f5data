Known Issue

The ntlmconnpool process may fail and restart.

This issue occurs when the following conditions are met:

  • Your virtual server references an NTLM profile
  • The client attempts to authenticate using a null user name and password

Impact

You may be unable to authenticate against the NTLM server while the ntlmconncpool process restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H379797 on the Diagnostics > Identified > Low screen.
  • An error message is logged in the /var/log/daemon.log file. The message appears similar to the following example:

    emerg logger: Re-starting ntlmconnpool
  • The /shared/core file may contain ntlmconnpool core files.

Workaround

To work around this issue, you can disable the OneConnect and NTLM Conn Pool profiles on the affected virtual server. To do so, perform the following procedure:

Impact of workaround:  NTLM connections will no longer be optimized.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the virtual server you would like to modify.
  5. Set the OneConnect Profile option to None.

    Note:  Disabling the OneConnect profile will also disable the NTLM Conn Pool profile.
  6. Click Update.
