Description

Are service policies/routes/waf exclusion rule case sensitive? - Yes, by default they are case sensitive.

Exception are HTTP headers, as per RFC: "Each header field consists of a name followed by a colon (":") and the field value. Field names are case-insensitive."

All routes like "/EXAMPLE", "/exaMple", "/EXample" etc. will not match.

Same in case of service policy parameters.

Recommended Actions

If you want to have case insensitive parameters/routes, you can use one of the below solutions.

Use transformers where possible

Transformers is a utility that will modify customer input before we compare it with policy values.

Note: Transformers menu is not available for all options. Some parts don't have it. If they are missing, you can use regex.

 

Use regex

You can use regex if transformers are not available.
If you want to remove case sensitivity from e.g. route, you can use "(?i)" regex flag. 
"(?i)" is case-insensitive flag and makes the rest of the regex ignore letter casing.
 

Regex like "(?i)^/uat.*" will match "/UAT", "/uAt" etc.

Additional Information

Signature exceptions

When you do signature exception, filed "Context name" don't support regex and is always case sensitive. 

The only option that You can use is wildcard ( * ) to add prefix or suffix wildcard matching. 
All other regex symbols will be interpreted just as normal signs without any special functions.
