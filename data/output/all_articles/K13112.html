Topic

This article applies to BIG-IP 11.0.0 through 11.3.0. For information about other versions, refer to the following article:

  • K16565: Configuring a Web Acceleration profile for use with a BIG-IP ASM-enabled virtual server (11.4.0 and later)

You should consider using this procedure under the following condition:

  • You want to increase the processing speed of a BIG-IP ASM web application by caching static content.

Description

The Web Acceleration profile can be applied to a BIG-IP ASM-enabled virtual server to cache commonly requested static content that conforms to the BIG-IP ASM security policy, such as images. Using HTTP Classes to define the traffic profiles to be cached allows for faster processing, lower overhead, and more efficient use of the cache.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have the BIG-IP ASM module licensed and provisioned.
  • Your existing configuration must have a functioning virtual server and pool combination that serves HTTP traffic to client connections.

Procedures

  • Configuring a custom Web Acceleration profile
  • Configuring a custom HTTP Class to handle static content that should be cached
  • Configuring a custom HTTP Class to handle all other traffic that should not be cached
  • Configuring an iRule to disable caching if the non-static content HTTP Class is selected
  • Associating the custom HTTP Class profiles, the Web Acceleration profile, and the iRule with the virtual server

Important: If you have already created a BIG-IP ASM policy for use, ensure it is in blocking mode before configuring the HTTP class options and the iRule. This will prevent direct and non-secure access to the web servers.

Configuring the custom Web Acceleration profile

F5 recommends that you create a new child profile based on the Web Acceleration profile, rather than modifying any settings in the default profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Services.
  5. Select Web Acceleration.
  6. Click Create.
  7. Provide a name for the custom Web Acceleration profile.

    For example:

    asm_acceleration_profile

  8. Select the Custom check box in the Settings section if you want to use all of the options available.

    Note: This section is optional, it is not required. You should configure your cache settings in the most appropriate way for your environment.

  9. Change the Minimum Object Size option from the default of 500 bytes to 1 byte.
  10. Change the Maximum Object Size option from the default of 50000 bytes to 150000 bytes.
  11. Click Finished.

Configuring a custom HTTP Class to handle static content that should be cached

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Select Application Security.
  3. Click Classes.
  4. Click Create.
  5. Provide a name for the custom HTTP Class.

    For example:

    static_content

  6. Select the Custom check box.
  7. Select the URI Paths option.
  8. Select Match Only in the drop-down menu.
  9. Enter the following regular expression for the URI Path:

    (?i)^/[a-zA-Z0-9_/]+\.(gif|jpg|bmp|png|css)$

  10. For the Entry Type, select Regular Expression (regex).
  11. Select Add.
  12. For the Actions option, select Custom.
  13. For the Send To option, select Pool.
  14. For the Pool option, select the name of your pool that references your servers.
  15. Click Finished.

Configuring a custom HTTP Class to handle all other traffic that should not be cached

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Select Application Security.
  3. Click Classes.
  4. Click Create.
  5. Provide a name for the custom HTTP Class.

    For example:

    all_content

  6. For the Actions option, select Custom.
  7. For the Send To option, select Pool.
  8. For the Pool option, select the name of your pool that references your servers.
  9. Click Finished.

Configuring an iRule to disable caching if the non-static content HTTP Class is selected

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select iRules.
  4. Select Create.
  5. Provide a name for the iRule.

    For example:

    irule_httpclass_cache

  6. Enter the iRule, using the following syntax:

    when HTTP_CLASS_SELECTED {

    if { not ([HTTP::class] eq "<name of static content HTTP Class>") } {
    CACHE::disable
    }
    }

    For example:

    when HTTP_CLASS_SELECTED {

    if { not ([HTTP::class] eq "static_content") } {
    CACHE::disable
    }
    }

  7. After entering the iRule, click Finished.

Note: In the iRule example, when an HTTP Class selected by the system is not the static_content HTTP Class, the cache is disabled and the request is sent to the BIG-IP ASM policy to be evaluated. Alternatively, if the HTTP Class is the static_content HTTP Class, the request is sent to the BIG-IP ASM policy to be evaluated, but the response is allowed to be cached if it is static content matching the regular expression string.

Associating the custom HTTP Class profiles, the Web Acceleration profile, and the iRule with the virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Associating the HTTP Class profiles with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select the virtual server that you want to associate with the HTTP Class.
  5. Select the Resources tab.
  6. In the HTTP Class Profiles section, click the Manage button.

    The Resource Management screen opens.
  7. In the Available section, select the HTTP class profile created for static content.
  8. Click <<.

    The HTTP class profile created for static content is moved to the Enabled section.
  9. In the Available section, select the HTTP class profile created for all other content.
  10. Click <<.

    The HTTP class profile created for all other content is moved to the Enabled section.
  11. Use the Up and Down buttons below the Enabled list to ensure that the HTTP class profile for static content is listed first.

    Note: The system applies the HTTP classes in the order they are listed.

    For example: static_content
    all_content

  12. Click Finished.

    You return to the Resources section.
  13. Click Update.

    The changes in the Resources section are now associated and saved with the virtual server.

Once you have configured all of the previously-mentioned requirements, run traffic to the site and build an ASM security policy for the static content web application. F5 recommends that you use a policy configured with the following elements:

  • File types

    Wildcard ( * ) without tightening. Using a wildcard makes the entry case insensitive and you do not have to specify both gif and GIF, and the tightening is not required since the file type filtering is done at the HTTP class level.
  • URLs

    Wildcard ( * ) without tightening. Using a wildcard makes the entry case insensitive and you do not have to specify every new image in the site--a task that requires configuration and could cause errors for users. As with file types, the filtering is done at the HTTP class level.
  • Enable blocking for ASM violations

Before enabling the Web Acceleration profile, ensure that the ASM policy is blocking on the following violations:

  • Cookie not RFC-compliant
  • Evasion technique detected
  • Illegal HTTP format
  • Non-RFC request
  • Illegal HTTP status in response
  • Illegal meta character in object
  • Illegal method
  • Illegal object type
  • Non-existent object Error
  • Request length exceeds defined buffer size
  • Illegal cookie length
  • Illegal header length
  • Illegal object length
  • Illegal request length
  • Failed to convert character
  • Forbidden Null in request
  • Illegal meta character in header
  • Illegal query string or POST data
  • Null in multi-part parameter value
  • Modified ASM cookie
  • Modified domain cookie(s)
  • Information leakage detected Error
  • Attack signature detected

Once you have built the policy for the site and enabled blocking for the policy, you can enable the Web Acceleration profile and add the iRule to the virtual server to allow the system to cache static content.

Associating the custom Web Acceleration profile with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select the virtual server that you want to configure.

    The Properties screen for the virtual server opens.
  5. For the Web Acceleration Profile setting, select the custom Web Acceleration profile created in the Configuring a custom Web Acceleration profile procedure above.

    For example:

    asm_acceleration_profile

  6. Click Update.

Associating the iRule with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select the virtual server that you want to associate with the iRule
  5. Select the Resources tab.
  6. In the iRules section, click the Manage button.

    The Resource Management screen opens.
  7. In the Available section, select the iRule created for static content.
  8. Click <<.

    The iRule created for static content is moved to the Enabled section.
  9. Click Finished.

Once you have completed these steps, any static media content that has been validated and cleared by BIG-IP ASM can now use the Web Acceleration cache. This behavior allows content that has been checked by the BIG-IP ASM to be served from the cache and allows the BIG-IP ASM to focus on checking and validating dynamic content.
