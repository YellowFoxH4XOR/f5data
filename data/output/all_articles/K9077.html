Topic

BIG-IP traffic flow is modeled differently than what is observed on typical Layer 2 (L2) or Layer 3 (L3) devices. Understanding BIG-IP traffic flow is important to ensure accuracy when creating and viewing throughput graphs.

Traffic flow in most L2 or L3 network devices is defined as In and Out with respect to the interface or Virtual Local Area Network (VLAN) configured on the interface. With each interface/VLAN completely independent of each other, traffic that is considered inbound on one interface/VLAN can be considered outbound to another interface/VLAN to which the traffic is sent.

In the context of a client/server model, you can see in respect to the L2 or L3 device how client-side initiated traffic is seen as In on the client facing side of the device and as Out on the server facing side of the device.

Figure 1 Client/server model

Traffic flow with respect to the BIG-IP system is viewed from a client-oriented model; the traffic flow from a client is seen as In to a virtual server and In to a server. Likewise, the response from the server is seen as Out from the server and Out from the virtual server.

This orientation is due to the BIG-IP system design. The virtual server is always presented as a client side access, regardless of whether the virtual server is being used by servers to access gateways. The virtual server is seen as providing a service to the client and thus traffic flow is defined from the point of view of the virtual server for which the connection was initiated.

Note: This behavior holds true for network and forwarding virtual servers regardless of whether they are listening on multiple VLANs, or for virtual servers configured for VIP Bounce Back/One Arm Configuration for which a virtual server resides on the same VLAN/subnet as the server to which it is load balancing.

Figure 2 Client-oriented model

When viewing the detailed throughput graphs for client-side throughput and server-side throughput, you can see the client bits out can match closely with the server bits out. For more information about client-side and server-side throughputs, refer to the K50309321: Viewing BIG-IP system throughput statistics.

Options that affect the throughput information

The following options affect the throughput information:

Note: The client and server side input/output information can also be affected by different maximum transmission unit (MTU) sizes within a network, or a lossy network that may result in retransmissions of the data.

HTTP cache

When configured, the HTTP cache provides the ability to serve common items directly from cache to reduce the number of requests needed to the server for information. If items within a client request can be served by the HTTP cache, the client bits out can be greater than the server bits out since the BIG-IP system is able to provide the information without contacting the server for the information.

iRules

iRules have the ability to alter information within a packet by adding or removing information, load balancing based on information contained within a packet, redirecting a request or dropping the request entirely. Depending on the iRule, traffic can appear different between the client and the server side.

Compression

When configured, compression will attempt to compress the response sent by the server before sending the information to the client. By compressing the data, less network resources are used to transmit the information, for which client side bits out will be smaller than the server side bits out.

Note: The opposite behavior can occur if compression is set too aggressively causing more resources to be used and larger files transmitted.

OneConnect

OneConnect attempts to open and maintain multiple connections to the back end servers. When viewed on the throughput graph when configured the initial behavior might be observed as additional server side in and out bits increasing when the connections are being opened. Once opened, subsequent requests for both client and server input/output might not match, as the server side of the connection might already be opened and waiting for use.
