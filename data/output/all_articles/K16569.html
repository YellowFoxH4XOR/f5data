Known Issue

A race condition in the high-speed logging (HSL) mechanism may cause the Traffic Management Microkernel (TMM) to produce a core file.

This issue occurs when all of the following conditions are met:

  • You have enabled logging for BIG-IP AFM, or another module, with a log destination set to a remote server.
  • The transport protocol for the remote logging server is TCP.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • In the /var/log/ltm file, you may observe messages that appear similar to the following example:

    notice sod[8810]: 01140045:5: HA reports tmm NOT ready.

  • In the /var/log/tmm* file, you may observe messages that appear similar to the following example:

    notice ** SIGSEGV **

  • In the /var/log/messages file, you may observe messages that appear similar to the following example:

    notice logger: Started writing core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
    notice logger: Finished writing 236194271 bytes for core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897

  • The BIG-IP system generates TMM core files to the /var/core directory, with a time stamp that correlates to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Apr 13 15:09 tmm.0.bld2384.0.core.gz

Workaround

To work around this issue, you can use UDP instead of TCP as the transport protocol for the remote logging destination servers.

Impact of workaround: The suggested workaround may also require configuration changes to your logging servers. Make sure that any modifications are compatible with your environment.
