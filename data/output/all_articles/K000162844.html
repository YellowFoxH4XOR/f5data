K000162844: Updating a TLS Certificate Used by an HTTP Load Balancer When Domains Are Removed

Type
Support Solution
Published
2026-08-07
Updated
2026-08-07
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud WAF
Source
https://my.f5.com/manage/s/article/K000162844

Description

Updating an in-use TLS Certificate object with a replacement certificate that omits existing SAN domains fails with the following error:

The following domains are not present on the updated TLS Certificate: Web_1.example.com, Web_2.example.com.

To update a TLS Certificate object that is being used by another object, the new certificate must contain at least each domain present on the old certificate.

Environment

  • F5 Distributed Cloud
  • HTTP Load Balancer
  • Custom TLS Certificate object attached to the HTTP Load Balancer
  • Existing certificate contains multiple FQDNs or SAN entries
  • Replacement certificate contains fewer or different domains
  • TLS Certificate object is referenced by the HTTP Load Balancer

Cause

This is expected validation behavior. When a TLS Certificate object is referenced by another object, such as an HTTP Load Balancer, a replacement certificate must retain every domain present in the existing certificate.

The validation compares the replacement certificate with the domains stored in the existing TLS Certificate object, even when those domains are no longer configured as active HTTP Load Balancer domains.

Recommended Actions

To replace the certificate with one containing fewer or different domains:

  1. Create a new TLS Certificate object.
  2. Upload the replacement certificate and corresponding private key to the new object.
  3. Confirm that the replacement certificate contains the intended domain and SAN entries.
  4. Update the HTTP Load Balancer to use the new TLS Certificate object.
  5. Verify that the HTTP Load Balancer uses the replacement certificate.

Additional Information

  • A replacement certificate containing all domains from the existing certificate can be used to update the in-use TLS Certificate object.
  • Removing SAN entries requires creating a new TLS Certificate object and switching the HTTP Load Balancer to that object.
  • The validation cannot be bypassed when updating an in-use TLS Certificate object with a certificate containing fewer domains.
