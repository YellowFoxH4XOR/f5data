Known Issue

This is the result of a known issue. When the BIG-IP ASM system blocks an HTTP request due to illegal POST data, and the same HTTP request also contains the Expect: 100-continue header, the user receives the blocking response page. However, the request is still sent to the web server. The expected behavior is for the BIG-IP ASM system to send the blocking response page to the user and drop the illegal request.

Important: The HTTP request described in this Solution is unusual because a client that does not want to wait for an HTTP 100 (continue) response before sending the POST data should not set the Expect: 100-continue header. However, an attacker intentionally sends this type of request to exploit the issue and send arbitrary data to the web servers hosted behind the BIG-IP ASM system. For more information about the use of the HTTP 100 (continue) status, refer to section 8.2.3 of RFC 2616.

Important: It is difficult to notice this issue has occurred because the BIG-IP ASM system reports the illegal request was blocked, therefore arising no suspicions. However, when inspecting the blocked requests, you may notice a response code other than N/A, for example, 200 (OK). This behavior is an indication that the blocked request reached the web server.

F5 Product Development tracked this issue as CR121610 and it was fixed in BIG-IP ASM 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.1-342.0-HF1 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing 10.x hotfixes, refer to K10025: Managing BIG-IP product hotfixes for 10.x.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

If upgrading is not an immediate option, you can work around this issue by configuring an iRule that removes the Expect header from HTTP requests that include POST data. To do so, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Enter a name for the new iRule.

    For example:

    SOL10791-workaround
  5. Enter the following iRule in the Definition box:

    when HTTP_REQUEST {
    if {[HTTP::header exists Expect]} {
    if {not ([HTTP::payload length] eq "0")} {
    log -noname local0. "SOL10791: HTTP payload is not 0, removing Expect header."
    HTTP::header remove Expect
    }
    }
    }
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Select the affected virtual server.
  9. Click the Resources tab.
  10. Click the Manage button next to iRules.
  11. Move the iRule you have just created from Available to Enabled.
  12. Click Finished.
  13. Repeat steps 7 through 12 for all affected virtual servers.
