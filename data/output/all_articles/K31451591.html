Description

Following message appears repeatedly in /var/log/messages:
notice logrotate[XXXX]: ALERT exited abnormally with [1]

Message similar to the following appears in /var/log/ts/cron.log:
asm|INFO|Jan 01 01:01:01.111|XXXXX|,,error: skipping "/ts/log/xui.log" because parent directory has insecure permissions (It's world writable or writable by group which is not "root") Set "su" directive in config file to tell logrotate which user/group should be used for rotation

Environment

  • BIG-IP running v14.1.X or later, now including the logrotate v3.8.0 package
  • The volume configuration, including the systemwide /var partition must have been created with a version 11.4.x or earlier
  • The ASM product is NOT provisioned during the upgrade procedure.
     
Cause
  • A known issue tracked as ID429221 caused the initial/factory installation of the volumes for the /var/log filesystem created under 11.4.x with open permissions
  • When ASM is provisioned, during upgrade, these permissions will be automatically corrected.  When ASM is not provisioned on reboot, the new logrotate software trigger errors showing these permissions
  • Changes to logrotate introduced in https://github.com/logrotate/logrotate/blob/r3-8-0/CHANGES

Permissions of the 'other' group being set to 'write'.
As per following:
- added "su" option to define user/group for rotation. Logrotate now
      skips directories which are world writable or writable by group
      which is not "root" unless "su" directive is used.

 

Recommended Actions

Determine which processes are causing the error to occur, then change the permissions of their log files to the correct settings:

  1. Create script /var/tmp/K31451591_script with the following syntax:

    #!/bin/sh

    for i in adm asm avr cbr datasync dosl7 dwbld iprepd wr_urldbd fpuserd autodosd botd cbr ; do
    case $i in
            asm)
                    log_conf="/etc/ts/common/asm_logrotate.conf"
                    ;;
            datasync)
                    log_conf="/etc/datasync/datasyncd_logrotate.conf"
                    ;;
            dosl7)
                    log_conf="/etc/dosl7/dosl7d_logrotate.conf"
                    ;;
            *)
            log_conf="/etc/${i}/${i}_logrotate.conf"
                    ;;
    esac
    echo "Logrotate $i"
    /usr/sbin/logrotate $log_conf
    EXITVALUE=$?
    if [ $EXITVALUE != 0 ]; then
            echo "ALERT $i exited abnormally with [$EXITVALUE]"
    fi
    done

  3. Examine the script output for the process(es) with the permissions issue.  For example, any processes with the following message have log files with incorrect permissions:

    ALERT <process> exited abnormally with [1]

  4. Determine Read/Write permissions for the log file(s) of to the process(es) identified

    ls -lR --lcontext /var/log | grep -w '<process>$'

    Example of incorrect permissions:

    User  == 7
    Group == 5
    Other == 2

  5. Set correct permissions for parent directory

    chmod 755 /var/log/ts

  6. Verify using logrotate command:

    /usr/sbin/logrotate
    /usr/sbin/logrotate -s /var/lib/logrotate-asm.status /etc/ts/common/asm_logrotate.conf


Additional Information

/ts/log is really a link to /var/log/ts

# ls -ld /ts/log
lrwxrwxrwx. 1 root root 11 Aug 29  2019 /ts/log -> /var/log/ts

Note: You may use the suggested in the article before upgrading the unit.
The files under /var/log are shared between installations, and any change will persist for all slots and future upgrade
