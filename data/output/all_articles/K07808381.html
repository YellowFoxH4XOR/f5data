Topic

February 1, 2019 marked DNS Flag Day, when major open source DNS vendors updated their deployed code for processing DNS to meet expected RFC standards pertaining to EDNS (extension mechanisms for DNS). This industry driven code update corrects inefficiencies in DNS processing from non-RFC compliant EDNS feature workarounds. These same workarounds inhibit the ability to add new features to DNS. 

For more information about February 1, 2019, refer to the DNS Flag Day site.

Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Impact

EDNS RFC non-compliance may result in timeouts in response to EDNS queries, malformed responses, or the EDNS OPT section may be missing in responses to EDNS queries. These behaviors can cause slow performance or cause dropped responses. Therefore, if your domain is hosted on a non-compliant authoritative server, users may be unable to access your site.

Recommendations

The Internet Software Consortium (ISC) recommends testing DNS servers for EDNS compliance using the EDNS Compliance Tester online testing tool. To access the online tool, refer to EDNS Compliance Tester. Alternatively, you can obtain the genreport command line EDNS compliance testing tool for Linux from the ISC. To download the ISC command line tool, refer to DNS-Compliance-Testing.

When testing fixed versions of BIG-IP DNS (formerly known as BIG-IP GTM), you should note the following observations pertaining to the genreport tool results. When testing BIG-IP implementations that are configured to cache DNS resolutions, you can expect the following test results, which may appear to be test failures. The nosoa and noaa responses are expected when running the validation tool against a DNS resolver configured to cache. The validation tool assumes the DNS server is an authoritative server and makes non-recursive queries.

Test results summary

Expected test results

When testing BIND and DNS Express, there should be no compliance issues or false positives.

Implementations configured with a resolver cache with root hints nosoa results are expected because the genreport tool makes non-recursive queries. Additionally, since the DNS cache does not answer queries authoritatively, noaa results are also expected. Testing a wide IP will produce nosoa in the test results. A Start of Authority record (SOA) is not owned by the wide IP record itself, but may be owned by the second level domain on the local BIND.

Additional known issues

  • The RD bit set in the test results for EDNS does not impact DNS Flag Day compliance. However, this anomaly was noted during compliance testing. This issue is tracked by ID 752216-6. For more information, refer to K33587043: DNS queries without the RD bit set may receive responses with the RD bit set.
  • Receiving timeout and noopt results while testing an FPGA hardware-accelerated cache are not expected. For more information, refer to K25351434: The DNS FPGA hardware-accelerated cache may drop DNS queries that contain EDNS OPT records.
  • In BIG-IP 12.1.4 and 14.1.0.1, DNS Express enters a restart loop when receiving an IXFR update (incremental zone transfer) containing only an SOA record. For more information, refer to Bug ID 756094. BIG-IP 13.x and 14.0 are not affected.
  • In certain EDNS RFC-compliant versions, aborted DNS queries to a cache may cause TMM to generate a core file and restart. For more information, refer to Bug ID 756774.
