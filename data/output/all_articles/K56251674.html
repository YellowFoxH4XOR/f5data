Known Issue

BIG-IP ISO image installation fails when iRulesLX is provisioned. When iRulesLX is provisioned, the /usr mount points are mounted in read-write mode. This causes the installation of a BIG-IP ISO image to fail.

This issue occurs when all of the following conditions are met:

  • The /usr mount points are mounted in read-write mode. 
  • You install a BIG-IP ISO image as you attempt to perform an update or upgrade of the BIG-IP system.

Impact

The BIG-IP ISO image installation fails, and you are unable to update or upgrade the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe a message similar to the following in the /var/log/liveinstall.log file:

    Terminal error: main::need_service_shutdown -- Unable to get hosting system product info.

  • You observe a message similar to the following when you enter tmsh show sys software on the bash command line:

    --------------------------------------------------------------------------------------------------
    Sys::Software Status
    Volume  Product   Version   Build       Active           Status
    --------------------------------------------------------------------------------------------------

    HD1.1   BIG-IP    15.1.0.3  0.0.12      no               complete

    HD1.2   BIG-IP    15.1.2.1  0.0.10      no               failed (Could not access configuration source; sda, 2 )

Workaround

To work around this issue, you can the remount the /usr file system in read-only mode. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Remount the /usr file system in read-only mode, by entering the following command:

    mount -o remount,ro /usr

  3. Verify that /usr is mounted in read-only mode by entering the following command:

    mount |  grep _usr

    You should observe output similar to the following, displaying ro for the file systems:

    /dev/mapper/vg--db--sda-set.1._usr on /usr type ext4 (ro,noatime,seclabel,discard,data=ordered)
    /dev/mapper/vg--db--sda-set.1._usr on /opt/.sdm/usr type ext4 (ro,noatime,seclabel,discard,data=ordered)
    /dev/mapper/vg--db--sda-set.1._usr on /opt/.sdm/lib type ext4 (ro,noatime,seclabel,discard,data=ordered)
    /dev/mapper/vg--db--sda-set.1._usr on /opt/.sdm/lib64 type ext4 (ro,noatime,seclabel,discard,data=ordered)
