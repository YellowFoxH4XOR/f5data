Description

Client applications connecting to a standard virtual server with a Client SSL profile attached abort frequently during large downloads. A client-side packet capture shows the client's TCP receive window decreasing steadily prior to the abort until the window is closed and the download stalls. The issue does not occur if the Client SSL profile is removed or if the virtual server type is changed to Fast L4.

Environment

  • BIG-IP LTM
  • Standard Virtual Server
  • Client SSL Profile

Cause

This issue may occur if the TLS record size used in the Client SSL profile is set to a value that is too large for the client. The receiving client's TCP buffer needs to accommodate all TCP segments comprising a single TLS record before it can start decrypting the record and passing its data up to the application for consumption. Larger TLS record sizes require more client-side buffering before the application can start draining the incoming traffic and may therefore cause the TCP receive window to close before all segments are received.

Recommended Actions

The Client SSL profile uses a 16KiB TLS Record size by default. If this is too large for the client application then you can reduce the maximum record size setting in the Client SSL profile.
