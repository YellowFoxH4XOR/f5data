K11135: A FastL4 virtual server or SNAT configured to perform connection mirroring does not honor the TCP Handshake Timeout setting

Known Issue

This is the result of a known issue. A FastL4 virtual server or SNAT configured to perform connection mirroring does not honor the TCP Handshake Timeout setting.

For example (virtual server):

  • A virtual server uses the FastL4 profile.
  • By default, the FastL4 profile has a TCP handshake timeout of 5 seconds.

    Note: The TCP handshake timeout can be customized on a per-profile basis by adjusting the value of the TCP Handshake Timeout setting.
  • The virtual server is also configured to perform connection mirroring.
  • If a client initiates but fails to complete a TCP handshake with the virtual server (for example, if nothing is transmitted other than the initial SYN packet), then the embryonic connection will remain in the BIG-IP system connection table until the idle timeout expires. The expected behavior is for the embryonic connection to remain in the BIG-IP system connection table until the TCP handshake timeout expires.

    Note: By default, the FastL4 profile has an idle timeout of 300 seconds. This timeout can be customized on a per-profile basis by adjusting the value of the Idle Timeout setting.

    Note: When a virtual server is affected, this issue would be a cause for concern if the FastL4 profile is configured with a long idle timeout and/or a large number of TCP connections fail to complete the handshake. If required, adjust the FastL4 profile Idle Timeout setting.

For example (SNAT):

  • By default, a SNAT has a TCP handshake timeout of 5 seconds (this cannot be modified) and a TCP idle timeout of Indefinite.
  • The SNAT is also configured to perform connection mirroring.
  • If a client initiates but fails to complete a TCP handshake through the SNAT (for example, if nothing is transmitted other than the initial SYN packet), the embryonic connection will remain in the BIG-IP system connection table until the idle timeout expires (never by default). The expected behavior is for the embryonic connection to remain in the BIG-IP system connection table until the TCP handshake timeout expires.

    Important: When a SNAT is affected, this issue will cause the connection table to grow indefinitely if the SNAT TCP idle timeout is set to the default value. If SNAT mirroring is required and cannot be disabled, F5 recommends that the SNAT TCP idle timeout is not set to Indefinite until this issue has been fixed in a future version of the software. The TCP idle timeout can be adjusted for each SNAT address. To do so, perform the following procedure:

    • Log in to the BIG-IP Configuration utility.
    • Navigate to Local Traffic >> SNATs >> SNAT Translation List.
    • Select the SNAT address from the list.
    • Change the TCP Idle Timeout setting to Specify and enter a desired idle timeout in seconds in the Seconds field.
    • Click Update.
    When adjusting the TCP Idle Timeout setting, be sure to take expected connection idle times into account so that valid connections are not prematurely terminated.
