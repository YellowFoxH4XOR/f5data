K000164070: Source Volume List Is Empty During GUI Upgrade to 17.5.1.xx Boot Volume on BIG-IP

Type
Support Solution
Published
2026-10-31
Updated
2026-11-03
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000164070

Description

After an upgrade to BIG-IP v17.5.1.xx and when trying to boot volume using the Configuration utility (GUI) with Install Configuration set to Yes, the Source Volume list may be empty (or not include the currently running boot location).

If you continue and activate/boot into the new volume, the GUI may display an error:

null does not exist

Environment

  • Upgrade from 17.5.1.x to 17.5.1.xx performed in the Configuration utility (GUI)
  • System > Software Management > Boot Locations > Install Configuration = Yes

Cause

This issue occurs due to ID1349933.

Recommended Actions

Note: The steps below are required only if there were configurations changes done to existing BIG-IP version done after the new version was installed. If no changes were done, then it's not required to follow any of the steps below and continue with Install Configuration set to No.

Follow any one of the steps below:

  1. Copy the configuration using the cpcfg command [RECOMMENDED]: 
    # cpcfg --source=<source HD volume> <destination HD volume>
    Use cpcfg to copy the configuration from the currently running boot location to the target boot location (K14724).
    [OR]
  2. Upgrade in two steps.
    Upgrade to 17.5.1.9 first, confirm the Source Volume list shows expected volumes, then upgrade to the newer target 17.5.1.xx build.
    [OR]
  3. Use default LiveInstall behavior (K13438)
    LiveInstall may still move/save the configuration depending on DB keys (see K13438):
    sys db liveinstall.moveconfig { value "enable" }
    sys db liveinstall.saveconfig { value "enable" }

Additional Information

  • K14724: Using the cpcfg command to copy a configuration from one boot location to another
  • K13438: LiveInstall move/save configuration behavior
