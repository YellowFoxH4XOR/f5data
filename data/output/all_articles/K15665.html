Known Issue

The local traffic policy server-ssl disable action fails with a rewrite profile in URL translation mode.

This issue occurs when all of the following conditions are met:

  • A local traffic policy that has a server-ssl disable action configured to disable a Server SSL profile is associated with a virtual server.
  • A rewrite profile configured in URL translation mode is also associated with the virtual server.

Impact

The Server SSL profile is not disabled for server-side traffic and the BIG-IP system erroneously attempts to establish server-side connections using SSL.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H477101 on the Diagnostics > Identified > Medium screen.
  • Requests to the affected virtual server fail.
  • You view messages in the /var/log/ltm file that appear similar to the following examples:

    info tmm[22991]: 01260013:6: SSL Handshake failed for TCP 10.10.10.50:80 -> 10.1.1.10:47496
    err tmm[22991]: 01230140:3: RST sent from 10.1.1.10:47496 to 10.10.10.50:80, [0x1d599e9:1340] SSL handshake timeout exceeded

Workaround

To work around this issue, you may be able to use an iRule in conjunction with a local traffic policy set-variable action to disable the Server SSL profile. To do so, perform the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Configuring a set-variable action in the local traffic policy

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Policies > Policy List and click on the existing policy with the server-ssl disable action.
  3. Under Rules, click the rule that contains the server-ssl disable action.
  4. Under Actions, select tcl from the Target drop-down list.
  5. In the Name box under Parameters, highlight name* and enter a name in the Value box.

    For example:

    policy_disable_serverssl
  6. Click the small Add button.

    The name should now appear in the List box.
  7. In the Name box under Parameters, highlight expression* and enter a value in the Value box.

    For example:

    1
  8. Click the small Add button.

    The expression should now appear in the List box.
  9. To add the set-variable action to the list, click Add.
  10. To save the changes, click Update Rule.

Creating an iRule and associating it with the virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, enter a name for the rule.
  5. In the Definition box, enter the code for the iRule.

    For example, using the example policy_disable_serverssl parameter name from the previous procedure, you would enter the following code:

when SERVER_CONNECTED {
if { [info exists policy_disable_serverssl] } {
SSL::disable serverside
unset policy_disable_serverssl
}
}

  • Click Finished.
  • Navigate to Local Traffic > Virtual Servers > Virtual Server List and click Edit next to the affected virtual server.
  • Under iRules, click Manage.
  • In the Available list, highlight the name of the iRule you created in step 4.
  • Click the arrow box to move the iRule to the Enabled box.
  • Click Finished.
