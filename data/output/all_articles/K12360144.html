Description

When testing a new application deployed with a Security Policy, DoS Profile, and Bot Defense Profile, you receive a blocked request with a support ID. This support ID cannot be found when searching the ASM event logs.

The block happens after navigating around the site, clicking between pages in rapid succession.

Environment

  • Bot Defense profile configured

Cause

Block in question comes from the Bot Defense profile, as the client is treated as a malicious bot due to unusual client-side behaviour. Bot defense logs are found in a different location.

Recommended Actions

To review the exact details for blocks issued by bot defense, apply a logging profile configured to log Bot Defense events. For example, the default profile local-bot-defense may be used.

Details for future blocks issued by bot defense can then be found under Security ›› Event Logs : Bot Defense : Bot Requests.

Additional Information

Bot Defense logs are separate from request logs found at Security ›› Event Logs : Application : Requests. This is applicable from BIG-IP version 14 onwards.

Note: There can be other reasons why events for particular support IDs are not found in either the application requests or bot defense logs. If you suspect the BIG-IP's logging mechanisms are misbehaving, open a service request with F5 Support.
