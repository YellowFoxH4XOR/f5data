Known Issue

This is the result of a known issue. TMM may panic if you change the iRule assignment for a virtual server while the virtual server is processing traffic and the iRule is in suspended state. This issue occurs for iRules containing commands that can suspend operation, such as the after, table, and persist iRule commands.

For example, if you use the Configuration utility to remove an iRule containing the table command from a virtual server while the virtual server is processing traffic, TMM can crash when the new iRule is applied to the virtual server.

F5 Product Development tracked this issue as ID 223883 (formerly CR132598) and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, and WOM release notes.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

In addition, BIG-IP iHealth may list Heuristic H356846 on the Diagnostics > Identified > High screen.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by performing the following steps prior to changing the iRule assignment for a virtual server:

Important: Use care when performing the following workaround as the steps involve manually editing the bigip.conf file.

  1. From the Configuration utility, define the new iRule.
  2. Back up the /config/bigip.conf file.

    For example:

    cp /config/bigip.conf /config/bigip.conf.SOL11149
  3. Use a text editor to edit the /config/bigip.conf file.
  4. Using the text editor, change the iRule association for the virtual server.

    For example, if the new iRule name is table_rule_new, you can change the iRule association for the following virtual server by using the text editor to replace the old iRule, table_rule, with the new iRule name:

    virtual VIP-A {
    pool pool-A
    destination 10.10.10.100:http
    ip protocol tcp
    rules table_rule
    profiles {
    http {}
    tcp {}
    }
    }

    Change to:

    virtual VIP-A {
    pool pool-A
    destination 10.10.10.100:http
    ip protocol tcp
    rules table_rule_new
    profiles {
    http {}
    tcp {}
    }
    }
  5. Save the file.
  6. Load the bigip.conf file by typing the following command:

    bigpipe load
