Description

You are experiencing unexplained connection interruptions on your application that flows through a BIG-IP Virtual Server.

Packet capture(s) shows TCP resets are interrupting the application flow.

Environment

  • BIG-IP
  • Virtual Server configured for application traffic
  • Virtual Server configured with TCP profile
  • Connections are being interrupted

Cause

TCP Resets

Recommended Actions

Confirm that TCP Resets are causing the interruptions.  Note: many applications will issue a reset when they complete their task instead of the RFC compliant 4 way close (i.e. a TCP RST may NOT be interrupting the flow the application)
  1. Take packet capture(s) of application flow that includes both the client side flow and server side flow (see K6546:  Recommended methods and limitations for running tcpdump on a BIG-IP system and K65251607:  Using tcpdump to create rotating packet capture files)
     
  2. Can any applications flows be found in the given packet capture?
    • If no, then TCP resets as a cause of application interruptions can not be confirmed.  Please take a new capture(s) which does have application flows.
       
  3. Does the packet capture show the client AND server flows?
    • If no, then retake packet capture(s) with both.
       
  4. If both #2 (applications flows exist) and #3 (client and server flows captured) are true, do any of these flows have TCP resets?
    • If no, TCP resets are not the cause of the application interruptions.
       
    • If yes, which device is sending the TCP reset?
      • If the Virtual Server, what is the Reset Cause?
        • If there is no Reset cause, ensure that you turned TM.RstCause.Pkt on in the BIG-IP.
          Note: How to do this and some of the causes are explained in K13223: Configuring the BIG-IP system to log TCP RST packets
      • If another device in the flow, is there a clear reason?
        • if no clear reason for the TCP Resets are found, further packet captures (including packet captures taken on the other devices in the flow) may be necessary.
          Note: Explaining the reason for other devices to send a TCP Reset is beyond the Scope of F5 Support and may require discussions with that device's vendor.

Additional Information

If you need to see the HTML that TCP is underlying and it is encrypted via SSL, please utilize articles in Related Content to obtain decrypted traffic.
