Known Issue

Deleting multiple access profiles on a BIG-IP APM system may fail.

This issue occurs when the following condition is met:

  • You attempt to delete two or more access profiles that are configured to reference the same AAA authentication profile.

Impact

Users cannot delete access profiles.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you use the Configuration utility to delete multiple access profiles, that reference the same AAA authentication profile, an error similar to the following example appears:

    01071108:3: Cannot delete aaa <authentication type> server (/<partition path>/<authentication profile>) because it is referenced by an agent (<access policy authentication agent>) in access profile (/<partition path>/<access profile name>).

  • When you attempt to delete access profiles, error messages similar to the following example log to the /var/log/apm file:

    01071349:3: File object by name (/<partition path>/<access profile associated object>) is in use.
    01071193:3: Cannot delete aaa <authentication type> server (/<partition path>/<referenced aaa profile>) because it is referenced by an agent <access policy action> profile (/<partition path>/<access policy object>).
    01071193:3: Cannot delete aaa <authentication type> server (/<partition path>/<aaa profile referenced server>) because it is referenced by an agent (<agent type> - for <access policy object>) in access profile (/<partition path>/<access policy object>).

Workaround

To work around this issue, you can clear the check box for deleting the associated AAA profile when you confirm deletion of the access profiles.

Impact of workaround: The AAA profile is not deleted and may require manual deletion if removal of the AAA profile is desired.
