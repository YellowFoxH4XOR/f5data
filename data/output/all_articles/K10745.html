Topic

Data Group names containing a special character must be enclosed with brace characters ( { } ) when referenced in an iRule. If the Data Group name contains a special character such as a period ( . ), or a hyphen ( - ) and no brace characters are used around the name in the iRule, the Tool Command Language (Tcl) misinterprets the Data Group name when a connection triggers the iRule.

Note: An underscore character ( _ ) does not require brace characters when referenced in an iRule.

For example, the following Data Group, test.network, contains a period in the name:

class test.network {
   network 172.16.64.0/24
}

The test.network Data Group is referenced without brace characters ( { } ) in the following iRule:

rule testrule {
   when CLIENT_ACCEPTED {
if { [matchclass [IP::client_addr] equals $::test.network] } {
                snat automap
        }
}

When a connection triggers the example iRule, the iRule fails to locate the Data Group name and the system logs an error message to the /var/log/ltm file that appears similar to the following example:

tmm tmm[1434]: 01220001:3: TCL error: test.rule <CLIENT_ACCEPTED> - can't read "::test": no such variable while executing "matchclass [IP::client_addr] equals $::test.network"

Using proper Tcl syntax when the Data Group name contains a special character

If the Data Group name contains characters other than letters, digits, underscores, enclose the Data Group name with brace characters, as displayed in the following iRule example:

rule testrule {
   when CLIENT_ACCEPTED {
if { [matchclass [IP::client_addr] equals ${::test.network}] } {
                snat automap
        }
}

Note: For more information about Tcl syntax, refer to the Tcl Reference Manual.
