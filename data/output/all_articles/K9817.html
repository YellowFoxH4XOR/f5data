Topic

In order to encrypt communications between client devices and FirePass, you must install an SSL server certificate on the FirePass controller. If you do not want to purchase a third-party SSL certificate, FirePass can generate a self-signed SSL certificate to encrypt communications. However, client systems will not inherently trust the self-signed certificate, and will issue a warning when users connect that the provided certificate is not from a trusted source. You can work around this behavior by manually configuring the FirePass SSL certificate as a trusted certificate on client devices, however this option may not be manageable in larger environments. Additionally, this option may not be suitable in environments where some client devices are not corporate-issued (for example, home computers or partner systems). Therefore, most companies opt to purchase an SSL certificate from a well known Certificate Authority (CA).

Note: Starting in FirePass version 6.1.0 with hotfix HF-610-1 installed, you have the ability to set the bit strength for the certificate from the FirePass Administrative Console. For more information regarding that enhancement, reference K10540: FirePass support for 2048-bit and 4096-bit SSL certificates.

Note: Some examples of well known CAs are VeriSign, Comodo, and GoDaddy. 

To obtain and install a third-party SSL certificate on a FirePass controller, complete the following procedure:
 
  1. Ensure that the WHOIS information for your domain is up-to-date, especially for the administrative and technical contacts. The CA will contact one or both of these contacts (typically by email) to verify that the SSL certificate was requested by an authorized party.

    Note: You can view your domain’s WHOIS information by searching for your domain name at http://whois.domaintools.com.
     
  2. Logon to the FirePass Administrative Console.
  3. Navigate to the Device Management : Security : Certificates page.
  4. In the Renew/Replace SSL Server Certificate section, select the Generate link next to Generate New Certificate Request.
  5. In the Server Name field, enter the fully qualified domain name (FQDN) of the FirePass controller. Or, if your FirePass controller will have multiple web services with different hostnames, enter the FQDN of the web service which will use this certificate. For example:

    firepass001.example.com

    Important: When you configure an SSL web service, the hostname you enter in the Hostname field must match the server name (also called the Common Name) contained in the SSL certificate. If it does not, users will receive a warning message when connecting to that web service. The one exception is with wildcard SSL certificates, which use pattern matching in place of the subdomain name. For more information about wildcard SSL certificates, refer to K8594: Support for wildcard SSL certificates.
     
  6. Enter the information appropriate for your company in the remaining fields. All fields must be completed.

    Important: Keep the password you enter in the Encryption Password field in a secure location. You’ll need to re-enter that password to install the SSL certificate on the FirePass controller. If you lose or forget the encryption password, you will be unable to install the certificate.
     
  7. Click the Generate Request button.
  8. Review the certificate request information displayed on the screen. If it is correct, proceed to the next step. If it is not, return to Step 3.
  9. Click on the link provided to download the certificate request zip file.
  10. On the client system, extract the three files contained in the zip file:

    • README.HTML

      This file contains basic instructions for obtaining an SSL certificate.
    • new.key

      This file contains the private key for your certificate. Please save this file in a safe location to prevent it from being lost, stolen, or misused. You cannot install the SSL certificate without this file.
    • newcert.csr

      This file contains the certificate signing request (CSR).

    Note: If the zip file does not contain all three files, return to Step 3 and generate a new CSR. Ensure that you fill out all fields on the certificate details page (Step 6).
     
  11. Select a CA and order your new certificate. F5 Networks does not recommend or endorse a specific certificate provider. Additionally, each CA offers different options when ordering a certificate. Choose the certificate validity period (how many years the certificate is valid), level of encryption, and optional add-ons based on the needs of your environment and your security policies. FirePass supports wildcard SSL certificates and Extended Validation (EV) SSL certificates in addition to standard SSL certificates.

    Note: For more information about wildcard SSL certificates, refer to K8594: Support for wildcard SSL certificates. For more information about EV SSL certificates, refer to K8357: FirePass support for Extended Validation SSL certificates.
     
  12. As part of the ordering process, you’ll be asked to provide a certificate signing request (CSR). Provide the contents of the file newcert.csr (Step 10) to your CA to be signed. If prompted for the server type or platform, select Apache or Mod_SSL.

    Note: The certificate and private key must be in X.509 Base64 PEM format in order to be installed on the FirePass controller. Selecting Apache or Mod_SSL for the server type instructs the CA to provide the files in the X.509 Base64 PEM format.

    Important: On Windows systems, open newcert.csr in Wordpad instead of Notepad. The certificate may display extra formatting characters in Notepad, resulting in the CA reporting an error when you cut and paste the CSR from Notepad.
     
  13. As mentioned in Step 1, the CA will typically perform some type of validation before issuing the certificate, such as emailing the administrative or technical contacts for your domain to authorize the SSL certificate. Ensure that the recipients of these emails authorize the issuance of the certificate.
  14. Once the CA validates the certificate request, the CA will provide you with a signed SSL certificate. Additionally, the CA may also provide the root and intermediate CA certificates which form the certificate chain (also called the certification path).

    Note: For more information about certificate chains, refer to RFC4158.

    Note: If you ordered an EV SSL certificate, users may receive certificate errors if the CA did not set the Extended Key Usage (EKU) field correctly in the SSL certificate. For more information, refer to K9164: Extended Validation SSL certificates may cause error messages when accessing Dynamic Application Tunnels and Web Application Tunnels.
     
  15. Navigate to the Device Management : Security : Certificates page.
  16. In the Renew/Replace SSL Server Certificate section, click the Install link next to Install/Renew Certificate.
  17. In the Paste the new certificate in the PEM format (for Apache + mod_ssl) here field, paste the signed certificate provided by your CA.
  18. In the Paste the corresponding cryptographic key in PEM format here field, cut and paste the contents of new.key (Step 10).
  19. In the Enter password here field, enter the encryption password you configured when creating the certificate request (Step 6).
  20. Optionally, in the Optionally, put your intermediate certificate chain here (in the PEM format) field, paste the root CA certificate and any intermediate CA certificates provided by the CA.

    Note: In some instances, the certificates in the certificate chain must be pasted in a specific order. For more information, refer to SOL8374: Error Message: Your certificate chain cannot be fully verified.

    Important: For EV SSL certificates, this is not an optional field. If you are installing an EV SSL certificate, you must enter the complete certificate chain to ensure full functionality.
     
  21. Click the Go! button.
  22. If FirePass reports a certificate error, resolve the issue reported before proceeding. If no certificate errors are reported, click the Save button.

    Note: For information about resolving the Your certificate chain cannot be fully verified error message, refer to K8374: Error Message: Your certificate chain cannot be fully verified.
     
  23. The certificate should now be displayed in a table. In the Filenames column, note the filenames of the certificate and key. For example:

    cert0.pem, key0.pem

    Note: You will need to remember these filenames when configuring the web service in Step 26.
     
  24. Click the Web Services tab.
  25. Click the Configure link next to the web service you want to configure or create a new web service in the Add new service section.

    Note: For detailed instructions about configuring a web service, refer to the FirePass Controller Administrator Guide.
     
  26. In the Certificate menu, select the certificate you just installed.

    Note: The Certificate menu will not appear unless the Use SSL check box is selected.
     
  27. Click the Update button.
  28. Click the Finalize tab.
  29. Click the Finalize Changes button.
  30. Click the Apply Changes and Restart button.
  31. Click the Restart button to restart the FirePass controller.

    Important: The new certificate will not take effect until you restart the FirePass controller.
     
  32. F5 Networks strongly recommends storing your private key, encryption password, SSL certificate, and all root/intermediate CA certificates provided by your CA in a secure location. The CA cannot provide the private key or encryption password if they are lost or forgotten.
