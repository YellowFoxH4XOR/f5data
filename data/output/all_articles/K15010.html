Known Issue

Description

The Traffic Management Microkernel (TMM) may stop responding due to a memory leak caused by the source address translation subsystem. This issue may occur on both the active and standby devices. In addition, source address translation features do not need to be enabled for this issue to occur.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H449188 on the Diagnostics > Identified > Low|Medium|High screen.
  • The amount of memory allocated for and used by the source address translation subsystem will increase over time.

    To inspect the memory usage for the source address translation subsystem, you can use the following Traffic Management Shell (tmsh) command:

    # tmsh show /sys memory | egrep 'Max\ Alloc|source\ addr'

    The output of the command will appear similar to the following example:

    SubSystem Alloc (bytes) Max Alloc (bytes) Object Size
    source address translation (var 4628466880 4628466880 4628466880

    Repeating the command will show an increase over time.
  • The BIG-IP system may fail over to the standby system if it is configured as a high-availability pair.
  • The BIG-IP system may generate a TMM core file to the /shared/core directory.
  • Prior to the TMM process becoming unresponsive, the sweeper may start terminating connections and report error messages similar to the following example:

    warning tmm2[11028]: 011e0003:4: Aggressive mode sweeper: 9 Connections killed

  • You may observe error messages similar to the following examples on any of the /var/log/tmm* files:

    notice ** SIGFPE **
    notice fault addr: 0x5ccde3
    notice fault code: 0x1
