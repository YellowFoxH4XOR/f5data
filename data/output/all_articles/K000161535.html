K000161535: Remote users with usernames containing a backslash or at sign cannot access some BIG-IP Configuration Utility pages or generate an auth token using the REST authentication API

Type
Support Solution
Published
2026-06-02
Updated
2026-09-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 21.0.0, 21.0.X, 21.1.X, 21.1.0, 17.1.3, 17.5.1
Source
https://my.f5.com/manage/s/article/K000161535

Description

The issue affects both the BIG-IP Configuration Utility WebUI and the iControl REST authentication API when remote users have usernames that contain a backslash (\) or an at sign (@).

In the BIG-IP Configuration Utility WebUI, users can log in successfully, but they cannot access certain pages afterward. The following error is displayed:

Error getting auth token from login provider.

Affected pages include:

  • Device Management
  • Shared Objects
  • iApps Application Services

For iControl REST API token-based authentication, when a remote user tries to request a token from the authentication API, the following error is returned:

token creation failed; valid username characters are alphanumeric, '.', '-' and '_'

This issue does not affect SSH CLI access or the initial WebUI login through a browser.

Environment

  • BIG-IP versions: v17.1.3.2, v17.5.1.6, v21.0.0.2, v21.1.0
  • Remote authentication is configured, such as Active Directory, LDAP or RADIUS
  • The username contains a backslash or an at sign, for example: DOMAIN\username or user@domain

Cause

The issue is tracked under Bug ID2304105.

Although the backslash (\) and at sign (@) are valid characters according to the REST API Naming Conventions documented in K000157972, a regression introduced by a prior security fix incorrectly removed both characters from the username validation regex in the iControl REST authentication token worker.

Answer/Recommended Actions

A fix is currently in progress and will be included in a future maintenance release.

If an immediate fix is required before the resolved version becomes available, contact F5 Support to request an Engineering Hotfix (EHF) for your specific BIG-IP version.
