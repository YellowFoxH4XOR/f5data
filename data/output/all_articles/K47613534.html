Description

When you configure a new ASM logging profile and set up remote logging, the BIG-IP system appears to be not sending any log messages to the configured remote log server. 

Environment

  • BIG-IP ASM
  • ASM logging profile with remote logging enabled

Cause

The problem is due to inconsistency among DCC/guishell and tmsh databases. The profile is missing in one of the mentioned places.

Recommended Actions

Impact: this procedure should not cause a negative impact on production traffic.

1.  Check if the profile is present in the TMSH config file:

[root@logging:Active:In Sync (Sync Only)] ts # tmsh list security log profile test_logging | grep servers -A 7
            servers {
                192.0.2.1:514 { }
                192.0.2.2:514 { }
                192.0.2.3:514 { }
                192.0.2.4:514 { }
            }
        }
    }

2.  check if the profile is present in the guishell DB:
[root@logging:Active:In Sync (Sync Only)] ts # guishell -c "select LEAF_NAME,ADDRESS,PORT from fw_log_server_address"
---------------------------------
|    LEAF_NAME | ADDRESS | PORT |
---------------------------------
| test_logging | 192.0.2.1 |  514 |
| test_logging | 192.0.2.2 |  514 |
| test_logging | 192.0.2.3 |  514 |
| test_logging | 192.0.2.4 |  514 |
---------------------------------

3.  check if the profile is present in the DCC DB:
 
[root@logging:Active:In Sync (Sync Only)] ts # mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "use DCC; select log_profile_name,server_ip from REMOTE_STORAGE_CONFIGURATION"
+----------------------+-----------+
| log_profile_name     | server_ip |
+----------------------+-----------+
| /Common/test_logging | 192.0.2.1  |
| /Common/test_logging | 192.0.2.2  |
| /Common/test_logging | 192.0.2.3  |
|                                   |<------- !!!! | /Common/test_logging | 192.0.2.4 | is missing
+----------------------+-----------+
4. If the profile is not present in one of the listed outputs, it means you are affected. To fix this problem, restart asm config services:
 
pkill -f asm_config_server
pkill -f dcc
pkill -f tsconfd
