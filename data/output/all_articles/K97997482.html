Description

The IPsec ALG for AFM profile (ipsecalg) fails to handle clients that detect NAT during tunnel negotiation.

During the ISAKMP negotiation of the IPsec tunnel, if the IPsec endpoints detect NAT and agree to switch to UDP port 4500, the ipsecalg profile will not handle that UDP flow.

As a result, the tunnel will fail to establish. The tunnel may work if an existing Virtual Server or listener on the BIG-IP matches the UDP port 4500 flow.

 

Environment

You are configuring IPsec application layer gateway (ALG) functionality with Internet Key Exchange (IKE) security for Advanced Firewall Manager™ (AFM™) firewall with network address translation (NAT).
  • A typical IPsec ALG configuration includes a UDP virtual server listening on Internet Security Association and Key Management Protocol (ISAKMP) port 500, using IPsec tunnel mode.
  • Some IPsec clients support NAT-T and some do not.
     

Cause

The IPsec ALG for AFM (ipsecalg) profile is designed to accommodate IPsec endpoints that do not support RFC3947 (Negotiation of NAT-Traversal in the IKE). The profile is not designed to handle UDP port 4500 traffic.

Recommended Actions

Configure a second Virtual Server to forward UDP port 4500 traffic. This can be considered a fallback Virtual Server, for the majority of IPsec clients that do support RFC3947.
The configuration of the Virtual Server will vary between use cases; there is no single correct method or best practice.
 

Additional Information

The IPsec ALG for AFM profile recommended only for special cases where legacy IPsec clients do not support NAT-T.
