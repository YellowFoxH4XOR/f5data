K5846: BIG-IP may remove connections from the software connection table while the connection is accelerated by the PVA

Known Issue

BIG-IP maintains both a software connection table and a hardware connection table for the Packet Velocity ASIC. When a connection is accelerated, BIG-IP creates a connection table entry in the software connection table and then creates a connection table entry for the Packet Velocity ASIC (PVA). When an idle connection reaches a timeout, BIG-IP deletes the connection from the software connection table, and then deletes the connection from the PVA connection table.

Connection timestamps are not passed from the PVA to the software connection table when a connection is accelerated. As a result, connections may reach an idle timeout for the software connection table while the PVA still considers the connection active. This situation can occur when the connection reaches the configured service timeout or when the max_syn_timeout limit is reached for the connection.

The max_syn_timeout variable controls the amount of time BIG-IP will wait to receive data on a node side connection, following the TCP three-way handshake. BIG-IP does not reset the timestamp on the entry in the software connection table when the connection is accelerated, so the software connection entry is always deleted when the max_syn_timeout variable expires for an accelerated connection.

Because the connection remains in the PVA connection table, the connection is not interrupted; however, the following issues may occur as a result of the missing software connection table entry:

  • When multiple delayed binding virtual servers, or a combination of delayed binding and non-delayed binding virtual servers share the same nodes, a non-accelerated connection and an accelerated connection may be assigned to the same port, leading to a port collision.
  • Connection limits may not be properly enforced, because only connection entries in the software connection table are counted toward the connection limit.
  • Statistics may not be accurate, because only connection entries in the software connection table are included in the statistics.

F5 Networks Product Development tracked this issue as CR34165, and the conditions that cause this issue were reduced in BIG-IP version 4.5.14. For information about upgrading, refer to the BIG-IP Release Notes.

This issue can only be eliminated completely by disabling the packet velocity ASIC.

BIG-IP version includes the following improvements to reduce the occurrence of this issue:

  • The max_syn_timeout setting no longer acts on accelerated connections. Idle accelerated node side connections will now remain open until TCP timeouts on the BIG-IP and the node are reached.
  • A new internal variable, hw_conn_reap_factor, was added to allow configuration of the timeout multiplier for accelerated connections.
  • The hw_conn_reap_factor internal variable allows you to specify a multiplier for the service_timeout value. The default value is 10. When the amount of time equal to the service_timeout value multiplied by the hw_conn_reap_factor is reached, the connection is deleted from the software connection table. If you use long-lived connections and short service timeouts, increasing the hw_conn_reap_factor may reduce the chance that active accelerated connections may be deleted from the software connection table.
  • F5 Networks recommends that you do not change this setting unless you experience one of the problems described in this Solution. At the default service_timeout value of 1005 seconds and the default hw_conn_reap_factor value of ten, the connection timeout for accelerated connections is 10050 seconds or approximately 2 hours and 47 minutes.
