Known Issue

Changes to connection limits on pool members or nodes do not immediately take effect.

This issue occurs when all of the following conditions are met:

  • Pool member has a connection limit set.
  • The connection limit is reached for the pool member.
  • The connection limit is subsequently increased for the pool member, using one of the following methods:
    • Using the Configuration utility
    • Using either the following bigpipe or tmsh command syntax examples:

      bigpipe pool <pool-name> members <ip:port> { limit <value> }

      tmsh modify /ltm pool <pool-name> members modify { <ip:port> { connection-limit <value> } }

If the connection limit is increased after the system has reached the connection limit, by using one of the aforementioned methods, the new connection limit will not take effect until the current connections fall below the previously-set connection limit.

Impact

The new connection limit does not take effect until the connection count drops below the previously-reached connection limit.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Connections are rejected to a pool member that has fewer connections than a newly-set connection limit.
