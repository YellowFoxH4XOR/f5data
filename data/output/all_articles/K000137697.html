K000137697: EMFILE and high memory errors when using Telemetry Streaming

Type
Support Solution
Published
2023-11-27
Updated
2025-03-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000137697

Description

After setting up TS (Telemetry Streaming) successfully on BIG-IP, BIG-IP may start printing the EMFILE error a few hours later.

Traceback:

Error: HTTP error: Error: connect EMFILE 192.168.2.1:9570 - Local (undefined:undefined)

 at Request.request.(anonymous function) [as _callback] (/var/config/rest/iapps/f5-telemetry/lib/utils/requests.js:181:24)

 

Environment

  • TS with generic HTTP consumer
  • restnoded restarting multiple times

Cause

TS has too many open connections to the consumer and resulting in high memory usage related to restnoded.

Recommended Actions

Include the necessary customOpts keys and value settings to the TS declaration json file so as to set a limit on the open connections to the consumer.

Example:

{
    "class": "Telemetry",
    "My_Consumer": {
        "class": "Telemetry_Consumer",
        "type": "Generic_HTTP",
        "host": "192.168.2.1",
        "protocol": "https",
        "port": 443,
        "path": "/",
        "method": "POST",
        "headers": [
            {
                "name": "content-type",
                "value": "application/json"
            },
            {
                "name": "x-api-key",
                "value": "`>@/passphrase`"
            }
        ],
        "passphrase": {
            "cipherText": "apikey"
        },
        "outputMode": "processed",
        "compressionType": "gzip",
        "customOpts": [
            { "name": "keepAlive", "value": true },
            { "name": "keepAliveMsecs", "value": 30000 },
            { "name": "maxSockets", "value": 30 },
            { "name": "maxFreeSockets", "value": 30 }
        ]
    }
}
