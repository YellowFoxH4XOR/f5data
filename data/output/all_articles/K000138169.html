Description

BIGIP administrator may notice the below error for setup where APM is configured as oAuth Client (and/or Resource Server) under oAuth Scope agent:

Dec 27 13:53:33 bigip.local err apmd[15543]: 01490290:3: /Common/ap_test:Common:3ef3b2cb:/Common/ap_test_act_oauth_scope_ag: OAuth Scope: failed for jwt-provider-list '<name_of_JWT_provider_list>' , error: None of the configured JWK keys match the received JWT token, JWT Header: eyJ0eXAiOiJKV1QiLCJub25jZSI6IkxDRGUxc2s1dVdZMi1VWFphTlAxbXZvc05vR2FfNFpMNkJxWWZIWklsdG8iLCJhbGciOiJSUzI1NiIsIng1dCI6IjVCM25SeHRRN2ppOGVORGMzRnkwNUtmOTdaRSIsImtpZCI6IjVCM25SeHRRN2ppOGVORGMzRnkwNUtmOTdaRSJ9

The error itself may have several triggers. This article will describe the issuer mismatch trigger.

Environment

APM
oAuth
Issuer

Cause

The Issuer claim mismatch may result to the error.

Recommended Actions

Make sure that the Issuer claim value received by APM in Access-token matches with Issuer value in 'apm oauth jwt-config' section. If APM gets the access-token value in jwt format which can be decoded (for instance, in https://jwt.io/), then you should see in Payload the "iss" key name. It's value must match with 'issuer' setting value from corresponding 'apm oauth jwt-config' section.

For example, the below config portion is generated when Azure AD (aka Microsoft Entra ID) is used by APM as oAuth Provider and JWKs are auto-discovered and auto-populated to APM; the Issuer setting was auto-populated with value 'login.microsoftonline.com':
apm oauth jwt-config /Common/auto_jwt_<provider_name> {
  allowed-keys {
    /Common/auto_jwk_<provider_name>1 { }
    /Common/auto_jwk_<provider_name>2 { }
    /Common/auto_jwk_<provider_name>3 { }
  }
  allowed-signing-algorithms { RS256 }
  auto-generated true
  issuer https://login.microsoftonline.com/<tenant_id>/v2.0 <<<< (!)
  jwks-uri https://login.microsoftonline.com/<tenant_id>/discovery/v2.0/keys
}

But in Access-token in jwt format after decode, the Payload section contained issuer value defined as 'sts.windows.net':
<omitted for brevity>
"iss": "https://sts.windows.net/<tenant_id>/" <<<< (!)
<omitted for brevity>

And it resulted to the common error "None of the configured JWK keys match the received JWT token".
