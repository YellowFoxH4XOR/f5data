Known Issue

Configuring identical primary and alternate network mirroring addresses corrupts the mirror message queue.

This issue occurs when all of the following conditions are met:

  • BIG-IP 10.x: You use either the Configuration utility or the Traffic Management Shell (tmsh) to configure network mirroring (also referred to as connection mirroring).
  • BIG-IP 11.0.0 to 11.2.1: You use tmsh to configure network mirroring (also referred to as connection mirroring).
  • The Primary and Alternate Mirroring address options are configured to use the same IP address.

Impact

The BIG-IP system does not maintain client connections after a failover event.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H638394-14 on the Diagnostics > Identified > Medium screen.
  • The connection mirror table on the standby system is missing entries. You can view the table by typing the following command:

    tmsh show sys connection type mirror

  • You notice many established client connections fail after a failover event.

Workaround

You can work around this issue by ensuring that the primary and alternate network mirroring address settings use unique IP addresses. To do so, perform one of the following procedures, depending on the version you are running:

BIG-IP 11.0.0 - 11.2.1

  1. Log in to the BIG-IP Configuration utility.
  2. Click Device Management.
  3. Click Devices.
  4. Click the local device.
  5. From the Device Connectivity menu, select Mirroring.
  6. Configure the primary and secondary mirror addresses to use different IP addresses.
  7. Click Update.

BIG-IP 10.x

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. Click Network Mirroring.
  5. Configure the self and peer alternate mirroring address settings to use different IP addresses than the configured primary mirroring address settings.
  6. To save the configuration, click Update.
