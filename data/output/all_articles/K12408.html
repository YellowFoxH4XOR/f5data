Known Issue

This is the result of a known issue. If you configure a pool to use an inband monitor together with an active monitor, TMM may become unresponsive with SIGFPE due to a rare race condition. In addition, the BIG-IP system will log an entry to the /var/log/tmm file that appears similar to the following example:

notice panic: ../base/pool.c:4062: Assertion "Pool member is passive downed" failed

The following example provides the configuration, an inband monitor MyInbandMon, and an active monitor MyHttpMon assigned to pool MyPool, which may result in this known issue:

monitor MyHttpMon {
defaults from http
}
monitor MyInbandMon {
defaults from inband
}
pool MyPool {
monitor all MyInbandMon and MyHttpMon
members 10.10.10.10:http {}
}

This known issue also occurs if you configure a pool to use an inband monitor and the pool member has active monitor assigned to its node. The following example provides the configuration, an inband monitor MyInbandMon assigned to pool MyPool, and active monitor gateway_icmp assigned to the node of pool member 10.10.10.10, which may also result in this known issue:

monitor MyInbandMon {
defaults from inband
}
node 10.10.10.10 {
monitor gateway_icmp
}
pool MyPool {
monitor all MyInbandMon
members 10.10.10.10:http {}
}

F5 Product Development tracked this issue as ID 223787 (formerly CR131891), and it was fixed in BIG-IP version 10.2.3. For information about upgrading, refer to the BIG-IP release notes.

Workaround

You can work around this issue by removing the inband monitor assigned to a pool and using only the active monitor. However, if you require the use of both an active and inband monitor in a pool, you will need to disable the retry feature of the inband monitor by configuring the inband monitor attribute Retry Time to zero (0). To do so, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Monitors.
  4. To select the desired inband monitor, click the inband monitor name.
  5. Configure the attribute Retry Time with a value of zero (0).
  6. To save the modification, click Update.

Command line

  1. Log in to the command line using a privileged account, such as root.
  2. To modify the Retry Time attribute of the inband monitor, type the following tmsh command syntax:

    tmsh modify ltm monitor inband <name of inband monitor> retry-time 0

    For example, to modify the inband monitor inband-223787 you would type the following tmsh command:

    tmsh modify ltm monitor inband inband-223787 retry-time 0

  3. To save the modifications into the /config/bigip.conf file, type the following tmsh command:

    tmsh save config
