K34110147: vCMP Guest gets stuck in ''starting'' after upgrade or reboot.

Type
Support Solution
Published
2021-06-25
Updated
2025-04-01
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K34110147

Description

After an upgrade or reboot, a vCMP Guest gets stuck in 'starting', and keeps on rebooting.
The vCMP guest shows errors similar to the following ones in /var/log/ltm:

mcpd: 0114002b:6: HA overdog_ctl watchdog enabled.
mcpd: 0114002b:6: HA daemon_heartbeat mcpd enabled.
mcpd: 0114002c:6: HA overdog_ctl watchdog disabled.
clusterd: 013a0023:6: Blade 1: No info received from slot: Starting up 
overdog: 01140104:5: Watchdog touch disabled.


The vCMP host shows error messages similar to these  in /var/log/ltm:

err vcmpd: 01510004:3: Guest (vCMP_guest_name): Failure - Error starting VM. Timed out after 900 seconds.
info vcmpd: 01510007:6: Guest (vCMP_guest_name): VS_STARTING->VS_FAILED
info vcmpd: 01510007:6: Guest (vCMP_guest_name): VS_WAIT_STARTING->VS_STARTING
notice vcmpd: 01510006:5: Guest (vCMP_guest_name): Starting VM.


In the vCMP host, the output of the command show /vcmp guest all-properties, the guest remains as  'starting'  status.

Environment

  • vCMP guest
  • Upgrade or reboot 
  • BIG-IP LTM

Cause

The BIG-IP system  database variable watchdog.state is set to disable. This prevents the guest from correctly starting.

Recommended Actions

  1. Verify if the watchdog.state database variable is disabled by running the following command:
     
    tmsh list sys db watchdog.state
     
    sys db watchdog.state {
        default-value "enable"
        scf-config "false"
        value "disable"
        value-range "disable enable"
    }
     
    Note: In the above output the variable is set to "disable"
     
  2. Enable the database variable by running the following command:
     
    tmsh modify sys db watchdog.state value enable
