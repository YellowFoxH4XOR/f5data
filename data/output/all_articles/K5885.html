Known Issue

This is the result of a known issue. If insufficient disk space is detected during the installation of a hotfix, the hotfix installation will abort and an error message that appears similar to the following example will display:

Available KiB blocks in root partition: 28555 insufficient disk space.
See solution: SOL5885 Hotfix aborted.

Note: This issue most often occurs when the BIG-IP system was installed on a Compact Flash (CF) storage device.

F5 Product Development tracked this issue as CR58707 and CR62727, and changes were made to reduce the likelihood of this issue occurring in BIG-IP version 9.1.2 for the BIG-IP 9.1 software branch, version BIG-IP 9.2.4 for the BIG-IP 9.2.0 software branch, and in the BIG-IP 9.3.0 and 9.4.0 software branches. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

Important: It is not possible to completely eliminate the possibility of insufficient disk space. Therefore, this issue may still occur on any BIG-IP version.

If you receive a similar message during the installation of a hotfix, you can work around this issue by removing the unused debug TMM packages and reinstalling the hotfix. To do so, perform the following procedure:

  1. Log in to the BIG-IP system command line.
  2. Force the link for TMM to the tmm.default file by typing the following command:

    ln -sf /bin/tmm.default /bin/tmm
  3. Remove the unused TMM packages by typing the following command:

    rpm -e tmm-debug tmm-strict

    Important: Recent BIG-IP 9.4.x versions do not install the tmm-debug and tmm-strict packages when the destination slot is a Compact Flash. If you are trying to free additional disk space in order to install a hotfix, and these packages are not present on your system, contact F5Technical Support to obtain an alternative workaround.
  4. Reinstall the hotfix by typing the following command:

    im <hotfix>
