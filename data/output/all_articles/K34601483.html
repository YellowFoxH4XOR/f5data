K34601483: Upgrade may fail on a multi blade system when there are scheduled reports in configuration

Type
Support Solution
Published
2023-04-06
Updated
2025-02-06
Status
Legacy Content
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K34601483

Description

You are unable to upgrade to a newer version or apply a hotfix, as the secondary slot consistently fails the upgrade. The error log displays a connection issue between tmsh and monpd on the secondary blades. The liveinstall.log shows the following error message:

error: status 256 returned by command: F5_INSTALL_SESSION_TYPE=install tmsh -f save sys ucs /var/tmp/fbSBcyXrsz.ucs
info: >++++ result:
info: Saving active configuration...
info: Thrift: Tue Dec 19 10:53:45 2017 TSocket::open() connect() <Host: localhost Port: 9090>Connection refused
info: Error during config save.
info: Unexpected Error: UCS saving process failed.

Environment

  • Viprion
  • AVR
  • Big IP v13.x

Cause

Secondary blades' monpd is listening on a non-slot-specific local address (127.0.0.1), causing tmsh to be unable to establish a connection to monpd using the address space (127.0.3.X).
 

Recommended Actions

  1. Save the configuration for scheduled reports separately.
  2. Remove all scheduled reports from the configuration.
  3. Perform the upgrade.
  4. Add scheduled reports back to the configuration.
