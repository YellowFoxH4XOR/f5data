K000135389: Configure the MAC Block Size for an existing BIG-IP tenant on the VELOS and rSeries systems

Topic

You should consider using this procedure under the following condition:

  • You want to configure the MAC block size for an existing BIG-IP tenant on the VELOS and rSeries systems.

Description

Beginning in F5OS-C 1.6.0 (for VELOS systems) and F5OS-A 1.3.0 (for rSeries systems), you can configure a BIG-IP tenant on these systems to use contiguous block of MAC allocation using the MAC Data/MAC Block Size setting in the webUI or the mac-block-size setting in the CLI and REST API. The available values for this setting are as follows:

ValueDescription
OneThis value represents a block with one (1) MAC address. This is the default value when you create a new BIG-IP tenant. When you configure the setting to one for a BIG-IP tenant with multiple VLANs, each VLAN would use the same MAC address. This behavior is same as that prior to the introduction of this setting in F5OS-A 1.3.0.
SmallThis value represents a contiguous block of eight (8) MAC addresses.
MediumThis value represents a contiguous block of sixteen (16) MAC addresses.
LargeThis value represents a contiguous block of thirty-two (32) MAC addresses.

Due to configuration validation, you cannot change the MAC Data/MAC Block Size setting in the webUI or the mac-block-size setting in the CLI and REST API while the BIG-IP tenant is in the deployed state. If you attempt to do so, the system does not commit the change and responds with an error similar to the following example:

Cannot modify mybigiptenant1 tenant field. Changes are invalid in current state.

Important: Depending on the allocation and de-allocation of MAC addresses for the system over time, fragmentation may occur. Since a block of MAC addresses assigned to a BIG-IP tenant must be contiguous, this can lead to situations where the system is unable to allocate a large block of thirty-two (32) contiguous MAC addresses even if there are more than enough MAC addresses available. In this scenario, the commit of the configuration fails and the system rolls the configuration back to the previous value of the MAC Data/MAC Block Size (mac-block-size) setting. Additionally if the system is able to find a contiguous block to match the new value, the new contiguous block of MAC addresses will differ from the previous block of MAC addresses.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the management interface (webUI/CLI/REST API) of the VELOS partition or the rSeries system.
  • If you intend to use the REST API procedures, you should have a workstation with curl and jq utilities installed. If you do not have one, you can login to the VELOS chassis or the rSeries command line as the root user to use the curl and jq utilities as needed.

Procedures

You can configure the MAC block size for an existing BIG-IP tenant using either webUI, CLI or REST API. To do so, perform the procedure most appropriate for your application environment/requirements:

Impact of procedure: The State (running-state) of the BIG-IP tenant needs to be set to either configured or provisioned prior to modifying the MAC block size setting and then set back to deployed after the modification. As a result, the BIG-IP tenant will be offline and will not process traffic while performing this procedure. F5 recommends you schedule an appropriate maintenance window to perform this procedure.

  • Using webUI
  • Using CLI
  • Using REST API

Using webUI

  1. Login to the webUI of the VELOS partition or the rSeries system as the administrative user.
  2. To determine the existing size of the allocated MAC address pool for the BIG-IP tenant, navigate to TENANT MANAGEMENT > Tenant Details. Select the name of the tenant for the Tenant Name setting under the Tenant Details section and the webUI returns the state of the tenant. Locate the MAC Pool Size to determine the existing size of the allocated MAC address pool for the tenant.
  3. Navigate to the TENANT MANAGEMENT gt; Tenant Deployments page.
  4. Select the name of the tenant you want to modify.
  5. Select either Configured or Provisioned for the State setting.
  6. Select Save & Close. Select OK to confirm the change. This will shutdown the tenant and bring it offline. The webUI will redirect back to the TENANT MANAGEMENT > Tenant Deployments page.
  7. Select the name of the same tenant again.
  8. Select One/Small/Medium/Large for the MAC Data/MAC Block Size setting as needed.
  9. Select Save & Close. Select OK to confirm the change. The webUI will redirect back to the TENANT MANAGEMENT > Tenant Deployments page.
  10. Select the name of the same tenant again.
  11. Select Deployed for the State setting.
  12. Select Save & Close. Select OK to confirm the change. This will start up the tenant and bring it online. The webUI will redirect back to the TENANT MANAGEMENT > Tenant Deployments page.
  13. To verify the change to the MAC Data/MAC Block Size setting, perform step 2 again.

Using CLI

  1. Login to the CLI of the VELOS partition or the rSeries system as the administrative user.
  2. To determine the existing size of the allocated MAC address pool for the BIG-IP tenant, enter the following command syntax:

    show tenants tenant <tenant name> state mac-data

    For example,

    show tenants tenant mybigiptenant1 state mac-data

    The command should return an output similar to the following example:

    state mac-data base-mac 14:a9:d0:1c:3d:24
    state mac-data mac-pool-size 1
    MAC                
    -------------------
    14:a9:d0:1c:3d:24  

    This example output shows the BIG-IP tenant mybigiptenant1 is currently configured with mac-block-size of one(1)

  3. Enter into the configuration mode by entering the following command:

    config

  4. Set the running-state of the BIG-IP tenant to either configured or provisioned by entering the following command syntax:

    tenants tenant <tenant name> config running-state [configured | provisioned]

    For example,

    tenants tenant mybigiptenant1 config running-state provisioned

  5. Commit the configuration change by entering the following command:

    commit ; top

  6. Modify the mac-block-size setting of the BIG-IP tenant by entering the following command syntax:

    tenants tenant <tenant name> config mac-data mac-block-size [one | small | medium | large ]

    For example,

    tenants tenant mybigiptenant1 config mac-data mac-block-size medium

  7. Commit the configuration change by entering the following command:

    commit ; top

  8. Set the running-state of the BIG-IP tenant to deployed by entering the following command syntax:

    tenants tenant <tenant name> config running-state deployed

    For example,

    tenants tenant mybigiptenant1 config running-state deployed

  9. Commit the configuration change by entering the following command:

    commit ; top

  10. To verify the change to the mac-block-size setting, perform step 2 again. Following the previous example, you should observe the output returned stating that the mac-pool-size is 16 with a list of 16 MAC addresses and a base-mac that is different from when its mac-pool-size was previously set to 1; similar to the following example:

    state mac-data base-mac 14:a9:d0:1c:3d:3f
    state mac-data mac-pool-size 16
    MAC                
    -------------------
    14:a9:d0:1c:3d:3f  
    14:a9:d0:1c:3d:40  
    14:a9:d0:1c:3d:41  
    14:a9:d0:1c:3d:42  
    ...

    Note: The example output is truncated for brevity.

Using REST API

  1. Login to a workstation with curl and jq utilities installed. Alternatively, you can login to the VELOS chassis or the rSeries command line as the root user.
  2. To determine the existing size of the allocated MAC address pool for the BIG-IP tenant, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/state/mac-data

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/state/mac-data

    The command should return an output similar to the following example:

    {
      "f5-tenants:mac-data": {
        "base-mac": "14:a9:d0:1c:3d:24",
        "mac-pool-size": 1,
        "f5-tenant-l2-inline:mac-block": [
          {
            "mac": "14:a9:d0:1c:3d:24"
          }
        ]
      }
    }

    This example output shows the BIG-IP tenant mybigiptenant1 is currently configured with mac-block-size of one(1)

  3. Set the running-state of the BIG-IP tenant to either configured or provisioned by entering the following command syntax:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' -X PATCH https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/config/running-state -d '{"f5-tenants:running-state": "[provisioned | configured]"}'

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X PATCH https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/config/running-state -d '{"f5-tenants:running-state": "provisioned"}'

    The command does not return an output if it is successful; enter the following command to verify the change:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/config/running-state

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/config/running-state

    The command should return an output similar to the following example:

    {
      "f5-tenants:running-state": "provisioned"
    }

  4. Modify the mac-block-size setting of the BIG-IP tenant by entering the following command syntax:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' -X PATCH https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/config/mac-data/f5-tenant-l2-inline:mac-block-size -d '{"f5-tenant-l2-inline:mac-block-size": "[one | small | medium | large]"}'

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X PATCH https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/config/mac-data/f5-tenant-l2-inline:mac-block-size -d '{"f5-tenant-l2-inline:mac-block-size": "medium"}'

    The command does not return an output if it is successful.

  5. Set the running-state of the BIG-IP tenant to deployed by entering the following command syntax:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' -X PATCH https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/config/running-state -d '{"f5-tenants:running-state": "deployed"}'

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X PATCH https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/config/running-state -d '{"f5-tenants:running-state": "deployed"}'

    The command does not return an output if it is successful; enter the following command to verify the change:

    curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' https://<management IP address of the VELOS partition or the rSeries system>/api/data/f5-tenants:tenants/tenant=<tenant name>/config/running-state

    For example,

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' https://localhost/api/data/f5-tenants:tenants/tenant="mybigiptenant1"/config/running-state

  6. To verify the change to the mac-block-size setting, perform step 2 again. Following the previous example, you should observe the output returned stating that the mac-pool-size is 16 with a list of 16 MAC addresses and a base-mac that is different from when its mac-pool-size was previously set to 1; similar to the following example:

    {
      "f5-tenants:mac-data": {
        "base-mac": "14:a9:d0:1c:3d:3f",
        "mac-pool-size": 16,
        "f5-tenant-l2-inline:mac-block": [
          {
            "mac": "14:a9:d0:1c:3d:3f"
          },
          {
            "mac": "14:a9:d0:1c:3d:40"
          },
          {
            "mac": "14:a9:d0:1c:3d:41"
          },
          {
            "mac": "14:a9:d0:1c:3d:42"
          },
          ...
        ]
      }
    }

    Note: The example output is truncated for brevity.
