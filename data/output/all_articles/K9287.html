Known Issue

This is the result of a known issue. When an HTTP pool member responds to a POST request before the entire response is received, some of the HTTP-specific features intended to manage the server response may not work as expected. The following features are affected:

  • Cookie insert persistence

    If a cookie insert persistence profile is applied to the virtual server and the pool member responds to a POST before the entire request is received, a persistence cookie may not be inserted.

  • Redirect rewrites

    If redirect rewrites are configured in the HTTP profile applied to the virtual server, and the pool member responds to a POST before the entire request is received, redirects may not be rewritten.

  • HTTP_RESPONSE iRule event

    If an iRule containing the HTTP_RESPONSE event is applied to the virtual server and the server responds to a POST before the entire request is received, the HTTP_RESPONSE event may not be raised. If the HTTP_RESPONSE event is not raised, the logic encoded in the HTTP_RESPONSE event is not executed for that response.

F5 Product Development tracked this issue as ID 217464 (formerly CR107585) and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or Link Controller release notes.
