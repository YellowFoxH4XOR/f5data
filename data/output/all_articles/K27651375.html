Known Issue

The BIG-IP GTM iRule IP::addr command may fail to match.

This issue occurs when the following condition is met:

  • The BIG-IP GTM iRule IP::addr command is configured to compare addresses with different masks.

For example, the following comparisons return false and fail to match:

  • [IP::addr [IP::client_addr] equals 10.10.50.1/16]
  • [IP::addr [IP::client_addr]/16 equals 10.10.50.1]
  • [IP::addr [IP::client_addr]/16 equals 10.10.50.1/8]

However, a comparison using the same mask, similar to the following example, returns true and matches:

  • [IP::addr [IP::client_addr]/16 equals 10.10.50.1/16]

Impact

BIG-IP GTM iRules using the IP::addr command do not perform as expected.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP GTM iRules that use the IP::addr command do not perform as expected.

Workaround

To work around this issue, you can format IP::addr iRule commands to ensure that the network mask matches for the addresses being compared.

For example:

[IP::addr [IP::client_addr]/16 equals 10.10.50.1/16]

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
