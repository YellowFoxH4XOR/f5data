K000090027: Controller dashboard does not show traffic related metrics

Type
Support Solution
Published
2021-08-15
Updated
2021-08-30
Source
https://my.f5.com/manage/s/article/K000090027

Description

  • I am able to see infrastructure/instance metrics but when viewing service metrics, even though traffic is passing, the controller reports 'No Data'

  • The datapath instance running NGINX Plus shows avrd is running: ps aux | grep avrd

  • When viewing the established connections from avrd, I do not see the expected output with a connection to the controller, similar to:

sudo ss -pt | grep avrd

ESTAB 0    0      10.10.100.21:38148   10.10.100.185:https  users (("avrd",pid=5764,fd=10))

 

  • After enabling nats-tls debug, the following log is observed:

2021/07/22 00:09:21 DEBUG: 10.10.0.186:58006 connecting to server at localhost:4222

2021/07/22 00:09:22 ERROR: 10.10.0.186:58006 failed to connect to server: dial tcp: i/o timeout

 

Environment

  • NGINX Controller 3.18
  • CentOS7
 

Cause

In some environments the default tls timeout of 1s may be too small.
 

 Recommended Actions

  1. Set the tls timeout to a larger value such as 5s (Note: value is base64 encoded)

kubectl -n nginx-controller patch secret/`kubectl get secret | grep nats-tls | sed 's/ .*//'` -p '{"data":{"TIMEOUT_SECONDS":"NQ=="}}'

kubectl delete pod -l app=nats

 

 

Additional Information

To enable nats-tls debug:

 

kubectl -n nginx-controller patch secret/`kubectl get secret | grep nats-tls | sed 's/ .*//'` -p '{"data":{"DEBUG":"dHJ1ZQ=="}}'

kubectl delete pod -l app=nats

 

To view nats-tls logs:

 

kubectl logs -l app=nats -c tls-proxy --tail 1 --follow
