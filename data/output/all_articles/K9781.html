K9781: User sessions may remain active after disconnecting the Windows Mobile SSL VPN client

Topic

The FirePass Windows Mobile SSL VPN client uses the Microsoft Connection Manager API to manage Network Access connections. Due to the design of the Connection Manager API, the user’s VPN session information may remain cached on the Windows Mobile device even after the user disconnects the SSL VPN client. Session caching means that the VPN session can be re-connected without the user having to re-enter authentication credentials. Additionally, the FirePass controller is not notified when the user disconnects the Window Mobile SSL VPN client. As a result, the user’s session remains active in FirePass until the inactivity timeout is reached.

If you have a heavily loaded FirePass controller that supports a large number of Windows Mobile clients, you may want to configure a shorter inactivity timeout value to prevent old Windows Mobile sessions from consuming a high volume of session licenses on the FirePass controller.

Note: For more information about configuring inactivity timeouts, refer to K3106: Configuring server-side session timeouts.
