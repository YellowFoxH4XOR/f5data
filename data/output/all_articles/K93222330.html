K93222330: Aspen Mesh event storage pods may become stuck in CrashLoopBackOff state

Type
Support Solution
Published
2021-12-02
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K93222330

Description

Aspen Mesh event storage pods may become stuck in CrashLoopBackOff state with the following error messages: 

Event logs error message:  error: failed switching to "cassandra": operation not permitted. 
Pods logs error message: failed - error: rpc error: code = Unknown desc = command error: time="xxxx-xx-xxxx:xx:xxx" level=error msg="exec failed: cannot exec a container that has stopped"

Environment

  • OpenShift container platform: 3.x, 4.x
  • Aspen Mesh: 1.6.x, 1.9.x

Cause

By default, the Open Shift Container Platform (OCP) runs containers using an arbitrarily assigned user ID; this is one of the measures OCP platform takes for additional security. However, according to Aspen Mesh's standard design, Aspen Mesh pods have predefined user IDs to run containers. To allow custom or predefined user IDs used by Aspen Mesh pods, you must add anyuid Security Context Constraints (SCC) to the istio-system namespace for successful deployment of Aspen Mesh on OCP.

Recommended Actions

  • Applying default anyuid SCC to system:serviceaccounts:istio-system. This is one of the prerequisites for running AspenMesh on OCP platform. 
  • To avoid failure, OCP admin should review the default values of anyuid SCC. Any customization or alteration to default values may create issue while doing Aspen Mesh deployment. Hence default values should be used only.
