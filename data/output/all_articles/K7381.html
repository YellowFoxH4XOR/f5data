Topic

When the BIG-IP system is communicating with a slow client or server, the BIG-IP system may receive a zero (0) window ACK packet, indicating the client or server's TCP window is closed. When this occurs, the BIG-IP system periodically sends TCP Keep-Alive packets to prompt the client or server to update its TCP window size. By default, the BIG-IP system sends up to eight TCP Keep-Alive packets before sending a TCP reset to the peer system.

This behavior is by design and controlled by the Maximum Segment Retransmission TCP profile setting. The Maximum Segment Retransmission setting specifies the maximum number of data segment retransmissions that the BIG-IP system allows. The default is eight retransmissions.

When the default number of retransmissions is exceeded, TMM resets the TCP connection to avoid resource starvation during a potential denial of service attack.

Adjusting the Maximum Segment Retransmission setting

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Click TCP from the Protocols drop-down menu.
  4. Click the relevant TCP profile.
  5. Update the Maximum Segment Retransmission setting.
  6. Click Update.
