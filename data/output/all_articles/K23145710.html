K23145710: Identifying and removing invalid duplicate device objects on the BIG-IQ system

Type
Knowledge
Published
2019-04-23
Updated
2025-02-06
Applies to
  • BIG-IQ
Source

Topic

You should consider using this procedure under the following condition:

  • Identify if you have duplicate managed device objects in your BIG-IQ configuration
  • Remove duplicate managed device objects from your BIG-IQ configuration if any exists

Description

The BIG-IQ system uses the value contained in the /config/f5-rest-device-id file as the unique identifier for the managed device. This is referred to as the UUID or machine ID. If the file has been modified on a managed device, it can result in the BIG-IQ system managing two duplicate managed device objects for the same device (the two managed device objects are identical except for their UUIDs). This can result in unpredictable behavior as well as intermittent deploy failures. The following are possible actions that could lead to duplicate managed device objects on the BIG-IQ system:

  • You restored a user configuration set (UCS) that has a different /config/f5-rest-device-id file to a managed device. This results in a change to the managed device's f5-rest-id.
  • You modified the /config/f5-rest-device-id file on a managed device.

Some deploys may fail with error messages similar to the following example in the /var/log/restjavad.0.log file on the BIG-IQ system:

[INFO][22 Mar 2018 03:01:06 GMT][/cm/shared/event/alerts AlertCollectionWorker] Deployment Task Notification | | BIG-IQ: iq1.example.com | Module: Network Security | Task Name: test_Eval | Task Status: FAILED | Type: Full | Timestamp: Mar 22, 2018 03:01(GMT) | User: admin | | BIG-IP Devices: | ltm1.example.com: CANCELED - Device is not available | ltm1.example.com: CANCELED - Device is not available |

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the command line on the BIG-IQ system
  • You have administrative access to the command line on the managed device(s)

Procedures

  • Identifying invalid duplicate managed device objects
  • Removing invalid duplicate managed device objects

Identifying invalid duplicate managed device objects

To identify invalid duplicate managed device objects on the BIG-IQ system, you can create two bash functions and run them, then compare the results with the managed device's f5-rest-id. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IQ system
  2. To create the first bash shell script function, list-devices, type the following command:

    list-devices(){ restcurl shared/resolver/device-groups/cm-bigip-allDevices/devices'?$select=address,hostname,machineId,selfLink'; }

    The list-devices bash function returns an abbreviated list of all discovered devices on the BIG-IQ system. 

  3. To create the second bash shell script function, list-dups, type the following command:

    list-dups() { list-devices| grep address | cut -d ':' -f2 | tr -d '",' | sort -n | uniq -c | grep -v -w 1; }

    The list-dups bash function returns IP addresses that show up in more than one object, and the number of instances where the IP addresses were found.

    Note: These two bash functions are temporary functions; they will no longer exist when the BIG-IQ system is rebooted. You will need to re-create them if you require them again.

  4. To identify duplicate managed device objects, type the following command:

    list-dups

    If there are duplicate managed device objects,the command will return an output indicating the number of duplicates for an IP address. The following example shows that there are two managed device objects with the IP address 192.168.0.97:

    2  192.168.0.97

    If there are no duplicate managed device objects, the command will not return any output.

  5. To determine the UUID/machine ID of the duplicate managed device objects, use the following command syntax:

    list-devices | grep -A4 <IP address identified from previous step>

    For example, type the following command:

    list-devices | grep -A4 192.168.0.97

    You should observe an output similar to the following example:

          "address": "192.168.0.97",
          "hostname": "ltm1.example.com",
          "machineId": "5480b771-d0e0-460d-b101-8a1a028a016e",
          "selfLink": "https://localhost/mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices/5480b771-d0e0-460d-b101-8a1a028a016e"
        },
    --
          "address": "192.168.0.97",
          "hostname": "ltm1.example.com",
          "machineId": "934239d7-64eb-42e8-9b4a-a06c2f952eb2",
          "selfLink": "https://localhost/mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices/934239d7-64eb-42e8-9b4a-a06c2f952eb2"
        },

  6. To determine the f5-rest-id of the affected managed device, log in to the command line of the affected managed device and type the following command:

    cat /config/f5-rest-device-id

    The command should return the f5-rest-id of the managed device. For example:

    5480b771-d0e0-460d-b101-8a1a028a016e

  7. When you have determined the f5-rest-id of the affected managed device, you can then identify which managed device object in the BIG-IQ configuration is invalid. Using the example outputs from step 5, the managed device object with machine ID 934239d7-64eb-42e8-9b4a-a06c2f952eb2 is invalid.

Removing invalid duplicate managed device objects

When you have determined the UUID/machine ID of the duplicate managed device objects in your BIG-IQ configuration and the f5-rest-id of the actual managed device, you can remove the invalid duplicate managed device object. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: F5 recommends that you always perform a UCS backup of the BIG-IQ system prior to removing any invalid managed device objects from the BIG-IQ configuration. For more information about BIG-IQ system UCS file backup and restoration, refer to the UCS Backup Management for the BIG-IQ System chapter of the BIG-IQ Centralized Management: Licensing and Initial Setup manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  1. Log in to the command line of the BIG-IQ system.

  2. Set variable with BIG-IP uuid to be removed:
    uuid_to_remove=<f5-rest-device-id>

  3. Set array variable with groups found to contain the uuid:
     groups_with_uuid=($(restcurl shared/index/config?\$filter=uuid%20eq%20%27"${uuid_to_remove}"%27|jq .items[].selfLink | cut -d '/' -f8 | tr -d '"'))

  4. Verify that the array contains one of more groups:
    echo ${groups_with_uuid[@]}
    Note: If nothing is returned the uuid was not found in any device groups

  5. Remove the the uuid from any groups it was found in:
    for group_name in ${groups_with_uuid[@]}; do restcurl -X DELETE shared/resolver/device-groups/${group_name}/devices/${uuid_to_remove}; done
