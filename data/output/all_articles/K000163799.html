K000163799: Static FDB entries for MAC masquerade address not getting removed when tenant is rebooted or restarting

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to

  • BIG-IP
  • F5OS-A
  • BIG-IP LTM: 17.5.X, 17.1.X, 17.5.1, 17.5.0, 17.1.3, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000163799

Description

When an active tenant is rebooted, the static FDB entries for MAC masquerade are not being removed from F5OS, despite the tenant no longer being online and active.

Entries in question are observed in the output of show fdb or docker exec system_fpga tmctl nse_l2.

mac               l2_tag entry_type age ifh.did_en ifh.svc
----------------- ------ ---------- --- ---------- -------
16:A9:D0:A9:7E:20     77          3   0          0      14

Note: An entry_type of 3 indicates a static entry.

As a result of this issue, traffic destined to that MAC address will not leave the system, even if a peer tenant is now active for the MAC masquerade address.

Environment

  • MAC masquerade configured in tenants
  • r5000, r10000, or r12000 appliances
  • FDB entries

Cause

This is a known issue with the static FDB entries for MAC masquerade.

  • Bug ID 1690005: Unable to ping the floating self addresses from the Standby tenant

A related issue:

  • Bug ID 2329957: Stale mac masquerade fdb entries are observed on rSeries devices after killing tmm on the active tenant

Recommended Actions

Upgrading to a tenant version with the fix for ID1690005 and ID2329957 is recommended.

As a workaround, you can remove any lingering static entries with the following command, from bash:

f5sh 'conf; no fdb mac-table entries entry <mac> <vlan id>; commit'

Alternatively, fail over the tenants back to the original active unit, then fail back. The entries should be deleted on transition to standby.

Additional Information

The F5OS platform.log will ordinarily contain a message sequence similar to the following when the tenant triggers deletion of its static FDB entries (for example, on orderly failover):

api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000039 msg="Receive listener request from tenant client" tenant="tenant01" instid=0 listeners_count=0 mac_masq_listeners_count=1.
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000080 msg="Listener mac masq request" vlantag=77 mac="16:a9:d0:a9:7e:20" op=2.
fpgamgr[16]: priority="Info" version=1.0 msgid=0x307000000000032 msg="Deleting static L2 entry." ENTRY="MAC=16:a9:d0:a9:7e:20, NTI=4095, VID=77, Type=1".
api-svc-gateway[12]: priority="Notice" version=1.0 msgid=0x5804000000000082 msg="Network manager mac masquerade reply returned OK" tenant="tenant01" tenantinstance=0 vlantag=77 mac="16:a9:d0:a9:7e:20" op=2.

Those will be absent when this issue occurs.
