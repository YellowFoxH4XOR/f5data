K12251435: Procedure for upgrading DCD with an extended /var partition

Type
Support Solution
Published
2021-10-06
Updated
2026-06-25
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K12251435

Description

This article explains the procedure for Upgrading DCD (Data Collection Device) with an extended /var partition.

Environment

  • Upgrading DCD from non-standard disk partition (Data Retention)
  • DCD devices are active

Cause

Attempt to upgrade DCD device from a non-standard partition while device is active

Recommended Actions

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Root level access to the device

Procedures

Impact of procedure: Disk size allocation will be impacted on all BIG-IQ devices.

In order to address customer's concern of potential data loss (statistics from DCDs) during upgrade we need to remind customer that DCD architecture is based on distributed Elasticsearch (ES) database - DCD device does not store complete database, and shards and indexes are distributed. If we are upgrading DCDs one at a time as done via rolling upgrade or manually, database from upgraded device will be distributed among surviving DCDs.

You can follow the below procedure to upgrade DCD from non-standard partition:

  1. Check what image is installed

  2. Assess current logical sizing

    [root@bigiq-cm1:Active:Standalone] config # lvs --unit=k

    LV VG Attr LSize Pool Origin Data% Move Log Cpy%Sync Convert
dat.log.1 vg-db-sda -wi-ao--- 7168000.00k
dat.maint.1 vg-db-sda -wi-a---- 307200.00k

set.1._var vg-db-sda -wi-ao--- 31002624.00k
set.1.root vg-db-sda -wi-ao--- 450560.00k

    Note: From this we can see that there is just one "set" that will used for boot slot that log, shared and maint partition are shared between boot slots - that is the reason we can share software images and logs between different boot slots.

  3. Assess current physical sizing

    [root@bigiq-cm1:Active:Standalone] config # pvs

    PV VG Fmt Attr PSize PFree
/dev/sda3 vg-db-sda lvm2 a-- 498.50g 423.64g

    We have plenty of free physical space

  4. Expand the /var partition

    The decision was made that we need to expand /var to 50G from 30G

  5. Verify the new partition size:

    [root@bigiq-cm1:Active:Standalone] config # lvs --unit=k

    LV VG Attr LSize Pool Origin Data% Move Log Cpy%Sync Convert

set.1._usr vg-db-sda -wi-ao--- 3452928.00k
set.1._var vg-db-sda -wi-ao--- 50003968.00k <----------------- /var is 50G
set.1.root vg-db-sda -wi-ao--- 450560.00k

  6. Create a new boot slot based on imageplan inside base software ISO

    Just to see what is the plan :
    [root@bigiq-cm1:Active:Standalone] config # imageplan /shared/images/BIG-IQ-6.1.0-0.0.1224.iso

    product BIG-IQ version 6.1.0 build 0.0.1224 (BIGIQ610) selected

Mount point: /var, Size: 10485760k

  7. Create new set we will name it HD1.2

    [root@bigiq-cm1:Active:Standalone] config # addvol HD1.2 /shared/images/BIG-IQ-6.1.0-0.0.1224.iso

info: zero sblock for member device; /dev/vg-db-sda/set.2._var

  8. Verify the creation of the volume set:

set.2._config vg-db-sda -wi-a---- 3321856.00k
set.2._usr vg-db-sda -wi-a---- 3452928.00k
set.2._var vg-db-sda -wi-a---- 31002624.00k <--------- new set is still 30G since imageplan prescribed 30G
set.2.root vg-db-sda -wi-a---- 450560.00k

    [root@bigiq-cm1:Active:Standalone] config #lvs --unit=k

set.2._config vg-db-sda -wi-a---- 3321856.00k
set.2._usr vg-db-sda -wi-a---- 3452928.00k

set.2.root vg-db-sda -wi-a---- 450560.00k

    This concludes prep phase for upgrade. Please note that this needs to be done on CM and all DCDs if we want to expand /var on them.

    Please keep in mind that though we created filesystem, but there is no HD1.2 volume present.

    [root@bigiq-cm1:Active:Standalone] config # tmsh show sys software

    ----------------------------------------------------
Sys::Software Status
Volume Product Version Build Active Status
----------------------------------------------------
HD1.1 BIG-IQ 6.1.0 0.0.1224 yes complete

  11. Install the new image using either the GUI or "create-volume volume HD1.2" while installing new image or EngHF.

    root@(bigiq-cm1)(cfg-sync Standalone)(Active)(/Common)(tmos)# install sys software hotfix Hotfix-BIG-IQ-6.1.0.0.33.1224-ENG.iso create-volume volume HD1.2
    root@(bigiq-cm1)(cfg-sync Standalone)(Active)(/Common)(tmos)# show sys software
