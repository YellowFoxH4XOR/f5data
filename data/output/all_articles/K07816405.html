Known Issue

Attempting to compile the F5-BIGIP-LOCAL-MIB file may fail due to invalid MAX-ACCESS clauses.

The F5-BIGIP-LOCAL-MIB mib file contains two deprecated objects, ltmNodeAddrNewSessionEnable and ltmPoolMemberNewSessionEnable, whose MAX-ACCESS variable is incorrectly specified as write-only. If you refer to RFC 2578 Structure of Management Information Version 2 (SMIv2), it specifies in section 7.3 that the MAX-ACCESS clause may only use one of the following values:

  • not-accessible
  • accessible-for-notify
  • read-only
  • read-write
  • read-create

Impact

You may be unable to compile the F5-BIGIP-LOCAL-MIB file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Third-party mib utilities may report an error when attempting to compile the F5-BIGIP-LOCAL-MIB file.

Workaround

To work around this issue, you can edit the F5-BIGIP-LOCAL-MIB file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

If you encounter an error while attempting to compile the F5-BIGIP-LOCAL-MIB file, you can edit the MIB file and update the two affected variables.

  1. Log in to the BIG-IP command line.
  2. Remount the /usr file system in read-write mode, by typing the following command:

    mount -o remount,rw /usr

  3. Back up the current F5-BIG-IP-LOCAL-MIB.txt file, by typing the following command:

    cp /usr/share/snmp/mibs/F5-BIGIP-LOCAL-MIB.txt /var/tmp/F5-BIGIP-LOCAL-MIB.txt.K07816405.save

  4. Edit the /usr/share/snmp/mibs/F5-BIGIP-LOCAL-MIB.txt file using either the vi or pico text editor.
  5. Locate the following objects within the files: ltmNodeAddrNewSessionEnable and ltmPoolMemberNewSessionEnable.
  6. Change the MAX-ACCESS value from write-only to read-only.
  7. Save your changes.
  8. Remount the /usr file system in read-only mode, by typing the following command:

    mount -o remount,ro /usr

  9. Recompile the MIB file using your MIB compiler.
