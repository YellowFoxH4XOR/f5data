K000163417: How to copy missing zone file from a working BIG-IP DNS device.

Type
Support Solution
Published
2026-10-03
Updated
2026-10-03
Applies to
  • BIG-IP
  • BIG-IP DNS
Source
https://my.f5.com/manage/s/article/K000163417

Description

On BIG-IP DNS, zrd may repeatedly restart or remain down when a BIND zone is configured in named.conf but the referenced zone file is missing or cannot be read by the named service.

Typical log messages include:

zoneload: error: zone <zone>/IN/external:
loading from master file db.external.<zone>. failed: file not found

zoneload: error: zone <zone>/IN/external:
not loaded due to errors

Re-starting zrd

Environment

  • BIG-IP DNS
  • DNS synchronization enabled
  • DNS zone-file synchronization enabled
  • BIG-IP DNS devices configured in the same DNS synchronization group
  • ZoneRunner/BIND zone files

Cause

The affected BIG-IP DNS device contained a BIND zone declaration for which the referenced zone file was not present.

Answer/Recommended Actions

For simplicity, let's say you have 2 BIG-IP DNS devices. Device-A has the working copy of the zone file. Device-B is the device experiencing zrd restart due to missing zone file.

1.) Back up the source file on Device A.

cd /var/named/config/namedb
cp db.external.example.com. db.external.example.com..pre-copy

2.) Prepare Device A and flush its journal.

cd /var/named/config/namedb
bigstart stop zrd
rndc freeze
rndc sync -clean

Then validate the source file. You should see "OK"

named-checkzone example.com. /var/named/config/namedb/db.external.example.com.

3.) On Device B, first preserve any existing file or related configuration, then run:

cd /var/named/config/namedb
bigstart stop zrd
rndc freeze 
rndc sync -clean

4.) Copy the complete file from Device A to Device B. Still on Device A, run:

scp /var/named/config/namedb/db.external.example.com. root@192.168.0.2:/var/tmp/

5.) Check the file if present then move the file into the ZoneRunner directory on Device B:

ls -l /var/tmp/db.external.claims.w-insurance.com.
mv /var/tmp/db.external.example.com. /var/named/config/namedb/db.external.example.com.

6.) Check ownership and permissions. Compare the restored file on Device B with the source file on Device A:

ls -l /var/named/config/namedb/db.external.example.com.

NOTE: All files under /var/named/config/namedb/ should have named:named as ownership and not root:root. If there is root owned, change the owner to named, run:

chown named:named /var/named/config/namedb/*
bigstart restart zrd

7.) Validate the file on Device B. You should see "OK"

named-checkzone example.com. /var/named/config/namedb/db.external.example.com.

Then check all configured zones: 

named-checkconf -j -z -t /var/named

There should be no more missing files.

8.) Thaw the zone and restart ZoneRunner on both devices.

rndc thaw
bigstart start zrd

NOTE: If you encounter this permission denied error below,  check ownership and permissions again.

rndc: 'thaw' failed: permission denied

Additional Information

If the file exists but has incorrect permissions or ownership, the log may report:

zoneload: error: zone <zone>/IN/external:
loading from master file db.external.<zone>. failed: permission denied
