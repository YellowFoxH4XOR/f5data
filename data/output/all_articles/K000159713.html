Description

  • BIG-IP system stopped sending logs to the remote syslog server after a recent system reboot.
  • The syslog server was unable to receive any logs from the F5 device, although there was no impact to business traffic.
  • No changes had been done immediately before the restart either.

 

Environment

  • Remote syslog configuration with local-ip parameter used
  • The configured local-ip address did not correspond to any actual management IP or self-IP on the system

 

Cause

The remote syslog configuration contained an invalid local-ip parameter that referenced an IP address that was not present on the system. While this misconfiguration was present in the pre-reboot configuration, it only took effect when the syslog-ng service restarted during the system reboot. The invalid local-ip prevented the syslog-ng service from properly binding to a valid source address, causing it to fail in sending logs to the remote syslog server.

 

 

Answer/Recommended Actions

  • Remove the invalid local-ip parameter from the remote syslog configuration and either use a valid local-ip or no local-ip definition.
  • If a specific source IP is required for remote syslog, configure the local-ip to use either the management IP address or a valid non-floating, self-IP address that exists on the system.
  • Restart the syslog-ng service to apply the configuration changes:
bigstart restart syslog-ng (this action is non-disruptive to traffic).
  • Monitor the syslog server to confirm logs are being received successfully.
