Known Issue

The AES::decrypt iRule command is unable to decrypt data that was previously encrypted with the same key by the AES::encrypt command. This issue occurs because the ciphertext generated by the AES::encrypt command is stored as a string, rather than a binary object. As a result, the AES::decrypt command is subsequently unable to decrypt the ciphertext.

Impact

iRules using the AES::encrypt and AES::decrypt iRule commands fail to provide expected results.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The iRule that uses the AES::encrypt command to encrypt content may fail to decrypt using the AES::decrypt command.

    For example, the following iRule myaesrule encrypts the content of the variable mycontent using the AES::encrypt command, but fails to decrypt using the AES::decrypt command and logs an empty value for the decrypted variable decryptmycontent in the /var/log/ltm file. The expected value for the variable decryptmycontent is the same as that for variable mycontent:

    rule myaesrule {
    when RULE_INIT {
    set mycontent "plaintext"
    set key "AESkey"
    log local0. "mycontent: $mycontent"

    set mycontentencrypted [AES::encrypt $key $mycontent]
    binary scan $mycontentencrypted H* mycontentinhex
    log local0. "mycontentinhex: $mycontentinhex"

    set decryptmycontent [AES::decrypt $key $mycontentencrypted]
    log local0. "decryptmycontent: $decryptmycontent"
    }
    }

    local/tmm info tmm[4776]: Rule myaesrule : mycontent: plaintext
    local/tmm info tmm[4776]: Rule myaesrule : mycontentinhex: 97009c138228952a0403743876e4078790da0b78652af866d24a6160bf0bf7573a8144abb74efc9ff9f5e60ae8
    local/tmm info tmm[4776]: Rule myaesrule : decryptmycontent:

Resolution

Status

F5 Product Development has assigned ID 242479 (formerly CR134048) to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release10.2.0K2200: Most recent versions of F5 software
HotfixNoneNone

Important: Although this issue is fixed in BIG-IP 10.2.0, a separate issue for the AES::decrypt iRule command is currently not fixed. Therefore, you may not be able to decrypt ciphertext from AES::encrypt iRule command properly. For more information, refer to K12944: The AES::decrypt iRule command does not work across TMM or after a failover or reboot.

Workaround

If you are performing HTTP cookie encryption/decryption operations in the iRule, you may be able to work around this issue by using the following alternative methods:

  • Using the HTTP::cookie encrypt and HTTP::cookie decrypt iRule commands
  • Use the Encrypt Cookies feature in the HTTP profile (available in BIG-IP 9.4.0 and later)

To do so, perform the following procedures:

Using the HTTP::cookie encrypt and HTTP::cookie decrypt iRule commands

Impact of Workaround: Performing the suggested workaround should not have a negative impact on your system.

Replace the AES::encrypt and AES::decrypt iRule commands with the HTTP::cookie encrypt and HTTP::cookie decrypt iRule commands respectively. For more information on the syntax and usage of HTTP::cookie encrypt and HTTP::cookie decrypt iRule commands, refer to the DevCentral Encrypting Cookies codeshare page. Note: A DevCentral login is required to access this content.

Using the Encrypt Cookies feature in the HTTP profile

Impact of Workaround: The HTTP profile Encrypt Cookies feature may not offer the customizable AES key length, which may not meet the encryption strength you require.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Click on the HTTP profile associated with the virtual server that is using the affected iRule.
  4. Select the Encrypt Cookies check box.
  5. Type in the name of the cookie you want to encrypt.
  6. Select the Cookie Encryption Passphrase check box.
  7. Type in the passphrase you want to use to encrypt the cookie.
  8. Select the Confirm Cookie Encryption Passphrase check box.
  9. Retype the passphrase you want to use to encrypt the cookie.
  10. Click Update.
