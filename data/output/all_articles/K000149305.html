Description

After upgraded and booted, the BIG-IP stays offline.  The config is not loaded (no virtuals, no pools, etc on GUI).

Checking /var/log/ltm, after booted, the similar to below warning and error message can be seen:

warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Traditional_Religions to /Common/Widely_Known_Religions in allowed categories of url filter <URL_Filter_object_name>
warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Non-Traditional_Religions to /Common/Lesser_Known_Religions in allowed categories of url filter <URL_Filter_object_name>
warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Society_and_Lifestyles to /Common/Human_Interests in allowed categories of url filter <URL_Filter_object_name>
warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Illegal_or_Questionable to /Common/Illegal_or_Unethical in blocked categories of url filter <URL_Filter_object_name>
warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Gay_or_Lesbian_or_Bisexual_Interest to /Common/LGBTQIA in blocked categories of url filter <URL_Filter_object_name>
err mcpd[<PID>]: 01070734:3: Configuration error: In url-filter (<URL_Filter_object_name>), you can include category number <Category_name> only once. This category number is entered in both allowed-categories and blocked-categories.
err mcpd[<PID>]: 0107142f:3: Can't connect to CMI peer 192.255.255.2, TMM outbound listener not yet created
err tmsh[<PID>]: 01420006:3: Loading configuration process failed.

Environment

  • BIG-IP
  • Secure Web Gateway (SWG) Module Provisioned
  • URL-Filter Category List object configured

Cause

  • BUG ID 1786769

    /Common/Society_and_Lifestyles was renamed to /Common/Human_Interests
    /Common/LGBTQIA was renamed to /Common/Gay_or_Lesbian_or_Bisexual_Interest
    /Common/Illegal_or_Unethical was renamed to /Common/Illegal_or_Questionable

Recommended Actions

Option 1: If you can revert back to previous version, please revert it back, and then consider the following configuration change to avoid after upgrade you have same category in both allowed and blocked categories on GUI.

Example 1

apm url-filter /Common/Custom_Tenant_URLfilter {
   allowed-categories { ... /Common/Society_and_Lifestyles ... }
   blocked-categories { ... /Common/Human_Interests ... }
}

In this case, when it is upgraded, both categories has "Human_Interests", as the below warning message tells:

warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Society_and_Lifestyles to /Common/Human_Interests in allowed categories of url filter <URL_Filter_object_name>

So consider to remove

  • "Society_and_Lifestyles" from allowed-categories

Or

  • "Human_Interests" from blocked-categories.

 

Example 2

apm url-filter /Common/Test_URLfilter {
   allowed-categories { ... /Common/Gay_or_Lesbian_or_Bisexual_Interest ... /Common/LGBTQIA ... }
   blocked-categories { ... /Common/Illegal_or_Questionable ... /Common/Illegal_or_Unethical ... }
}

in above examples, it will have duplicate entry for "LGBTQIA" and "Illegal_or_Unethical" in each categories, as the below warning messages tell:

warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Illegal_or_Questionable to /Common/Illegal_or_Unethical in blocked categories of url filter <URL_Filter_object_name>

warning mcpd[<PID>]: 0107185a:4: Warning generated, for version 15.1.0 or greater : Category name changed from /Common/Gay_or_Lesbian_or_Bisexual_Interest to /Common/LGBTQIA in blocked categories of url filter <URL_Filter_object_name>

So remove

  • "Gay_or_Lesbian_or_Bisexual_Interest" from allowed categories

AND

  • "Illegal_or_Questionable" from blocked-categories

Once config change is done, boot from new version location with setting "Installation Configuration" to "Yes" (as the the already installed location does not have the config change you did above)

 

Option 2: If you prefer to modify config manually while you are on new version, make a backup for /config/bigip.conf (and /config/partitions/<partition_name>/bigip.conf if you have partition and in partition you created URL filtering)

NOTE: This is recommended who is confident on modifying config manually with text editor. 

Using text editor modify the config as you need following the examples in the Option 1.

Once change is saved, then run the below command to verify your change is good.

tmsh load sys config verify
NOTE: warning may appear but warning can be ignored. ERROR is the one to check.

If there is no errors, then load config by running the below command

tmsh load sys config
