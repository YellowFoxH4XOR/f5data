Description

In GSLB, when removing a pool member(vs) from the pool or removing this vs from virtual server list in server while the status of this member was disabled, there would be a log in /var/log/gtm showing that this member was enabled.

For example:

gtm pool a /Common/pool {
    members {
        /Common/Server_1.1:vs_1 {
            disabled
            member-order 0
        }
        /Common/Server_1.1:vs_2 {
            member-order 1
        }
    }
}

Removing this member vs_1 from pool_1 or remove vs_1 from Server virtual server list, there will be a message logged like below in /var/log/gtm.

May 10 19:40:29 dns-log.bigip alert gtmd[8573]: 011a4005:1: SNMP_TRAP: Pool (/Common/pool) member (1.1.1.1:80) enabled

Environment

  • BIG-IP DNS
  • GSLB
  • Disabled pool member

Cause

It is our design. GTM enables pool members before deleting them. These logs are trivial when debugging and can be ignored in this case.

Recommended Actions

None

Additional Information

In LTM module, when deleting a pool member while the status is disabled, there has no such log occurrence.
