K8660: Static routes may be removed from Linux host routing table when overlapping matching virtual server addresses are created

Known Issue

This is the result of a known issue. If a virtual server address matches a static route, the tmrouted process may remove the static route from the Linux host route table.

This issue occurs when the tmrouted process parses the virtual address for route health injection, regardless of whether route health injection is configured. If the tmrouted process determines the virtual address should not be injected, it sends the delete signal to remove route. If the virtual address matches a defined static route, the tmrouted process ends up deleting the static route from the Linux host route table.

F5 Networks Product Development tracked this issue as CR94729 and it was fixed in BIG-IP version 9.4.4. For information about upgrading, refer to the BIG-IP LTM, ASM, and Link Controller Release Notes.

Workaround

If upgrading is not an immediate option, you can work around this issue by using one of the following two methods:
  • If dynamic routing is used, change the subnet of either the virtual server or the affected static route so they do not match.
  • If dynamic routing is not used, remove the tmrouted process from the bigstart startup list. To do so, perform the following procedure:
    1. Log in to the command line.
    2. Stop the tmrouted process by typing the following command:

      bigstart stop tmrouted
    3. Remove the tmrouted process from the bigstart startup list by typing the following command:

      bigstart remove tmrouted
