Known Issue

The BIG-IP system may continue to generate server-side TCP connections to pool members after the associated virtual server configuration is deleted.

This issue occurs when all of the following conditions are met:

  • The configuration contains a Performance HTTP virtual server that references the base FastHTTP profile.
  • The Performance HTTP virtual server processes at least one connection before being deleted.
  • The Performance HTTP virtual server configuration is removed.

To improve connection speeds for Performance HTTP virtual servers, the BIG-IP system primes connections to the pool members. When a client makes a connection to the virtual server, if an existing server-side flow to the pool member is idle, the BIG-IP LTM system marks the connection as non-idle and sends the client request over it.

Impact

A possible resource impact may affect the BIG-IP system or pool members.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Packet traces show the BIG-IP system connecting to pool members from its non-floating self IP address.
  • The BIG-IP connection table includes an entry showing the recurring connections. In the following example, the any6.any connection table entry represents the client-side IP address, and 10.11.16.221 is the BIG-IP self IP address:

    any6.any any6.any 10.11.16.221:44321 10.11.16.253:80 tcp 9 (tmm: 0)

Workaround

To work around this issue and prevent the BIG-IP system from incorrectly generating server-side TCP connections to pool members, perform one of the following procedures:

Deleting the pool object

You can work around this issue by deleting (or deleting and then creating) the pool object that was referenced by the performance HTTP virtual server.

Impact of workaround: The pool object may be referenced by other virtual servers on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click the pool object that was referenced by the performance HTTP virtual server.
  5. Click Delete.

Restarting the Traffic Management Microkernel (TMM) process

You can work around this issue by restarting the TMM process.

Impact of workaround: Restarting the TMM process temporarily interrupts traffic processing on the BIG-IP system.

  1. Log in to the command line.
  2. Enter the following command:

    bigstart restart tmm
