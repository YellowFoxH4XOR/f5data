K000140067: Shutting down Active VELOS system controller's management port causes loss of connectivity to Standby controller's management IP

Published

Updated

Applies to

  • F5OS-C: 1.6.X, 1.5.X, 1.6.2, 1.6.1, 1.6.0, 1.5.1, 1.5.0
Source

Description

When the Active VELOS system controller's management port is disabled or down, I lose access to the Standby system controller's management IP as well, even though its management port is UP.

Is this expected?

Environment

  • VELOS system controllers
  • Management port
  • Management connectivity

Cause

This is expected. All management traffic for a VELOS chassis goes out of the management interface of the active controller.

Furthermore, when an active controller's management interface goes down, a controller failover should be triggered.

In some cases the failover may not be triggered due to the system redundancy configuration:

VEL410-R80-S40-1-active# show running-config system redundancy
system redundancy config mode prefer-1                          <--- 
system redundancy nodes node controller-1
 config name controller-1
!
system redundancy nodes node controller-2
 config name controller-2
!

With the above example configuration, failover will not be triggered if the active controller-1's management link goes down. This is undesired in most cases, and may result in loss of access to the VELOS chassis.

Recommended Actions

Ensure system redundancy config mode is set to auto. This is appropriate for the vast majority of deployments.

Additional Information

The behaviour described in this article is applicable when the management ports are non-aggregated. This is the default configuration.
