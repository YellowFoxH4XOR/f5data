Known Issue

This is the result of a known issue. In the BIG-IP version 10.x software branch, F5 modified the algorithm for choosing a swap partition. As a result of this change, the following BIG-IP platforms running versions 10.1.0 or 10.2.0 may incorrectly use the CompactFlash (CF) card for the swap partition:

Note: This issue only affects systems formatted with the logical volume management (LVM) disk formatting scheme. For more information about determining the disk-formatting scheme used by a BIG-IP version 10.x system, refer to K10817: Determining the disk-formatting scheme used by a BIG-IP version 10.x system.

Note: This issue only affects BIG-IP software versions 10.1.0 and 10.2.0 running on the following platforms:

  • 3600 (C103)
  • 3900 (C106)
  • 6900 (D104)
  • 8900 (D106)
  • 8950 (D107)
  • 11050 (E102)
  • VIPRION (PB100, PB200)

In most cases, the BIG-IP system does not frequently write to the swap partition. However, under heavy load the system may swap memory to disk more often, possibly resulting in corruption of the CF drive.

Note: A high number of writes to a CF card (hda*) may eventually corrupt the flash memory on the drive.

To determine if your system is using the CF card for the swap partition, enter the following command:

cat /proc/swaps

The following command output indicates that the system is using the CF card for the swap partition (the hda* device indicates the CF card).

Filename Type Size Used Priority
/dev/hda2 partition 1048312 0 -1

In addition, if your system is using the CF card for the swap partition, error messages may be logged to the kern.log file that appear similar to the following example :

warning kernel: hda: task_in_intr: status=0x51 {DriveReady SeekComplete Error }
warning kernel: hda: task_in_intr: error=0x44 {DriveStatusError UncorrectableError }, LBAsect=288798, sector=288798
warning kernel: ide: failed opcode was: unknown
warning kernel: end_request: I/O error, dev hda,sector 288798
alert kernel: Read-error on swap-device(3:0:288800)

F5 Product Development tracked this issue as ID 341414, and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

You can work around this issue by forcing sysinit to use the swap partition on the hard drive on the next boot. To do so, perform the following procedure:

Note: You only need to perform this workaround once on any slot.

  1. Log in to the command line.

    Note: For VIPRION systems with two or more blades, you must stop the csyncd process on all blades by running the clsh bigstart stop csyncd command.
  2. To locate the swap partition in use, type the following command:

    cat /proc/swaps

    If the command output indicates hda*, the system is using the CF card as the swap partition.

    For example:

    Filename Type Size Used Priority
    /dev/hda2 partition 1048312 0 -1
  3. Type the following fdisk command, specifying the CF device:

    fdisk /dev/hda

    Output will appear similar to the following example:

    The number of cylinders for this disk is set to 16383.
    There is nothing wrong with that, but this is larger than 1024,
    and could in certain setups cause problems with:
    1) software that runs at boot time (e.g., old versions of LILO)
    2) booting and partitioning software from other OSs
    (e.g., DOS FDISK, OS/2 FDISK)

    Command (m for help):
  4. At the Command prompt, type p to list the partition table of the CF, and identify the swap partition. For example:

    Command (m for help): p

    Output will appear similar to the following example:

    Disk /dev/hda: 8455 MB, 8455200768 bytes
    16 heads, 63 sectors/track, 16383 cylinders
    Units = cylinders of 1008 * 512 = 516096 bytes

    Device Boot Start End Blocks Id System
    /dev/hda1 * 1 219 110375+ b W95 FAT32
    /dev/hda2 220 2299 1048320 82 Linux swap / Solaris
    /dev/hda3 2300 16382 7097832 8e Linux LVM

    Command (m for help):

    Note: In this example, /dev/hda2 is the swap partition.
  5. At the command prompt, type t to change a partition's system ID. For example:

    Command (m for help): t
  6. At the Partition number prompt, type the partition number that corresponds to the swap partition.

    For example:

    Partition number (1-4): <partition#>

    For example, if the swap partition resides on /dev/hda2, you would enter:

    Partition number (1-4): 2
  7. At the Hex code prompt, change the partition's system ID to 0 (zero). This configuration will make the CF card unsuitable for usage as a swap partition on next boot. For example:

    Hex code (type L to list codes): 0
    Changed system type of partition 2 to 0 (Empty)

    Command (m for help):
  8. At the Command prompt, type w to write the partition table to disk. For example:

    Command (m for help): w

    Output will appear similar to the following example:

    The partition table has been altered!

    Calling ioctl() to re-read partition table.

    WARNING: Re-reading the partition table failed with error 16: Device or resource busy.
    The kernel still uses the old table.
    The new table will be used at the next reboot.
    Syncing disks.
  9. From the bash prompt, reboot the system by typing the following command:

    reboot
  10. Once the system has rebooted, verify that the swap partition is now using the hard drive by typing the following command:

    cat /proc/swaps

    For example, the following command output indicates that the system is using the /dev/sda2 device (hard drive) as the swap partition:

    Filename Type Size Used Priority
    /dev/sda2 partition 1044216 0 -1
