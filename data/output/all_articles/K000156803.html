When deploying NGINX or NGINX Plus in production, it's important to reduce the system's attack surface and protect against misuse, misconfiguration, and known attack methods. The industry standard for this process is the CIS NGINX Benchmark.

In this context, hardening means reducing the attack surface by disabling features you don't need, tightening default settings, and enforcing stricter policies. This differs from general security practices such as patching vulnerabilities, enforcing authentication, or encrypting data. Security is the overall strategy; hardening is the tactical process of removing weak points so there's less for attackers to exploit.

The CIS Benchmark provides prescriptive guidance across several key areas:

  • Initial setup: Proper installation and software updates.
  • Basic configuration: Minimizing unnecessary modules, securing accounts, permissions, and network settings.
  • Logging: Enabling and protecting detailed access and error logs.
  • Encryption: Configuring TLS/SSL securely, enforcing strong ciphers, and using features like HSTS and OCSP stapling.
  • Request filtering and restrictions: Limiting request methods, sizes, and rates; applying access controls.
  • Browser security headers: Enforcing headers such as X-Frame-Options, CSP, and Referrer Policy.
  • Mandatory access control: Applying system-level protections for NGINX processes and files.
