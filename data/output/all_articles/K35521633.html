Description
Application connection timeouts occur when Loose Initiation is enabled and SYN cookies are activated. Disabling SYN cookie protection prevents timeouts.

This occurs when the connection goes idle for long enough for BIG-IP to delete the connection, then the client tries to continue using the connection.

Environment

  • FastL4 profile with:
    • SYN cookie protection enabled 
      (hardware or software)
    • Loose Initiation enabled
    • Reset on Timeout disabled
  • SYN cookie protection activated
  • client attempts to resume idle (but not closed) connection
    • connection goes idle (from BIG-IP perspective) longer than the FastL4 idle timeout

Cause
When SYN cookies are activated, BIG-IP is forced to translate the sequence space between server side and client side. If the connection times out and is deleted, BIG-IP no longer has a record of how to translate the sequence space for it.

When the client tries to resume communications using the deleted connection, Loose Initiation allows this but the server does not recognize the sequence numbers the client uses. The connection will either fail immediately or hang until it times out on server or client, depending on endpoint behavior.

Recommended Actions

Disable SYN cookie protection for all FastL4 profiles using Loose Initiation.
