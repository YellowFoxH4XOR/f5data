K000162324: CrowdStrike Falcon Sensor 7.39 on BIG-IP fails to download files

Description

After the CrowdStrike Falcon sensor on a BIG-IP system reaches version 7.39 or later, the sensor fails to download some files from the CrowdStrike cloud. This occurs on BIG-IP deployments where the sensor was installed using a version of the install.sh script that was downloaded before July 21, 2026.

You can encounter this in either of the following situations:

  • The sensor was installed with an earlier version and later updated to 7.39 by a CrowdStrike sensor update policy.
  • A new installation was performed with a falcon-sensor 7.39 RPM.

When the issue occurs, you observe the following symptoms:

  • The Falcon sensor fails to retrieve files from the CrowdStrike cloud.
  • The systemd journal and /var/log/daemon.log contain download errors similar to the following:
err falcon-sensor[42]: CrowdStrike(21): Failed download with status 0xc0000103; wrote 268 bytes @ 0

Note: The process ID, byte count, and offset in the message vary. The significant part is the specific status code.

 

Environment

  • BIG-IP
    • BIG-IP Virtual Edition (VE)
    • BIG-IP on iSeries or VIPRION systems
    • BIG-IP as a virtual clustered multiprocessing (vCMP) guest on iSeries or VIPRION systems
    • BIG-IP as an F5OS tenant on rSeries or VELOS systems
  • The CrowdStrike Falcon sensor was installed on the BIG-IP using a version of the install.sh script prior to v2.0, which you can identify from the version comments at the top of the script (obtained before July 21, 2026). Version 2.0 and later of the script are not affected.
  • The Falcon sensor is running version 7.39 or later.

Note: This issue does not apply to Falcon sensor installations on the rSeries or VELOS F5OS host, which are performed with the f5os_install.sh script.

 

Cause

Installation of CrowdStrike Falcon sensor on BIG-IP using install.sh script prior to v2.0 (downloaded before July 21, 2026) created /opt/CrowdStrike as a symbolic link, which causes issues with sensor version 7.39 or later. You can identify the script version from the version comments at the top of the script.

 

Answer/Recommended Actions

First determine whether the deployment requires mitigation/migration, then choose one of the resolution options. F5 recommends migrating any existing symbolic-link installation (Option 1), which requires a system reboot.

Determine whether migration is required

F5 recommends that any existing BIG-IP installation be migrated if the initial install was done using a version of the install.sh script prior to v2.0. Migrating proactively resolves the download failures if the sensor is already on 7.39, and prevents them if the sensor updates to 7.39 later.

  1. Log in to the BIG-IP command line as root.
  2. Determine whether the deployment is affected by checking whether /opt/CrowdStrike is a symbolic link:

    if [ -e /opt/CrowdStrike ]; then [ -L /opt/CrowdStrike ] && echo "Migration required" || echo "No migration needed"; fi

    If the command prints Migration required, /opt/CrowdStrike is a symbolic link and you should migrate using Option 1.

    If the command prints No migration needed, the deployment is not affected and no action is required.

Note (optional): To determine whether the sensor is currently affected, confirm the running sensor version. A Falcon sensor running version 7.39 or later on the symbolic-link layout exhibits the download failures described above. Regardless of the current version, F5 recommends migrating any symbolic-link deployment.

/opt/CrowdStrike/falconctl -g --version

Option 1: Migrate to the bind-mount layout (recommended)

Impact of migration: The recommended migration stages the change through systemd units and does not modify the running sensor. The conversion completes only after you reboot the BIG-IP. Choose a maintenance window accordingly.

This is the recommended option for any existing installation. It converts the deployment, which resolves the download failures if the sensor is already on version 7.39 or later, and prevents them if the sensor updates to 7.39 later. It keeps the sensor on its current version.

  1. Obtain the migrate.sh script as described in K000156881: Install Falcon sensor for F5 BIG-IP on the BIG-IP system or F5 hardware platforms, and place it in the /shared/images/ directory on the BIG-IP system.
  2. Make the script executable:

    chmod 744 /shared/images/migrate.sh

  3. Run the script:

    /shared/images/migrate.sh

    For chassis systems, run the script on all active blades:

    clsh /shared/images/migrate.sh

    Note: The script stages the migration only. It does not change the running sensor or the existing /opt/CrowdStrike symbolic link.

  4. Reboot the BIG-IP system to complete the migration. The conversion occurs during the next boot, when the sensor is not yet running. On a chassis system, follow your standard procedure to reboot the blades.
  5. After the system returns to service, confirm that /opt/CrowdStrike is now a bind mount:

    mountpoint /opt/CrowdStrike

    The command reports that /opt/CrowdStrike is a mountpoint, confirming the migration is complete.

Option 2: Uninstall and reinstall the Falcon sensor

  1. Uninstall the sensor using the uninstall.sh script as described in K000156881.
  2. Reinstall the sensor following K000156881 using the current version of the install.sh script.

Option 3: Downgrade to an earlier Falcon sensor version

If you cannot migrate immediately, you can return the sensor to an earlier supported version that is compatible with the symlink-based layout. Work with your Falcon administrator to downgrade the sensor.

Note: This is an interim measure. Unless the CrowdStrike sensor update policy is set so that it does not update the sensor to 7.39 again, the sensor can return to 7.39 and the issue can recur.

 

Additional Information

  • The version of the sensor RPM you installed may differ from the version currently running, because a CrowdStrike sensor update policy can update the sensor after installation. Confirm the running version with /opt/CrowdStrike/falconctl -g --version.
  • New installations performed with the updated install.sh script use the bind-mount layout and are not subject to this issue.
  • For the supported BIG-IP, F5OS, and Falcon sensor version combinations, refer to the compatibility matrix in K000157015: Getting started with Falcon sensor for F5 BIG-IP.
  • The install.sh, uninstall.sh, and migrate.sh scripts are authored by F5 Support. Maintenance and F5 Technical Support of these scripts is provided only if the software is unmodified.
