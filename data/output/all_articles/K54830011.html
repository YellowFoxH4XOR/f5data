Topic

This solutions article is intended for customers using F5 Fraud Protection Service (FPS) with the legacy WebSafe Alert Dashboard. F5 Technical Support will cease technical support of the WebSafe Alert Dashboard as of July 8, 2019, and all customers using the legacy WebSafe Alert Dashboard will need to migrate their dashboard data to the FPS Alert Dashboard in the BIG-IQ system.

Note: For more information, refer to K17300323: End of Sale announcement for WFP dashboard.

The F5 FPS development team has developed a plan for migrating the following types of data from the WebSafe Alert Dashboard to the FPS Alert Dashboard in the BIG-IQ system:

  • Signatures (BIG-IQ Alert Transform Rules)
  • Notifications (BIG-IQ Alert Forwarding Rules)
  • User profiles
  • Customer accounts

Note: Dashboard alerts cannot be migrated from the legacy WebSafe Alert Dashboard to the FPS Alert Dashboard in the BIG-IQ system. If you want to access dashboard alerts, F5 recommends that you continue to view them in the WebSafe Alert Dashboard or export them to a .csv file.

Important: F5 recommends performing the outlined migration tasks at a time where the selected BIG-IQ device is under minimal load. For WebSafe Alert Dashboard versions prior to 4.0, the migration can take up to a few hours.

Description

Prerequisites

  1. You have access to your current WebSafe Alert Dashboard.
  2. Your BIG-IQ system is installed with version 6.x, and the system has been configured for FPS.

    Note: For instructions on configuring BIG-IP FPS on the BIG-IQ system, refer to the Fraud Protection Service chapter of the BIG-IQ Centralized Management manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  3. You have contacted F5 Technical Support and downloaded the following required migration scripts and requirements.txt files. 
    • exportAS.py
    • importBigIQ.py
    • requirements.txt

      Important: If you want to migrate notifications (Alert Forwarding Rules) that are configured to forward to the cloud dashboard (F5 WebService in the WebSafe Dashboard), you must configure the WebService of the BIG-IQ system prior to performing the data migration procedures.

Procedures

To migrate dashboard data to the FPS Alert Dashboard in the BIG-IQ system, perform all of the following procedures:

  • Exporting WebSafe Alert Dashboard data
  • Importing WebSafe Alert Dashboard data into the BIG-IQ system

Exporting WebSafe Alert Dashboard data

  1. Upload the requirements.txt and exportAS.py files to a common directory on the WebSafe Alert Dashboard server.
  2. Log in to the command line on the WebSafe Alert Dashboard.
  3. To update the WebSafe Alert Dashboard server’s repositories and list the changes, type the following command:

    sudo apt update 

  4. To install python-pip on the WebSafe Alert Dashboard server, type the following command:

    sudo apt install python-pip 

  5. To verify that pip is installed on the server, type the following command:

    pip --version

  6. In the directory where the requirements.txt and exportAS.py files were previously uploaded, type the following command:

    sudo pip install -r requirements.txt

  7. Type the following command in the directory where the requirements.txt and exportAS.py files were previously uploaded:

    python exportAS.py

    Note: This script will create the following .csv files in the /tmp directory:

    • users.csv
    • accounts.csv
    • notifications.csv
    • signatures.csv
  8. To change directories to /tmp, type the following command:

    cd /tmp

  9. Copy all four .csv files to the BIG-IQ system in a common directory.
  10. Copy the importBigIQ.py file to the same directory as the .csv files.

Importing WebSafe Alert Dashboard data into the BIG-IQ system

  1. Log in to the command line of the BIG-IQ system.
  2. In the directory where you put the importBigIQ.py file, type the following command:

    python importBigIQ.py

  3. To check the result_log.txt file to see if any errors occurred, type the following command:

    more result_log.txt

  4. The BIG-IQ System Administrator should set new passwords for all users and notify them of the new password.

    Important: The script generates new passwords that are unknown even to the BIG-IQ system administrator. Therefore, the system administrator needs to reset all passwords to complete the data migration procedure. The old passwords from the WebSafe Alert Dashboard are not migrated. To reset your passwords, refer to the Role-Based User Access chapter of the BIG-IQ Centralized Management: Authentication, Roles, and User Management manual.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  5. For migrating from WebSafe Alert Dashboard version 4.2.x only, create a schedule to download Alert Transform Rules from the SOC.

    Note: For more information, refer to the Configuring How BIG-IQ FPS Processes Alerts chapter of the BIG-IQ Centralized Management BIG-IQ Centralized Management: Fraud Protection Service manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Limitations

  1. User profiles and customer accounts that start with digits (e.g. 1Bob) cannot be migrated because the BIG-IQ system does not support this.
  2. Notifications (Alert Forwarding Rules) that are configured for SMS forwarding in the WebSafe Alert Dashboard cannot be migrated because the BIG-IQ system does not support SMS forwarding.
  3. When migrating notifications for email forwarding, the sender email address is not migrated, and this field will need to be entered manually for each signature  that is configured for email forwarding.
  4. When migrating notifications with a Custom WebService, the following settings are not migrated to the BIG-IQ system:
    • WS Token Headers
    • WS Alert Headers
    • WS Alert Response.
  5. When migrating notifications for syslog forwarding, only notifications with an actual IP address for the server name are migrated. Notifications with a domain name assigned for the server name are not migrated.
  6. Signatures (Alert Transform Rules) with invalid regex statements (for example: aa**) cannot be migrated.
  7. When migrating user profile data, the following fields that exist in the WebSafe Alert Dashboard cannot be migrated:
    • Timezone
    • Display alerts from last days
    • Dashboard Tabs
  8. For users of older versions of the WebSafe Alert Dashboard (prior to 3.9), some notifications and signatures may look slightly different in the BIG-IQ system. They will be automatically adapted to the latest format, and any deprecated fields will be removed. This change will have no effect on their operation.
