Known Issue

This is the result of a known issue. After you power cycle or perform a full box reboot on the standby unit in a high availability (HA) pair that is configured to use serial failover, the standby unit briefly attempts to become active before resuming standby status. When this occurs, the active unit changes its status to standby for approximately 8 seconds, and then becomes active again. As a result, traffic may be briefly interrupted after the standby system fails over or reboots.

Note: This issue is known to affect the BIG-IP 1500 platform.

F5 Product Development is tracking this issue as ID 346140.

Workaround

BIG-IP 10.1.0 and later

You can work around this behavior for a planned power cycle or full box reboot by temporarily increasing the failover timeout to 10 seconds on the active system before you power cycle or full box reboot the standby system. To do so, perform the following procedure:

Impact of workaround: Increasing this parameter prolongs the time required for the BIG-IP redundant system to initiate a failover.

  1. Log in to the active BIG-IP system command line.
  2. Set the failover timeout to 10 seconds by typing the following command:

    bigpipe db Failover.NetTimeoutSec 10

  3. Perform a full box reboot, or a power cycle, on the standby system as needed.

    Wait for the standby system reboot to complete.

  4. Reset the active system's failover timeout to the default value of 3 seconds by typing the following command:

    bigpipe db Failover.NetTimeoutSec 3

BIG-IP 10.0.x

In versions prior to BIG-IP 10.1.0, you can work around this issue by removing the serial failover cable from the HA pair and configuring the pair to use network failover only. For more information about configuring network failover, refer to the Network Failover section of K11736: Defining network resources for BIG-IP high availability features (9.x - 10.x).
