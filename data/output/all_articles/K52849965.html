K52849965: A BIG-IP device can only be managed by a single BIG-IQ deployment

Type
Knowledge
Published

Updated

Applies to

Source

Topic

This article covers the single trust relationship maintained between a BIG-IQ deployment and a BIG-IP system. It also covers the various log messages that you may observe if the trust is broken.
 

Description

You can manage a BIG-IP device only by a single BIG-IQ deployment. The deployment can be either a standalone BIG-IQ or a BIG-IQ HA pair; therefore, you cannot deploy a separate BIG-IQ system and concurrently manage the same BIG-IP device. This is by design because the BIG-IQ establishes a trust relationship with the BIG-IP system. If you add a managed BIG-IP system into the inventory of another BIG-IQ device, the original trust relationship is broken, as demonstrated in the following example logs:

Messages in the /var/log/restjavad.*.log log files on the separate BIG-IQ device show the trust relationship is established with the BIG-IP system:

[INFO][15 Nov 2019 10:37:06 PST][/shared/device-discovery-tasks DeviceDiscoveryTaskCollectionWorker] On device 10.154.210.206, patched device-group cm-bigip-allBigIpDevices key pair. That device can no longer communicate with devices using the old key.

Messages in the /var/log/restjavad.*.log log files on the original BIG-IQ show it losing connectivity with the BIG-IP system and the authorization failures.

  • [INFO][15 Nov 2019 10:38:36 PST][/cm/shared/eventsource/device-state DeviceStateEventWorker] device: bigip13-1.askf5team.local not available for one cycle
  • [INFO][15 Nov 2019 10:40:36 PST][/cm/shared/eventsource/device-state DeviceStateEventWorker] device: bigip13-1.askf5team.local not available for two consecutive cycles, sending availability event
  • [WARN][15 Nov 2019 10:40:36 PST][/cm/shared/event/alerts AlertCollectionWorker] Managed device bigip13-1.askf5team.local (10.154.210.206:443) marked unavailable
  • [ERROR][15 Nov 2019 10:47:11 PST][/cm/shared/tasks/discover-config/6468a0b1-f0ff-4ca3-aa40-c605624c8722/worker SharedModuleDiscoveryTaskWorker] Error getting resource provisioning from /mgmt/tm/sys/provision on bigip13-1.askf5team.local (10.154.210.206), Authorization failure - you may need to remove the device from BIG-IQ and add it again to reestablish trust: java.net.ProtocolException: status:401, body:<html...>

Messages in the /var/log/httpd/httpd_errors* log files on the BIG-IP show authentication failures from the original BIG-IQ device:

  • Nov 15 11:47:34 bigip13-1 err httpd[14893]: [error] [client 10.155.19.136] Got exception while handling EM auth token request: Invalid Token: Could not decrypt authentication token: Could not RSA decrypt authentication token., referer: http://localhost:8100/shared/identified-devices/config/device-refresh
  • Nov 15 11:49:48 bigip13-1 err httpd[14918]: [error] [client 10.155.19.136] Got exception while handling EM auth token request: Invalid Token: Could not decrypt authentication token: Could not RSA decrypt authentication token.

Environment

  • BIG-IQ standalone or HA pair and BIG-IQ data collection devices (DCDs) that make up a BIG-IQ deployment.
  • Managed BIG-IP

Cause

The BIG-IQ is designed to establish a single trust relationship with a BIG-IP system.

Recommended Actions

  • To determine if a BIG-IP is already managed by a BIG-IQ, refer to K56555353: How to determine if a BIG-IP is managed by a BIG-IQ.
  • When upgrading to a new version of BIG-IQ, you should perform an in-place upgrade rather than a migration to a separate BIG-IQ instance. If you encounter issues with the upgrade, you can contact F5 Support or, if necessary, you can rollback to the previous version. For more information about backing out of an upgrade refer to K73599085: Rolling back a BIG-IQ upgrade.
