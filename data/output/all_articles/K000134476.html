Description

When applications in watched namespace are scaled down to zero or restarted internal objects like virtual servers are not deleted as they should be.

This issue occurs after applying a F5SPKIngressTCP Custom Resources where the port is not specified in the Service Configuration.

 

  • When viewing the F5SPKIngressTCP you will see a similar message
#oc get f5-spk-ingresstcp -n nginx-apps

NAME                STATUS  MESSAGE                                         AGE
invalid-nginx-port  FAILED  Failure in sending CR config to grpc endpoints  7s
  • In the f5-tmm logs you will see similar log message
tmm1[39]: 01010007:7: Config debug: Deleting Virtual Server nginx-apps-tcp-8443-ipv6-virtual-server.
tmm1[39]: 01010058:6: audit log: action: DELETE; UUID: nginx-apps-tcp-8443-ipv6-virtual-server-profile; event: declTmm.virtual_server_profile; Error: No error
tmm1[39]: 01010058:6: audit log: action: DELETE; UUID: nginx-apps-tcp-8443-ipv6-vs-persist_profile; event: declTmm.virtual_server_profile; Error: No error

 

 

Environment

SPK 1.4, 1.5, 1.6, 1.7

F5Ingress

Cause

ID1282605

Recommended Actions

  1. Remove the invalid F5SPKIngressTCP CR, correct the misconfigured port, and re-apply. 

Additional Information

Example configuration

Service Configuration

kind: Service
apiVersion: v1
metadata:
  name: nginx-server
  labels:
    app: nginx-server
spec:
  ports:
  - name: tcp80
    protocol: TCP
    port: 8080
    targetPort: 80
  - name: tcp443
    protocol: TCP
    port: 8443
    targetPort: 443
  - name: udp
    protocol: UDP
    port: 4445
    targetPort: 4445
  selector:
    app: nginx-server
  sessionAffinity: None
  ipFamilies:
    - IPv4
    - IPv6
  ipFamilyPolicy: PreferDualStack

Endpoint/Pod/Deployment config

apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-server
  labels:
    app: nginx-server
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx-server
  template:
    metadata:
      labels:
        app: nginx-server
    spec:
      containers:
        - name: iperf3
          image: '<image repository>/resource/nginx:<version>'
          ports:
            - name: http
              containerPort: 80
              protocol: TCP
            - name: https
              containerPort: 443
              protocol: TCP
          imagePullPolicy: Always
          securityContext:
            privileged: true
            runAsUser: 0
      serviceAccount: default

Valid IngressTCP Custom Resource

apiVersion: "ingresstcp.k8s.f5net.com/v1"
kind: F5SPKIngressTCP
metadata:
  name: fastl4-nginx
service:
  name: "nginx-server"
  port: 8080                    --------------> Port is referenced in the nginx-server service 
spec:
  idleTimeout: 88045
  destinationAddress: 2.3.4.5
  destinationPort: 8080
  ipv6destinationAddress: fd00::321
  serviceDownAction: "POOLMBR_ACTION_RESELECT"

Invalid IngressTCP Custom Resource

apiVersion: "ingresstcp.k8s.f5net.com/v1"
kind: F5SPKIngressTCP
metadata:
  name: fastl4-nginx-bad
service:
  name: "nginx-server"
  port: 8081                    --------------> Port is not referenced in the nginx-server service 
spec:
  idleTimeout: 88045
  destinationAddress: 2.3.4.5
  destinationPort: 8080
  ipv6destinationAddress: fd00::321
  serviceDownAction: "POOLMBR_ACTION_RESELECT"
