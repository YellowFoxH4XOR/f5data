K000161647: Request log shows wrong domain - domain of backend endpoint

Description

When retry policy is enabled on an HTTP Load Balancer in F5 Distributed Cloud, and Host Rewrite Method is set to Automatic Host Rewrite, request/access logs may display the backend/origin DNS name instead of the expected frontend application domain (FQDN defined on Load Balancer). This occurs for requests that result in a backend error (like: HTTP 500) and trigger a retry, causing the backend/origin DNS name to appear in logs instead of the frontend FQDN.

Environment

  • Product: F5 Distributed Cloud – Web App & API Protection / HTTP Load Balancer
  • Feature: Retry Policy (enabled (by default) on HTTP Load Balancer routes or default origin pool)
  • Host Rewrite Setting: Automatic Host Rewrite (default behavior when origin is defined by DNS name)
  • Log Destination: XC Request Logs / SIEM / external log destinations
  • Origin Pool: DNS-name-based origin (not IP-based)
  • Configuration: HTTP Load Balancer with or without explicit routes configured

Cause

When retry policy is enabled and Host Rewrite Method is set to Automatic Host Rewrite, feature auto_host_rewrite behavior causes the authority (Host header / domain field) to be overwritten with the origin/backend DNS name upon retry. This value is then reflected in the request logs, causing the backend FQDN to appear in log entries instead of the frontend application domain. This is a known platform behavior and a fix is under development.

Answer/Recommended Actions

Two workarounds are available to prevent the backend domain from appearing in request logs:

Option A – Disable the Retry Policy (Simplest)

  1. Navigate to HTTP Load Balancer → Edit Configuration → Routes → Configure → Add Item.
  2. Select Route Type: Simple Route.
  3. Optionally: define Host header matching if LB has multiple domains.
  4. Set Path Match: Prefix / (matches all requests).
  5. Under Retry Policy, select Do Not Retry.
  6. Save and apply the configuration.

This eliminates the retry-triggered host rewrite and resolves the incorrect domain logging.

Option B – Configure Explicit Host Rewrite to Frontend FQDN (Preserves Retry Functionality)

  1. Navigate to HTTP Load Balancer → Edit Configuration → Routes → Configure → Add Item.
  2. Select Route Type: Simple Route.
  3. Optionally: define Host header matching if LB has multiple domains.
  4. Set Path Match: Prefix / (matches all requests).
  5. Under Select Host Rewrite Method, choose Host Rewrite Value.
  6. Enter the exact frontend application FQDN (the Load Balancer's public domain).
  7. Save and apply the configuration.

This forces the Host header to always use the specified frontend domain, ensuring correct domain values appear in logs.

Note: If the Load Balancer uses a Default Origin Pool (no route configured) with a DNS-named origin, XC automatically rewrites the Host header to the origin's DNS name. If the origin is IP-based, the client's original Host header is passed through unchanged. Host header manipulation is only available at the Route level; a route must be configured (even a catch-all prefix /) to control Host rewrite behavior.

Additional Information

  • Disabling the retry policy at the route level resolves the incorrect domain logging issue. After disabling retries, log entries reflect the correct frontend application domain.
  • The incorrect domain in logs is currently understood to be a logging/display issue. The Engineering team is investigating whether the backend domain also appears in actual request headers sent to the origin, or whether it is limited to the log field only.
  • The Product Team is actively working on a permanent fix.
  • The three available Host Rewrite Method options and their behaviors:
    • Host Rewrite Value – Forces a specific, static host header value on all requests (including retries).
    • Automatic Host Rewrite – Rewrites the host header to the origin pool's DNS name (default when origin is DNS-based; triggers the issue described above on retry).
    • Disable Host Rewrite – Passes the original client Host header unchanged to the origin.
