Known Issue

You cannot delete CNAME records with a value of . (period) when you use the ZoneRunner utility. 

This issue occurs when all of the following conditions are met:

  • You use the ZoneRunner utility to create a CNAME Resource Record with a value of . (period).
  • You use the ZoneRunner utility to delete a CNAME Resource Record with a value of . (period).

The ZoneRunner utility does not prevent you from entering a . (period) for the CNAME value.

Impact

You cannot delete the CNAME record, and the system reports an error. 

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the Configuration utility, you observe an error message similar to the following example:

    Error parsing resource record form.

  • The Configuration utility may become unresponsive and restart.

Workaround

To work around this issue, you can use the command line to remove the CNAME. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure suspends updates to a dynamic zone. The system prevents all dynamic updates while the zone is frozen.

  1. Log in to the command line.
  2. To freeze the zone that contains the affected CNAME resource record, use the following command syntax:

    rndc freeze <zonename>

    For example:

    rndc freeze bar.com

  3. Using the following command syntax, edit the zone file and remove the CNAME resource record; the zone files are located in the /var/named/config/namedb/ directory:

    db.<viewname>.<zonename>.

    For example:

    nano /var/named/config/namedb/db.external.bar.com.

  4. Save the file.
  5. Release the zone from the freeze using the following command syntax:

    rndc thaw <zonename>

    For example:

    rndc thaw bar.com

    The system displays the following message indicating that the zone was reloaded and the thaw was successful:

    The zone reload and thaw was successful.
