Description

If iRule utilizes table commands in FLOW_INIT, traffic will be briefly disrupted for a few seconds when a primary dSSM pod goes down for whatever reason, such as a reboot of the worker node it's running on. 

Environment

  • BIG-IP Next CNF

Cause

If an iRule does a table lookup or a table set during FLOW_INIT, it connects to the Redis database on the primary dSSM pod. When the primary dSSM pod goes down, the table commands do not work until another dSSM pod is elected as a primary, and traffic gets disrupted during the small window.

Recommended Actions

Make the iRule less dependent on dSSM, especially when opening a flow whenever possible.
