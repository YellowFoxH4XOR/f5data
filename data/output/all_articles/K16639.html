K16639: The BIG-IP ASM bd process may produce a core file and restart when two attack signature sets are assigned to two security policies

Known Issue

The BIG-IP ASM bd process may produce a core file and restart. This issue occurs when all of the following conditions are met:

  • Your configuration includes a security policy with a set of attack signatures.
  • You subsequently configure a second security policy with a different set of attack signatures, and a different number of attack signatures than the first set.
  • Traffic processed by both security policies matches a significant number of attack signatures and generates a significant amount of violations or learning suggestions.

Impact

BIG-IP ASM traffic processing is temporarily interrupted.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H523190 on the Diagnostics > Identified > Low screen.
  • The BIG-IP ASM system logs a bd core file to the /var/core directory.
  • The BIG-IP ASM system sends a SIGSEGV fault to the bd process, and logs an error message similar to the following example to the /var/log/ts/bd.log file:

    BD_MISC|CRIT |<timestamp>|16804|signals.c:0076|Received SIGSEGV - Core Dumping

Workaround

You can mitigate this issue by assigning the same set of attack signatures to all security policies on the affected BIG-IP ASM system. For information about assigning attack signature sets to a security policy, refer to the Working with Attack Signatures chapter of the BIG-IP Application Security Manager: Implementations guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
