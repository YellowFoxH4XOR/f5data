Known Issue

The lb_http process may produce a core file with the Assertion failed: (!requests()->empty()), function waitUntilReadyForResponse error message.

This issue occurs when all of the following conditions are met:

  • You have a LineRate script configured in the datapath.
  • Your LineRate script uses the Node.js setTimeout() method with the client response configured as the callback value, with a delay value of 10 seconds. Your script may look similar to the following example (this example is truncated for brevity):

    var slow_respond = function(sReq, sRes) {
      var timeout = 10000;
      sReq.on('response', function(response) {
      ...
        response.on('data', function(chunk) {
          body += chunk;
        });
     
        response.on('end', function(chunk) {
          body += chunk;
          var timeoutResponse = function() {
            console.log("generating closure");
            return function() {
              console.log("closure executing");
              sRes.write(body);
            }
          }
     
          setTimeout(timeoutResponse(), timeout);
          console.log("set timeout");
        });
     });
    }

The LineRate system has an internal timeout value that is fixed at 10 seconds, which represents the script response timeout. The two timers can potentially create a race condition for the timeout event.

Impact

The lb_http processes produce a core file and then restart. All connections on the affected lb_http process are lost, and must be re-established. Other lb_http processes may be affected, depending on the retry by the client applications and whether you encounter the same conditions when reproducing the bug.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system loses connections that use the affected lb_http process.
  • In the /var/log/controller.messages file, the system logs messages similar to the following example:

    Assertion failed: (!requests()->empty()), function waitUntilReadyForResponse, file appmods/lb_http/client_connection.cc, line 971.
    ProcManager: lb_http exited: exited due to signal 6 (core dumped).

Workaround

To work around this, you can either override the default script response timeout by using resetTimeout() with a timeout value set to something other than the value configured for setTimeout(), or you can modify the delay value for the setTimeout() method to something other than the default 10 seconds.

Impact of workaround: Changing the design of your LineRate scripting may have additional effects on traffic processing. Ensure that any modification you make is compatible with your environment.

The following is a possible configuration for resetTimeout(), using the the example provided above:

var scriptTimeoutValue = 60;
sReq.on('response', function(response) {
  sReq.resetTimeout(scriptTimeoutValue);
  ...
    response.on('data', function(chunk) {
      body += chunk;
    });
  ....
}

Note: If the timeout in resetTimeout(timeout) is set to zero, the timer is disabled for this request, and a 504 Gateway Timeout is never automatically sent to the client.
