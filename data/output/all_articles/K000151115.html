K000151115: Virtual Server is not responding to TCP SYN of the client

Published

Applies to

Source

Description

This article describes an issue where a BIG-IP LTM virtual server does not respond to incoming TCP SYN packets.

  • Packet captures show that SYN packets are received by the BIG-IP, but no SYN-ACK is sent in response.
  • No related error messages or SYN cookie activation events are found in ltm logs.

Environment

  • BIG-IP LTM
  • Virtual server
  • TCP three-way handshake

Cause

When a new TCP SYN packet is received for a source IP and port combination that already exists in the BIG-IP connection table (i.e., an active or idle connection is still present), the BIG-IP will silently drop the SYN packet without sending a SYN-ACK. This behavior follows RFC 5961, which specifies that a SYN received on an existing connection should be discarded to prevent session hijacking and maintain connection integrity. 

Recommended Actions

Use packet captures and connection table inspection (e.g., tmsh show sys connection) to verify if the source IP:port combination is already present when the SYN is dropped.

Review upstream devices (such as NAT gateways or firewalls) to ensure they do not prematurely reuse source ports for new connections before previous connections have fully closed and timed out on the BIG-IP.

If port exhaustion or aggressive port reuse is suspected on upstream devices, coordinate with network teams or partner organizations to increase available source port range or improve port management.
