Description

When both BIG-IP are in In Sync status, you notice Virtual Server object(s) is missing on the peer device.

The specific Virtual Server will not be able to be sync to peer from Incremental Sync and Full Sync.

Navigating to Virtual Address List (Local Traffic > Virtual Servers > Virtual Address List), it is noticed that the Virtual Server's IP address is in traffic-group-local-only. It should be in traffic-group-1. You have followed the steps in K87963051 but the Virtual Address is still in traffic-group-local-only.

It is also seen that the Virtual Address which is in traffic-group-local-only is also a non floating Self IP of one of the F5 BIG-IP. Navigate to Network > Self IPs.

Environment

  • BIG-IP HA pair are In Sync status
  • Virtual Server object is missing is peer device
  • Virtual Address List shows IP in traffic-group-local-only
  • Same Virtual Address is a non floating Self-IP

Cause

The Virtual Server's IP address is the same IP of a non-floating Self-IP of one of the device.

Because of this, the Virtual Address shows that it is a traffic-group-local-only and it cannot be changed.

traffic-group-local-only are IP addresses unique to one BIG-IP and cannot be shared (in this case sync) with peer BIG-IP devices. This includes IP address on Virtual Servers.

Recommended Actions

You need to change the Virtual Server's IP to another IP which is not a self IP address.

  1. Login to the Configuration Terminal
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List
  3. Click on the Virtual Server which cannot be synced to its peer
  4. Under Destination Address/Mask change the IP address
  5. Click Update
  6. Sync the configuration
