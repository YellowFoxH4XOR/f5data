K000163810: BIG-IQ Certificate List Attaches a Key From a Different Silo When Not Filtered by Silo

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.0
Source
https://my.f5.com/manage/s/article/K000163810

Description

In BIG-IQ Centralized Management 8.4.0, when the SSL certificate list is not filtered by silo, marking a certificate can attach a key from a different silo instead of the key in the same silo. The GUI then displays a key with a different checksum than the expected key.

Symptoms:

  • Certificate and key objects share the same names (for example, wildcard.example.com.crt and wildcard.example.com.key) across multiple silos.
  • Without a silo filter, the attached key has a checksum from another silo (for example, SHA1:1730:...).
  • With the correct silo selected in the filter before marking the certificate, the attached key has the expected checksum from the same silo (for example, SHA1:1704:...).


Environment

  • BIG-IQ Centralized Management 8.4.0
  • Managed BIG-IP devices in Unmanaged state, with SSL objects in the Common partition
  • Multiple silos containing SSL certificate and key objects with identical names
  • Silos used as temporary containers during onboarding of existing BIG-IP devices into BIG-IQ

 

Cause

ID2690333 BIG-IQ certificate list associates a certificate with a same-named key from a different silo



Answer/Recommended Actions

Workaround (until the fix is applied): Filter the certificate list by the correct silo before marking the certificate and key. Confirm that the checksum of the attached key matches the expected key in that silo.


Option1: Verify release notes and upgrade to version where ID2690333 is fixed.


Option2: Create support ticket to request Engineering Hotfix for this issue


Additional Information

Expected behavior: The attached key should come from the same silo as the certificate.

Unexpected behavior: Without a silo filter, the GUI can attach a key from another silo with a different checksum.

Silos are intended only for temporary administrative tasks and are not designed for long-term use.
