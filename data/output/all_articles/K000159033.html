Description

This article explains why an HTTP request containing repeated headers may not be blocked by BIG-IP ASM, even when the Illegal Repeated Header violation is enabled with the blocking flag set to Yes and the security policy is operating in Blocking mode.


Specifically, this behavior is influenced by the Header Definitions configuration, and more precisely by the Repeated Occurrences setting. Depending on this configuration, ASM may allow repeated headers and therefore not trigger the violation.


Environment

  • BIG-IP Application Security Manager (ASM)
  • Security policy in Blocking mode
  • Illegal Repeated Header violation enabled
  • HTTP requests containing multiple instances of the same header (for example, X-Forwarded-For)

Cause

The observed behavior is caused by the configuration of the matching header definition (explicit or wildcard) in the ASM security policy.


ASM evaluates repeated HTTP headers based on header definitions in the following order:


1. Explicitly defined headers

2. The wildcard header (*) for all undefined headers


When the matching header has Repeated Occurrences set to Allow, ASM permits multiple instances of the same HTTP header. As a result, no Illegal Repeated Header violation is triggered.


Recommended Actions

1. Review the ASM policy Header Definitions configuration

2. Align the Repeated Occurrences setting with your security requirements

3. Validate policy behavior by testing requests with repeated headers


Additional Information

The Illegal Repeated Header violation enforces HTTP protocol compliance but is subject to header-level configuration.

Header definitions take precedence over violation settings; therefore, allowing repeated occurrences at the header level effectively overrides the violation behavior.

This behavior is expected and by design in ASM.
