Known Issue

BIG-IP ASM security policies fail to load after an upgrade.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system has one or more virtual servers configured with a BIG-IP ASM security policy.
  • Your BIG-IP ASM device is running version 14.0.0 or earlier.
  • You upgrade your BIG-IP ASM 12.x, 13.x, or 14.x device to version 14.1.0 or later.

Impact

After a software upgrade, BIG-IP ASM security policies may immediately fail to load, and the affected virtual servers stop processing traffic.

Symptom

As a result of this issue, you may encounter one or more of the following symptoms:

  • Immediately after a device upgrade, virtual servers configured with a security policy fail to process traffic.
  • When the system attempts to load the BIG-IP ASM security policies, the bd_io_plug process creates a core file in the /var/core directory.
  • In the /var/log/asm file, the system logs messages similar to the following example:

    asm|INFO|<date/time>|<pid>|,,DBD::mysql::db do failed: Can't get stat of '/ts/var/install/ts_db.save_dir_8608.cstmp/ts_db.data.DCC.ACCOUNT_VALID_HOST_NAMES_REGEXES.cstmp' (Errcode: 13) at /usr/local/share/perl5/F5/ConfigSync.pm line 940.
    asm|INFO|<date/time>|<pid>|,,Could not import table DCC_ucs.ACCOUNT_VALID_HOST_NAMES_REGEXES data from file ts_db.data.DCC.ACCOUNT_VALID_HOST_NAMES_REGEXES.cstmp - ASM configuration load aborted.

  • In the /var/log/auditd/audit.log file, the SELinux audit log contains repeated denied log messages similar to the following example:

    auditd/audit.log:type=AVC msg=audit(2019-12-12T09:00:30CET:114): avc: denied { read } for pid=27803 comm="bd_read_event" name="collection.f37a2843c1777d7662d246845c415ef9" dev="dm-14" ino=139314 scontext=system_u:system_r:bd_t:s0 tcontext=system_u:object_r:unlabeled_t:s0 tclass=file

Workaround

To work around this issue, you can remove security policies from virtual servers before upgrading. Alternatively, you can restore the device configuration using a UCS archive file after upgrading. To do so, perform one of the following:

  • Removing BIG-IP ASM security policies from virtual server configurations
  • Creating and restoring the device configuration with a UCS archive

Removing BIG-IP ASM security policies from virtual server configurations

To prevent this issue from occurring, you can remove security policies from virtual servers before upgrading.

Impact of workaround: Removing the security policies prevents the virtual servers from enforcing the security elements defined in the policies.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server.
  4. From the Security tab, select Policies.
  5. Note the name of the referenced security policy for Application Security Policy.
  6. For Application Security Policy, select Disabled.
  7. Select Update.
  8. After upgrading the system, repeat steps 2 through 4, and then for Application Security Policy, select Enabled and select the original security policy name for the virtual server.

Creating and restoring the device configuration with a UCS archive

To work around this issue, you can create a UCS archive file before upgrading, and then restore the device configuration using the same UCS archive file after the upgrade is complete.

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

  • Creating the UCS archive
  • Restoring the UCS archive file after upgrading

Creating the UCS archive

Before upgrading the target partition, create a UCS archive by performing the following steps:

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. Select Create.
  4. Enter a name for the archive file.
  5. Select Finished.
  6. Select the UCS archive file name.
  7. Select Download.

Restoring the UCS archive file after upgrading

After upgrading, boot to the target partition and restore the UCS archive by performing the following steps:

  1. Boot to the upgraded partition.
  2. Log in to the Configuration utility.
  3. Go to System > Archives.
  4. From your local device, select the name of the UCS archive file created in the previous procedure.
  5. Select Restore.
  6. Select Browse.
  7. Select the UCS file name.
  8. After the restoration is complete, go to System > Configuration > Device > General.
  9. Select Reboot.

Note: For more information about creating a UCS archive file and restoring the device configuration using the UCS archive file refer to: K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.
