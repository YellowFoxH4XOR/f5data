K15038: The BIG-IP WebAccelerator system may serve small objects with a zero content length

Known Issue

Requests for small, expired documents may result in the BIG-IP WebAccelerator system incorrectly caching and serving the document as 0 length.

This issue occurs when all of the following conditions are met:

  • You request an expired document that is smaller than 4k when compressed, but larger than 4k when uncompressed.
  • The document is requested multiple times in a simultaneous burst.

Impact

Affected documents served by the BIG-IP WebAccelerator system may not render properly on clients.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client may receive https responses with a Content-Length of 0 (zero) from the BIG-IP WebAccelerator system.
  • Clients may receive TCP resets from the BIG-IP WebAccelerator system.

Workaround

To work around this issue, you can disable the small object cache. To do so, perform the following procedure:

Impact of workaround: You may observe a small performance hit, as the system now caches small objects that it would otherwise not have cached.

  1. Log in to the BIG-IP command line as the root user.
  2. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  3. To disable the small object cache, type the following command:

    tmsh modify sys db wam.cache.smallobject.threshold value 0

  4. To save the change, type the following command:

    save /sys config
