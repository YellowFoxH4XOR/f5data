Known Issue

The BIG-IP APM vdi process may restart when processing traffic for a closed connection.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured with a Citrix or VMware View remote desktop.
  • The BIG-IP APM system sends vdi response traffic after the client has disconnected.

Impact

Users cannot access remote desktop resources while the vdi process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Access to remote desktop resources is impaired or unavailable.
  • The vdi process exits and generates a core file to the /shared/core directory.
  • Messages similar to the following examples appear in the /var/log/apm file:

    Citrix

    err vdi[32458]: 01490000: {7ede8.S.PNA.Launch} Abort with error: 'ResponseAddress returned failure.'
    err vdi[32458]: 01490000: {7ede8.S.PNA.Launch} Transaction FAILED. All resources failed!
    err vdi[32458]: 01490000: {7ee78.C} CallOutput on empty outputSink.

    VMware View

    err vdi[16550]: 01490000: {26.S} View signal: error processing client request: system:111 'Connection refused'
    err vdi[16550]: 01490000: {26.S} View signal: bad xml in client request, sending fail with 1034 code. Please check signal virtual server
    configuration
    err vdi[16550]: 01490000: {20.S} CallOutput on empty outputSink.
