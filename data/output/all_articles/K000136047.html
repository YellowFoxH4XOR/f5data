K000136047: iQuery is not established between DNS and LTM; SSL handshake failure with message unknown_ca

Type
Support Solution
Published
2023-08-31
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP DNS: 13.1.5
Source
https://my.f5.com/manage/s/article/K000136047

Description

Iquery between DNS and LTM is not connected. Port 4353 is open and device certificates have been correctly exchanged. However, logs confirm that SSL handshake between devices is failing. 


dns-device notice gtmd[13244]: 011ae01c:5: Connection complete to <IP_of_LTM> Starting SSL handshake

dns-device err gtmd[13244]: 011ae0fa:3: iqmgmt_ssl_connect: SSL error: SSL connect (1)


Additionally, when reviewing pcap file, you can observe that LTM resets the connection with Alert (Level: Fatal, Description: Unknown CA)


Environment

  • DNS and LTM
  • DNS using SSL certificate signed by third-party Certificate Authorities (CA)

Cause

LTM is not able to authenticate the DNS certificate because the root CA certificate is missing from trusted device certificates.


Recommended Actions

1) Download the root certificate from the CA server (you can export it from the DNS device)

2) Import root CA certificate to System > Certificate Management > Device Certificate Management > Device Trust Certificates on LTM device 


If necessary, reinitialize iQuery by restarting gtmd and big3d on DNS:

#tmsh restart sys service big3d gtmd 


Note: Restarting gtmd and big3d briefly halts iQuery communication with this DNS sync group peer.
