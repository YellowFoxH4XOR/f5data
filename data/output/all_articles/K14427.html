Known Issue

The BIG-IP ASM system may allow ASM::* iRule commands to be used with invalid events.

For example, you use the ASM::violation_data command in the HTTP_REQUEST_RELEASE event.

    When the BIG-IP ASM system is configured with strict iRule validation (by default), the system should disallow the iRule and report an error. You can verify the iRule validation setting by typing the following command:

    tmsh list sys db rule.validation

    Impact

    The BIG-IP ASM system may not process traffic as expected. In addition, the Traffic Management Microkernel (TMM) may crash.

    Symptoms

    As a result of this issue, you may encounter the following symptoms:

    • The BIG-IP ASM system does not process traffic as expected when an ASM::* iRule command is used in a non-valid event.
    • TMM crashes and produces a core file in the /shared/core directory.

    Workaround

    There is no work around for this issue. However, you can attempt to mitigate this issue by using the ASM::* iRule commands in their respective valid events.

    Impact of workaround: Depending on your application environment, this may require a rewrite of iRules. F5 recommends that you author an iRule that is best suited for your application environment. F5 recommends that you test any such changes in an appropriate environment.
