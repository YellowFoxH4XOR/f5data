Description

Processes are continuously restarting on single blade.

Environment

  • BIG-IP
  • Multi-cluster VIPRION
  • Single blade restarting services

Cause

There may be multiple causes, such as:

  • Full disk partition
  • Corrupt configuration
  • Hardware failure

Answer/Recommended Actions

If the issue persists after rebooting/reseating the blade, freeing disk space etc, use the below procedure to check for hardware issues and restore the blade.

Run an EUD to check for hardware issues as per the following article.

K05850234: EUD Test on VIPRION Chassis or Blades

If the EUD Test passes all tests proceed with a fresh software install on the impacted blade, otherwise open a case with F5 Support to raise an RMA.

Blade Recovery: install fresh software on the impacted blade

Copy the desired BIG-IP image ISO file to impacted blade and perform a software installation on impacted blade using the image2disk utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

As a precautionary measure, you should back up BIG-IP configuration files on the VIPRION system and transfer the created user configuration set (UCS) file to another location. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive. For information about transferring the UCS file to another location, refer to K175: Transferring files to or from an F5 system.

1. Log in to the primary blade of the VIPRION system using the secure shell (SSH) or serial console with a privileged user, such as root.

2. Locate the desired BIG-IP ISO image file in the /shared/images directory on the primary blade and copy it to the impacted blade using the following command syntax:

scp /shared/images/<BIG-IP ISO image file name> root@<impacted blade slot>:/shared/images

For example, you have BIGIP-13.1.0.5-0.0.5.iso in the /shared/images directory and you want to copy this ISO image file to the impacted blade in slot 2, type the following command:

scp /shared/images/BIGIP-13.1.0.5-0.0.5.iso root@slot2:/shared/images/

Note: You can safely ignore the following error message:

error: mcpd never came up... using /config/BigDB.dat.

3. Log in to the impacted blade through the primary blade using the following command syntax:

ssh slot<X>

For example, to log in to the impacted blade in slot 2, type the following command:

ssh slot2

Important: Ensure that you log in to the correct blade by verifying the prompt; it should report INOPERATIVE like the following example:

[root@bigip:/S1-green-P::Active:Standalone] config # ssh slot2
Last login: Tue May 8 14:26:39 2018 from 127.3.0.1
[root@localhost:/S2--S:INOPERATIVE:] config #

4. Perform a manual software installation using the image2disk utility on the impacted blade using the following command syntax:
image2disk --format=volumes --nosaveconfig /shared/images/<desired ISO image file name>

Using the previous examples, to install BIG-IP 13.1.0.5 on the impacted blade, type the following command:

image2disk --format=volumes --nosaveconfig /shared/images/BIGIP-13.1.0.5-0.0.5.iso

5. Wait for the blade to reboot into MOS, reformat its disk, and complete its installation of the specified BIG-IP version. To monitor the progress of the manual installation, you will need to connect to the serial console. For VIPRION B4xx0 blades (B4200, B43x0 and B4450), you may be able to monitor the serial console using the bladectl command syntax:
bladectl -b <slot number> -c

For example, to monitor the serial console of the impacted blade in slot 2, type the following command:

bladectl -b 2 -c

Note: The bladectl utility may not be as reliable as a physical serial console connection and may report errors, such as failed: Unable to capture blade 2 console. The B21x0 and B2250 blades do not support console port redirection.

6. Once the installation completes, the blade will boot into the installed version and initiate the process of joining the VIPRION cluster. The VIPRION system may initiate further software installations and/or reboots while it attempts to ensure that the blade is installed with the BIG-IP versions in boot locations that are the same as the rest of the blades in the cluster.
