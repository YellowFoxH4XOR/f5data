Topic

This article applies to VIPRION platforms running versions 9.6.x through 10.x. For information about other versions, refer to the following article:

  • K13325: Setting the serial console baud rate on a VIPRION system (11.x - 13.x)

Description

F5 recommends that you set the baud rate on the connecting serial terminal rather than modify the VIPRION serial port configuration. If you cannot modify the connecting serial terminal settings, you can set the serial console baud rate on a VIPRION system, by performing the following procedure:

  1. Connect to the serial console port of the primary blade of the VIPRION cluster using a serial terminal and a null modem cable.

    Note: The Primary LED is illuminated on the chassis to indicate which blade is currently the cluster primary.

    Note: The default baud rate for the serial console port is 19200.

  2. To change the configured baud rate in the VIPRION software configuration file, use the following command syntax, replacing <baud> with the desired baud rate:

    bigpipe hardware baud rate <baud>

  3. To change the baud rate in the system hardware, access the console port menu by simultaneously pressing the ESC+Shift+9 keys.
  4. Select the Set baud rate of serial console port option from the console port menu.
  5. Set the console port baud rate to the same value that you configured in Step 2.

    Note: When the new baud rate is accepted, your current console connection using the old baud rate will drop.

  6. Change the baud rate on your serial terminal to match the newly-configured baud rate.
  7. Re-establish the serial connection to the blade.
  8. Press Q to exit the console port menu.
  9. To save the configuration, type the following command:

    bigpipe save all

  10. Reboot the blade by typing the following command:

    reboot

    Note: Rebooting the blade forces the system to promote a new primary blade.

  11. Repeat the procedure on the newly-promoted primary blade until all blades in the cluster have been re-configured.

Note: Since bigpipe commands only affect the primary blade in a cluster, it is necessary to reboot after configuring each blade, forcing the system to promote a different blade to cluster primary. The blade with the longest uptime is typically promoted to primary after a reboot; however, in rare cases, another blade may be promoted. To ensure that you have configured each blade, note the identity of each blade you have configured as you complete the procedure. Repeat the procedure as many times as is necessary to change the baud rate of all the blades in the chassis.
