Description
SNMP traps that are mapped with bigpipe command failing to send alerts.

Environment

  • BIG-IP LTM
  • General SNMP traps 
  • bigpipe Utility

Cause

SNMP traps that is mapped with bigpipe command don't send alerts because bigpipe utility is depreciated. 

To verify if a trap is mapped to bigpipe, run the below command:
# snmptranslate -Td <OID>
Example:
# snmptranslate -Td .1.3.6.1.4.1.3375.2.4.0.28
Output:
F5-BIGIP-COMMON-MIB::bigipConfigLoaded
bigipConfigLoaded NOTIFICATION-TYPE
  -- FROM       F5-BIGIP-COMMON-MIB
  OBJECTS       { bigipNotifyObjMsg }
  DESCRIPTION   "Deprecated! The component which created this event has been
deprecated.  The configuration was loaded."
::= { iso(1) org(3) dod(6) internet(1) private(4) enterprises(1) f5(3375) bigipTrafficMgmt(2) bigipNotification(4) bigipNotifications(0) 28 }

Alternatively, you may verify from the /etc/alertd/alert.conf file and search using a keyword in the alert name.   
Example: 
/* bigpipe is deprecated.
 * from bigpipe 
alert BIGIP_SHELL_BP_CONFIGURATION_LOADED {
	snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.28"
}
*/
  Recommended Actions
  1. Search for any related general traps in /etc/alertd/alert.conf file can be used to create new alerts. 
  2. Create custom SNMP traps if no existing traps available as recommended in  K3727. 
  3. Test SNMP trap using steps mentioned in K11127
    Example:
    snmptrap -v 2c -c public <host> '' .1.3.6.1.4.1.8072.100 .1.3.6.1.4.1.8072.100.1 s "test" 
    Note: Replace <host> with the destination host IP address that you want to send the snmp trap.


Additional Information

General SNMP traps are available in /etc/alertd/alert.conf and these can be used to create user desired alerts in user_alert.conf in /config/.
