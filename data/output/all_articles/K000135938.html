K000135938: Having issue routing https traffic from proxy to ingress controller using proxy_pass

Type
Support Solution
Published
2023-09-20
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Plus: R26
Source
https://my.f5.com/manage/s/article/K000135938

 

Description

The issue:

  • Client gets 502 error while requests the service
  • Nginx access log record displays status = 502
  • Nginx error log record is:
[crit] 22779#22779: *373 SSL_do_handshake() failed (SSL: error:14077458:SSL routines:SSL23_GET_SERVER_HELLO:tlsv1 unrecognized name) while SSL handshaking to upstream, client: x.x.x.x, server: , request: "POST <uri> HTTP/1.1", upstream: “<request_to_uprtream>”, host: “<Host_header>

Environment

client <-> Nginx-plus (R26) <-> Nginx Ingress controller <-> Application

Cause

Absence of data expected by upstream (Host request header and name passed trough SNI)

 

Recommended Actions

Nginx configuration (on server/location level) should contain, for example

proxy_set_header Host $host;

proxy_ssl_server_name on;

proxy_ssl_name $ssl_server_name;

 

Additional Information

The exact values instead of variables can be defined. One of the way to find out these expected values is to send the requests to upstream group directly, bypassing nginx.
