Known Issue

This is the result of a known issue. When using the X509::cert_field iRule command with the subpubkey parameter to return the Subject Public Key Info for the certificate, the system fails to deallocate 4 bytes of memory each time the command is invoked. As a result, memory consumption increases over time and may eventually result in memory exhaustion.

For example, the following code provokes this behavior:

set certfields [ X509::cert_fields $client_cert 0 subject subpubkey ]

The memory is allocated to the method subsystem. You can observe the increasing allocation by performing the following procedure:

  1. Log in to the BIG-IP command line.
  2. To display the current memory allocation for the method subsystem, type the following command:

    b memory show | grep ' method'

    The command output appears similar to the following example:

    | method 0 1934 1

    Note: The first column contains the number of bytes of memory allocated to the method subsystem.
  3. Invoke the iRule by establishing a Secure Socket Layer (SSL) connection using a valid certificate to the virtual server running the offending iRule.
  4. Ensure the iRule processing for the connection has completed by closing the connection.

    Note: If you are using a browser, you may need to close the browser.
  5. To display the current memory allocation for the method subsystem, type the following command:

    b memory show | grep ' method'

    The command output appears similar to the following example:

    | method 4 1934 1

    Note: The allocation increases by 4 bytes each time the iRule is invoked.

F5 Product Development tracked this issue as ID 207980 and ID 307993, and it was fixed in BIG-IP 10.1.0 and 9.4.8. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by avoiding the use of the subpubkey option when querying X509 certificate fields in an iRule.
