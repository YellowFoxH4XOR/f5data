Description

When enabling HTTP/2 full-proxy support with the MRF Router on BIG-IP LTM, the system may experience a loss of management connectivity and a restart of multiple services (such as mcpd, tmm, mysql, and others). The following error may be observed in the var/log/ltm: 

Configuration error: In Virtual Server (<virtual_server_name>) an http2 profile with enforce-tls-requirements enabled is incompatible with client ssl profile '<profile_name>' renegotiation must be disabled... failed validation with error 17237812.

Environment

  • BIG-IP LTM
  • HTTP2

Cause

BugID 1070181: The combination of an HTTP/2 profile with "enforce-tls-requirements" enabled and multiple client SSL profiles, where some have renegotiation enabled and others have it disabled, triggers a software defect. This causes the secondary MCPD process to crash during configuration validation.

Recommended Actions

  • Ensure all client SSL profiles attached to the virtual server have consistent "renegotiation" settings (preferably set to disabled).
  • If you require multiple client SSL profiles with different renegotiation settings, disable "enforce-tls-requirements" in the HTTP/2 profile.
  • Review your configuration before applying changes in production environments to avoid outages.

Example Configuration:

ltm profile http <http2_profile_name> {
    activation-modes { alpn }
    app-service none
    concurrent-streams-per-connection 10
    connection-idle-timeout 300
    defaults-from none
    description none
    enforce-tls-requirements enabled    <---------- Disable
    frame-size 2048
    header-table-size 4096
    insert-header disabled
    insert-header-name X-HTTP2
    partition Common
    receive-window 32
    write-size 16384
}
