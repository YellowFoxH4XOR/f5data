K000161328: BIG-IP DNS configuration sync stops after migration using Journeys Tool

Type
Support Solution
Published
2026-05-19
Updated
2026-08-18
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161328

Description

After migrating a BIG-IP configuration to rSeries using the F5 Journeys tool, BIG-IP DNS (GTM) configuration changes are no longer synchronized between devices in the cluster. Although iQuery connections appear established, configuration changes made on one unit are not propagated to the other. 

The output of #tmsh show gtm iquery shows state as connected but Configuration Commit ID: shows '0' and Configuration Commit Originator:  shows blank or (null).

/var/log/ltm file shows repeatedly device_trust_group was not found.

May 13 08:27:09 LTM1.example.com err mcpd[5118]: 01020036:3: The requested devicegroup (/Common/device_trust_group) was not found. 

Environment

  • BIG-IP GTM
  • device_trust_group
  • Migration using Journey's tool

Cause

The Journey's tool, when processing the UCS file for migration, does not preserve the device_trust_group  device group. As a result, after loading the modified UCS on the new platform, the device_trust_group device group is absent,  breaking configuration synchronization between cluster members.

Answer/Recommended Actions

Reset device_trust_group either from GUI or CLI.

Note: If you unable to reset device trust using GUI due to following error  - " An error has occurred while loading this page." while navigating to Device Management  ››  Device Trust : Local Domain, reset device trust using below CLI procedure.

Perform following steps to reset the device_trust_group via CLI:

  • Log in to BIG-IP CLI 
  • Delete the existing trust domain to trigger recreation of the device_trust_group using below command

#tmsh delete cm trust-domain Root

  • Verify that device_trust_group is now present and has self device under devices

#tmsh list cm device-group all-properties

For example: Expected output should include device_trust_group and self device hostname under devices

cm device-group device_trust_group {
    app-service none
    asm-sync disabled
    auto-sync enabled
    description none
    devices {
        LTM1.example.com { }
    }
    full-load-on-sync false
    incremental-config-sync-size-max 1024
    network-failover disabled
    partition Common
    save-on-auto-sync false
    type sync-only
}

  • Verify that following error messages are no longer appears in /var/log/ltm file

01020036:3: The requested devicegroup (/Common/device_trust_group) was not found. 

  • Once device_trust_group is restored on all devices in GTM cluster, identify the unit with the most current GTM configuration  (consider it as master )  and perform changes on master unit to validate if gtm config sync now works.
  • Run below command and verify that configuration commit ID no longer shows '0'

#tmsh show gtm iquery

  • If sync still doesn't work after restoring device_trust_group device group, from non-master unit,  run gtm_add command pointing to the master unit to re-establish GTM synchronization.

Please refer to following - K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities to run gtm_add command
