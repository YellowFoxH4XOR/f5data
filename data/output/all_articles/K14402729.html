Description

  • You may experience it in different ways, for example:
    • Traffic not flowing as expected between route-domains
    • When sending traffic from internal to external VLANs, it is passed on both directions
    • When sending traffic from external to internal VLANs, it is not allowed from parent to child route-domains

Environment

  • Routing
  • Route-domains
  • Strict isolation disabled
  • Virtual Server has "VLAN and Tunnel Traffic" set to "Enabled On" with restricted VLANs per route-domain

Cause

  • Two possible causes identified so far:
    • Virtual Server with "VLAN and Tunnel Traffic" set to "Enabled On" only allows the traffic to originate from the specified VLANs. Any returning traffic will be allowed through the lifespan of the "connection".
    • If the Virtual Servers are configured with  "VLAN and Tunnel Traffic" set to "Enabled On / Disabled On", each route-domain must have a Virtual Server allowing the desired traffic flow.

Recommended Actions

  1. Configure the appropriate Virtual Server per route-domain to allow the BIG-IP to forward traffic from the desire sources towards the desire destinations. For more information please check article K7595: Overview of IP forwarding virtual servers.
  2. Configure "VLAN and Tunnel Traffic" at the Virtual Server level only if you want to restrict which "VLANs" should/shouldn't source traffic.
    1. Local Traffic  ››  Virtual Servers : Virtual Server List  ››  <Virtual_Server_Name>
    2. At "VLAN and Tunnel Traffic" dropdown menu, select "Enabled On / Disabled On" to "allow / disallow" which VLANs can source traffic to that Virtual Server.
