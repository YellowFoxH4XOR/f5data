Description

Telemetry stream using only mgmt (Default route-domain 0) interface to communicate with the different consumers. While, ignoring route-domain specific route for telemetry stream consumers (Non-default route-domain).

Environment

  • BIG IP
  • Telemetry stream

Cause

Function as design - The telemetry stream runs in host space, as such it doesn't use any route-domains routes configured.

It can only use TMM route-domain 0 (default route-domain ) and mgmt routes.

Recommended Actions

The workaround suggested is to use an iRule to divert traffic from route-domain 0 (zero) to another none default route domain. To do that,  you will need to disable route domain isolation.

Note: Using route-domain isolation, may have a security risk that needs strict isolation.

  1. Create a virtual server that shares IP address with one of the TS consumers
  2. Attached an iRule to this VS that will send traffic to a particular node that resides in a different route-domain (e.g, node 10.10.0.2%2)
  3. Disable route-domain isolation

Additional Information

An example of irule:

when CLIENT_ACCEPTED {
pool <consumer pool in RD2>%2 
}
