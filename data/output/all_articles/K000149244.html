K000149244: Creating a packet capture for the management interface on F5OS for a rSeries Appliance.

Description

You may need to check traffic that is routed on the management interface of your rSeries.  Such as Active Directory Auth traffic, or maybe for some other flow that routes over the management interface for F5OS. However, using the steps from K12313135 do not work to catch traffic on eth0 or mgmt. Trying to do so you may receive error messages such as...

R10900-R80-S7# system diagnostics tcpdump interface eth0                                                            
running  /usr/sbin/tcpdump -i eth0
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on eth0, link-type EN10MB (Ethernet), snapshot length 262144 bytes
 errbuf ERROR:Interface name can only be "0.0", "Port.SubPort", or a lag name
tcpdump: pcap_loop: Interface name can only be "0.0", "Port.SubPort", or a lag name

R10900-R80-S7# system diagnostics tcpdump interface mgmt
running  /usr/sbin/tcpdump -i mgmt
tcpdump: verbose output suppressed, use -v[v]... for full protocol decode
listening on mgmt, link-type EN10MB (Ethernet), snapshot length 262144 bytes
 errbuf ERROR:Interface name can only be "0.0", "Port.SubPort", or a lag name
tcpdump: pcap_loop: Interface name can only be "0.0", "Port.SubPort", or a lag name

Environment

Troubleshooting/inspecting traffic that uses the management interface for F5OS.

Cause

With F5OS many functions are not available unless you are in the correct shell. WithinF5OS there is no direct access to the Linux kernel and sudo does not work on F5OS. If you log in as admin then you are using the F5 operating system. If you log in as the local root you are using the Linux kernel and thus management. This is a bit of an over-simplification but it applies for this usage.

Recommended Actions

In order to capture traffic on the management interface of the rSeries platform it is nearly identical to Classic BIG-IP (cBIP). However, you have to log in with the local root user and password.

1) Log in to the CLI using the local root user and password on the rSeries host/controller.

2) Create the syntax to capture the traffic. For example for Active Directory you may use something like this...

[root@appliance-1(R10900-R80-S7):Active] ~ # tcpdump -s0 -nni mgmt '(host 10.126.10.34 and port 636)'
tcpdump: verbose output suppressed, use -v or -vv for full protocol decode
listening on mgmt, link-type EN10MB (Ethernet), capture size 262144 bytes
Got 45

For the interface it has to be mgmt and not eth0. If you use eth0...

[root@appliance-1(R10900-R80-S7):Active] ~ # tcpdump -s0 -nni eth0 '(host 192.1.1.1 and port 636)'
tcpdump: eth0: No such device exists
(SIOCGIFHWADDR: No such device

3) If it needs to go to a file there is a specific directory for captures.../var/shared/tcpdump. The classic /var/tmp that has been often used for the file in cBIP was a symbolic link to /shared/tmp, and /shared off of root no longer exists. There is now just a standard path for /var/tmp. It has other usages, but you can use it. So in most cases it may be best to use what has been established and something like this...

[root@appliance-1(R10900-R80-S7):Active] ~ # tcpdump -s0 -nni mgmt '(host 192.1.1.1 and port 636)' -vw /var/shared/tcpdump/test.pcap
tcpdump: listening on mgmt, link-type EN10MB (Ethernet), capture size 262144 bytes
Got 52

4) To retrieve the file you can login using an scp app with the same credentials and scp it off.
