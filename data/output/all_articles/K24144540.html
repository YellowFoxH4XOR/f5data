Topic

This article lists error messages you may encounter when configuring the BIG-IP APM system as an OAuth client, a resource server, or both, and the recommended actions you can perform.

When troubleshooting OAuth 2.0 with the BIG-IP APM system as OAuth client or resource server, you may need to set up an environment with OAuth 2.0 authorization to reproduce the error messages you encounter. In addition, to address each error message in this article, you may need to re-configure an OAuth resource. Use the following articles to do so:

  • K12744365: Quick deployment: BIG-IP APM API protection virtual server with Postman as OAuth client using Azure AD.
  • K53313351: Configuring BIG-IP APM as OAuth client with Azure AD OAuth authorization server
  • K25101870: Configuring BIG-IP APM as OAuth client with Google OAuth authorization server
  • K14391041: Configuring an OAuth setup using one BIG-IP APM system as an OAuth authorization server and another as the OAuth client

Description

The following table lists error messages, explanations, and recommended actions when you configure the BIG-IP APM system as an OAuth client or resource server.

For more OAuth error messages and their explanations, refer to the OAuth Client and Resource Server chapter of the BIG-IP Access Policy Manager: Authentication and Single Sign-On manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5. 

Important: You may encounter errors when using Microsoft identity platform 1.0, Azure Active Directory (AD). In that case, before troubleshooting further, you should use MS identity platform 2.0. With its release, the previous version, Microsoft identity platform 1.0, is deprecated. For differences between the two, refer to Why update to Microsoft identity platform (v2.0).

Error message in /var/log/apmPossible explanationsRecommended actions
01490290:3: [...] OAuth Scope: failed for jwt-provider-list '<name>' error: Internal error during signature verification

01870003:6: [...] Bearer error="invalid_token",error_description="Internal error during signature verification"

01490290:3: [...] OAuth Scope: failed for jwt-provider-list '/Common/<name>' , error: Signature verification failed for all the provided JWK keys

The access token the OAuth client received from the provider and presented to the OAuth resource server is not valid and failed signature verification.

This can happen when the OAuth client is not configured correctly and does not set the required parameters in the access token. This can happen when the Scope value is set incorrectly.

These errors mostly appear when you configure Internal validation in an OAuth Scope agent on the BIG-IP APM system. The details of the access token validation is logged.		If the access token is not opaque, use a sample JWT debugger to decode the token. For a valid token, you should observe a Signature Verified message from the JWT debugger. Observe that the Audience value may be incorrectly set. For example, it may be set to a string of 0s rather than a valid ID such as the client ID.

Review the configuration of the OAuth client resource:

  • If the BIG-IP APM system is the resource server validating the token, first ensure that the access token is valid before presenting it to the BIG-IP APM system for validation. Review the parameter values, in particular the Scope resource provided in your OAuth client.  
  • If the BIG-IP APM system is the OAuth client, configure the correct values, in particular Scope. You may find an OAuth Client agent in the access policy of the BIG-IP APM.

For social media providers, you can retrieve the Scope value on the App registration page. In Azure AD, the scope value may have the following syntax:

api://<client ID>/<scope name>

To see an example of using Postman as the OAuth client, refer to the Use Postman to send API requests with access token procedure in K12744365: Quick deployment: BIG-IP APM API protection virtual server with Postman as OAuth client using Azure AD
01870003:6: /Common/<profile name>: [...] value: Bearer error="invalid_token",error_description="JWT expired"The access token has expired and is no longer valid.Get a new token by logging out and logging back in to the application.
01870003:6: [...]Bearer error="invalid_token",error_description="Invalid JWS token"

01870003:6: [...] Bearer error="invalid_token",error_description="HTTP error 400, Error: Invalid Value"

An invalid access token is presented to the BIG-IP APM system which is validating the token.

This may be due to any of the cases described previously. These errors appear mostly when you configure External validation in a OAuth Scope agent on the BIG-IP APM system. A generic error Invalid value is logged.

Perform the actions recommended previously.

The format of an opaque token is proprietary. To validate these tokens, you need to contact the Authorization Server that issued the token. To configure BIG-IP APM to validate opaque tokens, in your OAuth Scope agent in the policy, for Token Validation Mode, select External.

01490290:3 error: Issuer Mismatch : Claim issuer= https://login.microsoftonline.com/<ID>/v2.0 Provider issuer= https://sts.windows.net/<ID>/

The issuer in the token does not match the issuer in the provider configured.

In this example, the claim issuer is configured to use MS Azure AD 2.0 while the provider issuer is using 1.0.
  • Verify that the OpenID URI used in the provider configuration is using the same issuer as the one configured when requesting for the access token. For example, if the OAuth client's URIs use 2.0, the OpenID URI must use 2.0 as well.

    To use the OpenID URI configuration on the BIG-IP APM system, go to Access > Federation > OAuth Client/Resource Server > Provider

  • This may occur when you use MS identity platform 1.0. This is deprecated and replaced by 2.0. Change to 2.0.

    If you must use 1.0,  you must configure the manifest as described in the last step of the Configuring an application in Azure AD portal procedure in K53313351: Configuring BIG-IP APM as OAuth client with Azure AD OAuth authorization server.

01490290:3: OAuth Scope: failed for jwt-provider-list '/Common/<name>' , error: Audience not found : Claim audience= <ID> JWT_Config Audience=The Audience value in the access token does not match the one configured in the JWT configuration.

In this example, the JWT configuration resides on the BIG-IP APM system and is not configured. 

Configure the JWT configuration with an Audience value that matches the one in the OAuth client requesting the access token. In most cases, this is the client ID found in the provider portal.

To use the JWT configuration on the BIG-IP APM system, go to Access > Federation > JSON Web Token : Token Configuration.

OAuth provider login page error:
AADSTS50011: The redirect URI 'https://<URI>/oauth/client/redirect' specified in the request does not match the redirect URIs configured for the application 'clientID'		The redirect URI https://<URI> specified in the request does not match the redirect URIs configured for the application <ID> in the OAuth provider

When authenticating with the provider, the specified redirect URI in the OAuth client is not registered with the provider. 

Register the redirect URI at the provider portal as a Web application. For examples to do so, refer to K53313351: Configuring BIG-IP APM as OAuth client with Azure AD OAuth authorization server and K25101870: Configuring BIG-IP APM as OAuth client with Google OAuth authorization server.

In BIG-IP APM as OAuth client, the redirect client URI can be found in the OAuth Client agent in the access policy.
