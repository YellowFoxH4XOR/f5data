K000135648: Blade FAILED and rejoined the cluster

Type
Support Solution
Published
2023-08-03
Updated
2023-08-15
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000135648

Description

Primary Blade reporting that a Peer Blade has failed and rejoined the cluster.

For example, where Blade 1 is the primary blade, and Blade 4 is the failing blade:

Notice slot1/LTM1.example.com clusterd[6345]: 013a0006:5: Blade status: 3 GREEN 0 YELLOW 0 Not Ready
Error slot1/LTM1.example.com clusterd[6345]: 013a0014:3: Blade 1: blade 4 FAILED
Warn slot1/LTM1.example.com chmand[4479]: 012a0004:4: Blade 4 status: plugged in,no fault,not powered up,action:BROADCAST_MSG|BIGIP_NOMINAL_CONDITION|
Notice slot1/LTM1.example.com clusterd[6345]: 013a0010:5: Blade 1: blade 4 powered up.
Info slot4/LTM1.example.com clusterd[8739]: 013a0023:6: Blade 4: No info received from slot: Starting up
Notice slot1/LTM1.example.com clusterd[6345]: 013a0012:5: Blade 1: blade 4 up
Notice slot4/LTM1.example.com clusterd[8739]: 013a0015:5: Blade 4 quorum state increasing from QUORUM to RUNNING.
Notice slot4/LTM1.example.com clusterd[8739]: 013a0020:5: Blade 4 turned Green: Run

Environment

  • Viprion with at least 2 blades in the chassis
  • EUD checked, no hardware errors
  • no other failing reason in the logs
  • blade is starting without additional errors and rejoining the cluster automatically without additional errors
  • high CPU control plane usage in primary blade at that time

Cause

Because of high CPU control plane usage in primary blade, causes losing messages from other blades and falsely declare those as failed.

Recommended Actions

  • troubleshoot the cause of high CPU control plane usage in primary blade vcmp HOST and vcmp GUESTs
  • lowering the vcmp HOST and GUESTs control plane usage should help resolve the issue
  • check well know bug IDs for vcmp HOST and corresponding GUESTs, which may be responsible for additional CPU control plane load
For further guidance, please see the related content section below.

Additional Information

There can be various causes of failing blades, please exclude those first, by performing the EUD, checking the logs and console outputs while the blade is starting.
