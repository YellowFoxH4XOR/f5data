Topic

When a core file is created on an ARX system, the following factors may prevent the ARX system from saving the core file:

  • The amount of space available in the core partition
  • The core file storage limit

Note: A previously saved core file will not be deleted to make room for a new core file.

When the core file is created, syslog will contain messages that indicate the core file was collected and is being written (saved).

For example:

:TCORED-0-NOTE-TCORED_COLLECTING:: Start collecting core '/acopia/var/core/temp_nsmCore.2780' from 169.254.220.4:41100.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 0, 65528 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 10000, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 20000, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 30000, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 40000, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 50000, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTING_DATA:: Core collecting to '/acopia/var/core/temp_nsmCore.2780' block 50865, 65536 bytes.
:TCORED-0-NOTE-TCORED_COLLECTED:: Done collecting core from processor 2.2, type 1480.
:CORE-0-ERR-CORE_NSM:: nsm[1]: [E:3] Writing core file.

However, if the ARX system encounters either insufficient space in the core partition or the core file storage limit is reached, the system will delete and not save the collected core file to the core partition.

You can use the show cores command to display which core files have been saved. The output appears similar to the following example:

  cores
      core-0001.dmp           Aug  4 07:41  642 MB
      core-0002.dmp           Aug  4 07:54  642 MB
      core-0003.dmp           Aug  4 08:00  643 MB
      core-0004.dmp           Aug  4 08:06  643 MB
      core-0005.dmp           Aug  4 08:17  348 kB

Note: When identifying a core file with a corresponding syslog message, the syslog message uses a UTC timestamp, while the show cores command output will use local time.

Amount of space available in the core partition

If the core partition does not have sufficiant free space to save a collected core file, the system deletes the core file and does not save the file to the core partition. When the system deletes the core file as a result of insufficient space in the core partition, the system logs an error message to the syslog file that appears similar to the following example:

:COMMONLIB-0-ERR-MSG3:: CORECOLLECT:16052:Free disk space on /acopia/var/core is less than 786432. Deleting core file(/acopia/var/core/saved_cores/sm-2-3_nsm.1)

The show chassis diskinfo command displays the amount of space allocated, used, and available for the core partition (Cores; DiagInfo; Lists). The command output appears similar to the following example:

Disk Usage:
Name                              Total MB    Used MB     Free MB     Used%

Core file storage limit

The core file storage limit is the maximum amount of space within the core partition that may be used for core files. The amount of space allocated for core files is limited because the core partition is also used for other files, such as diagnostic information files.

For ARX versions 5.x and earlier, the core file storage limit is 3 GB. Therefore, even if 21 GB is allocated for the core partition, 3 GB is the a maximum of amount of core files stored on the ARX system.

The core file storage limit was increased in ARX version 6.0.0. The new limit is the total space allocated to the core partition, minus 2 GB. For example, if the total space allocated for the core partition is 21 GB, the core file storage limit is 19 GB.

Note: The increased amount of space allocated for core files in the core partition will greatly reduce the likelihood of the system not saving the core file as a result of exceeding the core file storage limit.

When the ARX system attempts to save a collected core file, if the total amount of space consumed by core files is greater than the core file storage limit, the system deletes the collected core file and logs a message that appears similar to the following example to the procdat file:

: CORECOLLECT:9370:insuffient space to save core files: deleting file(core-0006.dmp) - 0001 nsm-2-2.1                 8/8/2011 17:0:42           76130

Important: Because the system does not log this message to the syslog file, this condition may be more difficult to identify when the core file is not saved as indicated in the syslog file.

The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Networks Support.
