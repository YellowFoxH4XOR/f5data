Topic

You should consider using these procedures under the following conditions:

  • You want to use the iControl representation state transfer (REST) application programming interface (API) to install new component updates for BIG-IP ASM components.
  • Your BIG-IP system is configured to automatically download component update files.
  • You manually upload component update files to your BIG-IP system.

Description

In BIG-IP 14.1.0 and later versions, you can configure the BIG-IP ASM system to automatically download and install individual BIG-IP ASM component files. You can also configure the system to install downloaded update component files based on a schedule. The following procedures outline installing the BIG-IP ASM component update files using the iControl REST API so that you can manually install the update files without configuring the BIG-IP ASM system to install the update component files using the scheduler.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the BIG-IP ASM Configuration utility.

Procedures

  • Check and retrieve a component update file
  • Check the availability of a component update file on the local system
  • Determine the availability of a BIG-IP ASM component update file
  • Install a new component update file
  • Delete unused component update files

This article uses the following substitution for common command syntax examples:

  • <PATCH> = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PATCH  https://<big-ip address>
  • <GET> = curl -sk -u admin:<password>   -H "Content-Type: application/json" -X GET https://<big-ip address>
  • <DELETE> =  curl -sk -u admin:<password>   -H "Content-Type: application/json" -X DELETE https://<big-ip address>

Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output. The period parameter is optional in jq 1.5 and later.

Check and retrieve a component update file

Use the following procedure to initiate the BIG-IP ASM system to check with F5 and retrieve a BIG-IP ASM update file when a file for the specified component type is available:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To have the BIG-IP ASM system check for and retrieve a new component update file, use the following syntax replacing <component update file type> with the appropriate value from the previous table:

<PATCH> /mgmt/tm/live-update/<component update file type>/availability  -d '{"status": "check"}' | jq -M .

Note: Component update file retrieval can take a few minutes, depending on file size. Be sure to note the status returned for the action prior to attempting to install a component update file.

Example of checking and, when available, retrieving a component update file for ASM attack signatures:

curl -k -u admin:admin -H "Content-type: application/json" -X PATCH "https://192.168.1.81/mgmt/tm/live-update/asm-attack-signatures/availability" -d '{"status": "check"}' | jq -M .

Check the availability of a component update file on the local system

After you have retrieved the component update file from F5, you can check the availability of the downloaded component file by querying the live-update database on the local system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To have the BIG-IP ASM system check the availability of the new component update file on the local system, use the following syntax replacing <component update file type> with the appropriate value from the previous table:

<GET> /mgmt/tm/live-update/<component update file type>/availability | jq -M .

Example of checking the local database for the ASM attack signature update file:

curl -k -u admin:admin -X GET https://192.168.1.81/mgmt/tm/live-update/asm-attack-signatures/availability | jq -M .

For example, after running the previous command, the following output reports that the ASM-AttackSignatures_20220629_141851.im update file was retrieved and downloaded to the local database:

Determine the latest version and availability of a BIG-IP ASM component update file

Use the following procedure to retrieve a list of downloaded component update files for the specific BIG-IP ASM component update types.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

<GET>/mgmt/tm/live-update/<component update file type>/installations | jq -M .

Note: Replace <big-ip address> with the IP address of your BIG-IP system, and replace <component update file type> with the update function file type name from the previous table.

Example of locating a component update file for Browser Challenges:

Install a new component update file

After you have determined the latest BIG-IP ASM component update file ID value, you can use the following REST command syntax to install the component update file.

Impact of procedure: Installing a component update file applies the component update to the active configuration. The component update is applied to requests that match the BIG-IP component of the related component update.

To install the identified component update file using REST, use the following syntax:

<PATCH>/mgmt/tm/live-update/<component update file type>/installations/<file id>"  -d '{"status": "install"}'

Note: Replace <big-ip address> with the IP address of your BIG-IP system, and replace <component update file type> with the update function file type name from the previous table.

Replace <file id> with the value of "id": found in the previous procedure.

Note: You can also set a component update file to stage by changing the syntax from '{"status" : "install"}' to '{"status": "stage"}.

Example of installing the latest Browser Challenges update file:

curl -k -u admin:admin -H "Content-type: application/json" -X PATCH "https://192.168.1.81/mgmt/tm/live-update/browser-challenges/installations/ff8080817145a0b7017145a1800b0003" -d '{"status": "install"}'

Note: You can view the installation status by re-executing the REST component update file installation command.

Possible returned status may include "Installation is already staged", "staged", "install-in-progress", "install-complete", "previously-installed" and "error".

Delete unused component update files

You can delete previously downloaded component update files that are not installed or staged on the BIG-IP ASM system.

Impact of procedure: The component update file is removed from the BIG-IP ASM system and is no longer available for installation.

Use the following REST command syntax to retrieve a list of downloaded files for a specific component:

<GET>/mgmt/tm/live-update/<component update file type>/update-files

Example list for BIG-IP ASM attack signature files:

curl -k -u admin:admin -X GET https://192.168.1.81/mgmt/tm/live-update/asm-attack-signatures/update-files | jq -M .

Locate the "id" value of the file you want to delete and use the following REST command syntax to delete the file from the BIG-IP ASM system:

<DELETE>/mgmt/tm/live-update/asm-attack-signatures/update-files/<file id>

Example of deletion of file id ff808081714187c901714187c9d90000:

curl -k -u admin:admin -X DELETE https://192.168.1.81/mgmt/tm/live-update/asm-attack-signatures/update-files/ff808081714187c901714187c9d90000

Note: When you attempt to delete a component update file that the system has used, the system displays an error message describing why the deletion failed.
