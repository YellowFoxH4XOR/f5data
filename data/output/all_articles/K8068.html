Known Issue

This is the result of a known issue. The event daemon uses iControl messaging to provide asynchronous event notification to subscribers. For example, the Enterprise Manager system subscribes to the eventd process, and uses the eventd process to trigger device information updates. Under certain conditions, the eventd process fails to clear the subscriber event list when the subscriber is disabled, resulting in increased memory usage for the daemon.

The eventd process keeps a queue of subscriber events in system memory. If a subscriber is unreachable, the eventd process attempts to deliver the subscriber's event list five times before disabling the subscriber. When the subscriber is finally disabled, the eventd process neglects to clear the subscriber's event list, causing the eventd process to consume potentially large amounts of memory for the remainder of its lifetime. In some cases, the increased memory pressure leads to switchboard failsafe.

F5 Networks Product Development tracked this issue as CR81826 and it was fixed in BIG-IP versions 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.1.3-HF1 issued for BIG-IP version 9.1.3, and in Hotfix-BIG-IP-9.4.3-HF2 issued for BIG-IP version 9.4.3. You may download these hotfixes or later versions of these hotfixes from the F5 Networks Downloads site.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about managing F5 Networks product hotfixes, refer to K6845: Managing F5 Networks product hotfixes.

Workaround

If you have observed that the eventd process is consuming an increasing amount of memory, you can temporarily work around this issue by restarting the eventd process. To do so, type the following command:

bigstart restart eventd
