Description

Connection to TCP virtual server is reset with "VIP disabled (administrative)"
  • TCP virtual server responds to connection requests with RST.
  • Viewing the RST in tcpdump or Wireshark indicates the RST reason is:

BIG-IP: [0x289aa93:2267] VIP disabled (administrative)

  • However the virtual server is not disabled.

Environment

  • TCP virtual server enabled on a specific VLAN
  • The VLAN does not have a self IP address on the subnet of the TCP virtual server
Cause

The virtual server has been enabled on a specific VLAN that does not have an IP address on the same subnet as the virtual server destination address.
For example:

ltm virtual /Common/example {
    destination /Common/10.20.1.1:80
    ip-protocol tcp
    mask 255.255.255.255
    vlans {
        /Common/External
    }
    vlans-enabled
}

If the VLAN /Common/External does not have a self IP address on the same subnet as the 10.20.1.1 virtual server address, connections to the virtual server will be RST with "Reset cause: BIG-IP: [0x289aa93:2267] VIP disabled (administrative)"

Recommended Actions

Configure a self IP on the specified VLAN that matches the subnet of the virtual server destination IP address.
