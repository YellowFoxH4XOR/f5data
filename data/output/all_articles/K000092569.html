K000092569: ASM incremental manual sync results in a sync recovery state and full sync being initiated

Type
Support Solution
Published
2022-11-07
Updated
2024-09-27
Source
https://my.f5.com/manage/s/article/K000092569

Description

  • ASM incremental manual sync results in a sync recovery state and full sync being initiated
  • A full sync occurs despite the Device Group being configured as manual and incremental.
  • Error messages:
    • info asm_config_server_rpc_handler.pl[11878]: ASM is now entering sync recovery state. Requesting complete configuration from /<partition>/<peer.Device.Hostname>

Environment

  • ASM provisioned
  • Device Group used for ASM synchronization is configured with Manual with Incremental sync type

Cause

This is expected behavior and by design. There is no incremental synchronization when a device group has ASM sync enabled and is configured for Manual with Incremental sync type. Any sync initiated with a device group configured in this manner will result in an ASM sync recovery state resulting in a full configuration sync being requested and received.

 Recommended Actions

If you want to avoid a full sync, configure the device group for Automatic with Incremental sync-type.

Additional Information

When it comes to multi-slot vCMP instances on VIPRION devices, it is important to note that, irrespective of the Sync Type employed within the Device Group for ASM synchronization, the synchronization between blades will invariably involve a complete UCS file load and full sync. This means that even when 'Automatic with Incremental Sync' type is used, there is no provision for incremental synchronization specifically for blade-to-blade sync.
