Description

AFM zero hit or stale rule refers to a situation in F5 BIG-IP Advanced Firewall Manager (AFM) where a firewall rule or policy shows a hit count of zero. This means that, according to the system statistics, no traffic has matched (or "hit") that rule since it was deployed or since the counters were last reset.

 

Common causes for zero hit count:

  • The rule is not correctly positioned in the rule list, so other rules are matching the traffic first.
  • The rule's criteria (source, destination, protocol, etc.) do not match any current traffic.
  • There may be a configuration or routing issue preventing traffic from reaching the rule.
  • In rare cases, software bugs can cause the hit count to remain at zero even when traffic should match the rule, e.g., K73247815.
 
CAUTION: If you intend to remove a rule that is infrequently or never hit, ensure that doing so will not create a security issue, and that a backup has been created beforehand. A rule may be triggered rarely, but it could still be a critical part of your security posture against specific or uncommon attacks.

 

Environment

  • BIG-IP AFM

 

Cause

None

 

Recommended Actions

To view the zero hit (stale) rules: 

 

Via GUI/Configuration Utility:

  1. Go to Security > Network Firewall > Active Rules in the BIG-IP GUI.
  2. Check the "Count" column for each rule.
  3. Review the "Latest Match" column to see when the rule was last hit.

[root@BIGIP::Active:Standalone] config # curl -s -k -u admin:admin  -H "Content-Type: application/json" -X GET https://localhost/mgmt/tm/security/firewall/rule-stat | jq -r '.entries | to_entries[] | .value.nestedStats.entries | [.action.description,.actualRule.description,.contextName.description,.contextType.description,.counter.value,.lastHitTimeFmt.description,.ruleListName.description,.ruleName.description,.ruleStatType.description,.useridValidation.description] | @csv'
