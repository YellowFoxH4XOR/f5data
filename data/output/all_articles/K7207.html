K7207: When using compression in an HTTP profile, the BIG-IP LTM system may not properly close some HTTP/1.0 connections

Known Issue

This is the result of a known issue. When using compression in an HTTP profile, the BIG-IP LTM system may return all of the response data to the client, including the Connection: close header, but not return the FIN packet to HTTP/1.0 clients. This issue is limited to HTTP/1.0 keep-alive connections when selective rechunk is enabled in the HTTP profile.

Note: The HTTP profile does not enable compression for HTTP/1.0 client connections by default.

F5 Networks Product Development tracked this issue as CR73277, and it was fixed in BIG-IP LTM version 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.
