Description

When testing Telemetry Streaming configuration for Splunk:

  • CloudDocs Home > Telemetry Streaming > Push Consumer  
{
    "class": "Telemetry",
    "My_Consumer": {
        "class": "Telemetry_Consumer",
        "type": "Splunk",
        "host": "192.0.2.1",
        "protocol": "https",
        "port": 8088,
        "passphrase": {
            "cipherText": "apikey"
        },
        "compressionType": "gzip"
    }
}

For example, If "" is missing for the host IP address,

{
    "class": "Telemetry",
    "My_Consumer": {
        "class": "Telemetry_Consumer",
        "type": "Splunk",
        "host": 192.0.2.1,
        "protocol": "https",
        "port": 8088,
        "passphrase": {
            "cipherText": "apikey"
        },
        "compressionType": "gzip"
    }
}
 
It will return error messages similar as below:
{
  "code": 500,
  "message": "Unexpected token . in JSON at position 131",
  "referer": "restnoded",
  "originalRequestBody": "",
  "errorStack": []
}
 

Environment

  • BIG-IP v14
  • Telemetry Streaming 1.21.0 
 

Cause

When configuration is not successfully validated, it will return 500 error code which can also be found in /var/log/restnoded/restnoded.log:
GMT - severe: [HttpRestOperationResolver] Error in parsing http payload: {}
GMT - severe: [ErrorHandlingModule] RestOperation failed: "". {"code":500,"message":"Unexpected token . in JSON at position 131","referer":"restnoded","originalRequestBody":"","errorStack":[]}
 

Recommended Actions

  1. Check the /var/log/restnoded/restnoded.log for the detailed information
  2. Check the syntax for the configuration
