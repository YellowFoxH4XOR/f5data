Known Issue

Attempting to create or regenerate Domain Name System Security Extensions (DNSSEC) keys on a BIG-IP GTM system with FIPS hardware may result in keys that are not stored in the FIPS hardware security module (HSM).

This issue occurs when either of the following conditions are met:

  • You attempt to create new DNSSEC Key Signing Keys (KSK) or Zone Signing Keys (ZSK)
  • DNSSEC KSK or ZSK created on a previous version are regenerated during a rollover period

In addition, all of the following conditions are met:

  • The BIG-IP platform contains the FIPS HSM
  • The DNSSEC keys have the FIPS option enabled
  • The DNSSEC key names are 15 characters or longer

This issue does not prevent the system from creating or regenerating the DNSSEC keys. However, the keys are not stored in the FIPS HSM as expected.

Impact

The new or regenerated DNSSEC keys are not stored in the FIPS HSM and may not be protected from physical and software attacks.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system logs error messages to the /var/log/ltm file. The error messages appear similar to the following examples:

    mcpd[5392]: 01071392:3: Background command '/usr/bin/fipskey gen64 dnssec-_Common_This-Is-15Chars 1024' failed. The command exited with status -4.
    mcpd[5392]: 010713e9:3: Key could not be parsed: public key output not in expected format; [Key name must be less than 31 characters].
    mcpd[5392]: 010713e7:3: FIPS manager key (dnssec-_Common_This-Is-15Chars) create failed, retry attempt 2.
  • The new or regenerated DNSSEC keys are not stored in the FIPS HSM

Resolution

Workaround

You can work around this issue by regenerating new DNSSEC keys with key names 14 characters or less in length.
