K12563: HTTP Compression Exclude List takes precedence over BIG-IP WebAccelerator compression

Known Issue

This is the result of a known issue. If you configure an object for compression in the BIG-IP WebAccelerator system and the same object is configured in the Compression Exclude List of the associated HTTP profile, the Compression Exclude List HTTP profile will take precedence. As a result, the BIG-IP WebAccelerator returns the object uncompressed to the client.

For example, if you configure the text/html object type in the Compression Exclude List of the http-compress-excludelist HTTP profile and this object is configured with Enable Content Compression in the Assembly tab of the acceleration policy, the BIG-IP WebAccelerator returns the object to the client without Content-Encoding: gzip, as you can see in the following example:

profile http http-compress-excludelist {
defaults from http
compress enable
compress content type include "application/(xml|x-javascript)"
compress content type exclude "text/html"
}

F5 Product Development tracked this issue as ID 345472, and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator or Edge Gateway release notes.

Workaround

You can work around this issue by removing the conflicting object from the associated Compression Exclude List HTTP profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility using a privileged account, such as admin.
  2. Click Local Traffic.
  3. Click Profiles > Services > HTTP.
  4. Click on the affected HTTP profile.
  5. Under the Compression section, locate Exclude List for the Content List parameter.
  6. Click on the affected object in Exclude List.
  7. To remove the affected object, click Delete.
  8. To save the modification, click Update.
