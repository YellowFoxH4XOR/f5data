Known Issue

The BIG-IP APM /var/log/httpd/access_log file may not contain data.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access policy that actively processes user sessions.
  • Your BIG-IP APM system has already run the daily log rotation (default time is 4:02 AM).
  • User sessions are processed after the daily log rotation.

Impact

Access logs are no longer written to the /var/log/httpd/access_log file.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After the BIG-IP APM system has completed a daily log rotation, the /var/log/httpd/access_log file is not updated and remains empty.

Workaround

To work around this issue, you can configure a cron job on the BIG-IP APM system to restart the httpd_apm service after the daily log rotation. To do so, perform the following procedure:

Impact of workaround: Restarting the httpd_apm service may impact active user sessions.

  1. Log in to the command line of the BIG-IP APM system with administrative privileges.
  2. Using a text editor, open the /etc/crontab file.
  3. Append the following line after the /etc/cron.daily crontab entry:

    30 4 * * * root /usr/bin/bigstart restart httpd_apm
  4. Save the crontab file changes.
