Topic

F5 has recently discovered and corrected a number of issues that affect customers running ARX 5.2.2. F5 recommends that all customers currently running version 5.2.2 install the latest cumulative rollup hotfix available.

The following table lists the rollup hotfixes available for ARX 5.2.2. Each hotfix lists the ID number and description for the issues fixed by the hotfix:

Note: These rollup hotfixes are cumulative. Therefore, each hotfix contains the fixes included in the previous hotfixes.

NSM encountered an assertion failure when trying to insert a CIFS transaction record into internal database. NSM has been enhanced to avoid a core in this scenario.
   
**5.2.2 HFRU15 (build-12704)406544
Various commands that are intended to modify an existing configuration object erroneously create an invalid partially-initialized object if applied to a non-existing object. This can happen if an object (namespace, volume, or share) is deleted in one session, while there is a CLI session currently in that configuration mode. The result is an invalid global-config that cannot be repaired or modified. This problem has been fixed.
408283Fixed an assertion failure problem in the handling of client requests that caused NSM to core.
408318Due to a bug in the kernel scheduler, two CPUs on the control plane could get into a race and block clock interrupts, causing the ARX to lock. The watchdog timer would time out and disable the links on the switch ports.  This issue has been fixed.
413480A problem that existed with a snapshot process starting in the middle of a switch replacement rendezvous and causing a failure to rejoin, has been fixed.
413481During HA rendezvous, when redundancy is first enabled, it is possible to set "no enable" redundancy on the ARX system that will become the backup switch before it is fully established.  As part of rolling back redundancy, all global scope data is removed from the joining ARX system. It was previously possible for a database transaction conflict to prevent removal of this data.  This would cause numerous split-brain conditions when the joining ARX system resumed stand-alone function.
In this situation, the joining ARX system now reboots on failure to clear all global scope data.  The data is then automatically removed during restart.
416424The ARX now recognizes and reacts properly to the response "Use of vfilers requires a multistore license" from a NetApp filer.
