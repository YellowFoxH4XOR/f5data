Issue

Old Behavior

In versions prior to 11.6.0, if the Server Name setting is not defined in the Client SSL profile, the BIG-IP system will use the common name (CN) from the server Secure Sockets Layer (SSL) certificate. The CN is embedded in the Server SSL certificate and is used for name-based authentication.

New Behavior

Beginning in 11.6.0, if the Server Name setting is not defined in the Client SSL profile, the BIG-IP system will use multiple hostnames from the Subject Alternative Name (SAN) field, and will also continue to use the CN from the server SSL certificate. The SAN is embedded in the Server SSL certificate and is used for name-based authentication.

Note: The SAN attribute may contain other information, such as IP addresses or URI. However, only the SAN Hostname is used for this feature enhancement.

Impact

The BIG-IP system now reads the CN and the SAN hostname fields from the certificate if you do not configure the Server Name setting.

Recommended Actions

If you want the BIG-IP system to use the hostname in the SAN field from the SSL certificate, you must clear the Server Name box in the Client SSL profile.
