Known Issue

Application traffic through a BIG-IP APM Network Access VPN tunnel may fail to be routed through a configured proxy server.

This issue occurs when all of the following conditions are met:

  • A Windows 10 (version 1703 or later) client establishes a Network Access VPN tunnel connection from a browser or the BIG-IP Edge Client.
  • The Windows 10 client is configured for a Unicode language (Japanese, Korean, Chinese, or similar) for non-Unicode programs.
  • Client proxy settings are configured in the Network Access policy settings, or the client is configured to use a proxy prior to establishing the VPN tunnel.

When establishing the VPN connection, the dial-up adapter name is written to the client's Windows registry with corrupted values if it contains localized (multibyte) characters. As a result, when the F5 VPN adapter for the VPN tunnel is created on the client, the adapter name does not match the corrupted registry values.

Impact

Proxy settings are not applied on client side after VPN is established.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Application traffic through a Network Access VPN tunnel that previously worked begins failing after applying a Windows Group Policy (GPO) update to version 1703 or later.
  • Application traffic through a Network Access VPN tunnel that is expected to be routed through a proxy server fails.
  • The client proxy settings configured in the Network Access policy settings or PAC file are not applied to the VPN tunnel network settings.
  • An error message similar to the following is logged in the %temp%/logterminal.txt file on the client:

    9720,9288,DIALER, 1, , 6371, CURDialer::PatchValue, Cannot set internet options (error: 0)

Workaround

To work around this issue, you can either configure the client to use English for non-Unicode programs or configure the BIG-IP APM access policy to use a custom variable to specify the F5 VPN adapter name that the client creates. To do so, perform one the following procedures:

  • Configuring client language for non-Unicode programs
  • Configuring the access policy to use custom variable

Configuring client language for non-Unicode programs

To configure the Windows 10 client to use English for non-Unicode programs, perform the following procedure:

Impact of workaround: The client system displays English text in programs that do not support Unicode.

  1. Open the Control Panel on the Windows client.
  2. Click Clock and Region.
  3. Click Region.
  4. Click the Administrative tab.
  5. Under Language for non-Unicode programs, click Change system locale.
  6. In the Current system locale list, click an English language.
  7. Click OK.

Configuring the access policy to use custom variable

To configure the access policy with a custom variable to specify the name the client uses for the F5 VPN adapter, perform the following procedure: 

Impact of workaround: Performing the following procedure should not have a negative impact on your system. However, F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).

    Note: For versions prior to BIG-IP 13.0.0, navigate to Access Policy > Access Profiles > Access Profiles List.

  3. Click Edit for the affected access policy to open the Visual Policy Editor.
  4. On a branch after the Logon policy item but before the resource is assigned, click the (+) icon to add an item.
  5. Click the Assignment tab.
  6. Click Variable Assign.
  7. Click Add Item.
  8. On the Properties page for the policy item, for Name, type a name for the policy item.
  9. Click Add new entry.
  10. Under Assignment click change.
  11. In the Custom Variable box, enter the following variable name syntax:

    config.connectivity_resource_network_access./Common/<network_access_resource_name>.client.ConnectionTrayIcon

    Note: Replace <network access resource name> with the name of the network access resource.

  12. In the Custom Expression box, enter the following expression syntax:

    return "</ConnectionTrayIcon><connection_name_txt>F5VPN</connection_name_txt><ConnectionTrayIcon>"

    Note: Replace <connection_name_txt> with the name of the adapter that the client creates.

  13. Click Finished.
  14. Click Save.
  15. Click Close to close the Visual Policy Editor.
  16. Select the check box next to the access policy you just edited.
  17. Click Apply Access Policy.

The next time the VPN is established, a new virtual adapter entry is created with the name provided in <connection_name_txt> tag.
