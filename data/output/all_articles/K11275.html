Known Issue

This is the result of a known issue. A Mac OS X user may be unable to connect to Network Access favorites if the Exclude subnets option has been configured. This issue is more pronounced when the IP addresses in the Exclude subnets options are public IP addresses. When the Exclude subnets option has been configured, the Mac OS X client is periodically unable to determine to which gateway the traffic should be sent. While this issue occurs more frequently with public IP address space, it can also occur with private IP address space.

F5 Product Development tracked this issue as ID 317663 (formerly CR133084), and it was fixed in FirePass 7.0.0.

This issue was fixed in cumulative hotfix HF-610-1 issued for FirePass version 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by disabling the Exclude subnets option located on the Client Settings tab of the Network Access: Resources page. When you disable this option, the traffic destined for the previously-excluded subnets will be sent to the FirePass controller if that traffic matches the split tunnel traffic configuration or if all traffic is configured to be tunneled.
