Description

After upgrading BIG-IP APM systems, the folders /var/apm/www and /var/apm/lib are missing, resulting in clients being unable to download necessary inspection files and failing endpoint checks. Error messages include "Access forbidden! You don't have permission to access the requested object" (HTTP 403) when attempting to download files such as OesisInspector.cab.

Environment

  • Product: BIG-IP APM

Cause

(Bug alias 2211137) [APM] EPSEC upgrade fails when default package pre-uploaded

When the default EPSEC package for the target upgrade version (e.g., epsec-1.0.0-1915.0.iso for 17.1.3) is uploaded but not installed on the previous version (e.g., 17.1.2), the upgrade process fails to properly install the EPSEC package. This results in missing /var/apm/www and /var/apm/lib folders, breaking client package downloads and endpoint checks.

Answer/Recommended Actions

  1. Workaround Steps:
    • If the default EPSEC package for the target version was uploaded but not installed before the upgrade, install a higher version of the EPSEC package after the upgrade.
    • Example: Install epsec-1.0.0-1963.0.iso (or any version higher than the default for the target upgrade).
    • After installation, verify that /var/apm/www and /var/apm/lib folders are restored and client package downloads work.
  2. General Recommendations:
    • When upgrading BIG-IP APM, ensure that any EPSEC package uploaded prior to upgrade is also installed, especially if it matches the default for the target version.
    • If a higher version EPSEC package is available, install it before or after the upgrade to avoid conflicts.
    • If folders remain missing after following the above steps, collect a fresh qkview and contact F5 Support for further analysis.
