Known Issue

This is the result of a known issue. The big3d_install utility is an interactive script designed to install the current or newer version of the big3d process on the remote F5 Networks system(s). The string comparison code used by the big3d process to determine the correct version to install to a remote system does not function correctly in version 9.x F5 Networks systems. As a result, when running the big3d_install utility between version 9.x and 10.x systems, the script may incorrectly skip a big3d installation or install an older version of the big3d process on a remote F5 Networks system.

The details of the incorrect behavior are described in the following three scenarios:

  • Running the big3d_install utility from a BIG-IP GTM version 10.x system to a remote BIG-IP LTM version 9.x system
  • Running the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.0.x system
  • Running the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.1.0 or later system

Running the big3d_install utility from a BIG-IP GTM version 10.x system to a remote BIG-IP LTM version 9.x system

If you run the big3d_install utility from a BIG-IP GTM version 10.x system to a remote BIG-IP LTM version 9.x system, big3d_install considers the 9.x version of big3d newer than the 10.x version of big3d, and skips the installation on the remote system. When the big3d installation is skipped on the remote F5 Networks device, iQuery communication is able to function as expected. This is because the version 10.x big3d process is backward compatible with the version 9.x big3d process running on the 9.x system.

Running the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.0.x system

Note: Running the big3d_install script from an F5 Networks device running an older version of software to an F5 Networks device running a newer version of software may occur if you run big3d_install without specifying an IP address of the remote device. If you run big3d_install without the IP address argument, the script will attempt to install big3d on all of the BIG-IP controllers listed in the /config/gtm/wideip.conf file.

If you run the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.0.x system, big3d_install considers the 9.x version of big3d newer than the 10.0.x version of big3d, and installs the 9.x version of big3d to the 10.0.x system. When the older version of big3d is copied to the remote F5 Networks system, iQuery communication is able to function as expected.

Running the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.1.0 or later system

If you run the big3d_install utility from a BIG-IP GTM version 9.x system to a remote BIG-IP LTM version 10.1.0 or later system, the 9.x version of big3d is copied to the remote BIG-IP LTM version 10.1.0 or later system.

Due to changes in the BIG-IP filesystem in version 10.1.0, big3d_install is unable to copy the version 9.x big3d process to the /usr/sbin/ directory on the version 10.1.0 or later system.

Note: The /usr/sbin/ directory is read-only in BIG-IP version 10.1.0 and later.

The script then copies big3d to the /shared/bin/ directory on the version 10.1.0 or later system, resulting in two versions of big3d running on the system. The 9.x version is installed to the /shared/bin/ directory and the 10.1.0 or later version is installed to the /usr/sbin/ directory. When the older version of big3d is copied to the remote 10.1.0 or later system, big3d continually restarts on the 10.1.0 or later system and an error message is logged to the console and the /var/log/daemon file that appears similar to the following example:

emerg logger: Re-starting big3d

Note: For more information about the Re-starting big3d error message, refer to K10999: Error Message: Re-starting big3d.

F5 Product Development tracked this issue as CR105417 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, GTM, or Link Controller release notes.

Note: Although the big3d_install script was updated to fix this issue in BIG-IP version 10.0.0, version 10.x systems can be adversely affected when running the big3d_install utility between version 9.x and 10.x systems as described in the above scenarios.

Workaround

The first two scenarios listed above do not require workarounds because big3d versions are backward compatible. For example, if you have a BIG-IP GTM version 10.0.1 system and a BIG-IP LTM version 9.4.8 system running different versions of big3d, iQuery communication will function properly.

If you encounter the third scenario, and the big3d process is continually restarting on the remote BIG-IP LTM system, you can work around the issue by performing the following procedure:

  1. Log in to the command line on the BIG-IP LTM version 10.1.0 or later system.
  2. Prevent big3d from attempting to restart by typing the following command:

    bigstart stop big3d

  3. Overwrite the version 9.x big3d with the version 10.1.0 or later big3d by typing the following command:

    cp /usr/sbin/big3d /shared/bin/

    Note: In BIG-IP GTM version 10.1.0 and later, big3d can run from either the /usr/sbin/ directory or the /shared/bin/ directory.

  4. Restart big3d by typing the following command:

    bigstart restart big3d
