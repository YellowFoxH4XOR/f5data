Known Issue

This is the result of a known issue. The BIG-IP system does not validate the rates configured for child rate classes, allowing the cumulative rates of child classes to exceed the rates configured for the parent class. This lack of validation may cause parent rate classes to become oversubscribed.

For example, the BIG-IP system should not load the following configuration:

rate class Parent {
rate 40Mbps
ceiling 40Mbps
type sfq
direction to client
}
rate class childA {
rate 40Mbps
ceiling 40Mbps
parent Parent
type sfq
direction to client
}
rate class childB {
rate 40Mbps
ceiling 40Mbps
parent Parent
type sfq
direction to client
}

However, the BIG-IP system loads the configuration with no errors.

F5 Product Development tracked this issue as CR101107 and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.
