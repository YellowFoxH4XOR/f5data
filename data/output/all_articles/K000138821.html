Description

When using Oauth with the BIG-IP as a Resource Server and EntraID (previously Azure AD) - when the user logs out of the BIG-IP it does not automatically remove/invalidate the users JWT token allowing them to login without re-entering credentials.

Environment

  • BIG-IP as OAuth Resource Server
  • EntraID as Authorization Server

Cause

The BIG-IP does not contain a mechanism to remove or revoke the users JWT token.

Recommended Actions

The can be resolved by redirecting the user to the logout URL provided by EntraID after the user logs out of APM.

Additional Information

The BIG-IP does not have a direct mechanisms to actually revoke users JWT token - however we can redirect the user to the EntraID logout URL after they logout of APM with the following iRule:
Sending the user to this URL will remove their session information from EntraID.

1.) Log into the BIG-IP Configuration Utility

2.) Navigate to: Local Traffic  ››  iRules : iRule List 

3.) Click Create... and add the following iRule:
Note: Ensure you update the "https://EntraID.ExampleURL.com/21dca27d-1390-46a4-b18e-468db144f3e1/b2c_1a_9_signup_signin/oauth2/v2.0/logout"  to the logout URL provided by EntraID.

when CLIENT_ACCEPTED { 
     ACCESS::restrict_irule_events disable
} 

when HTTP_REQUEST {
     if { ([HTTP::uri] contains "/vdesk/hangup.php3") } { 
          HTTP::respond 302 noserver Location "https://EntraID.ExampleURL.com/21dca27d-1390-46a4-b18e-468db144f3e1/b2c_1a_9_signup_signin/oauth2/v2.0/logout" 
     }
}
