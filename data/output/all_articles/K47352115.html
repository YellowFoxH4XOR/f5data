Description

Users are having issues connecting to the backend servers or see the internal website display in an unexpected way when being accessed via Portal Access.

Environment

  • APM
  • Portal Access

Cause

Recommended Actions

The primary area to look is within the F5 Rewrite profile at how the page is being rendered.
In order to do this, F5 needs to see the underlying HTML communication from end to end without APM, and With APM to determine the differences.

There are 2 distinct steps when troubleshooting Portal Access issues:
Important:  It is critical the user clear the browser cache before each test.
Any failure to do this will result in bad data and the tests will have to be re-done.

  1. Collecting a set of data going directly to the application showing the application working
    This will allow us to know what working is supposed to look like proir to going through Portal Access
    This will also allow us to recreate the issue in-house to do additional troubleshooting
    This should not be done via IP address, if needed enter a dummy host entry
     
  2. Collecting a set of data when connecting through APM Portal Access:

 

Test I going directly to the application bypassing APM: 
  1. Download and install HTTPWatch with the Chrome and/or Microsoft Edge plugins
    https://www.httpwatch.com/download/
     
  2. Start Chrome or Edge and change your home page to the URL, about:blank 
    This ensures when the browser re-opens it starts on a blank page
     
  3. From the Browser toolbar, Start Httpwatch Basic 
    HTTPWatch will open a window in a new window
     
  4. On the HTTPWatch control panel select
    Tools > Clear Cache and All Cookies
    Tools > Options > Recording >     Choose the radio button Automatically record when the browser opens a new tab
     
  5. Close the browser and re-launch
    This is to ensure any cached data still in memory is erased
     
  6. Use your choice of Windows Problem Step Recorder (PSR) or CamStudios to record your steps when reproducing the issue
     
  7. Begin collecting an HTTP Archive using the developer tools:
    K10370211: Generate an HTTP Archive using a browser
     
  8. Start the HTTPWatch recording
     
  9. Navigate the browser directly to the site with issues using the browser's address bar
    Do not go thru the Portal Access tunnel
     
  10. Perform the same steps that you would use to get to the failure point when going through APM, showing it working.
     
  11. Stop the HTTPWatch Recording
     
  12. On the HTTPWatch Toolbar, Select Save and save the recording in *.HWL format
    Please name it including direct in the filename
     
  13. Stop and save the PSR or CamStudio recording and Save as accordingly
    Please name it including direct in the filename


Test II going through APM Portal Access:

  1. Repeat steps 4-13, instead going to the HTTP URL for the APM Portal Access object.
    It is very important that the exact same steps are followed so the two recordings can be compared 
    Note:  In step 13, please save the APM Path file with via_apm in the filename
     

  2. If using a webtop the Portal Access resource will open in a new tab
    In order to get a proper recording, do not click on the Portal Access resource link but carefully read the below:

    Important: The very first requests are unfortunately never captured when a new tab opens following the click on a Portal Access resource.

    In order to get a perfect recording, you need to:
    • open a new tab manually
    • click on the httpwatch icon for that new tab (it will open a new httpwatch window for that tab specifically)
    • confirm it is recording
    • paste the same URL that would be opened when clicking on the Portal Access resource. In order to find out what that URL is, you need to know the Application URI of your Portal Access resource

Example of URL to paste:

  • Portal Access Application URI = https://www.example.com/login
  • Hex encoding of https://www.example.com (without any path) = 68747470733a2f2f7777772e6578616d706c652e636f6d (you can use any hex encoder available online to compute it)
  • Public fqdn of the VS where Portal Access is used: https://fqdn/

=> The URL to paste in the new tab will be: https://fqdn/f5-w-68747470733a2f2f7777772e6578616d706c652e636f6d$$/login

 

Via the BIG-IP CLI:

  1. Collect a qkview from the bash prompt with command: 
    qkview -s0
    The qkview file name displays after the command has completed and will appear in the /var/tmp/ folder

Provide the following information:

  • Virtual Server
  • Access Policy
  • Portal Access
  • Test username
  • Test SessionID

Upload the following data: 

  • /var/tmp/<BIG-IP Hostname>.qkview
  • HTTPWatch recording directly to application
  • Step recording going directly to the application
  • HTTPWatch recording going through Portal Access showing the issue
      Ensure if new tabs were opened, this is present in the recording before uploading.
    • Step recording going through APM Portal Access
