K13862: ZebOS OSPF may not be able to load network statement with wildcard mask notation

Published

Source

ZebOS OSPF may not be able to load a network statement with a wildcard mask notation.

This issue occurs when either one of the following conditions is met:

  • The ZebOS OSPF configuration with a wildcard mask notation in the network statement was created from BIG-IP 10.x, and the configuration was carried forward during an upgrade from BIG-IP 10.x to 11.0.0.
  • You attempted to insert a network statement with a wildcard mask notation on ZebOS OSPF on a BIG-IP 11.0.0 system.

The following example illustrates the network statement using a wildcard mask notation:

network 10.1.0.0 0.0.255.255 area 0

The following example illustrates the network statement using a prefix mask notation:

network 10.1.0.0/16 area 0

Impact

  • After you upgrade from a previous version to 11.0.0, the BIG-IP system may fail to dynamically advertise or discover routing information due to the ZebOS configuration file's failure to load.
  • On version 11.0.0, inserting a network statement using a wildcard mask notation results in an error.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • In the scenario where you performed an upgrade to version 11.0.0, the output of the running configuration on ZebOS and configuration file /config/ZebOS.conf does not match.

    To display the running configuration of ZebOS, type the following command:

    zebos cmd show running

    To display the content of the configuration file /config/ZebOS.conf, type the following command:

    cat /config/ZebOS.conf

  • On version 11.0.0, when you attempt to insert a network statement using a wildcard mask notation in OSPF, you may see an error message that appears similar to the following example:

    % Incomplete command

    For example:

    Insert a network statement with a wildcard mask notation, as follows:

    bigip1(config-router)#network 10.1.0.0 0.0.255.255 area 0

    You see an error message that appears similar to the following example:

    % Incomplete command

Workaround

To work around this issue, you can replace the network mask using a wildcard notation with a prefix notation. The following two procedures contain steps on how to recover from ZebOS configuration load failure after an upgrade, and information on how to avoid the issue by using the prefix mask notation when creating a network statement.

Recovering from ZebOS configuration load failure after an upgrade to BIG-IP 11.0.0

To work around this issue, after the upgrade you can replace the network wildcard mask notation with a prefix mask notation and reload the ZebOS configuration. To do so, perform the following procedure:

Impact of workaround: This procedure requires you to restart tmrouted, and doing so may disrupt traffic that is passing through this BIG-IP system.

  1. Log in to the command line.
  2. Change directories to /config by typing the following command:

    cd /config

  3. Using a text editor, edit the ZebOS.conf file by replacing the affected entries of the network statement that are using a wildcard mask notation with a prefix mask notation.

    For example:

    The following network entry uses a wildcard mask notation:

    network 10.1.0.0 0.0.255.255 area 0

    You would modify the entry by replacing the mask with a prefix mask notation, as follows:

    network 10.1.0.0/16 area 0

  4. Save the changes and exit the text editor.
  5. To load the modified configuration into ZebOS, restart the tmrouted service by typing the following command:

    bigstart restart tmrouted

  6. Compare the content of the ZebOS.conf file and the running configuration on ZebOS to ensure that the configurations are now loaded correctly.

    To display the configuration file, type the following command:

    cat /config/ZebOS.conf

    To display the running configuration on ZebOS, type the following command:

    zebos cmd show run

Creating a network statement using prefix notation on BIG-IP 11.0.0

To avoid the issue, you can use the prefix mask notation when you attempt to create a network statement. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the command line of the BIG-IP system.
  2. To access the ZebOS interactive command line shell, type the following command:

    imish

  3. To enter enable mode, type the following command:

    enable

  4. From the prompt, to enter configuration mode, type the following command:

    config terminal

  5. To enter the OSPF route configuration mode, type the following command:

    router ospf

  6. Use a prefix mask notation to add a new network statement.

    For example, to add a new network statement with area 0 for network 10.1.0.0 with wildcard mask notation of 0.0.255.255. You can use the prefix mask notation by typing the following command:

    network 10.1.0.0/16 area 0

  7. To quit the ZebOS interactive command line shell, type the following command to exit to each level of the configuration mode:

    quit
