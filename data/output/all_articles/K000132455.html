K000132455: Process ntpd unable to start due to Too many open files

Type
Support Solution
Published
2023-03-22
Updated
2023-03-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.2
Source
https://my.f5.com/manage/s/article/K000132455

Description

If you have a lot of interfaces (VLANs) in the BIG-IP system, the ntpd service will use all interfaces as listeners. This caused ntpd unable to start and logged

"ntpd[process_id]: unexpected socket() error Too many open files code 24 (not EPROTONOSUPPORT nor EAFNOSUPPORT nor EPFNOSUPPORT) - exiting"

 

Environment

  • LTM

Cause

  • Too many interfaces when ntpd loading the configuration.

Recommended Actions

  • To narrow down the interfaces to listen to on the F5 device

Important: please make sure you do not use BIG-IP as an NTP server. Because narrowing down the listening interface, is mean enabling the NTP server on which the interface that configured.

  • If you want to enable it on only one interface (management, for example), it is straightforward:
Syntax: tmsh modify sys ntp include 'interface listen'

For example

tmsh modify sys ntp include 'interface listen mgmt'

tmsh save sys config

Additional Information

  • If you require more interfaces, then it's a bit more tricky. You need to:
  1. tmsh
  2. edit sys ntp all-properties
  3. add IP's to listen to under "include" section (example from my LAB unit):
modify ntp {
description none
include "
interface listen mgmt
interface listen external
"
restrict none
servers replace-all-with { 192.168.1.1 }
timezone Singapore
}
  1. save (:!wq) and then tmsh save sys config
  2. bigstart restart ntpd
  3. netstat -panou | grep 123 will show you if NTP is indeed listening on the IP's selected or not
