Topic

Microsoft Internet Explorer versions 6 and 7 may not cache and display certain content if the content is accessed through an SSL-enabled virtual server with an HTTP profile that has the Browser Workarounds setting, a VARY header, and HTTP compression enabled. The missing content can include Cascading Style Sheets (CSS) or JavaScript information.

This issue occurs when the following three components are used simultaneously:

  • HTTPS protocol
  • The Browser Workarounds setting
  • The VARY header

HTTPS protocol

Microsoft has documented a known issue regarding the browser's ability to handle CSS and JavaScript over the HTTPS protocol.

Note: For more information and a suggested workaround, refer to the Internet Explorer Incorrectly Displays Web Pages Microsoft article. This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

Browser workarounds

Enabling browser workarounds to prevent CSS or JavaScript content from being compressed causes additional issues.

Note: For more information about browser workarounds and HTTP compression, refer to K6671: Order of precedence for HTTP compression.

The VARY header

Internet Explorer versions 6 and 7 only act on User-Agent, which allows Internet Explorer to cache data. All other information within the VARY header is interpreted by Internet Explorer to not cache the data.

Internet Explorer caches all data with the following header:

Vary: User-Agent

Internet Explorer does not cache any data with the following header:

Vary: Accept-Encoding, User-Agent

Note: For more information, refer to the Some hyperlinks may fail when the server sends a VARY header response Microsoft article. This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

F5 Product Development is tracking this issue as CR40502 in an effort to provide more granular browser workaround options.

Workaround

To correct the issue with Internet Explorer handling content, disable compression for all text/css and application/x-javascript files, which prevents the VARY header from being used.

To correct the issue with browser workarounds, modify the Exclusion list. In the compression profile, add the following to the Exclusion list:

text/cssapplication/x-javascript

The order of precedence designates that the Exclusion list takes precedence over those in the Inclusion list.
