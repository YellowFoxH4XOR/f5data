Note: For more information, refer to K10479: Bypassing the BIG-IP ASM system with an iRule in 10.x.

In BIG-IP ASM 9.4.0 and 9.4.1, to bypass application security inspection you had to set the asm_bypass flag within an iRule:

  • To disable ASM

    set asm_bypass 1

  • To enable ASM

    set asm_bypass 0

Note: For an example iRule using the asm_bypass command, refer to K7616: Configuring static web content to bypass the BIG-IP ASM.

In BIG-IP ASM 9.4.2 through 9.4.8, the following iRule commands are used to enable or disable BIG-IP ASM processing for certain requests or connections:

  • To disable ASM

    PLUGIN::disable ASM

  • To enable ASM

    PLUGIN::enable ASM

Note: When you use the PLUGIN::disable command to bypass the BIG-IP ASM system for one request, you should always re-enable ASM processing for subsequent connections by using the PLUGIN::enable command at the top of the HTTP_CLASS_SELECTED event. Otherwise, all subsequent requests on the connection will bypass the BIG-IP ASM security policy. For example, in the following iRule, the PLUGIN::enable command is used at the top of the HTTP_CLASS_SELECTED event to enable the BIG-IP ASM system for all requests. Only requests for .jpg files result in a call to the PLUGIN::disable command, and as a result, only those requests will bypass the BIG-IP ASM system.

when HTTP_CLASS_SELECTED {

PLUGIN::enable ASM

if { [HTTP::uri] ends_with ".jpg" } {

PLUGIN::disable ASM

}

}

Beginning in version 9.4.3, the PLUGIN::disable iRule command that you use to bypass the BIG-IP ASM system for certain connections will only work in the HTTP_CLASS_SELECTED event. This change occurred as a result of CR97521. For an example iRule using the HTTP_CLASS_SELECTED event, refer to K7616: Configuring static web content to bypass the BIG-IP ASM.

Note: The PLUGIN:: iRule commands do not function in BIG-IP 10.0.0, and were depreciated in version 10.0.1. For information, refer to K10128: The PLUGIN iRule commands do not function in BIG-IP 10.0.0.
