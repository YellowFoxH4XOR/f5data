K000161875: Slow or Failed NGINX Plus startup due to Slower system DNS servers

Applies to

  • NGINX Plus: 37.0.0, 37.0.X, 37.0.2, 37.0.1, R36, R32, R33, R34, 37.X.X, R35
Source

Description

When there are many static domain names in the NGINX Plus configuration and there are issues with the DNS servers configured in the system, NGINX Plus may start slowly or the system may stop the startup process due to a timeout.

Environment

  • NGINX Plus;
  • The DNS servers configured in the system are responding slowly and there is no way to improve the DNS servers' performance;
  • Many static domain names in the configuration (the number depends on how slow the DNS responses are);
  • There is no way to replace static domain names with addresses.

Cause

All static domain names specified in the NGINX Plus configuration are resolved during NGINX Plus startup. Since using the system resolver is a blocking operation, the number of domain names and the DNS servers' performance affect the time it takes to parse the configuration.

Answer/Recommended Actions

If you want to use domain names instead of addresses, you have the option to set them as dynamic. NGINX Plus resolves dynamic domain names asynchronously on its own. To do this you need to change the configuration as follows:

  • Instead of setting a domain name in the "proxy_pass" directive, set the "upstream" group name with this domain name;
  • Set the "resolver" directive (with DNS servers) to the "http {}" context (it is also possible to set the "resolver" directive for an "upstream" group);
  • Every "server" directive in an "upstream" group requires a "resolve" parameter.

For example:

http {
    resolver 10.1.2.3 10.2.3.4 ipv6=off;

    upstream dynamic_backend {
        zone dynamic_backend 64k;

        server backend1.local resolve;
        server backend2.local resolve;
    }

    server {
        location / {
            proxy_pass http://dynamic_backend;
        }
    }
}

Additional Information

The domain names in the NGINX Plus configuration that are resolved only when NGINX starts up are considered static domain names. Those that are resolved while NGINX Plus is running are considered dynamic domain names.
