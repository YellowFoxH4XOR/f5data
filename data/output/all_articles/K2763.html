K2763: The sudo utility may not work properly in BIG-IP and 3-DNS versions 4.5 and later

Topic

As of version 4.5, there are two issues related to the use of the sudo utility BIG-IP and 3-DNS:

  • After upgrading, you get an error message similar to the following when trying to use the sudo utility:

    bigip$ sudo bigtop -n
    Sorry, sudo must be setuid root.

  • If a user was given access to the command line interface (and sudo) and Configuration utility, the user will not be able to access the command line interface after upgrading.

Correcting the sudo utility error

This error is caused by incorrect file privileges. The incorrect settings are as follows:

-rwxr-xr-x 1 root wheel 89732 Aug 23 2002 sudo*

To correct this issue, change the settings by typing the following command:

chmod u=xs,go=x /usr/bin/sudo

The settings should now appear as follows:

---s--x--x 1 root wheel 89732 Aug 23 2002 /usr/bin/sudo

Correcting access

BIG-IP and 3-DNS use the LDAP database to store authentication information both for the command line interface and the Configuration utility. All user accounts present in the password files, /etc/passwd and /etc/master.passwd, that are not assigned to the daemon login class are migrated to the LDAP database during an upgrade. Corresponding entries are preserved in the password files, but only the LDAP database is used for authentication and authorization (both for Configuration utility and the command line interface).

This means that after upgrading:

  • Users that are configured for command line interface (sudo) access and full Configuration utility access prior to the upgrade will retain these privileges.

  • Users that are configured for command line interface access and read-only Configuration utility access prior to the upgrade will not be able to access the command line interface.

  • Users that are assigned to a login class that no longer exists in the upgraded version (for example, restricted) will not be able to access the command line interface.

To correct this issue before or after upgrading, assign all "non-root" local users to the daemon login class. To do this, run the vipw command to modify the password file and change the class field (see the passwd(5) manual page for more information) of the matching user entries to the daemon class.

For example:

Original entries:

hosting:xxxxxxxxxxxxx:501:501::0:0:Shared Hosting:/home/hosting:/bin/bash
hosting2:xxxxxxxxxxxx:501:503:restricted:0:0:Shared Hosting:/home/hosting:/bin/bash

Modified entries:

hosting:xxxxxxxxxxxxx:501:501:daemon:0:0:Shared Hosting:/home/hosting:/bin/bash
hosting2:xxxxxxxxxxxx:501:503:daemon:0:0:Shared Hosting:/home/hosting:/bin/bash

Note: Users assigned to the daemon login class will have a separate password for the command line interface (and sudo) and for the Configuration utility. It is recommended, but not required, that the two passwords match. You can grant these users any access privilege in the Configuration utility (including read-only).

To change the command line interface password, you must use the passwd command.

To change the Configuration utility password, you must use the System Administration page of the Configuration utility.
