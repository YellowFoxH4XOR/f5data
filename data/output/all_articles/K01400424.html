Description
snmpwalk query for sysDescr and sysObjectID returns a value of "UNKNOWN" for some platforms, such as i5600, i10600, i10800 and some VIPRION blades. 

Note: The list of hardware above may not be exhaustive and this may apply to other platforms as well.  If you experience this issue on other hardware platforms please contact F5 Support online or via phone.

  • K623: Opening a new case with F5 Technical Support from AskF5
  • Contact Support via Phone

Environment

Looking at the following output, we see some info not being displayed properly for the i5600 platform but this may happen on other platforms as well:

tmsh show /sys hardware

Platform
  Name           none                                                       <--------------------- None!!
  BIOS Revision  OBJ-0645-xx BIOS: 4.00.288.0 ME: 6.0.50.1252 08/24/2017

System Information
  Type                       C119                                           <--------------------- Alphanumeric Platform ID displayed instead of Platform Name
  Chassis Serial             f5-abcd-wxyz
  Level 200/400 Part         203-0396-06 REV B                              <--------------------- Part number
  Switchboard Serial         none
  Switchboard Part Revision  none
  Host Board Serial          pca5489g00be
 Host Board Part Revision   none
  
As a result of this, a snmpwalk query for sysDescr and sysObjectID returns a value of "unknown" instead of displaying the actual platform related information.

Cause
The /etc/hal/MARKETING-NAMES file that enlists each platform name is missing some of the platform names. This is often caused when the platform name isn’t finalized during the programming process for that version. Within this file, we see the platform name and it's part number specified, delimited by "=".

In order to address this issue with snmpwalk query returning "UNKNOWN" value for sysDescr & sysObjectID, we have improved upon this by virtue of ID528498 in future software releases for some platforms. This is classified as an "Improvement" and it only impacts versions which don't have our newer platform model info updated under it's marketing name file. Starting v13 and above, for the i5600, we see this part number already comes included in our marketing names file, as we can see below:

[root@LTM1:Active:Standalone] config # egrep '203-0396-06' /etc/hal/MARKETING-NAMES
BIG-IP i5000=203-0396-06

In this case, following same naming convention as seen above within /etc/hal/MARKETING-NAMES file, the format for i5600 would be like this:

BIG-IP i5000=203-0396-06

We were able to get the part number appended from "tmsh show /sys hardware" output. As long as the part number is specified, it doesn't matters if you specify 'BIG-IP i5000=203-0396-06' or 'BIG-IP i5600=203-0396-06'. However, given how we have 'BIG-IP i5000=203-0396-06' specified in newer versions, it is recommended to use the same name so it doesn't change after upgrading the device from to v13 or higher releases.

Recommended Actions

  1. Before modifying this marketing name file, make sure you create a backup copy of it using this command:
    cp -p /etc/hal/MARKETING-NAMES /shared/tmp/MARKETING-NAMES.bak
  2. Edit the /etc/hal/MARKETING-NAMES file using a virtual editor to include the your product part number and name within this file, for example:
    BIG-IP i5000=203-0396-06
  3. After adding this manually to /etc/hal/MARKETING-NAMES file and saving it, reboot the device in order for the changes to take effect.
    Note: Rebooting the device will cause a failover event, so it is recommended to be performed during a maintenance window
