K000139820: alert event in user_alert.conf not trigger action when regex *:* used

Type
Support Solution
Published
2026-09-08
Updated
2026-09-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000139820

Description

alert event in user_alert.conf doesn't trigger the action when regex *:* is used


Environment

user_alert.conf contains


alert ALERT_NAME "Pool /Common/testpool member /Common/*:* monitor status forced down" {

exec command="_some_tmsh_command_"

}


The aim is to trigger the tmsh command specified with 'exec command=' once any of the pool members in the 'testpool' pool goes down.


The exec command is not triggered with *:* regex notation.


Cause


As per https://my.f5.com/manage/s/article/K3727 (.*) is used for wildcard matching.


Recommended Actions

Use the below instead.


alert ALERT_NAME "Pool /Common/testpool member /Common/(.*) monitor status forced down" {

exec command="_some_tmsh_command_"

}
