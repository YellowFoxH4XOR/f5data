Known Issue

This is the result of a known issue. The bigpipe profile http <profile> ramcache exact command can be used to dump specific RAM Cache entries based on the URI and hostname contained in the request. The bigpipe profile http <profile> ramcache exact command does not properly match the queried hostname.

For example, the output of the following bigpipe command does not properly match the queried hostname:

bigpipe profile http HTTP_Profile ramcache exact uri /index.html host update.example.com

Profile HTTP_Vip
| URI /index.html
| Host www.example.com
| 1 hits Size 611
| Received 2007-12-19 11:59:27 Last sent 2007-12-19 11:59:27
| Expires 2007-12-19 08:00:41 Vary none Vary count 1

The hostname requested in the bigpipe command should match the hostname displayed in the command output (update.example.com), similar to the following example:

Profile HTTP_Vip
| URI /index.html
| Host update.example.com
| 1 hits Size 611
| Received 2007-12-19 11:59:43 Last sent 2007-12-19 11:59:43
| Expires 2007-12-19 08:00:57 Vary none Vary count 1


Note: The correct syntax for BIG-IP versions 9.4.2 and later, is as follows:

bigpipe profile http <Profile> ramcache entry exact uri <URI> host <Host>

F5 Product Development tracked this issue as CR91316 and it was fixed in BIG-IP LTM version 9.4.4 for the BIG-IP LTM 9.4 software branch. For information about upgrading, refer to the BIG-IP LTM Release Notes.
