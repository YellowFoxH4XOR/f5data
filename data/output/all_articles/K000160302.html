Description

LDAPS authentication fails on F5OS rSeries with the error message "failed to bind to LDAP server ldaps://example.com:636: Invalid credentials: 80090308: LdapErr: DSID-0C09044E, comment: AcceptSecurityContext error, data 775, v2580". Additionally, users are not assigned the correct administrative roles, and nslcd logs show "No gid for this entry - gid set to 99" and "No mapping found for gid" messages.

Environment

  • F5OS rSeries devices
  • LDAP authentication configured with Active Directory over LDAPS (port 636)
  • LDAP configuration with unix_attributes set to false
  • Users and groups in Active Directory may or may not have uidNumber/gidNumber attributes

Cause

The LDAP bind account may be locked, disabled, or have an expired password (error data 775). Additionally, when unix_attributes is set to false, F5OS ignores uidNumber/gidNumber attributes from Active Directory and requires explicit mapping of LDAP groups to F5OS roles. Without proper group mapping, users are not assigned the correct roles, resulting in authentication failures.

Answer/Recommended Actions

  1. Verify LDAP Bind Account Status
    • Contact your Active Directory administrator to verify the bind account is not locked, disabled, or expired.
    • Confirm the password is current and the account is enabled.
  2. Configure LDAP Group Mapping
    • If unix_attributes is set to false, explicitly map the required LDAP group to the appropriate F5OS role:
    • In the F5OS role configuration, set the remote GID value or specify an LDAP filter (e.g., samaccountname=<group_name>) to select the correct LDAP group for administrative access.
  3. Alternative: Use Unix Attributes
    • If uidNumber and gidNumber attributes are assigned to both users and groups in Active Directory, set unix_attributes to true in the F5OS LDAP configuration to allow automatic mapping.
  4. Update Bind Password (if needed)
    • Use the following commands to update the bind password:

    system aaa authentication ldap bindpw (<AES encrypted string>)

    commit

  5. Compare Configuration Between Devices
    • Compare the running config between working and non-working devices:

    # show running-config system aaa authentication ldap

Additional Information

  • When unix_attributes is false, F5OS generates its own UID/GID values and does not use those from AD.
  • Proper group mapping is required for role assignment; otherwise, users may be assigned a default or incorrect GID, resulting in failed authentication or lack of access.
  • If using unix_attributes true, ensure all relevant AD objects have the necessary attributes populated.
