Description

This article explains what is changing in the implementation made for front-end NTLM authentication on BIG-IP APM version 14.1.0.5 and upper.

In previous versions, the implementation depends on SAMBA library and uses its internal APIs to send netrLogonSamLogonEx requests to a Domain Controller.
That SAMBA library is very old and supports only SMBv1 protocol.
SMBv1 is obsoleted by Microsoft and suggested to be disabled on all servers.

Starting 14.1.0.5 the new implementation does not depend on SAMBA library.
Pass-through user authentication is made using MSRPC NetrLogonSamLogonWithFlags call which uses authenticators (schannel security) while netrLogonSamLogonEx does not.

There is no change in the way BIG-IP administrators must configure the feature.
However, BIG-IP administrators must make sure that the following ports are opened between the BIG-IP and any participating DC for this to work:

tcp/udp 88                - Kerberos (required for Machine domain join process & password renew process)
tcp/udp 464              - Kerberos Password Change (required for Machine domain join process & password renew process)
tcp 389                     - ldap with SASL (required for Machine domain join process & password renew process)
tcp 135                     - MSRPC - (before 14.1.0.5, SMB protocol was at play and used tcp/445)
tcp/high ports           - MSRPC Netlogon dynamic ports (assigned during DC startup)

Most visible change is that tcp port 135 must now be opened.

Environment

This applies to front-end BIG-IP APM NTLM Authentication ("Access >> Authentication >> NTLM" area in the BIG-IP APM UI).

Cause

Given that used ports have changed, this may cause a problem when upgrading to a version >= 14.1.0.5 if there is a filtering device between the BIG-IP and the participating Domain Controllers.

Recommended actions

Prior to upgrading, it is recommended to make sure that all ports listed in the description are not filtered.
