Known Issue

The Machine Cert Auth agent may implement the Match Issuer field in reverse order.

This issue occurs when all of the following conditions are met:

  • Your access policy is configured with an Endpoint Security Client-Side Machine Certificate Auth agent.
  • The user's device is running the Mac operating system.
  • The certificate contains DC components.

    For example, if the DC in the certificate says example.com, the Issuer DC string should be DC=example, DC=com, but instead, it is implemented in reverse order: DC=com, DC=example.

Impact

The machine certificate check fails and users are unable to establish an access session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The machine certificate check fails and users are unable to establish an access session.
  • You may observe that log messages similar to the following examples are written to C:\Windows\Temp\policyserver.log on the affected device:

    547,547,, 48, , 1424, DoRun, Running machine certificate check....
    547,547,, 1, , 645, matchRegex, Didnt Match: Pattern='CN=.*, DC=example, DC=com' with string='CN=aCn, O=anO, C=aCountry'
    547,547,, 1, , 1104, matchIssuer, 'Issuer' pattern didnt match
