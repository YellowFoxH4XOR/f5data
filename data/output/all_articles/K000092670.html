Description

  • BIG-IP reset the connection due to 'Illeagal character found in header name'
  • There is a warning showing as bellowing under the issued header in wireshark. For example,
          X-Content-Type-Options : nosniff\r\n
             [Expert Info (Warning/Protocol): Illegal characters found in header name]
  • If you check the details of RST packet from F5, the rst cause is due to 'Malformed HTTP header error'. For example,
         F5 Ethernet Trailer Protocol
             RST cause: [3018842:552] Malformed HTTP header error
          
 

Environment

  • BIG-IP LTM
  • Version later than 12.0.0
  • Configured HTTP profile in the virtual server
  • Without HTTP profile, it works as expected

Cause

Beginning BIG-IP 12.0.0 HTTP profile enforces strict header checks. HTTP request or response that does not conform to RFC 7230, will be considered a malformed HTTP header and the BIG-IP system will reset the connection.

 Recommended Actions

  1. F5 recommends that you fix the client or the server so that it does not send a malformed HTTP header.
  2. If you found there is a space in the header name, you can enable 'allow space header name' in the http profile in BIGIP 16.1.0 and later. For how to enable this option, please refer to K40243113: Overview of the HTTP profile
