K12066: Enabling the BIG-IP WebAccelerator MultiConnect feature for an NTLM-authenticated application causes unexpected 'HTTP 302 Found' redirect responses

Topic

Enabling the MultiConnect feature on a BIG-IP WebAccelerator version 9.x system for an NTLM-authenticated application may result in the system responding to client requests with unexpected HTTP 302 Found redirect responses for objects embedded on a requested page.

Important: The MultiConnect feature in BIG-IP WebAccelerator version 10.x is not currently compatible with NTLM authentication due to an unresolved known issue. For more information, refer to K11779: The Multiconnect feature is not compatible with virtual servers referencing an NTLM profile.

When MultiConnect is enabled, BIG-IP WebAccelerator rewrites the URLs that are embedded in a requested page to reference multiple related virtual subdomain URLs. However, when NTLM authentication is required, BIG-IP WebAccelerator may fail to associate the rewritten URLs with the originally authenticated session. When this behavior occurs, BIG-IP WebAccelerator sends HTTP 302 Found responses redirecting the client back to the non-MultiConnect URL. This behavior significantly increases the number of HTTP requests made by each client and can severely degrade BIG-IP WebAccelerator performance.

This behavior may occur under the following two conditions:

  • Improper BIG-IP WebAccelerator configuration prevents automatic reauthentication
  • A missing pv_ntlm_session or pv_ntlm_auth cookie prevents automatic reauthentication

Improper BIG-IP WebAccelerator configuration prevents automatic reauthentication

You must properly configure the BIG-IP WebAccelerator system to support NTLM authentication.

Note: For more information, refer to the Configuring Responses Cached Rules chapter in the Policy Management Guide for the BIG-IP WebAccelerator System.

Specifically, you must manually configure the accelerateNTLM and enableAutoNTLMAuth settings in the pvsystem.conf file by changing each setting from false to true. This configuration allows the BIG-IP WebAccelerator to generate the pv_ntlm_session and pv_ntlm_auth secure session cookies following a successful NTLM authentication on a particular domain for a specific client. These cookies are intended to be used for future requests from that same client to fetch authenticated content from the WebAccelerator cache, even if a NTLM-authenticated server-side connection is not currently established for that session.

Missing pv_ntlm_session or pv_ntlm_auth cookie prevents automatic reauthentication

Even if the BIG-IP WebAccelerator system is correctly configured, you may observe the same behavior if the BIG-IP WebAccelerator system does not receive the pv_ntlm_session or pv_ntlm_auth cookie previously returned to the client. This behavior may occur if the cookie is removed or modified by an upstream device, by an iRule, or if the client fails to send the cookie with subsequent requests. To determine if a missing cookie is the cause of the HTTP 302 Found responses, examine the requests received on the WebAccelerator virtual server to ensure that they include the required cookies. If requests are arriving without the required cookies, investigate further to determine whether the client is failing to send them, or if the request is modified before arriving at the BIG-IP WebAccelerator virtual server.
