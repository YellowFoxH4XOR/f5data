Topic

You should consider using this procedure under the following condition:

  • You want to display the contents of a BIG-IP DNS Cache for informational or troubleshooting purposes.

Description

The BIG-IP system can act as a DNS caching resolver or caching forwarder if you enable a DNS Cache in the DNS profile.

You can use the Traffic Management Shell (tmsh) to display or delete the contents of a BIG-IP DNS Cache. The BIG-IP system can display up to 1,000 records from the DNS Cache. When working with a large cache, you may want to narrow your search by using filters such as type, owner, and ttl-range, as described in the Procedures section of this article.

Note: The BIG-IP system does not limit the count of reported records when you use the count-only option, described in the Procedures section of this article.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrator access to the tmsh utility.

Procedures

You can use the tmsh utility to display or delete entries in a BIG-IP DNS Cache. To do so, perform the following procedures:

Note: The following list does not represent all of the available commands. For more information about displaying or deleting cache entries, use the tmsh utility to run the help ltm dns cache records command.

  • Displaying resource record entries in the DNS cache
  • Displaying message entries in the DNS cache
  • Displaying nameserver entries in the DNS cache
  • Displaying key entries in the DNS cache
  • Additional display options
  • Deleting entries in the DNS Cache

Displaying resource record entries in the DNS cache

Resource record entries are the individual records in a DNS response. The records may include an SOA record, DNSSEC key records, glue records, and other supporting records.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use one of the following command syntaxes to display resource record entries:
    • To display all resource records, use the following command syntax:

      show ltm dns cache records rrset cache <DNS Cache name>

      For example:

      show ltm dns cache records rrset cache exampleCache

    • To display resource records by type, use the following command syntax:

      show ltm dns cache records rrset type <resource record type > cache <DNS Cache name>

      For example:

      show ltm dns cache records rrset type a cache exampleCache

    • To display resource records by owner, use the following command syntax:

      show ltm dns cache records rrset owner <zone or domain name> cache <DNS Cache name>

      For example:

      show ltm dns cache records rrset owner com cache exampleCache

    • To display resource records by type and owner, use the following command syntax:

      show ltm dns cache records rrset type <resource record type> owner <zone or domain name> cache <DNS Cache name>

      For example:

      show ltm dns cache records rrset type ns owner example.com cache exampleCache

    • To display resource records by ttl-range, use the following command syntax:

      Note: The ttl-range filters command output by taking the number of seconds left before the system removes an entry from the cache. The starting value is the TTL provided in the DNS response message or the global DNS Cache settings.

      show ltm dns cache records rrset ttl-range <integer:integer> cache <DNS Cache name>

      For example:

      show ltm dns cache records rrset ttl-range 2000:10000 cache exampleCache

      You can also display records that are less than or equal to an integer by adapting the command syntax. The following example displays all entries greater than or equal to 2,000:

      show ltm dns cache records rrset ttl-range 2000: cache exampleCache

      The following example displays all entries less than or equal to 10,000:

      show ltm dns cache records rrset ttl-range :10000 cache exampleCache

Displaying message entries in the DNS cache

Message entries contain the entire contents of a particular DNS response message.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use one of the following command syntaxes to display message entries:
    • To display messages by query name, use the following command syntax:

      show ltm dns cache records msg qname <query name> cache <DNS Cache name>

      For example:

      show ltm dns cache records msg qname www.example.com cache exampleCache

    • To display messages by response code, use the following command syntax:

      show ltm dns cache records msg rcode <formerr|noerror|notauth|notzone|nxdomain|nxrrset|refused|servfail|yxdomain|yxrrset> cache <DNS Cache name>

      For example:

      show ltm dns cache records msg rcode noerror cache exampleCache

Displaying nameserver entries in the DNS cache

Nameserver (NS) entries contain information about the public DNS nameservers the resolver has used to fill the cache. Often there is more than one nameserver listed as an authority for a zone; therefore, the cache entries track metrics for the nameservers so that the system can send new queries to the best nameserver.

Note: The nameserver component of the ltm dns cache records command does not list NS records. Use the rrset component to display resource records.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use one of the following command syntaxes to display nameserver entries:
    • To display all nameservers the BIG-IP DNS Cache has queried, use the following command syntax:

      show ltm dns cache records nameserver cache <DNS Cache name>

      For example:

      show ltm dns cache records nameserver cache exampleCache

    • To display nameservers by zone, use the following command syntax:

      show ltm dns cache records nameserver zone-name <zone> cache <DNS Cache name>

      For example:

      show ltm dns cache records nameserver zone-name com cache exampleCache

Displaying key entries in the DNS cache

Key entries contain DNSKEY resource records that the BIG-IP system uses for DNSSEC validation and contain information about the validity of the DNSSEC keys.

Note: This command displays entries only when the DNS Cache in use is a validating resolver type cache configured with a trust or DLV anchor.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use the following command syntax to display key entries:
    • To display DNSKEY records, use the following command syntax:

      show ltm dns cache records key cache <DNS Cache name>

      For example:

      show ltm dns cache records key cache exampleCache

Additional display options

You can use the tmm and count-only options with any of the commands in the previous examples.

  • When you use the tmsh utility to display entries in the BIG-IP DNS Cache, the system chooses an arbitrary Traffic Management Microkernel (TMM) process from which to retrieve data to evenly distribute the processing load between each TMM process. The TMM processes synchronize cache data so that any differences are temporary.

    Important: Avoid repeatedly displaying BIG-IP DNS Cache content from the same TMM process. Additionally, F5 recommends that you use the tmm option only when troubleshooting.

    The tmm option of an ltm dns cache records command syntax appears similar to the following:

    tmm <TMM process number>

    For example the following command includes the tmm option to display all type A records in the TMM 1 cache:

    show ltm dns cache records rrset type a tmm 1 cache exampleCache

  • When you use the count-only option, the ltm dns cache records command reports the total number of entries found instead of the entries themselves. The BIG-IP system does not limit the count of records reported. To display the total number of entries found, append count-only to the end of the ltm dns cache records command.

    Note: The count-only option is introduced in BIG-IP 11.5.0.

    For example, the following command uses the count-only option to display a count of all NS records in the example.com domain:

    show ltm dns cache records rrset type ns owner example.com cache exampleCache count-only

Deleting entries in the DNS cache

Impact of procedure: The BIG-IP system removes entries from the cache and recursively resolves or forwards queries to answer clients and store the records in the cache again. F5 recommends that you test any changes during a maintenance window, and consider the possible impact on your specific environment.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use one of the following command syntaxes to delete entries in the cache:
    • To delete all component cache entries, use the following command syntax:

      delete ltm dns cache records <rrset|msg|nameserver|key> cache <DNS Cache name>

      For example:

      delete ltm dns cache records rrset cache exampleCache

    • To delete a specific entry or subset of entries, use the following command syntax:

      delete ltm dns cache records <rrset|msg|nameserver|key> <property> <property value> <DNS Cache name>

      For example:

      delete ltm dns cache records rrset owner example.com cache exampleCache

      Another example:

      delete ltm dns cache records msg qname www.example.com cache exampleCache
