Known Issue

The BIG-IP GTM system does not save topology records to the bigip_gtm.conf file. As a result, topology records defined using the Configuration utility or Traffic Management Shell (tmsh) exist only in running memory.

This issue occurs when the following condition is met:

  • A new topology record is created using the Configuration utility or tmsh.

Impact

Previously-defined topology records are missing after you have loaded the configuration or rebooted.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Previously defined topology records are missing after you have loaded the configuration or reboot.

    For example, after you have rebooted, the record is not listed when you execute the following tmsh command:

    tmsh list gtm topology

  • After defining a topology record using the Configuration utility or command line, the record does not appear in the bigip_gtm.conf file, as expected.
  • The Audit log file will show the creation of the topology record even though the system cannot find the record.

Workaround

To work around this issue, you can manually save the record from the command line. For example, if you have lost previously-defined topology records after you have rebooted or reloaded the configuration, you can complete the following steps to re-configure the records and manually save them from the command line. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the BIG-IP command line.
  2. Create the topology record using the Configuration utility (or tmsh). For information about creating topology records using the tmsh shell, type the tmsh help /gtm topology command.
  3. Log in to the BIG-IP GTM command line.
  4. Save the configuration using the following command:

    tmsh save sys config gtm-only partitions all

  5. Verify that the record exists in the bigip_gtm.conf file by typing the following command:

    cat /config/bigip_gtm.conf
