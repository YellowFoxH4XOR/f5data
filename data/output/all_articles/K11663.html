Issue

After the ARX system performs an import, the syslog file may contain Error: 'Pathname not found during lookup [-340]' error messages that appear similar to the following example:

:DNAS_IMPORT-1-ERR-IMPORT_FIND_FILES_CIFS_ERROR:: CIFS find-files failed for directory '/a/b/c' on share X (<\\x.x.x.x\BACKEND-SHARE>> [130]), Error: 'STATUS_OBJECT_NAME_NOT_FOUND'.
:DNAS_IMPORT-1-ERR-MSG3:: failed to enumerate directory, "/a/b/c" -340, share X (<\\x.x.x.x\BACKEND-SHARE>> [130])
:DNAS_IMPORT-1-NOTE-MSG5:: Timer 1: 1565.051119 Import Scan Time - share X (<\\x.x.x.x\BACKEND-SHARE>> [130])
:DNAS_IMPORT-1-ERR-IMPORT_SCAN_THREAD_ERROR:: Import scan thread 3 for share X (<\\x.x.x.x\BACKEND-SHARE>> [130]) has failed, Error: 'Pathname not found during lookup [-340]'.
:DNAS_IMPORT-1-ERR-IMPORT_SCAN_FAILED:: Import scan for share filea (<\\x.x.x.x\BACKEND-SHARE>> [130]) has failed, Error: 'Pathname not found during lookup [-340]'.
:DNAS_PGRP-1-NOTE-IMPORT_STORAGE_JOB_FAILURE_NO_RETRY:: Import storage job for share 'X' finished with a non-retryable error: 'Pathname not found during lookup [-340]'.
:L2SW_LVL7-0-NOTE-MSG5:: SNMP TRAP: shareImportFail (650) shr 'NAMESPACE:/VOLUME:SHARE', name 'FILER', ip 'x.x.x.x', : Error: path name was not found. Check the import report for more details.

These messages are logged when the ARX system finds a path during the directory scan, but the path is not found later when the ARX system attempts to enumerate the directory to import the files. These messages indicate the path was deleted, moved, or renamed on the back-end storage device after it was scanned.

Note: The import report does not contain the missing pathname as implied by the SNMP trap message (Error: path name was not found. Check the import report for more details.). For information, refer to K11665: Import report does not contain missing pathname information.
