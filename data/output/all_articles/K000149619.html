Description

In this configuration device is not working as expected, because one pool member is receiving traffic even though its Priority Group is lower than that of another pool member with Persistence set too.

 

Environment

  • BIG-IP LTM All
  • Pool member
  • Persistence
  • Priority Group Activation (PGA)

Cause

When a Virtual Server use a Priority Group Activation (PGA), Persistence can result in traffic continuing to go to a pool member in a lower priority group, even after pool member in a higher priority group become available again. 

Recommended Actions

To make specific pool member as primary:

  1. You have to disable persistence

Additional Information

Here is example of what the misconfiguration would look like. Ideally the 192.0.2.2 pool member should take the traffic as it has the higher priority value, set on 2. If this pool member fails, or is marked offline, the 192.0.2.1 (priority value, set on 0) pool member would begin to take the traffic, until the 192.0.2.2 comes back online. Unfortunately, is improper setup up describe above.

When a client connects to the my_virtual virtual server, the BIG-IP LTM system directs the connection to the 192.0.2.1 pool member and records this in it's persistence table. If the client reconnects before the persistence entry expires, the system bypasses load balancing and sends the connection directly to the priority 0 member 192.0.2.1, even if higher priority member with higher priority 192.0.2.2 is back online.

#Virtual Server
 
ltm virtual /Common/my_virtual {                                       
    destination /Common/192.0.2.252:http
    ip-protocol tcp
    last-modified-time 2025-01-15:05:55:55
    mask 255.255.255.255
    persist {
        /Common/source_addr_60min {    <====== Persistence enabled
            default yes
        }
    }
    pool /Common/my_pool               
    profiles {
        /Common/tcp { }
    }
   <...>
   <...>
}

#Pools

 ltm pool /Common/my_pool {                      
  members {
    /Common/membertest-02:http {
      address 192.0.2.01               <====== PGA set on 0
    }
    /Common/membertest-03:http {                  
      address 192.0.2.2
      monitor /Common/tcp
      priority-group 1                 <====== PGA enabled and set on 1
    }
  }
  min-active-members 1
  monitor /Common/tcp
}

#Persistence Profiles

ltm persistence source-addr /Common/source_addr_60min {
   <...>
   <...>
   timeout 3600                                 <====== Persistence set to 60min
}

When a virtual server references a priority group pool, persistence may cause traffic to persist to a pool in a lower priority group even after a higher priority group is reactivated. Once the persistence record expires, connections will be directed to higher priority pool member.
