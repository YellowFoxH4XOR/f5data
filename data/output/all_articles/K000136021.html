K000136021: Nessus plugin 42823 shows STS header is delivered via unencrypted channel for BIG-IP GUI

Type

Applies to

Source

Description

  • Nessus scan plugin 42823 suggests Strict-Transport-Security header is sent over an unencrypted channel (port 80) for BIG-IP configuration utility.

Environment

  • BIG-IP Configuration utility
  • HTTP to HTTPS redirect is enabled

Cause

HTTP to HTTPS 301 redirect response from F5 contains Strict-Transport-Security header.


(Status-Line) HTTP/1.1 301

Connection Keep-Alive

Content-Length 231

Content-Type text/html; charset=iso-8859-1

Date Wed, 30 Aug 2023 03:15:19 GMT

Keep-Alive timeout=4, max=100

Location https://10.201.219.207/

Server Apache

Strict-Transport-Security max-age=16070400; includeSubDomains

X-Frame-Options SAMEORIGIN

 Recommended Actions

The Strict-Transport-Security header is ignored by the browser when your site has only been accessed using HTTP. Once your site is accessed over HTTPS with no certificate errors, the browser knows your site is HTTPS capable and will honor the Strict-Transport-Security header. Browsers do this as attackers may intercept HTTP connections to the site and inject or remove the header.


However if this a concern, you can disable port 80 completely by unchecking "Redirect HTTP to HTTPS" under System ›› Preferences :
