K000162948: Maximum number of managed BIG-IPs when planning F5 Insight Capacity

Type
Support Solution
Published

Updated
2026-08-17
Applies to
  • BIG-IP
  • F5 Insight: 1.2.1
Source

Description

F5 Insight has no confirmed fixed maximum for managed BIG-IP systems. Capacity depends on allocated CPU, memory, primary-disk capacity, analytics ingestion, query workload, and data-retention requirements.

 

Environment

  • F5 Insight Deployment
  • F5 Insight manages BIG-IP systems and supports analytics and fleet-management workloads


Cause

Management capacity is determined by the resources allocated to F5 Insight and the workload profile rather than by a fixed BIG-IP system count. Analytics workloads increase CPU, memory, and storage consumption for data ingestion, queries, raw data, indexes, and rollups.


Answer/Recommended Actions

Use the following capacity-planning guidance:

  • For up to 50 BIG-IP instances, allocate:
    • 12 vCPUs.
    • 16 GB RAM.
    • 650 GB of thick-provisioned datastore space.
  • For each additional 50 BIG-IP instances, plan for approximately:
    • 6 additional vCPUs.
    • 4 GB additional RAM.
    • 500 GB additional primary-disk capacity.

When enabling or expanding analytics workloads:

  1. Evaluate CPU, memory, and storage together. Increasing RAM alone is generally insufficient.
  2. Estimate storage requirements using the expected ingestion volume, query workload, retention period, and growth of raw data, indexes, and rollups.
  3. Increase the primary-disk size when additional storage is required.
  4. Do not add secondary disks because additional disks are not currently supported.
  5. Keep the primary-disk allocation within the storage entitlement shown under System Management > License.
