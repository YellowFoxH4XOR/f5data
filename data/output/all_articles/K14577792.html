Description

You have assigned a SNAT IP of a subnet to the first set of BIG-IP on your OpenStack platform for a tenant.

Then you have assigned another SNAT IP of the same subnet to the second set of BIG-IP for the same tenant. After the operation, there is an issue of business interruption for the corresponding listener.

You may find the SNAT IP on the second set of BIG-IP is the same as the first set of BIG-IP. For example, you may find log messages like the below in the /var/log/ltm on each set of BIG-IP devices:

warning tmm<tmm id>[<pid>]: 01190004:4: address conflict detected for <snat ip> (<mac address>) on vlan <vlan id>

Environment

  • Multiple OpenStack LBaaS providers

  • Use the same subnet in the same tenant

  • F5 LBaaS agent lite mode 

  • BIG-IP SNAT IP

Cause

Lack of provider_name = '<provider_name>' in F5 LBaaS agent configuration file.

Each F5 LBaaS provider has its own F5 LBaaS agent configuration file, and each F5 LBaaS agent configuration file defines one set of BIG-IP, namely each provider corresponds to a specific set of BIG-IP.

If there is no provider_name = '<provider_name>' in the agent configuration file and a tenant has already issued a SNAT IP of a subnet to a set of BIG-IP of a provider. Then the next time, when this tenant wants to issue a SNAT IP to the set of BIG-IP of another provider, it will get the same SNAT IP as the previous one. It finally leads to address conflicts of the SNAT IP on different sets of BIG-IP and business issues.

The provider_name = '<provider_name>' is used for binding SNAT IP to the provider, and making sure that different sets of BIG-IP get different SNAT IP within the same subnet of a tenant.

Recommended Actions

You can follow the procedures below to resolve this issue.

  1. Delete the SNAT IP from OpenStack. This will remove the specific SNAT IP from one set of BIG-IP.
    Note: it may keep the SNAT IP on the other set of BIG-IP, so you need to manually delete it via configuration utility if the SNAT IP keeps there.

  2. Add entry provider_name = '<provider_name>' followed by the f5_snat_mode = True to each F5 LBaaS agent configuration file:

    [DEFAULT]
    --snipped--
    f5_snat_mode = True
    # Make SNAT IP different for the set of BIG-IP of different providers within the same subnet of a tenant.
    provider_name = '<provider_name>'
    --snipped--
     

    For example, if there are 2 F5 LBaaS providers named Provider01 and Provider02, then add the entry provider_name = 'Provider01' to the agent configuration file of Provider01 as:

    [DEFAULT]
    --snipped--
    f5_snat_mode = True
    # Make SNAT IP different for the set of BIG-IP of different providers within the same subnet of a tenant.
    provider_name = 'Provider01'
    --snipped--


    And then add the entry of provider_name = 'Provider02' to the agent configuration file of Provider02 as:

    [DEFAULT]
    --snipped--
    f5_snat_mode = True
    # Make SNAT IP different for the set of BIG-IP of different providers within the same subnet of a tenant.
    provider_name = 'Provider02'
    --snipped--
     

  3. Save the change and restart the F5 LBaaS agent service in order to make the configuration into effect.
