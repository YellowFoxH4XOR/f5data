Known Issue

Secure Sockets Layer (SSL) handshakes may fail when all of the following conditions occur:

  • The client sends an SSL version 2 Client Hello message type during the SSL handshake.
  • The value of the Challenge Length field in the Client Hello message is less than 32 bytes.
  • The client SSL profile has Strict Resume disabled.

The SSL version 2 specification provisions Challenge Length to be between 16 and 32 bytes, inclusive. The TLS version 1.0 specification states that the Challenge Length must be 32 bytes with provision that the TLS server should accept SSL version 2 Client Hello format if SSL version 2 is supported.

Impact

Client SSL connections may intermittently stall or fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • SSL clients experience intermittent SSL handshake failures.
  • Client SSL connections stall.

Workaround

You may be able to work around this issue by enabling Strict Resume for the affected client SSL profile. To do so, perform the following procedures:

Impact of Workaround: The workaround may result in a negligible performance impact due to an increase in SSL handshakes.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Click the name of the client SSL profile you would like to modify.
  4. Select the Strict Resume check box.

    Note: Enabling Strict Resume prevents clients that have closed a session with an unclean shutdown from resuming the session later, preventing the undesirable session resumption behavior.

  5. To save the modifications, click the Update button.

Alternatively, you can work around this issue by using the following iRule to pad the Challenge Length in the SSL client’s Client Hello packet to 32 bytes. To do so, perform the following procedure:

Impact of Workaround: Implementing this iRule may result in an increase in CPU or memory utilization on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name for this iRule.

    For example:

    sol12813

  5. Copy the following iRule and paste it in the Definition box:

    when CLIENT_ACCEPTED {
    SSL::disable
    TCP::collect
    }
    when CLIENT_DATA {
    if { [TCP::payload length] < 11 } {
    SSL::enable
    TCP::release
    return
    }
    binary scan [TCP::payload] H* payload
    binary scan [TCP::payload] ScSSSS length mtype version cipher_length sid_length challenge_length
    if { $version != 0x0300 && $version != 0x0301 } {
    SSL::enable
    TCP::release
    return
    }
    if { $challenge_length != 16 || $mtype != 0x01 } {
    SSL::enable
    TCP::release
    return
    }
    incr length 16
    set challenge_length 32
    TCP::payload replace 0 2 [binary format S $length]
    TCP::payload replace 10 2 [binary format S $challenge_length]
    TCP::payload replace [TCP::payload length] 0 [binary format c* { 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 }]
    SSL::enable
    TCP::release
    return
    }

  6. To save the iRule, click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the Edit link under the Resources column for the affected virtual server you would like to assign the iRule.
  9. Click the Manage button for the iRules section.
  10. In the Available box, select the iRule.
  11. Click the << button to move the iRule to the Enabled box.
  12. To save the modification, click Finished.
