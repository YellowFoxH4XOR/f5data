K6181: Configuring authenticate always for an SSL virtual server does not prevent session caching

Published
2007-05-11

Status

Applies to

  • BIG-IP LTM: 9.1.1, 9.1.0

Known Issue

This is the result of a known issue. When you enable the authenticate always feature for a Secure Sockets Layer (SSL) virtual server, the BIG-IP LTM system requires client authentication for each new session.

When the SSL session cache is not disabled, however, the BIG-IP LTM system will cache the authentication, which circumvents the requirement to authenticate each new session from the same client.

This behavior causes the BIG-IP LTM system to send a NULL SSL session ID length of 0 (zero) to the client, which instructs the connecting client that we do not support SSL session resumption. This issue prevents the BIG-IP LTM system from using the SSL session ID to persist or be used within an iRule since a new session ID is generated each time the client connects.

F5 Product Development tracked this issue as CR55371 and CR59264, and it was fixed in BIG-IP LTM 9.1.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, set the size of the SSL session cache to 0 (zero). Setting the size of the SSL session cache to 0 (zero) disables the session cache and forces clients to authenticate with every new session.
