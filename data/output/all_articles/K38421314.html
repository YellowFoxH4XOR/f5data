Description
When USB devices are inserted into a BIG-IP, basic information is written to log files about the event. In some cases, particularly for security auditing, more about the device may be desired. This can only be collected by creating a new udev rule.
Warning: Do not modify the udev_log setting in /etc/udev/udev.conf! Modifying this setting may cause the BIG-IP to fail to boot. Modifying this setting can cause huge volumes of debug to be written to console when udev initialises and the system will reboot after a watchdog timeout. 

Environment

  • Access to the BIG-IP as a root user in bash
  • USB drive

Recommended Actions

  1. Create a udev rule
    udev is the Linux subsystem that handles device identification and addressing for the kernel. Create a new udev rule to trigger a script when a new USB device is plugged in.
    The following steps are done in the bash shell.
    Create a file called using a text editor such as "vi"
    # vi /etc/udev/rules.d/01-local.rules
    Add a single line to the file, as follows:
    ACTION=="add", SUBSYSTEM=="usb", RUN="/config/udev-new-device.sh"

  2. Create a script
    Create a script file to be run when a udev triggers the new rule. The script must be made executable. The contents of the script are entirely at the user's discretion, but the example below will cause the output from the command "usb-devices" to be written into the ltm logfile.
    The following steps are done in the bash shell.
    Create a file called using a text editor such as "vi".
    # vi /shared/udev-new-device.sh
    Add the following contents to the file:
    #!/bin/bash
    /bin/logger -p local0.notice New device added $(usb-devices)
    exit 0
    Make the file executable:
    # chmod 700 /shared/udev-new-device.sh

  3. Reload the udev rules
    Ensure that udev picks up the new rule.
    Run the following command at the bash prompt:
    # udevadm control --reload-rules

Impact of procedure: Performing these procedures should not have a negative impact on your system.
