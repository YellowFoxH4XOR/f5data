Known Issue

BIG-IP PEM sessions remain in the system when the Policy and Charging Rules Function (PCRF) returns an unknown session ID.

This issue occurs when all of the following conditions are met:

  • PCRF is brought offline due to a reboot or failover event.
  • PCRF loses all the previously established sessions while the BIG-IP PEM system has the session records.
  • The BIG-IP PEM system continues to send usage data (for example, Gx-Update).

Impact

Users on the affected sessions may not be able to access the allowed services.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the BIG-IP PEM system sends a Credit-Control-Request Update (CCR-U) packet to PCRF, it responds back with a Credit-Control-Answer Update (CCA-U) with code 5002 (Unknown Session ID) because PCRF does not have the session information.
  • The affected sessions remain in the BIG-IP PEM system when PCRF does not acknowledge the session.
  • Users on the affected sessions may not be able to access their allowed services.

Workaround

To work around this issue, you can delete the affected BIG-IP PEM sessions to let PCRF recover the BIG-IP PEM session context.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

To delete the affected BIG-IP PEM session based on the known subscriber ID, use the following command syntax:

tmsh delete /pem sessiondb subscriber-id <Number>

To delete the affected BIG-IP PEM session based on the known session IP, use the following command syntax:

tmsh delete /pem sessiondb session-ip <IP-Address>
