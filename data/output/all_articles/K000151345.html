K000151345: Some SNMP OID returns large value after upgrading F5OS-A to 1.8.0

Type
Support Solution
Published
2025-05-15
Updated
2025-05-15
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.0
Source
https://my.f5.com/manage/s/article/K000151345

Description

In F5OS-A 1.5.x, the temperature values obtained via CLI (Command Line Interface) matched the monitored SNMP (Simple Network Management Protocol) OID (Object Identifier) such as F5-PLATFORM-STATS-MIB::tempCurrent. However, after upgrading to 1.8.0, the monitored values is 10 times higher, with the monitoring system reporting temperatures above 100°C even when monitoring system already loaded the latest F5OS MIB (Management Information Base) files.

.1.3.6.1.4.1.12276.1.2.1.3.1.1.2
tempCurrent OBJECT-TYPE
 -- FROM	F5-PLATFORM-STATS-MIB
 -- TEXTUAL CONVENTION TemperatureType
 SYNTAX	Integer32
 DISPLAY-HINT	"d-1"
 UNITS		"centigrade"
 MAX-ACCESS	read-only
 STATUS	current
 DESCRIPTION	"The current temperature in celsius/centigrade"

F5OS device returns a response, captured from mgmt interface:

Simple Network Management Protocol
  version: v2c (1)
  community: <REDACTED>

Environment

  • F5OS-A 1.8.0 SNMP OID such as F5-PLATFORM-STATS-MIB::tempCurrent, F5-PLATFORM-STATS-MIB::psuCurrentIn

Cause

From F5OS-A 1.8.0 onwards, F5OS MIB objects belonging to TemperatureType and PSUStatsType have been updated to use DISPLAY-HINT clause as described in RFC 2579 Section 3.1.

TemperatureType ::= TEXTUAL-CONVENTION
    DISPLAY-HINT "d-1"

PSUStatsType ::= TEXTUAL-CONVENTION
    DISPLAY-HINT "d-3"

Monitoring system that supports RFC 2579 will render the OID value without issue. Sample output from snmpget command of net-snmp:

F5-PLATFORM-STATS-MIB::tempCurrent."platform" = INTEGER: 30.0 centigrade

Recommended Actions

If the monitoring system does not support RFC 2579, the monitoring system needs to process or adjust the collected OID value from F5OS device prior to storing the final value.
