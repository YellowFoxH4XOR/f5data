Issue

Description

In some cases, a BIG-IP device may experience issues coming online due to MySQL errors due to table failure. Error message appear in /var/log/ltm similar to the following:

err logmysqld[<PID>]: Fatal error db.cpp:exec_query:150 LOCK TABLES log_data_current WRITE errno[145] strerror[Table './logdb/log_data_current' is marked as crashed and should be repaired]

Environment

  • Any module provisioned that uses MySQL (BIG-IP APM, ASM, or AVR)

Cause

This behavior can be caused by the BIG-IP system attempting to load a MySQL database when there isn't enough free space on the hard drive.

Recommended Actions

Note: This procedure restarts the BIG-IP device.

  1. Ensure disk space is appropriately freed. Refer to K14403: Maintaining disk space on the BIG-IP system to free disk space prior to moving forward.
  2. Rebuild the database.
    1. Obtain the MySQL password using the following command:

      perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw

    2. To repair all databases, run the following command and input the password returned from the previous command when prompted:

      mysqlcheck -r -p --all-databases

    3. To auto-repair, check (default), and optimize the database, run the following command and input the password when prompted:

      mysqlcheck -p --auto-repair -o --all-databases

    4. Run the following command to reload BIG-IP daemons:

      bigstart restart tomcat monpd

  3. Verify the configuration via the CLI with the following command:

    tmsh load sys config verify

  4. If this returns no errors, proceed to step 5.

    Important: If it returns an error, stop here and contact F5 Support with the results, as additional issues may be present.

  5. Clear the current running configuration mcpd database, so the BIG-IP system can reload it completely from the flat-file configuration.
    1. Create a zero byte file with the file name forceload in the /service/mcpd directory, by typing the following command:

      touch /service/mcpd/forceload

    2. Restart the BIG-IP system by typing the following command:

      reboot
