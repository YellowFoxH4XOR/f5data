K000138950: Preserving External HTTP Request ID on Aspen Mesh

Type
Support Solution
Published
2025-03-31
Updated
2025-03-31
Applies to
  • Aspen Mesh: 1.14, 1.11
Source
https://my.f5.com/manage/s/article/K000138950

Description

On Aspen Mesh, through Envoy, uses the x-request-id header to uniquely identify HTTP requests for stable access logging and tracing. By default, Envoy generates a new x-request-id for all external origin requests. However, in certain use cases, it is necessary to preserve the request ID from external requests instead of generating a new one. This article explains how to configure Aspen Mesh to retain the original external request ID.

Environment

  • Aspen Mesh 1.11.X 1.14.X 1.18.X
  • Istio Ingress Gateway
  • Istio Envoy Filter
  • HTTP1/HTTP2

Cause

By default, Envoy generates a new x-request-id for all external requests to ensure unique request tracing within the mesh. This behavior may interfere with external systems that depend on maintaining a consistent x-request-id across multiple hops.

Recommended Actions

To preserve the external request ID, apply the following EnvoyFilter configuration to Istio's ingress gateway to modify the HttpConnectionManager settings:

apiVersion: networking.istio.io/v1alpha3
kind: EnvoyFilter
metadata:
  name: ingressgateway-requestid
  namespace: istio-system
spec:
  configPatches:
  - applyTo: NETWORK_FILTER
    match:
      context: GATEWAY
      listener:
        filterChain:
          filter:
            name: envoy.filters.network.http_connection_manager
    patch:
      operation: MERGE
      value:
        typed_config:
          '@type': type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          preserve_external_request_id: true

 

Additional Information

After applying the EnvoyFilter, confirm that the setting is correctly applied to the Istio ingress gateway using the command:

istioctl pc listener <istio-ingressgateway-pod>.<namespace> -ojson | grep preserveExternalRequestId
