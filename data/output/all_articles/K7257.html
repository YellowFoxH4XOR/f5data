K7257: Enabling DNS can result in a long delay when you load or synchronize a configuration

Topic

If DNS is enabled and the DNS server is not reachable or is not responding to requests, loading or synchronizing the configuration may be delayed. It is also possible that the long delay in loading or synchronizing the configuration can result in a failed synchronization. When the configsync process times out, an error message that appears similar to the following example is returned:

SOAPException: 'Unexpected return Content-Type: text/html; charset=iso-8859-1'
Saving active configuration...
Transport and install failed
Error running config sync all.
BIGpipe parsing error:
   01110001:3: Error running config sync all

The behavior occurs when the BIG-IP LTM system attempts to resolve the following names while attempting a configuration load or synchronization:

  • allow
  • route
  • default
  • inet
  • monitor
  • session
  • dynamic
  • icmp

Note: The allow, route, default, and inet names are located in the bigip_base.conf file. The monitor, session, dynamic, and icmp names are located in the bigip.conf file.

As of BIG-IP LTM 9.4.0, this behavior is by design if a DNS server is configured for use; syntactically, the names listed can be hostnames.

F5 Product Development tracked this issue as CR76229, CR74910, and CR80258; it was fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, and WebAccelerator release notes.

Note: Starting in BIG-IP 9.4.2 the bigpipe utility can be configured to accept hostnames in place of IP addresses in bigpipe commands by using the bigpipe cli hostname command. The default is disabled.
