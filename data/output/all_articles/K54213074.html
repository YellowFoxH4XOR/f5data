Description

This document describes a process to update all Device Certificates in a BIG-IP DNS iQuery Mesh to use Third Party signed CA Certificates without interrupting the iQuery Mesh.

Environment

  • iQuery Mesh
  • 3rd Party Signed Certificates
  • Access to Advanced Shell (bash)
  • PEM Encoded Device and Root Certificates

Cause

None

Recommended Actions

Update all BIG-IP DNS and LTM Device Certificates to use Third Party Signed CA Certificates.

On Each BIG-IP DNS and BIG-IP LTM

  1. Copy the new Device Certificate to the device

    /var/tmp/new_server.crt
    /var/tmp/new_server.key

  2. Copy the new Root CA Certificate to each device
    Note: This procedure is written with the assumption that there are no Intermediate Certificates. If there are Intermediate Certificates, include them in root_ca.crt.

    /var/tmp/root_ca.crt

  3. Make a copy of the current Device Cert and Key

    mkdir /var/tmp/certbackup/
    cp /config/httpd/conf/ssl.crt/server.crt /var/tmp/certbackup/server.$(getHostName).crt
    cp /config/httpd/conf/ssl.key/server.key /var/tmp/certbackup/server.$(getHostName).key

  4. Replace with new Device Cert and Key

    cp /var/tmp/new_server.crt /config/httpd/conf/ssl.crt/server.crt
    cp /var/tmp/new_server.key /config/httpd/conf/ssl.key/server.key

  5. Restart httpd to use the new cert

    bigstart restart httpd

On BIG-IP DNS Only

  1. Copy Root CA Certificate to Trusted Server Certificate Store

    cat /var/tmp/root_ca.crt > /config/gtm/server.crt

On LTM and BIG-IP DNS

  1. Copy Root CA Certificate to Trusted Device Certificate Store

    cat /var/tmp/root_ca.crt     > /config/big3d/client.crt

  2. Copy the Device Certificate to the Trusted Device Certificate Store

    cat /var/tmp/new_server.crt >> /config/big3d/client.crt

Construct iqdump Commands Based on Current Configuration

Use the following bash one-liner to construct all of the iqdump commands needed.
Important: Each of these commands must pass prior to restarting big3d or gtmd.

Construct iqdump commands bash:

tmsh list gtm server all one-line | grep bigip | grep -Po '{ addresses {.*?} }?' --color | grep -v device-name | grep -oP "([0-9]{1,3}[\.]){3}[0-9]{1,3}" | xargs printf "iqdump %s\n"

Example Output:

iqdump 10.16.10.1
iqdump 10.16.10.2
iqdump 10.16.10.3
iqdump 10.16.10.4

Test Connectivity

From ALL BIG-IP DNS Systems, Test Connectivity to ALL BIG-IP Systems (LTM and DNS)

iqdump <server_addr>

    Additional Information

    iQuery is an F5 Networks proprietary XML-like protocol that collects configuration and metric information over a TLS encrypted tunnel and exchanges that information between BIG-IP DNS devices and other F5 Networks products running the big3d agent.

    iQuery connection will not be immediately terminated if the device certificate on the other device expires. 
    However, iQuery connection is renegotiated periodically and certificate is verified at that time (Interval is specified by dbkey big3d.renegotiation.interval, default value is 86400sec = 24h). 
    So, iQuery connection with expired device certificate will start down after the renegotiation.
