Known Issue

BIG-IP APM access session connections may fail when encapsulated.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a network access, remote desktop, or application tunnel destination resource.
  • Network traffic between the BIG-IP APM system and the destination resource is sent to another BIG-IP device using an iSession and IPsec encapsulation.
  • A user establishes an access session and attempts to connect to the destination resource.

Impact

The access session connection fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view network level traffic between the BIG-IP APM system and the destination resource, you notice that the SYN packets that the system sent to the destination resource are reset with the Policy action reset cause.
  • When the system sends traffic between the BIG-IP APM system and the destination resource that is processed by another BIG-IP system, and the traffic does not use IPsec encapsulation, the connection establishes.

Workaround

To work around this issue, you can remove the IPsec encapsulation of the BIG-IP APM tunnel from the communication between the BIG-IP devices.

Note: iSession uses Transport Layer Security (TLS) to encapsulate network traffic between the BIG-IP APM system and the remote resource destination BIG-IP device. The system should not require IPSec encapsulation of the encapsulated traffic.

Impact of workaround: Performing the suggested workaround removes the IPSec encapsulation for traffic sent between the BIG-IP devices.
