Known Issue

Extra escape characters may be appended to monitor send and receive strings after you upgrade.

This issue occurs when one of the following conditions is met:

  • You upgrade from 11.6.0, 11.6.0 HF1 through HF5, or any engineering hotfix for those versions, to any of the following versions:
    • 11.6.0 HF6 
    • 11.6.0 HF7
    • 11.6.0 HF8
  • You upgrade from 11.5.3, 11.5.3 HF1, 11.5.3 HF2, or any engineering hotfix for those versions, to either of the following versions:
    • 11.5.3 HF2 engineering hotfix 2
    • 11.5.3 HF2 engineering hotfix 45

For example, if an HTTP monitor is configured with the send string "GET /monitor.html HTTP/1.0\r\n\r\n", following an upgrade to one of the versions previously listed, the string would be changed to "GET /monitor.html HTTP/1.0\\r\\n\\r\\n".

Impact

Monitors containing the extra characters fail to function properly following an upgrade.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H565003 on the Diagnostics > Identified > High screen. 
  • Pool members and nodes are marked down following an upgrade.
  • Monitors begin to fail following an upgrade.
  • Extra characters are inserted into the send and receive strings of monitor configurations.

Workaround

While there is no workaround for this issue, you can mitigate this issue by removing any additional escape characters from the configuration manually.
