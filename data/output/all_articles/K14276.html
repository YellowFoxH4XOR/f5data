Issue

Error Message

Error Message:

NSM_CIFS_FILER_TREE_CONN_FAIL:: Backend-open: Tree Connect to filer [filer ip] (path \\[data location]) for client [client ip] user [username@domain.com], failed with error STATUS_INVALID_HANDLE (0xc0000008) - UNEXPECTED_NETWORK_ERROR

In this error message, note the following:

  • [filer ip] is the IP address of the EMC filer
  • [data location] is the location of the data the client is attempting to access
  • [username@domain.com] is the user and domain of the user

For example:

NSM_CIFS_FILER_TREE_CONN_FAIL:: Backend-open: Tree Connect to filer 10.10.10.120 (path \\example-arx\data1-arx$) for client 10.10.100.100, user exampleWebUser@ARXexample.com, failed with error STATUS_INVALID_HANDLE (0xc0000008) - UNEXPECTED_NETWORK_ERROR returned to the client.

Message Location

You may encounter this message in the following location:

  • ARX Syslog

Description

This message occurs when the following condition is met:

  • The client attempts to access a TreeID that is no longer valid

A TreeID will no longer be valid when:

  • The client has appeared inactive for the idle period (the default is 15 minutes).
  • Multiple users share a TCP connection and one user ends the session.
  • EMC Celerra closes client connections without notifying the client due to one of the following reasons:

    • The EMC Celerra param cifs LanmanServer.IdleUserAutoLogoff option has been enabled
    • The EMC Celerra param cifs farm.IdleUserAutoLogoff option has been enabled
    • The EMC Celerra is experiencing resource exhaustion
    • License related restrictions

The ARX log message indicates that the Celerra has forced an idle client to log off. As a result, Celerra is no longer tracking the TreeID associated with the client. When the client sends another request, the ARX system attempts a Tree Connect to the EMC Celerra share with the TreeID that was valid when this client first made its connection. However, the Celerra considers the TreeID invalid, because Celerra is no longer referencing the TreeID. Once the client OS receives error messages from the ARX system, the client OS decides whether an error message displays, or if it will create a new connection without user interaction.

Impact

  • Clients are unable to access their data

Recommended Actions

None
