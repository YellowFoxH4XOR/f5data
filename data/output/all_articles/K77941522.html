Description

The Interface Mirroring feature allows you to copy traffic from any port, or set of ports, to a separate port. Interface mirroring is useful for sending traffic at wire speed to a dedicated device for troubleshooting purposes. 

If Interface mirror configuration oversubscribes the switch, packet loss may result on all switch ports.  The Interface Mirroring mirror-to port can copy traffic from several ports, but caution should be exercised when adding multiple mirror-from ports because each port added doubles the ingress buffer space needed to process the traffic.  The Interface Mirroring mirror-from port/s combined bandwith should not exceed the Interface Mirroring mirror-to port bandwidth.

Symptoms of oversubscribed Interface Mirroring:
  •   Packet loss and latency on interfaces (this will not necessarily be on the Interface Mirror mirror-to or mirror-from interfaces)
  •   Performance Throughput graphs may show a flat line when traffic is at high levels
  •   Interface drop counters incrementing
    config # tmsh show net interface
    ----------------------------------------------------------------------
    Net::Interface
    Name  Status    Bits    Bits    Pkts    Pkts   Drops  Errs       Media
                      In     Out      In     Out                          
    ----------------------------------------------------------------------

    3.1       up  792.6G       0  745.0G       0   44.9G     0  10000SR-FD
    3.2     miss       0       0       0       0       0     0        non

Note: Due to the potential impact on throughput to every port in the system as described, F5 recommends that you use interface mirroring cautiously.


Environment

Interface Mirroring 'port-mirror' configured with one of the 2 conditions below:

  • Multiple port-from ports defined in the port-mirror, or port-from combined bandwidth exceeds the port-to config
  • High throughput, or bursty traffic that exceeds internal buffer capacity of the switch chip

Cause

  • Interface mirroring effectively doubles the bandwidth usage by that interface on the shared resources of the switch (buffers). Demand on these resources exceeding the capacity of the switch can affect throughput on all ports within the system.
  • Interface mirroring at wire speed is only possible when the aggregate speed of the mirror-from port(s) matches that of the mirror-to port(s) and the overall bandwidth demand does not exceed the capacity of the switch. Failing to configure identical capability port as mirroring port—for example over-subscribing the mirror port—results in degradation of the actual data flowing through the data port, which appears as delayed or dropped traffic.

Recommended Actions

  • Only configure one Interface Mirroring mirror-from port and verify the Interface Mirroring mirror-from port bandwith does not exceed the Interface Mirroring mirror-to port bandwidth. 
  • With some configs and traffic profiles it will require removing the Interface Mirroring port-mirror config.
