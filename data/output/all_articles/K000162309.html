K000162309: Application stuck on "in progress" when deploying/modifying new application through FAST Template

Type
Support Solution
Published
2026-07-17
Updated
2026-07-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162309

Description

When deploying an application using a BIG-IP FAST template, the deployment may remain stuck in the "Pending" or "In Progress" state if the application declaration references an SSL certificate that no longer exists on the BIG-IP system. No error message is displayed in the FAST UI, but logs may show certificate lookup failures such as:

The requested Certificate File (/Common/<certificate_name>) was not found.

This issue occurs because FAST stores application and tenant data as its source of truth. If a referenced certificate is deleted manually from BIG-IP, subsequent deployments or modifications to any application within the same tenant will fail to complete.

Environment

  • BIG-IP LTM running version 17.5.1.3
  • FAST templates and AS3 extension installed
  • Multiple FAST applications deployed under the same tenant
  • Applications using client-side TLS certificates and keys
  • SSL certificate manually deleted from BIG-IP while still referenced in FAST application data
  • High-availability (HA) configuration may be present

Cause

The FAST application data retained a reference to an SSL certificate that was manually deleted from BIG-IP. When FAST or AS3 reprocesses the tenant, BIG-IP cannot resolve the missing certificate object, resulting in a 404 error and preventing the deployment from completing. Because FAST-managed application data is independent of the current BIG-IP configuration, manual removal of referenced objects can create inconsistencies and deployment failures.

Answer/Recommended Actions

  1. Identify the missing certificate
    • Review the FAST application data and restjavad logs to determine which certificate is referenced and missing.
  2. Restore or update the certificate reference
    • If possible, re-import the certificate and key using the same object name as referenced by FAST.
    • If the original certificate cannot be restored, update all affected FAST applications to reference a valid, existing certificate.
  3. Restart REST services
    • After correcting the certificate reference, restart the following services:

    bigstart restart restjavad

    bigstart restart restnoded

  4. Retry the FAST deployment
    • Confirm that the deployment progresses beyond "Pending" and completes successfully.
  5. Best practices for certificate rotation
    • Import the replacement certificate and key before updating FAST applications.
    • Update all affected FAST applications to use the new certificate.
    • Remove the old certificate only after confirming no FAST application references it.
  6. Avoid manual changes to FAST-managed objects
    • Do not manually delete or modify certificates, keys, or other objects managed by FAST. Always use FAST to manage these resources.

Additional Information

  • FAST uses BIG-IP AS3 declarations to deploy applications and tenants.
  • FAST-managed application and tenant data is the source of truth for subsequent FAST operations.
  • Adding or modifying an application in a tenant causes the entire tenant configuration to be reprocessed, including references to any missing objects.
  • Manual changes to FAST-managed applications outside of FAST can be overwritten or cause inconsistencies.
