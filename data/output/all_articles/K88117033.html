Description

When BGP has been configured and is running, a message similar to the following may appear simultaneously in messages and user.log files:

[BIG-IP hostname] warning BGP[PID]: BGP : [BGP neighbor router ID]-Outgoing [DECODE] Open Cap: IgnoringVendor specific capability, code 69 len 4

Note: The code (69 in this case) and len (4 in this case) may change.

Environment

  • BGP configured with BGP neighbor communicating with the BIG-IP system
  • Version 11.5.0 and later

Cause

This message comes from the underlying ZebOS and is passed up to TMOS where it is then logged to these two files. The message indicates that it is a BGP Open, Capabilities section and it is ignoring a vendor-specific capability of a certain code and length. In the example above, the code is 69 with a length of 4 bytes.

This is expected behavior per RFC5492 Capabilities Advertisement with BGP-4, which states "If a BGP speaker receives from its peer a capability that it does not itself support or recognize, it MUST ignore that capability." In this case the BIG-IP system is receiving an unknown capability, logs that fact along with the capability parameters and then continues with its BGP peering.

Recommended Actions

Review these messages and determine if there are any unexpected issues with the BGP peering between the BIG-IP system and its BGP neighbor. If no issues are found, this message can be safely ignored as benign.
