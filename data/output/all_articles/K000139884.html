K000139884: Service Entry configuration rejected (malformed url) for IPv6 communication

Type
Support Solution
Published
2024-09-30
Updated
2024-09-30
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000139884

Description

You have created a service entry with IPv6 endpoint as follow:

apiVersion: networking.istio.io/v1beta1
kind: ServiceEntry
metadata:
  name: ipv6se
  namespace: default
spec:
  endpoints:
  - address: fd00:10:96::cd0e
  exportTo:
  - .
  hosts:
  - 'httpbin.default.svc.cluster.local'
  location: MESH_INTERNAL
  ports:
  - name: http-7000
    number: 7000
    protocol: HTTP
  resolution: DNS

 

And on the Istio-proxy container access logs, you are seeing the Service Entry getting rejected with the following error:

2024-09-27T22:59:48.944700Z     warning envoy config    gRPC config for type.googleapis.com/envoy.config.cluster.v3.Cluster rejected: Error adding/updating cluster(s) outbound|7000||httpbin.default.svc.cluster.local: malformed url: tcp://fd00:10:96::cd0e:7000, outbound6|7000||httpbin.default.svc.cluster.local: malformed url: tcp://fd00:10:96::cd0e:7000

 

Environment

  • AspenMesh 1.14.X and later
  • Dual-Stack enabled

Cause

The Service Entry is being rejected because the resolution is set as DNS and the endpoint is also specified. When you set resolution to DNS, it indicates that the service’s endpoints should be dynamically resolved using DNS lookups. 

Recommended Actions

In order to specify the endpoints on a Service Entry, you have to select the resolution as "STATIC". For example:

apiVersion: networking.istio.io/v1beta1
kind: ServiceEntry
metadata:
  name: ipv6se
  namespace: default
spec:
  endpoints:
  - address: fd00:10:96::cd0e
  exportTo:
  - .
  hosts:
  - 'httpbin.default.svc.cluster.local'
  location: MESH_INTERNAL
  ports:
  - name: http-7000
    number: 7000
    protocol: HTTP
  resolution: STATIC

Additional Information

Once you replace the resolution to STATIC, the Service entry will be applied correctly and you won't see the rejected error
