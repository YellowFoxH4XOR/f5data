Description

Important: This article describes the legacy cryptographic infrastructure (such as OpenSSL 1.1.1 and SChannel) on Windows 9 and 10 that has reached end of support.
- Beginning in APM Client 7.2.5, TLS 1.3 is supported on Windows 11. Refer to ID 1082909.
- Beginning In APM Client 7.2.7.0, legacy cryptographic infrastructure is replaced with OpenSSL 3.5.0, to enable the support for TLS 1.3 and PQC-ready cipher suites, such as X25519+MLKEM768. For more information, refer to APM Client Release Notes 7.2.7

BIG-IP Edge Client uses several F5 software components to create a SSL-encrypted connection between a client and the BIG-IP APM system.


This article provides SSL and Transport Layer Security (TLS) information about the non-F5 components that BIG-IP Edge Client for Windows and other F5 software components use to help create an SSL-encrypted VPN tunnel between a Windows client and the BIG-IP APM system.

Note: BIG-IP Edge Client for Mac and BIG-IP Edge Client for Linux use OpenSSL for all the components (EdgeClient, svpn, and PolicyServer) and for TLS and Datagram Transport Layer Security (DTLS) communication with the BIG-IP APM system. The BIG-IP APM system uses default OpenSSL transports and ciphers, so you can't modify them on the client.

EdgeClient component

The BIG-IP Edge Client API (APPCTRL) makes the BIG-IP Edge Client's initial outbound connection to the BIG-IP system with the assistance of the WinINET framework.

When BIG-IP Edge Client processes an access policy, certain access policy agents require the client to render JavaScript. When this happens, BIG-IP Edge Client launches a pop-up window with an embedded browser. This embedded browser is a Microsoft ActiveX control which runs in browser compatibility mode. The ActiveX control uses the WinINET framework, so it uses WinINET ciphers for any SSL/TLS communications that are required to render and run the JavaScript elements within the embedded browser.

The Windows configuration (Group Policy Objects, Windows Registry, and Windows Powershell) controls the WinINET ciphers. For more information about configuring SSL/TLS options for Group Policy Objects, Windows Registry, and Windows Powershell, refer to TLS/SSL Settings.

F5 TunnelServer component

BIG-IP Edge Client creates a Point-to Point Protocol (PPP) VPN tunnel over either TLS or DTLS. The TLS-based PPP tunnel establishes to the same virtual server that the BIG-IP Edge Client initially connects with. The DTLS-based PPP tunnel depends on the configuration of the Network Access resource and requires a properly configured User Datagram Protocol (UDP) virtual server to accept the DTLS connection from the BIG-IP Edge Client.

A PPP over TLS tunnel uses a Microsoft Secure Channel (Schannel) Security Support Provider (SSP) Implementation. PPP transports over a TLS tunnel are hard-coded to TLS1.0, TLS1.1, and TLS1.2, with the Windows configuration controlling the cipher suites. Therefore, the F5 TunnelServer.exe component does not support SSL 3.0 for a PPP over a TLS tunnel. For more information, refer to How to restrict the use of certain cryptographic algorithms and protocols in Schannel.dll.

A PPP over DTLS tunnel uses OpenSSL to secure the connection and uses default transports and OpenSSL ciphers, so you can't modify them on the client. The OpenSSL version that PPP uses depends on the BIG-IP Edge Client version. You can find information about the OpenSSL version in the TunnelServer log in the %TEMP% folder.

PolicyServer component

The PolicyServer component communicates with the BIG-IP system using TLS (DTLS is not supported), and the PolicyServer component uses the Microsoft Schannel SSP implementation. The transports are hard-coded to TLS1.0, TLS1.1, and TLS1.2 (SSL 3.0 is not supported), and the Windows Schannel configuration controls the cipher suites. For more information, refer to How to restrict the use of certain cryptographic algorithms and protocols in Schannel.dll.
