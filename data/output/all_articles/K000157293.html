K000157293: After upgrading devices in Azure units may incorrectly enter in an active/active state

Type
Support Solution
Published
2025-11-09
Updated
2025-11-10
Source
https://my.f5.com/manage/s/article/K000157293

Description

After upgrading F5 BIG-IP LTM devices in an Azure HA cluster, both units may incorrectly enter an active/active state for the same traffic group. This results in failover confusion, where both devices display as "active" rather than maintaining the expected active/standby configuration. No explicit error messages are shown, but traffic-group status and system logs indicate that failover is not functioning correctly. This issue is most commonly observed when using the Cloud Failover Extension (CFE) in Azure environments.

Environment

  • F5 BIG-IP LTM
  • Microsoft Azure cloud deployment

Cause

The management IP address on both BIG-IP devices was lost or reset to localhost/loopback following the upgrade process. In Azure environments using CFE, a valid management IP is required for REST API calls that coordinate HA failover operations between devices. When this IP is incorrect or missing, CFE cannot function properly, resulting in both units becoming active simultaneously.

Recommended Actions

  • Verify that each BIG-IP device has its correct Azure-assigned management IP address configured.
    • The management IP should not be set to localhost/loopback.
  • If necessary, restore the proper management IP address for each device.
  • After correcting the management IPs:
    • Confirm CFE functionality by querying its REST endpoint.
    • Perform HA failover tests to ensure correct behavior.
    • Ensure CFE is installed and properly configured on both units.
  • Refer to KB K000149690 for further troubleshooting steps regarding management IP issues in Azure environments.
    K000149690: Management IP address is set to localhost/loopback on Microsoft Azure cloud

Additional Information

  • This issue can occur after upgrades or configuration changes in Azure environments, especially if there are conflicting DHCP and static routes on the management interface.
  • The Cloud Failover Extension depends on a valid management IP for REST API communication between HA peers.
  • If the management IP is set incorrectly (e.g., localhost), CFE will be unable to perform failover operations and both devices may become active.
