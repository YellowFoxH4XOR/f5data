K10225061: BIG-IP LTM does not forward some TCP data due to stream profile buffer last bytes

Applies to

Description

You may experience service intteruption when using stream profile, in the tcpdump capture, you can find below symptoms.

  • Client keeps retranmiss the tcp data
  • LTM does not forward some tcp data to server side, or partial tcp data forwarded except the last few bytes.

Environment

  • BIG-IP LTM
  • Virtual server
  • Stream profile

Cause

  • This is the expected behavior of using stream profile , the stream profile is intended to buffer small amounts of data to try to handle stream replacements which occur across TCP segment boundaries.
  • The last few bytes of the TCP segment match the starting few bytes of stream expression,you may see partial TCP data forwarded to server, LTM is waiting for more data to do the stream matching and replacement
  • The client and server has service logic, client may keep retransmiss the tcp data until it receives the server's response, the service will stuck there.
  • The client and server has logic flow, the client will not send any more TCP data until got the server's response.

For example, configure below irule to replace ADCD  to 1234

STREAM::expression "@ABCD  @1234"

Client sends out tcp segment payload end with ABC,like xxxABC, waiting for server response.
LTM receives the tcp segment, but only forwards xxx to server, and waiting for more data from client to do matching.

Recommended Actions

The workaround solution is to use TCP::payload replace, refer to the links in related contents, and contact F5 professional service team to create iRule if you do not know how to do it to match your environment.
