Known Issue

A Secure Web Gateway (SWG) transparent forward proxy with a captive portal may fail.

This issue occurs when all of the following conditions are met:

  • The captive portal references an access profile containing the On-Demand Cert Auth agent.
  • Client traffic to the captive portal is processed by the On-Demand Cert Auth agent.

Impact

The BIG-IP SWG system will not proxy all traffic as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After successful evaluation of the captive portal access policy, the client connection resets.
  • The client is not redirected back to the original landing URI.
  • Following the initial connection request, future requests from the client will be correctly proxied to the application.
  • You view error messages in the /var/log/apm file that appear similar to the following example:

    <device_name> err tmm[<pid>]: 01490514:3: 00000000: Access encountered error: ERR_ARG. File: ../modules/hudfilter/access/access.c, Function: access_insert_nonce_headers, Line: 16659
    <device_name> err tmm[<pid>]: 01490514:3: 00000000: Access encountered error: ERR_ARG. File: ../modules/hudfilter/access/access.c, Function: access_forward_request_to_apd, Line: 13461
    <device_name> err tmm[<pid>]: 01490514:3: 00000000: Access encountered error: ERR_ARG. File: ../modules/hudfilter/access/access.c, Function: hud_access_handler, Line: 2450

  • You view error messages in the /var/log/ltm file that appear similar to the following example:

    <device_name> err tmm[<pid>]: 01230140:3: RST sent from 172.29.67.11:443 to 172.29.67.19:52964, [0x1ea20c0:897] Not connected
    <device_name> err tmm[<pid>]: 01230140:3: RST sent from 172.29.73.100:52962 to 74.125.205.136:443, [0x1e7a982:2182] {peer} TCP RST from remote system
