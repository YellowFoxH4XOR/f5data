Issue

Distributed SSH brute-force login attacks use automated botnets to repeatedly attempt to log into target hosts using a dictionary of potential usernames and passwords. If a weak password exists on any user account configured on the device, the password may be guessed. When this occurs, the attacker is able to access the system with the permissions assigned to the compromised account. Once the target host is compromised, the attacker may install and run new processes on the target host. These processes may gather information and send it to the attacking host, or may allow the target host to be used as an automated bot to attack other systems in the vicinity or on the public internet.

Recommended Actions

There is no way to completely prevent attempted brute-force password attacks against any system on the public internet. However, you can mitigate the risk of a successful attack. The following actions significantly assist in reducing the risk of a successful brute force password attack against any system. F5 recommends that you consider these options when configuring your F5 system and any systems to which it can connect:

  • Restrict access to minimum required for administration
  • Monitoring login attempts
  • Monitor for symptoms of an SSH brute force login attack
  • Choose suitable passwords
  • Remedial actions of suspected compromise

Restrict access to minimum required for administration

Best practice states that you should not expose administrative IP addresses and ports to the public internet. This includes self-IP addresses and management ports. You should configure firewall access control lists (ACLs) configured in the networks surrounding your systems which limit access to administrative IP addresses to only the addresses from which administrative sessions should originate.

You can also limit administrative access to only those IP addresses from which the system is to be administered from within the BIG-IP or BIG-IQ configuration. F5 recommends the following configuration:

  • Restrict access to the management IP address to those IP addresses from which the system is to be administered.

    Note: For more information on this refer to K5380: Specify allowable IP ranges for SSH access.

  • Use only the management IP address to configure the system by restricting access to all other IP addresses configured on the system. For example, configure Port Lockdown to prevent administrative access to self IP addresses configured on your BIG-IP or BIG-IQ system.

    Note: For more information about the Port Lockdown setting, refer to K17333: Overview of port lockdown behavior (12.x - 16.x) or K39403510: Managing the port lockdown configuration on the BIG-IQ system.

  • If an account is not actively in use, it should be disabled to prevent any possibility of inappropriate use.

Monitoring login attempts

You can monitor attempts to log in to the system using the information provided in the following articles:

  • BIG-IP Systems: K13426: Monitoring login attempts (11.x and 16.x)
  • BIG-IQ Systems: K08662997: Monitoring login attempts on the BIG-IQ system

Note: It is important to monitor both successful and unsuccessful logins from unrecognized source IP addresses.

Important: BIG-IP system administrators can set the maximum number of login failures on the User > Authentication page. However, setting this option is not recommended: A brute-force login attack may lock you out of the system with no alternative administrative access, even if the system is not compromised.

Monitor for symptoms of an SSH brute-force login attack

If you see unexpected processes running on a system, a system is unexpectedly connecting to other systems on your network or the internet, or you cannot log into a system, the system may have been compromised. For example:

  • The output of the netstat command displays a large number of SSH connections in various TCP states

  • The system log files contain a large number of failed login messages for the same account, referencing various source IP addresses from around the world:

    notice sshd[10419]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=10.0.10.10  user=root
    err sshd[9608]: error: PAM: Authentication failure for root from 10.0.10.10
    notice sshd[10149]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=192.168.1.1  user=root
    err sshd[9608]: error: PAM: Authentication failure for root from 192.168.1.1

    There are multiple log files from which logins may be monitored. Refer to K08662997: Monitoring login attempts on the BIG-IQ for further information.

Choose suitable passwords

Strong passwords are necessary to mitigate automated brute force login attacks. For information about strong passwords, refer to Guidelines for strong passwords on Wikipedia.

  • K15497: Configuring a secure password policy for the BIG-IP system (11.x - 16.x)

Remedial actions of suspected compromise

If you suspect your BIG-IP or BIG-IQ system has been compromised, F5 recommends the remedial measures outlined in K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system.
