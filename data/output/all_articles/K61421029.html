Known Issue

The BIG-IP system may reset TCP three-way handshake connections prematurely.

This issue occurs when all of the following conditions are met:

  • Your virtual server uses the FastL4 profile.
  • The TCP three-way handshake expires unexpectedly based on the absolute value of the TCP Handshake Timeout setting.

The BIG-IP system incorrectly terminates the TCP handshake based on the absolute value of the TCP Handshake Timeout setting instead of based on the Idle Timeout setting. For example, the system resets TCP connections after five seconds of the initial SYN from the client, and the client sends subsequent SYN retransmissions within the handshake timeout period.

Impact

TCP connections expire prematurely before the TCP three-way handshake completes.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you view the BIG-IP connection tables, TCP handshake connections terminate prematurely.

Workaround

To work around this issue, you can disable the TCP Handshake Timeout setting for the FastL4 profile. To do so, perform the following procedure:

Impact of workaround: Your TCP handshake will not prematurely timeout, and incomplete TCP connections remain open until the Idle Timeout setting expires. However, if you allow idle connections to remain in the BIG-IP connection table for extended periods, the idle connections continue to consume system memory, which reduces the amount of memory available for new connections.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select the FastL4 protocol.
  4. Select the affected profile that is associated with the virtual server.
  5. Disable the TCP Handshake Timeout setting.
  6. Click Update.
