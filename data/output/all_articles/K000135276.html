K000135276: Webui Showing discrepancy of Total Tripo record when SRR is down

Published
2023-06-28

2023-06-28
Applies to

Source

Description

  • When Tripo cross site SRR is down, there will be discrepancy in the total number tripo session display on webui



Environment

  • 2 SDC site with tripo replication
  • SRR connectivity is down


Cause

When Tripo entries are sync between site; their total entries are usually in sync with the same amount. Whenever tripo record are deleted due expiration or session termination, tripo will attempting to send an SRR DEL request towards the remote site and When it fails to completed the SRR, the session is kept as DeleteOccupied (meaning that it is still been counted as part of total record)


DeleteOccupied counter will normally be 0 but in event of situation that replication connection are not working between Tripo across 2 SDC site. The value will be elevated.


 Recommended Actions

  1. Troubleshoot network connectivity issue and make sure SRR connection are restore.
  2. Alternative; if SRR link/connectivity are block deliberately. The DeleteOccupied stats can be release by using "UI_Admin -d" to free up tripo memory.

Additional Information

When a session delete request is received, the Tripo holding the Master record removes the record from the Master column locally. Slave column is updated on the Tripo mate as well and then it attempts to send an SRR DEL request towards the remote site.When a SRR delete request fails to complete, the session is kept as DeleteOccupied and it is still been counted to Total Entries.
