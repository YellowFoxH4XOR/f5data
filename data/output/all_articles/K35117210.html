K35117210: Audit Logs entries with SSL certificate and key via Configuration Utility or tmsh

Type
Support Solution
Published
2021-04-15
Updated
2023-02-21
Applies to
  • Virtual Editions
Source
https://my.f5.com/manage/s/article/K35117210

Description

This article covers various audit log entries that you can make use of in order to keep track of auditing activities related to the Device Certificate and Traffic Certificate on BIG-IP systems via Configuration Utility or tmsh.

Environment

  • BIG-IP systems running 14.x and above releases
  • A local or remote auth user with access to Configuration Utility or CLI
  • SSL certificate and key pair installed (Device Certificate or Traffic Certificate)

Cause

Audit Log entries related to performing different operations such as view/list, renew, export, import, modify or delete commands related to SSL certificate and key pairs on BIG-IP systems have been improved from v14 and above releases as part of the enhancement introduced via ID589745.

Recommended Actions

  • Configuration Utility
  • TMSH

Depending on whether the operations related to SSL Certificate and Key pair are being carried through Configuration Utility or tmsh, different messages can be logged to /var/log/audit respectively. Here are some examples on the messages that you can witness in the logs:

Configuration Utility

In order to obtain audit logging activities pertaining to SSL Certificate and Key pair operations via Configuration Utility, you must ensure that GUI logging is set to Enable under Audit Logging section within System  ››  Logs : Configuration : Options. Once the GUI logging is enabled, accessing the Device or Traffic SSL Certificates or Key will result in messages such as the following enabled:

TMSH

The tmsh list commands only allows for you to view info about the cert or key will only return it's x509 details such as validity, issuer, serial number, fingerprint, revision, size etc. But it doesn't list the actual public or private key information.  The tmsh list commands will get logged to /var/log/audit similar to the following messages:

Mar 15 15:30:51 LTM1.local notice tmsh[1452]: 01420002:5: AUDIT - pid=1452 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=list sys crypto key default.key
Mar 15 15:32:48 LTM1.local notice tmsh[1460]: 01420002:5: AUDIT - pid=1460 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=list sys crypto cert default.crt
Mar 15 15:40:11 LTM1 notice tmsh[1460]: 01420002:5: AUDIT - pid=1460 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=list sys file ssl-cert default.crt

There isn't a possibility to run a tmsh show command to view either the cert or key. However, if you run a command such as edit sys file ssl-cert <cert-name>, it will allow for you to view the public key  (similarly possible for private keys as well). It'll take you into a vi shell and, as you exit that mode (regardless of whether you make a change), you will see the following logs sent to /var/log/audit:

Mar 15 15:46:58 LTM1.local notice tmsh[1460]: 01420002:5: AUDIT - pid=1460 user=root folder=/Common module=(tmos)# status=[edit canceled] cmd_data=edit sys file ssl-cert www.derp.com.crt
Mar 15 15:52:56 LTM1.local notice tmsh[1460]: 01420002:5: AUDIT - pid=1460 user=root folder=/Common module=(tmos)# status=[edit canceled] cmd_data=edit sys file ssl-key www.derp.com.key
