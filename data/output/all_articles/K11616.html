Known Issue

This is the result of a known issue. The BIG-IP system may erroneously insert a Transfer-Encoding header when a Content-Length header already exists in the HTTP response. The Content-Length header is used when the total number of bytes of the HTTP message body is known prior to transmission. The Transfer-Encoding header is typically used when the HTTP response is split into smaller chunks, and only the size of each chunk is known prior to transmission. As outlined in RFC2616, the Content-Length header must be ignored if both a Transfer-Encoding header and a Content-Length header are sent.

F5 Product Development tracked this issue as CR136660 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP APM, ASM, LTM, PSM, or WebAccelerator release notes.

This issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
