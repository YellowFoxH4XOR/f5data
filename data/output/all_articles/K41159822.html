K41159822: /Common/f5_api_com.crt will expire and unable to delete in configuration utility

Support Solution
Published
2022-02-06
Updated

Source

Description

Unable to delete expired f5_api_com.crt via Configuration Utility

  • Certificate list shows f5_api_com.crt expired or soon to expire in the Configuration Utility
  • Unable to delete the certificate from the list

Environment

Device has an f5_api_com.crt and f5_api_com.key

  • Certificate expiration date is near or past for f5_api_com.crt
  • Log events indicating certificate will or has expired

Cause

The certificate is near or exceeded expiration date.  Attempting to delete the certificate fails.  Cause is unknown at time of article creation.

Recommended Actions

Steps to manually remove device certificate and key.

  1.  Manually edit bigip.conf
    1. Remove references to the f5_api_com.crt and f5_api_com.key from the bigip.conf file:
    2. Use a text editor such a Vi to manually delete or comment out the reference sections for the cert and key.
      Example:
      sys file ssl-cert /Common/f5_api_com.crt {
          cache-path /config/filestore/files_d/Common_d/certificate_d/:Common:f5_api_com.crt_12345_1
          revision 1
          source-path file:///config/ssl/ssl.crt/f5_api_com.crt
      }

      sys file ssl-key /Common/f5_api_com.key {
          cache-path /config/filestore/files_d/Common_d/certificate_key_d/:Common:f5_api_com.key_12345_1
          passphrase [redacted]
          revision 1
          source-path file:///config/ssl/ssl.key/f5_api_com.key
      }
       
  2. Manually delete or move the certificate and key files.
    1. rm /config/ssl/ssl.crt/f5_api_com.crt
    2.  rm /config/ssl/ssl.key/f5_api_com.key

  3. Reload the configuration files with the command "tmsh load sys config".  Then confirm that the f5_api_com references are gone (in /config/bigip.conf and check the directory (ls -la /config/ssl/). Stop here if they reappeared.

  4. If the references are gone in step 3, continue by running this command "tmsh save sys config". 
  5. Now, re-activate the system license. This should cause a new API certificate to be installed and resolve the issue.
 

Additional Information

Doing this procedure will disable the phone home feature as the cert and key is used as a authentication mechanism for this service.  If you would like to use the phone home feature the cert and key should be able to be recreated using the AUTOMATIC License activation process.  Manual License activation will not generate the needed cert/key pair.
