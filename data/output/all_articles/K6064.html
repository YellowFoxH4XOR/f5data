Disabling Path MTU Discovery enforcement

Note: You may be able to determine the Path MTU size of the hops along the path to a destination by using the tracepath -n <destination address> Linux command.

Beginning in BIG-IP 9.1.2 and 9.3.0, you can disable the Path MTU Discovery enforcement. When disabled, the BIG-IP system no longer processes ICMP Fragmentation Needed messages (Type 3 Code 4), and continues to send oversized packets to endpoints that are unable to process the packets. To disable the BIG-IP system's path MTU enforcement and configure the system to transparently forward ICMP Fragmentation Needed messages and only generate ICMP Fragmentation Needed messages for packets that are too large for the BIG-IP system's configured MTU on the receiving interface, type the following command at the command line:

Important: Disabling the BIG-IP LTM system's path MTU enforcement may have adverse effects on the handling of traffic that requires a smaller MTU. Do not disable this setting unless F5 Technical Support recommends that you do so.

bigpipe db TM.EnforcePathMtu disable

When you disable the BIG-IP system's path MTU enforcement option, you should also disable the Route.Metrics.Mtu feature, preventing the BIG-IP system from obtaining MTU information from route metrics.

Preventing BIG-IP from obtaining MTU information from route metrics

Beginning in BIG-IP 9.1.2 and 9.3.0, you can prevent the BIG-IP system from obtaining MTU information and route metrics. To do so, type the following command at the command line:

bigpipe db Route.Metrics.Mtu disable

This command is useful when dealing with routers that use NATs for multiple connections. Disabling route metrics prevents the BIG-IP system from assigning the same or lower MTU to all of the connections coming from the address that uses NAT, even though all of the connections through the NAT can have various MTUs. The BIG-IP system can negotiate the MTU requirements of each connection separately.

Note: If the system prevents ICMP messages from reaching the offending host by not forwarding ICMP Fragmentation Needed messages, client or server application failures might result.

Note: You cannot query the current status of the route metric cache on BIG-IP 9.x through 10.x. F5 Product Development tracked a request to add this capability as ID 222463 (formerly CR119918), and it was included in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.
