K6150: The big3d agent attempts to run certain monitors from the wrong directory on BIG-IP LTM 9.0.x and 9.1.x

Known Issue

This is the result of a known issue. When BIG-IP GTM assigns a 9.0.x or 9.1.x BIG-IP LTM system to monitor resources, using one of the affected monitors listed below, the big3d agent attempts to run the monitors from the /usr/bin/monitors/builtins directory, which does not exist in version 9.0.x or 9.1.x.

The following is a list of affected monitors:

  • DB_monitor
  • POP3_monitor
  • UDP_monitor
  • DB_monitor.jar
  • RADIUSACCT_monitor
  • WAP_monitor
  • FLAPLNK_monitor
  • RADIUS_monitor
  • WMI_monitor
  • FTP_monitor
  • RS_monitor
  • base_monitors.conf
  • GENERIC_monitor
  • SIP_monitor
  • classes12.jar
  • IMAP_monitor
  • SMTP_monitor
  • fakewap
  • LDAP_monitor
  • SNMPDCABASE_monitor
  • gtm_base_monitors.conf
  • MSSQL_monitor
  • SNMPDCA_monitor
  • tcp_half_open
  • NNTP_monitor
  • SOAP_monitor
  • wrap_pinger
  • ORACLE_monitor
  • SYSLOG_monitor

The following symptoms are a result of your BIG-IP GTM assigning the BIG-IP LTM to an affected monitor:

  • The resources are marked down when the BIG-IP LTM version 9.0.x or 9.1.x is tasked to monitor them.This generally results in flapping, which is when the resource fluctuates between being marked up and down. This happens because the BIG-IP LTM usually shares monitoring duties with the BIG-IP GTM in the same data center.
  • Error messages in the /var/log/gtm file on the BIG-IP LTM will appear similar to the following example:

    Feb 28 12:09:10 bison big3d: 01330017:3: Can not find /usr/bin/monitors/builtins/LDAP_monitor
    Feb 28 12:09:15 bison big3d: 01330017:3: Can not find /usr/bin/monitors/builtins/RADIUS_monitor

F5 Product Development tracked this issue as CR59986 and it was fixed in BIG-IP GTM 9.3. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Workaround

You can work around this issue by creating a symbolic link from the /usr/bin/monitors/builtins directory to the correct directory. In versions 9.0.x and 9.1.x the monitors are located in the /usr/bin/monitors directory.

Create the symbolic link by typing the following command:

ln -s /usr/bin/monitors /usr/bin/monitors/builtins
