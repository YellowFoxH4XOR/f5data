Description
SNMP RFC has a limitation on oid size (128) and the BIG-IP will modify the supplied oid name to limit the size of the oid.

For example:
snmpwalk -v 2c -c public localhost ltmPoolName

F5-BIGIP-LOCAL-MIB::ltmPoolName."/Common/verylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnamever30cc2bc9" = STRING: /Common/verylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolname

  • pool name : /Common/verylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolname
  • hashed pool name : /Common/verylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnameverylongpoolnamever30cc2bc9


 

SNMP is truncated like this due to the depth - how many layers deep - and is capped at 100 layers for the index piece which encodes the pool name and pool member name together. 

As an example the OID of .1.3.6.....

Breaks down like this to understand the layering more easily. Notice this is now "3 layers"
1
3
6

So within our design we designate 28 "layers" for enterprise ID and leave 100 for actual index part which is the numerical encoding of the pool name.

This is due to RFC's max depth of 128:
https://datatracker.ietf.org/doc/html/rfc2578

3.5.  OBJECT IDENTIFIER values

   An OBJECT IDENTIFIER value is an ordered list of non-negative
   numbers.  For the SMIv2, each number in the list is referred to as a
   sub-identifier, there are at most 128 sub-identifiers in a value, and
   each sub-identifier has a maximum value of 2^32-1 (4294967295
   decimal).
