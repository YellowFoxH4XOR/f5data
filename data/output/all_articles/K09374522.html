Description

The vCMP guest stays INOPERATIVE state after upgrading the vCMP host or vCMP guest. 

When you access the vCMP Guest via vconsole and the cli is having a slow response, the following error messages logged in /var/log/ltm:

01071038:5: Loading keys from the file.
012a0004:4: halStorageRead: unable to read storage on this platform.
01071029:5: Cannot open unit key store

Environment

  • vCMP
  • Software Upgrade

Cause

Any of the following: 

  • Bug ID 769809: vCMP guests 'INOPERATIVE' after upgrade
  • Bug ID 810593: Unencoded sym-unit-key causes guests to go 'INOPERATIVE' after upgrade
  • vCMP guests are sent a truncated unit key and fail to decrypt the master key needed to load the config.
  • Hardware failure

Recommended Actions

To work around the issue you may consider the following procedure. 

Important: It is recommended to update the device Master Key during the initial configuration such as restoring UCS archive or configuring an RMA unit and use the f5mku utility to update the Master Key.

  1. Boot the BIG-IP to the working partition
    For example, if the working partition is HD1.1 you may run the below command

    switchboot HD1.1

  2. Gather UCS backup and Master Key from both vCMP host  and vCMP guest

    To display the current Master Key you may run the command:
    f5mku -K

    For Example:
    f5mku -K
    8/igZhCdlag5Z4rbuOpFtg==

  3. Boot the vCMP host or guest back to the upgraded version

  4. Verify the Master Key on the upgraded version is the same as the working version

    f5mku -K

  5. If the Master Key is not the same, then update the master key, with this command and the master keys retrieved in step 2:

    f5mku -r <master key>

    For Example:
    f5mku -r 8/igZhCdlag5Z4rbuOpFtg==

  6. Comment out the sym-unit-key of every guest in /config/bigip.conf:
    Note: A backup file will created: /config/bigip.conf.bak

    sed -i.bak 's/sym-unit-key/#sym-unit-key/g' /config/bigip.conf

  7. Manually load the configuration of vCMP host system from the command line

    tmsh load sys config

  8. Reboot the host
    Note: Without a reboot, the changes will not take effect.

    tmsh reboot

  9.  After the host rebooted, all guests should boot normally
    Note: If the vCMP guest config failed to load due to decryption failed, import Master Key - gathered from step 2 - and manually load the config.

Additional Information

• The command switchboot may not function as needed.
• You will need to know which volume to boot back to.
• In cases where a rollback is not possible a rebuild of the guest will be necessary.
  This rebuild can be done with the use of a UCS backup or from scratch.
• Building the guest from a fixed version is strongly recommended.
