Description

After an upgrade, the BIG-IP system may become unresponsive, perform very slowly, and display the following out of memory and configuration load errors:
  • You observe log messages in /var/log/kern.log similar to the following:

    warning kernel: syslog-ng invoked oom-killer: gfp_mask=0x201da, order=0, oom_adj=0, oom_score_adj=0
    err kernel: Out of memory: Kill process 6871 (java) score 8 or sacrifice child
    err kernel: Killed process 6871 (java) total-vm:464272kB, anon-rss:69712kB, file-rss:0kB, shmem-rss:0kB

  • You observe log messages in /var/log/ltm similar to the following:

    err tmsh[11538]: 01420006:3: Loading configuration process failed.
    emerg load_config_files[11535]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- Loading schema version: 12.1.2
    err mcpd[8944]: 01070425:3: Full configuration load failed.

The system may exhibit the following additional symptoms:
  • GUI (Configuration utility) access times out after a few seconds and reports an Unable to contact BIG-IP device error.
  • The Configuration utility displays the following:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

  • You observe high CPU usage with most cycles going to I/O wait.
  • Intermittent or no access to the BIG-IP command line.

Environment

  • BIG-IP 13.x and later excluding versions indicated as fixed in the Bug Tracker article referenced in the next section.
  • A BIG-IP Upgrade
  • Configuration error that is exposed after an upgrade.

Cause

The resource exhaustion issues described in this article are caused by Bug ID 886693.

Recommended Actions

Upgrade to a fixed version or refer to the workaround section in Bug ID 886693.
