Known Issue

When the user attempts to connect to a virtual server that has an access policy that includes the On-Demand Cert Auth action assigned to it, the user's session appears to hang indefinitely. This issue occurs because the On-Demand Cert Auth action does not prompt the BIG-IP APM, Edge Gateway or FirePass to send a certificate request to the user.

Workaround

In the BIG-IP APM and Edge Gateway systems, you can work around this issue by creating a custom Client SSL profile that has the Renegotiation option enabled, and assigning it to the virtual server.

Creating a custom Client SSL profile

  1. Log in to the BIG-IP APM Configuration utility.
  2. Click on Local Traffic.
  3. Click on Profiles.
  4. Click on SSL.
  5. Click on Client.
  6. Click Create.
  7. In the Name field, enter a name for the profile.
    For example:
    Reneg_clientssl
  8. Change the Configuration drop-down menu to Advanced.
  9. Select the Custom check box.
  10. Select the Renegotiation check box.
  11. Leave all other values at their default settings.
  12. Click Finished.

Apply the custom Client SSL profile to the virtual server

  1. Click on Local Traffic.
  2. Click on Virtual Servers.
  3. Click on the virtual server link to which the access policy is applied.
  4. In the Configuration section, change the SSL Profile (Client) drop-down menu to the custom Client SSL profile that you created.
  5. Click Update.
