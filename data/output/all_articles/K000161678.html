K000161678: OSPF adjacency between BIG IP and OSPF peer flaps when AFM is configured in Firewall mode

Type
Support Solution
Published
2026-06-12
Updated
2026-06-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161678

Description

When BIG-IP with AFM provisioned and AFM running in Firewall mode, OSPF adjacency between BIG-IP and OSPF peer will flap periodically. A BIG-IP capture will show BIG-IP responded to OSPF Link State Update packets with ICMP "Protocol 89 unreachable" messages, causing the OSPF peer to reset the OSPF neighbor relationship after excessive retransmissions.

Environment

  • BIG-IP LTM with AFM provisioned
  • Firewall policy allowing OSPF traffic applied to route domain
  • Self IP allow-service set to default (includes OSPF)
  • sys db tm.fw.defaultaction set to reject
  • No explicit AFM firewall policy applied to the affected self IP

Cause

When AFM is set to firewall mode (tm.fw.defaultaction = reject), the self IP allow-service setting alone does not permit OSPF traffic. Without an explicit AFM firewall policy allowing OSPF attached to the self IP, OSPF packets are rejected, resulting in adjacency failure. This behavior is tracked under Bug ID 2099685.

Answer/Recommended Actions

Create a firewall policy using the built-in _sys_self_allow_defaults rule list.

Apply this policy to the affected self IP and set allow-service to default.

Save the configuration.

Verify OSPF adjacency is restored and no further ICMP "protocol 89 unreachable" messages are observed.
