Description

The BIG-IP file system may become read-only while writing to the disk, which can prevent writing to the disk. 
This means there is a logical problem with the filesystem data. This can be caused by software or firmware corruption, or unexpected reboots days or years before the event.

If the filesystem has been made read-only by the kernel, after attempting to recover information about the root cause, or salvaging data from other filesystems, the system usually requires a reboot to recover.

You may notice a message similar to:

Error: EXT3-fs error (device dm-3): ext3_free_blocks not in datazone

You may also see a similar log under /var/log/kern.log:

BIG-IP crit kernel: EXT3-fs error (device dm-13): ext3_get_inode_loc: unable to read inode block - inode=102924, block=409668

Environment

  • BIG-IP file system errors

Cause

The file system state is marked as read-only and the BIG-IP system cannot start the installed software. The console displays file system errors.

Recommended Actions

When your BIG-IP system experiences files system issues, the device is possibly entered into Linux OS maintenance mode. 
You can use the following troubleshooting procedures to attempt to repair the erroneous file system(s) to resolve file system inconsistencies.  

1. Forcing a file system check on the next system restart

  1. Log in to the command line.
  2. To create the /forcefsck file, enter the following command:
            # touch /forcefsck

During the next restart, the /forcefsck file causes the system to perform a file system check.

       3. If you want to restart the system at this time, enter the following command:
              # reboot

              The system restarts and performs the fsck file system check. After the fsck operation has finished checking the file systems, the system continues to boot normally into the proper run levels.

              Note: The /forcefsck file is deleted as the system boots and does not remain for subsequent restarts.

2. If the BIG-IP system is still running as read-only after the previous procedure, run the EUD to detect possible hardware drive errors.

              Note: Refer to K7172: Overview of the End User Diagnostics software
