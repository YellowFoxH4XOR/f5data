Description

Understanding whether an HTTP/2 profile is configured on a virtual server allows you to verify compatibility or ensure optimal traffic handling for your HTTP connections. This guide explains how you can check if the HTTP/2 profile is properly applied.

Environment

  • BIG-IP LTM
  • Virtual servers
  • HTTP/2 profile

Cause

None

Recommended Actions

1. List All Configured HTTP/2 Profiles Your virtual server may use the default HTTP/2 profile (`http2`) or a custom profile. 

To list all HTTP/2 profiles: 

tmsh list ltm profile http2

 

2. Identify Which Virtual Servers Reference HTTP/2 Profiles

To find all virtual servers that reference any of your HTTP/2 profiles, use:

tmsh list ltm virtual all profiles | grep -e http2 -e <custom_profile_1> -e <custom_profile_2>

Replace <custom_profile_1>, <custom_profile_2>, etc. with the names from Step 1 if you have custom profiles.

3. Determine Which Virtual Servers Reference HTTP/2 Profiles

To get a mapping of virtual server names to their HTTP/2 profile assignments:

tmsh list ltm virtual all profiles | grep 'ltm virtual\|http2\|<custom_profile_1>\|<custom_profile_2>'

4. Determine Profile Context: Client-Side or Server-Side

To check whether the HTTP/2 profile is attached on the client-side, server-side, or both, review the full profile section of the relevant virtual server(s):

tmsh list ltm virtual <virtual_server_name> profiles

 

5. Identify Full Proxy (Both Sides) and MRF Router Usage

If both context clientside and context serverside are present for HTTP/2, and you see a httprouter profile attached, this virtual server is configured for full-proxy HTTP/2 (both inbound and outbound).

Additional Notes

  • If no output is returned in Steps 2 or 3, no virtual server is using an HTTP/2 profile.
  • For full-proxy mode (client and server side), the presence of both HTTP/2 profiles and the httprouter profile is required.
  • The above commands also reveal other profiles such as SSL or HTTP that may be relevant to your deployment.
