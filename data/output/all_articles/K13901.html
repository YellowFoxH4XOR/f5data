Known Issue

Configuring the TCP options database variable may cause TMM to core.

This issue occurs when the following condition is met:

  • The Rules.Tcpoption.settings db variable is modified.

Impact

TMM may core and the device may restart resulting in a service interruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Messages similar to the following example are written to the /var/log/tmm file:

    SIGFPE with error: ../modules/hudfilter/tcp4/tcp4.c:7359: Assertion "Too many
    option settings, max is 253" failed.

  • Core files similar to the following example are written to the /var/core/ directory:

    tmm.7.bld1789.135.core.gz

Resolution

Status

F5 Product Development has assigned ID 361745 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release10.2.3K2200: Most recent versions of F5 software
Hotfix10.2.2 HF1K9502: BIG-IP hotfix matrix

Note: Although BIG-IP 10.2.0 is included in the Applies To box, the ability to configure the rules.tcpoption.settings db variable was not added until BIG-IP 10.2.0 HF2. Earlier versions of 10.2.0 are not affected.

Workaround

To work around this issue, you can stop BIG-IP services before modifying the db key and restart the BIG-IP services after completing the modification. To do so, perform the following procedure:

Impact of workaround: You must restart BIG-IP services, which will result in a service interruption.

  1. Log in to the BIG-IP command line.
  2. Stop BIG-IP services by typing the following command:

    Important: This will cause a service interruption.

    bigstart stop

  3. Configure the TCP options DB variable using the following command syntax:

    bigpipe db Rules.Tcpoption.settings [option, first|last], [option, first|last]

    For example:

    bigpipe db Rules.Tcpoption.settings [8,first],[28,last]

  4. Restart BIG-IP services by typing the following command:

    bigstart start
