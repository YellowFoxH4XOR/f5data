K000152317: TMM crashing when In-TMM TCP monitor is configured without recv or recv-disable strings

Type
Support Solution
Published
2025-07-01
Updated
2025-10-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.5, 16.1.6, 17.1.2, 17.5.0
Source
https://my.f5.com/manage/s/article/K000152317

Description

Configuring an In-TMM TCP monitor without any "recv" or "recv-disable" string may result in a TMM crash. When this occurs, TMM restarts, causing temporary traffic disruption. 

A typical configuration that can trigger the issue appears as follows:

ltm monitor tcp tcp {
    adaptive disabled
    destination *:*
    interval 5
    ip-dscp 0
    recv none
    recv-disable none
    send "GET / HTTP/1.0\r\n\r\n"
    time-until-up 0
    timeout 16
}

Note: This issue does not occur when bigd monitor is used.  

 

Environment

This issue occurs when all of the following conditions are met:

  • The system is running one of the affected versions.
  • In-TMM monitor is enabled.
  • A TCP monitor is defined with a "send" string but without either a "recv" or "recv-disable" string.

 

Cause

This issue is due to a defect in the handling of In-TMM TCP monitor configuration that omits both "recv" and "recv-disable" strings. It is tracked as ID1819777.

 

Recommended Actions

To avoid this issue, take one of the following steps:

  • Ensure your TCP monitor configuration includes an explicit match string for either the "recv" or "recv-disable" conditions.
  • Remove the send string.
  • Disable In-TMM monitoring if you do not require it for your use case.
  • Upgrade to a fixed version.
