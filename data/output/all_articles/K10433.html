Known Issue

This is the result of a known issue. When you insert a VIPRION blade with an active boot location that differs from the primary blade, the VIPRION system will drop packets.

When a new blade configured with the same BIG-IP software version is installed on a different boot location than the primary blade, the system automatically installs the necessary software to the blade. However, the VIPRION system does not verify whether the active boot location matches the boot location for the primary blade before installing the software to the new blade; the VIPRION automatically installs the software on the active boot location. Once the software and configuration is installed to the new blade, the clusterd process adds the new blade to the cluster. If the boot location of the new blade does not match that of the primary blade, the clusterd process removes the blade from the cluster, reboots the blade so it will boot into the matching boot locations and performs the installation again before adding to the cluster. When traffic is sent to the newly installed blade, which has been abruptly removed by the clusterd process, packet loss occurs.

This issue is more likely to occur when a blade is removed from a VIPRION system where it was configured to boot to a different location, and then moved to another VIPRION system, which contains a setup where the primary blade utilizes a different boot location. For example, this issue will occur when adding or replacing a blade in a production system with a blade from a staging system, whose setup includes a different boot location than the product system.

F5 Product Development tracked this issue as CR124960 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, WebAccelerator, and WOM release notes.

This issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
