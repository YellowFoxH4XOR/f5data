This solution assumes that:

  • You want to maintain persistence for users accessing a virtual server (VIP) and an SSL proxy on BIG-IP
  • The ports on your web server are configured with the following parameters:
    • Port 80: Non-encrypted, low security content
    • Port 88: Contains sensitive material, with encryption and decryption performed by the BIG-IP SSL gateway.

The key to cookie persistence is to share the same cookie for HTTP and HTTPS. Since the cookie is created from node IP/pool information, it is crucial that the VIPs for HTTP and HTTPS use the same pool.

To configure cookie persistence to maintain persistence between HTTP (VIP) and HTTPS (SSL Proxy) sessions, perform the following steps.

  1. Create a pool with cookie persistence for this pool. The node port should be 0.
  2. Create a virtual server (VIP) for HTTP traffic on port 80 using the pool created in step 1.
    Disable port translation for this VIP.
  3. Create a second VIP on the loopback network (for example, 127.0.0.100:88) using the pool created in step 1.
    Disable port translation for this VIP.
  4. Create the SSL proxy. Specify the target of the proxy as the VIP created in step 2.

    Disabling port translation on both VIPs allows BIG-IP to use the same cookie for the two different services. After they are configured, the VIPs pass the traffic to the nodes on the port in which it received the connection. In this example that is port 80 for clear text HTTP, and port 88 for HTTPS/secure traffic.

Note: For specific instructions about creating pools, virtual servers, and SSL proxies, refer to the BIG-IP manuals.
