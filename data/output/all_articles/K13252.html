Known Issue

The ARX Network Lock Manager (NLM) daemon fails to release connection file descriptors used for sending call-backs to notify a client waiting for a file lock to become available.

This issue occurs when all of the following conditions met:

  • Clients are using NFS file locking
  • Multiple clients attempt to open and lock the same file concurrently

When multiple clients attempt to lock a file, the initial client is allowed to lock the file. The NLM daemon establishes a connection with the subsequent client to send a call-back and notify the client when the file lock is available. The ARX system has 1,024 file descriptors available for these NLM connections. Once the resource of file descriptors has been exhausted, the NLM daemon is no longer able to establish the connection and can no longer notify the client when the file is available to be locked.

Impact

Clients attempting to lock files may experience performance degradation and/or unexpected behavior.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Once the resource of file descriptors has been exhausted, the NLM daemon is no longer able to establish the connection and can no longer notify clients when file locks are available
  • Clients attempting to open a locked file may hang and/or experience performance degradation
  • The ARX syslog file will contain messages that appear similar to the following example:

    :NLM-0-NOTE-MSG5:: RRPC connect to NSM 169.254.214.65 failed. Error 'Too many open files'. Retrying...
    :NLM-0-NOTE-MSG5:: RRPC connect to NSM 169.254.214.65 failed. Error 'Too many open files'. Retrying...
    :NLM-0-NOTE-MSG5:: RRPC connect to NSM 169.254.214.65 failed. Error 'Too many open files'. Retrying...
