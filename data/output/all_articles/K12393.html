Known Issue

NTLM clients may receive an 'Access Denied' error message when attempting to access a CIFS share on a Windows 2008 R2 or Windows 2003 server.

This issue occurs when all of the following conditions are met:

  • Clients Authenticating with NTLM or NTLMv2
  • Windows 2008 R2 or Windows 2003 server with 128-bit encryption required for Network security: minimum session security

By default, Windows 2008 R2 servers require 128-bit encryption for NTLM SSP minimum session security. Prior to version 5.2.0 the ARX system did not support 128-bit encryption for NTLM SSP sessions.

Note: Windows 2003 servers are not configured, by default, for 128-bit encryption for NTLM SSP minimum security settings, but you can configure this item.

Impact

Clients are unable to authenticate by way of NTLM or NTLMv2 to the ARX resources.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Affected clients may receive an 'Access Denied' error message when attempting to access a CIFS share.

Workaround

To work around this issue, you can disable the default NTLM SSP requirement. To do so, perform the following procedure on the Windows 2008 R2 server:

  1. Log in to the Windows 2008 R2 server.
  2. Open the Local Security Policy.

    Note: You may access the Local Security Management console using the mmc secpol.msc command at the Windows Run prompt.

  3. Navigate to Local Policies >> Security Options.
  4. Open the properties for the Network security: Minimum session security for NTLM SSP based (including secure RPC) clients setting.
  5. Clear the Require 128-bit encryption check box.
  6. Open the properties for the Network security: Minimum session security for NTLM SSP based (including secure RPC) servers setting.
  7. Clear the Require 128-bit encryption check box.
  8. Click the OK button.
