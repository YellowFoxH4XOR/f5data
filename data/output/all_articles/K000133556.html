K000133556: Original IP address sent to backend servers for non HTTP traffic when SNAT configured

Type
Support Solution
Published
2023-04-19
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K000133556

Description

Sometimes SNAT configured is a must but also the original IP address is required in the backend servers

Environment

  • SNAT.
  • Non-HTTP traffic
  • TCP

Recommended actions

For achieving this you can include the original IP address (before SNAT) as a non-standard field in the TCP options field, the backend server should be able to read the original IP address from there and use it.

 

You must configure an specific tcp profile as follows:

 

# create ltm profile tcp tcp-options-28 tcp-options "{8 first} {28 last}"

 

# list ltm profile tcp tcp-options-28

ltm profile tcp tcp-options-28 {

  app-service none

  tcp-options "{8 first} {28 last}"

}

 

and then create an iRule that includes the following:

 

when SERVER_CONNECTED {

scan [IP::client_addr] {%d.%d.%d.%d} a b c d

TCP::option set 28 [binary format cccc $a $b $c $d] all

}

 

then assign the modified tcp profile and the iRule to the VS, and then when the Server is connected (the next message after the TCP handshake) we can see:

 

 You will see in the TCP Option field the byte-coded original IP address
