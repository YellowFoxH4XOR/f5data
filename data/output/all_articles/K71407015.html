Topic

You should consider using this procedure under the following conditions:

  • User Datagram Protocol (UDP) flood attack traffic is hitting the BIG-IP system.
  • BIG-IP AFM is provisioned on the BIG-IP system.
  • You want to use BIG-IP AFM DoS Protection profile or device-level DoS protection configuration on the BIG-IP system to mitigate the attack.

Description

UDP is a standard protocol for communication across IP networks, but, in contrast to TCP, UDP packets are stateless and thus require less error checking and validation. A UDP flood attack attempts to overload a server with requests by saturating the connection tables on every accessible port on a server. Filling the connection table with these requests prevents valid requests from being served, and the server can become inaccessible to valid clients.

BIG-IP AFM can mitigate UDP flood attack by detecting and rate-limiting UDP traffic hitting the self IP address or a virtual server using defined thresholds in the DoS Protection profile or device-level DoS protection configuration.

Note: When the BIG-IP AFM system is under DoS attack, the DoS Protection profile limits its mitigation effects to the associated virtual server; device-level DoS protection limits its mitigation effects to every virtual server on the BIG-IP AFM system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the BIG-IP AFM Configuration utility.
  • You have access to the console or an SSH session to the BIG-IP AFM system.
  • You have administrator access to the BIG-IP AFM system.

Procedures

The following sections discuss what you should look for when you review the device-level DoS protection or the DoS Protection profile statistics. They also provide sample statistics and tunings for UDP flood attack traffic:

  • Reviewing UDP flood attack traffic statistics
  • Configure the Detection and Rate Limit Thresholds for UDP Flood Attack type

Reviewing UDP flood attack traffic statistics

Depending which you are configuring, reviewing the UDP flood traffic statistics generated from device-level DoS protection or a Network Security-enabled DoS Protection profile helps determine a baseline of the amount of traffic for this type of attack vector. You need to periodically observe the Stats Rate (packet per second) and Stats 1m (amount of packets in the last minute) values for this attack type.

For example:

UDP Flood Statistic taken at 00:01:00 (HH:MM:SS)

Stats Rate                    52
Stats 1m                      3120

UDP Flood Statistic taken at 00:05:00 (HH:MM:SS)

Stats Rate                    70
Stats 1m                      4200

UDP Flood Statistic taken at 00:10:00 (HH:MM:SS)

Stats Rate                    60
Stats 1m                      3600

UDP Flood Statistic taken at 01:00:00 (HH:MM:SS)

Stats Rate                    100
Stats 1m                      6000

From these sample statistics, captured for an hour, the Stats Rate value average (mean average) is around 70 packets per second for the observed hour and may be the baseline traffic for the UDP attack type. The Stats 1m value provides an idea whether there was a traffic spike observed in the last minute. That is, if the Stats 1m value is 6000 you can safely assume that an average of 60 packets per second were observed in the last minute.

The following example shows a possible traffic spike:

UDP Flood Statistic taken at a possible traffic spike 

Stats Rate                    1000
Stats 1m                      276354

The sample statistics for Stats 1m is 276354 and Stats Rate is 1000, which is a 210% traffic spike in the last minute assuming that the average Stats Rate is 1000 packets per second.

Depending on your environment needs, you can perform either one or both of the following procedures to gather your baseline:

  • Viewing UDP flood attack statistics for device-level DoS protection
  • Viewing UDP flood attack statistics from DoS Protection profile applied to a virtual server

Viewing UDP flood attack statistics for device-level DoS protection

To determine the Stats Rate and Stats 1m values from device-level DoS protection configuration, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on the system.

  1. Log in to the command line of the system/
  2. To view the UDP flood traffic statistics from Dos device attack types as observed by the BIG-IP AFM system, enter the following command:

Viewing UDP flood attack statistics from DoS Protection profile applied to a virtual server

To determine the Stats Rate and Stats 1m values from the Network Security-enabled DoS Protection profile, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on the system.

  1. Log in to the command line of the system.
  2. To view the UDP flood traffic statistics from the DoS Protection profile, enter the following command syntax:

    tmsh show security dos profile <AFM Network Security enabled DOS Profile> { dos-network } | grep -i 'udp flood' -B 2 -A 27 | grep 'Virtual Server Name: <Virtual Server Name>' -B 2 -A 20

    For example, the following command displays the afm-dos profile that is applied to the vs-https virtual server:

Configuring the Detection and Rate Limit thresholds for UDP flood attack type

Depending on your environment needs, you can perform either one or both of the following procedures to configure the detection and mitigation thresholds for UDP flood attack type:

  • Tuning device-level DoS protection
  • Configuring the Network Security-enabled DoS Protection profile

Tuning device-level DoS protection

To tune the device-level DoS protection settings for mitigating UDP flood attack type, perform the following procedure:

Impact of procedure: Depending on your application environment, you need to determine the threshold values acceptable for your application environment.

BIG-IP AFM 14.x

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > Device Protection.
  3. Click Network to expose the UDP Flood attack type.
  4. Click UDP Flood attack type to expose its properties
  5. Modify the values for the following settings acceptable to your application environment:
    • Mitigation Threshold EPS
    • Detection Threshold %
    • Detection Threshold EPS*
  6. Click Commit Changes to System.

BIG-IP AFM 13.x

  1. Log in to the Configuration utility
  2. Navigate to Security > DoS Protection > Device Configuration > Network Security.
  3. Click the Add icon (+) next to the Flood category to expose the UDP Flood attack type.
  4. Click UDP Flood attack type to expose its properties.
  5. Modify the values for the following settings to those acceptable to your application environment:
    • Mitigation Threshold EPS
    • Detection Threshold %
    • Detection Threshold EPS*
  6. Click Update.

BIG-IP AFM 12.x

  1. Log in to the Configuration utility
  2. Navigate to Security  >  DoS Protection > Device Configuration.
  3. Click the Add icon (+) next to the Flood category to expose the UDP Flood attack type.
  4. Click UDP Flood attack type to expose its properties.
  5. Modify the values for the following settings to those acceptable to your application environment:
    • Detection Threshold PPS*
    • Detection Threshold Percent
    • Rate Limit
  6. Click Update.

For BIG-IP AFM DoS device-level protection, the threshold and rate limit values are applied per TMM. For more information, refer to K15023: The BIG-IP AFM system enforces configured thresholds and limits for each TMM.

*For Detection Threshold EPS/PPS value, as a sample possible value, allow an acceptable value to accommodate expected increase of this type of traffic. For example, if the Stats Rate value has an average value of 5000 packets per second, you are configuring four TMMs in the BIG-IP AFM, and the Detection Threshold EPS/PPS value is set to 8000, this allows the BIG-IP AFM to potentially handle a total of 31996 UDP flood packets before BIG-IP AFM detects the UDP Flood attack vector. However, if one of the TMMs exceeds the Detection Threshold EPS/PPS value of 8000, for example 8100, the BIG-IP AFM detects the UDP Flood attack and generates a log similar to the following example in the /var/log/ltm file:

err tmm1[21964]: 01010252:3: A Enforced DOS attack start was detected for vector UDP flood, Attack ID 480207285.

When the UDP Flood attack traffic falls below the Detection Threshold EPS/PPS value, a log similar to the following example is generated in the /var/log/ltm file noting that the attack stopped and referencing the corresponding UDP Flood Attack ID:

notice tmm1[21964]: 01010253:5: A Enforced DOS attack has stopped for vector UDP flood, Attack ID 480207285.

Note: The provided Detection Threshold EPS/PPS value are for examples only, as noted in the Reviewing UDP flood attack traffic statistics procedure, the Stats Rate value would need to be reviewed and observed periodically to determine an appropriate Detection Threshold and Mitigation/Rate limit value according to the needs of your environment.

Configuring Network Security-enabled DoS Protection profile

To configure the thresholds for UDP Flood attack type in the DoS Protection profile, perform the following procedure:

Impact of procedure: Depending on your application environment, you need to determine the threshold values acceptable for your application environment.

BIG-IP AFM 14.x

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > Protection Profiles.
  3. Click the name of the Network Security-enabled DoS Protection profile that you want to modify.
  4. Click Network.

    Note: If you do not see the Network setting, you must enable Network Security by selecting Network for the Families setting.

  5. Click UDP Flood under the Vector table. The Configuration utility displays the UDP Flood properties page.
  6. For State, click Mitigate to expose the settings.
  7. For Threshold Mode, choose the appropriate setting. If you want to configure the three settings manually, click Fully Manual.
  8. Modify the value for the following settings:
    • Detection Threshold EPS*
    • Detection Threshold %
    • Mitigation Threshold EPS
  9. Click Commit Changes to System.

BIG-IP AFM 13.x

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > DoS Profiles.
  3. Click the name of the Network Security-enabled DoS Protection profile you want to modify.
  4. Click the Network Security tab.
  5. In the Attack Type table, click UDP Flood.
  6. For State, click Mitigate.
  7. For Threshold Mode, choose an appropriate setting. If you want to configure the three settings manually, click Fully Manual.
  8. Modify the value for the following settings:
    • Detection Threshold EPS*
    • Detection Threshold Percent
    • Mitigation Threshold EPS
  9. Click Update.

BIG-IP AFM 12.x

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > DoS Profiles.
  3. Click the name of the Network Security-enabled DoS Protection profile you want to modify.
  4. Under Network General Settings, expand Known Attack Types to expose the UDP Flood attack type.
  5. Click Edit for the UDP Flood attack type.
  6. For Detection Status, click Enabled to expose the thresholds and rate limits for configuration.
  7. Modify the value for the following settings:
    • Threshold (in packets per second)*
    • Rate increase (in percent)
    • Rate Limit (in packets per second)
  8. Click Update.

For BIG-IP AFM DoS Protection profile, the threshold and rate limit values are applied globally. For more information, refer to K40477555: BIG-IP AFM DoS Protection profile thresholds are enforced globally.

*For Detection Threshold, as a sample possible value, allow an acceptable value to accommodate expected increase of this type of traffic. For example, if the Stats Rate value has an average value of 5000 packets per second, setting Detection Threshold to 8000 allows an acceptable increase of traffic for this attack type. Set Mitigation Threshold EPS/Rate Limit to a value at which you want the BIG-IP AFM to start dropping packets for the UDP Flood attack. For example, 10000 packets per second is considered a UDP Flood event. BIG-IP AFM detects the UDP Flood attack once the Detection Threshold EPS/PPS value is exceeded and generates a log similar to the following example in the /var/log/ltm file:

err tmm13[23890]: 01010252:3: A NETWORK /Common/VS1 DOS attack start was detected for vector UDP flood, Attack ID 846180281.

When the UDP Flood traffic falls below the Detection Threshold EPS value, a log similar to the following example is generated in the /var/log/ltm file noting that the attack stopped and referencing the corresponding UDP Flood Attack ID:

notice tmm13[23890]: 01010252:5: A NETWORK /Common/VS1 DOS attack has stopped for vector UDP flood, Attack ID 846180281.

Note: The Detection Threshold EPS value is an example. As noted in the Reviewing UDP flood attack traffic statistics procedure, you need to review and periodically observe the Stats Rate value to determine an appropriate threshold and rate limit value according to the needs of your environment.
