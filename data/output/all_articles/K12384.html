Known Issue

This is the result of a known issue. When using the tmsh utility to associate the profiles with a virtual server, HTTP class profiles do not retain the order specified in the tmsh command.

For example, the following tmsh command modifies the properties of the VIP-A virtual server by adding HTTP class profiles in a specified order:

tmsh modify ltm virtual VIP-A http-class replace-all-with { B-class A-class C-class }

After modifying the virtual server using the command in the previous example, the profiles are prioritized alphabetically rather than in the order specified in the command. This behavior is displayed in the following virtual server properties output:

ltm virtual VIP-A {
destination 172.16.65.224:http
http-class {
A-class
B-class
C-class
}
ip-protocol tcp
mask 255.255.255.255
pool respond_pool
profiles {
http { }
tcp_nto { }
}
}

F5 Product Development tracked this issue as ID 225071 (formerly CR138432) and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

You can work around this issue by reordering the HTTP class profiles using the Configuration utility.
