Known Issue

This is the result of a known issue. When the BIG-IP LTM system receives an ICMP type 3 (destination unreachable), code 4 (fragmentation required) packet, the BIG-IP LTM may delay the response from the server for three seconds.

This delay occurs when the BIG-IP LTM receives an ICMP fragmentation required packet. The BIG-IP LTM then passes the ICMP packet to the server, which allows the server to resend the information using a smaller packet.
 
F5 Networks Product Development tracked this issue as CR99497 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP version 9.4.3, and in Hotfix-BIG-IP-9.4.5-HF2 issued for BIG-IP version 9.4.5. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
