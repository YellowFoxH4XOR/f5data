Description

At times it may be necessary to create a local user on the CLI for the F5OS operating system.

Environment

  • Need to create a local user.)
  • Local user settings. (If the need were to arise to create a tenant-console user it can only be done on the CLI).
  • F5OS Appliance and Velos 

Recommended Actions

Login as admin to create the local user. If you are logged in as root you can use su admin to open an admin prompt.

  1. If no Expiry Status date is needed (in the example test_1 is the username. That will need to change to the username you choose)...
    1. appliance-1# config
    2. appliance-1(config)# system aaa authentication users user test_1 config role <role name>
    3. appliance-1(config-user-test_1)# commit
    4. Commit complete.
    5. appliance-1(config-user-test_1)# exit
    6. appliance-1(config)#
  2. If an Expiry Status date is needed (in the example test_31 is the username. That will need to change to the username you choose. Also set the expiry-status in this format YYYY-MM-DD)..
    1. appliance-1 config
    2. appliance-1(config)# system aaa authentication users user test_31 config role <role> expiry-status 2025-04-30
    3. appliance-1(config-user-test_31)# commit
    4. Commit complete.
    5. appliance-1(config-user-test_31)# exit
    6. appliance-1(config)#
  3. At this point the new user can be seen in the GUI. However a password still needs to be set. That can be done via the GUI or the CLI. Use the username as you created. There is no password confirmation nor can you show it in plain text, so be sure to type it correctly. To use the CLI...
    1. appliance-1# config
    2. appliance-1(config)# system aaa authentication users user test_31 config set-password password
    3. Value for 'password' (<string>): **********
    4. appliance-1(config)#

If you need to view a list of local users on the CLI use the following command...

show system aaa authentication users

Additional Information

A tenant-console user is automatically created when the tenant is created and first deployed, but not until it is first deployed. If for some reason that user is deleted then it can only be re-created via the CLI.

Do not create the tenant-console user prior to creating the tenant or you may run into Bug ID 1354329: Unable to access tenant through console access.

To unlock the tenant-console role K33373310: Accessing an F5 rSeries tenant console
