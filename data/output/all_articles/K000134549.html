K000134549: Clickhouse data is filling up allocated disk space, such as partition /var

Type
Support Solution
Published
2023-05-11
Updated
2026-09-28
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.10.0
Source
https://my.f5.com/manage/s/article/K000134549

Description

Clickhouse data can fill up allocated disk space such as partition /var. This can lead to out of disk space functionality issues and errors such as the following (from nms.log):

[ERROR] /usr/bin/nms-ingestion clickhouse/sink.go:430 Insert failed: committing transaction: code: 243, message: Cannot reserve X.XX MiB, not enough space

Environment

NMS

Cause

Retained clickhouse data, such as security events, grows over time. Data retention TTL is a function of clickhouse and is based on time rather than by data size. The default TTL is 1 month.

Recommended Actions

Here are a couple of solutions that will help mitigate this issue:

Change clickhouse data store to a different partition

The new partition size for data storage should be based on the size of the NMS environment. See Sizing Recommendations for guidance.

Using example directory /mnt/example as the new partition, here is how to make the necessary change on the NMS server

  • Stop clickhouse server: 
    sudo systemctl stop clickhouse-server.service
  • Edit /etc/clickhouse-server/config.xml, find all of the paths with base directory /var/lib/clickhouse/ and change them to the new partition directory. Example:  
    <path> from /var/lib/clickhouse/ to /mnt/clickhouse/
<tmp_path> from /var/lib/clickhouse/tmp/ to /mnt/clickhouse/tmp
<user_files_path> from /var/lib/clickhouse/user_files/ to /mnt/clickhouse/user_files/
<top_level_domains_path> from /var/lib/clickhouse/top_level_domains/ to /mnt/clickhouse/top_level_domains/
<format_schema_path> from /var/lib/clickhouse/format_schemas/ to /mnt/clickhouse/format_schemas/
    • There may be more or less paths to change depending on your environment.
  • (Optional) Copy the existing data to the new partition directory. For example use rsync to accomplish this task: 
     rsync -aH /var/lib/clickhouse/ /mnt/clickhouse
    • This step is optional because clickhouse will rebuild missing files, directories and data upon startup.
  • (Optional) Delete old clickhouse data to recover disk space:  
    rm -rf /var/lib/clickhouse/*
  • Start clickhouse-server: 
    sudo systemctl start clickhouse-server.service

Reduce retention time for Security Events

Use clickhouse-client to connect to clickhouse and reduce the Security Events data retention time.

  • Depending on how clickhouse is setup a password may be required to connect. The clickhouse password is configured within /etc/clickhouse-server/users.xml. Example:  
    $ sudo awk '/<users>/,/<password>T/' /etc/clickhouse-server/users.xml | egrep "<users>|<password>" -A2

<users>
    <!-- If user name was not specified, 'default' user is used. -->
    <default>
--
            Example: <password>qwerty</password>.
            Password could be empty.
--
         <password>examplepass</password>
  • Connect to clickhouse:  
    $ clickhouse-client --password examplepass
ClickHouse client version 22.8.4.7 (official build).
Connecting to localhost:9000 as user default.
Connected to ClickHouse server version 22.8.4 revision 54460.

  • Run the following commands:  
    ALTER TABLE nms.v4_security_events MODIFY TTL timestamp + toIntervalDay(10)
ALTER TABLE nms.v4_security_events_signatures_data MODIFY TTL timestamp + toIntervalDay(10)
ALTER TABLE nms.v4_security_events_violation_data MODIFY TTL timestamp + toIntervalDay(10)
    • This example sets the Security Events retention time to 10 days. This can be adjusted to weeks, hours, minutes and even seconds. See Clickhouse documentation for more information.
