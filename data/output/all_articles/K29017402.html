Description

On a running system, restjavad heap dump feature is usually enabled by running the following commands in order to collect memory snapshot when java terminates with java.lang.OutOfMemoryError.

  touch /service/restjavad/dump
  tmsh restart sys service restjavad

As long as the "dump" file exists on that directory, restjavad will be enabled for dumping heap memory.

To disable, delete the dump file and restart restjavad.

However this file is not carried over into an upgrade since new installation creates a new volume for var partition.

There are corner cases where a user would want to collect data for why restjavad ran out of memory immediately after an upgrade.  To enable the feature prior to booting into the new location, the administrator would need to create the file on the target directory.

/service is a symlink to /var/service, which would be under the /var partition.

Environment

The procedure described in this article applies to the following:

  • When restjavad heap dump feature needs to be enabled immediately when booting into an upgraded boot location. 
The requirements for this procedure are:
  • Administrator (root) privilege on the BIG-IP.

Cause

None.

Recommended Actions

1. Install the OS/EHF into a new boot location.

2. Once the OS and EHF installation has completed, perform the following before activating the new boot location:

   2.1. Create a temporary directory where the new var partition would be mounted.

                mkdir /tmp/tmp_mount/

   2.2. Identify the device where the new var partition was created. Use 'lvdisplay'. In this example, set.2 identifies the new boot location.

        --- Logical volume ---
        LV Path                /dev/vg-db-sda/set.2._var       
        LV Name                set.2._var
        VG Name                vg-db-sda

   2.3. Mount the new "var" partition into the temporary directory that was created on the previous step. In this example "/dev/vg-db-sda/set.2._var" is the device that will be mounted. This data was taken from output of 'lvdisplay'.

        mount /dev/vg-db-sda/set.2._var /tmp/tmp_mount/

   2.4. Create an empty 'dump' file inside the /tmp/tmp_mount/var/service/restjavad.

        touch /tmp/tmp_mount/var/service/restjavad/dump

   2.5. Unmount the mounted volume.

        umount /tmp/tmp_mount/

   2.6. (Optional) If running a multi-bladed system (ie. VIPRION or vCMP), SSH into the next blade and repeat these procedures on that blade.

3. Proceed with activating the new boot location.

Upon reboot, restjavad should start with these options enabled on the new boot location:

              -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/shared/tmp

If restjavad dumps the heap when running on the upgraded volume, the dump file will be located on /shared/tmp with filename similar to java_pid<pid>.hprof.
