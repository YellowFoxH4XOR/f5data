K000139180: MAC users getting error : Application update failed: PolicyServer pkg not found in server connectivity profile.

Type
Support Solution
Published
2024-04-05

2024-04-05
Applies to

  • BIG-IP APM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000139180

Description

After upgrading APM device , MAC VPN users get below error while trying to connect to VPN:

Application update failed: PolicyServer pkg not found in server connectivity profile. Do you want to continue using old version?

Environment

  • APM device upgrade
  • MAC users
  • VPN

Cause

The root cause is missing the part relating to EPSEC package as a part of preconfig response.

You can confirm this by accessing https://<APM_URL>/pre/config.php?version=2.0 it will respond with preconfigured response which will not have OESIS package ID shown below :

To be precise, it happened because by the time httpd_sam comes up and reads contents of /var/sam/www/webtop/public/download/, mac_oesisInspector.tar or mac_oesisInspector.tar.md5 or mac_oesisInspector.tar file links are not available. They might be created after httpd_sam has come up.

<PACKAGE>
<ITEM>
<ID>OesisInspector</ID>
<VERSION>7090.2024.0315.1</VERSION>
<SIGNATURE>KDGFYROIFIbcbhEFHEIDJHPWDKvghvdheHFRIHWbgsdeyhfdtgfwfgdDJEDOLdxgvffteDOLEHFHedhfdDEBDOPIHSWSACBEOCFHHewdyhg3weigduKSJDEFDGOHWEDSJdggdiswupoow==</SIGNATURE>
<SOURCE>/public/download/mac_oesisInspector.tar</SOURCE>
</ITEM>
</PACKAGE>
</AUTOUPDATE_MAC>
<AUTOUPDATE_LINUX>
<PACKAGE>

Recommended Actions

1) Check if the files are present under /var/apm/www/webtop/public/download/

Example : 

[root@bigip1:Active] config # cd /var/apm/www/webtop/public/download/
[root@bigip1:Active] download # ll
