Known Issue

This is the result of a known issue. If an unclean filesystem is detected during an installation or upgrade, the installation process is not interrupted. However, when the user is prompted to select the image slot to install or upgrade, all image slots appear empty. The empty slots indicate that the BIG-IP system could not read the filesystem and therefore is preparing to repartition the drive.

In versions 9.0.0 through 9.1.1, the installation packages are stored on the BIG-IP hard drive. If you continue with the installation after being prompted with the empty slots, your filesystems will be repartitioned and your BIG-IP system will be inoperable. In this state, the BIG-IP system will require a clean installation from a PXE server to recover.

In version 9.1.2 and versions 9.2.x, the installation packages are stored in a memory filesystem, rather than on the hard drive. Although your system will be operable if you continue the installation after being prompted with the empty image slots, the images that existed before the installation will be overwritten and lost.

Important: Since any pre-existing images will be lost during installation, never continue an installation or upgrade if the installation script inaccurately indicates that all image slots are empty.

F5 Product Development tracked this issue as CR64693 and introduced a warning prompt in versions 9.1.2 and 9.2.5 to ensure that you do not continue with the installation if the filesystem is unclean and the image slots are displayed as empty. For information about upgrading, refer to the BIG-IP LTM release notes.

The warning prompt appears as follows:

WARNING:  filesystem integrity test failed.Product images will be irrevocably lostif this installation session continues!A startup filesystem check may correct this problem;please reboot and try again.The following product image locations are affected:HD1.1HD1.2Continue with installation?

Note: This warning will also appear when upgrading from BIG-IP version 4.x to 9.1.x. The warning is essentially correct—the previous 4.x installation will be lost. However, the 9.x installation will successfully complete despite the warning.

Workaround

Reboot workaround

If the installer script inaccurately indicates that all image slots are empty, you can usually correct this issue by canceling the installation and rebooting the BIG-IP.

As the BIG-IP boots, a filesystem check is performed and unclean filesystem repairs are automatically attempted.

After the BIG-IP reboots, you can re-perform the installation or upgrade.

Workaround if a reboot does not resolve the issue

If a reboot of the BIG-IP system does not repair the unclean file system, and the installer script continues to inaccurately report the image slots as empty, you can correct this issue by performing the procedure described in K10328: Forcing a file system check on the next system reboot (recommended), or by booting the BIG-IP system into single-user mode and manually running the filesystem check.

To boot the BIG-IP system into single-user mode and manually run the filesystem check, perform the following steps:

  1. Cancel the installation or upgrade.
  2. Boot the BIG-IP system into single user mode using the procedure outlined in K4178: Booting BIG-IP in single user mode.

    After performing the above procedure, the single-user mode command prompt will display.

  3. Stop syslog-ng by typing the following command:

    kill `pidof syslog-ng`

  4. Unmount the filesystems by typing the following command:

    umount -a

  5. Perform a filesystem check by typing the following command:

    fsck -yaf

    The output should appear similar to the following example:

    sh-2.05b# fsck -yaffsck 1.32 (09-Nov-2002)/dev/hdc5: 20659/96576 files (0.0% non-contiguous), 28540/192779 blocks/dev/hdc1: 253/488640 files (5.5% non-contiguous), 97728/975948 blocks/dev/hdc7: 106/193152 files (0.9% non-contiguous), 14539/385559 blocks/dev/hdc8: 507/289728 files (3.7% non-contiguous), 19904/578339 blocks/dev/hdc9: /lost+found not found.  CREATED./dev/hdc9: 8457/96576 files (0.1% non-contiguous), 66071/192779 blocks
  6. Verify that all filesystem partitions are clean by typing the following command:

    fsck -ya

    The output should appear similar to the following example:

    sh-2.05b# fsck -yafsck 1.32 (09-Nov-2002)/dev/hdc5: clean, 20659/96576 files, 28540/192779 blocks/dev/hdc1: clean, 253/488640 files, 97728/975948 blocks/dev/hdc7: clean, 106/193152 files, 14539/385559 blocks/dev/hdc8: clean, 507/289728 files, 19904/578339 blocks/dev/hdc9: clean, 8457/96576 files, 66071/192779 blocks

    Note: If the filesystem partitions are not clean, repeat steps 5 and 6.

  7. Reboot the BIG-IP by typing the following command:

    reboot

  8. Perform the installation or upgrade.
