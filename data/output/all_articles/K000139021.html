Description

Should I use an "AND" or "OR" when adding keywords to custom attack signatures rules?

Environment

  • Advanced WAF / ASM attack signatures
  • Custom attack signatures
  • Adding keywords

Cause

Logical operators such as "AND" or "OR" are not required when adding keywords to custom attack signatures rules.

Recommended Actions

Custom (user-defined) attack signatures must adhere to a specific rule syntax. In most cases, F5 recommends using the Simple rule editor when creating custom signatures for your security policy. When using the Simple editor, you compile a series of keyword statements plus the matching element and criteria and the system translates the rule into a custom signature. Attack signature rule statements are combined using an implied "AND" operator; this makes it so that all conditions in the rule must be met in order to satisfy the rule as a whole.

Note: If you select the Advanced editor to define your custom attack signature, you must use Snort-format syntax when creating the rule.

Additional Information

Custom attack signatures adhere to Snort-format syntax. For Snort rules the action defined in the rule's header is not taken unless all of the options listed in the rule's body evaluates to true.

The same concept applies to custom attack signatures; the attack signature's action (block / alert) is not taken unless all of the keyword statements in the rule evaluates to true. For example, a custom signature may have a matched criteria of parameter/cookie with the following rule statements:

valuecontent:"abc"; nocase; httponly; norm; 
valuecontent:"XYZ"; httponly; norm;

In the case of the above signature, the cookie or parameter in the HTTP request would need to contain both of the following elements to activate the signature: abc (not case sensitive) and XYZ (case sensitive). For example, the following HTTP request would activate the signature:

GET / HTTP/1.1
Host: 10.10.10.1
User-Agent: Mozilla/120
Accept: */*
Cookie: USER_TOKEN=abc123XYZ
