K000162305: F5 Distributed Cloud: Same domain on Multiple HTTPS Ports Fails with Port Range Configuration

Type
Support Solution
Published
2026-07-16
Updated
2026-07-16
Source
https://my.f5.com/manage/s/article/K000162305

Description

An F5 Distributed Cloud HTTP Load Balancer was configured to serve the same domain on HTTPS port 443 and a custom HTTPS port using port ranges and port-based routes.

After enabling the port-range configuration, connections to port 443 were reset during the TLS handshake, while connections to the custom port timed out. No HTTP request logs or Request IDs were generated because the connections failed before HTTP processing.

Environment

  • F5 Distributed Cloud Services

  • Customer Edge site

  • HTTP Load Balancer advertised on a custom site VIP

  • Multiple HTTP Load Balancers sharing the same VIP

  • HTTPS traffic using the same domain on different ports

Cause

The affected HTTP Load Balancer was changed from a standard HTTPS listener to a port-range listener containing port 443 and a custom port. The same VIP was already shared by multiple HTTPS Load Balancers using individual HTTPS port listeners.

In this environment, the port-range configuration did not coexist correctly with the existing shared VIP listeners. Port 443 stopped completing the TLS handshake, and the custom port was not reachable. Route port matching alone does not create a frontend listener; it only selects a route after the connection reaches the load balancer.

Answer/Recommended Actions

Use separate HTTP Load Balancers for each required HTTPS port instead of configuring both ports through a single port-range listener.

  • Keep the existing HTTP Load Balancer configured with HTTPS port 443.

  • Create a second HTTP Load Balancer using the same domain and certificate, configured with the required custom HTTPS port.

  • Advertise both load balancers on the same custom VIP using Use Default Listen Port.

  • Configure the appropriate origin pool and enable WebSocket support on the custom-port load balancer when required.

  • Verify that no other load balancer uses the same VIP and port combination.

The same domain can be used by separate HTTP Load Balancers when each load balancer uses a different, non-overlapping frontend port.

Additional Information

A connection reset or timeout before the HTTP request is sent will not generate an HTTP Load Balancer Request ID or WAF event.

Use the following command to validate a custom port directly against the advertised VIP while preserving the required hostname and TLS SNI:

curl -skv --http1.1 \
  --resolve example.domain.com:<CUSTOM_PORT>:<VIP_ADDRESS> \
  https://example.domain.com:<CUSTOM_PORT>/<PATH> \
  -o /dev/null

Any HTTP response confirms that the frontend listener is active. A timeout or connection refusal indicates that the connection is failing before route, WAF, or origin processing.
