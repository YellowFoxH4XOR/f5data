Known Issue

This is the result of a known issue. When an import for a multi-protocol volume has more than 1,024 name inconsistencies, a multi-protocol import may experience extremely slow performance. In addition, the ARX system will log an error message to the syslog file that appears similar to the following example:

:DNAS_PGRP-1-NOTE-MAX_CACHED_FGNS:: The directory '/unix/incons/' on share ‘unix-s1' contains more than 1024 multi-protocol name inconsistencies; its contents will be processed one at a time.

You can also confirm this issue by enabling debug logging for DNAS_PGRP and reviewing the syslog file for post-op FGE detection messages that appear similar to the following example:

:DNAS_PGRP-1-DBG-MSG7:: [DNASMP] post-op FGN detection: DID 0x100000000000b, path '/unix/incons/', SID 39

Enabling debug logging

You can enable debug logging for DNAS_PGRP by performing the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter configuration mode by typing the following command:

    config
  4. Set the logging level for DNAS_PGRP to debug by typing the following command:

    logging level DNAS_PGRP debug

    Note: The debug logging level for DNAS_PGRP should only be used for troubleshooting, not for normal operation.
  5. When debug logging level is no longer required, disable debug logging for DNAS_PGRP by typing the following command:

    no logging level DNAS_PGRP

F5 Product Development tracked this issue as ID 39383 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

This issue has also been fixed in ARX version 5.1.5 HFRU 6. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this article number and ID 39383.
