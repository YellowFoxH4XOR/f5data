K000152642: Configuration Loading Failed, and MCPD Process cannot Come up with Re-starting Loop

Type
Support Solution
Published
2025-07-20
Updated
2025-07-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.X, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000152642

Description

You tried to load the configuration, either by using the "tmsh load sys config" command on Console or after Rebooting the BIG-IP Device / Virtual Edition, and noticed that the configuration failed to load successfully with below continuous Error messages on the Console:

2025 Jul 20 01:50:43 <Device-Name> logger[5715]: Re-starting devmgmtd

load_config_files[6214]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- Error: failed to reset strict operations; disconnecting  from mcpd.  Will reconnect on next command.
The connection to mcpd has been lost, try again.
 
2025 Jul 20 01:50:55 <Device-Name> logger[6931]: Re-starting mcpd

 

Additionally, you may see continuous Re-starting loop for "mcpd" and/or "devmgmtd" services. You can also see some similar logs under "/var/log/ltm", as below:

Jul 19 13:45:07 <Device-Name> notice mcpd[10985]: 01071027:5: Master key OpenSSL error: 4006627060:error:06065064:digital envelope routines:EVP_DecryptFinal_ex:bad decrypt:evp_enc.c:664

...

Jul 19 13:45:07 <Device-Name> err mcpd[10985]: 0107102b:3: Master Key decrypt failure - decrypt failure - final

...

Jul 19 13:45:07 <Device-Name> err mcpd[10985]: 01071769:3: Decryption of the field (value) for object (configsync.password) failed while loading configuration that is encrypted with a different master key.

...

Jul 19 14:30:17 <Device-Name> err loaddb[13695]: 01080023:3: Error return while getting reply from mcpd: 0x1071769, 01071769:3: Decryption of the field (value) for object (configsync.password) failed while loading configuration that is encrypted with a different master key.

Environment

  • LTM Module
  • Configuration loading failed

Cause

The sys db "configsync.password" has a passphrase which was not Encrypted with the current (correct) Master Key. As a result, upon loading the configuration, the value can not be Decrypted as desired, and the configuration refuses to load (as expected).

Recommended Actions

You can follow the below steps under MW to manually resume the config load as normally expected:

 

1. Connect to the Console of the affected Device, and run the below command:

# bigstart stop

 

2. Make a copy of the original file "/config/BigDB.dat" under the same directory:

# cp /config/BigDB.dat /config/BigDB.dat.backup

 

3. Open the "/config/BigDB.dat" file by using the below command:

# vi /config/BigDB.dat

 

4. Locate the config stanza as below, and Delete the complete line highlighted with Arrow, then Save the file and Exit:

[Configsync.password]
default=unused
type=string
realm=common
scf_config=false
display_name=Configsync.password
value=$M$q1$PGuWdfG4lhahh7yT0mpplw==        <----------- !!!!

 

5. Once done, run the below commands, one-by-one:

# rm -rf /var/db/mcpd*
# bigstart restart

 

6. Now, wait for a couple of Minutes, and check the configuration loading result. It's supposed to be automatically loaded in the background.

 

7. Once confirmed, you can run the below command to save the configuration:

# tmsh save sys config partitions all
