Known Issue

Creating or reconfiguring iApps fails when you configure a remote high-speed logging (HSL) destination of any type, such as ArcSight, IPFIX, Splunk, and so on.

This issue occurs when all of the following conditions are met:

  • You configure a log destination, publisher, and filter in which the Source of the filter is set to all or scriptd. For example, the following configuration contains a remote HSL destination and publisher that uses a filter with Source set to all: 
    sys log-config filter /Common/HSL_filter {
    publisher /Common/HSL_publisher
}
sys log-config publisher /Common/HSL_publisher {
    destinations {
        /Common/HSL_destination { }
    }
}
sys log-config destination remote-high-speed-log /Common/HSL_destination {
    pool-name /Common/HSL_POOL
}
  • You attempt to create or modify an iApp.

Impact

You are unable to create new iApps or reconfigure existing ones.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • If you use the Configuration utility to create or modify an iApp, the BIG-IP system reports the following error message in the /var/log/webui.log file and displays it in the Configuration utility:

    ERROR [TP-Processor1] handler.DBRequestHandler:handleMcpException     - com.f5.mcp.io.McpQueryException: script did not successfully complete: (The connection to mcpd has been lost, try again.)

  • If you create or modify an iApp using iControl, the BIG-IP system reports an error with the following error message syntax in the /var/log/audit file:

    notice icrd_child[<PID>]: 01420002:5: AUDIT - pid=<PID> user=<username> folder=/Common module=(tmos)# status=[The connection to mcpd has been lost, try again.] cmd_data=create sys application service

Workaround

To work around this issue, you can temporarily stop scriptd process logging to all destinations before you create or reconfigure an iApp.

If you have an existing log filter that has a source of scriptd and a publisher whose destination is of the type Remote High-Speed Log, as in the following example, you can set the Log Publisher of the affected log filter to None by using the Setting the Log Publisher setting of the affected Log Filter to None procedure.

sys log-config filter /Common/HSL_filter {
     publisher /Common/HSL_publisher 
     source scriptd 
}

Otherwise, you can create a new log filter with Source as scriptd, at level debug with Log Publisher set to None by using the Creating a new log filter with Source set as scriptd, at level debug, with Log Publisher set to None procedure.

Setting the Log Publisher setting of the affected Log Filter to None

If you have an existing log filter that has a source of scriptd and a publisher whose destination type is Remote High-Speed Log, you can stop scriptd logging to all destinations by performing the following procedure:

Impact of workaround: scriptd logging to the configured destination temporarily stops. Restarting the scriptd process should not have a negative impact on your system.

  1. Log on to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Log Filters.
  3. Click the affected Log Filter.
  4. Note the name of the existing Log Publisher.
  5. In the Log Publisher list, click None.
  6. Click Update.
  7. Repeat steps 3 to 6 for any other log filters for which the Source is scriptd.
  8. Restart the scriptd process by typing the following command:

    bigstart restart scriptd

  9. Create or reconfigure your iApp.
  10. Use the information you noted in step 4 to set the Log Publisher back to its original value.

Creating a new log filter with Source set as scriptd, at level debug, with Log Publisher set to None

If you do not have an existing log filter that has a source of scriptd and a publisher whose destination is of the type Remote High-Speed Log, you can stop scriptd logging to all destinations by performing the following procedure:

Impact of workaround: The scriptd process logging to the configured destination temporarily stops. Restarting the scriptd process should not have a negative impact on your system.

  1. Log on to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Log Filters.
  3. Click Create.
  4. Provide an appropriate name. For example, No_Script_Debug_HSL.
  5. In the Source list, click scriptd.
  6. Click Finished.
  7. Restart the scriptd process by typing the following command:

    bigstart restart scriptd

  8. Create or reconfigure your iApp.
  9. You can now navigate to System > Logs > Configuration > Log Filters to delete the log filter you created.
