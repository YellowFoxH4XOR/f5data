Topic

F5 does not support BIG-IP redundant pair configurations that run different software versions; this type of configuration can have a detrimental effect on the failover process. The failover pair must both run the exact same version of BIG-IP software. If the existing BIG-IP runs a later software version, you must upgrade the peer system so that both versions match. For information about upgrading, refer to the BIG-IP LTM release notes.

You will need to reboot the existing BIG-IP system. Therefore, you must perform this configuration change during a low traffic period or maintenance window. As a result of this procedure, both BIG-IP systems may be in active-active mode for a period of two to five minutes. During this period, performance will be severely reduced.

Configuration examples

The following configuration examples can assist you with preparing for your redundant pair configuration change for BIG-IP version 9.x or 10.x systems:

Original single controller configuration

In the following original single controller configuration example, the existing external and internal IP addresses (external_IP_1 and internal_IP_1) from the single BIG-IP system will become the new shared addresses on the redundant system:

  • external_IP_1 is the IP address to which the external router directs traffic.
  • internal_IP_1 is the default route for the servers being load balanced.

Two additional external and two additional internal IP addresses are required for the full configuration.

Redundant configuration

In the following new redundant configuration example, external_IP_2 and external_IP_3 are the new primary external interface addresses for each controller, and internal_IP_2 and internal_IP_3 are the new primary internal interfaces. The external_IP_1 and internal_IP_1 addresses are changed to the floating addresses that are shared between the units. This eliminates the need to modify the upstream router or downstream nodes.

BIG-IP 2 configuration (the new BIG-IP that is being added to the configuration)

  • external_IP_2 is the new primary external interface.
  • internal_IP_2 is the new primary internal interface.
  • external_IP_1 and internal_IP_1 are the new shared addresses.

BIG-IP 1 (the original stand-alone BIG-IP)

  • external_IP_3 is the new primary external interface.
  • internal_IP_3 is the new primary internal interface.
  • external_IP_1 and internal_IP_1 are the new shared addresses.

Configuring the new BIG-IP in a redundant pair

  1. Connect the new BIG-IP Controller with a fail-over cable to the existing BIG-IP Controller and turn on the power.

    Important: Do not connect the network cabling to the new BIG-IP system, as this can cause a network disturbance after the system reboots.

    Note: If the systems are going to be installed in physically separate locations, do not connect the new system to your network infrastructure until you ensure it will remain in standby mode after rebooting. For more information, refer to K8184: Overview of the Redundancy State Preference setting.

  2. Connect a console to the new BIG-IP system. When the system is powered up, type the following command:

    config

  3. Follow the steps to configure the management IP address, subnet mask, and default gateway.
  4. Log in to the Configuration utility using the management address.
  5. The Setup utility should run; prompting you to install the license.

    Note: If the BIG-IP system contains a previous configuration, you can run the Setup utility by clicking Overview > Welcome > Run the Setup Utility.

  6. Install the license.
  7. Enter the hostname in the Host Name field.
  8. From the High Availability drop-down menu, select Redundant Pair.
  9. From the Unit ID drop-down menu, select 1.

    Note: Each unit must be assigned a unique ID. For systems in the active-active configuration, virtual servers must then be assigned to one unit or the other. For more information, refer to the BIG-IP Network and Systems Management Guide.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  10. Finish defining the General Properties and User Administration information.
  11. Click Next.

    Important: The admin username and password should be the same as the existing system. If the username and password are not set correctly, the configurations will not be synchronized.

  12. Under Basic Network Configuration, click Next.

    The Internal Network Configuration screen displays.

  13. For the Floating IP, enter the existing BIG-IP system's internal address as the new internal Floating IP address (in this example, internal_IP_1).
  14. For the Failover IP, enter the new internal primary address of the peer unit in the redundant system (in this example, internal_IP_3).

    Important: Do not use the IP address that the existing system currently uses because that address will be the shared and floating address for the redundant pair. Additionally, the VLAN and appropriate VLAN tags must be on the new BIG-IP system. The VLAN name is case-sensitive.

  15. Finish defining the Internal Network and VLAN configuration.
  16. Click Next.

    The External Network Configuration screen is displays.

  17. Enter the appropriate addresses for the Floating IP and Failover IP.

    The new internal Floating IP is external_IP_1, and the Failover IP is external_IP_3.

  18. Complete the Setup utility.
  19. Reboot the new BIG-IP system.

    After the reboot, the BIG-IP system will be the standby controller in a redundant pair configuration (provided that the failover cable was connected).

  20. To verify the state of the BIG-IP system, type the following command:

    bigpipe fo

    If the new BIG-IP is in active mode, check to see if the failover cable is securely connected to the failover port.

    Note: The failover port resembles the serial port. Both ports are labeled. The failover cable has custom pinouts, as documented in K1426: Pinouts for the failover cable used with F5 BIG-IP products.

  21. Review the base IP configuration by typing the following command:

    bigpipe base list

Configuring the original BIG-IP as a standby system in a redundant pair

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click Platform.
  4. From the High Availability drop-down menu, select Redundant Pair.
  5. From the Unit ID drop-down menu, select 2.

    Note: The Unit ID is only significant when configuring an Active-Active load balancing system. If you are configuring an Active-Active system, each unit must be assigned a unique ID, and virtual servers must be assigned to one unit or the other. For more information, refer to the BIG-IP Network and Systems Management Guide.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  6. Click Update.
  7. Click Network.
  8. Click Self IPs.
  9. Edit the existing IPs, external_IP_1 and internal_IP_1, and select the Floating IP check box for each self IP.
  10. Create two new self IP addresses, where external_IP_3 is the new primary external interface, and internal_IP_3 is the new primary internal interface.
  11. Reboot the BIG-IP system.

    Important: Rebooting the BIG-IP system results in a temporary site outage.

    After you reboot, the BIG-IP system will be in a redundant pair configuration in standby mode (provided the failover cable was connected) because the new BIG-IP system is in active mode.

  12. To fail back to the original BIG-IP and start traffic flowing, type the following command on the new BIG-IP system:

    bigpipe fo standby

Synchronizing the configuration between the standby and the active system

  1. The existing BIG-IP should now be in active mode and the new BIG-IP should be in standby mode. Verify this by typing the following command on each system:

    bigpipe fo

    Important: The new BIG-IP system must be in standby mode before you connect it to the network, otherwise it may respond to ARP requests for the floating addresses, interfering with traffic currently flowing through the active system.

  2. After you confirm the state of the BIG-IP systems, connect the new BIG-IP system to the network.
  3. Synchronize the configuration by typing the following command:

    bigpipe config sync all

  4. Confirm that the new BIG-IP system has the correct configuration by typing the following command:

    bigpipe list

  5. Verify that the /config/bigip.conf file is the same size on both systems.

At this point, both units should have the same configuration and should failover seamlessly. F5 recommends that you test the configuration synchronization and failover in both directions during the maintenance window.
