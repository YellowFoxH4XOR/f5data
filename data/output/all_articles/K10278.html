Issue

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

• K14675: Error Message: 01070726:3: virtual server <Partition/Virtual_Name> in partition <Partition> cannot reference virtual address <Partition/Virtual_Addr> in partition <Partition>

When you create a virtual server, the associated virtual address is defined in the same partition as the virtual server. For virtual servers created in the Common partition, the virtual address is also defined in the Common partition, and is therefore available for use in creating virtual servers in any partition. If a virtual server is created in a partition other than the Common partition, the associated virtual address is defined in that partition, not in the Common partition. As a result, the virtual address is unavailable for use in creating virtual servers in other partitions. If a virtual address is defined in a partition other than the Common partition, and you attempt to create a virtual server in a partition other than that in which the virtual address is defined, an error message that appears similar to the following example is generated, and the virtual server is not created:

01070726:3: A virtual server may reference a virtual address in the same partition or the common partition (SOL10278_5:10.10.10.1)

Moving the virtual address to the Common partition

You can make the virtual address available in other partitions by moving it to the Common partition. To do so, perform one of the following two procedures:

  • Moving the virtual address to the Common partition using the Configuration utility
  • Moving the virtual address to the Common partition using the command line

Moving the virtual address to the Common partition using the Configuration utility

  1. Create a temporary virtual server in the Common partition. Use the address you want to share across partitions and a service port or VLAN other than that which will be used for any actual virtual server on this address.

    Note: This step will define the shared virtual address in the Common partition.
  2. Create the actual virtual server(s) in the other partitions. Use the same (shared) address and specify the actual port or VLAN each virtual server should use.
  3. Delete the temporary virtual server you created in step 1. The virtual address matches an existing virtual server and will remain in the Common partition, shareable among all partitions.

Moving the virtual address to the Common partition using the command line

  1. Log in to the BIG-IP command line.
  2. Open the /config/bigip.conf file in a text editor.
  3. Locate the stanza that defines the virtual address. It will appear similar to one of the following three examples:

    • virtual address any {
      mask 0.0.0.0
      }

    • virtual address 10.0.0.0 {
      mask 255.0.0.0
      }

    • virtual address 10.10.10.1 { }

  4. Move the entire stanza into the Common partition section of the configuration file, immediately after the following line:

    shell write partition Common

    Note: The virtual address may not be explicitly defined in the configuration file for host virtual servers with a netmask of 255.255.255.255 and no custom options defined. If the stanza does not yet exist, add a line similar to the following example, replacing x.x.x.x with the address of the virtual server:

    virtual address x.x.x.x { }

  5. Save the file.
  6. Load the modified configuration by typing the following command:

    bigpipe load

The virtual address now resides in the Common partition and may be used for virtual servers in any partition.

For example, the configuration file originally contained a definition of a wildcard virtual server in the User1 partition:

shell write partition Common
...
shell write partition User1
virtual address any {
mask 0.0.0.0
}
virtual wildcard {
destination any:any
mask 0.0.0.0
ip protocol tcp
vlans User1 enable
}
...

To make the wildcard address available in all partitions, modify the configuration to appear as follows:

shell write partition Common
virtual address any {
mask 0.0.0.0
}
...
shell write partition User1
virtual wildcard {
destination any:any
mask 0.0.0.0
ip protocol tcp
vlans User1 enable
}
...

To duplicate the wildcard virtual server to serve a second VLAN in a second partition, duplicate the virtual server definition in the second partition, give it a new name, and modify the enabled VLANs list.

The resulting configuration appears similar to the following example:

shell write partition Common
virtual address any {
mask 0.0.0.0
}
...
shell write partition User1
virtual wildcard_User1 {
destination any:any
mask 0.0.0.0
ip protocol tcp
vlans User1 enable
}
...
shell write partition User2
virtual wildcard_User2 {
destination any:any
mask 0.0.0.0
ip protocol tcp
vlans User2 enable
}

Note: If the configuration file contains more than one virtual server with the same name, only the last virtual server to load will appear in the running configuration. To avoid this, be sure to assign a unique name to each virtual server.

Note: If the configuration contains two virtual servers on the same address, they must vary on port, VLAN, or both. If they are not unique in this fashion, the following error message is generated, and the configuration will not load:

BIGpipe unknown operation error:
01070333:3: Virtual Server X illegally shares both address and vlan with Virtual Y.
