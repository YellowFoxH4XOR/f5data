K51561012: Use iControl REST API to search specific ASM signatures using filter

Type
Support Solution
Published
2022-01-14
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.X.X, 14.0.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.X, 14.0.1, 14.0.0, 14.1.0
Source
https://my.f5.com/manage/s/article/K51561012

Description

You should consider using this procedure under the following conditions:

  •     You configured attack signatures in your BIG-IP ASM security policy.
  •     You want to search attack signatures using iControl REST and using filters.

Environment

  • ASM/AdvWAF
  • iControl REST API

Cause

None

Recommended Actions

None

Additional Information

Each BIG-IP ASM security policy configured on the system includes a unique MD5 hash that identifies the security policy. You use the MD5 hash identifier to specify the security policy when managing attack signatures using the iControl REST API. To determine the MD5 hash identifier for the BIG-IP ASM security policy, perform the following procedure:

        Impact of procedure: Performing the following procedure should not have a negative impact on your system.   

  •      Log in to the command line of a system that has the curl and jq utilities.
  •      Use the following command syntax to determine the MD5 hash identifier for the security policy:

    curl -ksu <username:password> 'https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies?$filter=name%20eq%20<security_policy_name>&$select=name,id' | jq '.'

        For example, the system sends the following command to the host asm1.example.com and filters for the security policy named asmpol1:

    curl -ksu admin:admin 'https://asm1.example.com/mgmt/tm/asm/policies?$filter=name%20eq%20asmpol1&$select=name,id' | jq '.'

       The response contains the name of the security policy (asmpol1) and the corresponding hash identifier (FpUrTM3Za6zcos25HquN0g):

{
  "kind": "tm:asm:policies:policycollectionstate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies?$select=name%2Cid&ver=16.0.0&$filter=name%20eq%20asmpol1",
  "totalItems": 1,
  "items": [
    {
      "kind": "tm:asm:policies:policystate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g?ver=16.0.0",
      "name": "asmpol1",
      "id": "FpUrTM3Za6zcos25HquN0g"
    }
  ]
}

 Now using the hash-identifier (FpUrTM3Za6zcos25HquN0g) you can query a signature id status,etc for a asm poloicy "asmpol1" using filters:

  •  The command to query one signature id use the below command:    

    curl -sku <username:password> 'https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies/<hash-identifier>/signatures?$filter=signature/signatureId%20eq%20<sig-id-number>' | jq .   

        For example, the system sends the following command to the host asm1.example.com with hash-identifier (FpUrTM3Za6zcos25HquN0g) you can query a specific signature id "200104645" as below:   

    curl -sku <username:password> 'https://asm1.example.com/mgmt/tm/asm/policies/FpUrTM3Za6zcos25HquN0g/signatures?$filter=signature/signatureId%20eq%20200104645' | jq .

  •    The command to query multiple signature id use the below command
   curl -sku <username:password> 'https://<BIG-IP hostname or management IP address>/mgmt/tm/asm/policies/<hash-identifier>/signatures?$filter=signature/signatureId%20IN%20(<sig-id-number>,<sig-id-number>)' | jq .   

       For example, the system sends the following command to the host asm1.example.com with hash-identifier (FpUrTM3Za6zcos25HquN0g) you can query multiple signature id "200104645" and "200101559" as below:
