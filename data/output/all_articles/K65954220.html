Topic

You should consider using this procedure under the following condition:

  • You want to configure Open Shortest Path First (OSPF) protocol areas on the BIG-IP system.

Description

You can divide an OSPF area into sub-domains, called areas. An area is a logical collection of OSPF networks, routers, and links that have the same area identification. A router within an area must maintain a topological database for the area to which it belongs. The router does not have detailed information about network topology outside of its area, thereby reducing its database size. Areas limit the scope of route information distribution. Areas are identified by an area ID. You can define the area either as a decimal value or in IP address format.

The BIG-IP system supports the following OSPF areas:

  • Backbone area

    OSPF area 0 is also known as a backbone area, and each area must be connected to a backbone area (area 0). All routing between areas is distributed through the backbone area.

  • Stub area

    A stub area does not receive routes from other autonomous systems. Routing from the stub area performs through the default route to the backbone area.

  • Not-So-Stubby-Area

    The Not-So-Stubby-Area (NSSA) is a type of stub area that can import external routes, with some limited exceptions.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have an existing OSPF network.
  • You verify the OSPF area type to which the BIG-IP system joins.
  • You license the BIG-IP system for the BIG-IP Advanced Routing Module (BIG-IP ARM).
  • You have administrative access to the BIG-IP command line

Procedures

  • Configuring a network under a backbone area
  • Configuring an area as a stub area
  • Configuring an area as an NSSA
  • Verifying the type of OSPF area

Configuring a network under backbone area

To configure a network under a backbone area, perform the following procedure:

Impact of procedure: The impact of configuring OSPF areas will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your routing.

  1. Log in to the BIG-IP command line.
  2. Access the IMI Shell (imish) by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. To enter Router mode and to configure an OSPF routing process, use the following command syntax:

    router ospf <1-65535>

    For example, to create an OSPF routing process with area 100, type the following command:

    router ospf 100

  6. To enable OSPF routing with a specified area ID (and optionally an instance ID) on interfaces with IP addresses that match the specified network address, use the following command syntax:

    network A.B.C.D/M area (A.B.C.D|<0-4294967295>) (instance-id <0-255>|)

    For example, to configure network 10.12.19.90/24 in the backbone area 0, type the following command:

    network 10.12.19.90/24 area 0

  7. Exit Configuration mode by typing the following command:

    end

  8. Write the configuration by typing the following command:

    write

Verifying the type of OSPF area

To display OSPF area information, perform the following procedure:

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. To display OSPF general information, use the following command syntax:

    show ip ospf (<0-65535>)

    In this command syntax, note the following:

    • <0-65535> is the ID of the router process for which information will display.

    For example, to display OSPF information for router ID 100, type the following command:

    show ip ospf 100
