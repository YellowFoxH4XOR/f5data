K000162701: Using-an-iRule-to-set-next-hop-for-SOCKS-Virtual-Server

Description

A nexthop iRule command applied directly to a BIG-IP LTM virtual server using a SOCKS profile does not direct SOCKS-proxied traffic through the intended next hop. Applying the command in the SOCKS_REQUEST event also does not change the routed forwarding path.

Environment

  • BIG-IP LTM 17.5.1 configured with:
  • A SOCKS virtual server using a SOCKS profile.
  • SOCKS traffic placed into the socks-tunnel.
  • Source address translation configured with an SNAT pool.
  • An iRule attempting to apply nexthop directly to the SOCKS virtual server.

Cause

The SOCKS profile processes connections as a forwarding proxy and places the traffic into the socks-tunnel. The SOCKS_REQUEST event cannot change the next-hop MAC address for subsequent routed traffic. Consequently, applying nexthop directly to the SOCKS virtual server does not affect the forwarding path.

Answer/Recommended Actions

  • Retain the SOCKS virtual server with its SOCKS profile and tunnel configuration.
  • Create a separate forwarding IP virtual server that listens on the required destination address or 0.0.0.0/0.
  • Configure the forwarding virtual server for all ports.
  • Enable VLAN and tunnel traffic processing on socks-tunnel.
  • Apply the same SNAT pool used by the SOCKS virtual server to the forwarding virtual server.
  • Do not apply the nexthop iRule to the SOCKS virtual server.
  • Apply the nexthop iRule to the forwarding virtual server, specifying the required transit VLAN and next-hop IP address.
  • Test SOCKS connectivity and verify that traffic is forwarded through the intended next hop.

Additional Information

The forwarding virtual server processes the tunneled SOCKS traffic and allows the nexthop iRule to set the intended next-hop MAC address.
