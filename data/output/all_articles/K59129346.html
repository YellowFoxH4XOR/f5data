Description

After upgrade unable to re-activate the license on the unit

/var/log/ltm will show an error like the one below:
Jul 20 01:29:57 big-ip.com err mcpd[7990]: 01020036:3: The requested Certificate Key File (/Common/f5_api_com.key) was not found.

Environment

  • Upgrade to version 14.x or 15.x

Cause

'f5_api_com.key' is blocking your configuration to load properly after boot to upgraded version.

Recommended Actions

Remove references to "f5_api_com.key" from the configuration and folder locations, reload the configuration, then do a Configsync:

  1. Backup the "bigip.conf" file:

    cp /config/bigip.conf /config/bigip.K59129346

  2. Remove all config in "bigip.conf" related to this cert/key (copied the config out)
    Example:

      sys file ssl-key /Common/f5_api_com.key {
        cache-path /config/filestore/files_d/Common_d/certificate_key_d/:Common:f5_api_com.key_####
        #passphrase $N$P7$8/rtkaYUV1Jksdfe3fv1LN23e+qkU0gcMZeIg//RNnn4unX3QhurUqwEl2EY5ttYVoeUf0HwzMDGNhb3ep2nfZCnpNku1LNQmOa1ac2KF44=
        revision 1
        source-path file:///config/ssl/ssl.key/f5_api_com.key
      }

  3. Move all f5_api_com related keys to another folder:
    • /config/ssl/ssl.key/f5_api_com.key
    • /config/filestore/files_d/Common_d/certificate_key_d/:Common:f5_api_com.key_<number>_<revision>
       
  4. Confirm there is not f5_api_com certificate in:
    • /config/ssl/ssl.crt 
    • /config/ssl/ssl.csr
    • /config/filestore/files_d/Common_d/certificate_d/ 
      Else, move them to another folder
       
  5. Reload the configuration:

    # tmsh load sys config 

  6. Re-activate the license
     
  7. Confirm everything works as expected 
         * Config Sync worked as expected
       
    Note: Later on the 'f5_api_com.key' will be synced from peer unit.
