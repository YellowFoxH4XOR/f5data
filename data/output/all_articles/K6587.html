Topic

If a FirePass master group is configured to use native RSA SecurID authentication, and login attempts by users in that master group fail, your FirePass controller may have an improperly generated RSA configuration file.

The following symptoms indicate an improperly generated RSA configuration file:

  • All login attempts by users in that master group fail with the following error message on the login page:

    FirePass is unable to communicate with ACE server. Please contact your system administrator

  • All login attempts by users in that master group fail with the following error message on the login page:
    RSA SecurId configuration error. Please contact your system administrator.
  • All login attempts by users in that master group have failed since the last time you modified the authentication options for that master group.
  • A network packet dump from the Device Management: Maintenance: Troubleshooting Tools menu shows no traffic between the RSA Authentication Manager (formerly RSA ACE server) and the appropriate interface of the FirePass controller.

    Note: You can ensure that a lack of packets between the FirePass controller and the RSA server is not a routing problem by performing a ping and traceroute to the RSA server using the Java maintenance console on the Device Management: Maintenance: Troubleshooting Tools page or a serial console.

When configuring the FirePass controller to use SecurID authentication, you must add the FirePass controller as an Agent Host to the RSA server. In this process, a configuration file for the FirePass controller must be generated on the RSA server using the RSA configuration utility. The file is then imported into the FirePass controller through the FirePass Web Admin UI. For more information about this process, refer to the online help portion of the FirePass controller's Device Management: Configuration: RSA SecurID page.

A common way to incorrectly generate a configuration file occurs when you add the Agent Host in the RSA configuration utility. If an administrator selects Create node secret file while creating the Agent Host and then imports the node secret file created, this produces the aforementioned login failure and its error message.

To generate the configuration file, the administrator should select Generate Configuration Files from the Edit Agent Host menu item after creating the Agent Host.

The difference can be noted in the names of the two files. The default name of a valid configuration file is sdconf.rec. The incorrect method generates a node secret file with the default filename of nodesecret.rec.

Note: The FirePass controller does not require or use a node secret file. The native RSA protocol allows for dynamic generation and negotiation of the necessary encryption data. The FirePass controller and the RSA server will perform the necessary generation and negotiation when the first logon in the master group configured for RSA SecurID authentication takes place.

When you configure an RSA server on the Device Management: Configuration: RSA SecurID page, importing a node secret file instead of a configuration file does not produce any error messages. Additionally, the Users: Groups: Master Groups page for the master group does not echo the imported filename on the Authentication tab.

The only indicator of an imported node secret file (other than the aforementioned errors) may be in the RSA server Administration utility. If the Agent Host's Node Secret Created checkbox for the Agent Host is selected, on the Edit Agent Host page, then a node secret file has been created for the FirePass Agent Host, and possibly has been used instead of a configuration file.

If you have uploaded an improperly generated configuration file to your FirePass controller, you must delete the configuration for that RSA server in the FirePass Admin Web UI, and then re-add the RSA server using a valid configuration file. Deleting the configuration for an RSA server is done on the Device Management : Configuration: RSA SecurID page, in the Remove RSA SecurID Server Configuration section.
