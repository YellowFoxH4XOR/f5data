K10147299: AFM Disk Space Issue: /config partition is full

Type
Support Solution
Published
2020-03-27
Updated
2025-12-16
Applies to
  • BIG-IP
  • BIG-IP AFM: 14.1.0, 14.0.X, 13.1.X, 13.0.X, 14.0.1, 14.0.0, 13.1.5, 13.1.4, 13.X.X, 13.1.1, 13.1.0, 13.0.1, 13.0.0, 13.1.3
Source
https://my.f5.com/manage/s/article/K10147299

Description

  • Disk partition /config has 0% free space
  • The following messages can be seen on /var/log/ltm
    err diskmonitor: 011d0004:3: Disk partition /config (slot 1) has only 0% free
    err diskmonitor: 011d0004:3: Disk partition /config (slot 1) has only 0% free
  • Output of command df -h will be similar to:

    Filesystem            Size  Used Avail Use% Mounted on
    /dev/mapper/vg--db--vda-set.2.root
                          427M  282M  123M  70% /
    none                   14G  1.9G   12G  14% /dev/shm
    /dev/mapper/vg--db--vda-set.2._config
                          3.2G  3.2G     0 100% /config     <=== Note
    /dev/mapper/vg--db--vda-set.2._usr
                          4.0G  3.2G  633M  84% /usr
    /dev/mapper/vg--db--vda-set.2._var
                          3.0G  2.2G  652M  78% /var
    /dev/mapper/vg--db--vda-dat.share.1
                           30G  1.8G   27G   7% /shared
    /dev/mapper/vg--db--vda-dat.log.1
                          6.9G  254M  6.3G   4% /var/log
     
  • /config space is mostly taken by files/directories in /config/filestore/files_d/Common_d/l4bdos_context_d/

Environment

  • BIG-IP AFM
  • /config directory

Cause

The behavior is caused by a known issue tracked with Bug ID 737035

Recommended Actions

  • You can verify what files are taking up the most space in the /config directory by running the following command:
    find /config/ -xdev -type f -exec du -h {} \; | sort -rh | head -20
    If you confirm the /config/filestore/files_d/Common_d/l4bdos_context_d/* are causing the issue, then you are encountering the bug otherwise there are different files causing the excessive disk usage and the previous command will help you identify any unnecessary files that can be deleted.
  • Upgrade to a BIG-IP software version where bug ID 737035 is fixed.
  • As a workaround you can manually delete files/directories filling up under /config/filestore/ partition to free up disk space.
    1. Connect to the CLI
    2. Delete files/directories filling up under /config/filestore/files_d/Common_d/l4bdos_context_d/

      rm -rf /config/filestore/files_d/Common_d/l4bdos_context_d/*
