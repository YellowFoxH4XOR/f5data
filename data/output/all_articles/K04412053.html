Topic

In BIG-IP 11.6.0, F5 introduced HTTP/2 protocol support as defined in Internet Engineering Task Force (RFC 7540) for processing client-side HTTP/2 traffic. The support for server-side HTTP/2 traffic processing was introduced in BIG-IP 14.1.0; the webacceleration and OneConnect profiles are not supported in HTTP/2 full proxy mode in this version. In BIG-IP 15.0.0, F5 introduced the support for webacceleration profile in HTTP/2 full proxy mode.

Description

HTTP/2 is a major revision to the HTTP protocol, offering both speed and the following efficiency benefits:

  • Native support of header compression that significantly improves latency.
  • Multiplexing of responses from the BIG-IP system to the client.
  • Native support for parallel client requests.
  • Layer 7 (L7) flow control with its own receive window.

A virtual server with an associated HTTP/2 profile processes connections using the BIG-IP full proxy architecture for the purpose of making requests on behalf of clients. In this mode, the BIG-IP system typically processes HTTP/2 requests in the following order:

  • TCP three-way handshake
  • SSL handshake with Application Layer Protocol Negotiation (ALPN) indicating support for HTTP/2
  • HTTP/2 SETTINGS frame for configuration parameters exchanged after a successful SSL handshake
  • HTTP HEADERS frame to exchange HTTP request messages between the client and the server
  • HTTP/2 DATA frame to exchange data
  • HTTP/2 GOAWAY frame to signal HTTP/2 connection closure

The HTTP/2 protocol uses frame types to define what kind of information to expect during message exchange. For example, in the beginning of an HTTP/2 negotiation, the SETTINGS frame type is exchanged to negotiate connection parameters, including flow control. When the client is ready to issue a GET request, the protocol uses the HEADERS frame type. When payload is exchanged, the protocol uses the DATA frame type. When the HTTP/2 connection is ready to close, the protocol uses the GOAWAY frame type to signal the end of the HTTP/2 connection.

Configuring HTTP/2 full-proxy support

To enable full proxy support for HTTP/2, you must configure the virtual server with an HTTP/2 Profile(Server) as well as enable the HTTP MRF Router setting using the Configuration utility.

For more information about configuring HTTP/2 full proxy support, refer to the Configuring HTTP/2 Full-proxy Support on the BIG-IP system chapter of the BIG-IP System: HTTP/2 Full-proxy Deployment manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

BIG-IP HTTP/2 profile

The HTTP/2 profile provides settings to configure full L7 functionality for your virtual server traffic. You can use the default profile settings or configure custom profile settings when you create a profile. The following table contains the settings and definitions for the HTTP/2 profile.

SettingDefault  Description
NameNoneSpecifies the name of the profile.
Concurrent Streams Per Connection10Specifies the maximum number of concurrent HTTP/2 streams that BIG-IP system advertises to the client it can handle. The default value is 10.

Note: The BIG-IP system advertises the value from Concurrent Streams Per Connection during the exchange of HTTP/2 settings with client.

Connection Idle Timeout300Specifies the time BIG-IP system allows an HTTP/2 connection idle before sending HTTP2 GOAWAY message to close it. The default value is 300 seconds. 
Insert HeaderDisabledSpecifies whether an HTTP header indicating the use of HTTP/2 should be inserted into the request that goes to the server. The default value is Disabled.
Insert Header NameX-HTTP2Specifies the header name inserted when the Insert header is enabled. By default, the BIG-IP system inserts the X-HTTP2 header.

Note: Using the default configuration, the BIG-IP system adds X-HTTP2: Yes to the server-side HTTP request.

Enforce TLS RequirementsEnabledSpecifies whether BIG-IP system should enforce TLS requirements of RFC7540. The default value is Enabled.

Note: A configuration error message displays when attempting to add a Client SSL profile to an HTTP/2 virtual server if TLS Renegotiation is not disabled and the ECDHE cipher is not allowed. 

Activation ModesALPNSpecifies how the BIG-IP system negotiates HTTP/2 protocol. By default, the BIG-IP system accepts Application Layer Protocol Negotiation (ALPN).  Beginning in version 13.1.0, the BIG-IP system no longer supports Next Protocol Negotiation (NPN), which is now deprecated and replaced by the industry standard ALPN published as RFC 7301. Prior to BIG-IP 13.1.0, the NPN is accepted by the BIG-IP system.

Note: A third configuration option named Always, in which HTTP/2 is supported in plain-text, was originally developed for debugging purposes only. To use this option, you must remove Client SSL profiles attached to the virtual server.

Receive Window32Specifies the initial window size for all streams in a given HTTP/2 connection. This value is sent in the HTTP/2 SETTINGS message. The receive window allows HTTP/2 to stall individual upload streams, when needed. This functionality only applies to HTTP/2 version 3. The default value is 32KB.
Frame Size2048Specifies the maximum size of the payload of HTTP/2 data frames, in bytes, that the BIG-IP system sends to the client. Larger frame sizes improve network usage but can affect concurrency. The default value is 2048 bytes.

Note: Changing HTTP/2 Frame Size value can impact performance and F5 recommends that Client SSL profile Maximum Record Size and TCP profile Maximum Segment Size (MSS) to be taken into consideration before changing HTTP/2 Frame Size value. For example, if HTTP/2 Frame Size is reduced to the minimum value of 1024 bytes, the BIG-IP system can carry one or more HTTP/2 data frames in a single SSL Record. In contrast, setting Frame Size to a larger value may cause more than one SSL record message to be sent over multiple TCP messages for a single HTTP/2 data frame to be sent. HTTP/2 data frames are described in Section 6.1 of RFC 7540.

Write Size16384Specifies the total size of combined data frames in bytes of a single HTTP/2 message carried in the TLS payload. The default is 16384 bytes.

Note: The HTTP/2 header can carry multiple data frames combined. The payload of each frame is limited by the Frame Size and the total combined data by the Write Size.

Header Table Size4096Specifies the maximum table size, in bytes, for the 
    dynamic table of HTTP/2 header compression. The default value is 4096.

    Note: The HTTP/2 protocol compresses HTTP headers to save bandwidth and uses a static table with predefined values and a dynamic table with values that are likely to be reused again in the same HTTP/2 connection. The Header Table Size limits the number of entries of HTTP/2 dynamic table as described in Section 4.2 of RFC 7541. When the limit is reached, old entries are evicted so that new entries are added.

    Beginning in BIG-IP 13.1.0, the following new configuration options were added.

    SettingDefaultDescription
    Include Content LengthDisabledThis option allows the BIG-IP system to forward or not forward the Content-Length header sent by the pool member's HTTP response to the client. The default value is Disabled.

    Note: This option is now deprecated, and the BIG-IP system always forwards the Content-Length header to the client, even if the value is Disabled.
