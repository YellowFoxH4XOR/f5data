Known Issue

This is the result of a known issue. Starting in version 7.0, BEA changed the format of the WebLogic session ID. As a result, the wlnode function no longer works as expected.

F5 Networks Product Development tracked this issue as CR28656 and CR41838.

Note: The wlnode() function was valid only for WebLogic version 6.x. The WebLogic format of the WebLogic session ID has been modified several times since this function was introduced.  For more current versions of WebLogic, F5 Networks recommends using iRules to enforce JsessionID persistence. Examples of this solution are maintained in the DevCentral codeshare at the following location:

WebLogic JsessionID Persistence v4.x  (BIG-IP version 4.5.x and 4.6.x):    https://devcentral.f5.com/Wiki/iRules.Weblogic_JSessionID_Persistence_v4.ashx
