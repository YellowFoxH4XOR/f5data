Topic

This article provides steps on configuring the fully-qualified domain name (FQDN) ephemeral node feature to autopopulate BIG-IP pools using iControl REST API.

Description

You can configure the BIG-IP device to automatically populate node and pool member lists by using FQDNs. Depending on the number of IP addresses returned by the DNS server, the BIG-IP device creates an ephemeral pool member for each IP address returned in the DNS response. You may want to refer to the list of articles in the Related Content section at the bottom of this article for information about the behavior, limits and considerations when using the FQDN ephemeral node feature on the BIG-IP device.

Prerequisites

  • You must have administrative access to the iControl REST API on your BIG-IP device.
  • You have access to a workstation that is installed with the curl and jq utilities and have network access to your BIG-IP device.
  • Your BIG-IP device must be configured with a DNS server to handle DNS lookups. Additionally, you should ensure that your DNS server is not configured for round robin DNS resolutions; instead, your DNS server should return all available IP addresses in a DNS resolution. For information about configuring BIG-IP device to resolve DNS using iControl REST API, refer to the Creating or replacing the DNS server configuration section of K13225405: Common iControl REST API command examples.

Procedures

  • Creating a node using the FQDN ephemeral node feature
  • Configuring a pool using the FQDN ephemeral node feature
  • Disabling/enabling a FQDN pool member

Creating a node using the FQDN ephemeral node feature

Prior to configuring a pool that uses this feature to auto-populate the pool members, you should create the node(s) relevant to the pool. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to a workstation that has both curl and jq utilities installed.
  2. Create a node by entering the following iControl REST API command syntax:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<IP address>/mgmt/tm/ltm/node -d '{ "name":"<NODE NAME>", "fqdn":{"tmName":"<NODE FQDN>", "autopopulate":"<enabled | disabled>", "interval":"<[integer value] | ttl>"} }' | jq

    Note: The interval setting can either be a static integer value you configure or the TTL value obtained from the DNS response if configured with ttl. This setting affects how frequent the BIG-IP device sends DNS queries and repopulate the ephemeral nodes when the autopopulate is set to enabled.

    For example,

    curl -sku admin:admin -H "Content-Type: application/json" -X POST https://192.168.61.140/mgmt/tm/ltm/node -d '{ "name":"node-test-autodns", "fqdn":{"tmName":"test.myf5.lab", "autopopulate":"enabled", "interval":"ttl"} }' | jq

    The command returns an output similar to the following example:

Configuring a pool using the FQDN ephemeral node feature

To configure a pool using the FQDN ephemeral node feature, you should add the FQDN node(s) created from the previous procedure as pool member(s). To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to a workstation that has both curl and jq utilities installed.
  2. Configure a pool by entering the following iControl REST API command syntax:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<IP address>/mgmt/tm/ltm/pool -d '{ "name":"<POOL NAME>", "monitor":"<MONITOR NAME>", "members":[{ "name":"<NODE 1 NAME>:<PORT NUMBER>", "fqdn":{ "autopopulate":"<enabled | disabled>" } }, … ] }' | jq

    For example,

    curl -sku admin:admin -H "Content-Type: application/json" -X POST https://192.168.61.140/mgmt/tm/ltm/pool -d '{ "name":"pool-test-autodns", "monitor":"mon-http-test", "members":[{ "name":"node-test-autodns:8001", "fqdn":{ "autopopulate":"enabled" } }, { "name":"node-test-autodns:8002", "fqdn":{ "autopopulate":"enabled" } } ] }' | jq

Disabling/enabling a FQDN pool member

You can disable a FQDN pool member when you want the pool member to stop accepting new connections but complete the existing persistent and active connections. This is useful when you want to perform maintenance on the pool member. Note that the BIG-IP device does not allow modifications made to the individual FQDN ephemeral pool member, you can only make changes to the parent FQDN pool member. If you attempt to modify the individual FQDN ephemeral pool member, the BIG-IP device does not allow the modification and reports an error similar to the following example:

01071c39:3: Modify of ephemeral pool member (pool /Common/pool-test-autodns member /Common/192.168.40.131) is not permitted.

When you disable/enable the parent FQDN pool member, all the child FQDN ephemeral pool members will be disabled/enabled. To disable/enable a FQDN pool member, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to a workstation that has both curl and jq utilities installed.
  2. To disable a FQDN pool member, enter the following iControl REST API command syntax:

    curl -sku admin:<password> -H "Content-Type: application/json" -X PATCH https://<IP address>/mgmt/tm/ltm/pool/<POOL NAME>/members/~Common~<NODE NAME>:<PORT NUMBER> -d '{ "session":"user-disabled"}' | jq

    For example,

    curl -sku admin:admin -H "Content-Type: application/json" -X PATCH https://192.168.61.140/mgmt/tm/ltm/pool/pool-test-autodns/members/~Common~node-test-autodns:8002 -d '{ "session":"user-disabled"}' | jq
