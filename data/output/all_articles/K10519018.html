Description

After Switch firmware update Primary Device does not become the Active.

In /var/log/ltm the following is seen:

Jan 01 12:00:00 <hostname> notice sod[1111]: xxxxxxxx:x: Leaving active in favor of active peer.

Environment

  • Switch connected to each BIG-IP is updated
  • First Switch ( SW1 ) connected to Primary ( Active ) BIG-IP is updated and then the Switch ( SW2  ) to the Secondary ( Standby )
  • HA Group Configured
  • Sequence of Events:
    1. SW1 updated
      (Communication lost between Primary and Secondary)
    2. Both Devices are Active
      (???Communication Restored)
    3. Failover Status > Primary: Active; Secondary: Active
    4. SW2 updated
      (Communication lost between Primary and Secondary)
    5. Both Devices are Active
      (?????????????????????Communication Restored)
    6. Failover Status > Primary: Standby; Secondary: Active
       

Cause

When HA groups are used which device becomes the Active is determined by the HA health score.

The health score is calculated based on the HA Group configuration; trunk, pool or cluster availability. 

However, in the event when both devices are in the Active State and have the same HA Group scoore, then the device with the highest management IP address takes the role of the Active.

Recommended Actions

None.

Additional Information

None.
