Known Issue

Attack signature updates may fail.

This issue occurs when all of the following conditions are met:

  • You upgrade your BIG-IP ASM system to 12.0.0, 11.6.1, or 11.6.0.
  • During the upgrade process, the attack signature systems become corrupted in the configuration database.
  • You attempt to apply an attack signature update.

Impact

Users cannot install attack signature updates.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to apply an attack signature update, the system displays an error message similar to the following example:

    crit g_server_rpc_handler.pl[<pid>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Sigfile::Update::store_error_and_die): Failed on insert to PLC.NEGSIG_SYSTEMS (DBD::mysql::db do failed: Duplicate entry '<numeric value>' for key 'PRIMARY')

  • In the /var/log/asm file, you observe messages similar to the following example:

    crit g_server_rpc_handler.pl[<pid>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Sigfile::Update::store_error_and_die): Failed on insert to PLC.NEGSIG_SYSTEMS (DBD::mysql::db do failed: Duplicate entry '<numeric value>' for key 'PRIMARY')
    crit g_server_rpc_handler.pl[<pid>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::handle_error): Failed update_sigfile on duplicate record for 
    crit g_server_rpc_handler.pl[<pid>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): Failed on insert to PLC.NEGSIG_SYSTEMS (DBD::mysql::db do failed: Duplicate entry '<numeric value>' for key 'PRIMARY')

Workaround

To work around this issue, you can correct the signature system corruption and then reapply the attack signature update. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP ASM system with the administrator account.
  2. Enter the following command stanza:

    mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "DELETE FROM PLC.NEGSIG_SYSTEMS WHERE system_group = ''"

  3. Apply the attack signature update.
