Known Issue

This is the result of a known issue. Concurrent access to expired documents may cause a crash when the system attempts to update the cache records. This behavior occurs when multiple concurrent requests are issued for expired documents. The system refreshes the expired documents, but erroneously references the PvContentRecord used by the expired documents.

When this behavior occurs, a message is logged to the pvac.log file that appears similar to the following example:

debug WA Debug: * File: PvContentRecord.cxx, Line: 257
debug WA Debug: *
debug WA Debug: * Failed condition: sRecord_nodeRef==0
debug WA Debug: *

F5 Product Development tracked this issue as ID 223311 (formerly CR128792) and it was fixed in BIG-IP WebAccelerator 10.2.1. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue has been fixed in BIGIP-10.2.0-1755.1-HF1 for BIG-IP 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
