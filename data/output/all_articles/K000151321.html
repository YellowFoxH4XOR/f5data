Description

A request may be rejected due to exceeding the maximum allowed URL length as defined by the global system variable ecard_max_http_req_uri_len. This check considers the full URL, including both the path and the query string in their encoded forms. Even if a specific policy for a file type (such as no_ext) has its own URL length setting, the global variable is evaluated first and can cause the request to be denied before the policy-specific limit is checked.

Environment

  • System using URL inspection with F5 security policies
  • File type configuration such as no_ext
  • Global system variable ecard_max_http_req_uri_len in effect
  • URL length enforcement at both global and file-type levels

 

Cause

The rejection occurs when the combined length of the path and query string, as seen in the encoded request, exceeds the value set in ecard_max_http_req_uri_len. For example:

  • ecard_max_http_req_uri_len = 100
  • URL path = 99 characters (/A...A)
  • Encoded query string = ?query=value1%2Cvalue2 → adds to total URL length
  • Resulting full URL: /[99 A's]?query=value1%2Cvalue2 = 122 bytes
  • Because 122 > 100, the request is rejected.

Even though the file type no_ext also has a limit of 100, it only evaluates the path, not the query string. But since the global variable check happens first, the violation is triggered regardless of the file-type limit.

The size of ecard_max_http_req_uri_len can be increased:  K60450445: Configuring the maximum allowed URL length for an HTTP request

 

Recommended Actions

  1. Review and adjust the ecard_max_http_req_uri_len value if legitimate URLs in your environment often exceed this limit.
  2. Understand that file-type-specific limits (for example, no_ext) do not override global settings. Ensure both values are configured to handle the expected URL lengths.
  3. When testing or diagnosing issues, remember that URL length is computed after encoding, so special characters may increase the byte count.
  4. Consider logging or capturing full rejected URLs during testing to identify patterns and adjust thresholds accordingly.

 

Additional Information

  • The system calculates the URL length based on the original encoded form of the request. For standard ASCII characters, each is 1 byte.
  • A known issue involving URL length handling is documented under F5 bug tracker IDs ID747905 and ID1111129.
  • In some environments, a maximum threshold of 3610 bytes may be observed, possibly due to internal buffer limitations or related bugs.
  • Increasing the size of the ecard_max_http_req_uri_len variable will impact the memory consumption for all active ASM policies on the unit and could lead to a memory resource issue. The impact of increasing the value above 2048 bytes would be determined by the number of policies in use.
