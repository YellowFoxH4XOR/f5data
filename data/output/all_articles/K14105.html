Known Issue

The BIG-IP APM system reports an ActiveSync connection from an Apple iOS client to the BIG-IP APM system as a WINNT client using Internet Explorer.

Impact

Apple iOS clients are unable to retrieve Exchange email, calendar updates, or tasks.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The client receives the following error message:

    The connection to the server failed.
  • Viewing a session report shows an entry that appears similar to the following example:

    "Received client info - Type: IE Version: 7 Platform: WinNT CPU: unknown
    UI Mode: Full Javascript Support:8 1 ActiveX Support: 1"

Resolution

Status

F5 Product Development has assigned ID 379413 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

To work around this issue, you can add specific detection for an iOS device. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. Click Edit... next to the access profile to edit.
  5. Click Client OS action.

    Note: This procedure assumes you are using the Client OS action for OS detection.
  6. Click the Branch Rules tab.
  7. Ensure the Insert Before Drop down-menu is set to the first branch rule in the list.
  8. Click Add Branch Rule.
  9. Enter a name in the Name: text box.

    For example:

    iOS Active-sync
  10. Click Change.
  11. Click the Advanced tab.
  12. Enter the following text into the Advanced text box:

    expr { [mcget {session.ui.mode}] == 8 || [mcget {session.user.activesync}] == 1 }
  13. Click Finished.
  14. Click Save.
  15. Assign your additional actions for ActiveSync to the iOS ActiveSync branch.
  16. Click Apply Access Policy.
