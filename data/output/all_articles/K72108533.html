Description

When you are configuring Kerberos Authentication and getting this error messages in the /var/local/apm:

debug apmd[5978]: 01490266:7: /Common/testauth.devus.local:Common:966f95af: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'PrintGssErrorImpl()': 184: 966f95af : GSS-API error gss_accept_sec_context: d0000 : Unspecified GSS failure.  Minor code may provide more information
debug apmd[5978]: 01490266:7: /Common/testauth.devus.local:Common:966f95af: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'PrintGssErrorImpl()': 184: 966f95af : GSS-API error gss_accept_sec_context: 186a5 : Request ticket server HTTP/testauth.dev.local@DEVUS.LOCAL kvno 4 found in keytab but not with enctype rc4-hmac

Additionally you can run: 
klist -kte /config/filestore/files_d/Common_d/kerberos_keytab_file_d/:Common:testauth.dev.local_key_file_16226073_1
There should be an entry like this to support arcfour-hmac/rc4-hmac
KVNO Timestamp           Principal
---- ------------------- ------------------------------------------------------
   11 01/01/1970 01:00:00 HTTP/testauth.devus.local@DEVUS.LOCAL (arcfour-hmac)

Environment

  • BIG-IP APM 
  • Kerberos

Cause

Kerberos ticket encryption does not match the encryption type configured in the keytab file.

Recommended Actions

There are 2 options:

  1. If arcfour-hmac/rc4-hmac is not included for that KVN0 and Principal then you should create and upload to APM a new keytab file including that encryption.
    or
  2. The Kerberos connections is only using rc4-hmac because either the keytab or the backend server is requesting it. If it is not in the keytab, then the server is asking for it and needs to be fixed there.
