K000130266: TACACS authentication server may not work due to routing problem

Type
Support Solution
Published
2022-12-19
Updated
2023-01-17
Source
https://my.f5.com/manage/s/article/K000130266

Description

In most cases, the TACACS server is not reachable due to routing problem. The authentication server must be in the same subnet as the BIG-IP interface's IP which is on the path to it.

The appropriate interface should match with IP addresses between the TACACS server or intermediary device and BIG-IP. If the IPs aren't matching and are in different subnets, you should add a static route to avoid sending traffic via not appropriate interface.

You may encounter these kinds of messages in the /var/log/secure file, which indicates the server is not reachable:

Sep 27 12:58:42 hostname err httpd[18116]: pam_tacplus: error communicating with server <-----------------!
Sep 27 12:58:42 hostname notice httpd[18116]: pam_tacplus: Auth server unavailable, trying fallback
Sep 27 12:58:42 hostname notice httpd[18116]: pam_tacplus: pam_tacplus: user xxxx not authenticated
Sep 27 12:58:42 hostname warning httpd[18116]: pam_unix(httpd:auth): check pass; user unknown

Environment

  • BIG-IP
  • TACACS+ authentication server

Cause

The TACACS server IP address is routable by a different path than the management and that is the cause of communication problem. To check the path of the TACAC's server IP, perform the below command:

# ip route get <Authentication_server_ip>


If you encounter this kind of output it indicates that BIG-IP is not using the management interface:

x.x.x.x via y.y.y.y dev External src z.z.z.z


The expected output is similar to the below:

x.x.x.x dev mgmt src z.z.z.z

Recommended Actions

You should consider adding a static management route for your TACACS authenticator server. To do so, perform the below command:

# tmsh create /sys management-route <name> network x.x.x.x/32 gateway <management gateway>
