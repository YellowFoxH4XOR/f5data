K000151113: BIG-IP not forwarding SIP INVITE using MRF

Type
Support Solution
Published
2025-04-30
Updated
2025-04-30
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151113

Description

BIG-IP is not forwarding or dropping a Session Initiation Protocol(SIP) INVITE using Message Routing Framework(MRF) Virtual Server and other SIP methods are forward.  Virtual servers using Message Based Load Balancing(MBLB) forward SIP INVITE without issue.

Environment

  • LTM
  • MRF

Cause

SIP Content-Length header does not match the Session Description Protocol(SDP) lenght correctly.  MRF Virtual Servers are far more strict than MBLB Virtual Servers and Content-Length is required to match SDP length correctly to be forwarded through MRF Virtual Server. 

 

Example Content-Length in SIP header does not correctly match SDP lenghth.

SIP/2.0 200 OK
Via: SIP/2.0/UDP 192.168.0.1:5060;maddr=192.168.0.1;branch=4aaee095-7b19-4eab-942b-9ec1cefc83fe
From: <sip:4255559876@192.168.0.2:5060>;an=0ae3a4e7-b409-429b-81eb-ea05c4b443d6;tag=6988ee57
To: <sip:4255551234@192.168.0.1:5060>;an=7610b137-91e0-41e0-a6dd-8617eca44e20;tag=10148
Call-ID: 4166@192.168.0.2
CSeq: 1 INVITE
Contact: <sip:192.168.100.2:5060;transport=UDP>
Accept: application/sdp, application/isup, application/dtmf, application/dtmf-relay,  multipart/mixed
Allow: INVITE,ACK,CANCEL,BYE,REFER,SUBSCRIBE,NOTIFY,PRACK,UPDATE,OPTIONS
Supported: timer
Session-Expires: 1800;refresher=uas
Content-Disposition: session; handling=required
Content-Type: application/sdp
Content-Length:  166

v=0
o=user1 12345678 1234567890 IN IP4 192.168.100.2
s=-
c=IN IP4 192.168.100.2
t=0 0
m=audio 6000 RTP/AVP 0
a=rtpmap:0 PCMU/8000
a=sendrecv
a=maxptime:20

Recommended Actions

Alter the SIP content-length header to be correctly cacluated.
