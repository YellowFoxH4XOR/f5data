Description
A Standard virtual server with tcp profile responds to TCP response based on pool state of "Offline (Enabled) - The children pool member(s) are down".

Environment

  • BIG-IP
  • Standard virtual server
  • TCP 3-way handshake completes before TCP RST is sent

Cause
This is the expected behaviour of BIG-IP as per K9812 and allows for iRule processing even when the VIP is offline.

If the virtual server references a TCP profile (Standard virtual server type),  the system allows the three-way TCP handshake to complete before sending the TCP RST to the client.
If the virtual server references a FastL4 profile, the system sends a TCP RST packet in response to a connection attempt. The TCP RST packet is sent on the client-side of the connection, and the source IP address of the reset is the relevant virtual server IP address.

Further information can be found in K000159991: Virtual Server TCP connection behavior based on the pool or the virtual server state.

Recommended Actions

Any one of the following options can be applied to resolve the issue:
  1. Use an alternative monitor type
  2. Utilise the Performance (Layer 4) Virtual Server type and fastL4 profile if appropriate
  3. Modify the TCP profile Connection Setup
    Disable Fast Open
    Enable Verified Accept
