Known Issue

This is the result of a known issue. The Records Per Screen setting in the BIG-IP Configuration utility specifies the number of records that the system displays for all list screens. The Configuration utility does not enforce the Records Per Screen range of 1 to 1000, and allows a user to specify a value of less than 1. As a result, the system is unable to display the data for list screens, and instead displays an error message.

If the Records Per Screen parameter is set to 0 (zero) and a user navigates to a list screen, such as the Virtual Servers screen, the following error message displays in the Configuration utility:

[Exception in:/tiles/tmui/standard_list_buttons.jsp] / by zero

If the Records Per Screen parameter is set to a negative value and a user navigates to a list screen, the Configuration utility generates the following error message:

General database error

F5 Product Development tracked this issue as CR103682 and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator release notes.

This issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP version 9.4.5. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by changing the value of the Records Per Screen parameter to a value greater than zero. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System in the left hand menu.
  3. Click on Preferences.
  4. Change the value of the Records per Screen parameter to a value greater than zero.
  5. Click Update to save the changes.

Note: If the parameter was set to a value less than 1 prior to upgrading, you must perform this workaround once after upgrading.
