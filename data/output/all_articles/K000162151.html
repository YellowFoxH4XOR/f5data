K000162151: NGINX R37 configured via NIC does not reflect "keepalive 0" to upstream

Type
Support Solution
Published
2026-07-09
Updated
2026-07-09
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 5.3.0
Source
https://my.f5.com/manage/s/article/K000162151

Description

Setting keepalive: 0 in a VirtualServer manifest for NGINX Ingress Controller with NGINX Plus R37 does not result in the keepalive 0 directive appearing in the upstream block of the nginx configuration. Instead, the configuration omits the directive, and connections to upstream servers are closed, effectively disabling keepalive. This differs from NGINX Plus R36, where keepalive was disabled by default and did not cause errors. Setting keepalive: 1 or higher is reflected correctly in the configuration.

Environment

  • NGINX Ingress Controller version 5.3.0 and 5.4.2
  • NGINX Plus R36 and R37
  • VirtualServer manifests configured in Kubernetes
  • Upstream blocks in nginx.conf generated by NGINX Ingress Controller

Cause

There is a misalignment between NGINX Ingress Controller's VirtualServer manifest processing and the updated keepalive behavior in NGINX Plus R37. When keepalive: 0 is set, the directive is not written to the upstream block, but keepalive is disabled by triggering "Connection: close" to upstream servers.

Answer/Recommended Actions

  • Setting keepalive: 0 in the VirtualServer manifest disables keepalive by triggering connection closure to upstream servers, even though the directive is not present in the nginx configuration.
  • Setting keepalive: 1 or higher will be reflected in the configuration as expected.
  • If errors are observed, capture packet traces (pcap) to verify connection closure behavior.
  • Monitor the relevant GitHub issue for updates regarding a fix for NGINX Ingress Controller's handling of keepalive values with NGINX Plus R37.

Additional Information

  • The issue was not present in NGINX Plus R36, where keepalive was disabled by default.
  • NGINX Ingress Controller's configuration generation logic does not currently write keepalive 0 to the upstream block, but disables keepalive by other means.
  • Feedback indicated errors when keepalive: 0 is set and not reflected in the configuration, which differs from previous behavior.
