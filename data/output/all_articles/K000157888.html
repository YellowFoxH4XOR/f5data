K000157888: F5OS SDAG hash randomisation can cause performance degradation in CGNAT deployments

Description

The CMP feature (Clustered Multiprocessing) allows BIG-IP platforms that contain multiple CPUs to run multiple TMM threads. With multiple TMM threads simultaneously processing traffic, system performance is enhanced, and traffic management capacity is expanded.  With multiple TMM threads, traffic needs to be disaggregated evenly between all available threads. On F5OS platforms, SDAG is the mechanism used for such disaggregation.
When Traffic Management Microkernel (TMM) restarts or a blade reboots, SDAG hash tables on F5OS devices can change dynamically. This behavior can negatively affect CGNAT environments, where unnecessary CMP connection redirects may be seen (which can lead to higher CPU usage).
This article provides details on the issue's impact and addresses methods for mitigating and resolving this behavior.

Environment

  • F5OS
  • CGNAT

Cause

CGNAT translation IP's in PBA mode are allocated to a client having in account the client IP.  The idea is to allocate a CGNAT translation IP which falls on the same TMM as the client, so that no redirections happen. SDAG hashes play a role as they dictate how traffic is disaggregated (to what TMM) given a certain hash.
When for example a TMM restarts or a blade reboots, the SDAG hash tables are randomised. This means that earlier CGNAT persistence entries (created having in account previous hashes) will still be in place but now with a different SDAG hash, which may point the translation address to a different TMM.  Since these persistence entries still have to be honoured by the BIG-IP, this may result in increased packet redirects (between TMM's) which may cause a degradation in system performance.

Key technical manifestations include the following:

  • Changed tmctl tmm/sdaglib_hash_table and tmctl tmm/sdaglib_mirror_table tables post-event
    tmctl -d blade tmm/sdaglib_hash_table
    tmctl -d blade tmm/sdaglib_mirror_table
  • Heavy CMP connection redirects tracked in tmm_stat table outputs
    tmctl tmm_stat -s slot_id,cpu,client_side_traffic.tot_conns,cmp_conn_redirected

Recommended Actions

Mitigation

  1. Apply Fixes for ID1966941 and ID1966945
    Install the relevant hotfix or firmware updates to include fixes for these known bugs, which enable configuring static SDAG hash tables.
  2. Set Static SDAG Hash Values
    Depending on whether your tenant version contains the fix for ID2037409 or not, perform one of the following procedures.

Procedure 1: For Versions Without the Fix for ID2037409

  1. Fetch Current SDAG hash values
    Use the following commands to obtain hash and mirror tables (respectively):
    tmctl -d blade tmm/sdaglib_hash_table -s table -c | grep -v table | uniq
    tmctl -d blade tmm/sdaglib_mirror_table -s table -c | grep -v table | uniq
  2. Set static SDAG hash values using sys db keys from point A
    Copy the output values into the following commands (first one hash table, second one mirror table):
    tmsh modify sys db sdag.runtime.hashtable value "hash"
    tmsh modify sys db sdag.runtime.mirror.hashtable value "hash"
  3. Save Configuration Persistently
    Save your changes:
    tmsh save sys config

Procedure 2: For Versions With the Fix for ID2037409

  1. Download and Use Python Script for Translation
    Use the following Python script to interpret tmctl outputs into the appropriate sys db format. Save this file as /var/tmp/dag_hashes.py
    import sys
def parse_hex_list(s):
    return [int(token, 16) for token in s.split(':') if token]
def main():
    if len(sys.argv) != 3:
        print(f"usage: {sys.argv[0]} did_table table")
        sys.exit(0)
    dids = parse_hex_list(sys.argv[1])
    table = parse_hex_list(sys.argv[2])
    output = [f"{dids[i]:x}" for i in table]
    print(':'.join(output))
if __name__ == "__main__":
    main()
    And make the script executable:
    chmod u+x /var/tmp/dag_hashes.py
  2. Extract and translate SDAG hash tables
    Fetch did_table and table outputs from both sdaglib_hash_table and sdaglib_mirror_table from your device:
    tmctl -d blade tmm/sdaglib_hash_table -s did_table -c | grep -v did_table | uniq
    tmctl -d blade tmm/sdaglib_hash_table -s table -c | grep -v table | uniq
    Using the values obtained above commands ('did_table' and 'table', respectively), run the Python script to translate the did_table and table into a single output:
    python3.8 /var/tmp/dag_hashes.py <did_table> <table>
    Note: the python output will be used later on, under point D, to set the "translated_hash" value
  3. Extract and translate SDAG mirror tables
    Fetch did_table and table outputs from both sdaglib_hash_table and sdaglib_mirror_table from your device:
    tmctl -d blade tmm/sdaglib_mirror_table -s did_table -c | grep -v did_table | uniq
    tmctl -d blade tmm/sdaglib_mirror_table -s table -c | grep -v table | uniq
    Using the values obtained above commands ('did_table' and 'table', respectively), run the Python script to translate the did_table and table into a single output:
    python3.8 /var/tmp/dag_hashes.py <did_table> <table>
    Note: the python output will be used later on, under point D, to set the "translated_mirror_hash" value
  4. Set static SDAG hash tables
    Use the translated outputs as the static hashes. Configure the sys db keys:
    tmsh modify sys db sdag.runtime.hashtable value "translated_hash"
    tmsh modify sys db sdag.runtime.mirror.hashtable value "translated_mirror_hash"
  5. Save Configuration Persistently:
    Save your configuration to ensure persistence:
    tmsh save sys config

Additional Information

Verification Steps:
After setting static SDAG hash values, confirm SDAG hash tables remain consistent post-reboot:
tmctl -d blade tmm/sdaglib_hash_table -s table -c | grep -v table | sort | uniq
tmctl -d blade tmm/sdaglib_mirror_table -s table -c | grep -v table | sort | uniq
