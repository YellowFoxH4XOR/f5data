K000138583: ASM/AdvWAF Behavioral & Stress-based (D)DoS Detection behavior for the first 24 hours after an upgrade.

Type
Support Solution
Published
2024-02-12
Updated
2024-02-12
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000138583

Description

After an upgrade you see actions taken by the AdvWAAF DoS policy that were not occurring prior to the upgrade.

Environment

  • Upgrade the BIG-IP.
  • Behavioral & Stress-based (D)DoS Detection
  • ASM/AdvWAF

Cause

When an upgrade is done the learning in the prior version is not brought along in the upgrade. So after the upgrade, during the first 2 hours, it uses whatever the high level setting for Source IP, Device ID, URL, and Site Wide for the TPS range setting for each (The default settings for each vary). After that first 2 hours it moves to the more aggressive setting in the set range. From there every hour it adjusts as it learns until the 24 hour time has expired and the 'initial' baseline is set.

Since this is a limited amount of time there is a chance false positives may occur.

For example In the case of Source IP the default high setting is 5000. After the first 2 hours of detection it adjusts to use the range starting at the lowest setting. In the case of Source IP the default is 5 TPS. Then after adjusting to the lowest setting, it'll start aggressive and update its threshold hourly to be less aggressive by the 24 hr mark, and thus having established that 'initial' baseline.

Recommended Actions

Albeit rare if there is concern that a false positive may occur during this 24 hour period it can be dealt with by:

  1. Modifying the lower setting. For example if we use Source IP the default of 5 could be set to a higher number prior to the upgrade. 200 may a good point to use. Please remember this does loosen the policy. It is suggested that it be left at 5 and if false positives do occur to adjust it only as much as necessary to remediate the false positives.
  2. Upgrade one BIG-IP/AdvWAF, set it as the active, and monitor for 24 hours. If there are no issues then upgrade the peer.

Note: if the second method is used please be aware that High Availability (HA) will still function as designed. However, depending on the type of upgrade/update Configsync will not function until the OS versions match. K13667: BIG-IP device group members must run the same major, minor or maintenance software version
