NOTE : In case you do not find any files with larger size,

  • Try to run the  command from the top directory /.

  • Try with smaller file size, instead of 1024 to use 512.
    du --max-depth=8 | sort -n | awk '{print $1/512/512,"MB", $2}' | grep -ve "^0" -ve "e-0"

Environment

  • BIG-IQ
  • Low disk space due to /var
  • /var shows elasticsearch indices is the biggest size
  • There are many UNASSIGNED shards

Cause

UNASSIGNED shards is causing the high disk space utilization for your BIG-IQ.

Recommended Actions

You will need to delete the UNASSIGNED shards to regain your disk space.

  1. Login to the BIG-IQ Command Line.
  2. Download and install the script to clean up UNASSIGNED shards from K92678530.
  3. Once the script has been installed, run the script with the following command:
    python2.7 /shared/scripts/delete_es_indices.py --elastic_ips=localhost:9200 --delete_index --debug
  4. Review the UNASSIGNED shards with the following command:
    curl -s localhost:9200/_cat/shards?v
  5. Restart the retention daemon to clear the shards. Run command:
    tmsh restart sys service appiqconfig
  6. Review the UNASSIGNED shards from step (4).
    Important: Deleting UNASSIGNED shards will take some time. Depending on how many UNASSIGNED shards you have in your BIG-IQ system, it might take from 12 hours to 24 hours to clear the UNASSIGNED shards
