Description

  • Waiting for BIG-IQ services to become available
  • In /var/log/ltm: Waiting for Mcpd without a response. Try again...
  • GUI inaccessible

Environment

  • BIG-IQ VE 7.0
  • Reboot of BIG-IQ

Cause

Most of the time this issue is caused by GUI-related daemons not working properly.
However, sometimes source of the problem might be different, e.g:

/var/log/ltm:

notice sod[5092]: 010c0063:5: Waiting for Mcpd without a response. Try again...
notice sod[5092]: 010c0063:5: Waiting for Mcpd without a response. Try again...
notice sod[5092]: 010c0063:5: Waiting for Mcpd without a response. Try again...
notice sod[5092]: 010c0064:5: Waiting for Mcpd without a response. Happened 5 times. Reconnect.

Recommended Actions

Normally performing a following command should fix this problem:

tmsh restart /sys service tokumx tokumond restjavad webd guiserver

However, when the problem is related to e.g mcpd failure we have to restart mcpd first:

bigstart restart mcpd

Additional Information

It happens that after mcpd failure there might be another problem with SQL database:

emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base " - failed. -- 010719a2:3: PostgreSQL database error: ERROR:  role "john_smith" already exists CONTEXT:  SQL statement "CREATE ROLE "john_smith" LOGIN" PL/pgSQL function rbac_create_user(name) line 7 at EXECUTE  Unexpected Error: Loading configuration process failed.

In such scenario it's required to delete user the "john_smith" user from:  /config/bigip_user.conf
  1. Use text editor to edit  /config/bigip_user.conf
  2. Remove john_smith
  3. Save File
  4. Perform 'tmsh load sys config'
