Known Issue

Description

Users may not be able to configure Virtual Local Area Networks (VLANs) with similar and long names after a configuration reloads.

This issue occurs when all of the following conditions are met:

  • The configuration contains multiple VLANs with long names that, when truncated as interface names, have the same prefix.

    For example, the interface names for VLANs long_vlan_name_101 and long_vlan_name_102, will both be truncated and use the same prefix (long_vlan_nam~1 and long_vlan_nam~2).

    Note: This condition can also occur for shorter VLAN names that have the same leaf name but different paths (for example, /Common/vlan_name_1 and /Noncommon/vlan_name_1).
  • The configuration is saved and then reloads after you delete one or more of the affected VLANs.

Attempts to modify an affected VLAN, or create a configuration object that references an affected VLAN, will fail with an error message indicating that the truncated interface name is not present. The error message appears similar to the following example:

01070712:3: Cannot get device index for long_vlan_nam~1 in rd0 - ioctl failed: No such device - net/validation/routing.cpp, line 474

Impact

Users cannot modify an affected VLAN, or create other configuration objects which reference the affected VLANs (such as self IPs).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H479696 on the Diagnostics > Identified > Medium screen.
  • You cannot modify an affected VLAN configuration.
  • You cannot create a configuration object (for example, self IPs) that references an affected VLAN.
  • When you attempt to modify an affected VLAN, or create a configuration object that references an affected VLAN, an error message similar to the following appears:

    01070712:3: Cannot get device index for bml_WVS_vlan_~1 in rd0 - ioctl failed: No such device - net/validation/routing.cpp, line 474

Workaround

To work around this issue, you can use shorter VLAN names, or ensure that long names are unique within the first nine characters so the truncated interface names do not match each other.

However, to recover from this issue, you must restart MCP. To do so, type the following command:

bigstart restart

Impact of workaround: Restarting services will result in a brief traffic disruption.
