Known Issue

This is the result of a known issue. The secondary blades of a VIPRION system may fail to load the configuration when an administrative partition uses a default route domain that is not route domain 0 (zero). When this issue occurs, the affected secondary blades will enter a restart loop and will not be able to process traffic. The primary blade will not be affected and will correctly continue to process traffic.

This issue is triggered when a blade is rebooted or its services are restarted. For example, if your configuration is susceptible to the issue described in this Solution and your VIPRION system is comprised of four blades, should you restart one of the blades, that blade and that blade only may experience the issue described in this Solution.

Note: It is difficult to identify which specific error message will be logged to the /var/log/ltm file of the relevant blade should this issue occur. The issue consists of the blade attempting to load a configuration object using an incorrect route domain. The most likely way to identify whether you are affected by this issue is looking for an error message that details a route domain formatted IP address for an object that lives in the default route domain or a different route domain. The error message may appear similar to the following example:

err mcpd[4027]: 01070734:3: Configuration error: Configuration from primary failed validation: 01020036:3: The requested monitor instance (my_icmp 10.0.0.10%50 0 2) was not found.

F5 Product Development is tracking this issue as ID 351308.

Workaround

You can work around this issue by ensuring that the Partition Default Route Domain setting of each administrative partition remains set to the default value of route domain 0. All objects in the administrative partition that are part of a non-default route domain will require the route domain to be specified on a per object basis. For example, to configure a self IP address in route domain 100, you will have to append %100 to the IP address.

Note: Implementing this change may require that you remove and then re-add some of the configuration objects that live in the affected administrative partition(s).
