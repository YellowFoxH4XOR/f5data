Known Issue

Description

VIPRION secondary blades may go offline when referencing an external monitor. This issue occurs when one of the following conditions is met:

  • You have created an external monitor that references an executable from the /usr/share/monitors directory path.
  • In a version prior to BIG-IP 10.1.0, you created an external monitor that references an executable from the /usr/bin/monitors/builtins directory path; you then upgraded to BIG-IP 10.1.0 or later.

Starting in BIG-IP 10.1.0, the /usr directory is read-only. Therefore, external monitors should reference executables in the /config/monitors directory.

Impact

The secondary blades may go offline and become unavailable for traffic processing.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system may post an error message in the /var/log/ltm file. The message appears similar to the following example:

    0107094e:0: File cache: fatal error (can't create backup file for (/usr/bin/monitors/builtins/<Monitor_Executable_Filename>), Read-only file system) (FileCache.cpp:1523)

    For example, if the external monitor file name is SYSLOG_monitor, the error message appears similar to the following example:

    0107094e:0: File cache: fatal error (can't create backup file for (/usr/bin/monitors/builtins/SYSLOG_monitor), Read-only file system) (FileCache.cpp:1523)
  • The secondary blades go offline and the system daemons restart continuously and log messages to the /var/log/ltm file. The messages appear similar to the following example:

Workaround

To work around this issue, you can relocate the external monitor's executable to the /config/monitors directory, delete the affected external monitor, and re-create the external monitor using the executable in the /config/monitors directory. To do so, perform one of the following two procedures:

Impact of workaround: None.

BIG-IP 11.x

  1. Log in to the command line of the VIPRION system using the management IP address or the primary blade IP address.
  2. To copy the affected external monitor's executable to the /config/monitors directory, use the following command syntax:

    cp -a /usr/share/monitors/<Executable_Filename> /config/monitors/.

    For example, if the affected external monitor executable is /usr/share/monitors/Eg_External_Monitor, you would type the following command:

    cp -a /usr/share/monitors/Eg_External_Monitor /config/monitors/.
  3. Log in to the BIG-IP Configuration utility.
  4. Click the name of the product module to which the external monitor is configured.

    For example:

    Local Traffic
  5. Click Monitors.
  6. Click Create.
  7. From the Type menu, select External.
  8. Define the new external monitor using the same settings as the affected external monitor, and select the appropriate executable from the External Program menu.

    Note: The executable appears in the External Program menu once it has been copied to the /config/monitors directory.
  9. Click Finished.
  10. Replace all references on the pool resources that use the affected external monitor to the new external monitor created in Step 5.
  11. Select the affected external monitor.
  12. Click Delete.

    A couple of minutes after completing this procedure, the secondary blades receiving the new configuration will slowly re-join the cluster and be online.

BIG-IP 10.1.0 through 10.2.x

  1. Log in to the command line of the VIPRION system using the management IP address or the primary blade IP address.
  2. To copy the affected external monitor's executable to the /config/monitors directory, use the following command syntax:

    cp -a /usr/share/monitors/<Executable_Filename> /config/monitors/.

    For example, if the affected external monitor executable is /usr/share/monitors/Eg_External_Monitor, you would type the following command:

    cp -a /usr/share/monitors/Eg_External_Monitor /config/monitors/.
  3. Log in to the BIG-IP Configuration utility.
  4. Click the name of the product module to which the external monitor is configured.

    For example:

    Local Traffic
  5. Click Monitors.
  6. Click Create.
  7. From the Type menu, select External.
  8. Define the new external monitor using the same settings as the affected external monitor, and enter /config/monitors in the External Program field.
  9. Click Finished.
  10. Replace all references on the pool resources that use the affected external monitor to the new external monitor created in Step 5.
  11. Select the affected external monitor.
  12. Click Delete.

    A couple of minutes after completing this procedure, the secondary blades receiving the new configuration will slowly re-join the cluster and be online.
