Known Issue

This is the result of a known issue. When you create a self-signed client root certificate on the FirePass controller after January 19, 2008, if 30 years is chosen for the expiration of the certificate (the valid to field of the certificate), the certificate will be created with an incorrect expiration date due to the Year 2038 Problem.  Because the data structure that stores time past January 1, 1970 will reach its maximum value and roll over, a certificate intended to have an expiration date beyond January 19, 2038 will instead be created with the "two's complement" year (1902 instead of 2038; 1903 for 2039, and so on).

A client root server certificate enables client certificate-based authentication between the FirePass controller and its remote access clients. The client root certificate contains a valid to field, which indicates the date and time at which the certificate will expire. When a client root certificate with an expiration date beyond January 19, 2038 is created by clicking the Self-Signed Certificate link on the Device Management: Security: Certificates page, the page that is displayed once the certificate is created will appear similar to the following example:

The expiration date listed will be incorrect. In the above example, the correct expiration year for the certificate is February of 2038.

The page that is displayed once the certificate is saved will appear similar to the following example:

The date listed will be incorrect. In the above example, the correct expiration year for the certificate is February of 2058.

Clicking the Details link in the row belonging to the certificate on the Device Management: Security: Certificates page will display the certificate, including the period over which it is valid.

In the following example, the incorrect year of 1902 is visible:

        Signature Algorithm: sha1WithRSAEncryption
        Issuer: C=US, ST=CA, L=SJ, O=F5, OU=IT, CN=fpca.siteconfig.com/emailAddress=admin@siteconfig.com
        Validity
            Not Before: Oct 13 04:13:01 2008 GMT
            Not After : Oct 13 21:44:45 1902 GMT

The functionality of the client root certificate is impaired by this issue, and the certificate will not correctly authenticate the client certificates it issued. Because the client root certificate's expiration date is earlier than its start date (e.g. 1902 and 2008, respectively), there is no valid date range into which the client certificates can fall, during the SSL handshake between the browser and the FirePass controller. As a result, the client certificate is deemed expired by the SSL web service on the FirePass controller. 

Users connecting to the FirePass controller with Internet Explorer will typically receive the following message:

This page cannot be displayed

Users connecting with Firefox may receive a pop-up message that appears similar to the following example:

Could not extablish an encrypted connection with <name of FirePass controller> because your certificate is expired. 

Since the issue is not the client certificate from the browser, but rather the client root certificate, all users' client certificates will be treated as expired for purposes of the SSL handshake. Users whose browsers present the client certificate automatically or users who choose to send a client certificate from a pop-up window will not be able to reach the login page using SSL (HTTPS URLs).

Additionally, if you are using the client root certificate to issue client certificates from the FirePass controller using the built-in PKI (as opposed to an external certificate authority), refer to K8451: Self-signed client certificates with expirations past 1/19/2038 corrupt client certificate database.

F5 Product Development is tracking this issue as ID 266973 (formerly CR94775).

Workaround

To eliminate the symptom of a user with a client certificate being unable to reach the login page with an SSL connection, the client certificate can be removed from the browser's certificate store, or the browser can be instructed not to present the client certificate automatically. Consult the documentation for your browser in order to remove the client certificate or change the configuration to present the client certificate manually, so that its use can be declined by the user. Eliminating the user's certificate from authentication may require reconfiguration of pre-login sequences or protected configurations on the FirePass controlller.

For a permanent resolution, delete the client root certificate from the FirePass controller and create a new self-signed client root certificate that expires in a shorter time period, such as 10 or 5 years.

Important: When you delete a self-signed client root certificate from the FirePass controller, all client certificates issued by that client root certificate will no longer function. Client certificates will have to be reissued using the new client root certificate.
