Known Issue

Custom bidirectional persistence entries are not updated to session timeout.

This issue occurs when all of the following conditions are met:

  • You create a custom Session Initiation Protocol (SIP) persistence iRule that uses the SIP::persist bidirectional command, and you assign the iRule to a SIP virtual server.
  • You associate a siprouter profile and a sipsession profile with the SIP virtual server.
  • Your system receives a successful SIP response message.

Impact

Persistence prematurely times out.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Your BIG-IP system creates custom bidirectional persistence entries using the transaction timeout when processing requests but does not update the session timeout when it receives a successful response.

Workaround

To work around this issue, you can set the transaction timeout in the siprouter profile to the session timeout value from the sipsession profile. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Message Routing > SIP.
  3. Click the custom sipsession profile.
  4. Note the Persist Timeout (seconds) value.
  5. To return to the previous page, click Profiles : Message Routing : SIP above Properties.
  6. Click Router Profiles.
  7. Click the custom siprouter profile.
  8. For Transaction timeout (seconds), type the value you noted in step 4.
  9. Click Update.
