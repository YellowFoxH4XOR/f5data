Topic

You should consider using these procedures under the following condition:

  • You want to use the BIG-IP system to load balance connection requests to SSH File Transfer Protocol (SFTP) servers.

Note: For information about File Transfer Protocol Secure (FTPS) load balancing, refer to K9347: Configuring passthrough FTPS load balancing.
Note: For information about File Transfer Protocol (FTP) load balancing, refer to K8021: Configuring the BIG-IP LTM system to allow outbound FTP sessions.

Description

This article covers how to configure the BIG-IP system to load balance connection requests across multiple SFTP servers.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the BIG-IP system.
  • Your SFTP servers are available and accessible from the BIG-IP system.

Procedures

To watch a video demo of these procedures, go to  Create a load-balanced SFTP virtual server using the Configuration utility.

  • Creating the SFTP pool tcp_half_open monitor
  • Creating a custom SFTP pool external monitor (optional)
  • Creating a new monitor profile using the external monitor files (optional)
  • Creating the SFTP load balance pool
  • Creating the SFTP source address persistence profile
  • Creating the SFTP virtual server

Creating the SFTP pool tcp_half_open monitor

The following procedure covers creating a health monitor to monitor the SFTP servers TCP port availability.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. For Name, enter a name for the monitor.
  5. Optional: For Description, enter a description for the monitor.
  6. For the Parent Monitor, select tcp_half_open.
  7. For Interval, enter the the frequency, in seconds, to poll the SFTP servers.
  8. For Timeout, enter the maximum number of seconds to wait to receive a response from the SFTP servers, from the monitor requests. 
  9. For Transparent, leave the default setting No.
  10. Select Finished.

Creating a custom SFTP pool external monitor (optional)

The following procedure covers creating an external health monitor to monitor the SFTP server's logon availability. After performing the procedure, you can apply this monitor to the pool of SFTP servers.

Note: The expect command is available in BIG-IP 12.0.0 and later. F5 recommends that you understand the expect command before you implement the following expect script example.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Using a text editor, create the following two text files on your local device:

    sftp_expect_script
    sftp_monitor.txt

    Note: F5 recommends that you use either the vi or pico text editor on the BIG-IP or Linux system, or for a local Windows device, use Notepad to prevent hidden editor format characters from corrupting the file content.

    You will later upload these files to your BIG-IP system.

  2. In the text file sftp_expect_script, enter the following example expect script stanza:

    #!/usr/bin/expect
    set node_ip [lindex $argv 0];
    set user_name [lindex $argv 1];
    set user_password [lindex $argv 2];
    set result 1
    set timeout 5
    spawn sftp -c aes256-ctr $user_name@$node_ip
    expect {
    "$user_name@$node_ip's password:" {
    send "$user_password\r"
    expect "Connected to $node_ip." {set result 0 }
    send "bye\r"
    }
    timeout {
    set result 1
    }
    }
    exit $result

    Note: The $user_name and $user_password values are supplied in the arguments section of the custom monitor that is covered in the Creating a new monitor profile using the external monitor files section of this article.

    Important: Manually verify, and when required, modify each of the expect script expect and send commands for your SFTP servers before you deploy the monitor.

    Note: To test the expect script before you deploy it as a monitor, you can use the following syntax on the BIG-IP system command line:

    expect -f sftp_expect_script <sftp server ip address> <username> <user password>

    Note: In case the response from the "expect" command is a continuous "y", this means that the system is trying to pass the RSA ID warning of the SFTP server, but it needs the entire word "yes" to continue. In order to allow the "expect" command to work properly, it is best to log in to the sftp server first using the command in step 3, just below, and then, once you accept the RSA ID of all SFTP servers involved, you can return to the expect script to make sure it works properly

  3. For troubleshooting, manually access your SFTP servers from the command line by launching an SFTP session using the following syntax:

    sftp <username>@<sftp server ip address>

  4. Note the text of the prompts as you supply the user password and bye/exit command.
  5. Ensure that the prompts in the expect script match the SFTP server prompts.
  6. Save the sftp_expect_script file.
  7. In the text file sftp_monitor.txt, enter the following example monitor script stanza:

    #!/bin/sh
    # these arguments supplied automatically for all external pingers:
    # $1 = IP (::ffff:nnn.nnn.nnn.nnn notation or hostname)
    # $2 = Port
    # $3 = Username
    # $4 = User Password
    # $MONITOR_NAME = name of the monitor
    # Name of the pidfile
    pidfile="/var/run/$MONITOR_NAME.$1..$2.pid"
    # Send signal to the process group to kill our former self and any children
    # as external monitors are run with SIGHUP blocked
    if [ -f $pidfile ]
    then
       kill -9 -`cat $pidfile` > /dev/null 2>&1
    fi
    echo "$$" > $pidfile
    # Remove the IPv6/IPv4 compatibility prefix
    node_ip=`echo $1 | sed 's/::ffff://'`
    # Using the nc utility to get data from the server.
    # Check that the SFTP ls functions.
    #If the expect script received the password prompt it will send a ctrl-d and exit with the word "up".
    /usr/bin/expect -f /config/monitors/sftp_expect_script ${node_ip} $3 $4 > /dev/null >& diag && echo "up"
    # Remove the pidfile
    rm -f $pidfile

  8. Upload the first file sftp_expect_script to your BIG-IP system, placing the file in the /config/monitors directory.

    Important: The sftp_expect script does not automatically synchronize to your BIG-IP devices when you run a configuration synchronization (ConfigSync).

  9. Log in to the command line of the BIG-IP system.
  10. Set the file permissions for the sftp_expect_script using the following command:

    chmod 755 /config/monitors/sftp_expect_script

  11. Log in to the Configuration utility.
  12. Go to System > File Management > External Monitor Program File List.
  13. Select Import.
  14. For Name, enter sftp_external_monitor.
  15. For File Name, select Choose File.
  16. Ensure that Create New is selected (default).
  17. Select the sftp_monitor.txt file that you previously created.
  18. Select Import.

Creating a new monitor profile using the external monitor files (optional)

The following procedure covers creating a health monitor profile to monitor the SFTP servers using the previously created external monitor files.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. For Name, enter sftp_monitor.
  5. Optional: For Description, enter a description for the monitor.
  6. For Type, select External.
  7. For Interval, enter the frequency, in seconds, to poll the SFTP servers.

    Note: In a high availability (HA) configuration, both BIG-IP devices send health checks at the configured interval to your SFTP servers.

  8. For Timeout, enter the maximum number of seconds to wait to receive a response from the SFTP servers, from the monitor requests.

    Important: This monitor may not be suitable for deployments where you have a large amount of SFTP servers monitored across the BIG-IP configuration. The example expect script has a spawn and connect timeout of 5 seconds (set timeout 5). When you use the external monitor script, F5 recommends that you set the monitor Interval value greater than the expect script timeout, and the Timeout value of the monitor at 3x Interval + 1. For example if Interval is set to 15, then Timeout should be set to 46.

  9. For External Program, select the sftp_external_monitor that you previously created.
  10. For Arguments, enter the username followed by a space character and the user password.

    Important: The Arguments are stored in clear text. Ensure that the user account that you use for monitoring the SFTP servers has limited access rights. The example expect script requires only a successful logon and no access to files.

  11. Select Finished.

Creating the SFTP load balance pool

The following procedure covers creating an SFTP load balance pool, as well as additional options that you can use when configuring pools.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools.
  3. Select Create.
  4. For Configuration, select Advanced.
  5. For Name, enter the name of the pool.
  6. Optional: For Description, enter a description for the pool.
  7. For Health Monitors, in the Available list, select the monitor you created in the previous procedure and move it to the Active list.
  8. If your SFTP servers maintain state across the servers, for Action On Service Down, select Reselect.

    If you are unsure if your servers maintain state across the servers, or the SFTP servers do not maintain state, select the default, None.

  9. Under Resources, for Load Balancing, select the preferred method.

    Note: F5 recommends that you use Least Connections (member).

  10. Optional: Depending on your configuration, select the appropriate Priority Group Activation for your environment.

    Note: For more information about Priority Group Activation, refer to K7065: Configuring the BIG-IP system to use alternate servers when pool members are unavailable.

  11. To add new pool members (nodes not previously configured), select New Node.

    Note: To use previously configured nodes, select Node List and skip to step 15.

  12. For Node Name, enter a name for the new node.
  13. For Address, enter the IP address of the new node.
  14. For Service Port, enter 22 or select SSH.
  15. For Priority, when configured for Priority Group activation, enter the priority group numeric value.

    Note: The higher the number, the higher the priority.

  16. Select Add.

Creating the SFTP source address persistence profile

The following procedure covers creating a persistence profile for the SFTP virtual server load balanced connections.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Persistence.
  3. Select Create.
  4. For Name, enter a name for the persistence profile.
  5. For Persistence Type, select Source Address Affinity.
  6. Select the Custom check box.
  7. If you want persistence records mirrored in an HA BIG-IP pair, select the Mirror Persistence check box.

    Note: For more information about persistence mirroring, refer to K84303332: Overview of connection and persistence mirroring (13.x - 14.x).

  8. For Hash Algorithm, leave the default setting.
  9. For Timeout, leave the default setting of 180 seconds, unless your environment requires a different timeout value for idle persisted connections.
  10. Select Finished.

Creating the SFTP virtual server

The following procedure covers creating a load balanced SFTP virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the new virtual server.
  5. Optional: For Description, enter a description for the virtual server.
  6. For Type, select Performance (Layer 4).
  7. For Destination Address/Mask, enter the virtual server IP address.
  8. For Service Port, enter 22 or select SSH.
  9. For Configuration, select Advanced.
  10. For Protocol, leave the default setting, TCP.
  11. For Protocol Profile (Client) and Protocol Profile (Server), select the appropriate TCP profile for your environment.
  12. For VLAN and Tunnel Traffic, select the appropriate VLAN or Tunnels, or leave at the default setting, All VLANs and Tunnels.
  13. For Source Address Translation, select Auto Map.

    Note: You must use Source Address Translation only when the SFTP servers do not use the BIG-IP system as the outbound default gateway, or when the SFTP servers are configured with multiple routes.

  14. Optional: For Connection Mirroring, if you want to mirror the virtual server SFTP connection records to an HA BIG-IP pair, select the check box.

    Note: For more information about connection mirroring, refer to K84303332: Overview of connection and persistence mirroring (13.x - 14.x).

  15. For Address Translation and Port Translation, leave the default setting, Enabled.
  16. For Default Pool, select the name of the pool you created in the previous procedure.
  17. For Default Persistence Profile, select the name of the persistence profile that you created in the previous procedure.
  18. Select Finished.

Important: F5 recommends that you do not use the OneConnect feature for SFTP load balanced connections. For more information, refer to: K7208: Overview of the OneConnect profile.
