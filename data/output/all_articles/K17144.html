Known Issue

The Traffic Management Microkernel (TMM) may leak memory when the BIG-IP system is deployed in an nPath routing environment.

This issue occurs when all of the following conditions are met:

  • You deploy the BIG-IP system in an nPath routing environment.
  • You configure a pool on the BIG-IP system that consists of servers that route responses directly back to clients.
  • The pool uses one of the following IP encapsulation methods:
    • gre
    • ipip
  • You associate the pool with a FastL4 virtual server.
  • The FastL4 virtual server processes traffic.

Impact

TMM memory may eventually be exhausted and may result in the system producing a core file. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Over time, system performance is degraded and the system may eventually stop responding or reboot due to memory exhaustion.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • If configured as a high-availability pair, the BIG-IP system fails over to the standby system.
