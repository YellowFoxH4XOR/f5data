Description

vCMP guest is in an 'INOPERATIVE' state on the secondary slot with the following error and clusters restart loop after the upgrade.

  • Messages similar to the following are logged in /var/log/ltm file on the primary blade when clusterd restarts on a secondary blade:

notice clusterd[3676]: 013a0006:5: Hello from slot 1.
notice clusterd[3676]: 013a0006:5: Informing MCP about slot ID 1 member status.
notice clusterd[3676]: 013a0006:5: Goodbye from slot 1.

  • Messages similar to the following are logged in /var/log/ltm file on the secondary blade as clusterd daemon keep restaring: 
warning clusterd[21034]: 013a0005:4: Clusterd using /VERSION for SW specification
info clusterd[21034]: 013a0023:6: Blade 2: No info received from slot: Starting up
notice mcpd[4801]: 01071d15:5: adjust_admin_ips: old_mbrAddrs of slot: 2: <address>/<mask>
notice mcpd[4801]: 01071d15:5: adjust_admin_ips: mbrAddrs of slot: 2: <address>/<mask>
notice mcpd[4801]: 01071d15:5: set_admin_ip: called with addr: <address> mask: <mask> oldAddr: :: oldMask: ::
err mcpd[4801]: 0107146f:3: Self-device state mirroring address cannot reference the non-existent Self IP (<address>); Create it in the /Common folder first.
err clusterd[21034]: 013a0004:3: result {
err clusterd[21034]: 013a0004:3:     result.code 17241199
err clusterd[21034]: 013a0004:3:     result.message 0107146f:3: Self-device state mirroring address cannot reference the non-existent Self IP (<address>); Create it in the /Common folder first.
err clusterd[21034]: 013a0004:3: }
err clusterd[21034]: 013a0004:3:
notice clusterd[21034]: 013a0006:5: Disconnecting from mcpd.
info clusterd[21034]: 013a0007:6: clusterd stopping...
notice clusterd[21034]: 013a0015:5: Blade 2 quorum state increasing from INITIAL to SHUTDOWN.

Environment

  • VIPRION with vCMP 
  • After re-activating the license on the host and upgrading the vCMP guest, you can observe the following status on the secondary slot on the vCMP guest 
show /sys cluster all-properties
  --------------------------------------------------------------------------------------------------------------------
  | Sys::Cluster Members
  | ID  Address               Availability     State     Licensed  HA               Clusterd      Reason
  --------------------------------------------------------------------------------------------------------------------
    1   <address>          available        enabled   true      standby          running       Run
    2   <address>          unknown          enabled   false     unknown          shutdown      ShutDown: Starting up

Cause

Bug ID 707013: vCMP host secondary member's cluster.conf file may be replaced by that of vCMP guest

Recommended Actions

1. On the vCMP Host, copy the file /shared/db/cluster.conf from the primary to secondary cluster member. For secondary blade's slot, use a command similar to the following:
Note: Implementing the workaround does not prevent the issue from recurring. An upgrade to an unaffected version is recommended.

scp /shared/db/cluster.conf slot<slot number>:/shared/db/cluster.conf

2.  Use the following command to SSH into a specific slot and Reboot the secondary slot. 
Note: This reboots only a specific slot, so if you want to reboot all blades you can use this command 'clsh reboot'.

ssh <slot number>
reboot
 
Example:
[root@vguest1:/S1-green-P:Active:Standalone] config # ssh slot2 
[root@vguest1:/S2-green-P] config # reboot
