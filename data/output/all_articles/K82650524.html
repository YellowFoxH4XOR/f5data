Description

After modifying the configuration related to monitors on one BIG-IP peer and synchronizing the configuration, the other peer generates email alerts of the status of the monitors that were changed.

Environment

  • Active and Standby BIG-IPs configured to send email alerts when monitor events are logged to /var/log/ltm log

Cause

This is expected behavior. When synchronizing configurations between systems, if monitors are changed, they are modified when synchronized, resulting in the monitor process restarting for the affected node/pool.

Example log event on standby BIG-IP after sync from Active noting monitor status UP:

notice mcpd[6409]: 01070727:5: Pool /Common/http-pool member /Common/192.138.1.2:80 monitor status up. [ was up for 0hr:1min:50sec ]

Recommended Actions

No action is required, as this is expected behavior. If you want to modify the alerting, consider adjusting the email alert settings or filtering the specific events that trigger alerts.
