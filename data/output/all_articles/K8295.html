Known Issue

This is the result of a known issue. The boot order for the BIG-IP 1500 platform's host motherboard is incorrect.

The BIG-IP 1500, 3400, 6400, 6800, 8400, and 8800 platforms contain a host motherboard that is used by the BIG-IP system, the switchboard, and the SCCP motherboard used for BIG-IP management.

The host motherboard contains a separate BIOS that specifies which device is used when booting the system. You can control the boot order through the SCCP. For example, you could specify the PXE boot when upgrading or installing the operating system.

In a small percentage of 1500 platforms, the hard disk boot option is incorrectly positioned in the boot order. As a result, the SCCP utility will ignore the PXE server boot option.

Note: This behavior affects less than 0.01 percent of shipped 1500 platforms.

Workaround

You can work around this issue and allow a PXE boot to occur. To do so, perform the following procedure:

  1. Connect to the BIG-IP 1500 serial port with a terminal emulator.

    Note: For more information about connecting to a serial port with a terminal emulator, refer to K7683: Connecting a serial terminal to a BIG-IP system.
  2. Log in to the command line.
  3. Connect to the SCCP command menu by simultaneously typing the ESC, Shift, and 9 key, as follows:

    ESC (

    The following command menu displays:

    [hostconsh] Command Menu:
    1 --- Connect to Host subsystem console
    2 --- Select Host subsystem boot mode: boot from local drive
    3 --- Select Host subsystem boot mode: netboot from SCCP
    4 --- Select Host subsystem boot mode: netboot from external server
    5 --- Reboot Host subsystem (sends reboot command)
    6 --- Halt Host subsystem (sends halt command)
    7 --- Reset Host subsystem (issues hardware reset--USE WITH CARE!)
    8 --- Reboot SCCP subsystem (issues hardware reset--USE WITH CARE!)
    9 --- Halt SCCP subsystem (issues hardware shutdown--USE WITH CARE!)
    B --- SCCP baud rate configurator
    L --- SCCP login
    N --- SCCP network configurator
  4. To reset the Host subsystem, type 7.

    Note: This step issues a hardware reset; use with care.
  5. To proceed with the Host subsystem reset, type Y.
  6. To connect to the Host subsystem console, type 1.
  7. When prompted, enter the CMOS SETUP by typing the TAB key.
  8. Navigate to the EXIT menu of the CMOS SETUP by using the ARROW keys.
  9. Select LOAD OPTIMAL DEFAULTS.
  10. Select Save and EXIT.

    The Host should now boot to the management port if so directed.

Follow the Netboot procedure specified in the release notes for the version you want to upgrade to or install.
