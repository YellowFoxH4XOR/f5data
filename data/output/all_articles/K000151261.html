Description

Broadcoms Symantec VIP solution provides modern authentication management including Two-Factor Authentication (2FA) and Oauth 2.0 with Open ID federation. This article discusses how APM can integrate with Symantec VIP to utilize VIPs OAuth/Open ID and 2FA capabilities

 

Environment

Symantec VIP

BIGIP version 17.1.x or higher with APM provisioned

 

Prerequisites

Before completing this task on APM, ensure Symantec VIP is configured for 2FA and as an OAuth Authorization Server (AS). You will need to get the generated Client ID and Shared Secret.

 

Recommended Actions

1A CONFIGURE PROVIDER AUTOMATED STEPS

This method is much simpler and less error prone than manually configuring the various objects but if you do not have the OpenID configuration uri then you can use the manual configuration method

  1. Login to the Bigip's web interface using your admin credentials
  2. Configure the Symantec VIP Provider
    1. Navigate to Access -> Federation -> OAuth Client / Resource Server -> Provider
    2. Click Create
      1. Name - Name the provider whatever you want
      2. Type - Custom
      3. Trusted Certificate Authorities - select the ca-bundle.crt
      4. Use Auto JWT - select this option to auto create the jwt
      5. OpenID URI - you'll need the app id. Specify the uri and click Discover. This will auto populate all the fields and generate the JWT and associated JWK configurations
      7. Save the configuration

1B CONFIGURE PROVIDER MANUAL STEPS

  1.  Login to the Bigip's web interface using your admin credentials
  2. Create a JSON Web Key
    1. Navigate to Access -> Federation -> JSON Web Token -> Key Configuration
    2. Click Create
      1. Name - Name it whatever you want, here it's named it symantec_jwk
      2. ID - insert the client id generated on Symantec VIP as the AS
      3. Shared Secret - insert the shared secret generated on Symantec VIP as the AS
    3. Click Save
  3. Create a JSON Web Token (utilizes the created jwk configuration)
    1. Navigate to Access -> Federation -> JSON Web Token -> Token Configuration
    2. Click Create
      1. Name - Name it whatever you want
      2. Issuer - This is specific to your Symantec VIP deployment and will include the ID of the instance
      3. Signing Algorithms - ensure the Allowed algorithms contains those appropriate for your Symantec VIP deployment.
      4. Keys (JWK) - Ensure the configuration in step 2
    3. Click Save
  4. Create the Symantec VIP Provider
    1. Navigate to Access -> Federation -> OAuth Client / Resource Server -> Provider
    2. Click Create
      1. Name - Name the provider whatever you want
      2. Type - Custom
      3. Trusted Certificate Authorities - select the ca-bundle.crt
      4. Use Auto JWT - we've already created the JWK and JWT configs so no need to select this if manually creating
      5. Token Configuration (JWT) - drop down and select the created JWT
      6. For the following URI's you'll need your App ID from Symantec VIP to populate these fields
      8. Save the configuration

2 CONFIGURE A DNS RESOLVER

This is used when it's time to retrieve the token. The token retrieval is performed between APM and AS. So this configuration needs to define a server that can resolve the OAuth AS name

  1. Navigate to Network -> DNS Resolvers -> DNS Resolvers List
  2. Click Create
    1. Name - Provide a name and everything else can remain at defaults
    2. click Finished
    3. Click the newly created Resolver
    4. Click the Forward Zones tab
    5. Click Add
      1. Name - put a dot "." (without quotes)
      2. Address - specify the IP address of a DNS server that can resolve the Symantec VIPs host name
      3. Click Add
      4. Click Finished
    7. Click Finished

 

3 CONFIGURE AN OAUTH SERVER

This configuration will determine if we can act as a client, a resource server, or both and defines the client credentials used during the oauth flow

  1. Navigate to Access -> Federation -> OAuth Client / Resource Server > OAuth Server
  2. Click Create
    1. Name - Name the server
    2. Mode - select Client
    3. DNS Resolver - select the DNS Resolver created above
    4. Client Id and Client Secret - populate these fields with the information provided by Symantec VIP
    5. Client's ServerSSL Profile Name - select serverssl
    6. Client JWE Key - Select the automatically generated jwk (it has auto_jwk_ followed by the name of the Provider)
  3. Click Finished

4 CONFIGURE REQUESTS

Requests allows APM to tailor to different server needs in how they want to receive the data

 

Create a Token Request

  1. Navigate to Access -> Federation -> OAuth Client / Resource Server -> Request
  2. Click Create
    1. Name - Name it whatever you want
    2. Type - token-request
    4. Click Finished

Create a Token Refresh Request

  1. Navigate to Access -> Federation -> OAuth Client / Resource Server -> Request
  2. Click Create
    1. Name - Name it whatever you want
    2. Type - token-refresh-request
    4. Click Finished

 

5 CONFIGURE THE IRULE

Symantec VIP requires a jwt token to be sent in a request before performing OAuth operations. This iRule will generate that request along with the necessary parameters. Note the JWT_CREATE agent_id. This needs to match in the policy's iRule Event configured later

  1. Navigate to Local Traffic -> iRules -> iRules List
  2. Click Create
    1. Name - Name the iRule whatever you want
    2. Definition - Insert the following for the following code
    4. Click Finished
    5. when ACCESS_POLICY_AGENT_EVENT {
    if { [ACCESS::policy agent_id] eq "JWT_CREATE" } {
        set symantec_uname [ACCESS::session data get "session.logon.last.username"]
        # Inline logic for creating JWT
        set header "{\"alg\":\"HS512\",\"typ\":\"JWT\"}"
        set iat [expr [clock seconds]]
        set exp [expr {[clock seconds] + 900}]
        set client_id "<Client ID>"
        set redirect_uri "https://[ACCESS::session data get session.server.network.name]/oauth/client/redirect"
        set payload "{\"iat\":${iat},\"exp\":${exp},\"aud\":\"${client_id}\",\"sub\":\"${symantec_uname}\"}"
        set jwt_symantec [ACCESS::oauth sign -header $header -payload $payload -alg HS512 -key "/Common/symantec_jwk"]
        ACCESS::session data set session.custom.jwt_symantec $jwt_symantec
    }
}
 
when ACCESS_PER_REQUEST_AGENT_EVENT {
    if { [ACCESS::perflow get perflow.irule_agent_id] eq "JWT_CREATE" } {
        set symantec_uname [ACCESS::session data get "session.logon.last.username"]
 
        set header "{\"alg\":\"HS512\",\"typ\":\"JWT\"}"
        set iat [expr [clock seconds]]
        set exp [expr {[clock seconds] + 900}]
        set client_id "<Client ID>"
 
        set redirect_uri "https://[ACCESS::session data get session.server.network.name]/oauth/client/redirect"
        se payload "{\"iat\":${iat},\"exp\":${exp},\"aud\":\"${client_id}\",\"sub\":\"${symantc_uname}\"}"
 
        set jwt_symantec [ACCESS::oauth sign -header $header -payload $payload -alg HS512 -key "/Common/symantec_jwk"]
        ACCESS::perflow set perflow.custom $jwt_symantec
    }
}

6 CREATE THE APM POLICY

A Per-Session Policy or a Per-Request Policy can be used.

Creating a Per-Session Policy

  1. Navigate to Access -> Profiles / Policies -> Access Profiles (Per-Session Policies)
  2. Click Create
    1. Name - name the policy whatever you want
    2. Profile Type - select all
    3. Languages - Specify the languages the policy needs to support
    4. The remaining fields can be left at defaults
    5. Click Finished
  3. Scroll to the newly created policy and click Edit to the right of the access policy name. This brings you into the Visual Policy Editor (VPE) in a new tab
    1. iRule Event should have the ID matching the ID in the iRule above
    2. The OAuth Client will use the requests and oauth server we created earlier

7 CREATE THE VIRTUAL SERVER

This will be where users go to access the configuration

  1. Navigate to Local Traffic -> Virtual Servers
  2. Click Create
    1. General Properties
      1. Define the name of the virtual
      2. Define the Destination IP that users will use to access this virtual
      3. Define the port (443)
    2. Configuration (basic)
      1. Define the HTTP profile (client) by specifying http in the drop down (the server will use this same profile)
      2. Define a client ssl profile containing trusted certs
    3. Content Rewrite (optional)
      1. this is only needed if the access policy contains a portal access resource
    4. Access Policy
      1. Select the Access Policy created previously
      2. If the policy contains any connectivity type of resources (vdi, network access, app tunnels, etc..) you'll need to specify a connectivity profile
    5. Resources
      1. Select the iRule containing the iRule Event ID created earlier
      2. If the end result of the access policy no assigned resources, you will need a pool
  3. Click Finished
