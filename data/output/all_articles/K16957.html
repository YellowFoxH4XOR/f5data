Known Issue

TMM may restart and produce a core file when a BIG-IP APM profile accesses a closed HTTP connection.

This issue occurs when all of the following conditions are met:

  • The BIG-IP virtual server that is processing traffic is configured with an HTTP profile and an Access Profile.

    Note: This issue is triggered by a race condition where the BIG-IP APM profile action is run after the HTTP profile has finished handling the request.

Impact

The BIG-IP system is unable to process traffic while the TMM process restarts, and the system fails over if it is configured for high-availability.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access the BIG-IP APM system or experience a traffic disruption.
  • The TMM process generates a core file to the /shared/core directory.
  • The system generates a SIGSEGV fault, and in the /var/log/tmm file, you may observe messages similar to the following example:

    notice session_process_pending_event_callback ERROR: could not send callback to <Client_side_ip_address>:50441 - <vip_ip_address>:443 ERR_NOT_FOUND
    notice session_process_pending_event_callback ERROR: could not send callback to <Client_side_ip_address>:52541 - <vip_ip_address>:443 ERR_NOT_FOUND
    notice ** SIGSEGV **
    <snip> notice RIP=0x8cc872
