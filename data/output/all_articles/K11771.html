Known Issue

This is the result of a known issue. If you configure multiple volumes to use the same metadata share, and you defined that metadata share as critical, using the metadata critical command, the ARX system may log numerous messages containing the string SSRM-0-ERR-SSRM_TOO_MANY_VSRECS to the ARX syslog.

For example:

ldb001:1-1-ACM-3805:SSRM-0-ERR-SSRM_TOO_MANY_VSRECS:: Share meta-only:192.168.0.25:/vol/01/ has multiple VolStorage records
[<id:1b2,ns:1,vo:30,sh:dd,fi:5,ii:1,fl:4,ip:192.168.0.25>]

These log messages are benign and you can safely ignore them.

F5 Product Development tracked this issue as ID 39386 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in ARX versions 5.0.6 HF12 (build 11780) and 5.1.5 HF7 (build 11982). Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 39386.
