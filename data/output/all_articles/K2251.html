Topic

Following are the different options to gain administrative access to nodes through BIG-IP without using NAT:

  • Virtual servers
  • Forwarding virtual servers
  • Forwarding Pools
  • ICMP and other Protocols
  • VLANs
  • IP forwarding

Virtual servers

To configure virtual servers to allow administrative access from SSH to one node through BIG-IP:

  • Create a pool with the node in it, using TCP port 22
  • Create a virtual server, using an available IP, on port 22

For instructions about how to create pools and virtual servers, refer to the BIG-IP documentation.


Forwarding virtual servers

Forwarding virtual servers work like IP forwarding, but only expose selected servers and/or ports. You can create a forwarding virtual server for an address (or network) in a VLAN, allowing access from an alternate VLAN.

For example, in a configuration with two VLANs, one named external and the other named internal, the external VLAN faces away from your internal servers and is assigned to the 192.168.0/24 network. The internal VLAN is in your internal resource network and is assigned to 10.0.0/24.

Note: The VLAN names admin and internal are default VLAN names. You may have configured your BIG-IP to use a different naming convention.

To make an address on the 10.0.0 network accessible from the 192.168.0 network, create a forwarding virtual server for that address (or point the virtual server to a forwarding pool). This assumes that there are no routes in place allowing the internal and external device to communicate.

In the following configuration example, the forwarding virtual server is using any port, which allows all valid TCP/IP protocols to be sent from the external VLAN to the internal destination.

b virtual 10.0.0.1:any forward vlan internal disable arp disable

For a better understanding of VLANs, refer to the BIG-IP documentation.


Forwarding pools

You can also create a forwarding pool to allow administrative access from an alternate VLAN.

To allow administrative access to the internal VLAN from the external VLAN, you would type:

b pool forwarding_pool { forward }
b virtual 10.0.0.1:any use pool forwarding_pool vlan internal disable arp disable

Note: The VLAN names admin and internal are default VLAN names. You may have configured your BIG-IP to use a different naming convention.

This form of forwarding pool can be expanded to include an entire network. To do this, use a zero as the last octet. For example:

b virtual 10.0.0.0:any use pool forwarding_pool vlan internal disable arp disable

ICMP and other protocols

If you want to pass ICMP, or a protocol such as GRE, you will need to go add one of the following commands to your forwarding configuration to allow the BIG-IP to forward on a non-standard protocol based on source and destination IP addresses. (Note that no port definition is required.)

b virtual 10.0.0.1 any_ip enable

or

b virtual 10.0.0.0 any_ip enable

VLANs

VLANs do not require special configuration, just the utilization of the existing VLANs on your BIG-IP.

Example Configuration:

In this configuration, you have a group of systems associated with the BIG-IP VLAN called admin. You would like all the systems on this VLAN to be able to access the web servers that are aligned with an alternative VLAN on the same BIG-IP called internal.

Note: The VLAN names admin and internal are default VLAN names. You may have configured your BIG-IP to use a different naming convention.

To allow the admin VLAN open access to the server VLAN without providing unrestricted access across all VLANs, you can create a VLAN group, which would join the admin and internal VLAN. The VLAN group essentially creates a virtual VLAN that treats the two separate VLANs (networks) as one unified VLAN (network).

To create a VLAN group, type the following command:

bigpipe vlangroup combo_vlan admin internal

After running this command, the admin and internal VLANs will act as one unified VLAN.

If some of the systems within the VLAN have access problems to the alternative VLAN, (for instance, system A in the original admin VLAN cannot access system A in the original internal VLAN), make the following changes to the self IP addresses of the admin and internal VLANs. To do this, you would need to delete each self IP address and add the self IP address of the new VLAN group. (In this example, that would be combo_vlan.)

bigpipe self x.x.x.x delete

bigpipe self x.x.x.x { vlan combo_vlan netmask y.y.y.y }

Repeat this command for each self IP address assigned to the individual admin and internal VLANs.

Warning: When you delete a self IP address that is only associated through the network address, the VLAN connectivity will be disrupted. Review the self IP configuration before you delete self IP address to insure that all relevant information is carried over, such as netmask/broadcast, floating IP, SNAT automap, etc.

IP Forwarding

IP forwarding (not recommended) allows BIG-IP to forward packets based on its routing table. When a BIG-IP interface receives packets that are not destined for any of BIG-IP's configured IP addresses (self IPs, Virtual Server IPs, and so on), then BIG-IP forwards the packet based on the kernel routing table. No address translation is performed. For more information on IP forwarding, refer to the BIG-IP documentation.

For the specific advantages and disadvantages of IP forwarding, refer to K473: Advantages and disadvantages of using IP forwarding.
