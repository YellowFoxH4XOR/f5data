K000158970: High merged CPU may result from a massive process table due to a very large number of zombie processes

Description

High CPU is observed in control plane due to high use by merged process. Merged has to manipulate data in tmstat statistics tables and when these have an extremely large number of rows it will use more CPU. If the tmstat table proc_pid_stat, which reflects the stats kept on processes by the Linux kernel gets very large due to a very large number of zombie processes merged CPU use may increase noticeably.


Environment

Specifically, where the REST API is in use frequently on BIG-IP to run process in bash shell via an intermediate tmsh process on software versions where ID 969345 isn't fixed.

In the more general case this can happen where there are a very large number (thousands or more) of zombie processes in the process table.


Cause

ID 969345 is likely root cause, due to failure of a failed tmsh to clean up after its child bash process.


Recommended Actions

Reboot to clear zombie processes.

Update to at least 17.1.2.2 or upgrade to 17.5.1, latest 17.1.x or 17.5.x or later being advised.


Additional Information

Process tables recent versions can have up to 131,070 entries. Zombie processes only exist as an entry in the process table. If the process table fills the system will have severe issues and require restart. This isn't likely to happen at zombie creation rates normally seen, when zombie creation happens in the first place. However the indirect affects such as extra merged CPU use may make it worthwhile to clear the issue with a scheduled reboot, or investigate why the zombies processes are being created.
