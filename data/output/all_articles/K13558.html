Topic

This article applies to BIG-IP 11.x through 17.x. For information about other versions, refer to the following article:

  • K10346: Allowing asymmetrically routed connections across multiple VLANs (9.x - 10.x)

You should consider using this procedure under the following condition:

  • Your BIG-IP system needs to accept asymmetrically routed connections.

Description

You can configure the BIG-IP system to accept asymmetrically routed connections across multiple Virtual Local Area Networks (VLANs) on a per virtual server basis or on a global system-wide basis, depending on the expected traffic path through the BIG-IP system.

To configure the BIG-IP system to accept asymmetrically routed connections, you must perform one of the following procedures:

  • Using a custom FastL4 profile with Loose Initialization and Loose Close enabled (To allow asymmetric routing per virtual server)
  • Disabling VLAN-keyed connections (To allow system-wide asymmetric routing)

Prerequisites

You must meet the following prerequisite to use this procedure:

  • The BIG-IP configuration must already contain existing VLANs and virtual servers properly configured for your environment.

Procedures

Using a custom FastL4 profile with Loose Initiation and Loose Close enabled

Enabling Loose Close in a custom FastL4 profile is required when an individual virtual server processes asymmetric traffic. Enabling Loose Initiation can be useful when an individual virtual server processes asymmetric traffic. For example, in an nPath configuration, the virtual server processes only the client-side traffic, and responses from the pool member are routed around the BIG-IP system. Use Loose Initiation or Loose Close for TCP traffic only as it is a connection-oriented protocol. You do not have to enable the settings for UDP, a connectionless protocol. For more information about these settings, refer to K09948701: Overview of the FastL4 profile.

Note: As of the fix for ID1008077, Loose-Close is required for asymmetric traffic and Loose-Init is optional. This is different from previous versions. In previous versions Loose-Close is not required. If you upgrade to one of the versions with the fix, you need to update Loose-Close setting in the FastL4 profiles to make sure asymmetric traffic successfully processes.

Command line

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To create the profile, use the following command syntax:

    create ltm profile fastl4 <profile name> loose-close enabled loose-initialization enabled

    For example, to create a FastL4 profile named MyL4Profile, enter the following command:

    create ltm profile fastl4 MyL4Profile loose-close enabled loose-initialization enabled

    Note: For platforms that contain a PVA chip, you must also disable pva-acceleration in the FastL4 profile, as shown in the following command:

    create ltm profile fastl4 MyL4Profile pva-acceleration none loose-close enabled loose-initialization enabled

  3. To associate the custom FastL4 profile with an existing virtual server and remove any existing TCP profile that is already associated with the virtual server, use the following command syntax:

    modify ltm virtual <virtual server name> profiles delete {<existing profile> } profiles add { <custom profile> }

    For example, to remove the default TCP profile and add the custom profile created in the previous procedure from the virtual server MyVip, enter the following command:

    modify ltm virtual MyVip profiles delete {tcp } profiles add { MyL4Profile }

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. For Protocol, select FastL4.
  4. Select Create.
  5. Enter a name for the profile.
  6. Select the Custom check box on the right side of the Settings section for both Loose Initiation and Loose Close.
  7. To enable the settings, select the Loose Initiation and Loose Close check boxes.
  8. (If your platform does not have a PVA chip, skip to step 9.)

    Set the PVA Acceleration box to None.

  9. Select Finished.
  10. Go to Local Traffic > Virtual Servers.
  11. Select the appropriate virtual server.
  12. Set Configuration to Advanced.
  13. For Protocol Profile, select the custom FastL4 profile that you created.
  14. Select Update.

Disabling VLAN-keyed connections

With VLAN-keyed connections enabled, the VLAN for the ingress traffic must match the configured VLAN and be present in the BIG-IP connflow lookup table, otherwise, the connection will not be processed by the BIG-IP system. This behavior is different for egress traffic, as egress traffic may use an alternate VLAN. For example, when a client sends SYN packets to a virtual server address configured on VLAN A, and that virtual server address replies to the connection request with a SYN/ACK from VLAN B, the ACK from that client will be matched when arriving on VLAN A or VLAN B. The BIG-IP system will not process the client's ACK reply if the reply arrives on a VLAN that is not VLAN A or VLAN B.

Disabling VLAN-keyed connections allows the BIG-IP system to accept asymmetrically routed connections across multiple VLANs. For example, this situation allows connection initiation to a pool member on VLAN A while the pool member's acknowledgment is received on VLAN B.

Note: As of the fix for ID1008077, Loose-Close is required for asymmetric traffic when disabling VLAN-keyed connections. In versions with the fix, you need to enable the Loose-Close setting in the FastL4 profiles to make sure asymmetric traffic successfully processes.

Note: Disabling VLAN-keyed connections only relaxes connection matching across VLANS within the same route domain.

Impact of procedure: Disabling VLAN-keyed connections affects all VLANs configured on the BIG-IP system, globally. F5 recommends that you test the system to watch for unintended consequences.

Command line

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To disable the connection.vlankeyed database key, enter the following command:

    modify sys db connection.vlankeyed value disable

  3. Save the changes by entering the following command:

    save sys config

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic.
  3. Select General.
  4. Disable the VLAN-Keyed Connections option.
  5. Select Update.
