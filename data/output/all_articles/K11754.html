Topic

If a gigabit fiber port on certain Cisco switches is booted into the disabled state, when that port is enabled, auto-negotiation will fail with a BIG-IP system running version 9.3.1 or later. The issue is not caused by the BIG-IP system.

Beginning in BIG-IP version 9.3.1, the BIG-IP system always auto-negotiates the status of its gigabit fiber ports. If a particular configuration is specified for a gigabit fiber port (for example 1000baseSX full), then the BIG-IP system only advertises that capability. In other words, auto-negotiation still happens, there is just only one possible successful outcome.

The IEEE 802.3z standard states that it is optional for gigabit fiber interfaces to connect without auto-negotiation. However, it states that it is mandatory for gigabit fiber interfaces to support auto-negotiation.

The issue described in this Solution occurs because certain Cisco switches erroneously do not perform auto-negotiation for gigabit fiber ports that boot into the disabled state and are enabled at a later time.

Cisco tracked this software defect as CSCeh46046 and it was fixed in CatOS version 8.4(4).

When this issue occurs:

  • The Cisco switch reports the link is up
  • The BIG-IP system reports the link is down
  • No traffic successfully passes
  • If the BIG-IP system is running version 9.3.1, the link light will be on; in later versions, the link light will not be on

Workaround

You can work around this issue by toggling the negotiation state of the affected port on the Cisco switch. For example, to toggle the negotiation state of port 1/9 you would type the following commands:

set port negotiation 1/9 disable
set port negotiation 1/9 enable

Once you have performed the workaround, the remote end (the BIG-IP system) becomes connected.
