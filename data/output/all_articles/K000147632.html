Description

  • You want to conduct load testing against a F5 Distributed Cloud Platform environment.
  • You want to run DDoS attack simulations against a Distributed Cloud environment.
  • This document augments the F5 Acceptable Usage policy: https://support.f5.com/csp/home 

Environment

  • F5® Distributed Cloud

Cause

Customers or authorized delegates may conduct load testing of Distributed Cloud (XC) environments subject to the following restrictions:

  • The target endpoint must be owned by the customer performing the test.  Examples of allowed and disallowed test targets:
    • Allowed: The Virtual IP (VIP) associated with any Load Balancer (LB) within the customer tenant
    • Allowed: Addresses within an IP prefix owned by a customer and advertised through XC
    • Prohibited: Endpoints not within the customer's own tenant
    • Prohibited: F5 XC infrastructure, including the XC Console
  • The volume of traffic must be within acceptable limits, or be specifically authorized by F5.
    Tests can be conducted without F5 authorization up to the following limits:

    • 1,000 HTTP requests per second (HTTP RPS)
    • 20 Mbps

  • Most DDoS attack simulations will involve volumes exceeding these limits and thus require approval. 

 

Recommended Actions

Customers intending to perform a load test or DDoS attack simulation with traffic volumes exceeding the above limits are required to notify F5 and receive authorization before proceeding with the activity.  Notification must be provided at least 7 days prior to the commencement of the activity.  Notification should be submitted as a Support ticket with the following information:

 

  • Time and Duration of the Test
  • Region(s)/Points of Presence (PoPs) being targeted for the test
  • Is the test falling under business hours for the region?
  • Nature of testing to be performed (L3/L4/L7/DNS)
  • Does the customer has Routed DDoS subscription?
  • Are the Load balancer configurations finalized/adjusted?
  • Expected Traffic Volume (For L3/L4 tests)
  • Expected RPS/QPS (For L7/DNS)
  • Capacity of the origin in RPS
  • Does the default DDOS detection threshold need to be updated before the test (if yes, what's the threshold value in RPS)?
  • Target Endpoint(s) (IP address, IP subnet, application FQDN)
  • PoP Type (Regional Edge/Customer Edge)
  • Total number of unique source IPs
  • Tool(s) used for the tests
  • Test plans and details (if available)
  • Can the test be stopped immediately if required?
  • Can the test be conducted incrementally, starting from a lower limit?
  • Emergency Point of Contact
  • Caveats (if any)

Customer will receive authorization or otherwise within the same ticket.

 

Additional Information

F5 reserves the right to request that any customer-initiated testing schedule be adjusted to accommodate F5 scheduled changes, maintenance, or other planned or unplanned activities. F5 will take reasonable effort to communicate the request to modify scheduled testing to the customer as soon as possible. F5 will work in good faith with the customer to adjust the scope of the testing if F5 determines that excessive risk will be applied to the Distributed Cloud services during testing.
