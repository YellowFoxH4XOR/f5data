K9809: Active Directory authentication and dynamic group mapping fail if the Active Directory group name contains a parenthesis character

Known Issue

This is the result of a known issue. If you configure a master group with Active Directory authentication and select the Check nested groups check box, authentication fails if one or more of the following conditions are met:

Note: The Check nested groups check box does not appear unless you enter a value in the User must belong to Domain group field and click Save settings.

  • The group name you entered in the User must belong to Domain group field contains a parenthesis character
  • The group name you entered in the User must belong to Domain group field is nested through a group name that contains a parenthesis character. For example, if the user belongs to the group Sales (USA), and the group Sales (USA) belongs to the group Employees, authentication fails if you entered Employees in the User must belong to Domain group field
 
Similarly, if you configure an Active Directory dynamic group mapping method and select the Check nested groups while mapping check box, mapping fails fails if one or more of the following conditions are met:
  • The group name you entered in the Active Directory Group field contains a parenthesis character

    Note: The Active Directory Group field is located in the master group and resource group mapping tables.
  •  The group name you entered in the Active Directory Group field is nested through a group name that contains a parenthesis character. For example, if the user belongs to the group Sales (USA), and the group Sales (USA) belongs to the group Employees, authentication fails if you entered Employees in the Active Directory Group field
 
For dynamic group mapping, you can confirm this issue by testing the affected user accounts on the Users: Groups: Dynamic Group Mapping page under the Master group mapping table tab. When this issue occurs, FirePass reports an error message that appears similar to the following example in the test function output:
 
get_nested_groups: Bad search filter
 
F5 Product Development tracked this issue as CR116967 and it was fixed in FirePass version 7.0.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative HF-603-3, which has been issued for FirePass version 6.0.3. You may download this hotfix or a later version of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
 
Workaround
 
If you do not require the nested groups feature, you can work around this issue by clearing the Check nested groups and Check nested groups while mapping check boxes.
 
Note: Active Directory nested groups are supported starting in FirePass version 6.0.3. For more information, refer to K9472: Change in Behavior: Active Directory authentication and dynamic group mapping now support nested groups.
