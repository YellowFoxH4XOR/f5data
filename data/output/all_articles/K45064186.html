K45064186: Locate TCP connection latency by using wireshark

Type
Support Solution
Published
2021-11-12
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K45064186

Description

You should consider using this procedure under the following conditions:
  • You are troubleshooting a high volume virtual server traffic that uses the same source IP address (all connection coming from one NAT address).
  • You are experiencing some intermittent TCP connection delays whether in the client side of the connection or in the server side of the connection.

Environment

You must meet the following prerequisites to use these procedures:
  • You have access to the Bash Shell in cli.
  • You perform a full tcpdump capture. Filter on the client IP, VIP IP, and back-end server IP in your tcpdump syntax and save the output into a binary file.
    Note: You have to ensure that the intermittent TCP connection delay occurred while the tcpdump capture was running.
  • You have installed Wireshark on your local machine.

Cause

None

Recommended Actions

Impact of procedure: The following procedure should not have a negative impact on your system.

  1. Extract the Capture from the BIG-IP into your local device.

  2. In Wireshark, filter the traffic to/from the client and the F5 virtual server by using this filter:
    ip.addr==<CLIENT_IP> && ip.addr==<VIP_IP> && tcp.port==<VIP_PORT>

  3. From the top tabs in Wireshark click on Statistics --> Conversations then wait for Wireshark to calculate.

  4. Click on the TCP tab

  5. After the calculation is done, click the box where is says 'Limit to display filter'

  6. Sort the output by Duration.

The above steps will show you all the TCP connections duration between client and virtual server in the capture. The top part of the connections will be the ones with the highest latency.
