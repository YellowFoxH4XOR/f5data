Description

bd_io_plug core files are generated and system may become Disconnected in Offline state.


Core files are visible under /var/core directory

ls -latr /var/core
1682304 rw-rw-rw- root root 860489681 2021-10-15 20:59:07 bd_io_plug_8.bld0.0.4.core.gz
1682040 rw-rw-rw- root root 860353856 2021-10-15 21:19:05 bd_io_plug_1.bld0.0.4.core.gz
1681992 rw-rw-rw- root root 860328643 2021-10-15 21:21:26 bd_io_plug_14.bld0.0.4.core.gz
1682176 rw-rw-rw- root root 860422492 2021-10-15 21:09:07 bd_io_plug_9.bld0.0.4.core.gz
1682296 rw-rw-rw- root root 860485053 2021-10-15 21:00:07 bd_io_plug_10.bld0.0.4.core.gz

/var/log/ltm is showing messages like the ones below :
notice logger[10321]: Started writing core file: /var/core/bd_io_plug_1.bld0.0.4.core.gz for PID 10209
notice logger[10350]: Finished writing 860520684 bytes for core file: /var/core/bd_io_plug_1.bld0.0.4.core.gz for PID 10209

 

When the device is running out of space, there are many unlikely behavior take place, especially for ASM. Hence, bd-agent core is a symptom and not the cause. The cause appears to be low disk space.

Environment

Big-IP 14.x and 15.x
ASM

Cause

Bug ID 969345: Temporary TMSH files not always removed after session termination

Recommended Actions

Follow workaround in Bugtracker Bug ID 969345: Temporary TMSH files not always removed after session termination

Alternatively, in order to clean all the temp files created by tmsh i.e. file under /var/system/tmp/tmsh/, you can run the following command as a workaround:
clean_tmsh_tmp_dirs

This shouldn't have any negative impact on traffic/overall performance of the device
