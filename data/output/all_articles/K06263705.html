Known Issue

The bigd process may leak file descriptors and stop working when it reaches its file descriptor limit.

This issue occurs when either of the following conditions is met:

  • You have a TCL health monitor configured (for example, FTP, IMAP, POP3, SMTP monitor).
  • You have enabled monitor logging for the pool members or nodes.

    To check the monitor logging status of a pool member, use the following command syntax:

    tmsh list /ltm pool <pool_name> members { <pool_member> { logging } }

    For example, the following command shows the monitor logging status of a pool named test_pool and pool member named test_node:http:

    tmsh list /ltm pool test_pool members { test_node:http  { logging } }

    If you have enabled monitor logging, the output of the command should appear similar to the following example:

    ltm pool test_pool {

        members {
            test_node:http {
                logging enabled
            }
        }
    }

    To check the monitor logging status of a node, use the following command syntax:

    tmsh list /ltm node <node> logging

    For example, the following command  shows the monitor logging status of a node named test_node:

    tmsh list /ltm node test_node logging

    If you have enabled monitor logging, the output of the command should appear similar to the following example:

    test_node {ltm node

        logging enabled
    }

Impact

Health monitors stop working and the system may erroneously mark pool members down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H610521 on the Diagnostics > Identified > Medium screen. 
  • Health monitors stop working and the system may erroneously mark pool members down.
  • The /var/log/ltm file contains error messages similar to the following example:

    01060154:4: Bigd PID 7147, instance 0, throttling monitor instance probe because file descriptor limit 65436 reached.

Workaround

There is no workaround. If you have monitor logging enabled on the pool members or nodes, you can avoid this issue by disabling monitor logging and restarting the bigd process. To do so, perform the following procedure:

Impact of procedure: Restarting the bigd process temporarily interrupts the BIG-IP monitor processing, which may cause an interruption in traffic processing. F5 recommends that you perform this procedure during a maintenance window.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To disable monitor logging on all of the members of a pool, use the following command syntax:

    modify /ltm pool <pool_name> members modify { all { logging disabled }}

    For example, to disable monitor logging on all the members of a pool named test_pool, type the following command:

    modify /ltm pool test_pool members modify { all  { logging disabled }}

  3. To disable monitor logging on all the nodes, type the following command:

    modify /ltm node all logging disabled

  4. To restart the bigd service, type the following command:

    restart /sys service bigd
