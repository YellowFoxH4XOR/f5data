Topic

With the BIG-IP system, you can configure the level of information that the system logs for events related to Traffic Management.

Log levels related to Traffic Management events

Traffic Management events use levels to distinguish the severity of the event. Traffic Management uses these severity levels when designating log levels. Log levels set the threshold at which Traffic Management event messages start accruing in the log files. Traffic Management event messages equal to and greater than the specified log level are written to the log file. For example, if you specify a log level of Warning, the system writes events classified as Warning, Error, Critical, Alert, and Emergency to the log file.

For information about how to specify which events are logged, refer to the Configuring log levels for Traffic Management Events section of this article.

Important: Use caution when changing a log level from its default setting. Refer to the event mapping files in the /etc/alertd/ directory to determine which Traffic Management event messages are associated with each log level. Repeat this procedure after each upgrade, as some Traffic Management event messages and their associated log levels may differ between software releases.

The following information details the available log levels related to Traffic Management events. The log levels are listed in order of severity:

Note: The default setting is indicated by the wildcard character, an asterisk (*). Additionally, not all log levels are available to configure from the Configuration utility.

Audit logging

In addition to Traffic Management events, you can control the level of Audit logging performed. Audit logging allows you to track configuration modifications. The user, the configuration object name, and the properties that the user modified will appear in the log message.

Audit (MCP) - config.auditing

Specifies the log level for configuration changes on the system.

Log levelConfiguration changes
disableTurn off audit logging
*enableTurn on logging for user-initiated configuration changes only
verboseTurn on logging for user-initiated configuration changes and configuration loads
allTurn on logging for all user-initiated and system-initiated configuration changes

Configuring global auditing for tmsh commands

You can disable or enable global auditing for the TMOS Shell (tmsh) commands run by users on the BIG-IP system. By default, audit logging is enabled and the audited commands are stored in the /var/log/audit file. To disable or enable audit logging, perform the following procedure:

Note: The system does not audit commands that are run as a result of running the tmsh load command.

Impact of procedure: If auditing is disabled, the system does not log tmsh commands that users enter.

Using tmsh to disable or enable audit logging for tmsh commands

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To determine the current state of audit logging, enter the following command:

    list /cli global-settings audit

    The output will look similar to the following example

    cli global-settings {
      audit enabled
    }

  3. To disable auditing, enter the following command:

    modify /cli global-settings audit disabled

  4. To re-enable auditing, enter the following command:

    modify /cli global-settings audit enabled

Configuring log levels for Traffic Management events

You can configure log levels for Traffic Management events from the Configuration utility or the command line. To do so, perform one of the following procedures:

Impact of procedure: An overloaded BIG-IP system may experience performance degradation if the logging intensity is high.

Using the Configuration utility to configure log levels for Traffic Management events

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Options.
  3. Select the log levels for the Local Traffic Logging event or Audit Logging event.
  4. Select Update.

Using tmsh to configure log levels for Traffic Management events

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the log level of the event, use the following command syntax:

    modify /sys db <name> <string>

    For example, to set the log level for MCP events to debug, you would enter the following command:

    modify /sys db log.mcpd.level value debug

    To enable audit logging for user-initiated configuration changes and configuration loads, you would enter the following command:

    modify /sys db config.auditing value verbose
