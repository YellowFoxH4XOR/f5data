K000133382: Abnormal size of sflow_agent.log causing disk space issues

Type
Support Solution
Published
2023-05-25
Updated
2023-05-25
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.2.0
Source
https://my.f5.com/manage/s/article/K000133382

Description

The output of the df -h command indicates the low disk space availability for /var/log.

/var/log/sflow_agent.log takes a huge amount of disk space of /var/log dir.
 

Environment

  • BIG-IQ
  • Low disk space in /var/log

 

Cause

Bug ID 799001: Sflow agent does not handle disconnect from SNMPD manager correctly.

 

Recommended Actions

1. Remove sflow agent logs:

rm -f /var/log/sflow_agent.log

2. Follow the below article to fix this sflow issue:

K00559898: sFlow Agent down after reboot
 

3. Sflow should no longer log the error message, so you should not have your disk space full again in the future.

 

If after the workaround snmp is restarting in a loop, edit bigip_base.conf to remove IP addresses specified in the agent-addresses under sys snmp configuration.


Example:

sys snmp {

agent-addresses { tcp6:161 udp6:161 10.245.6.30 10.244.10.0/255.255.254.0 10.245.6.172 10.245.6.173 10.245.6.174 10.223.21.130 10.223.21.66 10.223.4.30 10.223.4.31 }

...etc.

 

modify to:

sys snmp {

agent-addresses { tcp6:161 udp6:161 }

...etc.

 

Additional Information

None.
