K10433354: TLS handshakes from some clients may intermittently fail when using Diffie-Hellman ciphers

Topic

Using Diffie-Hellman (DH) ciphers with some third-party Transport Layer Security (TLS) implementations may result in periodic handshake failures.

Description

Due to an issue in some third-party TLS implementations, when using conventional DH ciphers with some clients, approximately one in 256 handshakes may fail. This issue applies to ciphers identified as DH, DHE or EDH (Ephemeral Diffie-Hellman).

This is specifically known to occur with some versions of the Microsoft Windows TLS stack.

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Traffic Management Microkernel (TMM) sends a fatal TLS alert immediately after receiving the ChangeCipherSpec message and an encrypted handshake message from the client:
    • If Generic Alert is enabled (default), the alert is the handshake_failure type.
    • If Generic Alert is disabled, the alert is the bad_record_mac type.
  • TMM may log a message to the /var/log/ltm file that appears similar to the following example:

    tmm[17938]: 01260009:4: Connection error: hud_ssl_handler:1230: codec alert (20)

    Note: For more information, refer to K09322055: The BIG-IP system now logs debug SSL errors through standard logging .

This issue does not apply to Elliptic Curve DH ciphers, identified as Elliptic Curve Diffie-Hellman (ECDH) or ECDHE (Elliptic Curve Ephemeral Diffie-Hellman).

Recommended Action

In most cases, no action is necessary. Clients usually retry if the initial TLS handshake fails.

There are two possible workarounds if intermittent handshake failure is unacceptable and client software cannot be patched:

  • F5 recommends migrating to ECDH ciphers.
  • If ECDH is not an option, you may use ciphers using RSA key exchange.

    Important: Unlike DH and ECDH ciphers, RSA does not offer perfect forward secrecy. Evaluate whether this is acceptable for your environment's security before implementing this workaround.

For more information about configuring cipher strength, refer to K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x).
