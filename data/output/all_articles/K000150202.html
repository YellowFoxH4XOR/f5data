K000150202: Removing leftover epsec images from multi-blade cluster standby unit

Published

Description

 When running a cluster with multiple blades (VIPRION, vCMP guests or VELOS tenants), if you delete any non used epsec image from the active unit, it will not be deleted from the standby (even after a successful synchronization). That means you will have leftover images stored under /shared/apm/images/ on the standby.

This can lead to further issues when you need to upgrade the standby and make it active, as older images will re-appear in the configuration.

Environment

 The problem happens when all conditions are matching:

  • BIG-IP APM HA pair
  • Multi-slot cluster system like VIPRION, vCMP guests, and VELOS tenants

Cause

When deleting an epsec image from the active unit and syncing the config, it does not remove the associated epsec image from /shared/apm/images/ on the standby.

Recommended Actions

 After deleting the older epsec image from the active and synchronizing the configuration, run the following commands on the standby :

 clsh bigstart stop csyncd
 clsh rm -f /shared/apm/images/epsec-1.0.0-xxxx.0.iso
 clsh bigstart start csyncd
