K000161558: After upgrading Guests, all configs are wiped

Type
Support Solution
Published
2026-06-03
Updated
2026-06-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161558

Description

 BIG-IP may boot after an upgrade or installation with an apparent default configuration instead of the expected saved configuration when the DB variables liveinstall.moveconfig and liveinstall.saveconfig are set to disable. Symptoms can include the system coming up with default login behavior, the previous configuration appearing to be wiped, and upgrade workflows appearing to stall during reboot verification even though the software installation itself succeeds. Configuration files remained present and valid, mcpd was running, and tmsh load sys config verify reported no load errors.

Environment

BIG-IP LTM 17.1.3

Cause

liveinstall.moveconfig and liveinstall.saveconfig are set to disable

sys db liveinstall.moveconfig {
default-value "enable"
scf-config "false"
 value "disable"
value-range "disable enable"
}
...
sys db liveinstall.saveconfig {
default-value "enable"
scf-config "false"
 value "disable"
value-range "disable enable"
}


Answer/Recommended Actions

1.Verify the DB variable settings by running:

tmsh list sys db liveinstall.moveconfig

tmsh list sys db liveinstall.saveconfig

2.If either value is disable, restore both settings to their default value of enable for expected installation and upgrade behavior.

tmsh modify sys db liveinstall.moveconfig value enable

tmsh modify sys db liveinstall.saveconfig value enable

3.Save the configuration after making the change.

tmsh save sys config

4.Retry the upgrade or installation.

Additional Information

Note: The DB variables liveinstall.moveconfig and liveinstall.saveconfig being changed from their default values is not something that the F5 BIG-IP software code would natively perform or alter during normal operation or upgrade procedures. Such changes must be made manually by an administrator or through external automation tools. Unless intentionally modified, these settings should remain at their default values to ensure proper upgrade behavior.

If additional validation is needed, use the following checks to confirm the issue is not caused by configuration corruption or mcpd load failure:

  1. Confirm /config/bigip.conf and /config/bigip_base.conf are present and not empty/default.
  2. Run tmsh load sys config verify and review for errors.
  3. Check mcpd status and last configuration load status.
  4. Review installation and boot logs to confirm the software installation completed successfully.
