Known Issue

The Traffic Management Microkernel (TMM) may exit and restart when Woodside congestion control is enabled.

This issue occurs when all of the following conditions are met:

  • You configure the Congestion Control setting in a TCP profile to use the Woodside algorithm.
  • You associate the TCP profile with a virtual server and begin processing traffic.

Impact

The BIG-IP system experiences a traffic disruption while the tmm process restarts. The BIG-IP system fails over to a standby system if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM produces a core file to the /shared/core/ directory.
  • The BIG-IP system logs a SIGSEGV to the /var/log/tmm file at the time of the disruption.
  • The BIG-IP system fails over to a peer if configured for HA.

Workaround

To work around this issue, you can configure the BIG-IP system to use a different congestion algorithm. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > TCP.
  3. Click the name of the affected profile.
  4. In the Congestion Control section, select an appropriate algorithm other than Woodside for the Congestion Control setting.
  5. Click Update.
