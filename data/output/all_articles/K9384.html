Known Issue

This is the result of a known issue. The sys-reset command restores the BIG-IP LTM to factory default values by removing all system configuration settings, including all files that are not recorded in the RPM database.

When the sys-reset command encounters a filename containing spaces, and the file is not recorded in the RPM database, the sys-reset command fails to remove the file and generates error messages. For example, the following error message was generated when the sys-reset command failed to remove the access_log_Sharepoint Apps_si_v542.log file:

Cross-checking filesystem and rpm database...
2183 files found that appear to be un-managed
/usr/bin/sys-reset-rl1: line 80: [: /var/log/wa/access/access_log_Sharepoint: binary operator expected
rm: cannot remove `/var/log/wa/access/access_log_Sharepoint': No such file or directory
rm: cannot remove `Apps_si_v542.log': No such file or directory

F5 Product Development tracked this issue as CR110790 and it was fixed in BIG-IP 9.4.8. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization Release Notes.

Note: For more information, refer to K7550: Resetting the BIG-IP system configuration to the factory default settings using the sys-reset command.

Note: The sys-reset command was removed in BIG-IP version 10.0.1. In versions 10.0.1 and later, you can use the image2disk command to reset BIG-IP systems to factory default settings. For more information, refer to K10519: Resetting a BIG-IP version 10.x configuration to the factory default settings.
