Description

SNMP pulling doesn't work for dynamic routing protocols in route-domains. with the standard configuration of snmp
Config example:


SNMP configuration required to support pulling of OIDS for dynamic routing protocols in route domains

net route-domain 0 { routing-protocol none }
net route-domain RD10 { routing-protocol { OSPFv2 } }

sys snmp
{ agent-addresses { tcp6:161 udp6:161 }
allowed-addresses { ALL }
communities {
comm-public { community-name public source default }

Snmpwalk does not show any OIDS for dynamic protocol configured in non-default route domain

snmpwalk -v2c -c public localhost . |grep OSPF

HOST-RESOURCES-MIB::hrSWRunParameters.17801 = STRING: "OSPF"

Environment

  • Route-domains configured
  • Enabled Dynamic protocol in non-default route domains
  • SNMPv2 agent access configured
  • pulling for dynamic routing  OIDs  ( like OSPF or BGP etc)

Cause

Configuration requires additional community configured

Recommended Actions

Configure community for  non-default route-domain:
  1. Go to System  ››  SNMP : Agent : Access (v1, v2c)
  2. Click Create...
  3. Specify Community - Specify community with route domain number  (RD<#>@public)

    Example: If we specify route-domain with ID 10 - RD10@public

  4. Specify Type, Source, OID, Access
  5. Click Finished

Additional Information

After configuring dynamic routing in route domain 0  You should more OIDS for the dynamic routing protocol

For example :
