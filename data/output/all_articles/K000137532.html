Description

There are times that the most expedient, or only way, to recover a BIG-IP virtual edition, that is not functioning properly, is to delete it and rebuild it from scratch.

Environment

  • Snapshotting a BIG-IP or other procedures can cause a partial or total loss of the BIG-IP
  • Configuration issues that can not be recovered
  • VMWare or other hypervisors.

Cause

There are several reasons that often the most expedient way to recover a BIG-IP VE is to delete and rebuild it from scratch. It may be simply a matter of how long it may take to fix what is going on verses just rebuilding and moving on.

Recommended Actions

Overview of how to delete and rebuild...

  1.  Delete the one in question and rebuild it as if it is a new one... VMware ESXi: F5 BIG-IP Virtual Edition Setup
  2. If the VE is still functional to some degree and to minimize any risk simply shutdown the one to be rebuilt (in case there are issues with the build of the new one you can then still use this one until whatever happens is rectified).

IMPORTANT: Either way when you build the new one the one you are replacing needs to be offline completely or there will likely be IP conflicts.

Once the new one is built you have a choice to make...

  1. Once you have it up set the base config (vlans, non-floating self-ips, and such) then build HA and sync from the running peer.
  2. Once the new one is built use a ucs archive to rebuild the config using the no-license check option.

IMPORTANT; During this process DO NOT have Auto sync enabled.

NOTE: In order to re-use the license you will need to get an "Allow Move" of the license done. To do that simply call in to Support. The people who answer the phones are called Technical Service Coordinators. One of their main duties is dealing with licenses issues. They can do that Allow Move and it only takes a minute or so to do. Then about a 15 minute wait to be sure the system updates.

The above link should get you through the build as it is very detailed. But it would be a good idea to also review...

Best practices for deploying BIG-IP VE on VMware

So the basic steps flow like this...

  1. Get the Allow Move done and that can be done ahead of time.
  2. Shutdown the one to be rebuilt.
  3. Build the new one.
  4. Setup the management IP.
  5. Rebuild the config
  6. Test
  7. Delete the old one.
