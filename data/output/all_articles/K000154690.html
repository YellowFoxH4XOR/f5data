K000154690: "Access encountered an error (Illegal argument)" logged by BIG-IP when receiving SAML SLO LogoutResponse from AD FS acting as SAML IdP

Description

In a SAML SP initiated SLO flow, an AD FS server acting as SAML IdP, will redirect the browser back to a URL such as "https://www.example.com/saml/sp/profile/redirect/slo?SAMLResponse=xxx".
BIG-IP acting as SAML SP (handling www.example.com) will receive it and will send back a RST with "Access encountered an error (Illegal argument)".
This happens because AD FS server may append certain parameters, like "client-request-id".
This parameter is not part of the core SAML 2.0 specification; instead, it is an implementation-specific addition by AD FS to help with diagnostics and client troubleshooting

Environment

  • BIG-IP APM as SAML SP
  • ADFS as SAML IdP 

Cause

 The "client-request-id" parameter is not expected here as per OASIS Standard so BIG-IP is acting properly.

Recommended Actions

You can use below workaround iRule to skip the "client-request-id" parameter from the request.  ​​​​​

​​

when HTTP_REQUEST {
   if { [HTTP::has_responded] } { return }
   if { [HTTP::method] eq "GET" } {
      # Get the complete query string
      set query_string [HTTP::query]
      # Only proceed if a query string exists and it contains client-request-id
      if { [info exists query_string] && $query_string ne "" && $query_string contains "client-request-id" } {
         # Split the query string into a list of parameters
         set param_list [split $query_string "&"]
         # Initialize a new list to hold updated parameters
         set updated_params {}
         # Loop through each parameter
         foreach param $param_list {
            # Add the parameter to updated_params only if it's NOT "client-request-id"
            if {!([string tolower $param] starts_with "client-request-id=")} {
               lappend updated_params $param
            }
         }
         # Reconstruct the updated query string without client-request-id
         set updated_query [join $updated_params "&"]
         # Update the URI with the new query string (or just the path if no params are left)
         if {$updated_query eq ""} {
            HTTP::uri [HTTP::path]
         } else {
            HTTP::uri [HTTP::path]?$updated_query
         }
      }
   }
   # Optional: Log the modified HTTP URI (for debugging)
   #log local0. "Modified HTTP Request URI: [HTTP::uri]"
}
