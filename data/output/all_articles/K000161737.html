K000161737: ASM Automatic Signature Update (ASU) Fails to Sync to Standby Unit After Upgrade

Type
Support Solution
Published
2026-06-16
Updated
2026-06-22
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000161737

Description

After upgrading BIG-IP ASM, the Automatic Signature Update (ASU) fails to synchronize from the active unit to the standby unit. The active unit successfully installs the latest ASU, but the standby unit does not receive or apply the update.

  • The latest ASU is installed and active on the primary (active) unit but is absent on the standby unit
  • The nsyncd service on the standby unit appears to be running normally (no crash or restart observed)
  • The sync issue may recur after subsequent ASU releases, even if earlier ASUs synced successfully
  • No explicit error is surfaced to the administrator; the standby unit silently stalls waiting for a response from the active unit

Environment

  • Product: BIG-IP ASM
  • Version:  All existing versions
  • Configuration: Active/Standby High Availability (HA) pair
  • Feature: Automatic Signature Update (ASU) with nsyncd synchronization service
  • Trigger condition: This issue may get triggered after BIG-IP upgrade, reboot, nsyncd service restart.

Cause

Bug ID 2295693

The root cause is a timing issue in the nsyncd state machine between the active and standby units:

  • When the standby unit returns (e.g., after an upgrade or reboot), it sends a sync request to the active unit and sets an internal state variable to true (indicating it is waiting for a response)
  • If the active unit is not yet ready to handle this request at that moment, it does not respond
  • The standby unit then waits indefinitely, as there is no mechanism to reset the internal state variable back to false
  • This causes the nsyncd state machine on the standby unit to stall permanently until the service is restarted

Answer/Recommended Actions

Perform the following nsyncd restart procedure in the correct order to resolve the stalled sync state. Restarting on the active unit first ensures it is ready before the standby re-initiates its sync request.

  1. On the active unit, restart the nsyncd service:
    bigstart restart nsyncd
  2. Confirm nsyncd is running on the active unit:
    bigstart status nsyncd
  3. Once the active unit's nsyncd is confirmed running, restart nsyncd on the standby unit:
    bigstart restart nsyncd
  4. Confirm nsyncd is running on the standby unit:
    bigstart status nsyncd
  5. Verify that the latest ASU has synchronized to the standby unit.

Important: The order of restart matters. Restarting nsyncd on the active unit first ensures it is in a ready state before the standby unit re-initiates its sync request, preventing the state machine from stalling again.

Additional Information

  • Simply restarting nsyncd on the standby unit alone may resolve the immediate issue, but restarting on the active unit first is the more precise workaround.
  • The sync issue may not occur with every ASU release. It has been observed to recur intermittently.
  • This issue may get triggered after BIG-IP upgrade, reboot, nsyncd service restart.
