Description

  • Attempted K16700: Decrypting SSL traffic using the SSL::sessionsecret iRules command but there is no SSL session key.
  • The SSL Decrypt iRule does not show the session ID, as session cache is turned off.  For example:
Session-ID: Master-Key:7bfcb98c9725de0da25eda2110937550d9097039912ad422c877e20b43d8741572d9467365dac6a6a3e4cc19ec608bfd

Environment

  • BIG-IP v12.x and later
  • SSL offloading virtual server
  • Win/Mac PC with Wireshark

Cause

None

Recommended Actions

Decrypting SSL traffic using the SSL::sessionsecret iRules command

  1. Create an iRule using a SSL::sessionsecret iRules command syntax similar to the following example:

    Note: In the following example, <client_IP_addr> is the IP address of the remote client accessing the BIG-IP virtual server.

    when CLIENTSSL_HANDSHAKE {
      if {[IP::addr [IP::client_addr] equals "<client_IP_addr>"] } {
        log local0. "[TCP::client_port] :: RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
        log local0. "CLIENT_RANDOM [SSL::clientrandom] [SSL::sessionsecret]"
      }
    }

    Note: To dump a server-side session key, use SERVERSSL_HANDSHAKE instead of CLIENTSSL_HANDSHAKE.

  2. Associate the iRule with the virtual server.
  3. Start tcpdump capture on the BIG-IP system.
  4. Access the virtual server from the client system.
  5. Stop the tcpdump command.
  6. Remove the iRule from the virtual server.
  7. Download the generated tcpdump packet.
  8. Produce a Master Secret log file using the following command at the BIG-IP command line:

        grep -h -o 'CLIENT_RANDOM.*' /var/log/ltm* > /var/tmp/sessionsecrets.pms

  9. Download the /var/tmp/sessionsecrets.pms file to your local drive.
  10. Open the packet capture with the Wireshark application.
  11. Navigate to Edit > Preferences.
  12. Navigate to Protocols > SSL.
  13. Under (Pre)-Master-Secret log filename, Browse... to the sessionsecrets.pms file
  14. Click Open
  15. Click OK

The SSL sessions are now decrypted.

Additional Information

The SSL::sessionsecret iRules command extracts the SSL session key from SSL sessions that are terminated by the Traffic Management Microkernel (TMM).
This method allows you to decrypt an SSL session and review the application data using the Wireshark application without having access to the server's private key.
This procedure functions on both client- and server-side and works with Diffie-Hellman and Elliptic Curve Diffie-Hellman key exchange algorithms as well as RSA.
