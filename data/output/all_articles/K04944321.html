Description

After upgrading the LTM the flow broke between web servers and SQL DB through a forwarding Virtual Server that uses nPATH

Environment
This issue occurs when all of the following conditions are met:

  • BIG-IP platform using RSS DAG hash, for instance, z100 and 2000 or 4000 series hardware platform or using xor_fold hash on i2000/i4000 platforms
  • FastL4 profile associated with a virtual server
  • Virtual Server configured with source-port preserve
  • FastL4 profile setup to use Loose Initiation and thus have an nPATH setup

Cause

A tcpdump done on the LTM shows that the LTM changed the Source Port that came from web server towards the Firewall to get to the SQL DB after upgrading LTM:

Sample tcpdump (10.2.85.102 is the web server-Pool Member IP which communicates to the SQL DB on 10.2.84.102 via forwarding VS) : 

tcpdump -nnnnvvvvi 0.0 -w /var/tmp/paac.pcap host 10.2.85.102

10.2.85.102 → 10.2.84.102  916 61597 1433 TDS IN  s1/tmm2 : Remote Procedure Call
10.2.85.102 → 10.2.84.102  916 19270 1433 TDS OUT s1/tmm2 : Remote Procedure Call       <---------------------- The Source Port change 61597 to 19270.
10.2.85.102 → 10.2.84.102  40 61597 1433 TCP IN  s1/tmm2 : 61597 → 1433 [RST, ACK, CWR] Seq=877 Ack=1 Win=0 Len=0
10.2.85.102 → 10.2.84.102  40 19270 1433 TCP OUT s1/tmm2 : 19270 → 1433 [RST, ACK, CWR] Seq=877 Ack=1 Win=0 Len=0

Recommended Actions

  1. There is a known BUG ID for change in behavior for some particular platforms regarding source-port preserve:
    Bug ID 726176: Platforms using RSS and xor_fold DAG hash reuse source port too rapidly when the FastL4 virtual server is set to source-port preserve
  2. The fix for those specific platforms was that the "preserve" works the same as "change" for source-port.
  3. To keep the nPATH flow working, the Source Port setting on the Virtual Server now needs be' Preserve Strict' setting to make the flow work on newer versions and specific platforms stated in the BUG ID.

Additional Information
It is always recommended for nPATH routing that you use srcport preserve strict for the virtual server.
