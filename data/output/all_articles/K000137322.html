Security Advisory Description

A specifically crafted HTTP request may lead the BIG-IP system to generate multiple HTTP redirect responses.

This issue occurs when all of the following conditions are met:

  • A virtual server has one or more of the following configurations:
    • An iRule with an HTTP::redirect or an HTTP::respond command that redirects HTTP requests based on the content of the request.
    • An LTM policy that redirects HTTP requests based on the content of the request.
  • The virtual server receives and processes a malformed HTTP request.

Impact

The BIG-IP system may respond with multiple HTTP redirect responses. Intermediate systems may cache these HTTP redirect responses and clients may unexpectedly receive them.

Mitigation

To work around this issue, you can associate the following mitigation iRule to the affected BIG-IP virtual server. The mitigation iRule should be listed as the first iRule on the virtual servers iRule list before the HTTP redirection iRules:

Important: If an LTM policy is redirecting HTTP requests, convert the LTM policy redirect conditions to an iRule with HTTP::redirect syntax.

# F5 iRule for Mitigation of HTTP Redirect Response
# For additional information please see https://my.f5.com/manage/s/article/K000137322
#
# Version 1.0 - 2023-10-26 09:00 Pacific
# - Initial Release
# Version 1.1 - 2023-10-26 14:00 Pacific
# - Added LWS / header continuation detecting

when RULE_INIT {
    # Set debug to 1 for logging actions, 0 to disable logging (recommended in production)
    set static::smuggling_mitigation_logging 0
}

when HTTP_REQUEST priority 1 {
    set contentLength [string trim [HTTP::header "Content-Length"]]
    set requestMethod [HTTP::method]
    set transferEncoding [string tolower [HTTP::header "Transfer-Encoding"]]

    # Check for chunked transfer encoding

    if {$transferEncoding eq "chunked"} {
        if {$static::smuggling_mitigation_logging == 1} {
            log local0. "Chunked Transfer-Encoding detected. Bypassing Content-Length checks."
        }
        unset -nocomplain contentLength requestMethod transferEncoding
        return
    }

    if {($contentLength eq "" || $contentLength < 0) && ([string tolower [HTTP::header names]] contains "content-length")} {
        event disable all
        reject
        if {$static::smuggling_mitigation_logging == 1} {
            log local0. "Blocked request with empty Content-Length"
        }
       return
    }

    if {(![string is double -strict $contentLength] || [string match "*+*" $contentLength] || [string match "*-*" $contentLength] || [string match "*.*"      $contentLength]) && $contentLength ne ""} {
        event disable all
        reject
        if {$static::smuggling_mitigation_logging == 1} {
            log local0. "Blocked request with invalid Content-Length: $contentLength"
        }
        return
    }

    foreach header [HTTP::header names] {
        set header_value [HTTP::header values $header]

        if { (([string tolower $header_value] contains "content-length") ||
        ([string tolower $header_value] contains "transfer-encoding")) &&
        ([string first ":" $header_value] >= 0) } {
            event disable all
            reject
            if {$static::smuggling_mitigation_logging == 1} {
                log local0. "Dropping request from [IP::client_addr] due to presence of suspect header value of $header"
            }
            return
        }
    }

    if {$static::smuggling_mitigation_logging == 1} {
        log local0. "Content-Length: $contentLength"
    }
    unset -nocomplain contentLength requestMethod transferEncoding header header_value
}

BIG-IP

To create the mitigation iRule and associate it with a virtual server, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the affected BIG-IP system.
  2. Go to Local Traffic > iRules > iRule List.
  3. Select Create.
  4. Enter a value for Name. For example, K000137322.
  5. Copy the mitigation iRule and paste it into the Definition box.
  6. Select Finished to save the iRule.
  7. Go to Local Traffic > Virtual Servers > Virtual Server List.
  8. Select the name of the virtual server.
  9. Select Resources.
  10. In the iRules section, select Manage.
  11. Select the iRule you have configured in previous steps from the Available box and move it to the Enabled box by selecting <<.
  12. Continue to select Up to move the new iRule to the top of the list.
  13. Select Finished.

Note: For more information about the priority iRule command, refer to the F5 Cloud Docs priority page.

BIG-IP Next

To create the mitigation iRule and associate it with an application, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to BIG-IP Next Central Manager.
  2. Select Go To Application Workspace.
  3. Select the iRules tab, then select + Create.
  4. Enter a value for Name. For example, K000137322.
  5. Copy the mitigation iRule and paste it into the box, and then select Save.
  6. Go to Applications > My Application Services.
  7. Select an application using an affected redirect iRule.
  8. Select Edit at the top of the page.
  9. Next to the iRules column, select the editing icon.
  10. Select + Add, select the check box next to the newly created mitigation iRule, and then select the Add button.
  11. Select the check box next to the newly added mitigation iRule, select the up arrow at the top of the page to ensure it is in the first row, then select Save.
  12. Select Review & Deploy to confirm the deployment.
  13. Repeat steps 6-12 for each affected application.

Additionally, in BIG-IP 15.1.0 and later, F5 recommends enabling RFC protocol compliance in the HTTP profile. This optional feature helps protect against a wide range of other HTTP smuggling attacks. To do so, select the check box next to the Enforce RFC Compliance setting in your HTTP profile. HTTP profiles are located on the Local Traffic > Profiles > Services > HTTP page. For more information, refer to K40413116: Information about the Enforcement of RFC compliance for the HTTP protocol feature.
