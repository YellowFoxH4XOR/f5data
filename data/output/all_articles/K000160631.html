K000160631: Configuration Synchronization Issue Between Platform and Tenant

Type
Support Solution
Published
2026-04-06
Updated
2026-04-06
Applies to
  • F5OS
  • F5OS-A: 1.5.4
Source
https://my.f5.com/manage/s/article/K000160631

Description

On an F5OS rSeries platform with a BIG-IP tenant, a newly created VLAN configured on the F5OS layer does not appear inside the BIG-IP tenant, suggesting a platform-to-tenant VLAN synchronization/visibility issue. Tenant redeploy/reboot and re-provisioning do not resolve it.

Environment

  • F5OS rSeries platform with a BIG-IP tenant
  • Network uses LAGs/trunks with VLANs
  • VLANs are created/managed at the F5OS layer and assigned to the tenant

Cause

The new VLAN was created with a VLAN ID that duplicated/conflicted with an existing (or previously used) VLAN ID in the platform/tenant mapping, preventing the VLAN from becoming visible inside the tenant.

Recommended Actions

  1. Recreate the VLAN on the F5OS platform using a unique VLAN ID.
  2. Reassign the VLAN to the appropriate interface/LAG and attach it to the tenant.
  3. After reattaching, refresh/re-login to the tenant and verify the VLAN is present.
  4. Ensure VLAN IDs are unique on the platform (and across VLANs assigned to the same tenant) before creating/attaching new VLANs.

Additional Information

In rSeries/F5OS deployments, tenants inherit VLANs from the F5OS layer based on VLAN ID. A VLAN ID conflict can appear as a “VLAN not syncing/appearing” issue even if the tenant is otherwise healthy and other VLANs are present.
