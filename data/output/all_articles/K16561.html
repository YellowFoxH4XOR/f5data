Known Issue

The Traffic Management Shell (tmsh) may display connections that are accelerated on one side of the connection, as accelerated on both sides.

This issue occurs when all of the following conditions are met:

  • You use a FastL4 virtual server type.
  • You attempt to view the connection acceleration state using the tmsh show sys conn command.

Impact

There is no impact; you can safely ignore this issue.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The tmsh show sys conn command erroneously displays a connection as accelerated on both-sides instead of client-side or none.

    For example:

    1.1.1.1:8411 2.2.2.2:8000 1.1.1.1:8411 2.2.2.2:8000 tcp 38 (tmm: 0) both-sides
    1.1.1.1:57475 2.2.2.2:9000 1.1.1.1:57475 2.2.2.2:9000 tcp 3 (tmm: 5) both-sides

  • The total number of accelerated flows does not match the total number of flows displayed in the tmsh show sys conn command.

    You can use the following tmctl command to display the total correct number of accelerated flows:

    tmctl -i -d blade -e 'tmm/hsb_internal_lbb.netc_epva_crnt_entries'
