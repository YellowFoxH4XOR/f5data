K6849: IPv6 AAAA DNS queries cause BIG-IP GTM to remove persistence information

Type
Known Issue
Published
2007-05-09
Updated

  • BIG-IP GTM: 9.2.5, 9.2.4, 9.2.3, 9.2.2
Source

Known Issue

This is the result of a known issue. Each time an LDNS queries the wide IP (WIP) when the wide IP is configured with persistence enabled, a persistence entry is created that records the LDNS IP address and the answer sent by BIG-IP GTM.

The LDNS IP address and the answer that was sent by BIG-IP GTM is then synchronized with BIG-IP GTM systems in the network so that the same response is given to the same LDNS if it queries a different BIG-IP GTM.

You can view the persistence entries by performing the following procedure:

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to Overview > Statistics.
  3. Select Global Traffic.
  4. From the Statistics Type menu, select Persistence Records.
  5. Select Refresh.

When an LDNS that has a record in the persistence table makes an IPv6 AAAA DNS request, BIG-IP GTM will return a non-error DNS response with no answer record (expected behavior), and will remove the persistence entry for that LDNS from the persistence table (unexpected behavior).

When the same LDNS makes an IPv4 A record DNS request again, the BIG-IP GTM will treat the request as though it is the first time it has been received. As a result, a different response can be handed out for a resource in an entirely different datacenter than the one in which the original BIG-IP GTM was housed. Under these circumstances, clients may seem to be going back and forth between datacenters (oftentimes requiring reauthentication in the middle of a session) despite having wide IP persistence enabled.

F5 Product Development tracked this issue as CR72128 and CR72129, and it was fixed in BIG-IP GTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Workaround

You can work around this issue by performing the following procedures:

  • Creating a pool that will handle the IPv6 AAAA DNS requests
  • Creating an iRule that will direct IPv6 AAAA DNS requests to the pool
  • Applying the iRule to the wide IP that is configured to use persistence

Creating a pool that will handle the IPv6 AAAA DNS requests

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to Global Traffic > Pools.
  3. Select Create.
  4. Name the pool, GTM_pool_return_to_dns.
  5. Select Return to DNS for the Primary, Alternate, and Fallback load balancing methods.
  6. Select Finished.

Note: There is no need to specify a virtual server for this pool, as this procedure creates a pool that allows BIND to handle answering the IPv6 AAAA DNS request.

Creating an iRule that will direct IPv6 AAAA DNS requests to the pool

To create a BIG-IP GTM iRule that will direct IPv6 AAAA DNS requests to the pool created above, perform the following procedure:

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to Global Traffic > iRules.
  3. Select Create.
  4. Name the iRule, GTM_ipv6_workaround.
  5. Enter the following syntax in the Definition box: 
    when DNS_REQUEST {      if { [DNS::rrtype] equals "AAAA"} {      pool GTM_pool_return_to_dns   }    }
  6. Select Finished.

Applying the iRule to the wide IP that is configured to use persistence

To apply the BIG-IP GTM_IPv6_workaround iRule to the wide IP that is configured to use persistence, perform the following procedure:

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Navigate to Global Traffic > Wide IPs.
  3. Select the wide IP configured to use persistence.
  4. Select iRules.
  5. Select Manage.
  6. Select the iRule GTM_ipv6_workaround.
  7. Select Add.
  8. Select Finished.
