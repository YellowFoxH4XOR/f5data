K000151233: Intermittent status code 429, body TooManyRequests errors when deploying an HTTP Load Balancer via Terraform

Type
Support Solution
Published
2025-05-08
Updated
2025-05-08
Source
https://my.f5.com/manage/s/article/K000151233

What Happened?

  • You deployed a HTTP load balancer or any other object via Terraform and often get 429 as status code and body TooManyRequest

  • Rerunning the failed jobs typically allow the pipeline to complete without an issue.

Environment

  • F5 Distributed Cloud HTTP Load Balancer 
  • Terraform
  • F5 Distributed Cloud Terraform provider

Resolution/Answer

This behavior is due to the API rate limits enforced by the F5 Distributed Cloud platform.

To reduce the frequency of these errors, run Terraform with reduced concurrency using the -parallelism=1 flag. This setting forces Terraform to process one resource at a time, which reduces the rate of API requests and helps avoid hitting rate limits.

Example: 

terraform apply -parallelism=1

Note: This flag controls concurrency, not rate limiting directly. The F5 Distributed Cloud Terraform provider currently does not support client-side rate limiting. Feature requests for enhanced control over API request behavior are under consideration.

Cause

The F5 Distributed Cloud platform enforces rate limits on API usage. During high-volume Terraform operations, these limits can be exceeded, resulting in 429 TooManyRequests responses.

Additional Information

  • The -parallelism flag in Terraform controls how many operations are executed concurrently during plan or apply.
  • By default, Terraform uses up to 10 concurrent operations.
  • Reducing parallelism may increase execution time, but it helps in environments sensitive to API request volume.
