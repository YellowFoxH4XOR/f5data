Known Issue

If a Secure Sockets Layer (SSL) client attempts to resume an SSL session using a hybrid handshake, the process may fail.

This issue occurs when all of the following conditions are met:

  • You have a virtual server with a Client SSL profile configured.
  • The SSL client attempts to resume an SSL session to the virtual server using SSLv2 with TLS1.0.

Impact

The client's attempt to resume the SSL session fails, requiring the client to perform a complete SSL handshake to reconnect.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A client attempting to resume an SSL session using SSLv2 with TLS1.0 experiences delays or connection failures.
  • The BIG-IP system experiences a performance impact.

Workaround

To work around this issue, you can disable the SSL session cache in the client SSL profile. To do so, perform the following procedure:

Impact of workaround: Disabling the SSL session cache may affect system performance. Additionally, the impact of the suggested workaround depends on the specific environment. F5 recommends testing any changes during a maintenance window, with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. From the SSL menu, select Client SSL profile.
  4. Select the profiles that are using session caching.
  5. From the Configuration menu, select Advanced.
  6. Enter 0 (zero) for the Cache Size setting to disable SSL session caching.
  7. Select Update.
