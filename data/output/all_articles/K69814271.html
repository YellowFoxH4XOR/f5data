Description

The VIPRION failover happened, from Active change to Standby. Maybe some of the blades reboot reboot silently.

In the kernel log, contain the log like:

warning sod[PID]: 01140029:4: HA tmm_detect_fail_t tmm fails action is failover.
info bcm56xxd[PID]: 012c0012:6: FFP HDAG installed for default (cmp state 0x2)
sod[PID]: 01140030:5: HA tmm_detect_fail_t tmm is now responding.
info bcm56xxd[PID]: 012c0012:6: FFP HDAG installed for default (cmp state 0x3)

In the tmm log, contain the log like:

notice CDP: exceeded 1/2 timeout for slot 1
notice HA: state forced to 1, unit mask forced to 0.
notice Immediately transitioning dissaggregator to state 0x2
notice cmp state: 0x2
notice MPI dgram: connection with node 127.20.1.1 established
notice cmp state: 0x3

Before this event, find the log match K23505424:

info kernel: ltm driver: Idle enforcer starting - tid: <pid> cpu: 1/1
info kernel: ltm driver: Idle enforcer exiting - tid: <pid> cpu: 1
 

Environment

  • VIPRION with multiple blade
  • Imbalanced traffic between blade, like the cable only connect to blade 1.
  • Load is high, like throughput is X Gbit/sec (depending on the hardware plaform).
  • Minimum Up Members setting is 2 or higher

Cause

The root cause is similar with ID 662296 and K12776, the business traffic on the backbone cause the issue.

Recommended Actions

Reduce the traffic between blade. For example, follow the article K15222, adjust the physical network topo.

Additional Information

None.
