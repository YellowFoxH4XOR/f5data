Known Issue

This is the result of a known issue. If two route entries point to similar IP ranges and are configured to use pools, TMM drops one of the pool routes from the configuration.

For example:
  • Route 10.6.0.0/16 is configured to use the route1_pool pool as a resource.
  • Route 10.6.6.0/24 is configured to use the route2_pool pool as a resource.
  • Route default is configured to use the default_route_pool pool as a resource.
When TMM loads the example route information into the routing table, the route add logic within TMM drops one of the pools. As a result, the route table list is incomplete, and traffic is not routed even though the system is configured with the specific routes.

F5 Product Development tracked this issue as CR90494 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.3-14.3-HF3 issued for BIG-IP version 9.4.3. You may download this hotfix or a later version of this hotfix from the F5 Downloads site.
