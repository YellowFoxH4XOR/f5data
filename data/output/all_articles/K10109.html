Topic

Note: Use of multicast addresses for the Network Failover feature was introduced in BIG-IP version 9.6.0.

When network failover is configured to use multicast addresses, each unit of a redundant pair is both a multicast source and a multicast subscriber. In order for the multicast subscription mechanism to function, Internet Group Management Protocol (IGMP) messages must be propagated bi-directionally between the BIG-IP peers.

By default, many high-end switches enable IGMP snooping and have no multicast router ports configured. The IGMP snooping algorithm blocks multicast streams to a specific port if no IGMP traffic is seen on that port. In a multi-switch environment, IGMP messages may not be seen by all switches; as a result, some ports may be inappropriately blocked.

If both BIG-IP peers are uplinked to the same IGMP-aware switch, the switch will propagate IGMP messages as expected with no further configuration.

However, if the BIG-IP peers are uplinked to separate cross-linked IGMP-aware switches with no multicast router ports, one of the following approaches may be required to ensure propagation of IGMP messages between the BIG-IP peers:

  • On each switch, configure the crosslink port to the other switch as a static multicast router port. Each switch will then dynamically relay IGMP messages to the other switch.
     
  • On each switch, configure two static multicast MAC address entries: One for the crosslink port to the other switch, and one for the downlink port to the BIG-IP. Each switch will then be able to forward multicast traffic to the intended destination.

    Note: This solution works well, but is neither scalable nor dynamic.
     
  • On each switch, configure Protocol Independent Multicast (PIM). 

    Note: PIM is slightly more complex to configure and manage, and provides minimal benefits in this specific scenario over a static multicast router port.
     
  • On each switch, disable IGMP Snooping. This will cause the switch to broadcast all multicast messages to all ports.

    Note: This solution will not scale in production environments, but could be useful for initial testing and proof of concept.
