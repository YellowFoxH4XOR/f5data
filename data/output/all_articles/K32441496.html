Description

The Content-Length header is removed when HTTP compression is enabled.

Environment

  • Virtual server with HTTP compression enabled
  • HTTP profile

Cause

This behaviour is by design.

Recommended Actions

Leave the Response Chunking setting in the HTTP profile set to the default value of Selective (BIG-IP 14.x and earlier) or Sustain (BIG-IP 15.x and later) when using HTTP compression.

Additional Information

The Response Chunking value set to Preserve in the HTTP profile and HTTP compression enabled, forces the BIG-IP to send the incorrect response when the compressed response size exceeds the buffer size. For example when the compressed size exceeds the TCP profile's Send Buffer size of 131072, the BIG-IP must start sending the compressed response, without setting the Content-Length header, as the compressed length is unknown then. Response Chunking set to Preserve in the HTTP profile prevents sending the response chunked; therefore, it results in an invalid response which is unchunked and has no Content-Length header.
