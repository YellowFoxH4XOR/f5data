Description

After performing upgrade to software version 16.x the configuration does not load with the following error:

err mcpd[5220]: 01070712:3: Caught configuration exception (0), Invalid primary key on classification_signatures_update_scheduling object - path is empty..
err tmsh[10988]: 01420006:3: Loading configuration process failed.

Environment

  • BIG-IP ASM/AFM

Cause

Classification signatures are mostly used by PEM, ASM or AFM to classify traffic. ASM/AFM would leverage the signatures for validating if an IP is malicious using IP intelligence.

The error is an mcpd validation error and is generic. Refers to an mcpd DB object-key reference that's broken or missing.

Note: The classification signatures update scheduling feature creation has been deprecated beginning in BIG IP version V16, and due to this software upgrade from 15.1.10.6 or lower versions to BIG IP versions v16.x or above can lead to configuration loading issues. to BIG-IP 16.1.0 and later versions.

Recommended Actions

Perform this workaround to load the configuration:

  1. Copy a backup of bigip.conf
# cp /config/bigip.conf /config/bigip.conf.bak
  1. Edit bigip.conf with "nano" or another editor and remove or comment out below part:
ltm classification signature-definition {
    last-attempt-automatic-mode enabled
    last-attempt-datetime 2021-01-10:03:19:15
    last-update-automatic-mode enabled
    last-update-datetime 2017-08-25:03:21:05
    message "Download server cannot be reached (No response from update server). Please download the DPI Signatures file and install manually."
    progress-status failure
}
ltm classification signature-update-schedule {
    auto-update-enabled
    auto-update-interval daily
}
ltm classification signature-version {
    updated-time 2017-08-18:14:16:00
}
ltm classification auto-update settings {
    auto-update-interval weekly
    enabled no
}
  1. Save bigip.conf
  2. Load this new configuration
# tmsh load sys config
