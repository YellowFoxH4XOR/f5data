K11656: When performing XML content-based routing, each XPath query returns the value of only one element

Topic

Note: Beginning with BIG-IP version 10.2.0, you can use the BIG-IP system to perform XML content-based routing. This allows the system to route HTTP requests to an appropriate pool or pool member based on specific content in an XML document. For more information, refer to the Configuring XML Content-Based Routing section of the BIG-IP Local Traffic Manager: Implementations Guide.

When performing XML content-based routing, each XPath query can match more than one element in an XML document. However, the $XML::values TCL variable will only hold the value of the element that was matched first.

For example:

  • A virtual server is configured with the following XML profile:

    profile xml SOL11656 {
       defaults from xml
       xpath queries {
          "//book"
          "//movie"
       }
    }

    Note: This profile performs two XPath queries, which look for elements called book and movie.
  • The virtual server is also configured with the following iRule:

    rule SOL11656 {
    when XML_CONTENT_BASED_ROUTING
    {   
         for {set i 0} { $i < $XML::count } {incr i} {
            log local0. $XML::queries($i)
            log local0. $XML::values($i)
         }
    }
    }

    Note: This iRule, which is triggered when the XML profile inspects incoming XML requests, logs the names of the queries that matched and the values of elements that matched.
  • The virtual server receives the following XML message:

    <?xml version="1.0" encoding="ISO-8859-1"?>
    <bookstore>
    <book>
      <title lang="eng">Book1</title>
      <price>19.99</price>
    </book>
    <book>
      <title lang="eng">Book2</title>
      <price>22.99</price>
    </book>
    </bookstore>
    <moviestore>
    <movie>
      <title lang="eng">Movie1</title>
      <price>24.99</price>
    </movie>
    <movie>
      <title lang="eng">Movie2</title>
      <price>16.99</price>
    </movie>
    </moviestore>
    </xml>
  • The BIG-IP system logs the following lines to the /var/log/ltm file, indicating that the $XML::values TCL variable only holds the value of the element that was matched first:

    Rule SOL11656_XML <XML_CONTENT_BASED_ROUTING>: //book
    Rule SOL11656_XML <XML_CONTENT_BASED_ROUTING>:     Book1    19.99
    Rule SOL11656_XML <XML_CONTENT_BASED_ROUTING>: //movie
    Rule SOL11656_XML <XML_CONTENT_BASED_ROUTING>:     Movie1    24.99

This behavior is by design.
