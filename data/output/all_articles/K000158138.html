K000158138: Bot Defense with Private CE Origin

Type

Published
2025-12-10
Updated
2026-01-13
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud Bot Defense
Source

Description

A limitation exists whereby F5 XC Bot Defense will not function on a HTTP Load Balancer with origin server(s) on private CE with restricted egress through Forward Proxy.

 

Environment

  • F5® Distributed Cloud

  • Bot Defense
  • HTTP Load Balancer
  • Private CE Origin
  • Forward Proxy

 

Answer/Recommended Actions

Consider an architecture with the following characteristics:

  1. Publicly available HTTP LB
  2. Origin Pool with endpoints (origin servers) having RFC1918 addressing, available on a given CE site.
  3. Public networks are unreachable from the private CE without going through Forward Proxy, as defined in the site definition.

F5 XC Bot Defense will not work under these conditions.  This is because the Bot Defense engine calls an external service "IBD" at the following domains:

ibd-webus.fastcache.net
ibd-webemea.fastcache.net
ibd-webapac.fastcache.net
ibd-webemea2.fastcache.net

 

These endpoints are silently installed in the origin pool and are health checked for reachability.  When the origin pool is defined only on a private CE site, and that CE is configured to allow outbound access only through a forward proxy, this configuration does not extend to the 'invisible' IBD cluster.  Health check and (theoretically) upstream data-plane traffic does not egress through the forward proxy, therefore cannot reach the public IBD endpoints.  The IBD pool never comes up and Bot Defense cannot function.

Currently, Bot Defense is not supported on HTTP LB having private CE origin with restricted egress through forward proxy.

At this time, the only way to make this configuration operable is to permit direct outbound access from the CE to the four domains referenced above.

 

Additional Information

It may be possible to reach the IBD endpoints from the CE SiteCLI shell (using curl, etc.), but this traffic still egresses through the configured proxy.

There are no such limitiations for public origins, or private origins in CEs with open egress.
