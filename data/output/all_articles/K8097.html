K8097: Windows Logon Integration support for pre-logon inspectors

Topic

The FirePass Windows Logon Integration component supports pre-logon inspectors that do not access information on the client system. For example, the Check for Antiviruses, Check Processes, Check Registry, and Check Files inspectors cannot be used with Windows Logon Integration because these inspectors access information on the client system. However, the Check Time and Write to Logon Log pre-logon inspectors can be used with Windows Logon Integration, since neither of these inspectors access information on the client system.

If you enable a pre-logon sequence that contains a client inspector, users who attempt to log on to the FirePass controller with Windows Logon Integration will fail to authenticate, and receive an error message similar to the following example:

Error 1327: Logon failure: user account restriction.
Possible reasons are blank passwords not allowed, logon hour restrictions, or a policy restriction has been enforced

The FirePass Windows Logon Integration component allows users to establish a FirePass VPN connection when they log on to their Windows systems without modifying Microsoft GINA components. The connection users receive appears as a dial-up connection on the Windows client system, and the Windows Logon Integration component provides support for logon scripts such as drive mappings. For more information about the Windows Logon Integration component, refer to the FirePass Controller Administrator Guide.

Workaround

If you need to configure a pre-logon sequence that contains a client inspector, users can log on to the FirePass controller using a browser instead of the Windows Logon Integration component.

Alternately, you can configure a pre-logon sequence that bypasses pre-logon checks for Windows Logon Integration clients. For more information, refer to K8916: Configuring a pre-logon sequence to detect Windows Logon Integration clients.
