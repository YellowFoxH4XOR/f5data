K22783330: Aspen Mesh control plane is restarting or not running

Type
Support Solution
Published
2021-06-16
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K22783330

Description

Aspen Mesh control plane has been restarting frequently or has not been running properly.

  • The last state of the control plane pod reports that it was terminated with the reason OOMKilled. For example:

    Last State:     Terminated
          Reason:       OOMKilled
          Exit Code:    2
          Started:      Thu, 03 Jun 2021 14:35:47 -0500
          Finished:     Thu, 03 Jun 2021 14:38:19 -0500
        Ready:          True
        Restart Count:  3

Environment

  • Aspen Mesh 1.6.x - 1.9.x
  • Red Hat OpenShift 4.6.x - 4.7.x
  • Kubernetes 1.17.x - 1.20.x

Cause

The most common causes of this issue are:

  • Control plane terminated due to insufficient memory allocation.
  • Control plane dependencies are not running correctly.
  • An incorrect configuration is preventing the control plane from running.

Recommended Actions

Use the following procedures to rule out the most common reasons for the control plane issues.

  • Review the last state of the Aspen Mesh control plane pod
    • Increase memory limits for the control plane pod
  • Verify pod component dependencies
  • Verify the override Helm values configuration file

Review the last state of the Aspen Mesh control plane pod

Impact of action: Performing the following procedure should not have a negative impact on your system.

  1. List the pods in the istio-system namespace by running the following command:

    kubectl -n istio-system get pods

Increase memory limits for the control plane pod

If the Aspen Mesh control plane pod was terminated with OOMKilled, you can increase the memory limits for the pod and perform a Helm upgrade to resolve the issue.

Impact of action: Adjustments to memory allocation should be performed in a test environment to ensure compatibility with your environment.

  1. Edit the override Helm values deployment file for your Aspen Mesh installation.
  2. Increase the memory limit to at least double the current value. For example, if the original installation value is 256Mi, you should increase the limit to 512Mi, which would appear similar to the following:

    aspen-mesh-controlplane:
      userAuth:
        type: none
      clusterId: demo

      resources:
      requests:
        memory: "128Mi"
        cpu: "100m"
      limits:
        memory: "512Mi"
        cpu: "200m"

  3. Save the file and exit, then upgrade your Helm installation with the new values by running the following command:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery -n istio-system --values overrides-aspenmesh.yaml

  4. Confirm that the values have been updated by running the following command and observing the change:

    kubectl -n istio-system get deployment aspen-mesh-controlplane -o yaml | grep -A5 'limits' | tail -6

  5. Monitor the Aspen Mesh control plane pod and confirm that there are no further restarts.

Verify pod component dependencies

The Aspen Mesh control plane has dependencies from other pod components, and in most cases, is the last pod to run. If other pods have not completed their start up, or if they are otherwise not running correctly, they can prevent the Aspen Mesh control plane from starting or running correctly.

  1. Using the kubectl -n istio-system get pods command from step 1, confirm that the following pods are in a running state, by viewing all pods in the istio-system namespace:
    • aspen-mesh-metrics-collector pod

    • aspen-mesh-event-storage pods
    • aspen-mesh-jaeger and istiod-cassandra pods (if tracing is enabled)

Verify the override Helm values configuration file

Another common reason for the control plane not running properly is a misconfiguration or typo in the override Helm values file when you install or update an Aspen Mesh system. The override file uses yaml syntax, which must follow proper whitespace and indent rules.

Impact of action: Performing the following procedure should not have a negative impact on your system.

  1. Using an IDE such as Visual Studio or Atom, visually review the override Helm values file for the following issues.
    • Missing spaces
    • Missing quotes
    • Misspelled words
    • Incorrect indentation
  2. Correct any misconfigurations and upgrade the Helm release using the fixed override values file by running the following command:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery -n istio-system --values overrides-aspenmesh.yaml
