Known Issue

Statistics fail after configuring the merge method with the slow_merge option.

This issue occurs when the following condition is met:

  • You configure the merged.method system database variable to use the slow_merge option.

When you configure the merge method with the slow_merge option, the system fails to create a /var/tmstat/cluster directory that is required for statistics.

Impact

Statistics are no longer available after configuring the merge method to use the slow_merge option.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After configuring the merge method to use the slow_merge option and rebooting the system, you view error messages that appear similar to the following example:
     
    • 12.x

      err statsd[5873]: 011b0309:3: 01070995:4: get_tmstat: tmstat_sample not ready. Statsd may not be running. query_stats access_stat
      warning mcpd[6330]: 01070995:4: get_tmstat: tmstat_sample not ready. Statsd may not be running.

    • 11.x

      err statsd[PID]: 011b0309:3: 01070995:4: get_tmstat: tmstat_sample not ready. Statsd may not be running. query_stats access_stat
      err statsd[PID]: 011b0900:3: TMSTAT error from tmstat_subscribe: No such file or directory.
      err statsd[PID]: 011b0900:3: TMSTAT error tmstat_query: read_system_stats: No such file or directory.
      err statsd[PID]: 011b0900:3: TMSTAT error read_system_stats: read failed.

  • When attempting to view statistics using the Configuration utility, you view the following error message:

    General database error retrieving information.

Workaround

To work around this issue, you can configure the merged.method system database variable to use the fast_merge option (the default value), or you can create the /var/tmstat/cluster directory. To do so, perform one of the following procedures:

  • Configuring the merge method to use fast_merge option
  • Creating the /var/tmstat/cluster directory

Configuring the merge method to use fast_merge option

To configure the merged.method system database variable to use the fast_merge option (the default value), perform the following procedure:

Impact of workaround: Resetting the merge method requires a system reboot, which will result in a service interruption.

  1. Log in to the command line.

    Note: for a system with multiple blades, log in to the primary blade.

  2. Configure the merged.method database variable to use the fast_merge value by typing the following command:

    tmsh modify sys db merged.method value fast_merge

  3. Reboot the system by typing the following command:

    reboot

    For a system with multiple blades, you must reboot all blades by typing the following command:

    clsh reboot

Creating the /var/tmstat/cluster directory

To create the /var/tmstat/cluster directory perform the following procedure:

Impact of workaround: The /var/tmstat/cluster directory will be removed if the system is rebooted. Additionally, for multiple bladed systems, you must create the /var/tmstat/cluster directory on all blades.

  1. Log in to the command line.
  2. Create the /var/tmstat/cluster directory by typing the following command:

    mkdir /var/tmstat/cluster

    Optionally, you can add the mkdir /var/tmstat/cluster command to the /config/startup file so that it will be created each time you restart the system. To do so, type the following command:

    echo "mkdir /var/tmstat/cluster" >> /config/startup

    For a system with multiple blades, you must repeat steps 1 and 2 for each remaining blade in the chassis.
