Description

In BIG-IP APM 11.4.0 and later, you can create and query a local user database for access policy authentication.  This feature allows you to create multiple local user databases and provide on-box user access authentication, segment users, and maintain individual user information. 

You can add a user to Local Database either using Allow User Creation from configuration utility or by importing an existing user database from a properly formatted CSV file.

Environment

  • APM
  • Local User Database
  • 11.4.0 and later

Cause

None

Recommended Actions

None

Additional Information
During access policy operation, you can read from and write to a local user database.
You can read from a local user database to:

  • Determine whether a user is locked out of a local user database instance.
  • Check the number of failed login attempts for a user.
  • Check group membership for the user to determine which access policy branch to take.
    Note: Groups are text strings. You create them from the Configuration utility.

You can write to a local user database primarily to increment or reset the number of login failures for a user.
You can also update the locked out status for the user; although this option provides flexibility, use it sparingly.
Normally, locked out status is set programmatically.

There is no size limitation on the number of users created in the database. However, importing a large list of users may take some time to process the list, and in some cases may cause unpredictable situation such as Configuration Utility stall.
