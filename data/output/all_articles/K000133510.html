K000133510: Loading of sys config halts the BIG-IP due to corruption of EPSEC rpm database

Type
Support Solution
Published
2023-04-20
Updated
2023-04-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.0, 15.1.2, 15.1.1, 15.1.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000133510

Description

Loading sys config fails and mcpd may not be running properly due to corruption of EPSEC rpm database.

 

You may see the following logs:

 

emerg load_config_files[10761]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Error: failed to reset strict operations; disconnecting from mcpd. Will reconnect on next command.

 

Failed to reset strict operations; disconnecting from mcpd.

 

 

Environment

  • BIG-IP APM
  • Previous EPSEC packages that are still residing on the system from earlier BIG-IP versions are installed upon boot.

Cause

Bug ID 967557

 

Recommended Actions

1.Rebuild the rpm database with the following bash commands:

rm -rf /var/apm/lib/rpm

epsec -f refresh​​​

 

2.Delete unused EPSEC files following the next article:

K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system

Note: Also delete unused epsec files from the bash directory /config/filestore/files_d/Common_d/epsec_package_d

 

Additional Information

None.
