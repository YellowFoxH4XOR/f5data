K19517970: Configuring cross-origin resource sharing for single-page applications

Applies to

Topic

You should consider using this procedure under the following conditions:

  • You have configured a DoS Protection profile for single-page applications (SPA).
  • You want to allow cross-origin resource sharing (CORS) for the SPA.

Description

The BIG-IP ASM system supports SPA and AJAX applications in the DoS protection profile by injecting JavaScript code into client responses and generating custom HTTP headers. However, if the client sends cross-origin requests, the custom header is not inserted since it can cause browser-generating CORS pre-flight requests and may break the application because not all the servers can handle pre-flight requests.

For example, the following HTTP GET request shows the Origin headers from the main application host domain_b.com making a CORS request to the remote host domain_a.com:

GET /ajax_response.json HTTP/1.1
Host: domain_a.com
Origin: https://domain_b.com

Starting in BIG-IP 14.0.0, the BIG-IP ASM system supports CORS in SPA with a custom query string to prevent CORS pre-flight requests from being generated by the browser.  A new system database variable dosl7.allowed_origins is introduced so that you can configure a list of domains to be included in the CORS requests.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the TMOS Shell (tmsh).

Procedures

Modifying allowed origins supported in SPA

To modify allowed origins supported in SPA, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the domain list, use the following command syntax:

    modify /sys db dosl7.allowed_origins <new_list>

    For example, to include https://domain_b.com in the allowed origins, type the following command:

    modify /sys db dosl7.allowed_origins value "https://domain_b.com"

  3. To verify the modified domain list, type the following command:

    list /sys db dosl7.allowed_origins
