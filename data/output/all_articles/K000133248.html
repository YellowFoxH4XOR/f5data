Description

Password change for local users is successful. However, when trying to SSH into another blade instance, the system may not accept a new password or may prompt for a password change if the account is expired.

Environment

  • Multi-bladed vCMP guest or F5OS tenant
  • Mismatch in local user password or expiration between slots
  • Logs

Cause

Bug ID 1280881

This will happen if a user-generated SSH identity exists in the ~/.ssh directory, with one of the following names:

  • id_rsa
  • id_dsa
  • id_ecdsa
  • id_ed25519

The failures occur when REST storage snapshots are SCP'd via the backplane interfaces to other slots.
SSH blade instance is trying to use one of the files starting with 'id' to authenticate, but the matching public key entry is not present in the authorized_keys file.

Recommended Actions

Check ~/.ssh directory on all the slots. Then either remove the user-generated identity (if unused), or add the corresponding public key to ~/.ssh/authorized_keys.

For example:

cat /root/.ssh/id_rsa.pub >> /root/.ssh/authorized_keys

The changed file will be copied by csyncd to other slots.
