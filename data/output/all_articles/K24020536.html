Description

Progress bar does not move from 0% when attempting to upload the file "BIGIP-14.1.x.iso"

Environment

  • BIG-IP ISO file larger than 2.0GB

Cause

Result of Bug ID 614648

Recommended Actions

Follow any one of the workarounds below:

Uploading using alternate method:
Use another method, such as SCP (K175: Transferring files to or from an F5 system), to copy the BIG-IP software image to the target BIG-IP system in /shared/images.

(OR)

Renaming uploaded temporary file:
 A temporary file is created under /shared/images with a name in the form of: upload_###################.dat.
  •  After sufficient time has elapsed to allow the software image upload to complete, manually rename the temporary file under /shared/images to the final file name found on Downloads.F5.com
    Note: It is highly recommended to verify the md5sum of the temporary file to confirm that upload is complete, and that the temporary file is an accurate copy of the original software image uploaded. K8337: Verifying the MD5 checksum for the downloaded F5 software file

Additional Information

Attempting to upload a software image at the System > Software Management > Image List > New Image...

  1. The Progress bar in the GUI never moves from 0%
  2. A temporary file is created under /shared/images with a name in the form of: upload_###################.dat.
  3. The temporary file is never renamed to the correct image file name (as uploaded).

This may occur on affected versions of BIG-IP when the size of the software image to be uploaded is larger than 2GB in size.
For example: BIG-IP v14.1.0 Upgrade ISO is 2.1GB in size. Other BIG-IP v13.x and v14.x Recovery ISOs may also be larger than 2GB in size.
