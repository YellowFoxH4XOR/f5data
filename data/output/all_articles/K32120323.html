Known Issue

Virtual servers configured with a rate class may sporadically stop processing traffic.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with an acceleration rate class.
  • You assign the rate class to a virtual server.
  • Traffic received on the virtual server includes a TCP Segmentation Offload (TSO) packet that is larger than the configured rate class ceiling.

Impact

The virtual server stops processing traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the virtual server encounters this issue, the associated Traffic Management Microkernel (TMM) process of the connection stops processing other connection requests.
  • Failing over to a peer device temporarily resolves the issue.
  • Modifying the rate class ceiling with a larger value than the TSO packet size allows connections to process normally.

Workaround

To work around this issue, you can configure the Rate Class with a ceiling value greater than the expected TSO packet size. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure increases the rate class ceiling; the rate of traffic permitted by the rate class increases based on this change.

  1. Log in to the Configuration utility.
  2. Navigate to Acceleration > Rate Shaping > Rate Class Lists.
  3. Click the Name of the affected rate class.
  4. Enter a value for Ceiling that is greater than the largest anticipated TSO packets.
  5. Click Update.

Note:  If you are unable to reliably determine a ceiling value, or raising the ceiling value does not resolve the issue, you may also consider disabling TSO as detailed in K15609: Overview of TCP Segmentation Offload and Large Receive Offload.
