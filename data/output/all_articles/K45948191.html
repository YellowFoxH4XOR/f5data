Known Issue

The BIG-IP system may fail to maintain time synchronization with a network time protocol (NTP) server.

This issue occurs when all of the following conditions are met:

  • You are running one of the following platforms:
     
    • A BIG-IP appliance (excluding VIPRION platforms)
    • BIG-IP Virtual Edition (VE)
    • A Virtual Clustered Multiprocessing (vCMP) instance
  • The BIG-IP configuration uses an NTP server for time synchronization.
  • The NTP server is also configured on another host in the same network.
  • One of the following events occurs:
     
    • The BIG-IP system receives NTP traffic from the NTP server, which uses a multicast address.
    • The BIG-IP system receives NTP traffic from the NTP server, which uses a unicast address meant for the other host in the network. This event can happen when the switch floods unicast traffic to all ports in the Virtual Local Area Network (VLAN) while attempting to locate the port that the host is connected to.

      For example, the switch may flood unicast traffic to all ports when it is not able to locate the host entry in its L2 forwarding database (FDB). The host entry in the FDB can expire due to a lack of network activity on the host or a network issue can cause the switch to lose the host entry in its FDB (for example, the host may fail over to a redundant switch which has NIC teaming/bonding configured or an STP topology change).

Impact

The BIG-IP system may fail to synchronize with an NTP server.

Symptoms

As a result of this issue, you may encounter all of the following symptoms:

  • Your BIG-IP system fails to maintain time synchronization with the NTP server.
  • You notice that the BIG-IP system responds to the NTP server with a source IP address of 127.3.0.0 or a multicast address instead of its management IP address.
