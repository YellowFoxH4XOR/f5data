Description

  • You have NGINX configured as a proxy to relay request/response between requesting clients and responding upstream.
  • With the above and (large volume of traffic), however, you observe error "upstream timed out (110: Connection timed out) while reading response header from upstream" 
      1970/09/10 10:09:19 [warn] 36#36: *8706986 upstream server temporarily disabled while reading response header from upstream, client: <IP>, server: <hostname>, request: "POST /some/request HTTP/1.1", upstream: "http://<IP>/some/request", host: "<hostname>"
      
      1970/09/10 10:09:19 [error] 36#36: *8706986 
            upstream timed out (110: Connection timed out) while reading response header from upstream, 
            client: <IP>, 
            server: <hostname>, 
            request: "POST /some/request HTTP/1.1",
            upstream: "http://<IP>/some/request", 
            host: "<hostname>"
  • You want to know cause and resolution 
  • NGINX, in this regard, encompasses any of these products NGINX Plus, NGINX Open Source, NGINX App Protect, NGINX ingress Controller

Environment

  • NGINX Plus
  • NGINX Open Source
  • NGINX App Protect
  • NGINX ingress Controller
  • proxy_read_timeout Directive

Cause

  • Primarily the source of the issue is the upstream.
  • This can be due to
    • selected upstream being very busy (overloaded / lack of resource),
    • or not having sufficient upstream to process traffic
    • or the presence of network congestion where configured upstream is required to further proxy the request to another application server

Recommended Actions

  • On the NGINX, one can modify the timeout by adjusting the value of "proxy_read_timeout"  directive,
  • By default, the value of "proxy_read_timeout" is set to 60 seconds
  • However, as discussed above, the source of the issue is the upstream. Hence, it is also best to check the load, setting and the health of the network as a whole

 

  • You can modify "proxy_read_timeout" at HTTP, Server or location block. To do so,
    • SSH into the host system where NGINX installed
    • To increase the timeout to 70 seconds, at the http block level, navigate to /etc/nginx/nginx.conf
      • sudo vi /etc/nginx/nginx.conf
    • proxy_read_timeout 70s;
      • save and exit 
    • reload Nginx 
      • sudo nginx -t && sudo nginx -s reload 

Additional Information

High overview of request/response

  • NGINX receives a GET/POST request from Client
  • NGINX proxy request to Application Pod
  • Application Pod receives request from NGINX
  • Application Pod responds with its response
    • during this time, NGINX has to read the response in full within 60 seconds
    • the timeout is set only between two successive read operations, not for the transmission of the whole response
    • when the read timeout exceeds the default 60 seonds a timeout happens.
    • read timeout, defines a timeout for reading a response from the proxied server
    • and if NGINX failed to get the full response, it will log the mentioned error and terminates the connection
  • Hence, on the NGINX, the recommendation is to adjust "proxy_read_timeout" directive
