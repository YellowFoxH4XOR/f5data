Known Issue

TMM may core when processing connections for a virtual server that is configured to use a FastL4 protocol profile and a Source Address Affinity persistence profile.

A race condition may allow TMM to try and process a connection flow that has been closed and is no longer present. This causes TMM to core.

Impact

TMM may crash and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H420018 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system temporarily fails to process traffic and potentially fails over to the standby host.
  • A TMM core file at the time of the crash is located in the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault and stack trace in the /var/log/tmm file that appears similar to the following example:

Workaround

Note: There is no work around for this issue under the conditions listed. However, you may be able to modify the configuration to avoid the precipitating conditions. For example, you can change the virtual server type from Performance (Layer4) to Standard, or change the type of persistence used from source address affinity to universal persistence. However, you must evaluate the possible modifications to determine if they are acceptable for your environment.

To prevent this issue, you may be able to modify the virtual server configuration using one of the following procedures:

Modifying the virtual server type from Performance to Standard

Impact of workaround: Before performing this procedure, you should ensure that this modification is compatible with your environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the affected virtual server.
  5. Change the Type option from Performance (Layer 4) to Standard.
  6. Make additional modifications to the virtual server appropriate for your environment, such as selecting an HTTP profile.
  7. Click Update.

Modifying the type of persistence used by the virtual server

Impact of workaround: Before performing this procedure, you should ensure that this modification is compatible with your environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the affected virtual server.
  5. Click Resources.
  6. Select the desired universal persistence profile from the Default Persistence Profile menu.
  7. Click Update.
