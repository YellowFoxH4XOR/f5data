Known Issue

The debug Traffic Management Microkernel (TMM) kernel may produce a core file and restart when processing Internet Control Message Protocol (ICMP) packets.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with the debug TMM kernel.
  • TMM processes an ICMP Path MTU Discovery packet.
  • The maximum transmission unit (MTU) of the ICMP Path MTU Discovery packet is set with an MTU that is larger than the MTU specified for the BIG-IP VLAN that receives the request.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails over to another host in the device group.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system temporarily fails to process traffic.

Workaround

To work around this issue, you can configure the BIG-IP system to block incoming ICMP PMTUD packets. To do so, perform the following procedure:

Impact of workaround: Blocking incoming ICMP Path MTU Discovery packets causes Path MTU Discovery to fail, and the BIG-IP system may silently drop IP packets with the Don't Fragment (DF) bit set if you configure the MTU's devices on the network path incorrectly.

  1. Log in to the Configuration utility.
  2. Go to Network > Packet Filters.
  3. Set Packet Filtering to Enabled.
  4. Set Unhandled Packet Action to Accept.
  5. Select the Options setting's Filter established connections check box.
  6. Ensure the Protocols setting Always accept ARP option has the default value of checked.
  7. Under the Exemptions > Protocols section, clear the Always accept important ICMP check box.
  8. Ensure all other exemption settings have the default value of None.
  9. Select Update.
  10. Create the new Internet Control Message Protocol (ICMP) packet filter by going to Network > Packet Filters.
  11. Select Rules > Create.
  12. Enter a Name in the rule text box.
  13. Set Order to First.
  14. Set Action to Discard.
  15. Set VLAN / Tunnel to the VLAN name of the affected VLAN.
  16. Set Logging to Enabled.
  17. From the Filter Expression Method list, select Enter Expression Text.
  18. In the Filter Expression text box, enter the following expression:

    (icmp and icmp[icmptype] == 3 and icmp[icmpcode] == 4) or (icmp6 and not ip6[4:2] == 0 and ip6[ip6[4:2]*4] == 0x02)

  19. Select Finished.

Important: If normal operations of the BIG-IP system do not include packet filters, disable packet filtering prior to switching back from the debug TMM kernel. If you use packet filtering in the normal operations of your BIG-IP system, remove the new ICMP iRule created for use with the debug TMM kernel prior to switching back from the debug TMM kernel.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. To disable MTU path enforcement and MTU route metrics, enter the following command:

    modify /sys db tm.enforcepathmtu value disable
    modify /sys db route.metrics.mtu value disable

    Important: If you do not use these tmsh database settings in normal operations, revert these values to enable prior to switching back from the debug TMM kernel.

  3. To exit tmsh, enter the following command:

    quit
