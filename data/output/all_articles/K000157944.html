Description

Article explains how rate limiting of requests is enforced and why sometimes you can observe a bit more successful requests from some sources than your rate limit.
For example, when a rate limit is set to 250 requests per 10 minutes per user, it is possible to observe more than 250 successful requests (during 10 minutes period) in logs before rate limit enforcement begins.

Environment

  • Rate Limiting
  • Load Balancer
  • Distributed architecture 
  • Regional Edge

Cause

It's possible that you will observe more successful requests in given time than your set rate limit because of:

  • RE factor
  • Convergence time

RE factor

Every RE counts user requests separately and this information is not shared between REs. If RE that handled user traffic change, new RE won't be aware of previously sent requests.   

Convergence time

Our architecture and systems are distributed even inside RE.  Each proxy instance inside RE counts user incoming requests independently and we need to add all user requests from distributed proxies instances. Such synchronization between nodes introduces a brief window where more requests than configured may be accepted before blocking begins. This can lead to a temporary overshoot of the configured rate limit before enforcement occurs.

Recommended Actions

None, working as expected.
