Description

Upload function is not working in application after applying BIG-IP ASM policy and it is configured as transparent mode.

Environment

  1. BIG-IP ASM running v15.1.0 or above 
  2. The pool member server requires the "Expect: 100-continue" header to be present. After analysis of packet capture it is noted that BIG-IP removing the "Expect: 100-continue" header before forwarding the request to the pool member server.
  3. BIG-IP ASM policy can be in transparent or blocking mode

 

Cause

This is caused by the BIG-IP sending HTTP/1.1 100 Continue and removing the "Expect: 100-continue" header before forwarding the request to the pool member server
 

Recommended Actions

Follow the steps mentioned in the article K40165336


Additional Information

Before v15.x onwards BIG-IP will pass the  HTTP POST requests with \"Expect: 100-continue\" header to the backend server, However starting from v15.x BIG-IP will reply with HTTP/1.1 100 Continue, will wait for the next request from the client and then will pass this to the backend server, with stripping off \"Expect: 100-continue\" header." v15.x comes with a value set to 1. If we set it to 0, it would send "Expect: 100-continue" to the backend server and will not send HTTP/1.1 100 Continue.

answer_100_continue 1 ====> Remove the header
answer_100_continue 0 ====> Keeps the header
