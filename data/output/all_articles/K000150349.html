Environment

  • BIG-IP (managed by BIG-IQ)
  • BIG-IQ
  • REST DB

Cause

The issue occurs due to corruption in the REST database (REST DB) on the affected BIG-IP device. This corruption prevents proper communication between the BIG-IQ and the BIG-IP during the upgrade process, leading to failures in retrieving or transferring software images.

Recommended Actions

1. Rebuild the REST Database by running the below command on the affected BIG-IP device via CLI:

#clear-rest-storage

Notes: 
- This command will rebuild the REST DB and restart restjavad and restnoded services automatically. This will reset the trust to BIG-IQ as well.
- Refer to knowledge base article K67220984 before executing the "clear-rest-storage" command.

2. After running clear-rest-storage, verify that the REST API is functioning correctly by executing this command on the affected BIG-IP device:

# curl -kv https://localhost/mgmt/cm/autodeploy/software-images -u admin | jq .

Enter admin credentials when prompted. If it returns HTTP/1.1 200 OK, it indicates that the REST DB has been rebuilt.

3. After rebuilding REST DB, unmanage and remanage the BIG-IP by following the below knowledge articles to build the trust again between BIG-IP and BIG-IQ.

K42354921: How to remove a BIG-IP device from BIG-IQ
https://my.f5.com/manage/s/article/K42354921

K04185857: How to add a BIG-IP device to BIG-IQ
https://my.f5.com/manage/s/article/K04185857

4. Rediscover/Reimport the BIG-IP again by following the below knowledge base article.

K63557165: Discovering a BIG-IP device with a BIG-IQ system and importing the BIG-IP service configuration
https://my.f5.com/manage/s/article/K63557165

5. Once all steps above are completed successfully, retry upgrading your software via BIG-IQ.
