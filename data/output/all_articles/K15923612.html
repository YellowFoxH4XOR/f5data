Topic

This article applies to BIG-IP 13.x through 21.x. For information about other versions, refer to the following article:

  • K14267: Configuring Route Health Injection for use with BGP (11.x - 12.x)
  • K6165: Configuring Route Health Injection (RHI) for use with BGP (9.x - 10.x)

You should consider using this procedure under the following condition:

  • You want to configure Route Health Injection (RHI) for BIG-IP virtual server addresses. RHI allows the BIG-IP system to advertise routes for virtual server addresses by way of the Border Gateway Protocol (BGP).

Description

You can configure Route Health Injection (RHI) for a virtual address so that the BIG-IP system advertises the availability of the address as a host route. When the virtual address is available, the BIG-IP system sends the address information to the neighboring router device, which periodically propagates the virtual address availability according to the RHI information it receives.

For example, if you enable Route Advertisement for the virtual address 192.168.10.100, and configure Border Gateway Protocol (BGP) to redistribute kernel routes, the system sends the virtual address contained in the Network Layer Reachability Information (NLRI) of the BGP Update message to BGP neighbors. The transaction is shown in the following figure.

Figure: BIG-IP BGP route advertisement for virtual address 192.168.10.100If the virtual address becomes unavailable, the BIG-IP system withdraws the route by sending a BGP update message to immediately withdraw the route. The transaction is shown in the following figure.

Figure: BIG-IP BGP route withdrawal for virtual address 192.168.10.100

You can select options in the following table when configuring route advertisement for a virtual address.

SettingDescription
AlwaysThe BIG-IP system always advertises the route for the virtual address, regardless of availability status. This requires an enabled virtual address.

Example: You want the BIG-IP to provide the service regardless of status of the backend servers. Instead of having the network reroute traffic elsewhere, you have configured actions (such as a redirect or an iRule to display a maintenance page) on the BIG-IP system to handle failures.

EnabledThe BIG-IP system advertises the route when the virtual address is available. This option is deprecated. Use Selective instead. For more information, refer to K85543242: Additional virtual address Route Advertisement configuration options available.
Disabled (default)The BIG-IP system does not advertise the route for the virtual address, regardless of the availability status.

Example: You do not require dynamic routing through route advertisements. For example, you configured static routes in internal testing environments.

SelectiveThe BIG-IP system advertises the route for the available virtual address based on the calculation method in Availability Calculation. This replaces the Enabled setting and has the same function.
AnyThe BIG-IP system advertises the route for the virtual address when any virtual server is available.

Example: Behind the virtual address, the service is available through different ports, for example HTTP/80, HTTPS/443 and HTTPS/8443 and as long as one of them are available you want to advertise the route.

AllThe BIG-IP system advertises the route for the virtual address when all virtual servers are available.

Example: Every application and service behind the virtual address is critical and required.

To configure the BIG-IP system to advertise routes for virtual server addresses by way of BGP, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP system is licensed to include the BGP routing protocol.
  • Your BIG-IP system is configured as a BGP peer with the upstream routers.

Procedures

  • Configuring route advertisement for the virtual server address using the Configuration utility
  • Configuring route advertisement for the virtual server address using tmsh
  • Configuring BGP to redistribute kernel routes
  • Verifying that the BIG-IP system is advertising the route by way of BGP

Configuring route advertisement for the virtual server address using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Address List.
  3. Select the virtual address for which you want to enable route advertisement.
  4. Under Configuration, select one of the following options for Route Advertisement:
    • Always
    • Enabled (Deprecated; Use Selective)
    • Selective
    • Any
    • All
  5. Select Update.

Configuring route advertisement for the virtual server address using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To configure route advertisement, use the following command syntax:

    modify ltm virtual-address <IP address> route-advertisement <value>

    In the previous example, <value> is one of the following options:

    • Always
    • Enabled (Deprecated; Use Selective)
    • Selective 
    • Any
    • All

    For example, to enable route advertisement for virtual server address 192.168.10.100, enter the following command:
    Note: After setting route-advertisement to selective with the following command, configure the Availability Calculation/server-scope setting as appropriate. For more information on server-scope, refer to the TMSH reference for virtual address.

    modify ltm virtual-address 192.168.10.100 route-advertisement selective

  3. To save the configuration, enter the following command:

    save sys config

Configuring BGP to redistribute kernel routes

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the IMI shell (imish), enter the following command.

    imish

  3. To enter enable mode, enter the following command:

    enable

  4. To enter configuration mode, enter the following command:

    configure terminal

  5. To enable the BGP routing process, use the following command syntax, where <ID> is the router ID:

    router bgp <ID>

  6. To configure BGP to redistribute kernel routes, enter the following command:

    redistribute kernel

  7. Exit the current mode by entering the following command:

    end

  8. Save the configuration by entering the following command:

    copy running-config startup-config

  9. Log out of imish by entering the following command:

    exit

Verifying that the BIG-IP system is advertising the route by way of BGP

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the imish, enter the following command.

    imish

  3. To enter enable mode, enter the following command:

    enable

  4. To display BGP routes that the system is advertising or learning, enter the following command:

    show ip bgp
