Description

SSL handshake fails between client machine and BIG-IP virtual server. SSL handshake failure fatal alert is generated after client send client hello. 
At the same time you can see the following log on /var/log/ltm:

warning tmm[<PID>]: 01260009:4: <client_IP>:<source_port> -> <VS_IP>:443: Connection error: ssl_select_suite:9908: alert(40) no shared ciphers
warning tmm[<PID>]: 01260026:4: No shared ciphers between SSL peers <client_IP>.<source_port>:<VS_IP>.443.
warning tmm[<PID>]: 01260013:4: SSL Handshake failed for TCP <client_IP>:<source_port> -> <VS_IP>:443

Environment

  • Virtual server configured on BIG-IP on HTTPS

Cause

This issue generally occurs when an older SSL client attempts to connect to the BIG-IP system using a less secure cipher. Or Respective Client SSL profile does not have the cipher presented by Client in client hello for SSL negotiation.

Recommended Actions

1. Take a tcpdump to find out what are the ciphers client is presenting in client hello. 
2. Check the cipher string configured in client SSL profile attached to the virtual server. 
3. Once you find the cipher string, use below command to see the list of ciphers available on the BIG-IP for the respective virtual server. 

tmm --clientciphers '<cipher_string>'

For example:

tmm --clientciphers 'DEFAULT:!DHE:!EXP:!LOW:!MEDIUM:!NONE:!SSLv3:!3DES:!TLSv1_1:!TLSv1'

Note: The default cipher list is DEFAULT.

4. Once list of ciphers client supports and list of ciphers virtual server has enabled are determined, then enable the required ciphers either in Client SSL profile on BIG-IP or enable the strong ciphers on client machines which are supported by BIG-IP cipher string.
