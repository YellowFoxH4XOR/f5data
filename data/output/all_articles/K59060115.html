Description

f5-cloud-libs is a set of Node.js libraries that assist in cloud template deployments.

In some cloud template deployments, such as failover via Cloud provider API, these libraries use a key to encrypt a required credential, which is saved to a local file. This credential file is then decrypted at failover time for use by the failoverProvider.js script.

After upgrading a BIG-IP device in a failover via-api HA pair that was configured using f5-cloud-libs to a version earlier than v14.1, the key used to decrypt the credential will not match the encryption key. The decryption process will fail and /var/log/cloud/azure/failover.log will log an error message that contains:

2021-05-03T16:52:02.224Z warn: symmetricDecrypt failed error:040A1079:rsa routines:RSA_padding_check_PKCS1_OAEP_mgf1:oaep decoding error
2021-05-03T16:52:02.227Z error: Failover failed: error:040A1079:rsa routines:RSA_padding_check_PKCS1_OAEP_mgf1:oaep decoding error

Note: This credential is not used in failover via-lb deployments.

Environment

A pair of BIG-IP devices using API failover has been deployed successfully using an F5 cloud template. An upgrade to a BIG-IP version earlier than v14.1 is performed and the configuration is restored using a UCS file.

For example, the devices are upgraded from BIG-IP v13.1.3.5 to v13.1.3.6.

Cause

After restoring the UCS file, the key used to decrypt the local credential file does not match the encryption key.

Recommended actions

If you are upgrading the HA pair to BIG-IP v14.1 or later, F5 strongly recommends migrating to the F5 Cloud Failover Extension.

To resolve this issue, you will need to retrieve the credential from a working BIG-IP device, then re-encrypt it to a local file on the upgraded BIG-IP device.

Note: You must have access to a device that has not yet been upgraded. F5 recommends upgrading one device at a time and verifying functionality before proceeding. If you do not have access to a working device, you must redeploy the HA pair using the F5 cloud template.

Azure is used in this example; if you are running the commands in Google, substitute gcp when specifying CLOUD_LIB_DIR.

Steps:

  1. On both BIG-IP devices, run the following commands:

    export CLOUD_LIB_DIR='/config/cloud/azure/node_modules/@f5devcentral'
    export TMP_CREDENTIALS_FILE='/tmp/.tmpPasswd'
    export BIG_IP_CREDENTIALS_FILE='/config/cloud/.passwd'

  2. On the BIG-IP device that has not yet been upgraded, run the following commands:

    f5-rest-node $CLOUD_LIB_DIR/f5-cloud-libs/scripts/decryptDataFromFile.js --data-file $BIG_IP_CREDENTIALS_FILE
    echo $BIG_IP_CREDENTIALS_FILE
    Copy the output of the previous command

  3. On the BIG-IP device that has been upgraded, run the following commands:

    f5-rest-node $CLOUD_LIB_DIR/f5-cloud-libs/scripts/encryptDataToFile.js --data-file $TMP_CREDENTIALS_FILE --out-file $BIG_IP_CREDENTIALS_FILE
    rm $TMP_CREDENTIALS_FILE
    Trigger failover to verify that the credential is successfully decrypted.

After upgrading the 2nd BIG-IP device in the HA pair, you must repeat step 3 on that device.
