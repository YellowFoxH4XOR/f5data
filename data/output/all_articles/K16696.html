Known Issue

Deleting a FIPS protected Secure Sockets Layer (SSL) key by handle may remove the SSL key from the FIPS card, while leaving the key in the BIG-IP configuration.

This issue occurs when all of the following conditions are met:

  • You have a FIPS protected SSL key that has a key name that is different from its FIPS-label.
  • Using the Traffic Management Shell (tmsh), you delete the SSL key by handle, instead of by name.

    For example:

    tmsh delete sys crypto fips by-handle 10

Impact

The FIPS-protected key is deleted from the FIPS device, but remains in the BIG-IP configuration. This situation causes connection failures if the key is mistakenly selected for use.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • New client SSL connections are failing.
  • A FIPS protected SSL key exists in the BIG-IP configuration when, for example, you run the following command:

    tmsh list sys crypto key

    A FIPS protected SSL key does not exist in the FIPs card when, for example, you run the following command:

    tmsh show sys crypto fips

Workaround

To work around this issue, make sure when you delete a FIPS protected SSL key by handle, that no corresponding reference to the key exists in the BIG-IP configuration. If you have already deleted the FIPS key, and the SSL key exists in the BIG-IP configuration, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Check if the corresponding key still exists in the BIG-IP configuration by typing the following command:

    list sys crypto key

  3. If the SSL key exists in the configuration, remove it by using the following command syntax:

    delete sys crypto key <key name>

  4. Save the configuration by typing the following command:

    save sys config
