Known Issue

The HTTP::disable iRules command may fail.

This issue occurs when the following condition is met:

  • The BIG-IP system triggers the HTTP::disable iRules command in a subsequent HTTP connection after completing a previous HTTP connection.

Impact

The BIG-IP system resets the affected HTTP connection, resulting in application failures.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • An HTTP connection that triggers the HTTP::disable iRules command fails to complete and your BIG-IP system resets the connection.
  • In the /var/log/ltm file, you observe an error message similar to the following example:

    011f0007:3: http_process_state_prepend - Invalid action:0x109040 (Server side: vip=<virtual server name> profile=<HTTP profile name> pool=<pool name> server_ip=<virtual server IP address>)

  • If you have configured your BIG-IP system to log TCP RST packets, you observe additional error messages similar to the following example in the /var/log/ltm file:

    Note: For more information about configuring the BIG-IP system to log TCP RST packets, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

    01230140:3: RST sent from <virtual server:port> to <client IP:port>, [<F5 internal code>] {peer} HTTP internal error (bad state transition)

    01230140:3: RST sent from <bigip IP:port> to <pool member IP:port>, [<F5 internal code>] HTTP internal error (bad state transition)
