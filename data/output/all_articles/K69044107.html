Description
When you reference solution K7392 to create iRule for universal persistence function, you may see the connection reset and similar error logs in /var/log/ltm like below:

err tmm1[<PID>]: 01220001:3: TCL error: /Common/JSESSIONID_iRules <HTTP_REQUEST> - attempt to use empty persistence key (line 1)     invoked from within "persist uie [HTTP::cookie "JSESSIONID"]"

Environment

  • BIG-IP
  • iRule
  • Universal Persistence Profile

Cause
The issue is seen when a client sends a malformed cookie header where the cookie value is empty. 

Recommended Actions
You can use an iRule similar to one of the following examples below to evaluate the client request before doing the persist. 

Option one - Checking the cookie value before doing persist uie:

when HTTP_RESPONSE {
    if { [HTTP::cookie exists "JSESSIONID"] } {
        persist add uie [HTTP::cookie "JSESSIONID"]
    }
}
when HTTP_REQUEST {
    if { [HTTP::cookie exists "JSESSIONID"] and [HTTP::cookie value JSESSIONID] ne "" } {
        persist uie [HTTP::cookie "JSESSIONID"]
    } else {
        set jsess [findstr [HTTP::uri] "JSESSIONID" 11 ";"]
        if { $jsess != "" } {
            persist uie $jsess
        }
    }
}

Note: You may need fine-tune the iRule base on your environment.

Option two - Using catch to avoid the error:

when HTTP_REQUEST {

    if { [HTTP::cookie exists "JSESSIONID"] } {
        catch { persist uie [HTTP::cookie "JSESSIONID"] }
    } else {
        set jsess [findstr [HTTP::uri] "JSESSIONID" 11 ";"]
        if { $jsess != "" } {
            persist uie $jsess
        }
    }
}
when HTTP_RESPONSE {
    if { [HTTP::cookie exists "JSESSIONID"] } {
        persist add uie [HTTP::cookie "JSESSIONID"]
    }
}

Note: You may need fine-tune the iRule base on your environment.
