Description

When using LTM policy with the condition to match specific "HTTP User-Agent", the condition is not met and LTM policy action is not triggered.

For example, with this LTM policy:

ltm policy drop-policy {
   requires { http }
   rules {
       rule1 {
           actions {
               0 {
                   shutdown
                   connection
               }
           }
           conditions {
               0 {
                   http-user-agent
                   browser-type
                   contains
                   values { Mozilla }
               }
           }
       }
   }
   status published
   strategy first-match
}

Traffic is not rejected when an HTTP request with the following HTTP header hits the Virtual Server.

User-Agent: Mozilla/5.0 (platform; rv:geckoversion) Gecko/geckotrail Firefox/firefoxversion

Environment

  • LTM Policy
  • Rule condition using "HTTP User Agent"

Cause

"HTTP User Agent" condition only recognizes the following (hard-coded) User-Agent values:

  • Chrome
  • Firefox
  • MSIE
  • Opera
  • Safari

There's no way to add or overwrite this list to add any other value, so any value that is not on the list will not be recognized as User-Agent.

Recommended Actions

"HTTP User Agent" setting for the LTM policy condition is not maintained and it's recommended to use the HTTP Header condition instead.
