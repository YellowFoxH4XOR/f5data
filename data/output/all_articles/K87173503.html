Description

Nagle's algorithm, defined in RFC896, is a congestion control mechanism designed to bundle smaller chunks of data for delivery into one big packet. Nagle's algorithm is a TCP optimization that makes the stack wait until all data is acknowledged on a connection before sending more data. This process, called "nagling", increases the efficiency of a network application system by decreasing the number of packets that must be sent.
Delayed acks specifies, when selected (enabled), that the system can send fewer than one ACK (acknowledgment) segment per data segment received. This is part of TCP congestion control that is defined in RFC 1122 and RFC 2581.
Nagle's algorithm and delayed ACKs should not be enabled on two sides of a TCP connection.

Environment

  • BIG-IP
  • Virtual server
  • TCP profile
  • Old Servers with Nagle's Algorithm enabled

Cause

Starting in BIG-IP version 11, Nagle's Algorithm is disabled by default in default TCP profile, and delayed ACKs is enabled by default in default TCP profile. For very old servers, which may still have Nagle's Algorithm enabled, the delayed ACKs feature may cause servers transmission delay.

Recommended Actions

Disable Nagle's Algorithm on the servers, or disable delayed ACKs on the BIG-IP system.
