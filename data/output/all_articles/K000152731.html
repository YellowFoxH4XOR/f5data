Description

On BIG-IP systems, Tomcat may continuously restart and the Web GUI becomes inaccessible. /var/log/tomcat/catalina.out log file may show repeated entries such as:

./run: syslog-ng is not listening to tomcat.pipe!

This indicates a problem with the syslog-ng service, which is required for Tomcat and other management daemons to function correctly.

Environment

  • BIG-IP LTM
  • Custom syslog-ng configuration using the include field in sys syslog

Cause

A misconfigured syslog-ng include section, specifically missing the required persist-name(<label>) attribute in custom destination definitions, prevents syslog-ng from properly handling named pipes such as tomcat.pipe. This causes Tomcat and related services to fail and restart repeatedly.

Recommended Actions

1. Check syslog-ng Configuration:
Review the custom include section in the syslog-ng configuration for missing persist-name attributes in destination blocks.

2. Correct the Configuration:
Add a unique persist-name(<label>) to each custom destination. For example:

destination MySYSLog1 { tcp("<IP_ADDRESS_1>" port(514) localip("<LOCAL_IP_1>") persist-name(mysyslog1)); };
destination MySYSLog1 { tcp("<IP_ADDRESS_2>" port(514) localip("<LOCAL_IP_2>") persist-name(mysyslog2)); };
filter f_alllogs { level (debug..emerg); };
log { source(s_syslog_pipe); filter(f_alllogs); destination( MySYSLog1); destination( MySYSLog2); };


3. Apply and Save the Configuration:
- Update the syslog-ng configuration with the corrected include section.
- Save the system configuration:
tmsh save sys config
- Restart the relevant daemons to apply changes:
bigstart restart syslog-ng restjavad restnoded httpd tomcat

4. Verify System Stability:
- Confirm that Tomcat and the GUI are accessible.
- Check that logs are being sent to the intended remote syslog servers.
