Known Issue

This is the result of a known issue. FirePass rotates its system log file every 24 hours at midnight. If the log rotation process takes longer than one second to complete, the previous day's log entries contained in the rotated log file are no longer displayed on the Reports: System Logs page in the FirePass Administrative Console.

This issue typically occurs when one or more of the following conditions are met:

  • The FirePass controller has a high CPU load when the log rotation process runs.
  • The FirePass controller has a large system log file; this may be due to a high volume of user activity, or in FirePass 6.0.1 it may be due to the log levels that are configured on the Device Management: Maintenance: Logs page. For example, the Warning log level creates more log entries than the Emergency log level.

F5 Product Development tracked this issue as CR68382 and it was fixed in FirePass 6.0.2. For information about upgrading, refer to the FirePass release notes.

Workaround

You can reduce the occurrence of this issue in FirePass 6.0.1 by configuring lower log levels in the Logging Options section on the Device Management: Maintenance: Logs page. For example, the Information log level creates the highest volume of logs and CPU utilization while the Emergency log level creates the lowest volume.

Note: The Logging Options feature was introduced in FirePass 6.0.1; therefore, you cannot perform this workaround on FirePass software versions prior to 6.0.1.

To determine which log level to use, refer to the descriptions of each log level listed in the FirePass online help on the Device Management: Maintenance: Logs page. Lower log levels are recommended for day-to-day use, while higher log levels can be useful while testing or troubleshooting. For example, you may want to set the Application Access log level to Information while troubleshooting a specific application issue, then set it to Critical for day-to-day use.
