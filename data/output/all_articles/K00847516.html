Description

Trying to log LTM events using the Request Logging profile, but it is not clear how to do it from the BIG-IP Manual.

The manual chapter in question is the Configuring Request Logging chapter of the External Monitoring of BIG-IP Systems: Implementations manual.

Environment

  • Request Logging
  • Virtual Server

Cause

None

Recommended Actions

The manual refers to configuring logging of HTTP request/response data using the Request Logging profile, which can be assigned to a virtual server which is load balancing your application traffic. Note that the virtual server needs a HTTP profile applied to log HTTP data.

The Request Logging profile itself, once configured and assigned, uses High Speed Logging (HSL) to send the logs directly out of TMM, to a pool of log servers. In this case the logs are being sent using the same TMM microkernel which handles all other traffic, hence high speed logging. As opposed to traditional syslog logging which uses the management interface.

You can log almost anything about the HTTP request/response - configured with the template in the Request Logging profile. The available values are summarized below in section Additional Information

For example, you can configure the Template field in the Request Logging section of the profile to use the following NCSA Common formatted log string:

${CLIENT_IP} - - ${DATE_NCSA} ${HTTP_REQUEST} ${HTTP_STATCODE} ${RESPONSE_SIZE}

Using the above string in the Template field would send logs similar to the following example:

Note: In this example, 10.10.10.1 is the client, date is Feb 24, HTTP GET request is sent, and 200 response is received which is 222 bytes long.

10.10.10.1 - - [24/Feb/2012:03:47:40 -0500] "GET / HTTP/1.1" 200 222

Note: the use of brace expansion ${VARIABLE_NAME} for values is recommended to prevent incorrect parsing when applying additional formatting strings between variables.

To summarise the steps needed to configure and Implement a Request Logging profile, refer to the below:

  1. Configure your virtual server and pool for handling application traffic, with a HTTP profile
  2. Create another pool, containing your log server

  3. Create the Request Logging profile by defining:

    • Request/Response logging Enabled/Disabled
    • Template
    • Protocol
    • HSL Pool
    • Everything else is optional
  4. Assign the Request Logging profile to your virtual server
  5. Pass HTTP traffic, the logs should be sent to the log pool

Additional Information

You can also create an iRule to do high speed logging to a pool, and perform the logging without a Request Logging profile.

The Request Logging profile can only be used with Remote logging. If you want to do local logging, which is not recommended in large amounts, you need to use iRules. Too much local logging will affect the system, but can be useful for debugging purposes.
