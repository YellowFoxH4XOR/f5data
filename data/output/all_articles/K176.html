Note: For information about BIG-IP LTM versions 9.x and 10.x, refer to K7566: Disabling nodes or pool members for maintenance (9.x - 10.x).

For BIG-IP LTM version 11.x, refer to K13310: Disabling nodes or pool members for maintenance (11.x)

When you disable a node, BIG-IP allows the current sessions to that node to complete (until the persistence timer times out), but does not allow new sessions to connect to that node.

Note: A session is defined as a connection from a client that does have a current persistence mapping to a node.

Connections from clients that already have a current persistence mapping (session) to a node are still permitted to access to that node even if it is in a disabled state, whereas connections from clients without a current persistence mapping (new clients) are not allowed to access to a disabled node. BIG-IP will send connections from new clients to a different node in the pool.

To gracefully disable a node or node address, type the following command:

bigpipe node <ip address of node> disable

For the <ip address of node> variable, you can specify a node address and port (for example, 192.168.21.1:80) or just a node address (for example, 192.168.21.1).

After running this command, the BIG-IP Controller does not allow new sessions to the disabled node. If persistence is enabled, persistent connections continue until the persistence timeout value is reached.

You can view current connections by typing the following command:

bigpipe node <ip address of node> show

To view all nodes and statistics by port, type the following command:

bigpipe node show

To enable a node, type the following command:

bigpipe node <ip address of node> enable

Important: Starting in BIG-IP version 4.0, if you use the keyword down instead of disable when disabling a node with the bigpipe node command, BIG-IP will disconnect the persistent connections. Further, if you enable svcdown_reset on your virtual server, BIG-IP will shut down the current connections immediately.
