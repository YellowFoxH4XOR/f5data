Description

Security log profile cannot be assigned to virtual servers using address list (traffic matching criteria, TMC). The following error message displayed: 

Configuration error: Virtual server (/Common/test_list) with TMC or security ACL/NAT/IPI/DoS/Eviction/Scrubber/Blacklist Publisher configured cannot co-exist between them.

Environment

  • Virtual server is configured with address list (traffic matching criteria, TMC)
  • Add security log profile to the virtual server

Cause

This is a correct mcpd validation error, the expected behaviour by default.

Recommended Actions

Starting with version 15 there is a new db variable afm.allowtmcvirtuals is implemented to allow disabling this validation. By name it appears to be as AFM specific, and while it allows ASM configuration to also be applied, doing so is not supported at this time.

The value of the variable is set to false by default:

(cfg-sync Standalone)(Active)(/Common)(tmos)# list sys db afm.allowtmcvirtuals
sys db afm.allowtmcvirtuals {
    value "false"
}

Change it to true:

(cfg-sync Standalone)(Active)(/Common)(tmos)# modify sys db afm.allowtmcvirtuals value true
(cfg-sync Standalone)(Active)(/Common)(tmos)# list sys db afm.allowtmcvirtuals
sys db afm.allowtmcvirtuals {
    value "true"
}

After the change the security log profile can be assigned to the virtual server using traffic matching criteria.
Important: TMC virtual servers are not currently supported for use with ASM. It is not recommended to use this db key to allow configuration of ASM policies or logging profiles with TMC virtual servers. This should be considered experimental only.  Please see K28358628 for more information.
