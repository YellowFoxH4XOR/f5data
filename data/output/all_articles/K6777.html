Known Issue

This is the result of a known issue. The BIG-IP GTM system utilizes an SNMP prober for supported third party load balancers and host systems to gather information used to make decisions about how the BIG-IP GTM will provide responses to a DNS request. In doing so, the incorrect server is used for SNMP prober mapping in the big3d utility.

The type of server chosen under the Product section of the Configuration utility is used to map to that product's corresponding SNMP OIDs. Those SNMP OIDs will then be used to query the device and obtain the information BIG-IP GTM uses for decision handling.

The following table shows the incorrect BIG-IP GTM interpretation of the server-to-SNMP prober mappings in the big3d utility:

ProductIncorrect mapping within big3d
Sun SolarisWindows 2000 Server
Windows NT 4.0Windows 2000 Server
Windows 2000 ServerSun Solaris

F5 Product Development tracked this issue as CR65293 and CR65292, and it was fixed in BIG-IP GTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP GTM Release Notes.
