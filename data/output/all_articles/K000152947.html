K000152947: F5OS-A - If the file export fails with status "failed to send file" the failure reason is not clear.

Published
2025-08-11

Applies to

Source

Description

When using the file export command on F5OS-A (F5OS - Appliance) version 1.8.0 to transfer backup files to a remote Linux system via SCP or SFTP, the operation may fail with status messages such as failed to send file or Couldn't connect to server. The file transfer-status command displays both failed and successful attempts. Log entries from utils-agent may include:

utils-agent file transfer error ERROR="failed to send file"

or

AUDITLOG="File transfer AUDIT. Failed Export file operation. protocol(SCP) ..."

Failures often occur when the remote file path is not fully specified or user permissions are insufficient.

Environment

  • Product: F5OS - Appliance
  • Version: 1.8.0
  • File transfers using file export CLI command
  • User accounts: root, admin, or other non-root users

Cause

File transfers fail if the specified remote file path is invalid or if the user does not have write permissions for the target directory on the remote host. When only a filename is provided (without a full path), the system attempts to write to the user's home directory on the remote host; if this directory does not exist or lacks proper permissions, the transfer fails. Error messages in logs and CLI output do not provide detailed reasons for these failures.

Recommended Actions

  • Always specify an absolute path for the remote-file parameter in the file export command that points to a directory where your user has write permissions.

Example:

file export local-file configs/backup.xml remote-host <IP_ADDRESS> remote-file /tmp/backup.xml protocol scp username <username> insecure

 

  • Ensure that the user account used for transfer has appropriate write access on the target directory of the remote host.
  • Use file transfer-status to review both failed and successful operations for troubleshooting.

Additional Information

Upcoming version 2.0.0 provides clearer error details visible on platform.log
