Known Issue

The BIG-IP system may erroneously import incorrect SSL certificates and keys to the filestore. This issue occurs when one of the following conditions is met:

  • Prior to an 11.x upgrade, the BIG-IP system has an SSL certificate, which has the same name as a legitimate SSL certificate in the /config/ssl/ssl.crt directory, residing in another directory under the /config directory
  • Prior to an 11.x upgrade, the BIG-IP system has an SSL key, which has the same name as a legitimate SSL key in the /config/ssl/ssl.key directory, residing in another directory under the /config, /home, /etc, or /root directories
  • The UCS archive file that is installed on a BIG-IP system running 11.x contains an SSL certificate, which has the same name as a legitimate SSL certificate in the /config/ssl/ssl.crt directory, residing in another directory under the /config directory
  • The UCS archive file that is installed on a BIG-IP system running 11.x contains an SSL key, which has the same name as a legitimate SSL key in the /config/ssl/ssl.key directory, residing in another directory under the /config, /home, /etc, or /root directories

    For example, if the BIG-IP system or the UCS archive has an SSL certificate with file and path name /config/ssl/ssl.crt/myabc.crt and another SSL key with file and path name /config/myabc.crt, the BIG-IP system will inappropriately import the /config/myabc.crt file instead of the /config/ssl/ssl.crt/myabc.crt file to the filestore during an upgrade to 11.x or during an UCS archive restoration.

    If the BIG-IP system or the UCS archive has an SSL key with file and path name /config/ssl/ssl.key/myabc.key and another SSL key with file and path name /config/ssl/myabc.key, the BIG-IP system will inappropriately import the /config/ssl/myabc.key file instead of the /config/ssl/ssl.key/myabc.key file to the filestore during an upgrade to 11.x or during an UCS archive restoration.

Impact

The BIG-IP system may fail to load configuration.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H381831 on the Diagnostics > Identified > Low screen.
  • If the affected certificate or key is associated with an SSL profile, the BIG-IP system will fail to load configuration and log an error message that appears similar to the following example to the /var/log/ltm file :

    01070313:3: Error reading key PEM file /config/filestore/.stage_d/1_d/Common_d/certificate_key_d/:Common:mykey.key_1 for profile /Common/myssl: error:0B080074:x509 certificateroutines:X509_check_private_key:key values mismatch

  • If the affected key is imported to a FIPS card, the BIG-IP system will fail to load configuration and log error messages that appear similar to the following example to the /var/log/ltm file:

    010713e4:3: FIPS subsystem reported error while attempting file object operation: FipsMgr::get_handle_from_modulus error unable to obtain handle. Modulus(bb:75:6d...a7:9e:d7), FIPS:APPLICATION ERROR.
    01070712:3: Caught configuration exception (0), unable to obtain key handle from modulus. For key (/Common/mykey.key) - sys/validation/FileObject.cpp, line 4531.

Workaround

If you have not upgraded the BIG-IP system, you can prevent this issue by ensuring the BIG-IP system has SSL certificates or keys residing in only the /config/ssl/ssl.crt or /config/ssl/ssl.key directories and removing other copies residing in a different directory if they exist.

If you have encountered this issue after restoring an affected UCS archive, you can modify the UCS archive by removing the incorrect SSL certificates or keys and restoring the UCS archive. To do so, perform the following procedure:

Impact of procedure: None.

  1. Log in to the command line.
  2. Change directories to the /var/tmp directory by entering the following command:

    cd /var/tmp

  3. Make a copy of the UCS archive and change the file extension to .tar.gz by entering the following command:

    cp -p <path/to/UCS> /var/tmp/sol13534.tar.gz

    For example, if the UCS archive is located in /tmp/MyUCS.ucs, you would enter the following command:

    cp -p /tmp/MyUCS.ucs /var/tmp/sol13534.tar.gz

  4. Unzip the UCS archive by entering the following command:

    gunzip /var/tmp/sol13534.tar.gz

  5. List all files with extension .crt or .key in the UCS archive by entering the following command:

    tar -tf /var/tmp/sol13534.tar --wildcards "*.crt" --wildcards "*.key"

  6. Inspect the output list and look for files that have the same name as those in the /config/ssl/ssl.crt or /config/ssl/ssl.key directories.

    For example:

    /config/ssl/ssl.key/myabc.key
    /config/ssl/myabc.key

    If the output list contains the above excerpts, you must remove the /config/ssl/myabc.key file.

  7. Remove these files that do not reside in the /config/ssl/ssl.crt or the /config/ssl/ssl.key directories from the UCS archive by entering the following command:

    tar --delete -f /var/tmp/sol13534.tar <path/to/.crt or .key file A> <path/to/.crt or .key file B>...

    For example, to remove the /config/myabc.crt and /config/ssl/myabc.key files from the UCS archive, enter the following command:

    tar --delete -f /var/tmp/sol13534.tar config/myabc.crt config/ssl/myabc.key

  8. Extract the SPEC-Files and SPEC-Manifest files from the UCS archive by entering the following command:

    tar -xf /var/tmp/sol13534.tar SPEC-Files SPEC-Manifest

  9. Edit the SPEC-Files file using a text editor of your choice.
  10. Locate and delete entries of the .crt or .key files removed in step 7.

    Using the example in step 7, you would locate and delete the following entries:

    N /config/myabc.crt 7aacd217f6244d4607c9df284c05c104 33188 0 48 944 1335151274 -
    N /config/ssl/myabc.key 962887d794475d99869750a52dd27e53 33188 0 48 887 1335152295 -

  11. Save the changes to the SPEC-Files file and exit the text editor.
  12. Edit the SPEC-Manifest file using a text editor of your choice.
  13. Locate and delete entries of the .crt or .key files removed in step 7.

    Using the example in step 7, you would locate and delete the following entries:

    /config/myabc.crt
    /config/ssl/myabc.key

  14. Save the changes to SPEC-Manifest file and exit the text editor.
  15. Update the UCS archive file with the modified SPEC-Files and SPEC-Manifest files by entering the following command:

    tar -uf /var/tmp/sol13534.tar SPEC-Files SPEC-Manifest

  16. Compress the modified UCS archive file by entering the following command:

    gzip /var/tmp/sol13534.tar

  17. Rename the modified UCS archive file to .ucs extension by entering the following command:

    mv /var/tmp/sol13534.tar.gz /var/tmp/sol13534.ucs

  18. Restore configuration using the modified UCS archive file by entering the following command:

    tmsh load sys ucs /var/tmp/sol13534.ucs
