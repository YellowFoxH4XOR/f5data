Known Issue

Connections that have reached idle timeout may not be removed from the PVA connection table when handled by a FastL4 profile, and PVA acceleration is set to guaranteed.

This issue occurs when all of the following conditions are met:

  • You have a Performance Layer 4 profile (FastL4) configured.
  • You have set the pva.acceleration global database variable to guaranteed.
  • You are running BIG-IP 11.4.1 with HF6, HF7, HF8 or HF9.

Impact

BIG-IP system performance may degrade over time. Connections may fail intermittently.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H498074 on the Diagnostics > Identified > Medium screen.
  • New connections may fail intermittently.
  • In the /var/log/ltm file, you may observe an error message similar to the following example:

    err tmm4[9876]: 01230140:3: RST sent from 192.168.1.1:123 to 192.168.1.100:80, [0x189670e:1420] TCP 3WHS rejected

Workaround

To work around this issue, you can modify tmm_init.tcl to remove idle or abandoned flows from the ePVA connection table. To do so, perform the following procedure:

Impact of workaround: The following procedure requires that you reboot the BIG-IP system; you should perform the procedure only during a scheduled maintenance period.

  1. Log in to the command line.
  2. Type the following command:

    echo "EPVA::enable_fix_reset 1" >> /config/tmm_init.tcl

  3. Restart the system services by typing the following command:

    bigstart restart
