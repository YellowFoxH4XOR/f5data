Topic

You should consider using this procedure under the following conditions:

  • Enterprise Manager is unable to use the current database due to database corruption.
  • You are downgrading Enterprise Manager from a newer version.
  • You want to purge a database of current information, including statistical information, and all data for discovered devices.

Description

As of Enterprise Manager 1.7.0, Enterprise Manager stores the managed device information and statistics in MySQL databases. If you have to purge your database, you can build a new statistics or main database using CLI commands on Enterprise Manager.

In the event of database corruption, you will see messages that appear similar to the following on the Enterprise Manager console:

emerg logger: Re-starting emstatsd

You may see error messages that appear similar to the following in the /var/log/em log file:

emstatsd err [15060]: 040a0100: 3: Could not initialize EM daemon stats: Wrong version of db stats January 25 3:29:48 p.m. local/GSC-MEM4F5-RECN emstatsd err [15105]: 040a0102: 3: The stats Has an incorrect database version (2.3.0.4 expecting, but got 3.0.0.2). Restarting in 15 seconds.

emstatsd[3309]: 0402010e:3: EX! StatLoader.cpp:1092::flush:mysqlpp::BadQuery 'Table'./f5em_extern/perfmon_pool_stat' is marked as crashed and should be repaired'

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have root access to the Enterprise Manager command line.
  • In the case of a corrupt MySQL database, before using this procedure, F5 recommends that you attempt to repair the MySQL database. To do so, refer to K10736: Enterprise Manager may experience MySQL database corruption, for instructions on how to repair Enterprise Manager MySQL databases.

Procedures

Wiping the Enterprise Manager databases

In the event that Enterprise Manager databases are no longer accessible, or you have to completely purge the information, you can remove and build a new empty database. To do so, perform the following procedure:

Impact of procedure: This procedure will remove the Enterprise Manager database configuration, including all statistical information, discovered devices, and user configuration set (UCS) archives for discovered devices. In addition,  Enterprise Manager will not be fully functional while the procedure is taking place.

Important: Rebuilding the Enterprise Manager database may not resolve all issues, and you might need to perform a clean install of Enterprise Manager.

  1. Log in to the Enterprise Manager command line.

    Note: If you access the Enterprise Manager command line using a self IP for this step, you will lose access when bigstart stop is performed in step 2. F5 recommends that you access the Enterprise Manager command line using the management IP address or the serial console port for this procedure.

  2. To stop Enterprise Manager services, type the following command:

    bigstart stop

  3. To delete the statistics database, type the following command:

    rm -f /shared/em/mysql_shared_db/f5em_extern/*

  4. To recreate the statistics database, type the following command:

    /etc/em/f5em_extern_db_setup.sh

  5. To recreate the main database, type the following command:

    /etc/em/f5em_db_setup.sh

  6. To restart Enterprise Manager services, type the following command:

    bigstart start

  7.  As Enterprise Manager initializes, type the following tail command.

    tail -f /var/log/em

    You should see the system checking each database table, and when the process has finished, you will see the following message:

    Completed statistic tables error check

  8. When the statistics table error check has completed, you can view the devices using the Configuration utility.

    Note: In the Device > Statistics menu of the Configuration utility, you will see No Data displayed for all devices for a brief period, but the graphs will start showing up as the system begins to populate the new database.
