K000158985: F5 Access iOS Per-App VPN: Native Apps Work But Safari Doesn't Trigger VPN

Source

Description

Safari and Safari-based progressive web apps (PWAs) on iOS devices not triggering the F5 Access per-app VPN connection, while managed native apps correctly triggered the VPN based on the configured domain list.

Environment

  • IOS
  • Per-app VPN deployment
  • Native managed apps successfully triggering VPN based on domain configuration
  • Safari and Safari-based progressive web apps failing to trigger VPN

Cause

VPN configuration profile missing the SafariDomains key required for Safari and Safari-based apps to trigger the per-app VPN connection

Recommended Actions

Add a SafariDomains key to the VPN configuration profile payload containing all hostnames used by web applications that should trigger the VPN.

In the F5 per-app VPN examples for iOS 3.x, this is done with the SafariDomains key in the VPN payload, for example (old doc F5 Access for iOS: Migration from 2.1.x to 3.x):

<key>SafariDomains</key>
<array>
<string>test.siterequest.com</string>
<string>test2.siterequest.com</string>
...
</array>

For deployment without MDM, create a .mobileconfig file with:

PayloadType = com.apple.vpn.managed.applayer

VPNSubType = com.f5.access.ios

SafariDomains = array of domain strings (e.g., "test.example.com")

and then manually install that profile on devices (Apple Configurator, email, web download, etc.).

SafariDomains is part of the VPN configuration profile payload, not an app setting.
Apple’s Configuration Profile Reference makes it clear that per-app VPN is defined via a configuration profile (com.apple.vpn.managed.applayer), and keys like SafariDomains only live inside that profile.

This is quite a bit more complex than using MDM, however.

Note that per-app VPN does not support Web Logon mode.

Consult Apple documentation for deployment guidance if needed: Configuration Profile Reference and AppLayerVPN documentation.
