Topic

Network Access packet filter rules control the type of network traffic that is allowed through a Network Access VPN tunnel. All packet filter rules are evaluated on the server and not the client.

When packet filter rules are enabled, the FirePass controller will evaluate the global packet filter rules first, starting with the top packet filter rule. The first packet filter rule match found will be used. If a global packet filter rule match has an Action value of Continue, the FirePass controller will evaluate the resource group level packet filter rules for that match. Similar to global packet filtering, the top resource group packet filter rule will be evaluated first, and the first packet filter rule match found will be used.

Note: The default rule is drop packet for both global and resource group packet filtering; you cannot change this default rule.

Note: Applied packet filter rules take effect immediately.

Each packet filter rule includes a Logging feature. When this feature is enabled, every rule match will be logged. This feature can be useful for troubleshooting Network Access connectivity issues.

Important: The packet filter Logging feature may lead to gratuitous logging, which can affect FirePass performance. Therefore, F5 Networks strongly recommends enabling the packet filter Logging feature for troubleshooting purposes; the packet filter Logging feature should be disabled unless there is a specific need for it. For more information about packet filter logs, refer to K10749: Packet filter system logs.

Enabling Network Access packet filter rules

  1. From the Administrative Console, click Network Access.
  2. Click Global Settings.
  3. Under Network Access Settings, select the Use Packet filter to access LAN check box.
  4. Click the Apply these rules now button.

Configuring global packet filter rules

  1. From the Administrative Console, click Network Access.
  2. Click Global Settings.
  3. Under Packet Filter Rules, click Add New Rule.
  4. Define the global rule as follows:
     
    FieldDefinition
    Rule NameA reader-friendly text name
    ProtocolTCP, UDP, ICMP, or All protocols
    Dst PortPort number or port range as first:last (for example 0:65535). An empty field means any port. Specifying a port has no affect on ICMP packets
    Dst Address/MaskThe destination host IP address: for example, 192.168.2.1 or subnet/mask; for example, 192.168.2.0/24 or 192.168.2.0/255.255.255.0. 0/0 means any address
    Src Address/MaskThe source host IP address: for example, 192.168.2.1 or subnet/mask; for example, 192.168.2.0/24 or 192.168.2.0/255.255.255.0. 0/0 means any address
    ActionAccept, Reject, or Continue
  5. After you define the global filter rule, click the Save button.
  6. Click the Apply these rules now button.

Configuring resource group packet filter rules

  1. From the Administrative Console, click Network Access.
  2. Click Resources.
  3. From the Resource Group drop-down box, select the resource group for which you want to apply the packet filter rules.
  4. Click the IP Group Filters tab.

    Note: The IP Group Filters tab will not be available until the packet filter rules are enabled.
  5. Under Group Packet Filter, click Add New Rule.
  6. Define the resource group rule as follows:
     
    FieldDefinition
    Rule NameA reader-friendly text name
    ProtocolTCP, UDP, ICMP, or All protocols
    PortPort number or port range as first:last (for example 0:65535). An empty field means any port. Specifying a port has no affect on ICMP packets.
    Address/MaskThe destination host IP address: for example, 192.168.2.1 or subnet/mask; for example, 192.168.2.0/24 or 192.168.2.0/255.255.255.0. 0/0 means any address.
    ActionAccept, Reject, or Continue.
  7. After the resource group filter rule has been defined, click the Save button.
  8. Click the Apply these rules now button.

Packet filter rules processing

When packet filtering has been enabled, the order of events are as follows:

  • The FirePass controller passes the packet received from the Network Access VPN connection to the global packet filter rule set.
  • The top global packet filter rule is evaluated first. If there is no match, the next global packet filter rule will be evaluated.
  • If there is a match, the matched global packet filter rule will be applied.

    Note: If there is no match among the configured packet filter rules, the default rule will apply (drop packet).
  • If the matched global packet filter rule has an Action value of Continue, the FirePass passes the packet to the resource group packet filter rule set corresponding to the Network Access VPN connection.
  • The top resource group packet filter rule is evaluated first. If there is no match, the next resource group packet filter rule will be evaluated.
  • The first matching rule will be applied.

    Note: If there is no match among the configured packet filter rules, the default rule will apply (drop packet).
