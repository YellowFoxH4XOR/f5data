K000153122: CFE Declaration Randomly Reverts

Published

Source

Description

In BIG-IP LTM deployments on AWS using the Cloud Failover Extension (CFE), the CFE declaration may unexpectedly revert to a previous or default configuration after certain operations, such as software upgrades. This reversion can result in incorrect failover functionality. The issue is characterized by the CFE declaration reverting to what is stored in /config/cloud/cfe_config.json.

Environment

  • Product: BIG-IP LTM
  • Cloud Provider: AWS
  • Deployment Method: AWS CloudFormation Templates (CFT), specifically older v1 templates (e.g., Template v6.0.0 for 3NIC clusters)

Cause

The root cause is the re-execution of the EC2 instance user-data script after a BIG-IP software upgrade that involves booting into a new volume. When this occurs, the local cloud-init cache - which tracks whether user-data has already run, is missing, causing cloud-init to treat the instance as new and execute user-data again. In older CFT deployments, this script includes logic to reapply the initial CFE configuration from cfe_config.json or CloudFormation metadata, overwriting any manual changes made since deployment. Newer v2 templates use bigip-runtime-init for onboarding, which does not overwrite existing configurations if modules are already present.

Recommended Actions

  1. Remove User-Data Script from Existing Instances:
    - For instances deployed with older CFTs, remove the user-data script from each EC2 instance’s configuration to prevent it from running after future upgrades.
    - Steps:
    1. Stop the EC2 instance.
    2. In AWS EC2 Console, select your instance and choose “Actions” > “Instance settings” > “Edit user data.”
    3. Remove all content from the user data field and save.
    4. Restart your instance.
  2. Use Latest Deployment Templates for New Deployments:
    - Deploy new BIG-IP instances using updated CFT v2 templates that utilize bigip-runtime-init for onboarding and extension installation/configuration.
    - bigip-runtime-init is idempotent; it will not overwrite existing configurations if modules are already installed.
  3. manual Config Sync Consideration:
    - The issue is more likely when manual config sync is enabled (auto sync disabled). Ensure you remove user-data in these environments.
  4. No Impact on Normal Reboots:
    - Standard reboots or stop/starts do not trigger user-data execution unless there’s an instance ID change (such as after installing a new boot volume).
