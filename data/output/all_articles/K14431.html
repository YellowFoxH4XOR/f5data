Known Issue

A standby BIG-IP system may not update connection information for established mirrored connections.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP systems, in an HA Sync-Failover device group, are set in an active/standby configuration.
  • You configure the BIG-IP systems to use both a primary and secondary IP address for mirroring.
  • You enable Connection Mirroring on a virtual server that uses a FastL4 profile.
  • A standby system either reboots or is added to the HA failover group while the active system processes connections for a FastL4 virtual server.

When the mirroring connection is established between an active and a standby BIG-IP system, the standby system intermittently fails to update the connection flow information for established FastL4 virtual server connections.

Note: This issue does not affect connections established after the mirroring connection has been established between the active and standby systems.

Impact

In the event of a failover, the affected established connections may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The standby system's connection table may not match the active system for the affected established connections.
    • The idle times for the affected connections may differ between the active and standby BIG-IP systems.
    • The connection entries for the affected virtual servers may differ between the active and standby systems.
  • Established connections to the affected FastL4 virtual servers may fail in the event of a failover.

Workaround

To work around this issue, you can configure the BIG-IP systems in a failover group to use only a primary mirror address. To do so, perform the following procedure:

Impact of workaround: If the primary mirroring network fails, the BIG-IP systems are unable to fall back to a secondary mirroring network.

Note: You must perform this procedure on each member of the Sync-Failover device group.

  1. Log in to the Configuration utility.
  2. Navigate to System > High Availability > Device Connectivity.
  3. Click Mirroring.
  4. From the Secondary Local Mirror Address box, select None.
  5. Click Update.
  6. Repeat this procedure for each member of the Sync-Failover device group.
