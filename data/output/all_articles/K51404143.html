Known Issue

The BIG-IP system may fail to load the configuration after you upgrade the system. This issue occurs when all of the following conditions are met:

  • An internal data group existed in the BIG-IP configuration before you upgraded the system.
  • The internal data group is of string type and has at least one record that contains an open/close brace as part of its data.

    For example:

    ltm data-group internal /Common/my_data_group {
    records {
    first_record {
    data }
    }
    second_record {
    data {
    }
    }
    type string
    }

  • The BIG-IP system is upgraded to a version listed in the Applies To box, located in the upper-right corner of this article.
  • The BIG-IP system is then booted to the upgraded volume.

Impact

The BIG-IP system is unable to load its configuration upon booting to the upgraded volume.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to load the configuration after booting into an upgraded volume, and remains in the inoperative state.
  • In the /var/log/ltm file, you might observe error messages similar to the following example:

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all" - failed. -- Syntax ne: 41) "second_record" unknown property
    err mcpd[<pid>]: 01070425:3: Full configuration load failed.

Workaround

There is no work around for this issue. To prevent this issue from occurring, you must ensure that the existing data groups have no record that contains an open/close brace as part of its data before you perform an upgrade. To recover from this issue, you must edit, from the command line, the data groups' configuration stanza in the /config/bigip.conf file. To do so, perform the following procedure:

Impact of workaround: Any syntax errors in the /config/bigip.conf file may result in the BIG-IP system being unable to load the configuration, until the error is rectified.

  1. Log in to the command line of the affected BIG-IP system.
  2. Create a backup of the /config/bigip.conf file by typing the following command:

    cp -p /config/bigip.conf /var/tmp/bigip.conf.sol51404143

  3. Edit the /config/bigip.conf file using a text editor of your choice, for example vi.
  4. Locate the data group configuration stanza that is causing this issue. Using the example in the previous section, the my_data_group data group configuration stanza should look similar to the following example:

    ltm data-group internal /Common/my_data_group {
    second_record {
    data {
    }
    }
    type string
    records {
    first_record {
    data }
    }
    }

  5. Place the records in the correct order. Using the previous example, the my_data_group data group configuration stanza should look similar to the following example:
    ltm data-group internal /Common/my_data_group {
    records {
    first_record {
    data }
    }
    second_record {
    data {
    }
    }
    type string
    }

  6. Remove the open/close brace, and replace it with your desired data; ensure that there is no open/close brace in your replacement data. If you want to use an open/close brace in your replacement data, you must add quotes around it and escape the quotes with a backslash. For example, data } in first_record must be replaced with data "\"}\"" for the system to accept and load the configuration. Using the previous example, the modified my_data_group data group configuration stanza should look similar to the following example:

    ltm data-group internal /Common/my_data_group {
    records {
    first_record {
    data "\"}\""
    }
    second_record {
    data "\"{\""
    }
    }
    type string
    }

  7. Save the changes and exit the text editor.
  8. Load the configuration by typing the following command:

    tmsh load sys config
