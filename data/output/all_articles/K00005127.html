Description

The following symptoms may be observed when encountering this issue:

  • BIG-IP receives a response packet for an established connection but appears to drop it, resulting in retransmissions and eventual failure of the connection, depending on the protocol in use.

  • A packet trace of the affected traffic while capturing internal TMM information shows the following in f5ethtrailer.analysis, for the frame which is dropped:

            [Expert Info (Warning/Sequence): Flow lost, incorrect VLAN, loose initiation, tunnel, or SYN cookie use]
                [Flow lost, incorrect VLAN, loose initiation, tunnel, or SYN cookie use]
                [Severity level: Warning]
                [Group: Sequence]

    Note: Information contained in square brackets ( [ ] ) within Wireshark is not part of the captured data, but additional information provided by Wireshark for analysis purposes.

  • The packet trace also shows an empty Flow ID and Peer ID:

            Flow ID: 0x0000000000000000
            Peer ID: 0x0000000000000000

    Note: The f5ethtrailer information will only be available when the f5ethtrailer protocol is enabled in Wireshark.

Environment

  • Packet trace

Cause

As indicated by the warning itself, there are various reasons this issue could be seen. The underlying cause is usually a network problem.

One example where this issue can occur, is if the BIG-IP receives a SYN/ACK in a frame destined for a destination MAC address which is not local to the BIG-IP system.

Recommended Actions

Review the packet trace to determine if there are any abnormalities with the frame received by the BIG-IP.

  • K1893: Packet trace analysis

If the packet trace has been reviewed and the connection flow does not appear to be unusual, but this problem still occurs, open a service request with F5 Support for further investigation.

Additional Information

To enable the f5ethtrailer protocol in Wireshark, navigate to Analyze > Enabled Protocols, then tick the checkbox next to F5 Ethernet Trailer.
