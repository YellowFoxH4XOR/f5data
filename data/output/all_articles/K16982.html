Topic

The Simple Object Access Protocol (SOAP) monitor does not currently include support for nested content.

Description

The BIG-IP system's SOAP monitor verifies only top-level content in a server response. If the return value is nested in the server response, the SOAP monitor does not verify the value and then marks the node or pool member down; this limitation is expected.

In the following example, the server response 'true' string matches the SOAP monitor configuration; however, the response is nested in the body of the response, so the BIG-IP system may mark the server down:

<SOAP-ENV:Envelope
    xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:SOAP-ENC="http://schemas.xmlsoap.org/soap/encoding/"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    xmlns:archwsdl="archserver.wsdl.dataflux.com"
    xmlns:archxsd="archserver.xsd.dataflux.com">
<SOAP-ENV:Body>
    <archxsd:datasvc_server__status.ddf_out>
        <table_>
            <row>
            <OUTPUT_VAL>true</OUTPUT_VAL>
            </row>
        </table_>
    </archxsd:datasvc_server__status.ddf_out>
</SOAP-ENV:Body>
</SOAP-ENV:Envelope>

Recommendations

F5 recommends that you modify server responses to send required SOAP monitor strings within the top level of the response (non-nested). Alternatively, you can use an HTTP monitor with an iRule for the pool member.
