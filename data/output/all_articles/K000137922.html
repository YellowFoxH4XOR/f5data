Description

RDG not working over HTTPs after applying ASM security policy.

Environment

BIG IP ASM AWAF

Cause

The BIG-IP ASM system does not currently support RDG over HTTPs. Typically, these requests can be identified by the following unique HTTP attributes:

HTTP path/URI: /remoteDesktopGateway/

HTTP methods: RDG_IN_DATA or RDG_OUT_DATA

The BIG-IP ASM system will block these requests and log the following violation:

Request blocked, violations: Illegal method.

Recommended Actions

You can configure a irule to bypass the BIG-IP ASM system for connections that use RDG over HTTP. To do so, perform the following procedure:

Log in to the Configuration utility.

Navigate to Security ›› Application Security : Headers : Methods

Click Create

Change to Advanced

Click Custom

For Custom Method: type RDG_IN_DATA

For Act As Method: chose GET or POST

Click Create.

Repeat the same for "RDG_OUT_DATA" method.

Click Apply Policy

Configure an iRule and associate it with the BIG-IP ASM-enabled virtual server to bypass the BIG-IP ASM system for RDG over HTTP requests. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Log in to the Configuration utility.

Click Local Traffic.

Click iRules.

Click iRule List.

Click Create.

For Name, type a name for the iRule.

For Definition, type the following iRules syntax.

Note: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any changes in an appropriate environment.

ltm rule /Common/RDP_over_HTTPs {
when HTTP_REQUEST {
if { ([HTTP::path] eq "/remoteDesktopGateway/") and \
(([HTTP::method] equals "RDG_IN_DATA") or ([HTTP::method] equals "RDG_OUT_DATA"))}{
ASM::disable
log local0. "ASM disabled."
} else {
ASM::enable /Common/Brute_Force_WAF
log local0. "ASM enabled. Current ASM policy is [ASM::policy]"
}
}
}

 

Click Finished.

Click Local Traffic.

Click Virtual Servers.

Click Virtual Server List.

Under Resources for the BIG-IP ASM-enabled virtual server, click Edit.

In iRules, click Manage.

In the Available box, click the iRule that you created in the previous procedure.

Move the iRule to the Enabled box.

Click Finished.
