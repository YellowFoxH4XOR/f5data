Description

  • A branch rule using "string first -nocase" may not work as expected

 

Environment

  • BIG-IP with APM
  • VPE branch rule uses the function "string first" with the "-nocase" option and the match extends past position 21
  • Example:
  • session.custom.variable contains string "LDsO profile email PkelMaI"
  • branch rule is
  • expr {[string first -nocase "kelmai" [mcget {session.custom.variable}]] >= 0}

 

Cause

APM uses TCL syntax for branch rules, but the code to process these is different from iRules, using small size variables to store strings. This is tracked with BugID 1238897.

 

 Recommended Actions

Avoid using "-nocase"

Alternatives to the example above:

expr {[string first -nocase "kelmai" [string tolower [mcget {session.custom.variable}]]] >= 0}

or

expr {[string tolower [mcget {session.custom.variable}]] contains "kelmai"}
