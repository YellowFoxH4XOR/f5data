Description

When an APM Client connects to a Windows Domain, you have the option to Register the client with DNS
However, Windows will Register both the VPN Assigned IP Address and the local IP Address.
This can cause issues with Windows Applications like JAMF or SCCM which use the Dynamic DNS Entries to push Software to the clients.

Environment
  • BIG-IP Edge Client for Windows
  • Connecting to Windows Domain

Cause

This is caused by the fact that all Active Network Adapters Register their IP Address with the Windows DNS Servers
Note: This is a Microsoft Windows 10 issue and is covered in the Microsoft support article KB4507466. 

Recommended Actions

To fix this issue for Name Resolution Policy Table (NRPT) based VPN solutions like an Always On VPN (AOVPN) deployment, Microsoft introduced a new Registry Key to fix this issue in KB4507466

Addresses an issue that causes a Windows device to incorrectly register host A records for two network interface controllers (NIC) after establishing a virtual private network (VPN) connection to the corporate domain. This occurs when the device is configured with two NICs and one of them is a VPN. To implement this solution, make the following registry changes and then restart your device:

  • Setting: DisableNRPTForAdapterRegistration
  • Path: HKLM\System\CurrentControlSet\Services\Dnscache\Parameters
  • Type: DWORD
  • Value: A value of 1 means that only the host A records for the VPN interface will register on an active VPN connection. A value of 0 (default) means host A records will also be registered for other local interfaces.
