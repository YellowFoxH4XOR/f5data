Known Issue

The BIG-IP ASM bd process may produce a core file when a content profile is assigned to the security policy.

This issue occurs when the following condition is met:

  • The BIG-IP ASM system is running version 15.1.5.1 or 15.1.6. No other released versions are affected.
  • The content profile, such as an XML profile, is configured to check attack signatures.

Impact

The BIG-IP ASM system stops processing traffic and fails over to a peer device when configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP ASM system temporarily stops processing traffic.
  • The BIG-IP ASM system generates a bd core file to the /shared/core directory.
  • The BIG-IP ASM system sends a SIGFPE signal to the bd process and logs a message to the /var/log/ts/bd.log file, similar to the following example:

    BD_MISC|NOTICE|<date and time>|<pid>|signals.c:0047|Received SIGFPE - terminating

Workaround

To work around this issue, you can set the internal parameter disable_second_extra_normalization to 1 and restart the BIG-IP ASM system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure forces the BIG-IP system offline for a short period of time. F5 recommends that you perform this procedure during a maintenance window.

  1. Log in to the bash command line.
  2. To set the internal parameter disable_second_extra_normalization to 1, enter the following command:

    /usr/share/ts/bin/add_del_internal add disable_second_extra_normalization 1

  3. To restart the BIG-IP ASM system, enter the following command.

    bigstart restart asm
