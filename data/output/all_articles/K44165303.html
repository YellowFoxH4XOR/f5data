K44165303: HTTPs monitor marks a node down but the node is working fine when accessed directly from browser

Type
Support Solution
Published
2021-05-06
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • VIPRION Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K44165303

Description

Some nodes using HTTPs monitor are being marked down, but they are configured properly.

  • Some or all of the nodes are being marked down by BIG-IP.
  • The nodes are working fine when directly accessed from browser.

Environment

  • BIG-IP LTM using HTTPs monitor to probe the nodes.
  • There were some changes or upgrade done to the nodes.
  • In-tmm monitoring is disabled in BIG-IP.

Cause

One of the possible cause is that the nodes start expecting SNI for their requests even if there is only one application hosted on them.

Recommended Actions

To fix this, the monitors will have to modified so that probes are sent from the BIG-IP with SNI.

  • Verify if the server sends refuses to send certificate without SNI. OpenSSL command below:
openssl s_client -connect NODE_IP_ADDRESS:443 -showcerts
====================== SNIP START ======================
# openssl s_client -connect 10.10.10.10:443 -showcerts
CONNECTED(00000003)
write:errno=104
---
no peer certificate available  <==============================!
---
No client certificate CA names sent
---
====================== SNIP END ======================
  • Try the OpenSSL command with SNI and see if the node returns the certificate. OpenSSL command below:
openssl s_client -servername DOMAIN_NAME -connect NODE_IP_ADDRESS:443
====================== SNIP START ======================
---
Server certificate
-----BEGIN CERTIFICATE----- <==============================!
====================== SNIP END ======================
  • After validating that the node is sending the certificate when requested with SNI, follow the articles below to configure SNI in monitor.
    • Enable In-TMM monitoring - K11323537: Configuring In-TMM monitoring
    • Modify the severssl profile and add the SNI to "Server Name" field - K65219243: SNI support for HTTPS monitors 

Additional Information

If that doesn't help, please refer K12531: Troubleshooting health monitors
