Known Issue

When a virtual server or proxy IP address is configured with a subnet mask other than /16 (255.255.0.0) or /24 (255.255.255.0), the ARX will incorrectly create the associated network route.

This issue occurs when all of the following conditions are met:

  • A virtual server or proxy IP address is configured with a network mask other than /16 or /24
  • The ARX platform is an ARX VE 1500 or 2500

Impact

Undesired routing behavior.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX system may be unable to access resources on the affected network.
  • Viewing the  ARX route table with the show ip route command will indicate an unexpected network route.

    If the virtual server or proxy IP address is configured with a subnet mask of /17 through /23, the associated network route will have a /16 subnet mask. If the virtual server or proxy IP address is configured with a subnet mask of /25 through /31, the associated network route will have a /24 subnet mask.

    If a virtual server is defined using a /20 subnet mask, the show ip route command will display a network route with a /16 subnet mask. For example:

    Destination/Mask    Gateway          Cost Interface        Age
    ---------------------------------------------------------------------
    0.0.0.0/0           172.30.65.1      128  VLAN1           1650
    172.30.0.0/16       0.0.0.0          0    VLAN            Direct
    172.30.65.0/24      0.0.0.0          0    VLAN1           Direct
  • You will be unable to remove the undesired network route.

Workaround

Impact of workaround: None.

To work around this issue, you can configure the desired static IP routes. To do so, use the ip route command. For information about the ip route command, refer to the ARX CLI Reference Guide.
