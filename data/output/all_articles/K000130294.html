Description

The Active Directory user account that is used in an APM AAA Active Directory profile requires specific permissions so that users will be able to change their password.
If the user account is a Domain Admin account then no action is required and that article does not apply.

This article explains the minimum requirement for a regular user account to be able to successfully change user passwords, even when fine grained password policies are applied to the domain.

Failing to configure it properly, you may see some of these error logs under /var/log/apm:

  • Password policy check error: can't find password policies from cache
  • AD PSO Cache: Can't find policy object 'CN=Fine_Grained_Example,CN=Password Settings Container,CN=System,DC=example,DC=com' from cache of server '/Common/AD_user'
  • Can't get PSO for domain 'EXAMPLE.COM'

Environment

  • APM with a AAA Active Directory profile using a non Domain Admin Account under "Admin Name".
  • APM configured to allow Active Directory users to change their password.
  • Fine-grained password policy deployed on the domain.

Cause

Some specific permissions are required for the user account used in an APM AAA Active Directory profile.
 

Recommended Actions

In order to allow users to change their password, the user account used in an APM AAA Active Directory profile must have the following minimum requirements:

  • The user is added to Domain Users group.
  • The user is granted the privilege to reset passwords of other AD users.
  • The user is added to the Group Policy Creator Owners group.
  • The user is allowed to Read all properties.
  • The user is allowed to Read all properties on CN=System,CN=Password Settings Container and all child containers/objects, or Read all properties on the Fine Grained Password Policy object name itself and all descendant objects (which by default is under "CN=System,CN=Password Settings Container")
