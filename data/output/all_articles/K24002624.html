Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file when the last member of the Dynamic Host Configuration Protocol (DHCP) server pool is not available.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP PEM system is configured with a DHCP Relay virtual server.
  • The affected virtual server is associated with a pool of DHCP servers, where the last DHCP pool member configured is not available.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and fail over may occur if the system is configured as part of a high-availability (HA) group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the last member of the DHCP server pool is down, the original DHCP packet from the client is not freed, which may cause the TMM process to restart.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory, with a time stamp that correlates to the traffic interruption.
  • Your BIG-IP system may unexpectedly fail over to another system in the device group.

Workaround

To work around this issue, you can remove the last DHCP pool member that is down. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Remove the affected DHCP pool member using the following tmsh command syntax:

    modify ltm pool <Pool-Name> members delete { <Pool-Member> }

    For example, to delete the affected DHCP pool member 10.10.10.100 on the pool named Pool-DHCP-A, type the following tmsh command:

    modify ltm pool Pool-DHCP-A members delete { 10.10.10.100 }
