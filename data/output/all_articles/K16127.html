Topic

You should consider using this procedure under the following conditions:

  • To ensure that the configuration is rolled forward when you upgrade a standalone BIG-IQ Security system.
  • To ensure that the configuration is rolled forward when you upgrade a pair of active/standby BIG-IQ Security systems.

Description

When you upgrade the BIG-IQ Security system 4.0.0, 4.1.0, or 4.2.0, the BIG-IQ configuration that contains managed devices does not roll forward to the upgraded version. This procedure describes the steps that F5 recommends you take to upgrade older releases.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IQ Security system is currently running 4.0.0, 4.1.0, or 4.2.0.
  • You have Administrator role access credentials to the BIG-IQ system.
  • You have advance shell access to the BIG-IQ system.
  • The BIG-IQ software ISO image target to which you want to upgrade has been downloaded and transferred to the target systems.

Procedures

Upgrading the standalone BIG-IQ Security system

To upgrade a standalone BIG-IQ Security system, perform the following procedure.

Impact of procedure: The following procedure involves rebooting the system, and F5 recommends that you perform this procedure during a scheduled maintenance period. Ensure that all changes to managed devices on the BIG-IQ system have been deployed. Block network access to the BIG-IQ user interface during this period to ensure that no additional changes were made to the managed devices and resources.

  1. Run a BIG-IQ deployment operation before proceeding to the next step, as this procedure will cause you to lose all undeployed changes.
  2. Create a UCS backup of the device, and transfer the backup to an external storage location.

    For more information, refer to K175: Transferring files to or from an F5 system

  3. Review existing software volumes usage and select an available software volume on which to install the new version. To view the existing software volume status, type the following command:

    tmsh show /sys software status

  4. To install the new software to the available software volume, use the following command syntax:

    tmsh install /sys software image <ISO> volume <HDx.y>

    For example, to install BIG-IQ 4.5.0 into software volume HD1.3, type the following command:

    tmsh install /sys software image BIG-IQ-4.5.0.0.0.7028.iso volume HD1.3

  5. To verify that the software installation is complete, type the following command:

    tmsh show /sys software status

  6. When the installation has completed, reboot the BIG-IQ system to the newly installed software volume, by typing the following command syntax:

    tmsh reboot volume <HDx.y>

    For example, to reboot into software volume HD1.3, type the following command:

    tmsh reboot volume HD1.3

  7. Log in to the newly installed BIG-IQ system, and ensure that the installation is successful.
  8. Rediscover the BIG-IP devices that were previously managed by this BIG-IQ system.

    1. Discover and upgrade the REST framework on the BIG-IP devices as part of the device discovery.
    2. Validate that the discovery of the BIG-IP devices are successful by reviewing the configuration in the BIG-IQ system.
    3. Repeat the previous step for the remaining BIG-IP devices.

If the BIG-IP devices could not be properly rediscovered, and you want to revert back to the previous version, you can revert the BIG-IQ system to the previously installed version and install the backup UCS that you created in step 2.

Upgrading a pair of active/standby BIG-IQ Security systems

To upgrade the active/standby BIG-IQ Security systems with high availability (HA), you must perform all of the following procedures:

Prepare for an upgrade

Create a backup save configuration UCS for both devices

Perform the upgrade on Device 1

Perform the upgrade on Device 2

Perform the HA pairing procedure

Prepare for an upgrade

To ensure that the configuration objects in the pair of target systems are in-sync, we have to wait for the storage sync to arrive on the Standby device. Alternatively, we can force a storage synchronization. To force a storage synchronization, perform the following procedure:

Impact of procedure: Ensure that all changes to the managed devices on the BIG-IQ system have been deployed. Block network access to the BIG-IQ user interface during this period to ensure that no further changes were made to the managed devices and resources.

  1. Run a BIG-IQ deployment operation on the Active system before proceeding to the next step, as this entire upgrade procedure will cause you to lose all undeployed changes.
  2. Log in to the advanced shell of the BIG-IQ Security Standby device.
  3. To force a storage synchronization, type the following command:

    curl -X PUT -d '{"snapshotFile":""}' http://localhost:8100/shared/storage/snapshot-client

  4. To verify the storage synchronization, validate that the file /var/config/rest/active-storage.zip exists.

Create a backup save configuration UCS for both devices

To create a copy of the UCS file on both the devices, and transfer the UCS file to an external storage location, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To save the latest copy of the UCS, log in to the Active device using either the tmsh utility or the BIG-IQ user interface.
  2. Transfer the copy of the UCS file from the Active system to an external location. For more information, refer to K175: Transferring files to or from an F5 system.
  3. Similarly, repeat step 1 and 2 on the Standby device.

Perform the upgrade on Device 1

To perform the upgrade on Device 1, you need to start from the Active device and force the Standby device to go active before you can perform the upgrade on Device 1. To complete the upgrade on Device 1, perform the following procedure.

Impact of procedure: This procedure involves interrupting the BIG-IQ system service. F5 recommends that you perform this procedure during a scheduled maintenance period, and that you identify a way to block access to the BIG-IQ system interface during the procedure.

  1. Stop the restjavad service on the Device 1 device by typing the following command:

    tmsh stop /sys service restjavad

    Doing so causes an HA failover to the Standby device and expands the storage synchronized file in the Standby device, and makes it the Active device. When this is complete, proceed to the next step.
  2. With Device 2 becoming Active, you must restart the restjavad service on Device 1. At the command prompt of Device 1, type the following command:

    tmsh start /sys service restjavad

    This brings the Device 1 system back online.
  3. Break the HA cluster from Device 2 by removing Device 1. To do so, perform the following steps:

    1. Log in to the Device 2 BIG-IQ user interface, and navigate to System > Overview > High Availability.
    2. Click Delete.
    3. Click Accept.
  4. Verify on the BIG-IQ user interface that the HA cluster indicator reports Standalone on both devices.
  5. Complete the software upgrade on Device 1 by performing the following steps:

    1. Review and select an available software volume on which to perform the installation of the new version. To review the software volume usage, type the following command:

      tmsh show /sys software status

    2. To install the new software to the available software volume, use the following command syntax:

      tmsh install /sys software image <ISO> volume <HDx.y>

      For example, to install BIG-IQ 4.5.0 into software volume HD1.3, type the following command:

      tmsh install /sys software image BIG-IQ-4.5.0.0.0.7028.iso volume HD1.3

    3. To verify that the software installation is complete, type the following command:

      tmsh show /sys software status

    4. When the installation has completed, reboot the BIG-IQ system to the newly installed software volume by typing the following command syntax:

      tmsh reboot volume <HDx.y>

      For example, to reboot into software volume HD1.3, type the following command:

      tmsh reboot volume HD1.3

    5. Log in to the newly installed version on Device 1, and ensure that the installation is successful.
  6. Rediscover the BIG-IP devices that were previously managed by Device 1 by performing the following steps:

    1. On Device 1, discover and upgrade the REST framework on the BIG-IP device as part of the device discovery process.
    2. Validate that the discovery of the BIG-IP device is successful by reviewing the BIG-IQ configuration on Device 1.
    3. Repeat the previous two steps for the remaining BIG-IP devices.

Perform the upgrade on Device 2

After you have successfully upgraded Device 1, you can perform an upgrade on Device 2. To perform the upgrade, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the advanced shell on Device 2, and go to the /var/config/rest directory by typing the following change directory command:

    cd /var/config/rest/

  2. Rename the active-storage.zip file to a backup name by typing the following command:

    mv -b active-storage.zip SOL16127-backup-active-stroage.zip

  3. Review and select an available software volume on which to perform the installation of the new version. To review the software volume usage, type the following command:

    tmsh show /sys software status

  4. To install the new software to the available software volume, use the following command syntax:

    tmsh install /sys software image <ISO> volume <HDx.y>

    For example, to install BIG-IQ 4.5.0 into software volume HD1.3, type the following command:

    tmsh install /sys software image BIG-IQ-4.5.0.0.0.7028.iso volume HD1.3

  5. To verify that the software installation is complete, type the following command:

    tmsh show /sys software status

  6. When the installation has completed, reboot the BIG-IQ system to the newly installed software volume. Type the following command syntax:

    tmsh reboot volume <HDx.y>

    For example, to reboot into software volume HD1.3, type the following command:

    tmsh reboot volume HD1.3

  7. Log in to the newly installed version on Device 2, and ensure that the installation is successful.

Perform the HA pairing procedure

When you have successfully upgraded both Device 1 and Device 2, and all managed BIG-IP devices have been discovered, the two BIG-IQ systems are ready for you to complete the HA pairing procedure. To do so, perform the following procedure.

Impact of procedure: Ensure that all changes to managed devices on Device 1 have been deployed.

  1. Log in to the Device 1 BIG-IQ user interface.
  2. Navigate to System > Configuration > BIG-IQ Systems > Management Group.
  3. Click the gear symbol in the right corner, and select Add Device.
  4. Enter the IP address of Device 2 that you have assigned for HA peer communication.
  5. Enter the administrator username and password for Device 2.
  6. Select HA Peer Group.
  7. For BIG-IQ 4.5.0, select the desired HA mode. For all other versions, skip this step.
  8. Click Add.

    Device 1 pushes the objects to Device 2 to complete the HA pairing procedure.
