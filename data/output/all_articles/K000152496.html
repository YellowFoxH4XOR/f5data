K000152496: How to Add a Default Content-Security-Policy If Upstream Does Not Provide One

Type

Published

Updated
2025-07-09
Applies to

  • NGINX Plus: R34
Source

Description

When proxying requests to an upstream application, there may be cases where the upstream server sets its own Content-Security-Policy (CSP) header. In some scenarios, it’s desirable to preserve this upstream CSP when it exists, but add a default CSP if the upstream does not provide one.

Environment

NGINX Plus

Cause

By default, directives like more_set_headers will unconditionally overwrite any existing headers. This makes it difficult to conditionally add a security header like Content-Security-Policy only when one is not already set by the upstream application.

Recommended Actions

Use the map directive to check if the upstream response includes a Content-Security-Policy header. If the header is missing, apply a default policy.

 

Below is an example configuration:

# Define a map to determine the appropriate CSP value
map $upstream_http_content_security_policy $csp {
  default "";
  ""   "my_own_csp_content";
}

server {
  location / {
    # Conditionally add the CSP header if it was not set by upstream
    add_header Content-Security-Policy $csp;
    proxy_pass http://upstream_backend;
    ...
  }
}

How it works:

  • If the upstream sets Content-Security-Policy, the $upstream_http_content_security_policy variable has a value, so $csp is empty and add_header does not add a new header.
  • If the upstream does not set Content-Security-Policy, the map sets $csp to the default value, which add_header then adds to the response.
