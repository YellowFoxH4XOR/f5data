Topic

You should consider using this procedure under the following condition:

  • You want to use Terraform to install F5 Declarative Onboarding (DO) on the BIG-IP system.

Description

With DO, you can configure the BIG-IP system using a declarative representational state transfer (REST) API. However, you must first install the DO package on your BIG-IP system.

Terraform is an orchestration tool that automates and manages multi-machine configuration and deployment. You can use Terraform to automate the process of installing the DO package on a single or numerous BIG-IP systems.

After you install DO, you can use it to configure your BIG-IP system. For more information, refer to K10631470: Using Terraform and DO to configure the BIG-IP system.

After you complete the initial configuration, if you want to use a declarative model to configure applications and services on your BIG-IP system, you can use the F5 Application Services 3 extension (AS3). For more information on using Terraform and AS3, refer to K23449665: Using Terraform and AS3 to configure your BIG-IP system.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You read the F5 Resources for Terraform User Guide.
  • You read the F5 Declarative Onboarding documentation.
  • You installed Terraform 0.12.10 or later on your control machine.
  • You installed BIG-IP 13.1 or later on the devices in your environment.

Procedures

To configure Terraform to install the DO package on your BIG-IP system, you create the following two files in the same directory:

  • install_do.tf—The Terraform file that creates the resources required for installation. You can give the file an arbitrary name, such as install_do or main, but it must have the .tf extension.
  • terraform.tfvars—Contains all the variables you want to declare at runtime. You must use this file name and extension.

Important: For a new installation running BIG-IP 14.0.0 or later, you must log in to the system at least one time to change your root and administrator passwords. When you change the administrator password for the first time, the system automatically changes the root password. This is a one-time event. For more information, refer to K10612010: Root and admin users must reset default passwords when logging in to the BIG-IP system for the first time.

To create these two files and apply them to your BIG-IP system, perform the following procedures:

  • Downloading the DO package
  • Creating the install_do.tf Terraform file
  • Creating the variable definition file
  • Running Terraform to apply the definitions and install DO
  • Destroying the definitions and uninstalling DO

Downloading the DO package

To download the DO package, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Download the latest (highest numbered) .rpm file from the f5-declarative-onboarding repository on Github.
  2. Upload the file.

    Place your Terraform files, including the ones you create in the following procedures, in the same directory on your control machine.

Creating the install_do.tf Terraform file

Create the Terraform file, install_do.tf, in the same directory as the DO package from the previous procedure.

In the following example:

  • The first seven objects declare the address and password variables for the BIG-IP system and other required variables.
  • The next object defines a Terraform null_resource, which contains the following definitions of objects:
    • triggers—A map of the strings to the terraform.tfvars file
    • connection—Defines an SSH connection to the BIG-IP system.
    • file provisioner—Copies the DO installation package from your control machine to the BIG-IP system.
    • local-exec provisioner—Defines the curl commands you run on your local control machine to install and uninstall the DO package.
    • remote-exec provisioner—(Optional) Defines the command your BIG-IP system runs to remove the installation package.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. In a text editor, copy and paste the following example:

    variable "admin_password" {
            type = string
    }
    variable "advanced_shell_user_password" {
            type = string
    }
    variable "advanced_shell_user" {
            type = string
    }
    variable "admin_user" {
            type = string
    }
    variable "bigip_address" {
            type = string
    }
    variable "f5_do_rpm_filename" {
            type = string
    }
    variable "do_install_dir" {
            type = string
    }

    resource "null_resource" "f5_do_installer" {
       triggers = {
            advanced_shell_user = var.advanced_shell_user
            advanced_shell_user_password = var.advanced_shell_user_password
            admin_password = var.admin_password
            do_install_dir = var.do_install_dir
            f5_do_rpm_filename = var.f5_do_rpm_filename
            bigip_address = var.bigip_address
      }
      connection {
            type = "ssh"
            host = "${self.triggers.bigip_address}"
            user = "${self.triggers.advanced_shell_user}"
            password = "${self.triggers.advanced_shell_user_password}"
            port = "22"
      }
      provisioner "file" {
            #Uses the ssh connection to transfer the file to the BIG-IP system
            source      = "${self.triggers.f5_do_rpm_filename}.rpm"
            destination = "${self.triggers.do_install_dir}${self.triggers.f5_do_rpm_filename}.rpm"
      }
      provisioner "local-exec" {
            #curl command to install DO
            command =  "curl -kvu admin:${self.triggers.admin_password} https://${self.triggers.bigip_address}/mgmt/shared/iapp/package-management-tasks -H \"Origin: https://${self.triggers.bigip_address}\" -H 'Content-Type: application/json;charset=UTF-8' --data '{\"operation\":\"INSTALL\",\"packageFilePath\":\"${self.triggers.do_install_dir}${self.triggers.f5_do_rpm_filename}.rpm\"}'"
      }
      provisioner "local-exec" {
            #Optional: This command verifies that the installation is successful. You should see: "class": "Result", "code": 200, "status": "OK"
            command = "sleep 3; curl -sku admin:${self.triggers.admin_password} https://${self.triggers.bigip_address}/mgmt/shared/declarative-onboarding/info"
      }
      provisioner "local-exec" {
            #curl command to uninstall DO
            when = destroy
            command = "curl -kvu admin:${self.triggers.admin_password} https://${self.triggers.bigip_address}/mgmt/shared/iapp/package-management-tasks -d '{ \"operation\":\"UNINSTALL\",\"packageName\":\"${self.triggers.f5_do_rpm_filename}\"}'"
      }
      provisioner "remote-exec" {
            when = destroy
            inline = ["rm -f ${self.triggers.do_install_dir}${self.triggers.f5_do_rpm_filename}.rpm",]
      }
    }

  3. Save the file as install_do.tf.

Creating the variable definition file

There are various ways that you can define variables in Terraform. When you do not provide default values, such as the admin_password and advanced_shell_password variables in this example, the system prompts you to enter them at runtime.

For other variables, you can declare them in a file that you must name terraform.tfvars and locate in the same directory as your Terraform .tf file.

To create this file and declare your variables, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. In a text editor, copy and paste the following example:

    bigip_address="10.10.10.1"
    admin_user="admin"

    #advanced_shell_user requires Advanced Shell access on the BIG-IP system
    advanced_shell_user="root"

    #Enter the filename. Do not include the .rpm extension
    f5_do_rpm_filename="f5-declarative-onboarding-1.9.0-1.noarch"

    do_install_dir="/var/config/rest/downloads/"

  3. Edit the bigip_address and f5_do_rpm_filename values to make them appropriate for your environment.
  4. Save the file as terraform.tfvars.

Running Terraform to apply the definitions and install DO

To run Terraform and install DO on your BIG-IP system, perform the following procedure:

Important: For a new installation running BIG-IP 14.0.0 or later, you must log in to the system at least one time to change your root and administrator passwords. When you change the administrator password for the first time, the system automatically changes the root password. This is a one-time event. For more information, refer to K10612010: Root and admin users must reset default passwords when logging in to the BIG-IP system for the first time.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.

  2. Enter the following command:

    terraform apply

Destroying the definitions and uninstalling DO

To uninstall DO and remove the installation from your BIG-IP system, perform the following procedure:

Impact of procedure: This procedure restarts the restnoded process, but the system does not remove the DO definitions and objects you applied in the past. The restnoded process provides control-plane access to the BIG-IP using an HTTP REST API.

  1. Log in to your control machine.
  2. Enter the following command:

    terraform destroy -auto-approve
