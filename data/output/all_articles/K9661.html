Topic

Beginning in BIG-IP 9.2.0, you can connect a USB mass storage device to the BIG-IP system to transfer configuration archives, software images, log files, and core dumps.

This feature is possible with BIG-IP platforms that include a USB port using a software version listed in the Applies To list. For the list of currently supported BIG-IP platforms, refer to K9476: The F5 hardware/software compatibility matrix.

Note: The USB mass storage device that you intend to use on the BIG-IP system should be formatted with the FAT, FAT32, EXT2 or EXT3 file system. Other file systems may not be supported by the BIG-IP system (for example, NTFS). Because of its relative simplicity and interoperability between different operating systems, USB thumb drives are generally pre-formatted with the FAT32 file system.

Once a USB mass storage device has been connected to the BIG-IP system, the device will not appear in the Configuration utility. You must log on to the BIG-IP system command line and use the Linux operating system to manage the USB mass storage device. The actual procedure will vary depending on the BIG-IP platform, and on how the USB mass storage device was partitioned and formatted (assuming that these tasks were already completed).

The following example procedure provides a generic reference for mounting and using a USB mass storage device on the BIG-IP system:

  1. Log on to the BIG-IP system command line.
  2. Connect the USB mass storage device to the BIG-IP system.
  3. Run the dmesg command to verify that the system has detected the USB mass storage device.

    Note: The dmesg command prints the message buffer of the kernel. When you connect a USB device to the BIG-IP system, the kernel should generate (and append to its message buffer) some diagnostic messages.

    For example, the following messages indicate that the BIG-IP system has correctly detected and attached as sdb a 2 GB USB mass storage device:

    usb 5-1: new high speed USB device using ehci_hcd and address 4
    usb 5-1: configuration #1 chosen from 1 choice
    Initializing USB Mass Storage driver...
    scsi4 : SCSI emulation for USB Mass Storage devices
    usb-storage: device found at 4
    usb-storage: waiting for device to settle before scanning
    usbcore: registered new driver usb-storage
    USB Mass Storage support registered.
      Vendor: Sony      Model: Storage Media     Rev: 1.00
      Type:   Direct-Access                      ANSI SCSI revision: 02
    SCSI device sdb: 3917824 512-byte hdwr sectors (2006 MB)
    sdb: Write Protect is off
    sdb: Mode Sense: 23 00 00 00
    sdb: assuming drive cache: write through
    SCSI device sdb: 3917824 512-byte hdwr sectors (2006 MB)
    sdb: Write Protect is off
    sdb: Mode Sense: 23 00 00 00
    sdb: assuming drive cache: write through
     sdb: sdb1
    sd 4:0:0:0: Attached scsi removable disk sdb
    usb-storage: device scan complete

  4. Run the fdisk -l <device> command to inspect the partition table of the USB mass storage device.

    For example, assuming that the USB mass storage device was attached as sdb, replace <device> with /dev/sdb. The command output appears similar to the following example:

    fdisk -l /dev/sdb

    Disk /dev/sdb: 2005 MB, 2005925888 bytes
    62 heads, 62 sectors/track, 1019 cylinders
    Units = cylinders of 3844 * 512 = 1968128 bytes

       Device Boot      Start         End      Blocks   Id  System
    /dev/sdb1               1        1019     1958487    b  W95 FAT32

    This example command output indicates that the USB mass storage device includes one partition only (/dev/sdb1), and that the partition type is W95 FAT32.

    Note: This example procedure assumes that the partition does not need to be formatted.

  5. Create the /mnt/usb directory by running the mkdir /mnt/usb command.
  6. Mount the USB mass storage device on the /mnt/usb directory by running the following command:

    mount <device><partition> /mnt/usb

    For example:

    mount /dev/sdb1 /mnt/usb

    Note: The <device> content represents the disk name assigned to the whole USB mass storage device by the BIG-IP system (for example /dev/sdb), <partition> represents the partition number that you wish to mount (for example, 1). There is no space between <device> and <partition>.

  7. The /mnt/usb directory now refers to the root of the file system that you mounted in step 6. You can now copy files to or from the /mnt/usb directory.
  8. Once you have finished using the USB mass storage device, leave the /mnt/usb directory (for example, by running the cd / command), and unmount the file system by running the umount /mnt/usb command.
  9. You can now disconnect the USB mass storage device from the BIG-IP system.

F5 Product Development tracked this enhancement as CR44598, and it was added in BIG-IP 9.2.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.
