K000156498: How to Disable mTLS for Specific Paths in NGINX Plus

Description

NGINX Plus configured with mutual TLS (mTLS) on specific ports for API access can present challenges when integrating monitoring tools that do not support mTLS, such as New Relic (NR).

Attempts to disable mTLS for a particular path (e.g., /nginx_status) using ssl_verify_client off inside a location block are invalid and result in configuration errors. The error message typically encountered is:

nginx: [emerg] "ssl_verify_client" directive is not allowed here.

Monitoring agents unable to perform mTLS handshake will fail to connect to endpoints exposed on ports where mTLS is enforced.

 

Environment

  • Product: NGINX Plus

 

Cause

SSL/TLS handshakes and client certificate verification in NGINX occur before the request is mapped to a location block. Therefore, directives like ssl_verify_client are only valid at the server {} or http {} context level and cannot be set per-location. This architectural limitation means it is not possible to selectively disable mTLS for individual paths within a server block.

Configuration that caused the error:

server {
    listen 6443 ssl;
   
    location /nginx_status {
        ssl_verify_client off;
        stub_status;
    }
}

 

Recommended Actions

  • Configure separate server {} blocks for API access (with mTLS enabled) and monitoring endpoints (without mTLS), each listening on different ports.
    Example configuration:  
    server {
  listen 8443 ssl;
  ssl_verify_client off;
  location /nginx_status {
    stub_status;
  }
  location /nginx_api_status {
    api;
  }
  location / {
    proxy_pass https://127.0.0.1:6443;
  }
}
server {
  listen 6443 ssl;
  ssl_verify_client on;
}
  • Expose monitoring endpoints such as /nginx_status or /nginx_api_status only on non-mTLS ports. These endpoints provide global statistics for the entire NGINX instance, including traffic handled by all other server blocks.
  • For richer metrics, including HTTP status codes, use the ngx_http_api_module. Query its endpoint via a port without mTLS enabled.
  • The ngx_http_api_module comes bundled with NGINX Plus; no additional installation is required. It does not appear in the output of nginx -V.
  • When configuring third-party monitoring integrations (e.g., New Relic), ensure they query the correct endpoint and port. Some integrations may require separate monitors per port, but querying the API module endpoint from any non-mTLS port provides global metrics.
