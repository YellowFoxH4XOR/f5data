Known Issue

Description

The pvac and comm_srv processes do not automatically re-establish communication with the mcpd process when the connection is interrupted.

This issue occurs when the following condition is met:

  • The pvac and comm_srv processes lose communication with the mcpd process.

The mcpd process is the BIG-IP messenger process that allows other processes to communicate with Traffic Management Microkernel (TMM). When the mcpd process stops and restarts, processes that communicate with the mcpd process must also restart in order to re-establish communication.

Impact

The comm_srv and pvac processes are unable to communicate with the mcpd process or TMM, and continually log communication error messages.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The comm_srv process will log its communication failures every few seconds to the /var/log/wa/comm_srv.log file. For example:

    WA Debug (12581): [          WaMcpClient.cxx:345     processMCPMessages ] mcpmsg_nonblocking_receive error [0x1020003] on [0x7]
    WA Debug (12581): [   McpResponseHandler.cxx:46                 execute ] Error [0x1020003]
  • The pvac process will log its communication failures every few seconds to the /var/log/wa/pvac.log file. For example:

    WA Debug (12665): [          WaMcpClient.cxx:345     processMCPMessages ] mcpmsg_nonblocking_receive error [0x1020003] on [0x7]
    WA Debug (12665): [   McpResponseHandler.cxx:46                 execute ] Error [0x1020003]

Workaround

To work around this issue, restart the comm_srv and pvac processes. To do so, perform the following procedure:

Restarting the comm_srv and pvac processes

Impact of workaround: Traffic directed to the BIG-IP WebAccelerator module will be disrupted while the comm_srv and pvac processes restart.

  1. Log in to the BIG-IP WebAccelerator command line.
  2. To restart the comm_srv and pvac processes, type the following command:

    bigstart restart comm_srv pvac
