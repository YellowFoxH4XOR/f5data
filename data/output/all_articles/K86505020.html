Description

When Single Page Application setting is enabled in DOS profile, the page is loading Favicon from the default path (/favicon.ico). The issue exists in Chrome, it was not observed in Firefox.

Environment

  • BIG-IP ASM
  • DOS profile with Single Page Application enabled
  • Accessing application from Chrome browser
  • Favicon in application code loaded from the non-default path, for example:  
    <link rel="icon" href="/img/favicon.ico" type="image/x-ico; charset=binary">

Cause

By default, BIG-IP injects the JS script after the head tag. With this behavior, Chrome is not able to load favicon.ico from the non-default path. 

Recommended Actions

To workaround this, use the following tmsh command:

# tmsh modify sys db dosl7.parse_html_inject_tags value "before,/head"

After making this change, now the JS injection is inserted before the </head> tag and the favicon is loaded properly in Chrome.
