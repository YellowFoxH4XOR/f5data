Known Issue

When a remote syslog server initiates a connection closure, the BIG-IP ASM system may incorrectly keep the connection open.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM system is configured with a remote logging profile
  • The BIG-IP ASM management interface sends log information to the remote server

When a remote syslog server sends a FIN-ACK packet to the BIG-IP ASM system, the BIG-IP ASM system responds with an ACK packet, but will not send a FIN-ACK to completely close the connection. The BIG-IP ASM system will leave the socket in a CLOSE_WAIT state.

Impact

Remote logging performance may degrade and log messages may be lost.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system may have a large number of connections to the remote syslog server in the CLOSE_WAIT state.

    For example, the output of the netstat -an | grep 10.10.10.1 command will show numerous connections in the CLOSE_WAIT state as in the following example:

    Note: In the command example, 10.10.10.1 is the IP address of the remote syslog server.

    tcp 1 0 10.134.192.60:39785 10.10.10.1:514 CLOSE_WAIT

    tcp 1 0 10.134.192.60:38039 10.10.10.1:514 CLOSE_WAIT
    tcp 1 0 10.134.192.60:38068 10.10.10.1:514 CLOSE_WAIT
    tcp 1 0 10.134.192.60:37875 10.10.10.1:514 CLOSE_WAIT

  • If the BIG-IP ASM system creates enough connections, the max-connections limit of the syslog server may be reached. If the majority of the available connection count is used by connections stalled in the CLOSE_WAIT state, the syslog server may begin dropping subsequent connections from the BIG-IP ASM system, and log messages my be lost.

Workaround

To work around this issue, you can configure TCP Keep-Alives, or route the syslog traffic through a switch interface. To do so, perform one of the following procedures:

Configuring TCP Keep-Alives

Impact of workaround: A version upgrade or hotfix installation is required for this workaround. The internal parameters that allow administrators to control the TCP Keep-Alive behavior are only available in the versions of the software listed in the Versions Fixed column in the table above. These processes both require a full system reboot. Configuring the parameters will require an additional restart of the BIG-IP ASM service.

To use the internal parameters that control TCP Keep-Alive behavior, the system must be upgraded to one of the versions listed in the Versions Fixed column of the Status table. For more information about upgrading or installing a hotfix, refer to the Supplemental section of this article. To configure TCP Keep-Alives, refer to K13291: Configuring BIG-IP ASM to use TCP Keep-Alives for connections to remote syslog servers.

Routing syslog traffic through a switch interface

Impact of workaround: None.

As this issue only affects connections that egress the BIG-IP ASM through the management interface, you can work around the issue by routing syslog traffic out via an existing switch interface that provides connectivity to the syslog server. To route traffic destined for the syslog server over a switch interface, you will need to create a static route. To do so, perform the following procedure:

Note: The following procedure details the steps for creating a static route for one possible kind of existing configuration. The steps may need to be modified to meet the criteria defined by your network topology.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Routes.
  3. Click Add.
  4. Set the Type to Route.
  5. In the Destination field, enter the IP address of the syslog server.

    For example:

    10.10.10.1
  6. In the Netmask field, enter 255.255.255.255.
  7. Set the Resource option to Use Gateway.
  8. Set the Gateway Address to IP Address, and enter the IP Address value of the gateway.

    For example:

    10.1.1.1
  9. Click Finished.

If there is no extant VLAN or gateway that can provide connectivity to the syslog server, you will first need to create the appropriate network resource in order to work around the issue using this method. For more information about creating the network objects appropriate to your environment, refer to the TMOS Management Guide for BIG-IP Systems, and the BIG-IP TMOS: Concepts manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.
