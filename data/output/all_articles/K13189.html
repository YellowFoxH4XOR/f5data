Issue

Old Behavior

Previous to BIG-IP 10.2.3, the BIG-IP system did not log traces of TCP RST packets in any of the log files.

The only way to find traces of TCP RST packets was through tcpdump captures on the BIG-IP system.

New Behavior

Beginning in BIG-IP 10.2.3, you can configure the BIG-IP system to log TCP RST packets to the /var/log/ltm file, similar to the following example:

01230140:3: RST sent from <Src_IP_address:Src_Port> to <Dst_IP_address:Dst_Port>, <TCP RST code and reason>

For example, if a BIG-IP system with self IP 10.2.77.1:41539 sends a TCP RST packet to server 10.2.61.1:80 during a TCP three-way handshake, the BIG-IP system logs the following entry to the /var/log/ltm file:

01230140:3: RST sent from 10.2.77.1:41539 to 10.2.61.2:80, [0x11a7401:3343] TCP 3WHS rejected

This behavior is enabled by configuring the TM.RstCause.Pkt and TM.RstCause.Log db variables. The two db variables are set to disable, by default.

F5 Product Development tracked this change as ID 225328.

Impact

An overloaded BIG-IP system may experience performance degradation if the BIG-IP system processes a large amount of TCP RST packets and logs them into the /var/log/ltm file.

Recommended Actions

For information about the usage of the TM.RstCause.Pkt and TM.RstCause.Log db variables, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.
