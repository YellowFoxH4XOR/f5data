Description

ASM Attack Signature update failing with Installation error seen in the GUI:

"Live Update file could not be loaded"

And in /var/log/tomcat/live_update_upload.log :

apply_asm_attack_signatures|ERR|Jan 01 12:00:00.000|11111|F5::LiveUpdate::PayloadHandler::clean_fail,,Fail load update files: TSocket: Could not read 1024 bytes from 127.0.0.1:1111

Similar logs seen in /var/log/asm. 

Environment

  • Automatic Update enabled
  • LiveUpdate is made via Firewall
  • Connection between BIG-IP and Firewall working


Cause

In /var/log/kern.log it was found that at multiple times daemons such as java, mysqld, https, asm_config_server triggered oom-killer when LiveUpdate was initiated.

It was concluded ASM Attack Signature update is failing due to system being out of memory.
 

Recommended Actions

For a vCMP or a Virtual Edition, if possible, add more memory to the BIG-IP.
 

Additional Information

There is another option to consider as well such as De-provisioning of LTM module. Refer to K17173140: Setting LTM Provision NONE does not disable licensed LTM functionality.

By de-provisioning LTM module, more memory can be allocated to the host without losing LTM functionality.
