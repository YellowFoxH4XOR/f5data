Description

TCP connection reset with cause "HTTP internal error (bad state transition)"

/var/log/ltm logs output similar to

Nov 3 16:26:54 BIGIP err tmm[12765]: 011f0007:3: http_process_state_prepend - Invalid action:0x107041 clientside (172.16.1.1:55555 -> 172.16.100.100:443) ((null connflow)) (Client side: vip=/Common/vs_prod profile=http pool=/Common/pool_prod client_ip=172.16.1.1)

Environment

BIGIP with standard virtual server and irule calling HTTP::respond in event ASM_REQUEST_DONE

Cause

HTTP::respond does not work in event ASM_REQUEST_DONE. This is due to how BIGIP processes the sequence of events internally.

Recommended Actions

Move the HTTP::respond to event HTTP_REQUEST_RELEASE. If required, add logic (eg: setting a flag) in ASM_REQUEST_DONE to control the call to HTTP::respond in HTTP_REQUEST_RELEASE).

For example, the following irule snippet was previously failing when HTTP::respond was called within event ASM_REQUEST_DONE. The fix here is to move the call for HTTP::respond to event HTTP_REQUEST_RELEASE. The control is made using the newly added variable "flag_error".
 

when ASM_REQUEST_DONE {
  set flag_error 0
  if {[HTTP::uri] contains "/images" and ([class match [ASM::client_ip] equals "/Common/trust-list"])} {
    ASM::unblock
  } else {
# The line below is now relocated to event HTTP_REQUEST_RELEASE
# HTTP::respond 404 content "HTTP ERROR 404 Reason: Access denied" Mime-Type "text/html" 
    set flag_error 1
  }
}

when HTTP_REQUEST_RELEASE { 
  if {([info exists flag_error]) and ($flag_error)} { 
    HTTP::respond 404 content "HTTP ERROR 404 Reason: Access denied" Mime-Type "text/html"
    set flag_error 0
    event disable
    TCP::close
  }
}
