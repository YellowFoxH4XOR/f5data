Known Issue

BIG-IP APM may incorrectly rewrite URLs when no href attribute is defined in the anchor tags.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP APM system for portal access
  • The web application uses an HTML anchor tag that contains an onClick attribute
  • The anchor tag does not contain an href attribute with a linking URL
  • You press the Enter key while the password field is active

When you use HTML forms to allow user input for usernames and passwords, you can employ anchor tags with onClick attributes to facilitate login submission. If the anchor tag does not also include an href attribute with a linking URL, the BIG-IP APM system may incorrectly handle the click() method. This behavior occurs when you press the Enter key while the HTML form is active. As a result, the current page may accidentally reload or the base URL may erroneously load if defined.

Impact

An incorrect page loads, causing the application to malfunction.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Login attempts fail using BIG-IP APM portal access
  • Web application pages load incorrectly
  • Single Sign-On functionality is impaired

Workaround

You may be able to work around this issue by replacing the anchor tags that do not include href attributes with input tags.

Impact of workaround: Performing the following workaround alters code in your application. You should thoroughly test any changes in your environment before placing these changes into production.

For example:

<a id=Submit onclick=submitLogon()>Click me</a>

You can change the previous example to include the following input tags:

<input type=button onclick=submitLogon()>Click me</input>
