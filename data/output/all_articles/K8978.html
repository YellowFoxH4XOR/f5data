K8978: Logon delays may occur after enabling RADIUS accounting

Topic

If you enable RADIUS accounting on the FirePass controller, and the primary RADIUS accounting server you configure becomes unavailable, users will experience delayed logons while FirePass awaits a response from the RADIUS accounting server.

RADIUS accounting is configured on the Device Management : Maintenance : Accounting page in the FirePass Administrative Console. The Timeout value is the number of seconds FirePass waits for a response to a RADIUS accounting request before sending a duplicate RADIUS accounting request. The Retries value is the maximum number of times FirePass sends the same RADIUS accounting request to the same RADIUS accounting server.
 
There is no logon delay if your primary RADIUS accounting server is available, even if your secondary or tertiary server RADIUS accounting server is unavailable. FirePass does not attempt to reach the secondary RADIUS accounting server unless the primary RADIUS accounting server is unavailable. Similarly, FirePass does not attempt to reach the tertiary RADIUS accounting server unless the secondary RADIUS accounting server is unavailable.
 
The maximum logon delay (in seconds) that a user may experience is equal to the following:
 
[Number of RADIUS accounting servers configured] x [Timeout value] x [Retries value]
 
If you want to minimize logon delays caused by unavailable RADIUS accounting servers, lower the Timeout and Retries values as appropriate for your environment. For example, you may want to lower the Timeout value from five seconds to three seconds, and lower the Retries value from five retries to three retries.
