Known Issue

This is the result of a known issue. If you perform a Web Applications engine trace, the data contained in the Front-end response (FirePass versions 5.5 and later) or in the .OUT file (FirePass versions 5.4.2 and earlier) does not reflect modifications performed by post-processing sed scripts. Instead, the Front-end response or the .OUT file displays the data after it has been translated by the reverse-proxy engine, but before it has been translated by post-processing sed scripts.

The FirePass controller Web Applications engine trace feature provides an easy way for you to capture logs of user sessions through the Web Applications feature of Portal Access. The logs provide detailed information about how the FirePass reverse-proxy engine translates the data stream.

Note: For more information about performing and analyzing Web Applications Engine Traces, refer to the FirePass controller Administrator Guide.

Note: Web Applications engine traces are performed on the Maintenance: Troubleshooting Tools page. Sed scripts are configured on the Portal Access: Content Processing page under the Preprocessing Scripts tab.

F5 Product Development tracked this issue as CR86447 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

Workaround

To work around this issue, use an HTTP capture tool or a packet capture tool on the client system to capture the data stream returned from the FirePass controller.
