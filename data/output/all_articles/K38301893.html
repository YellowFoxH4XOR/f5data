Description:

There are periodically CPU spikes found on odd cores of the BIG-IP system which is managed by the BIG-IQ CM system.

Environment:
  • BIG-IP system
  • LTM module provisioned
  • Managed by BIG-IQ CM
  • BIG-IQ CM version is prior to 6.0
Cause:
 
BIG-IQ CM LTM module management periodically gathers state and status information on the Virtual Servers, Nodes, and Pool Members. If there are large numbers of objects of those types, the BIG-IP system may have large CPU spikes on odd cores.

Recommended Actions:

You can disable the mechanism or increase the frequency of polling using the REST API on BIG-IQ.
 
Disable the refresh mechanism

This workaround will configure 'isMonitorRunning' to 'false' to disable the refresh mechanism.
  1. Log in to the BIG-IQ CM system.
  2. Run the following command in bash
restcurl -X PUT /cm/adc-core/current-config/stats-refresh -d '{"isMonitorRunning": false}'

Increase the frequency of polling

This workaround will set the 'pollingIntervalSeconds' to a larger number to reduce the frequency. For example, to increase the polling frequency to 15 minutes.
  1. Log in to the BIG-IQ CM system.
  2. Run the following command in bash
restcurl -X PUT /cm/adc-core/current-config/stats-refresh -d '{"isMonitorRunning": true, "pollingIntervalSeconds": 900}'

Additional Information:

Upgrading the version of BIG-IQ system to 6.x and later will be recommended for these 2 reasons:
  • BIG-IQ release 5.3 will be EoTS at 13-Jul-2020 refer to BIG-IQ software support policy.
  • From BIG-IQ 6.x, data collection mechanism is changed and will mitigate the CPU spike. For more details, please refer to K96505382: The BIG-IP system now pushes statistics data to BIG-IQ DCD
