Known Issue

The tmm process may restart and produce a core file when the DNS iRule nodes_up command is executed.

This issue occurs when all of the following conditions are met:

  • You have configured a wide IP to use an iRule.
  • The iRule contains the nodes_up command that references an invalid BIG-IP LTM virtual server IP address and/or port.
  • The wide IP receives a client request.

Impact

The BIG-IP system may temporarily fail to process traffic, as it recovers from the Traffic Management Microkernel (TMM) restarting. If configured as a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP GTM system fails over to another system in the device group.
  • The BIG-IP GTM system generates a TMM core file in the /shared/core directory.
  • The BIG-IP GTM system temporarily fails to process traffic.
  • In the /var/log/gtm file, you observe log messages similar to the following example:

    err tmm[<pid>]: 011a7001:3: TCL error: Rule /<partition>/<irule name> <DNS_REQUEST> - GTM VS '<virtual server ip address> <virtual server port>' not found (line 1) invoked from within "nodes_up <virtual server ip address> <virtual server port>"

Workaround

To work around this issue, you can modify the affected iRule to correct the virtual server IP address and/or port specifications.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
