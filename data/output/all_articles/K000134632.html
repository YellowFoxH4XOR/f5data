K000134632: Nginx Resolver Directive is not working with frequent IP changes

Type
Support Solution
Published
2023-05-17
Updated
2023-05-17
Applies to
  • NGINX Products
  • NGINX Plus: R29, R26, R27, R28
Source
https://my.f5.com/manage/s/article/K000134632

Description

  • You have deployed you Nginx instance on a Cloud Service environment, like AWS where you make use of its Application Load Balancer [ALB]
  • The load balancer ALB, sits in front of Nginx and frequently changes its IP address.
  • You configuration also consists of a location block, which proxy_pass request to a static hostname like "https://example.com/1.2.3/oauth/validator;"
  • You configured resolver directive to handle frequent IP address changes as shown below.
              location /example_validator {
                  resolver 192.168.1.2 192.168.1.3 valid=30s;
                          
                  proxy_set_header Accept "*/*";
                  proxy_set_header Content-Type "application/json";
                  proxy_set_header Authorization "Basic Z0G!7dFew22udA==";
                  
                  proxy_pass https://example.com/1.2.3/oauth/validate;
                }
  • However, Nginx, irrespective of timeout or presence of the resolver directive, it seems NOT to use ALB's new IP address.
  • Instead, you may see the below error
023/04/18 09:38:18 [error] 7372#7372: *11356507 upstream timed out (110: Connection timed out) while connecting to upstream, 
            client: 10.10.1.1, 
            server: my.example.server, 
            request: "GET /api/some-random-service/v1/AcceptrepairAndOrder?yourID=1100220033 HTTP/1.1", 
            subrequest: "/example_validator/abcd1234efg-0000-1111", 
            upstream: "https://192.168.1.4:443/1.2.3/example_validator", host: "my.example.com"
  • As shown in the above error log, Nginx still attempts to connect to an old ALB IP address 192.168.1.4.
  • Usually, a restart of Nginx resolves issue; however, this is not a desired solution and you want a permanent and automated IP address update. 

Environment

  • Nginx Plus
  • Resolver Directive
  • AWS Application Load Balancer [ALB]

Cause

  • Nginx does not refresh static hostnames when used along with proxy_pass directives.

Recommended Actions

  • We can workaround this by creating a new upstream block
  • We then configure the upstream with a resolver directive and server directive pointing to the same hostname, as shown below
              upstream new.backend.com {
                      resolver 192.168.1.2 valid=30s;
                      server example.com resolve;
                      zone http_backend 32k;
              }

Additional Information

  • With the additional upstream block configured, we force Nginx to acquire new IP address for the mentioned hostname every 30 seconds.
  • No additional change is required on the location block.
