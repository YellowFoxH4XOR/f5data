Description

After configuring iRule for pool selection (for example: K27803480: iRule for selecting a Pool or Pool-member based on HTTP Request URI contents.), connection is being reset with reset cause: [F5RST: Address in use] after HTTP request is received on client side.

Environment

  • iRule for pool selection based on HTTP response
  • TCP profile with 'verified accept' option enabled
  • HTTP profile applied

Cause

This is expected behavior, as verified accept option enforces opening server side connection before replying with SYN-ACK to the client.

When HTTP profile is assigned, SYN is not sent until HTTP request is received, but since using verified accept option from TCP profile enforces opening server side before receiving HTTP request, it is leading to connection reset, as this setting is not compatible with iRule for pool selection.

Recommended Actions

Do not use 'verified accept' option from TCP profile if you are using iRule based on HTTP request for pool selection.
