K53205549: Error: Status 403 when pulling/pushing Aspen Mesh images to Harbor registry

Type
Support Solution
Published
2022-11-01
Updated
2023-07-18
Applies to
  • Aspen Mesh: 1.11, 1.14
Source
https://my.f5.com/manage/s/article/K53205549

Description

  • You observe the scripts found in Store Aspen Mesh container images in a private image registry  in the Aspen Mesh documentation don’t work with Harbor registry.
  • You observe the following error message when using an outdated version of Docker:
    Error: Status 403 trying to pull repository aspenmesh/carrier-grade-releases: "{\"error\": \"Permission Denied\"}"
  • You are unable to pull/push images from/to Harbor registry

Environment

  • Kubernetes 1.20.x, 1.21.x.
  • Aspen Mesh 1.11.x
  • Docker 20.x
  • Harbor Registry

Cause

The error message Status 403 could be caused if an outdated version of Docker is being used (e.g., 1.13.x) which does not have --password-stdin flag used in the script to authenticate.

Pulling/Pushing to Harbor Registry needs a different syntax not considered in scripts found in the Aspen Mesh documentation.

Recommended Actions

  1. Make sure you are using a recent release of Docker, e.g., 20.x as the script uses the --password-stdin flag to authenticate to pull the images from Aspen Mesh registry.
  2. Use the following scripts, after login into the Aspen Mesh registry and pulling the images, when using Harbor registry to rename and push the images:
    • rename-images.sh
    • push-images.sh 

      ++++++++++rename-images.sh++++++++++
#!/bin/bash
 
set -Eeuo pipefail
 
TOOLS_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" &> /dev/null && pwd)"
 
registry_repo=${registry_repo:-}
if [ -z "$registry_repo" ]; then
echo "registry_repo must be defined"
    exit 1
fi
 
images_used="$TOOLS_DIR/../images-used"
repo_name=$(grep -v "am-istio" "$images_used" \
    | cut -d "/" -f3 | cut -d ":" -f1 | head -1)
 
awk -F: '{print $2}' "$images_used" | xargs -L1 -I{} \
   docker tag "quay.io/aspenmesh/${repo_name}:{}" "${registry_repo}/${repo_name}:{}"
grep proxyv2 "$images_used" | awk -F: '{print $2}' | xargs -L1 -I{} \
   docker tag quay.io/aspenmesh/am-istio:{} "${registry_repo}/am-istio:{}"
echo "Done"

      ++++++++++push-images.sh++++++++++
#!/bin/bash
 
set -Eeuo pipefail
 
TOOLS_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" &> /dev/null && pwd)"
 
registry_repo=${registry_repo:-}
if [ -z "$registry_repo" ]; then
    echo "registry_repo must be defined"
    exit 1
fi
 
images_used="$TOOLS_DIR/../images-used"
repo_name=$(grep -v "am-istio" "$images_used" \
    | cut -d "/" -f3 | cut -d ":" -f1 | head -1)
grep proxyv2 "$images_used" | awk -F: '{print $2}' | xargs -L1 -I{} \
   docker push "${registry_repo}/am-istio:{}"
awk -F: '{print $2}' "$images_used" | xargs -L1 -I{} \
   docker push "${registry_repo}/${repo_name}:{}"
echo "Done"

Additional Information

By default, Kubernetes pulls Aspen Mesh container images from the Aspen Mesh image registry, which is available over the public internet. However, you can store the Aspen Mesh container images in a private image registry and tell Kubernetes to use that registry when it needs an Aspen Mesh container image.
