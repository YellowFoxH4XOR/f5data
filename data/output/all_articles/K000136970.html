K000136970: "It was not possible to connect to the revocation server or a definitive response could not be obtained" error when connecting to the VPN using Edge Client

Type
Support Solution
Published
2023-09-25
Updated
2023-12-03
Applies to
  • BIG-IP
  • APM Clients
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000136970

Description

Users using BIG-IP Edge Client 7241 and later versions may encounter the following error when connecting to the VPN:

As a result, user is not able to get connected to the VPN

Environment

  • BIG-IP Edge Client 7241 and later versions
  • Network Access VPN
  • Certificate / intermediate certificate which contains a Certificate Revocation List (CRL)

Cause

This is similar to the issue mentioned in K25042015: APM Client alerts: Revocation information for the security certificate for this site is not available. Do you want to proceed? The error is because the client machines are unable to access and download the CRLs defined in the SSL certificate / intermediate certificates.

The only difference between the Edge Client versions, is in how they handle such scenario (i.e., when a client is not able to download the CRL info).
A CRL is a HTTP request (port 80). If access to the CRL is denied then the certificate cannot be verified.
Check that the client can download the CRL manually. Failure can be because:

  • A HTTP proxy is in use that blocks HTTP.
  • Device Security software is deployed that blocks HTTP.
  • DNS is failing to resolve the CRL host.

in Edge Client v7240 and earlier versions: users will get the CRL prompt. In this case, however, users have the option to proceed (by clicking Yes) and the connection will still push through.

in Edge Client v7241 and later versions: Due to security enhancements introduced to address the most recent vulnerabilities, users *no longer* have the option to proceed; hence users are not able to connect to the VPN and they get the error instead.
 

Recommended Actions

To suppress the certificate revocation prompt, make sure users have access to download the CRLs defined in the certificate, from their client machines. On most browsers, you can select the lock or warning icon next to the URL on your browser to view/find the CRL information in the certificate. For more information, refer to the steps in K25042015.

One way to test, to see if users have access to the said CRLs:

1. open a browser and browse to the CRLs defined in the SSL certificate / intermediate certificate

if they can successfully download the CRLs, then that confirms they have access to the said CRLs.

Additional Information

On the windows platform, Edge Client with Always Connected mode, the F5 Networks Stonewall Service will block the connection to the CRL server, cause this issue.
The solution is, build the new Edge Client package with exclusion list, which contain the servers for CRL, then re-install the Edge Client.
