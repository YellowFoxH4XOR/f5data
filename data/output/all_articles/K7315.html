Known Issue

This is the result of a known issue. After launching a Network Access favorite, FirePass may not display certain icons in the Network Access pop-up window. A missing icon may be indicated with a red x in a white square or by an empty space where the icon would normally appear.

This issue occurs with full browsers that are configured to reject cookies, either from all sources or specifically from the FirePass controller.

If the FirePass cannot place and read the session cookie it normally sets to identify a user session, the FirePass controller will use a cookieless mode to perform session management for the login. As a result of the cookieless mode login, certain icons will not display.

If you log in with cookieless mode, you may see the System Warnings icon on your webtop. Clicking on the Webifyer will display the following message:

No cookies are installed
Warning: Your browser has disabled cookies. Some web pages and single-signon systems may not function correctly. For full functionality, you must enable cookies in your browser.

If your webtop is not configured to display the System Warnings, you can determine if your session is in cookieless mode by viewing the URL used to access the FirePass controller.

For example:

https://firepass.company.com/vdesk/index.php3?S=e979511e7d1c84b0fb6b066a282dd171&Z=8,7

The example URL indicates cookieless mode by the S=e979511e7d1c84b0fb6b066a282dd171 session ID, which is absent when the browser accepts cookies.

F5 Networks Product Development tracked this issue as CR77470 and it was fixed in FirePass version 6.0.2.  For information about upgrading, refer to the FirePass Release Notes.

This issue still exists in the FirePass version 5.x branch.

This issue was fixed in cumulative hotfix HF-601-3 issued for FirePass version 6.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by enabling your browser to accept cookies from the FirePass controller. For instructions about performing this configuration for your specific browser, consult the documentation for the browser.
