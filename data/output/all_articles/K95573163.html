Description

SNAT is disabled as the customer would still like to preserve the source ip address for non-HTTP traffic. Server (pool member) is responding directly to the client bypassing the BIG-IP results in asymmetric routing which causes BIG-IP to reset the connection as the SYN-ACK is not returned to the BIG-IP.

Environment

  • BIG-IP 
  • Virtual Server traffic
  • Source Address Translation (SNAT) is configured as None
  • Non-HTTP traffic = x-forwarded-for is not an option

Cause

SNAT being disabled (set to 'None') leaves the client's original source-ip as the source-ip in the server side packets. Pool member's SYN-ACK response packet does not reach the BIG-IP.

Recommended Actions

Disabling SNAT will require that the pool-member's Default Gateway be configured to use the BIG-IP's Floating Self-IP assigned to the VLAN. In doing this, the pool-member's new Default Gateway points traffic bound for remote subnets or the Internet to the BIG-IP. This means a Wildcard Forwarding Virtual Server would need to be configured to allow the pool-members to have access to remote subnets and the Internet through the new Default Gateway of the BIG-IP. For information about IP forwarding virtual server please refer to K7595: Overview of IP forwarding virtual servers.

In addition, these changes would cause necessary network routing configurations in the environment so traffic can be directed back and forth between the BIG-IP Wildcard Forwarding Server, remote subnets, and the Internet.
