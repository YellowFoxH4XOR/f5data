K8634: The sendcmd process fills the BIG-IP ASM process table

Known Issue

This is the result of a known issue. Under rare conditions, multiple instances of the sendcmd process may hang and fill the BIG-IP ASM process table. As a result, the BIG-IP ASM system will begin paging, and will eventually stop processing traffic.

You can verify this behavior by running the ps command. If multiple instances of the sendcmd process have filled the process table, the output will appear similar to the following example:

root  2204  684 ?   S    Jan02   0:00 sh -c /ts/tools/sendcmd 127.0.0.1 19000 "from=replication;uid=72540;s
root  2784  520 ?   S    Jan02   0:00  \_ /ts/tools/sendcmd 127.0.0.1 19000 from=replication;uid=72540;stat
root  2196  688 ?   S    Jan02   0:00 sh -c /ts/tools/sendcmd 127.0.0.1 19000 "from=replication;uid=71542;s
root  1302  576 ?   S    Jan02   0:00  \_ /ts/tools/sendcmd 127.0.0.1 19000 from=replication;uid=71542;stat
root  2208  688 ?   S    Jan02   0:00 sh -c /ts/tools/sendcmd 127.0.0.1 19000 "from=replication;uid=71545;s

F5 Networks Product Development tracked this issue as CR92292 and it was fixed in BIG-IP ASM version 9.4.5. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.4-73.1-HF1 issued for BIG-IP ASM version 9.4.4 for the 9.4 software branch. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
