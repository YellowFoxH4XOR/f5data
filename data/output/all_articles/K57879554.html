Known Issue

A non-existent user may be authenticated for secure shell (SSH) access when they use remote authentication.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with remote authentication using Radius.
  • The External Users default role is set to Administrator.
  • Your BIG-IP system is configured with SSH host-based authentication.
  • A non-existent user presents the root SSH authentication key when they initialize their SSH session.

Impact

The non-existent user is granted SSH access.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You can establish an SSH session to the BIG-IP system when you authenticate using a username that is not configured on the local BIG-IP system, and does not exist in the Radius authentication server's users list, as long as you present the root SSH authentication key.

Workaround

To work around this issue, you can modify the External Users default role to a role that does not have administrator privileges. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure may require that you reconfigure some remote access users with the Administrative role.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Users > Authentication.
  3. In the External Users section, from the menu, set Role to a non-Administrative role, such as Guest.

    Note: For granular role assignment, you can configure the BIG-IP or Radius server to provide the user's role at authentication.

    For more information about configuring your Radius server, refer to: K14324: Using F5 vendor-specific attributes with RADIUS authentication (11.x -12.x)

  4. Click Finished.
