K42593363: REST endpoints to check for currently running DMA tasks on a BIG-IQ

Description

Centrally managing a BIG-IP device using the BIG-IQ system is sometimes referred to as declaring management authority (DMA) over a BIG-IP device.

By default, the BIG-IQ UI imposes restrictions for preventing declare management authority (DMA) / Remove Management Authority (RMA) tasks from running in parallel. The DMA/RMA process is modal. Once the process starts, you are blocked from performing any other tasks or interacting in any way until the process is complete or canceled.

DMA workflows run exclusively with BIG-IQ device configuration management tasks, e.g. via import, modification, drift-detection, snapshotting, deployment of device configuration (LTM, ASM, etc.). No other tasks would use DMA.

Unfortunately, these restrictions do not apply when interacting with the BIG-IQ REST API outside of the BIG-IQ UI such as in an automated iControl REST scripted environment where there is potential for parallel/overlapping tasks to occur.

Environment
  • BIG-IQ Centralized Management as a REST proxy.
  • Mixed environments utilizing both BIG-IQ UI as well as scripted automation iControl REST API workflows for task management (in parallel).
Cause
  • Overlapping iControl API Task failure.

For Example:

[ERROR][22 Mar 2019 01:26:27 GMT][/cm/asm/tasks/declare-mgmt-authority/44f7973c-e0ea-4ba4-9d6c-5b9be5d28dd1/worker AsmDMATaskWorker] Task C04135757_3/21/2019 https://localhost/mgmt/cm/asm/tasks/deploy-configuration/52a246fe-a60b-402b-ae62-a4f3d5fd6b16 found in a running state: STARTED

Recommended Actions
  • Maintain a workflow sequence and abide the restrictions imposed by the BIG-IQ UI.
  • Incorporate pending DMA/RMA checks within your custom iControl REST script(s) in order to avoid parallel task executions.
All API endpoints to query pending DMA tasks, for each module (ASM, ADC-CORE, etc.):

/mgmt/cm/asm/tasks/declare-mgmt-authority
/mgmt/cm/adc-core/tasks/declare-mgmt-authority
/mgmt/cm/security-shared/tasks/declare-mgmt-authority
/mgmt/cm/websafe/tasks/declare-mgmt-authority
/mgmt/cm/dns/tasks/declare-mgmt-authority
/mgmt/cm/access/tasks/declare-mgmt-authority
/mgmt/cm/firewall/tasks/declare-mgmt-authority
 
Each of these endpoints would provide information on pending DMA tasks (if any) for the corresponding device module. For example, if there's a DMA task running on ASM configuration, a GET to "/mgmt/cm/asm/tasks/declare-mgmt-authority" would yield the following response (simplified):

{
  "items": [
    {
      "deviceReference": {
        "link": "http://host:port/path/to/resource"
      },
      "status": "QUEUED"
    }
  ]
}

Here are the possible values for the "status" of DMA task:

"statusEnumValues": [
  "QUEUED",
  "CREATED",
  "STARTED",
  "CANCEL_REQUESTED",
  "CANCELED",
  "FAILED",
  "FINISHED"
]

One would iterate all the API endpoints above, or just the ones relevant for the supported BIG-IP modules and look for pending task(s). If there's any DMA pending, query the status. Anything different from "FINISHED" or "FAILED", should stop the workflow of attempting a subsequent DMA. Failed tasks (if any) should first be deleted before attempting new ones.

Now keep in mind that DMA (Declare Management Authority) also has the corresponding opposite paradigm: RMA (Remove Management Authority). The same workflow restrictions apply. Namely, no overlapping/parallel workflows involving DMA/RMA. For checking for RMA would also be relevant, if the workflow(s) involve anything close to removing device configurations, discovered devices, etc.

Here are the RMA API endpoints (symmetrical with the DMA ones):

/mgmt/cm/asm/tasks/remove-mgmt-authority
/mgmt/cm/adc-core/tasks/remove-mgmt-authority
/mgmt/cm/security-shared/tasks/remove-mgmt-authority
/mgmt/cm/websafe/tasks/remove-mgmt-authority
/mgmt/cm/dns/tasks/remove-mgmt-authority
/mgmt/cm/access/tasks/remove-mgmt-authority
/mgmt/cm/firewall/tasks/remove-mgmt-authority

For a more detailed API/documentation on the endpoints above, one should invoke the /example URI on any of them, e.g. "/mgmt/cm/asm/tasks/remove-mgmt-authority/example". This would provide a full JSON on all the available response fields, for the related API.
