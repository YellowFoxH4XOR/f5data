Topic

To find out about the information F5 requires when opening a support case for other F5 products, refer to K2633: Instructions for submitting a support case to F5.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help you gather all the required information, use the following guidelines to prepare for opening a case:

  • General Information
  • BIG-IP-specific Information
  • SSL Orchestrator-specific information

General Information

Provide the following information when you open a case with F5 Support:

  • A full description of the issue, including the following:

    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have taken in an attempt to resolve the issue

  • A description of the impact that the issue is having on your site, using the following definitions:

    • Site Down

      Your network or application is down, or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue, and any alternative contacts who can work on the issue if you are not available

  • Remote access information, if possible

    Remote access to your network environment is important, because it is the most effective method to collect information and troubleshoot technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone and through email; however, this approach can often be more time consuming and may require file transfers, replication, and additional testing.

BIG-IP-specific information

Collect the following information from the affected system and provide it when you open the case. For information about sending this information to F5 Support, refer to K000090853: Exchange files with F5 Support using MyF5.

  • qkview

    The qkview utility generates a file that contains the configuration files that F5 Support most frequently needs when troubleshooting an issue. You should run the qkview utility on F5 SSL Orchestrator before opening a case. For more information about qkview, refer to K12878: Generating BIG-IP diagnostic data using the qkview utility.

  • UCS archives

    If you cannot give F5 Support remote access to your system, you must provide a user configuration set (UCS) archive of the current configuration. For more information, refer to K4423: Overview of UCS archives.

  • Core files

    Core files contain the contents of the system memory at the time a crash occurred. If the system is not responding and producing core files, the core files will be located in the /var/core directory. Submit any existing core files when you open the case. For information about identifying and submitting core files, refer to K10062: Overview of managing BIG-IP core files.

SSL Orchestrator-specific information

It is important that you enable debug logging and reproduce the issue before you collect and upload log files to F5 Support. To enable debug logging for SSL Orchestrator, perform the following procedure:

Impact of procedure: Debug logging in Per-Request policy can be verbose. Depending on your environment, you may plan to perform this procedure either during off peak hours or during a scheduled maintenance window.

  1. Log in to the Configuration utility
  2. Go to SSL Orchestrator  >  Configuration.
  3. Select the name of your topology
  4. Select Log Settings.
  5. Select Debug for Per-Request Policy and SSL Orchestrator Generic.
  6. Select Save & Next.
  7. Select Deploy.
Depending on your system, debug logging may quickly increase the file size of the log files . After reproducing the issue, you should revert the change, immediately turning debug logging off.

  • Tarball file of the /var/log directory

    Large log files included in a qkview may be truncated. To ensure that F5 Support receives the latest log entries on your BIG-IP system, you should generate and upload a tarball of the logs in the /var/log directory. Enter the following command to generate a tarball:

    tar czvf /var/tmp/varlogs.tgz /var/log/*

    Upload /var/tmp/varlogs.tgz

  • SSL Orchestrator iFile 

    Beginning in SSL Orchestrator 9.0, there is an iFile that captures SSLO objects and configurations. To generate this file, use the following command syntax:

restcurl -X POST -d '{"operation": "read"}' https://127.0.0.1/mgmt/shared/iapp/f5-iappslx-ssl-orchestrator/mcpBlockIO -u <username>:<password> > /var/tmp/"$HOSTNAME"_ifile

Upload /var/tmp/"$HOSTNAME"_ifile

  • Packet traces

    If the issue involves the traffic to the deployed services (such as HTTP, ICAP, L2/L3 inline, receive-only/TAP etc), you should perform a packet trace while the issue is occurring and provide the packet trace when you open the case. For more information about performing packet traces with tcpdump, refer to K4714: Performing a packet trace and providing the results to F5 Support.

  • SSL-encrypted packet traces

    If the issue involves encrypted traffic, you can use the ssldump utility to examine, decrypt and decode the SSL-encrypted packets. For more information about decrypting SSL-encrypted packets, refer to K10209: Overview of packet tracing with the ssldump utility.
