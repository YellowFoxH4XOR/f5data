Description

Under certain circumstances, you may find the virtual server not processing traffic destined to it.

For example, a standard virtual server (with TCP profile attached) does not respond to SYN from clients, or an IP forwarding virtual server does not forward the packet received from client to the server-side.

You run the following command on the BIG-IP:

# tmctl virtual_server_stat -s name,no_acl_match_drop,no_acl_match_reject

name              no_acl_match_drop no_acl_match_reject

----------------- ----------------- -------------------

/Common/VIP-HTTPS        35          0

While traffic is being sent to the virtual server (and not processed), you notice that the "no_acl_match_drop" counter increments correspondingly.

Environment

  • BIG-IP AFM provisioned
  • virtual server
  • traffic not processed

Cause

Traffic might have been blocked by AFM.

Recommended Actions

You may check if AFM is dropping/rejecting the traffic. Refer to K13723376: Troubleshooting | BIG-IP AFM operations guide, especially on how to use the Packet Tester.
