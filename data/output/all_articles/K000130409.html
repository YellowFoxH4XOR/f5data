K000130409: ASM event logs show HTTP response code 200 when 404 is returned on HTTP response

Type
Support Solution
Published
2022-12-29
Updated
2022-12-29
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.2
Source
https://my.f5.com/manage/s/article/K000130409

Description

When you have an iRule that evaluates for HTTP response codes that are not allowed in an application security policy, and then makes a custom response to the client, the security event log will show a response code of 200 instead of the not allowed code.

The iRule should have the command HTTP::respond. For example if code 404 is not allowed in security policy and the iRule has the HTTP::respond command:

 

when HTTP_RESPONSE {

 if { [HTTP::status] == 404 } {

  HTTP::respond 404 content "<HTML><HEAD><TITLE>Content not Found</TITLE></HEAD>\

<BODY>Content not Found</BODY></HTML>"

 }

}
 

The resulting request will Response Status Code 200 shown in Security event logs.

  

Environment

  • BIG-IP ASM
  • iRule using HTTP::respond command 

 

Cause

Bug ID 464328.

 

Recommended Actions

None, this is an expected behavior. The HTTP::respond command in a server-side context results in a response being sent to the client, otherwise bypassing other server-side processing. This response sends an internal response across the chain.  

This internal response has a status of 200 and zero content, and makes sure all other components are in the correct state after the response completes.  

The internal response will be seen only in the Application Security logs.

 

Additional Information

None.
