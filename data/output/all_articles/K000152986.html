Description

After upgrading a vCMP Host from earlier version to newer version, Its Guests are not coming up as normally expected and failed to load their configuration and stuck in "Offline" state for long time. This can result in Guests remaining in a "provisioned" or "offline" state and not running as expected. 

You performed the License Reactivation 'AFTER' the vCMP Host upgrade, and not 'BEFORE' starting the upgrade operation - which could negatively affect all the Guests running on the Host as those are still referring to the previous / old License data, and not the newly reactivated license.

Environment

  • vCMP-Enabled (Host / Guest)
  • Upgrade
  • License Reactivation performed after the upgrade

Cause

After a vCMP Host upgrade, the Host must be re-licensed for the new TMOS version. If License Re-activation is performed after the upgrade (but before starting the Guests), the new license may NOT be fully applied, causing the Guests to fail to start. 

Recommended Actions

  • Always perform License Re-activation "BEFORE" upgrading the vCMP Host to ensure the new license is valid for the upgraded TMOS version.
  • If License Re-activation was performed after the upgrade and Guests fail to start, Reboot the vCMP Host to apply the new license fully. This typically resolves Guest startup Issues.
  • If even Rebooting the vCMP Host does not resolve the Issue, consider rolling back to the previous version, verify the service check date, and attempt a fresh upgrade again after removing the previously-failed Boot Locations.
