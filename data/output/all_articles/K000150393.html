K000150393: Pool member status marked as disabled after manually enabling - recv-disable string configured in monitor

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.0, 17.1.X, 17.1.2, 17.1.1

Description

 

A pool member remains in the "Disabled" state even after attempting to enable it via the GUI or tmsh. The status reverts back to "Disabled" immediately after enabling.

 

Environment

 

BIG-IP LTM

 

Cause

 

The issue is caused by a custom monitor configuration that includes a recv-disable string. This setting marks the pool member as disabled if its response matches the recv-disable string but not the recv string. The monitor configuration may look similar to the following:

ltm monitor https /Common/monitor_https {

...

recv <response if working>

recv-disable <response expected to mark member as disabled>

...

}

 

If the monitored endpoint returns a response matching recv-disable response it triggers this condition and disables the pool member automatically.

 

Recommended Actions

 

To resolve this issue, follow these steps:

 

  1. Verify Monitor Configuration:
    1. Check if your custom monitor has recv-disable strings defined.
    2. Ensure that this string aligns with your application's expected responses.
  2. Test with Default Monitors:
    1. Temporarily change the pool's monitor to a default HTTPS or TCP monitor to confirm whether disabling behavior persists.
  3. Modify Custom Monitor:
    1. If using a custom monitor is necessary, remove or adjust the recv-disable string in your custom HTTPS monitor configuration if it is not required for your use case.
