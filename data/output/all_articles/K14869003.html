K14869003: Create a SecureVault cryptogram for an AS3 declaration

Topic

You should consider using this procedure under the following condition:

  • You want to create a SecureVault cryptogram for a passphrase or password in an AS3 declaration.

Description

To encrypt secrets such as a passphrase or password in a SecureVault cryptogram within an AS3 declaration, you must first deploy the declaration to a BIG-IP system. This can be a problem if you need to deploy the declaration to a BIG-IP system in a public cloud for example, and you want an extra layer of protection beyond HTTPS for secrets during transmission. To avoid this dilemma, you can deploy the declaration to a staging device in a secure, internal network first to obtain the SecureVault cryptogram and then use it to replace the plaintext passphrase or password with the encrypted one and replay the declaration to the production device. If you are not going to deploy to separate staging and production systems, this deployment process is still beneficial if you want to store declarations in a version control repository that has encrypted passphrases and passwords rather than plaintext ones. For more information refer to Secrets in AS3 declarations.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have read the AS3 User Guide.
  • You have installed AS3 on your staging and production BIG-IP systems.
  • If you are going to deploy to separate staging and production systems, the staging BIG-IP system where you create the SecureVault cryptogram must have the same master key as the production BIG-IP where you deploy it.

Procedures

  • Ensure that the staging and production systems have the same master key
  • Encrypt a passphrase or password in an AS3 declaration with a two-stage deployment process

Ensure that the staging and production systems have the same master key

If you plan to deploy your declaration to a separate production BIG-IP system after encrypting a passphrase or password on a staging BIG-IP, the master keys of both systems must match.

Impact of procedure: Performing the following procedure changes the master key on the BIG-IP system and re-encrypts all passwords and passphrases in the configuration. F5 recommends that you perform this procedure on a staging or test system and not on a production system.

  1. Ensure that the staging and production systems have the same master key by entering the following command on each BIG-IP command line:

    f5mku -K

    If the systems have the same key, you can skip to the next procedure.

  2. If applicable, on the staging BIG-IP, back up the current key by storing the output from the previous command in a safe location and change the master key to match the production system.

    Re-key the staging system by typing the following command:

    f5mku -r <master key from production system>

    For more information, refer to K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later).

  3. Save the configuration so existing master key-encrypted passphrases and passwords are re-encrypted with the new master key. To do so, type the following command on the staging BIG-IP system:

    tmsh save sys config

Encrypt a passphrase or password in an AS3 declaration with a two-stage deployment process

Passphrases and passwords in an AS3 declaration can be defined with a JWE object. The following procedure shows how to deploy a declaration to create a SecureVault cryptogram for use in a JWE object so the declaration can be re-deployed or stored with encrypted secrets.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use the echo and base64 utilities on a Linux host or a BIG-IP system to encode your passphrase or password in Base64. Use echo -n to leave out the trailing newline. Use the following syntax:

    echo -n "<passphrase>" | base64

    For example:

    echo -n "as3test" | base64

  2. (Optional) If you are installing a certificate and key, you can make these compatible with JSON format by using the jq utility on a Linux host or on a BIG-IP system. Use the following syntax:

    jq -Rs . < <certificate or key file>

    For example:

    jq -Rs . < as3test.key

  3. On your workstation use a code editor such as VSCode to create an AS3 declaration.
  4. (Optional) If you are using VSCode, to validate the declaration, add a $schema property and refer to the specific schema for the AS3 version you are using. For more information refer to Validating a declaration.
  5. Add classes to your declaration, and when needed for a passphrase or password, enter the JWE object with the ciphertext encoded in Base64 and remove the trailing equal sign (=). If applicable, add your JSON-formatted certificate and key.

    For example:

    "webcert1": {
        "class": "Certificate",
        "remark": "replace these with real certificates and keys",
        "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
        "privateKey": "-----BEGIN ENCRYPTED PRIVATE KEY-----\n...\n-----END ENCRYPTED PRIVATE KEY-----",
        "passphrase": {
            "ciphertext": "YXMzdGVzdA"
        }
    }

    Note: The contents of the certificate and key in this example have been removed for succinctness.

  6. Save the declaration and deploy it to your staging BIG-IP system. The SecureVault feature will encrypt the passphrase or password with the master key.
  7. In the response to the POST, save the output for the JWE object which contains the SecureVault cryptogram. If you need to view the output again, issue a GET request for the tenant by using the following URL syntax:

    https://<BIG-IP mgmt address>/mgmt/shared/appsvcs/declare/<tenant>

  8. Create a copy of your declaration or edit the original and replace the unencrypted JWE object with the SecureVault cryptogram.

    For example:

    "webcert1": {
        "class": "Certificate",
        "remark": "replace these with real certificates and keys",
        "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----\n",
        "privateKey": "-----BEGIN ENCRYPTED PRIVATE KEY-----\n...\n-----END ENCRYPTED PRIVATE KEY-----\n",
        "passphrase": {
            "ciphertext": "JE0keUkkUHFreklESDdKZmtkSGhXaWcxQnh3QT09",
            "protected": "eyJhbGciOiJkaXIiLCJlbmMiOiJmNXN2In0=",
            "miniJWE": true
        }  
    }

    Note: The protected value is {"alg":"dir","enc":"f5sv"} encoded in Base64. The contents of the certificate and key in this example have been removed for succinctness.

  9. Deploy the new declaration with the encrypted values for the secrets to the production BIG-IP system or store the declaration in your version control repository.
  10. If you used a staging system to create the SecureVault cryptogram, you can delete the deployment on this system if you want to.
