Topic

Important: BIG-IP 9.4.7 and later versions use a different memory allocation scheme than the method described in this Solution. BIG-IP 9.4.7 and 9.4.8 can use the bigpipe db Provision.ExtraMB <amount in megabytes> to allocate additional memory to the Linux host. For information about BIG-IP 10.x, refer to the Resource Provisioning section in the Configuration Guide for BIG-IP Local Traffic Management.

In BIG-IP 9.x, the host system for traffic management is comprised of the Traffic Management Microkernel (TMM), which runs as a daemon in a Linux kernel. When a BIG-IP system is properly licensed, the BIG-IP determines the amount of memory allocated to the Linux host and to TMM.

By default, when BIG-IP software is installed and there is no license installed on the system (this includes other slots), and the memory is divided evenly; half of the memory is available to the Linux host and half of the memory is available to TMM. This memory allocation will remain until a license is installed and activated.

For example, prior to activating a license on a system with 1G of memory, 512M (mem=512M) will be allocated to the Linux host, and 512M available to TMM. The memory available to Linux is specified in the grub.conf file as a Linux kernel command line option (mem=xxxM). The memory allocation is determined at boot time and can be viewed from the CLI by typing the following command:

Note: BIG-IP 9.3.1 and 9.6 and later no longer use the switchboot -d option. For more information, refer to K8937: The switchboot -d option has been removed.

switchboot -d

The output appears similar to the following example:

title BIG-IP 9.2.3 Build 34.3 - drive hdc.2
kernel (hd1,1)/vmlinuz.hdc.2 ro root=/dev/hdc10
console=ttyS0,19200 panic=1 mem=512M platform=C62 quiet

When a license is properly activated, the BIG-IP system allocates memory depending on the licensed features for the system and the total amount of memory in the unit. At this time, the Linux host is assigned a defined amount of memory, and the remaining memory in the system is made available to TMM. For example, after properly activating a license on a system with 1G of memory, 384M (mem=384M) will be allocated to the Linux host, making 640M available to TMM.

To view memory allocation after the system has been properly licensed, type the following command:

switchboot -d

The output should appear similar to the following example:

title BIG-IP 9.2.3 Build 34.4 - drive hdc.1
kernel (hd1,1)/vmlinuz.hdc.1 ro root=/dev/hdc5
console=ttyS0,19200 panic=1 mem=384M quiet platform=C62

The license must be activated properly in order to ensure proper memory allocation. You can properly activate the license following a new installation by performing one of the following three procedures:

  • Activate the license from the Configuration utility
  • Install the license from the command line and run the bigstart restart command prior to rebooting the system
  • Install the license from a UCS install and run the bigstart restart command prior to rebooting the system

If the license is not activated properly, the memory allocation can remain in an even split, leaving an inadequate amount of memory available to TMM.

You can correct the memory allocation for the current slot by typing the grubmem -f command.
