Description

After upgrading your BIG-IP DNS devices, you see that one or more of your GSLB pool members have a flapping monitor status

You are seeing big3d time outs when using prober pools in the var/log/gtm
Monitor /Common/gateway_icmp from /Common/Testpool : no reply from big3d: timed out

Environment

  • BIG-IP DNS
  • Prober Pools

Cause
This may be caused by one of your BIG-IPs no longer getting successful monitor responses from the server

Recommended Actions

  1. Verify what prober instance is timing out and what instance is sending the probes in question by enabling gtmd debug by following the below
    tmsh modify /sys db log.gtm.level value debug
    tmsh modify /sys db gtm.debugprobelogging value enable
  2. Logged now in var/log/gtm we can now see what instance is sending the probe like we see in the below 
    Nov 12 14:39:32 bigip1.local debug gtmd[17171]: 011ae039:7: Check probing of IP:Port 192.168.111.5:443 in DC /Common/TEST-B
    Nov 12 14:39:32 bigip1.local debug gtmd[17171]: 011ae03a:7: Will not probe 192.168.111.5:443 in DC /Common/TEST-B because will be done by other GTM (/Common/TestgtmA:192.168.1.1)     <--- BIG-IP instance sending the failing probe
