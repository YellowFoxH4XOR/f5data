Known Issue

TMM may exit and produce a core file when processing an empty URI or a large URI.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is performing URL redirection.
  • The BIG-IP APM system processes an empty URI request or a request greater than 4096 bytes.

Impact

The BIG-IP APM system is unable to process traffic while the TMM process is unavailable.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to access the BIG-IP APM system or may experience a traffic disruption.
  • The TMM process generates a core file to the /shared/core directory.
  • The BIG-IP system generates a SIGSEGV fault and stack trace in the /var/log/tmm file, similar to the following example:

    notice ** SIGSEGV **
    <snip>
    RIP=0x7478ca

  • Error messages similar to the following example are logged to the /var/log/apm file:

    err tmm[24792]: 01490519:3: 00000000: Received user request URI is longer than max supported length of 4096 bytes.
    err tmm[24792]: 01490514:3: 00000000: Access encountered error: ERR_NOT_SUPPORTED. File: ../modules/hudfilter/access/access.c, Function: access_store_uri, Line: 14922
    err tmm[24792]: 01490514:3: 00000000: Access encountered error: ERR_VAL. File: ../modules/hudfilter/access/access.c, Function: access_process_state_get_session_id, Line: 5178
