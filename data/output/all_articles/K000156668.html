K000156668: VELOS - "Quorum: primary conflict" error appears when manualy disabling a tenant's primary blade

Type
Support Solution
Published
2025-09-29
Updated
2025-09-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000156668

Description

On BIG-IP systems running in a multi-blade VELOS environment, the following symptoms may be observed when disabling the primary blade while the min-up-members setting is enabled for the cluster:

  • The cluster enters a "primary conflict" state, and the following messages appear in logs and tmsh output:

    notice clusterd: transition to quorum for primary conflict
    warning clusterd: Blade quorum state decreasing from RUNNING to QUORUM
    warning sod: HA min_up_cluster_member clusterd fails action is failover.
    warning sod: HA cluster_member_disabled clusterd fails action is go offline and down links.

  • Cluster members may show as unavailable or in a failsafe-fault state.
  • Traffic groups may be unable to go active, and the system may cycle between standby and offline states.

Environment

  • Product: BIG-IP LTM
  • Platform: VELOS multi-blade chassis
  • Tenant Software Version: 17.1.2, 17.1.2.2 (and likely other 17.x versions)
  • Configuration:
    • Multi-blade cluster
    • /sys cluster min-up-members set to a value greater than 1 (e.g., 2)
    • min-up-members-enabled set to yes
    • Blade failover or primary blade disable operation performed

Cause

This issue is caused by a known software bug (Bug ID 637613) in which the cluster fails to properly handle primary transitions when the number of up members drops below the configured min-up-members threshold. This results in a "primary conflict" state and prevents the cluster from electing a new primary, causing traffic groups to remain offline or in a non-active state. 

Recommended Actions

  • Workaround:
    Before disabling or failing over the primary blade, temporarily lower the min-up-members value or disable the min-up-members feature. This will allow the cluster to transition primaryship smoothly and avoid entering a primary conflict state.
    tmsh modify sys cluster default min-up-members 1
    tmsh modify sys cluster default min-up-members-enabled no
    After maintenance or failover is complete and all blades are online, restore the original min-up-members configuration.
