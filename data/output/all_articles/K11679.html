Known Issue

Note: The issue described in this article does not affect BIG-IP 10.0.1, and only affects BIG-IP 10.0.1 HF1 or later versions.

Note: A session cookie can be set without an expiration date. The system generally stores session cookies in volatile memory by clients, and the cookies expire when the user session expires (that is when the browser shuts down).

The persist cookie insert and persist cookie rewrite iRule commands fail to set session cookies.

After you apply a generic cookie persistence profile to a virtual server, you can use an iRule to more efficiently manage persistence cookies. For example, you can write an iRule that inspects each HTTP request and then intelligently sets the cookie name or cookie expiration.

When invoked with no additional arguments, the persist cookie insert and persist cookie rewrite iRule commands should set a session cookie. However, due to the issue described in this article, the iRule commands set a cookie that expires after 180 seconds.

The same issue also occurs if the aforementioned iRule commands are invoked with the 0d 00:00:00 optional expiration argument, which tells the BIG-IP system to set a session cookie.

For example, the following iRules incorrectly generate persistence cookies that expire after 180 seconds:

rule SOL11679_A {
when HTTP_REQUEST {
persist cookie insert
}
}

rule SOL11679_B {
when HTTP_REQUEST {
persist cookie rewrite
}
}

rule SOL11679_C {
when HTTP_REQUEST {
persist cookie insert my_cookie_name "0d 00:00:00"
}
}

rule SOL11679_D {
when HTTP_REQUEST {
persist cookie rewrite my_cookie_name "0d 00:00:00"
}
}

Note: The example iRules correctly handle expiration times other than 0d 00:00:00. For example, if the expiration argument is set to 1d 00:00:00, the persistence cookie expires after 1 day.

F5 Product Development tracked this issue as ID 223446 (formerly CR129809) and it has been fixed in BIG-IP 11.3.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

Important: You must modify the cookie persistence profile from the command line. Modifying the cookie persistence profile from the Configuration utility removes the timeout setting. For more information, refer to K13069: The BIG-IP system removes the timeout setting when the cookie persistence profile is updated using the Configuration utility.

To work around this issue, set the timeout to immediate. To do so, perform the following procedure:

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Set the timeout to immediate using the following command syntax:

    modify ltm persistence cookie <profile name> timeout 0

    For example, to modify the profile named MyCookieProfile, you would type the following command:

    modify ltm persistence cookie MyCookieProfile timeout 0
  3. Save the change by typing the following command:
    • BIG-IP 10.1.0 and later versions:

      save /sys config
    • BIG-IP 10.0.x:

      save config

After performing the workaround

Inspect the /config/bigip.conf file to view the timeout 0 line that the system adds to the affected persistence profile.

For example:

ltm persistence cookie /Common/MyCookieProfile {
app-service none
defaults-from /Common/cookie
timeout 0
}
