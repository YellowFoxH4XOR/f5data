K000162897: BIG-IP Service Discovery Down When the Telemetry VLAN Is Missing

Type
Support Solution
Published
2026-08-12
Updated
2026-08-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000162897

Description

BIG-IP Service Discovery may remain Down or repeatedly transition between Up and Down when the Customer Edge (CE) can reach the BIG-IP management interface but cannot reach the BIG-IP telemetry service on TCP port 18093.

Common errors include:

  • No active device found in the cluster

  • Invalid character 'u' looking for beginning of value

  • unexpected end of JSON input

  • Login retries for telemetry configuration exhausted

Successful HTTPS or iControl REST access to a BIG-IP management address does not confirm that the Service Discovery telemetry path is operational.

Environment

  • F5 Distributed Cloud BIG-IP Service Discovery.
  • Customer Edge with separate interfaces for routing, data collection, and management.
  • BIG-IP HA pair.
  • Dedicated telemetry/data VLAN required for communication between the CE and BIG-IP.
  • Manual configuration synchronization between BIG-IP devices.

Cause

The required telemetry/data VLAN and corresponding BIG-IP self IP configuration were missing.

BIG-IP Service Discovery uses BIG-IP self IP addresses for telemetry communication. Management addresses are not treated as self IP addresses for this purpose. As a result, the CE could access the BIG-IP management interface but could not reach TCP port 18093 through the required telemetry path.

This caused authentication, telemetry, and cluster-discovery operations to fail or return incomplete or non-JSON responses.

Recommended Actions

  1. Verify that the CE is healthy and that clock synchronization and tunnel connectivity are operational.
  2. Configure the required dedicated telemetry/data VLAN on each BIG-IP device.
  3. Configure corresponding BIG-IP self IP addresses on the telemetry/data VLAN.
  4. Ensure that TCP port 18093 is permitted between the CE and each BIG-IP self IP.
  5. Test port 18093 connectivity from the CE to both members of the BIG-IP HA pair.
  6. Confirm that the Service Discovery configuration references the correct BIG-IP addresses and credentials.
  7. If BIG-IP configuration synchronization is manual, synchronize the devices after:
    • Creating or modifying the telemetry VLAN or self IPs.
    • Enabling or disabling Service Discovery visibility.
    • Enabling API Discovery.
    • Allowing Distributed Cloud to create or modify BIG-IP objects.
  8. Enable visibility for the required discovered Virtual Servers.
  9. Enable API Discovery for the applicable Virtual Servers.
  10. Generate application traffic through the Virtual Servers to allow API Discovery to collect endpoint data.
  11. Confirm that:
    • Service Discovery remains Up.
    • Both HA members are available.
    • TCP port 18093 remains reachable.
    • Discovered services remain populated after the normal discovery interval.
    • API Discovery displays endpoints after sufficient application traffic is generated.

Additional Information

  • Management-interface reachability and access to the BIG-IP login page do not prove that the Service Discovery telemetry path is operational.
  • Service Discovery depends on BIG-IP self IP configuration, not only on management-interface reachability.
  • Service Discovery may show Down when the CE can access one BIG-IP member but cannot reach the telemetry service on the other member.
  • When BIG-IP synchronization is manual, Distributed Cloud-created configuration changes must be synchronized across the HA pair before the configuration is fully consistent.
  • API Discovery requires visibility to be enabled for the applicable BIG-IP Virtual Server and requires traffic to be generated through that Virtual Server.
