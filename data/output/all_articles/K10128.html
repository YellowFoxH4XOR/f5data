Known Issue

This is the result of a known issue. In BIG-IP version 9.4.2, the PLUGIN::disable and PLUGIN::enable iRule commands were introduced to disable or enable the specified plugin. The PLUGIN iRule commands do not function in BIG-IP version 10.0.0. When you create an iRule containing the PLUGIN::disable or PLUGIN::enable commands, the system does not report a syntax error. However, when the PLUGIN command is triggered, the system logs an error message.

Note: BIG-IP ASM was added as a plugin in version 9.4.2, and BIG-IP WebAccelerator was added as a plugin in version 10.0.0.

For example, the following iRule enables the BIG-IP ASM plugin for the virtual server when the HTTP class is selected, and disables the plugin for requests containing .jpg images:

rule irule_plugin {
when HTTP_CLASS_SELECTED {
PLUGIN::enable ASM
if { [HTTP::uri] contains ".jpg" } {
PLUGIN::disable ASM
}
}

In BIG-IP version 10.0.0, when a request triggers the above iRule, an error message that appears similar to the following example is logged to the /var/log/ltm file:

01220001:3: TCL error: disable_plugin <HTTP_CLASS_SELECTED> - while executing "PLUGIN::enable ASM"

F5 Product Development tracked this issue as CR118939 and it was fixed in BIG-IP version 10.0.1. For information about upgrading, refer to the BIG-IP ASM and WebAccelerator release notes.

Note: Starting in BIG-IP version 10.0.1, the iRule syntax used to disable and enable a plugin module changed to the following:

<plugin_name>::disable
<plugin_name>::enable

For example, in version 10.0.1, you can disable BIG-IP Webaccelerator for certain requests using the WAM::disable iRule command. For information about bypassing BIG-IP WebAccelerator in version 10.x, refer to K10127: Bypassing BIG-IP WebAccelerator with an iRule in version 10.x.
