Description

CLI commands to get specific information from a virtual server or pool.

For more information about a virtual server or pool, refer to the following guides:

  • The About Virtual Servers chapter of the BIG-IP Local Traffic Management: Basics manual
  • The About Pools chapter of the BIG-IP Local Traffic Management: Basics manual

Environment

  • BIG-IP Advanced Shell (Bash)

Cause

None

Recommended Actions

  1. Log into the BIG-IP Advanced shell (bash)
  2. If you want to list which profile is associated with a virtual server, run the following command syntax:

    # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|<profile name>'

    For example,

    # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|my_http_profile1'

    ltm virtual my_fastl4_vs {
    ltm virtual my_http_vs_A {
            my_http_profile1 {
    ltm virtual my_http_vs_B {
    ltm virtual my_http_vs_C {
    ltm virtual my_https_vs {

    The previous command output displays the list of virtual servers which shows that the my_http_profile1 profile is listed under the virtual server my_http_vs_A; this means that the my_http_profile1 is associated with my_http_vs_A virtual server.

  3. If you want to list which pool is associated with a virtual server, run the following command syntax:

    # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|<pool name>'

    For example,

    # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|my_http_pool_2'

    ltm virtual my_fastl4_vs {
    ltm virtual my_http_vs_A {
    ltm virtual my_http_vs_B {
        pool my_http_pool_2
    ltm virtual my_http_vs_C {
    ltm virtual my_https_vs {

    The previous command output displays the list of virtual servers which shows that the my_http_pool_2 pool is listed under the virtual server my_http_vs_B; this means that the my_http_pool_2 is associated with my_http_vs_B virtual server.

  4. If you want to list the IP address of the member and which monitor is associated with a pool, run the following command syntax:

    # tmsh list ltm pool all-properties | egrep -i 'ltm pool|address|<monitor name>'

    For example,

    # tmsh list ltm pool all-properties | egrep -i 'ltm pool|address|my_http_monitor'

    ltm pool my_http_pool_1 {
                address 192.168.155.111
        monitor my_http_monitor
    ltm pool my_http_pool_2 {
                address 192.168.155.121
                address 192.168.155.122
    ltm pool my_http_pool_3 {
                address 192.168.155.131
        monitor my_http_monitor
    ltm pool my_http_pool_4 {
                address 192.168.155.141
                address 192.168.155.142

    The previous command output displays the list of pools which shows that the my_http_monitor monitor is listed under the pool my_http_pool_1 and my_http_pool_3; this means that the my_http_monitor is associated with both my_http_pool_1 and my_http_pool_3 pools.

  5. See below for some other examples of useful CLI commands for virtual servers:
    • To list the persistence profile associated with a virtual server, run the following command syntax:

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|<persistence profile name>'

      For example,

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|my_cookie_persist_profile'

      ltm virtual my_fastl4_vs {
      ltm virtual my_http_vs_A {
      ltm virtual my_http_vs_B {
              my_cookie_persist_profile {
      ltm virtual my_http_vs_C {
      ltm virtual my_https_vs {

      The previous command output displays the list of virtual servers which shows that the my_cookie_persist_profile persistence profile is listed under the virtual server my_http_vs_B; this means that the my_cookie_persist_profile is associated with my_http_vs_B virtual server.

    • To list the clientssl and/or serverssl profile(s) associated with a virtual server, run the following command syntax:

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|<clientssl profile name>|<serverssl profile name>'

      For example,

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|my_clientssl_profile|my_serverssl_profile'

      ltm virtual my_fastl4_vs {
      ltm virtual my_http_vs_A {
      ltm virtual my_http_vs_B {
      ltm virtual my_http_vs_C {
      ltm virtual my_https_vs {
              my_clientssl_profile {
              my_serverssl_profile {

      The previous command output displays the list of virtual servers which shows that the my_clientssl_profile and my_serverssl_profile profiles are listed under the virtual server my_https_vs; this means that both the my_clientssl_profile and my_serverssl_profile are associated with my_https_vs virtual server.

    • To list the IP address of the virtual servers and display their translate address and translate port settings, run the following command syntax:

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|destination|translate-address|translate-port'

      ltm virtual my_fastl4_vs {
          destination 0.0.0.0:any
          translate-address disabled
          translate-port disabled
      ltm virtual my_http_vs_A {
          destination 192.168.201.100:http
          translate-address enabled
          translate-port enabled
      ltm virtual my_http_vs_B {
          destination 192.168.201.1:http
          translate-address enabled
          translate-port enabled
      ltm virtual my_http_vs_C {
          destination :any
          translate-address enabled
          translate-port disabled
      ltm virtual my_https_vs {
          destination 192.168.201.1:https
          translate-address enabled
          translate-port enabled

    • To list the IP address pf the virtual servers and the irules associated with a virtual server, run the following command syntax:

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|destination|<irules name>'

      For example,

      # tmsh list ltm virtual all-properties | egrep -i 'ltm virtual|destination|my_redirect_to_https_vs_rule'

      ltm virtual my_fastl4_vs {
          destination 0.0.0.0:any
      ltm virtual my_http_vs_A {
          destination 50.50.201.100:http
              my_redirect_to_http_vs_rule
      ltm virtual my_http_vs_B {
          destination 50.50.201.1:http
      ltm virtual my_http_vs_C {
          destination :any
      ltm virtual my_https_vs {
          destination 50.50.201.1:https

      The previous command output displays the list of virtual servers which shows that the my_redirect_to_http_vs_rule irule is listed under the virtual server my_http_vs_A; this means that the my_redirect_to_http_vs_rule is associated with my_http_vs_A virtual server.
