Description
BIG-IP sends incorrect IP header checksum on packets forwarded through ePVA

Compared to the expected checksum:

  • the transmitted checksum is different by:
    • a single toggled bit, or
    • an equivalent arithmetic operation, for example: +/- 1, 2, 4, or 8 from any digit
  • the corruption always occurs at the same bit in the header checksum
You can use a tool such as Wireshark to calculate the expected checksum using a capture showing corrupted packets.

Environment

  • VIPRION or BIG-IP with ePVA
    • including vCMP guest
  • ePVA enabled
  • FastL4 or IP Forwarding virtual server

Cause
This issue is usually linked to hardware failure related to the ePVA.

Recommended Actions

  • Run End-User Diagnostics to test BIG-IP hardware
    K7172: Overview of the End User Diagnostics software
  • Contact F5 Support for further assistance 
    K2633: Instructions for submitting a support case to F5
