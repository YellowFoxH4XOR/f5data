Description

When attempting to upgrade BIG-IP software, the process may fail or be blocked if the Service Check Date (license activation date) does not meet the minimum requirement for the target version. Attempts to reactivate the license may not update the Service Check Date if the support contract has expired. Typical symptoms include:

  • The Service Check Date in the license file does not advance after reactivation.
  • Dossier warning codes (e.g., Dossier warning XX) appear in system logs.
  • The upgrade process does not proceed or is blocked with license-related errors.

Example Log Entries:

In the license file:

grep "Service check date" /config/bigip.license
Service check date : YYYYMMDD
Note: The date does not update after license reactivation.

 

/var/log/ltm 

warning chmand[4822]: 012a0004:4: CHMAN request (from get_dossier) for tag:19 failed

warning mcpd[7390]: 01070267:4: Dossier warning XX.

notice mcpd[7390]: 01070419:5: Platform initialization phase triggered.

 

/var/log/audit

notice mcpd[7390]: 01070417:5: AUDIT - client tmui, user <user> - transaction #<id> - object 0 - reset_license { } [Status=Command OK]

Environment

  • BIG-IP (all modules and platforms)
  • License Reactivation
  • Service Check Date
  • License Expired
  • CLI
  • GUI

Cause

BIG-IP software upgrades require the system license to have a Service Check Date later than the minimum required by the target software version. If the support contract for the BIG-IP instance has expired, license reactivation will not update the Service Check Date beyond the contract expiration date, which can prevent the upgrade.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Verify Service Check Date:

    • Run CLI command:
      grep "Service check date" /config/bigip.license

    • Compare the Service Check Date to the minimum required by the target upgrade version (refer to the release notes or upgrade documentation for the required date).

  2. Check Support Contract Status:

    • If the support contract has expired, license reactivation will not update the Service Check Date.

    • Contact your F5 Sales representative or partner to renew the support contract if needed.

  3. Reactivate License After Renewal:

    • After renewing the support contract, reactivate the license to obtain an updated Service Check Date.

  4. Upgrade Procedure:

    • Once the Service Check Date is updated, proceed with the upgrade.

    • If a previous upgrade attempt failed, roll back to the previous version (do NOT select "Install Configuration"), delete any failed boot location, reactivate the license, and retry the upgrade.

  5. Dossier Warning Codes:

    • Dossier warning codes in logs (e.g., Dossier warning 08) may indicate hardware or license attribute mismatches and are expected if the license cannot be updated due to contract expiration.
