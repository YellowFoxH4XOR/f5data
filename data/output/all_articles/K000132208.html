Description
  • VPN portal login is stuck on "Connecting" when connecting from a MacOS client. The problem applies to both Monterey and Ventura clients. Another access portal where there is no DTLS virtual server does not exhibit the same issue.
ltm virtual /Common/Virtual_Server_Name { 
[...]
 profiles {
        /Common/SSL_Profile_Client_Name {
            context clientside
        }
[...]

ltm profile client-ssl /Common/SSL_Profile_Client_Name {
[...]
options { dont-insert-empty-fragments no-dtls no-tlsv1.3 no-tlsv1.1 no-dtlsv1.2 tls-rollback-bug no-sslv3 no-tlsv1 }
[...]
  • .pcap file indicates that issue as following:
3207           DTLSv1.2    404    IN  s1/tmm1 : Client Hello
3208           DTLSv1.2    316    OUT s1/tmm1 : Alert (Level: Fatal, Description: Handshake Failure)
7633           DTLSv1.2    404    IN  s1/tmm2 : Client Hello
7634           DTLSv1.2    316    OUT s1/tmm2 : Alert (Level: Fatal, Description: Handshake Failure)

Environment
  • Client machines: MacOS Monterey and Ventura Clients.
  • DTLS Virtual Server is configured.
Cause
  • no-dtlsv1.2 is configured as an option in Client-SSL profile that is attached to the DTLS Virtual Server.
Recommended Actions
  • Attaching standard SSL Client Profile with dtls1.2 option enabled to the DTLS Virtual Server.
  • K33000012: How to disable SSL protocols or specific versions of TLS on an SSL profile such as TLS 1.0 and TLS 1.1

None
