Description

After vCMP guest was upgraded from 15.1.2.1 to 15.1.6, the guest/device will be in inoperative mode.

  • All the daemons, including mcpd, are constantly restarting.
  • Even after reverting to 15.1.2.1, the issue doesn't get resolved.
  • See the following error in /var/log/ltm - "Decryption of the field (value) for object (config.auditing.forward.sharedsecret) failed while loading configuration that is encrypted with a different master key."

Environment

  • Recent upgrade.
  • BIG-IP GTM or BIG-IP LTM
  • The Secure Vault password was changed.

Cause

This is caused by a known bug ID1066285

Recommended Actions

The workaround depends on whether the bug has been triggered or not.

For devices that have the bug triggered already (constant daemons restarts), please follow the steps below:
  1. Reset the auditing.forward.sharedsecret to NULL. Command below:
    # tmsh modify sys db config.auditing.forward.sharedsecret value '<null>'
  2. Load the config again. Command below:
    # tmsh load sys config
  3. After the config loads and the guest/device becomes stable, update the auditing.forward.sharedsecret again.
    # tmsh modify sys db config.auditing.forward.sharedsecret value <password>
(OR)

For devices that have not encountered the issue but running affected software versions, please follow the steps below either after changing the auditing.forward.sharedsecret or before upgrading the software:
# setdb config.auditing.forward.sharedsecret "$(getdb config.auditing.forward.sharedsecret)"
# save sys config

Note: Running the above command shouldn't affect the traffic and will ensure the config.auditing.forward.sharedsecret value gets saved to disk properly.
