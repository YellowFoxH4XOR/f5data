Organizations rely on a virtual private network (VPN) to provide their employees with continuous, secure, remote access to corporate resources. Use this article to help resolve issues that may arise with your VPN.

You can configure your BIG-IP system to optimize its resources and ensure that VPN performance does not impact your users by doing the following:

  • Prepare to make changes that optimize your BIG-IP APM system
  • Optimize BIG-IP APM resources (CPU, memory) to handle increased load due increased VPN usage
  • Optimize VPN network performance for increased speed and throughput

Prepare to make changes that optimize your BIG-IP APM system

Before you optimize your BIG-IP APM system and give it larger workloads, perform the following checks to ensure that the system is running without errors for a sustained period of time:

  • BIG-IP version—Upgrade your BIG-IP system to the latest version.
  • License—Verify that your BIG-IP APM license provides for sufficient sessions. For more information, refer to K94234421: Licensing and provisioning Network Access, an F5 VPN solution.
  • SSL hardware acceleration—When you optimally configure SSL hardware acceleration, it can significantly improve performance by offloading crypto operations to better balance CPU and hardware usage.

    As you configure SSL hardware acceleration, consider the following factors:

    • F5 recommends using the default SSL hardware acceleration configuration.
    • The choices you make between full hardware acceleration and none depend on requirements specific to your environment. If your BIG-IP system CPU usage is maximized at 100 percent, consider offloading more processing to hardware. On the other hand, when CPU is underutilized and you need to improve the performance of your BIG-IP APM Network Access, you can allocate more processing to CPU. Beginning in BIG-IP 15.1.0, you can set the ratio between CPU and hardware acceleration by configuring the Acceleration Strategy of the system. For more information, refer to K50459385: Overview of the hybrid SSL acceleration feature.
    • Verify you enabled hardware acceleration by entering the following command:

      tmsh list sys db crypto.hwacceleration

    • Configure SSL algorithms that are hardware accelerated. For more information, refer to K13213: SSL algorithms that are hardware accelerated.
    • As you configure your system's SSL settings, refer to SSL statistics by entering the following command:

      tmsh show /ltm profile client-ssl <profile_name>

      Specifically, beginning in BIG-IP 15.1.0, you can differentiate between software and hardware offloading for a given cipher or algorithm with the previous command. For more information, refer to K41057430: Enhanced SSL profile statistics.

  • Errors—Verify system logs and graphs for error messages, including the following:
    • System issues—These issues include SSL transactions, CPU memory usage, and licensing. Check the /var/log/ltm file and graphs from iHealth.
    • BIG-IP APM-related issues—These issues include errors in the /var/log/apm file.
  • Lease pool address—When your configuration has insufficient lease pool addresses, users cannot connect.
  • Proxy Auto Configuration (PAC) server—When you have a proxy PAC server in your Network Access resource, ensure that it is working optimally.

Optimize BIG-IP APM resources to handle increased load

Enable split tunnel network access

You can significantly reduce the VPN traffic load on your BIG-IP system by enabling split tunnel network access. With reduced traffic, the load on your BIG-IP system also goes down.

Note that with full tunnel network access, you can control all traffic going through your corporate client devices. When you enable split tunnel, you cannot manage traffic that does not enter the VPN tunnel.

  • Full tunnel—All network traffic from users enters the VPN tunnel and goes through the BIG-IP system.
  • Split tunnel—Only selected VPN traffic enters the VPN tunnel. You define the traffic using IP addresses and and DNS names.

    Note: You use the IPv4 LAN Address Space and DNS Address Space settings to define traffic that enters the VPN tunnel.

For a description of the steps to configure split tunnel, refer to the Configuring Network Access Resources chapter of the BIG-IP APM: Network Access manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Configure minimal logging

When your BIG-IP system experiences high workloads that result in poor performance, reduce logging to a minimum. This includes system- and BIG-IP APM-related logs. You can set the following logging levels on events, ordered from highest to lowest severity:

  • Emergency
  • Alert
  • Critical
  • Error
  • Warning
  • Notice
  • Informational
  • Debug

To configure system log levels, go to System > Logs > Configuration > Options.

To configure logging for BIG-IP APM, go to Access > Overview > Event Logs > Settings.

Manage user sessions

BIG-IP APM sessions running on the system consume resources, such as licenses, CPU, and memory. You can optimize these resources by managing the number of connected sessions. To do so, configure the following parameters in the affected access profile:

  • Inactivity Timeout—The number of seconds that pass before the access policy times out
  • Access Policy Timeout—The number of seconds that pass before the access profile times out because of inactivity
  • Maximum Session Timeout—The maximum number of seconds a session can exist
  • Max Concurrent Users—The maximum number of users that can use an access profile at the same time
  • Maximum Sessions Per User—The maximum number of concurrent sessions that one user can start

You can find these settings by going to Access > Profile / Policies in the Configuration utility. For more information about the settings, refer to K12300: Overview of access policy timeout settings.

Reduce the number of configuration entries, including IP Addresses and ACLs

The Network Access resource consists of configuration objects, such as IP addresses, DNS address spaces, and access control lists (ACLs). You can reduce the number of configuration entries by consolidating them into one. For example, for IP addresses and ACLs, you can configure blocks of IP ranges. In the following example, the first block uses multiple IP addresses:

10.5.1.0/24
10.5.2.0/24
[...]
10.5.253.0/24

However, you can consolidate them into a single entry, as displayed in the following example:

10.5.0.0/16

In particular, large ACL entries take up significant resources and slow down the user experience. For DNS address spaces, you can use the * operator to consolidate multiple entries, as displayed in the following example:

*.example.com.

Verify compression settings (deprecated)

Important: Beginning in APM Clients 7.2.6, BIG-IP network access VPN compression (client and server side) is deprecated. For more information, refer to K000158915: BIG-IP network access VPN compression deprecated from APM Client 7.2.6.

Compressing BIG-IP APM Network Access data can reduce the amount of traffic on the network. However, the compression process requires CPU processing, and you must configure it correctly to avoid high CPU usage that results in dropped packets. Therefore, when you experience poor Network Access performance, check for the following:

  • High CPU usage
  • Changes to the BIG-IP system compression parameters from the default values

For more information, refer to K12524516: APM Network Access (VPN) compression causes high CPU usage.

When you plan to use the previously listed compression settings to change the default configuration, consider the following factors:

  • Compression is a CPU intensive process. When enabling compression, ensure that your BIG-IP system has the resources to handle the added work load. In addition, after you enable compression, closely monitor system resource usage using the ltm and apm log files and graphs on iHealth.
  • The BIG-IP system offers various levels of software and hardware compression capability. You should review the hardware datasheet for your BIG-IP system. Specifically, for HTTP compression, refer to K13469: Determining the compression capability of your BIG-IP system.
  • Do not enable multiple compression settings if you are unsure about them or without thorough testing, unless F5 Support advises you to do so.
  • Understand the type of data in the VPN tunnel. Compression works best with text files and therefore compression can improve users' experience with web pages. However, the following files types do not yield good compression ratios:
    • Files that are already compressed, including PDF, image, Open Office, Microsoft Office, and multimedia files
    • Files with high entropy, including some image and encrypted files

Configure Client Traffic Classifier for Windows clients

Description

The Network Access Client Traffic Classifier feature in a network access resource enables you to shape and prioritize the outgoing (upload only) network traffic from users' Microsoft Windows clients. You enable it at the Network Settings tab of a network access resource. You can implement it for various use cases, including the following:

  • You observe users consuming a large amount of resources (bandwidth, CPU) when accessing specific applications, such as file uploads. You want to place a bandwidth limit on these applications.
  • You want users who are accessing certain critical applications to have priority.
  • You want different groups of users to have different levels of service quality. For example, you want to allocate more bandwidth for executive users while placing a ceiling rate for guest users.
  • You want to enforce rules, such as limits and priority, based on the client system's virtual Point-to-Point Protocol (PPP) interface—or VPN—and/or default physical network interface.

Planning

When planning to use Client Traffic Classifiers, consider the following:

  • Traffic classifier entries let you identify applications that require bandwidth control using the following:
    • Protocol—"Echo Reply" message (ICMP), User Datagram Protocol (UDP), and TCP
    • Source and destination network address and service port
    • Interface—local physical adapter, virtual PPP adapter, or both
  • The system applies and makes traffic shaping rules active when a Windows client establishes a BIG-IP APM Network Access connection.
  • When the BIG-IP APM Network Access connection terminates, the system removes the traffic shaping rules from the Windows client interfaces.
  • F5 recommends installing the F5 Traffic Control Windows service on client systems. Without this service, the user must have administrative rights to allow client traffic control.

Implementation

You implement the Client Traffic Classifier feature by configuring three BIG-IP APM objects:

  • Client Rate classes—You configure rate classes by adjusting Ceiling Rates, Burst Size, and other settings. The Differentiated Services Code Point (DSCP) option allows you to give priority to traffic at the packet level.

    Note: After you enable the DSCP override, the system allows you to set up to 64 differentiated services by entering a DSCP value (0–63). The DSCP is a number from zero to 63 that the system places into an IP packet to mark it according to the class of traffic it belongs to. The feature enables other network devices to continue to enforce priority for DSCP-marked traffic. The differentiated services (DiffServ) RFCs provide recommendations for creating different service classes by mapping DSCP values to service classes. For more information, refer to RFC 4594: Configuration Guidelines for DiffServ Service Classes.

  • Client Traffic Classifiers—You can assign the rate classes you configured to either or both the virtual PPP interface and local physical interface.
  • Network Access resource—You can only assign one Client Traffic Classifier to your Network Access resource under the Network Settings tab of your network access resource. If you want to assign different client traffic classifiers for different groups of users, you can create more than one Network Access resource. Then, you assign a Network Access resource to each user group dynamically by creating different branches in the Visual Policy Editor (VPE).

For more information, refer to the Shaping Traffic on the Network Access Client chapter of the BIG-IP APM: Network Access manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Scale out a high availability cluster into standalone systems

There may be isolated peak periods when your BIG-IP system does not have enough resources (CPU, memory) to handle large workloads. If you tried the steps in the preceding sections, and you have a pair of BIG-IP systems in a high availability (HA) pair, you can convert the systems into separate, active, standalone systems to handle the additional load. To do so, use one of the following methods:

  • Use BIG-IP DNS to load balance your BIG-IP APM Network Access session and provide HA between the multiple BIG-IP APM systems. For more information, refer to the F5 BIG-IP GTM with APM for Global Remote Access (BIG-IP 11.2+: GTM, APM) deployment manual.
  • If you want to use a DNS-based scaling solution but you do not have a BIG-IP DNS system, F5 Cloud Services is an ideal solution, because it is easy to set up and provides HA across multiple locations intelligently. For more information, refer to F5 DNS Load Balancer Cloud Service.
  • Use a BIG-IP LTM system to load balance inbound BIG-IP APM Network Access traffic to multiple BIG-IP APM systems. The BIG-IP LTM system uses a FastL4 virtual server to load balance BIG-IP APM sessions across a pool of BIG-IP APM systems with source address persistence. For more information about this implementation, refer to K33765223: Load balancing BIG-IP APM network access VPN systems with the BIG-IP LTM system.

Optimize VPN network performance for increased speed and throughput

It is important to note that when you want to optimize network performance, you must allocate time to tune each configuration to match the requirements specific to your environment. In addition, configuration changes that improve performance may increase BIG-IP system resource (CPU, memory) usage.

Configure a DTLS Network Access virtual server

BIG-IP APM Network Access can create a VPN tunnel using either Transport Layer Security (TLS) or Datagram Transport Layer Security (DTLS). TLS runs over TCP, a connection oriented protocol. The DTLS protocol is based on TLS and provides equivalent security using datagrams. In many cases—especially unreliable networks, applications such as media streaming, voice telephony, and online gaming—DTLS provides a significant improvement to TLS. Beginning in BIG-IP 16.0.0 with APM Clients 7.2.1, F5 introduces BIG-IP APM network access VPN support for Datagram Transport Layer Security (DTLS) 1.2, as defined in RFC6347. For more information, refer to K24074415: BIG-IP APM network access VPN support for DTLS 1.2.

Note: The RFC link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Before you enable DTLS for your BIG-IP APM Network Access, you must already have a virtual server with TLS network access working. Enabling DTLS for your BIG-IP APM Network Access involves the following two steps:

  • Enable the DTLS option on your existing BIG-IP APM Network Access resource, specifying the DTLS port.
  • Create a new DTLS (UDP) virtual server with a Client SSL and connectivity profile.

For more information about creating a DTLS Network Access virtual server, refer to K54955814: How to create a DTLS Virtual Server for Network Access VPN.

Note: You can also use the Device Wizard in the Configuration utility to build a new Network Access resource and DTLS virtual server.

For the client device to successfully switch to DTLS, take note of the following in your configuration:

  • You must configure the new DTLS virtual server with the same IP address as the existing TLS virtual server.
  • Configure the listening port number on the DTLS virtual server to be the same as the one specified in the network resource.
  • On the client system, ensure there is no firewall or port filter blocking the DTLS port.
  • After you successfully connect DTLS, verify DTLS by doing the following:
    1. On the client system, select the BIG-IP Edge Client icon, and then select Details (View Details on Mac).

      Under Tunnel Details, the Protocol Version provides the tunnel type.

    2. On the BIG-IP system, view confirmation messages. For example, the following message indicates that the system connected a DTLS VPN tunnel:

      9806870c: Assigned PPP Dynamic IPv4: 10.5.22.6 ID: a0d5bb07 Tunnel Type: VPN_TUNNELTYPE_DTLS NA Resource: /Common/exampleNA_na_res Client IP: 10.5.2.245

      In contrast, the following example shows a client connected to a TLS VPN tunnel:

      6c6c4a39: Assigned PPP Dynamic IPv4: 10.5.22.5 ID: 1603d0b1 Tunnel Type: VPN_TUNNELTYPE_TLS NA Resource: /Common/exampleNA_na_res Client IP: 10.5.2.245

Configure TLS dynamic record sizing in Client SSL profile

Beginning in BIG-IP 12.1.0, on non DTLS network access virtual servers, you can enable the TLS Allow Dynamic Record Sizing setting in the Client SSL profile to improve your organization's VPN speed. For more information on this feature, refer to Improve BIG-IP APM VPN speed with TLS dynamic record size on DevCentral.

Configure optimized application support for the Network Access resource

For certain applications, such as a file server delivering large text or video files to users, you can improve BIG-IP APM Network Access performance by configuring optimized application support to the destination. Optimized application is a set of compression characteristics applied to VPN traffic destined for a specific IP address and port. An optimized tunnel provides a TCP L4 connection to an application. You can create optimized application support for a Network Access resource using the Configuration utility by selecting the Network Access resource, and then selecting the Optimization tab.

When you configure optimized applications, consider the following factors:

  • The type of traffic for the destination that you configure—Not all traffic is suitable for compression. Large files, like image files with low entropy and PDF files that are already compressed, are not good candidates for compression. Large text files and video files, on the other hand, result in good compression ratio.
  • Compression requires CPU resources—To ensure that the system has sufficient resources to handle the additional load, record and compare the CPU and memory usage profiles of your BIG-IP system before and after implementing optimized applications support.
  • Differences in each of the compression settings (Deflate, LZO, Bip2, and Adaptive)—Each setting requires a different amount of CPU and provides a different compression ratio. For more information about each, refer to the Creating Optimized Application Tunnels chapter of the BIG-IP APM: Network Access manual.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Optimize the TCP profile

Beginning in BIG-IP 13.0.0, for a BIG-IP virtual server using the TCP protocol, you can optimize the TCP transport layer by using the built-in f5-tcp-progressive profile for particular network use cases to further improve VPN performance. The f5-tcp-progressive profile contains the very latest features for early adopters whereas the existing default TCP profile is a more conservative choice. When using the f5-tcp-progressive profile, you should take the following into consideration:

  • Before implementing the new profile, note that it may result in slightly higher CPU utilization when compared to the parent TCP profile.
  • As with all attempts to optimize the TCP profile, this requires thorough testing to ensure that it matches your specific network environment.
  • You can configure this profile either on the client side or the server side or both. For server-side connectivity, you can realize increases in performance can when you also tune the TCP stack on the servers to be complementary with the LAN profile on the BIG-IP system.
  • On the client side, the improvement in performance varies according to the network. For example, for client-side connections that traverse a WAN (latency greater than 10 ms), the new f5-tcp-progressive protocol performs significantly better than all other protocols. When there’s nominal latency the f5-tcp-progressive protocol does no harm. For a comparison of the performance on different networks with the different TCP profiles, refer to F5 Unveils New Built-In TCP Profiles on DevCentral.

For more information about the f5-tcp-progressive profile, refer to

  • Stop Using the Base TCP Profile on DevCentral
