K000163452: MCPD Restart Loop Caused by an Invalid Default Node Monitor Reference

Type
Support Solution
Published
2026-09-29
Updated
2026-09-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163452

Description

BIG-IP LTM may enter an MCPD restart loop when HA peers have inconsistent ltm default-node-monitor settings. Configuration save operations can fail with a message similar to:

01070712:3: Object of type monitor_rule with autoid 9 referenced by default_monitor_rule.node_address not found

Additional errors may include:

UCS saving process failed

01070596:3: An unexpected failure has occurred ... exiting

Lost connection to mcpd

When MCPD exits, dependent services may also restart or lose connectivity.

Environment

  • BIG-IP LTM
  • High-availability configuration
  • Different ltm default-node-monitor settings between HA peers
  • One peer references /Common/icmp, while the other has no default monitor configured:

  • ltm default-node-monitor {

    rule /Common/icmp

    }

  • ltm default-node-monitor {

    rule none

    }

Cause

Bug ID 2461325 

Recommended Actions

  1. Compare the default node monitor configuration on both HA peers:
    tmsh list ltm default-node-monitor
  2. Review the MCPD logs for the missing monitor_rule reference.
  3. Ensure that both HA peers use consistent default node monitor settings.
  4. As a workaround, set the default node monitor on the affected peer to none:
    tmsh modify ltm default-node-monitor rule none
  5. Perform configuration synchronization after correcting the inconsistent setting.
  6. Verify that configuration-save operations complete successfully and that MCPD remains running.
  7. Install a software fix that addresses Bug ID 2461325, following the applicable F5 hotfix policy.

Additional Information

The issue is not limited to a specific node type. It can occur when synchronization causes the HA peers to have inconsistent default node monitor references. A software fix is available to prevent the invalid reference and resulting MCPD restart loop.
