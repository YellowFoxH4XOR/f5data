K000158146: ipv6 AAAA query receiving SOA record response

Type
Support Solution
Published
2025-12-10
Updated
2025-12-10
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.X, 17.1.0, 17.5.1, 17.5.0, 17.1.1
Source
https://my.f5.com/manage/s/article/K000158146

Description

This article describes a technical issue where BIG-IP DNS (GTM) fails to return a synthesised IPv6 (AAAA) record for IPv4-only domains when both DNS64 and resolver cache are enabled. Symptoms include:

  • The first AAAA query after cache clear or TMM restart returns a synthesised IPv6 address.
  • Subsequent AAAA queries for the same domain return no answer, only SOA in the authority section.
  • The problem is intermittent and may depend on cache state or query patterns.
  • Other locations with similar configuration may not show the issue.

Environment

  • Product: BIG-IP DNS (GTM)
  • Modules: DNS
  • Configuration:
    • DNS profile with DNS64 enabled and resolver cache enabled
    • Both IPv4 and IPv6 listeners configured
    • Issue observed on specific device(s), others work as expected

Cause

Bug ID 1821089: DNS64 and resolver cache may not function together as expected.

Recommended Actions

  1. Upgrade BIG-IP DNS to a version with the fix and apply the Engineering Hotfix (EHF):
    • For v17.1.3: Download and install the public EHF for this version.
    • For v17.5.x: Request and install the EHF for this version.
    • Follow F5’s standard hotfix installation procedures.
  2. If upgrade/hotfix is not immediately possible:
    • Clearing the DNS cache or restarting TMM may temporarily restore correct behavior (disruptive; not permanent).
    • Disabling either DNS64 or resolver cache in the profile may avoid the issue (not recommended for production).
  3. After applying the fix, test AAAA queries from an IPv6 client to confirm that synthesized responses are returned as expected.

Additional Information

  • The issue is not configuration-specific; it can appear intermittently depending on traffic/cache state.
  • Devices running identical versions/configuration may behave differently due to differences in traffic patterns or cached data.
  • The public EHF for v17.x contains additional fixes; a custom EHF with only Bug ID 1821089 can be requested if needed.
  • Consider opening a proactive case with F5 Support before upgrading.
