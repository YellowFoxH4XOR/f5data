Topic

You should consider using this procedure under the following condition:

  • You want your BIG-IP system to open a new socket for each monitor request.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must be able to use the TMOS Shell (tmsh) to access your BIG-IP system.

Description

By default, if the BIG-IP monitoring process bigd has an open socket to the monitored node and a subsequent monitor request is sent before a response to the previous request has been received, the bigd process reuses the existing open socket for that monitor request.

Sockets are reused under the following conditions:

  • For TCP:
    • The TCP connection is successfully established.
    • No response is received from the server.
    • The connection is not shut down (FIN) or terminated (RST).
  • For UDP:
    • No response is received from the server.
    • No error (such as ICMP Destination Unreachable) is received in response to UDP datagrams.

If the bigd process is able to establish a TCP connection to a node but the node is not responding in any other way, the BIG-IP system may prematurely mark down the node, even if other connections to that node respond correctly. Similarly, if a UDP monitor's transmitted data is successfully delivered to a node, but the node does not respond in any way, the BIG-IP system may prematurely mark the node down. For UDP monitors, since there is no connection, this behavior appears as multiple datagrams from the same source port.

The following examples demonstrate instances when reuse of an existing source port may result in the system unexpectedly marking down a node:

  • You have an HTTP monitor configured to monitor a node, and, after the initial TCP three-way handshake, the node doesn’t respond before the next monitor interval. The BIG-IP system sends subsequent monitor requests over the same open socket, expecting a response and marking the host down after the timeout. Reasons for the lack of response from the node are usually external to the BIG-IP system, such as if a node must query a database server that doesn't respond. Other connections to this node may still respond as expected, so this host is unexpectedly marked down.
  • You have a DNS monitor configured to monitor a node, and no response is received to a query before the next monitor interval. The BIG-IP system sends subsequent queries over the same open socket (from the same source port), expecting a response and marking the host down after the timeout. This may occur if a single response is lost, then the DNS server ignores additional queries from the same source port.

By disabling the bigd.reusesocket database key, you can force the bigd process to open a new socket for every monitor request.

Procedures

Disabling the bigd.reusesocket database key

Impact of procedure: Disabling the bigd.reusesocket database key affects all monitors on the system and in rare cases may cause port exhaustion.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To disable the bigd.reusesocket database key, type the following command:

    modify sys db bigd.reusesocket value disable

  3. Save the change by typing the following command:

    save /sys config
