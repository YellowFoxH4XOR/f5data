Known Issue

Client SSL profiles may fail to load when they have no reference to an SSL key and certificate pair, or the inherit-certkeychain option is not configured.

This issue occurs when all of the following conditions are met:

  • The system has an administrative partition other than /Common, which contains one or more configuration objects.
  • The BIG-IP system default profile named crypto-server-default-clientssl or a custom Client SSL Profile has no reference to an SSL key and certificate pair, or the inherit-certkeychain option is not configured.

Impact

The BIG-IP system is unable to process traffic, because the configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP configuration fails to load, and the BIG-IP system produces an error message similar to the following example at the command prompt and in the /var/log/ltm file:

    01070726:3: ClientSSL Profile /Common/example_ssl_profile in partition Common cannot reference ClientSSL CertKeyChain Entry /Common/example_ssl_profile default_default in partition Uncommon

  • After upgrading the BIG-IP system to 11.6.0, the configuration fails to load.
  • A user configuration set (UCS) on a BIG-IP system running 11.6.0 fails to load.

Workaround

To work around this issue, you can ensure that the default SSL profile crypto-server-default-clientssl and all child SSL profiles reference an SSL key and certificate, or have the inherit-certkeychain option configured. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Modifying the default crypto-server-default-clientssl profile.

  1. Log in to the command line of the BIG-IP system.
  2. Remount the /usr file system in read-write mode by typing the following command:

    mount -o remount,rw /usr

  3. Using a text editor, edit the /defaults/profile_base.conf file and find the crypto-server-default-clientssl object and ensure that both cert and key options and the inherit-certkeychain option match the following example:

    ltm profile client-ssl crypto-server-default-clientssl {
    defaults-from /Common/clientssl
    cert-key-chain {
    default {
    cert /Common/default.crt
    chain none
    key /Common/default.key
    passphrase none
    }
    }
    cert /Common/default.crt
    chain none
    key /Common/default.key
    passphrase none
    inherit-certkeychain true
    }

  4. Save the /defaults/profile_base.conf file.
  5. Using a text editor, edit the /config/profile_base.conf file and find the crypto-server-default-clientssl object, and ensure that both the cert and key options and the inherit-certkeychain option match the example in step 4.
  6. Save the /config/profile_base.conf file.
  7. Remount the /usr file system in read-only mode by typing the following command:

    mount -o remount,ro /usr

  8. Load the system configuration by typing the following command:

    tmsh load sys config

Modifying the child SSL profile.

  1. Log in to the command line of the BIG-IP system.
  2. Using a text editor, edit the /config/bigip.conf file and find any profile that begins with ltm profile client-ssl. Ensure that all profiles have an associated cert and key, and the inherit-certkeychain true option is configured as in the following example:

    Note: The SSL profile requires only a cert and key reference; the referenced cert and key does not have to match the example.

    ltm profile client-ssl /Common/example {
    app-service none
    cert-key-chain {
    default {
    cert /Common/example.crt
    key /Common/example.key
    }
    }
    defaults-from /Common/clientssl
    inherit-certkeychain true
    }

  3. Save the /config/bigip.conf file.
  4. Load the BIG-IP system configuration by typing the following command:

    tmsh load sys config
