Known Issue

This is the result of a known issue. If you configure a Network Access connection to auto-launch Microsoft Outlook, and you did not specify an application parameter in the optional Parameters field, Outlook does not launch properly on the client system. When this issue occurs, Outlook may report an error message that appears similar to the following example:

Cannot start Microsoft Office Outlook. The command line argument is not valid. Verify the switch you are using.

F5 Networks Product Development tracked this issue as CR102196 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue has been fixed in cumulative hotfix HF-602-8, which has been issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by configuring an Outlook command-line switch in the optional Parameters field, along with the path to Outlook configured in the required App Path field. For example, the /recycle command-line switch instructs Outlook 2003 and 2007 to use an existing Outlook window, if open, instead of launching a new instance of Outlook. For information about other Outlook command-line switches, refer to your Microsoft Outlook documentation.

Note: The App Path and Parameters fields are located on the Network Access : Resources page under the Launch Application tab.
