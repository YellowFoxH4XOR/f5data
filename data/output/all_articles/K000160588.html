Description

When configuring a client SSL profile on BIG-IP to use a CA bundle containing multiple root CA certificates, only the first CA with a given Common Name (CN) in the bundle is used for client certificate validation. If two root CAs with the same CN are included in the bundle, only the first one is considered during the certificate chain validation process. As a result, client certificates signed by the second CA with the same CN will fail validation. This behavior is observed when following procedures such as those in K83002327 for CA bundle creation.

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • Configuration:
    • Client SSL profile using a CA bundle for "Trusted Certificate Authorities" and "Advertised Certificate Authorities"
    • CA bundle containing multiple root CA certificates, potentially with the same CN
    • Client certificates signed by different root CAs

Cause

This behavior is due to the OpenSSL 1.0.x implementation used by BIG-IP. OpenSSL performs a hash-based subject lookup and only uses the first matching CA with a given CN in the bundle for certificate validation. If multiple CAs with the same CN are present, only the first is used, and others are ignored for chain validation.

Answer/Recommended Actions

  • Avoid including multiple root CA certificates with the same Common Name in a single CA bundle on BIG-IP.
  • If it is necessary to support both an old and a new root CA with the same CN, consider the following:
    1. Use a cross-signed intermediate CA that is signed by both the old and new root CAs. This allows clients with either root CA to validate the certificate chain.
    2. If cross-signing is not possible, only one root CA with a given CN can be present in the CA bundle for successful validation.
  • To check if a certificate is a CA certificate, use:
    openssl x509 -in /config/ssl/ssl.crt/<certificate_name>.crt -noout -text
    and verify the "CA:TRUE" value under "Basic Constraints".

Additional Information

  • This is expected behavior due to the OpenSSL version used by BIG-IP.
  • When root CAs in the bundle have different CNs, client certificates signed by either CA are validated successfully.
  • The order of certificates in the bundle is significant when CAs share the same CN.
