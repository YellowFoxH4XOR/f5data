Description

A critical disk space issue may occur on BIG-IP systems, indicated by the error message:

011d0004:3: Disk partition / has only 2% free

System logs may repeatedly show:

err diskmonitor[PID]: 011d0004:3: Disk partition / has only 2% free

This condition can impact system stability and normal operations. Investigation may reveal large files in directories such as /opt/Solarwinds/Agent/bin/.

Environment

  • Product: BIG-IP
  • Configuration Detail: Installation of third-party Solarwinds agent for monitoring

Cause

The root (/) partition on BIG-IP systems is intentionally small. Installing third-party software such as the Solarwinds agent can result in accumulation of large files within directories like /opt/Solarwinds/Agent/bin/, quickly exhausting available disk space. Storing files directly in the root partition (including /home, /, /tmp, or /opt) increases risk of disk space exhaustion and related system errors.

Recommended Actions

  • Remove any third-party software (e.g., Solarwinds agent) from the BIG-IP system; installation of such software is not supported. see K93238294 : Support for 3rd party software installation for details.
  • Use SNMP-based monitoring for BIG-IP devices from Solarwinds, which is recommended and supported. see K000135567: Setting up SNMP monitoring for BIG-IP via Solarwinds for more details.
  • Regularly monitor disk usage and avoid storing files in the root partition; use designated directories such as /shared for storing temporary or large files.
  • To identify large files, use commands such as:
    find / -xdev -type f -exec du {} \; | sort -rn | head -20
    du -xh / --max-depth=1
  • Remove unnecessary files (such as old qkview, pcap, log files, or dead.letter) using the rm command.
  • Refer to F5 documentation for best practices on disk space management and supported monitoring configurations.
