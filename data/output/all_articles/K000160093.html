Description

When using the NGINX Load Balancer for Kubernetes (NLK) setup guide with a local Kubernetes cluster and NGINX Ingress Controller (NIC), issues arise when attempting to route traffic to multiple application upstreams using a single nodePort Service.

Problem: When a single nodePort Service is configured and the same statefile is shared across multiple upstreams in the NGINX configuration, only the original upstream receives NLK updates. Other upstreams require a manual NGINX reload to reflect the NLK changes.

 

Environment

  • NGINX Ingress Controller cluster with NGINX Load Balancer for Kubernetes (NLK) installed
  • NGINX Plus Load Balancer
  • nodePort Service configuration
  • Shared statefile between multiple upstreams
  • NLK updating NGINX configuration with upstream information

Cause

NLK is designed to support one nodePort per upstream application and will only update one API endpoint per nodePort. When the API is updated with new information from NLK, NGINX updates the corresponding statefile to ensure consistency in case of an NGINX reload.

Limitation: Sharing a single nodePort across multiple upstreams is not supported by NLK's design.

 

Answer/Recommended Actions

Use one nodePort per application or upstream

Example Configuration

app1 Namespace

apiVersion: v1
kind: Service
metadata:
name: nodeport-app1
namespace: app1-namespace
annotations:
# Let the controller know to pay attention to this service.
# If you are connecting multiple controllers, the value can be used to distinguish them.
nginx.com/nginxaas: nginxaas
spec:
type: NodePort
ports:
- targetPort: 443
port: 443
protocol: TCP
# The port name must be prefixed with either `http-` or `stream-`
# and the rest of the name must match the name of an upstream in that context.
name: http-app1-upstream
selector:
app.kubernetes.io/name: nginx-ingress

app2 Namespace

apiVersion: v1
kind: Service
metadata:
name: nodeport-app2
namespace: app2-namespace
annotations:
# Let the controller know to pay attention to this service.
# If you are connecting multiple controllers, the value can be used to distinguish them.
nginx.com/nginxaas: nginxaas
spec:
type: NodePort
ports:
- targetPort: 443
port: 443
protocol: TCP
# The port name must be prefixed with either `http-` or `stream-`
# and the rest of the name must match the name of an upstream in that context.
name: http-app2-upstream
selector:
app.kubernetes.io/name: nginx-ingress

Load Balancer config

upstream app1-upstream {
  zone app1-upstream 256k;
  least_time last_byte;
  keepalive 16;
  state /var/lib/nginx/state/app1-upstream.state;
}

upstream app2-upstream {
  zone app2-upstream 256k;
  least_time last_byte;
  keepalive 16;
  state /var/lib/nginx/state/app2-upstream.state;
}

 

Additional Information

  • The nodePort Service can be deployed in either the NGINX Ingress Controller namespace or in an application-specific namespace.
  • Each upstream requires its own dedicated nodePort Service and unique statefile for NLK to function correctly.
  • The port name in the Service definition must follow the naming convention: http-;<upstream-name> or stream-<upstream-name> to match the corresponding upstream block in the NGINX configuration.
