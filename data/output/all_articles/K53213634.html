Issue

Description

  • The virtual server is not passing traffic.
  • The virtual server resets connections.
  • Pool members responding with a TCP Reset.
  • The following warning message is logged in /var/log/ltm:

    warning tmm[<PID>]: 01260009:4: Connection error: ssl_null_parse:3167: record length too large (22)

    • <PID> is the current Process ID for TMM.

Environment

  • Server SSL profile assigned to virtual server
  • Pool with port 80 members

Cause

Server SSL profile is assigned to a virtual server but the pool members expect HTTP traffic on port 80.

Recommended Actions

There are two methods to resolve this issue:

  • If the server-side connections are intended to be HTTP (not HTTPS), remove the Server SSL Profile from the virtual server.
  • If the pool is a mixture of HTTP and HTTPS pool members, you can assign an iRule to the virtual server that allows the BIG-IP system to establish an SSL session with the port 443 pool members only. For connections to any other pool members the BIG-IP will not attempt an SSL session. For example,

    when SERVER_CONNECTED {
      if {[LB::server port] == 443 } {
      } else {
        catch SSL::disable
      }
    }
