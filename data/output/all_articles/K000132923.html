Source
https://my.f5.com/manage/s/article/K000132923

Description

  • SIP traffic may fail after upgrading to 16.0.0
  • The SIP 200 OK response is dropped by the BIG-IP, and calls fail translation

Environment

  • BIG-IP
  • v16.x and later
  • SIP MRF profile
  • SIP Route: header uses a domain name instead of an IP address (FQDN)

Cause

  • Bug ID 1213469

 Recommended Actions

One workaround is to remove the Route: header before SIP MRF processes the packet, then adding it back before sending out the SIP packet.

Example iRule:

when SIP_REQUEST {
     set pd_route_hdr_count [SIP::header count Route]
     set pd_route_unset 0
     set pd_route [SIP::header Route]
     if {[SIP::method] == "INVITE" && ($pd_route_hdr_count equals 1) && $pd_route contains "sip:<customerfqdnroute.customersite.net>;lr" } {
          SIP::header remove "Route"
          set pd_route_unset 1
     }
}

when SIP_REQUEST_SEND {
     if {[SIP::method] == "INVITE" && ($pd_route_unset == 1)} {
          SIP::header insert "Route" $pd_route
     }
}

 

Additional Information

The problem appears when the SIP request Route: header uses a name (FQDN, not IP). The BIG-IP then should have created a related connflow to listen to the SDP IP address, but it did not, and caused the issue.
