Known Issue

This is the result of a known issue. After adding an HTTP class with Application Security enabled on the virtual server, BIG-IP ASM may show high CPU utilization for CPU0. The high CPU utilization is due to the learning_manager.pl, script, which parses request violations and provides suggestions on the Forensics screen about modifying the policy. When there are a high volume of request violations, the learning_manager.pl process may use excessive CPU time.

F5 Product Development tracked this issue as CR71620, and beginning in BIG-IP ASM 9.3 and 9.4, the learning_manager.pl process is assigned a lower CPU priority than the BIG-IP ASM processes responsible for passing traffic. Because of this, you may still see high CPU utilization for the learning_manager.pl process when the BIG-IP ASM system is mostly idle. However, as traffic load increases, the proportion of CPU time allocated to the learning_manager.pl process will be reduced. This reduction allows the traffic processing components of BIG-IP ASM as much CPU time as they require, so as not to affect the traffic processing capabilities of the unit. For information about upgrading, refer to the BIG-IP ASM Release Notes.
