Known Issue

The BIG-IP system may experience high Traffic Management Microkernel (TMM) memory usage when User Datagram Protocol (UDP) flows are not correctly cleared.

This issue occurs when all of the following conditions are met:

  • You have a virtual server with a UDP profile configured and the Datagram LB option enabled.
  • The virtual server experiences heavy load with many UDP connections.

Impact

The BIG-IP system exhibits high TMM memory usage and may generate a core file, leading to traffic disruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM produces a core file and temporarily fails to process traffic.
  • TMM memory usage continually increases in performance graphs.
  • In the /var/log/ltm file, you observe error messages similar to the following example:

    011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (0) (global memory) 4928 Connections killed

  • You observe a high number of UDP connection flows in the TMM statistics, but not in the connection table.
    • To list the number of connections for a virtual server, use the following command syntax:

      tmsh show sys connection cs-server-addr <virtual_server_IP_address> cs-server-port <virtual_server_port> | grep "Total records"

      For example, type the following command for a virtual server with IP address 10.5.2.104 and port number 53:

      tmsh show sys connection cs-server-addr 10.5.2.104 cs-server-port 53 | grep "Total records"

      Output appears similar to the following:

      Total records returned: 200

    • To list the TMM statistics, type the following command:

      tmctl virtual_server_stat -w 160 -s name,clientside.cur_conns,clientside.max_conns,clientside.tot_conns,serverside.cur_conns,serverside.max_conns,serverside.tot_conns;tmctl profile_dns_stat -s drops,malformed

      Output appears similar to the following:

      name       clientside.cur_conns clientside.max_conns clientside.tot_conns .. serverside.tot_conns drops malformed
      ---------- -------------------- -------------------- -------------------- .. -------------------- ------ ---------
      exampleVS1  23574                30471               100000                   0                   100000    100000

    In these examples, note the exampleVS1 virtual server's high number of client side connections and dropped packets in the TMM statistics, and significantly lower number of connections in the connection table.
