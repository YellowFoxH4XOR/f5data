Topic

Important: In BIG-IP 11.x, the symmetric deployment feature is not functional, and as a result, may not be affected by the limitation discussed in this article. For more information, refer to K13561: The symmetric deployment feature is not functional in WebAccelerator 11.x.

Note: The BIG-IP WebAccelerator 10.0.x fails to be added to a symmetric deployment, and as a result, may not be affected by this limitation. For more information, refer to K12578: The wam_add.pl utility fails when attempting to add a BIG-IP WebAccelerator to a symmetric deployment.

BIG-IP WebAccelerator systems in a symmetric deployment use iQuery to exchange database updates regarding shared policy, application, and HTTP class configuration objects. iQuery uses the device certificate to authenticate the session as it accesses information through the secure management web server running on the BIG-IP WebAccelerator. The default length of validity for the device certificate on the BIG-IP WebAccelerator is one year. When the device certificate expires, iQuery requests sent to the affected system fail because the device certificate is no longer valid. As a result, the BIG-IP WebAccelerator systems are unable to communicate changes to each other.

Workaround

To work around this limitation, perform the following procedures:

  • Renewing the BIG-IP WebAccelerator certificate
  • Running the bigip_add script
  • Restarting the comm_srv process on WebAccelerator version 9.x

Renewing the BIG-IP WebAccelerator certificate

You can renew the BIG-IP WebAccelerator certificate for another year or for longer than one year. To do so, perform the appropriate procedure below.

Renewing the BIG-IP WebAccelerator certificate for another year

Impact of procedure: None.

  1. Log in to the BIG-IP WebAccelerator Configuration utility on the system with the expired certificate.
  2. Select System.
  3. Select Device Certificates.
  4. Select Renew.
  5. Change Issuer from Certificate Authority to Self.

    Note: As an optional step, you may choose to update any of the remaining certificate information at this point.

  6. Click Finished.

Renewing the BIG-IP WebAccelerator certificate for longer than one year

Note: Beginning in BIG-IP 10.0.0, you can adjust the self-signed device certificate's validity within the Configuration utility. For more information, refer to K10233: Change in Behavior: Self-signed device certificates lifetime value can be configured within the Configuration utility.

Impact of procedure: You may momentarily lose connectivity to the Configuration utility until the httpd process is running.

  1. Log in to the command line.
  2. Change directories to the /config/httpd/conf/ssl.crt directory by typing the following command:

    cd /config/httpd/conf/ssl.crt

  3. Convert the server.crt certificate to a certificate signing request .csr by typing the following command:

    openssl x509 -x509toreq -in server.crt -out server.csr -signkey /config/httpd/conf/ssl.key/server.key

  4. Using the new CSR, specify the number of days for which the certificate should be valid by typing the following command:

    openssl x509 -req -in server.csr -signkey /config/httpd/conf/ssl.key/server.key -days <# of days> -out server.crt

    Replace <# of days> with the number of days in year increments for which you want the certificate to be valid.

    For example, if you want to make the certificate valid for a year, type the following command:

    openssl x509 -req -in server.csr -signkey /config/httpd/conf/ssl.key/server.key -days 365 -out server.crt

    You can use the following quick reference table to select the number of years for which you want the certificate to be valid:

    Years
    		Number of Days
    1365
    2730
    51826
    103652
  5. Restart the web server daemon by typing the following command:

    bigstart restart httpd

Running the bigip_add script

After you have renewed the SSL certificate, you must run the bigip_add script on both BIG-IP WebAccelerator systems so each system can update its configuration with the new SSL certificate. Failure to run the script on both systems prevents the systems from communicating as required.

This procedure authenticates, copies, and adds the certificate to the remote system, allowing the BIG-IP WebAccelerator system to authenticate the certificate each time it communicates with its partner. To run the bigip_add script, perform the following procedure:

Impact of procedure: None.

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Enter the following command:

    bigip_add <remote_wa_system>

  3. Enter the root password of the remote BIG-IP WebAccelerator system, when prompted.

Additionally, if this BIG-IP WebAccelerator system is communicating with a BIG-IP GTM system, you must ensure that the renewed device certificate is added to the trusted device certificate file on the BIG-IP GTM system. You can do so by running the bigip_add utility on the BIG-IP GTM system. Failure to run the bigip_add utility prevents the BIG-IP GTM system from communicating with this BIG-IP WebAccelerator system.

Note: If the BIG-IP GTM systems are in a synchronization group, you need to perform this procedure on only one BIG-IP GTM system. If the BIG-IP GTM systems are not in a synchronization group, you must perform this procedure on each BIG-IP GTM system that had its device certificate updated or changed, that communicates with this BIG-IP system.

This procedure authenticates, copies, and adds the device certificate to the /config/gtm/server.crt file, which allows the BIG-IP GTM system to authenticate the certificate each time it communicates with this BIG-IP WebAccelerator system. To add the renewed device certificate, perform the following procedure on the BIG-IP GTM system:

Impact of procedure: None.

  1. Log in to the BIG-IP GTM command line.
  2. Enter the following command:

    bigip_add <BIG-IP_WA_IP_address>

  3. Enter the root password of the BIG-IP WebAccelerator system, when prompted.

Restarting the comm_srv process on BIG-IP WebAccelerator 9.x

For BIG-IP WebAccelerator 9.x, you have to perform an additional step to restart the comm_srv process on the BIG-IP WebAccelerator system that has the rsync error logs (previously referred to in this article). This action is necessary to ensure that the comm_srv process is running properly with the new SSL certificate. To restart the comm_srv process, perform the following procedure on each of the affected BIG-IP WebAccelerator systems:

Impact of procedure: Restarting the comm_srv process only momentarily affects the configuration synchronization between peers in the symmetric deployment; restarting the comm_srv process does not affect traffic processing on the WebAccelerator system.

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Enter the following command:

    bigstart restart comm_srv
