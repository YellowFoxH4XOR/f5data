Known Issue

An improperly formatted HTTP request-line may cause connections to hang and eventually timeout.

This issue occurs when the following conditions are met:

  • The HTTP request-line contains an improperly formatted protocol version token.
  • The virtual server references an HTTP profile.

If the client request contains an HTTP request-line with an improperly formatted protocol version, the BIG-IP system assumes the version to be HTTP/0.9. For example, the following request-line contains an invalid HTTP version token:

GET / HTTP/ <CRLF>

In the previous example, the BIG-IP system buffers any data following the CRLF, including HTTP headers (for example, the Host header). Some web servers, such as Apache and IIS, may consider the request to be HTTP/1.1, and wait for additional data (for example, the Host header), before sending a reply. Since no data is forthcoming, the connection hangs for several seconds until the server times out the connection.

Impact

Resources may become exhausted on the back-end server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H524489 on the Diagnostics > Identified > Medium screen.
  • The connection hangs and eventually times out.
  • Resources on the back-end server may become exhausted.

Workaround

To work around this issue, you can configure an iRule that validates the HTTP version and sets the version correctly on the server-side of the connection. In addition, you can adjust the protocol profile idle timeout as required.

Impact of workaround: The following iRule examples may not apply to all environments. F5 recommends that you author an iRule that may work best for your application environment. Additionally, adding an iRule may increase the resources used by the associated virtual server. For more information about iRule commands, refer to the iRules wiki page on DevCentral.

  • Configure an iRule that validates improperly formatted HTTP request-lines and properly formats the request.

    For example, the following iRule validates the HTTP version in the request, and changes the version to HTTP/1.1 on the server-side of the connection:

    when HTTP_REQUEST {
    if { [HTTP::version] ne "1.0" and [HTTP::version] ne "1.1" } {
    # Set server side request version to 1.1
    HTTP::version "1.1"
    }
    }

  • Adjust the protocol profile timeout as required.

    For example, you can use the following Traffic Management Shell (tmsh) command syntax to adjust the TCP protocol profile timeout from the default of 300 seconds to a value that is suitable for your application:

    tmsh modify /ltm profile tcp <profile_name> idle-timeout <seconds>
