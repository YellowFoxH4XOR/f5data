Issue

Old Behavior

In versions prior to BIG-IP 13.0.0, when all members of a pool have been disabled, the virtual server state is reported as Available (enabled).

Disabling all members of a pool is not accurately reflected by the virtual server status displayed in the Configuration utility or the TMOS Shell (tmsh).

  • The virtual server status is displayed in the Configuration utility as a green circle with hover text that reads as follows:

    Available (enabled) - The virtual server is available

  • The virtual server status is displayed in tmsh as available and enabled similar to the following:

    ------------------------------------------------------------------
    Ltm::Virtual Server: http_vs
    ------------------------------------------------------------------
    Status
      Availability     : available
      State            : enabled
      Reason           : The virtual server is available
      CMP              : enabled
      CMP Mode         : all-cpus
      Destination      : 10.11.10.201:80

Additionally, with a virtual server status of Available (enabled), a new connection to a virtual server that has all associated pool members disabled is required to complete a 3-way TCP handshake, and allow the client to send an initial packet before resetting the connection with a reset cause of No pool member available.

For example:

C  > VS --- Syn
VS > C  --- Syn / Ack
C  > VS --- Ack
C  > VS --- Data Packet
VS > C  --- Ack
VS > C  --- Reset (rst_cause=No pool member available)

New Behavior

Beginning in BIG-IP 13.0.0, when all members of a pool have been disabled, the virtual server state is reported as Available (Disabled Parent).

Disabling all members of a pool is now accurately reflected by the virtual server status displayed in the Configuration utility or tmsh.

  • The virtual server status is displayed in the Configuration utility as a grey circle with hover text that reads as follows:

    Available (Disabled Parent) - The children pool member(s) might be disabled

  • The virtual server status is displayed in tmsh as available and disabled-by-parent similar to the following example:

    ------------------------------------------------------------------
    Ltm::Virtual Server: http_vs
    ------------------------------------------------------------------
    Status
      Availability     : available
      State            : disabled-by-parent
      Reason           : The children pool member(s) might be disabled
      CMP              : enabled
      CMP Mode         : all-cpus
      Destination      : 10.11.10.201:80

Additionally, with a virtual server status of Available (Disabled Parent), a new connection to a virtual server that has all associated pool members disabled will not require a complete a 3-way TCP handshake. The connection is immediately reset following the initial Syn, with a reset cause of VIP disabled (administrative).

For example:

C  > VS --- Syn
VS > C  --- Reset (rst_cause=VIP disabled (administrative)F5 Product Development tracked this change as ID 597899.

Impact

The status of a virtual server that has all associated pool members disabled is now accurately reported.

Additionally, the system no longer requires the additional overhead of the 3-way TCP handshake to reset the connection. However, this new reset behavior creates unwanted behaviors. The following BIG-IP 15.1.0 articles in F5 Bug Tracker track these behaviors:

  • Bug ID 783617
  • Bug ID 718790
