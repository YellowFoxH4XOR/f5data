Known Issue

Important: This issue occurs only when using the non-NATIVE SSL stack, such as specifying EXPORT ciphers or a cipher stack that is not included with the default SSL stacks.

This is the result of a known issue. SSL connections may hang when sending or receiving SSL records greater than 14 KB. Hanging occurs when BIG-IP LTM receives the entire record but does not forward the record until either the client or server requests the connection to be closed. As a result, BIG-IP LTM sends the data just before the TCP connection is closed.

Note: This issue affects both the ClientSSL and the ServerSSL profile.

F5 Product Development tracked this issue as CR67244 and CR58885, and it was fixed in BIG-IP LTM 9.1.3, 9.2.4, and 9.3. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

To work around this issue, you can use the following iRule to close a keep-alive connection for the specific URI that is causing the problem:

when HTTP_REQUEST {
if {[HTTP::uri] contains "Problem URI here"} {
HTTP::header replace Connection: Close
}
}

This iRule replaces the client's Connection: Keep-Alive header with a Connection: Close header before passing it back to the server. As a result, the server closes the connection after the data has been sent and BIG-IP LTM will forward the information before the TCP connection is closed.
