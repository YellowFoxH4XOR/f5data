Description

BIG-IQ was unable to delete an application from the Application tab, blocking the removal of services from a managed BIG-IP device. The deletion failed with the error: "unable to retrieve config to delete.: Get document for key: cm/global/classic-configs/xxxxxxx-xxxx-xxxx-xxxx-xxxx12cexxxx returned nothing"

Environment

- BIG-IQ version 8.4.1, platform: F5-BIQ-VE-S

- Application visible in BIG-IQ GUI but could not be deleted via standard UI or force-delete REST API

- Force-delete task failed at step `GET_CONFIG_REFERENCES_TO_DELETE` with the above error, indicating the application's configuration document could not be located in the BIG-IQ database

- Issue consistent with a UUID/machineId mismatch in the BIG-IQ database (e.g., caused by a UCS restore on the managed BIG-IP)

Cause

A UUID/machineId mismatch in the BIG-IQ database caused the application's configuration document to be unreachable during deletion. When the force-delete task attempted to retrieve the configuration document using the stored key/xxxxxxx-xxxx-xxxx-xxxx-xxxx12cexxxx returned nothing

Answer/Recommended Actions

- Take a UCS backup of the BIG-IQ system before proceeding with any remediation steps.

- Verify machineId mismatch on BIG-IQ CM:

 

```

restcurl cm/system/machineid-resolver | grep "uuid\|machineId\|hostname"

```

- If a mismatch is found, correct the device ID on the managed BIG-IP by editing `/config/f5-rest-device-id` with the correct UUID from Step 1, then restart restjavad:

```

tmsh restart sys service restjavad

```

 

- Re-discover and re-import LTM on BIG-IQ: navigate to **Devices > BIG-IP Devices > [affected BIG-IP] > SERVICES > Local Traffic (LTM) > Re-discover > Re-import**.

- Retry the force-delete via REST API:

 

```

restcurl -X POST cm/global/tasks/force-delete -d/<UUID>`), it returned nothing because the document no longer existed at that path — likely due to a prior UCS restore on the managed BIG-IP that changed its machineId. The force '{"configSetName":"<<Legacy Application Name>>"}'

```

- If the force-delete removes data but leaves a stale application index (application still visible in GUI), manually delete the residual index entry from the BIG-IQ database.

- If the application is not a legacy type and deletion is blocked by remaining `appComponents`, list the application ID and delete each component before deleting the parent application object:

 

```

restcurl /cm/global/global-apps/ | jq '.items[]|{name:.name,id:.id}'

restcurl /cm/global/global-apps/<app-id>

```

- After the blocking application is removed, proceed to remove BIG-IP device services via **Devices > BIG-IP Devices**. If GUI-based removal fails, use the REST API approach documented in KB K01131523.

Additional Information

- KB K70894946: "Unable to delete application on BIG-IQ" — describes the known issue where a machineId change on a managed BIG-IP (e.g., after UCS restore) causes a UUID mismatch in the BIG-IQ database, resulting in force-delete failures with the "returned nothing" error.

- KB K42354921: Referenced for removing BIG-IP device services after the blocking application is cleared.

- KB K01131523: REST API approach for removing BIG-IP device services when GUI-based removal fails.
