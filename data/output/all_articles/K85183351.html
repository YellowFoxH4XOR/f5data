Topic

You should consider using this procedure under the following condition:

  • You want to deploy a BIG-IP VE instance in an existing Proxmox Virtual Environment prior to version 9.x.

Note:  F5 will provide assistance in relation to the underlying KVM environment.

For information about deploying BIG-IP VE instances on Proxmox Virtual Environment 9.x, refer to K000159686: Deploying BIG-IP Virtual Edition in Proxmox Virtual Environment 9.x.

Description

The Proxmox Virtual Environment integrates the Kernel-based Virtual Machine (KVM) hypervisor, LXC Linux containers, software defined storage and network functionality into a single management platform that allows configuration, deployment, and monitoring through browser-based access. The following procedures outline how to deploy a BIG-IP VE instance using the Proxmox Virtual Environment.

Note: You cannot upload or import image files through the Proxmox Virtual Environment GUI.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a general understanding of the Proxmox Virtual Environment.
  • You are familiar with using the Linux command line.
  • You can access the Proxmox Virtual Environment on TCP ports 8006 and 22.
  • You have a BIG-IP registration key and access to the internet.

    Note: The BIG-IP VE instance does not require access to the internet; however, internet access is required to complete licensing of the BIG-IP VE instance.

Procedures

  • Create a new virtual machine (VM)
  • Add additional network interfaces to the BIG-IP VM
  • Utilize the BIG-IP qcow2 disk image
  • Alternate method to use the BIG-IP qcow2 disk image
  • Launch the BIG-IP VM instance

Optional procedures

  • Optional: Considerations for configuring the Proxmox Virtual Environment and multiple VM networks
  • Optional: Install the ifupdown2 utility for non-subscription Proxmox Virtual Environments
  • Optional: Modify the /etc/networks/interfaces file

Create a new virtual machine (VM)

The following procedure creates a base virtual machine (VM) that specifies the BIG-IP VE name, CPU, memory, and management network settings

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Proxmox Virtual Environment GUI.
  2. Select Server View.
  3. Go to Datacenter.
  4. Select the Proxmox Virtual Environment name for which you want deploy the BIG-IP VE instance.
  5. In the upper-right corner of the GUI, select Create VM.
  6. Select the Advanced check box.
  7. In General, enter a name for the VM instance in the Name text box and select Next.

    Important: Note the numeric VM ID.

  8. In OS, for Use CD/DVD disc image file (iso), select Do not use any media.
  9. For Guest OS Type, select Linux and Version to 5.x-2.6 Kernel, then select Next.
  10. In System, for SCSI Controller, select VirtIO SCSI.
  11. For BIOS, select SeaBIOS (default).
  12. For Machine, select i440fx (default), and select Next.

    Note: You must select 8.0 for Version after selecting i440fx for Machine; selecting any other versions may result in error 51133 license activation failure when you attempt to activate a license for the BIG-IP. If there is no Version field for selection, proceed to the next step. After completing the wizard, you can return to Hardware > Machine to configure the Version field.

  13. In Hard Disk, for Bus/Device, select SCSI 1.
  14. For Cache, select No cache.
  15. For Storage, select a location.
  16. For Disk size, select 1G.

    Note: The disk is not used in the final configuration.

  17. For Format, select QEMU (qcow2).
  18. Leave all other settings at the defaults and select Next.
  19. In CPU, for Type, select kvm64 (default).

    Note: F5 recommends that you review the memory and CPU requirements for KVM deployments in K15796: Hardware requirements to host BIG-IP VE on private cloud platforms.

  20. For Sockets and Cores, enter the values recommended in K15796 Hardware requirements to host BIG-IP VE on private cloud platforms.
  21. Leave all other CPU configuration options at the defaults and select Next.
  22. In Memory, for Memory(MiB), enter the value recommended in K15796 Hardware requirements to host BIG-IP VE on private cloud platforms. This is typically 2G for each core. For example, a four-core system should have a minimum of 8GB.
  23. For Minimum memory, use the same value as you did for Memory (MiB).
  24. Clear the Ballooning Device check box and select Next.
  25. In Network, select the network Bridge to use for the management interface of the BIG-IP VM instance (typically vmbr0).
  26. For Model, select VirtIO (paravirtualized) and select Next.

    Note : You can add additional interfaces (bridges) later.

  27. In Confirm, review the BIG-IP VE instance settings and make sure that Start after created is not selected.
  28. Select Finished.

Add additional network interfaces to the BIG-IP VM

The BIG-IP VM configuration currently uses a single-network interface. The following procedure adds additional network interfaces to the BIG-IP VM.

Note: Refer to Optional: Considerations for configuring Proxmox Virtual Environment and multiple VM network regarding installation issues of the ifupdown2 utility and workaround.

Important: This procedure is only required when you want a deployment in which the BIG-IP VM directly interacts with multiple local networks.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Select Hardware.
  2. Select Add.
  3. Select Network Device.
  4. For Bridge, select an additional interface to add to the BIG-IP VM.
  5. For Model, select VirtIO (paravirtualized).
  6. Select Add.
  7. Repeat steps 1 through for each additional network interface you want to add.

Utilize the BIG-IP qcow2 disk image

You need to import the BIG-IP qcow2 image file for use with the new virtual machine as an available hard drive.

To import the qcow2 file, you need to access the Proxmox Virtual Environment command line.

Impact of procedure: Performing the following procedure should not have a negative impact on your system; however, ensure that there is storage space available on the destination datastore partition greater than the BIG-IP instance qcow2 file size.

  1. Log in to the command line of the Proxmox Virtual Environment.
  2. Import the BIG-IP qcow2 image using the following qm command syntax:

    qm importdisk <VM ID> <path><big-ip version name>.qcow2 <destination datastore name>

    Note: <VM ID> is the numeric virtual machine ID assigned in the Creating a new VM procedure, and <destination datastore name> is the name of a Proxmox datastore configured when you deploy the Proxmox Virtual Environment.

    For example:

    qm importdisk 107 /mnt/pve/ISOs/images/BIGIP-16.0.0.1-0.0.3.ALL.qcow2 datastore-2

    Important: The import procedure can take several minutes.

Configuring the VM to use the imported disk image

For the new VM to boot the imported BIG-IP VE image file, you must modify the VM instance to remove the hard drive of the initial deployment and select the BIG-IP image file as the default hard drive.

The following procedure removes the initial deployment hard drive and configures the VM to use the imported hard drive.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Proxmox Virtual Environment GUI.
  2. Select Server View.
  3. Go to Datacenter.
  4. Expand the Proxmox VM list.
  5. Select the name of the previously created BIG-IP virtual machine.
  6. Select Hardware.
  7. Locate the Hard Disk generated when the BIG-IP instance was created (size=1G).

    Important: Note the disk name for the next step.

  8. Select Detach.
  9. Select the disk now displayed as an Unused Disk and ensure that the disk name is the same name of the detached disk from the previous step.
  10. Select Remove.
  11. Double-click the remaining Unused Disk (the BIG-IP imported disk).

    Important: Note the disk Bus/Device settings.

  12. Select Add.
  13. Select Options.
  14. Double-click Boot Order.
  15. Set Boot device to the imported BIG-IP disk image, based on the Bus/Device settings in the previous step.
  16. Select OK.

Alternate method to use the BIG-IP qcow2 disk image

Use the following secure copy (SCP) syntax to upload the compressed (zipped) BIG-IP VE qcow2 image to your Proxmox Virtual Environment images or ISO directory:

Important: Ensure that the destination Proxmox Virtual Environment has sufficient storage space in the partition to accommodate at the uploaded file and ZIP file extraction.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

scp <path><bigip qcow2 zip file> <user>@<proxmox ip address>:<path>

For example:

scp ./BIGIP-16.0.0.1-0.0.3.ALL.qcow2.zip root@192.168.0.240:/mnt/pve/ISOs/

After you upload the BIG-IP VE image file, access the Proxmox Virtual Environment command line and use the following command syntax to unzip the qcow2 file:

cd <path to upload file>

unzip <big-ip image file name>

For example:

unzip BIGIP-16.0.0.1-0.0.3.ALL.qcow2.zip

Locate the virtual machine autogenerated hard disk image

To find the location of the VM instance hard drive you can use following command syntax:

find / -name vm-<VM ID#>-disk*.qcow2

Note: Replace <MV ID#> with the virtual machine numeric ID.

For example:

find / -name vm-102-disk*.qcow2

Output appears similar to the following:

/var/lib/vz/images/102/vm-102-disk-0.qcow2

Move the extracted BIG-IP disk image

After the BIG-IP qcow2 disk images is extracted, move the BIG-IP image to the VM instance hard drive storage location reusing the existing name of the VM hard drive (overwriting the autogenerated qcow2 disk) that was automatically specified when the VE instance was created. 

mv <big-ip qcow2 image>  /<VM storage path>/<VM instance hard drive>

Note:Replace <big-ip qcow2 image> with the full name of the extracted BIG-IP image. Replace <VM storage path> with the directory path to the hard drive location for the VM. Replace <VM instance hard drive> with the specific autogenerated name of the VM instance qcow2 hard drive.

For example:

The VM instance numeric ID is 102 and the hard drive, generated by the Proxmox Virtual Environment when creating the virtual machine and located in /var/lib/vz/images/102, has the Proxmox generated disk name vm-102-disk-0.qcow2. Using the Linux mv (move) command, the BIG-IP disk image overwrites the auto-generated disk image name of vm-102-disk-0.qcow2.

mv BIGIP-16.0.1-0.0.3.ALL.qcow2 /var/lib/vz/images/102/vm-102-disk-0.qcow2 

Launch the BIG-IP VM instance

The following procedure launches the BIG-IP VM instance, resets the BIG-IP root password, and, if you want, configures the BIG-IP management IP address.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Select the BIG-IP VM.
  2. Select Start.
  3. Select Console.
  4. Log in to the BIG-IP console as the root/default user.

    Note: The system prompts you to reset the root password.

  5. To determine the IP address of the management interface, enter the following command:

    ip a show mgmt

  6. To change the management IP address access the TMOS Shell (tmsh) by entering the following command:

    tmsh

  7. Use the following syntax to set a static IP address for the management interface:

    modify /sys global-settings mgmt-dhcp disabled
    delete /sys management-ip <existing ip address>
    create /sys management-ip <ip address>/<netmask>
    save /sys config

    Note: These commands are not required if you prefer the BIG-IP VM to use DHCP to configure the management interface IP address.

    Note: Replace <existing ip address> with the IP address listed by the by the ip a show mgmt command.

    Note: Replace <ip address/netmask> with an available IP address on your management network range as configured on the Proxmox Virtual Environment (typically vmbr0).

  8. You can now access the BIG-IP Configuration utility using the specified management IP address to license, provision, and configure the BIG-IP virtual machine.

    Note: For single network interface deployments, access the Configuration utility using the following URL syntax: https://<management-ip address>:8443/.

    Note: <management-ip address> is the IP address configured in the previous steps or from DHCP.

Optional: Considerations for configuring the Proxmox Virtual Environment and multiple VM networks

If you want the BIG-IP VE instance to use multiple network interfaces, you must configure the Proxmox Virtual Environment with multiple network interfaces. This requires you to install the Linux ifupdown2 utility on the Proxmox Virtual Environment. For some versions of Linux, the ifupdown2 utility displays errors during installation that it cannot be installed (Debian 10 "Buster"). To work around this Linux OS limitation, you can manually modify the Proxmox Virtual Environment /etc/networks/interfaces file and specify a virtual machine bridge (VMBR) to each physical network interface.

Important: These procedures are only required when your Proxmox Virtual Environment device cannot successfully install the ifupdown2 utility and you want to configure multiple network interfaces.

Important: The following procedures were tested on Proxmox Virtual Environment version 6.2-12.

Optional: Install the ifupdown2 utility for non-subscription Proxmox Virtual Environments

In non-subscription Proxmox Virtual Environments in which you encounter an issue installing the ifupdown2 utility, you can work around this limitation by modifying the Proxmox sources list, upgrading the Proxmox Virtual Environment, and installing the ifupdown2 utility.

  1. Log in to the Proxmox Virtual Environment command line.
  2. Change to the /etc/apt/sources.list.d/ directory by entering the following command:

    cd /etc/apt/sources.list.d/

  3. Copy the source list pve-enterprise.list to pve-no-subscription.list by entering the following command:

    cp pve-enterprise.list pve-no-subscription.list

  4. Use vi, pico, or nano to open the pve-no-subscription.list file.
  5. Modify the source reference as follows:

    Original:

    deb https://enterprise.proxmox.com/debian/pve stretch pve-enterprise

    Updated:

    deb http://download.proxmox.com/debian/pve stretch pve-no-subscription

    Note: Change the protocol from https to http, change the FQDN host from enterprise to download, and change the depository from pve-enterprise to pve-no-subscription. Do not change the release name (stretch in the example).

  6. Save the changes to the pve-no-subscription.list file.
  7. Enter the apt-get utility update command:

    apt-get update

  8. Enter the apt-get distribution update command:

    apt-get dist-upgrade

  9. After completion of the distribution upgrade, restart the Proxmox virtual environment by entering the following command:

    reboot

  10. After the system starts, log in to the Proxmox Virtual Environment command line.
  11. To install the ifupdown2 utility, enter the following command:

    apt-get install ifupdown2

Disabling software updates from the pve-no-subscription source

If do not want the Proxmox Virtual Environment to automatically update using the alternate depository, perform the following procedure:

  1. Log in to the Proxmox Virtual Environment.
  2. Use vi, pico, or nano to open the /etc/apt/sources.list.d/pve-no-subscription.list file.
  3. Insert the pound symbol (#) at the beginning of the following stanza:

    deb http://download.proxmox.com/debian/pve buster pve-no-subscription

  4. Save the changes to the pve-no-subscription.list file.

Optional: Modify the /etc/networks/interfaces file

If you want the BIG-IP VE instance to use multiple network interfaces, you must preconfigure the Proxmox Virtual Environment with multiple network interfaces. This requires that you install the ifupdown2 utility on the Proxmox Virtual Environment. For some versions of Linux, the ifupdown2 utility may encounter an issue when installing. To work around this limitation, you can manually modify the Proxmox server /etc/networks/interfaces file and specify the VMBR for each network with a physical interface.

To determine available network interfaces, you can use the IP utility command ip link.

Note: For more information on the IP utility, refer to K13986052: Equivalent commands in the net-tools package and 'ip route' utility.

When determining the physical interfaces from virtual interfaces, physical interfaces excluding the loopback interface (lo:) are listed at the beginning of the IP command output. Available interfaces are not assigned an mq master vmbr <number>. You assign the vmbr<number> to the specific interfaces that you want the Proxmox Virtual Environment to present when creating or configuring a virtual machine (VM). You do this by assigning the vmbr<number> value, which you do by editing the Proxmox Virtual Environment Linux /etc/network/interfaces file.

Note: <number> signifies the numeric increment values assigned to the VMBR.

Impact of procedure: Performing the following procedure should not have a negative impact on your system; however, misconfiguration may leave the Proxmox Virtual Environment without network access.

To add VMBR values to an existing unassigned interfaces, open the /etc/networks/interfaces (Debian Linux) file using a Linux text editor, such as vi, pico, or nano, based on the following example:

The following is an example of an original /etc/networks/interfaces file in which only the loop back network (lo) and a singular physical interface are defined (enp2s0f0):

auto lo
iface lo inet loopback
iface enp2s0f0 inet manual

auto vmbr0
iface vmbr0 inet static
address 192.168.0.1/24
gateway 192.168.1.254
bridge-ports enp2s0f0
bridge-stp off
bridge-fd 0

The following is an example of an updated Proxmox Virtual Environment /etc/networks/interfaces file in which the virtual machine bridges vmbr1 and vmbr2 are added for the networks 172.16.1.0/24 and 10.0.0.0/16 respectively:

auto lo
iface lo inet loopback
iface enp2s0f0 inet manual
iface enp2s0f1 inet manual
iface enp3s0f0 inet manual
iface enp3s0f1 inet manual


auto vmbr0
iface vmbr0 inet static
address 192.168.0.1/24
gateway 192.168.1.254
bridge-ports enp2s0f0
bridge-stp off
bridge-fd 0

#Additional VM Bridge (vmbr) configurations
auto vmbr1
iface vmbr1 inet static
address 172.16.1.1/24
bridge-ports enp2s0f1
bridge-stp off
bridge-fd 0

auto vmbr2
iface vmbr2 inet static
address 10.0.0.1/16
bridge-ports enp3s0f0
bridge-stp off
bridge-fd 0

Important: After completing modifications to the /etc/networks/interfaces file, you need to restart the Proxmox Virtual Environment.
