Description

This article shows how to define a custom access log format on a per-workload basis, applications running in the mesh may require different information to be shown in the istio-proxy logs.

Environment

1.14.x

Cause

Without Telemetry API and ExtensionProviders, the only way to modify the log format is by changing the value of accessLogFormat in the meshConfig section of our override values file and upgrading our chart.
In the example below, we want to have the default log format with %UPSTREAM_HOST% as the first field in the istio-proxy log:

meshConfig:
        accessLogFormat: "%UPSTREAM_HOST% [%START_TIME%] %REQ(MY_CUSTOM_HEADER)% %REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL% %RESPONSE_CODE% %RESPONSE_FLAGS% %BYTES_RECEIVED% %BYTES_SENT% %DURATION% %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)% %REQ(X-FORWARDED-FOR)% %REQ(USER-AGENT)% %REQ(X-REQUEST-ID)% %REQ(:AUTHORITY)% \n"
helm upgrade istiod manifests/charts/istio-control/istio-discovery \
    --namespace istio-system \
    --values aspen-mesh-override-values.yaml


With the configuration above and after upgrading our chart, all sidecars will show the same format:
Example:
sleep -> httpbin

➜  kubectl logs  sleep-75b7b55866-7jznt -c istio-proxy | tail -1

Recommended Actions

Use ExtensionProviders and Telemetry API to define different log formats per workload.
The first step to achieve this is to define a new ExtensionProvider under the meshconfig section, this should contain our custom desired log format

In the example below, we defied a new extension provider named my-custom-log. For now, the default log format will still show %UPSTREAM_HOST% at the start of the log and our desired log format(my-custom-log) will have the %START_TIME% value.

meshConfig:
    extensionProviders:  
      - name: my-custom-log
        envoyFileAccessLog:
          path: /dev/stdout
          logFormat:           #The desired custom log format
            text: "[%START_TIME%] \"%REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL%\" %RESPONSE_CODE% %RESPONSE_FLAGS% \"%UPSTREAM_TRANSPORT_FAILURE_REASON%\" %BYTES_RECEIVED% %BYTES_SENT% %DURATION% %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)% \"%REQ(X-FORWARDED-FOR)%\" \"%REQ(USER-AGENT)%\" \"%REQ(X-REQUEST-ID)%\" \"%REQ(:AUTHORITY)%\" \"%UPSTREAM_HOST%\" %UPSTREAM_CLUSTER% %UPSTREAM_LOCAL_ADDRESS% %DOWNSTREAM_LOCAL_ADDRESS% %DOWNSTREAM_REMOTE_ADDRESS% %REQUESTED_SERVER_NAME% %ROUTE_NAME%\n"

                               #Default format
    accessLogFormat: "%UPSTREAM_HOST% [%START_TIME%] %REQ(MY_CUSTOM_HEADER)% %REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL% %RESPONSE_CODE% %RESPONSE_FLAGS% %BYTES_RECEIVED% %BYTES_SENT% %DURATION% %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)% %REQ(X-FORWARDED-FOR)% %REQ(USER-AGENT)% %REQ(X-REQUEST-ID)% %REQ(:AUTHORITY)% \n"

After setting the new ExtensionProvider, upgrade the chart and bounce the sidecars so the new changes can be applied.

The second step is to create our Telemetry object, where we will set the scope of the workloads that should use the new format defined in my-custom-log.

apiVersion: telemetry.istio.io/v1alpha1
kind: Telemetry
metadata:
  name: log-test1
  namespace: default
spec:
  accessLogging:
  - providers:
    - name: my-custom-log
  selector:
    matchLabels:
      app: sleep

The telemetry object above shows that the log format defined in my-custom-log ExtensionProvider will only apply to the workloads that have the label app: sleep.
