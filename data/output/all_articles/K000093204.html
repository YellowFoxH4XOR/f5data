K000093204: AFM FQDN Mapping shows "Next Refresh" after the validity period

Type
Support Solution
Published
2022-12-12
Updated
2026-03-16
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.X.X, 21.X.X, 16.X.X, 21.0.X, 21.0.0, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0, 16.1.X, 16.1.6, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.X, 16.0.1, 16.0.0
Source

Description

When examining the output of tmsh show security firewall fqdn-info fqdn command, the Next Refresh shows it will be done after the DNS record's TTL has expired. This occurs when the TTL of the DNS record for the FQDN is lower than the configured refresh interval. Reachability issues may occur when a client resolves the new IP address and the BIG-IP is still using the stale IP address in its firewall rules.

For example:

# dig +noall +answer @10.1.20.44 ns1.f5test.net

ns1.f5test.net.        60    IN    A    10.2.3.44


# tmsh list security firewall global-fqdn-policy

security firewall global-fqdn-policy {
    dns-resolver f5test.net
    refresh-interval 90
}

# tmsh show security firewall fqdn-info fqdn all

---------------------------
Firewall FQDN Mapping Info:
---------------------------
Total records returned: 1

  FQDN                     ns1.f5test.net
  Last Refresh             Feb 26 2026 12:49:29
  Next Refresh             Feb 26 2026 12:50:59  <-- refresh-interval (90s)
  Last Successful Refresh  Feb 26 2026 12:49:29
  DNS Records Valid Until  Feb 26 2026 12:50:29  <-- TTL (60s)
  IP Addresses
                           10.2.3.44
-----------------------------------------------

Environment

  • BIG-IP AFM
  • Global FQDN Policy

Cause

The "Next Refresh" time uses the following formula:

    MAX of (refresh interval, TTL)

This means that if the refresh interval is set to 90 seconds and the validity (TTL) is 60 seconds then BIG-IP AFM will use the larger of the two values. In the given example, the next refresh will be at the 90 second mark.

Recommended Actions

If the refresh needs to be the same as the TTL set by the DNS server, configure the refresh interval to be lower or equal to the TTL. For more stable mappings where IP addresses does not frequently change, you may set the refresh interval to a higher value than the TTL.
