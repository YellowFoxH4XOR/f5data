K000138041: Error regarding 'epsec' files when creating a .scf backup file from tmsh

Applies to

Source

Description

Error regarding 'epsec' files when creating a .scf backup file from tmsh with command:  tmsh save /sys config file <file_name.scf> no-passphrase
For instance, you could see a message like the following: 
# tmsh save /sys config file test2.scf no-passphrase
/bin/tar: files_d/Common_d/epsec_package_d/\:Common\:epsec-1.0.0-1372.0.iso_67155_1: Cannot stat: No such file or directory
/bin/tar: Exiting with failure status due to previous errors
Unexpected Error: Failed to append to temp tar file "/var/system/tmp/tmsh/0VVQiY/data" cache path "/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-1372.0.iso_67155_1"exit code (2).

 

Environment

  • BIGIP 15.x ,16x, 17.x
  • A user with Administrator role & Advanced Shell access
  • Trying to create a SCF file with a passphrase

Cause

Unable to create .scf file due to a missing '.epsec' file, and that could be happening because the '.epsec' file was deleted previously
 

Recommended Actions

As a workaround, you can create a dummy & empty file with the same name as the 'epsec' file that seems to be missing.
For the purpose of this example, the file name is:
':Common:epsec-1.0.0-1372.0.iso_67155_1'

1.- Go to the dir on which the missing '.epsec' file is supposed to be located. That is: /config/filestore/files_d/Common_d/epsec_package_d
2.- Then create an empty file with the same name. (you can do it with vi or touch). For example: 
   epsec_package_d # touch :Common:epsec-1.0.0-1372.0.iso_67155_1

3.- After that, you should be able to save the .scf file without issues:

epsec_package_d # tmsh save /sys config file test2.scf no-passphrase
Saving running configuration...
  /var/local/scf/test2.scf
  /var/local/scf/test2.scf.tar
