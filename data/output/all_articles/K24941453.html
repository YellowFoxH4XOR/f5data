Description

When attempting to use Promote button to initiate manual failover from BIG-IQ Active Configuration Utility, following error is seen from /var/log/ha.log:

PROMOTE] ERROR: ha_corosync_promote.sh -s pause may only be done on the primary device in an HA pair

Environment

  • BIG-IQ HA
  • Manual Failover

Cause

This message comes from /usr/bin/ha_corosync_promote.sh:

if [[ ${ASSIGNED_ROLE} = ${ROLE_NONE} ]]; then
  log_error "This device does not appear to be part of an auto-failover cluster"
  exit 0
fi

The ASSIGNED_ROLE comes from determining which HA IP address in /etc/hosts is on the current system.  The system will create an ha-primary, ha-secondary, and ha-quorum alias when using auto failover.  These aliases do not exist when HA is setup in manual mode. If for some reason these aliases still exist in the /etc/host file of a BIG-IQ system, this can cause promote action to fail if manual failover is used.

Recommended Actions

Clear hostname definitions if confirmed manual failover is used.

You can run from the command line:

# tmsh modify sys global-settings remote-host delete {ha-primary}
# tmsh modify sys global-settings remote-host delete {ha-secondary}
# tmsh modify sys global-settings remote-host delete {ha-quorum}
