Known Issue

This is the result of a known issue. When you use the bigpipe or tmsh utilities to modify an existing NAT with VLANs specified, the modified NAT will not allow traffic to pass.

For example:

  • A NAT already exists on the system with the following configuration:

    nat 172.16.65.170 to 172.18.66.60 {
    vlans {
    external
    internal
    } enable
    }
  • Traffic passes freely through the configured NAT.
  • You modify the NAT by using the tmsh command to change the source address from bigpipe nat 172.16.65.177 to 172.18.66.60 {vlans internal external enable}
  • The modified NAT no longer passes traffic.

Note: This issue only affects NATs for which specific VLANs are allowed or disallowed. This issue only occurs when using the tmsh or bigpipe utilities from the command line, as the Configuration utility does not allow modifications to NATs.

F5 Product Development is tracking this issue as ID 340397.

Workaround

To work around this issue, F5 recommends that you use the BIG-IP Configuration utility or the BIG-IP command line to delete the NAT and then re-create it.

Notes:

  • For information about using the bigpipe or tmsh utilities from the command line, refer to either the Bigpipe Utility Reference Guide or the Traffic Management Shell (tmsh) Reference Guide.
  • For information about using the Configuration utility or NATs, refer to the Configuration Guide for BIG-IP Local Traffic Manager (9.x - 10.x) or BIG-IP Local Traffic Manager: Concepts (11.x).
