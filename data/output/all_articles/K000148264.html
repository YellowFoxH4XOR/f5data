Description

Access policy finishes with 'Logon_Deny' because the OCSP agent fails with error 'Responder Error: malformedrequest (1)'

 

Environment

  • APM is deployed with OCSP Authentication
  • OCSP server on APM configured ignoring AIA extension and adding an URL to access the OCSP responder

apm aaa ocsp {

  ignore-aia true

  url http://server.example.com/ocsp

 

Cause

Error 'Responder Error: malformedrequest (1)' comes from OCSP responder and not APM   

Online Certificate Status Protocol

  responseStatus: malformedRequest (1)

 

From RFC 2560, it is 'an Illegal confirmation request'

 

   OCSPResponseStatus ::= ENUMERATED {
       successful            (0),  --Response has valid confirmations
       malformedRequest      (1),  --Illegal confirmation request
       internalError         (2),  --Internal error in issuer
       tryLater              (3),  --Try again later
                                   --(4) is not used
       sigRequired           (5),  --Must sign the request
       unauthorized          (6)   --Request unauthorized
   }  

 

Root cause can be the OCSP agent sending the POST OCSP request to a wrong virtual directory on the OCSP Responder.

For example sending it to 'http://server.example.com/ocsp' instead of 'http://server.example.com/'

 

Recommended Actions

You can check the url included in the client certificate 

 

X509v3 extensions:
    Authority Information Access:
        OCSP - URI:http://server.example.com

 

Or contacting the Certificate Authority team to confirm which is the URL where OCSP Responder is listening to OCSP requests
