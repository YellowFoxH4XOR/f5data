Description

On BIG-IP versions after 13.1, the linux kernel can report the MemAvailable metric.
This reports on the memory available in 4kB pages that the kernel can use to fulfill a memory allocation request from a process.
This value includes immediately available free memory, as well as any memory that the kernel is using for Buffers and Cache to improve performance.

MemAvailable generally provides the best snapshot of memory available to host processes (not TMM), and decreasing MemAvailable should be a measure of concern.
If MemAvailable is insufficient when a process makes a memory allocation request, then the kernel Out-Of-Memory Killer process is triggered, which may disrupt critical host processes and cause unexpected failover.

MemAvailable is not currently reported via SNMP, and is not currently recorded in performance graphs or snapshots.

Environment

  • BIG-IP
  • SNMP

Cause

None

Recommended Actions

To configure a custom SNMP OID that returns the MemAvailable memory metric, perform the following procedure:

1. Log in with administrative privileges to the command line of the target device.
2. Using a text editor, create or edit the following file:

    /config/snmp/custom_mib.tcl

3. Enter the following command syntax in the /config/snmp/custom_mib.tcl file:

Note: if you have existing custom mibs in the custom_mib.tcl file, you will need to change the OID number to suit

register_mib ".1" mem_available string

proc mem_available {}
{
  set status [catch {exec /bin/cat /proc/meminfo } result]
  set memavail [string trim [lindex [split [lindex [split $result "\n"] 2] ":"] 1]]
  return $memavail
}


4. Save the changes.
5. To restart the SNMP service, type the following command:

    tmsh restart /sys service snmpd

6. To verify that the workaround is functional, type the following command:

    snmpwalk -Os -c public -v 2c localhost .1.3.6.1.4.1.3375.2.100.1
  bigipTrafficMgmt.100.1.0 = STRING: "1177884 kB"
