Description

BIG-IP Virtual Edition (VE) supports trunking in version 13.1.0 and later. When interfaces are added to a trunk, the trunk picks up one of the MAC addresses of member interfaces and apply the MAC address to all of the member interfaces like below.

    net trunk trunk1 {
        interfaces {
            1.1
            1.2
        }
        mac-address fa:16:3e:a6:cb:99
    }
    net interface 1.1 {
        mac-address fa:16:3e:a6:cb:99
    }
    net interface 1.2 {
        mac-address fa:16:3e:a6:cb:99
    }

However, removing the interface from the trunk or deleting the trunk does not reset the MAC addresses of interfaces to the original value. This may lead to a state where more than one trunk share the same MAC address on BIG-IP VE instance when reconfiguring trunk.

Environment

- BIG-IP Virtual Edition v13.1.0 and later that support VE Trunking
- SR-IOV interfaces in use
- Tried to change trunk configuration
- The issue was observed in BIG-IP VE running on OpenStack/KVM

Cause

Due to software limitation of BIG-IP VE, removing the interface from the trunk or deleting the trunk does not reset the MAC addresses of interfaces to the original value.

Recommended Actions

When deleting a trunk or making changes to trunks, delete the trunks from the BIG-IP VE and restart all services or power cycle the BIG-IP VE instance depending on the BIG-IP version.

v13.1.0 and later and prior to v14.1.2.8 or v15.0.1.4 or v15.1.0.5

  1. Delete the trunks.
  2. Restart all services.
[BIG-IP] # bigstart restart
 
v14.1.2.8 or v15.0.1.4 or v15.1.0.5 and later (version with the fix of ID 842865)
  1. Delete the trunks. 
  2. ?Shutdown and power off BIG-IP VE to release MAC addresses of SR-IOV VF.
[BIG-IP] # shutdown -h now
  1. Power on BIG-IP VE from hypervisor.

Additional Information

If BIG-IP VE has two or more different trunks with the same MAC address and deletion of trunks is difficult, please follow procedures below to reset MAC addresses for interfaces and trunks.

v13.1.0 and later and prior to v14.1.2.8 or v15.0.1.4 or v15.1.0.5

  1. Force mcpd process to reload configuration as per K13030.
[BIG-IP] # touch /service/mcpd/forceload
  1. Reboot BIG-IP VE.
[BIG-IP] # shutdown -r now
 
v14.1.2.8 or v15.0.1.4 or v15.1.0.5 and later (version with the fix of ID 842865)
  1. Force mcpd process to reload configuration as per K13030.
[BIG-IP] # touch /service/mcpd/forceload
  1. ?Shutdown and power off BIG-IP VE to release MAC addresses of SR-IOV VF.
[BIG-IP] # shutdown -h now
  1. Power on BIG-IP VE from hypervisor.
