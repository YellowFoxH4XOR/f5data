K000151845: APM policy expressions may fail if the string being evaluated, contains a #

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000151845

Description

APM policy expressions may fail to return expected results, when evaluating strings or values that contain a #.

Environment

Big-IP APM

Cause

APM expressions cannot not properly interpret strings containing #, because TCL expresssion parsers interpret # as a comment indicator

Recommended Actions

The workaround is to use "matches_regex" and adding a .* at the beginning and end of the expression.

 

For example:

 

If this is expression you are attempting to implement that is failing:

 

expr {[mcget {session.custom.memberOf}] contains "CN=\#Admin,OU=Security Groups,DC=Corp,DC=info"}

 

You would need to instead use this expression:

 

expr {[mcget {session.custom.memberOf}] matches_regex ".*#Admin,OU=Security Groups,DC=Corp,DC=info.*"
