K03453341: HTTP 204 No Content responses contain chunked body with rewrite profile

Description

You observe that HTTP responses have a Transfer-Encoding: Chunked header added by the BIG-IP, even if there is no body in the response.

Like the following example:

1. Response direct from server

< HTTP/1.1 204 No Content
< Server: nginx/1.19.6
< Date: Mon, 21 Dec 2020 14:59:25 GMT
< Connection: keep-alive

2. Response after passing through BIG-IP

< HTTP/1.1 204 No Content
< Server: nginx/1.19.6
< Date: Mon, 21 Dec 2020 14:59:25 GMT
< Connection: keep-alive
< Transfer-Encoding: chunked

Note: This issue is not exclusive to 204 No Content responses.

Environment

  • 15.0 or later
  • Rewrite profile in use

Cause

Bug ID 899097: Existence of rewrite profile with HTTP profile response chunking mode 'sustain' always triggers client-side chunking

Recommended Actions

As a workaround, you can set response-chunking to unchunk instead of sustain in the HTTP profile.

Additional Information

The HTTP profile now uses response-chunking: sustain by default, instead of the previous response-chunking: selective.
