K000164107: AS3: HTTP monitor may remain deleted after a virtual server conflict

Type
Support Solution
Published
2026-11-04
Updated
2026-11-04
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000164107

Description

When an AS3 declaration fails with a VIP conflict, the HTTP monitor assigned to the pool can be deleted from the BIG-IP configuration, even though the declaration was rejected.


The conflict occurs when a declaration defines two port 80 virtual servers with the same destination address, source address, protocol, and VLAN. This happens when redirect80: true is set and the declaration also defines a separate port 80 virtual server for the same destination. AS3 rejects the transaction with:


01070333:3: Virtual Server /<partition>/<folder>/<vs-name> illegally shares destination address,

source address, service port, ip-protocol, and vlan with Virtual Server /<partition>/<folder>/<redirect-vs-name>.


After this failure, the pool's HTTP monitor is no longer present in the configuration.


Environment

  • AS3 declarations configuring pools, HTTP monitors, and virtual servers.
  • A separately defined port-80 virtual server alongside an HTTP redirect virtual server generated by redirect80: true.


Cause

Virtual server configuration conflict

The separately defined HTTP virtual server conflicts with the AS3-generated redirect virtual server because both use port 80 with matching destination, source, protocol, and VLAN. This collision triggers the declaration failure.


Monitor recovery-path defect

The analyzed AS3 recovery command omitted the http monitor type when attempting to recreate the monitor after transaction cancellation.


Note: Recovery command compared with the correct command

The catch branch of the AS3 recovery script runs tmsh::cancel_transaction, then re-creates the monitor. The command used is missing http flag:


tmsh::create ltm monitor /<partition>/<folder>/<monitor-name> adaptive disabled ...


The command that should have been used:

tmsh::create ltm monitor http /<partition>/<folder>/<monitor-name> adaptive disabled ...



Answer/Recommended Actions

  •  Remove the virtual server conflict in the declaration. Use one of the following options, then redeploy:
    • Remove redirect80: true, or
    • Do not define a separate port 80 virtual server for the same destination, source, protocol, and VLAN.

  • Verify the monitor after any failed AS3 declaration. Run these commands on the BIG-IP:
    • tmsh list ltm pool /<partition>/<folder>/<pool-name> monitor to confirm the pool still references the monitor.
    • tmsh list ltm monitor http /<partition>/<folder>/<monitor-name> to confirm the monitor exists.


  • Enable AS3 diagnostics for future occurrences. Add the following to the declaration's Controls class:

"controls": {

"class": "Controls",

"dryRun": false,

"trace": true,

"traceResponse": true,

"logLevel": "debug"

}

  • Capture the AS3 trace output together with the mcpd audit log entries. Audit entries for obj_delete of a monitor identify when the monitor was removed.


Note: When "trace": true is enabled, AS3 creates tenant-specific trace files in /tmp/ on the BIG-IP, including desired, current, and diff JSON files and the generated CLI script. With "traceResponse": true, trace output is also included in the API response. For details about these files and the logging options, refer to K000160784: AS3: How to Enable Debug and Trace Logging.


Fix availability: This issue fixed in the AS3 3.59.0 build. If you require the correction before the generally available release containing the fix is available, contact F5 Support, reference bug 2547581, and request a pre-release build. Confirm build availability and suitability with Support, and test it on a non-production device before production deployment.


Additional Information

  • Expected behavior: When AS3 rejects a declaration with a validation error such as 01070333:3, the configuration should remain as it was before the failed declaration, including the pool monitor.
  • Unexpected behavior: Deletion of the pool's HTTP monitor after a rejected declaration.
