K90352042: High CPU usage by bigd process

Type
Support Solution
Published
2023-04-19
Updated
2025-04-01
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K90352042

Description

High CPU utilization observed for bigd process.
Error messages similar to the following may be observed in /var/log/ltm:

warning bigd.0[<pid>]: 01060148:4: Bigd PID 8181, instance 0, over 95% load

Many HTTPS monitors are configured, and ECDHE and DHE ciphers are already disabled for use in HTTPS health monitors
 

Environment

  • BIG-IP
  • any version
  • high CPU usage
  • bigd

Cause

  • Bug ID 1060541

Recommended Actions

It is possible that even with ECDHE and DHE ciphers are disabled, frequent key exchanges during TLS handshakes still utilise a lot of CPU overhead. Make sure that session resumption is supported and enabled on the back-end application servers to limit these key exchanges by utilising the cached session ID that the BIG-IP sends with it's ClientHello to the servers.

You can also consider to use in-TMM monitor: K11323537: Configuring In-TMM monitoring

Additional Information

To check if the session resumption is the cause of the high CPU:

  1. Take a packet capture between the BIG-IP and the backend server being monitored using HTTPS health monitor.
  2. Observe the TLS Handshake and see if the ClientHello contains a SessionID and if the corresponding ServerHello sends back the same SessionID, meaning to say it is resuming sessions.
