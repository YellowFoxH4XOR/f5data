Topic

This article applies to BIG-IP version 9.x through 10.x. For information about other versions, refer to the following articles:

  • K13302: Configuring the BIG-IP to use an SSL chain certificate (11.x - 12.x)

Chain certificates are used to help systems which depend on Secure Sockets Layer (SSL) certificates for peer identification. The chain certificate is intended to create a chain of trust between the Certificate Authority (CA) that signed the certificate and the CA that is already trusted by the recipient of the certificate, allowing the recipient to verify the validity of the certificates presented, even when the signing CA is unknown.

Procedures

  • Using a custom chain certificate
  • Using a CA-provided chain certificate

Using a custom chain certificate

To create and use a custom chain certificate (also known as an intermediate certificate chain), you must perform the following three procedures:

  • Import the intermediate certificates to the BIG-IP system
  • Create the custom certificate bundle or chain
  • Configure an SSL profile to use the certificate chain

Import the intermediate certificate(s) to the BIG-IP system

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click SSL Certificates.
  4. Click Import.
  5. Select Certificate from the Import Type menu.
  6. Click the Create New option.
  7. Type a unique name for the Certificate Name.
  8. Click Browse and navigate to select the certificate or certificate bundle to import.
  9. Click Open.
  10. Click Import.

Create the custom certificate bundle or chain

If you are using certificates signed by an Intermediate CA or a private CA, you may need to build your own certificate bundle or chain. To do so, perform the following procedure:

  1. Import all of the CA certificates to the BIG-IP system.
  2. Log in to the BIG-IP command line.
  3. Change directories to the SSL certificate directory by typing the following command:

    cd /config/ssl/ssl.crt/

  4. Create a chain certificate file named chain.crt by typing the following command:

    cat intermediateCA_1.crt intermediateCA_2.crt rootCA.crt > chain.crt

    Note: Including the root CA certificate in the bundle is optional and does not affect its functionality.

  5. Verify whether the chain certificate creates a chain of trust to the SSL certificate by typing the following command:

    openssl verify -CAfile /config/ssl/ssl.crt/chain.crt /config/ssl/ssl.crt/<ssl-cert>

    where <ssl-cert> is the name of the corresponding SSL certificate file, for example, YourCert.crt.

    If the chain of trust can be established for the certificate using the specified chain, the command returns output that appears similar to the following example:

    site.crt: OK

    For example:

    [root@3400a:Active] tmp # openssl verify -CAfile /config/ssl/ssl.crt/chain.crt /config/ssl/ssl.crt/site.crt
    site.crt: OK
    [root@3400a:Active] tmp #

Configure an SSL profile to use the certificate chain

Note: As with all profile customizations, F5 recommends against editing the supplied default profiles on the BIG-IP system. Instead, you should create new custom profiles based on the default profile of the desired type. If some non-default profile settings (such as ciphers and certificate chains) will be used for all custom child profiles, you should consider first creating a new custom profile with these non-default base settings, then use the new custom profile as the parent for a second generation of custom child profiles.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select Server from the SSL menu.
  5. Select the Server SSL profile to configure.
  6. Select Advanced from the Configuration menu.
  7. Select the appropriate chain certificate from the Chain drop-down menu.
  8. Click Update.

Virtual servers that use this server SSL profile will now present the chain certificate along with the configured client certificate.

Using a CA-provided chain certificate

To use a CA-provided chain certificate, perform the following two procedures:

  • Import the chain certificate to the BIG-IP system
  • Configure an SSL profile to use the chain certificate

Note: You may obtain intermediate certificates or chain certificates for a Public Key Infrastructure (PKI) from the vendor of the certificate. The intermediate certificate or chain certificate must be in PEM format. Import the chain certificate to the BIG-IP system

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click SSL Certificates.
  4. Click Import.
  5. Select Certificate from the Import Type menu.
  6. Click the Create New option.
  7. Type a unique name for the Certificate Name.
  8. Click Browse and navigate to select the certificate or certificate bundle to import.
  9. Click Open.
  10. Click Import.

Configure an SSL client profile to use the chain certificate

Note: As with all profile customizations, F5 recommends that you do not edit the supplied default profiles on the BIG-IP system. Instead, you should create new custom profiles based on the default profile of the desired type. If some non-default profile settings (such as ciphers and certificate chains) will be used for all custom child profiles, you should consider first creating a new custom profile with these non-default base settings, then use the new custom profile as the parent for a second generation of custom child profiles.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select Client from the SSL menu.
  5. Select the Client SSL profile you wish to configure.
  6. Select Advanced from the Configuration menu.
  7. Select the appropriate chain certificate from the Chain drop-down menu.
  8. Click Update.

Virtual servers that use this client SSL profile will now present the chain certificate along with the configured server certificate.
