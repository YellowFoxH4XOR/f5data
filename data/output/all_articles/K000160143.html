K000160143: VELOS Partition Blades Show Amber LEDs and "Blade Powering On" Status After RMA or OpenShift Cluster Reinstall

Type
Support Solution
Published
2026-02-25
Updated
2026-02-25
Applies to
  • F5OS
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000160143

Description

  • After replacing blades via RMA or performing an OpenShift cluster uninstall/reinstall on a VELOS chassis, newly installed or replacement blades may display persistent amber LEDs.
  • The partition reports a platform node-status of "blade powering on" for the affected blades.
  • The controller qkview shows all blades with "OK" status and "In Cluster" state.
  • The partition qkview shows no health status for the replacement blades.
  • The partition cannot deploy tenant workloads to the affected blades.
  • Partition infrastructure pods (virt-handler, sync, ovs, sdn) may be running on all blades, but the f5-resources-manager pod is missing from the partition.

Environment

  • F5 VELOS chassis (CX1610 + SX1610, CX410, or similar platforms)
  • F5OS-C version 1.8.2 (and potentially other versions)
  • OpenShift cluster deployed within a partition
  • Recent blade RMA (Return Merchandise Authorization) replacement
  • Recent OpenShift cluster uninstall/reinstall operation
  • Partition not disabled and re-enabled after hardware changes or cluster reinstall

Cause

Bug ID 1138085

Answer/Recommended Actions

  1. After OpenShift cluster reinstall or blade RMA, disable and re-enable the partition from the system controller to ensure all partition management pods are restarted and blades are fully initialized:
    • Log in to the system controller CLI as admin
    • Enter configuration mode: config
    • Disable the partition: partitions partition <partition_name> config disabled
    • Commit the change: commit
    • Re-enable the partition: partitions partition <partition_name> config enabled
    • Commit and exit: commit and-quit

  2. Verify partition pod status and blade health after re-enabling:

    • Check for presence of f5-resources-manager pod: kubectl get pods --all-namespaces or oc get pods --all-namespaces
    • Confirm blade health status from partition CLI: show system health
    • Verify platform node-status: show cluster nodes
    • Monitor blade LED status to confirm they change from amber to green
    • Verify tenant workload deployment capability
