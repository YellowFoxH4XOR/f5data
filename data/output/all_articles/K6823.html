Topic

There are three supported methods for using a single virtual server to handle multiple host names:

  • A Secure Socket Layer (SSL) wildcard certificate
  • A SAN/UCC certificate (K11438: Creating a SAN/UCC certificate request)
  • The Transport Layer Security (TLS) Server Name Indication (SNI) extension (K13452: Configuring a virtual server to serve multiple HTTPS sites using TLS Server Name Indication feature)

Before the introduction of TLS SNI, you could not assign multiple certificates to a server because of how SSL decrypts the client's request to extract the host name. The extraction of the host name does not occur until after the SSL certificate is presented and the final key exchange occurs, after which time a secure connection is established. Therefore, the server is unable to determine which certificate it should present, as it does not know what host name has been set in the client's HTTPS request.

A wildcard certificate contains a wildcard in place of the host name. In order for multiple sites to use a single wildcard certificate, the sites must all contain the same domain name—only the host name can be different. The wildcard matches the domain name to the domain name that the client requested.

The browser performs the verification that occurs on the client side when accessing an SSL encrypted site. In addition, the browser determines whether the certificate presented is valid or invalid. The browser also contains a list of known Certificate Authorities, while the server side does not.

Creating a wildcard certificate request

To create a wildcard certificate request, perform the following procedure:

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Navigate to the following location for your version:
    • 11.x

      Navigate to System > File Management, and click SSL Certificate List.
    • 9.x to 10.x

      Navigate to Local Traffic > SSL Certificates.
  3. Select Create.
  4. Specify a name for the key and certificate.
  5. For Issuer, select Certificate Authority.

    Note: Select Self if you want to create a self-signed certificate for testing purposes.

  6. Specify the Common Name, using the following syntax:

    *.<domain>.<1st level domain identifier>

    For example:

    *.mydomain.net

    Note: You cannot specify the second-level domain as a wildcard. Doing so creates a security risk, and any certificate requested is not be honored by a Certificate Authority (CA). Only the host name portion of the domain can be a wildcard.

    For example, the following domain name is not valid:

    *.*.net

  7. Specify the Division, Organization, Locality, State or Province, Country, Challenge Password, and Confirm Password, as you would any other certificate.
  8. Select Finished.
  9. Copy the Certificate Request and send it to the CA of your choice.
  10. Import the certificate received from the CA and test the configuration as needed.
