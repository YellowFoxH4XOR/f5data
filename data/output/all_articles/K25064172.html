Description
 

You may see error messages similar to the following in /var/log/ltm on BIG-IP(s) when trying to synchronize configuration from one BIG-IP in HA cluster to another:

May 12 21:01:26 bigip1.local notice mcpd[5915]: 01070430:5: end_transaction message timeout on connection 0x637de008 (user %cmi-mcpd-peer-10.1.7.78)
May 12 21:01:26 bigip1.local notice mcpd[5915]: 01070418:5: connection 0x637de008 (user %cmi-mcpd-peer-10.1.7.78) was closed with active requests
May 12 21:01:26 bigip1.local notice mcpd[5915]: 0107143c:5: Connection to CMI peer 10.1.7.78 has been removed
May 12 21:01:26 bigip1.local notice mcpd[5915]: 01071432:5: CMI peer connection established to 10.1.7.78 port 6699 after 0 retries
 
May 12 21:06:29 bigip1.local notice mcpd[5915]: 01070430:5: end_transaction message timeout on connection 0x637de008 (user %cmi-mcpd-peer-10.1.7.78)
May 12 21:06:29 bigip1.local notice mcpd[5915]: 01070418:5: connection 0x637de008 (user %cmi-mcpd-peer-10.1.7.78) was closed with active requests
May 12 21:06:29 bigip1.local notice mcpd[5915]: 0107143c:5: Connection to CMI peer 10.1.7.78 has been removed
May 12 21:06:29 bigip1.local notice mcpd[5915]: 01071432:5: CMI peer connection established to 10.1.7.78 port 6699 after 0 retries

The above log messages indicate that config-sync is taking too long and then timing out after five minutes.
 

Environment

  • Two BIG-IP VMs in an Active/Standby or Active/Standby configuration running in AWS
  • BIG-IP systems are members of a sync-failover device group
  • BIG-IP(s) HA peers are running one of the following software versions: 14.1.3.1 or above, 15.1.2 or above, 16.0.1.1 or above.

Cause

ID1022997 - TCP segments with an incorrect checksum are transmitted when the sock driver is used in AWS deployments (e.g., 1NIC).


Recommended Actions

Note:  Before implementing this workaround, please read the following article:  K10142141 - Configuring the BIG-IP VE system to use the SOCK network driver

Use one of the following workarounds:

AWS BIG-IP deployments with multiple available drivers

Verify available drivers:

1. Log into the BIG-IP as the root user
2. To display the current configuration (available_drivers and driver_in_use), enter the following command:

    tmctl -d blade tmm/device_probed

    The output appears similar to the following example:

    pci_bdf pseudo_name type available_drivers driver_in_use
    --------------- --------------- --------- ------------------ ---------------
    0000:01:00.0       F5DEV_PCI    xnet, sock,
    0000:05:00.0 1.3 F5DEV_PCI mlxvf5, xnet, xnet
    0000:08:00.0 1.4 F5DEV_PCI mlxvf5, xnet, xnet
    0000:09:00.0 1.1 F5DEV_PCI mlxvf5, xnet, sock, xnet
    0000:0a:00.0 1.2 F5DEV_PCI mlxvf5, xnet, sock, xnet

Use the following procedure to switch from sock to xnet driver on BIG-IP(s):

1. Check the contents of /config/tmm_init.tcl file on BIG-IP with the following command:
    grep sock /config/tmm_init.tcl

    If the sock driver is in use, you'll see the following:
    device driver vendor_dev 1d0f:ec20 sock

2. Take a backup of /config/tmm_init.tcl file:

    cp /config/tmm_init.tcl /var/tmp/

3. Remove /config/tmm_init.tcl file by entering following command:

    rm /config/tmm_init.tcl

4. Restart TMM to reload the driver by entering the following command:

    bigstart restart tmm

Note: Restarting TMM will cause a failover (or an outage if there is no high availability (HA) peer available).
 

AWS BIG-IP deployments which only have 'sock' as the available driver
 

Verify available drivers:

1. Log into the BIG-IP as the root user
2. To display the current configuration (available_drivers and driver_in_use), enter the following command:

    tmctl -d blade tmm/device_probed

    The output appears similar to the following example:

    pci_bdf      pseudo_name type      available_drivers driver_in_use
    ------------ ----------- --------- ----------------- -------------
    0000:00:05.0               F5DEV_PCI sock,
    0000:00:06.0 1.1         F5DEV_PCI sock,             sock

3. Modify (or create, if not present) the file /config/tmm_init.tcl on the affected BIG-IP systems, and add the following line to it:

    ndal force_sw_tcs off 1d0f:ec20
 
4. Restart TMM:

    bigstart restart tmm
 
Note: Restarting TMM will cause a failover (or an outage if there is no high availability (HA) peer available).
