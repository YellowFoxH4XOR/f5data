Topic

On occasion, it may be necessary to allow requests from certain IP addresses to bypass the BIG-IP ASM security policy, while directing requests from other IP addresses through the BIG-IP ASM security policy. However, the BIG-IP ASM system does not offer an option in the httpclass object to manage requests based on source IP address. In order to allow requests from certain IP addresses to bypass the BIG-IP ASM security policy while directing requests from other IP addresses through the BIG-IP ASM security policy, you must associate an iRule to the virtual server in addition to the httpclass that is already applied.

Allowing requests from a specific host IP address to bypass the BIG-IP ASM security policy

To create an iRule that allows requests from a specific host IP address to bypass the BIG-IP ASM security policy, perform the following procedure:

Note: The example iRules in the following procedure allow requests originating from 192.168.1.1 to bypass the BIG-IP ASM security policy. Adjust the logic as necessary to match your requirements. For example, to match the entire 192.168.1.0/24 subnetwork instead of a single host, use standard CIDR notation to specify a subnet instead of a host address: 192.168.1.0/24. To match multiple hosts or subnets, create a data group list that specifies the list of addresses and/or subnets to match, then use the matchclass command to compare them: if {[matchclass [IP::remote_addr] equals $::data_group_list]}.

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click iRules.

    The iRules screen is displayed.
  3. Click Create.
  4. Type a name for the iRule.
  5. In the Definition field, enter an iRule similar to the example below that is appropriate for the BIG-IP version you are running:
    • BIG-IP 10.0.1 and later

      when HTTP_CLASS_SELECTED {
      if { [IP::addr [IP::remote_addr] equals 192.168.1.1 ] } {
      pool test
      ASM::disable
      }
      }

    • BIG-IP 10.0.0
      The PLUGIN::disable iRule command used to disable the BIG-IP ASM does not function as expected in version 10.0.0.

      Note: For more information and a workaround, refer to K10128: The PLUGIN iRule commands do not function in BIG-IP version 10.0.0.

    • BIG-IP 9.4.2 through 9.4.8

      when HTTP_CLASS_SELECTED {
      if { [IP::addr [IP::remote_addr] equals 192.168.1.1 ] } {
      pool test
      PLUGIN::disable ASM
      }
      }

    • BIG-IP 9.4 and 9.4.1

      when CLIENT_ACCEPTED {
      if { [IP::addr [IP::remote_addr] equals 192.168.1.1 ] } {
      pool test
      set asm_bypass 1
      }
      }

    • BIG-IP 9.2.x and 9.3.x

      Important: This iRule will disable all events in all iRules applied to the virtual server. If iRule processing is required on the virtual server when BIG-IP ASM is disabled, you must upgrade to version 9.4 or later.

      when CLIENT_ACCEPTED {
      if { [IP::addr [IP::remote_addr] equals 192.168.1.1 ] } {
      pool test
      event disable all
      }
      }
