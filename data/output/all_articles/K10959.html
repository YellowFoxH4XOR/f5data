Known Issue

This is the result of a known issue. The BIG-IP system sends an emergency-level SNMP trap when a user logs in to or out of a BIG-IP system. Receiving such an SNMP trap may lead a BIG-IP administrator to believe that the system is in an unusable condition, since the emergency log level is for system panic messages only.

When a user logs in or out of a BIG-IP system, a log entry is created in the /var/log/audit and /var/log/secure files, noting the login or logout. While the syslog-ng daemon logs these messages as informational, they are written with an incorrect message ID indicating an emergency-level message. If the BIG-IP system is also configured to send SNMP traps to a network management station, the BIG-IP system will send an SNMP trap for each login and logout with an SNMP OID signaling an emergency-level event. Both configuration utility logins and command line interface logins are affected.

F5 Product Development tracked this issue as CR128089 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Workaround

You can work around this issue by adding the following line to the /config/user_alert.conf file:

alert WORKAROUND_SOL10959 "01070417:0" {}

This line identifies the erroneous message ID that would otherwise cause an SNMP trap to be sent. Instead, since there is nothing inside the brace characters ( { } ), the alertd daemon does nothing when it sees a message with the above message ID.
