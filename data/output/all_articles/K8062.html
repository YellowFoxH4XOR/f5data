K8062: Virtual servers require a default pool if the WebAccelerator module is configured to use a Destination Host

Topic

For feature equivalence with the standalone WebAccelerator product, it is possible to configure the BIG-IP WebAccelerator module application to use a Destination Host that has been configured to use a specific origin server and not use the BIG-IP Internal Pool. However, F5 Networks does not recommend this configuration because the pvac daemon will process the connection to the origin server, and you will lose the benefits of allowing the TMM daemon to process the connection to the origin server. Benefits, such as load balancing or persistence, will be lost.

Important: If the BIG-IP WebAccelerator module application is configured to use a Destination Host that has been configured to use a specific origin server rather than the BIG-IP Internal Pool, the virtual server is still required to have a default pool configured.

When the BIG-IP WebAccelerator module application is configured to use a Destination Host, and the virtual server does not have a default pool configured, the request is never passed from the TMM daemon to the pvac daemon. The pvac daemon manages HTTP and HTTPS traffic for the BIG-IP WebAccelerator module.

Note: The recommended and default setting when creating a BIG-IP WebAccelerator module application is to select the BIG-IP Internal Pool as the Destination Host. Connections to the virtual server are processed by the TMM daemon. The requests that match the HTTP class are passed from TMM to the pvac daemon for processing. The pvac daemon manages HTTP and HTTPS traffic for the BIG-IP WebAccelerator module and sends it back to the TMM daemon to be load balanced to a member of the virtual servers default pool. The requests to the virtual server that do not match the HTTP class are processed by the TMM daemon and load balanced to the default pool without being passed to the pvac daemon.
