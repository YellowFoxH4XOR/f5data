Known Issue

Network access session DNS queries may not attempt to query a secondary name server.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured with a network access profile.
  • The network access profile is configured with primary and secondary name servers.
  • A user has an established network access session.
  • The user initiates a DNS domain query handled within the scope of the network access tunnel.
  • The first name server queried responds with "No such name."

Impact

The secondary name server is not queried.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to resolve a domain query for a network access session that is configured with primary and secondary name servers, and the first name server query results in "No such name" the secondary name server is not queried.
  • When reviewing the DNS configuration settings of the defined DNS name servers, the name servers do not share the same DNS configuration.

Workaround

To work around this issue, you can minimize the network access profile-configured name servers to a single primary name server. To do so, perform the following procedure:

Impact of workaround: The Network access session will not have DNS redundancy.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Network Access.
  3. In the Name box, click the name of the affected network access profile.
  4. Click the DNS/Host tab.
  5. Remove the configuration information for the IPV4 Secondary Name Server.
  6. Click Update.
  7. In the upper-left corner, click Apply Access Policy.
  8. Click the Apply Access Policy button.
