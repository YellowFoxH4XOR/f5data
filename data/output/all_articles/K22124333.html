K22124333: Failed to import BIG-IP APM services - BIG-IQ

Type
Support Solution
Published
2022-03-26
Updated
2025-02-06
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 7.X.X
Source
https://my.f5.com/manage/s/article/K22124333

Description

When trying to import BIG-IP APM policy configuration to the BIG-IQ an error message similar to the following is displayed:

Error messages: Coordinator failed during working-config update, roll-back working-config started; reason: Worker http://localhost:8100/cm/access/working-config/apm/policy/customization-group failed validation with status 500: java.lang.IllegalStateException: /Common/mysession-tst-lc_tst.app/mysession-tst-lc_tst_eps_1 refers to nonexistent object (https://localhost/mgmt/cm/access/working-config/apm/policy/customization-source/21005c43-25f8-3f85-8d62-2d51d7041c2d)

Environment

  • BIG-IQ
  • BIG-IP APM
  • Import of a BIG-IP APM policy

Cause
The import fails if the Access Group config version and the device versions do not match.

Recommended Actions 

  1. Log on to the BIG-IQ Configuration utility.
  2. Go to Devices > BIG-IP Devices > select the BIG-IP APM.
    Note:     The services displays the following import error for Access (APM) - "Device version 'X.Y' must be same as Access Group version <x.x.x.x>". 
    Note: The value of <x.x.x.x> is the version number 
  3. Ensure that the devices are part of an access group listed as version 'X.Y' by navigating to  the Devices > BIG-IP Clusters > Access Groups section
  4. Execute a rediscovery / re-import
