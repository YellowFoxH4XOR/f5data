K58438736: icmp is not processed when wild card Virtual Server is configured with Traffic Matching Criteria net port list

Applies to

Source

Description

An ip forward or fastl4 virtual server is not processing icmp traffic when net port-list is used as part of traffic-matching-criteria.

Example Config:

ltm traffic-matching-criteria /Common/Test-TMC {
    destination-address-inline 0.0.0.0
    destination-port-list /Common/allowed_ports     
    source-address-inline 0.0.0.0
    source-address-list /Common/TEST-SERVERS
}

net port-list /Common/allowed_ports {
    ports {
        25 { }
        53 { }
        80 { }
        123 { }
        443 { }
    }
}

Environment

  • Wild card virtual server with traffic-matching-criteria
  • Traffic-matching-criteria is configured with source port list
  • No Existing connection flow

Cause

BIG-IP keeps track of all unique flows through the device. For TCP and UDP the source and destination ports are used to identify subsequent packets on the same flow.  For ICMP, the icmp code (echo_request = 8) is used, which is stored in the connection table's "port" field since ICMP does not have a port.  This means that if a port list or firewall rule does not allow "port 8" through the virtual, the ICMP traffic will be dropped.

Recommended Actions

When applying port restrictions to a virtual server, ensure port 8 is included if ICMP echo requests (and their related reply traffic) should be processed by the virtual server.

Example Config:

net port-list /Common/allowed_ports {
    ports {
        8 { }
        25 { }
        53 { }
        80 { }
        123 { }
        443 { }
    }
}

Additional Information

Note: If the ICMP message is different from an "Echo Request", port number tracked might differ. See: Internet Control Message Protocol (ICMP) Parameters
