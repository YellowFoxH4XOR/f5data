Known Issue

This is the result of a known issue. Connection mirroring is used on the BIG-IP system to duplicate a unit's state information to the peer unit. When a client requests an HTTP Keep-Alive session, and the server does not support HTTP Keep-Alive connections, mirrored connections may be aborted on the standby system. This issue occurs when the virtual server properties are configured as follows:

  • Connection mirroring is configured for the virtual server
  • HTTP and OneConnect profiles are defined for the virtual server

If this issue occurs prior to a failover, or during a failover, the connection hangs as the peer system becomes active.

F5 Product Development tracked this issue as CR110277 and it was fixed in BIG-IP LTM versions 9.4.7 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP version 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue, disable the Time Wait Recycle TCP profile setting by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select TCP from the Profiles drop-down menu.
  5. Click the TCP profile that is associated with the virtual server.
  6. Clear the Time Wait Recycle check box.
  7. Click Update.
