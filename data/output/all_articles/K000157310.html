K000157310: Web application requests may experience delays when DNS resolution fails and an ASM policy is attached

Description

When a web application is protected by a ASM policy, you may observe delays in request processing.

This behavior can occur when the request contains parameters with values resembling URLs, and DNS resolution of those URLs fails or times out.

 

Environment

  • BIG-IP ASM or Advanced WAF
  • security policies containing wildcard parameter with parameter value type set to 'Auto-Detect'

 

Cause

When the ASM policy inspects an HTTP request, it classifies parameter values based on their content.

If a parameter value appears to be a URL (for example, https://example.com/path), ASM performs a redirection safety check, which includes a DNS lookup of the referenced domain.

If the DNS lookup fails or takes too long (for example, due to unreachable DNS servers or temporary resolution failures), the bd process delays forwarding the request until the lookup completes or times out.

As a result, the client experiences a noticeable delay before receiving the server response.

 

Recommended Actions

You can mitigate this behavior using one of the following options:

 

1. Disable automatic URL detection on parameter level

  • Change the Parameter Value Type from Auto-Detect to User Input.

2. Ensure successful DNS resolution

  • Verify that the BIG-IP system can resolve external domains used in the application.
  • Check system and ASM DNS settings and correct any connectivity or resolver issues.
  • For more details on configuring DNS resolution for ASM, refer to K000148675

Additional Information

When ASM performs URL safety checks, each unique URL-like parameter value may trigger a separate DNS lookup.
