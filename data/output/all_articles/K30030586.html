Topic

You should consider using this procedure under the following condition:

  • You want to access the Configuration utility using passwordless SSL client certificate authentication.

Description

You can configure the BIG-IP system to authenticate users who provide a signed SSL client certificate rather than a traditional password. When you enable this authentication method, also referred to as Remote ClientCert LDAP, the BIG-IP system performs the following steps to authenticate users:

  1. Requests the Certificate Authority (CA)-signed SSL client certificate
  2. Verifies the revocation status of the SSL client certificate using Online Certificate Status Protocol (OCSP)
  3. Verifies that the SSL client certificate has been signed by the imported CA
  4. Extracts the username from one of the SSL client certificate x.509 or x.509v3 attributes
  5. Verifies that the user account exists on a remote Lightweight Directory Access Protocol (LDAP) server

For more information about the Remote ClientCert LDAP feature, review the following sections:

SSL client certificate attributes

The BIG-IP system extracts usernames from a chosen attribute in the SSL client certificate. Usernames must appear in either the X.509 common name (CN) attribute or one of the X.509v3 attributes, such as Directory Name, DNS Name, EDI Party, Email, and IP Address. In the following SSL client certificate example, you can extract the user jsmith using the X.509 CN attribute:

Subject: C=US, ST=WA, O=F5 Networks, Inc., OU=AskF5 Team, CN=jsmith

LDAP directory attributes

After the BIG-IP system extracts the username, the system verifies that the account exists by searching the remote LDAP server using a specified LDAP attribute. In the following example, you can locate the LDAP account for jsmith using the LDAP uid attribute:

dn: ou=Users,dc=ldap,dc=example,dc=com
uid: jsmith

User role, shell, and partition access

When the Remote ClientCert LDAP feature is enabled, the system applies user roles, shell, and partition access as follows:

Note: The Remote Role Groups feature is not available when Remote ClientCert LDAP is enabled. This issue applies only to BIG-IP 12.0.x. For more information, refer to K40128010: BIG-IP does not retrieve LDAP attributes during remote role group matching.

  • If the user has a local BIG-IP system account, the system applies the locally configured user role, shell, and partition access.
  • If the user does not have a local BIG-IP system account, the system applies the configured Remote ClientCert LDAP External Users role, shell, and partition access.

Default admin account

Because the username and password prompt is not presented, you must also authenticate the default admin account using an SSL client certificate. You may want to ensure you have command line access allowed for the admin or root user as a fallback method of accessing the BIG-IP system.

To authenticate users employing a CA-signed SSL client certificate, perform the following procedures.

Note: If you already have a CA-configured and intend to validate client certificates using OCSP, review step 6 of the first procedure to ensure your CA extensions are configured correctly.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to a workstation with the OpenSSL package installed or access to the BIG-IP system Advanced Shell (bash).
  • You have created BIG-IP system accounts on a remote LDAP authentication server.

Procedures

  • Create a new root CA and sign a new SSL client certificate
  • Configure the BIG-IP system to use Remote ClientCert LDAP
  • Import the SSL client certificate into the web browser

Create a new root CA and sign a new SSL client certificate

This procedure uses OpenSSL to create a new root CA and sign SSL client certificates. You can import the client certificates into a web browser and present them when accessing the Configuration utility. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation command line or bash.
  2. To create a working directory to store the CA root certificate and key, use the following command syntax:

    mkdir <directory_name>

    For example, to create a directory named bigip_ca, enter the following command:

    mkdir bigip_ca

  3. To change to the directory, use the following command syntax:

    cd <directory_name>

    For example, to change to the bigip_ca directory, enter the following command:

    Note: If you have not yet changed a directory, the current directory on the BIG-IP system should be /config/bigip_ca.

    cd bigip_ca

  4. To determine the OpenSSL configuration directory, enter the following command:

    openssl version -a

    In the following example, the OpenSSL configuration directory is in the /etc/pki/tls directory:

    OPENSSLDIR: "/etc/pki/tls"

  5. To copy the OpenSSL configuration file, openssl.cnf, to the working CA directory, use the following command syntax:

    cp </path>/openssl.cnf .

    For example, to copy the openssl.cnf file to your working directory using the path /etc/pki/tls, enter the following command:

    cp /etc/pki/tls/openssl.cnf .

  6. Using a text editor, edit the openssl.cnf file in the working CA directory and ensure that the existing configuration directives agree with the following example information. The [section] information is included to help you go the OpenSSL configuration file. Do not remove the configuration directives.

    Note: To avoid encoding issues, F5 recommends that you manually edit the openssl.cnf file rather than copy and paste.

    Important: The CA certificate and private_key are created in step 9 of this procedure. If you prefer a different name than bigip_ca, modify the configuration file accordingly and use the same names in step 9.

    [ CA_default ]
    dir             = .                                               
    certificate     = $dir/bigip_ca.crt                                                  
    private_key     = $dir/bigip_ca.key  
    new_certs_dir   = $dir

    default_days = 3650 
    default_md   = sha256

    policy = policy_anything

    [ policy_anything ]
    countryName             = optional
    stateOrProvinceName     = optional
    organizationName        = optional
    organizationalUnitName  = optional
    commonName              = supplied
    emailAddress            = optional

    [ req ]
    default_bits            = 2048
    default_md              = sha256

    [ usr_cert ]
    basicConstraints=CA:FALSE
    keyUsage = nonRepudiation, digitalSignature, keyEncipherment, keyAgreement, dataEncipherment

    [ v3_ca ]
    basicConstraints = critical, CA:TRUE, pathlen:9
    keyUsage = critical, nonRepudiation, digitalSignature, keyEncipherment, keyCertSign, keyAgreement, dataEncipherment, cRLSign
    extendedKeyUsage = OCSPSigning

  7. Save the file.
  8. To create the necessary CA serial and index.txt files, enter the following commands:

    Note: The index.txt file contains the list of signed SSL certificates. The serial file is the source of the SSL certificate serial number. The number increments by 1 with each signing.

    echo 100000 > serial
    touch index.txt

  9. To create a new root CA key and certificate signing request (CSR), use the following command syntax:

    openssl req -out <csr_name>.csr -new -newkey rsa:4096 -keyout <key_name>.key -extensions v3_ca -config ./openssl.cnf

    For example, to create a root CA key named bigip_ca.key and a CSR named bigip_ca.csr, enter the following command:

    Note: This command requires that you provide a password and answer the questions in the following table.

    openssl req -out bigip_ca.csr -new -newkey rsa:4096 -keyout bigip_ca.key -extensions v3_ca -config ./openssl.cnf

    QuestionDescriptionExample
    Enter PEM pass phrase:The pass phrase used to protect the CA key. This pass phrase is required each time you sign a certificate. Store it in a safe place.Choose a strong pass phrase
    Country NameA two-letter abbreviation for your country.US
    State or Province Name The full state or province name where your organization is located. Washington
    Locality NameThe full city name where your organization is located.Seattle
    Organization NameThe full legal name of your organization.Example, Inc.
    Organizational Unit NameOptional for additional organization information.Example F5 admin
    Common NameThis identifies the BIG-IP root certificate.bigipca.example.com
    Email AddressThe email address for the CA contact (optional).f5admin@example.com
  10. To self-sign the CA CSR and create a new CA signing certificate, use the following command syntax:

    Note: With OCSP enabled, the httpd service checks revocation status for both the CA signing certificate and SSL client certificate. The -self-signed option causes the CA signing certificate to appear in the certificate database (index.txt) along with the SSL client certificates.

    openssl ca -selfsign -in <csr_name>.csr -out <cert_name>.crt -extensions v3_ca -config ./openssl.cnf

    For example, to self-sign the root CA certificate signing request named bigip_ca.req and a create the CA signing certificate named bigip_ca.crt, enter the following command:

    openssl ca -selfsign -in bigip_ca.csr -out bigip_ca.crt -extensions v3_ca -config ./openssl.cnf

    The command output appears similar to the following example:

    Enter pass phrase for ./bigip_ca.key:

    Certificate is to be certified until Jan 01 12:30:23 2030 GMT (3650 days)

    Sign the certificate? [y/n]:y

    1 out of 1 certificate requests certified, commit? [y/n]y

  11. To create a directory that stores BIG-IP SSL client certificates, use the following command syntax:

    mkdir <name>

    For example, to create a directory named client_certs that stores BIG-IP SSL client certificates, enter the following command:

    mkdir client_certs

  12. To create a CSR for the SSL client certificate, use the following command syntax:

    openssl req -new -nodes -out <directory>/<request_name>.req -keyout <directory>/<key_name>.key -config ./openssl.cnf

    For example, to create a new CSR named jsmith.csr and an SSL key named jsmith.key in the directory client_certs, enter the following command:

    Note: This command requires that you answer the questions in the following table. When prompted for a challenge password, enter Enter for no password.

    Important: In this example, the SSL client certificate's Common Name (CN) attribute is used to store the BIG-IP system username.

    openssl req -new -nodes -out client_certs/jsmith.csr -keyout client_certs/jsmith.key -config ./openssl.cnf

    QuestionDescriptionExample
    Country NameA two-letter abbreviation for your country.US
    State or Province NameThe full state or province name where your organization is located. Not abbreviated.Washington
    Locality NameThe full city name where your organization is located.Seattle
    Organization NameThe full legal name of your organization.Example Company
    Organizational Unit NameOptional for additional organization information.Example F5 admin
    Common NameThe fully qualified host name or IP address used to access the BIG-IP system.jsmith
    Email AddressThe email address for the CA contact (optional).jsmith@example.com
    A challenge password []:Not required since the request is not being sent to a remote CA.Enter
    An optional company name:Not required.Enter
  13. To sign the CSR with the root CA certificate, use the following command syntax:

    openssl ca -out <directory>/<cert_name>.crt -config ./openssl.cnf -infiles <directory>/<request_name>.csr

    For example, to sign a request named jsmith.req in the client_certs directory, enter the following command:

    Note: You must provide the CA private key pass phrase. Answer Y to the questions that follow.

    openssl ca -out client_certs/jsmith.crt -config ./openssl.cnf -infiles client_certs/jsmith.csr

    The command output appears similar to the following example:

    Enter pass phrase for ./bigip_ca.key:

    Certificate is to be certified until Jan 01 12:34:56 2030 GMT (3650 days)

    Sign the certificate? [y/n]:y

    1 out of 1 certificate requests certified, commit? [y/n]y

  14. To create the pkcs12 file for the final procedure, use the following command syntax:

    openssl pkcs12 -export -in <directory>/<cert_name>.crt -inkey <directory>/<key_name>.key -out <directory>/<p12_name>.p12 -name "<comment>"

    For example, to create a pkcs12 file named jsmith.p12 in the client_certs directory, enter the following command:

    Note: Because pkcs12 files contain both the SSL certificate and key, it should be password protected. However, you can press Enter twice if a password is not required. 

    openssl pkcs12 -export -in client_certs/jsmith.crt -inkey client_certs/jsmith.key -out client_certs/jsmith.p12 -name "jsmith pkcs12"
    Enter Export Password:
    Verifying - Enter Export Password:

  15. You can repeat steps 10 through 14 for additional SSL client certificates. Make sure to change the file name and the SSL client certificate username attribute for each user.

    Note: The user pkcs12 file is located in the /config/bigip_ca/client_certs. directory on the BIG-IP system.

  16. Continue to the next procedure.

Impact of procedure: System users will not be able to access the Configuration utility until performing the final procedure for importing the SSL client certificate into the web browser.

Configuration utility

  1. Obtain the CA signing certificate, which is the SSL certificate used to sign SSL client certificates.

    Note: If you used the previous procedure, the certificate is named bigip_ca.crt and is stored in the /config/bigip_ca directory.

  2. Log in to the Configuration utility.
  3. To upload the CA certificate, go to one of the following locations:
    • 13.0.0 and later:

      System > Certificate Management > Device Certificate Management > Device CA Certificate List > Import

    • 12.1.3 and earlier:

      System > File Management > Apache Certificate List > Import

  4. For File Name, select Choose File.
  5. Go to and select the CA signing certificate.
  6. Select Open.
  7. For Name, enter a unique name for the CA signing certificate.
  8. Select Import.
  9. To configure and enable Remote ClientCert LDAP, go to System > Users > Authentication. 
  10. In the Authentication list, select Advanced.
  11. Select Change.
  12. For User Directory, select Remote - ClientCert LDAP.
  13. In the Host section, enter the IP address or host name of the of the remote LDAP server.
  14. In the Remote Directory Tree section, enter the LDAP file location for the user account database.
  15. For Scope, select the LDAP search scope.
  16. In the Bind section, enter the LDAP server search account username and password information. 
  17. For CA Certificate, select the CA signing certificate imported in step 1 of this procedure.
  18. For Login Name, enter the SSL client certificate attribute to extract from the SSL client certificate.
  19. For Login Attribute, enter the LDAP attribute to search using the extracted username.
  20. For Login Filter, enter the filter to be applied to the username extracted from the SSL client certificate. 
  21. For Client Certificate Name, select the x.509 attribute to search in the SSL client certificate.
  22. For OCSP Override, select on.
  23. For OCSP Responder, fill in the connection information for the OCSP responder.
  24. Under External Users, select the appropriate Role, Partition Access and Terminal Access for user accounts that do not exist locally on the BIG-IP system
  25. Select Finished.

TMOS Shell (tmsh)

  1. Secure Copy (SCP) the CA signing certificate to the BIG-IP system's /shared directory. For example:

    scp <name>.key <admin_user>@<BIG-IP_address>:/shared/<name>.key

  2. To log in to tmsh, enter the following command:

    tmsh

  3. To configure the ClientCert LDAP settings, use the following command syntax:

    create auth cert-ldap system-auth servers add { <ldap_server> } bind-dn <search_user_dist_name>  bind-pw <search_user_password> login-attribute <ldap_attribute> search-base-dn <remote_directory> login-name <ssl_cert_attribute> login-filter <filter_expression> sso on

    For example, to configure ClientCert LDAP settings to connect using searchadmin user and password askf5123 to LDAP server at 192.16.10.100, using the LDAP uid attribute to search for the user as a login name and a login filter that searches the first eight alphabetic characters, enter the following command:

    create auth cert-ldap system-auth bind-dn cn=searchadmin,dc=askf5,dc=pslab,dc=local  bind-pw askf5123 login-attribute uid search-base-dn ou=Users,dc=askf5,dc=pslab,dc=local servers add { 192.168.10.100 } sso on login-name cn login-filter "[a-z]\{8\}"

  4. To import the CA signing certificate into the BIG-IP system filestore, use the following command syntax:

    create sys file apache-ssl-cert <ca_cert_name> source-path file:/shared/<ca_cert_name>.crt

    For example, to import the CA signing certificate named bigip_ca.crt  and name it bigip_ca in the BIG-IP system file store, enter the following command:

    create sys file apache-ssl-cert bigip_ca source-path file:/shared/bigip_ca.crt

  5. To associate the CA signing certificate with the BIG-IP Apache service, use the following command syntax:

    modify sys httpd ssl-ca-cert-file /Common/<ca_cert_name>

    For example, associate the CA signing certificate named bigip_ca with the BIG-IP Apache service, enter the following command:

    modify sys httpd ssl-ca-cert-file /Common/bigip_ca

  6. To configure the OCSP responder's connection information, use the following command syntax:

    modify sys httpd ssl-ocsp-override-responder on ssl-ocsp-enable on ssl-ocsp-default-responder http://<IP address:Service Port>

    For example, to configure an OCSP responder using IP address 192.168.10.100 and service port 2560, enter the following command:

    modify sys httpd ssl-ocsp-override-responder on ssl-ocsp-enable on ssl-ocsp-default-responder http://192.168.10.100:2560

  7. To define the external users role, shell and partition access, use the following command syntax:

    modify auth remote-user default-role <role> remote-console-access <tmsh|disabled> default-partition <partition>

    For example, define all external users role as admin with tmsh shell access to the all partitions, enter the following command:

    modify auth remote-user default-role admin remote-console-access tmsh default-partition all

  8. To change the BIG-IP system authentication method to Remote ClientCert LDAP, enter the following command:

    modify auth source type cert-ldap

  9. To save the configuration enter the following command:

    save sys config

  10. To ensure there are no configuration errors, load the configuration by entering the following command:

    load sys config

  11. To restart the httpd process, enter the following command:

    restart sys service httpd

  12. Continue to the next procedure.

Import the SSL client certificate into the web browser 

Before you connect to the Configuration utility, you must import the user's pcks12 file into the web browser's personal certificate store. The steps may vary depending on your web browser.

Note: The following procedures describe third-party software and may change without our knowledge. Refer to each browser's documentation for more information.

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Microsoft Edge

  1. Copy the SSL client certificate to your workstation.

    Note: If you performed the first procedure, the SSL client certificate is named <user name>.p12 and is stored in the /config/bigip_ca/client_certs directory.

  2. Open the web browser.
  3. Enter edge://settings in the browser address bar.
  4. Select Privacy, search, and services
  5. Under Security, select Manage Certificates.
  6. In the Certificates manager, select the Personal tab.
  7. Select Import.
  8. Browse to and select the SSL client certificate.

    Note: If the .p12 file does not appear, change Certificate Files to All Files.

  9. Select Next.
  10. If the .p12 file is password protected, enter the password.
  11. Select Next.
  12. Select Finished.

Google Chrome

  1. Copy the SSL client certificate to your workstation.

    Note: If you performed the first procedure, the SSL client certificate is named <user name>.p12 and is stored in the /config/bigip_ca/client_certs directory.

  2. Open the web browser.
  3. Enter chrome://settings in the browser address bar.
  4. Select Privacy and Security
  5. Select Security
  6. Select Manage Certificates.
  7. In the Certificates manager, select the Personal tab.
  8. Select Import.
  9. Browse to and select the SSL client certificate.

    Note: If the .p12 file does not appear, change Certificate Files to All Files on the far right.

  10. Select Next.
  11. If the .p12 file is password protected, enter the password.
  12. Select Next.
  13. Select Finished.

Mozilla Firefox

  1. Copy the SSL client certificate to your workstation.

    Note: If you performed the first procedure, the SSL client certificate is named <user name>.p12 and is stored in the /config/bigip_ca/client_certs directory.

  2. Open the web browser.
  3. Enter about:preferences#privacy in the browser address bar.
  4. In the Security section, next to Certificates, select View Certificates.
  5. Select the Your Certificates tab.
  6. Select Import.
  7. If the .p12 file is password protected, enter the password.
  8. Browse to and select the SSL client certificate.

    Note: If the file does not appear, change Certificate Files to All Files on the far right.

  9. Select Open.
  10. Select OK.

Internet Explorer

Note: Microsoft announced the end of support for Internet Explorer on June 15, 2022. You should use supported browsers such as Microsoft Edge, Google Chrome, or Mozilla Firefox.
  1. Copy the SSL client certificate to your workstation.

    Note: If you performed the first procedure, the SSL client certificate is named <user name>.p12 and is stored in the /config/bigip_ca/client_certs directory.

  2. Open the web browser.
  3. Go to Tools > Internet Options.
  4. Select the Content tab.
  5. Select Certificates.
  6. Select the Personal tab.
  7. Select Import and Next.
  8. Browse to and select the SSL client certificate.

    Note: If the file does not appear, change Certificate Files to All Files.

  9. Select Open.
  10. Select Next.
  11. If the .p12 file is password protected, enter the password.
  12. Select Next.
  13. Select Finished.
