Description
Syslog connection failed with a repeated message logged under /var/log/messages.

notice syslog-ng[3544]: Syslog connection established; fd='51', server='EXAMPLE_SERVER(10.10.10.4:514)', local='EXAMPLE_SERVER(0.0.0.0:0)'
notice syslog-ng[3544]: Syslog connection broken; fd='51', server='EXAMPLE_SERVER(10.10.10.4:5514)', time_reopen='60'
notice syslog-ng[3544]: Syslog connection established; fd='25', server='EXAMPLE_SERVER(10.10.10.4:514)', local='EXAMPLE_SERVER(0.0.0.0:0)'
notice syslog-ng[3544]: Syslog connection broken; fd='25', server='EXAMPLE_SERVER(10.10.10.4:514)', time_reopen='60'
notice syslog-ng[3544]: Syslog connection established; fd='54', server='EXAMPLE_SERVER(10.10.10.4:514)', local='EXAMPLE_SERVER(0.0.0.0:0)'

Environment

  • BIG-IP LTM
  • Remote Syslog server

Cause

There may be one or more multiple causes for this issue:
  • Remote syslog services were stopped.
  • Network connectivity issues
  • MTU Mismatch between BIG-IP and another network device

Recommended Actions

  1. Make sure the connection is stable and services are running on remote syslog server

  2. To check connectivity issue, collect a packet capture on BIG-IP. 
    # tcpdump -nni 0.0:nnn -s0 host <Syslog IP> and port 514 -w /var/tmp/syslog.pcap -v

  3. Verify if syslog packets are sent out from the BIG-IP to the syslog server. 

    Additional Troubleshooting steps can be found in:
    K86480148: Troubleshooting issues sending logs to a remote syslog server

Additional Information

If the issue is related to MTU mismatch, you can either:

  • Increase the MTU on the router to match the one of BIG-IP.
  • Create a static route to syslog server with specific MTU matching one on the router. For example:
    tmsh create /sys management-route <server IP>/<mask> mtu <MTU value> gateway <gateway IP>
  • Configure TCP based syslog.
