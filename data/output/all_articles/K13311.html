Known Issue

The BIG-IP system may incorrectly close a virtual server connection when processing a TCP RST packet with a sequence number that falls outside of the advertised window.

This issue occurs when the following condition is met:

  • The virtual server references a FastL4 profile.

This issue occurs because the BIG-IP system does not properly validate the sequence number for the RST packet before removing the connection.

RFC793 states the following about RST processing: In all states except SYN-SENT, all reset (RST) segments are validated by checking their SEQ-fields. A reset is valid if its sequence number is in the window.

Impact

The BIG-IP system may incorrectly close some FastL4 virtual server connections.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may incorrectly close FastL4 virtual server connections.
  • The pool member does not close the associated connection.
