Description

Increasing statistics retention on BIGIQ to custom values.

Environment

  • BIG-IQ

Cause

None

Recommended Actions

  2. From the outcome, you need to sum up all the "store.size" field to determine the hourly data space usage(specified in MB).
    For the above example, hourly data statistics usage is roughly 58 MB calcuated from total on store.size , this is for 168 hours(default value) i.e, 7 days.
    If you want to retain 6 months of hourly data (i.e. 180 days approx ) you need roughly 26 times the existing usage to retain the new data.
    New usage would be 180/7*58= 1491 MB

    This is a sample output : shards disk.indices disk.used disk.avail disk.total disk.percent host         ip           node

    As per output disk available to store further statistics is roughly 7GB, this should be more than sufficient to meet our new hourly data retention requirement(1491MB). 
    However, if the existing storage is not adequate enough to accommodate the new data, you may need to resize the DCD. 
    If resizing DCD is not an option or is not a VE, you may need to add additional DCD to the cluster.

    Note: If you have more than one DCD, you need to take in to account the disk available on both data nodes.

Additional Information

Same procedure may be used to calculate real-time, daily and monthly retention usage too:

  • for real-time data : curl http://localhost:9200/_cat/indices?v?pretty | grep tl0 
  • for daily data : curl http://localhost:9200/_cat/indices?v?pretty | grep tl2 
  • for monthly data : curl http://localhost:9200/_cat/indices?v?pretty | grep tl3
