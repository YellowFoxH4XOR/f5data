Topic

You should consider using this procedure under the following condition:

  • You want to establish an IPsec ESP tunnel connection through the BIG-IP system, using an IP forwarding or FastL4 virtual server.

Important: The following article is not applicable to configurations where the BIG-IP system is the IPsec Security Endpoint.

Description

In BIG-IP 11.0.0, additional Traffic Management Microkernel (TMM) handling of IPsec traffic was introduced with the ability of the BIG-IP system to terminate an IPsec connection as an IPsec SA endpoint. When processing an IPsec connection, TMM uses the IPsec ESP Security Parameter Index (SPI) in the connection flow hash to uniquely identify the connection.

If you pass IPsec ESP traffic through an IP forwarding or FastL4 virtual server, because the SPI is not symmetric, it will likely not be the same from client to server as from server to client. When forwarding IPsec ESP traffic through an IP forwarding virtual server, if the SPI in the server to client response packet has changed, TMM will not identify the response as matching an existing traffic flow and drop the packet. To pass the IPsec ESP reply traffic, you must disable the BIG-IP system from using the SPI to identify the connection flow.

The ipsec.lookupspi database variable added in BIG-IP 11.2.0 allows you to disable the BIG-IP system from using the SPI to identify the connection flow.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have configured an appropriate IP forwarding or FastL4 virtual server to forward the desired IPsec traffic.
  • The Protocol configuration of IP forwarding or FastL4 virtual server is set to * All Protocols.
  • Your BIG-IP system is not configured to be an IPsec SA terminal endpoint.

Procedures

Disable SPI lookup

To disable the BIG-IP system from using the SPI to identify the connection flow, perform the following procedure:

Impact of procedure: The BIG-IP system cannot function as an IPSec SA terminal endpoint with this database key disabled.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To disable SPI lookup, enter the following command:

    modify sys db ipsec.lookupspi value disable

  3. Save the change by entering the following command:

    save /sys config

    Important: Under no circumstances should you disable ipsec.lookupspi when you try to configure or troubleshoot an IPsec tunnel that terminates on the BIG-IP system. This value does not influence tunnel establishment in any way. This value influences the handling of ESP packets by TMM. If you disable ipsec.lookupspi while there is an IPsec tunnel that terminates on the BIG-IP system, you break communication over that tunnel.

    Note: ESP carries the encrypted end-to-end data and is not related to tunnel establishment itself. When you have inappropriately disabled ipsec.lookupspi, you can see the BIG-IP system send ICMP Protocol 50 unreachable messages to the other peer.

    Note: If the IPsec traffic that either passes through the BIG-IP system or terminates on the BIG-IP system has NAT Detection enabled and detected, then the ISAKMP and ESP traffic switches to UDP port 4500. The SPI in lookupspi is a field in the ESP header. When switching to UDP port 4500, the ipsec.lookupspi variable is rendered meaningless because the IP protocol is UDP and not ESP.
