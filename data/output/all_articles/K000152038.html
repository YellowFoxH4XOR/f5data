K000152038: When using IPv6 virtual servers, the system performs source NAT (SNAT) using the device’s IPv4 self IP address - even when SNAT is disabled on the virtual server.

Type
Support Solution
Published
2025-06-30
Updated
2025-07-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000152038

Description

When using BIG-IP LTM with IPv6 virtual servers, it is observed that BIG-IP system performs source NAT (SNAT) using device's IPv4 self IP address - even when SNAT is disabled on the virtual server level. As a result, the backend server sees the IPv4 self IP as the source address instead of the original client's IPv6 address. This behavior does not occur with IPv4 virtual servers, where the original client IP address is preserved. 

 

Environment

  • BIG-IP LTM
  • IPv6 virtual server
  • IPv4 backend server

Cause

IPv6 and IPv4 are not directly compatible protocols. When a client connects using IPv6 and the backend pool member is configured with IPv4, the BIG-IP must translate between the two protocols. In such cases, the BIG-IP uses its own IPv4 self IP as the source address to establish connectivity with the IPv4 backend server. This behavior occurs even if SNAT is disabled. 

 

Recommended Actions

This is an expected behavior when the BIG-IP is bridging traffic between IPv6 clients and IPv4 backend servers. The BIG-IP system must use IPv4 address as the source when connecting to IPv4 machines. If it is necessary to preserve the original client IP, ensure that both the client-side and server-side are using using the same IP protocol version (either both IPv4 or both IPv6). For environments requiring end-to-end visibility of the client IP address, consider using X-Forwarded-For headers or similar mechanism at the application layer.
