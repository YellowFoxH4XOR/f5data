Security Advisory Description

A specifically crafted HTTP request may bypass BIG-IP HTTP RFC enforcement and may lead the BIG-IP system to pass malformed HTTP requests to a target pool member web server.

This issue occurs when all of the following conditions are met:

  • A virtual server with an iRule that contains a HTTP::redirect command, processes the malformed HTTP requests.
  • You are running a BIG-IP version that contains the fix for the issue described in K50375550: A specifically crafted HTTP request may lead the BIG-IP system to pass malformed HTTP requests to a target pool member web server (HTTP Desync Attack)
  • Depending on your BIG-IP version, you enabled HTTP RFC Compliance by performing one of the following steps:
    • Select the Enforce RFC Compliance checkbox under the Enforcement section of the HTTP profile for the affected BIG-IP virtual server.
    • Enable the tmm.http.rfc.enforcement Database Variable and reboot the BIG-IP system.

Impact

The malformed HTTP requests may be passed to the pool member web server and, depending on the behavior of the pool member web server, may allow an HTTP Request Smuggling attack to take place against the pool member web server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Depending on the client requests and HTTP RFC compliance of the target pool member web server, the pool member web server may interpret the client requests differently and perform unintended actions.

To work around this issue, you can associate an iRule to the affected BIG-IP virtual server. For more information about the iRule, contact F5 Support, and reference this article number.
