Description

After an upgrade, when booting into the new volume with the new software version, the device is INOPERATIVE.

The Configuration Utility (GUI) shows an image with error: starting web server.

You can find the following continuous logs on /var/log/ltm:

notice mcpd[<PID>]: 01071038:5: Loading keys from the file.
notice mcpd[<PID>]: 01071029:5: Cannot open unit key store

Trying to boot into the previous working partition and the command switchboot does not work:

[root@localhost:INOPERATIVE:] config # switchboot
No software status records found.

When trying to load the configuration with tmsh load sys config, you get the following error:

01071029:5: Master Key not present.
Unexpected Error: Validating configuration process failed.

Environment

  • You have upgraded from a version where Bug-ID 737910 is fixed, to a version where Bug-ID 737910 is not fixed

    Note: Refer to K18535734: BIG-IP Secure Vault vulnerability CVE-2019-660 for more details of versions involved.

  • BIG-IP iSeries platforms

Cause

This issue occurs due to a change in unit key storage.

Recommended Actions

  1. Connect to the device using console
  2. Reboot into the previously working volume used before the upgrade, using the GRUB menu
  3. Delete the volume with the inoperative software version using this command:

    tmsh delete /sys software volume <volume>

    For example, to delete volume HD1.2, enter the following command:

    tmsh delete /sys software volume HD1.2

  4. Start the upgrading process again using a software version where this issue has been fixed

As an alternative to step 1-2 above, if you do not have immediate console access, use the grub_default -b <boot location> command to select the previous volume, then reboot the device with the reboot command.

Additional Information

BIG-IP administrators are more likely to encounter this issue when upgrading to an intermediate version in a given upgrade path. For example, upgrading from 12.1.6 to 14.1.0, with an ultimate target of 16.1.x, would cause this issue when booting into 14.1.0. In general, there is no good reason not to use the latest point release in this scenario.
