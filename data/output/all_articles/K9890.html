Known Issue

This is the result of a known issue. By design, the BIG-IP GTM system should support a single or redundant BIG-IP LTM configuration containing multiple virtual servers with the same IP address:Port combination. However, if virtual server discovery is enabled, this configuration will cause the BIG-IP GTM system to continuously rewrite and reload its configuration.

Important: The BIG-IP GTM system is not intended to support this configuration across multiple BIG-IP LTM systems that operate independently.

This issue occurs when all of the following conditions are met:

  • The BIG-IP LTM system is added to the BIG-IP GTM system and virtual server discovery is enabled.
  • The BIG-IP LTM system is configured with two or more virtual servers that share the same IP address:Port combination. Virtual servers may share the same IP address:Port combination when certain virtual server configuration elements are different as described in the following examples:

    The following virtual servers share the same IP address and port, but are named differently and are associated with different VLANs:

    virtual myVirtualExternalVLAN {
    pool myPool
    destination 172.16.1.14:http
    ip protocol tcp
    vlans external enable
    }
    virtual myVirtualInternalVLAN {
    pool myPool
    destination 172.16.1.14:http
    ip protocol tcp
    vlans internal enable
    }

    The following virtual servers share the same IP address and port, but are named differently and are configured to use different protocols:

    virtual my_dns_tcp {
    pool dns_tcp_pool
    destination 172.16.1.14:domain
    ip protocol tcp
    vlans external enable
    }
    virtual    my_dns_upd {
    pool dns_udp_pool
    destination 172.16.1.14:domain
    ip protocol udp
    vlans external enable
    }

When the above conditions are met, the following behavior will occur:

  • Metrics may be missing from one or all virtual servers that share the same IP address:Port combination. The missing metrics include virtual server utilization and monitor status. The missing metric data may affect load balancing of virtual servers when answering DNS requests.
  • The /var/log/gtm file will report configuration updates and reload as often as every 30 seconds.

    For example, the following block of entries will log repeatedly, typically every 30 seconds:

    gtmd[1666]: 011a0025:5: Uploading updated configuration to MCPD
    gtmparse: Initializing ...
    /usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
    /usr/local/gtm/include/base_region.ISP: SUCCESS
    /config/gtm/wideip.conf: SUCCESS
    gtmparse: SUCCESS

F5 Product Development tracked this issue as ID 222281 (formerly CR116346) and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
