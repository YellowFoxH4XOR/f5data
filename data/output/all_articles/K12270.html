Known Issue

Note: The issue described in this Solution affects only BIG-IP systems running version 10.2.0 HF2 that are being configured to use network failover for the first time. If you had network failover configured before you upgraded to BIG-IP version 10.2.0 HF2, and you carried over the previous configuration, this Solution does not apply to you.

This is the result of a known issue. When network failover is enabled for the first time using the Configuration utility, the /config/bigip_sys.conf file is not correctly updated to reflect the change.

As a result, note the following:

  • If you perform a ConfigSync operation, the receiving unit will disable network failover, causing an active-active situation.
  • If you reload the configuration of one the units, that unit will disable network failover, causing an active-active situation.
  • If you restore a UCS archive that was taken at this stage, that unit will disable network failover, causing an active-active situation.

F5 Product Development tracked this issue as ID 339955, and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

To resolve this situation and ensure that the network failover configuration is correctly saved to the /config/bigip_sys.conf file, perform the following procedure on both units:

  1. Log in to the BIG-IP system command line.
  2. Enable network failover by typing the following command:

    bigpipe failover network failover enable

  3. Save the configuration by typing the following command:

    bigpipe base save

After completing this procedure, one of the two units sets itself as standby, and all tasks (such as ConfigSync) work as intended. Additionally, you are also able to use the Configuration utility to further enable or disable network failover.
