Description

We have a microservice ( lets say MSRV-A) that is deployed in Azure Kubernetes Services that needs to make a call to another service deployed in the same AKS ( MSRV-B) . The microservice initiating the request (MSRV-A) will make a call with a COOKIE or a header example :

 

KEY : mass_auth

Value: pod1/pod2/pod3

 

The app team wants the call from (MSRV-A) with mass_auth value pod1 to go to POD1 of MSRV-B and likewise value pod2 to upstream traffic only to pod2.

 

The reason for this as per app team is that the expected auth token response for MSRV-A would only be available in a specific pod in MSRV-B and they believe if they send some headers NGINX INGRESS CONTROLLER can make the choice of upstream based on that header and proxy it to specific header.
 

Environment

  • NGINX Ingress Controller
  • traffic-splitting
  • subselector

Virtual Server config

apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
  name: cafe
spec:
  host: cafe.example.com
  upstreams:
  - name: tea-cookie
    service: cafe-svc
    subselector:
      cookie: tea
    port: 80
  - name: coffee-cookie
    service: cafe-svc
    subselector:
      cookie: coffee
    port: 80
  - name: cafe
    service: cafe-svc
    port: 80
  routes:
  - path: /cafe
    matches:
    - conditions:
      - cookie: cafe
        value: tea
      action:
        pass: tea-cookie
    - conditions:
      - cookie: cafe
        value: coffee
      action:
        pass: coffee-cookie
    action:
      pass: cafe
