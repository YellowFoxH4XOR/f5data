Description

Connections reset after applying an empty NAT policy and connecting to the virtual server: F5RST: No server selected.

For example, given the following virtual server and NAT policy:

ltm virtual ip-fwd-vs {
    destination 10.0.0.0:any
    ip-forward
    ip-protocol tcp
    mask 255.0.0.0
    profiles {
        fastL4 { }
    }
    security-nat-policy {
        policy empty_policy
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    translate-address disabled
    translate-port disabled
    vs-index 13
}

security nat policy empty_policy {
    traffic-group /Common/traffic-group-1
}

Connections are immediately reset on the first SYN:

1 10.10.30.15 → 10.10.30.85 IN  s1/tmm2 : 40728 → 80 [SYN]
2 10.10.30.85 → 10.10.30.15 OUT s1/tmm2 : 80 → 40728 [RST, ACK] [F5RST: No server selected]

Environment

  • AFM NAT policy

Cause

This is expected behaviour when applying an empty NAT policy with no rules.

Recommended Actions

Do not apply an empty NAT policy to a virtual server.
