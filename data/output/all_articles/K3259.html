Topic

The bigpipe summary command provides detailed information about the traffic that BIG-IP receives and processes. You can use this information to help troubleshoot any problems that BIG-IP encounters when passing traffic.

Note: BIG-IP does not store the data that is provided by the bigpipe summary command past reboot. If you want to retain this information, you must write it to a file before you reboot BIG-IP. For information about retaining output from the bigpipe summary command, refer to K134: Retaining the output from the bigpipe summary and bigpipe ms commands after reboot.

bigpipe summary

The bigpipe summary output includes the following messages:

OutputDefinition
BIG-IP total uptimeThis statistic provides the total uptime for BIG-IP since the last reboot. It displays in days, hours, minutes, and seconds.
BIG-IP total uptime (secs)This statistic provides the total uptime for BIG-IP since the last reboot. It displays in seconds.
BIG-IP total # connectionsThis statistic provides the total number of connections that BIG-IP has handled since the last reboot. A connection is a data path between a client machine, a virtual server, NAT, or SNAT, and a node.

Connections last until they are timed out by a TCP or UDP timer. This is important to note, because a system configured with longer timeout values will generally report a higher number of connections.

Note: For more information about treapers, refer to K2287: Configuring BIG-IP to close idle connections.

BIG-IP total # pktsThis statistic provides the total number of packets that BIG-IP handled since the last reboot. The value should equal the sum of BIG-IP total # pkts(inbound) and BIG-IP total # pkts(outbound). To get the average packets per second since the last reboot, divide this value by BIG-IP total uptime (secs).
BIG-IP total # bitsThis statistic provides the total number of bits that BIG-IP handled since the last reboot. This value should equal the sum of BIG-IP total # bits(inbound) and BIG-IP total # bits(outbound). To get the average bits per second since the last reboot, divide this value by BIG-IP total uptime (secs).
BIG-IP total # pkts(inbound) This statistic provides the total number of packets that BIG-IP has received.
BIG-IP total # bits(inbound) This statistic provides the total size of inbound packets that BIG-IP has received, in bits.
BIG-IP total # pkts(outbound) This statistic provides the total number of packets that BIG-IP has sent.
BIG-IP total # bits(outbound)This statistic provides the total size of outbound packets that BIG-IP has sent, in bits.
BIG-IP error no nodes availableThis error indicates that the BIG-IP attempted to make a connection to a node, but none of the nodes in the selected pool were available. Because no nodes were available, the incoming packet was dropped. If this number is higher than zero, it indicates that one or more of the virtual servers are, or have been, down.
BIG-IP tcp port denyThis statistic indicates that a connection was attempted, but the TCP port requested was not open. Because the port was not open, BIG-IP discarded the incoming packet. This statistic applies only to self IP addresses on the BIG-IP, not to virtual servers, NATs, or SNATs.
BIG-IP udp port denyThis statistic indicates that a connection was attempted, but the requested UDP port was not open. Because the port was not open, BIG-IP discarded the incoming packet. This applies only to self IP addresses on the BIG-IP, not virtual servers, NATs, or SNATs.

If the verbose_log_level global is set to 1 or 15, the closed port and source IP address will appear in the /var/log/bigip file. You can also select this level in the Advanced Properties section of the Configuration utility.
BIG-IP virtual tcp port denyThis statistic indicates that a connection was attempted to a virtual server address, but the TCP port used was not open. Because the port was not enabled for this virtual server, BIG-IP discarded the incoming packet.

If the verbose_log_level global is set to 1 or 15, the closed port and source IP address will appear in the /var/log/bigip file. You can also select this level in the Advanced Properties section of the Configuration utility.
BIG-IP virtual udp port deny.This statistic indicates that a connection was attempted to a virtual server address, but using a UDP port that was not open. Because the port was not enabled for this virtual server, BIG-IP discarded the incoming packet.

If the verbose_log_level global is set to 4 or 15, the closed port and source IP address will appear in the /var/log/bigip file. You can also select this level in the Advanced Properties section of the Configuration utility.
BIG-IP max connections denyThis error indicates that the maximum number of connections was received for a service with a concurrent connection limit configured. Because the connection limit was exceeded, BIG-IP dropped the packet.
BIG-IP virtual duplicate syn sslThis error is obsolete and should never report a value other than zero.
BIG-IP virtual duplicate syn new destThis error indicates that a connection arrived from a source port and address for which a connection already existed on BIG-IP; however, this connection requested a different destination. BIG-IP tore down the existing connection and created a new connection.

This occurs most frequently for packets that are arriving from busy proxies where source ports are constantly being reused. These errors are common and should not be a cause for alarm.
BIG-IP virtual duplicate syn node downThis error indicates that a SYN packet arrived for a virtual server and BIG-IP selected a node for the connection. The node did not respond within the client's TCP timeout and the client retransmitted the SYN. When the retransmitted SYN arrived, the node that was originally selected by the virtual server was no longer available, so BIG-IP tore down the existing connection and selected a different node to receive the connection. This error is common when nodes are unreliable or overburdened. The seriousness of this error varies from site to site. On sites where there are a large number of low-capacity nodes, you would see this error as some nodes become overloaded and are marked down. This error is also more common with some load-balancing modes where certain nodes may receive more connections than others.
BIG-IP virtual maint mode denyThis error indicates that a connection was attempted but denied because the BIG-IP was in maintenance mode. You can view the current maintenance status using the bigpipe maint command.
BIG-IP virtual addr max connections denyThis error indicates that a connection was attempted to a virtual server address that exceeded the configured connection limit. Because the connection limit was exceeded, BIG-IP dropped the packet.
BIG-IP virtual path max connections denyThis error indicates that a connection was attempted to a virtual server that exceeded the configured connection limit. Because the connection limit was exceeded, BIG-IP dropped the packet.
BIG-IP virtual non synThis error indicates that a packet arrived with a virtual server destination; however, the packet was not a SYN and there was no existing connection. BIG-IP discarded the packet. BIG-IP will only create a new connection to a virtual server when it receives a SYN.

This error is common and could occur for a variety of reasons. It is typical for this number to grow very large. In most cases, this error occurs when packets arrive out of sequence or when packets are dropped before arriving at BIG-IP.
BIG-IP no handler denyThis error indicates that a packet arrived at BIG-IP, but BIG-IP could not match it to any configured virtual server, NAT, or SNAT and IP forwarding was not enabled, so BIG-IP dropped the packet.

BIG-IP error virtual fragment no portThis error indicates that a packet fragment arrived, but it was not the first fragment. Since the first fragment contains the port and is required to set up a new connection, BIG-IP discarded the fragment.

This is roughly equivalent to the BIG-IP virtual non syn error, but it refers to fragmented packets rather than intact packets. As with virtual non syn, this most likely occurred because fragments arrive out of sequence or not at all. This is a common error and not usually a cause for concern.
BIG-IP error virtual fragment no connThis error indicates that a packet fragment arrived, but it was not the first fragment. BIG-IP previously received the first fragment, but it was not a SYN and did not match an existing connection, so BIG-IP discarded it.

This error is most likely to occur in conjunction with a virtual non syn error. When BIG-IP received the first packet, it found that it met the criteria for virtual non syn and dropped it. This error indicates that the BIG-IP is dropping the following fragments of that packet. As with virtual non syn and virtual fragment no port, this error is relatively common.
BIG-IP error standby shared dropThis error indicates that a packet arrived at the standby BIG-IP with a destination of the shared alias. Because BIG-IP was in standby state, it dropped the packet.

This is most likely to occur when a BIG-IP has failed over, but the ARP cache of another device has not yet been updated. Because that device is caching an invalid ARP, it continues to send packets to the previously active BIG-IP.
BIG-IP tcp timeoutsThis statistic indicates the total number of TCP connections that have been timed out and closed by a TCP service timeout.

Note: In BIG-IP versions 4.0 through 4.1.1, the BIG-IP tcp timeouts field was called BIG-IP reaped.

BIG-IP udp timeoutsThis statistic indicates the total number of UDP connections that have been timed out and closed by the UDP timer.
BIG-IP ssl timeoutsThis statistic indicates the total number of persistence records based on SSL session IDs that have timed out and been deleted.
BIG-IP persist timeoutsThis statistic indicates the total number of non-SSL persistence records that have timed out and been deleted.
BIG-IP memory errorsThis error indicates that BIG-IP could not create a connection because there was insufficient memory.
BIG-IP Total Number of CPUsThis statistic indicates the total number of CPUs detected and used by BIG-IP.
BIG-IP ModeThis value indicates whether the BIG-IP is in active (UP) or standby (DOWN) state.
BIG-IP mem pool totalThis statistic indicates the total amount of memory available on BIG-IP.
BIG-IP mem pool usedThis statistic indicates the percentage of total memory in use on the BIG-IP.
