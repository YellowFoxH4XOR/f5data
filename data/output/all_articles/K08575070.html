Description

  • You may observed after upgrade the following ASM error in /var/log/asm.log file, ' ASM subsystem error (asmlogd,): Can't call method "execute" on an undefined value at /usr/local/share/perl5/F5/DbUtils.pm line 200'
  • The BIG-IP ASM modules may also record error in /var/log/ts/ts_debug.log

asm|INFO|Jul 14 20:18:35.750|13896|,,DBD::mysql::db selectrow_array failed: Table './PRX/REQUEST_LOG#P#p420800001' is marked as crashed and last (automatic?) repair failed at /usr/local/share/perl5/F5/RequestLog.pm line 1072.
asm|INFO|Jul 14 20:18:35.804|13896|,,DBD::mysql::db do failed: Table './PRX/REQUEST_LOG#P#p420800001' is marked as crashed and last (automatic?) repair failed at /usr/local/share/perl5/F5/Db/Partition.pm line 40.

Environment

  • ASM
  • MySQL

Cause

  • Corrupt PRX.REQUEST_LOG table

Recommended Actions

- The PRX.REQUEST_LOG table needs repairing

  • To repair PRX.REQUEST_LOG
  1. Take a back up System  ››  Archives
  2. Access the BIG-IP from command line

Running the below command should not have negative impact on device capability to process traffic. But, for the purpose of safe guarding production environment, we recommend to perform the task on a box that is on a standby status. 

  1. To start repairing PRX.REQUEST_LOG table, run the following command to repair the database.
  • mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'check table PRX.REQUEST_LOG'
  1. Once the repair is completed, you should have the following output next to PRX.REQUEST_LOG 

+-----------------+-------+----------+-----+
| Table | Op | Msg_type | Msg_text |
+-----------------+-------+----------+-----+
| PRX.REQUEST_LOG | check | status | OK |
+-----------------+-------+----------+-----+

- If it still shows error on the database, you need to use the script recover_db.pl, following article K14194: Troubleshooting the BIG-IP ASM MySQL database.
