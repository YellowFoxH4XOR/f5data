Description

While running tcpdump on BIG-IP, tcpdump may automatically exit with error "errbuf ERROR:Session expired due to timeout", as shown below example.

[root@bigip:Active:Standalone] config # tcpdump -ni 0.0:nnn -s0 [tcpdump capture filter] -w /shared/tmp/mycapture.cap
tcpdump: listening on 0.0:nnn, link-type EN10MB (Ethernet), capture size 65535 bytes
 errbuf ERROR:Session expired due to timeout
tcpdump: pcap_loop: Session expired due to timeout
17745743 packets captured
17745743 packets received by filter
0 packets dropped by kernel
[root@bigip:Active:Standalone] config #

 

On /var/log/ltm log file, you will see "013e0004:3: Tcpdump on 127.1.1.X:2 from 127.1.1.254:xxxxx is exiting due to timeout" error as well.

While running tcpdump on BIG-IP, TMM opens internal UDP connection with tcpdump client application on host linux. The error can happen at the time when internal communication between tcpdump client application and TMM stalls (i.e., high volume of traffic is passed from TMM to tcpdump client and tcpdump client application is too busy to respond to TMM PING).

 

Note: This error may happen even though K000133518 condition is NOT met ("-n" option is set and name resolution is disabled).

 

Environment

  • Trying to capture high volume of traffics.

 

Cause

Tcpdump client application is too busy to communicate with TMM. 

Bug ID 1099529 was previously opened to diagnose this error further. However, Bug ID 1099529 was finally closed as F.A.D (Functioning As Designed). In other words, it is product limitation. K6546 states as follows.

Important: The BIG-IP system is designed as an application delivery network platform and not as a packet capture device. If you intend to capture traffic under high load conditions, F5 recommends that you mirror traffic to a dedicated sniffing device.

 

Recommended Actions

There are some possible options that can help tcpdump not to exit with aforementioned error.

  • Adjust tcpdump filter string so as not to capture much traffic.
  • Use "tmm.tcpdump.pkt.ratelimit" db key to rate-limit number of pkts to be sent to tcpdump application. Refer to Bug ID 1492681.

Note: But even if any of the above options is applied, depending on the traffic volume and/or BIG-IP system performance, tcpdump may still exit with aforementioned error. As described on K6546, the bottom line is that BIG-IP is not designed as a packet capturing device and BIG-IP tcpdump is considered as 'best effort'. Consider capturing packets off the BIG-IP box if high volume of traffic needs to be captured and analyzed.
