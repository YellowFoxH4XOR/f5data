K000160885: After adding/deleting virtual server on LTM device object, other virtual servers on the same LTM device object changed its status from "available/disabled" to "offline/disabled".

Type
Support Solution
Published
2026-04-20
Updated
2026-04-20
Applies to
  • BIG-IP
  • BIG-IP DNS: 21.0.0, 17.5.1, 17.1.3
Source
https://my.f5.com/manage/s/article/K000160885

Description

On DNS device, after modifying a virtual server configuration of LTM device object, other/unrelated virtual servers on the same LTM device object may change its status from "available/disabled" to "offline/disabled" with an error "no reply from big3d: timed out". This problem can happen under limited condition.

Here is an example of how removing one virtual server from LTM device object affects other/remaining disabled virtual servers. On this example, LTM device object has three virtual servers "vs1", "vs2", and "vs3". Two virtual servers "vs1" and "vs2" are manually disabled. And we are going to delete "vs3" from bigipLTM device object, which is monitored by DNS system through bigip type monitor. Note that here DNS system does not directly monitor LTM virtual servers by its own monitor. DNS system acquires virtual server status from remote big3d running on remote LTM device via iquery communication.

 

gtm server /Common/bigipltm {
    datacenter /Common/MYDC
    devices {
        bigipltm {
            addresses {
                10.1.1.190 { }
            }
        }
    }
    monitor /Common/bigip
    product bigip
    virtual-servers {
        vs1 {
            destination 10.1.1.191:80
            disabled
        }
        vs2 {
            destination 10.1.1.192:80
            disabled
        }
        vs3 {
            destination 10.1.1.193:80
        }
    }
}

Starting from above condition, delete one virtual server "vs3" on LTM device object.

root@(bigipdns)(cfg-sync Standalone)(Active)(/Common)(tmos)# modify gtm server bigipltm virtual-servers delete { vs3 }

 

After delete "vs3", other two virtual servers, "vs1" and "vs2", change its status from "available/disabled" status to "offline/disabled" status. Error message "no reply from big3d: timed out:" is recorded despite there is no iQuery communication problem between DNS system and remote LTM system.

Environment

All of the following conditions need to be met.

 

  • DNS system manages remote LTM device and its virtual servers.
  • DNS system acquires LTM virtual server monitor status from big3d running on remote LTM device via iQuery. 
  • On DNS system, there are disabled virtual servers on LTM device object.
  • "Monitor Disabled Object" parameter under "DNS >> Settings : GSLB : General" is unchecked (default).
  • On DNS system, add/delete virtual server on LTM device object.

 

Cause

Bug ID2258929.

 

Answer/Recommended Actions

To rescue affected virtual servers, you can temporarily assign any monitor to virtual server objects and can remove it. After this change, affected virtual server will get back to "available/disabled" status.

# tmsh modify gtm server bigipltm virtual-servers modify { vs1 { monitor gateway_icmp } vs2 { monitor gateway_icmp } }
# tmsh modify gtm server bigipltm virtual-servers modify { vs1 { monitor none } vs2 { monitor none } }
# tmsh save /sys config gtm-only

 

Alternatively, to rescue affected virtual servers, you can just restart gtmd.

# tmsh restart /sys service gtmd

Important: Restarting gtmd will briefly interrupt the established iQuery connections with remote DNS system or LTM system. Restarting gtmd can also affect GSLB name resolution shortly.

 

To prevent this problem from recurring, change "gtm global-settings general monitor-disabled-objects" parameter to "yes" (default "no"). 

# tmsh modify gtm global-settings general monitor-disabled-objects yes
# tmsh save sys config gtm-only

 

On GUI, you can find "Monitor Disabled Object" parameter under "DNS >> Settings : GSLB : General".
