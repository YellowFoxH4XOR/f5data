K55500484: [F5OS-C] Velos Major network failure for multiple tenants

Published

Applies to

  • F5OS

Source

Description

Major impact to BIG-IP tenant virtual server traffic.
PoolMember health monitors fluctuate up and down, or remain down. LACP LAGs may go down.
The LACP daemon will be unable to transmit its PDUs.

/var/F5/partition<n>/log/velos.log contains messages similar to below logs at the time the problem started:

blade-$(p$) dma-agent[10]: priority="Alert" version=1.0 msgid=0x4201000000000129 msg="Health monitor detected DM Tx Action Completion ring hung." ATSE=0 DM=2 OQS=3.
blade-$(p$) dma-agent[10]: priority="Info" version=1.0 msgid=0x4201000000000135 msg="Health monitor DM register dump requested.".
blade-$(p$) dma-agent[10]: priority="Info" version=1.0 msgid=0x4201000000000137 msg="Health monitor DM register dump complete." FILE="agent-dump-1666310215.txt".

 

Environment

  • F5OS-C
  • v1.3.x and 1.5.0
  • Velos
  • Network instability
  • L7 mirroring enabled

Cause

  • Bug alias 1128765: Under investigation

Recommended Actions

Reducing the use of connection mirroring, especially for standard virtual servers, should reduce the likelihood of encountering this issue.
  1. To recover a device, determine which blade is affected by looking at the start the following dma-agent log message in /var/F5/partition<n>/log/velos.log:

      blade-1(p1) dma-agent[10]: priority="Alert" version=1.0 msgid=0x4201000000000129 msg="Health monitor detected DM Tx Action Completion ring hung." ATSE=0 DM=2 OQS=3.
      This example log tells it is occuring in slot 1
     
  2. Then, reboot the blade. This will shut down all tenant instances on the blade. Once the blade boots up, the tenants should run and pass traffic normally.
  3. If the blade cannot be rebooted immediately, it may be possible to mitigate the problem for a multi-slot tenant by disabling the impacted slot to steer traffic to the remaining slots that are still healthy:
    e.g. An example of disabling BIG-IP tenant slot 1
    tmsh modify sys cluster default members { 1 { disabled } }
 

Additional Information

When this issue is hitting the unit, In the BIG-IP tenant, the tmctl sep_stats table shows high counts for tx_send_drops2 or tx_send_drops3 (over 10,000).
