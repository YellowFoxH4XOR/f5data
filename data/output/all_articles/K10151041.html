K10151041: TCP Window Scaling on BIG-IP

Published
2021-10-20
Updated
2025-09-09
Applies to
  • BIG-IP
Source

Description

TCP Window Scaling was introduced in RFC 1072 and refined in RFC 1323. Essentially, window scaling simply extends the 16-bit window field to 32 bits in length. However, engineers could not simply insert an extra 16 bits into the TCP header as this will render it completely incompatible with existing implementations. The solution was to define a TCP option that specifies by how much the initial TCP Window field should be bitwise shifted to produce a larger value.

Beginning in BIG-IP 11.4.0, the window scale functionality is built into the TCP profile and cannot be manually disabled or enabled. The functionality will be negotiated if the send or receive buffer is larger than 65535 bytes. See K13924148: Overview of the TCP profile (11.x) for more details on the TCP profile option.

Environment

  • All Big-IP versions from 11.4.0 onwards
  • Any Virtual Server that uses a TCP profile.

Cause

None

Recommended Actions

The following steps can be used to determine and adjust the send or receive buffer settings for custom TCP profiles for performance tuning.

1. Determine the initial TCP window size sent by a client in the SYN packet.

  • Use tcpdump to capture client traffic to a binary file.
  • Open the packet capture in WireShark and filter for incoming SYN packets from clients. The filter in wireshark can be used: tcp.flags.syn == 1
  • Expand the TCP section in WireShark and note the window size sent in by the client.
Window size value: 29200
  • Expand the TCP section in WireShark and then expand the options table. Locate the TCP window scale option and note the shift count.

TCP Option - Window scale: 7 (multiply by 128)
    Kind: Window Scale (3)
    Length: 3
    Shift count: 7
    [Multiplier: 128]
  • A shift count of one shifts the binary value of the field to left by one bit, doubling it. A count of two shifts the value two places to the left, quadrupling it. A count of seven (as shown in the example above) multiplies the value by 128.
  • So we can now multiply the initial TCP window size by the window scale shift count to see the largest TCP window size that the client can support. In the example above this is 29200 * 128 = 3737600 bytes
  1. Once an appropriate value has been determine then update the relevant TCP profile with the calculated value. See K13924148: Overview of the TCP profile (11.x) for further details.


Note: It is very rare that a client's window size would actually go over 2 or 3 shift counts.  Shift counts of 1 or 2 would typically cover most scenarios.
Moreover, the initial window size may vary from client to client so multiple client connections should be checked to get a more wide ranging value.

Important: Increasing the send and receive buffers also increase the memory usage of individual TCP connections where that TCP profile applies, hence these values should not be set to extreme values, i.e setting to 3737600 for a production system is likely to cause memory constraints.
