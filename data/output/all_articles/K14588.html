Known Issue

TMM may stop responding when using a Rate Class with a virtual server.

This issue occurs when all of the following conditions are met:

  • An FTP or RTSP virtual server is configured.
  • A Rate Class is associated with the virtual server.
  • The virtual server processes traffic.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H425810 on the Diagnostics > Identified > Medium screen.
  • Connections may hang or drop.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system reports error messages similar to the following example to any of the /var/log/daemon* files.

    emerg logger: Re-starting tmm

Workaround

There is no workaround. However, to alleviate the issue, you can disassociate the Rate Class from the affected virtual server. To do so, perform the following procedure:

Remove a rate class from a virtual server

Impact of workaround: The virtual server will no longer enforce the throughput policy.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Virtual Server List.
  5. Click the affected virtual server.
  6. In the Configuration box, select Advanced.
  7. In the Rate Class box, select None.
  8. Click Update.
