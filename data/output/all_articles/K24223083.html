Known Issue

F5 SSL Orchestrator may fail to indicate that existing deployed applications need to be re-deployed after an upgrade. Additionally, the Deploy button is disabled for existing deployed applications after the upgrade. The Deploy button should be enabled for existing deployed applications, even if there is no change in their configuration.

This issue occurs when all of the following conditions are met:

  • You have an existing deployed application configured on SSL Orchestrator 14.1.0-5.0.
  • You then upgrade SSL Orchestrator to 14.1.0-5.1.

SSL Orchestrator does not automatically re-deploy existing applications after an upgrade. You must manually re-deploy them after the upgrade. If you do not re-deploy the existing applications, they continue to use the templates from previous version. Only applications deployed after the upgrade use the templates from the upgraded version.

Impact

The existing deployed applications do not use the features or fixes from the upgraded version.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system does not indicate that the existing deployed applications need to be re-deployed after an upgrade.

Workaround

To work around this issue, you can click Save Draft for the existing deployed applications and then click Deploy so that the system re-deploys the application using the template from the upgraded version. Clicking Save Draft re-enables the Deploy button for an existing deployed application, even if there is no configuration change. To do so, perform the following procedure:

Impact of procedure: Performing this procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to SSL Orchestrator > Configuration.
  3. On the Topologies tab, click the name of the existing deployed application.
  4. Click Save Draft; this re-enables the Deploy button.
  5. Click Deploy.
