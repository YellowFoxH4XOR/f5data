Issue

The naming convention used in RFC 2317 separates the network address and mask from the reverse lookup subnet by using a forward slash (/).

NameSurfer uses the name of the zone as the name of the zone file when it inserts the zone definition into /etc/named.conf file. This means that named attempts to create a file that contains a forward slash the first time it initiates a zone transfer from NameSurfer, which results in the following error:

failed to load temporary file

By design, the 3-DNS Controller's file system does not support using slashes in file names. Using slashes will cause the operating system to interpret the portion before the forward slash as a directory and the portion after the forward slash as the file name.

In section 4, RFC 2317 specifically warns of the potential adverse behavior that can be caused by using forward slashes and suggests using a different character.

To avoid this issue, do not use the forward slash in the zone name. Instead, use a hyphen (-) or some another character that does not have special meaning to the file system.
