Topic

You should consider using this procedure under the following condition:

  • You use BIG-IP ASM Live Updates/Attack Signatures to update Browser Challenges.
  • You want the Browser Challenge updates to be effective immediately.

Description

When updating Browser Challenges through Live Updates or Attack Signatures Updates, the contents of the Browser Challenges file are applied 48 hours after installation of the file. In some cases, instant Browser Challenges updates are useful to solve urgent issues. This article describes the procedure to immediately apply Browser Challenge updates with the provided Bash script.

Note: The provided datasync_update_file_apply_date script is supported in BIG-IP 13.1.0.6 and later. You can run it on a Linux system with administrative access to the target BIG-IP system. The following procedure demonstrates running the script on a local BIG-IP system.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP ASM system.

Procedures

  • Applying the datasync update script on BIG-IP standalone systems
  • Applying the datasync update script on a BIG-IP high availability (HA) system

Applying the datasync update script on BIG-IP standalone systems

You can apply the browser challenge update immediately by running the provided datasync update script. To do so, perform the following procedure:

Impact of procedure: Running the datasync update script causes system offline for a short time. F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments. 

  1. Perform a manual update to ensure that the ASM Browser Challenge components are up-to-date. For more information about Live Updates and Attack Signatures Updates, refer to the following articles:

    K82512024: Managing BIG-IP ASM Live Updates (14.1.x and later)
    K8217: Managing BIG-IP ASM attack signatures (11.5.x - 14.0.x)

    Note: If you have more than one standalone systems in the same network need to apply the immediate update, make sure to perform the manual update on all of them before proceeding the following.

  2. Wait 60 seconds for datasyncd process to read the update file.
  3. Download the Bash script to your local system.
  4. Use an SCP client to copy the script file to the /var/tmp directory of the BIG-IP system.

    Note: For information about uploading files to an F5 system, refer to: K175: Transferring files to or from an F5 system.

  5. Log in to the BIG-IP command line.
  6. To change the directories to the script located directory, enter the following command:

    cd /var/tmp

  7. To rename the file and set the file permissions, enter the following command:

    mv datasync_update_file_apply_date.txt datasync_update_file_apply_date && chmod 755 datasync_update_file_apply_date

  8. To retrieve the required date argument for the script, enter the following command:

    date -u +%Y%m%d_%H%M%S -d '-3 days'

  9. To run the datasync_update_file_apply_date Bash script, use the following command syntax:

    ./datasync_update_file_apply_date <IP> <USER> <PASS> <DATE>

    Note: In this command syntax, note the following:
    <IP> is the BIG-IP device management IP.
    <USER> and <PASS> are the administrative user credential.
    <DATE> is the date on which the update should be applied. To apply the update immediately, set the date to 3 days earlier than the current system date with the provided command in step 8.

    For example:

    ./datasync_update_file_apply_date 10.10.10.1 admin example_password 20200720_000000

  10. The system goes offline after running the update script and returns to an online state shortly thereafter after the browser challenge update is effective.
  11. If you have more than one standalone system in the same network on which you need to apply the update, repeat step 9 with the IP address and administrative credentials from the target BIG-IP system. You should reuse the date information retrieved from the first device, so the update timestamps are the consistence across your environment.

Applying the datasync update script on a BIG-IP high availability (HA) system

To apply the browser challenge update immediately on a BIG-IP HA system, you can run the provided datasync update script on the standby member of the device group and perform a manual failover and a synchronization of the datasync-global-dg device group. To do so, perform the following procedure:

Impact of procedure: Running the datasync update script causes the system to go offline for a short time. You should performed the procedure on the standby device. You perform manual failover in this procedure to minimize the service impact; however, a brief traffic interruption may occur during the failover action. F5 recommends that you schedule this procedure during a maintenance window.

  1. On the standby device, perform a manual update to ensure that the ASM Browser Challenge components are up-to-date. For more information about Live Updates and Attack Signatures Updates, refer to the following articles:

    K82512024: Managing BIG-IP ASM Live Updates (14.1.x and later)
    K8217: Managing BIG-IP ASM attack signatures (11.5.x - 14.0.x)

  2. Wait 60 seconds for datasyncd process to read the update file.
  3. Download the Bash script to your local system.
  4. Use an SCP client to copy the script file to the /var/tmp directory of the standby BIG-IP system.

    Note: For information about uploading files to an F5 system, refer to: K175: Transferring files to or from an F5 system.

  5. Log in to the BIG-IP command line of the standby device.
  6. To change the directories to the script located directory, enter the following command:

    cd /var/tmp

  7. To rename the file and set the file permissions, enter the following command:

    mv datasync_update_file_apply_date.txt datasync_update_file_apply_date && chmod 755 datasync_update_file_apply_date

  8. to run the datasync_update_file_apply_date Bash script, use the following command syntax:

    ./datasync_update_file_apply_date <IP> <USER> <PASS> <DATE>

    Note: In this command syntax, note the following:
    <IP> is the BIG-IP device management IP.
    <USER> and <PASS> are the administrative user credential.
    <DATE> is the date on which the update should be applied. To apply the update immediately, set the date to 3 days earlier than the current system date.

    For example:

    ./datasync_update_file_apply_date 10.10.10.1 admin example_password `date -u +%Y%m%d_%H%M%S -d '-3 days'`

  9. The system goes offline after running the update script and returns to an online state and returns to an online state shortly thereafter after the browser challenge update is effective.
  10. Optionally, perform a manual failover to make the script updated device as an active member of the device group.
  11. Log in to the Configuration utility of the script updated device.
  12. Go to Device Management > Overview.
  13. Under Device Groups, select datasync-global-dg.
  14. Under Devices, select the device you have applied the datasync update script (Self).
  15. Under Sync Options, select Push the selected device configuration to the group.
  16. Select Sync.
  17. The peer devices goes offline for a short time during the datasync-global-dg device group synchronization and shortly thereafter returns to an online state after the synchronization is completed.

    Note: The datasync_update_file_apply_date script only needs to be applied on one device in the device group. The updates on the peer devices are applied through the datasync-global-dg device group synchronization. For more information about datasync-global-dg device group, refer to: K16509: Overview of the datasync-global-dg device group.
