Known Issue

Under certain conditions, BIG-IP LTM can cause monitor failures when VLAN failsafe is triggered.

This issue occurs when all of the following conditions are met:

  • The BIG-IP LTM VLAN failsafe detects a VLAN as unavailable
  • The BIG-IP LTM initiates a count down timer for the failed VLAN condition
  • The BIG-IP will actively attempt to generate network communication at 50 percent of the timeout value
  • As part of the recovery attempt, the BIG-IP LTM will clear the local TMM neighbor table of the TMM that has detected a VLAN failsafe condition
  • Should the VLAN state recover prior to the timeout expiration, VLAN failsafe will abort the VLAN failure count down

As a result, TMM daemons running on the BIG-IP LTM neighbor tables can fall out of synchronization. The inconsistent TMM neighbor tables can cause the TMM daemon monitor attempts to fail. Typically, this issue will clear once the all TMMs expire and refresh their neighbor tables (which occurs approximately every four to six minutes).

Impact

  • The BIG-IP LTM can report available members as unavailable
  • Load balanced resources may become unavailable

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When the BIG-IP system reports members or nodes as unavailable, messages are logged to the /var/log/ltm file. The messages appear similar to the following example:

    notice mcpd[2964]: 01070640:5: Node <ServerIP> monitor status down
  • When a health monitor marks all members of a pool down, messages are logged to the /var/log/ltm file. The messages appear similar to the following example:

    tmm err tmm[4779]: 01010028:3: No members available for pool <Pool_name>
  • Log messages indicate that VLAN failsafe has been triggered prior to members being marked as unavailable.
  • Devices remain in the unavailable state for up to six minutes and then begin to be reported as available.

Workaround

To recover from this issue, you can clear individual ARP entries from the TMM ARP cache. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To clear individual ARP entries, type the following command:

    delete net arp <ip address of impacted member>

    For example:

    delete net arp 192.168.0.100

    Note: You can clear the entire TMM ARP cache by typing the delete net arp all command.
