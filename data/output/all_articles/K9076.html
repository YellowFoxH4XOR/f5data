K9076: Network failover traffic fails after the TM.PreserveClientPort BigDB key is set to disable

Known Issue

This is the result of a known issue. The TM.PreserveClientPort BigDB variable determines whether the BIG-IP system preserves the client's ephemeral port when connecting to the server. By default, the TM.PreserveClientPort BigDB variable is set to enable, and the BIG-IP system attempts to preserve the client's source port. When TM.PreserveClientPort is set to disable, network failover traffic may be dropped by the redundant peer system. If the source port is changed, the peer will drop the traffic.

Note: For information about the network failover transport protocol, refer to K9057: Overview of the BIG-IP LTM network failover transport protocol.

F5 Product Development is tracking this issue as CR104425.

This issue does not affect the 9.3.x, 9.6.x, and 10.x software branches.

Workaround

If the functionality provided by setting TM.PreserveClientPort to disable is absolutely required in conjunction with network failover, you can work around this issue by configuring the management port address as the failover address. The management interface is owned by the Linux host, hence traffic is not affected by the change. To configure the failover address, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. Click Network Failover.
  5. Replace the exisiting Network Failover addresses with the management port address of the peer system.

Note: For more information, refer to the BIG-IP Network and System Management Guide.
