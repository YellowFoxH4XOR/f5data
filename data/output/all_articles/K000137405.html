Cause

This can be caused by instability in the network environment.

Most common data paths look like:

Client ---- internet --- APM --- intranet ---- internal servers


Internet traffic may lose packets sometimes and hence connection may reset.

For the APM network access, like the OSI model, the data model is:

Application data: The application data like HTTP, DNS, FTP ICMP etc, it is the data between client and internal servers.
TCP:: The data was segmented, application data is the payload.
IP:: The TCP segment is the payload.
PPP:: The IP frame is the payload for the PPP frame.
TLS/SSL:: The PPP frame is the payload for the TLS session.
TCP:: The TLS data is the payload.
IP:: The TCP segment was encapsulated by IP.
Ethernet:: IP on the layer 2
Physical connection::  the bit on the wire.

Errors are then seen under such a scenario since the internet connection is unstable.

Recommended Actions

Normally, this error count can be ignored since TCP protocol itself initiates re-transmissions.
Most client/server have the mechanism to reconnect when connections are reset to make sure the data is delivered.
