Cryptographic failures

Attackers often target sensitive data, such as passwords, credit card numbers, and personal information, when you do not properly protect them. Cryptographic failure is the root cause for sensitive data exposure. According to the Open Web Application Security Project (OWASP) 2021, securing your data against cryptographic failures has become more important than ever.

A cryptographic failure flaw can occur when you do the following:

  • Store or transit data in clear text (most common)
  • Protect data with an old or weak encryption
  • Improperly filter or mask data in transit

Cryptographic failure attack scenario

In the following attack scenario an attacker uses a rainbow table to crack unsalted password hashes in a database.

  1. The attacker gains access to an organization's network.
  2. The attacker uses an application flaw to retrieve a password database.
  3. Since the database used unsalted hashes to encrypt passwords, the attacker can use a rainbow table to expose the passwords.
  4. The attacker uses credential stuffing tools to test credential pairs on other websites.

The system applies an additional layer of protection by encrypting passwords and passphrases that it stores in the configuration. The Secure Vault feature uses the following two cryptographic keys to protect data while it is at rest:
    • The master key is a symmetric AES128CBC key that performs password and passphrase encryption and decryption.
    • The unit key is a is a symmetric AES256CBC key that performs master key encryption and decryption.

Secure your applications against cryptographic failures with F5 products

The cryptographic protocol Secure Sockets Layer (SSL) is becoming the de-facto protocol to secure your application data on transit. Configuring SSL is not simply configuring a cipher or setting a single SSL profile. It involves implementing an SSL everywhere architecture covering from client devices through to your application servers. Review the following resources to implement SSL everywhere to secure and optimize your inbound traffic before it reaches your web servers.

  • The F5 SSL Reference Architecture white paper.

Using BIG-IP LTM to mitigate cryptographic failures

The following table lists BIG-IP LTM protections that mitigate cryptographic failures and describe how to configure them.

Table 2.2 BIG-IP LTM controls that protect against cryptographic failures
BIG-IP LTM protectionRecommendationsResource
SSL profilesProtect client-side and server-side communication using TLS with strong cipher and secure key exchange by assigning client SSL and server SSL profiles to your virtual servers.
  • When you have a BIG-IP LTM full-proxy architecture and you want a high level of security, you can implement SSL bridging. With SSL bridging, you configure both client and server SSL profiles in the virtual server settings, so the system re-encrypts data before it leaves the BIG-IP system.
  • Enhance SSL transactions by fine-tuning cipher strings in your SSL profiles to ensure the system uses an encryption algorithm supported by perfect forward secrecy (PFS) during SSL/TLS negotiation, such as Elliptic Curve Diffie-Hellman Exchange (ECDHE).
  • K14783: Overview of the Client SSL profile (11.x - 15.x)
  • K14806: Overview of the Server SSL profile (11.x - 15.x)
  • K01770517: Configuring the cipher strength for SSL profiles (14.x)
  • The SSL Traffic Management chapter of the BIG-IP System: SSL Administration manual.
HTTP Strict Transport Security (HSTS)Consider using HTTP Strict Transport Security (HSTS) for your virtual server
  • HSTS is an HTTP security enhancement defined in Request for Comments (RFC) 6797. When you implement HSTS, it forces all communications through HTTPS to ensure all web browsing is secure. HSTS is one of the directives that OWASP suggests to prevent sensitive data exposure.

    Important: F5 recommends that you consult with your security team before implementing HSTS to ensure that it aligns with your information security policy guidelines.
  • iRules command controls in F5 Cloud Docs.
  • K68657325: How to enforce HTTP Strict Transport Security (HSTS) on a virtual server

  • Enable the Predictable Resource Location attack signature to detect attempts to access known sensitive resources on a web application host system.
  • Enable the Information Leakage attack signature to detect attempts to retrieve sensitive information that should not be accessible by design. This attack type is also known as Information Disclosure.
