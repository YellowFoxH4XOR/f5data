Known Issue

This is the result of a known issue. The BIG-IP GTM system does not pick a new pool member when a pool is selected by an iRule in response to an LB_SELECTED event.

In the context of BIG-IP GTM iRules, the LB_SELECTED event is a valid event for the pool command. Executing the pool command in response to an LB_SELECTED event causes the BIG-IP GTM system to select a new pool or pool member after an initial load balancing decision was already made. In some cases, evaluating the initial load balancing decision made by the BIG-IP GTM system, and then forcing a new selection, may allow a BIG-IP administrator to define custom load balancing algorithms.

Note: The feature described in this Solution is generally not required and intended for expert users only. The BIG-IP GTM system provides out of the box load balancing algorithms that fit almost all scenarios.

The syntax of the pool iRule command is described below:

pool <pool_name>

Specifies the pool that you want to use to answer the DNS request.

pool <pool_name> [member <addr> <port>]

Specifies the pool member that you want to directly use to answer the DNS request.

The pool <pool_name> [member <addr> <port>] syntax works as expected; however, the pool <pool_name> syntax does not. When the pool <pool_name> syntax is used, the BIG-IP GTM system does not pick a new pool member from the specified pool.

F5 Product Development tracked this issue as CR132858, and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP 10.1.0, and Hotfix-BIGIP-9.4.8-407.0-HF4 issued for BIG-IP 9.4.8. You may download the hotfixes or later versions of the hotfixes from the F5 Downloads site.
