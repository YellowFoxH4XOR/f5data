K000153187: High CPU utilization when browsing Firewall Rules

Description

Searching firewall rules in the BIG-IP AFM GUI can result in control plane CPU utilization spiking to 90-100%, causing slow response, timeouts, or GUI disconnects. This occurs when the Inline Rule Editor is disabled. During these events, tomcat (java) and mysqld processes show high CPU usage. The issue is reproducible on both active and standby devices and does not affect data plane traffic. Restarting tomcat restores GUI access temporarily, but does not resolve the underlying problem.

Environment

  • Product: BIG-IP AFM
  • Version: 17.1.1 (and earlier)
  • Platforms: F5-BIG-LTM-I2600, C117; also tested on i2800
  • Configuration:
    • Large number of firewall-related configuration objects like policies, address-lists, port-lists 
    • Inline Rule Editor disabled
    • Issue triggered during rule search operations in the GUI

Cause

Disabling the Inline Rule Editor leads to inefficient processing when searching firewall rules with large policies and object lists. The java process (tomcat) consumes excessive CPU resources as it renders and searches rule lists without optimization provided by the Inline Rule Editor. This behavior stems from legacy software defects that were mitigated by introducing the Inline Rule Editor feature.

 

Recommendations

  • Enable the Inline Rule Editor in AFM GUI for efficient rule search operations:
    • Go to Security > Network Firewall > Policies and enable Inline Rule Editor.
  • Remove unused/inactive policies or objects to reduce system load.
  • Confirm management provisioning is sized appropriately for your configuration.
  • If needed, increase memory allocation for tomcat/restjavad processes; however, enabling Inline Rule Editor is the primary solution.
  • Restarting tomcat may restore GUI responsiveness temporarily but does not fix root cause.
  • No impact expected on data plane traffic; issue affects only control plane/GUI.
