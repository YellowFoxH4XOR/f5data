Description
A GTM/DNS BIG-IP, which is attempting to establish iQuery connectivity to a LTM BIG-IP, will send SYN packets that look to be ignored by the LTM BIG-IP.  This behavior may be seen following an LTM upgrade from a version prior to 14.0.0 to a version 14.1.0 and higher.

  • Port 22 (SSH) connections use the Auto Lasthop feature to send traffic to the MAC address of the self IP address on the TMM interface, which received the incoming SYN packet
  • Port 4353 (iQuery) connections do not use auto lasthop (14.1.0 and later), so the LTM looks at the routing table to send the SYN,ACK back.
When you run a tcpdump on the LTM, the LTM seems to ignore the GTM's TCP SYN. 
# tcpdump -nni 0.0 port 4353 and host 10.10.10.1
tcpdump: verbose output suppressed, use -v or -vv for full protocol decode
listening on 0.0, link-type EN10MB (Ethernet), capture size 65535 bytes
01:08:10.378262 IP 10.10.10.1.55530 > 192.168.10.1.4353: Flags [S], seq 4108387312, win 29200, options [mss 1460,sackOK,TS val 4223154104 ecr 0,nop,wscale 3], length 0 in slot1/tmm0 lis=
01:08:12.377812 IP 10.10.10.1.55530 > 192.168.10.1.4353: Flags [S], seq 4108387312, win 29200, options [mss 1460,sackOK,TS val 4223156110 ecr 0,nop,wscale 3], length 0 in slot1/tmm0 lis=

As illustrated above, the GTM (10.10.10.1) sends the TCP SYN to LTM, without auto lasthop function, LTM looks at its routing table but does not have a TMM route to return the traffic back to 10.10.10.1, so LTM finds the default route in the management routing table and sends the SYN,ACK out from the management interface instead.
 

Environment

  • BIG-IP VE 14.1.0 and later
  • iQuery connection to Self IP address on TMM interface
  • No TMM routes configured for the source of the traffic

Cause
The Auto Lasthop functionality does not apply to all ports on TMM interfaces (for example, iQuery port 4353 will not use the Auto Lasthop function and requires a  route to the client).

Recommended Actions
Add the necessary static route(s) to the BIG-IP configuration.  For information on adding static routes on the BIG-IP, refer to: K13833: Managing static routes in BIG-IP and BIG-IQ
