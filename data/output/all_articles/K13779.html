Known Issue

The HTTP::cookie remove command fails to remove the entire cookie when certain attributes exist. This issue occurs when all of the following conditions are met:

  • An HTTP virtual server is configured with an iRule that uses the HTTP::cookie remove command
  • The HTTP request or response has a cookie that is to be removed by the iRule command
  • The cookie to be removed contains one or more of the following attributes:
     
    • Expires (uppercase E)
    • max-age (lowercase m and a)
    • httponly (lowercase h and o)

The HTTP cookie header is widely used by HTTP clients and servers to maintain a stateful session over HTTP protocol. The header may contain attributes, such as Expires, Max-Age, Domain, Path, Secure, and HttpOnly. For more information about the HTTP cookie header, refer to RFC6265: HTTP State Management Mechanism
Note: The previous link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Impact

Depending on the HTTP client or server, this behavior may result in errors on the HTTP client or server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After the iRule performs the cookie removal for an HTTP request that matches these conditions, the cookie name is removed from the HTTP header, but the cookie attribute remains.

    For example, an HTTP request contains the following cookie in the HTTP header:

    Cookie: bug386763=abc123;httponly

    After the iRule performs the cookie removal, the HTTP request contains the following cookie in the HTTP header:

    Cookie: httponly

  • After the iRule performs the cookie removal for an HTTP response that matches these conditions, the cookie name is removed from the HTTP header, but the cookie attribute remains.

    For example, an HTTP request contains the following cookie in the HTTP header:

    Set-Cookie: bug386763=abc123; expires=Fri, 27 Jul 2012 16:40:20; Path=/; httponly

    After the iRule performs the cookie removal, the HTTP response contains the following cookie in the HTTP header:

    Set-Cookie: httponly

Workaround

To completely remove the HTTP cookie header field, you may use an iRule snippet similar to the following example to parse and remove the desired HTTP cookie by using the appropriate events and HTTP cookie:

Impact of workaround: Due to TMM memory allocation limitation described in K6578: TMM stops responding if an iRule collects too much data, you must ensure the payload does not exceed the data size described in SOL6578.

Note: The following iRule may not apply to all environments. F5 recommends authoring an iRule that may work best for your application environment. F5 recommends testing any such changes in an appropriate environment.

when <CLIENT_ACCEPTED | SERVER_CONNECTED> {
  TCP::collect
}
when <CLIENT_DATA | SERVER_DATA> {
  set oldpayload [TCP::payload]
  if {[set removecookiestart [string first -nocase "<Cookie | Set-Cookie>: <cookie name>" [TCP::payload]]] != -1 }{
    set removecookieend [string first "\n" [TCP::payload] $removecookiestart]
    set newpayload [string replace $oldpayload $removecookiestart $removecookieend ""]
    TCP::payload replace 0 [TCP::payload length] ""
    TCP::payload replace 0 0 $newpayload
  }
  TCP::release
}

For example, the following iRule snippet parses and removes the Set-Cookie header for cookie name bug386763 from the origin web server:

when SERVER_CONNECTED {
  TCP::collect
}
when SERVER_DATA {
  set oldpayload [TCP::payload]
  if {[set removecookiestart [string first -nocase "Set-Cookie: bug386763" [TCP::payload]]] != -1 }{
    set removecookieend [string first "\n" [TCP::payload] $removecookiestart]
    set newpayload [string replace $oldpayload $removecookiestart $removecookieend ""]
    TCP::payload replace 0 [TCP::payload length] ""
    TCP::payload replace 0 0 $newpayload
  }
  TCP::release
}

Note: For more information about the iRule objects, arguments, and events used in the previous example rules, such as CLIENT_ACCEPTED, Set-Cookie, or SERVER_DATA, refer to devcentral.f5.com. A DevCentral login is required to access this content.
