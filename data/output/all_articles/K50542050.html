Known Issue

The mcpd process may restart and produce a core file when you use Traffic Management Shell (tmsh) batch mode transactions.

This issue occurs when the following condition is met:

  • When using a single tmsh batch mode transaction, you attempt to create a VLAN before creating a route domain.

    For example:

    echo "create cli transaction; create /net vlan v_3 interfaces add {1.1 {tagged}};create /net route-domain 1 vlans add {v_1 v_2}; submit cli transaction" | tmsh

Impact

The BIG-IP system, if configured as part of a high-availability system, may temporarily fail to process traffic and fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the tmsh utility, you may notice an error message similiar to the following example:

    transaction failed: The connection to mcpd has been lost, try again.
    Batch mode transaction is active, it will be lost, quit anyway? (y/n)
    Jan 29 15:37:00 ptt-vadc-1 emerg logger: Re-starting lind
    Jan 29 15:37:01 ptt-vadc-1 emerg logger: Re-starting mcpd
  • You notice a core file for the mcpd service in the /shared/core directory, similar to the following example:

    mcpd.bld0.0.110.core.gz
  • The BIG-IP system may fail over if configured as part of a high-availability system.

Workaround

To work around this issue, you can change the order of commands in the tmsh batch mode. For example, you can create a route domain before creating a VLAN or before the tunnel groups configuration.

None
