K6801: BIG-IP does not initialize after upgrade if the primary or secondary failover address is configured to use the MGMT interface

Known Issue

This is the result of a known issue. The BIG-IP system will fail to initialize after upgrading from versions 9.1.1 and earlier to versions 9.1.2 or 9.2 and later if the BIG-IP system is configured to use the management IP address as the primary or secondary failover address.

The following symptoms display when the BIG-IP system fails to initialize after the upgrade:

  • The BIG-IP system is unreachable through its non-management interfaces
  • When connected to the system through the serial console or SSH to the management IP address, the following message displays:

    Waiting for system initialization to complete. Enter <CR> for prompt

The BIG-IP system fails to initialize due to a change of behavior introduced in BIG-IP versions 9.1.2 and 9.2. The management IP address is no longer a valid address to use as the primary or secondary failover addresses. For information about the change of behavior, refer to K6800: Change in Behavior: Primary and secondary failover addresses can no longer be configured to use the management IP address.

F5 Networks Product Development tracked this issue as CR56968 and CR51503 and it was fixed in BIG-IP version 9.1.2 and 9.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, you can configure the BIG-IP system to initialize after the upgrade by using a non-management self IP address for the primary and secondary failover addresses. To configure the BIG-IP system to initialize after the upgrade, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. Type the non-management self IP address to be used as the primary failover address for this BIG-IP system in the Self field.
  5. Type the non-management self IP address to be used as the primary failover address for the peer BIG-IP system in the Peer field.
  6. If desired, type the non-management self IP address to be used as the secondary failover address for this BIG-IP system in the Self field.
  7. If desired, type the non-management self IP address to be used as the secondary failover address for the peer BIG-IP in the Peer field.
  8. Click the Update button.

Repeat this procedure on the peer BIG-IP system.

Recovering from the BIG-IP system failing to initialize after upgrade

To recover from the BIG-IP system failing to initialize after the upgrade, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Press Enter to continue past the following message:

    Waiting for system initialization to complete message.

  3. Reset the current primary and secondary failover addresses by typing the following commands:

    bigpipe db StateMirror.Ipaddr reset
    bigpipe db StateMirror.PeerIpaddr reset
    bigpipe db StateMirror.Secondary.Ipaddr reset
    bigpipe db StateMirror.Secondary.PeerIpaddr reset

  4. Restart the BIG-IP system by typing the following command:

    bigstart restart

  5. Log in to the Configuration utility.
  6. Click System.
  7. Click High Availability.
  8. Type the non-management self IP address to be used as the primary failover address for this BIG-IP system in the Self field.
  9. Type the non-management self IP address to be used as the primary failover address for the peer BIG-IP in the Peer field.
  10. If desired, type the non-management self IP address to be used as the secondary failover address for this BIG-IP system in the Self field.
  11. If desired, type the non-management self IP address to be used as the secondary failover address for the peer BIG-IP system in the Peer field.
  12. Click the Update button.

Repeat this procedure on the peer BIG-IP system.
