Description

When logging into the Webui and browsing to Local Traffic  ››  iRules : LX Workspaces you see the following error:

General database error retrieving information.General error: 01070711:3: Caught runtime exception, boost::filesystem::status: Permission denied: "/var/ilx/workspaces/Common/<Workspace_Name>/extensions/<Extension_Name>/node_modules/.bin/<Module>

• <Workspace_Name> = This will be the name of the workspace
• <Extension_Name>   = This is the name of the extension
• <Module>                   = Name of the Module

Note: The module can be identified because the module name is after the .bin/ within the message above.
 

Environment

  • BIG-IP
  • v14.1.0+
  • iRulesLX
     

Cause

Bug ID 764969


Recommended Actions

If encountering this you will want to check for symlinks in the work space.

Example of work space with symlinks:

[root@bigip2:Active:Standalone] lx_extension_1 # ls -al /var/ilx/workspaces/Common/Repro/extensions/lx_extension_1/node_modules/.bin
total 8
drwxr-xr-x.  2 root root 4096 Oct 24 09:45 .
drwxrwxr-x. 79 root sdm  4096 Oct 24 09:45 ..
lrwxrwxrwx.  1 root root   18 Oct 24 09:45 <Module> -> ../<Module>/bin/<Module>  <----- symlink which causes the issue
[root@bigip2:Active:Standalone] lx_extension_1 #

To resolve this issue:
1. Uninstall the node module
# npm remove <Module>

Important: Some npm modules add symlink files to the .bin directory that are not the same name as the npm module itself. If you run the above command and see no output proving a successful deletion, this may be the case. You will need to do research to determine what module added the symlink. Another option is to review the alternative workaround steps noted in Bug ID 764969.

2.  Install the node module using "--no-bin-links"
# npm install <Module> --no-bin-links

Example of work space with out symlinks:

[root@bigip2:Active:Standalone] lx_extension_1 # ls -al /var/ilx/workspaces/Common/Repro/extensions/lx_extension_1/node_modules/.bin
total 8
drwxr-xr-x.  2 root root 4096 Oct 24 10:02 .
drwxrwxr-x. 79 root sdm  4096 Oct 24 10:04 ..

Now you should be able to browse to "Local Traffic  ››  iRules : LX Workspaces" with out seeing error.


Additional Information

Symlinks often appear under .bin directory in installed npm modules. When a file is a link, 'ls -l' shows 'l' in the far left of the file permission (e.g., lrwxrwxrwx) and the -> shows the link from the current file to the target file.

Here is an example output from the .bin directory from the 'request' npm module (note: this is from non BIG-IP unix box as you can't create symlinks on a BIG-IP).

total 0

lrwxrwxrwx. 1 root root 23 Mar 11  2019 sshpk-sign -> ../sshpk/bin/sshpk-sign
lrwxrwxrwx. 1 root root 25 Mar 11  2019 sshpk-verify -> ../sshpk/bin/sshpk-verify
lrwxrwxrwx. 1 root root 16 Mar 11  2019 uuid -> ../uuid/bin/uuid
