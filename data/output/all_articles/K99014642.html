Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Obtain your BIG-IP platform information

To update or upgrade your BIG-IP environment, you must know your BIG-IP platform type.

BIG-IP hardware platforms

Hardware platforms have a model name and a platform type. Additionally, you must know which of the following you have:

  • BIG-IP hardware platform
  • BIG-IP hardware platform with the Virtual Clustered Multiprocessing (vCMP) module

To determine your BIG-IP model and platform information, refer to K13144: Determine the BIG-IP model and platform type (11.x - 21.x).

BIG-IP VE platforms

There are two types of BIG-IP Virtual Edition (VE) platforms:

  • BIG-IP VE, cloud type
  • BIG-IP VE, hypervisor type

Determine the software versions your platform supports

BIG-IP hardware platforms

If you have a BIG-IP hardware platform, do the following to determine the software versions your platform supports:

  1. Refer to K9476: The F5 hardware/software compatibility matrix.
  2. Do one of the following.
    • If you do not have the vCMP module:
      • Skip this step.
    • If you are upgrading a vCMP host or guest:
      • To determine the BIG-IP software versions that are compatible between your hosts and guests, refer to K14088: vCMP host and compatible guest version matrix.

BIG-IP VE platforms

If you have a BIG-IP VE platform, do one of the following to determine the software versions your platform supports:

  • If you have BIG-IP VE cloud, refer to Cloud platforms: BIG-IP VE supported platforms.
  • If you have BIG-IP VE hypervisor, refer to Hypervisors: BIG-IP VE supported platforms.

Note: For a BIG-IP VE upgrade, make sure the software version you plan to upgrade is within the permitted version range for the product SKU. For more information, refer to K42091606: Determine your BIG-IP VE SKU and permitted software version range.

Select a software release

To select a release type that is appropriate for your environment, use the following release descriptions, and ensure you review the software lifecycle policy and product release notes.

Software release typeChoose this release when you want:
Major or minorNew features, new hardware support, or a specific performance improvement.
MaintenancePrevious point releases, product defect and security fixes, minor functional improvements, and new hardware support.
PointSignificant software and security fixes discovered between minor and maintenance releases.

Recommendations

  • If your priorities are security and sustainability, your best choice is the latest maintenance release of a Long-Term Stability Release version.
    • Long-Term Stability Release versions have 1 for their minor release number (x.1.x), and they are not available for a period of time after a major release (x.0.x).
    • The latest maintenance release of a Long-Term Stability Release version (x.1.latest) can be between x.1.0 and x.1.n.
  • F5 recommends that you review K5903: BIG-IP software support policy so that you know:
    • Which BIG-IP versions currently have Long-Term Stability Release versions (x.1.x) or only major release versions (x.0.x).
    • The latest maintenance release for each Long-Term Stability Release version (x.1.latest) or major release version (x.0.lastest).
    • The date when each BIG-IP version reaches—or has already reached—End of Software Development (EoSD) and End of Technical Support (EoTS).
  • F5 recommends that you review K8986: F5 product support policies for complete details about:
    • Definitions of each release type.
    • The duration of time that F5 supports major release and Long-Term Stability Release versions.
  • Customers must determine which software release best meets the needs of their specific environment. The best practice is to regularly update to the most recent maintenance release and latest point release, if applicable, for each Long-Term Stability Release version. This ensures you have the latest security fixes and maximum stability, as updating to a maintenance or point release will not introduce a change in existing default behavior for that Long-Term Stability Release version.

    Note: To ensure you have the most advanced features, new protocol support, and security capabilities, F5 recommends that you upgrade your BIG-IP systems to the most recent maintenance and point release.

    In the following instances, however, you may want to make an exception to this practice:

    • There are vulnerabilities you need to protect against using a patch.
    • There is specific functionality you want that is only available in a higher version.
  • You can also refer to F5 iHealth for general update or upgrade suggestions. To do so, consult the information at the following location:
    • Go to Status > Overview.
    • Under Diagnostic, in Evaluation, view general update or upgrade suggestions.
  • F5 recommends that you review the release notes for the release you select for details about:
    • New features, release fixes, behavior changes, and known issues.
    • Module combination and memory considerations.
    • Additional user documentation for the release.

Review the update or upgrade path for your BIG-IP software

After you select a suitable software release, refer to the following article so that you are aware of the supported BIG-IP upgrade paths: K13845: Overview of supported BIG-IP upgrade paths and an upgrade planning reference.
