Description

You would like to know % of the memory page used on the BIG-IP device.

Environment

  • BIG-IP
  • Memory

Cause

None.

Recommended Actions

Below are steps that help to calculate the pagemem memory utilization via the tmctl or SNMP options.

tmctl:

1. - For the VE with four TMMs:

  • 'tmid' is the TMM number,
  • 'Slot' is, in this case, multiple slots (VIPRION devices),
  • 'pages_avail' is the total number of pages per TMM,
  • 'pages_used' is the number of pages available per a TMM.

# tmctl page_stats -s slot,tmid,pages_used,pages_avail

slot tmid pages_used pages_avail
---- ---- ---------- -----------
0 0 101403 866304
0 1 83354 867328
0 2 82768 867328
0 3 83705 867328

2. - If no pages are available (all pages_avail are used), it fetches pages from other TMMs.

Automation:

1. - The cronjob could run the script below that calculates the percentage of pages. If larger than X (here "50"), write a log to the LTM log. Later, a custom alert can be used to send an SNMP trap.

#! /bin/bash
pages_used=$(tmctl page_stats -s slot,tmid,pages_used,pages_avail -c | grep -v pages | sed '/^[[:space:]]*$/d' | cut -d ',' -f3 | awk '{s1+=$1} END {print s1}')
pages_avail=$(tmctl page_stats -s slot,tmid,pages_used,pages_avail -c | grep -v pages | sed '/^[[:space:]]*$/d' | cut -d ',' -f4 | awk '{s1+=$1} END {print s1}')
pages_result=$(awk "BEGIN {print ($pages_used / $pages_avail) * 100}" | cut -d '.' -f 1)
if [ $pages_result -ge "50" ];
then
 logger -p local0.notice "page memory usage: $pages_result%"
fi;

 

2. - A cronjob could be created pointing to that script. Examples of how to create a cronjob are found in the below articles:

K000138297: Automating a local UCS archive and storing a copy to a SFTP remote system

K13418: Archiving UCS files using the logrotate and crontab utilities (11.x - 17.x)

SNMP:

We can utilize SNMP for fetching the same values as in the example below:

1. - Using the 'snmpwalk':

# snmpwalk -v2c -c public localhost F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail.0.0 = Counter64: 866304
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail.0.1 = Counter64: 867328
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail.0.2 = Counter64: 867328
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail.0.3 = Counter64: 867328
 
# snmpwalk -v2c -c public localhost F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed 
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed.0.0 = Counter64: 101403
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed.0.1 = Counter64: 83354
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed.0.2 = Counter64: 82768
F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed.0.3 = Counter64: 83705

2. - Also with numeric OIDs:

# snmptranslate -On F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesAvail
.1.3.6.1.4.1.3375.2.1.8.4.3.1.4
# snmptranslate -On F5-BIGIP-SYSTEM-MIB::sysTmmPagesStatPagesUsed
.1.3.6.1.4.1.3375.2.1.8.4.3.1.3

3. - A custom SNMP alert pointing to the LTM log can be created that searches for the log containing "page memory usage."
