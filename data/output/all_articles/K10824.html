Known Issue

This is the result of a known issue. If a virtual server configured with a FastL4 profile generates an ICMP error message in response to a request, the BIG-IP system may insert invalid internal data within the ICMP payload. As a result, when TMM attempts to read the payload, TMM cores and the system crashes.

F5 Product Development tracked this issue as CR127233 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM or ASM release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP WebAccelerator version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
