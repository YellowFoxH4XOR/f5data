Description

BGP peers configured to send recursive routes are dropped by the BIG-IP. 

  • The following symptoms can be observed: 
    1. Oscillation of BGP routes into the routing table
    2. Loss of connectivity towards destinations learned through BGP Peer.
     
  • Log messages in /var/log/ltm may contain the following:

Environment

  • BGP configured
  • Configuring a static route or network statement with recursive routes
  • Configuration objects and settings example: 

router bgp 65001
 network 10.120.4.220/32
 neighbor 10.120.6.164 remote-as 64001

Cause

When the route towards the BGP peer IP address is learned through BGP itself it creates a recursive routing failure. This is the intended behavior.
Showing the routing table shows the /32 route installed.  Since this is the most specific route, all other routes learned from peer will be unreachable.

Recommended Actions

The recommendation to remove configuration on peer advertising /32 of directly connected subnet.  It can be done using the following steps:

  1. Ensure you are in the desired Autonomous System Number (ASN) with this command:
    router bgp <ASN-ID>
    For example, if your ASN is 65001, the following command can be run:
    router bgp 65001

  2. Remove the offending network statement:
    no network <network/subnet>
    For example, if the offending network is 10.120.6.164/32, the following command can be used:
    no network 10.120.4.220/32
