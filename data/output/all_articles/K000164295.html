K000164295: ASM Policy Builder Changes Parameter data type to Integer in Automatic Learning Mode due to option "Learn Integer Parameters"

Type
Support Solution
Published
2026-11-18
Updated
2026-11-18
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000164295

Description

With Automatic learning and automatic application enabled, ASM Policy Builder changes a user-input parameter's data type from Alpha-Numeric to Integer without any integer traffic. The changed parameter is then placed in staging and enforced, which appears as an unexpected policy change.

Observed symptoms:

  • Policy Builder changes the parameter data type from Alpha-Numeric to Integer after Automatic learning is enabled.
  • The parameter enters staging and is later enforced.
  • The learning suggestion shows 0 sample requests triggered it, with an average request violation rating of 0.0.

ASM policy audit log entries:

Parameter lang [update]: Data Type was set to Integer by Policy Builder. Staging enabled, element not enforced.

Parameter lang [update]: Start enforcing element by Policy Builder.

Environment

  • ASM policy in Automatic learning mode with automatic application enabled
  • "Learn Integer Parameters" option enabled on the policy
  • Parameter was previously classified as Alpha-Numeric

Cause

This behavior matches Bug ID 937957: "PB should not continue to classify parameter as integers - if parameter not in staging" Policy Builder continues to attempt integer classification on parameters that have already completed classification and staging. The bug is not fixed.

With "Learn Integer Parameters" enabled and Automatic learning active, Policy Builder changes the parameter to Integer even without integer-sample evidence.

Answer/Recommended Actions

  1. Disable "Learn Integer Parameters" on each ASM policy that uses Automatic learning. This setting must be changed per policy.
  2. Verify that the affected parameter remains Alpha-Numeric after the change. It stays unchanged unless non-integer values are detected and the learning scope reaches 100%.
  3. Enable the "Illegal parameter data type" violation if integer values in an Alpha-Numeric parameter should be flagged.
  4. Review the audit log for parameter data-type changes made by Policy Builder.
  5. Consider Manual learning mode for applications that change infrequently. Automatic mode is better suited to applications that change often.

Additional Information

  • Expected behavior: With Automatic learning and automatic application enabled, Policy Builder can change learned entities based on traffic and server responses. Automatic enforcement and changes are expected in this mode. See K61994817: ASM Policy-builder can changes parameters based on traffic learning.
  • Unexpected behavior: Changing a parameter to Integer without integer traffic matches Bug ID 937957.
  • The "Illegal parameter data type" violation determines whether integer values in an Alpha-Numeric parameter are flagged. This is separate from the learning behavior.
  • Recent policy templates have "Learn Integer Parameters" disabled by default. Older policies may still have it enabled.
