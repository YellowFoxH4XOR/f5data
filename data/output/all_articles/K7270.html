Known Issue

This is the result of a known issue. When a Network Access Favorite uses IP Group Filters, any change to the IP Group Filter's Packet Filter Rules will cause all Network Access traffic to be blocked until a Services Restart is performed.

The FirePass controller provides a packet filter capability for Network Access Favorites on a per-Resource Group basis (as well as a global basis). This feature is enabled when the Use packet filter to access LAN check box is selected on the Network Access: Global Settings page. When this check box is selected, the IP Group Filters tab appears on the Network Access: Resources page, which contains the Group Packet Filter rules.

When a change is made to a rule in the Group Packet Filter section of the IP Group Filters tab, the Network Access Favorite fails to pass traffic, and users cannot reach resources on the internal network using the Network Access Favorite. Turning the IP Group Filters on by selecting the Use packet filter to access LAN check box also causes the failure.

Note: Turning off the IP Group Filters does not cause a failure.

In the Admin UI, you may see error messages on the Reports: System Logs page that appear similar to the following example:


Mar 29   01:38:46   maintenance   "iptables 

    -X vr-25t65mfAD06RZUFra1RJk" command failed with status: 1

Mar 29   01:38:46   maintenance   "iptables 

    -X vd-25t65mfAD06RZUFra1RJk" command failed with status: 1

F5 Networks Product Development tracked this issue as CR77068 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue was fixed in Cumulative Hotfix HF-601-1 issued for FirePass version 6.0.1. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Networks Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by performing a Services Restart from the Device Management: Maintenance: Restart Services page of the Admin UI after making a change to an IP Group Filter. Once the Service Restart is complete, connectivity should return and the new rules should take effect.

Note: Restarting services may cause service interruptions for users, depending on the type of FirePass resource being used. For Network Access resources, the F5 Networks client should attempt to reconnect automatically. The client may prompt the user to retry the connection if restarting services takes longer than the number of connection retries performed by the client.
