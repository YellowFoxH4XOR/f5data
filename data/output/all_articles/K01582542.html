Description

The BIG-IP is forwarding a fragmented or incomplete HTTP request to pool members.

For example, given this request received on the client-side:

GET /prod/data/main.js?version: 4.12.0.15 HTTP/1.1
User-Agent: Mozilla/5.0 (Windows NT 10.0; WOW64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/98.0.4758.102 Safari/537.36
Accept-Encoding: gzip
Host: example.com
Cache-Control: max-age=86400
Connection: keep-alive

The BIG-IP sends the following request on the server-side:

GET /prod/data/main.js?version: 4.12.0.15 HTTP/1.1

The server-side request is missing all of the HTTP headers from the client-side request.

This results in application impact, as the pool member is expecting to receive HTTP headers, and in some cases a HTTP payload.

Environment

  • HTTP profile
  • Running a version which fixes the behaviour described in ID858285 / K27551003

Cause

The client-side request contains an unencoded whitespace in the HTTP URI section of the request line.

GET /prod/data/main.js?version: 4.12.0.15 HTTP/1.1
                               ^_____ Unencoded whitespace

This is a violation of RFC 7230 section 3.1.1, which specifies the request line format that user agents should adhere to.

In this scenario, and with the fix for ID858285, the BIG-IP parses the request as HTTP/0.9, ignoring everything after the request line. This will result in the request line being forwarded as-is, with a single terminating CR/LF. Most web servers will not treat this as a complete HTTP/1.1 request (expecting a HTTP/1.1 request to be terminated with a double CR/LF), so this is likely to result in a reset or 408 response.

Recommended Actions

It is recommended to fix this behaviour on the client side, so that the whitespace can be removed, or properly encoded, for example:

GET /prod/data/main.js?version:%204.12.0.15 HTTP/1.1
                               ^^^___ Encoded whitespace

The BIG-IP can also be configured to reset the connection when such a request arrives, rather than treating it as HTTP/0.9. This is configured on a global scale, by enabling the tmm.http.rfc.enforcement db key:

tmsh mod sys db tmm.http.rfc.enforcement value enable

This can also be configured per HTTP profile from version 15.1.0, by enabling the Enforce RFC Compliance option within the profile.
