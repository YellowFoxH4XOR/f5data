Topic

Summary

Under heavy load, NFS-managed volumes with exports that reside on NetApp filers may experience slow traversal of directories or the inability to mount the ARX VIP.

Description

A filer will see many TCP connections with a small number of requests per connection. To optimize TCP performance, the ARX system aggregates client connections and sends multiple data requests over a small number of TCP connections.

By default, the NetApp NFS flow controlled feature may cause the ARX-managed TCP connections to be throttled. Under heavy use, the NetApp filer may no longer open the TCP window for the ARX system. The ARX system constantly cleans up the connection attempts for clients while the filer does not open its TCP window. The more requests that originate from these clients as the filer continues to respond in this manner to the ARX system, the more cleanup the ARX will need to accomplish. As a result, more processor usage will be consumed, causing clients that are assigned to the same highly utilized processors to have access issues.

ARX procdat messages appear similar to the following example:

NET_NFS-0-ERR-NSM_NFS_TCP_ERROR:: NFS/TCP ACCESS Error-Closed Connection: Internal (cleanup). XID 0x0 0.0.0.0:0 => at 0.0.0.0:0. Client XID 0x53cbf1c6 10.10.72.130:738.

NET_NFS-0-ERR-NSM_NFS_TCP_ERROR:: NFS/TCP ACCESS Error-Closed Connection: Internal (cleanup). XID 0x0 0.0.0.0:0 => at 0.0.0.0:0. Client XID 0x53cbf1c6 10.10.72.130:737.

NET_OS-0-DBG-NSM_CONN_BUFFER_FULL:: TCP connection transmit buffer is full details nfs filer at 10.10.10.10:2049 sent:0 queue len:22303368 bytes max queue len:16384 pkts una:1698899814 nxt:1698899142 tx_win:0 tx_cwnd:2920

Note: The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.

When reviewing the NetApp filer, a common symptom is for NFS connections to time out. When this behavior occurs, NetApp logs may display the following error message:

[erinas2-fan: nfsd.tcp.close.idle.notify:warning]: Shutting down idle connection to client (10.10.10.100) where transmit side flow control has been enabled. There are 193 outstanding replies queued on the transmit buffer. This socket is being closed from the deferred queue.

When attempting to diagnose the issue, F5 recommends that you gather a proxy-all capture with the capture session command and review the ARX and filer communication. When using Wireshark to review the capture, use the expert.message == Zero window filter to view the specific packets.

For example:

2011-12-19 13:38:03.491985                 131.101.117.161                131.101.117.140                TCP        [TCP ZeroWindow] nfs > entrust-sps
[ACK] Seq=1 Ack=1 Win=0 Len=1

2011-12-19 13:39:48.493183                131.101.117.161               
131.101.117.250                TCP        [TCP ZeroWindow] nfs > entrust-sps
[ACK] Seq=1 Ack=1 Win=0 Len=1

In the previous example, the filer is no longer opening its TCP window for the ARX system identified by the TCP ZeroWindow comment in the packet data.  

Recommendations

When using ARX to NetApp NFS deployment, you can adjust NetApp NFS flow control parameters to give more resources to the smaller number of TCP connections. 

Important: Before making changes on the NetApp filer, F5 recommends that you first contact NetApp support for more information. In addition, it is important to note the current option settings on the NetApp filer before changing the settings to the recommended values.

  • You may display the current options levels by typing the following command into the NetApp CLI:

options nfs.ifc

  • Adjust the NetApp flow control options by typing the following command into the NetApp CLI:

options nfs.ifc.xmt.high 64 options nfs.ifc.xmt.low 63
