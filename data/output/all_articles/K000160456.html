Description

Packets were duplicated on a trunk (LAG) using SR-IOV interfaces on BIG-IP VE.

When SR-IOV interfaces are attached to BIG-IP VE and combined into a trunk (LAG), incoming packets, including ICMP packets, appear duplicated as shown below:

[root@bigip1:Active:Standalone] config # ping 10.1.1.2
PING 10.1.1.2 (10.1.1.2) 56(84) bytes of data.
64 bytes from 10.1.1.2: icmp_seq=1 ttl=255 time=0.563 ms
64 bytes from 10.1.1.2: icmp_seq=1 ttl=255 time=0.572 ms (DUP!)
64 bytes from 10.1.1.2: icmp_seq=1 ttl=255 time=0.575 ms (DUP!)
64 bytes from 10.1.1.2: icmp_seq=1 ttl=255 time=0.578 ms (DUP!)

Environment

  • BIG-IP VE on any type of hypervisors
  • Trunk is configured using SR-IOV interfaces

Cause

Multiple SR-IOV Virtual Functions (VF) from the same Physical Function (PF - physical NIC) were attached to the BIG-IP VE.

The trunk feature on BIG-IP VE configures the same MAC to the trunk member interfaces as described in K05563326. Under the condition, the single PF has multiple VFs with the same MAC address. Therefore, each packet is duplicated and sent to all the trunk member interfaces.

Answer/Recommended Actions

Network architecture requires design considerations when using one or more trunks (LAGs) on BIG-IP.

Typical design

  • Switch Redundancy: Each host connects to two upstream switches to avoid dependency on a single switch.
  • Link Redundancy: The upstream switches form an MLAG so that traffic continues through the remaining link if one link fails.
  • PF Redundancy: Interfaces are distributed across multiple PFs connected to different switches.
  • BIG-IP LAG Redundancy: Interfaces backed by VFs from different PFs are aggregated into a BIG-IP trunk.
  • BIG-IP Redundancy: BIG-IP VE instances are deployed on separate hosts and operate in an Active/Standby configuration.

 

Network with packet duplication

Both of the following designs will result in packet duplication.

Please keep in mind that:

  • A trunk on a BIG-IP VE instance should not have VFs (trunk member interfaces) from the same PF.
  • The BIG-IP VE instances in HA or the instances that communicate with each other should not have trunk member interfaces from the same PF.
