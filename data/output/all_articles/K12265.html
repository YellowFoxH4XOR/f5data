K12265: The BIG-IP WebAccelerator does not compress data when compression is enabled in the http-acceleration profile

Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator does not support compression within the http-acceleration profile. If you enable compression in the http-acceleration profile, the BIG-IP WebAccelerator no longer compresses content served from its cache, regardless of the acceleration policy settings. As a result, the amount of client-side traffic from the BIG-IP WebAccelerator may increase substantially depending on the content. This issue does not affect content that is proxied by the BIG-IP WebAccelerator with an S10201 code.

Note: Due to a different issue, the BIG-IP WebAccelerator does not compress content proxied with an S10201 code if the code is configured in both the BIG-IP WebAccelerator acceleration policy and the Compression Exclude List of the associated HTTP profile. For more information, refer to K12563: HTTP Compression Exclude List takes precedence over BIG-IP WebAccelerator compression.

F5 Product Development tracked this issue as ID 222692 (formerly CR123170) and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP WebAccelerator and Edge Gateway release notes.

Workaround

You can prevent this issue from occurring by disabling compression in the http-acceleration profile. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Services.
  5. Select HTTP.
  6. Select the name of the http-acceleration profile you want to modify.
  7. In the Compression menu, select Disabled.
  8. Click the Update button.

Note: You may be required to clear the BIG-IP WebAccelerator cache if the content you would like to compress is currently held in the cache. To do so, perform the appropriate procedures for your version described in K7618: Clearing the WebAccelerator cache from the command line
