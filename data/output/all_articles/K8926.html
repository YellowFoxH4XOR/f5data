Known Issue

This is the result of a known issue. If users access a Java applet through Portal Access, and the applet code contains the new URL() Java constructor, the Portal Access reverse-proxy engine may not rewrite the Java applet correctly, causing the applet to fail to load. 

Note: The new URL() Java constructor is part of the java.net.URL class.
F5 Product Development tracked this issue as CR87188 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

This issue still exists in the FirePass version 5.x branch.

Additionally, cumulative hotfix HF-552-11 has been issued for FirePass version 5.5.2, cumulative hotfix HF-601-10 has been issued for FirePass version 6.0.1, and cumulative hotfix HF-602-2 has been issued for FirePass version 6.0.2. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by disabling Java rewriting for the affected applets. To do so, perform the following procedure.

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Portal Access : Web Applications : Content Processing page.
  3. Click the Global Settings tab.
  4. In the Java Byte Code Rewriting section, add the URLs for the affected applet file(s).

    For example:

    http://www.siterequest.com/app1/*.cab
    http://www.siterequest.com/app2/app2.jar
     
  5. Click the Update button.
