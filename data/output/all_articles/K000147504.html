K000147504: How to add an HTTP header allowlist to an F5 Distributed Cloud Load Balancer

Description

  • I need to apply a header allowlist to a load balancer.

Environment

  • F5 Distributed Cloud HTTP Load Balancer

Answer/Recommended Actions

To apply a header allowlist to a load balancer, follow these steps:

1. Log in to the F5 Distributed Cloud console.

2. Click on the Web App & API Protection tile.

3. In the Manage section, go to Service Policies > Service Policies.

4. Click Add Service Policy at the top of the page.

5. Enter a name for the service policy.

6. Under the Rules section, click Configure and create a rule:

  1. Enter a name for the rule.
  2. In the Action section, select Allow.
  3. Under HTTP Headers, click Add Item.
  4. Enter the header name you want to allow (e.g., “QA-tester”).
  5. Choose a match option:
  6. Present: Allow the request if the header is present.
  7. Not Present: Allow the request if the header is not present.
  8. Match Values: Allow requests with specific values.
  9. Under Exact Values or Regex Values, add the specific or regex values you want to match.

7. Click Apply to save each configuration step (HTTP Header, Request Matcher, and Rule).

8. Click Save and Exit to save the service policy.

9. Now, apply this policy to your load balancer:

  1. Go to Load Balancers > HTTP Load Balancers under the Manage section.
  2. For the load balancer you want to modify, click the three dots under Actions and select Manage Configuration.
  3. Click Edit Configuration in the top right.
  4. Under Common Security Controls, select Apply Specified Service Policies from the Service Policies dropdown.
  5. Click Configure, select your service policy, and click Apply.

10. Click Save and Exit.

 

Cause

A header allowlist ensures that only requests containing specific headers (and values, if needed) are allowed through the load balancer. All other requests will be blocked if they do not meet the allowlist criteria.

Additional Information

  • Implicit Deny: Service policies have an implicit deny at the end, meaning any request that does not match the allowed headers will be blocked.
  • Policy Order: If you have multiple service policies applied to a load balancer, make sure the allowlist policy is at the top.
