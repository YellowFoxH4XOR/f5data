K3025: Reasons why switches may respond to the BIG-IP system on multiple ports

Topic

By default, the BIG-IP system uses the same MAC address on all VLANs. This means the BIG-IP system uses the same MAC address for all interfaces and all IP addresses.

This can cause problems with some switches, because it appears that the MAC address exists on multiple ports, which, in turn, can cause the switch to alternate the port to which it sends packets for a certain MAC address.

The BIG-IP system monitors and records the VLANs that are associated with particular connections. Once a connection is established on a VLAN, the BIG-IP system will drop any packets that are part of that connection if they arrive on a different VLAN.

As a result, if you use the BIG-IP system in default configuration with certain switches, you will experience dropped connections.

You can resolve this issue by enabling the vlans unique_mac global variable on the BIG-IP system. With this feature enabled, the BIG-IP system will use a unique MAC address for each VLAN, rather than one system-wide MAC address. The BIG-IP system will then use the MAC address of the lowest numbered interface configured in each VLAN.

For further illustration, refer to the following example configuration.

InterfaceMAC address
1.10:3:47:8:a4:d4
1.20:3:47:8:a4:d5

VLAN External contains interface 1.1.
VLAN Internal contains interface 1.2.

Without the vlans unique_mac global variable enabled, all the VLANs on the system would use 0:3:47:8:a4:d4 as their MAC address. Even though Port 1.2 has a different MAC address, the VLAN Internal will use the first MAC address ( 0:3:47:8:a4:d4).

When you enable the vlans unique_mac global variable, VLAN External will use the MAC address 0:3:47:8:a4:d4 and VLAN Internal will use the MAC address 0:3:47:8:a4:d5.

To enable the vlans unique_mac global variable, type the following command:

bigpipe global vlans unique_mac enable
