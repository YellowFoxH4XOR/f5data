Known Issue

Restarting the BIG-IP ASM system may generate a disk provisioning error.

This issue occurs when the following conditions are met:

  • The following BIG-IP ASM versions are installed on two or more partitions:
    • BIG-IP 11.6.x - 12.0.0 HF2
    • BIG-IP 12.1.0 or later
  • You restart the BIG-IP system or restart the BIG-IP ASM system on one of the partitions. For example, you type the following command:

    bigstart restart asm

For example, BIG-IP ASM 11.6.1 is installed on partition-1, and 12.1.0 is installed on partition-2. If you boot from one partition to the other, or attempt to restart the BIG-IP ASM system on one of the partitions, the BIG-IP ASM system may fail to start, and the BIG-IP system generates a disk provisioning error message.

Starting in BIG-IP 12.1.0, the BIG-IP ASM system uses a different application volume name. Previous BIG-IP software versions identify the application volume as being owned by the BIG-IP ASM system, and allows the BIG-IP ASM system to be provisioned and start. However, in the previous versions, the BIG-IP ASM system creates two BIG-IP ASM application volumes. If the BIG-IP ASM system is restarted with bigstart or tmsh, or if the BIG-IP system is rebooted, provisioning does not allow the BIG-IP ASM system to start.

Impact

The asm process fails to start and the system is unable to pass traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP ASM system is unable to process application traffic.
  • The asm process fails to start, and the bigstart status asm command output indicates an error that appears similar to the following example:

    bigstart status asm

    asm          down, Disk Provisioning error

Workaround

To work around this issue, you can remove the affected volume and re-provision the BIG-IP ASM system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Boot in to the most recent version of BIG-IP software.

    For example, if BIG-IP ASM 11.6.1 is installed on partition-1, and 12.1.0 is installed on partition-2, boot in to partition-2.

  2. Log in to the BIG-IP ASM command line.
  3. To remove any DoS profiles from the virtual servers, use the following command syntax:

    tmsh modify /ltm virtual all profiles delete { <profile> }

    For example:

    tmsh modify /ltm virtual all profiles delete { dos }

  4. To set asm provisioning to none, type the following command:

    tmsh modify /sys provision asm level none

  5. Wait for one to two minutes while the system changes the provisioning configuration.
  6. To confirm that the BIG-IP ASM system is no longer provisioned on the system, type the following command:

    tmsh show /sys provision asm

    The output should indicate that system resources are no longer assigned to the BIG-IP ASM system.

    For example:

    ---------------------------------------------------------
    Sys::Provision
    Module  CPU (%)  Memory (MB)  Host-Memory (MB)  Disk (MB)
    ---------------------------------------------------------
    asm           0            0                 0          0
    host         10          780                 0      28748
    tmos         89         1854               140          0

  7. To delete the asm volume, type the following command:

    tmsh delete /sys disk application-volume asmdata1

  8. To provision the BIG-IP ASM module, type the following command:

    tmsh modify /sys provision asm level nominal

  9. Once provisioning is complete, apply the DoS profiles back to the virtual servers using the following syntax:

    tmsh modify /ltm virtual all profiles add { <profile> }

    For example:

    tmsh modify /ltm virtual all profiles add { dos }
