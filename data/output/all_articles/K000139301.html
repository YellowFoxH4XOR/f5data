Description

While trying to generate a UCS file, you might encounter the following  mysql dump error after you run the following command from bash :

a2w-lab@(LAB1)(cfg-sync Disconnected)(/S1-green-P::Active)(/Common)(tmos) save sys ucs v15-test.ucs
Saving active configuration...
mysqldump: Error: 'Can't create/write to file '/var/tmp/#sql_476e_2.MAI' (Errcode: 13)' when trying to dump tablespaces
mysqldump: Couldn't execute 'show fields from `all_suggestions`': Can't create/write to file '/var/tmp/#sql_476e_0.MAI' (Errcode: 13) (1)
/var/local/ucs/v15-test.ucs is saved.

Environment

  • BIG-IP
  • VCMP 
  • VCMP GUEST
  • VIPRION
  • BLADES

Cause

This problem might happen due to incorrect permissions in the /shared/tmp directory.

  • An incorrect permission will look like below:

[admin@LAB1:/S1-green-P::Active:Disconnected] ~ # ls -laZd /shared/tmp

drwxr-xr-x. root root system_u:object_r:tmp_t:s0 /shared/tmp 

  • A correct permission looks like below:

[root@LAB1:/S1-green-P::Active:Standalone] config # ls -ladZ /shared/tmp/

drwxrwxrwt. root root system_u:object_r:tmp_t:s0    /shared/tmp/

Recommended Actions

Execute below command to correct the permissions for /shared/tmp directory and verify if issue still exists:

# chmod 1777 /shared/tmp

Note: Run the ls commands from root or admin user.

Additional Information

Incorrect file permissions are not an issue as long as specific process tries to perform file related operation e.g. open, write, read. If operation is not permitted system call will fail. Program that triggered this system call in the first place will also fail and set the errno value accordingly e.g. EACCES. If error handling is implemented error message should be reported.

/shared/tmp directory is not part of Filesystem Hierarchy Standard and it's F5 specific. There's no documentation that tells about file system privileges. Standard permissions are 755 for directories and 644 for files.
