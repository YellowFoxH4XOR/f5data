Known Issue

This is the result of a known issue. A wildcard virtual server with a host netmask fails to process traffic even after the netmask is corrected.

If a wildcard virtual server is created by mistake with a 32-bit host netmask (0.0.0.0/255.255.255.255), rather than the expected 0-bit wildcard netmask (0.0.0.0/0.0.0.0), the virtual server will only accept traffic with a destination address of 0.0.0.0, rather than accepting traffic destined for all addresses. This behavior is expected. However, changing the netmask of the virtual server to the correct 0-bit wildcard netmask value of 0.0.0.0 does not correct the misconfiguration.

F5 Product Development is tracking this issue as ID 249019 (formerly CR97936).

Workaround

You can work around this issue by deleting the virtual server originally created with the 32-bit host netmask, and recreating the virtual server with the correct 0-bit wildcard netmask value of 0.0.0.0.
