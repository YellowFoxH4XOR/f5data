K000137245: Old software image showing up in GUI

Type
Support Solution
Published
2023-10-15
Updated
2023-10-15
Source
https://my.f5.com/manage/s/article/K000137245

Description

You are experiencing an issue where, after upgrading to F5OS-A 1.3.2, attempts to delete an older software version 1.1.1-9159 partially succeeded. The patch services version was removed but the base service version (1.1.0-7645) was not, leaving it in an erroneous, stuck state. Attempts to delete it through the GUI resulted in the following error:

Server Error(s)
1. Image 1.1.0-7645 (Service) cannot be removed - error: Image 1.1.0-7645 does not exist

Similarly, the CLI presents the error with the following output:

appliance-1# show system image
--snip--
VERSION                                 IN
SERVICE     STATUS DATE       SIZE   USE
------------------------------------------------
1.1.0-7645  error  1          1      false         <- Old base service version that cannot be deleted, and listed twice.
1.1.0-7645  error  1          1      false         <-
1.3.2-13054 ready  2023-01-26 2.54GB true          <- Currently running version.
1.3.0-8327  ready  2023-01-26 2.54GB false

Environment

  • Upgraded from F5OS-A 1.1.1-9159 to 1.3.2-13054
  • Issue encountered when deleting the older software version via GUI and CLI
  • Operational environment is on F5 appliance
  • CLI and GUI both showing the erroneous stuck state of version 1.1.0-7645

Cause

The root cause of this issue has been identified as a bug. This bug is triggered when you attempt to remove a non-base version of F5OS ISO file (e.g., a "dot-one" or "dot-two" release like 1.5.1 or 1.3.2). More technical details on this bug can be found on the F5 bug tracker: BugID1267205.

Recommended Actions

To resolve this issue, you will need to apply the workaround provided in the Bug Tracker. The steps are as follows:

  1. Access the system and navigate to the location of the import.json file.
  2. Edit the import.json file to remove the JSON object for the problematic version 1.1.0-7645.
  3. Save and close the import.json file.
  4. Restart the sw-mgmt and system_image_agent services on the system.

Following these steps should remove the erroneous stuck version from the system, allowing normal operation.

Additional Information

This workaround involves manual editing of system files and restarting crucial system services. It's advisable to perform these steps during a maintenance window or when the system usage is low to minimize any potential impact. Always ensure to have a backup of the system configuration and the import.json file before making changes.
