Known Issue

Applying an ASM security policy repeatedly fills the /var disk partition.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION chassis with ASM provisioned.
  • You update the ASM security policy in either of the following scenarios:
    • You select the Apply Policy button in a security policy repeatedly and frequently.
    • You enable automatic policy building for one or more policies with several frequent changes.

As part of the synchronization process between blades, the BIG-IP ASM system creates files in the /var/ts/var/cluster/send directory, which are cleaned up at regular intervals. If there are frequent changes, whether through policy builder, or manual updates, it is possible to fill the disk partition before this cleanup occurs.

Impact

The /var disk partition becomes full, causing system instability that may include intra-blade communication failure, blades going offline, or blades failing over within a cluster.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    err istatsd[7898]: 015b0000:3: [rollup.cpp:113 createSegment] could not create /var/tmstat2/cluster/blade1.tm2.1yD9Zj: No space left on device

    err diskmonitor: 011d0004: Disk partition var has only 0% free

  • The /var/ts/var/cluster/send directory contains a large number of files that appear similar to the following example:

    sync_20150929_143600_full_update

  • The df command line utility reports that the /var partition is at or near capacity, as shown in the following example:

    df -h /var

    Filesystem Size Used Avail Use% Mounted on
    /dev/mapper/vg--db--sda-set.1._var
    3.0G 3.0G 0 100% /var

Workaround

To work around this issue, on a very active system with a high number of policy changes, you can create a cron job to delete the contents of the /var/ts/var/cluster/send directory more frequently. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Change directories to the /etc/cron.d directory by typing the following command:

    cd /etc/cron.d

  3. Using a text editor, create a file named remove_asm_cluster_send_files.
  4. Enter the following data into the file:

    */5 * * * * root /usr/bin/perl -MF5::Utils::File -e "F5::Utils::File::cleanup_files(glob_pattern => '/var/ts/var/cluster/send/*', max_retained_files => 10)"

    Note: This command will remove all but the most recent 10 files from the /var/ts/var/cluster/send directory, every 5 minutes.

  5. Save the file and exit the text editor.
