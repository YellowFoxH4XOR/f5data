Description

After application of the workaround for Bug ID 997793 you reboot the device, and the reboot time is longer than expected.

After the reboot has completed users attempting to access a service provided by the BIG-IP APM you are redirected to /my.logout.php3?errorcode=XX, and the browser shows  an error similar to the following:

ERR_CONNECTION_RESET

Environment

  • EPSEC packages
  • BIG-IP APM
  • If you reboot the device, completing the process takes a long time. 

Cause

For unknown reasons the httpd_apm service may fail to start after the reboot.

 Recommended Actions

To fix the issue of the APM URL we have to manually restart both httpd_apm and httpd_sam services and rebuild the EPSEC RPM database.
Impact of workaround: There should be no impact on your device by executing the following commands.

1. Restart the daemons that are down with the following command:

bigstart restart httpd_sam httpd_apm

2. Validate that the services are running properly:

tmsh show sys service httpd_sam httpd_apm

3. Delete the existing database

rm -rf /var/apm/lib/rpm

 4. Refresh the database using the EPSEC bash script

epsec -f refresh
