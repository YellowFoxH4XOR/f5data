Answer/Recommended Actions

This demonstration illustrates the security risks associated with outdated PHP versions, specifically PHP 5.3. By exploiting Remote File Inclusion (RFI) vulnerabilities in such an old PHP version, we can show how outdated software components can be leveraged to execute unauthorized commands and access sensitive system information. 

Remote File Inclusion (RFI) vulnerabilities are not exclusive to old PHP versions, but their prevalence and exploitation have been more common in older versions due to less stringent security measures and outdated practices. Using F5 XC WAF we can identify, and block threats that come along with outdated software.   

 

To configure the WAF (Web Application Firewall): 

1. From the Distributed Cloud console homepage, select WAAP service.
2. Select HTTP Load Balancer under Manage->Load Balancers.
3. Select your Load Balancer and go to Manage Configuration, and then click Edit Configuration.
4. Go to Web Application Firewall, enable it and select Add Item.

5. Select the constructed app firewall and scroll down to Security Configuration, where you may Enable WAF (Web Application Firewall). Press Save & Exit.

You will see the following interface for the configuration: 

Enforcement Mode: We should set this to blocking after 1 week of grace period of monitoring mode of the WAF this is for the ML model to observe regular baseline traffic, the change of enforcement must be done manually after the grace period. 

Security Policy: We recommend leaving this as default, it will perform automatic Attack Signature tuning. Threat campaign and Violations are by default enabled.

Note: If we require granular tuning we can change to custom and specify: High, Medium & Low attack signatures, but this can trigger some false positives due to low accuracy signatures and is generally not recommended. 

Signature-Based Bot protection: We recommend leaving this at default, malicious bots will be automatically blocked while suspicious bots will be reported for manual review.

Allowed Response Status Codes: We recommend leaving these at default (What are default response codes allowed on Web Application Firewall layer ?).

Mask Sensitive parameters in Logs: Sensitive parameters such as Passwords, and relating to credit-cards are automatically configured however if your application uses custom parameter for these fields this section must be set to custom and you must specify the parameters that pertain to sensitive personal information. 

Blocking Response Page: This can be left at default. 

 

6. To validate the WAF is working as expected we have launched a POC on a Remote File Inclusion (see details below) , once you have received the Support ID, go back to the XC console and navigate to Home; Web App & API Protection >> select the namespace in which you configured your LB >> Overview >> Security, then scroll to the bottom of the console and select your LB. 

7.In our Security Analytics Tab  we can see a summary of the details of the attack, and in this case it triggered on 2 signatures and was blocked.

 

The Distributed Cloud WAF engine has effectively identified and prevented the known vulnerability, which falls under the category of obsolete and vulnerable components as evidenced by the previous screenshot. 

 

 

Additional Information

File inclusion vulnerabilities allow executable code from untrusted sources to be smuggled in by taking advantage of the dynamic file include capabilities in applications. This usually happens when a program receives input from the user and sends it to a file inclusion API, allowing malicious code to be loaded into the context of the susceptible program.

  • Remote File Inclusion (RFI) when the attacker is able to load remote code in the application, increasing the likelihood that malicious code will be executed on the target
  • Local File Inclusion (LFI) when the vulnerability permits files to be loaded on the target server.

 

Remote File Intrusion - Proof-Of-Concept:

In order to execute this POC, the following was present in our outdated test environment: 

  • Set Up Damn Vulnerable Web App 
  • Outdated PHP Version: PHP Version 5.3
    Command ran in vulnerable app to grab php version:
127.0.0.1; /opt/alt/php53/usr/bin/php -v

  • Enabled allow_url_fopen and allow_url_include: These PHP configuration settings must be enabled to allow the inclusion of remote files. They are crucial for RFI attacks.

  • Vulnerable Code: The PHP application must have code that allows for file inclusion based on user input. This could be a page parameter or similar that includes files dynamically without proper validation.

  • Remote Malicious File: A remote PHP file designed to exploit the vulnerability should be hosted. This file will contain code to execute commands or retrieve sensitive information. For example, malicious.php should include code to run commands like system($_GET['cmd']);.

In this case we hosted a malicious.php with the following code for demonstration purposes:

<?php
if (isset($_GET['cmd'])) {
echo "<pre>";

$cmd = $_GET['cmd'];

$allowed_cmds = array('whoami', 'uname -a', 'lscpu', 'free -m', 'df -h', 'php -i', 'ps aux', 'cat /etc/passwd');
$allowed_cmds = array_map('escapeshellarg', $allowed_cmds); 

$cmd = escapeshellarg($cmd);

if (in_array($cmd, $allowed_cmds)) {
system($cmd);
} else {
echo "Command not allowed.";
}

echo "</pre>";
}
?>

Note: the malicious.php can be hosted in any external server and without WAF protection will execute any given command that is input. 

 

1. We publicly hosted the DVWA for testing purposes, and will show you a comparison of what a command execution would look like without a properly configured WAF actively blocking threats. Using the page parameter we load the malicious.php directly.

The command then executes to the server and it discloses critical information that can be used to leverage other attacks or further disclose existing vulnerabilities.

This attack would have been successful if the application would not be behind F5XC WAF. However, behind XC WAF it would generate the block as seen in step 6 of this article.
