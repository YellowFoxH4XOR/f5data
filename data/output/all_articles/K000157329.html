K000157329: iRule's 'nexthop' command is not working

Type
Support Solution
Published
2025-11-25
Updated
2025-11-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000157329

Description

When the nexthop command is used to route traffic going out of F5, it's required that the pool member is reachable via regular routes from the routing table.

Otherwise, the connection is reset with "no route to host" without processing the nexthop command from the iRule (that would point to a valid nexthop).


Environment

- iRule

- 'nexthop' command used to forward traffic

- connection is reset with [F5RST: No route to host]


Cause

The initial route to the pool member must exist on the system, even if it will be overridden by the iRule's nexthop command; otherwise, the connection fails before nexthop is applied.


Recommended Actions

Ensure a valid route exists to each pool member before applying a nexthop route override via iRule.
