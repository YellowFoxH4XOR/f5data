K000159810: How to Identify and Filter Attack Signatures by Attack Type for Use in configuring Accuracy Filters in F5 WAF for NGINX

Source

Description

When configuring filter-based signature sets in F5 WAF for NGINX policies, you may need to identify the correct attackType.name values to use in accuracy filters. This is particularly useful when attempting to reduce false positive alerts by setting low accuracy signatures (such as SQL Injection) to alarm-only mode instead of blocking mode.

The Attack Signature Report tool can be used to generate a comprehensive list of all signatures and their associated attackType.name values, which can then be filtered to identify specific attack types for use in policy configurations.

Environment

  • F5 WAF for NGINX
  • Filter-based signature sets using accuracyFilter parameter
  • Attack Signature Report tool (/opt/app_protect/bin/get-signatures`)))

Cause

None

Answer/Recommended Actions

  1. Run the Attack Signature Report tool against your WAF compiler image to generate a JSON report of all signatures:
    /opt/app_protect/bin/get-signatures -o /path/to/signature-report.json
  2. Filter the generated JSON output to identify signatures for specific attack types. For example, to find SQL Injection signatures, use:
    jq '.signatures[] | select(.attackType.name | contains("SQL-Injection"))' /path/to/signature-report.json
    Use the confirmed attackType.name value in your filter-based signature-set configuration. For SQL Injection, the correct value is "SQL-Injection" (with hyphen, not space).
  3. Example configuration for setting low accuracy SQL Injection signatures to alarm-only mode:

    {
    "name": "SQL Injection Signatures - Low Accuracy",
    "alarm": true,
    "block": false,
    "signatureSet": {
    "filter": {
    "accuracyFilter": "eq",
    "accuracyValue": "low",
    "attackType": {
    "name": "SQL-Injection"
    },
    "hasCve": "all",
    "lastUpdatedFilter": "all",
    "riskFilter": "all",
    "riskValue": "all",
    "signatureType": "request",
    "tagFilter": "all",
    "userDefinedFilter": "all"
    },
    "type": "filter-based"
    }
    }

  4. Test the policy compilation and validate that the intended signatures are being filtered as expected.

Additional Information

The Attack Signature Report tool output includes the following information for each signature:

  • attackType.name: The attack type classification (e.g., "SQL-Injection", "Detection Evasion", "Predictable Resource Location")
  • accuracy: The accuracy level of the signature (e.g., "low", "medium", "high")
  • Additional signature metadata

The attackType.name values use hyphens rather than spaces (e.g., "SQL-Injection" not "SQL Injection").
