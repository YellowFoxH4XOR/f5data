Description

  • The F5 Container Ingress Service(formerly known as Container Connector) instance is sending the Kubernetes workload node arp to the BIG-IP static ARP list.
  • You have configured the host network in one or more workload pods
  • You may find the below error message in the Container Ingress Service instance log:

    {"code":400,"message":"01071d9d:3: Neighbor entry (<kubernetes workload node ip>) can not be resolved.","errorStack":[],"apiError":3}

Environment

  • F5 Container Ingress Service with ClusterIP mode
  • Kubernetes pods with hostNetwork: true
  • BIG-IP LTM

Cause

Pods with hostNetwork: true are not compatible with F5 CIS ClusterIP mode when VXLAN is used as the connectivity mechanism (e.g., Flannel VXLAN, OpenShift SDN). In this scenario, CIS attempts to program the node IP as a static ARP entry over the VXLAN tunnel, but the node IP is only reachable via the physical network, causing ARP resolution to fail. This limitation does not apply when using Static Routing Mode (--static-routing-mode=true), where the BIG-IP reaches destinations via physical network routes and the node IP is a valid, directly reachable pool member.

Recommended Actions

Please avoid using host network mode for your pods.
To identify if there are any host network configured for your pods, please use the below command at your kubectl environment:
kubectl get pod [-n <namespace>] -o=custom-columns='NAME:.metadata.name,HOSTNETWORK:.spec.hostNetwork' | { head -1; grep true; }
For example, for a kubernetes cluster that has Container Ingress Service instance watching on namespace prod:
kubectl get pod -n prod -o=custom-columns='NAME:.metadata.name,HOSTNETWORK:.spec.hostNetwork' | { head -1; grep true; }
