K7041: Connections to a BIG-IP ASM-enabled virtual server with a redirect iRule may be reset

Known Issue

This is the result of a known issue. In BIG-IP ASM versions prior to 9.4.0, the HTTP_REQUEST iRule events are processed before the HTTP class BIG-IP ASM iRule. This can cause connections to a BIG-IP ASM-enabled virtual server with a redirect iRule to be terminated.

F5 Product Development tracked this issue as CR59261 and CR71824, and it was fixed in BIG-IP ASM 9.3.0 and 9.4.0. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Workaround

To work around this issue, you must be running BIG-IP ASM 9.2.4 or a later version. To work around this issue in BIG-IP 9.2.4 through 9.2.5, you can create a redirect iRule containing the set asm_bypass 1 statement, similar to the following example iRule:

when HTTP_REQUEST {  set asm_bypass 0  if { "[HTTP::uri]" starts_with "/mydir" } {    HTTP::redirect "http://www.mysite.com/myredirect"    set asm_bypass 1  }}
