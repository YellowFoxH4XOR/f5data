Topic

The amount of memory displayed through the bigpipe ms or bigpipe summary commands, or the memory utilization screen in the Configuration utility, is for the BIG-IP kernel memory objects only.

The kernel in BIG-IP is limited to a maximum of 1024MB of memory. Out of this maximum, the kernel uses various memory pools in order to support functions like IPFW and network drivers.

RAM is allocated from a specific memory pool for specific BIG-IP related functions. The BIG-IP memory pool has a maximum memory size structure limitation of 1GB (1024 * 1024 * 1024 = 1073741824). If you are running a BIG-IP with 2GB of RAM, the memory pool total will be listed as 1020725820, which slightly lower than 1073741824. This discrepancy is due to a small amount of overhead required in the structure that defines the memory pool.

The advantage of a BIG-IP with 2GB of RAM is that the BIG-IP memory pool is expanded to its maximum size, whereas in a 1GB memory configuration it is not, because a certain percentage of memory is allocated for non-kernel processes. Having 2GB of RAM also increases the availability of memory to other processes that run on the BIG-IP, such as 3-DNS, proxyd (SSLProxy), and iControl.
