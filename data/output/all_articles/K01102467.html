Known Issue

The configuration validation may fail if you delete an iRule.

This issue occurs when all of the following conditions are met:

  • Your iRule calls a procedure in a different iRule.

    For example, the following iRule test_2 calls the procedure do_a_thing in the different iRule test_1:

    ltm rule test_1 {
    proc do_a_thing {} {
        log local0. "otters"
        }
    }
    ltm rule test_2 {
    when CLIENT_ACCEPTED {
            call test_1::do_a_thing
        }
    }

  • You associate the iRule with a virtual server.
  • You delete the iRule that runs the procedure call.

Impact

The configuration validation fails, which may result in configuration load or configuration synchronization (ConfigSync) failures.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm log file, you observe error messages that appear similar to the following example:

    01020036:3: The requested rule (/Common/rule_uses_procs) was not found.

  • You observe that the iRules procedure is still referenced in the configuration, even after you delete the iRule.

Workaround

To work around this issue, you can force the mcpd process to reload the configuration to the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: Rebooting the BIG-IP system disrupts traffic processing until the system is back up.

  1. Log in to the BIG-IP system command line.
  2. To create a null file with the file name forceload in the /service/mcpd directory, type the following command:

    touch /service/mcpd/forceload

    On VIPRION systems, type the following command to run this command on all blades:

    clsh touch /service/mcpd/forceload

  3. To reboot the BIG-IP system, type the following command:

    reboot

    On VIPRION systems, type the following command to run this command on all blades:

    clsh reboot
