Known Issue

BIG-IP configurations fail to load after upgrading from 10.x to 11.x.

This issue occurs when all of the following conditions are met:

  • Your configuration contains a pool that is monitored by the default SMTP monitor.
  • You upgrade from BIG-IP 10.x to 11.x, or attempt to load a BIG-IP 10.x user configuration set (UCS) on a BIG-IP 11.x system.

In BIG-IP 10.x, you can associate the default SMTP monitor with a pool by using the bigpipe command. In BIG-IP 11.x and later versions, this is no longer a valid configuration option.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you attempt to install a BIG-IP 10.x UCS file on a BIG-IP 11.x system, the configuration does not load.
  • After you upgrade from BIG-IP 10.x to 11.x, the configuration does not load.
  • After loading the UCS file, you notice an error message that appears similar to the following example:

    BIGpipe unknown operation error: 01070712:3: Cannot use default monitor template (/Common/smtp) - ltm/validation/MonitorRule.cpp, line 351

Workaround

To work around this issue, you can boot back to the BIG-IP 10.x slot and then create a new monitor that is based off of the default SMTP monitor. After creating the new monitor, you can assign that monitor to the desired pool objects in place of the default SMTP monitor, and then proceed with the upgrade or UCS backup process.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
