Description
After upgrading to V16, the configuration fails to load with

Virtual Server(/Common/example_vs) cannot have Virtual-address(192.168.1.1) associated with different traffic groups.

Environment

  • Upgrading from V14 or V15
  • Using Shared Objects: Address Lists
  • Multiple Traffic Groups

Cause

  • When an Address List is applied to a Virtual Server, the BIG-IP creates Virtual-Addresses of each address listed.
  • Prior to V16, it was possible to subsequently edit the Virtual-Addresses so they are in different Traffic-Groups.
  • This is Invalid and may well cause other issues.
  • In V16 this cannot be done and a configuration containing this mismatch cannot be loaded.
     

Recommended Actions

Boot back to the prior version, ensure the virtual addresses are in the same traffic group, and re-perform the upgrade.

When you boot to the new boot location, use "Install Configuration"  yes on the Activate Boot Location to push the configuration forward.

Additional Information

To identify the affected virtual addresses in a large configuration the following tmsh commands may be helpful:

Find the traffic-matching criteria. These are created on using an address list with a Virtual Server. 
list ltm traffic-matching-criteria

ltm traffic-matching-criteria mybad_vip_VS_TMC_OBJ {
    destination-address-inline 0.0.0.0
    destination-address-list myaddresslist       <<---
    destination-port-inline http
    protocol tcp
    source-address-inline 0.0.0.0
}
Then find affected addresses.
list net address-list all

net address-list myaddresslist {
    addresses {
        192.168.1.100 { }
        192.168.2.200 { }
    }
}
Check these addresses to see if they are in the same Traffic-Group.
list ltm virtual-address  192.168.1.100

ltm virtual-address 192.168.1.100 {
    address 192.168.1.100
    mask 255.255.255.255
    traffic-group traffic-group-1
}
list ltm virtual-address  192.168.2.200

ltm virtual-address 192.168.2.200 {
    address 192.168.1.100
    mask 255.255.255.255
    traffic-group traffic-group-2  << Error!!
}
