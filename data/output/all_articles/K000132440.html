K000132440: [F5OS-C] etcd ClashLoopBackOff status and message log has "grep: /etc/etcd/etcd.conf: No such file or directory"

Type
Support Solution
Published
2023-02-09
Updated
2023-07-18
Source
https://my.f5.com/manage/s/article/K000132440

Description

etcd status goes CrashLoopBackOff status, the below command shows etcd status is CrashLoopBackOff

oc get pods | grep etcd*

Also on CLI of the affected controller, can not run the below script.

/etc/etcd/dump_etcd.sh

You can also observe the below logs repeatedly in /var/log/message

journal: grep: /etc/etcd/etcd.conf: No such file or directory
omd_container.sh: grep: /etc/etcd/etcd.conf: No such file or directory

Environment

  • F5OS-C
  • Velos
  • v1.x

Cause

  • unknown

Recommended Actions

Log in to CLI as root, and run the below command on both units

# ls -al /etc/etcd


Gather qkview from Acrtive controller (as this should gather Standby Controller qkview) with Max Files Size 1000

# su admin
# system diagnostics qkview capture maxfilesize 1000 filename

And escalate the issue to F5 Support with the command output and the qkview.

 

Additional Information

If the below command does not list  etcd.conf

ls -la /etc/etcd

 

Then to resolve the issue, rebuilding Openshift is required, it may take over 1.5 hours, and it will affect the tenants.

touch /var/omd/CLUSTER_REINSTALL


to check the installation is succeeding, monitor /var/log/openshift.log on both controllers.
