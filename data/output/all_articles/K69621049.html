K69621049: iControl REST POST call with source-path from a remote user with sufficient privilege may fail

Type
Support Solution
Published
2020-03-04
Updated
2023-02-21
Status

Applies to

  • BIG-IP LTM: 12.1.3
Source
https://my.f5.com/manage/s/article/K69621049

Description

iControl REST POST call with source-path from a remote user with sufficient privilege may fail

  • The call results with the following error message with the HTTP response code 400 is replied to the POST /mgmt/tm/sys/file/iFile iControl REST request.
    {
      "apiError": 26214401,
      "code": 400,
      "errorStack": [],
      "message": "Failed! exit_code (37).\n"
     }

  • The error is also recorded in /var/log/audit log file, similar to the following:
    Jan 31 11:21:08 ltm1213 notice icrd_child[11830]: 01420002:5: AUDIT - pid=11830 user=john folder=/Common module=(tmos)#status=[Unexpected Error: Failed! exit_code (37).] cmd_data=create sys file data-group /Common/mouton { separator := type string source-path file:///var/config/rest/downloads/datagroup.txt }

Environment

  • One of the following iControl REST calls:
    • POST /mgmt/tm/sys/file/data-group
    • POST /mgmt/tm/sys/file/ifile
    • POST /mgmt/tm/sys/file/ssl-key
  • Against BIG-IP version 12.1.3, AND
  • By a remote user (e.g., RADIUS, Active Directory) with administrator role, AND
  • Using Token Authentication, AND
  • With the request data with the source-path property file not readable by group and/or others (e.g., file permission is 600)

Cause

BIG-IP is fails to access the desired file due to permissions issue. F5 assigned Bug ID 874561 to this issue. It is fixed in BIG-IP 12.1.5. See Supplemental Document : BIG-IP 12.1.5.1 Fixes and Known Issues.

Recommended Actions

To fix the issue, execute one of the following workaround options:

  • Upgrade BIG-IP. The symptom is known to occur only on 12.1.3.
  • Change the permission of the file that the source-path designates. The file permission is most likely 600 (-rw-------) when you experienced the error. Change it to 644 (-rw-r--r--).
  • Use tmsh to perform the desired action. The equivalent tmsh command works with the same user.

To change the file permission on the device, use the following chmod command syntax:

chmod 644 <file>

To change the file remotely using iControl REST, using the following curl syntax:

curl -sku admin:<passswd> https://<host>/mgmt/tm/util/bash \
  -X POST -H "Content-Type: application/json"\
  -d '{"command":"run", "utilCmdArgs": "-c \"chmod 644
  <file>\""}'

Additional Information

The curl manual page describes the error code 37 as:

CURLE_FILE_COULDNT_READ_FILE (37)
A file given with FILE:// couldn't be opened. Most likely because the file path doesn't identify an existing file. Did you check file permissions?
