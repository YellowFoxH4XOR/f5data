Connection and persistence mirroring operation

The failover mechanism of a redundant system ensures that the peer BIG-IP system is available to process connections with little or no interruption in service at the time of the failure event. You can use the connection and persistence mirroring features on the BIG-IP system to duplicate a unit's state information to the peer unit. When failover occurs, connections can proceed as the peer system becomes active.

In BIG-IP LTM, the state mirroring mechanism is managed by the Traffic Management Microkernel (TMM) process, and connection data is synchronized to the standby unit with every packet or flow state update. The mirroring packets are tunneled from the active unit to the standby unit across the high-availability connection. The packets are then decapsulated by the standby unit and added to the connection table.

Note: If you run tcpdump on the standby system, it is possible to see Layer 7 mirroring traffic.

The BIG-IP LTM system uses a different transport protocol depending on the version of BIG-IP software you are running. The mirroring transport protocol was changed from TCP in version 9.1.0 to SCTP in version 9.2.0, and back to TCP in versions 9.3.0 and later.

The BIG-IP LTM system can mirror connection and persistence information as follows:

Connections

The BIG-IP LTM system can mirror TCP or UDP connections for the following Local Traffic objects:

  • Virtual server
  • SNAT

Persistence

The BIG-IP LTM system can mirror persistence information between peers for the following persistence profiles:

  • Destination address affinity
  • Hash
  • Microsoft Remote Desktop
  • SIP
  • Source address affinity
  • SSL
  • Universal

Configuring connection and persistence mirroring

Enabling connection mirroring for a virtual server

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click the virtual server for which you want to enable connection mirroring.
  5. From the Configuration drop-down menu, select Advanced.
  6. Check the Connection Mirroring check box.
  7. Click Update.

Enabling connection mirroring for a SNAT

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click SNATs.
  4. Click the SNAT for which you want to enable connection mirroring.
  5. Check the Stateful Failover Mirror check box.
  6. Click Update.

Enabling persistence mirroring

To enable persistence mirroring, select the Mirror Persistence check box in the relevant persistence profile.

Creating a new persistence profile

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click the Persistence menu.
  5. Click Create.
  6. Type a name for the profile.
  7. From the Persistence Type drop-down menu, select the persistence type most appropriate for your application.

    For example, to enable persistence for Microsoft Remote Desktop traffic, select Microsoft Remote Desktop from the drop-down menu.
  8. Select the Mirror Persistence check boxes.
  9. Click Finished.

You must now associate the new persistence profile with the virtual server.

Viewing connection and persistence mirroring data

Viewing mirrored connections from either the active or standby unit

  1. Log in to the command line.
  2. Type the following command:

    bigpipe conn mirror show all

Viewing mirrored persistence data from either the active or standby unit

  1. Log in to the command line.
  2. Type the following command:

    bigpipe persist show

Best practice recommendations

  • F5 recommends that you enable connection and persistence mirroring when the loss of a session, due to a BIG-IP LTM failover, would cause the user's session to be significantly disrupted.

    For example, where long-term connections such as FTP and Telnet are good candidates for mirroring, mirroring short-term connections, such as HTTP and UDP, is not recommended, as this will cause a decrease in system performance. In addition, mirroring HTTP and UDP connections is typically not necessary, as those protocols allow for failure of individual requests without loss of the entire session.
  • F5 recommends that you disable mirroring when the standby unit in a redundant pair is offline. For more information, refer to K12370: Memory usage on an active unit may significantly increase when mirroring is enabled and the standby unit is offline.
  • Only FastL4 and SNAT connections are re-mirrored after failback.
  • You cannot currently mirror Secure Sockets Layer (SSL) connections that are terminated by the BIG-IP LTM system. For information about why the BIG-IP LTM system does not support connection mirroring for SSL terminated traffic, refer to K7216: BIG-IP support for SSL connnection mirroring.
