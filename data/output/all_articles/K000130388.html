K000130388: VELOS PXE clean install of compute blade

Type
Support Solution
Published
2022-12-28
Updated
2026-02-04
Applies to
  • F5OS
  • VELOS Platforms
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000130388

Description

You should consider using these procedures under the following condition:

  • You would like to clean install the compute blade installed in your chassis using the internal PXE server.

Environment

  • F5OS-C
  • Clean install
  • Compute Blade
  • VELOS
  • PXE

Cause

None

Recommended Actions

1. SSH from the system controller Bash Shell into the target blade. We will use blade-1 as an example in this article.
[root@controller-2 ~]# ssh blade-1.chassis.local
2. From the blade-1 Bash Shell determine the current boot devices and take note of boot index that is highlighted as shown below: 
[root@blade-1 ~]# efibootmgr
BootCurrent: 0003
Timeout: 3 seconds
BootOrder: 0003,0001,0002
Boot0001* UEFI: PXE IP4 Intel(R) Ethernet Connection X722 for 10GbE backplane
Boot0002* UEFI: PXE IP4 Intel(R) Ethernet Connection X722 for 10GbE backplane
Boot0003* UEFI: SAMSUNG MZ1LB960HAJQ-00007, Partition 1
MirroredPercentageAbove4G: 0.00
MirrorMemoryBelow4GB: false
3. Determine the boot index of the internal network NIC, discarding the leading zeros and select it as the first boot device: 
[root@blade-1 ~]# efibootmgr -n 1
BootNext: 0001
BootCurrent: 0003
Timeout: 3 seconds
BootOrder: 0003,0001,0002
Boot0001* UEFI: PXE IP4 Intel(R) Ethernet Connection X722 for 10GbE backplane
Boot0002* UEFI: PXE IP4 Intel(R) Ethernet Connection X722 for 10GbE backplane
Boot0003* UEFI: SAMSUNG MZ1LB960HAJQ-00007, Partition 1
MirroredPercentageAbove4G: 0.00
MirrorMemoryBelow4GB: false
4. Proceed to reboot the blade: 
[root@blade-1 ~]# systemctl reboot
Shared connection to blade-1.chassis.local closed.
5. The blade will PXE boot and clean install. Once the blade is re-installed, the Orchestration Manager will add the blade to the cluster and once this is completed, the Orchestration Agent will re-launch any tenants scheduled to run on the newly re-installed blade. The time to completion is dependent on the number of tenants running on the blade. From the Management CLI, run the following to watch the status of the blade: 
syscon-2-active# show cluster nodes | repeat 5
