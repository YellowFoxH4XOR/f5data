K72589011: Latency is observed under heavy SSL traffic conditions

Type
Support Solution
Published
2021-02-01
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K72589011

Description

Under heavy SSL traffic, sw crypto codec queue is stuck and taken out of service without failover.

The following ltm logs may be observed:

crit tmm3[20908]: 01010025:2: Device error: crypto codec Request already complete.
crit tmm2[20908]: 01010025:2: Device error: crypto codec No codec available to initialize request context.

When you issue the command tmctl crypto_codec_status  it may display 0 in the active column for one  or more of the sw crypto queues:

Example:

tmctl crypto_codec_status
name        active def bulk pk pkecc ka kaecc kdf
----------- ------ --- ---- -- ----- -- ----- ---
sw_crypto-0      1   0    0  0     0  0     0   0
sw_crypto-1      0   0    0  0     0  0     0   0    <==== the active value is 0 for sw_crypto-1

Environment

  • BIG-IP
  • SSL Profile
  • BIG-IP Versions 12.1 to 12.1.4.1

Cause
Bug ID 745405

Recommended Actions

  • Upgrade to a version listed in the Fixed section of the Bug Tracker article.
  • Follow the suggested workaround in the Bug Tracker article.
  • To clear the stuck software crypto queue a reboot is required.
