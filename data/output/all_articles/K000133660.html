Description

  • You may find the SSL handshake failed with the error "Connection error: ssl_select_suite:10023: alert(86) TLS_FALLBACK_SCSV with a lower protocol", even the TLS Fallback Signaling Cipher Suite Value (SCSV) function is enabled, for the detailed description for the function of TLS Fallback SCSV please check K1693.

  • This article helps you to introduce the different combinations of TLS Fallback Signaling Cipher Suite Value (SCSV) and SSL profile protocol versions which could trigger the Bug ID 883133: TLS_FALLBACK_SCSV with TLS1.3, for example:

  1. The BIG-IP virtual server is configured for supporting TLS1.3, and the client is configured for supporting TLS1.0, TLS1.1, and TLS1.2, and this combination is described from Bug ID 883133: TLS_FALLBACK_SCSV with TLS1.3.
  2. The BIG-IP virtual server is configured for supporting TLS1.3, and the client is configured for supporting TLS1.0, TLS1.1, TLS1.2, and TLS1.3, and this combination should also trigger this bug.
  3. The BIG-IP virtual server client SSL profile supports TLS1.2,  the Client supports TLS1.0, TLS1.1, TLS1.2, and TLS1.3, this combination is found from a support case, you may know the client supports the TLS1.0 to TLS1.3 from the below picture: 

Environment

  • Client side SSL profile.
  • TLS Fallback SCSV functions are enabled from both of the BIG_IP and the client.
  • The different combinations of TLS Fallback Signaling Cipher Suite Value (SCSV) on the client support SSL version and the virtual server's SSL profile protocol versions.

Cause

Bug ID 883133: TLS_FALLBACK_SCSV with TLS1.3

Recommended Actions

There is no workaround for the issue, but you may request the engineering hotfix or you may upgrade to at least v16.1.x for the permanent fix.

Additional Information

You may need to check your virtual server's client-side SSL profile configuration then you can know the supported SSL version from your virtual server.
