Known Issue

A configuration load fails when it contains a BIG-IP LTM policy, and there is an iRule that contains a commented line that ends with an escape character (backslash).

This issue occurs when the following conditions are met:

  • The configuration contains a BIG-IP LTM policy.
  • An iRule contains a commented line that ends with a backslash.

For example, a configuration load fails when there is a policy similar to the first example and an iRule similar to the second example.

ltm policy /Common/Test_Policy {

controls { forwarding }
requires { http tcp }
rules {

TestPol_Rule1 {

actions {

0 {

forward
select
node 10.2.10.20

}

}

conditions {

0 {

tcp
address
matches
values { 10.1.10.20 }

}

}

}

}

strategy /Common/first-match

}

...

ltm rule /Common/log_info {

when HTTP_RESPONSE {

#log local0. "Original Location header value: [HTTP::header value Location],\
updated: [string map ":[TCP::remote_port]/ /" [HTTP::header value Location]]"

}
}

Impact

The configuration load fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A configuration load fails.
  • Some iRules display an error message similar to the following example:

    Syntax Error:(/config/bigip.conf at line: 42078) double quotes are not balanced.

Workaround

To work around this issue, you can perform one of the following actions:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

  • Delete the line of code with the comment.
  • Put the entire comment on one line of code.
  • Divide lengthy comments into a series of smaller ones, so that each comment fits within one line of code.
  • Modify the /config/bigip.conf file to move the iRule sequentially before the LTM policy.
