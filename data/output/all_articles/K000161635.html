K000161635: BIG-IP TMOS 17.5.1.6 EHF upgrade fails with “Failed to start Jitterentropy Gatherer Daemon” error

Type
Support Solution
Published
2026-06-08
Updated
2026-09-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161635

Description

After installing BIG-IP TMOS Engineering Hotfix build 17.5.1.6 Build 0.39.25 on virtualized BIG-IP TMOS instances, including F5OS tenants, vCMP guests, and BIG-IP Virtual Edition, or on non-iSeries hardware deployments, the device may fail to boot and display the following error:

Failed to start Jitterentropy Gatherer Daemon

TMOS does not start successfully after the upgrade. When accessing the device through SSH, you may be left at the maintenance prompt:

root::

In some cases, the device GUI may still be accessible, and SSH access may also be available, but functionality may be limited.

Environment

  • Virtualized BIG-IP TMOS instances, including F5OS tenants, vCMP guests, and BIG-IP Virtual Edition
  • Non-iSeries hardware deployments
  • BIG-IP TMOS Engineering Hotfix build 17.5.1.6 Build 0.39.25

Cause

The specific Engineering Hotfix was built to address Bug ID2291757 on iSeries platforms. However, when this fix is applied to other platforms, it can cause a boot failure due to insufficient space on the `/usr` filesystem during the upgrade. For background information on ID2291757, refer to K000161170.

Two bugs are involved:

  • Bug ID2291757: This issue affects iSeries appliances when upgrading to 17.5.1.6.
  • Bug ID2296269: The fix for Bug ID2291757 introduced a boot failure on non-iSeries platforms or virtualized instances, causing the “Jitterentropy Gatherer Daemon” to fail and preventing the system from booting into TMOS.

The fix for Bug ID2291757 was originally provided as Engineering Hotfix 17.5.1.6 Build 0.39.25, which appears on MyF5 Downloads as:

Hotfix-BIGIP-17.5.1.6.0.39.25-ENG.iso

When this hotfix is applied to BIG-IP Virtual Edition, vCMP guests, F5OS tenants, or other non-iSeries platforms, it can cause a boot failure. This issue is now tracked as Bug ID2296269.

The fix for Bug ID2296269 is included in a newer EHF, which appears on MyF5 Downloads as:

Hotfix-BIGIP-17.5.1.6.0.67.25-ENG.iso

Answer/Recommended Actions

Install the newer Engineering Hotfix (EHF) to resolve the boot failure:

  1. If the system is already booted into 17.5.1.6 and is experiencing SSH or login issues, roll back to the previous version by activating the previous boot location through the GUI (TMUI) or CLI.
  2. Sign in to MyF5 and accept the EULA.
  3. Navigate to the BIG-IP / BIG-IP v17.x / 17.5.1-LTS / 17.5.1.6 download page on MyF5.
  4. Download the newer EHF file: Hotfix-BIGIP-17.5.1.6.0.67.25-ENG.iso.
  5. Copy the EHF ISO to the target system.
  6. Copy the base ISO to the system if it is not already present: BIGIP-17.5.1.6-0.0.25.iso.
  7. Install the EHF to the target boot volume. The EHF can be installed to the same boot location where 17.5.1.6 was previously installed; it will overwrite the existing installation in that boot location.
  8. Boot into the EHF volume.
  9. Verify that the system boots successfully.

Note: Devices in an HA pair may fail to sync after an attempted upgrade, even after rolling back to an earlier version. This issue persists until the configuration is reloaded or both devices are upgraded to 17.5.1.6. For more information, refer to K000161569.
