Known Issue

This is the result of a known issue. The big3d process leaks memory during monitor probe responses for Host virtual servers. The big3d memory leak can occur with all monitor responses for Host virtual server probes except SNMP monitor responses. When this issue occurs, you may observe the BIG-IP GTM or Link Controller system intermittently marking Host virtual servers up and down.

F5 Product Development tracked this issue as CR93994 and it was fixed in BIG-IP GTM and Link Controller 9.4.5. for information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF3 issued for BIG-IP GTM and Link Controller 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

If you have determined that the big3d process is leaking memory, you can temporarily work around the issue by running the bigstart restart big3d command from the BIG-IP GTM or Link Controller command line.
