Known Issue

Importing BIG-IP APM Security Assertion Markup Language (SAML) metadata may fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as an SAML service provider (SP).
  • The External IdP Connector is configured for SAML single logout (SLO).
  • You attempt to import the metadata into an external SAML Identity Provider (IdP) system.

When exporting BIG-IP APM SAML SP metadata, the <SingleLogoutService> element appears below the <AssertionConsumerService> element, which may cause a problem when importing to some SAML IdP implementations. The Original OASIS SAML 2.0 Standard specifies the sequence of non-optional metadata elements in the <SPSSODescriptor> element, as follows:

<ArtifactResolutionService>
<SingleLogoutService>
<ManageNameIDService>
<NameIDFormat>
<AssertionConsumerService>
<AttributeConsumingService>

Impact

BIG-IP APM SAML metadata may fail to import correctly.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Importing BIG-IP APM SAML metadata fails with an "Unexpected element" error message.
  • The external SAML IdP system is unable to authenticate users for the SAML SP service.

Workaround

To work around this issue, you can directly edit the exported XML file before importing. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Using an XML editor, open the exported metadata XML file for editing.
  2. Locate the <SingleLogoutService> element.
  3. Move the entire element string, including opening and closing tags, so it appears in the correct order of elements, as previously shown.

    Note: Be sure to retain proper XML formatting when editing the metadata file.

  4. Save the changes and re-import the metadata.
