K000162908: Persistence is not maintaining session affinity with Microsoft Entra ID

Type
Support Solution
Published
2026-08-13
Updated
2026-08-13
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162908

Description

You observed that Source Address persistence was not maintained on a virtual server when user sessions were authenticated via Microsoft Entra ID. Multiple source IP addresses can be observed for the same user session, resulting in traffic being distributed across different backend servers and breaking application continuity. 

Environment

  • Source Address persistence profile configured on the affected virtual server
  • Client authentication via Microsoft Entra ID

Cause

Source Address persistence relies on a consistent client source IP address. Entra ID Application Proxy can proxy requests for the same user session through multiple source IP addresses. BIG-IP therefore creates or uses separate persistence records for each source IP, preventing consistent session affinity.

This is expected behavior when the source address changes.

Answer/Recommended Actions

  1. Switch from Source Address persistence to Cookie persistence on the affected virtual server, as Cookie persistence uses HTTP cookies and does not depend on the client source IP.
  2. Review and select the persistence method that best fits the application’s requirements when using cloud identity providers that proxy connections.

None.
