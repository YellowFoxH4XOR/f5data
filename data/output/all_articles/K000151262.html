Description

When deploying or starting a BIG-IP tenant on F5OS rSeries platforms, the tenant may fail to start and remain stuck in a "starting" or "deployed" state. The system may reports below logs

  • Message log (var/log/messages) reports
    "Unable to authenticate the request" err="[invalid bearer token, Token has expired.]"
  • k3s event log (/var/F5/system/log/k3s_events.log) reports
  • 2025-05-10 03:33:31.462535 - 8:-1249925376 - Event Updated: Pod/virt-launcher-tenant-1-b22qd UID: .... OLD_TYPE: Warning NEW_TYPE: Warning OLD_REASON: FailedCreatePodSandBox NEW_REASON: FailedCreatePodSandBox OLD_LOG: Failed to create pod sandbox: rpc error: code = Unknown desc = failed to setup network for sandbox ".....": Multus: [default/virt-launcher-tenant-1-b22qd]: error getting pod: Unauthorized NEW_LOG: Failed to create pod sandbox: rpc error: code = Unknown desc = failed to setup network for sandbox "....": Multus: [default/virt-launcher-tenant-1-b22qd]: error getting pod: Unauthorized
  • show tenant reports

  • show service-pods reports
    # show service-pods

Environment

  • F5OS Appliance

Cause

  • ID1694481
  • The issue is caused by an expired Multus service account bearer token. When the token expires, the Multus CNI plugin cannot authenticate with the Kubernetes API, resulting in "Unauthorized" errors and failure to set up pod networking. This blocks the deployment or startup of BIG-IP tenants.

Recommended Actions

  • Follow the workaround on the bug page ID1694481 or upgrade to fixed version
  • Open support ticket to check the validity of the Multus service account token. If expired, refresh or recreate the token.
