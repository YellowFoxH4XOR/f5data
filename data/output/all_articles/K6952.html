K6952: Certificate warning countdown freezes using Standalone SSL VPN client

Topic

When using the F5 VPN Client for Windows, (also called the Standalone Client)  if a Security Alert: Server certificate verification error warning pop-up window appears upon logging in to FirePass, the countdown may briefly freeze if no user input for the certificate warning is received.

Important: This issue occurs only when the F5 VPN Client is used in Simple Mode. The freeze does not occur when the F5 VPN Client is in Advanced Mode. The mode is set from the View menu in the F5 VPN Client in current versions, or View >> Settings in older versions of the Client.

The certificate warning window is a result of one or more SSL error conditions with the FirePass SSL server certificate, such as an expired certificate, or a user accessing the FirePass with a name or IP address that is not the same as the server name in the certificate. The window contains three buttons:View certificate, Yes and No (3:00). The No (3:00) option counts down from three minutes in increments of one second. The freeze will occur approximately 30 seconds or 90 seconds (depending on your version of the F5 VPN Client) after the security alert window appears. The countdown in the middle button of the security alert window will stop counting the seconds while the freeze occurs, and resume when the freeze is finished.

The freeze coincides with the F5 VPN Client displaying an error message similar to the following example:

The remote computer did not respond. For further assistance, click More Info or search Help and Support Center for this error number.

However, the security alert window typically covers the F5 VPN Client, blocking the F5 VPN Client's error message from view unless the security alert window is dragged to another location on the Windows Desktop.

If you supply input by clicking one of the buttons in the security alert window prior to the freeze, the F5 VPN Client will operate normally. Alternatively, installing a valid server certificate will prevent this issue from occurring. Ensure that you access the FirePass using the same name as the Common Name in the certificate.
