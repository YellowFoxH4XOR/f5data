K000135976: Getting CrashLoopBackOff error for aspen-mesh-event-storage

Published

Updated

Applies to

Source

Description

Getting CrashLoopBackOff error for aspen-mesh-event-storage:

NAME                                 READY STATUS            RESTARTS         AGE
aspen-mesh-event-storage-0           1/1   Running           0                18h
aspen-mesh-event-storage-1           0/1   CrashLoopBackOff  117 (2m51s ago)  18h

 

Container logs show:

This node was decommissioned and will not rejoin the ring unless cassandra.override_decommission=true has been set, or all existing data is removed and the node is bootstrapped again.
Fatal configuration error; unable to start server. See log for stacktrace.

 

 

Environment

Aspen Mesh 1.11.x
Aspen Mesh Event Storage
 

Cause

The Cassandra database node running in aspen-mesh-event-storage pod was not removed correctly.
 

Recommended Actions

Scale the statefulset to 0 and then delete the PVC and PV (with dynamic provisioning, the PV should be deleted automatically after deleting the PVC, otherwise please make sure to delete the PV and provision a new one).

kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=0
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-0
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-1
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-2

Delete PVs associated to the data-aspen-mesh-event-storage-* PVCs

kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=3

 

 

Additional Information

The aspen-mesh-event-storage pods use Cassandra as an underlying database.
Aspen Mesh Event Storage and Metrics collector are deprecated features that have been removed from Aspen Mesh 1.14 and may be removed in a later release.
