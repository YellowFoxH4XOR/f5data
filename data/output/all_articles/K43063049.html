Topic

You should consider using this procedure under the following condition:

  • You want to configure BIG-IP APM Kerberos SSO constrained delegation for Windows domain user access to multiple applications.
  • You are using Active Directory (AD) as your key distribution center (KDC) with IIS.
  • You have configured a virtual server with a BIG-IP APM access policy that includes Kerberos authentication.
  • Your client devices are joined to the domain and users are logged in with their domain-user accounts.

Description

In Kerberos SSO constrained delegation, the BIG-IP APM system first authenticates users by requesting their credentials once and thereafter reusing the cached identity to seamlessly log the user in to the secured web applications. The main components of Kerberos SSO on the BIG-IP APM system, apart from the virtual server, are the following:

  • A Kerberos SSO configuration object.
  • An initial authentication mechanism to first identify the user in your access policy. For example a logon page with AD authorization.
  • A resource that calls the Kerberos SSO object. For example, an access profile, an iRule (WEBSSO::select command), a portal access resource, an Exchange profile, and so on.

    Note: This article describes how to configure a portal access resource to call the Kerberos SSO object.

  • An SSO credential mapping assignment in an access policy.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility of the BIG-IP APM system.
  • You have access to the Configuration utility of the Windows domain controller and IIS.

Configuring time synchronization, DNS, and network connectivity on the BIG-IP APM system

A functioning time and DNS network environment is essential for Kerberos to work, so ensure the following:

  • Your BIG-IP APM device's time is synchronized to a time source.

    Note: Manually verifying that the times between the systems are within 5 minutes of one another is not sufficient. The system's times must be synchronized to a network time protocol (NTP) server.

  • Forward DNS resolution of the domain controller hostname and web server are configured.
  • Reverse DNS resolution of the IP addresses of the domain controller and web server are configured.

    Note: Alternatively, if you have multiple domain controllers, you can configure SRV DNS records so that your BIG-IP APM system discovers the domain controllers.

  • TCP and UDP ports 88 are open between the BIG-IP APM system and the domain controllers.

Creating an AD service account with Kerberos constrained delegation

You need to create a delegation account and register a host service principal name (SPN) to the account, then configure Kerberos constrained delegation for the account to the service provided by the web server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in and open AD Domain Services (AD DS) on your Windows domain controller.
  2. Create a new user account with attributes similar to the following example:
    • First name: John
    • Full name: John Smith
    • User logon name: host/apm.example.com
    • User logon name (pre-Windows 2000): : samaccountname
    • Password never expires: Select the check box.
  3. Register the host SPN for the account using the following syntax on the Windows command line:

    setspn -A host/<name>.<domain> <samaccount_name>

    Note: host/<name>.<domain> is the User logon name of the account you created in step 2, and <samaccount_name> is the User logon name (pre-Windows 2000). For example: setspn -A host/apm.example.com samaccountname.

  4. Verify the SPN is registered by using the following command syntax:

    setspn -L <samaccount_name>

    For example:

    setspn -L samaccountname

  5. Verify that there are no duplicate names by typing the following command:

    setspn -X

  6. To configure Kerberos constrained delegation, perform the following steps:
    1. Open the user account and click the Delegation tab.
    2. Click Trust this user for delegation to specified services only.
    3. Click Use any authentication protocol and add all your services to the list under Services to which this account can present delegated credentials.
      Note: The option Use Kerberos only is not supported, and will break your environment.
      Every service should have Service Type HTTP (or http) and host name of the pool member or web application resource host that you will use in your configuration.
    4. Click Add .
    5. Click Users or Computers.
    6. Enter the hostname of your web server and click OK.
    7. Select the row where Service Type is HTTP and click OK to add the HTTP/webserver.example.com service for Kerberos constrained delegation.
    8. Click OK

To verify the names for the account you created, from the BIG-IP APM command line, enter the following adtest command syntax:

adtest -t query  -r "<REALM>" -A <user> -W <password> -u <kerberos_delegation_account> -d 1 -g true -G true | grep 'domain name\|Delegate'

Note: <user> refers to any user in AD with read permissions and <password> refers to the corresponding user password.

For example, for the account created previously, run the following command:

adtest -t query  -r "EXAMPLE.COM" -A host/apm.example.com -W 'pass' -u samaccountname -d 1 -g true -G true | grep -i 'domain name\|Delegate'

Output appears similar to the following:

Test done: total tests: 1, success=1, failure=0
domain name = 'EXAMPLE.COM'
msDS-AllowedToDelegateTo: | http/webserver.example.com/example.com | http/webserver.example.com | http/WEBSERVER | http/webserver.example.com/EXAMPLE | http/WEBSERVER/EXAMPLE |
[...]
sAMAccountName: samaccountname
servicePrincipalName: host/apm.example.com
userPrincipalName: host/apm.example.com@example.com

Verify that the names are correct and that the msDS-AllowedToDelegateTo value has the http service your webserver is providing.

Enabling integrated authentication on your IIS web application

Only IIS servers are supported for pool members or web application resources on the BIG-IP APM system. Set up the following configurations for IIS for your website:

Note: Refer to your IIS documentation for the configuration steps. Depending on your web application and IIS version, the steps may differ. For example if your application is Exchange Online Web Access (OWA), for some versions you should configure using the Exchange Control Panel rather than the IIS administrative console.

  • Disable Anonymous Authentication.
  • Enable Windows Authentication.
  • Ensure that Negotiate:Kerberos is at the top of the Enabled Providers for Windows Authentication list.
  • If you have a load-balanced environment with multiple web servers in which, for example, users access app.example.com instead of server1.example.com or server2.example.com , you should configure the application pool to run using the AD service account. For more information, refer to Kerberos and Load Balancing.

    Note: The previous link takes you to resources outside of AskF5. The third party could remove the documents without our knowledge.

You should first configure and verify that IIS Kerberos authentication works correctly directly without the BIG-IP APM system. Ensure that the successful SSO is not due to NTLM or basic authentication. You can do this by selecting only Negotiate:Kerberos in the Enabled Providers list, without NTLM and basic authentication being enabled.

Creating a Kerberos SSO object

On the BIG-IP APM system, the configuration settings that matches the configuration on the domain controller are in the Kerberos SSO object. To create a Kerberos SSO object, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Single Sign-On > Kerberos.

    Note: For BIG-IP 12.x or earlier, navigate to Access Policy > SSO Configurations > Kerberos.

  3. Click Create
  4. Enter an appropriate name.
  5. For Kerberos Realm, type your realm in uppercase. For example: EXAMPLE.COM.
  6. For KDC, enter the IP address or hostname of your domain controller. If you leave this empty, the KDC must be discoverable through DNS using an SRV record.
  7. For Account Name, you must enter the same User logon name of the service account you created in step of the Creating an AD service account with Kerberos constrained delegation procedure, using the following command syntax:

    host/<name>.<domain>

    For example:

    host/apm.example.com

  8. Enter the account password.
  9. For SPN pattern, you may leave it blank. If you do, the name of the web service that the BIG-IP APM system requests to access is derived from msDS-AllowedToDelegateTo , which you configured in the Creating an AD service account with Kerberos constrained delegation procedure. Using the examples in this article, you may optionally specify the same name. For example:

    HTTP/webserver.example.com@EXAMPLE.COM

  10. Click Update.

Creating a portal access resource with Kerberos SSO

Configure a portal access resource to call the Kerberos SSO object. To configure the portal access resource, perform the following procedure:

Note: You can achieve configure a portal access resource to call the Kerberos SSO object by associating it with your access profile or using an iRule or an Exchange profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Connectivity / VPN > Portal Access > Portal Access Lists.

    Note: For BIG-IP 12.x or earlier, navigate to Access Policy > Portal Access > Portal Access List.

  3. Click Create.
  4. Enter a name for the resource.
  5. For Link Type, click Application URI.
  6. For Application URI, enter the URI of the web application on your server. For example:

    https://webserver.example.com/owa

  7. Click Create.
  8. For Resource Items , click Add to add the Kerberos SSO object you created in the previous procedure as a resource item.
  9. Under New Resource Item, for Link Type, click Paths.
  10. For Destination, enter either the application server's hostname or IP address. For example:

    webserver.example.com

    Note: If you enter an fully qualified domain name (FQDN), it must be resolvable by DNS on the BIG-IP system.

  11. For Paths, enter a path or list of paths separated with spaces that you want the BIG-IP APM system to trigger Kerberos SSO. For example:

    /owa*

  12. For SSO Configuration, click the Kerberos SSO object you created earlier.
  13. Click Update.
  14. Create a webtop to host the portal access resource by navigating to Access > Webtops > Webtop Lists.

    Note: For BIG-IP 12.x, navigate to Access Policy > Webtops.

  15. Click Create.
  16. Enter a name for the webtop.
  17. For Type, to host a portal access resource, click either Full or Portal Access. Click Full when you need to host other resources on the webtop.
  18. Click Finished.

Creating an access profile with an access policy with SSO credential mapping

BIG-IP APM stores usernames and passwords in APM session variables. By default, Kerberos SSO retrieves the username from the session variable session.sso.token.last.username. To enable the population of this session variable, you need to include the SSO credential mapping assignment object in your access policy. For more information refer to K11629: Configuring single sign-on credentials using session variables from the Logon page.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).

    Note: For BIG-IP 12.x, navigate to Access Policy > Access Profiles > Access Profiles List.

  3. Click Create
  4. Enter a name for the access profile.
  5. For Profile Type, click All.
  6. Under Language Settings, click one or more languages in the Factory Builtin Languages list and move it to the Accepted Languages list.
  7. Click Finished.
  8. For the access profile you just created, in the Per-Session Policy column, click Edit to modify the policy in the Visual Policy Editor (VPE).
  9. On the fallback branch, click the Add icon (+).
  10. On the Logon tab, click Logon Page and click Add Item.
  11. Make any changes appropriate for your environment, and click Save.
  12. On the fallback branch of the Logon Page policy item, click the Add icon (+).
  13. Click the Authentication tab and add an appropriate authentication mechanism. For example, AD Auth.
  14. Click Add Item , make any appropriate configuration changes to the properties, and then click Save .
  15. On the Successful branch of your authentication policy agent, click the Add icon (+).
  16. Click the Assignment tab, click Advanced Resource Assign , and click Add Item.
  17. Click Add new entry, then click Add/Delete.
  18. Click the Webtop tab and click the webtop you created earlier.
  19. Click the Portal Access tab and click the portal access resource that you created earlier.
  20. Click Update then click Save.
  21. On the fallback branch of the Advanced Resource Assign policy item, click the Deny endpoint, click Allow and click Save.
  22. Click Apply Access Policy .

Creating a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click Create, and enter a name for the profile.
  4. For Destination Address/Mask, type the virtual server IP address.
  5. For Service Port, type 443 or click https.
  6. For the SSL Profile (Client) and SSL Profile (Server), click the appropriate profiles. For example, clientssl and serverssl.
  7. For HTTP Profile, click an appropriate HTTP profile. For example, http
  8. For Source Address Translation, click Auto Map if your environment requires it.
  9. For Rewrite Profile, click rewrite.
  10. Under Access Policy , for Access Profile, click the access profile you created in the Creating an access profile with an access policy with SSO credential mapping procedure.
  11. For Connectivity Profile, click an appropriate profile. If you do not have one, click the Add icon (+) to create a new one.
  12. Click Finished.
