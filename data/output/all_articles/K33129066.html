Description

HTTP / HTTPS Virtual Server will forward HTTP requests to the pool members only if the client request contains an FQDN on the host header and not an IP address.

Environment

  • iRules
  • Permit FQDN only access to HTTP / HTTPS virtual

Cause

None

Recommended Actions

Use an iRule similar to the following example, in order permit FQDN only access to an HTTP / HTTPS Virtual Server:

  1. Navigate to Local Traffic > iRules > iRule List, click Create
  2. Create an iRule with similar code as below:

    when HTTP_REQUEST {
        if { ([HTTP::host] != "www.example.com") } {
           reject
        }
    }

    Alternatively, if you would like to permit multiple FQDNs, you can use an iRule like the one below. Just add or remove if / else statements according to your needs:

    when HTTP_REQUEST {
        if { ([HTTP::host] == "www.example.com") } {
            # Do nothing, meaning permit request
        } elseif { ([HTTP::host] == "web.example.com") } { 
            # Do nothing, meaning permit request   
        } elseif { ([HTTP::host] == "access.example.com") } { 
            # Do nothing, meaning permit request   
        } else {
            # If the host header does not contain any of the previously matching values then reject the request
        reject
        }
    }

    If you want to permit large numbers of FQDNs, one method is to put the FQDNs in a data group and reference them via the data group in an iRule similar to the one below:

    when HTTP_REQUEST {
        if { [class match [HTTP::host] equals "K33129066-datagroup"] } {
            # Do nothing, meaning permit request
        } else {
                # If the host header does not contain any of the matching values in the data group then reject the request
            reject
        }
    }

    This method allows you to add/delete FQDNs to the data group without modifying the iRule:

    ltm data-group internal K33129066-datagroup {
        records {
            access.example.com { }
            web.example.com { }
            www.example.com { }
        }
        type string
    }

  3. Attach the iRule to the Virtual Server serving this site.

Note: These are just example iRules and thorough tests are suggested before making use of it on a production environment.
