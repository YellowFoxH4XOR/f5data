Description

You're trying to create a CNAME record for the root zone or apex (mydomain.org) in ZoneRunner. No errors encountered but the record doesn't appear in the Resource Records List.

Environment

  • BIG-IP DNS
  • Configuration Utility (ZoneRunner)
  • Adding a CNAME record for the root zone
For Example:
 
mydomain.org.    3600    IN    SOA      dns1.mydomain.org.
mydomain.org.    3600    IN    NS       dns1.mydomain.org.
mydomain.org.    3600    IN    NS       dns2.mydomain.org.
mydomain.org.    3600    IN    MX       10 mail.mydomain.org.
...
mydomain.org.    3600    IN    CNAME    www.otherdomain.org.
 

Cause

RFC1034 states that if a CNAME RR is present at a node, no other data should be present; this ensures that the data for a canonical name and its aliases cannot be different.
RFC2181 states that an alias name (label of a CNAME record) may, if DNSSEC is in use, have SIG, NXT, and KEY RRs, but may have no other data.
Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Since a zone apex is where the SOA and NS (and often MX) records for a DNS zone are placed, creating a CNAME record for the root zone will not conform with the RFCs.

Recommended Actions

You will not be able to add this type of record in this scenario. This is by design.

One of the alternatives is to do a webserver redirection, which is to set up a webserver for mydomain.org that will return a web redirect (HTTP 3xx) to www.otherdomain.org.
