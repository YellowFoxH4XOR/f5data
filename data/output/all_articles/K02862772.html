Description

You received a learning suggestion to increase the Maximum Decoding Pass Attempts, but the request that generated the suggestion is already decodable within the currently configured number of passes.

For example, with the following request:

GET /Home?t=prod&errmsg=Invalid%252520Login HTTP/1.1

A space character has been encoded three times and therefore requires three decoding passes.

%252520 --> %2520 --> %20 --> ' '

If the security policy is set to a maximum of 3 decoding passes, a learning suggestion may recommend increasing the maximum passes to 4 upon receiving this request.

Environment

  • Security policy
  • URL encoded request

Cause

This is expected behaviour.

The violation occurs on the specified number of passes, so it's not a maximum number of allowed decoding passes, but a limit that will trigger the violation after that number of passes.

Recommended Actions

Increase the Maximum Decoding Pass Attempts, either manually or by accepting the learning suggestion.

With the example given in this article, setting the number to 4 would be appropriate, as 3 passes are needed to fully decode the request. More would be considered an evasion attempt.
