Known Issue

Important: This solution only applies to the 2400 platform.

This is the result of a known issue. When an Enterprise Manager system performs a discovery or refresh on a BIG-IP 2400 platform, the following error messages are logged in the /var/log/messages file:

May 1 10:59:08 A1000 VFS: busy inodes on changed media.
May 1 10:59:08 A1000 VFS: busy inodes on changed media.
May 1 10:59:08 A1000 VFS: busy inodes on changed media.

Note: The message is logged three times for each discovery or refresh performed by the Enterprise Manager system. The messages do not indicate a failure.

F5 Networks Product Development tracked this issue as CR78856 and it was fixed in BIG-IP version 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, or Link Controller Release Notes.

Workaround

You can work around this issue by preventing the syslog-ng utility from logging error messages that cause unnecessary consumption of disk space. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Change directories to the /etc/syslog-ng directory by typing the following command:

    cd /etc/syslog-ng

  3. Back up the original syslog-ng.conf file by typing the following command:

    cp syslog-ng.conf syslog-ng.conf.sol7538

  4. Using a text editor, edit the syslog-ng.conf file.
  5. Locate the f_kern filter similar to the following example:

    filter f_kern {
    facility(kern) and level(notice..emerg);
    };

  6. Change the f_kern filter to the following code:

    filter f_kern {
    facility(kern) and level(notice..emerg)
    and not match("VFS:busy inodes on changed media");
    };

  7. Save the syslog-ng.conf file.
  8. Restart syslog-ng by typing the following command:

    bigstart restart syslog-ng
