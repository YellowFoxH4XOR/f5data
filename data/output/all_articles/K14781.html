Known Issue

BIG-IP APM client operating system detection may not correctly detect Windows 8.1.

This issue occurs when all of the following conditions are met:

  • An access policy is configured to run client operating system or device detection.
  • Users connect to the access policy through one of the following:
    • Windows 8.1 inbox VPN client
    • Windows 8.1 phone OS

Microsoft introduced the Windows inbox VPN framework for the Windows 8.1 operating system. Third-party vendors can create a VPN plug-in that communicates with the Windows inbox VPN framework so that clients and administrators can easily create and deploy VPN connections, removing the need for clients to install separate client software packages.

The F5 plug-in is designed to work with the Windows inbox VPN framework. Windows client€™s can create the VPN connections using Windows network settings. All that is required to configure the Windows inbox VPN is the IP address or FQDN to access the BIG-IP APM system and the client's credentials. The plug-in authenticates and encapsulates and de-encapsulates all of the traffic for the access policy's VPN network access session. The VPN plug-in is intended for network access VPN tunnels and should be used only with BIG-IP APM policies that grant client network access.

Impact

The access policy is unable to detect the Windows 8.1 operating system and cannot apply operating system-specific polices for the session.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Access profiles that implement operating system detection deny access to client devices that are running the Windows 8.1 operating system.
  • After successful authentication, you receive the following error message on a client device that is running the Windows 8.1 operating system and attempting to access a policy that is configured for operating system detection:

    Access Denied

Workaround

To work around this issue, you can either limit the scope of client operating system detection or create specific Windows 8.1 detection checks.

To detect the Windows inbox VPN and Windows 8.1 Phone devices you can create the following specific checks to detect the Windows 8.1 operating system and the Windows 8.1 Phone as describe in the following procedures. Alternatively BIG-IP APM administrators can limit the scope of the BIG-IP APM access policy with a log on page, authentication, and an assigned network access resource and network access webtop without running device and operating system checks.

For more information, refer to the Creating an Access Policy for Network Access chapter in the BIG-IP Access Policy Manager: Network Access Configuration manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

The following procedures are intended for BIG-IP APM 11.5.1 HF3 and prior, or 11.5.0 HF4 and prior.

Adding Windows 8.1 Phone OS detection

Impact of workaround: The following workaround should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. To the right of the affected profile name in the Access Policy section, click Edit to open the visual policy editor.
  5. Click the Client OS box.
  6. Click the Branch Rules tab.
  7. Click Add Branch Rule.
  8. Assign a Name: to the new branch rule such as Windows 8.1 Phone.
  9. Click change link in Expression: Empty change.
  10. Click the Advanced tab.
  11. In the Advanced text box, add the following text:

    expr { [mcget {session.client.platform}] == "WindowsPhone" }

  12. Click Save.
  13. Click Access Policy.
  14. Click Access Profiles.
  15. Select the check box for the modified profile.
  16. Click Apply Access Policy.

Adding Windows inbox VPN framework detection

Impact of workaround: The following workaround should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. To the right of the affected profile name in the Access Policy section, click Edit to open the visual policy editor.
  5. Click the Client Type box.
  6. Click the Branch Rules tab.
  7. Click Add Branch Rule.
  8. Assign a Name: to the new branch rule, such as Windows inbox VPN.
  9. Click change link in Expression: Empty change.
  10. Click the Advanced tab.
  11. In the Advanced text box, add the following text:

    expr { [mcget {session.client.type}] == "Standalone" && [mcget {session.client.app_id}] == "vpn_plugin" }

  12. Click Save.
  13. Click Access Policy.
  14. Click Access Profiles.
  15. Select the check box for the modified profile.
  16. Click Apply Access Policy.
