Description

Clients accessing SharePoint through BIG-IP APM fail to open documents when using the Chrome browser.

  • Unable to open documents from SharePoint when using Chrome browser.
  • When attempting to open a document from SharePoint user is prompted to authenticate.

Environment

  • Microsoft SharePoint
  • BIG-IP APM
  • Google Chrome browser

Cause

When opening an office document through APM to Sharepoint, there will need to be an MRHSession Cookie that is passed from the browser session to the office Office application for APM to validate a session.
If the MRHSession cookie is missing, the BIG-IP will not acknowledge a valid session and redirect the user using a 302 to /my.policy to re-authentciate and obtain a new session and MRHSession cookie.
Client using Chrome browser to access Sharepoint does not send the APM MRHSession cookie with request is relayed to the office application.
The root cause for this is unknown at the time of publication.

  • In a packet capture you will observe that the APM MRHSession Cookies are not sent with the request. Below is an example of Chrome versus Internet Explorer behavior:

      <virtual_ip_address> <client_ip_address> HTTP 713 OUT s1/tmm0 : HTTP/1.1 403 Forbidden  0.001275000
       
    • Internet Explorer:

Recommended Actions

 

There are a couple of options for getting this to work.

1. Configure MS OFBA for Sharepoint in APM.
    Note: This option will prompt users for authentication, as OFBA is NOT SSO.

Manual Chapter : Configuring MS OFBA for Sharepoint in APM

ltm data-group internal /Common/sys_APM_MS_Office_OFBA_DG {
    description "This internal data-group is used in _sys_APM_MS_Office_OFBA_Support irule"
    records {
        ie_sp_session_sharing_enabled {
            data 1 <<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<< (!) the default value was 0 which per guide don't share sessions between office apps and browser
        }
        ie_sp_session_sharing_inactivity_timeout {
            data 60
        }

Deploying the BIG-IP System with Microsoft SharePoint 2016  **See page 47

2. Perform the following steps to help ensure the Office applications include the MRHSession cookies in the requests to be granted access to the document.

  •     Add virtual server to the Internet Options's Local Intranet sites
  •     Run Internet Options, go to Control Panel > Internet Options > Security, click on Local Intranet, click on button Sites, click on button Advanced, add virtual server URI (i.e https://www.example.com)
  •     Make sure that Virtual Server SSL certificate is signed by one from “Trusted Root Certification Authorities”
  •     Add virtual server to the Trusted locations list of Microsoft Office programs
  •     Run target Microsoft Office Program, for example Excel, go to File > Options > Trust Center > Trust Center Settings > Trusted Locations , check in Allow Trusted Locations on my network and press Button Add new location, and add virtual server URI with checked Subfolders of this location are also trusted.
