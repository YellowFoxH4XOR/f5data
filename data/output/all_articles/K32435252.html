Description

After upgrading to version 14.1.x the following error messages may appear while using HTTP::respond/redirect/retry in iRule/s: 

  • Log messages report TCL runtime errors.
 01220001:3: TCL error: _plugin_rule_/Common/ntlm <HTTP_RESPONSE> - Can't call after responding - ERR_NOT_SUPPORTED (line 1)     invoked from within "HTTP::header exists Content-Length"
 

Environment

BigIP v14.1.x

  • Using HTTP::respond/redirect/retry in an iRule
  • Using NTLM Profile (It has a built in iRule)

Cause

As of BigIP v14.1.x iRules that inspect HTTP state will error out after HTTP::respond/redirect/retry (see  K23237429 ).
One of the components has a string hard-coding an iRule. This rule does quite a bit including calls to HTTP::cookie exists which can be a problem if a respond or redirect has happened.
This was found as a bugID 895557

Recommended Actions

F5 got a fix for this BugID with Engineering Hot-Fix.
More about requesting EHF in the following KB article: K4918: Overview of the F5 critical issue hotfix policy

Additional Information

The log message is invoked because there is a trying to access the [HTTP::method - or similar commands] AFTER the HTTP::redirect or HTTP::respond was sent  ). 
This is an invalid operation in the current context (because F5 already responded to the HTTP request), and F5 is logging this informatively.
In this terms, the behavior on BigIP v14.1.x is correct and improved compared to previous versions.
