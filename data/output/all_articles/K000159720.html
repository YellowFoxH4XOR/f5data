1. Description

When attempting to update or create an NS (nameserver) record for a DNS zone in BIG-IP DNS ZoneRunner, the operation fails with the following error:

Error Message:

01150406:3: Operation failed: Update operation refused

This issue occurs even when a corresponding A record (glue record) exists for the nameserver. The problem is related to BIND nameserver requirements for exact format consistency between NS records and their corresponding glue records.

Symptoms:

  • Unable to modify existing NS records in ZoneRunner
  • NS record update operations are rejected by BIND
  • Error message displayed in the ZoneRunner GUI when attempting to save changes
  • Zone serial number may remain unchanged after attempted updates

2. Environment

  • BIG-IP DNS (formerly GTM)
  • Version: 17.1.3 and other versions
  • ZoneRunner feature enabled
  • DNS zones configured with type: master
  • Zone files using $ORIGIN directive
  • NS records defined as fully qualified domain names (FQDNs) with trailing periods
  • A records defined as short names under $ORIGIN

3. Cause

BIND requires an exact format match between the NS record target and the corresponding A record (glue record) within the same zone during dynamic updates. When the NS record is specified as a fully qualified domain name (e.g., example.ex.gov.) while the A record is defined using a short name (e.g., example) under $ORIGIN ex.gov., BIND's validation mechanism rejects the update operation.

Although BIND automatically expands the short name to the FQDN based on the $ORIGIN directive during zone processing, its validation during dynamic updates (such as those performed via ZoneRunner) requires exact format matching. This format inconsistency causes BIND to fail to recognize the glue record as valid for the NS record.

4. Answer/Recommended Actions

To resolve this issue, ensure format consistency between the NS record and its corresponding A (glue) record. Choose one of the following approaches:

Option 1: Use Short Name Format for Both Records (Recommended)

  1. Navigate to DNS > Zones > ZoneRunner > Resource Record List
  2. Select the affected DNS zone
  3. Modify the NS record to use the short name format instead of the FQDN
    • Change from: NS example.ex.gov.
    • Change to: NS example
  4. Save and apply the changes
  5. Verify the update by running: dig @localhost <zone-name> NS
  6. Confirm the SOA serial number has incremented

Option 2: Use FQDN Format for Both Records

  1. Navigate to DNS > Zones > ZoneRunner > Resource Record List
  2. Select the affected DNS zone
  3. Modify the A record to use the FQDN format with trailing period
    • Change from: example A <IP_ADDRESS>
    • Change to: example.ex.gov. A <IP_ADDRESS>
  4. Ensure the NS record also uses the FQDN format: NS example.ex.gov.
  5. Save and apply the changes
  6. Verify the update and confirm serial number increment

Option 3: Create Additional Glue Records

If the nameserver needs to be referenced across multiple zone levels:

  1. Create glue records for the nameserver in all relevant zones
  2. Add A records in parent zones (.ex, .example.ex.gov) as needed
  3. Create a separate zone for the nameserver FQDN if required
  4. Ensure all NS records can resolve to their corresponding A records

Verification Steps:

After making changes:

  • Verify the NS record update: dig @localhost <zone-name> NS
  • Check the SOA serial number has incremented
  • Test zone transfers if applicable
  • Monitor BIND logs for any related errors

5. Additional Information

Understanding $ORIGIN Directive:

The $ORIGIN directive in BIND zone files sets the default domain suffix for relative names (names without a trailing period). When $ORIGIN ex.gov. is set:

  • A short name like example expands to example.ex.gov.
  • An FQDN like example.ex.gov. remains unchanged

Format Matching Requirements:

BIND's strict validation during dynamic updates requires:

  • If NS record uses FQDN format (example.ex.gov.), the A record must also use FQDN format
  • If NS record uses short name format (example), the A record must also use short name format
  • Mixing formats, even though they resolve to the same name, will cause validation failures

Best Practice:

Using consistent short name format for both NS and A records within the same zone is the recommended approach, as it:

  • Simplifies zone file management
  • Reduces format mismatch errors
  • Leverages the $ORIGIN directive effectively
  • Maintains compatibility with ZoneRunner dynamic updates
