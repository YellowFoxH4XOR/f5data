K000133527: Failed to authenticate to https://identity.account.f5.com/oauth2. Login failed.

Type
Support Solution
Published

Updated
2023-08-28
Applies to

Source

Description

When uploading a qkview to the new iHealth (iHealth2) from BIG-IQ 8.3 the error "Failed to authenticate to https://identity.account.f5.com/oauth2" is seen.

Environment

  • BIG-IQ 8.3
  • iHealth2

Cause

iHealth has a new authentication scheme for qkview uploads that require a client id and secret.

BIG-IQ needs this client id and secret in order to generate an oAuth token for uploads.

 Recommended Actions

  1. Go to https://ihealth2.f5.com/qkview-analyzer/settings, and under API Token, select Generate New Credentials.
  2. A pop-up window will appear with a newly generated Client ID and Client Secret. (Note: if there was a previously generated client ID/Secret, it will no longer be valid at this time). Be sure to copy the Client ID and Client Secret for future reference as they are not shown in iHealth again. Client ID and Client Secret are valid for six months, after which time you must return to the settings page and regenerate new ones.
  3. Return to BIG-IQ, System Tab. BIG-IQ iHealth --> Configuration
  4. Under Credentials, click Add.
  5. Enter the new Client ID and Client Secret in the places provided. Enter a name for the new credential and click Test" to test the new credentials.

If the BIG-IQ version is 8.3 and the login is still not working:
  1. From the command line of the BIG-IQ check the currently configured iHealth endpoints with the command "restcurl cm/device/ihealth/config"
  2. If the iHealthEndpoint still reflects the classic iHealth - "https://ihealth-api.f5.com" or the iHealthAuth Endpoint reflects "https://api.f5.com" then you will need to correct the endpoints manually.
  3. From command line, enter this: restcurl -u admin:a mgmt/cm/device/ihealth/config -d '{"iHealthEndpoint": "https://ihealth2-api.f5.com/qkview-analyzer/api/","iHealthAuthEndpoint": "https://identity.account.f5.com/oauth2/ausp95ykc80HOU7SQ357/v1/token"}' -X PUT
