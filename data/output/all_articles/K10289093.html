K10289093: An internal error when processing external datagroups may result in "entry != NULL" panic

Type
Support Solution
Published
2024-03-31
Updated
2024-03-31
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K10289093

Description

  • Log messages written to /var/log/ltm:
    • notice tmm2[30394]: 01010259:5: External Datagroup (/Common/dg1) queued for update.
    • notice panic: ../kern/sys.c:1081: Assertion "entry != NULL" failed.
  • TMM may restart and a core file generated under /var/core

Environment

  • Datagroup is in use or when trying to create a datagroup.
  • Some condition causes a datagroup to not be present (e.g., delete, rename operations, or another, internal operation).
  • System tries to load the config.

Cause

This is caused by a known bug ID927633.

Recommended Actions

Monitor the progress of the fix in the software version for ID927633.

You may also consider to contacting F5 Support to inquire about the possibility of an Engineering Hotfix for ID927633.

Additional Information

None.
