Known Issue

The dwbld process may leak memory during extended uptime.

This issue occurs when all of the following conditions are met:

  • Your system is licensed and provisioned with the BIG-IP AFM or BIG-IP ASM modules.
  • The BIG-IP system uptime is extensive (many hours).

Impact

Memory exhaustion may result in degraded performance or interruptions in traffic processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H707945 on the Diagnostics > Identified > Medium page.
  • You notice a progressive increase in the amount of memory used by the dwbld process.
  • When configured as part of a high availability (HA) group, the device fails over due to memory exhaustion.
  • When configured as a standalone device, the device stops responding due to memory exhaustion.

Workaround

To work around this issue, you can restart the dwbld process periodically. To do so, perform the following procedure:

Impact of workaround: The IP intelligence feature does not function while the dwbld process restarts.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Type the following command:

    restart /sys service dwbld

  3. Exit tmsh by typing the following command:

    quit
