Known Issue

The Clear Local Config Cache button for an Oracle Access Manager (OAM) AccessGate deletes the incorrect config.cache file.

This issue occurs when the following condition is met:

  • You attempt to clear the cached local configuration for an OAM Access Server by pressing the Clear Local Config Cache button on the OAM AccessGate Properties page.

When an OAM Server is configured with one or more AccessGates, the system generates a config.cache file for each AccessGate under a file path that includes the Partition, OAM server, and AccessGate names. For example, for an OAM server named OAMaaa1, with an AccessGate named AccessGate1 configured in the /Common partition, the system generates a local cache file at the following path:

/config/aaa/oam/Common/oamaaa1/AccessGate1/config.cache

The system also has a default template config.cache file found at /config/aaa/oam/config.cache.

Pressing the Clear Local Config Cache button incorrectly deletes the /config/aaa/oam/config.cache template file, instead of deleting the actual local config.cache that was generated for the configured AccessGate.

Impact

The BIG-IP APM system does not delete the local config.cache file, so the system does not reinitialize the OAM Access server with the updated configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to clear a cached OAM configuration after an OAM server configuration change, the BIG-IP APM system does not reinitialize the OAM Access server with the updated configuration.
