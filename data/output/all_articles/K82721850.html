Known Issue

Under rare conditions, the Traffic Management Microkernel (TMM) may restart and produce a core file when multiple TCP Keep-Alive timers start for the same FastL4 flow.

This issue occurs when the following condition is met:

  • You have a FastL4 profile configured with the TCP Keep-Alive option enabled.

    The configuration may appear similar to the following example:

    ltm profile fastl4 /Common/fastL4-test {
        app-service none
        defaults-from /Common/fastL4
        idle-timeout 3600
        keep-alive-interval 10   
        tcp-close-timeout 20
        tcp-handshake-timeout 20
    }

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and devices configured for high availability (HA) may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core/ directory.
  • The BIG-IP system temporarily fails to process traffic while TMM restarts.

Workaround

To work around this issue, you can disable the TCP Keep-Alive option for the FastL4 profile. To do so, perform the following procedure:

Impact of workaround: Disabling the TCP Keep-Alive interval may expire your Fast L4 TCP connection sooner than expected since the BIG-IP system does not send Keep-Alive packets.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select the Fast L4 protocol.
  4. Select the affected profile that is associated with the virtual server.
  5. Disable the TCP Keep Alive Interval option.
  6. Click Update.
