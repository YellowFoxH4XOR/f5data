Description

How to properly setup vxlan tunnel in across-AZ configuration so that each device keeps its own local address for vxlan tunnel?

  • Devices go through the config sync, the secondary device picks up local/internal address of the primary device and modifies its vxlan tunnel to use primary's local/internal address.
  • When we do failover this does not work and pool members cannot be contacted since vxlan is inoperable (secondary device is trying to use IP address of the primary device that does not exist on secondary).

Environment

  • Deployment in Azure cloud
  • Configured 3-nic cloud formation template
  • Using VXLAN and failing over
  • Setup the Self IP was created for VXLAN for connection to Openshift cluster
  • BIG-IP LTM

Cause
Misconfiguration

Recommended Actions

To get this to work. "VXLAN configsync disable" -  is required for implementations with non-floating IPs (with any implementation in the Cloud)

In order to disable VXLAN configsync disable perform the following steps.

  1. tmsh list sys db iptunnel.configsync value
  2. tmsh modify sys db iptunnel.configsync value disable
  3. tmsh save sys config
