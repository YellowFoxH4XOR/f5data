Topic

The BIG-IP WebAccelerator has its own compression engine, which the pvac process handles. This compression engine is separate from the BIG-IP Traffic Management Operating System (TMOS) compression engine, which the TMM handles. The pvac process handles compression operations using only the CPU resource allocated for the pvac operations. Unlike TMM, the pvac process does not use any of the installed hardware compression cards on the BIG-IP system for its compression operations.

The BIG-IP WebAccelerator enables compression, by default, in all pre-defined policies on the BIG-IP WebAccelerator. You can configure compression for any node using the Enable Content Compression setting under the Assembly tab of the Acceleration Rules in a policy (see the following procedures). You can enable the BIG-IP TMOS compression by configuring the HTTP profile compression settings. In most cases, when you have both the BIG-IP WebAccelerator compression and the BIG-IP TMOS compression enabled, the BIG-IP WebAccelerator compression takes precedence. The exception to this rule is when broken compression behavior exists (for details, see K12563: HTTP Compression Exclude List takes precedence over BIG-IP WebAccelerator compression).

Note: For more information about the HTTP profile compression settings, refer to K3393: Overview of compression settings for the HTTP profile.

There may be situations where F5 recommends that you disable the BIG-IP WebAccelerator compression engine and use only the BIG-IP TMOS compression engine. These situations may include, but are not limited to, the following:

  • The system requires a higher level of compression (For more information, refer to K8766: Compression level used by the BIG-IP WebAccelerator)
  • You must address performance bottlenecks with the BIG-IP WebAccelerator
  • You must reduce CPU load on the BIG-IP system
  • You must fix broken BIG-IP WebAccelerator compression behavior (for example, behavior exhibited in K12265: The BIG-IP WebAccelerator does not compress data when compression is enabled in the http-acceleration profile  and K12563: HTTP Compression Exclude List takes precedence over BIG-IP WebAccelerator compression)

To offload the compression from BIG-IP WebAccelerator and move it to BIG-IP TMOS, you must perform the following procedures:

To enable the BIG-IP TMOS compression using an existing http profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Click the name of the HTTP profile you want to configure.
  4. Under the Compression section, select the check box to the right of the Compression setting.
  5. Click the Disabled drop-down box.
  6. Select Enabled.
  7. Select the check box to the right of the HTTP/1.0 Requests setting.
  8. Select the HTTP/1.0 Requests check box.

    Note: If the HTTP/1.0 Requests setting is cleared when you enable BIG-IP TMOS compression, the BIG-IP system inserts a Vary: User-Agent header into the compressed responses. Multiple copies of identical objects may populate the RAM Cache, if enabled, due to different browsers requesting the same objects. As a result, the RAM Cache may have a high eviction rate.

  9. Select the check box to the right of the Browser Workarounds setting.
  10. Clear the Browser Workarounds check box.

    Note: If you select the Browser Workarounds check box, the BIG-IP system inserts a Vary: User-Agent header when it compresses content that is not of MIME type text/html or text/plain. Multiple copies of objects, such as JavaScript and CSS, may populate the RAM Cache, resulting in a high eviction rate.

  11. Click the Update button.

To enable the BIG-IP TMOS compression by creating a new http profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Click the Create button.
  4. Type the name you want to give to this profile in the Name box.
  5. Click the Parent Profile drop-down box.
  6. Select the http-acceleration profile on which to base this profile.
  7. Under the Compression section, select the check box to the right of the Compression setting.
  8. Click the Disabled drop-down box.
  9. Select Enabled.
  10. Select the check box to the right of the HTTP/1.0 Requests setting.
  11. Select the HTTP/1.0 Requests check box.

    Note: If the HTTP/1.0 Requests setting is cleared when you enable BIG-IP TMOS compression, the BIG-IP system inserts a Vary: User-Agent header into the compressed responses. Multiple copies of identical objects may populate the RAM Cache, if enabled, due to different browsers requesting the same objects. As a result, the RAM Cache may have a high eviction rate.

  12. Select the check box to the right of the Browser Workarounds setting.
  13. Clear the Browser Workarounds check box.

    Note: If you select the Browser Workarounds check box, the BIG-IP system inserts a Vary: User-Agent header when it compresses content that is not of MIME type text/html or text/plain. Multiple copies of objects, such as JavaScript and CSS, may populate the RAM Cache, resulting in a high eviction rate.

  14. Click the Finished button.
