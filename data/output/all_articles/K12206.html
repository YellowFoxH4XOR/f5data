K12206: The BIG-IP system does not verify the client SSL certificate on SSL session resume

Known Issue

This is the result of a known issue. When a client resumes an SSL session, the BIG-IP system does not reverify the client SSL certificate that it previously cached and returns the status of the SSL certificate as verified. As a result, the BIG-IP system will allow the SSL session to resume, even if the client SSL certificate has expired.

F5 Product Development tracked this as ID 226920 (formerly CR142392) and ID 248045 (formerly CR142392-1) and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2, which has been issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing 10.x hotfixes, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You may be able to work around this issue by modifying the client SSL profile to disable caching and force the client to always authenticate. To do so, perform the following procedure:

  1. Log in to Configuration utility using a privileged account such as admin.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click SSL.
  5. Click Client.
  6. Click on the client SSL profile in question.
  7. Set Cache Size to 0.
  8. Enable Strict Resume.
  9. Set Client Certificate to require.
  10. Set Frequency to always.
  11. Click Update.
