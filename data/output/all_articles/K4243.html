Topic

The 9.x branch of the BIG-IP system cannot be configured to send core files to a remote Trivial File Transport Protocol (TFTP) server.

F5 Product Development is tracking the request for this functionality as CR30146.

To configure the BIG-IP system to take full advantage of its available space in order to attempt to save a core dump, perform the following procedure:

  1. Log in to the command line.
  2. Determine the amount of available disk space by typing the following command:

    df

    The BIG-IP system returns a table of statistics that appears similar to the following example:

    Filesystem 1K-blocks Used Available Use% Mounted on /dev/hda5 354653 287413 48928 86% / /dev/hda7 62297 4709 54371 8% /config /dev/hda8 62297 2938 46142 22% /var /dev/hdc1 4134932 47608 3877276 2% /shared none 110176 28 110148 1% /dev/shm none 110176 1264 108912 2% /var/tmpfs

    The Available column that is associated with the /shared file system is the amount of free space available for core files, in kilobytes.

    For this example, 3877276KB is available.

  3. Using a text editor, edit the /etc/sysconfig/coresize file.

    The content of the file is either a number or the word unlimited.

  4. Delete the content of the file, and replace it with the amount of free space available, in bytes.

    To obtain this number, multiply the number you found in step 2 by 1024.

    For example:

    3877276 * 1024 = 3970330624

  5. Restart the BIG-IP system so that it uses the new parameter by typing the following command:

    bigstart restart

    The system now attempts to write core files only as large as the available space.

    Note: On systems such as BIG-IP 1000, 2400, and 5100, the available space may still be insufficient.
