Topic

The BIG-IP ASM system provides a group of negative regular expressions that are used in a security policy to block malicious requests. When a BIG-IP ASM security policy is created, the BIG-IP ASM system associates many of the default negative regular expressions with the appropriate objects defined in the security policy.

On some occasions, a negative regular expression associated with the security policy may incorrectly block access to a web object or parameter in the web application. When this issue occurs, you must define an exception to the negative regular expression.

Defining an exception to a negative regular expression

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Web Applications.
  3. In the Name column, click the name of the web application you want to edit.
  4. In the Web Application Properties section, click the name of the security policy you want to edit.
  5. Click the Neg. RegExps menu.
  6. Select the check box of the negative regular expression for which you want to create an exception.
  7. Click Edit.
  8. In the Except RegExp box, type a regular expression that defines an exception for the web object or parameter for which you do not want this regular expression to be applied.
  9. Click Update.

Four parameters are specified in the following example request:

http://foo/bar?a=one&b=two&c=%3Cscript%3Everthing%20is%20normal &d=%3Cscript%3EYes,Everything

The following four parameters will trigger the Cross-Site Scripting 1 within the Neg.RegExps (Negative Regular Exps) located in each security policy:

  • a=oneThe parameter a, which is set to one.
  • b=twoThe parameter b, which is set to two.
  • c=%3Cscript%3Everthing%20is%20normalThe parameter c, which is set to %3Cscript%3Everthing%20is%20normal.
  • d=%3Cscript%3EYes,EverythingThe parameter d, which is set to %3Cscript%3EYes,Everything.

You can exclude parameters c and d from the negative regular expression by entering the following regular expression in the Except RegExp box:

(c|d)=.*
