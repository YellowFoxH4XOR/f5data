K12524: A web browser generates an error message or blank page when accessing a web application that is directed to a landing URI

Topic

Accessing a virtual server configured with a BIG-IP APM access policy may display a blank page or an HTTP 404 Not Found error message when all of the following conditions are met:

  • You attempt to access a URL that references a landing URI

    Note: A landing URI directs the browser to a specific web page or virtual directory. For example, https://www.siterequest.com/owa/ or https://www.siterequest.com/stats.html.

  • You are on the BIG-IP APM logon page and have not logged in
  • You navigate away from the logon page to another website
  • You return to the original landing URI

This behavior is expected. The BIG-IP APM system establishes a session when a user accesses the logon page, but the BIG-IP APM system does not process the full policy. When the BIG-IP APM system has not yet authenticated a user, and the user attempts to redirect to a landing URI with an active session, the BIG-IP APM system reads the behavior as an access violation and prevents access to the resource. The default timeout for a session is 300 seconds.

F5 Product Development tracked a Request for Enhancement (RFE) as ID 339951 to allow a customized HTTP 404 Not Found error page for BIG-IP APM logout. This feature has been added in BIG-IP 10.2.2. For information about upgrading, refer to the BIG-IP APM or Edge Gateway release notes.

In addition, this feature has been addressed in cumulative Hotfix-BIGIP-10.2.1-496.0-HF2, which has been issued for BIG-IP APM 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about downloading software from F5, refer to K167: Downloading software from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You may minimize this behavior by implementing a cache and session control access policy item in your access policy. Refer to the Setting up cache and session control chapter of the Configuration Guide for the BIG-IP Access Policy Manager for your version.
