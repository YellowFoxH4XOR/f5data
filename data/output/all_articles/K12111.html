Topic

You should consider using this procedure under the following conditions:

  • You have installed a new license or a license for an add-on module on a BIG-IP system.
  • You want to unprovision a licensed but unused add-on module on a BIG-IP system.

Description

If you have installed a license for an add-on module on a BIG-IP system, you must also provision resources for the add-on module. If you have unused licensed add-on modules, you should unprovision the modules.

The following effects are observed while the licensed module is unprovisioned:

  • The system does not perform the functions of the licensed module.
  • Items related to the module do not appear in the Configuration utility.
  • The TMOS Shell (tmsh) does not present or permit configuration of objects related to the module.
  • The bigstart status command returns output that appears similar to the following example for daemons related to the unprovisioned module:

    <daemon_name>          down, Not provisioned

Note: In some versions, configuration objects related to unprovisioned modules are incorrectly exposed. For more information, refer to K10376: The Configuration utility allows configuration of unprovisioned modules.

Note: Resource provisioning configuration cannot be synchronized between members in a BIG-IP device group. Each device must be licensed for the module and provisioned individually. For more information, refer to K21259300: BIG-IP items that are not synchronized between device group members during a ConfigSync operation.

To provision or unprovision licensed modules, perform one of the following procedures:

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have access to the Configuration utility.

Procedures

  • Provision licensed modules 
  • Unprovision licensed modules

To watch a video demo of these procedures, go to  Provision or unprovision a licensed BIG-IP module.

Provision licensed modules

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. Reprovisioning involves restarting system processes and rebooting. These actions interrupt traffic. Additionally, when the BIG-IP system is in a device group, it fails over to the next available member.

  1. Log in to the Configuration utility.
  2. Go to System > Resource Provisioning.
  3. In the Provisioning column, select the check box for each licensed module and select either Minimum or Nominal.

    Note: For BIG-IP versions prior to 11.3.0, select Minimum or Nominal for each licensed module.

  4. Select Submit.

    Note: For BIG-IP versions prior to 11.3.0, select Update.

  5. The system warns you about the reprovisioning impact. Select OK to proceed.
  6. After you make the necessary provisioning changes, go to System > Configuration > Device.
  7. To restart the system, for Operations, select Reboot.
  8. When prompted, select OK to confirm restart.
  9. If the BIG-IP system is in a device group, repeat the procedure on the other members. Provisioning is not synchronized in a ConfigSync operation.

Unprovision licensed modules

Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. Reprovisioning involves restarting system processes and rebooting. These actions interrupt traffic. Additionally, when the BIG-IP system is in a device group, it fails over to the next available member.

  1. Log in to the Configuration utility.
  2. Go to System > Resource Provisioning.
  3. In the Provisioning column, clear the check box for each licensed module you want to unprovision.

    Note: For BIG-IP versions prior to 11.3.0, select None (Disable) for each licensed module you want to unprovision.

  4. Select Submit.

    Note: For BIG-IP versions prior to 11.3.0, select Update.

  5. The system warns you about the reprovisioning impact. Select OK to proceed.
  6. After you make the necessary provisioning changes, go to System > Configuration > Device.
  7. To restart the system, for Operations, select Reboot.
  8. When prompted, select OK to confirm restart.
  9. If the BIG-IP system is in a device group, repeat the procedure on the other members. Provisioning is not synchronized in a ConfigSync operation.
