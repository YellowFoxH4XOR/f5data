K2720: SSH connections may not be successful between established units and newly installed RMA units

Known Issue

When you replace a BIG-IP or 3-DNS system with a new system that uses the same IP address, the SSH keys for the new system will not match the SSH keys that were used on the system that was replaced.

The 3dnsmaint unit cannot fix this discrepancy, so it will fail to synchronize the SSH keys.

In addition, if the SSH known_hosts file is missing, 3dnsmaint cannot synchronize the SSH keys.

Workaround

To work around this issue, complete the following procedures.

Locating the known_hosts file

To locate the known_hosts file, perform the following steps:

  1. Log in to the command line.
  2. Change directories to the /root/.ssh directory, by typing the following command:

    cd /root/.ssh

  3. List the files in the directory, by typing the following command:

    ls -la |grep known_hosts

  4. Look for a file named known_hosts.

    If the known_hosts file exists, continue on to the procedure titled, Fixing an existing known_hosts file.

    If the known_hosts file does not exist, continue on to the procedure titled, Creating a known_hosts file.

Fixing an existing known_hosts file

To fix an existing known_hosts file, perform the following steps:

  1. Using a text editor, such as vi or pico, edit the known_hosts file.
  2. Locate the line that begins with the IP address or host name of the unit that you are replacing.
  3. Delete the line.
  4. Save the file and exit the editor.

You should now be able to use 3dnsmaint to synchronize the SSH keys.

Creating a known_hosts file

If the known_hosts file does not exist, you can create the file by typing the following command:

touch known_hosts

You should now be able to use 3dnsmaint to synchronize the SSH keys.
