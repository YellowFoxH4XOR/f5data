Known Issue

Description

Policy attack signatures may be removed from a policy when the software is upgraded or installed.

This issue occurs when all of the following conditions are met:

  • An 11.0.0 security policy has assigned attack signatures.
  • Either of the following procedures is performed:
    • The 11.0.0 configuration is upgraded to BIG-IP 11.0.0 HF-1
    • The 11.0.0 configuration is transferred to a new boot location running 11.0.0 as part of the installation process

Impact

A security policy will have no attack signatures protecting the web application.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H372643 on the Diagnostics > Identified > Critical screen.
  • A security policy will have no attack signatures listed in the Configuration utility, under Application Security > Attack Signatures > Policy Attack Signatures
  • Attack Signature Detected violations will not be triggered by requests that would otherwise normally do so, and the requests will not be blocked
  • No Attack Signature Detected violations will be displayed under Application Security > Reporting

Resolution

Status

Workaround

To work around this issue, you can rebuild the attack signature sets cache from the MySQL database. To do so, enter the following command from the BIG-IP ASM command line:

Impact of workaround: None.

perl -MF5::DbUtils -MF5::NegativeSignatures -e 'F5::NegativeSignatures->new(dbh => F5::DbUtils::get_dbh())->link_sigs_to_set'
