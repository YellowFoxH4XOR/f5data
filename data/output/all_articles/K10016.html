Known Issue

This is the result of a known issue. The VIPRION platform may experience a kernel panic and reboot following an upgrade to BIG-IP version 10.x. This issue occurs if the system is running version 9.6.x with a BIOS firmware version earlier than build 461, and the VIPRION unit is upgraded to version 10.x with the management interface connected to a subnet with live traffic.

Note: The upgrade to version 10.x installs a BIOS version number of build 461 or later. However, if the upgrade is performed with the management interface connected to a live subnet, the VIPRION system reboots before the firmware manager can update the BIOS to the appropriate version.

F5 Product Development tracked this issue as ID 217599 (formerly CR107874) and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

If you have not yet upgraded the VIPRION system to version 10.x, run the bigpipe platform command to determine the BIOS build number. If the BIOS build number is lower than 461, you must proceed with the following workaround. If the BIOS build number is 461 or higher, you can skip the workaround procedure and upgrade to version 10.x.

For example, you would type the following command to determine the BIOS build number:

bigpipe platform |grep BIOS

The command output indicates that you do not need to perform the workaround because the VIPRION system is running BIOS build 461:

BIOS revision: LinuxBIOS 2.0.0 OBJ-0235-06 REV. A build 461

If you have either determined that the BIOS build number is lower than 461, or you have already attempted to upgrade the VIPRION to version 10.x and the system is experiencing a kernel panic and rebooting, allow the 10.x installation and BIOS upgrade to complete by performing the following procedure:

  1. Disconnect the network cable from the management interface and reboot the blade.

    Note: With the management interface disconnected, the blade will reboot without the kernel panic.
  2. Once the unit has rebooted, reconnect the network cable to the management interface and copy the version 10.x ISO upgrade image to the blade that is experiencing the kernel panic.
  3. Once the image has been copied over, remove the network cable from the management port.
  4. Use the image2disk utility to install version 10.x on the VIPRION system.

    The installation process will reboot the blade.

    As the system initializes, the the firmware manager will update the BIOS to version 461 or later. After the BIOS has been updated, the blade will be rebooted.
  5. Once the blade comes back up, you can reconnect the management interface. The unit will not have a kernel panic because the management interface is connected.
