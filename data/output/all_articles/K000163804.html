K000163804: HTTPS monitors may mark pool members down after an upgrade when peer-cert-mode is set to require on SSL Profile attached to the HTTPS monitor

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 21.1.0, 21.1.X, 17.5.1, 17.1.3
Source
https://my.f5.com/manage/s/article/K000163804

Description

An HTTPS monitor may mark a pool member down after an upgrade when the monitor uses a Server SSL profile with peer-cert-mode require and the backend server presents an expired, untrusted, or otherwise invalid certificate.


The behavior is expected in releases containing the certificate-validation fix for Bug ID2333277, starting from the following:


  • BIG-IP 17.1.3.5
  • BIG-IP 17.5.1.9
  • BIG-IP 21.1.0.2


Environment

  • In-TMM monitoring is disabled (default).
  • HTTPS monitor configured with a server SSL profile.
  • Server SSL profile configured with peer-cert-mode require.
  • BIG-IP versions starting from 17.1.3.5, 17.5.1.9, and 21.1.0.2


Cause

The bigd HTTPS monitor did not consistently apply the Server SSL profile's peer-certificate validation settings in earlier releases.


Changes made for bug ID2333277 corrected this behavior so that bigd HTTPS monitors apply certificate validation consistent with In-TMM HTTPS monitors. When peer-cert-mode is set to require, the backend certificate must satisfy the configured validation requirements.


Answer/Recommended Actions

This behavior is expected in the corrected releases. To restore a successful monitor result while maintaining certificate validation:


  1.   Renew or replace the expired backend certificate.
  2.   Confirm that the backend certificate is issued by a CA trusted by the Server SSL profile.
  3.   Confirm that the complete certificate chain is valid.
  4.   For a self-signed backend certificate, configure the certificate as the trusted CA used by the Server SSL profile.
  5.   Verify that the HTTPS monitor references the intended Server SSL profile.
  6.   If the backend uses multiple certificates, verify that the expected certificate is selected during the TLS handshake, including any required SNI configuration.


Additional Information

  • Bug ID 2333277: BIGD HTTPS monitors now honor the certificate verification
