K04270666: POST request fails when HTTP/2 profile is applied to the LTM virtual server

Type
Support Solution
Published
2022-01-23
Updated
2024-02-14
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.X, 16.1.0, 16.1.3, 16.1.2, 16.1.1
Source
https://my.f5.com/manage/s/article/K04270666

Description

When BIG-IP receives an HTTP/2 POST request, the request hangs and after some time HTTP2 protocol error appears on the client browser:
"ERR_HTTP2_PROTOCOL_ERROR"

Environment

  • BIG-IP LTM
  • HTTP/2 profile 
  • OneConnect profile

Cause

The POST requests hang because BIG-IP (TMM) doesn't send HTTP/2 flow control messages. F5 Product Development has assigned ID1042509 to this issue.

Recommended Actions
For a workaround, use an HTTP router profile: assign the 'httprouter' profile to the virtual server, or select the 'HTTP MRF Router' option.

Additional Information

In HTTP/2, there is a flow control for each request(stream). The sender sends DATA messages as long is doesn't exceed the receiver window and the receiver, in turn, updates the sender on the window size using WINDOW_UPDATE messages.
In our case, TMM doesn't update the sender which is the client, on the current window size. In turn, the client stops sending DATA frames and waits for confirmation that the WINDOW is free again. When it doesn't receive it, the client then stop sending data after timeout is reached and the client sends PING heartbeat messages and eventually ends the session.
