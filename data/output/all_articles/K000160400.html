Description

When Windows users access BIG-IP APM configured with endpoint checks through a web browser (without the full BIG-IP Edge Client pre-installed), the system automatically delivers a lightweight installer called f5epi_setup.exe to handle endpoint inspection.

This lightweight installer does not include the F5 Inspector Service by default. That service can be required by certain endpoint checks (such as antivirus last scan time retrieval) that need elevated privileges to function correctly.

As a result, endpoint checks that depend on admin-level access — such as reading the Windows Defender last scan date — will fail with an WAAPI_ERROR_ACCESS_DENIED error, even when the user's machine is fully compliant.

This article describes how to use an iRule combined with BIG-IP hosted content to transparently redirect browser-based users to a custom, pre-built BIG-IP Edge Client package that includes all required services, without requiring any action from the end user beyond a single "Run as Administrator" installation.

Environment

  • BIG-IP APM
  • Windows clients accessing APM via a web browser (browser-based Network Access / webtop)
  • Access policy configured with Endpoint Inspection (for example, Antivirus check, Firewall check)
  • An endpoint check requiring F5 Inspector Service

Cause

The f5epi_setup.exe installer that BIG-IP APM automatically delivers to browser-based users is a minimal Endpoint Inspector package. It does not include the F5 Inspector Service component.

Certain OPSWAT SDK methods — such as GetLastScanTime for Windows Defender — are flagged as admin_required, meaning they can only be invoked by a process running with elevated privileges. Without the F5 Inspector Service installed and running as a Windows service (with the necessary elevated rights), these checks will fail with access denied errors.

As documented in K000134812: Browser based Network Access VPN users on Windows fail the AV check with "Access Denied", the recommended solution is to have users install a custom BIG-IP Edge Client package that includes the Inspector Service. The challenge is delivering this package seamlessly to browser-based users who would otherwise only receive f5epi_setup.exe.

Recommended Actions

The approach consists of two parts:

  • Part 1 — Build and host the custom package on BIG-IP
  • Part 2 — Use an iRule to transparently redirect users to the custom package

Part 1 — Build and upload the custom BIG-IP Edge Client package

Step 1: Build the custom Windows client package

  1. Navigate to Access > Connectivity/VPN > Connectivity > Profiles
  2. Select your connectivity profile
  3. Click the dropdown arrow next to Customize Package and select Windows
  4. In the Customize Windows Client Package dialog, ensure the following components are selected:
    • Inspector Service (required for endpoint checks that need elevated privileges, such as AV last scan time, firewall state)
    • Component Installer Service (allows updating and installing client-side components for users without admin rights)
    • Endpoint Security (required for OPSWAT-based AV/FW checks)
    • Web Browser Add-ons for BIG-IP Edge Client (required for browser-based access, provides f5epi_setup.exe)
  5. Click Download to save the package (for example, BIGIPEdgeClient.exe)

Step 2: Upload the package as BIG-IP hosted content

  1. Navigate to Access > Webtops > Hosted Content > Manage Files (path may vary by version)
  2. Click Upload
  3. Click Browse and select the BIGIPEdgeClient.exe file from Step 1.
  4. Click OK
  5. Note the public URI path where the file will be served (by default that will be /public/share/BIGIPEdgeClient.exe)
  6. Navigate to Access > Webtops > Hosted Content > Manage Access
  7. Enable 'Retain Public Access' next to the Access Profile that will be used for endpoint checks
  8. Click OK

Part 2 — Apply the iRule to redirect f5epi_setup.exe requests to the custom package

Attach the following iRule to the virtual server handling APM access. It intercepts the automatic download request for f5epi_setup.exe and silently redirects the browser to the custom hosted package instead:

when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
    if { [HTTP::has_responded] } { return }
    if { [HTTP::uri] == "/public/download/f5epi_setup.exe" } {
        HTTP::redirect "/public/share/BIGIPEdgeClient.exe"
    }
}

Notes:

  • Replace /public/share/BIGIPEdgeClient.exe with the actual URI path where you uploaded the custom package in Part 1
  • The ACCESS::restrict_irule_events disable command in the CLIENT_ACCEPTED event is required to allow the iRule to process HTTP events within an APM-protected virtual server
  • The redirect is transparent to the end user — the browser will automatically follow it and download the correct package
  • When connecting to the VS using a browser, end users will be prompted to download the Endpoint inspection client components as usual.
  • Thanks to the iRule, the custom package will be downloaded. Users will then only have to right-click the downloaded file and select 'Run as administrator'

Verification

  1. Connect to the APM webtop from a Windows browser session (without the Edge Client pre-installed)
  2. Confirm that the browser downloads the custom BIGIPEdgeClient.exe package instead of f5epi_setup.exe
  3. Install the package with 'Run as administrator'
  4. Verify in Windows Services that 'F5 Inspector Service' and 'F5 Networks Component Installer' services are listed and running
  5. Re-run the APM access policy and confirm that endpoint checks now pass

Additional Information

  • According to K000134812, the following Windows security products are known to require the Inspector Service for specific SDK methods:
    • GetLastScanTime: Windows Defender, BitDefender, Acronis Cyber Protection Agent
    • GetRealTimeProtectionState: ESET File Security for Microsoft Windows Server
    • GetDefinitionState: FireEye Endpoint Agent
    • GetFirewallState: AVG Internet Security, AhnLab V3 Internet Security
