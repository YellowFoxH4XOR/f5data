Description

After upgrade to v15.1.9.x, v16.x, v17.x, service disconnected for fastL4 virtual servers.
Client reset to SYN-ACK from FastL4 virtual server.
When PVA in the FastL4 profile is disabled, issue does not occur.

 

Environment

  • BIG-IP
  • v15.1.9.x, v16.x, v17.x
  • FastL4 with PVA enabled.
  • Client reset to SYN-ACK
  • AFM

 

Cause

  • Bug ID 1325681

 

Recommended Actions

Collect a packet capture on intermediate device between client and BIG-IP in order to verify issue timestamp value.

Identify packets where the client did not ack a packet and inspect the timestamp in the tcp stream.

The client will drop the packet if the timestamp value is invalid as per RFC1323

In this example the problem is found in the tcp handshake, however the issue can also been found in application packets:

 

Check client's SYN packet's Timestamp value in the TCP Option

Options: (20 bytes), Maximum segment size, SACK permitted, Timestamps, No-Operation (NOP), Window scale
TCP Option - Maximum segment size: 1460 bytes
TCP Option - SACK permitted
TCP Option - Timestamps
Kind: Time Stamp Option (8)
Length: 10
Timestamp value: 3793951481: TSval 3793951481, TSecr 0 
Timestamp echo reply: 0

Check SYN_ACK from BIG-IP timestamp echo reply is match with the Timestamp value in the SYN.

Options: (16 bytes), Maximum segment size, SACK permitted, Timestamps
TCP Option - Maximum segment size: 1460 bytes
TCP Option - SACK permitted
TCP Option - Timestamps
Kind: Time Stamp Option (8)
Length: 10
Timestamp value: 2793663953: TSval 2793663953, TSecr 588970345
Timestamp echo reply: 588970345 <<------this should match with SYN's Timestamp value

 

Confirm if tscookie is enabled at any context: 

security dos device-config dos-device-config {
    tscookie-vlans {
        <VLAN> <<<---------[!]
    }
}
security dos device-config /Common/dos-device-config {
   dos-device-vector {
     tcp-ack-ts {
       ...
       tscookie enabled <<<---------[!]
       ...

* Note that tscookie configuration applies even if tcp-ack-ts DoS vector is disabled. 
ltm profile fastl4 /Common/fastL4_profile {
   ...
   pva-acceleration full <<<---------[!]
   tcp-timestamp-mode preserve <<<---------[!]
   ...

If those are matching with your symptom and the config, follow the workaround in the Bug ID 1325681.
 

Review and update the threshold values as per the following article to ensure they are correct after a recent upgrade:

K000139860: The tcp-ack-ts vector with lower thresholds is triggered after upgrading to v17.1

Additional Information

If a recent upgrade to 17.1.x triggered this issue, follow the steps below to disable tscookie which was enabled by default in attack vector TCP ACK (TS):

  • To disable Timestamp Cookie via GUI (Configuration Utility), navigate to Security  ››  DoS Protection : Device Protection, find vector TCP ACK (TS) and uncheck "Timestamp Cookie" setting. 
  • To disable Timestamp Cookie via CLI (tmsh), you can run following command:

tmsh modify security dos device-config dos-device-config dos-device-vector { tcp-ack-ts { tscookie disabled }}

tmsh save sys config
