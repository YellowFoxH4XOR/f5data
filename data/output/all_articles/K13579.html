K13579: Generating new default certificate and key pairs for BIG-IP SSL profiles

Type
Knowledge
Published
2015-07-06
Updated
2025-07-24
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K13579

Topic

You should consider using this procedure under the following condition:

  • The default certificate and key must be regenerated for reasons of functionality or security.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have root or administrator access to the BIG-IP system's Advanced Shell (bash).

Note: F5 recommends that you create a user configuration set (UCS) archive as a precaution for recovery purposes. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).

Description

Each BIG-IP device comes with a default Secure Sockets Layer (SSL) certificate and key pair named default.crt and default.key that can be referenced by an SSL profile to establish secure connections. The default SSL certificate and key pair are required for system operation and should not be deleted. If the default.crt, and default.key files are missing or corrupt, the BIG-IP configuration may fail to load properly and generate error messages to the console and /var/log/ltm file. If the default.crt and default.key files are missing or corrupt, you can use one of the following platform-dependent procedures to generate a new default certificate and key pair:

  • Regenerating the default certificate and key
  • Regenerating the default certificate and key (VIPRION platforms)

Procedures

Regenerating the default certificate and key

When regenerating a new default certificate, you will be asked to answer the following questions:

Country Name (2 letter code) [XX]:
State or Province Name (full name) []:
Locality Name (eg, city) [Default City]:
Organization Name (eg, company) [Default Company Ltd]:
Organizational Unit Name (eg, section) []:
Common Name (eg, your name or your server's hostname) []:
Email Address []:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the bash shell.
  2. Regenerate the certificate and key by typing the following command:

    openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -keyout /config/ssl/ssl.key/default.key -out /config/ssl/ssl.crt/default.crt

  3. Reload the configuration to load the new certificate and key by typing the following command:

    tmsh load sys config

  4. You can verify the new certificate using the following methods:
    • The bash shell: openssl x509 -in /config/ssl/ssl.crt/default.crt -noout -text
    • Configuration utility: System > Certificate Management > Traffic Certificate Management > SSL Certificate List > default.crt
    • The tmsh utility: tmsh list sys crypto cert default.crt

    Important: Due to a known issue, the newly generated default SSL certificate and key may not be displayed in the BIG-IP Configuration utility or tmsh utility. You may have to create a null /service/mcpd/forceload file with the command touch /service/mcpd/forceload and then reboot the system. For more information, refer to ID 528314.

Regenerating the default certificate and key (VIPRION platforms)

When regenerating a new default certificate, you will be asked to answer the following questions:

Country Name (2 letter code) [XX]:
State or Province Name (full name) []:
Locality Name (eg, city) [Default City]:
Organization Name (eg, company) [Default Company Ltd]:
Organizational Unit Name (eg, section) []:
Common Name (eg, your name or your server's hostname) []:
Email Address []:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the bash shell and ensure this is the primary blade.

    Note: The bash prompt designates the primary blade with a capital P (S1-green-P). Secondary blades are designated with a capital S (S2-green-S).

  2. Regenerate the certificate and key by typing the following command:

    openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -keyout /config/ssl/ssl.key/default.key -out /config/ssl/ssl.crt/default.crt

  3. Sync the new key to all installed blades using the following command syntax:

    tmsh show sys cluster | grep active | awk '{system ("scp /config/ssl/ssl.key/default.key slot"$2":/config/ssl/ssl.key/default.key")}'

  4. Sync the new certificate to all installed blades using the following command syntax:

    tmsh show sys cluster | grep active | awk '{system ("scp /config/ssl/ssl.crt/default.crt slot"$2":/config/ssl/ssl.crt/default.crt")}'

  5. Reload the configuration to load the new certificate and key by typing the following command:

    tmsh load sys config

  6. You can verify the new certificate using the following methods:
    • The bash shell: openssl x509 -in /config/ssl/ssl.crt/default.crt -noout -text
    • Configuration utility: System > Certificate Management > Traffic Certificate Management > SSL Certificate List > default.crt
    • The tmsh utility: tmsh list sys crypto cert default.crt

    Important: Due to a known issue, the newly generated default SSL certificate and key may not be displayed in the BIG-IP Configuration utility or tmsh utility. You may have to create a null /service/mcpd/forceload file with the command clsh touch /service/mcpd/forceload and then reboot the VIPRION system with the command clsh reboot. For more information, refer to ID 528314.
