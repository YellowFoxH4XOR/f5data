Known Issue

This is the result of a known issue. When the BIG-IP system uses the Oracle monitor to monitor an Oracle server, the BIG-IP system correctly marks the pool member up if it receives the expected reply back from the server. However, the TCP connection used for the health check is not immediately closed; instead the connection is kept open and re-used for further health checks.

While each instance of the monitor works as expected by comparing the reply received from the server with the receive string configured for the monitor, the BIG-IP system also opens additional TCP connections to the Oracle server and immediately closes those connections.

The Oracle server expects each connection attempt to be followed by data from the client, and since the BIG-IP system does not send the expected data before closing all connections, the Oracle server logs the following error message:

TNS-12502: TNS:listener received no CONNECT_DATA from client

This message indicates that a connection was made to the database, but that the Oracle server did not see the CONNECT_DATA string typically sent by the client. The message does not indicate an issue with the BIG-IP LTM or the monitor.

Note: The same error message will be logged on the server if a TCP monitor is configured instead, since the exchange expected by the server is not completed by the BIG-IP system.

F5 Product Development tracked this issue as id 204508 (formerly CR110195) and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP release notes.
