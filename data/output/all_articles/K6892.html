Known Issue

This is the result of a known issue. The BIG-IP LTM IP::timeout iRule command specifies an idle timeout value as the criteria for selecting the pool to which you want the BIG-IP system to send traffic. The BIG-IP LTM FastL4 Profile does not honor the IP::timeout iRule command, which is set from the CLIENT_ACCEPTED iRule event.

F5 Product Development tracked this issue as CR69775 and CR62072 and it was fixed in BIG-IP LTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
