Known Issue

The BIG-IQ user interface may fail to load after an upgrade to version 8.0.0. This is due to the BIG-IQ Role Based Access Control (RBAC) subsystem failing to update task tables that have a large number of items.

This issue occurs when the following condition is met:

  • You attempt to upgrade the BIG-IQ system when there are more than 100,000 records for a single task in the BIG-IQ database.

Impact

The BIG-IQ system fails to function, and you cannot access the user interface.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IQ user interface fails to load and displays an error message similar to the following example:

    Waiting for BIG-IQ services to become available

  • In the /var/log/bootstrap/bootstrap.out file, you observe messages that appear similar to the following example:

    Database upgrade succeeded.

  • In the /var/log/postgres/postgresql-<date>.log file, you observe messages that appear similar to the following example:

    ERROR:  query string argument of EXECUTE is null
    CONTEXT:  PL/pgSQL function rbac_add_pattern(text,text,text,text[],boolean) line 108 at EXECUTE
    STATEMENT:  call rbac_add_pattern($1,$2,$3,$4,$5)

  • In the /var/log/tokumon/current file, you observe messages that appear similar to the following example:

    [ERROR] postgres_configurator: _isRBACReady: RBAC is not ready.

Workaround

To work around this issue, you can modify the rbac_add_pattern_proc.sql file and perform a manual database update. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IQ system.
  2. To verify that the workaround was not previously implemented, enter the following grep command, and make sure the output is clean:

    grep -A 2 -B 3 "create_triggers_sql IS NOT NULL" /var/config/rest/postgres/sql/post/rbac_add_pattern_proc.sql

  3. To fix the rbac_add_pattern_proc.sql file, enter the following sed command:

    sed -i -e "s/EXECUTE create_triggers_sql || ';';/IF (create_triggers_sql IS NOT NULL) THEN \n EXECUTE create_triggers_sql || ';'; \n END IF; /" -i -e "s/EXECUTE create_index_sql || ';';/IF (create_index_sql IS NOT NULL) THEN \n EXECUTE create_index_sql || ';'; \n END IF; /" /var/config/rest/postgres/sql/post/rbac_add_pattern_proc.sql

  4. To verify that the workaround script is added to the SQL file, enter the following grep command again:

    grep -A 2 -B 3 "create_triggers_sql IS NOT NULL" /var/config/rest/postgres/sql/post/rbac_add_pattern_proc.sql

    Output appears similar to the following example:

    IF (create_index_sql IS NOT NULL) THEN
    EXECUTE create_index_sql || ';';
    END IF;
    IF (create_triggers_sql IS NOT NULL) THEN
    EXECUTE create_triggers_sql || ';';
    END IF;

  5. To run the script to re-declare the procedure in the database, enter the following command:

    psql -U postgres -d bigiq_db -f /var/config/rest/postgres/sql/post/rbac_add_pattern_proc.sql

  6. To reset the RBAC subsystem, enter the following command:

    rbac-reset

  7. You must wait until rbac-reset is complete before proceeding further. Even though the rbac-reset command returns as complete on the command line output, the re-calculation of the RBAC information on all documents happens in the background, and this process takes a long time (sometimes an hour). To check the calculation status, enter the following command and wait until it reaches 0 before proceeding further:

    while true ; do date ; psql -U postgres -d bigiq_db -c "select count(*) from bigiqauthorization.shared_authorization_journals;" ; sleep 10 ; done

    Output appears similar to the following example:

    Mon Mar 22 07:34:43 PDT 2021
     count 
    -------
         0
    (1 row)

    Note: You should see the count decreasing each time the query is run. The reset process is completed when the count reaches 0.

  8. Press Ctrl+C to stop the verification command.
  9. Review the Postgres logs in the /var/log/postgres directory and confirm that no more rbac_add_pattern errors occur.

    Note: If you still see errors, the rbac-rest process has not yet completed. Wait before proceeding further.

  10. At this point, tokumon begins the re-indexation process and you need to wait until this is fully complete. To check the tokumond re-indexing progress, enter the following command and wait until the process is completed:

    Note: The tokumond process does not start indexing entries until after the rbac-reset process is completed.

    while true ; do fgrep Progress /var/log/tokumon/current | tail -n1 ; sleep 10 ; done

    Output appears similar to the following example:

    2021-01-25_13:39:04.35913 [INFO] postgres_configurator: sendFind: percentComplete:85. Progress: [========================================== ]
    2021-01-25_13:39:04.58741 [INFO] postgres_configurator: sendFind: percentComplete:89. Progress: [============================================ ]
    2021-01-25_13:39:04.83006 [INFO] postgres_configurator: sendFind: percentComplete:93. Progress: [============================================== ]
    2021-01-25_13:39:05.08111 [INFO] postgres_configurator: sendFind: percentComplete:97. Progress: [================================================ ]

    The BIG-IQ user interface is restored after the re-indexing progress reaches 99%.

  11. Press Ctrl+C to stop the verification command.
