K17474375: BIG-IP Edge Client for Windows repeatedly disconnects due to routing table changes on the client

Type
Knowledge
Published
2019-09-03
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K17474375

Issue

Description

BIG-IP Edge Client for Windows may stop passing traffic and disconnect when a routing table change is forced by a client process, application, or operating system change while connected to the VPN. The user may see the Edge Client enter an Initializing state, and then reconnect to the VPN.  During the time the client reconnects, a user briefly loses VPN connectivity.

Environment

  • BIG-IP Network Access with the Prohibit routing table feature enabled.  
  • BIG-IP Edge Client on a Windows device 

Cause

When the Client Side Security > Prohibit routing table changes during Network Access connection is enabled on the BIG-IP APM Network Access resource, this causes the VPN client to constantly check the routing table it created for any changes. If a user action, application, or operating system action changes the routing table, Edge Client immediately attempts to restore the routing table using the Route table snapshot it created during the VPN connection initiation.  If a user or process continuously modifies the route, the VPN client treats this behavior as a security threat and the VPN connection terminates after four attempts to correct the routing table change.

The following log messages indicate that the tunnel is disconnected due to a routing table change: 

Log File: %temp%/logterminal.txt 

<date> <time> HOST CHostCtrl::DispatchVPNEvent, As this represents a potential security threat, Network Access connection is terminated.)
<date> <time> APPCTRL CAppTunnelEx::DispatchEvent, As this represents a potential security threat, Network Access connection is terminated. errorCode:9)

The offending or missing route is identified by the following log messages: 

Log File: %temp%/logterminal.txt

<date> <time> DIALER \UIpForwardTable.cpp, UIpForwardTable::CompareTable, Routes missing from VPN interface,<missing route>  

    Recommended Actions

    • Identify the offending route and contact the client device system administrator to determine if this is a security threat or if you should change the Network Access configuration to take that route changes into consideration. 
      • Third party VPN clients (even when disconnected) will force a route insertion on the route table.
      • Network changes that affect VPN connectivity may also change routes unexpectedly, for example, roaming.
         
    • Work around expected client route table changes.
      • Verify that the Network Access VPN > Network Access List of the profile is configured with Allow Local Subnet > Enable.
      • Verify that the Network Access VPN > Network Access List of the profile is not configured with Client Side Security > Prohibit routing table changes during Network Access connection.

        Important: Allowing client side route table changes during an established VPN session can introduce security concerns and should be implemented with caution.
