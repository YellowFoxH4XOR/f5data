Known Issue

This is the result of a known issue. The Encrypt Cookies setting in the HTTP profile allows you to configure the BIG-IP LTM to encrypt HTTP cookies before sending responses to the client system.

Note: For more information, refer to K7784: Overview of cookie encryption.

When cookie encryption is configured in the HTTP profile, and multiple cookie headers appear in the server response, the BIG-IP system does not correctly account for the length difference between the unencrypted cookie value and the encrypted cookie value. This behavior results in invalid or corrupted HTTP header values when the cookie to be encrypted is not the last cookie in the HTTP header.

This issue can also affect the use of certain iRule commands. For example, if you use the HTTP::header iRule command in the HTTP_RESPONSE event to return a header value, the value may appear to be corrupted.

F5 Product Development tracked this issue as ID 326834 ( formerly CR114198 ) and it was fixed in versions 9.4.7 and 10.0.1. For information about upgrading, refer to the BIG-IP LTM or ASM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.0-5514.0-HF2 issued for BIG-IP version 10.0.0. You may download these hotfixes or later versions of these hotfixes from the F5 Downloads site.
