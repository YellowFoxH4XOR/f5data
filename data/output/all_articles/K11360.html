Known Issue

This is the result of a known issue. When TMM starts, the BIG-IP system logs error messages in the /var/log/tmm file that appear similar to the following example:

notice log.*.level: invalid enum value: info
notice MCP Message:
notice modify {
notice db_variable {
notice db_variable_name "log.mcpd.level"
notice db_variable_value "info"
notice db_variable_object_id 8753
notice db_variable_transaction_id 65521
notice }
notice }
notice mcp error: 1031000 in mcpmsg_to_database

You can safely ignore these messages.

The error messages are the result of a mismatch between the DB key used to define the logging level for mcpd and a related DB key that is no longer used by TMM, which is illustrated in the following table:

DB keyAllowed values
Log.Mcpd.Leveldebug, info, notice, warning, warn, err, error, crit, alert, emerg, panic
Log.Tmm.LevelDebug, Informational, Notice, Warning, Error, Critical, Alert, Emergency

In the example error message, the Log.Mcpd.Level value has been set to info. A mismatch occurs when the BIG-IP system attempts to set the Log.Tmm.Level DB key to info also. Since info is not an allowed value for the Log.Tmm.Level DB key, the message is logged. However, the Log.Tmm.Level DB key is no longer used.

F5 Product Development is tracking this issue as ID 224813 (formerly CR137767).
