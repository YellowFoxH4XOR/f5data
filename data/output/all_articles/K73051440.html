Description

This article provides an overview and some historical information about the tmipsecd process.

tmipsecd is principally the configuration handler for IPsec and IKEv1. The IKEv1 control process racoon interacts with tmipsecd in order to write configuration out. tmipsecd is a layer between mcpd (the BIG-IP configuration handler) and racoon.

tmipsecd also monitors and spawns the racoon process. When tmipsecd is restarted intentionally or due a crash, racoon also restarts because tmipsecd is the parent process of racoon. As a result, the IKEv1 configuration is reprocessed and all IKEv1 tunnels are restarted. Restarting tmipsecd is sometimes recommended by F5 Support to clear all IKEv1 tunnels and reload the config at the same time.

A restart of tmipsecd will not cause IKEv2 tunnels to restart.

Before software version 12.0.0 it was possible to restart racoon using the "bigstart restart racoon" command. This was intentionally deprecated due to reduce any chance that tmipsecd and racoon could fall out of sync and have different views of the IKEv1 tunnel configurations.

tmipsecd can be falsely blamed as the source of a problem when frequent "restarting tmipsecd" messages are seen at the console. In most cases, tmipsecd is restarting because it has lost connection to tmm. That means if tmm restarts, the first message logged will be from tmipsecd, when tmm is actually in the process of failing. In that sense, tmipsecd restarts are normally a precursor to a problem rather than being the problem itself.

On software versions prior to v12.0.0 tmipsecd will restart during an HA state transition. This behaviour was acceptable because the racoon process should not run on a Standby device and High Availability / Mirroring is not supported for IKEv1.

tmipsecd has its own log file /var/log/tmipsecd and the log level is influenced by the ike-daemon log level. The default level is info:

tmsh modify net ipsec ike-daemon ikedamon log-level info 

This command also changes the log level of racoon (/var/log/racoon.log) and IKEv2 (/var/log/ipsec.log). Therefore, changing the log level might have a negative system impact if hundreds of IPsec tunnels are configured and up.

Environment

tmipsecd is an integral part of IKEv1 IPsec.

Cause

None

Recommended Actions

Restarting tmipsecd is only recommended when the desire is to restart all IKEv1 tunnels and re-read the IPsec configuration.

bigstart restart tmipsecd

Or

tmsh restart /sys service tmipsecd

Looking at the tmipsecd log file may yield signs of actual failures, but interpreting these message normally requires the help of F5 Support.
