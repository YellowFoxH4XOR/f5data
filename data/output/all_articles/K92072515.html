Description
When trying to load balance PASV FTP connections through a virtual server, you may experience similar TCP resets to:

[F5RST: FTP error (Illegal argument)]

Environment

  • Virtual sever configured to load balance PASV FTP connections.
  • Virtual server uses an FTP profile.

Cause
BIG-IP expects the server to send back its own address in the PASV response. If the server sends back anything besides its own address the BIG-IP will reset the connection with reason, "Illegal argument".

Recommended Actions

  1. Make sure that the FTP server is sending back it's own address in the PASV response.

    For instance-
    If the FTP server's FQDN is ftp.server.com, its IP address is 10.11.12.13 and the port 40054 is selected by the server at random, then we would expect to see a similar PASV response from the server:

    Response: 227 Entering Passive Mode (10,11,12,13,156,118)
    or
    Response: 227 Entering Passive Mode (ftp,server,com,156,118)

    Where 10,11,12,13 is the servers IP address, or the FQDN ftp,server,com which would translate to 10.11.12.13.

    156,118 is the port designated by the server: (156 * 256) + 118 = 40054
