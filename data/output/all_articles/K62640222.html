Topic

You should consider using this procedure under the following conditions:

  • You have multiple BIG-IP DNS systems located in geographically separate data centers.
  • You want to configure the BIG-IP DNS systems to perform one of the following actions:
    • Fail over a wide IP from one data center to another when a pool (service) becomes unavailable.
    • Fail over a group of wide IPs from one data center to another when a pool (service) becomes unavailable.

Description

BIG-IP DNS data centers represent a group of services or applications that reside in a specific geographic location. BIG-IP DNS systems use pools to represent and monitor the availability of each service or application. To direct application traffic to a primary data center, the wide IPs configured to use Global Availability load balancing mode respond to DNS name resolution requests using the IP addresses of available pools in the primary data center.

Data center failover is the process of changing the IP addresses that the wide IP uses when answering DNS name resolution requests from those of the primary pool in one data center to those of a secondary pool in another data center.

All BIG-IP DNS systems in a configuration synchronization (ConfigSync) group receive requests for DNS name resolution; however, when responding to DNS name resolution requests, the wide IP uses only the IP addresses of primary and available pools.

This article describes how to configure basic data center failover and distributed application failover for the wide IPs.

Basic data center failover

Basic data center failover occurs when one or more primary pools within a data center fail, causing the wide IP to use the IP addresses of secondary pools when answering DNS name resolution requests.

The following table shows a DNS response example in which a Seattle data center uses the 192.168.100.0/24 IP address space and a Spokane data center uses the 192.168.200.0/24 IP address space. All wide IPs are configured to prefer pools residing in the Seattle data center. When the Seattle SEA_http_pool pool fails, the IP addresses that wide IP uses change from those of the SEA_http_pool pool to those of the SPO_http_pool pool, causing traffic to flow to the Spokane data center for those services until the Seattle pool recovers.

Distributed application failover

Distributed applications associate multiple wide IPs, creating a dependency based on the availability of all member wide IPs. When a primary pool in the data center fails, all wide IPs in the distributed application begin using the IP addresses from their secondary pools when answering DNS name resolution requests.

The following table shows a DNS response example in which Seattle data center uses the 192.168.100.0/24 IP address space and the Spokane data center uses the 192.168.200.0/24 IP address space. All wide IPs are configured to prefer pools in the Seattle data center. Also, a distributed application is configured to associate the www.example.com and ldap.example.com wide IPs. When the Seattle SEA_http_one pool fails, the IP addresses that the wide IP uses change from the SEA_http_one and SEA_ldap_one pools to the SPO_http_one and SPO_ldap_one pools, causing traffic to flow to the Spokane data center for those services until the Seattle pool recovers.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the Configuration utility.
  • You have created the necessary data centers and BIG-IP DNS server objects in their respective data centers.
  • You have multiple BIG-IP DNS systems configured in a functioning sync group.
  • You have delegated the necessary subdomains to the BIG-IP DNS systems. For more information, refer to: K277: Delegating a subdomain to a BIG-IP DNS or BIG-IP Link Controller system from another DNS server

Procedures

You can use the following procedures to configure the wide IP data center failover:

  • Configuring basic data center failover
    • Creating the primary and secondary pools
    • Creating the wide IP
  • Configuring distributed application failover
    • Creating the distributed application

Configuring basic data center failover

Use this procedure to configure a primary and secondary pool and a wide IP that uses the Global Availability load balancing algorithm to perform basic data center failover.

Note: Because the BIG-IP DNS system is in a sync group, you can choose any BIG-IP DNS device to perform the procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Creating the primary and secondary pools

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Pools > Pool List.
  3. Click Create.
  4. Under General Properties, for Name , type a unique pool name that identifies the service and, if possible, the location. For example, SEA_http_one for your primary pool and SEA_http_two for your secondary pool.
  5. For Type, click the appropriate DNS query type that wide IP uses to respond:
    • A and AAAA types reference one or more virtual servers.
    • SRV, CNAME, and MX types reference one or more wide IPs.
    • NAPTR type reference one or more flags.
  6. Under Members, for Load Balancing Method, click a load balancing method for Preferred , Alternate , and Fallback.

    Important: If you are creating the primary pool, for Fallback , click None to make sure the system uses the secondary pool rather than BIND. If this is your secondary or additional pool, click None if you intend to configure additional pools. If you do not intend to create more pools, click your preferred load balancing method.

  7. For Member List, use the list associated with the DNS query type you chose in step 5 (Virtual Servers, Wide IP, or Flags) to click the name of the resource you want to add, and then click Add. Repeat this step to the add the remaining resources to the data center pool.
  8. Click Finished.
  9. Repeat these steps to create the secondary pool. Repeat them again to create additional pools.

Creating the wide IP

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Wide IPs > Wide IP List.
  3. Click Create .
  4. Under General Properties, for Name , type the fully qualified subdomain that is delegated to the BIG-IP DNS system.
  5. For Type , click the DNS query type that the wide IP uses to respond.
  6. Under Pools, for Load Balancing Method click Global Availability.
  7. For Pool List, click the primary pool in the Pool list and click Add. Then, click the secondary pool and click Add. Repeat this step for any additional pools, if necessary.
  8. Click Finished.

Configuring distributed application failover

Use this procedure to configure a primary and secondary pool, a wide IP that uses the Global Availability load balancing algorithm, and a distributed application to perform distributed application failover.

Note: Because the BIG-IP DNS system is in a sync group, you can choose any BIG-IP DNS device to perform the procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To configure distributed application failover, first perform the steps from the previous procedures:

  • Creating the primary and secondary pools
  • Creating the wide IP

Next, perform the following procedure to create the distributed application:

Creating the distributed application

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Distributed Applications > Application List.
  3. Click Create .
  4. Under General Properties, for Name , type a unique name for the distributed application.
  5. Under Persistence, click Data Center in the Dependency Level list.
  6. For Member List, in the Wide IP list, click the name of a wide IP and click Add to add it. Repeat this step to add all wide IPs you want to associate with the distributed application.
  7. Click Finished.
