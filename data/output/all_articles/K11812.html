K11812: Failure to specify non-floating self IP addresses in the VLAN group Proxy Exclusion List may cause misdirected monitor traffic

Applies to

Topic

The Proxy Exclusion List is a VLAN group setting that can be used to specify IP addresses to which you do not want the BIG-IP system to send ARP requests.

F5 recommends that if you have a redundant BIG-IP system with a VLAN group configuration, that you define a Proxy Exclusion List for each system. The Proxy Exclusion List for a BIG-IP system should contain all non-floating self IP addresses of the peer system and any other hosts to which you do not want the BIG-IP system to send ARP requests. Failure to define non-floating self IP addresses in the Proxy Exclusion List of the peer system may result in inconsistent monitoring behavior.

Description

In a VLAN group configuration, the BIG-IP system can perform proxied ARP requests. A proxied ARP request is an ARP request that the BIG-IP system can send, on behalf of a host in a VLAN, to hosts in another VLAN. In some cases, you may not want the BIG-IP system to forward proxied ARP requests to a specific host, nor is it recommended for a BIG-IP unit in a redundant system to forward a proxied ARP request to the peer unit.

For example, in a redundant system containing a VLAN group, the standby unit sends ARP broadcast requests on all child VLANs defined in the VLAN group when attempting to populate its ARP table. If the source IP address in the ARP request is not defined in the Proxy Exclusion List of the active BIG-IP unit, then the active unit may send a proxied ARP reply, which forces the standby unit to direct monitor traffic through the incorrect VLAN. As a result, monitor traffic on the standby system may be directed to the node through the active unit's Layer 2 forwarding proxy instead of directly to the node, causing the node(s) to be marked up/down.

The importance of configuring the Proxy Exclusion List on both systems is illustrated in the following scenario:

  • A BIG-IP redundant pair configuration contains a VLAN group called vlangroup1 with child VLANs External and Internal. No Proxy Exclusion List entries are defined on either system.
  • The standby system is monitoring the following node which resides on the Internal VLAN: 10.1.1.100.
  • In order to populate its ARP cache, the standby system broadcasts an ARP request for 10.1.1.100 to both the External and Internal VLANs.
  • When the active system receives the ARP request on its External VLAN, if it does not have a matching ARP entry, the system proxies the ARP request to the Internal VLAN.
  • The 10.1.1.100 node responds to ARP requests from the active system.
  • The active system will now respond to the ARP requests for the node on its External VLAN.
  • If the standby system receives the ARP response from the node first, and then the proxy ARP reply from the active unit, the standby will be left with an ARP entry that directs traffic for 10.1.1.100 out the External VLAN (even though the node is directly connected to the Internal VLAN).

Defining a Proxy Exclusion List on the BIG-IP systems in a high available configuration

You can prevent this kind of behavior by defining a Proxy Exclusion List on the BIG-IP systems in a high available configuration. To define a Proxy Exclusion List, perform the following procedure:

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

BIG-IP 11.x

  1. Log in to the Configuration utility.
  2. Navigate to Network > VLANs > VLAN Groups.
  3. Click on the name of the VLAN group.
  4. Click on the Proxy Exclusion List tab.
  5. Click Create.
  6. Enter the non-floating self IP address of the peer system.
  7. To save the changes, click Finished.
  8. Repeat the procedure on the peer system

BIG-IP 9.x through 10.x

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click VLANs.
  4. Select Proxy Exclusion List from the VLAN Groups menu.
  5. Click Create.
  6. Enter the non-floating self IP address of the peer system.
  7. Click Finished.
  8. Repeat the procedure on the peer system.
