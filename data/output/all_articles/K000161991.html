Description

After a device failover or system reload on BIG-IP LTM, iRules that validate HTTP host headers against a datagroup may fail to match expected entries. This results in valid application traffic being rejected with log messages such as:

  • host name: <hostname> not ending with allowed apigee hosts

  • Match Failed | Host: '<hostname>' | Target Header: <header> | Allowed: <datagroup entries>

Symptoms include service impact to multiple domains and virtual servers, with logs showing only a subset of the expected datagroup entries being loaded into memory for comparison.

Environment

  • High Availability (HA) configuration
  • iRules referencing internal datagroups for host header validation
  • Multiple partitions containing datagroups with the same name

Cause

The issue is caused by having two datagroups with the same name in different partitions, while the iRule references the datagroup by name only (without the full partition path). This leads to non-deterministic selection of which datagroup is loaded into memory, resulting in incomplete or incorrect datagroup entries being used for host header validation.

Answer/Recommended Actions

  • Update all iRules to reference datagroups using the full partition path (e.g., /Partition_Name/Data-Group_Name) instead of just the datagroup name.
  • Audit the configuration to ensure that identically named datagroups across partitions are referenced with their full path in all iRules.
  • After making changes, verify that all expected datagroup entries are loaded and that host header validation works as intended.
  • If the issue persists, recreate the datagroup under a unique name and update the iRule reference accordingly.

Additional Information

  • Referencing a datagroup by name only in a non-Common partition can result in unpredictable behavior, as the system may use whichever datagroup was loaded last.
  • This behavior may not manifest immediately and can be triggered by configuration reloads, failovers, or other system events.
  • Using the full partition path for datagroup references ensures deterministic and correct behavior.
