K74454030: NTLM SSO failing on one server intermittently

Type
Support Solution
Published
2022-08-08
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.4
Source
https://my.f5.com/manage/s/article/K74454030

Description

You are using ltm-apm type access policy. Requests are forwarded to a pool member. NTLM SSO or Kerberos SSO fails intermittently for one server.

  • NTLM SSO or Kerberos session fails intermittently
  • session.ad.last.attr.sAMAccountName.sso.state, value:1

Environment

  • NTLM or Kerberos SSO
  • One connect profile

Cause
This is caused by Bug ID 1050165: APM - users end up with SSO disabled for their session, admin intervention required to clear session

One of the following will be seen in apm logs:

tmm.session.[SID].session.ad.last.attr.sAMAccountName.sso.state:
tmm.session.[SID].session.ad.last.attr.sAMAccountName.sso.state:0
tmm.session.[SID].session.ad.last.attr.sAMAccountName.sso.state:1

After a fresh APM session established, the SSO.state will not be set or set with "0". If the SSO authentication fails for 3 times consecutively, sso.state will be set to 1 and SSO is disabled for the reminder of the APM session. So any new connections from the client lands to the APM session (which has sso.state=1), SSO won't be performed.

This can happen if a SNAT device sits in between the Client systems with fixed source port and BIG-IP or one connect profile is attached to VS.

Recommended Actions

Remove one connect profile from Virtual Server

Additional Information

Bug ID 1050165: APM - users end up with SSO disabled for their session, admin intervention required to clear session
