K000138275: Tenant not fully deleted when resetting F5OS configuration

Type
Support Solution
Published
2024-01-17
Updated
2024-01-17
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000138275

Description

Noticed that running rm -f /var/F5/system/cdb/*.cdb, followed by a reboot, does not fully delete a tenant.

When another tenant is created with the same name, all configuration including passwords are inherited from the previous tenant.

This does not happen if the configuration is reset using system database reset-to-default.

Environment

  • F5OS
  • Tenant creation

Cause

This is expected.

When you run rm -f /var/F5/system/cdb/*.cdb; reboot, this is deleting the confd configuration data stores.

However, the tenant's virtual disk remains [at /var/F5/system/cbip-disks/<tenant>/<tenant>.raw], so when you create a "new" tenant in confd with the same name as the one that was deleted, the system reuses the existing virtual disk.

When you run system database reset-to-default, the system deletes the tenant and its associated virtual disk file.

Recommended Actions

To fully reset the system configuration, use system database reset-to-default.

Additional Information

The rm -f /var/F5/system/cdb/*.cdb method should only be used when attempting to recover from a specific issue (e.g. K000133379 ), or when directed by F5 Support.
