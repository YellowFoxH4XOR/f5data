Description

After deploying a HA pair of LTM in AWS with cloud failover extension (CFE), failover between two instances works as expected by using 'Force to Standby' function. However, after you start to create some virtual servers on the F5, the CFE no longer works as expected. The status of LTM shows correctly in the web GUI (either Active or Standby), which means 'Force to Standby' function still works, but the public IP (F5 vip) of the previous active F5 does not move. In fact, you can observe the public elastic IP was detached from the external interface in AWS networking. In restnoded.log you can see the similar messages:

Environment

  • BIG-IP: BIG-IP 15.1.2 Build 0.0.9 Final
  • f5-appsvcs: f5-appsvcs-3.25.0-3.noarch.rpm
  • f5-cloud-failover: f5-cloud-failover-1.7.1-1.noarch.rpm

Cause

For AWS, CFE supports two network topologies (use cases): - Same-net: when both BIGIP VE instances reside within the same network and therefore it is possible to re-associate IP addresses on BIGIP VE. As a result, virtual addresses are part of floating traffic group. - Across-net: when both BIGIP VE in different AWS availability zones and therefore in different subnets. In this case, there is VIP Elastic Public IP which points to secondary private address of active BIGIP Instance. When failover event happens, CFE just re-associates VIP Elastic Public IP to point to new active BIGIP secondary ip. In this case, virtual address must be included in non-floating traffic group or traffic group is set to “none”
 

Recommended Actions

Set traffic group to 'None' on the virtual addresses

For example,

Local Traffic ›› Virtual Servers : Virtual Address List ›› vip-name

In the Traffic Group option, please select None from the drop-down list. Both virtual addresses needs to be None in the traffic group.
