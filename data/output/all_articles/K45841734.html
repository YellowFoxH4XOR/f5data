K45841734: Connection is not reset by Action on Service Down: Reject

Type
Support Solution
Published
2022-10-17
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K45841734

Description

When OneConnect profile is used, even if Action on Service Down: Reject is configured in Pool, RST may not send.

Environment

  • BIG-IP LTM
  • OneConnect profile
  • HTTP profile

Cause

This is by design. If both an HTTP profile and a OneConnect profile are associated with the virtual server, the BIG-IP system selects a pool member when the client-side connection is first established. When the response is complete, the BIG-IP system automatically detaches the server-side connection. Due to this behavior, you may observe the connection to be idle by using 'tmsh show sys connection' as follows. Since the server-side connection is detached, Action on Service Down: Reject will not work.


Idle Connection:
Sys::Connections
any6.any            any6.any         172.16.222.222:40800  172.16.200.1:80  tcp  9  (tmm: 1)  none  none
10.10.147.65:40800  10.10.111.77:80  any6.any              any6.any         tcp  9  (tmm: 1)  none  none

If the connection is Active as follows, it can be reset by Action on Service Down: Reject.

Active Connection:
Sys::Connections
10.10.147.65:40800  10.10.111.77:80  172.16.222.222:40800  172.16.200.1:80  tcp  0  (tmm: 1)  none  none
