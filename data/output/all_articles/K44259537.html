Topic

You should consider using this procedure under the following conditions:

  • You would like to reboot a VIPRION Virtual Clustered Multiprocessing (vCMP) host or guest system using the Configuration utility.
  • You would like to reboot a VIPRION vCMP host or guest system using the Traffic Management Shell (tmsh).

Description

You can reboot the VIPRION vCMP hosts and guests using either the Configuration utility or tmsh. Both utilities offer options to reboot either the entire chassis or a single blade.

Note: Ensure that vCMP hosts with multiple blades and vCMP guests provisioned on multiple slots have the cluster IP and cluster IP member addresses configured. For assistance, refer to K15690: Changing the cluster IP or cluster member IP addresses for VIPRION platforms.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Have Administrator or Resource Administrator access to the Configuration utility.
  • Have Root or Administrator access to tmsh.

Procedures

It is important to understand what the terms blade and slot refer to in the following procedures:

  • Blade refers to the vCMP host's underlying hardware. Blades are physically installed in the VIPRION chassis.
  • Slot refers to the vCMP guest's use of the underlying hardware. Slots are allocated during guest provisioning.

For example, a two-slot vCMP guest will have been provisioned to use two vCMP host blades.

Rebooting the vCMP Host Chassis using the Configuration utility

Rebooting the vCMP host chassis will reboot all of the installed blades and all vCMP guest instances provisioned on all slots.

Impact of procedure: Performing the following procedure will temporarily halt the vCMP host and traffic processing for all vCMP guests. You should perform this procedure only during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. In the Operations section, click Reboot Chassis.
  4. The BIG-IP system prompts with the message Are you sure you want to reboot this chassis?
  5. Click OK to begin the chassis reboot. You will be logged out of the BIG-IP systems.
  6. Once you are able to access the Configuration utility, navigate to System > Clusters > Properties to verify the blade's cluster status.

Rebooting the vCMP Host Blade using the Configuration utility

Rebooting the vCMP host blade will reboot a single blade and all vCMP guest instances provisioned on that slot. If you are logged in to the Configuration utility using the cluster IP address, the system reboots the primary blade. If you are logged in to the Configuration utility using a cluster member IP address, the system reboots the blade that you are logged in to.

Impact of procedure: Performing the following procedure should not have a negative impact for multiple blade vCMP hosts. It may halt traffic processing for a single slot vCMP guest that is provisioned on the rebooted blade. If you are unsure about the current number of vCMP host blades or vCMP guest slots, you should perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. In the Operations section, click Reboot Blade.
  4. The BIG-IP system prompts with the message Are you sure you want to reboot this blade?
  5. Click OK to begin the blade reboot.
  6. To verify the blade's cluster status, navigate to System > Clusters > Properties.

Rebooting the vCMP Host Chassis using tmsh

Rebooting the vCMP host chassis will reboot all of the installed blades and all vCMP guest instances on all slots.

Impact of procedure: Performing the following procedure will temporarily halt the vCMP host and halt traffic processing for all vCMP guests. You should perform this procedure only during a scheduled maintenance period.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To reboot all installed blades, type the following command.

    You will be logged out of tmsh:

    reboot slot all

  3. Once you are able access tmsh, type the following command to verify the blades cluster status:

    show sys cluster

Rebooting the vCMP Host Chassis using bash

Rebooting the vCMP host chassis will reboot all of the installed blades and all vCMP guest instances on all slots.

Impact of procedure: Performing the following procedure will temporarily halt the vCMP host and halt traffic processing for all vCMP guests. You should perform this procedure only during a scheduled maintenance period.

  1. Log in to the Advanced Shell (bash) by typing the following command:

    bash

  2. To reboot all installed blades, type the following command.

    Note: You will be logged out of the command line.

    clsh reboot

Rebooting the vCMP Host Blade using tmsh

Rebooting the vCMP host blade will reboot only a single blade and all vCMP guest instances provisioned on that slot.

Impact of procedure: Performing the following procedure should not have a negative impact for a multiple blade vCMP host system. The procedure may halt traffic processing for single slot vCMP guest provisioned on the rebooted blade. If you are unsure about the current number of vCMP host blades or vCMP guest slots, you should perform this procedure during a scheduled maintenance period.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To reboot an individual blade, use the following command syntax:

    reboot slot <slot number>

    For example, to reboot the vCMP host slot number 1, type the following command:

    reboot slot 1

  3. To verify the blade's cluster status, type the following command:

    show sys cluster

Rebooting the vCMP Guest Chassis using the Configuration utility

Rebooting the vCMP guest chassis will reboot the vCMP guest instance running on all slots. This will not affect the vCMP host or other vCMP guest instances.

Impact of procedure: Performing the following procedure will temporarily halt traffic processing for the vCMP guest and you should perform the procedure during a scheduled maintenance period. This procedure should not have a negative impact on the vCMP host or other vCMP guests.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. In the Operations section:

    If your system is later than BIG-IP 12.1.0, click Reboot Guest Chassis.

    If your system is earlier than BIG-IP 12.1.0, click Reboot Chassis.

  4. The BIG-IP system prompts with the message Are you sure you want to reboot this chassis?
  5. Click OK to begin the vCMP guest reboot.

    You will be logged out of the Configuration utility.

  6. Once you are able to log in to the Configuration utility, navigate to System > Clusters > Properties to verify the blades cluster status.

Rebooting the vCMP Guest Blade using the Configuration utility

Rebooting the vCMP guest blade will reboot the vCMP guest instance on a single slot. If you are logged in to the Configuration utility using the cluster IP address, the vCMP guest instance running on the primary slot is rebooted. If you are logged in to the Configuration utility using a cluster member IP address, the system reboots the vCMP guest instance running on that slot. This will have no effect on the vCMP host or other vCMP guest slots.

Impact of procedure: Performing the following procedure should not have a negative impact for vCMP guest systems provisioned on more than one slot. This procedure may halt traffic processing for a single-slot vCMP guest provisioned on the rebooted blade. If you are unsure about the current vCMP guest slot count, you should perform this procedure during a scheduled maintenance period. This procedure should not have a negative impact on the vCMP host or other vCMP guests.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. In the Operations section:

    If your system is later than BIG-IP 12.1.0, click Reboot Guest Blade.

    If your system is earlier than BIG-IP 12.1.0, click Reboot Blade.

  4. The BIG-IP system prompts with the message Are you sure you want to reboot this chassis?
  5. Click OK to reboot the vCMP guest slot.
  6. Navigate to System > Clusters > Properties to verify the blade's cluster status.

Rebooting the vCMP Guest Chassis using tmsh

Rebooting the vCMP guest chassis will reboot the vCMP guest instance running on all provisioned slots. This will have no effect on the vCMP host or other vCMP guests.

Impact of procedure: Performing the following procedure will temporarily halt traffic processing for the vCMP guest. This procedure should not have a negative impact on the vCMP host or other vCMP guests.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To reboot all installed blades, type the following command:

    reboot slot all

  3. Once you are able access tmsh, type the following command to verify the blades cluster status:

    show sys cluster

Rebooting the vCMP Guest Chassis using bash

Rebooting the vCMP host chassis will reboot all of the installed blades and all vCMP guest instances on all slots.

Impact of procedure: Performing the following procedure will temporarily halt the vCMP host and halt traffic processing for all vCMP guests. You should perform this procedure only during a scheduled maintenance period.

  1. Log in to bash by typing the following command:

Rebooting the vCMP Guest Blade using tmsh

Rebooting the vCMP guest blade will reboot the vCMP guest instance on a single slot. This will have no effect on the vCMP host or other vCMP guest slots.

Impact of procedure: Performing the following procedure should not have a negative impact for vCMP guest systems provisioned on more than one slot. It may halt traffic processing for single-slot vCMP guest provisioned on the rebooted blade. If you are unsure about the current vCMP guest slot provisioning count, you should perform this procedure during a scheduled maintenance period. This procedure should not have a negative impact on the vCMP host or other vCMP guests.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To reboot an individual blade, use the following command syntax:

    reboot slot <slot number>

    For example, to reboot the vCMP guest's slot number 1, type the following command:

    reboot slot 1

  3. To verify the blade's cluster status, type the following command:

    show sys cluster
