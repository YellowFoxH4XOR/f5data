Description

This article addresses an issue on F5 BIG-IP LTM systems where the following TCL error is logged when using an iRule:

TCL error: /Common/exampleiRule <LB_FAILED> - no such pool: (line 1) invoked from within "active_members [LB::server pool]"
The error occurs when the iRule tries to execute [active_members [LB::server pool]], but the referenced pool does not exist or is unavailable in the current context. This situation typically arises on virtual servers without a default pool assigned and where LTM policies are used for dynamic pool selection. 

Environment

  • iRule
  • Pool Member

Cause

The command [active_members [LB::server pool]] fails when there is no default pool configured on the virtual server. In this case, [LB::server pool] returns a non-existent or invalid pool name, resulting in a "no such pool" error. 

Recommended Actions

Ensure a default pool is configured on the virtual server or modify the iRule logic to handle cases where no default pool is present.

If you use LTM policies for dynamic pool selection and do not wish to assign a default pool, update your iRule to reference only pools selected by policy or ensure it does not attempt to access non-existent pools.
