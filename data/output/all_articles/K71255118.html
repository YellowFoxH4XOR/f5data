Known Issue

Virtual Clustered Multiprocessing (vCMP) guests may deploy with the hostname bigip1.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is running 11.6.0 or earlier.
  • You configure a vCMP guest instance that is running BIG-IP 11.6.0 or later.
  • You have configured the vCMP guest instance with a hostname other than bigip1.
  • You deploy the vCMP guest instance.

Impact

The vCMP guest does not use the configured hostname.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you access the vCMP guest instance after you deploy the system, the instance uses the hostname bigip1.

Workaround

To work around this issue, you can manually edit the configuration file bigip_base.conf and configure the correct hostname. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure requires that you reload the system configuration, which temporarily disrupts traffic processing.

  1. Log in to the affected vCMP guest command line with administrative privileges.
  2. Create a backup file /config/bigip_base.conf by typing the following command:

    cp /config/bigip_base.conf /config/bigip_base.conf_646768

  3. Replace all instances of bigip1 in the file /config/bigip_base.conf and port to the new file /config/new_bigip_base.conf by typing the following command:

    cat /config/bigip_base.conf | sed 's/bigip1/<hostname>/g' | tee /config/new_bigip_base.conf

    Important: Replace <hostname> with the hostname you want for the vCMP guest.

  4. Replace the existing /config/bigip_base.conf file with the updated /config/new_bigip_base.conf file by typing the following command:

    cp -f /config/new_bigip_base.conf  /config/bigip_base.conf

  5. Load the system configuration with the following TMOS Shell (tmsh) command:

    tmsh load /sys config

  6. To verify the hostname change, type the following command:

    tmsh show /cm device
