Description:
As a result of an upstream change, UDP packets arrive to the BIG-IP from a different MAC address than the UDP connection was established with.
  • UDP client is not receiving a response from the BIG-IP.
  • Packet captures indicate the BIG-IP is sending the responses to a MAC address that is not the current MAC address for the next hop back to the client.

Environment:
  • UDP connection
  • Auto-Lasthop enabled
  • Client MAC address changes for an existing UDP connection

Cause:
The UDP virtual server is enabled for Auto Last Hop (default setting).  Auto Last Hop will continue to use the original MAC address that the connection was established with for the life of the connection. New connections will use the new MAC address.

Note: even though UDP is a connectionless protocol, BIG-IP treats UDP packets from the same source IP address and port as a 'connection' . The lifespan of the connection is determined by the amount and frequency of connection traffic. You may be able to control the lifespan of the UDP connection using the Idle Timeout setting in the UDP profile. For information about the Idle Timeout value refer to K7535: Overview of the UDP profile.

Recommended Actions:
Depending on the specific environment, there are multiple methods to mitigate this condition.
  • Determine the reason for the upstream MAC address changes, and try to prevent the MAC address changes (perhaps MAC masquerade, VRRP, or HSRP depending on your specific environment and he upstream device(s))
  • BIG-IP configuration changes:
    • Disable Auto Last Hop for the affected virtual server and configure the virtual server to use a Last Hop Pool.
    • Disable Auto Last Hop for the affected virtual server and allow the connections to be routed based on routing table. However, this could have other implications and would require appropriate routing be in place for affected traffic.
    • Shorten the idle time (UDP profile) for the affect virtual server. This will not completely eliminate the possibility of the issue occurring. However, this could allow the connection to end sooner (if idle) and allow a new connection be established from the new MAC address.
Any of these methods would need to be evaluated and tested in the specific environment.
