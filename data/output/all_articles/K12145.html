Known Issue

This is the result of a known issue. A custom port specified for Windows Remote Management (WinRM) is not retained after editing and saving the file server configuration using the ARX Manager GUI. As a result, the ARX system will use the default port (80).

Note: This behavior occurs when the customer presses the OK button to save the file server configuration, even if the customer did not make any changes to the file server configuration.

Note: For information about a related issue, refer to K12144: The Windows Remote Management port for a file server cannot be configured using the ARX Manager GUI.

F5 Product Development tracked this issue as ID 339599 and it was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX release notes.

Workaround

Customers can work around this issue by using the command line to edit file server (external-filer) configurations.
