Known Issue

This is the result of a known issue. If a FirePass cluster is configured for load balancing, and a user’s Windows domain password is expired, the user may not  be able to logon to the FirePass controller. FirePass may report that the domain password is expired when the user attempts to logon, but not allow the user to change it.

Note: Load balancing is enabled for a cluster if the Load Balancing menu is set to Random on the Clustering : Settings page on the primary (master) cluster node.

This issue occurs when the user is redirected to a FirePass secondary (slave) cluster node for logon. When the user logs on to the primary cluster node, the user can successfully update the expired domain password.

F5 Product Development tracked this issue as CR106973.

Additionally, cumulative hotfix HF-602-7.2 has been issued for FirePass 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by selecting the Allow optional manual logon to slave nodes from master logon page check box on the Clustering : Settings page on the primary cluster node. If a user has an expired domain password, the user can select the primary cluster node at the logon page, and then update the domain password when prompted.
