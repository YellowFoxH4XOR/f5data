Topic

NGINX Controller 3.0.0 introduces a new design to the user interface. When you browse the NGINX Controller 3.0.0 or later user interface, depending on the filter rules employed, certain content-filtering and ad-blocking web browser extensions may incorrectly block the elements on the NGINX Controller events page. As a result, when you access the Analytics > Events page using the NGINX Controller user interface, you may observe messages indicating missing events or other. The following figure shows an example of such a message displaying in the NGINX Controller user interface.

Figure: Message indicating missing events on the Analytics > Events page

Description

You should verify the filtering rules of the ad blocker when encountering a message such as the one shown previously on the NGINX Controller events page. For example, the uBlock Origin browser extension has the EasyPrivacy filter enabled by default. This filter includes the /analytics/event string, which blocks some elements on the Controller events page requiring the /analytics/events string in the HTTP request URIs.

To work around this issue, you can include the NGINX Controller host name or the URI string of the events page in the ad-blocker accept list. To acceptlist the Controller Events page in the uBlock Origin browser extension, include the following syntax in the uBlock Origin accept list settings:

*<Controller_hostname>/analytics/events*

For example, to acceptlist the NGINX Controller with host name example.mycontroller.net, include the following string in the accept list:

*example.mycontroller.net/analytics/events*

Note: To apply the new filtering rules after adding items in the ad-blocker accept list, initiate a fresh HTTP session by opening a new NGINX Controller user interface page.
