Topic

Beginning in the following BIG-IP versions in their respective software branches, BIG-IP Virtual Edition (VE) preserves the NIC ordering for five or more network interfaces, when you enable the vAPP option on VMware:

  • BIG-IP 17.x.x
  • BIG-IP 16.1.x: 16.1.2.2
  • BIG-IP 15.1.x: 15.1.5.1
  • BIG-IP 14.1.x: 14.1.X

Description

Old Behavior

BIG-IP VE does not preserve the NIC ordering when you add five or more network interfaces in VMware. When you perform the procedure Adding more TMM interfaces (for a total range between 5 and 10) described in K12149: Adding TMM interfaces to the BIG-IP or BIG-IQ VE running on VMware ESXi, the system may not add the Traffic Management Microkernel (TMM) interface in the same order as that in the VMware hypervisor.

The NIC ordering (beginning from the fifth NIC), is based on the PCI bus ordering, which is not consistent with the hypervisor ordering. You can view the PCI ordering by entering the following command on the BIG-IP system:

cat /etc/ethmap 

To display the list of network interfaces on the BIG-IP system, enter the following command:

tmsh show net interface all-properties

New Behavior

Starting from the following versions:

  • BIG-IP 17.x.x: 17.0.0
  • BIG-IP 16.1.x: 16.1.2.2
  • BIG-IP 15.1.x: 15.1.5.1
  • BIG-IP 14.1.x: 14.1.5

If you enable the vAPP option on VMware, the TMM interface is added following the same order as in the VMware hypervisor when you add TMM interfaces (beginning from the fifth one).

Note: The procedure to add/remove the interface, described in Adding more TMM interfaces (for a total range between 5 and 10) in K12149: Adding TMM interfaces to the BIG-IP or BIG-IQ VE running on VMware ESXi, remains unchanged.

The new NIC ordering is consistent with the hypervisor ordering and can be displayed using the following vmtoolsd command:

  • vmtoolsd --cmd "info-get guestinfo.ovfEnv"

When the vApp option is not enabled on VMware, the system uses the old behavior.

F5 Product Development tracked this change as ID 1026005.

Impact

In the old behavior, you may encounter issues with automation scripts that assume the TMM interfaces on the BIG-IP system follow the ordering on the hypervisor.

Recommendations

  • Enable the vApp option for your virtual machine to use the new behavior
  • Display the NIC ordering on the hypervisor using the vmtoolsd command
  • Verify the new behavior

Enable the vApp option for your virtual machine to use the new behavior

  1. On the vCenter Server inventory configuration utility, enable the following two options for your virtual machine:
    • Enable vApp options

      For more information, refer to Enable vApp Options for a Virtual Machine and your VMware documentation.

      Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

    • OVF environment transport > VMware Tools

    The following image illustrates the two options to enable:

    Figure: Enable vApp option on VMware

  2. Once the options are enabled on your device, reboot the virtual machine by powering it off and then powering it on from the hypervisor.

Display the NIC ordering on the hypervisor using the vmtoolsd command

After enabling the vApp option, you can use the vmtoolsd command to display the NIC ordering on the hypervisor:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system.
  2. To display the NIC ordering on the hypervisor, enter the following command:

    vmtoolsd --cmd "info-get guestinfo.ovfEnv"

    The XML output appears similar to the following example:

    <?xml version="1.0" encoding="UTF-8"?>
    <Environment
    [...]
          <Version>6.7.0</Version>
          <Vendor>VMware, Inc.</Vendor>
          <Locale>en</Locale>
       </PlatformSection>
       <ve:EthernetAdapterSection>
          <ve:Adapter ve:mac="00:50:56:93:b0:4b" ve:network="Public Access" ve:unitNumber="7"/>
          <ve:Adapter ve:mac="00:50:56:93:2f:c9" ve:network="Public Access" ve:unitNumber="8"/>
          <ve:Adapter ve:mac="00:50:56:93:49:26" ve:network="exampleInternal" ve:unitNumber="9"/>
          <ve:Adapter ve:mac="00:50:56:93:a4:21" ve:network="Public Access" ve:unitNumber="10"/>
       </ve:EthernetAdapterSection>
    </Environment>

    The BIG-IP system follows the order as illustrated by ve:unitNumber=. If you do not have the vApp option enabled on VMware, the output appears similar to the following example:

    No value found

Verify the new behavior

Verify /var/log/boot.log

To verify the new behavior, refer to the /var/log/boot.log file after a system reboot. The entry appears similar to the following example:

notice: Setting BIG-IP ordering using VMware hypervisor NIC ordering.

When the vApp option is not enabled and the system uses the old behavior, the entry appears similar to the following example:

notice: logger[xxx] : Cannot set VMware's hypervisor NIC ordering: VMware tools transport for ovfEnv/vApp should be enabled and the VE restarted from the hypervisor.

Verify NIC ordering using tmsh

To display the list of network interfaces on the BIG-IP system, enter the following command:

tmsh show net interface all-properties
