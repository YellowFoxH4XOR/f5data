Issue

Description

The BIG-IP Edge Client or browser VPN client remains in the initializing state, giving the impression of a disconnect/reconnect issue when connecting to the VPN.

Environment

  • BIG-IP APM Network Access in full- or split-tunnel mode with a client proxy auto-config (PAC) file
  • BIG-IP Edge Client for Windows
  • Browser Network Access client

Cause

The VPN client is not able to download the PAC file from the specified location through the network access tunnel.

Recommended Actions

Reviewing the log files

  • Review the log file logterminal.txt for the following errors:

    Note: Depending on the Windows version, configuration, and user permissions, log files may be located in the %userprofile%\Local Settings\Temp, %temp%, or %userprofile%\AppData\Local\Temp file.

    The following log message syntax indicates that the VPN client cannot download the PAC file from the specified location through the network access tunnel:

    <date>,<time>, DIALER \PACHelper.cpp, WritePACFileFromURL, Failed to connect for downloading a PAC file (URL: http://<IP address or host>)

    The following log messages syntax indicate that the VPN client is not able to resolve the DNS name of the PAC host:

    <date>,<time>, DIALER \PACHelper.cpp, PrepareURL, EXCEPTION - Failed to Resolve Host Name: <host>
    <date>,<time>, DIALER \PACHelper.cpp, WritePACFileFromURL, EXCEPTION caught: Failed to prepare URL for fetching PAC file

Verifying the Network Access resource configuration

Confirm that the Network Access setting on the BIG-IP APM Ignore Client Proxy Autoconfig Script Download Failure is set. If this is the case, the VPN clients disregard the failure and continue to connect to the VPN.

  1. Log in to the Configuration utility.
  2. Go to Access > Connectivity/VPN > Network Access (VPN) > Network Access List.
  3. Select your Network Access resource.
  4. Select the Network Settings tab.
  5. For Client Settings, select Advanced.

    Note: This setting is not visible unless client proxy settings are enabled.

You can also verify the setting from the client side logterminal.txt file by searching for the following log line syntax:

<date>,<time>, HOST CHostCtrl::Load properties, HostCtrl information: property #42, name="PACIgnoreError0", value="yes".

If this setting is configured, then the PAC failure is not what is causing the disconnect condition.

Checking your network routing

  • Confirm networking (Routing, DNS, and HTTP) and PAC availability from the BIG-IP system. For example:

    [root@1-3009487461-bigip1:Active:Standalone] config # ip route get <IP>
    10.10.10.253 dev Internal src 10.10.10.152
    cache
    [root@1-3009487461-bigip1:Active:Standalone] config # curl http://<IP>
