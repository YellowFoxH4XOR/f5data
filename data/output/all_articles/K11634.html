K11634: The BIG-IP WebAccelerator may abort connections when initial requests bypass the acceleration policy

Known Issue

This is the result of a known issue. When a client establishes a connection with a BIG-IP WebAccelerator virtual server and sends initial requests that bypass the acceleration policy due to buffer shortages or request queue overflow, any subsequent requests sent over the same connection that do not bypass the policy will cause the connection to be aborted.

This behavior is due to how the BIG-IP WebAccelerator initializes the context for the server-side flow. When the client first establishes the connection to the virtual server and the initial requests bypass the acceleration policy, the BIG-IP WebAccelerator system does not establish the server-side flow for non-bypassed traffic. When the client sends subsequent requests that are processed by the policy, the BIG-IP WebAccelerator system aborts the connection because the server-side context does not exist for the traffic.

F5 Product Development tracked this issue as CR135955 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

This issue was fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
