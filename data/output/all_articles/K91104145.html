Topic

You should consider using this procedure under the following condition:

  • You have a virtual server configured to serve multiple sites.
  • You want to only allow access to the virtual server for certain host and URL path combinations.

Description

You can configure the BIG-IP system to limit access to a virtual server to only the host and URL path combinations that you specify. Using local traffic policies, you can create rules that inspect HTTP requests and compare the host name in the Host header and the URL path provided in the Request Line to the list of allowed hosts and paths in the rules. If the host name or URL path fails to match, the BIG-IP system can reset the connection.

For example, you can create a policy to reject all requests to a virtual server unless the requested URL path starts with /images/ or /api/ and the hostname is either abc.com or 123.com:

  • abc.com/images/*
  • abc.com/api/*
  • 123.com/images/*
  • 123.com/api/*

In the following example policy, there are two rules configured. The first rule, named host, checks the Host header in the request for either abc.com or 123.com.  If there is no match, a message is logged to the /var/log/ltm file and the connection is reset. The second rule, named path, checks to see if the URL path found in the Request Line of the request starts with either /images/ or /api/. If the URL in the request does not start with either entry, a message is logged to the /var/log/ltm file and the connection is reset.

Using the previous example, the following host/path combinations are rejected by the BIG-IP system:

  • www.abc.com/images/
  • abc.com/image/index.html
  • abc.net/images/
  • 123.com/api
  • 123.org/api/
  • example.com

ltm policy host_path {
    requires { http }
    rules {
        host {
            actions {
                0 {
                    log
                    write
                    facility local0
                    message "tcl:[HTTP::host] blocked"
                    priority info
                }
                1 {
                    shutdown
                    connection
                }
            }
            conditions {
                0 {
                    http-host
                    host
                    not
                    values { abc.com 123.com }
                }
            }
        }
        path {
            actions {
                0 {
                    log
                    write
                    facility local0
                    message "tcl:[HTTP::uri] blocked"
                    priority info
                }
                1 {
                    shutdown
                    connection
                }
            }
            conditions {
                0 {
                    http-uri
                    path
                    not
                    starts-with
                    values { /images/ /api/ }
                }
            }
            ordinal 1
        }
    }
    status published
    strategy first-match
}

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility, TMOS Shell (tmsh), and the iControl REST API.
  • You have command line access to a Linux system (or an alternate BIG-IP system) that has the curl and jq (command-line JSON processor) utilities installed.

Procedures

You can create local traffic policies using the Configuration utility, the Traffic Management Shell (tmsh), or by using the iControl REST API.  To create the above example policy, perform one of the following procedures:

  • Configuring the local traffic policy using the Configuration utility
  • Configuring the local traffic policy using tmsh
  • Configuring the local traffic policy using iControl REST

Configuring the local traffic policy using the Configuration utility

When you create a local traffic policy you first create a draft of the policy. After the draft is published, you can associate it with a virtual server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies > Policy List.
  3. Select Create and provide a name for the draft policy.
  4. Go to the Local Traffic > Policies > Policy List.
  5. Under Draft Policies, select the name of the draft policy.
  6. For Rules, select Create. 
  7. For Name, enter a name for the rule.
  8. For Match all of the following conditions, select the add icon (+) and configure the conditions so that the statement reads as follows:

    HTTP Host host is not any of abc.com 123.com at request time.

  9. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows:

    Log message tcl:[HTTP::host] blocked. at request time.

  10. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows:

    Reset traffic connection at request time.

  11. Select Save.
  12. For Rules, select Create. 
  13. For Name, enter a name for the second rule.
  14. For Match all of the following conditions, select the add icon (+) and configure the conditions so that the statement reads as follows:

    HTTP URI path does not start with /images/ /api/ at request time.

  15. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows: 

    Log message tcl:[HTTP::uri] blocked. at request time.

  16. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows:

    Reset traffic connection at request time.

  17. Select Save.
  18. To save the draft and publish the policy, under General Properties, for Save Draft, select Save and Publish Policy. 
  19. To apply the published policy to a virtual server, go to Local Traffic > Virtual Servers > Virtual Server List.
  20. Under Resources for the virtual server, select Edit.
  21. Under Policies, select Manage.
  22. Select the published policy from the Available list, then to move it to the Enabled list.
  23. Select Finished.

Configuring the local traffic policy using tmsh

To create a draft of the local traffic policy, publish the policy, and associate it with a virtual server using tmsh, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create the policy using the following syntax:

    create /ltm policy /Common/Drafts/<policy_name> rules add { <rule1_name> { conditions add { <ordinal> { http-host host not values { <hostname_list> } request } actions add { <ordinal> { log write facility <facility> message "<message>" priority <priority> request } <ordinal> { shutdown connection request } } } <rule2_name> { conditions add { <ordinal> { http-uri path not starts-with values { /images/ /api/ } request } } actions add { <ordinal> { log write facility <faclility> message "<message>" priority <priority> request } <ordinal> { shutdown connection request } } } } requires add { http } strategy first-match

    To create the policy used in the previous syntax, enter the following:

    create /ltm policy /Common/Drafts/host_path rules add { host { conditions add { 0 { http-host host not values  { abc.com 123.com } request } } actions add { 0 { log write facility local0 message "tcl:[HTTP::host] blocked." priority info request } 1 { shutdown connection request } } } path { conditions add { 0 { http-uri path not starts-with values { /images/ /api/ } request } } actions add { 0 { log write facility local0 message "tcl:[HTTP::uri] blocked." priority info request } 1 { shutdown connection request } } } } requires add { http } strategy first-match

  3. Publish the policy using the following syntax:

    publish /ltm policy <policy_name>

    For example:

    publish /ltm policy Drafts/host_path

  4. Associate the published policy with the virtual server using the following syntax:

    modify /ltm virtual <virtual_server_name> policies add { <policy_name> }

    For example, to associate the host_path local traffic policy with the vs_http virtual server, enter the following command:

    modify /ltm virtual vs_http policies add { host_path }
