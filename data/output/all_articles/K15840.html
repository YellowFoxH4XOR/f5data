Known Issue

Configuration synchronization (ConfigSync) operations may fail with an sFlow receiver object error message. This issue occurs when the following condition is met:

  • You perform a ConfigSync operation after one of the following events:
    • You modify or delete an iApp (or the objects created by an iApp), even if you have not defined an sFlow receiver object in the configuration
    • Immediately after a device fails over

Impact

Users cannot perform a ConfigSync operation between devices in a device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H490961 on the Diagnostics > Identified > Medium screen.
  • Your BIG-IP system fails to complete the ConfigSync operation and reports error messages in the /var/log/ltm file that appear similar to the following example:

    01070710:3: Database error (13), Cannot update_indexes/checkpoint DB object, class:sflow_http_virtual_data_source status:13 - EdbCfgObj.cpp, line 127.
    01071488:3: Remote transaction for device group /Common/device-group-failover-1ca07debf6ef to commit id 3 6053095026189915855 /Common/bigip1.example.com 0 failed with error 01070710:3: Database error (13), Cannot update_indexes/checkpoint DB object, class:sflow_http_virtual_data_source status:13 - EdbCfgObj.cpp, line 127..

Workaround

To work around this issue, you can force the mcpd process to reload the BIG-IP configuration. To do so, perform the steps described in K13030: Forcing the mcpd process to reload the BIG-IP configuration.

Impact of workaround: Rebooting the BIG-IP system disrupts traffic processing until the system is back up.
