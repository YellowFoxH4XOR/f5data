Issue

A user configuration set (UCS) is an archive of the configuration files that the BIG-IP system requires to restore the system. When you save the BIG-IP system configuration to a UCS file, the UCS file contains the existing license file.

BIG-IP 10.1.0 and later

Beginning in BIG-IP 10.1.0, when you restore the UCS file on the BIG-IP system, the UCS installer uses the following logic to determine whether to install the license from the UCS file or to retain the system's existing license file:

  • The system installs the license file from the UCS file only when the host name in the UCS file matches the system host name, even if the system already has a license.

F5 Product Development made this change in response to ID 205356 (formerly CR 114586), to simplify the license management process.

If you plan to replace a BIG-IP 10.1.0 or later system, ensure that you perform one of the following procedures before you install the UCS archive:

  • Make a backup copy of the existing license file, which is located at /config/bigip.license. You will restore the license after you have installed the UCS.
  • Open a case with F5 Technical Support requesting that they move the license from the serial number of the original system to the serial number of the new system. Once they have moved the license, you can install the UCS archive without first saving the existing license.

    Note: Moving a license file to a new serial number is only performed by F5 Technical Support as needed in the event of a Return Materials Authorization (RMA).

BIG-IP 9.0.0 - 10.0.x

In versions prior to 10.1.0, when you restore the UCS file on the BIG-IP system, the UCS installer uses the following logic to determine whether to retain the system's existing license file or to install the license from the UCS file:

  • The system installs the UCS license file only when the host name in the UCS file matches the system host name.
  • If the BIG-IP system does not have a /config/bigip.license file, the system installs the UCS license file.
  • If the BIG-IP system has a /config/bigip.license file, the system performs the following checks to determine whether to retain the system's existing license file or to install the license file from the UCS.
    • If neither license file contains a License end date, the BIG-IP system uses the LATEST_ONE.

      Note: For more information, refer to the following LATEST_ONE section.

    • If both licenses contain a License end date, the BIG-IP system uses the license that expires last. If the time limited date is the same, the BIG-IP system uses the LATEST_ONE.

      Note: For more information, refer to the following LATEST_ONE section.

    • If only one license contains a License end date:
      • If the license has expired, the system uses the other license.
      • If the license is still valid, the system uses the LATEST_ONE.

      Note: For more information, refer to the following LATEST_ONE section.

LATEST_ONE

Using the following LATEST_ONE criteria, the BIG-IP system refers to the service check dates in both bigip.license files for the following conditions, and proceeds as follows:

  • If only one license contains a service check date, the system uses that license.
  • If both licenses contain a service check date, the system uses the license with the latest service check date.
  • If the service check dates match or do not exist, the system refers to the license check dates and uses the license with latest license check date.
