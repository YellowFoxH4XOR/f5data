Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file. This issue occurs when the following condition is met:

  • A Clustered Multiprocessing (CMP)-enabled virtual server forwards traffic to a CMP-disabled virtual server on the same BIG-IP system.

    For example, this condition can happen in the following scenarios:

    • A CMP-enabled virtual server uses the virtual iRule command to target a CMP-disabled virtual server.
    • A CMP-enabled virtual server is demoted to CMP-disabled, because it uses an iRule that is not CMP-compatible (such as an iRule that uses Tool Command Language (Tcl) global variables), and then another CMP-enabled virtual server subsequently forwards traffic to the CMP-disabled virtual server.

Impact

The BIG-IP system temporarily fails to process traffic, and may fail over if configured as part of a high availability (HA) system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H508489 on the Diagnostics > Identified > High screen.
  • Your BIG-IP system fails over to the standby system if configured as part of a HA system.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system logs a panic string, similar to the following example, to the /var/log/tmm file:

    panic: ../net/loop.c:487: Assertion "cmp dest set on incorrect listener type" failed.

Workaround

There is no workaround for this issue. However, F5 recommends that you avoid using CMP-disabled virtual servers or iRules that are not CMP-compatible, which demote CMP-enabled virtual servers to CMP-disabled.

For more information about constructing CMP-compatible iRules, refer to K13033: Constructing CMP-compatible iRules.
