K3558: TCP and UDP ports that are open and listening on FirePass

Topic

Security auditing tools (such as Nessus, Nikto, Nmap, and Whisker) will flag FirePass Controller services as potential security vulnerabilities.

The following descriptions explain each service, the potential risks for exposure, and how to best secure your system.

Port 22 TCP (SSH)

SSH access to FirePass allows F5 Technical Support to remotely access FirePass to diagnose problems. The authentication method and information is available to only a limited number of F5 Support personnel.

The SSH version used on FirePass is fully patched and considered low risk. F5 responds quickly to new vulnerabilities. However, as with any application, vulnerabilities could exist and F5 recommends that you block access to this port when it is not in use.

If you want to restrict access to this feature, you can configure a firewall to block incoming TCP connections to port 22 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation.

Port 67 UDP (DHCP Relay)

Starting in FirePass versions 6.0.3 and 6.1.0, DHCP Relay Agent is included with FirePass to support the DHCP Relay feature on UDP Port 67.

This DHCP Relay Agent is custom F5 software and is considered low risk. F5 responds quickly to new vulnerabilities. However, F5 recommends that you configure your firewall to block incoming UDP connections to port 67 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation.

Port 80 TCP (HTTP)

FirePass runs the Apache Web server to allow HTTP connections to the FirePass Administrative Console. These connections are redirected internally to port 443 (HTTPS).

The Apache version used on FirePass is fully patched and considered low risk. F5 responds quickly to new vulnerabilities. However, this service is not required for any FirePass feature, so F5 recommends that you disable it.

You can disable HTTP support on the FirePass from the FirePass Web Services configuration screen. Additionally, you can configure your firewall to block incoming TCP connections to port 80 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation.

Port 81 TCP (Desktop Access)

FirePass uses port 81 for the Desktop Access feature.

Starting in FirePass version 5.2.0, you can disable the Desktop Access feature. Additionally, you can configure your firewall to block incoming TCP connections to port 81 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation. For information about disabling the Desktop Access feature, refer to the online help on the Web Services tab of the Device Management: Configuration: Network Configuration page.

Note: FirePass version 5.5.2 is the last version of FirePass software to support the Desktop Access feature. For more information, refer to K5491: End of Life Announcement for the Desktop Access, VASCO Built-in Server, Unix Adapter and Solaris Client Support Features.

Port 443 TCP (HTTPS)

FirePass runs the Apache Web server to allow HTTP connections to the FirePass Administrative Console. FirePass also processes all VPN connections through this port.

HTTPS is well known as a secure protocol and the Apache version used on FirePass is fully patched and considered low risk. F5 responds quickly to new vulnerabilities. This service is required for FirePass administration and the use of any VPN features.

You should not block remote access to port 443.

Port 161 UDP (SNMP)

Port 161 provides access to the FirePass SNMP service.

The snmpd version for FirePass is fully patched and considered a low risk. F5 responds quickly to new vulnerabilities. However, you should disable this service if you are not using SNMP monitoring.

You can also configure your firewall to block incoming UDP connections to port 161 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation.

Port 514 UDP (SYSLOG)

Port 514 is used when syslog is configured to log data to a remote syslog server.

The version of syslog that is used on FirePass is fully patched and considered low risk. F5 responds quickly to new vulnerabilities. However, F5 recommends that you disable this service if you are not using remote logging.

You can also configure your firewall to block incoming UDP connections to port 514 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation.

Port 10001 TCP (MyDesktop)

Port 10001 is a bridge port used to allow direct access between MyDesktop remote and desktop machines.

Starting in FirePass version 5.2.0, you can disable the MyDesktop feature. Additionally, you can configure your firewall to block incoming TCP connections to port 10001 on the FirePass controller.

Note: For information about blocking connections, refer to your firewall or router documentation. For information about disabling the MyDesktop feature, refer to the on-line help on the Web Services tab of the Device Management: Configuration: Network Configuration page.

Ports 32768 - 33000 UDP

Several FirePass internal services including the SNMP trap service and the RADIUS client service bind to varying UDP high ports. These ports numbers are dynamically assigned when the services start, and each assigned port number typically falls within the 32768to 32780 range.

Note: For information about blocking connections, refer to your firewall or router documentation.
