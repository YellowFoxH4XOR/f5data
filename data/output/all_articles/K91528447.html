Known Issue

The configuration may fail to load after you create multiple IP forwarding virtual servers.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with route domains.
  • In a partition other than the /Common partition you create an any IP forwarding virtual server in the default route domain (for example: 0.0.0.0:any or 0.0.0.0:0).
  • Using the Traffic Management Shell (tmsh), you create an any IP forwarding virtual server  in a partition other than the /Common partition that resides in a non-default route domain.
  • You save the configuration changes.
  • You attempt to load the system configuration.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you attempt to load the system configuration, you may view an error message that appears similar to the following example:

    0107176c:3: Invalid Virtual Address, the IP address 0.0.0.0%<route domain number> already exists

Workaround

To work around this issue, you can modify the partition/route domain bigip.conf file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log on to the command line of the affected BIG-IP system.
  2. Using a text editor, open the/config/partitions/<partition name>/bigip.conf file of the affected partition/route domain.
  3. Locate all instances of the following highlighted stanza.

    For example:

    ltm virtual-address /route_domain_10_partition/0.0.0.0%10 {
    address any%10
    arp disabled
    icmp-echo disabled
    mask 255.255.255.255
    traffic-group /Common/traffic-group-1
    }

  4. Replace all references of any%<route domain> with 0.0.0.0%<route domain>.

    For example:

    ltm virtual-address /route_domain_10_partition/0.0.0.0%10 {
    address 0.0.0.0%10
    arp disabled
    icmp-echo disabled
    mask 255.255.255.255
    traffic-group /Common/traffic-group-1
    }

  5. Save the file modifications.
  6. Load the system configuration by typing the following command:

    tmsh load /sys config
