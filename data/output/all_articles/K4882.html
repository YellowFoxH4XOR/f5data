Topic

You can configure a FirePass Portal Access Web Application favorite to view a web portal page such as Citrix Web Interface (formerly Citrix NFuse) with a list of published Citrix resources. However, if the web server which hosts the portal page does not return the HTTP Content-Type header of application/x-ica, or if an intermediate device such as a proxy or an application-aware firewall changes the HTTP Content-Type header from application/x-ica to another value, communication between the client and the Citrix web portal will not function properly through Portal Access.

When a user selects a published resource on a Citrix web portal page, a Citrix ICA client configuration file is downloaded from the portal. The ICA configuration file contains the IP address of the Citrix XenApp server (formerly Citrix Presentation Server and Citrix MetaFrame Server), which will serve the published resource to the Citrix ICA Web Client. The line in the ICA configuration file with the server IP address appears similar to the following example:

Address=192.168.101.128

IP addresses are used by default; the Citrix server can be configured to use a hostname/fully qualified domain name (FQDN) instead.

The HTTP response containing the ICA configuration file should have an HTTP Content-Type header of application/x-ica. The FirePass reverse-proxy engine uses this header to identify Citrix ICA traffic, and it rewrites the Address parameter in the ICA configuration file to a loopback IP address on the client system. The reverse-proxy engine will then automatically launch a Static Applicaton Tunnel (FirePass version 6.x) or an Application Tunnel (FirePass version 5.x) to permit the Citrix ICA Web Client to connect to the Citrix server using the ICA protocol. The ICA protocol uses either TCP port 1494, or TCP port 2598 if Session Reliability is enabled (FirePass version 6.0.2 or later). The loopback IP address inserted into the ICA file is used by the auto-launched Application Tunnel in the same manner as an Application Tunnel favorite created by the FirePass administrator would use the loopback IP address specified in the Application Tunnel favorite's Local Host field.

If you cannot connect to a Citrix server with your ICA Web client, the FirePass reverse-proxy engine may not have been able to rewrite the IP address of the Citrix server in the ICA configuration file. If this is the case, the ICA Web Client may attempt a direct connection to the Citrix server instead of using a FirePass Application Tunnel. Typically, the Citrix server is not reachable directly by the client, and the connection fails.

To determine whether the reverse-proxy engine was able to rewrite the IP address, you can use the Network packet dump utility on the Device Management: Maintenance: Troubleshooting Tools page. Using the Network packet dump utility, you can capture the SSL packets between the FirePass controller and the remote access client when attempting a Citrix session, then decode the SSL packets with the FirePass built-in SSL decoder. You can locate the ICA file in the decoded packets and determine whether the original IP address of the Citrix server is still present, or if it has been rewritten to a loopback IP address.

For more information about performing a packet dump or using the SSL decode function, consult the FirePass online help on the Device Management: Maintenance: Troubleshooting Tools page.

Workaround

You can work around this issue by performing one of the following procedures:

  • Changing the appropriate server or firewall configuration to set or keep the correct Content-Type header value
  • Configuring a content processing script on the FirePass controller to rewrite the Citrix server IP address and insert the Application Tunnel into the configuration file

Changing the appropriate server or firewall configuration to set or keep the correct Content-Type value

The most common reason for rewrite failure is a Content-Type header with a value other than application/x-ica. This rewrite failure may be due to the web server configuration on the Citrix server system failing to set the correct value, or it may be due to an intermediate system like a proxy server or application firewall that changes HTTP headers.

You can resolve the issue by changing the appropriate server or firewall configuration to set or keep the correct value. You may use the FirePass Network packet dump utility described previously to capture the HTTP response with the ICA configuration file received by the FirePass controller from the Citrix server, and the HTTP response the FirePass controller sends to the client.

Configuring a content processing script to rewrite the Citrix server IP address and insert the Application Tunnel into the configuration file

If the IP address of the Citrix server is not rewritten, but the Content-Type is correct, or the Content-Type cannot be set to application/x-ica, you may be able to work around the issue by configuring a content processing script to perform the IP address rewriting that would normally be done automatically. In addition to the IP address rewriting, the content processing script will probably need to insert JavaScript into the HTML source to create an Application Tunnel for the Citrix ICA Web Client, since the condition that prevented rewriting of the Citrix server IP address will likely prevent insertion of the JavaScript for the Application Tunnel.

Content processing scripts are configured on the Portal Access: Web Applications: Content Processing page.

To rewrite the Citrix server IP address and insert the Application Tunnel in the configuration file, create a content processing script with values similar to the ones below, in the respective fields:

  • URL match patterns field:

    http://citrix.server.com/*
  • Content Type field:

    Determine this value from the packet dumps
  • sed processing script field:

    s/Address=192\.168\.0\.10/Address=127\.100\.100\.100/g

    s/<HEAD>/<HEAD><script> var w_name = name\+(Math.random()).toString().substring(2,16); var childWindow = window.open('\/vdesk\/geekster\/connection.php3?rhost0=192.168.0.10\&rport0=1494\&lhost0=127.100.100.100    \&lport0=1494\
    &name=Citrix%20Server', w_name,'name='+w_name+',resizable=0,scrollbars=0,statusbar=0,menubar=0,width=320,height=240', false);<\/script>/

    s/<BODY/<BODY onunload="if(childWindow) childWindow.close();"/

    Important: Sed commands are case sensitive. If the Citrix web portal page uses a different capitalization format for its HTML tags, for example <Head> or <head> instead of <HEAD>, ensure that you modify the example sed scripts above to exactly match the format of the HTML tags on the Citrix web portal page.

    Important: You may use line breaks to separate multiple sed commands, but you cannot use line breaks within a single sed command. If you copy the example command starting with s/<HEAD>/<HEAD> from this Solution, you must remove the line breaks before pasting it into the FirePass Administrative Console.

    Note: For Citrix Metaframe Presentation Server version 3.0 and later, Advanced or Enterprise edition (but not Standard addition), the default port for ICA/CGP sessions is 2598/TCP, which reflects the newer Session Reliability feature. If using a version of Citrix server with Session Reliability on port 2598/TCP, then substitute 2598 in place of 1494 for the lport and rport parameters.
  • Processing:

    Post-processing response data

The first sed command performs the IP address substitution, using a loopback address chosen by the FirePass administrator. For best results, select a loopback address value which is not used by any existing Static Application Tunnel favorites (FirePass version 6.x) or Application Tunnel favorites (FirePass version 5.x).

The second and third commands insert the JavaScript. The JavaScript code opens a new popup window with an AppTunnel object and inserts a body.onunload event handler to close the popup window upon exiting. Note that the rhost parameter is the real IP address of the Citrix server, and lhost is the IP address of the loopback for the Application Tunnel. These values are the same IP addresses used in the first sed command. Post-processing is used so that the JavaScript functions are not rewritten by the reverse-proxy engine.

For multiple Citrix servers, repeat the first and second commands for each Citrix server, using the IP addresses of the additional Citrix servers and different loopback addresses.  Do not repeat the third command for each Citrix server.

Additionally, if you are running FirePass version 6.x, you must add the remote host and port to the Allow List field in the Access Control List section of the  Application Access : App Tunnels : Master Group Settings page. For example, if the rhost parameter is set to 192.168.0.10 and the rport parameter is set to 1494, you would add 192.168.0.10:1494 to the Allow List field. If you do not add the remote host and port to the master group Application Tunnel Allow List, users in that master group will receive a Security Exception error when the Application Tunnel attempts to connect to the remote host.

Note: For additional information about writing content processing scripts, refer to the FirePass Controller Administrator Guide. For an overview of Citrix access through Portal Access, refer to K8644: Overview of Citrix access through Portal Access.
