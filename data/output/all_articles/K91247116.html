K91247116: HTTPS monitor does not send client certificate chain from Server SSL profile

Type
Support Solution
Published
2020-01-03
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.5, 13.1.4, 13.1.3, 13.1.X, 13.1.0, 13.1.1
Source
https://my.f5.com/manage/s/article/K91247116

Description

HTTPS monitor does not send the full chain when configured with either a certificate chain or concatenated certificates in the associated Server SSL profile.

ltm profile server-ssl /Common/https-mon-ssl {
    app-service none
    cert /Common/monitor.crt <--------- Client certificate
    chain /Common/intermediate.crt <--- Chain certificate
    defaults-from /Common/serverssl
    key /Common/monitor.key
}

As a result of this issue, monitors may fail since pool members are unable to establish a chain of trust back to their trusted root CA.

Environment

  • HTTPS Monitor
  • bigd.tmm database variable is disabled

Cause

bigd uses openssl for HTTPS monitoring and this implementation does not support sending multiple client certificates.

Recommended Actions

There are two possible solutions to this issue:

Install all of the necessary signing CA's certificates on the pool member. This allows a chain of trust to be established from the client certificate sent by the BIG-IP. This is generally considered to be an efficient solution as it eliminates the need for the client to send a full certificate chain for each connection.

Alternatively, use In-TMM monitoring, which enables the BIG-IP to send the full client certificate chain configured in the Server SSL profile. See the following article for more information about configuring In-TMM Monitoring:

  • K11323537: Configuring In-TMM monitoring

Note: Full Server SSL profile functionality is not available to HTTPS monitors unless In-TMM monitoring is enabled.
