Description

If a BIG-IP LTM is a server object in two separate DNS sync groups that have the same sync group name, the DNS prober pool monitor result from one DNS sync group will broadcast to another DNS sync group.  If the monitored objects have different status for different sync groups, the monitor logs will look like it is flapping. The logs may also indicate the prober pool configuration is not working as the big3d response comes from a different DNS sync group.

Environment

  • BIG-IP DNS
  • BIG-IP LTM
  • 2 DNS sync groups with the same name

Cause

Prober results between the two DNS Sync group instances, with the same name, will cause inconsistent prober pool status.

Recommended Actions

Modify the name of the second DNS Sync group to be unique (eg. Sync group 1 = "West", Sync group 2 = "East").

Additional Information

The core of this issue is that an LTM attaches the prober pool responses using the sync group name.  If the sync groups have the same name, then incorrect status may be sent to the wrong sync group, causing inconsistent status of the prober pool. 

Note: LTM devices as a server object in a datacenter can be configured in 2 different DNS sync groups as long as the sync group names are unique.
