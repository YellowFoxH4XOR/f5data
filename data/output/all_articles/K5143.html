K5143: Web aggregation is not used when default SNAT automap is enabled

Known Issue

This is most likely the result of a known issue. When you enable a SNAT automap on a BIG-IP that uses virtual servers with delayed binding features, and the SNAT includes VLANs on which the virtual server traffic arrives, BIG-IP will not re-use idle node-side connections. As a result, web aggregation is effectively disabled. Rather than re-using HTTP connections between the BIG-IP and the node, BIG-IP allows existing connections to remain idle, opening new connections instead.

F5 Networks Product Development tracked this issue as CR28533 and CR42119.

Workaround

To work around this issue, you can disable unnecessary VLANs within the SNAT.

For example, if you use a SNAT to allow outbound connections through an internal VLAN, you can disable connections through the external VLAN. If all virtual server traffic arrives on the external VLAN an you disable SNAT automap for the external VLAN, web aggregation will work normally.

To disable VLANs within a SNAT, perform the following steps:

  1. Log in to the command line.
  2. Disable VLANs for the SNAT, using the following command:

    bigpipe snat <address> vlans <vlans> disable

  3. Replace <address> with the SNAT address or with default, if it is a default SNAT. Replace <vlans> with a space-separated list of VLAN names you wish to disable.

    For example:

    bigpipe snat default vlans external DMZ disable

  4. Save the configuration, using the following command:

    bigpipe save
