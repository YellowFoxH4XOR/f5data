Topic

You should consider using this procedure under the following condition:

  • You want to monitor BIG-IP ASM system resources.

Description

In BIG-IP ASM 14.0.0 and later, you can configure the ASM resource health monitor to send alerts when the system has exceeded the configured threshold for a specified alert type. You can configure the system to send alert messages using one or more of the following notification types:

  • Syslog: The system sends notifications to syslog (the System > Logs > Local Traffic page).
  • SNMP: The system sends notifications as SNMP traps.
  • E-Mail: The system sends notifications by email to specific email addresses.

To specify the system statistic alerts, adjust the following alert thresholds as needed.

Alert typeDescriptionThreshold
TMM CPU UtilizationReports the percent CPU usage for TMM processes over all cores.85%
Total CPU UtilizationReports the percent CPU usage for all system processes over all cores.90%
ASM CPU UtilizationReports the percent CPU usage for BD processes over all cores.85%
ASM CPU Utilization per VSReports the percent CPU usage for BD processes per virtual server.35%
TMM Memory UtilizationReports the percent TMM memory usage out of the total memory provisioned for TMM processes.95%
UMU Memory UtilizationReports the percent of UMU memory pool usage out of the total memory provisioned for BD processes, excluding XML traffic memory.90%
XML Memory UtilizationReports the percent XML traffic memory usage out of the total memory provisioned for BD processes.90%
Total Swap Memory UtilizationReports the percent swap memory usage for all processes out of the total swap area.10%
ASM Swap Memory in MBReports the percent swap memory used for BD processes out of the total swap area (in MB).5 MB
Event Message Queue UtilizationReports the percent memory usage for events awaiting BD processing in the message queue, out of the total memory for all queues.90%
Backlog Message Queue UtilizationReports the percent memory usage for messages removed from the message queue and transferred to the backlog queue, out of the total memory for all queues.5%
Bypassed Transaction RateReports the number of HTTP transactions per second (TPS) that bypassed BD processing due to unavailability of the BD.0.1 TPS

Procedures

Configuring ASM resource alerts and thresholds

To configure BIG-IP ASM resource alerts and adjust the resource threshold values, perform the following procedure:

Impact of procedure: Enabling BIG-IP ASM resource monitoring may have a negligible impact on your system. However, F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Reporting > Settings > ASM Alerts.
  3. Under ASM Alerts, select the Enabled check box next to the specific alert.
  4. For Threshold, enter the threshold value.
  5. For Notification Type, select one or more of the notification option check boxes.

    Note: If you select the E-Mail check box, you must select the SMTP configuration from the SMTP Configuration list or click Create to add a new SMTP configuration.

  6. Click Update.

Additional Information

These ASM health alerts fall under one AVR umbrella OID and the message text will vary depending on which alert kicks in.

/usr/share/snmp/mibs/F5-BIGIP-COMMON-MIB.txt:
...
bigipAvrAlertsMetricSnmp  NOTIFICATION-TYPE
        OBJECTS {
                bigipNotifyObjMsg
        }
        STATUS      current
        DESCRIPTION
                "AVR alert metric state changed - notification for SNMP."
        ::= { bigipNotifications 105 }
...

The corresponding SNMP OID for this MIB can be found using snmp-translate and is as follows:

# snmptranslate -On F5-BIGIP-COMMON-MIB::bigipAvrAlertsMetricSnmp
.1.3.6.1.4.1.3375.2.4.0.105
