Description

BIG-IP LTM systems may experience TMM core dumps with errors such as SIGFPE if iRules allow connection-scoped variables to grow without bounds. This issue can occur when variables are not properly initialized, guarded, or cleaned up for each request, especially in environments with persistent connections handling many requests.

Environment

  • Product: BIG-IP LTM
  • iRules using connection-scoped variables

Cause

If an iRule does not properly manage per-request variables, such as failing to reset or unset variables at the start of each request or appending to variables without guards, memory usage can grow unbounded. On long-lived connections, this can lead to memory exhaustion and TMM core dumps.

Answer/Recommended Actions

  • Always initialize or unset per-request variables at the start of each HTTP_REQUEST (or equivalent) event.
  • Use guards (such as flags or existence checks) before appending to or logging variables.
  • Clean up (unset) variables after use, including in CLIENT_CLOSED or error paths.
  • Review iRules for logic that could allow variables to persist and grow across multiple requests on a single connection.
  • Consult F5 Professional Services for a thorough review or redesign of complex iRules.

Additional Information

  • This risk applies to all iRules using connection-scoped variables, not just specific implementations.
  • Proper variable management is essential to prevent memory leaks and TMM core dumps.
  • Long-lived connections with many requests are at higher risk.
