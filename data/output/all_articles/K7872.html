Known Issue

This is the result of a known issue. If you customize the FirePass controller's user interface using WebDAV sandbox customization, and a user connects to the FirePass controller through an SSL-Offloaded web service, FirePass will prompt the user for WebDAV credentials before retrieving files from the sandbox. When a user connects to the FirePass controller through an SSL-enabled web service, FirePass correctly retrieves files from the sandbox without prompting the user for WebDAV credentials. This issue occurs because when you enable WebDAV on the Device Management: Customization page, FirePass enables WebDAV for all non-SSL web services configured under the Web Services tab on the Device Management: Network Configuration page. The correct behavior is for FirePass to enable WebDAV on all non-SSL web services except SSL-Offloaded web services. In an SSL Offload configuration, the SSL processing for a specific web service is offloaded to a BIG-IP LTM.

WebDAV is a set of HTTP protocol extensions that allow administrators to publish HTML content to a web server. FirePass implements WebDAV so that administrators can publish customized web pages for the FirePass controller logon, publish files for performing client-side remediation based on pre-logon sequence checks, and complete other tasks.

F5 Product Development tracked this issue as CR83549, and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

Additionally, cumulative hotfix HF-601-5 has been issued for FirePass version 6.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
