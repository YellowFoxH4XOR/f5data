Known Issue

This is the result of a known issue. The HTTP::cookie decrypt iRule command decrypts the value for the given cookie using a key generated from the pass phrase. If the HTTP::cookie decrypt command fails for any reason, (for example, attempting to decrypt an unexpected cookie format), memory leaks may occur causing system instability.

F5 Product Development tracked this issue as CR106813 and it was fixed in BIG-IP version 9.4.7. For information about upgrading, refer to the BIG-IP LTM release notes.

This issue has been fixed in Hotfix-BIG-IP-9.3.1-HF5, which was issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by using the AES::encrypt and AES::decrypt iRule commands in conjunction with the HTTP::cookie value command to replace the HTTP::cookie encrypt/decrypt commands.

For a sample iRule that demonstrates this technique, refer to the Encrypting Cookies iRules example on the F5 DevCentral website.

Note: A DevCentral user account is required to access the codeshare.
