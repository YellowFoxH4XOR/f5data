Description

When configuring a Virtual Server for the MQTT protocol using the "Message Routing" type on BIG-IP LTM, the option to directly assign a pool or pool member in the Resources section is not available. Additionally, if server-side SSL is not configured and the backend pool members expect encrypted (TLS) traffic, connections may fail because BIG-IP will send unencrypted traffic to the pool members.

Environment

  • BIG-IP Local Traffic Manager (LTM)
  • Message Routing Virtual Server for MQTT protocol

Cause

  • In Message Routing Virtual Servers for MQTT, pools are not mapped directly under the Virtual Server’s Resources tab. Instead, routing is managed through an MQTT Router Profile that references Static Routes and Peer Profiles.
  • If server-side SSL (serverssl) is not enabled in the Transport Config of the Peer Profile and backend servers require TLS-encrypted connections, communication will fail due to protocol mismatch.

Recommended Actions

To configure MQTT Message Routing Virtual Servers correctly and ensure proper pool member mapping and encryption:

  1. Create a Standard LTM Pool

    • Define your desired pool and add all required pool members.

  2. Configure an MQTT Peer Profile

    • Go to: Local Traffic → Profiles → Message Routing → MQTT → Peers
    • Create a new peer profile.
    • Select the previously created LTM pool.

  3. Configure an MQTT Static Route

    • Go to: Local Traffic → Profiles → Message Routing → MQTT → Static Routes
    • Create a new static route referencing the peer profile from step 2.

  4. Create an MQTT Router Profile

    • Go to: Local Traffic → Profiles → Message Routing → MQTT → Router Profiles
    • Create a new router profile referencing the static route from step 3.

  5. Assign Router Profile to Virtual Server

    • When creating or editing your Message Routing Virtual Server for MQTT, select this router profile under Application Protocol settings.

  6. Enable Server-Side SSL if Required

    • Create a transport profile via Local Traffic ›› Profiles : Message Routing : MQTT ›› Transport Config.
    • Select both serverssl and mqttsession from the profile.
    • Click Finished.
    • Go to Local Traffic ›› Profiles : Message Routing : MQTT ›› Peers.
    • Click on required Peer and specify the previously configured Transport config.

  7. Use Appropriate Ports

    • Use IANA-assigned ports:
      • 1883 for standard (unencrypted) MQTT
      • 8883 for secure (TLS-encrypted) MQTT
