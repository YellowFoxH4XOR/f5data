Known Issue

This is the result of a known issue. If a user logs on to the FirePass webtop using Internet Explorer (IE), and then the user logs on and off from a Microsoft Outlook Web Access (OWA) server in another IE browser window or tab, FirePass redirects the user to the session expired page when the user attempts to access a resource or link on the webtop. Additionally, if the user has an active Network Access connection, the FirePass client-side component may terminate the Network Access connection when the user logs off from the OWA server.

Although FirePass redirects the user to the session expired page, the user’s session is still active in FirePass as reported on the Reports: Sessions page in the FirePass Administrative Console.

Important: If numerous users encounter this issue, a potential licensing issue may arise if your FirePass controller frequently reaches its licensed concurrent session limits. The potential licensing impact can be greatly reduced by configuring concurrent session limits and inactivity timeouts. For more information, refer to K8696: Overview of user session management mechanisms. 

F5 Networks Product Development is tracking this issue as CR109903.

Workaround
 
If you are running FirePass version 6.0.2 or later, you can work around this issue by configuring a Portal Access Web Application favorite for access to an OWA server.

Important: The above workaround applies to the current (default) version of the Portal Access reverse-proxy engine. This workaround will not succeed if you enable Compatibility Mode in Portal Access.
 
Additionally, users can work around this issue by performing one of the following two actions:
 
  • Launching a separate instance of IE for access to the OWA server
  • Connecting to the FirePass controller using an alternate browser, such as Firefox
