Description

"ModuleNotLicensed" shows on the command-line of the vCMP guest, but not the host.

Environment

  • vCMP

Cause

Unlicensed module such as AAM was provisioned but NOT licensed.

Recommended Actions

  • Work with F5 Account Manager to license the desired module.
  • De-provision the unlicensed module on the vCMP guest. To do so, perform the following procedure:

    Impact of procedure: F5 recommends that you perform this procedure during a maintenance window. Reprovisioning involves restarting system processes and rebooting. These actions interrupt traffic. Additionally, when the BIG-IP system is in a device group, it fails over to the next available member.

    • Use the Configuration utility
    • Use tmsh

    Use the Configuration utility

    1. Log in to the BIG-IP Configuration utility on the vCMP guest.
    2. Go to System > Resource Provisioning.
    3. Locate any unlicensed modules that are currently provisioned. The license status of the modules are shown in the License Status column.
    4. In the Provisioning column, clear the check box next to the unlicensed module to set the provisioning status to None.
    5. Select Submit.
    6. After you make the necessary provisioning changes, go to System > Configuration > Device.
    7. To restart the system, for Operations, select Reboot.
    8. When prompted, select OK to confirm restart.
    9. If the BIG-IP system is in a device group, repeat the procedure on the other members. Provisioning is not synchronized in a ConfigSync operation.

    Use tmsh

    1. Log in to the BIG-IP Advanced shell on the vCMP guest.
    2. Enter the following command:

      tmsh

    3. Enter the following command to view provisioned modules:

      list /sys provision

      For example, the following partial output shows the Local Traffic Controller (ltm) and Link Controller (lc) modules are provisioned:

      ...
      sys provision lc {
          level nominal
      }
      sys provision ltm {
          level nominal
      }
      ...

      If you are unsure which module is unlicensed, you can view the System > Resource Provisioning page in the Configuration utility, or compare the provisioned modules against the output of the show /sys license detail command.

    4. Use the following syntax to de-provision the unlicensed module where <module_name> is the name of the unlicensed module:

      modify /sys provision <module_name> level none

      For example, to de-provision the Link Controller (lc) module, enter the following command:

      modify /sys provision lc level none

    5. Enter the following command to save the changes:

      save /sys config

    6. Enter the following command to reboot the system:

      reboot

    7. If the BIG-IP system is in a device group, repeat the procedure on the other members. Provisioning is not synchronized in a ConfigSync operation.
