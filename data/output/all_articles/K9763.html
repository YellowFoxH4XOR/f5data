Topic

Starting in BIG-IP 10.0.0, the BIG-IP 6400 and BIG-IP 6800 platforms run in Clustered Multiprocessing (CMP) mode. No additional configuration is required to use CMP. In BIG-IP 10.0.0 and later versions, CMP is enabled globally on these platforms. With this change, all BIG-IP platforms with multiple processor cores now take advantage of CMP.

CMP is an F5 technology that provides near linear performance scaling as additional hardware resources, such as CPU, memory, Secure Socket Layer (SSL), and compression hardware are added to the system. This feature is accomplished by running a separate instance of the Traffic Management Microkernel (TMM) process on each processor core. The TMM processes are responsible for processing all load balanced traffic managed by the BIG-IP system. Each TMM process is automatically allocated an even share of the available processing and communication resources, such as CPU, memory, network interfaces, and offload hardware. Most system configuration, monitoring, and maintenance tasks are identical to those for non-CMP systems, resulting in a small administrative learning curve. All TMM instances reference the same configuration, and an instance of each configuration object exists in each TMM. Although connections to the same virtual server may be processed on different TMM instances, the distribution and management of connections are completely transparent to the BIG-IP administrator and the end user.

Performance Improvements

Almost all configurations on the BIG-IP 6400 and BIG-IP 6800 platforms see a measurable increase in performance by using CMP, most notably in the area of CPU processing capacity. Previously, one processor core was dedicated to processing load balanced traffic, while the other remained mostly idle, utilized only for management and monitoring processes, and for compression offload if the BIG-IP system was licensed for hardware accelerated compression. Using CMP, both processor cores are utilized for both management and load balancing tasks, and all tasks are dynamically distributed across TMM instances based on available resources. Up to 90 percent of each processor core may be dynamically allocated to load balancing tasks, as compared to 100 percent of one core previously, resulting in an 80 percent increase in the CPU capacity available for traffic management. The total system capacity is increased for all tasks, and the system is more flexible and scalable, capable of handling most processing spikes without administrative intervention.

Specific performance changes observed using CMP on the BIG-IP 6400 and BIG-IP 6800 platforms include the following:

Configuration load times

  • GUI and configuration load times remain largely unchanged
  • For configurations of 2000 to 6000 pools, load times decrease 42 to 56 percent 
  • For configurations with 4,000 or more nodes, load times increase 25 to 40 percent 

Compression

  • For highly-compressible content (more than 90 percent compressible) in any size response, performance increases 27 to 72 percent 
  • For moderately compressible content (60 to 70 percent compressible) in response sizes of 8KB or smaller, performance increases 13 to 72 percent 
  • For moderately compressible content (60 to 70 percent compressible) in response sizes of 64KB to 512KB, performance decreases 7 to 18 percent 

FastL4, FastHTTP, and Standard virtual servers using the HTTP, OneConnect, and RAM Cache profiles

  • For responses that are 8KB and smaller, performance increases 14 to 78 percent 
  • For larger responses, performance increases modestly

SSL

  • For all response sizes, common ciphers, and session ID reuse with or without OneConnect, performance increases 13 to 63 percent 
  • For re-encryption of responses 64KB and larger, performance increases 19 to 23 percent 
  • For re-encryption of responses smaller than 64KB, performance increases modestly

Note: Several factors affect how the performance results detailed above may compare to your BIG-IP system's performance using CMP. Since BIG-IP 9.4.6 (non-CMP) is compared against version 10.0.0 (CMP), and BIG-IP 10.0.0 introduced new features and optimizations that improve configuration scalability and administrative performance, it is difficult to calculate the impact of CMP alone. Furthermore, each BIG-IP platform has a unique combination of hardware. As a result, optimizations for one platform may not have the same impact on other platforms.
