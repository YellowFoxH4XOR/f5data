K000138596: Troubleshooting LDAP/LDAPS authentication for F5OS-C/A administrative users

Issue

You should consider using this procedure under the following conditions:

  • Your F5OS-C/A system is configured to use the Lightweight Directory Access Protocol (LDAP) or LDAP over SSL (LDAPS) protocol for authenticating F5OS-C/A remote administrative users.
  • Administrative user accounts defined on the remote LDAP server are unable to log in to the F5OS-C/A system.

    Note: If the remote user accounts are unable to log in to the F5OS-C/A system, the locally defined user accounts, such as the default admin account and the root command line account, are able to log in to the system.

Symptoms

As a result of LDAP authentication failures, you may encounter the following symptoms:

  • The F5OS-C/A remote administrative users are unable to login to the system.
  • The F5OS-C/A system logs error messages related to LDAP login failures for remote LDAP administrative users.

Recommended Actions

LDAP is a protocol based on the X.500 standard and is used for accessing and maintaining distributed directory information over a network.For more information about the LDAP protocol, refer to Internet Engineering Task Force (RFC 4511).

In the context of LDAP authentication for F5OS-C/A remote administrative users, the following flow describes a typical LDAP authentication:

  1. The remote administrative user attempts to log in to the F5OS-C/A system using his/her LDAP username and password.
  2. The F5OS-C/A system establishes a TCP connection with the remote LDAP server over port 389. If LDAPS is configured, the F5OS-C/A establishes a TCP connection with the remote LDAP server over port 636.
  3. The F5OS-C/A system attempts to bind to the remote LDAP server using the LDAP binding user account name and password.
  4. If the LDAP binding is unsuccessful, the F5OS-C/A system fails the LDAP authentication. If the LDAP binding is successful, the F5OS-C/A system sends an LDAP search query for the LDAP account from step 1 to the remote LDAP server.
  5. The remote LDAP server then responds back with the results. If there is 0 result or an error ensues, the F5OS-C/A system fails the LDAP authentication. If the result returns a valid account, the F5OS-C/A system performs another LDAP binding to the remote LDAP server using the LDAP account from step 1.
  6. The remote LDAP server responds back with the results again. Similarly, if there is 0 result or an error ensues, the F5OS-C/A system fails the LDAP authentication. If the LDAP binding is successful, the F5OS-C/A system proceeds to assign the configured user role based on the group ID (gidNumber) returned for the LDAP account. If no group ID (gidNumber) is found or does not match any of the configured user role on the F5OS-C/A system, the user will not be allowed access to the F5OS-C/A system.

Procedures

When experiencing LDAP authentication issues, you can use the following troubleshooting steps to assist in determining the root cause:

  • Verifying the remote LDAP configuration on the F5OS-C/A system
  • Verifying the remote LDAP server availability
  • Enabling debug logging for LDAP authentication
  • Reviewing LDAP authentication logs

Verifying the remote LDAP configuration on the F5OS-C/A system

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the F5OS-C chassis/F5OS-C partition/F5OS-A system as the F5OS-C chassis admin/F5OS-C partition admin/F5OS-A admin respectively.
  2. Verify the LDAP server group configuration settings by entering the following command syntax:

    show running-config system aaa server-groups server-group <server group name>

    The command should return an output similar to the following example:

    system aaa server-groups server-group adservergroup
     config name adservergroup
     config type LDAP
     servers server DC01.example.myf5.lab
      config address DC01.example.myf5.lab
      ldap config auth-port 636
      ldap config type ldaps
     !
    !

    Note the example output indicates that the F5OS-C/A system is configured to establish LDAPS connections to host DC01.example.myf5.lab on port 636.

  3. Confirm that the output from the previous step match the remote LDAP server Fully Qualified Domain Name (FQDN)/IP address and listening port.
  4. Verify the LDAP authentication settings by entering the following command:

    show running-config system aaa authentication ldap

    The command should return an output similar to the following example:

    system aaa authentication ldap binddn adldapbinduser
    system aaa authentication ldap bindpw <LDAP binding user account password hash>
    system aaa authentication ldap base [ dc=example,dc=myf5,dc=lab ]
    system aaa authentication ldap bind_timelimit 10
    system aaa authentication ldap timelimit 0
    system aaa authentication ldap idle_timelimit 0
    system aaa authentication ldap ldap_version 3
    system aaa authentication ldap ssl on
    system aaa authentication ldap active_directory true
    system aaa authentication ldap tls_reqcert demand
    system aaa authentication ldap tls_cacert "-----BEGIN CERTIFICATE-----\nMIIDgTCCAmmgAwIBAgIQPO5XpwyXLYVGugCVGV5Y9jANBgkqhkiG9w0BAQsFADBT\n<truncated for brevity>\no+imHv/K991ccyDCfHl/0epPmJVtv3kkw7GkXl2hA5VoBv3LVA==\n-----END CERTIFICATE-----"
    system aaa authentication ldap chase-referrals true

    Note the example output indicates that the F5OS-C/A system is configured to perform the following:

    • establish a LDAP over SSL connection to the remote LDAP server (ssl on), request the LDAP server certificate; if no or bad SSL cert is provided by the remote LDAP server, terminate the LDAP session immediately (tls_reqcert demand), and uses the SSL cert (tls_cacert) to perform peer authentication with the remote LDAP server.
    • For the different time limit settings, set the connection setup time out at 0 seconds (timelimit 0), wait 10 seconds for a response from the remote LDAP server (bind_timelimit 10), and not time out inactive connection(s) to the LDAP server (idle_timelimit 0). Note that these values are default for each of the time limit settings.
    • LDAP bind to the remote LDAP server as adldapbinduser (binddn) with its hashed password (bindpw) using LDAP protocol version 3 (ldap_version 3).
    • use the base distinguished name (DN) dc=example,dc=myf5,dc=lab (base) as the search base and Micosoft Active Directory specific filters as well as maps (active_directory true) for the LDAP search.
    • chase a LDAP URI referral to a different LDAP server from the original remote LDAP server (chase-referrals true).

    Note: For the description of these LDAP authentication settings and their respective values, refer to K000138401: Configuring F5OS-C/A devices for LDAP over SSL remote authentication with Active Directory.

  5. Confirm that the output from the previous step match the configured settings on the remote LDAP server.
  6. Verify that LDAP has been included as one of the authentication methods by entering the following command:

    show running-config system aaa authentication config authentication-method

    The command should return an output similar to the following example:

    system aaa authentication config authentication-method [ LOCAL LDAP_ALL ]

    If the output includes the LDAP_ALL value, then LDAP is included as one of the authentication methods.

Verifying the remote LDAP server availability

If you have configured the address of the LDAP server group using the FQDN of the remote LDAP server like the example in step 2 of the previous procedure, you should ensure that the DNS server your F5OS-C/A system is configured to use for DNS resolution is capable of resolving the FQDN of the remote LDAP server to a valid IP address in your network and the IP address is reachable from the management IP address of your F5OS-C/A system. To verify the remote LDAP server availability, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the F5OS-C chassis or the F5OS-A system as the root user.
  2. Use a utility, such as ping, to verify network availability of the remote LDAP server.

    ping <remote LDAP server FQDN or IP address>

    For example,

    ping DC01.example.myf5.lab

  3. If the remote LDAP server responds to the ICMP requests, you can verify if the remote LDAP server is listening on the expected LDAP port (by default, port 389 or port 636 for LDAP over SSL) using a utility such as nc.

    nc <remote LDAP server FQDN or IP address> <listening port> -v -z

    For example,

    nc DC01.example.myf5.lab 636 -v -z

  4. If the remote LDAP server supports LDAP over SSL and listens on port 636, you can verify if the SSL connection can be established and the SSL cert presented by the remote LDAP server is valid using the openssl utility.

    openssl s_client -connect <remote LDAP server FQDN or IP address>:<listening port> -showcerts </dev/null 2>/dev/null | openssl x509 -noout -text

    For example,

    openssl s_client -connect DC01.example.myf5.lab:636 -showcerts </dev/null 2>/dev/null | openssl x509 -noout -text

  5. To verify if the LDAP service is working properly on the remote LDAP server, you can use the ldapsearch utility from the name-service-ldap (F5OS-C chassis and F5OS-A system) or partition<ID>_name-service-ldap (F5OS-C partition) container where <ID> is the F5OS-C partition number.

    docker exec -it [-e LDAPTLS_REQCERT=never] < name-service-ldap | partitionID_name-service-ldap > ldapsearch -LL -H "< ldaps | ldap >://<remote LDAP server FQDN or IP address>" -b <base DN> -W -x -D '<bind DN>' [<LDAP search query parameters>]

    For example,

    From the F5OS-A system CLI, you want to verify if the LDAP service is working properly on DC01.example.myf5.lab on port 389 with base DN dc=example,dc=myf5,dc=lab using the service account adldapbinduser@example.myf5.lab to bind to the remote LDAP server:

    docker exec -it name-service-ldap ldapsearch -LL -H "ldap://DC01.example.myf5.lab" -b dc=example,dc=myf5,dc=lab -W -x -D 'adldapbinduser@example.myf5.lab'

    From the F5OS-C chassis CLI, you want to verify if the LDAP service is working properly on DC01.example.myf5.lab on port 636 (without requesting for SSL cert from the remote LDAP server) with base DN dc=example,dc=myf5,dc=lab using the service account adldapbinduser@example.myf5.lab to bind to the remote LDAP server:

    docker exec -it -e LDAPTLS_REQCERT=never name-service-ldap ldapsearch -LL -H "ldaps://DC01.example.myf5.lab" -b dc=example,dc=myf5,dc=lab -W -x -D 'adldapbinduser@example.myf5.lab'

    From the F5OS-C chassis CLI, you want to verify if the LDAP service is working properly on DC01.example.myf5.lab on port 636 (without requesting for SSL cert from the remote LDAP server) with base DN dc=example,dc=myf5,dc=lab using the service account adldapbinduser@example.myf5.lab to bind to the remote LDAP server and search for an AD user account f5osadmin from the partition1's name-service-ldap container:

    docker exec -it -e LDAPTLS_REQCERT=never partition1_name-service-ldap ldapsearch -LL -H "ldaps://DC01.example.myf5.lab" -b dc=example,dc=myf5,dc=lab -W -x -D 'adldapbinduser@example.myf5.lab' 'samaccountname=f5osadmin'

Enabling debug logging for LDAP authentication

You can enable debug logging for LDAP authentication, attempt to log in using remote LDAP user accounts, and then review the debug log files. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and affect system performance.

  1. Log in to the CLI of the F5OS-C chassis or the F5OS-A system as the root user.
  2. Enable debug logging for LDAP authentication by entering the following command:

    F5OS-C chassis / F5OS-A system

    docker exec -it name-service-ldap /bin/bash -c "echo -d > /var/run/authd/nslcd_debug"

    F5OS-C partition

    docker exec -it partition<ID>_name-service-ldap /bin/bash -c "echo -d > /var/run/authd/nslcd_debug"

    Note: The verbosity of the debug logging is controlled by the number of d in the command. For maximum verbosity, you would replace the -d with -ddd. Using the F5OS-A system example, you would enter docker exec -it name-service-ldap /bin/bash -c "echo -ddd > /var/run/authd/nslcd_debug".

  3. Test LDAP authentication by attempting to log in using remote LDAP user accounts.
  4. After testing LDAP authentication, disable debug logging by entering the following command:

    F5OS-C chassis / F5OS-A system

    docker exec -it name-service-ldap /bin/bash -c "rm -rf /var/run/authd/nslcd_debug"

    F5OS-C partition

    docker exec -it partition<ID>_name-service-ldap /bin/bash -c "rm -rf /var/run/authd/nslcd_debug"

  5. Refer to the next procedure for instructions on how to review the debug log messages from the container.

Reviewing LDAP authentication logs

To review the log messages related to LDAP authentication, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the F5OS-C chassis or the F5OS-A system as the root user.
  2. Display the log messages related to LDAP authentication by entering the following command:

    F5OS-C chassis / F5OS-A system

    docker logs --timestamps name-service-ldap

    F5OS-C partition

    docker logs --timestamps partition<ID>_name-service-ldap

  3. Review the log entries for error messages related to LDAP login failures. You may want to refer the following examples:
    • Error trying to bind (to the LDAP server)

      The Bind DN / Password values specify the distinguished name and password used for binding to the LDAP server; these values usually represent the administrative username and password for the LDAP database. When binding to the LDAP server fails due to a bad username or password, the system logs error messages similar to the following example:

      nslcd: [8b4567] <passwd="f5osadmin"> failed to bind to LDAP server ldaps://DC01.example.myf5.lab:636: Invalid credentials: 80090308: LdapErr: DSID-0C090434, comment: AcceptSecurityContext error, data 52e, v4f7c
      nslcd: [8b4567] <passwd="f5osadmin"> no available LDAP server found: Invalid credentials: Bad file descriptor

    • Error trying to bind as user

      When an F5OS-C/A administrative user attempts to log in using a bad username or password, the system logs messages similar to the following example:

      Incorrect password

      nslcd: [334873] <authc="f5osadmin"> DEBUG: failed to bind to LDAP server ldaps://DC01.example.myf5.lab:636: Invalid credentials: 80090308: LdapErr: DSID-0C090434, comment: AcceptSecurityContext error, data 52e, v4f7c
      nslcd: [334873] <authc="f5osadmin"> CN=f5osadmin,CN=Users,DC=example,DC=myf5,DC=lab: lookup failed: Invalid credentials

      Incorrect username

      nslcd: [5f007c] <authc="f5osadmin1"> DEBUG: "f5osadmin1": user not found: No such object

      Note: Bad username does not include case sensitive username. At the point of publishing, the F5OS-C/A system supports case sensitive LDAP username; case insensitive LDAP username is not supported. For example, if the LDAP username is f5osadmin, then the accepted username during log in is f5osadmin and not f5osAdmin. Similarly if the LDAP username is f5osAdmin, then the accepted username during log in must be f5osAdmin and not f5osadmin.

    • The LDAP server fails to respond or refuses the connection

      When the specified service port or IP address for the LDAP server is incorrect, or the LDAP server is configured to allow requests from only a certain address range, the system logs error messages similar to the following example:

      nslcd: [7b23c6] <passwd="f5osadmin"> failed to bind to LDAP server ldaps://DC01.example.myf5.lab:637: Can't contact LDAP server: Transport endpoint is not connected
      nslcd: [3c9869] <passwd="f5osadmin"> no available LDAP server found: Server is unavailable: Transport endpoint is not connected

    • TLS/SSL handshake failure for LDAP over SSL

      When the F5OS-C/A system is configured to use SSL to communicate with the LDAP server and the handshake fails, the system logs error messages similar to the following example:

      nslcd: [8b4567] <passwd="f5osadmin"> failed to bind to LDAP server ldaps://DC01.example.myf5.lab:636: Can't contact LDAP server: error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed (unable to get local issuer certificate)

    • LDAP referral failure

      When the F5OS-C/A system is configured with LDAP chase-referrals true but the referred LDAP system is unreachable/unavailable, the system logs error messages similar to the following example:

      nslcd: [8e1f29] <authc="f5osadmin"> ldap_result() failed: Referral: 0000202B: RefErr: DSID-0310079D, data 0, 1 access points
          ref 1: 'example.myf5.lab'
      : Transport endpoint is not connected
      nslcd: [8e1f29] <authc="f5osadmin"> DEBUG: "f5osadmin": user not found: Referral
