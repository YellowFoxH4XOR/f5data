K32720572: BIG-IP DNS HTTP and HTTPS monitors now support customized response HTTP status codes

Type
Support Solution
Published
2020-11-05
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP DNS: 16.X.X, 16.1.X, 15.1.0, 15.1.1, 15.1.2, 15.1.3, 15.1.4, 15.1.5, 15.1.6, 15.1.7, 15.1.8, 16.0.0, 16.0.1, 16.1.0, 16.1.1, 16.1.2, 16.1.3, 15.1.X, 16.0.X
Source

Description
Starting in version 15.1.0, the BIG-IP DNS HTTP and HTTPS monitors support the ability to configure a customized list of HTTP status codes required in server responses. One or more status codes (including 200) can be added and then one of the matching codes must be present in the server response for the monitor to declare it up or subsequently check for a Receive String match (if configured).

Environment

  • BIG-IP DNS 15.1.0 or later
  • GSLB HTTP and/or HTTPS monitors configured

Cause
This was a functionality enhancement included in 15.1.0. By default this additional behavior isn't active and all HTTP/HTTPS monitors accept any status code (if HTTP 0.9 is used) or only 200 OK (if HTTP 1.0/1.1 is used).

Recommended Actions

Configuration Utility
The HTTP and HTTPS monitor configuration now has an additional section called Status Code List. This list defaults to empty.

TMSH
The additional attribute "recv-status-code" has been added and does not show up by default. Status codes are added as arguments to the attribute, surrounded by quotes and space-delimited.

Example syntax to add three status codes to the allowed list of monitor called "custom-http":
tmsh modify gtm monitor http custom-http recv-status-code "200 201 305"

The configuration would then look similar to:
gtm monitor http custom-http {
    defaults-from http
    interval 30
    probe-timeout 5
    recv none
    recv-status-code "200 201 305"
    send "GET /"
    timeout 120
}
