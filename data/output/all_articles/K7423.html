Known Issue

This is the result of a known issue. BIG-IP LTM systems using a long network failover timeout can inadvertently go into a standby state when the peer system is down. For example, if your failover timeout is set to 20 seconds or more, and system 2 is the active unit and system 1 is halted, system 2 changes from an active state to a standby state, then back to an active state.

F5 Product Development tracked this issue as CR76187 and CR76191 and it is fixed in BIG-IP LTM 9.1.3, 9.3, and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.
