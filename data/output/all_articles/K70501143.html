K70501143: Configure systemd-journald log suppression

Type
Support Solution
Published
2022-01-24
Updated
2025-12-04
Source
https://my.f5.com/manage/s/article/K70501143

Description

  • I notice that important log messages appear to be missing
  • I see logs indicating log suppression such as:
Dec 30 12:25:52 bigip.local info systemd-journal[3308]: Suppressed 6281 messages from /system.slice/runit.service
Dec 30 12:25:52 bigip.local info systemd-journal[3308]: Suppressed 13402 messages from /system.slice/runit.service
Dec 30 12:26:22 bigip.local info systemd-journal[3308]: Suppressed 13374 messages from /system.slice/runit.service
Dec 30 12:26:22 bigip.local info systemd-journal[3308]: Suppressed 6261 messages from /system.slice/runit.service

Environment

  • BIG-IP
  • High logging rate such as when debugging enabled.

Cause

The systemd-journald process suppresses writing of logs when the rate exceeds a burst threshold (default 1000 in 30s). 

Recommended Actions

To expand the suppressed log messages, you can perform the following procedure:

Impact of procedure: By expanding the suppressed messages, the log file will grow larger and use more hard disk space. Ensure your system has sufficient disk space allocated before performing this procedure.
  1. Edit /etc/systemd/journald.conf
  2. Uncomment the RateLimitBurst line and set to a higher value i.e. RateLimitBurst=100000, or RateLimitBurst=0, no limitation.
  3. Uncomment the RateLimitInterval line and set to 0, RateLimitInterval=0.
  4. Save changes
  5. Restart systemd-journald using the command below:
systemctl restart systemd-journald


Note: To avoid overwhelming the system at first, it is possible to run "journalctl -u runit" to list the messages emitted by the runit service. We can with high probability assume that the suppressed ones are similar. If the messages don't concur with the overall symptoms and analysis, we should proceed to expanding the messages as per procedure above.


Additional Information

Note: Disabling log suppression may cause higher CPU usage which can effect other processes. Refer to High CPU usage with systemd-journal 219 on CentOS
