Known Issue

This is the result of a known issue. The event daemon uses iControl messaging to provide asynchronous event notification to subscribers, such as Enterprise Manager systems. The eventd process establishes a queue of subscriber events in system memory, and transmits the entire event list to subscribers in a single notification message. If the event queue is large, the system generates large SOAP documents and causes the eventd process to consume excessive amounts of memory. In some cases the increased memory pressure leads to switchboard failsafe.

F5 Product Development tracked this issue as CR86950 and it was fixed in BIG-IP LTM 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
