Known Issue

Migrating or upgrading from a BIG-IP PSM to a BIG-IP ASM system may result in degraded performance if traffic triggers any attack signatures that are enabled in the BIG-IP ASM system.

This behavior is expected as the BIG-IP PSM system does not contain attack signatures that are found on the BIG-IP ASM system. Therefore, if you migrate or upgrade from BIG-IP PSM to BIG-IP ASM, you may experience degraded performance if incoming traffic triggers the attack signatures, especially if the administrator is not aware that the attack signatures are enabled by default on BIG-IP ASM.

The degraded performance is a result of the BIG-IP ASM system learning, logging, and buffering the traffic for inspection of any violations triggered by the attack signatures.

Note: Attack Signatures are activated in staging and will not block any traffic.

This behavior typically does not occur when the BIG-IP ASM system is in a production environment, as most of the initial checking and configuration of a security policy for a website occurs when the BIG-IP ASM system is in a pre-production environment. Once the BIG-IP ASM system has been configured and a security policy established, the system is moved into a production environment where it will allow or deny traffic based on its security policy.

F5 recommends that you move the BIG-IP PSM system from the production environment into a staging environment before migrating or upgrading to a full BIG-IP ASM system and perform the staging guideline outlined in the Configuration Guide for BIG-IP Application Security Management. This will allow proper configuration of the new BIG-IP ASM system and prevent network performance degradation.
