Description

<p style="margin: 8px 0;">Continuous SNMP trap-spammer alarms were generated for the OID <code style="font-family: monospace; padding: 1px 3px;">1.3.6.1.4.1.3375.2.4.0.34</code> because the active BIG-IP LTM system was logging a very high number of <code style="font-family: monospace; padding: 1px 3px;">RST sent from ... No local listener</code> events. The alarm stopped after RST-cause logging was disabled.


 

Environment

• BIG-IP LTM version 17.5.1.

• Affected system was an active vCMP guest.

• The BIG-IP system had tm.rstcause.log enabled.

• The system reported 253,273,626 No local listener TCP reset causes.


 

Cause

The continuous OID alarm itself was caused by the enabled tm.rstcause.log database setting, which logged the high volume of reset events and triggered the corresponding SNMP trap.


 

Answer/Recommended Actions

• Disable RST-cause logging on the affected BIG-IP system:

``bash

tmsh modify sys db tm.rstcause.log value disable

tmsh save sys config

`

• Keep tm.rstcause.pkt enabled if RST-cause information is required for future packet-capture troubleshooting.

• Verify the configuration with:

`bash

tmsh list sys db tm.rstcause.log

`

The expected value is disable.

• Monitor /var/log/ltm and the monitoring platform to confirm that No local listener` messages and the associated OID traps remain absent.

• If investigation of the underlying resets is required, perform a packet capture while the resets are occurring to identify the originating traffic and affected virtual servers or listeners.
