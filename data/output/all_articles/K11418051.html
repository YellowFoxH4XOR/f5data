Known Issue

B4450N VIPRION blades fail to go active under rare conditions. Over extended periods of booting and rebooting, a switch port in the blade connected to the High-Speed Bridge (HSB) may fail to initialize properly.

This issue occurs when the following condition is met:

  • After approximately 8 to 12 hours of continuous rebooting.

Note: Not all conditions that cause the issue are known.

Impact

The B4450N blade may be unable to go active and join the cluster, preventing it from processing traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The affected blade does not pass traffic. In a multi-blade system, the issue appears intermittent because other blades pass traffic.
  • The HSB receives frame check sequence errors at a high frequency and does not receive valid traffic from the port switch.
  • The BIG-IP system logs messages to the /var/log/ltm file that appear similar to the following example:

    warning tmm[18190]: 01010031:4: Device warning: hsb hgm_fcs_errs[0] exceeds 1000

Workaround

To work around this issue, you can reboot the affected VIPRION blade once. To do so, perform one of the following procedures:

  • Rebooting the VIPRION blade using the Configuration utility
  • Rebooting the VIPRION blade using tmsh

Rebooting the VIPRION blade using the Configuration utility

Rebooting the VIPRION blade will reboot a single blade and all Virtual Clustered Multiprocessing (vCMP) guest instances provisioned on that blade. If you are logged in to the Configuration utility using the cluster IP address, the system reboots the primary blade. If you are logged in to the Configuration utility using a cluster member IP address, the system reboots the blade that you are logged in to.

Impact of procedure: Performing the following procedure should not have a negative impact for multiple blade VIPRION systems. It will halt traffic processing for a single blade VIPRION system or vCMP guest that is provisioned on the rebooted blade. If you are unsure about the current number of VIPRION blades or vCMP guest slots, you should perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility of the affected blade using the cluster member IP address.
  2. Navigate to System > Configuration > Device > General.
  3. In the Operations section, click Reboot Blade.
  4. The BIG-IP system prompts with the following message:

    Are you sure you want to reboot this blade?

  5. To begin the blade reboot, click OK.
  6. To verify the blade's cluster status log in to the Configuration utility of the primary blade and navigate to System > Clusters > Properties.

Rebooting the VIPRION blade using tmsh

Rebooting the VIPRION blade will reboot only a single blade and all vCMP guest instances provisioned on that blade.

Impact of procedure: Performing the following procedure should not have a negative impact for multiple blade VIPRION systems. It will halt traffic processing for a single blade VIPRION system or vCMP guest that is provisioned on the rebooted blade. If you are unsure about the current number of VIPRION blades or vCMP guest slots, you should perform this procedure during a scheduled maintenance period.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To reboot the affected blade, use the following command syntax:

    reboot slot <slot number>

    For example, to reboot the VIPRION slot number 1, type the following command:

    reboot slot 1

  3. To verify the blade's cluster status, type the following command:

    show sys cluster
