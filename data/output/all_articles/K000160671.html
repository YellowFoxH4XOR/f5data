Description

You need to understand how encrypted XML payloads are processed by BIG-IP ASM's Web Services Security (WSS) engine. If the decryption process uses symmetric or asymmetric encryption, and clarifying the sequence of encryption and decryption operations at the application layer for XML data protected according to the W3C XML Encryption specification. 

Environment

  • BIG-IP ASM/advanced WAF
  • TLS termination performed on BIG-IP LTM (using Client SSL profiles)
  • Encrypted XML payloads are processed by BIG-IP ASM's Web Services Security (WSS) engine
  • Server certificate and private key in PEM format installed on BIG-IP ASM

Cause

None

Answer/Recommended Actions

  • After TLS is terminated on BIG-IP LTM, the decrypted HTTP payload may still contain XML-encrypted content.
  • BIG-IP ASM uses a hybrid approach for XML decryption, as defined by the W3C XML Encryption specification:
    1. The client encrypts the XML payload using a randomly generated symmetric session key.
    2. The session key is then encrypted with the server's public key and included in the XML payload.
    3. During decryption, BIG-IP ASM uses the server's private key to decrypt the session key (asymmetric decryption).
    4. The decrypted session key is then used to decrypt the XML payload (symmetric decryption).
  • This process is separate from TLS encryption and occurs at the application layer after TLS termination.
  • Ensure the server's private key and certificate are correctly installed on BIG-IP ASM for successful XML decryption.

Additional Information

The hybrid encryption model (asymmetric for session key, symmetric for payload) is standard for XML encryption and is distinct from the TLS encryption used for HTTP transport.
