K6995: Configuring a router to be monitored as a node with snmp_dca on a BIG-IP/3DNS combo unit causes the router entry in the 3-DNS to be marked down

Note: This information only applies to BIG-IP and 3-DNS combination units, where the 3-DNS unit is configured with routers and the BIG-IP system has a corresponding node entry for the same routers, but is using snmp_dca as the only monitor. The following information does not affect non-combination systems.

If a router entry is defined on the 3-DNS side of a BIG-IP and 3-DNS combination unit, and the corresponding router IP address is also configured on the BIG-IP side as a node being monitored by the snmp_dca monitor, the big3d utility will incorrectly report the router entry and link on the 3-DNS side as DOWN.

This behavior occurs because of the way the big3d daemon handles gateway probing. The big3d utility does not correctly probe the router entry because of a conflict with the address being associated with the snmp_dca monitor as a node object.

The big3d daemon will first check to see if there is a node that corresponds with the IP address of the gateway (the router). If there is a corresponding node, the big3d daemon will use the status of that node, which is retrieved through the bigapi process. If there is no corresponding node, the big3d utility will create an icmp path pinger to check the status of the router with the path probe.

Since the snmp_dca monitor's only purpose is to gather performance statistics and does not check or report whether or not the node that the snmp_dca monitor is checking is up or down, the big3d daemon does not retrieve an up or down status through the bigapi process for this node.

In order for 3-DNS to correctly probe the router, a dummy pool with the router IP address must be created on the BIG-IP side of the combo and an ICMP monitor assigned to the IP address. The other alternative is to remove the snmp_dca monitor from the router, if the snmp_dca monitor is the only monitor associated with the IP address.
