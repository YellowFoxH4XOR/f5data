Description

In some upgrade's cases you might get the following errors, which will indicate an inconsistency postgres DB during nginx controller upgrade.

Waiting for statefulset spec update to be observed...

error: timed out waiting for the condition

 The embedded database did not start successfully.

 Detailed information can be found in the installation logs at /var/log/nginx-controller/failure.

 Retry the NGINX Controller update or contact NGINX Support for assistance. You may be asked to provide the logs.

 The NGINX Controller update failed. Restoring the previous NGINX Controller version...

 Error. Failed to restore the config database. See the logs at /opt/nginx-controller/postgres_data/backup for details or contact NGINX Support for assistance.

 

Environment

  • Nginx-controller
  • Nginx Plus
  • Recommended upgrade 

Cause

  • Inconsistence in postgres DB.

Recommended Actions

In case of inconsistence in the postgres DB, we recommend reinstall Nginx Controller from the scratch. 

  1. Before any activity save a copy of backup files for Nginx controller DB - here is where the backup files are saved: 
    /opt/nginx-controller/cluster-backup/cluster-config-backup-<data>.tgz
/opt/nginx-controller/postgres_data/backup_<timestamp>UTC.tar
  2. Uninstalled current Nginx Controller version with deleting DB  - > "yes delete database" and next "yes delete"
/opt/nginx-controller/uninstall.sh
uninstall process will ask for deleting database:
Do you want to  delete all the DATA stored in internal databases?
To continue, type "yes delete database" below
You can also type keep to preserve database data.
Response (or "keep" or [q/Q] to quit): yes delete database
next
To continue, type "yes delete" below
Response (or [q/Q] to quit): yes delete
  1. Install again current Nginx controller version according the procedure with the backup files you saved in first step.
  2. Restore the cluster keys from file cluster-config-backup-<data>.tgz according the procedure
/opt/nginx-controller/helper.sh cluster-config load <cluster-config-backup-<data>.tgz>
  1. Restore the postgres backup from file backup_<timestamp>UTC.tar according the procedure
/opt/nginx-controller/helper.sh backup restore <backup_<timestamp>UTC.tar>
  1. In case Nginx Plus instances are offline from GUI, we will need to get the curl command from the GUI,as it shown below:
Example from the Nginx Controller GUI navigate to Infrastructure :
This is the output from GUI:
curl -sS -L https://<nginx plus></install/controller-agent> install.sh && API_KEY='xxxxxxx' sh ./install.sh
Important: Make sure to get the compatible version between the Nginx Plus instances and the Nginx Controller version
