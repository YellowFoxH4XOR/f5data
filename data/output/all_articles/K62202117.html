Topic

An opaque access token in OAuth is a credential used to access protected resources issued by the Authorization Server to a client. In BIG-IP APM, the access token limit per user, configured in an OAuth profile and associated to an access policy, is 5000. When this limit is exceeded, you may observe error messages in the /var/log/apm file similar to the following examples:

Authorization server logs

01990004:3: /Common/exampleOAuthProfile:Common: Request Access Token from Source ID exampleSourceID IP 10.200.1.5 failed. Error Code (access_denied) Error Description (This user has reached configured access token limit.)

Client/Resource server logs

01490007:6: /Common/Oauth-exampleAccessProfile:Common:82089471: Session variable 'session.oauth.client./Common/exampleClientResourceServer.errMsg' set to 'HTTP error 400, Error: access_denied: This user has reached configured access token limit.'

Note: User in this limit is defined as the user ID. The user ID is set based on the logon username of the BIG-IP APM session. You can display the user ID in two ways: using the Configuration utility or the TMOS Shell (tmsh). For more information, refer to Displaying access token detailed information procedure in this article.

Description

When administering opaque access tokens in your authorization server, you can use the following procedures to view and manage the access tokens:

  • Configuring the Access Token Limit Per User value
  • Displaying access token detailed information
  • Revoking an access token

Configuring the Access Token Limit Per User value

To configure the access token limit per user value, perform the following procedure:

Impact of procedure: This procedure limits the number of access tokens your authorization server issues. F5 recommends performing this during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Federation > OAuth Authorization Server > OAuth Profile.
  3. Click on the appropriate OAuth profile.
  4. For Access Token Limit Per User, enter the limit you want to use.

Displaying access token detailed information

To view the number of  access tokens issued by your authorization server to an application for a specific user, perform the following procedure:

Impact of procedure: Performing the following procedures should not have a negative impact on your system

  1. Log in to tmsh.
  2. To list the details of tokens issued for an application, use the following syntax:

    tmsh list apm oauth token-details app-name <app name> user-id <userID>

    For example:

    tmsh list apm oauth token-details app-name exampleAppname user-id /Common/OauthAS.John

  3. The following example displays an example of a token with the user id /Common/OauthAS.John where Common is the name of the partition and OauthAS is the name of the OAuth profile.

    apm oauth token-details 1b7471f8f762344118d26d4d340ed08a705c5d8c2ceddaef {
        [...]
        access-token-status "active"
        [...]
        refresh-token-status "active"
        user-id "/Common/OauthAS.John"
    }
    [...]

Active tokens and tokens with refresh-token-status active contribute to the access token per user limit.

Revoking an access token

In some cases, it may be useful to revoke access tokens. To do so, perform the following procedure:

Impact of procedure: Performing the following procedures should not have a negative impact on your system

  1. Log in to the Configuration utility.
  2. Navigate to Access  >  Overview > OAuth Reports > Tokens.
  3. Enter the name of your application and click Search.
  4. On the left, select the token you want to revoke.
  5. Click Revoke.
