Known Issue

The Transparent option for BIG-IP health monitoring is not compatible with IPv6 addressing or the Route Domain feature. The BIG-IP system does not send Transparent health monitor traffic to any pools, pool members, or nodes using these features.

This issue occurs when either of the following conditions is met:

  • The Transparent monitoring option is enabled for a pool member or node using an IPv6 address.
  • The Transparent monitoring option is enabled for a pool member or node that resides in a route domain other than route domain 0.

The BIG-IP system internally translates all IPv4 addresses into IPv6 addresses. The Route Domains feature takes advantage of the extra bits available in an IPv6 address and uses this space to store the IPv4 address plus the route domain information for that address. Due to this issue, although all IP addresses in a configuration may be IPv4, any addresses using route domains (outside of the default route domain 0) are functionally IPv6 addresses, and thus incompatible with the Transparent monitoring option.

Note: The route domain feature was introduced in BIG-IP 10.0.0.

Impact

Pools, pool members, and nodes are incorrectly marked down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP health monitors will incorrectly mark down pool members and nodes that have IPv6 addresses.
  • BIG-IP health monitors will incorrectly mark down pool members and nodes that have been assigned a route domain other than 0.

Workaround

You may be able to partially work around this issue by configuring a monitor to act transparently and check through a pool member instead of checking the pool member directly. To do so, configure a monitor to check an alias IPv6 address via a static route that has the IPv6 pool member address as its gateway.

Impact of workaround: The impact may be limited in its applicability, and requires significant configuration administration as described in the following example scenario.

For example, a scenario where you want to check the health of two IPv6 pool members transparently, would have the following configuration requirements:

  • For each pool member, you will need to identify a unique IPv6 host address to act as an alias IPv6 address.

    Note: This host must be reliable, as this will be the address that will be checked to determine the health of your pool member.

  • For each pool member, you will need to create a unique monitor that is configured with the unique host's IPv6 address as the alias address.
  • For each pool member, you will need to assign its unique monitor as a node specific monitor.
  • For each alias IPv6 address, you will need to configure a static route, specifying the related IPv6 pool member as the route gateway.
