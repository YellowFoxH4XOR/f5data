Known Issue

When the system calls the HTTP::disable function from within an iRule, a TMM core may result when the system attempts to cache an uncacheable request.

This issue occurs when all of the following conditions are met:

  • HTTP caching is enabled.
  • OneConnect is enabled within the HTTP profile.

    Note: OneConnect is automatically enabled when the system uses the NTLM authentication profile.

  • An iRule is configured and calls the HTTP::disable function.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H416361 on the Diagnostics > Identified > High screen.
  • A TMM core occurs resulting in a failover.
  • Traffic is affected as a result of the failover.

Workaround

To work around this issue, when HTTP::disable is called in a client-side event, you must also disable cache, compression, and OneConnect in the client-side event. Additionally, you must disable OneConnect in a corresponding server-side SERVER_CONNECTED event.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

Note: If you are using the described configuration for a Microsoft Exchange Server deployment, F5 recommends that you download and use the F5 supported iApp template for Microsoft Exchange Server instead of using the workaround. For information about downloading and installing the Microsoft Exchange Server iApp template, refer to K13497: iApp: Microsoft Exchange Server 2010 Client Access Servers.

You can complete these tasks by disabling the following functions in the client-side event of the iRule:

  • ONECONNECT::reuse disable
  • CACHE::disable
  • COMPRESS::disable

    Note: The COMPRESS::disable function is required only if the system has compression enabled within the HTTP profile or is using the WAM/WOM profile.

  • HTTP::disable

Additionally, you must disable the following functions in a server-side SERVER_CONNECTED event of the iRule:

  • ONECONNECT::reuse disable
  • ONECONNECT::detach disable

For example:

when HTTP_REQUEST {
set oc_reuse_ss_disable 1
ONECONNECT::reuse disable
CACHE::disable
COMPRESS::disable
HTTP::disable
}
when SERVER_CONNECTED {
if { [info exists oc_reuse_ss_disable] } {
ONECONNECT::reuse disable
ONECONNECT::detach disable
}
}
