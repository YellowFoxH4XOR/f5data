Topic

By default, the syslog application runs on all BIG-IP and 3-DNS systems. You can configure syslog to log messages to the hard drive, the network, or to another process, such as /usr/local/sbin/checktrap.pl, which reads incoming syslog messages.

To configure syslog to log messages to the checktrap.pl process, edit the /etc/syslog.conf file. Once configured, checktrap.pl compares the text portion of messages that it receives to the /etc/snmptrap.conf file. If checktrap.pl finds a regular expression (regex) match, it sends the message across the network in UDP protocol as an SNMP trap to the trapsinks that are specified in the /etc/snmpd.conf file.

Prior to BIG-IP 4.5 PTF-06, the /etc/syslog.conf file sent messages directly to /checktrap.pl, which initiated a new process each time a syslog message was sent. Therefore, it was possible to have dozens of /checktrap.pl processes open at once, causing a reduction in BIG-IP or 3-DNS performance and resources.

Beginning in BIG-IP 4.5 PTF-06, you can configure the syslog application (through the /etc/syslog.conf file) to send messages to the /var/run/trapper file. Messages are stored in the /var/run/trapper file until they are read, rather than being sent directly to the checktrap.pl process.

To configure the syslog application to send messages to the /var/run/trapper file, perform the following steps:

  1. Using a text editor, such as vi or pico, open the /etc/syslog.conf file.
  2. Scroll to the end of the file.
  3. Remove the comment # from the lines that appear similar to the following:

    # local0.*   /var/run/trapper
    # local1.*   /var/run/trapper
    # local2.*   /var/run/trapper
    # auth.*   /var/run/trapper
    # kern.*   /var/run/trapper

  4. Save the file.
  5. Reboot the system to initiate the changes.

The checktrap.pl process will read the messages in the order that they were sent, using a first in, first out (FIFO) method. A FIFO file is similar to a text file where each new line is appended to the bottom of the file, and the file is read from the top. A message is deleted once it is read, and the message beneath it become the first message, preventing the file from becoming too large.
