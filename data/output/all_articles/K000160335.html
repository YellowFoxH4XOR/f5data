K000160335: WAF exclusion regex fails to match a path which includes ".." double dot

Published

Applies to

Source

Description

You create a WAF exclusion rule using a regular expression like ^/some/\.\./path$ but it fails to match requests for /some/../path even though it is a proper regular expression.

Environment

  • F5 Distributed Cloud
  • F5 XC Load Balancer
  • WAF

Cause

An F5 XC load balancer does path normalization before any regex is applied. A request like "/some/../path" is normalized to /path . F5 XC enforces this to prevent path confusion vulnerabilities. Path confusion occurs when a proxy and a backend server interpret a URL differently.

If F5 XC did not first normalize the path, an attacker could easily bypass a strict security policy or route meant to protect /path by simply sneaking ../ into the URL. By forcing all incoming requests into a single, standardized format, F5 XC ensures that security policies and routing rules cannot be tricked by obfuscated URLs.

Recommended Actions

To keep links in your web applications clean and prevent "dot-segments" (like /../) from appearing in URLs, you should move away from document-relative paths in favor of site root-relative or canonical absolute paths.
