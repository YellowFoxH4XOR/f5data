Known Issue

This is the result of a known issue. HTTP application health monitors whose Send string includes a double backslash sequence can be defined in the BIG-IP Configuration utility, and the monitor initially functions as expected. However, if you use the bigpipe load command to load a configuration that contains such a monitor, the BIG-IP will replace each double backslash sequence in the monitor Send string with a single backslash. As a result, healthy servers to which the monitor is applied may not respond to the monitor request as expected. When the expected response is not received, the BIG-IP system marks the server down. If the same monitor is applied to all pool members, this may result in disruption of service.

Note: The bigpipe load command may be typed at the command line, or may be invoked as a result of one of the following actions:

  • Synchronizing the configuration between units of a redundant pair
  • Restoring a configuration archive
  • After upgrading your BIG-IP system

For example, the following monitor is created and saved in the Configuration utility, and applied to a pool of HTTP servers:

monitor my_http {
defaults from http
send "GET /index.html\\r\\n"
}

The monitor sends the configured Send string, including the double backslash sequence, to the servers to which it is applied. BIG-IP marks the servers up or down depending on the server response.

After synchronizing the configuration and failing over, the peer BIG-IP system marks all of the servers in the pool down. Examining the monitor configuration using the bigpipe monitor list command reveals that the running configuration contains the following monitor definition:

monitor my_http {
defaults from http
send "GET /index.html\r\n"
}

Note: Unless the running configuration is saved, only the running configuration is affected, and the monitor object in the bigip.conf file still contains the double backslash sequences. However, if you save the running configuration after using the bigpipe load command, the running configuration is written to the bigip.conf file, and the original monitor definition with the double backslash sequence is overwritten.

F5 Networks Product Development is tracking this issue as CR128053 for the BIG-IP version 9.4.x branch.

This issue does not affect the 9.3.x and the 10.x branches.

Workaround

You can work around this issue by replacing each backslash character with its equivalent regular expression hexadecimal escape sequence, \x5c. For example, the monitor above would be modified as follows:

monitor my_http {
defaults from http
send "GET /index.html\x5c\x5cr\x5c\x5cn"
}

This approach allows the double backslash sequence to escape detection by the bigpipe parser. When the BIG-IP system constructs the monitor packet based on this monitor definition, each escape sequence in the Send string is translated to a backslash character, and the monitor functions as expected.
