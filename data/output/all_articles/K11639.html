Known Issue

This is the result of a known issue. Attempting to monitor a BIG-IP version 10.1.0 system with 3-DNS version 4.x will result in iQuery communication disruptions, such as virtual servers intermittently changing state and ineffective BIG-IP GTM load balancing. The disruptions will affect valid BIG-IP GTM communication with the BIG-IP device that is being monitored with a 3-DNS version 4.x device.

Important: Beginning in BIG-IP LTM version 10.1.0, iQuery communication is no longer supported with 3-DNS 4.x versions. For more information, refer to K11106: Change in Behavior: iQuery communication is not supported between BIG-IP or 3-DNS version 4.x and BIG-IP LTM or GTM version 10.1.0 or later.

To prevent any disruption with iQuery communication within your network, do not configure any 3-DNS devices to monitor a BIG-IP running version 10.1.0. If upgrading from a 3-DNS to BIG-IP GTM, F5 recommends that you upgrade the 3-DNS infrastructure to BIG-IP GTM and verify that it is operating correctly before upgrading to BIG-IP version 10.1.0.

F5 Product Development tracked this issue as CR138987, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or Enterprise Manager release notes.

Note: BIG-IP LTM version 10.2.0 does not support communication with 3-DNS version 4.x; the fix in version 10.2.0 prevents the BIG-IP iQuery communication from being disrupted by a 3-DNS version 4.x attempting to monitor the BIG-IP LTM.

Important: Enterprise Manager version 1.8 and later installs the version 10.1.0 big3d process onto managed devices. As a result, this issue may affect BIG-IP systems running versions prior to BIG-IP version 10.1.0.
