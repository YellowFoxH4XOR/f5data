K10967: Drive mapping and the 'net use' command may intermittently fail on Windows Vista, Windows 7, and Windows 2008 clients

Topic

If a user running Windows Vista, Windows 7, or Windows 2008 attempts to connect to a CIFS share by using the net use command or by mapping a drive, and the user is already connected to a share on the same back-end filer, the connection may fail with a system error 1219. This behavior occurs when the initial connection to the back-end filer was made using the UPN format (username@domain) of the Windows username.

This behavior occurs because of the Windows client software; it is not an issue with the ARX software. You can observe this issue when no ARX system is present between the client and file server. For example, the following output was taken from a Windows 7 client. The client connected directly to a Windows 2003 file server; no ARX system was present.

C:\>net use \\172.16.0.100\share1 /USER:test@example.com
The command completed successfully.

C:\>net use \\172.16.0.100\share2 /USER:test@example.com
System error 1219 has occurred.

Multiple connections to a server or shared resource by the same user, using more
 than one user name, are not allowed. Disconnect all previous connections to the
 server or shared resource and try again.

C:\>net use \\172.16.0.100\share2 /USER:example.com\test
System error 1219 has occurred.

Multiple connections to a server or shared resource by the same user, using more
 than one user name, are not allowed. Disconnect all previous connections to the
 server or shared resource and try again.

C:\>net use /delete \\172.16.0.100\share1
\\172.16.0.100\share1 was deleted successfully.

C:\>net use \\172.16.0.100\share1 /USER:example.com\test
The command completed successfully.

C:\>net use \\172.16.0.100\share2 /USER:example.com\test
The command completed successfully.

Users can prevent this behavior by using the format DOMAIN\username for the Windows username when mapping a drive or running the net use command. If a user is already connected to a share on a back-end filer, for example, if a domain logon script automatically maps a drive using the UPN username format, the user must disconnect all shares to the back-end filer before attempting to connect to a new share on the filer. To disconnect, users should run the net use /delete command.

For example:

net use /delete \\172.16.0.100\share1

Alternately, if the user has a mapped drive, the user can right-click on the drive name in Windows Explorer and select Disconnect.
