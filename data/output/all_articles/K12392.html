Known Issue

This is the result of a known issue. The Cavium Networks NITROX card, which is used by the BIG-IP system to accelerate Secure Sockets Layer (SSL) connections, does not correctly handle RSA keys whose lengths are not divisible by eight. The first connection to a virtual server configured with an SSL private key whose length is not divisible by eight will cause a failure in the SSL acceleration card. As a result of this failure, the Traffic Management Microkernel (TMM) will crash and dump core.

F5 Product Development tracked this issue as ID 303431 (formerly CR82078), and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, or WAN Optimization release notes.

Workaround

In order to avoid this issue, ensure that every SSL private key you import and use on the BIG-IP system is of a length that is divisible by eight. If you have already encountered this issue, disassociate the offending Client SSL or Server SSL profile from all virtual servers that were configured with it.

Note: To determine the length of an SSL private key, use the following command syntax:

openssl rsa -in <key file> -noout -text | head -1

For example:

openssl rsa -in /config/ssl/ssl.key/test.key -noout -text | head -1
Private-Key: (1024 bit)

Additional information

RSA key lengths that are not divisible by eight are uncommon; typical lengths include 512, 1024, 2048, and 4096 bits. Every time this issue was reported to F5, it was determined to be the result of a user error during the generation of the SSL private key. For example, 1024 is often erroneously typed as 1042.
