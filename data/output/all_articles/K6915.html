Known Issue

This is the result of a known issue. After installing the BIND security patch, the named utility will not start successfully. If you run the bigstart status named command, the status information will report that the named utility is continually restarting, as the output below demonstrates:

# bigstart status named
named run (pid 4637) 0 seconds, 2 starts, 59 restarts

The patch installs a version of the named startup script, which calls a program that does not exist in the BIG-IP 9.1.x code branch.

F5 Product Development is tracking this issue as CR70369.

Workaround

To work around this issue, replace the incorrect named startup script with the 9.1.x version of the script by performing the following procedure:

  1. Log in to the BIG-IP LTM command line.
  2. Change directories to the /etc/bigstart/scripts/named directory by typing the following command:

    cd /etc/bigstart/scripts/named

  3. Using a text editor, edit the named startup script, as follows:

    The following script output is the incorrect named startup script:

    #!/bin/sh
    # wait awhile for mcpd to get fully loaded and be ready so that runsm1 can
    # make the mcp connection.
    # depend: mcpd 15
    # start zfd in the foreground for daemontools to work.
    exec /sbin/runsm1_named /usr/sbin/named -f -t /var/named -u named -c /config/named.conf

    Replace the incorrect named startup script (shown above), with the following base 9.1.x script:

    #!/bin/sh
    # start zfd in the foreground for daemontools to work.
    exec /usr/sbin/named -f -t /var/named -u named -c /config/named.conf

  4. Save the changes and exit the text editor.
