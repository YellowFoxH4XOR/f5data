Topic

You should consider using this procedure under the following condition:

  • You want to configure a BIG-IP LTM virtual server to load balance gRPC traffic on HTTP/2 (client and server side).

    For more information on gRPC, refer to the gRPC documentation.

    Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Description

Beginning in BIG-IP 16.1.0, gRPC is supported in BIG-IP LTM full proxy. To load balance gRPC traffic, you create a HTTP/2 virtual server with the following configuration:

  • Client and Server SSL profiles with the Renegotiation parameter disabled.
  • HTTP/2 Client and Server profiles with the Enforce TLS Requirements parameter enabled
  • HTTP MRF Router enabled.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have a gRPC client and server that works directly without the BIG-IP system.
  • You have Administrator access to the BIG-IP Configuration utility

Procedures

To watch a video demo of these procedures, go to Configure a BIG-IP LTM virtual server for gRPC traffic using the Configuration utility.

To create a BIG-IP LTM virtual server for gRPC traffic, perform the following procedures:

  • Create a pool for your gRPC servers
  • Create a virtual server

Create a pool for your gRPC servers

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the Configuration utility.
  2. Go to Local Traffic > Pools
  3. Select Create
  4. Enter an appropriate Name.
  5. Select an appropriate monitor: icmp, tcp, https. 

    Note: Depending on your gRPC server, the default HTTP/2 monitor may or may not be able to receive a successful response from the gRPC server. For example, your gRPC server may have specific requirements such as SEND string, authentication, and so on. If you require a more specific monitor, you can create an external monitor using the curl or nghttp commands as described in the Troubleshooting section. For more information on external monitors, refer to K71282813: Overview of BIG-IP EAV external monitors

  6. Enter the Node Name, Address and Service Port. 
  7. Select Add
  8. Select Finished

Create a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers
  3. Select Create.

  4. Enter the configurations in the following table for your virtual server.

    ParameterComments
    Namegrpc_vs
    Destination Address/MaskIP address accessible from the gRPC client
    Service PortTLS enabled port number
    HTTP Profile (Client)http
    HTTP Profile (Server)http
    SSL Profile (Client)Create a Client SSL profile with the Renegotiation parameter disabled
    SSL Profile (Server)Create a Server SSL profile with the Renegotiation parameter disabled
    Source Address TranslationAuto Map
    Default PoolThe pool created in the previous procedure
    HTTP/2 Profile (Client)http2 (A profile with the Enforce TLS Requirements parameter enabled)
    HTTP/2 Profile (Server)http2 (A profile with the Enforce TLS Requirements parameter enabled)
    HTTP MRF RouterEnabled

  5. Select Finished.

Troubleshooting

  • Your gRPC client must work directly with the gRPC server without the BIG-IP virtual server.
  • Verify that HTTP/2 communication is successful with the gRPC server with the following tools. Enter the commands on the BIG-IP system:

    Note: This only verifies successful HTTP/2 communication from the BIG-IP system to the gRPC server. It does not verify gRPC functionality.

    • curl

      Beginning in BIG-IP 14.1.0, you can use curl with the --http2 switch on the BIG-IP system to verify the HTTP/2 health of your pool members. To do so, use the following command syntax:

      curl --http2 -Ivk https://<server_IP_address>:<port number>

      When your pool member is able to provide HTTP/2 service, you may observe an output similar to the following truncated example:

      * ALPN, server accepted to use h2
      [...]
      * Using HTTP2, server supports multi-use
      * Connection state changed (HTTP/2 confirmed)
      [...]

    • nghttp

      Beginning in BIG-IP 14.1.0, you can also use nghttp to verify the health of the back-end server. To do so, use the following command syntax:

      nghttp -ynv https://<server_IP_address>:<port number>

      You may observe an output similar to the following truncated example:

      [  0.202] Connected
      The negotiated protocol: h2
      [...]
