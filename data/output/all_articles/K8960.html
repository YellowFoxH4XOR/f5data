Known Issue

This is the result of a known issue. The HTTP::respond iRule command sends double Connection headers when using a user-specified Connection: Close header.

Note: A user-specified Connection header should override the default Connection header, only if the user specifies Close; forcing a connection to remain open is not allowed.

For example, a virtual server is associated with the following iRule:

rule respond_rule {
when HTTP_REQUEST {
HTTP::respond 304 Connection Close
}
}

Using the HTTP::respond iRule command, the expected HTTP response behavior should be as follows:

HTTP/1.0 304 Not Modified
Connection: Close
Server: BIG-IP
Content-Length: 0

Due to the known issue, the following HTTP response occurs:

HTTP/1.0 304 Not Modified
Connection: Close
Connection: close
Server: BIG-IP
Content-Length: 0

The HTTP response contains the user-specified Connection: Close header, as well as the default Connection: Close header sent by the HTTP::respond iRule command when the Connection header is not specified.

This issue is cosmetic and does not affect the client connection.

F5 Product Development tracked this issue as CR99706 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP version 9.4.5, for the BIG-IP 9.4 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
