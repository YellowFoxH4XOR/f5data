Description:

There is a range of issues of an application when an ASM policy is configured in the virtual server:

  • App flow issues like blank page is shown, error page or a different webpage.
  • User experience is affected like image are not shown or look-and-feel changes
  • Errors in the validation of the user input

Environment

  • ASM security policy
  • Application issues

Cause

None

Recommended Action:

1- Disable the ASM policy. Be sure the issue is caused by an ASM security policy, disable the ASM policy to check if the issue persists or not. If the answer is not, keep going to the next point.

2- Check the event logs in Security > Event logs > Application > Request to see if any blocked request or alarm has been raised. In some occasions, some requests are blocked but are not shown to the user as they are executed in the background like AJAX requests. If the app is a single page application, enable SPA for all policies or configure a DOSL7 profile with SPA:

K51185822: How to Enable Single Page Application (SPA) Support for Javascript Challenges in ASM

https://my.f5.com/manage/s/article/K51185822

3- Test different browsers and OS to check if a particular browser is affected like Safari, Chrome, Firefox, mobile OS, Windows, Linux or MacOS. Just the most popular browsers are tested. Not well-known are not tested and then, we cannot guarantee all security features work for all browsers.

4- Narrow the issue by determine which feature is causing the problem: Some security features inject a Javascript code to generate Device ID which may cause an erratic behaviour in some apps. Then, disable features like Session Hijacking, Session Awareness with Device ID Threshold and brute-force protection.

K19556739: Overview of BIG-IP ASM client fingerprinting

https://my.f5.com/manage/s/article/K19556739

5- Collect a HAR file and browser console before and after the ASM policy is configured with screenshots. If any of above features is injecting a Javascript but the HTTP response page already contains a Javascript function, it's possible the client's Javascript code won't be executed due to CSP violation:

Bug ID 754109: ASM/Bot-Defense/DoSL7 content-security-policy header modification violates Content Security Policy directive

https://cdn.f5.com/product/bugtracker/ID754109.html

If above happens, you can see the error in the browser console. Then, open debugging tools in the browser and check the browser console and network tab, take a screenshot in both scenarios (working and failure) to compare which errors are "normal" from the one introduced by the ASM policy.

Collect the HAR file as well, but most important, take a screenshot to observe the last HTTP request in the failure scenario. Later, check the differences in the reponses collected in the HAR files, especially, the last HTTP request:

K10370211: Generate an HTTP Archive using a browser

https://my.f5.com/manage/s/article/K10370211

6- Collect a packet capture in both scenarios and the HTTP response of working scenario. If above points are not helping to determine what's the cause of the issue, extract a string of the page only present in the working scenario, using debugging tools, select a string using the mouse and click right click, in the submenu click inspect (most browsers), copy the HTML code in a text file.

In order to collect the packet captures, check if the VIrtual Server is using Client SSL, Server SSL profiles or both. If any of them, there is a tcpdump option that has been added that removes the requirement for an iRule to create a Pre Master Secret file.
 

K31793632: Creating a decrypted tcpdump capture without using an iRule

https://my.f5.com/manage/s/article/K31793632

Open the packet capture of working scenario and look for the HTTP request of the response containing the copied HTML code using below filter in tshark after decrypted packet capture:

Filter: data-text-lines contains "string-copied-from-working-scenario"

Compare both HTTP requests in working and failure scenarios, an useful tool is Notepad++ with differences plugin. An example, can be the bug ID1095041 which truncates the cookie names with whitespaces:

Bug ID 1095041: ASM truncates cookies that contain a space in the name and TS cookie as part of cookie list.

https://cdn.f5.com/product/bugtracker/ID1095041.html
