Known Issue

Description

A data group record containing a number sign/hash (#) will cause loading of the BIG-IP configuration to fail.

For example, if you use the Configuration utility or the Traffic Management Shell (tmsh) to create or edit a data group, where records contain the number sign/hash character, and save it to disk, a subsequent load of the configuration fails.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you use tmsh to load the BIG-IP configuration, you may see an error message similar to the following example:

    Validating configuration...
    /config/bigip_base.conf
    /config/bigip_user.conf
    /config/bigip.conf

    Data Input Error:(at line: 62) a value must be provided for "type" attribute when creating "internal"

    Note: For devices configured with partitions, if the affected data group resides in a partition other than /Common, the partition path of the bigip.conf file displays before the Data Input Error:.

Workaround

To recover from a failed load of the configuration, using a text edito, you can modify the data group configuration to allow the configuration to load. To do so, perform the following procedure:

Impact of workaround: The workaround temporarily enables the configuration to load with data groups that include the number sign/hash (#) in data group string data.

Important: This workaround is intended to allow the configuration to load allowing the number sign/hash (#) character to remain in the string data record of the data group only while loading. When you subsequently save the configuration, the system will revert the workaround modifications.

  1. Log in to the command line of the affected system.
  2. Using a text editor, open the /config/bigip.conf file.
  3. Locate any number sign/hash characters located within the data group records.

    Following is an example of an original data group syntax record containing a number sign/hash (#) character:

    ltm data-group internal A-Group {
    records {
    # {
    data testing
    }
    }
    type string
    }

  4. Place double quotations ( " ) around the number sign/hash character contained in the data record, or precede the number sign/hash character with a backslash ( \ ).

    Following is an example of updated data group syntax using quotes:

    ltm data-group internal A-Group {
    records {
    "#" {
    data testing
    }
    }
    type string
    }

    Example updated data-group syntax using the backslash:

    ltm data-group internal A-Group {
    records {
    \# {
    data testing
    }
    }
    type string
    }

    Note: F5 highly recommends that you remove the offending string data number sign/hash character and replace it with syntax that does not include the use of the number sign/hash character.

  5. Save the changes to the bigip.conf file and exit the text editor.
  6. To load the modified /config/bigip.conf file, type the following command:

    tmsh load /sys config

  7. Once the system has successfully loaded the configuration, you should see all the number sign/hash (#) characters removed or replaced in the affected data group records.

    You can make these modifications using the Configuration utility, tmsh, or else use a text editor to modify the /config/bigip.conf file.

    Note: For devices configured with partitions, if the affected data group resides in a partition other than the /Common partition, modify the bigip.conf file located in the designated partition.
