K000149269: ICMP connectivity behavior with VELOS Partitions from VELOS Controllers

Type
Support Solution
Published
2025-01-13
Updated
2025-01-13
Applies to
  • F5OS
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000149269

Description

Upon deploying a partition, ICMP and wget requests to the partition IP address do not receive responses from the configured management IP addresses when tested from the floating IP and active controller. The issue resolves when failing over to the standby controller, but recurs when roles are switched back.

Environment

  • VELOS with redundancy (active and standby controllers)

Cause

The root cause of the issue is due to the Macvlan network configuration. The partition IP is assigned to a Macvlan interface, which restricts accessibility from the same node (active controller) due to how Macvlan works. This setup ensures that the management network is not accessible from the same node (the partition active controller).

Recommended Actions

There are a few recommended actions to take or consider in such situations:

  1. Access Management Network from Outside Controllers: Ensure that the management network is accessed from outside the active and standby controllers to avoid interference.
  2. Failover for Testing: If testing connectivity, perform a failover to the standby controller as it allows ICMP and wget to work.
