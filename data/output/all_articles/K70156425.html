Description

Manually modifying the /etc/openldap/ldap.conf configuration file, sometimes there's a big delay until changes are applied.

For each authentication request, during setting up the pam-ldap session, it re-reads the configuration file.
When a new session is opened by pam, the session is re-created, configuration loaded and session cached. This cache file is present under /var/run/pamcache/ folder.
The cache works by storing information such as a username hash and the remote client's IP address in the memory file-system. When the client sends a new request, it authenticates to the cache by submitting a BIGIPAuthCookie to the BIG-IP system.

When we logout of the Configuration Utility/GUI, this cache file also will be deleted automatically.

Environment

  • BIG-IP version before v14.1 is using pam_ldap

Cause

An older pamcache file exists

Recommended Actions

We have two options to Resolve the issue.

Option#1: disable the auth-pam-validate-ip as below:
  CLI : tmsh modify sys httpd auth-pam-validate-ip off
  GUI :

  1.  Log in to the Configuration utility.
  2.  Navigate to System > Preferences.
  3.  Clear the "Require A Consistent Inbound IP For the Entire Web Session" check box.
  4.  Click Update.

  Note: K13048 for more details.


Option#2: adjust the auth-pam-idle-timeout value as below:
  tmsh modify sys httpd auth-pam-idle-timeout <value>
  The default pamcache timeout is 1200 seconds. The minimum timeout is 120 seconds and the maximum is 2147483647 seconds.
  Note: K11140735 for more details.
