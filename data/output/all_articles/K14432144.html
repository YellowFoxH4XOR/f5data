Description

Microsoft recommends to migrate all applications that are using the Azure Active Directory Authentication Library (ADAL) for authentication and authorization functionality to the Microsoft Authentication Library (MSAL) because Microsoft support and development for ADAL ends in December, 2022. Microsoft also recommends migrating your application from Azure AD Graph to Microsoft Graph

Azure AD Endpoints V2 uses MSAL and Microsoft Graph API.
https://login.microsoftonline.com/<AAD_TENANT>/v2.0/.well-known/openid-configuration

The implicit grant flow has been replaced by the OAuth 2.0 authorization code with Proof Key for Code Exchange (PKCE).
 PKCE is supported by MSAL.


Procedure

1)Configuration on AAD
https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-app-registration

1.1) Register a new app on (AAD > App Registrations) 
1.2) Configure that app as Mobile and desktop applications (AAD > App Registrations > APP > Authentication > Add Platform > Mobile and desktop applications)

    Redirect URIs: http://localhost:8000/
    Do not select any "Implicit grant and hybrid flows" option.

1.3) Check that only 'Microsoft Graph -> openid' is added in (AAD > App Registrations > APP > API permissions)
1.4) Copy 'Application (client) ID' (APP_ID) value from (AAD > App Registrations > APP > Overview). 
1.5) Assign that App to users/group
1.6) Set "accessTokenAcceptedVersion" to be "2" in (AAD > App Registrations > APP > Manifest)

{
    "id": "<...>",
    "accessTokenAcceptedVersion": 2

2) Configuration on APM 
2.1) Set 'OpenID URI (authentication-uri)' in the 'OAuth Provider' and click discover
 
apm aaa oauth-provider /Common/AzureAD {
    trusted-ca-bundle /Common/ca-bundle.crt
    type azure-ad
    authentication-uri https://login.microsoftonline.com/<AAD_TENANT>/v2.0/.well-known/openid-configuration

2.2) Add your App Id as 'audience' in the 'JWT Token Configurations', populated after (2.1)

apm oauth jwt-config /Common/auto_jwt_AzureAD {
    audience { APP_ID }

2.3) Create a 'JWT Provider List' and add the 'OAuth Provider'

apm oauth jwt-provider-list /Common/jwt-provider-AAD {
    providers {
        /Common/AzureAD { }
    }
}

2.4) Add an OAuth Scope agent in the access policy with the 'JWT Provider List'

apm policy agent aaa-oauth /Common/AP_act_oauth_scope_ag {
    jwt-provider-list /Common/jwt-provider-AAD
    token-validation-mode internal
    type scope
}

2.5) Create a connectivity profile with these values. Add this connectivity profile to the VS.

apm profile connectivity /Common/conn-na-AAD {
    client-policy {
        conn-na-AAD_clientPolicy {
            oauth {
                client-id APP_ID 
                done-uri https://vpn.lab.wan/public/oauth_done.html 
                provider-name /Common/AzureAD
                scopes "openid"
            }
            servers {
                {
                    alias vpn
                    host vpn.lab.wan
                }
            }

2.6) Add this irule to VS

when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
  if { [string tolower [HTTP::host]] starts_with "vpn.lab.wan" and [HTTP::path] starts_with "/my.logon.php3" } {
      if { [HTTP::header exists Authorization] and [HTTP::header Authorization] contains "Bearer" } {
        set jwtauth [string range [HTTP::header Authorization] 7 end]
        ACCESS::session data set -secure session.oauth.client.last.access_token $jwtauth
      }
  }
}


Troubleshooting

1) Edge Client (EC) receives configuration from APM

GET https://vpn.lab.wan/pre/config.php?version=2.0

200 OK
<AUTH>
  <OAUTH2>
    <DONE_URI>https://vpn.lab.wan/public/oauth_done.html</DONE_URI>
    <OPENID_URI>https://login.microsoftonline.com/<AAD_TENANT>/v2.0/.well-known/openid-configuration</OPENID_URI>
    <USERINFO_ENDPOINT>https://graph.microsoft.com/oidc/userinfo</USERINFO_ENDPOINT>
    <AUTHORIZATION_ENDPOINT>https://login.microsoftonline.com/<AAD_TENANT>/oauth2/v2.0/authorize</AUTHORIZATION_ENDPOINT>
    <TOKEN_ENDPOINT>https://login.microsoftonline.com/<AAD_TENANT>/oauth2/v2.0/token</TOKEN_ENDPOINT>
    <DISCOVERY_INTERVAL>0</DISCOVERY_INTERVAL>
    <CLIENT_ID>APP_ID</CLIENT_ID>
    <SCOPES>openid</SCOPES>
  </OAUTH2>
</AUTH>

2) EC creates and records a secret named the "code_verifier" and derives a transformed version "t(code_verifier)", referred as "code_challenge", which is sent in the "OAuth Authorization Request" along with the transformation method "t_m" referred as "code_challenge_method".

GET https://login.microsoftonline.com/<AAD_TENANT>/oauth2/v2.0/authorize?client_id=<...>&response_type=code&redirect_uri=http%3A%2F%2Flocalhost%3A8000%2F&state=<...>&scope=openid&code_challenge=<...>&code_challenge_method=S256

3) OAuth AS records "t(code_verifier)", the transformation method and provides an authorization code

302 OK
 Location http://localhost:8000/?code=<...>&state=<...>&session_state=<...>

4) EC redirects UA to close browser's tab

GET http://localhost:8000/?code=<...>&state=<...>&session_state=<...>

302 OK
 Location https://vpn.lab.wan/public/oauth_done.html

5) EC sends the authorization code in the "OAuth Access Token Request" to OAuth AS, including the "code_verifier" secret generated at (3.2).

POST https://login.microsoftonline.com/<AAD_TENANT>/oauth2/v2.0/token
 grant_type: authorization_code
 redirect_uri: http://localhost:8000/
 client_id: <...> 
 code_verifier: <...>
 code: <...>

6) OAuth AS transforms "code_verifier" and compares it to "t(code_verifier)" from (3.3). If they match, OAuth AS sends an access token to EC

200 OK
{
  "token_type": "Bearer",
  "expires_in": 4800,
  "ext_expires_in": 4800,
  "access_token": "<...>",
  "refresh_token": "<...>",
  "id_token": "<...>"
}

7) EC sends the access token to APM as bearer token.

GET https://vpn.lab.wan/my.logon.php3?outform=xml&get_token=1&client_version=2.0
 Authorization Bearer <...>
