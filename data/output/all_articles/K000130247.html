K000130247: Using header information as input for rate limiting on KIC Virtual Server resource

Type
Support Solution
Published
2023-01-26
Updated
2023-08-07
Source
https://my.f5.com/manage/s/article/K000130247

Description

If you are trying to use a header that you send to turn on and off rate-limiting for your ingress controller and you are using virtual server resources you can follow the solution below. 

Environment
  • NGINX Ingress Controller
  • rate-limit
  • Virtual Server resource

Cause

None 

 Recommended Actions

Create the rate-limit policy using the file below and change the header name to whatever header you will be passing in. 
apiVersion: k8s.nginx.org/v1
kind: Policy
metadata:
  name: rate-limit-policy
spec:
  rateLimit:
    rate: 1r/m
    key: ${http_custom_header_name}
    zoneSize: 10M
Add this policy to your Virtual Server resource 
apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
  name: webapp
spec:
  host: webapp.example.com
  policies:
  - name: rate-limit-policy
  tls:
    secret: webapp-secret
  upstreams:
  - name: webapp1
    service: webapp1-svc
    port: 80
  routes:
  - path: /webapp1
    action:
      proxy:
        upstream: webapp1

This adds the following lines to your nginx.conf which configures the rate-limiting on the header

limit_req_zone ${http_custom_header_name} zone=pol_rl_default_rate-limit-policy_default_webapp:10M rate=1r/m;
server {
    listen 80;
    listen [::]:80;
    server_name webapp.example.com;
    status_zone webapp.example.com;
    set $resource_type "virtualserver";
    set $resource_name "webapp";
    set $resource_namespace "default";
    listen 443 ssl;
    listen [::]:443 ssl;
    ssl_certificate /etc/nginx/secrets/default-webapp-secret;
    ssl_certificate_key /etc/nginx/secrets/default-webapp-secret;
    server_tokens "on";
    limit_req_log_level error;
    limit_req_status 503;
    limit_req zone=pol_rl_default_rate-limit-policy_default_webapp
