Known Issue

The BIG-IP system may experience memory issues when a TCP virtual server is configured with Session Initiation Protocol (SIP) and message-based load balancing (MBLB) profiles.

This issue occurs when the following condition is met:

  • Pool members process messages significantly slower than the rate of messages queued for them.

If a pool member is slow to consume data, and begins advertising a receive window of zero, the BIG-IP system stops sending any other TCP data for that flow, other than window probes. This is normal congestion control behavior. However, the SIP filter, which has no limit, continues accepting data and increasing its memory consumption.

The BIG-IP system has an adaptive reaping feature, which allows the system to aggressively reap connections when memory utilization reaches a low-water mark, and stop establishing new connections when memory utilization reaches a high-water mark percentage.

Impact

The BIG-IP system may begin to drop connections and/or stop accepting new connections, until memory utilization returns to normal.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H484539 on the Diagnostics > Identified > Low screen.
  • Messages similar to the following example log to the /var/log/ltm file:

    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode activated. (117504/138240 pages)
    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode deactivated. (117503/138240 pages)

Workaround

To mitigate this issue, you can increase the number of pool members to distribute the messages.
