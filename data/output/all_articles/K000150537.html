K000150537: Handle OpenAPI file with overloaded path parameters after 17.1.x

Published

Applies to

Description

This article describes the behavioural changes on handling OpenAPI file with overloaded path parameters in v17.1.x.

Environment

Advanced WAF, OpenAPI swagger file is assigned

Cause

Take below Swagger file extract as an example:

"paths": { "/absolute-redirect/{n}": { "get": { "parameters": [ { "in": "path", "name": "n", "type": "integer" } ]
}}, "/bytes/{n}": { "get": { "parameters": [ { "in": "path", "name": "n", "type": "string" } ] }

Prior to v17.1.x, when there is an identically named positional parameter in different configurations, the existing global parameter with the same name is updated with the later configuration.

New parameters generated from example will be:

Parameter Name: n, Data Type: Alpha-Numeric

 

After 17.1.x, behaviour change is made for the OpenAPI processing to add the Unique Identifiers for the URL (Method, Protocol, URI name) to the parameter name that is being created for the positional parameter, so they can each have unique configuration.

New parameters generated from example:

Parameter Name: GET_absolute-redirect#_n, Data Type: Integer

Parameter Name: GET_bytes#_n, Data Type: Alpha-Numeric

From this example you can see a split on generated Parameters, thus may cause increase of Parameter Numbers on the ASM Policy when upgrading from pre-v17.1.x to v17.1.x.

Recommended Actions

This is an expected behaviour. No actions is required.

Additional Information

None.
