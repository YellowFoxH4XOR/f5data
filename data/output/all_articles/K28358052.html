Description

TCP profiles has two settings to control TCP retransmission behavior:

  • Minimum RTO (min-rto): Specifies the minimum length of time that the system waits for acknowledgements of data sent, before resending the data
  • Initial Retransmission Timeout Base Multiplier for SYN Retransmission (syn-rto-base): Specifies the initial RTO (Retransmission TimeOut) base multiplier for SYN retransmissions

In some cases, BIG-IP may retransmit an unACKed TCP segment after syn-rto-base instead of min-rto interval.

Environment

  • TCP profile is configured with a syn-rto-base value that is lower than minimum-rto
  • Client does not use TCP timetamps (the timestamps option in TCP enables the endpoints to keep a current measurement of the round trip time (RTT))
  • The BIG-IP system has not received any ACK before the TCP retransmission timer expires

Cause

BIG-IP uses min-rto interval once RTT value is calculated. Until RTT is known, BIG-IP will resend unACKed TCP segment after syn-rto-base interval.

NOTE: Above applies only to first TCP retransmission. Starting from 2nd retransmission, BIG-IP uses min-rto interval.

Recommended Actions

The following ID has been submitted to change this behavior: ID897437 - Make sure that minimum-rto is used before RTT measurement has been made.

Additional Information

Below example shows BIG-IP's behavior when client does not use TCP timestamps:

Client (10.10.10.10) <----> (10.10.10.100:80) Virtual Server

ltm profile tcp TCP-RTO {
    app-service none
    defaults-from tcp
    minimum-rto 600
    syn-rto-base 500
}
