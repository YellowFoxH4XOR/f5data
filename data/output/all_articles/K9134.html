Known Issue

This is the result of a known issue. The CPU load balancing mode distributes connections to the virtual server that currently has the most CPU processing time available to handle name resolution requests. When the CPU load balancing mode is used for a wide IP pool, the big3d agent running on the remote BIG-IP system returns a CPU value of zero. This behavior causes the BIG-IP GTM system to evenly distribute connections to the pool members, regardless of the actual CPU utilization of the remote BIG-IP system.

F5 Product Development tracked this issue as CR106685 and it was fixed in BIG-IP GTM 9.4.6. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Resolution

Workaround

To work around this issue, use the ratio load balancing mode and adjust the ratios of the BIG-IP GTM pool members accordingly.
