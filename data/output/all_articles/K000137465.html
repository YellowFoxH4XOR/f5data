Description

The Controller is not functional.

On login only the platform tab is available.

There are no options to interact with the platform.
 

kubectl get pods -A

shows that the secrets-svc pod is restarting.

On getting the logs and description of that pod it shows:

 

Description:

Warning Unhealthy 12m                 kubelet           Liveness probe failed: Error checking seal status: Get https://127.0.0.1:8200/v1/sys/seal-status: dial tcp 127.0.0.1:8200: connect: connection refused

 

Log:

2023-11-01T04:48:26.554Z   [FATAL]          basic            start/start.go:111   failed to initialize/unseal vault unable to unseal with saved tokens

 

Environment

This will occur if the Controller system has suffered a unrecoverable failure.

  • You have uninstalled the product and reinstalled it to restore operation.
  • You have left  the Postgresql Configuration database in place.
  • You have restored the cluster configuration as per https://docs.nginx.com/nginx-controller/admin-guides/backup-restore/backup-restore-cluster-config/

Cause

The Controller uses kubernetes secrets which are restored in the cluster config. This allows decryption (unsealing) of secrets stored in the Configuration (Postgresql) database.

The Cluster secrets and the Configuration database must match.

Installing Controller on a system which already has a Configuration database results in the configuration being reset.

The secrets-svc pod cannot unseal the secrets and system startup does not proceed.

 

Recommended Actions

The Configuration database must be restored.

 

Additional Information

There is no way to recover or re-key the secrets, by design.
The License will be restored.
