Description

There are use cases where the BIG-IP is required to only advertise a default route to its BGP peer when a certain route prefix exists in its routing table.
This article provides the steps to achieve that using 'neighbor <peer_IP_addr> default-originate route-map <route_map>' configuration.
 

Environment

  • BIG-IP is licensed with Routing Bundle
  • imish utility
  • ZebOS
  • A BGP neighbor or peer group for which the condition should be applied to.

Cause

None.

Recommended Actions

  1. From Bash CLI, access ZebOs console using  'imish' and create a prefix-list and route-map to be used for checking whether a specific route exists in the BIG-IP's routing table:
    Note: In this example, the route that needs to exist in the routing table so that BIG-IP would advertise a default route towards its peer is "192.168.1.0/20".

    # imish
    LTM1[0]>enable
    LTM1[0]#configure terminal
    Enter configuration commands, one per line.  End with CNTL/Z.

    LTM1[0](config)#ip prefix-list conditional-prefix seq 10 permit 192.168.1.0/24

    LTM1[0](config)#route-map conditional-rmap permit 10
    LTM1[0](config-route-map)# match ip address prefix-list conditional-prefix

  2. Apply the route-map into neighbor, following the default-originate command:

    Note: AS number 40, neighbor 10.1.10.147 are sample ASN and peer respectively.

    LTM1[0](config-route-map)#router bgp 40
    LTM1[0](config-router)#neighbor 10.1.10.147 default-originate route-map conditional-rmap
    LTM1[0](config-router)#end

  3.  Perform an outbound route refresh towards the peer after applying the route-map:

    LTM1[0]# clear ip bgp 10.1.10.147 soft out

  4. Verify the routes that are being advertised towards the peer:
    LTM1[0]# show ip bgp neighbors 10.1.10.147 advertised-routes

  5. Verify whether the desired prefix is in the routing table:
    LTM1[0]# show ip route 192.168.1.0/24
