Known Issue

Virtual servers created using the portal access setup wizard only use the default Client Secure Sockets Layer (SSL) certificate. The portal access setup wizard automatically creates an HTTPS virtual server with the default Client SSL profile. Once the wizard completes, configuring the Client SSL profile to use a non-default certificate successfully completes in the Configuration utility; however, the BIG-IP APM system continues to use the default certificate. The BIG-IP APM system will continue using the default certificate even after deleting the Client SSL profile from the virtual server.

Impact

Changes to the Client SSL profile have no effect, and the BIG-IP APM system only uses the default Client SSL certificate.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You are able to successfully change the certificate and key used in the Client SSL profile using the Configuration utility, but the change does not take effect in the BIG-IP APM system.
  • Users connecting to the BIG-IP APM system receive the default Client SSL certificate, regardless of the certificate configured in the Client SSL profile.

Workaround

To work around this issue, you can create the virtual server manually. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the name of the virtual server created by the wizard and note the name and configuration. You will need this information when you manually recreate the virtual server later in this procedure.
  4. Once you have documented the virtual server's configuration, delete the virtual server by clicking Delete.
  5. Navigate back to Local Traffic > Virtual Servers and click Create.
  6. In the Name setting, enter the name of the old virtual server.
  7. Enter the destination IP address of the old virtual server and 443 for the service port.
  8. Select the desired HTTP profile.
  9. Select the Client SSL profile with the desired certificate and the desired Server SSL profile.
  10. In the VLAN and Tunnel Traffic setting, select the VLANs to be enabled.
  11. In the Source Address Translation setting, select Auto Map.
  12. Select the desired rewrite profile.
  13. In the Access Policy section, select the access and connectivity profiles created by the wizard.
  14. In the HTTP Compression setting, select the httpcompression profile.
  15. In the Web Acceleration setting, select the optimized-caching profile.
  16. Configure any other virtual server settings needed for your environment.
  17. Click Finished.
