K000163532: Missing Timestamps in CGNAT NAT Logging when forwarding to HSL Remote Syslog

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000163532

Description

 BIGIP CGNAT NAT logging generates records without a populated timestamp (the 14th field) when forwarding them to a remote HSL logging server. For example:

"/Common/CGNAT_FORWARD_VS","Session Start","10.10.10.1","10.10.20.1","44656","80","0","TCP","10.10.20.11","10.10.20.1","1136","80","0"," ","112233445566"

Environment

  • BIGIP CGNAT
  • NAT logging profile
  • High-Speed Logging (HSL)

Cause

Only the CGNAT license has been provisioned.  AFM was not licensed and provisioned on the BIG-IP system.

Answer/Recommended Actions

Option 1: License and provision AFM

  1. Provision the AFM license if the AFM NAT logging format is required.  After AFM is enabled, the 14th field is populated with the timestamp.

Option 2: Use BSD syslog without an AFM license

  1. If AFM is not licensed or is not an option, configure a remote-syslog destination using BSD syslog format and reference the existing remote-high-speed-log destination.  
    1. Navigate to System ›› Logs: Configuration: Log Destinations and create a new log destination:
      1. Type: select Remote Syslog
      2. Syslog Format: BSD Syslog (Default)
      3. Forward To: Existing remote HSL destination

      Configuration example:
      sys log-config publisher /Common/cgnat_log_publisher {
    destinations {
        /Common/cgnat_log_destination { }
    }
}
sys log-config destination remote-high-speed-log /Common/cgnat_log_destination {
    pool-name /Common/syslog
    protocol udp
}
sys log-config destination remote-syslog /Common/syslog_bsd_dst {
    remote-high-speed-log /Common/cgnat_log_destination
}

       

  2. After BSD syslog is configured, the timestamp is added to the beginning of the syslog message.  Example: 
    <134>Sep 22 07:30:00 bigip.cgnat tmm[18478]: 23003161 "/Common/CGNAT_FORWARD_VS","Session Start","10.10.10.1","10.10.20.2","58150","80","0","TCP","10.10.20.12","10.10.20.2","1046","80","0","","112233445566"
    Note: The 14th field within the NAT payload remains empty in this format since AFM is not licensed.
