Description

Unable to see the clone pool IP address in packet capture. This is an article to verify if the clone pools are copying traffic to the Tealeaf server.  

Note: For information about configuring the clone pools, refer to K67550544: Configuring clone pools for IBM Tealeaf

Environment

  • BIG-IP v15 onwards
  • Virtual server with clone pool configured
  • Clone pools with IBM Tealeaf Server

Cause

None

Recommended Actions

Take a packet capture to view the clone traffic. To do so, use the following tcpdump syntax:

tcpdump -Xnes0 -i <vlan name>:nnnn <any tcpdump filters relating to connections as processed by the virtual server>

Note : <vlan name> is the name of the VLAN on which the Tealeaf server resides.

While reviewing the packet capture, we can see packets coming to BIG-IP from the client and those packets are sent to the clone pool member where the destination IP address is not of the clone pool member but the destination MAC address is of clone pool member.
This is because we are cloning the source and destination IP of the actual traffic. Therefore, we can only see the duplicate traffic with the destination MAC of the clone pool member.

We can verify the MAC address of the clone pool members from the ARP table in BIG-IP:

tmsh show /net arp
