Description

After configuring a Vitual Server with SSL re-encryption, traffic passing through the Virtual Server fails.

You can see a RST on the server side connection, sent by the pool member to the BIG-IP right after the Client Hello, not finishing the SSL handshake. Similar to the following output from a traffic capture, where 10.0.0.1 is the example pool member IP:

192.168.1.1   10.0.0.1   47000   443     OUT s1/tmm1 : Client Hello
10.0.0.1   192.168.1.1   443     47000   IN  s1/tmm1 : 443 → 47000 [RST, ACK]

Environment

  • Virtual Server with SSL re-encryption
  • Server SSL profile with server-name set to none

Cause

Some HTTPS servers require SNI and may close a connection with a TCP reset if SNI is not provided in the Client Hello message. For more details refer to: K50528306: HTTPS connections may fail with TCP reset when pool members require SNI.

Recommended Actions

Follow steps on  Determining if the pool member requires SNI, to check if your server requires SNI. If it does, proceed to configure the server-name parameter on the Server SSL profile attached to the Virtual Server, for details refer to: Configuring the Server SSL profile to use SNI.

Note: If your server is not configured to require SNI, keep troubleshooting for other possible issues causing the server to reset the connection.
