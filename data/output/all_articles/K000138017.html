K000138017: Ratio(node) Loadbalncing Method Not Working Properly

Type
Support Solution
Published
2023-12-22
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000138017

Description

Ratio(node) load balancing method is not working as expected.


Environment

  • LTM
  • radio-node load-balancing method

Cause

Ratio(node) load balancing method is not based on the ratio value configured on the pool member. It respects the values that are configured directly on the node.


For example, with the following configuration:

==========

ltm pool http-pool {

   load-balancing-mode ratio-node

   members {

       172.16.1.1:http {

           address 172.16.1.1

ratio 1

           session monitor-enabled

           state up

       }

       172.16.1.2:http {

           address 172.16.1.2

           ratio 3

           session monitor-enabled

           state up

       }

   }

   monitor gateway_icmp

}


ltm node 172.16.1.1 {

   address 172.16.1.1

   ratio 2

   state up

}


ltm node 172.16.1.2 {

   address 172.16.1.2

   ratio 1

   state up

}

==========


One should expect to see pool member 172.16.1.1 (node ratio 2) getting twice as many connections as 172.16.1.2 (node ratio 1), despite the configured pool member's ratio being 3:1 for 172.16.1.2.

The pool member ratio value is used by the ratio(member) load balancing method.
