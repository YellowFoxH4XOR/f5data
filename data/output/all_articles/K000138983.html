Description

There is often a need to access and manage system-level SNMP information programmatically for effective network management and monitoring. This article provides guidance on how to access and modify SNMPv2-MIB:system objects, such as sysLocation, sysContact, sysName, and others, using RESTCONF/API on F5OS.

Environment

  • F5OS
  • SNMP

Cause

While SNMP management information bases (MIBs) are typically accessed via SNMP protocol operations, there are scenarios where RESTCONF/API might be preferred for integration with modern orchestration tools or for simplifying automation workflows.

Recommended Actions

To retrieve SNMPv2-MIB:system information via RESTCONF/API, use the following curl command syntax:

curl -sku <username:password> -H "Content-Type: application/yang-data+json" https://<management IP address>:8888/restconf/data/SNMPv2-MIB:SNMPv2-MIB/system | jq -S '.'

The curl command should return an output similar to the following example:

{
  "SNMPv2-MIB:system": {
    "sysContact": "A gang of otters <otters@example.com>",
    "sysDescr": "Linux 3.10.0-1160.71.1.F5.1.el7_8.x86_64 : Appliance services version 1.7.0-8741",
    "sysLocation": "A pool of water",
    "sysName": "gallery-r5900-R85-S35",
    "sysORLastChange": 10,
    "sysObjectID": "1.3.6.1.4.1.12276.1.3.1.1",
    "sysServices": 72,
    "sysUpTime": 97132032
  }
}

Note: Replace the <management IP address> placeholder with the MGMT IP address of your F5OS device. Similarly replace <username:password> with the username and password of your F5OS device.

 

To modify an SNMPv2-MIB:system object, such as sysLocation, use a PATCH request as shown in the following curl command syntax:

curl -sku <username:password> -H "Content-Type: application/yang-data+json" -X PATCH https://<management IP address>:8888/restconf/data/SNMPv2-MIB:SNMPv2-MIB/system -d '{"system":{"sysLocation": "multiple pools of water"}}'

The curl PATCH command is not expected to return an output.

 

After executing the curl PATCH request, you can verify the change by running the curl GET command again as shown above.

curl -sku <username:password> -H "Content-Type: application/yang-data+json" https://<management IP address>:8888/restconf/data/SNMPv2-MIB:SNMPv2-MIB/system | jq -S '.'

The curl command should return an output similar to the following example:

{
  "SNMPv2-MIB:system": {
    "sysContact": "A gang of otters <otters@example.com>",
    "sysDescr": "Linux 3.10.0-1160.71.1.F5.1.el7_8.x86_64 : Appliance services version 1.7.0-8741",
    "sysLocation": "multiple pools of water",
    "sysName": "gallery-r5900-R85-S35",
    "sysORLastChange": 10,
    "sysObjectID": "1.3.6.1.4.1.12276.1.3.1.1",
    "sysServices": 72,
    "sysUpTime": 97137999
  }
}

Additional Information

To be able to perform API calls like these, make sure your IP that will be performing these to F5OS is within the Allowed-IP range on F5OS.

Here is how to add it:

  • Configure the Allow List on the F5 rSeries system
  • Configure the Allowed IP Addresses on the VELOS system (f5.com)
