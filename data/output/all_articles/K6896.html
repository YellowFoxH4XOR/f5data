Known Issue

This is the result of a known issue. If the BIG-IP LTM system sends a response to a client on a FastHTTP connection, and the first packet the BIG-IP LTM receives back from that client ACKs the entire response but contains an out-of-order payload, any further TCP sequence number processing for both client and server is incorrect.

F5 Product Development tracked this issue as CR70928, CR71147, and CR71149 and it was fixed in BIG-IP 9.1.3, 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
