Description

OAuth with Open ID is working. However, when we use refresh token to get new access token and ID token, it fails as the response from BIG-IP does not include ID token.

 

Extract the refresh_token from the previous request and use this to get an new tokens, run in the client similar to: 

curl --location 'https://<OAUTH_URL_FOR_TOKEN' \
  --header 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'Accept=application/json' \
  --data-urlencode 'client_id=<CLIENT_ID>' \
  --data-urlencode 'client_secret=<CLIENT_SECRET>' \
  --data-urlencode 'grant_type=refresh_token' \
  --data-urlencode 'scope=openid Email' \
  --data-urlencode 'refresh_token=<REFRESH_TOKEN>'

REPLY from BIG-IP APM:

{
 "access_token":"ACCESS_TOKEN",
 "expires_in":<SECONDS>,
 "token_type":"token_type",
 "scope":"Email openid",
 "refresh_token":"REFRESH_TOKEN"
 <<<---- no "id_token" included
}

 

Environment

  • BIG-IP APM
  • OAuth
  • OpenID
  • Refresh Token
  • ID token

 

Cause

  • F5 has not yet support ID token as part of token refresh.

NOTE: The purpose of an ID Token is to prove that a user is authenticated. Once authenticated there's typically no need to re-authenticate that user for the remainder of that session. Therefore, and according to the OpenID specs (further detail in the Additional Information), an Authorization Server can optionally return an ID Token back.

 

Recommended Actions

  • There is no workaround, and if this behavior is causing problems, please contact F5 Support.

 

Additional Information

In the case of refreshing, only the access token is necessary to send back. Please see:

  • OpenID Connect Core 1.0 incorporating errata set 2: 12.2.  Successful Refresh Response

"Upon successful validation of the Refresh Token, the response body is the Token Response of Section 3.1.3.3 except that it might not contain an id_token." (at this publication)
