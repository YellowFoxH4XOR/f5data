Note: For information about a known issue where the ARX system does not rediscover the new SPN when a resource group is moved to a new node, or the node changes as a result of a cluster failover, refer to K10840: The ARX system may not rediscover the SPN for a node in a Windows cluster.

When a share is enabled, the ARX system discovers the Service-Principal Name (SPN) of the filer. For virtual servers of a Windows cluster, each physical node in the cluster has an SPN. Additionally, there is an SPN for the virtual server if the virtual server is joined to the domain.

For Windows 2003 server, joining the virtual server to the domain is optional. The virtual server is joined to the domain when the Enable Kerberos Authentication option is selected for the virtual server. However, for Windows 2008 server, the virtual server is automatically joined to the domain.

The F5 recommended best practice is to join the virtual server to the domain and to configure the external filer on the ARX system with the SPN of the virtual server. For information about using the spn command to configure an SPN, refer to the ARX CLI Reference Guide.
