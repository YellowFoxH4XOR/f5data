Known Issue

This is the result of a known issue. If two or more non-floating self IP addresses are located on the same subnet as a VLAN with a SNAT or SNAT pool, and BIG-IP issues an ARP request for a device on the same subnet, the BIG-IP does not update the ARP table when it receives the reply. As a result, the BIG-IP does not route traffic correctly.

F5 Product Development tracked this issue as CR91867 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.3-14.3-HF3 issued for BIG-IP version 9.4.3. You may download this hotfix or a later version of this hotfix from the F5 Downloads site.
