K000138214: After upgrade GSLB configuration is missing on BIG-IP DNS

Type
Support Solution
Published
2024-02-07
Updated
2024-02-07
Applies to
  • BIG-IP
  • BIG-IP DNS: 16.1.4
Source
https://my.f5.com/manage/s/article/K000138214

Description

After reboot to volume with a new software version, BIG-IP cannot load gtm configuration.
 

In /var/log/gtm there are errors:

Jan 12 15:22:33 dns-bigip1.test Unexpected Error: Configuration cannot be saved unless mcpd is in the running phase. Save was canceled. See "show sys mcp" and "show sys service". If "show sys service" indicates that mcpd is in the run state, but "show sys mcp" is not in phase running, issue the command "load sys config" to further diagnose the problem.
Jan 12 15:22:33 dns-bigip1.test err gtmd[15109]: 011a0058:3: hookOnChild: tmsh config save exited with error code 1

The /var/log/ltm includes logs like below:

Jan 12 15:21:05 dns-bigip1.test err tmsh[13088]: 01420006:3: Loading configuration process failed.
Jan 12 15:21:05 dns-bigip1.test emerg load_config_files[13082]: "/usr/bin/tmsh -n -g -a load sys config partitions all gtm-only" - failed. -- Loading schema version: 14.1.5.4
Jan 12 15:21:06 dns-bigip1.test err mcpd[7900]: 01070678:3: Full gtm configuration load failed ( Original ).

 

When running "tmsh load sys config gtm-only verify" you got:

#tmsh load sys config gtm-only verify
Validating GTM system configuration...
/usr/local/gtm/include/gtm_base_region_isp.conf
/usr/share/monitors/gtm_base_monitors.conf
Validating configuration...
Loading schema version: 14.1.5.4
/config/bigip_gtm.conf
Loading schema version: 16.1.4.2
010712d2:3: DNSSEC Key Generation XX of key /Common/example.com-zsk is incomplete.
Unexpected Error: Validating configuration process failed.

Environment

  • BIG-IP DNS
  • DNSSEC configured

 

Cause

Configuration cannot be validated and loaded because bigip_gtm.conf contains DNSSEC key with 'generation' section which does not include 'private-text' and 'public-text' (private and public DNSSEC keys).

 

Due to previous failures, there may be generation section without DNSSEC keys.

ltm dns dnssec key /Common/example.com-zsk {
      algorithm rsasha256
      expiration-period 30:0:0:0
      generation {
              XX {
                     handle F1F65BFCACEBE388820DB8FF20827D2F 
              } 
              YY {
                    creator dns-bigip1.test
                    expiration 2024-02-04:15:26:19
                    handle C5367BABB457B9BC26A7A1907019F2DA
                    key-tag 53343
                    private-text ***scrubbed***
                    public-text ***scrubbed***
                    rollover 2024-01-26:15:26:19
              }
     }
     rollover-period 21:0:0:0
}

 

Recommended Actions

To solve the issue:

1) Remove the incorrect section using text editor of your choice.

 

In the given example, we need to remove 3 lines related to generation XX and after the change dnssec key should look like:

ltm dns dnssec key /Common/example.com-zsk {
      algorithm rsasha256
      expiration-period 30:0:0:0
      generation {
              YY {
                    creator dns-bigip1.test
                    expiration 2024-02-04:15:26:19
                    handle C5367BABB457B9BC26A7A1907019F2DA
                    key-tag 53343
                    private-text ***scrubbed***
                    public-text ***scrubbed***
                    rollover 2024-01-26:15:26:19
              }
     }
     rollover-period 21:0:0:0
}


2) Run tmsh load sys config gtm-only verify to check if there are no other issues.

 

3) If no errors appears, load configuration by running:

tmsh load sys config gtm-only
