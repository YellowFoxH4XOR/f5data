Description
By default, when creating a Certificate Signing Request (CSR) using the BIG-IP Configuration utility, the system uses the SHA256 hash algorithm to sign the CSR. The resulting digital signature allows the CA to trust that the CSR is valid and was submitted by your organization.

F5 recommends using the default hash algorithm to sign your CSR, however, if you want to use a stronger algorithm to sign your CSR you can do so using the OpenSSL utility.

Environment

  • CSR
  • Signature Hash Algorithm

Cause
By default, tmsh/GUI uses SHA256 as hashing algorithm while creating CSR file.

Recommended Actions

  1. Log in to the command line.

  2. Change directories to the /var/tmp directory.
    # cd /var/tmp

  3. Create a directory to store the SSL keys, certificates, and certificate requests.
    # mkdir /var/tmp/mySSL

  4. Generate a certificate request with the desired hashing algorithm like sha256, sha512, etc.
    # openssl req -new -nodes -newkey rsa:<key size in bytes> -config <custom config file> -keyout <FQDN>.key -out <FQDN>.csr -<hashing algorithm>   
    Example:
    openssl req -new -nodes -newkey rsa:1024 -config /var/tmp/mySSL/myssl.cnf -keyout /var/tmp/mySSL/www.example.com.key -out /var/tmp/mySSL/www.example.com.csr -sha512

  5. Verify the Signature Hash Algorithm by 
    # openssl req -noout -text -in <CSR> | grep 'Signature Algorithm'
    Example:
    openssl req -noout -text -in /var/tmp/mySSL/www.example.com.csr | grep 'Signature Algorithm'
    Output: Signature Algorithm: sha512WithRSAEncryption

Additional Information
For configuring SANs (subject alternative names), -reqexts req_ext needs to be added to the command in step 5 after adding the alternate names in myssl.cnf file. Please refer K11438.
