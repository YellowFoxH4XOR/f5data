Topic

FirePass offers the following two modes for cookie handling:

  • Block cookies mode
  • Pass through cookies mode

Block cookies mode

In block cookies mode, FirePass caches most web portal cookies on the FirePass device. This behavior works for most applications; however, some do not work because client-side JavaScript or components must inspect cookies on the client. The maximum length and number of possible cookies is large because all cookies are stored on the Firepass device, not on the client. FirePass meets the requirements with block cookies mode, outlined in RFC2109: HTTP State Management Mechanism.

Pass through cookies mode

In pass through cookies mode, FirePass passes slightly modified cookies to the client from the web application. FirePass must pass through cookies to the server when client requests come in. FirePass must also accept its own session-ID cookies and simultaneously accept them from the client. Since the FirePass server limit is set to 8190 bytes for the entire header, only approximately 3000 to 5000 bytes for all cookies remain available, which is below the RFC recommended level. As a result, issues may occur when portal access applications use too many cookies. Users may receive an error message that appears similar to the following example:

Size of a request header field exceeds server limit.

Workaround

If your users report this error message, they can work around this issue by consulting their browser's vendor documentation about how to clear all cookies.

Alternatively, you can add the web application URL to Portal Access: Web Applications: Content Processing: Global Settings: Do not block cookies at FirePass 1200, pass them to the browser for specified URL patterns section under Web Applications Global Settings.

Note: Adding URLs will require a service restart.
