Topic

You can install and use third-party Secure Sockets Layer (SSL) certificates that are signed by another party such as Verisign, Thawte, or Comodo. Additionally, third-party certificates can be correctly verified when communicating with BIG-IP GTM 9.3.0 or later.

Note: This article only applies to BIG-IP LTM 9.1.0 through 9.1.2, and 9.2.0 through 9.2.5, with BIG-IP GTM versions supporting third-party SSL certificates. For BIG-IP LTM 9.3.0 and later, refer to the Authenticating with SSL Certificates Signed chapter of the BIG-IP Global Traffic Manager and Link Controller Implementations Guide. This functionality was introduced in BIG-IP GTM 9.3.0 and 9.4.2. Additionally, you can refer to the following articles for more information about third-party certificates:

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  • K7717: BIG-IP DNS and Link Controller support for third-party SSL certificates  
  • K7548: The big3d agent -c option fails to load the certificate level
  • K6996: The trusted device certificate is imported to the incorrect file

Important: This article only applies to configurations where the BIG-IP GTM system communicates with the BIG-IP LTM system and is configured to use third-party SSL certificates. If you do not have the BIG-IP GTM versions defined above, the BIG-IP GTM system will be unable to communicate with the BIG-IP LTM system because the BIG-IP GTM system will be unable to validate the SSL certificate chain.

Verifying the version of the big3d process that is currently installed on the BIG-IP LTM system

  1. Log in to the command line.
  2. Verify the version of big3d installed on the BIG-IP LTM system is version 9.3.0 by typing the following command:

    big3d -v

Note: If the version reported is not version 9.3.0, you must run the big3d_install script from the BIG-IP GTM device to install big3d 9.3.0 on the BIG-IP LTM device.

Installing big3d version 9.3.0

Note: This procedure is only required if big3d version 9.3.0 has not been installed.

  1. Log in to the BIG-IP GTM command line.
  2. At the prompt, use the following command syntax:

    big3d_install <ip addresses>

    For example:

    big3d_install 192.168.5.10 192.168.5.11 10.10.5.20 10.10.5.21

  3. Press the Enter key to run the script.

Note: This script instructs the BIG-IP GTM system to connect to each BIG-IP system that you specified by IP address. As it connects to each system, it prompts you to supply the appropriate logon information to access that system.

When the script has completed its operations, the following changes take effect on each BIG-IP system:

  • The SSL certificates are exchanged between each system, which authorizes communication between each system.
  • The big3d agent on each system is upgraded to the same version that is installed on the BIG-IP GTM system.

Importing the CA certificate to BIG-IP LTM 9.1.0 through 9.1.2

Note: The CA certificate must be in PEM format.

  1. Upload the CA certificate to the BIG-IP LTM system as outlined in K175: Transferring files to or from an F5 system.
  2. Log in to the BIG-IP LTM command line.
  3. Add the CA certificate to the big3d client certificate file by using the following command syntax:

    cat <path to CA certificate> >> /config/big3d/client.crt

    For example:

    cat /var/tmp/CAchain.pem >> /config/big3d/client.crt

Importing the CA certificate to BIG-IP LTM 9.2.0 through 9.2.5

You can import the certificate using the command line or the Configuration utility.

Note: The CA certificate must be in PEM format.

Importing using the command line

  1. Upload the CA certificate to the BIG-IP LTM system as outlined in K175: Transferring files to or from an F5 system.
  2. Log in to the BIG-IP LTM command line.
  3. Add the CA certificate to the big3d client certificate file by using the following command syntax:

    cat <path to CA certificate> >> /config/big3d/client.crt

    For example:

    cat /var/tmp/CAchain.pem >> /config/big3d/client.crt

Importing using the Configuration utility

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Select System.
  3. Select Device Certificates.
  4. Click the Trusted Device Certificates tab.
  5. Click Import.
  6. Select Paste Text.
  7. Select Append from the Import Method menu.

    Note: The Import Method menu may be unavailable and set to Replace when trusted device certificates are not specified. This behavior is generally observed on BIG-IP LTM 9.2.2 through 9.2.5 because the Configuration utility cannot find the file. For more information about this issue, refer to K6996: The trusted device certificate is imported to the incorrect file.

  8. Paste one of the certificates from the signing chain into the text field.
  9. Click Import.
  10. Repeat steps 5 through 9 for any other certificates in the signing chain.
  11. Move the trusted device certificates to the proper file.

    Note: For information about how to move the trusted device certificates to the proper file, refer to K6996: The trusted device certificate is imported to the incorrect file.

Modifying the big3d startup script to allow big3d to properly follow the SSL certificates chain depth

  1. Log in to the BIG-IP LTM command line.
  2. Make a backup of the big3d startup script file by typing the following command:

    cp /etc/bigstart/scripts/big3d /etc/bigstart/scripts/big3d.original

  3. Using a text editor, edit the /etc/bigstart scripts/big3d file.
  4. Locate the following line based on the version of BIG-IP LTM that you are using:

    BIG-IP LTM 9.1.0 - 9.1.2

    exec /usr/sbin/big3d -f

    BIG-IP LTM 9.2.0 - 9.2.5

    exec /usr/sbin/big3d

  5. Change the line based on the version of BIG-IP LTM that you are using:

    BIG-IP LTM 9.1.0 - 9.1.2

    exec /usr/sbin/big3d -c <signing chain length> -f

    BIG-IP LTM 9.2.0 - 9.2.5

    exec /usr/sbin/big3d -c <signing chain length> -c <signing chain length>

    Note: Due to a known issue, the signing chain length command -c must be used twice. For more information, refer to K7548: The big3d agent -c option fails to load the certificate level.

    Note: Replace the <signing chain length> string with a value between 0 (zero) and 9 that inclusively represents the number of certificates in the signing chain length. For a BIG-IP GTM system that uses a self-signed certificate, the value would be 0 (zero), which is the default value. For a BIG-IP GTM certificate that is directly signed by the root CA, the value would be 1 or greater. For a BIG-IP GTM certificate that is signed by a CA that is signed by the root CA, the value would be 2 or greater.

Restarting the big3d process

After you are finished importing the CA certificate, you must restart the big3d process, so it can read the signing chain length and the SSL certificate. To do so, type the following command:

bigstart restart big3d
