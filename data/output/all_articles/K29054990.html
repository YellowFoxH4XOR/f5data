K29054990: SNMP report via SNMPv3 failing after user credential change

Type
Support Solution
Published
2021-04-30
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.X.X, 14.0.X, 14.1.5, 14.1.4, 14.1.3, 14.1.2, 14.1.X, 14.0.1, 14.0.0, 14.1.0
Source
https://my.f5.com/manage/s/article/K29054990

Description

After adding a new SNMPv3 user, BIG-IP fails to send a report. Below logs can be seen in /var/log/snmpd.log: 

  • snmpd: send_trap: USM unknown security name (no such user exists)
  • Authentication failed for [username]
  • Reconfiguring daemon

Environment

  • SNMPv3 configured on BIG-IP

Cause

New SNMPv3 user added with complex password. 

Recommended Actions

Check below steps in case of above errors: 
  1. Ensure the authKey and prviKey set in BIG-IP and monitoring tool  match.
  2. Use simple password for the user added without any special characters. 
  3. Restart snmpd service using below command: 
    Impact of workaround: Performing the following procedure should not have a negative impact on your system.
    bigstart restart snmpd

Additional Information

None.
