Topic

You should consider using these procedures under the following condition:

  • You want to troubleshoot issues with HTTP/3 over QUIC by capturing and analyzing packet traces.

Description

Beginning in BIG-IP 15.1.0.1, F5 introduced the HTTP/3 and QUIC profiles as experimental features.

Beginning in BIG-IP 15.1.1 and BIG-IP 16.1.0, BIG-IP supports QUIC and HTTP/3 draft-ietf-quic-http-27 and draft-ietf-quic-http-28 . For more information, refer to ID 915713.

The HTTP/3 network protocol is the next major version of the Hypertext Transfer Protocol succeeding HTTP/2. HTTP/3 over QUIC uses the User Datagram Protocol (UDP), so the procedures for capturing and analyzing the packet traces may differ from communications using the TCP protocol.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You can reproduce the issue to collect a packet capture.
  • You have a client system with Wireshark 3.2.0 or later installed.
  • You have root user access to the BIG-IP system.

Procedures

Using the tcpdump command and Wireshark to capture and analyze traffic

You must have Wireshark 3.2.0 or later to load the SSL secrets to decrypt the SSL traffic. When troubleshooting issues with HTTP/3 over QUIC, you will first run the tcpdump command to capture SSL traffic and then use the Wireshark application to decrypt and analyze traffic. To do so, perform the following procedures:

  • Capturing SSL traffic and generating the handshake secret on the BIG-IP system
  • Loading the SSL secret on Wireshark

Capturing SSL traffic and generating the handshake secret on the BIG-IP system

To use the tcpdump command to capture traffic on the BIG-IP system and generate its handshake secret, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Change the directory to /var/tmp by entering the following command:

    cd /var/tmp

  3. Use an editor, such as vi, to create an Advanced Shell (bash) script by entering the following:

    #!/bin/bash
     
    OUTPUT=$(tcpdump -r $1 2>/dev/null)
     
    ES=$(echo $OUTPUT | grep -P '1.3ES:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3ES:\([^ ]*\).*$/\1/')
    HSC=$(echo $OUTPUT | grep -P '1.3HSC:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3HSC:\([^ ]*\).*$/\1/')
    HSS=$(echo $OUTPUT | grep -P '1.3HSS:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3HSS:\([^ ]*\).*$/\1/')
    APPC=$(echo $OUTPUT | grep -P '1.3APPC:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3APPC:\([^ ]*\).*$/\1/')
    APPS=$(echo $OUTPUT | grep -P '1.3APPS:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3APPS:\([^ ]*\).*$/\1/')
    CR=$(tcpdump -r $1 2>/dev/null | grep -P '1.3CR:(?!0000000000000000)' | head -n1 | sed 's/^.*1.3CR:\([^ ]*\).*$/\1/')
     
    cat << EOF > ssl-secret.log
    CLIENT_EARLY_TRAFFIC_SECRET $CR $ES
    CLIENT_HANDSHAKE_TRAFFIC_SECRET $CR $HSC
    SERVER_HANDSHAKE_TRAFFIC_SECRET $CR $HSS
    CLIENT_TRAFFIC_SECRET_0 $CR $APPC
    SERVER_TRAFFIC_SECRET_0 $CR $APPS
    EOF
     
    echo "Wrote ssl-secret.log"

  4. Save the file using the following file name:

    /var/tmp/gensecret

  5. Add execution permission to the file by entering the following command:

    chmod u+x /var/tmp/gensecret

  6. Enable SSL key logging via tcpdump by entering the following command:

    tmsh modify sys db tcpdump.sslprovider value enable

  7. Start a tcpdump capture on the BIG-IP system by entering the following command:

    tcpdump -ni 0.0:nnn -s0 --f5 ssl:v udp or icmp -vvv -w /var/tmp/quic.pcap

  8. Pass QUIC traffic to the BIG-IP system by reproducing the issue.
  9. Stop the capture.
  10. To generate the SSL secrets, enter the following command:

    /var/tmp/gensecret /var/tmp/quic.pcap

  11. Verify that the secrets are generated by entering the following command:

    cat /var/tmp/ssl-secret.log

    If no secrets are generated, repeat the procedure from step 6 again. You may need to restart and clear your browser's cache.

  12. To revert the change in step 5 and disable SSL key logging via tcpdump, enter the following command:

    tmsh modify sys db tcpdump.sslprovider value disable

Loading the SSL secret on Wireshark

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Copy the two files, ssl-secret.log and quic.pcap, generated in the previous procedure to your client system.
  2. Open the Wireshark application.

    Note: You need Wireshark 3.2.0 or later.

  3. Go to Edit > Preferences > Protocols > TLS.
  4. For the (Pre)-Master-Secret log file name, select Browse and locate the ssl-secret.log file.
  5. Go to Edit > Preferences > Protocols > QUIC.
  6. For QUIC UDP port, enter the port number of your BIG-IP virtual server.
  7. Select Ok.

    The quic.pcap file is decrypted.
