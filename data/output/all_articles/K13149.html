Known Issue

Websites that contain JavaScripts may become unresponsive when accessed through a Portal Access favorite using the Firefox browser. This issue occurs when the user enters the window.opener command within a JavaScript. The Firefox browser defines the window.opener command again after it has already been called, which leads to an infinite loop.

This issue occurs when all of the following conditions are met:

  • The website contains a JavaScript that uses the window.opener command
  • The user accesses the website through a Portal Access favorite
  • The user attempts to connect to the favorite using the Firefox browser

Impact

The user will be unable to load the website correctly.

Symptoms

As a result of this issue, the user may encounter the following symptoms:

  • The user may receive an error message indicating that the script is unresponsive.

    For example:

    A script on this page may be busy, or it may have stopped responding. You can stop the script now, or you can continue to see if the script will complete
  • The website content may fail to load correctly. For example, only portions of the page may load or the website may fail to load entirely.

Workaround

To work around this issue, you request users to employ a different supported browser, such as Internet Explorer or Safari. Alternatively, you can use a sed script to properly handle the window.opener javascript command. To do so, perform the following procedure:

Impact of workaround: Minimal decrease in performance. Most likely undetectable

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Portal Access : Web Applications : Content Processing.
  3. Click the Add New Favorite link.
  4. Enter a name for the script in the Processing script name field.

    For example:

    FireFox window.opener Script
  5. Enter the following content in the URL match patterns field:

    */ps/cache/PT_SAVEWARNINGSCRIPT_empty_11.js*
  6. Enter the following content in the Content Type field:

    javascript
  7. Enter the following content in the sed processing script field:

    s@F5_Invoke_open(\[0x6f,0x70,0x65,0x6e\],F5_window,tgturl, target, ((target\.toLowerCase() == '_blank') ? openNewWindowOption : ''));@F5_Invoke_open([0x6f,0x70,0x65,0x6e],F5_window,tgturl, target, ((target.toLowerCase() == '_blank') ? openNewWindowOption : ''));if(typeof(window.opener) !== 'undefined') window.opener = null;@
  8. From the Processing drop-down menu, select Post-process response data (after content patching).
  9. Click the Add New button.
