Description
Unexpected HTTP request chunking. 

HTTP requests with a payload (such as POST request) are always chunked by BIG-IP regardless of the Request Chunking setting on the HTTP profile.

Environment

  • HTTP profile
  • Stream profile

Cause
The Stream profile always forces HTTP payloads to be chunked, since it can change the content in-flight and cannot guarantee the length will not change.

This behavior was introduced in TMOS v15.0.0 to resolve Bug 248424.

Recommended Actions

If you have a server that cannot handle chunked request bodies and the stream profile replacement is not needed for requests, you may disable the stream profile on requests using an iRule such as the following: 
when HTTP_REQUEST { 
    STREAM::disable 
} 
when HTTP_RESPONSE { 
    STREAM::enable 
}

You may wish to use a more advanced iRule to selectively enable the Stream profile only for certain response types; reference K39394712: Overview of the Stream profile for further details.

    Additional Information
    HTTP v1.1 requires that servers tolerate requests using chunked transfer-encoding. In most conditions there should be no negative impact from this behavior.
