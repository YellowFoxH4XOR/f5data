Known Issue

The BIG-IP APM system may fail to process traffic when using Kerberos authentication.

This issue occurs when all of the following conditions are met:

  • There are two virtual servers with access policies configured for Kerberos Request-Based Authentication (RBA).
  • Traffic is processed on a virtual server that differs from the one where the session was initiated.
  • The access policy of the virtual server where the traffic was initiated is configured with a domain cookie.

Impact

Users are unable to access content through the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are successfully authenticated through the BIG-IP APM system, however, they are unable to access the application content.
  • The apmd process produces a core file in /shared/core/.

    For example:

    apmd.bld637.0.core.gz

Workaround

To work around this issue, you can either disable RBA or remove the domain cookie on the originating access policy. To do so, perform the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Disabling RBA on the originating access profile

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Access Profiles Lists.
  3. Open the visual policy editor by clicking Edit to the right of the originating access profile name.
  4. Select the Kerberos Auth action.
  5. Set the Request Based Auth property to Disable.
  6. Click Save.
  7. Click Apply Access Policy.

Removing the domain cookie on the originating access profile

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Access Profiles Lists.
  3. Click the name of the originating access profile.
  4. Select the SSO/Auth Domain tab.
  5. Remove the value of the Domain Cookie.
  6. Click Update.
  7. Click Apply Access Policy.
