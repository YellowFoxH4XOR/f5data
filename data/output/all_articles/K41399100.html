Topic

When you use multicast traffic, you can simultaneously send a single packet to multiple destination devices. IPv6 uses multicast addresses to define groups of devices (multicast groups). You use a unicast source address to send multicast packets to the multicast destination address.

Unlike an IPv4 broadcast, in an IPv6 multicast, each service uses a unique multicast address to communicate to a range of IPv6 devices. To view common IPv6 multicast addresses, refer to the Standard IPv6 Multicast addresses section of this article.

When you configure your BIG-IP devices for one of the following dynamic multicast routing protocols, they can process IPv6 multicast for various routing scenarios:

  • Protocol-Independent Multicast–Dense Mode (PIM-DM)
  • PIM-Sparse Mode (PIM-SM)
  • Multicast Listener Discovery version 2 (MLDv2)

Note: PIM-SM support is available in BIG-IP 12.1.0 and later versions.

By default, the BIG-IP system does not process IPv6 multicast traffic, unless you specifically configure it to do so. To view the routing protocols that the BIG-IP system supports, refer to K6654: Routing protocols and extensions included in the BIG-IP Advanced Routing Module.

Important: You must have the BIG-IP Routing Bundle add-on license (available for BIG-IP 12.0.0 and later) for the BIG-IP device to participate as a IPv6 router for multicast. The BIG-IP system does not support IPv6 multicast through a virtual server. You can use a subset of the IPv6 multicast functionality through a virtual server when you use a wildcard forwarding virtual server and configure the BIG-IP system with PIM-DM advanced routing (requires a BIG-IP Routing Bundle add-on license). You typically use this configuration for video stream multicast routing functionality and use the MLDv2 protocol for IPv6.

You can configure the BIG-IP device to forward multicast packets in Switch mode by enabling the TM.AllowMulticastL2DestinationTraffic system database variable.

The IPv6 multicast address

The first 16 bits of the multicast address-block specify an IPv6 multicast address, which is an identifier for a group of interfaces. The interfaces may belong to any number of multicast groups.

IPv6 multicast address format

Bits844112
Field namePrefixFlagsScoreGroup ID

Prefix

A prefix value of FF/ff or 11111111 (eight-ones) signifies that the address is a multicast address.

Flags

The Flags field is 4 bits, and the system can set four available flags for a multicast address.

Flag NameSet to: 0Set to: 1
0Not in useCurrently not in use.Currently not in use.
1RendezvousThe system does not embed the multicast rendezvous point with a multicast address.The system embeds the multicast rendezvous point with a multicast address.
2PrefixThe multicast address is not based on a network prefix.The multicast address is based on a network prefix.
3TransientThe multicast address is a permanently assigned (well-known) multicast IPv6 address.The multicast address is a transient (dynamically assigned) multicast address.

Scope

The Scope field is 4 bits, and routers use it to determine whether they can forward the multicast packet.

ScopeDescription
1The interface—Local scope spans a single interface only.
2Link—Nodes use local addresses when communicating with neighboring nodes on the same link.
4Admin—Local scope is the smallest administratively configured scope that the system does not automatically derive from physical connectivity.
5The scope of a site—Local address is the site or organization internetwork.
8The intention for this scope is that it spans multiple sites belonging to a single organization.
EThe system uses global scope to uniquely identify interfaces anywhere in the Internet.

Group ID

The remaining 112 bits of the address make up the multicast group ID.

The group ID can be a 32-bit media access control (MAC) address based on the Extended Unique Identifier (EUI) format for how a system creates a link local IP address based on MAC.

L2 multicast (multicast bridging)

Multicast bridging is the propagation of multicast frames on the local network. Layer 2-only (L2) switches handle L2 multicast traffic as though it is L2 broadcast traffic, flooding the multicast frames to all active interfaces in the same Virtual Local Area Network (VLAN). Layer 2/Layer 3 (L2/L3) hybrid switches typically implement Internet Group Management Protocol (IGMP) snooping to monitor multicast group membership messages. Then, they selectively forward multicast frames to only those interfaces through which multicast group join messages have been seen.

Protocols such as OSPF, Hot Standby Router Protocol (HSRP), and VRRP rely upon L2 multicast bridging (as do many firewalls and other redundant network devices) to ensure full mesh communication with related devices in the local network.

The BIG-IP LTM system as a multicast bridge

By default, the BIG-IP LTM system functions as an L2-only switch, flooding frames addressed to L2 multicast addresses across all interfaces in the VLAN, except the origin. You can customize this behavior to support specific L2 multicast traffic management requirements.

Note: You may need to enable the TM.AllowMulticastL2DestinationTraffic system database variable in order for the BIG-IP system to monitor FTP service that resides on a host with an L2 multicast address.

Multicast traffic and Auto Lasthop

The BIG-IP LTM system’s Auto Lasthop feature uses the MAC address from the Ethernet header as the destination MAC for response traffic, even if the sender specified a multicast response address in the payload, which may prevent all intended recipients from receiving the response. Disable Auto Lasthop if it interferes with L2 multicast response forwarding in this manner.

Accepting frames with L2 multicast source address

Although frames with L2 multicast source addresses do not conform to the IEEE 802.3 standard, some redundant or clustered devices are known to send them. You can configure the BIG-IP LTM system to accept frames sourced from multicast and/or unicast addresses by setting the tm.allowethernetsourcetype database variable to either unicast-multicast or any.

The tm.allowethernetsourcetype database variable accepts the following values:

ValueDescription
unicastThe BIG-IP system only processes frames with unicast source MAC addresses (default value).
unicast-multicastThe BIG-IP system only processes frames with unicast or multicast source MAC addresses.
any The BIG-IP system processes frames with any type of source MAC address (including broadcast source MAC addresses).

Multicast traffic and VLAN groups

When multicast traffic must traverse a VLAN group, you may have to modify the default BIG-IP LTM system configuration to support the intended traffic flow. The BIG-IP system may have the tm.allowmulticastl2destinationtraffic database variable enabled, forcing the BIG-IP system to flood frames addressed to L2 multicast addresses across all interfaces in all VLANs in the VLAN group, except the origin.

This setting is required to support any multicast traffic across a VLAN group, including multicast responses to unicast requests. For example, the system may construct an Address Resolution Protocol (ARP) request using a unicast L2 source address in the Ethernet header but advertise a multicast target MAC address in the payload. The system uses the target MAC address in the payload as the destination for the response, resulting in a multicast response to a unicast request. When tm.allowmulticastl2destinationtraffic is not enabled, the system does not bridge the response across the VLAN group. Enabling this variable allows the BIG-IP LTM system to bridge the responses that use the advertised multicast address as the destination across the VLAN group.

L3 multicast (multicast forwarding and routing)

Multicast forwarding is the intelligent forwarding of multicast datagrams to other networks. In multicast forwarding, a router forwards L3 multicast traffic to other networks where multicast nodes are listening, and prevents the forwarding of multicast traffic to networks where there are no nodes listening. For multicast forwarding to work across an internetwork, the participating nodes and all intervening routers must be multicast-capable.

Multicast routing is the propagation of multicast group listening information to other multicast routers to create loop free data paths only to interested subscribers. In multicast routing, a router propagates relevant multicast subscription information to other multicast routers, adding and deleting multicast group memberships as requested by way of the established multicast routing protocol (that is: PIM, IGMP).

Note: For more information about the IPv6 Gateway module refer to K13013: Overview of IPv6 Gateway Module and Advanced Routing Module. To enable the BIG-IP Advanced Routing Module (BIG-IP ARM), you must purchase an additional license key, depending on your version of BIG-IP software. For more information, contact F5 Technical Support.

The BIG-IP LTM system as a multicast router

A multicast-capable router must be able to perform the following forwarding and routing functions:

  • Listen for all multicast IP datagrams on all attached networks, and then upon receiving a multicast datagram, forward it to attached networks with listening nodes and to downstream routers with listening nodes.
  • Listen for group membership messages and update the IP multicast forwarding table.
  • Use a multicast routing protocol to propagate multicast group listening information to other multicast-capable routers.

Beginning in BIG-IP 12.0.0, the BIG-IP system supports both PIM-DM and IGMP for multicast routing. BIG-IP 12.1.0 adds support for PIM-SM and PIM-Sparse-Dense Mode (PIM-SMDM); however, the new feature does not support BIG-IP systems in the role of a rendezvous point for PIM-SM. You can implement the Multicast Routing feature with a dynamic routing bundle license and a multicast routing bundle license using the BIG-IP ARM. In versions previous to BIG-IP 12.0.0, the BIG-IP system lacks the multicast routing protocol implementation required to selectively forward multicast IP datagrams or to exchange group membership information with other multicast routers, and thus you cannot consider it a multicast router.

With the new protocol support for multicast routing, you can configure the BIG-IP LTM system to forward multicast traffic with a wildcard forwarding virtual server. In versions previous to BIG-IP 12.0.0, the BIG-IP system does not support forwarding multicast traffic through virtual server or secure network address translation (SNAT)/NAT objects.

The BIG-IP LTM system as a multicast node

A multicast node is comprised of devices that are capable of managing their own participation in multicast routing by way of multicast-enabled hardware.

A multicast-capable node must be able to:

  • Send and receive multicast IP datagrams.

  • Register the multicast IP addresses to which the node is listening with local routers, enabling multicast IP datagrams to be forwarded to the network of the node.

    IP nodes use multicast routing protocols, such as IGMP, to notify local routers that they are listening on a specific IP multicast address for IP multicast traffic.

The BIG-IP LTM system is capable of sending and receiving multicast IP datagrams, but it lacks the IGMP implementation required to register group membership with local multicast routers, and thus you cannot consider it a multicast node.
