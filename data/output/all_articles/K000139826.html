K000139826: SWG handle HTTP non-CONNECT, and HTTPS with one wildcard virtual server

Type
Support Solution
Published
2025-05-29
Updated
2025-05-29
Source
https://my.f5.com/manage/s/article/K000139826

Description

You want to setup Secure Web Gateway with only one wildcard virtual server instead of the standard two to handle HTTP CONNECT, HTTP-non CONNECT, and HTTPS CONNECT traffic.

Environment

SWG deployment with port 80 wildcard virtual server and port 443 wildcard virtual server tunnel listeners.

Cause

By default (if deployed by iapp or followed the deployment guide), there will be two wildcard (0.0.0.0) virtuals one listening for HTTP CONNECT and one for HTTPS CONNECT.  The HTTP tunnel listener does not handle HTTP GET requests so an irule is needed to capture them (see K000139699).

Recommended Actions

This irule would make it so you don’t need the extra port 80 tunnel vip, and you can route non-connect http and connect https on the one tunnel wildcard vip:

iRules on the proxy VIP:


when HTTP_REQUEST {
  sharedvar proto
  if {[HTTP::header exists "Proxy-Connection"] and [HTTP::method] != "CONNECT"}{
  #setting sharedvar for disabling SSL on server side
  set proto "http"
  #Force HTTP traffic to tunnel VS
  virtual swg-explicit-tunnel-vs [HTTP::proxy addr] [HTTP::proxy port]
  }
}
 
iRules on the tunnel VIP:


when CLIENT_ACCEPTED {
 sharedvar proto
 if { ( [info exists proto] ) and ( ${proto} == "http" ) } {
  SSL::disable serverside
 }
}
 
Both HTTP non-CONNECT and HTTPS CONNECT traffic on the same tunnel VIP will work after this.
