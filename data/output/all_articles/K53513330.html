K53513330: After upgrading to v16.1.2.1, TCP::close in iRule is not working because HTTP response is not delivered to the client

Description


The TCP::close in iRule was working in BIG-IP version 15.x. However, it is not working after upgrading to BIG-IP version 16.1.2.1 because HTTP response is not delivered to the client

Example: 

when HTTP_REQUEST {

HTTP::respond 200 content "\
<html>
<head>
</head>
<body> The management application has moved to cloud.<br>
The connection details are available on this <a href=http://management.customer.com >Management Application page on The Cloud</a>
</body>
</html>
"\
noserver\
Pragma "no-cache" Cache-Control "no-cache, must-revalidate"\
Connection "Close"
TCP::close                                                                                        

}

Error message in /var/log/ltm;
Mar 2 08:49:07 slot1/Hostname err tmm[12041]: 011f0007:3: http_process_state_prepend - Invalid action:0x107061 clientside (10.xx.xxx.xxx:63764 -> 192.xxx.xxx.xxx:80) ((null connflow)) (Client side: vip=/HTTPRESPONSE_80_PROD profile=http addr=192.xxx.xxx.xxx port=80 rtdom_id=0 client_ip=10.xx.xxx.xxx)
 

Environment

  • BIG-IP LTM v16.1.2.1
  • iRule with HTTP::respond
  • iRule with TCP::close
     

Cause

Bug ID 1075205: Using TCP::close after HTTP::redirect/HTTP::respond causes HTTP response not to be delivered to the client.
 

Recommended Actions

Please remove TCP::close from the iRule: 

1. Log in to the BIG-IP Configuration utility.
2. Go to Local Traffic > iRules > iRule List.
3. Select iRule Name.
4. In Definition, please remove "TCP::close";

when HTTP_REQUEST {

HTTP::respond 200 content "\
<html>
<head>
</head>
<body> The management application has moved to cloud.<br>
The connection details are available on this <a href=http://management.customer.com >Management Application page on The Cloud</a>
</body>
</html>
"\
noserver\
Pragma "no-cache" Cache-Control "no-cache, must-revalidate"\
Connection "Close"
TCP::close                             <===== Please remove it

}


5. Click Update button.
 

Additional Information

None.
