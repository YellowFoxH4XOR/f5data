Description

Looking at a packet capture, it is found that the Radius server is responding to the "Access Request" messages after the timeout (3 seconds) has elapsed.

The response can be either "Access Reject" or "Access Accept", the BIG-IP doesn't have the connection active anymore, so hence the "Destination unreachable" response from the Big-IP
 
For example:

No.   Time                          Delta       Source        Destination    Src Port Dest Port   Protocol      Length         Info
15    2021-06-07 14:09:42.425082    0.029986    10.0.1.1      10.0.2.2       55105    1812        RADIUS        184            OUT s1/tmm5 : Access-Request id=80

The access request from the BIG-IP to the Radius server is sent in packet number 15, at 14:09:42, the response arrives in packet number 80, at 14:09:53, 11 seconds later:

No.   Time                          Delta       Source        Destination    Src Port Dest Port   Protocol      Length         Info
80    2021-06-07 14:09:53.804145    0.149062    10.0.2.2      10.0.1.1       1812     55105       RADIUS        86             IN  s1/tmm5 : Access-Reject id=80

So the Big-IP immediately replies in packet 81 with a "Destination unreachable (Port unreachable)" message:

No.   Time                          Delta       Source        Destination    Src Port Dest Port   Protocol      Length         Info
81    2021-06-07 14:09:53.804502    0.000357    10.0.1.1      10.0.2.2       1812     55105       ICMP          94             OUT s1/tmm5 : Destination unreachable (Port unreachable)



Environment

  • Remote Radius Authentication
  • Responses from Radius server are not being received in time

Cause

      Responses are received after the radius timeout has expired (default 3 seconds)

      From ICMP RFC 792:

      If, in the destination host, the IP module cannot deliver the datagram because the indicated protocol module or process port is not active, the destination host may send a destination unreachable message to the source host.

Recommended Actions

     Ensure the responses form the Radius server to Access requests does not exceed the Radius timeout setting (default 3 seconds)

Additional Information

K17403: Configuring RADIUS authentication for administrative users
