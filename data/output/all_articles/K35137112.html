K35137112: Determining the failover state of a BIG-IQ system using iControl REST

Type
Knowledge
Published

Applies to

Source

Topic

You should consider using this procedure under the following condition:

  • You want to determine the failover state of a BIG-IQ system in a high availability (HA) configuration using the iControl REST API.

Description

Other than the BIG-IQ user interface, another method to determine the failover state of a BIG-IQ system in an HA configuration is to use iControl REST. You can do so by sending a request to the /mgmt/shared/failover-state endpoint. You can limit the attributes that you want to display by specifying the attributes using the jq utility.

curl and jq utilities

Performing the following procedure requires that you have command line access to a system that has the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems, but you can also install them on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure from a BIG-IQ system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IQ system is licensed and configured with a management IP address.
  • You have administrative access to the BIG-IQ system interface.
  • You have command line access to a system with the curl and jq utilities. If your system does not have these utilities, you must use the BIG-IQ command line to perform the procedure.

Procedures

Querying the BIG-IQ system for its failover state

You can use the iControl REST API to query the BIG-IQ system for its failover state. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system that has the curl and jq utilities installed.
  2. Obtain a BIG-IQ authentication token.

    For more information, refer to K04452074: Overview of using the BIG-IQ system authentication token.

  3. To store the BIG-IQ authentication token, create a shell variable named f5token using the following command syntax:

    f5token=<BIG-IQ authentication token obtained in step 2>

    Note: The authentication token has a timeout of 300 seconds, so you may need to repeat this step. Alternatively, you can use the following command substitution syntax to assign the f5token variable:

    f5token=$(curl -ks -X POST -d '{"username":"admin", "password":"<password>"}' https://<BIG-IQ IP address>/mgmt/shared/authn/login | jq .token.token)

    • Replace <password> with the BIG-IQ system admin user password.
    • Replace <BIG-IQ IP address> with the BIG-IQ system management IP address.
  4. To query the failover state of the BIG-IQ system, use the curl utility and use the following syntax:

    curl -ks -H “X-F5-Auth-Token: $f5token” https://<BIG-IQ IP address>/mgmt/shared/failover-state | /usr/bin/jq -M .

    • Replace <BIG-IQ IP address> with the BIG-IQ system management IP address.

  5. If you want to limit the displayed attributes, you can specify the attributes using the jq utility.

    For example, you can find out the following information:

    • The HA role of the BIG-IQ system you are querying (.nodeRole)
    • The queried BIG-IQ system’s hostname and current state (.haStatus.primary.hostname and .haStatus.primary.nodeState)
    • The BIG-IQ HA’s existing auto failover mode (.useQuorumHA)
    • The BIG-IQ HA's current state (.haStatus.currentState)
    • The BIG-IQ HA peer’s availability, hostname, and current state (.haStatus.peerAvailable, .haStatus.secondary.hostname, and .haStatus.secondary.nodeState)

    To find out the information, modify the query from the previous step using the following syntax:

    curl -ks -H "X-F5-Auth-Token: "$F5TOKEN"" https://<BIG-IQ IP address>/mgmt/shared/failover-state | /usr/bin/jq '{Role: .nodeRole, PrimaryHost: .haStatus.primary.hostname, PrimaryState: .haStatus.primary.nodeState, AutoFailover: .useQuorumHA, HACurrentState: .haStatus.currentState, IsPeerAvailable: .haStatus.peerAvailable, SecondaryHost: .haStatus.secondary.hostname, SecondaryState: .haStatus.secondary.nodeState}'

    • Replace <BIG-IQ IP address> with the BIG-IQ management IP address.
