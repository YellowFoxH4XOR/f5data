K619: Configuring a 3-DNS controller to log a message when a virtual server is marked with a status of up

Topic

Without modification, syslogd will log a message to the /var/log/3dns file when a virtual server goes from green (up) to red (down). However, the 3-DNS Controller will not log a message when the virtual server goes from red (down) to green (up). Any change to the down status is logged at the .err level by local2 and any change to the up status is logged at the .notice level by local2.

Configuration

To configure the 3-DNS Controller to allow you to view both types of messages from the /var/log/3dns file, perform the following steps:

  1. Change the following section in the /etc/syslog.conf file:

     

    syslog.conf (default)
#
# 3DNS
#
local2.err         /var/log/3dns

    To read as follows:

    #
# 3DNS
#
local2.notice         /var/log/3dns
  2. Send a HUP signal to the syslogd process.
  3. To view the messages, grep the /var/log/3dns file for SMTP_TRAP (must be all caps).

Testing the configuration

To test this configuration, perform the following steps:

  1. From the Configuration utility, open the VS statistics page.
  2. Start a continuous tail on the /var/log/3dns file, by typing the following command:
    tail -f  /var/log/3dns &

    All new messages that are sent to /var/log/3dns will now be displayed immediately.

  3. Disable a virtual server so that it displays as red in the Configuration utility.

    You should then see an error message in the log file.

  4. Enable the virtual server so that it displays green in the Configuration utility.

    You should see a message appear in the syslog indicating that the virtual server is back up.
