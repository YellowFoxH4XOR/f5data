K000150846: TMM restart caused by iRules using large regexp or regsub commands

Type
Support Solution
Published
2025-04-16
Updated
2025-04-16
Source
https://my.f5.com/manage/s/article/K000150846

Description

The iRules regular expression commands: regsub and regexp can use significant resources when compiling the regular expression argument, if it is too long or complex.  If the regular expression takes too long to compile, it may cause TMM to restart.

 

Environment

  • BIG-IP
  • A regexp or regsub iRules command where the exp argument is very long (e.g. >10KB in length) or complex

Cause

This issue arises when iRules execute a regexp or regsub command with overly complex or lengthy regular expressions. These operations are computationally intensive and may exceed the TMM's processing capacity, resulting in significant performance degradation, memory exhaustion, and ultimately, a TMM crash.

You may also see following log message.

- Multiple clock advances will be logged in tmm logs.

- A message similar to the one below will be logged in tmm logs:

notice sod[9938]: 01140041:5: Killing tmm.0 pid <PID of tmm>.

Recommended Actions

F5 strongly recommends being very wary if you are trying to craft a regular expression from potentially untrustworthy data, such as HTTP header values, DNS FQDN’s, and packet payloads.  F5 strongly recommends determining the minimum necessary length that is required to implement the desired functionality and truncating any input strings to that length before submitting them as part of the regular expression.  F5 recommends keeping regular expressions under 10KB in length to avoid TMM restarts.
