K000163739: rndc: 'thaw' failed: permission denied

Type
Support Solution
Published
2026-10-15
Updated
2026-10-15
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163739

Description

After fixing errors reported by named-checkconf, specifically a missing zone file, running rndc thaw throws an error:

rndc: 'thaw' failed: permission denied

Error messages similar to this might appear in /var/log/audit:

type=AVC msg=audit(2026-10-14T17:33:21-03:4236167): avc: denied { open } for pid=3072 comm="named-checkconf" path="/config/namedb/db.external.example." dev="dm-13" ino=262530 scontext=system_u:system_r:zrd_t:s0 tcontext=unconfined_u:object_r:user_tmp_t:s0 tclass=file

Environment

  • BIG-IP DNS
  • An external zone file was copied from a functioning peer to the affected device.
  • zrd unable to startup properly 

Cause

A zone file manually copied over by following K000163417.

The copied external zone file retained an incorrect SELinux context, `user_tmp_t`, instead of the context permitted for BIG-IP DNS operation. SELinux therefore denies the `zrd`/`named-checkconf` process access to the file, causing the zone-load failure, `rndc thaw` permission error, and repeated `zrd` restarts.

Answer/Recommended Actions

Restore the expected SELinux contexts on the BIG-IP DNS configuration directory by running this command from bash:

# restorecon -R -v /var/named/config/

Additional Information

The error messages that lead to a manual copy of a zone file look like this:

zone example.com/IN: loading from master file db.external.example.com failed: file not found

zone example.com/IN: not loaded due to errors.

external/example.com/IN: file not found
