Description

IPsec is used to connect remote networks over an encrypted and authenticated tunnel. High Availability (HA) with mirroring additionally provides seamless failover of existing tunnels during an Active/Standby state transition of the BIG-IPs. This means that tunnels do not need to renegotiate when failover happens and established traffic is not interrupted. 

 

Environment

This article applies in the following conditions.

  • IKEv2 IPsec tunnels.
  • High Availability is configured.
  • Mirroring is enabled.
  • The BIG-IP terminates IPsec tunnels (it does not forward IPsec traffic between peers).

 

Cause

Seamless failover of IPsec traffic may not occur if incorrectly configured.
 

Recommended Actions

The following items must be configured.

  1. High Availability (HA) is configured with Active and Standby devices for the floating traffic-group.
  2. Mirroring is enabled.
  3. A floating IP on the BIG-IP is used to terminate the IPsec tunnel.
  4. Virtual Servers are configured to mirror traffic.

When points 1, 2 and 3 (above) are configured correctly, the IPsec tunnel will mirror IPsec Security Associations (SAs). This allows the newly Active device to take over the tunnel state. There is nothing specific to IPsec itself that needs to be configured as long as the BIG-IP terminates the IPsec tunnels on a floating IP.

Established user connections utilizing the IPsec tunnel may be lost. To avoid that, the Virtual Servers handling the private traffic should also be configured for mirroring.

The two common modes of IPsec are Interface and Tunnel. In Tunnel mode, the floating self IP is specified on the ipsec-policy (abridged example):

net ipsec ipsec-policy <policy name> {
    mode tunnel
    tunnel-local-address <floating self IP>
    tunnel-remote-address <remote peer IP>
}

This is " Tunnel Local Address" in the web UI / configuration utility (Network  ››  IPsec : IPsec Policies).

In Interface mode, the floating self IP is specified on the "tunnels tunnel" object (abridged example).

net tunnels tunnel <tunnel name> {
    local-address <floating self IP>
    remote-address <remote peer IP>
}

This is "Local Address" in the web UI / configuration utility (Network  ››  Tunnels : Tunnel List).
