Description

GTM pool member order is changed if we delete one of the member in the pool. If UCS is generated at this stage and try to load UCS file on other BIG-IP DNS device, the UCS configuration load will fail with error.

Environment

  • BIG-IP DNS 
  • GTM Pool 
  • GTM Pool member order

Cause

GTM pool member configuration changes like delete of member, can lead  to incorrect member order.

Recommended Actions

  1. In order to correct the member order of GTM pool members, reload the configuration by executing below command
     
    #tmsh load /sys config gtm-only 

    Impact of workaround: Performing a configuration reload on an active device group member may cause a service disruption of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.
     
  2. Then proceed to create UCS for restoration in another BIG-IP DNS device
 

Additional Information

  1. For example, in below configuration GTM pool test, if we have GTM pool with 2 members in pool, the order will  be  0 and 1. If we have 3 members in GTM  pool then the order will be 0,1 and 2 and this is right order.

    # list pool a test
    gtm pool a test {
        members {
            server1:server1_80 {
                member-order 1
            }
            server1:server1_443 {
                member-order 2
            }
            server1:server1_6443 {
                member-order 0
            }
        }

    Delete a member from this GTM pool
    # modify server server1 virtual-servers delete  { server1_80 }
     
  2. Order is incorrect after deletion of member
    # tmsh list pool a test
    gtm pool a test {
        members {
            server1:server1_443 {
                member-order 2
            }
            server1:server1_6443 {
                member-order 0
            }
        }
    }
  3. In order to correct the member order of GTM pool members, reload configuration by executing below command
    # tmsh load /sys config gtm-only
  4. Once configuration is reloaded ,member order will show the right value.
    # tmsh list pool a test
    gtm pool a test {
        members {
            server1:server1_443 {
                member-order 1
            }
            server1:server1_6443 {
                member-order 0
            }
        }
    }
  5. Then proceed to collect UCS from device and proceed for restoration in another BIG-IP DNS device
