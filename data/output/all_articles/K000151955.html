Description

This Article describes how to  fully remove a user's session based on the result of the Per-Request Access Policy.

Environment

  • APM
  • Per-Request Access Policy
  • iRule event agent

Cause

N/A

Recommended Actions

The Access session can be removed using an iRule command ("ACCESS::session remove"), however this action cannot be performed while executing the Per-Request iRule event ("ACCESS_PER_REQUEST_AGENT_EVENT"). Directly calling "ACCESS::session remove" from within "ACCESS_PER_REQUEST_AGENT_EVENT" triggers a TCP reset from BIG-IP and browsers will usually just re-try their request, resulting in a loop of requests / resets.

In order to avoid this behavior, we can set a variable inside the "ACCESS_PER_REQUEST_AGENT_EVENT" event when the session needs to be removed, then process that removal ("ACCESS::session remove") during the "HTTP_REQUEST_SEND" event.

Additional Information

Here is an example iRule that will delete a user's session when it detects a request to "/deny.html" URL:

when ACCESS_PER_REQUEST_AGENT_EVENT {
  if { [HTTP::uri] == "/deny.html" } {
    set todelete 1
  }
}

when HTTP_REQUEST_SEND {
  if { [info exists todelete] && $todelete == 1 } {
    HTTP::respond 403 content "Access denied - session closed"   
    ACCESS::session remove
  }
}
