Topic

You should consider using this procedure under the following conditions:

  • You want to configure the BIG-IP system to form Border Gateway Protocol (BGP) neighbors for Exterior BGP (eBGP) multihop, and to exchange routing prefixes.
  • You want to verify BGP neighbor configurations, eBGP multihop configurations, and routing prefixes exchange on the BIG-IP system.

Description

The BIG-IP system supports Border Gateway Protocol 4 (BGP4) and BGP4+. RFC 1771 defines BGP as a dynamic routing protocol primarily used on the internet to exchange routing and reachability information among autonomous systems (AS). For an overview of BGP on the BIG-IP system, refer to K10168: Overview of BGP on the BIG-IP system. This article describes how to configure and verify the BIG-IP system to form BGP neighbors for eBGP multihop and redistribution.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP system is licensed for the BIG-IP Advanced Routing Module (BIG-IP ARM).
  • You have administrative access to the BIG-IP command line.

Configuring and verifying the BIG-IP system to form BGP neighbors

Two BGP routers become neighbors or peers after successfully establishing a TCP connection on port 179. These routers negotiate connection parameters and exchange routing updates. Internal Border Gateway Protocol (iBGP) is used when BGP runs between two peers in the same AS. External Border Gateway Protocol (eBGP) is used when BGP runs between peers in a different AS.

This implementation describes the procedures for configuring iBGP peering between BIG-IP A and BIG-IP B, and eBGP peering between BIG-IP B and BIG-IP C. For configuration instructions on third-party devices, refer to the manufacturer's documentation.

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Configuring the port lockdown settings of Self IP addresses

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Click the self IP on which you want to use BGP.
  4. For Port Lockdown, click Allow Custom (Include Default).
  5. For Custom List, click TCP and Port.
  6. For the port value, enter 179, then click Add.
  7. Click Update.
  8. Repeat steps 2 through 7 for all self IP addresses you want to configure with BGP.

Note: Allow Custom (Include Default) is recommended unless you are certain you will not need the default ports open, in which case you would use Allow Custom and add only the ports you want. For more information, refer to K17333: Overview of port lockdown behavior (12.x - 21.x).

Enabling BGP routing on BIG-IP A and BIG-IP B

  1. Enable the BGP on your route domain. For more information, refer to K13802: Enabling dynamic routing protocols for a route domain.
  2. Log in to the BIG-IP command line.
  3. Access the Integrated Management Interface (IMI) Shell (imish) by typing the following command:

    imish

    Note: imish is not accessible when the BIG-IP system is in the Force Offline mode.

  4. Enter Enable mode by typing the following command:

    enable

  5. Enter Configuration mode by typing the following command:

    config terminal

  6. Enable BGP routing and specify AS 200 by typing the following command:

    router bgp 200

  7. Exit Configuration mode by typing the following command:

    end

  8. Write the configuration by typing the following command:

    write

Enabling BGP routing on BIG-IP C

  1. Enable the BGP on your route domain. For more information, refer to K13802: Enabling dynamic routing protocols for a route domain.
  2. Log in to the BIG-IP command line.

Configuring iBGP peering on BIG-IP A

  1. Log in to the BIG-IP command line.
  2. Access imish  by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. Enter BGP routing Configuration mode in AS 200 by typing the following command:

    router bgp 200

  6. Specify BIG-IP B as an iBGP neighbor by typing the following command:

    neighbor 10.10.20.1 remote-as 200

  7. Enable the neighbor to exchange routing information by typing the following command:

    neighbor 10.10.20.1 activate

  8. Exit Configuration mode by typing the following command:

    end

  9. Write the configuration by typing the following command:

    write

Configuring and verifying the BIG-IP system for eBGP multihop

You can use eBGP multihop to form peer relationships and exchange messages between two BGP routers that are not directly connected. In the following example, BIG-IP A and BIG-IP C need to cross a non-BGP router to become eBGP neighbors.

Note: Connectivity should exist between BIG-IP A and BIG-IP C through static routes or an Interior Gateway Protocol (IGP).

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Configuring eBGP multihop on BIG-IP A

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. Enter BGP routing Configuration mode in AS 200 by typing the following command:

    router bgp 200

  6. Specify BIG-IP C as the eBGP neighbor by typing the following command:

    neighbor 160.10.20.2 remote-as 300
    neighbor 160.10.20.2 ebgp-multihop

  7. Exit Configuration mode by typing the following command:

    end

  8. Write the configuration by typing the following command:

    write

Configuring eBGP multihop on BIG-IP C

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. Enter BGP routing Configuration mode in AS 300 by typing the following command:

    router bgp 300

  6. Specify BIG-IP A as the eBGP neighbor by typing the following command:

    neighbor 10.10.20.2 remote-as 200
    neighbor 10.10.20.2 ebgp-multihop

  7. Exit Configuration mode by typing the following command:

    end

  8. Write the configuration by typing the following command:

    write

Verifying eBGP multihop on BIG-IP

Configuring and verifying the BIG-IP system to exchange routing prefixes

You can exchange network prefixes with BGP on the BIG-IP system with the network command or through redistribution.

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Exchanging network prefixes with the network command

You can use the network command to specify the network prefixes that the BIG-IP system will advertise.

Configuring BIG-IP D to originate its local subnet through BGP

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. Enter BGP routing Configuration mode in AS 100 by typing the following command:

    router bgp 100

  6. Specify BIG-IP C as the eBGP neighbor by typing the following command:

    neighbor 150.10.20.1 remote-as 300

  7. Advertise local subnet prefix 140.10.20.0/24 by typing the following command:

    network 140.10.20.0/24

  8. Exit Configuration mode by typing the following command:

    end

  9. Write the configuration by typing the following command:

    write

Verifying that BIG-IP D prefix is advertised through BGP

  1. Log in to the BIG-IP C command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Display the routing table by typing the following command:

    show ip route

    The command output displays that BIG-IP C learned the prefix 140.10.20.0/24 through BGP:

Exchanging network prefixes through redistribution

You can use redistribution to advertise IGP prefixes and static routes into BGP. Since all internal routes are dumped into BGP, you should apply careful filtering to ensure that only advertised prefixes are exchanged.

Configuring BIG-IP-B to redistribute OSPF and static routes into BGP

Note: BIG-IP A does not run BGP but advertises the prefix 130.10.20.0/24 through OSPF.

Note: BIG-IP B is configured with a static route to 175.10.20.0/24.

  1. Log in to the BIG-IP command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Enter Configuration mode by typing the following command:

    config terminal

  5. Enter the OSPF process by typing the following command:

    router ospf 10

  6. Redistribute OSPF prefixes into BGP with a metric of 12 by typing the following command:

    redistribute bgp metric 12

  7. Exit the router Configuration mode by typing the following command:

    exit

  8. Configure an access list to only permit prefixes 130.10.20.0/24 and 175.10.20.0/24 by typing the following command:

    access-list 1 permit 130.10.20.0 0.0.0.255

    access-list 1 permit 175.10.20.0 0.0.0.255

  9. Enter BGP routing Configuration mode in AS 200 by typing the following command:

    router bgp 200

  10. Redistribute static routes by typing the following command:

    redistribute static

  11. Specify BIG-IP C as the eBGP neighbor with a filter by typing the following command:

    neighbor 160.10.20.2 remote-as 300

    neighbor 160.10.20.2 distribute-list 1 out

  12. Exit Configuration mode by typing the following command:

    end

  13. Write the configuration by typing the following command:

    write

Verifying that IGP prefixes and static routes redistributed into BGP

  1. Log in to the BIG-IP D command line.
  2. Access imish by typing the following command:

    imish

  3. Enter Enable mode by typing the following command:

    enable

  4. Display the routing table by typing the following command:

    show ip route
