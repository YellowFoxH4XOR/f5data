K000160864: Private Key JWT client authentication on APM OAuth Client

Support Solution
Published
2026-04-19
Updated
2026-04-19
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source

Description

Private Key JWT (private_key_jwt) is an OpenID Connect client authentication method used by Relying Parties (Client) to authenticate to the OpenID Provider (Authorization Server) when using the Token Endpoint.

ID831857 was filed to support Private Key JWT on APM OAuth Client.

Check first with F5 Support team if ID831857 is implemented, otherwise you can follow this procedure as Proof of Concept

You will need to adapt this procedure to your Provider's requirements.

Environment

  • BIG-IP provisioned with APM
  • APM deployed as OAuth Client

Cause

With Private Key JWT client authentication, your OAuth Client creates a JWT and signs it using a private key and the Provider verifies the signature with the public key uploaded previously by you.

The JWT must contain the following required Claim Values:

iss (Issuer): This must contain the client_id of the OAuth Client.
sub (Subject): This must contain the client_id of the OAuth Client.
aud (Audience): This should be the URL of the Authorization Server's Token Endpoint.
jti (JWT ID): This is a unique identifier for the token, which can be used to prevent reuse of the token.
exp (Expiration): This is the time on or after which the JWT must not be accepted for processing.

And may contain the following optional Claim Value:

iat (Issued at): This is the time at which the JWT was issued.

The JWT may contain other Claims. Any Claims used that are not understood must be ignored.

The JWS token must be sent as the value of the "client_assertion parameter" parameter and the value of the "client_assertion_type" parameter must be "urn:ietf:params:oauth:client-assertion-type:jwt-bearer"

Those two parameters are sent in the POST OAuth Token request message along with the rest of parameters.
For example, this could be the OAuth Token request message in the Authorization Code Flow

POST /token HTTP/1.1
Host: server.example.com
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
  code=<code>&
  client_id=<client_id>&
  client_assertion_type=urn%3Aietf%3Aparams%3Aoauth%3Aclient-assertion-type%3Ajwt-bearer&
  client_assertion=<JWS>

Recommended Actions

You can verify that your Provider supports 'private_key_jwt' client authentication in the OIDC discovery endpoint (OpenID URI)

https://server.example.com/oauth2/default/.well-known/openid-configuration

"token_endpoint_auth_methods_supported": [
  "private_key_jwt",

Follow these steps to configure Private Key JWT client authentication on APM for the  Authorization Code Flow.

Create a private key and a self-signed certificate in PEM format and upload them to APM

Obtain the public key from the certificate and transform it to JWK format.

Check which is the Signature algorithm requested by your Provider and add this metadata to that JWK (kty, kid, use, alg and keys_ops). Set your own Key Id 'kid'. This 'kid' must match later the 'key-id' in your APM JWK.

The JWK public key you upload to your Provider should be like this

{
  "kty": "RSA",
  "kid": "client-key-v1",
  "use": "sig",
  "alg": "RS256",
  "n": "<...>",
  "e": "<...>",
  "key_ops": [
    "verify"
  ]
}

Create a JWK object (ie. /Common/private_key_jwt) that will be used in the irule. Replace previous CERTIFICATE and PRIVATE_KEY. 

apm oauth jwk-config private_key_jwt {
    alg-type RS256
    cert CERTIFICATE
    cert-key PRIVATE_KEY
    include-x5c yes
    jwt-type jws
    key-id client-key-v1
    key-type rsa
    key-use signing

Create a POST TOKEN_REQUEST with these parameters

apm aaa oauth-request {
    parameters {
        client_assertion {
            value "%{session.custom.privatejwt}"
        }
        client_assertion_type {
            value urn:ietf:params:oauth:client-assertion-type:jwt-bearer
        }
        grant_type {
            type grant-type
        }
        redirect_uri {
            type redirect-uri
        }
    }
    type token-request
}

Create an OAuth Provider, discovering the Provider's endpoints with the OpenID URI. Configure the rest of parameters.

Create an OAuth Server filling in the CLIENT_ID (from your app). You do not need a client-secret with Private Key JWT. Configure the rest of parameters.

Create an access policy adding an irule event and an OAuth Client agent after it, assigning previous TOKEN_REQUEST. Configure the rest of parameters.

apm policy agent irule-event {
    id private_key_jwt

apm policy agent aaa-oauth {
    openid-connect enabled
    token-request TOKEN_REQUEST

Add this irule to the Virtual Server, replacing CLIENT_ID and TOKEN_ENDPOINT ('Token URI' from oauth provider on APM). In this irule signing algorithm is RS256 and uses previous JWK "/Common/private_key_jwt".

when RULE_INIT {
    set static::claim_list_string { {sub} {aud} {jti}}
    set static::jwt_iss {CLIENT_ID}
    set static::jwt_sub {CLIENT_ID}
    set static::jwt_aud {TOKEN_ENDPOINT}
    set static::jwt_jti {jwtid_}
    set static::jwt_expires_in 10
}

proc gettimeofday {} {
    return [ clock seconds ]
}

proc generate_payload { claim_list_string } {
    set src_port [TCP::remote_port]
    set payload "\{"
    append payload {"iss":"} $static::jwt_iss {"}
    set iat [ call gettimeofday ]
    append payload {,"iat":} $iat
    append payload {,"exp":} [ expr { $iat + $static::jwt_expires_in } ]
    foreach claim $claim_list_string {
     switch $claim {
       "sub" {
           set value $static::jwt_sub
        }
        "aud" {
           set value $static::jwt_aud
        }
         "jti" {
           set value $static::jwt_jti$iat$src_port
        }
      }
     if { [ string length value ] == 0 } {
        continue
     }
     append payload {,"} $claim {":"} $value {"}
    }
    append payload "\}"
    return $payload
}

proc generate_jws {} {
    set payload [ call generate_payload $static::claim_list_string]
    return [ ACCESS::oauth sign -payload $payload -alg RS256 -key /Common/private_key_jwt -ignore-cert-expiry ]
}

when ACCESS_POLICY_AGENT_EVENT {
    if { [ACCESS::policy agent_id] eq "private_key_jwt" } {
      set jws [call generate_jws ]
      ACCESS::session data set session.custom.privatejwt $jws
     }
}
