K000160104: Clearing Persistent Fan and AOM Alarms After Hardware Replacement on F5OS rSeries

Type
Support Solution
Published
2026-02-20
Updated
2026-04-09
Applies to
  • F5OS
  • F5OS-A: 1.8.3
Source
https://my.f5.com/manage/s/article/K000160104

Description

After replacing a fan tray on F5OS rSeries platforms, hardware alarms for fan faults and AOM (Appliance Operations Manager) faults may persist even though:

  1. The hardware replacement was successful
  2. System health shows all fans operating normally with correct RPM readings

Environment

  • Hardware replacement completed
  • Alarms visible in 'show system alarms' with old timestamps that do not update

Cause

The alert-service is not receiving the clear event. This is tracked as bug alias 2225577: F5OS: Fan and AOM alarms persist after hardware RMA and cannot be cleared using standard docker alert-service commands.

Answer/Recommended Actions

The troubleshooting example is for a device with an AOM Fault and errors with fan 9 and fan 10.

Restart alert-service

# docker restart alert-service

This will clear any ZMQ issue.

Now try the clear commands:

# docker exec alert-service /confd/test/sendAlert -n "AOM Fault" -s "appliance" -r clear -se error -i 65543 -d "Fault detected in the AOM"

# docker exec alert-service /confd/test/sendAlert -n "HWfault" -s "fan-9" -r clear -se critical -i 65536 -d "Hardware device fault detected"

# docker exec alert-service /confd/test/sendAlert -n "HWfault" -s "fan-10" -r clear -se critical -i 65536 -d "Hardware device fault detected"
