Topic

This article applies to BIG-IP 11.x through 17.x. For information about other versions, refer to the following article:

  • K10516: Overview of BIG-IP pool status (9.x - 10.x)

Description

The BIG-IP system determines the status of a pool based on the availability of the members of that pool. The availability of a pool member is determined by its health check results and by the state to which the pool member is set. More specifically, the BIG-IP system can mark a pool member Available if the health check succeeds or Offline if the health check fails while the BIG-IP administrator can assign the status of Enabled, Disabled or Forced Offline. 

Important: The availability of a pool member may be overridden by the availability of its parent node. For example, if you assign the 10.0.0.1 node the Internet Control Message Protocol (ICMP) monitor and the 10.0.0.1:80 pool member the HTTP monitor, even if the HTTP monitor reports the pool member as up, if the parent node discards ICMP traffic (failing the health check), the pool member will inherit the down status of the parent node.

Note: Pool members with a status of unknown, for example when no monitor is applied, can receive new client requests.

A BIG-IP administrator can assign a pool member one of the following states:

  • Enabled  

    The pool member is eligible to receive all traffic. The BIG-IP system sends monitor traffic to the pool member.

  • Disabled  

    The pool member accepts new connections with a persistence record (for example, a new connection arriving to the BIG-IP system that presents a persistence cookie pointing to that pool member), and continues to serve existing connections (for example, an established TCP connection). New connections without a persistence record are not load balanced to this pool member. The BIG-IP system sends monitor traffic to the pool member.

  • Forced offline  

    The pool member continues to serve only existing connections. No new connections are allowed. The BIG-IP system stops sending monitor traffic to the pool member.

    Note: The Forced Offline status is not available for BIG-IP GTM and BIG-IP DNS pool members.

When performing maintenance on a server, a BIG-IP Administrator should disable or force the node or the pool member offline.
