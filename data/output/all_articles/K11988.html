Known Issue

This is the result of a known issue. The MCPD parser incorrectly allows the use of the HTTP::uri, HTTP::path, HTTP::query, and HTTP::host commands in events in which they are not meant to be valid, such as the SERVER_CONNECTED and HTTP_RESPONSE events. The parser may also allow the use of these commands when the required HTTP profile is not active on the virtual server.

The HTTP::uri, HTTP::path, HTTP::query, and HTTP::host commands are only meant to be valid in the HTTP_REQUEST, HTTP_REQUEST_DATA, HTTP_REQUEST_SEND, HTTP_CLASS_SELECTED, HTTP_CLASS_FAILED events, and then only when an HTTP profile is active on the virtual server. However, in BIG-IP versions prior to 10.1.0, some invalid uses of these commands would result in connection failure. In other cases, their invalid use was silently ignored, producing no noticeable detrimental effects. However, upon upgrading to BIG-IP version 10.1.0 or later, commands which had silently failed may now produce error messages and may prevent the configuration from loading.

Workaround

You can avoid these issues by restricting use of the HTTP::uri, HTTP::path, HTTP::query, and HTTP::host iRules commands to the HTTP_REQUEST, HTTP_REQUEST_DATA, HTTP_REQUEST_SEND, HTTP_CLASS_SELECTED, and HTTP_CLASS_FAILED events, and then only when an HTTP profile is active on the virtual server.

Note: For more information about the change in behavior, refer to K11989: Change in Behavior: HTTP iRule commands now generate error messages when used incorrectly.
