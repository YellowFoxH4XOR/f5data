Description

Machine certificate authentication fails on macOS when connecting to BIG-IP APM via a home router. The error message "Client response for the machine cert request: invalid request format" appears in APM logs.

Environment

  • Failing: Connected via home router which assigns DNS suffix via DHCP
  • Working: Connected via other gateways

Cause

The home router assigns its own DNS suffix (e.g., example.net) via DHCP, resulting in the client's FQDN (e.g., macbook.example.net) not matching the SAN in the machine certificate (e.g., device.example.com). The APM policy requires a match between the SAN and the FQDN, causing authentication to fail when there is a mismatch.

Answer/Recommended Actions

Review the APM policy for machine certificate authentication, specifically the SAN-to-FQDN matching requirement.

Check the DNS suffix assigned by the DHCP server (home router) and how it affects the client's FQDN.

Additional Information

In one identified case, the router in question was Technicolor. When connected to this router, it distributes its own DNS suffix technicolor.net via DHCP. As a result, the host receives the FQDN with the hostname macbookpro.technicolor.net.
