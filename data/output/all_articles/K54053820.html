K54053820: SAML SLO request doesn't clear the existing session based on the SAML assertion contents

Type
Support Solution
Published
2022-03-24
Updated
2025-02-06
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.4
Source
https://my.f5.com/manage/s/article/K54053820

Description

When a user logs out from another SP, the SLO is send to the IdP and the IdP is sending an SLO request to the F5. The SLO request for the user is received but the APM session is not terminated by the BIG-IP.

Environment
 

  • BIG-IP APM is configured as SAML SP.

Cause

The session is not deleted on APM because the cookie in SLO Request from IDP provider doesn't contain APM-related session.
APM was not not designed initially to remove user's session based on NameID or SessionIndex SAML parameters seen on SLO request.

Recommended Actions

Add: "Samesite=none;Secure" to all "Set-Cookie" headers as explained in the article below:
https://devcentral.f5.com/s/articles/iRule-to-set-SameSite-for-compatible-clients-and-remove-it-for-incompatible-clients-LTM-ASM-APM
