Description

You may encounter a false positive violation in Adv. WAF when the parameter serialization defined in your OpenAPI Spec file doesn't align with the expected serialization format observed in received API requests. This mismatch can trigger a security alert even though the actual traffic may be legitimate.

Environment

  • Adv. WAF
  • OpenAPI Spec File

Cause

The discrepancy between the defined serialization in the OpenAPI Spec and the actual format used in requests leads Adv. WAF to flag the traffic as suspicious. This can happen due to:

  • Inaccurate Spec Definition: The OpenAPI Spec might not accurately reflect the actual serialization format used by your API clients.
  • Client-Side Discrepancies: Clients might be sending requests with a different serialization format than what's documented in the Spec.

Recommended Actions

Analyze traffic logs to understand the actual serialization format being used by clients and modify the OpenAPI Spec file to reflect the observed serialization format. This ensures consistency between defined expectations and real-world behavior.

Additional Information

For more details on parameter serialization options and best practices, refer to the OpenAPI Specification documentation: Parameter Serialization
