K000151785: Persistent restjavad "Connection refused" Errors

Type
Support Solution
Published
2025-06-11
Updated
2025-06-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000151785

Description

On BIG-IP LTM version 17.1.2, users may encounter persistent errors in the restjavad process, such as:

org.apache.thrift.transport.TTransportException: java.net.ConnectException: Connection refused (Connection refused)

[SEVERE][com.f5.rest.workers.asm.AsmConfigWorker] Exception: org.apache.thrift.transport.TTransportException: java.net.ConnectException: Connection refused (Connection refused)

[SEVERE][8100/tm/asm/owasp/task OWASPTaskScheduleWorker] Unexpected exception in getting all the policies: org.apache.thrift.transport.TTransportException: java.net.ConnectException: Connection refused (Connection refused)

 

These errors can disrupt automation tools and API-based configuration changes, especially those involving ASM (Application Security Manager) components.

Environment

Affected components include restjavad, ASM workers, and any automation or API integrations relying on these services.

 

Cause

This issue is due to a software defect identified as Bug ID991829 in BIG-IP LTM version 17.1.2. The bug causes internal communication failures between restjavad and ASM-related workers, resulting in persistent "connection refused" errors that disrupt API calls and automation workflows.

 

Recommended Actions

  • Upgrade BIG-IP LTM to version 17.5.0 or later where this defect is resolved.
  • There is no supported workaround for affected versions.
  • If experiencing frequent restjavad restarts due to out-of-memory conditions, increasing the Java heap size for restjavad may reduce restart frequency but will not resolve the underlying connection issues or restore full automation/API functionality.
  • Schedule an upgrade to a fixed version at the earliest opportunity to restore normal operation.

 

Additional Information

Steps to Increase restjavad Heap Size

  1. Connect to the BIG-IP system using SSH or the console as an administrative user.
  2. Check the current heap size setting:
    1. tmsh list sys db provision.restjavad.extramb
  3. Set a higher heap size value (for example, to 896 MB):
    1. tmsh modify sys db provision.restjavad.extramb value 896
    2. Note: Adjust the value as needed, based on your system’s available memory and requirements.
  4. Restart the restjavad process for the change to take effect:
    1. bigstart restart restjavad

Note:

  • Ensure your system has sufficient free memory before increasing the heap size to avoid impacting other processes.
  • This adjustment may help with memory-related restjavad restarts but will not fix the underlying connection refused errors.
