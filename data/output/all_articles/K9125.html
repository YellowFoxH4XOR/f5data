Topic

Dynamic Ratio load balancing is a special load balancing mode for which the BIG-IP system actively polls pool members and assigns a weight value to each individual member, based on a set of default or user-defined threshold values. The weight assigned to an individual pool member determines how much traffic the pool member receives. The higher the value of the weight, the more traffic is directed to the pool member. The lower the value, the less traffic is directed to the pool member.

Note: The weights assigned to the pool members are dynamic and can change with each polling cycle that the snmp_dca or the snmp_dca_base monitors perform.

Note: Currently the Dynamic Ratio (member) option is only available when used with a Server/Application State Protocol (SASP) type monitor. When other monitor types are in use, choosing Dynamic Ratio (member) load balancing causes the BIG-IP system to distribute traffic evenly to all pool members.

When using Dynamic Ratio, the BIG-IP system never sets the weight of a node to a value less than 1. If the node weight is set to a value greater than 1, but you do not understand the reason for the value assignment, you can review the calculation using the following default Dynamic Ratio formula:

(Number of Nodes in Pool)^(Mem Coefficient((Mem Threshold - Mem Utilization)/Mem
Threshold)) + (Number of Nodes in Pool)^(CPU Coefficient((CPU Threshold - CPU Utilization)
/CPU Threshold)) + (Number of Nodes in Pool)^(Disk Coefficient((Disk Threshold - Disk Utilization)
/Disk Threshold))

The BIG-IP system rounds the sum of the value to the nearest whole number when assigning the Dynamic Ratio weight for the node.

Important: Because the snmp_dca monitor, which reads the values used by the Dynamic Ratio load balancing method, is associated with nodes rather than pools, it does not actually learn the number of nodes in a pool. As a result, the calculation always uses the default value of 10 for the Number of Nodes in Pool value.

For snmp_dca and snmp_dca_base, weight1 is zero (unless custom OIDs are defined). For snmp_dca_base, weight2 is always 0 because the snmp_dca_base monitor has no pre-defined variables.

Memory usage calculation

Memory usage calculation is performed using the raw values returned by the following memory OIDs:

.1.3.6.1.4.1.2021.4.5.0 UCD-SNMP-MIB::memTotalReal.0
.1.3.6.1.4.1.2021.4.6.0 UCD-SNMP-MIB::memAvailReal.0

The memory usage percentage is obtained using the following formula:

used_memory = memTotalReal - memAvailReal
Memory Utilization = (used_memory / memTotalReal) * 100

For example:

used_memory = 1025576 - 187808 = 837768
Memory Utilization = (837768 / 1025576) * 100
Memory Utilization = 81 %

Note: In this example, memory usage exceeds the specified threshold of 70 percent. Therefore, the value of 70 (matching that of the threshold value) is assigned to the memory usage to prevent a negative value being used in the calculation of the weight value.

CPU usage calculation

CPU usage calculation is performed using the raw values returned by the following CPU OIDs:

.1.3.6.1.4.1.2021.11.50.0 UCD-SNMP-MIB::ssCpuRawUser.0
.1.3.6.1.4.1.2021.11.52.0 UCD-SNMP-MIB::ssCpuRawSystem.0
.1.3.6.1.4.1.2021.11.51.0 UCD-SNMP-MIB::ssCpuRawNice.0
.1.3.6.1.4.1.2021.11.53.0 UCD-SNMP-MIB::ssCpuRawIdle.0

The CPU usage percentage is obtained using the following formula:

used_cpu = ssCpuRawUser + ssCpuRawNice + ssCpuRawSystem
available_cpu = used_cpu + ssCpuRawIdle
load = used_cpu / available_cpu
CPU Utilization = load * 100

For example:

used_cpu = 13193.000000 + 11517.000000 + 12046.000000 = 36756
available_cpu = 36756 + 19387175.000000 = 19423931
load = 36756 / 19423931 = 0.00189230490985578562856303391934
CPU Utilization = 0.00189230490985578562856303391934 * 100
CPU Utilization = 0.189230 %

Note: The SNMP DCA and BASE DCA monitors use only the first 6 significant digits following the decimal point.

Disk usage

The OID used for disk usage already reports values as a percentage, therefore no calculations are required to obtain a percentage value.

Note: In order to obtain disk usage, SNMP on the host system must be configured to report such information. This is typically performed during the installation of the SNMP package, during which time it asks which directories or file systems you want to monitor and report to SNMP. Refer to the SNMP configuration manual for your installed SNMP software.

.1.3.6.1.4.1.2021.9.1.9.1 UCD-SNMP-MIB::dskPercent.1

After the memory, CPU, and disk values have been calculated, those values can be entered into the main formula used to assign a weight value to the node.

(Number of Nodes in Pool)^(Mem Coefficient((Mem Threshold - Mem Utilization)/Mem
Threshold)) + (Number of Nodes in Pool)^(CPU Coefficient((CPU Threshold - CPU Utilization)
/CPU Threshold)) + (Number of Nodes in Pool)^(Disk Coefficient((Disk Threshold - Disk Utilization)
/Disk Threshold))

For example:

The sampling returned by the snmp_dca monitor produces the following formula values:

10^(1((70 - 70)/70)) + 10^(1.5((80 - 0.189230)/80)) + 10^(2((90 - 7)/90)) = 102.260211

The answers for each portion of the calculation include the following values:

1 + 31.365479 + 69.894732 = 102.260211

The BIG-IP system rounds the values to the nearest whole number.

For example:

1 + 31 + 70 = 102

Because the Dynamic Ratio weight can only be within the range of 1 to 100, the Dynamic Ratio weight value is 100 for this node.

Note: In the previous example, even though memory usage exceeds the threshold value specified, CPU and disk usage is low, which causes this node to be eligible to receive traffic. Due to the low CPU and disk values, the node is assigned the highest Dynamic Ratio weight range available. It should also be noted that the test system used only contained 1 GB of RAM, though most modern day operating systems use RAM more efficiently and typically allocate additional RAM for use with memory paging pools. While the system has allocated the RAM and the system is reporting the RAM as being in use, the operating system may not use the additional allocation. In a production environment, most server systems contains a minimum of 4 GB of RAM, with 16 GB minimum being the most common configuration.

If the BIG-IP system frequently assigns a Dynamic Ratio weight value of 1, when the weight value should be higher, this behavior may occur due to one of the following reasons:

  • The node is not returning SNMP data in the correct format. If the BIG-IP system cannot interpret the data returned by the SNMP DCA monitor, it sets the weight of the node to 1.
  • The threshold set for a polled item on the node is exceeded; therefore, the BIG-IP system sets the weight of that node to 1.

To view the values returned for SNMP OIDs used by your SNMP DCA monitors, you can enable logging. For information, refer to K14127: Enabling and disabling monitor logging for SNMP DCA and SNMP DCA Base monitors (11.x - 16.x).
