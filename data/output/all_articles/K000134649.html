Description

Solarwinds monitoring tool generating warning below warnings about cached and shared memory utilization:


'One or more Volumes have state: Critical'


Environment

Solarwinds monitoring tool via snmp

BIG-IP LTM


Cause

Incorrect OIDs used on Solarwinds


Recommended Actions

In this case, below OIDs are used by Solarwinds:


Volume Size and usage:

  OID = hrStorageIndex = 

1.3.6.1.2.1.25.2.3.1.1.

  OID = hrStorageType = 

1.3.6.1.2.1.25.2.3.1.2.

  OID = hrStorageDescr = 

1.3.6.1.2.1.25.2.3.1.3.

  OID = hrStorageAllocationUnits = 

1.3.6.1.2.1.25.2.3.1.4.

  OID = hrStorageSize = 

1.3.6.1.2.1.25.2.3.1.5.

  OID = hrStorageUsed = 

1.3.6.1.2.1.25.2.3.1.6.

  OID = hrStorageAllocationFailures = 

1.3.6.1.2.1.25.2.3.1.7.



These OIDs aren't F5-specific OIDs. Regarding the alert from monitoring tool, these OIDs used on the monitoring system belong to the standard Host Resources MIB (https://tools.ietf.org/html/rfc2790.html) and not F5 MIB and is getting the value from Linux rather than TMOS. There is not much value to be gained on polling non-F5 OIDs on a BIG-IP due to how BIG-IP utilize and allocate memory.


When it comes to determining memory usage on a BIG-IP, please refer below articles:

K16419: Overview of BIG-IP memory usage


Please refer below articles which suggests correct MIB file and OIDs for F5:

K24160532: SNMP OID for BIG-IP disk partition size

K32077003: High memory and disk utilization reported by SNMP
