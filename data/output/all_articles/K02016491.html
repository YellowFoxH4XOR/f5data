Known Issue

When you frequently update a BIG-IP APM access profile within a 24 hour period, the Traffic Management Microkernel (TMM) runs out of memory and produces a core file.

This issue occurs when all of the following conditions are met:

  • You update an access profile in BIG-IP APM frequently (several hundred times) within a 24 hour period.
  • The access profile you are updating is complex and contains many variables.

BIG-IP APM creates a version of a configuration snapshot each time you update an access profile. The system clears old versions of the BIG-IP APM configuration snapshots that are not used from memory after 24 hours. When you frequently update a complex access profile in a 24 hour period, it can lead to TMM memory exhaustion.

Impact

TMM runs out of memory and generates a core file resulting in service disruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic while TMM restarts.
  • TMM generates a core file in the /shared/core directory.
  • The BIG-IP system fails over to another host in the device group.
