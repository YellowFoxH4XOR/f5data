Description

You may observe issues during installation of a new software release on your system.
While attempting to copy configuration and reboot to desired boot partition you're getting below example errors:

cpcfg --source=HD1.1 --reboot HD1.2
error: status 8192 returned by command: mount -orw /dev/vg-db-sda/set.2.root /mnt/tm_install/961.JSwMQm/ 2>/dev/null
info: >++++ result:
info: mount: /dev/mapper/vg--db--sda-set.2.root already mounted or /mnt/tm_install/961.JSwMQm/ busy
info: mount: according to mtab, /dev/mapper/vg--db--sda-set.2.root is mounted on /mnt/tm_install/25484.xsVj_F
info: >----
Could not access configuration destination; sda, 2 .

Environment

  • BIG-IP LTM
  • Software installation
  • Copy configuration
  • Boot partition

Cause

None

Recommended Actions

  • Log in to tmsh by typing the following command:
tmsh
  • Verify status of installed software versions:
show sys software status

The command output appears similar to the following example:


--------------------------------------------------------------------
Sys::Software Status
Volume  Product   Version   Build  Active    Status  Allowed Version
--------------------------------------------------------------------
HD1.1    BIG-IP    15.1.0  0.0.31     yes  complete              yes
HD1.2    BIG-IP  16.1.2.2  0.0.28      no  complete              yes  <<--- In presented example this will be the desired new software version
  • Enter Advance Bash shell:
bash
  • Copy the configuration from a source boot location to a target boot location and immediately reboot to the specified target partition (in presented example syntax will be):
cpcfg --source=HD1.1 --reboot HD1.2
  • If you're getting error presented in first section, please delete affected boot location, and re-install desired software version. The following articles may help achieve that:
K33265170: Deleting a boot location volume to free up disk space
K34745165: Managing software images on the BIG-IP system
