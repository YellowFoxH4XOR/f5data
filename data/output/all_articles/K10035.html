Known Issue

This is the result of a known issue. If you use the sys-reset command to reset a BIG-IP system to factory defaults when remote authentication is configured, the sys-reset command will not properly reset the system-auth link from remote authentication to local authentication. As a result, local authentication will fail and users will be prevented from logging in after a reboot.

Note: For more information, refer to K7550: Resetting the BIG-IP system configuration to the factory default settings using the sys-reset command.

F5 Product Development tracked this issue as CR111038 and it was fixed in BIG-IP version 9.4.8. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator release notes.

This behavior does not affect BIG-IP version 10.0.0 due to architectural changes. The sys-reset command was removed from the system in BIG-IP version 10.0.1.

Workaround

If you have already run the sys-reset command, and are affected by this issue, contact F5 Technical Support for assistance in restoring the correct settings to allow local authentication.

If you have not issued the sys-reset command on a system configured with remote authentication, you can prevent this issue from occurring by reconfiguring the BIG-IP system to local authentication. To do so, perform the following procedure:

Important: The following procedure is to be performed before the sys-reset command is issued on a system configured with remote authentication..

  1. Log in to the Configuration utility.
  2. Select System.
  3. Select Users.
  4. Click Authentication.
  5. Click the Change button under Authentication User Directory.
  6. Select Local.
  7. Click Finished.

Once the User authentication option has been changed, you can safely issue the sys-reset command.
