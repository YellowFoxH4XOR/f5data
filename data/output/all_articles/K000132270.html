Description

 

When you want to send an HTTP/1.1 request with the send string of your HTTP/HTTPS monitor, the HTTP 1.1 version of the protocol strictly requires a host header. You may refer to: K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor

 

If you have multiple pool members in a single pool that have different host headers, you can apply the "null" string to the send string of your HTTP pool monitor.

 

 

Environment

  • BIG-IP LTM
  • HTTP/HTTPS monitors
  • HTTP 1.1 request

Cause

HTTP/1.1 requires a valid host header

 

Recommended Actions

Use the following format structure by adding the "null" string to the Host header:

 

Example:

GET / HTTP/1.1\r\nHost: null\r\nConnection: Close\r\n\r\n

 

This way, the server response will be a 200 OK instead of a 400 Bad Request due to the missing host header value.

 

You can test this string with the following open_ssl command bash command from the BIG-IP CLI:

Note: Substitute the <Server IP:Port and Route-domain fields for the correct values

 

(echo -e "GET / HTTP/1.1\r\nHost:null \r\nConnection: Close\r\n\r\n";sleep 1) | rdexec <Route-domain> openssl s_client -connect <Server IP:Port>
