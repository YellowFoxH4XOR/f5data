Known Issue

The BIG-IP system may intermittently fail to complete the boot up process after upgrading. This issue may occur when all of the following conditions are met:

  • The BIG-IP software is installed on the 3400 platform.
  • The system has been upgraded to BIG-IP 10.1.x or 10.2.x.
  • The device is rebooted by either power cycling or issuing the full_box_reboot command at the command line.

This issue is the result of race condition between the Linux host and the SCCP host that manifests after the new software is installed. When this issue occurs, the system may be intermittently unable to boot after upgrading, regardless of the selected boot partition.

Impact

The BIG-IP 3400 system may not be able to boot up after upgrading to BIG-IP 10.1.x or 10.2.x.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The affected BIG-IP 3400 system stops booting unexpectedly after logging messages on the serial console that appear similar to the following example:

    kernel.core_uses_pid = 0
    kernel.core_pattern = /var/core/%e.sccp.core
    Host Console Shell --- Press ( for command menu.

Workaround

If the system fails to boot, you may be able to recover the system by power cycling it. If the system persistently fails to complete the boot cycle, contact F5 Technical Support for assistance.

To prevent this issue from occurring, you must modify the /etc/rc.local file that resides on the SCCP. To do so, perform either of the following procedures:

  • Modifying the SCCP rc.local file using the serial console
  • Modifying the SCCP rc.local file using SSH

Modifying the SCCP rc.local file using the serial console

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. From the serial console, display the SCCP menu by pressing ESC + SHIFT + 9 keys.
  2. Select item L --- SCCP login from the SCCP menu.
  3. Enter the login credentials for the root user.
  4. Backup the /etc/rc.local file by typing the following command:

    cp -p /etc/rc.local /etc/rc.local.sol13115

  5. Edit the /etc/rc.local file using the vi text editor by typing the following command:

    vi /etc/rc.local

  6. Navigate to the end of the file by pressing SHIFT + G keys.
  7. Open a new line in the file by pressing the O key.

    You can safely ignore the warning about editing a read-only file.
  8. Copy the following text and paste it into the vi text editor.

    # Delayed Host reset
    OLDLEVEL=$(runlevel | cut -b 1)
    NEWLEVEL=$(runlevel | cut -b 3)
    if [ x$OLDLEVEL = xN ]; then
    if [ x$NEWLEVEL = x2 ]; then
    cpldutil -q -w 0x05 0x72
    sleep 1
    cpldutil -q -w 0x05 0x73
    fi
    fi
    # End delayed Host reset

  9. Exit edit mode in the vi editor by pressing the ESC key.
  10. Save the modifications by typing the following key sequence in the vi editor and pressing enter:

    :wq!

  11. Type the following command to save your changes to the SCCP non-volatile memory:

    /usr/bin/savenv

  12. Exit the SCCP by typing the following command:

    exit

Modifying the SCCP rc.local file using SSH

If the SCCP of the affected BIG-IP 3400 system is configured to allow access through SSH from the network, perform the following procedure:

Note: To enable SCCP access from the network using SSH, refer to K3753: Configuring the switch card control processor so that it can be accessed over the network.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
