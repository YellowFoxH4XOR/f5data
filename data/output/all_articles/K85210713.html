Description

You want to enable In-TMM monitoring. When In-TMM monitoring is enabled, it will replace bigd process for health monitors.

Enable In-TMM monitoring is a global option.

This article explains the impact when enabling the In-TMM monitoring.

Environment

  • BIG-IP 13.1 and above
  • In-TMM monitoring enabled

Cause

None

Recommended Actions

bigd process uses the host system's resources while tmm will have its own allocated memory and CPU (allocated during provision process) and is responsible for traffic processing.

When In-TMM monitoring is enabled, it will use tmm to process the health monitors. All the load of monitoring from bigd will be moved to the tmm process.

There is no definite prediction of how tmm will react from processing all the health monitors as this would come down to the allocated resources and the amount of objects it is monitoring. Please be aware of the known Bugs and related issues that you may encounter when enabling In-TMM monitoring (see the Additional information section below).

You should take into account that tmm will do more processing when In-TMM is in use.

Enabling In-TMM monitoring

Impact of procedure: Performing the following procedure configures the BIG-IP system to perform monitor functions in TMM instead of the bigd process.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable the bigd.tmm database key, enter the following command:

    modify sys db bigd.tmm value enable

Disabling In-TMM monitoring

Impact of procedure: Performing the following procedure configures the BIG-IP system to perform monitor functions using the bigd process instead of TMM.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To disable bigd.tmm database key, enter the following command:

    modify sys db bigd.tmm value disable

Additional Information

Be aware of the following Bugs prior to deploying In-TMM Monitors in a production environment.
  • K16343688: HTTP monitor down after changing to in-tmm monitoring
  • K31461254: BIG-IP LTM Configuring In-TMM Health Monitor Causes HTTP Monitors to Fail
  • K33437445: in-tmm https monitor failed without a specific SSL profile
  • Bug ID 822245: Large number of in-TMM monitors results in some monitors being marked down
  • Bug ID 832133: In-TMM monitors fail to match certain binary data in the response from the server
  • Bug ID 778853: In-TMM monitor issues pertaining to the use the username/password or ip-dscp options
  • Bug ID 788257: Bigd.mgmtroutecheck setting ignored by in-tmm monitors after bigstart restart
