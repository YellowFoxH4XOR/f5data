Known Issue

This is the result of a known issue.  When you attempt to download a network packet dump from the FirePass controller, the packet dump file may instead display in the browser used to take the packet dump.  Because the packet dump file is in a binary format, the displayed information appears in the browser as random characters, blank spaces, or similar unrecognizable graphics.

The FirePass controller provides a network packet dump feature for troubleshooting purposes.  Network packet dumps can be performed from the Device Management: Maintenance: Troubleshooting Tools page of the FirePass Administrative Console.  When a packet dump is completed, you have the option to display a text-based version of the packet dump in the browser, or download the binary file to your local client for later viewing in an application such as Ethereal/Wireshark.  If you select the download option, the FirePass may instead display the packet dump in the browser, but without converting the binary file to a text representation.

This symptom occurs because the HTTP response from the FirePass controller, which contains the packet dump file, uses an incorrect HTTP header.  Normally, when the download option is selected, an HTTP Content-type header with the value application/octet-stream is used.  However, the FirePass controller may instead send an HTTP Content-type header with the value text/html.  This incorrect value prevents the browser from displaying a dialog box to select an application to display the file, or from choosing the application automatically if the file's .dmp extension is mapped to an application.

F5 Product Development tracked this issue as CR85668 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Workaround

Typically, restarting the FirePass Services will correct this issue.  You can restart the FirePass Services from the Device Management: Maintenance: Restart Services page.
