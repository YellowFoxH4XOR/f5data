Description

  • DNSSEC on the DNS Zone and is failing DNSSEC validation checking.
  • The customer wants to enable DNSSEC in the F5® Distributed Cloud (XC).

Environment

  • F5® Distributed Cloud
  • DNS Management

Cause

None

Answer/Recommended Actions

You can configure this in two ways:

  1. DNSSEC as a Delegated Domain.
  2. DNSSEC in the XC Primary Zone.

To enable DNSSEC as a Delegated Domain:

1. Go to DNS Management.

2. Go to Delegated Domain Management.

3. Go to Manage Configuration. 

4. Click on Edit Configuration.

5. Verify DNSSEC Mode is set to Enable within the drop down box options. 

6. Go to Delegated Domain Management and look for the DNSSEC DS Record. 

Key Tag: 48553
DS Algorithm: (13) ECDSA CURVE P-256 with SHA 256 
Digest: f7f39f5c40294621433f9778e7ff3fdcc00f25459879c56d212eebce0c5398c3
Digest Type: (2) SHA-256

Example DNSSEC DS Record: (48553 13 2 f7f39f5c40294621433f9778e7ff3fdcc00f25459879c56d212eebce0c5398c3)

 

7. Visit the domain registrar (this is external to F5) and input the key values automatically generated in the DNSSEC DS Record field.

8. Validate the correct implementation utilizing:

dig ds yourdomain.com

 

To enable DNSSEC in the XC Primary Zone:

1. Go to DNS Zone Management and select + Add Zone.

2. Go to Primary DNS Configuration and go to Edit Configuration. 

3. Go to DNSSEC Mode and set it to Enable.

4. Go to DNS Zone Management and copy the values from DNSSEC DS Record.

Key Tag: 48876
Ds Algorithm: (13) ECDSA CURVE P-256 with SHA 256
Digest: ccd88ac35ecac8e6a06347eac3457bc2113b844261a296409d4788e9834c71fa
Digest Type: (2) SHA-256

Example DNSSEC DS Record: (48876 13 2 ccd88ac35ecac8e6a06347eac3457bc2113b844261a296409d4788e9834c71fa)

 

5. Visit the domain registrar (this is external to F5) and input the key values automatically generated in the DNSSEC DS Record field.

6. Validate the correct implementation utilizing:

dig ds yourdomain.com

Additional Information

You should be able to see your newly implemented records listed; otherwise, you can utilize external simple tools like: https://domsignal.com/dnssec-test

If you need an extended validation check, you may utilize other tools like: https://dnssec-debugger.verisignlabs.com/

Error: No DS records found in “website” in the com zone?

This error is generally attributed to 3 possible causes: 

  • DNSSEC not enabled: It is possible that the "website" domain does not have DNSSEC enabled.
  • Misconfiguration: The DNSSEC configuration for the domain or parent zone may be incorrect.
  • Delay in propagation: If DNSSEC was only recently upgraded or enabled, it can take some time for all authoritative DNS servers to receive DS records.

 

What is a DS Record?

A delegation signer record, or DS record, is a record that contains the DNSSEC signature key of a delegated zone, or the subdomain's zone on a different name server. This DS record is found in the zone of your domain name and links to your subdomain's DNSSEC information on the external name server, allowing the accuracy of your subdomain's DNSSEC information to be confirmed.  Through the domain's DS record, a visitor's browser will confirm the subdomain's DNSSEC information is reliable.

In addition, the DS record for the domain name itself (which is automatically established at the registry if the domain is registered with TransIP and you utilize the TransIP name servers) can be used by the browser to verify the veracity of the DNSSEC data of the root domain itself. 

It is possible to confirm that the DNS zone of the domain name is appropriately secured with DNSSEC by using this technique, which verifies the reliability of each step. DNSSEC security is built on this idea, which is known as the "Chain of trust."

Read more on DNSSEC: https://www.icann.org/resources/pages/dnssec-what-is-it-why-important-2019-03-05-en 

 

What does the XC Cloud automatic-generated DNSSEC DS record mean?

Let's break down the example we used in this tutorial:
(48876 13 2 ccd88ac35ecac8e6a06347eac3457bc2113b844261a296409d4788e9834c71fa)

  1. Key Tag: 48876. It indicates to which DNSKEY record this DS record relates. DNSKEY records can be identified more quickly by using key tags.
  2. Algorithm: 13. The algorithm number is this. It provides the hash value's generating cryptographic algorithm. In this case, 13 belongs to (ECDSA Curve P-256 with SHA-256).
  3. Digest Type: 2. The Digest Type 2 details the hash value generation algorithm; in this case, it belongs to (SHA-256). 
  4. Digest: ccd88ac35ecac8e6a06347eac3457bc2113b844261a296409d4788e9834c71fa: This hash is computed using the DNSKEY record's public key by the DNSSEC signer.

What happens if the customer is only hosting subdomains in XC and the parent domain in a different DNS Zone registry? 

If the customer is hosting subdomains within XC Cloud (XC being the DNS hosting provider), and the parent domain is hosted in a different DNS zone registry, the customer needs to take the following steps to establish a chain of trust using DNSSEC.

  1. Enable DNSSEC in XC Cloud: Each subdomain hosted within XC Cloud must have DNSSEC enabled. When DNSSEC is activated, XC DNS automatically generates the DS record for the domain.
  2. Get DS Record: After enabling DNSSEC for the domain in XC Cloud, get the DS record that XC DNS generated. This DS record contains cryptographic information necessary for validating the authenticity of DNS responses for the domain and its subdomains.
  3. Add DS Record to Parent Zone: Manually add the DS record obtained from XC DNS to the DNS settings of the parent zone. This establishes a secure chain of trust between the parent domain and its subdomains hosted within the XC Cloud.
