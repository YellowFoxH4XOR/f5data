K9017: Using WinHttpCertCfg.exe to grant non-administrator users access to machine certificate private keys

Topic

Beginning with FirePass version 6.0.1 and with BIG-IP APM, you can perform client side checks for a valid machine certificate on a Windows client system. Machine certificates and their corresponding private keys are located in the Local Computer certificate store on Windows client systems. Private keys located in the Local Computer certificate store are only accessible by the user who installed the private key, and by users with administrator privileges. If a user did not install the machine certificate and does not have administrator privileges on the Windows client system, the Edge client components that run with that user’s privileges cannot access the private key to validate the machine certificate. One workaround is to use the Microsoft Windows HTTP Services Certificate Configuration Tool (WinHttpCertCfg.exe) to grant a non-administrator user access to the machine certificate private key in the Local Computer certificate store.

Important: FirePass version 7.0.0 is unable to inspect Windows 7 client systems. A fix for version 7.0.0 was introduced in cumulative hotfix HF-70-2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Note: For more information about machine certificate private keys, including additional workarounds, refer to K7866: Private key verification and configuration for the Windows machine certificate checker pre-logon inspector for FirePass and refer to K12354: Private key verification and configuration for the Machine Cert Auth action for BIG-IP APM.

To use WinHttpCertCfg.exe to grant a non-administrator user access to the machine certificate private key in the Local Computer certificate store, perform the following procedure:

  1. Open a browser to http://go.microsoft.com/fwlink/?linkid=20506.

    Note: This link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.
  2. Download WinHttpCertCfg.exe.
  3. Install WinHttpCertCfg.exe on the Windows client system.
  4. Log on to the Windows client system using an account with administrator privileges.
  5. On the Windows command line, use the following command syntax:

    Note: In the following command, [\path\to\winhttpcertcfg.exe] is the full path to WinHttpCertCfg.exe on the client system, [Subject CN] is the Subject CN field in the machine certificate, and [User Account] is the users’s Windows account.

    [\path\to\winhttpcertcfg.exe] -g -c LOCAL_MACHINE\My -s [Subject CN] -a [User Account]

    For example, if the Subject CN of the machine certificate is laptop1.siterequest.com and you want to grant the user DOMAIN\JOHN access to the machine certificate private key, you would type the following command:

    [\path\to\winhttpcertcfg.exe] -g -c LOCAL_MACHINE\My -s laptop1.siterequest.com -a DOMAIN\JOHN

    Important: Since the purpose of a machine certificate is to authenticate the identity of a client system, the Subject CN field in the machine certificate must be identical to the full computer name configured on the Windows client system. If the Subject CN field in the machine certificate is different than the full computer name configured on the Windows client system, the client system will fail the Windows machine certificate pre-logon check.

Note: For more information about WinHttpCertCfg.exe, including command line examples, refer to http://msdn.microsoft.com/en-us/library/aa384088(VS.85).aspx. This link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.
