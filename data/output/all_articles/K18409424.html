K18409424: ICMP monitor is marking the node up and down constantly

Description

Node using ICMP is constantly flapping (being marked up and down) even though the node is up and responding properly.

  • Node is being marked down even when the node is up and is responding to ICMP echo.
  • When tested normally, the node is responding to all pings.
  • TCPdump shows the ICMP echo reply from node is reaching the BIG-IP but it's still being marked down.

Environment

  • BIG-IP LTM with node using ICMP monitor
  • Packet filters are configured though it has rules to permit traffic from self-IP to the node.

Cause

This can be because the ICMP echo reply is hitting a different tmm instance than the instance which sent out the ICMP echo. The packet filtering rules are processed before inter-tmm traffic is processed. When the ICMP echo reply hits the same tmm instance, it will be marked up but if the ICMP echo reply hits a different tmm instance, it will be marked down due to the packet filter.

Recommended Actions

Follow the steps to remediate this issue.

  1. Test by disabling packet filters completely to see if that stops the flapping of node. If it does, proceed to next step.
  2. Create a packer filter rule to allow ICMP traffic from the node to self-IP.
Example: Self-IP - 10.0.0.1, Node-IP 10.0.0.5. Though there is a Packet filter rule for 10.0.0.1 to 10.0.0.5, a new rule needs to be added for ICMP traffic from 10.0.0.5 to 10.0.0.1.
