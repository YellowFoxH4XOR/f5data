Issue

You should consider using this procedure under the following condition:

  • You want to perform additional diagnostics or troubleshooting of the Server/Application State Protocol (SASP) monitor.

Symptoms

When configuring or using an SASP monitor that is experiencing issues, you may encounter the following symptoms:

  • Pool members are incorrectly marked down (instead of up).
  • Pool members are marked up and down repeatedly, in quick succession.
  • The SASP monitor cannot communicate with the Group Workload Manager (GWM) server.

Recommended Actions

SASP provides a mechanism for load balancers and IBM workload management systems to communicate better ways of distributing the existing workload to the group members.

Unlike standard BIG-IP monitors that monitor each individual resource directly, the BIG-IP SASP monitor is an external monitor that connects to an IBM GWM server or Enterprise Workload Manager (EWLM) server to indirectly obtain the up/down availability status and distribution ratio information for monitored pool members.

The SASP monitor was originally introduced in BIG-IP 9.4.0. In BIG-IP 13.0.0, the SASP monitor was updated to address reliability and scalability concerns encountered with previous versions. The SASP monitor now meets IBM scaling requirements and scales to 1,000 pool members. The SASP monitor uses the same configuration as previous versions, so there are no configuration changes required when upgrading from an earlier version.

When working with SASP monitors, you should consider the following:

  • To use the distribution ratios provided by the GWM server, you must configure the pool's load balancing method to use Ratio (node) or Ratio (member).
  • The pool member up/down status can be triggered by the GWM. You can also manually mark pool members up or down from the BIG-IP system, and the monitor will notify the GWM.
  • You can configure the SASP monitor in Push mode or Pull mode. By default, the monitor is set to Push mode.
    • In Push mode, the SASP monitor listens for the GWM server to send pool member status information to the monitor.
    • In Pull mode, the SASP monitor requests pool member status information from the GWM server at the interval specified by the GWM server (when the GWM Interval setting is set to Automatic) or as explicitly specified by the SASP monitor.

Procedures

When experiencing SASP monitor issues, you can use the following troubleshooting procedures to determine the root cause:

  • Viewing the tmsh configuration for SASP monitors
  • Displaying the monitored pool member status
  • Configuring debug logging
  • Configuring GWM server down delay
  • Reviewing the troubleshooting matrix

Viewing the tmsh configuration for SASP monitors

Note: To view the tmsh syntax used for SASP monitors, enter the tmsh help ltm monitor sasp command at the command line.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. View the tmsh configuration for SASP monitors by typing the following command:

    list /ltm monitor sasp all-properties

    Output appears similar to the following example:

    ltm monitor sasp my_sasp {
        app-service none
        defaults-from sasp
        description none
        interval auto
        mode push
        partition Common
        primary-address 10.1.20.99
        protocol tcp
        secondary-address none
        service 3860
        time-until-up 0
    }

Note: The interval value is used only for Pull mode and is ignored when the monitor is configured in Push mode. The time-until-up and app-service values are legacy values that are not used by the BIG-IP system.

Displaying the monitored pool member status

To display the up and down status of each of the pool members, as reported by the GWM server, you can view the pool member status from the command line by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Display the monitor pool member status using the following command syntax:

    show ltm monitor sasp <monitor_name>

    Output appears similar to the following example:

    show ltm monitor sasp my_sasp
    ------------------------------
     LTM::Monitor /Common/my_sasp

Configuring debug logging

The BIG-IP system logs SASP monitor messages to the /var/log/monitors/saspd.log file. The logging level for SASP monitor logging is controlled by the saspd.loglevel database variable. By default, the log level is set to error. If you want more verbose logging for SASP monitor functions, you can configure debug logging for SASP monitors. The following debug log levels are available:

  • debug

    Logs additional information such as monitor messages with the GWM server, pool member ratio weight changes, and GWM failover messages.

  • deep_debug

    Logs debug level logging with additional verbosity.

  • debug_msg

    Logs deep_debug level messaging, additional MCP messages, and the contents of sent and received SASP messages.

To configure the SASP logging level, perform the following procedure:

Impact of procedure: You should enable debug logging only when you are actively troubleshooting SASP monitor issues. Excessive debug logging may negatively impact system performance.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Enable debug logging by typing the following command:

    modify sys db saspd.loglevel value "debug"

Note: To revert to the default SASP logging level, use the tmsh modify sys db saspd.loglevel value "error" command.

Configuring GWM server down delay

If the SASP monitor fails to connect to the GWM server (or secondary GWM server) for 30 seconds, the BIG-IP system marks all pool members associated with the SASP monitor as down. The delay is controlled by the saspd.gwmdowndelay database variable, and the default value is 30 seconds.

The following table describes the available saspd.gwmdowndelay database variable values.

ValueDescription
-1 Never marks pool members down
0 Marks pool members down immediately
1 ~ 86400Number of seconds to delay before marking pool members down
86401 Same as -1

To configure the saspd.gwmdowndelay database variable, perform the following procedure:

Impact of procedure: Modifying the GWM down delay can impact traffic when the SASP monitor is unable to communicate with the GWM.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Change the GWM down delay using the following command syntax:

    modify sys db saspd.gwmdowndelay value "<value>"

Note: To revert to the default delay, use the tmsh modify sys db saspd.gwmdowndelay value "30" command.
