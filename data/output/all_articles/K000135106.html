Description

Experienced a network failure that caused a trunk/LAG to go down.

Why didn't the system trigger NIC failsafe (show sys ha-status) and reboot or failover to the standby unit?

Environment

  • HA table
  • Failover
  • BIG-IP
  • VELOS
  • rSeries

Cause

NIC failsafe events are triggered when a problem is detected with the internal switch fabric of the system.

It would be expected to not have NIC failsafe triggered in the HA table on external network failure, because there is no problem with the F5 hardware itself.

If there is a problem detected with the F5 hardware, NIC failsafe action should be triggered.

In the event of an external network failure, systems configured with redundant IPs (management, self IP) for failover purposes will typically not fail over, because at least one of those failover channels is likely to still be established.

Recommended Actions

Consider implementing either HA Group, VLAN Failsafe, or Gateway Failsafe functionality. These features can fail over the system in the event of an external network failure.
