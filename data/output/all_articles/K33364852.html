Description:

HTTP monitor not marking pool member down even though the receive string configured not matching with the received response.

Under the monitor logs there will be entries which will state that  "Response matched regex".

For ex:

ltm monitor https /Common/test

{
    recv up               <======================================= very generic and short receive string.
    send "GET /adc.html HTTP/1.0\r\n\r\n"
}

Environment:

  • Custom HTTP monitor.
  • Receive String.

Cause:

HTTP response is containing the receive string as a substring in one of HTTP headers due to which BIG-IP is considering the response to be matched with regex.

 

Recommended Actions:

Use a more specific and longer receive string to reduce false positives.

None.
