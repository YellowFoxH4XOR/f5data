Description
A new or modified HTTP or HTTPS BIG-IP LTM health monitor configuration for NTLM or NTLMv2 Authentication marks pool members down, even when receiving the expected 401 Unauthorized response with a WWW-Authenticate: NLTM header

Environment
HTTP monitor send string configured with one or more of the following issues:

  • HEAD request method used instead of GET when the HTTP response from the server indicates Content-Length: value greater than 0 or uses Transfer-Encoding: chunked header
  • Connection: Close header
  • Ending with closing double CR/LF \r\n\r\n when there is a Username and Password for the monitor

Cause

  • HEAD request method indicates that only headers should be included in the response. NTLM HTTP response may have a body and the BIG-IP will not send the next expected request if that is not included.
  • NTLM authenticates a single connection using a sequence of HTTP transactions, so using the HTTP Connection: Close header will not allow this authentication sequence to complete as expected.
  • Unlike other HTTP monitor send strings, an NTLM or Basic Authentication monitor should not include a closing double CR/LF sequence. When NTLM/NTLMv2 is enabled by adding a Username and Password to the monitor configuration, the BIG-IP system appends the Authorization header and a double CR/LF sequence after the last character in the Send string.

Recommended Actions

  • Use the GET method
  • Ensure that if a Connection: header is used in the send string that the value is Keep-Alive
  • Do not include a closing \r\n\r\n when configuring Username/Password

Example send string:

GET /Home.aspx HTTP/1.1\r\nHost: host.domain.com
