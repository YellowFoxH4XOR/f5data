Known Issue

BIG-IP APM rewrite of Flash ActionScript 3 (AS3) content may truncate URL paths.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy uses a rewrite profile.
  • AS3 content returned from the destination resource references URLs that use "../" in content paths.

Impact

The content is not accessible.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Rendering of AS3 content may freeze or fail.
  • When rendering AS3 content, the user may see an error message similar to the following example:

    OST Manager: XML File Not Found

  • The rewritten URL may be missing the BIG-IP APM rewrite path /f5-w-xxx$/ and "../" paths.

Workaround

To work around this issue, you may be able to use an iRule to identify affected requests and correct the affected URI path within the HTTP_REQUEST event.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

Example iRule definition syntax:

when HTTP_REQUEST {
# catch the original path containing the ../ request from flash file
if { [HTTP::path] starts_with "/v104/" } {
HTTP::path "/f5-w-687474703a2f2f7777772e696e746572616374697665616e61746f6d792e636f6d$$[HTTP::path]"
}
}

The iRule [HTTP::path] starts_with and the stated /f5-w-(hexadecimal value)$ are specific to the affected environment. You can obtain the required information to create an environment-specific iRule by reviewing successful rewritten URIs referrer and request data to the same destination resource. Once the BIG-IP APM hexadecimal path is identified (/f5-w-.....$), you can substitute the path for the f5-w- path that is used in the example syntax.
