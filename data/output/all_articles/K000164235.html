Description

At the time of writing this article, GUI dashboard of r5900 running F5OS v2 showed:
F5OS System shows 44% used; 8.3GB available of 14.9 GB. 
F5OS Tenant shows 77% used; 24.7GB available of 110.5GB.
Note: these values will be present on F5OS > 1.8.0 due to a fix for ID1233865.

Now, to have a good understanding of how these confd values are calculated, here are the formulas and respective explanations:
available:

    /proc/meminfo --> MemAvailable

    An estimate of how much memory is available for starting new applications, without swapping. 
    Calculated from MemFree, SReclaimable, the size of the file LRU lists, and the low watermarks in each zone. 
    The estimate takes into account that the system needs some page cache to function well, 
    and that not all reclaimable slab will be reclaimable, due to items being in use. 
    The impact of those factors will vary from system to system.

free:

    /proc/meminfo --> MemFree
 
    An estimate of how much memory is available for starting new applications, without swapping. 
    Calculated from MemFree, SReclaimable, the size of the file LRU lists, and the low watermarks in each zone. 
    The estimate takes into account that the system needs some page cache to function well, and that not 
    all reclaimable slab will be reclaimable, due to items being in use. The impact of those factors will vary from system to system.

used-percent:

    /proc/meminfo --> (MemTotal - MemAvailable) / MemTotal * 100
    An estimate in % of how much total memory is used.

platform-total:

    /proc/meminfo --> (MemTotal - (HugePages_Total * md.HugePageSize))

    This is the amount of memory allocated to the F5OS platform services layer. 
    The tenant memory is reserved and that is why used-percent is such a large number. 
    This number attempts to represent the mount left over used by platform services.

platform-used:

    /proc/meminfo --> (MemTotal) - (md.HugePagesTotal * md.HugePageSize) - MemFree - MemBuffers - Cached
    Attempts to report how much of the platform layer is currently in use.

platform-used-percent: 

    (platform-used / platform-total) * 100
    This is the amount of memory used by the platform layer.

tenant-reserved:

    memory total - platform-total
    This is the amount of memory available for tenant allocation.

tenant-configured:
    
    This is the amount of memory allocated to tenants in Configured state.

tenant-provisioned:

    This is the amount of memory allocated to tenants in Provisioned state.

tenant-deployed:

    This is the amount of memory allocated to tenants in Deployed state.

tenant-configured-percent:
  
    (tenant-configured / tenant-reserved) * 100  
    This is the amount of memory used by tenants in Configured state out of all memory reserved for tenants.

tenant-provisioned-percent:

    (tenant-provisioned / tenant-reserved) * 100  
    This is the amount of memory used by tenants in Provisioned state out of all memory reserved for tenants.

tenant-deployed-percent:

    (tenant-deployed / tenant-reserved) * 100  
    This is the amount of memory used by tenants in Deployed state out of all memory reserved for tenants.
GUI dashboard is calculated based on what confd reports, and the dashboard also does an extra unit calculation for better user experience. /proc/meminfo is in KiB, so 1024 bytes, not 1000 bytes. That means, values from confd needs to be multiplied by 1073741824 (2³⁰), so the divisor is binary, to get a value in GB (gigabyte) shown in GUI.
