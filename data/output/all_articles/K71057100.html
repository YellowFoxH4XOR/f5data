Description
This article describes how to configure the minimum TLS version used by the big3d process for iQuery connections. 

Environment

  • BIG-IP
  • iQuery
  • big3d process

Cause

By default the value of the system database variable big3d.minimum.tls.version is TLSv1

tmsh list sys db big3d.minimum.tls.version all-properties

sys db big3d.minimum.tls.version {
    default-value "TLSv1"
    scf-config "true"
    value "TLSv1"
    value-range "string"
}

Recommended Actions

In order to configure the big3d iQuery connection to only use a specific TLS version and above, follow the procedure below. You will need to perform these steps on each device in a device group.

Reconfigure the big3d process to disable non-compliant versions of TLS

  1. Use the following tmsh syntax to configure the minimum TLS version for big3d:
    tmsh modify sys db big3d.minimum.tls.version value <TLSv1|TLSv1.1|TLSv1.2>

    For example:

    tmsh modify sys db big3d.minimum.tls.version value TLSv1.2

    Note: TLSv1.2 is the current highest version of TLS supported.
    Note: The system database value allows for arbitrary arguments. Additionally, the values are case insensitive so the argument tlsv1.2 is equivalent to TLSv1.2.

  2. Restarting big3d is required to re-establish the iQuery connection. This action should not be traffic impacting.
    bigstart restart big3d

  3. This system database variable is not synced to an HA peer and must be set individually. If necessary repeat the procedure on other device group members.

Additional Information

An iQuery connection is an SSL connection on port 4353 from a gtmd process to the big3d process on a remote or local BIG-IP. When big3d starts, it listens on port 4353 on all configured self IP addresses and the management interface IP address. By default the local gtmd process establishes an iQuery SSL connection to the remote big3d process using version TLS1.0 or higher. In some situations this SSL connection needs to run at a higher TLS version.
