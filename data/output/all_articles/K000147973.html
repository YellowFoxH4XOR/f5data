Working with SRV Records

SRV records are to discover available services using DNS-based service discovery. Records must contain service and protocol, which make up the record name. 

 

The following values are required with an SRV record: 

  • service: the symbolic name of the desired service.
  • proto: the transport protocol of the desired service; this is usually either TCP or UDP.
  • name: the domain name for which this record is valid, ending in a dot.
  • TTL: standard DNS time to live field.
  • SRV: Type of Record.
  • priority: the priority of the target host, lower value means more preferred.
  • weight: A relative weight for records with the same priority where a higher value indicates a higher chance of being selected by a client.
  • port: the TCP or UDP port on which a client can access the service.
  • target: the canonical hostname of the machine providing the service, ending in a dot.

 

 

For example, the following SRV records enable service discovery for Microsoft 365:

      _sip._tls.example.com. 3600 IN SRV 100 1 443 sipfed.online.lync.com.

      _sipfederationtls._tcp.example.com. 3600 IN SRV 100 1 5061 sipfed.online.lync.com.

 

Targets defined in an SRV record must point to a hostname with an A or AAAA address record. The target must not use a hostname associated with a CNAME record.

 

The SRV record specification is defined in RFC 2782 & RFC 6186.
