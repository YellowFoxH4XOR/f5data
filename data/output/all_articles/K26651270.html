Topic

You should consider using this procedure under the following condition:

  • You require the BIG-IP Fraud Protection Service (FPS) module to send FPS alerts to a remote logging node by way of HTTPS.

Description

In BIG-IP 12.0.0 and later, you can configure the BIG-IP FPS module to send FPS alerts to a remote logging node using HTTPS as a communication channel. This method is not supported in versions prior to BIG-IP FPS 12.0.0.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have a BIG-IP system licensed and provisioned with an FPS module.
  • Have a remote logging node that supports HTTPS for receiving logs.
  • Have administrative access to the TMOS Shell (tmsh).
  • Have an IP address for the dummy virtual server that is used for HTTPS communications.

Procedures

To configure the BIG-IP FPS to send FPS alerts to a remote logging node by way of HTTPS, you must perform the following procedures:

  • Configuring the remote logging node pool
  • Configuring the log destination and publisher
  • Configuring the FPS profile
  • Configuring the iRule to disable SSL for non-alert-path traffic
  • Configuring the FPS pool and virtual server

Configuring the remote logging node pool

To use the remote logging node as the Alert Pool for an FPS profile, you must configure it in a pool. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create a pool, and add the remote logging node to the pool using the following command syntax:

    create ltm pool <name> members add { <remote logging node IP>:443 }

    For example, you would enter the following command to add remote logging node 192.168.1.196 to the pool alert_pool:

    create ltm pool alert_pool members add { 192.168.1.196:443 }

  3. Save the changes by typing the following command:

    save sys config

Configuring the log destination and publisher

To use the remote logging node as the Log Publisher for the FPS profile, you must first create a dummy virtual server (for HTTPS communications), then a dummy node, as well as a dummy pool, before using them for the log destination and log publisher. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create the dummy virtual server, and use the remote logging node pool from the previous procedure as its pool, by using the following command syntax:

    create ltm virtual <name> { destination <IP address>:80 profiles add { <server SSL profile name> {context serverside} tcp {} } snat automap pool <remote logging node pool name> }

    For example, you would type the following command to create the dummy virtual server alert_pool_vs with IP address 172.16.33.50, as well as server SSL profile serverssl, and add the pool alert_pool, created in the previous procedure:

    create ltm virtual alert_pool_vs { destination 172.16.33.50:80 profiles add { serverssl {context serverside} tcp {} } snat automap pool alert_pool }

  3. Create the dummy node using the dummy virtual server address, by using the following command syntax:

    create ltm node <name> { address <dummy vs IP address> description <description> }

    For example, you would type the following command to create the dummy node vs_node using the dummy virtual server address 172.16.33.50 from the previous example:

    create ltm node vs_node { address 172.16.33.50 description “dummy virtual server node” }

  4. Create the dummy pool using the dummy node that you created in the previous step, by using the following command syntax:

    create ltm pool <name> { members add { <node name>:http } }

    For example, you would type the following command to create the dummy pool alert_pool_thru_vs using the dummy node vs_node from the previous example:

    create ltm pool alert_pool_thru_vs { members add { vs_node:http } }

  5. Create the log destination using the dummy pool that was created in the previous step by using the following command syntax:

    create sys log-config destination remote-high-speed-log <log destination name> { pool-name <pool name> protocol tcp }

    For example, you would type the following command to create log destination alert_server using the dummy pool alert_pool_thru_vs from the previous example:

    create sys log-config destination remote-high-speed-log alert_server { pool-name alert_pool_thru_vs protocol tcp }

  6. Create the log publisher using the log destination that you created in the previous step using the following command syntax:

    create sys log-config publisher <log publisher name> { destinations replace-all-with { <log destination name> } }

    For example, to create log publisher alert_publisher using log destination alert_server from the previous step, type the following command:

    create sys log-config publisher alert_publisher { destinations replace-all-with { alert_server } }

  7. Save the changes by typing the following command:

    save sys config

Configuring the FPS profile

You can configure the FPS profile to use the remote logging node as its Alert Pool and Log Publisher by performing the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create an FPS profile and configure the Alert Pool and Log Publisher settings to use the objects you created in the previous procedures, by using the following command syntax:

    create security anti-fraud profile <name> alert-publisher <log publisher name> alert-pool <pool name>

    For example, you would type the following command to create the FPS profile demo_bank_prof, and configure the Alert Pool and Log Publisher settings to use alert_pool and alert_publisher respectively:

    create security anti-fraud profile demo_bank_prof alert-publisher alert_publisher alert-pool alert_pool

  3. Configure the rest of the settings in the FPS profile, as needed
  4. Ensure that the FPS alerts to the Alert Pool remains HTTPS, by typing the following command:

    modify sys db antifraud.disableserversidessl.alert value false

  5. Save the changes by typing the following command:

    save sys config

Configuring the iRule to disable SSL for non-alert-path traffic

You must also create an iRule to disable SSL for traffic that is not destined to the alert path. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create the iRule by using the following command syntax:

    create ltm rule <iRule name>

    For example, you would type the following command to create the iRule /Common/sol26651270_ssl_disable:

    create ltm rule /Common/sol26651270_ssl_disable

  3. The previous step invokes a vi editor; type the following iRule syntax:

    when HTTP_REQUEST {
            if { [HTTP::path] ne "stats" } {
                if { [catch { SSL::disable serverside } ] } {
                }
            }
    }

  4. When you are done with the iRule syntax, exit the vi editor by typing the following key sequence:

    :wq!

  5. When tmsh prompts you to save the changes, type y.

    The system saves the changes.

Configuring the FPS pool and virtual server

You can now create the FPS pool, as well as the FPS virtual server, with settings applicable to your environment. You must also associate the FPS profile and iRule that you created in the previous procedures, to the FPS virtual server. For more information about creating the pool and virtual server, refer to the About Pools and About Virtual Servers sections, respectively, in the BIG-IP Local Traffic Management: Basics guide.
