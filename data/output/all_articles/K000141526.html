Topic

This article discusses the behaviour for BIG-IP Edge Client on Windows clients. For MAC clients, refer to K000150860: BIG-IP Edge Client on MAC Systems uses default browser for authentication.

Important: Beginning in BIG-IP 21.1.0 and APM Client 7.2.7 (both required), BIG-IP Edge Client Windows no longer requires iRules to use the default browser for authentication; you can use this feature, without performing the steps in the Procedure section.

Description

Beginning from APM Client 7.2.5.1, you can now configure BIG-IP Edge Client to use the default browser on your Windows client for authentication. Before this, BIG-IP Edge Client uses the embedded browser. This article describes what you should do to configure BIG-IP Edge Client to use the default browser on Windows client for authentication when connecting to VPN.

In APM Clients 7.2.5.0, BIG-IP Edge Client supports Windows Default Browser Authentication for the access policy with Modern customization only. However, starting from APM Client 7.2.5.1, BIG-IP Edge Client now supports Windows Default Browser Authentication for both Standard and Modern customization types.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You configured a BIG-IP APM virtual server with an access policy that authenticates VPN Windows clients with authentication.
  • You update to APM Clients 7.2.5.1 or later.
  • There is no HTTP/2 profile attached to the VPN Virtual Server ("ACCESS::restrict_irule_events disable" command, used as part of the iRule delivered for this solution, is not compatible with HTTP/2 profile - RFE is tracked with ID 1013173).

Procedure

To configure BIG-IP Edge Client to use the default browser on Windows client for authentication perform the following procedures:

  1. On the BIG-IP APM
    1. Download the iRule and iFiles available on F5 downloads as a zip file based on the Access Policy customization type you are using:
      1. If you are using the Modern customization Access Policy, download the file Default_Browser_edgeClient_v5.zip.
      2. If you are using the Standard customization Access Policy, download Default_Browser_windows_edgeClient_standard_V3.zip
        Note: The file is located in the Group = BIG-IP, Product Line = APM Clients, Product Version = 7.2.5.1 product container.
    2. Create an iRule. To do so on the Configuration utility, go to Local Traffic > iRules > iRule List +. (The name of the iFiles should be left unchanged when creating them as the iRule references those files)
    3. Create an iFile. To do so on the Configuration utility, go to Local Traffic > iRules > iFile List +.
    4. Associate the iRule to your BIG-IP APM virtual server.

  2. On Windows Client(s)
    To enable use of the default system browser for authentication, you create the following Windows registry key on your Windows client(s) with the DWORD value 1 at the following location: Computer\HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\F5 Networks\RemoteAccess.

    To do so, depending on your deployment, perform one of the following 3 procedures:
    1. Create Windows registry key manually on Windows:

      You can perform this procedure, together with automatic client update (Component Update set to yes) configured in the connectivity profile. After you update APM Clients, when clients connect to establish VPN, BIG-IP Edge Client automatically updates. 
      To create the registry key on your organization's Windows clients, you can use regedit on a single Windows client or Group Policy in Windows Active Directory Domain Services for a group of clients.

      DWORD keyValuesDescription
      UseExternalBrowserForAuth0 (default)
      1

      Authentication happens in BIG-IP Edge Client embedded browser
      Authentication happens on system default browser

    2. Create a customized BIG-IP Edge Client installer for distribution and installation on Windows clients:
      Perform the following procedure:
      1. Download the BIG-IP Edge Client package from the connectivity profile. On the Configuration utility, go to Access > Connectivity/VPN > Connectivity > Profiles.
        Select the name of the profile and Customize Package and Download.
      2. Open the downloaded package, BIGIPEdgeClient.exe, with an archive manager and extract the files to a new folder.
      3. Browse to the folder F5 VPN inside the extracted folder
      4. Edit the file config.f5c using a text editor by adding the following config directly below <PROFILE VERSION="2.0">
        <USE_DEFAULT_BROWSER>YES</USE_DEFAULT_BROWSER>

        The configuration looks similar to the following:

        <PROFILE VERSION="2.0">
        <USE_DEFAULT_BROWSER>YES</USE_DEFAULT_BROWSER>
        <ALLOW_HTTP_CONNECTIONS>NO</ALLOW_HTTP_CONNECTIONS>

      5. Use a archive manager to create a zip file containing the following (F5 VPN, _setup_configuration_.f5c, , f5fpclients.msi)
        Name it BIGIPEdgeClientUpdated.zip.
      6. Download file setupstub.exe from your virtual server from the following location:
        https://<VirtualServer>/public/download/setupstub.exe
      7. Copy setupstub.exe to the same directory as BIGIPEdgeClientUpdated.zip.
      8. Merge setupstub.exe and BIGIPEdgeClientUpdated.zip (created in step V) using the following command:
        copy setupstub.exe /b + BIGIPEdgeClientUpdated.zip /b BIGIPEdgeClientUpdated.exe
      9. Distribute BIGIPEdgeClientUpdated.exe to your Windows client devices for installation.

    3. Install BIG-IP Edge Client using msiexec the command line:
      To create the required registry key when you install the BIG-IP Edge Client using the msiexec command, you set <EXTERNALBROWSERAUTH> to 1 using the following command syntax:

      msiexec /i f5fpclients.msi /qn EXTERNALBROWSERAUTH=<Value 0 or 1> /l*vx msiInstallerLog.txt

      <EXTERNALBROWSERAUTH> 

      0 - Use Embedded browser for Authentication
      1 - Use Default browser for Authentication

      For more information on how to use msiexec, refer to K13710: Installing BIG-IP Edge Client from the Windows command line.

Additional Information

You need to configure additional settings if your deployment contains the following specific use cases:

  • When your deployment contains redirection from one virtual server to another one, append %{session.server.landinguri} to the redirection URL. For example: 

    https://<VS:PORT>%{session.server.landinguri}

  • Review any Landing URI agents in your access policy, and update the expression.
    Note: The Landing URI agent is found in the visual policy editor's Endpoint Security (Server-Side) tab
    From
    expr {[mcget {session.server.landinguri}] == "/uri1" || [mcget {session.server.landinguri}] == "/uri1/"}
    To
    expr {[mcget {session.server.landinguri}] == "/uri1" || [mcget {session.server.landinguri}] starts_with "/uri1"}
