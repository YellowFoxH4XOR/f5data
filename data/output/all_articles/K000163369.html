Description

The F5OS diag-controller interface may report the following generic warning:

Component Health Changed component="appliance/hardware" severity="Warning" interface="diag-controller"

The event indicates that diag-agent failed to change a component health state. It does not identify the affected component, attribute, or current health state.

Environment

  • F5OS on an rSeries appliance
  • Alert component: appliance/hardware
  • Alert interface: diag-controller
  • Alert severity: Warning

Cause

The cause cannot be determined from the generic event alone. The message does not provide sufficient information to confirm a hardware fault or identify a specific affected component.

Answer/Recommended Actions

Note: The component query is a read-only listing operation and does not modify the appliance configuration.

1) Check the appliance health summary (with 'admin' account):

# show system health summary

2) Check for active system alarms (with 'admin' account):

# show system alarms | tab

3) Check the health of individual components (with 'admin' account):

# show system health components

4) Retrieve the hardware component list and health information:

Note: For running this command, you need to run it with 'root' account.

# docker exec -it diag-agent psf call get:components \$filter="key matches 'hardware'"

5) Correlate the warning with individual component status and associated alarms.

6) If a component reports an unhealthy state or a related alarm is present, collect the component status and a host-level QKview for further investigation.

7) If no unhealthy component or related alarm is present, no corrective action is required for the generic message alone.

Additional Information

  • A Warning severity alone does not confirm that a hardware component is unhealthy.
  • F5OS health-state mapping treats Warning, Notice, and Info severities as healthy pending further review. Severities from Emergency through Error indicate an unhealthy state.
  • The F5OS Error Catalog documents the Component Health Changed messages as having no listed impact or recommended action.
  • The alert should be treated as an indication requiring component-level correlation, not as confirmation of a hardware failure.
