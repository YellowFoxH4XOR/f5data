Issue

Error Message

crit tmm1[<PID>]: 01790602:2: [C] <src_IP_port> -> <dst_IP_port>: (<ERR_MESSAGE>) URL category lookup failed

In this error message, note the following:

  • <PID> is the process ID for the Traffic Management Microkernel (TMM) process.
  • <src_IP_port> is the source IP address and port number of the HTTPS connection.
  • <dst_IP_port> is the destination IP address and port number of the HTTPS connection.
  • <ERR_MESSAGE> can be either one of the following:
    • <ERR_CONN>
    • <ERR_LICENSE>

For example:

crit tmm1[10075]: 01790602:2: [C] 10.10.0.1:5060 -> 10.20.0.1:5060: (ERR_CONN) URL category lookup failed
info tmm1[10075]: 01870003:6: /Common/example_accessProfile:Common:4ccc8824: Agent created variable name: perflow.category_lookup.failure, value: 1
crit tmm1[10075]: 01790602:2: [C] 10.10.0.1:5060 -> 10.20.0.1:5060: (ERR_REJECT) Error processing URL Classification query from CatEngine

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file

Description

This message occurs when all of the following conditions are met:

  • The BIG-IP system does not have Secure Web Gateway (SWG) or URLDB provisioned.
  • You have a per-request policy that performs any one of the following Category Lookup types:
    • Custom categories first, then standard categories if not found
    • Always process full list of custom and standard categories
    • Process standard categories only

When SWG or URLDB is not provisioned, the Category Lookup Type for all Category Lookups in the per-request policy must be Process custom categories only. When you configure this on the Visual Policy Editor of the per-request policy, the categorization input field for Category Lookup Type will only have the Process custom categories only option.

Impact

The Category Lookup action in the per-request policy fails and the BIG-IP system resets the HTTPS connection.

Recommended Actions

The specific cause and conditions leading to the error message varies. In general, to resolve or work around the issue, you can perform one of the following procedures:

  • License and provision SWG or URLDB on your BIG-IP system and wait for the categorization database to download.
  • Modify the Category Lookup action in the per-request policy on the Visual Policy Editor to Process custom categories only.
