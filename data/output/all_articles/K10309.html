K10309: Non-English characters in a user ID are incorrectly encoded when accessing a website that requires NTLM

Known Issue

This is the result of a known issue. When non-English characters are used in a user ID, users experience authentication failures when Proxy NTLM is enabled for the master group. Rather than encoding the non-English characters to Unicode, they are encoded as ASCII. For example, if the Russian letter Y is in the user's ID, FirePass encodes it as 0x00e9 in ASCII, rather than 0x0049 in Unicode. Because the site to which the user is trying to connect is expecting the Unicode information, the site rejects the authentication and the user is prompted for their credentials again.

F5 Product Development tracked this issue as CR123248 and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative hotfix HF-603-4.2 issued for FirePass version 6.0.3. You may download these hotfixes or later versions of the cumulative hotfix from the F5 Downloads site.
