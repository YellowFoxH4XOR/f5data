Description

You have replaced the device certificate with a new one signed by your organisation's CA. The change resulted in losing access to Configuration utility (GUI), but you can log in using CLI. The MD5 checksums of the certificate and key match.

Environment

  • BIG-IP
  • Replacing device certificate
  • CA signed device certificate

Cause

The new certificate does not include client authentication (clientAuth) and server authentication (serverAuth) extended key usage (EKU) extensions. 

Recommended Actions

1.Log in to BIG-IP command line.

2. Verify if your certificate includes the required extensions:

openssl x509 -noout -purpose -in /config/httpd/conf/ssl.crt/server.crt | grep -iE 'client|server'

3. The command output should show "Yes" for both SSL client and SSL server:

SSL client : Yes
SSL client CA : No
SSL server : Yes
SSL server CA : No

 

4. If the certificate is missing any of the required extensions, generate a new CSR and submit it to your organisation's CA to sign. For more information refer to K51035715: Replace the Configuration utility's self-signed device certificate with a certificate signed by your organization's CA.

Additional Information

To avoid losing access to Configuration utility, you can verify if the required extensions are included in the certificate before installing it. Once the certificate file is transferred to /var/tmp, execute the following and verify if SSL client and SSL server are set to "Yes":

openssl x509 -noout -purpose -in /var/tmp/<cert_name> | grep -iE 'client|server'
