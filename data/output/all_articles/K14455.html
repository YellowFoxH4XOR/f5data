Known Issue

The BIG-IP system may erroneously loop multicast or broadcast IPv4 or IPv6 packets back to the transmitting interface.

This issue occurs when the following conditions are met:

  • The system transmits IPv4 or IPv6 packets to Ethernet multicast or broadcast addresses on the small form-factor pluggable (SFP) (2.x) interfaces
  • The BIG-IP platform is one of the following:

    • BIG-IP 2000s, 2200s (C112)
    • BIG-IP 4000s, 4200v (C113)

When the BIG-IP system transmits multicast or broadcast traffic through a 2.x interface on a Traffic Management Microkernel (TMM) instance other than TMM0, the traffic may be looped back to TMM0's receive queue for that interface.

Impact

The forwarding database (FDB) table may contain incorrect entries for the source MAC address, resulting in a possible traffic disruption.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  •  BIG-IP iHealth lists Heuristic H422726 on the Diagnostics > Identified > High screen.
  • The system may experience a traffic disruption.
  • The FDB table may contain incorrect entries for the source MAC address if the multicast IP packet is being bridged through from one interface on the VLAN to another (IPv6 router advertisements, for example).
  • The tcpdump utility captures may show an inbound echo of some outbound L2 multicast IP traffic on the 2.x interfaces.

Workaround

To work around this issue, you can replace an entry in the /etc/init.d/stratospfinit file. To do so, perform the following procedure:

Impact of workaround: The following procedure requires restarting the BIG-IP system and should be performed during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Use a text editor to edit the /etc/init.d/stratospfinit file.

    For example:

    vi /etc/init.d/stratospfinit
  3. Locate the following line:

    modprobe ixgbe max_vfs=$vfs,$vfs force_rss_sriov=1,1 lacp_target_queue=1,1 >/dev/null 2>&1
  4. Replace the line with the following:

    modprobe ixgbe max_vfs=$vfs,$vfs force_rss_sriov=1,1 lacp_target_queue=1,1 L2LBen=0,0 >/dev/null 2>&1
  5. Save the changes and exit the file.
  6. Restart the BIG-IP system.
