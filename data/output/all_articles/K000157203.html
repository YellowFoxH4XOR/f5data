Description

When deploying a new tenant on F5OS, the tenant may fail to start and remain stuck in the "deployed Starting Unavailable" state. System logs may display repeated errors such as:

Multus: [default/virt-launcher-] error getting pod: Unauthorized

failed to setup network for sandbox: Multus: error getting pod: Unauthorized

Failed to create sandbox for pod: rpc error: code = Unknown desc = failed to setup network for sandbox: Multus: error getting pod: Unauthorized

These errors indicate that the Multus CNI plugin is unable to authenticate with the Kubernetes API, which prevents proper network setup for the tenant.

Environment

  • F5OS version 1.5.1
  • Platform: F5-BIG-LTM-R10600, C128
  • Multus CNI plugin used for Kubernetes networking
  • Tenant deployment on rSeries appliance
  • Recent action: Creation of a new tenant with a larger disk following a security upgrade

Cause

Bug ID 1694481

Recommended Actions

  1. Refresh the Multus Service Account Token
    - Delete the Multus pod to force Kubernetes to recreate it and generate a new token:
    kubectl -n kube-system delete pod -l app=multus
    - This refreshes the token and restores authentication between Multus and the Kubernetes API.
  2. Redeploy the Tenant
    - After refreshing the token, move the affected tenant into provisioned state and redeploy it.
  3. Alternative Resolution
    - If unable to run the above command due to CLI restrictions, rebooting the appliance will also refresh the Multus token and resolve this issue.
  4. Optional
    - Verify token expiry before and after restarting pods as described in referenced KBs.

Additional Information

  • The underlying issue is an expired Multus service account token blocking tenant networking.
  • Both deleting the Multus pod or rebooting refreshes this token.
  • This behavior is tracked under Bug ID1694481.
