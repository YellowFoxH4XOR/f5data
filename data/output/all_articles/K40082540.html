Known Issue

An iRule node selection may not function as expected.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP virtual server is configured with an iRule.
  • The iRule uses the LB_SELECTED event in conjunction with the node command.
  • The iRule node command sets a destination node and port.
  • The virtual server port differs from the specified node port.

    Following is an example of the iRule syntax:

    when LB_SELECTED {
           node 10.10.10.100 1234
    }

Impact

Traffic that the system sends to the node does not use the iRules-specified port.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system sends traffic that is processed by the iRule to the specified node using the destination port of the associated virtual server.
  • When you configure the iRule to log the destination port, the iRule reflects the configured node port; however, the actual port that the system uses is the configured destination port of the associated virtual server.

Workaround

To work around this issue, you can use a compatible iRules event type. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click the name of the affected iRule.
  4. Modify the iRule Definition text to use a compatible event type.

    For example, the following is affected iRules syntax, with an event type of LB_SELECTED

    when LB_SELECTED {
           node 10.10.10.100 80    
    }

    The following is an example of iRules syntax with an event type of CLIENT_ACCEPTED:

    when CLIENT_ACCEPTED {
        set selected_node 10.10.10.100
        node $selected_node 80
    }

  5. To save the iRules modification, click update.
