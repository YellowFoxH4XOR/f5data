Topic

You should consider using this procedure under the following condition:

  • You want the BIG-IP Advanced WAF / ASM system to disallow requests using unsafe HTTP methods.

Description

By default, BIG-IP Advanced WAF / ASM security policies allows requests that use the following HTTP methods: 

  • GET
  • HEAD
  • POST

Some HTTP methods are designed for testing and debugging HTTP applications and may not be appropriate or safe to allow in a production environment. For example, the following HTTP methods may pose a security risk as they allow an attacker to perform actions such as, modifying or deleting web server files, uploading malicious files or stealing credentials:

Unsafe methodDescriptionPolicy default
PUTThe PUT method allows a client to modify an existing file or upload a new file to the origin server. An attacker may be able to use the PUT method to upload a malicious file to the server, such as a exe file, or modify an existing file.Disabled
DELETEThe DELETE method allows a client to delete the resource identified by the Request-URI. This method may be used by an attacker to remove files from the origin server or possibly initiate a DoS attack.Disabled
TRACEThe TRACE method echoes the request message back to the client and is often used for debugging an application. This method may be used to initiate Cross-Site Tracing (XST) attacks. XST attacks can be used to steal user’s cookies or expose the user’s Authorization header.Disabled
CONNECTThe CONNECT method is used with proxies to dynamically switch a connection to tunnel mode. This method may allow an attacker to use the origin server as a proxy.Disabled

You may want to verify that your policy has not been modified to allow unsafe HTTP methods. To do so, perform the following procedures.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Disallow unsafe HTTP methods in the security policy (17.x and later)

To disallow unsafe HTTP methods in the security policy for 17.x and later, perform the following steps.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the security policy name.
  4. Under HTTP Message Protection select Headers.
  5. Under Methods, remove the HTTP methods as required.
  6. Select Save.
  7. Select Apply Policy.

Disallow unsafe HTTP methods in the security policy (14.x - 16.x)

To disallow unsafe HTTP methods in the security policy for 14.x - 16.x, perform the following steps.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the Configuration utility.
  2. Go to Security > Application Security > Headers > Methods.
  3. Select the security policy name from the menu.
  4. Under HTTP Message Protection select Headers.
  5. Under Allowed Methods, remove the HTTP methods as required.
  6. Select Save.
  7. Select Apply Policy.

Modify the Learning and Blocking Settings for Illegal methods

To modify the Learning and Blocking Settings for Illegal methods, perform the following steps.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings > Headers.
  3. For Illegal Methods, select Learn, Alarm, Block as required.
  4. Select Save.
  5. Select Apply Policy.
