The ltm nat feature (as opposed to the ltm snat feature, which provides secure nat translation) provides unrestricted access to a pool member (or any other IP address reachable via the LTM) via an external-facing different IP address, for example you can use it to allow traffic hitting 100.0.0.1 to traverse through the BIG-IP to an internal address such as 192.168.1.1 without restriction.

It is possible for an ltm nat to be configured to translate from an external address onto a local self-ip, which performs the same way, and effectively bypasses port lockdown settings that may be applied to that self-ip, allowing traffic sent to the translation address to unconditionally reach the self-ip, allowing access to services such as ssh and the BIG-IP web-based graphical user interface.

For example:

tmsh create net self test-ip {
    address 1.0.0.1/24
    vlan test
    allow-service none
}
tmsh create ltm nat test-nat {
   originating-address 1.0.0.1
   translation-address 1.0.0.2
}

$ telnet 1.0.0.1 80
Trying 1.0.0.2...
telnet: Unable to connect to remote host: Connection timed out

$ telnet 1.0.0.2 80
Trying 1.0.0.2...
Connected to 10.0.0.2.
Escape character is '^]'.

Environment

  • self-ip address(es)
  • ltm nat, configured with an originating address which is the same as a self-ip on the same box.

Recommended Actions

If you are required to translate another address onto a self-ip, then consider using the more flexible ltm snat object, rather than an ltm nat. For more information on SNAT feature, refer to K7820: Overview of SNAT features.

Additional Information

This feature is working as designed. This article was created because the feature can be configured in a manner that unexpectedly allows access to services. For information about BIG-IP port lockdown behavior, refer to K17333: Overview of port lockdown behavior (12.x - 16.x).
