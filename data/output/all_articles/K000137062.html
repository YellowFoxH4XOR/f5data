Description

An irule configured with RESOLV::lookup, in a specific route domain, may fail after upgrading to 15.x or 16.x. The error "Route domain not reachable (strict mode)." may appear in /var/log/ltm.

 

Environment

  1. irule configured with RESOLV::lookup and is pointing to the name of the virtual server.
  2. the irule is in a custom route domain.
  3. the route domain's parent is set to none.
  4. the target virtual is in the same custom route domain.
  5. after upgrading from 14.x to 15.x or 16.x the RESOLV::lookup fails.

      Cause

      This is caused by RESOLV::lookup being unable to find the virtual server by name in the current route domain and trying to reach out to a parent route domain, which isn't configured.

       

      The RESOLV::lookup @<virtual name> doesn't have the ability to specify the route domain ID, which appears to be leading to this behavior.

       

      Starting 15.x and 16.x the RESOLV::lookup command is deprecated and our suggestion is to use RESOLVER::name_lookup instead.

       

      Recommended Actions

      To workaround this problem, the irule can be modified to reference the IP address with the route domain tag. For example:

      RESOLV::lookup <10.20.30.40%2>

      This will allow the irule to query the IP address directly in the specific route domain.
