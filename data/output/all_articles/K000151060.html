K000151060: Altering the disk size or changing the allowed blade slots (Resource Provisioning Slots) for BIG-IP tenants on F5OS (VELOS) results in the loss of tenant configuration.

Description

Altering the disk size or changing the allowed blade slots (Resource Provisioning Slots) for BIG-IP tenants on F5OS (VELOS) results in the loss of tenant configuration.

After such changes, tenants are redeployed with only the base image and all previous configuration is erased. No specific error message is displayed, but upon redeployment, the tenant appears empty and unconfigured.

Environment

  • F5OS - Chassis (VELOS)
  • Actions that trigger this issue:
    • Disk resizing
    • Changing Resource Provisioning Slots (blade allocation)
    • Redeploying tenants via GUI

Cause

When disk size or allowed blade slots for a tenant are changed, F5OS removes the existing tenant instance and creates a new one with updated resource parameters. This process wipes all previous configuration from the tenant and loads only the base image. Tenant configuration is not included in F5OS partition or chassis backups; it must be backed up separately using UCS archives. This behavior is by design to ensure consistency after significant resource changes.

Recommended Actions

  • Always create a UCS backup of each tenant before making any changes to disk size or allowed blade slots.
  • After resizing disks or changing blade allocation, restore the tenant’s configuration from the previously saved UCS backup.
  • Ensure that the BIG-IP version running on the tenant matches what was used when creating the UCS backup before restoring.
  • If encrypted objects exist in your configuration and you do not know their passwords/passphrases, copy the master key from a peer system using f5mku -K prior to restoring UCS.
  • Allowing a tenant to use more blades increases redundancy and performance but does not multiply assigned resources per blade; resources are shared across blades.
  • Verify all blades are healthy and have required software images before changing blade allocation.
  • For detailed steps on resizing disks or changing blade allocations without data loss, refer to official F5 documentation.
