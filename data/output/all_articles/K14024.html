K14024: Requests that exceed the large request limit may not be terminated

Known Issue

The BIG-IP system may incorrectly process a request that exceeds the configured large request limit.

This issue occurs when all of the following conditions are met:

  • An HTTP request exceeds the long_request_buffer_size value.
    (The default value is 10 megabytes.)
  • The Request Length Exceeds Defined Buffer Size request check is set to Block.

When a request exceeding the long_request_buffer_size is detected, the BIG-IP PSM process generates a violation and stops processing the request, but may not instruct TMM to immediately terminate the connection. TMM may continue to keep the connection open after the limit has been reached.

Impact

Performance may degrade over time and the system may eventually become unresponsive due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • TMM may crash with a SIGABRT, and core files named similarly to the following example may be written to the /var/core directory:

    tmm.0.bld297.0.core.gz

  • Memory allocation errors that appear similar to the following examples may be written to the /var/log/ltm file:

    01010004:3: Memory allocation failed: cn_io
    01010004:3: Memory allocation failed: ssl_hs

  • If enough large connections are simultaneously open, the connection sweeper may enter aggressive mode and write messages to the /var/log/ltm file that appear similar to the following example:

    011e0002:4: sweeper_update: aggressive mode activated. (254159/299008 pages)

Workaround

None. In fixed versions of the BIG-IP PSM system, you can configure the behavior of the system when the large_request_buffer value is exceeded by following the steps detailed in K14034: Configuring large request processing for the BIG-IP PSM system.
