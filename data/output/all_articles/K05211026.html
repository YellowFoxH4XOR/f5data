Issue

Error Message

SSL error: error:14094418:SSL routines:ssl3_read_bytes:tlsv1 alert unknown ca

gtmd example:

f5_DNS_1 err gtmd[21233]: 011ae0fa:3: iqmgmt_ssl_connect: SSL error: error:14094418:SSL routines:ssl3_read_bytes:tlsv1 alert unknown ca (336151576) from connection 10.1.1.34

big3d example:

f5_LTM_1 err big3d[24231]: 012b300e:3: SSL Error: error:14094418:SSL routines:ssl3_read_bytes:tlsv1 alert unknown ca on connection to ::ffff:10.1.1.33:45076

Message Location

You may encounter this message in the following location:

  • The /var/log/gtm file

Description

This message occurs when the following condition is met:

  • The BIG-IP DNS system (formerly known as BIG-IP GTM) is configured to use iQuery to monitor a remote BIG-IP device.

Additionally, this message occurs when any of the following conditions are met:

  • The BIG-IP DNS device certificate is not added to the authorized list on the remote BIG-IP device. (gtmd error)
  • The remote BIG-IP device certificate is not added to the authorized list on the BIG-IP DNS. (big3d error)

Impact

iQuery fails to establish.

Recommended Actions

The recommended actions depend on the type of certificate you have installed on your BIG-IP DNS system.

  • If your BIG-IP DNS and remote BIG-IP systems use self-signed device certificates, you need to perform only the first procedure.
  • If your BIG-IP systems use third-party signed certificates and you included the CA certificates with the device certificate in the /etc/httpd/conf/ssl.crt/server.crt file, you need to perform only the first procedure.
  • If your BIG-IP DNS system uses a third-party signed certificate and you are getting the gtmd error, you must perform Adding the CA certificate to the remote BIG-IP system.
  • If your remote BIG-IP system uses a third-party signed certificate and you are getting the big3d error, you must perform Adding the CA certificate to the BIG-IP DNS system

Exchange system SSL certificates

The bigip_add script appends the local BIG-IP DNS system's SSL certificate to the remote BIG-IP system's list of authorized certificates (contained in the /config/big3d/client.crt file). The script then appends the remote BIG-IP system's iQuery SSL certificate to the BIG-IP DNS system's local list of authenticated iQuery SSL certificates (/config/gtm/server.crt). To run bigip_add, perform the following procedure:

Note: For more information about the bigip_add utility, refer to K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities (11.x - 16.x).

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the local BIG-IP DNS system.
  2. Exchange certificates using the following command syntax:

    bigip_add <remote BIG-IP device IP>

Add the CA certificate to the remote BIG-IP system

If the local BIG-IP DNS system uses a CA signed certificate, add the CA certificate to the list of authorized certificates on the remote BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the remote BIG-IP device.
  2. Go to System > Certificate Management > Device Certificate Management > Device Trust Certificates.
  3. Select Import.
  4. Ensure Append is selected for Import Method.

    Note: If there are no existing certificates, the Import Method option is not available.

  5. Paste the CA certificate in the Certificate Source box.
  6. Select Import.

Add the CA certificate to the BIG-IP DNS system

If the remote BIG-IP system uses a CA signed certificate, add the CA certificate to the list of authorized certificates on the local BIG-IP DNS system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the BIG-IP DNS system.
  2. Go to DNS > GSLB > Servers > Trusted Server Certificates.
  3. Select Import.
  4. Ensure Append is selected for Import Method.

    Note: If there are no existing certificates, the Import Method option is not available.

  5. Paste the CA certificate in the Certificate Source box.
  6. Select Import.
