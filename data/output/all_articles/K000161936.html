Description

This article demonstrates how to quickly deploy the F5 Journeys tool, which can be used to migrate BIG-IP configuration from a legacy platform to a modern one running a newer software release. For more information on the tool itself, refer to K000137313

Environment

The journeys tool is provide as a tarball, which can be downloaded from the 'My F5 Downloads' site, and contains several docker images, which can be run in an air-gapped or offlne environment, as well as in fully online mode, where it has direct network connectivity to the target system

The tool requires the docker, and docker compose packages to already be installed on a suitable linux system. F5 recommends Ubuntu Server, but any modern linux distribution should be suitable, including Windows Support for Linux version2 (WSLv2), allowing for the tool to be used on a system running the Microsoft Windows operating system.

Note:  When deploying the tool under WSLv2, the WSL environment must first be configured to support nested virtualization, so that docker can access the virtualization hardware from within the WSL virtual linux machine.  This can be done by adding the keyword 'nestedVirtualization=true' to the [wsl2] section of your .wslconfig file, and restarting the WSL environment. For more information on configuring the WSL environment, refer to Microsoft's WSLv2 documentation. If you are not sure whether nestedVirtualization is enabled within WSL, install the 'cpu-checker ' package, then execute the resulting 'kvm-ok' utility - it should report that /dev/kvm exists, and that KVM acceleration can be used.

Ensure that both the docker and docker-compose-v2 packages are installed prior to deploying the journeys tool.

Deploying the tool

  1. Download the journeys tool, and copy it to the target linux system
  2. Extract the contents of the tarball (.tgz file) into a suitable location on the linux system
    tar zxvf f5-journeys*
  3. If necessary, Install the docker.io and docker-compose-v2 packages
    apt -y install docker.io docker-compose-v2
  4. Ensure that docker is accessible to the current user
    docker version
    docker compose version
  5. Change to the f5-journeys folder
    cd f5-journeys
  6. Run the installation script to install the bundled docker images
    ./install.sh
  7. Copy the default sample enviroment settings to .env
    cp sample.env .env
  8. Verify that the default settings defined in .env are suitable (tcp listening port JOURNEYS_PORT, location of working folder WORKING_FOLDER)
    (check/edit contents of the .env file - the working folder location should exist, and initially be empty of files, especially after upgrading to a newer version of the journeys tool)
    mkdir /tmp/journeys 
  9. Bring the docker containers up using docker compose v2:
    docker compose up -d
  10. Verify that the containers came up and are stable.  Output should look similar to this:
    ~/f5-journeys$ docker compose ps
    NAME                          IMAGE                                                 COMMAND                  SERVICE         CREATED        STATUS        PORTS
    f5-journeys-acc-1             f5devcentral/f5-automation-config-converter:1.126.0   "/usr/local/bin/node…"   acc             5 minutes ago   Up 5 minutes
    f5-journeys-celery-worker-1   f5devcentral/f5-bigip-journeys-app:v4.2.2             "/code/entrypoint.sh…"   celery-worker   5 minutes ago   Up 5 minutes
    f5-journeys-journeys-1        f5devcentral/f5-bigip-journeys-app:v4.2.2             "/code/entrypoint.sh…"   journeys        5 minutes ago   Up 5 minutes   127.0.0.1:8443->443/tcp
    f5-journeys-postgres-1        postgres:16.10-alpine3.22                             "docker-entrypoint.s…"   postgres        5 minutes ago   Up 5 minutes   5432/tcp
    f5-journeys-redis-1           redis:8.2.2-alpine3.22                                "docker-entrypoint.s…"   redis           5 minutes ago   Up 5 minutes   6379/tcp
  11. Troubleshoot docker if any of the containers are restarting, or showing errors.  View the container logs as required:
    # if required for troubleshooting:
    docker compose logs -f
    cat /tmp/journeys/journeys.log
  12. Access the built-in webserver 
    Point your browser at the linux server - https://x.x.x.x:8443 (or the JOURNEYS_PORT specified in the .env file
