Description

When trying to connect to resources configured within an Oracle WebLogic database, Windows clients are unable to connect, but MacOS or Linux-based clients report no issues

  • Resources configured in Oracle WebLogic database as Pool Members
  • TCP SYN to pool member not responded to.
  • Packet capture reports reset reason of "TCP retransmit timeout"
  • Windows users report connection being reset

Environment

  • Oracle WebLogic database virtual server application on BIG-IP
  • pool members UP

Cause

While the BIG-IP is able to mitigate the behaviour causing the connection issue, the root cause is related to the Oracle WebLogic database, and a support case should be raised with Oracle to investigate further.

Investigation by support has found that clients not presenting Timestamps in TCP Options (TSval/ecr) are unable to connect to the Oracle WebLogic database.

Recommended Actions

To resolve the behaviour, TCP Timestamps must be present in the TCP Options in the packets to the Pool Member.
In order to configure the BIG-IP serverside connection to negotiate TCP Timestamps, the following TCP Profile settings MUST be configured on both the clientside and serverside TCP Profiles:

NOTE: Changing these settings will NOT affect currently established TCP connections.

  1. Proxy Maximum Segment: disabled (untick)
  2. Proxy Options: disabled (untick)
