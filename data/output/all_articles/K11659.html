Known Issue

This is the result of a known issue. When the BIG-IP configuration contains a VLAN route that is used to direct traffic to a specific host, the BIG-IP system may send ARP requests without using a valid self IP address as the source IP address in the ARP request. When this issue occurs, the TMM sends the ARP request without changing the source IP address from its original reserved loopback address of 127.1.1.2 or 127.1.1.3 to the self IP address for the VLAN.

For example, in the following configuration, the self IP address 10.10.65.11 resides on VLAN-1 and 10.10.64.11 resides on VLAN-2:

self 10.10.65.11 {
netmask 255.255.255.0
vlan VLAN-1
allow default
}
self 10.10.64.11 {
netmask 255.255.255.0
vlan VLAN-2
allow default
}

The following route overlaps with the 10.10.65.11/24 self IP address, and routes traffic to the 10.10.64.1 gateway via VLAN-2:

route 10.10.65.0/25 {
gateway 10.10.64.1
}

The following VLAN route exists to route traffic from host 10.10.65.1 to VLAN-1:

route 10.10.65.1 {
vlan VLAN-1
}

With the above configuration in place, if you attempt to ping the host defined in the VLAN route (in this case 10.10.65.1) from the BIG-IP system, the BIG-IP system sends ARP requests where the sender protocol address (SPA) field contains a loopback IP address of either 127.1.1.2 or 127.1.1.3. The tcpdump output appears similar to the following example:

The above ARP request is ignored and dropped by the receiving host. This behavior may prevent the BIG-IP monitor requests from reaching the host.

Note: This issue does not occur if the BIG-IP ARP table contains an existing ARP entry for the host defined in the VLAN route.

F5 Product Development is tracking this issue as ID 248014 (formerly CR141338).

Workaround

You can work around this issue by adding a static ARP entry on the BIG-IP system for the host defined in the VLAN route. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Click Network.
  3. Click ARP.
  4. Click Create.
  5. Enter the IP address of the host defined in the VLAN route in the IP Address field.
  6. Enter the MAC address of the host defined in the VLAN route in the MAC Address field.
  7. Click Finished.
