K000148938: F5RST: Malformed HTTP header error when response contains both Transfer-Enconding and Content-Length header

Type
Support Solution
Published
2025-06-04
Updated
2025-06-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 15.1.9, 17.1.2, 17.1.1, 17.1.X, 16.1.6, 16.1.5, 16.1.4, 15.1.10
Source
https://my.f5.com/manage/s/article/K000148938

Description

A virtual server with an associated HTTP profile will reset the connection with "[F5RST(peer): Malformed HTTP header error]" when pool member replies to BIG-IP with non compliance HTTP response.

Environment

  • BIG-IP LTM v17.1.0, v16.1.4, v15.1.9 later
  • HTTP profile

Cause

The error is due to an unexpected HTTP response from pool member contains both Transfer-Encoding and Content-length header.

RFC 7230 defines, "A sender MUST NOT send a Content-Length header field in any message that contains a Transfer-Encoding header field."

There is not a way to disable the RFC enforcement on BIG-IP.

Recommended Actions

Remove Content-length header when Transfer-Encoding header is inserted to HTTP response on pool member.
