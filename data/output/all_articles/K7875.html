K7875: An iRule will incorrectly handle certain values if represented as an escaped string

Topic

Certain data may contain values or characters within the ASCII range that are not printable, but need to be processed by an iRule before load balancing or other handling of the data can occur. The iRule will incorrectly handle these values if represented as an escaped string value.

In the following example, the iRule will collect four bytes when the client has established a connection. When the client sends data, the iRule sends a response back to the client that is similar to the following example:

when CLIENT_ACCEPTED {
  TCP::collect 4
}
when CLIENT_DATA {
  set r "\x00\x01\x02\x00" 
  TCP::respond "$r\r\n" 
  TCP::close
}

In the example iRule, the ASCII: NUL SOH STX NUL string values are defined in the following line:

set r "\x00\x01\x02\x00"

The character definitions are as follows:

HEXASCIIDefinition
00NULnull
01SOHstart of heading
02STXstart of text
0DCRcarriage return
0ALFline feed

The expected result that the client receives in HEX would be similar to the following example:

00 01 02 00 0D 0A

However, the client receives a response similar to the following example, where C0 80 is an illegal UTF-8 sequence for respresenting NULL:

C0 80 01 02 C0 80 0D 0A

The BIG-IP sends the response as string literals because the TCL engine interprets the characters to be UTF-8 encoded characters.

Certain iRule commands, such as respond and playload replace, can process binary data. However in the above case, the TCL engine incorrectly interprets the data within the double quotes as an escaped literal string value, which interprets the value of \x00 as C0 80. The escape character in this example is the backslash (\).

The correct method to handle the information is to specify the values in binary format, using the decimal equivalent of the desired ASCII values.

The following iRule will respond with the correct HEX value, because it specifies binary format and uses the decimal equivalent of the ASCII values in place of the HEX values.

 when CLIENT_ACCEPTED {
  TCP::collect 4
}
when CLIENT_DATA {
  set r [binary format c* { 0 1 2 0 13 10 } ]
  TCP::respond $r
  TCP::close
}

The set r [binary format c* { 0 1 2 0 13 10 } ] line in the iRule sets the variable r to the following equivalent format:

\x00\x01\x02\x00\x0D\x0A

The keyword binary format creates a binary format from normal Tcl values, and c* specifies that the number of elements in the list. In this example, the count is not restricted since a wild card is used.
