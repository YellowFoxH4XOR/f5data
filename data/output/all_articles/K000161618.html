Description 

Starting in version 1.8.0 and continuing in 2.x remote logging can be setup in the GUI for both rSeries and Velos. 

    Environment

    • F5OS version 1.8.0 or later
    • Access to the F5OS GUI with administrative privileges

    There are several things to consider;

    1. Host Log Forwarding must be Enabled.
    2. There are several Selectors. However, the F5OS, system_rsyslogd redirects all logs to facility LOCAL0; this is the only supported facility for remote logging, and it includes platform logs.
      1. The one exception to this is that the Audit logs require the use of a separate Selector selection. K000135458: Missing audit logs on remote logging server - rSeries system
      2. The 'Selectors' section for F5OS uses generic/standard Linux syslog facility codes (RFC 3164). However, only some actually are functional at this point. Some may or may not be used in the future. From the F5OS/rSeries CLI Documentation:

        "F5OS supports only the LOCAL0 logging facility. All logs are directed to this facility, and it is the only one that you can use for remote logging."

    3. The log/host path in the F5OS GUI/CLI maps to the underlying /var/log directory — the standard Linux host OS log directory. The 49 files you see are the actual files present in /var/log on the system (things like messages, secure, cron, dmesg, boot.log, httpd/, container logs, k3s logs, etc. — as documented in K000135261).
    4. Create any Custom log File entries.

    NOTE: Selectors = filter the syslog stream by facility/severity. The log/host file list = forward the content of specific files on disk from the Linux host layer.

    Answer/Recommended Actions

    Configuration:

    1.  In the GUI, navigate to System Settings > Logging > Remote Log Servers.
      1. Enter the remote syslog server’s IP address, protocol (UDP/TCP), port (default: 514), and authentication if required.
      2. Choosing Selectors at this point is not needed.
    2. Host Log Settings:
      1. Enable Host Log Forwarding. 
      2. Selectors:
        1. Select LOCAL0  and the logging level to instruct the system to send F5OS system logs to include the platform log.
        2. For Audit logs it is necessary to enable AUTHPRIV and the logging level.
      3. Log/host and Custom Log File;
        1. In the log/host section, select files from /var/log to forward.
        2. For the Custom Log File enter only the filename (e.g., audit.log, secure). Do not include the path; the system automatically uses /var/log/.
          1. The system will monitor and forward the file if it appears later. If the file appears later, it will be automatically picked up and processed. The following syslog message is expected and informational in this scenario:rsyslogd: imfile: on startup file '/var/log/TEST' does not exist but is configured in static file monitor - this may indicate a misconfiguration. If the file appears at a later time, it will automatically be processed.
          2. This feature is intended for non-syslog-generated text log files residing in the host's /var/log directory. If the file is syslog-generated, it is more efficient to use syslog configuration directly to forward those messages rather than using the file monitoring method.

    Warning: Do not select messages or /var/log/messages as a custom log file. This can cause a logging loop and fill disk space, potentially leading to a system outage (Bug ID 1588093).

    Additional Information

    For advanced use cases, customers may use the user configuration space under /etc/rsyslog.d on the host to forward any desired log files, following standard rsyslogd documentation. 

    File completion works for controller and appliance hosts, as their /var/log directory is mounted and available. For blade hosts, the list of available files is not provided automatically — users must manually identify the relevant files in the blade's /var/log directory.
