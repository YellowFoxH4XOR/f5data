K37734542: Client IP not being passed in AWS

Type
Support Solution
Published
2020-02-04
Updated
2025-02-06
Applies to
  • Public Cloud
  • BIG-IP
  • BIG-IP Cloud Edition
  • Amazon Web Services
Source
https://my.f5.com/manage/s/article/K37734542

Description

If traffic passes through an Amazon Web Services (AWS) Network Load Balancer (NLB) before reaching the BIG-IP it may not pass the real client IP.

Environment

  • Amazon Web Services Network Load Balancer
  • Target group configured with IP based routing
  • BIG-IP instances in AWS

Cause

If the target group is configured with IP based routing, the client IP will not be passed. If the target group is configured with instance-based routing, the Network Load Balancer will only forward traffic to interface eth0.

Recommended Actions

  1. If the real client IP is required, then the target group must be instance-based.  
  2. The Network Load Balancer only forwards traffic to eth0 of the instance.  This may be the management interface.  Using a 1-NIC instance resolves this issue.  If a multi-NIC instance is required, then the management NIC must be switched manually.

Changing the NIC used for BIG-IP VE management

Impact: Performing the following procedure should have an impact on traffic. Perform these steps in maintenance window. 

    1. Stop tmm
      bigstart stop tmm
    2. Change the management NIC by typing 
      tmsh modify sys db provision.managementeth value eth1 
      where eth1 is the NIC you want to use for management. You can use any available NIC.
    3. Reboot the BIG-IP instance
