Description

BIG-IP as IPsec end-point displays more than one pair of phase 2 SAs per remote peer. Usually this does not impact performance, but makes it difficult to identify which SAs are in use and can hinder troubleshooting. Under extreme cases memory issues might occur.

Environment

  • BIG-IP as IPsec end-point using ikeV1 or ikeV2

  • More likely to be seen with remote IPsec peers that are not BIG-IP

Cause

When BIG-IP establishes an IPsec connection to a remote peer, a pair of IPsec (or phase 2) security associations (SAs) are created. One is inbound and one is outbound. The purposes of these SAs are to define the nature of the encryption for traffic to and from the remote peer. The SAs have a lifetime in terms of time and amount of data sent.

For the time based lifetime, each peer will look to rekey the SAs before the lifetime expires. The intention is to have new SAs available in order to send and receive data before the lifetime of the original SAs expire. For BIG-IP, the rekey takes place after the expiry of the "soft" lifetime. The soft lifetime is a randomised value between 80-90% of the configured phase 2 lifetime (known as the "hard" lifetime).

Phase 2 lifetimes are not negotiated. Each side has its own configuration and scheme for determining soft lifetime.

It is possible that, depending on the relative hard and soft lifetimes, and the implemented schema for handling SAs that the old SAs are not deleted. Over time, a number of redundant SAs might be observed via the command "tmsh show net ipsec ipsec-sa". In this case, to avoid the growth of redundant SAs, BIG-IP has implemented a sys db key to clear out old (redundant) SAs. 

Recommended Actions

Enable sys db ipsec.removeredundantsa using the following command:

tmsh modify sys db ipsec.removeredundantsa value enable

When this key is enabled, when new SAs are created BIG-IP will check and delete any duplicate SAs. A delete message will also be sent to the remote peer to ensure that it is aware of which SAs have been deleted by BIG-IP.

The default value of sys db ipsec.removeredundantsa is "disable".

Additional Information

When using a VIPRION platform, the display command for the SAs should be prefixed with the "clsh" command in order to apply it to all blades. ie:

clsh tmsh show net ipsec ipsec-sa
