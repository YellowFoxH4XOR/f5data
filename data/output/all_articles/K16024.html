Known Issue

The Traffic Management Microkernel (TMM) may restart when a SERVER_CONNECTED iRule event fails.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system has a virtual server configured with a FastL4 profile assigned.
  • The FastL4 profile assigned to the virtual server has Hardware SYN Cookie Protection and PVA Acceleration enabled.
  • The virtual server has an iRule with the SERVER_CONNECTED event configured.

If the SERVER_CONNECTED iRule event receives a TCL_ERROR, for example, as a result of the TCL catch command, the flow is aborted before the connection is properly terminated. This results in TMM restarting.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the BIG-IP system is configured as part of a high availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory.
  • You observe messages similar to the following example in the /var/log/ltm log file:

    notice sod[7056]: 01140045:5: HA reports tmm NOT ready.
