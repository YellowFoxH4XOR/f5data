Known Issue

The Traffic Management Microkernel (TMM) may experience a memory leak when using a suspending iRule command within a CLIENT_ACCEPTED event.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured to use an iRule.
  • The iRule contains a suspending command (for example, the table command) within a CLIENT_ACCEPTED event. For more information about which commands suspend iRules, refer to K12962: Some iRule commands temporarily suspend iRule processing.
  • The virtual server referencing the iRule processes traffic that triggers a CLIENT_ACCEPTED event.
  • The connection flow is terminated while the iRule is suspended.

Impact

TMM memory may eventually be exhausted and may result in a system core. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM memory consumption steadily increases over time.

    You can monitor TMM memory usage using the tmstat command, or the following tmsh command:

    tmsh show sys memory

  • The sweeper may be triggered, as indicated by error messages in the /var/log/ltm file that appear similar to the following examples:

    tmm warning tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode activated. (166681/196096 pages)
    tmm warning tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode deactivated. (166680/196096 pages)

  • If configured as a high-availability pair, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
