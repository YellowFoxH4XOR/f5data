K16022207: Aspen Mesh enable protocol detection timeout for first server protocols.

Type
Support Solution
Published
2021-11-24
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source

Description

Istio and Aspen Mesh can automatically detect HTTP and HTTP/2 traffic. If the protocol cannot automatically be determined, traffic will be treated as plain TCP traffic.

Server First protocols, such as MySQL, are incompatible with automatic protocol selection.

Environment

  • Kubernetes: 1.17x, 1.18.x, 1.19.x, 1.20.x
  • Aspen Mesh: 1.6.x, 1.9.x

Cause

Some protocols are Server First protocols, which means the server will send the first bytes. This may have an impact on PERMISSIVE mTLS and Automatic protocol selection. Both features work by inspecting the initial bytes of a connection to determine the protocol, which is incompatible with server first protocols. In order to support these cases, follow the Explicit protocol selection steps in the Istio documentation to declare the protocol of the application as TCP.

The following ports are commonly known to carry server first protocols, and are automatically assumed to be TCP: 

ProtocolPort
SMTP25
DNS53
MySQL3306
MongoDB27017

Recommended Actions

You can override the default behavior of istio-proxy and forcibly balance the connections.

  • Configure workloads with the following options to ensure automatic protocol detection
  • Configure protocol detection timeout if your application have a different requirement (PERMISSIVE mTLS mode)

Configure workloads with the following options to ensure automatic protocol detection

  1. Configure mTLS mode STRICT for both client and server. This will enforce TLS encryption for all requests. (This is the default in Aspen Mesh)
  2. Configure mTLS mode DISABLE for both client and server. This will disable TLS sniffing, allowing server first protocols to be used.
  3. Configure all clients to send TLS traffic, generally through a DestinationRule or by relying on auto mTLS.
  4. Configure your application to send TLS traffic directly.

Configure protocol detection timeout if your application have a different requirement (PERMISSIVE mTLS mode)

If your application needs to use PERMMISIVE mTLS mode, the protocol selection might not be working. You can override this behavior by specifying a global setting named protocolDetectionTimeout.
  1. In your override values file set the following config:

    meshConfig:
        protocolDetectionTimeout: 1s

  2. Upgrade your current release:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery -n istio-system --values override-values.yaml

  3. Test the connections between your workloads. The traffic should be accepted now.
