Known Issue

The Configuration utility may stop responding when you view the Network Map page.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with 3,000 or more virtual servers, pools, and accompanying objects.
  • Multiple administrative users access the Local Traffic > Network page in the Configuration utility.

Impact

The Configuration utility may stop responding.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility does not respond.
  • In the /var/log/tomcat/catalina.out file, you observe a log message similar to the following example:

    SEVERE: Caught exception (java.lang.OutOfMemoryError: Java heap space) executing org.apache.jk.common.ChannelSocket$SocketAcceptor@f14c7c, terminating thread

Workaround

To work around this issue, you can restart the tomcat service. To reduce the possibility of encountering this issue, you can allocate more memory to the tomcat service. Alternatively, you can minimize the resource usage of the Network Map page by using a filter. To do so, perform one the following procedures:

  • Restarting the tomcat service
  • Increasing allocated memory to the tomcat service
  • Using the Network Map page filter

Restarting the tomcat service

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the tomcat service, type the following command:

    restart /sys service tomcat

Increasing allocated memory to the tomcat service

If the tomcat service continues to encounter this issue and becomes unresponsive, you can increase the amount of memory allocated to the tomcat service.

Impact of procedure: The Configuration utility will be unavailable while the tomcat service is restarting.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To view the current setting of the provision.tomcat.extramb database variable, type the following command:

    list /sys db provision.tomcat.extramb

    The command output appears similar to the following example:

    sys db provision.tomcat.extramb {
    value "0"
    }

    Note: When the value is zero (0), no additional memory is configured for the tomcat service.

  3. To set the provision.tomcat.extramb database variable to allocate additional memory to the tomcat service, use the following command syntax:

    modify /sys db provision.tomcat.extramb value <MB>

    Note: <MB> is the amount of additional memory in megabytes that will be allocated to the tomcat service. 20 MB is recommended.

  4. To restart the tomcat service, allocating the additional configured memory, type the following command:

    restart /sys service tomcat

    Important: If the system is configured for high availability (HA) or as part of a device group, repeat steps 1 through 3 on all peer devices.

Using the Network Map page filter

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Network Map.
  3. To filter the displayed objects, select one of the following filters from the top of the map:
    • Status  specifies whether to constrain contents and search operations based on object status.
    • Type specifies whether to constrain contents and search operations based on object type.
    • Search specifies a text string that the system uses in the object search operation.
  4. Click a search setting for Status, Type, or Search. When using the Search option, enter text in the search text box to search for configured objects with matching text.
  5. Click Update Map.
