Known Issue

This is the result of a known issue. When Global Availability is configured as the primary load balancing method, and Round Robin is configured as the secondary or fallback load balancing method for a wide IP, if Global Availability fails, Round Robin will only return the first member of the pool in response to queries for the wide IP.

F5 Product Development tracked this issue as CR106521 and it was fixed in BIG-IP 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You can work around this issue by configuring a fallback load balancing method other than Round Robin when using Global Availability as the primary load balancing method.
