Known Issue

This is the result of a known issue. When an authentication database such as LDAP or Active Directory returns attribute values with leading or trailing whitespace, the whitespace is not stripped from the values. Any comparison tests, such as those done for group mapping or with a session variable will fail. As a result, users may be unable to log in due to failed group mapping, or users may be unable to receive certain resources that depend on a session variable value taken from the value returned by the authentication database.

To detect whether your authentication database returns values with leading or trailing whitespace, you can use a management tool such as the Microsoft's Active Directory Users and Computers program, an LDAP browser, or similar tool to view the database and determine whether any values contain trailing or leading whitespace. A network packet dump, such as the one available on the Device Management: Maintenance: Troubleshooting Tools page, may also reveal leading or trailing whitespace if the communication is not encrypted.

Note: The FirePass Administrative Console will not display any trailing or leading whitespace in returned values. The Test mapping feature, or the Session Variable Dump feature, which is available in FirePass version 6.0.0 or later, will strip trailing or leading whitespace before displaying the value. The Test Mapping feature is located on the Users: Groups: Dynamic Group Mapping page. The Session Variable Dump feature is activated on the Device Management: Maintenance: Troubleshooting Tools page, and displays results in the Logon details section of the Reports: Logons page.

F5 Product Development is tracking this issue as ID 289272 (formerly CR73504) and ID 266877 (formerly CR85184).

Workaround

To work around this issue, remove the whitespace from the value returned by the authentication database.
