K000147610: How to Validate JWT Claims

Published

Applies to

Source

Description

A JSON Web Token (JWT) is used to carry information related to the identity and characteristics of a client. Distributed Cloud Console can help you configure your security policy to identify these JWTs for future analysis and vulnerability management.

Environment

  • F5® Distributed Cloud Load Balancer

Cause

  • None

Answer/Recommended Actions

To validate JWT claims:

  1. In the Multi-Cloud App Connect service, navigate to your load balancer.
  2. Click ... > Manage Configuration > Edit Configuration.
  3. Scroll down to the API Protection section.
  4. Under JWT Validation, click Configure.

  5. From the Target menu, select whether to perform validation on all endpoints, specific API groups, or a specific path. Target location(Bearer) will look for the JWT token in the Authorization HTTP header with Bearer authentication scheme.

  6. From the Action menu, select whether to block or report if JWT is not valid. Report action is the monitoring mode, and it allows the request to pass through and logs the security event. Block action will block the request and return a 403 error if audiences are not allowed. Block action will return a 401 error otherwise.

  7. Under JSON Web Key Set (JWKS), click Configure.

  8. In the text box, copy and paste the JSON Web Key Set (JWKS) used for authorization with the server. JWKS should be in JSON format.
    Example JWKS looks like: 

     {
  "keys": [
    {
      "alg": "RS256",
      "e": "AQAB",
      "key_ops": [
        "verify"
      ],
      "kty": "RSA",
      "n": "w0JvunVibishdaiksuhdwqQsadweiu23hfdfheiuwhfrq9834rhjeoqwfijeq89frrh34uirp9f34h8fjrepq349fhrq389",
      "use": "sig",
      "kid": "a91568fd054656774764"
    }
  ]
}

    Note: Sometime keys can be generated without "keys" entry: 

    {
  "keys": [  
      ]
    }

    If entry is not there, you need to add it. Either way keys will not be accepted and will show an error. 

  9. Click Apply.

  10. In the Reserved Claims Validation section, perform the following:

    • From the Issuer (iss) menu, select whether to match exactly the issuer’s reserved claim, or to disable this functionality. If you choose to match exactly, provide the exact match value in the corresponding field.

    • From the Audience (aud) menu, select whether to match exactly the JWT pre-configured value, or to disable this functionality. If you choose to match exactly, provide the exact match value in the corresponding field. You can add more than one value to match for using Add Item.

    • From the Validation Period menu, select Enable (default value) or Disable. Enable selection will validate the JWT expiration and not before (nbf) values (if present in the request token). Disable selection will not perform validation against these fields. After you finish with configuration, click Apply.

  11. In the Mandatory Claims section, perform the following:
    • Click Add Item. Enter the name of the claim. It must match the claim already present in the payload, in the JWT.
  12. After you finish with configuration, click Apply.

Additional Information

When JWT verification is active, you will see new entries in GLR logs and in LB request details. To see them in console:

  • Go to your LB requests:

  • Choose request and switch to JSON view:
     
     

    Note: JWT details are only visible now in JSON view. "Information" tab will not show these details.  
  • When JWT validation is enabled, you can find in request JSON entries like: 

"jwt_status" - show status of provided JWT token. Example values are: "OK", "Jwt is expired", "Jwt is missing".

"jwt_mode" - shows mode of JWT token validation. Can be in "Report" or "Block" mode. 

"jwt_action" - shows JWT action for request, if it's "Allowed" or "Blocked".

 

If you have any problems e.g you don't see JWT entries in requests JSON details, please open a ticket to our Distributed Cloud support.
