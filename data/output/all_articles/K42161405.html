Topic

You should consider using this procedure under the following conditions:

  • After modifying the management IP/host name of your units, you need to rebuild the device trust.
  • You receive a Returns Materials Authorization (RMA), but you do not have a valid user configuration set (UCS) file to restore the configuration, and you need to join the replacement unit to the high availability (HA) cluster after performing its basic configuration.
  • You need to rebuild the device trust as part of the configuration synchronization (ConfigSync)/device service clustering (DSC) troubleshooting process. For more information, refer to K13946: Troubleshooting ConfigSync and device service clustering issues.

To use the TMOS Shell (tmsh) to perform this procedure, refer to K40832524: Rebuilding device trust using tmsh (11.x - 17.x).

Description

This article provides steps to rebuild the device trust for a group of BIG-IP devices configured in an HA device group.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility.
  • The devices are currently configured for HA device groups.
  • Ensure that the BIG-IP HA devices are properly configured for network time protocol (NTP).

    For more information, refer to the General Configuration Properties chapter of the BIG-IP LTM BIG-IP TMOS: Concepts manual or K3122: Using the BIG-IP Configuration utility to add an NTP server.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

  • F5 recommends that before making any changes to your systems, you back up each system and store the backup to a remote location. For information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

Procedures

To watch a video demo of these procedures, go to  Rebuild device trust for BIG-IP devices in an HA device group using the Configuration utility.

  • Pre-work checklist
  • Force the standby device offline
  • Break the trust
  • Rebuild the trust
  • Perform the ConfigSync
  • Release the standby devices from offline

Pre-work checklist

Confirm and make notes of the IP address and device management configuration for each BIG-IP system in the HA configuration. You should perform the following procedure on each device in the device group.

Impact of procedure: F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the device labeled (Self).
  4. Select the ConfigSync tab.
  5. Ensure that Local Address is set to the self IP address for the local BIG-IP system.
  6. Select the Failover Network tab.
  7. Ensure that at least one network is configured.

    Note: F5 recommends the management IP address and a self IP address from at least one Virtual Local Area Network (VLAN).

  8. Go to Network > Self IPs.
  9. Select the self IP that you will use for synchronization.
  10. Ensure that Port Lockdown is set to either Allow All or Allow Default.
  11. Repeat this procedure on each device in the device group.

Force the standby device offline

You can force the standby device to an offline state, which will prevent devices from entering an active-active state while performing this maintenance. To do so, perform the following procedure:

Impact of procedure: The standby device will not be available if a failover action occurs. F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

  1. Log in to the Configuration utility on the standby unit.
  2. Go to Device Management > Traffic Groups.
  3. Select traffic-group-1 and set the failover method to Failover using Preferred Device Order and then Load Aware.
  4. Select Save.
  5. Go to Devices.
  6. Select the device labeled (Self).
  7. Select Force Offline.

    Note: You will need to repeat these steps for each traffic group you have configured and standby device in the device group.

Break the trust

To break an established trust, you must remove the devices from the device group before you can delete the device trust. To do so, perform the following procedure:

Impact of procedure: Performing this procedure will remove the HA configuration from your environment. F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

Note: After performing this procedure, the active device should have a status of online (Active) Standalone and the standby devices should have a status of Forced offline Standalone.

  1. Log in to the Configuration utility.

    Important: Perform this procedure first on the active device of the device group, then repeat the procedure on each standby device in the device group.

  2. Go to Device Management > Device groups.
  3. Select your failover group from the list.
  4. Remove the standby member from the device group by selecting it in the Includes list and moving it to the Available list.
  5. Select Update.
    If you get an error message Cannot delete device (/Common/<Device Name>) from device group (/Common/<Device Group>) because it is used by HA order on traffic group (/Common/<traffic group>), go to the traffic group configuration and move the standby device from Preferred Order to Load Aware and then repeat steps 4. and 5.)
  6. Go to Device Management > Device Trust > Device Trust Members.
  7. Select the check box to the left of each peer device and select Delete.

Repeat this procedure on each standby device in the device group.

Rebuild the trust

To rebuild the device trust, perform the following procedures:

  • Rebuild the trust from the active device
  • Rebuild the trust from the standby devices

Rebuild the trust from the active device

Impact of procedure: F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

  1. Log in to the Configuration utility of the active device.
  2. Go to Device Management > Device Trust > Local Domain.
  3. For Trust Information, select Reset Device Trust.
  4. For Certificate Signing Authority, select Retain Current Authority.
  5. Select Update.

    Important: This step breaks device trust for ALL devices in the group. In the event that you have more than two devices in your cluster, you will need to add all devices again.

  6. Go to Device Management > Device Trust > Device Trust Members.
  7. Select Add, add the Device IP Address, Administrator Username, and Administrator Password for the standby device.
  8. Select Retrieve Device Information.
  9. Select Device Certificate Matches.
  10. Select Add Device.
  11. Go to Device Management > Device Groups.
  12. Select your failover group from the list.
  13. Add the standby member to the failover group by selecting it in the Available list, and moving it to the Includes list.

    Note: At this point, both the active and standby devices should be in the Includes list on the active device.

  14. Select Update.

Rebuild the trust from the standby devices

Note: In some versions these steps are not required, and the peer device is already added to the failover group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of a standby device.
  2. Go to Device Management > Device Trust > Local Domain.
  3. For Trust Information, select Reset Device Trust.
  4. For Certificate Signing Authority, select Retain Current Authority.
  5. Select Update.

    Important: This step breaks device trust for ALL devices in the group. In the event that you have more than two devices in your cluster, you need to add all devices again.

  6. Go to Device Management > Device Trust > Device Trust Members.
  7. Select Add, then add Device IP Address, Administrator Username, and Administrator Password for the standby device.
  8. Select Retrieve Device Information.
  9. Select Device Certificate Matches.
  10. Select Add Device.
  11. Go to Device Management > Device Groups.
  12. Select your failover group from the list.
  13. Add the active member to the failover group by selecting it in the Available list, and moving it to the Includes list.

    Note: Both the active and standby devices should be in the Includes list on the standby device.

  14. Select Update.
  15. Repeat this procedure for each of the standby devices in the device group.

Perform the ConfigSync

To perform the ConfigSync operation, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Overview.

    Note: You should be able to see both devices and the current sync status should be Awaiting Initial Sync.

  3. In Devices, select the device labeled (Self).
  4. Select Sync Device to Group or Push the selected device configuration to the group.
  5. Select Sync.

If either device fails to sync at this point, refer to K13946: Troubleshooting ConfigSync and device service clustering issues.

Release the standby devices from the forced offline state

To release the standby devices from the forced offline state, perform the following procedure:

Impact of procedure: F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

  1. Log in to the Configuration utility on the standby unit.
  2. Go to Device Management > Traffic Groups.
  3. Select traffic-group-1 and set the failover method to the previously configured value.
  4. Select Save.
  5. Go to Devices.
  6. Select the device labeled (Self).
  7. Select Release Offline.

    Note: You need to repeat these steps for each traffic group you have configured and standby device in the device group.
