K000159822: How to Selectively Enable or Disable ICAP Inspection for HTTP Requests while uploading files.

Description

When using BIG-IP LTM ICAP Request/Response Adaptation profiles, all HTTP requests processed by the virtual server are sent to the ICAP server for inspection by default. In scenarios where only specific types of requests (such as file uploads, specific URIs, or certain content types) require ICAP inspection, sending all traffic to the ICAP server is inefficient and may unnecessarily consume ICAP server resources. This article describes how to selectively enable or disable ICAP inspection based on request attributes using iRules.

Environment

  • Virtual server with both HTTP and request-adapt profiles.
  • Uploading files for ICAP inspection via the Virtual Server.

Cause

ICAP Request/Response Adaptation profiles do not have built-in filtering capabilities to selectively inspect only certain types of requests. When an ICAP Request Adaptation profile is attached to a virtual server, ADAPT processing is enabled by default for all requests, resulting in all traffic being forwarded to the ICAP server regardless of whether inspection is necessary or appropriate for that specific request type.

Answer/Recommended Actions

To enable or disable ICAP inspection specifically for file uploads:

Create or Edit the Request Adaptation Profile

  1. Go to Local Traffic > Profiles > Services > Request Adapt.
  2. Set the internal virtual server for your ICAP service.
  3. Set the service-down-action as needed (ignore, reset, drop).

Create an iRule to Control ICAP Inspection

Example: Enable ICAP only for file uploads (POST with multipart/form-data):

when HTTP_REQUEST {
    if { [HTTP::method] eq "POST" && [HTTP::header "Content-Type"] starts_with "multipart/form-data" } {
        ADAPT::enable true
    } else {
        ADAPT::enable false
    }
}

Apply the iRule and Profile

Attach both the Request Adaptation profile and the iRule to your virtual server.
