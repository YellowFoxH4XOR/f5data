K000161773: BIG-IP VE with Accelerated Networking on Azure: Traffic Loss and eal-intr-thread core after Azure Host Maintenance or Live Migration

Type
Support Solution
Published
2026-06-17
Updated
2026-06-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161773

Description

BIG-IP Virtual Edition (VE) deployed on Microsoft Azure with Accelerated Networking enabled may intermittently stop processing traffic following Azure platform events such as host maintenance or live migration. Symptoms include:

 

  • Device stops processing traffic; all connections drop
  • Sudden CPU spike observed on core 0
  • Core files generated: eal-intr-thread.bld0.0.x0.core.gz
  • Network interfaces absent from ifconfig output prior to reboot; interfaces reappear after reboot
  • No automatic failover triggered in Active/Active deployments
  • Issue recurs each time Azure performs a host maintenance or live migration event

The following kernel log messages may be observed around the time of the event:

hv_netvsc <id> eth1: Data path switched to VF: f5slave1

mlx5_core <id> f5slave2: Link up

hv_netvsc <id> eth2: Data path switched to VF: f5slave2

hv_netvsc <id> eth2: VF unregistering: f5slave2

tmm.0:<pid> map pfn RAM range req uncached-minus for [mem ...], got write-back

device f5slave2 entered promiscuous mode

mlx5_core <id> f5slave2: S-tagged traffic will be dropped while C-tag vlan stripping is enabled

hv_netvsc <id> eth1: VF unregistering: f5slave1

device f5slave1 entered promiscuous mode

Environment

  • BIG-IP LTM VE, version 17.5.1.4
  • Deployed on Microsoft Azure
  • Accelerated Networking enabled (mlx5/Mellanox virtual functions)
  • Multiple data interfaces configured
  • Azure host maintenance or live migration events occurring on the underlying hypervisor
  • Active/Active HA configuration

Cause

Two known software defects in the DPDK mlx5 driver are responsible for this behavior:

 

  • ID2263721
  • ID2313441

Answer/Recommended Actions

  • Request an Engineering Hotfix (EHF) for your current version that includes the fix.
  • Switch from Active/Active to Active/Standby HA mode. This ensures automatic failover occurs when a device becomes unavailable, reducing the impact of these events on traffic continuity.

Additional Information

  • Both defects are triggered by Azure platform events
  • All Azure BIG-IP VE deployments running 17.5.1.x with Accelerated Networking enabled are potentially affected.
  • After a reboot or TMM restart, the mlx5 VFs are re-registered and traffic resumes normally.
