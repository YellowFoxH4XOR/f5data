K11340: The BIG-IP WebAccelerator logs superfluous messages when a client request does not include a Host header

Known Issue

Note: Beginning in BIG-IP WebAccelerator version 10.1.0, client requests that do not include a Host header bypass the BIG-IP WebAccelerator. For more information, refer to K11336: Change in Behavior: Client requests that do not include a Host header bypass the BIG-IP WebAccelerator.

This is the result of a known issue. When a client request that does not include a Host header hits a BIG-IP WebAccelerator virtual server, the system logs messages to the /var/log/wa/pvac.log file that appear similar to the following example:

debug WA Debug ( 6544): [             TmPlugin.cxx:3483  populateHeadersFromPlugin ] handleHeadersEnd failed with [0x36]
debug WA Debug ( 6544): [             TmPlugin.cxx:3485  populateHeadersFromPlugin ] [GET /
debug WA Debug ( 6544): ]
debug WA Debug ( 6544): [             TmPlugin.cxx:3487  populateHeadersFromPlugin ] Index [0x0]
debug WA Debug ( 6544): [             TmPlugin.cxx:3496  populateHeadersFromPlugin ] Value [GET]
debug WA Debug ( 6544): [             TmPlugin.cxx:3487  populateHeadersFromPlugin ] Index [0x1]
debug WA Debug ( 6544): [             TmPlugin.cxx:3496  populateHeadersFromPlugin ] Value [/]
debug WA Debug ( 6544): [             TmPlugin.cxx:3487  populateHeadersFromPlugin ] Index [0x2]
debug WA Debug ( 6544): [             TmPlugin.cxx:3496  populateHeadersFromPlugin ] Value []

These debug messages are superfluous and should not be logged by the BIG-IP WebAccelerator.

For example, this issue can occur when a BIG-IP LTM system monitors a BIG-IP WebAccelerator system with the HTTP health monitor. By default, the BIG-IP HTTP health monitor sends HTTP version 0.9 requests, which do not include a Host header. As a result, the BIG-IP WebAccelerator writes nine lines to the log file once every 5 seconds, which is the default monitor interval, or twice every 5 seconds in a high availability setup.

Note: For more information, refer to K9884: BIG-IP WebAccelerator performance reports indicate a large number of HTTP 400 (Bad Request) responses and K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor.

F5 Product Development tracked this issue as CR135924, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
