K10350: Deleting the dynamic parameter does not delete the corresponding extraction object

Type
Known Issue
Published
2010-02-15
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP ASM: 9.4.8, 10.0.1, 10.0.0, 10.1.0, 9.4.7
Source

Known Issue

This is the result of a known issue. When a Dynamic Content Value Parameter has an extraction defined is deleted, the corresponding extraction definition is not deleted. As a result, when the policy is applied, the system will continue to unnecessarily accumulate responses for requests containing that parameter.

In BIG-IP versions 10.0.0 and later, the system also logs a validation error to the Security Policy History for each extraction definition that does not have a matching parameter in the policy. The error message appears similar to the following example:

The following extracts do not have a matching parameter:

Global Extract '<extraction_definition>'

Note: The validation errors may be viewed by clicking on the link in the Validation Errors column.

For example, if you delete the Dynamic Content Value Parameters that refer to the session_id and change_view extraction definitions, and then reload the policy, the system will continue to accumulate the relevant responses unnecessarily,and log a message that appears similar to the following example:

The following extracts do not have a matching parameter:

Global Extract 'session_id'
Global Extract 'change_view'

F5 Networks Product Development is tracking this issue as CR122080.

Workaround

You can work around this issue by removing extractions that do not have matching parameters. To do so, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Browse to Application Security > Web Applications.
  3. From the Web Applications list, click the name of the application whose policy you want to edit.
  4. Browse to Application Security > Policies List.
  5. From the Policies List, click the name of the policy you want to edit.
  6. Click Parameters in the left menu.
  7. Click the Extractions tab.
  8. Select the check box next to the extraction object(s) referenced in the error message..
  9. Click Delete All to delete the object(s) from the list..
  10. Click OK the confirm the deletion..
  11. Apply the modified policy by clicking the Apply Policy button.
