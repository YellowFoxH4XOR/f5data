K000152579: Nginx App Protect responds with a 444 HTTP response and the Nginx error.log states "APP_PROTECT aborting request" when the number of concurrent long requests is exceeded

Type
Support Solution
Published
2025-07-15
Updated
2025-08-26
Applies to
  • NGINX Products
  • NGINX App Protect WAF: 5.4.0
Source
https://my.f5.com/manage/s/article/K000152579

Description

  • When viewing Nginx error.log you observe a 444 response being sent to clients from APP_PROTECT.
  • Error messages:
    • Nginx error log: 2025/04/14 05:29:02 [warn] 24145#24145: *368566848 APP_PROTECT aborting request 0000558837179530 ctx id 35043630, client: 1.1.1.1, server: my.server.com, request: "POST /my/url HTTP/1.1", host: "my.server.com" 1.1.1.1 - USER [14/Apr/2025:05:29:02 +0200] "POST /my/url HTTP/1.1" 444 0 "-" "okhttp/4.12.0" "2.2.2.2,3.3.3.3"
    • Nginx App Protect log, var/log/app_protect/bd-socket-plugin.log: IO_PLUGIN|WARN |Apr 14 03:22:16.795|63455|/builds/6x631E1L/0/waf/waf-general/secore/bd/io_plugin/plugin_common.c:3730|Too many concurrent long requests allowed 32 ,current 32 needed request length: 1286875

Environment

  • Nginx App Protect enabled
  • Exceeding the default (32) concurrent long request. A request ends up in Nginx App Protects long request buffer when it exceeds 10MB.

Cause

A 444 is an expected response when the max concurrent long request value is exceeding.

For example, for the default concurrent long requests value of 32, when the 33rd request arrives it will receive a 444 response from Nginx (App Protect).

Recommended Actions

Reach out to F5 support if the max concurrent long requests needs to be increased for your environment.
