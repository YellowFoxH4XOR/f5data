K000151941: LDAPS monitor is down.

Type
Support Solution
Published
2025-06-19
Updated
2025-06-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151941

Description

LDAPS monitor is showing down the pool.


Debug logs show:


start tls error(-1): Can't contact LDAP server


The monitor configuration has TLS like this and pcap shows communication on port 636:


ltm monitor ldap /Common/ldaps_monitor {

app-service none

base OU=SaAccounts,DC=test,DC=com

chase-referrals no <====

debug no

defaults-from /Common/ldap

description 636 encrypted LDAPS

destination *:*

filter objectClass=person

interval 10

mandatory-attributes none

manual-resume disabled

partition Common

password ***scrubbed***

security tls <-----------here it needs to be ssl

time-until-up 0

timeout 31

up-interval 0

username ldaps-service@test.com

}


Environment

BIGIP LTM


Cause

STARTTLS uses port 389.

The pcap shows port 636, which is for LDAPS.

The monitor needs to use SSL instead of TLS.


Recommended Actions

Change the monitor configuration from "TLS" to "SSL"
