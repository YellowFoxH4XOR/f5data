K81070000: Clientside SAN Certificate use may need ''server name'' setting in serverSSL profile when bridging SSL

Type
Support Solution
Published
2022-06-28
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K81070000

Description
When configuring an LTM Virtual server for SSL "bridging"  where you have a clientSSL profile with a SAN Certificate/key and a serverSSL profile to 're-encrypt" before going to a backend server,  you need to include the expected "server name" in the serverSSL configuration. 

Environment

  • BIG-IP LTM
  • Virtual server doing "SSL Bridging" 
  • using a SAN (Subject Alternative Name) based certificate with multiple FQDNs. 

Cause

  • When consuming the SSL Certificate, the requested SAN FQDN Is not passed to the serverSSL request, resulting in a failed SSL transaction with the backend server.   Since the backend server does not know which FQDN is being requested, it rejects the SSL handshake. 

Recommended Actions

  1. Create a custom serverSSL profile  (see: Overview of the Server SSL profile (11.x - 17.x) ) 
  2. in the Server Name field,  enter the unique SAN FQDN being used for this pool.
