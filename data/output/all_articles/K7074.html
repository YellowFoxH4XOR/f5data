Topic

Note: For information about other compression settings available in the HTTP profile, refer to K3393: Overview of compression settings for the HTTP profile.

The following three compression modes are available in the HTTP profile:

  • Enable
  • Selective
  • Disable
Enabled

The Enabled compression mode enables compression according to the other compression settings specified in the HTTP profile.  It is not possible to disable compression from within an iRule when the compression mode is set to Enabled.

Selective

The Selective compression mode allows compression to be conditionally managed in an iRule. In Selective mode, the HTTP profile settings are not used to determine what is compressed, and no compression is performed unless specifically enabled in an iRule. For example, you can selectively enable compression only for documents of type "text" by setting the compression mode to Selective, then applying an iRule similar to the following:

when HTTP_REQUEST {   COMPRESS::disable   if { [HTTP::header Content-Type] contains "text" } {      log "Enabling compression for this request"      COMPRESS::enable   }}
Disabled

The Disabled compression mode disables compression for connections using the HTTP profile. It is not possible to enable compression from within an iRule when the compression mode is set to Disabled.

Note: To disable compression for the HTTP profile, you must select Disabled from the Compression drop-down menu. If you attempt to disable compression by leaving the compression setting enabled and removing all URI/content types from the URI / Content List fields, the system compresses all HTTP content.
