Description

This article explains the behavior of Service Policy (SP) enforcement in F5 Distributed Cloud TCP Load Balancer, specifically how it affects TCP connections when access is restricted by source IP or similar criteria.

Environment

  • F5 Distributed Cloud
  • TCP Load Balancer
  • Service Policy (SP) configured to restrict access (e.g., by source IP)
  • Any backend/origin server (e.g., SFTP/SSH, but applies to all TCP protocols)

Cause

  • The F5 Distributed Cloud TCP Load Balancer allows the TCP three-way handshake (SYN, SYN-ACK, ACK) to complete before enforcing the Service Policy.
  • The Service Policy is applied when the client sends the first payload (application data) after the handshake.
  • If the policy denies the connection, the payload is blocked and not forwarded to the backend/origin. The backend sees the connection as established, but no data is received, and the connection is closed shortly after.

Answer/Recommended Actions

Use Fast ACLs if you require the connection to be blocked before the handshake; the Service policy is enforced at the payload stage.

Additional Information

  • When a Service Policy is configured to deny traffic, for example, from certain source IPs, connection attempts from those IPs may still appear as "established" on the backend/origin server.
  • The backend/origin may log a TCP connection (three-way handshake completed), but no application payload is delivered.
  • The client experiences a connection reset or denial after the handshake, when it attempts to send data.
  • This behavior is by design and is consistent across TCP-based protocols.
