K000160341: Adding subnet mask in local-IP in syslog config can cause BIG-IP to not send syslog messages to remote server

Type
Support Solution
Published
2026-03-13
Updated
2026-03-16
Source

Description

Adding subnet mask in local-IP in syslog config can cause BIG-IP to not send syslog messages to remote server 

Environment

  • Remote Syslog

Cause

Adding subnet mask in local-ip IP address in remote syslog config can cause BIG-IP to consider it as a DNS name and it will try to resolve it and will fail to resolve it to IP address and no messages will be sent to remote server.

 

sys syslog {

        remote-servers {

                  /Common/syslog1 {
                        description none
                        host 10.10.10.10 
                        local-ip 192.168.1.1/24
                        remote-port 514
                     }
        }
       user-log-from notice
       user-log-to emerg
}

Below type of log messages can be seen in the /var/log/messages -

 

Feb 21 11:09:26 localhost err syslog-ng[7382]: Initiating connection failed, reconnecting; time_reopen='60'
Feb 21 11:09:26 localhost err syslog-ng[7382]: Error resolving hostname; host='192.168.1.1/24'
Feb 21 11:09:26 localhost err syslog-ng[7382]: Initiating connection failed, reconnecting; time_reopen='60'
Feb 21 11:10:26 localhost err syslog-ng[7382]: Error resolving hostname; host='192.168.1.1/24'
Feb 21 11:10:26 localhost err syslog-ng[7382]: Initiating connection failed, reconnecting; time_reopen='60'
Feb 21 11:10:26 localhost err syslog-ng[7382]: Error resolving hostname; host='192.168.1.1/24'
Feb 21 11:10:26 localhost err syslog-ng[7382]: Initiating connection failed, reconnecting; time_reopen='60'

Answer/Recommended Actions

Do not add subnet mask in local-ip with IP address.

It should look like this as shown in below example.

sys syslog {

        remote-servers {

                  /Common/syslog1 {
                        description none
                        host 10.10.10.10 
                        local-ip 192.168.1.1
                        remote-port 514
                     }
        }
       user-log-from notice
       user-log-to emerg
}
