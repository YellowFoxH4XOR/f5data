Description

BIG-IP resets chunked response with reason "HTTP Unexpected server data past end of response".
  • Chunked response is actually correct and Wireshark decodes it properly.
  • Trigger is the server sending multiple 10x responses with little time between them.

Environment

  • Virtual Server with HTTP profile

Cause

multiple "100 Continue" responses were sent prior to the chunked "200 OK" response.

Recommended Actions

There are two options for resolving this issue:
  • Upgrade to BIG-IP v14.x or later
-or-
  • Apply the following iRule to the virtual server to insert a 10ms delay between the "100 Continue" packets.
    Note: You might need to adjust the delay to minimise but suit your environment.

    when HTTP_RESPONSE {
      # Add small delay to separate out "100 Continue" responses from server
      if {[HTTP::status] == "100"} {
       after 10
      }
    }
