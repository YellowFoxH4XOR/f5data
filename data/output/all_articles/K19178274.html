Description

Sometimes the SSL Orchestrator configuration will become broken, which is caused by bug, or incorrect operation, or capacity issue.
This article will list some steps to find the broken blocks in the SSLO, and fix them.

Environment

  • BIG-IP SSL Orchestrator
  • Topology

Cause

Bug, incorrect operation, or capacity issue cause broken data.

Recommended Actions
The steps below is applicable for SSL Orchestrator standalone deployment. And it is applicable for each SSL Orchestrator in the HA deployment too.
Even you did not get any warning message, it is suggested to check it too.

  1. Please login the Configuration Utility with administrator role.
  2. Navigate to SSL Orchestrator  ››  Configuration, get the topology list.
  3. If you cannot get the expected page, like error / warning, please research it and fix it, contact F5 technical support team if you cannot fix it.
  4. Navigate to iApps  ››  Application Services : Applications LX, review the "Application Services List".
  5. If an application status is ERROR (red square), tick it and delete it.
  6. If an application status is BOUND (green dot), tick it and undeploy it, then delete it.
When modify the SSLO configuration, it will generate temperary applications with BOUND status, but it should be deleted automatically in 10 minutes. If the BOUND application persist more than 10 minutes, please tick it and undeploy it, then delete it.
  1. If an application status is BOUNDING(circling) or UNBOUNDING(circling), please run the command below to change the status to ERROR, then follow step 5, delete it.
restcurl -i -u admin:<password> /mgmt/shared/iapp/blocks?\$filter=state%20eq%20%27UNBINDING%27 |grep selfLink |grep shared   /// get the ID string for UNBOUNDING appliations
restcurl -i -u admin:<password> /mgmt/shared/iapp/blocks?\$filter=state%20eq%20%27BINDING%27 |grep selfLink |grep shared   /// get the ID string for BOUNDING applications
restcurl -X PATCH -d '{"state" : "ERROR" }'  shared/iapp/blocks/<ID string>
  1. If an application status is PENDING (grey dot and the name is started with sslo_ob), tick it and delete it (it should be delete automatically).
  2. Restart restjavad and restnoded in the bash:
bigstart restart restjavad restnoded

Additional Information

This is an open topic, may cannot cover all versions, all scenarios, al issues. And the policy is, if SSL Orachestrator cannot work as expected, and you cannot fix it, please contact F5 technical support team.
We suggest to backup the configuration before any modification.
We suggest to perform the steps in the maintenance window (the steps 1-9 should have no negative impact).
Without F5 instruction, please do not deploy / undeploy / delete the applications under iApps  ››  Application Services : Applications LX.
