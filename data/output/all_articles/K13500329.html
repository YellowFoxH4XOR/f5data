Issue

The HTTP protocol and its many companion protocols and languages are continuously evolving. Due to this, there is a possibility that the BIG-IP APM rewrite process may not modify an element when rewriting server responses to the destination client.  This can result in the client submitting an HTTP request to the BIG-IP system without the required portal access syntax, which contains the hexadecimal encoded URL destination the BIG-IP APM process will forward the client's portal request to.

You should consider using this procedure under the following condition:

  • HTTP URL requests for portal access are processed by the BIG-IP APM system without the required rewrite for portal processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The elements of a portal access URL access session fail to display correctly.
  • Connections to an access session portal access URL fail.

Recommended Actions

F5 recommends following the troubleshooting steps outlined in K14184: Troubleshooting BIG-IP APM portal applications to determine if portal access to the application is failing due to the BIG-IP APM processed portal URL missing the required hexadecimal URL from client requests.

If a BIG-IP APM failed URL rewrite is identified, open a service request with F5 Technical Support so that the root cause of the portal URL rewrite failure can be reviewed for correction in the BIG-IP APM rewrite software. Provide all the diagnostic data collected while troubleshooting the issue in your service request.

Note: For more information about creating a service request, visit the F5 Support Offerings page.

Workaround

To work around this issue, you can implement the following iRule workaround that will correct the URL to include the required URL rewrite syntax.

Important: When troubleshooting portal access issues with F5 Technical Support, the workaround iRule will need to be temporarily removed from the virtual server.

  • Creating the iRule workaround
  • Adding the iRule workaround to the virtual server

Creating the iRule workaround

Impact of procedure: This procedure should not have a negative impact on the BIG-IP system.

  1. Determine the hexadecimal value of the URL for the application accessed via portal access.

    For more information about converting a URL to a hexadecimal value, refer to the ASCII to Hex text converter page.

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

    For example:

    https://application.example.com = 68747470733a2f2f6170706c69636174696f6e2e6578616d706c652e636f6d

    Note: When converting the ASCII text of the URL to hexadecimal, remove any white space between hexadecimal characters.

  2. Log in to the Configuration utility.
  3. Navigate to Local Traffic > iRules > iRule List.
  4. Click Create.
  5. Enter a name for the new iRule.
  6. Enter the following command syntax into the Definition field: 
    when HTTP_REQUEST {
   if { [HTTP::has_responded] } { return }
   if { [string tolower [HTTP::uri]] starts_with "/<uri>"} {
   HTTP::uri "/f5-w-<HEX_equivalent_of_backend_FQDN>$$[HTTP::uri]"
   }
}

    Note: Replace <uri> with the beginning of the URI for the HTTP request that is not being rewritten, and replace <HEX_equivalent_of_backend_FQDN> with the hexadecimal value noted in step 1.

  7. Click Finished.

Applying the iRule to the affected virtual server

Impact of procedure: F5 recommends performing the following procedure during a scheduled maintenance window.

  1. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  2. Click on the name of the virtual server used to provide portal access to the application.
  3. Click the Resources tab.
  4. Navigate to iRules > Manage.
  5. Move the workaround iRule from Available to Enabled.
  6. Click Finished.

Note: To back out of this procedure, move the workaround iRule from Enabled to Available.
