Description

When a BIG-IP is licensed or not for LTM, and when you have at least one other module provisioned (including just AVR), LTM provisioning can be set to NONE.

Environment

  • BIG-IP v12 and above
  • One or more modules other than LTM are licensed and provisioned.

Cause

LTM functionality is enabled with a license and/or with BIG-IPs that are module specific. For example if it is an ASM/AdvWAF only BIG-IP it will still have LTM functionality.

Recommended Actions
Important: Changing LTM provisioning may impact other features like DoS (dosl7d) due to the reduced memory allocated to TMM, the change in provisioning should be tested before implementing in production devices,

Important: This procedure should be performed on each unit in an HA cluster and may require rebooting the system. Recommend the following procedure be performed in a maintenance window and when it is standby to minimize impact.

Important: Starting in version 13.x the db variable  pvasyncookies.virtual.maxsyncache  used for per virtual SynCookie Protection was deprecated and replaced with a configuration object. This configuration object is found at System  >> Configuration : Local Traffic : General and is titled "Default Per Virtual Server SYN Check™ Threshold ". If you are using this option and deprovision LTM you will no longer be able to access that setting via the GUI, but can via the CLI. For more information about this refer to  K48278733: GUI behavior changes since v13.x that effect Syncookie Protection and BIG-IPs that do not have LTM Provisioned.
De-provisioning the LTM module via the GUI

Impact of procedure: Altering system provisioning will interrupt traffic processing and may trigger a failover if performed on the active unit in an HA cluster.

  1. Access the BIG-IP GUI as an admin level user
     
  2. Navigate to the System menu and select Resource Provisioning
     
  3. Uncheck the checkbox for Local Traffic (LTM) under the Provisioning column
     
  4. Press the Submit button
     

De-provisioning the LTM module via the CLI

Impact of procedure: Altering system provisioning will interrupt traffic processing and may trigger a failover if performed on the active unit in an HA cluster.

  1. Access the BIG-IP CLI as a root level user, either via SSH or console.
     
  2. Run the following command:   
    tmsh modify sys provision ltm level none
     
  3. Save the configuration:  
    tmsh save sys config
     

Additional Information

Some iApp templates require LTM be provisioned. If that is of concern you can read more about that here K16717317: General information and troubleshooting suspected resource issues
