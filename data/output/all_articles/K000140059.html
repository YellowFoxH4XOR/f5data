Description

Environment

  • BIG-IP LTM.
  • HA PAIR
  • NTP

Cause

Both devices lost connectivity with the NTP servers.

Recommended Actions

Verify the connectivity to the NTP servers using below steps:

  • Check with ip route command if the NTP server subnet has a direct or default route.
  •  Ensure that firewall is not blocking the port 123.
  • Check the NTP connectivity with ntptime command. In the working scenario the command output should be like the following:

root@basic-lab-bigip1:Active:Disconnected] config # ntptime
ntp_gettime() returns code 0 (OK)
  time ea1dd51e.4e78af20  Wed, Jun 19 2024 15:07:26.306, (.306529349),
  maximum error 479239 us, estimated error 1090 us, TAI offset 0
ntp_adjtime() returns code 0 (OK)
  modes 0x0 (),
  offset -249.718 us, frequency 3.156 ppm, interval 1 s,
  maximum error 479239 us, estimated error 1090 us,
  status 0x6001 (PLL,NANO,MODE),
  time constant 10, precision 0.001 us, tolerance 500 ppm

If the command returns the error ntp_adjtime() returns code 5 (ERROR) means that the NTP cannot communicate and exchange data with the BIGIP. You can confirm that by collecting packet capture with tcpdump utility using following command:

tcpdump -ni mgmt -vw /var/tmp/NTPTEST port 123
