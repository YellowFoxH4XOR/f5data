Known Issue

Importing a BIG-IP product or hotfix ISO image file may fail.

This issue occurs when the following condition is met:

  • You perform the import using the Configuration utility on a BIG-IP system that is running on a version that is listed in the Applies To box.

Impact

The Configuration utility fails to import files to their expected locations.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After attempting to import a BIG-IP ISO image file using the Configuration utility, you encounter the following issues:
    • On the Configuration utility, an error message that appears similar to the following example may appear:

      An error has occurred while trying to process your request.

    • The root filesystem/disk space is fully used. Use the following command on the BIG-IP command prompt to check the filesystem disk usage:

      df -h /

      Output that appears similar to the following example shows that the root filesystem / disk space is fully used:

      Filesystem Size Used Avail Use% Mounted on
      /dev/mapper/vg--db--sda-set.5.root
      248M 236M 0 100%

      /
    • A temporary file resulting from the import failure is stored in the /tmp folder. Use the following command to look for the temporary file:

      ls -al /tmp/upload_*.tmp

      Output that appears similar to the following example displays, as follows:

      -rw-r--r-- 1 tomcat tomcat 125976926 May 14 13:19 /tmp/upload_1a174545_13749c94ceb__8000_00000000.tmp

Resolution

Status

F5 Product Development has assigned ID 379583 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
ReleaseNoneNone
HotfixNoneNone

This issue does not affect BIG-IP 11.x.

Workaround

If you have already attempted to import the BIG-IP ISO image file, you can work around this issue by removing the temporary file. In addition, you can prevent the issue from occurring by using an alternative method to import the BIG-IP ISO image file, as follows.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Removing the temporary file caused by import failure

You can remove the temporary file that is stored in the /tmp folder as a result of the import. To do so, perform the following procedure:

  1. Log in to the BIG-IP command prompt.
  2. Locate the temporary file in the /tmp directory using the follow command:

    ls -al /tmp/upload_*.tmp

    You may see output that appears similar to the following example:

    -rw-r--r-- 1 tomcat tomcat 126251008 May 9 15:28 /tmp/upload_43ccc0fe_137307fb1f2__8000_00000000.tmp

  3. Delete the file that resulted from Step 2, using a command similar to the following:

    rm -f /tmp/upload_43ccc0fe_137307fb1f2__8000_00000000.tmp

  4. With the temporary file deleted, you can verify the disk space usage to make sure it is no longer 100 percent used on the root filesystem /, by using the following command:

    df -h /

  5. If you still need to import the BIG-IP ISO image file, you can use the alternative method in the following section.

Alternative method to import the ISO image file

You can use secure copy (SCP) as an alternative method to copy the BIG-IP ISO image file into the BIG-IP system. Make sure that you copy the files to the BIG-IP system's /shared/images/ directory.
