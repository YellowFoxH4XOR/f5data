K000141417: NGINX Maintains Connections to Drained Server

Type
Support Solution
Published
2024-10-11
Updated
2024-10-11
Applies to
  • NGINX Products
  • NGINX Plus: R32, R30, R29, R28, R31
Source
https://my.f5.com/manage/s/article/K000141417

Description

  • You have NGINX Plus installed and configured.
  • You change the status of a configured server to "draining” mode. 
  • After the change, however, you continue to notice active connection/s to a drained upstream (server).
  • You want to know why NGINX continues to proxy request/s to a server that is drained 

Environment

  • NGINX Plus
  • server Directive Drain parameters
  • Upstream Block

Cause

  • None -

Recommended Actions

  • None. NGINX exhibits the correct and expected default behavior
    • If a NEW client with NEW request establish connection with NGINX, NGINX will NOT proxy the request to a server that is drained
    • If an existing client with bound session makes additional request, then NGINX will proxy to a server that is drained
      • bound connection mean, existing client which established connection / session with a server before drainage

Additional Information

  • Even though the state of the server is "drained", NGINX maintains active connection to the server, so long that there is a "bound" request.
  • Meaning, placing a server in "draining” mode does NOT prevent NGINX from proxying more inbound connections/requests
  • An example of a Bound request can be
    • "The upstream connection is bound to the client connection once the client sends a request with the “Authorization” header field value starting with “Negotiate” or “NTLM”. In this case, further client requests will be proxied through the same upstream connection, thereby keeping the authentication context."
    • Another example will be "persistence". If you configure the upstream with a persistence, like Sticky Cookie, then you would have NGINX maintaining session/connection with this server, even though it is drained.
  • https://nginx.org/en/docs/http/ngx_http_upstream_module.html#:~:text=only%20requests%20bound%20to%20the%20server%20will%20be%20proxied%20to%20it.
