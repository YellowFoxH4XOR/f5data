K000135073: All packets on B4450N's interface dropped due to incorrect VLAN

Type
Support Solution
Published
2023-06-17
Updated
2023-06-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000135073

Description

In rare situations, B4450N's interface may drop all packets due to incorrect VLAN.

 

Environment

  • BIG-IP v15
  • VIPRION chassis with B4450N blades
  • Traffic affected
  • All packets continually dropped at an interface due to incorrect VLAN

 

Cause

Unknown. ID1304801 is filed to track this issue.

 

Recommended Actions

You may verify if you encounter the same issue by following the steps below:

 

1. Generate 2 qkviews of the device, an interval (for example, 20 minutes) apart. Let us call them "before" and "after" qkviews.

 

2. Compare interface_stat tmctl table of the qkviews.

 

Before:

name    counters.pkts_in counters.drops_in

------- ---------------- -----------------

3/8.0          360209279         357917386

 

After:

name    counters.pkts_in    counters.drops_in

------- ----------------    -----------------

3/8.0          360456558 (+247279)  358163316 (+245930) <==

 

In the example above, we see an increase of 247279 packets and almost all (>99%) of them were dropped.

 

3. Compare drop_reason tmctl table of the qkviews

 

Before:

name  counters.rx_vlan

----- ----------------

3/8.0        357917386

 

After:

name  counters.rx_vlan

----- ----------------

3/8.0        358163316 (+245930) <==

 

Of the 245930 packets that were dropped at the interface, all were dropped due to rx_vlan (incorrect VLAN).
