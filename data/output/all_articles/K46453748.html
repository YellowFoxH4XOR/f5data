Known Issue

The Firefox browser fails to display portal access content.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a portal access profile.
  • Content processed by the profile includes web application JavaScript code where a value is set to a string value.

    For example:

    o = {tagName: true, setAttribute: true}
    o.innerHTML = "<value>";

  • You access the content using the Firefox browser.

Impact

The content download does not complete and the Firefox browser fails to display content.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When accessing content, the Firefox browser does not display the content and remains in the downloading state.
  • When accessing content using an alternate browser, such as Internet Explorer or Google Chrome, the web application content displays correctly.

Workaround

To work around this issue, you can craft a custom iRule and apply it to the affected virtual server. To do so, perform the following procedure:

Impact of workaround: F5 recommends performing the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRules List.
  3. Click Create.
  4. Enter the name of the iRule in the Name box.
  5. Modify the PATTERN_PATH to match the path of the affected JavaScript web application content using the following iRules syntax:

    when REWRITE_REQUEST_DONE { 
      if { [HTTP::path]  contains "<PATTERN_PATH>" } { 
        # log "URI=([HTTP::path])"  
        # Found the file we wanted to modify 
        REWRITE::post_process 1
      } 
    }

    when REWRITE_RESPONSE_DONE {
      set strt [string first {<script>} [REWRITE::payload]]
      if {$strt > 0} {
        REWRITE::payload replace $strt  0 {
          <script>
            if (typeof F5_Inflate_index !== 'undefined' && typeof F5_old_Inflate_index === 'undefined') {
              var F5_old_Inflate_index = F5_Inflate_index;
              F5_Inflate_index = function(o, s, incr, v) {
                if (typeof v !== 'boolean') return F5_old_Inflate_index (o,s,incr,v);
                return  (o[s] = incr ? o[s] + v : v)
              }
            }
          </script>
        }
      }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click on the name of the affected virtual server.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. Locate the newly created iRule in the Available column and click the name of the iRule.
  12. To move the iRule to the Enabled column, click <<.
  13. Click Finished.
