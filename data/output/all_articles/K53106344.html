Known Issue

The Open Shortest Path First (OSPF) routing table may show summary routes as dynamically learned inter-area (IA) and not blackhole, or null interface, as expected.

This issue occurs when all of the following conditions are met:

  • You have multiple BIG-IP systems in a high availability (HA) configuration.
  • The BIG-IP systems are configured as OSPF peers.
  • You add one or more new blackhole OSPF summary routes on one of the BIG-IP HA peers.
  • After a short period of time, you add the same blackhole summary routes to one of the other BIG-IP HA peers.

Note: This issue occurs because the second BIG-IP HA peer to be configured learns the new blackhole route as an IA summary route before it is configured.

Impact

Packets are unnecessarily routed from the BIG-IP HA peer with IA routes to the BIG-IP HA peer with black hole routes.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You run the tmsh show net route command on multiple BIG-IP systems and notice that blackhole summary routes show as being dynamically learned IA routes.

Workaround

To work around this issue, you can perform one of the following procedures in the recommended order on the affected system:

  • Restarting the tmrouted process
  • Clearing the OSPF session
  • Terminating and recreating the OSPF configuration

Impact of workaround: Performing any of the following procedures will briefly interrupt OSPF routing.

Restarting the tmrouted process

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the tmrouted process, type the following command:

    restart sys service tmrouted

Clearing the OSPF session

  1. Log in to the Advanced Shell (bash).
  2. To clear the OSPF session, type the following command:

    imish -e 'clear ip ospf process'

Terminating and recreating the OSPF configuration

  1. Log in to bash.
  2. To enter privileged mode, type the following command:

    enable

  3. To enter router mode, type the following command:

    config t

  4. To terminate the current OSPF configuration, use the following command syntax:

    no router ospf <OSPF process ID>

    For example, to terminate the configuration for OSPF process ID 200, type the following command:

    no router ospf 200

  5. Reconfigure the OSPF configuration.
  6. To exit configuration mode, type the following command:

    end

  7. To save the configuration, type the following command:

    write
