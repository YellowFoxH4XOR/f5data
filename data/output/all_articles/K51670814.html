Description

In some environments it may be necessary to disable hardware and software syn-cookie protection

  • Syn-cookie protection provided by upstream firewall
  • Syn-cookies causing problems with normal traffic flow
  • Could be hitting Bug ID 802493 HW Syncookie may retrieve incorrect MSS

Environment

F5 support does not generally recommend disabling syn-cookie protection but under some circumstances it may be necessary.

You can check if syn-cookies are activated by checking the global traffic stats and the per-virtual stats.

tmsh show sys traffic raw | grep Syncookies
  HW Syncookies Generated            75.5M
  HW Syncookies Detected             10.0M

tmsh show ltm virtual | grep -i "ltm\|\-\-\-\|full-software\|full-hardware\|not-activated\|Total Software Accepted\|Total Hardware Accepted"
------------------------------------------------------------------
Ltm::Virtual Server: example-virtual-server-1
------------------------------------------------------------------
  Status                         not-activated
  Total Software Accepted                    0
  Total Hardware Accepted                 8.5M
------------------------------------------------------------------
Ltm::Virtual Server: example-virtual-server-2
------------------------------------------------------------------
  Status                         not-activated
  Total Software Accepted                    0
  Total Hardware Accepted                 1.5M

Recommended Actions

In BIG-IP 11.x and 12.x it is not possible to completely disable software syn-cookie protection, but the activation thresholds can be configured to maximum and hardware syn-cookie protection can be disabled.
Also if syn-cookie protection is already activated and you are on a version affected by ID 667618 then a reboot will be required to de-activate syn-cookie protection.

Example for 11.5.4:

  1.  Can not disable software syn-cookie protection in 11.x but we can set the threshold to max:
    tmsh modify sys db connection.syncookies.threshold value 2147483647

  2. Can not disable software syn-cookie protection in 11.x but we can configure the per virtual syn-cookie threshold to maximum the virtual servers:
    tmsh modify sys db pvasyncookies.virtual.maxsyncache value 4093

  3. Disable hardware syn-cookie protection:
    tmsh modify sys db pvasyncookies.enabled value false       ## required after every reboot or mcpd restart due to ID 675431

  4.  Also per-profile changes are required for tcp and FastL4 profiles:
    tmsh modify ltm profile tcp [profile name] hardware-syn-cookie disabled
    tmsh modify ltm profile fastL4 [profile name] hardware-syn-cookie disabled    ## needed because of ID 690316
    tmsh modify ltm profile fastL4 [profile name] software-syn-cookie disabled    ## needed because of ID 690316

Example for 12.1.2:

  1.  Can not disable software syn-cookie protection in 12.x but we can set the threshold to max:
    tmsh modify sys db connection.syncookies.threshold value 2147483647

  2. Can not disable software syn-cookie protection in 12.x but we can configure the per virtual syn-cookie threshold to maximum the virtual servers:
    tmsh modify sys db pvasyncookies.virtual.maxsyncache value 65535

  3. Disable hardware syn-cookie protection:
    tmsh modify sys db pvasyncookies.enabled value false       ## required after every reboot or mcpd restart due to ID 675431

  4.  Also per-profile changes are required for tcp and FastL4 profiles:
    tmsh modify ltm profile tcp [profile name] hardware-syn-cookie disabled
    tmsh modify ltm profile tcp [profile name] syn-cookie-whitelist enabled
    tmsh modify ltm profile fastL4 [profile name] hardware-syn-cookie disabled    ## needed because of ID 690316
    tmsh modify ltm profile fastL4 [profile name] software-syn-cookie disabled    ## needed because of ID 690316
