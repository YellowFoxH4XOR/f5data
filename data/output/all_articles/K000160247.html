Description

IP (IPI) Intelligence objects cannot be synchronized across all traffic groups. IPI object changes (such as adding or removing IP addresses with TTL values or editing categories) made on the primary device of traffic-group-1 do not appear on other devices or traffic groups. The configuration is only visible on the device where it was created and is stored in the background (hence it is not visible if you try searching for it in the configuration).

You will see an error in the UI such as this:

An error occurred:
#######:#: Non active device[/partition/HOSTNAME] is not allowed to add shuns to the system.

Environment

  • Product: BIG-IP Advanced WAF
  • Version: 17.1.3
  • Configuration:
    • Multiple traffic groups
    • IP Intelligence objects and categories

Cause

Current product design limitation: IPI object changes can only be made from the primary device of traffic-group-1. These changes are stored in the background and are not visible in the configuration on standby devices or other traffic groups. The configuration is not propagated to other traffic groups or devices as expected. But, is propagated to other devices on the same traffic group it was created (traffic-group-1) at failover, if the TTL has not expired.

Answer/Recommended Actions

  • IPI object changes (additions, edits, deletions) must be performed on the primary device of traffic-group-1.
  • These changes are not visible in the configuration on other devices or traffic groups, but are stored in the background and will take effect if a failover occurs within the defined TTL (e.g., 120 seconds).
  • It is not currently possible to synchronize IPI object changes across all traffic groups or devices.

Additional Information

Feature requests have been submitted to allow IPI object management from any traffic group and to improve visibility and synchronization across devices.
