Known Issue

An LB::status iRules command that references a pool name in a variable has validation issues.

This issue occurs when the following condition is met:

  • An iRule uses the LB::status command that references a pool name in a variable.

For example:

LB::status pool $getPoolName member $getMemberName

or

LB::status pool /Common/Test_Pool member $getMemberName

Impact

You cannot use the LB::status iRule.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H717798 on the Diagnostics > Identified > Medium page.
  • When you use an LB::status iRule where the DNS Pool name is in a variable, instead of directly written into the command, the BIG-IP system displays an error message similar to the following example:

    Can't read '$<Variable_Name>': no such variable.
