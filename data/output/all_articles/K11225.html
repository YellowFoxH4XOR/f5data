Topic

An iRule is a powerful and flexible feature that you can use to manage your network traffic. You can add an iRules event to a BIG-IP APM access policy to trigger a specific iRule at a specific point in the access policy. For detailed information about iRules syntax, refer to the F5 DevCentral web site.

Note: A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Note: For a list of supported iRules events, refer to Appendix D in the Configuration Guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

The following procedure creates an iRule, enables the iRule on a virtual server, and adds an iRule event to the access policy to trigger the iRule:

Note: This procedure assumes that you have a working access policy associated with a virtual server.

  1. Log in to the Configuration utility.
  2. Expand Local Traffic.
  3. Click iRules.
  4. Click Create to create a new iRule.
  5. In the Name field, enter a name for the iRule.

    For example:

    log-av-failure

  6. In the Definition field, enter the iRule.

    For example:

    when ACCESS_POLICY_AGENT_EVENT {
       log "Antivirus check failed"
    }

    Note: The event ACCESS_POLICY_AGENT_EVENT ensures that the iRule will not run unless it is specifically triggered by an iRule event action configured in the access policy.

  7. Click the Finished button to save the iRule.
  8. Under Local Traffic, click Virtual Servers.
  9. Click the name of the virtual server to which the access policy is applied.
  10. Select the Resources tab.
  11. Next to iRules, click Manage.
  12. In the Available box, highlight the name of the iRule you just created.
  13. Click the << button.

    The iRule moves to the Enabled box.

    Important: The iRule must be enabled in the virtual server in order to be triggered by the associated access policy.

  14. Click Finished.
  15. Expand Access Policy.
  16. Click Access Profiles.
  17. Click the Edit link next to the name of the access profile associated with the virtual server you just modified.

    The visual policy editor opens in a new window or tab.

  18. On a rule branch of the access policy, click the plus sign (+) to add the iRule event.

    The Add Item pop-up screen opens.

  19. Select iRule Event.
  20. Click Add Item .
  21. In the ID box, type the name of the iRule exactly as you entered it in step 5.

    For example:

    log-av-failure

  22. Click Save.
  23. In the top left corner of the visual policy editor, click Apply Access Policy.

Using the example above, when the iRule event is triggered in the access policy, a log message similar to the following example is logged to the file /var/log/ltm:

Mar  1 15:50:20 local/tmm info tmm[4511]: 01220002:6: Rule log-av-failure <ACCESS_POLICY_AGENT_EVENT>: Antivirus check failed

Additionally, you can view the iRule statistics using the b rule command. For example:

[root@3400a:Active] ~ # b rule log-av-failure
RULE log-av-failure
+-> ACCESS_POLICY_AGENT_EVENT   4 total   0 fail   0 abort
[root@3400a:Active] ~ #
