Description

Under certain conditions you may notice that virtual server forwards HTTP requests to pool members as HTTP/0.9 requests in which headers are stripped.
It may cause applications to behave in unexpected ways due to missing headers.
It may cause cookie-based persistence to not work.

Environment

  • BIG-IP LTM
  • HTTP Profile
  • HTTP request with unencoded space in the URI, ex.
GET /example uri HTTP/1.1

Cause

HTTP requests with unencoded space in URI are not valid as they do not comply with RFC7230

BIG-IP treats such requests as HTTP version 0.9 and therefore forwards to pool members request without headers.
 
Recommended Actions

Ensure that client does not include space characters in URI, or correctly encode space characters.
