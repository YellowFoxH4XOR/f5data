Description

You have setup the Application Security (ASM) or the Advanced Web Application Firewall (AdvWAF) Synchronization and ensured it is configured correctly, but there are indications it is not working. What do you do next? Symptoms may include seeing policies or Learning Persistence tables that are not sync'd.

Environment

  • ASM sync has been setup per F5 documentation K12200102: Enabling Application Security Synchronization on a device group and/or per the applicable manuals for the version you are using.
  • ASM Device Sync-Only (Preferred) or Sync-Failover is being used
  • ASM, Advanced WAF, Device Service Cluster

Cause

There are various causes that can bring about an issue with ASM sync. They range from a bug to the asm_config_server process being "stuck".

Recommended Actions

You can investigate this yourself by creating an asmqkview and uploading it to iHealth (K12878: Generating diagnostic data using the qkview utility) and then reviewing the Diagnostics and Log files it contains. You can also search via the CLI through those logs, but the asmqkview is likely easier. The steps below do two things... 1) They give you the steps to create the asmqkview for upload to iHealth for your own review and 2) They provide the data needed, in advance, if you find you need to open a case with F5 Support to speed up the process.

  1. Enable asm_config_server debug...
    1. Open an ssh session to the BIG-IP.
    2. Run these 3 commands in the bash shell (they can also be run in the TMOS shell by omitting the 'tmsh' part of the command):
      tmsh modify sys db log.asm.asmconfig.level value debug
      tmsh modify sys db log.asm.asmconfigevent.level value debug
      tmsh modify sys db log.asm.asmconfigverbose.level value debug
 
Next you will need to follow these steps...
  1. Enable mcpd debug...
    Important: You should enable debug logging for the mcpd process for the shortest period of time possible to reduce unnecessary logging and data collection. This minimizes customer impact and provides mcpd debug logging specifically while the system runs the suspect configuration change or other commands.
    1. Log in to the BIG-IP Configuration utility.
    2. Browse to System > Logs > Options.
    3. For MCP option, select Debug.
    4. Select Update.
  2. Attempt a config sync of the Device Service Group used for ASM/AdvWAF.
  3. Immediately disable mcpd debug by returning it to the Notice setting.
  4. Disable the asm config db variables by changing the value 'debug' to 'info' and running the commands.
  5. Using an app such as WinSCP, or the scp command, retrieve the mcpd.out file from /shared/tmp.
  6. Purge the mcpd.out file using this command.
    cat /dev/null > /shared/tmp/mcpd.out
    This is necessary in order to keep the file to a reasonable size.
  7. Create an asmqkview...
    1. To create an asmqkview it must be done on the CLI.
    2. Run the following command:
      Note: The --add-request-log option includes the ASM request logs and traffic data in the resulting qkview file which may contain sensitive parameter information, such as usernames or passwords.
      asmqkview -s0 --add-request-log -f /var/tmp/`/bin/hostname`_asmqkview_`date +%Y%m%d%H%M%S`.tgz
    3. This kind of qkview is typically much larger and can be over 600MB and take over 20 minutes to run.
    4. Once the asmqkview script is finished, the resulting file will need to be retrieved from the BIG-IP and will be in directory /shared/tmp/.
  8. Upload the asmqkview to iHealth for your review.
    1. When reviewing the logs for this kind of issue the most common places to look are /var/log/asm and /var/log/log/ts/asm_config_server.
  9. If you find you need to open a case with F5 Support (K6825: Information required when opening a support case for BIG-IP ASM) you can then include in the case information that you have followed these steps. You should also upload the asmqkiew to F5 Support Files (K000090853: Exchange files with F5 Support using MyF5). Once it has been loaded up to F5 Support Files we can then create a repro of the ASM/AdvWAF policy configuration, Event logs, and Learning Suggestions. Due to the nature of how these are stored in a mysql database they are not included in a standard qkview and it is the only way to view them.
