K04373820: Telemetry RPM and Schema Version Mismatch

Description
iControl REST API Telemetry schemaCurrent and schemaVersion values do not match

Example API Declaration:

fqdn: example.f5.com

api_call: /mgmt/shared/telemetry/info'

{
'nodeVersion': 'v8.11.1',
'version': '1.27.0',
'release': '3', '
schemaCurrent': '1.27.0', <- RPM VERSION
'schemaMinimum': '0.9.0'
}

api_call: /mgmt/shared/telemetry/declare
{'class': 'Telemetry', 'My_Poller': {'class': 'Telemetry_System_Poller', 'interval': 0, 'actions': [{'includeData': {}, 'locations': {' 'system': true}, 'enable': True}], 'host': 'localhost', 'port': 8100, 'protocol': 'http', 'allowSelfSignedCert': False, 'enable': True}, 'My_System': {'class': 'Telemetry_System', 'enable': True, 'systemPoller': 'My_Poller', 'host': 'localhost', 'port': 8100, 'protocol': 'http', 'allowSelfSignedCert': False}, 'My_Pull_Consumer': {'class': 'Telemetry_Pull_Consumer', 'type': 'Prometheus', 'systemPoller': 'My_Poller', 'enable': True, 'trace': False}, 'schemaVersion': '1.20.1'} <- DIFFERENT SCHEMA VERSION

Environment

  • BIG-IP
  • iControl REST API

Cause
Telemetry Schema does not support true API versioning.  A declaration submitted with schemaVersion 1.0.0 will be treated exactly the same as a declaration submitted with schemaVersion 1.20.0.  The purpose of the schemaVersion property is simply to check that the submitted declaration is not expecting to use features that are newer than the running version of Telemetry Schema.

If the schemaVersion property is omitted in the declaration, the current product schemaVersion is inserted by default.  Since all 1.x.x versions are backwards compatible, any version less than the current product schemaVersion and greater than the current schemaMinimum is acceptable.
