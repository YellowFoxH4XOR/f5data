K000163423: LTM Pool Members Remain Unchecked After MCPD Restart

Type
Support Solution
Published
2026-09-29
Updated
2026-09-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163423

Description

When MCPD crashed, the monitor agent channels between bigd and TMM were closed. All in-TMM monitor activities were deleted. Related logs found in /var/log/ltm log file:

 

Lost connection to mcpd

Monitor Agent TMM: channel connection closed

Monitor Agent TMM: deleted activity

 

Under normal circumstances, bigd should restart, reconnect to TMM, and recreate all monitor activities after MCPD restart. In few cases, communication between bigd and TMM may not recover correctly after MCPD restart. Monitor activities can remain deleted, leaving pool members in a Checking or blue state with no health-monitor probes being transmitted.

 

Environment

  • BIG-IP LTM
  • Multiple bigd worker processes
  • Pool members with health monitor enabled

 

Cause

Two known defects can cause this behaviour when bigd runs as multiple processes

 

1. Bug ID 1481969 - Under certain conditions, when the connection between bigd and TMM is interrupted, bigd closes the socket and reconnects but does not reset its internal tracking of monitor activities. It believes all activities are already created in TMM when they are not. No probes are sent.

 

2. Bug ID 1091021 - When bigd consists of multiple processes, they all share a single heartbeat row with the sod daemon. If one or more bigd processes become impaired, sod cannot detect this because the remaining healthy processes continue updating the shared heartbeat. The impaired process remains running but non-functional indefinitely.

 

Answer/Recommended Actions

Impact: Restarting bigd will cause a brief interruption to health monitoring. Monitor status will temporarily show pool members as "checking" until probes complete.

 

The following workaround steps can restore monitor functionality without a full device reboot:

 

1. Restart bigd:

 bigstart restart bigd

 This forces all bigd processes to fully restart and recreate their TMM monitor channels and activities from scratch.

 

2. If step 1 does not resolve the issue, forcefully terminate all bigd worker processes:

 pgrep -f 'bigd\.[0-9]+' | xargs kill -9

The bigd processes will be automatically restarted by the process manager.

For a permanent fix, install a supported software release or engineering hotfix containing fixes for Bug ID 1091021 and Bug ID 1481969. EHF for Bug ID 1481969 can be provided through a support case.
