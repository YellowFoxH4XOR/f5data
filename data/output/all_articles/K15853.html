Known Issue

When you register with the Lights Out Processor (LOP) daemon (lopd) or the VIPRION CAN daemon (cand), the system logs messages that you can safely ignore.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a remote syslog server.
  • The remote syslog logging level is configured at the informational (info) level, which has a higher verbosity.

Impact

The remote server's log file is filled with BIG-IP cand or lopd messages.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H491294 on the Diagnostics > Identified > High screen.
  • The remote syslog server receives the lopd message from the BIG-IP system every 2 seconds.
  • The remote syslog server receives the cand message from the BIG-IP system every 20 seconds.
  • The cand message may appear similar to the following example:

    info cand[18088]: 013d0007:6: request for unsolicated data on 2.1041
    info cand[18088]: 013d0007:6: client /var/run/cand.chmand.can2uns already registered (uid:0)

  • The lopd message may appear similar to the following example:

    info lopd[8519]: 013d0007:6: client /var/run/lopd.chmand.lopuns already registered (uid:0)

  • The cand messages are related to communication with the CAN daemon, and you can safely ignore the messages.
  • The lopd messages are related to communication with the LOP, and you can safely ignore the messages.

Workaround

To work around this issue, you can set the remote syslog logging level to notice (which has a lower verbosity than info). For more information on how to set the log level, refer to K13317: Configuring the level of information that syslog-ng sends to log files (11.x).
