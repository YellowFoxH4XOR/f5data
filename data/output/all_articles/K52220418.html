Description

You should consider using this procedure under the following condition:

  • You wish to use the HTTPS or HTTP2 monitor on a pool member that utilizes TLS v1.3
  • Your HTTPS pool otherwise requires TLS v1.3 and will not accept connections that utilize anything less
  • In-TMM monitoring has been enabled

Environment

  • BIG-IP 14.x or later
  • In-TMM Monitoring enabled

Cause

In-TMM monitoring allows for TLS 1.3 to be used in monitor probe TLS handshakes, like those used for HTTPS or HTTP2 monitors.

Recommended Actions

First, create a server SSL profile that uses TLS v1.3 - see K10251520.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client or Server.
  3. Select Create or choose an existing profile.
  4. If necessary, for Configuration, select Advanced.
  5. For Ciphers, select the Custom check box.
  6. Select Cipher Group, and then select a group such as f5-default, which is equivalent to the DEFAULT cipher string from the list.
    Note: When TLS 1.3 is enabled, you must configure a cipher group.
  7. For Options, select the Custom check box.
  8. In the Enabled Options list, select No TLSv1.3 and then select Disable.
  9. Configure other properties as needed.
  10. Select Finish or Update.

Second, create a new HTTPS or HTTP/2 monitor depending on your application environment.

  1. Go to Local Traffic > Monitors.
  2. Select Create.
  3. Name your monitor, and for Type, select https or http2.
  4. For Configuration, select Advanced.
  5. Under SSL Profile, select the new profile that you created in the above steps.
  6. Configure other properties as needed.
  7. Select Finish.

Finally, add this monitor to your pool.

  1. Go to Local Traffic > Pools > Pool List.
  2. Select the pool you wish to monitor, or create a new pool as needed.
  3. Under Configuration, go to Health Monitors.
  4. Select your new monitor in the Available list, and make it active.
  5. Select Update.

You are now monitoring this pool with TLS v1.3.
