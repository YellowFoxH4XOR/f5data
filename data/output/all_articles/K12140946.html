Topic

You should consider using this procedure under the following conditions:

  • You want to configure your BIG-IP system to encrypt application traffic using a Client SSL profile.
  • You want to configure the Client SSL profile to perform two-way or mutual Secure Sockets Layer (SSL) authentication.

Description

SSL certificates protect application traffic by providing encryption, authentication, and message integrity. This article discusses authentication and how to configure mutual or two-way (mutual) authentication using a Client SSL profile to protect application traffic.

One-way authentication

One-way authentication is the most popular method for protecting application traffic. Using one-way authentication, clients perform SSL handshakes when initiating a new connection with SSL protected applications. During the SSL handshake, the protected application sends its public SSL certificate to the remote client for validation. The remote client validates the application's public SSL certificate by searching for the signing Certificate Authority (CA) certificate in its trusted CA store. If the remote client is unable to validate or find the signing CA for the public SSL certificate, it should not complete the SSL handshake and abandon the new connection attempt.

Figure: One-way authentication

Two-way authentication

Two-way authentication is a less popular method for protecting application traffic as it requires an additional layer of security. When using two-way authentication, clients perform a slightly modified SSL handshake when initiating a new connection with SSL-protected applications. During the modified SSL handshake, the protected application sends its public SSL certificate to the remote client for validation and requests that the remote client sends its Client SSL certificate for validation as well. Both the remote client and protected application validate the SSL certificates they receive by searching for the signing CA certificates in their respective trusted CA stores. If the remote client or the protected application is unable to validate the received SSL certificate, they should not complete the SSL handshake and abandon the new connection attempt.

Figure: Two-way authentication

Client SSL profiles

When you configure the BIG-IP system to protect application traffic using a Client SSL profile, you can use either one-way or two-way authentication. This article discusses how to configure the BIG-IP system to protect application traffic using two-way authentication and assumes you have already configured a virtual server with associated pool members.

Prerequisites

You must meet the following prerequisites to use the procedures:

  • You have administrative access to the Configuration utility.
  • You have the application or website's SSL certificate and key.
  • You have the SSL certificate used by the CA to sign client certificates.
  • You have an optional Certificate Revocation List (CRL) file.

Procedures

To watch a video demo of these procedures, go to Configure the BIG-IP system to perform two-way SSL authentication using a Client SSL profile.

  • Import the website SSL certificates and key
  • Create the Client SSL profile
  • Import the client certificate (PFX file)

Import the website SSL certificates and key

To configure mutual authentication, you must first import the application or website SSL certificate and key, and then the CA certificate to sign the client certificates. You can also import a CA CRL file, if required. The following table details how to use each SSL certificate and key in the Client SSL profile.

SSL objectClient SSL profile option / use
SSL certificate and keyReferenced by the Certificate Key Chain option to protect application traffic.
CA signing certificateReferenced by the Trusted Certificate Authorities option to validate client SSL certificates.
CRLReferenced by the CRL File option to validate revoked certificates.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Import the application or website certificate and key

  1. Log in to the Configuration utility.
  2. To import the SSL certificates and key, go to System > Certificate Management > Traffic Certificate Management > SSL Certificate List > Import.
  3. For Import Type, select Key.
  4. Ensure New is selected.
  5. For Key Name, enter a unique name for the SSL key.
  6. For Key Source, select either Upload File or Paste Text.
  7. Select Import.
  8. Under Name, select the newly imported key by name.
  9. Select Import.
  10. For Certificate Source, select either Upload File or Paste Text.
  11. Select Import.

Import the CA signing certificate

  1. To import the CA signing certificate, select Import located in the top-right section.
  2. For Import Type, select Certificate.
  3. Ensure New is selected.
  4. For Certificate Name, enter a unique name for the CA signing certificate.
  5. For Certificate Source, select either Upload File or Paste Text.
  6. Select Import.
  7. You can repeat this procedure to import the Privacy-enhanced Mail (PEM)-encoded CRL file if certificate revocation validation is required.

Create the Client SSL profile

After importing the necessary SSL certificates and key, you must configure the Client SSL profile for two-way authentication. You can configure two-way authentication in a strict manner (require) or more loosely (request). The following table details the basic Client SSL profile options to configure two-way authentication.

OptionDescription
Client CertificateRequire: The BIG-IP system will request a Client SSL certificate and continue the SSL handshake only if the client certificate is signed by the trusted CA associated with the Client SSL profile.
Request: The BIG-IP system will request a Client SSL certificate and continue the SSL handshake regardless of whether the client certificate is signed by the trusted CA associated with the Client SSL profile.
Trusted Certificate AuthoritiesAssociates the CA certificate that the BIG-IP system uses to validate client certificates.
Advertised Certificate Authorities (optional)Associates the CA certificate that the BIG-IP system advertises to remote clients to help select the proper client certificate.
CRL File (optional)Associates the PEM-encoded CA revocation list to validate revoked SSL certificates. For CRL file size limits, refer to K10054: The BIG-IP file size limits for CRL files.

Based on your Client SSL profile status, choose one of the following two options:

  • If your Client SSL profile is new, perform all of the following procedure:
    • Associate the application or website SSL certificate and key
    • Associate the CA signing certificate and optional CRL
    • Associate the Client SSL profile with the virtual server
  • If the Client SSL profile exists and is already associated with the virtual server, perform the following procedures:
    • Associate the application or website SSL certificate and key
    • Associate the CA signing certificate and optional CRL

Associate the application or website SSL certificate and key

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. If the profile already exists, select the profile under Name. If the profile does not exist, select Create to the right of the page.
  4. For Name, enter a unique name for the Client SSL profile.
  5. For Configuration, select the Custom check box.
  6. For Certificate Key Chain, select Add.
  7. For Certificate and Key, associate the application or website SSL certificate and key.
  8. Select Add.
  9. If a CRL is required, associate the CRL file by performing the following procedure.

Associate the CA signing certificate and optional CRL

Impact of procedure: If the SSL profile's Client Certificate option is set to Require, SSL handshakes initiated by clients without an SSL certificate signed by the trusted CA will fail.

  1. For Client Authentication, select the Custom check box.
  2. For Client Certificate, select either require or request.
  3. For Trusted Certificate Authorities, select the imported CA signing certificate.
  4. Optional: For Advertised Certificate Authorities, select the imported CA signing certificate.
  5. Optional: For CRL File select the PEM-encoded CRL file.
  6. Select Add.
  7. If your Client SSL profile is new, associate the profile with the virtual server by performing the following procedure.

Associate the Client SSL profile with the virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Under Name, select the virtual server by name.
  3. Under Configuration, locate the SSL Profile (Client) section.
  4. Under Available, select the new Client SSL profile by name and move it to the Selected list.
  5. Select Update.

Import the client certificate (PFX file)

The final step is to install the client certificate in the web browser's SSL certificate store using a Personal Information Exchange (PFX) file (.pfx). The PFX file contains both the signed Client SSL certificate and key and is usually password protected. The steps may vary depending on your web browser.

Note: If you set the Client Certificate option to Require, attempt a new SSL connection prior to importing the client certificate to ensure the connection fails.

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Microsoft Edge and Chrome

  1. Copy the PFX file to your local workstation.
  2. Open the browser.
  3. In the browser address bar, enter one of the following depending on your browser:
    1. edge://certificate-manager/clientcerts
    2. chrome://certificate-manager/clientcerts
  4. Select Manage imported certificates from Windows.

    Note: On MacOS systems with Chrome, select Manage imported certificates from MacOS. You will then need to follow the prompts to import the client certificate on your MacOS system. The rest of this procedure assumes you are using Windows.

  5. To use the Certificate Import Wizard, select Import, then select Next on the following screen.
  6. Select Browse and go to the location of the PFX file on your workstation.

    Note: If the PFX  file does not appear, filter for Personal Information Exchange.

  7. Select the PFX file, then select Open.
  8. Select Next.
  9. If the PFX file is password protected, enter the password.
  10. Select Next.
  11. Confirm client certificates are in the Personal certificate store.
  12. Select Next.
  13. Select Finish.

Firefox

  1. Copy the PFX file to your local workstation.
  2. In the browser address bar, enter about:preferences#privacy.
  3. Under Certificates in the Security section, select Manage Certificates.
  4. Ensure Your Certificates is selected at the top of the page.
  5. Select Import.
  6. Go to the client location of the PFX file on your workstation.

    Note: If the PFX file does not appear, filter for PKCS12 Files.

  7. Select the PFX file, then select Open.
  8. If the PFX file is password protected, enter the password.
  9. Select OK.

After you install the client certificate, you should be able to access the website. If you have SSL connectivity issues after importing the client certificate, refer to K14819: Troubleshooting client certificate authentication.
