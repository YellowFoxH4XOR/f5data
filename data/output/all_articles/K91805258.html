Description

Video streaming is having an issue when using Firefox. The same video stream is playable when using Google Chrome.

When a pcap is captured TCP ZeroWindow is noticeable being sent to the server. Eventually the BIG-IP will send a RST to the server.

Environment

  • BIG-IP LTM
  • Firefox is not able to stream video correctly
  • Google Chrome has no issue streaming the same video
  • Pcap shows that TCP ZeroWindow and RST is being sent by the BIG-IP to the server

Cause

The behavior seen is called content spooling and it is not necessary a BIG-IP issue.

Basically, the BIG-IP will buffer and store data until the TCP connection in which it will be sent allows when the client allows the BIG-IP to do so. In this case, the BIG-IP receiving and acknowledging data pretty fast, but the client does not. If the server doesn't stop sending and the client will not receive as fast as BIG-IP do from the server, then data needs to be stored somewhere. That's where the BIG-IP buffer comes in.

However the buffer is not an infinite amount of data, so when the buffer for that connection starts filling up the BIG-IP, need to tell the server to either slow down or to stop, until the client starts acknowledging the BIG-IP data and opens its receive window again.

Client side pcap will show that the client Window Size will decrease and the BIG-IP will mimic the Window Size to the server. The BIG-IP will ZeroWindow telling the server to stop sending more data while waiting for the client.

Details of content spooling can be read at K3422.

On why this issue is happening on Firefox and not Google Chrome is because on Firefox there is only one TCP stream but on Google Chrome, there will be multiple TCP streams. On each TCP stream behavior BIG-IP will send a RST when it is not able to receive more packets from the server. Once the RST is sent, the video will stop streaming.

Since there is more than one TCP stream on Google Chrome, not all TCP stream will RST thus Google Chrome will keep streaming the video.

Recommended Actions

To resolve the issue, you will need to increase the proxy buffer and/or increase Zero Window Timeout.

Increase the proxy buffer

  1. Login to the BIG-IP Configuration Terminal.
  2. Navigate to Local Traffic > Profiles > Protocol > TCP.
  3. Click on the associated TCP profile to the mentioned Virtual Server.
    Important: Do not modify the default TCP profile. Create a new custom TCP
  4. Under Memory Management, make changes to these values.
    Proxy buffer high: 262144
    Proxy buffer low: 196608
    Receive window: 131072
    Send buffer: 196608
  5. Click Update.
Increase the Zero Window Timeout
  1. Login to the BIG-IP Configuration Terminal.
  2. Navigate to Local Traffic > Profiles > Protocol > TCP.
  3. Click on the associated TCP profile to the mentioned Virtual Server.
    Important: Do not modify the default TCP profile. Create a new custom TCP
  4. Under Zero Window Timeout , increase the current value.
    Note: It is recommended that you gradually increase it and test so you can find the appropriate value that works for their application.
  5. Click Update.
