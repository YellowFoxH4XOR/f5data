K000138685: After upgrading from 15.x to 16.x or 17.x some requests are not working

Type
Support Solution
Published
2024-02-26
Updated
2026-07-02
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000138685

Description

After upgrading BIG-IP from v15.x to 16.x or 17.x, some requests are not working

  • Up to further inspection, these requests are being reset by BIG-IP.
  • Analysis of packet captures, reveal these connections are reset due to "Compression Error"
  • RST Cause: Compression Error

Environment

Relevant environmental factors specific to the topic

  • Upgraded from BIG-IP v15.x to 16.x/17.x
  • BIG-IP LTM
  • The response from the back-end may be chunked
  • The assembled response is quite large (more than 1,572,864 bytes)
    • To check the size of an assembled, decrypted http response in wireshark, ensure 'Allow subdissector to reassemble TCP streams' is enabled in Protocol Preferences. Click on the reassembled http response, and in the http fields you will see the uncompressed size:

            Content-encoded entity body (gzip): 40000 bytes -> 4000000 bytes

            File Data: 4000000 bytes

Cause

This is due to the introduction of a new feature called tmm.deflate.memory.threshold with BIG-IP 16.x and 17.x. This was introduced to prevent high memory usage under certain scenarios.

Recommended Actions

To mitigate this, follow steps below:

  1.  Increase the tmm.deflate.memory.threshold to higher value.
  2. The maximum possible value of tmm.deflate.memory.threshold is depends on the BIG-IP version:
    1. BIG-IP 16.x and 17.x up to 17.1.3.0: 4,718,592
    2. BIG-IP 17.1.3.1: 9,437,184 (expanded by the fix for Bug ID1474877)
    3. BIG-IP 17.1.3.2: 4,718,592 (the BigDB.dat range update from 17.1.3.1 was not carried forward; 17.1.3.2 is listed in the Known Affected Versions of Bug ID1474877)
  3. The command below is to set the threshold value:
# tmsh modify sys db tmm.deflate.memory.threshold value 3000000

Additional Information

NOTE: If the responses are higher than 4718592 bytes, reach out F5 support and request for a Hotfix for ID1474877. With the EHF in place, tmm.deflate.memory.threshold can be increased to much higher values and can be completely disabled by setting tmm.deflate.memory.threshold to 0. If you decide to disable the db variable all-together proceed with caution, as doing so will expose the system to certain types of attacks.
