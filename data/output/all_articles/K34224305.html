Topic

What You'll Learn

A growing number of web application requests are coming into datacenters over SSL. As a system administrator, you want to make sure this traffic is secure and fast.

You can do this with the BIG-IP LTM system by applying a basic set of security and optimization features for your web traffic.

Description

The following videos guide you through the steps to secure and optimize your inbound traffic before it reaches your web servers.

Enable system-wide state mirroring

Before you start this task, make sure your BIG-IP user account gives you permission to use the Traffic Management Shell (tmsh).

For application requests coming in over SSL, you should enable a system-wide variable called statemirror.secure.

You can also find the video here: How to enable system-wide state mirroring
 

Set up OCSP stapling to send certificate status

Before you start this task, make sure that there is a proxy server pool or a DNS resolver already configured on the system.

Create an OCSP Stapling profile to speed up the time it takes for the client to get the revocation status of the BIG-IP system's device certificate during an SSL handshake.

You can also find the video here: How to set up OCSP stapling
 

Look for SSLv3 support in a cipher string

Before you start this task, make sure your BIG-IP user account gives you permission to use the Advanced Shell (bash) shell prompt.

SSL3 is an unsecure protocol. Before you set up the system to decrypt and re-encrypt inbound connections, find out whether the ciphers you want to specify in the Client and Server SSL profiles include or exclude support for SSL3.

You can also find the video here: How to look for SSLv3 support in a cipher string
 

Decrypt SSL connections and manage ciphers for client-side requests

Create a Client SSL profile where you can define the cipher strings that you want to manage the client-side requests. With this profile, the BIG-IP system decrypts all HTTPS requests that it receives from the client.

You can also find the video here: How to create a Client SSL Profile

Re-encrypt SSL connections and manage ciphers for server-side requests

To re-encrypt SSL connections, you need a Server SSL profile. This profile allows you to re-encrypt all SSL client requests that it sends to a web server.

You can also find the video here: How to create a Server SSL profile
 

Enforce full encryption by enabling HSTS in an HTTP profile

You can create your own HTTP profile to tell the BIG-IP system how you want it to manage HTTP traffic. When you create an HTTP profile, you should enable the HSTS (Hypertext Strict Transport Security) protocol, which makes sure that clients communicate only with servers over a fully-encrypted connection. Doing so helps to prevent cookie hijacking and man-in-the-middle attacks.

You can also find the video here: How to enable HSTS
 

Identify your web servers to the BIG-IP system

Before you start this task, you need to know the IP addresses of the servers you want to include in your server pool.

To configure SSL data protection, you must create a web server pool with pool members. The IP addresses in the pool identify what web servers you want the virtual server to send client requests to, using a round-robin approach.

You can also find the video here: How to identify your web servers to the BIG-IP system
 

Set a target virtual server BIG-IP address for inbound client requests

Before you create a virtual server, make sure that you have already created your own HTTP and Client SSL and Server SSL profiles.

A virtual server is a target IP address and port for inbound client traffic. The virtual server tells the BIG-IP system what profiles to apply and which pool of servers to send client requests to.

You can also find the video here: How to set a target address for inbound client requests
