Description
This article explains how MRF responds back to the client if the Diameter Server does not reply after a specified period of time.
By default, MRF does not reply back to the client if a timeout occurs, but this can be configured at the MRF session profile.

Environment
  • LTM
  • MRF (virtual server type: message routing)
  • Diameter
Cause

 The diameter peer is not responding to the application traffic within the configured timer i.e. Retransmission Timeout.

Recommended Actions
You can set the retransmission action by navigating below:

In the BIG-IP Configuration utility (gui), navigate to Local Traffic > Profiles > Message Routing > Diameter  > Profile name.
Modify the Retransmission Action and the Retransmission Timeout.

Example:
If you set the retransmission timeout value as 3 seconds and If you want to send the result code 3004 (DIAMETER_TOO_BUSY) to the client.  Then Select "Retransmission actions" as busy. 
In this case, MRF will send DIAMETER_TOO_BUSY to the client.
