Description

  • Active/Standby units shows different device status from CLI and from WebUI.
  • Device-groups shows Standby device with status Offline on the WebUI, but from CLI it is Online with all device-groups are in SYNC.
  • No traffic impact

Environment

  • vCMP system
  • Multi-Blade clustered system
  • High Availability environment 

Cause

Cluster's members IP addresses are missing with Failover Unicast Configuration, as it shown in the example below:
list /sys cluster all-properties

sys cluster default {
    address 10.10.10.10/27
    enabled
    members {
        1 {
            address ::
            enabled
            priming disabled
        }
        2 {
            address ::
            enabled
            priming disabled
        }
        3 {
            address ::
            enabled
            priming disabled
        }
        4 {
            address ::
            enabled
            priming disabled
        }
    }
    min-up-members 1
    min-up-members-enabled yes
}

Recommended Actions

You can define a mesh of unicast entries using the cluster member IP address of each blade in each VIPRION system. The full mesh of unicast entries includes the cluster member IP address for each slot on the VIPRION system that is configured to communicate with the cluster member IP address for each slot on the peer VIPRION system. If you are unable to use the previous multicast option, you may use the unicast mesh option.
Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, go to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

To define a unicast mesh, perform one of the following procedures:

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the local host name.

    For example:

    LTM1.example.com (Self)

  4. Select Failover Network.
  5. For Failover Unicast Configuration, select Add.
  6. For Address, choose the cluster member IP address that corresponds to slot 1 on the VIPRION system.
    Important: The cluster IP address is not the same as the cluster member IP address. Use only the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration. You can view the cluster member IP address by going to System > Clusters > Management IP Address.
  7. Accept the default port of 1026.
  8. Select Finished.
  9. Repeat steps 1 through 8 for every slot on the VIPRION system.
    Important: Failure to add the cluster member IP address of each blade in the Failover Unicast Configuration may result in failover daemon (sod) communication issues.
tmsh
  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list the cluster member IP addresses, enter the following command:

    list /sys cluster members address

  3. To define the failover unicast address for the device, specify the cluster member IP address that corresponds to slot 1 on the VIPRION system. To do so, use the following command syntax:

    modify /cm device <hostname> unicast-address {{ ip <cluster_member_addr> }}
    Important: The cluster IP address is not the same as the cluster member IP address. Only use the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration.

  4. Save the configuration by entering the following command:

    save /sys config

  5. Repeat steps 1 through 4 for every slot on the VIPRION system.
    Important: Failure to add the cluster member IP address of each blade in the Failover Unicast Configuration may result in failover daemon (sod) communication issues.
