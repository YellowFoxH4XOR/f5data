K000135437: Clickhouse data growing causing disk pressure

Type
Support Solution
Published
2023-07-10
Updated
2023-07-10
Applies to
  • NGINX Products
  • NGINX Controller: 3.22.6
Source
https://my.f5.com/manage/s/article/K000135437

Description

Clickhouse data store is large and growing. The system is experiencing disk pressure as a result. Several pods are in crashloopbackoff.

Environment

NGINX Controller

Cause

Kubernetes db-rollup-jobs cronjob, responsible for reducing clickhouse data size (down sampling), gets scheduled for a future date. This can occur if NTP becomes disabled, unintentionally or otherwise, and the system time gets set to a future date. While waiting for the cronjob to run clickhouse data will continue to increase.

Recommended Actions

Ensure the system time is correct and NTP is running.
Stop NGINX Controller, delete and pause the db rollup jobs: 

$ /opt/nginx-controller/helper.sh controller stop
Turning controller off... done.
$ kubectl delete pod --force -l app=db-rollup-job
warning: --force is ignored because --grace-period is not 0.
pod "db-rollup-job-1681930500-snd47" deleted
pod "db-rollup-job-1681930800-cfw8q" deleted
pod "db-rollup-job-1681931100-prsbw" deleted
$ kubectl patch cronjobs db-rollup-job -p '{"spec" : {"suspend" : true }}'

Scale up clickhouse:

$ kubectl scale --replicas=1 statefulset clickhouse
statefulset.apps/clickhouse scaled

Note: IF at this point clickhouse shows image pull backoff then load the controller image from the inline installer package into docker:

$ gunzip -c ./controller-installer/files/controller.img.gz | sudo docker load

Truncate all of the clickhouse data:

$ kubectl -n nginx-controller exec -it $(kubectl -n nginx-controller get pod -lapp=clickhouse -o name) -- bash -c "HOME=/tmp clickhouse client -u writer --password \$CLICKHOUSE_PASS_writer -d controller -m"
ClickHouse client version 19.14.7.15 (official build).
Connecting to database controller at localhost:9000 as user writer.
Connected to ClickHouse server version 19.14.7 revision 54425.
clickhouse-0.clickhouse.nginx-controller.svc.cluster.local :) TRUNCATE TABLE controller.metrics;
TRUNCATE TABLE controller.metrics
Ok.
0 rows in set. Elapsed: 0.986 sec.

Note: IF the TRUNCATE query does not remove the data then remove it manually:

  • Detach table in clickhouse: 
    DETACH TABLE controller.metrics;
  • Find path to clickhouse directory on system node: 
    $ kubectl describe pv clickhouse | grep Path: 
Path: /opt/nginx-controller/clickhouse_data
  • Remove metrics data from clickhouse directory on system node: 
    $ sudo rm -rf /opt/nginx-controller/clickhouse_data/data/controller/metrics
  • Attach table in clickhouse: 
    ATTACH TABLE controller.metrics;
Scale down clickhouse: 
$ kubectl scale sts clickhouse --replicas=0 
statefulset.apps/clickhouse scaled

Start Controller:

$ /opt/nginx-controller/helper.sh controller start 
Turning controller on... done.

Note: IF pods show image pull backoff then load the Controller and installer images from the inline installer package into docker:

$ gunzip -c ./controller-installer/files/controller.img.gz | sudo docker load 
$ gunzip -c ./controller-installer/files/installer.img.gz | sudo docker load
