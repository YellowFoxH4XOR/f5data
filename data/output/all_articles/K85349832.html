K85349832: VDI connections fail with the error, ''DNS resolution failed 0 1''

Type
Support Solution
Published
2022-09-01
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K85349832

Description

This solution will give details of this error message and how to correct it.

  • Users are able to login to the Access Policy, but when they attempt to launch VDI connections they fail.
  • The follow error is observed in /var/log/apm:
<big-ip_hoshtname> debug tmm[19853]: 019cffff:7: /Common/<access_policy>:Common:<session_id>: RD: [C] 192.168.1.1.6292 i 10.10.10.1.443: DNS resolution failed 0 1

Environment

  • VDI (Citrix, VMWare, MS Remote Desktop)
  • Remote Desktop configurations.
  • APM

Cause

This issue occurs when the BIG-IP is unable to resolve the hostname of the back end VDI server(s).

Recommended Actions

Verify the DNS configuration on the BIG-IP.

  1. Login to the BIG-IP Admin GUI.
  2. Navigate to System>Config>Device>DNS.
  3. Verify the correct DNS servers are configured.
Test DNS from the BIG-IP BIG-IP CLI.
  1. Login to the CLI.
  2. You can use "nslookup" to test DNS resolution:
 [root@apm-bigip:Active:Standalone] config # nslookup website.f5lab.local
Server:         10.155.205.254
Address:        10.155.205.254#53

Name:   website.f5lab.local
Address: 10.155.205.253

Verify connection and route to DNS server.
  1. Login to the BIG-IP CLI.
  2. Enter the command "ip route get <dns_server_ip_address>"
[root@apm-bigip:Active:Standalone] config # ip route get 192.168.100.90
192.168.100.90 dev mgmt  src 192.168.100.88
    cache
[root@apm-bigip:Active:Standalone] config # ip route get 10.155.205.253
10.155.205.253 dev external  src 10.155.205.194
    cache

Note: In the command output above "mgmt" is the management interface and "external" is a tmm VLAN. Depending on your network and BIG-IP configuration the system DNS can use either management routes or tmm routes.

Run a tcpdump to capture system DNS traffic.
  1. Login to the BIG-IP CLI.
  2. Use the following tcpdump command to capture traffic on the DNS Server IP Address or Port 53. For traffic on the management interface use "eth0" and for traffic on a tmm interface use "0.0":
tcpdump -ni eth0 -s0 host <dns_server_ip> or port 53 -vvv -w /shared/tmp/DNS_Test.pcap

tcpdump -ni 0.0 -s0 host <dns_server_ip> or port 53 -vvv -w /shared/tmp/DNS_Test.pcap
