K000161945: Intermittent TLS1.3 bad_record_mac after handshake –wrong key usage (R-series only)

Description

Java clients experience intermittent TLS1.3 failures when connecting through a BIG-IP LTM virtual server on R-series hardware. The TLS handshake completes successfully, but immediately after, BIG-IP sends Application Data, and the Java client responds with a "bad_record_mac" alert, terminating the connection. The error observed in Java logs is:

javax.net.ssl.SSLException: (bad_record_mac) Tag mismatch at java.base/sun.security.ssl.Alert.createSSLException(Alert.java:132)

Environment

Product: BIG-IP LTM

Platform: F5-BIG-R10900, C128

Client SSL profile: ssl-sign-hash set to "any"

Cause

The issue is related to the use of FFDHE ciphers in combination with the "strength" ordering in the cipher group on R-series hardware. This can result in incorrect key usage during TLS1.3 record encryption, leading to "bad_record_mac" errors on the client side.

Answer/Recommended Actions

  • Change the cipher group ordering from "strength" to "order" for the affected virtual server.
  • Alternatively, exclude FFDHE ciphers from the cipher group to prevent negotiation of these ciphers.
  • Ensure the client SSL profile's "ssl-sign-hash" is set to "any".

Additional Information

  • The issue is specific to TLS1.3 and does not affect TLS1.2.
  • The problem is platform-specific (R-series only) and was not observed on i-series hardware with the same configuration.
  • The backend (serverside) connection is not established when the error occurs.
  • The issue is intermittent and not deterministic per session, but reproducible over time.
