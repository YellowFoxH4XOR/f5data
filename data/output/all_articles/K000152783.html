K000152783: Issue in forwarding Decoded ASM Logs to Qradar

Type
Support Solution
Published
2025-07-28
Updated
2025-07-28
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000152783

Description

When forwarding Application Security Manager (ASM) logs from F5 BIG-IP to a remote SIEM solution such as IBM QRadar, the logs are received in an encoded format. While ASM event logs viewed directly on the F5 device appear decoded (readable), the logs sent to the SIEM contain the original encoded request data. There is no error message, but the log content is not human-readable in the SIEM.

Environment

  • Product: F5 BIG-IP ASM
  • Logging destination: Remote SIEM (e.g., IBM QRadar)
  • Logging profile: Security logging profile configured for remote logging
  • Logging format: Any (e.g., key-value pairs, ArcSight, Splunk, CSV)

Cause

BIG-IP ASM is designed to forward the original (encoded) request data to remote logging servers. The decoded (readable) format is only available in the ASM event logs on the F5 device itself. There is no built-in option or configuration in BIG-IP ASM to automatically send decoded request data to a remote SIEM. The log format and content sent to the SIEM are determined by the logging profile, but the request payload remains encoded.

Recommended Actions

  • If decoded (readable) request data is required in the SIEM, decoding must be performed on the SIEM side or by using a post-processing tool after the logs are received.
  • Review security logging profile settings on BIG-IP ASM to ensure desired log fields and formats are selected; note that this will not affect encoding of request payloads.
  • Consult your SIEM documentation or support for guidance on decoding ASM log payloads after ingestion.
  • There is no standard configuration or workaround on BIG-IP ASM to forward decoded request data directly to a remote SIEM.
