Description

This article explains what happens when your CE (Customer Edge) site is upgraded: the phases the upgrade moves through, what behavior is normal along the way, and when you may need to contact support.

An upgrade can be started by a scheduled software release or triggered by certain configuration changes. Either way, the process follows the same set of phases described below.

Environment

  • F5 XC Customer Edge

How the upgrade is structured

The upgrade runs through five phases. The first one, System Setup, runs in the background. The remaining four — Image Download, Site Components, Node Components, and Validation — run one after another in sequence.

1. System Setup

This phase prepares the underlying operating system and platform on each node — the foundation everything else builds on. It runs asynchronously, meaning it happens in the background alongside the other phases rather than blocking them.

If System Setup runs into a problem, the overall upgrade may pause until it can complete. Note that the Validation phase (below) does not check System Setup

2. Image Download

Before the new components are applied, the site downloads the container images they'll need in advance, so they're ready the moment they're required.

If an image fails to download during this phase, it does not stop the upgrade. The node can still retrieve the image later, when the updated components are applied.

3. Site Components

In this phase, the site applies the updated configuration for all system and monitoring components, switches them to the new version, and waits for each one to come back up and report healthy.

Because some components depend on others, they aren't all updated at once. They're upgraded in ordered stages, with components that can safely update at the same time grouped together.

If node-by-node upgrades are enabled (the default), components that run on every node are prepared during this phase but are not restarted yet. Restarting those is handled in the next phase, Node Components.

4. Node Components

This phase appears only when node-by-node upgrades are enabled, which is the default setting.

Instead of restarting every-node components all at once, the upgrade replaces them one node at a time. It drains only as many worker nodes simultaneously as your configuration allows, and master nodes are always drained one at a time. This approach keeps your site available throughout the upgrade.

If node-by-node upgrades are disabled, this phase will not appear, and those components are handled during the Site Components phase instead.

5. Validation

Finally, the upgrade checks for errors across the Image Download, Site Components, and Node Components phases. (Validation does not cover System Setup.)

It is normal for validation to report errors temporarily and then pass on a later automatic retry, so a transient error here is not necessarily a sign of a problem.

What to expect during an upgrade

A few behaviors are completely normal and worth knowing about:

  • System Setup runs in the background, while Image Download, Site Components, Node Components, and Validation run in sequence.
  • The upgrade retries automatically. If it hits a temporary issue, it will keep retrying on its own so in most cases you don't need to take any action.
  • The Node Components phase only appears when node-by-node upgrades are enabled.
  • The main page won't refresh while the upgrade status panel is open. If you want to see updated overall status, close the panel or navigate away and back.
  • The time of the upgrade may take from 30 to 60 minutes per node.
