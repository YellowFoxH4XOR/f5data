Description

ZRD (ZoneRunner Daemon) may show as "down" and "not configured" on BIG-IP GTM devices after running the gtm_add command. The following error messages may appear in logs:

rsync: link_stat "/var/named/config/named.conf" failed: No such file or directory (2)
rsync error: some files/attrs were not transferred (see previous errors) (code 23) at main.c(1518) [Receiver=3.0.9]
Could not sync /var/named//config/named.conf!
open: /config/named.conf: file not found
loading configuration: file not found
exiting (due to fatal error)

These errors indicate that the required 'named.conf' configuration file is missing, leading to synchronization failures and service crashes.

Environment

  • BIG-IP DNS
  • gtm_add
  • missing or corrupt named.conf

Cause

The issue occurs due to the absence or corruption of the 'named.conf' configuration file on DNS hosts. This prevents proper synchronization during the execution of the 'gtm_add' process, causing ZRD services to fail.

A common cause is running gtm_add (instead of bigip_add) to the self-ip of the same device, since this process involves wiping out the current configuration as stated in the warning message on running the gtm_add script:

"WARNING: Running this script will wipe out the current configuration files (bigip_gtm.conf, named.conf and named zone files) on the BIG-IP GTM"

Recommended Actions

To resolve this issue, follow steps 1 or 2:

1. Restore Configuration from Backup:

  • If a UCS backup was created before running 'gtm_add', restore it on one of the DNS hosts.
  • Verify that the 'named.conf' file is present and ZRD is no longer restarting.
  • Run 'gtm_add <Valid_GTM_IP>' on other DNS hosts to synchronize them with the restored running configuration.

2. Manually Recreate Missing Configuration File:

  • Stop the named service:

bigstart stop named 

  • If no backup is available, manually recreate a default 'named.conf' file.
  • Upload a default 'named.conf' file to '/var/named/config/'.
  • Check if the file is present

  ls -lah /var/named/config/named.conf

    • Change ownership of the uploaded file and restore permissions:

    chown named.named /var/named/config/named.conf

    restorecon -R /var/named/

    • Check the permissions

    ls -lah /var/named/config/named.conf

    • Start the named service again:

       bigstart start named

    • Ensure that both 'named' and ZRD services are running
    • Run 'gtm_add <Valid_GTM_IP>' on other DNS hosts to synchronize them with the restored configuration.
      named.conf will be recreated automatically.

    Additional Information

    Verify Services:
    After restoring or recreating the configuration, ensure that both 'named' and ZRD services are running.

    Preventive Measures:
    Always create a UCS backup before making significant changes like adding GTMs using 'gtm_add'.
