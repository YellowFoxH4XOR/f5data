K000149731: HSB loopback corruption messages do not trigger snmp traps

Type
Support Solution
Published
2025-02-25
Updated
2025-02-25
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 16.1.0, 16.1.3, 16.1.2, 16.1.1, 17.1.X, 16.1.X, 15.1.10, 17.1.2, 17.1.1, 17.1.0, 16.1.5, 16.1.4
Source
https://my.f5.com/manage/s/article/K000149731

Description

  • Starting with software versions 17.1.1, 16.1.4 and 15.1.10, Loopback validation have been introduced on some hardware platforms equipped with HSB.
  • If a validation loopback packet is found to be corrupt, one or more messages like the below is logged in /var/log/tmm:

notice HSB loopback corruption at offset 46. tx: 0x4f, rx: 0x50, len: 2043

  • These log messages do not by default trigger snmp traps.

 

Environment

Hardware platform equipped with HSB 
Software version with the fix for ID1211513

 

Cause

SNMP traps are not by default sent for HSB loopback corruption messages located in /var/log/tmm

Recommended Actions

To trigger snmp traps for  HSB loopback corruption messages located in /var/log/tmm, a custom snmp trap needs to be configured on the unit.  Below is an example custom snmp trap that can be used.

 alert HSB_CORRUPTION ".*0x.*, rx: 0x.*, len: .*" {
 snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.440"
  }

Notes: Make sure the above custom traps is thoroughly tested before used in a production environment.
