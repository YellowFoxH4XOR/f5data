K32905151: High Swap use with LTM and ASM provisioned on 8GB BIG-IP

Type
Support Solution
Published
2021-10-30
Updated
2023-01-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.0.0, 12.1.3, 12.1.2, 12.1.1, 12.1.0, 12.0.0, 11.6.1, 11.6.0, 11.5.4, 11.5.3, 11.5.2, 11.5.1, 11.5.0, 11.4.1, 11.4.0
Source
https://my.f5.com/manage/s/article/K32905151

Description
When a BIG-IP is configured with LTM and ASM on version 13 or above and only has 8GB of RAM, heavy swapping will be seen.

Environment

  • BIG-IP Hardware or VE
  • Version 13 or above
  • 8GB RAM
  • ASM and LTM both provisioned (with or without AVR)

Cause
This is a combination of increased swap usage by the Linux kernel after version 13 and increased system demands when running ASM.  It is not a problem unless Out of Memory errors are seen or traffic processing is impacted.

Recommended Actions

  • Unless problems are seen, no action is required.
  • Consider deprovisioning LTM.  This will take some of the RAM reserved for tmm and make that memory available to other processes on the unit.
  • If viable (VE), increasing system RAM should help alleviate this.
Note: Deprovisioning LTM does not turn off licensed LTM functionality.
Note: Changing the provision.extramb db variable (a frequent recommendation for similar provisioning issues) will, while making more RAM available to non-tmm processes, actually reduce ASM's maximum UMU memory.
