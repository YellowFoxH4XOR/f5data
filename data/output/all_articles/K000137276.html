K000137276: Can't get monitor stats in non-Common partition via REST API

Type
Support Solution
Published
2023-10-18
Updated
2025-02-07
Status
Legacy Content
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000137276

Description

You can't get stats information of a monitor via REST API when the monitor is in a non-Common partition.


# curl -sku <username>:<password> https://<BIG-IP>/mgmt/tm/ltm/monitor/http/~myPartition~myHttpMonitor/stats | jq .

{

 "code": 404,

 "message": "Object not found - /myPartition/myHttpMonitor",

 "errorStack": [],

 "apiError": 1

}


You don't have a problem getting the configuration of the monitor.


# curl -sku <username>:<password> https://<BIG-IP>/mgmt/tm/ltm/monitor/http/~myPartition~myHttpMonitor | jq .

{

 "kind": "tm:ltm:monitor:http:httpstate",

 "name": "myHttpMonitor",

 "partition": "myPartition",

 "fullPath": "/myPartition/myHttpMonitor",

<snip>


Environment

  • BIG-IP
  • iControl REST


Cause

This is a limitation of the BIG-IP so far. You also have the same limitation with tmsh.


[root@bigip:Active:Standalone] config # tmsh list ltm monitor http /myPartition/myHttpMonitor 

ltm monitor http /myPartition/myHttpMonitor {

  adaptive disabled

  defaults-from http

  interval 5

  ip-dscp 0

  partition myPartition

  recv none

  recv-disable none

  send "GET /\r\n"

  time-until-up 0

  timeout 16

}

[root@bigip:Active:Standalone] config # tmsh show ltm monitor http /myPartition/myHttpMonitor 

[root@bigip:Active:Standalone] config # !!! <--- You don't get the output here.


F5 tracks the issue as ID 712925.
