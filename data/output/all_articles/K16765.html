Known Issue

Description

When creating Security Assertion Markup Language (SAML) objects by using a metadata file, the BIG-IP APM system may select the wrong certificate for signing.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as SAML service provider (SP) or SAML Identity Provider (IdP).
  • The external IdP connector or external SP connector was created on the BIG-IP APM system from an imported metadata file.
  • The imported metadata file contains multiple certificates.

Impact

The BIG-IP APM system uses the wrong certificate for signing and causes authentication to fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system selects the last certificate in the metadata file, instead of selecting the certificate with the signing attribute set.
  • The external SAML IdP system is unable to authenticate users for the SAML SP service.
  • The external SAML SP system is unable to process signed SAML assertions.
  • You notice messages in the /var/log/apm file that appear similar to the following example:

    failed to process signed assertion
