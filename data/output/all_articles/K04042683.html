Description

iRule datagroup maching is case-sensitive
 

Environment

  • iRule created and doing a datagroup lookup
  • "string tolower" is used in the iRule parsing
 

Cause

Some datagroup entries may not match, as the listed items are case-sensitive.

For example, in the following iRule we are checking the value of the User-Agent HTTP header, converting that to lowercase with the "string tolower" manipulation, then sending matching browsers to a specific virtual server and logging the event:

when HTTP_REQUEST {
    log local0. "Request: [HTTP::header "User-Agent"]"
    if { [ class match [ string tolower [HTTP::header User-Agent]] contains testUserAgent ]  } {
         virtual xyz.vip 192.168.10.10 80
         log local0. "Sent to XYZ virtual server"
    }
}

Your datagroup would then be populated with user-agent values you need to check. For example:

  curl/7.47.1 { }
  Mozilla/5.0 { }

If your client device sends over the value "Curl/7.47.1" we will successfully match since the datagroup value matches the lowercase. However, if the client sends "Mozilla/5.0", we will no longer match, since the iRule code is converting that to lowercase and the datagroup entry has uppercase characters.
 

Recommended Actions

There are a couple of options to fix the datagroup lookups:

  1. Convert the datagroup entries to all lowercase.
  2. Change the iRule code to not use the "string tolower" conversion. For example:
      when HTTP_REQUEST {
    log local0. "Request: [HTTP::header "User-Agent"]"
    if { [ class match [HTTP::header User-Agent] contains testUserAgent ]  } {
         virtual xyz.vip 192.168.10.10 80
         log local0. "Sent to XYZ virtual server"
    }
}
