Known Issue

This is the result of a known issue. After you reboot a VIPRION blade, the clusterd process may request multiple time synchronization reboots on VIPRION systems. When this issue occurs, you may experience a significant delay before the blade can rejoin the cluster. In addition, when the reboot cycle completes, the VIPRION system logs multiple message sequences that appear similar to the following example to the /var/log/ltm file:

warning clusterd[3836]: 013a0005:4: Clusterd: rebooting system for time synchronization
notice overdog[3690]: 01140029:5: HA cluster_time_sync clusterd fails action is reboot.
emerg overdog[3690]: 01140043:0: Ha feature cluster_time_sync reboot requested.
crit overdog[3690]: 01140102:2: Overdog daemon requests reboot.

Note: F5 expects a single reboot for time synchronization behavior. For information about the VIPRION system requesting one additional reboot for time synchronization, refer to K12721: Error Message: clusterd: rebooting system for time synchronization.

F5 Product Development tracked this issue as ID 241688 (formerly CR131363) and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.
