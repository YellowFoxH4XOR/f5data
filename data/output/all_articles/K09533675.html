Environment

  • VIPRION
  • Upgrade to version 16.1.2.2

Cause
Bug ID 1083977: MCPD crashes when changing HTTPD configuration, all secondary blades of clustered system remain offline

For the issue described in this article, the following change to the HTTPD configuration caused the issue: 
sys httpd {
    auth-pam-dashboard-timeout on
    redirect-http-to-https enabled   <---!!!
    ssl-protocol "ALL -TLSv1 -TLSv1.1 -SSLv2 -SSLv3"
}

You can view this output by viewing the /config/bigip_base.conf file or entering the following command on the bash shell:

tmsh list sys httpd

Recommended Actions

To work around the issue, you may follow the following procedures:
  1. Log in to the CLI of the primary blade
  2. Verify if the affected HTTP configuration is made either by viewing the /config/bigip_base.conf file or entering the tmsh list sys httpd command:

    Do not proceed further if this is not configured. This article applies only when this is configured.

    redirect-http-to-https enabled

  3. Make a backup of the /config/bigip.conf file by typing the following command: 

    # cp /config/bigip_base.conf /config/bigip_base.conf_backup

  4. Edit /config/bigip_base.conf  using text editor, such as pico or vi.
  5. Remove the following line:

    redirect-http-to-https enabled

  6. Save the file, If using vi, select ESC and enter the following command:

    :wq!

  7. Load the config   

    tmsh load sys config

  8. SSH to secondary slot straight away, reboot it

    reboot

  9. Wait for both slots to come back up.
  10. Move the VCMP to Configured and back to Deployed to give it another proper reboot
  11. Ensure all VCMP host-to-guest services work.
