Known Issue

The Traffic Management Microkernel (tmm) process may restart without a stack trace or core file after becoming disconnected from the Master Control Program Daemon (mcpd) process.

This issue occurs when all of the following conditions are met:

  • The Linux kernel memory becomes fragmented.
  • Another memory-intensive operation occurs, which may include:
    • You perform a configuration synchronization (ConfigSync) with full reload.
    • You run a tcpdump session.

If tmm fails to start or restart properly as a result of this issue, you can try to recover the system temporarily by restarting the BIG-IP system.

Note: Restarting the system is not a permanent workaround. It is a way to temporarily recover the system until you can upgrade to a software version that contains a fix for this issue in which the internal driver is improved, which allows the system to work in low or fragmented-memory conditions.

Impact

The BIG-IP system may experience degraded performance or unexpected failover leading to interruptions in traffic processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system experiences gradually degraded performance.
  • The tmm process restarts.
  • The BIG-IP system stops responding and fails over to a standby system or another system in the device group.
  • The interface between TMM and the Linux host may stall, causing TMM and MCPD to become disconnected from each other.
  • In the /var/log/ltm file, you notice an error message similar to the following example:

    01070406:5: Removed publication with publisher id TMM1

  • In the /var/log/ltm file, you notice a message similar to the following example. The timestamp of the message may be seconds or minutes after the original event:

    01010020:2: MCP Connection aborted, exiting' after a delay of seconds to minutes or more with a timestamp at time of event.

  • If you encounter the issue during the TMM early startup process, or if TMM is unable to restart properly after encountering this issue because the issue has not cleared, you may observe that, instead of restarting, TMM continuously logs an error message similar to the the following example in the /var/log/ltm file:

    notice MCP connection expired early in startup; retrying

    In this case, it may be necessary to restart TMM to complete the restart process.
