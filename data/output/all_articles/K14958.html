Known Issue

Clients may be unable to log in and access resources when the BIG-IP APM access profile is configured for Multi-domain Single Sign-On (SSO).

This issue occurs when all of the following conditions are met:

  • The client attempts to log back in after logging out of a previously established session.
  • The Authentication Domain Configuration section of the access profile is configured with Host in the Cookie drop-down menu.

The BIG-IP APM system uses HTTP cookies to track successfully established user sessions. When a client logs out of an established session, the BIG-IP APM system instructs the browser to delete the session cookies. When the BIG-IP APM system is configured with multi-domain SSO, some of the session cookies may not be marked for deletion causing subsequent login attempts to fail.

Impact

Clients are unable to log in and access resources through the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Login attempts using valid credentials fail and the client is redirected to the logout page.
  • Clients may view error messages in the web browser that appear similar to the following example:

Invalid Session ID. Your session may have expired.

Workaround

To work around this issue, you can delete all session cookies in the web browser before attempting to log in again. You may also be able to work around this issue by using Domain instead of Host in the Authentication Domain Configuration section of the access profile. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Access Profile List.
  3. Click the name of the access profile with the multi-domain SSO configuration.
  4. Click the SSO/Auth Domains tab.
  5. In the Authentication Domain Configuration area, configure the cookie by selecting Domain and typing the fully qualified domain name.
  6. Click Update.
  7. To apply the changes to the policy, click Apply Access Policy.
