Known Issue

Description

A reboot loop occurs when the 10000 series platform boots from an 11.5.x partition to a partition with either 11.3.x or 11.4.x software installed.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP platform that belongs to the 10000 series.
  • You have multiple boot partitions with either 11.3.x or 11.4.x installed.
  • You install 11.5.0 to a new partition and boot the BIG-IP system to that partition.
  • You boot the BIG-IP system back to a partition with 11.3.x or 11.4.x installed.

Impact

  • The system is unable to process traffic while the reboot loop occurs.
  • Loss of redundancy occurs if you have configured a redundant pair.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system continuously reboots.
  • A message appears in the /var/log/ltm file that appears similar to the following example:

    HSBE2 - main Version 1.8.12.2 is in quarantine. (Remove /shared/fwmgr/hsbe2_quarantine to retry HSB bitstream update)
  • Prior to rebooting, the BIG-IP system logs the following message to the /var/log/ltm file:

    notice overdog[7518]: 01140029:5: HA nic_failsafe tmm fails action is reboot.
    emerg overdog[7518]: 01140043:0: Ha feature nic_failsafe reboot requested.

Workaround

To work around this issue, you can delete the hsbe2_quarantine file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will require you to reboot the system.

  1. Boot the BIG-IP system back into the partition with 11.5.0 installed.

    If you are unfamiliar with changing boot partitions, refer to K5658: Overview of the switchboot utility.
  2. Log in to the command line as a user with BASH terminal access.
  3. Remove the hsbe2_quarantine file using the following command syntax:

    rm /shared/fwmgr/hsbe2_quarantine
  4. Boot the BIG-IP system back into the partition with either 11.4.x or 11.3.x installed.
