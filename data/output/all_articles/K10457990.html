K10457990: Dynamic RDP: domain suffix not added automatically

Type
Support Solution
Published
2021-10-19
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP Platforms
  • BIG-IP
  • Virtual Editions
  • BIG-IP APM: 14.1.4
Source
https://my.f5.com/manage/s/article/K10457990

Description

User defined RDP resource doesn't resolve hostnames. FQDN entry works fine.

  • In var/log/apm: Failed to connect to RDG target <hostname>:3389: system:111: Connection refused

Environment

  • BIG-IP APM
  • Native RDP
  • Resource with user defined destination

Cause

When user enters short hostname in user defined native RDP resource the connection is refused. When he use FQDN name, the connection is successful.
BIG-IP APM doesn't add the DNS suffix for the entered short hostname.

Recommended Actions

1. Check the DNS setting on your BIG-IP:
# tmsh list sys dns
sys dns {
    name-servers { 10.1.0.1 10.1.0.2 }
    search { domain.name localhost }
}
2. If you can see the localhost entry on the first place in the DNS order, please rearrange it via Configuration utility or CLI

Using the Configuration utility to configure DNS order
  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Device > DNS.
  3. In the section DNS Search Domain List select localhost entry.
  4. Using Down button, move the localhost to the last place or use Delete to remove localhost entry if not needed.
  5. Select Update.
Using the tmsh to configure DNS order
  1. Log in to tmsh by entering the following command:
    tmsh
  2. To remove the localhost name server from your /etc/resolv.conf file, use the following command:
    modify sys dns { search delete { localhost }}
    To replace existing order with the new one, with localhost on last place, please use:
    modify sys dns { search replace-all-with { domain.name localhost }}
  3. To save the configuration, enter the following command:
    save /sys config
  4. To exit tmsh, enter the following command:
    quit
3. Once localhost entry is not in the first place, the connection to RDG target entered as a short hostname is successful.

Additional Information

DNS Search Domain List specifies the domains that the system searches for local domain lookups, to resolve local host names.
