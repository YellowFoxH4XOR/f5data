Description

Overview of the Best Practices of rebooting BIG-IP devices in a High Availability Pair (HA Pair)

  • You want to know the best method or order of operations for rebooting your BIG-IP devices
Environment
  • BIG-IP
  • HA Pair

Cause

As Designed

Recommended Actions

The following steps will outline the best method for rebooting your HA devices with minimal impact to your production traffic

Important: If any of the following steps are not successful stop the procedure and address the issue(s)

Note: While some of these steps may seem unneeded they're purpose is to assist in recovery if any unforeseen circumstances arise

  1. Perform a ConfigSync
    K13920: Performing a ConfigSync using the Configuration utility
     
  2. Save the configuration using the command line on both devices

    tmsh save /sys config partitions all
     
  3. Verify that the currently saved configuration can successfully load

    tmsh load /sys config verify

    K53233552: How to verify if BIG-IP configuration contains error
    Note: When running this command you may see warnings and errors. Errors will prevent the configuration from loading when the device is rebooted. If errors are seen please address before continuing

  4. Create and download UCS archives for both devices
    K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

    Note: Some BIG-IP configuration objects and databases are not contained in a UCS archive. For more information related to this and how to modify what is contained please see
    K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive
     
  5. Generate and copy masterkey

    f5mku -K

    K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later)
     
  6.  Verify failover functionality by performing a manual Failover of the BIG-IP HA Pair
    K42061352: How to perform a Manual Failover of a BIG-IP High Availability Traffic Group from the Webui
     
  7.  Verify that application traffic is flowing as expected in your environment
     
  8. Force standby device into forced offline mode
    K15122: Overview of the Force Offline option for devices and traffic groups
     
  9.  Reboot forced offline device
    K7369: Shut down and restart the BIG-IP system
    Note: You can also reboot the devices by using the Configuration Utility: System > Device > Configuration > General
     
  10. Verify that forced offline device is up and accessible
    Note: As an example the configuration has loaded, and your virtual servers are all listed in the Configuration Utility
    Be aware of the following as stated in K15122:
        When the BIG-IP system starts with Force Offline enabled, monitored nodes and pool members are initially marked Unchecked, then remain Unchecked until Force Offline is released.
        While the BIG-IP system has Force Offline enabled, newly created nodes and pool members are initially marked Unchecked, then remain Unchecked until Force Offline is released.
        Monitored nodes and pools that are green (Available) when enabling Forced Offline remain Available while Force Offline is enabled.
     
  11. Release forced offline device from forced offline mode so that it becomes standby
    K15122: Overview of the Force Offline option for devices and traffic groups
     
  12. Perform a Manual Failover
    K42061352: How to perform a Manual Failover of a BIG-IP High Availability Traffic Group from the Webui
     
  13. Verify that application traffic is flowing as expected in your environment on the newly rebooted and now active device
     
  14. Repeat steps 8 through 13 for the peer device, which is now the standby device
When the procedure is completed and all of the steps have been accomplished you should now have two devices that have successfully been rebooted in an HA pair
