Topic

You should consider using this procedure under the following condition:

  • You want to increase the disk space for a BIG-IP Virtual Clustered Multiprocessing (vCMP) guest that may not have sufficient disk space for one or more of the following tasks:
    • Upgrading software or installing hotfixes
    • Provisioning multiple modules
    • Preparing for increased logging that requires additional disk space

Note: In most cases you will find /var to be about 4.5G. In AFM this could be do to a large firewall policy that in the latest versions (17.1.0, 16.1.4, 15.1.9) could reach until 8G. For ASM that may not be sufficient. K000157081: Adv WAF and ASM Upgrade Best Practices

Description

If you are running BIG-IP vCMP and the vCMP guest instance does not have sufficient disk space for upgrading software or provisioning multiple modules, you may need to increase the disk space  allocated to the vCMP guest. When the vCMP host is running BIG-IP 12.1.0 or later, the system allocates 150 GB for newly created virtual disk images, which is suitable for most deployments. However, if you want to increase the disk space for a BIG-IP vCMP guest, you can do so by performing the procedures in this article:

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP host system is running BIG-IP 11.x or later.
  • You have sufficient access rights to the vCMP guest and rights to modify the vCMP guest settings on the BIG-IP host system.
  • You have created a backup UCS archive file of your vCMP guest.

Procedures

Creating a UCS archive file for the vCMP guest system

Important: Before you can increase the disk space for the vCMP guest, you must create a user configuration set (UCS) archive file for the guest system. The UCS archive contains all of the files that are required to restore your current configuration.

To create a UCS archive on the vCMP guest system, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. In a secure place, record the master key, which you can view by running the following command.  The master key is required when re-loading the UCS.

    f5mku -K

    Note: For more information about the master key, refer to K9420: Installing UCS files containing encrypted passwords or passphrases.

  2. Log in to the TMOS Shell (tmsh) of the vCMP guest by entering the following command:

    tmsh

  3. To create the UCS archive file, use the following command syntax:

    save /sys ucs <path/to/UCS>

    Replace <path/to/UCS> with the full path to the UCS archive file, similar to the following example:

    save /sys ucs /var/tmp/vCMPguest.ucs

  4. Copy the UCS file to another system. For information about copying the UCS archive file to another system, refer to K175: Transferring files to or from an F5 system.

    Note: For more information about creating and restoring UCS archive files, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).

Increasing the disk space for a BIG-IP vCMP guest

There are two methods to increase the disk space for a BIG-IP vCMP guest; modifying the vcmp.vdisk.new_image_size database variable or using the qemu-img utility. If you modify the vcmp.vdisk.new_image_size database variable to a desired size, all existing vCMP guests would have their virtual disk image increased to the value of the database variable after subsequent redeployment. This behavior also affects all subsequent new vCMP guests created. Note that this database variable exists in BIG-IP 12.1.0 and later. If you prefer to modify the disk space of a specific vCMP guest, you can use the qemu-img utility. Depending on your requirements, perform either of the following procedures:

  • Increasing the disk space for a vCMP guest by deleting and re-creating the guest with a larger disk size using the vcmp.vdisk.new_image_size database variable (BIG-IP 12.1.0 and later)
  • Increasing the disk space for a vCMP guest for vCMP hosts by resizing the disk image file using the qemu-img utility

Increasing the disk space for a vCMP guest by deleting and re-creating the guest with a larger disk size using the vcmp.vdisk.new_image_size database variable (BIG-IP 12.1.0 and later)

To increase the disk space for a BIG-IP vCMP guest, you must log in to the BIG-IP vCMP host system. To increase the disk space for a BIG-IP vCMP guest on which the vCMP host is running BIG-IP 12.1.0 and later, perform the following steps:

Impact of procedure: You are required to shut down the BIG-IP vCMP guest system during the disk-provisioning steps, and the system is not available for traffic processing during that time. You should perform this procedure during a maintenance window.

  1. Log in to tmsh of the vCMP host by entering the following command:

    tmsh

  2. To shut down the vCMP guest by moving the guest to the configured state, use the following command syntax:

    modify vcmp guest <guest_name> state configured

    For example, the following command moves the vCMP guest named MyGuest to the configured state:

    modify vcmp guest MyGuest state configured

  3. For appliance based (non-Viprion) platforms: After you shut down the vCMP guest, delete the guest's virtual disk using the following command syntax:

    delete vcmp virtual-disk <virtual_disk_name>

    For example, the following command deletes the virtual disk for the vCMP guest named MyGuest:

    delete vcmp virtual-disk MyGuest.img

  4. For VIPRION platforms: After you shut down the vCMP guest, delete the guest's virtual disk using the following command syntax:

    delete vcmp virtual-disk <virtual_disk_name>/<slot_number>

    For example, the following command deletes the virtual disk for the vCMP guest named MyGuest on both slots 1 and 2:

    delete vcmp virtual-disk MyGuest.img/1 MyGuest.img/2

  5. To set the vcmp.vdisk.new_image_size database variable to the desired size of the new virtual disk image, use the following command syntax:

    modify sys db vcmp.vdisk.new_image_size value <size>

    For example, the following command sets the new virtual disk image size to 200 GB:

    modify sys db vcmp.vdisk.new_image_size value 200

    Note: Due to a known issue, you may have to disable the vdisk templates database variable (vcmp.installer.use_vdisk_templates) if your BIG-IP version is affected. For more information, refer to Bug ID 595313.

  6. To start up the vCMP guest by moving the guest to the deployed state, use the following command syntax:

    modify vcmp guest <guest_name> state deployed

    For example, the following command moves the vCMP guest named MyGuest to the deployed state:

    modify vcmp guest MyGuest state deployed

  7. If you want to increase the size of another vCMP guest, you should repeat steps 2, 3, or 4 (depending on your BIG-IP platform), and then step 6.

Increasing the disk space for a vCMP guest for vCMP hosts by resizing the disk image file using the qemu-img utility

To increase the disk space for a BIG-IP vCMP guest, you must log in to the BIG-IP vCMP host system. To increase the disk space for a BIG-IP vCMP perform the following steps:

Impact of procedure: You are required to shut down the BIG-IP vCMP guest system during the disk-provisioning steps, and the system is not available for traffic processing during that time. You should perform this procedure during a maintenance window.

  1. Log in to the BIG-IP command line of the vCMP host.
  2. To shut down the vCMP guest by moving the guest to the configured state, use the following command syntax:

    tmsh modify vcmp guest <guest_name> state configured

    For example, the following command moves the vCMP guest named MyGuest to the configured state:

    tmsh modify vcmp guest MyGuest state configured

  3. After you shut down the guest, extend the size of the virtual disk image by using the following command syntax on each slot that the guest spans:

    qemu-img resize <virtual_disk_image_file> +<size>G

    For example, the following command increases the given virtual disk image by 50 GB on that slot:

    qemu-img resize /shared/vmdisks/my_guest.img +50G

  4. To start up the vCMP guest by moving the guest to the deployed state, use the following command syntax:

    tmsh modify vcmp guest <guest_name> state deployed

    For example, the following command moves the vCMP guest named MyGuest to the deployed state:

    tmsh modify vcmp guest MyGuest state deployed

    Note: If the vCMP guest fails to boot after moving it to the deployed state, move the guest to the configured state, wait for it to completely shut down, and then move the guest back to the deployed state. If you are running a version of BIG-IP affected by Bug ID 744730 you may need to manually restart the guest again before the extra disk space is recognized.

  5. If you want to increase the size of another vCMP guest, you should repeat steps 2 through 4.

Restoring the UCS archive on the vCMP guest

After the vCMP guest is running, you can restore the UCS archive to the guest. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Copy the UCS archive file you created in the Increasing the disk space for a BIG-IP vCMP guest procedure to the restored vCMP guest.
  2. Restore the master key by entering the following command syntax:

    f5mku -r <master_key>

  3. Log in to tmsh of the vCMP guest by entering the following command:

    tmsh

  4. To restore the UCS archive, use the following command syntax:

    load /sys ucs <path/to/UCS>

    Replace <path/to/UCS> with the full path to the UCS archive file, similar to the following example:

    load /sys ucs /var/tmp/vCMPguest.ucs
