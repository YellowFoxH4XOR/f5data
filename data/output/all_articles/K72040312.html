Known Issue

The BIG-IP system may experience Traffic Management Microkernel (TMM) memory leaks on standby systems.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a OneConnect profile.
  • The BIG-IP system is in a high availability (HA) configuration with a standby system.
  • Mirroring is enabled.
  • The BIG-IP platform supports Clustered Microprocessing (CMP).

Impact

The standby BIG-IP system may be unable to process traffic in the event of an HA failover. 

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Standby BIG-IP systems experience high memory usage.
  • The affected BIG-IP systems may restart due to memory exhaustion.

Workaround

To work around this issue, you can remove the OneConnect profile from the virtual server.  To do so, perform the following procedure:

Impact of workaround:  Efficiency and performance benefits derived from use of the OneConnect feature are lost.

Removing a OneConnect profile from a virtual server using the BIG-IP configuration utility

  1. Log into the BIG-IP Configuration utility as an administrative user.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the virtual server from which you want to remove the OneConnect profile.
  4. Under Acceleration, for OneConnect Profile, click None.
  5. Click Update.

Removing a OneConnect profile from a virtual server using tmsh

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Remove the OneConnect profile from a virtual server by using the following command syntax:

    modify ltm virtual <Virtual Server> profiles delete { <Profile> }

    Note: Replace <Virtual Server> with the name of the virtual server you want to modify and <Profile> with the name of the OneConnect profile you want to delete

    For example:

    modify ltm virtual vs1 profiles delete { test-oneconnect }
