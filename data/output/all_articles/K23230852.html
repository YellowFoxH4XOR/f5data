Known Issue

Virtual Clustered Multiprocessing (vCMP) guests may experience an active-active traffic group when the mysqld and bcm56xxd processes run at high CPU on the vCMP host.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has the vCMP module provisioned.
  • The vCMP host is running one of the following software versions:
    • 12.1.0
    • 12.1.1
    • 12.1.2
  • You have deployed multiple vCMP guests in a high availability (HA) configuration.

Impact

An active-active traffic group may cause traffic processed by vCMP guests to fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The mysqld or bcm56xxd process runs at or near 100 percent CPU for an extended period on the vCMP host.

    Note: An average run time of five seconds is considered an extended period.

  • Connections being processed by vCMP guests are randomly failing.
  • In the /var/log/ltm file, the system logs error messages on both vCMP guests at the same time that appear similar to the following example:

    notice sod[5678]: 010c007e:5: Not receiving status updates from peer device /Common/example.com (192.168.10.100) (Disconnected).
    notice sod[5678]: 010c006d:5: Leaving Standby for Active: Next Active, peers agree on config.
    notice sod[5678]: 010c0053:5: Active for traffic group /Common/traffic-group-1.
    notice sod[5678]: 010c0019:5: Active

Workaround

To work around this issue, stop the monpd process on the vCMP host. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure halts statistics collection on the vCMP host, but does not have a negative impact on the vCMP systems.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To stop the monpd process, type the following command:

    stop sys service monpd

  3. To ensure that the monpd process does not start following a system reboot, type the following command:

    modify sys service monpd remove

  4. To save the configuration, type the following command:

    save sys config
