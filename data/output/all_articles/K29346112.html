Issue

Error Message

01260009:4: Connection error: <ssl_function>:<function_id>: <error_reason> (<reason_code>)

In this error message, note the following:

  • <ssl_function> is the SSL function in use at the time of the error.
  • <function_id> is the internal numeric identifier for the SSL function.
  • <error_reason> is the reason for the SSL error message.
  • <reason_code> is the numeric identifier for the SSL error reason.

For example:

  • 01260009:4: Connection error: ssl_hs_rxhello:3840: insecure renegotiation disallowed (40)
  • 01260009:4: Connection error: ssl_hs_rxhello:7110: unsupported version (70)
  • 01260009:4: Connection error: ssl_hs_rxhello:7363: name not available (112)
  • 01260009:4: Connection error: ssl_hs_rsaprivenc:8428: no shared hash algorithm (40)
  • 01260009:4: Connection error: ssl_hs_session:7863: cipher selected does not match original session's cipher (47)
  • 01260009:4: Connection error: ssl_hs_dos_report:7124: renegotiation rate (80)
  • 01260009:4: Connection error: ssl_select_suite:6786: TLS_FALLBACK_SCSV with a lower protocol (86)
  • 01260009:4: Connection error: ssl_select_suite:7152: no shared ciphers (40)
  • 01260009:4: Connection error: ssl_passthru:4021: not SSL (40)
  • 01260009:4: Connection error: ssl_process_extensions:5476: unrecognized name: www.domain.com. (112)
  • 01260009:4: Connection error: ssl_cn_decrypt_fin_cb:2034: fin decryption failed (20)
  • 01260009:4: Connection error: hud_ssl_handler:<1129>: invalid profile (20)
  • 01260009:4: Connection error: ssl_codec_rx:1956: received alert (48)
  • 01260009:4: Connection error: ssl_shim_vfycerterr:4530: certificate not trusted (48)
  • 01260009:4: Connection error: ssl_shim_vfycerterr:4789: application verification failure (46)
  • 01260009:4: Connection error: ssl_shim_vfycerterr:4789: out of memory (80)
  • 01260009:4: Connection error: ssl_hs_rx_srvhello:5830: Handshake with unpatched server disallowed (40)
  • 01260009:4: Connection error: ssl_shim_vfycerterr:4059: unable to get local issuer certificate (48)
  • 01260009:4: Connection error: ssl_codec_rx:2289: received alert (90)

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

These error messages occur because a remote SSL client fails to establish a connection with a server during the SSL handshake process. 

The most common cause of this issue is a client sending non-SSL traffic to an SSL virtual server.

However, these messages may also occur when any of the following conditions are met:

  • A remote client or server attempts to use SSL protocols or ciphers not supported by the client SSL profile or BIG-IP system.
  • A remote client or server attempts a renegotiation that is not secure.
  • A remote client attempts to renegotiate at a rate faster than the maximum renegotiations per minute setting in the Client SSL profile.
  • A remote client attempts to initiate an SSL handshake while a prior SSL handshake is in progress.
  • A remote client attempts to initiate an SSL handshake with an invalid SSL client hello.
  • A remote client attempts to use lower protocol and fallback is not allowed.
  • SSL connection mirroring fails
  • The BIG-IP system receives an SSL alert.
  • A client SSL profile sets client certificate required, and the client provides an untrusted client certificate.
  • A client SSL profile sets client certificate required, and the client sends corrupted client certificated.
  • The BIG-IP system is unable to determine the certificate issuer.

The "unsupported version" error message may be the result of a client attempting to connect with an unsupported signature algorithm version during the handshake process.

Impact

Remote clients or servers are unable to establish an SSL connection.

Recommended Actions

Ensure clients are not sending non-SSL traffic to an SSL virtual server.

If the client is sending SSL traffic and you are still getting the error, refer to K15292: Troubleshooting SSL/TLS handshake failures to troubleshoot SSL handshake issues.
