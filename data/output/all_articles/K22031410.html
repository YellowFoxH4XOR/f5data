Known Issue

An IPsec Traffic Selector configuration may fail to load and cause an INOPERATIVE system status.

This issue occurs when all of the following conditions are met:

  • You have a configuration that contains an IPsec Traffic Selector that uses the default IPsec policy (default-ipsec-policy).
  • You attempt to load the configuration in a manner that causes the system to load it from the config files, as follows:
    • You perform an upgrade to an affected version and roll forward an affected configuration.
    • You activate a different boot location and use the Install Configuration option to install the affected configuration.
    • You load an affected configuration from an SCF file using the tmsh load sys config file command.
    • You force the mcpd process to load the configuration from files, as described in K13030: Forcing the mcpd process to reload the BIG-IP configuration.

Impact

The configuration fails to load, and the BIG-IP system status becomes INOPERATIVE and fails to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The configuration fails to load, and the system displays error messages similar to the following examples:

    err mcpd[#]: 01070734:3: Configuration error: IPsec policy /Common/default-ipsec-policy does not exist.

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base " - failed. -- 01070734:3: Configuration error: IPsec policy /Common/default-ipsec-policy does not exist. Unexpected Error: Loading configuration process failed.

  • The BIG-IP system command line status is INOPERATIVE and the Configuration utility device status is Offline.

Workaround

To prevent this issue, before you save your configuration or upgrade and roll forward a configuration, you can create a custom IPsec policy that uses the same default values as the default-ipsec-policy, and then reconfigure any Traffic Selectors that use the default-ipsec-policy to use the new custom IPsec policy.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

To recover from an INOPERATIVE system that failed a configuration load, you can manually edit the /config/bigip_base.conf file to add a new custom IPsec policy with default values, and configure the existing Traffic Selector configuration to use the new custom IPsec policy. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure requires a reboot of the BIG-IP system. However, because the BIG-IP system failed to load the configuration, the system will already be in an INOPERATIVE mode at this stage. Performing this procedure should not have any further impact on your BIG-IP system.

  1. Log in to the BIG-IP command line.
  2. Back up the /config/bigip_base.conf file by typing the following command:

    cp /config/bigip_base.conf /config/bigip_base.conf.k22031410

  3. Open the /config/bigip_base.conf file in a text editor.
  4. Locate the stanza defining the existing Traffic Selector. The stanza appears similar to the following example:

    net ipsec traffic-selector /Common/my-traffic-selector {
        destination-address 1.1.1.1/32
        ipsec-policy /Common/default-ipsec-policy
        order 1
        source-address 1.1.1.2/32
    }

  5. Directly above the existing Traffic Selector stanza, add a custom IPsec policy with default values by using the following syntax:

    Note: If the configuration contains multiple Traffic Selectors, you should insert the custom IPsec policy directly above the first Traffic Selector entry.

    net ipsec ipsec-policy /Common/<Policy_Name> { }

    For example, to add a custom IPsec policy named my-ipsec-policy, enter the following line directly above the existing Traffic Selector stanza:

    net ipsec ipsec-policy /Common/my-ipsec-policy { }

  6. Modify the Traffic Selector to use the new custom IPsec policy. To do so, change the ipsec-policy entry from /Common/default-ipsec-policy to be the name of the new custom IPsec policy.

    Note: If the configuration contains multiple Traffic Selectors that use the default-ipsec-policy, you must modify each affected Traffic Selector to use the new custom IPsec policy.

    For example, if you added a new customer policy named my-ipsec-policy, the new and modified entries will now appear similar to the following example:

    net ipsec ipsec-policy /Common/my-ipsec-policy { }
    net ipsec traffic-selector /Common/my-traffic-selector {
        destination-address 1.1.1.1/32
        ipsec-policy /Common/my-ipsec-policy
        order 1
        source-address 1.1.1.2/32
    }

  7. Save the /config/bigip_base.conf file.
  8. Create a null file with the file name forceload in the /service/mcpd directory by typing the following command:

    touch /service/mcpd/forceload

  9. Reboot the BIG-IP system by typing the following command:

    reboot
