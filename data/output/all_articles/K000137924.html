Description

The Apache Struts project recently released updates for the popular open-source web application framework, with fixes for a critical vulnerability that could lead to remote code execution (CVE-2023-50164). This article covers some recommendation on how to mitigate this issue and protect applications from this vulnerability issue using BIG-IP ASM / Advanced WAF.

Environment

  • BIG-IP ASM Module provisioned
  • ASM/Advanced WAF Security Policy configured and applied to Virtual Server handling file uploads

Cause

You are looking to mitigate CVE-2023-50164 through the BIG-IP ASM / Advanced WAF

Recommended Actions

CVE-2023-51064 vulnerability issue is related to case-sensitive parameters and it talks about a parameter that can be over-written due to case-sensitive handling that should be insensitive handling.

Ensure that Signature ID 200007016: Directory Traversal attempt "../" (Parameter) is enabled and part of your security policy in order to mitigate this issue. In general, Path Traversal signatures will help provide signature coverage against CVE-2023-50164. This can be achieved through either one of the following two approaches:

1. Assign the built-in Path Traversal Signatures set to the security policy.
2. A user-defined signature set can be created within Security  ››  Options : Application Security : Attack Signatures : Attack Signature Sets section within the Configuration Utility with Type: Filter-based and Attack Type: Path Traversal and assign this user-defined set to your policy.

Another option that can be used to mitigate this issue is to utilize a case-insensitive policy and disallow repeated parameter. The latter can be done by through the following two approaches:
1. Disabling the Allow Repeated Occurrences setting for the parameters within the security policy.
2. Enabling block setting for Illegal repeated parameter name violation (introduced in 16.1.x and above releases)

Note: It is not possible to change case sensitivity/insensitivity setting of security policy after it has been created, so the policy would need to be newly created.
