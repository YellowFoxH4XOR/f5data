Description

RDP through APM fails intermittently.

  • When launching the remote desktop resource, you observe an error message similar the below:
    The remote Desktop can't connect to the remote computer for one of the following reasons:
    1) Remote access to the server is not enabled.
    2) The remote computer is turned off.
    3) The remote computer is not available on the network.
    Make sure the remote computer is turned on and connected to the network, and that remote access is enabled.
  • In the packet capture, you may find  [F5RST: No server selected]
  • In /var/log/apm, similar to the below log when you set logging profile set with debug for Access Policy and VDI.

debug tmmx[<PID>]: 019cffff:7: <Access_Profile_Name>:00000000: RD: [C] <Client_IP>.<Client_Port> i <Virtual_Server_IP>.<Virtual_Server_Port>: server-side connection was reset, reason: No server selected

And can NOT see the Server side connection initiated with the similar log

debug vdi[17008]: 019cffff:7: <Access_Profile_Name>:<Partition_name>:<Session_ID>: {<no>.C} Connecting to <RDP_Server_IP>:<RDP_Port>, SSL disabled rtdom 0
debug vdi[17008]: 019cffff:7: <Access_Profile_Name>:<Partition_name>:<Session_ID>: {<no>.S} Connected to <RDP_Server_IP>:<RDP_Port> (id: <ID>)

Environment

  • BIG-IP APM
  • RDP with Native Client
  • OneConnect 

 

Cause

  • By design: The Oneconnect profile does not support VDI use cases.
     

Recommended Actions

Remove the OneConnect profile from the virtual server. To do so, perform the following procedure:
NOTE: Removing the OneConnect profile from the virtual server should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click on the name of the affected virtual server.
  4. Set the Oneconnect profile to None.
  5. Click Update.
