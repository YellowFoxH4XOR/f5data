K9779: HTTP headers containing no header value generate HTTP protocol compliance violations

Applies to

Issue

In BIG-IP ASM 9.4.3 and earlier, the non_rfc_bitmask setting is used to configure RFC compliance for the security policy.

By default, the BIG-IP ASM system considers an HTTP header with no value to be non-RFC compliant if it does not end with a colon character (:). For example, the following header is considered to be invalid and will trigger a non-RFC compliance violation in BIG-IP ASM 9.4.3 and earlier:

Header-Name\r\n

The following header is considered valid and will not trigger a non-RFC compliance violation in BIG-IP ASM 9.4.3 and earlier:

Header-Name:\r\n

Note: For more information about configuring non-RFC enforcement masks in BIG-IP ASM 9.2.0 through 9.4.3, refer to K7925: Configuring a non-RFC enforcement mask and K5713: Configuring a Non-RFC enforcement mask.

Beginning in BIG-IP ASM 9.4.4, RFC compliance is now configured using the HTTP Protocol Compliance screen, and the Header name with no header value setting specifies whether the BIG-IP ASM system checks requests for valueless header names.

Note: The HTTP Protocol Compliance screen is located at Application Security > Blocking > HTTP Protocol Compliance.

In addition, the default behavior for valueless headers has changed. For example, in BIG-IP ASM 9.4.4 and later, the following headers are considered invalid and will trigger a HTTP protocol compliance failed violation:

Header-Name\r\n
Header-Name:\r\n
Header-Name: \r\n

Note: Valueless HTTP headers ending with a colon can be used as part of an HTTP request smuggling attack.

F5 Product Development tracked this change in behavior as CR116975.
