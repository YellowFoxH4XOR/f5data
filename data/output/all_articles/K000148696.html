Description

After changing the tenant memory the tenant is stuck in a running state: Not ready: containers with unready status: [compute]

 

Numerous entries in /var/log/messages are similar to:

appliance-1 k3s: E1024 04:33:05.189130 28398 authentication.go:63] "Unable to authenticate the request" err="[invalid bearer token, Token has expired.]"

appliance-1 k3s: E1024 04:33:05.190098 28398 authentication.go:63] "Unable to authenticate the request" err="[invalid bearer token, Token has expired.]"

appliance-1 k3s: E1024 04:33:06.190024 28398 authentication.go:63] "Unable to authenticate the request" err="[invalid bearer token, Token has expired.]"

 

Environment

  • F5OS
  • Change in tenant memory

 

Cause

This is a known issue (bug ID1694481)

 

Recommended Actions

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

 

  1. Delete the multus pod by logging into the system as root and running the following command:
  2. #kubectl -n kube-system delete pod -l app=multus
  3. You can check the status of the multus pod by running the following command:

           # kubectl get pods --all-namespaces | grep multus 

       4. Once the command is executed, move the tenant into the provision state and then into deploy the state.
