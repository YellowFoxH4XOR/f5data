K000134697: ModSec to NGINX App Protect Migration

Type
Support Solution
Published
2023-05-19
Updated
2023-05-19
Source

Description

You want to migrate your ModSecurity (ModSec) deployed on NGINX Plus solution to NGINX Plus with NGINX App Protect.

Environment

  • Supported version of NGINX Plus
  • ModSecurity (ModSec)
  • Supported version of NGINX App Protect

Cause

On August 26, 2021, Trustwave, a key supporter of the ModSecurity WAF, announced the End-of-Life and End-of-Sale of their support for the ModSecurity WAF, and their intent to hand over maintenance to the open source community. Further, on December 22, 2021, the Open Web Application Security Project (OWASP) Foundation, a key contributor to the Core Rule Set (CRS) for ModSecurity, announced that they will be re-focusing their efforts and curtail specific investments in CRS for the ModSecurity WAF. Since the majority of ModSecurity users have implemented the CRS, this signifies a concern for those users of ModSecurity OSS with CRS on NGINX.

Recommended Actions

Since ModSec and NGINX App Protect are fundamentally different solutions there is no migration tool or path per se. (Although they both solutions provide Web Application Firewall functionality - ModSec is configured using Rules, while NGINX App Protect is signature based and cofigured using policies). As such, the "migration" from ModSecurity to NGINX App Protect essentially involves deploying NGINX App Protect from scratch, and ensuring that the applied policies meet all of the app security requirements.

If you are using an unmodified CRS v3 ruleset, NGINX App Protect WAF installs a default policy that is similar in configuration to the CRS. It is highly recommended that testing techniques be applied with the use of this policy in the context of your web application, to ensure the policy has been configured to provide optimal security without negatively impacting your application’s functionality. It is also recommended to initially configure the policy to operate in a “transparent” enforcement mode, to facilitate the safe behavioral testing of the policy without actual enforcement. This is similar to configuring ModSecurity’s SecRuleEngine setting to DetectionOnly during policy tuning. It is highly likely that the policy will need to be modified to support the specifics of your application and applicable security goals. The following section introduces approaches to NGINX App Protect WAF policy modification.

At installation time, NGINX App Protect WAF includes two template JSON policies in the /etc/app_protect/conf/ directory: NginxDefaultPolicy.json and NginxStrictPolicy.json, both of which are described here. In summary, NginxDefaultPolicy is a balance of security and usability. The NginxStrictPolicy adds additional security features beyond the default policy but may require more tuning for your specific use case.

NGINX App Protect WAF is configured entirely through NGINX configuration and JSON policy files. If your NGINX ModSecurity WAF configuration has been modified from OWASP CRS v3, it is likely that you will need to migrate individually modified NGINX ModSecurity WAF rules to your NGINX App Protect WAF policy.
