Description

When authenticating with Chrome only. Occasionally it will lock up doing NTLM and the process will halt. Closing the browser usually will fix, however sometimes only using incognito will clear the problem.

Environment

  • BIG-IP APM
  • Google Chrome Web Browser

Cause

This behavior is due to the POST request from the Chrome web browser sending the HTTP headers and the POST body separately, 30 miliseconds apart. BIG-IP sends 401 response after it receives the HTTP headers, which is correct behavior, and before POST body is sent, which leads to the NTLM stall.

Recommended Actions

  • Use a different web browser
OR
  • Include the following iRule to allow for the Virtual Server to handle the split POST request:
when HTTP_REQUEST {
                if { [string tolower [HTTP::header User-Agent]] contains "chrome" && [string tolower [HTTP::method]] eq "post" } {
                                #log local0. "Brief pause in milliseconds for BIG-IP to wait for Chrome to send the body in the request..."
                                after 100
                }
}
