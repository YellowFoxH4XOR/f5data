K000135858: Rewrite profiles get corrupted, when edited with the new GUI

Type
Support Solution
Published
2023-08-15
Updated
2023-08-15
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.0, 17.1.X, 17.0.X, 15.1.9, 17.0.0
  • BIG-IP LTM: 17.0.0, 15.1.9, 17.1.X, 17.0.X, 17.1.0
Source
https://my.f5.com/manage/s/article/K000135858

Description

On GUI, created && saved new rewrite profile from "+" of VIP,

 # tmsh list ltm profile rewrite test_rewrite_2

ltm profile rewrite test_rewrite_2 {
  app-service none
  bypass-list none
  client-caching-type cache-css-js
  defaults-from rewrite-uri-translation
  java-ca-file ca-bundle.crt
  java-crl none
  java-sign-key default.key
  java-sign-key-passphrase-encrypted none
  java-signer default.crt
  location-specific false
  request {
    insert-xforwarded-for enabled
    insert-xforwarded-host disabled
    insert-xforwarded-proto disabled
    rewrite-headers enabled
  }
  response {
    rewrite-content enabled
    rewrite-headers enabled
  }
  rewrite-list none
  rewrite-mode uri-translation
  split-tunneling false
  uri-rules {
    uri_1687862900915 {
      client {
        path /
      }
      server {
        path /test/
      }
    }
  }
}

 

GUI on rewrite profile

 

Then... try to modify URI rules on GUI: Local Traffic >> Profiles: Services: Rewrite > test_rewrite_2 

Also can not modify the profile.
 

Environment

  • BIG-IP 
  • v15.1.9 and later
  • v17.0.0 and later
  • Rewrite profile
 

Cause

Bug ID 1321713 which addresses two issues:

  1. inconsistent validation of the uri-rule (GUI requires URI format while tmsh does not).
  2. redirect to the old rewrite profile configuration page from the Virtual Server Create page (using the "+" button).
 

Recommended Actions

Use TMSH command to modify the profile.
