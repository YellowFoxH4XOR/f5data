Known Issue

Data Guard data masking may cause the BIG-IP ASM system to prematurely reset connections.

This issue occurs when all of the following conditions are met:

  • The Security Policy Enforcement Mode is set to Transparent
  • The Data Guard feature is enabled
  • The Mask Data option is enabled within the Data Guard configuration
  • Either of the following two features is also enabled:
    • CSRF Protection
    • Web Scraping Detection

Impact

The BIG-IP ASM system may prematurely terminate some connections.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP ASM system may prematurely generate a TCP RST packet for some connections

    For example, if you capture a tcpdump, the capture will show that the BIG-IP ASM system incorrectly sends a RST packet, possibly even before it has received the complete HTTP response from the server.

Workaround

To work around this issue, you can change the Enforcement Mode to Blocking, and set the Information Leakage blocking mask to Alarm. To do so, perform the following procedures:

Impact of workaround: The entire security policy will be set to Blocking mode. Ensure this is an appropriate setting for your environment before proceeding with this workaround. For more information, refer to the Configuring the enforcement mode chapter in the Configuration Guide for BIG-IP Application Security Manager.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Configure the Information Leakage violation

  1. Log in to the Configuration utility.
  2. Select Application Security >> Policy >> Blocking.
  3. Set the blocking mask for the Information Leakage detected violation to Alarm.
  4. Click Save.
  5. Click Apply Policy.

Configure the Enforcement Mode

  1. Log in to the Configuration utility.
  2. Select Application Security >> Policy.
  3. Change the Enforcement Mode to Blocking.
  4. Click Save.
  5. Click Apply Policy.
