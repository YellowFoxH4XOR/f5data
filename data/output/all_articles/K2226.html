Configuring the TFTP server

A core file is a compressed memory image of the BIG-IP system. If the BIG-IP system has 1GB of memory, the uncompressed core file will be the same size.

If you are using a BIG-IP installation CD as the TFTP server, you will need enough memory to run both the TFTP server and save the core file. In this case, the compressed core file may be as small as take up only 20 percent of the BIG-IP system's total memory. Therefore, if the BIG-IP memory is 1GB, the core file may be as little small as 200MB. For instructions about using the BIG-IP installation boot disk as an TFTP server, refer to the section titled Using the BIG-IP installation CD to convert a system to a TFTP server.

When the BIG-IP system sends core files to the TFTP server, it will attempt to match its core file with the existing file on the TFTP server, in the subdirectory named core. To configure the TFTP server to receive and save core files from BIG-IP, perform the following procedure:

  1. Verify that the TFTP server has enough hard drive space to save the core file.
  2. Create a subdirectory under the tftp root directory of the TFTP server (typically, tftpboot), named core.
  3. Using the UNIX touch utility, create an empty file in the core directory named, bsdcore.gz, by typing the following UNIX command:

    touch /tftpboot/core/bsdcore.gz

  4. Define the core directory and the bsdcore.gz file as world writable (so there are no access restrictions) by typing the following commands:

    chmod 777 /tftpboot/core

    chmod 777 /tftpboot/core/bsdcore.gz


Connecting the TFTP server to BIG-IP

To transfer core files, the TFTP server must be connected to the same physical network as the BIG-IP management interface in one of the following two ways:

  • With a network cable on the BIG-IP management interface (labeled MGMT on the front panel of the BIG-IP)

    Note: If you connect the TFTP server directly to the BIG-IP management interface, you must use an Ethernet cross-over cable.

  • Through a hub or switch

    Important: For this application, routing is not supported and will not work.  The BIG-IP management interface and the TFTP server must both use the same local network.

Configuring the BIG-IP system

To configure the BIG-IP system to send core files to the TFTP server, perform the following steps:

  1. Using a text editor, open the /etc/boot.default file. It should appear similar to the following:

    -echooff
    -bootdebug 0
    -autodebug -q
    -console auto

  2. If the BIG-IP is panicking and dumping core frequently, F5 Networks recommends that you limit the boot memory utilization in the /etc/boot.default file by adding the following line:

    Important: Any typographical errors or extra lines in the boot.default file can leave the BIG-IP unable to reboot. When modifying the boot.default file, it is important that you check all syntax and statements for errors or blank lines before saving the file.

    -memsize 256M

    This will set the memory on the BIG-IP to 256MB, and the core file (being the same size as memory) will also be 256MB (prior to compression).

  3. Modify the /etc/boot.default file to point to the remote TFTP server for writing core files by adding a line similar to the following:

    Important: Any typos or extra lines in the boot.default file can leave the BIG-IP unable to reboot. When modifying the boot.default file, it is important that you check all syntax and statements for typos or blank lines before saving the file.

    -netcore <IP Address for BIG-IP> <IP Address for server>

    The /etc/boot.default file will now appear as follows:

    -echooff
    -bootdebug 0
    -autodebug -q
    -console auto
    -memsize 256M
    -netcore <IP Address for BIG-IP> <IP Address for server>

  4. Reboot the BIG-IP system to save the changes.

  5. On a standby system, force the BIG-IP system  to panic (in order to test the TFTP write capability), by typing the following command:

    /sbin/bigpipe wd panic

    When the system panics, it will attempt to connect to the TFTP server. If there is not sufficient hard drive space or memory (using the BIG-IP install CD TFTP server), the BIG-IP will attempt to write the core file until the limit is reached and then it will abort.

Using the BIG-IP installation CD to convert a system to a TFTP server

If you do not have a TFTP server, you have the option to use the BIG-IP installation CD and to convert a system to a TFTP server.

The most common issues with this are:

  • The TFTP server has limited hard drive or memory capacity.
  • The core file is very large (+512MB) and the TFTP server times out after a long transfer time.
  • The TFTP server has a network interface card that is not supported by the F5 Networks PXE network boot server.

Note: For a complete list of supported network cards, refer to K2306: Network interfaces cards supported by the F5 Networks PXE network boot server.

To do use the BIG-IP installation CD and to convert a system to a TFTP server, perform the following steps:

  1. Put the BIG-IP installation CD into the CD-ROM drive of the system you want to use for the TFTP server and reboot the system.

    You will see the following prompts: 

    1. Install software onto hard disk
    2. Setup server to provide network installation
  2. Select 2, Setup server to provide network installation
  3. Modify the defaults presented to configure the TFTP server. In this example, 10.0.0 matches the other examples used in this solution. Make sure you specify network information specific to your configuration at this prompt. At the Upper IP range for clients prompt, you can accept default value, 210, but since this is a one-to-one TFTP transaction it is best to use a range that is limited, such as 10-11.
  4. When prompted, review and confirm your settings.
  5. To verify that the BIG-IP will write a core file to the TFTP server, you can have the BIG-IP panic with the following command:

    Important: The following command causes a panic and a reboot. Do not do perform this on the Active BIG-IP system.

    b wd panic

    This will panic the BIG-IP and cause it to send a core file to the TFTP server, if everything is configured correctly.

  6. Copy the bsdcore.gz file from the TFTP server where you send it through FTP it to a remote destination.

    If the remote destination is on a network other than the one used to configure the TFTP server, you may need to add a static route. For example, if you want to copy the file to the host 172.16.0.1, and the gateway for that network is 10.0.0.254, you would type the following command:

    route add 172.16.0.1 -gateway 10.0.0.254

    Note: Moving the core files can take between 10-30 minutes (depending on the size of the file).
