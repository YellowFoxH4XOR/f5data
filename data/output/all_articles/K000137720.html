Description

The BIG-IP Next CNF helm installation of dSSM fails , if there is no default storage class 

# oc get pod
NAME                                          READY   STATUS    RESTARTS      AGE
f5-dssm-db-0                                  0/2     Pending   0             3m13s
f5-dssm-sentinel-0                            0/1     Running   0             3m13s

# oc describe pod f5-dssm-db-0 | grep -i Events -A 10
Events:
  Type     Reason            Age    From               Message
  ----     ------            ----   ----               -------
  Warning  FailedScheduling  5m59s  default-scheduler  0/5 nodes are available: 5 pod has unbound immediate PersistentVolumeClaims. preemption: 0/5 nodes are available: 5 Preemption is not helpful for scheduling.
  Warning  FailedScheduling  53s    default-scheduler  0/5 nodes are available: 5 pod has unbound immediate PersistentVolumeClaims. preemption: 0/5 nodes are available: 5 Preemption is not helpful for scheduling.

# oc describe pvc data-f5-dssm-db-0 |  grep -i Events -A 10
Events:
  Type    Reason         Age                   From                         Message
  ----    ------         ----                  ----                         -------
  Normal  FailedBinding  52s (x26 over 6m39s)  persistentvolume-controller  no persistent volumes available for this claim and no storage class is set

 

Environment

  • OpenShift 4.12
  • BIG-IP Next CNF 1.1.1

Cause

No default storage class defined which is required by dSSM design 

Recommended Actions

1. Uninstall dSSM and remove persistent volume claim manually 

2. Patch required storage class as default 
# oc patch storageclass local-storage -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
storageclass.storage.k8s.io/local-storage patched

# oc get sc
NAME                      PROVISIONER                    RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
local-storage (default)   kubernetes.io/no-provisioner   Delete          WaitForFirstConsumer   false                  13d

3. Install dSSM DB via helm , which result with :
# oc get pod
NAME                                          READY   STATUS    RESTARTS      AGE
f5-dssm-db-0                                  2/2     Running   0             82s
f5-dssm-sentinel-0                            1/1     Running   0             83s

# oc get pvc
NAME                STATUS   VOLUME             CAPACITY   ACCESS MODES   STORAGECLASS    AGE
data-f5-dssm-db-0   Bound    worker1-local-pv   5Gi        RWO            local-storage   2m30s
