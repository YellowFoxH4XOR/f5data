Environment

  • Routing Rules
  • SDC 5.1 CF 21
  • EMS

Cause

As discussed in SDC bug CPF-25179, in the unlikely chance that there is no site available for the last routing row, the current site ID is applied to the last decision table row number and no exception error is generated. The not synchronized site was last in the list of EMS and it reset the index because it didn’t found the last routing row.

Recommended Actions

Workaround:

  1. Stop all process on EMS1 and EMS2
  2. Backup /data/backup on all the nodes (EMS+SDC)
  3. On EMS1 and EMS2, go to the latest flowmanager directory of each subfolder (ems, sdc site1, sdc site2 etc) and run the command below:
    • VAL=`grep -F \>RT- flowManager.xml |awk -F\DecisionRow\>\<Id\> '{print $2}' |awk -F\< '{print $1}' |grep RT |awk -F\- '{print $2}' |sort -n |tail -1`
    • sed -i 's/maxRoutingDecisionId<\/key><value>-1<\//maxRoutingDecisionId<\/key><value>'"${VAL}"'<\//g' flowManager.xml
  4. Start all process on EMS1 and EMS2
  5. Login to EMS1 WebUI, add a dummy config (ex. peer profile) to distribute fixed flow manager. Check the WebUI on the sdc sites if it has the last changes, then remove it.
  6. Check if you can add a new routing rule.

Fix : 
A permanent fix has been added to version CF 27.
