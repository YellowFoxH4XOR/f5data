Description

  • In some environments, your resource servers behind the BIG-IP system may require user data to be sent through HTTP headers. 
  • These may be used for authentication or auditing purposes by the server.

Environment

  • BIG-IP APM is configured as a Security Assertion Markup Language (SAML) service provider (SP)
  • Identity Provider (IdP) is configured to send user-specific information within SAML attributes
  • Resource servers are configured to inspect HTTP headers for user information

Cause

None

Recommended Actions

Configuring an iRule to convert session variables into HTTP headers

To enable the BIG-IP APM system to send these attributes to the servers, you must configure an iRule to take the necessary session variables and add them as HTTP headers. To do so, perform the following procedure:

  1. Log in to the Configuration utility (GUI).
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. For Name, enter a name for the iRule. For example:
saml-attribute-rule
  1. For Definition, enter the iRule using the following syntax:
    Note: Depending on the use case with your IDP/SP, and the client application, you may need to replace the iRule event HTTP_REQUEST below, with HTTP_REQUEST_RELEASE.
when HTTP_REQUEST_SEND {
    clientside {
        HTTP::header replace <Header_Name> [ACCESS::session data get "session.saml.last.attr.name.<attribute_name>"]
    }
}

For example, your iRule may appear similar to the following:

when HTTP_REQUEST_SEND {
    clientside {
        HTTP::header replace Username [ACCESS::session data get "session.saml.last.attr.name.Name"]
    }
}

 

  1. Click Finished.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the name of the virtual server to which the access policy will be applied.
  4. Click the Resources tab.
  5. For iRules, click Manage.
  6. In the Available box, highlight the name of the iRule you just created.
  7. Click the << button. The iRule moves to the Enabled box.
  8. Click Finished.
