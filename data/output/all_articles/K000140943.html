K000140943: Persistent TMM Restarts and Device Instability on BIG-IP 17.1.1.3

Type
Support Solution
Published
2024-09-04
Updated
2024-09-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000140943

Description

  • Persistent TMM Restarts and Device Instability on software version 17.1.x
  • Error messages similar to the following can be seen on var/log/ltm

    err tmm[22907]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (6) (global memory) 30 Connections killed
    err tmm1[22907]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (1000000000007) (global memory) 23 Connections killed
    err tmm3[22907]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (3000000000007) (global memory) 25 Connections killed
    err tmm2[22907]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (200000000000b) (global memory) 19 Connections killed

Environment

  • BIG-IP
  • APM provisioned
  • BIG-IP configured as SP and with "Sign Authentication Request" enabled

Cause

Seen behaviour is caused by a known issue tracked with the Bug ID 1353021.

Recommended Actions

At the time of creation of this article, there is no fix available on public releases. If required, an EngHF with the fix can be provided.

Additional Information

To confirm that the Bug in question is in play. You can run the following command and check if process sso::sso_saml memory usage is increasing over time/

ls /shared/tmstat/snapshots/blade*/public/3600/* | xargs -I {} sh -c 'echo "\n"{}; tmctl -f {} memory_usage_stat -s memory_usage_stat -s name,max_allocated -OK max_allocated| head -n 15;'
