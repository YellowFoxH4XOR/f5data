Known Issue

The BIG-IP system does not allow the community string to be set to the value of none for an existing SNMP access configuration.

This issue occurs when one of the following conditions is met:

  • A configuration with the SNMP community string set to none is upgraded to 11.x.
  • You attempt to set an SNMP community string to none on a version 11.x BIG-IP system.

In versions prior to 11.0.0, the BIG-IP system allows the SNMP community string to be set to none for an existing SNMP access configuration. Setting the community string to none allows the BIG-IP system to prevent SNMP access from any hosts, including localhost.

Impact

The SNMP community name may not be set to none, preventing the SNMP from accessing any hosts, including localhost.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system may not load the configuration after booting to the 11.x upgrade.
  • If you have configured an SNMP community with the community name property set to none in a previous version, the BIG-IP system may not load the configuration. As a result, if you attempt to load the configuration from the command line (tmsh load sys config), the system will report an error message that appears similar to the following example:

    Data Input Error:(at line: 146) a value must be provided for "community-name"

  • When you attempt to set the community name property to none, the BIG-IP system reports an error message that appears similar to the following example:

    Data Input Error: "community-name" is a required property and may not be set to "none" or an empty value

Workaround

If the BIG-IP system is unable to load the configuration after an upgrade, you can reset the SNMP community to its default value by removing the SNMP configuration stanza from the /config/bigpipe/bigip_sys.conf file and reloading the configuration. To do so, perform the following procedure:

Impact of workaround: The SNMP community string will be reset to its default value of public.

  1. Log in to the command line.
  2. Edit the /config/bigpipe/bigip_sys.conf file using a text editor of your choice.
  3. Locate and remove the SNMP configuration stanza, as shown in the following example:

    snmpd {
    community comm-public {
    community name none
    source none
    }
    }

  4. Save the changes and exit the text editor.
  5. Reload the configuration by entering the following command:

    Important: You should use the following command only when instructed in an article or by F5 Support.

    /usr/libexec/bigpipe daol

  6. Save the configuration using the Traffic Management Shell (tmsh) by entering the following command:

    tmsh save sys config partitions all

  7. Reload the configuration using the tmsh utility by entering the following command:

    tmsh load sys config partitions all

  8. Ensure that the comm-public SNMP community is set to its default value by entering the following command:

    tmsh list sys snmp communities

    The output should appear as follows:

    sys snmp {
    communities {
    comm-public {
    community-name public
    source default
    }
    }
    }
