K16329254: webd continually restarting server.key is encrypted

Type
Support Solution
Published
2020-11-04
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K16329254

Description

The BIG-IQ web interface is not compatible with an encrypted SSL private key. A private key with a password is an encrypted SSL private key. If a server.key that is password protected is used the webd process will not start successfully.
The log webd_errors.log will have error messages similiar to the following error:

xxxx/xx/xx xx:xx:xx [emerg] xxxxx#x: SSL_CTX_use_PrivateKey_file("/etc/httpd/conf/ssl.key/server.key") failed (SSL: error:0906406D:PEM routines:PEM_def_callback:problems getting password error:0906A068:PEM routines:PEM_do_header:bad password read error:140B0009:SSL routines:SSL_CTX_use_PrivateKey_file:PEM lib)

Environment
  • BIG-IQ

Cause

The BIG-IQ Configuration utility is not compatible with an encrypted SSL private key

Recommended Actions

Option 1

Use a /config/httpd/conf/ssl.key/server.key that is not password encrypted

Option 2

Generate a new key without a password
Note: If you have the password for a private key a new private key can be generated from it that is not encrypted.

  1. To create an unencrypted key from an encrypted key:
    openssl rsa -in [original.key] -out [new.key]
  • It will ask for the password.
  • The new.key will be unencrypted.
