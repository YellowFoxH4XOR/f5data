Known Issue

The BIG-IP APM aced process may stop responding if a child process exits.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured to provide RSA SecurID authentication.
  • An aced child process exits unexpectedly.

The aced process can spawn as many child processes as needed to accommodate the RSA SecurID AAA servers configured on the BIG-IP APM system. If one of the child processes exits unexpectedly, the service may stop authenticating users.

Impact

RSA SecurID authentication fails and users cannot log in.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H500910 on the Diagnostics > Identified > Medium screen.
  • Your BIG-IP APM system cannot authenticate users by using RSA SecurID AAA servers.
  • The aced process exits and generates a core file to the /shared/core directory.
  • When a user attempts to log in, the system displays a message similar to the following example:

    err apd[572]: 01490122:3: 136c67a7: SECURID module: authentication with '<username>' failed: Exception: Could not bind to port. , code: -1, state: SECURID_AUTH_STATE_ACCESS_DENIED

Workaround

To work around this issue, you can manually restart the aced process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM command line.
  2. To manually stop any remaining aced processes, type the following command:

    killall aced

  3. To restart the main aced process, type the following command:

    bigstart restart aced
