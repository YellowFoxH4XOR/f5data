Topic

This article describes iRules commands that may temporarily suspend iRules processing.

Description

Suspending commands

The iRules command set contains commands that may temporarily suspend iRules processing for the current connection when the rules are run, and the connection is held until iRules processing resumes. After the command has completed, iRules processing resumes and the connection is processed according to the BIG-IP configuration. This behavior is intended to allow the BIG-IP system to efficiently share the data managed by these commands across multiple Traffic Management Microkernel (TMM) instances.

Note: iRules processing is suspended only for the specific connection that triggered the iRule. iRules processing is not suspended for other connections processed by the same iRule or the same virtual server. iRules processing continues without suspension for each connection until that connection traverses the iRule and runs the suspending command.

Note: The term "suspend" is commonly referred to as "park" or "parking."

The following suspending commands were introduced in BIG-IP 9.0.0:

  • SSL::sessionid
  • TCP::notify
  • session
  • persist

The following suspending command was introduced in BIG-IP 10.0.0:

  • after

The following suspending commands were introduced in BIG-IP 10.1.0:

  • table
  • RESOLV::lookup
  • ACCESS::session

    Note: When you run the ACCESS::session command, iRules execution on the connection will be suspended until the operation completes only if the session database record is held by another TMM; this situation allows the current TMM to retrieve the data from the other TMM before processing the remainder of the iRule. The ACCESS:: commands are available only if your BIG-IP system is licensed for the BIG-IP APM system.

The following suspending commands were introduced in BIG-IP 11.0.0

  • connect
  • recv
  • send

Note: For more information about each command, refer to the Commands Introduced in BIG-IP LTM 11.0.0 page on F5 Cloud Docs.
