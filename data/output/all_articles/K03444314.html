Description
Starting in version 12.0, GSLB Pools and WideIPs have specific types like A, AAAA and CNAME. Issuing tmsh show gtm pool and wideip commands using the "field-fmt" option will result in the type of object (pool or wideip) being displayed twice in the output.

Example of the output for a Pool:
gtm pool pool emptypool:A {
    alternate 0
    dropped 0
    fallback 0
    name emptypool
    pool-type A
    preferred 0
    return-from-dns 0
    return-to-dns 0
    status.availability-state offline
    status.enabled-state enabled
    status.status-reason No enabled pool members available
}

Example of the output for a WideIP:
gtm wideip wideip testwip.company.com:A
    alternate 0
    cname-resolutions 0
    dropped 0
    fallback 0
    persisted 0
    preferred 0
    rcode 0
    requests 0
    resolutions 0
    return-from-dns 0
    return-to-dns 0
    status.availability-state unknown
    status.enabled-state enabled
    status.status-reason Checking
    wip-name testwip.company.com
    wip-type A
}

Environment

  • GTM/DNS provisioned
  • GSLB Pool(s) and/or GSLB WideIP(s) configured

Cause
This is due to an anomalous condition and is tracked with ID774257, fixed in 16.0.0.

Recommended Actions

There is no performance or functionality impact with the output displaying the word "pool" or "wideip" twice in the output. The repetition can be safely ignored. Upgrading to 16.0.0 or later will fix this issue.
