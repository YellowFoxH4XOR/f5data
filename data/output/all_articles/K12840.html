Known Issue

Description

When importing shares for a managed volume enabled for subshares, the import will fail for subshares using the same name as a subshare that has already been imported for a different managed volume on the ARX.

Impact

The subshares with duplicate names will not be imported and the managed volume will be in a degraded state.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Volume status will be marked as Degraded in the ARX Manager GUI.
  • The Share status will be marked as Offline: Disabled in the ARX Manager GUI.
  • An error message that appears similar to the following example is logged to the syslog file:

    DOLLAR_SUBSHARE_CONFLICT: Subshare exports 'Share1' and 'Share1' would both try to use share name
    'Share1$' on the backend filers. Please use a different export name.
  • Users will be unable to access affected shares.

Workaround

To work around this issue, you can rename the affected subshares on the filer and in the ARX configuration for one of the managed volumes. To rename a share in the ARX configuration, you must delete the undesired share name then re-add a share using the desired share name. Use the share command to add and delete shares from the managed volume. 

Impact of workaround: Users will be required to re-map their shares to use the new name.

Supplemental Information

For information about the share command, refer to the ARX CLI Reference Guide.
