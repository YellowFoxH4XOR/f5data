Known Issue

This is the result of a known issue. Cluster load balancing can send connections to an off-line secondary node instead of keeping the connections on the cluster primary node.

In a FirePass cluster, the new logon connections first go to the cluster primary, if the Load Balancing drop-down menu on the Clustering: Settings page is set to Random. This load balancing will cause the cluster primary either to accept the logon, or to redirect the logon to a secondary node.

If the load balancing algorithm decides to redirect to a secondary node, the primary will first perform a health check on the secondary to determine whether the secondary node is off-line. If the health check fails, the primary will not issue the redirect and instead keep the logon connection. However, an issue with the load-balancing algorithm will cause only the first logon request per 30 minute period to be kept on the primary. Subsequent logon requests will act as if the health check to an off-line secondary had succeeded, and issue the HTTP redirect to the off-line secondary. This will typically result in a timeout error or similar error in the client browser.

F5 Product Development tracked this issue as CR70678, and it was fixed in version 6.0.1. For information about upgrading, refer to the FirePass Release Notes.

Additionally, a hotfix has been issued. For version 6.0.0 of FirePass software, this issue was fixed in cumulative hotfix HF-600-6. For version 5.5.2 of FirePass software, this issue was fixed in cumulative hotfix HF-552-1. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
