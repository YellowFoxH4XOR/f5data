Issue

You should consider using this procedure under the following conditions:

  • The Dropped Requests column values are not populated in the AFM DoS Reporting page. 
  • You are experiencing the side effects of Bug ID 649873, where the drop requests value is reported as zero (0).

Symptoms:

  • The Dropped Requests column value is not populated in the AFM DoS Reporting page, even if an AFM DoS Vector was triggered and logs were generated from the Configuration utility (Security > Reporting > DoS > Network), where the Dropped Requests column value shows zero (0).
  • You review the log file /var/log/ltm and the AFM DoS Vector is triggered:

    f5 err tmm[17144]: 01010252:3: A NETWORK /Common/vs DoS attack start was detected for vector TCP RST flood, Attack ID 3629569319.
    f5 notice tmm[17144]: 01010253:5: A NETWORK /Common/vs DoS attack has stopped for vector TCP RST flood, Attack ID 3629569319.

  • You use the Traffic Management Shell (tmsh) to review the AFM DoS vector that was triggered, using the following command syntax, but the Dropped Requests column values in the AFM DoS Reporting page does not appear:

    tmsh show security dos profile <AFM_Dos_Profile> | grep -i <VS_Name> -A15

      | Virtual Server Name: <VS_Name>
      | Network DoS Vector: TCP SYN flood
      -----------------------------------
      |
      | Statistics Type        Count
      |   Attack Detected          0
      |   Attack Count             1
      |   Stats 1h Samples         0
      |   Stats             23424960
      |   Stats Rate               0
      |   Stats 1m                 0 
      |   Stats 1h                 0
      |   Drops             23409954
      |   Drops Rate               0
      |   Drops 1m                 0
      |   Drops 1h                 0

    Note the following count indicators:

    • The Attack Count counter increments every time the respective DoS vector is triggered.
    • The Drops counter value should reflect the same value on the AFM DoS Reporting Page in the Configuration utility.

Recommended Actions

To recover the Dropped Requests column values on the AFM DoS Reporting page in the Configuration utility, you can restart the monpd process. To do so, perform the following procedure:

Impact of procedure: No reporting charts are displayed while the monpd process is restarted.

  1. Log in to the BIG-IP command line.
  2. Restart the monpd process by typing the following command:

    tmsh restart /sys service monpd

If restarting the monpd process does not recover the Dropped Requests column value, you can reset the BIG-IP AVR statistics database. To do so, perform the following procedure:

Impact of procedure: The following procedure removes all Analytics data and resets the MySQL database. Perform this procedure during a scheduled maintenance window. Save a copy of a UCS backup from the BIG-IP device before you run the procedure. Ensure that the backup UCS is saved off the BIG-IP  device where it can be retrieved at a later time.

  1. Log in to the BIG-IP command line.
  2. Create the /var/avr/init_avrdb file by typing the following command:

    touch /var/avr/init_avrdb

  3. Restart the monpd process by typing the following command:

    tmsh restart /sys service monpd
