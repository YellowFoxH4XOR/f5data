Description

In its output of tmsh show qtm iquery BIG-IP with DNS or LC shows its own server type unknown

--------------------------------------------------
Gtm::IQuery: 192.168.1.1
--------------------------------------------------
Server                                        b101
Server Type                                unknown

Note: The previous example output is truncated for brevity.

Environment

BIG-IP DNS or LC provisioned

Cause

Initially the server type field is set to value unknown and then changed to BIGIP-DNS when one of the two conditions is true

  • A heartbeat message is received from the peer over the established iQuery connection
  • The code realises that the iQuery connection is established to its own self IP [because heartbeat messages are not sent over connections to self IP]

If for some reason the code remains unaware that the iQuery connection is established to its own self IP, so that the server type field value remains unknown

Recommended Actions

The condition is believed not reproducible at will, no code changes can be confirmed to fix it. A possible workaround is restarting the iQuery connectivity using in bash CLI:

# bigstart restart big3d
