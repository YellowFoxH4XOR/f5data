K000162932: NGINX Ingress Controller Retains Stale Upstream Endpoints After Deployment Changes

Type
Support Solution
Published
2026-08-14
Updated
2026-08-14
Applies to
  • NGINX Products
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000162932

Description

NGINX Ingress Controller can retain a stale upstream endpoint when a backend Deployment is recreated or scaled. The issue affects cross-namespace VirtualServer (VS) or VirtualServerRoute (VSR) configurations, causing the generated NGINX configuration to retain outdated backend endpoints.

Environment

  • NGINX Ingress Controller with NGINX Plus.
  • Cross-namespace VS or VSR configuration referencing a backend Service.
  • Multiple namespaces configured for monitoring.
  • Custom resources enabled with:
    -enable-custom-resources

Cause

This behavior is associated with GitHub issue 9640 in the NGINX Ingress Controller project. A product fix is required.

Answer/Recommended Actions

  1. Verify that NGINX Ingress Controller monitors every namespace containing the relevant VS, VSR, Service, and backend resources:
    -watch-namespace=<required namespaces>
  2. Confirm that custom resources are enabled when using VS or VSR objects:
    -enable-custom-resources
  3. Verify that the backend Service and its EndpointSlice or Endpoints objects contain the expected endpoints.
  4. Confirm that the VS or VSR references the correct namespace and Service.
  5. Deploy or upgrade NGINX Ingress Controller to version 5.6.0 or a later release containing the fix.
  6. No additional configuration is available to force an immediate refresh of the stale upstream endpoint. Changing the namespace watch configuration alone is not expected to resolve this defect.

Additional Information

The issue can occur even when all required namespaces are being monitored. Validate the generated configuration and backend resource state when the stale endpoint is present.
