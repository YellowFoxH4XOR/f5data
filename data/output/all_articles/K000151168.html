K000151168: Assigning more memory for tenant fails with an error: Insufficient memory on node, retrying tenant deployment.

Type
Support Solution
Published
2025-06-11
Updated
2025-06-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000151168

Description

Even if there is more than enough memory to accommodate the tenant as per the system summary in the GUI dashboard, assigning more resources fails with an error 'Insufficient memory on node, retrying tenant deployment'.

 

Platform logs present the following:

2025-04-29T05:09:45.635074 node-agent[10843]: priority="Info" version=1.0 msgid=0xe01000000000052 msg="Total four K memory consumed by all tenants are" MEMORY=0.

2025-04-29T05:09:45.640633 orchestration-agent[8]: priority="Err" version=1.0 msgid=0x506000000000039 msg="NodeAgent failed to process the request with error" message="No enough memory available for tenant allocation.".

2025-04-29T05:09:45.640648 orchestration-agent[8]: priority="Err" version=1.0 msgid=0x506000000000042 msg="Failed to allocate memory for tenant" TENANT="tenant_name" node=1.

 

When checking the output from the 'show components' command, the system presents more tenants than are currently configured.

Environment

  • F5OS-A
  • Increasing memory for the tenant

Cause

For some reason, the memory resources have not been released fully after deleting old tenants.

Recommended Actions

Reboot.

Additional Information
