The 3-DNS Controller uses the following ports to communicate with specific processes. These ports are open and listening only on the loopback interface. There is no need to have these ports open on your firewall.

PortService
127.0.0.1:8053NameSurfer:UI
127.0.0.1:1515LocalLBServer
127.0.0.1:1616ITCMSystemServer (includes ConfigSync interface)
127.0.0.1:1717ITCMNetworkingServer
127.0.0.1:1818ITCMManagementServer
127.0.0.1:8054NameSurfer:DNS Requests (UDP and TCP)
127.0.0.1:389LDAP Server
127.0.0.1:90013-DNS self-service checks
127.0.0.1:2121Sync agent for 3-DNS synchronization
127.0.0.1.8007Tomcat

If you have a redundant pair of 3-DNS Controllers, you can use the following ports for inter-controller communication. These ports are open on the external network interfaces and may need to open on the firewall. There is no present need to allow access to these ports from other systems.

*.683iControl remote non-crypto communication
*.684iControl remote SSL communication

iQuery is the proprietary protocol used for 3-DNS Controllers to share information between F5 Networks systems. Each 3-DNS Controller communicates to all other 3-DNS, BIG-IP, and GLOBAL-SITE/EDGE-FX systems using the following ports.

*.4353iQuery (TCP or UDP)
*.245iQuery (UDP)

Following is the standard DNS port. It is important to allow incoming connections with a destination port of 53.

Note: BIND may also pick an ephemeral UDP port to open for recursive queries. For more information on this port and how to control it, refer to K1485: Use of ports higher than 1028 on 3-DNS.

*.53BIND (TCP and UDP)

The syslog port displays as open, but does not accept connections; therefore, it is not necessary to allow connections to the 3-DNS on the following port.

*.514syslog

The following port is open for SNMP requests (if bigsnmpd is running). Open this port on your firewall if you plan on monitoring your 3-DNS Controller using SNMP.

*.161SNMP

SSH is primarily used for administrative access to the 3-DNS Controller. You will most likely want to allow access through your firewall on the following port. Occasionally, the 3-DNS Controller will need to push out a new big3d agent to the BIG-IP Controllers. This will be done through SSH (scp), so you must allow the 3-DNS Controller to communicate to the BIG-IP Controllers over this port as well.

*.22SSH

HTTPS is used to securely administer the 3-DNS Controller through a web browser. If you want your firewall to allow this traffic, you must allow access the following port.

*.443HTTPS
