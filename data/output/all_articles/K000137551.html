Description

Event log(s) may not be sent to remote logging server(s) during peak traffic. Remote event logs are dropped, while locally logged (when configured).

When traffic volume reduces, logging resumes to remote logging server(s).

Stable connectivity with remote logging server(s) during the peak traffic and loss of event(s).

Environment

  • ASM remote logging profile

Cause

During peak traffic, too many event logs are generated. Virtual server(s) may have multiple remote logging profile(s) attached. Multiple remote logging profiles could multiply the remote logging volume. When remote event log volume exceeds the internal remote_logger queue size some logs are dropped.

Recommended Actions

ASM remote logging flows through two queues:

First the socket queue (TCP connection queue). Socket behavior is controlled via internal parameter: "guarantee_remote_logging"

Second is an internal BD queue between the traffic enforcement (plugin) thread) and the remote logger thread. The plugin thread adds log messages to the remote_logger queue. The remote logger thread sends and then removes the messages from the queue.

 

If the queue reaches the max queue length, 500 messages by default, further messages are silently dropped. No message is logged of the dropped log messages.

The 6th column of the UMU message printed in the bd.log file, in part, represents the number of remote log messages. There are additional uses of this UMU column, not only the request log messages.

BD_MISC|NOTICE|Oct 18 11:34:15.197|16992|temp_func.c:4154|UMU: 0 0 0 0 0 0 0 0 0 || 733 385 203 590 134 744 62 123 335 0 0 0 || 0 41 454 0 1 8834

 

Simply seeing the 6th column exceeding the default queue length, 500 by default, does not indicate messages are being dropped. Only a need to further inspect the stats for the remote_logger tmstat information for drops.

# tmctl -f /var/tmstat/blade/asm_bd asm/bd_remote_log_pipe name=remote_logger
name          internal_drop external_drop successful
------------- ------------- ------------- ----------
remote_logger             0             0          0

 

The size of this queue is defined by the internal parameter prx_batch_queue_len.

 

For the internal BD queue, the internal parameter "remote_logging_guarentee_logging" controls holding the traffic until queue space is available. When enabled, the log event will check for available queue space until space is available, endlessly. This does not block other threads from writing to the queue, only the reporting thread will loop the check until there is space to write the log event to the remote logging queue. When disabled, if queue space is not available, the log event is dropped and reported in the "internal_drop" counter.

Use "remote_logging_guarentee_logging" when memory resources are low,  or cannot increase the prx_batch_queue_len size, and logging all the data is required, regardless of traffic volume.
 

For the socket queue, the "quarantee_remote_logging" parameter is used. Failure of log events at the socket connection are reported in the "external_drop" counter.

"guarantee_remote_logging" is not displayed under "Security ›› Options : Application Security : Advanced Configuration : System Variables", but is enabled by default.

If present, verify "guarantee_remote_logging" is enabled. Then adjust the size of internal bd queue using "prx_batch_queue_len".

 

To increase:

# /usr/share/ts/bin/add_del_internal add prx_batch_queue_len xxx
# tmsh restart sys service asm

To revert to default: 

# /usr/share/ts/bin/add_del_internal add prx_batch_queue_len 500
# tmsh restart sys service asm

IMPORTANT: The bigger the size, the more memory the system will use for buffering and holding data from the message until it will get actually queued. There is no algrithom to calculate how many more memory is consumed when you change the value. We recommend you to increase the value gradually and monitor memory usage on device.

Impact of procedures: device will be in offline status and production traffic will be impacted, so please schedule a maintenance window do to it.
