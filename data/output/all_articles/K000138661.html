K000138661: istiod-cassandra-x container constantly restarting

Type
Support Solution
Published
2024-03-01
Updated
2024-03-01
Applies to
  • Aspen Mesh: 1.11
Source
https://my.f5.com/manage/s/article/K000138661

Description

istiod-cassandra pod is in 'CrashLoopBackOff' state and is constantly restarting.

Environment

- Aspen Mesh
- istiod-cassandra pods

Cause

Unknown at time of publication.

Recommended Actions

1) Use the same procedure as described in: https://my.f5.com/manage/s/article/K000135976

2) If the problem still occurs, repeat the modified version of the procedure from K000135976:


- scale down the Cassandra pods
- delete the PVCs,
- scale up the Cassandra pods to 1
- scale up the Cassandra pods to 2
- finally scale up the Cassandra pods to 3
 

This modified procedure should allow Cassandra to recover without entering a perpetual CrashLoopBackOff cycle

When using istiod-cassandra:

kubectl scale statefulset -n istio-system istiod-cassandra --replicas=0
statefulset.apps/istiod-cassandra scaled
kubectl delete pvc -n istio-system data-istiod-cassandra-0
kubectl delete pvc -n istio-system data-istiod-cassandra-1
kubectl delete pvc -n istio-system data-istiod-cassandra-2

kubectl scale statefulset -n istio-system istiod-cassandra --replicas=1
kubectl scale statefulset -n istio-system istiod-cassandra --replicas=2
kubectl scale statefulset -n istio-system istiod-cassandra --replicas=3


When using aspen-mesh-event-storage:

kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=0
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-0
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-1
kubectl delete pvc -n istio-system data-aspen-mesh-event-storage-2

kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=1
kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=2
kubectl scale statefulsets -n istio-system aspen-mesh-event-storage --replicas=3
