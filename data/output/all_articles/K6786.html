Known Issue

The iRule b64encode function performs a string conversion NULL values (hex value: 0x00) causing them to be UTF-8 encoded (hex value: 0x80c0).

Base64 is typically used for encoding PEM. PEM is typically used for such things as email and SSL certificates.

The result of the improper conversion of NULL values causes the b64encode function to translate the 0x00 value to 0x80c0, preventing the receiving system (server or client) from decoding the information correctly using either OpenSSL or any other Base64 implementation.

F5 Product Development tracked this issue as CR70918 and it was fixed in BIG-IP LTM versions 9.1.3, 9.3.0, and 9.4.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by using the X509::whole command to return the certificate in PEM format instead of binary.

If you are currently using the b64encode [SSL::cert 0] function in your iRule, replace [SSL::cert 0] with [X509::whole [SSL::cert 0]], as in the following example:

b64encode [X509::whole [SSL::cert 0]]

Replacing [SSL::cert 0] with [X509::whole [SSL::cert 0]] in the iRule ensures that the information encoded as Base64 does not contain NULL values.
