Known Issue

This is the result of a known issue. The pvac process leaks memory each time the configuration is loaded when the BIG-IP WebAccelerator policy contains cache invalidation rules. The total amount of memory leaked depends on the number of invalidation rules contained in the policy. For example, a large number of invalidation rules in the BIG-IP WebAccelerator policy will result in a higher amount of physical memory leaked by pvac following each configuration load.

Note: It is possible to observe the memory leak by running the top command and looking at the RSS column while sending a SIGHUP signal to the pvac process.

F5 Product Development tracked this issue as ID 352275 and it was fixed in BIG-IP WebAccelerator versions 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes. In addition, BIG-IP iHealth may list Heuristic H842942 on the Diagnostics > Identified > Low|Medium screen.

Note: F5 initially filed ID 317416 (formerly CR117059) for the issue but it did not completely address the memory leak.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-496.0-HF2, which has been issued for BIG-IP WebAccelerator version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by restarting the pvac process on a regular basis, depending on the severity of the memory leak. To do so, perform the following procedures:

  1. Log in to the BIG-IP command line.
  2. Restart the pvac process by typing the following command:

    Important: Restarting the pvac process will briefly interrupt connections and you should schedule it accordingly.

    bigstart restart pvac
