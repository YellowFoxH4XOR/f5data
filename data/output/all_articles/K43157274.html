Description

BIG-IQ managed Web Application Security (ASM) policy configuration re-import fails with the following error.

Failed to copy configuration to working-config; reason: Policy '<policy-name>': caseInsensitive is set only once, and should not be changed. Existing value: '<true/false>', New value: '<true/false>'
Note: A similar error is reported by both the UI as well as logged within the /var/log/restjavad.*.log file of the BIG-IQ Centralized Management(CM) device. 

Environment

  • BIG-IQ Centralized Management
  • BIG-IP ASM 
  • Web Application Security (ASM) policy configuration re-import

Cause

When you first create a ASM security policy you have the option of making a security policy case-sensitive or not. You cannot change this setting after the security policy is created. BIG-IQ will not import the configuration of an identically-named Web Application Security (ASM) policy with case sensitive option set to a different value for the same policy.

Recommended Actions

Make a determination of the Web Application Security (ASM) policy containing the correct case-sensitive value. The *only* way to change the case-sensitive value for either the BIG-IQ or target managed BIG-IP ASM device is to re-deploy the ASM policy from scratch requiring all of the Web Application Security (ASM) policy configuration objects to be manually recreated followed by either a BIG-IQ configuration Deployment or a re-import of the updated (ASM) managed BIG-IP policy configuration. 

Note: Web Application Security policy deletion requires dependant associated objects to first be de-associated from the ASM policy before the ASM policy deletion is permitted for the policy recreation. 

There is another workaround available to import proper configuration of ASM policy:

  1. Identify which policy is causing issue
  2. Go to Configuration tab > Web Application Security > Virtual Servers
  3. Filter VSes by attached policy using filter
  4. Detach policy from each virtual server by clicking on VS then clicking X in attached polices
  5. Do this for each VS and apply by clicking save and close
  6. When all VSes has it detached we are OK to remove the Police only from BIG-IQ
  7. Now You can do re-discover and re-import ASM service
Note: This plan of action does not have negative impact on Policy which is configured on BIG-IP device

Additional Information

If configuration contains a lot of policies with similar error consider using script to unassociate remove all  ASM policies.
 

NOTE: You need to remember that using this workaround requires rediscover and reimport for ALL ASM devices managed on this BIG-IQ

PATCH VS
Use following commands on BIG-IQ CM CLI to remove Policy associacion from all virtual servers:

  1. restcurl -u admin:admin /mgmt/cm/asm/working-config/virtual-servers/ | jq '.items[] | select(.hasAttachedPolicies == true)' | grep selfLink | awk '{gsub(/"/, "",$2); print $2}' | sed 's/,//g' | sed -r 's/.{22}//' | while read -r line; do restcurl -u admin:admin $line -X PATCH -d '{ "attachedPoliciesReferences": [], "hasAttachedPolicies": false }' ; done
  2. Verify if all have been removed: restcurl /cm/asm/working-config/virtual-servers/ | jq '.items[] | select(.hasAttachedPolicies == true) | {name,hasAttachedPolicies}' | jq -s '. | length'

 Check if this returns 0. If Yes, Proceed to Delete Policies step.

 If No, Step 1 should be showing some error messages related to advance settings validation.  This likely might require opening support ticket  to verify errors.

DELETE Policies
Use following command to remove policies from working-config of BIG-IQ

Note: This command does not have negative impact on Policy which is configured on BIG-IP device

 

restcurl -u admin:admin /mgmt/cm/asm/working-config/policies/ | grep selfLink | awk '{gsub(/"/, "",$2); print $2}' | sed 's/,//g' | sed -r 's/.{17}//' | while read -r line; do restcurl -u admin:a $line -X DELETE ; done
