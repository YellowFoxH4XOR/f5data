Known Issue

VIPRION blades with an HSBe2 high speed bus (HSB) may calculate an incorrect TCP checksum.

This issue occurs when all of the following conditions are met:

  • You are using a VIPRION system with the following affected blades that use HSBe2:

    • B4300
    • B2100
  • You are transmitting large volumes of data.
  • The data is passing internally between the client and the server between two TMMs over HSBe2.

The HSB of the sending TMM changes the TCP checksum from 0xfffe to 0xffff. As a result, the HSB of the receiving TMM treats the checksum as though it is bad and drops the packet.

Impact

Transmission of data may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H427293 on the Diagnostics > Identified > Low screen.
  • Data transfers may fail.
  • The 0xfffe TCP checksum changes to the 0xffff checksum when passing through HSBe2 to the server, which may cause excessive TCP checksum errors and retries.

Workaround

To work around this issue, you can configure the VIPRION system to use a software checksum instead of a hardware checksum. To do so, perform the following procedure:

Impact of workaround: You will experience a small performance impact when using software checksums.

Configuring a BIG-IP VIPRION system to use software checksums

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Configure TMM to use software-only checksums by entering the following command:

    Note: You also have the Hardware-enabled option for the tm.tcpudptxchecksum db key.

    modify sys db tm.tcpudptxchecksum value Software-only

  3. Save the change by typing the following command:

    save /sys config

Note: After upgrading to a later release that resolves this issue, you must re-enable hardware checksums. To do so, type the following command:

modify sys db tm.tcpudptxchecksum value Hardware-enabled

Note: When using vCMP, both the host and guests must be upgraded to a fixed version.
