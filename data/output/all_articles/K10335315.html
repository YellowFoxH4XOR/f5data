K10335315: APM does not record web applications trace when enabled

Type
Support Solution
Published
2019-11-04
Updated
2025-02-06
Status
Legacy Content
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP APM: 14.1.2
Source
https://my.f5.com/manage/s/article/K10335315

Description

When using K13384 to create a web applications trace no directories are created in /var/tmp/WebAppTrace/ and the trace is not recorded.

If you review /var/log/auditd/audit.log you will see the similar errors as below:

type=PATH msg=audit(2019-09-26T17:02:28UTC:281578): item=0 name="/var/tmp/WebAppTrace/" inode=131083 dev=fd:01 mode=040755 ouid=0 ogid=0 rdev=00:00 obj=system_u:object_r:initrc_tmp_t:s0 objtype=PARENT
type=AVC msg=audit(2019-09-26T17:02:28UTC:281579): avc:  denied  { write } for  pid=20080 comm="rewrite" name="WebAppTrace" dev="dm-1" ino=131083 scontext=system_u:system_r:rewrite_t:s0 tcontext=system_u:object_r:initrc_tmp_t:s0 tclass=dir


The name will equal "/var/tmp/WebAppTrace" you will see AVC error of denied.  This is an issue with the SELinux Policy on the device for these file paths.

Environment

  • BIG-IP APM
  • Performing a web applications trace following KB Article K13384
  • Web applications trace isn't working as expected


Cause

Unknown at time of publication
 

Recommended Actions

To resolve the issue please run the following command on the BigIP command line.

  • From Command line, (Advanced Shell),  Run
    • restorecon -Rv /var/tmp/WebAppTrace/
