Known Issue

The BIG-IP GTM 11.x system may be unable to monitor virtual servers on BIG-IP LTM 10.2.x systems.

This issue occurs when all of the following conditions are met:

  • BIG-IP GTM 11.x is monitoring the status of a BIG-IP LTM 10.2.x virtual server.
  • BIG-IP LTM 10.2.x that was being monitored was upgraded to 11.x, and then subsequently downgraded to 10.2.x.

When you upgrade a BIG-IP LTM system from 10.2.x to 11.x, the BIG-IP GTM system internally stores the BIG-IP LTM host name by using the partitioned name.

For example:

/Common/ltm_hostname

In this scenario, when the BIG-IP LTM system is downgraded to 10.2.x, the BIG-IP GTM system continues to refer to the remote host as /Common/ltm_hostname instead of the ltm_hostname non-partitioned name that BIG-IP LTM 10.2.x uses.

Impact

The BIG-IP LTM system cannot monitor virtual servers on downgraded BIG-IP systems.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP GTM system marks the virtual servers as down even though the BIG-IP LTM system shows the virtual servers as up.
  • The BIG-IP GTM virtual server status displays the reason for the non-availability as no reply from big3d: timed out, and includes the partitioned name with the full path name to the system.

    For example, type the following command:

    tmsh show gtm server <BIG-IP_LTM_HOST> virtual-servers

    In the previous example, <BIG-IP_LTM_HOST> is the host name that the virtual server is attached to. Portions of the output appear similar to the following example:

    ------------------------------------
    | Gtm::Virtual Server: f5_bigip_host
    ------------------------------------
    | Status
    | Availability : offline
    | State : enabled
    | Reason : Monitor /Common/bigip from /Common/ltm_hostname : no reply from big3d: timed out
    | Destination : 10.2.215.25:80

Workaround

To work around this issue, you can manually edit the bigip_gtm.conf file on the BIG-IP GTM host by changing the partitioned names to non-partitioned names. To do so, perform the following procedure:

Impact of workaround: The BIG-IP GTM system cannot respond to requests while restarting.

  1. Log in to the BIG-IP GTM command line as the root user.
  2. Use an editor, such as the vi editor, to edit the following file:

    /config/bigip_gtm.conf
  3. Find the server entry for the BIG-IP LTM system that your virtual server is associated with. For example, if your host name is f5_bigip_host, the entry would start with:

    gtm server /Common/f5_bigip_host {
  4. Within this entry, find the lines that begin with ltm-name. For example:

    ltm-name /Common/ltm.vs.name
  5. Remove the folder portion of the name so that it looks similar to the following example:

    ltm-name ltm.vs.name
  6. Save your changes and exit from the editor.
  7. Restart the BIG-IP GTM system by typing the following command:

    bigstart restart gtmd
