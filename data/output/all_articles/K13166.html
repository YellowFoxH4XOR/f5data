Issue

Old Behavior

The TCP stack for the Linux host on BIG-IP 9.2.0 through 9.4.2 has the net.ipv4.tcp_timestamp TCP timestamp option set to 0.

Setting the net.ipv4.tcp_timestamp parameter to 0 stops the Linux host from inserting a timestamp into the TCP header when traffic is passed through its TCP stack. This configuration prevents conflicting TCP timestamps sent by the Linux host and TMM since they are using different clock sources. When neighboring devices receive conflicting timestamps, the recipient may refuse to accept packets with a later timestamp, and as a result, stop responding to the BIG-IP system for up to 45 seconds.

TCP Timestamps is an option introduced in RFC1323: TCP Extensions for High Performance as part of a mechanism known as Protect Against Wrapped Sequence Numbers (PAWS). When enabled, it adds 12 bytes to the 20 bytes TCP header and is used to prevent retransmissions for segments already received. 

New Behavior

Beginning in BIG-IP 9.4.3, the TCP stack for the Linux host has the TCP timestamp option net.ipv4.tcp_timestamp set to 1. The Linux host now uses TMM clock source when sending the initial SYN packet and utilizes the constant offset derived from the two different clock sources for subsequent packets.

F5 Product Development tracked this change as ID 282349 (formerly CR80268).
