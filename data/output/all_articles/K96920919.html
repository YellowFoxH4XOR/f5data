Description
When upgrading from a version prior to 14.1.x, where httpd allow was configured with any text in the list, the configuration will fail to load.  This includes host names. 

This is an example of a bad configuration that you might see in the /config/bigip_base.conf file

sys httpd {
    allow { 192.168.122.2 www.google.com }
    auth-pam-idle-timeout 123456789
}

This is a valid configuration:

sys httpd {
    allow { 192.168.122.2 }
    auth-pam-idle-timeout 123456789
}


Possible errors that you might see are:

  • tmsh load sys config
    ...snip...
    [9423]: syntax check command FAILURE for unix_config_httpd returned: '256'
     
  • STDERR/STDOUT text begins
    AH00526: Syntax error on line 199 of /var/run/config/httpd.conf:
    ip address 'and' appears to be invalid
     
  • tmsh modify sys httpd allow replace-all-with { www.google.com }
    01070920:3: Application error for confpp: AH00526: Syntax error on line 202 of /var/run/config/httpd.conf:
    ip address 'www.google.com' appears to be invalid

Environment

  • BIG-IP 14.1.x - 15.x
  • Upgrading from BIG-IP 14.1.0 or earlier.

Cause
Beginning in Apache 2.4 you can't use host names with "Require ip". Instead you have to use a "Require host" line within the httpd.conf file where we place the input from tmsh modify sys httpd allow.
Placing text into httpd allow will cause a load failure for unix_config_httpd or application error for confpp

Recommended Actions

  1. Avoid using any text in the httpd allow list and instead use only IP address. If you MUST use host names you might be able to modify the httpd.conf file directly and place a line "require host <hostname>".  However, this is not recommended as you would have to make that modification after every configuration load, reboot or upgrade.

Additional Information
This issue and change is tracked in ID844645. Once this ID is fixed then this document no longer applies.
