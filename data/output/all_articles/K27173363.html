Description

  • Customer would like to help users to logon to BIG-IP APM by pre-populating the Logon Page "username" field with a username, but he wants the user to be able to change the username if needed. The username is supplied as part of the URI.
  • Currently pre-populating of the "username" field in the Logon Page is only possible in "Read-Only" mode.

Environment

  • BIG-IP APM
  • Logon Page customization

Cause

The code for the Logon Page VPE object enforces that the "username" field can only be pre-populated if the field is in read-only mode.
 Recommended Actions

Use customization to change the Logon page behaviour.

For Customization Type "Standard":

  1. Log on to the Configuration utility.
  2. Select Access Policy  ››  Customization : Advanced
  3. Change "Edit Mode" to "Advanced"
  4. Navigate to Customization Settings | Access Profiles | <AP_Name> | Access Policy | Logon Pages | <Logon_Page_name> | logon.inc
  5. Below "$formHeader = '%[form_header]';" (around line 32, varies between BIG-IP versions) insert the following lines:
        if ( "username" == $fields_settings[$i]["name"]) {
            $fields_settings[$i]["value"] = '%{session.logon.last.'.$fields_settings[$i]["varname"].'}';
        }
  6. Click on "Save Draft" (top of the input window)
  7. Click on "Save" icon (top menu bar)
     

For Customization Type "Modern":

  1. Log on to the Configuration utility.
  2. Select Access Policy  ››  Customization : Advanced
  3. Change "Edit Mode" to "Advanced"
  4. Navigate to Customization Settings | Access Profiles | <AP_Name> | Access Policy | Logon Pages | <Logon_Page_name> | user-logon.js
  5. Enter the code below:

You will also have to make sure that the system variable "session.logon.last.username" contains the desired value before the VPE object "Logon Page" is reached. For example, this can be achieved with an iRule:

 when ACCESS_POLICY_AGENT_EVENT {
     if { [ACCESS::policy agent_id] eq "GetUsername" } {
        ACCESS::session data set session.logon.last.username [URI::decode [URI::query [ACCESS::session data get session.server.landinguri] username]]
     }
 }
