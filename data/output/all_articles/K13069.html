Known Issue

If you use the Configuration utility to update an existing cookie persistence profile, the timeout setting is removed from the profile. As a result, the cookie persistence profile reverts to the default timeout of 180 seconds. This issue occurs when all of the following conditions are met:

  • The affected cookie persistence profile is configured to use HTTP Cookie Insert, HTTP Cookie Passive or HTTP Cookie Rewrite as its cookie method
  • The affected cookie persistence profile has its timeout setting explicitly configured using the bigpipe or tmsh command
  • The affected cookie persistence profile is updated using the Configuration utility after the above two conditions are met

By default, there is no requirement to configure the timeout setting if the cookie persistence profile is using the following cookie method:

  • HTTP Cookie Insert
  • HTTP Cookie Passive
  • HTTP Cookie Rewrite

Due to a known issue with the persist cookie insert and persist cookie rewrite iRule commands failing to set session cookies, you may need to configure the timeout setting to the value of 0 (zero) or immediate. For more information, refer to K11679: The ‘persist cookie insert’ and ‘persist cookie rewrite’ iRule commands fail to set session cookies.

Impact

The cookie persistence profile reverts to the default timeout of 180 seconds.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380443 on the Diagnostics > Identified > Low screen.
  • The timeout setting is missing from the affected cookie persistence profile in the running configuration and the /config/bigip.conf file. For example, if you configure the cookie persistence profile mycookie with the timeout set to immediate, the persistence profile will appear similar to the following example in the command line:

    profile persist mycookie {
    defaults from cookie
    mode cookie
    timeout immediate
    }

    When the issue described in this Solution occurs, the timeout immediate line is removed from the mycookie cookie persistence profile:

    profile persist mycookie {
    defaults from cookie
    mode cookie
    }

  • The persist cookie insert and persist cookie rewrite iRule commands, which reference the affected cookie persistence profile, will use a 180-second timeout instead of an immediate timeout. As a result, sessions may not persist as expected. For more information, refer to K11679: The ‘persist cookie insert’ and ‘persist cookie rewrite’ iRule commands fail to set session cookies.

Workaround

You can work around this issue by reconfiguring the timeout setting to immediate using the tmsh utility. To do so, type the following command:

tmsh modify ltm persistence cookie <cookie profile> timeout 0

In this command, note the following:

  • <cookie profile> is the name of the affected cookie persistence profile.
