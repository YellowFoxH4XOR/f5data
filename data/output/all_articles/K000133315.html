Description

Configure the vlan failsafe, and then the interface down, but the failover event happen before the timeout reached.
For exmple, timeout value is 10 seconds, but the failover happen in 6 seconds.
list /net vlan
net vlan internal {
    failsafe enabled
    failsafe-action failover
    failsafe-timeout 10
    interfaces {
        1.1 { }
    }
    tag 4093
}
The example LTM log when the interface down:
Mar 10 21:37:36 bigip1.example.com info bcm56xxd[<PID>]: 012c0015:6: Link: 1.1 is DOWN
Mar 10 21:37:42 bigip1.example.com warning sod[<PID>]: 01140029:4: HA vlan_fs /Common/vlan_internal fails action is failover.
Mar 10 21:37:42 bigip1.example.com notice sod[<PID>]: 010c005c:5: Failover condition reported by bigip1.example.com for traffic group traffic-group-1, it will not be able to go active.
Mar 10 21:37:42 bigip1.example.com notice sod[<PID>]: 010c0052:5: Standby for traffic group traffic-group-1.
Mar 10 21:37:42 bigip1.example.com notice sod[<PID>]: 010c0018:5: Standby

Environment

  • BIG-IP
  • Vlan failsafe

Cause

It maybe expected result, it is depending on the traffic on the vlan.

 Recommended Actions

Refer to the article K13297: Overview of VLAN failsafe, by default, failover.vlanfailsafe.resettimeronanyframe is disabled, the possible history is (refer to the example in the description):
At Mar 10 21:37:32, BIG-IP receive the last ARP / NDP frame on the interface 1.1.
At Mar 10 21:37:36, interface 1.1 is down.
At Mar 10 21:37:37, BG-IP cannot receive the ARP / NDP frame, as interface 1.1 was down.
At Mar 10 21:37:39, BG-IP cannot receive the ARP / NDP / multicast frame, as interface 1.1 was down.
At Mar 10 21:37:42, VLAN failsafe action was performed.
If we need to verify it, we need to capture the traffic, review the frame on the interface / vlan.
The possible solutions:
  1. Follow K13297: Overview of VLAN failsafe, enable failover.vlanfailsafe.resettimeronanyframe will mitigate the issue.

Additional Information

If BIG-IP cannot receive any traffic on the vlan, even the interface is up, it may trigger the VLAN failsaft event too.
