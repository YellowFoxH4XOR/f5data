Topic

This article applies to BIG-IP 9.x through 11.x. For information about other versions, refer to the following article:

  • K13002225: Providing diagnostic core files to F5 Support (12.x and later)

Important: Forcing the BIG-IP system to process a core file interrupts service and may cause failover or system instability. Produce a core file only when F5 Support requests that you do so.

Review the amount of available disk space on your system before you force a core file. If there is not enough disk space to contain a core file, you risk causing system instability and producing a truncated and useless core file. For information about maintaining disk space on the BIG-IP system, refer to the following articles:

  • K14403: Maintaining disk space on the BIG-IP system
  • K12263: Maintaining disk space on the BIG-IP system (9.x - 10.x)

In the event of a system lock-up, the watchdog process ensures that the BIG-IP system restarts and fails over. If you are forcing the BIG-IP system to produce a core file for diagnostic purposes, you must disable the watchdog process to allow the core file to write to disk before the system restarts. For steps to disable the watchdog process, refer to the following articles:

  • K13539: Disabling the watchdog process to perform a core dump (11.x - 15.x)
  • K9308: Disabling the watchdog process to perform a core dump (9.3.0 - 10.x)

Forcing the TMM process to produce a core file

Most BIG-IP platforms are enabled with Clustered Multiprocessing (CMP) and run multiple Traffic Management Microkernel (TMM) instances. You can collect TMM diagnostics core files from all TMM instances (systems that run a single instance or multiple instances of tmm). To do so, enter the following command:

Note: When producing a diagnostic core on a multi-blade system, you may wish to produce cores on all blades simultaneously. This can be done by using the clsh command to run the killall command across all blades: clsh killall -v -s 6 tmm

killall -v -s 6 tmm

Note: On platforms with large memory capacity, if you enter the killall command, the system responds slowly while it writes several gigabytes of data to the disk, and then compresses the core files. This process may take several minutes to complete. After compressing the core files, the unit returns to normal operation and restarts the TMMs.

Important: When you run the kill command to produce a core file using a daemon, remember that if the daemon is in the middle of a task that cannot be interrupted, the daemon may ignore the kill command.

Forcing other BIG-IP processes to produce a core file

You can use the kill command to produce a core file from individual processes. For most processes or daemons that run on a BIG-IP system, you can use the kill command with an associated flag of -6 (-SIGABRT) or -11 (-SIGSEGV) to produce a core file.

  1. To find the process identification (PID) number for a specific daemon, use the grep command.

    For example, for the bigd process, enter one of the following commands:

    For BIG-IP 10.x and later:

    ps ax | grep bigd

    The output appears similar to the following example:

    5780 ? S 0:00 runsv bigd
    5789 ? S 22:18 /usr/bin/bigd
    14367 pts/0 S+ 0:00 grep bigd

    Note: When you select a PID for a process, exclude processes preceded with runsv running the kill command , as these processes do not produce a usable core file.

    For BIG-IP 9.x and earlier:

    ps -ax |grep bigd

  2. To force the process to produce a core file, use the following command syntax:

    kill -6 <pid of that process>

    For example, to force the bigd process to produce a core file, enter the following command:

    kill -6 5789

If you force a process that uses a significant amount of memory to produce a core file, it may take the system several minutes to write the core file. The core files are located in the /shared/core directory.
