Known Issue

This is the result of a known issue. The bigpipe load and tmsh load sys config commands fail when a pool member contains the following service numbers: 63, 66, 172, 211, 564, 629. For example, the following bigpipe pool command creates a pool member using service number 172:

bigpipe pool bogus { member 10.0.0.10:172 }

If you save the above configuration using the bigpipe save command and list the pool configuration using the bigpipe pool list command, the following configuration displays:

pool bogus {
   members 10.0.0.10:cl/1 {}
}

If you then run the bigpipe load command to load the BIG-IP configuration, the bigpipe utility displays a parsing error message that appears similar to the following example:

BIGpipe parsing error (/config/bigip.conf Line 759):
   012e0022:3: The requested value (10.0.0.10:cl/1 {) is invalid (show | <pool member list> | none) [add | delete]) for 'members' in 'pool

A similarly configured pool member created with tmsh commands will result in the same failure. However, the tmsh error message will appear similar to the following example:

Syntax Error:(at line: 68) "/Common/10.10.10.1:cl/1" port is missing, address is ""

Note: In BIG-IP 11.x, the tmsh list /ltm pool members command output will not result in an error message, but it may contain bogus characters in the port number field (10.10.10.1:cl/1).

F5 Product Development is tracking this issue as ID 291782 (formerly CR132482).

Workaround

You can work around this issue using either the Traffic Management Shell (tmsh) or the bigpipe utility.

Preventing the tmsh utility from converting service numbers (11.x)

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Disable automatic service name translation by typing the following command:

    modify sys db bigpipe.displayservicenames value false
  3. Save the configuration to overwrite the service names in the bigip.conf file with numeric port values by typing the following command:

    save sys config

Preventing the bigpipe utility from converting service numbers (9.x - 10.x)

  1. Log in to the BIG-IP command line.
  2. Disable automatic service name translation by typing the following command:

    bigpipe db Bigpipe.DisplayServiceNames false
  3. Save the configuration to overwrite the service names in the bigip.conf file with numeric port values by typing the following command:

    bigpipe save
