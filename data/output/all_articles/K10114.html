K10114: Testing whether the ARX proxy user has permissions to access a back-end Samba share

Topic

To test whether the proxy user you defined for a namespace has the necessary file and share permissions to access a back-end Samba share, access the Samba share directly (bypassing the ARX system) using the proxy user account. When accessing the share, ensure that the proxy user can perform a directory listing. If the proxy user also has write permissions, ensure that the proxy user can create a test file or directory on the share.

Most Samba distributions include the Samba client utility, smbclient. You can run this utility on the back-end Samba server to connect to the share directly.
 
The proxy user is root, the root password is pass123, and the Samba share name is share1 in the following output, which was taken from a Linux server running Samba 3.0.33:
 
# smbclient //127.0.0.1/share1 -U root%'pass123'
Domain=[WIN2003] OS=[Unix] Server=[Samba 3.0.33-3.7.el5]
smb: \> dir
 .                                   D        0 Thu Mar 26 19:46:24 2009
 ..                                  D        0 Thu Mar 26 21:16:13 2009
 file2.txt                                   15 Thu Mar 26 19:46:10 2009
 file1.txt                                   15 Thu Mar 26 19:46:04 2009
 file3.txt                                   15 Thu Mar 26 19:46:24 2009
 
               38312 blocks of size 262144. 26788 blocks available
smb: \> mkdir test
smb: \> dir
 .                                   D        0 Tue Apr 21 22:40:27 2009
 ..                                  D        0 Thu Mar 26 21:16:13 2009
 file2.txt                                   15 Thu Mar 26 19:46:10 2009
 file1.txt                                   15 Thu Mar 26 19:46:04 2009
 file3.txt                                   15 Thu Mar 26 19:46:24 2009
 test                                D        0 Tue Apr 21 22:40:27 2009
 
                38312 blocks of size 262144. 26788 blocks available
smb: \> quit
#
 
As shown in the example, the directory test was successfully created. Therefore, the proxy user root has write access to the Samba share share1.
 
To view all shares available to the proxy user, run smbclient with the -L flag. For example:
 
# smbclient -L 127.0.0.1 -U root%'pass123'

Output will appear similar to the following example:
 
Domain=[WIN2003] OS=[Unix] Server=[Samba 3.0.33-3.7.el5]

Note: For more information about smbclient, refer to your vendor documentation or the man page for smbclient.
