K000162160: HTTP/2 connections might be reset with GOAWAY (PROTOCOL_ERROR) when client initial SETTINGS is empty

Type
Support Solution
Published
2026-07-13
Updated
2026-07-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 21.1.0
Source
https://my.f5.com/manage/s/article/K000162160

Description

HTTP/2 session establishment fails on the connection preface if the HTTP/2 client includes an empty SETTINGS frame. It can be seen that the BIG-IP responds with a GOAWAY frame and PROTOCOL_ERROR.

Empty SETTINGS behaviour is not common among HTTP/2 clients, and for this reason, it is possible that this issue is only seen on a small subset of clients. Nevertheless, this behaviour is compliant with RFC 9113 - 3.4. HTTP/2 Connection Preface.

Environment

Product: BIG-IP LTM

Version: 21.1.0

Feature: HTTP/2

HTTP/2 client using empty SETTINGS

Cause

This is a consequence of Bug ID 2388333.

To begin the analysis, a packet capture should be taken and decrypted. Please, follow the guidelines described on K31793632: Creating a decrypted tcpdump capture without using an iRule.

While reviewing the decrypted packet capture, look for the client SETTINGS frame, it will be empty.

HyperText Transfer Protocol 2
    Stream: Magic
        Magic: PRI * HTTP/2.0\r\n\r\nSM\r\n\r\n
HyperText Transfer Protocol 2
    Stream: SETTINGS, Stream ID: 0, Length 0
        Length: 0
        Type: SETTINGS (4)
        Flags: 0x00
            0000 000. = Unused: 0x00
            .... ...0 = ACK: False
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0000 = Stream Identifier: 0

After receiving this, and possibly other frames (as WINDOW_UPDATE or SETTINGS ACK) from the client, the BIG-IP responds with a SETTINGS ACK and GOAWAY (PROTOCOL_ERROR) as follows.

HyperText Transfer Protocol 2
    Stream: SETTINGS, Stream ID: 0, Length 0
        Length: 0
        Type: SETTINGS (4)
        Flags: 0x01, ACK
            0000 000. = Unused: 0x00
            .... ...1 = ACK: True
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0000 = Stream Identifier: 0
HyperText Transfer Protocol 2
    Stream: GOAWAY, Stream ID: 0, Length 8
        Length: 8
        Type: GOAWAY (7)                    # <<------------
        Flags: 0x00
            0000 0000 = Unused: 0x00
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0000 = Stream Identifier: 0
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0000 = Last-Stream-ID: 0
        Error: PROTOCOL_ERROR (1)           # <<------------

The BIG-IP will subsequently close the connection sending a TCP FIN; the client will possibly do the same and also include a TLS Alert of Close Notify.
