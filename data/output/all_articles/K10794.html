Known Issue

This is the result of a known issue. When the BIG-IP WebAccelerator receives a response from the origin web server containing a Content-Length header with a value of zero and no message body, the system does not send the response to the client.

Note: This issue is known to occur when the Assembly on Proxies feature is disabled in the policy.

F5 Product Development tracked this issue as CR115553 and it was fixed in BIG-IP WebAccelerator version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3, which has been issued for BIG-IP WebAccelerator version 10.0.1, for the 10.0 software branch. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing 10.x hotfixes, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You may work around this issue by enabling the Assembly on Proxies feature in the relevant policy. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. In the navigation pane, expand WebAccelerator.
  3. Click Policies.
  4. On the User-defined Acceleration Policies table, click the name of the acceleration policy that you want to edit.
  5. On the Policy Tree, click the node for which you want to enable the content assembly on proxies feature.
  6. From the Matching Rules list on the Policy Editor menu bar, select Acceleration Rules.
  7. On the Policy Editor menu bar, click Assembly.
  8. Select the Enable Content Assembly on Proxies check box.
  9. Click the Save button.
