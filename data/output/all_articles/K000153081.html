Description

Tenant does not boot up healthy, and F5OS-A repeats to try booting it.

k3s_events.log shows errors similar to below:

2025-07-02 01:13:34.690326 - 8:140412857599744 - Event Updated: Pod/virt-launcher-ep0tsd01-1-tjq8s UID: ebe433ef-3840-4f9a-9fc0-66224f703c40 UPDATE TIME: 2025-07-02T01:13:30Z CREATION TIME: 2025-07-02T01:12:33Z OLD_TYPE: Normal NEW_TYPE: Warning OLD_REASON: Started NEW_REASON: Unhealthy OLD_LOG: Started container compute NEW_LOG: Liveness probe failed: building SEP devices

platform.log in F5OS-A shows errors similar to below:

2025-07-02T10:12:39.109254+09:00 ep0tsd01 dma-agent[16]: priority="Err" version=1.0 msgid=0x4201000000000094 msg="Error mapping SEP file. Unlinking. Disconnecting client.".

Running the following command shows one file in DEL state.

lsof -p $(pidof fpgamgr) |grep huge

Output is similar to below. The /var/huge_pages/2048kB/l2_learn/l2_learn.seg file is in DEL state.

[root@appliance-1 ~]# lsof -p $(pidof fpgamgr) |grep huge
fpgamgr 15062 root  mem       REG   0,40   2097152  262806 /var/huge_pages/2048kB/l2_learn/sep0
fpgamgr 15062 root  mem       REG   0,40   2097152  262807 /var/huge_pages/2048kB/l2_learn/sep1
fpgamgr 15062 root  DEL       REG   0,40            247322 /var/huge_pages/2048kB/l2_learn/l2_learn.seg   # <--!!!
fpgamgr 15062 root  mem       REG   0,40 134217728  247324 /var/huge_pages/2048kB/l2_learn/l2_learn.seg

Environment

  • rSeries appliance (F5OS-A)
  • VELOS (F5OS-C)

Cause

ID 1578553

Recommended Actions

Performing one of the following allows the system to boot the tenant.

  • Reboot the whole device, as it's supposed to release the stale memory segment taken by the file descriptor in DEL state.
  • Upgrade to the version with the fix for ID 1578553.
  • Reduce the tenant's memory assignment by 128 MB (for example, from 230304 MB to 230176 MB on R10900)

Additional Information

Due to ID 1578553, there may be one file descriptor taking up an additional 64 hugepages (128 MB). Therefore, a short-term solution/workaround until the upgrade may be to reduce the tenant's memory assignment slightly by 128 MB if a reboot does not reliably resolve the issue.
