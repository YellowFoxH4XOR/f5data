Description

Observing multiple false positive ASM violations for requests similar to the following:

POST /Device/Enrol HTTP/1.1
Host: example.com
Content-Type: application/pkcs7-signature
Connection: keep-alive
Accept: */*
User-Agent: Main/1.0
Content-Length: 3673
Accept-Language: en-us

Note: The Content-Type is application/pkcs7-signature.

The violations appear to be false positives.

Environment

  • Security policy
  • Event logs

Cause

Requests utilising the application/pkcs7* media type are expected to contain binary content in the payload

Binary content cannot be parsed by ASM, and if it tries to parse it, many false positive violations are likely to occur.

Recommended Actions

Configure ASM to prevent requests with binary content from being parsed.

The simplest way to do this is to add an Allowed URL to the policy, and add a rule to Header-Based content profile handling as follows:

Request Header Name: Content-Type
Request Header Value: *pkcs7*
Request Body Handling: Do nothing
