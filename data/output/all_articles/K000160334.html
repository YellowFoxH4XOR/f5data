K000160334: Controller Replacement and OpenShift Cluster Rebuild Readiness on F5OS VELOS

Description

After a controller replacement via RMA, the OpenShift cluster did not rebuild correctly. The cluster status showed "NOT initialized" with blades appearing to be stuck in "being added to the openshift cluster" state. Log messages indicated failures such as "Failed to set cluster-initialized entry" and "CC is not longer active, aborting" during the rebuild process. The issue was caused by initiating a manual controller failover before the OpenShift cluster rebuild process had fully completed.

Environment

  • Product: F5OS (F5 VELOS)
  • Configuration: Multi-blade chassis with redundant controllers
  • Scenario: Controller replacement via RMA, OpenShift cluster rebuild, manual controller failover during rebuild

Cause

Manual controller failover was initiated before the OpenShift cluster rebuild process had fully completed. This interrupted the cluster initialization, causing the new active controller to trigger a full cluster reinstall, significantly extending recovery time (90+ minutes).

Answer/Recommended Actions

Recommended Controller Readiness Checks Before Manual Failover:

  1. Check Cluster Initialization Status
    Run: show cluster
    Confirm:
    • cluster orchestration-manager cluster-initialized is true
    • cluster orchestration-manager cluster-ready is true
    • All stages show STATUS: Done
  2. Monitor OpenShift Cluster Status
    Run: tail -f /var/log/openshift.log
    Ensure:
    • All blades/controllers are reported as added and healthy
    • No active ansible-playbook executions
    • Messages such as InstallProgress: Execution for play book [name] is Done
    • No "InProgress" messages
  3. Verify Controller Connectivity
    Run: show cluster cluster-status
    Both controllers should be:
    • All controllers show STATUS: Ready
    • Pingable and accessible via SSH
    • Message: "Openshift cluster is healthy, and all controllers and blades are ready"
  4. Check for Completion Markers
    Run: ls -la /var/omd/
    The CLUSTER_INSTALLED file should exist
  5. Check System Redundancy Details
    Run: show system redundancy-details state hardware
    Confirm both controllers are healthy and peer is healthy

Additional Information

  • Initiating a manual controller failover before the cluster is fully initialized can cause a full cluster reinstall, which is expected to take 90+ minutes.
  • There is currently no single command that explicitly states when it is safe to fail over; the above checks should be used in combination.
  • This behavior is expected if the failover is performed prematurely.
