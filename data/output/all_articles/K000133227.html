K000133227: DNS::is_wideip output may mis-lead if the DNS query type is not correctly filtered.

Type
Support Solution
Published
2023-03-28
Updated
2026-07-17
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP DNS: 15.1.8
Source
https://my.f5.com/manage/s/article/K000133227

Description

  • Using the DNS::is_wideip in the irule to log if the request is for a wideip.
  • Drop the request if it is not for a wide-ip existing on the box.
  • irule configured exactly as shown in the article: https://clouddocs.f5.com/api/irules/DNS__is_wideip.html and modified to log as shown below:

when DNS_REQUEST priority {

   if {![DNS::is_wideip [DNS::question name]]} {

        log local0. "[DNS::question name] is NOT wideIP"

        DNS::drop

        return

    } else {

             log local0. "[DNS::question name] is a wideIP"

             return

            }

}

 

Environment

  • GTM/DNS configured with wide-ip
  • Customer wants to drop all the queries for non-existent wide-ip's.
  • The irule is intermittently logging the existent wide-ip as "not wide-ip" as shown below:
  • WIde-IPs are configured for A record only.

Mar 28 01:09:51 test.local info tmm1[30300]: Rule /Common/wide_or_not <DNS_REQUEST>: the dns question name is test1.rest.com

Mar 28 01:09:51 test.local info tmm1[30300]: Rule /Common/wide_or_not <DNS_REQUEST>: test1.rest.com is a wideIP

Mar 28 01:26:05 test.local info tmm3[30300]: Rule /Common/wide_or_not <DNS_REQUEST>: the dns question name is test1.rest.com

Mar 28 01:26:05 test.local info tmm3[30300]: Rule /Common/wide_or_not <DNS_REQUEST>: test1.rest.com is NOT wideIP

 

 

Cause

The irule doesnt take into account the DNS Questions::type. So if client are sending the DNS query for A record type, the irule will work fine, however, if the type is changed anything other than A, the irule will log as "NOT wideip".

 

This might mislead the reader of the logs to believe that the irule is failing to detect the wideip.

 

 

 Recommended Actions

  1. A better way to re-write this irule would be to first check if the DNS question type is A or not. Only proceed if the record type is A (note this is just an example, you may need to change the syntax to suit your environment).

when DNS_REQUEST priority {

log local0. "the dns question name is [DNS::question name] and type: [DNS::question type]"

 if { [DNS::question type] eq "A"} {

      log local0. "The DNS questions type is [DNS::question type] check if this is a wide-ip or not"

         if {![DNS::is_wideip [DNS::question name]]} {

               log local0. "[DNS::question name] is NOT wideIP"

               DNS::drop

               return

            } else {

                     log local0. "[DNS::question name] is a wideIP with a valid [DNS::question type] record "

                     return

                    }

    }

    log local0. "The DNS questions type is [DNS::question type] and is not allowed"

    DNS::drop

    return

}

 

 

In this irule, we are checking if the DNS question type is A, if yes, only then proceeds to check if this is a request for wide-ip or not.
