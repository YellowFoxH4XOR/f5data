Known Issue

A TCP profile may allow a non-SYN packet to create a new connection flow after sending a TCP RST (reset) to the client.

This issue occurs when all of the following conditions are met:

  • You are using one of the following platforms that have hardware SYN cookie protection enabled by default:

    • BIG-IP appliances: BIG-IP 5000 series, 7000 series, 10000 series, and 12000 series
    • BIG-IP VIPRION blades: B2000 series, and B4300
  • You have configured your virtual server to use a TCP profile.

Impact

A new connection flow may be created after the RST is sent to the client.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TCP profile allows a non-SYN packet to create a new connflow after the RST is sent to the client.
  • In the /var/log/ltm file, you notice error messages similar to the following example:

    tmm1[<pid>]: 01070417:6: ICSA: non-session TCP packet rejected, source: 10.10.10.10 port 43784, destination: 10.10.10.101 port:5060

Workaround

To work around this issue, you can modify the BIG-IP system database variable. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure may cause slightly higher CPU usage, as the SYN cookie algorithm is performed by the Traffic Management Microkernel (TMM).

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the connection.syncookies.algorithm database variable, type the following command:

    modify /sys db connection.syncookies.algorithm value software

  3. Save the configuration change by typing the following command:

    save /sys config
