K000152838: ASM Event Logs may fail to load intermittently due to async handler recycling

Description

ASM Event log loading is intermittently delayed, with requests queuing for up to a minute before completion, occasionally fail to load.


Environment

  • BIG-IP ASM
  • Accessing ASM Event Logs via GUI


Cause

The delays are due to the design of ASM async handler processes. When a handler reaches a threshold (number of calls or memory usage), it is shut down to maintain system stability. Pending tasks are reassigned to another handler, causing intermittent delays during the handover.


Key points:


  • Async handlers are automatically shut down after processing a certain number of requests or reaching memory thresholds to maintain system stability.
  • When shut down, any pending tasks in their queue are saved to disk and later reassigned to other handlers.
  • Delays occur during this handover period, as new or existing handlers reload and process the saved queues.
  • The delay is not due to resource exhaustion, but a by-design handoff mechanism for task reassignment.


Recommended Actions

No specific corrective action is required. The system is functioning as designed.


However, to reduce the frequency or visibility of the delays:

  1. Regularly review and clear unnecessary learning suggestions.
  2. Avoid excessive filtering or querying in the Event Logs page, especially if the system is already handling a high background load.


Additional Information

While this mechanism can introduce minor delays, it is essential to maintain system stability. The presence of learning suggestions or large policies does not directly cause the behavior but may contribute to the overall async processing load.
