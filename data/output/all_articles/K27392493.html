Description

ASM can flag requests with Illegal parameter data type violation for parameters that are configured with Data Type set to 'Email' within the policy.

Environment

  • BIG-IP ASM provisioned
  • Policy consisting of a parameter configured with Data Type set to 'Email'.
  • Alarm and/or Block setting enabled for Illegal parameter data type violation
  • ecard_regexp_email System Variable using default configuration value
  • Software versions: 11.x - 16.x

Cause

The current default email parameter Regular Expression (regex) built into ASM via System Variable ecard_regexp_email will fire an Illegal parameter data type violation when encountering a parameter, within the HTTP request, that's configured in the policy with Data Type set to 'Email' and having a value in the request consisting of one of the special characters defined in RFC3696 section #3.

RFC3696 doesn't forbid or mention any restriction on using the above special characters and ASM should not block them when parameter data type is set to 'Email'.  F5 Product Engineering team is tracking this as a known issue at ID 635286.

Recommended Actions

You can go through the following steps to workaround this false positive violation:

  1. Change the regular expression for System variable ecard_regexp_email to the following value so that it conforms to RFC3696:

    ^\s*[\w!#$%&'*+/=?^_`{|}~-]+(?:\.[\w!#$%&'*+/=?^_`{|}~-]+)*@([\w.-]+)\s*$

  2. Restart ASM process to ensure the changes get pushed out to the policy using the following command:

    bigstart restart asm
