Known Issue

This is the result of a known issue. The MultiConnect feature does not operate as expected when applied to a virtual server referencing an NTLM profile. When the MultiConnect feature is enabled in the WebAccelerator policy and an NTLM profile is associated with the WebAccelerator virtual server, the BIG-IP WebAccelerator system creates separate server-side connections for MultiConnect-eligible requests. As a result, the origin web server (OWS) sends additional HTTP 401 (Unauthorized) responses and potentially sends extra authentication prompts.

Note: The MultiConnect feature is designed to achieve faster downloads for certain traffic by modifying embedded URLs with unique subdomains and prompting the client to open more persistent TCP connections to the BIG-IP WebAccelerator system. The OWS never gets a request for these additional subdomains. For more information about the MultiConnect feature, refer to the Policy Management Guide for the BIG-IP WebAccelerator System.

F5 Product Development is tracking this issue as ID 291797.

Workaround

You can work around this issue by disabling the MultiConnect feature for virtual servers referencing an NTLM profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. In the navigation pane, expand WebAccelerator and click Policies.

    The Policies screen displays a list of existing acceleration policies.
  3. Click the appropriate acceleration policy.
  4. On the Policy Tree, click the node for which you want to disable the MultiConnect feature.
  5. Select Acceleration Rules from the drop-down menu.
  6. Click the Assembly tab.
  7. Clear the Enable MultiConnect check box.
  8. Click Save.
