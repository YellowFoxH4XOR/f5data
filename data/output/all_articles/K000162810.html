K000162810: AS3 rejects CIS-generated LTM monitor declarations with timeout: should be <= 900

Type
Support Solution
Published
2026-08-06
Updated
2026-08-06
Source
https://my.f5.com/manage/s/article/K000162810

Description

F5 Container Ingress Services declarations fail during AS3 submission with HTTP 422 when an BIG-IP LTM monitor uses a timeout value greater than 900 seconds.

Example error:

code: 422

message: declaration is invalid

errors: [timeout: should be <= 900]

The same monitor values can be accepted through the BIG-IP web interface and tmsh.

Environment

  • F5 Container Ingress Services configuring BIG-IP through AS3.
  • BIG-IP LTM HTTP or HTTPS monitors defined in VirtualServer declarations.
  • Monitor declarations with timeout values greater than 900 seconds.
  • BIG-IP LTM supports monitor interval and timeout values from 1 through 86400 seconds.

Cause

AS3 schema validation incorrectly limited LTM monitor timeout values to 900 seconds. This limit did not match the BIG-IP-supported maximum of 86400 seconds.

The issue is tracked under Bug ID 2366069, which corrected the validation ranges for LTM monitor interval and timeout parameters.

Recommended Actions

  1. Upgrade AS3 to a release 3.58.0.
  2. Reapply the affected VirtualServer declaration.
  3. Confirm that the AS3 declaration is accepted and the monitor is created successfully.
  4. Keep LTM monitor interval and timeout values within the BIG-IP-supported range of 1 through 86400 seconds.
  5. If AS3 cannot be upgraded, use a timeout value of 900 seconds or less to avoid the affected schema-validation error.
  6. Configure monitor values according to the recommended interval-to-timeout relationship.

Additional Information

The 900-second restriction was imposed by AS3 schema validation and was not a BIG-IP LTM monitor limitation. Values greater than 86400 seconds remain invalid.
