K000150564: RRsets are limited to 100 records of the same type after 17.1.2

Support Solution
Published

Applies to

Description

DNS resolution issues were observed after upgrading to BIG-IP GTM version 17.1.2.1. Symptoms included empty DNS responses with is_wideip=0, SERVFAIL replies, and errors in the logs such as:

 

error: dns_master_load: db.external.example.f5.com.:378: record1.example.f5.com.: too many records 

zoneload: error: zone example.f5.com/IN/external: loading from master file db.example.f5.com. failed: too many records 

zoneload: error: zone example.f5.com/IN/external: not loaded due to errors.

 

Additionally, journal logs indicated that zones containing RRsets with a single owner name exceeding 100 records of the same type were not being loaded.

Environment

DNS

Zonefiles

Cause

Upgrading to 17.1.2 or higher will update the BIND version from 9.16.48 to 9.18.28. The root cause was identified as a change in behavior introduced by BIND version 9.18.x, which enforces a default limit of 100 records for RRsets where a single owner name has more than 100 records of the same type.

Recommended Actions

To resolve the issue caused by exceeding the default record limit in BIND, update the max-records-per-type parameter in the named configuration file to accommodate your environment's requirements:

1.Log in to the BIG-IP GUI.

2. Navigate to DNS → Zones → Zonerunner → Named Configuration.

3. Locate the options section and add or modify the following line:

   max-records-per-type <desired_limit>;

      Example:

   max-records-per-type 200;

4. Click on Update to save changes.

5. This adjustment increases the maximum allowable number of records per RRset and ensures zones are properly loaded.

Additional Information

Verify wide-IP configurations and ensure proper handling of DNS queries for unsupported record types (is_wideip=0).

Review changelogs for BIND upgrades and assess their impact on DNS query handling within your environment.
