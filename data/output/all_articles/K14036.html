Known Issue

The BIG-IP snmpd process may leak memory. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is polled for the number of members in a pool using the ltmPoolMemberCnt OID.

The SNMP OID ltmPoolMemberCnt returns the total number of members in each pool. The memory leak is in proportion to the number of members in a pool, the number of pools polled, as well as the frequency of the snmp poll. The larger the number of members and the more frequently the pools are polled, the faster the memory leak grows.

Impact

Over time, you may see the system performance degrade, and the system may eventually become unresponsive or reboot, due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP snmpd process memory allocation grows over time. You can monitor the memory usage for the BIG-IP snmpd process using the top utility. For example, using the top -p `pidof snmpd` command, you can observe from the following output that over time the snmpd process memory allocation grew from 17MB to 172MB:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    5195 root 20 0 29964 17m 7920 S 0.7 0.4 0:00.98 snmpd

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    5195 root 20 0 190m 172m 3720 S 0.0 4.3 1:14.55 snmpd

  • The system swap file usage may increase as the BIG-IP snmpd process memory allocation grows. You can monitor the system swap file usage using the top utility.
  • Due to excessive memory usage, the snmpd process may produce a core dump.
  • In the event of severe system memory exhaustion, the Linux kernel may restart the TMM process and log error messages to the /var/log/kern.log file that appear similar to the following example:

    kernel: Out of memory: kill process 13457 (tmm.start) score 42570 or a child
    kernel: Killed process 13631 (tmm) vsz:1814076kB, anon-rss:1048kB, file-rss:66152kB

Workaround

To work around this issue, you can restart the snmpd process at regular intervals outside of the polling intervals. To do so, perform one of the following procedures:

Impact of workaround: The BIG-IP system may not respond to snmp polls while the snmpd process is restarting.

You can use the following two options to restart snmpd:

  • Manually monitor snmpd memory usage and manually restart snmpd from the command line
  • Restart snmpd at a regular interval using the crontab utility

Manually monitor snmpd memory usage and restart snmpd from the command line

  1. Log in to the command line.
  2. To view the amount of memory that snmpd is currently using, type the following command:

    top -n 1 -p `pidof snmpd`

    Output appears similar to the following example:

    top - 16:04:58 up 10 min, 2 users, load average: 0.13, 0.68, 0.51
    Tasks: 1 total, 0 running, 1 sleeping, 0 stopped, 0 zombie
    Cpu(s): 3.7%us, 2.3%sy, 0.7%ni, 92.9%id, 0.4%wa, 0.0%hi, 0.0%si, 0.0%st
    Mem: 8191020k total, 8109128k used, 81892k free, 12024k buffers
    Swap: 1048504k total, 0k used, 1048504k free, 951584k cached

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    6675 root 20 0 29284 16m 7808 S 0.0 0.2 0:01.39 snmpd

    To refresh and display updated snmp information, type the following command:

    top -p `pidof snmpd`

  3. To exit, press Control + C.

    In the previous example output, RES -Resident Size is reporting that the snmpd process is using 16 MB of physical memory. When you see this value growing larger over time, a memory leak is occurring and you should restart snmpd to clear the leak.
  4. To restart snmpd, type the following command:

    tmsh restart sys service snmpd

Restart snmpd at a regular interval using the crontab utility

This option allows you to use the crontab utility to restart snmpd. The benefit of using crontab is that you can restart snmpd without user intervention during non-peak hours.

To create a custom crontab entry to specify the frequency at which you want snmpd to restart, perform the following procedure:

  1. Log in to the command line.
  2. Check the current crontab entries for root by typing the following command:

    crontab –l

  3. Edit the root crontab file by typing the following command:

    crontab -e

    Note: This command invokes the vi editor.

  4. Select one of the following entries to add the root crontab file, depending on the frequency at which you want snmpd restarted:

    * Daily restart

    The following entry will restart snmpd every day at 3 a.m.:

    00 3 * * * tmsh restart sys service snmpd

    * Weekly restart

    The following entry will restart snmpd once a week on Sunday at 3 a.m.:

    00 3 * * 0 tmsh restart sys service snmpd

  5. To enter insert mode, type i in the editor.
  6. On a new line in the root crontab file, type one of the options listed in step 4.

    For example:

    # cron tab for root
    1-59/30 * * * * /usr/bin/diskmonitor
    00 3 * * * tmsh restart sys service snmpd

  7. To exit from insert mode, press the ESC key.
  8. Simultaneously press the Shift and the colon ( : ) key.
  9. To save the changes and quit the editor, type the following command at the vi command prompt:

    wq
