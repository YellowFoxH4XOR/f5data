Known Issue

This is the result of a known issue. The HTTP::respond iRule command is not allowed in a CLIENTSSL_HANDSHAKE event. For example, if you attempt to create an iRule containing the HTTP::respond command in a CLIENTSSL_HANDSHAKE event, the system generates an error message in the Configuration utility and the /var/log/ltm file that appears similar to the following example:

01070151:3: Rule error: line 10: [command is not valid in current event context (CLIENTSSL_HANDSHAKE)] [HTTP::respond 200 content "No cert!"]

Note: The HTTP::respond iRule command generates a response to the client as if it came from the server. The command should be permitted in the CLIENTSSL_HANDSHAKE event, which is triggered after a client-side SSL handshake is completed.

F5 Product Development tracked this issue as CR125264 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

This issue was fixed in Hotfix-BIGIP-9.4.8-385.0-HF2 issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
