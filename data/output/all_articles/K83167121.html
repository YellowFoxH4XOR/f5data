Description

When moving to a production license from a lab/eval license, the configuration may load but the device will not go active.
In the BIG-IP Configuration Utility, there is a yellow banner at the top of the page with the following error message:

      This device is not operational because the loaded configuration contained errors or unlicensed objects. Please adjust the configuration and/or the license, and re-license the device.

In /var/log/ltm, the following error can be seen:

  • HA license_exceeded_t mcpd fails action is go offline and down links.

Environment

When using a lab/eval license to develop a configuration for production

  • Configuration saved with lab/eval License
  • Production license deployed and validated

Cause

Most lab/eval licenses contains almost all the available modules. When moving to a production license it will often support a more restricted feature set. Even using just the lab/eval license to enable a single module like APM, the defaults for certain features under the lab/eval license may contain features not supported in your production License.

Recommended Actions

1. Check the LTM logs and look for entries that can narrow down where the issue is happening. If you cannot resolve the issue from the log messages, you may need to open a ticket for F5 Support to assist.
2. Compare the lab/eval and production licenses. Check which features/flags are enabled on the lab/eval license, which may not be present on the production license. Below is an example:

Lab/Eval license has the following flags enabled:

config # grep mod_ bigip.license.eval
mod_ltm :                          enabled
mod_ilx :                          enabled
mod_afm :                          enabled
mod_dnsgtm :                       enabled
mod_cgnat :                        enabled
mod_asm :                          enabled
mod_apm :                          enabled
mod_afw :                          enabled


Production license only has the following flags enabled:

config # grep mod_ bigip.license.prod
mod_ilx :                          enabled
mod_apm :                          enabled

In some cases where the production license does not contain the features/flags that are required to support your configuration, it may be necessary to speak with your F5 Sales representative or Accounts team about getting a new registration key -- one that contains the correct flags/features set you require.

Additional Information

Here is an example of the sort of message that you could see in the logs, and the configuration that caused the issue:

err mcpd[<PID>]: 01070356:3: Ratio load balancing feature not licensed.

So by searching for the word "ratio" in the configuration, we found a pool that has been created using a feature that was unsupported in the production license. Deleting that line from the configuration (the pool will will revert to the default supported LB mode) and the configuration can then be reloaded without error.

ltm pool /YELLOW/RADIUS_AAA_Pool {
    load-balancing-mode ratio-member   <<<<<<<<<

There are of course a number of possible conflicts, and the above example is just one.

Here is another example of the sort of message that you could see in the logs, and the configuration that caused the issue:

err mcpd[<PID>]: 01070356:3: 01070356:3: Connection rebinding feature not licensed.

Check the configuration, it is caused by the following configuration, remove the configuration "service-down-action reselect" in the bigip.conf and do "tmsh load sys config", the issue will gone:

ltm pool /Common/test_pool {
    load-balancing-mode ratio-member
    members {
        /Common/2001:db8:8000:3::c.53 {
            address 2001:db8:8000:3::c
        }
        /Common/2001:db8:8000:3::d.53 {
            address 2001:db8:8000:3::d
        }
    }
    monitor /Common/gateway_icmp
    service-down-action reselect               <<<<<<<
