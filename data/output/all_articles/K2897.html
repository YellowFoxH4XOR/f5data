K2897: The respawn daemon message may appear in log files

Topic

BIG-IP and 3-DNS Controllers use the respawn daemon to ensure that specific daemons are always functional. It does this by monitoring any daemon that is started and verifies that the daemon is running in the process list. If respawn cannot find the daemon in the process list, it will attempt to restart the monitored daemon a total of 3 times at an interval of 10 seconds between each attempt.

When restarting daemons, respawn will log messages similar to the following:

respawn: respawning /usr/local/libexec/slapd
respawn: respawning /usr/local/corba/bin/ITCMPortal
respawn: respawning /usr/local/corba/bin/LocalLBServer
respawn: respawning /usr/local/corba/bin/ITCMSystemServer
respawn: respawning /usr/local/corba/bin/ITCMNetworkingServer
respawn: respawning /usr/local/corba/bin/ITCMManagementServer
respawn: /usr/local/corba/bin/LocalLBServer terminated by signal: 'Abort trap'
respawn: respawning /usr/local/corba/bin/LocalLBServer

respawn also watches the daemon's exit status to determine if it prematurely terminated. If a daemon that respawn starts terminates prematurely, respawn will restart the process.
