Topic

This article describes the different facilities and options you have available to get started on creating declarative security policies and applying them in NGINX App Protect WAF to protect your application environment.

Description

One of the first tasks you need to perform after installing NGINX App Protect WAF is to create a new security policy appropriate for your application environment and apply it. Because of security policy optimization and tuning, and the fact that NGINX App Protect WAF allows you to configure multiple security policies and apply them in different contexts (http, server, location), this task applies to the initial deployment and thereafter. This is an on-going operational task as you add applications to your environment and introduce new security requirements. The following sections describe some considerations and available tools to help get you started with creating security policies:

  • Reference NGINX App Protect WAF security policies
  • Conversion tools in NGINX App Protect WAF
    • The BIG-IP Advanced WAF security policies conversion tool
    • The user-defined signatures conversion tool
  • Use the NGINX ApiSecurityPolicy.json security policy

Reference NGINX App Protect WAF security policies

NGINX App Protect WAF ships with three security policies that you can use when you start creating your first security policy. Using any of the files as a base reference, you can edit them to add, modify, and remove security capabilities to match the security requirements in your application environment. You can find the following three files in the /etc/app_protect/conf directory (/etc/nginx in version 3.x) if you used the default installation settings:

  • NginxDefaultPolicy.json: This is the default security policy file that the system uses when you do not specify any security policy for the app_protect_policy_file directive in the NGINX configuration. You can find the default values for each setting, entity, and attribute in the /<installation directory>/app_protect/install/policy_templates/nginx_base.xml base template. For example, /opt/app_protect/install/policy_templates/nginx_base.xml.
  • NginxStrictPolicy.json: This security policy inherits settings from the default security policy and implements additional settings for applications that demand more restrictive security requirements.
  • NginxApiSecurityPolicy.json: This security policy inherits settings from the default security policy and implements additional settings for API protection. You use this policy with an OpenAPI specification file. Refer to the Use the NginxApiSecurityPolicy.json security policy section for instructions.

NGINX App Protect WAF lets you define multiple security policy files depending on the http, server, or location contexts for targeted protection. The following example illustrates an nginx.conf file that implements the three reference security policy files at different contexts, as follows:

  • For the default server, the /swagger-ui directory is protected by policies defined in the NginxApiSecurityPolicy.json API security policy.
  • In the example.com server context, the /secure directory is protected by policies defined in the NginxStrictPolicy.json strict security policy.
  • For all other requests, the declarations in NginxDefaultPolicy.json, defined in the http context, apply.

Note: The SSL configurations were omitted for readability.

Example: nginx.conf file
http {
    app_protect_enable on;
    app_protect_security_log_enable on;
    app_protect_policy_file "/etc/app_protect/conf/NginxDefaultPolicy.json";
    #[...]
}
server {
    listen 443 ssl default_server;
    #[...SSL configurations...]
    location / { ... }
    location /swagger-ui {
          app_protect_policy_file "/etc/app_protect/conf/NginxApiSecurityPolicy.json";
     }
}
server {
    listen  443 ssl ;
    server_name example.com;
    #[...SSL configurations...]
    location / { ... }
    location /secure {
         root   /usr/share/nginx/html/secure;
         index  index.html index.htm;
         app_protect_policy_file "/etc/app_protect/conf/NginxStrictPolicy.json";
    }
}

Conversion tools in NGINX App Protect WAF

The following section describes two tools available in the NGINX App Protect WAF compiler package. You can use them without a full installation of NGINX App Protect or NGINX Plus.

The BIG-IP Advanced WAF security policies conversion tool

One of the fastest ways to create a security policy is to start by already having one configured on a BIG-IP Advanced WAF system. NGINX App Protect WAF provides a conversion tool, convert-policy, to convert security policies exported from BIG-IP Advanced WAF in XML format to JSON format, to use in NGINX App Protect WAF. If you used the default installation settings, the file is saved as /opt/app_protect/bin/convert-policy. NGINX App Protect WAF supports security policies exported from BIG-IP Advanced WAF versions in XML format listed in the following table.

NGINX App Protect WAF versionSecurity policies exported from BIG-IP Advanced WAF
5.x16.1.x and earlier
4.x16.0.x and earlier
3.x16.0.x and earlier
2.x16.0.x and earlier

F5 recommends using the convert-policy tool that comes with the NGINX App Protect WAF installation to convert and deploy the security policy to the same NGINX App Protect WAF installation. You should not use the convert-policy tool from a different NGINX App Protect WAF version to do so. For more information, refer to Policy Converter in the NGINX documentation.

To perform the conversion, use the following command syntax:

/<full path to convert-policy>/convert-policy -i <filename of exported policy>.xml -o <filename of new policy>.json | jq

For example, enter the following command to convert exported-policy.xml to app-protect-policy.json:

/opt/app_protect/bin/convert-policy -i exported-policy.xml -o app-protect-policy.json | jq

You may observe output similar to the following, which displays a list of settings and entities that the tool removed, which are not supported on NGINX App Protect WAF.

{
  "file_size": 21364,
  "completed_successfully": true,
  "warnings": [
    "Default header '*-bin' cannot be deleted.",
    [...]
    "Traffic Learning, Policy Building, and staging are unsupported",
    [...]
    "/blocking-settings/http-protocols/description value 'Bad host header value' is unsupported.",
    "/whitelist-ips/trustedByPolicyBuilder must be '0' (was '1').",
    "Element '/websocket-urls' is unsupported."
  ],
  "filename": "/root/nginx_base.json"
}

The output file is based on the default security base template and is ready to use. You can retain all settings, saving them in the output file, including those not supported on NGINX App Protect WAF, by including the --keep-full-configuration switch. Note, however, that when you do so, the system reports unsupported features as errors when you attempt to load the resulting output policy into NGINX App Protect WAF and fail.

The user-defined signatures conversion tool

When you have your own user-defined signatures in XML format, such as one exported from a BIG-IP Advanced WAF system, NGINX App Protect provides the user-defined signatures tool to convert your XML file to JSON format so you can incorporate the file into an App Protect security policy. If you used the default installation settings, the file is saved in /opt/app_protect/bin/convert-signatures. For more information, refer to User Defined Signatures Converter in the NGINX documentation.

To perform the conversion, use the following command syntax:

/<full path to convert-signatures>/convert-signatures -i <filename of exported signatures>.xml -o <filename of new signature>.json | jq

For example, enter the following command to convert signatures.xml to signatures.json:

/opt/app_protect/bin/convert-signatures -i signatures.xml -o signatures.json | jq

Use the NginxApiSecurityPolicy.json security policy

You can configure NGINX App Protect WAF to provide API protection for your API servers by using, as a base reference, the NginxApiSecurityPolicy.json security policy, as described in the Reference NGINX App Protect WAF security policies section. The security policy file lets you specify an OpenAPI Specification (formerly called Swagger) file. This file is an API description format of REST APIs in either YAML or JSON format. It contains descriptions such as the endpoints (/users), operations (GET, POST), operation parameters, authentication methods, and so on, of your APIs.

You can, therefore, easily configure a security policy for API protection by simply referencing your OpenAPI Spec file. You do so by defining the OpenAPI Spec file location in the open-api-files setting in a security policy file, as follows:

Note: The following example references the OpenAPI Spec file in the file system locally. You can replace it with an HTTP URI at a remote internal server. For example, http://internal-server.example.local/myapi.yaml

Example: NginxApiSecurityPolicy.json security policy

{
   "policy" : {
      "name" : "app_protect_api_security_policy",
      "description" : "NGINX App Protect API Security Policy. The policy is intended to be used with an OpenAPI file",
      "template": {
        "name": "POLICY_TEMPLATE_NGINX_BASE"
      },

      "open-api-files" : [
            {
                "link": "file:///etc/nginx/nap.d/myapi.yaml"
            }
      ],

      "blocking-settings" : {
      [...]
     }
}

For more information on defining an OpenAPI Spec file in a security policy, refer to OpenAPI Specification File Reference in the NGINX documentation.
