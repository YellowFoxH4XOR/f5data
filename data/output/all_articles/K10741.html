K10741: Objects may be cached and immediately expired when the response includes a Cache-Control: Must-Revalidate header

Known Issue

This is the result of a known issue. When the OWS response includes a Cache-Control: Must-Revalidate header, the BIG-IP WebAccelerator inserts the X-Pvinfo header into the response with a value of S10202 (Proxy due to expire), indicating that the content will be expired immediately. This issue occurs even if the Use HTTP lifetime headers if present and Ignore no-cache headers settings are enabled, and the content is eligible for caching under the current BIG-IP WebAccelerator policy configuration.

F5 Networks Product Development is tracking this issue as ID 222940 (formerly CR126028).

Workaround

You can work around the issue by adding and applying rewrite code, which forces the BIG-IP WebAccelerator to ignore the Cache-Control: Must-Revalidate header value. To do so, perform the following procedure:

  1. Download the /config/wa/transforms/common.zip file from the BIG-IP WebAccelerator to your workstation.
  2. Create a text file named clvalidate_SOL10741.code, which contains the following rewrite code:

    import common.code;
    setvar _OWSCC "must-revalidate";
    setvar _CC "no-cache";
    search_addtoken _OWSCC Proc( (key proc span) (
    emit_add _CC;
    )
    );
  3. Add the file created in Step 2 into the common.zip file.
  4. Upload the common.zip file back to the BIG-IP WebAccelerator /config/wa/transforms directory.
  5. Log in to the BIG-IP WebAccelerator command line.
  6. To restart the pvac process, type the following command:

    bigstart restart pvac
  7. Type one of the following commands as appropriate for your version:

    Version 10.x:
    ls /var/wa/config/policies/localhost:8081/transforms

    Version 9.x:
    ls /usr/local/wa/config/policies/localhost:8081/transforms

    Ensure the clvalidate_SOL10741.code file appears in the directory listing.
  8. Log in to the BIG-IP WebAccelerator Configuration utility.
  9. Open the policy, and click on the node for which the Cache-Control: Must-Revalidate header will be ignored.
  10. From the drop-down box, select Acceleration Rules.
  11. Click on the Assembly tab.
  12. In the Content Assembly Options section, select Advanced from the drop-down box.
  13. In the Response Rewriting section, select clvalidate_SOL10741.code from the Rewrite proxied data using... list box.
  14. To save the new configuration, click Save and publish the policy.
  15. Clear the disk cache by typing the following command:

    wa_clear_cache

Note: Ensure that the Use HTTP lifetime headers if present and Ignore no-cache headers settings are still enabled for the node you are configuring to ignore the Cache-Control: Must-Revalidate header; they are enabled by default.
