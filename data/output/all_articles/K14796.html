Known Issue

The BIG-IP system uses an incorrect source address for FTP monitor traffic.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system configuration uses multiple Virtual Local Area Networks (VLANs).
  • Your BIG-IP system configuration monitors pool members by way of Equal-cost multi-path (ECMP) routes.

If your BIG-IP system uses ECMP routes, FTP monitor traffic that egresses one VLAN (VLAN A) interface may intermittently use the self IP address from another VLAN (VLAN B), causing the system to drop the pool member response that arrives on VLAN B. If the correct VLAN (VLAN A) does not receive a successful response within the monitor timeout value, the system marks the affected pool member as down.

Impact

FTP monitors intermittently report available pool members as not available in a false failure.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H432439 on the Diagnostics > Identified > Medium screen.
  • FTP monitors intermittently report available pool members as not available.

Workaround

To work around this issue, if your network environment allows, you can configure the BIG-IP system to allow asymmetric routing by disabling VLAN keyed connections. To do so, perform the following procedure:

Impact of workaround: Disabling VLAN-keyed connections is a global setting that allows all virtual servers to perform asymmetric routing.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Disable the connection.vlankeyed db key by typing the following command:

    modify sys db connection.vlankeyed value disable

  3. Save the change by typing the following command:

    save /sys config
