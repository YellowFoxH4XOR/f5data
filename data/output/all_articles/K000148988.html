K000148988: VirtualServerRoute error "Invalid value: "subroutes": must have only one subroute if regex match or exact match are being used"

Type
Support Solution
Published
2024-12-14
Updated
2024-12-14
Applies to
  • NGINX Products
  • NGINX Plus: R32, R31, R30, R33
Source
https://my.f5.com/manage/s/article/K000148988

Description

  • You deployed NGINX Ingress Controller version greater than 3.4.3, for example, version 3.7.x.
  • You created a virtualServer with multiple path and multiple regex.
  • After creating the virtualServer, (we provided a sample example below), you note Error message - "default/example-regex-issue is invalid: spec."subroutes" and we must have only one subroute if regex match or exact match are being used;" 
                  VirtualServerRoute default/example-regex-issue is invalid: spec.subroutes: 
                          Invalid value: "subroutes": must have only one subroute if regex match or exact match are being used; 
                  VirtualServerRoute default/example-regex-issue is invalid: spec.subroutes: 
                          Invalid value: "subroutes": must have only one subroute if regex match or exact match are being used

Environment

  • NGINX Ingress Controller
  • virtualServer Resource
  • virtualServerRoute (VSR)
  • Regex match

Cause

  • In version 3.4.3, NGINX addressed ID #4744, (validation for VSR exact & regex subroutes)

Recommended Actions

  • Simply speaking, in the past and prior to 3.4.3, validation of virtualServer route was not implemented in strict manner.
  • Meaning, multiple subroutes config validation could have succeeded.
  • However, in version 3.4.3, we addressed this short coming by fixing validation for VSR exact & regex subroutes.
  • The change is discussed and described here, as well as in our release note.
  • Hence, a VSR containing a single subroute using exact or regex matching succeeds config validation

Additional Information

  • Sample VirtualServerRoute that can generate the above reported issue 
                        apiVersion: k8s.nginx.org/v1
                        kind: VirtualServerRoute
                        metadata:
                          name: example-regex-issue
                          namespace default
                        spec:
                          host: example .com
                          upstreams:
                            - name: example-pool
                              service: example-svc
                              port: 80
                          subroutes:
                            - path: ~^/example/location/([a-zA-Z0-9_-]+)$
                              action:
                                proxy:
                                  upstream: example-pool
                                  rewritePath: "/example/location/$1"
                            - path: ~^/example/location/([a-zA-Z0-9_-]+)/new$
                              action:
                                proxy:
                                  upstream: example-pool
                                  rewritePath: "/hello/world/$1/new"
                          defaultAction:
                            return:
                              code: 404
                              type: plain
