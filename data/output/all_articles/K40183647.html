Description

The connection to mcpd may be lost due to an out-of-memory condition on the Linux host system.

Messages similar to the following may be found in /var/log/ltm:

warning bigd.0[26977]: 01060148:4: Bigd PID 26977, instance 0, over 90% load.
warning bigd.1[26969]: 01060148:4: Bigd PID 26969, instance 1, over 80% load.
warning bigd.0[26977]: 01060148:4: Bigd PID 26977, instance 0, over 95% load.

Note: The previous log messages indicate high CPU usage by bigd, the monitoring process. It is typical to see this in conjunction with high memory usage by bigd.

Messages in the following syntax are logged to the /var/log/kern.log file:

warning kernel: : [9685697.726152] <process> invoked oom-killer

Messages similar to the following are logged on a VIPRION platform in the /var/log/ltm file:

err clusterd[5690]: 013a0018:3: Blade 3 turned RED: Quorum: mcpd down: Connection to mcpd is not ready
 

Environment

  • BIG-IP
  • any version
  • many monitor instances are running
     

Cause

The out-of-memory condition is a result of too many monitors being configured, consuming resources on the Linux host system.
The mcpd process was killed by oom-killer, which is invoked by the Linux kernel when an out-of-memory condition occurs.
 

Recommended Actions

To mitigate the issue, refer to the Recommended Actions section of K42421592: The use of some monitors may bring about High CPU utilization of bigd.

Additional Information

When a system process invokes oom-killer, it simply kills another process which is using a high amount of memory. In this case it is mcpd, but this isn't a logical decision. It just means that the mcpd process is the victim of this high memory condition. Since mcpd is the master process which binds everything together on the system, this results in a failed state until it recovers.

Monitoring is done by the bigd service, which is a control plane process and isn't intended for such a large amount of monitor resource demands.
