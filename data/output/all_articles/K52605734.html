K52605734: Procedure to deploy parent policy changes from BIG-IQ to BIG-IP

Description

Starting in 13.x, we have the ability to deploy parent and child policies with ASM. Before you can deploy a child or security policy change from BIG-IQ to BIG-IP, you need to associate that policy to a virtual server within Configuration > Security > Web Application Security > Virtual Servers section in order for it to be eligible for deployment. If it doesn't have to be tied to a virtual server, you can associate the policy to inactive virtual server on the BIG-IQ.

When it comes to parent policy, you cannot associate them to a virtual server (the option wouldn't even show up, if you tried). Given that scenario, this article is intended to offer insight into how to deploy parent policy changes from BIG-IQ to BIG-IP devices.

Environment

  • BIG-IQ deployed with parent / child policies

Cause

You cannot associate a parent policy to inactive or any other virtual server within the Configuration > Security > Web Application Security > Virtual Servers section, since parent policies cannot be tied to a virtual server. This is expected behavior.  However, there can be a need to push changes to a parent policy that is being utilized across several child policies (residing on multiple devices) for inheritance.

As soon as you associate the corresponding child policy to a virtual server, you have the ability to deploy not only that child policy changes but it's corresponding parent policy changes to the target BIG-IP devices.

Recommended Actions

The following steps can be leveraged to push changes to a parent policy from BIG-IQ to target BIG-IP device(s):

  1. Create a parent policy and a corresponding child policy that is inheriting settings from this parent policy, both within Configuration > Security > Web Application Security > Policies. If a parent / child policy already exists, make the necessary changes to them that soon needs to be deployed.

  2. Associate the child policy to a virtual server (or inactive, if it isn't going to be tied to a virtual server) within Configuration > Security > Web Application Security > Virtual Servers.

  3. Deploy the parent and/or child policy (or changes from these policies) from within Configuration > Security > Web Application Security > Policies section by checking the relevant policy/policies and then use the More > Deploy option.

  4. Once you are in the Evaluate/Deploy section following step #3, you can now confirm the relevant policies have been selected and then see the target BIG-IP device(s) when using the Find relevant devices option. If you don't see a particular device in there, it likely means the child policy from that device hasn't been tied to a virtual server on that device, which would subsequently prevent you from pushing out the same parent policy's changes out to that device.
