Known Issue

This is the result of a known issue. Removing a non-responsive NTLM server from the ARX configuration may result in an NSM core with error messages that appear similar to the following example:

:SNMP TRAP:ntlmAuthServerOfflineClear (347) ip '10.10.10.15', : Secure Agent at IP address 10.10.10.15 offline state is cleared
:SNMP TRAP: cpuHalt (68) : failed slot:1 proc:5
:Disabling NSM slot 2 proc 4.
:SNMP TRAP: nsmStandby (411) : Processor 1.5 is in standby.
:VCIFS-2-WARN-CNXRECVERR::[7i/10.10.10.67] receive error - Connection reset by peer [104].
:SNMP TRAP: ntlmAuthServerOfflineRaise (346) ip '10.10.10.19', : Secure Agent at IP address 10.10.10.19 is offline
:2-4-NSM-0:CORE-0-ERR-CORE_NSM:: nsm[1]: [E:0] Writing core file.

F5 Product Development tracked this issue as ID 348799 and it was fixed in ARX version 5.2.2. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in hotfix 5.1.9 HFRU 2. For information about the hotfix, refer to K12595: Overview of ARX version 5.1.9 hotfixes. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 3348799.
