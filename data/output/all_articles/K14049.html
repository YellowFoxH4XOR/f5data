Known Issue

The value of a pool threshold setting in a high availability (HA) Group configuration is reset to zero after a reboot. This issue occurs when all of the following conditions are met:

  • The affected system is a vCMP guest.
  • The HA Group configuration consists of at least one pool with a threshold setting configured with a value greater than zero.

An HA Group is a set of configuration objects, such as trunks or pools, that is used by the BIG-IP system to calculate an overall HA score for each device in the redundant system configuration. The device that has the best HA score at any given time becomes or remains the active unit.

Impact

An unexpected device in the redundant system configuration may become the active unit.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • An unexpected device in the redundant system configuration becomes the active unit.
  • The tmsh list sys ha-group all-properties command reports the value of a pool threshold setting in an HA Group configuration as zero, although the previously configured value continues to be preserved in the /config/bigip.conf file.

Workaround

There is no workaround for this issue. However, if your BIG-IP system has encountered this issue, you can recover from this issue by correcting the value of the pool threshold setting from the Configuration utility. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Navigate to System > High Availability > HA Group.
  3. Enter the desired value in the Threshold column for the affected Pool Object Type.
  4. To save the changes, click Update.
