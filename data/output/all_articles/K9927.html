Known Issue

This is the result of a known issue. The BIG-IP ASM system may parse object types incorrectly when using dynamic session IDs in the URL.

For example, a web application containing the following custom dynamic session in the URL regular expression should match any resource in the request following a literal string of .123, and remove it from the path to parse the object type and object:

(?<=\.123).*

For example, the following sample URL contains a string of file .123 followed by MySessionId:

http://some.site.com/dir/file.123/MySessionId/?param1=value1

The path is /dir/file.123/MySessionId/, and the regular expression should remove /MySessionId/ in order to parse the .123 object type and the /dir/file.123 object. The BIG-IP ASM system correctly parses the /dir/file.123 object, but the BIG-IP ASM does not identify and parse the .123 object type. As a result, the security policy blocks valid requests.

F5 Product Development tracked this issue as CR61630 and it was fixed in BIG-IP ASM versions 9.2.4, 9.3, and 9.4. However, this issue was reintroduced in BIG-IP ASM 9.4.4 and 10.0.0. F5 Product Development tracked this issue as CR99697 and it was fixed in BIG-IP ASM 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

This issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
