Known Issue

The access policy Group Resource Assign agent may fail to detect group match.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM access policy includes the Group Resource Assign agent for Active Directory Domain Services (AD DS) or Lightweight Directory Access Protocol (LDAP).
  • When comparing the group information returned from the authentication, authorization, and accounting (AAA) server, the case used for the attribute expression does not match the case used in the server reply.

    For example, the Group Resource Assign expression appears similar to the following:

    expression "expr { [mcget {session.ldap.last.attr.memberOf}] contains \"cn=vpnfull,\" }"

    In the group mapping returned from the AAA server, the uppercase CN attribute does not match the lowercase cn attribute used in the expression, similar to the following:

    CN=vpnfull

Impact

Attribute detection fails, and the expression fails to detect the associated group value.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Authenticated users do not have the intended policy access resources assigned.
  • If you modify the agent expression to match the attribute case returned by the AAA servers, Group Resource Assign functionality is restored.
