Topic

The tmctl command gives you the ability to display system (CPU, memory) statistics. One of its most powerful features is to display these statistics over time, allowing you to understand system resource usage trends.

tmstat snapshots organization

You use the tmctl command to read binary snapshot files from tmstat tables located in the /shared/tmstat directory. The sub directories may differ depending on platform. A typical /shared/tmstat directory is organized as follows:

tmctl commands to display host memory

One of the most powerful features of tmctl is to display memory trend and statistics. The following section provides examples of using tmctl to display memory usage over time that is useful to determine if there is a host memory leak.
Note: TMM does not contribute to host memory use.

  • Display free swap memory trend from host_info_stat table
  • Display a process memory usage trend from proc_pid_stat table

Display free swap memory trend from host_info_stat table

The following commands are equivalent and display the statistics specified by the -s switch in the host_info_stat table containing snapshots taken every 3 hours (10800):

  • cd /shared/tmstat/snapshots/blade0/performance
    tmctl -w 10000 -D ./10800 -s time,slot_id,free_ram,shared_ram,buffer_ram,total_swap,free_swap host_info_stat

  • tmctl -w 10000 -D /shared/tmstat/snapshots/blade0/performance/10800 -s time,slot_id,free_ram,shared_ram,buffer_ram,total_swap,free_swap host_info_stat

  • tmctl -w 10000 -D /shared/tmstat/snapshots -s time,slot_id,free_ram,shared_ram,buffer_ram,total_swap,free_swap -T performance -R 10800 host_info_stat
    • -D: Subscribe to specific snapshots directory.
    • -s: Display the specified columns
    • -T: Limit snaptshots to the performance or public categories
    • -R: Limit snapshots to the specified intervals in seconds.

The commands display the value of free_swap in bytes. In this example, the output shows a healthy and steady value of free swap taken every 3 hours.

A low free swap value alone does not indicate an issue as there could have been a single event that required additional memory at one point, and the system can re-claim the used swap. When the value of free_swap is in a persistent downward trend passing below 400MB-500MB (depending on the specific system), and the values of swap in (si), swap out (so) from vmstat are non-zero, you should investigate further referring to K000152525: Overview of monitoring BIG-IP host (OS) memory. 

Display a process memory usage trend from proc_pid_stat table

The following command displays the statistics specified by the -s switch in the proc_pid_stat table containing snapshots taken once a day (86400):

tmctl -w 10000 -D /shared/tmstat/snapshots -T public -R 86400 -s time,proc_name,pid,vsize,rss,command_line proc_pid_stat

As the output displays a long list, you can use any of the column names as filter to display only the output you need. For example, if you observe errors in the /var/log/apm file indicating memory issues, or an apmd core file generated, to investigate the process memory usage trend, append the proc_name=apmd filter to the command as follows:

tmctl -w 10000 -D /shared/tmstat/snapshots -T public -R 86400 -s time,proc_name,pid,vsize,rss,command_line proc_pid_stat proc_name=apmd

You may observe an output similar to the following:

rss: This is the resident memory in 4kB page size representing the actual space a process occupies in physical memory. The RES column from the output of top (and cat /proc/<pid>/status) displays the equivalent value in kB.

When the value of resident memory rss is in a persistent upward trend together with a persistent downward trend in free swap determined in the previous section, it could indicate a memory leak for the process. In this example, the output shows a healthy and steady value of rss each day over a period of 6 days.

Recommendations

When understanding or investigating host memory usage on your system, consider the following:

  • exclude TMM in your analysis. For examples of using tmctl to analyzeTMM memory, refer to K000151935: Overview of tmsh and tmctl commands to display BIG-IP memory usage.

  • on iHealth, the tmctl command can be found in the Commands menu: Commands > Unix > TMOS.
  • in addition to tmctl, use a combination of at least 2 or more facilities to analyze host memory usage. For more information, refer to K000152525: Overview of monitoring BIG-IP host (OS) memory
