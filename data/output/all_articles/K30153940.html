K30153940: BIG-IQ no longer shows statistics, ASM Event Logs are empty

Type
Support Solution
Published
2023-05-05
Updated
2026-06-16
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.0, 8.1.X, 8.2.X, 8.3.X, 8.4.2, 8.4.1, 8.4.X, 8.1.0, 8.2.0, 8.3.0
Source
https://my.f5.com/manage/s/article/K30153940

Description

The BIG-IQ stopped updating statistics and ASM event logs. Elasticsearch cluster goes into read-only mode. The log record smilar to the following records may be found at /var/log/tokumond/log or /var/log/restjavad.log at BIG-IQ CM, or /var/log/appiq/agentmanager.log at BIG-IQ DCD.

[FORBIDDEN/12/index read-only / allow delete (api)]

Environment

BIG-IQ Central Management (CM) with multiple BIG-IQ Data Collection Devices (DCDs).

  • These statistics populated until recently.
  • AVR is provisioned on the remote BIG-IPs.
  • No connectivity issues between the BIG-IQ CM & BIG-IQ DCDs
  • BIG-IQ CM logs disk usage exceeded for the DCDs in /var/log/appiq/configserver.log
  • BIG-IQ CM shows low disk space per BIG-IQ DCDs in var/tmp/bigiqdiags/bigiq_diagnostics.txt 

Cause

ID1055153

Recommended Actions

Allocate more disk space & clear the read only blocks to allow ElasticSearch to resume.

  1. Increase disk space on /var for the BIG-IQ DCDs exceeding disk usage. By default, the size of the BIG-IQ DCDs cannot exceed 85% of /var.
    • K14952: Extending disk space on BIG-IP VE
       
  2. Clear read only blocks per the workaround for ID 1055153.

​​
for idx in $(curl -ks -u admin:admin https://localhost:9200/_cat/indices | awk '{print $3}'); do if [ $idx != ".opendistro_security" ]; then curl -k -u admin:admin -X PUT "https://localhost:9200/$(echo $(echo $idx | cut -d\+ -f1)*)/_settings?pretty" -H 'Content-Type: application/json' -d'{"index.blocks.read_only_allow_delete": false}'; fi; done
