K10179: The packet filter may inappropriately block response traffic

Known Issue

This is the result of a known issue. If you apply a packet filter that blocks a specific type of traffic, the filter will block all packets of that type, even responses to requests sent from the BIG-IP system.

Note: The filter is intended to be disabled for traffic related to an established connection flow.

As a result, some critical communications, such as monitor response traffic, may be adversely affected.

For example, if you apply a packet filter to deny all ICMP traffic, all ICMP traffic will be dropped, even the responses to ICMP requests sent to monitored nodes. Since the response is dropped, the node and all pool members that use the address will be marked unavailable regardless of their actual status.

F5 Product Development tracked this issue as CR120747 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM or Link Controller release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing BIG-IP version 10.x hotfixes, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Workaround

You can work around this issue by modifying the packet filter to explicitly trust the hosts from where the response traffic is blocked. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Browse to Local Traffic > Network > Packet Filters.
  3. In the Exemptions section, add either the IP addresses or the VLAN from which traffic is being inappropriately blocked.
  4. Click Update.
