K05058711: Getting ''Server Error'' when clicked on Monitoring tab in BIG-IQ

Type
Support Solution
Published
2021-09-13
Updated
2025-01-13
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 7.1.0, 8.0.0
Source
https://my.f5.com/manage/s/article/K05058711

Description

On the BIG-IQ when navigating to the Monitoring tab, you will get a Server Error.

For example, you navigate from Monitoring > DASHBOARDS > Web Application Security, you will not see any data but see Server Error.

Additional check shows that the ES Cluster Health status is red and multiple ES Indices are also red. Run the following commands on the BIG-IQ to view the status:
curl -s localhost:9200/_cluster/health?pretty
curl -s localhost:9200/_cat/indices?v

The ES indices example above shows there are 4 red indices and 1 green indice.

Environment

  • BIG-IQ
  • Objects in Monitoring tab not displayed
  • "Server Error" seen in Monitoring tab pages
  • ES Cluster Health status is red
  • Multiple ES Indices are red

Cause

Unhealthy ES cluster is causing the objects (pages) in the Monitoring tab to display Server Error.

Recommended Actions

You would need to delete the red indices to resolve the issue.
Important: In BIG-IQ 8.0.0 and later, TLS encryption has been enabled between ElasticSearch nodes in the cluster. As a result, you would need to add the -k flag to the curl command, and prepend https:// to the URL.

BIG-IQ 8.0.0 and later

  1. Login to the command line of the BIG-IQ CM.
     
  2. The command to delete a indice is:
    curl -k -X DELETE https://localhost:9200/<indice name>
     
  3. The command to delete a indice which has a date, time and time zone the command would be:
    curl -k -X DELETE https://localhost:9200/<indice name-date-time>%2B<0800>
     
  4. For the red indices examples from the Description, run the following commands to delete all the red indices:
    curl -k -X DELETE https://localhost:9200/book-keeper-start
    curl -k -X DELETE https://localhost:9200/doslogindex_2021-03-29t11-01-36%2B0800
    curl -k -X DELETE https://localhost:9200/botindex_2021-03-29t11-01-30%2B0800
    curl -k -X DELETE https://localhost:9200/source_registrations
     
  5. Do not delete green indices.
     
  6. Leave it some time so that the deleted red indices will propagate to the DCDs also.
     
  7. You can check the status of the ES Cluster Health and ES Indices with the following commands:
    curl -s localhost:9200/_cluster/health?pretty
    curl -s localhost:9200/_cat/indices?v
     
  8. Once the ES Cluster Health status is green and ES Indices does not have any red indices, the issue should be resolved.
