Topic

A BIG-IP APM system that processes a high volume of traffic may experience excessively large BIG-IP APM log files. This behavior may lead to lower performance, disk space issues, and stability issues with the BIG-IP system.

Description

The BIG-IP APM system may display the following symptoms when logging extra detail:

  • The /var/log/apm file may fill the logging drive.
  • Performance is reduced.
  • The /var/log/apm log may not be rotated.
  • The system may log the following error messages in the /var/log/ltm file:
    • emerg alert: 01100045:1 /var/log disk usage exceeds <disk space percentage>. Reduce log disk space now
    • warning diskmonitor: 011d0006: Disk partition var_log exceeded groth limit 5%
    • emerg alert: 01100048:0: Log disk usage still higher than 80% after logrotate and <count of log deletion> times log deletion
  • Running the following command from a command prompt lists the BIG-IP APM log file size is greater than 2 GB in size.

    ls -lh /var/log/apm

    For example:

    #ls -lh /var/log/apm
    -rw-r--r-- 1 root root 3.1G Mar 20 14:35 /var/log/apm

Recommendations

F5 recommends that you reduce or disable the BIG-IP APM logging level. You can do so by performing one the following procedures:

  • Reducing the BIG-IP APM logging level using the Configuration utility
  • Reducing the BIG-IP APM logging level using the tmsh utility
  • Disabling BIG-IP APM logging using the tmsh utility

Reducing the BIG-IP APM logging level using the Configuration utility

This procedure will reduce the number of messages logged.

Impact of workaround: Reducing the logging level will stop BIG-IP APM from logging messages that contain additional detail about BIG-IP APM sessions.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs.
  3. From the Configuration menu, select Options.
  4. In the Access Policy Logging section, select the least detail level of logging acceptable to your environment from the Access Policy menu. F5 recommends using a level of Error, Critical, Alert, or Emergency.
  5. Click Update.

Reducing the BIG-IP APM logging level using the tmsh utility

This procedure will reduce the number of messages logged.

Impact of workaround: Reducing the logging level will stop BIG-IP APM from logging messages that contain additional detail about BIG-IP APM sessions.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the new logging level, use the following command syntax. Set the log level to the least detail acceptable to your environment. F5 recommends using a level of Error, Critical, Alert, or Emergency.

    modify /sys db log.accesscontrol.level value "<new log level>"

    In this command syntax, <new log level> is the following:

    • Emergency
    • Alert
    • Critical
    • Error
    • Warning
    • Notice
    • Informational
    • Debug
  3. Save the change by typing the following command:

    save /sys config

Disabling BIG-IP APM logging using the tmsh utility

This procedure disables logging of BIG-IP APM messages and prevents message logging. F5 recommends performing this procedure only when absolutely necessary, such as performing stress tests for the BIG-IP system.

Impact of workaround: Disabling logging will stop BIG-IP APM from logging any messages.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To disable BIG-IP APM logging, type the following command:

    modify /sys db log.access.syslog value disable

  3. Save the change by typing the following command:

    save /sys config
