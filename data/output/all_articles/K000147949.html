Description

How do I setup an initial routed configurations? How do I configure GRE tunnels?

 

 

Environment

  • F5® Distributed Cloud (XC) DDoS

 

Cause

Routed configuration is required for the service to work.

Recommended Actions

What are GRE tunnels?

GRE stands for Generic Routing Encapsulation. A GRE Tunnel establishes a route between F5 and your Data Center. Once your traffic has been cleansed of malicious attack traffic, it is routed into the GRE Tunnel and back to the customer over the Internet. The advantage is that attackers can not attack your network, since all traffic must come through F5 for inspection.

 

Requirements for GRE Tunnel Setup (IPv4)

Important: MUST meet these requirements to use Routed DDoS Protection.

  • ASN: It is mandatory to obtain a Public ASN provided by a Regional Internet registry and maintained by your organization.
  • Route Object(s): The longest prefix accepted by F5 and its carriers is a /24. Anything more specific than /24 will be rejected by policy without exception.
    • The route object MUST be non-RFC1918
    • The route object MUST be maintained by your organization on any IRR, or
    • The route object MUST be included as part of the organization maintained AS-Set (if applicable)
    • For additional prefixes/ASNs open a ticket to Distributed Cloud Support.
  • Customer Endpoint: IP Address on your router where F5 will terminate tunnel.
    • Must be non-RFC1918 (publicly routable).
    • Important: Cannot be included in prefixes that will be diverted to F5XC for protection
  • Location:  A basic notation used as a tunnel identifier. Generally, companies will use the three-letter code for the airport nearest their data center.
  • Redundant Tunnels: For each of your locations, you will create at least 2 tunnels to different geo-located F5 routers. 

Requirements for IPv6 Tunnel Setup

Important: Before you can provision your IPv6 Tunnels (Step-by-step guide in next section!), you'll need to be prepared with the following information:

  • ASN: You must have an ASN assigned by ARIN (APNIC, etc).
  • BGP Subnets: IP Addresses that we will be announcing (minimum /48), or your AS SET. Important Note: With IPv6, a /48 is the smallest allocation that will be honored across multiple carriers. This is different than the GRE Tunnel minimum of /24.
  • Customer Endpoint: IPv6 Address on your router where F5 will terminate tunnel. Must be non-RFC1918 (publicly routable).
  • Location:  A basic notation used as a tunnel identifier. Generally, companies will use the three letter code for the airport nearest their data center.
  • Redundant Tunnels (recommended): For each of your locations, you will create at least 2 tunnels to F5XC (e.g. 1 to Seattle and 1 to San Jose).

 

Standard Setup Proces

Here is the standard process that we will follow to set up your GRE Tunnels and start routing your traffic through the F5XC scrubbing center as soon as possible.

  1. Sign into the XC Console
  2. Select DDoS & Transit Services
  3. Under Manage select ASNs
  4. Select Add ASN
  5. Enter ASN information
  6. Under Manage select Prefixes
  7. Select Add Prefix
  8. Enter prefix information
  9. Under Manage select  Tunnels
  10. Click Add Tunnel
  11. Enter name, select tunnel location and your enter the GRE endpoint.
  12. Build your GRE tunnels based on the data generated from the console
  13. Establish the GRE tunnels
  14. Establish the BGP session
  15. Test BGP/subnet is routed through F5 XC to your endpoints
  16. Legitimate traffic requests begin
  17. You verify that you are receiving traffic via the tunnel and routing out via your carrier.
  18. Verify that you see traffic in your XC Console graphs.

 

Additional Information

IPv4 Sample Configs

As soon as GRE tunnels are provisioned, use the following configurations as guidelines. Note: examples below include the commands to configure both GRE/BGP. 

Key

GRE ENDPOINTS -
XC: 198.51.100.1 [auto-generated in XC console]
CUST: 192.0.2.2

BGP INTERCONNECTS [auto-generated in XC console] -
XC: 100.64.0.2
CUST: 100.64.0.3

ISP NEIGHBOR: 192.0.2.1

 

Cisco 

interface Tunnel0
description F5XC-DCA1000001
ip address 100.64.0.3 255.255.255.254 [Cust interconnect]
load-interval 30
keepalive 30 4
tunnel source 192.0.2.2 
tunnel destination 198.51.100.1 [F5 Endpoint IP]

router bgp 64501
network 203.0.113.0 mask 255.255.255.0 [prefix to be advertised]
no synchronization
bgp log-neighbor-changes
no auto-summary
neighbor F5XC peer-group
neighbor F5XC remote-as 55002
neighbor F5XC description F5XC-peer-group
neighbor F5XC password md5BGPpassword
neighbor F5XC version 4
neighbor F5XC send-community
neighbor F5XC prefix-list deny-all in
neighbor F5XC prefix-list route-to-F5XC out
neighbor ispA peer-group
neighbor ispA remote-as 64500
neighbor ispA description upstream-ISP-peer-group
neighbor ispA version 4
neighbor ispA send-community
neighbor ispA prefix-list suppress-to-ispA out
neighbor 100.64.0.2 peer-group F5XC [F5 interconnect BGP neighbor F5 side]
neighbor 100.64.0.2 description F5XC-neighbor-1 [F5 interconnect BGP neighbor F5 side]
neighbor 192.0.2.1 peer-group ispA
neighbor 192.0.2.1 description ispA-neighbor-1

ip route 0.0.0.0 0.0.0.0 192.0.2.1 name ispA-uplink
ip route 203.0.113.0 255.255.255.0 Null0 201 name F5XC-routed-prefix

ip prefix-list deny-all deny 0.0.0.0/0 le 32

ip prefix-list route-to-F5XC permit 203.0.113.0/24

ip prefix-list suppress-to-ispA deny 203.0.113.0/24
ip prefix-list suppress-to-ispA permit 0.0.0.0/0 le 24

 

Juniper

interfaces {                            
     gr-0/0/0 {
         unit 1 {
             description F5XC-DCA1000001;
             tunnel {
                 source 192.0.2.2;
                 destination 198.51.100.1;
             }
             family inet {
                 address 100.64.0.3/31;
             }
        }
    }
}
 routing-options {
     static {
         route 0.0.0.0/0 next-hop 192.0.2.1;
         route 203.0.113.0/24 discard;
     }
     autonomous-system 64501;
 }
 protocols {
     bgp {
         log-updown;
         local-as 64501;
         group F5XC {
             type external;
             advertise-inactive;
             import reject-all;
             authentication-key md5BGPpassword;
             export route-to-F5XC;
             peer-as 55002;
             neighbor 100.64.0.2;
         }
         group ispA {
             type external;
             advertise-inactive;
             export suppress-to-ispA;
             peer-as 64500;
             neighbor 192.0.2.1;
         }
     }
     oam {
         gre-tunnel {
             interface gr-0/0/0.1 {
                 keepalive-time 30;
                 hold-time 120;
             }
        }
     }
 }
 policy-options {
     prefix-list route-to-F5XC {
         203.0.113.0/24;
     }
     policy-statement reject-all {
         then reject;
     }
     policy-statement route-to-F5XC {
         term route-to-F5XC {
             from {
                 prefix-list-filter route-to-F5XC;
             }
             then accept;
         }
         then reject;
     }
     policy-statement suppress-to-ispA {
         term suppress-to-ispA {
             from {
                 prefix-list-filter route-to-F5XC;
             }
             then reject;
         }
         then accept;
     }
 }
