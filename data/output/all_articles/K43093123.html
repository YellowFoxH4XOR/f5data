Description

 

Sometimes it is required to start a connection from an iRule, but when doing this operation, BIG-IP unit might use a wrong mac address.

Due to behavior above, Cisco ACI might "blacklist" BIG-IP's floating ip address.

 

 

Environment

 

BIG-IP

Mac masquerade

iRule(s) containing "Connect" or "Send" commands.

 

 

 

Cause

 

This behavior is caused by ID 1041261:

 

"When MAC masquerade is in use and sideband connection is generated with iRule (using 'connect' and 'send' commands) and floating self-ip is used as a source of the connection, the outgoing sideband packets are not using the masquerade MAC address."

 

Cisco ACI might blacklist floating ip address due to "Rogue Endpoint Detected" feature.

 

 

Recommended Actions

 

Instead of specifying a source address in iRule, direct traffic (from same iRule) to specially configured virtual server (with no VLAN access):

 

 

Procedure

 

  • Modify iRule to send connection to local VS:

 

When CLIENT_ACCEPTED { 

 set data "MyData" 

 #set conn_id [connect -protocol UDP -myaddr aaa.bbb.ccc.ddd  -myport <port> eee.fff.ggg.hhh:80]   <<<<<< Original "Connect" command

 set conn_id [connect -protocol UDP sideband_vs]                                                                                 <<<<<< Workaround connect towards dedicated VS

 set send_bytes [send -timeout 1000 -status send_status $conn_id $data] 

 log local0. "Sent $send_bytes with status $send_status" 

 } 

}

 

 

  • With floating self-ip, note virtual-server is not enabled in any vlan:

 

ltm virtual sideband_vs {
    destination 172.16.1.215:http
    ip-forward
    ip-protocol udp
    mask 255.255.255.255
    profiles {
        fastL4 { }
    }
    source 0.0.0.0/0
    source-address-translation {
        pool SPOOL
        type snat
    }
    vlans-enabled     <<<<<<<< No vlans defined (Only accepts local requests).
}


ltm snatpool SPOOL{
    members {
        10.11.63.46
    }
}

 

  • Make sure  virtual-address is configured for a desired floating traffic group:

 

ltm virtual-address 172.16.1.215 {
    address 172.16.1.215
    mask 255.255.255.255
    traffic-group traffic-group-1
}

 

 

Traffic will now use a MAC masquerade (tmm) address when using SNAT pool.
