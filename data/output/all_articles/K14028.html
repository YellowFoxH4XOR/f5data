Known Issue

The BIG-IP GTM system may fail to properly auto-discover virtual servers. This issue occurs when all of the following conditions are met:

  • The target BIG-IP 10.x system is added as a BIG-IP server object to the GTM 11.x configuration.
  • The affected BIG-IP server object is configured with the Virtual Server Discovery setting
  • The virtual server objects are discovered and added to the BIG-IP GTM configuration
  • The target BIG-IP system is upgraded to 11.x

When the above conditions occur, the BIG-IP GTM system re-discovers the virtual servers on the target BIG-IP system, and includes the partition information when adding the virtual server objects. If the BIG-IP server object is configured with the Virtual Server Discovery Enabled setting, the BIG-IP GTM system removes the affected virtual servers from their assigned pools. If the BIG-IP server object is configured with the Virtual Server Discovery Enabled (No Delete) setting, the BIG-IP GTM system retains the original virtual server objects, and adds duplicate virtual server objects that include the 11.x partition information.

Impact

The affected wide IP may fail to resolve as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H400608 on the Diagnostics > Identified > Low screen.
  • If the BIG-IP server object is configured with the Virtual Server Discovery Enabled (No Delete) setting, the affected BIG-IP server object configuration appears to contain duplicate virtual servers.

    For example, the following BIG-IP GTM server configuration stanza shows the BIG-IP GTM system discovers example_vs1 and /Common/exampe_vs1 virtual servers for BIG-IP server object bigip.example.com:

    gtm server bigip.example.com {
    addresses {
    192.168.0.2 {
    device-name bigip.example.com
    }
    }
    datacenter exampledc1
    monitor bigip
    virtual-server-discovery enabled-no-delete
    virtual-servers {
    example_vs1 {
    destination 192.168.3.4:http
    ltm-name example_vs1
    }
    /Common/example_vs1 {
    destination 192.168.3.4:http
    ltm-name /Common/example_vs1
    }
    }
    }
  • If the BIG-IP server object is configured with the Virtual Server Discovery Enabled setting, the BIG-IP GTM system removes the affected virtual server from the pool that it was previously associated with.

Workaround

To prevent this issue, you can modify the ltm-name setting to reflect the full path for each virtual server on the BIG-IP GTM system before attempting to upgrade the target BIG-IP system to 11.x.

If you have encountered this issue, you can recover by modifying the ltm-name setting to reflect the full path for each affected virtual server before removing each duplicate virtual server from the BIG-IP server object configuration on the BIG-IP GTM system. Additionally, if the virtual server auto-discovery is set to Enabled on the affected BIG-IP server object, you must re-add each affected virtual server to the pool it was previously associated with.

Perform either one of the following procedures applicable to your environment:

  • Modifying the ltm-name setting for each virtual server before upgrading
  • Recovering the the affected virtual server and re-adding to the pool

Modifying the ltm-name setting for each virtual server before upgrading

Impact of workaround: None.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  2. Modify the ltm-name setting to reflect the full path for each virtual server by using the following command syntax:

    modify /gtm server <server name> virtual-servers modify { <virtual server 1> { ltm-name /<partition>/<virtual server 1> } <virtual server 2> { ltm-name /<partition>/<virtual server 2> } ... }

    For example, you would enter the following command for virtual server example_vs1 in the Common partition of the BIG-IP server bigip.example.com:

    modify /gtm server bigip.example.com virtual-servers modify { example_vs1 { ltm-name /Common/example_vs1 } }
  3. Repeat step 2 for each BIG-IP server object.
  4. Save the change by typing the following command:

    save /sys config gtm-only

You may now proceed to upgrade the target BIG-IP system to 11.x.

Recovering the the affected virtual server and re-adding to the pool

Impact of workaround: None.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.
  2. Modify the ltm-name setting to reflect the full path for each virtual server by using the following command syntax:

    modify /gtm server <server name> virtual-servers modify { <virtual server 1> { ltm-name /<partition>/<virtual server 1> } <virtual server 2> { ltm-name /<partition>/<virtual server 2> } ... }

    For example, you would type the following command for virtual server example_vs1 in the Common partition of the BIG-IP server bigip.example.com:

    modify /gtm server bigip.example.com virtual-servers modify { example_vs1 { ltm-name /Common/example_vs1 } }
  3. Remove the duplicate virtual server by using the following command syntax:

    modify /gtm server <server name> virtual-servers delete { /<partition>/<virtual server 1> /<partition>/<virtual server 2> ... }

    For example, you would enter the following command to remove the duplicate virtual server example_vs1 in the Common partition of the BIG-IP server bigip.example.com:

    modify /gtm server bigip.example.com virtual-servers delete { /Common/example_vs1 }
  4. Repeat steps 2 through 3 for each BIG-IP server object.
  5. If the BIG-IP server object virtual server auto-discovery is set to Enabled, re-add the affected virtual server to its previous pool by using the following command syntax:

    modify /gtm pool <pool name> members add { /<partition>/<server name>:<virtual server 1> /<partition>/<server name>:<virtual server 2> ... }

    For example, you would type the following command to re-add virtual server example_vs1 of the BIG-IP server bigip.example.com to the pool example-pool:

    modify /gtm pool example-pool members add { /Common/bigip.example.com:example_vs1 }
  6. Save the modifications by entering the following command:

    save /sys config gtm-only
