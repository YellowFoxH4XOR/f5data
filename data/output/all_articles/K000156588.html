K000156588: The ASM system variables are synchronized across the BIG-IP systems that belong to the same HA cluster

Type
Support Solution
Published
2025-09-23
Updated
2025-09-24
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000156588

Description

The ASM system variables are synchronized across all BIG-IP devices that belong to the same HA cluster via the sync-only or sync-failover device group.

The ASM system variables will be impacted are:

Environment

  • ASM system variables
  • HA synchronization

Cause

None

Recommended Actions

Before you modify a variable, be aware that if the system is in auto-sync mode, the entire HA cluster will synchronize immediately. 

This could lead to unexpected system behavior if the synchronization overwrites your change from the wrong direction. Here is a demostration: 

1.BIGIP #1 : Edit the ASM system variable, restart ASM services, and synchronize the HA cluster : 

[bigip1] config # bigstart restart asm

[bigip1] config # grep "ecard_max_http_req_uri_len" /var/log/ts/
BD_MISC|NOTICE|Sep 23 06:41:50.475|26503|temp_func.c:1578|ecard_max_http_req_uri_len = 2048
BD_MISC|NOTICE|Sep 23 09:58:28.337|11536|temp_func.c:1170|CHANGED INTERNAL PARAM: [ecard_max_http_req_uri_len][4096]
BD_MISC|NOTICE|Sep 23 09:58:28.337|11536|temp_func.c:1578|ecard_max_http_req_uri_len = 4096

2. BIGIP #2 : Since BIG-IP #1 has already synchronized its configuration, simply restarting the ASM daemon on BIG-IP #2 will apply the new value.

Important: The new value will not take effect until the ASM daemon is restarted.

[bigip2] config # bigstart restart asm

[bigip2] config # grep "ecard_max_http_req_uri_len" /var/log/ts/bd.log
BD_MISC|NOTICE|Sep 23 09:59:13.374|4283|temp_func.c:1170|CHANGED INTERNAL PARAM: [ecard_max_http_req_uri_len][4096]
BD_MISC|NOTICE|Sep 23 09:59:13.374|4283|temp_func.c:1578|ecard_max_http_req_uri_len = 4096
