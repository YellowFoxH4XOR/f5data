Known Issue

A BIG-IP ASM virtual server configured with an iRule may cause the Traffic Management Microkernel (TMM) to leak memory.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP virtual server is configured with a BIG-IP ASM security policy and an iRule.
  • The iRule uses the ASM_RESPONSE_VIOLATION event.

Impact

Incoming virtual server connections may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In high memory usage conditions, connections arriving to the virtual server receive a TCP reset with a reset cause of TCP closed.
  • System connection statistics for the virtual server continually increase each time the virtual server processes a request that triggers the iRules event.
  • The amount of memory allocated for and used by the TMM process increases over time.

Workaround

To work around this issue, you can remove the iRule from the affected virtual server and assign a OneConnect profile.

Impact of workaround: Performing the suggested workaround either removes the iRules functionality from the virtual server, or in the case of enabling OneConnect open TCP ports, the virtual server is re-used on destination resources for new connections.
