K000162467: F5 Container Ingress Services AS3 Declarations Fail with HTTP 422 on Non-Default Route Domains

Type
Support Solution
Published
2026-07-27
Updated
2026-07-27
Applies to
  • F5 Automation and Orchestration
  • BIG-IP
  • F5 Application Services 3 Extension
  • F5 BIG-IP Container Ingress Services
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162467

Description

F5 Container Ingress Services (CIS) cannot create or update virtual servers, pools, or other Kubernetes-managed objects in a tenant partition that uses a non-default route domain. BIG-IP returns an HTTP 422 response containing:

When deploying an AS3 declaration to a tenant partition that uses a non-default (non-zero) Route Domain and AFM (Advanced Firewall Manager) is not provisioned, every declaration attempt fails with the following error:

{
  "code": 422,
  "message": "declaration failed",
  "response": "one or more properties must be specified",
  "tenant": "<partition-name>"
}

The corresponding BIG-IP `restnoded.log` entry:

severe: [appsvcs] {"message":"Declaration failed: one or more properties must be specified","level":"error"}

CIS (Container Ingress Services) users may additionally observe:  

[ERROR] [AS3] Response from BIG-IP: code: 422 --- tenant:<partition> --- message: declaration failed one or more properties must be specified

After the 422 failure, CIS may retry and receive a `201/202` response — but with an empty `tenant:[]` in the result. No objects are created or updated on the BIG-IP despite CIS logging apparent success. 

Environment

  • BIG-IP LTM
  • F5 Container Ingress Services (CIS) 2.20.3
  • AS3 versions 3.55 through 3.57
  • Tenant partitions configured with non-default route domains (Route Domain ID ≠ 0)
  • AFM not provisioned on the BIG-IP
  • CIS using AS3 declarations to manage Kubernetes resources

Symptoms

CIS logs may show:

code: 422

message: Declaration failed: one or more properties must be specified

The AS3 logs may contain a command similar to:

tmsh::modify net route-domain <partition>/<route-domain> fw-enforced-policy none

CIS may then report a successful declaration even though the declaration is empty and no virtual server or pool is deployed.

A separate temporary error may also occur while BIG-IP REST services are processing another asynchronous task:

503 Service Unavailable

There is an active asynchronous task executing.

The HTTP 503 condition is separate from the persistent AS3 declaration failure.

Cause

Bug ID 2376329 (AUTOTOOL-5289) affects AS3 processing when all of the following conditions apply:

  • The tenant partition uses a non-default route domain.
  • AFM is not provisioned.
  • The AS3 release generates an internal route-domain command containing the AFM-only fw-enforced-policy property.

Because the property is unavailable without AFM, declaration processing fails. AS3 returns the generic error:

one or more properties must be specified

Recommended Actions

Install AS3 3.58 or a later release containing the fix for Bug ID 2376329.

Upgrade AS3 on all BIG-IP devices in your deployment.

1. Download AS3 3.58.0
Download `f5-appsvcs-3.58.0-x.noarch.rpm` from the [F5 Downloads portal](https://downloads.f5.com).

2. Upload the RPM to the BIG-IP
scp f5-appsvcs-3.58.0-x.noarch.rpm admin@<bigip-mgmt>:/var/config/rest/downloads/

3. Install via iControl REST
curl -sku admin:<password> -X POST \
  https://<bigip-mgmt>/mgmt/shared/iapp/package-management-tasks \
  -H 'Content-Type: application/json' \
  -d '{"operation":"INSTALL","packageFilePath":"/var/config/rest/downloads/f5-appsvcs-3.58.0-x.noarch.rpm"}'

4. Verify the installed version*
curl -sku admin:<password> \
  https://<bigip-mgmt>/mgmt/shared/appsvcs/info | python3 -m json.tool | grep version
# Expected output: "version": "3.58.0"

5. Restart REST services

tmsh restart sys service restjavad
tmsh restart sys service restnoded

6. For CIS environments — restart the CIS pod

kubectl rollout restart deployment/<cis-deployment-name> -n <namespace>

7. Verify declarations succeed

kubectl logs -n <namespace> deployment/<cis-deployment-name> | grep "Response from BIG-IP"
# Expected: code: 200 or 201 — tenant: <partition> — message: success

 

Workaround (if immediate upgrade is not possible)
Downgrade AS3 to version 3.52.x or earlier. Versions prior to 3.55 do not contain the defective `fw-enforced-policy` logic. Note that this is a temporary workaround only — upgrading to AS3 3.58.0 is the recommended long-term resolution.

Additional Information

  • This issue does not affect tenant partitions using the default Route Domain (Route Domain ID 0).
  • If you observe an additional log message alongside the 422 error —  
    `ng_profile command failed: PHP Warning: mkdir(): Permission denied in /var/sam/www/`  
    — this indicates a secondary filesystem permission issue on the BIG-IP. Check and correct ownership of `/var/sam/www/`:
    ls -la /var/sam/www/ 2>/dev/null || echo "Directory does not exist"
    mkdir -p /var/sam/www/
    chown -R apache:apache /var/sam/www/
    chmod -R 755 /var/sam/www/
  • In **CIS deployments**, after the 422 failure CIS may retry and submit an empty declaration that BIG-IP accepts (`201/202` with `tenant:[]`). This causes CIS to log a false success. No BIG-IP objects are created in this case. After upgrading to AS3 3.58, a CIS pod restart is required to trigger a fresh full declaration cycle.
