K000150811: SNMP v2c is not working from F5 to Client on third party app, but network path is clear.

Type
Support Solution
Published
2025-04-10
Updated
2025-07-03
Applies to
  • BIG-IP
  • BIG-IP LTM
  • BIG-IP DNS: 17.1.0
Source
https://my.f5.com/manage/s/article/K000150811

Description

Deploying new client SNMP server that is able to send traffic to the F5 but the F5 is unable to send traffic out.

All network ports open and listening between servers. F5 is configured SNMP correctly. 

Client Server must verify their snmpd.conf file or windows config for snmp has the correct group. 

 

Environment

  • BIG-IP LTM
  • BIG-IP GTM

Cause

SNMP v2c traffic is sending to F5 from client, but F5 is not sending to client destination due to lacking config on client server. 

[root@test-v4-bigip1:Standby:Changes Pending] config # traceroute -U -p 161 10.0.0.0

traceroute to 10.0.0.0 (10.0.0.1), 30 hops max, 60 byte packets

 1 10.0.0.1 (10.0.0.1) 1.350 ms 1.392 ms 1.368 ms

[root@test-v4-bigip1:Standby:Changes Pending] config #

[root@test-v4-bigip1:Standby:Changes Pending] config # snmpwalk -v 2c -c a 10.0.0.1

Timeout: No Response from 10.0.0.1

[root@test-v4-bigip1:Standby:Changes Pending] config #

 

Recommended Actions

Edit the client server snmpd.conf to listen. (or the config on windows server) 

sudo chmod 777 /etc/snmp/snmpd.conf

add community string and IP example: rwcommunity a 10.0.0.0/8

sudo system restart snmpd
