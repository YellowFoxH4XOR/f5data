K15164952: High cpu after ssl certificate replacment

Type
Support Solution
Published
2021-09-30
Updated
2026-08-10
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • Public Cloud

Source
https://my.f5.com/manage/s/article/K15164952

Description
After ssl certificate replacement on a virtual server, CPU is much higher than it was before with the same amount of traffic. . 

Environment

  • BIG-IP 11.x, 12.x, 13.x, 14.x, 15.x, 16.x, 17.x, 21.x
  • SSL profile
  • SSL certificate replacement

Cause
Replacing SSL certificate with a new one with a bigger key size will result in higher CPU usage. 

Recommended Actions

  1. Log in to the BIG-IP command line.
  2. Go to the folder with the SSL certificate used currently and before replacment by the SSL profile:
    File   Location Example
    certificate /config/filestore/files_d/<partition>_d/certificate_d/   /config/filestore/files_d/Common_d/certificate_d/   
     
  3. Check the size of the SSL certifications keys with the below command:
    openssl x509 -in certificate.crt -text -noout | grep "Public-Key"

    Example commands with outputs: 
    # openssl x509 -in  \:Common\:old_certificate.crt -text -noout | grep "Public-Key"
      Public-Key: (1024 bit)

    # openssl x509 -in  \:Common\:new_certificate.crt -text -noout | grep "Public-Key"
      Public-Key: (4096 bit)
  4. If your new certificate has a bigger public key size, this will result in higher resource consumption.
    NOTE: More about key size impact you can read in K13067: Performance impact of transitioning to 2048-bit SSL key sizes
  5. If you want to avoid higher CPU usage, create a certificate with the same key size as the previous certificate and replace it.
