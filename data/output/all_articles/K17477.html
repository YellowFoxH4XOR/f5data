Topic

This article provides information about disk usage by way of provisioning for the BIG-IP modules with application volumes.

Note: The content in this article only applies to BIG-IP systems that were deployed using BIG-IP 12.1.0 or earlier images (13.0.1 or earlier for BIG-IP VE) and progressively upgraded to later versions. If the BIG-IP system was deployed using BIG-IP 12.1.1 or later images (13.1.0 or later for BIG-IP VE), the BIG-IP system would be using the newer partition scheme that consolidates the application volumes into one logical volume named appdata; the content in this article would not apply to these BIG-IP systems deployed using BIG-IP 12.1.1 or later images (13.1.0 or later for BIG-IP VE).

Note: The content in this article currently also applies to BIG-IP systems that were deployed in rSeries.

Description

Provisioning for BIG-IP modules AFM, AAM, ASM, APM, AVR, and PEM consumes additional disk usage due to the application related data, called application volumes. Application volumes consist of disk space that is allocated uniquely for the purpose of storing the application-related data that the provisioned BIG-IP module uses.

To display the application volume that is allocated on the BIG-IP system, enter the following command: tmsh list sys disk application-volume.

To delete the application volume that is allocated on the BIG-IP system, enter the following command: tmsh delete sys disk application-volume [Name of the Disk].

Note: Alternatively, using the Configuration utility, go to System > Disk Management > HD1, and look at the table Contained Application Volumes.

In the following section, there are four examples of the output from the Traffic Management Shell (tmsh) command to display the application volumes that are allocated on the BIG-IP system. The examples are based on the types of modules being provisioned:

Recommendations

  1. Provisioned with a BIG-IP AFM module that is installed on the software volume HD1.1. The application volumes allocated the disk space from the logical disk HD1, and the system uses these volumes for storing the BIG-IP AFM data and the MySQL database. The application volumes may be allocated as follows:

    sys disk application-volume afmdata {
        logical-disk HD1
        owner afm
        preservability precious
        resizeable false
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume mysqldb_HD1.1 {
        logical-disk HD1
        owner mysql
        preservability precious
        resizeable false
        size 12288
        volume-set-visibility-restraint HD1.1
    }

  2. Provisioned with a BIG-IP ASM module that is installed on the software volume HD1.2. The application volumes allocated the disk space from the logical disk HD1, and the system uses these volumes for storing the BIG-IP ASM data, the AVR data, and the MySQL database. The application volumes may be allocated as follows:

    sys disk application-volume asmdata {
        logical-disk HD1
        owner asm
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume avrdata {
        logical-disk HD1
        owner avr
        preservability precious
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume mysqldb_HD1.2 {
        logical-disk HD1
        owner mysql
        preservability precious
        size 12288
        volume-set-visibility-restraint HD1.2
    }

  3. Provisioned with BIG-IP AFM and ASM modules that are installed on the software volume HD1.1. The application volumes allocated the disk space from the logical disk HD1, and the system uses these volumes for storing the BIG-IP AFM data, the BIG-IP ASM data, the AVR data, and the MySQL database.

    sys disk application-volume afmdata {
        logical-disk HD1
        owner afm
        preservability precious
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume asmdata {
        logical-disk HD1
        owner asm
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume avrdata {
        logical-disk HD1
        owner avr
        preservability precious
        size 3900
        volume-set-visibility-restraint none
    }
    sys disk application-volume mysqldb_HD1.1 {
        logical-disk HD1
        owner mysql
        preservability precious
        size 12288
        volume-set-visibility-restraint HD1.1
    }

  4. Delete an application volume which is a MySQL database on the software volume HD1.1 named mysqldb_HD1.2

    [root@bigip:Active:Standalone] config # tmsh list sys disk application-volume
    sys disk application-volume mysqldb_HD1.2 {
        logical-disk HD1
        owner mysql
        preservability precious
        size 12288
        volume-set-visibility-restraint HD1.2
    }
    [root@bigip:Active:Standalone] config # tmsh delete sys disk application-volume mysqldb_HD1.2

    When you provision a new BIG-IP module, a different set of application volumes (for example, the MySQL database) can be added to the logical disk HD1 disk usage. Therefore, when you plan to provide additional BIG-IP modules to the system, you should also consider the required disk space for the additional application volumes. Each module provisioned and installed on a different software volume may have its own set of the application volume disk usage.

    When planning to perform an upgrade or to install a new software volume, you can verify the amount of disk space available on the BIG-IP system, and review the amount of application volumes currently being allocated to determine if the system has sufficient space. For more information about managing disk space, refer to K14403: Maintaining disk space on the BIG-IP system (11.x - 12.x)
