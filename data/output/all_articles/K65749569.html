Issue

Description

The BIG-IP system reestablishes trust automatically, but the process may fail due to various reasons. For example, if the connection to the primary Active Directory Federation Services (ADFS) server is down or if either device is offline. 

When the ADFS trust is not established, the following errors may be logged in the /var/log/apm file:

  • err adfs_proxy[<pid>]: 01aeffff:3: (null)::00000000: Can't connect to ADFS (/Common/example.app/example_adfs_pool) for trust renewal.
    err adfs_proxy[<pid>]: 01aeffff:3: (null):Common:00000000: Can't get configuration from /Common/example_adfs_Pool: 401 Unauthorized
  • ADFS Trust Establishment Failed: Failed to establish ADFS trust relationship on the virtual server /Common/example.app/example_adfs_vs_443: Can't connect to ADFS.

Environment

  • BIG-IP APM is configured as ADFS Proxy server with an ADFS primary server

Cause

  • One of the BIG-IP APM or ADFS primary servers is offline.
  • Network issues between the BIG-IP APM system and ADFS primary server.

Recommended Actions

When automatic trust reestablishment fails, you must perform manual trust reestablishment. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the appropriate virtual server.
  4. Under Access Policy, for ADFS Proxy, select the Enabled check box.
  5. Select Establish Trust.
  6. Evaluate the expiration date of the trust certificate.
  7. Provide credentials in UPN format. (domain\username or username@domain.com)
  8. Select OK.

Additional Information

During the trust establishment, the BIG-IP APM system as ADFS proxy generates a 2048 bit self-signed RSA trust certificate, along with the expiration date/time, and registers it with the ADFS server. The certificate is valid for 20 days, and this validity period is not configurable. When ADFS accepts the registration, the certificate is linked to the Server SSL profile of the given virtual server. This means the Certificate and Key parameters of the Server SSL profile are updated with the newly generated Certificate and Key parameters. The trust renewal is initiated when 30 percent or less of the validity time period remains (6 days or less before certificate expires).
