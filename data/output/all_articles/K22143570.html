Description
snmpd is sending debug messages similar to the following to remote syslog server

2020-08-19T19:17:09.040Z <bigip_device_name> debug snmpd[6888]: Check host access for incoming connection UDP/IPv6: [IP address]:59711
2020-08-19T19:17:09.040Z <bigip_device_name> debug snmpd[6888]: Adding connection UDP/IPv6: [address]:59711 to cache at oldest index 3
2020-08-19T19:17:13.020Z <bigip_device_name> debug snmpd[6888]: Check host access for incoming connection UDP/IPv6: [IP address]:64072
2020-08-19T19:17:13.020Z <bigip_device_name> debug snmpd[6888]: Adding connection UDP/IPv6: [address]:64072 to cache at oldest index 5

Environment

  • Remote syslog configured
  • BIG-IP software version 13.1.3.2, 14.0.0-14.0.1

Cause

These unwanted snmpd debug log messages are present due to net-snmp patches for CentOS 6.8 applied to certain BIG-IP version as part of Bug ID 687115 fix.
 
Note: 14.1.0 or higher uses CentOS 7.3 which does not include net-snmp patches for CentOS 6.8; therefore, snmpd debug messages do not appear in 14.1.0 and higher.
 
Recommended Actions
  1. Add a filter to filter out all the debug logs from any daemon by following the steps below, or K13333.
  2. If you don't want to use filter, consider upgrade to 14.1.0 and higher.

How to filter debug messages:

If you want to filter the log messages that the system sent to remote syslog servers, you must first remove the remote-servers statement and then configure a syslog include statement that defines a filter rule and the remote server. To do so, perform the following tasks:

Removing the remote-servers syslog statement (if defined)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To remove the currently defined remote syslog servers, enter the following command:

    modify /sys syslog remote-servers none

  3. Save the change by entering the following command:

    save sys config

Defining a syslog filter to remove debug messages

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To define the desired syslog filter that references the remote server, enter the following command:

    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include none
        iso-date disabled
        kern-from notice
        kern-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg

  3. Replace the include none line with the following syslog filter.
    (In the example below, 10.87.17.66 is the remote syslog IP and UDP port 514 is configured)

    destination d_loghost {
        udp("10.87.17.66" port(514) persist-name(remoteserver0_10.87.17.66));
    };
    filter f_nodebug {
               level(notice..warning);
    };
    log {
            source(s_syslog_pipe);
            filter(f_nodebug);
            destination(d_loghost);
    }

    After adding the filter rule above, the syslog configuration appears similar to the following example:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        clustered-host-slot enabled
        clustered-message-slot disabled
        console-log enabled
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
        filter f_nodebug {
                level(notice..warning);
        };
        destination d_loghost {
                udp(10.87.17.66 port(514) persist-name(remoteserver0_10.87.17.66));
        };
        log {
                    source(s_syslog_pipe);
                    filter(f_nodebug);
                    destination(d_loghost);
        };
        "
        iso-date disabled
        kern-from debug
        kern-to emerg
        local6-from notice
        local6-to emerg
        mail-from notice
        mail-to emerg

    Important: You should use this parameter with caution. The system does not validate the configuration used with the include parameter. If you use this parameter incorrectly, the BIG-IP syslog may fail to function. F5 recommends that you test this in an appropriate environment before implementing in a production environment.

  4. Exit the text editor by entering the following key sequence:

    :wq!

  5. At the following prompt, press y to save the changes to the file:

    Save changes? (y/n/e)

    The tmsh prompt returns.

    Note: If the syslog filter contained syntax errors, tmsh returns the following prompt:

    There were errors. Continue editing (y) or discard changes (n) (y/n)

    The BIG-IP system now sends syslog traffic to the remote server using the defined syslog filter.

  6. Save the configuration by entering the following command:

    save /sys config
