K4159: PeopleSoft portal users may be logged out immediately after logging in

Type
Knowledge
Published
2007-06-25
Updated
2023-02-21
Status
Legacy Content
Applies to
  • Legacy Products
  • FirePass: 6.0.2, 6.0.1, 6.0.0
Source
https://my.f5.com/manage/s/article/K4159

Topic

PeopleSoft sets a cookie, named PS_LOGINLIST, which stores the hostname of the portal server. The client reads the value of this cookie and compares it against the URLs that are accessed from the client browser. If the cookie value does not match the URL that is accessed from the client browser, the PeopleSoft portal logs the user out.

Since the PeopleSoft server is accessed through FirePass, the hostname is changed to the FirePass hostname. As a result, the hostname that is used in the cookie does not match the URL that is accessed by the client and PeopleSoft logs the user out.

Workaround

You can work around this issue using one of the following procedures:

  • Beginning with FirePass version 5.4.1, you can work around this issue by using the Minimal Content Rewriting Bypass feature. For specific configuration instructions, refer to K4746: Overview of the Minimal Content Rewriting Bypass.

  • If you are running a version of FirePass prior to 5.4.1 and upgrading is not an immediate option, you can work around this issue by installing a content processing script. Due to the complex nature of content processing scripts, F5 Networks is not providing specific steps about how to configure the content processing scripts, but offers the following guidelines:

    • The names of the files and functions that you must modify in the content processing script are not the same in every PeopleSoft version. To locate the files and functions to modify in order to create the script, you may need to analyze a packet trace.

    • You need to remove the JavaScript function that performs the comparison of the cookie value to the current URL from the content processing scripts. In the versions that F5 Networks has examined, the function that performs this comparison is called getLoginCookieValue located in the PT_SAVEWARNINGSCRIPT_1.js file.

    • If your implementation contains the getLoginCookieValue located in the PT_SAVEWARNINGSCRIPT_1.js file, create a content processing script with the following settings:

      Processing script name: <any string meaningful to the admin>

      URL match patterns: */PT_SAVEWARNINGSCRIPT_1.js

      Content Type: application/x-javascript

      Sed processing script: s!var val =  
      getLoginCookieValue("PS_LOGINLIST");!var val = 1;!

      Processing: Pre-process response data
