Description

This article explains how the different timeout settings work in the HTTP Load Balancer.

 

Environment

  • F5® Distributed Cloud Load Balancer 

Answer/Recommended Actions

The HTTP Load Balancer has three different timeout configurations: Load Balancer Idle Timeout, Route Timeout, and Origin Pool Idle Timeout.

 

Load Balancer Idle Timeout:

  • Applies to: The connection between the client and the Load Balancer.
  • Impact: If the client remains idle (e.g., during a keep-alive session or slow upload), the Load Balancer will terminate the connection after the configured timeout period.

Route Timeout:

  • Applies to: The internal path between the Load Balancer and any service policy, such as firewall or bot defense.
  • Impact: If there is no activity during this stage (e.g., in long-lived or streaming sessions), the route may be torn down.

Origin Pool Idle Timeout:

  • Applies to: The connection between the Load Balancer and the application (origin).
  • Impact: If the backend takes too long to respond or the connection remains idle (e.g., during slow processing), the Load Balancer will close the connection to the origin.
