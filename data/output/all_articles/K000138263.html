Description

Facing issue reaching to the BIG-IP LTM VS assigned VIP address via Public.
Troubleshooting has shown:

  1. Unable to ping from the network that are at the same subnet as the VS assigned VIP address
  2. Packet capture has shown no ARP/ICMP traffic coming in for the VS assigned VIP address
 

Environment

  • BIG-IP
  • LTM
  • VIP
  • Azure Cloud Portal
  • Secondary IP
 

Cause

Secondary IP for the VIP is not mapped via Azure portal to the BIG-IP VE
 

Recommended Actions

Map the required VIP as secondary IP address via Azure portal to the BIG-IP VE instance. The steps can be refer to the F5 Azure Cloud documentation on how to add secondary IP address for VS.
Microsoft Azure Vnet: Multi-NIC F5 BIG-IP Virtual Edition > Add a secondary IP address for the virtual server

Steps as below which are extracted, may review the documentation link above for details.

Add a secondary IP address for the virtual server
Before you can create a virtual server, you must assign a secondary IP address to the external network interface. You will associate this secondary IP address with the BIG-IP VE virtual server address. For complete details, see Azure documentation.

  1. Using the Azure Portal, under Settings -> Networking, click the external NIC.
  2. Under Settings -> IP Configurations, click Add.
  3. Enter a name (for example, virtual-service-1-ipconfig in the following screenshot).
  4. Set the Private IP Settings -> Allocation, select Static.
  5. Enter 10.0.1.101 for the address, and then click Save.
