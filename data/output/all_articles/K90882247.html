Known Issue

The Traffic Management Microkernel (TMM) may continuously restart after the Virtual Clustered Multiprocessing (vCMP) module is provisioned.

This issue occurs when all of the following conditions are met:

  • Your system has the BIG-IP LTM module provisioned.
  • You attempt to provision the vCMP module.

Impact

Traffic is not processed while TMM continuously restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system is unable to process traffic.
  • TMM continuously restarts and generates a core file in the /var/core directory.
  • An error message similar to the following example is logged to the /var/log/tmm file:

    panic: ../dev/cn1120/n3_compress.c:555: Assertion 'enough n3_comp_dev structs' failed.

Workaround

To work around this issue, you can verify that the vCMP module is licensed and provisioned, and then reboot the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: This procedure restarts the BIG-IP system and should be performed only during a planned maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to System > Resource Provisioning.
  3. Ensure that the Virtual CMP (vCMP) module is licensed, and that it is the only module provisioned.
  4. Log in to the command line of the BIG-IP system.
  5. To save the system configuration, type the following command:

    tmsh save sys config

  6. To reboot the BIG-IP system, type the following command:

    reboot

  7. After rebooting, ensure that the BIG-IP system remains active and displays only two Nitrox 3 compression devices in the /var/log/tmm file:

    notice n3-compress0 PASS 0.1: Nitrox 3 Compression Device
    notice n3-compress1 PASS 0.1: Nitrox 3 Compression Device
