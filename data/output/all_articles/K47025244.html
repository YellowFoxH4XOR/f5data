Known Issue

Compression hardware may stop responding and fail to recover.

This issue occurs when all of the following conditions are met:

  • Hardware compression is enabled on any of the following platforms:
    • BIG-IP 5000
    • BIG-IP 7000
    • BIG-IP 10000
    • BIG-IP 12000
    • VIPRION B2250 blades
  • The BIG-IP system is running Virtual Clustered Multiprocessing (vCMP) guests.
  • The BIG-IP system is experiencing high traffic volume.

Impact

Compression requests are sent to the software compression provider until the Traffic Management Microkernel (TMM) process restarts, which may cause local CPU use to climb.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system logs error messages to the /var/log/ltm file that appear similar to the following examples:

    01010025:2: Device error: n3-compress0 Zip engine ctx eviction (comp_code=0): ctx dropped.
    01010025:2: Device error: n3-compress1 Nitrox 3, Hang Detected: compression device was reset (pci 00:09.1).
    01010025:2: Device error: n3-compress0 Nitrox 3, Too many failed resets: compression device forced down (pci 00:09.2).

  • After the BIG-IP system logs the related error messages, the Nitrox compression device will no longer accept compression requests.
  • The BIG-IP system experiences high CPU utilization.

Workaround

There is no workaround for this issue. However, you can temporarily recover from this issue by restarting the TMM process. To do so, perform the following procedure:

Impact of workaround: Restarting the TMM process temporarily interrupts traffic processing. If the BIG-IP system is configured as part of a high availability (HA) pair, the device may fail over. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigstart restart tmm
