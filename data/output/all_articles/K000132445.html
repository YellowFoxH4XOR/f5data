Description

You have configured an iRule on the BIG-IP doing pool or node selection based on the URI in the HTTP request, but it's not working as expected.

Environment

  • iRule that does a pool or node selection based on the URI
  • BIG-IP LTM

Cause

HTTP/1.1 uses HTTP pipelining. This is a feature in HTTP where the client opens one connection and sends multiple requests through that single connection.

Without OneConnect, the BIG-IP makes the load balancing decision at the start of the connection based on the first request received. This is the only load balancing decision that will be made for the life of the connection unless updated by further iRule commands. 

Recommended Actions

For more information about iRule load balancing based on HTTP requests and detailed recommendations for that configuration refer to K9800: Using an iRule to load balance HTTP requests to multiple pools.
