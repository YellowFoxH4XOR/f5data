Description

This article provides suggestions for troubleshooting when you are experiencing issue accessing the site via the Virtual Server after you migrated the Pool Member (Backend Server) to VMware Cloud on AWS with Mobility Optimized Network (MON) enabled.
 

Environment

  • BIG-IP any version
  • Pool Member (Backend Server) on VMware Cloud with Mobility Optimized Network (MON) enabled
  • Previously working environment
  • Test using another Pool that is not in the VMware Cloud is working
     

Cause

The architectural change could be preventing the Pool Member's (Backend Server) response reaching the BIG-IP. 
 

Recommended Actions

When you experience this issue, you can use the following troubleshooting steps:

  1. On the BIG-IP, verify the Virtual Server Source Address Translation. For example: Auto Map.
  2. Verify the Backend Server's Default Gateway.
  3. Run packet capture simultaneously on the BIG-IP and the Server.
  4. If you notice the following behavior same as below, check the Documentation of the VMware Cloud Mobility Optimized Networking (MON) to ensures routing for traffic remains symmetric.
    • Client-side - Client to the Virtual Server is OK
    • Server-side - Traffic from SNAT IP to the Pool Member is failing. The BIG-IP sends SYN and TCP Retransmission but no response received from Pool Member (looks like asymmetric routing).
    • However, packet capture on the Server shows that it sends the response but it didn't reach the BIG-IP. Additionally, all the retransmissions sent out by the SNAT IP was received by the Pool Member. It always sends the response to all of those but the response (SYN,ACK) was not received by the BIG-IP's SNAT IP.
