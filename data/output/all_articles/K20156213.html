Description

When requirement is to configure email alert for pool/pool member availability status with below customization.

  • To have pool/pool member in message body instead of subject line along with the status of pool/pool member.

  • Below article provides steps to configure email alerts for pool, virtual servers and pool member availability status changes. 
    K59616664: Configuring email alerts for pool, virtual server, and pool member availability status changes

    For e.g. by configuring the alert using above article, entity name and its status (pool/pool member/virtual server) will be added into subject line with generalized message in email body as below:

    Subject as:
    Pool /Common/pool_test member
    /Common/node_test:80 monitor status down. [ /Common/tcp: down;
    last error: /Common/gateway_icmp: No successful responses received before
    deadline. @2020/04/14 00:21:16.  ]  [ was up for 583hrs:50mi...

    message body as:
    A pool member went down

Environment

  • BIG-IP

Cause

None.

Recommended Actions

To customize the email alerts you need to make sure you have configured the SMTP server and /config/user_alert.conf file as per solution article: K59616664

  1. Try to run below command under bash in CLI of BIG-IP to see if it allows to generate any test email:

    mail -s 'Pool Member Down' j.smith@example.com <<< 'Pool /Common/pool_test member /Common/node_test:80 monitor status down.'

    Note: Replace email ID j.smith@example.com with your email ID. This is just a test command to see if you receive an email.
     
  2. Run below command to see if it shows any logs.

    # audit2allow -i /var/log/auditd/audit.log

    Note : Below is sample output of above code.

    #============= sendmail_t ==============
    allow sendmail_t sendmail_exec_t:lnk_file read;
    allow sendmail_t var_run_t:fifo_file { read write };
     
  3. Edit allow.tt file using vi editor.

    vi allow.tt
     
  4. Add below line in allow.tt

    type=AVC msg=audit(1589956280.995:420340): avc:  denied  { read } for  pid=26396 comm="mail" name="sendmail" dev=dm-8 ino=88032 scontext=system_u:system_r:sendmail_t:s0 tcontext=system_u:object_r:sendmail_exec_t:s0 tclass=lnk_file
     
  5. Once done, run below command. 

     # audit2allow -M alertd.allow < allow.tt

    Note : Below is sample output of above code.

    ******************** IMPORTANT ***********************
    To make this policy package active, execute:

    semodule -i alertd.allow.pp
     
  6. Run the command

    # semodule -i alertd.allow.pp
     
  7. Test the mail by running below command and see if you receive an email.

    mail -s 'Pool Member Down' j.smith@example.com <<< 'Pool /Common/pool_test member /Common/node_test:80 monitor status down.'

    Note: Replace email ID j.smith@example.com with your email ID. This is just a test command to see if you receive an email.
     
  8.  Modify /config/user_alert.conf file with below script:

    alert POOLMEMBER_UP "Pool /Common/pool_test member /Common/node_test:80 monitor status up." {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.11";
            exec command="mail -s 'Pool Member Down' j.smith@example.com <<< 'Pool /Common/pool_test member /Common/node_test:80 monitor status up.'"
    }
    alert POOLMEMBER_DOWN "Pool /Common/pool_test member /Common/node_test:80 monitor status down." {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.10";
            exec command="mail -s 'Pool Member Down' j.smith@example.com <<< 'Pool /Common/pool_test member /Common/node_test:80 monitor status down.'"
    }

    Note: Replace email ID j.smith@example.com with your email ID and pool/node names with the respective names on your device. 
    Note :You will need to add script for every pool added on the BIG-IP. (script per pool). above script is only for one pool.
     
  9. Save the user_alert.conf file and restart alertd service by running below command:

    tmsh restart sys service alertd

    Note: Restarting alertd daemon should not have impact. 
     

Additional Information

This only works for versions prior to version 13.1.x, because the mailx rpm is no longer present on the BIG-IP on v15 and above, and the "mail" command will no longer work, as mentioned in K23400624: Script for sending emails no longer works. 


You can verify if the mail package is present on not on the device by running below command:

rpm -qa | grep mailx

Output of the command will look like below:

mailx-12.4-8.el6_6.i686
