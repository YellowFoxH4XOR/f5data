Description

Configuration fails to load after upgrade with this Error Message in /var/log/ltm:

0107186b:3: Invalid "enforce-tls-requirements" value for profile /Common/http2. In Virtual Server <virtual server> an http2 profile with enforce-tls-requirements enabled is incompatible with client-ssl/server-ssl profile with renegotiation enabled. Value must be disabled.

Environment

  • Upgraded to version where Bug ID 794417 is fixed
  • Virtual server with:
    • HTTP/2 profile with enforce-tls-requirements enabled
    • Server SSL profile or Client SSL profile with renegotiation enabled

Cause
Bug ID 794417 was created to prevent an invalid configuration where HTTP/2 profile exists with renegotiation enabled on the Server or Client ssl profile.  If you configure an HTTP/2 profile with renegotiation enabled it will allow the configuration but future renegotiated handshakes will fail.  This error message does not exist in versions prior to where this bug is fixed. However, the configuration is still incorrect and will not function properly. The bug was created to prevent people from misconfiguring their device. Unfortunately that sometimes means that on upgrade the configuration will now fail to load.

Recommended Actions

  1. Reboot to the original boot location using the following command:
    tmsh reboot volume <volume name>

    Example:
    tmsh reboot volume HD1.1

  2. Once booted back to the original location. If a virtual server has both an SSL profile and an HTTP/2 profile modify them so that HTTP/2 does not have enforce-tls-requirements set to enabled where the ssl profile (be it client or serverssl) also has renegotiation set to enabled 

  3. After the configuration has been correct you can either re-install the configuration to the new boot location or use copy config.
    ----For further information about cpcfg utility, please refer to: K14724: Using the cpcfg command to copy a configuration from one boot location to another

  4. If you wish to re-install the software then first delete the old installation.

  5. You can delete that via the command line
    tmsh delete sys software volume <volume name>

    Example (this assumes HD1.2 is going to be the new boot locaiton)
    tmsh delete sys software volume HD1.2

  6. Re-install the software to a new location and then reboot into it.

OR

Note: This method is not officially supported but can work. Please be cautious when using this method.

  1. Run: vi /config/bigip.conf

  2. If a virtual server has both an SSL profile and an HTTP/2 profile modify them so that HTTP/2 does not have enforce-tls-requirements set to enabled where the ssl profile (be it client or serverssl) also has renegotiation set to enabled.

  3. Save and close the file

  4. Run: tmsh load sys config and the configuration should load.
