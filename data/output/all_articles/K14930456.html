Description

A web application may have a flow that allows an attacker to target end users and steal their sessions or other requests on behalf of the victims. Although the attack is executed on the end user who visited the website, the actual flow is in the web application. There are many ways to execute a cross-site scripting (XSS) attack, including evasion and miscellaneous encoding, which makes the attack difficult to detect. The success of an XSS attack also depends on the end user browser type and version.

Environment

  • The application is under an XSS attack.
  • Your system is versioned for BIG-IP ASM 12.x.
  • A security policy is assigned to the virtual server.
  • The BIG-IP ASM request log is enabled by default to the illegal request.

Cause

None

Recommended Actions

BIG-IP ASM can mitigate XSS attacks using the attack signature feature or defined meta characters. These procedures list the steps needed to mitigate XSS attack using the appropriate attack signatures and assumes a default configuration is defined.

Note: Default configuration means a security policy was created using any of the policy templates with transparent and staging period enabled for the policy.

These procedures include steps about how to assign the relevant attack signature set, enable it, and configure it in blocking mode to mitigate the XSS attacks. The final step is the mitigation verification, where the administrator can verify the blocked XSS attack.

Impact of procedure: Adding attack signatures to the security policy can generate false positives. In such cases, you should remove false positives using the Learning page. Adding the XSS attack signatures set includes various types of XSS technology, which allows protection regardless of the back-end infrastructure server.

  • Adding XSS attack signatures to the security policy
  • Switching the security policy to Blocking mode
  • Verifying that the XSS attack is blocked

Adding XSS attack signatures to the security policy

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the Current edited policy list, select the desired security policy.
  4. In the upper-right corner, select Advanced.
  5. To reveal the settings, select Attack Signatures.
  6. Under the Attack Signatures table, select Change.

    The Configuration utility displays the Select Policy Attack Signature Sets page.

  7. Select the Cross Site Scripting Signatures check box, and then select Change.
  8. In the Attack Signatures table, verify that the signature set is enabled for Learn, Alarm, and Block.
  9. Clear the Enable Signature Staging check box.
  10. Select Save, and then select Apply Policy.

Switching the security policy to Blocking mode

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the Current edited policy list, select the desired security policy.
  4. Under General Settings, for Enforcement Mode, select Blocking.
  5. Select Save, and then select Apply Policy.

Verifying that the XSS attack is blocked

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select Show Filters Details.
  4. For Violation, select Attack signature detected, and then select Go.

    The blocked request with cross-site scripting is listed in the request log.

    Note: In the request log, the attack type name is Cross Site Scripting.
