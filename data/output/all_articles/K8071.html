Known Issue

This is the result of a known issue. When the Action on Service Down setting in the pool is set to Reselect, and the pool member is unavailable, BIG-IP LTM reselects the same node rather than selecting the next available pool member.

The Action on Service Down setting specifies the responses from the BIG-IP system when the pool member becomes unavailable. When this action occurs on systems equipped with a single processor, the TMM process can crash.

F5 Product Development tracked this issue as CR85186 and it was fixed in BIG-IP 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM release notes.
