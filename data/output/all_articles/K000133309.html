K000133309: CPU utilization increase after enabling Telemetry Streaming

Type
Support Solution
Published
2023-05-19
Updated
2024-01-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000133309

Description

  • CPU utilization increase after enabling Telemetry Streaming (TS)
  • top command shows icrd_child+ consuming high CPU
  • CPU spike interval matches polling interval. Following snippet of TS declaration, shows 300s (5 minutes) polling interval:

    {
     "class": "Telemetry",
     "My_System": {
      "class": "Telemetry_System",
      "systemPoller": {
       "interval": 300     <------ 300s is equivalent to 5 minutes
      }
     }
     

Environment

  • BIG-IP
  • Telemetry Streaming
  • icrd_child process

Cause

Pushing more than 1K virtual servers configuration to the consumer endpoint causing CPU utilization increase.

Recommended Actions

Consider using the Telemetry Streaming custom endpoints feature.

For example, if you are interested in gathering virtual server stats (mgmt/tm/ltm/virtual/stats), you can reduce CPU consumption by getting just the stats and ignoring the configuration (mgmt/tm/ltm/virtual). You do this by customizing the endpoints as exhibited below:

{
  "class": "Telemetry",
  "My_System": {
    "class": "Telemetry_System",
    "systemPoller": {
      "interval": 300,
      "endpointList": [
        {
          "name": "virtuals",
          "path": "mgmt/tm/ltm/virtual/stats"
         }
       ]
     }
<other declaration contents>
...
  }
}

Note: The previous example shows a snippet of the custom endpoints configuration. It is not a complete declaration.

Additional Information

None.
