Description

In the event that the named process does not start due to syntax or validation errors when processing the config files, the zrd daemon will enter a restart loop. Although zrd restarts are not in themselves directly impacting, the messages related to the restarts (which are logged to the console and terminal every ~2 seconds) can be frustrating when trying to troubleshoot the root cause. The zrd daemon can be temporarily disabled, and then re-enabled once the root cause for named failing to start has been identified and fixed

It is also possible, with certain misconfigurations, for zrd to enter a restart loop while the named process is actually up and running, for example, if the definition of zonerunner's "zrd-acl-000-00x" acl (where x is a digit) has been manually removed from named.conf.

Messages similar to the following may be seen on the serial console and in connected ssh sessions:

2023 Apr 28 11:31:59 gtm-1 logger: Re-starting zrd
2023 Apr 28 11:32:01 gtm-1 logger: Re-starting zrd
2023 Apr 28 11:32:03 gtm-1 logger: Re-starting zrd
2023 Apr 28 11:32:06 gtm-1 logger: Re-starting zrd
2023 Apr 28 11:32:08 gtm-1 logger: Re-starting zrd

In the event that zrd is unable to process the contents of the /var/named/config/named.conf file, messages similar to those below will appear in /var/log/gtm:

/var/log/gtm

Apr 28 11:31:59 gtm-1 notice zrd[11157]: 0115120a:5: zrd[11157] stopping.
Apr 28 11:32:01 gtm-1 notice zrd[11235]: 01151209:5: zrd[11235] starting.
Apr 28 11:32:01 gtm-1 err zrd[11235]:  <descriptive message>
Apr 28 11:32:01 gtm-1 notice zrd[11235]: 0115120a:5: zrd[11235] stopping.

The descriptive message text will vary, but should indicate the nature of the problem, for example

err zrd[11235]: 01150711:3: No views found for Wide IP/Alias '< WideIP Name> .'. ZoneRunner requires at least one view in named.conf.
err zrd[11235]: 0115020b:3: Errors in config file /config/named.conf:60: undefined ACL 'zrd-acl-000-001'

Environment

  • BIG-IP DNS
  • Zone Runner

Cause

The zrd (zonerunner daemon) process interacts with named in order to provide a GUI interface to bind (named). If zrd encounters a critical error, it will simply exit and restart, and if the error is still present, this will result in a restart loop.

Recommended Actions

  1. To temporarily stop the zrd process while troubleshooting the root cause, you can issue one of the following commands:

    tmsh modify sys service zrd disable

    OR

    bigstart stop zrd

    Note that any changes made to files under /var/named/config will automatically restart zrd, even if it was stopped. If such changes are necessary as part of the troubleshooting process, and zrd restart related messages re-appear, zrd can be removed from the startup scripts entirely:

    tmsh modify sys service zrd remove

    OR

    bigstart remove zrd

  2. To re-enable the zrd process after troubleshooting has been completed, use one of the following commands:

    If the zrd process was simply stopped:

    tmsh modify sys service zrd enable

    OR

    bigstart start zrd

    If the zrd process was completely removed, it must first be re-added to the startup scripts, and then started:

    tmsh modify sys service zrd add
    tmsh modify sys service zrd enable

    OR

    bigstart add zrd
    bigstart start zrd
