Description

You want to load balance IPsec concentrators which do not share session state.


You may need to adjust timeouts if IPsec sessions fail after failover or after extended idle periods (several minutes or more).

Environment

  • BIG-IP using UDP or FastL4
  • Pool of IPsec VPN concentrators or gateways
    • NAT-T enabled (required for this configuration)

Cause

IPsec has a large amount of shared state between endpoints, and uses UDP for transport when NAT-T is enabled. BIG-IP needs to be configured to allow the various types of IPSec sessions to persist to the same pool member.

Recommended Actions

  • Ensure that the persistence profile and virtual server both have mirroring enabled, if in an HA environment. This will protect sessions during failover.
  • If using separate port 500 and port 4500 virtual servers, ensure Match Across Services is enabled on the persistence profile.
  • Set timeouts as follows:
    • Set the persistence timeout equal to the ISAKMP lifetime. This may also be referred to as IKE or Phase 1.
    • Set the protocol profile (UDP or FastL4) timeout as follows:
      • If Dead Peer Detection (DPD) is enabled, set the protocol timeout slightly greater than the DPD interval. For example, if the DPD interval is 300 seconds, set the protocol timeout to 315 seconds.
      • If DPD is disabled but traffic initiated from the concentrator or network to the remote endpoint (client) is expected, set the protocol timeout to the IPsec lifetime. This may also be referred to as Phase 2.
      • If traffic is only expected to be initiated from the remote endpoint, the default timeout should be sufficient.
