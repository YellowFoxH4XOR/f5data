Known Issue

When you configure an ARX namespace to use the NFSv3/TCP protocol, the ARX system uses UDP when probing the filer. As a result, if the filer has NFSv3/UDP disabled, clients will be unable to access shares on the filer.

Impact

Clients will be unable to access resources on the affected filer.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The probe will fail with the following message:

    WARNING: The nfs share on <IP Address> (via nfs export /NFS) is not currently available. The
    probing of this share will continue in the background.
  • The syslog file will contain error messages that appear similar to the following example:

    : [SMGMT-TCP] Failed FSINFO NFSv3 call, status: share linux-vol01, (192.168.50.100:/vol01), RPC: Timed out.  Access to volumes hosted by this instance may be degraded.

Workaround

To work around this issue, you can re-enable UDP on the filer. For more information, refer to your server vendor documentation.

Impact of workaround: Unknown; depends on reason for disabling UDP on the filer.
