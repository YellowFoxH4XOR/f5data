Description

You have configured an IPI feed list under Security ›› Network Firewall : IP Intelligence : Feed Lists.

The feed list does not appear to be downloaded successfully. IP addresses on the feed list are not present when queried with show security ip-intelligence info address <ip address>.

A message similar to the following is seen in /var/log/dwbl/dwbld.log when the feed list URL is polled:

dwbld| err|Nov 23 06:57:06.006|12464|CURLER|curler|(null)|CURL failed with error HTTP response code said error

However, a manual curl of the feed list URL from the command line of the BIG-IP retrieves the feed list successfully.

Environment

  • IPI feed list
  • No username/password configured in feed list

Cause

The feed list request from dwbld utilizes curl. An Authorization: Basic header is always present in the requests, even if no username and password are configured. Similar to the following:

Authorization: Basic Og==

In this example, there is no username and password, the base64 Og== decodes to :, the separator for the username and password in HTTP Basic authentication.

Some servers may have a problem with this, and return (for example), a 400 response:

HTTP/1.1 400 Authentication information is not given in the correct format. Check the value of Authorization header.

Bug ID 968953 has been filed to improve this behaviour.

Recommended Actions

Investigate if the server can be changed to accept the Authorization header with an empty username and password.

Alternatively, you may configure a virtual server to handle the feed list requests, and load balance the request to the server that hosts the feed list. Use an iRule to remove the Authorization header. The virtual server's destination address must reside in the same subnet as a self IP.

Additional Information

If a feed list is successfully downloaded, it should be cached in the /var/dwbl/.cache directory.

Restarting the dwbld daemon prompts the system to attempt downloading the feed list again, without waiting for the configured poll interval:

tmsh restart sys service dwbld

Note: There is no impact to traffic.
