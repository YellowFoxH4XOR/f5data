K000151498: NAP -Encoded special characters in the URL are not being blocked

Type
Support Solution
Published
2025-05-23
Updated
2025-05-23
Applies to
  • NGINX Products
  • NGINX App Protect WAF: 4.4.0
Source
https://my.f5.com/manage/s/article/K000151498

Description

NGINX App Protect WAF may not block HTTP requests containing URL-encoded metacharacters (such as %3b representing ;)

For example, a request to /example/a.map;.js is blocked as expected, but /example/a.map%3b.js is allowed 

Environment

NAP

URL encoded

Cause

With metacharsOnUrlCheck set to false, NGINX App Protect does not decode and inspect URL-encoded metacharacters within the URL path for violations

As a result, encoded characters like %3b are not identified as illegal metacharacters and requests containing them are not blocked, even though their decoded equivalents would be.

Recommended Actions

Set the metacharsOnUrlCheck option to true within the relevant section of your security policy.

"metacharsOnUrlCheck": true,

Additional Information

None.
