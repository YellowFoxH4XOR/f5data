K7046: BIG-IP LTM sends traffic to a pool member even though sessions are disabled for the parent node

Published

Known Issue

This is the result of a known issue. When sessions are disabled for the parent node, BIG-IP LTM may send traffic to a pool member when all of the following conditions are met:

  • A health check is enabled for a pool member
  • Sessions are disabled for a parent node address
  • The pool member's health check fails and succeeds in succession

As a result, BIG-IP LTM will send traffic to the pool member although sessions are disabled for the parent node address.

F5 Product Development tracked this issue as CR74063, and it was fixed in BIG-IP LTM 9.3 and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can work around this issue by forcing the node offline, instead of disabling sessions. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Nodes.
  3. Click the node address you want to disable.
  4. In the General Properties section, change the state to Forced Offline (Only active connections allowed).
  5. Click Update.
