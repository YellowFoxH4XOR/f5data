Known Issue

Modifying the monitor configuration using the replace-all-with option may produce an orphaned instance.

This issue occurs when all of the following conditions are met:

  • You have a multi-bladed VIPRION system.
  • You attempt to modify a monitor instance of a BIG-IP DNS (formerly known as BIG-IP GTM) virtual server using the TMOS Shell (tmsh) with the replace-all-with option.

    For example:

    modify /gtm server server1 virtual-servers replace-all-with { test_vs2 { destination 192.168.1.100:80 monitor http } }

Impact

The duplicate, orphaned monitor instance may consume excessive memory and CPU resources. Restarting a secondary slot in the VIPRION system results in a restart loop.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Restarting the secondary slots in the VIPRION system results in a restart loop.
  • In the /var/log/ltm file, you observe error messages similar to the following examples:

    err mcpd[8982]: 01020036:3: The requested monitor instance (/Common/bigip 10.10.10.1 443 gtm-vs) was not found.
    err mcpd[8982]: 01070734:3: Configuration error: Configuration from primary failed validation: 01020036:3: The requested monitor instance (/Common/bigip 10.10.10.1 443 gtm-vs) was not found.... failed validation with error 16908342.

  • The system creates a duplicate, orphaned monitor instance.

Workaround

To work around this issue, you can restart the services on the affected VIPRION platform. To do so, perform the following procedure:

Impact of workaround: Restarting the BIG-IP services may change the primary slot on the affected VIPRION platform. The following procedure disrupts traffic processing, and you should perform it only during a maintenance window.

  1. Log in to the command line of the VIPRION system.
  2. To restart the services on the VIPRION system, enter the following command:

    bigstart restart
