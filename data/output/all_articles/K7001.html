K7001: Security implications of Portal Access options that turn off URL rewriting

Topic

The FirePass Portal Access for Web Applications reverse proxy technology dynamically rewrites the URLs in web pages sent through the reverse proxy to a FirePass user's browser. However, FirePass provides Portal Access configuration options in which the FirePass does not rewrite the URL of the web server responses sent through the reverse proxy. Configuring one of these FirePass options can impact your security and elevate risks from certain types of attacks.

When a web server response is sent through the reverse proxy, the FirePass rewrites the URLs in the web page so that the FirePass hostname replaces the hostname of the URLs. In addition, the web server's original hostname is encoded into the new URL, and the protocol is set to https.

You can turn off the rewriting functionality by using the following FirePass Portal Access features:

  • Split Tunneling

    The Split Tunneling feature, located on the Portal Access: Web Applications: Master Group Settings page, specifies which URLs the FirePass will rewrite and which URLS the FirePass will not rewrite in a web page, based on regular expression patterns. A client's browser accesses the non-rewritten URLs directly, rather than going through the FirePass reverse proxy.

    Note: If a URL is not specified in either list, the web page will not load in the client's browser as a security precaution.

  • <FP_DO_NOT_TOUCH> tags in HTML source

    The <FP_DO_NOT_TOUCH> </FP_DO_NOT_TOUCH> tags specify a section of a web page's content that the reverse proxy will not process. URLs are not rewritten and script functions are not wrapped. A client's browser accesses the non-rewritten URLs directly, rather than going through the FirePass reverse proxy. You can add the tags statically to the web page code, or dynamically by the FirePass using preprocessing scripts.

    The Process content of the FP_DO_NOT_TOUCH element checkbox on the Global Settings tab located on the Portal Access: Web Applications: Content Processing page has been added for troubleshooting and security purposes in FirePass version 5.5.2 of the maintenance release and FirePass version 6.0.1 of the feature release. This setting is enabled by default. Uncheck this checkbox if you are concerned that an attacker could gain access to a web server that is accessible by your users through FirePass.

As with configuration options in any security device, using these configurations can change your security risk level. When selecting these configurations, it is important to understand the security implications, in the context of their organization's security policies and security architecture.

When allowing URLs to pass back to the client's browser without rewriting, the following security issues should be considered:

  • Disclosure of internal information

    If URLs of internal servers were not rewritten, then the hostnames of the servers and paths of the web pages will be visible on the client system, and perhaps cached by the browser, unless a mechanism such as the FirePass Cache Cleaner is employed.

  • Inability to protect or filter a web request

    Users who follow links that are not rewritten will go directly to the link's web server, without first traversing the FirePass controller. As a result, FirePass access control lists are bypassed, and content inspection is not performed on the web page request or any subsequent requests made from links in the content of the web page.

Important: F5 Networks recommends that you use FirePass access control lists (ACLs) to limit users' access to web sites whose content you trust and control, such as an internal web server on which you can perform security audits. F5 Networks strongly recommends using a default deny policy when deploying ACLs for Portal Access Web Applications. A default allow policy with specific deny list patterns could result in unintended access due to misconfiguration or use of alternate encoding for URLs by authenticated attackers. In general, good security practices dictate use of default deny policies for ACLs, just as when you are configuring firewall rules.

If you are running FirePass version 6.0.0 or later, you can enable a default deny policy for Web Applications on the Portal Access : Web Applications : Master Group Settings page. To do so, select Deny from the Default action menu in the Access Control Lists section, then click Update.

If you are running an earlier version of FirePass, you can enable a default deny policy for Web Applications on the Portal Access : Web Applications : Master Group Settings page. To do so, select the Restrict resources accessible via Web Applications check box, enter the allowed URLs in the Allow list, and leave the Deny list empty.
