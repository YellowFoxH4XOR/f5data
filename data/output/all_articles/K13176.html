Known Issue

The BIG-IP GTM system does not perform any validation checks or report an error when an object, such as a pool or node, referenced by an iRule is deleted. For example, if an iRule references a pool, that pool can be deleted without any warning message or log regarding the dependency.

This issue occurs when all of the following conditions are met:

  • An object referenced by an iRule is deleted
  • The iRule is not deleted

Impact

The configuration will fail to load correctly, sync groups may experience failures, and the BIG-IP GTM system may be unable to answer wide IP queries.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380469 on the Diagnostics > Identified > High creen.
  • A BIG-IP GTM server deployed in a high availability configuration may experience a sync storm when the bad configuration is pushed out to other servers
  • Reloading the configuration will fail. For example, running the gtmparse -l command from the command line will result in an error message that appears similar to the following example:

    [root@3400b:Active] config # gtmparse -l
    gtmparse: Initializing ...
    /usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
    /usr/local/gtm/include/base_region.ISP: SUCCESS
    /config/gtm/wideip.conf: SUCCESS
    gtmparse: SUCCESS
    ERROR, recvMCPreply: Got bad result: 01070151:3: Rule [gtm_irule] error:
    line 3: [can't find gtm_pool] [pool gtm_http_pool ]
    line 4: [can't find gtm_pool] [pool gtm_http_pool ]
  • The administrator is not given any warning prior to deleting the object
  • No error messages will appear in the log file

Resolution

Status

F5 Product Development has assigned ID 351938 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.0.0*K2200: Most recent versions of F5 software
HotfixNoneNone

*Important: The fix added to BIG-IP 11.0.0 performs a validation check before deleting an object referenced by an iRule, only if that iRule has been applied to a wide IP. If the iRule is not applied to a wide IP, the administrator can still delete the object silently, but the configuration will load correctly and no sync storm will occur.
