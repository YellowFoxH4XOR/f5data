K000163220: The ASM signature have the different status between the Web GUI and XML policy file or on Policy Diff

Description

When Enable Signature Staging is disabled for a BIG-IP ASM security policy, the BIG-IP ASM may display attack signatures as Enforced in the GUI while Policy Diff report the signature is on staging status. When exported policy to XML format file, the signature option in_staging=true. For example:

<signature signature_id="200013201">

<enabled>true</enabled>

<in_staging>true</in_staging>

</signature>

Environment

  • Product: BIG-IP ASM
  • Enable Signature Staging: Disabled
  • Attack signatures added or updated through an ASM attack signature update
  • Relevant setting: Security > Application Security > Policy Building > Learning and Blocking Settings > Enable Signature Staging
  • Relevant policy page: Security > Application Security > Security Policies > Policies List > [policy] > Attack Signatures

Cause

BIG-IP ASM maintains the effective policy-level staging behavior separately from each signature’s stored individual staging state.

When Enable Signature Staging is disabled:

  • The signature is effectively enforced by the policy.
  • The individual signature-level staging value can remain set to true.
  • The retained value can appear in the exported XML and Policy Diff results.

This design preserves the individual signature state if policy-level staging is enabled again later.

This behavior is tracked by Bug ID 2456229( Policy Diff incorrectly reports signatures as staged after “Enable Signature Staging” is disabled), and is functioning as designed.

Recommended Actions

Enforce selected signatures when staging is enabled

  1. Navigate to Security > Application Security > Security Policies > Policies List > [policy] > Attack Signatures.
  2. Filter the signatures by staging status.
  3. Select the required signatures.
  4. Enforce the selected signatures.
  5. Update and apply the policy.

Handle signatures after an Attack Signature Update

When Enable Signature Staging is enabled:

  • New or updated signatures may enter staging.
  • Signatures can be manually enforced after they are ready.
  • The Enforcement Readiness Period is 7 days by default and can be configured to a shorter interval.
  • With automatic learning, signatures may be enforced automatically when the policy has sufficient traffic and no relevant violations.
  • With manual or disabled learning, signatures generally require manual enforcement after the Enforcement Readiness Period.

When Enable Signature Staging is disabled:

  • New signatures are treated as enforced for traffic processing.
  • The GUI may not provide a staging filter because the effective policy state is enforced.
  • No additional wait is required for traffic enforcement.

Entries that appear only in exported policy data but do not exist in the policy’s Attack Signatures list cannot be enforced from that policy. They can be disregarded because they do not affect traffic processing.

Additional Information

  • The GUI’s effective Enforced status determines how a signature is applied to traffic.
  • in_staging=true in exported policy data does not by itself indicate that the signature is allowing traffic when Enable Signature Staging is disabled.
  • Policy Diff and exported policy data may expose retained element-level staging information that differs from the effective GUI status.
  • Updated signatures may have an enforced version and a staged version concurrently until the updated version is enforced.
