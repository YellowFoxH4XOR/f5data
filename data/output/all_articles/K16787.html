Known Issue

Changing the configuration of a copper small form-factor pluggable (SFP) OPT-0015 module on a BIG-IP 10000 series appliance may cause the bcm56xxd process to restart.

This issue occurs when all of the following conditions are met:

  • The affected BIG-IP platform is the 10000 series with the platform ID D112 or D113.
  • You are using the copper SFP OPT-0015 module on the affected BIG-IP device.
  • You are attempting to change the configuration of the affected network interfaces with either of the following actions:
    • You are modifying the state of the interface to either disabled or enabled.
    • You are modifying the media speed and duplex settings of the interface to auto or to a particular speed-duplex setting (for example, 1000T-FD).

Impact

The bcm56xxd process restarts and the affected interfaces may appear as unpopulated or unknown.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The bcm56xxd process restarts when you attempt to perform a configuration change to the affected interface.
  • The affected interface slot may appear as unpopulated or unknown.
  • You may observe error messages in the /var/log/bcm56xxd file that appear similar to the following example:

    SOC unit 0 attached to PCI device BCM56844_A1
    [bcmLINK.0]Linkscan thread 0x569dab90 starting on unit 0
    soc_phy_i2c_select_mux(0):soc_i2c_start() failed(-1) by 0x55afcae0
  • The bcm56xxd process may generate a core file, which is located in the /var/core directory.

Workaround

There is no work around for this issue. However, you can recover from this issue by forcing the affected BIG-IP system to go offline, rebooting the system, and then releasing the offline status after resuming from the reboot. To do so, perform the following procedure:

Impact of procedure: This procedure requires you to reboot the affected BIG-IP system. F5 recommends performing this procedure only during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. Click Force Offline.
  4. To reboot the affected BIG-IP system, click Reboot.
  5. Wait for the BIG-IP system to resume from the reboot sequence.
  6. Log in to the Configuration utility.
  7. Navigate to System > Configuration > Device > General.
  8. Click Release Offline.
