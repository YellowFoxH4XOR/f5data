Description

You may experience a significant delay when attempting to log in with incorrect credentials on an application using the F5 BIG-IP Access Policy Manager (APM). This delay is observed between the submission of the incorrect login details and the response indicating the failure of authentication on the APM login page. This issue can lead to confusion and may affect user experience adversely.

Environment

  • APM
  • Access Profile

Cause

The primary cause of the observed delay is the configuration of the Minimum Authentication Failure Delay and the Maximum Authentication Failure Delay settings within the APM Access Profile. These settings are intended to prevent rapid successive login attempts, which can be a security measure against certain types of attacks. However, if configured with high values, they can inadvertently cause a significant delay for users upon failed authentication attempts.

For example, this Access Profile named MyAccessProfile was configured with the following delay settings, causing an artificial delay ranging from 60 to 120 seconds:

apm profile access /Common/MyAccessProfile {
    [...]
    max-failure-delay 120
    min-failure-delay 60
    [...]
}

Recommended Actions

To resolve the issue and improve the user experience, it is recommended to adjust these settings to lower values. This can be achieved by following the steps below:

  1. Navigate to Access ›› Profiles / Policies : Access Profiles (Per-Session Policies).
  2. Select the appropriate Access Profile.
  3. Modify the min-failure-delay and max-failure-delay settings to lower values that still provide security against brute-force attacks without significantly impacting user experience. For example, setting them to 2 and 4 seconds respectively.
  4. Save the changes and apply the updated profile.
