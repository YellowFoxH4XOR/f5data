Known Issue

This is the result of a known issue. When upgrading from BIG-IP version 9.x to version 10.x, if you have used a value of host none to remove the remote syslog server definition, the BIG-IP configuration will fail to load completely.

The value of host none when defining a remote syslog server is valid in version 9.4.x, indicating there is no remote server defined. Beginning in version 10.0.0, the BIG-IP will try to resolve the hostname none. When the resolution fails, the remainder of the configuration will fail to load, and an error message that appears similar to the following example is displayed:

Validating the configuration ...
BIGpipe unknown operation error:
01070920:3: Application error for confpp: Syntax OK
STDERR/STDOUT text begins

Starting syslog-ng: Error resolving hostname; host='::'
No destination address set;
[FAILED]
STDERR/STDOUT text ends

May 27 11:48:07 lcanccl2.via.ca.kp.org confpp[4853]: reconfig command FAILURE for unix_config_syslog returned: '/etc/init.d/syslog-ng restart 2>&amp;1'
Stopping syslog-ng: [FAILED]
Starting syslog-ng: [ OK ]
[ OK ]ing httpd: [ OK ]
Stopping syslog-ng:
Starting syslog-ng: [ OK ]

F5 Product Development tracked this issue as CR136243 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or WOM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by removing the remote syslog server definition from the /config/bigip_sys.conf file. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Open the /config/bigip_sys.conf file in a text editor.
  3. Locate the stanza defining the syslog feature, which appears similar to the following example:

    syslog {
    include none
    remote server logserver {
    host none
    }
    }
  4. Remove the three lines defining the remote logserver:

    remote server logserver {
    host none
    }
  5. Reload the configuration by typing the following command:

    bigpipe load
