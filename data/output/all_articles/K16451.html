Known Issue

When receiving an ICMP Fragmentation Needed (Type 3 Code 4) message, the BIG-IP system incorrectly adds an additional 40 bytes to the L4 header length, and calculates the Maximum Segment Size (MSS) 40 bytes smaller than expected.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system has established a TCP connection with a client.
  • The BIG-IP system receives an ICMP Fragmentation Needed message from the client requesting a smaller Maximum Transmission Unit (MTU), for example 1490 bytes.
  • The BIG-IP system sends a TCP packet to the client using an MTU that is 40 bytes smaller, or 1450 bytes.

Impact

You may experience additional network congestion due to smaller packet size.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Packets on the network are 40 bytes smaller than expected.
  • You experience additional network traffic because packets are 40 bytes smaller.

Workaround

To work around this issue, you can disable the Path MTU Discovery setting. To do so, perform the following procedure:

Impact of workaround: This is a global setting that impacts all connections to the BIG-IP system and may have adverse effects on traffic handling that requires a smaller MTU. If you are uncertain about the impact of this modification, contact F5 Technical Support.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To disable the Path MTU Discovery setting, type the following command:

    modify sys db tm.enforcepathmtu value disable
