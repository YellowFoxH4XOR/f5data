In BIG-IP 10.0.0, F5 introduced logical volume management (LVM) to manage disk space. LVM is not backward-compatible with BIG-IP  9.x installations, which use the partitions disk format instead of LVM. If you need to revert a system running 10.x back to a 9.x system, or if you want to run both 10.x and 9.x on the same system, you need to reinstate the partitions disk format.

Before you start

You will perform two installation procedures as part of this reversion process. The first installation reverts the file system to be compatible with 9.x software, and then installs the 10.x software on one of the newly created partitions. The second installation re-installs the 9.x software of your choice. (The 9.x software must be a currently-supported version, for example, 9.3.1 or 9.4.8). Additionally, the installations use different utilities. The 10.x installation uses the image2disk utility. The 9.x installation uses the im utility. You cannot mix-and-match these tools; you must use the appropriate utility, as specified in the procedures.

When you install the 9.x software, you can install the 9.x image on a different partition from the 10.x installation. This allows you to run both 10.x and 9.x software on the same system.

You should make a full backup of your configuration as documented in SOL11318 and copy it to another host.

Reverting the LVM system to a partition layout and installing version 10.x

  1. Connect to the serial console of the BIG-IP system that you want to revert.
  2. Make sure that you have at least one 10.x ISO image inside the /shared/images directory of the BIG-IP system. To list the directory contents, type the following command:

    ls -lah /shared/images

  3. Change directories to the /shared/images directory by typing the following command:

    cd /shared/images

  4. Enter the image2disk command, with the following options:

    image2disk --instslot=<HD1.1 or HD1.2> --format=partitions <BIGIP-10.X.iso>

    In the command, <BIGIP-10.X.iso> is the file name of the BIG-IP 10.x ISO image you have chosen to use for the installation, and --instslot is the location where BIG-IP 10.x will be installed.

    Note: If you are using BIG-IP 10.2.1 or 10.2.2 ISO image for the installation, you must omit the --instslot option due to a change in behavior. For more information, refer to K12561: The image2disk utility --instslot and --format options are now mutually exclusive

    Note: The --instslot option must specify either HD1.1 or HD1.2. During the installation, all mass-storage devices will be reformatted with the version 9.x disk format and only two boot locations will be created by default: HD1.1 and HD1.2. Even if the BIG-IP system currently features additional boot locations (for example HD1.3 and HD1.4), those locations will no longer exist after the disk is reformatted, and supplying one of those locations to the --instslot option will cause the installation to fail. For more information, refer to K10380: The image2disk utility erroneously validates the target location  when the --format option is specified.

    Important: If you do not want the system to copy and install the existing system configuration to the new installation, add the --nosaveconfig option to the image2disk command. This option can be used to prevent the system from trying to install a newer configuration on an older version of the software, which is not an F5-supported action, and will cause the installation to fail. For more information about using the image2disk utility, type one of the following two commands:

    man image2disk
    or
    image2disk --help

The system reboots into the Maintenance Operating System (MOS), re-formats all mass-storage devices with the 9.x disk format, and installs the version 10.x software. Once these operations have been completed, the system boots from the target location where BIG-IP 10.x was installed.

Reinstalling version 9.x software on the reformatted 10.x system

Once you have reformatted the disk layout and reinstalled the 10.x software, you must download the 9.x installation image and use one of the standard 9.x installation methods to install any version 9.x release that the platform supports. For example, you can use the following command syntax to install 9.x software:

im /shared/local-install-<9.X_version_number>.im

When you install the 9.x software, you can install the 9.x image on a different partition from the 10.x installation.

Important: You cannot use the image2disk command to install 9.x software. The installation will fail. You must use one of the 9.x installation methods. For more information, refer to the appropriate 9.x release notes.

Note: For 9.x installation information, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization release notes.

Note: You will not be able to install a 10.0.x UCS file on the version 9.x software.

Getting help if the reversion is not successful

In the event that reverting from LVM back to disk partitions is unsuccessful, F5 Technical Support may require the following diagnostic information:

  1. To list the file system layout, type the following command:

    tmidiag -d

  2. To obtain the installation log file from the most recent 10.x installation, type the following command:

    tmidiag -l > install.log

Considerations for BIG-IP 6900 and 8900 platforms

Due to a series of known issues, the procedures outlined in this Solution may not work on a BIG-IP 6900 or 8900 platform:

  • Using the BIG-IP 10.1.0 ISO image for the first installation procedure will cause the installation to fail and the bootloader to become corrupted. For more information, refer to K11063: Installing BIG-IP version 10.1.0 on a 6900 or 8900 platform fails and corrupts the bootloader.
  • Even if you reverted a BIG-IP 6900 or 8900 system to the partitions disk-formatting scheme using a version 10.x ISO image other than 10.1.0, you may not be able to install 9.4.x on the new partitions. For more information, refer to K11283: In certain cases, BIG-IP version 9.4.x may fail to install on a 6900 or 8900 platform.

If you do not require running both 10.x and 9.x on the same system, you should not revert your BIG-IP 6900 or 8900 system to use the partitions disk-formatting scheme.

If you do require running BIG-IP 9.4.x and 10.x on the same BIG-IP 6900 or 8900 system, do not refer to this Solution; instead, refer to the workaround section of K11283: In certain cases, BIG-IP version 9.4.x will fail to install on a 6900 or 8900 platform.
