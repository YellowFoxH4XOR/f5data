Description

After migrating a BIG-IP configuration from one platform to another using UCS platform-migrate, the new device continuously initiates outbound TCP connections on port 443 to the management IP of the old device. The connections time out and are reset, as confirmed by packet captures showing repeated TCP SYN attempts followed by RST/ACK resets.

Observed symptoms:

  • The new BIG-IP self IP continuously initiates TCP SYN packets to the old device's tenant management IP on port 443
  • Connections fail with [F5RST(peer): handshake timeout] resets
  • The old device's IP addresses are not present as pool members or nodes in the migrated configuration
  • Behavior persists even after ARP table clearing and data cable migration

Example packet capture output:

  • 10.0.0.0 → 172.16.0.0  TCP OUT : 50721 → 443 [SYN]
  • 10.0.0.0 → 172.16.0.0  TCP OUT : 50721 → 443 [RST, ACK] [F5RST(peer): handshake timeout]

Environment

  • BIG-IP LTM
  • Migration via UCS platform-migrate
  • Source BIG-IP device was previously managed by BIG-IQ

Cause

After the UCS platform-migrate, stale BIG-IQ iControl REST framework state from the previous BIG-IQ management relationship was retained on the new BIG-IP. This leftover REST framework configuration caused the new tenant to continuously attempt TCP/443 connections back to the old device's management IP, even though BIG-IQ had been removed from the environment.

Answer/Recommended Actions

Follow this troubleshooting steps prior to clearing the REST framework:

  1. Verify the old device's IP is not referenced as a pool member or node: 
    tmsh list /ltm node | grep <old_mgmt_ip>
tmsh list /ltm pool recursive | grep <old_mgmt_ip>
  2. Check for stale device trust or CM peer references: 
    tmsh list /cm device all
tmsh show /cm device-group
  3. Review all routes (management and data) on the new device for any references to the old device.
  4. If no stale pool members, nodes, or CM references are found and the device was previously managed by BIG-IQ, follow the F5 article "K78734243: Clearing or restoring REST framework from BIG-IP after being managed by BIG-IQ" to remove the stale BIG-IQ iControl REST framework state from the migrated BIG-IP tenant.

Additional Information

This issue is specific to scenarios where the source BIG-IP was previously managed by BIG-IQ. The BIG-IQ iControl REST framework leaves residual state on the BIG-IP device that is carried over during a UCS platform-migrate operation.

Simply removing BIG-IQ from the environment or decommissioning the old device does not automatically clear the stale REST framework references on the BIG-IP tenant.

The stale REST framework state is not visible in standard LTM configuration objects (pool members, nodes, routes, ARP) — it resides within the REST framework layer.

All other traffic may function normally while this issue is present.
