Known Issue

This is the result of a known issue. BIG-IP LTM pool statistics show the current connection count to be higher than the maximum connection count for BIG-IP systems running Clustered Multi-Processing (CMP).

Note: The following BIG-IP platforms support CMP:

  • BIG-IP 8400 (D84)
  • BIG-IP 8800 (D88)

For example, the following output from the bigpipe pool command shows one pool member with 79 current connections, and 55 maximum connections:

+-> POOL MEMBER abcd/aaa.bbb.ccc.ddd:xx   active,up|   |     session enabled    priority 0    ratio 0|   |     (cur, max, limit, tot) = (79, 55, 2500, 4.754M)|   |     (pkts,bits) in = (28.64M, 32.21G), out = (30.51M, 125.0G)|   |     requests (total) = 0+-> POOL MEMBER abcd/aaa.bbb.cc.eee:xx   active,up|   |     session enabled    priority 0    ratio 0|   |     (cur, max, limit, tot) = (66, 57, 2500, 4.311M)|   |     (pkts,bits) in = (25.95M, 29.26G), out = (27.60M, 112.2G)|   |     requests (total) = 0

F5 Product Development tracked this issue as CR82850 and it was fixed in BIG-IP LTM 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.
