Known Issue

This is the result of a known issue. After upgrading a BIG-IP ASM system from version 9.4.x to version 10.1.0 or later, any user-defined attack signature sets will have their Assigned Systems list cleared and will be assigned a generic set of signatures.

Note: This issue only affects user-defined attack signature sets; system-defined attack signature sets are unaffected by this issue and will be assigned to the policy after the upgrade. If signature staging is enabled for the policy, any new or updated signatures will automatically be placed into staging, while any unchanged signatures will be left in enforcement mode.

F5 Product Development tracked this issue as ID 337875, and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP ASM release notes.

This issue has also been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue by recreating any user-defined attack signature sets after the upgrade. After the user-defined attack signature sets have been recreated and assigned to their respective policies, F5 recommends that you go through the attack signature staging process again to ensure that there are no false positives.
