Description

At times the need to access the tenant via a console on a Velos system may occur. This would normally be due to a loss of access via the CLI and GUI at the same time. It is done the same whether the tenant is deployed on a BX110 or BX520 blade.

Environment

VELOS has separate management layers:

  1. System controller — chassis-level management and Bash access
  2. Chassis partition — F5OS partition management through ConfD
  3. BIG-IP tenant — the guest BIG-IP system

Cause

The partition CLI is an F5OS ConfD management CLI, not a Linux shell. Therefore, the partition administrator cannot enter a normal Linux ssh command at the partition CLI prompt to open the tenant console.

It can be accessed via a controller using virtctl.

Note: Console access via the Controller is a virtual serial-console connection. Providing you with direct access to the tenant. Whereas the tenant-console account does not have this direct access. The tenant-console account used by the partition cannot run Linux SSH. The partition-side tenant-console method is an SSH proxy through the partition management IP and is distinct from virtctl.

Answer/Recommended Actions

    Access the tenant console through the system controller. This bypasses the partition management-IP SSH/websocket path.

    1. Log in to the system controller as root from the Bash shell:ssh root@<system-controller-management-IP>Use the controller that is active for the partition if the active controller is known.
    2. Determine the required values:
      • PARTITION_ID
      • TENANT_NAME
      • TENANT_INSTANCE_ID

      The tenant instance ID is obtained from the partition CLI:show tenants tenant <tenant-name> state instances

        1. The output would look something like this...default-2# show tenants tenant examplebigip2 state instances
          state instances instance 1 examplebigip2
           instance-id   1
           phase         Running
           creation-time 2025-01-31T12:30:28Z
           ready-time    2025-01-31T12:30:55Z
           status        "Started tenant instance"
           mgmt-mac      ca:c3:7d:64:30:7e          Then they would be applied to the following command as...PARTITION_ID       = 2
          TENANT_NAME        = examplebigip2
          TENANT_INSTANCE_ID = 1
          The partition-2 namespace comes from the F5OS chassis partition ID. It is not the BIG-IP administrative partition.          For a multi-blade tenant the output may contain multiple instances:default-2# show tenants tenant examplebigip2 state instances
          state instances instance 1 examplebigip2
           instance-id   1
           phase         Running
           status        "Started tenant instance"
          state instances instance 2 examplebigip2
           instance-id   2
           phase         Running
           status        "Started tenant instance"
    3. Run virtctl from system-controller Bash/usr/share/omd/kubevirt/virtctl console -n partition-<PARTITION_ID> <TENANT_NAME>-<TENANT_INSTANCE_ID>
      Example:
      /usr/share/omd/kubevirt/virtctl console -n partition-2 examplebigip2-1      If it is a multi-blade then the corresponding console targets are:/usr/share/omd/kubevirt/virtctl console -n partition-2 examplebigip2-1
      /usr/share/omd/kubevirt/virtctl console -n partition-2 examplebigip2-2
    4. When you are done exit the console with:Ctrl-]
      1. This method is documented in the VELOS console-access section of K65442484. The F5OS-C Tenant Management document also describes tenant-console access, but the controller-side virtctl procedure is most clearly specified in K65442484.

      Additional Information

      The system-controller virtual-console procedure is documented in K65442484: Overview of access to the F5 VELOS system, under VELOS console access → Tenant → Method 1 through system controller.

      The F5OS-C Tenant Management documentation also describes tenant-console access through the partition management IP in Connect to a tenant instance console from the CLI.
