K000162699: HA pair reporting wrong version for pair

Type
Support Solution
Published
2026-07-30
Updated
2026-07-30
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162699

Description

A BIG-IP LTM Virtual Edition high-availability pair may fail configuration synchronization and display stale peer-version information when the VMware virtual network adapter assigned to the HA interface is disconnected.

Potential symptoms include:

  • The HA interface is down and reports no media.
  • tmsh show /cm failover-status reports updates received on only one of two connections.
  • One HA connection reports an error.
  • Configuration synchronization does not complete.
  • The active device displays an incorrect or outdated software version for the standby device.

Environment

  • BIG-IP LTM Virtual Edition HA pair
  • VMware vCenter or ESXi
  • HA/failover traffic configured on a dedicated interface
  • The VMware virtual network adapter assigned to the HA interface is not configured to connect automatically after reboot or power-on

Cause

The VMware virtual network adapter assigned to the HA interface is disconnected or is not configured for automatic connection after reboot. The BIG-IP HA interface remains down with no media, preventing the associated failover and configuration-synchronization traffic from operating.

Recommended Actions

  1. If necessary, place the standby device in offline mode before restoring the HA connection to prevent an unexpected active state.
  2. In VMware vCenter, edit the standby BIG-IP LTM Virtual Edition virtual machine settings.
  3. Identify the virtual network adapter mapped to the BIG-IP HA interface.
  4. Enable the VMware option that automatically connects the adapter after reboot or power-on. Depending on the VMware interface, this option may be labeled Connect, Connected, or Connect at power on.
  5. Confirm that the adapter is connected to the correct port group and HA VLAN.
  6. If required by the virtualization environment, shut down and start the virtual machine to apply the adapter setting.
  7. Verify the HA interface status:
    tmsh show /net interface <ha-interface>
    The interface should report an up status with negotiated media.
  8. Verify that the HA peer can be resolved through ARP:
    tmsh show /net arp
  9. From the active device, initiate a configuration synchronization using the BIG-IP Configuration utility or supported tmsh workflow.
  10. Verify configuration synchronization status:
    tmsh show /cm sync-status
  11. Verify failover connectivity:
    tmsh show /cm failover-status
    Both HA connections should report an Ok status.
  12. Verify peer-device information:
    tmsh show /cm device recursive
    Confirm that the standby device displays its current software version.

Additional Information

The failover heartbeat, CMI configuration synchronization, and peer-device version information depend on communication between the HA devices. If the VMware virtual network adapter used for HA traffic is disconnected, the pair may retain partial connectivity while synchronization and peer-state information remain incomplete or stale.

Configure all VMware virtual network adapters used for BIG-IP HA traffic to connect automatically after reboot or power-on.
