Topic

This article explains the recommended agent placement in per-request policies.

Description

When creating a per-request policy, the placement or flow of the policy agents is important. Per-request policy agents depend on per-flow session variables set or modified by previous agents. When an agent that requires specific per-flow session variables from previous agents is placed in an incorrect flow order, the missing per-flow session variables may cause the policy to fail.

Recommendations

Ensure that the agents of a per-request policy are placed in the following order or the Per-Request Policy may not work as expected:

Protocol Lookup

  • Protocol Lookup > Category Lookup > Response Analytics > URL Filter Assign

Proxy Select

  • Protocol Lookup > Category Lookup > Proxy Select > Response Analytics > URL Filter Assign
  • Protocol Lookup > Proxy Select > Category Lookup > Response Analytics > URL Filter Assign
  • Proxy Select > Protocol Lookup > Category Lookup > Response Analytics > URL Filter Assign

Note: You can add other agents between the noted agents as long as the general flow of the policy agents matches the order recommended in this article.

Protocol Lookup agent

The Protocol Lookup agent should precede the Category Lookup agent in the policy flow. The Protocol Lookup agent provides the ability to branch based on the protocol (HTTP or HTTPS) used by the request traffic. This prevents the policy from using protocol-based agents that do not match the protocol of the request. After the Protocol Lookup agent has determined the protocol of the request, the agent creates many per-flow session variables for use by other Secure Web Gateway (SWG) or URL-specific agents.

Important: In a policy where the Protocol Lookup agent is not at the beginning of the flow, the policy can use mismatched protocols to process requests (for example, using an SSL protocol-based agent on an HTTP request). Protocol mismatches cause the per-request flow to fail and BIG-IP APM sends a TCP reset for the connection.

Category Lookup agent

The Category Lookup agent should follow the Protocol Lookup agent in the policy flow. The Category Lookup agent performs the URL lookup against the URL database.

Response Analytics agent

When a policy requires additional scanning of a request response by the Response Analytics agent, the Response Analytics agent should follow the Category Lookup agent and precede the URL Filter Assign agent in the policy flow. The Category Lookup agent drives the execution of the Response Analytics agent by setting the 'Additional Scanning is needed' per-flow session variable to determine when an accessed URL or host requires additional scanning.

URL Filter Assign agent

The URL Filter Assign agent should follow the Category Lookup and Response Analytics agents (when configured) in the policy flow. The URL Filter Assign agent depends on the per-flow session variables set by the Category Lookup agent. Without these session variables, the URL Filter Assign agent cannot determine the URL Filtering policy enforcement to apply to the request.

Proxy Select

The Proxy Select agent must occur before the Response Analytics and URL Filter Assign, but can otherwise be placed anywhere in the policy flow.
