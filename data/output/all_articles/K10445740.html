Description

VPN connections show immediate and repeating Connection/Disconnection/Re-connection states.

  • When connecting to VPN using BIG-IP Edge Client, you observe the client staying in the Initializing state.
  • When using the browser VPN client to connect, you may observe the browser transitioning to the Disconnected state with the following error message:

    The connection was terminated by the remote computer before it could complete

The %temp%/logterminal.txt file on the Windows computer contains errors similar to the following:

DIALER, 1, , 1579, CURDialer::OnRasCallback(), RAS error (state=RASCS_AuthNotify, error=720: A connection to the remote computer could not be established. You might need to change the network settings for this connection.)

HOST, 48, , 636, CHostCtrl::DispatchVPNEvent, OnError event (message: A connection to the remote computer could not be established. You might need to change the network settings for this connection.)

Standalone, 0,,,, Failed to establish Network Access: "/Common/<network_access_resource>"

Important: The Windows Remote Access Service component is mandatory for F5 VPN software to function properly. For more information, refer to K15453: Error Message: Network Access Connection Device not found.

Environment

  • BIG-IP APM
  • Network Access VPN in Full or Split Tunnel mode
  • BIG-IP Edge Client
  • Microsoft Windows
  • BIG-IP Browser Network Access Client

Cause

There are various causes of the RAS 720 error, and F5 Support has determined that the issue can occur when the WAN Miniport (IP) or Virtual Adapter has been corrupted and/or tampered with. This issue can consistently be reproduced when the WAN Miniport (IP) Virtual Adapter has been disabled in the Windows Device Manager. 

Recommended Actions

Consider rebooting your client device before performing the following procedures. Note that the reboot may resolve the issue but leave the root cause of the issue undetermined.
  • Double-check the RasMan service is running, then restart the service
  • Verify that Wanarp driver is set to start automatically
  • Confirm there are no broken Miniport adapters on the computer
  • Remove and reinstall the F5 Client Components
  • Examine Windows Remote Access Services (RAS) logs
  • Remove and reinstall the "WAN Miniport (IP)" device and drivers
  • Reset the Windows TCP/IP
  • Re-image the local client device

Double-check the RasMan service is running, then restart the service

  1. On the local client device, open Windows Task Manager.
  2. Select the Services tab.
  3. For RasMan, check the Status column to verify the service is running.
  4. Right-click the RasMan service.
  5. Select Restart.
  6. Attempt to establish an access session Network Access VPN connection.
Verify that Wanarp driver is set to start automatically
  1. Using administrator privileges, open a Windows command prompt (CMD).
  2. Enter the following command:

    sc qc wanarp

  3. Auto start is set if it shows:

    start_type = 2 AUTO_START

  4. If it is not the case, run the following command:

    sc config wanarp start= auto          

    Note: the space after '=' is mandatory

Confirm there are no broken Miniport adapters on the computer

This error could be due to a broken Miniport adapter on the computer. Complete this procedure to confirm there is no broken Miniport on the workstation:

  1. From the Windows Control Panel, open Device Manager.
  2. Go to View > Show hidden devices.
  3. Expand the Network adapters section.
  4. Confirm there are no yellow exclamation marks <!> over the adapter icons.

Remove and reinstall the F5 Client Components

Note: The Client Troubleshooting Utility (CTU) is required to complete this procedure. For more information, refer to K12444: Overview of the Client Troubleshooting Utility for Windows.

  1. Launch the CTU (f5wininfo.exe).
  2. To remove the APM Client Components:
    1. Select the Tools tab.
    2. Select Remove Components.
    3. Remove any F5 components listed in Add/Remove Programs.
  3. Delete any BIG-IP APM VPN adapters that have been added by launching Windows Control Panel and going to Network and Internet > Network and Sharing Center > Change adapter settings.
  4. Right-click each F5 Networks VPN adapter and select Delete.
  5. Reboot the Windows device.
  6. Reinstall the BIG-IP APM Client Components with local device administrator rights.
  7. Attempt to establish an access session Network Access VPN connection.

In some cases, you may need to manually remove the BIG-IP APM client components. To do so, use the Manually removing BIG-IP APM client components procedure in K8253: Removing BIG-IP APM client components from Windows client systems.

Examine Windows Remote Access Services (RAS) logs

The Windows Remote Access Services (RAS) logs may contain information to explain the 720 error.

  1. Using Administrator privileges, open a Windows command prompt (CMD).
  2. To enable RAS logging, enter the following command:

    netsh ras set tracing * enabled

  3. Attempt to establish an access session Network Access VPN connection.
  4. Stop RAS logging by entering the following command:

    netsh ras set tracing * disabled

  5. In the c:\windows\tracing folder, examine the log files to search for anomalies.

    For more information about enabling RAS tracing, refer to K11135300: Enabling RAS Tracing on Windows when troubleshooting BIG-IP APM network access issues.

Remove and reinstall the "WAN Miniport (IP)" device and drivers

  1. From the Windows Control Panel, open Device Manager.
  2. Expand the Network adapters section.
  3. Right-click WAN Miniport (IP).
  4. Select Uninstall device.
  5. Scan for Hardware changes. Windows should add back the "WAN Miniport (IP) and driver.
  6. After completing the driver update process, reboot and attempt to establish an access session Network Access VPN connection.

    Note: When running the F5 Network Access Diagnostic, the CTU Report collected from the Windows machine, log messages containing the following may indicate Windows driver issues:

    VPN Driver installed
    IP Filter Driver installed
    RAS device for VPN not installed

Reset the Windows TCP/IP

  1. Using administrator privileges, open a Windows command prompt (CMD).
  2. Enter the following command:

    netsh int ip reset

  3. Restart the computer after the reset process finishes.
  4. Attempt to establish an access session Network Access VPN connection.

Re-image the local client device

If the RAS 720 error continues to occur after completing the previous troubleshooting procedures, re-imaging the computer has been shown to resolve this issue.
