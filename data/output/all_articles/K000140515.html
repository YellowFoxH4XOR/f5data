Description

Guide for load balancing RADIUS traffic via profiles radiusLB and radiusLB-subscriber-aware

 

Environment

  1. load-balancing Virtual Server using radiusLB
  2. load-balancing Virtual Server using radiusLB-subscriber-aware with a persistence attribute

 

Cause

Configure load-balancing Virtual Server using radiusLB and/or radiusLB-subscriber-aware with a persistence attribute

 

Recommended Actions

Steps for a standard virtual server.

  1. Create a custom RADIUS profile by navigating to: Local Traffic > Profiles > Services > RADIUS
    1. Click create
    2. Name it
    3. Select radiusLB or radiusLB-subscriber-aware as the Parent Profile and configure custom settings based on your requirements and click finished.
  2. Create a pool by navigating to: Local Traffic > Pools > Pool List
    1. Click create
      • Name it
      • Select desired load balancing method
    2. Add members:
      • Enter an optional node name
      • Enter RADIUS server's IP address
      • Enter the port the RADIUS servers are expecting traffic on (default is 1812)
    3. Repeat for each member needed in the pool
    4. Click Finished when done entering members.
  3. Create virtual server by navigating to: Local Traffic > Virtual Servers > Virtual Server List
    1. Click create
      • Name it
      • Configure dest addr/port
    2. Under the Configuration section set it to Basic then:
      • Select "Protocol" and change to UDP
      • Select "Source Address Translation" and change it to Automap (This can be SNAT if wanting to configure it with a SNAT pool)
    3. Go back to Configuration and switch it from Basic to Advanced (setting it to basic just made it easier to find previous entries)
    4. Scroll down until you find: "RADIUS Profile" and select your custom profile created earlier.
    5. Scroll down until you find: "Default Pool" and select your RADIUS pool.
    6. Select finished.

 

When configuring the BIG-IP, if there are any questions about fields or configurations there is a dynamic Help tab in the upper-left portion of the GUI that can be very informative that changes depending on the page.

 

Additional Information

Some clarification on persist attribute field on the radiusLB profile:

 

The field is expecting an AVP code from 1 to 255. In RFC2865, there is a list of RADIUS Attribute Value Pairs (AVP). IANA extends the list available in the RFC from 1-63 in the RFC to 1-255 in the IANA page. You can find the extended list in the "RADIUS Attribute types" section at:

https://www.iana.org/assignments/radius-types/radius-types.xhtml
