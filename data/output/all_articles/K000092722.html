K000092722: Alarm race condition

Type
Support Solution
Published
2022-11-26
Updated
2022-11-26
Source
https://my.f5.com/manage/s/article/K000092722

Description

  • When an event happens like a disconnection or a down component or peer an alert is raised to the NMSAgent. Once it gets resolved, a corresponding alert is raised to the NMSAgent to clear the initial alert. 
  • A race condition is when a series of alarms are raised, while most of the alarms are registered, one or two of the alarm might be missed out. For example, a down alarm is raised for a component and in a split second another up alarm is raised for the same component. However, the down alarm is registered and the up alarm is missed. As a result, the NMSAgent only remembers the down alarm and the Webui will display the same false alarm.

Environment

  • SDC 5.1 
  • NMSAgent

Cause

NMSAgent JVM is unable to process such large amount of data to process.

 Recommended Actions

1. First check if the alarm is indeed false. If the alarm is about 2 components being disconnected then check the netstat output for the components IP address to see if it is indeed down. If the alarm is about a component being down then check monit summary output if the component is indeed down or not.

2. Once you have determined that it is a false alarm, you can restart the NMSAgent component to clear the alarm. 
monit stop NMSAgent
monit start NMSAgent

3. If restarting the NMSAgent does not clear the alarm, the next step you can take is to perform the procedures below to clear it from the Cassandra DB.
