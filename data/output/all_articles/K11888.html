K11888: Optimized TCP profile settings are not saved to the bigip.conf configuration file

Known Issue

When a virtual server is created using the BIG-IP WOM Quick Start utility, optimized server-side and client-side TCP profiles are applied to the virtual server configuration. However, if the configuration is subsequently loaded using the bigpipe load command, some of the customized profile settings revert to their default values.

Note: The bigpipe load command is invoked upon failover, upon running it manually, and after synchronizing the configuration to a member of a redundant pair.

For example, the following virtual server is created by the Quick Start utility to optimize traffic for the VMotion application:

virtual vmotion_optimized {
   srcport change
   destination any:8000
   mask 0.0.0.0
   ip protocol tcp
   profiles {
      isession-vmotion {
         serverside
      }
      wom-tcp-lan-optimized {
         clientside
      }
      wom-tcp-wan-optimized {
         serverside
      }
   }
   vlans {
      VMAdmin
      lan
      nfsnet
      vmotionNet
   } enable
}

The virtual server references the following wom-tcp-wan-optimized TCP profile, which is a customized version of the tcp-wan-optimized profile:

profile tcp wom-tcp-wan-optimized {
   defaults from tcp-wan-optimized
   delayed acks disable
   proxy mss disable
   selective nack enable
   slow start disable
   bandwidth delay disable
   nagle enable
   pkt loss ignore rate 10000
   pkt loss ignore burst 8
   proxy buffer low 131072
   proxy buffer high 196608
   idle timeout 600
   send buffer 819200
   recv window 819200
}

After loading the configuration using the bigpipe load command, the send buffer and receive window settings are both reset to their default value of 458,752.

For example:

profile tcp wom-tcp-wan-optimized {
   defaults from tcp-wan-optimized
   delayed acks disable
   proxy mss disable
   selective nack enable
   slow start disable
   bandwidth delay disable
   nagle enable
   pkt loss ignore rate 10000
   pkt loss ignore burst 8
   proxy buffer low 131072
   proxy buffer high 196608
   idle timeout 600
   send buffer 458752
   recv window 458752
}

F5 Product Development tracked this issue as ID 226686 and ID 324380 (formerly CR141977) and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP WOM release notes.

Additionally, this issue has been fixed in cumulative Hotfix-BIGIP-10.2.0-1755.1-HF1, which has been issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing version 10.x hotfixes, refer to K10025: Managing BIG-IP product hotfixes (10.x).

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by saving the configuration manually after creating the virtual server. To do so, log in to the command line and type the following command:

bigpipe save

Alternatively, you can manually edit the bigip.conf file to include the desired profile settings. After editing the file, reload the configuration using the bigpipe load command.
