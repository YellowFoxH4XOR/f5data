You should consider using this procedure under the following condition:

  • You want to refer to predefined resources with an F5 Application Services 3 Extension (AS3) declaration.

When creating an AS3 declaration, you can refer to predefined resources such as iRules, profiles, SSL certificates, and SSL keys. You may need to do this if, for example, you want to apply the same iRule to multiple applications with an AS3 declaration. This article describes the correct syntax to use to reference existing configuration objects. For more information, refer to the Which existing objects can AS3 reference in the Common partition? section in the AS3 FAQ.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have read the AS3 User Guide.
  • You have installed AS3 on your target BIG-IP system.

Procedures

Reference an existing configuration object in an AS3 declaration

The following basic procedure describes how and where to reference an existing object when composing a declaration.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use a code editor such as VSCode to create an AS3 declaration.
  2. Optional: If you are using VSCode, add a $schema property and refer to the specific schema for the AS3 version you are using to validate the declaration. For example:

    "$schema": "https://raw.githubusercontent.com/F5Networks/f5-appsvcs-extension/master/schema/3.23.0/as3-schema.json",

    Note: For more information, refer to Validating a declaration.

  3. Add classes to your declaration. In each class, when needed, reference an existing object by using the bigip property with the path to the object as the value and enclose them in braces. The following are examples of some of the ways you can reference an existing object.

    An iRule in a service class:

    "myService": {
        "class": "Service_HTTP",
        "virtualAddresses": ["10.2.2.2"],
        "pool": "web_pool",
        "iRules": [ {"bigip": "/Common/example_irule"} ]
    }

    A certificate and key in a certificate class:

    "demo_cert": {
        "class": "certificate",
        "certificate": {"bigip": "/Common/Demo-Certificate.crt"},
        "privateKey": {"bigip": "/Common/Demo-Certificate.key"}
    }

    An iRule in a FAST template or Ansible template:

    "myService": {
        "class": "Service_HTTP",
        "virtualAddresses": "{{virtual_address}}",
        "pool": "web_pool",
        "iRules": [ {"bigip": "/Common/{{existing_irule}}"} ]
    }
  4. Save and deploy your declaration.

Example AS3 declaration with bigip property

{
"$schema": "https://raw.githubusercontent.com/F5Networks/f5-appsvcs-extension/master/schema/3.23.0/as3-schema.json",
"class": "AS3",
"action": "deploy",
"persist": true,
"declaration": {
    "class": "ADC",
    "schemaVersion": "3.23.0",
    "id": "useexistingirule1",
    "label": "useexistingirule1",
    "updateMode": "selective",
    "AS3-partition":{
        "class": "Tenant",
        "Application1":{
            "class": "Application",
            "myService": {
                "class":"Service_HTTP",
                "virtualAddresses": ["10.2.2.2"],
                "pool": "web_pool",
                "iRules": [
                    {"bigip": "/Common/example_irule"}
                ]
            },   
            "web_pool": {
                "class": "Pool",
                "members": [
                    {
                        "servicePort": 80,
                        "serverAddresses": ["192.0.2.1"]
                    }
                ]
            }
       }   
   }   
}
}

Note: This example declaration uses an AS3 3.20 and later schema, where the default template in the Application class is generic. The generic template eliminates the requirement to name your service, serviceMain.
