Description

After an upgrade, there is some recent configuration changes that is now missing.

 

Environment

  • BIGIP All versions
  • HA cluster

 

Cause

When the software upgrade is installed, it will take a snapshot of the current configuration as it is then, and this snapshot will be used as the configuration when you finally reboot into the new version.

 

Thus, if you install the upgrade in advance of when you plan to go live with that version, any changes made to the configuration between the install date and the go live date could effectively be lost.

Because of this, you have the option to make a snapshot again when you reboot, so that you can take the most up to date configuration.

It should also be noted that when the device is rebooted and the config is loaded, there is a commit time applied to the configuration, which is like a virtual timestamp, and out of the pair, this will be identified as the most recent configuration, (whether it is or not) so care should be taken when performing a config sync.

 

Recommended Actions

When booting into an upgraded version for the first time, and especially if it is some time after the upgrade software was initially installed, you should use the copy config option to ensure that you have the most up to date configuration deployed in the new version.
