Note: This Solution assumes that you know how to create a pool, set up cookie persistence, create a virtual server and an SSL proxy, and generate or install an SSL certificate. If you do not know how to perform these procedures, refer to the BIG-IP manual or contact F5 Networks Support for assistance.

When configuring persistence across services (from HTTP to HTTPS, for example), and simple persistence is not an option, you can maintain persistence by configuring an HTTP virtual server and an SSL proxy that points to a loopback virtual server which uses the same pool. Since the cookie name is based on the pool name, and provided the HTTP virtual server and SSL proxy are on the same IP address, this will keep the client persisted to the same server as the client transitions from HTTP to HTTPS.

To set up persistence across services, perform the following procedure:

  1. Create a pool.

    For example:

    bigpipe pool my_https_and_http_pool { lb_mode rr member 192.168.1.1:0 member 192.168.1.2:0 }

    In this example, you created a pool with two members, 192.168.1.1 and 192.168.1.2, that use the round robin load balancing method and have port 0 enabled.

  2. On the pool, enable ports 80 and 443, by typing the following command:

    b service 80 443 tcp enable

    Note: If you do not enable the ports, you will not be able to add virtual servers to the pool.

  3. Configure cookie persistence.

    For example:

    b pool my_https_and_http_pool modify { persist cookie cookie_mode insert cookie_expiration 0d 00:00:00 }

    Note: The timeout value for the cookies is written as <days>d hh:mm:ss.

  4. Create a virtual server and point it at the pool that you created in step 1.

    For example:

    bigpipe virtual 10.1.1.1:80 use pool my_https_and_http_pool

  5. Create a temporary certificate on, or copy your permanent certificates to, the BIG-IP. The key goes in the /config/bigconfig/ssl.key/ directory and the certificate goes in /config/bigconfig/ssl.crt/ directory.
  6. After you install the certificate and key that you want to use, bind the proxy to the virtual server, key, and certificate. You can do this in one of two ways.
    • Option 1

      Create an SSL proxy that points to an external virtual server or create a virtual server on the loopback interface and point the SSL proxy at the loopback virtual server (for example: 127.0.0.x).

      Warning: Do not create the loopback virtual server on 127.0.0.1, as this address is used internally by the BIG-IP; attempting to create a virtual server using this address will have a negative impact on traffic.

      For example:

      Run the following command to bind the proxy to 10.1.1.1 (external network) and to the virtual server that you previously created (on the external network).

      bigpipe proxy 10.1.1.1:443 target vip 10.1.1.1:80 clientssl enable key myserverkeys.com.key cert myserverkeys.com.crt

      This command uses myserverkeys.com.key to encrypt data and myserverkeys.com.crt to decrypt data.

    • Option 2
      1. Create a second virtual server on the loopback interface.

        For example:

        bigpipe vip 127.0.0.10:80 use pool my_https_and_http_pool

      2. Bind the proxy to the virtual server, key, and certificate.

        For example:

        bigpipe proxy 10.1.1.1:443 target vip 127.0.0.10:80 clientssl enable key myserverkeys.com.key cert myserverkeys.com.crt

  7. Test the virtual server and make sure that your connections are persisting from HTTP to HTTPS.
