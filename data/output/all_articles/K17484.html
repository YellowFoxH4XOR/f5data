Known Issue

DNS zone transfers fail when you use ZoneRunner's Transfer From Server method and the remote server is running Windows 2003.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has the BIG-IP GTM module licensed.
  • You used ZoneRunner to create a new zone, and chose Transfer From Server for the Records Creation Method.
  • The configured remote server is running the Windows 2003 operating system.

Impact

Zone transfers from remote DNS servers fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Zone file transfers from remote DNS servers are failing.
  • Errors similar to the following  appear in the /var/log/gtm file after you attempt to create a new zone:

    01150213:3: Zone 'example.com.' in file 'db.external.example.com' contains errors: zone example.com/IN: has 0 SOA records. zone example.com/IN: has no NS records. zone example.com/IN: not loaded due to errors.

Workaround

To work around this issue, you can obtain the zone file from the remote server using the dig command and using ZoneRunner's Load From File method. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of your local desktop computer.
  2. To obtain the zone file from the remote DNS server, use the following syntax:

    dig @axfr server_name zone_name > zone_file.txt

    For example, to obtain the zone file for example.com from the remote server 192.168.10.100 and store the output to example.txt, you would type the following command:

    dig @axfr 192.168.10.100 example.com > example.txt

  3. Add the new zone using ZoneRunner's Load From File Records Creation Method by choosing the newly created .txt file.
