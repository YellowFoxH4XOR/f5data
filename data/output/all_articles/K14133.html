Known Issue

The BIG-IP PSM system may return an SMTP 500 syntax error message. This issue occurs when all of the following conditions are met:

  • A virtual server is associated with an SMTP profile that has Protocol Security enabled.
  • The virtual server receives a client SMTP command in more than one TCP packet.

Typically, an SMTP client sends an SMTP command in a single TCP packet. For example, most clients send the SMTP HELO my.example.com command in one TCP packet. Some clients may send an SMTP command in multiple TCP packets. For example, a Windows Telnet client sends the SMTP HELO my.example.com command in 19 separate TCP packets because it sends out each character in a TCP packet.

Note: In BIG-IP 11.5.0 and later, Protocol Security Module (PSM) is discontinued as a separate module and FTP and SMTP security are available in the BIG-IP ASM system.

Impact

The SMTP client connection will fail.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The SMTP client receives an SMTP 500 syntax error response from your BIG-IP PSM system for each SMTP command sent.

Workaround

To work around this issue, you can create an iRule to buffer the SMTP command into a single TCP packet before being processed by the BIG-IP PSM system. To do so, create an iRule similar to the following example:

Impact of workaround: The following example iRule may not apply to all environments. F5 recommends you create an iRule that works best for your application environment. Additionally, adding an iRule will increase the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

when CLIENT_ACCEPTED {
TCP::release
TCP::collect
}
when CLIENT_DATA {
set cdata [TCP::payload]
if { [ string length $cdata ] <= 0 } {
return
}
if { not ( $cdata contains "\r\n" ) } {
return
}
set cehlo [string trim [TCP::payload]]
TCP::payload replace 0 [string length $cehlo] ""
TCP::payload replace 0 0 $cehlo
TCP::release
TCP::collect
}
