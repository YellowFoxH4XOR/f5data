Known Issue

A VIPRION system's secondary blades may continually restart when the default route domain value for an administrative partition is not 0 (zero).

This issue occurs when all of the following conditions are met:

  • You have a VIPRION system with two or more installed blades.
  • Your configuration includes one or more non-default route domains.
  • Your configuration includes one or more administrative partitions with the default route domain ID set to a value other than 0 (zero).
  • You load a configuration that sets the administrative partition's default route domain ID to a value other than the previously saved ID. For example, you restore a user configuration set (UCS) file.

Impact

All processes on the secondary blades continually restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After loading your configuration, all of the secondary blade's processes continually restart.
  • When you log in to the secondary blade, you observe error messages logged in the shell which appear similar to the following examples:

    slot4/localhost emerg logger: Re-starting tmm
    slot4/localhost emerg logger: Re-starting tmm1
    slot4/localhost emerg logger: Re-starting tmm2
    slot4/localhost emerg logger: Re-starting tmm3
    slot4/localhost emerg logger: Re-starting bigd
    slot4/localhost emerg logger: Re-starting named
    slot4/localhost emerg logger: Re-starting statsd
    slot4/localhost emerg logger: Re-starting alertd
    slot4/localhost emerg logger: Re-starting merged

Workaround

To work around this issue, you can restore the BIG-IP configuration to factory default settings prior to loading a configuration with a different default route domain on an administrative partition. For more information, refer to K13127: Restoring the BIG-IP configuration to factory default settings (11.x - 12.x).

Impact of workaround: Restoring the BIG-IP configuration to factory default settings removes all local traffic objects, network configuration, and module data from the BIG-IP system.
