Known Issue

The IMAP monitor fails when monitoring a Courier IMAP server and no messages exist in the monitored mailbox.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration includes a pool that uses an IMAP monitor.
  • One of the monitored pool members is a Courier IMAP server.
  • There are no mail messages in the mailbox of the monitored Courier IMAP server.

Impact

Monitored pool members are marked down or offline, and are unavailable for load balancing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The IMAP monitor continuously reports the Courier IMAP server status as down or offline.
  • When you enable the IMAP monitor's debug log level, error messages similar to the following example appear in a file created specifically for the monitor using the following syntax: /var/log/<monitor_type>_<ip_address>.<port>.log.

    error code: 8 FTP: weird server reply

Workaround

To work around this issue, you can add a mail message to the monitored mailbox of the Courier server.

Impact of workaround: Performing the suggested work around should not have a negative impact on your system.
