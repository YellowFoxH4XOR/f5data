K000162029: Can the Customer Endpoint IP of a GRE tunnel be changed?

Description

Does the XC platform allow for a GRE endpoint to be changed once the tunnel is deployed? This process explains the steps needed to replace the customer GRE endpoint of an existing tunnel configuration.

 

Environment

  • DDOS 

Cause

 ISP/providers change, device replacements or simply a modification in the assigned IP space could incur in a different IP used for terminating GRE tunnels on the customer side.

 

Answer/Recommended Actions

While updating a GRE tunnel endpoint is generally a transparent process with low risk of traffic disruption, it's strongly advised reviewing how prefix advertisements are configured and distributed prior to any changes. This is particularly important for customers advertising prefixes over a single session. To mitigate risk, consider adding redundant advertisements across multiple tunnels or configuring backup announcements with your provider.

 

To modify the GRE endpoint of an existing tunnel, follow the next steps:

  1. Inside the Tunnels section, from the Actions menu, select the Manage Configuration option.
  2. Click on Edit configuration on the top right corner.
  3. Enter the new Customer endpoint IP, as shown below (The Tunnel type cannot be changed).
  4. Click on Save Tunnel.

Please note that with this method, once saved, a complete deployment can take up to an hour. Additionally, the old configuration (previous GRE endpoint) will continue to be active until the change is fully deployed.

 

Alternatively, the configuration can also be cloned into a new object, the steps are:

  1. Inside the Tunnels section, from the Actions menu, select the Clone Object option.
  2. Enter the new Customer endpoint IP, as shown below (In this case, the tunnel type can be changed)
  3. Click on Save Tunnel

Be aware that this method may result in a change to F5's GRE endpoint and BGP interconnects, both of which would then need to be updated on the customer device. Still, this approach typically requires significantly less deployment time than updating an existing tunnel.
