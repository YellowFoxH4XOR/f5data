Description

When you assign a new custom http monitor to a pool, the servers are marked as unavailable.

However, when when you curl from the BIG-IP command line, to the monitor send string configured, it is successful.

On a packet capture of the monitor traffic, you can see the HTTP probes going out as expected to the pool member and the pool member responding with the expected recv string.

Environment

  • Newly created HTTP monitor

Cause

Incorrect monitor configuration, using the reverse option as enabled, when it should be disabled.

The Reverse option, instructs the system to mark the target resource down when the test is successful. This setting is useful, for example, if the content on your web site home page is dynamic and changes frequently, you may want to set up a reverse ECV service check that looks for the string Error. A match for this string means that the web server was down. To use this option, you must specify values for Send String and Receive String.

Yes / Enabled: Specifies that the monitor operates in reverse mode.

No / Disabled: Specifies that the monitor does not operate in reverse mode.

Recommended Actions

Disable the reverse option on the newly created monitor.

Additional Information

On the command line of the BIG-IP or on the qkview file, you might see this option as the example below with tmsh list /ltm monitor http all-properties:

ltm monitor http /Monitoring/<Monitor_Name> {
    adaptive disabled
    defaults-from /Common/http
    destination *:*
    interval 5
    ip-dscp 0
    recv 200
    recv-disable none
    reverse enabled → Note!
    send "GET /examplestring HTTP/1.1\r\nHost: \r\nConnection: Close\r\n\r\n"
    time-until-up 0
    timeout 16
}
