Description

You may find stale connection at CLOSE_WAIT on loopback interface after GUI access, or REST API access.

The stale connection in the output of command line is following.

netstat -nap | grep CLOSE_WAIT | grep httpd

tcp        1      0 127.0.0.1:60818         127.0.0.1:8100          CLOSE_WAIT  1094/httpd
tcp        1      0 127.0.0.1:49346         127.0.0.1:8100          CLOSE_WAIT  11465/httpd
tcp        1      0 127.0.0.1:56930         127.0.0.1:8100          CLOSE_WAIT  24112/httpd
tcp        1      0 127.0.0.1:56924         127.0.0.1:8100          CLOSE_WAIT  24103/httpd
tcp        1      0 127.0.0.1:55880         127.0.0.1:8100          CLOSE_WAIT  1306/httpd
tcp        1      0 127.0.0.1:56932         127.0.0.1:8100          CLOSE_WAIT  24111/httpd
tcp        1      0 127.0.0.1:37014         127.0.0.1:8100          CLOSE_WAIT  1091/httpd
tcp        1      0 127.0.0.1:45942         127.0.0.1:8100          CLOSE_WAIT  24140/httpd

 

Environment

BIG-IP all version

Cause

The stale connection is left because of httpd ProxyPass reuse or keepalive feature. 

You do not need to care about the stale connection, those connection is deleted when next request comes in.

The reuse and keepalive feature is enabled by default, there is not configuration option for httpd to disable the feature.

Recommended Actions

None
