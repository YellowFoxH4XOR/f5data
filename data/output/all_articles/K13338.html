Known Issue

The Traffic Management Shell (tmsh) may incorrectly allow a management IP address to be created on a subnet that overlaps with the subnet of an existing self IP address.

This issue occurs when all of the following conditions are met:

  • A management IP address is defined with a subnet that overlaps the subnet defined for a self IP address.
  • The self IP address is not set to be a Mirroring Address.

For example, if the system is configured with the self IP address of 10.1.1.1/24, and a user attempts to set the management IP address to 10.1.0.2/16, the system allows the address to be set, creating an invalid and unsupported configuration.

Impact

An unsupported network configuration may be created on the BIG-IP system, and the system configuration may fail to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Prior to a configuration load operation, the unsupported configuration with overlapping network segments results in unexpected network behavior.
  • The system cannot load after a configuration reload, system reboot, or user configuration set (UCS) archive installation. Attempting to load the conflicting network segments generates an error similar to the following example:

    01070392:3: Self IP 10.1.1.1 / 255.255.255.0: This IP shares a network with the management IP (10.1.0.2 / 255.255.0.0).

Workaround

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

You can recover from this issue by reconfiguring the management port settings. For more information, refer to the documents in the Supplemental Information section.

If the unsupported network configuration prevents you from accessing the Configuration utility using the management IP, you can reconfigure the management port settings by connecting to the serial console port, from the LCD panel of the device, or from a self IP. To do so, perform one of the following procedures:

  • Reconfiguring networking options for the management interface using the serial console port
  • Configuring management port settings from the LCD panel
  • Configuring management port settings by connecting to the Configuration utility on a self IP

Reconfiguring networking options for the management interface using the serial console port

  1. Connect a terminal emulator to the BIG-IP system by using the serial port.

    Note: For more information about configuring terminal emulation, modifying baud, and the null modem serial cable requirements, refer to the following articles:

    K7683: Connecting a serial terminal to a BIG-IP system
    K9156: Setting the baud rate of the serial console port (9.x - 10.x)
    K587: Pinouts for serial terminal cables used to connect the 9-pin serial port on F5 products

  2. From the BIG-IP command line, start the F5 Management Port Setup tool by typing the following command:

    config

  3. Enter data in the IP address, netmask, and default management route screens.

Configuring management port settings from the LCD panel

You can set the management network settings by using the LCD display and keypad on the front panel of the device. For more information about this process, refer to the appropriate platform guide for your hardware platform.

Configuring management port settings by connecting to the Configuration utility on a self IP

Note: By default, the BIG-IP system is not configured to allow connections to the Configuration utility on a self IP address. F5 does not recommend this configuration; however, if you have modified the self IP port lockdown settings to allow access to the Configuration utility, you can use this method to reconfigure the management port settings.

  1. Log in to the Configuration utility.
  2. Navigate to System > Platform.
  3. In the Management Port section, enter the configuration data.
  4. Click Update.
