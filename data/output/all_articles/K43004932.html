Description

You have installed the latest signature manually via LiveUpdate, after a while, you may find that ASM installs older signatures automatically.

Environment

  • BIG-IP ASM
  • ASM Live Update mode is set to Scheduled
  • You have installed newer attack signature manually
  • Automatic(Scheduled) signature update is failed (for example, because of no connectivity to the internet)

Cause

This behavior is by design.
When the scheduled installation is failed, the system tries to reinstall latest "non-manually" installed file.
Thus, the system may install the older signature. 

Recommended Actions

You have to investigate why scheduled signature update is failed and fix it.
Or you have to disable scheduled installation and update the signature manually.

Additional Information

For ASM devices managed by BIG-IQ, the default behavior in BIG-IQ is that managed ASM devices are automatically opted in to scheduled BIG-IQ LiveUpdate pushes, referred to as "Remote Updates," which can be found under Configuration >> Security >> Threat Intelligence >> Web Application Security.

If scheduled LiveUpdates are also enabled on the local ASM device, this setup can create conflicts as discussed in this article, with LiveUpdates being scheduled from multiple sources and BIG-IQ LiveUpdate pushes being treated as manual installations.

To avoid conflicts from multiple scheduling sources, select a single source (either BIG-IQ or ASM), but not both to manage the scheduled LiveUpdates.

Note: This unintended behavior has been identified and is being tracked under defect ID 2330389 for resolution in a future release.
