Known Issue

A VIPRION B2100 blade may unexpectedly stop processing traffic across all VLANs.

This issue may occur for the following platform:

  • The VIPRION 2400 chassis with a B2100 blade installed

When this issue is encountered, unaffected blades are able to pass traffic as expected. The management port on the affected blade is also able to process traffic as expected.

Impact

The affected blade is unable to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H994737-2 on the Diagnostics > Identified > Medium screen.
  • The blade fails to pass traffic across any VLAN. For example, locally originated traffic, such as ICMP/ping, is not passed to hosts on local VLANs. On a single-blade chassis, this results in total loss of network connectivity except through the blade's MGMT port.
  • The BIG-IP system logs MPI channel messages to the /var/log/tmm file that appear similar to the following example:

    notice MPI stream: connection to node 127.10.1.3 lost
    notice MPI stream: connection with node 127.10.1.3 established
    notice MPI dgram: connection with node 127.10.1.3 established

  • The BIG-IP system marks all members of all pools down at the same time, and logs a message for each to the /var/log/ltm file:

    01070638:5: Pool member <ServerIP_port> monitor status down

  • All interfaces assigned to an affected VLAN report the correct interface status.
  • The output of the tmctl -d blade tmm/hsbe2_internal_lbb command shows non-zero values for the hgm_tx_pause_cnt counter.

    A sample output for the command tmctl -d blade tmm/hsbe2_internal_lbb may appears similar to the following example:

Resolution

Status

F5 Product Development has identified the following two root causes of this issue:

  • BRAM timing errata from the FPGA manufacturer

    The originally documented characteristics of the FPGA differ from the manufactured product. An update to the HSB firmware is required to accommodate the correct timing properties.

    F5 Product Development has assigned ID 362139 and ID 365470 to this issue. For information about releases or hotfixes that resolve this issue, refer to the following table:

    Important: The BRAM timing fix partially mitigates the issue by making occurrences less frequent. If you are running one of the BIG-IP versions mentioned in the below table, you must also apply the HSB firmware fix to entirely mitigate the issue.

Workaround

If the system is unable to process traffic due to this issue, you can recover by rebooting the affected VIPRION chassis. However, the issue is likely to re-occur within five days on the same system or on its peer. If you are unable to upgrade, you may be able to minimize the impact of encountering the issue again by configuring network or connection mirroring along with VLAN failsafe or gateway failsafe.

  • Rebooting the affected chassis
  • Configuring high availability features

Rebooting the affected chassis

Impact of workaround: The VIPRION system will not process any traffic until the system has fully rebooted.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Device > General.
  3. To reboot the BIG-IP system, click Reboot.
  4. To confirm the reboot action, click OK.

Configuring high availability features

Impact of workaround: Configuring network mirroring features may increase resource utilization on the VIPRION system.

For information about configuring network mirroring and other high availability features, refer to the following manual sections:

  • The BIG-IP Device Services Clustering: Administration manual
  • The High Availability Configuration chapter of the VIPRION Systems: Configuration manual
