Known Issue

This is the result of a known issue. The BIG-IP SSL OCSP authentication module does not correctly honor AuthorityInfoAccess (AIA) extensions in client certificates, which prevents OCSP verification.

Instead of reading the AIA extension, the BIG-IP system attempts to use the URL field from the OCSP Responder configuration. Since this field is intentionally blank to allow the use of the URL within the AIA extension, verification fails.

Expected behavior is for the BIG-IP SSL OCSP authentication module to look inside the client certificate presented for the AIA extension. This extension contains the URL that should be used by the authentication module for OCSP verification. This allows administrators to configure the authentication module to utilize the URL in the AIA extension of incoming certificates instead of hard-coding a URL within the OCSP Responder configuration.

Note: For information about configuring the BIG-IP SSL OCSP authentication module, refer to the Authenticating Application Traffic using a Remote Server chapter of the Configuration Guide for BIG-IP Local Traffic Manager.

F5 Product Development is tracking this issue as ID 343034.

This issue has been fixed in a hotfix. To request the hotfix, contact F5 Technical Support, referencing this article number and the associated ID numbers.
