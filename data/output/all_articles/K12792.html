Known Issue

On the BIG-IP system, the cron daemon executes the system_check script as the syscheck user every two minutes. Because the /etc/passwd file specifies a home directory for the syscheck user, but this directory does not actually exist on the file system, the cron daemon fails to change the working directory before executing the system_check script. As a result, each time the cron daemon executes the system_check script, a message that appears similar to the following example is logged to the /var/log/cron file:

local/bigip01 info crond[16642]: (CRON) chdir(HOME) failed: (No such file or directory)
local/bigip01 info crond[16643]: (syscheck) CMD (/usr/bin/system_check -q)

Note: The error message has a log level of Informational; therefore, it is only logged when the minimum log level for the cron daemon is set to either Informational or Debug. The default syslog configuration for the cron daemon does not allow the error message to be logged.

Impact

You can safely ignore this issue. The system_check script works as expected despite the fact the cron daemon fails to change the working directory before executing the script.

Symptoms

The BIG-IP system will log the aforementioned error messages.

Resolution

Note: This issue will continue to affect BIG-IP systems upgraded from 10.0.x to a fixed version. If you experienced this issue after upgrading to version 10.2.1 or later, F5 recommends to workaround the issue by following the procedure in the Workaround section.

Workaround

To work around this issue, you can create a home directory for the syscheck user, thus preventing the cron daemon from failing to change the working directory before executing the script. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Modify the home directory location for syscheck user by typing the following command:

    usermod -d / syscheck 2> /dev/null
