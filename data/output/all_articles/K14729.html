Topic

When performing IP comparisons using the IP::addr iRules command, specifying a netmask on the first IP address object requires additional processing that may impact performance.

Description

The IP::addr iRules command uses the following syntax:

IP::addr <addr1>[/<mask>] equals <addr2>[/<mask>]

When formatting the IP::addr iRules command, the syntax allows a network mask to be specified for the first IP address object (addr1). However, if you specify a network mask on the first IP address object (addr1), additional CPU cycles are required to convert the address into a string, apply the mask, then reconvert it back to an IP address object.

When the network mask is applied to the second IP address object (addr2) on the other side of the equation, the additional conversions are not required. Therefore, a network mask on the second IP address object (addr2) is more efficient than placing a network mask on the first IP address object (addr1).

Additionally, the network mask format can also affect the efficiency of the command. Using a Classless Inter-Domain Routing (CIDR) notation for the mask format is the most efficient method.

While the following IP::addr iRules command examples produce the same result, the first example is the recommended format. The examples are listed in order of efficiency, from most efficient to least efficient:

  • [IP::addr [IP::remote_addr] equals 10.10.20.0/24]
  • [IP::addr [IP::remote_addr] equals 10.10.20.0/255.255.255.0]
  • [IP::addr [IP::remote_addr] equals "10.10.20.0 mask 255.255.255.0"]
  • [IP::addr [IP::remote_addr]/24 equals 10.10.20.0]
  • [IP::addr [IP::remote_addr]/255.255.255.0 equals 10.10.20.0]
  • [IP::addr "[IP::remote_addr] mask 255.255.255.0" equals 10.10.20.0]

For more information and an efficiency comparison of the IP::addr command syntax formats, refer to the iRules IP Comparison Considerations with IP::addr Command article on DevCentral.

Recommendations

F5 recommends that you format IP::addr iRules commands to use a CIDR notation formatted network mask on the second IP address object and avoid specifying a network mask for the first IP address object, when possible.
