Description

When a BIG-IP LTM virtual server IP receives traffic that does not match any configured virtual server or active connection, it may reply to clients with ICMP Type 3 (Destination Unreachable, Port Unreachable) packets. This is the default system behavior and can be undesirable in security-sensitive environments where explicit rejection signals should be suppressed. Administrators may wish to disable these ICMP Type 3 responses so that unmatched traffic is silently dropped, resulting in client-side timeouts rather than immediate rejection.

Environment

  • Traffic destined to unmatched virtual server
  • BIG-IP LTM

Cause

The BIG-IP system was configured with the default setting (tm.rejectunmatched = true), which causes it to actively send ICMP Type 3 (Port Unreachable) or TCP RST responses for unmatched traffic. This is expected behavior.

Answer/Recommended Actions

To suppress ICMP Type 3 and TCP RST responses for unmatched traffic globally:

  1. Run the following command to change the system database key from the default value (true) to the new value of 'false':
    tmsh modify sys db tm.rejectunmatched value false
  2. Save the Configuration:
    tmsh save sys config

Note: The "ICMP Echo" setting on virtual addresses only affects ICMP Echo (ping) responses and does not impact ICMP Type 3 behavior.

To change back the system variable value to its default, you can run the below command, and then save the configuration:

tmsh modify sys db tm.rejectunmatched value true

Additional Information

  • Changing "tm.rejectunmatched" to 'false' affects both ICMP Type 3 and TCP RST responses for unmatched traffic.
  • This may impact client-side application behavior, as clients will not receive immediate feedback for failed connections.
  • For normal, matched virtual servers, communication proceeds as usual.
