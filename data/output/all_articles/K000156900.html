Description

ICMP traffic sent from the BIG-IP Linux host using the 'ping -I <self-IP> <destination IP>' command may not go through the VLAN of the self IP. The "-I <self IP>" option will set the source IP of ICMP echo frame, and the frame will be send out, the outgoing VLAN is depending on the route table. If the next hop is a pool, the ICMP echo frame may send to one of the pool member. Specifying a source IP with the '-I' option does not guarantee the outgoing VLAN or pool member, and TMM determines the path based on its routing logic, which can result in unexpected connectivity behavior.

Environment

  • BIG-IP LTM
  • IP route and next hop is a pool
  • ICMP traffic initiated from the BIG-IP Linux host using ping -I <self IP> <server IP>

Cause

BIG-IP TMM manages all traffic forwarding and selects the outgoing VLAN and pool member based on its routing table and connection logic. When using the '-I <self-IP>' option in the Linux ping command, the source IP is set, but TMM may select a different VLAN and next hop than expected. The outgoing ICMP packets may not use the specified VLAN or pool member, and replies may not be received if the network does not route responses back correctly.

Recommended Actions

  • To control the data path for ICMP traffic from Linux host, create specific route entries for the destination server with specific gateway, so TMM can select the appropriate source IP, VLAN, and next hop.
  • In environments with multiple self IPs and VLANs, ensure routing and next hop selection match the desired connectivity path.
  • Use “ tmsh show sys connection ss-server-addr <server IP> all-properties” to observe how TMM creates connection entries for ICMP traffic and which nexthop is selected.
