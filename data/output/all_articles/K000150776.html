Description

  • Disk partition /var has only 0% free
  • Unable to identify significant source of space usage by looking for large files.
  • Check for "Deleted" files consuming space on the system.

Environment

  • BIG-IP
  • Low /var space even after removing obvious files.
  • Deleted files are still consuming space on the system.
  • SCP auto-job is used to backup UCS files to a remote system.

Cause

Hanging scp processes are holding a significant amount of storage space in limbo due to not allowing deleted files to be freed from storage.

Recommended Actions

  • Running this command shows hanging scp processes:
ps aux | grep -E 'COMM|scp'
  • Run the command:
killall scp

Optional steps:

  • Investigate why the scp process is hanging to ensure that the cycle doesn't continue to consume unnecessary storage.
  • One way to do this is by executing the individual parts of the automated job to see where the hang-up is coming into the system.

Additional Information

Useful commands for analyzing /var storage:

 

This command shows top 20 files consuming /var storage:

find /var/ -xdev -type f -exec du -h {} \; | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -20

 

This command shows large files and directories:

du -ha /var | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -n 20

 

This command searches for recent files in the /tmp directory:

find /tmp -mtime -3 -mtime +1 -ls

 

This command lists files that are deleted but still occupying space because they are currently open by a process:

lsof -ws | grep -i 'size\|deleted'
