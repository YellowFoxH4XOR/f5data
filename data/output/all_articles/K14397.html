Topic

You should consider using this procedure under the following condition:

  • You want the BIG-IP system to run a command or run a custom script based on a syslog message.

Description

You can configure the BIG-IP system to perform an action, such as run a command or run a custom script, based on log messages distributed by the syslog daemon. For example, you can run a custom debugging script when the system logs a particular error message by configuring the /config/user_alert.conf file to execute the command or script based on a defined log message.

When the alertd process starts, it creates a dynamic configuration file by appending the /config/user_alert.conf file to the /etc/alertd/alert.conf file. The BIG-IP system then searches the dynamic configuration file sequentially for matches. When a match is found, the system performs the action specified by the alertd syntax.

Note: The /config/user_alert.conf file is read and evaluated from bottom to top.

Review the following information carefully before performing the procedures in this article:

  • F5 Technical Support does not write or debug custom scripts.
  • BIG-IP APM messages are not processed by the alertd SNMP process, and therefore custom scripts cannot be triggered based on syslog messages for BIG-IP APM systems.
  • Messages generated by the dosl7d process in BIG-IP ASM 11.3.0 and later are not processed by the alertd SNMP process. Layer 7 (L7) denial of service (DoS) messages,therefore, cannot be used for triggering commands or custom scripts.
  • Use care when configuring the user_alert.conf file to run custom scripts. A poorly designed implementation can potentially cause system performance issues.
  • Modifications to the user_alert.conf file may not be preserved after system upgrades or hotfix installations. F5 recommends that you create a user configuration set (UCS) archive before upgrading or installing a hotfix if you want to maintain customizations in the file.

    Note: For information about UCS archives, refer to K4423: Overview of UCS archives.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command line access to the BIG-IP system.
  • You select a command or custom script to be triggered by the syslog message.

Information to consider when selecting the syslog message that will trigger the command or script

When you configure the BIG-IP system to run a command or script based on a syslog message, carefully evaluate the syslog message that will trigger the designated action. Review the following information before selecting which syslog message will trigger the command or script:

  • Select a syslog message that is logged at an appropriate verbosity level, such as emerg - notice. Choosing a message that is logged at a high verbosity level may result in the system running the custom script or command more frequently than desired, which can negatively affect system performance.
  • Verify that the chosen message does not match the 'message' part of any other entry already defined in the /etc/alertd/alert.conf file or the /config/user_alert.conf file. Only the first match will generate the desired action.

    For example, the matched_message in the below user_alert.conf syntax must be unique across the entire alertd configuration:

    alert <custom_alert> "<matched message>" {
    exec command="/shared/tmp/mycustomscript.pl"
    }

Note: For information about how to determine which alerts are pre-configured to trigger a Simple Network Management Protocol (SNMP) trap, refer to K6414: Determining which alerts are pre-configured to trigger an SNMP trap.

Information to consider when configuring the user_alert.conf stanza

After you select the syslog message that will trigger the command or script, you must properly define the user_alert.conf stanza. When you configure the user_alert.conf stanza, consider the following information:

  • The pattern matching can include regular expressions.
  • The snmptrap, lcdwarn, and exec commands are allowed within the stanza. The snmptrap and lcdwarn commands can be combined into one stanza. If present, the exec command must be the only command in a stanza.
  • The exec command requires double quotation marks. To quote strings within the command stream, you must use single quotation marks.
  • The label may contain alphanumeric characters, dashes, underscores, and periods.

Defining the user_alert.conf stanza

Impact of procedure: Using a flawed user_alert.conf stanza configuration or poorly designed implementation could cause system performance issues or traffic disruption.

  1. Log in to the command line.
  2. To back up the user_alert.conf file, type the following command:

    cp /config/user_alert.conf /config/user_alert.conf.SOL14397

  3. Use a text editor to edit the /config/user_alert.conf file.
  4. Add the stanza to the file using the following format, where matched_message matches the syslog message body (or a portion of the syslog message body):

    /* comment */
    alert <custom_alert> "<matched_message>" {
    exec command="/path/to/command_or_customscript"
    }

    For example, to restart the ntpd process after the system completes a reboot, you can use the following stanza:

    /* This stanza restarts ntpd after the system completes a reboot */
    alert ntpd_startup_delay "Initialization complete. The MCP is up and running" {
    exec command="sleep 15";
    exec command="/usr/bin/bigstart restart ntpd";
    }

  5. Save the file and then exit the editor.

Using tmsh commands in the user_alert.conf stanza

Impact of procedure: Using a flawed user_alert.conf stanza configuration or poorly designed implementation could cause system performance issues or traffic disruption.

  1. Log in to the command line.
  2. To back up the user_alert.conf file, type the following command:

    cp /config/user_alert.conf /config/user_alert.conf.SOL14397

  3. Use a text editor to edit the /config/user_alert.conf file.
  4. Add the stanza to the file using the following format, where matched_message matches the syslog message body (or a portion of the syslog message body):

    /* comment */
    alert <custom_alert> "<matched_message>" {
    exec command="export REMOTEUSER=admin; /usr/bin/tmsh <tmsh command syntax>"
    }

    For example, to restart the ntpd process after the system completes a reboot, you can use the following stanza:

    /* This stanza sends an arp for 10.0.0.1 after a bigstart start/restart of ntpd */
    alert ntpd_startup_mac "bigstart (.*) ntpd" {
    exec command="export REMOTEUSER=admin; /usr/bin/tmsh create net arp 10.0.0.1 mac-address 00:20:03:01:AF:01"
    }

    Note: For BIG-IP versions prior to 11.0.0, the REMOTEUSER statement is required.

Testing the user_alert.conf configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To test the user_alert.conf configuration, use the following logger command syntax with the selected syslog message:

    logger -p <facility.level> "selected_syslog_message."

    For example:

    logger -p local0.warning "Initialization complete. The MCP is up and running."

    This command outputs a syslog-ng message to the local0.warning facility (the default location is the /var/log/ltm file). The command should initiate the command or script defined in the user_alert.conf stanza.

Information to consider when debugging the user_alert.conf configuration

  • If the user_alert.conf file contains syntax errors, error messages that appear similar to the following example are reported to the console:

    local/localhost emerg logger: Re-starting alertd

    Note: If the alertd process continually restarts, SNMP traps will not function as expected.

  • If the alertd process is restarting, you should edit the user_alert.conf file and temporarily comment out the new stanza.
  • To resolve syntax issues, review the /var/log/ltm messages. Syntax issues are reported in messages that appear similar to the following examples:

    alertd[9984]: 01100021:3: Couldn't process the /config/user_alert.conf: problems at line <XX>.

    alertd[9984]: 01100010:3: Couldn't load file /config/user_alert.conf

  • If the user_alert.conf stanza contains an exec string, and the exec command fails, the system logs error messages that appear similar to the following example to the /var/log/ltm file:

    alertd[10796]: 01100014:3: Action <your-exec-cmd-string> is failed.
