Topic

The BIG-IP system can send locally generated email messages without resorting to external DNS resolution by using a smart mail relay host. This approach is useful in environments where the BIG-IP system must send email alerts, but an appropriate DNS resolver is not available.

Note: For more information about configuring the BIG-IP system in environments where DNS resolvers are available, refer to K3664: Configuring BIG-IP system to deliver locally generated email messages (9.x - 10.x).

To configure the BIG-IP system to use a mail relay host, perform the following procedure:

  1. Log in to the command line.
  2. Using a text editor, open the /etc/postfix/main.cf file and locate the following lines:

    #relayhost = $mydomain
    #relayhost = gateway.my.domain
    #relayhost = uucphost
    #relayhost = [an.ip.add.ress]
  3. Immediately following these comments, add a line specifying the relayhost for your mail server:
    • To specify the IP address of the mail relay server, add a configuration line similar to the following:

      relayhost = [192.168.1.100]
       
    • Alternatively, if the hostname and address of the mail relay server are in the BIG-IP system's /etc/hosts file, you can add a configuration line similar to the following:

      relayhost = [mail1.mycompany.com]

      Important: The square brackets [ ] around the host in either option are required to prevent an MX record lookup.
  4. Optionally, you can configure the fallback_relay option to specify a backup mail server in the event the primary mail relay server is unreachable.
    • To specify the IP address of the fallback relay server, add a configuration line similar to the following:

      fallback_relay = [192.168.1.101]
       
    • Alternatively, if the hostname and address of the fallback relay server are in the BIG-IP system's /etc/hosts file, you can add a configuration line similar to the following:

      fallback_relay = [mail2.mycompany.com]

      Important: The square brackets [ ] around the host in either option are required to prevent an MX record lookup.
  5. The completed configuration snip will appear similar to the following example:

    #relayhost = $mydomain
    #relayhost = gateway.my.domain
    #relayhost = uucphost
    #relayhost = [an.ip.add.ress]
    relayhost = [192.168.1.100]
    fallback_relay = [192.168.1.101]
  6. Save the main.cf file.
  7. By default, the postfix service does not automatically start when the BIG-IP system boots. Determine whether the postfix service is currently running by typing the following command:

    bigstart status postfix
  8. If the postfix service is not running, start it by typing the following command:

    bigstart start postfix

    If the postfix service is running, restart it by typing the following command:

    bigstart restart postfix
  9. If you want the postfix service to automatically start every time the BIG-IP system boots, type the following command:

    bigstart add postfix
  10. Test the configuration using the following command syntax:

    echo test | mail <email_address>

Note: The /etc/postfix/main.cf file is not configured for inclusion in UCS archives; therefore, any modifications you make to the file will not survive a software upgrade and will not be synchronized between redundant BIG-IP systems. For more information about UCS archives, refer to K4423: Overview of UCS archives. For more information about the specific files that are contained in a UCS archive and instructions about how to include additional files, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.
