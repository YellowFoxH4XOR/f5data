Topic

This article applies to BIG-IP 11.x through 15.x. For information about other versions, refer to the following article:

  • K5483: Testing an HTTPS Monitor with user authentication from the command line (9.x - 10.x)

You should consider using this procedure under the following condition:

  • You want to use the interactive s_client utility from the command line to simulate an HTTPS monitor and see the server response.

Description

The s_client utility allows you to establish an SSL session with the member server you want to test and send the same request string and authentication credentials that are used by the HTTPS monitor. As a result, the HTTP response you see from the target server is the same response the HTTPS monitor would receive. This feature can be a valuable tool when troubleshooting or configuring HTTPS monitors.

The syntax for the s_client utility to establish a session with a member server is similar to the following example:

openssl s_client -host <IP_Address> -port <Port>

Apache 2.4.25 web servers automatically respond after the Enter key is pressed.  If that happens, you may need to use the -crlf option.

For more information regarding this behavior, refer to: Apache: httpd throws error 400 "malformed request line" if mod_ssl enabled and connecting with openssl s_client on a linux terminal.

Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

The following example demonstrates the syntax required to use the the openssl utility -crlf option.

openssl s_client -crlf -connect <ip address>:<port>
openssl s_client -crlf -host <ip address> -port <port>

Note: Replace <ip address> with the destination server IP address and <port> with the destination server port.

After the session is established, you can interactively type HTTP formatted requests. By specifying an HTTP 1.0 or HTTP 1.1 protocol formatted request as part of the initial send request, you can enter additional HTTP headers that may be required by your member server, such as an Authorization header and password string. You can then terminate the session by pressing the Enter key on a blank line.

Additionally, if you configured the HTTPS monitor to use a client certificate, you can use the -cert and -key options to specify the client certificate and key.

For example:

openssl s_client -host <IP_Address> -port <Port> -cert /config/ssl/ssl.crt/<some-client-cert.crt> -key /config/ssl/ssl.key/<some-client-cert.key>

Note: Replace <some-client-cert.crt> with the name of the client certificate file, and replace <some-client-cert.crt> with the name of the corresponding private key file.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have command line access to the BIG-IP system.
  • You know the send string as listed in the definition of the HTTPS monitor you want to simulate.

    You may view the HTTPS monitor definitions in the /config/bigip.conf file or the tmsh list ltm monitor https command output. The HTTPS monitor definitions appear similar to the following example:

    ltm monitor https ssl_test {
    adaptive disabled
    cipherlist DEFAULT:+SHA:+3DES:+kEDH
    compatibility enabled
    defaults-from https
    destination *:*
    interval 5
    ip-dscp 0
    password $M$9M$8OS5HIvhox5Vp5Yik1yE1g==
    recv "Match This"
    send "GET /testpage.asp\r\n"
    time-until-up 0
    timeout 16
    username f5
    }

  • You know the encrypted password string or retrieve the password string for the Authorization header. You can generate the password string using the following syntax:

    echo -n 'username:password' | base64

    For example, using the username f5 and the password f5passwd:

    echo -n 'f5:f5passwd' | base64

    The output appears similar to the following example:

    ZjU6ZjVwYXNzd2Q=

Procedures

To test an HTTPS monitor against a member, perform the following procedure:

Important: If the member server requires NTLM Authentication, you cannot use this procedure to test the HTTPS monitor because s_client closes the TCP connection after receiving HTTP/1.1 401 Unauthorized, so does not fully complete the HTTPS monitor test.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Type the following s_client command syntax:

    openssl s_client -host <IP_address> -port <port> <Enter>

    For example, to test against a member 10.1.1.1:443, type the following command:

    openssl s_client -host 10.1.1.1 -port 443 <Enter>

  3. After the session is established, quickly enter the HTTP formatted request:

    <send string> <HTTP Protocol> <Enter>

    For example:

    GET /testpage.asp HTTP/1.0 <Enter>

    Note: The Host header is required in an HTTP 1.1 request; although, it may contain a null value. For example: Host:

  4. Quickly enter the Authorization HTTP header:

    Authorization: Basic <password string> <Enter>

    For example:

    Authorization: Basic ZjU6ZjVwYXNzd2Q= <Enter>

  5. You then terminate the session by pressing the Enter key on a blank line.
  6. You can now parse the HTTP response from the member to verify the receive string you want is present.

    The receive string is defined in the monitor definition recv line.

    For example, in the previous ssl_test monitor example, the Match This string is the receive string you want.
