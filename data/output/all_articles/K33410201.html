Known Issue

The BIG-IP system may fail to perform a 12.x hotfix upgrade.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is initially installed with BIG-IP 12.x software with no hotfixes, either from a clean installation or from a Return Materials Authorization (RMA) replacement.
  • Your BIG-IP system is then installed with BIG-IP 11.x software in the next available software slot and booted into the newly installed slot.
  • You subsequently attempt to perform a hotfix installation on the initial slot that contains BIG-IP 12.x software.

The BIG-IP hotfix installation requires that you import both the base software and hotfix installation files into the BIG-IP system. By default, the BIG-IP system installs the base software version first, before applying the hotfix to the target software slot. If the required base software (for example, 12.0.0) is present on the target software slot, the BIG-IP system performs only the hotfix installation (for example, 12.0.0 HF3). For more information, refer to K13123: Managing BIG-IP product hotfixes (11.x - 13.x).

Impact

The BIG-IP 12.x hotfix upgrade fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe the following tmsh show /sys software status command output, which displays that the installation failed:

    --------------------------------------------------------------------------------------------------------------
    Sys::Software Status
    Volume  Product  Version   Build  Active                                                 Status
    --------------------------------------------------------------------------------------------------------------
    HD1.1    BIG-IP   12.0.0   3.0.654      no  failed (Cannot enumerate packages on target partition)
    HD1.2    BIG-IP   11.5.4   0.0.256     yes                                                complete

  • The software installation fails, and in the /var/log/liveinstall.log file, you observe an error message similar to the following example:

    rpmdb: /mnt/tm_install/15978.efq3ZX/var/lib/rpm/Packages: unsupported hash version: 9
    error: cannot open Packages index using db3 - Invalid argument (22)
    error: cannot open Packages database in /mnt/tm_install/15978.efq3ZX/var/lib/rpm
    Terminal error: Cannot enumerate packages on target partition

Workaround

To work around this issue, you can delete the failed software slot and perform the hotfix installation again. To do so, perform the following procedure:

Impact of workaround: If the BIG-IP system is the active member of a redundant system, rebooting will cause a failover. If the BIG-IP system is a standalone unit, rebooting will interrupt traffic processing.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To delete the failed software slot, use the following command syntax:

    delete /sys software volume <failed_software_slot>

    For example, to delete the failed software slot HD1.1, type the following command:

    delete /sys software volume HD1.1

    If the delete operation fails, you may need to reboot the system before proceeding to the next step.

  3. To perform the hotfix installation, use the following command syntax:

    install /sys software hotfix <Hotfix_version> create-volume volume <target_software_slot>

    For example, to perform the BIG-IP 12.0.0 HF3 hotfix installation on target software slot HD1.1, type the following command:

    install /sys software hotfix Hotfix-12.0.0.3.0.654.iso create-volume volume HD1.1
