Known Issue

Temporary files may remain on the LineRate system after a remote backup operation.

This issue occurs when all of the following conditions are met:

  • You perform a remote backup operation on the LineRate system, using either the CLI or REST interface.
  • A Secure Shell (SSH) communication or authentication error occurs between the LineRate system and the remote destination server.

When you perform a backup operation on the LineRate system, the system first creates a temporary compressed tar file in the /home/linerate/backups directory. The system then uploads the file to the remote server using a Secure Copy (SCP). Once the file successfully uploads to the remote server, the temporary file is deleted. If an error occurs during the SSH communication or authentication for SCP, the temporary file is not deleted. Subsequent failed attempts to perform a backup will result in the system creating more temporary files in the /home/linerate/backups directory. This behavior may eventually result in disk space exhaustion.

Impact

Disk space on the LineRate system may reach capacity.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If disk space is already exhausted, when you attempt to save your LineRate configuration using the write command, you may view the following output:

    Building configuration...
    ERROR: Error copying file: basic_ios::clear
  • The system logs messages to the /var/log/all.messages file similar to the following example:

    LROS kernel: pid 826 (controller), uid 0 inumber 7143056 on /: filesystem full
  • The disk free (df) utility displays output similar to the following:

    Filesystem                           Size    Used   Avail Capacity  Mounted on
    /dev/ufs/LROSadff046bc97f9crootfs    138G    138G    -11G   109%    /

    Note: Available space (Avail) reported as a negative (-) value, and Capacity reported as a value over 100 percent are both indications that the file system is using reserved space. The FreeBSD system reserves 8 percent by default, to avoid disk out of space issues. However, once the system reaches this limit it will not be able to write anything to disk.

Workaround

To work around this issue, you can monitor disk space and manually remove temporary files left in the /home/linerate/backups directory. To do so, perform the following procedure:

Impact of workaround: Use caution to remove only files from the /home/linerate/backups directory.

  1. Log in to the LineRate system CLI.
  2. Confirm the existence of temporary files in the /home/linerate/backups directory by typing the following command:

    bash "ls -lh /home/linerate/backups"

    The command output appears similar to the following example:

    total 299264
    -rw-------  1 root  lros    78M Jul  1 15:47 temp.backup.HfVASa
    -rw-------  1 root  lros    27M Jul  1 15:49 temp.backup.ayyiSr
    -rw-------  1 root  lros    40M Jul  1 15:49 temp.backup.r6kzgr
  3. Remove the temporary files by typing the following command:

    bash "sudo rm /home/linerate/backups/temp.backup.*"
  4. Confirm the files have been removed by repeating the command in step 2.
