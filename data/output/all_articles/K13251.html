Known Issue

Description

The access policy Machine Cert Auth action fails to match a certificate when the Certificate Match Rule is set to issuer.

Impact

Users are unable to log on.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Users are unable to log on and receive the following error message:

    Access was denied by the access policy. This may be due to a failure to meet access policy requirements.

  • BIG-IP APM logs the following error message in the /var/log/apm file:

    apd[<pid>]: 01490125:6: <sessionid>: Client response for the machine cert request: No matching certificate found

    In the above error message, note the following:

    • <pid> is the program ID
    • <sessionid> is the APM session ID

Workaround

To work around this issue, you can configure the Certificate Match Rule to match any issuer. To do so, perform the following procedure:

Impact of workaround: This workaround will allow any device with a machine certificate to pass the Machine Cert Auth test.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Access Policy.

    The Access Policy navigation panel expands.

  3. Click Access Profiles.

    The Access Profiles List opens in the right pane.

  4. Click Edit... next to the name of the access policy you want to edit.

    The Visual Policy Editor opens in a new window.

  5. Click the Machine Cert Auth action.

    The Machine Cert Auth properties window opens.

  6. Enter .* in the Issuer text box.
  7. Click the Save button.
  8. Click Apply Access Policy.
  9. Click the Close button.
