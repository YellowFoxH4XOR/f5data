K000162088: Admd Memory Leak and Increased Swap Usage on BIG-IP Advanced WAF with DoS Profiles

Type
Support Solution
Published
2026-07-07
Updated
2026-09-01
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1, 17.1.3
Source
https://my.f5.com/manage/s/article/K000162088

Description

On BIG-IP Advanced WAF systems, you may observe a continuous increase in "Other" memory and swap usage. The admd process consumes excessive memory, leading to out-of-memory (OOM) events and automatic restarts of the admd process. System logs may show messages such as "admd invoked oom-killer" and "Re-starting admd." This issue typically occurs after attack signatures block events when DoS profiles are attached to virtual servers.

Environment

  • Product: BIG-IP Advanced WAF
  • Configuration:
    • DoS profiles attached to virtual servers

Cause

Memory leak in the admd process after attack blocked by the signature occurs when DoS profiles are attached to virtual servers. The PE team is tracking the issue under ID 2347029.

Recommended Actions

  • The ID2347029 has been fixed in 21.1.0.1, 21.0.0.3, 17.5.1.8, 17.1.3.4, please upgrade BIG-IP to the latest version of the fix branch.
  • If it is not possible to upgrade the version at present, please monitor admd memory usage (RSS) and restart the admd process if it approaches 4GB to avoid service impact.
  • As a temporary mitigation, you can consider to remove DoS profiles from virtual servers to prevent the admd process from leaking memory until the fixed software is installed.

Additional Information

  • The admd process is responsible for DoS profile functionality. Its memory leak can lead to OOM events and process restarts, which are not expected behavior.
