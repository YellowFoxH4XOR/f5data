Known Issue

This is the result of a known issue. The TCP profile Deferred Accept option does not free resources used when a connection is established, but no data is sent.

The Deferred Accept option, which is disabled by default, allows the system to defer allocation of a connection chain context until the system receives the payload from the client. This option is useful when dealing with three-way handshake denial-of-service attacks.

The issue occurs when a client connection completes the three-way handshake, but does not send data, which causes a stale connection that is not freed after the timeout period should have reclaimed and reset the connection. If enough connections end up in a stale state, the SYN cache may become full and prevent new connections from being established.

F5 Networks Product Development tracked this issue as CR88145 and it was fixed in version 9.4.4 for the BIG-IP 9.4 software branch. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in HOTFIX-BIG-IP-9.4.3-14.3-HF3 issued for BIG-IP version 9.4.3, for the BIG-IP 9.4 software branch, and in HOTFIX-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
