Topic

Beginning with FirePass version 6.0.1, you can check for a valid machine certificate on a Windows client system as part of a pre-logon sequence. When you enable the Windows machine certificate checker pre-logon inspector, FirePass validates the certificate using the following criteria:
  • The Common Name (CN) of the machine certificate must exactly match the full computer name configured on the Windows client system.
  • The machine certificate must be issued by a Certificate Authority (CA) whose Client Root Certificate is installed on the FirePass controller.
  • The machine certificate parameters must be valid. For example, the certificate cannot be expired.
  • The machine certificate cannot appear on a Certificate Revocation List (CRL) configured on the FirePass controller.
  • The machine certificate must be stored in the Local Computer certificate store on the Windows client system.
  • The FirePass client-side components must be able to sign a character string sent by the FirePass controller using the machine certificate private key.

Private keys located in the Local Computer certificate store are only accessible by the user who installed the private key, and by users with administrator privileges. If a user did not install the machine certificate and does not have administrator privileges on the Windows client system, the FirePass client-side components that run with that user?s privileges cannot access the private key to sign the character string sent by the FirePass controller. When the Windows machine certificate checker pre-logon inspector can verify the machine certificate but not the private key, it will trigger the found rule. The default behavior for the found rule is to redirect the user to the Logon Denied page.

Note: For enhanced security, do not mark the private key as exportable when you import a machine certificate onto a client system. For more information about certificate security, refer to your Windows documentation.

Workaround

You can work around this issue by performing one of the following four procedures:

  • Grant the user account administrator privileges on the Windows client system.

  • Import the machine certificate private key into the user?s personal certificate store on the Windows client system.

    Important: Do not remove the machine certificate from the Local Computer certificate store. The Windows machine certificate checker pre-logon inspector requires that the machine certificate reside in the Local Computer certificate store.

  • Use the Microsoft Windows HTTP Services Certificate Configuration Tool (WinHttpCertCfg.exe) on the Windows client machine to grant the user access to the machine certificate private key in the Local Computer certificate store. For more information, refer to K9017: Using WinHttpCertCfg.exe to grant non-administrator users access to machine certificate private keys.

  • Configure the Windows machine certificate checker pre-logon inspector to verify the machine certificate but not the private key.

For more information about performing the first three procedures, refer to Microsoft Windows documentation.

Configuring the Windows machine certificate checker pre-logon inspector to verify the machine certificate but not the private key

To configure the Windows machine certificate checker pre-logon inspector to verify the machine certificate but not the private key, perform the following procedure:

  1. Log in to the FirePass Administrative Console.

  2. Navigate to the Users: Endpoint Security: Pre-Logon Sequence page.

  3. Click the edit link or the backup & edit link next to the pre-logon sequence you want to configure.

  4. Next to the Check machine certificates action, locate the found rule.

    Note: The session variable and value associated with the found rule is session.cert_check.last_check.result ==2.

  5. To the right of the found rule, change the ending from Logon Denied Page to Logon Allowed Page or to the next action in your pre-logon sequence.

  6. Click the Back to console link in the top right corner of the page.
