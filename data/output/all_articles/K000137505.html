K000137505: "Error getting auth token from login provider" after 17.1.0 software upgrade

Type
Support Solution
Published
2023-11-08
Updated
2026-03-05
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
  • BIG-IP DNS: 17.1.1
  • BIG-IP ASM: 17.1.1
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000137505

Description

After upgrading to BIG-IP software version 17.1.0, when attempting to perform certain actions, such as generating a Qkview, or syncing a HA, the Configuration utility (GUI) displays an error message that reads "Error getting auth token from login provider" in a yellow bar across the top middle of the page.

Environment

BIG-IP LTM or any other module

BIG-IP 17.1.0+

Cause

ID 1353957: GUI pages are failing, a message "Error getting auth token from login provider" is displayed

Recommended Actions

1. Retrieve the current idle timeout value for the Configuration utility:

      # tmsh list sys httpd auth-pam-idle-timeout

2. Reset the Configuration utility idle timeout value to the default value:

    Note: The default idle timeout is 1200 seconds (20 minutes).

     # tmsh modify sys httpd auth-pam-idle-timeout 1200

     # tmsh save sys config

3. Remove the current cookies from the /var/run/pamcache directory:

     # rm -f /var/run/pamcache/*

4. Restart the HTTPD service:

     # bigstart restart httpd (wait for 2mins)

Note: If this is an HA setup and the BIG-IP systems are not in sync or if the status changes to Pending state, perform the previous steps on both the standby and active systems and then log in again to both systems.

Note: The procedure in the Recommended Actions section is specific to the conditions discussed in the Description section at the beginning of this article. If you observe this error on your BIG-IP device and your BIG-IP device is not experiencing these conditions, you may want to look at the articles listed in the Related Content section at the end of this article. This is because the error message is generic and may not be version specific.

Additional Information

If Remote Authentication of the Configuration Utility is configured, similar problems displaying pages can happen due to a different bug:
ID 1395081 - Remote users are unable to generate authentication tokens.
ID1395081 is fixed in v17.1.1.1 but the workaround above is still needed.
