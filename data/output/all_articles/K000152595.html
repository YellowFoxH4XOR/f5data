K000152595: APM Portal Access: Backend connections use incorrect port when 'translate-port' is disabled

Type
Support Solution
Published
2025-09-29
Updated
2025-11-13
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000152595

Description

When configuring BIG-IP APM Portal Access on a virtual server that listens on a non-standard port (for example, TCP/8080), backend connections may be made to the same port as the client-side VIP, even if the Application URI specifies a different backend port (such as 443 for HTTPS). This results in failed connections to backend services.

Traffic captures (tcpdump) show the BIG-IP attempting to connect to the backend server on the VIP port instead of the intended backend port.

Environment

  • Virtual server configured with APM and listening on a non-standard port
  • Portal Access resources using Application URIs specifying backend ports

Cause

The virtual server's "translate-port" option is set to "disabled." When this option is disabled, BIG-IP uses the same port for backend connections as the one used by clients to connect to the VIP, regardless of any different port specified in the Application URI.

Recommended Actions

  • Enable the "translate-port" option on your virtual server so that backend connections use the correct port as specified in each Application URI.
    • GUI Steps:
      1. Log in to the BIG-IP Configuration Utility.
      2. Go to Local Traffic > Virtual Servers.
      3. Select your target virtual server.
      4. Switch view mode to Advanced.
      5. Enable "Translate Port."
      6. Click Update.
    • TMSH Command:
      tmsh modify ltm virtual <virtual_server_name> translate-port enabled
      tmsh save /sys config
  • After enabling "translate-port," verify with tcpdump or similar tools that backend connections are now made using the correct destination port from your Application URI.
