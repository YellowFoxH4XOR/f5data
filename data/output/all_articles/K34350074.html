Topic

When you configure the DNS cache feature, the BIG-IP system resolves DNS requests, and responds to repeated DNS queries by serving answers from the cache. You can configure the DNS cache feature on BIG-IP systems licensed for DNS Services.

Description

The DNS cache feature optimizes responses to DNS queries. There are three types of DNS cache configurations available on the BIG-IP system. Refer to the following table for cache setting definitions and recommendations.

Cache settingDefault valueDescription
NameNoneThe name of the DNS cache.
Resolver TypeResolver
  • Resolver: The system resolves DNS queries and caches the responses. Use Resolver when clients use the BIG-IP system as the LDNS to resolve DNS queries.
  • Validating Resolver: The system resolves DNS queries and uses DNSSEC to verify the response before caching the response. Use Validating when clients use the BIG-IP system as the LDNS and you want the system to verify responses using DNSSEC prior to caching the response.
  • Transparent: Sends the query to a DNS server for resolution, and stores the response in the DNS cache. Use Transparent resolver when the BIG-IP system is in front of external resolvers and can consolidate cache content from the external resolvers.
Route Domain NameThe default route domain (0)The route domain the resolver uses for outbound traffic.
Message Cache Size1048576 bytesIndicates the maximum size of the message cache. The allowable range is 0 to 4294967295 bytes.
Resource Record Cache Size10485760 bytesIndicates the maximum size of the resource record cache. The allowable range is from 1 to 4294967295 bytes.
Name Server Cache Count16536 entriesIndicates the maximum number of DNS nameservers for which the system caches connection and capability data. The range is from 0 to 4294967295 entries.
Answer Default ZonesDisabledIndicates whether the system passes along or answers DNS queries for the default zones localhost, reverse 127.0.0.1 and ::1, and AS112.
DNSSEC Key Cache Size1048576 bytesThe maximum size of the DNSKEY cache. This setting is displayed only when the Resolver Type is Validating Resolver.
RRSet RotateNoneIndicates the resource record rotation method used within cached responses. The following options are available:
  • none: The resource record order is not modified and the system returns the RRset records from the DNS cache in the same order they were received from the upstream server.
  • query id: The system uses the query ID in conjunction with the number of records in the RRset to determine which record to display first for cached responses. Configure the DNS cache to rotate the records using the query id if you need to alleviate load issues on the destination resource.
Use IPv4EnabledIndicates whether the system uses IPv4 to query back-end nameservers. An IPv4 self IP and default route must be available for these queries to work successfully.
Use IPv6EnabledIndicates whether the system can use IPv6 to query back-end nameservers. An IPv6 self IP and default route must be available for these queries to work successfully.
Use UDPEnabledIndicates whether the system answers and issues UDP-formatted queries.
Use TCPEnabledIndicates whether the system answers and issues TCP-formatted queries.
Max. Concurrent UDP Flows8192The maximum number of concurrent UDP sessions the system supports.
Max. Concurrent TCP Flows20The maximum number of concurrent TCP sessions the system supports.
Max. Concurrent Queries1024The maximum number of concurrent queries used by the resolver.
Unsolicited Reply Threshold0The maximum number of unsolicited replies to DNS queries that the system handles before generating an SNMP trap and log message as an alert to a potential security attack, such as cache poisoning or DOS. The default value of zero (0) indicates the system does not generate SNMP traps or log messages when it rejects unsolicited replies. Note that the system always rejects unsolicited replies. Change the default value to the value you want to use for alerts for unsolicited replies.
Allowed Query Time200 msIndicates the time that the system allows a query to remain in the queue before replacing it with a new query when the number of concurrent distinct queries exceeds the limit.




   
 
Randomize Query Character CaseEnabledIndicates whether the resolver randomizes character case in domain name queries issued to the root DNS servers. For more information, refer to K39070231: Overview of the Randomize Query Character Case setting.
Root HintsDNS root nameserversYou can override the default option (DNS root servers published by InterNIC) by specifying the IP addresses of DNS servers that the BIG-IP system considers authoritative for the DNS root nameservers. When you add DNS server IP addresses to Root Hints, the BIG-IP system no longer uses the default nameservers published by InterNIC, but instead uses the nameservers you add as authoritative for the DNS root nameservers.

The Root Hints configuration operates as follows: when the BIG-IP system receives a DNS query and the DNS cache is empty, the system sends "priming" queries to obtain the updated DNS root server information. If you manually defined root hints IP addresses for the DNS cache, the system sends "priming" queries to each address in the list, by randomly selecting an address from the Root Hints list and sending a priming query to the address. After the system has sent a priming query to each address in the list, the updated root server information is added to the DNS cache.
Prefetch KeyEnabledWhen enabled, the validating resolver fetches the DNSKEY early in the validation process. Disable this setting when you want to reduce resolver traffic, but understand that a client might have to wait for the validating resolver to perform a key lookup. This setting is displayed only when the Resolver Type is Validating Resolver.
Ignore Checking Disabled BitDisabledWhen enabled, the system ignores the Checking Disabled setting on client queries, performs validation, and returns only secure answers. This setting is displayed only when the Resolver Type is Validating Resolver.
nameserver-ttl900 secondsThis setting is introduced in BIG-IP 16.1.0 and available only in the tmsh utility. The allowable range is 0 to 4294967295 seconds. The value for this setting determines the Time To Live (TTL) for a DNS nameserver after it has been marked up or down. If a DNS nameserver becomes unresponsive, a probing scheme is applied. If this fails, the DNS nameserver is blocked for 900 seconds (default). During this period, the status of all responses from this nameserver is marked as SERVFAIL. Upon expiration of the TTL, the system attempts to contact the DNS nameserver. Reducing the value for this setting allows the BIG-IP DNS cache to recover quickly if the connectivity to the back-end DNS nameserver is interrupted.

Note: The value of the nameserver-ttl setting is synced between blades, but the time in which the queries processed by each blade may be different. As a result, the nameserver-ttl for each blade may expire at different times.
