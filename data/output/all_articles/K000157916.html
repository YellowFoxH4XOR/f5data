Topic

You should consider using this procedure under the following conditions:

  • You are running one of the following BIG-IP or BIG-IQ versions released prior to the October 2025 releases:
    • BIG-IP 17.5.1.2 and earlier
    • BIG-IP 17.1.2.2 and earlier
    • BIG-IP 16.1.6 and earlier
    • BIG-IP 15.1.10.7 and earlier
    • BIG-IQ 8.4.0 and earlier
  • You want to update CA bundles using the CA Bundle Manager.

Description

In March of 2025, F5 responded to an industry shift to phase out support for Entrust issued certificates, by replacing the Entrust certificate used at the F5 service hosting the managed CA bundle. The CA Bundle Manager utility on BIG-IP and BIG-IQ systems uses this F5 service to fetch and routinely update the default blended bundle (ca-bundle.crt). As a result, attempting to update CA bundles using the CA Bundle Manager on BIG-IP and BIG-IQ systems fails and the system will not be able to download the updated blended bundle. This issue affects all versions of BIG-IP and BIG-IQ released before October 15 2025.

A CA bundle is used any time that the BIG-IP needs to reach outbound services on the Internet. This CA bundle is like the CA keystore of any browser and is used to validate trust with the remote TLS server. If the TLS connection cannot be trusted, because the CA bundle used on the BIG-IP is missing the CA certificates needed to validate, the TLS connection will fail. In any scenario where you need the BIG-IP to connect to servers on the Internet, the correctness of this CA bundle is critical. The primary use case for this is forward proxy with products like BIG-IP SSL Orchestrator (SSLO) and F5 Secure Web Gateway (SWG), but this can also impact HTTP Connectors in BIG-IP APM reaching Internet services or iRule sideband calls to do the same. For BIG-IP, the CA Bundle Manager utility connects to https://cdn.f5.com to fetch a blended CA bundle. The CA bundle that is included in the BIG-IP image (ca-bundle.crt) contains roughly 480 CA certificates, while the blended bundle is routinely updated and contains around 900 CA certificates.

The CA Bundle Manager utility, by default, pins the TLS connection to https://cdn.f5.com to a separate f5-ca-bundle which contains the single outdated CA. Because F5 has rotated the certificate behind cdn.f5.com, the TLS connection from BIG-IP will fail and the BIG-IP will not be able to download the blended-bundle. The CA Bundle Manager comes with a default configuration object to fetch the blended bundle, which also defines the f5-ca-bundle as its trust anchor. When this issue occurs, the system logs a message similar to the following example:

Download failed: https://cdn.f5.com/product/ca-bundle/blended-bundle.crt - Peer certificate cannot be authenticated with given CA certificates

Recommendations

In order to mitigate this issue, F5 recommends you upgrade to one of the following, or later, versions:

  • BIG-IP 17.5.1.3
  • BIG-IP 17.1.3
  • BIG-IP 16.1.6.1
  • BIG-IP 15.1.10.8
  • BIG-IQ 8.4.0 HF3 (Hotfix-BIG-IQ-8.4.0.0.23.139-ENG.iso)
  • BIG-IQ 8.3.0 HF2 (BIG-IQ-8.3.0-0.38.118.iso)

If you are unable to upgrade at this time, you can mitigate this issue using the provided script below. The script downloads a curated trust anchor CA bundle from the F5 GitHub site and loops through all existing CA Bundle Manager configuration objects that are using the old CA bundle and updates them to use the new curated CA trust anchor bundle, thus allowing the CA Bundle Manager to successfully update the CA bundles moving forward. To use the script, perform the following procedure:

  • BIG-IP
  • BIG-IQ

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP

  1. Log in to the BIG-IP system Advanced shell (bash) as root.
  2. Using a text editor, create a file named f5-ca-bundle-installer.sh with the following content:

    Note: You can download the script file from GitHub by entering the following command: curl -s https://raw.githubusercontent.com/askf5/K000157916/main/f5-ca-bundle-installer.sh -O

    #!/bin/bash
## Author: kevin-at-f5-dot-com
## Version: 20251216-2
## Installs a new curated F5 CA bundle on the BIG-IP

BUNDLE_NAME="f5-ca-bundle-new.crt"
CERT_URL="https://raw.githubusercontent.com/askf5/K000157916/main/updated-ca-bundle.crt"
HASH=5a062aa2c73be246f650dd0a48554a8beecc0ad1623d89132c132ba7585f0384

## Reporting function
report() {
    local interact="${1}"
    local message="${2}"

    if [ "${interact}" == 1 ]; then
        echo -e "${message}"
    else
        logger -p local0.info "F5 CA Bundle Update Script: ${message}"
    fi
}

## Test for interactive shell
if [ -t 0 ]; then interactive=1; else interactive=0; fi

## Ask interactive user for option to update existing CA Bundle Mgr objects (bypass for non-interactive/BIG-IQ script run)
if [ "${interactive}" == 1 ]; then
    ## Ask user if they want the script to update any ca-bundle-manager objects using the old bundle
    answer=false && found=false
    echo -e "Do you wish for this script to adjust any CA Bundle Manager objects using the old F5 CA bundle?"
    echo -e "Note: the default 'ca-bundle.crt' object cannot be modified."
    while true; do
        read -p "Type 'yes', 'no', or 'q' to quit: " yn
        case $yn in
            yes ) answer=true; break;;
            no ) answer=false; break;;
            q ) answer=false; exit;;
        esac
    done
else
    answer=true
    found=false
fi

## Echo/log start of script
report "${interactive}" "Starting"

## Fetch the new CA bundle file and store locally for validation testing
curl -s "${CERT_URL}" -o "${BUNDLE_NAME}"

## TEST: Calculate SHA256 hash on the downloaded CA bundle, exit on validation failure
echo "${HASH} ${BUNDLE_NAME}" | sha256sum --check --status
if [ $? -ne 0 ]; then report "${interactive}" "Checksum failed, halting" && rm -f "$(pwd)/${BUNDLE_NAME}" && exit 1; fi

## TEST: Count the number of certs in the bundle. Verify that at least one certificate exists in the bundle, exit on validation failure
certcount=$(grep -e "-----BEGIN CERTIFICATE-----" "${BUNDLE_NAME}" | wc -l)
if [ "$certcount" == 0 ]; then report "${interactive}" "CA bundle download failed, halting" && rm -f "$(pwd)/${BUNDLE_NAME}" && exit 1; fi

## Loop through and verify all certs in the bundle, exit on any validation failures
for index in $(seq 1 ${certcount}); do
    ## Separate each certificate
    tmpcert=$(awk "/-----BEGIN CERTIFICATE-----/{i++}i==$index" "${BUNDLE_NAME}")
    
    ## TEST: Run openssl x509 on each certificate to get details, also checking for parsing errors. Exit on validation failures
    certdata=$(echo "$tmpcert" | openssl x509 -noout -subject -issuer -enddate 2>&1)
    if [ $? -ne 0 ]; then report "${interactive}" "Found certificate error, halting" && rm -f "$(pwd)/${BUNDLE_NAME}" && exit 1; fi
done
      
## Validation tests passed: Create/update f5-ca-bundle-new
tmsh install sys crypto cert ${BUNDLE_NAME} from-local-file "$(pwd)/${BUNDLE_NAME}"

## If user opts to update CA bundle mgr objects, loop through ca-bundle-manager objects and replace the trusted-ca-bundle if using the old bundle
if [[ "$answer" == "true" ]]; then
    for p in $(tmsh list sys crypto ca-bundle-manager | egrep '^sys' | awk -F" " '{print $4}'); do 
        if [[ "$p" != "ca-bundle" && "$(tmsh list sys crypto ca-bundle-manager ${p} one-line)" =~ "f5-ca-bundle.crt" ]]; then
            report "${interactive}" "$p contains old f5-ca-bundle"
            found=true
            tmsh modify sys crypto ca-bundle-manager ${p} trusted-ca-bundle ${BUNDLE_NAME}
        fi
    done
    if [[ "$found" == "false" ]]; then
        report "${interactive}" "No CA bundle manager objects are using the old F5 CA bundle"
    fi
fi

## Clean up local files, echo/log end of script
rm -f "$(pwd)/${BUNDLE_NAME}"
report "${interactive}" "Complete"
exit 0
  3. Make the f5-ca-bundle-installer.sh file executable by entering the following command:

    chmod 744 ./f5-ca-bundle-installer.sh

  4. Enter the following command to run the script:

    ./f5-ca-bundle-installer.sh

  5. The following prompt appears:

    Do you wish for this script to adjust any CA Bundle Manager objects using the old F5 CA bundle?
    Note: the default 'ca-bundle.crt' object cannot be modified.
    Type 'yes', 'no', or 'q' to quit:

    To update any CA Bundle Manager objects, enter yes and press Enter:

  6. Output will appear similar to the following example when complete:

    Complete

Important: The script does not update the default blended bundle(ca-bundle.crt) object. The default ca-bundle object needs to update manually. To update default ca-bundle, refer to K60612439 after you downloaded the new certificate bundle for continued access to F5 services.

BIG-IQ

For BIG-IQ deployments, you need to run the script natively on the BIG-IQ system to update its CA bundle, then run the script in Script Management in order to update the managed BIG-IP systems. To do so, perform the following procedures:

  • Update BIG-IQ
  • Update managed BIG-IP systems

Update BIG-IQ

  1. Log in to the BIG-IQ Advanced shell (bash) as root.
  2. Perform steps 2 - 6 from the BIG-IP procedure above to create the script file and run the script. 
  3. You can verify the new CA bundle by entering the following command:

    tmsh show /sys crypto cert f5-ca-bundle-new.crt

Update managed BIG-IP systems

  1. Log in to the BIG-IQ Configuration utility.
  2. Go to Devices > Script Management > Scripts.
  3. Select Add.
  4. Enter a name for the script.
  5. Enter the contents of the script into the Script box.
  6. Select Save & Close.
  7. Select the check box next to the newly added script.
  8. Select Run to update the managed BIG-IP systems.
  9. In the Script Task Properties screen, enter a Name for the task, then select the check box next to the managed BIG-IP system you want to update.
  10. Select the right arrow to move the selected BIG-IP system from the Available box to the Selected box.
  11. Select Run.
  12. When updating managed BIG-IP system using BIG-IQ, the script runs non-interactively so there are no prompts. You can use the tail -f /var/log/ltm command on the managed BIG-IP system to monitor the progress. You should see output similar to the following example when successful:

    F5 CA Bundle Update Script: Starting
    F5 CA Bundle Update Script: example-bundle-mgr contains old f5-ca-bundle
    F5 CA Bundle Update Script: Complete
