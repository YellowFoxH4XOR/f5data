Chapter 0: Guide introduction and contents

Introduction

An application programming interface (API) is a software component that is commonly used to integrate applications and microservices with existing applications and software systems. As API use increases, attacks against APIs have become more prevalent; a recent Gartner study suggests that API attacks are among the most-frequent attack vector. In addition, APIs are subject to many of the same types of attacks as web applications and may be especially vulnerable to attacks related to authentication, authorization, and excessive data exposure.

Note: This guide pertains to the Open Web Application Security Project (OWASP) Top 10 risks for APIs. For information about the OWASP Top 10 risks for web applications and how to secure your F5 products and web applications against the OWASP Top 10 risks, refer to K45215395: Guide introduction and contents | Secure against the OWASP Top 10 for 2021.

About the OWASP API Security Top 10

The OWASP API Security Top 10 (2023) defines the most serious security risks for APIs. For more information, refer to the OWASP API Security Top 10.

F5 products provide controls that enable you to secure your F5 products and APIs against the OWASP API Security Top 10 risks.

Secure your APIs against OWASP API Top 10 risks with F5 products

This guide describes how to use the security controls available in F5 products to secure your APIs against the OWASP API Security Top 10 risks. Bear in mind that your configuration and the level of security protection you implement depend on the specifics of your API.

F5 Distributed Cloud services (F5 XC)

Security controls are available in F5 Distributed Cloud services, which use both positive and negative security models to secure your APIs against OWASP API Security Top 10 risks. The positive security model is based on a combination of API discovery, inventory, authenticated/unauthenticated API identification, access control list, and rate limit. The negative security model uses attack signatures to detect and thwart OWASP API Security Top 10 attacks.

F5 BIG-IP Advanced WAF and BIG-IP ASM

Security controls are available in the Advanced WAF and BIG-IP ASM systems, which use both positive and negative security models to secure your APIs against OWASP API Security Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and application response. The negative security model uses attack signatures to detect and thwart OWASP API Security Top 10 attacks.

BIG-IP APM

You can enhance API security against OWASP API Security Top 10 risks by using the BIG-IP APM system, which provides authentication, authorization, and other different controls such as rate limiting, clearly defined URI endpoints and methods for API protection.

NGINX App Protect

Security controls are available in the NGINX App Protect system, which uses both positive and negative security models to secure your APIs against OWASP API Security Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and API response. The negative security model uses attack signatures to detect and thwart OWASP API Security Top 10 attacks.

Contents

Chapter 1: Broken object level authorization (API1:2023)

Broken object level authorization occurs when authorization rules that dictate which object can be accessed by which users do not exist or are not applied properly. This allows attackers to manipulate API request parameters to access objects to which they are not authorized to access. This chapter includes the following topics:

  • Broken object level authorization
  • Secure your APIs against broken object level authorization attacks with F5 products

Chapter 2: Broken authentication (API2:2023)

Broken authentication occurs when the API authentication mechanisms are lacking or are not implemented correctly, allowing attackers to gain complete control of other users' accounts in the system, read their personal data, and perform sensitive actions on their behalf. Attacks that target authentication endpoints include brute-force, credential stuffing, and credential cracking. This chapter includes the following topics:

  • Broken authentication
  • Secure your APIs against broken authentication attacks with F5 products

Chapter 3: Broken object property level authorization (API3:2023)

Broken object property level authorization occurs when the API is designed to return all properties of an object without considering the sensitivities of each property. This leads to the API returning more data than required by the end user, thereby increasing the risk of exposure of sensitive data. This chapter includes the following topics:

  • Broken object property level authorization
  • Secure your APIs against broken object property level authorization attacks with F5 products

Chapter 4: Unrestricted resource consumption (API4:2023)

Unrestricted resource consumption occurs when there are inadequate restrictions on the number, content, and type of requests made by users of the API. This chapter includes the following topics:

  • Unrestricted resource consumption
  • Secure your APIs against unrestricted resource consumption attacks with F5 products

Chapter 5: Broken function level authorization (API5:2023)

Broken function level authorization occurs when API user functions are not clearly defined or are too complex and, as a result, authorization checks are not completely implemented based on clear user group and roles. This chapter includes the following topics:

  • Broken function level authorization
  • Secure your APIs against broken function level authorization attacks with F5 products

Chapter 6: Unrestricted access to sensitive business flows (API6:2023)

Unrestricted access to sensitive business flows occurs when an API exposes a business flow without regard to whether excessive access to the flow may harm the business. This chapter includes the following topics:

  • Unrestricted access to sensitive business flows
  • Secure your APIs against unrestricted access to sensitive business flows attacks with F5 products

Chapter 7: Server side request forgery (API7:2023)

Server side request forgery attack occurs when an API is fetching a remote resource without validating the user-supplied URL. This chapter includes the following topics:

  • Server side request forgery
  • Secure your APIs against server side request forgery attacks with F5 products

Chapter 8: Security misconfiguration (API8:2023)

Security misconfiguration vulnerabilities occur when an API component is susceptible to attack due to a misconfiguration or non-secure configuration option. Misconfiguration vulnerabilities are configuration weaknesses that may exist at any level of the API stack. This chapter includes the following topics:

  • Security misconfiguration
  • Secure your APIs against Security misconfiguration attacks with F5 products

Chapter 9: Improper inventory management (API9:2023)

Improper inventory management vulnerabilities can occur when security best practices are not followed during the API development cycle. Not following security best practices in the design phase may lead to vulnerabilities such as old API versions, unpatched systems, outdated API documentation, and unnecessarily exposed API endpoints. This chapter includes the following topics:

  • Improper inventory management
  • Secure your APIs against improper inventory management attacks with F5 products

Chapter 10: Unsafe consumption of APIs (API10:2023)

Unsafe consumption of APIs occurs when the back-end systems or API implementations that have integration with external or third-party APIs do not verify the endpoints or validate/sanitize their inputs. This chapter includes the following topics:

  • Unsafe consumption of APIs
  • Secure your APIs against unsafe consumption of APIs attacks with F5 products
