K000159592: Export and re-import of WAF security policy in XML format fails with error "Field parameter/user_input_format may not contain the value 'openapi-array'"

Type
Support Solution
Published
2026-01-16
Updated
2026-01-16
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000159592

Description

When attempting to export and re-import a BIG-IP Advanced WAF security policy in XML format, the operation fails with the following error:

Field parameter/user_input_format may not contain the value 'openapi-array'

This issue prevents cloning or migrating security policies that were originally created using an OpenAPI template.
The 'openapi-array' value is present in the exported XML file but is not visible in the Configuration utility (UI).
The error specifically affects XML-based policy exports and imports.
Binary format exports (.plc) are not affected by this issue.

Environment

  • BIG-IP Advanced WAF version 17.1.3
  • Security policies created using an OpenAPI template
  • Parameters with user_input_format value set to 'openapi-array' (e.g., "post_logout_redirect_uri")
  • XML export format (.xml)

Cause

Bug ID2199485

Answer/Recommended Actions

Option 1: Use Binary Export Format (Recommended)

  1. Navigate to Security > Application Security > Security Policies
  2. Select the security policy you want to export
  3. Click Export
  4. Choose Binary format (.plc) instead of XML
  5. Use the binary export file to import or clone the policy

Option 2: Modify Parameter Data Type

  1. Navigate to the affected parameter (e.g., "post_logout_redirect_uri") in the security policy
  2. Change the data type to Alpha-Numeric
  3. Export the policy in XML format
  4. The XML export/import will now work correctly

Option 3: Request an EHF from f5 support

Additional Information

  • The binary export format (.plc) is not affected by this issue and can be used as an alternative to XML exports for policy migration and cloning operations
  • This issue is specific to security policies created using the OpenAPI template and does not occur with policies created using other templates
  • The 'openapi-array' user_input_format value is valid for OpenAPI-based policies but is not compatible with XML import operations in the affected version
  • Changing the parameter data type from 'openapi-array' to 'Alpha-Numeric' allows XML export/import to function, but may affect parameter validation behavior
