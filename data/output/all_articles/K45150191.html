Issue

Error Message

011b0203:3: Error <message> opening file <filename>

In this error message, note the following:

  • <message> is a string indicating the problem.
  • <filename> is the name of the file to be opened.

For example:

011b0203:3: Error 'No such file or directory' opening file /sys/block/sdb/stat

Message Location

You may encounter this message in the following locations:

  • The /var/log/ltm file
  • The BIG-IP Configuration utility

Description

This message occurs when the following condition is met:

  • The merged or statsd process failed to open a file for reading.

For example, if the error message references the /sys/block/sda/stat file, the drive (sda) might be defined by the operating system, but the statistics are not available yet or are no longer available. This error may also be generated by disk failures.

Impact

Statistics for the disk are unavailable if the file in the message is /sys/block/<disk>/stat.  If the file in the message is located in the /var/rrd/ directory, historical data is unavailable for the BIG-IP system.

Recommended Actions

  • If the file is /sys/block/<disk>/stat, there is no workaround, and you may need to replace the disk if rebooting the BIG-IP system does not resolve the issue.
  • For the /var/rrd/ directory, verify that the directory exists, and that the directory and the files it contains have the correct permissions. To do so, perform the following procedure:

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the BIG-IP system command line as root.
    2. The /var/rrd file is a symbolic link to the /shared/ directory.  Verify the link to the /shared/rrd.1.2/ directory by typing the following command:

      ls -al /var/

      The output for the link should look similar to the following example:

      lrwxrwxrwx  1 root  root     15 Jun 17 10:15 rrd -> /shared/rrd.1.2

      If the link has incorrect permissions, delete the link and re-create it by typing the following commands:

      rm -f /var/rrd

      ln -s /shared/rrd.1.2 /var/rrd

       
    3. Verify the permissions for the /shared/rrd.1.2 directory by typing the following command:

      ls -al /shared/

      If the permissions are correct, the output should looks similar to the following example:

      drwxrwxrwt  2 root root     760 Jun 17 10:15 rrd.1.2

      If the permissions are incorrect, set them to the default settings by typing the following command:

      chmod 1777 /shared/rrd.1.2/

       
    4. Verify the permissions for the files in the /shared/rrd.1.2 directory by typing the following command:

      ls -al /shared/rrd.1.2/

      The permissions for all the files should look similar to the following two example entries:

      -rw-r--r--  1 root root  1474888 Jul 27 11:51 access
      -rw-r--r--  1 root root     2278 Jan 22  2014 access.info

      If the permissions are incorrect, set them to the default by using the following command syntax, replacing <filename> with the name of the file with incorrect permissions:

      chmod 644 /shared/rrd.1.2/<filename>
