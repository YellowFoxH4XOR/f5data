Description


Traffic passes over an IPsec tunnel after a restart, but fails after a period of time.
 

Environment
 

  • IPsec tunnel using IKEv2.
  • Configuration of PFS (perfect forward secrecy) on ike-peer (phase 1) and ipsec-policy (phase 2) are different.
  • This is most likely to occur when the remote endpoint is not a BIG-IP.

Cause


Due to the shortened nature of security association (SA) setup in IKEv2, the initial phase 2 SAs are established using the value of "phase1-perfect-forward-secrecy".
BIG-IP uses this setting for all future rekeying. The value of ike-phase2-perfect-forward-secrecy is ignored and overridden.

Some vendors may implement this differently triggering SA rekey failure.

Recommended Actions


Configure the BIG-IP ike-peer and ipsec-policy PFS to have the same value.
Configure the remote peer to match.
