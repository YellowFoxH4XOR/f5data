K000136091: Slow GRE performance with AFM provisioned

Type
Support Solution
Published
2023-09-06
Updated
2024-01-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.6
Source
https://my.f5.com/manage/s/article/K000136091

 

Description

GRE (Generic Routing Encapsulation) traffic is underperforming. Captures indicate that BIG-IP is dropping GRE packets.
 

Environment

 

  • GRE passing through BIG-IP via fastL4.
  • GRE being terminated on BIG-IP.
  • DDOS is enabled via AFM provisioning.


Cause

 

BIG-IP DDOS protection identifying GRE as "IP uncommon proto" and applying throughput thresholds.
 

Recommended Actions

 

Either increase the thresholds for "IP uncommon proto" or change GRE from "unknown" to "known" uncommon protocol.
 

Additional Information

 

For GRE with DDOS protection, the GRE traffic is marked as "IP uncommon proto" and are likely to be dropped if the thresholds are exceeded.
 

Looking at the output of "tmsh show /security dos device-config" from either qkview or direct on BIG-IP

---------------------------------------------------------------
Security::DOS/stat: IP uncommon proto
---------------------------------------------------------------
...
Drops       155929     <=== drops
Drops Rate       0
Drops 1m         0
Drops 1h         3
...

 

This is confirmed by the logs in /var/log/ltm:

# grep -hE "uncommon" ltm*

Aug 8 23:40:17 <BIG-IP> err tmm2[6934]: 01010252:3: A Enforced Device DOS attack start was detected for vector IP uncommon proto, Attack ID 4003717357.

Aug 8 23:47:04 <BIG-IP> notice tmm1[6934]: 01010253:5: A Enforced Device DOS attack has stopped for vector IP uncommon proto, Attack ID 4003717357.

 

To change the thresholds:
From the GUI:

 Security -> DoS protection -> Device protection

  Click on network, scroll down and click on IP Uncommon Proto

From there you can make the changes that you want to make.


Alternatively, move GRE from the "IP Uncommon Proto List". ie: From the same panel, select "GRE" and move it to the right hand panel to be a "known" protocol.


If you wish to test threshold setting, use the following command live on BIG-IP:

  tmctl dos_stat vector_name="IP uncommon proto" -q -s drops

eg: # tmctl dos_stat vector_name="IP uncommon proto" -s drops,drops_rate,drops_1m,drops_1h,dropped_bytes
