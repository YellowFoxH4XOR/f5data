K25415554: The BIG-IP ASM system blocks suspicious browsers without issuing a CAPTCHA challenge

Type
Known Issue
Published
2018-06-07
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 13.0.0, 12.1.3, 12.1.2
Source
https://my.f5.com/manage/s/article/K25415554

Known Issue

When the system identifies a suspicious browser and blocks the request, you cannot force a Bot Defense iRules action to issue a CAPTCHA challenge.

This issue occurs when all of the following conditions are met:

  • The Bot Defense iRules command triggers a TCP RST for a suspicious browser.
  • You want to issue a CAPTCHA challenge.

Impact

The system blocks suspicious browsers without issuing a CAPTCHA challenge.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system unexpectedly blocks some browser clients.
  • If logging is enabled, bot defense actions return the following message in the /var/log/ltm file:

    request is a followup of a challenge

Resolution

Status

Workaround

To work around this issue, you can change the dosl7.browser_legit_min_score_drop database variable to issue a CAPTCHA challenge to all suspicious browsers. To do so, perform the following procedure:

Impact of workaround: The system will issue all suspicious browsers CAPTCHA challenges.

  1. Log in to the TMOS Shell (tmsh) as an administrative user.
  2. Type the following command:

    modify sys db dosl7.browser_legit_min_score_drop value 999
