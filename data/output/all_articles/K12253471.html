Known Issue

The Traffic Management Microkernel (TMM) may produce a core file and restart during GY reporting.

This issue occurs when all of the following conditions are met:

  • Failover is triggered on a chassis platform installed with more than one slot.
  • The disaggregation (DAG) library hash redistributes the subscriber data to different slots on the chassis hardware.
  • Existing flows continue on the slots that were allocated using the old hash of the DAG library.

    Note: This issue is rare.

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is configured for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When the intra-chassis failover is triggered in a loaded chassis, TMM produces a core file and restarts during GY reporting.
