K000160141: BIG-IP HA Cluster: Security Log Profiles Not Syncing Between Devices Despite "In Sync" Status (Bug ID2171845)

Description

In BIG-IP LTM high availability (HA) clusters running version 17.1.x, security log profiles attached to virtual servers do not synchronize correctly between devices during manual or overwrite sync operations. The cluster reports an "In Sync" status despite configuration inconsistencies. This issue affects only security log profiles; all other objects (such as profiles, pools, and policies) synchronize as expected. Typical symptoms include:

  • Virtual servers on primary and secondary devices have different security log profiles assigned
  • Manual sync or overwrite sync does not resolve the inconsistency
  • The cluster status remains "In Sync" even when configurations differ
  • No error messages are shown, but log profile differences are visible in CLI or GUI configuration comparisons

Environment

  • Product: BIG-IP LTM
  • Configuration: HA cluster with two devices (Primary/Secondary)
  • Sync Mode: Manual sync (full-load and incremental)
  • Security log profiles attached to virtual servers

Cause

A software bug (Bug ID 2171845) in BIG-IP 17.1.x causes security log profiles attached to virtual servers to not synchronize correctly during manual or overwrite sync operations. This results in configuration drift while the system incorrectly reports "In Sync" status. 

Answer/Recommended Actions

  1. Apply Engineering Hotfix (EHF):
    • An Engineering Hotfix is available that includes the fix for Bug ID2171845 on top of BIG-IP 17.1.3.1.
  2. Preparation Before Upgrade:
    • Ensure manual sync mode is enabled.
    • Perform a manual sync from the device with the correct configuration to its peer.
  3. Post-Upgrade Actions:
    • After upgrading and applying the EHF, perform a manual sync from the device with the correct configuration to its peer to ensure consistency.
    • Avoid using sync overwrite from a device that does not have the latest intended configuration.
  4. Verification:
    • Use the following command to list security log profiles attached to each virtual server:
    tmsh list ltm virtual { security-log-profiles }
    • Compare outputs between devices to confirm consistency.
  5. Resume Normal Operations:
    • Once the issue is resolved and configurations are consistent, normal sync operations can be resumed.

Additional Information

  • The issue is limited to security log profiles attached to virtual servers; other LTM and ASM objects synchronize correctly.
  • Manual intervention is required to verify and update log profiles prior to applying the fix.
  • The fix was validated in lab environments and confirmed by F5 Product Development.
