K12467: An accumulation of uncleaned temporary files may result in insufficient disk space to create new report files

Known Issue

This is the result of a known issue. An accumulation of uncleaned temporary files may result in the disk space allocated for reports to become insufficient for creation of new reports. As a result, attempts to create a new report will fail and an error message that appears similar to the following example will be logged to the syslog file:

:REPORT-0-ERR-REPORT_NO_SPACE:: There is not enough space to generate the report file <filename>. 123456789 bytes are required but only 1234567 bytes are available. Please delete old reports to free up additional space.

F5 Product Development tracked this issue as ID 348130 and it was fixed in ARX version 5.2.2. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was fixed in ARX version 5.1.9 HF1. For information about this hotfix or later versions of the cumulative hotfix, refer to K12595: Overview of ARX version 5.1.9 hotfixes.

The accumulation of uncleaned temporary files results from copying reports off of the ARX using FTP, NFS, CIFS or SCP and and specifying a format other than XML. The ARX system will create a temporary file to perform a conversion prior to transferring the report. The ARX does not clean up this temporary file upon successful completion of the copy. If multiple reports are copied during a single logon session or scheduled job, the ARX will overwrite and re-use the same temporary file. However, when the logon session or scheduled job ends the temporary file from the last copied report will remain. The ARX will create another temporary file for each logon session or scheduled job that copies a report.

Note: The file size of the last report copied during a user session or scheduled job will directly affect the rate at which temporary space is consumed.

Customers already affected by this issue should contact F5 Technical Support to request assistance removing the unremoved temporary files. Reference ID 348130 and this Solution.

Workaround

There is no work around that will eliminate the issue. However, the rate at which the temporary space is consumed can be slowed. To minimize the effect of this issue, prior to logging out of a session or ending a scheduled job that was used to copy reports, you should copy a known small report off of the ARX using the same syntax as used previously.  This will overwrite the temporary file that was created for that session, leaving a smaller file in the temporary directory. 

You can create a "small" report for this purpose using the following procedure:

  1. Log in to the ARX CLI.
  2. Create an report file using the following command syntax:

    terminal logging <report_prefix>

    For example, create a report file with a prefix of empty_file by typing the following command:

    terminal logging empty_file

    The output of the command will indicate the report filename similar to the following:

    Generating CLI output report: 'empty_report_201103022233.rpt'..
  3. Stop logging to the report file by typing the following command:

    no terminal logging

This procedure will create a report file that is essentially empty (593 Bytes). 

Note: This report may be removed at any time using a delete reports <report_name> command. The full report name can be displayed using the show reports type CLI command. For information about the delete reports or show reports commands, refer to the ARX CLI Reference Guide.

Determining the cause of insufficient space

Additionally, the insufficient space to create reports may simply be a result of too many reports. To determine if the insufficient space is a result of this issue, or if there are too many reports stored on the ARX system. You can use the show reports command to list the report files on the ARX system and the show chassis diskuse command to view the amount of disk space reported as Used for reports.

For systems affected by this issue, the amount of disk space reported as Used for reports will be greater than the sum of the file sizes shown for the reports on the ARX system.

If the insufficient space is a result of too many report files stored on the ARX system, remove old report files that are no longer required.
