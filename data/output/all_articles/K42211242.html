K42211242: BIG-IP APM: Navigating to <apm_fqdn>/my.policy results in invalid session error

Type
Support Solution
Published
2022-04-21
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K42211242

Description

This article will describe the behavior and workaround for when a user attempts to access an APM enabled Virtual Server by going directly to <apm_fqdn>./my.policy instead of the <apm_fqdn>. For example a user has saved a bookmark in their browser for https://f5_apm.f5.com/my.policy.

  • User navigates to the URI <apm_fqdn>./my.policy instead of the <apm_fqdn>
  • In the browser the user will see an "Invalid session" error or "Your session could not be established."
  • You will see the following message in /var/log/apm:
<bigip_hostname> notice tmm1[11768]: 01490520:5: /Common/<access_policy_name>:<session_id>: Session deleted due to admin initiated termination.

Environment

  • APM (Access Policy Manager)
  • Virtual Server with an Access Policy.
  • Web Browser

Cause

This issue occurs because the APM is expecting a Session Cookie at the /my.policy URI. Since there is no Session Cookies set when you go directly to this URI you receive a invalid session error.

Recommended Actions

Add the following iRule as a workaround for this issue.

  1. Login to the BIG-IP Admin GUI
  2. Navigate to Local Traffic>iRules>iRule List
  3. Click Create
  4. Enter a name for the iRule in the Name field.
  5. In the Definition field enter the following iRule:
when CLIENT_ACCEPTED {
        ACCESS::restrict_irule_events disable
}

when HTTP_REQUEST {
    if { [HTTP::uri] equals "/my.policy" } {
        if { [ACCESS::policy result] equals "" } {
            HTTP::respond 302 Location "/"
        return
        }
    }
}

6. Click Finished.
7. Navigate to Local Traffic>Virtual Servers>Virtual Server List.
8. Select the APM Virtual Server.
9. Select the Resources tab.
10. Click on Manage for the iRules.
11. Move the iRule to the enabled list.
12. Click Finished.
