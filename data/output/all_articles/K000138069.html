K000138069: /shared/tmp/.config.tmp on BIG-IP fills up every 2-3 mins when BIG-IQ discovers it for the first time

Description

BIG-IP devices managed by BIG-IQ Centralized Management can accumulate temporary directories under .config.tmp when statistics collection is enabled. The directories may consume all available inodes on the /shared filesystem and prevent configuration-save operations from completing.

 

Environment

The issue can occur in the following environment:

BIG-IP LTM or BIG-IP DNS managed by BIG-IQ Centralized Management.
BIG-IQ Centralized Management statistics collection enabled.
Large or complex configurations, including multiple partitions or DNS/GTM objects.
Configuration discovery, import, or save operations involving the BIG-IP device.

 

Cause

Bug ID1036461

BIG-IP creates temporary configuration directories under .config.tmp during configuration-related processing. These directories are expected to be removed after processing completes. Under the affected condition, cleanup does not complete, causing the directories to persist and accumulate.

The directories contain configuration-processing data rather than statistics data itself. Statistics collection can trigger or expose the configuration-processing activity, but the disk and inode exhaustion results from stale temporary directories not being removed.

 

Recommended Actions

1. Temporarily disable BIG-IQ Centralized Management statistics collection for the affected BIG-IP device:

Navigate to Devices.
Select the BIG-IP device.
Open Statistics Collection.
Clear Collect Statistics Data.

2. Check inode utilization and temporary-directory growth:

df -i /shared
du -sh /shared/tmp/.config.tmp
ls -la /shared/tmp/.config.tmp

3. Remove stale temporary subdirectories after confirming that no configuration operation is active. Deleting stale subdirectories under .config.tmp is safe, but removing a large number of entries can generate significant disk I/O and temporarily affect device performance.

4. Install a software fix containing Bug ID1036461. Contact F5 Support to obtain the fix applicable to the installed BIG-IP release.

5. After installing the fix, re-enable statistics collection and monitor:

/shared inode utilization.
The number and age of directories under .config.tmp.
Configuration-save operations.
Audit and MCPD logs for SDM:Save is already in progress messages.

 

Additional Information

Manually deleting stale temporary directories may provide immediate relief, but the directories can return if the underlying cleanup issue remains unresolved.
When /shared reaches 100% inode utilization, BIG-IP may be unable to complete configuration-save operations or generate backups.
Changing the BIG-IQ Centralized Management statistics collection interval does not correct the underlying cleanup failure.
The software fix addresses the stale temporary-directory cleanup issue so that the data no longer consumes disk space or inodes.
