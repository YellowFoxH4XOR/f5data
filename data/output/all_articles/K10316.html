Known Issue

This is the result of a known issue. When a BIG-IP WebAccelerator virtual server is configured with autoNTLMAuth enabled, the BIG-IP WebAccelerator sets the pv_ntlm_auth cookie without specifying a domain attribute for the cookie.

Different browsers may respond differently when managing a cookie which does not include a domain attribute. As a result, cookie-dependent BIG-IP WebAccelerator features, such as MultiConnect, may not function as expected with some browsers.

For example, Microsoft Internet Explorer will send a domainless cookie in future requests for the originally-requested host and any of its subdomains. Requests for multiconnected URLs will include the cookie. However, Firefox will send a domainless cookie only in future requests for the originally requested host, not for its subdomains. As a result, Firefox requests for multiconnected URLs will not include the expected cookie, and the MultiConnect feature will fail.

F5 Product Development tracked this issue as ID 208394 (Formerly CR122236 and CR118629) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-HF1 issued for BIG-IP version 10.0.1. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

Workaround

You can work around this issue by using an iRule similar to the following example to add a domain to the pv_ntlm_auth cookie:

when HTTP_RESPONSE_SEND {
   if { [HTTP::cookie exists pv_ntlm_auth] } {
      HTTP::cookie domain pv_ntlm_auth "www.domain.com"
   }
}

Note: For more information about HTTP cookies, refer to RFC2965 - HTTP State Management Mechanism.

Note: For information about a related issue regarding the NTLMconnpool cookie used in BIG-IP version 10.x, refer to SO10285: The NTLMconnpool cookie does not include a domain attribute.
