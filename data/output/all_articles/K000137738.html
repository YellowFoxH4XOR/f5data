K000137738: F5 BIG-IP inserts the same persistence cookie twice - encrypted and not encrypted

Type
Support Solution
Published
2023-12-08
Updated
2023-12-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.0, 16.1.2, 16.1.1, 16.1.X, 16.1.4, 16.1.3
Source
https://my.f5.com/manage/s/article/K000137738

Description

F5 BIG-IP can set the same persistence cookie twice - one encrypted and another not encrypted.

Environment

  • BIG-IP LTM
  • cookie persistence profile
  • cookie encryption

Cause

Each time there is a load balancing decision made and a cookie persistence profile is used on virtual server F5 BIG-IP inserts a persistence cookie into HTTP response.

When HTTP traffic is passing through two virtual servers and each virtual server has the same cookie persistence profile in use then the same persistence cookie will be inserted twice using the same name but different values. Additionally, if persistence cookie encryption is enabled, the first virtual server sets persistence cookie encrypted and another virtual server sees that cookie existing and encrypted so another cookie with the same name is inserted but this time with not encrypted value.

Recommended Actions

Use dedicated persistence profiles for each virtual server. Persistence cookie names should be unique.
