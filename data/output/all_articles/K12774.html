Known Issue

The BIG-IP system marks pool members down when a database server returns NULL.

This issue occurs when all of the following conditions are met:

  • The BIG-IP has a SQL monitor (MSSQL, MySQL, Oracle, or PostgreSQL) configured with both a Send String and a Receive String.
  • The SQL server returns a NULL response after processing the Send String.

Impact

The BIG-IP system marks the pool member down after the configured timeout elapses. In addition, if there is another instance of the same SQL monitor assigned to a different pool member, the other pool member will be incorrectly marked down after the configured timeout elapses, even though it returns a response that matches the Receive String.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Using the following example BIG-IP configuration:

    monitor mysql-mon {
    defaults from mysql
    interval 10
    timeout 31
    database "test"
    password "bigip"
    recv "UP"
    send "select b from test where a = 3;"
    username "bigip"
    }
    pool mysql-poolA {
    monitor all mysql-mon
    members 10.10.10.219:mysql {}
    members 10.10.10.220:mysql {}
    }
    • The MySQL server 10.10.10.219 returns NULL after evaluating the Send String, the BIG-IP system marks the pool member 10.10.10.219 down after the timeout 31 seconds elapses, and logs a message to the /var/log/ltm file that appears similar to the following example:

      01070638:5: Pool member 10.10.10.219:3306 monitor status down
    • The MySQL server 10.10.10.220 returns UP after evaluating the Send String, the BIG-IP system also marks the pool member 10.10.10.220 down after the timeout 31 seconds elapses, and logs a message to the /var/log/ltm file that appears similar to the following example:

      01070638:5: Pool member 10.10.10.220:3306 monitor status down

Workaround

To work around this issue, you can prevent the SQL server from returning NULL. This can usually be achieved by using a SQL command that results in the SQL server returning a non-NULL response if the SQL expression is evaluated to be NULL. To do so, perform the following procedure:

Impact of workaround: The following example may not apply to all environments. F5 recommends that you consult the vendor documentation for your SQL server software, and test any modifications in an appropriate environment.

To modify the monitor send string, perform the following procedure:

Using the previous configuration example, you can use the IFNULL(expr1, expr2) command for MySQL 5.0 in the Send String field, to look like the following example:

select ifnull(b,’UP’) from test where a = 3;

The previous SQL expression results in the MySQL server returning a string value of UP instead of NULL.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Monitors > Monitor List.
  3. Click the name of the SQL monitor you would like to modify.
  4. Replace the content in the Send String box with the suggested, appropriate workaround SQL expression, depending on your SQL server type and version.

    For example, you would type the following MySQL expression for MySQL server 5.0:

    select ifnull(b,’UP’) from test where a = 3;

  5. To save the changes, click Update.
