Topic

The BIG-IP system uses a trunk distribution hash algorithm to statistically distribute traffic in a trunk group among member ports. The system recombines various address and attribute bits from each transmitted frame to specify the particular trunk port that the frame uses.

Description

For IPv6 traffic on most platforms, and for all IPv4 traffic, the BIG-IP system uses a typical algorithm based on the source and destination IP address and the service port information to create the hash and select the trunk port. This allows optimal frame distribution, which egresses to a common Layer 2 (L2) destination bound for diverse Layer 3 (L3) destinations, such as those traversing a local gateway router to access a system on a different sub network. For details, refer to the List of platforms and hash algorithm used table later in this article.

For IPv6 traffic on some platforms, a hardware limitation prevents the BIG-IP system from using the source and destination address in the trunk hash algorithm. Instead, the system uses the three least significant bits from both the source and destination MAC addresses to create the hash and select the trunk port. As a result, all IPv6 traffic that egresses over a trunk using the same source and destination MAC addresses, regardless of the source and destination IP address, uses only a single port in the trunk instead of distributing the frames over multiple trunk ports when address information varies.

There are two common scenarios in which this limitation may cause problems for IPv6 traffic. On a client-side trunk group, if many IP addresses correspond to a single MAC address, the response frames from the BIG-IP system to the multi-homed device all use the same hash value and therefore also use only a single trunk port. On a server-side trunk group, if the trunk terminates on an L2/L3 switch between the BIG-IP system and the server pool network, all frames use the same hash value and therefore use only a single trunk port.
