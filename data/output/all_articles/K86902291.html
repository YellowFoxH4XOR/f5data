K86902291: Changes to the device certificate of a managed BIG-IP system affects connectivity with the BIG-IQ system

Type
Knowledge
Published
2015-12-05
Updated
2025-02-07
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K86902291

Description

When the BIG-IQ system discovers and manages a BIG-IP device, the BIG-IQ system uses the BIG-IP system's device certificate to establish a device management connection. In the event that the device certificate information has been changed, for example, the Common Name was changed, the BIG-IQ system stops managing the affected BIG-IP device. This is expected behavior.

Recommendations

When a managed BIG-IP device has to change the device properties (for example, the hostname) or the device certificate information (for example, the Common Name), and you would like the BIG-IQ system to continue to manage this device, you can perform the following procedures:

  • Disable socket reuse for the BIG-IQ restjavad process
  • Restart restjavad and rediscover the BIG-IP device

Disable socket reuse for the BIG-IQ restjavad process

You can disable socket reuse by modifying the BIG-IQ restjavad configuration so that future changes to the authentication certificate do not disable device management; you have to perform this procedure only once. To do so, perform the following procedure:

Impact of procedure: You have to restart the restjavad process, and BIG-IQ services to all managed devices may be interrupted. F5 recommends that you perform this procedure during a scheduled maintenance window. Disabling the socket reuse impacts device discovery performance and BIG-IQ system management.

  1. Log in to the BIG-IQ system command-line prompt with the access credential of an Administrator role.
  2. To stop the restjavad service, type the following command:

    tmsh stop /sys service restjavad

  3. To make a backup copy of the restjavad script, type the following command:

    cp -a /etc/bigstart/scripts/restjavad /etc/bigstart/scripts/restjavad.BACKUP.$$

    Note: To locate the actual backup file name, use the following command:

    ls -alt /etc/bigstart/scripts/restjavad.BACKUP*.

  4. Use an editor of your choice to modify the /etc/bigstart/scripts/restjavad file.
  5. Locate the line that begins with the following content:

    ARGS="--port=8100 --workerJarDirectory=${REST_JARS_DIR} ...

    Note: ... denotes the remaining text string on the line that you do not need to modify.

  6. Add --isConnectionReUseDisabled=true to the line, so the line appears similar to the following example:

    ARGS="--port=8100 --isConnectionReUseDisabled=true --workerJarDirectory=${REST_JARS_DIR} ...

    Note: ... denotes the remaining text strings on the line that you do not need to modify.

  7. Save the changes you made to the /etc/bigstart/scripts/restjavad file, and exit the editor.
  8. To start the restjavad service, type the following command:

    tmsh start /sys service restjavad

Restart restjavad and rediscover the BIG-IP device

When you have modified the managed BIG-IP system's device certificate, you need to discover the BIG-IP device again. You can repeat this procedure whenever you have modified the managed BIG-IP system's device certification. To do so, perform the following procedure:

Impact of procedure: You have to restart the restjavad process, and BIG-IQ services to all managed devices may be interrupted. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IQ system command-line prompt with the access credential of an Administrator role.
  2. To restart the restjavad service, type the following command:

    tmsh restart /sys service restjavad

  3. Log in to the BIG-IQ user interface.
  4. Navigate to the Devices panel.
  5. Expand the group name where the affected BIG-IP device resides, and double-click the affected BIG-IP device name.
  6. Type the username and password credentials, and click Rediscover.
