Known Issue

Multi-slot Virtual Clustered Multiprocessing (vCMP) guests may experience loss of communication between slots.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION 2200 or 2400 chassis configured as a vCMP host or hypervisor.
  • You have configured and deployed one or more multiple slot vCMP guests.

Impact

Traffic processing performance will degrade due to a reduced number of available slots.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • From the affected slot of the vCMP guest, all other slots' availability status is offline when you type the following command from the Advanced Shell (bash): 

    tmsh show /sys cluster all-properties

    In the following example, slot 2 is the affected slot and shows the availability status for slots 1, 3 and 4 as offline:

  • From the affected slot of the vCMP guest, the /var/log/ltm file does not receive logging information. To verify, type the following command from the bash utility:

    tail -f /var/log/ltm

  • From the affected slot of the vCMP guest, the TX values increase while the RX values do not increase when you type the following command from the bash utility:

Workaround

To work around this issue, you can either reinitialize the affected slot's eth1 interface on the vCMP guest or redeploy the vCMP guest on the vCMP host. To do so, perform one of the following procedures:

  • Reinitializing the eth1 interface on the affected vCMP guest
  • Redeploying the affected vCMP guest on the vCMP host

Reinitializing the eth1 interface on the affected vCMP guest

Impact of workaround: Performing the following procedure should not have a negative impact on the affected vCMP guest slot.

  1. Log in to the bash utility of the affected vCMP guest.
  2. Reinitialize the eth1 interface by typing the following command:

    ifconfig eth1 down ; ifconfig eth1 up

Redeploying the affected vCMP guest on the vCMP host

Impact of workaround: Performing the following procedures will temporarily stop all traffic processing on the affected vCMP guest system.

  1. Log in to the command line of the vCMP host and enter the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To list all available guests, type the following command:

    show vcmp guest

  3. To disable the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state configured

    For example, to disable a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state configured

  4. To ensure that the affected vCMP guest is disabled, use the following command syntax:

    Note: Once you disable the vCMP guest, it will not appear.

    show vcmp guest [Name]

    For example, to ensure that the vCMP guest named vcmp_one is disabled, type the following command:

    show vcmp guest vcmp_one

  5. To deploy the affected vCMP guest, use the following command syntax:

    modify vcmp guest [Name] state deployed

    For example, to deploy a vCMP guest named vcmp_one, type the following command:

    modify vcmp guest vcmp_one state deployed

  6. To verify that the vCMP guest is deployed, use the following command syntax:

    Note: The vCMP guest Status will change to running and the Requested State will change to deployed.

    show vcmp guest [Name]

    For example, to verify that the vCMP guest named vcmp_one is deployed, type the following command:

    show vcmp guest vcmp_one
