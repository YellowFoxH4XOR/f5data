Topic

This article applies to BIG-IP ASM 12.1.2 through 13.0.x. For information about other versions, refer to the following article:

  • K18650749: Configuring brute force attack protection (13.1.0 and later)

You should consider using these procedures under the following condition:

  • You want to configure the security policy to mitigate brute force attacks.

Description

In a brute force attack, the attacker attempts to gain unauthorized access to a secured area of the web application by making multiple user name/password guesses with the hope of eventually guessing correctly; the attack involves systematically checking all possible passwords and passphrases until the correct combination is found.

The BIG-IP ASM system can mitigate brute force attacks by tracking the number of failed login attempts for a URL that is defined in the security policy and taking an action when an attack is detected. The action may be to log a message to the Reporting screen, drop the request, or both.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the Configuration utility.
  • You have defined one or more login URLs and specified the appropriate authentication type for the URL.

  • Configuring brute force attack protection
  • Viewing brute force logging data

Configuring brute force attack protection

To configure the security policy to mitigate brute force attacks, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Anomaly Detection > Brute Force Attack Prevention.
  3. Click Create.
  4. Select a login page from the Login Page menu, or click Create to create a login page.
  5. In the Session-based Brute Force Protection section, define the following settings:
    • For the Login Attempts From The Same Client option, specify how many times a user may attempt to log on before the system blocks the request.
    • For the Re-enable Login After option, specify the number of seconds the user must wait after the system blocks the request, before re-attempting to log in.
    • For the Use Device ID, click Enabled if you want the system to use the device ID as an identifier to count failed login attempts.
  6. In the Dynamic Brute Force Protection section, define the following settings:
    • For Operation Mode, specify one of the following options for how the system responds when a brute force attack is detected:
      • Off: The system does not check for brute force attacks.
      • Alarm: The system responds to brute force attacks by logging the attack information to the Reporting screen.
      • Alarm and Block: The system responds to brute force attacks by logging the attack information to the Reporting screen and blocking the request.
    • For Measurement Period, specify the length (in seconds) of time to be measured for failed login attempts.
    • For Detection Criteria, define the following settings:
      • The Minimum Failed Login Attempts setting indicates an attack if the number of login attempts is equal to or greater than the specified number.
      • The Failed Login Attempts increased by setting indicates an attack if the ratio between the detection interval and the history interval is greater than the specified number.
      • The Failed Login Attempts Rate reached setting indicates the system considers unsuccessful login attempts to be an attack if the login attempt rate reaches the specified number.
    • For Suspicious Criteria, you can define how to identify a potential attacker’s IP address. If at least one of the following criteria is met, the system treats the IP address as an attacker, and prevents the attacker from trying to guess the password:
      • The Failed Login Attempts increased by setting specifies that the system considers logon attempts from an individual IP address to be an attack if the ratio between the detection interval and the history interval is greater than the specified number.
      • The Failed Login Attempts Rate reached setting specifies that the system considers an individual IP address to be suspicious if the number of logon attempts per second from an IP address is equal to or greater than the specified number.
    • For Prevention Policy, the system implements the first method that you enable on the following list, and then uses the next enabled methods as required:
      • When the Source IP-Based Client Side Integrity Defense setting is enabled, the system determines whether the client is a legal browser by sending a JavaScript response to suspicious IP addresses and waiting for a response.
      • When the URL-Based Client Side Integrity Defense setting is enabled, the system determines whether the client is a legal browser by sending a JavaScript response to suspicious URLs and waiting for a response.
      • When the Source IP-Based Rate Limiting setting is enabled the system drops requests from the suspicious IP address to the URL.
      • When the URL-Based Rate Limiting setting is enabled and a URL is under attack, the system limits the rate of all logon requests for the URL according to the URL’s history interval.
    • The Prevention Duration setting specifies how long the system performs attack prevention against an attacker IP address or an attacked URL.
  7. Click Create.
  8. Click Apply Policy.
    Note: For the brute force attack protection to work, you must set the security policy's Enforcement Mode setting to Blocking and enable both the Alarm and Block flags for Brute Force: Maximum login attempts are exceeded violation (under the Sessions and Logins section). You can locate these settings in the Security > Application Security > Policy Building > Learning and Blocking Settings page.

Viewing brute force logging data

You can view the event logs to see whether brute force attacks have occurred, and review information about the attacks. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Event Logs > Application > Brute Force Attacks.
  3. Use the Security Policy and Time Period menus to filter the logs, as needed.
  4. Review the list of brute force attacks to see which URLs were attacked, and the start and end times of the attack.
