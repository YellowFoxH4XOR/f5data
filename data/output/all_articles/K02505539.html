Topic

A BIG-IP LTM TCP health monitor reads up to a maximum of 5,120 bytes of TCP content to search for a TCP Receive String. If the monitor cannot find a match for the Receive String within the first 5,120 bytes, the BIG-IP system marks the node as down.

Description

The default BIG-IP LTM TCP health monitor checks the health of the servers by performing a TCP handshake with the server and then promptly closing the connection. This TCP handshake allows the monitor to check if the port is listening and allowing new connections; the monitor does not check for text content, by default.

You can create a BIG-IP LTM TCP monitor that sends and reads text strings by using an existing health monitor as a template and adding a send and receive rule.

For example:

ltm monitor tcp my_tcp {
    adaptive disabled
    defaults-from tcp
    destination *:*
    interval 5
    ip-dscp 0
    recv ok
    recv-disable none
    send test\r\n
    time-until-up 0
    timeout 16
}

This new BIG-IP LTM TCP monitor connects to the defined port in the pool of the server, sends the string test, and if the monitor receives an OK within the first 5,120 bytes of the content that the server returns, the monitor marks the node as up.
