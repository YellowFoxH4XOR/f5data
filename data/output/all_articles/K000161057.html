K000161057: F5OS: Incorrect System Event Log Timestamp for FPGA Firmware Loading Appears Before Reboot

Type
Support Solution
Published
2026-04-30
Updated
2026-04-30
Applies to
  • F5OS
  • F5OS-A
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000161057

Description

On F5OS platforms with an FPGA, the system event log may display the FPGA firmware loading event (such as “Firmware update is running for atse 1”) with a timestamp that appears before the reboot event. In reality, the firmware loading occurs after the reboot. This log ordering can cause confusion during troubleshooting, as it may appear that the firmware update triggered the reboot, when it is actually a post-reboot operation.

Example log sequence:

65550 appliance firmware-update-status EVENT NA "Firmware update is running for atse 1" "2026-04-15 03:35:51.430501158 UTC"

326781 appliance reboot EVENT NA "reboot - appliance-1.chassis.local F5OS-A R5R10 version 1.8.3-23453" "2026-04-15 03:35:56.168226229 UTC"

Environment

  • Product: F5OS with an FPGA
  • Event log sources: “show system events” and system event logs
  • Reboot methods: Physical power cycle (removing/reinserting PSUs), CLI-initiated reboot, AOM power cycle

Cause

Bug ID 2291145

Answer/Recommended Actions

  • This is a known cosmetic logging issue tracked under Bug ID 2291145.
  • The actual FPGA firmware loading always occurs after the reboot, regardless of the event log order.
  • For accurate event sequencing, refer to the platform logs (e.g., platform.log), where the firmware loading event is correctly shown after the boot marker.
  • When reviewing system event logs, do not assume the firmware update event is the cause of the reboot if it appears before the reboot marker.
  • No action is required for device operation; this does not affect system functionality.
  • Follow Bug ID 2291145 for updates and resolution.

Additional Information

  • The issue is reproducible with both physical and software-initiated reboots.
  • Only the system event log is affected; platform logs display the correct sequence.
  • The issue has been observed on multiple F5OS versions and platforms.
