Description

During a BIG-IP software upgrade, installing a new software image in a new partition (both via webUI or TMSH) is failing with an error message similar to the one below with x representing the slot number:

slot x: failed (Could not access configuration source; <vda/sda>, 1 )

For example, if this is happening on slot 0, the exact error message would be:
slot 0: failed (Could not access configuration source; <vda/sda>, 1 )

In /var/log/liveinstall.log, logs similar to the one below can be seen:

info: >++++ result:
info: mount: /dev/mapper/vg--db--vda-set.1._usr is already mounted or /mnt/tm_install/27210.OiQ1en/usr busy
info:        /dev/mapper/vg--db--vda-set.1._usr is already mounted on /usr            <<<----[!] 
info:        /dev/mapper/vg--db--vda-set.1._usr is already mounted on /opt/.sdm/usr   <<<----[!]
info:        /dev/mapper/vg--db--vda-set.1._usr is already mounted on /opt/.sdm/lib   <<<----[!]
info:        /dev/mapper/vg--db--vda-set.1._usr is already mounted on /opt/.sdm/lib64 <<<----[!]
info: >----
error: status 8192 returned by command: mount -oro  /dev/vg-db-vda/set.1._usr /mnt/tm_install/27210.OiQ1en/usr 2>/dev/null
info: >++++ result:
info: umount: /mnt/tm_install/27210.OiQ1en/shared: not mounted
info: >----
error: status 8192 returned by command: umount /mnt/tm_install/27210.OiQ1en/shared
Terminal error: Could not access configuration source; vda, 1
*** Live install end at 2020/07/08 20:49:21: failed (return code 2) ***

Environment

  • BIG-IP
  • Running on version 12.x through 16.0.0 (excluding version 15.1.2 which is not affected)
  • Viprion platform
  • vCMP host or vCMP guest

Cause

This issue is caused by Bug ID 915605


Recommended Actions

To resolve the issue, you need to remount /usr to read-only.
Refer to K05920565 to resolve this issue.
