K5050: OneConnect may prevent NTLM authentication from succeeding

Known Issue

NTLM authentication over HTTP requires a multi-packet handshake between the client and the server, and imposes a requirement to persist the connection to the same pool member until authentication is completed. When you use the HTTP profile with OneConnect enabled, the packets sent by the client to complete the authentication handshake may not be sent to the same pool member. When the initially selected pool member does not receive the subsequent handshake packets from the client once the handshake has been initiated, the server may repeatedly request re-authentication. However, each new authentication attempt is likely to experience the same issue. As a result, the authentication handshake fails, and the client is unable to complete the request.

Beginning with BIG-IP LTM 9.2, BIG-IP LTM will not close the server side of the connection when a pool member responds with an HTTP 401 (Unauthorized) message. This action ensures that the connection uses the same pool member until the authentication handshake is completed.

F5 Product Development tracked this issue as CR48426 and it was fixed in BIG-IP LTM 9.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Note: For more information about another issue with OneConnect which may affect NTLM authentication, refer to K7447: OneConnect sessions can stall after the BIG-IP LTM system detaches the existing serverside flow and makes the connection available for reuse.
