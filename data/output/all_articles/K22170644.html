Environment

  • SSLo HA

  • BIGIP HA

Cause
SSLo HA certificate mismatch in REST database.

Recommended Actions

We can workaround it to fix the certificate issue.

 

1. Create a UCS backup on both units.
2. Execute following command on both of the units.

restcurl -X DELETE /shared/device-certificates

3. Unjoin the HA by doing reset device trust and Generate New Self-Signed Authority on both of the units.
 

Device Management  >>  Device Trust : Local Domain > Generate New Self-Signed Authority
K42161405: Rebuilding device trust using the Configuration utility (11.x - 16.x)
 

4. Execute following command on both of the units.

restcurl -X POST /shared/device-key-pair -d "{'generateKeyPair': true}"

5. Execute following command on both of the units and wait for awhile for the processes to come back online.

bigstart restart restnoded restjavad

6. Join them back in HA and performing a ConfigSync.

K42161405: Rebuilding device trust using the Configuration utility (11.x - 16.x)
 

7. Once got them in synced, navigate to SSLo UI and validate the messages on GUI.

8. You'd run the sslofix script on both of the units and validate for any error:

sslofix -D <sync-failover group> -H <remote BIG-IP host> --diagnostic

If errors are found during the diagnostic, run sslofix in repair mode (without --diagnostic) on the unit that have the latest configuration. Use the --force option.

sslofix -D <sync-failover group> -H <remote BIG-IP host> --force
