K000161263: Handling Web App Scanning False Positives for Moodle CSRF Token ("sesskey") in F5 Distributed Cloud

Type
Support Solution
Published
2026-05-13
Updated
2026-06-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud WAF
Source
https://my.f5.com/manage/s/article/K000161263

Description

Web App Scanning on Moodle applications may report requests as missing a CSRF token. This occurs because Moodle uses the "sesskey" parameter as its CSRF token, which is not recognized by the scanner. Additionally, the default token length (10 characters) is below the recommended minimum of 32 characters, leading to alerts about insufficient entropy.

  • Web App Scanning flags requests as missing CSRF token when "sesskey" is present.
  • Alerts persist due to non-standard parameter name and short token length.

Environment

  • Product: F5 Distributed Cloud Web Application Firewall (WAF)
  • Feature: Web App Scanning
  • Application: Moodle (using "sesskey" as CSRF token)
  • Occurs consistently with Moodle's default implementation

Cause

The scanner does not recognize "sesskey" as a valid CSRF token parameter and flags tokens shorter than 32 characters, resulting in false positives.

Answer/Recommended Actions

  1. Mark the Alert as Resolved:
    • In Web App Scanning results, mark the CSRF token alert as "Resolved" to prevent it from resurfacing in future scans.
  2. (Optional) Increase Token Length in Moodle:
    • Consider increasing the "sesskey" token length in Moodle to at least 32 characters for improved security.
  3. No Configuration Change in F5 Distributed Cloud:
    • There is no option to configure the scanner to recognize custom CSRF parameter names or adjust token length requirements.

Additional Information

  • The scanner checks for CSRF tokens with sufficient entropy and recommends a minimum length of 32 characters.
  • Shorter tokens are considered less secure due to lower randomness.
  • This behavior is intentional and by design.
