Known Issue

This is the result of a known issue. In BIG-IP ASM version 10.x, the XML parser incorrectly interprets some characters in regular expressions as metacharacters, rather than literal ASCII characters. As a result, the XML profile may not enforce the correct pattern constraints as defined by the WSDL specified in the profile.

For example:

<xsd:element name="MyElement">
       <xsd:simpleType>
       <xsd:restriction base="xsd:string">
          <xsd:pattern value="[A-Za-z0-9.'-_ ]+"/>

             </xsd:restriction>
       </xsd:simpleType>
       </xsd:element>

The pattern is set to constrain acceptable characters to A to Z, a to z, 0 to 9, and the following non-alphanumeric characters:

  • period ( . )
  • hyphen ( - )
  • underscore ( _ )
  • single quote ( ' )

However, due to a known issue in the XML parsing library, the period and the hyphen characters are interpreted as a regular expression metacharacter; any character that is not a carriage return ( &#xD; ) or newline ( &#xA; ), and a range between the adjacent characters, respectively. Rather than defining the literal ASCII period character as valid, this interpretation of the period will result in any character other than a carriage return or newline designated as valid within the pattern constraint.

Rather than defining the three literal ASCII characters of single quote, hyphen, and underscore as valid characters, the following string will define a range of any character between ASCII 0x2C ( ' ) and  ASCII 0x5f ( _ ) as matching the expression. XML transactions containing characters outside the range defined will not be blocked by the BIG-IP ASM as intended:

'-_

F5 Product Development tracked this issue as ID 341429 and it was fixed in BIG-IP ASM version 10.2.1. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

You can work around this issue by escaping the period and hyphen characters with a preceding backslash ( \ ) in the pattern constraint value.

For the element defined above, you would change the following pattern constraint:

<xsd:pattern value="[A-Za-z0-9.'-_ ]+"/>   

Changing the pattern constraint to appear as follows will force the XML parser to interpret the period and hyphen as their literal representations, and not as regular expression metacharacters:

<xsd:pattern value="[A-Za-z0-9\.'\-_ ]+"/>
