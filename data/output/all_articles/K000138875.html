K000138875: UCS generation fails when using iControl REST API

Type
Support Solution
Published
2024-03-11
Updated
2026-11-03
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000138875

Description

You observe the following:

  • UCS creation via the iControl REST API appears to hang when sending a request to /mgmt/tm/sys/ucs
  • UCS creation via the iControl REST API appears to do nothing when sending a request to /mgmt/tm/task/sys/ucs

Environment

  • BIG-IP v13 and later
  • iControl REST API

Cause

The synchronous, URI, /mgmt/tm/sys/ucs request does not get an immediate response when saving large UCS files and waits for a response from iControl REST.

In contrast, sending a request to the asynchronous URI, /mgmt/tm/task/sys/ucs only creates a task with the task state of STARTED or UPDATING. To start the task, modify the value of task state to VALIDATING in a PUT request and specify the selfLink as the endpoint.

Recommended Actions

When saving a large UCS file that will take a long time, create the UCS asynchronously with a task using the URI /mgmt/tm/task/sys/ucs. You must then validate that task to run otherwise it will time out and nothing will happen.

You can follow these steps:

  1. Create the UCS task. For example:
    curl -sk -u admin:admin -H "Content-Type: application/json" -X POST https://localhost/mgmt/tm/task/sys/ucs -d '{"command":"save","name":"/var/local/ucs/ucs-filename.ucs"}' | jq
    Output will appear similar to this:
    {
    "_taskId": 1708800684638206,
    "_taskState": "STARTED",
    "_taskTimeInStateMs": 0,
    "_taskResultLink": "https://localhost/mgmt/tm/task/sys/ucs/1708800684638206/result?ver=16.1.4.2",
    "selfLink": "https://localhost/mgmt/tm/task/sys/ucs/1708800684638206?ver=16.1.4.2"
    }
  2. The next step is to validate the task so the job will actually run. We accomplish this with the VALIDATING keyword and the task ID in the URI. For example:
    curl -sk -u admin:admin -H 'Content-Type: application/json' -X PUT -d '{"_taskState":"VALIDATING"}' https://localhost/mgmt/tm/task/sys/ucs/1708800684638206 | jq
    Output will appear similar to this:
    {
    "code": 202,
    "message": "Task will execute asynchronously.",
    "errorStack": []
    }
  3. (Optional) You can check that the task completed successfully with a GET request to the task ID. This request waits for task completion to produce output so you typically should wait to run it until after you expect the UCS creation task to be complete. For example:
    curl -sk -u admin:admin https://localhost/mgmt/tm/task/sys/ucs/1708800684638206 | jq
    Output will appear similar to this:
    {
    "selfLink": "https://localhost/mgmt/tm/task/sys/ucs/1708800684638206?ver=16.1.4.2",
    "_taskId": 1708800684638206,
    "_taskState": "COMPLETED",
    "_taskTimeInStateMs": 74000,
    "_taskResultLink": "https://localhost/mgmt/tm/task/sys/ucs/1708800684638206/result?ver=16.1.4.2"
    }

Additional Information

The above examples are shown piping the data to the jq command. While not mandatory, this tool will display the output in a much easier to read format.
