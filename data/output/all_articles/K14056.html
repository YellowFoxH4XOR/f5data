Topic

Summary

A scheduled place-rule may start outside of the scheduled time.

Description

When a periodic volume free space scan fails, the ARX system will review the status of the previous scheduled place-rule scan. If the ARX system finds that the place-rule scan did not complete, it will attempt to finish the scan by starting the place-rule scan.

When a free space scan fails and the place-rule scan starts outside of its schedule, the ARX syslog will contain log messages that appear similar to the following examples:

POLICY_PEP-9-INFO-RULE_SCAN_STATUS:: Rule [Example:/Share-vol:Share_vol]: Scan status is now [Could not determine target free space]
POLICY_PEP-9-INFO-RULE_MIGRATION_STATUS:: Rule [Example:/Share-vol:Share-vol]: Migration status is now [Source unavailable]
POLICY_PEP-9-INFO-RULE_SCAN_STATUS:: Rule [Example:/Share-vol:Share_vol]: Scan status is now [Waiting for scan to start]
POLICY_PEP-9-INFO-RULE_MIGRATION_STATUS:: Rule [Example:/Share-vol:Share_vol]: Migration status is now [Waiting]
POLICY_PEP-9-INFO-MSG6:: virtual PolicyEventData DPRuleTag::QueueScan(const PolicyEventData&)[Example:/Share:Share_vol] - Queuing tree walk for directory [/Share_vol/] share [2442] (tree walk version [29]).

When the scheduled form of the place-rule scan is started, the ARX syslog will contain log messages that appear similar to the following example:

POLICY_PDP-0-NOTE-MSG5:: Scheduler: running schedule 'Schedule-Share_Vol'.

Recommendations

When experiencing place-rules running outside of the set schedule, F5 recommends that you work with F5 Technical Support to isolate the root cause of the initial scan failures.
