A vulnerability exists in the FirePass logon sequence. Under certain conditions, the Firepass controller accepts an existing session ID cookie sent by the browser, and returns the cookie with the same session ID after the user authenticates to the FirePass controller. A successful exploit would allow an attacker to access a user's webtop while the legitimate user is logged on to the FirePass controller.

The attack is not a session hijack, in that the attacker does not take over the existing user's session, but rather obtains a new session with which to access the user's webtop. The attacker cannot bypass any additional authentication steps required by the resources represented by user's favorites.

A successful attack has several prerequisites. First, the attacker must place a session cookie into the browser of a user who has a logon to the FirePass controller. This prerequisite typically requires the exploitation of another vulnerability on a server within the domain to which the FirePass controller belongs. The victim user must then access the affected server and have the attacker's session cookie sent to their browser.

Second, the attack can only succeed if the logon to the FirePass controller is done through a direct HTTP request to the vulnerable URL, which is not the standard logon page. Users who access the FirePass controller through the standard logon page will prevent any exploit from succeeding, even if the first criterion regarding the session cookie has been met. Typically, the only logon configuration that could produce the necessary direct request is an external logon web page, either hosted on a web server, or a WebDAV-customized login page on the FirePass controller. However, not all such logon configurations will issue the required type of HTTP request.

Additionally, several FirePass configuration parameters and external factors affect whether the attack can succeed.

Because of the complexity of the scenario, F5 considers the likelihood of successful exploit to be low.

F5 Product Development tracked this issue as CR85960 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.
