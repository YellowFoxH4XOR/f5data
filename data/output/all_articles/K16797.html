Known Issue

When the BIG-IP PEM system processes a RADIUS accounting message with a multiple IPv6 prefix, the TMM process may produce a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP PEM system is configured with a RADIUS Subscriber Discovery virtual server.
  • The BIG-IP PEM system receives the RADIUS accounting message that contains multiple Framed-IPv6-Prefix AVPs.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You may observe incorrect PEM sessions being created.
  • The RADIUS accounting message containing the multiple Framed-IPv6-Prefix AVPs may cause the AVPs, with the exception of the first pair, to be incorrectly parsed by the BIG-IP PEM system.
  • The BIG-IP system fails over to the standby system if the systems are configured for HA.
  • The BIG-IP system may generate TMM core files to the /var/core directory.

Workaround

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

To work around this issue, you can use multiple RADIUS accounting messages that contain a single Framed-IPv6-Prefix AVP for each message. This would require you to set the BIG-IP system DB key tmm.pem.session.provisioning.continuous to enable, which is the default setting.
