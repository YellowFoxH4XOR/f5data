Description

You observe your floating traffic objects(for example, virtual address, floating selfip, or snat/nat address) don't migrate timely from active to standby device during a failover event. Even if the original active device now is standby, the traffic still goes to it. When you check the ARP table on the upstream/downstream devices, you find the ARP entries for the floating traffic objects don't refresh. When you check the BIG-IP setting, you find none is configured for traffic group.

For example, you may have similar setting like below.

ltm virtual-address /Common/192.168.20.100 {
    address 192.168.20.100
    arp enabled
    icmp-echo enabled
    mask 255.255.255.255
    server-scope none
    traffic-group none   ----!!!!
}
 
ltm snat-translation /Common/10.10.10.1 {
    address 10.10.10.1
    traffic-group none   ----!!!!
}

ltm nat /Common/NAT_internal {
    originating-address 192.168.11.1
    traffic-group none   ----!!!!
    translation-address 10.10.10.2
}

net self /Common/Internal_floating {
    address 10.10.10.100/24
    traffic-group none   ----!!!!
    vlan /Common/vlan_in
}

When the traffic group for those objects are none:
  1. They don't belong any traffic group(include traffic-group-local-only).
  2. The system won't send the GARP for them during a failover.
  3. When the upstream/downstream device refresh it ARP table, the HA system will send the mac address for the one where the traffic-group-1 locates.

Environment

  • BIG-IP LTM
  • Traffic Group
  • Virtual address
  • Floating self ip
  • SNAT/NAT address

Cause

It could be possible that the configuration was changed incorrectly, so it shows none in traffic-group for those objects. Or it inherits from the Common partition, refer to K14104 and K08114320.

Recommended Actions

Change the traffic group setting for those objects to a traffic group other than none, you can use either of the below methods:

In GUI, navigate to the objects where they locate, change the traffic group to any traffic-group other than none.
For example, change the traffice group for virtual address 192.168.20.100:

  1. Navigate to Local Traffic  ››  Virtual Servers : Virtual Address List,
  2. Click on 192.168.20.100,
  3. Find Traffic Group setting in General Properties,
  4. Change the setting to a traffic group other than none.


In CLI, for example change the traffic group for virtual address 192.168.20.100 to traffic-group-1, use the below command:

tmsh modify ltm virtual-address 192.168.20.100 traffic-group traffic-group-1

Additional Information

The traffic-group is not selectable when creating a virtual address, SNAT or SNAT pool, it is automatically assigned to traffic-group-1 in a HA system.
