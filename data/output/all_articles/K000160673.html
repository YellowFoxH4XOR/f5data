Description

This article addresses an issue where a BIG-IP LTM policy containing rules with overlapping TCP address ranges and HTTP host conditions results in a 'policy execution error' (TCP reset/RST) for certain client IPs. As a result, the traffic does not match the intended rule and instead hits the default rule, causing a policy execution error.

The policy rule fails to match even when it meets the specified criteria.

Environment

  • BIG-IP
  • Virtual server with an LTM policy containing multiple rules

Cause

The root cause was a misconfiguration in the LTM policy where an overlapping IP network in a different rule matched the affected client IP.

Answer/Recommended Actions

  1. Correct the misconfigured IP network in the LTM policy.
  2. Review all LTM policy rules for unintended IP range overlaps to prevent similar issues.
  3. Monitor for further policy execution errors after making the correction.
  4. Upgrade to non-vulnerable version.
