Known Issue

Changing the BIG-IP management (MGMT) interface subnet may result in inoperative static routes.

This issue occurs when all of the following conditions are met:

  • You configure a default gateway on the MGMT interface.
  • You configure a default gateway on a Traffic Management Microkernel (TMM) interface.
  • You configure static routes to use the MGMT interface subnet.
  • You subsequently update the MGMT interface subnet.

Impact

After the MGMT interface subnet changes, static routes that are configured to use the MGMT interface subnet are removed from the routing table.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Services that previously egressed the MGMT interface, such as network time protocol (NTP), SNMP, SMTP and logging, no longer egress the MGMT interface.
  • After changing the MGMT interface subnet, the tmsh list sys management-route command continues to list the previously configured static routes with the previously configured MGMT subnet address.
  • Static routes that were previously configured to use the MGMT interface subnet are removed from the routing table after the MGMT interface subnet is changed.

Workaround

To work around this issue, you can reconfigure the static routes to use the new MGMT interface network. For more information, refer to K13284: Overview of management interface routing (11.x - 12.x).

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
