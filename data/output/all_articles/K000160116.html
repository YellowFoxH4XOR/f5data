Description

After upgrading the NGINX Instance Manager (NIM), the nms.conf configuration file was replaced with a default version, causing loss of custom configuration.

Environment

  • NIM
  • RHEL distribution

Cause

On RHEL-based systems, RPM does not prompt interactively during upgrades when configuration files have been modified. Instead, it handles conflicts automatically. The system will rename the existing nms.conf to nms.conf.rpmsave and install a default configuration, resulting in the loss of custom settings unless they are manually restored.

A log will show as follows during the upgrade process:

warning: /etc/nms/nms.conf saved as /etc/nms/nms.conf.rpmsave

Answer/Recommended Actions

Manually restore custom configuration from nms.conf.rpmsave to nms.conf after upgrade.
