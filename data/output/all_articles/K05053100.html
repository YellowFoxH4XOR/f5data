Description

The virtual server resets some the of existing connections.
The virtual server does not process some of the connection request to the destination resource.
The virtual server drops some of the received connection request.
 

Environment

  • BIG-IP
  • any version
  • after modifying Virtual server or profile attached to the virtual server.
     

Cause

You modify a virtual server profile changing the timeout value of the profile to a lower time value.
You create or delete a virtual server configured with a UDP profile that is processing traffic. 
 

Recommended Actions

When a virtual server configuration is modified and the virtual server is processing traffic, the modifications are applied to new connection request. Established connections continue to be processed using the running configuration when the connection was initially processed.

Procedures

The following procedures can assist in troubleshooting intermittent connection issues such as dropped packets.
  • Troubleshooting connection issues after an active (processing traffic) virtual server profile idle timeout is modified
  • Troubleshooting connection issues after an active (processing traffic) virtual server is created or deleted

Troubleshooting connection issues after an active (processing traffic) virtual server profile idle timeout is modified

Determine which client is affected by unexpected drop/reset or connectivity issues, then check if there are connections using an older configuration.

Impact of procedure: Running the show sys conn tmsh command on systems with a high connection count may impact performance or temporarily impact the processing of traffic.

Note: For more information, refer to K17332: The tmsh 'show sys conn' command may cause TMM to produce a core file and K54757915: Running the tmsh show /sys conn command may cause TMM to stop responding and produce a core file.

  1. Log in to the TMOS Shell (tmsh).
  2. Use the following command syntax to view the connection table:

    show /sys connection cs-client-addr <client_ip> and cs-server-port <virtual_server_port>

    Note: F5 recommends that you filter the command output by viewing connections to a specific virtual server (IP address and port) and client IP address..

    For example:

    show /sys connection cs-client-addr 211.6.12.167 and cs-server-port 3306 

    Output appears similar to the following:

  3. To remove a connection establish prior to the modification use the following command syntax:

    Note: Change <client_ip> to the client IP address of the connection, and change <virtual_server_connect_aphemeral_port> to the client source port of the virtual server connection.

    For example:

    To delete line 9 in the example connection table, type the following command:

    delete /sys connection cs-client-addr 203.0.113.167 and cs-client-port 57264

    To delete all client connections for the client ip address 203.0.113.167 to 172.24.42.3:3306 in the example connection table, type the following command:

    delete sys connection cs-client-addr 203.0.113.167 and cs-server-port 3306
     

Troubleshooting connection issues after an active (processing traffic) virtual server is created or deleted

When the virtual server is processing periodic connections (stateless) from the same client connection (such as NTP, SNMP, or so on), the associated connection timeout is also updated periodically using the pre-modified configuration.

To determine which clients may be affected by connectivity issues from the configuration change (such as unexpected drop/reset), check the connection table to determine if there are pre-modification connections.

Impact of procedure: This procedure may cause a temporary connection drop, the impact to client connections that are periodical is minimal. Running the show sys conn tmsh command on systems with a high connection count may impact performance or temporarily impact the processing of traffic.

Note: For more information refer to K17332: The tmsh 'show sys conn' command may cause TMM to produce a core file and K54757915: Running the tmsh show /sys conn command may cause TMM to stop responding and produce a core file.

  1. Log in to tmsh.
  2. To view the connection table for a specific client IP address, virtual server, and port, use the following command syntax:

    show /sys connection cs-client-addr <client_ip> and cs-server-port <virtual_server_port>

  3. To delete all established connections for a specific client IP address and virtual server and port use the following command syntax:

    delete /sys connection cs-client-addr <client_ip> and cs-server-port <virtual_server_port>

    Note: Change <client_ip> to the client IP address of the connection, and change <virtual_server_port> the client source port of the virtual server connection.

    Note: Removing all existing connections for the specific client IP address and virtual server and port causes the client to establish new connections that use the modified virtual server configuration.
