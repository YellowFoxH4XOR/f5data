Issue

Error Message

Error Message: Connection attempt to insecure SSL server (see RFC5746): <address>:<port>

In this error message, note the following:

  • <address> is the destination address of the BIG-IP virtual server
  • <port> is the service port of the BIG-IP virtual server

For example:

01260018:5: Connection attempt to insecure SSL server (see RFC5746): 192.168.10.100:443

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when all of the following conditions are met:

  • A remote client initiates a connection to a BIG-IP virtual server configured with a Server SSL profile.
  • The Server SSL profile Secure Renegotiate setting is set to Request.
  • The back-end SSL server lacks support for the Transport Layer Security (TLS) renegotiation indication extension described in RFC5746.

Impact

This message is informational and does not indicate that an SSL connection failure occurred. 

Recommended Actions

Older SSL servers and BIG-IP software upgrades

This message indicates that one or more back-end servers or pool members use an older implementation of SSL. While the message does not indicate an SSL connection failure, it may be followed by additional messages that do indicate an SSL connection failure. In the following example, the BIG-IP system was upgraded to 11.5.0 and later, and one or more pool members associated with the 192.168.10.100:443 virtual server does not support the TLS protocol:

Note: In BIG-IP 11.5.0 and later, the default server SSL profile no longer supports SSLv3.

01260018:5: Connection attempt to insecure SSL server (see RFC5746): 192.168.10.100:443
01260013:6: SSL Handshake failed for TCP from 192.168.10.150:12345 to 192.168.10.100:443
 

Stopping the message

You can change the logging level for SSL traffic events from Notice to Warning using either the Configuration utility or the TMOS Shell (tmsh). To do so, perform one of the following procedures:

Impact of procedure: Notice level SSL traffic events will not be obtained due to the modified logging level.

Using the Configuration utility to configure log levels for traffic management events

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Options.
  3. Use the SSL drop-down to change the logging level from Notice to Warning.
  4. Click Update.

Using tmsh to configure log levels for traffic management events

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To set the log level for SSL events from Notice to Warning, type the following command:

    modify /sys db log.ssl.level value warning

  3. Save the change by typing the following command:

    save sys config
