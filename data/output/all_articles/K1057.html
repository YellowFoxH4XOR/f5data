Topic

This solution discusses three common rule issues:

  • Rule length limits
  • Rule complexity
  • Rules and load balancing decisions

Rule length limits

BIG-IP uses kernel-level processing, rather than user-land application resources. Kernel-level processing gives BIG-IP a significant advantage over user-land processing in terms of speed; however, there is a limit to the number of resources available in kernel processing.

To prevent internal resource errors, BIG-IP has the following hard-set limits for rules:

  • BIG-IP version 4.0 - 4.6 is limited to 224 conditions.
  • BIG-IP version 3.3.1 is limited to 100 conditions.

These limits include both the horizontal and vertical conditions combined. This means your rule cannot process more than the set number of conditions regardless of how you write it.

Note: If you require a single rule to be more complex than the hard-set limit allows, it is very likely that there is a better solution than a complex rule. For further assistance, contact .

Rule size limits

Following is a sample of a multi-tiered rule. This rule design is designed with the following assumptions:

  • http_uri starts_with '/ageconnect' is the most likely condition to fail within this horizontal string and is most likely to match vertically.
  • http_cookie 'Legacy' and http_cookie 'Legacy' == 'true' is the second most likely condition to fail in the horizontal string.
  • http_method == 'GET' is third most likely condition to fail in the horizontal string.
  • exists http_cookie 'old') is least likely condition to fail in the horizontal string.
  • client_addr == 10.0.0.0 netmask 255.0.0.0 is second most likely condition to match in the vertical string.
  • And so on.

Sample rule:

rule local-internet-clear {

if (http_uri starts_with '/ageconnect' and exists http_cookie 'Legacy'
     and http_cookie 'Legacy' == 'true' and http_method == 'GET' and exists 
	 http_cookie 'old') {
	      use ( legacy )
}
 else {
   if (client_addr == 10.0.0.0 netmask 255.0.0.0) {
     cache (http_uri matches_regex '.*') {
	 origin_pool www-clear
	 cache_pool cache-local-80
   }
}
 else {
    cache (http_uri matches_regex '.*') {
	  origin_pool www-clear
	  cache_pool cache-internet-80
	}
   }
  }
 }

Rules and load balancing decisions

To optimize rule processing, you want BIG-IP to first evaluate conditions that are most likely to match (vertically) and those that are most likely to fail (horizontally). This optimizes rule processing because it will most quickly select on success (vertically) or failure (horizontally).
