Known Issue

This is the result of a known issue. The BIG-IP system fails to load an external class file that references the whole IPv4 address space in any of the following formats:

network 0.0.0.0/0
network 0.0.0.0 prefixlen 0
network inet default

All of the above formats are valid and should be accepted by the BIG-IP system. This issue occurs regardless of whether the Configuration utility, the bigpipe utility, or the tmsh shell is used to create the external class.

Note: The Configuration utility and the tmsh shell refer to classes as data groups.

When attempting to load an external class file that references the whole IPv4 address space in any of the above formats, the BIG-IP system returns an error message that appears similar to the following example:

BIGpipe class creation error:
01070626:3: The IP class external file (/config/example_class) has an invalid format, line: 1.

F5 Product Development is tracking this issue as ID 338815.

Workaround

You can work around this issue by referencing the whole IPv4 address space in the following format:

network 0.0.0.0 mask 0.0.0.0

Using this format will not cause the BIG-IP system to fail loading the external class file.

Important: This workaround is only effective if the external class is configured as read-only. If the class access mode is set to read/write, the BIG-IP system will replace network 0.0.0.0 mask 0.0.0.0 with network inet default, which will cause the issue described in this Solution to occur again.
