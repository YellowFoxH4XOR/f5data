Issue

You should consider using this procedure under the following conditions:

  • The proxy user cannot access their back-end CIFS storage due to failed authentication
  • The quorum disk user is unable to authenticate

Symptoms

As a result of a locked client account, you may encounter the following symptom:

  • Metadata and user shares are marked Offline

Recommended Actions

The ARX configuration contains the credentials for domain user accounts (proxy user and quorum disk user) created to allow the ARX system to perform required system functions within the domain. If the password for one of these users is changed on the domain controller, it must also be changed in the ARX configuration. If the ARX system is not configured to use the proper password, the domain controller may lock the user account after several failed attempts to authenticate.

Note: The password must match the password set for the users on the domain controller. If you change the user’s password on the domain controller, you must also change the password on the ARX system.

Procedures

When experiencing authentication issues, you can perform the following procedures to determine the root cause:

  • Reviewing the log files
  • Using the probe authentication command

Reviewing the log files

You can review the log files for error messages using the following keywords:

  • metaDataOffline
  • shareOffline
  • SHARE_UNAVAILABLE

Impact of procedure: None.

  1. Log in to the ARX CLI.
  2. Search the ARX log files using the following command syntax:

    grep [keyword] logs [log file name]

    For example:

    ARX#grep SHARE_UNAVAILABLE logs syslog

    SHARE_UNAVAILABLE:: Storage Transition: [10.10.10.10] path [shares] id [4] (Status now unavailable); 4 probes failed over 0 seconds (durations:  12ms 9.6ms 7.6ms  14ms); Last probe status: [STATUS_ACCOUNT_LOCKED_OUT]

    • Log messages that appear similar to the following examples indicate that the proxy user account has been locked out:

      • Traplog

        SNMP TRAP: metaDataOffline (270) shr 'Cifs:/volume:metadata-share', name 'cifs1', ip '10.10.10.10'
        SNMP TRAP: shareOffline (670) shr 'ARX1:/volume:share', name 'cifs1', ip '10.10.10.10'
        SNMP TRAP: shareLogonFailureRaise (666) shr 'cifs:/volume:share'', name 'cifs1', ip '10.10.10.10:  proxy user logon failed with error 'Account Locked Out'.
      • Syslog

        BESPD_METADATA_OFFLINE:: Metadata share (:MetaData) for Namespace 'cifs', Volume /volume is offline
        SHARE_UNAVAILABLE:: Storage Transition: [10.10.10.10] path [shares] id [4] (Status now unavailable); 4 probes failed over 8 seconds (durations:  14ms 7.0ms 5.6ms 9.7ms); Last probe status: [STATUS_ACCOUNT_LOCKED_OUT]
        Recommendation: Reset the password stored in the ARX configuration for the affected users and unlock the users on the Domain controller, Authentication will continue to fail until the stored accounts have been properly configure and the have been unlocked on the Domain Controller.

        Note: To reset the proxy user and quorum disk user passwords on the ARX system, refer to the ARX CLI Reference Guide.
    • Log messages that appear similar to the following examples indicate that the proxy user account has been manually disabled by a domain administrator:

      • Traplog

        kerberosDCOffline (230) name 'ARXFOREST.COM', ip '10.10.10.10': Domain controller for realm ARXFOREST.COM at IP 10.10.10.10 transitioned from state ACTIVE to state OFFLINE because health check failed to connect.
        SNMP TRAP: metaDataOffline (270) shr 'Cifs:/volume:metadata-share', name 'cifs1', ip '10.10.10.10'
        SNMP TRAP: shareOffline (670) shr 'ARX1:/volume:share', name 'cifs1', ip '10.10.10.10'

      • Syslog

        SNMP TRAP: shareLogonFailureRaise (666) shr 'ARX1:/volume:share', name 'cifs1', ip '10.10.10.10':  proxy user logon failed with error 'Logon Failure'.
        METADATA_OFFLINE:: Metadata share (:MetaData) for Namespace 'cifs', Volume /volume is offline
        SHARE_UNAVAILABLE:: Storage Transition: [10.10.10.10] path [shares] id [4] (Status now unavailable); 4 probes failed over 8 seconds (durations:  16ms 7.0ms 7.1ms 9.7ms); Last probe status: [STATUS_ACCOUNT_DISABLED]

    F5 recommends that a domain administrator enable the affected user account.

Using the probe authentication command

You can use the probe authentication command to manually test authentication for a proxy or quorum disk user by performing the following procedure:

Impact of procedure: None.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Test authentication using the following command syntax:

    probe authentication kerberos host x.x.x.x user[username] windows-domain [users Domain]

    In this command syntax, note the following:

    • [username] is the name of the authenticated user
    • [users Domain] is the domain name for the authenticated user

    For example:

    probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
    • Example of a successful authentication probe

      ARX# probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
      Password: ******

      IP address   : 10.10.10.10
      SPN          : cs-dc1-001$@ARXFOREST.COM 
      User         : arxproxy@ARXFOREST.COM 
      Protocol     : Kerberos
      Status       : STATUS_SUCCESS
    • Examples of failed authentication probes














      • Failed authentication due to an incorrect password:

        ARX# probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
        Password: ******

        IP address   : 10.10.10.10
        SPN          : cs-dc1-001$@ARXFOREST.COM
        User         : arxproxy@ARXFOREST.COM
        Protocol     : Kerberos
        Status       : STATUS_LOGON_FAILURE
        Krb5Error    : KRB5KDC_ERR_PREAUTH_FAILED
      [KRB5KDC_ERR_PREAUTH_FAILED] Krb5Error indicates that the password for the account is incorrect. F5 recommends verifying the password and trying again.
    • Failed authentication due to the user account being locked out or administratively disabled:

      ARX# probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
      Password: ******

      IP address   : 10.10.10.10
      SPN          : cs-dc1-001$@ARXFOREST.COM
      User         : arxproxy@ARXFOREST.COM
      Protocol     : Kerberos
      Status       : STATUS_LOGON_FAILURE
      Krb5Error    : KRB5KDC_ERR_CLIENT_REVOKED
    [KRB5KDC_ERR_CLIENT_REVOKED] Krb5Error indicates that the account has been locked out or administratively disabled. F5 recommends resetting affected users' password stored in the ARX configuration and unlocking the users on the domain controller, if the account was locked out due to repeated failed logon attempts. For information about resetting a proxy user password in the ARX configuration, refer to the proxy-user command in the ARX CLI Reference Guide. For information about resetting quorum disk user password in the ARX configuration, refer to the quorum-disk command in the ARX CLI Reference Guide. Note: Authentication will continue to fail until you have properly configured the stored accounts and unlock or enable the accounts on the domain controller.
  4. Failed authentication due to an incorrect windows-domain:

    ARX# probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
    Password: ******

    IP address   : 10.10.10.10
    SPN          : cs-dc1-001$@ARXFOREST.COM
    User         : arxproxy@ARXFOREST.COM
    Protocol     : Kerberos
    Status       : STATUS_LOGON_FAILURE
    Krb5Error    : KRB5_REALM_UNKNOWN
[KRB5_REALM_UNKNOWN] Krb5Error indicates that the domain specified is invalid or does not exist on the domain controller. F5 recommends verifying the domain information and trying again.
  • Failed authentication due to the username not existing on the domain:

    ARX# probe authentication kerberos host 10.10.10.10 user arxproxy windows-domain ARXFOREST.com
    Password: ******

    IP address   : 10.10.10.10
    SPN          : cs-dc1-001$@ARXFOREST.COM
    User         : arxproxy@ARXFOREST.COM
    Protocol     : Kerberos
    Status       : STATUS_LOGON_FAILURE
    Krb5Error    : KRB5KDC_ERR_C_PRINCIPAL_UNKNOWN
[KRB5KDC_ERR_C_PRINCIPAL_UNKNOWN] Krb5Error indicates that the authenticated username is not a valid user for the domain. F5 recommends verifying the username, attempting to probe with a different user, or creating the desired user account on the domain controller.
