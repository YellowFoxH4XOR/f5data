K000139499: Getting a minimal qkview-collect package from a failed controller using the ccpeer link

Description

This article discusses the procedure for collecting a minimal qkview package from a failed VELOS controller via the ccpeer link, which can be crucial for troubleshooting when the peer controller is unreachable through standard means.

 

Environment

  • Inability to execute a standard qkview on a failed VELOS controller.
  • Failed controller is unreachable through normal SSH methods.
  • VELOS system with an active and a failed controller.
  • SSH access to the VELOS controllers.
  • The active controller must have SSH access to the failed controller via the ccpeer link.
  • The user must have root access to the VELOS controllers.

Cause 

The failed controller might be unreachable due to network issues or misconfigurations, such as an incorrectly set configured-network-range-type. In situations where a VELOS controller fails and is unreachable, obtaining diagnostic data is essential for analysis. The standard qkview may not collect from an unreachable peer controller, necessitating an alternative method.

Recommended Actions

  1. SSH to the active VELOS controller as root.
  2. SSH to the peer controller using the internal ccpeer link:
    • For Controller-1: ssh 100.65.7.51
    • For Controller-2: ssh 100.65.7.52

Note:  The addresses above are the default ones, when show system network state configured-network-range-type is 'RFC6598'.  If the internal network prefix of the chassis has been modified by setting this to 'RFC1918', the first two octets of these addresses will be different. 

  1. If the SSH connection is successful, run the qkview-collect command on the failed controller to collect a minimal set of data.
  2. After the collection is complete, a file named qkview.tar.gz will be present in the current directory on the failed controller.
  3. Exit back to the active controller and copy the qkview.tar.gz file over the ccpeer link:
    • For Controller-1: scp 100.65.7.51:qkview.tar.gz qkview-collect-controller1.tar.gz
    • For Controller-2: scp 100.65.7.52:qkview.tar.gz qkview-collect-controller2.tar.gz
  4. Download the qkview-collect-controller*.tar.gz file from the active controller using SFTP.

Use Cases

  • Network Isolation: A VELOS controller becomes isolated from the network, but the ccpeer link remains operational.
  • Misconfigured Network Range: An engineer discovers that the configured-network-range-type is set incorrectly, preventing SSH access to the failed controller. 

Additional Information 

The minimal qkview package obtained via the ccpeer link is not suitable for iHealth processing. Users should send this data to F5 through the securefiles.f5.com portal for further analysis. Always ensure secure handling and transmission of potentially sensitive diagnostic data.
