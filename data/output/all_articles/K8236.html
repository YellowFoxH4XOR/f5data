Known Issue

This is the result of a known issue. The installation process mounts the IM file for access to the installation program and files. If the IM file is unmounted before the installation process has completed, the installation will fail with a panic error. If the device being upgraded is actively polled by an Enterprise Manager, which updates the device's status during the installation process, or if the switchboot utility is performed on the device during the installation process, the installation IM file will be unmounted.

The installation will fail with an error message that appears similar to the following example:

F5 Automated Product Installer
error: panic: function=transfer_file, line=NNN
error: panic: ptok=isolinux,
rep=/mnt/tmp/install/shared/tmp/install/product.iso, url=, src=vmlinuz, dest=/var/boot/vmlinuz
Failed to retrieve MOS file: vmlinuz

Important: If you receive this error message, you must reboot the device before performing the installation again.

Note: This issue often occurs when the Enterprise Manager polling interval has been shortened.

F5 Product Development tracked this issue as CR71645 and it was fixed in BIG-IP versions 9.3.1 and 9.6.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, and WebAccelerator release notes.

This issue still exists in the BIG-IP 9.4 software branch.

Important: This issue can still occur when upgrading to a fixed version from a version that is not fixed.

Workaround

If you are upgrading a device managed by Enterprise Manager, you can work around this issue by performing the installation or upgrade when a poll is unlikely to occur, or by putting the device in maintenance mode on Enterprise Manager. For information about placing a device into maintenance mode, refer to the Enterprise Manager Administrator Guide.

Do not run the switchboot utility on a device during the installation process.

Perform installation or upgrades during periods of minimal activity for the device.
