Description

PTR (reverse DNS) queries fail to resolve on BIG-IP DNS when using a custom DNS profile with DNS cache enabled. When clients query PTR records via the listener IP, responses may be "Server failed" or no answer is returned. However, PTR lookups succeed when queried without specifying the DNS listener IP in BIG-IP command line interface.

Environment

  • BIG-IP DNS VE
  • Custom DNS profile with DNS cache enabled
  • Listener virtual servers for client-facing DNS queries
  • "use-local-bind" set to "no" in the custom profile
  • DNSExpress not initially configured
  • No forward zones defined in the resolver for affected domains/PTRs

Cause

PTR lookups succeed when queried without specifying the DNS listener IP, because BIND is running and the PTR zones, we are querying are defined as such an answer will be provided by BIND.

When Cache defined, there is no fallback to BIND even though "use-local-bind" set to "yes", BIG-IP does not consult local BIND for any queries not resolved by cache. As a result, PTR queries for zones are not answered via listener IPs.

Recommended Actions

We have to either create a forward zone or DNSExpress zone.

The forward zone option will be more complicated as this will require an additional internal virtual server because forward zone DNS servers option does not accept localhost. The only simple solution will be DNSExpress, which we can configure following the link below. We MUST make sure that DNSExpress is enabled in the DNS profile.

Configuring DNS Express :
