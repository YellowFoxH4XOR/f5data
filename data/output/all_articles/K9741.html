Topic

When the Statistics Data Collection feature on Enterprise Manger is enabled, the Enterprise Manger will determine the current version of the big3d agent running on each managed device. If the Enterprise Manger has a newer version of the big3d agent than the target, Enterprise Manger will upgrade the big3d agent on the target device. This automatic upgrade will also occur during initial device discovery and upon any subsequent device refreshes. The upgrade of the big3d agent will cause the BIG-IP GTM to reflect a temporary change in status to Offline for all objects hosted on the system being upgraded.

During normal operations, the BIG-IP GTM system's gtmd process establishes a persistent iQuery connection to the big3d process running on TCP port 4353 on each BIG-IP server defined in the BIG-IP GTM configuration. This iQuery connection is used to communicate the status of the BIG-IP hosted virtual servers, data centers, links, and other monitored objects to the BIG-IP GTM. If the iQuery connection is broken between the BIG-IP GTM and any of its configured BIG-IP devices, the BIG-IP GTM will mark all objects associated with that device as offline, and will not choose them as load balancing targets. This behavior is intentional, since BIG-IP GTM must assume that a device with which it no longer can communicate may not be available to accept load balanced traffic.

When Enterprise Manger upgrades the big3d agent on a managed device, all existing connections to that big3d agent are disconnected. BIG-IP GTM systems monitoring the device being upgraded mark all hosted objects offline until the BIG-IP GTM is able to re-establish connectivity with the remote big3d agent. After the upgrade completes and the new big3d agent is started, BIG-IP GTM systems are again able to connect to the upgraded big3d agent and correctly report the status of its hosted objects.

Maintaining status while iQuery communication is briefly interrupted

In order to reduce the impact to production traffic relying on the BIG-IP GTM infrastructure, F5 recommends that you enable the Statistics Data Collection during a maintenance window. Alternatively, you can configure the BIG-IP GTM system to maintain an Available status for the virtual servers on each managed device while iQuery communication is briefly disrupted. The procedure varies depending on the BIG-IP software version your system is running. For more information, refer to the following Solutions:

  • K10835: Specifying BIG-IP GTM virtual server dependence on the iQuery connection state
  • K8506: Specifying GTM virtual server dependence on the iQuery connection state in BIG-IP GTM 9.x
