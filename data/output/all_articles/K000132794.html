Topic

This article applies to legacy BIG-IP Next CNF versions. For information about using the qkview utility to generate diagnostic data on BIG-IP Next CNF 2.x, refer to K000150767: Generate diagnostic data for BIG-IP Next SPK, BIG-IP Next CNF, and BIG-IP Next for Kubernetes using the QKView API.

Description

The qkview utility is a program that you can use to automatically collect diagnostic and logging information from BIG-IP Next CNFs. The qkview utility is an executable program that generates machine-readable (XML) diagnostic data and combines the data into a single compressed Tape ARchive (TAR) format file. You can upload this file, called a QKView file, and provide it to F5 Support to help them troubleshoot any issues.

Note: F5 Support requires a QKView file in all cases in which remote access to the product is not available.

The qkview utility is included with a set of diagnostic tools in the debug sidecar, which deploys by default with the BIG-IP Next CNFs. You can run the qkview utility from the debug and f5-fluentd containers to capture a full set of diagnostic data.

Note: To save qkview diagnostic files to a filesystem on a worker node, you must have a Kubernetes PersistentVolume available for binding and configure the debug container’s persistence parameter in the Helm values file. For more information, refer to F5 Cloud-Native Network Functions on F5 Cloud Docs.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Have BIG-IP Next CNFs running in the Robin Cloud-Native Platform (CNP).
  • Have a Linux or Mac workstation with Go installed.

Procedures

To generate diagnostic data for BIG-IP Next CNFs using the qkview utility, perform one of the following procedures, as needed:

  • Run the qkview utility using the debug sidecar
  • Run the qkview utility from a local workstation

Run the qkview utility using the debug sidecar

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a workstation with access to the Kubernetes cluster.
  2. Locate the name of the Traffic Management Microkernel (TMM) Proxy pod using the following syntax:

    kubectl get pods --selector app=f5-tmm -n <namespace>

    For example, if the TMM pod is running in the cnf-gateway namespace, enter the following command:

    kubectl get pods --selector app=f5-tmm -n cnf-gateway

    The following output indicates the name of the TMM pod is f5-tmm-59bfff4449-gqzkc:

    NAME                      READY   STATUS    RESTARTS   AGE
    f5-tmm-59bfff4449-gqzkc   5/5     Running   0          204d

  3. Connect to the TMM pod using the following syntax:

    kubectl exec -it <tmm_pod_name> -c debug -n <namespace> -- bash

    For example, using the TMM pod name and namespace from above, connect to the debug container in the TMM pod by using the following command:

    kubectl exec -it f5-tmm-59bfff4449-gqzkc -c debug -n cnf-gateway -- bash

    Once connected, you should see the name of the TMM pod in the shell prompt, similar to the following example:

    debuguser@f5-tmm-59bfff4449-gqzkc:~$

  4. Run the qkview utility by entering the following command:

    qkview

    When complete, the diagnostic snapshot file is saved to the local directory. The following example output indicates that the name of the diagnostic file is qkview.20210310-142024.tar.gz:

    Diagnostic snapshot file saved: qkview.20210310-142024.tar.gz

  5. Enter the following command to disconnect from the debug container:

    exit

  6. Copy the file to your workstation using the following syntax:

    kubectl cp <namespace>/<tmm_pod_name>:<qkview_file_name> ./<qkview_file_name> -c debug

    For example, if the TMM pod is named f5-tmm-59bfff4449-gqzkc and resides in the cnf-gateway namespace, enter the following command to copy the qkview.20210310-142024.tar.gz file:

    kubectl cp cnf-gateway/f5-tmm-59bfff4449-gqzkc:qkview.20210310-142024.tar.gz ./qkview.20210310-142024.tar.gz -c debug

  7. Locate the name of the Fluentd logging pod using the following syntax:

    kubectl get pods --selector app=f5-fluentd -n <namespace>

    For example, if the f5-fluentd pod is running in the cnf-gateway namespace, enter the following command:

    kubectl get pods --selector app=f5-fluentd -n cnf-gateway

    The following output indicates the name of the f5-fluentd pod is f5-toda-fluentd-84f96b6757-vw6j9:

    NAME                               READY   STATUS    RESTARTS   AGE
    f5-toda-fluentd-84f96b6757-vw6j9   1/1     Running   0          204d

  8. Connect to the Fluentd logging pod using the following syntax:

    kubectl exec -it <f5-fluentd_pod_name> -n <namespace> -- bash

    For example, if the Fluentd pod resides in the cnf-gateway namespace and is named f5-toda-fluentd-84f96b6757-vw6j9, enter the following command:

    kubectl exec -it f5-toda-fluentd-84f96b6757-vw6j9 -n cnf-gateway -- bash

  9. Run the qkview utility by entering the following command:

    qkview

    The following example output indicates the file name of the saved diagnostic snapshot is strong>qkview.20210310-152528.tar.gz:

    Diagnostic snapshot file saved: qkview.20210310-152528.tar.gz

  10. Enter the following command to disconnect from the f5-fluentd pod:

    exit

  11. Copy the file to your workstation using the following syntax:

    kubectl cp <namespace>/<f5-fluentd_pod_name>:<qkview_file_name> ./<qkview_file_name>

    For example, if the f5-fluentd pod name is f5-toda-fluentd-84f96b6757-vw6j9 and the pod resides in the cnf-gateway namespace, enter the following command:

    kubectl cp cnf-gateway/f5-toda-fluentd-84f96b6757-vw6j9:qkview.20210310-152528.tar.gz ./qkview.20210310-152528.tar.gz

  12. To upload the qkview files to iHealth, open a web browser and log in to https://ihealth.f5.com/qkview-analyzer/.
  13. Select Upload.
  14. Select Choose and select the qkview files on the local workstation.

    Note: As an alternative to using F5 iHealth, you can also provide the QKView file to F5 Support. To do so, refer to K000090853: Exchange files with F5 Support using MyF5.

Run the qkview from a local workstation

Note: The BIG-IP Next CNFs QKView package is currently only available as an Early Access (EA) feature.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Download the QKView tarball and the QKView md5sum files from CloudDocs.
  2. Using the Linux workstation, verify the integrity of the files using the following command:

    cat qkview-packaging.tar.gz.md5 ; md5sum qkview-packaging.tar.gz

    The resulting output should match as in the following example:

    19e2de4fd4ee1edc9a62fffa6095984f qkview-packaging.tar.gz
    19e2de4fd4ee1edc9a62fffa6095984f qkview-packaging.tar.gz

  3. Extract the qkview-packaging.tar.gz file using the following command:

    tar xvf qkview-packaging.tar.gz

  4. Enter the following command to list the files:

    ls -1

    Output should appear similar to the following:

    qkview-collector.sh
    qkview-packaging.tar.gz
    qkview-packaging.tar.gz.md5
    qkview-wrapper-darwin
    qkview-wrapper-linux

  5. Ensure the qkview utility files are executable by entering the following command:

    chmod 755 qkview-wrapper-* qkview-collector.sh

  6. The package includes a separate qkview-wrapper utility for Linux and Darwin (macOS) systems. Run the appropriate qkview-wrapper utility for your workstation using the following syntax:

    ./qkview-wrapper-<linux | darwin> -f ./qkview-collector.sh -n <namespace>

    For example, when using a Linux workstation and BIG-IP Next CNFs resides in the cnf-gateway namespace, enter the following command:

    ./qkview-wrapper-linux -f ./qkview-collector.sh -n cnf-gateway

  7. When complete, the qkview utility will generate the following file in the current directory:

    iHealth_qkview-packaging.tar.gz

  8. To upload the qkview file to iHealth, open a web browser and log in to https://ihealth.f5.com/qkview-analyzer/.
  9. Select Upload.
  10. Select Choose and select the iHealth_qkview-packaging.tar.gz file on the local workstation.

    Note: As an alternative to using F5 iHealth, you can also provide the QKView file to F5 Support. To do so, refer to K000090853: Exchange files with F5 Support using MyF5.
