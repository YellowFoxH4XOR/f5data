K30423885: Removing one or more unreachable DCDs from the BIG-IQ system

Type
Support Solution
Published
2019-05-17
Updated
2026-06-10
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.X, 8.3.X, 8.4.0, 8.3.0
Source
https://my.f5.com/manage/s/article/K30423885

Description

When one or more data collection devices (DCDs) are unreachable from the BIG-IQ system, you may want to remove it from the elasticsearch cluster configuration. However, you may not be able to remove the affected DCD because the BIG-IQ system needs to be able to reach the DCD for it to be removed.

Environment

  • Your BIG-IQ deployment consists of the following instances:
    • BIG-IQ Centralized Management system
    • One or more DCDs
  • One or more DCDs are no longer reachable

Cause

ElasticSearch cluster instabilities caused by unexpected BIG-IQ system operations.

Recommended Actions

To remove the unreachable DCDs, you can perform either of the following procedures:

  • Removing the unreachable DCD
  • Resetting the elasticsearch cluster

Removing the unreachable DCD

To remove a single unreachable DCD, perform the following procedure:

Impact of procedure: This procedure removes the existing elasticsearch data only from the unreachable node if the remaining DCD takes over the primary shards.

  1. Log in to the BIG-IQ command line.
  2. Identify the UUID of the unavailable DCD that you want to remove by typing the following command:

    restcurl /shared/resolver/device-groups/cm-esmgmt-logging-group/devices | grep -e hostname -e selfLink

  3. Create a shell variable uuid with the UUID value you have identified from the previous step using the following command syntax:

    uuid=<UUID of unavailable DCD>

    For example:

    uuid=c1544df0-40fd-4d88-8bb0-87b06b64365f

  4. Remove the unavailable DCD from the esmgmt logging group using the following command syntax, replacing <username:password> with the appropriate administrative user account:

    curl "localhost:8100/shared/resolver/device-groups/cm-esmgmt-logging-group/devices/$uuid" -u <username:password> -X DELETE

  5. Remove the unavailable DCD from all existing logging nodes (in case the DCD had multiple services enabled) using the following command syntax, replacing <username:password> with the appropriate administrative user account:

    for i in cm-access-allLoggingNodes cm-adccore-allLoggingNodes cm-afmevents-allLoggingNodes cm-asm-allLoggingNodes cm-dosevents-allLoggingNodes cm-websafe-allLoggingNodes ; do curl -X DELETE "localhost:8100/shared/resolver/device-groups/$i/devices/$uuid" -u <username:password> ; done

  6. Identify the cluster ID and set a shell variable clusterid with the cluster ID value by typing the following command:

    clusterid=`restcurl /cm/shared/esmgmt/cluster/ | grep selfLin | egrep -o  ".{8}-.{4}-.{4}-.{4}-.{12}"`

  7. BIG-IQ 8.x and later:
    Extract the current cluster configuration into a text file /var/tmp/cluster.txt by typing the following command:

    restcurl /cm/shared/esmgmt/cluster/$clusterid | sed -e s/\"lastUpdateMicros.*//g | sed -e s/\"generation.*//g | sed -e s:internal_elasticsearch\",:internal_elasticsearch\":g  > /var/tmp/cluster.txt

    BIG-IQ 7.x and earlier:
    Extract the current cluster configuration into a text file /var/tmp/cluster.txt by typing the following command:

    restcurl /cm/shared/esmgmt/cluster/$clusterid | sed -e s/\"lastUpdateMicros.*//g | sed -e s/\"generation.*//g | sed -e s:elasticsearch/data\",:elasticsearch/data\":g  > /var/tmp/cluster.txt

  8. Edit the /var/tmp/cluster.txt using a text editor of your choice.
  9. BIG-IQ 8.x and later:
    Locate the configuration stanza for the unavailable DCD and remove it. Using the previous example of the unavailable DCD with UUID of c1544df0-40fd-4d88-8bb0-87b06b64365f, the following example removes the following stanza:

          "allowData": true,
          "allowMaster": true,
          "httpAddress": "127.0.0.1",
          "httpPort": "9200",
          "transportAddress": "192.168.161.38",
          "transportPort": "9300",
          "zone": "default",
          "mlockall": true,
          "repo": "/var/config/rest/elasticsearch/data",
          ...
          ...
          ...
          "opendistroSecurityRestapiRolesEnabled": [
            "all_access",
            "security_rest_api_access",
            "opendistro_security_anonymous_backendrole"
          ],
          "opendistroSecuritySslHttpEnabledCiphers": [
            "TLS_DHE_RSA_WITH_AES_256_CBC_SHA256"
          ],
          "opendistroSecuritySslHttpEnabledProtocols": [
            "TLSv1.1",
            "TLSv1.2"
          ],

          "opendistroSecurityEnableSnapshotRestorePrivilege": true,
          "opendistroSecuritySslAuditType": "internal_elasticsearch"
        }

    BIG-IQ 7.x and earlier:
    Locate the configuration stanza for the unavailable DCD and remove it. Using the previous example of the unavailable DCD with UUID of c1544df0-40fd-4d88-8bb0-87b06b64365f, the following example removes the following stanza:

        {
          "machineId": "c1544df0-40fd-4d88-8bb0-87b06b64365f",
          "allowData": true,
          "allowMaster": true,
          "httpAddress": "127.0.0.1",
          "httpPort": "9200",
          "transportAddress": "192.168.161.38",
          "transportPort": "9300",
          "zone": "default",
          "mlockall": true,
          "repo": "/var/config/rest/elasticsearch/data"
        }

  10. Upload the edited cluster configuration file /var/tmp/cluster.txt to restjavad using the following command syntax, replacing <username:password> with the appropriate administrative user account:

    curl -X PUT localhost:8100/cm/shared/esmgmt/cluster/$clusterid -u <username:password> -d @/var/tmp/cluster.txt

  11. Restart the restjavad and elasticsearch processes to push the configuration to elasticsearch.json and the remaining DCDs by typing the following command:

    bigstart restart restjavad ; sleep 5 ; bigstart restart elasticsearch

  12. BIG-IQ 8.x and later:
    You should no longer see the unavailable DCD in the BIG-IQ user interface, restjavad or elasticsearch configuration on any of the remaining cluster members. To verify, enter the following commands:

    restcurl /cm/shared/esmgmt/cluster/ | grep -e transportAdd

    egrep ":9300" /var/config/rest/elasticsearch/config/elasticsearch.yml

    BIG-IQ 7.x and earlier:
    You should no longer see the unavailable DCD in the BIG-IQ user interface, restjavad or elasticsearch configuration on any of the remaining cluster members. To verify, enter the following commands:

    restcurl /cm/shared/esmgmt/cluster/ | grep -e transportAdd

    egrep 10.*9300 /var/config/rest/elasticsearch/config/elasticsearch.json

Resetting the elasticsearch cluster

To remove and re-add the DCDs to the cluster, perform the procedure described in the following article: K02014651: Removing a DCD association from BIG-IQ Centralized Management

Additional Information

The DCDs and BIG-IQ Centralized Management are all part of an elasticsearch cluster. You can determine the detailed configuration of the elasticsearch cluster from BIG-IQ Centralized Management by typing the following command:

restcurl /cm/shared/esmgmt/cluster/

If your cluster contains more than two DCDs, the cluster health stays YELLOW for a short period of time while the replicas are recreated and redistributed among the remaining available DCDs.

Although the BIG-IQ user interface reports that the unreachable DCD is unavailable on the BIG-IQ Data Collection Devices page (System > BIG-IQ DATA COLLECTION > BIG-IQ Data Collection Devices), the elasticsearch configuration continues to include it. You can confirm by typing the following command:

restcurl /cm/shared/esmgmt/cluster/ | grep transportAdd

The following example output shows that the unavailable DCD at 192.168.161.38 is still included in the elasticsearch configuration:

          "transportAddress": "192.168.161.36",
          "transportAddress": "192.168.161.37",
          "transportAddress": "192.168.161.38",

Attempts to remove the unreachable device from the BIG-IQ user interface fail because the BIG-IQ Centralized Management must be able to reach the DCD.
