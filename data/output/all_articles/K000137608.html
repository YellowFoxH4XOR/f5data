K000137608: iRule not working with error: Can't call after responding - ERR_NOT_SUPPORTED (line 1) invoked from within "HTTP::uri"

Type
Support Solution
Published
2023-11-17
Updated
2023-11-17
Applies to
  • BIG-IP
  • BIG-IP AFM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000137608

Description

After assigning a second iRule to a virtual server the following error is logged on /var/log/ltm

err tmm[21399]: 01220001:3: TCL error: /Common/irule_2_example <HTTP_REQUEST> - Can't call after responding - ERR_NOT_SUPPORTED (line 1) invoked from within "HTTP::uri"

Environment

  • BIG-IP LTM.
  • 2 or more iRules assigned to the same virtual server.

Cause

  • LTM iRule attempting to process HTTP context data after LTM iRule has already completed URI redirect
  • Change in behavior due to enhancement ID 737252

Recommended Actions

  • You will need to modify assigned iRules to include return or HTTP::has_responded command
  • Example syntax:
when HTTP_REQUEST
{
if {[HTTP::has_responded]} {
    return
  } else {
    switch [HTTP::uri]
    {
        "/uri_one"
        {
            HTTP::respond 200 
        }
        "/uri_two"
        {
            HTTP::respond 200 
        }
    }
}
