K36641730: Removing the ca-bundle.crt from SSL certificate expiration email alerts

Applies to

Source

Topic

You should consider using this procedure under the following conditions:

  • You have configured the BIG-IP system to send email alerts prior to Secure Socket Layer (SSL) certificate expiration. For more information refer to K15288: Sending an advance email alert for impending SSL certificate expiration.
  • You would like to stop receiving expiration emails for SSL certificates stored in the BIG-IP system ca-bundle.crt file.

Description

The BIG-IP system runs the check-cert utility once a week to detect and warn when an SSL certificate expiration period is within 30 days. The check-cert utility also examines the SSL certificates stored in the ca-bundle.crt file. Over time, you may receive an increasing number of email alerts for well-known CA certificates stored in the ca-bundle.crt as they near expiration.

The ca-bundle.crt is located in the /config/ssl/ssl.crt directory and is not easily modified due to being referenced by default system configuration objects. If you require the use of and would like to modify the ca-bundle.crt file, you can do so by installing the CA Bundle iAPP and following the procedures in the F5 CA bundle iApp deployment guide. If you do not use or need the ca-bundle.crt file, it may be easier to remove the ca-bundle.crt from email alerts.

You can use the following procedures to verify that the ca-bundle.crt file is not in use and remove them from email alerts.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the BIG-IP system Advanced Shell (bash).

Verifying if ca-bundle.crt is in use

You can configure the following SSL profile options to use the ca-bundle.crt file:

  • Chain - Helps remote clients establish a trust relationship when they are presented with a server SSL certificate that is signed by an untrusted CA.
  • Trusted Certificate Authorities - CAs that the BIG-IP system trusts when configured to perform Client SSL certificate authentication.

If one or more profiles references the ca-bundle.crt file, you may not want to remove the file from SSL certificate expiration email alerts. Use the following procedure to verify that the ca-bundle.crt file is not currently in use.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system.
  2. To view SSL profiles that are configured to use the ca-bundle.crt file, type the following command:

    tmsh list ltm profile | grep -iE 'profile|bundle'

    In the following example, two SSL profiles are configured to use the ca-bundle.crt file:

    ltm profile client-ssl chain_example {
        chain ca-bundle.crt
        chain ca-bundle.crt
    ltm profile client-ssl client_auth_example {
        ca-file ca-bundle.crt
        client-cert-ca ca-bundle.com

    If no ca-bundle.crt files are in use, no output is displayed.

Removing ca-bundle.crt from email alerts

The BIG-IP system uses crond to run the check-cert utility every Sunday at 4:22 AM. You can modify the check-cert utility option to ignore the ca-bundle.crt by performing the following procedure.

Note: These changes will not be saved in a User Configuration Set (UCS) or carried forward with system upgrades.

Impact of procedure: If the ca-bundle.crt file is not in use (see the first procedure), performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system Advanced Shell (bash).
  2. Using a text editor, edit the /etc/cron.weekly/5checkcert file.
  3. Locate the following line that runs the check-cert utility:

    /usr/bin/tmsh run sys crypto check-cert stdout disabled

  4. Add the ignore-large-cert-bundles enabled option to the check-cert command, as follows:

    /usr/bin/tmsh run sys crypto check-cert ignore-large-cert-bundles enabled stdout disabled

  5. Save the file.

Verifying the expiration emails

The SSL certificate alert email indicates the name of the file that contains the expiring SSL certificate in the Subject. The following example shows an expired certificate stored in the ca-bundle.crt file:

01420008:4: Certificate 'CN=Certificate Authority,O=CA Inc,C=US' in file /Common/ca-bundle.crt will expire on Dec 31 23:59:59 2016 GMT

You can verify alert emails that the BIG-IP system sends by performing the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system Advanced Shell (bash).
  2. To send test SSL certificate expiration emails, type the following command:

    /etc/cron.weekly/5checkcert

  3. Log in to the workstation that receives alert emails and ensure that no emails mention ca-bundle.crt.
