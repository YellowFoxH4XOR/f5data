Description

Redeploying an F5 SSL Orchestrator explicit proxy topology after a topology-level change can remove custom iRules assigned to the explicit-proxy virtual server. The deployment may complete successfully without displaying an error.

Changes made directly through the applicable interception rule retain the iRule assignments.

Environment

  • Product: F5 SSL Orchestrator
  • Feature: Explicit proxy topology
  • Configuration objects:
    • SSL Orchestrator topology
    • Explicit-proxy interception rule
    • Explicit-proxy virtual server
    • Custom iRules

Cause

This behavior is caused by a product defect in the explicit proxy topology deployment workflow. This is tracked in ID2454073.

Answer/Recommended Actions

A product fix is required to prevent custom iRules from being removed during the affected topology deployment workflow.

Until a fix is available, re-add the custom iRules after deploying the explicit proxy topology:

  1. Go to Main > SSL Orchestrator > Configuration.
  2. Select the Interception Rules tab.
  3. Select the affected explicit-proxy interception rule.
  4. Edit the interception rule.
  5. Under Resources, move the required custom iRule to the selected resources.
  6. Save and deploy the interception rule.
  7. Verify that the iRule is assigned to the intended explicit-proxy virtual server.

To reduce the impact:

  • Complete topology-level changes and deploy the topology first.
  • Re-add custom iRules afterward from the Interception Rules tab.
  • Do not rely on iRule assignments being retained when redeploying the topology.

Additional Information

  • The Resources section and deployed virtual-server list are available when the interception rule is accessed through the Interception Rules tab.
  • Accessing an interception rule through the topology does not expose the same deployed virtual-server resources.
  • Direct changes to the interception rule followed by deployment do not remove the iRules.
  • The iRules can be removed when the topology is subsequently modified and redeployed, including after unrelated changes such as modifying logging or the destination address and mask.
