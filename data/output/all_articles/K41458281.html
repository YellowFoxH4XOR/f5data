Description

When configuring an IPSec tunnel between a BIG-IP unit and an Azure endpoint, it is mandatory for both phases'  PFS ciphers to match.


Environment

 

  • BIG-IP against Azure hosted IPSec endpoint.
  • Azure hosted BIG-IP against external IPSec endpoint.
  • Azure hosted BIG-IP against Azure hosted IPSec endpoint.

 

 

Cause


It is the only actual PFS ciphers combination that works in BIG-IP - Azure. F5 is still researching the cause.


Recommended Actions
 

Configure same PFS ciphers to phase 1 and phase 2 IPSec configuration in BIG-IP unit:
 
Procedure

Example:


1.-  In BIG-IP GUI go to    Network  ››  IPsec: Policies  ››  New Policy    and configure PFS phase 2 cipher value


net ipsec ipsec-policy /Common/MY-IPSEC-POLICY {
    app-service none
    description none
    ike-phase2-auth-algorithm sha1
    ike-phase2-encrypt-algorithm aes256
    ike-phase2-lifetime 60
    ike-phase2-lifetime-kilobytes 0
    ike-phase2-perfect-forward-secrecy modp1024 <----------- Phase 2 PFS ciphers value must match value defined in phase 1 cipher
    ipcomp none
    mode interface
    protocol esp       
    tunnel-local-address ::
    tunnel-remote-address ::
}



2.- In BIG-IP GUI go to Network ››  IPsec : Traffic Selectors  ››  New Traffic Selector   and assign configured IPSec policy



net ipsec traffic-selector /Common/MY-IPSEC-TS {
    action protect
    app-service none
    description none
    destination-address 0.0.0.0/0
    destination-port any
    direction both
    ip-protocol 255
    ipsec-policy /Common/MY-IPSEC-POLICY
    order 1
    source-address 0.0.0.0/0
    source-port any
}


3.- In BIG-IP GUI go to    Network  ››  IPsec: IKE Peers  ››  New IKE Peer    and configure PFS phase 1 cipher value


net ipsec ike-peer /Common/MY-IKE-PEER {
    app-service none
    ca-cert-file none
    crl-file none
    description none
    dpd-delay 45
    generate-policy off
    lifetime 60
    mode main
    my-cert-file none
    my-cert-key-file none
    my-id-type address
    my-id-value aaa.bbb.ccc.ddd
    nat-traversal on
    passive false
    peers-cert-file none
    peers-cert-type none
    peers-id-type address
    peers-id-value bbb.ccc.ddd.eee
    phase1-auth-method pre-shared-key
    phase1-encrypt-algorithm aes256
    phase1-hash-algorithm sha1
    phase1-perfect-forward-secrecy modp1024              <-------------- PFS phase 1 cipher value matching phase 2 cipher
    preshared-key-encrypted ***scrubbed***
    prf sha1
    proxy-support enabled
    remote-address ccc.ddd.eee.fff
    replay-window-size 64
    state enabled
    traffic-selector { /Common/MY-IPSEC-TS }
    verify-cert false
    version { v2 }
}
--------------------------------

Configure al other parameters as required

------------------ Same PFS ciphers must be configured at other (Azure) end.
