Known Issue

This is the result of a known issue. Entries containing include statements are not correctly imported during an upgrade from BIG-IP version 9.x to version 10.x. The import script used during the upgrade does not properly read the include statement that is often associated with NTP and syslog configurations, causing the system to report an error and fail to load the information correctly.

Note: The remote syslog information is stored in the /config/bigip_sys.conf file.

For example, a remote syslog entry from a BIG-IP version 9.4.x before upgrade will appear similar to the following example:

syslog {   include "destination d_somewhere3 { tcp(\"10.10.1.2\" port(1517) );};log { source(local); destination(d_somewhere3);};"   remote port 1517   remote server none}

A remote syslog entry from a BIG-IP version 10.x after the upgrade will appear similar to the following example:

syslog {   include "destination d_somewhere3 { tcp(\"10.10.1.2\" port(1517) );};log { source(local); destination(d_somewhere3);};"   remote server logserver {      host none      remote port 1517   }}

In the post upgrade example, the include statement is retained, but since the import script did not correctly handle the include statement, it inserts the following information:

remote server logserver {      host none      remote port 1517   }

This additional information causes the following error message to display when the bigpipe load command is issued:

BIGpipe unknown operation error:   01070920:3: Application error for confpp: STDERR/STDOUT text beginsStopping syslog-ng:Starting syslog-ng: Error resolving hostname; host='::'No destination address set;[FAILED]STDERR/STDOUT text ends*************************************************************confpp[18252]: reconfig command FAILURE for unix_config_syslog returned: '/etc/init.d/syslog-ng restart 2>&1'Stopping syslog-ng: [FAILED]Starting syslog-ng: [  OK  ]

F5 Product Development tracked this issue as CR124024 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

If an error is reported or information is not being sent to a remote syslog server is not using the correct servers following an upgrade to version 10, you can work around this issue by removing the extraneous information. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Open the bigip_sys.conf file using a text editor.
  3. Locate the syslog { entry.
  4. Remove the following from the syslog entry:

    remote server logserver {
    host none
    remote port <port>
    }
  5. Save the changes.
  6. Reload the configuration using the following command:

    bigpipe load
