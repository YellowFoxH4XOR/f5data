Known Issue

HTTP downloads that are larger than 2.1 gigabytes (GB) may fail.

This issue occurs when all of the following conditions are met:

  • Your virtual server is of the Performance HTTP type with the fasthttp profile.
  • An HTTP client requests a file that is larger than 2.1 GB.
  • The Content-Length header is present in the response and shows a content length that is larger than 2.1 GB.

Impact

You will be unable to serve files greater than 2.1 GB in length.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Requests for large files will fail.
  • The BIG-IP resets the connection after the connection has been idle for the duration of the idle timeout value configured in the fasthttp profile associated with the virtual server.

Workaround

To work around this issue, you can use a different virtual server type. To do so, perform the following procedure:

Impact of workaround: Performance may be impacted, depending on your specific environment.

  1. Log in to the BIG-IP Configuration utility as the administrator.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the affected virtual server.
  5. From the Type menu, select either Performance Layer 4 or Standard.
  6. Click Update.
