Known Issue

Firefox and Safari browsers using private browsing mode on iOS devices do not pass persistent client identification challenge.

This issue occurs when all of the following conditions are met:

  • Web scraping is configured with the Persistent Client Identification option enabled in an ASM security policy.
  • A client is using the Safari or Firefox web browser on an iOS device.

Impact

The client browser is unable to access the web page.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system logs messages to the /var/log/tmm file that appears similar to the following example:

    notice CLNG|DBUG|dosl7_parse_challenge_headers:3044|failed parsing header 3

Workaround

To work around this issue, you can turn off the Persistent Client Identification option. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Anomaly Detection > Web Scraping.
  3. In the Web Scraping Configuration section, clear Enabled in the Persistent Client Identification field.
  4. Click Save.
  5. Click Apply Policy.
