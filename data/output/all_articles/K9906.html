Note: This Solution only applies to BIG-IP platforms that contain a switch card control processor (SCCP). The BIG-IP platforms affected include the 1500, 3400, 4100, 6400, 6800, 8400, and 8800 platforms.

When troubleshooting an issue, F5 Technical Support may request the log files from the SCCP subsystem in order to help determine the cause of the issue. It is important to gather the SCCP log files before any of the following operations occur:

  • System is power cycled
  • A full_box_reboot is performed
  • End User Diagnostic (EUD) software is run

If any of these operations are performed before you can gather the SCCP log files, the SCCP log files will be lost. The SCCP log files are kept in memory only as long as the SCCP is not shut down.

Note: For more information, refer to K6013: Overview of SCCP logging.

F5 Technical Support most commonly requests SCCP log files when an unexpected BIG-IP system reboot occurs. The SCCP log files may provide information to the cause of the reboot, or any information that is reported while it is rebooting.

Gathering SCCP log files

  1. Log in to the BIG-IP CLI through the console or SSH as the root user.
  2. Copy the messages log file to the /var/tmp/ directory on the host system using the following command:

    scp root@sccp:/var/log/messages /var/tmp/`/bin/hostname`-sccplogs.log
  3. Copy the bcm56xxd log file to the /var/tmp/ directory on the host system using the following command:

    scp root@sccp:/var/log/bcm56xxd /var/tmp/`/bin/hostname`-bcm56xxd.log
  4. Upload the files that you copied to the /var/tmp/ directory from Steps 2 and 3.

Note: For information about how and where to upload files for F5 Technical Support, refer to K2486: Providing files to F5 Technical Support.
