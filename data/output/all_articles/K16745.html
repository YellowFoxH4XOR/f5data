Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when the TCP::close iRule command is executed during a Secure Sockets Layer (SSL) handshake.

This issue occurs when the following condition is met:

  • A virtual server is configured with an iRule that appears similar to the following example:

    when CLIENTSSL_CLIENTHELLO {
    log local0. "closing"
    TCP::close
    }

The CLIENTSSL_CLIENTHELLO event triggers when the BIG-IP system receives the client's SSL ClientHello message, before the system sends its SSL ServerHello message. For more information, refer to CLIENTSSL_CLIENTHELLO on F5 Cloud Docs.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • Messages similar to the following example are logged to the /var/log/ltm file:

    notice sod[8810]: 01140045:5: HA reports tmm NOT ready.
  • Messages similar to the following example are logged to the /var/log/messages file:

    notice logger: Started writing core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
    notice logger: Finished writing 236194271 bytes for core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
  • The BIG-IP system generates TMM core files to the /var/core directory, with time stamps that correlate to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Apr 13 15:09 tmm.0.bld2384.0.core.gz

Workaround

To work around this issue, F5 recommends that you use either the drop or reject iRules commands, instead of the TCP::close command.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.
