K000135047: ASM default blocking page uses JavaScript history.back()

Type
Support Solution
Published
2023-11-24
Updated
2024-01-03
Source
https://my.f5.com/manage/s/article/K000135047

Description

Several of the default ASM blocking pages use the JavaScript function "history.back()" to give the application user the opportunity to return to the previous page when being blocked by the configured policy actions.

Since ASM does not control the contents of the client browser's history, it is possible that this will return the user to a page outside of the protected website depending on the sequence of events leading up to the blocking action being taken and this may result in user confusion.

Environment

  • BIG-IP Advanced WAF/ASM provisioned
  • The system-default blocking pages are in use (Default Blocking Page, Login Page blocking page and Failed Login Honeypot page)

Recommended Actions

If the protected website handles sensitive data and you wish to ensure that any user encountering the blocking page cannot be manipulated into leaving the protected website (through some manipulation of their browser history) you should configure appropriate custom blocking pages.

Consider the use of absolute links to return the user to a specific page, or a JavaScript call such as window.location.href or window.location.replace in place of history.back(), e.g.;

window.location.href = 'http://' + window.location.host;
or
window.location.replace('http://' + window.location.host);

Ensuring that the URI scheme is appropriate for your application (e.g., http or https)

Additional Information

In some circumstances it may be possible for a malicious actor to use the presence of history.back() to confuse or otherwise help enable a phishing attack against a target user. F5 considers this scenario as unlikely, however configuring a custom blocking page as suggested above can resolve any concerns around this. See Related Content for an external blog describing how such an attack could theoretically take place.

Bug ID1280557 has been opened to improve the default blocking page; once resolved this bug ID will appear in the Release Notes for any version(s) with improved default blocking pages.
