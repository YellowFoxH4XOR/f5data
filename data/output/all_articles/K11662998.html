Known Issue

The dynconfd process leaks a small amount of memory with each MCP message. The process may leak more memory with certain configurations, such as large numbers of pool members, combined with flapping.

Impact

The dynconfd process memory usage increases over time. This behavior may cause the host to exhaust its memory, and the BIG-IP system processes may restart. If you have configured your BIG-IP system as a device group member, the device may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The top utility indicates that the dynconfd process memory allocation grows over time.
  • In the /var/log/kern.log file, you observe error messages similar to the following examples:

    err kernel: Out of memory: Kill process 8141 (dynconfd) score 155 or sacrifice child
    err kernel: Killed process 8141, UID 0, (dynconfd) total-vm:2786984kB, anon-rss:2713480kB, file-rss:748kB

  • The BIG-IP system swap file usage increases as the dynconfd process memory allocation grows.

Workaround

To temporarily work around this issue, you can restart the dynconfd process. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system cannot resolve the fully qualified domain name (FQDN) nodes while the dynconfd process is restarting.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the dynconfd process, type the following command:

    restart /sys service dynconfd
