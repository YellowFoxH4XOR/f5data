Known Issue

This is the result of a known issue. If you disable a BIG-IP interface, the setting is not retained following a system reboot or a restart of the mcpd process.

For example, if you disable interface 1.1 using the bigpipe command or the Configuration utility, the interface is reenabled following a system reboot or a restart of the mcpd process. This behavior occurs for both the management port and TMM ports.

F5 Product Development is tracking this issue as ID 247221 (formerly CR112289).

Note: This issue does not affect the BIG-IP version 10.x software branch.

Workaround

You can work around this issue and restore the disabled status for the affected interfaces by issuing the bigpipe load command at the BIG-IP command line after mcpd completes its initialization and logs the following message in /var/log/ltm:

Oct 14 19:10:57 big-ip mcpd[1989]: 01070427:5: Initialization complete. The MCP is up and running

This command will then load the custom interface settings, which will remain active until mcpd restarts.

Additionally, you may automate the bigpipe load command execution by using the alertd facility to monitor the logs for the above message indicating that mcpd has been reloaded. To do so, perform the following procedure:

  1. Open the /config/user_alert.conf file in a text editor.
  2. Add the following lines to the end of the file:

    alert if_media_workaround "Initialization complete. The MCP is up and running" {
    exec command="/bin/bigpipe load"
    }
  3. Save and close the file.
  4. At the command line, execute the following command to persist this change through future reboots:

    bigpipe save all

The system will now recognize an mcpd restart, and will automatically execute the bigpipe load command to reload the custom interface settings.
