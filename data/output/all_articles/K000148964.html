Description

Tenants are suffering packet drops. This behavior get much worse after vlan-group is created on tenants

 

Environment

  • F5OS-A
  • rSeries r5000/r10000
  • Tenant
  • Packet loss/drops

Cause

  • Bug ID 1579181

This drop occurs, when front panel capacity of traffic is lower than Internal traffic which is fixed speed 100G.
NOTE: this does not affect r2000/r4000.

 

Recommended Actions

To check if the unit is suffered this bug ID, run the below command in rSelies CLI in bash mode

docker exec system_fpga tmctl -w $COLUMNS gbx_stat

If you can see drop count in egr_pkt_drop_cnt and egr_byte_drop_cnt are increasing, you are hitting this bug.

This issue occurs when total speed of the external interfaces for each port group is less than 100G.

We recommend

  • Use 100G interface where it is possible
  • We can provide EngHF for this issue on top of v1.8.0. Please escalate the issue to F5 Support with fresh qkviews.
  • Change the port group's speed or numbers of interface to use to higher for each interface in use (make close to 100G in total in each pipeline.)

 

When you can not use 100G interface nor unable to upgrade to 1.8, consider below and try to use maximize total speed of external interface for the port group.

The below picture tells the interface design of r5 Series from rSeries Networking

The PIPELINE (RED) is dedicated in one of internal interface. and the PIPELINE (BLUE) is dedicated in the other internal interface.

To check, which PIPELINE has what interface, run the bellow command in ConfD on rSeries CLI.


show port-mappings

Consider to use up each PIPELINE's interfaces. 

For example, in the case of above example output for gbx_stat table, the best option is move interface 5.0 (f5sw_link_nw_4) and 6.0 (f5sw_link_nw_5) to PIPELINE-2's interfaces (7.0-10.0). And add the all intefaces (5.0 and 6.0) on PIPELINE-1 for the traffic handled with interface 2.0 (f5sw_link_nw_2) and 3.0 (f5sw_link_nw_3) .
