Known Issue

BIG-IP Advanced Routing Module (BIG-IP ARM) may fail to redistribute routes using Open Shortest Path First version 2 (OSPFv2) when route entries are rapidly deleted and added.

This issue occurs when all of the following conditions are met:

  • Your system is configured to use BIG-IP ARM.
  • BIG-IP ARM is configured to redistribute routes using OSPFv2.
  • A kernel or static route is removed and then added, multiple times, in quick succession.

Impact

Some local routes are not redistributed using OSPFv2.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A route appears in the local routing table, but does not appear in the OSPFv2 database.

Workaround

To work around this issue, you can terminate the ospf process in the BIG-IP ARM system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will briefly disrupt dynamic routing that uses the ospf process.

  1. Log in to the command line of the BIG-IP ARM system.
  2. To display the OSPF Process ID number for the affected route domain, use the ps command:

    For example:

    ps | grep ospfd
     
  3. To terminate the ospfd process, use the kill command:

    For example:

    kill -9 <ospfd_PID>
