K000160890: Since migrating to rSeries 2000/4000 platform, certain NAT services have been disconnecting.

Published

Description

NAT connections intermittently disconnect and source port is not preserved after migrating to rSeries 2000/4000 platform, causing service disruptions.

Environment

  • rSeries 2000/4000 platform
  • BIG-IP tenant with LTM
  • NAT configured on LTM

Cause

The RSS CMP hash algorithm on rSeries platforms does not preserve source port for NAT/SNAT when using the standard "Preserve" setting, leading to connection disruptions.

Answer/Recommended Actions

Set the Source Port option to "Preserve Strict" on the affected virtual servers to ensure source port preservation:

  • On the affected virtual server(s), set the Source Port option to "Preserve Strict".
  • In the BIG-IP Configuration utility, navigate to the virtual server.
  • Click on "Advanced" settings.
  • Set "Source Port" to "Preserve Strict".

This ensures the source port is preserved for NAT/SNAT traffic, preventing unexpected disconnections.

Additional Information

When troubleshooting intermittent disconnections of NAT you may see the following on packet captures: repeated TCP retransmissions and RSTs with "[F5RST: Unable to obtain local port]" during NAT-processed flows.

Identified that on rSeries platforms, the RSS CMP hash algorithm does not preserve source port with standard "Preserve" setting for NAT/SNAT, as documented in K50261325.

Determined that only the "Preserve Strict" source port setting on the virtual server can guarantee source port preservation, though with potential performance impact.
