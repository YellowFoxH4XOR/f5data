Security Advisory Description

Validating the order of the public keys in the Diffie-Hellman Key Agreement Protocol, when an approved safe prime is used, allows remote attackers (from the client side) to trigger unnecessarily expensive server-side DHE modular-exponentiation calculations. The client may cause asymmetric resource consumption. The basic attack scenario is that the client must claim that it can only communicate with DHE, and the server must be configured to allow DHE and validate the order of the public key. (CVE-2024-41996)

Note: For more information, refer to the D(HE)at Attack project page. This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.

Impact

Mitigation

BIG-IP

To mitigate this vulnerability, you can disable Diffie-Hellman ciphers in your configuration. To do so, perform the following procedures, as applicable:

Impact of action: Disabling Diffie-Hellman ciphers may prevent connections from being established, depending on the type of configuration in your scenario. F5 recommends testing all changes in a test environment and scheduling a maintenance window for any production changes.

BIG-IP (data plane)

Configure Client SSL and Server SSL profiles to not use DHE ciphers. Use a cipher group/suite that does not use DHE ciphers. To do so, refer to the following articles:

  • K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x)
  • K10866411: Creating a custom cipher group using the Configuration utility.

Note: The default Client SSL and Server SSL profiles use DHE ciphers.

Configuration utility (httpd)

The Configuration utility uses Elliptic Curve Diffie-Hellman Ephemeral (ECDHE) ciphers by default, but not Diffie-Hellman (DH) or Diffie-Hellman Ephemeral (DHE). ECDHE ciphers are not vulnerable to this issue. To manage the ciphers used by the BIG-IP Configuration utility, refer to K02321234: Manage the SSL protocols and ciphers allowed by the Configuration utility.

OpenSSH

The OpenSSH server configuration allows Diffie-Hellman ciphers by default. To verify that the Diffie-Hellman ciphers are enabled in the OpenSSH server on your BIG-IP system, you can log in to the Advanced Shell (bash) and run the following command:

sshd -T | grep kex

The command should return an output similar to the following example indicating that the Diffie-Hellman ciphers are enabled:

gssapikexalgorithms gss-gex-sha1-,gss-group1-sha1-,gss-group14-sha1-
kexalgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,diffie-hellman-group14-sha1,diffie-hellman-group-exchange-sha1

You should omit these Diffie-Hellman ciphers and include the ciphers that your SSH clients support in the key exchange algorithms for the OpenSSH server on your BIG-IP system.

Note: To display the list of supported key exchange algorithms on your SSH client, you can run the ssh -Q kex command in the command line of your SSH client.

To configure the specific key exchange algorithms ciphers for the OpenSSH server on your BIG-IP system, you can perform the Modifying the list of ciphers, KEX algorithms, and MAC algorithms used by the SSH service procedure in K80425458: Modifying the list of ciphers and MAC and key exchange algorithms used by the SSH service on the BIG-IP or BIG-IQ systems and replace the include none line in the sshd configuration with include "KexAlgorithms <list of KEX ciphers separated by commas>". For example:

include "KexAlgorithms curve25519-sha256@libssh.org,curve25519-sha256,ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521"

After you have saved the changes, you can run the sshd -T | grep kex command in bash to verify if the Diffie-Hellman ciphers are now omitted from the OpenSSH server on your BIG-IP system. Based on the previous example, you should observe an output similar to the following example indicating the OpenSSH server on your BIG-IP system no longer allows Diffie-Hellman ciphers for key exchange algorithms:

gssapikexalgorithms gss-gex-sha1-,gss-group1-sha1-,gss-group14-sha1-
kexalgorithms curve25519-sha256@libssh.org,curve25519-sha256,ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521

BIG-IQ

F5 recommends that you do not enable the DHE cipher suite in the httpd SSLCiphers list.

F5OS-A and F5OS-C

F5OS tenants (Data plane)

Configure your F5OS tenants to disable Diffie-Hellman and use ECDHE instead. For BIG-IP tenants, refer to the BIG-IP (data plane) section.

webUI (httpd)

The webUI in F5OS allows Diffie-Hellman key exchange by default. To disable Diffie-Hellman and use ECDHE, refer the example provided in the Using the CLI section in K000139007: Managing the SSL ciphers allowed by the VELOS or rSeries system webUI.

OpenSSH

The SSH service in F5OS uses Diffie-Hellman key exchange by default. To disable Diffie-Hellman and use ECDHE, refer the example provided in the Using the CLI section in K000139008: Managing the list of ciphers and MAC and Key Exchange algorithms used by the SSH service on the VELOS or rSeries systems.
