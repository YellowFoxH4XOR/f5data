Known Issue

Under rare circumstances, the merged process may restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is provisioned as a Virtual Clustered Multiprocessing (vCMP) host.
  • The Traffic Management Microkernel (TMM) or the bcm56xxd process is starting up due to one of the following events:
     
    • A system startup after an upgrade or reboot.
    • The bigstart restart command is run on the system.
    • A system restart after re-licensing.

The merged process integrates statistical data at defined intervals. When this issue occurs, the merged process is processing temporary invalid statistics published by TMM or the bcm56xxd process.

Impact

There is no impact to the system or the statistics. The invalid statistics are cleaned up automatically, and the merged process recovers successfully on its own.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe a merged core file in the /shared/core/ directory.
  • In the /var/log/daemon.log file, you observe a log message similar to the following example:

    emerg logger: Re-starting merged

  • In the /var/log/kern.log file, you observe a log message similar to the following example:

    merged[<pid>]: segfault at fed26ffc ip 000000000708eac2 sp 00000000fed29fd0 error 6 in merged[8048000+53000]
