K000152335: VELOS blades still in incorrect/old partition after assigning slots to a new partition

Type
Support Solution
Published
2025-07-02
Updated
2025-07-02
Applies to
  • F5OS
  • F5OS-C: 1.8.X, 1.6.X, 1.5.X, 1.8.1, 1.8.0, 1.6.2, 1.6.1, 1.6.0, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000152335

Description

Assigned VELOS blades to a new partition, after deleting a previous partition they were assigned to:

slots slot 1
 enabled
 partition partition02
!
slots slot 2
 enabled
 partition partition02
!

However, the blades still appear to be part of the old, deleted partition, when viewing the output of show cluster:

                                                          ABLE  ABLE                           
                                        IN       READY    TO    TO                PARTITION    
INDEX  NAME                   INSERTED  CLUSTER  CLUSTER  PING  SSH   STATE       LABEL        
-----------------------------------------------------------------------------------------------
1      blade-1.chassis.local  true      true     true     true  true  In Cluster  partition-1 
2      blade-2.chassis.local  true      true     true     true  true  In Cluster  partition-1
...

Environment

  • VELOS blades
  • OpenShift cluster

Cause

Bug ID 1962261: The controller-manager pods can enter CrashLoopBackOff due to expired API server certificate

Cluster age is greater than two years, when viewing the output of:

ls -l /var/omd/CLUSTER_INSTALLED

In addition, both controller-manager pods are observed to be in CrashLoopBackOff state when viewing the output of:

oc get pods --all-namespaces

The process list might show an oc delete project command appears to be hanging, when viewed with ps aux.

Recommended Actions

Perform an OpenShift rebuild to recover from this issue. For example, by following the procedure outlined in K64001020.
