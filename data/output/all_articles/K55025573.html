Description

F5 can create engineering hotfixes (also known as critical issue hotfixes) as documented in K4918: Overview of the F5 critical issue hotfix policy. Installation of engineering hotfixes is similar to that of hotfix rollups. Engineering hotfix installation is not changed after the F5 software release movement to the point release system.

It is mandatory to have also uploaded the matching version's base image to the Software Management > Image List section of the GUI in order to perform and Engineering hotfix (EHF) installation. Because an EHF cannot be applied to an already existing/active boot location, it must be installed simultaneously with the base image into a new boot location, therefore prior installation of the base OS is not required.

Environment

  • Engineering hotfix

Cause

None at time of publication.

Recommended Actions

When installing an engineering hotfix, the destination partition can be absent (installing to a new partition), it can hold a different major or minor release (overwriting old partition) or it can have the base release/hotfix/point release on which the engineering hotfix is based. Regardless of the state of the destination, the installation requirements for an engineering hotfix remain the same.

An engineering hotfix requires that the base image from which it is created to be present in the image files (located in /shared/images) along with the engineering hotfix image file. Examples of base image files are BIG-IP 11.5.4, 12.1.3, 13.1.1.5, and 14.1.0.1. BIG-IP 11.5.4 Hotfix Rollup 2 is not a base image. Even if an engineering hotfix is based on a hotfix rollup (for example 11.5.4 Hotfix Rollup 2), all that you need for installation of the engineering hotfix is the base image 11.5.4.

In the new Point Release system, a point release (formerly known as a hotfix rollup) now includes the full software to allow the point release image to install to a partition without needing a base image. An engineering hotfix based on a point release requires only the point release file. For example, an engineering hotfix based on 12.1.3.7 needs the base 12.1.3.7 file present along with the engineering hotfix image file, as 12.1.3.7 is considered the base.

For the installation to begin, you only need to select the corresponding EHF under Software Management > Hotfix List section of the GUI and click on Install... It will automatically find the corresponding base image and install them both. The rest of the upgrade process is exactly the same as when installing a base image alone.

For more information about engineering hotfixes, including installation instructions, refer to the following article:

  • K13123: Managing BIG-IP product hotfixes (11.x - 17.x)

Additional Information

Engineering hotfix images always require the base image because they are considered partial installation files and consequently need the base image to be present to complete an installation.
