Description

This article describes a scenario where configuration synchronization fails between BIG-IP DNS (GTM) devices within a sync group. Symptoms include:

  • Changes made on one GTM device are not reflected on peer devices.
  • WideIP objects and other configuration updates do not propagate across the cluster.
  • The show /gtm iquery command displays incorrect Server Type recognition ("BIGIP" instead of "BIGIP-DNS") for some cluster members.
  • Log entries show join/leave events for sync groups, but expected entries for affected devices may be missing. For example, the below 1.2.3.4 and 4.3.2.1 are the self IP of a demo DNS sync group device, but 1.2.3.4 is configured to a Generic Host address. It is expected to have "joined sync group" for the GTM device but there is only left message:
Nov 30 00:00:00 BIGIP-DNS-1.example.com alert gtmd[12345]: 011a5009:1: SNMP_TRAP: BIG-IP GTM /Common/gtm_dns_example (4.3.2.1) left sync group GTM_SYNC_GROUP
...
Nov 30 00:00:00 BIGIP-DNS-1.example.com alert gtmd[12345]: 011a5008:1: SNMP_TRAP: BIG-IP GTM /Common/general_host_example (1.2.3.4) joined sync group GTM_SYNC_GROUP

 

Environment

  • Product: BIG-IP DNS (GTM)

Configuration Related:
- A generic host object was configured with an address overlapping a device’s self IP.

Cause

The root cause is a configuration error: a generic host object was configured an address that overlaps with the self IP of one or more GTM devices. This overlap prevents the big3d process from sending proper DNS heartbeat packets, resulting in other cluster members failing to recognize the affected device as a GTM ("BIGIP" instead of "BIGIP-DNS"). This blocks configuration synchronization within the group.

Recommended Actions

  1. Modify the generic host object's address so it does not overlap with any device's self IP. Update the address in the Generic Host configuration for the concerned Generic to a unique, non-overlapping value(normally the related virtual server destination address).
  2. Restart DNS-related processes on all affected devices to refresh internal address mappings:
    bigstart restart gtmd big3d
    Note: This may temporarily disrupt GSLB resolution and cause health check flapping.
  3. Verify post-change status: 
    1. Use show /gtm iquery to confirm Server Type is "BIGIP-DNS" for all DNS members in the same sync group.
    2. Check tmsh list sys db gtm.peerinfototalgtms to ensure the correct number of GTMs is reflected in the cluster for each of the devices.
