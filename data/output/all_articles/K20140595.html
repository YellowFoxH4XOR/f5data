Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file and restart when processing wide-IP iRules commands.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP DNS device is configured with a wide IP that has pool-level persistence enabled and is configured with an iRule.
  • The iRule uses one of the following DNS iRules commands:
    • drop
    • discard
    • forward
    • noerror
    • reject
  • Traffic is processed by the wide IP iRule, resulting in the iRules command being executed.

Impact

If the BIG-IP DNS device is a member of a sync-failover group, traffic fails over to a BIG-IP DNS peer device. If the BIG-IP DNS device is not part of a sync-failover group, traffic is interrupted while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP DNS system generates a TMM core file to the /shared/core directory.
  • The BIG-IP DNS system fails over a peer device in the device group.

Workaround

To work around this issue, you can disable persistence on the wide-IP configured pool. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure disables persistence on the affected wide IP.

  1. Log on to the Configuration utility.
  2. Navigate to DNS > GSLB > Wide IPs > Wide IP List.
  3. Click the name of the affected wide IP.
  4. Click the Pools tab.
  5. For Persistence, click Disabled.
  6. Click Update.
