Known Issue

Description

Adding a tagged VLAN to a channel using the vlan-tag command will also erroneously add an untagged VLAN entry using the same VLAN ID.

This issue occurs when the following condition is met:

  • The vlan-tag command is used to add a tagged VLAN to a channel

Impact

The system may not process VLAN traffic as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The show running config command displays a tagged and untagged VLAN using the same VLAN ID that appears similar to the following:

    ;================================ channel ================================
      channel 1
        members 1/2
        spanning-tree shutdown
        vlan 19
        vlan 20
        vlan-tag 19
        vlan-tag 20
        exit
  • If multiple untagged VLANs are erroneously configured, any untagged VLANs listed after the first untagged VLAN will fail to load and the system logs an error similar to the following to syslog:

    :CLI-0-ERR-CHANNEL_ALREADY_IN_UNTAG_VLAN:: Channel 1 is already configured for untag VLAN 20.

Workaround

To work around this issue, you can remove the erroneously-added untagged VLAN. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enable configuration mode by typing the following command:

    config
  4. Enable the channel configuration mode for the desired channel using the following command syntax:

    channel <channel #>

    For example:

    channel 1
  5. Remove the unwanted, untagged VLAN using the following command syntax:

    no vlan <VLAN ID>

    For Example:

    no vlan 20
  6. Exit the channel configuration mode and return to privileged mode by typing the following command:

    end

Supplemental Information

  • For information about the vlan-tag command, refer to the ARX CLI Reference Guide.
