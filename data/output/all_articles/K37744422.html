Topic

You should consider using this procedure under the following condition:

  • You want to specify the name of a violation in an iRule.

Description

When you configure iRules for the BIG-IP ASM system and want to specify a violation name in the iRules syntax, you should first identify the violation you want to reference and then verify the syntax for the violation name. The naming convention for built-in BIG-IP ASM violations is as follows:

The name starts with the word VIOLATION and contains uppercase words separated by underscores.

For example:

VIOLATION_ATTACK_SIGNATURE_DETECTED

To determine the violation name to use in an iRule, perform the following procedures:

Creating an iRule to log the violation name
Triggering the violation
Locating the violation name in the log files

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have identified the violation you want to reference.
  • You have access to the BIG-IP ASM Configuration utility.

Procedures

Creating an iRule to log the violation name

To determine the correct syntax for the violation name, you can create an iRule that logs the violation details to the local log files. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. Type a name for the iRule.
  5. In the Definition box, enter an iRule that appears similar to the following example:

    when ASM_REQUEST_DONE {
                    log local0. "ASM violation name: [ASM::violation names]"
    }

  6. Click Finished.
  7. Associate the iRule with the virtual server.

Triggering the violation

You can use a pen-test utility to trigger the violation. The following procedure uses the client URL (cURL) utility to trigger violations:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a host system, such as a Linux client, that has access to the BIG-IP ASM virtual server.
  2. Use a tool, such as the cURL utility, to trigger the specific violation.

    For example, the following syntax uses cURL to send a request to the BIG-IP ASM virtual server. Since cURL is a non-browser client, the request triggers an Attack signature detected violation:

    curl http://<virtual_server_addr>

    The following syntax uses cURL to send a request to the BIG-IP ASM virtual server without a required Host header. The request triggers an Attack signature detected violation, and an HTTP protocol compliance failed violation.

    curl -H "Host:" http://<virtual_server_addr>

Locating the violation name in the log files

After you have triggered the violation, you can review the log files and locate the violation name. The previous iRule logs the violation name to /var/log/ltm.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Change to the /var/log directory by typing the following command:

    cd /var/log

  3. Use a Linux utility, such as cat or grep, to locate the violation.

    For example, to view the ltm log file, type the following command:

    cat ltm

    To search the ltm log file for the violation, type the following command:

    grep -i violation ltm

  4. The following log entry indicates the names of two violations that were triggered by a request:

    tmm[25875]: Rule /Common/asm_violation <ASM_REQUEST_DONE>: ASM violation name: VIOLATION_HTTP_SANITY_CHECK_FAILED VIOLATION_ATTACK_SIGNATURE_DETECTED
