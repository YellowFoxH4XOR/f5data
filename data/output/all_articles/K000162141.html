K000162141: Unable to set BIG-IQ auto-failover HA with BIG-IQ DCD as a quorum

Type
Support Solution
Published
2026-08-27
Updated
2026-08-27
Applies to
  • BIG-IQ
  • F5 Distributed Cloud Services
Source
https://my.f5.com/manage/s/article/K000162141

Description

BIG-IQ is unable to set the auto-failover HA with the BIG-IQ DCD as a quorum, when you are trying to set it up again after breaking it before.

Environment

  • BIG-IQ
  • Auto-failover with BIG-IQ DCD as a quorum.

Cause

BIG-IQ CM after breaking the auto-failover still contains the information about previous configuration which would prevents to set the HA again with new BIG-IQ DCD.

Answer/Recommended Actions

Step 1: Reset all three nodes to standalone

Step 1.1: On Primary CM, Secondary CM, and Quorum DCD (bash, as root):

On BIG-IQ DCD:

touch /etc/corosync/corosync.conf

On BIG-IQ DCD, CM and secondary CM

ha_reset -f <local_discovery_IP>

Step 1.3: after running on each node, verify:

ha_corosync_monitor.sh -q

# Expected: Assigned role...:none

Step 2: Fix SELinux context (if ha_reset was previously run). Run on all three nodes before attempting HA setup again as a root in bash shell:

chcon system_u:object_r:system_conf_t:s0 /etc/sysconfig/iptables{,.save}
chcon system_u:object_r:system_conf_t:s0 /etc/sysconfig/ip6tables{,.save}

Step 3: Restart restjavad on the Primary CM

bigstart restart restjavad

note: wait for the GUI to become available.

Step 4: Rebuild HA with Auto Failover from the GUI

From the Primary CM GUI: System -> BIG-IQ HA -> Add Standby
Enter Secondary CM discovery IP and credentials
Select Auto Failover
Set up Quorum DCD
Click Add
Monitor progress in real time:

# On Primary CM:
tail -f /var/log/restjavad.0.log | grep -i "AddPeerTask\|quorum\|corosync\|failover"

# On all nodes:
watch -n 5 ha_corosync_monitor.sh -q
