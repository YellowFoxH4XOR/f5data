K000158770: "Permission Denied" When Logging In via TACACS+ After Upgrade from 1.7.x to 1.8.x

Type
Support Solution
Published
2025-12-26
Updated
2026-03-24
Applies to
  • rSeries Platforms
  • F5OS
  • rSeries 10000
  • F5OS-C: 1.8.X, 1.8.0, 1.8.2, 1.8.1
  • F5OS-A: 1.8.X, 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000158770

Description

After upgrading F5OS-A on rSeries appliances to version 1.8.x (e.g., 1.8.3), TACACS+ remote authentication may fail with the following symptoms:

  • Users cannot log in to the web GUI using TACACS+ credentials
  • CLI access with the root account remains functional
  • "Permission denied" errors appear when attempting GUI login
  • Packet captures show no TACACS+ authentication traffic sent to the external server when a local user with the same username exists
  • After removing duplicate local users, authentication requests reach the TACACS+ server but users are still denied access

Error messages in logs "/var/log/secure" may include:

pam_unix(password-auth:auth): authentication failure

reject rc 1, user '<username>' Not Authenticated

Environment

  • TACACS+ configured
  • TACACS+ authentication

Cause

This issue has two potential root causes:

  1. Duplicate Username Conflict: When a local user exists with the same username as a remote/TACACS+ user, F5OS 1.8.x and above prioritizes local authentication and does not send authentication requests to the external TACACS+ server. This is by design in F5OS 1.8.x and above as a security fix introduced in Bug ID 1332781.
  2. Missing F5OS Vendor-Specific Attributes: If the local user is removed and remote authentication is attempted, the TACACS+ server (e.g., Cisco ISE) must return required F5OS vendor-specific attributes in its authorization reply. If only standard attributes (e.g., priv-lvl=15) are returned without F5OS-specific attributes, the user is mapped to the "nobody" group with no privileges, resulting in "Permission denied" errors.

Recommended Actions

  1. Remove Duplicate Local Users

    a. Identify any local users that have the same username as remote TACACS+ users.
    b. Delete local user accounts that should be authenticated remotely via TACACS+.

CLI Example:

config system aaa authentication users user <username> delete commit

WebUI:

Navigate to System > User Management > Users and delete the conflicting local user.

  1. Configure TACACS+ Server to Return Required F5OS Vendor-Specific Attributes

Ensure your TACACS+ server (e.g., Cisco ISE) is configured to return all required F5OS vendor-specific attributes in the authorization reply. At a minimum, the following attributes must be included:

    • F5-F5OS-UID (e.g., 1001)
    • F5-F5OS-GID (e.g., 9000 for admin, 9001 for operator)
    • F5-F5OS-HOMEDIR (e.g., /tmp)
    • F5-F5OS-USERINFO (optional user information)
    • F5-F5OS-SHELL (optional; typically ignored)

Example TACACS+ Configuration (tac_plus.conf):

group = admin_group {
    service = ppp protocol = ip {
        default attribute=permit
        F5-F5OS-UID=1001
        F5-F5OS-GID=9000
        F5-F5OS-HOMEDIR=/tmp
        F5-F5OS-USERINFO=admin_user
    }
}

user = tacacs_user {
    global = cleartext "password"
    member = admin_group
}

For Cisco ISE:

Configure the TACACS+ profile to include the required attributes. In the TACACS+ Profile configuration, switch to Raw View and add:

F5-F5OS-UID=1001

F5-F5OS-GID=9000

F5-F5OS-HOMEDIR=/tmp

Refer to KB article K000136131 for detailed step-by-step instructions on configuring Cisco ISE for F5OS TACACS+ remote authentication.

 

  1. Verify Configuration
    1. After making the above changes, test login via the web GUI.
    2. Confirm that users are authenticated successfully and assigned the correct roles.
    3. Review logs in /var/log/secure to verify successful authentication and authorization.

Expected log entries for successful authentication:

pam_authenticate succeeded

tac_author_read_timeout: args cnt <number>

tac_author_read_timeout: adding buf/value pair F5-F5OS-UID <value>

tac_author_read_timeout: adding buf/value pair F5-F5OS-GID <value>

tac_author_read_timeout: adding buf/value pair F5-F5OS-HOMEDIR <value>

Additional Information

  • Behavior Change in F5OS 1.8.x: The security fix introduced in Bug ID 1332781 prevents remote authentication when a local user with the same username exists. This is expected behavior to prevent authorization bypass vulnerabilities.
  • Group ID Mapping: The F5-F5OS-GID attribute must match valid F5OS group IDs:
    • 9000 = admin (read/write access)
    • 9001 = operator (read-only access)
    • 9100 = tenant-console
    • Other partition-specific GIDs (9101-9108)
  • Insufficient Attributes: If only "priv-lvl=15" is returned by the TACACS+ server without F5OS vendor-specific attributes, users will be mapped to the "nobody" group (GID 99) and denied access.
  • Password Considerations: If both local and remote users exist with the same username but different passwords:
    • Logging in with the TACACS+ password will fail
    • Logging in with the local password will succeed as a local user with local permissions
  • Trailing Whitespace Issue: If you encounter GUI login failures specifically related to trailing whitespace in the F5-F5OS-HOMEDIR attribute after upgrading to F5OS 1.8.0, refer to K000156626.
