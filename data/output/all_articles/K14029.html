Known Issue

When the Maximum Entries RAM Cache option is set to 0 for unlimited entries, the BIG-IP system will fail to cache HTTP responses, and may cause a TMM failure.

This issue occurs when all of the following conditions are met:

  • You have enabled RAM Cache in an HTTP profile and the Maximum Entries parameter is set to 0.
  • You have assigned the HTTP profile to a virtual server.

Impact

The system will continue to process traffic, but it will not cache responses. The BIG-IP system may also experience an unexpected TMM failure and subsequent failover to the standby host.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system will not cache responses and the RAM Cache entry table for that profile will be empty.
  • The system will log an error message to the /var/log/ltm file that appears similar to the following example. This message appears when the HTTP profile is initialized either at system boot or when the HTTP profile is first associated with a virtual server:

    local/tmm err tmm[4936]: 01300001:3: RAMCACHE Initialize - Not enough memory available to create the cache. Please try reducing the cache size and max entries
  • You may encounter TMM core files in the /var/core directory.

Workaround

To work around this issue, you can set the Maximum Entries option to a high number, such as 999999999, which is virtually equivalent to a setting of 0, the value that denoted an unlimited number of entries. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility as an administrator.
  2. Navigate to Local Traffic > Profiles > Services > HTTP.
  3. Select the HTTP profile you want to modify.
  4. Under the RAM Cache section, change the Maximum Entries option to 999999999.
  5. Click Update.
