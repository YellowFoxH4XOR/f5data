Known Issue

This is the result of a known issue. BIG-IP systems with virtual servers using Secure Sockets Layer (SSL) profiles and SSL session caching may experience Traffic Management Microkernel (TMM) panics accompanied by the following assert message:

../modules/hudfilter/ssl/ssl_session.c:682: Assertion "unlinked" failed.

This issue occurs on Clustered Multiprocessing (CMP) platforms when the SSL session cache drops a reference to a session owned by another TMM instance.

Note: Beginning in BIG-IP 10.1.0, the SSL session cache is shared across multiple TMM instances on CMP systems.

F5 Product Development tracked this issue as CR134940 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around the issue by disabling SSL session caching for all virtual servers referencing an SSL profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select Client or Server from the SSL drop-down menu, depending on if you have clientssl or serverssl profiles using SSL session caching.
  4. Click the profiles that are using session caching.
  5. Select Advanced from the Configuration drop-down menu.
  6. Enter 0 (zero) for the Cache Size setting to disable SSL session caching.
  7. Click Update.

Note: Repeat this procedure for all SSL profiles configured for SSL session caching.
