Known Issue

iRules that use sideband connections may leak memory.

This issue occurs when all of the following conditions are met:

  • An iRule uses a sideband connection command (connect).

    For example:

    when CLIENT_ACCEPTED {
        set conn_id [connect 10.10.10.10:80]
        close $conn_id
  • The virtual server associates with the iRule.
  • The client is connected to the virtual server.

Each time an iRule processes the connect command, the amount of memory allocated to the Traffic Management Microkernel (TMM) increases. This behavior may eventually cause the TMM process to exit.

Impact

TMM memory may eventually be exhausted and may result in a system core. If the system is configured as part of a high-availability (HA) pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H423273 on the Diagnostics > Identified > High page.
  • The BIG-IP system becomes unresponsive or fails over to another system in the device group.
  • TMM exits and generates a core file in the /shared/core directory.
  • The TMM memory usage graph constantly grows.

Resolution

Workaround

None. However, you can mitigate the issue by rewriting your iRule to remove any sideband commands.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure that modifications are compatible with your environment.
