Description

The console port on your rSeries / VELOS device is not functioning in one of the following ways:

  • No output on the terminal emulator when powering on the device.
  • AOM prompt (--- Press ( for AOM Command Menu) appears but does not respond to keystrokes.
  • Unable to access the AOM Command Menu via Esc + ( or Alt + (
  • Text appears scrambled/illegible, but there is output.

Environment

  • rSeries
  • VELOS

Cause

If you see garbled/scrambled text rather than no output at all, this indicates a baud rate mismatch - try 9600, 38400, or 115200. For more details, see Connecting to the serial console on the rSeries and VELOS

If you see no output at all - this could indicate a different problem, including a hardware defect.

Answer/Recommended Actions

Before you attempt to troubleshoot further, attempt to connect with a known good cable which has been confirmed as functional by connecting to the console port of another device if one is available. This cable needs to be a RJ45-to-DB9 serial console cable, or an RJ45F-to-RJ45M rolled adapter with a CAT5 cable to connect to the console port.

Step 1: Attempt to Access the AOM Menu

Even if the host OS is not booting, the AOM (Always-On Management) subsystem should respond on the console port. Use Esc + ( to invoke the AOM Command Menu (hold the Esc key while simultaneously pressing Shift and the 8 or 9 key for ( depending on your keyboard layout). If the AOM menu appears, the console port hardware itself is functional.

If the AOM menu is accessible:

  • Press B to verify/adjust the baud rate.
  • Ensure your terminal emulator matches the configured baud rate.
  • Press I from the AOM menu to display platform information.
  • Press Esc + D from within the AOM menu to run diagnostics (outputs System Event Logs and diagnostic data).

If the AOM menu is not accessible: Proceed to Step 2.

Step 2: Full Power Cycle

Power the device completely down, physically unplug both PSU power cables from the rear, wait 1–2 minutes, then reconnect and power back on.

If after the above steps the console port remains completely unresponsive at all baud rates with a confirmed good cable and no AOM response, contact F5 Support for further assistance and potential replacement.

If you are having issues with console port access and have collected AOM diagnostics files - please provide this data to F5 Support when opening a service request.
