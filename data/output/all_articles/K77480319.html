Description

Two vCMP guests running on separate physical hosts are found to be using the same MAC address:

show /sys mac-address
------------------------------------------------------------------------------------------------------------
Sys::MAC Address
Entry                      Component                 Object-ID                      Property
------------------------------------------------------------------------------------------------------------
...
 2:1:23:45:0:a             net vlan                  /Common/Internal               mac_true
 2:1:23:45:0:a             net vlan                  /Common/External               mac_true
 2:1:23:45:0:a             net vlan                  /Common/HA                     mac_true
 2:1:23:45:0:a             net interface             0.11                           mac_addr
 2:1:23:45:23:fe           net vlan                  /Common/tmm_bp                 mac_true

MAC address in question is 02:01:23:45:00:0a, and is not derived from the guest's base MAC address (base MAC address not shown in the above example).

Environment

  • vCMP
  • MAC addressing

Cause

MAC address is derived from tmm_bp, and this behaviour is present due to this db key setting on the guests:

sys db vlan.macassignment {
    default-value "unique"
    scf-config "false"
    value "vmw-compat"                      <---
    value-range "global unique vmw-compat"
}

The value of vmw-compat should only be used on VE, and never used on a vCMP guest.

This issue might happen if a UCS file sourced from a VE was loaded to a vCMP guest.

Recommended Actions

Execute the following sequence of commands on the affected systems:

tmsh mod sys db vlan.macassignment value unique

tmsh mod ltm global-settings general share-single-mac unique && tmsh save sys config

reboot

Additional Information

For more information about MAC assignment and sys db vlan.macassignment, refer to:

  • K14513: MAC address assignment for interfaces, trunks, and VLANs (11.x and later)
