Known Issue

This is the result of a known issue. On the initial load of RAM Cache-enabled HTTP profiles, the mcp process attempts to validate whether the resulting new total RAM Cache memory size will exceed the maximum allowed total RAM Cache memory size. However, this validation occurs before the size of the new RAM Cache store is known. As a result, an invalid configuration may be loaded initially, then fail to load upon update.

When a RAM Cache-enabled HTTP profile is modified, the mcp process revalidates the total RAM Cache memory size. If the total RAM Cache memory size exceeds the maximum allowed total RAM Cache memory size, the profile being updated is disabled, along with its RAM Cache memory store. When this behavior occurs, any subsequent traffic traversing the virtual server may cause TMM to crash.

F5 Product Development tracked this issue as CR139057, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
