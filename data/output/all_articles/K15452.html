Known Issue

If a FastL4 any:any virtual server overlaps with a Point-to-Point (PPTP) virtual server, it is possible that the Traffic Management Microkernel (TMM) will match the wrong flow during PPTP initiation and fail.

This issue occurs when all of the following conditions are met:

  • You have a FastL4 any:any virtual server.
  • You have virtual server configured with a PPTP profile.
  • You initiate a PPTP connection to the PPTP virtual server.

Impact

The BIG-IP system may temporarily fail to process traffic and fail over if configured as part of a high availability system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H473336 on the Diagnostics > Identified > Medium|High screen.
  • The TMM process fails and produces a core file in the /var/core directory.

Workaround

To work around this issue, you can create a reject virtual server that will exclude PPTP GRE traffic from the any:any FastL4 virtual server.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Enter the traffic management shell (tmsh) by typing the following command:

    tmsh

  3. Create the reject virtual server by typing the following command:

    create ltm virtual gre.trap destination 0.0.0.0:34827 profiles add { fastL4 } ip-protocol gre reject

    Note: Port 34827 is the value TMM uses to indicate that this is a PPP (PPTP GRE) flow.

  4. Save the configuration by typing the following command:

    save sys config
