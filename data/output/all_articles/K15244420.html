K15244420: Remote Desktop resource in Route Domain failed to connect

Type
Support Solution
Published
2025-07-01
Updated
2025-07-01
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K15244420

Description

  • Configuring a Remote Desktop resource in a different Route Domain than the APM Virtual Server
  • When trying to connect users immediately get connection error message
  • Error messages in /var/log/apm:

    Dec  2 13:10:09 example.bigip notice vdi[13023]: 019c0001:5: /<Partition>/<Access_Polciy_Name>:<Partition>:<sessionID>: Starting RDP 'Desktop' from resource '/<Partition>/<RD_Resource_Name>'
    Dec  2 13:10:23 example.bigip notice vdi[13023]: 019cffff:5: (null)::<sessionID>: {733c.S} Operation '' failed, error: 'unspecified'
    Dec  2 13:10:23 example.bigip notice vdi[13023]: 019cffff:5: (null)::<sessionID>: {733c.S} Error reported for an outgoing connection
    Dec  2 13:10:23 example.bigip notice vdi[13023]: 019cffff:5: (null)::<sessionID>: {733c.S} Failed to connect to RDG target <targetIP>:3389: system:111: Connection refused
     

Environment

  • BIG-IP with APM provisioned
  • The Remote Desktop resource is configured with an IP on a different Route Domain than the APM Virtual Server
  • Access Policy contains a "Route Domain and SNAT Selection" VPE object pointing to the target Route Domain and SNAT "automap"
  • APM Virtual Server is configured with a "Source Address Translation" set to "SNAT" and a SNAT pool

Cause

ID 791477.
If the APM Virtual Server is configured with a "Source Address Translation" set to "SNAT", the SNAT setting in  the "Route Domain and SNAT Selection" VPE object does not get applied and no outbound traffic from the BIG-IP to the target host on port tcp3389 is observed.

Recommended Actions

Set "Source Address Translation" on the APM Virtual Server to "Auto Map".
