Known Issue

This is the result of a known issue. If external monitors that fork other processes are configured, the big3d process may not kill the child processes belonging to monitor instances that have timed out. When these monitors are configured to monitor a large number of virtual servers or hosts, it is possible for the orphaned child processes to consume all available file handles. When this behavior occurs, error messages that appear similar to the following example are written to the /var/log/gtm file:

big3d[1168]: 0133200c:3: ExtMonitor /usr/bin/monitors/<MonitorName> read error Resource temporarily unavailable

Note: The name of the configured monitor experiencing the resource contention will be inserted in place of <MonitorName>.

In some cases, the big3d process may repeatedly restart and dump core.

F5 Product Development tracked this issue as CR121876 and it was fixed in BIG-IP 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You may be able to work around this issue by replacing the external monitors with an alternative monitor.
