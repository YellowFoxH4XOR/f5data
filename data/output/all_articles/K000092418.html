K000092418: Recover the root user password on RAID-capable BIG-IQ device

Type
Support Solution
Published
2022-10-05
Updated
2022-10-05
Source
https://my.f5.com/manage/s/article/K000092418

Description

  • You want to gain access to CLI or SSH but you don't have root or other user credentials

Environment

  • BIG-IQ v8.x.x
  • Raid file system
  • Grub v2.0
  • no root access
  • no CLI or SSH access

Cause

You do not have SSH or CLI for root or other users

 Recommended Actions

1. Reboot the device until you see your Grub 2.0 menu

2. Boot into TMOS maintenance from your GRUB 2.0 menu

3. Run tmidiag -m to get the /dev/md? location of the /var and /config for the current active volume

EXAMPLE: Current active volume is MD1.2

info: MultiDisk summary

cpmirror.app.biq.set.1.biqdata : /dev/md16  -> /dev/vg-db-sda/mdm.app.biq.set.1.biqdata, /dev/vg-db-sdb/mdm.app.biq.set.1.biqdata

cpmirror.app.biqucs.dat.biqucs : /dev/md17  -> /dev/vg-db-sda/mdm.app.biqucs.dat.biqucs, /dev/vg-db-sdb/mdm.app.biqucs.dat.biqucs

cpmirror.dat.log  : /dev/md2  -> /dev/vg-db-sda/mdm.dat.log, /dev/vg-db-sdb/mdm.dat.log

cpmirror.dat.share  : /dev/md1  -> /dev/vg-db-sda/mdm.dat.share, /dev/vg-db-sdb/mdm.dat.share

cpmirror.dat.swapvol : /dev/md3  -> /dev/vg-db-sda/mdm.dat.swapvol, /dev/vg-db-sdb/mdm.dat.swapvol

cpmirror.set.1./  : /dev/md4  -> /dev/vg-db-sda/mdm.set.1.root, /dev/vg-db-sdb/mdm.set.1.root

cpmirror.set.1./config : /dev/md6  -> /dev/vg-db-sda/mdm.set.1._config, /dev/vg-db-sdb/mdm.set.1._config

cpmirror.set.1./usr  : /dev/md5  -> /dev/vg-db-sda/mdm.set.1._usr, /dev/vg-db-sdb/mdm.set.1._usr

cpmirror.set.1./var  : /dev/md7  -> /dev/vg-db-sda/mdm.set.1._var, /dev/vg-db-sdb/mdm.set.1._var

cpmirror.set.2./  : /dev/md8  -> /dev/vg-db-sda/mdm.set.2.root, /dev/vg-db-sdb/mdm.set.2.root

cpmirror.set.2./config : /dev/md10  -> /dev/vg-db-sda/mdm.set.2._config, /dev/vg-db-sdb/mdm.set.2._config <-----!!!!!!

cpmirror.set.2./usr  : /dev/md9  -> /dev/vg-db-sda/mdm.set.2._usr, /dev/vg-db-sdb/mdm.set.2._usr

cpmirror.set.2./var  : /dev/md11  -> /dev/vg-db-sda/mdm.set.2._var, /dev/vg-db-sdb/mdm.set.2._var <-----!!!!!!

 

4. From the output above your config is mounted to md10 while var is on md11. Copy the output to your notepad for reference.

 

5. Reboot the device again to enter single user mode

 

While starting, the BIG-IP system displays the GRUB menu and counts down before continuing the start process.

 

Before the countdown expires, use the arrow keys to stop the countdown and select the appropriate boot image.

 

6. Press the E key to edit the start options.

 

A new GRUB menu displays.

 

7. Press the arrow keys to select the line that begins with:

kernel /boot/<boot location>/vmlinuz

 

7. Press End or the Right arrow to go to the end of line.

 

8. Type the word rd.break at the end of the kernel /boot/<boot location>/vmlinuz line and delete console=ttyS0

 

Depending on the platform, the boot command may appear similar to the following example:

kernel /boot/1/vmlinuz ro root=UUID=7237fa64-e347-4bb7-a755-6e2617bd7c0e console=ttyS0 panic=1 platform=D113 <default_cpu_order quiet> rd.break

 

9. Press ctrl+x to boot 

10. After the boot sequence completes, the following command-line prompt appears:

 

switch_root:\#

 

11. Next, mount the /sysroot/config and /sysroot/var partitions using the following command:

 

  Depending on the platform, the mount command may appear similar to the following example as per example on step #3:

 

mount /dev/md11 /sysroot/var

 

mount /dev/md10 /sysroot/config

 

12. For any partitions mounted as "ro" that means that they are in read-only mode, you have to re-mount them to read-write mode first.

    

For example, to re-mount the /sysroot and the /sysroot/usr partitions to Read-Write mode first, use the following commands:

 

mount -o remount,rw /sysroot

 

mount -o remount,rw /sysroot/usr

 

13. Change the root file system to /, type the following command:

 

chroot /sysroot

 

When you use chroot command, the command prompt will change to display as follows:

 

sh-4.2#

 

14. Change root password using the passwd command and you enter the new password twice.

 

passwd root

 

15. After keying in the new root password, force SELinux to relabel context on next boot, type the following:

 

touch /.autorelabel

 

16. Enter 'exit' twice to allow the system to boot as normal.
