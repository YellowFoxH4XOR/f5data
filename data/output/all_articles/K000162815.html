K000162815: Traffic is not reaching the HTTPS nodes

Type
Support Solution
Published
2026-08-27
Updated
2026-08-27
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162815

Description

You may observe the situation where you can't access the particular application. The client-side TLS handshake failed because BIG-IP returned a fatal handshake-failure alert before traffic reached the backend pool.

You may observe similar output in Packet Capture:

  1. 5 0.000181 2026-08-06 07:20:37.978778 10.10.30.100 41104 10.10.10.10 TLSv1.2 508 0 IN s1/tmm0 : Client Hello (SNI=big-ip.com)
  2. 6 0.000071 2026-08-06 07:20:37.978849 10.10.10.10 443 10.10.30.100 TLSv1.2 238 0 OUT s1/tmm0 : Alert (Level: Fatal, Description: Handshake Failure)

Environment

  • BIG-IP
  • HTTPS Virtual Server

Cause

The client SSL profile was misconfigured, causing BIG-IP to reject the client-side TLS handshake with a fatal handshake-failure alert. If you set the no-tls option in Client-SSL profile, the Virtual Server will reject every TLS connections.

ltm profile client-ssl /Common/client_SSL {
options { dont-insert-empty-fragments no-tlsv1.3 no-tlsv1.1 no-tls no-dtlsv1.2 }
}

Answer/Recommended Actions

  1. Correct the client SSL profile settings to match the requirements of the connecting clients and application.
  2. Test the HTTPS virtual server after any SSL-profile changes and confirm successful TLS negotiation.
