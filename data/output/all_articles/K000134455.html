Description

GUI shows error code 502 "message: upstreams unavailable" after NMS Installation

Environment

  • NGINX Management Suite (NMS)

Cause

NMS processes were not started properly.

Recommended Actions

Use the following procedures to troubleshoot and gather diagnostic information.

  • Restart NMS services
  • Temporarily set SELinux policy to permissive
  • Gather diagnostic information

Restart NMS services

Impact of procedure: Restarting services will cause NMS to become unavailable until services are fully restarted.

  1. Log in to the command line of the NMS host system.
  2. Restart the NMS services using the following command:

    sudo systemctl restart nms --now

  3. Confirm that NMS services are all active, using the following command:

    sudo systemctl status nms* --lines=0

    You can omit the --lines=0 portion of the command to return the corresponding lines from journalctl.

  4. Attempt to access the GUI again to see if the 502 message persists.

Temporarily set SELinux policy to permissive

If you are using SELinux, you can temporarily set the mode to permissive to determine whether policy is preventing NMS from starting correctly.

SELinux permissive mode is used for debugging and for policy development and will not enforce policy, but will log any denials. For more information about modes, refer to the SELinux Project Guide/Mode page.

Note: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.

For more information about configuring SELinux with NMS, refer to the Configure SELinux page.

Impact of procedure: This procedure reboots the host system and should be performed during a maintenance window.

  1. Log in to the command line of the NMS host system.
  2. Edit the /etc/selinux/config file using your preferred text editor. For example:

    sudo vi /etc/selinux/config

  3. Change the value of SELINUX to permissive. For example:

    SELINUX=permissive

  4. Save your changes and exit the text editor. Using the vi editor example, you can do so by typing the following key sequence:

    esc :wq

  5. Reboot the host system
  6. After the system has rebooted, log back in and confirm the SELinux mode using the following command:

    sestatus

    The Current mode should appear similar to the following example:

    SELinux status: enabled
    SELinuxfs mount: /sys/fs/selinux
    SELinux root directory: /etc/selinux
    Loaded policy name: default
    Current mode: permissive
    Mode from config file: permissive
    Policy MLS status: enabled
    Policy deny_unknown status: allowed
    Memory protection checking: requested (insecure)
    Max kernel policy version: 31

  7. Attempt to access the GUI again to see if the 502 message persists.

Gather diagnostic information

If the issue still persists, collect the following diagnostic information for review. For more information, refer to K2633: Submit a support case.

Impact of procedure: Performing the following procedure should not have an impact on your system.

  1. Get the current systemctl status of the NMS services, using the following command:

    systemctl status nms* > /var/tmp/nms-service-status.txt

  2. Get the current ps status of the NMS services, using the following command:

    ps aufx | grep nms > /var/tmp/nms-ps-status.txt

  3. Collect diagnostic information from your system, using the support-package.sh script:

    cd /var/tmp/ && sudo bash /etc/nms/scripts/support-package.sh

    Note: For more information about the support-package.sh script, refer to the Create a Support Package page.

  4. Collect the following files and contact F5 support:

    /var/tmp/nms-service-status.txt
    /var/tmp/nms-ps-status.txt
    /var/tmp/support-pkg-<timestamp>.tar.gz
