Known Issue

Shifting traffic patterns may cause Datastor to exit and restart.

This issue occurs when all of the following conditions are met:

  • TCP request queueing is enabled in the pool configuration.
  • The BIG-IP AAM system experiences high load.
  • Traffic with varied velocities cause objects in Datastor to become corrupted or deleted.
In rare circumstances, traffic patterns with changing velocities may lead to Datastor corruption that causes the datastor daemon to restart. This issue is exacerbated when the value for the Cache Size setting configured in the Web Acceleration profile is much smaller than the default value used in the optimized-acceleration profile. For example, the frequency of this issue increases if you modify the value for the cache size from its default of 6 GB to 10 MB.

Impact

The BIG-IP AAM system experiences a cache outage and you must completely reseed the cache. In addition, the datastor daemon generates a core file and restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP AAM experiences performance degradation.
  • BIG-IP AAM generates a datastor core file to the /shared/core/ directory.
  • Optimized connections experience latency.
