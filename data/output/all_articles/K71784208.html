DescriptionYou may see the "clsh" command fails silently when following K11333 to shut down or to restart one or more blades in a VIPRION system, or running the "clsh" command described in K16727 to execute a command on multiple blades simultaneously.

For example, you want to check the blade date by running "clsh date", but you get the output like below:

# clsh date
=== slot 2 addr 127.3.0.2 color green ===
=== slot 3 addr 127.3.0.3 color blue ===
=== slot 4 addr 127.3.0.4 color blue ===
=== slot 1 addr 127.3.0.1 color green ===

Or you want to use the "ssh slot<slot number>" command described in K07557518 to SSH into a specific slot, but you also failed.

Environment

  • VIPRION with multiple blades
  • SSHD not listening on the default port 22
  • SSH to a specific slot using "ssh slot<slot number>"
  • Unable to run "clsh" commands

Cause

The clsh and ssh slot command requires the SSHD listen on the default port 22, but you changed the default to another port.

Recommended Actions

To work around the issue, you can reconfigure the SSHD back to listen on the default port 22.

You can refer to the command below to change the listening port back to 22:

tmsh modify sys sshd port 22

Note: You can use the following command to check the current SSHD listening port "tmsh list sys sshd all-properties".

Alternative, you may use either of the below commands to ssh to another specific slot:

  • ssh -p <SSHD port> slot<slot number> 
  • ssh -p <SSHD port> 127.3.0.<slot number>

Note:  You can replace <SSHD port> with your configured port, for example, 50000. Then, run the command "ssh -p 50000 slot<slot number>" or "ssh -p 50000 127.3.0.<slot number>" from another slot.

For example, the SSHD is listening on the port 50000, and you want to ssh to slot 2 from slot 1, you may try "ssh -p 50000 slot2", or "ssh -p 50000 127.3.0.2".
