K000161828: Security Dashboard Configuration on NIM (Nginx Instance Manager)

Published

Source
https://my.f5.com/manage/s/article/K000161828

Description

NGINX Instance Manager (NIM) Security Dashboard and Security Monitoring features are visible, but no security metrics or WAF (App Protect) events are displayed. WAF Analytics APIs (/analytics/security/*) return no data or HTTP 500 errors. ClickHouse database tables for security events remain empty despite NGINX App Protect generating traffic.

Relevant log messages:

  • feature 'SECURITY-POLICIES' enforced by securityPolicyEnforcer
  • feature SECURITY-POLICIES requires valid license
  • feature ANALYTICS requires valid license
  • feature SECURITY-MONITORING requires valid license for user <user-id>

ClickHouse tables confirmed empty:

  • nms.v4_security_events
  • nms.v4_security_events_signatures_data
  • nms.v4_security_events_violation_data

Environment

  • Product: NGINX Management Suite – Security Monitoring module, version 1.6.0
  • Components: NGINX Instance Manager (NIM), NGINX Plus with App Protect WAF, nginx-agent, ClickHouse database
  • License features: NGINX_NAP, NGINX_NAP_DOS, IM_INSTANCES, NGINX_INSTANCES
  • Security Dashboard and Security Monitoring enabled in NIM
  • Syslog configured for WAF log collection
  • nginx-agent deployed on NGINX Plus instances and connected to NIM control plane

Cause

Misconfiguration of the nginx-agent and NGINX App Protect syslog settings, resulting in WAF security logs not being delivered to the nginx-agent's local listener and therefore not ingested into NIM or ClickHouse. Specifically:

  • The syslog_ip in nginx-agent.conf was pointing to an external rsyslogd server instead of the local NGINX Plus host IP where nginx-agent listens.
  • The nap-monitoring extension was missing or incorrectly named (using underscore nap_monitoring instead of hyphen nap-monitoring) in agent-dynamic.conf.
  • The app_protect_security_log directive in nginx.conf was writing logs to a local file instead of forwarding them to the nginx-agent syslog listener.
  • An incorrect or missing log profile (log_sm.json) was used for security monitoring.

Answer/Recommended Actions

Follow these steps to correctly configure NGINX App Protect security log forwarding to NIM via nginx-agent:

Step 1: Update /etc/nginx-agent/agent-dynamic.conf to include nap-monitoring under extensions

version: v2.44.0
tags:
- <your-tags>
extensions:
- nginx-app-protect
- nap-monitoring # Use hyphen, NOT underscore
queue_size: 100

Step 2: Update /etc/nginx-agent/nginx-agent.conf – configure nap_monitoring section

extensions:
- nginx-app-protect
- nap-monitoring
- advanced-metrics

nap_monitoring:
collector_buffer_size: 50000
processor_buffer_size: 50000
syslog_ip: "<IP address of the local NGINX Plus host>" # Must be the local host IP, NOT an external syslog server
syslog_port: 514

Note: For NAP v4 on bare metal: 127.0.0.1 is acceptable.
For NAP v5 (containerized): 127.0.0.1 cannot be used — use the docker0 interface address (typically 172.17.0.1) or the host's IP address.

Step 3: Verify the NIM control plane hostname is resolvable

server:
host: <NIM hostname or IP>
grpcPort: 443

Step 4: Create the security monitoring log profile on the NGINX Plus instance

Create /etc/app_protect/conf/log_sm.json as described in the official documentation:
Set up F5 WAF for NGINX instances for Security Monitoring

Step 5: Update nginx.conf – point app_protect_security_log to the nginx-agent syslog listener

# Primary: send to nginx-agent syslog listener → forwarded to NIM
app_protect_security_log "/etc/app_protect/conf/log_sm.json" syslog:server=127.0.0.1:514;

# Optional backup: keep a local file copy for manual inspection
app_protect_security_log "/etc/app_protect/conf/log_illegal.json" /var/log/app_protect/security.log;

Step 6: Restart the nginx-agent service

sudo systemctl restart nginx-agent

Step 7: Verify NIM is listening on the syslog port

sudo netstat -tulpn | grep 514

Step 8: Validate data ingestion

    • Generate test traffic through the WAF-protected application.
    • Check the NIM Security Dashboard for incoming events. Note that a slight delay between event generation and dashboard visibility is expected behavior.

    Additional Information

    • The nginx-agent acts as a middleman: it receives WAF syslog events locally on the NGINX Plus host and forwards them to NIM. Security logs must not be sent directly to an external rsyslogd server if the intent is to populate the NIM Security Dashboard.
    • The nap-monitoring extension name must use a hyphen (-), not an underscore (_), in agent-dynamic.conf. Using the wrong separator will prevent the extension from loading correctly.
    • A slight delay between WAF event generation and visibility in the NIM Security Dashboard is expected behavior.
