Description

When using High-Speed Logging (HSL) with an iRule in a BIG-IP cluster, logs are unexpectedly generated by both the active and standby units.

This behavior occurs even though the standby node is not actively processing traffic.

The issue manifests as duplicate log entries being sent to the remote logging server.

 

Environment

  • BIG-IP
  • HSL logging configured via an iRule.
  • Connection mirroring enabled on the virtual server.
  • Remote HSL log destination used for logging.

Cause

The root cause of this issue lies in the interaction between connection mirroring and the iRule's CLIENT_ACCEPTED event. When connection mirroring is enabled, connection and persistence information are replicated from the active unit to the standby unit. This replication triggers the CLIENT_ACCEPTED event on both units, causing logs to be generated by both devices.

 

Recommended Actions

To resolve this issue and ensure that only the active node generates logs:

 

1) Disable Connection Mirroring:

If connection mirroring is not required for your use case, disable it on the virtual server to prevent mirrored traffic from triggering events on the standby unit.

 

2) Modify iRule Logic:

Update your iRule to include a condition that checks whether the device is in an active state before sending logs. Use the HA::status command to determine if a device is active or standby.

More details you may find in below article:

HA::status

With above modifications you may add condition which ensures that only logs from the active unit are sent to the remote syslog server.
