Description

Attempted to deploy a tenant on F5OS-A rSeries platform, but deployment failed, with the following message:

Tenant deployment failed - Server is not responding

What is the root cause of this message?

How can we fix the problem and deploy tenants?

Environment

  • F5OS-A
  • Tenant deployment

Cause

This message has no single root cause, but typically means that there is an issue communicating with the Kubernetes API server.

Recommended Actions

You should first investigate /var/log/messages and /var/F5/system/log/platform.log to determine the exact nature of the communication problem.

This problem can occur if the system clock is off, for example. Kubernetes is particularly sensitive to time issues since certificates are used to authenticate with the API server.

You may observe a message like the following in /var/log/messages:

Unable to connect to the server: x509: certificate has expired or is not yet valid: current time 2000-01-07T00:11:27Z is before 2024-05-27T03:38:16Z

In this message, note the stated current time which is in the year 2000. This is incorrect.

In this instance, you should set the system time manually. This can be done in the GUI's Time Settings page. You should also configure NTP, ensuring that the NTP server is reachable and is a reliable time source.

After setting the system clock manually, check whether the hardware clock is also up to date:

hwclock --show

If the hardware clock is not in sync with the system clock, run:

hwclock --systohc

A reboot or power cycle is suggested at this point to verify that the system and hardware clocks maintain the correct time.

If the time is not maintained, open a case with F5 Support for investigation.

Additional Information

A k3s reinstall may be required after correcting system time issues.
