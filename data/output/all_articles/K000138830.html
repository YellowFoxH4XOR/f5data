K000138830: Troubleshooting port groups and interfaces on F5 rSeries and F5 VELOS systems

Issue

You should consider using this procedure under the following condition:

  • You want to troubleshoot port groups or interfaces on your F5 rSeries or F5 VELOS system.

Symptoms

As a result, you may encounter the following symptoms:

  • The operational status of an interface on your F5 rSeries or F5 VELOS system shows DOWN.
  • You are unable to establish a network link between your F5 system and the peer system.

Recommended Actions

F5 rSeries systems and F5 VELOS blades include front panel small form factor pluggable (SFP) ports to provide high-speed throughput. These front panel ports support port groups which allow you to specify the mode of the physical port. A mismatch between the port group configuration and the type of SFP transceiver can prevent a link from coming up for the interface. 

For r5000/r10000/r12000 series systems, you can specify the following modes for the ports in the port group configuration:

ModeDescription
100GbECreates a single interface at 100G speed.
40GbECreates a single interface at 40G speed.
25GbECreates a single interface at 25G speed.
10GbECreates a single interface at 10G speed.
4 x 10GbECreates four unbundled interfaces at 10G speed.

For F5 r2000/r4000 series systems, the following pre-defined port profiles are supported:

ModeDescription
4 x 25GbEConfigures each of the four SFP ports to run either 25G, 10G, or 1G speeds. The RJ45 ports are disabled.
4 x 10Gbe + 2 x 25GbEConfigures two of the SFP ports (5.0 and 6.0) to run either 25G, 10G, or 1G speeds, and each of the four RJ45 ports to run either 10G or 1G speeds. The other two SFP ports are disabled.
8 x 10GbEConfigures each of the eight ports (four SFPs and four RJ45) to run either 10G or 1G speeds (default).

For VELOS blades, the following modes are supported:

ModeDescription
400GbECreates a single interface at 400G speed on BX520 blades port 2.0.
4 x 100GbECreates four unbundled interfaces at 100G speed on BX520 blades (F5OS-C 1.8.1 and later).
100GbECreates a single interface at 100G speed.
40GbECreates a single interface at 40G speed.
4 x 25GbECreates four unbundled interfaces at 25G speed.
4 x 10GbECreates four unbundled interfaces at 10G speed.

When you configure the port group for an interface, you need to set the mode to match the speed and bundling for the transceiver you are using. Changing a port group mode forces the system to reboot and remove the stale interfaces from the configuration. On a F5 rSeries system, this means the appliance reboots. On a F5 VELOS system, the blade on which the port group resides reboots. Depending on the mode you selected, a different FPGA version is loaded and the system recreates the port group components.

When configuring port groups on F5 rSeries or F5 VELOS systems, consider the following:

  • For F5 VELOS BX520 blades, port 1.0 supports either 100Gb or 4 x 100Gb optics, and port 2.0 supports either 400Gb or 4 x 100Gb optics. For 4 x 100Gb support, both ports must be configured to use 4 x 100Gb.
  • For F5 r5000/r10000/r12000 series systems, the following adjacent high-speed ports need to be configured with the same speed and must be bundled (no breakout cables):
    • r5000 - ports 1.0 and 2.0
    • r10000 / r12000 - ports 1.0 and 2.0, and ports 11.0 and 12.0
  • For F5 VELOS systems running versions prior to F5OS-C 1.5.1, both front panel ports on a blade must be configured to use the same mode. You cannot mix different port group settings on the same blade. In F5OS-C 1.5.1 and later, more flexible options were introduced for mixing modes on the same blade. For more information, refer to VELOS Port Groups on F5 Cloud Docs.
  • F5 rSeries systems and F5 VELOS systems only support Forward Error Correction (FEC) CL108 or compatible on 25G interfaces. Peer network devices must be configured with this FEC mode (also known as RS_IEEE_FEC or RS_FEC_IEEE).
  • Only F5 branded SFP transceivers are supported. Supported speeds are 400G, 100G, 40G, 25G, 10G, and 1G, depending on the platform and transceiver. For more information about supported optics, refer to the following documentation:
    • rSeries Supported Optics on F5 Cloud Docs
    • VELOS Supported Optics on F5 Cloud Docs
  • Interface numbering
    • For rSeries systems, interface numbering begins with 1.0 and extends to the maximum number of available ports on the appliance. For example, r5900 systems have 10 ports which are numbered 1.0, 2.0, 3.0, etc, up to 10.0.
    • For VELOS systems, interfaces are numbered beginning with the blade number (<blade#>/<port#>). For example, the interfaces on blade 1 are numbered 1/1.0 and 1/2.0 and the interfaces on blade 2 are numbered 2/1.0 an d 2/2.0. When using breakout cables, the interface numbering for blade 1 will be 1/1.1, 1/1.2, 1/1.3, and 1/1.4 for the first port, and 1/2.1, 1/2.2, 1/2.3, and 1/2.4 for the second port.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have installed an SFP transceiver in your F5 system and connected it to a port on the peer device.
  • You have administrative access to the F5 rSeries or VELOS webUI and CLI.

Procedures

  • Check the status of the interface
  • Verify the type of SFP transceiver installed
  • Verify the configured port group mode
  • Check logs

Check the status of the interface

You can use the F5 rSeries or F5 VELOS chassis partition webUI or CLI to get information about an interface, such as the operational status (UP or DOWN), port speed, and whether it is enabled or not. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

webUI

  1. Log in to the F5 VELOS chassis partition webUI or F5 rSeries system webUI.
  2. Go to NETWORK SETTINGS > Interfaces.
  3. To view information about an interface, select the name of the interface.
  4. Verify the State of the interface is Enabled and the Operational Status for the interface is UP. If the State is Disabled, enable the interface by selecting Enabled for the State setting then selecting Save. If the interface is DOWN, continue to verify the type of SFP transceiver installed and the port group mode.

CLI

  1. Log in to the F5 VELOS chassis partition CLI or F5 rSeries system CLI as admin.
  2. To verify the status of an interface, enter the following command:

    show interfaces interface <interface#>

    In the above command, note the following:

    • <interface#> is the interface number on the F5 rSeries system or the F5 VELOS blade. For more information about interface numbering for F5 rSeries and F5 VELOS systems, refer to Interface numbering above.

    For example, the following partial output shows interface 1/1.0 on a VELOS system is UP and the port speed is 100G:

    interfaces interface 1/1.0
     state type               ethernetCsmacd
     state mtu                9600
     state enabled            true
     state oper-status        UP
     ethernet state port-speed SPEED_100GB

  3. Verify state enabled is true and state oper-status for the interface is UP. If state enabled is false, you can enable the interface. To do so, enter the following command to enter configuration mode. Otherwise, continue to step 6:

    config

  4. Enable the interface by entering the following command where <interface#> is the interface number:

    interfaces interface <interface#> config enabled

  5. Commit the change and exit configuration mode by entering the following command:

    commit and-quit

  6. If the interface oper-status is DOWN, continue to verify the type of SFP transceiver installed and the port group mode.

Verify the type of SFP transceiver installed

You can verify the type of SFP transceiver installed on a F5 rSeries and F5 VELOS system using the CLI. You can then compare the configured port group mode to the type of SFP transceiver to ensure it matches. To view details for the installed SFP transceiver, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5 VELOS chassis partition CLI or F5 rSeries system CLI as admin.
  2. To verify the type of SFP transceiver currently installed, enter the following command:

    show portgroups 

    The following example shows partial output for portgroup 1/1 which corresponds to interface 1/1.0 on the VELOS blade:

    portgroups portgroup 1/1
     state vendor-name      "F5 NETWORKS INC."
     state vendor-oui       009065
     state vendor-partnum   "OPT-0031        "
     state vendor-revision  A1
     state vendor-serialnum "1234567                "
     state transmitter-technology "850 nm VCSEL"
     state media            100GBASE-SR4
     state optic-state      QUALIFIED

    The output shows the installed optic is F5 branded and operates at 100G speed.

Verify the configured port group mode

You can check the configured port group mode for an interface using the webUI or CLI. The port group mode needs to match the speed and bundling mode of the installed SFP transceiver. To check the port group mode and change it to the correct setting, perform the following procedure:

Impact of procedure: Changing the port group mode for an interface causes the system to reboot and should be done during a maintenance window. For F5 rSeries the appliance reboots. For F5 VELOS systems, the blade containing the port group reboots. 

webUI

  1. Log in to the F5 VELOS chassis partition webUI or F5 rSeries system webUI.
  2. Go to NETWORK SETTINGS > Port Groups.
  3. Verify the port group mode for the interface. For example, if the configured port group is set to 40GbE for a 100GbE transceiver, there is a mismatch and the port group should be changed to be 100GbE. If there is a mismatch between the configured port group mode and the type of SFP transceiver, change the port group mode to the correct setting and select Save.
  4. A message pops up indicating the system will reboot. Select OK to proceed.

CLI

  1. Log in to the F5 VELOS chassis partition CLI or F5 rSeries system CLI as admin.
  2. To verify the port group mode, enter the following command:

    show running-config portgroups

    The following output shows both port group 1/1 is configured for 40G speed:

    portgroups portgroup 1/1
     config mode MODE_40GB
     config ddm ddm-poll-frequency 30
    !
    portgroups portgroup 1/2
     config mode MODE_100GB
     config ddm ddm-poll-frequency 30
    !

  3. If the configured port group mode is incorrect for the installed SFP transceiver, change the port group mode to the correct setting. For example, if the configured port group is set to MODE_40GB for a 100GbE transceiver, there is a mismatch and the port group should be changed to be MODE_100GB. To do so, enter the following command to enter configuration mode:

    config

  4. Change the port group mode using the following syntax where <portgroup#> is the port group number and <mode> is the port group mode, such as MODE_10GB or MODE_40GB:

    portgroups portgroup <portgroup#> config mode <mode>

    For example, to change portgroup 1/1 to be 100G speed, enter the following command:

    portgroups portgroup 1/1 config mode MODE_100GB

  5. Commit the change and exit configuration mode by entering the following command:

    commit and-quit

  6. A message appears indicating the system will reboot. Enter yes to continue.

 

Check logs

When troubleshooting downed interfaces, you can check the logs for any error messages related to the SFP transceiver or interface. Information about SFP transceivers and interface status are logged to the /varF5/system/log/platform.log file on F5 rSeries systems and the /var/F5/partition<#>/log/velos.log file on F5 VELOS systems. For example, messages similar to the following are logged when the interface on a VELOS blade comes up successfully:

100.65.17.1 blade-1(p1) fpgamgr[14]: priority="Notice" version=1.0 msgid=0x303000000000005 msg="Optic inserted" Portgroup="1/1" Vendor="F5 NETWORKS INC." PartNum="OPT-0036" Rev="04" Serial="BR5490S1".
100.65.17.1 blade-1(p1) fpgamgr[14]: priority="Notice" version=1.0 msgid=0x303000000000011 msg="FEC is configured" ifname="1/1" value="N/A".
100.65.17.1 blade-1(p1) fpgamgr[14]: priority="Notice" version=1.0 msgid=0x304000000000002 msg="DDM is supported by this optic." PORTGROUP="1/1" Vendor="F5 NETWORKS INC." PartNum="OPT-0036    " Rev="04".
100.65.17.1 blade-1(p1) fpgamgr[15]: priority="Info" version=1.0 msgid=0x309000000000002 msg="Updating interface link state" ifname="1/1.0" state="UP".

If any error messages appear, review them to see if they point to a cause. To troubleshoot, you can try removing the transceiver and installing it in a different port on the F5 rSeries system or F5 VELOS blade to see if the problem follows to the new port. You can try this both with the cable attached and with the cable detached. If you have another transceiver, you can try to swapping transceivers to see if the problem persists. You can also check the cabling or try installing a different cable.

To get more detailed log messages related to SFP transceivers or interfaces, you can enable Debug logging for the fpgamgr component before reproducing the issue. To enable debug logging for the fpgamgr component, perform the following procedure:

Impact of procedure: Performing the following procedure increases the number of messages logged and should only be used during troubleshooting. You should set the log level back to INFORMATIONAL once complete.

webUI

  1. Log in to the F5 VELOS chassis partition webUI or F5 rSeries system webUI.
  2. Go to SYSTEM SETTINGS > Log Settings.
  3. In the Software Component Log Levels section, locate the fpgamgr log setting. You may need to select Show on the right to display the components.
  4. Select DEBUG for the fpgamgr component.
  5. Select Save, then OK to accept the changes. 
  6. To set the log level back to the default setting, repeat steps 1 - 5 selecting INFORMATIONAL in step 4.

CLI

  1. Log in to the F5 VELOS chassis partition CLI or F5 rSeries system CLI as admin.
  2. Enter the following command to enter configuration mode.

    config

  3. To change the fpgamgr log level to DEBUG, enter the following command:

    system logging sw-components sw-component fpgamgr config severity DEBUG

  4. Enter the following command to commit the change and exit config mode:

    commit and-quit

  5. To set the log level back to the default setting, repeat steps 1 - 4 entering the following command in step 3:

    system logging sw-components sw-component fpgamgr config severity INFORMATIONAL
