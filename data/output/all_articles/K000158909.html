K000158909: How to re-allocate disk space from /shared/vmdisks to /shared on a VIPRION vCMP host slot

Type
Support Solution
Published
2025-12-24
Updated
2025-12-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000158909

Description

On VIPRION vCMP hosts, you may observe that /shared is smaller on one slot than on another and this can trigger a low-disk alarms. In certain scenarios, you may need to re-allocate disk space from /shared/vmdisks to /shared on a VIPRION vCMP host slot. 

 

Environment

  • BIG-IP LTM 
  • VIPRION chassis with multiple blades/slots
  • BIG-IP vCMP host (with multiple vCMP guests)

Cause

/shared partition has a smaller size on a specific slot and low space alarms are generated. 

 

Recommended Actions

Important: This procedure needs to be done in a schedule maintenance window that requires guest downtime. When reducing the size, it is always best to do it with the file system unmount. If not, there will be data corruption which is unrecoverable and can lead to system failing to boot. 

 

Follow the below steps to re-allocate certain disk space from /shared/vmdisk partition to /shared partition.

 

1. Backup all guests and change state of all guests to "Configured" status.

 

  • Take backup copies of all guests and save off the device
  • Set all guests to configured.

      tmsh modify vcmp guest all state configured

 

2. Console into the affected slot and enter single-user mode

  • Log in as a root
  • Stop BIG-IP services: 

       bigstart stop

 

  • Switch to single-user mode: 

       init 1

 

  • Remove the prompt to make it easy to enter commands via the console.

       umount /var/prompt

 

3. Unmount all /shared-related mount points:

 

  • Identify /shared-related mounts

       mount | grep share

 

  • Unmount in this order (as applicable)

       umount /shared/rrd.1.2

       umount /shared/vmdisks

       umount /shared

 

4. Verify LV sizes before resizing

 

  • Record current LV sizes

       lvdisplay | egrep "share|vcmp" -B1 -A14

 

5. Resize (shrink vmdisk LV first, then grow /shared)

 

  • Shrink the vmdisk by the required disk size

      lvresize /dev/vg-db-sda/app.vcmp.dat.vmdisks -rL -<disk size to shrink>

 

  • Increase /shared size

      lvresize /dev/vg-db-sda/dat.share.1 -rL +<disk size to reallocate>

 

  • Verify LV sizes after resizing

      lvdisplay | egrep "share|vcmp" -B1 -A14

 

6. Reboot the blade:

reboot

 

7. Redeploy guests after the slot returns

After the slot is back online, redeploy guests:

tmsh modify vcmp guest all state deployed
