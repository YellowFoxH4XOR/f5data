Description

 BIG-IP status OFFLINE after an upgrade. 

As a result, error messages similar to the following may be present in /var/log/ltm:

emerg load_config_files[25770]: "/usr/bin/tmsh -n -g -a load sys config partitions all gtm-only" - failed. -- Loading schema version: 13.1.0.8
err tmsh[14282]: 01420006:3: Can't find specified cli schema data for x.x.x.x             #  <---------  (x.x.x.x will indicate an older version of BIG-IP software)
err mcpd[4247]: 01070678:3: Full gtm configuration load failed ( Original ).
info install_ucs.pm[20163]: Configuration loading error: gtm-config-load-failed
info install_ucs.pm[20163]: ERROR: UCS installation failed.
err tmsh[20137]: 01110001:3: Error running config install
err tmsh[20137]: 01420006:3: UCS loading process failed.
...
err mcpd[4247]: 01070678:3: Full gtm configuration load failed.

Environment

  • BIG-IP DNS / GTM configuration (/config/bigip_gtm.conf)
  • Software Upgrade

Cause

The BIG-IP contains historical DNS (GTM) configuration from a previous version of BIG-IP software. This can happen if the BIG-IP system was previously provisioned for BIG-IP DNS / GTM, and then de-provisioned prior to the upgrade being carried out.

This issue is being tracked as bug ID837637

Recommended Actions

  1. Delete the GTM configuration file:
    rm /config/bigip_gtm.conf

  2. Restart services
    tmsh restart sys service all

Workaround

After deprovisioning the GTM module, delete (or rename) the GTM configuration file /config/bigip_gtm.conf, before starting the upgrade.
