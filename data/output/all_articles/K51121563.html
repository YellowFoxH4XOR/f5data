K51121563: SSO to Citrix Xenapp farm failed for some users while other users part of same domain did not have this issue.

Type
Support Solution
Published
2019-08-07
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.1.1
Source
https://my.f5.com/manage/s/article/K51121563

Description
APM was used in replacement mode (Webtop replaced Storefront).
In working condition the published Apps on Xenapp for for that client should be presented on the Webtop once the client logs in.
However in this case after logging in, client did not get the published Apps, instead it showed same of the Citrix VDI resource configured on APM and when clicking it SSO failed with the following error : 

#####
/Common/ExamplePolicy
Logon to your resource failed. Please click the Try Again button to try again or Close button to close this dialog.
Show additional information
ErrorId (failed-credentials), BrowserError (None), MPSError (None), RemedyHint (None)
#####

Issue was for only some users, after they login and get APM webtop the Citrix published resources has SSO failing.
For others users it worked fine.
All the users (working and non-working were part of the same domain and followed the same branch to have resource assigned in the Access policy.
 

Environment

  • 13.1.1.2
  • BIG-IP APM in Replacement mode (no Storefront) integrating with Xenapp farm

Cause
For working user the Radius server never presented a challenge and replied with a access-accept soon after the access-request from APM.

For non working user the Radius server sent Radius challenge, user is prompted with logon page to enter the verification code received via SMS, session variable gets populated and we can see session.sso.token.last.password being written at this point in the access debug logs .

The password was getting overwritten by the token in the session variable session.logon.last.password resulting in the token being sent for SSO instead of password.

The MFA server (added as Radius Auth agent in Access policy) there were four Authentication methods(Phone Call, SMS, AuthToken & Mobile APP) which user can select.

Now out of 4 methods, SMS & Authtoken sends the authentication code to user mobile & then user need to enter the code in F5 portal for successful Authentication.

When user 'user1' was using the SMS & Authtoken method, the Citrix loading fails but when the user tried other 2 methods(Call & Mobile APP) Citrix Apps publishing in the Webtop worked fine as soon as user logged in i.e. no SSO issue. 

Recommended Actions

  1. Created a custom variable session.logon.last.password1 to store content of session.logon.last.password after the logon page
  2. Copy it back to session.logon.last.password after the radius auth agent. And it solved the issue - now users using all four authentication methods has SSO working.
