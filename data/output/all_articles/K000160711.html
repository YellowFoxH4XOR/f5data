K000160711: Unable to Sync after installing 17.5.x

Type
Support Solution
Published
2026-04-10
Updated
2026-05-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000160711

Description

After upgrading or installing BIG-IP devices to v17.5.x or creating new HA cluster configuration on BIG-IP devices running v17.5.x , persistent HA config sync failures may occur. The devices enter a loop where sync attempts are repeatedly unsuccessful. The following log messages are observed:

  • notice mcpd[<PID>]: 0107168e:5: Unable to do incremental sync, reverting to full load for device group <dg> device <peer> from commit id { <id> } to commit id { <id> }
  • notice mcpd[<PID>]: 01b00004:5: There is an unfinished full sync already being sent for device group <dg> on connection <connection id>, delaying new sync until current one finishes.

Attempts to rebuild HA trust, update certificates, and reboot the devices do not resolve the issue. This behavior matches the known issue documented as ID 2224937.

Environment

  • Product: BIG-IP LTM
  • Configuration: Devices in HA cluster configuration

Cause

Bug ID 2224937

Answer/Recommended Actions

  • If you encounter this sync loop issue on  BIG-IP LTM HA cluster running v17.5.x, upgrade boxes to the version v17.5.1.6 or higher where Bug ID 2224937 was fixed.
  • If an immediate resolution is required, consider rolling back to a previously stable version after consulting with F5 Support.
  • For software installation procedures, refer to K84554955: Overview of BIG-IP system software upgrades

Additional Information

  • Rebuilding HA trust, updating certificates, and rebooting the devices do not resolve the sync loop.
  • The issue is specific to the upgrade to version  v17.5.x and is not resolved by standard HA troubleshooting steps.
  • The bug results in repeated unsuccessful sync attempts, as evidenced by the specific mcpd log messages.
