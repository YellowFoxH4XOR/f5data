Description

Few users are unable to connect to VPN through Internet Explorer or BIG-IP Edge Client as it gets stuck at "Waiting to connect to server…" user also gets a prompted "Cannot reach server. Change anyway?"

Client Troubleshooting Utility Report shows:

\URLConnect.cpp, 940, URLConnectEx::DownloadFile, Connection failed (URL: <VPN URL>)
CAppTunnelEx::InternalLoadConfiguration, Failed to load configuration. URL: "<VPN URL>", return code: "-1", error: 1223 (1223 (0x4c7) The operation was canceled by the user.)
CAppTunnelEx::InternalLoadConfiguration, Failed to load configuration. Connection error.
 

Client machine can:
Resolve the VPN URL 
ping/telnet to APM VIP 
Even other browsers like Chrome and Microsoft Edge can access the VPN URL 

Environment

  • Edge Client 
  • Windows client
 

Cause

This can happen when SSL handshake between client and APM device fails.

For example : In Window's Internet Options, Advanced tab, TLS1.2 is disabled and and TLS1.0 enabled whereas VIP clientssl profile is configured to only use TLS1.2.
Edge Client will use the TLS settings configured in IE.

Recommended Actions

You can take a packet capture on your BIG-IP APM device using the following steps:

  1. Close all existing sessions from client machine.
  2. Start packet capture:

    tcpdump -ni 0.0:nnn host <client ip> -s0 -w /shared/tmp/test.pcap -vvv

    Note  Replace <client ip> with actual client IP.

  3. Have the user reproduce issue.
  4. Stop trace

    Ctrl+c 

  5. Use WinSCP or any other SCP utility to download test.pcap from /shared/tmp location and analyze using Wireshark.

If for example:

Client machine is using TLS1.0  and APM VIP only uses TLS1.2, then you need to make sure TLS1.2 is enabled on:

Windows > Control Panel > Internet Options > Advanced > Settings > Check "Use TLS 1.2" to ensure client machine (Browser/EdgeClient) uses TLS1.2 for SSL handshake with APM VIP.
