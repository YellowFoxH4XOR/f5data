Issue

The sweeper is the component within the Traffic Management Microkernel (TMM) core that both watches for expired connection flows and responds to resource exhaustion by adaptively reaping connection flows.

Old Behavior

In versions prior to BIG-IP 11.6.0, the adaptive connection reaping low-water and high-water percentages are configured using the connection.adaptivereaper.lowwater and connection.adaptivereaper.hiwater bigdb variables. These database variables represent the percentage of memory (pagemem) utilization in the TMM kernel that will trigger the adaptive connection reaper behavior that is applied system wide to all connection flows.

  • The connection.adaptivereaper.lowater threshold determines at what point adaptive reaping becomes more aggressive. Aggressive reaping accelerates the closing of connections with the highest idle time. While in aggressive mode, the BIG-IP system may reap these connections before the timeouts set in the configuration file.
  • The connection.adaptivereaper.hiwater threshold determines when unestablished connections through the BIG-IP system will no longer be allowed. Once memory utilization reaches the high-water mark, the system does not allow new connections until the available memory is reduced to the low-water mark threshold.

For more information about adaptive connection reaping in versions prior to BIG-IP 11.6.0, refer to the following article:

  • K5670: Overview of adaptive connection reaping (11.5.x and earlier)

New Behavior

Beginning in BIG-IP 11.6.0 the system no longer uses the following bigdb variables: connection.adaptivereaper.lowwater and connection.adaptivereaper.hiwater bigdb. The adaptive connection reaping Low Water and High Water threshold values are now configured in an eviction policy (System > Configuration > Local Traffic > Eviction Policy List). The High Water and Low Water thresholds configured in an eviction policy represent a percentage of the quota used to trigger when the adaptive connection reaping behaviors start and stop.

  • High Water - Specifies the target maximum load on the context. The adaptive reaper will be more aggressive as this limit is approached. The allowable range is 50 - 100, and the high-water value must be higher than or equal to the low-water value.
  • Low Water - Specifies the aggressive sweeper activation threshold as a percentage of total capacity. The allowable range is 50 - 100, and the low-water value must be lower than or equal to the high-water value.

The quota used to trigger adaptive connection reaping behaviors depends on the context to which the eviction policy is applied. Eviction policies can be configured in a global context, virtual server context, or route domain context. When configured in a global context, the low/high water quota represents a percentage of memory (pagemem) utilization reached. When configured in a virtual server or route domain context, the low/high water quota represents a percentage of connection limits reached.

Additionally, within an eviction policy you can specify options to enable slow flow monitoring, and apply user-selectable algorithms which weight the decisions for which flows will be removed.

For more information about adaptive connection reaping beginning in BIG-IP 11.6.0, refer to the following article:

  • K15740: Overview of adaptive connection reaping (11.6.0 and later)

Impact

Eviction policies provide more granular control of the connection reaping functionality.

Recommended Actions

For information about the settings available in an eviction policy, refer to K15821: Overview of eviction policies

The system comes with a default eviction policy named default-eviction-policy. The default eviction policy uses values of 85 percent for low-water and 95 percent for high-water, and has the Bias Idle and Bias Oldest algorithms selected. You should not modify the values of a default policy. For information about configuring an eviction policy with custom values, refer to K15822: Configuring custom eviction policies
