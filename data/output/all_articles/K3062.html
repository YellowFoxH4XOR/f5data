Topic

BIG-IP SSL persistence allows you to persist SSL connections to a node, based on the SSL session ID of the connection.

Note: Transport Layer Security (TLS) 1.3 specification has made SSL session ID obsolete and explicitly removed it. If you require the use of SSL session ID, you have to use TLS 1.2. For more information, refer to K53520835: Error Message: 01260044:4 SSID is not supported with TLS 1.3.

Advantages

  • SSL persistence is much more granular than simple persistence. Unlike simple persistence, SSL persistence does not rely on proxies and network address translations (NATs) and is not subject to the associated issues that can make simple persistence ineffective.
  • SSL persistence ensures that repeat connections from the same client are sent to the same node. This allows the use of SSL session resumption, which saves processing time for both the client and the server.

Disadvantage

  • Some browsers, such as versions of Internet Explorer, force SSL session ID renegotiation at very short intervals (every two minutes with Internet Explorer). As a result, the client browser can supersede the effective SSL persistence timeout.

Configuration requirements

You can use SSL persistence with either of the following configurations:

  • With a virtual server without a Client SSL or Server SSL profile, when the nodes are configured with the SSL certificate. The BIG-IP system passes SSL traffic from the browser to a node. The BIG-IP system does not process the traffic but extracts the Session ID / Encrypted Session Ticket for persistence.
  • With a virtual server configured with a Client SSL profile, when the BIG-IP system terminates client-side SSL connections. Client Authentication may or may not be enabled on the Client SSL profile. If enabled, the frequency is set to Once. You can use this configuration regardless of whether server-side SSL is specified.

You cannot use SSL persistence with the following configuration:

  • With a virtual server configured with a Client SSL profile, when the BIG-IP system terminates client-side SSL connections, Client Authentication is enabled on the Client SSL profile, and the frequency is set to Always. In this case, the Session ID / Encrypted Session Ticket is ignored and handshakes default to Full Handshake since Client Authentication is mandatory. In other words, SSL Session ID persistence is not applicable.

Configuring an SSL persistence profile using the Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Persistence.
  3. Click Create.
  4. Type a name for the SSL persistence profile.
  5. For Persistence Type, click SSL.
  6. Define the profile configuration.
  7. Click Finished.

You now have to associate the SSL persistence profile with the virtual server.

Configuring an SSL persistence profile using tmsh

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To create an SSL persistence profile with desired options, use the following command syntax:

    create /ltm persistence ssl <name> <options>

  3. Save the change by typing the following command:

    save /sys config

  4. Associate the SSL persistence profile with the virtual server.
