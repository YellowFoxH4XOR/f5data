Known Issue

Important: This issue only affects BIG-IP 9.4.3 running HF2 or HF3, due to a code change.

This is the result of a known issue. Failed ARP requests generated by transparent monitors can cause the Traffic Management Microkernel (TMM) to crash.

This issue occurs when ARP requests, generated by a transparent monitor, fail and exceed the number of retries allowed by the system. Additionally, this issue occurs when the address specified in the transparent monitor is unreachable, or the system attempts to reach the address through a different gateway.

The default number of ARP retry attempts is set to 6. The ARP retry attempts are found in the bigpipe db Arp.Retries variable.

To view the number of ARP retries, type the following command at the command line:

bigpipe db Arp.Retries

F5 Product Development tracked this issue as CR92899 and it was fixed in BIG-IP LTM 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
