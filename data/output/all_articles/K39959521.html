Topic

When configuring a virtual server using the TMOS Shell (tmsh) you have the option of setting multiple persistence profiles.

Description

Using tmsh, you can configure a virtual server to use multiple persistence profiles, which is helpful in environments where you use a virtual server to process different services.

You can configure a virtual server configured with multiple persistence profiles to use any of the persistence profiles as the default persistence profile of the virtual server by setting the default yes option (the default option is default no). By configuring a persistence profile as the default persistence profile for the virtual server, traffic processed by the virtual server will be persisted using that profile when no overriding option selects a non-default (default no) persistence profile. You can select a non-default persistence profile through a custom iRule.

Note: When you set all persistence profiles of a virtual server configuration to default no without using an iRule for persistence profile selection, or if the iRule does not set the persistence profile, no persistence is applied and the connection is load-balanced.

The following any TCP protocol virtual server can process multiple different services and use Microsoft Remote Desktop (MSRDP) persistence for MSRDP traffic, Secure Sockets Layer (SSL) persistence for SSL traffic, and Source Address persistence for all remaining traffic.

ltm virtual example_vs {
    destination 172.16.1.154:any
    ip-protocol tcp
    mask 255.255.255.255
    persist {
        example_msrdp {
            default no
        }
        example_srcaddr {
            default yes
        }
        example_ssl {
            default no
        }
    }
    pool example_pool
    profiles {
        tcp-lan-optimized { }
    }
    rules {
        example_persist_select_rule
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port disabled
    vs-index 43
}

Note: The virtual server is configured with the example_srcaddr persistence profile set as the default (default yes).

Example iRule where the iRule sets the persistence profile based on the virtual server port match:

when CLIENT_ACCEPTED {
if { [TCP::local_port] == 443 }{
persist ssl 
log local0. "SSL selected: client: [IP::client_addr] > virtual: [IP::local_addr]:[TCP::local_port]."
 }
elseif { [TCP::local_port] == 3389}{
persist msrdp 
log local0. "MSRDP selected: client: [IP::client_addr] > virtual: [IP::local_addr]:[TCP::local_port].."
 }
else {
log local0. "iRule did not select persistence for client: [IP::client_addr] > virtual: [IP::local_addr]:[TCP::local_port]."
   }
}

Note: The iRule persistence profiles are selected with SSL and MSRDP, where the virtual server is configured with the example_ssl, example_msrdp and example_xrcaddr custom persistence profiles.

In the example virtual server configuration, the example_srcaddr persistence profile is the persistence profile for all traffic that is not identified by the example_persist_select_rule iRule. The iRule checks for the virtual server connection request for TCP ports 443 and 3389. Connection request that are matched by the iRule will select the configured persistence profile based on the TCP port match.  It is important to note the iRule can only be configured to set a persistence profile choice using a system parent persistence profile name; in the example, iRule persistence profiles SSL and MSRDP are set. The iRule will not accept custom persistence profile names. When the iRule sets the persistence profile to a system persistence parent profile, the virtual server-configured child persistence profile based on the system parent persistence profile is used for persisting the connection request; the example uses the example_srcaddr and example_msrdp persistence profiles.

Recommendations

When a virtual server with multiple persistence profiles, you should consider the following factors:

  • You can configure a virtual server to use multiple persistence profiles, which is helpful when you use the virtual server to process different types of services in an environment that requires unique persistence for each service.
  • You add the persistence profiles to the virtual server configuration using the default setting default no, unless you specifically configure the persistence profile as default yes.
  • The virtual server protocol profiles must support the virtual server persistence profiles for inclusion in the virtual server configuration.
  • When all configured persistence profiles are set with default no and you do not use an iRule to set the persistence profile for a connection request, or the configured iRule does not set the persistence profile for the connection request, the connection request is load-balanced with no persistence applied.
  • When creating the persistence profile selection iRule, ensure that the iRule persist refers to the system parent persist profile name used by the child persistence profile of the virtual server configuration.
