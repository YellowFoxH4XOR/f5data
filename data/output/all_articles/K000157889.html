Description:

This article addresses an issue where BIG-IP Virtual Edition (VE) devices in a High Availability (HA) sync-failover group on Microsoft Hyper-V experience persistent "Changes Pending" status and failed configuration syncs after licensing changes or upgrades. Attempts to manually sync result in the error:

There is an unfinished full sync already being sent for device group delaying new sync until current one finishes.

Environment:

  • BIG-IP Virtual Edition (VE) version 17.x (also relevant for 15.x)
  • Microsoft Hyper-V hypervisor
  • HA device group with sync-failover
  • Recent actions: License reactivation, module deprovisioning, device trust re-establishment, device group rebuild, and attempted config syncs

Cause 

TCP Segmentation Offload (TSO) is enabled by default on BIG-IP VE. In certain Hyper-V environments and with specific NIC drivers, TSO offloads TCP segmentation to the NIC, resulting in invalid TCP checksums on large packets. This causes config sync failures and persistent "changes pending" status.

Recommended Actions:

To resolve the issue, disable TCP Segmentation Offload (TSO) on both BIG-IP VE devices and restart the Traffic Management Microkernel (TMM):

  1. Run the following command on each BIG-IP VE:
    tmsh modify sys db tm.tcpsegmentationoffload value disable
  2. Restart TMM for the change to take effect:
    bigstart restart tmm
  3. After TMM restarts, initiate a config sync and confirm that the "changes pending" status is cleared and both devices are "in sync."
  4. Save the configuration changes:
    tmsh save sys config

Additional Information:

  • Disabling TSO may increase CPU usage on BIG-IP VE.
  • This issue is specific to Hyper-V environments and may not occur on other hypervisors.
  • Prior troubleshooting steps (NTP sync, device trust re-establishment, device group rebuild) do not resolve the issue if TSO is enabled.
  • TCP offloading (TSO) is enabled by default in BIG-IP VE version 15.x and later unless manually disabled.
