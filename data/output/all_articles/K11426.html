Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:
  • K81537366: Interoperability with third-party caching proxy servers (11.x - 13.x)

Description

Some third-party caching proxy servers will not cache content unless the Vary header in the HTTP response is set to a specific value. For example, some servers will not cache content unless the Vary header is either set to the Accept-Encoding value or it is absent from the HTTP header.

Note: For the specific requirements of your caching proxy servers, refer to your vendor documentation.

By default, the BIG-IP system does not modify the Vary header. However, if the HTTP profile associated with the virtual server has compression enabled, the BIG-IP system will modify the Vary header as follows:

  • If the Enable Compress HTTP 1.0 setting is enabled in the HTTP profile, the BIG-IP system adds the Accept-Encoding value to the Vary header if it is not already present.
  • If the Vary header setting is enabled in the HTTP profile and the Enable Compress HTTP 1.0 setting is disabled in the HTTP profile, the BIG-IP system adds the Accept-Encoding and User-Agent values to the Vary header if they are not already present.

    Note: If BIG-IP WebAccelerator is enabled on the virtual server, the BIG-IP system does not add the User-Agent value to the Vary header.

  • If both the Enable Compress HTTP 1.0 setting and the Vary header setting is enabled in the HTTP profile, the BIG-IP system adds the Accept-Encoding value (without the User-Agent value) to the Vary header if it is not already present.

Modifying the Vary header for better compatibility with third-party caching proxy servers

If you want to modify the Vary header for better compatibility with your third-party caching proxy servers, perform one of the following three procedures:

Important: If compression is disabled, F5 Networks recommends configuring the back-end web servers to send the appropriate Vary headers. By default, the BIG-IP system does not modify the Vary header when compression is disabled.

Important: The following procedures are intended for environments that use a single vendor for caching proxy servers. In a mixed environment, you may not want to manipulate the Vary header.

  • Adding the Vary header
  • Modifying the Vary header
  • Removing the Vary header

Adding the Vary header

If the back-end web server is not sending a Vary header, and compression is enabled, you can set the Vary header to the Accept-Encoding value by selecting the Enable Compress HTTP 1.0 check box in the HTTP profile.

If compression is not enabled, or if you do not want to change your compression settings, you can add the Vary header using an iRule. For example, the following iRule sets the Vary header to the Accept-Encoding value:

Important: If compression is enabled, you must also clear the Vary Header check box in the HTTP profile to prevent additional Vary header injection.

when HTTP_RESPONSE {
HTTP::header insert Vary "Accept-Encoding"
}

Note: For more information about configuring iRules, refer to the F5 DevCentral site. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Modifying the Vary header

If the back-end web server is sending the correct Vary header, and you do not want the BIG-IP system to add the User-Agent value to the Vary header, clear the Vary Header check box in the HTTP profile. Alternately, selecting the Enable Compress HTTP 1.0 check box in the HTTP profile will also prevent the BIG-IP system from adding the User-Agent value to the Vary header.

If the back-end web server is not sending the correct Vary header, you can modify the header using an iRule. For example, the following iRule removes the Vary header sent by the back-end web server, and replaces it with the Accept-Encoding value:

Important: If compression is enabled, you must also clear the Vary Header check box in the HTTP profile to prevent additional Vary header injection.

when HTTP_RESPONSE {
HTTP::header remove "Vary"
HTTP::header insert Vary "Accept-Encoding"
}

Note: For more information about configuring iRules, refer to the F5 DevCentral site. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Removing the Vary header

To remove the Vary header from the HTTP response, configure the following iRule:

Important: If compression is enabled, you must also clear the Vary Header check box in the HTTP profile to prevent Vary header injection.

when HTTP_RESPONSE {
HTTP::header remove "Vary"
}

Note: For more information about configuring iRules, refer to the F5 DevCentral site. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).
