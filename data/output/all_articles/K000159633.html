Description

When MAC masquerade is configured on a traffic group for an ESXBIG-IP Virtual Edition (VE) using SR-IOV Virtual Functions on Intel E810-XXV NICs, communication through the SR-IOV VF fails. The issue occurs when the SR-IOV Virtual Function (VF) is attached to the BIG-IP VM and MAC masquerade is applied to the traffic group, even when the ESXi port group is configured with "Allow MAC address changes", "forged transmits" and "promiscuous mode set to Accept".

 

When failure occurs, the following symptoms are observed:

  • Floating objects with IP addresses in the traffic group do not respond
  • BIG-IP tmm logs show error messages from the iavf driver
  • - AQ returned error -5 to request 10
  • - Error -5 waiting for PF to complete operation
  • - WARNING: Error adding VF mac filter
  • - WARNING: Device may not receive traffic

Environment

- BIG-IP Virtual Edition running on VMware ESXi

- Intel E810-XXV for SR-IOV Virtual Functions

- SR-IOV Virtual Function (VF) attached to BIG-IP VM

- MAC masquerade configured on BIG-IP traffic group

- Port group configured with "Allow MAC address changes", "forged transmits" and "promiscuous mode" set to Accept

Cause

The ESXi host's Physical Function (PF) driver rejects MAC address change requests from the BIG-IP Virtual Function (VF) because "trust mode" is not configured on the SR-IOV VF.

Answer/Recommended Actions

1. Update ESXi host Intel E810-XXV NIC drivers to the latest release which supports setting Virtual Function "trust mode"

2. Enable trust mode for all Virtual Functions which are attached to vlans where BIG-IP MAC masquerade will be enabled, sample command trust mode on VFs in position 1 to 4 on a PF with 8 VFs.

esxcli system module parameters set -a -m icen -p trust_all_vfs=1,1,1,1,0,0,0,0
