Known Issue

A single client may open multiple sessions and surpass the Max Sessions per User limit.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM access policy has been configured to use Active Directory authentication.
  • Your BIG-IP APM access profile has been configured with a Max Sessions per User value.
  • Clients establish multiple sessions by differentiating the case of their user name.

    For example, one user could establish multiple sessions using the following variations of their user name:

    JohnSmith
    johnsmith
    Johnsmith
    johnSmith

Impact

The BIG-IP system may not enforce the Max Sessions per User setting as intended.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • An individual client appears to the BIG-IP APM system as multiple clients, based on the case of the user name that establishes a session.
  • Session counts seem disproportionately higher than the expected rates.

Workaround

To work around this issue, you can configure the affected access profile's access policy to convert the case of the client's user name to all lowercase characters. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy > Access Profiles.
  3. Locate the affected profile that has been previously defined with the Max Sessions Per User value.
  4. To the right of the profile name in the Access Policy section, click Edit to open the visual policy editor.
  5. Locate the defined AD Auth box and the Successful branch to the right in the policy flow.
  6. Click the first + in the Successful branch to add a new action to the branch.
  7. Select the Assignment tab.
  8. Select the radio button for Variable Assign.
  9. Click Add Item.
  10. In the Variable Assign pop-up, modify the default name of Variable Assign to a name that helps identify the action.

    For example:

    Logon-to-Lowercase

  11. Click Add new entry.
  12. Click change for the newly created empty assignment.
  13. Leave the Custom Variable menu selection at the default setting of Unsecure.
  14. In the Custom Variable box, type the following:

    session.logon.last.logonname

  15. In the Custom Expression box, enter the following:

    expr {[string tolower [mcget {session.logon.last.username}] ]}

  16. Click Finished.
  17. Navigate to Access Policy > Access Profiles.
  18. Select the check box for the modified profile.
  19. Click Apply Access Policy.
