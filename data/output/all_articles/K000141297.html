Description

Client connecting to a HTTPS virtual server is getting reset connection. You want to diagnose and troubleshoot the issue. For example: 

connection from 198.51.100.10 is being reset by Virtual Server - VS1 (203.0.113.1).

Environment

  • BIG-IP
  • TCP reset

Cause

None. Diagnostic.

Recommended Actions

You need run tcpdump and generate a qkview file.

Traffic capture illustrating the issue using following syntax:

1. Enable decrypt and reset cause in the BIGIP:

tmsh modify sys db tcpdump.sslprovider value enable

tmsh modify sys db tm.rstcause.pkt value enable

tmsh modify sys db tm.rstcause.log value enable

Note: When you perform a tcpdump capture with tcpdump.sslprovider enabled, understand that the TLS master secret will be written to the tcpdump capture itself. Be careful with whom you share the capture file (K31793632: Creating a decrypted tcpdump capture without using an iRule).

2. (Optional) Run below packet capture replace with any IP address which does not exist your environment. You can run the capture for couple of minutes, no need to save it to a file. For example 192.0.2.1. This is just to make sure mitigating the effect of long-lived connection flows when using the p modifier K20233108: Running the tcpdump utility using the p interface modifier 

tcpdump -s0 -nni 0.0:nnn host <any non existing IP in your environment>

For example:

tcpdump -s0 -nni 0.0:nnn host 192.0.2.1

After couple of minutes, stop the capture.

3. Run the traffic capture illustrating the issue using following syntax on BIG-IP system (replace the client_IP):

tcpdump -s0 -nni 0.0:nnnp --f5 ssl host <client_IP> -vw /var/tmp/"$HOSTNAME"_"$(date +%Y%m%d_%H%M%S)".pcap

4. Initiate a new traffic to the affected virtual server.

5. Stop the network capture by Ctrl + C

6. After you have reproduced the issue, close all of the tcpdump sessions and disable reset cause.

tmsh modify sys db tcpdump.sslprovider value disable

tmsh modify sys db tm.rstcause.pkt value disable

tmsh modify sys db tm.rstcause.log value disable

7. Generate a qkview (K12878: Generating diagnostic data using the qkview utility) and upload to ihealth.

Attempt to analyze the logs. If you are unable analyze, open a case with Network Support and provide above information. i.e., tcpdump capture and qkview file. If possible please specify TCP stream or client port that is illustrating the issue.
