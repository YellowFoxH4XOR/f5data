K41050379: HTTP logout request RESET by BIG-IP APM module

Type
Support Solution
Published
2020-12-23
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.1.3
Source
https://my.f5.com/manage/s/article/K41050379

Description

HTTP logout request is RESET by BIG-IP APM

Environment

  • Access Policy
  • Logout URI Include

Cause

The URI in the "logout URI include" of the access profile cannot have a URI that also has query parameters.
For example: 
/a.spx?a=b
/index.cgi?logout=1

Recommended Actions

There are two possible iRules that can be used as a workaround for this issue.
Use only one of the options, not both, and the iRule must be applied to the virtual server that has the access policy applied to it.
Example#1 is best used where you only have one logout uri, whereas Example#2 is best used when you have multiple logout URIs 

Example #1:
(change the value or "logout URI" to be equal to the URI causing the issue)
when HTTP_REQUEST {
  if { [HTTP::uri] equals "logout URI" } {
    HTTP::redirect https://[HTTP::header host]/vdesk/hangup.php3
  }
}

Example #2:
(You will also need to create a datagroup called "logoutURI_dg" which will contain a list of the URIs used to trigger a logout)
when RULE_INIT {
        set doLogout 0
}
when HTTP_REQUEST {
        set http_path [string tolower [[HTTP::path]HTTP::path]]
        log local0. "$http_path"
        if { [matchclass $http_path starts_with logoutURI_dg] } {
                set doLogout 1
        } elseif { $http_path starts_with "/my.logout.php" } {
                set doLogout 2
        } else {
                set doLogout 0
        }
}
when HTTP_RESPONSE {
        if {$doLogout == 1} {
                [HTTP::respond]HTTP::respond 302 Location "/my.logout.php"
                set static::doLogout 0
        } elseif {$doLogout == 2} {
                [HTTP::respond]HTTP::respond 302 Location "/"
        }
}
