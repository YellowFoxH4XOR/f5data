Issue

You should consider using these procedures under the following condition:

  • You cannot successfully discover remote BIG-IP systems from the BIG-IQ system.

Symptoms

As a result of communication failure, you may encounter the following symptom:

  • An error message similar to the following examples appears in the BIG-IQ user interface while attempting to discover a new BIG-IP system:

    The device 192.168.10.100 is not reachable from BIG-IQ on port 443. Validate networking configuration on BIG-IQ, validate the target BIG-IP is operational, then retry the operation.

    Failed to connect to device 192.168.10.100 using address 192.168.10.100 and port 443

Recommended Actions

Ensure the BIG-IP system you are attempting to discover is compatible with the BIG-IQ system. For more information about compatibility, refer to the following article:

  • K34133507: BIG-IQ Centralized Management compatibility matrix

For successful inter-device communication, you must configure each device with a proper route, configure each device to use the proper interface, and ensure TCP service ports on each device are able to accept new connections. For more information about inter-device connectivity requirements, refer to the following article:

  • K15612: Connectivity requirements for the BIG-IQ system

Without the proper network routes on each device, discovery attempts fail. For more information about configuring routes, refer to the following articles:

  • K13833: Managing static routes in BIG-IP and BIG-IQ
  • K13284: Overview of management interface routing (11.x and later)

The BIG-IQ and BIG-IP systems use specific TCP service ports and device interface settings for communication. On remote BIG-IP systems that are being discovered, ensure that these service ports are able to accept new connections from the BIG-IQ system. For more information about managing BIG-IP service ports, refer to the following article:

  • K17333: Overview of port lockdown behavior (12.x - 17.x)

Important: Prior to version 5.0.0, the BIG-IQ system does not support the use of Virtual Local Area Network (VLAN) tags.

F5 products rely on the system time being synchronized throughout the network; ensure that the Network Time Protocol (NTP) server is configured on all devices. For more information about configuring NTP, refer to the following articles:

  • K16309: Using the BIG-IQ user interface to add an NTP server
  • K3122: Using the BIG-IP Configuration utility to add an NTP server

Procedures

When experiencing BIG-IQ device discovery errors, you can use the following troubleshooting steps to determine the root cause:

  • Establish communication between BIG-IQ and BIG-IP systems
  • Verify TCP communication between BIG-IQ and BIG-IP systems
  • Update the BIG-IP REST framework

Establish communication between BIG-IQ and BIG-IP systems

TCP service port communication

  • The BIG-IQ system uses TCP port 443 to discover and manage remote BIG-IP systems using the Representational State Transfer (REST) Application Programming Interface (API). The REST API is implemented by the restjavad process running on the remote BIG-IP system.
  • The BIG-IQ system uses TCP port 22 to update the REST API framework on remote BIG-IP systems. The sshd process that runs on the remote BIG-IP system is used to accept REST API software updates from the BIG-IQ system.

Device interface communication

  • In BIG-IQ 4.5.0 and later, either a self IP address or the management port can be used for device communication. The preferred method for communication is the management port.
  • In BIG-IQ 4.4.0 and earlier, only a self IP address can be used for device communication.

Token-based authentication

  • In BIG-IQ 5.1.0 and later, the basic HTTP authentication is disabled by default; to perform REST API related communication, you must use token-based authentication. For more information, refer to K04452074: Overview of using the BIG-IQ system authentication token.
  • In BIG-IP 12.0.0 and later, token-based authentication is required when the BIG-IP system is associated with remote authentication. For more information about using token-based authentication on BIG-IP system, refer to Demystifying iControl REST Part 6 - Token-Based Authentication on DevCentral.

Verify TCP communication between BIG-IQ and BIG-IP systems

TCP port 443

You can verify TCP port 443 availability using the curl utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IQ system.
  2. Use the following curl command syntax, replacing <x.x.x.x> with the remote BIG-IP system's IP address:

    curl -k -v -X GET https://admin:admin@<x.x.x.x>/mgmt/shared/echo

    When token-based authentication is required on either the BIG-IQ or BIG-IP system, you will receive HTTP 401 authentication failed error messages when running the previous curl command. To overcome this error, perform this procedure using the curl command with token-based authentication.

    For token-based authentication, use the following command syntax, replacing <Token> with the authentication token string that you have received from the remote BIG-IP system:

    curl -k -H X-F5-Auth-Token:<Token> https://<x.x.x.x>/mgmt/shared/echo

    The curl utility produces a considerable amount of diagnostic data. However, the important data to consider is in the Server certificate section; specifically, the Subject elements, which should match the remote BIG-IP system's Device Certificate Subject information.

    The output appears similar to the following example:

    * Server certificate:
    * subject: C=US; ST=WA; L=Seattle; O=F5 Networks, Inc.; OU=AskF5; CN=remote1.f5.com

  3. Log in to the Configuration utility of the remote BIG-IP system.
  4. To view the remote BIG-IP system's Device Certificate Subject information, go to System > Device Certificates > Device Certificate.
  5. Under Certificate Properties, note the Subject elements. These elements should match the data gathered in step 2.

TCP port 22

You can use the ssh utility to verify TCP port 22 availability. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IQ system.
  2. Use the following ssh command syntax, replacing <x.x.x.x> with the remote BIG-IP system's IP address:

    ssh <x.x.x.x>

  3. Optional: If a warning message appears, asking if you want to continue, select yes.

    For example:

    Are you sure you want to continue connecting (yes/no)? yes

  4. When you receive the Password prompt, provide the root user credentials.
  5. To verify the remote BIG-IP system by host name, view the command prompt or run the following command:

    [root@remote1:Active:Standalone] config # tmsh list sys global hostname
    sys global-settings {
        hostname remote1.f5.com
    }

Test failures

If either TCP port tests fail, the following diagnostic data provided by the error message can help you understand the cause:

  • Connection refused error messages usually indicate a TCP port is being blocked, either in the network or on the remote BIG-IP system.
  • No route to host error messages usually indicate a misconfigured route or a missing or mistyped IP address.

Update the BIG-IP REST framework

The BIG-IQ and BIG-IP systems use the REST framework to exchange configuration and statistical data. Device discovery can fail when discovering BIG-IP devices with older REST frameworks or REST frameworks missing soft REST software components. If errors are encountered when discovering devices, to manually upgrade the REST framework, perform the following procedure:

Note: BIG-IP systems running 12.x or later are not suitable for this procedure. The device discovery process for BIG-IP 12.x automatically installs the compatible REST framework to the system if the system detects missing components during the device discovery process.

Impact of procedure: The BIG-IQ system manages only compatible BIG-IP versions. F5 recommends that you review the compatibility matrix between the two systems by referring to K34133507: BIG-IQ Centralized Management compatibility matrix before starting this procedure. When you perform the manual REST framework upgrade procedure using incompatible versions, the restjavad service may become stuck in a restart loop.

  1. Log in to the BIG-IQ command line as the root user.
  2. To establish SSH trust between the BIG-IQ system and the managed BIG-IP device, use the following command syntax: 

    Note: This step is optional. However, if you do not establish trust, you must provide the BIG-IP system's root password multiple times.

    ssh-copy-id -i ~/.ssh/identity.pub root@<BIG-IP Management IP Address> 

    For example, to establish trust between the BIG-IQ system and a remote BIG-IP device with an IP address of 192.168.10.100, enter the following command:

     ssh-copy-id -i ~/.ssh/identity.pub root@192.168.10.100

  3. To go to the folder where the required files reside, enter the following command:

    cd /usr/lib/dco/packages/upd-adc

  4. To run the installation script, use the following command syntax:

    ./update_bigip.sh –a admin –p <password> <BIG-IP Management IP Address> 

    For example, to install the required files on the remote BIG-IP device using the examplepw admin password and an IP address of 192.168.10.100, enter the following command:

    ./update_bigip.sh –a admin –p examplepw 192.168.10.100

  5. Optional: To revoke SSH trust between the BIG-IQ system and the remote BIG-IP device, use the following command syntax:

    Note: This step is not required if you did not establish trust in step 2.

    ssh-keygen –R <BIG-IP Management IP address> 

    For example, to revoke SSH trust between the BIG-IQ system and the remote BIG-IP device with an IP address of 192.168.10.100, enter the following command:

    ssh-keygen –R 192.168.10.100
