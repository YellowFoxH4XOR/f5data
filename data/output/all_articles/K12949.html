Known Issue

Description

When the origin web server (OWS) sends a response that contains more than one Cache-Control header, the BIG-IP HTTP cache (referred to as RAM Cache in BIG-IP versions prior to 11.0.0) only examines the last Cache-Control header, and ignores any preceding Cache-Control header.

For example, the following HTTP response contains two Cache-Control headers; the Cache-Control: private header precedes the Cache-Control: max-age=0 header and indicates that the response must not be cached; however, the BIG-IP system ignores the Cache-Control: private header and caches the response when it should not:

HTTP/1.1 200 OK
Server: Apache/2.2.3 (CentOS)
Content-Type: text/html; charset=UTF-8
Date: Wed, 09 Dec 2009 19:15:01 GMT
Content-Length: 176
Last-Modified: Wed, 09 Dec 2009 18:27:40 GMT
Cache-Control: private
Cache-Control: max-age=0
Connection: Keep-Alive
Vary: Accept-Encoding
Accept-Ranges: none

This issue occurs when all of the following conditions are met:

  • HTTP caching is enabled.
  • The OWS sends a response that contains more than one Cache-Control header.

Impact

The BIG-IP system may cache some responses that it should not.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H383289 on the Diagnostics > Identified > Low page.
  • Your BIG-IP system provides a cached response for an object it should not have cached.

Workaround

To work around this issue, you can use an iRule to combine all instances of a header in the response into a single comma-delimited header. To do so, refer to the following DevCentral article:

Fixup Cache Control Headers

Note: A separate DevCentral login is required to access this content.

Impact of workaround: The suggested workaround should not have a negative impact on your system.
