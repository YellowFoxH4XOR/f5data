Known Issue

Deleting a traffic selector may cause the tmipsecd process to restart and produce a core file.

This issue occurs when the following condition is met:

  • The tmipsecd process attempts to delete a non-existing traffic selector.

When deleting a traffic selector, a rare race condition allows for the traffic selector being deleted to have already been removed by the time the tmipsecd process attempts to delete it.

Impact

The IPsec tunnel experiences temporary outages and the tmipsecd process produces a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The IPsec tunnel experiences temporary outages.
  • The tmipsecd process produces a core file in the /var/core directory.
  • In the /var/log/tmipsecd file, you may observe log message similar to the following example:

    tmipsecd: data/Data.cpp:139: void data::IPSecPolicy::removeFromTSHashMa (f5cpp::IpAddr&, boost::shared_ptr<data::TrafficSelector>): Assertion `iter != trafficSelectorHashMap.end()' failed.

  • In the /var/log/racoon.log file, you may observe log message similar to the following example:

    INFO: failed to recv from pfkey (Inappropriate ioctl for device), retry later
    emerg logger: Re-starting tmipsecd
