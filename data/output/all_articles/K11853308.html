K11853308: Modifying GTM pool may take longer time

Type
Support Solution
Published
2026-08-25
Updated
2026-08-25
Status
Final
Applies to

  • BIG-IP GTM

Source
https://my.f5.com/manage/s/article/K11853308

Description

    You may encounter the following symptoms when trying to modify DNS pool configuration through tmsh command.

    • tmsh command seems hanging for extra longer time.

    • The odd numbered CPU surges to about 100% for mcpd usage.

    • The rrd data may be lost and statistic graph shows interrupted for some time.

    • If there is external SNMP query running at the time, you may notice some logs in /var/log/ltm as below:

        warning snmpd[10944]: 010e0004:4: MCPD query response exceeding 60 seconds

    Environment

    • BIG-IP DNS
    • Wide IP
    • DNS Pool

    Cause

    The issue is caused  when below conditions match

    •  You are trying to modify GTM/DNS pool or pool member settings with tmsh command

    • The pool is referred by many wide IP

    Recommended Actions

    • Reduce the number of wide IP dependencies on pools, so that changes to a single pool do not affect so many wide IPs.

    • If this issue happens on VE, consider to allocate more more resources to this instance, this may provide some relief.

    Additional Information

     None.
