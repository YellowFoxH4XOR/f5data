Known Issue

A Virtual Clustered Multiprocessing (vCMP) guest instance may be disabled when the network trunk configuration is added or deleted.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system has vCMP provisioned or deployed with at least one vCMP guest instance.
  • On the vCMP host system, a network trunk configuration is added or deleted.

For example, this issue can occur after a vCMP guest instance is deployed and running in an operational state, and a new network trunk configuration is created on the vCMP host system. The new network trunk configuration can be created from the Configuration utility Trunk List page, or the Traffic Management Shell (tmsh). When the new trunk configuration is saved, all guest instances running on this vCMP host will become unavailable. Similarly, when you delete a network trunk configuration on the vCMP host, all guest instances will also become unavailable.

Impact

The vCMP guest instance becomes unavailable. If you have more than one guest instance, all instances will become unavailable.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The vCMP guest instances that were provisioned or deployed are no longer available, even though the requested state indicates the instances as Deployed.
  • Network traffic to the vCMP guest instances is unreachable.
  • You cannot restart or reactivate the vCMP guest instances.

Workaround

There is no workaround for this issue. However, you can recover from this issue by restarting the vcmpd process on the vCMP host system, by using the following tmsh utility command:

restart /sys service vcmpd
