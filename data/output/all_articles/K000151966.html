Description

When you try logging into the F5OS GUI using "admin" but failed with "Permission denied" as the following screenshot.

Environment

  • All F5OS platforms (F5OS-A or F5OS-C)
  • Any software version
  • GUI access using admin account

Cause

Somehow the Group ID (GID) has been changed to other values from the original value (9000).

Recommended Actions

1. Login to the F5OS CLI using "root".

2. Check the user's GID by running the following command.

cat /etc/passed | grep "<user>"

For the example to view the admin's GID:

[root@appliance-1(rSeries) ~]# cat /etc/passwd | grep "admin"
admin:x:1000:9100::/var/F5/system:/var/lib/controller/f5_confd_cli -> The correct GID should be set as 9000 (admin) which has GUI and CLI confd access.

3. If the result from (2) is different than 9000, you may use any editor (eg. nano or vi) to modify the GID to 9000.

The correct GID should be the following.

[root@appliance-1(rSeries) ~]# cat /etc/passwd | grep "admin"
admin:x:1000:9000::/var/F5/system:/var/lib/controller/f5_confd_cli

Additional Information

During the time when the GID is wrong, you are not able to have CLI access to confd shell either.
The available commands which you were able to use are only exit or quit as per the following example.

appliance-1# ?
 -------------^
Possible completions:
 exit - Exit the management session
 quit - Exit the management session

You firstly modify the correct GID (9000), then the CLI confd access will be recovered.
