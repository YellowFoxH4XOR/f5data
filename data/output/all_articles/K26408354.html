K26408354: Getting a TimeoutException from Telemetry Streaming when using a Pull Consumer

Type
Support Solution
Published
2021-09-21
Updated
2025-07-01
Applies to
  • F5 Automation and Orchestration
  • F5 Telemetry Streaming Extension
Source
https://my.f5.com/manage/s/article/K26408354

Description

When using a Pull Consumer (type "class": "Telemetry_Pull_Consumer") the target device returns a 400 error with java.util.concurrent.TimeoutException in the errorStack details.

Environment

  • BIG-IP
  • Telemetry Streaming
  • Sufficiently large amount of configuration objects

Cause

Using a pull consumer relies on restnoded within the BIG-IP to gather data. There is an implicit 60 second timer, and if the amount of data takes longer than 60s you will get a timeoutException. F5 filed this issue as ID982681 to add flexibility and included this feature in BIG-IP Telemetry Streaming v1.18. This issue doesn't affect push consumers, which could be used as a workaround. You can also explore reducing the data burden (and thus not triggering the timeout) by filtering nonessential data. See Data Modification on F5 CloudDocs for more information.

Recommended Actions

  1. Reduce the data needed for the pull consumer to ensure the query finishes within 60s, or
  2. Utilize a Push Consumer, or
  3. Upgrade to the latest version of BIG-IP Telemetry Streaming (v1.18 or newer) in order to configure the timeout to cover the needed time period. About timeout configuration, please refer to https://clouddocs.f5.com/products/extensions/f5-telemetry-streaming/latest/troubleshooting.html#why-do-i-getting-a-timeoutexception-from-telemetry-streaming-when-using-a-pull-consumer
