Description

Removing a VLAN from the allowed VLANs list Tenant configuration within VELOS or rSeries host does not propagate that change to the guest or tenant and the MCP VLAN object still remains.

Environment

The following steps are carried out in order to observe this issue:

  • Create tenant with at least one allowed VLAN
  • Deploy the tenant, verify the VLAN object is present with tmsh list net vlan
  • Set tenant to configured/provisioned
  • Remove VLAN from the tenant
  • Set tenant to deployed
  • Observe VLAN object is still present

Cause

When a VLAN is added to a tenant, that VLAN object gets created in MCP for that tenant. However, if the VLAN is removed from the tenant at the F5OS level, the VLAN object remains in MCP. Although the object will remain in MCP, F5OS will not allow that tenant to pass traffic on that VLAN if it is later removed from the tenant.

Recommended Actions

No action is essential. The behavior described with Tenants on F5OS is the same as what is observed with vCMP guests deployed on an underlying vCMP host (VIPRION or non-VIPRION chassis), so it is considered to be expected behavior.
