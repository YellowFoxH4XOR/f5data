K000137611: Traffic not routing from Ingress Gateway to service and getting error "503 NC cluster_not_found" on logs

Type
Support Solution
Published
2023-12-28
Updated
2023-12-28
Applies to
  • Aspen Mesh: 1.14, 1.11
Source
https://my.f5.com/manage/s/article/K000137611

Description

The traffic flow isn't working from the Ingress gateway to inside the cluster(service). And on the Ingress gateway logs you can see the error "503 NC cluster_not_found" 

Environment

Aspen Mesh 1.14.X 1.11.X

Cause

When the traffic is not routing to the service properly and you are getting the error "503 NC cluster_not_found", it means that the IGW doesn't know where to send the traffic, for example there is a duplicated Virtual Service associated to the Gateway and each VirtualService sends traffic to different hosts or the destination host of the VirtualService is misspelled or doesn't exist.

This is an example of the log on the Ingress Gateway with the 503 error:

[2023-12-28T16:18:45.291Z] "GET / HTTP/1.1" 503 NC cluster_not_found - "-" 0 0 0 - "10.125.1.3" "curl/7.68.0" "xxxxxxxxxxxxxxxxxxx" "10.125.1.200" "-" - - 10.244.1.9:8080 10.125.1.3:6249 - -


For envoy "NC" log means NoClusterFound, Upstream cluster not found.


Recommended Actions

Verify that you don't have duplicated Virtual Services associated to the same port/path of the gateway:

istioctl pc route <your-istio-ingressgateway>.<your-namsepace>
NAME          DOMAINS     MATCH                  VIRTUAL SERVICE
http.8080     *           /*                     httpbin.ns1
http.8080     *           /*                     httpbin2.ns1


kubectl get virtualservices.networking.istio.io -n <your-namespace>
NAME       GATEWAYS              HOSTS   AGE
httpbin    ["httpbin-gateway"]   ["*"]   51m
httpbin2   ["httpbin-gateway"]   ["*"]   45m

Or verify that the destination host of the VirtualService is typed correctly:

apiVersion: networking.istio.io/v1alpha3
kind: VirtualService
metadata:
  name: httpbin
spec:
  hosts:
  - "*"
  gateways:
  - httpbin-gateway
  http:
  - route:
    - destination:
        host: httpbim
        port:
          number: 8000

(In the previous VS yaml example, the destination host of the VirtualService should be httpbin)

 

Additional Information

Once you have identified the duplicated Virtual services or corrected the misspelled destination host, it should look like this:

NAME          DOMAINS     MATCH                  VIRTUAL SERVICE
http.8080     *           /*                     httpbin.ns1
