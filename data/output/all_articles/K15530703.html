Known Issue

The Traffic Management Microkernel (TMM) restarts when a header remove operation occurs before a Proxy Select agent within a policy.

This issue occurs when all of the following conditions are met:

  • You configure a per-request policy for use with forward proxy chaining.
  • An HTTP Header agent with the header remove operation occurs before the Proxy Select agent within a policy.

When configuring a policy to remove an HTTP header, the HTTP Header agent must occur after a Proxy Select agent within the policy. When the header remove operation occurs before a Proxy Select agent, the BIG-IP APM system is unable to remove the header, because the header information has not been cached yet.

Impact

The BIG-IP APM system experiences a traffic disruption while the tmm process restarts. A failover event occurs if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file to the /shared/core/ directory.
  • The BIG-IP APM system fails over to a standby system if configured for HA.

Workaround

To work around this issue, when configuring a policy, configure HTTP Header agents that occur after Proxy Select agents with a header remove operation. Configuring the header remove operation before a Proxy Select agent is not a valid configuration.
