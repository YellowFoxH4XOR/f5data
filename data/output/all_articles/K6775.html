Known Issue

This is the result of a known issue. When the BIG-IP system is licensed for hardware compression, if compression is enabled for any virtual server, the Linux top utility, SNMP, and the BIG-IP performance graphs report CPU 0 usage at 100 percent, and continue to do so even after compression is disabled on all virtual servers.

When the BIG-IP system is configured to use compression, it starts the tm_comp process. Once started, the tm_comp process appears to use 100 percent of CPU 0. As a result, the tm_comp process is running, and incorrect usage metrics are displayed in the statistics section of the BIG-IP LTM Configuration utility, in SNMP, and in the top utility.

Important: Although CPU 0 appears to be fully consumed, the tm_comp process yields the CPU to other processes, as needed.

Note: This issue is also present in BIG-IP LTM 9.4, when using the tmzd process. For more information, refer to K7006: BIG-IP performance graphs report the CPU 0 usage at 100 percent if the BIG-IP system is licensed for hardware compression.

F5 Product Development is tracking this issue as CR47329.

Workaround

You can work around this issue by re-booting the affected BIG-IP system
