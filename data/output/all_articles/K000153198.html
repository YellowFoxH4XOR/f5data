Description

In certain scenarios, you may want to permit legitimate traffic for any "unknown" bot signature User-Agent. However, the Bot Defense profile does not provide a direct option to create custom bot signatures specifically for the "Unknown" category.

Environment:

BIG-IP Advanced WAF
Bot Defense Profiles

Cause

None

Recommended Actions

Creating a custom bot signature to manage traffic from "Unknown" bot categories can only be achieved through either an iRule or an LTM Policy. Below are two options:


Option 1: iRule for the Unknown Bot Signature

For example, to allow traffic matching the "ksoap2" User-Agent string, the following iRule can be used:

 

when BOTDEFENSE_ACTION {  
    if { [HTTP::header exists "User-Agent"] } {  
        if { [HTTP::header "User-Agent"] contains "ksoap2-android/2.6.0+" } {  
            BOTDEFENSE::action allow  
        }  
    }  
}


Option 2: LTM Policy for Unknown Bot Signatures

  1. Original Bot Defense Profile: /Common/test1.
  2. New Bot Defense Profile: Create a new profile named /Common/test2-disable-alarm-unknown-bots, mirroring the configuration of the original profile. Modify the Unknown bot mitigation setting in this new profile from rate-limit to none.
  3. LTM Policy Creation: Create an LTM policy as follows and attach it to the VIP:

ltm policy /Common/test-policy {  
    controls { bot-defense }  
    draft-copy /Common/Drafts/test-policy  
    requires { http }  
    rules {  
        rule-default {  # Default rule sends traffic to the original bot defense profile (test1)
            actions {  
                0 {  
                    bot-defense  
                    enable  
                    from-profile /Common/test1  
                }  
            }  
            ordinal 1  
        }  
        rule-ksoap2 {  # Custom rule checks User-Agent and directs matching traffic to test2 profile
            actions {  
                0 {  
                    bot-defense  
                    enable  
                    from-profile /Common/test2-disable-alarm-unknown-bots  
                }  
            }  
            conditions {  
                0 {  
                    http-header  
                    name User-Agent  
                    contains  
                    values { ksoap2-android }  
                }  
            }  
        }  
    }  
    strategy /Common/first-match  
}

 

  • The default rule sends all traffic to the original Bot Defense profile /Common/test1.
  • The specific rule checks if the User-Agent header contains "ksoap2-android". If a match is found, traffic is directed to the newly created Bot Defense profile /Common/test2-disable-alarm-unknown-bots, where mitigation actions such as rate-limit and alarms for unknown bots are disabled (set to "none").
  • For all other unknown bots not matching the "ksoap2-android" rule, traffic is sent back to the original Bot Defense profile (/Common/test1).
  • This approach gives granular control over unknown bot categories, allowing specified legitimate traffic to bypass mitigation actions while maintaining protection against other bots.
