Known Issue

The BIG-IP system may not persist connections correctly when cookie hash persistence is enabled. This issue occurs when the following condition is met:

  • The selected pool member changes the cookie value

The BIG-IP system creates a persistence entry based on the cookie value from the request. If the selected pool member changes the value of the cookie in a later response, subsequent requests may not match the existing persistence record for the current session. As a result, the system may load balance subsequent requests and create a new persistence record based on the new cookie value.

For example, the following steps take place when this issue occurs:

  1. The BIG-IP system accepts an initial HTTP request from a client that contains no cookie, makes a load balancing decision, and forwards the request to the selected pool member A.
  2. Pool member A sets a cookie in its response header that matches the Cookie Name in the cookie hash persistence profile.
  3. The BIG-IP system processes the response, records the composed value in its persistence table, and forwards the response to the client.
  4. The client sends a subsequent request that contains the cookie with the expected value, matching the previous cookie hash persistence entry.
  5. The BIG-IP system processes the request and persists the request to pool member A.
  6. Pool member A sets a different/new cookie value in its response header.
  7. The BIG-IP system processes the response, ignores the different/new cookie value, and forwards the response to the client.
  8. The client sends a subsequent request with the different/new cookie value.
  9. The BIG-IP system parses the request, finds no record in its persistence table, and uses the configured load balance mode to select a new pool member B.
  10. The BIG-IP system creates a new record in the persistence table and sends the request to the newly-selected pool member B.

Impact

The affected virtual server may fail to persist sessions as it is expected to.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system may fail to persist client connections to the correct pool members.
  • The persistence table may contain two records for the same connection.
