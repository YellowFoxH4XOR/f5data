Known Issue

This is the result of a known issue. The CLIENTSSL_CLIENTCERT iRule event is triggered when the system receives a certificate from the client during the SSL handshake.

If a client resumes a previously-negotiated SSL session, the BIG-IP system incorrectly triggers the CLIENTSSL_CLIENTCERT event, even though the client did not present the certificate when resuming the session.

F5 Product Development tracked this issue as ID 226818 (formerly CR142205), and it was fixed in BIG-IP version 10.2.1.

For information about upgrading, refer to the BIG-IP release notes.

Workaround

If this issue is causing the iRule to fail, you can work around the issue by forcing the client to authenticate when reusing an SSL session. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select Client from the SSL menu.
  5. Click the appropriate Client SSL profile.
  6. Select Advanced from the Configuration drop-down menu.
  7. In the Client Authentication section, select Always from the Frequency drop-down menu.
  8. Click Update.
