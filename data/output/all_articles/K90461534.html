Description

You may want to understand the cause of the following logs:

notice mcpd[<pid>]: 01070921:5: Virtual Server '/<partition>/<virtual_server_name>' on partition '<partition>' <user_action> by user '%cmi-mcpd-peer-<IP>'

In this example, 192.168.0.1 is the IP address assigned for config sync:

notice mcpd[6426]: 01070921:5: Virtual Server '/Common/vs_test' on partition 'Common' disabled by user '%cmi-mcpd-peer-192.168.0.1'.

In K04763728, it explains each fields as below however you may find there is not existing username called %cmi-mcpd-peer-<IP>, for example, %cmi-mcpd-peer-192.168.0.1:

  • <PID> is the process ID for the mcpd process.
  • <partition> is the name of the partition on which the virtual server resides.
  • <virtual_server_name> is the name of the virtual server.
  • <user_action> is the user requested action and is either enabled or disabled.
  • <username> is the name of the user performing the action.

Environment

  • ConfigSync in HA pair

Cause

The log message indicates a virtual server is disabled on the peer device and then following a configuration sync action. The username %cmi-mcpd-peer-<Configsync_IP> is an internal account for configuration sync actions. You may also notice a similar log but with user_action as enabled if the virtual server is enabled from its previous disabled status.

Recommended Actions

You may safely ignore this log message if this virtual server is expected to be disabled/enabled. You may also want to follow K04763728 to enable/disable a virtual server.
