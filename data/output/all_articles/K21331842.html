Known Issue

Certain iRules commands may cause the Traffic Management Microkernel (TMM) to send duplicate Online Certificate Status Protocol (OCSP) requests and leak memory.

This issue occurs when all of the following conditions are met:

  • You have a Secure Sockets Layer (SSL) virtual server configured to use a Client SSL profile with OCSP stapling enabled.
  • The virtual server is also configured with an iRules command that triggers an SSL handshake, such as the SSL::renegotiate command.
  • The virtual server processes a request for a certificate for which an OCSP response has not been cached.

When processing an SSL request, TMM sends an initial OCSP request to verify the certificate. OCSP stapling pauses the SSL handshake state machine until the OCSP response is received. However, if an iRule executes a command such as the SSL::renegotiate command at this point in the process, the command can trigger the SSL handshake state machine to start again, causing TMM to send a second OCSP request for the same handshake. As a result, TMM fails to release memory used for the initial OCSP request.

Impact

TMM memory usage increases over time and may eventually trigger aggressive reaping mode.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM memory usage increases over time.
  • In the /var/log/ltm file, you observe warning messages similar to the following example:

    warning tmm[11300]: 011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (0) (global memory) 115 Connections killed.
