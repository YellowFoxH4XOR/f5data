Description
When following K73827442 to force a file system check with /forcefsck does not run though for v15.1.0.4.
 

Environment

  •  BIG-IP VE
  •  v15.1.0.4 and later
     

Cause
After CentOS 7.3 is used as Base OS, /forcefsck file does not work due to startup mechanism was changed.
Note: For more information refer to: K3645: Base operating system information for the BIG-IP host system
 

Recommended Actions

To running the fsck command during a system boot.
 Note: Before running fsck, you should use root user, you should enable root account if it is disabled. 

  1. Backup a copy of fstab
    cp /etc/fstab /etc/fstab.orig
  2. Set 1 to pass option(6th field) for / partition  and 2 for other partition in /etc/fstab.
    Example:
    diff fstab.orig fstab
    before:
     > UUID=36c39cf5-5179-4a46-ad41-ec7ff95246d0    /    ext4    defaults,noatime,discard    1 0
     > UUID=81ea50ec-462e-4616-aba8-99b4404d32a2    /config    ext4    defaults,noatime,discard    1 0
     > UUID=1d937c0f-cb6d-40b7-b4fa-b400d415dfe5    /usr    ext4    defaults,noatime,discard,ro    1    0
     > UUID=5c283130-0303-4f0b-a3fb-ef0c96dbbf8f    /var    ext4    defaults,noatime,discard,noexec    1    0
     > UUID=4f376fbd-6200-4952-bb14-16a359ac0357    /appdata    ext3    defaults,noatime    1 0
    after:
     < UUID=36c39cf5-5179-4a46-ad41-ec7ff95246d0    /    ext4    defaults,noatime,discard    1 1
     < UUID=81ea50ec-462e-4616-aba8-99b4404d32a2    /config    ext4    defaults,noatime,discard    1 2
     < UUID=1d937c0f-cb6d-40b7-b4fa-b400d415dfe5    /usr    ext4    defaults,noatime,discard,ro    1    2
     < UUID=5c283130-0303-4f0b-a3fb-ef0c96dbbf8f    /var    ext4    defaults,noatime,discard,noexec    1    2
     < UUID=4f376fbd-6200-4952-bb14-16a359ac0357    /appdata    ext3    defaults,noatime    1 2
     ---

     
  3. Create /etc/default/grub file and add the value inside.       
    vi /etc/default/grub  
    value:
    GRUB_CMDLINE_LINUX_DEFAULT="fsck.mode=force" 
    to exit type:
    :wq!
     
  4. Reboot the BIG-IP device:
    reboot
     
  5. Check by journalctl command               
    journalctl --boot | grep -i "File System Check"

    Example:
        Apr 21 17:58:18 localhost systemd[1]: Starting File System Check on /dev/disk/by-uuid/36c39cf5-5179-4a46-ad41-ec7ff95246d0...
      Apr 21 17:58:18 localhost systemd[1]: Started File System Check on /dev/disk/by-uuid/36c39cf5-5179-4a46-ad41-ec7ff95246d0.
      Apr 21 17:58:18 localhost systemd[1]: Starting File System Check on /dev/disk/by-uuid/1d937c0f-cb6d-40b7-b4fa-b400d415dfe5...
      Apr 21 17:58:18 localhost systemd[1]: Started File System Check on /dev/disk/by-uuid/1d937c0f-cb6d-40b7-b4fa-b400d415dfe5.
      Apr 21 17:58:24 localhost systemd[1]: Starting File System Check on /dev/disk/by-uuid/81ea50ec-462e-4616-aba8-99b4404d32a2...
      Apr 21 17:58:24 localhost systemd[1]: Starting File System Check on /dev/disk/by-uuid/4f376fbd-6200-4952-bb14-16a359ac0357...
      Apr 21 17:58:24 localhost systemd[1]: Starting File System Check on /dev/disk/by-uuid/5c283130-0303-4f0b-a3fb-ef0c96dbbf8f...
      Apr 21 17:58:24 localhost systemd[1]: Started File System Check on /dev/disk/by-uuid/5c283130-0303-4f0b-a3fb-ef0c96dbbf8f.
      Apr 21 17:58:24 localhost systemd[1]: Started File System Check on /dev/disk/by-uuid/81ea50ec-462e-4616-aba8-99b4404d32a2.
      Apr 21 17:58:24 localhost systemd[1]: Started File System Check on /dev/disk/by-uuid/4f376fbd-6200-4952-bb14-16a359ac0357
     
  6. Remove /etc/default/grub and /etc/fstab file:
    rm -rf /etc/default/grub

    rm -rf /etc/fstab

  7. Revert /etc/fstab to original setting by running the command below:
    mv /etc/fstab.orig /etc/fstab
