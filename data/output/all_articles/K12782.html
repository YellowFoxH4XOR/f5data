Known Issue

This is the result of a known issue. When a Single-Sign On (SSO) profile has been applied to an access policy in a high availability (HA) deployment, and the active member of the HA pair goes down, users are unable to authenticate using SSO. This issue occurs because the keys on the active unit are not synchronized to the standby unit. When the standby unit becomes the active member, it does not have the keys necessary to authenticate users.

F5 Product Development is tracking this issue as ID 350269.

Workaround

If the active member is offline and the standby unit becomes the active member, you must restart the access policy daemon (apd) in order to generate a new key pair. To do so, perform the following procedure:

Restarting the apd process

  1. Log in to the BIG-IP command line of the standby unit.
  2. To restart the apd process, type the following command:

    bigstart restart apd
  3. Confirm that users are now able to authenticate.
