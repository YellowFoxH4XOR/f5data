K000160037: Virtual server not working after applying Hybrid KEM Cipher Group

Type
Support Solution
Published
2026-02-17

Applies to

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source

Description

When configuring a client SSL profile on BIG-IP LTM with a cipher group that includes hybrid Key Exchange Mechanism (KEM) algorithms (such as "ML-KEM") and enabling only TLSv1.2, all virtual servers associated with the profile may become unreachable. This issue occurs immediately after applying the configuration. The symptoms include:

  • Virtual servers become unreachable when TLSv1.2 is the only enabled protocol version
  • Connectivity is restored only by re-enabling all TLS versions (TLSv1.0, TLSv1.1, and TLSv1.2)
  • TLS 1.2 handshake failures when hybrid KEM algorithms are prioritized in the cipher group

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1
  • Platform: F5-BIG-LTM-R4600, C131
  • Configuration:
    • Client SSL profile using a cipher group with hybrid KEM algorithms (e.g., "ML-KEM" or "ecb-default-mlkem")
    • Only TLSv1.2 enabled (TLSv1.0 and TLSv1.1 disabled)
    • External (Internet-facing) load balancers
  • Recent action: Applied a new client SSL profile with the above cipher group and TLS version settings

Cause

Bug ID 2064505

Recommended Actions

Apply the workaround documented in Bug ID 2064505:

  1. Access the BIG-IP configuration interface
  2. Navigate to the affected client SSL profile
  3. Modify the cipher group configuration to ensure hybrid KEM algorithms (such as "ML-KEM") are not listed first in the cipher rule
  4. Reorder the cipher group so that other compatible ciphers appear before hybrid KEM algorithms
  5. Save and apply the updated configuration
  6. Verify that virtual servers are reachable with only TLSv1.2 enabled
  7. Test connectivity to confirm the issue is resolved
  8. Monitor for any further issues

Note: Consider upgrading to a future software release that addresses Bug ID 2064505 when it becomes available (already fixed in version 21.0.0).

Additional Information

  • The issue is specific to configurations where hybrid KEM algorithms are prioritized (listed first) in the cipher group and only TLSv1.2 is enabled
  • Reverting to allow all TLS versions (TLSv1.0, TLSv1.1, and TLSv1.2) restores connectivity but may not be acceptable for security compliance requirements
  • The workaround does not require disabling hybrid KEM support entirely; it only requires reordering the cipher list
