Description

This article explains how to get logs and enable logging for the Aspen Mesh istio-proxy sidecar.

Environment

  • Aspen Mesh

Cause

None

Recommended Actions

Impact of Procedure: This procedure should have no impact.

Viewing the logs on the sidecar assumes that you have the appropriate privileges.

  • Syntax:
    oc -n (NAMESPACE) logs [-f] [-p] (POD | TYPE/NAME) [-c CONTAINER]

  • Output the log to terminal:
    oc -n mynamespace logs mypod -c istio-proxy

  • Write the log externally:
    oc -n mynamespace logs mypod -c istio-proxy &>  ~/mypod.log

  • Continually log output to the terminal:
    oc -n mynamespace logs -f mypod -c istio-proxy

Modify the logging level on the istio-proxy sidecar

Impact of Procedure: This procedure should have no impact however, it's not recommended to leave in debug state.

  • To turn on Debugging
    oc -n <NAMESPACE> exec <POD> -c istio-proxy -- curl -X POST “localhost:15000/logging?filter=debug” -s

  • Return to normal Setting
    oc -n <NAMESPACE> exec <POD> -c istio-proxy -- curl -X POST “localhost:15000/logging?filter=warning” -s

    Example:
    oc -n mynamespace exec mypod -c istio-proxy -- curl -X POST “localhost:15000/logging?filter=debug” -s
    oc -n mynamespace logs mypod -c istio-proxy &>  ~/mypod.log
    oc -n mynamespace exec mypod -c istio-proxy -- curl -X POST “localhost:15000/logging?filter=warning” -s
