Known Issue

Modifying the BIG-IP system time may cause high availability (HA) devices to display an incorrect synchronization status.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP devices are configured as a HA device group.
  • The BIG-IP HA devices display that they are in synchronization (In-Sync).
  • You modify the time of one of the BIG-IP devices to a date and/or time that is earlier than the currently configured time.
  • You modify a BIG-IP HA device shared configuration object.

Impact

The BIG-IP HA synchronization status is not updated.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After making a configuration change to either of the BIG-IP HA devices, both devices continue to display the In-Sync status.

Workaround

To work around this issue, you can manually correct the synchronization status of the BIG-IP devices. To do so, perform one of the following procedures:

  • Forcing a ConfigSync to another device with the farthest future system time
  • Modifying a synchronized object on the peer device with the farthest future system time

Impact of workaround: Performing either of the following procedures should not have a negative impact on your system.

Forcing a ConfigSync to another device with the farthest future system time.

  1. Log in to the TMOS Shell (tmsh).
  2. To force a configuration synchronization (ConfigSync) to the BIG-IP HA device with the farthest future system time, use the following command syntax:

    modify /cm device-group <device group name> devices modify { <sync-to-device-name> { set-sync-leader } }

    For example:

    modify /cm device-group sync-failover-device-group devices modify { bigip1.test.local { set-sync-leader } }

  3. Exit tmsh by typing the following command:

    quit

Modifying a synchronized object on the peer device with the farthest future system time.

  1. Log in to the BIG-IP HA device with the farthest future system time.
  2. Modify a synchronized object such as a pool, virtual server, monitor or node.

Note: After completing the object modification, the BIG-IP HA device should display the Changes Pending status.
