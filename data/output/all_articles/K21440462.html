Description

After upgrading device to 16.x access to the virtual servers fails and error messages similar to the following are logged to /var/log/ltm: 

err tmm1[26391]: 011f0007:3: http_process_state_prepend - Invalid action:0x107061 clientside (<client IP>:<src port> -> <VS IP>:<VS port>) ((null connflow)) (Client side: vip=<vipname> profile=http addr=<VS IP> port=<VS port> rtdom_id=0 client_ip=<client IP>)

err tmm[26391]: 011f0007:3: http_process_state_prepend - Invalid action:0x107061 clientside (<client IP>:<src port> -> <VS IP>:<VS port>) ((null connflow)) (Client side: vip=<vipname> profile=http pool=<pool name> client_ip=<client IP>)

Note: When reset cause logging is enabled, or a tcpdump is taken, resets sent virtual servers have the reset cause: HTTP internal error (bad state transition).
 

Environment

  • BIG-IP
  • Upgrade
  • Multiple iRules attached to virtual servers

Cause

An attached iRule uses a HTTP_REQUEST event with event disable, event disable all, or TCP::close. This issue is tracked by F5 as Bug ID 1075205. If the vitual server has an Access profile attached that uses a per-request access policy, see Bug ID 1100081.

Recommended Actions

  1. Review virtual server attached iRules. 
  2. Check each iRule for the combination of  "when HTTP_REQUEST" event and any of the following: 

    Example:
    TCP::close
    event disable; or event disable all

     
  3. Remove or comment lines (place the # symbol at the beginning of the line) in the iRule for 'TCP::close;' and 'event disable;' as below:

    Example:
    #TCP::close
    #event disable
