Description

This article addresses situations where BIG-IP LTM virtual servers reset connections with the error "F5RST: HTTP header size exceeded by client" visible in packet captures, but no corresponding error logs appear in '/var/log/ltm'. This makes it difficult to determine the exact HTTP header size causing the reset and to configure an appropriate Maximum Header Size value in the HTTP profile.

Environment

  • BIG-IP LTM [Virtual server with HTTP profile configured]
  • TCP resets visible in packet captures with "F5RST: HTTP header size exceeded by client" message
  • No related error logs in '/var/log/ltm'
  • Connection failures despite increasing the Maximum Header Size in the HTTP profile
  • System variable "tm.rstcause.log" set to "Disable" (default setting)
  • HTTP/1.x traffic (for HTTP/2 traffic, RST causes are intentionally not logged - K000154583)

Cause

The client sent an HTTP header that exceeded the Maximum Header Size configured in the HTTP profile. The absence of logs in '/var/log/ltm' occurs because the system variable "tm.rstcause.log" is disabled by default, which suppresses logging of TCP RST causes. 

Answer/Recommended Actions

To enable logging and determine the exact header size causing the issue:

  1. Enable TCP RST cause logging by running the following command in tmsh: [K13223]
    tmsh modify sys db tm.rstcause.log value enable
     Note: No system reboot is required; the change takes effect immediately. 

  2. Reproduce the issue to generate log entries in occurs '/var/log/ltm'.

  3. Review the logs to identify the exact HTTP header size that triggered the reset. Look for messages similar to:

    tmm[<pid>]: 011f0005:3: HTTP header (<size>) exceeded maximum allowed size of <configured_limit> (Client side: vip=<vs_name> profile=<profile_name> pool=<pool_name> client_ip=<client_ip>)

  4. Adjust the Maximum Header Size in the HTTP profile based on the findings: [K8482]

    • Log in to the Configuration utility
    • Navigate to Local Traffic > Profiles > Services > HTTP
    • Select the HTTP profile associated with your virtual server
    • Locate Maximum Header Size
    • Adjust the value to accommodate the required header size
    • Click Update

    Important: Allocate only the necessary bytes to handle HTTP headers. Excessive values may result in memory exhaustion since buffer space is allocated for each request.

  5. After troubleshooting is complete, disable TCP RST cause logging to prevent excessive logging:

    tmsh modify sys db tm.rstcause.log value disable
