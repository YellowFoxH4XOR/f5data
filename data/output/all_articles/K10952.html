The BIG-IP ASM cookie does not support the domain attribute. Therefore, if a client cookie is set with a domain attribute, the corresponding BIG-IP ASM cookie may not be sent to other hosts in the same domain in subsequent requests.

The domain attribute in a cookie tells the client browser to send the cookie when requesting a resource located in the specified domain. For example, a company may send a cookie with the domain attribute for the sites www.example.com and secure.example.com.

When a client visits www.example.com, which is protected by the BIG-IP ASM system, the client receives a cookie from the web server with the domain attribute of domain=.example.com. The BIG-IP ASM system parses the responses for the Set-Cookie header, performs a hash on the cookie, and inserts the hash value into the BIG-IP ASM Main cookie. The BIG-IP ASM system then uses the Main cookie to enforce elements in the security policy.

When the BIG-IP ASM system sets the Main cookie, it does not contain the domain attribute that is specified in the client cookie. As a result, when the client visits an alternate site in the domain, such as secure.example.com, the browser sends the web server cookie. However, the Main cookie is not sent in the request. As a result, the BIG-IP ASM system generates the Modified domain cookie violation.

Note: For more information about the Modified domain cookie violation, refer to K5907: BIG-IP ASM violation: Modified domain cookie.

F5 Product Development tracked a Request for Enhancement (RFE) to add support for domain cookies as ID 227227 (formerly CR60624). This functionality was added in BIG-IP 11.0.0.

For information on upgrading refer to K2200: Most recent versions of F5 software.
