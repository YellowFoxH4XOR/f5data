Topic

You should consider using this procedure under the following conditions:

  • You have a BIG-IP cloud instance deployed on Amazon Web Services (AWS).
  • You want to migrate the instance to a newer version of the BIG-IP system, retaining the configuration of the instance.

Description

Changing the BIG-IP licensing model, a subscription or Bring-Your-Own-License (BYOL), or upgrading from a single slot BIG-IP instance requires launching a new AWS BIG-IP instance. The following procedure covers the steps required to launch a new BIG-IP instance and how to configure the instance retaining the configuration of the originating instance.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Access to AWS
  • Administrative access to the deployed BIG-IP instance

Procedures

Migrating an originating BIG-IP instance to a new AWS instance

To migrate a deployed AWS BIG-IP instance to a newly created AWS BIG-IP instance, perform the following procedure:

Impact of procedure: F5 recommends performing the following procedure during a scheduled maintenance window. Migrating the BIG-IP instance may require you to perform additional licensing steps.

Obtain the following Elastic Network Interfaces (ENI) configuration information from the Instance Description tab of the originating BIG-IP instance:

  • The private IPs (IPv6 and IPv4 addresses) and their interface mappings
  • All secondary private IPs (IPv6 and IPv4 addresses) and their interface mappings
  • All subnet IDs
  • All configured elastic IP address and the associated private IP addresses
  • All associated security groups
  • The key pair name used by the instance for SSH access

    Note: The bulk of the ENI information (excluding the key pair name) can be derived from the network interfaces pop-up links. 

Obtain the following configured tag information from the Instance Tags tab of the originating BIG-IP instance:

  • Configured keys and values
  1. Ensure that the ENIs of the originating BIG-IP instance, are set with the Delete on termination setting is not selected (set to false).
  2. Create a UCS backup of the originating BIG-IP instance and download it to your local device. 

    For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive and K9420: Installing UCS files containing encrypted passwords or passphrases.

  3. Obtain the fully qualified domain name (FQDN) host name of the originating BIG-IP instance by typing the following TMOS Shell (tmsh) command:

    list /sys db hostname

  4. Shut down the originating BIG-IP instance.
  5. Terminate the originating BIG-IP instance.
  6. Launch a new BIG-IP instance and manually configure it with the identical (ENIs, security groups, and tags) settings gathered from the originating BIG-IP instance.

    Note: Configuration of static private IP addresses may require editing the instance after the instance is initially deployed (prior to any BIG-IP configuration and licensing), and then associating the public elastic IP addresses to the interfaces configured with the correlating static private addresses.

  7. After the new BIG-IP instance is accessible, type the following tmsh commands:

    modify /auth user admin prompt-for-password

    save /sys config

  8. Log in to the BIG-IP instance using the Configuration utility.
  9. Follow the presented steps to license the new BIG-IP instance.

    Note: When using BYOL for the BIG-IP instance, contact F5 Technical Support to request a license Allow-Move of the existing BYOL license.

  10. Set the new BIG-IP instance FQDN host name to match the exact host name of the originating BIG-IP instance.
  11. Upload the originating BIG-IP UCS file to the new BIG-IP instance.
  12. Restore the UCS file to the BIG-IP instance using the following tmsh command syntax:  

    tmsh load sys ucs <ucs file name> no-license

    If the UCS load fails due to a decryption error, refer to K9420: Installing UCS files containing encrypted passwords or passphrases.

  13. Save the BIG-IP configuration by typing the following command:

    save /sys config partitions all

  14. Reboot the BIG-IP instance by typing the following command: 

    reboot

  15. Access the AWS BIG-IP instance and verify its functionality.
