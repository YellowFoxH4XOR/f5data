K4412: BIG-IP and 3-DNS may fail to set the date correctly during boot

Type

Published

Updated
2023-02-21
Status

Applies to

  • 3-DNS: 4.6.4
  • BIG-IP 4.X: 4.6.4
Source

Topic

BIG-IP and 3-DNS use ntpdate to adjust the time when they boot. If the system time needs to be adjusted significantly, you must run ntpdate before starting ntpd.

If BIG-IP or 3-DNS are booted when they are not connected to the network, or booted when they are connected to a switch that has blocked the ports used by BIG-IP or 3-DNS, ntpdate cannot change the time.

To work around this problem, change the retry timeout for ntpdate, using the following steps:

  1. Log in to the command line.
  2. Edit the /etc/bigstart/scripts/ntpdate-ctrl file.
  3. Locate the following line:

    OPTIONS=

  4. Change the line to appear as follows:

    OPTIONS="-t <time>"

    Replace <time> with the amount of time, in seconds, that you want ntpdate to continue to retry, multiplied by five. You must multiply by five because the <time> value is composed of .2 second units.

    For example, to set the retry period to sixty seconds, add the following line:

    OPTIONS="-t 300"

Sixty seconds should be a sufficient length of time to allow the switch to unblock the ports to which BIG-IP or 3-DNS are connected.
