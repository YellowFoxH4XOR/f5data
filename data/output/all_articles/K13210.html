Known Issue

When one or more Virtual Local Area Networks (VLANs) in a VLAN group trigger a VLAN failsafe event, the BIG-IP system may not take the failsafe action.

This issue occurs when all of the following conditions are met:

  • At least one VLAN in a VLAN group experiences a failure that would normally cause a VLAN failsafe event
  • At least one VLAN in the same group is not experiencing VLAN failsafe events

The system will not take the defined failsafe action until all members of the group are reporting failsafe events.

Impact

The system may not take the defined VLAN failsafe action, which may result in impaired ability to pass traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • At least one VLAN in a VLAN group is known to be failing, but your BIG-IP system does not log a VLAN failsafe error message and does not take a VLAN failsafe action, such as fail-over and restart.

    For example, the following tmsh show net vlan-group command output indicates that the 1.1 interface is down; however, the output does not write HA vlan_fs error messages to the /var/log/ltm file for vlan1:

    Net::Vlangroup: MyVlanGroup(ifname: MyVlanGroup)
    ---------------------------------------------------
    Interface Name  vlan1
    Mac Address     0:1:d7:92:a3:43

    Net::Interface
    Name  Status  Bits   Bits  Errs  Errs  Drops  Drops  Colli
                    In    Out    In   Out     In    Out  sions
    ----------------------------------------------------------
    1.1     down  6.6M  30.6K     0     0  11.6K      0      0

    -------------------------------
    Interface Name  vlan2
    Mac Address     0:1:d7:92:a3:44

    Net::Interface
    Name  Status  Bits   Bits  Errs  Errs  Drops  Drops  Colli
                    In    Out    In   Out     In    Out  sions
    ----------------------------------------------------------
    1.3       up  6.6M  19.2K     0     0  11.7K      0      0

  • While a VLAN is known to be failing, the tmsh show sys ha-status command output does not display vlan-failsafe failures.

    For example:

    Sys::HA Status
    Feature               Key       Action                        Fail
    ------------------------------------------------------------------
    vlan-failsafe         vlan1     restart-all                   no
    vlan-failsafe         vlan1     restart-all                   no
    vlan-failsafe         vlan2     restart-all                   no
    vlan-failsafe         vlan2     restart-all                   no

    Note: The word vlan-failsafe is spelled incorrectly in the ha-status command output in BIG-IP 10.2.x.

  • Your BIG-IP system takes a VLAN failsafe action and logs HA vlan_fs error messages to the /var/log/ltm/ file only when all VLANs in a VLAN group are reporting a VLAN failsafe event.

    For example:

    01140029:5: HA vlan_fs vlan1 fails action is reboot.
    01140029:5: HA vlan_fs vlan2 fails action is reboot.

Resolution

Status

F5 Product Development has assigned ID 363547 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.1.0
10.2.3		K2200: Most recent versions of F5 software
Hotfix10.2.2 HF-4K9502: BIG-IP hotfix matrix

Important: Although BIG-IP 10.2.1 is listed in the Applies to (see versions) box, this issue is occurs only in BIG-IP 10.2.1 HF-1 and later. The base version of 10.2.1 is not affected.

Workaround

While there is no way to prevent or work around this issue, you can recover from this issue by setting the affected BIG-IP system to Force to Standby and failing over to the high availability peer. For more information about this process, refer to the Managing Failover and Working with Device Groups chapters of the BIG-IP Device Service Clustering: Administration manual.
