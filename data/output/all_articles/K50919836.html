Description
BIG-IP iQuery port 4353 is accessible over the management interface and the PCI DSS Standard has requirements that prohibit the use of TLSv1.0 along with some older ciphers (DES) and encryption methods (CBC). A security scan report may detect the use of TLSv1.0 and old ciphers with allowed port 4353 and mark this as a failure. To prevent a vulnerability, either the weak ciphers can be disabled or the port can be disabled.

For BIG-IP versions earlier than 14.1.0, follow the procedure in this article to disable port 4353 on the management interface. In BIG-IP 14.1.0 and later you must use the Configuration utility or the TMOS shell (tmsh) to disable port 4353 on the management interface. For more information, refer to K46122561: Restrict access to the BIG-IP management interface using network firewall rules.

Alternatively, you can modify the TLS version and cipher that big3d is configured to use rather than disable the port. To do so refer to:

  • K71057100: Configuring the minimum TLS version for iQuery.
  • K31434426: Configuring the cipher strength for iQuery

Environment

  • BIG-IP LTM
  • Management interface
  • iQuery
  • TLSv1.0

Cause
None

Recommended Actions

Impact of Procedure: F5 device will not be discoverable via the management interface. Also ConfigSync and DNS synchronization via the management interface will not work. You must use self IP addresses instead.

Note: Beginning in BIG-IP 14.1.0 instead of iptables you must use the Configuration utility or the TMOS shell (tmsh) to disable access to the management interface on the BIG-IP system. To do so, refer to the following article: K46122561: Restrict access to the BIG-IP management interface using network firewall rules.

  1. Log in to the BIG-IP command line with the root account.
  2. Use the following command syntax to disable port 4353 on the management interface:
    iptables -A INPUT -p udp --dport 4353 -d <management-ip>/32 -j DROP
    iptables -A INPUT -p tcp --dport 4353 -d <management-ip>/32 -j DROP
    service iptables save

  3. Verify the disabled port by running this command:
    iptables -L

  4. (Optional) If necessary, rollback the change by enabling the port with this command syntax:
    iptables -D INPUT -p udp --dport 4353 -d <management-ip>/32 -j DROP
    iptables -D INPUT -p tcp --dport 4353 -d <management-ip>/32 -j DROP
    service iptables save

  5. Verify the port is disabled (or enabled) by connecting to the management IP address with telnet on port 4353:
    telnet <management IP address> 4353

Additional Information
iQuery is used with TCP port 4353 and must be allowed between BIG-IP DNS systems. BIG-IP DNS synchronization group members use TCP port 4353 to communicate. An iQuery connection is an SSL connection on port 4353 from a gtmd process to the big3d process on a remote or local BIG-IP. When big3d starts, it listens for port 4353 on all configured self IP addresses and the management interface IP address (Configuration utility).  By default, iQuery establishes an SSL connection to the remote big3d process using version TLS1.0 or higher.

BIG-IP also uses TCP port 4353 for ConfigSync on all configured self IP addresses and the management interface IP address. If you disable port 4353 on the management interface, ConfigSync and DNS synchronization will continue to work if configured on self IP addresses.
