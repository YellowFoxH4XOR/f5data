Description

  • You want to use AWS Elastic IP addresses to inherit the proper state from a Virtual Server hosted in a DNS server object.
  • The LTM resides in a cloud with Elastic IP Virtual Server configured and have dependencies configured on the DNS Device from Server objects to those LTM Elastic IP VIPs as they reside in a cloud.

Environment

  • BIG-IP DNS and LTM in separate Data Centers.
  • AWS Elastic IP addresses

Cause

Due to the was GTM/DNS matches probes to virtual servers, the use of the same Elastic IP across several virtual servers can cause issues with proper reporting.

Recommended Actions

It is necessary in this situation to set the ltm-name on the DNS device to mirror the virtual server it's supposed to be getting status for.
The ltm-name directly tells the GTM/DNS to probe that specific virtual server by the name and get the status.

  1. big3d has an order in which it tries to match probes to virtual servers.
    - ltm-name
    - name
    - IP
     
  2. You will need to run the following command on the BIG-IP DNS to set the ltm-name.  There is no option to set ltm-name within the WebUI:

    # tmsh modify gtm server /Common/Server1 virtual-servers modify { /Common/Virtual_Server_using_Elastic_IP { ltm-name /Common/LTM_Virtual_Server_1 } }
     
  3. Then save the configuration

    # tmsh save sys config gtm-only
     
  4. On DNS device under GSLB Server: Virtual Servers:

    Virtual_Server_using_Elastic_IP {
                app-service none
                description none
                destination 10.0.0.1:https   <-------Elastic IP address
                enabled
                explicit-link-name none
                limit-max-bps 0
                limit-max-bps-status disabled
                limit-max-connections 0
                limit-max-connections-status disabled
                limit-max-pps 0
                limit-max-pps-status disabled
                ltm-name /Common/LTM_Virtual_Server_1    <-----Name of VS on LTM
                monitor none
                translation-address none
                translation-port any
                depends-on none
            }

    On LTM it looks below:

    ltm virtual LTM_Virtual_Server_1 {
        creation-time 2021-10-04:08:16:32
        description "Virtual Mapped to DNS/GTM with EIP"
        destination 192.168.0.1:https
        ip-protocol tcp
        mask 255.255.255.255
        pool my_pool_1
        profiles {
            tcp { }
            http { }
        }
        source 0.0.0.0/0
        translate-address enabled
        translate-port enabled
        vs-index 1
    }
     
  5. In order to have the Elastic IP be used for on the DNS probing, the ltm-name has to be used.
