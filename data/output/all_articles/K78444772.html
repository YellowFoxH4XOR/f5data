K78444772: Script task stuck on ''Running'' status

Type
Support Solution
Published
2022-11-03
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X
Source
https://my.f5.com/manage/s/article/K78444772

Description
When deploying a script task from the BIG-IP towards managed BIG-IP device(s), the task status on Script Log appears to be stuck in Running state even after the timeout (default 600s) has elapsed. Cancelling the script run does not help either at which point the status will be stuck in Cancel Requested. From this state, BIG-IQ will not advance to the next steps in the script task execution.

This occurs when BIG-IQ encounters an event or a response from the BIG-IP which the BIG-IQ is unable to handle correctly. Some of the errors you might see from BIG-IQ restjavad logs are similar to the following which result in Format specifier exception on the BIG-IQ.

Environment

  • BIG-IQ
  • BIG-IP
  • Bash script being pushed to BIG-IP via BIG-IQ's Script Management UI.

Cause
This is due to bug ID 1182177 where BIG-IQ is unable to handle failure scenarios.

Recommended Actions
Once the BIG-IQ encounters this stuck state, it will never advance to the next script task.

If the script deployment task is being deployed for a batch of BIG-IPs, a failure in one "bad" BIG-IP will result in the entire batch being stuck. An administrator may need to identity the "bad" BIG-IP(s) by checking the restjavad logs for events containing the string "Failed to run script on" using the command:

  egrep "UserScriptTaskWorker.*Failed to run script on" /var/log/restjavad\.* | awk '{print $12}' | sort | uniq

The identified "bad" BIG-IP should not be included in future script deployment tasks until the underlying issue for the failure on the "bad" BIG-IP has been resolved.

If the BIG-IQ administrator would like to get rid of the spinning wheel next to the stuck task in the BIG-IQ Script Log UI, the procedure would be:

  1. Get the ID of the stuck task using Bash CLI command:

    restcurl shared/user-script-execution?\$filter=status%20ne%20%27FINISHED%27\&\$select=name,status,id

    From the output, similar to the following, identify the stuck task and note down the value for its task "id".

    {
      "totalItems": 2,
      "items": [
        {
          "name": "Echo Test 5",
          "status": "STARTED",
          "id": "3282a130-885f-47e3-9b94-ad6b4617f140"
        },
        {
          "name": "Echo Test 4",
          "status": "CANCEL_REQUESTED",
          "id": "6af1509e-6545-4d1b-86ba-3649a0bcffe0"
        }
      ],
      "generation": 34,
      "kind": "shared:user-script-execution:userscripttaskcollectionstate",
      "lastUpdateMicros": 1666825560191665,
      "selfLink": "https://localhost/mgmt/shared/user-script-execution"
    }
     
  2. Pull the details of the stuck script task and redirect the output to a file (ie. /tmp/payload.json). In the command below, replace {SCRIPT_TASK_ID} with actual task ID value noted in Step 1.

    restcurl /shared/user-script-execution/{SCRIPT_TASK_ID} > /tmp/payload.json
     
  3. Edit the payload.json file and set all status with a value of "FAILED". This should include those tasks under the userScriptTaskStatuses.
     
  4. Send a PATCH request to the script task  using the following command, replacing {SCRIPT_TASK_ID} with actual script task ID noted in Step 1:

    curl -X PATCH localhost:8100/shared/user-script-execution/{SCRIPT_TASK_ID} -H "Content-Type: application/json" -d @/tmp/payload.json
     
  5.   BIG-IQ Script Log in the UI should now indicate the parent task and node tasks as "Failed". You may then delete the task via UI.
