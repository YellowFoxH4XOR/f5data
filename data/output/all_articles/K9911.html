Known Issue

This is the result of a known issue. On a heavily loaded FirePass controller, RSA SecurID authentication may begin to fail after working successfully for a period of time. When this issue occurs, RSA SecurID authentication does not resume until services are restarted on the FirePass controller. 

Note: The period of time before RSA SecurID authentication fails varies based on the load of the FirePass controller.
 
This issue occurs when a single RSA SecurID server is configured on the FirePass controller. If you configure multiple RSA Secure ID servers, this issue does not occur.
 
F5 Product Development tracked this issue as CR112445 and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative hotfix HF-603-1 issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround
 
You can work around this issue by configuring a second dummy RSA SecurID server in FirePass. When configuring the second server, upload the same RSA configuration file, such as the sdconf.rec file that you uploaded for the first RSA SecurID server.
 
Note: You can configure a new RSA SecurID server by selecting the Configure a new RSA SecurID Server link under the Authentication tab in the master group configuration.
