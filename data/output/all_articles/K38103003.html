Description

BIG-IP iSeries platform was rebooted unexpectedly.

/var/log/ltm has NO log indicating the cause of the reboot before the boot_marker log, but usually has a similar line to this within a minute or two after the boot_marker log:

warning chmand[7406]: 012a0004:4: Host Watchdog timeout count: 1

/var/log/sel log has entries similar to the following towards the end of the log file:

INF SMI  Memory #08 Uncorrectable ECC, DIMM[33] 6f [a1 00 21]
...
INF Sms  OS Critical Stop #46 panic(Fat) 6f [a1 61 74]

Environment

  • iSeries platform
  • All BIG-IP versions

Cause

  • Memory corruption problems on a memory DIMM that weren't correctable. The Linux kernel decided to panic, leading to reboot.
  • A single bit error (single event upset, SEU) can be detected and corrected. Two bit errors can be detected but not corrected.

Recommended Actions

  • Run All (non-interactive) tests on EUD.
    • Please refer the platform specific document in: K7172: Overview of the End User Diagnostics software
  • Once the EUD testing has completed, contact F5 Support, reference this article, and provide the EUD test output for analysis.

Additional Information

Above log can be seen at the end of the /var/log/sel log.
