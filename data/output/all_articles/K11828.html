Known Issue

Note: You can configure health monitors on the BIG-IP system for manual resume. When a node or pool member is marked down by a health monitor that is configured for manual resume, the object will remain in a Forced Offline state until it is manually re-enabled by a BIG-IP administrator. The manual resume feature allows a BIG-IP administrator to verify the health status of a node or pool member that suffered a failure before the BIG-IP system resumes load balancing traffic again.

This is the result of a known issue. After a health monitor configured for manual resume has marked a node down, the Configuration utility incorrectly reports the node as Enabled instead of Forced Offline. As a result, once the node is back online, the BIG-IP administrator may not know how to re-enable the node using the Configuration utility.

Note: This issue only affects node objects. When a health monitor configured for manual resume is assigned to a pool or pool member, this issue does not occur.

Status

F5 Product Development has assigned ID 226964 (formerly CR142468) to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper right corner of this article.

Workaround

To work around this issue, you can re-enable a node that was disabled by a health monitor configured for manual resume. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Nodes > <node IP address>.
  3. Although the Enabled (All traffic allowed) option is already selected, click it again.
  4. Click Update.
