K25071552: No Reset to Standalone option on the Secondary BIG-IQ after breaking HA

Type
Support Solution
Published
2020-05-27
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K25071552

Description

After breaking HA from Primary BIG-IQ CM, unable to do a Reset to Standalone on the Secondary as part of steps when resetting HA as the Settings page is showing no items.

Environment

BIG-IQ Centralized Manager in HA pair.

Cause

Most likely reason is either the BIG-IQ HA was broken by using the Reset to Standalone on the Primary instead of the Remove Standby button. Another possible cause is that the BIG-IQ deployment is running with less than the minimum 32Gb of RAM

Recommended Actions

To reset the BIG-IQ CM to a Standalone when the WebUI is not available, use the following CLI command syntax:
 
# sh /usr/bin/ha_reset -f <local device IP>

Optional: After resetting HA, you can also reset stuck webd and restiavad processes using the following command:
 
# bigstart restart webd restjavad

The WebUI should recover after that.

To verify the state of the BIG-IQ CM to confirm if the procedure was successful, use the following command:
 
# restcurl /shared/failover-state

Output of the command should be similar to this:
