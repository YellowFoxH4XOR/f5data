K000160896: The connection to the Route Domain Virtual Server failed with the error: "No route to host."

Description

A configured HTTP virtual server on BIG-IP LTM does not open the intended URL, resulting in browser errors such as "site cannot connect" and tcpdump errors indicating "no route to host." Accessing the backend server directly by IP works, but connections through the virtual server fail.

Symptoms:

  • The web browser displays "site cannot connect" when accessing the virtual server.
  • tcpdump on BIG-IP shows "no route to host" for the backend pool member.

Environment

  • Product: BIG-IP LTM
  • Version: 17.x, 21.x
  • Virtual server configured with route domains and VLANs

Cause

The pool member was missing the required route domain tag, causing the BIG-IP system to be unable to route traffic from the virtual server (in Route Domain, e.g., 52) to the pool member. This resulted in "no route to host" errors and connection failures.

Answer/Recommended Actions

  1. Verify Route Domain Tag on Pool Member:
    • Ensure the pool member address includes the correct route domain tag (e.g., %52).
    • Example configuration:

    ltm pool /Common/mypool {
        members {
           /Common/10.21.24.58%52:http {
               address 10.21.24.58%52
            }
        }
       monitor /Common/http
    }

  2. Check Routing and VLAN Assignments:
    • Confirm that the virtual server, self IP, and pool member are all in the same route domain and VLAN.
  3. Test Connectivity:
    • After making changes, test access to the virtual server URL and verify successful connections.
