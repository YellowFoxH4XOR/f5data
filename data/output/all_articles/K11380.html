Known Issue

This is the result of a known issue. The BIG-IP system may attempt to load one or more child rate classes before loading the corresponding parent rate classes. As a result, the child classes fail to load and rate shaping is not enforced.

F5 Product Development tracked this issue as CR96067 and it was fixed in BIG-IP LTM 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

To verify whether the child rate classes have loaded properly, run the bigpipe rate class list command. If one or more child classes failed to load, run the bigpipe load command followed by the bigpipe rate class list command until all child rate classes are loaded properly.

To ensure the BIG-IP system is enforcing the assigned rate shaping, restart TMM. To restart TMM, enter the following command:

Important: The bigstart restart tmm command will temporarily interrupt traffic processing.

bigstart restart tmm
