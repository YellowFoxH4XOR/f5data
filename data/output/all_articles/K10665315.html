Known Issue

The BIG-IP system fails to convert backslash characters in monitors after an upgrade.

This issue occurs when all of the following conditions are met:

  • You attempt to upgrade your system from BIG-IP 11.6.x to BIG-IP 12.1.x or 13.1.x.
  • Your configuration contains a local traffic policy.
  • Your configuration contains a monitor with a send or receive string that contains two backslash characters (\\) similar to the following example:

ltm monitor http /Common/<monitor_name> {
    adaptive disabled
    defaults-from /Common/http
    destination *:*
    interval 30
    ip-dscp 0
    recv “200 OK”
    send "GET /<filename>.htm\\r\\n"
    time-until-up 0
    timeout 31
}

During the upgrade process from BIG-IP 11.6.x to 12.1.x or 13.x, the system processes escape sequences in send and receive strings of monitors.

For example, this is the string in BIG-IP 11.6.x:

\\r\\n

After the upgrade process to 12.1.x or 13.x, this is the same string:

\r\n

Impact

The system fails to convert the backslash characters, causing the monitor to incorrectly mark nodes and pool members down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After the upgrade, double backslash characters in the send or receive strings of monitors are not converted.
  • The affected monitors incorrectly mark nodes and pool members down following the upgrade.
