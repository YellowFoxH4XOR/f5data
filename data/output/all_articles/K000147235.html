What Happened?

I am receiving a default error page with a "Blocking Temporarily" error message and don't know why.

Environment

  • F5® Distributed Cloud

Resolution/Answer

  • Sometimes a webpage is being blocked temporarily and it is likely due to them mistakenly being grouped as malicious user. 
  • You must configure User ID to be source IP + TLS fingerprint. Once it's done, DDoS protection may be less effective for the websites.
  • This can happen from time to time that they are blocked by the malicious user detection feature of F5 Distributed Cloud with default error page "temporary blocking".
  • This  can also happen on specific browsers. (For Example: users might report that it happened on Firefox and is working with the other browsers at the same time.)
  • There can also be instances that "blocking temporarily" error messages are not appearing in any of the data in the dashboards/logs.

Cause

  • This can be due to User identification policy for that Load-Balancer is misconfigured. It maybe due to users defined TLS fingerprint to be user identifier in the past in order to stop DDoS attacks.
  • The problem with that configuration is that TLS fingerprint is not unique so if one actor is detected as malicious, but other actors have the same TLS Fingerprint then they will be also blocked by Malicious User Mitigation mechanism because all these actors have same User ID.

Additional Information

  • Sometimes, the issue might happen once and refreshing the browser will fix the issue/ to reproduce the issue, browser cache can be deleted.
  • It is because few other actors (IPs) can have the same TLS fingerprint as the above user. During last 24 hours there can be 1000's of security events with the same TLS fingerprint: scanners (IP addresses with bad reputation), rate limiting, etc.
