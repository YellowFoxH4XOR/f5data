Topic

You should consider using this procedure under the following condition:

  • You want to enable specific BIG-IP ASM signatures to URLs.

Description

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP ASM Configuration utility.
  • You have a basic understanding of attack signatures.
  • You have a predetermined list of URLs and the attack signatures to apply to the URLs.

Procedures

  • Identifying attack types
  • Adding attack types to a security profile
  • Applying attack types to URLs

Identifying attack types

This procedure is intended to help you to identify the attack types of the attack signatures you want to apply to the URLs.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature List.
  2. Click Show Filter Details.
  3. For Containing String, enter a search string. Alternatively, for Signature ID, enter the numeric attack signature ID and skip steps 4 through 6 of this procedure.
  4. For Signature Type, click the appropriate type.
  5. For Signature Scope, click URI.
  6. For Attack Type, click the appropriate type.
  7. Click Go.

Note: Click the signature name to view the Attack Signature Properties, including the Attack Type.

For example the following choices creates a search for attack signatures related to JSP server-side injection on URIs:

  1. For Containing String click JSP.
  2. For Signature Scope click URI.
  3. For Attack Type, click Server Side Code Injection.

Adding attack types to a security profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Change the view to Advanced.
  3. Expand Attack Signatures
  4. Click Change.
  5. Select the check the box for the attack signature set(s) that you want. For example, JSP Expression Language Expression Injection.
  6. Click Change.
  7. Click Save.

Applying attack types to URLs

After you add the JSP Injection signatures sets , the modification needs to be applied to the running security policy. The following procedure shows how to add the attack signatures to URLs.

Impact of procedure : After you apply the security policy, depending on your security policy settings, traffic matching the attack signature(s) may be blocked.

  1. Navigate to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
  2. Click the URL to which you want to apply the specific attack signature(s).

    For example: If you click * (asterisk) next to [HTTPS], you can apply the URL it to all HTTPS traffic for the security policy.

  3. Click the URL Parameters tab.
  4. Click Create.
  5. For Parameter Name, keep Explicit and enter a parameter a name. Alternatively, you can click No Name.

    Note: F5 recommends using Explicit unless underlying factors such as a wildcard URI path is required for your security needs.

  6. For Perform Staging, clear the check box.
  7. Click the Attack Signatures tab.
  8. In the Global Security Policy Settings list, click the name of the attack type. For example, JSP Expression Language Expression Injection. You can type the name into the filter box to find the attack type.
  9. Move the attack type to the Overridden Security Policy Settings list.
  10. In the State column, click Enabled for each attack type.
  11. Click Create.
  12. Click Apply Security Profile.
