Known Issue

Packet Velocity ASIC (PVA) accelerated connections that have been mirrored may time out after a failover event.

This issue occurs when all of the following conditions are met:

  • Your configuration is running on a platform that supports PVA or embedded Packet Velocity Acceleration (ePVA) acceleration.
  • Your configuration includes a FastL4 virtual server with connection mirroring enabled.
  • The FastL4 profile has PVA acceleration enabled.
  • The first packet received by the newly active BIG-IP system after a failover is from the server.

For example, the following chain of events may occur:

  1. A failover event occurs.
  2. The first packet received for an affected established connection flow is from the server.
  3. The Traffic Management Microkernel (TMM) sets the connection’s idle timeout to the TCP Handshake Timeout specified in the FastL4 profile (5 seconds by default) instead of the specified Idle Timeout (300 seconds by default).

Impact

The BIG-IP system may prematurely remove affected established connections from the connection table after a failover and require the client to re-establish the connection.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system prematurely resets established connections after a failover.

Workaround

To work around this issue, you can either disable the tm.fastl4_ack_mirror sys db setting, or disable PVA acceleration in the FastL4 profile. To do so, perform one of the following procedures:

Disabling the tm.fastl4_ack_mirror sys db setting

Impact of workaround: Restarting TMM interrupts traffic processing and should be performed during a maintenance window. Additionally, when the tm.fastl4_ack_mirror is disabled, the active BIG-IP system no longer waits for a mirrored connection to be acknowledged by the peer before completing the connection. As a result, it is possible for the active system to have established connections that are not mirrored to the standby system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Disable the tm.fastl4_ack_mirror sys db setting by typing the following command:

    modify sys db tm.fastl4_ack_mirror value disable
  3. Save the change by typing the following command:

    save /sys config
  4. Exit the tmsh by typing the following command:

    quit
  5. Restart TMM on all blades by typing the following command:

    clsh --color=all bigstart restart tmm
  6. Once TMM has restarted, repeat the procedure on the active BIG-IP system.

    Important: When TMM is restarted on the active system, it will cause a failover.

Disabling PVA acceleration on the FastL4 profile

Impact of workaround: Disabling PVA acceleration may impact system performance and increase CPU utilization.

Note: F5 does not recommend modifying a default profile. If an affected virtual server uses the default FastL4 profile, you should create a new custom FastL4 profile with PVA Acceleration disabled, and configure the affected virtual server to use the new custom FastL4 profile.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol.
  3. To view the list of FastL4 profiles, click FastL4.
  4. Select the affected FastL4 profile.
  5. From the PVA Acceleration menu, select None.
  6. Click Update.
  7. Repeat this procedure for each affected FastL4 profile.
  8. Synchronize the updated configuration to the peer BIG-IP system.
