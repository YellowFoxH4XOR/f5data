Important: Beginning in FirePass version 6.0.2, you have the ability to disable Compatibility Mode. Disabling Compatability Mode may significantly decrease the types of restrictions that your web developers need to be aware of. For more information, refer to K10697: Writing JavaScript applications for websites that are accessed through Portal Access when Compatibility Mode is disabled.

The FirePass MyIntranet feature parses and changes content as it passes through the FirePass, in order to rewrite HTML links. If you are writing JavaScript applications that are accessed through FirePass, use the following guidelines:

  • Do not build URLs dynamically in JavaScript code.
  • Use fully qualified URLs
  • Do not use the IndexOf() function to search for the forward slash (/) character.
  • Separate JavaScript from HTML and other content.
  • Specify text/javascript content type in the HTML code, for example, in the type attribute of the SCRIPT element.

Do not build URLs dynamically in JavaScript code

FirePass parses JavaScript code and obfuscates anything that it recognizes as a URL. This secures the site by making the server paths unreadable and enables FirePass to identify the session based on the obfuscated URL. It is possible for FirePass to misidentify portions of URLs within JavaScript as full, static URLs. In these cases, FirePass will modify each URL component in the JavaScript code, resulting in an incorrect URL.

For example, the following JavaScript code will fail when accessed through the FirePass MyIntranet feature:


 var url_base = "/application/directory";

...

abc[0] = strDynamic + url_base + "/" + _something + "/" + _somethingElse;

Use fully qualified URLs

Relative URL paths can be misidentified as full, static URLs. In these cases, FirePass will modify each URL component in the JavaScript code, resulting in an incorrect URL.

For example, the following JavaScript code will fail when accessed through the FirePass MyIntranet feature:

window.open("/application/directory");

The fully qualified URL will be parsed correctly, as shown in the following example:

window.open("http://www.example.com/application/directory");

Do not use the "IndexOf()" function to search for the forward slash ("/") character

Because FirePass interprets the forward slash character ( / ) as a portion of a URL, it will attempt to obfuscate the text included with the forward slash. Therefore, FirePass will incorrectly obfuscate an IndexOf() function directed to locate a forward slash, resulting in incorrect code.

Separate JavaScript from HTML and other content

When parsing content, FirePass uses the Content-Type HTTP header to determine how to process the content. When JavaScript code is embedded within HTML code, FirePass will attempt to process the JavaScript code as if it were HTML code. This will result in incorrectly processing the JavaScript.

To avoid this issue, isolate JavaScript in separate files and call it from the HTML files using the SRC= directive.

For example:


<SCRIPT LANGUAGE="JavaScript" SRC="javascriptfile.js">

</SCRIPT>

Specify the correct content type in the code

FirePass uses the Content-Type HTTP header to determine how to process content. Therefore, it is important that you include and specify the Content-Type headers in the code. Identify JavaScript code by a Content-Type header that contains application/x-javascript. Ensure that the web server indicates the content type of each component of your application.
