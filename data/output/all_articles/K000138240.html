Description

Users from different region are not resolving to the correct datacenter specific under the GTM Topology Geolocation settings.
For example:-
HQ DC located in US
DC1 located in NY
DC2 located in SG

fqdn.example.com will resolve as below when trying to resolve from regional local DNS servers.

  • US users will resolve to US IP
  • NY users will resolve to NY IP
  • SG users will resolve to SG IP

It is found SG users are not resolving to SG IP instead it is resolving to US IP, while other region users is working as expected.

Environment

  • BIG-IP
  • GTM/DNS
  • Geolocation
  • Country/Region

Cause

The possibility of the SG users are pointed to DNS server located in US instead of SG local DNS server.

Recommended Actions

Check the local PC's DNS settings and ensure they are not configured to use a DNS server from another region. 

For example:
Users might have been directed to the US HQ's DNS server due to MPLS/VPN connections to HQ or using a public DNS service located in other region.
