K55110060: Disable retries for Virtual Service on Aspen Mesh

Type
Support Solution
Published
2021-06-17
Updated
2023-07-18
Applies to
  • Aspen Mesh: 1.11, 1.14
Source
https://my.f5.com/manage/s/article/K55110060

Description

Given any application inside the service mesh, receiving a HTTP 503 response code, the sidecar behavior is to retry up to 2 times (default value). How can I disable the retries to 0?

Environment

  • Redhat Openshift: 4.6x, 4.7.x
  • Kubernetes: 1.17x,1.18.x,1.19.x,1.20.x
  • Aspen Mesh: 1.6.x, 1.9.x


Cause

This is due to the default behavior of the max-retries HTTP filter in Envoy.

Recommended Actions

Disable retries applying a Virtual Service setting the number of attempts to 0. 

Disable retries procedure:

  • Create the following manifest to apply against your service host, replace the name and the hosts according to your needs in your environment. 
    apiVersion: networking.istio.io/v1alpha3
kind: VirtualService
metadata:
  name: example-route
spec:
  hosts:
  - example.prod.svc.cluster.local
  http:
  - route:
    - destination:
        host: example.prod.svc.cluster.local
    retries:
      attempts: 0
  • Apply the configuration using one of the following commands depending on your environment:
oc apply –f your-manifest.yaml
kubectl apply –f  your-manifest.yaml

  • Verify the resource is created using one of the following commands

    oc get virtualservice -n <your-namespace> <object-name>
kubectl get virtualservice -n <your-namespace> <object-name>
  • Verify the retries in your sidecar configuration are disabled with the following istioctl command syntax:
istioctl proxy-config routes <pod-name> -n <namespace> -o json

The following example output is when Retries is on.
#Retries on:
"route": {
    "cluster": "outbound|8000||example.prod.svc.cluster.local",
    "timeout": "0s",
    "retryPolicy": {
        "retryOn": "connect-failure,refused-stream,unavailable,cancelled,retriable-status-codes",
        "numRetries": 2,
        "retryHostPredicate": [
            {
                "name": "envoy.retry_host_predicates.previous_hosts"
            }
        ],
        "hostSelectionRetryMaxAttempts": "5",
        "retriableStatusCodes": [
            503
        ]
    },
    "maxStreamDuration": {
        "maxStreamDuration": "0s"
    }
},
"decorator": {
    "operation": "example.prod.svc.cluster.local:8000/*"
}
The following example output is when Retries is off.
#Retries off:
"route": {
    "cluster": "outbound|8000||example.prod.svc.cluster.local",
    "timeout": "0s",
    "maxStreamDuration": {
        "maxStreamDuration": "0s"
    }
},
"metadata": {
    "filterMetadata": {
        "istio": {
            "config": "/apis/networking.istio.io/v1alpha3/namespaces/default/virtual-service/ example-route "
        }
    }
},
"decorator": {
    "operation": "example.prod.svc.cluster.local:8000/*"
}


Additional Information

  • A VirtualService defines a set of traffic routing rules to apply when a host is addressed. Each routing rule defines matching criteria for traffic of a specific protocol. If the traffic is matched, then it is sent to a named destination service (or subset/version of it) defined in the registry.
