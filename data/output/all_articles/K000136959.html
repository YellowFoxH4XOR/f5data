Description

When the BIG-IP file systems become full, undesirable or unpredictable behavior may result. Symptoms may include the following:
 

  • df ouput shows a full file system:

    df -h

    Filesystem        Size Used Avail Use% Mounted on
    /dev/mapper/vg--db--vda-set.2.root  419M 414M  0 100% /
    devtmpfs        189G 4.0K 189G 1% /dev
    tmpfs         189G 2.3M 189G 1% /dev/shm
    tmpfs         189G 2.3M 189G 1% /run
    tmpfs         189G  0 189G 0% /sys/fs/cgroup

  • df output indicates a full file system. This indicates the inodes are full and the issue is likely many small files. 

    df -i

    Filesystem      Inodes  IUsed   IFree IUse% Mounted on
    /dev/md4        112640   4721  107919    5% /
    none           6191813    130 6191683    1% /dev/shm
    /dev/md6        208000    266  207734    1% /config
    /dev/md5        216000  52524  163476   25% /usr
    /dev/md7        196608 196608       0  100% /var

  • The diskmonitor utility generates warning messages or traps. The diskmonitor utility is a script that runs periodically on the BIG-IP system and alerts you if the partition space or volumes reach a defined threshold. If one or more of these thresholds are reached, a log message is logged to the /var/log/ltm file.

    For example, the following message indicates that the /shared partition has less than 30 percent free space available:

    diskmonitor: 011d005: Disk partition shared has less than 30% free

    The following message indicates that the /shared partition has zero percent free space available:

    diskmonitor: 011d004: Disk partition shared has only 0% free

    Additionally, the BIG-IP system sends the following SNMP trap alerts when the partition space reaches a defined threshold:

    alert BIGIP_DMON_ERR_DMON_ALERT {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.25"
    }
    alert BIGIP_DMON_ERR_DMON_WARN {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.25"
    }
    alert BIGIP_DMON_ERR_DMON_GROWTH {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.26"

  • Upgrades, hotfix installations, or point release installations fail to proceed.
  • Daemon log messages appear similar to the following examples:

    Couldn't write to <file> / <partition>
    Failed to open file

  • The system performance degrades, such as slow or failed disk writes.
 

Environment

A partition, disk, or file system is full on any F5 product. 
 

Cause

There are many causes to a full file system. 

  • Large files
  • Many small files
  • Deleted files still taking disk space
 

Recommended Actions

Locate and remove any offending files or folders. Please modify the commands below to the filesystem you are searching through indicated by the "df" output. 
 

  • Find largest files for a given directory

    find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20

    2189582 /shared/tcpdump.cap
    1277060 /shared/images/BIGIP-11.3.0.2806.0.iso
    1186512 /shared/images/BIGIP-11.2.1.797.0.iso
    18460 /shared/core/mcpd.bld3341.0.core.gz
    5200 /shared/rrd.1.2/endpisession
 

  • Find the largest folders. Useful for location large deposits of small files. 

    find / -xdev -type d -exec du {} \; | sort -rn | uniq | head -30

    304517084    /shared
    2324272    /shared/images
