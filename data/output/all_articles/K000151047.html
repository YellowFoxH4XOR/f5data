K000151047: TCP resets from VIP

Type
Support Solution
Published
2025-04-25
Updated
2025-04-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151047

Description

You are experiencing an issue where the application becomes inaccessible, and connections are being reset unexpectedly. This issue is observed when attempting to access the application through the BIG-IP system. The following message or behavior may appear:

  • Severity: Connection reset by BIG-IP
  • The application URL fails to load or page says RESET_CONN

Environment

  • BIG-IP LTM (Local Traffic Manager) deployed
  • Pool members configured with multiple ports across the same pool
  • Application accessed via HTTPS (default port 443)

Cause

Misconfiguration of pool members within the same pool. Pool members should not have different port numbers. If the application URL resolves to a default port like HTTPS (443), and the pool contains members with mismatched ports (e.g., 631), this discrepancy results in the BIG-IP system resetting the connection in response to the real server's reset.

Recommended Actions

  • Ensure that all pool members within a pool are configured with the same port.
  • Review and update the pool configuration as follows:
  1. Log in to the BIG-IP Configuration Utility.
  2. Navigate to Local Traffic > Pools.
  3. Select the affected pool and review the list of pool members.
  4. Ensure all pool members use the same port. For example, if using HTTPS, all members should listen on port 443.
  5. Save and apply your changes to commit the updated pool configuration.

Additional Information

None.
