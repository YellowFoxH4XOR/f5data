Description

When a client advertises a large MSS, this can result in a sub-optimal TCP window size being advertised by the BIG-IP.

This can result in the BIG-IP advertising a TCP zero window size later in the TCP connection, which can impact TCP performance.

Environment

  • Client advertises a large MSS, due to the use of jumbo frames.
  • BIG-IP may advertise a sub-optimal TCP window size, which increases the chances of the BIG-IP advertising a TCP zero window size.
  • The TCP profile assigned to the virtual server has an 'Initial Receive Window Size' that results in a calculated window size greater than 65535 bytes.

Cause

Due to bug ID834217, the TCP window size advertised by the BIG-IP may be sub-optimal when a client advertises a larger MSS.

On the BIG-IP, the initial TCP window size is the calculated by multiplying the client's MSS by the 'Initial Receive Window Size' from the TCP profile associated with the virtual server on the BIG-IP.

Example:

  • A client advertises a MSS of 8440 bytes.
  • The TCP profile associated with the virtual server has an 'Initial Receive Window Size' set to 16.
  • 8440 (client's MSS) * 16 (Initial Receive Window Size) = 135040, which exceeds the maximum 65535 bytes allowed.
  • The initial TCP window size advertised by the BIG-IP is 3968 bytes (135040 - 65536 - 65536 = 3968).

A tcpdump taken on the BIG-IP shows the sub-optimal TCP window advertised by the BIG-IP:

192.0.2.10.8896 > 192.0.2.98.80: Flags [S], cksum 0x3fa5, seq 3803754332, win 25320, options [mss 8440,sackOK,TS val 863117274 ecr 0,nop,wscale 7], length 0 in slot1/tmm0 lis=

192.0.2.98.80 > 192.0.2.10.8896: Flags [S.], cksum 0x81e7, seq 1000757148, ack 3803754333, win 3968, options [mss 1460,sackOK,TS val 653231480 ecr 863117274]

Recommended Actions

  • Upgrade

Bug ID834217 is fixed in version 16.0.0/15.1.9 and above.

  • Workaround

Modify the 'Initial Receive Window Size' in the TCP profile associated with the virtual server so the initial TCP window advertised does not exceed 65535 bytes.

Example:

  • A client advertises a MSS of 8440 bytes.
  • To calculate the maximum 'Initial Receive Window Size', divide 65535 by the client's MSS and use the resulting whole number as the setting for the 'Initial Receive Window Size'.
  • 65535 / 8440 = 7

After making the above change to the TCP profile, a tcpdump taken on the BIG-IP shows the correct TCP window advertised by the BIG-IP:

192.0.2.10.22521 > 192.0.2.98.80: Flags [S], cksum 0x5e74, seq 1124962353, win 25320, options [mss 8440,sackOK,TS val 863013546 ecr 0,nop,wscale 7]

192.0.2.98.80 > 192.0.2.10.22521: Flags [S.], cksum 0x81e7, seq 222819409, ack 1124962354, win 59080, options [mss 1460,sackOK,TS val 653127482 ecr 863013546]
