K000152216: BIGIP not sending client certificate in TLS Handshake to backend server after moving to Azure

Type
Support Solution
Published
2025-06-27
Updated
2025-06-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.5
Source
https://my.f5.com/manage/s/article/K000152216

Description

After migrating a deployment to a Microsoft Azure deployment where mTLS (mutual TLS) is required, an admin noticed that BIGIP was not sending a client certificate in the TLS handshake to the backend server, causing connections to fail.

 

Environment

Big-IP LTM, Azure, mTLS

 

Cause

This typically happens when migrating existing applications to a setup where the server requires a client certificate, from deployments where it did not require that in the past.

For this to work, the Big-IP requires the Client Certificate Constrained Delegation (CCCD, also known as C3D) feature to be configured before it will "pass on" a client connection's client certificate to the serverside connection.

By default, even if a client sends a client certificate on the clientside of the Big-IP LTM VS, the Big-IP will not automatically try to send a client certificate on the serverside connection when requested by the server.

 

Recommended Actions

Please see "K72668381: Overview of the SSL Client Certificate Constrained Delegation feature" at https://my.f5.com/manage/s/article/K72668381 for instructions on how to configure CCCD on the Big-IP, if required.
