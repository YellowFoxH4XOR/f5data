Description

When trying to upload a file to an application, ASM sometimes will block the request as it detects signature matching in the content of the uploaded file.

 

Environment

  • Request Content-Type is multipart/form-data
  • signature detected on parameter level of the form data
  • customer thinks this is a false-positive and should be bypassed on ASM

an example violation would be similar to below one:

 

Cause

ASM understands multipart/form-data natively and will parse it into parameters. So it's normal that the value of the paramters can trigger signature violations sometims.

 Recommended Actions

There are several methods to workaround this.

The most simple ones would be to disable the detected signature(s) on the parameter level, the URL level or a combination of both.

If you want to disable it on the URL level, you need to create an explicit URL first on the asm policy, then navigate to 'Attack signatures' tab, and then disabled the detected signatures.

If you want to disable it on the parameter level, you need to create an explicit parameter first on the asm policy, make sure 'data type' is 'file upload', then navigate to 'Attack Singatures' and disable the detected signatures."

If you want to minimize the security risk of disabling signatures, you can combine these two procedures, and make the parameter applicable to the defined URL only. This way other parameter violations on other URLs will not be affected.

In order to do this, you need to create an explicit URL first. Note don't disable sigantures at URL level now. You only need to create this URL. 

Then, create a new parameter of the detected violation. In the above example, the parameter name is 'file'.

You can choose the 'parameter level' to be the defined URL, instead of global. Data type should be 'file upload' on the first screenshot. Then you can diable the signatures under 'Attack Signatures' tab.

For detailed procedures, please refer to K8866.

 

 

If you want to loose the asm policy and have ASM do nothing to the uploaded file, we can create a header based content profile to bypass ASM inspection.

 

1. Navigate to: Security ›› Application Security : Security Policies : Policies List

 

2. Create an allowed URL using the URL found in the ASM event log

 

3. Select advanced

 

4. Add the below Header based content profile: 

Request header Name :Content-Type

Request Header Value : *multipart/form-data*

Request Body Handling : Do nothing

 

5. Move the newly added content profile to the top by checking the box in front of the line and click 'up'.
