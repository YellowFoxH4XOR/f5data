Known Issue

The BIG-IP GTM system may incorrectly mark virtual servers as down.

This issue occurs when all of the following conditions are met:

  • You are running BIG-IP GTM 11.2.1 HF6.
  • The virtual server is in a non-zero route domain.
  • The virtual servers that the BIG-IP GTM system is load balancing contain a period (.) or colon (:) character in the name.

Impact

BIG-IP GTM load balanced virtual servers will not accept incoming traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H424615 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP GTM system indicates that the virtual servers are marked down.
  • The virtual servers on the BIG-IP LTM system continue to be marked up.

Workaround

To work around this issue, avoid using a period (.) or colon (:) character in the virtual server name. Alternatively, you can remove the server objects and re-configure BIG-IP GTM to discover and monitor BIG-IP virtual servers that are associated with route domains. For more information, refer to K12969: Configuring BIG-IP GTM to discover and monitor BIG-IP virtual servers that are associated with route domains.

Note: To ensure that each BIG-IP GTM server only discovers and probes the virtual server in its own route domain, the exposer-route-domain option must be set to no. This option is located in the BIG-IP GTM server stanza and is set to no by default. If the expose-route-domain option is set to yes, each BIG-IP GTM server will probe beyond the designated virtual server, which causes duplicate actions.
