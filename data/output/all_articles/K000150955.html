Description

When multiple client SSL profiles are assigned to a BIG-IP LTM virtual server, it may be unclear which profile will be selected during the SSL handshake—especially if the profiles use certificates with identical Common Names (CN), Subject Alternative Names (SAN) and no unique Server Name configured in ssl profile.  

This can result in uncertainty about which certificate is presented to clients, including situations where an expired certificate might be used.

 

Environment

BIG-IP Local Traffic Manager (LTM)

 

Cause

The selection of a client SSL profile by BIG-IP is determined by configuration matching criteria—specifically SNI, SAN, CN, and the sni-default flag—not by the validity or expiration status of the certificate within each profile. 

Beginning in BIG-IP 13.0.0, the BIG-IP system matches a requested hostname using the order of precedence in K55504740.

 

The system first tries to match a requested host name with a server name configured in the Client SSL profiles. If no match, it tries to match a subject alternative name (SAN) of an SSL certificate used by the Client SSL profile. If there is no match, then the system tries to match a common name (CN) of an SSL certificate used by the Client SSL profiles.

 

If there is no hostname match, BIG-IP selects the profile with sni-default set to true. 

 

If multiple client SSL profiles match at the same time, BIG-IP will not select the profile with "Default SSL Profile for SNI" enabled.  Instead, it will select the first matching profile as ordered in configuration, excluding the one with sni-default enabled.

 

Recommendation

From the logic above, since multiple SNI SSL profiles are used to support different sites, each profile should use certificates with different server names, CNs, or SANs.  
Therefore, the scenario where multiple SSL profiles use the same certificate is not considered.

For a single virtual server, only one SSL profile is needed for the same site.  You should avoid configuring SSL profiles with certificates that have identical server names, CNs, or SANs.  If you need to update a certificate, you should replace the certificate or update the SSL profile accordingly.

 

Additional Information

The selection of a client SSL profile by BIG-IP is determined by configuration matching criteria—specifically SNI, SAN, CN, and the sni-default flag—not by the validity or expiration status of the certificate within each profile.  The system does not automatically switch away from a profile containing an expired certificate.
An expired certificate will still be presented if its corresponding profile matches according to precedence rules and browsers/clients may display security warnings as a result.
