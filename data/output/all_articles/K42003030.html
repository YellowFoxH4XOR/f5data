Topic

Prior to BIG-IP 14.0.0, the number of core files was limited to one per daemon on BIG-IP systems and subsequent core files produced by the same daemon overwrite the existing core file. This may result in investigating a core file that is unrelated to the root cause of the issue. Beginning in BIG-IP 14.0.0, the BIG-IP system has enhanced the core file logging process when a daemon generates a core file.

Description

The BIG-IP system has improved the handling of the core file process for F5-maintained daemons to have consistent behavior when providing a core file in its standard log file. This improves the manageability of core files and the ability to effectively troubleshoot the issue. When a daemon produces a core file, the core file produces information written to the standard log file of the daemon and stores it in the /var/log/crashinfo directory with a file name matching the daemon and a .crashlog extension. For example, the BIG-IP system logs a core file for the bigd process in the /var/log/crashinfo/bigd.crashlog directory.

The following BIG-IP daemons use the new process and log core files in the /var/log/crashinfo directory:

  • bigd
  • sod
  • snmpd
  • aced
  • rewrite
  • pccd
  • TMM
  • tmrouted
  • devmgmtd
  • vcmpd

Note: The core file for the Traffic Management Microkernel (TMM) daemon is logged in the /var/log/tmm directory
