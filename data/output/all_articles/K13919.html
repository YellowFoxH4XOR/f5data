Known Issue

The BIG-IP system fails to establish adjacent neighbor relationships with an OSPFv3 router. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with an IPv6 wildcard forwarding virtual server with destination ::.any.
  • The IPv6 wildcard forwarding virtual server is listening on the VLAN where the OSPFv3 peering occurs.

Impact

The BIG-IP system is unable to exchange dynamic routing information with OSPFv3 neighbors.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The OSPFv3 neighbor is unable to see any advertised route from the affected BIG-IP system.
  • The OSPFv3 neighbor may report the state of the affected BIG-IP system as INIT/DROTHER instead of FULL/DROTHER.

    For example:

    Neighbor ID     Pri   State           Dead Time   Interface ID    Interface
    192.168.1.1       0   INIT/DROTHER    00:00:33    11              FastEthernet1/0
  • When you enter the show ipv6 ospf neighbor command in the imish utility, the affected BIG-IP system fails to report OSPFv3 neighbors.
  • No OSPFv3 multicast Hello packets from the OSPFv3 neighbor are observed when performing packet captures on the VLAN of the affected BIG-IP system.

Workaround

To work around this issue, you can remove the IPv6 wildcard forwarding virtual server and configure IPv6 forwarding virtual servers with a more specific network address/port/protocol. For example, if you require only port 80 traffic, you can configure the IPv6 forwarding virtual server with destination ::.80 instead of ::.any. For more information about configuring a forwarding virtual server with specific network address/port/protocol, refer to the Virtual Servers chapter of the BIG-IP Local Traffic Manager: Concepts guide.

Impact of workaround: F5 recommends that you configure forwarding virtual servers that work best for your environment and that you test any such changes in an appropriate environment.
