K000140024: 'Bad HTTP version' or 'Cookie not RFC-compliant' violations flagged after upgrade

Type
Support Solution
Published
2024-06-17
Updated
2024-06-17
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000140024

Description

After upgrading to v17 release, some requests were blocked with HTTP protocol compliance failed > Bad HTTP version sub-violation and/or Cookie not RFC-compliant violation.

Environment

  • Upgrading from pre-v17 to post-v17 release
  • ASM provisioned

Cause

The HTTP protocol compliance failed > Bad HTTP version sub-violation can be raised due to improvements in enforcement introduced via ID840873 to abide by the compliance issues documented in RFC7230. Among things that have been improved are to enforce presence of whitespace after the HTTP version is specified in the request-line within the raw HTTP header. This particular enforcement has been introduced in v16 and above releases.

The Cookie not RFC-compliant violation was due to inheriting a fix for a known bug ID1069441 that in place to track this issue with a Cookie header containing a cookie name with no value.

Recommended Actions

There are a couple of recommendations that can be considered:

  • Ensure the application is compliant with RFC7230 so that those requests don't get flagged with these violations post upgrade to versions where these issues have been addressed.
  • Disable these violations within the security policy, if it is considered to be a false positive.
