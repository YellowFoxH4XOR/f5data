MAC address assignment in tenants

When a VLAN is created, a MAC address from the pool is assigned to the VLAN. The BIG-IP system uses this MAC address to pass L3 or above traffic. The BIG-IP database variable vlan.macassignment, controls how MAC addresses are assigned to VLANs.

The possible database values in BIG-IP tenants for vlan.macassignment are:

  • unique - Each VLAN is assigned a unique MAC address this is only true as long as there are available MAC addresses to assign. If you create many VLANs, the BIG-IP system will start assigning the same MAC address to multiple VLANs. This is the default database value for vlan.macassignment. Note that this is only true as long as there are available MAC addresses to assign. If you create more VLANs than there are available MAC addresses, multiple VLANs are assigned the same MAC address.
  • global - All VLANs are assigned the same MAC address.
  • vmw-compat - Specific to VE systems, only one interface is allowed per VLAN, and the VLAN will use the MAC address of its corresponding interface. No trunks may be attached to these VLANs.

Note: Multiple VLANs can safely share the same MAC address as long as your other network devices support a per-VLAN MAC address table. This allows those devices to learn the same MAC address on multiple VLANs without issue. This is a common feature.

Note: VLAN MAC assignment may change after upgrade, restart, or restarting the mcpd process.

Additional Information

You can determine the address range of the pool by adding one fewer than the appropriate number (depending on the platform) to the base MAC address. However, because MAC addresses are represented as hexadecimal values, you would actually have to perform hexadecimal addition. For example, to determine the range of MAC addresses for a r2600 appliance, perform the following addition where the hexadecimal numbers 7F is the equivalent of the decimal number 127:

<base MAC address> + 7F

To determine the base MAC address of the appliance, enter the following command in the ConfD CLI as the administrative user:

show system state base-mac

Note: The equivalent REST API command is curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' https://<management IP address>/api/data/openconfig-system:system/state/f5-system:base-mac

For example, using the base MAC address of 14:A9:D0:28:DC:80, the range of 127 MAC addresses would be:

14:A9:D0:28:DC:80 – 14:A9:D0:28:DC:FF (80+7F = FF)

If you want to view the MAC allocation on the system, you should enter the following command in the ConfD CLI as the administrative user:

show system mac-allocation

Note: This command is only available on F5 VELOS systems running F5OS-C 1.6.0 and later as well as F5 rSeries systems running on F5OS-A 1.3.0 and later.

Note: The equivalent REST API command is curl -sku <admin user>:<admin password> -H 'Content-Type: application/yang-data+json' https://<management IP address>/api/data/openconfig-system:system/f5-system-mac-allocation:mac-allocation

The command should return an output that provides information about how many single or small/medium/large blocks of MAC addresses has been allocated and how many are still available. The following is an example taken off a r10900 system:

VELOS system (F5OS-C)

The vcc-partition-agent service on the chassis controller is the manager of the chassis-wide pool of MAC addresses; it divides the available MAC address pool into groups of thirty-two (32) addresses. When a partition is created, the vcc-partition-agent service on the chassis controller allocates a pool of MAC addresses to the partition; typically sixteen (16) single MAC addresses. When the partition configuration expands and the requirement for MAC addresses exceeds the pool of MAC addresses allocated to the partition, the partition's active network-manager service will request MAC addresses from the vcc-partition-agent service on the chassis controller. The vcc-partition-agent service on the chassis controller manages the MAC address requests from the partition on a first come first serve basis until the pool is exhausted.

MAC address exhaustion handling

When the vcc-partition-agent service on the chassis controller does not have sufficient MAC addresses to satisfy a request from a partition, it sends a RECLAIM message to the other partitions. The partition requesting MAC address(es) fails its configuration commit. If any partition returns unallocated MAC addresses, the vcc-partition-agent service on the chassis controller can then update its Confd configuration with the returned MAC addresses. It may then be able to satisfy subsequent requests from any partitions.

MAC address handling when you attempt to downgrade F5OS-C software

If you downgrade the F5OS-C software on the chassis controller to a version prior to F5OS-C 1.6.0 (which does not support the use of contiguous block of MAC address allocation), the partition's active network manager will allow the configured BIG-IP tenants to keep the MAC addresses that were already assigned to them. However, the partition's active network manager will now store the MAC addresses allocated to it as single MAC addresses instead of contiguous blocks of MAC addresses. If you attempt to configure the mac-block-size for a new BIG-IP tenant or reconfigure an existing BIG-IP tenant with a size other than one (1), the system fails the configuration commit and returns an error message similar to the following example:

The Chassis Controller does not support mac-block-size > 1, tenant myBIGIPtenant mac-block-size large. Cancel this commit.

If you attempt to downgrade the F5OS-C software on a partition to a version prior to F5OS-C 1.6.0 (which does not support the use of contiguous block of MAC address allocation) and the partition has allocated blocks of MAC addresses to BIG-IP tenants, then the system does not allow the software downgrade and returns an error message similar to the following example:

This partition has allocated MAC blocks. It cannot be downgraded to a version less than 1.6.0. To downgrade, reconfigure tenants to use mac-block size of 1.

In another scenario where the mac-block-size setting of a BIG-IP tenant is reconfigured from large/medium/small to one, the partition's active network manager releases the chunk and tries to allocate a single MAC address. If the partition has no single MAC address available but has a block of thirty-two MAC addresses, the partition's active network manager breaks the block into 32 single MAC addresses and allocates a single MAC address to the tenant. In this case, the system also does not allow the software downgrade to happen; the tenant must be deleted in order to downgrade.

Important: As of this writing, F5 does not support VELOS systems with partitions running a F5OS-C software version that is different from the chassis controller. For more details, refer to K86001294: F5OS hardware/software support matrix.
