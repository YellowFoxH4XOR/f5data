Topic

To allow nodes behind the BIG-IP Controller to make connections outbound to external resources (such as the Internet), use one of the following methods:

Note: For detailed configuration instructions for each method, refer to the BIG-IP manuals.

  • Create a NAT for the node.

    A NAT is a one-to-one, bi-directional address translation. You must create one NAT for each node that requires outbound access (using a unique external address). In addition to allowing the node outbound access, external users can connect to the NAT to reach the node.

    Using a NAT is a less secure of address translation than using a SNAT, because you are opening all ports of your servers to external access

  • Create a SNAT for the node, or create a default SNAT.

    A SNAT is a one-to-one, unidirectional address translation. A default SNAT is a many-to-one, unidirectional address translation. Many nodes can use one SNAT to connect outbound, but inbound access is not allowed through a SNAT. A default SNAT translates the source IP address of requests originating from the nodes behind the BIG-IP, through a router, out to the Internet. These node addresses are translated as a single SNAT IP address.

    A SNAT, or default SNAT, is the most secure form of address translation.

  • Enable IP Forwarding.

    When IP forwarding is enabled, BIG-IP acts as a router and forwards packets. This method is typically used when no address translation is required, such as when the when the node IP addresses are routable on the Internet. IP forwarding requires that devices external to BIG-IP (such as routers) have routes that reach the node IP subnet through BIG-IP.

    IP forwarding is the least secure way to allow outbound connections, because you are exposing the node IP of all your servers.

    Note: Enabling IP forwarding can hinder performance and is not recommended since the fastest path through BIG-IP is not used. Do not use IP forwarding if you are using NATs or SNATs.

  • Use virtual servers (VIPs).

    In firewall load balancing scenarios, such as a firewall sandwich, you can use virtual servers (VIPs) to provide outbound access.
