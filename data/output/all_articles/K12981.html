Topic

You should use this procedure under the following conditions:

  • You are creating a new Domain Name System Security Extensions (DNSSEC) zone or renewing keys for an existing zone.
  • You want to establish an authentication chain between the parent and child DNSSEC zones.

Description

One of the steps in configuring DNSSEC on the BIG-IP GTM system involves establishing an authentication chain between the parent and child DNSSEC zones. When you create a DNSSEC zone, or renew keys for an existing DNSSEC zone, you must provide the Delegation Signer (DS) Resource Record(s) to the parent domain. Providing the DS record to the parent domain establishes the authentication chain between the parent and child DNS zones, allowing each link in the chain to vouch for the next. Without a complete authentication chain, an answer to a DNS lookup cannot be securely authenticated.

After you have created the DNSSEC zone with the appropriate zone-signing and key-signing keys, and the Configuration utility has marked the zone green, you can obtain the DS record information and submit it to the parent domain. The methods for obtaining DS records differ based on software version, ensure you choose the following correct procedure by version.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP GTM physical and logical configuration is complete, as defined in the Introducing Global Traffic Manager Components chapter in the Configuration Guide for BIG-IP Global Traffic Manager.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  • You have configured a DNSSEC zone and added the zone-signing and key-signing keys to the zone.
  • The Configuration utility indicates that the DNSSEC zone status is available (enabled).

Procedures

Providing the DNSSEC DS record to the parent domain (11.x and later)

To obtain the DS record from the BIG-IP GTM system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to tmsh, you can skip this step.

  2. To display the DS record, type the following command:

    list /ltm dns dnssec zone example.org all-properties

  3. For example, the contents of the DS record for the example.org DNSSEC zone appear similar to the following example:

    Note: The DNSKEY in the following example output has been truncated for clarity.

    ltm dns dnssec zone example.org {
        app-service none
        description none
        ds-algorithm sha1
        enabled
        keys {
            test
            test3
        }
        nsec3-algorithm sha1
        seps {
            {
                dnskey "example.org. 86400 IN DNSKEY 257 3 7 AwEAAbeK1tqEvCyElKl8spWL9YOHq+VQ2KezweUgHxqDpxCkNTeeazLDUN+cPE"
                ds "example.org. 86400 IN DS 50841 7 1 cae28c034f13b53fe4da4ca3865a92b14a82d7b4"
                generation-id 1
                key-name /Common/test3
            }
        }
    }

    The important record values are defined as follows:

    DS record fieldExample Values
    Domainexample.org.
    TTL86400
    Resource Record ClassIN (Internet)
    Resource Record TypeDS (Delegation Signer)
    Key tag50841
    Key algorithm7
    Key digest type1
    Key digestcae28c034f13b53fe4da4ca3865a92b14a82d7b4
  • Copy the contents of the DS record and submit it to your ISP or, more commonly, to the domain registrar or certificate authority related to the parent DNSSEC domain.

Providing the DNSSEC DS record to the parent domain (10.x)

To obtain the DS record from the BIG-IP GTM system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP GTM command line.
  2. To change directories to the /config/gtm directory, type the following command:

    cd /config/gtm

  3. To list the directory contents, type the following command:

    ls -las

    For example, for the DNSSEC zone named example.org, the system generates a DS record called dsset-example.org, as displayed below:

    # ls -las

    2 -rw-r--r-- 1 root root 172 Jul 19 08:48 dsset-example.org
    2 -rw-r--r-- 1 root root 276 Jul 19 08:48 keyset-example.org
    3 -rw------- 1 root root 1379 Dec 31 1969 server.crt
    12 -rw-r--r-- 1 root root 10915 Jul 19 08:58 wideip.conf
    17 -rw-r--r-- 1 root root 14615 Jan 5 2011 wideip.conf.sample
    12 -rw-r--r-- 1 root root 10876 Jul 19 08:58 wideip.conf~

  4. To display the contents of the DS record, type the following command:

    cat dsset-<dnssec_domain_name>

    For example, the contents of the DS record for the example.org DNSSEC zone appear similar to the following example:

    # cat dsset-example.org
    example.org. 86400 IN DS 56079 7 1 09f22e86b96725c2f41891bc260304b903c30448 ; xedez-durym-kuvyk-lunos-dituc-meger-sunib-fecar-nibos-fuceg-maxex {key = example.ksk, gen = 0}

    The important record values are defined as follows:

    DS record fieldExample Values
    Domainexample.org.
    TTL86400
    Resource Record ClassIN (Internet)
    Resource Record TypeDS (Delegation Signer)
    Key tag56079
    Key algorithm7
    Key digest type1
    Key digest09f22e86b96725c2f41891bc260304b903c30448
  • Copy the contents of the DS record and submit it to your ISP or, more commonly. to the domain registrar or certificate authority related to the parent DNSSEC domain.
