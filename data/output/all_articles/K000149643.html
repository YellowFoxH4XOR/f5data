K000149643: Updating a Kubernetes TLS Secret with a new certificate and key

Type
Support Solution
Published
2025-02-05
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Ingress Controller
Source
https://my.f5.com/manage/s/article/K000149643

Description

  • You want to update a Kubernetes TLS Secret that is referenced by an NGINX Ingress Controller resource with a new certificate and key

Environment

  • NGINX Ingress Controller
  • Kubernetes TLS Secret

Cause

  • The current SSL certificate referenced by the Kubernetes TLS Secret is expiring soon

Recommended Actions

1. Backup the Current Secret:

       kubectl get secret <secret-name> -n <namespace> -o yaml > backup-secret.yaml

2. Replace Secret (Recreate Secret)

       kubectl delete secret <secret-name> -n <namespace>
       kubectl create secret tls <secret-name> --cert=new_certificate.crt --key=new_private.key -n <namespace>

3. Confirm the Secret is Updated

       kubectl get secret <secret-name> -n <namespace> -o jsonpath="{.data['tls\.crt']}" | base64 -d | openssl x509 -noout -text
       kubectl get secret <secret-name> -n <namespace> -o jsonpath="{.data['tls\.key']}" | base64 -d | openssl rsa -noout -text

Note: Kubernetes Ingress Controller should automatically reload the updated TLS Secret. You do not need to restart them manually.

4. Test the update from the client side (e.g., via a browser or using tools like curl) to confirm the new certificate is applied:

       openssl s_client -connect 192.168.0. 1:443 -servername www.example. com </dev/null 2>/dev/null | openssl x509 -noout -dates
  • Example Output:
       notBefore=Sep 12 16:15:35 2024 GMT
       notAfter=Sep 11 16:15:35 2029 GMT
