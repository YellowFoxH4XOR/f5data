K000159068: BIG-IP APM Edge Client Network Access Fails with Error Page After Authentication When HTTP Only Cookie Option is Enabled

Type
Support Solution
Published
2026-01-18
Updated
2026-01-18
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000159068

Description

Network access via BIG-IP APM fails after successful authentication when using the Edge Client for VPN connectivity. Users experience the following symptoms:

  • Edge Client displays an error page after successful login (Can't reach this page)
  • Network Access connection cannot be established despite successful authentication
  • VPN icon from the APM WebTop does not start the VPN connection
  • Client-side errors occur preventing tunnel establishment

The APM session logs show successful authentication and policy completion, but the Edge Client is unable to establish the VPN connection and display the webtop or network access resources.

Environment

  • BIG-IP APM module, version 17.5.1 (affects other versions as well)
  • Platform: F5-BIG-BT-I4600, C115
  • Access Policy configured with VPN/Network Access resources
  • Edge Client used for VPN connectivity
  • Access Profile Cookie Options configured with "HTTP Only" flag enabled

Cause

The "HTTP Only" cookie option was enabled in the Access Profile's Cookie Options settings. The HTTP Only flag is designed to include an HTTPOnly flag in the Set-Cookie HTTP response header to help mitigate the risk of client-side script access to protected cookies. However, this flag should only be used for LTM+APM access profile types and must NOT be enabled for VPN deployments with connectivity resources such as Network Access or Portal Access. When this flag is set, it prevents the Edge Client from properly accessing the required session cookies, causing the connection to fail.

Recommended Actions

Note: F5 Support suggests you perform the following set of actions out of working hours or during downtime.

  1. Using the Configuration Utility, navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies)
  2. Click the name of the relevant Access Profile
  3. From the top of the page, click the tab SSO / Auth Domains
  4. Uncheck the checkbox HTTP Only from the parameter Cookie Options
  5. Click the Update button
  6. Click the link Apply Access Policy from the top left of the page
  7. Test the Edge Client connection to verify successful Network Access connectivity

Additional Information

The HTTP Only flag in cookie settings is intended only for LTM-APM access profile types where users access applications through the browser without requiring connectivity resources. For BIG-IP APM deployments with connectivity resources (such as Network Access, Portal Access, etc.), do not set BIG-IP APM cookies with the HTTP Only flag.

When properly configured without the HTTP Only flag, the APM session logs will show successful policy completion followed by successful Edge Client connectivity. The session should remain active until the user disconnects or the session timeout is reached, rather than being terminated due to connection errors.

Browser-based VPN access may work correctly even with the HTTP Only flag enabled, but Edge Client connections will fail. This can lead to confusion during troubleshooting if testing is only performed with browser-based clients.
