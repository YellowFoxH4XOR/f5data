Description

When using F5 Access for macOS to connect to a BIG-IP APM VS configured with Microsoft Entra ID (Azure AD) as the authentication provider, if device compliance information status is expected as part of Conditional Access policies, it may fail to complete if F5 Access for macOS was not granted access to the SSO extension (providing the Primary Refresh Token). As a result, users will be denied VPN access despite completing authentication successfully, with an error such as:

You cannot access this righ now

Your sign-in was successful but does not meet the criteria to access this resource.

Environment

  • BIG-IP APM
  • F5 Access for macOS
  • Microsoft Entra ID Conditional Access policy requiring device compliance
  • Mac devices managed by Microsoft Intune with Platform SSO or Microsoft Enterprise SSO Extension configured

Symptoms

  • F5 Access for macOS connects to the BIG-IP APM VS and completes authentication successfully
  • Entra ID Conditional Access evaluation fails — device compliance is not satisfied
  • The VPN connection is denied despite the successfull user authentication

Cause

F5 Access for macOS uses an embedded WebView to render the Entra ID authentication page. This embedded WebView operates in an isolated context and cannot communicate out of the box with the Microsoft SSO Extension (the SSO broker) running on the Mac.

Recommended Actions

Configure the Microsoft Enterprise SSO Extension (or Platform SSO settings catalog policy) in Intune to explicitly allow F5 Access to participate in the SSO broker flow.

This is achieved by adding the F5 Access bundle ID (com.f5.access.macos) to the AppAllowList in the Intune configuration profile for the Microsoft SSO Extension.

Prerequisites

  • Mac devices are enrolled in Microsoft Intune
  • The Microsoft Enterprise SSO Extension or Platform SSO is already configured and deployed via MDM
  • F5 Access for macOS is installed on the Mac endpoints

Procedure

Step 1 — Locate the Microsoft SSO configuration profile in Intune

  • In the Microsoft Intune admin center, navigate to Devices > Configuration profiles
  • Locate the existing profile that configures the Microsoft Enterprise SSO Extension or Platform SSO settings catalog policy

Step 2 — Add the MacOS F5 Access bundle ID to the AppAllowList

In the SSO Extension configuration, add the following entry to the AppAllowList (the list of application bundle IDs permitted to use the SSO broker):

com.f5.access.macos

This explicitly grants F5 Access for macOS permission to interact with the Microsoft Enterprise SSO Extension and retrieve available PRT tokens during the authentication flow.

Step 3 — Deploy and test

  • Deploy the updated configuration profile to the target Mac devices via Intune
  • On a test Mac, launch F5 Access and attempt to connect to the BIG-IP APM VS
  • Verify that the authentication flow completes and that Entra ID Conditional Access (device compliance) is satisfied

Additional Information

  • For instructions on deploying F5 Access for macOS via MDM/Intune, refer to K000153125: BIG-IP administrator instructions for downloading and installing F5 Access Mac.
