Description

Nginx Limiting requests functionality allows to configure traffic limiting for different varieties of requirements. The basic of the feature is to allow passing certain amount of requests and rejecting excessive requests. For every rejected request nginx records the reason in the error log on [error] level as "... limiting requests, excess: <value> by zone "zone_name", ..." and counts so called "excess" value. The definition and estimating of exact value for this "excess" is confusing from the nginx blog post at the moment, as well as it is hardly understandable based on the nginx code snippet. This article provides the explanation based on the "representing" dependency from leaky bucket model along with several test examples for better understanding the "excess" value.

 

Error log record: 

2024/12/28 15:28:14 [error] 19274#19274: *2536 limiting requests, excess: 0.966 by zone "one", client: <client_ip>, server: localhost, request: "GET /111 HTTP/1.1", host: "nginx.example.org:8080"

Environment

Nginx Plus instance with "limit_req" configured. The test tool to send the external traffic, jmeter or wrk can be used, or simple "curl" command.

 

Cause

The Excess is calculated for every request but recorded in error log for excessive requests only (rejected or passed in "dry ran" mode) 

Recommended Actions

The general formula of "excess":

excess = excess_initial - rate * <delta-in-seconds-since-last-successful-request> + <request1>

Where:

    • excess_initial =1 (and 1+burst, if you have the burst)
    • rate=1/60 for r/m, and rate=1 for r/s (from the configuration)
    • <request1> = 0 for rejected requests, and =1 for accepted requests.

 

Test 1: rate=1 r/m, config and example of the log, 2 cases

Configuration:

limit_req_zone $binary_remote_addr zone=one:10m rate=1r/m;
#...;
server {
  #...;
  location / {
          #...;
          limit_req zone=one;
          proxy_pass http://backend;

Summary

What is the "excess" value displayed in error log record:

Excess represents the part of time period (+ burst, e.g. "over" the burst) that remains till the moment when nginx will allow to pass the next request. It is calculated for every single excessive request, doesn't depend on the load, and depends only on the time when this particular request comes.
