Known Issue

Note: This issue only affects the BIG-IP 1500, 3400, 6400, and 6800 platforms.

This is a result of a known issue. The BIG-IP system may incorrectly report that the chassis fan has failed, is no longer operating, or is below RPM threshold (3000 RPM). As a result, the BIG-IP system logs an error message in the /var/log/ltm file that appears similar to the following example:

system_check: 010d0005:3: Chassis fan 10x: status (0) is bad.

This behavior is due to a SMBus timing issue, in which the system_check script communicates with various monitored hardware components in order to obtain information.

F5 Product Development tracked this issue as CR63196 and it was fixed in BIG-IP 9.1.3, 9.3.0 and 9.4.0. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, or Link Controller release notes.

Workaround

You must first verify whether you are experiencing this issue. After verifying the issue, you can work around the issue by performing a full power down. To do so, perform the following two procedures:

Verifying whether you are experiencing this issue

You may be able to verify whether you are experiencing this issue, by attempting to successfully poll the related SNMP OID branch. To do so, type the following command, replacing public with the SNMP community string configured for your BIG-IP system:

snmpwalk -On -c public localhost .1.3.6.1.4.1.3375.2.1.3.2.1

Systems affected by this issue will report a timeout after about 10 seconds that appears similar to the following example:

Timeout: No Response from localhost

Note: The timeout error response may be also generated under a number of other conditions, such as a bad community string, an SNMP misconfiguration, etc.

Working around this issue by performing a full power down

Important: The following workaround clears the issue temporarily and does not prevent the issue from recurring. In order to prevent the issue from recurring, upgrade to a BIG-IP version where this issue has been resolved.

If upgrading is not an immediate option, you can work around this issue by performing a full power down, or by using the full_box_reboot command on BIG-IP versions that support this option.

Note: This operation is also known as a hard reset and is required, since a normal reboot will only restart the host subsystem and not restart the SCCP. Both the host subsystem and the SCCP must be reset to clear the issue.

In BIG-IP 9.0.0 through 9.1.1 and 9.2.0 through 9.2.3, you can use the shutdown -h now command to safely halt the host subsystem; then you must remove power from the BIG-IP system in order to power down the SCCP as well.

In BIG-IP 9.1.2, 9.1.3, 9.2.4 and later, you can use the full_box_reboot command to restart both the host subsystem and the SCCP.
