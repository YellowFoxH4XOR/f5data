K000150007: MySQL monitor may connect with TLSv1.1 to back end database servers

Type
Support Solution
Published
2025-02-28
Updated
2026-04-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150007

Description

When monitoring an LTM pool member with a MySQL monitor, the TLS connection may use an outdated TLSv1.1 version, and there are no controls or settings to change this.

Environment

  • BIG-IP LTM
  • MySQL pool members
  • MySQL monitor assigned to the pool members

Cause

The MySQL monitor type simply calls the Oracle Java Database Connector (JDBC) for MySQL, which makes the decision about which TLS version to use. When a client connects to a MySQL server, the server initially sends it a Server Geeting packet, describing its version, features, and capabilities - this data includes a flag that indicates whether the server supports upgrading to TLS. If the client also supports TLS connections, then the client will indicate that in its own capabilities list, and will initiate a TLS handshake by sending a TLS Client Hello.

Testing has shown that the MySQL JDBC client will connect using TLSv1.1 when speaking to any version of MySQL server lower than 8.0, and will use TLS1.2 for server version 8.0 and higher. This is not configurable, and is hard-coded into the connector, which is provided by Oracle.

Recommended Actions

To use TLSv1.2 with monitor probes for versions of MySQL below 8.0, you must implement an EAV (external) monitor that uses the MySQL command-line client, which does not have the same limitations as the JDBC.

For example:

#!/bin/bash 
 
# arguments supplied by bigd:
# $1 = IP (::ffff:nnn.nnn.nnn.nnn notation or hostname)
# $2 = port (decimal, host byte order)
# $3 and higher = additional arguments
 
user=$MYSQL_USER
passwd=$MYSQL_PASSWORD
 
# Name of the pidfile
pidfile="/var/run/$MONITOR_NAME.$1..$2.pid"
if [ -f $pidfile ]
then
   kill -9 -`cat $pidfile` > /dev/null 2>&1
fi
 
echo "$$" > $pidfile
# Remove the IPv6/IPv4 compatibility prefix 
node_ip=`echo $1 | sed 's/::ffff://'`
 
result=$(MYSQL_PWD=$MYSQL_PASSWWORD mysql --ssl --host $node_ip --port $2 --user "$MYSQL_USER" -e "SELECT @@VERSION" 2>&1)
 
if [ $? -eq 0 ]
then
    rm -f $pidfile
    echo "up"
else
    echo "$0: Mysql monitor probe failed for $node_ip:$port with message $result" | logger -p local0.notice
fi

To install and apply the external monitor script:

Using the BIG-IP GUI:

    1. Import the script  (System >> File Management >> External Monitor Program File List >> Import) 
    2. Create an external monitor (Local Traffic >> Monitors >> Create ,  Type: External, External Program: (name of program file from previous step)

 

Using the BIG-IP traffic-management shell (tmsh)

    1. tmsh create sys file external-monitor mysql_eav_script source-file file:///tmp/filename
    2. tmsh create ltm monitor external xxxxx run /Common/mysql_eav_script user-defined MYSQL_PASSWD mysqlpassword user-defined MYSQL_USER mysqluser
