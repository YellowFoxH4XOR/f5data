Known Issue

System statistics may fail to update, report sudden spikes in traffic, or report negative statistical values.

This issue occurs when one of the following conditions are met:

  • The system is spawning and reaping processes, such as a large number of external monitors, on a frequent basis.
  • The configuration includes iRules that frequently use the SSL::profile command to select different SSL profiles for a virtual server.

    For more information about the SSL::profile command, refer to the SSL::profile wiki page on F5 Cloud Docs.

Under some conditions, the BIG-IP system may fail to report statistics over time. This issue occurs when there are frequent changes occurring to the underlying statistics data structures.

Impact

System statistics fail to merge, which results in an incorrect view of system behavior and operation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • System statistics report the following:
    • Unchanging statistics; for example, all zeros
    • Sudden spikes in traffic
    • Negative values for some counters
  • System performance graphs appear to have gaps of missing data.
  • If debug logging is enabled for the merged process, the system logs messages similar to the following example to the /var/log/ltm file:

    debug merged[12345]: 011b0999:7: remerge detected generation change : merge delayed

Workaround

To work around this issue, there are 2 options:

Option 1: Reduce the frequency of changes in the statistics data structures. The specific action to take depends on what is triggering them. To do so, use any or all of the following:

Impact of workaround: Changing the design of an iRule or other configuration parameters may have additional effects on traffic processing. Ensure that any modification you make is compatible with your environment.

  • Reduce the frequency of configuration changes.
  • Reduce the usage of the SSL::profile command in iRules.
  • Reduce the number or frequency of processes spawned by the system. For example, reduce the amount of external monitors used in your configuration.

Option 2: Configure the merged.method system database variable to use the slow_merge setting. To do so, perform the following procedure:

Note: On certain older BIG-IP versions, F5 recommends against using the slow_merge setting. For more information, refer to K80886243: Statistics fail after configuring the merge method with the slow_merge option

Impact of workaround: Modifying the merge method causes an increase to the system CPU utilization while merging statistics. Performing this workaround has the side effect of disabling tmstat snapshots on the device. The tmstat snapshots are intended for F5 Internal use only. The lack of snapshots has no bearing on the functionality of your system; however, F5 Support may be impacted in their ability to troubleshoot issues on your system.

  1. Log in to the command line.
  2. Configure the merged.method database variable to use the slow_merge setting by typing the following command:
    tmsh modify sys db merged.method value slow_merge
  3. Change the merge-interval value to 2 to reduce CPU usage when merge-method is slow-merge.
    tmsh modify /sys db merged.merge.interval {value "2"}
