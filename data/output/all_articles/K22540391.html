Known Issue

Older BIG-IP DNS (formerly known as BIG-IP GTM) monitor instances may remain in the system after performing a configuration merge that modifies an existing monitor. For example, you merge a configuration that replaces an existing monitor with a new one.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP DNS configuration contains global server load balancing (GSLB) objects with health monitors that are actively monitoring virtual servers.
  • You perform a configuration merge using the following command syntax:

    tmsh load sys config merge <file>

  • The configuration merge modifies the type of health monitor used by GSLB objects, such as servers, virtual servers, pools, or pool members in the configuration.

Impact

When the old monitor instance exists in the configuration, restarting a secondary slot in a VIPRION system or vCMP guest will result in a restart loop.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Secondary slots in a VIPRION system or vCMP guest will continuously restart.
  • Error messages in the /var/log/ltm file appear similar to the following examples:

    err mcpd[8982]: 01020036:3: The requested monitor instance (/Common/bigip 10.10.9.39 443 gtm-vs) was not found.
    err mcpd[8982]: 01070734:3: Configuration error: Configuration from primary failed validation: 01020036:3: The requested monitor instance (/Common/bigip 10.10.9.39 443 gtm-vs) was not found.... failed validation with error 16908342.
