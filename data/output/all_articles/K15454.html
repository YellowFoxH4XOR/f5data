Known Issue

The BIG-IP APM full webtop may not display resources.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access policy that includes full webtop access.
  • A large amount of resources is assigned to the user's full webtop.

The BIG-IP APM system automatically generates an XML list of resource items based on the assigned access policy resources for a user. The XML file is then used by the user's browser to display the webtop resource icons. The XML resource list file has a maximum generation file size of 4 KB. The amount of resources that can be displayed on the webtop varies greatly based on the byte length of each of the resource names and the bytes used for the configuration information of each resource. When the webtop XML maximum file size is exceeded, the webtop resource icons are not displayed.

Impact

The BIG-IP APM webtop does not display the available resources for the user.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H473319 on the Diagnostics > Identified > Medium screen.
  • BIG-IP APM full webtop users see an error message similar to the following example:

    Object required or 'null' is null or not an object
  • The system logs messages similar to the following example in the /var/log/apm file:

    err Access encountered error: ERR_NOT_SUPPORTED. File: ../modules/hudfilter/access/access_euie.c, Function: access_uri_info_alloc, Line: 563
    err Access encountered error: ERR_MEM. File: ../modules/hudfilter/access/access.c, Function: access_process_state_client_finish_portal_req, Line: 3453
    err Access encountered error: ERR_MEM. File: ../modules/hudfilter/access/access.c, Function: hud_access_handler, Line: 2050
  • Reducing the number of access policy available resources included in the user's full webtop allows the webtop to start displaying resources.

There is no work around for this issue other than limiting the number of resources available to the user in the access policy.
