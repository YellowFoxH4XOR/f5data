Issue

You should consider using this procedure under the following condition:

  • The F5 BIG-IP Container Ingress Service (CIS) for Kubernetes is unable to manage F5 BIG-IP devices from Kubernetes.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You are running compatible versions of Kubernetes and BIG-IP CIS in accordance with the BIG-IP CIS/Platform compatibility matrix on the F5 BIG-IP Container Ingress Service (CIS) Releases and Versioning page.
  • You integrate the BIG-IP system to the Kubernetes cluster with flannel VXLAN.

BIG-IP system integration for Kubernetes

You can connect the BIG-IP system to a Kubernetes cluster using flannel VXLAN. After you connect it, the F5 BIG-IP CIS for Kubernetes enables the BIG-IP system to serve north-south traffic in the Kubernetes cluster.

For more information about F5 BIG-IP integration for Kubernetes, refer to F5 Container Ingress Services - Kubernetes.

Recommended Actions

Procedures

When experiencing BIG-IP system connectivity issues to a Kubernetes cluster, you can use the following troubleshooting steps to determine the root cause:

  • Verify the BIG-IP system licenses
  • Verify the VTEP MAC address on the BIG-IP system
  • Verify the vxlan local address on the BIG-IP system
  • Verify FDB records on the BIG-IP system
  • Modify FDB records on the BIG-IP system
  • Verify ARP records on the BIG-IP system
  • View VXLAN tunnel statistics on the BIG-IP system
  • Capture VXLAN tunnel traffic on the BIG-IP system

Verify the BIG-IP system licenses

When using cluster mode to integrate the BIG-IP system to the Kubernetes cluster, you must use a BIG-IP system license that includes SDN services. If you are using a network fabric requiring Border Gateway Protocol (BGP), such as Calico, you must also use a BIG-IP system license that includes BIG-IP Advanced Routing Module (BIG-IP ARM). Perform the following procedure to verify your BIG-IP system license.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To verify that the license includes SDN Services and BIG-IP ARM, enter the following command:

    show sys license | grep 'SDN Services\|Routing Bundle'

    The command output appears similar to the following example:

    SDN Services
    Routing Bundle

  3. To quit tmsh, enter quit.

Verify the VTEP MAC address on the BIG-IP system

When integrating the BIG-IP system to a Kubernetes cluster, you create the BIG-IP system as a dummy node using the VXLAN Tunnel Endpoint (VTEP) MAC address. To verify the VTEP MAC address, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify the VTEP MAC address, enter the following command:

    show net tunnels tunnel <flannel_vxlan> all-properties

    The command output appears similar to the following example:

    -------------------------------------------------
    Net::Tunnel: flannel_vxlan
    -------------------------------------------------
    MAC Address                     00:50:56:92:78:55
    Interface Name                      flannel_vxlan
    ...

  3. To quit tmsh, enter quit.

Verify the vxlan local address on the BIG-IP system

When integrating the BIG-IP system to a Kubernetes cluster, the local address of the vxlan tunnel should be reachable by other nodes in the Kubernetes cluster. To verify the local address, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify the local address, enter the following command:

    list net tunnels tunnel <flannel_vxlan>

    The command output appears similar to the following example:

    net tunnels tunnel flannel_vxlan {
        if-index 144
        key 1
        local-address 172.24.171.54
        profile fl-vxlan
    }

  3. To quit tmsh, enter quit.

Verify FDB records on the BIG-IP system

After you successfully deploy the F5 Container Ingress Service (CIS) in the Kubernetes cluster, CIS populates the BIG-IP system forwarding database (FDB) with records of Kubernetes nodes. Perform the following procedure to verify the FDB entries on the BIG-IP system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify FDB records on the BIG-IP system, enter the following command:

    show net fdb tunnel <flannel_vxlan>

    The command output appears similar to the following example, where each entry record represents a Kubernetes node:

    -------------------------------------------------------------------
    Net::FDB
    Tunnel         Mac Address        Member                    Dynamic
    -------------------------------------------------------------------
    flannel_vxlan  12:85:12:68:84:42  endpoint:172.24.171.45%0  no
    flannel_vxlan  b6:c9:a0:d4:10:a9  endpoint:172.24.171.51%0  no
    flannel_vxlan  d2:56:d9:95:4c:16  endpoint:172.24.171.52%0  no

  3. To quit tmsh, enter quit.

Modify FDB records on the BIG-IP system

F5 BIG-IP CIS should automatically populate FDB records of Kubernetes nodes. However, depending of your environment, you may have to manually modify FDB records on the BIG-IP system. Perform the following procedure to modify FDB records on the BIG-IP system.

Note: Depending on your Flannel VXLAN tunnel profile, you may not be able to perform this procedure. For example, when the Flooding-Type parameter of your VXLAN profile is none, you cannot manually add FDB records.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To create an FDB record, enter the following command:

    modify net fdb tunnel <tunnel_name> records add { ff:ff:ff:ff:ff:ff { endpoints add { IP_addresses } } }

  3. To delete an FDB record, enter the following command:

    modify net fdb tunnel <tunnel_name> records delete { ff:ff:ff:ff:ff:ff }

  4. To quit tmsh, enter quit.

Verify ARP records on the BIG-IP system

After you successfully deploy F5 resources, you should be able to reach Kubernetes pods exposed to the BIG-IP system and each should have a record in the BIG-IP Address Resolution Protocol (ARP) table. Perform the following procedure to verify ARP records on the BIG-IP system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To verify ARP records on the BIG-IP system, enter the following command:

    show net arp all

    The command output appears similar to the following example, where the static entry records represent Kubernetes pods:

    -----------------------------------------------------------------------------------------------
    Net::Arp
    Name                     Address        HWaddress          Vlan         Expire-in-sec  Status
    -----------------------------------------------------------------------------------------------
    /Common/k8s-10.244.0.3   10.244.0.3     12:85:12:68:84:42  -            -              static
    /Common/k8s-10.244.1.8   10.244.1.8     b6:c9:a0:d4:10:a9  -            -              static
    /Common/k8s-10.244.2.10  10.244.2.10    d2:56:d9:95:4c:16  -            -              static
    172.24.171.45            172.24.171.45  00:50:56:92:5a:81  /Common/wan  83             resolved
    172.24.171.51            172.24.171.51  00:50:56:92:4e:f2  /Common/wan  96             resolved
    172.24.171.52            172.24.171.52  00:50:56:92:1d:77  /Common/wan  43             resolved

  3. To quit tmsh, enter quit.

View VXLAN tunnel statistics on the BIG-IP system

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view VXLAN tunnel statistics, enter the following command:

    show net tunnels tunnel <flannel_vxlan>

    The command output appears similar to the following example:

    --------------------------------------
    Net::Tunnel: flannel_vxlan
    --------------------------------------
    Incoming Discard Packets             0
    Incoming Error Packets               0
    Incoming Unknown Proto Packets       0
    Outgoing Discard Packets             0

    HC Incoming Octets               12.7M
    HC Incoming Unicast Packets     172.2K
    HC Incoming Multicast Packets        0
    HC Incoming Broadcast Packets        0
    HC Outgoing Octets               17.3M
    HC Outgoing Unicast Packets     258.3K
    HC Outgoing Multicast Packets        0
    HC Outgoing Broadcast Packets        0

  3. To quit tmsh, enter quit.

Capture VXLAN tunnel traffic on the BIG-IP system

When troubleshooting BIG-IP system connectivity issues, you can capture traffic on the VXLAN tunnel from the command line. For example, using the following command captures all traffic on the VXLAN tunnel flannel_vxlan, including link-level headers:

tcpdump -e -i flannel_vxlan
