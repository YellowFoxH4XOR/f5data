K8397: Network Access Connection fails when a primary proxy server in proxy auto-configuration script is unavailable

Known Issue

This is the result of a known issue. If a user’s browser is configured to use a proxy auto-configuration (PAC) script, and the primary proxy server defined in the PAC script is unavailable, the Network Access Connection fails with an error message similar to the following example:

Connecting to <firepass hostname or ip address> failed –
No connection could be made because the target machine
actively refused it. Unable to connect to the proxy server.

The correct behavior is for the FirePass client-side component to follow the fallback policy defined in the PAC script.

For example, the following PAC script defines proxy1.siterequest.com as the primary proxy server, proxy2.siterequest.com as the secondary proxy server, and a direct connection as the final fallback:

function FindProxyForURL(url, host) {
        return "PROXY proxy1.siterequest.com:8080; proxy2.siterequest.com:8080; DIRECT";
}

When a user with the above PAC script attempts to establish a Network Access Connection, and proxy1.siterequest.com:8080; is unavailable, the Network Access connection fails. In this example, the FirePass client-side component displays correct behavior by attempting to reach proxy2.siterequest.com:8080 when proxy1.siterequest.com:8080 is unavailable. If neither proxy server is available, the FirePass client-side component should attempt a direct connection.

F5 Networks Product Development tracked this issue as CR78269 and it is fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass Release Notes.

This issue still exists in the FirePass version 5.x branch.

Additionally, Cumulative Hotfix HF-552-11 has been issued for FirePass version 5.5.2 and Cumulative Hotfix HF-601-10 has been issued for FirePass version 6.0.1. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Networks Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

Users can work around this issue by disabling the PAC script option in their browser configuration before opening a Network Access Connection.
