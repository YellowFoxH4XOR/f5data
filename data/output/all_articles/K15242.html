Known Issue

On rare occasions, the BIG-IP MySQL or MSSQL monitor may stop responding after repeated connection failures.

This issue occurs when all of the following conditions are met:

  • The BIG-IP configuration uses a MySQL or MSSQL monitor to monitor the database server resources.
  • The database server receives several connection failures from the affected monitor. For example, an incorrect password may have caused the connection failures.
  • The database server closes the connection with the affected monitor.
  • The affected monitor continues to use the cached database connection that is no longer valid.

Impact

The BIG-IP system falsely marks the database server as unavailable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H459939 on the Diagnostics > Identified > High page.
  • The BIG-IP system stops using the affected monitor to send probes to the database server. You can observe this issue by using the tcpdump utility to capture traffic between the BIG-IP system and the database server that is being monitored.
  • In the /var/log/DBDaemon.log file, you observe that the database server is marked as unavailable, while the database server is actually available. You may observe this symptom when debugging is enabled for the affected monitor.

To work around this issue, you can change the count setting of the affected MySQL or MSSQL monitor to a non-zero value that specifies the number of monitor probes to be sent per connection to the database. A count value of zero (0), which is the default value, indicates the BIG-IP system will leave a single connection open to send probes. To work around the issue, perform one of the following procedures:

Modifying the count setting on a BIG-IP LTM MySQL or MSSQL monitor

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the count setting of the affected MySQL or MSSQL monitor using the following command syntax:

    modify /ltm monitor <mysql_or_mssql> <monitor_name> { count <count_number> }

    For example, the following command changes the count setting to two (2) on the MySQL monitor named example:

    modify /ltm monitor mysql example { count 2 }

  3. Repeat step 2 for all affected monitors.
  4. Save the configuration change by typing the following command:

    save /sys config

  5. To exit the tmsh utility, type q and press Enter.

Modifying the count setting on a BIG-IP GTM MySQL or MSSQL monitor

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Modify the count setting of the affected MySQL or MSSQL monitor using the following command syntax:

    modify /gtm monitor <mysql_or_mssql> <monitor_name> { count <count_number> }

    For example, the following command changes the count setting to two (2) on the MSSQL monitor named example:

    modify /gtm monitor mssql example { count 2 }

  3. Repeat step 2 for all affected monitors.
  4. Save the configuration change by typing the following command:

    save /sys config gtm-only

    Note: Step 4 is necessary only if Automatic Configuration Save is disabled.

  5. To exit the tmsh utility, type q and press Enter.
