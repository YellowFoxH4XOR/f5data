Description

This article intends to solve system behavior of failing to receive incoming mails via mail virtual server
In traffic capture a RST message originated by the BIG-IP can be seen (packet 85):

85    2021-08-03 10:31:25.933333    10.0.19.231    10.0.22.250    25 → 37280 [RST, ACK] Seq=0 Ack=3054368688 Win=0 Len=0 [F5RST: TCP closed]

TCP connections hang. Memory usage increases. TMM restarts.

Numerous hanging connections reported similar to the following:
-- config # tmsh show sys conn protocol tcp

10.0.0.1:5855  10.0.0.250:80  any6.any  any6.any  tcp  449  (tmm: 0)  none  none
10.0.0.1:5891  10.0.0.250:80  any6.any  any6.any  tcp  449  (tmm: 0)  none  none

Those connections hang indefinitely (even past the idle timeout).
Memory increases, eventually leading to a possible TMM out-of-memory condition, requiring a TMM restart.
Traffic disrupted while TMM restarts.

Environment

Pool member fails to respond with an ACK to BIG-IP system serverside FIN.
The BIG-IP system serverside connection eventually times out, and the clientside connection is orphaned

Cause

The cause for this behavior is bug ID754143

Recommended Actions

  1. Perform failover and reboot the current standby device
  2. Failover again and reboot the standby device
  3. Upgrade your system to version 13.1.4.1
