Known Issue

This is the result of a known issue. If you enable the Verified Accept option for a TCP profile, all virtual servers configured with that profile may stop accepting new connections. This issue is triggered when a client resets an established connection with a virtual server that is configured with a susceptible TCP profile. Once this event has occurred, the TCP profile will no longer accept new connections, causing all virtual servers configured with that profile to become unavailable. A packet capture taken at this time will show the client trying to connect to the virtual server (retransmitting the same SYN packet multiple times) and the BIG-IP system not attempting to connect to the pool member at all.

Note: The Verified Accept TCP profile option is available in version 10.x and is disabled by default. When enabled, the system verifies that the pool member is available to accept the connection by sending the server a SYN and waiting for the SYN-ACK before responding to the client's SYN with a SYN-ACK.

F5 Product Development tracked this issue as ID 348660 and it was fixed in BIG-IP 10.2.2.

For information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about downloading software from F5, refer to K167: Downloading software from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You should not use the Verified Accept option until the issue described in this Solution has been resolved in a future version of the software. To return the BIG-IP system to its normal operating state, disable the Verified Accept option for every TCP profile and then restart TMM by running the bigstart restart tmm command.

Important: On a VIPRION platform, run the clsh bigstart restart tmm command instead. This command will restart TMM on every blade.

Important: Restarting TMM will temporarily interrupt traffic processing. Additionally, if the BIG-IP system is the active member of a redundant pair, the system will failover.
