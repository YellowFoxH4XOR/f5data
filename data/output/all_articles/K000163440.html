K000163440: Why IP Reputation does not block when the feature "HTTP Redirect to HTTPS" is enabled?

Description

Traffic that should be denied by the IP Reputation Protection is allowed when "HTTP Redirect to HTTPS" configured in F5 Distributed Cloud.

Logs show traffic hitting the "ves-io-always-allow" rule in the first policy.

 

Environment

  • Product: F5 Distributed Cloud — Web App & API Protection
  • Feature: IP Reputation (HTTP Load Balancer)
  • Feature: HTTP Redirect to HTTPS (HTTP Load Balancer)
  • Configuration:
    • IP Reputation Protection applied to an HTTP Load Balancer
    • HTTP Redirect to HTTPS enabled on the HTTP Load Balancer

Cause

The "ves-io-always-allow" is a built-in F5 Distributed Cloud (XC) service policy set that appears in security/policy logs as a catch-all "default allow" rule. It is the policy_set name that shows up in policy_hits log entries when a request matches no explicit deny/allow rule and falls through to the default action, with result: "default_allow" — meaning the traffic wasn't evaluated against a custom service policy and was simply let through by default 1.

For example:

"rsp_code": "301",
"rsp_code_class": "3xx",
"rsp_code_details": "direct_response", <================== Direct Response from the "HTTP Redirect to HTTPS" feature,
"dst_ip": "159.10.10.10",
"dst_port": "80", <================== Port 80
"policy_hits": {
"policy_hits": [
{
"ip_risk": "HIGH_RISK",
"ip_threat_categories": "SPAM_SOURCES",
"ip_trustscore": "5",
"ip_trustworthiness": "LOW",
"malicious_user_mitigate_action": "MUM_NONE",
"policy_set": "ves-io-always-allow",
"rate_limiter_action": "none",
"result": "default_allow" <============= Default Allow Policy
}
]
},

Answer/Recommended Actions

In case where a Load Balancer is listening on over HTTP (80 port) but also have the enabled feature "HTTP Redirect to HTTPS" the HTTP requests will be first matching ves-io-always-allow with default_allow instead of being evaluated prior to the Security feature of the Load Balancer, even though those requests were flagged under any IP threat/reputation such as SPAM_SOURCES.

 

In short: This is not a policy the customer configures, it is the system default fallback that "always allows" traffic when no other policy rule (allow or deny) matches, and it expected to observe it when the Redirection from HTTP to HTTPS is happening due to the Load Balancer configuration.
