Known Issue

The domain-join command will fail when the user ID is specified using a fully qualified Kerberos name.

This issue occurs when one of the following conditions is met:

  • Joining a CIFS global server to a domain, and specifying a fully qualified Kerberos name from the joined domain as the user ID to authenticate the domain join request.

    For example, you join the vip1.domain.com global server to the domain.com domain and specify the user ID as administrator@domain.com.
  • Joining a CIFS global server to a child domain, and specifying a fully qualified Kerberos name from a trusted parent domain of the joined domain as the user ID to authenticate the domain join request.

    For example, you join the vip1.child.domain.com global server to the child.domain.com domain and specify the user ID as administrator@domain.com.

The ARX system appends the domain joined to the end of the username specified to join the domain. For example, if you use the domain-join command to join a CIFS service to a domain.com domain, and the fully qualified Kerberos name specified is administrator@domain.com, the ARX system will append an additional @domain.com to the username as follows:

administrator@domain.com@domain.com

As a result, the domain join request will fail.

The domain-join command registers a CIFS front-end service with its Active-Directory (AD) domain. This is similar to adding client computers to the Active Directory domain, and it requires a sufficiently-privileged username and password. For information about the minimal access privileges required to join the domain with either a new machine account or a pre-created account, refer to the domain-join command in the ARX CLI Reference Guide.

Impact

You are unable to register a CIFS service with the AD domain.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The domain-join command fails with an error message that appears similar to one of the following examples:

    • ARX version 6.x

      % ERROR: ADJOIN_LDAPSIGN (44892222):
        The domain-join operation failed because the domain controller's security policy requires LDAP signing, which is not supported. See  documentation for more information.
    • ARX version 5.x

      % ERROR: ADJOIN_GENERIC (44892216):
        The domain-join operation failed due to a generic error. See documentation for next steps.
  • The ARX system logs an error message to the syslog file that appears similar to the following example:

    : net:   kerberos_kinit_password  administrator@domain.com@DOMAIN.COM@DOMAIN.COM failed:  Malformed representation of principal

Workaround

To work around this issue, you can use a sufficiently privileged account local to the joined domain and enter only the user ID without specifying the fully qualified Kerberos name.

For example, use administrator instead of administrator@domain.com.

To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter the CIFS service configuration mode for the global server to be configured using the following command syntax:

    cifs <Global_Server_Name>

    For example, enter CIFS service configuration mode for a global server named vip1.domain.com by typing the following command:

    cifs vip1.domain.com
  5. Join the CIFS service to the domain using the following command syntax:

    domain-join <domain>

    For example, join the vip1.domain.com global server to the domain by typing the following command:

    domain-join domain.com

    The domain-join command will prompt for a username and password.

    Note: The domain-join command requires a sufficiently privileged username and password to join the domain with either a new machine account or a pre-created account.
  6. At the Username prompt, enter a sufficiently privileged username local to the joined domain.

    For example: 

    administrator
  7. At the Password prompt, enter the password.
  8. Enable the global service by typing the following command:

    enable
  9. Exit global configuration mode by typing the following command:

    end
