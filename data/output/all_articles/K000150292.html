Description


This article explains the cause and resolution of an issue where requests from allowed domains are blocked due to the "Origin header validation failed: Origin is not allowed" violation after enabling CSRF protection with the verify origin feature in BIG-IP ASM.


Environment


  • BIG-IP ASM or Advanced WAF
  • CSRF Protection with Verify Origin enabled
  • Virtual server listening on a non-standard HTTPS port (e.g., 8443 or 10443)
  • Requests originating from a mobile application

Cause


The violation "Origin header validation failed: Origin is not allowed" occurs because the virtual server listens on non-standard HTTPS port. However\, the Origin header is sent without the port information:


Origin: https://example-origin.com


By design, ASM compares the Origin header hostname with one of the configured Host Names in the policy and also checks the port. Since the Origin header does not explicitly specify a port, ASM defaults to the scheme-based port (443 for HTTPS). This mismatch causes the request to be blocked.


Standard web browsers automatically append non-standard ports to the Origin header, preventing this issue. However, mobile applications may not include the port, leading to enforcement failures.


Recommended Actions


1. Modify the Client Application Behavior:


Ensure that the mobile application explicitly appends the port number to the Origin header when making requests.


Example:


Origin: https://example-origin.com:10443


2. Workarounds on ASM:


The "Host Names" settings in ASM do not support port configuration, meaning a server-side fix is not available. The resolution must be applied on the client side.


Additional Information


ASM enforces strict origin validation by design and does not provide built-in options to ignore port differences. If modification of the client application is not feasible, consider alternative CSRF protection mechanisms, such as CSRF tokens, to reduce reliance on the Origin header.
