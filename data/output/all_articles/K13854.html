Known Issue

The BIG-IP system incorrectly allocates the SSL session cache size based on per virtual. This issue occurs when the following condition is met:

  • An SSL profile is referenced by two or more virtual servers.

The global SSL session cache size is shared among all SSL profiles that are actively in use, even though the total combined SSL session cache size for all SSL profiles can be configured to be greater than the value of the global session cache size. As a result of this issue, the BIG-IP system may evict older cached sessions earlier than expected.

The following example illustrates how this issue affects the sharing of the global SSL session cache. For example, there are four virtual servers referencing one SSL profile and 65,536 existing cached sessions for each virtual server (four virtual servers with 65,536 cached sessions fill up the global SSL session cache size of 262,144). When one of the virtual servers needs to store a new session in the cache, the BIG-IP system has to evict the oldest entry associated with the SSL profile. In another example of four virtual servers referencing SSL profile A and another four virtual servers referencing SSL profile B, and 32,768 existing cached sessions for each virtual server (8 virtual servers with 32,768 cached sessions fill up the global SSL session cache size of 262,144), when one of the virtual servers referencing SSL profile B needs to store a new session in the cache, the BIG-IP system has to evict the oldest entry associated with SSL profile B.

Impact

The BIG-IP system may fail to resume SSL sessions.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • SSL sessions may fail to resume.
  • The BIG-IP system may use resources higher than expected.

Workaround

To avoid this issue, you should consider limiting the total combined configured session size for all SSL profiles assigned to virtual servers to the value of the global session cache size. For example, if you have four virtual servers referencing one SSL profile, you may want to consider configuring the session Cache Size setting for the profile to 65,536 (25 percent of the global cache size of 262,144). If you have four virtual servers referencing SSL profile A and another four virtual servers referencing SSL profile B, you may want to consider configuring the session Cache Size setting for each profile to 32,768.

For information about configuring the Cache Size setting for an SSL profile, refer to K6767: Overview of the BIG-IP SSL session cache profile settings.

Impact of workaround: None.
