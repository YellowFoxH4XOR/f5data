Known Issue

This is the result of a known issue. The subsnmpd and rmonsnmpd SNMP subagents are stopped but not restarted after creating an SNMPv3 access record. Failure to restart the subagents will cause v1, v2, and v3 SNMP queries to fail for some SNMP objects.

F5 Networks Product Development tracked this issue as CR72002 and it was fixed in BIG-IP version 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, or Link Controller Release Notes.

Workaround

If upgrading is not an immediate option it is possible to restart the subsnmpd and rmonsnmpd SNMP subagents from the command line, by performing the following procedure:

  1. Log in to the BIG-IP system command line.
  2. Restart the subsnmpd and rmonsnmpd SNMP subagents, by typing the following command:

    bigstart startup subsnmpd rmonsnmpd

  3. Verify that the subsnmpd and rmonsnmpd SNMP subagents restarted, by typing the following command::

    bigstart status | grep -i snmp

    The command will display an output similar to the following:

    # bigstart status |grep -i snmp
    nokiasnmpd   down 22 hours
    rmonsnmpd    run (pid 21271) 3 seconds, 1 start
    snmpd        run (pid 21042) 1 minutes, 1 start
    subsnmpd     run (pid 21266) 3 seconds, 1 start
