Topic

Microsoft Windows servers have the ability to detect denial-of-service (DoS) attacks against its file server program. Under high stress conditions where the ARX system receives a large amount of file system traffic, the server may interpret the traffic from the ARX system as a DoS attack. The server will disconnect the connection that the ARX system had establish with the filer.

When the server disconnects a connection, the ARX system will log an error message that appears similar to the following example:

2008-01-21T08:11:19.120+0000:SWITCHNAME:1-1-ACM-11017:VCIFS-1-4-CNXRECVERR:: [21o/SERVERIPADDRESS] receive error - Connection reset by peer [104].

When the Windows server disconnects a connection, the server will log an event in the System log that appears similar to the following example:

Event ID: 2025
Source: SRV
Description: "The server has detected an attempted Denial-Of-Service attack from client \\<computer_name>, and has disconnected the connection."

Workaround

You can use one of the following two methods to prevent Windows server from closing connections from the ARX system under heavy traffic conditions:

  • Increase the MaxMpxCt value for the Server Service. MaxMpxCt is the maximum number of concurrent outstanding network requests that are allowed.
  • Disable the server's DoS attack detection.
