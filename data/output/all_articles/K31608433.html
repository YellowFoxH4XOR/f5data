Description

Using a security policy, you would like to allow downloads of an exe only at a certain URL, while the exe filetype is also configured as a globally disallowed filetype.

Environment

  • Security policy
  • exe
  • Downloads

Cause

You don't want to add exe as an accepted filetype globally for the policy.

Recommended Actions

Add exe as a disallowed file type, and use an iRule to override the block when path is equal to the file you want to allow, and the illegal file type violation has occurred for a request.

Here is one example:

when ASM_REQUEST_DONE {
    if {[ASM::violation names] contains "VIOLATION_OBJ_TYPE" and [string tolower [HTTP::path]] equals "/downloads/abc.exe"} {
        ASM::unblock
    }
}

In this example, the unblocking action is called when the path in the requested URL is equal to /downloads/abc.exe, and the VIOLATION_OBJ_TYPE violation name (disallowed filetype) has been encountered when ASM finished processing the request at the ASM_REQUEST_DONE event.

Note: This is considered an example only, and may be modified to suit your exact requirements. For instance, you could simply unblock if the path contains /downloads/, or similar, or you can use a datagroup to specify multiple files to allow downloads for.

You need to enable iRule events in the security policy's settings, or the iRule won't do anything.

Another solution is to use an iRule or traffic policy, and select a different security policy if the HTTP::path is equal to /downloads/abc.exe. The main security policy will block exe as a file type, secondary security policy will allow it. This allows for more granularity but is more difficult to manage.
