K15201207: HTTP content is not returning back to client browser

Type
Support Solution
Published
2022-10-05
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 16.1.3, 16.1.2, 16.1.1, 16.1.X, 16.1.0
Source
https://my.f5.com/manage/s/article/K15201207

Description
Users trying to use an application, which is part of a virtual server, they authenticate and get access, however, at some point during their interaction, the pool member sends content back to the user, but somehow the HTTP content does not seem to be returned to the client browser.

Environment

  • LTM virtual server
  • TCP profile assigned
  • It is not possible to see the content in browser
  • TCP handshake is completed succesfully between client and VS

Cause
Multiple TCP Dup ACK in a capture

[TCP Dup ACK 201#3] 53992 → 443 [ACK] Seq=3890 Ack=82407 Win=131072 Len=0 TSval=3381465375 TSecr=4215065227 SLE=28327 SRE=29665
[TCP Dup ACK 201#4] 53992 → 443 [ACK] Seq=3890 Ack=82407 Win=131072 Len=0 TSval=3381465376 TSecr=4215065227 SLE=29665 SRE=31003
[TCP Dup ACK 201#5] 53992 → 443 [ACK] Seq=3890 Ack=82407 Win=131072 Len=0 TSval=3381465381 TSecr=4215065227 SLE=31003 SRE=32341

Recommended Actions

  1. Take a capture to analyze flow between client and virtual server
  2. Adjust the TCP profile to send and receive more than the default window settings of 65535
  3. To modify TCP profile:
    Local Traffic  ››  Profiles : Protocol : TCP  ››  Select the tcp profile  and adjust Receive Window option
