Topic

When a browser connects to a website, it sends a User-Agent string to the web server. User-Agent is an HTTP header field which contains a text string that identifies the browser. A few examples of common User-Agent strings are as follows:

Mozilla/5.0 (Windows; U; Windows NT 5.1; en-US; rv:1.8.0.12) Gecko/20070508 Firefox/1.5.0.12
Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1; SV1; .NET CLR 1.1.4322; .NET CLR 2.0.50727; InfoPath.1)
Mozilla/5.0 (Macintosh; U; PPC Mac OS X; en) AppleWebKit/412.6.2 (KHTML, like Gecko) Safari/412.2.2 (United States)

If JavaScript is enabled in your browser, you should be able to view the User-Agent string by entering the following text into the browser’s address bar:
 
javascript:alert(navigator.userAgent)
 
You can configure a pre-logon sequence which performs different actions based on the User-Agent string sent by the browser. The procedure below creates a pre-logon sequence that directs the client browser to the Logon Denied page if its User-Agent string is equal to Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.1;) or Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.2; NET CLR 1.1.4322):
 
  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Users : Endpoint Security : Pre-Logon Sequence page.
  3. In the Create new sequence field, enter a name for the pre-logon sequence.
  4. In the Based on menu, select template: Empty.
  5. Click the Create button.

    The new pre-logon sequence appears in the Select Sequence to Use section.
  1. Click edit next to the pre-logon sequence you just created.

    The Pre-Logon Sequence Editor opens.
  1. Mouse over the Go action.

    A plus sign (+) appears to the right of the Go action.
  1. Click the plus sign (+).

    The Change Sequence panel opens.
  1. In the Using menu, select New action.
  2. Click the Apply changes button.

    The Edit Action panel opens.
  1. In the Name field, enter a name for this action.

    For example:

    Check browser
  1. Click the Update details button.
  2. Click the Close Panel link at the upper right of the panel.
  3. Mouse over the fallback rule.

    A plus sign (+) appears to the left of the fallback rule.
  1. Click the plus sign (+).

    The Insert Rule Panel opens.
  1. Enter a name for the rule in the Name field.

    For example:

    Internet Explorer 7
  1. Enter a rule to detect the User-Agent string using syntax similar to the following example:

    session.browser.user_agent == "Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.1;)" OR session.browser.user_agent == "Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.2; NET CLR 1.1.4322)"

    Note: The User-Agent strings shown above are based on Internet Explorer 7 running on Windows XP Professional and Windows Server 2003 (respectively) and are only two of many possible variants. When configuring this rule, you must specify the exact User-Agent strings sent by your users’ browsers. You can view the User-Agent strings sent by users’ browsers in the User Agent column on the Reports: Logons page.
     
  1. Click the Insert Rule button.

    The rule is added to the pre-logon sequence. The pre-logon sequence now displays the new rule's name leading to the Logon Denied Page action, and a fallback branch leading to the Logon Allowed Page action.

    Note: Optionally, you may want to provide text on the Logon Denied page to indicate to users that they have been denied access due to the browser they're using. To do so, click the Logon Denied Page, enter the text that you want users to see, then click the Update button.
     
  1. Click the Back to console link at the upper right corner of the page.
  2. Click the option button next to the pre-logon sequence you just edited, under the Select Sequence to Use section.
  3. Click the Apply button.
 
Users whose browsers send the Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.1;) or Mozilla/4.0 (compatible; MSIE 7.0; Windows NT 5.2; NET CLR 1.1.4322) User-Agent string will now be directed to the Logon Denied page.
