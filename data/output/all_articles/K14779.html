Topic

This article applies to BIG-IP 11.3.x through 12.x. For information about other versions, refer to the following articles:

  • K74451051: Configuring SYN cookie protection (13.x - 15.x)
  • K7847: Overview of BIG-IP SYN cookie protection (9.x - 11.2.x)

The SYN cookie feature prevents the BIG-IP SYN queue from becoming full during a SYN flood attack. BIG-IP platforms equipped with the high speed bus (HSBe2) chip can perform both hardware and software SYN cookie protection, while other platforms perform software-only SYN cookie protection.

The following BIG-IP platforms are equipped with the HSBe2 chip, and you can configure them to perform hardware SYN cookie protection:

  • BIG-IP 5000 series (C109)
  • BIG-IP 7000 series (D110)
  • BIG-IP 10000 series (D113)
  • BIG-IP 12000 series (D111)
  • BIG-IP i5600, i5800 (C119)
  • BIG-IP i7600, i7800 (C118)
  • BIG-IP i10600, i10800 (C116)
  • VIPRION B4300 series blade (A108, A110)
  • VIPRION B2250 blade (A112)
  • VIPRION B2100/2150 blade (A109, A113)

BIG-IP platforms that do not contain the HSBe2 chip perform software-only SYN cookie protection, and do not have the Hardware SYN Cookie Protection option available in the protocol profile.

Note: You must enable autolasthop for hardware SYN cookie protection to function. For more information, refer to K16887: Autolasthop must be enabled for hardware SYN cookie protection to function.

Description

The BIG-IP SYN cookie feature protects the system against SYN flood attacks; the use of SYN cookies allows the BIG-IP system to maintain connections when the SYN queue begins to fill up during an attack. When the SYN Check Activation Threshold value is reached, the BIG-IP system responds to SYN requests by sending the SYN+ACK response back to the client that contains an encoded secret consisting of a 32-bit TCP sequence number containing encoded connection information. The system then discards the SYN queue entry and waits for the ACK from the client.

When the SYN Cookie authentication method is active for a virtual server or self IP address, established connection/packet handling and high availability (HA) features such as mirroring should perform as normal.

Note: In a Virtual Clustered Multiprocessing (vCMP) configuration, hardware SYN cookie functionality is still handled by the vCMP guest, rather than its host.

SYN cookie operation

When you enable SYN cookie protection for the protocol profile, the feature operates as follows:

  1. A client sends a TCP SYN request to the BIG-IP virtual server or self IP address.
  2. The receiving Traffic Management Microkernel (TMM) instance determines whether to enable hardware or software SYN cookie protection as follows:
    • If the platform contains the HSBe2 chip, and hardware SYN cookie protection is enabled in the profile, TMM notifies the High-Speed Bridge (HSB) chip and other TMM instances in the cluster to enable hardware SYN cookie protection. The HSB chip and receiving TMM instance then programs HSB hardware for hardware SYN cookie generation and validation for the virtual server or self IP address, and synchronize the status to all TMM instances in the cluster.
    • For TCP and FastHTTP profiles, if the platform does not contain the HSB chip or hardware SYN cookie protection is disabled in the profile, TMM notifies other TMM instances in the cluster to enable software SYN cookie protection.
    • For FastL4 profiles, if the platform does not contain the HSB chip or hardware SYN cookie protection is disabled, SYN cookie protection is not available for the virtual server unless the software SYN cookie protection option is specifically enabled.
  3. The BIG-IP system sends the SYN+ACK response back to the client but discards the SYN queue entry. The BIG-IP system does not maintain the SYN-RECEIVED state that is normally stored in the connection table for the initiated session. Because the system does not maintain the SYN-RECEIVED state for the connection, the SYN queue is not exhausted, and normal TCP communication continues.
  4. If the BIG-IP system then receives a subsequent ACK response from the client, the system reconstructs the SYN queue entry by decoding data in the TCP sequence number.
  5. After the BIG-IP system validates the client's ACK, the system adds the session to the connection table and initiates a connection to the pool member.

Collaborative hardware/software SYN cookie protection

In BIG-IP 11.3.0 and later versions, the SYN cookie feature uses collaborative hardware/software SYN cookie protection for platforms that contain the HSB chip. When the hardware SYN cookie feature is active, the system monitors relevant virtual servers, and determines when to enable SYN cookie protection. When SYN requests exceed the SYN Activation Threshold, the receiving TMM notifies the HSB chip and other TMM instances in the cluster to enable hardware SYN cookie protection.

Hardware SYN cookie protection database variables

The following database variables control whether the hardware SYN cookie feature is enabled/disabled globally and the conditions under which TMM initiates SYN flooding protection for the BIG-IP system.

Database variableDefinitionDefault settingRange
pvasyncookies.enabledDefines whether hardware syncookie protection is enabled/disabled globally.EnabledN/A
pvasyncookies.secretupdate.intervalDefines the hardware syncookie secret update interval in seconds.42 - 16
pvasyncookies.virtual.connthresholdhighDefines the per virtual server SYN cookie High Watermark: 2^(value) for any single TMM. If a virtual server's number of embryonic connection against the global setting, or the current syn cache usage against global syn cache threshold, is greater than this setting, the system enables SYN cookie protection. The measurement of this is therefore in percentage: SYN cookie High Watermark Percentage = (2^(value)/2^(max value) * 100

Example:

The default value for pvasyncookies.virtual.connthresholdhigh is 5.

SYN cookie High Watermark = (2^5/2^7) * 100 = 25%

Default SYN Check Activation Threshold = 16384 connections

SYN Check Activation Threshold * SYN cookie High Watermark Percentage = Number of connections greater than this value enables SYN cookie protection

16384 x .25 = 4096 

When the virtual server's embryonic connections are greater than 4096 for any single TMM, SYN cookie protection is enabled.

50 - 7

SYN cookie settings

SYN cookie protection is enabled by default for select protocol profiles, and you can configure the following settings:

  • SYN Check Activation Threshold: Indicates the number of new or untrusted TCP connections (those that have not yet completed the three-way TCP handshake) that can be established before the BIG-IP system activates the SYN Cookie authentication method for subsequent TCP connections. To configure the SYN Check Activation Threshold setting, go to System > Configuration > Local Traffic > General.
  • Profiles: The following protocol profiles support hardware and software SYN cookie protection:
    • TCP: Hardware SYN cookie protection is enabled by default in the TCP profile. If the platform does not support hardware SYN cookie protection, or hardware SYN cookie protection is disabled in the profile, the system uses software SYN cookie protection.
    • FastL4: Hardware SYN cookie protection is enabled by default in the FastL4 profile. The FastL4 profile also has an option for Software SYN Cookie Protection; software SYN cookie protection can be enabled in the FastL4 profile if you are using an nPath routing configuration and want to enable SYN cookie protection.
    • FastHTTP: Hardware SYN cookie protection is disabled in the FastHTTP profile, and the system uses software SYN cookie protection by default.

The BIG-IP system initiates the SYN cookie protection mechanism when the threshold value of SYN Check Activation Threshold setting is exceeded. The BIG-IP system activates the SYN cookie protection mechanism when the sum of all virtual servers’ SYN cookie threshold calculated values reaches the value of this global threshold even if each virtual server’s SYN cookie threshold value has yet to be reached. The value of this threshold is per TMM.

You can use the following procedure to view the default settings for SYN Check Activation Threshold:

Using the Configuration utility to view the SYN Check Activation Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Local Traffic > General.
  3. Under Properties, the SYN Check Activation Threshold displays the default value.

Using tmsh to view the SYN Check Activation Threshold

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the SYN Check Activation Threshold, use the following command syntax:

    list /ltm global-settings connection syncookies-threshold

    Output appears similar to the following example:

    ltm global-settings connection {
        syncookies-threshold 16384
    }

For example, a BIG-IP system with four available TMMs activates the SYN cookie protection mechanism when the number of existing embryonic connections (those that have not yet completed the three-way TCP handshake) exceeds the value of 65,536 (16384 x 4). This example assumes that these embryonic connections are evenly distributed among the available TMMs.

Virtual Server SYN Cookie Threshold

The virtual server SYN cookie threshold is a percentage of the global SYN cookie threshold and is calculated using the following formula:

SYN Check Activation Threshold setting (connection.syncookies.threshold) / 2 ^ (7 – pvasyncookies.virtual.connthresholdhigh)

Using the default values for these database variables, the result is 16384 / 2 ^ (7 – 5) = 4096.

Note: The value is hard-coded in BigDB.dat in /usr/shared/default/BigDB.dat and it is not equal to the result of the calculation.

Note: This value is per-TMM and the default value example assumes that the embryonic connections are evenly distributed among the available TMMs.

SYN Cache Threshold

The SYN cache threshold defines the maximum number of outstanding unanswered SYN a virtual server can hold per TMM before the SYN cookie protection mechanism is activated. You can use the following procedure to view the default settings for SYN Cache Threshold database key:

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the SYN Cache Threshold, use the following command:

    list /sys db pvasyncookies.virtual.maxsyncache default-value

  3. The system displays output similar to the following example:

    sys db pvasyncookies.virtual.maxsyncache {
        default-value "2999"
    }

Recommendations

To monitor the SYN cookie status for a virtual server, and determine whether the system has activated hardware or software SYN cookies, go to Local Traffic > Virtual Servers > virtual_server_name > Syncookie Status in the General Properties section. The possible values are listed in the following table.

SYN cookie statusDescription
OffThe SYN cookie feature is not currently active for the virtual server.
Full HardwareThe SYN cookie feature is currently active for the virtual server, and the system uses the HSB chip to process the SYN cookies.
Software SYN Cookie OnlyThe SYN cookie feature is currently active for the virtual server, and the system uses the software to process the SYN cookies.
