Known Issue

If you use the TMOS Shell (tmsh) list command with a wildcard character in the parent name, the system may return an incomplete list of nested objects.

This issue occurs when the following condition is met:

  • You use tmsh with a wildcard character in the configuration object name to list the nested configuration objects.

    For example, note the following commands:

    Note: In the following example, where you query the objects using a wildcard (*_vs), the value displayed for depends-on is incorrect.

    tmsh list gtm server *_vs virtual-servers vs1 

    gtm server example_vs {
        virtual-servers {
            vs1 {
                depends-on none
            }
        }

    Note: In the following example, where you query the objects using the full object name (example_vs), the value displayed for depends-on includes more detailed information.

    tmsh list /gtm server example_vs virtual-servers  vs1

    gtm server www.example.com {
        virtual-servers {
            vs1 {
                depends-on {
                    www.example.com:/Common/vs2     {
                        app-service none
                    }
                }
            }
        }
    }

Impact

The system may display nested configuration objects with incorrect values, or the displayed information may be missing some objects.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you list the nested configuration objects using the parent object name, the system displays all of the configuration objects.
  • When you use a wildcard to search parent objects, some of the nested configuration objects may be incorrect or missing.
