Description
FDB table is not added automatically in K8S environment with bigip-ctlr, while integrating with BIG-IP. 

Environment

  • BIGIP-ctlr version earlier to V 2.2.2
  • Using VXLAN node
  • Kubernetes Controller

Cause
Based on the debug log, it indicates a parsing error.
Flannel defines BIGIP's MAC address: 

[root@LTM2.example.com bigip]# kubectl describe node bigip
Name:               bigip
Roles:              <none>
Labels:             <none>
Annotations:        LTM.example.com/backend-data: {"VtepMAC": "01:00:5E:90:10:00"}          <<<<<<<<<<<<< MAC address
                    LTM.example.com/backend-type: vxlan
                    LTM.example.com/kube-subnet-manager: true
                    LTM.example.com/public-ip: 10.225.1.6

Debug log for BIGIP-CTLR:

2021/02/11 14:31:12 [DEBUG] [VxLAN] Vxlan manager (POC_VXLAN) wrote config section: [{VtepMAC 10.225.1.197}]
...
2021/02/11 14:31:28 [DEBUG] [2021-02-11 14:31:28,472 __main__ DEBUG] NET Config: {"userFdbTunnels": [{"name": "POC_VXLAN", "records": [{"name": "VtepMAC", "endpoint": "10.225.31.210"}]}]}

Note: The MAC address under debug log should display as shown in expected log, instead the MAC address is replaced with "VtepMAC"

Expected log: 

2021/02/17 02:12:36 [DEBUG] [VxLAN] Vxlan manager (vxlan_k8s_tunnel) wrote config section: [{01:00:5E:90:10:00 10.255.1.197} {01:00:5E:90:10:01 10.255.1.198} {01:00:5E:90:10:02 10.255.1.199}]
2021/02/17 02:12:51 [DEBUG] [2021-02-17 02:12:51,658 __main__ DEBUG] NET Config: {"userFdbTunnels": [{"name": "vxlan_k8s_tunnel", "records": [{"name": "01:00:5E:90:10:00", "endpoint": "10.255.1.197"}, {"name": "01:00:5E:90:10:00", "endpoint": "10.255.1.198"}, {"name": "01:00:5E

Recommended Actions

Upgrade Kubernetes controller k8s-bigip-ctlr version to later than 2.2.2
