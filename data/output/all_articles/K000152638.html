Description

BIG-IP device may log messages containing "Got exception while handling EM auth token request: Invalid Certificate".

  • Device may fail to ConfigSync for various module configurations or failover may not function.
  • Authentication error messages logged in /var/log/httpd/httpd_errors on the BIG-IP.
  • Error messages vary based on module and functionality failing.
  • Device will show "Device is not available" in the BIG-IQ and cannot be managed.

Error message on BIG-IP:

err httpd[<PID>]: [auth_f5_auth_token:error] [pid <num>] [client <IP and port>] Got exception while handling EM auth token request: Invalid Certificate: Could not open certificate file: "/shared/em/ssl.crt/<IP address>.crt": No such file or directory, referer: < URL >

Error messages on BIG-IQ:

[ERROR][24 Feb 2026 11:39:54 PST][/cm/shared/tasks/discover-config/fdeefa81-e638-48a7-979d-71d2f1da8099/worker SharedModuleDiscoveryTaskWorker] Error getting resource provisioning from /mgmt/tm/sys/provision on bigip2.com (10.1.1.1), Authorization failure - you may need to remove the device from BIG-IQ and add it again to reestablish trust: java.net.ProtocolException: status:401, body:<html...>

[INFO][24 Feb 2026 12:26:53 PST][/shared/identified-devices/config/device-refresh DeviceRefreshWorker] Device Refresh Failed (enable DEBUG logging for details): https://10.1.1.1:443/mgmt/shared/inflate 

Environment

  • REST authentication certificate file goes missing on the device reporting error message.
  • Device managed by BIG-IQ or device in a cluster for any module including APM, ASM, LTM etc.
  • BIG-IP any module.

Cause

REST authentication certificate goes missing on device reporting the error message.

Recommended Actions

  1. Identify which device is trying to authenticate:

    grep -r auth_f5_auth_token /var/log/httpd | awk '{print $11,$27}' | awk -F":" '{print $1,$2}' | awk '{print $1,$3}' | sort -n | uniq -c;echo -e "\r"

    Output will show the number of occurrences, the client trying to connect to the device, and the name of the certificate which in the case of BIG-IQ management will have a random IP address:

    <number> <client IP> "/shared/em/ssl.crt/<IP address>.crt"

  2. Log in to the device reporting the error messages.
  3. Change directories to /shared/em/ssl.crt:

    cd /shared/em/ssl.crt/

  4. Copy the missing certificates from one of the clients listed in the output from the grep command. If the device is being managed by a BIG-IQ, clients will include the BIG-IQ IP address: 

    scp root@<client IP>:/shared/em/ssl.crt/<IP address>.crt $PWD

  5. Repeat for any other certificates listed in the grep output.
