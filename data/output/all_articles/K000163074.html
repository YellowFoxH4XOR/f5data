Description

When TCP SYN and SYN/ACK packets arrive on different VLANs, resulting in incomplete connection tracking and preventing the security log profile from recording the request and response.

An HTTP response may appear in a packet capture without generating an event log when the corresponding HTTP request was not processed by the virtual server.

Environment

  • BIG-IP ASM
  • Passive monitoring mode
  • Security log profiles configured to log all request and response types, and the option guarantee-logging enabled
  • TCP SYN and SYN/ACK packets arrive on different VLANs

Cause

When VLAN-Keyed Connections is enabled, BIG-IP uses the ingress VLAN as part of connection matching. If the TCP SYN and SYN/ACK arrive on different VLANs, BIG-IP may not associate them with the same connection or virtual server.

Consequently:

  • The SYN/ACK may not complete connection processing through the expected virtual server.
  • The corresponding HTTP request may not be processed by ASM.
  • A subsequent HTTP response cannot be logged as part of the expected request/response event.
  • The issue is not caused by the HTTP/JSON content type.

Recommended Actions

  1. Capture the affected traffic and compare the VLANs on which the SYN and SYN/ACK packets arrive.
  2. Where possible, configure the switching or traffic-mirroring path so that both directions of the TCP connection use the same VLAN.
  3. If asymmetric VLAN traffic is required, configure BIG-IP to accept asymmetrically routed connections:
    • For a per-virtual-server configuration, use a custom FastL4 profile with Loose Close enabled. Loose Initiation may also be enabled when required by the traffic flow.
    • For a system-wide configuration, disable the connection.vlankeyed database key.
  4. Verify that the ASM security log profile remains attached to the affected virtual server and is configured to log the required request and response types.
  5. Generate new test traffic and verify that:
    • The SYN and SYN/ACK are associated with the same tracked connection.
    • The request reaches the expected virtual server.
    • ASM event logs are generated for the request and response.

Additional Information

  • Response logging depends on BIG-IP successfully tracking the associated request.
  • Seeing an HTTP response in a packet capture does not by itself confirm that the request/response pair was processed by ASM.
  • Using the same VLAN for both directions is preferred when the network design permits it.
  • Disabling VLAN-Keyed Connections restored event logging in the affected asymmetric traffic flow.
