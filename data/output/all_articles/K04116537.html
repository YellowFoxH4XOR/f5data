Description
When a Standard Virtual Server is configured with translate-address disabled and a pool is not assigned, the LTM will use the routing table to load balance requests.

  • The translate-address VS property prevents the LTM from translating the destination IP Address when the LTM forwards traffic to the destination server.

For example, the following Virtual Server does not have a pool applied and address-translation is disabled so it will refer to the TMM routing table to perform a load balancing decision.

ltm virtual example_vs {
    destination 192.168.0.1:443
    mask 255.255.255.255
    ip-protocol tcp
    profiles {
        tcp { }
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address disabled
    translate-port enabled
    vs-index 3
}

Additionally, if you want to perform SSL Offloading, you can apply a Client SSL Profile:
 

ltm virtual bartels_http_host {
    destination 192.168.10.70:pcsync-https
    mask 255.255.255.255
    ip-protocol tcp
    profiles {
        clientssl {
            context clientside
        }
        tcp { }
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address disabled
    translate-port enabled
    vs-index 3
}

Environment

  • VS with translate-address disabled
  • No pool assigned to VS

Cause

This behavior is by design.

Recommended Actions

  • The standard virtual server described in this article may result in an L3 routing loop depending on your network environment.

Additional Information

The following example illustrates a conditions where an L3 routing loop may occur:
  1. No pool/node/virtual being associated or defined in the virtual server, including in an iRule.
  2. translate-address disabled
  3. The listener is not 0.0.0.0/0 and it doesn't belong to any subnet of the Self IPs.
  4. Using a listener 192.168.1.1 as an example,
    • The BIG-IP system has a routing table that 192.168.1.1 can be routed to a gateway. (The virtual IP is not advertising itself to TMM)
    • The gateway has a routing table for 192.168.1.1 and the nexthop is the BIG-IP. (This normally happens when the BIG-IP is sitting on a one-arm network)
Also refer to K01260505: Recursive DNS cache listener/VS creates a loop as an example.
