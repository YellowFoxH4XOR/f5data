Description

After upgrading a BIG-IP VE to next versions some SelfIPs do not work. Because of this issue after upgrade of BIG-IP VE, some of the virtual IPs will be online and some virtual IPs will be offline.

  • BIG-IP 17.0.0 or above
  • BIG-IP 16.1.2.2 or above in 16.1.x
  • BIG-IP 15.1.5.1 or above in 15.1.x
  • BIG-IP 14.1.4.6 or above in 14.1.x
The device shows "incomplete/unknown" in the arp table: 
tmsh show /net arp

Name           Address        HWaddress          Vlan            Status
---------------------------------------------------------------------------------------
10.10.10.10    10.10.10.10    incomplete         /Common/vlan2   unknown
10.10.10.11    10.10.10.11    incomplete         /Common/vlan3   unknown

Environment

  • Upgrade BIG-IP VE
  • Interfaces
  • Self-IP

Cause

BIG-IP VE might not preserve the NIC ordering for five or more network interfaces on VMware.

Recommended Actions

The interface assignments can be swapped in the BIG-IP. For Example: 
Old version: 
net vlan /Common/vlan2 {
    interfaces {
        1.5 {
            app-service none
            tag-mode none
            untagged
        }
    }
}
net vlan /Common/vlan3 {
    interfaces {
        1.6 {
            app-service none
            tag-mode none
            untagged
        }
    }
}

New version: 
net vlan /Common/vlan2 {
    interfaces {
        1.6 {
            app-service none
            tag-mode none
            untagged
        }
    }
}
net vlan /Common/vlan3 {
    interfaces {
        1.5 {
            app-service none
            tag-mode none
            untagged
        }
    }
}

Additional Information

Beginning in the following BIG-IP versions in their respective software branches, BIG-IP Virtual Edition (VE) preserves the NIC ordering for five or more network interfaces, when you enable the vAPP option on VMware:

  • BIG-IP 17.x.x: 17.0.0
  • BIG-IP 16.1.x: 16.1.2.2
  • BIG-IP 15.1.x: 15.1.5.1
  • BIG-IP 14.1.x: 14.1.4.6
