K45294491: Bot or DoS profile stats not showing X-Forwarded-For IP as client IP

Description

A HTTP profile with the Accept XFF option enabled is applied to a virtual server with a DoS or Bot Defense profile.

The client IP addresses in the statistics do not reflect the actual client IPs contained in the value of the HTTP X-Forwarded-For header. Instead, the source IP of the device in front of the BIG-IP is shown.

For example, this anomaly may be seen at Security ›› Reporting : DoS : Dashboard.

Environment

  • HTTP profile
  • DoS profile
  • Bot Defense profile

Cause

Bug ID 924945

This issue occurs when attaching a HTTP profile with Accept XFF enabled after initially using a different HTTP profile with Accept XFF disabled. The original HTTP profile is not detached successfully.

Recommended Actions

Create a new virtual server and attach the correct profile to it. Or delete the existing virtual server and re-create it, attaching the correct profile. Furthermore, ensure that the correct HTTP profile is initially applied for any new virtual server.

Additional Information

Use the following command to quickly see the number of unique client IPs in the statistics:

show analytics dos-l7 report view-by client-ip range now-1w limit 100 drilldown { { entity virtual values { <virtual server> } } }
