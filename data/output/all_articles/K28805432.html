K28805432: BIG-IP DNS VE 15.1 DNS http monitor recv-status-code does not work when monitor uses HTTP/1.0 or HTTP/1.1

Applies to

  • BIG-IP
Source
https://my.f5.com/manage/s/article/K28805432

Description
DNS HTTP monitor recv-status-code does not work when HTTP version is specified.

For the following examples, gtm_minitor_http01 failes while gtm_minitor_http02 works fine for the same monitored object.

gtm monitor http /Common/gtm_minitor_http01 {
    defaults-from /Common/http
    interval 5
    password <password>
    probe-timeout 5
    recv COOKIE
    recv-status-code "302 200"
    send "GET /index.html HTTP/1.0\r\n"
    timeout 16
    username admin
}

gtm monitor http /Common/gtm_minitor_http02 {
    defaults-from /Common/http
    destination *:*
    interval 5
    probe-timeout 5
    recv none
    recv-status-code "302 200"
    send "GET /"
    timeout 16
    username admin
}

Environment

  • BIG-IP versions 15.1
  • BIG-IP DNS HTTP monitor is configured with both recv-status-code and send string

Cause

GTM HTTP(S) monitor "Status Code" feature broken when monitor uses HTTP/1.0 or HTTP/1.1

Recommended Actions

There is no workaround for this issue. The current version cannot configure both ecv-status-code and http version in send string at the same time
