Topic

If you install the IP geolocation database files incorrectly, the incorrect installation might change the SELinux security context for the database files.

Description

The BIG-IP system uses an IP geolocation database to determine the origin of an IP address. F5 releases the updates to the database in the GeoLocationUpdates container on the F5 Downloads site.

When installing or updating the IP geolocation database files, you should upload the IP geolocation ZIP archive file to the /shared/tmp directory on the BIG-IP system. When you extract the database files, the BIG-IP access control mechanism (SELinux) applies the appropriate security context to the database files, and the system installs the files to the /shared/GeoIP directory.

If you upload the IP geolocation ZIP archive file to a different directory on the BIG-IP system (for example, /root/) and then extract the database files, the SELinux module may apply the incorrect security context to the files. When this occurs, the system may fail to properly load the IP geolocation database.

Recommendations

Restoring the proper security context to the IP geolocation database files

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP 12.1.0 and later

  1. Log in to the BIG-IP command line.
  2. Verify that the tmm and gtmd processes have loaded the correct database files by comparing the inode numbers. To do so, type the following command:

    ls -i /shared/GeoIP/v2/F5GeoIPISP.dat ; lsof 2>/dev/null | grep F5GeoIP

    The following output indicates that the gtmd (1376259) and tmm (80575) inode numbers do not match for the F5GeoIPISP.dat database file. In this example, the tmm process has loaded the incorrect database file from /usr/share/GeoIP/F5GeoIPISP.dat.

    gtmd  5871   root  mem  REG  9,0  567630     3915778  /shared/GeoIP/v2/F5GeoIPv6.dat
    gtmd  5871   root  mem  REG  9,0  194864440  966658   /shared/GeoIP/v2/F5GeoIPOrg.dat
    gtmd  5871   root  mem  REG  9,0  373413     1376259  /shared/GeoIP/v2/F5GeoIPISP.dat
    tmm   10612  root  mem  REG  9,0  127452     966660   /shared/GeoIP/v2/F5GeoIPRegion2.dat
    tmm   10612  root  mem  REG  9,0  567630     3915778  /shared/GeoIP/v2/F5GeoIPv6.dat
    tmm   10612  root  mem  REG  9,0  94864440   966658   /shared/GeoIP/v2/F5GeoIPOrg.dat
    tmm   10612  root  mem  REG  9,4  3993525    80575    /usr/share/GeoIP/v2/F5GeoIPISP.dat

  3. To verify the security context of the database files in the /shared/GeoIP directory, type the following command:

    ls -Z /shared/GeoIP/v2/

    The following output indicates that the security context for the F5GeoIPISP.dat file is root:object_r:default_t, which is preventing the system from properly loading the IP geolocation database.

    lrwxrwxrwx  root root  root:object_r:shared_geoip_t F5GeoIP.dat  ->  /shared/GeoIP/v2/F5GeoIPRegion2.dat
    -rw-r--r--  root root  root:object_r:default_t F5GeoIPISP.dat
    -rw-r--r--  root root  system_u:object_r:shared_geoip_t F5GeoIPOrg.dat
    -rw-r--r--  root root  system_u:object_r:shared_geoip_t F5GeoIPRegion2.dat
    -rw-r--r--  root root  system_u:object_r:shared_geoip_t F5GeoIPv6.dat

  4. To restore the proper SELinux security context to the geolocation database files, type the following command:

    restorecon -Rv /shared/GeoIP/v2/ ; tmsh load sys geoip
