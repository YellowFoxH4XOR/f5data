K000158131: BIG-IP HTTP Compression profile does not work for certain payloads

Type
Support Solution
Published
2025-12-09
Updated
2025-12-09
Source
https://my.f5.com/manage/s/article/K000158131

Description

HTTP compression was not functioning as expected on a BIG-IP LTM virtual server.

If the length of the payload is too small, compression does not occur.

Environment

BIG-IP

Packet captures and web browser inspection confirms that compression was not applied.

Cause 

The HTTP Compression profile has a min-size parameter, which is set to 1024 bytes by default.

Compression is only applied to responses when the length of the payload exceeds the value of the min-size parameter; smaller responses are not compressed.

Recommendations 

If your packet does not exceed the current minimum content length, please consider reducing the min content length parameter to accommodate smaller packets if you need to compress smaller payloads (the default is 1024 bytes; consider reducing it to accommodate your use case).

Please note that compressing small payloads consumes CPU resources, the CPU overhead may outweigh the benefit obtained in this case.

Go to: Local Traffic > Profiles > Services > HTTP Compression > Choose your HTTP compression profile > Minimum Content Length
