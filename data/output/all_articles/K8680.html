Known Issue

This is the result of a known issue. When you configure a FirePass controller to perform group mapping to multiple Active Directory (AD) servers, and the first AD servers do not respond to the network connections, logins that require this group mapping will take up to two minutes per unreachable AD server.

The FirePass controller's group mapping methods (master group mapping and resource group mapping) can be configured to use up to three AD servers in order to ensure that FirePass logins can succeed in the event of a failure in one or more AD servers. The group mapping methods tab of the Users: Groups Dynamic Group Mapping page requires configuration of a primary AD server, and optionally a secondary and tertiary AD servers. If the primary server fails to respond to network connections, the FirePass controller attempts to query the secondary server; if the secondary fails to respond, the FirePass controller attempts to query the tertiary server.

Note: Failure is based on network connections failing, not a failure of authentication credentials or other failures within the AD protocols.

When a server fails to respond to a network connection attempt, the FirePass controller does not use the information that the server is unresponsive. The FirePass controller will continue to attempt connections to the unresponsive server or servers for group mapping with each login that requires group mapping and is not satisfied by a group mapping method of higher priority, as specified in the group mapping tables.

F5 Product Development tracked this issue as CR92934 and is fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Additionally, cumulative hotfix HF-602-3 has been issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
