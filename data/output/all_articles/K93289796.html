K93289796: APM customization is broken post v15 upgrade

Type
Support Solution
Published
2020-02-11
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.X.X, 15.0.X, 15.1.0, 15.0.1, 15.0.0, 15.1.8, 15.1.7, 15.1.6, 15.1.X, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.5
Source
https://my.f5.com/manage/s/article/K93289796

Description

After upgrading BIG-IP APM to version 15.x, in some rare circumstances, users see a page with raw session variables when logging out from their APM session. For instance, instead of seeing the "Your session is finished." message, users see "%[success_title]".
 















In the above example, this is what the user would normally see if the session variables get replaced with the correct respective values.

%[success_title] -----> Your session is finished.
%[success_message] -----> Logged out successfully.
%[new_session] -----> To open a new session, please
%[new_session_link] -----> click here.

Environment

  • BIG-IP APM with some form of advanced customization done.
  • Upgraded to v15.x

Cause

Starting from v15.0, internal customization files layout was refactored. During the upgrade, logout.inc file should be removed from its old location (/var/sam/www/client/customization-group/logout/Common/<AP_name>_logout/logout.inc), however in some cases, this does not happen.

Recommended Actions

To workaround the issue (in this example, we're assuming access policy name: AP_Authentication-1):

  1. move the existing logout.inc file to logout.inc.OLD with the following example.
     # mv /var/sam/www/client/customization-group/logout/Common/AP_Authentication-1_logout/logout.inc /var/sam/www/client/customization-group/logout/Common/AP_Authentication-1_logout/logout.inc.OLD
     
  2. clear ramcache
    NOTE: user-facing pages are cached by ramcache, so it's necessary to clear it after making some modification.

    # tmsh delete ltm profile ramcache all
