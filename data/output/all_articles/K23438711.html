Known Issue

The BIG-IP system may fail to provision the Trusted Platform Module (TPM) for use.

This issue occurs when all of the following conditions are met:

  • You have an existing BIG-IP system running on BIOS that did not have TPM provisioning support. This includes systems running on BIG-IP 11.x, 12.x, and 13.0.0 (including their respective point releases/hotfixes).
  • You upgraded this system to BIG-IP 14.1.0. BIG-IP 14.1.0 includes a new BIOS firmware with TPM provisioning support.
  • You are running one of the following BIG-IP platforms which has a Trusted Platform Module (TPM) that was manufactured using an earlier BIOS version:
    • i850, i2600, i2800, i4600, i4800
    • i5600, i5800, i7600, i7800, i10600, i10800
    • i12600, i12800, i15600, i15800
    • B4400 series blades

Impact

TPM is non-functional on the affected system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • While the system boots to BIG-IP 14.1.0, you observe an error message that appears similar to the following example:

     tpm-status[5380]: System Integrity Status: Invalid

  • If you run the local attestation or remote attestation on the affected system, the system integrity check status reports as invalid. For more information about running local or remote attestation, refer to K58311205: Overview of Local Attestation and Remote Attestation with TPM on the BIG-IP system.

Workaround

If you have not upgraded your BIG-IP system to BIG-IP 14.1.0, you must first perform an upgrade to BIG-IP 13.1.x before upgrading to BIG-IP 14.1.0. This should ensure that the TPM on your system is properly enabled and provisioned prior to the upgrade to BIG-IP 14.1.0.

If you have already upgraded your BIG-IP system to BIG-IP 14.1.0, the only way to recover the TPM into a functional state is to install the engineering hotfix.
