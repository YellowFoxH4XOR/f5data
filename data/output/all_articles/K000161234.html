Description

When routing client traffic to specific origin servers based on the client's IP address is required, F5 Distributed Cloud Services provides the ability to control traffic flows for use cases such as canary deployments or scenarios where resources in one location are more appropriate to process requests from specific clients.

  • How can client traffic be routed to a specific origin server based on the client's IP address in F5 Distributed Cloud?
  • What is the Origin Server Subset Rules feature and how does it work?
  • How are Known Labels configured and applied to origin servers for traffic steering?
  • How is Subset Load Balancing enabled on an Origin Pool?
  • How are Origin Server Subset Rules configured on an HTTP Load Balancer?

Environment

  • F5 Distributed Cloud (SaaS)
  • HTTP Load Balancer with Origin Server Subset Rules configured
  • Two or more origin servers located in different sites or Customer Edge (CE) locations
  • Customer Edge (CE) sites connected via IPsec tunnels (in this example: one on-premises KVM CE and one AWS VPC CE)
  • Origin Pool with Subset Load Balancing enabled
  • Known Labels configured in Shared Configuration for traffic routing key-value pairs
  • Use case: canary deployments or client IP-based geographic/network routing

Cause

None

Answer/Recommended Actions

Use the Origin Server Subset Rules feature on an F5 Distributed Cloud HTTP Load Balancer to match incoming client traffic based on source IPv4 address and route it to a specific subset of origin servers identified by labels. The following steps walk through the full configuration.

Solution Overview

Origin Server Subset Rules provide the ability to create match conditions for incoming traffic using country, ASN, F5 Regional Edge (RE), IP address, or client label selectors to determine which origin server subset handles the request. In this example:

  • Specific client IP addresses are routed to Origin Server 1 (Location 1 — application version 1, on-premises CE).
  • All other client IP addresses are routed to Origin Server 2 (Location 2 — application version 2, AWS CE).

Step 1: Create a Known Label

A Known Label is a key-value pair that can be attached to objects for referencing them using the label selector in subset rules.

  1. Navigate to Home → Shared Configuration → Manage → Labels → Known Keys.
  2. Click Add Known Key and configure the following:
    • Label Key: route-traffic
    • Label Values: Add two values — app-v1 and app-v2
  3. Click Add Key to save.
  4. To verify the labels were created, navigate to Manage → Labels → Known Labels.

Step 2: Add Labels to Origin Servers

  1. Navigate to Home → Multi-Cloud App Connect or Web App & API Protection → Manage → Load Balancers → Origin Pools.
  2. Identify the Origin Pool to configure. Click the three-dot menu (•••) on the right and select Manage Configuration.
  3. For each origin server, click the edit (pencil) icon and select Show Advanced Fields.
  4. Under Origin Server Labels, select the label key route-traffic and assign the appropriate value:
    • On-premises CE origin server: assign label route-traffic: app-v1
    • AWS CE origin server: assign label route-traffic: app-v2
  5. Click Apply to save each origin server configuration.

Step 3: Enable Subset Load Balancing on the Origin Pool

  1. Within the Origin Pool configuration, navigate to the Other Settings section.
  2. Click Configure next to Enable/Disable Subset Load Balancing.
  3. Select Enable Subset Load Balancing and click Configure.
  4. Under the Subset Classes section, click Add Item and add the label key created in Step 1: route-traffic.
  5. Save the Subset Load Balancing configuration.

Step 4: Configure Origin Server Subset Rules on the HTTP Load Balancer

  1. Navigate to the HTTP Load Balancer configuration associated with the Origin Pool.
  2. Locate the Origin Server Subset Rules section. Ensure Show Advanced Fields is enabled.
  3. Confirm the Origin Pool (app-op) is configured with weight and priority both set to 1.
  4. Click Add Item under Origin Server Subset Rules to add the first rule:
    • Provide a name and optional description for the rule.
    • Under Action, select the label key route-traffic and set the value to app-v1.
    • Under Match Condition, select Source IPv4 Match and enter the specific client IP address(es) that should be routed to Origin Server 1.
    • Repeat to add additional client IP addresses as needed, all mapped to app-v1.
  5. Click Add Item again to add the default rule for all other traffic:
    • Under Action, select the label key route-traffic and set the value to app-v2.
    • Configure the match condition to cover all other IP addresses (default/fallback rule).
  6. Save and apply the Load Balancer configuration.

Verification

  • Send test requests from the specific client IP addresses configured in the subset rules. Confirm requests are routed to the on-premises CE (f5xc-onprem-ce) hosting application version 1.
  • Send test requests from other IP addresses. Confirm requests are routed to the AWS CE (f5xc-aws-ce) hosting application version 2.
  • Navigate to the HTTP Load Balancer Performance Monitoring → Requests tab to verify the Origin Server column reflects the expected routing per client IP.

Additional Information

The Origin Server Subset Rules feature in F5 Distributed Cloud supports the following match criteria for determining which origin server subset handles a request:

  • Source IPv4 address (as demonstrated in this article)
  • Country
  • ASN (Autonomous System Number)
  • F5 Regional Edge (RE) location
  • Client label selectors

This feature is particularly useful for the following use cases:

  • Canary deployments: Route a specific subset of clients (by IP, ASN, or geography) to a new application version while the majority of traffic continues to the stable version.
  • Geographic or network-based routing: Route clients from specific networks or regions to the most appropriate origin for latency, compliance, or data residency reasons.
  • A/B testing: Direct specific client groups to different application versions for comparison testing.

The label key-value pairs assigned to origin servers in the Origin Pool act as selectors. When a request matches an Origin Server Subset Rule, F5 Distributed Cloud selects only the origin servers whose labels match the action defined in the matching rule. Rules are evaluated in order, and the first matching rule determines the origin server subset used for that request.
