Topic

This article discusses how CMP-enabled BIG-IP systems handle Address Resolution Protocol (ARP) traffic.

Description

Starting in BIG-IP 12.0.0, ARP traffic is handled across all Traffic Management Microkernel (TMM) instances based on a distributed hash algorithm, and the primary TMM (tmm0) no longer proxies all ARP traffic. Secondary TMMs, upon receiving a ARP reply, forward the reply to the primary TMM (tmm0) to be shared internally over the MPI channel to the other TMMs.

Note: For IPv6, the Neighbor Discovery Protocol (NDP) traffic continues to be pinned to primary TMM (tmm0) only.

For example, if you have configured 200 virtual addresses on a system running two TMMs (TMM0, TMM1), each TMM instance sends out 100 gratuitous ARPs for 100 virtual addresses.

Prior to BIG-IP 12.0.0, the primary TMM (tmm0) acts as a proxy for all ARP traffic. If the primary TMM is handling an outbound connection, and the ARP entry is not in the primary TMM's cache, the primary TMM sends ARP requests and propagates the reply to the ARP table of the secondary TMMs over the MPI channel. If a secondary TMM is handling an outbound connection, and the ARP entry is not in the secondary TMM's cache, the secondary TMM sends ARP requests over the MPI channel to the primary TMM which provides the answer from its cache if one exists, or issues a request over the network on behalf of the secondary TMM. The DAG directs all ARP replies back to the primary TMM for internal distribution to facilitate the proxy behavior of the primary TMM. The arp.retries system database variable has a default value of 6. If a secondary TMM makes an ARP request, the first request is sent to the primary TMM and then subsequent attempts are performed by the primary TMM over the network.

Note: The mpidump utility cannot capture messages over the MPI channel between TMMs. This utility is used for capturing messages on an MPI channel between a TMM and TMM plug-ins.

Impact

The BIG-IP system may send gratuitous ARP traffic at a higher rate after upgrading to BIG-IP 12.x since ARP requests are distributed across all TMMs.

Recommended Actions

If the upstream switch is unable to process ARP requests at the higher rate, you can adjust the BIG-IP system's gratuitous ARP behavior using the arp.gratuitousrate and arp.gratuitousburst database variables or keys. For more information, refer to K11985: Overview of the arp.gratuitousrate and arp.gratuitousburst database variables.
