Description

After upgrading, users might encounter errors when loading configurations in F5 APM. The errors are as follows:

err mcpd[7764]: 01b7005b:3: APM Network Access (/Common/Network_Access_Resource_Name) DNS name (192.168.0.1) is not a valid domain name

err tmsh[11259]: 01420006:3: Loading configuration process failed

This issue arises because the validation process in newer versions enforces that DNS names, not IP addresses, must be used in the DNS Address Space field.

Environment

  • APM
  • Network Access (VPN) configuration load
  • IPs used in NA DNS Address Space

Cause

The error occurs due to the presence of an IP address (192.168.0.1 in this example) in the DNS Address Space field of the Network Access resource configuration. The field "DNS Address Space" requires domain names rather than IP addresses.

Recommended Actions

  1. If you encountered to this status after booting new boot location, boot it back to original boot location. (when you encounter this issue while you are updating config, go to step 2)
  2. Navigate to Access ›› Connectivity / VPN : Network Access (VPN) : Network Access Lists ›› Network_Access_Resource_Name
  3. Open the Network Settings tab
  4. Locate the field DNS Address Space
  5. Replace the IP address(es) (e.g., 192.168.0.1) with the appropriate Fully Qualified Domain Name(s) (FQDN(s)) that correspond to the IP address, such as dns1.local or dns2.local, depending on your network configuration
  6. Test the connection using the FQDN
  7. Attempt to load the config again. But if you are booting from the other boot location, then you will need to set install configuration "Yes", and also select current boot location so that the new boot location can have the fixed config of current boot location.

Additional Information

  • Ensure that all Network Access resources are checked for similar issues, even if the error message only specifies one resource, as the configuration validation process stops at the first encountered error.
  • This validation change aims to enhance security and proper DNS resolution in network configurations.
  • Bug ID 1167985 (f5.com) is a second possible cause.
