Known Issue

This is the result of a known issue. The BIG-IP system’s management of Secure Sockets Layer (SSL) certificates and keys is not partitions aware. Therefore, all users, regardless of their administrative partition, share the same pool of SSL certificates and keys. As a result, SSL certificates and keys can be deleted even if they are currently used in a different administrative partition.

For example:

  • The admin user, while in the Common administrative partition, imports the example SSL certificate and key pair onto the BIG-IP system.
  • The admin user creates a new administrative partition named partition1.
  • The admin user creates a new user account named John, with a role of Manager and access to partition1 exclusively.
  • In partition1, John creates a new ClientSSL profile that uses the example SSL certificate and key pair.
  • Back in the Common administrative partition, the BIG-IP system incorrectly allows the admin user to delete the example SSL certificate and key pair, even though this is currently used by the ClientSSL profile created by user John in partition1.
  • The next time the configuration is loaded, the services are restarted or the configuration is synchronized to the peer system, the BIG-IP system returns an error message that appears similar to the following example:

    BIGpipe client SSL profile modification error:
    01070313:3: Error reading key PEM file /config/ssl/ssl.key/example.key for profile example_ssl: error:2006D080:BIO routines:BIO_new_file:no such file

F5 Product Development tracked this issue as ID 336538 and it was addressed in BIG-IP 11.0.0.

Workaround

Before deleting SSL certificates or keys, ensure that they are not being used in a different administrative partition.

If this issue has already occurred, you can either re-import the SSL certificates or keys that were deleted, or delete the orphan Client SSL/Server SSL profiles.
