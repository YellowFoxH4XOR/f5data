Description

F5 Distributed Cloud supports attaching multiple custom TLS certificates to a single HTTP or TCP Load Balancer. This allows organizations to host multiple domains with different certificates from a single Load Balancer, optimizing costs and simplifying configuration. TLS certificates can also be shared across multiple Load Balancers and managed centrally as standalone objects.

  • How can multiple custom TLS certificates be attached to a single HTTP Load Balancer in F5 Distributed Cloud?
  • How is a TLS certificate object created and managed in the F5 Distributed Cloud Console?
  • How is an intermediate certificate chain configured for a TLS certificate?
  • How can TLS certificates be shared across multiple Load Balancers?
  • How are TLS certificate expiration alerts configured and viewed?
  • Can multiple custom TLS certificates be configured on a TCP Load Balancer?

Environment

  • F5 Distributed Cloud (SaaS)
  • HTTP Load Balancer and/or TCP Load Balancer with custom TLS certificates (Bring Your Own Certificate)
  • Load Balancer advertised on Regional Edges (RE) or Customer Edge (CE)
  • TLS certificates in PEM or PKCS#12 (P12) format
  • Optional: Intermediate certificate chain configured as a standalone object
  • Optional: OCSP Stapling configured on TLS certificate objects

Cause

None

Answer/Recommended Actions

Step 1: Create a TLS Certificate Object in the F5 Distributed Cloud Console

  1. From the F5 Distributed Cloud Console home page, navigate to Shared Configuration.
  2. In the left menu, select Certificate Management → TLS Certificates.
  3. Click Add TLS Certificate.
  4. Configure the certificate properties:
    • Provide a Name for the certificate object.
    • Under Certificate, click Import from File to upload the certificate file.
    • Provide the corresponding Private Key (BlindFold encrypted).
    • Supported certificate formats: PEM and PKCS#12 (P12).
  5. Optionally, configure OCSP Stapling:
    • OCSP (Online Certificate Status Protocol) is used to determine the revocation status of digital certificates. For configuration details, refer to the OCSP Stapling documentation.
  6. Optionally, configure an Intermediate Certificate Chain:
    • Select or reference a pre-configured intermediate certificate chain object.
    • The certificate chain of trust consists of: Root Certificate (self-signed, issued by Root CA) → Intermediate Certificate (signed by Root CA, signs server certificates on behalf of Root CA) → Leaf/Server Certificate (signed by Root CA or Intermediate CA, used to establish the secure connection).
  7. Click Save and Exit.

Note: Certificate Management can be accessed from any of the following services: Multi-Cloud App Connect, Web App & API Protection, Distributed Apps, or Shared Configuration.

Step 2: Attach Multiple TLS Certificates to an HTTP Load Balancer

  1. Navigate to Multi-Cloud App Connect or Web App & API Protection → Manage → Load Balancers → HTTP Load Balancers.
  2. Create a new HTTP Load Balancer or edit an existing one.
  3. In the Load Balancer configuration, navigate to the TLS section and select Custom Certificate (Bring Your Own Certificate).
  4. Add the first TLS certificate object created in Step 1.
  5. Click Add Item to attach additional TLS certificate objects for other domains hosted on the same Load Balancer.
  6. Configure routes using host header matching to direct traffic for each domain to the appropriate origin pool. Example route configuration:
    • Route Type: Simple Route
    • HTTP Method: ANY
    • Path Match: Prefix /
    • Headers: host — Exact match — domain1.example.com
    • Origin Pool: origin-pool-domain1
  7. Under Other Settings, configure VIP Advertisement as needed (Internet or CE-specific).
  8. Click Save and Exit.

Note: When multiple certificates are attached to a Load Balancer, the Load Balancer's certificate expiration date is automatically set to the expiry date of the certificate expiring earliest among all attached certificates.

Step 3: Verify TLS Certificate Configuration

  1. Open a browser and navigate to the Load Balancer domain(s). Confirm the connection is shown as secure.
  2. Click the padlock icon in the browser address bar and inspect the certificate to confirm the correct certificate is being served for each domain.
  3. In the F5 Distributed Cloud Console, navigate to Multi-Cloud App Connect → Manage → Load Balancers and confirm the Certificate Status shows Valid and the correct certificate expiration date is displayed.

Configuring TLS Certificates on a TCP Load Balancer

Multiple custom TLS certificates can also be configured on TCP Load Balancers using the same process described above. For detailed TCP Load Balancer configuration steps, refer to the F5 Distributed Cloud TCP Load Balancer documentation.

TLS Certificate Expiration Alerts

F5 Distributed Cloud generates alerts when a TLS certificate's expiration date approaches. To view active certificate expiration alerts:

  • Navigate to Notifications → Alerts from the left sidebar menu, or
  • Click the bell icon in the top right corner of the F5 Distributed Cloud Console.

Additional Information

The ability to attach multiple custom TLS certificates to a single HTTP or TCP Load Balancer enables the following operational benefits:

  • Cost optimization: Host multiple domains with different certificates from a single Load Balancer rather than requiring separate Load Balancers per domain.
  • Simplified configuration: Manage all domain certificates for a service from a single Load Balancer object.
  • Centralized certificate management: TLS certificate objects are standalone, reusable objects that can be shared across multiple Load Balancers. View and manage all certificates and intermediate certificate chains from a centralized location in Shared Configuration.

The three components of a certificate chain of trust are:

  • Root Certificate: Belongs to the Root CA and is self-signed.
  • Intermediate Certificate: Belongs to an Intermediate CA, signed by the Root CA. The Intermediate CA signs certificates on behalf of the Root CA. There can be one or more Intermediate CAs in a chain.
  • Leaf/Server Certificate: Belongs to the web server and is used to establish the secure connection or authenticate clients. Can be signed by either a Root CA or an Intermediate CA.

This feature is supported for HTTP and TCP Load Balancers advertised on both Regional Edges (REs) and Customer Edges (CEs).
