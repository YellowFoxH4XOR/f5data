Description

When viewing log files on iHealth some log files may appear with "_truncated" appended to their name as so:

Environment

  • Qkview without specifying size option
  • iHealth logs

Cause

This is expected behavior:  the default file size limit for a file in a qkview is a bit over 5 MB.

Recommended Actions

There are three ways to get around this problem.  

 

  • In the web interface, when you crate the qkview, look for the "Unlimited Snaplen" check box when you are on the creation screen, and select that. 
  • Similarly, on the command line, run qkview -s0 for the same results.

As another option, you may use tar to pack up the logs for us.  Run this in the advanced shell:  tar -zcvf /shared/tmp/<filename>.tgz /var/log/*

  • The filename is, of course, up to you
  • You can run this in tmsh, but certain bits will be lost.  Read on. 
  • When uploading to F5, use the following: tar -zcvf /shared/tmp/<case number>-$HOSTNAME-<informative info>.tgz /var/log/* 
    • Do not include the <Angle Brackets> when adding data
    • The $HOSTNAME variable will insert the device's hostname into the filename, and is useful to track which log archive is from which device.  You must be in bash (aka Advanced Shell) for this to work; in tmsh, it will show up literally in the filename as "$HOSTNAME".

Additional Information

  • As a general rule, logs will wind up so large if there is more data than necessary being logged; for example, a heavily used iRule that uses log local0. any time the iRule is triggered will send anything so logged to /var/log/ltm.  Also consider monitor logging (/var/log/monitors/*) and APM debug logging for these purposes.  
  • The top limit for -s0 in qkview is about 100 MB; if your log files are larger than about 100 MB, then you'll need to use the 'tar' method to get the logs to us without truncation.
