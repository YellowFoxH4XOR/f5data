Known Issue

Description

A case difference between an ARX export path and the path of the subshare on the filer will cause the ARX subshare subsystem to fail when the export is added to a virtual service. The failure causes the ARX to reboot until the case matches.

This issue occurs when all of the following conditions are met:

  • There is a case difference between the ARX export definition and the path on the filer
  • The ARX managed volume with the export definition has filer-subshares enabled

For example, this issue will occur if you add an export with a path of users\user1, when the actual path on the filer is users\USER1.

Impact

The ARX system services will be unavailable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX subshare daemon cores.
  • Syslog contains an error message that appears similar to the following example:

    SUBSHRMGT-0-DBG-MSG7::layer.cc:586:select_master - No master subshare because share UserShare relpath users\adir\user1 does not match definitive relpath users\adir\USER1

  • The ARX system continuously reboots until the case difference has been corrected or until the system reaches the three-reboot bounce limit.
  • This issue affects both ARX systems in a redundant pair.

Workaround

You can prevent or recover from this issue by performing the appropriate procedure:

Preventing this issue

To prevent this issue and allow the ARX export to be safely added, you can rename the path on the filer to match the case of the export path that you are configuring on the ARX.

Important: Clients may be affected by the case change and may be required to reconnect to the affected subshare.

Recovering from this issue

If your ARX system has encountered this issue after attempting to add an ARX export, you must rename the subshare path on the filer as described in the Preventing this issue section. Additionally, you must reload the ARX system using the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Reload the ARX system by typing the following command:

    reload

Supplemental Information

For information about the reload command, refer to the ARX CLI Reference Guide.
