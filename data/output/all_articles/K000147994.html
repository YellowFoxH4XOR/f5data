Description

On occasions, issuance of a TLS certificate may fail or look stuck, like in the pictures below:

Common status: 

  • Auto Cert State: AutoCertRateLimited
  • Auto Cert State: DnsDomainVerification

Environment

  • F5® Distributed Cloud (XC)
  • HTTP Load Balancer
  • Auto Cert
  • Letsencrypt 

Answer/Recommended Actions

Here is a list of things to check in such a case. Checks:

  1. Are there CAA records on the zone and NS? Do they match Letsencrypt CA? If there is any CAA record created for root domain, then you must either add additional record to include letsencrypt.org, or remove every existing CAA record. 
    1. $ dig NS <root-domain>
      $ dig SOA <root-domain>
      $ dig CAA <domain>
  2. Enter the domain name https://letsdebug.net/ . Any error? 
    • Using DNS01 - https://letsdebug.net/
    • Certificate Search - https://crt.sh/
    • Let's Debug Toolkit - cert-search  - https://tools.letsdebug.net/cert-search
    • DNS Viz - https://dnsviz.net/

In case of delegated domains, do the following:

  • Verify in Console that domain object is in publish state and F5 Distributed Cloud NS servers are listed for the domain.

  • Verify NS record created for the delegated domain in the root domain registrar. The NS record should point to F5 Distributed Cloud NS servers. Verify using the following command:

$ dig NS <delegated-domain>

Output of above command should return F5 Distributed Cloud DNS servers.

 

Verify non-delegated domains.

Verify that ACME challenge CNAME records are created in the domain registrar for all domains, and they point to the values provided by F5 Distributed Cloud Services.

Use the following command to verify:

$ dig CNAME _acme-challenge.<non-delegated-domain>

Output for the above command should return CNAMEs that match Load Balancer DNS records.
