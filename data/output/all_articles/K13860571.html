Description

Various logging information is sent by BIG-IP ASM to /var/log/asm. This information can be sent to a remote syslog server using the built in syslog-ng server. If you want to filter the /var/log/asm log messages that the system sent to remote syslog servers, you must first remove the remote-servers statement and then configure a syslog include statement that defines a filter rule and the remote server. For more information, refer to K13333: Filtering log messages sent to remote syslog servers (11.x - 15.x).

Environment

  • BIG-IP ASM

Cause

Information sent by BIG-IP ASM to /var/log/asm uses facility local3. For more information about facility, refer to K15934495: Configuring the level of information that syslog-ng sends to log files (12.x - 16.x).
local3 is not a preconfigured facility in K13333 so sending the logs remotely requires additional configuration using the "include" statement using technique in K13333.

Recommended Actions

  1. Review the table below to determine the severity values you would like to log for /var/log/asm. See K13333 for additional details.
    Note the IP/Port/Protocol that will be used for the destination remote syslog server in step 2 below.

    Level

    Description

    Verbosity

    emerg

    Emergency system panic messages

    Minimum

    alert

    Serious errors that require administrator intervention

    Low

    crit

    Critical errors, including hardware and filesystem failures

    Low

    err

    Non-critical, but possibly very important, error messages

    Low

    warning

    Warning messages that should at least be logged for review

    Medium

    notice

    Messages that contain useful information, but may be ignored

    Medium

    info

    Messages that contain useful information, but may be ignored

    High

    debug

    Messages that are only necessary for troubleshooting

    Maximum

 

  1. Change "level(warning..emerg)" in the include statement below to match the severity determined in step 1 above.
    Change the line beneath "destination d_remote_loghost" in the include statement below to include your remote server IP/Port/Protocol.
modify /sys syslog {
    auth-priv-from notice
    auth-priv-to emerg
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include none.          <<<< replace this with include lines below
    iso-date disabled
    kern-from notice
    kern-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers none
    user-log-from notice
    user-log-to emerg
}


2.1 Substitute in the following for the "include" statement above:  

  include "
    filter f_remote_loghost {
        level(warning..emerg) and facility(local3);
    };
    destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
    };
    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
    };
    "


The command to achieve the desired result should look like this:

modify /sys syslog include "filter f_remote_loghost { level(warning..emerg) and facility(local3);}; destination d_remote_loghost {udp(\"IP_RemoteServer\" port(#));}; log { source(s_syslog_pipe); filter(f_remote_loghost); destination(d_remote_loghost);};"

Note: Please set your IP Address in the IP_RemoteServer and the port instead #.

2.2 After applying the previous command and running the list /sys syslog all-properties command should look like this:

# list sys syslog all-properties 
                                                                                                  
sys syslog {
    auth-priv-from notice
    auth-priv-to emerg
    clustered-host-slot enabled
    clustered-message-slot disabled
    console-log enabled
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include "filter f_remote_loghost { level(warning..emerg) and facility(local3);}; destination d_remote_loghost {udp(\"IP_RemoteServer\" port(#));}; log { source(s_syslog_pipe); filter(f_remote_loghost); destination(d_remote_loghost);};"
    iso-date disabled
    kern-from debug
    kern-to emerg
    local6-from notice
    local6-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers none
    user-log-from notice
    user-log-to emerg
}

           2.3 At the end, don't forget to save all the changes.

save /sys config

  1. Use the following commands to test remote logging by collecting tcpdump and running logger to trigger syslog messages.

    Remote syslog via the management interface:

    tcpdump -i eth0 host 10.11.16.252 and port 514

    Remote syslog via TMM interfaces:

    Note: This does not capture traffic on the management interface.

    tcpdump -nni0.0:nnn host 10.11.16.252 and port 514 
    Then run,
    logger -p local3.warning "hello world...sample message"  

    The logger message should be written in both /var/log/asm and sent over network as shown by the tcpdump
