Description

  • When attempting to use the vconsole utility from the vCMP Host to a vCMP Guest the connection closes immediately after establishing.
  • Example failed vconsole connection: 
    [root@BIG-IP-Viprion:/S1-green-P::Active:Standalone] config # vconsole <guest name> <slot #>
Trying 127.3.0.1...
Connected to 127.3.0.1.
Escape character is '^]'.
Connection closed by foreign host.

Environment

  • BIG-IP Viprion / vCMP Host and vCMP Guest
  • vconsole utility

Cause

The vconsole utility uses the telnet protocol to connect to vCMP guests.
If a previous vconsole session is not properly closed, the telnet process can stay alive on either the vCMP host and/or vCMP guest.  
This existing telnet process can cause the inability to connect to some or all vCMP guests using vconsole.

Recommended Actions

If you are unable to use the vconsole utility to connect to some or all of your guests, please follow the below recommended plan of action to restore connectivity.

  1. On the vCMP Host / vCMP Guest, check for long lived telnet connections from the bash Command Line using the below command. 
    # ps -A | grep "/usr/bin/telnet"
  2. If the output of the above command is similar to below you will need to kill that process holding onto the old telnet connection. 
    12345 pts/9 S+ 0:00 /usr/bin/telnet 127.3.0.1 22000 <------- 
28735 pts/10 S+ 0:00 grep /usr/bin/telnet
  3. You can kill the existing connection with the following command.
    **For the example above the PID of the telnet process is 12345.  We can use the kill command to get rid of it. 
    # kill 12345

Once this is complete, you should have access to the other vCMP guests using the vconsole utility.
