Known Issue

This is the result of a known issue. When multiple ARX managed volumes use the same share for metadata, the ARX system will incorrectly identify this as an issue and log error messages to the syslog file that appear similar to the following example:

SSRM-0-ERR-SSRM_TOO_MANY_VSRECS:: Share meta-only:<IP addr>:<volume> has multiple VolStorage records

The show documentation SSRM_TOO_MANY_VSRECS command displays the following explanation for the error:

SSRM_TOO_MANY_VSRECS documentation:

Two or more VolStorage records in the Object Manager database both map to the same <namespace_id, volume_id, share_id> triple that should uniquely identify a share. This is an internal software error and should be reported to customer service.

Using the same share for multiple managed volumes is not allowed; however, it is supported for a metadata share.

F5 Product Development tracked this issue as ID 39386 and iot was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX Release Notes.

Additionally, this issue has been fixed in ARX versions 5.0.6 HF12 (build 11780) and 5.1.5 HF7 (build 11982). Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 39386.
