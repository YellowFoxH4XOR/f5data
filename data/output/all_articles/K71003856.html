Known Issue

Console access on certain BIG-IP platforms may appear unresponsive in the Maintenance Operating System (MOS).

This issue occurs when all of the following conditions are met:

  • You are running on a BIG-IP 2000 series (C112) or BIG-IP 4000 series (C113) system.
  • You have installed the MOS from the affected version.
  • You have configured the boot loader to boot to the Traffic Management Operating System (TMOS) maintenance, which may occur after you use the mosreboot command.

The BIG-IP system uses the MOS for maintenance purposes. For example, if the BIG-IP system no longer boots from the normal boot locations, you can use the MOS to retrieve important files before proceeding to re-image the system. For more information, refer to K14245: Overview of the recovery tasks performed from the MOS (11.x - 14.x).

Impact

You cannot access the MOS to perform maintenance tasks.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you boot into the MOS, you notice some error messages in the console output that appear similar to the following example:

    ACPI Error: No installed handler for fixed event [00000000] (20090903/evevent-306)
    ACPI Error: No installed handler for fixed event [00000003] (20090903/evevent-306)
    ACPI Error: No installed handler for fixed event [00000004] (20090903/evevent-306)
    ACPI Error: No handler or method for GPE[ 0], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ 1], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ 2], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ 5], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ 6], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ 8], disabling event (20090903/evgpe-706)
    ACPI Error: No handler or method for GPE[ A], disabling event (20090903/

  • The console output freezes after a short period of time.

Workaround

There is no workaround for this issue. However, you can attempt to recover from this issue by power cycling the system to boot into an existing slot. Additionally, you can prevent this issue from occurring by performing a temporary installation of BIG-IP 12.0.0 on a new software slot and delete the software slot once the installation completes. The software installation will upgrade the MOS to a version that resolves this issue. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To install BIG-IP 12.0.0 to a new software slot, use the following command syntax:

    install sys software image BIGIP-12.0.0.0.0.606.iso create-volume volume <software_slot>

  3. To delete the software slot, use the following command syntax:

    delete sys software volume <software_slot>
