K000161962: BIG-IP HA Pair Enters Active-Active State Due to Devices Not Being Added to the Sync-Failover Device Group

Type
Support Solution
Published
2026-06-29
Updated
2026-06-29
Source
https://my.f5.com/manage/s/article/K000161962

Description

Two BIG-IP LTM devices enter an unexpected Active-Active state, resulting in loss of high availability failover functionality. Both devices announce themselves as Active and standalone. The following log message is observed on the device that was previously in Standby:

010c006d:5: Leaving Offline for Active for dbvar not redundant.


This message indicates that the device does not detect a redundant failover peer and therefore transitions itself to Active as a standalone unit. The result is a split-brain condition where both devices are simultaneously Active, each processing traffic independently with no failover coordination between them.

Environment

  • BIG-IP LTM
  • Two device groups configured on the system
  • One device group of type sync-only, with both devices added and network-failover disabled
  • One device group of type sync-failover, with no devices added
  • Network failover not enabled on either device
  • Device trust broken or not properly established

Cause

The root cause is a device group misconfiguration. Both devices are added only to a sync-only device group, which does not support failover. The sync-failover device group, which is required for Active-Standby failover to function, has no devices added to it.

When a BIG-IP device is not a member of any sync-failover device group, the sod daemon cannot detect a redundant failover peer. When the device is released from an offline state or comes online, sod evaluates whether a redundant peer exists. Finding none, it logs the message shown above and transitions the device to Active as a standalone unit. This happens independently on both devices, resulting in both becoming Active simultaneously.

The underlying configuration that produces this behavior is as follows.

A sync-only device group containing both devices but not supporting failover:

cm device-group /Common/device_trust_group {
    auto-sync enabled
    devices {
        /Common/<device-1-hostname> { }
        /Common/<device-2-hostname> { }
    }
    hidden true
    network-failover disabled
}
A sync-failover device group that supports failover but has no devices added to it:

cm device-group /Common/<sync-failover-group-name> {
    auto-sync enabled
    type sync-failover
}
Because no devices are members of the sync-failover group, failover negotiation between the two devices is never possible. Only configuration synchronization is active. When either device is taken offline and released, or when it comes online and finds no peer in a sync-failover group, it declares itself Active as a standalone unit.

Answer/Recommended Actions

To restore proper Active-Standby failover functionality, perform the following steps.

Step 1. Add both devices to the sync-failover device group. Both devices must be members of the same sync-failover group for failover to function.

tmsh modify cm device-group /Common/<sync-failover-group-name> devices add { /Common/<device-1-hostname> /Common/<device-2-hostname> }

Step 2. Enable network failover on the sync-failover device group. Network failover allows the devices to monitor each other over the network and trigger failover when a peer becomes unreachable.

tmsh modify cm device-group /Common/<sync-failover-group-name> network-failover enabled

Step 3. Configure the ConfigSync IP address on each device. This is the self-IP address used for configuration synchronization between the devices.

tmsh modify cm device /Common/<device-hostname> configsync-ip <self-ip-address>

Step 4. Configure the unicast failover addresses on each device. These are the addresses used for failover heartbeat communication.

tmsh modify cm device /Common/<device-hostname> unicast-address {{ ip <self-ip-address> port 1026 }}

Step 5. Save the configuration on both devices.

tmsh save sys config

Step 6. Perform an initial configuration synchronization from the device with the correct configuration to the peer.

tmsh run cm config-sync to-group /Common/<sync-failover-group-name>


Step 7. Verify that both devices are now in the sync-failover group and that one device shows Active and the other shows Standby.

tmsh show cm sync-status
tmsh show cm failover-status
