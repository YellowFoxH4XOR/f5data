Description

A newly created HTTPS monitor marks the pool member down
  • Checking the pool member using openssl, the following error may be displayed :
    ssl.crt # openssl s_client -connect <ip_addr_of_pool_member> :
    47568901767688:error:14094412:SSL routines:SSL3_READ_BYTES:sslv3 alert bad certificate:s3_pkt.c:1272:SSL alert number 42
    47568901767688:error:140790E5:SSL routines:SSL23_WRITE:ssl handshake failure:s23_lib.c:177:

Environment

  • BIG-IP LTM
  • Newly created HTTPS monitor
  • 2-way authentication configured on pool-member

Cause

SSL handshake fails because the HTTPS monitor does not provide the certificate that the pool member requires for 2-way authentication.
 
Recommended Actions
Create a new SSL profile to offer a certificate allowed by a pool member and then assign the new SSL profile to the HTTPS monitor :

Creating SSL profile
  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Server
  3. Click Create
  4. Fill all required fields
  5. Select the appropriate certificate + key ( eventually chain )
  6. Click finished
Assign newly created SSL profile to the HTTPS monitor
  1. Log in to the Configuration utility
  2. Go to Local Traffic > Monitors
  3. Click on the name of your HTTPS monitor
  4. Select Advanced from the Configuration list
  5. From the SSL Profile list, select the previously created SSL profile
  6. Click update

Additional Information

Receiving alert bad certificate (code 42) means the server demands you authenticate with a certificate, and you did not do so, and that caused the handshake failure. A few lines before the line SSL handshake has read ... and written ... you should see a line Acceptable client certificate CA names usually followed by several lines identifying CAs, possibly followed by a line beginning Client Certificate Types and maybe some about Requested Signature Algorithms depending on your OpenSSL version and the negotiated protocol.
