Known Issue

The gtmd process stops running when the server certificate file (/config/gtm/server.crt) is corrupted.

Impact

The BIG-IP GTM system may fail to respond to DNS requests.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP GTM system may fail to respond to DNS requests
  • The bigstart status gtmd command reports that the gtmd process stops running.

    For example:

    gtmd down 9 seconds, normally up
  • The BIG-IP GTM system logs an error message to the /var/log/gtm file. The error message appears similar to the following example:

    011ae0f1:2: iqmgmt_SSL_init failure, stopping gtmd: failure to verify certificates in file /config/gtm/server.crt

    Note: In the fixed versions, the BIG-IP GTM system continues to log this error message, although the gtmd process is running and responding to DNS queries.

Workaround

To work around this issue, you can rebuild the server certificate file on the affected BIG-IP GTM system and start the gtmd process. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the command line on an affected BIG-IP GTM system.
  2. Recreate the /config/gtm/server.crt file by typing the following command:

    >/config/gtm/server.crt
  3. Start the gtmd process by typing the following command:

    bigstart start gtmd
  4. Ensure the /config/gtm/server.crt file is populated with its own device certificate by comparing it with the /config/httpd/conf/ssl.crt/server.crt file. You can view the details in each file by typing the following commands:

    openssl x509 -in /config/gtm/server.crt -text -noout
    openssl x509 -in /config/httpd/conf/ssl.crt/server.crt -text -noout
  5. Repeat steps 1 through 4 on the remaining affected members, if any.
  6. Re-add the device certificate file of the members in the BIG-IP GTM synchronization group by typing the following command for each member:

    bigip_add <IP address of remaining members>
  7. Repeat step 6 on the remaining affected members, if any.
