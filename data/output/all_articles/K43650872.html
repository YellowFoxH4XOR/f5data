Known Issue

TMM may restart and produce a core file when parsing a malformed packet on a loopback interface.

This issue occurs when all of the following conditions are met:

  • You run the sniff_commit_id_update command on the loopback interface.

    For example:

    # /usr/bin/python /usr/local/bin/sniff_commit_id_update -i loopback
  • You receive a malformed packet on the loopback interface.

Impact

The BIG-IP system may temporarily fail to process traffic while the TMM process restarts, and the system fails over if it is configured for high-availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system sends a SIGSEGV to the TMM process, and you may observe a message similar to the following example in the Traffic Management Shell (tmsh):

    Segmentation fault (core dumped)
  • The TMM process restarts and produces a core file in the /shared/core directory.
