Description

In some cases you want BIG-IP to distribute and load balance incoming packets across a large number of TMMs (cores), while we have different types of DAG modes that you can choose from, the RRDAG (Round Robin DAG) is the preferred method when you have UDP packets with low entropy and the packets might be arriving from the same set of ports and/or IP addresses. 

Environment

  • BIG-IP.
  • RR-DAG supported hardware.

Cause

  • Entropy traffic is ending up on limited set of TMMs and not distributing traffic evenly across the available TMMs
  • Performance slowness for certain flows or VIPs.

Recommended Actions

In such scenarios with limited or low entropy it is best to configure RRDAG to distribute incoming packet in round-robin fashion to each tmm.  There are several changes that need to be made to enable RRDAG for UDP packets

  1. Immediate timeout profile must be applied to virtual servers that process RRDAG traffic.  In the example, a UDP profile is modified to include 0 second timeout(immediate). 
    1. modify ltm profile udp <udp_profile_name> idle-timeout 0 modify ltm profile udp <udp_profile_name> datagram-load-balancing enabled
  2. Inclusion of UDP destination port or ports that should be processed by RRDAG as a db variable.  In the example, UDP ports 6000 and 6060 are what would use RRDAG 
    1. modify sys db dag.roundrobin.udp.portlist value "6000:6060"
  3. Modification of ingress vlan to enable RRDAG
    1. modify net vlan <ingress_vlan_name> dag-round-robin enabled

Note: All three steps must be complete for UDP packets to be processed via RRDAG.
