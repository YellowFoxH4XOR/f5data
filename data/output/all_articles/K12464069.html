Known Issue

The BIG-IP system may unnecessarily send gratuitous Address Resolution Protocol (ARPs) for self IP addresses.

This issue occurs when all of the following conditions are met:

  • You configure a virtual server and associate it with a pool.
  • All pool members in the pool transition from offline to online status, or online to offline status.
In a high availability (HA) group configuration, all BIG-IP systems send gratuitous ARPs for the floating self IP address, with the standby BIG-IP systems additionally sending a gratuitous ARP for the non-floating self IP address.

Impact

Depending on the frequency of the virtual server status changes, and how the upstream devices are configured, the upstream devices may ignore subsequent non-erroneous ARP messages from the BIG-IP system, for example, during an HA failover.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A tcpdump reveals that the BIG-IP system sends gratuitous ARPs for self IP addresses when a virtual server status changes. In the following example, 10.10.10.1 is a virtual server; 10.10.10.2 is a floating self IP; and 10.10.10.3 is a non-floating self IP:

    16:03:13.009177 00:23:e9:xx:xx:xx > ff:ff:ff:ff:ff:ff, ethertype 802.1Q (0x8100), length 46: vlan 423, p 0, ethertype ARP, arp who-has 10.10.10.1 (ff:ff:ff:ff:ff:ff) tell 10.10.10.1
    16:03:13.142174 00:23:e9:xx:xx:xx > ff:ff:ff:ff:ff:ff, ethertype 802.1Q (0x8100), length 64: vlan 423, p 3, ethertype ARP, arp who-has 10.10.10.2 (ff:ff:ff:ff:ff:ff) tell 10.10.10.2
    16:03:13.342608 00:23:e9:xx:xx:xx > ff:ff:ff:ff:ff:ff, ethertype 802.1Q (0x8100), length 64: vlan 423, p 3, ethertype ARP, arp who-has 10.10.10.3 (ff:ff:ff:ff:ff:ff) tell 10.10.10.3
