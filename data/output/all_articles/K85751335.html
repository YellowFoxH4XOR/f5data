Description
When configuring External Identity Provider (IdP) Connectors using metadata exported from the IdP, additional certificate properties may be present in the saml-idp-connector object. These values will note be visible from the Configuration Utility.

Environment

  • BIG-IP APM as SAML Service Provider (SP)
  • External IdP Connector metadata contains two or more signing certificates

Cause
Product design

Recommended Actions

None

Additional Information

APM as SAML SP implements SAML auth settings from external SAML IdP entities which are referred to as "External IdP Connectors". These settings can be created either manually or automatically by importing metadata that was exported from the external IdP. When creating manually or re-configuring an External IdP Connector from the BIG-IP Configuration utility (TMUI), only one certificate, used to verify SAML responses from the IdP, can be specified within "Certificate Settings". Changing the certificate within the IdP connector settings from TMUI also changes the value of attribute "idp-certificate" within the corresponding bigip.conf "apm aaa saml-idp-connector" object. Creating an external IdP connector from exported IdP metadata that contains two or more certificates results in the following:

  1. The first two certificates listed in the imported metadata are stored in the BIG-IP System's certificate management store while subsequent certificates listed in the metadata are discarded
  2. The first certificate listed in the imported metadata is specified in the corresponding IdP connector's "Certificate Settings" and subsequently becomes the value of attribute "idp-certificate" within the corresponding bigip.conf "apm aaa saml-idp-connector" object
  3. The second certificate listed in the imported metadata becomes the value of attribute "secondary-idp-certificate" within the corresponding bigip.conf "apm aaa saml-idp-connector" object (not exposed in IdP connector settings from TMUI)
  4. The "secondary-idp-certificate" attribute within the bigip.conf "apm aaa saml-idp-connector" object serves no functional purpose other than to point to the second certificate listed in the imported metadata. 

Because the "secondary-idp-certificate" attribute points to the imported certificate said certificate cannot be deleted from BIG-IP System's certificate management store. The following error occurs when attempting to delete said certificate:

"The Certificate File (<name_of_cert_trying_to_delete>) cannot be deleted because it is in use by a IDP Connector (<name_of_idp_connector>)."

Since configuration of the "secondary-idp-certificate" attribute is not exposed in the IdP connector's "Security Settings" from TMUI, use the following tmsh command to remove the imported certificate from the IdP connector configuration, thus allowing said certificate to be deleted:

tmsh modify apm aaa saml-idp-connector <name_of_idp_connector> secondary-idp-certificate none

As of BIG-IP build versions >=12.1.3.2 and build versions >=13.1.0, multiple certificates imported from  IdP metadata  will result in the creation of a bundled certificate where all certificates listed in the metadata will reside. The IdP connector's "Security Settings" will point to the bundled certificate and the "secondary-idp-certificate" attribute within the corresponding bigip.conf "apm aaa saml-idp-connector" object will retain value none.

Note: if BIG-IP contains an IdP connector configuration where "secondary-idp-certificate" is pointing to a certificate prior to upgrading to a build version >=12.1.3.2 then that configuration will not change after upgrading to a build version >=12.1.3.2

Using a bundled certificate, the signature verification process will match from the list of certificates within the bundle the certificate that signed an incoming SAML IdP assertion/response message and use said certificate to verify said message.

Note: To verify if the certificate imported from IdP metadata is a bundled certificate, i.e. if it contains multiple certificates, from TMUI go to the BIG-IP System's certificate management list, find the imported certificate and look at the value for column "Contents". If it's bundled then the "Contents" value will be "Certificate Bundle". You can also open up the certificate from the BIG-IP System's certificate management list and view all of the certificates contained within the bundle.

Regarding BIG-IP as IdP, importing external SP metadata that contains multiple certificates in BIG-IP build versions prior to v12.1.3.2 will result in the following: 

  1. The first certificate listed in the imported metadata is stored in the BIG-IP System's certificate management store while subsequent certificates listed in the metadata are discarded
  2. The first certificate listed in the imported metadata is specified in the corresponding SP connector's "Security Settings" and subsequently becomes the value of attribute "sp-certificate" within the corresponding bigip.conf "apm sso saml-sp-connector" object
Note: External SP connector configuration does NOT contain a secondary certificate attribute

Importing external SP metadata that contains multiple certificates in BIG-IP build versions >=12.1.3.2 results in the creation and usage of a bundled certificate, just as is done with multi-cert IdP metadata imports.
