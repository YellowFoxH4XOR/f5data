Known Issue

The SERVERSSL_DATA event is not triggered when the SSL::collect command is called in the SERVERSSL_HANDSHAKE event.

This issue occurs when the following condition is met:

  • The system calls the [SSL::collect] in the SERVERSSL_HANDSHAKE event.

    For example:

    when SERVERSSL_HANDSHAKE {
        SSL::collect
    }
    when SERVERSSL_DATA {
        log local0. "ServerSSL Data"
        log local0. [SSL::payload]
        SSL::release
    }

Impact

The system does not trigger the SERVERSSL_DATA event.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The failure of the system triggering the SERVERSSL_DATA prevents the iRule from examining and manipulating the decrypted data.

Workaround

To work around this issue, you can add the SSL::release command to the SERVERSSL_HANDSHAKE event.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Modify the affected iRule by adding the SSL::release command to the SERVERSSL_HANDSHAKE event.

For example:

when SERVERSSL_HANDSHAKE {
    SSL::collect
    SSL::release  <-- Added to the SERVERSSL_HANDSHAKE event.
}
when SERVERSSL_DATA {
    log local0. "ServerSSL Data"
    log local0. [SSL::payload]
    SSL::release
}
