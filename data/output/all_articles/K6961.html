Known Issue

This is the result of a known issue. When a user in a master group using RADIUS authentication logs in to FirePass using their email address instead of their username, the authentication fails. If you log in using the standard FirePass username, which is the username for the account on the RADIUS server, authentication works normally.

FirePass permits user's to use their email address instead of their username, if the Allow to logon with email address as substitute of user name checkbox is selected on the Users: Global Settings page. The user can then log in with the email address listed in the Email: field of their account.

Normally, FirePass will substitute the username for the email address when attempting to authenticate to an external server, unless configured to do otherwise. However, when the user belongs to a master group that authenticates to an external server that is a RADIUS server, the FirePass fails to make this substitution. Viewing the RADIUS server log or a network packet dump shows that the RADIUS Name attribute is the email address, not the standard username.

Note: The Reports: Logons page displays the standard username for the logon record, not the email address.

F5 Product Development is tracking this issue as CR73078 and it was fixed in version 6.0.1 of FirePass software. For information about upgrading, refer to the FirePass release notes.

Workaround

You can work around this issue by logging in to the FirePass using the standard username, not the email address.
