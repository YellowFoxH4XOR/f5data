Known Issue

Multiple BIG-IP GTM configuration changes may cause multiple save operations that consume large amounts of memory.

This issue occurs when all of the following conditions are met:

  • ?You have configured the BIG-IP GTM system to automatically save BIG-IP GTM configuration changes (enabled by default).
  • You have made multiple BIG-IP GTM configuration changes to a configuration that is large enough that it takes longer to save than the configured timeout value for the automatic configuration saves.

By default, the BIG-IP GTM systems are configured to automatically save BIG-IP GTM configuration changes to the /config/bigip_gtm.conf file. The default timeout value is 15 seconds after the configuration change. However, large BIG-IP GTM configurations can take longer to save to the bigip_gtm.conf file than the configured timeout value. When you make multiple configuration changes to a large configuration, the system does not wait for the current save operation to finish before starting the subsequent save operation. As a result, making numerous changes over a short period of time can lead to many instances of the save operation running simultaneously and consuming large amounts of memory, and potentially exhausting memory resources.

Impact

The BIG-IP GTM system performance may be degraded, or the system may become unresponsive due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system performance may be degraded.
  • The system may become unresponsive due to memory exhaustion.
  • The ps command output lists multiple instances of tmsh save operations, similar to the following example:

    #ps -ef | grep tmsh
    root 4739 7622 0 20:12 ? R 0:10 /usr/bin/tmsh save sys config gtm-only partitions all
    root 4798 7622 0 20:13 ? S 0:00 /usr/bin/tmsh save sys config gtm-only partitions all
    root 4826 7622 0 20:14 ? S 0:00 /usr/bin/tmsh save sys config gtm-only partitions all
    root 4861 7622 0 20:14 ? S 0:00 /usr/bin/tmsh save sys config gtm-only partitions all

Workaround

To work around this issue, you can increase the automatic configuration save timeout to a value that allows the configuration save to complete before the next save is performed, or you can disable automatic configuration saves for BIG-IP GTM configuration changes. To do so, perform one of the following procedures:

Increase the automatic configuration save timeout
Disable automatic configuration saves

Increase the automatic configuration save timeout

To increase the automatic configuration save timeout value, perform the following procedure:

Impact of workaround: If you increase the automatic configuration save timeout value (from the default of 15 seconds), you need to allow additional time between configuration changes.

Important: Setting this value to lower than 10 seconds can impact system performance.

  1. Log in to the Configuration utility.
  2. Navigate to the DNS > Settings > GSLB > General configuration page.
  3. In the Configuration Save section, in the Timeout box, type the timeout value you want. (The default is 15 seconds.)
  4. Click Update.

Alternatively, you can disable automatic configuration saves using the following tmsh command syntax:

tmsh modify gtm global-settings general automatic-configuration-save-timeout <value>

For example, to set a timeout value of 30 seconds, you would type the following command:

tmsh modify gtm global-settings general automatic-configuration-save-timeout 30


Disable automatic configuration saves

To disable automatic configuration saves, perform the following procedure:

Impact of workaround: If you disable automatic configuration saving, you will need to manually save any changes to the BIG-IP GTM configuration.

  1. Log in to the Configuration utility.
  2. Navigate to the DNS > Settings > GSLB > General configuration page.
  3. In the Configuration Save section, clear the Enabled check box for the Automatic box.
  4. Click Update.

Alternatively, you can disable automatic configuration saves by typing the following tmsh command:

tmsh modify gtm global-settings general automatic-configuration-save-timeout -1
