Topic

You can use this F5 supported iApp template to marshal statistical and logging data from the BIG-IP system.  The iApp takes this data and formats it as a JSON object which is then exported for consumption by data consumers such as F5 BIG-IQ or applications such as Splunk.

The iApp allows you to configure several categories of data to be exported. For data consumers like Splunk, the iApp lets you configure the network endpoint to which the data is sent.

For instructions about using this iApp template, refer to the associated F5 Analytics deployment guide.

Important: F5 Application Services Templates (FAST) are replacing iApp templates. The f5.analytics iApp template was replaced by the Telemetry Streaming (TS) Extension as part of the F5 Automation Toolchain. For more information, refer to K13422: F5-supported and F5-contributed iApp templates.

To download and install the iApp template, perform the following procedures:

  • Downloading the iApp template
  • Installing the iApp template

Downloading the iApp template

Important: You must download the file; do not copy and paste the contents.

  1. Go to the F5 Downloads site.
  2. On the Downloads Overview page, click Find a Download.
  3. For BIG-IP Product Family, click iApp Templates.
  4. On the Select a Product Version and Container for page, click iApp-Templates.
  5. Read the End User Software License Agreement and either accept the license by clicking I Accept, or cancel the process by clicking Cancel.

    If you accept the End User Software License Agreement, the Select a Download page appears, which shows a table with the file name, product description, and file size details.

    Note: After you accept the End User Software License Agreement, the system does not present the agreement again for subsequent downloads that you perform during the same browser session.

  6. From the Filename column of the table, click the file named iapps-x.x.x.x.x.zip. For example, the file for the July 2018 iApp release is named iapps-1.0.0.518.0.zip.
  7. F5 supports the FTP, HTTP, and HTTPS protocols for downloading files from F5. Click one of the three supported protocols listed by clicking the down arrow button.

    A pop-up window appears, prompting you to either open or save the file.

    Note: Some browsers save the file to a default location. You can review your specific browser's documentation to change the default location of where you want to save files.

  8. Select the option to save the file.

Installing the iApp template

  1. Unzip the zip file to a location that is accessible from your BIG-IP system.
  2. Log in to the BIG-IP Configuration utility.
  3. From the iApp tab, select Templates.
  4. Click Import.
  5. Select the Overwrite Existing Templates check box.
  6. Click Browse.
  7. Browse to the location where you saved the iApp file.
  8. Select the file named f5.analytics.vx.x.x that corresponds to the iApp version you want to install. For example, the file for the July 2018 release of this iApp is named f5.analytics.v3.7.1.

    Note: Refer to the previously-listed Support Matrix to select the most current, supported template for your BIG-IP software version.

  9. Click Upload.

When the upload completes, the iApp is available for use.

Revision History

f5.analytics.v3.7.1

Features added and configuration changes

  • Added support for BIG-IP 12.1.x through 13.1.0
  • Added support for sending data to Sumo Logic. Options for Sumo Logic are the same as for Splunk except "API Key" options do not appear. The Sumo Logic does not use an APIKey for authentication.

Issues resolved

  • Corrected an issue with the iApp sending incorrect log messages about failures to connect to the remote analytics server.
  • Corrected an issue in which the iApp fails to apply Risk-engine logging iRules to virtual servers when the Module High Speed Logging Streams and Send LoginEvents to Analytics System? was set to Yes, and Send Risk Logs to AnalyticsSystem?' was set to No.
  • Corrected an issue with the iApp when leaving old statistics files on the BIG-IP hard disk.
  • Corrected an issue if a F5 iHealth password includes a dollar-sign ($) character (ASCII 0x24), the iApp fails to upload data to iHealth.
  • Corrected an issue in which any of the following characters in a TMOS configuration object name or attribute value may cause the iApp to generate improper JSON which are rejected by data consumers such as Splunk:  asterisk (*), question mark (?), left bracket ([), quotation mark ("), apostrophe ('), backslash (\), space (ASCII 0x20).
    Note: Starting in iApp version 3.7.1, the  quotation marks and backslashes in configuration object names or attributes are replaced with underscore (_)characters in JSON data, and all control characters (ASCII 0x00-0x1f plus 0xff) are replaced by exclamation-points (!).
  • Fixed an issue that was preventing statistical data from being sent because an array was not initialized.
  • Corrected an issue where, on a VIPRION with multiple blades, secondary blades go down after running the iApp.
  • Corrected an issue that causes parsing of QKView files for iHealth to fail.
  • Corrected an issue that causes the analytics solution API key not be included in the authorization header.
  • Corrected an issue that causes the parsing of BIG-IP GTM configuration to fail on certain BIG-IP devices.
  • Corrected an issue in the iApp code where the command for getting certain BIG-IP device information was different for BIG-IP 12.1.0 and earlier versions.
  • Corrected an issue when using an FQDN pool member on systems prior to BIG-IP 12.x. Attempting to use an FQDN pool member prior to version 12.x was denied, but only logged with no error reported to the user.
  • Corrected an issue in which a self IP with a non-zero route domain was used as the gateway to get into the data plane.
  • Corrected an issue in the iApp where in some BIG-IP versions you receive an error, stating FQDNs are not supported.
  • Corrected an issue where not all syslog messages were delivered to the remote endpoint.
  • Updated the iApp so it checks to see if a management route exists (management routes are not a part of the Application Service Object (ASO)).  If it does exist, the iApp updates it, if not it creates a new route.
