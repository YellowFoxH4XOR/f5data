Description

In a complex DNS deployment with multiple BIG-IP DNS devices, iQuery connection is full meshed between BIG-IP devices, you may find the following symptoms:

  • Some configuration is not synced, like the virtual server list is different.
  • Status is not synced, like some virtual server status is different
  • Error log in /var/log/gtm

err iqsyncer[<PID>]: 011ae104:3: Gtm config sync result from local mcpd: result {    result_code 17241961    result_message "01071769:3: Decryption of the field (pvalue) for object (/Common/<monitor name> 2 PASSWORD=) failed while loading configuration that is encrypted with a different master key."    result_attribute monitor_param }

  • Error log in the /var/log/ltm

err mcpd[<PID>]: 01071488:3: Remote transaction for device group /Common/gtm to commit id 65525 7005030723725864897 /Common/<device name> 0 failed with error 01071769:3: Decryption of the field (pvalue) for object (/Common/<monitor name> 2 PASSWORD=) failed while loading configuration that is encrypted with a different master key..

Environment

  • BIG-IP DNS / BIG-IP GTM
  • Monitor with password

Cause

Because the Master Key was not synced between BIG-IP GTM / DNS devices.

Recommended Actions

The solution is, sync the Master key between BIG-IP DNS / GTM devices manually. You can refer to "Using the f5mku utility to align the Master Key on each BIG-IP GTM system" in the article K11868: The master key is not synchronized after upgrading a BIG-IP GTM synchronization group
