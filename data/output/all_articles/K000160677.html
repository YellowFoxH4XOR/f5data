Description

No security event data or logs from F5 WAF for NGINX instances are visible in the NGINX Instance Manager (NIM) GUI, despite the nginx-agent reporting successful transmission of security violation events. 

/var/log/nginx-agent/agent.log

time="2026-03-27T13:36:14Z" level=info msg="reached a report interval of 60s, sending 10 Security Violation Events as a report"
time="2026-03-27T13:37:14Z" level=info msg="reached a report interval of 60s, sending 3 Security Violation Events as a report"

You have already added the nap_monitoring configuration in nginx-agent file as per Set up F5 WAF for NGINX instances for Security Monitoring

There could be a few reasons behind this behaviour, but in this article, we describe one particular scenario.

Environment

  • F5 WAF for NGINX (formerly NAP) managed by NGINX Instance Manager (NIM)

Cause

The root cause was a misconfiguration in the nginx-agent.conf file on the NAP instances, specifically the omission of the "/etc/app_protect" directory from config_dirs. This prevented the agent from collecting and forwarding security event logs to NIM. 

# OSS NGINX default config path
# path to aux file dirs can also be added
config_dirs: "/etc/nginx:/usr/local/etc/nginx:/usr/share/nginx/modules:/etc/nms"

Answer/Recommended Actions

  1. Update nginx-agent.conf on NAP instance to include the "/etc/app_protect" directory. Resulting stanza would look like below.
    # OSS NGINX default config path
# path to aux file dirs can also be added
config_dirs: "/etc/nginx:/usr/local/etc/nginx:/usr/share/nginx/modules:/etc/nms:/etc/app_protect"
  2. Restart the nginx-agent service after making the configuration change. 
    sudo systemctl restart nginx-agent.service
  3. Verify that security event logs appear in the NIM GUI and dashboards (You might have to might couple of minutes until the new data is sent).
