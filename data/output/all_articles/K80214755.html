Description

You are using a TCP monitor with Transparent option set to Yes.

After the 3 way handshake, the BIG-IP sends a RST. Refer to the packet capture sample below.

$ tshark -r 'sample.pcap'
    1   2.069167 0.000000 4094  10.10.10.66 → 10.10.10.205 60 43636 80 TCP OUT s1/tmm0 : 43636 → 80 [SYN] Seq=0 Win=14600 Len=0 MSS=1460 SACK_PERM=1 TSval=2047294050 TSecr=0 WS=128
    2   2.069808 0.000641 4094 10.10.10.205 → 10.10.10.66  60 80 43636 TCP IN  s1/tmm0 : 80 → 43636 [SYN, ACK] Seq=0 Ack=1 Win=28960 Len=0 MSS=1460 SACK_PERM=1 TSval=2607434642 TSecr=2047294050 WS=128
    3   2.070390 0.000582 4094  10.10.10.66 → 10.10.10.205 52 43636 80 TCP OUT s1/tmm0 : 43636 → 80 [ACK] Seq=1 Ack=1 Win=14720 Len=0 TSval=2047294051 TSecr=2607434642
    4   2.070398 0.000008 4094  10.10.10.66 → 10.10.10.205 52 43636 80 TCP OUT s1/tmm0 : 43636 → 80 [RST, ACK] Seq=1 Ack=1 Win=14720 Len=0 TSval=2047294051 TSecr=2607434642 [F5RST(peer): RST from BIG-IP internal Linux host]

The RST will have the description:
F5RST(peer): RST from BIG-IP internal Linux host

Environment

  • TCP monitor
  • Transparent option set to Yes
  • RST by BIG-IP after 3 way handshake
  • RST description is: F5RST(peer): RST from BIG-IP internal Linux host

Cause

The RST is an expected behavior when Transparent is set to Yes in the TCP monitor options.

Recommended Actions

If the RST is causing issues to your application and you need to remove RST, choose the following steps to resolve your issue:

  1. Disable Transparent in the TCP monitor
  2. Disable the global value for TCP reset transparent

Disable Transparent in the TCP monitor
  • You will not be able to set Transparent to No for the current TCP monitor
  • You will need to create a new TCP monitor with the Transparent option set to No
  • Once you have configure this new TCP monitor, replace the old TCP monitor with this new TCP monitor on the pool monitor

 Disable the global value for TCP reset transparent
  1. Login to the Command Line
     
  2. Run the following command to disable TCP reset transparent:
    tmsh modify sys db bigd.resettransparent value false
    Note: This is a global change and will impact all TCP monitors. It will impact all TCP monitor which is using transparent.
     
  3. Run the following command to confirm the change:
    tmsh list sys db bigd.resettransparent

    The output would be as follows:
    tmsh list sys db bigd.resettransparent
    sys db bigd.resettransparent {
        value "false"
    }
     
  4. If you need to revert the TCP reset transparent to the default value, run the following command:
    tmsh modify sys db bigd.resettransparent value true

    To confirm the value is the default value, run the following command:
    tmsh list sys db bigd.resettransparent

    The output would be as follows:
    tmsh list sys db bigd.resettransparent
    sys db bigd.resettransparent {
        value "true"
    }
    Important: Reset for TCP transparent is an expected behavior so F5 cannot guarantee any unexpected outcome when you disable reset for TCP transparent. This is the official description of transparent TCP monitor:
    A monitor that operates in transparent mode can monitor nodes or pool members through transparent network devices, such as firewalls.
