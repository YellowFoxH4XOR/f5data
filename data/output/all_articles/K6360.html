Note: Beginning in BIG-IP 11.x, F5 recommends that you use the tmsh utility for creating self-signed certificate/key pairs and certificate signing requests (CSRs). For additional information, refer to the sys crypto Module Components chapter of the Traffic Management Shell (tmsh) Reference Guide for command syntax and examples.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

The BIG-IP system ships with the gencert utility, which simplifies the creation of self-signed certificate/key pairs and certificate signing requests (CSRs) from the command line.

The following table provides a list of arguments accepted by the gencert utility and the default values:

Gencert argumentDescriptionDefault valueNotes
-pThe path for storing the certificate, key, and CSR files/config/sslEach file is stored in a subdirectory of the specified location:

Certificates: ssl.crt
Keys: ssl.key
CSRs: ssl.csr

The subdirectories are created automatically if they do not already exist.
-nThe base name for the certificate, key, and CSR filesdefaultFor ease of identification, F5 recommends that you use the virtual server FQDN or Common Name as the base filename.
-hCommon Name or FQDN for which the certificate, key, and CSR are createdlocalhost.localdomainnone
-cCountryUSnone
-sStateWAnone
-tCitySeattlenone
-oOrganizationMyCompanynone
-uOrganizational UnitITnone
-eEmail addressroot@localhost.localdomainnone
-fFIPS compatibilitynoneIf this option is used, the key may be used with FIPS.
-yChange the certificate datenoneUse this option to backdate the certificate by one day (11.x and later).
-XThe certificate will not be part of the configurationnoneUse this option for certificates that will not be part of the configuration (11.x and later).
<keysize>The size, in bits, of the key to be generatednoneF5 recommends that you use a minimum key size of 1024 bits.

For example, to create a test self-signed certificate / key pair and matching CSR, type a command that appears similar to the following example:

gencert -n f5test -h f5test.test.com -c US -s TX -t Somewhere -o "F5 Test" -u "Some Unit" 1024

Important: You must use quotation marks to enclose arguments which include non-alphanumeric characters, including whitespace.

The certificate file is placed in the /config/ssl/ssl.crt directory.

The key file is placed in the /config/ssl/ssl.key directory.

The certificate signing request file (CSR) is placed in the /config/ssl/ssl.csr directory.

The file names are f5test.crt, f5test.key and f5test.csr.

The certificate / key pair and CSR are created with the following attributes:

hostname: f5test.test.com
country: US
state: TX
city: Somewhere
org: F5 Test
orgunit: Some Unit
keysize: 1024

Note: Certificates generated by the BIG-IP gencert utility are valid for 3,655 days, which is just over 10 calendar years. The expiry cannot be customized using the BIG-IP gencert utility. However, if you want to customize the expiry of a self-signed certificate, you can use the web-based Configuration utility to create the certificate. To do so, browse to Local Traffic > SSL Certificates > Create, and specify the appropriate number of days for the Lifetime setting when creating the certificate. The default lifetime for self-signed certificates created in the Configuration utility is 365 days.
