Topic

You should consider using this procedure under the following conditions:

  • You have a virtual server configured to serve multiple HTTPS sites using the Transport Layer Security (TLS) Server Name Indication (SNI) extension.
  • You want to allow access to the virtual server based on the hostname provided by the client in the TLS SNI extension.

Description

You can use local traffic policies to limit access to a virtual server based on the host name provided by the client in the TLS SNI extension.  The host name of the target server is sent by the client in the SNI server_name extension type as part of the client hello during the SSL handshake.  The BIG-IP system can compare the server name in the SNI sent by the client to the allowed host names configured in the local traffic policy and decide which requests to allow.  When a request reaches the virtual server that does not match any of the configured allowed host names, the BIG-IP system can reset the connection.

For example, you can create a local traffic policy that only allows access to the virtual server if the SNI server name is one of of the following:
  • example.com
  • example.net
  • 10.10.10.100

In the following example policy configuration, the policy is named ltp_sni and has two rules named no_sni and rule_allow. When the BIG-IP system receives the SSL client hello message, the no_sni rule checks for the existence of the SNI extension. If there is no SNI extension present, the BIG-IP system logs a Blocked no SNI message to the /var/log/ltm file and immediately resets the connection.  If the SNI extension is present in the SSL client hello, the rule_allow rule compares the server name to the list of allowed host names.  If the server name does not match any of the allowed host names, the BIG-IP system logs a Blocked bad SNI message to the /var/log/ltm file and immediately resets the connection. If the server name is allowed, the BIG-IP system selects the appropriate SSL certificate and completes the SSL handshake.

ltm policy /Common/ltp_sni {
    requires { client-ssl }
    rules {
        no_sni {
            actions {
                0 {
                    log
                    ssl-client-hello
                    write
                    facility local0
                    message "Blocked no SNI."
                    priority info
                }               
                1 {
                    shutdown
                    ssl-client-hello
                    connection
                }
            }
            conditions {
                0 {
                    ssl-extension
                    ssl-client-hello
                    server-name
                    not
                    exists
                }
            }
        }
        rule_allow {
            actions {
                0 {
                    log
                    ssl-client-hello
                    write
                    facility local0
                    message "Blocked bad SNI."
                    priority info
                }
                1 {
                    shutdown
                    ssl-client-hello
                    connection
                }
            }
            conditions {
                0 {
                    ssl-extension
                    ssl-client-hello
                    server-name
                    not
                    values { example.com example.net 10.10.10.100 }
                }
            }
            ordinal 1
        }
    }
    strategy /Common/first-match
}

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Configuration utility, TMOS Shell (tmsh), and the iControl REST API.
  • You have command line access to a Linux system (or an alternate BIG-IP system) that has the curl and jq (command line JSON processor) utilities installed.

Procedures

You can create local traffic policies using the Configuration utility, tmsh, or by using the iControl REST API.  To create the previous policy, perform one of the following procedures:
  • Configuring the local traffic policy using the Configuration utility
  • Configuring the local traffic policy using tmsh
  • Configuring the local traffic policy using iControl REST

Configuring the local traffic policy using the Configuration utility

When you create a local traffic policy you first create a draft of the policy. After the draft is published, you can associate it with a virtual server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies > Policy List.
  3. Select Create and provide a name for the draft policy.
  4. Go to the Local Traffic > Policies > Policy List.
  5. Under Draft Policies, select the name of the draft policy.
  6. For Rules, select Create.
  7. For Name, enter a name for the rule.
  8. For Match all of the following conditions, select the add icon (+) and configure the conditions so that the statement reads as follows:

    SSL Extension server name does not exist at ssl client hello time.

  9. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows:

    Log message Blocked no SNI at ssl client hello time.

  10. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows:

    Reset traffic connection at ssl client hello time.

  11. Select Save.
  12. For Rules, select Create.  
  13. For Name, enter a name for the second rule.
  14. For Match all of the following conditions, select the add icon (+) and configure the conditions so that the statement reads as follows:

    SSL Extension server name is not any of example.com example.net 10.10.10.100 at ssl client hello time.

  15. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows: 

    Log message Blocked bad SNI. at ssl client hello time.

  16. For Do the following when the traffic is matched, select the add icon (+) and configure the conditions so that the statement reads as follows: 

    Reset traffic connection at ssl client hello time.

  17. Select Save.
  18. To save the draft and publish the policy, under General Properties, for Save Draft, select Save and Publish Policy. 
  19. To apply the published policy to a virtual server, go to Local Traffic > Virtual Servers > Virtual Server List.
  20. Under Resources for the virtual server, select Edit.
  21. Under Policies, select Manage.
  22. Select the published policy from the Available list and move it to the Enabled list.
  23. Select Finished.

Configuring the local traffic policy using tmsh

To create a draft of the local traffic policy, publish the policy, and associate it with a virtual server using tmsh, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create the policy using the following syntax:

    create /ltm policy /Common/Drafts/<policy_name> rules add { <rule1_name> { conditions add { <ordinal> { ssl-extension server-name not exists ssl-client-hello } } actions add { <ordinal> { log write facility <facility> message "<message>" priority <priority> ssl-client-hello } <ordinal> { shutdown connection ssl-client-hello } } } <rule2_name> { conditions add { <ordinal> { ssl-extension server-name not values { <allowed_servernames> } ssl-client-hello } } actions add { <ordinal> { log write facility <faclility> message "<message>" priority <priority> ssl-client-hello } <ordinal> { shutdown connection ssl-client-hello } } } } requires add { client-ssl } strategy first-match

    To create the policy used in the previous example, enter the following:

    create /ltm policy /Common/Drafts/ltp_sni rules add { no_sni { conditions add { 0 { ssl-extension server-name not exists ssl-client-hello } } actions add { 0 { log write facility local0 message "Blocked no SNI." priority info ssl-client-hello } 1 { shutdown connection ssl-client-hello } } } rule_allow { conditions add { 0 { ssl-extension server-name not values { example.com example.net 10.10.10.100 } ssl-client-hello } } actions add { 0 { log write facility local0 message "Blocked bad SNI." priority info ssl-client-hello } 1 { shutdown connection ssl-client-hello } } } } requires add { client-ssl } strategy first-match

  3. Publish the policy using the following syntax:

    publish /ltm policy <policy_name>

    For example:

    publish /ltm policy Drafts/ltp_sni

  4. Associate the published policy with the virtual server using the following syntax:

    modify /ltm virtual <virtual_server_name> policies add { <policy_name> }

    For example, to associate the ltp_sni local traffic policy with the vs_http virtual server, enter the following command:

    modify /ltm virtual vs_http policies add { ltp_sni }
