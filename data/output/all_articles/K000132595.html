Description

You want to suppress error messages caused by Bug ID 567503

Environment

  • BIG-IP APM version affected by Bug ID 567503

Cause

Bug ID 567503: ACCESS:session remove can result in confusing ERR_NOT_FOUND logs
K03293396: Running iRule commands may trigger erroneous ERR_NOT_FOUND log messages

Recommended Actions

Please consider upgrading your BIG-IP to a version fixed for a permanent fix.
As a temporary workaround you can use base guidelines from K35284961: Filtering BIG-IP log messages to filter out those error messages:

Impact of procedure: Below procedure should have no impact to traffic processing.

  1. Remount /usr into read-write, make a backup of template file and grant it a write permission, run commands:

    mount -o rw,remount /usr
cp /usr/share/defaults/config/templates/syslog.tmpl /var/tmp/syslog.tmpl.orig
chmod +w /usr/share/defaults/config/templates/syslog.tmpl
  2. Open /usr/share/defaults/config/templates/syslog.tmpl using prefered text editor (nano/vi/vim), e.g. nano 
    nano /usr/share/defaults/config/templates/syslog.tmpl
  3. While in nano, use Ctrl+W to search and look for f_messages {, locate the closing bracket }; , and add a break line (ENTER) and paste following: 
    filter f_K000132595 {
   not(message("Access encountered error: ERR_NOT_FOUND. File: ../modules/hudfilter/access/access.c, Function:"));
};
    So the whole section looks as following:  
    filter f_messages {
   level(UNIX_CONFIG_SYSLOG_REPLACE_MESSAGESFROM..UNIX_CONFIG_SYSLOG_REPLACE_MESSAGESTO)
   and not facility(auth, authpriv, cron, daemon, mail, news)
   and not message("WA");
};

filter f_K000132595 {
   not(message("Access encountered error: ERR_NOT_FOUND. File: ../modules/hudfilter/access/access.c, Function:"));
};

source s_adm_2cloud {
   pipe("/var/run/adm.dump.2cloud.pipe" perm(0640));
};
  4. Then use Ctrl+W again to find the following section 
    log {
   source(local);
   destination(d_syslog_pipe);
};
  5. Add filter(f_K000132595); entry between source(...) and destination(...), so afterwards the section looks as following: 
    log {
   source(local);
   filter(f_K000132595);
   destination(d_syslog_pipe);
};
  6. Save with Ctrl+O and exit nano with Ctrl+X
  7. To apply changes run: 
    tmsh modify /sys syslog daemon-from info && tmsh modify /sys syslog daemon-from notice
  8. Verify changes done by running: 
    grep f_K000132595 /etc/syslog-ng/syslog-ng.conf -c
    You should see "2" in output. This indicates the procedure was done and applied correctly.
    If that's not the case please verify syntax (mind all brackets and semicolons).
  9. Lastly, retain write permission to template file and remount /usr to read only , run: 
    chmod -w /usr/share/defaults/config/templates/syslog.tmpl
mount -o ro,remount /usr

 

Additional Information

Syslog-ng Administration Guide section "Using filters"
To check syslog-ng version installed on BIG-IP see: K59285635: BIG-IP third-party software matrix (14.x)

In HSL setups there is another workaround based on
Bug ID 597955: APM can generate seemingly spurious error log messages 
tmsh modify /sys db tmm.access.extendedlog value disable
