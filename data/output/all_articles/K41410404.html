Issue

Error Message

notice mcpd[<PID>]: 0107168e:5: Unable to do incremental sync, reverting to full load for device group <dg> device <peer> from commit id { <id> } to commit id { <id> }

In this error message, note the following:

  • <PID> is the process ID for the mcpd process
  • <dg> is the name and partition of the device group
  • <peer> is the name of the peer device in the device group
  • <id> is the configuration change identifier

For example:

notice mcpd[2789]: 0107168e:5: Unable to do incremental sync, reverting to full load for device group /Common/syncgroup1 device %cmi-mcpd peer-/Common/ltm1.example.com from commit id { 4 6390393316259868817 /Common/ltm1.example.com } to commit id { 3 6391877370007482801 /Common/ltm2.exmample.com }.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

The incremental config cache is a buffer that contains a list of the mcpd transactions (configuration changes).  It is an optimization that allows the configsync process to send only the transactions required to bring a peer device up to the current configuration, rather than sending the full device configuration.The cache has a limited size, and the oldest changes are dropped from the cache to make room for more recent ones. When the remote device's configuration is older than the oldest commit ID held in cache, the message described here is logged, and the full device config is instead sent to the peer.

This message occurs when all of the following conditions are met:

  • The BIG-IP system is a member of a device group configured to perform an incremental configuration synchronization (ConfigSync).
  • When the configuration data required by the peer device-group member is sufficiently old that the cache no longer contains a complete set of changes since that commit time
  • The incremental configuration cache is insufficiently large to contain the entire set of changes between two commits.

Impact

ConfigSync operations may take longer to complete. If automatic synchronization is enabled and many changes are made to configuration in the device group, the mcpd process may become unresponsive or experience a low memory condition.

Recommended Actions

To reduce the time required for a config sync to complete, you can reduce the size and frequency of the configuration changes made to the BIG-IP system, or alternatively, you can increase the size of the incremental ConfigSync cache. to hold more data.

To increase the size of the incremental ConfigSync cache, perform the following procedure:

Impact of procedure: Increasing the incremental ConfigSync cache size will increase the normal operating memory footprint of the mcpd process.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To view the current setting for the incremental ConfigSync cache, use the following command syntax:

    list cm device-group <device_group_name> incremental-config-sync-size-max

    For example:

    list cm device-group sync_group1 incremental-config-sync-size-max

  3. To increase the incremental ConfigSync cache, use the following command syntax:

    modify cm device-group <device_group_name> incremental-config-sync-size-max <value>

    For example, to increase the size to 2048 KB, type the following command:

    modify cm device-group sync_group1 incremental-config-sync-size-max 2048
