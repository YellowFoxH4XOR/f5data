Topic

While handling real-server responses, the LineRate system preserves the transfer encoding that the real-server provides. The auto-chunking behavior is determined by the following:

  • The presence of the Content-Length header in the HTTP response from the real-server.
  • The way you alter the HTTP response before sending the response to the client.

Description

If the real-server response contains a Content-Length header, the system passes the header through to the client, unchanged. This situation happens regardless of any changes that the LineRate scripting made to the HTTP response body. If the LineRate system manipulates the HTTP response from the real-server and removes the Content-Length header from the real-server response, then the auto-chunking feature applies the ??Transfer-Encoding: chunked? header to the response before the system sends the response to the client; the auto-chunking feature also applies the proper chunk encoding to the body. This information comes in to play when you use LineRate scripting to alter an HTTP response body that is served from a real-server, before sending the HTTP response body to the requesting client. 

For example, consider the following request-handler script:

Note: The following code is intended only as an example and may not be applicable to your configuration. Refer to the Scripting Developer's Guide for your version of LineRate LROS.

    vs.on('request', function (servReq, servResp, cliReq) {
      console.log("request received for: " + servReq.url);

      // immediately send request to back end real-server

      servReq.bindHeaders(cliReq);
      servReq.fastPipe(cliReq);
      var alertstr = self.append_string;
      cliReq.on('response', function(response) {
          console.log("**HANDLING RESPONSE " + servReq.url + "**");

          // send along response headers un-touched

          response.bindHeaders(servResp);
          response.on('data', function(chunk) {

            // get a chunk, send a chunk

            servResp.write(chunk);
            console.log("  " + servReq.url + " got some response data");
          });
          response.on('error', function(blah) {
            console.log("#### " + servReq.url + " errored out: "+ blah);
            servResp.end();
          });
          response.on('end', function(chunk) {
            console.log("  ## ENDING ##");

            // add our additional content

            servResp.end(alertstr);
          });
      });
    });
  });
}

var appender = new ResponseAppender('vs_test', '<script>alert("SURPRISE!")</script>');

The previous example would append <script>alert ("SURPRISE!")</script> to the HTTP response that the real-server sent. However, if the original HTTP response contained a Content-Length header, the client browser may not display that added content, since the actual message body would now be larger than the length reported by the Content-Length header.

Recommendations

When using LineRate scripting to modify HTTP response data from real-servers, you should consider the following factors:

If you want to preserve the non-chunked transfer encoding, then you need to alter your script in order to maintain the total byte count of the response body you want to send, and then ensure that the Content-Length header is assigned this value. However, if you are not concerned with the presence of a Content-Length header in the response to the client, then you can simply remove the Content-Length header, if present, and allow the auto-chunking behavior to manage the framing of the response body.

You can remove the Content-Length header by using the servResp.removeHeader() object. Using the previous example, find the section with response.bindHeaders(servResp); and modify it to match the following:

Note: The following code is intended only as an example and may not be applicable to your configuration. Refer to the Scripting Developer's Guide for your version of LineRate LROS.

          response.bindHeaders(servResp);
          servResp.removeHeader("Content-Length");

All HTTP responses from real-servers will now have the Content-Length header stripped and replaced with the Transfer-Encoding: chunked header, which allows the page to properly display in the client browser.
