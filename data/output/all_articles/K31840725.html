Known Issue

HTTP/2 connections to a BIG-IP virtual server may fail with a security error.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server with an HTTP/2 profile.
  • The virtual server receives a client request that uses the Application Layer Protocol Negotiation (ALPN) or Next Protocol Negotiation (NPN) Transport Layer Security (TLS) extensions.
  • The BIG-IP system chooses a cipher suite that is incompatible with HTTP/2.
  • The BIG-IP system or client chooses HTTP/2 as the next protocol during the TLS handshake.

The problem occurs because HTTP/2 only permits TLS 1.2 or higher cipher suites that use ephemeral keys. If the cipher suite chosen is not permitted, the HTTP/2 connection will fail with an INADEQUATE_SECURITY error code.

Impact

HTTP/2 connections to BIG-IP virtual servers fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • HTTP/2 connections to BIG-IP virtual servers configured with an HTTP/2 profile fail.
  • The HTTP/2 client reports an error message similar to the following example:

    INADEQUATE_SECURITY

Workaround

To work around this issue, you can make sure that TLS 1.2 cipher suites that are compatible with HTTP/2 (cipher suites that use ephemeral keys) come first. Create a Client SSL profile with a custom cipher string and use it to replace the Client SSL profile on the affected virtual server. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the SSL menu, select Client.
  4. Click Create.
  5. Type a name for the SSL profile.
  6. From the Parent Profile menu, select clientssl.
  7. From the Configuration menu, select Advanced.
  8. In the Ciphers section, select the Custom check box.
  9. In the Ciphers box, remove the default string and type a cipher string that will place cipher suites that use ephemeral keys at the top of the list.

    For example, the following string is the equivalent of the BIG-IP 12.0.0 default string, but places cipher suites with ECDHE/RSA and EDH/RSA key exchange mechanisms first:

    !SSLv2:!EXPORT:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:DHE+3DES:RSA+AES-GCM:RSA+AES:RSA+3DES:ECDHE+3DES:-MD5:-SSLv3:-RC4

    Note: Alternatively, you can perform the workaround using the Traffic Management Shell (tmsh) by typing the following command syntax:

    tmsh create /ltm profile client-ssl <profile_name> ciphers !SSLv2:!EXPORT:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:DHE+3DES:RSA+AES-GCM:RSA+AES:RSA+3DES:ECDHE+3DES:-MD5:-SSLv3:-RC4

    Note: For more information about configuring the cipher strength, refer to K17370: Configuring the cipher strength for SSL profiles (12.x).

  10. Complete the remaining profile settings by copying any custom settings from the profile you will replace.
  11. Click Finished.
  12. Navigate to Local Traffic > Virtual Servers.
  13. Select the affected virtual server you want to edit.
  14. In the Selected field, replace the existing profile with the new profile you created, which will appear in the Available field.
  15. Click Update.
