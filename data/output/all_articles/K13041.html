Topic

F5 has recently discovered and corrected a number of issues that affect customers running ARX version 6.0.0.

The following table lists the rollup hotfixes released for ARX version 6.0.0. The table lists each hotfix, along with the ID numbers of issues that the corresponding hotfix resolves, and a description of each issue.

Note: These rollup hotfixes are cumulative; each hotfix contains all fixes included in the previous hotfixes. For example, HF3 includes all IDs fixed in HF1 and HF2.

ARX VersionID NumberDescription
*6.0.0 HFRU9
(build-13610)
375327A problem that caused generation of a core file as a result of handling a bad SMB packet has been fixed.
385790In a DR scenario, the load command fails on the backup cluster if the failed active cluster has wins-alias in its configuration. This problem has been fixed.
388156Fixed a problem where wrong permissions can be granted when multiple WMA (windows-management-authorization) users are defined in a namespace.
390045NSM crashes due to a non-maskable interrupt (NMI) with an exception code. The NMI fires because the NSM failed to switch tasks within a certain amount of time. For further root cause analysis, code has been changed to collect additional debug information if the issue arises again.
392570New firmware is needed for the new Adaptec 5405z RAID controller to support proper functionality of CLI RAID commands.
   
*6.0.0 HFRU8
(build-13609)
370559NLM client callbacks now originate from the first VIP that the client has connected to.
385203 Fixed a problem in NLMD that could prevent NLM from posting callbacks to MAC OS clients.
385244 When SMB signing is enabled and Kerberos configured, Windows XP clients will encounter connection issues.
386795 Fixed a problem where the remove namespace volume command could inadvertently remove metadata shares for other managed volumes in a multi-headed or multi-homed filer.
   
**6.0.0 HFRU7
(build-13608)		359839Fixed a problem where place rules start scanning unexpectedly after a reload.
362675A problem in instrumentation functionality for the ARX-500 that caused the creation of a core file when IPC connection problems occurred has been fixed.
377753Additional logging and graceful error handling have been added to the Chassis Manager module.
380020A problem where empty NOTIFY CHANGE response is returned back to the client has been fixed.
381053A license limit was flagged for direct shares when adding managed volumes. This problem has been fixed. 
381140A license daemon transaction leak that could cause expected reboot of backup switch has been fixed.
381513The sub-share daemon could core when it sync the back-end sub-shares during a share online. This problem has been fixed.
382020The problem of high CPU utilization used by the java process has been fixed.
383519A problem that caused the ARX to generate NSM cores when the VIP received an excessive stream of ICMP ECHO requests with many small fragments has been fixed.
385014The DCSLOW log message and its documentation have been improved to provide more accurate information.
   
**6.0.0 HFRU6
(build-13607)		368578Copy a release file from a namespace to ARX is now working.
370677The NSM core due to the internal packet buffer exhaustion has been fixed.
374686When a slow DC is detected, the ARX will now produce a syslog entry for each slow DC and promote the correct backup DC. 
374708Fixed a problem where the PID of a client request is not correctly preserved and the request would fail.
374752Fixed a problem where DNAS does not properly identify an alternate file name generated by the filer when multi-byte characters are involved.
375366A problem that caused a delete-on-last-close file to remain open in metadata after having been closed by the filer and the NSM has been fixed.
375669The auto-migrate parameter now works correctly for share farms according to the policy-freespace settings that are configured.
375673An invalid key type input that could cause cli_daemon to generate a core has been fixed.
376622A problem has been fixed in which the last-name-offset value in the SMB find-first response was set incorrectly.
377813An array index problem which could cause NSM core and switch reboot has been fixed.
377892Fixed a problem where ARX uses wrong name and type for a domain during WINS registration retry.
378577The NVRAM allocation problem which could cause user access has been fixed.
378613Fixed a problem where a policy rule does not run due to incorrect count of ‘start’ time and ‘every’ time.
379969A problem has been fixed in which a snapshot delete operation could fail and include wrong shares.
380355Fixed a fastpath packet buffer leak problem that could cause NSM to fail.
   
*6.0.0 HFRU5
(build-13605)		367007A timeout is now used by the junior when the senior does not initiate the membership protocol.  Without it, the junior could fail during the pairing process after the reboot.
371718Some ipmi.pl debug log messages were removed from the syslog and placed in the procdat.
374950Fixed a database problem where changes made on the active switch are not propagated to the junior.
371268Fixed an internal timer issue which could cause long delays to act on OMDB changes such as adding new exports.
373159Sync shares algorithm has been improved to avoid excess processing which causes cifsconfd slowness.
373157Fixed an infinite loop problem in the timer logic that could lead to a non-maskable interrupt (NMI) and NSM cores.
374201A reserved internal port that is used by the NSM was re-used for client connections. This could cause RPC failures when DNAS needs to communicate with the NSM. The port collision issue is fixed.
375408A stale attribute cache problem which could display incorrect SI/IS entries in the inconsistency report has been fixed.
368594A problem with the count form of the ‘ip proxy-address’ command that caused proxy IP address assignments to be created out of order, and resulting subsequently in the creation of core files, has been fixed.
373156Fixed a nil pointer problem that could cause subshrmgtd to core during share removal.
374560Sync from cifs service could result in shares missing due to volume paths with incorrect case. This problem has been fixed.
371405Fixed a vip/xip net mask processing problem where non -/16 prefix could be programmed into /16.
   
**6.0.0 HFRU4
(build-13604)		366235A problem that caused storage resources to become inaccessible to users has been corrected by changing the handling of timeouts in the ARX's path caching functionality.
367301A problem that caused NFS TCP connections to back end filers to get stuck in the "Retrying" state, preventing access to the back end file systems, has been fixed.
368412Increase the size of the ARP cache on the ARX1500 and ARX2500 to allow for larger non-routed networks.
368456A problem that caused a paired NSM core when a replacement ARX re-establishes redundancy has been fixed. 
369267When an ARX virtual snapshot takes longer than two minutes, the WinRM connection from ARX to the Windows file server may be reset by the Windows file server, causing the snapshot operation to fail. The ARX now re-establishes the WinRM connection and completes the snapshot operation with the new connection.
369429The ARX 1500 and ARX 2500 now properly reject HTTP requests to the ARX VIP.
371633A problem that caused filer probe and import to fail when there are 112 or more user accounts in the share security tab has been fixed.
371717A problem that caused file history queries to return no files in the report has been fixed.

   
*6.0.0 HFRU3
(build-13601)		365373A problem existed that when volume configuration was edited via the GUI, the metadata shares in ARX disaster recovery clusters would become misconfigured. This problem manifested only in disaster recovery clusters and is fixed now.
366051Corrected an issue where an unexpected error on an NFS metadata connection resulted in a namespace restarting.
366698Performing a shadow copy operation for a directory may fail with error code 26 ["Stage file failed"].   This happens when the existing directory on the target is read-only. If the directory does not contain any data, this issue can be solved by turning off the READONLY attribute before the shadow receiver changes the directory on the target volume.
368040If an ARX 1500 or ARX 2500 booted up with a configuration in which VLAN 1 was used and all interfaces were used as members of channels, the ARX would generate a core file and reboot.
369794Fixed a broken error handling routine related to inode allocation that could result in an internal deadlock, resulting in a namespace eventually failing to service client requests until it is restarted.
   
**6.0.0 HFRU2
(build-13599)		359696A file tracking query using a wildcard in the search parameters could fail with the error: “File history query exceeded maximum search depth” when the search should have worked.
360165During an import, the import report could be improperly truncated if the ARX system encounters 1000 or more of any of the following errors:  dfsLinkFound, abeCheckFailed, noEnumSupport, rootNotImported, maxHardLinksFound, dirPromoteFailure, pathNotFound, or dirIgnored.
363194Fixes a problem where the “show policy” command returns an error after a software upgrade.
363758Addressed an internal timing problem that could result in Stale file handle NFS errors for the du and ls commands.
364211A problem has been fixed in which multiple place-rules targeted the same share-farm and caused the removal of each other's pending directory promotes.
364300The timeout for connecting to a domain controller, for NTLM/NTLMv2 authentication when constrained delegation is used, has been increased from 10-20ms to about 10 seconds.
364320File tracking reports no longer fail when initiated after another file tracking report that had been cancelled.
364364Using the quorum-disk command with the spn argument no longer changes the user's domain to that of the quorum disk SPN domain.
364805The “license” keyword was missing from the copy command for copying to the ARX.
365540The ARX1500 and ARX2500 now reject connection requests to port 135.
365802A check is made to see if the client connection state referenced by a transaction is still valid before error statistics are accessed and incremented. This fixes a crash that was caused by disconnection from the front end and subsequent attempts to increment error statistics associated with that client connection state.

   
**6.0.0 HFRU1
(build-13598)		358916Prevent system failure if a sync files operation and a remove share operation are running on the same share.
359924Snapshots to a Windows 2003 server stopped working after a patch changed the server’s behavior to no longer reply to ARX requests with a drive letter.  The ARX now accepts a NULL drive letter.
361102Prevent the internal location broker process from being unnecessarily restarted on a busy system. 
361219Fix “show filer connections” CLI command to work properly on ARX1500 and ARX2500 platforms.
361293Fix problem activating new evaluation license after previous evaluation license has expired.
361295In an NFS environment with UDP entirely disabled on an external filer, the ARX would not be able to successfully create connections to it.
361975An NSM core could occur if a response to an outstanding back-end CIFS request is received while the NSM is in the process of aging out a front-end connection.
362584Internal directory permission settings could prevent a report from being copied from the ARX system.
362719A failure of the gsmd subsystem could occur on a successful LDAP query that returned 0 results.
363243Certain variants of Linux 2.6 can cause a crash on the ARX1500 and ARX2500 during NFS access.
363799The “constrained-directories below” share-farm option treated any number greater than 1 as 1 instead of the configured value.
