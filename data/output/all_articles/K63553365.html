K63553365: Loading configuration fails with ''there is no copy in trash-bin'' for APM customization cache path

Description

  • After upgrading BIG-IP version, loading configuration fails on the BIG-IP system with APM. 
  • In /var/log/ltm, you see the message similar to the following which points to the APM customization cache path:

    err mcpd[<PID>]: 01070712:3: Caught configuration exception (0), Failed: name (/<partition>/<access_profile_name>_<object>) Cache path (/config/filestore/files_d/<partition>_d/customization_group_d/:<partition>:<access_profile_name>_<object>) does not exist and there is no copy in trash-bin to restore from..
    err tmsh[<PID>]: 01420006:3: Loading configuration process failed.
    emerg load_config_files[<PID>]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: Failed: name (/<partition>/<APM_policy>_customization) Cache path (/config/filestore/files_d/<partition>_d/customization_group_d/:<partition>:<access_profile_name>_<object>) does not exist and there is no copy in trash-bin to restore from.
    err mcpd[<PID>]: 01070425:3: Full configuration load failed.

Environment

  • BIG-IP APM 13.1.x, 14.x
  • Performed BIG-IP version upgrade

Cause

  • APM customization cache path in the configuration file (bigip.conf) and the physical path under /config/filestore/files_d/<partition>_d/customization_group_d on the BIG-IP system do not match; therefore, the system is unable to load configuration
  • This is triggered by Bug ID 755475

Recommended Actions

Rename the physical path under the /config/filestore/files_d/<partition>_d/customization_group_d directory to match with the path appearing in the error message (which the path in the bigip.conf)

  1.  Log into the BIG-IP command line.
  2.  Go to /config/filestore/files_d/<partition>_d/customization_group_d directory.  For example;
     cd /config/filestore/files_d/Common_d/customization_group_d
     
  3.  List the path which contains the access profile name appearing in the error.  You will see the path with the same name but the last numeric digit (referred as "revision" number) is different. 

    For example, if the error is:
    Cache path (/config/filestore/files_d/Common_d/customization_group_d/:Common:test_profile_logon_page_12345_1) does not exist and there is no copy in trash-bin to restore,

    then running ls command with the access profile name:
    ls -l *test_profile*

    This will return the following where the revision number is different from the one in the error message.  For example;
    :Common:test_profile_logon_page_12345_2
     
  4.  Rename the physical path above to match with the revision number appearing in the error.  For example;
    mv \:Common:test_profile_logon_page_12345_2 \:Common:test_profile_logon_page_12345_1
     
  5. Try loading configuration by running the following command:
    tmsh load sys config

    The system should be able to load configuration without an error.

    Note:  There may be more than 1 customization path you may need to fix and rename.

Additional Information

'tmsh load sys config verify' command does NOT detect unmatched customization path.
