Topic

SSL session resumption allows a client and server to reuse previously negotiated SSL parameters. The ability to cache and reuse SSL Session IDs can increase the TPS by limiting processor-intensive SSL key exchange functions.

You can manage SSL session resumption on the BIG-IP system by modifying the client-side SSL profiles. For client-side SSL profiles, you can configure the SSL session cache timeout and size values, as well as view and clear SSL session cache entries. Each profile maintains a separate SSL session cache.

SSL Cache Size and Timeout settings

The Cache Size setting specifies the number of sessions in the SSL session cache. Configuring the Cache Size setting to 0 (zero) disables SSL session caching for the profile. The SSL session cache size limits the number of sessions that are cached for a particular profile. When the profile cache limit is reached, the oldest SSL session entry associated with that profile is evicted from the cache and the new SSL session is cached.

The total cache size of all active SSL profiles on a BIG-IP system is limited by the BIG-IP system's global SSL cache size. The BIG-IP system's global SSL cache size increased in 11.5.0 and later.

  • 11.5.0 and later

    The default Client SSL profile cache size is 262,144 per Traffic Management Microkernel (TMM), so if the limit is set to 262,144 entries, each TMM allows 262,144 entries.

    The BIG-IP system's global cache size limit is configurable from between 262,144 sessions to 4,194,304 sessions. For more information, refer to K16303: The BIG-IP global SSL session cache can be increased to 4,194,304 sessions.

  • 11.4.1 and earlier

    The default Client SSL profile cache size is 262,144 globally.

    The BIG-IP system's global cache size of 262,144 sessions per TMM. For more information, refer to K11170: The BIG-IP global SSL session cache size was increased to 262,144 sessions.

The Cache Timeout setting specifies the timeout value in seconds of the SSL session cache entries. The default cache timeout is 3,600 seconds.

Note: The cache entries are removed automatically when restarting TMM or reloading the configuration. The timeout of the cache entry is not refreshed when the client connects using the same session ID. When the timeout expires the entry is eligible for removal but may remain until the memory is reclaimed.

Modifying and viewing the SSL session cache

To modify and view the SSL session cache, perform the following procedures:

  • Modifying the SSL session cache size using the Configuration utility
  • Modifying the SSL session cache size using tmsh
  • Modifying the SSL session cache timeout using the Configuration utility
  • Modifying the SSL session cache timeout using tmsh
  • Viewing the SSL session cache size using the Configuration utility
  • Viewing the SSL session cache size using tmsh
  • Clearing the SSL session cache

Modifying the SSL session cache size using the Configuration utility

Impact of procedure: Updating a Client SSL profile clears the current SSL session cache entries, forcing remote clients to renegotiate SSL parameters.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the name of the Client SSL profile that you want to edit.
  4. For Configuration, select Advanced.
  5. For Cache Size, enter the value you want.
  6. Select Update.

Modifying the SSL session cache size using tmsh 

  1. Log in to the Advanced Shell (bash) as the root user.
  2. To list the current cache size for the Client SSL profile, use the following command syntax:

    tmsh list ltm profile client-ssl  <client_ssl_name> cache-size

  3. To update the new cache size, use the following command syntax:

    tmsh modify ltm profile client-ssl  <client_ssl_name> cache-size <value>

  4. Save the configuration change by entering the following command:

    tmsh save sys config

Modifying the SSL session cache timeout using the Configuration utility

Note: F5 does not recommend setting the cache timeout to indefinite because longer cache timeout periods can increase the risk of SSL session hijacking.

Impact of procedure: Updating a Client SSL profile clears the current SSL session cache entries, forcing remote clients to renegotiate SSL parameters.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the name of the Client SSL profile that you want to edit.
  4. For Configuration, select Advanced.
  5. For Cache Timeout, enter the value you want.
  6. Select Update.

Modifying the SSL session cache timeout using tmsh

  1. Log in to bash as the root user.
  2. To list the current cache timeout value for the Client SSL profile, use the following command syntax:

    tmsh list ltm profile client-ssl <client_ssl_name> cache-timeout

  3. To update the current cache size value for the Client SSL profile, use the following command syntax:

    tmsh modify ltm profile client-ssl <client_ssl_name> cache-timeout <new value>

  4. Save the configuration change by entering the following command:

    tmsh save sys config

Viewing the SSL session cache size using the Configuration utility

Note: Each Client SSL profile maintains a separate SSL session cache. To view a profile's SSL session cache size, first determine the name of the associated virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. From the Virtual Server List tab, select the name of the virtual server.
  4. Select the Statistics tab.
  5. Under Profiles, for Select Profile, select the associated Client SSL profile.
  6. Locate the Session Cache section to view the Current Entries.

Viewing the SSL session cache size using tmsh

  1. Log in to bash as the root user.
  2. Enter the following command:

    tmsh show ltm profile client-ssl test_ssl | grep 'Session Cache' -A 5

Clearing the SSL session cache

Impact of procedure: Updating a Client SSL profile clears the current SSL session cache entries, forcing remote clients to renegotiate SSL parameters.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the name of the Client SSL profile that you want to edit.
  4. Select Update.

Recommendations

When more than one SSL profile is configured without mutually exclusive session cache limits, contention in the shared global cache may cause entries for one virtual server to be evicted in favor of another even if fewer than the maximum configured for that profile are cached. To avoid this possibility, consider limiting the total combined configured session size for all SSL profiles to the value of the global session cache size. For example, if you have four SSL profiles in use on a single TMM BIG-IP running 10.1.0 or later, you may want to consider configuring the session Cache Size setting for each profile to 65,536 (25 percent of the global cache size of 262,144).

Note: Due to an issue where the BIG-IP system allocates the global SSL cache size based on per virtual, you may want to consider configuring the Cache Size setting for each profile to be per virtual. For information, refer to K13854: The BIG-IP system incorrectly allocates the SSL session cache size based on per virtual.
