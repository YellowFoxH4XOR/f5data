Known Issue

The BIG-IP system may attempt to send outbound emails unexpectedly.

This issue occurs when all of the following conditions are met:

  • The Simple Mail Transfer Protocol (SMTP) configuration on the BIG-IP system uses 'mail' (default setting) as the mail hub. The command and output of the SMTP mailhub entry may look similar to the following example:

    tmsh list sys outbound-smtp mailhub
    sys outbound-smtp {
        mailhub mail
    }

  • You configure a DNS server entry for name resolution on the BIG-IP system.
  • The mail hub entry (mail) gets resolved by the DNS server to an IP address which is a valid host on the network.
  • An email notification gets triggered (for example, by a scheduled cron job).

Impact

The BIG-IP system may send outbound email notifications unexpectedly.

Symptoms

As a result of this issue, you may encounter one of the following symptoms:

  • If the mail hub entry points to a valid email server on the network, you receive emails from your BIG-IP system unexpectedly.
  • In the /var/log/maillog file, you observe messages similar to the following example:

    Dec 10 03:25:24 BIG-IP err sSMTP[8421]: Unable to connect to "mail" port 25.
    Dec 10 03:25:24 BIG-IP err sSMTP[8421]: Cannot open mail:25

Workaround

To work around this issue, you can configure localhost as the mail hub entry to prevent any SMTP traffic from leaving the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will fail to send outbound emails using localhost as the mail hub. This will result in additional error messages logged to the /var/log/maillog file. For more information, refer to K09554025: The BIG-IP system logs repeated SSMTP configuration error messages.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To configure localhost as the mail hub entry, type the following command:

    modify /sys outbound-smtp mailhub localhost

  3. Save the change by typing the following command:

    save /sys config
