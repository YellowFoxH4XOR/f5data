Issue

Description

The BIG-IP system configuration may fail to load with the following error message while upgrading or experiencing a system reboot:

01070712:3: failed in syscall link(/config/filestore/files_d/Common_d/customization_group_d/:Common:TEST_VPN_vpn.test.com_secure_access_client_customization_32523_1, /config/filestore/.trash_bin_d/.current_d/Common_d/customization_group_d/:Common:TEST_VPN_vpn.test.com_secure_access_client_customization_32523_1) errno=(No such file or directory)
Unexpected Error: Loading configuration process failed.

Environment

  • BIG-IP upgrade or system reboot

Cause

This issue can occur during any of the following circumstances:

  • Objects in /config/bigip.conf are renamed.
  • File or directory is missing.
  • You have made modifications to an iApp deployment.

Recommended Actions

To work around the issue, you may follow either of the following procedures:

Note: Both procedures allow your configuration to load; however, the original configuration is not restored. You should perform a full configuration sync from a high availability pair (if available) after performing the procedures.

  • Commenting out all objects logged in the error message from configuration files
  • Restoring the deleted file by creating the directory and file

Commenting out or delete all objects logged in the error message from configuration files

Important: Performing this procedure will allow your configuration to load, however it will not restore the missing files.

  1. Make a backup of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.backupfile

  2. Search /config/bigip.conf for the configuration object in question and comment out or delete it from the configuration file.

    Note: By commenting out or deleting an object in the configuration file, references to the commented out or deleted object must be commented out or deleted as well.

    For example:

    # TEST_VPN_vpn.test.com_secure_access_client_customization_32523_1

  3. Verify the configuration by typing the following command:

    tmsh load sys config verify

  4. Load the configuration by typing the following command:

    tmsh load sys config

  5. You can revert back to the original configuration file at any time by typing the following command:

    cp /config/bigip.conf.backupfile /config/bigip.conf

Restoring the deleted file by creating the directory and file

Important: Performing this procedure allows your configuration to load; however, the files being staged are empty, and your configuration may not perform as expected.

  1. Create the missing directory by typing the following command:

    mkdir config/filestore/.trash_bin_d/.current_d/Common_d/customization_group_d/

  2. Create the missing file by typing the following command:

    touch /config/filestore/.trash_bin_d/.current_d/Common_d/customization_group_d/:Common:TEST_VPN_vpn.test.com_secure_access_client_customization_32523_1

  3. Verify the configuration by typing the following command:

    tmsh load sys config verify

  4. Load the configuration by typing the following command:

    tmsh load sys config

Additional Information

  • An error message logged in /var/log/ltm file or the TMOS Shell tmsh or Advanced shell (bash). The configuration does not load unless the changes are restored or any relevant objects are deleted.
  • You may also encounter this error when attempting to perform a ConfigSync.
