Description

After deploying the FAST template for Exchange, it is possible that the pool members may not come up.

Environment

  • BIG-IP LTM
  • Exchange FAST Templates

Cause

The default monitor that is deployed with the Exchange FAST template is created for HTTP/1.1 - However, Exchange 2019 uses HTTP/2.0 when utilizing concurrent session.
Due to this, the monitor will be marked down when the Exchange server returns an HTTP/2.0 response.

Recommended Actions

You can check this by sending a cURL to the Exchange server healthcheck and see if it returns a 'HTTP/2.0 200' response, if so update your monitors to HTTP/2.0
  1. Open a CLI to the BIG-IP
  2. Run the following curl command replacing the IP address
Example:  curl -vk https://server22.apmsupport.net/autodiscover/healthcheck.htm 
curl -vk https://<hostname or ip>/autodiscover/healthcheck.htm
If it returns a response such as the following, please update your monitors: 
* Connection state changed (MAX_CONCURRENT_STREAMS updated)!
< HTTP/2.0 200
< server:Microsoft-IIS/10.0
< x-powered-by:ASP.NET
< x-feserver:SERVER22
< date:Mon, 09 Oct 2023 15:50:14 GMT
< content-length:34

Additional Information

The Microsoft Exchange for BIG-IP FAST Template does not support Access Policy Manager (APM) configuration. In order to configure APM using the BIG-IP FAST Microsoft Exchange template, refer to the following information.
Before you begin, APM must be licensed and provisioned on the BIG-IP. See K12111: Provisioning licensed BIG-IP modules
F5 Microsoft Exchange deployment guide, beginning on page 98, has instructions and scenarios for configuring the BIG-IP APM module.
