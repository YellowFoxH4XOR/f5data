Overview of wildcard virtual servers

A standard virtual server typically represents a specific site and its IP address matches the IP address that DNS associates with the site's domain name. When BIG-IP receives a connection request for a defined site, BIG-IP recognizes that the client's destination IP address matches the IP address of the virtual server, and it subsequently forwards the client to one of the content servers that the virtual server load balances.

Wildcard virtual servers are a special type of virtual server designed to manage network traffic for transparent network devices, such as transparent firewalls, routers, proxy servers, or cache servers. A wildcard virtual server manages the network traffic with a destination IP address unknown to the BIG-IP, such as with transparent nodes.

For transparent nodes, the client's destination IP address is random. When load balancing transparent nodes, the BIG-IP cannot match the client's destination IP address to a virtual server IP address. Wildcard virtual servers resolve this problem by providing a generic IP address of 0.0.0.0 that the BIG-IP can use for address matching.

For example, when the BIG-IP does not find a virtual server match for a client's destination IP address, it matches the client's IP address to a wildcard virtual server. The BIG-IP then forwards the client to one of the firewalls or routers that the wildcard virtual server load balances, which in turn forwards the client to the actual destination IP address.

When you configure wildcard virtual servers and the nodes that they load balance, you can use a wildcard port (port 0) in the place of a real port number or service name. A wildcard port handles any and all types of network services.

A wildcard virtual server that uses port 0 is referred to as a default wildcard virtual server, and it handles traffic for all services. A port-specific wildcard virtual server handles traffic only for a particular service, and you define it using a service name or a port number. If you use a default wildcard virtual server and port-specific wildcard virtual servers, any traffic that does not match a standard virtual server or one of the port-specific wildcard virtual servers is handled by the default wildcard virtual server.

You can use port-specific wildcard virtual servers for tracking statistics for a particular type of network traffic, or for routing outgoing traffic, such as HTTP traffic, directly to a cache server rather than a firewall or router.

When you define transparent nodes that need to handle more than one type of service, such as a firewall or a router, we recommend that you define the node port number as 0.

Note: If you define a node with port 0 and want to perform a service check on that node, you must first configure service check intervals and timeouts using port 0. Then, you can configure a simple TCP service check. For more information about configuring service checks, refer to the BIG-IP Reference Guide.

Wildcard virtual server mappings

You can define the wildcard virtual server mapping using one of the following methods:

  • Configuration utility
  • Command line interface

Defining the wildcard virtual server mappings from the Configuration utility

To define a wildcard virtual server mapping using the Configuration utility perform the following steps:

  1. From the Configuration utility navigation pane, click Virtual Servers.
  2. In the Virtual Servers screen, click the Add button.

    The Add Virtual Server screen opens.

  3. In the Address box, type the wildcard IP address of 0.0.0.0.
  4. In the Service box, type the port number for the wildcard virtual server, or select a service from the drop-down menu.

    Note: For load balancing proxy servers, you can use port 0 to load balance all services. If you leave the box blank, the default is 0.

  5. Enter an optional netmask in the Netmask box and click Next.

    Note: Use the default netmask unless your configuration requires a different netmask. If you leave this box blank, the BIG-IP Controller generates a default broadcast address based on the IP address and netmask of this virtual server.

  6. From the Associate Wildcard VLAN drop-down menu, select the VLAN on which the wildcard server will be a member of and click Next.

    Note: If you want it to be part of all VLANs, leave the selection as All.

  7. From the Configure Basic Properties screen, uncheck the Enable Port Translation checkbox, and click Next.

    Note: For information about other optional properties, click the Help button.

  8. From the Select Physical Resources screen, choose the type of resource that will be used by the wildcard virtual server, and click Done.

    Note: This is usually a pool of proxy servers that you have configured beforehand.

Defining the wildcard virtual server mappings from the command line interface

To define a wildcard virtual server mapping using the command line interface, perform the following steps:

  1. Type the following command:
    bigpipe virtual 0.0.0.0:<port> use pool <pool_name>

    For example, the following command defines a wildcard virtual server that maps to a pool called firewall_pool, which contains three firewalls. Because the members are firewalls and need to handle a variety of services, both the virtual server and the nodes are defined using port 0.

    bigpipe vip 0.0.0.0:0 use pool firewall_pool

  2. Since you are sending information through a transparent device to another connection, configure the wildcard virtual server so that it does not translate port numbers, type the following command to modify the virtual server you created:

    bigpipe virtual 0.0.0.0:<port> use translate port disable

Destination address affinity/sticky persistence

You can optimize your proxy server array with destination address affinity (also called sticky persistence). Address affinity directs requests for a certain destination to the same proxy server, regardless of which client the request comes from.

This enhancement provides the maximum benefits when load balancing caching proxy servers. A caching proxy server intercepts web requests and returns a cached web page if it is available. In order to improve the efficiency of the cache on these proxies, it is necessary to send similar requests to the same proxy server repeatedly. You can use destination address affinity to cache a given web page on one proxy server instead of on every proxy server in an array. This saves the other proxies from having to duplicate the web page in their cache, wasting memory.

Important: To prevent sticky entries from clumping to one server, you must use a static load balancing mode, such as Round Robin.

You can only activate destination address affinity on pools referenced directly or indirectly by wildcard virtual servers.

You can activate the destination address affinity using one of the following methods:

  • Configuration utility
  • Command line interface

Configuring the destination address affinity from the Configuration utility

    To activate destination address affinity using the Configuration utility, perform the following steps:
    • From the Configuration utility navigation pane, click Pools.

      The Pools screen opens.

    • Click the pool you want to configure.

      The Pool Properties screen opens.

    • Click the Persistence tab at the top of the screen.

      The Pool Persistence screen opens.

    • Check the Destination Address Affinity Enable box to enable destination address affinity.
    • In Destination Address Affinity Mask box, type in the mask you want to apply to sticky persistence entries.
    • Click the Apply button.

      • Configuring destination address affinity from the command line

      To configure destination address affinity function from the command line, use the following commands:

      ActionCommand
      Display the status of sticky persistence and sticky mask for a specified pool

      bigpipe pool <pool_name> persist show

      Enable sticky persistence for a pool.

      bigpipe pool <pool_name> modify {persist_mode sticky}

      Disable sticky persistence for a pool.

      bigpipe pool <pool_name> modify {persist_mode none}

      List sticky persistence entries for the specified pool.

      bigpipe pool <pool_name> persist dump

      Delete sticky entries for the specified pool.

      bigpipe pool <pool_name> sticky clear

      Define the sticky mask for the pool.

      bigpipe pool <pool_name> modify {persist_mode sticky sticky_mask <mask>}

      Remove sticky mask for the pool

      bigpipe pool <pool_name> modify {persist_mode sticky sticky_mask none}
