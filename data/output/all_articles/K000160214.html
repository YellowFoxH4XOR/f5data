K000160214: Understanding Kerberos Authentication Requests from BIG-IP APM Self-IP to Active Directory

1. Description

Active Directory logs show Kerberos authentication ticket (TGT) requests from a BIG-IP APM self-IP address, including both successful authentications (Result Code: 0x0) and failed attempts with invalid usernames (Result Code: 0x6 - KDC_ERR_C_PRINCIPAL_UNKNOWN with NULL SID S-1-0-0).

2. Environment

  • BIG-IP APM (Access Policy Manager)
  • Kerberos Single Sign-On (SSO) and/or Kerberos Constrained Delegation configured in APM access policy
  • F5 self-IP communicating with Active Directory domain controllers
  • AD logs showing Kerberos authentication ticket (TGT) requests from the F5 self-IP
  • Occasional failed authentication attempts with invalid usernames (e.g., email addresses instead of domain usernames)

3. Cause

The observed Kerberos authentication requests from the F5 self-IP are expected behavior when BIG-IP APM is configured for Kerberos SSO or Constrained Delegation. Failed authentication attempts with Result Code: 0x6 and NULL SID are due to invalid usernames being submitted to the APM policy, not due to account enumeration or a security incident.

4. Answer/Recommended Actions

  • No changes are required on the F5 device; it is operating as designed.
  • Inform security monitoring or SOC teams that authentication traffic from the F5 self-IP to AD is expected and legitimate for Kerberos SSO/Constrained Delegation.
  • Review APM access logs to identify users or applications submitting invalid usernames and correct input formats as needed.
  • Verify APM access policy configuration, especially username parsing and logon page settings, to reduce invalid submissions.
  • Consider whitelisting the F5 self-IP in security monitoring tools to prevent false positive alerts.

5. Additional Information

  • Successful authentications (Result Code: 0x0) represent normal Kerberos SSO or Constrained Delegation traffic, where BIG-IP APM acts as a Kerberos client on behalf of users.
  • Failed authentications (Result Code: 0x6, NULL SID) are typically caused by user input errors or applications submitting incorrect username formats, not by malicious activity.
  • The presence of the krbtgt service, use of strong encryption, and successful result codes indicate a healthy Kerberos authentication flow.
