Known Issue

A memory leak may occur when the system uses compression hardware to perform compression functions.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is running on one of the following platforms:
    • BIG-IP 5000, 7000, 10000, or 12000 series platforms
    • VIPRION with B22xx blades
  • The BIG-IP system is configured with a virtual server that is associated with an HTTP compression profile.
  • The BIG-IP system is configured to use compression hardware to perform compression functions (by default).

Impact

Over time, the system runs out of memory due to memory leaks.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The memory usage on the affected BIG-IP system increases over time when the system performs compression functions.
  • The affected BIG-IP system repeatedly logs an error message similar to the following example before running out of memory:

    crit tmm[PID]: 01010025:2: Device error: n3-compress0 Nitrox 3, Hang Detected

Workaround

To work around this issue, you can configure the BIG-IP system to use software only when performing compression functions. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system's CPU usage may increase over time due to the additional processing performed by the Traffic Management Microkernel (TMM). The extent of the impact depends on the application environment. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Configure the BIG-IP system to use software compression by typing the following command:

    modify /sys db compression.strategy value softwareonly

  3. Save the change by typing the following command:

    save /sys config
