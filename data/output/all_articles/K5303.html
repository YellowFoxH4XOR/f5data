K5303: BIND attaches to every available self IP address when DNS proxying is configured

Known Issue

This is the result of a known issue. When you enable DNS proxying on BIG-IP, the BIND process attaches to every self IP address and every virtual server IP address. The BIND process is limited to 256 sockets.

If you have configured a large number of virtual servers, and those virtual server IP addresses numerically precede the self IP addresses, the BIND process may exhaust the number of sockets available before attaching to the self IP addresses. If the BIND process is not attached to the self IP addresses, it cannot receive DNS requests.

When this occurs, you will find the following error in the /var/log/messages file:

socket too high: 256

F5 Networks Product Development is tracking this issue as CR32963, and it is scheduled to be fixed in a future release. Monitor future BIG-IP Release Notes for the status of this CR.

Workaround

To work around this issue, restrict the interfaces available to BIND, by performing the following steps:

  1. Log in to the command line.
  2. Edit the /etc/named.conf file.
  3. Locate the section of the file that begins with the following text:

    options {

  4. Add a new line at the end of the Options section, by typing the following syntax:

    listen-on { <Self IP Address>; <Self IP Address>; ... };

    Include each self IP address that should receive DNS queries.

    For example:

    listen-on { 10.90.110.1; 10.90.111.1; 10.90.111.2; };

  5. Save the file and exit the editor.
  6. Restart the named utility, by typing the following command:

    bigstart restart named

BIND will now attach only to the self IP addresses you specified.
