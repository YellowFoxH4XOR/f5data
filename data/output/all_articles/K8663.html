Topic

To display the security tab on the properties page for a folder or file when using Microsoft Windows, you must enable the persistent Access-Control Lists (ACLs) feature on the ARX volume.

Important: The filers for all shares in the volume on the ARX must support persistent ACLs in order to enable persistent ACLs on the volume. For instructions about enabling persistent ACLs on your filer, refer to your vendor documentation.

To view the status of persistent ACLs for a volume, use the show namespace <namespace_name> command. The persistent ACLs setting is listed in the Volumes section, under the CIFS configuration for the volume.

The persistent ACLs feature is not enabled if the CIFS configuration indicates persistent ACLs: no.

Enabling persistent ACLs

To enable persistent ACLs for the volume by using either the ARX Manager GUI or the CLI, perform one of the following two procedures:

Enabling persistent ACLs using the ARX Manager GUI

  1. Log in to the ARX Manager.
  2. Click Managed Volumes.

    The Managed Volume Summary page is displayed.
  3. Select the check box for the desired volume.
  4. Click the Edit button.
  5. From the CIFS Characteristics section, select the persistent ACLs check box.
  6. Click the OK button.

Note: If any of the filers for the shares in the volume do not support persistent ACLs, an error message will display that appears similar to the following example:

CIFS_VOL_ATTRIB_UNSUPP: The CIFS share sroc2012 on the filer at 10.10.10.11 does not support the persistent-acls attribute.

Enabling persistent ACLs using the CLI

  1. Log in to the command line.
  2. Enable privileged mode by typing the following command:

    enable

    The prompt will appear similar to the following example:

    [hostname]
  3. Enter global mode by typing the following command:

    global

    The prompt will appear similar to the following example:

    [hostname](gbl)#
  4. Configure the namespace by typing the following command:

    namespace <namespace name>

    For example:

    namespace NS_CIFS

    The prompt will appear similar to the following example:

    [hostname](gbl-ns[NS_CIFS])#
  5. Configure the volume by typing the following command:

    volume <volume_name>

    For example:

    volume /volume1

    The prompt will appear similar to the following example:

    [hostname](gbl-ns-vol[NS_CIFS~/volume1])#
  6. Enable persistent ACLs by typing the following command:

    persistent-acls

    Note: If any of the filers for the shares in the volume do not support persistent ACLs, the command will fail with an error message that appears similar to the following example:

    % ERROR: CIFS_VOL_ATTRIB_UNSUPP (41353240):
    The CIFS share sroc2012 on the filer at 10.10.10.11 does not support the persistent-acls attribute.
  7. Exit configuration mode by typing the following command:

    end
  8. Verify the persistent ACLs setting for the volume by typing the following command:

    show namespace <namespace_name>

    The persistent ACLs setting is listed in the Volumes section, under the CIFS configuration for the volume. The persistent ACLs feature is enabled if the CIFS configuration indicates persistent ACLs: yes.
