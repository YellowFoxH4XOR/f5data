Description

You have configured LDAP Auth  with a CA Certificate

 

  • Remote LDAP Auth does not work as expected
  • If you do a tcpdump, you may see the following:-

    9   02:11:07.984271  10.xxx.xxx.134  10.xxx.xxx.161  TLSv1.2 451  OUT s1/tmm0 : Client Hello
    11  02:11:07.991019  10.xxx.xxx.161  10.xxx.xxx.134  TLSv1.2 610  IN  s1/tmm0 : Server Hello, Certificate, Server Key Exchange, Certificate Request, Server Hello Done
    14  02:11:07.993062  10.xxx.xxx.134  10.xxx.xxx.161  TLSv1.2 153  OUT s1/tmm0 : Alert (Level: Fatal, Description: Unknown CA)
    17  02:11:07.994318  10.xxx.xxx.161  10.xxx.xxx.134  TCP     134  IN  s1/tmm0 : 636 → 33260 [RST, ACK] Seq=1913 Ack=314 Win=0 Len=0

    The Certificate sent by the LDAP Server uses SHA256 Encryption
         algorithmIdentifier (sha256WithRSAEncryption)
     
  • You may see errors similar to the following in /var/log/secure
    May  6 18:34:21 bigip-11-01 err httpd[12973]: pam_ldap: reconnecting to LDAP server...
    May  6 18:34:21 bigip-11-01 err httpd[12973]: pam_ldap: ldap_simple_bind "Can't contact LDAP server".  A "Can't contact" error also happens when ssl handshakes go wrong.
    May  6 18:34:21 bigip-11-01 alert httpd[12973]: pam_unix(httpd:auth): check pass; user unknown
    May  6 18:34:21 bigip-11-01 notice httpd[12973]: pam_unix(httpd:auth): authentication failure; logname= uid=48 euid=48 tty= ruser= rhost=10.xxx.xxx.134

Environment

You have configured LDAP Remote Auth with CA

(tmos)# list auth ldap system-auth
auth ldap system-auth {
    bind-dn ******
    bind-pw ******
    port ldaps
    search-base-dn ******
    servers { ad1.xxxxxx.local }
    ssl enabled
    ssl-ca-cert-file XXXXXX-AD1-CA.crt
}

Cause

This may be caused by the fact that the Windows CA has been changed from SHA1 to SHA256

Recommended Actions

You need to export the Windows CA Certificate again, and use the new SHA256 Encrypted Certificate
