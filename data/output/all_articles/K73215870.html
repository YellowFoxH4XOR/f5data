At a glance–Recommendations

F5 has identified the following software update recommendations:

  • Subscribe to F5 TechNews and Security mailing lists.
  • Check for software updates.
  • Find the latest software.
  • Check for OPSWAT downloads.
  • Download and install updates to the IP geolocation database.
  • Check for BIG-IP Application Security Manager ASM and DPI signatures.

Background

This section provides context for our recommended procedures in the form of overviews and supplemental information.

In BIG-IP 11.5.0 and later, F5 the Automatic Update Check (phone home) feature is enabled by default.

If your device has access to the F5 software download servers using the internet, this feature automatically checks for BIG-IP software updates on a weekly basis and lists the updates in the Configuration utility, including relevant links.

If you use this feature, you do not have to check for the latest software updates manually. For more information refer to: K15000 Using the Automatic Update Check and Automatic Phone Home features.

In addition to updates to the BIG-IP operating software, F5 provides additional updates for features like the IP Geolocation database, OPSWAT, and BIG-IP ASM security updates. Updates for these features are managed separately from the core BIG-IP updates. F5 recommends that administrators keep these features updated to ensure your BIG-IP system has current information and protection against the latest security threats.

Note: You can only perform major software upgrades if the BIG-IP system is entitled under a current Support contract. For more information about entitlement, refer to K93101019: BIG-IP TMOS operations guide | Chapter 8: Licenses and entitlement.

Procedures

This section details how to complete the following software update tasks:

Getting security updates

F5 recommends regular and timely acquisition of F5 security updates, BIG-IP ASM attack signature updates, and OPSWAT updates.

When F5 discovers remote vulnerabilities, F5 implements, tests, and releases security hotfixes for any vulnerable, supported version and sends an email alert to the F5 Security mailing list. F5 encourages customers with an active support account to subscribe to this list. For more information, refer to K4602: Overview of the F5 security vulnerability response policy.

Signing up for security updates

  1. Go to the Customer Preference Center.
  2. Select the types of communications you want to manage.
  3. Enter your contact information.
  4. Select the types of communications you want to receive.
  5. Select Submit.

Subscribing to TechNews

The Customer Preference Center provides email publications to help keep administrators up-to-date on various F5 updates and other offerings:

  • TechNews Weekly: Up-to-date information about product and hotfix releases, new and updated articles, and new features.
  • TechNews Notifications: Brief notifications about special F5 documentation and F5 software releases.

Subscribing to updates

  1. Go to the Customer Preference Center.
  2. Select the option to change your marketing email preferences.
  3. To opt in, complete the fields with your information .
  4. Select the subscriptions you want to receive.
  5. Select Submit.

MyF5 recent additions and updates

You can subscribe to F5 RSS feeds to stay informed about new documents pertaining to your installed products or products of interest. The Recent additions and updates page on MyF5 provides an overview of all the documents recently added to MyF5.

New and updated articles are published over RSS. You can configure feeds that pertain to specific products, product versions, and/or document sets. You can also aggregate multiple feeds into your RSS reader to display one unified list of all selected documents. 

For more information, refer to K9957: Creating a custom RSS feed to view new and updated documents.

Finding the latest software

Release notes for the version of software you want to install contain instructions for the specific installation.

Finding the latest software version for your F5 product

  1. Go to F5 Downloads.
  2. Select Find a Download.
  3. Find the product you want to download and select the link for the appropriate version.
  4. Find and select the link for the update you want to download.
  5. Read and accept the End User Software license agreement.
  6. Select the file name, choose a download location, and then save the file to your computer.

Before upgrading your BIG-IP software

Before you upgrade your BIG-IP software, review the BIG-IP upgrade guide for step-by-step guidance on how to prepare for the upgrade, including how to choose which BIG-IP version to upgrade to.

Updating OPSWAT packages for BIG-IP Access Policy Manager

The BIG-IP Access Policy Manager (APM) antivirus and firewall client-side checks use software libraries from a software development kit (SDK) created by OPSWAT, Inc. OPSWAT periodically issues new versions of the SDK libraries to support new security products and resolve bugs in the software. F5 distributes these updates in the form of hotfixes.

Viewing OPSWAT version information using the Configuration utility (BIG-IP 11.2.1 and later)

  1. Go to System > Software Management.
  2. Hover on the Antivirus Check Updates tab and select Device EPSEC Status.
  3. For Local Device/Device Group, select the local device or a device group you want to check.

Viewing OPSWAT version information using the TMOS Shell (tmsh) at the command line

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Display the version by entering the following command:

    show apm epsec software-status

    Output appears similar to the following example:

    +---------------------------------------------------------------------------------+
    | Epsec:: Software Device OESIS Previous Previous Status Version OESIS Version Installed OESIS version Installed Version
    +----------------------------------------------------------------------------------+
    | /common/ 1.0.0-192.0 3.6.5595.2 1.0.0-192.0 3.6.5595.2 success | bigip1121.test.lab
    +-----------------------------------------------------------------------------------+

Viewing the OPSWAT version information at the command line

  • Enter the following command:

    epsec version

    Output appears similar to the following example:

    Version: 1.0.0-160.
    0SDK Version: 3.5.2461.2
    Installation Date: Thu Dec 6 16:25:57 PST 2012
    #APM Endpoint Inspection Plugin for Linux
    #APM Endpoint Inspection Plugin for Mac OS X
    #APM Endpoint Inspection Libraries for Windows

Viewing available OPSWAT versions at the command line

  • Enter the following command:

    epsec list

    Output appears similar to the following example:

    No updated endpoint security packages available.
    Package: epsec-1.0.0-283.0.iso(installed)
    Version:1.0.0-283.0
    SDK Version:3.6.8392.2

Installing an OPSWAT hotfix from the Configuration utility (BIG-IP APM 11.2.1 and later)

  1. Download the OPSWAT hotfix from F5 Downloads.

    Note: For instructions about how to obtain a hotfix, refer to K000090258: Download F5 products from MyF5.

  2. Log in to the BIG-IP Configuration utility.
  3. Go to System > Software Management.
  4. Hover on the Antivirus Check Updates tab and select Package Status.
  5. Select Upload Package.
  6. Select Browse.
  7. Select the hotfix file you downloaded.
  8. For Install Option, select the appropriate installation option.

    Note: The Do Not Install option uploads the EPSEC package without installing it.

  9. If you selected the Install on Autosync enabled Device Group check box for Device Group, select the device group.
  10. Select Upload.
  11. After the software uploads, select OK.

    Note: The upload process may take a couple of minutes.

    BIG-IP Access Policy Manager (APM) is now running the OPSWAT package.

  12. To confirm that the installation was successful, review Installed Version on the Device EPSEC Status tab.

Installing an OPSWAT hotfix using tmsh (BIG-IP APM 11.0 and later)

  1. Download the OPSWAT hotfix from the F5 Downloads page.

    Note: For instructions about obtaining a hotfix, refer to K000090258: Download F5 products from MyF5.

  2. Use a secure copy (SCP) utility to copy the file you downloaded in step 1 to the /shared/apm/images folder.
  3. Log in to tmsh by entering the following command:

    tmsh

  4. Create a new package by entering the following command syntax:

    create apm epsec epsec-package <package name> local-path <path/filename>

    Note: Replace <package name> with the name the BIG-IP system uses to identify the package and <path/filename> with the path and name of the EPSEC file copied to the BIG-IP device.

    For example:

    create apm epsec epsec-package epsec-1.0.0- 196.0.iso local-path /shared/apm/images/epsec- 1.0.0-196.0.iso

    Note: When you use the Configuration utility to perform this procedure, the BIG-IP system uses the file name as the package name by default. You may rename the package.

  5. Install the new package by using the following command syntax:

    install apm epsec epsec-package <package name>

    Note: Replace <package name> with the name of the package you created in the previous step.

    For example:

    install apm epsec epsec-package epsec-1.0.0- 196.0.iso

  6. To validate the package was installed, enter the following command:

    show apm epsec software-status

Downloading and installing updates to the IP geolocation database

The BIG-IP system uses an IP geolocation database to source data about the origin of a name resolution request. The default database provides geolocation data for IPv4 addresses at the continent, country, state, ISP, and organization levels. The state-level data is worldwide, and thus includes designations in other countries that correspond to the U.S. state-level in the geolocation hierarchy, for example, provinces in Canada.

Note: You can only access the ISP and organization-level geolocation data for IPv4 addresses using the iRules where is command. For more information, about iRules, search DevCentral.

The default database also provides geolocation data for IPv6 addresses at the continent and country levels.

Note: If you require geolocation data at the city-level, contact your F5 sales representative to purchase additional database files.

You can download a monthly update to the IP geolocation database from F5. For more information, refer to K11176: Downloading and installing updates to the IP geolocation database.

Downloading and installing an update to the IP geolocation database

  1. Go to F5 Downloads.
  2. Select Find a Download.
  3. Under Product Line, select the appropriate BIG-IP software branch (for example, BIG-IP 11.x).
  4. Select your BIG-IP version.
  5. Select GeoLocationUpdates.
  6. Read and accept the license agreement.
  7. Select the ip-geolocation zip file.
  8. Choose a download location.
  9. Save the file to your computer.

Installing the geolocation database update at the command line

  1. Copy the ip-geolocation zip and MD5 files you downloaded from F5 Downloads to the /shared/tmp directory on the BIG-IP system.
  2. Log in to the command line.
  3. Change the working directory to the /shared/tmp directory by entering the following command:

    cd /shared/tmp

  4. Open and extract the RPM files by entering the following command syntax:

    unzip </path/to/zipfile>

    Note: Replace </path/to/zipfile> with the path to the zip file on the BIG-IP system:

    For example:

    unzip /shared/tmp/ip-geolocation-1.0.1- 20140627.30.0.zip

    The output appears similar to the following example:

    Archive: ip-geolocation-1.0.1-20140627.30.0.zip
    inflating: geoip-data-Region2-1.01.- 20140627.30.0.i686.rpm
    inflating: geoip-data-ISP-2.0.1-20140627.30.0.i686.rpm
    inflating: geoip-data-Org-1.0.1-20140627.30.0.i686 rpm

  5. For each RPM file you extracted, Enter the following command syntax:

    geoip_update_data -f </path/to/rpm>

    Note: Replace </path/to/rpm> with the path to the RPM file.

    For example:

    # geoip_update_data -f /shared/tmp/geoip-data- Org-1.0.1-20120627.30.0.i686.rpm

    The BIG-IP system installs and loads the specified database file.

  6. Verify that the geolocation database was loaded with a geoip_lookup command to query the database. For example, the following command syntax queries one of the database files for a specific IP address:

    geoip_lookup -f <path/to/db/files> IP

    For example:

    # geoip_lookup -f /shared/GeoIP/F5GeoIPOrg.dat 65.61.115.197

    The output appears similar to the following example:

    opening database in /shared/GeoIP/F5GeoIPOrg.dat
    size of geoip database = 180356873, version = GEO-146 20120627
    Build 1 Copyright (c) F5 Networks Inc All Rights Reserved
    geoip_seek = 014f0ad1
    geoip record ip = 65.61.115.197 name = f5 networks

For information about transferring files to the F5 system, refer to K175: Transferring files to or from an F5 system.

Fixing issues with incorrect IP geolocation installations

If you install the IP geolocation database files incorrectly, the incorrect installation might change the SELinux security context for the database files.

The BIG-IP system uses an IP geolocation database to determine the origin of an IP address. F5 releases the updates to the database in the GeoLocationUpdates container on F5 Downloads. When installing or updating the IP geolocation database files, you should upload the IP geolocation ZIP archive file to the /shared/tmp directory on the BIG-IP system.

When you extract the database files, the BIG-IP access control mechanism (SELinux) applies the appropriate security context to the database files, and the system installs the files to the /shared/GeoIP directory.

If you upload the IP geolocation ZIP archive file to a different directory on the BIG-IP system (for example, /root/) and then extract the database files, the SELinux module may apply the incorrect security context to the files. When this occurs, the system may fail to load the IP geolocation database properly.

Restoring the proper security context to the IP geolocation database files

To restore property security context to the IP geolocation database files, you need to compare the inode numbers to verify that the Traffic Management Microkernel (TMM) and gtmd processes have loaded the correct database files.

Comparing inode numbers at the command line

  • Enter the following command syntax:

    ls -i /shared/GeoIP/F5GeoIPISP.dat ; lsof 2>/dev/null | grep F5GeoIP

    Note: If the /shared/GeoIP directory is empty, review and perform the steps in the section Installing the geolocation database update at the command line again.

    If the gtmd (1376259) and TMM (80575) inode numbers do not match for the F5GeoIPISP.dat database file, the output appears similar to the following example:

    1376259 /shared/GeoIP/F5GeoIPISP.dat
    gtmd 5871 root mem REG 9,0 66127452
    966660 /shared/GeoIP/F5GeoIPRegion2.dat
    gtmd 5871 root mem REG 9,0 567630 3915778
    /shared/GeoIP/F5GeoIPv6.dat
    gtmd 5871 root mem REG 9,0 194864440
    966658 /shared/GeoIP/F5GeoIPOrg.dat
    gtmd 5871 root mem REG 9,0 5373413
    1376259 /shared/GeoIP/F5GeoIPISP.dat
    tmm10612 root mem REG 9,0 66127452
    /shared/GeoIP/F5GeoIPRegion2.dat
    966660
    tmm10612 root mem REG 9,0 567630
    /shared/GeoIP/F5GeoIPv6.dat
    3915778
    tmm10612 root mem REG 9,0 194864440
    966658/shared/GeoIP/F5GeoIPOrg.dat
    tmm10612 root mem REG 9,4 3993525 80575
    /usr/share/GeoIP/F5GeoIPISP.dat

    Note: In this case, TMM has loaded the incorrect database file from /usr/share/GeoIP/F5GeoIPISP.dat.

Verifying the security context of the database files in the /shared/GeoIP directory at the command line

  • Enter the following command:

    ls -Z /shared/GeoIP/

    Note: If the /shared/GeoIP directory is empty, review and perform the steps in Installing the geolocation database update at the command line again.

    If the security context for the F5GeoIPISP.dat file is root:object_r:default_t, which is preventing the system from properly loading the IP geolocation database, the following output appears similar to the following example:

    lrwxrwxrwx root root:object_r:shared_geoip_t F5GeoIP.dat -> /shared/GeoIP/F5GeoIPRegion2.dat
    -rw-r--r-- root root:object_r:default_t F5GeoIPISP.dat
    -rw-r--r-- root system_u:object_r:shared_geoip_t F5GeoIPOrg.dat
    -rw-r--r-- root system_u:object_r:shared_geoip_t F5GeoIPRegion2.dat
    -rw-r--r-- root system_u:object_r:shared_geoip_t F5GeoIPv6.dat

Restoring the proper SELinux security context to the geolocation database files

  • Enter the following command:

    restorecon -Rv /shared/GeoIP/ ; tmsh load sys geoip
