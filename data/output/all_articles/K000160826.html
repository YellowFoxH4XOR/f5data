K000160826: Traffic Not Fully Forwarded to Intended Pool After Applying New LTM Policy on BIG-IP LTM

Description

After applying a new Local Traffic Manager (LTM) policy on BIG-IP LTM to forward HTTP traffic for a specific host to a designated pool, some traffic continues to be forwarded to the default pool. Requests for the specified host are distributed across both the intended and default pools, rather than exclusively to the target pool. Symptoms include intermittent traffic sent to both pools and packet captures showing connections forwarded to the default pool after the policy is applied. The issue persists until existing connections are cleared.

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • Virtual server configured for HTTP/HTTPS traffic
  • New LTM policy created to forward traffic for a specific HTTP host to a designated pool
  • Default pool configured for the virtual server

Cause

From the packet captures, the failing connections show no client-side connection initialization. These appear to be long-lived connections that are still operating based on the previous configuration. Long-lived or persistent connections established before the new LTM policy was applied are not re-evaluated for the updated policy. These connections continue to use the default pool, causing traffic to be forwarded incorrectly until the connections are cleared.

Answer/Recommended Actions

To ensure the new LTM policy is enforced for all traffic:

  1. Delete all existing connections to the affected virtual server after applying the new LTM policy:
    tmsh delete /sys connection cs-server-addr <VS_IP> cs-server-port <VS_Port>
    Replace <VS_IP> and <VS_Port> with the virtual server's IP address and port.
  2. Validate traffic flow after clearing connections to confirm correct pool selection.
  3. For future policy changes, schedule connection clearing during maintenance windows to minimize impact on active sessions.

Additional Information

This behavior is expected when persistent or long-lived connections exist prior to policy changes. Clearing connections ensures all new traffic is evaluated against the updated policy.
