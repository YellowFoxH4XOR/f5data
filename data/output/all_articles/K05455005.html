K05455005: Disable ssl-static-key-ciphers on BIG-IP GUI

Type
Support Solution
Published
2021-06-23
Updated
2025-04-01
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K05455005

Description

Vulnerability scanner has detected ssl-static-key-ciphers being used on the BIG-IP Configuration utility.

This article explains how to disable ssl-static-key-ciphers for the BIG-IP Configuration utility.

Environment

  • BIG-IP
  • Disable ssl-static-key-ciphers on BIG-IP Configuration utility

Cause

ssl-static-key-ciphers more likely is that the key exchange is not ephemeral, DHE and ECDHE would be the key exchanges you might be looking for to enable ephemeral key exchange. Allowing only ephemeral key exchange is typically one of the requirements that enable Perfect Forward Secrecy (PFS).

In a TLS connection where (EC)DHE is not used, the key is exchanged using RSA, so the same symmetric key is used for the entire connection.

In summary to disable ssl-static-key-ciphers, you will need to remove RSA from the httpd configuration.

Recommended Actions

To disable ssl-static-key-ciphers, you will need to add !RSA to the httpd configuration.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To list the currently configured SSL ciphers, type the following command:

    list /sys httpd ssl-ciphersuite

    For example, the BIG-IP 14.1.0 system displays the following ciphers:

    ssl-ciphersuite ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-SHA:ECDHE-RSA-AES128-SHA256:ECDHE-RSA-AES256-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-SHA:ECDHE-ECDSA-AES256-SHA:ECDHE-ECDSA-AES128-SHA256:ECDHE-ECDSA-AES256-SHA384:AES128-GCM-SHA256:AES256-GCM-SHA384:AES128-SHA:AES256-SHA:AES128-SHA256:AES256-SHA256

  3. You can either specify the ciphers you wish to use and omit any ciphers you do not want enabled to remove ssl-static-key-ciphers. In this case, you would want to omit the following ciphers:

    AES128-GCM-SHA256:AES256-GCM-SHA384:AES128-SHA:AES256-SHA:AES128-SHA256:AES256-SHA256

    Alternatively, you may append :!RSA to your SSL cipher suites configuration to achieve similar effect.

  4. To change the SSL ciphers allowed in Configuration utility, type the following command:

    modify /sys httpd ssl-ciphersuite "<allowed ciphers>"

    For example:

    modify /sys httpd ssl-ciphersuite "ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-SHA:ECDHE-RSA-AES128-SHA256:ECDHE-RSA-AES256-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-SHA:ECDHE-ECDSA-AES256-SHA:ECDHE-ECDSA-AES128-SHA256:ECDHE-ECDSA-AES256-SHA384"

  5. Save the configuration change by typing the following command:

    save /sys config

Additional Information

If you are looking to enhance the SSL profile for your Standard virtual server, you can perform similar configuration on the clientSSL profile by ensuring ECDHE and/or DHE ciphers are prioritized while disabling RSA key exchanges. In BIG-IP 13.1.x and later, you can do so by adding :!RSA to the default cipher of the associated clientSSL profile. For detailed information about configuring cipher strength for your SSL profile, refer to K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x). For information about configuration requirements for SSL virtual servers, refer to K12015: Configuration requirements for SSL virtual servers, profiles, pools, and monitors.
