Known Issue

In rare situations, the BIG-IP ASM correlation process may enter a restart loop.

This issue occurs when one of the following conditions is met:

  • The BIG-IP ASM watchdog restarts the correlation process.
  • You manually restart the BIG-IP ASM system.

Impact

The Configuration utility Events Correlation page is not updated with new events.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/asm log file, you notice an error message similar to the following example:

    ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: correlation, Failure: Insufficient number of threads (required: 1, found: 0).

  • In the /var/log/ltm log file, you notice an error message similar to the following example:

    err correlation[1234]: 01560000:3: An instance with pid 5678 is already running

Workaround

To work around this issue, you can modify the asm_processes.yaml file and restart the BIG-IP ASM system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure forces the BIG-IP system offline for a short period of time. F5 recommends that you perform this procedure during a maintenance window.

  1. Log in to the Advanced Shell (bash) using the root account.
  2. Create a backup of the /usr/share/ts/config/asm_processes.yaml file by typing the following command:

    cp /usr/share/ts/config/asm_processes.yaml /usr/share/ts/config/asm_processes.yaml.orig

  3. Patch the YAML file by typing the following command:

    Note: The space characters in this command are significant. F5 recommends that you cut and paste the text.

    perl -pi -e 's/correlation:/correlation:\n    pid_file: \/shared\/tmp\/correlation.pid/' /usr/share/ts/config/asm_processes.yaml

  4. Display the differences between the original file and the patched file by typing the following command:

    diff -C 1 /usr/share/ts/config/asm_processes.yaml.orig /usr/share/ts/config/asm_processes.yaml

  5. Verify that the diff output generated in step 4 is exactly as follows:

    Note: Space characters are significant and time stamps will differ.

    *** /usr/share/ts/config/asm_processes.yaml.orig    2015-11-09 10:12:06.000000000 -0500
    --- /usr/share/ts/config/asm_processes.yaml    2015-11-09 10:12:14.000000000 -0500
    ***************
    *** 33,34 ****

    --- 33,35 ----
    correlation:
    +     pid_file: /shared/tmp/correlation.pid

    exec_method: system

  6. Restart the BIG-IP ASM system by typing the following command:

    Note: This step forces the BIG-IP system offline.

    bigstart restart asm

  7. Verify that the BIG-IP system is active and that the corresponding log files do not contain error messages similar to the following examples:
    • The /var/log/asm file:

      ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: correlation, Failure: Insufficient number of threads (required: 1, found: 0).

    • The /var/log/ltm file:

      An instance with pid xxxx is already running

  8. Optional: To reverse the workaround, type the following commands:

    mv /usr/share/ts/config/asm_processes.yaml.orig /usr/share/ts/config/asm_processes.yaml

    bigstart restart asm
