Multicast traffic overview

Multicast traffic allows a packet to be sent to a subset of hosts, as opposed to unicast, where a packet is sent to a single host, or broadcast, where a packet is sent to all hosts.

In a multicasting environment, a single stream of data is sent by the multicast source to the routers and Ethernet switches, and only recipients who have advertised an interest in receiving the information in the stream will receive it. The routers in the path between the source and the receivers replicate the multicast data and send it on. By limiting traffic to only those hosts that express interest, multicasting can reduce network bandwidth consumption and host processing.

For multicast routing to work across an internetwork, all intervening routers must have implemented appropriate multicast routing protocols that populate the Multicast Routing Information Base (MRIB) and propagate multicast frames according to the information in the MRIB.

Multicasting takes place on two separate network layers, in some cases simultaneously: Layer 3 (L3) multicasting allows multicast communication across internetworks, while Layer 2 (L2) multicasting takes place on the local network segment. Although there are a number of common variations, typical multicast addressing uses a unicast source MAC address, a unicast source IP address, a multicast destination MAC address and a multicast destination IP address which maps to multiple recipients.

Note: For a full description of the multicast routing architectures currently deployed on the Internet, refer to the following document:

RFC 5110: Overview of the Internet Multicast Routing Architecture

L2 multicast addressing

An Ethernet multicast address consists of the multicast bit (bit 0 of the first octet), the 23-bit vendor component, and the 24-bit group identifier assigned by the vendor.

According to the IEEE 802.3 standards specification, a multicast MAC address should be used only as the destination of a datagram, never the source.

L3 multicast addressing

IP multicast uses the Class D address range (224.0.0.0 through 239.255.255.255).

224.0.0.0 - 224.0.0.255 : Reserved link local addresses

224.0.1.0 - 238.255.255.255: Globally scoped addresses
232.0.0.0 - 232.255.255.255: Source Specific multicast addresses
233.0.0.0 - 233.255.255.255: GLOB addresses
239.0.0.0 - 239.255.255.255: Administratively (locally) scoped addresses

An IP multicast address represents a group of IP devices (sometimes called a host group). An IP multicast address may be used only as the destination of a datagram, never the source.

L2 multicast (multicast bridging)

Multicast bridging refers to the propagation of multicast frames on the local network. L2-only switches handle L2 multicast traffic as if it were L2 broadcast traffic, flooding the frames to all active interfaces in the same VLAN. L2/L3 hybrid switches typically implement IGMP snooping to monitor multicast group membership messages and selectively forward multicast frames to only those interfaces through which multicast group join messages have been seen.

Protocols such as OSPF, HSRP, and VRRP rely upon L2 multicast bridging (as do many firewalls and other redundant network devices) to ensure full mesh communication with related devices in the local network.

BIG-IP LTM as a multicast bridge

By default, LTM functions as an L2-only switch, flooding frames addressed to L2 multicast addresses across all interfaces in the VLAN except the origin. Some customization of this behavior is possible to support specific L2 multicast traffic management requirements.

Note: Beginning in BIG-IP 10.0.0, you may have to enable db variable TM.AllowMulticastL2DestinationTraffic for the BIG-IP system to monitor FTP service that resides on a host with L2 multicast address. For more information, refer to K13113: Change in Behavior: The TM.AllowMulticastL2DestinationTraffic db key must be enabled on the BIG-IP system to monitor FTP service on a host with Layer 2 multicast addressing

Multicast traffic and Auto Lasthop

The BIG-IP LTM system’s Lasthop feature will use the MAC address from the Ethernet header as the destination MAC for response traffic even if the sender specified a multicast response address in the payload, which may prevent all intended recipients from receiving the response. Disable Auto Lasthop if it interferes with L2 multicast response forwarding in this manner.

Accepting frames with L2 multicast source address

Although frames with L2 multicast source addresses do not conform to the IEEE 802.3 standard, some redundant or clustered devices are known to send them. Beginning in BIG-IP LTM 9.0.5, you can configure The BIG-IP LTM system to accept frames sourced from multicast or broadcast MAC addresses by setting the tm.allowethernetsourcetype db variable to either unicast-multicast or any.

The tm.allowethernetsourcetype db variable accepts the following values:

ValueDescription
unicastOnly frames with unicast source MAC addresses are processed by the BIG-IP system (default value).
unicast-multicastOnly frames with unicast or multicast source MAC addresses are processed by the BIG-IP system.
any Frames with any type of source MAC address (including broadcast source MAC addresses) are processed by the BIG-IP system.

Multicast traffic and VLAN groups

When multicast traffic must traverse a VLAN group, some modification of the default BIG-IP LTM configuration may be required to support the intended traffic flow.

The tm.allowmulticastl2destinationtraffic db variable may be enabled on the BIG-IP system, forcing the BIG-IP system to flood frames addressed to L2 multicast addresses across all interfaces in all VLANs in the VLAN group, except the origin.

This setting is required to support any multicast traffic across a VLAN group, including multicast responses to unicast requests. For example, an ARP request may be constructed using a unicast L2 source address in the Ethernet header but advertising a multicast target MAC address in the payload. The target MAC address in the payload is used as the destination for the response, resulting in a multicast response to a unicast request. Without tm.allowmulticastl2destinationtraffic enabled, the response will not be bridged across the VLAN group. Enabling this variable allows the BIG-IP LTM system to bridge the responses that use the advertised multicast address as the destination across the VLAN group.

L3 multicast (multicast forwarding & routing)

Multicast forwarding refers to the intelligent forwarding of multicast datagrams to other networks. In multicast forwarding, a router forwards L3 multicast traffic to other networks where multicast nodes are listening, and prevents the forwarding of multicast traffic to networks where there are no nodes listening. For multicast forwarding to work across an internetwork, the participating nodes and all intervening routers must be multicast-capable.

Multicast routing refers to the propagation of multicast group listening information to other multicast routers to create loop free data paths only to interested subscribers. In multicast routing, a router propagates relevant multicast subscription information to other multicast routers, adding and deleting multicast group memberships as requested by way of the established multicast routing protocol (that is: PIM, IGMP).

BIG-IP LTM as a multicast router

A multicast-capable router must be able to perform both forwarding and routing functions as follows:

  • Listen for all multicast IP datagrams on all attached networks, and then upon receiving a multicast datagram, forward it to attached networks with listening nodes and to downstream routers with listening nodes.
  • Listen for group membership messages and update the IP multicast forwarding table.
  • Use a multicast routing protocol to propagate multicast group listening information to other multicast-capable routers.

Beginning in BIG-IP 12.0.0, the BIG-IP system supports both PIM-DM and IGMP for multicast routing. BIG-IP 12.1.0 adds support for PIM-SM and PIM-SMDM; however, the new feature does not support BIG-IP systems in the role of a rendezvous point for PIM-SM. The Multicast routing feature can be implemented with a dynamic routing bundle license and a multicast routing bundle license using the BIG-IP Advanced Routing Module. In versions previous to BIG-IP 12.0.0, the BIG-IP system lacks the multicast routing protocol implementation required to selectively forward multicast IP datagrams or to exchange group membership information with other multicast routers, and thus may not be considered a multicast router.

With the new protocol support for multicast routing, you can configure BIG-IP LTM to forward multicast traffic with a wildcard forwarding virtual server. In versions previous to BIG-IP 12.0.0, the BIG-IP system does not support forwarding multicast traffic through virtual server or SNAT/NAT objects.

BIG-IP LTM as a multicast node

The term multicast node refers to devices capable of managing their own participation in multicast routing by way of multicast-enabled hardware.

A multicast-capable node must be able to:

  • Send and receive multicast IP datagrams
  • Register the multicast IP addresses being listened to by the node with local routers, so that multicast IP datagrams can be forwarded to the network of the node. (IP nodes use multicast routing protocols such as Internet Group Management Protocol (IGMP) to notify local routers that they are listening on a specific IP multicast address for IP multicast traffic.)

The BIG-IP LTM system is capable of sending and receiving multicast IP datagrams, but it lacks the IGMP implementation required to register group membership with local multicast routers, and thus should not be considered a multicast node.
