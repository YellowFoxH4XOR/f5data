K000139552: flannel container isn't running anymore

Description

You have configured BIG-IP Virtual Machine or BIG-IP Next Instances or both on rSeries F5OS-A 1.7.0
However K3S events logs shows that flannel container isn't running anymore.

The following errors may be observed in K3S event logs and system logs:

Warning REASON: FailedMount LOG: MountVolume.SetUp failed for volume "flannel-cfg" : configmap "kube-flannel-cfg" not found

MountVolume.SetUp failed for volume "kube-api-access-<id>" : failed to fetch token: serviceaccounts "flannel" not found

ERROR: Failed to install CNI plugin. CNI="Flannel upgrade check failed:" ERROR=256

This resulting in networking issues for virtual machines and containers.

Environment

  • rSeries
  • F5OS-A 1.7.0
  • K3S Cluster
  • Flannel Container

Cause

This issue is caused by Bug ID 1576141. During K3S installation or upgrade, if `/var/log/appliance.log`` exists as a directory instead of a regular file, the flannel CNI plugin installation fails. This results in repeated uninstall/install attempts of Flannel, preventing creation of required resources such as configmaps and service accounts.

Recommended Actions

Delete /var/log/appliance.log directory and create it as a file.

Check if `/var/log/appliance.log`` is a directory:
ls -ld /var/log/appliance.log

2. If it is a directory, delete it:
rm -rf /var/log/appliance.log

3. Recreate `/var/log/appliance.log`` as an empty regular file:
touch /var/log/appliance.log

4. Reinstall or restart K3S so that the flannel CNI plugin can install correctly.

5. Verify that the flannel daemonset and pods are running:

kubectl get ds -A
kubectl get pods -A

6. Confirm that the necessary configmaps and service accounts related to flannel exist in the namespace.

kube-system
