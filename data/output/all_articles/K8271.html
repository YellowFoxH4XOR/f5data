Known Issue

This is the result of a known issue. If the BIG-IP LTM is configured to asymmetrically route client-side traffic, the connection may stall after the next-hop gateway ARP entry times out.

For example, if the BIG-IP system is configured with multiple external-facing VLANs, and the client request arrives in a different VLAN from which the response is sent, the connection will stall after the BIG-IP system times out the next-hop gateway ARP entry. This issue is more likely to affect long-lived TCP connections.

F5 Product Development is tracking this issue as ID 251127 (formerly CR82703).

Workaround

You can work around this issue by adding a static ARP entry on the BIG-IP system for the gateway through which the return traffic to the client is routed. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click ARP.
  4. Choose Static List from the drop-down menu.
  5. Click Create.
  6. Enter the IP Address and MAC Address of the next-hop gateway in the respective fields.
  7. Click Finished.
