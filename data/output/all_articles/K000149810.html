K000149810: APM: iRule using event HTTP_RESPONSE_RELEASE fails to access HTTP::cookie with errors

Description

This solution will explain why this iRule configuration fails and the proper configuration to avoid this issue.

  • Synopsis of issue, question, or intent
  • Connections to APM Virtual Server fail with a immediate redirect to https://<apm_vip_fqdn>/my.logout.php3?errorcode=25
  • In the /var/log/ltm log file you will observe the following error message:

<big_ip_hostname> err tmm[13184]: 01220001:3: TCL error: /Common/<iRule_name>_HTTP_RESPONSE_RELEASE <HTTP_RESPONSE_RELEASE> - Can't call after responding - ERR_NOT_SUPPORTED (line 1) invoked from within "HTTP::cookie names"


  • In a packet capture you will observe the following Reset Cause:

0.006788000 356 OUT s1/tmm0 : 443 → 49227 [RST, ACK] Seq=2697950385 Ack=1292332149 Win=0 Len=0 [F5RST: iRule execution error] 3007 /Common/<virtual_server_name> 0x0000000000000000 2697950385 2025-02-11 20:48:37.795374 iRule execution error


Environment

Relevant environmental factors specific to the topic

  • APM Virtual Server with the following type of iRule applied:

ltm rule /Common/Secure_Cookie_HTTP_RESPONSE_RELEASE {

when HTTP_RESPONSE_RELEASE {

  foreach mycookie [HTTP::cookie names] {

  HTTP::cookie secure $mycookie enable

  }

}

}

  • Access Policy
  • Secure Cookies
  • APM
  • iRules

Cause

This occurs because the event HTTP_REPSONSE_RELEASE can not access HTTP::cookies. HTTP_RESPONSE_RELEASE is processed after the HTTP Response is sent leaving an error: 'Can't call after responding' because it already sent the response.

Recommended Actions

Enable the Secure Cookies option on the APM Access Policy:

  1.  Login to the Admin GUI
  2. Navigate to Access> Profiles / Policies>Access Profiles (Per-Session Policies)
  3. Click on the Access Policy name.
  4. Click on the SSO/Auth Domains tab
  5. Under the Cookie Options enable "Secure."
  6. Click update.
