Description

Observing anomaly Resource request without browser verification cookie when enabling Bot Defense.

Environment

  • Multi-layered virtual server setup
  • SNAT pool on first virtual server with multiple translation addresses
  • Bot Defense profile on second virtual server

Cause

Browser verification cookie arrived from a different IP address to the one where the Browser Challenge was sent, failing bot defense's IP checksum validation.

This happens due to the SNAT pool (or other SNAT object) on the first virtual server translating source IP to different IPs throughout the course of the browser session.

Recommended Actions

The preferred and recommended solution is to insert the X-Forwarded-For header on the first virtual server, and enable Accept X-Forwarded-For on the second virtual server. This should be configured in the respective HTTP profiles.

For example:

ltm profile http first-vip-http {
    app-service none
    defaults-from http
    insert-xforwarded-for enabled   <----
    proxy-type reverse
}

ltm profile http second-vip-http {
    accept-xff enabled              <----
    app-service none
    defaults-from http
    proxy-type reverse
}

An alternative solution is to disable the IP validation, but this is generally not recommended:

tmsh modify sys db dosl7.proactive_defense_validate_ip value disable

Note: There are other conditions where the Resource request without browser verification cookie anomaly may be seen.

Additional Information

When making changes to a virtual server's HTTP profile, be aware of the following bug:
