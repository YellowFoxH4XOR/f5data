Description

In the GUI you are notified that a certificate is about expire, or maybe you see a log entry informing you about a certificate expiration. The log entry may resemble...

warning tmsh[<PID>]: 01420008:4: Certificate 'CN=<CertificateName> CA,O=<CertIssuer>, Inc.,C=US' in file /Common/ca-bundle.crt will expire on <Month> <Day> <HH:MM:SS> <YEAR> <TIME ZONE>

The default ca-bundle is updated when an upgrade is done. However, upgrades are not done every few weeks nor does that update a custom bundle. You may want to configure the BIG-IP system to automatically update the desired certificate bundles.

Generally, root CA certificates have a long validity period, such as ten years. When choosing an update interval for the certificate bundles, choose an interval that is suitable for your deployment. For example, if you regularly update your BIG-IP software and run the latest maintenance and point release for your software branch, you may not need to configure the system to automatically update the certificate bundles. However, if you do not schedule regular software updates you should consider configuring the system to automatically update the desired certificate bundles every 2-3 weeks or so. For custom certificate bundles you may want to configure a more frequent update interval. 

Environment

  • ca-bundle, custom bundles, SSL certificates
  • SSL/TLS certificates

Cause

A ca-bundle (default or custom) certificate bundle file used by the system contains some soon-to-be and/or expired certificates.

 

 Recommended Actions

Use the Certificate Bundle Manager to setup automatic updates.

 

  1. For the default ca-bundle:
    1. Go to System ›› Certificate Management : Traffic Certificate Management : Bundle Manager List ›› ca-bundle
    2. Scroll down to Update Interval and specify the update interval in days to refresh the default bundle.
    3. Click Update.
  2. For a custom bundle it is a bit more involved. You have to specify which bundles to to include and maybe exclude when setting this up for your custom bundle. You can do this while creating a new bundle or by updating an existing one. The existing one is done the same as the default. For a new one...
    1. On the Main tab, click System Certificate Management Traffic Certificate Management Bundle Manager List
    2. Click Create.
    3. From the Include Bundles Available list, select the certificate file objects to include for generating a new CA bundle.
    4. In the Include URLs field, type the URL where remote CA bundles reside, and click Add to include that for generating the new CA bundle.
      1. NOTE: Only HTTPS URLs are allowed in the Include URLs fields.
    5. From the Exclude Bundles Available list, select the certificate file objects to exclude from the new CA bundle.
    6. In the Exclude URLs field, type the URL where remote CA bundles reside, and click Add to exclude it from the new CA bundle.
      1. NOTE: Only HTTPS URLs are allowed in the Exclude URLs fields.
    7. In the Update Interval field, type the number of days at which to refresh the remote CA bundles at the URLs. The default value is set to 0 and indicates that the generated CA bundle is not dynamically updated.
    8. From the Trusted CA-Bundle list, select the CA bundle that this CA bundle manager will use to download remote CA bundles in the include and exclude URLs.
    9. In the Proxy Server field, type the host name or IP address of the proxy server for accessing remote URL resources.
      1. NOTE: Only HTTP proxy is supported. You may optionally prepend http:// to the host name or IP address.
    10. In the Proxy Server Port field, type the port number of the proxy server for accessing remote URL resources. The default is 3128
    11. In the Download Timeout field, specify the timeout period, in seconds, to download the remote CA bundles from the URLs. The value range is from 1 to 3600 (1 hour) seconds. The default value is 8 seconds.
    12. Click Finished.
