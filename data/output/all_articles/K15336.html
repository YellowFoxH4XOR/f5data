Topic

You should consider using this procedure when you want to place a Virtual Local Area Network (VLAN) in a Virtual Clustered Multiprocessing (vCMP) guest in an administrative partition other than the Common partition.

Description

When planning for vCMP guests, you should consider the following factor:

  • If VLANs that reside in administrative partitions other than the Common partition are required, you should perform the following procedure since vCMP guests create inherited VLANs in the Common partition by default.

Important: You must ensure that no other objects, such as self IP addresses, secure network address translations (SNAT), network address translations (NAT) and virtual servers have been configured to reference the inherited VLAN before proceeding to delete the VLAN. If there are objects already configured to reference the inherited VLAN, you must remove them before you attempt to delete the VLAN. Otherwise, the system will report an error that the VLAN is referenced by another object and fails to delete the VLAN.

Prerequisites

You must meet the following prerequisite to perform this procedure:

  • You have administrative access to the Configuration utility.

Procedures

To move an inherited VLAN on the vCMP guest to an alternate partition, you must first delete the VLAN. To do so, perform one of the following procedures:

Moving a VLAN to an alternate partition using the Configuration utility

Impact of procedure: Performing the following procedure may impact traffic processing. You should perform this procedure during a maintenance window.

  1. Log in to the Configuration utility of the vCMP guest.
  2. Navigate to Network > VLANs > Select.
  3. Select the inherited VLAN under the check on the left and click Delete.
  4. Navigate to System > Users > Partition List.
  5. Click Create and fill in the necessary information.
  6. Click Finished.
  7. Change to the new partition using the upper right hand corner selection box.
  8. Navigate to Network > VLANs.

    Important: When creating VLANs on the guest, do not modify the interfaces under the Resources section. It is expected that all interfaces remain as available.

    Note: The tag used on the vCMP guest VLAN must match the tag on the vCMP host VLAN.

  9. Click Create and fill in the necessary information.
  10. Click Finished.

Moving a VLAN to an alternate partition using the TMOS Shell

Impact of procedure: Performing the following procedure may impact traffic processing. You should perform this procedure during a maintenance window.

Important: The following method requires that you have command line access to the vCMP host system. If you do not have access, you need to contact your vCMP Host system administrator or use the Configuration utility method.

  1. Log in to the command line of the vCMP guest.
  2. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  3. List the current VLANs by typing the following command:

    list /net vlan

  4. Delete the inherited VLAN by typing the following command syntax:

    delete /net vlan <VLAN Name>

  5. Create a new partition by typing the following command syntax:

    create /auth partition <Partition Name> description <"Description of the partition">

  6. Change directory to the new partition by typing the following command:

    cd /<Partition Name>

  7. Create the VLAN under the new partition by typing the following command syntax:

    create /net vlan <VLAN Name> tag <TAG>

    Note: The tag used on the vCMP guest VLAN must match the tag on the vCMP host VLAN

  8. Save the changes by typing the following command:

    save /sys config

    Note: After you perform this procedure, the vCMP guest logs a benign message similar to the following each time you reload mcpd, or each time a change is made on the host that causes the vlan_allowed list to be sent to the guest for revalidation:

    warning mcpd[]: 01071321:4: Vlan allowed mismatch found: hypervisor (<VLAN_NAME>:<TAG>), guest (/Common/<VLAN_NAME>:-1) and (/<NEW_PARTITION>/<VLAN_NAME>:<TAG>).
