Known Issue

This is the result of a known issue. The FirePass Client API provides an Application Programming Interface (API) for use by third party applications. If you configure a Network Access connection to map a drive or launch an application, the API OnConnected event does not occur until after the FirePass client-side component performs drive mappings and launches applications. Similarly, if you configure a Static Application Tunnel (FirePass version 6.x) or an Application Tunnel (FirePass version 5.x) to launch an application, the API OnConnected event does not occur until after the FirePass client-side component launches the application.

The correct behavior is for the OnConnected event to occur when the Network Access connection or Application Tunnel is established, prior to launching applications and mapping drives.

Important: In FirePass 6.0.3 and in FirePass 6.0.2 with cumulative hotfix HF-602-6 or later, the API OnConnected event can occur twice when launching a Network Access or Application Tunnel favorite. For more information, refer to K10529:The FirePass Client API OnConnected event may occur twice.

Note: For more information about the Client API, refer to K7615: FirePass Client API.

F5 Product Development tracked this issue as CR100361 and it was fixed in FirePass 6.0.3. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass 5.x branch.

This issue has been fixed in cumulative HF-602-6, which has been issued for FirePass 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
