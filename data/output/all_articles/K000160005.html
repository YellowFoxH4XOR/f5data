K000160005: Monitor delays and misleading service stats due to time change after boot on Hyper-V

Type
Support Solution
Published
2026-02-13
Updated
2026-02-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000160005

Description

F5 BIG-IP running on Microsoft Hyper-V may delay running monitors and show services as "running, 0 seconds" for some hours after boot.

This can occur any time the clock moves backwards after boot, but this is known to occur under unknown conditions when running on Hyper-V.

The service status reporting is cosmetic and does not indicate any functional issue. However, bigd delaying monitors may impact service.

Environment

  • F5 BIG-IP VE
  • Microsoft Hyper-V

Cause

If Hyper-V provides time at boot that is ahead of the time zone expected by the Linux kernel on BIG-IP, after boot when NTP starts it will step the clock backwards. This can occur under the following conditions:

  • the Linux kernel expects a local time with a negative offset from UTC, but Hyper-V provides UTC
  • the Linux kernel expects UTC, but Hyper-V provides a local time with a positive offset from UTC

The conditions that cause this are not known. By default, BIG-IP VE expects local time when running on Hyper-V, so the first condition is more likely.

Additionally, bigd being impacted by clock changes is Bug ID 1971905.

Answer/Recommended Actions

If the local time zone for the Hyper-V server has a negative offset from UTC:

  1.  Run the following command from bash on BIG-IP:
    sed -i.bak -e 's/LOCAL/UTC/' /etc/adjtime

Additional Information

During boot, the Linux kernel requests initial time from the hardware real-time clock (RTC). Virtualization platforms provide a virtual RTC. Typically, Linux expects the hardware time in UTC, but this is configurable - it is configured to expect local time by default on Hyper-V.

Hyper-V sometimes provides the virtual RTC in UTC, and sometimes provides it in local time. F5 worked with Microsoft to try to understand and document this behavior, but was unable to determine what controls this behavior.
