K000161822: F5 Edge Client getting Stuck on Endpoint Inspection Stage on MAC

Type
Support Solution
Published
2026-07-16
Updated
2026-07-16
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000161822

Description

BIG-IP APM on macOS may cause F5 Edge Client to stall at the Endpoint Inspection stage and display a manual prompt, such as “Try to launch endpoint inspection again,” when the Access Policy places a Macro between EPI-related agents. The issue occurs when macro logic interrupts the expected sequence of endpoint inspection checks, particularly when Machine Cert Auth is followed by a Macro (e.g., "Blacklist Computers") before subsequent EPI agents like OS Platform or Antivirus.

Environment

  • BIG-IP APM 17.1.2 / 17.1.2.2

  • F5 Edge Client for macOS, versions 7244, 7245, and 7251

  • macOS clients managed via MDM with machine certificates provisioned

  • Access Policy includes EPI-related agents: Machine Cert Auth, OS Platform, Client OS, and Antivirus

  • Macro logic (e.g., "Blacklist Computers") is placed between EPI-related agents

Cause

Placement of a Macro between EPI-related agents disrupts the expected endpoint inspection flow on macOS. This interruption causes the Edge Client to remain at the Endpoint Inspection stage until manually retriggered by the user.

See Bug ID 2161909: MAC endpoint inspection needs a relaunch when the Access policy has an iRule check between endpoint inspection agents

Recommended Actions

  1. Review Access Policy flows for macOS endpoint inspection paths.

  2. Avoid placing Macro or iRule logic between EPI-related agents.

  3. Position Macros either before all EPI checks or after all EPI checks are completed.

  4. Example corrected flow: IP Geo → Login Message → Machine Cert Auth → OS Platform/Client OS → MAC Antivirus → Blacklist Computers → remaining policy items

  5. Duplicate the existing Access Policy before changes.

  6. Apply the updated policy to a test Virtual Server for validation.

  7. Test VPN connection from affected macOS devices to confirm Endpoint Inspection completes without manual intervention.

  8. Compare behavior with and without Machine Cert Auth to isolate whether the issue stems from EPI sequence disruption rather than client or antivirus issues.

  9. Back up BIG-IP configuration before changes; verify sufficient disk space.

Additional Information

The issue is specific to macOS clients; Windows clients do not exhibit the same behavior.

Reinstalling Endpoint Inspector, changing Edge Client versions, replacing OS Platform with Client OS, adjusting TCP MSS, and investigating certificate or JAMF-related configurations did not resolve the issue.

Resolution was achieved solely by correcting the Access Policy flow.

The problem may be difficult to detect because connections can succeed after a manual retry, masking the underlying policy design flaw.

When troubleshooting, verify the exact order of all EPI-related agents and any Macro/iRule logic in the Access Policy Visual Policy Editor.
