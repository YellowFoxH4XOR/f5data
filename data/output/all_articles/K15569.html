Known Issue

If you delete a BIG-IP APM access policy, the system may not remove all associated objects.

This issue occurs when all of the following conditions are met:

  • You created the access policy using the Configuration utility Device Wizard.
  • You deleted the Device Wizard-created access policy.

Impact

After you delete the access policy, some customization-group objects remain.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After you delete the access policy, if you use the Configuration utility to review the access policy objects, you find no related objects.
  • If you use the Traffic Management Shell (tmsh) to display access policy objects, you see remaining customization groups for the deleted access policy.
  • If you created the access policy using the Device Wizard in a partition other than the default Common partition, and you subsequently delete the access policy, you may be unable to delete the partition because of the remaining access policy customization group objects.

Workaround

To work around this issue, you can use tmsh to remove the remaining customization groups of the access policy. To do so, perform the following procedure:

Finding and deleting orphan customization group objects

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Type the following command to list the configured customization-groups.

    list /apm policy customization-group

    To limit the listed customization-group output, you can use a search string that includes a subset of the original access policy name.

    For example, if the Device Wizard-created access policy name contained "abc" (case sensitive), you can limit the returned list to only customization-group objects that contain "abc" in the name by using the following syntax:

    list /apm policy customization-group *abc*_customization

    Note: Typical orphaned customization-group objects are the secure connection and webtop profiles <policy name>_cp_customization and <policy name>_webtop_customization.

  3. Once you have identified the orphaned customization group name, you can delete the customization group using the following syntax:

    delete /apm policy customization-group <full name of the orphaned customization-group>

    For example:

    delete /apm policy customization-group abc_webtop_customization
    delete /apm policy customization-group abc_cp_customization

  4. Save the configuration changes by typing the following command:

    save /sys config

  5. To exit the tmsh, type the following command:

    quit
