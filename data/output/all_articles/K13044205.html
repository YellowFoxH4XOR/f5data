Topic

This article applies to BIG-IP 12.x - 13.x. For information about other versions, refer to the following article:

  • K82334253: Overview of the FTP profile (11.x)
  • K08859735: Overview of the FTP profile (14.x)

This article discusses the FTP profile settings. You can find the FTP profile in the Configuration utility by navigating to Local Traffic > Profiles > Services > FTP.

Description

The FTP profile allows an administrator to specify how a BIG-IP virtual server processes File Transfer Protocol (FTP) traffic. To manage FTP traffic, you can tailor FTP profile settings to your specific needs. For those settings that have default values, you can retain those default settings or modify them. You can modify any settings either when you create the profile, or at any time after you have created it.

Settings and definitions in the FTP profile

General Properties

SettingDefault ValueDescription
Name Specifies the name of the FTP profile.
Parent ProfileftpSpecifies the profile from which this profile inherits settings. The default is the system-supplied ftp profile.

Settings

SettingDefault ValueDescription
Translate ExtendedEnabledSpecifies, when selected (enabled), that the system uses ensures compatibility between IP version 4 and IP version 6 clients and servers when using the FTP protocol. The default is selected (enabled).
Inherit Parent ProfileDisabledSpecifies, when selected (enabled), that the FTP data channel inherits the TCP profile used by the control channel. If disabled, the data channel uses FastL4 only. The default is cleared (disabled).
Introduced in 11.1.0.
Data Port20Allows you to configure the FTP service to run on an alternate port. The default is 20.
Allow FTPSDisabledSpecifies, when disabled (cleared), that the BIG-IP system resets the connection to any client that sends AUTH SSL or AUTH TLS to initiate FTPS. The BIG-IP system also does not respond to FEAT commands from FTPS clients.

Specifies, when enabled (selected), that the system allows explicit FTPS negotiation for SSL or TLS. FTPS negotiation transitions the virtual server to pass-through mode and the traffic is encrypted. The BIG-IP system can no longer inspect FTPS traffic after this transition.
Once a connection has transitioned to explicit FTPS, the BIG-IP system only supports passive-mode data connections. To support passive-mode connections, there must be another virtual server that is the listener for the data connections. This must be a wild-card virtual server, which means Source Address is 0.0.0.0/0, Destination Address is also 0.0.0.0/0, and Service Port is 0.

If the FTP virtual server has source address translation, the wild-card virtual server must have the same configuration. If an LSN pool is configured on the FTP virtual server, the wild-card virtual server must use the same LSN pool, and the LSN pool must have persistence enabled.
Any security profile on the virtual server, such as ASM policies and firewall rules, is disabled for connections when they transition to explicit FTPS.
Protocol SecurityDisabledSpecifies, when checked (enabled), that the system inspects FTP traffic for security vulnerabilities, by using an FTP security profile. This option is available only on systems licensed for ASM.

Recommendations

The BIG-IP system allows you to modify the default FTP base profile. However, F5 recommends that instead of modifying a default profile, you create a custom profile using the default profile as the parent profile. You can then modify some or all of the values defined in the custom profile, while leaving the parent profile settings at their default value. For information, refer to K14488: Working with profiles.
