Topic

You can test the SNMP trap for syslog messages by sending the syslog facility to checktrap.pl and searching for a string in the log message. A matching string will generate an SNMP trap with the message that is defined in the /etc/snmptrap.conf file.

Note: For additional information about SNMP traps, refer to the BIG-IP or 3-DNS Controller Reference Guide.

Testing SNMP trap generation for messages such as System coldstart and service or node down may require disruptive adjustments to the BIG-IP or 3-DNS Controller's server nodes. To test less intrusively, use the logger utility to generate the syslog messages.

For example:

logger -p local1.warning "Service detected DOWN for 10.100.100.24"

This command will generate a log message to the syslog local1.warning facility and an SNMP trap for this message (provided snmptrap.conf file has the correct string).

For additional information, about the logger utility, refer to the logger man page.
