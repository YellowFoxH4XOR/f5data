Known Issue

This is a result of a known issue. When a virtual server is configured to use OneConnect and SNAT pools, and the virtual server handles persistent HTTP connections, TMM may crash. This issue is rare as it is a result of the connection flow reference within the SNAT pool being erroneously freed while still in use.

F5 Product Development tracked this issue as CR71999, CR71998, and CR71953 and it was fixed in BIG-IP LTM 9.1.3, 9.3.0, and 9.4.0. For information about upgrading, refer to the BIG-IP LTM release notes.
