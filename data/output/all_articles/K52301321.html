Description

The ASM local Event Logs are getting deleted or rolled over very quickly. Sometimes in minutes after the event is triggered.

  • ASM local event logs are quickly deleted.
  • Not able to find the Support ID reported by end users.

Environment

  • BIG-IP with local logging.
  • Lots of virtual servers are logging locally and the device is handling a large number of requests.
  • ASM/AWAF module provisioned.

Cause

When the logging rate is very high, the events get deleted from the logs. To check the limits, please refer to article K45320421: ASM event logs are deleted or rotated out very quickly

Recommended Actions

Since hard drive I/O can't linearly scale like other resources like CPU or memory, local logging will have to be tuned properly to avoid overwhelming the device's hard drive I/O.

Short-term Solution: Disable local logging in other virtual servers. To find out which virtual server is generating lots of local logging events, use the following command:

mysql -N -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "use PRX; select virtual_server_name from REQUEST_LOG" | uniq -c | sort -rn

Long-term Solution: Use remote logging with a user-defined log format to include headers and other parts of the request, for better visibility and decision-making capabilities, just from the remote logging server.
