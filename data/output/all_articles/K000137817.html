K000137817: HTTP Profile removes Content-Length when both Transfer-Encoding and Content-Length are present in HTTP response

Type

Published
2023-12-06
Updated

Status
Legacy Content
Applies to

Source
https://my.f5.com/manage/s/article/K000137817

Description

You notice that the Content-Length header in the HTTP response is removed after the version up to 15.1.9, 16.1.4, 17.1.0 or its successor when both Transfer-Encoding and Content-Length headers are present.


Environment

BIG-IP LTM

HTTP Profile


Cause

This is a behavior change by ID 1040609. You can refer to K21800102 for more detail.


Recommended Actions

This is an expected behavior.


Additional Information

RFC 7230 defines, "A sender MUST NOT send a Content-Length header field in any message that contains a Transfer-Encoding header field."
