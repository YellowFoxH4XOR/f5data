Known Issue

A small memory leak may be present on some BIG-IP systems.

This issue occurs when all of the following conditions are met:

  • The IP Address Intelligence Service (IPI Subscription) is enabled.
  • Your BIG-IP system has outbound access to retrieve IPI Subscription updates.
  • The initial IPI Subscription reputation database retrieval has completed.
  • The IPI Subscription automatically attempts to update the reputation database.

Impact

This issue causes a very slow memory leak, which may eventually affect other services and overall system performance.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view memory consumption of the iprepd service, the total used memory increases by 8 to 16 bytes with each database update check.
  • When memory usage is extreme, your BIG-IP system fails over to another host in the device group.
  • In the /var/log/kernel file, you observe messages similar to the following example:

    err kernel: Out of memory: Kill process <pid> (bd) score <numeric value> or sacrifice child
    err kernel: Killed process <pid>, UID 0, (bd) total-vm:<memory size>, anon-rss:<memory size>, file-rss:<memory size>
