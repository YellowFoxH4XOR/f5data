Known Issue

The BIG-IP APM system does not process multi-valued Security Assertion Markup Language (SAML) assertion attributes.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM is configured as a SAML Identity Provider (IdP) or service provider (SP) in one of the following scenarios:
    • The BIG-IP APM system is configured as a SAML IdP and attempts to create an assertion with multi-valued attributes.
    • The BIG-IP APM system is configured as a SAML SP and receives an assertion that contains multi-valued attributes.

    Example multi-valued attribute:

    The attribute called optionalParams is a list of name=value pairs.

    <ns2:Attribute Name="optionalParams" NameFormat="urn:oasis:names:tc:SAML:2.0:attrname-format:unspecified">
    <ns2:AttributeValue>OPhoneCountry=1</ns2:AttributeValue>
    <ns2:AttributeValue>OPhoneArea=206</ns2:AttributeValue>
    <ns2:AttributeValue>OPhoneLocal=555.1212</ns2:AttributeValue>
    <ns2:AttributeValue>Address1=401 Elliott Ave West</ns2:AttributeValue>
    <ns2:AttributeValue>City=Seattle</ns2:AttributeValue>
    <ns2:AttributeValue>State=WA</ns2:AttributeValue>
    <ns2:AttributeValue>MT=<15,202,334,103></ns2:AttributeValue>
    <ns2:AttributeValue>TC1=Sales</ns2:AttributeValue>
    <ns2:AttributeValue>TC2=8888</ns2:AttributeValue>
    </ns2:Attribute>

When you configure the BIG-IP APM system as the SP, multi-valued attributes are parsed only for the first attribute value; all subsequent values for that attribute are ignored. When you configure the BIG-IP APM system as the IdP, you can only set SAML attributes with a single value.

Impact

Clients may have no access or limited access to BIG-IP APM-configured resources.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client access to BIG-IP APM-configured resources may fail.
  • Clients may have limited access to BIG-IP APM-configured resources.
