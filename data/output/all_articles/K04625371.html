Known Issue

Content-Type matching is case-sensitive in HTML and rewrite-uri-translation profiles.

This issue occurs when the following condition is met:

  • You use a rewrite profile or an HTML content profile, and a response header does not match the provided headers (text/plain), or the response header case does not match. For example, the response header is Text/Html when it should be text/html.

Impact

HTML and rewrite-uri-translation profiles do not process some HTML responses.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • HTML and rewrite-uri-translation profiles do not process HTML pages when the character case in the Content-Type and configured Content-Type selection list does not match. The default configuration contains only text/html and text/xhtml types.

Workaround

To work around this issue, you can perform one of the following options:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Adding affected response content types into the HTML profile Content-Type Selection list

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Content > HTML.
  3. Locate the custom Content HTML profile in use, select the check box next to the name, and click Edit.
  4. Select Content Settings.
  5. Click Add and enter the content type received.

    For example:

    Text/Html

  6. To add the new content type, click Update.
  7. To save your changes, click Ok.

Setting the Enable Content Detection flag on the HTML Content configuration page

Performing this procedure will enable dynamic content type detection based on a first chunk of response. For example, if the first packet of data for a response looks like HTML, the response will be processed as HTML.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Content > HTML.
  3. Locate the custom HTML content profile in use, select the check box next to the name, and click Edit.
  4. Select Content Settings.
  5. Select the check box next to Enable Content Detection.
  6. To save your changes, click Ok.

    Note: When the rewrite-uri-translation profile is configured without an HTML content profile, create one, apply the suggested changes, and attach it to the virtual server along with rewrite-uri-translation profile.
