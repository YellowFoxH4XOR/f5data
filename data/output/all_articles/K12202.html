Known Issue

This is the result of a known issue. WMI and Real Server monitors send a POST request with an IPv6 address in the Host header when the target IPv4 node resides in a non-default route domain. If the server uses the information stored in the Host header, for virtual hosting, for example, the monitor request fails and the node is marked down.

For example, the following POST request was generated from the BIG-IP WMI performance monitor. The request was destined for an IPv4 node, which resides in a non-default route domain. The request contains the IPv6 route domain IP address in the Host header:

POST /scripts/F5Isapi.dll?GetCPUInfo HTTP/1.1
User-Agent: Mozilla/4.0 (compatible: MSIE 5.0; Windows NT)
Host: 2620:0000:0C10:F501:0000:000A:0A00:0002
Accept: */*
Content-Length: 16
Content-Type: application/x-www-form-urlencoded

Note: The BIG-IP system stores all IP addresses in IPv6 format internally. The Route Domain feature utilizes the IPv4 route domain address and ID inside an IPv6 address range reserved by F5. The above IPv6 address contained in the Host header represents the route domain IP%ID notation of 10.0.0.2%10.

F5 Product Development tracked this issue as ID 226531 (formerly CR141727), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.
