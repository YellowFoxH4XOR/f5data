Known Issue

This is the result of a known issue. When SIP persistence is enabled, BIG-IP uses the SIP Call-ID header to persist connections, but it does not key the persistence information to a particular virtual server. As a result, any SIP connection that uses the same Call-ID header will be persisted to the same node, regardless of the virtual server at which it arrives.

F5 Networks Product Development tracked this issue as CR27515 and CR41775.

SIP connections are handled separately by each virtual server. To work around this issue, disable SIP persistence.
