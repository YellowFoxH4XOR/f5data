K000160255: IP Intelligence feed list using HTTPS, the system fails to download the feed if the server does not provide a complete certificate chain.

Type
Support Solution
Published
2026-03-06
Updated
2026-03-06
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160255

Description

When configuring BIG-IP AFM to update its IP Intelligence feed list using HTTPS, the system fails to download the feed if the server does not provide a complete certificate chain. Certificate verification errors are observed in logs and when testing with openssl s_client, such as:

verify error:num=20:unable to get local issuer certificate

verify error:num=21:unable to verify the first certificate

The TCP 3-way handshake to the feed server completes, but the connection is immediately closed without a TLS handshake (no Client Hello observed in packet captures).

Environment

  • Product: BIG-IP AFM
  • Version: 17.1.3
  • Feature: IP Intelligence feed list using HTTPS
  • Root CA certificate installed on BIG-IP
  • Feed list server presenting an incomplete certificate chain (missing intermediate CA)

Cause

The feed list server does not provide the required intermediate CA certificate in its certificate chain during the TLS handshake. As a result, BIG-IP cannot validate the server certificate using its trust bundle, causing the HTTPS connection to be aborted before the TLS handshake.

Answer/Recommended Actions

  1. Obtain the missing intermediate CA certificate from the feed list server administrator.
  2. Append the intermediate CA certificate to the BIG-IP's system trust bundle (ca-bundle.crt):
    • Back up the existing ca-bundle.crt file.
    • Append the intermediate CA certificate to the file.
  3. Perform mcpd reload
  4. Verify the feed list can be successfully downloaded and that certificate verification errors no longer occur.
  5. Advise the feed server administrator to configure the server to present the full certificate chain in future.

Additional Information

  • The absence of a TLS Client Hello in packet captures indicates the connection is closed by BIG-IP before the TLS handshake due to certificate validation failure.
  • This issue can occur after server certificate renewals or changes if the new certificate chain is not properly configured on the server.
  • The recommended long-term solution is to ensure the feed server is configured to present the complete certificate chain.
