Topic

This article applies to BIG-IP 11.x - 16.x. For more information about other versions, refer to the following article:

  • K9900: Modifying large external classes (9.x - 10.x)

Description

Purpose

You should consider using these procedures under the following condition:

  • You want to minimize a temporary CPU spike resulting from a full configuration load when modifying a large external data group.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the TMOS Shell (tmsh).
  • You are familiar with the vi text editor.

Description

Data group lists provide a way to include lists of information for reference by iRules in the BIG-IP system's configuration. Internal classes are defined in the /config/bigip.conf file along with the data they contain. External classes are also defined in the /config/bigip.conf file, but the data they contain is stored in a separate file that is referenced from the external class definition. F5 recommends that you use external classes for maintaining large data sets, as external classes result in a more compact and manageable bigip.conf file and are less memory-intensive during config load and ConfigSync operations.

When you update the source file, you need to tell the BIG-IP system to reload the data. You can do this in the following ways:

Procedures

  • Load the entire configuration
  • Update the source-path attribute of the sys file object
  • Modify the external data-group file using tmsh

Load the entire configuration

Impact of procedure: Performing the following procedure can result in a temporary increase in CPU load while the configuration is parsed and loaded.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following command to load the configuration and reload the updated data:

    load /sys config

Update the source-path attribute of the sys file object

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following command syntax to modify the contents of a specific data group:

    modify /sys file data-group example_dg source-path http://x.x.x.x/datagroup.txt

    Note: The URI does not need to be different from the current value. Setting it to the existing value triggers the system to reread the file.

    Note: For a file that has already been copied to the BIG-IP system, the URI should be in the following format: file:/<path>/<filename>. For example: file:/shared/tmp/datagroup.txt

    You should expect to see messages similar to the following in the /var/log/ltm file, indicating that the system has reread the data group.

    Mar 10 10:51:56 bigip1 notice tmm[16236]: 01010259:5: External Datagroup (/Common/example_dg) queued for update.
    Mar 10 10:51:56 bigip1 notice tmm[16236]: 01010259:5: External Datagroup (/Common/example_dg) update finished.

Modify the external data-group file using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following command syntax to modify the contents of a specific data group:

    edit /sys file data-group <filename>

    For example, to modify a data group named example, enter the following command:

    edit /sys file data-group example

    Note: This command launches the vi editor within tmsh.

  3. After you're in the vi editor, the existing data group entries appear.
  4. Add or remove data within the data group in the vi editor.
  5. Save the configuration and exit the vi editor.
  6. The vi editor prompts you to confirm the changes. To confirm, enter the following:

    y

  7. To save the configuration, enter the following command:

    save /sys config
