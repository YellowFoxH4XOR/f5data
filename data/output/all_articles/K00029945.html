Topic

You should consider using this procedure under either of the following conditions:

  • You are making changes to a system licensed for F5 Full-Box FIPS.

    Note: F5 recommends running the sys-eicheck utility before and after making changes to your system.

  • You need to troubleshoot integrity check problems on a system licensed for F5 Full-Box FIPS.

Description

The sys-eicheck utility is the FIPS version of the sys-icheck utility. The sys-eicheck utility scans the BIG-IP system for any unexpected changes to the system software. It differs from the sys-icheck utility in that it is tuned to avoid false alerts on files such as configuration files which intentionally change.

For more information on the sys-icheck utility, refer to K9118: Overview of the sys-icheck utility.

The sys-eicheck utility is installed with all BIG-IP systems, but it only runs automatically on systems that are licensed for the F5 Full-Box FIPS add-on. The system runs the sys-eicheck utility for the power-on and daily self-tests required for FIPS validation. You can also run it manually to determine if the device will pass or fail the tests.

RunActions
On power-onOn Pass: No action
On Fail: Logs details to the /config/f5_public/fipserr file, stops the boot process, and reports a failure on the console
DailyLogs the following result to the /var/log/secure file:
Pass: BIG-IP Integrity Check: [ PASS ]
Fail: BIG-IP Integrity Check: [ FAIL ] -- Contact F5 Networks technical support

Beginning in BIG-IP 17.1.0, when the sys-eicheck integrity daily cron job fails, then during the next login, the system displays the following message to the user on both the Configuration utility and tmsh (tmos) shell:

BIG-IP Integrity Check: [ FAIL ] -- THE SYSTEM WILL HALT UPON REBOOT, CONTACT F5 NETWORKS FOR TECHNICAL SUPPORT

ManuallyDisplays results and details on the console
For QKViewAdds detailed results to the QKview /fips_module.xml file

Prerequisites

  • You must log in to the command-line console as an administrator.
  • Your system must be licensed for the F5 Full-Box FIPS add-on.

    Note: You can run the sys-eicheck command on any BIG-IP system regardless of FIPS licensing,.

Procedures

Manually running the sys-eicheck utility

Impact of procedure: Running the sys-eicheck utility should not have a negative impact on your system.

  • At the command line, type the following command:

    /usr/libexec/sys-eicheck.py

You can view the detailed sys-eicheck output on the console after you run the utility manually or in the /config/f5_public/fipserr file after a boot failure.

Important: If the sys-eicheck utility displays a fail status, the system does not boot to the current volume the next time it restarts. Therefore, you must resolve any fail issues before you restart the BIG-IP system. For troubleshooting information, refer to K11402545: Troubleshooting FIPS self-test failure

The sys-eicheck output contains the following four sections and a summary:

  • Non-critical files missing
  • Non-critical files modified
  • Critical files missing
  • Critical files modified

The utility only considers missing or modified critical files as failures. The output contains non-critical files for informational purposes only.

The system shows pass or fail messages following this output. You may observe an output similar to the following when the test result passes:

- Critical file modifications result in failure.
