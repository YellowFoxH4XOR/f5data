Topic

Starting in BIG-IP APM and Edge Gateway version 10.2.0 with Hotfix-BIGIP-10.2.0-1755.1-HF1 installed, Oracle Access Manager (OAM) users will only be presented with a logon page if they attempt to access a protected resource. Prior to this hotfix, an iRule was needed to prevent users accessing non-protected resources from being required to login.

Workaround

If you are unable to install the hotfix, you can use an iRule to verify whether the resource is protected, and if so, to prompt the user for logon credentials. For example:

         when HTTP_REQUEST {
           set sid [HTTP::cookie MRHSession]
           log local0. "======== BEGIN ========"
           log local0. "https://[HTTP::host][HTTP::uri], sid: $sid"
       
           if { [ACCESS::session exists $sid] == 1} {
               log local0. "Valid Session found, ACCESS enabled"
           } else {
             if { [HTTP::uri] contains "f5iupstate=1" } {
               log local0. "Protected URI detected, ACCESS enabled"
             } else {
               if { [HTTP::uri] contains "?" } {
                  set newuri [HTTP::uri]&f5acmode=1
               } else {
                  set newuri [HTTP::uri]?f5acmode=1
               }
               HTTP::uri $newuri
               log local0. "HTTP_REQUEST: Disable ACCESS, updated new uri: $newuri"
               ACCESS::disable
             }
           }
           log local0. "======== END ========"
        }

Note: For more information about using iRules, please see the F5 DevCentral site. A DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).
