Description

BIG-IP originated ARP packets are being dropped when enabling QoS policy on your network

Environment

  • BIG-IP LTM 
  • ARP CoS or QoS

Cause

In some networks with specific QoS policies, an ARP packets from BIG-IP LTM can be dropped due to default low priority assigned to it.

Recommended Actions

Modify the arp.vlanpriority sys db according to your environment:

modify sys db arp.vlanpriority value 3

Note: The db variable arp.vlanpriority supports values from -1 to 7, where -1 has a variable meaning:

1) When arp.priority is set to high and arp.vlanpriority is set to -1, BIG-IP echoes 802.1p value in the ARP request. Internal priority is set to 4/5.
   BIG-IP uses the value set in the tm.egress.pktpriority for the outgoing ARP requests from the BIG-IP.
 
2) When arp.priority is set to high and arp.vlan priority is set to other than -1, BIG-IP echoes 802.1p value in the ARP request. Internal priority is set to 4/5.
   BIG-IP uses the value set in the arp.vlanpriority for the outgoing ARP requests from the BIGIP.
 
3) When arp.priority is set to normal and arp.vlanpriority is set to -1, BIG-IP echoes 802.1p value in the ARP request. Internal priority is set to 3
   BIG-IP uses the value set in the tm.egress.pktpriority for the outgoing ARP requests from the BIGIP.
 
4) When arp.priority is set to normal and arp.vlan priority is set to other than -1, BIG-IP echoes 802.1p value in the ARP request. Internal priority is set to 3.
   BIG-IP uses the value set in the arp.vlanpriority for the outgoing ARP requests from the BIGIP.

Additional Information

arp.priority is used to set the priority of ARP packets within tmm, and has the following settings


sys db arp.priority {
    default-value "normal"
    scf-config "false"
    value "normal"
    value-range "high normal"
}
