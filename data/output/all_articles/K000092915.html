Description

Beginning in BIG-IP 14.1.0 you can configure network firewall rules to limit access to the management interface on the BIG-IP system. The management interface network firewall rules use the same syntax as network firewall rules in BIG-IP AFM but do not require the BIG-IP AFM module to be licensed and provisioned.

For example, you can configure a positive security posture by creating rules that allow access to specific ports on the management interface from specific hosts on your network. The last rule you create in the rule list is an inclusive rule that drops all traffic destined to the management interface. As a result, the BIG-IP system drops any traffic that does not match an allow rule.


However, if you have created a deny-all rule, but no explicit allow rule for NTP, you may find the symptoms below:

  • The output from the ntpq command may appear similar to the following example, which indicates the local ntpd process fails to communicate with an NTP peer server. 

[device1@bigip1:Peer Time Out of Sync:Changes Pending] ~ # ntpq -np
remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
192.168.10.67         .INIT.     16 u    - 1024    0    0.000    0.000   0.000
192.168.19.23         .INIT.     16 u    - 1024    0    0.000    0.000   0.000

In addition, you may find more explanation of each field in the output in K10240: Verifying NTP peer server communications.

  • By manually triggering NTP synchronization with steps in K78084428: How to force ntpd to sync to a specific NTP server, it showed "no server suitable for synchronization found".

[device1@bigip1:Peer Time Out of Sync:Changes Pending] ~ # ntpdate -bv 192.168.10.67
7 Nov 15:31:04 ntpdate[18640]: ntpdate 4.2.6p5@1.2349-o Fri Jan 29 09:51:38 UTC 2021 (1)
7 Nov 15:31:08 ntpdate[18640]: no server suitable for synchronization found

Environment

  • BIG-IP

  • NTP

  • Management interface

Cause

If you have explicitly created the deny-all rule as the Last in the rule list for it to block access from non-allowed sources, but no allow rule for NTP traffic, BIG-IP will drop NTP traffic and cause failure to communicate with NTP servers.

Recommended Actions

You may add allow network firewall rule on management interface for port 123 of UDP protocol, with K46122561: Restrict access to the BIG-IP management interface using network firewall rules, to create a explicit allow rule for NTP traffic before the deny-all rule in the rule list.
