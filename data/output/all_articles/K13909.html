Known Issue

The BIG-IP GTM system may fail to apply a pool load-balancing method.

This issue occurs when the following conditions are met:

  • The ipv6_noerror option is enabled for the wide IP.
  • The Local Domain Name System (LDNS) sends a request for an AAAA record.

This issue may occur under different configuration combinations. In the following example, the www.example.com wide IP uses the Global Availability load balancing method that should select the first pool, gtm_pool1 (no IPv6 members), as long as the pool is available. Only when gtm_pool1 is not available should the system select the secondary pool, gtm_pool2 (one IPv6 member). When an LDNS server sends an AAAA record to the wide IP, the system should select pool gtm_pool1 and send a NOERROR response. In addition, since gtm_pool1 does not contain IPv6 members, the system should use the alternate load balancing mode of drop packet. Instead, the system incorrectly skips the alternate and fallback load-balancing modes in gtm_pool1 and returns the AAAA record from gtm_pool2.

wideip {
name "www.example.com"
pool_lbmode ga
ipv6_noerror yes
partition "Common"
pool "gtm_pool1"
pool "gtm_pool2"
}

pool {
name "gtm_pool1"
ttl 30
monitor all "gateway_icmp"
preferred rr
alternate drop_packet
fallback drop_packet
partition "Common"

member 172.17.1.101:80
}

pool {
name "gtm_pool2"
ttl 30
monitor all "gateway_icmp"
preferred rr
alternate drop_packet
fallback drop_packet
partition "Common"

member 2404:6400:0:2:192:2:0:151.80
}

Impact

The BIG-IP GTM system may load balance requests to the incorrect resource.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP GTM system ignores the pool load-balancing method.
  • The BIG-IP GTM system may load balance requests to the incorrect resource.

Workaround

To work around this issue, you may be able to add an iRule that drops AAAA requests for the specified pool.

For example:

when LB_SELECTED {
if { ([DNS::rrtype] eq "AAAA") and ([DNS::rrname] eq "www.example.com") } {
drop
}
}

Alternatively, you can add a dummy IPv6 virtual server object to the pool and disable the virtual server to ensure that the system does not skip alternate and fallback load balancing modes.
