Known Issue

The BIG-IP ASM configuration fails to load after an upgrade.

This issue occurs when all of the following conditions are met:

  • You have created a custom Application Security scheduled report.
  • The custom report references the Top alerted URLs predefined filter.
  • You upgrade your system from BIG-IP ASM 11.3.0 or 11.4.0, to 11.4.1 and later.

Impact

The BIG-IP ASM configuration fails to load after an upgrade.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When attempting to load the configuration after an upgrade, the affected system displays an error message similar to the following example:

    010715ee:3: The predefined report /Common/Top alerted URLs doesn't exist. Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can use a text editor to manually correct the predefined filter name used in the /config/bigip.conf file. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected system.
  2. Create a backup copy of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf_557062

  3. Use your preferred text editor to open the /config/bigip.conf file.
  4. Locate all instances of the following string:

    /Common/Top alerted URLs

  5. Replace the word alerted with alarmed.

    For example, the configuration lines should now appear similar to the following:

    /Common/Top alarmed URLs

  6. Save the modified /config/bigip.conf file.
  7. Load the configuration by typing the following command:

    tmsh load /sys config

  8. After successfully loading the configuration, save the loaded configuration by typing the following command:

    tmsh save /sys config
