K35750411: Virtual Server doesn't forward traffic to the pool member

Type
Support Solution
Published
2023-05-05
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.X.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.X, 13.0.1, 13.0.0, 13.1.0
Source
https://my.f5.com/manage/s/article/K35750411

Description

Intermittently, the virtual server doesn't forward traffic to the pool member

Environment

  • The incoming packets are fragmented

Cause

The next fragments aren't received, therefore, the BIG-IP doesn't forward this traffic.

Recommended Actions

Collect tcdumps from a middleware network device and the BIG-IP

Check the tcpdumps for fragmentation. 
ip.flags.mf == 1
Confirm the fragmentation bit is enabled. "More Fragments" should be set to 1. The offset in the first fragmented packet should be zero. Note the frame where this packet is reassembled.
Internet Protocol Version 4, Src: 1.1.1.1, Dst: 2.2.2.2
    0100 .... = Version: 4
    .... 0101 = Header Length: 20 bytes (5)
    Total Length: 1500
    Flags: 0x60, Don't fragment, More fragments
        0... .... = Reserved bit: Not set
        .1.. .... = Don't fragment: Set
        ..1. .... = More fragments: Set <<<<<<<<<<<<<<<
    ...0 0000 0000 0000 = Fragment Offset: 0
    [Reassembled IPv4 in frame: 123]
Data (1480 bytes)

Confirm next packet arrived. Offset should be set to begin at the length of the previous packet, 1480. This is 1500 minus 20 for the IP header. If no further packets are expected the "don't fragment" bit should be set to 1.

        ..0. .... = More fragments: Not set
    ...0 0101 1100 1000 = Fragment Offset: 1480 <<<<<<<<<<<<<<< Offset == 1480.
    [2 IPv4 Fragments (1581 bytes): #121(1480), #123(101)]
        [Frame: 121, payload: 0-1479 (1480 bytes)]
