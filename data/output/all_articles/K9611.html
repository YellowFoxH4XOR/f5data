Known Issue

This is the result of a known issue. When configuring a server object with multiple IP addresses on a BIG-IP GTM system that is a member of a sync group, the server object IP addresses are not consistently displayed among sync group members.

For example, if you configure the BIG-IP GTM device, GTM1, with a BIG-IP redundant server type definition where the system's self IP address is 1.1.1.1, and the peer system's self IP address is 1.1.1.2, the Configuration utility on GTM1 properly displays the IP addresses.

However, if you log in to the Configuration utility of sync group member GTM2, and navigate to the Server List page, the system may incorrectly display the IP address for the redundant system as 1.1.1.2. If you then click the BIG-IP redundant server object to display the General Properties page, the self IP addresses are ordered properly. For example, the system's self IP address is 1.1.1.1, and the peer IP address is 1.1.1.2.

This behavior is only a display issue. This issue occurs because BIG-IP GTM does not sort the IP addresses in memory when they are loaded from the configuration file. Therefore, the IP address that displays in the GUI is not consistent between members.

F5 Product Development tracked this issue as CR103775 and it was fixed in BIG-IP GTM version 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.
