Description

When trying to upgrade we are seeing the following error messages

Aug 14 16:13:42 BIG-IP-01 notice mcpd[8652]: 01071038:5: Loading keys from the file.
Aug 14 16:13:46 BIG-IP-01 err mcpd[8652]: 01070712:3: Caught configuration exception (0), Unable to verify key (/Common/f5_api_com.key) is protected by provided passphrase..
Aug 14 16:13:46 BIG-IP-01 err tmsh[6668]: 01420006:3: Loading configuration process failed.
Aug 14 16:13:46 BIG-IP-01 emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- 01070712:3: Unable to verify key (/Common/f5_api_com.key) is protected by provided passphrase. Unexpected Error: Loading configuration process failed.

 

Environment

  • Upgrade failed
  • License reactivation
  • Loading of a UCS file

Cause

This is the result of a known issue BUG ID: 675329 Decryption of the field (passphrase) for object (/Common/f5_api_com.key) failed error during upgrade 

Recommended Actions

For HA cluster systems:

1) Attempted to perform sync operation from working peer unit.
    
2) Run following commands on both HA devices in the group to ensure they have the same keys.

    f5mku -K


3) If the keys match then use a text editor comment out offending configuration lines in /config/bigip.conf file:

For instance:
#sys file ssl-cert /Common/f5_api_com.crt {
#    cache-path /config/filestore/files_d/Common_d/certificate_d/:Common:f5_api_com.crt_59005_1
#    revision 1
#    source-path file:///config/ssl/ssl.crt/f5_api_com.crt
#}

3a) If auto-sync is enabled in device-group - Disable it.

Important: Since the config has failed to load even if you can get into the WEBUI the change of disabling auto sync may not take effect when the config finally loads. Therefore you will need to disable within the bigip_base.conf  file of the non-working system or when the config loads it may auto sync anyways.

3b) Load the configuration from the command line:
     
    tmsh load sys config
    
3c) Once the configuration loads successfully. Perform sync operation pushing configuration from the peer (unaffected unit) to the trouble device. Re-enable autosync if you disabled it.
