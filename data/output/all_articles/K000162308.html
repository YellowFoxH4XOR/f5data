Overview

F5 is introducing an upgraded and streamlined login experience that is designed to be more secure for its customer-facing F5 applications. To achieve this, we are transitioning to the Auth0 platform from Okta.

This upgrade is part of our ongoing commitment to supporting a secure user experience for customers. In the future, you will be able to access all our applications with your new F5 identity. The first application that will be onboarded to the new identity platform will be DevCentral. The remainder of the applications will follow the schedule outlined in the table below.

What to expect

  • You will notice a refreshed login screen when signing into F5 applications.
  • You will need to set up a new Multi-Factor Authentication (MFA) for your account. Your existing password should still work, and you can use the same email address.
  • We are changing the available MFA options. The new factors will be:
    • Auth0 Guardian App
    • Google Authenticator or similar TOTP code generators
    • Security keys
    • WebAuthn

Application-Specific Migration Details

iHealth

GUI Access

Starting August 31st, you will be able to sign in using the same email address and password you used with Okta. You will be required to register for new Multi-Factor Authentication (MFA).

API Access

Your iHealth API integrations will continue to work seamlessly on August 31st . When your current client ID and client secret expire, you can generate new credentials through the iHealth platform using Auth0. This follows the standard credential rotation process you use today, so no changes to your integration workflow are required.

BIG-IP Integrations

For BIG-IP versions 17.x that have an iHealth integration, they will continue to function as expected after August 31st.

MyF5

GUI Access

Starting August 31st, you will be able to sign in using the same email address and password you used with Okta. You will be required to register for new Multi-Factor Authentication (MFA).

API Access

When your current client ID and client secret expire, you can generate new credentials through the MyF5 GUI using Auth0. This follows the standard credential rotation process you use today, so no changes to your integration workflow are required.

SecureFiles

Starting August 31st, you will be able to sign in using the same email address and password you used with Okta. You will be required to register for new Multi-Factor Authentication (MFA).

Frequently Asked Questions

Why is this change happening?

We are upgrading our login system to provide you with a streamlined experience that is designed to be more secure for customer-facing F5 applications.

Do I have to create a new account in Auth0?

No, you will only be required to set up new MFA. For all other applications, please continue to use your existing credentials.

Will I need to make a new account for all the other applications when they are onboarded?

No, this is a one-time setup process in Auth0 that will work for all F5 customer-facing web applications as they are onboarded to the platform.

What will happen to my old account?

Your old account will be deleted by the end of September 2026.

Can I use the same email address?

Yes, please use the same email address as this will ensure a consistent and unified user experience.

Will this become my login for MyF5, DevCentral, iHealth, etc.?

Yes, this will be your login for all F5 customer-facing web applications as they are onboarded.

Is my data secure?

Protecting your data is one of our highest priorities. This upgrade is part of our ongoing commitment to supporting a secure user experience for customers.

When will this change take effect?

We are implementing this change in phases, starting in July 2026 and completing by September 2026. iHealth, MyF5, and SecureFiles will migrate on August 31st, 2026.

Can I use a distribution list or shared mailbox as my account email?

Since access needs to be tied to individuals' user accounts, a distribution list or shared mailbox should not be used as your account email. Each user should register with an individual, named email address rather than a shared mailbox or distribution list. In addition to providing better accountability and protection for your organization, individual accounts allow Multi-Factor Authentication (MFA) to be applied for each individual user.

With regard to email as an MFA factor, email does not offer the same level of protection as the supported factors listed above. If your organization prefers to manage access centrally, F5 will support federation with your own identity provider (IdP) for F5 applications as part of a future release. For any issues, please contact your F5 account team or representative.
