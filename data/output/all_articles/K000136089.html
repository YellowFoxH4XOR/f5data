K000136089: No space left on /var partition even after removing large files

Type
Support Solution
Published
2023-09-05
Updated
2023-09-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000136089

Description

The /var partition may report no space left even after removing large files such as old UCS archives.
In the logs you can see messages similar to:

011d0004:3: Disk partition /var has only <x>% free.

 

Environment

  • BIG-IP
  • /var partition reporting no space left 
  • Large files, like UCS archives, have been removed already
  • Space on /var partition has not been increased after removing the files.

 

Cause

Recently deleted files are still open by the running process.

 

Recommended Actions

1)   Log in to CLI/bash

2)   Execute a command:

lsof -ws | grep -i 'size\|deleted'

 

You see an output similar to this one:

java     15634 5534     root 151r     REG            253,16  146984926    172055 /var/local/ucs/BIGIPHOSTname.ucs (deleted)

 

3)   Execute a command to kill the process that keeps deleted files open – in the above example it is java with PID 15634

kill -9 15634

 

Impact: GUI may not be accessible for a while. It should be restored automatically (new java process/worker spawned).

 

4)   Execute a command to verify free space:

df -h

          

The free space on /var partition should be increased now.

 

Additional Information


None.
