Description

Persistent syslog alerts may occur on F5 BIG-IP systems due to soon-to-expire certificates found in the default CA bundle file (ca-bundle.crt). Users may observe repeated log messages even after renewing their certificates (or updating the CA bundle):

/var/log/ltm
warning tmsh[<PID>]: 01420008:4: Certificate 'CN=InCommon ECC Server CA,OU=InCommon,O=Internet2,L=XXX,ST=MI,C=US' in file /Common/ca-bundle.crt will expire on Dec 16 23:59:59 2025 GMT
warning tmsh[<PID>]: 01420008:4: Certificate 'CN=InCommon ECC Server CA,OU=InCommon,O=Internet2,L=XXX,ST=MI,C=US' in file /Common/ca-bundle will expire on Dec 16 23:59:59 2025 GMT

 

Environment

  • BIG-IP LTM All
  • Default CA bundle (ca-bundle.crt)

 

Cause

  • The alert warns that the intermediate CA certificate "CN=InCommon ECC Server CA" in the ca-bundle.crt file will expire on December 16, 2025.
  • This is a proactive notification, not an indication of an already expired certificate.

 

  • The system alerts about certificates approaching expiration, even if the user has recently updated the bundle, as long as the expiring certificate remains in the bundle.
  • BIG-IP runs scheduled checks for certificates expiring within 30 days and logs warnings for certificates with future expiration dates as they near that window.

 

  • The alert will persist until the expiring certificate is removed from ca-bundle.crt, either by updating to a newer bundle or by manual removal.
  • If a certificate (e.g., "InCommon ECC Server CA") is no longer present in the latest bundle, it means F5 has removed it due to expiration, replacement, or loss of trust.
  • The presence of "InCommon ECC Server CA 2" in both files indicates that only the original CA was removed, while its successor remains trusted.

 

  • F5 does not publish a fixed schedule for blended-bundle.crt updates.
  • Updates occur as needed, typically in response to changes in the global CA landscape (new roots, removals, expirations).
  • Users should periodically check and download the latest bundle from the F5 Downloads site to ensure their CA bundle is current.

 

  • If the expiring certificate is not referenced by any active SSL profiles or virtual servers, there is no impact to traffic—only the alert is generated.
  • If you require a certificate that has been removed from the official bundle, you must manage it manually in a custom bundle.

 

  • The latest blended-bundle.crt can always be obtained from the F5 Downloads site.

Recommended Actions

    1. User can update Certificate.
    2. User can also manually update at any time by downloading the latest blended-bundle.crt from F5 Downloads and uploading it to your BIG-IP.
    3. By default, the CA bundle manager does not auto-update the bundle (the update interval is set to 0, meaning no automatic updates). User can set an "Update Interval" in days (for example, every 14 or 21 days) to have the system automatically refresh the CA bundle from F5's CDN.

    Additional Information

    Identify Expired Certificates

    1. Run the following command to list expired or soon-to-expire certificates:
       # tmsh run sys crypto check-cert
      or
       # openssl x509 -in /config/ssl/ssl.crt/f5_api_com.crt -text -noout
    2. For a full list of certificates and their expiration dates:
       # tmsh list sys file ssl-cert
