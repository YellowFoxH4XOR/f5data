Known Issue

You may not be able to access virtual servers and virtual addresses.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is a BIG-IP Virtual Edition (VE) instance.
  • You configure a Virtual Local Area Network (VLAN) that is not assigned to an interface.
  • You create a self IP address assigned to the new VLAN.
  • You create a virtual server that is enabled by the specific VLAN.
  • You attempt to connect to the virtual server or virtual server address.

Impact

You are unable to connect to the virtual server or virtual server address.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When running an ICMP "ping" test, you receive an ICMP response from the VLAN self IP, however, the virtual address that is configured on the same VLAN does not respond and fails with an ICMP message similar to the following example:

    Destination Host Unreachable

  • When you attempt to connect to the virtual server, you fail to connect, and observe an error message similar to the following example:

    No route to host

Resolution

Status

F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can modify the VLAN MAC address. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP system.
  2. To set the VLAN MAC address to 00:00:00:00:00:00, type the following command:

    ip link set <vlan name> address 00:00:00:00:00:00
