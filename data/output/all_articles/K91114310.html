K91114310: Reducing the performance impact of BIG-IQ statistics gathering on managed BIG-IP systems

Type
Knowledge
Published
2020-02-18
Updated
2025-04-02
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K91114310

Topic

You should consider using this procedure under the following conditions:

  • You use BIG-IQ to manage BIG-IP LTM or BIG-IP DNS configurations.
  • The managed BIG-IP system has large number of configuration objects.

Description

When a BIG-IQ manages a BIG-IP LTM or BIG-IP DNS system, it periodically gathers statistics and status information of the configuration objects including virtual servers, nodes, and pool members. The data-collection behavior may cause CPU utilization spikes when the managed BIG-IP system has large number of configuration objects. BIG-IQ 6.0.1 and later use an application programming interface (API) to support management for statistics gathering tasks. To reduce the performance impact on the BIG-IP system caused by the BIG-IQ statistics gathering, you can configure the request interval and behavior of BIG-IQ data requests to the BIG-IP systems by adjusting the parameter values through the BIG-IQ Stats API.

The supported BIG-IQ Stats API parameters are defined in the following table.

NameDescriptionDefault value
isMonitorRunningSpecifies whether the statistics gathering is enabled (true) or disabled (false)true
pollingIntervalSecondsSpecifies the interval time of the statistics gathering requests in seconds

Note: If useAppIqDcd is set true, the highest value you can use for this field is 300 seconds.		300
batchSizeSpecifies the batch size200
waitingBetweenBatchesSpecifies the wait time between batches in seconds

Note: For a BIG-IP system with 1000 to 3000 configuration objects, F5 recommends that you set an interval of 5-10 seconds' wait time between batches.

0
monitorItemSpecifies a list of monitored configuration objects[ "virtual_server",
"pool",
"node" ]
useAppIqDcdSpecifies whether a BIG-IQ data collection device (DCD) is used to collect statistics (true) or not (false)

Note: You must have a functional and properly configured DCD before enabling this parameter.

Note: F5 recommends that you use DCD for BIG-IP data-collection tasks by setting the useAppIqDcd parameter to true if you have at least one DCD in your BIG-IQ deployment.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IQ system.

Procedures

Viewing the BIG-IQ Stats API configurations

You can view the current BIG-IQ Stats API configuration by sending a local API call. To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line.
  2. To view the BIG-IQ Stats API configuration, enter the following command:

    restcurl /cm/adc-core/current-config/stats-refresh

    The output looks similar to the following example:

    {
    "isMonitorRunning": true,
    "pollingIntervalSeconds": 300,
    "batchSize": 200,
    "waitingBetweenBatches": 0,
    "monitorItems": [
    "virtual_server",
    "pool",
    "node"
    ],
    "useAppIqDcd": false,
    "generation": 1234,
    "lastUpdateMicros": 1581619002348484,
    "kind": "cm:adc-core:current-config:stats-refresh:statsmonitorstate",
    "selfLink": "https://localhost/mgmt/cm/adc-core/current-config/stats-refresh"
    }

Modifying the BIG-IQ Stats API configurations

You can modify the BIG-IQ Stats API configuration by sending a local API call. To do so, perform the following procedure.

Impact of procedure: The suggested procedure alters the behavior of BIG-IQ stats gathering and the impact depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the BIG-IQ command line.
  2. To view the BIG-IQ Stats API configuration, use the following command syntax:

    restcurl -X PUT /cm/adc-core/current-config/stats-refresh -d '{<stats_configuration>}'

    For example, if your managed BIG-IP system has 3000 configuration objects, you want to increase the BIG-IQ system's polling interval time to 900 seconds and batch wait time to 10 seconds, as in the following example command. Doing this helps reduce the performance impact on the managed BIG-IP system.

    restcurl -X PUT /cm/adc-core/current-config/stats-refresh -d '{"isMonitorRunning": true, "pollingIntervalSeconds": 900, "waitingBetweenBatches": 10}'

    The output appears similar to the following example:

    {
    "isMonitorRunning": true,
    "pollingIntervalSeconds": 900,
    "batchSize": 200,
    "waitingBetweenBatches": 10,
    "monitorItems": [
    "virtual_server",
    "pool",
    "node"
    ],
    "useAppIqDcd": false,
    "generation": 0,
    "lastUpdateMicros": 0,
    "kind": "cm:adc-core:current-config:stats-refresh:statsmonitorstate"
    }
