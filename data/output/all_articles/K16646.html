Known Issue

HTTPS monitors may fail to reuse Secure Socket Layer (SSL) sessions.

This issue occurs when all of the following conditions are met:

  • BIG-IP pool members are configured with HTTPS health monitors.
  • The BIG-IP system monitors servers that use SSL session caching.
  • The monitors are configured to support a combination of Transport Layer Security (TLS) 1.0 and TLS 1.2 servers (BIG-IP 11.5.0 and later).

The way in which the bigd process, which is responsible for the health checks of nodes and pool members, stores session ID information may cause the BIG-IP system to attempt to reuse the incorrect session ID for a particular pool member. If this issue occurs, session reuse fails and a complete SSL handshake must be performed.

Additionally, BIG-IP 11.5.0 and later HTTPS health monitors support TLS 1.2. Environments with both TLS 1.0 and TLS 1.2 servers that perform SSL session caching may experience monitor flapping or servers being marked down unexpectedly.

Impact

The bigd process may consume more CPU than necessary because the process may always be performing complete SSL handshakes. BIG-IP 11.5.0 and later versions may experience monitor flapping or servers being marked down unexpectedly.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Messages similar to the following example are logged to the /var/log/ltm file:

    err bigd[13958]: 01060111:3: Open SSL error - error:1409E0E5:SSL routines:SSL3_WRITE_BYTES:ssl handshake failure.
    err bigd[13958]: 01060111:3: Open SSL error - error:1408F10B:SSL routines:SSL3_GET_RECORD:wrong version number.

    notice mcpd[7842]: 01070638:5: Pool /Common/<pool_name> member /Common/<member IP:port> monitor status down. [ /Common/https: down ] [ was up for 0hr:0min:21sec ]
