K000160054: ASM processes restarting after upgrade

Type
Support Solution
Published
2026-02-23
Updated
2026-02-23
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160054

Description

You see one or more ASM (Adv. WAF) related processes rebooting continuously after an upgrade.

Environment

  • ASM
  • Post-upgrade

Cause

This is expected behavior.

After an upgrade the system may take several minutes, to a few hours before being FULLY loaded.

You can "Confirm.. the asm configuration has been loaded after an upgrade or reboot".

Answer/Recommended Actions

Allow ASM time to fully load the config.

Additional Information

After an upgrade, DO NOT REBOOT THE SYSTEM, until you have confirmed the full config load (link above).

If you reboot the device before the full config has been loaded, this will interrupt the config load process and corrupt the new volume.

 

If you accidentally rebooted the system before the full config load (as outlined in the link above) then you will have to:
1. Boot back to previous version
2. Delete the upgrade volume
3. Re-install a new upgrade volume
4. Boot into this new upgrade volume (after the re-installation)
