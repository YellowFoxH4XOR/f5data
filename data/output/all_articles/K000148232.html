Security Advisory Description

A session fixation issue was discovered in the NGINX OpenID Connect reference implementation, where a nonce was not checked at login time. This flaw allows an attacker to fix a victim's session to an attacker-controlled account. As a result, although the attacker cannot log in as the victim, they can force the session to associate it with the attacker-controlled account, leading to potential misuse of the victim's session. (CVE-2024-10318)

Impact

An attacker may be able to force the session to associate it with the attacker-controlled account, leading to potential misuse of the victim's session. The following NGINX systems may be affected by this issue:

NGINX Plus

NGINX Plus systems in which the administrator has installed and configured the OpenID Connect (NJS-based) component to perform authentication are affected by this issue. OpenID Connect (NJS-based) is an open-source implementation that configures NGINX Plus as a relying party for OpenID Connect authentication by leveraging NGINX JavaScript (NJS). The OpenID Connect (NJS-based) component is installed independently by an NGINX administrator and is not integrated by default.

NGINX Instance Manager, NGINX API Connectivity Manager, and NGINX Ingress Controller

NGINX Instance Manager, NGINX API Connectivity Manager, and NGINX Ingress Controller systems in which the administrator has configured the OpenID Connect component to perform authentication are affected by this issue. OpenID Connect is bundled with the NGINX Instance Manager, NGINX API Connectivity Manager, and NGINX Ingress Controller products by default.

F5 Product Development has assigned ID NWA-2059 (NGINX Plus, NGINX Instance Manager, NGINX API Connectivity Manager, and NGINX Ingress Controller) to this vulnerability. This issue has been classified as CWE-384: Session Fixation.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by installing a version listed in the Fixes introduced in column. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch and F5 recommends that you upgrade to a version with the fix (refer to the tables).

If the Fixes introduced in column lists a version prior to the one you are running, in the same branch, then your version should have the fix.

NGINX Plus

To resolve this issue for NGINX Plus, F5 recommends that you perform the following actions:

  1. Upgrade NGINX Plus to version R31 or later.
  2. Update the nginx-plus-module-njs module and nginx-openid-connect component.
    Note: For more information about updating the nginx-plus-module-njs module and nginx-openid-connect component to the latest version, refer to the nginx-openid-connect page.
  3. Verify you have installed the fixed version of the nginx-openid-connect component by entering the git log command from the directory to which you cloned the git repository. 

    For example, as displayed below, the fixed version should show a git commit output that is equal to or newer than Date: Thu Oct 24 23:15:54 2024 +0100 with a full commit hash of 133504f4fd9f72f3e36668f9f2f3d32a86fcb269:

Mitigation

End users should avoid clicking links from untrusted or unknown sources, especially those that may direct you to login pages.
