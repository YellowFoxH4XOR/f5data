Description

When you deploy a BIG-IP Next from Central Manager via the vSphere provider, after clicking deploy, an error occurs:
 
Error: Unable to create BIG-IP Next instance. Reason: template "default-standalone-ve": failed to render template: Parameters failed validation: { "default_gateway": "10.155.255.254", "dns_servers": [ "10.154.1.241" ], "hostname": "testnext.local", "instantiation_provider": [ { "id": "d23c97e5-4f96-4d3f-af42-796f7cc3854b", "name": "vSphere", "type": "vsphere" } ], "l1Networks": [ { "l1Link": { "linkType": "Interface", "name": "1.1" }, "name": "Internal", "vlans": [ { "name": "All", "selfIps": [ { "address": "10.10.10.75/24" } ], "tag": null } ] }, { "l1Link": { "linkType": "Interface", "name": "1.2" }, "name": "External", "vlans": [] } ], "management_address": "10.155.74.71", "management_credentials_password": "*****", "management_credentials_username": "admin-cm", "management_network_cidr_width": "/16", "ntp_servers": [ "10.154.1.241" ], "vSphere_properties": [ { "cluster_id": "domain-c1006", "datacenter_id": "datacenter-1001", "datastore_id": "datastore-2083", "resource_pool_id": "resgroup-1007", "vm_template_id": "ab8edb30-2f4b-48a6-be4d-fcabf48a8461", "vm_template_library_id": "56e5f965-37aa-4597-b601-788d577f07a8" } ] } Validation error: [ { "keyword": "type", "dataPath": ".l1Networks[0].vlans[0].tag", "schemaPath": "#/properties/l1Networks/items/properties/vlans/items/properties/tag/type", "params": { "type": "integer" }, "message": "should be integer" } ].

Environment

Relevant environmental factors specific to the topic
  • BIG-IP Next Central Manager
  • Deploying a new instance using the wizard for the vSphere provider

Cause

The most important part of the error message occurs at the every end of the string.  In this error message, the error is:
Validation error: [ { "keyword": "type", "dataPath": ".l1Networks[0].vlans[0].tag", "schemaPath": "#/properties/l1Networks/items/properties/vlans/items/properties/tag/type", "params": { "type": "integer" }, "message": "should be integer" } ].

The schema path is to "vlans", so the message means that a VLAN tag was not entered as an integer.  In BIG-IP Next v20.0, the wizard permits you to leave this field blank, which sends a NULL entry and that causes this validation error to occur.
 

Recommended Actions

  1. Identify the last portion of the error message, the portion that begins with "Validation Error" or "Message"
  2. In the message, review the schemaPath to identify what object is throwing the validation error
  3. Correct the error and re-submit the declaration (in this example, a VLAN tag of 0 is allowed)
