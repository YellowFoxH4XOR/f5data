Known Issue

The ARX system may incorrectly log Policy_Action messages at debug level.

This issue occurs when all of the following conditions are met:

  • The logging level POLICY_ACTION is set to notice (default level).

The configuration of the POLICY_ACTION facility is incorrectly being set to log at the debug level when configured for notice level. This causes the procdat to log aggressively and rotate every one to two minutes.

Impact

The system may experience a high level of disk I/O and performance degradation.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX 1500 and 2500 platforms may experience metalog latency issues. The ARX 1500 and 2500 platforms use disk instead of NVRAM for the metalog. The increased disk I/O, as a result of this issue, can cause a metalog latency condition.
  • Administrators notice Metalog latency errors within the logs.

    The log output appears similar to the following example:

    Wed Mar 07 001:01:01 2012 - metaLogLatencyRaise (291) : metalog latency is too
    high (disk/network/total completion time) 527/0/0
    Wed Mar 07 001:01:01 2012- metaLogLatencyClear (292) : metalog latency is
    normal (disk/network/total completion time) 49/0/0

  • The system fills the procdat logs with the following traps:

    DBG-RULE_MATCH_FILE_RESULT

  • The procdat log is rotating, on average, every one to two minutes.

Note: The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.

Workaround

To work around this issue, you can disable the offending logging action. To do so, perform the following procedure:

Disabling POLICY_ACTION logging category

Impact of workaround: You lose the logging of objects under the POLICY_ACTION logging group.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Enter the config configuration mode by typing the following command:

    config

  4. Display the current logging levels by typing the following command:

    show logging levels

    The POLICY_ACTION facility is set to notice as shown in the following example output:

    Configured Log Levels:
                     disable  debug   info   notice  warning  error critical
POLICY              |       |       |       |   X   |       |       |       |
POLICY_ACTION       |       |       |       |   X   |       |       |       | 
POLICY_CLI          |       |       |       |   X   |       |       |       |
POLICY_PDP          |       |       |       |   X   |       |       |       |
POLICY_PEP          |       |       |       |   X   |       |       |       |
POLICY_SHADOW       |       |       |       |   X   |       |       |       |
  5. Disable the logging of that facility using the following command syntax:    

    logging level POLICY_ACTION disable

    The POLICY_ACTION facility will be set to disable as shown in the following example output:

    Configured Log Levels:
                     disable  debug   info   notice  warning  error critical
POLICY              |       |       |       |   X   |       |       |       |
POLICY_ACTION       |  X    |       |       |       |       |       |       | 
POLICY_CLI          |       |       |       |   X   |       |       |       |
POLICY_PDP          |       |       |       |   X   |       |       |       |
POLICY_PEP          |       |       |       |   X   |       |       |       |
POLICY_SHADOW       |       |       |       |   X   |       |       |       |
  6. Exit the share configuration mode by entering the following command:

    exit
