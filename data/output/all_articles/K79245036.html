Description
This article provides the procedure on how to resolve truncated logs via iRule for large Active Directory Group MemberOf list in APM.

For whatever purpose, when capturing the log of the user APM session's AD Group MemberOf attribute via iRule like below, shows truncated:

ltm rule /Common/apm_ad_memberof_logging {
    when ACCESS_POLICY_AGENT_EVENT {
            set memberOf [ACCESS::session data get "session.ad.last.attr.memberOf"]
            log local0. "$memberOf"
    }
}

Although, when viewing the user APM session's AD Group MemberOf attribute using the sessiondump tool, it is not so:

# sessiondump --sid <sessionID/MRH> | grep session.ad.last.attr.memberOf

Environment

  • BIG-IP APM
  • BIG-IP LTM
  • iRule
  • Active Directory

Cause

None

Recommended Actions
The said logging becomes truncated because of the set message size limit for sending to a remote syslog server as explained in the old article K8306: Syslog enhancement supports larger message sizes sent to remote syslog servers using an iRule.

For BIG-IP 11.x and above, this is controlled in the db key tmm.maxremoteloglength. The default value is 1,024 bytes and the maximum value is 64,000 bytes.

You can slowly increase the value of the said db key e.g. 2048, 4096, and so on, until you acquire your preferred string length or full AD group memberof list.

Note: F5 recommends that before making any changes to your systems, you back up each system and store the backup in a remote and secure location. See K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

In the BIG-IP CLI, do the following: 

    To view the current db key value

    # tmsh list sys db tmm.maxremoteloglength all-properties
    sys db tmm.maxremoteloglength {
        default-value "1024"
        scf-config "true"
        value "1024"
        value-range "unsigned integer min:1024 max:65507"
    }

    To modify the db key value

    # tmsh modify sys db tmm.maxremoteloglength value <new value>
