K000163807: DB key values can revert without impact in tenant TMOS migrated from i2k

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163807

Description

On BIG-IP LTM 17.5.1, the database keys clusterd.communicateovertmmbp and deduplication.dictionary.size do not retain their configured values in a migrated tenant environment. This does not affect tenant TMOS functionality.

Environment

  • BIG-IP LTM 17.5.1
  • Tenant TMOS environment migrated from an i2k source system
  • Database keys: clusterd.communicateovertmmbp and deduplication.dictionary.size

Cause

These database keys are not used by the affected tenant environment. Their values can differ from the values set during migration without affecting tenant TMOS operation.

Answer/Recommended Actions

  • Ignore the values of clusterd.communicateovertmmbp and deduplication.dictionary.size in this environment.
  • Do not spend additional effort selecting or restoring specific values for these keys.
  • No configuration change is required to maintain tenant TMOS functionality.
  • If a separate functional impact is observed, collect the relevant diagnostic data and open a new investigation focused on that impact.

Additional Information

The behavior has no functional impact and is not considered a product bug. Value changes have been observed following a reboot, but this does not establish that both keys always change after every reboot.
