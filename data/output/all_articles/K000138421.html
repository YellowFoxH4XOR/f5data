K000138421: How to use Resolver directive in upstream block with Nginx Open Source

Type
Support Solution
Published
2024-01-31
Updated
2025-04-02
Applies to
  • NGINX Products
  • NGINX Plus
Source
https://my.f5.com/manage/s/article/K000138421

Description

  • You deployed Nginx Open Source and configure an upstream block with servers that are defined using domain name
  • The upstream uses the "resolve" parameters along "server" directive as well as the "resolver" directive as shown below. 
upstream backend {
  server example.upstream.local:1433 resolve;
  resolver 192.168.3.4;
}
  • However, the above fails to dynamically resolve upstream name all the time 

Environment

  • Nginx Open Source
  • Resolver directive

Cause

  • Nginx OSS does not have the full feature of Nginx Plus; hence, the use of "resolver" directive needs to be adjusted ever slightly.

Recommended Actions

  • In Nginx Open Source, to dynamically resolve upstream name, you need to use variable in proxy_pass directive from within the "server block" as shown below instead of using upstream group.
server {
  listen 1433;
  resolver 192.168.3.4;
  set $backend "example.upstream.local:1433";
  proxy_pass $backend;
}
