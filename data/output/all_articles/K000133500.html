Description

iApp scripts may intermittently produce an error message, which may also be displayed on the GUI:

ERROR: 'query_view' query reply did not contain a result object

 

Environment

  • An iApp that runs TCL scripts calling tmsh functions that query mcp or REST calls to mcp that intermittently generate the error

 

Cause

When there are more than one mcpd query running in parallel, mcpd may close a query connection early, causing the mcpd client to get a blank or corrupted response.

The issue is documented in ID 1136429. Note: Refer to the relevant bugtracker article to check the known affected versions.

This issue can affect configuration components that run multiple mcp connections, such as iApp implementations and REST calls to mcpd. The error message can be observed on the GUI, /var/log/restjavad.0.log, or scriptd debug logs.

Troubleshooting

If an mcp call is done by REST, restjavad.0.log messages may show the following:

from 127.0.0.1 failed because java.net.ProtocolException: status:400, body:{"code":400,"message":"The configuration was updated successfully but could not be retrieved. The error is \"ERROR: 'query_view' query reply did not contain a result object.\".","errorStack":[],"apiError":26214401}


If the problematic mcp call is run from scriptd, then scriptd.out might show the error as a response to another script call:

Feb 03 17:08:25.139753 Connection 0xe7165008 (user admin_f5) calling send() for message (req_id 0 seq 259):
 result {
  result_code 21954567
  result_message "script did not successfully complete: (ERROR: 'query_view' query reply did not contain a result object.
   while executing
 \"tmsh::get_config \"/gtm pool a $pool_name members\"\"


In order to collect complete mcp transactions for scriptd, you can do the following troubleshooting procedure:
 
1. Edit the scriptd startup script
   # vi /etc/bigstart/scripts/scriptd
 
2. Add the -m option to start scriptd to log all messages to and from mcpd. To do this, change this line:
 
exec /usr/bin/${service} > /var/tmp/${service}.out 2>&1
 
into these lines:
 
exec /usr/bin/${service} -m > /var/tmp/${service}.out 2>&1
# exec /usr/bin/${service} > /var/tmp/${service}.out 2>&1
 
3. Restart scriptd

   # bigstart restart scriptd
 

 

 Recommended Actions

Upgrade to a known version with a fix to Bug ID 1136429 .
