Known Issue

The SNMP daemon may unexpectedly terminate.

This issue occurs when the following condition is met:

  • Your BIG-IP device is configured for SNMP.

Impact

SNMP requests sent to the BIG-IP device fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the status of the SNMP daemon on the affected device, by using the tmsh show /sys service snmpd command, output appears similar the following example:

    snmpd run (pid 4649) 26 days, got TERM.

    Note: For BIG-IP 10.2.4 devices, the affected process is subsnmpd.

  • When attempting to retrieve SNMP metrics from the affected device, the SNMP request fails with an error message similar to the following example:

    No Such Object available on this agent at this OID

  • Error messages are logged to the /var/log/snmpd.log file, similar to the following example:

    Received broken packet. Closing session.

  • Error messages are logged to the /var/log/sflow_agent.log file, similar to the following example:

    AgentX session to master agent attempted to be re-opened.

Workaround

To work around this issue, you can restart the snmpd process on the affected device. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the snmpd process by typing one of the following commands:

    BIG-IP 11.x and later

    restart /sys service snmpd

    BIG-IP 10.2.4

    restart /sys service subsnmpd

  3. To exit the tmsh utility, type the following command:

    quit
