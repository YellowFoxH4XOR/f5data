Description

The BIG-IP ASM may write the following log message to /var/log/asm: "ASM subsystem error (asm_config_server.pl,F5::PrepareConf::Policy::prepare_alternate_response_file_tbl): failed to parse response headers - please check blocking response page" without an obvious triggering event. Behavior of the Login Page blocking page may function in an unexpected manner.

Environment

  • BIG-IP with ASM Module provisioned
  • BIG-IP managed by BIG-IQ with Web Application Security (ASM) Service configured for BIG-IP in BIG-IQ
  • One or more ASM Security Policies on BIG-IQ with Response Page: Login Page set to default of Default Response
  • Initial Deployment of one or more of the above ASM Security Policies from BIG-IQ to BIG-IP

Cause

BIG-IQ bug ID893977 results in the XML export of ASM Security Policies from BIG-IQ missing the response information for the Response Page: Login Page when the response is the default value of Default Response. If this truncated Security Policy (in XML format) is then imported into the BIG-IP, the "failed to parse response headers" error message will occur when that truncated Security Policy is parsed by the BIG-IP. This parse typically occurs once per restart of the asm process, typically at boot up or when the Policy is initially deployed by BIG-IQ to BIG-IP.

When BIG-IQ performs the initial deployment of an ASM Security Policy to BIG-IP it will export the Policy as XML and then import the Policy as XML into the BIG-IP. This automatic process can then trigger the above error message due to ID893977 truncating the Policy during the XML export process.

Recommended Actions

ID893977 is fixed in BIG-IQ 7.1 so this issue can be avoided entirely by upgrading to BIG-IQ to 7.1 or later.

If the log message is being reported on BIG-IP devices already, the below steps can resolve the occurrence. The steps are not service affecting, similar to a normal BIG-IQ policy update deployment.
  1. Configure existing and new ASM Security Policies in BIG-IQ to have a custom, rather than default value in the Response Page: Login Page. The custom value can have identical content as the default value with the only change being the response type set to "Custom Response" instead of "Default Response".
  2. Deploy the updated policies to all affected BIG-IPs.

Additional Information

If an ASM Child Security Policy inherits it's Response Pages from an ASM Parent Security Policy, the Response Page: Login Page change only needs to be made to the Parent policy with the change then applied to all of it's Child policies.

BIG-IP bug ID802873 (fixed in 16.0.0) improved ASM Security Policy import via XML by handling improper default values more robustly.
