Issue

This document is intended to provide basic steps for troubleshooting the loss of access to the Switch Card Control Processor (SCCP)/Always-On Management (AOM) subsystem.

Description

SCCP is a separate subsystem that provides control of the F5 switch hardware using the 10/100/1000 Ethernet management port over secure shell (SSH), or using the serial console. The following examples include ways you can use the SCCP subsystem:

  • Change the system boot device
  • Halt or restart the system
  • Perform specialized troubleshooting tasks as requested by F5 Technical Support

AOM is a separate subsystem that provides lights-out management for the BIG-IP system using the 10/100/1000 Ethernet management port over SSH, or using the serial console. The following examples include ways you can use the AOM subsystem:

  • Manage the BIG-IP platform even if the host subsystem is turned off
  • Reset the BIG-IP host subsystem if it locks up
  • Turn on or off and restart the BIG-IP host subsystem

To determine whether a specific BIG-IP platform has a SCCP subsystem or an AOM subsystem, refer to K9476: The F5 hardware/software compatibility matrix.

Symptoms

You can identify the loss o2f access to the SCCP/AOM subsystem when you encounter any of the following symptoms:

  • An attempt to connect to the SCCP or AOM subsystem using the management port over SSH times out
  • An attempt to connect to the SCCP or AOM subsystem using the ssh sccp or ssh aom command from the BIG-IP system command line fails
  • Serial console does not respond appropriately or display garbage characters
  • No response from the serial console when you press the Esc + Shift + 9 key combination

If you lose access to the AOM subsystem, you may not be able to manage the BIG-IP system using the AOM Command Menu through the serial console, or remotely by way of SSH to the AOM subsystem. However, the BIG-IP system’s traffic processing capability is unaffected.

If you lose access to the SCCP subsystem due to the subsystem failure, the BIG-IP system's traffic processing capability may be affected.

Procedures

When you lose serial console access to the SCCP/AOM subsystem, or remote access to the SCCP/AOM subsystem by way of the management port, you can use the following troubleshooting procedures:

  • Verifying the serial port baud and setting it, if necessary (specific for losing serial console access)
    • BIG-IP 2000/4000/5000/7000/1x000 Series appliances, VIPRION C4800 chassis

      To watch a video demo of this procedure, go to Verify and configure the serial port baud settings for BIG-IP 2000-10000 and VIPRION C4800.

    • BIG-IP iSeries appliances

      To watch a video demo of this procedure, go to Verify and configure the serial port baud settings for BIG-IP iSeries systems.

  • Correcting communication after a baud mismatch
  • Checking SSH authentication to the SCCP or AOM
  • Verifying your client’s network connectivity to the management port (specific for losing remote access)
  • Checking known issues
  • Additional troubleshooting

Verifying the serial port baud and setting it, if necessary (specific for losing serial console access)

By default, the serial console is configured to operate with the serial port baud set at 19200. If you cannot connect a serial console using that baud, you can use the LCD panel to check the serial console port baud. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

BIG-IP B2000/4000/5000/7000/1x000 Series appliances, VIPRION C4800 chassis

  1. On the LCD panel, press the X button to enter the menu.
  2. Using the Down Arrow button, select System.
  3. Press the Check button.
  4. Using the Down Arrow button, select Serial Speed.
  5. Press the Check button.
  6. Where LCD panel displays a check mark next to the baud, this value is the baud speed to which the serial port is currently set.

    Note: After step 6, the remaining steps are necessary only if you need to configure the serial port baud speed to match the baud settings on your client terminal software.

  7. Use the Up Arrow or Down Arrow button to select the desired baud speed that matches the baud settings on your client terminal software.
  8. Press the Check button.
  9. Press the X button twice to exit the menu.

BIG-IP iSeries appliances

  1. Tap on the LCD panel to start.
  2. Tap Setup.
  3. Tap Baud Rate.
  4. Where the LCP panel displays a check mark next to the baud, this value is the baud speed to which the serial port is currently set.

    Note: After step 4, the following additional steps are necessary only if you need to configure the serial port baud speed to match the baud settings on your client terminal software.

  5. Select your desired baud rate. For example, select 9600.
  6. Tap Commit.
  7. To verify the change, select Baud Rate again.
  8. Verify that the system is set to the desired baud rate.

Correcting communication after a baud mismatch

You may be able to restore serial communication using one of the following methods, which do not interrupt traffic processing:

  • After connecting to the serial console port again at the correct baud, enter several text characters (avoid using Enter). Some BIG-IP systems automatically detect the correct baud and recover the serial console without further action.

    Note: This method is generally effective for recovering BIG-IP systems that use a lights-out processor (LOP) or Serial Port Redirector (SPR) subsystem to manage the serial console interface, such as VIPRION 4xxx with B4200 or B4300 blades, VIPRION 2400/B2100 blades, and the BIG-IP 4000-series appliances.

  • After connecting to the serial console port again at the correct baud, access the AOM or SCCP menu by typing the following key sequence:

    ESC (

    Typically, the AOM or SCCP menu displays normally, even if the host subsystem console does not.

    a. Use the AOM or SCCP menu command to configure the AOM/SCCP baud, and re-select the same correct baud (for example: 19200 baud).

    b. Then, use the AOM or SCCP menu command to reconnect to the host subsystem console.

    Note: This method is generally effective for recovering BIG-IP systems that use an AOM or SCCP subsystem to manage the serial console interface, such as BIG-IP 1600, 3600, 3900, 6900, 8900/8950, 11000/11050, 1500, 3400/3410, 6400, 6800, 8400, and 8800 appliances.

  • After connecting to the serial console port again at the correct baud, access the AOM menu by typing the following key sequence:

    ESC (

    Typically, the AOM menu displays normally, even if the host subsystem console does not.

    a. Use the AOM menu command to reboot the AOM subsystem.

    b. Then, use the AOM menu command to reconnect to the host subsystem console.

    Note: This method is generally effective for recovering BIG-IP systems that use an AOM subsystem to manage the serial console interface, such as BIG-IP 1600, 3600, 3900, 6900, 8900/8950, and 11000/11050 appliances.

Checking SSH authentication to the SCCP or AOM

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

AOM on the following BIG-IP platforms supports SSH password authentication using the root password:

  • 2000, 4000, 5000, 7000, and 10000 series platforms

All other BIG-IP platforms use SSH host key authentication for AOM/SCCP access. If SSH authentication fails when attempting to access SCCP or AOM, you may need to regenerate the SSH host keys on the system. For more information, refer to K13532: Regenerating SSH host keys.

Verifying your client's network connectivity to the management port (specific for losing remote access)

You can verify your client's network connectivity to the SCCP/AOM subsystem management port by using the ping command on the client to perform a ping test to the IP address assigned to the SCCP/AOM subsystem. If the ping command does not receive a response, you may want to verify that there is no network device between the client and the SCCP/AOM subsystem that blocks traffic to the SCCP/AOM subsystem.

Checking known issues

The following articles are known issues that may affect the serial console access to the SCCP/AOM subsystem:

  • K10834: The serial port baud rate must match the Always-On Management baud rate
  • K12821: Modifying the baud rate configuration may result in garbled console output

The following articles are known issues that may affect the remote access to the SCCP/AOM subsystem by way of the management port:

  • K6126: Log files may grow too large and cause problems with the SCCP
  • K7036: The Linux uptime counter wraps after 497 days
  • K7193: A high volume of network traffic on the management port can cause the BIG-IP system to reboot
  • K7745: The SCCP password file is deleted when you create a user account that begins with root
  • K9084: Running the EUD from the lights-out management command menu (hostconsh) may cause the system to become inoperative
  • K10005: A high volume of network traffic on the management network may cause an SCCP watchdog timeout

Additional troubleshooting

If none of the previous procedures restore access to the SCCP/AOM subsystem, removing and restoring external power to the BIG-IP system may allow you to regain access.

Impact of procedure: The BIG-IP system does not process any traffic during the power cycle.

If the SCCP/AOM subsystem does not recover after a power cycle, contact F5 Technical Support.
