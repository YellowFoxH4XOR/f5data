Description

A Virtual Server is not getting RST's from client and possibly not FIN's.

This leaves the flow up until the TCP idle timeout clears it.

(Existing flows do not respond to SYN requests.)

Clearing the flow due to idle timeout  normally generates a RST from the Virtual Server back to the client and is detectable in traffic captures on the BIG-IP.


Environment

Azure Firewall talking to on premises BIG-IP via  a Palo Alto firewall.


Cause

The on premises Firewall, a Palo Alto, is set to deny Challenge Acks.

This causes further SYN to be ignored. That stalls new connections.

The Firewall filters the incoming RST's.

Recommended Actions

Enable the ‘tcp allow-challenge-ack’ feature  on the Firewall.


Additional Information


https://knowledgebase.paloaltonetworks.com/KCSArticleDetail?id=kA10g000000boBJCAY

https://datatracker.ietf.org/doc/html/rfc5961


If the Client is the Azure firewall, it may react by attempting to close connections by sending RST's.
