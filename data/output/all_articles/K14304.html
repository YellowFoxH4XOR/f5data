Known Issue

BIG-IP GTM systems running big3d 11.3.0 may experience iQuery communication issues with systems running previous versions of big3d.

This issue occurs when the following conditions are met:

  • One or more BIG-IP GTM synch group members are running big3d 11.3.0, and are attempting to communicate with other BIG-IP GTM synch group members that are running an earlier version of big3d. This situation can occur under the following scenarios:

    • One of the BIG-IP GTM sync group members was upgraded to 11.3.0, and the others are running an earlier version.
    • One of the BIG-IP GTM sync group members was upgraded to 11.3.0 and then rebooted to a volume containing a previous version of the BIG-IP GTM system.

      Note: When the BIG-IP system is upgraded to a new software version, the system copies the /usr/sbin/big3d process to the /shared/bin directory and runs the /shared/bin/big3d process. As a result, if you reboot to a volume running an older version of the BIG-IP system, the system continues to run the newer big3d version.

The BIG-IP 11.3.0 big3d process generates a sync_request message that is not properly interpreted by the mcpd process. As a result, iQuery communication may fail between the devices. This issue does not occur when all sync group members are running big3d 11.3.0.

Impact

The affected BIG-IP GTM sync group member may fail to synchronize configuration updates.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The /shared/bin/big3d -v command indicates that big3d 11.3.0 is running on the system.
  • The affected BIG-IP GTM sync group member may fail to synchronize configuration updates.
  • The system may log an error to the /var/log/ltm that appears similar to the following example:

    mcpd[5884]: 01070712:3: Caught configuration exception (0), Can't parse MCP message, unknown tag in message current message state: [sync_request tag:13044 state:1][start_commit_id tag:13047 state:2] status:18030 - msg++/MsgParser.cpp, line 1070.

  • The system may log an error to the /var/log/gtm that appears similar to the following example:

    gtmd[22680]: 011a0005:3: hookOnChild: SYNC syncer exited with error code 255

Workaround

If you upgraded the BIG-IP GTM sync group member to version 11.3.0, and then rebooted to a volume containing a previous version of the BIG-IP GTM system, you can restore the earlier big3d version. To do so, perform the following procedure:

Impact of workaround: This procedure requires that you reboot the system, which you should do during a maintenance window.

  1. Log in to the command line of the affected system.
  2. Verify the big3d version by entering the following command:

    /shared/bin/big3d -v

    The following output example indicates that the system is running big3d version 11.3.0:

    big3d version big3d Version 11.3.0.2806.0 for linux

  3. Stop the big3d process from running by entering the following command:

    bigstart stop big3d

  4. Remove the big3d process by entering the following command:

    rm -f /shared/bin/big3d

  5. Reboot the system.
  6. After the reboot, verify that the earlier big3d version is running, by entering the following command:

    /shared/bin/big3d -v

    The following output example indicates that the system is running big3d version 11.1.0:

    /shared/bin/big3d version big3d Version 11.1.0.2268.0 for linux
