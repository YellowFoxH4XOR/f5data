Description


BIGIP APM no longer allows users to authenticate. Everyone is affected.
Some log files may display a message: Agent not initialized during load

Environment

  • BIGIP APM
  • Users are authenticated with an "AD Auth" or a "LDAP Auth" agent.

Cause

This is very likely due to some corruption to the internal configuration database.

Recommended Actions
- Perform "Force sync" from the working node
OR
- Force the mcpd process to reload the BIG-IP configuration as per the article K13030
OR
- Deprovision the APM module and to provision it again:

  1. With the Configuration Utility, please navigate to  System  ››  Resource Provisioning
  2. Locate the "Access :Policy (APM)" line and uncheck the box within the "Provisioning" column;
  3. Click "Submit"
  4. Wait for the unit to process the change and for the Configuration Utility to be available again;
  5. Locate the Access :Policy (APM) line and check the box within the Provisioning column;
  6. Click "Submit"

Additional Information
The typical error message we can retrieve form the /var/log/apm file is:

<date> <time> bigip err apmd[14069]: 014902bd:3: /Common/AccessProfile:Common:12345678: Agent: /Common/Access_Profile_act_ldap_auth_ag, not initialized during load
