K000158089: You would like to cover multiple version of Chrome in BoT Defense Signature with Advanced Rule with the wildcard syntax

Type
Support Solution
Published
2025-12-05
Updated
2025-12-05
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000158089

Description

You would like to create custom Bot Defense and ASM (Application Security Manager) signatures in BIG-IP Advanced WAF to match specific Chrome browser versions range. The issue addressed is the inability to use wildcards (*) in Bot Defense signature syntax, which results in errors such as "Bad dos signature rule." 

Environment

  • Custom Bot Defense Signatures
  • Custom ASM Attack Signatures

Cause

Bot Defense signature syntax does not support wildcards (*) in the headercontent or uricontent fields. Pattern matching for version ranges requires the use of regular expressions (regex).

Recommended Actions

Use a ASM Custom Signatures instead of Bot defense Signatures as they are more granular:

  1. Navigate Security >> Options >> Application Security >> Attack Signatures
  2. Click Create in the top right corner
  3. Navigate to Rule * and select Advanced mode
  4. Use regex within the headercontent field to match a range of Chrome versions in the Example (to match Chrome versions 81–87):
headercontent:"Chrome/(8[1-7])\.[0-9]+\.[0-9]+\.[0-9]+"; nocase; useragentonly;

Explanation:

    • headercontent: inspects the HTTP User-Agent header.
    • "Chrome/(8[1-7])\.[0-9]+\.[0-9]+\.[0-9]+" matches any User-Agent string reporting Chrome version from 81 through 87.
    • nocase; makes it case-insensitive.
    • useragentonly; restricts inspection to the User-Agent header.
