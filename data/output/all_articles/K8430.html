Topic

This article applies to BIG-IP 9.x - 10.x. For information about other versions, refer to the following article:

  • K13418: Archiving UCS files using the logrotate and crontab utilities (11.x - 13.x)

F5 recommends that you save archived user configuration set (UCS) files offsite for secure disaster recovery methods. However, if you archive the UCS files locally, you can use them for testing or to allow quick access to backups.

Note: F5 recommends that you use the BIG-IP Enterprise Manager, iControl, or another method to save and store UCS files offsite for production implementations.

Saving multiple UCS files locally can quickly consume all available space on a partition, depending on the size and number of UCS files saved. The larger the files and the more frequently the files are created, the faster the partition space will be used.

The following two utilities can lessen the impact of archiving UCS files locally:

  • Crontab

    This utility creates and controls the frequency that the UCS files are created.

  • Logrotate

    This utility rotates the UCS files to save space.

    Note: F5 recommends that you do not use the logrotate method on compact flash-only systems, due to the limited available space.

Note: For more information about UCS archives, refer to the following articles:

  • K4423: Overview of UCS archives
  • K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive

Automating a local UCS archive

Important: The configuration produced by the following procedures may not survive a software upgrade. You may need to repeat the procedures after performing a software upgrade, or after installing a hotfix.

Alternatively, these changes may persist an upgrade or hotfix installation if you include the edited files in a UCS file collection. For more information about modifying the contents of UCS files, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

To automate a local UCS archive, you must perform the following procedures:

  • Creating a local directory to store and rotate the UCS files
  • Creating a custom crontab entry to specify the frequency at which the UCS backup file should be created
  • Creating a custom logrotate entry to rotate the UCS files

Note: In the following procedures, F5 assumes that you are logged in to the command line.

Creating a local directory to store and rotate the UCS files

Note: F5 recommends that you create the directory under the /var directory, which resides on the shared partition (the largest partition on the system).

Note: This directory is not guaranteed to remain after an upgrade. You will most likely need to re-create the directory after an upgrade.

Creating a custom crontab entry to specify the frequency at which the UCS backup file should be created

  1. Check the current crontab entries for root by typing the following command:

    crontab –l

  2. Edit the root crontab file by typing the following command:

    crontab -e

    Note: This command invokes the vi editor.

  3. Select one of the following entries to add the root crontab file, depending on the frequency for which the UCS backup files will be created:

    Note: Replace <hostname> with the name of the system or the FQDN of the system.

    • Daily backup

      The following entry will create a UCS backup every day at 3 a.m.:

      00 3 * * * bigpipe config save /var/ucs/<hostname>.ucs

    • Weekly backup

      The following entry will create a UCS backup once a week on Sunday at 3 a.m.:

      00 3 * * 0 bigpipe config save /var/ucs/<hostname>.ucs

    • Monthly backup

      The following entry will create a UCS backup once a month on the 1st of the month at 3 a.m.:

      00 3 1 * * bigpipe config save /var/ucs/<hostname>.ucs

  4. To enter insert mode, type i in the editor.
  5. On a new line in the root crontab file, type one of the options listed in Step 3, or refer to the Creating a custom archive schedule procedure to configure a custom schedule that meets your needs.

    For example:

    # cron tab for root1-59/30 * * * * /usr/bin/diskmonitor
    00 3 * * * bigpipe config save /var/ucs/<hostname>.ucs

  6. Press the ESC key to exit from insert mode.
  7. Simultaneously press the Shift and the colon (:) key, as follows:

    :

  8. To save the changes and quit the editor, type the following at the vi command prompt:

    wq

Creating a custom logrotate entry to rotate the UCS files

The logrotate utility is used to rotate the archive files for a period of eight days, after which the oldest UCS archive is removed from the system. The cron.daily script runs the logrotate utility once a day.

BIG-IP 9.0.0 through 9.4.1

  1. Change directories to the /etc/logrotate.d directory by typing the following command:

    cd /etc/logrotate.d

  2. Create a backup of the current syslog-ng file by typing the following command:

    cp syslog-ng /var/tmp/syslog-ng.original

    Note: This backup ensures that the syslog-ng file can be restored to its original form, if needed, during the editing process. Once the changes are made, the backup file in the /var/tmp/ directory can be deleted.

  3. Edit the syslog-ng file using a text editor.
  4. Add the following to the end of the file:

    /var/ucs/<hostname>.ucs {
    nocompress
    missingok
    notifempty
    sharedscripts
    postrotate
    /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true
    endscript
    }

    Note: Replace <hostname> with the name of the system or the FQDN of the system. The <hostname> should match that of the <hostname> specified in the crontab, as this name will be used by logrotate to locate and rotate the archive backup.

    Note: The rotated UCS archive is not compressed as the file is already in a compressed state. In addition, the compression creates a larger file and adds an additional step that is required to uncompress before loading the file.

  5. Save the changes to the syslog-ng file.

BIG-IP 9.4.2 and later

Beginning with BIG-IP 9.4.2, many UNIX utilities are now accessed only through the bigpipe shell utility. To create a custom logrotate entry for versions 9.4.2 and later, perform the following procedure:

  1. Enter the bigpipe shell utility by typing the following command:

    bigpipe shell

  2. Enter the following logrotate command at the bigpipe shell prompt:

    logrotate syslog include "/var/ucs/<hostname>.ucs {
    nocompress
    missingok
    notifempty
    sharedscripts
    postrotate
    /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true
    endscript
    }"

    Note: Replace <hostname> with the name of the system or the FQDN of the system. The <hostname> should match that of the <hostname> specified in the crontab, as this name will be used by logrotate to locate and rotate the archive backup.

    When entering from a bigpipe shell prompt, the logrotate command syntax appears similar to the following example:

    bp>logrotate syslog include "/var/ucs/<hostname>.net.ucs {
    >>>nocompress
    >>>missingok
    >>>notifempty
    >>>sharedscripts
    >>>postrotate
    >>>/bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true
    >>>endscript
    >>>}

  3. To exit, type quit at the bp> prompt.
  4. Verify that the previous information is entered into the system by typing the following command:

    bigpipe logrotate syslog include show

    The output appears similar to the following example:

    LOGROTATE - Include Data for syslog logrotate file: /var/ucs/asm.askf5lab.net.ucs
    {
    nocompress
    missingok
    notifempty
    sharedscript
    postrotate
    /bin/kill -HUP `cat /var/run/syslog-ng.pid 2> /dev/null` 2> /dev/null || true
    endscript
    }

The UCS archive files are now placed in /var/ucs using the syntax <hostname>.ucs. The archive files are then rotated by logrotate and appended with a number indicating the status of the files rotation. Files are archived for a maximum of eight days, specified by the .1 through .8. The current archive file does not contain a <number>. After eight days, the last archive file is removed and previous archive files are incremented by 1.

Creating a custom archive schedule

You can customize the archive schedule by setting specific values for the date and time fields in the crontab file. The first five columns in each line represent the time and date on which the action in the sixth column will be executed. The time and date fields are as follows:

FieldPossible values
minute0 through 59
hour0 through 23
day of month1 through 31
month1 through 12, or the first three letters of the month (not case sensitive).
day of week0 through 7, or or the first three letters of the day (not case sensitive). Sunday is numerically represented by both 0 and 7. Therefore, for Sunday, you could enter any of the following three values: 0, 7, or Sun.
  • A field may be an asterisk ( * ), which always stands for first through last.
  • Ranges of numbers are allowed. Ranges are two numbers separated with a hyphen. The specified range is inclusive. For example, 8-11 for an hours entry specifies execution at hours 8, 9, 10, and 11.
  • Lists are allowed. A list is a set of numbers (or ranges) separated by commas. For example: 1,2,5,9 or 0-4,8-12.
  • Step values can be used in conjunction with ranges. Following a range with /<number> specifies skips of the number's value through the range. For example, 0-23/2 can be used in the hours field to specify command execution every other hour. Steps are also permitted after an asterisk. Therefore, if you want to say every two hours, just use */2.
  • Ranges or lists of names are not allowed.

Note: For more information about crontab and the crontab file, type man crontab at the command line, or refer to the following documents:

  • crontab(1) - Linux man page
  • crontab(5) - Linux man page
