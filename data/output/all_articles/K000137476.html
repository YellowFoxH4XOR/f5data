Description

BIG-IP GUI is unresponsive and slow, almost unusable.

mcpd CPU usage is observed to be high when viewed using Linux utilities such as top or ps, or with tmctl commands.

The /var/log/ltm logs contain one or more mcpd error relating to pools that use FQDN nodes.

Example error:

err mcpd[<pid>]: 01070622:3: The monitor /Common/https has a wildcard destination service and cannot be associated with a node that has a zero service.

Environment

  • GUI
  • FQDN nodes configured

Cause

  • Bug ID 990173: Dynconfd repeatedly sends the same mcp message to mcpd

Recommended Actions

You can resolve this issue by identifying the root cause of the mcpd error that is triggering the problem.

Using the example given in the description of this article, the problem is caused by applying a TCP-based monitor to a a pool member that is configured with a non-zero port:

ltm pool /Common/problem-pool {
    members {
        /Common/problem.pool.example.com:0 {
            fqdn {                     ^______ Note
                autopopulate enabled
                name problem.pool.example.com
            }
        }
    }
    monitor /Common/https
}

This configuration should be fixed by either using a non-zero port, or removing the TCP-based monitor (/Common/https in this example).

Additional Information

High CPU usage of mcpd might be caused by other factors. Some of those are:

  • Excessive SNMP polling
  • Excessive use of the REST API
  • Frequent configuration updates
  • Software defects
