Description

In some scenarios, when the BIG-IP is the Identity Provider IdP it is required to send different Service Providers SP initiated connections down different branches in the Visual Policy Editor VPE.
Note: This solution is only designed for POST SAML Authn Request Binding from the SP. Redirect binding will place the SAML Authn Request in the URL and need additional configuration to work as intended.

Environment

  • BIG-IP APM
  • BIG-IP as IdP
  • Multiple SPs

Cause

By default, the BIG-IP as IdP does not have the ability to identify each SP before choosing which branch to send the user down for authentication.

Recommended Actions

To accomplish this, it will require that each of your SPs update their SSO URL that points to the BIG-IP as IdP. The following steps outline how to choose each branch based off the SSO URL Landing URI.

  1. For example the Single Sign On URL for the first SP:
    SP1: https://idp.example.local/sp1

  2. On the BIG-IP as IdP, open the Visual Policy Editor for the IdP
    Access  ››  Profiles / Policies : Access Profiles (Per-Session Policies)  ››  Choose your IdP

  3. Click on Edit... under the Per-Session Policy column

  4. As the first action of the VPE click on the + to add a new action

  5. Click on General Purpose  ››  Choose Empty and click Add Item

  6. Click on the Branch Rules tab  ››  click on  Add Branch Rule and give it a name sp1

  7. Click on change  ››  Add Expression

    NameValue
    ContextLanding URI
    ConditionLanding URI
    Landing URI is/sp1

  8. Click on Add Expression  ›› Click on the Advanced tab

  9. Manually change == to starts_with
    expr { [mcget {session.server.landinguri}] starts_with "/sp1" }

  10. Click Finished  ›› Click Save

Next you will need to reassign the Landing URI to /saml/idp/profile/redirectorpost/sso/, this is what is going to allow the BIG-IP to recognize the SAMLRequest as SP-initiated SAML.

  1. Directly after the matched Landing URI branch, click the + to add a new action

  2. Click on Assignment  ›› choose Variable Assign  ››  Click Add Item

  3. Click on Add new entry  ›› Click on change

    NameValue
    Custom Variablesession.server.landinguri
    Custom Expressionreturn {/saml/idp/profile/redirectorpost/sso/}

  4. Click Finished  ›› Click Save

Note: You will need to repeat this process for each branch for each SP.
Note: This must be your first action within your Visual Policy Editor and NOT within a Macro.

Additional Information

The BIG-IP requires that all SAMLRequests are sent to the SSO URL /saml/idp/profile/redirectorpost/sso/.  This URL is how the BIG-IP recognized that the SAMLRequest and triggers SP-initiated SAML.
For example, if the host virtual server is https://idp.example.com, type: https://idp.example.com/saml/idp/profile/redirectorpost/sso
This article outlines how to workaround this requirement for multiple SP-initiated connections for multiple branches.
