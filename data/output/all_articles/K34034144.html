K34034144: Support for unique DiameterIdentity when Connection Mode for the Diameter Message Routing Peer is set to Per TMM

Applies to

Topic

For some settings in the Diameter Session profile, you can include one or more macros to ensure the uniqueness of the DiameterIdentity for certain attribute value pairs (AVPs) in diameter messages egressing from the BIG-IP system.

Description

When you set the Connection Mode setting for the Diameter Message Routing Peer to Per TMM, each Traffic Management Microkernel (TMM) can maintain its own connection to the backend diameter nodes. Starting in BIG-IP 14.1.0, you can assign a unique DiameterIdentity to each TMM when you configure the following Diameter Session profile settings:

  • Origin Host Rewrite
  • Origin Realm Rewrite
  • Destination Host Rewrite
  • Destination Realm Rewrite
  • Origin Host (Capabilities Handshake)
  • Origin Realm (Capabilities Handshake)

To do so, specify one or more of the following macros in your desired identifier.

MacroDescription
$gIncludes the blade number where the diameter message is egressing. If the BIG-IP system is not a chassis-based platform, it returns the value of zero (0).
$uIncludes the TMM number where the diameter message is egressing.
$rIncludes the ID of the route domain which the diameter message is egressing.
$mIncludes the identifier for the Connection Mode setting of the Diameter Message Routing Peer where the returning value of:
  • 1 is Per Peer.
  • 2 is Per Blade.
  • 3 is Per TMM.
  • 4 is Per Client.
$iIncludes the connection instance number if multiple connections are defined. 

For example, in the Diameter Session profile, you can specify the following identifier in the Origin Host Rewrite setting:

blade$gtmm$urd$rconn$mint$i.askf5.local

The Origin Host AVP of the diameter message egressing the BIG-IP system should appear similar to the following example:

Origin-Host: blade0tmm3rd0conn3int0.askf5.local
