K6757: Compressed content that exceeds the compression buffer can be truncated or can cause the connection to fail

Known Issue

This is the result of a known issue. If you configure a BIG-IP LTM virtual server to use the HTTP Compression module and the payload of the content to be compressed exceeds the configured buffer size, the connection may fail, or the files and pages can be truncated.

The compression buffer is a temporary holding area. As information is being compressed before it is sent to the client, the server sends a response to the BIG-IP LTM to hold the information. When the specified buffer memory is exceeded, the BIG-IP LTM sends the information that is contained within the buffer and closes the connection. As a result, the client does not receive information exceeding the defined buffer space.

The BIG-IP LTM may indicate this known issue with the following behavior:

  • If JavaScript is used on the page, the browser might display a message in the message bar indicating the JavaScript has been truncated
  • If the client connects through SSL, the following error message may display:

    ERROR_HTTP_INVALID_SERVER_RESPONSE

    F5 Product Development tracked this issue as CR56880 and it was fixed in BIG-IP LTM 9.1.3. For information about upgrading, refer to the BIG-IP LTM Release Notes.

    Workaround

    You can work around this issue by increasing the compression buffer size in the HTTP profile to exceed the already-compressed content size.

    Increasing the compression buffer size

    To increase the compression buffer size in the HTTP profile to exceed the already-compressed content size. To do so, perform the following procedure:

    1. Log in to the BIG-IP LTM Configuration utility.
    2. Choose HTTP Profile.
    3. Select Local Traffic.
    4. Select Profiles.
    5. Select your custom HTTP profile.
    6. Select Compression.
    7. Adjust the Compression Buffer Size.

      Note: The default size of the compression buffer size is 4096 bytes (4 kB). You can increase the compression buffer size by increments of 1024 bytes.


    Decreasing the compression buffer size

    To decrease the compression buffer size, perform the following procedure:

    1. Log in to the BIG-IP LTM Configuration utility.
    2. Choose HTTP Profile.
    3. Select Local Traffic.
    4. Select Profiles.
    5. Select your custom HTTP profile
    6. Select Response Chunking.

      Note: The default setting for Response Chunking is Preserve.
    7. Select Rechunk.
