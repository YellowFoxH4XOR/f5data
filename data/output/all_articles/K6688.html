Known Issue

This is the result of a known issue. When a user running a Windows-based operating system enters Protected Workspace, then launches a Network Access Favorite, then terminates Protected Workspace without first terminating the Network Access, the user will leave Protected Workspace and be returned to their normal Desktop environment. However, the temporary host file entries made by the Network Access control will not be removed.

Note: When not using Protected Workspace, host file entries are properly removed, regardless of whether the user terminates the Network Access.

When a Network Access Favorite is launched, the Network Access control attempts to write entries into the local host file (typically C:\Windows\System32\drivers\etc\hosts) for the FirePass controller and for any hosts configured in the Static Hostnames section on the Hosts tab of the Network Access: Resources page. For example:

192.168.8.11 myfp.mycompany.com #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#
192.168.8.11 myfp #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#
10.123.321.1 somehost.corp.mycompany.com #ADDED BY F5 NETWORKS SSL TUNNEL - ORIGINAL RECORD#

The first two entries are the entries for the FirePass controller. The third entry is configured as a Static Hostname.

If the following sequence occurs, the host entries will not be removed:

  • A user connects to the logon page of a FirePass controller.
  • The user is placed into Protected Workspace by a Pre-logon Sequence.
  • The user logs into FirePass controller.
  • The user launches a Network Access Favorite.
  • The user later clicks the Logout button on the Webtop, or double-clicks the Exit Protected Workspace shortcut on the Desktop, without first clicking the Terminate button in the Network Access pop-up window.

This can cause issues. For example, if the FirePass controller's hostname maps to multiple IP addresses in DNS. Many-to-one mappings are used when multiple FirePass units are load balanced by an F5 Global Traffic Manager or similar device. An unremoved host file entry would cause the user to connect to the same FirePass controller every time, instead of gaining the benefit of the load balancing from the Global Traffic Manager.

F5 Product Development tracked this issue as CR68036 and CR66982, and it was fixed in FirePass versions 6.0.1 and 5.5.2. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in Cumulative Hotfix HF-600-8 for FirePass version 6.0.0. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can ensure that the host file entries are removed by terminating the Network Access Favorite prior to logging off the FirePass controller when inside Protected Workspace.

To remove the temporary host file entries, you can log into the FirePass controller, start Network Access, and terminate it normally. The FirePass Network Access control will clean up all needed entries. Alternatively, you may edit your hosts file with a text editor to remove the entries.
