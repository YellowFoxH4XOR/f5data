Topic

The nitrox_diag command line utility is useful for gathering diagnostic data when a Cavium Nitrox Secure Sockets Layer (SSL) hardware accelerator card experiences hardware errors. The following platform series have Cavium Nitrox SSL hardware acceleration cards installed:

  • BIG-IP i11400-DS, i11600-DS, i11800-DS
  • BIG-IP 1600, 3600, 3900, 5000, 6900, 7000, 8900, 10000, 11000, 12000
  • VIPRION 2100, 2150, 2250, 4100, 4200, 4300

Description

BIG-IP systems use SSL hardware accelerator cards to improve SSL traffic processing. On rare occasions, an SSL hardware accelerator card may experience hardware errors. As a result of these hardware errors, SSL applications may experience latent or even failing SSL connections.

Beginning in BIG-IP 11.5.4 HF3, 11.6.1 HF2, and 12.1.2 HF1, the nitrox_diag utility was created to help diagnose hardware errors associated with Cavium Nitrox SSL hardware accelerator cards. The utility helps to determine why hardware errors are occurring by gathering the following diagnostic data:

  • Register information from PCIe switch chips
  • Register information from the Cavium Nitrox card
  • Cryptography related statistics from the Traffic Management Microkernel (TMM)
  • Cavium Nitrox-related information from the Linux kernel
  • QKView file
  • TMM core file

After creating the diagnostic data file, you should contact F5 Technical Support for further troubleshooting assistance. Follow the steps detailed in the following sections to correctly run and gather the diagnostic file that a support representative will need to further assist you.

Running the nitrox_diag utility

The nitrox_diag utility should be run while the BIG-IP system is experiencing SSL accelerator card hardware errors. While the utility is gathering diagnostic information and during the rebooting process, the BIG-IP system will not process traffic. To run the nitrox_diag utility and reboot the BIG-IP system after creating a diagnostic data file, log in to the Advanced Shell (bash) and type the following command:

nitrox_diag -r

The diagnostic utility can be run using the following options:

  • -s creates and stores only a single diagnostic file.
  • -d specifies an alternate directory to store diagnostic data files.
  • -r reboots the BIG-IP system after creating diagnostics data files.

Gathering the diagnostic data file

By default, the nitrox_diag utility collects all of the results in a single diagnostic data file that can be found in the /shared/nitroxdiag directory. The utility stores up to five files, the lowest numbered file representing the most current diagnostic data file. In the following example, nitroxdiag1.tar.gz is the most current diagnostic data file:

ls -1 /shared/nitroxdiag
nitroxdiag1.tar.gz
nitroxdiag2.tar.gz
nitroxdiag3.tar.gz

Note: Diagnostic output from the nitrox_diag utility may be truncated due to a 5 MB limitation. To capture the full output, you can specify no size limit for the diagnostic data using the qkview -s0 command, or create an archive of the log files. For more information about archiving log files, refer to K135: Information required when opening a support case for BIG-IP LTM, AFM, DNS, Link Controller, and PEM.

After the BIG-IP system has rebooted and become accessible, transfer the diagnostic data file from the BIG-IP system to your workstation. For assistance with transferring files, refer to K175: Transferring files to or from an F5 system.

For assistance creating a support case, refer to K2633: Instructions for submitting a support case to F5.

Recommendations

Configuring a custom SNMP trap

You can configure a custom SNMP trap to alert you when a Cavium Nitrox SSL accelerator card experiences hardware errors. For example, a message similar to the following is logged to the /var/log/ltm file when the SSL accelerator card experiences a hardware error:

tmm[123456]: 01010025:2: Device error: crypto codec cn-crypto-3 queue is stuck.
tmm[123456]: 01010260:2: Hardware Error(Co-Processor): n3-crypto1 request queue stuck

For more information about configuring custom SNMP traps, refer to K3727: Configuring custom SNMP traps.
