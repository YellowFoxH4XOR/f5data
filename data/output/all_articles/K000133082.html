K000133082: [F5OS-A] Is there any difference the way r5000/r10000 and r2000/r4000 manage tenant interfaces

Type
Support Solution
Published
2023-04-21
Updated
2025-01-27
Applies to

  • rSeries Platforms
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000133082

Description

A new build attempting to present a LAG and Interfaces on the r5000 series's. The tenant sees the LAG, but not the physicals Interfaces.
However r2000/r4000 series's tenant does not have any problem

Environment

  • F5OS-A
  • rSeries r2000/r4000
  • rSeries r5000/r10000
  • Tenants
  • Interface 

Cause

Expected behavior depending on platform.

r2000 / r4000 series use SR-IOV, so the tenant sees the actual physical interfaces and has knowledge of what the network config is supposed to look like (i.e. what VLANs are attached to which interfaces/trunks).

r5000 / r10000 function like tenants on VELOS and vCMP guests; the tenant has no knowledge or insight into the physical networking on the system with the *exception* of the fact it can see a trunk object for the purposes of HA groups.

Recommended Actions

The below is expected for a r5000 / r10000 rSeries appliance:

net trunk Example_30 {

distribution-hash src-dst-mac

interfaces {

3.0

4.0

}

stp disabled

type ha-only

}

net vlan /Common/CTE_Internal_F5_Pool {

tag 3723

}

net vlan /Common/CTE_Internal_F5_VIP {

tag 1123

}
 

The below is r2000 / r4000 rSeries appliance (note the "type vcmp-shadow" and the association of a VLAN to a particular trunk defined in the tenant)

net trunk LAG_Example-core-leaf125_126 {

distribution-hash src-dst-mac

interfaces {

1.7

1.8

}

stp disabled

type vcmp-shadow

}

net vlan /Common/Dev-external-enclave {

dag-adjustment none

interfaces {

LAG_pdc-co-core-leaf125_126 { # NOTE: this value is only present on low-end rSeries appliances.

tagged

}

}

mtu 9000

tag 493

}
