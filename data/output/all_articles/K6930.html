Known Issue

Note: This issue only effects the Japanese version of MSSQL server running on the Japanese version of Microsoft Windows Server.

This is the result of a known issue. The MSSQL health monitor incorrectly marks the Japanese version of the MSSQL server as down even if the login attempt is successful.

This issue occurs when the /usr/java/j2re/lib/charset.jar file is missing on both the BIG-IP LTM and the classpath of the DBDaemon.

When this issue occurs, the monitor receives the following error message/SQL exception from the MSSQL server:

Unsupported VM encoding MS932

The error message is only seen if debug is enabled on the MSSQL monitor. When debug is enabled, the log information will be written to the log file listed below, substituting the name of the monitor name, node ip address and node port as part of the log name:

/var/log/MSSQL_<monitor name>.::ffff:<node ip address>..<node port>.log

F5 Product Development tracked this issue as CR72666, and it was fixed in BIG-IP versions 9.3.0 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

This issue still exists in BIG-IP version 9.1.x software branch.

Workaround

To work around this issue, you can manually copy the charset.jar file to the /usr/jva/j2re/lib/ directory, allowing multiple character sets to be recognized by the monitor. To do so, perform the following procedure:

  1. Download the charset.jar file.
  2. Copy the charset.jar file to your BIG-IP LTM system using SCP.
  3. Save the charset.jar file to the /usr/java/j2re/lib/ directory.
  4. Reboot the BIG-IP system or issue the following command from the command line to restart the MSSQL monitor:

    /usr/bin/monitors/builtins/DB_monitor cmd quit

    Note: This command will stop the current MSSQL monitor and the system will start a new MSSQL monitor that will read the necessary information from the charset.jar file.
