Known Issue

The End-User Diagnostics (EUD) utility may incorrectly report a failure when testing an empty SFP/SFP+ port.

This issue occurs when all of the following conditions are met:

  • The platform being tested is a BIG-IP 8900 with one or more empty SFP/SFP+ ports.
  • You are running EUD 12.9.0 or 12.10.0
  • You have run either of the following EUD tests:
    • 3 SFP/SFP+ Report
    • A Run All (Non-Interactive) Test

When testing empty SFP/SFP+ ports, the EUD test intermittently fails and reports that the SFP module could not be read. However, this is a false positive failure report and is not indicative of a hardware failure.

Impact

You will see a false indication of a hardware failure.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H432703 on the Diagnostics > Identified > High screen.
  • The SFP/SFP+ section of the EUD test report indicates a failure similar to the following example:

    Executing SFP/SFP+ Report ....
    Test Begin: SFP/SFP+ Report
    Port 2.1 SFP : Not Present
    Port 2.2 SFP : Not Present
    ERROR: Could not read SFP module at 0x50
    ERROR: Could not read SFP for port 2.3
    Port 2.4 SFP : Not Present
    Port 2.5 SFP : Not Present
    Port 2.6 SFP : Not Present
    Port 2.7 SFP : Not Present
    Port 2.8 SFP : Not Present
    Port 3.1 SFP+ : Not Present
    Port 3.2 SFP+ : Not Present
    Test Complete: SFP/SFP+ Report: FAILED

  • The EUD menu then indicates that the SFP/SFP+ test passed, and appears similar to the following example:

    ==================================================
    Product: F5 Networks End User Diagnostics
    Build: EUD_M build 12.10.0.3.0
    Platform: BIG-IP 8900
    Serial Number: f5-abcd-efgh
    ==================================================

    System Tests:
    1 System Report
    2 Sensor Report
    3 SFP/SFP+ Report ...................... PASSED
    4 I2C Test
    5 PCI Test

    ---output truncated for display purposes---

Status

Workaround

There is no workaround for this issue. You should verify that the SFP/SFP+ port is actually empty and then re-run the test.
