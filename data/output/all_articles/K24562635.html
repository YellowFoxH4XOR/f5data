Description

Unable to do ConfigSync due to Internal Virtual Servers using a Destination / Virtual Address which resides in a different partition.

Sync error on bigip1.example: Load failed from /Common/bigip2.example 01070726:3: Virtual Address /nonprod/0.0.0.0 in partition nonprod cannot be referenced by Virtual Server /prod/icap_vs_1344 in partition prod

Example configuration:

ltm virtual-address /nonprod/0.0.0.0 {
    address any
    arp disabled
    icmp-echo disabled
    mask any
    spanning disabled
    traffic-group /Common/traffic-group-1
}

Note: This example Virtual Address resides in the nonprod partition, while the Virtual Server referenced in the error resides in the prod partition.

Environment

  • ConfigSync
  • Internal Virtual Server
  • Multiple partitions

Cause

Bug ID 723306

This configuration would ordinarily be considered invalid because a Virtual Server cannot reference a Virtual Address in another partition. The exception to this is if the Virtual Address resides in the Common partition.

The Internal Virtual Server is a special use case and should be exempt from the normal rules, but it is not, resulting in the error - this is tracked in bug ID 723306.

Internal Virtual Servers always reference Destination 0.0.0.0 in the configuration, and this cannot be changed. The Destination address is never actually used.

The fix for bug ID 723306 allows an Internal Virtual Server to reference a 0.0.0.0 Virtual Address in a non-Common partition. This would not ordinarily be permitted, for example, with a non-Internal Virtual Server.

Note: While running an affected version, the configuration will also fail to load.

Recommended Actions

To work around the issue on affected versions, move the 0.0.0.0 Virtual Address to the Common partition, which will allow Virtual Servers in other partitions to reference it. This may require temporarily deleting Virtual Servers that use the Virtual Address. An alternative approach is to modify the bigip.conf files, moving the Virtual Address to the Common /config/bigip.conf file - then reload the configuration with tmsh load sys config.

Important: Reloading the BIG-IP configuration is potentially traffic disrupting, so this should be done in a maintenance window.
