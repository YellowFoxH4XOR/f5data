Description

Queries to BIG-IP DNS (using a cache resolver with a forward-zone for a specific FQDN) return SERVFAIL or time out. Packet captures show BIG-IP forwarding the initial query to the configured nameserver and receiving a CNAME response.

However, BIG-IP does not return the final A record to the client, only the CNAME (or nothing).

Dns cache debug logs includes logs similar to:

Jan 25 23:20:41 LTM1.example.com info tmm[11700]: DNScache: response for example.com. A IN
Jan 25 23:20:41 LTM1.example.com info tmm[11700]: DNScache: reply from <example.com> 10.10.10.10#53
Jan 25 23:20:41 LTM1.example.com info tmm[11700]: DNScache: incoming scrubbed packet: ;; ->>HEADER<<- opcode: QUERY, rcode: NOERROR, id: 0 ;; flags: qr rd ra ; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0  ;; QUESTION SECTION: example.com.    IN    A  ;; ANSWER SECTION: example.com.    231    IN    CNAME    example.net.  ;; AUTHORITY SECTION:  ;; ADDITIONAL SECTION: ;; MSG SIZE  rcvd: 74
Jan 25 23:20:41 LTM1.example.com debug tmm[11700]: DNScache: iter_handle processing q with state QUERY RESPONSE STATE
Jan 25 23:20:41 LTM1.example.com info tmm[11700]: DNScache: query response was CNAME

Environment

  • BIG-IP DNS (GTM)
  • dns cache resolver with forward-zone configured for a specific FQDN

Cause

When a forward-zone is configured for a specific FQDN (e.g., example.com), BIG-IP will forward queries for that FQDN to the specified nameserver. If the response is a CNAME pointing to another domain (e.g., example.net), BIG-IP does not use the forwarder for the CNAME target. Instead, it attempts to resolve the CNAME target starting from the root ("."). If BIG-IP is not configured for full recursion or cannot reach the root servers, the resolution fails, resulting in SERVFAIL or timeout.

Recommended Actions

To ensure that all queries—including CNAME targets—are forwarded to your upstream DNS servers, configure a forward-zone for the root domain (".") in your DNS cache resolver. This will cause BIG-IP to forward all DNS queries, including those for CNAME targets outside the original FQDN, to the specified nameservers. 

ltm dns cache resolver <your_resolver> 
  forward-zones {
    "." {
      nameservers {
        <your_upstream_dns1>:53 { }
        <your_upstream_dns2>:53 { }
      }
    }
  }
  ...
}

After the change, more specific forward-zones (e.g., for example.com) will still take precedence for matching queries.

The root forward-zone acts as a catch-all, ensuring CNAME chains and all other queries are forwarded if no more specific zone matches.
