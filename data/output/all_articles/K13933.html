Known Issue

The BIG-IP system may continue to generate VLAN failsafe traffic after receiving responses to VLAN failsafe requests.

This issue occurs when all of the following conditions are met:

  • You are running a CMP compatible platform
  • You have VLAN failsafe enabled

When the VLAN failsafe feature is enabled for a VLAN, the tmm0 instance may fail to update the vlan_failsafe timer for other TMM instances when it receives a response to VLAN failsafe requests. In some cases, this issue causes the other TMM instances to enter VLAN failsafe aggressive mode.

Impact

The BIG-IP generates extraneous VLAN failsafe traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP generate extraneous VLAN failsafe traffic.

    For example, the system may generate extraneous ARP traffic, multicast pings to 224.0.0.1, and ICMPv6 neighbor discovery probes.

Workaround

If upgrading is not an immediate option, you may be able to mitigate this issue be setting the failover.vlanfailsafe.resettimeronanyframe DB key to true. To do so, perform the following steps:

Impact of workaround: When the failover.vlanfailsafe.resettimeronanyframe DB key is set to true, the BIG-IP system resets the timeout counter upon reception of any frame on the VLAN, including responses to BIG-IP monitor traffic.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. Set the value of the failover.vlanfailsafe.resettimeronanyframe DB key to true by typing the following command:

    modify sys db failover.vlanfailsafe.resettimeronanyframe value true

  3. Save the change by typing the following command:

    save /sys config
