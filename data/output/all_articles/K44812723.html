Known Issue

The BIG-IP system may unexpectedly limit the rate of reject packets.

This issue occurs when the following condition is met:

  • A traffic pattern triggers your BIG-IP system to perform a rate limit check for addresses in two different traffic groups within one second.

The BIG-IP system limits the rate at which it sends TCP RST or Internet Control Message Protocol (ICMP) unreachable packets in response to incoming client-side or server-side packets that the system cannot match with existing connections to BIG-IP virtual servers, self IP addresses, or Secure Network Address Translations (SNATs). This feature is a denial-of-service (DoS) counter measure. The tm.maxrejectrate database key allows you to adjust the maximum reject rate limit. For more information, refer to K13151: Configuring the rate at which the BIG-IP system issues TCP RSTs or ICMP unreachable packets (11.x - 12.x).

Impact

Traffic sent to a traffic group at a level that has not exceeded the tm.maxrejectrate threshold will trigger the BIG-IP system to limit the rate of reject packets.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails to send TCP RSTs, ICMP unreachable, or ICMP echo responses for some addresses.
  • Your BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following examples:

    warning tmm[1234]: 011e0001:4: Limiting open port RST response from 251 to 250 packets/sec
    warning tmm[1234]: 011e0001:4: Limiting closed port RST response from 251 to 250 packets/sec
    warning tmm[1234]: 011e0001:4: Limiting icmp unreach response from 251 to 250 packets/sec
    warning tmm[1234]: 011e0001:4: Limiting icmp ping response from 251 to 250 packets/sec.
