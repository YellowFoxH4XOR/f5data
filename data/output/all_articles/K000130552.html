K000130552: The Background on UNNAMED Entity

Type
Support Solution
Published
2023-01-10
Updated
2023-01-10
Source
https://my.f5.com/manage/s/article/K000130552

Description

In certain circumstances, ASM will generate a violation; Illegal Parameter or Illegal File Type.

 

The offending entity's name will be UNNAMED ( it will be in Italics ) .

 

 

Environment

  • Violations are triggered
  • No Learning suggestions to add UNNAMED

 

Cause

There are two reasons why ASM may display UNNAMED;

1) UNNAMED may be seen when policy there is a query parameter but which has no value.

For example, the following URL request:

/abc/website/page1?field1=value1&=value2&field3=value3

The &=value2 in the query will trigger Illegal Parameter and in the violation details, Parameter name given will be UNNAMED.

2) UNNAMED may also be seen where policy builder was expecting an alphanumeric value ( all letters, digits, underscore, and null ).

Policy Builder can interpret an invalidly terminated previous parameter value as an unnamed parameter.

For example, the following URL request:

/abc/website/page1?field1=value1&&field2=value2

Typically the query request should appear as: field1=value1&field2=value2...

and the extra "&" is invalid termination of parameter field1, hence, triggering the violation.
 

Recommended Actions

For reason 1, perhaps there should be a field2. This may require modifying the code on the application servers.
For reason 2, removing the extra &, prevents triggering the violation.

Additional Information

As part of improvements ( ID419261 ) , ASM no longer makes suggestions for UNNAMED Parameter.
https://techdocs.f5.com/kb/en-us/products/big-ip_asm/releasenotes/product/relnote-asm-11-5-3.html

This was also done for file types; ID713051; ASM won't make suggestions.
