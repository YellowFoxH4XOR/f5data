Known Issue

When a configuration change is made directly on an NGINX Plus or NGINX OSS instance that is managed by NGINX One Console or NGINX Instance Manager but the NGINX service on that instance is not restarted or reloaded, NGINX Agent reports the new configuration, even though it has not been loaded and it is not being used. This can also occur if an NGINX restart or reload fails to load the new configuration.

For example, a configuration with an http server and a stream server both listening on the same port may pass a syntax check using nginx -t, but the configuration causes a port bind clash and therefore fails to load. No further changes can be performed using NGINX Console One or NGINX Instance Manager until the data plane configuration on the NGINX instance has been reloaded with a valid configuration.

This issue occurs when all of the following conditions are met:

  • A configuration change is made directly on an NGINX data plane instance
  • The new configuration is not loaded, due to either of the following reasons:
    • The NGINX service was not restarted or reloaded
    • The new configuration is invalid and failed to load

Impact

NGINX One Console and NGINX Instance Manager both show a configuration that is not actually being used by the data plane instance. Additionally, any subsequent changes attempted from NGINX One Console or NGINX Instance Manager may fail if the configuration is invalid.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When attempting to make a change to the configuration using NGINX One Console, you see messages similar to the following example:

    Configuration changes failed to publish to instance <instance ID>

Workaround

To work around this issue, you can load a valid configuration on the NGINX data plane instance. If the configuration is invalid, the command output reports why the configuration cannot be loaded. For example, if you attempt to add a stream server listening on port 80 to a system that already has an http server listening on port 80, you would see messages similar to the following example when you restart the NGINX service:

nginx: [emerg] bind() to 0.0.0.0:80 failed (98: Address in use)

If you backed up the previous configuration file, you can restore that file and restart NGINX service.

Impact of workaround: Until a valid configuration is provided, the NGINX instance continues to use the configuration currently loaded. If the system is restarted before a valid configuration is provided, the NGINX service will not start. F5 recommends that you perform these modifications during a maintenance window.
