K6368: Authentication is not required to log in to Microsoft Outlook Web Access through Portal Access

Topic

When accessing Microsoft Outlook Web Access (OWA) through Portal Access, you may be directed to your Inbox or another user's Inbox instead of receiving an authentication prompt from the OWA server.

This behavior occurs when both of the following conditions are met:

  • The Outlook Web Access server is configured to authenticate users through HTTP Basic authentication or NTLM authentication for HTTP.

    Note: NTLM authentication for HTTP is referred to as Integrated Windows Authentication.

  • The FirePass controller is not configured to proxy HTTP Basic or NTLM authentication for the user's master group.

This behavior is the result of the improper termination of a previous FirePass session in which OWA was accessed. To ensure proper termination of the OWA session when the above conditions are met, log out of the FirePass controller and close the browser. Additionally, close all browser windows and tabs spawned from the initial browser window (for example, a browser window opened because the FirePass Portal Access favorite for OWA is configured to open in a new window).

To resolve this issue, you can enable the FirePass controller to proxy Basic and NTLM authentication. For more information about enabling the FirePass controller to proxy Basic and NTLM authentication, refer to K4236: Configuring FirePass to ensure secure access to Microsoft Outlook Web Access.
