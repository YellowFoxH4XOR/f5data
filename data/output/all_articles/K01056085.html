Description
How to troubleshoot flapping pool members when a monitor marking a pool member up and down

Environment

  • pool members
  • monitor

Cause
There are a wide array of reasons a pool member can flap up and down.  The steps below are intended to help you gather appropriate data to narrow the scope of troubleshooting.

Recommended Actions

  1. Enabling monitor logging for the affected pool member using the steps provided in the following article:
    K12531: Troubleshooting health monitors

  2. Enable TCP Reset Cause logging:

    tmsh modify /sys db tm.rstcause.pkt value enable
tmsh modify /sys db tm.rstcause.log value enable

  3. Start a TCPDump with the following syntax: (replace x.x.x.x with your pool members IP addresses and the x.x with the appropriate port)

    tcpdump -nnvi 0.0:nnn -s0 '(host x.x.x.x or host x.x.x.x)' and port xx -w /var/tmp/monitor_issue.pcap

  4. Reproduce the issue or wait for it to occur.

  5. Stop the capture (Hit Ctrl+C and then run the command "pkill tcpdump")

  6. Create a fresh qkview with an Unlimited Snaplen:
    A. Go to System  ››  Support  ››  Support and click on "New Support Snapshot".
    B. In the section labeled "Support Snapshot" choose "Generate Qkview".
    C. In the section labeled "QKView Options" select "Unlimited Snaplen".
    D. Click Start.
    E. Once it is done in the section labeled "Last Generated Snapshot" it will appear (This make take a few minutes to appear).
    F. Click on the Download button and download it.

  7. Return logging to normal using the steps in K12531 and disable logging again:

    tmsh modify /sys db tm.rstcause.pkt value disable
tmsh modify /sys db tm.rstcause.log value disable
tmsh modify ltm pool all members modify { all { logging disabled }}

  8. Upload the qkview to iHealth to examine the LTM logs and review the "Diagnostics" results

  9. Examine the packet capture for any anomalies or connection RSTs

Additional Information
If you are not able to find a resolution please submit both the qkview and the packet captures to F5 Support...K000090853: Exchange files with F5 Support
