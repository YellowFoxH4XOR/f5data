K000159903: Resolving BIG-IP Configuration Utility and REST API Failures Due to restjavad and tomcat Memory Exhaustion

Type
Support Solution
Published
2026-02-05
Updated
2026-02-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000159903

1. Description

The BIG-IP Configuration Utility (GUI) becomes unresponsive or returns "500 Internal Server Error" messages, and REST API calls fail with authentication errors. Monitoring tools that rely on the REST API may also experience failures. The issue requires repeated manual restarts of restjavad, restnoded, httpd, and tomcat daemons to temporarily restore functionality.

Error messages observed in logs include:

  • java.lang.OutOfMemoryError: Java heap space in /var/log/tomcat/catalina.out
  • IllegalStateException: AsyncContext completed and/or Request lifecycle recycled in restjavad logs
  • Frequent 401 authentication failures in restjavad.0.log
  • java.util.ConcurrentModificationException errors
  • Automatic tomcat restarts triggered by memory exhaustion

2. Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (issue can occur in other versions)
  • Platform: F5-BIG-LTM-I7800, C118, or other platforms
  • vCMP deployment with multiple guests (or standalone systems)
  • Configuration Utility (GUI) and REST API used for management and monitoring
  • Default tomcat memory allocation (provision.tomcat.extramb set to 0 MB)
  • High volume of REST API calls from monitoring tools or management applications
  • Systems with large configurations or frequent API usage

3. Cause

Insufficient Java heap memory allocated to the tomcat and restjavad processes results in memory exhaustion. When memory limits are reached, the Java processes experience OutOfMemoryError conditions, causing the Configuration Utility and REST API to become unresponsive. The tomcat process has a failsafe mechanism that automatically restarts when detecting out-of-memory conditions, but this does not resolve the underlying memory shortage.

4. Answer/Recommended Actions

Immediate Resolution Steps

  1. Restart affected daemons to restore service:
  2. bigstart restart restjavad
  3. sleep 20
  4. bigstart restart restnoded
  5. bigstart restart httpd
  6. bigstart restart tomcat
  7. Note: This provides temporary relief but does not address the root cause.
  8. Verify available host memory before allocating additional resources:
  9. cat /proc/meminfo | grep MemAvailable
  10. or
  11. free -m
  12. Ensure sufficient memory is available on the Linux host before proceeding.

Permanent Resolution - Increase Tomcat Memory Allocation

  1. Check current tomcat memory allocation:
  2. tmsh list sys db provision.tomcat.extramb
  3. Default value is 0, indicating no additional memory is allocated.
  4. Increase tomcat memory allocation:
  5. tmsh modify sys db provision.tomcat.extramb value 50
  6. tmsh save sys config
  7. Note: Start with 50 MB increments. If OutOfMemoryError messages continue, increase by an additional 50 MB until the errors stop. F5 recommends not exceeding 1 GB without consulting F5 Support.
  8. Restart the tomcat process:
  9. tmsh restart sys service tomcat
  10. For High Availability (HA) configurations:
  • Repeat steps 3-5 on all peer devices
  • The provision.tomcat.extramb setting does not synchronize automatically between devices
  • Restart tomcat on each device individually

Additional Considerations for restjavad

  1. If restjavad also experiences memory issues, consider increasing restjavad memory:
  • For versions 17.1.0, 16.1.4, and 15.1.9 or later:
  • tmsh modify sys db provision.restjavad.extramb value <MB>
    • bigstart restart restjavad
  • For earlier versions:
  • tmsh modify sys db restjavad.useextramb value true
    • bigstart restart restjavad
    • Also consider increasing Management provisioning from Small to Medium or Large via the GUI under System > Resource Provisioning

Monitoring and Validation

  1. Monitor logs to confirm resolution:
  2. tail -f /var/log/tomcat/catalina.out
  3. tail -f /var/log/restjavad.0.log
  4. Verify that java.lang.OutOfMemoryError messages no longer appear.
  5. Monitor daemon uptime:
  6. bigstart status restjavad
  7. bigstart status tomcat
  8. Confirm processes remain stable without frequent restarts.

Proactive Measures

  1. Review and optimize REST API usage:
  • Evaluate the frequency and volume of REST API calls from monitoring tools
  • Reduce unnecessary or redundant API calls where possible
  • Implement rate limiting or throttling for API clients if appropriate
  1. Keep software up to date:
  • Apply the latest software updates and hotfixes to benefit from bug fixes and performance improvements
  • Review release notes for memory-related improvements

5. Additional Information

  • Memory exhaustion in tomcat and restjavad can cause the Configuration Utility and REST API to become unresponsive, requiring manual intervention.
  • The tomcat process has an automatic restart mechanism when OutOfMemoryError is detected, but this does not prevent recurrence if insufficient memory is allocated.
  • Increasing tomcat memory allocation is drawn from Linux host memory and does not affect TMM (Traffic Management Microkernel) memory.
  • The provision.tomcat.extramb setting does not synchronize between HA peers and must be configured on each device individually.
  • In vCMP environments, memory allocation should be reviewed for both the host and guest systems.
  • High volumes of REST API calls, large configurations, or monitoring tools can contribute to increased memory consumption.
  • The "AsyncContext completed and/or Request lifecycle recycled" error is often associated with Bug ID 1710621 and can be resolved by restarting restjavad and restnoded services.
