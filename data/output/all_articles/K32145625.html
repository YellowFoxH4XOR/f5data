Source

Description

NTLM authentication fails, you observe the following logs in /var/log/apm:

Jan 01 01:01:00 device err eca[]: 0162000e:3: Failed to resolve DC FQDN (dc.fqdn), Temporary failure in name resolution (-3)
Jan 01 01:01:00 device err eca[]: 0162000e:3: Failed to resolve DC FQDN (dc.fqdn), Temporary failure in name resolution (-3)
Jan 01 01:01:00 device err eca[]: 0162000e:3: Invalid argument (/Common/NTLM Auth Configuration name)
Jan 01 01:01:00 device err eca[]: 0162000e:3: Invalid metadata (select_ntlm:/Common/NTLM Auth Configuration name)
Jan 01 01:01:00 device err eca[]: 0162000e:3: Invalid argument (/Common/NTLM Auth Configuration name)
Jan 01 01:01:00 device err eca[]: 0162000e:3: Invalid metadata (select_ntlm:/Common/NTLM Auth Configuration name)

Environment

  • APM

Cause

This can happen due to failed DC name resolution.

Recommended Actions

  1. Review Machine Account and NTLM Auth Configuration settings. Check if the Domain Controller FQDN is correct and if it can be resolved
  2. Check if DNS is reachable from the BIG-IP device.
