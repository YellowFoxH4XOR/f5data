Description
How does BIG-IP know how to send LTM statistics or Device logs to BIG-IQ

Environment

  • BIG-IP v 13.1.x onwards
  • BIG-IQ 7.1.x onwards
  • Managing BIG-IP statistics via BIG-IQ
  • BIG-IP is already discovered in BIG-IQ Central Management

Cause
None

Recommended Actions

  1. The first task in managing a BIG-IP device from BIG-IQ is to add it to BIG-IQ. This is making sure that the BIG-IQ system can access the device at the specified IP address and ports. This is sometimes referred to as establishing trust with the BIG-IP device.
  2. After this task is complete, all of the BIG-IQ Device functionality (inventory reporting, backup and restore, script management, licensing, password management, software upgrade, and so on) is available for the discovered device. If at least one Data Collection Device (DCD) is deployed in the environment, statistics data for device, LTM, and DNS objects can also be collected and reported.
  3. During the discovery process the BIG-IQ configures the Analytics global settings in the BIG-IP in order for the BIG-IP to know where to send these statistics data and logging. 
  4. To verify that the BIG-IQ configured the Analytics global settings properly on the BIG-IP. Enter the following command from the BIG-IP command line:
    tmsh list analytics global-settings

    Example:
    root@(BIG-IP)(cfg-sync Standalone)(Active)(/Common)(tmos)# list analytics global-settings
    [api-status-warning] analytics/global-settings, properties : deprecated : ecm-port
    analytics global-settings {
        avrd-interval 30
        ecm-port 443
        enable-bigiq-configuration enabled
        offbox-protocol https
        offbox-tcp-addresses { 10.1.1.x 10.1.1.x } <--- these are BIG-IQ DCD IP addresses
        offbox-tcp-port 443
        source-id e7d157c3-2611-4907-955c-4de2c7128528_10.1.1.x <--- these is the BIG-IQ CM UUID and IP Address
        use-offbox enabled
    }
  5. For BIG-IP devices running version 13.1.0.5 or later, BIG-IQ needs to provide access on Port 443 so that the BIG-IP AVR module can send statistics to the BIG-IQ DCD via the IP address (MGMT or Self IP) which ever you used during discovery.

Additional Information

  • Report and Event logs are configured via the Data Collection Devices Services such as Web Application Security, Access, DOS Protection, Network Security, Fraud Protection Service and IPSec. This is based on routing settings during your deployment. (Please refer to your Deployment Manual)
  • The BIG-IP system pushes the statistics data to the DCD, bi-directional connectivity using port 443 is still required. The DCD retrieves object status (online, offline, disabled, and so on) by connecting to the BIG-IP and transferring the Analytics iApp output file.
  • The BIG-IP device connects to the assigned BIG-IQ DCD, and streams the Analytics data that it is configured to send. If the AVR process cannot connect to the first DCD, it tries a second one, if configured, and so on. The BIG-IQ DCD still initiates a connection to the BIG-IP device to periodically retrieve event data.
  • If the BIG-IP Application Visibility and Reporting module is not provisioned on the BIG-IP device and it is not able to initiate a connection to destination port 443 on the BIG-IQ DCD over the network, statistics collection on the BIG-IQ fails for the managed device.

Note: F5 does not recommend enabling statistics for Virtual Clustered Multiprocessing (vCMP) host systems.
