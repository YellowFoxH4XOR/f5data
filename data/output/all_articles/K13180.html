Topic

This article applies to BIG-IP 11.x through 21.x. For information about other versions, refer to the following article:

  • K3664: Configuring the BIG-IP system to deliver locally generated email messages (9.x - 10.x)

Purpose

You should consider using these procedures under the following condition:

  • You want to configure the BIG-IP system to deliver locally generated email messages.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have command line access to the BIG-IP system.
  • You are familiar with a Linux text editor.

Description

The unix ssmtp utility is a simple SMTP relay server, which accepts a mail stream on standard input, with email recipients specified on the command line, and can be used to send email from the linux commandline or by other process running on the BIG-IP device.   This configuration is managed through the 'sys outbound-smtp' tmsh settings, which is separate from the "sys smtp-server" tmsh setting, which is used for scheduled reports from the AVR and ASM modules. For further clarification, refer to article K45161233 What is the difference between outbound-smtp and smtp-server in bigip_base.conf

Procedures

You can configure the BIG-IP system to deliver locally generated email messages using sSMTPh by performing one of the following procedures, depending on your BIG-IP version.

    You can use the  TMOS Shell (tmsh) to configure an SMTP mail hub. In BIG-IP 13.x and later, you can also configure RewriteDomain and FromLineOverride. BIG-IP versions 11.5.0 - 12.x do not support advanced sSMTP options using tmsh.  

    Note: Due to a known issue, the BIG-IP system does not automatically configure a domain name in the email From: line. For more information about and how to work around the issue, refer to K15188934: Emails generated by the BIG-IP system may fail after upgrading to version 13.0.0.

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to tmsh by entering the following command:

      tmsh

    2. To configure the system to send locally generated email messages, use the following command syntax:

      modify /sys outbound-smtp mailhub <mail_server>:<port>

      For example, to configure the system to send locally generated email messages to host mail.mydomain.com using port 587, enter the following command:

      modify /sys outbound-smtp mailhub mail.mydomain.com:587

    3. To save the configuration, enter the following command:

      save /sys config

    Configuring advanced sSMTP options manually

    While the basic ssmtp settings can be configured in tmsh, it is not possible to configure advanced options, such as TLS support, by using the tmsh utility.

    As a workaround, advanced ssmtp settings can be configured by directly editing the /etc/ssmtp/ssmtp.conf file, however doing so comes with important caveats:

    Any changes made manually to the ssmtp.conf file will be lost at any time the tmsh utilty is used to modify any other "sys outbound-smtp" settings, as the whole file is re-generated from a template. Changes will also be lost any time the system boots into a new BIG-IP boot location, or any time the hardware is replaced via the RMA process.  Customers opting for this workaround will need to re-apply their changes each time the manually-applied settings are lost.   There is a partial mitigation for this risk - see 'Avoiding loss of advanced ssmtp options', below

    Any such changes are made at the customer's risk, and F5 Support will provide only limited assistance to revert the file to a known good state by regenerating it using tmsh.  

    The following advanced settings may configured in /etc/ssmtp/ssmtp.conf using a manual text editor such as nano or vim:

    1. Optional: If the BIG-IP system has custom alerts configured in /config/user_alert.conf to send an email notification using the fromaddress parameter, you must clear the comment in the following line in the /etc/ssmtp/ssmtp.conf file:

      FromLineOverride=YES

      Note: Alternatively, you can use the tmsh utility to configure the FromLineOverride parameter. For more information, refer to K27540405: The tmsh command now supports the RewriteDomain and FromLineOverride SSMTP configuration.

    2. Optional: If the SMTP mail host supports SSL/TLS authentication, you must add the following four additional parameters into the /etc/ssmtp/ssmtp.conf configuration file: 
      UseSTARTTLS=yes
UseTLS=yes
AuthUser=<SMTP-Account-Username>
AuthPass=<SMTP-Account-Password>
TLS_CA_File=<text file containing trusted Root certificates - see note below>

      In these parameters, note the following:

      • <SMTP-Account-Username> is the username of a valid account on the SMTP mail host server.
      • <SMTP-Account-Password> is the password of the user account on the SMTP mail host server.

      If the SMTP mail host supports SSL/TLS authentication and establishes a secure connection automatically, you should omit the UseSTARTTLS parameter. Otherwise, you fail to connect to the mail host successfully and may notice an error message in the /var/log/maillog file that appears similar to the following example:

      err sSMTP[20654]: Invalid response SMTP Server (STARTTLS)

      Important: If you enable TLS (either UseTLS or UseSTARTTLS), sSMTP attempts to verify the remote SMTP server's certificate. To do this, you need to tell it where the trusted root certificates are located. While you can use the existing f5-provided ca-bundle, you can't use it directly due to SELinux restrictions. Instead, you must first copy the certificate file to /etc/ssmtp/, and change the SELinux context of the new file to allow sSMTP to read it.

      To add the additional parameters to /etc/ssmtp/ssmtp.conf, perform the following steps:

      1. Log in to Advanced Shell (bash) on the BIG-IP system.
      2. Enter the following command:

        cp /config/ssl/ssl.crt/ca-bundle.crt /etc/ssmtp/
        chcon -u system_u -t etc_t /etc/ssmtp/ca-bundle.crt

      3. Add "TLS_CA_File=/etc/ssmtp/ca-bundle.crt" to /etc/ssmtp/ssmtp.conf.

        If a TLS_CA_File is not specified or does not include the remote SMTP server's certificate, mail delivery fails with an error similar to the following:

        sendmail: Cannot open smtp.office365.com:587

        If the SELinux context is not set correctly, sSMTP reports a Permission denied message when trying to read the certificate file. You can see this in the system journal by entering the following command:

        journalctl | grep SMTP

        Output appears similar to the following example:

        Jul 01 00:00:00 bigip1.local sSMTP[xxxxx]: Error setting verify location: Permission denied

    3. Save the changes, and then exit the text editor.
    4. Verify that sSMTP is configured properly and can send an email message. To do so, send a test email message using a command that appears similar to the following example:

      echo -e "Subject: Test email for K13180\n\nssmtp test mail" | ssmtp -v myemail@mydomain.com

    5. Verify that you receive the email message.

    Avoiding loss of the advanced ssmtp options

    For customers who choose to manually edit their ssmtp.conf, the file can be flagged as "immutable" (unable to be written to, even by the root user), preventing mcpd or tmsh from updating and overwriting it at a later time.  This can be done with the "chattr" (change attribute) unix utility, as follows.  If this proceedure is followed, it is highly recommended that an explanatory comment is first included in the ssmtp.conf file, to avoid unnecessary delays with supporting the device at a future time, for example, adding this line at the top of the file:

    # ssmtp.conf has been modified manually, and set as immutable per K13180.

    To set the file immutable, in order to prevent tmsh or any other process from being able to change it, use the following steps:

    1. Log in as the root user to the bash command line
    2. Execute the command "chattr +i /etc/ssmtp/ssmtp.conf"
    3. Verify the file attributes (an 'i' will show up in the 5th position) with "lsattr /etc/ssmtp/ssmtp.conf"
    4. If necessary, remove the immutable flag with the command "chattr -i /etc/ssmtp/ssmtp.conf"

    When the file is set immutable, no system process will be able to modify it, unless the immutable flag is first removed.   If tmsh is used to alter "sys outbound-smtp" settings, the mcpd (BIG-IP) configuration will be updated, and no errors will be noted, but the ssmtp.conf file will not be changed, meaning the displayed configuration in tmsh will not necessarily match the configuration of the ssmtp utility.  

    Note that even if the file is set immutable,  it will not survive a software upgrade or RMA. Any changes that have been manually made to the file will need to be re-applied in those situations.
