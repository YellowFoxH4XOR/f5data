Description

Software installation failed, and unable to delete the new volume.

 

When trying to delete the new installation volume, you observe messages similar to the following examples in logs:

Aug 7 08:27:13 LTM1.example.com err lind[6771]: 013c0004:3: unmount failed Invalid argument

Aug 7 08:27:13 LTM1.example.com err lind[6771]: 013c0004:3: Fatal error: mount failed:Device or resource busy

Aug 7 08:27:19 LTM1.example.com err mcpd[6766]: 01020036:3: The requested software status (0 HD1.5) was not found.

 

Output of the tmsh show sys software command appears similar to the following example:

-------------------------------------------------------------------------------------

Sys::Software Status

Volume Product Version Build Active      Status Allowed Version

-------------------------------------------------------------------------------------

HD1.1 BIG-IP 16.1.3 0.0.12  yes     complete    yes

HD1.5  none  none none  no failed to delete volumeset    yes

 

Where HD1.5 is the volume that software installation was interrupted.

Environment

  • Software installation failure
  • Volume cannot be deleted
  • Volume may previously be in 'audited' state
Note: if your volume is currently in 'audited' state, refer to article K91155702 .

Cause

'lind' process is unable to delete the volume, because partitions installation is stuck/pending.

Recommended Actions

To work around this issue, you can manually remove logical volumes that the BIG-IP system was unable to remove from the HD1.5 volume set after installation failed.

To do so, perform the following procedure:

Impact of workaround: Any data on the logical volumes that you remove will be irrecoverably lost. The procedure involves restarting a service and reboot of the system; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window.

 

1. Check the error why the installation failed and fix it.

2. Create a User Configuration Set (UCS) and Master Key backup.

3. Log in to the command line.

4. Stop lind process:

tmsh stop sys service lind

5. List the partitions that need to be removed manually:

df -h

in example above, those partitions belong to volume HD1.5 and needs to be removed manually:

/dev/mapper/vg--db--vda-set.5.root
/dev/mapper/vg--db--vda-set.5._config
/dev/mapper/vg--db--vda-set.5._usr
/dev/mapper/vg--db--vda-set.5._var

6. Unmount the partitions for affected volume (if necessary):

umount <path/to/logical/volume>

for example, unmount the partitions for volume HD1.5:

umount /dev/mapper/vg--db--vda-set.5._config
umount /dev/mapper/vg--db--vda-set.5._usr
umount /dev/mapper/vg--db--vda-set.5._var
umount /dev/mapper/vg--db--vda-set.5.root

7. Remove the partitions for affected volume:

lvremove <path/to/logical/volume>

for example, remove the partitions for volume HD1.5:

lvremove /dev/mapper/vg--db--vda-set.5._config
lvremove /dev/mapper/vg--db--vda-set.5._usr
lvremove /dev/mapper/vg--db--vda-set.5._var
lvremove /dev/mapper/vg--db--vda-set.5.root

8. Delete the files generated by lind process:

rm -rf /tmp/lind_util*


9. Start the lind process if the installation error was fixed, and the lind will attempt to reinstall the logical volumes on volume HD1.5 again:
(If you want to remove the corrupted Volume HD1.5 completely, do not start the lind process, and go to point 10)
tmsh start sys service lind
 

10. Reboot the system, without starting the lind, so that the volume HD1.5 can be removed from hard drive upon reboot:

reboot

11. Check the volumes list with command  tmsh show sys software
     
If the volume HD1.5 is still on the list, you should be able to delete it by:
tmsh delete sys software volume HD1.5
