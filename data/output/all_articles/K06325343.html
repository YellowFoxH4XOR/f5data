K06325343: AVR Partition not large enough for installation during an upgrade.

Type
Support Solution
Published
2022-06-07
Updated
2025-02-06
Applies to
  • Virtual Editions
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K06325343

Description
Before the upgrade, you notice that the /var partition is using more than 75 GB of disk space. 
The upgrade fails with this error Software Installation failed for device x.x.x.x
Using the command df -h, in the device where the installation failed, the directory /var for the new boot location only has 75 GB od disk space assigned.

Environment

  • Upgrade
  • BIG-IQ DCD
  • Disk space
  • Virtual Editions

Cause
When the boot location is created during the installation, it is created with the default values for disk space, this normally is 75 GB.

Recommended Actions

  1. Delete the boot location where the installation failed.
# tmsh delete /sys software volume <volume>
  1. Use this command to verify that you have enough disk space to match the amount of disk space that your /var partition is currently using.
# pvs
For instance, if your current /var directory has 200GB of disk space assigned, you will need 200GB of disk space free.
  1. Initiate a new installation process.
  2. In the device where the installation failed, monitor when the new directories for the new boot location are mounted.
# watch -n1 df -h
The command  can be interrupted with ctrl + c
  1. Right after the directories are mounted, and before the copying process starts, resize the current /var directory to the same size it is already using.
# resizevol /var <new size in kilobytes>
for instance, if your current /var directory is 200GB use this command:
# resizevol /var 209715200
