Description

Pentesting tool "wafw00f" expose the vendor information makes easier for the attackers to identify application is behind F5 BIG-IP.

    Environment

    • wafw00f
    • LTM cookie
    • HTTP header ('X-Cnection', 'close')

    Cause

    Based on the source code of wafw00f tool detects only if LTM cookie name starts with "^bigipserver" or HTTP header ('X-Cnection', 'close') exist in the response.

    Recommended Actions

    1. Replace the "BIGipServer" cookie name with a custom cookie named "MyCookie" without using an iRule, you can modify this using cookie persistence profile settings directly in the F5 BIG-IP.
      1. Create a Custom Cookie Persistence Profile:
        • Navigate to Local Traffic > Profiles > Persistence.
        • Click on "Create" to new persistence profile.
        • Enter a name for your new profile, for example, "CustomCookiePersistence".
        • Set the Persistence Type to "Cookie".
        • In the "Cookie Name" field, enter your desired custom cookie name, such as "MyCookie".
        • Adjust other settings as needed (e.g., timeout, method).
        • Click on "Finished" to save the new profile.
      2. Assign the Custom Cookie Persistence Profile to a Virtual Server:
        • Navigate to Local Traffic > Virtual Servers.
        • Select the virtual server to which you want to assign the custom cookie persistence profile.
        • Click on the "Resources" tab.
        • Under "Default Persistence Profile," click "Manage."
        • Select the "CustomCookiePersistence" profile you created and move it to the "Default Persistence Profile" section.
        • Click on "Finished" to save the changes.
      3. By following the above steps, you have created a custom cookie persistence profile that uses the cookie name "MyCookie" instead of the default "BIGipServer". This way, you avoid using the default "BIGipServer" cookie name, making it less likely to be detected by tools that look specifically for this name.
    2. For removal of connection close header response you can apply the below irule and bind it to vServer 
      when HTTP_REQUEST {
  if { ([HTTP::method] eq "GET") || ([HTTP::method] eq "HEAD") } {
    set change_response_headers 1
  } else {
    set change_response_headers 0
  }
}

when HTTP_RESPONSE {
    if { $change_response_headers == 1 }{
        HTTP::header remove "Connection"
    } 
}
