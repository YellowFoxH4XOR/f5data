BIG-IP ASM: ASM live update fails when using an HTTPS proxy server

Description

When you attempt to update BIG-IP Application Security Manager (ASM) attack signatures through a configured HTTPS proxy server, the live update fails. Bypassing the proxy server and updating directly succeeds.

You may observe the following error when testing connectivity to activate.f5.com through the proxy:


curl: (60) SSL certificate problem: unable to get local issuer certificate

Environment

  • BIG-IP Application Security Manager (ASM)
  • HTTPS proxy server configured on the BIG-IP device (for configuration steps, see K82512024 under the section "Configure BIG-IP ASM Live Update through an HTTPS proxy")
  • ASM attack signature live update fails through the proxy, but succeeds when the proxy is bypassed

Cause

The HTTPS proxy server strips the root and intermediate certificates from the certificate chain before passing the response to the BIG-IP device. This causes the SSL certificate verification to fail, and the live update download through the proxy server does not complete.

Recommended Actions

  1. Verify connectivity to the F5 server without the HTTPS proxy by running the following command:

    openssl s_client -connect callhome.f5.com:443 -CAfile /etc/pki/tls/certs/ca-bundle.crt

    The output displays the certificate chain presented by the F5 server. Note this output for comparison in step 3.

  2. Run a packet capture while triggering a live update from the GUI. Navigate to System > Software Management > Live Update and initiate a check for updates for ASM attack signatures.
    1. If traffic to the HTTPS proxy server goes through the management interface, run the following command from bash:

      tcpdump -nni eth0 host <proxy_server_IP> -v -w /var/tmp/throughproxy.pcap

    2. If traffic to the HTTPS proxy server goes through a TMM interface, run the following command from bash:

      tcpdump -nni 0.0:nnnp host <proxy_server_IP> -v -w /var/tmp/throughproxy.pcap

  3. Stop the tcpdump capture and analyze the packet capture. Compare the SSL certificate chain in the capture against the output from step 1. If the proxy server is stripping the root or intermediate certificates, the chain in the capture will be incomplete.
  4. Reconfigure the proxy server to preserve the full SSL certificate chain when forwarding packets to the BIG-IP device.
  5. If the proxy server presents its own root certificate, add that certificate to the BIG-IP device's trusted certificate store so the device trusts the proxy's certificate.
