Known Issue

The Traffic Management Microkernel (TMM) may restart during heavy DNS traffic when zxfrd logging is set to debug.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system to use both Global Server Load-Balancing (GSLB) and DNS Express.
  • The BIG-IP GTM listener has no associated pool.
  • The DNS profile has the following configuration:
    • Use BIND Server on BIG-IP is set to disabled. (Enabled is the default.)
    • Unhandled Query Actions is set to Allow. (Allow is the default.)
  • The log.zxfrd.level db key is set to debug. (Notice is the default.)

Impact

TMM fails to process traffic while restarting.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, you can set the DNS profile's Unhandled Query Action option to Drop.

Impact of workaround: The system will drop DNS requests that do not match a DNS Express zone, instead of forwarding the requests to another DNS server.
