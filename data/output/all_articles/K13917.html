Known Issue

TMM may experience a memory leak when processing SSL connections.

This issue occurs when all of the following conditions are met:

  • The Client SSL profile is configured to use a chain certificate.
  • Clustered Multi-Processing (CMP) is enabled for the virtual server.

Impact

The BIG-IP system may experience resource exhaustion and possible failover.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The show sys memory command may indicate that the memory that the TMM used is close to the amount of allocated TMM memory.
  • You may see errors that appear similar to the following examples in your /var/log/tmm.log file:

    notice panic: umem_backstore_free: no such allocation
    notice cmp state: 0x0
    notice ** SIGFPE **
    notice fault addr: 0x510fbc
    notice fault code: 0x1

  • Unexpected TMM restarts and HA failover events may occur.

Workaround

To work around this issue, you can disable CMP on individual virtual servers that use a chained certificate. To do so, perform the following procedure:

Impact of workaround: Traffic for the virtual servers for which CMP has been disabled is re-directed to tmm0 and results in uneven distribution of CPU load.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. Disable CMP on the virtual server. Replace <virtual server> with the name of the virtual server you want to modify.

    modify /ltm virtual <virtual-server> cmp-enabled no

  3. Save the change by typing the following command:

    BIG-IP 10.1.0 and later:

    save /sys config

    BIG-IP 10.0.x:

    save config
