K30133809: The var volume on BIG-IQ Centralized Management is now larger

Type
Knowledge
Published
2020-04-30
Updated
2025-02-06
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 7.1.0
Source
https://my.f5.com/manage/s/article/K30133809

Issue

Old Behavior

In versions prior to BIG-IQ 7.1.0, the var logical volume mounted to the /var directory is typically 10 GB in size. Example output from lvs command:

LV            VG        Attr      LSize
set.1._var    vg-db-sda -wi-a----  10.00g

New Behavior

Beginning in BIG-IQ 7.1.0, the var logical volume is at least 25 GB. Example output from lvs command:

LV            VG        Attr      LSize
set.1._var    vg-db-sda -wi-ao---  25.00g

Impact

The default disk size of BIG-IQ VE 5.2.0 through 7.1.0 is 95 GB which may prevent you from upgrading to BIG-IQ 7.1.0 if the BIG-IQ system has multiple boot locations. You need at least 31 GB of free disk free space on the volume group to install BIG-IQ 7.1.0. To view available disk space for the volume group enter the vgs command from the Advanced Shell (bash) of the BIG-IQ.

Additionally, the 95 GB disk size will only allow a single boot location with BIG-IQ 7.1.0. The logical volumes for swap, logging, and the /shared directory typically use an additional 38 GB of space leaving roughly 26 GB which is not enough for a second boot location with BIG-IQ 7.1.0.

If the system disk is full, you will see the following error messages:

Recommended Actions

To allow enough disk space for a larger BIG-IQ image, perform one of the following actions:

  • When deploying a BIG-IQ VE, use the LARGE VM file that has a 500 GB disk.
  • Delete unused boot locations by performing the following procedure:

    Delete unused boot locations

    Impact of procedure: Deleting a boot location also referred to as a volume will irrevocably remove the volume and the content stored on it.

    1. Log in to the BIG-IP VE bash.
    2. To delete the unused boot location use the following syntax:

      tmsh delete sys sof volume <volume name>

      For example:

      tmsh delete sys sof volume HD1.1

  • Use your hypervisor to increase the disk size of your 95 GB BIG-IQ VE deployment by performing the following procedure:

    Extend disk space for upgrading software on an additional boot location

    Impact of procedure: You must shut down the BIG-IQ VE during the disk provisioning steps. During shut down, the system is not available for traffic processing. You should perform this procedure during a suitable maintenance window. Increasing the disk size on the BIG-IQ VE is irreversible because F5 does not support disk shrinking. Increasing the disk size beyond 1.9 TB may render the system unable to boot. F5 recommends the extended disk space should not exceed 1.9 TB.

    1. Log in to the BIG-IQ VE bash.
    2. To shut down the system, enter the following command:

      shutdown -h now

    3. Provision the disk space you want for the BIG-IQ VE on the hypervisor. For information about disk provisioning on the hypervisor, refer to the documentation from your hypervisor vendor.
    4. Start up the BIG-IQ VE guest instance on your hypervisor. For information about starting a guest instance on the hypervisor, refer to the documentation from your hypervisor vendor.
    5. When the BIG-IQ VE is up, log in to bash.
    6. Confirm the hypervisor expanded the disk by using the following commands:
      • vgs
      • tmsh list sys disk
