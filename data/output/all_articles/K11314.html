Topic

The BIG-IP WebAccelerator generates ETags for the content it processes. When the Use HTTP lifetime headers if present setting is enabled, but the Ignore no-cache in HTTP header in the response setting is disabled, the ETag includes a hash of the response body and some of the response headers, including the OWS cache control headers.

As a result, when the OWS changes a cache control header sent for an otherwise unchanged object, a new ETag value will be calculated. This may result in inconsistent ETags for the same object prior to its promotion into the cache. In symmetric deployments, this may also result in inconsistent ETags being generated by each WebAccelerator instance.

This is expected behavior. For more information, refer to the Using HTTP/1.1 Cache-Control Headers section of the Configuring Lifetime Rules chapter in the BIG-IP WebAccelerator Policy Management Guide.

If this behavior is undesirable, enable the Ignore no-cache in HTTP header in the response setting. When this setting is enabled, the OWS cache control headers are not included in the hash calculation. As a result, the ETag value does not change if the response body has not changed.
