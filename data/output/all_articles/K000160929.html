K000160929: Tenant instance re-created by the system, despite tenant already being deleted via confd

Type
Support Solution
Published
2026-04-21
Updated
2026-04-21
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000160929

Description

A tenant was re-created shortly after being deleted via confd, and is observed to have a running virt-launcher pod in the output of kubectl get pods --all-namespaces (for example).

Despite the running virt-launcher pod, the tenant still does not exist in confd.

Environment

  • r2x00/r4x00
  • Recently deleted a tenant
  • After a previous delete and re-create of the tenant

Cause

This happens rarely when deleting and re-creating a tenant with the same name multiple times in short succession (seconds later).

The issue might be observed more frequently when using automation to deploy tenants, for example via terraform.

Recommended Actions

Re-create and delete the tenant once more.

If the tenant's virt-launcher pod remains, delete it:

kubectl delete pods -l name=<tenant name> --force

To avoid the issue, wait a few minutes between tenant create and delete operations.
