Topic

Purpose

You should consider using this procedure under the following condition:

  • The ARX system's startup-config file has been deleted

The ARX Manager GUI and CLI allows users to delete the startup-config file without warning that deletion will result in the ARX system restoring to factory defaults.

Description

The ARX system uses a startup-config file, which is a combination of the running-config file and the global-config file. If the ARX is reloaded without a startup-config file, it will boot to the boot-config file, which is a minimum config file that contains only the parameters that are set by the initial-boot script. As a result, the system has a clean configuration with only the out-of-band management address and console port reachable.

Important: An ARX could run for days or even months without a saved startup-config file. You may only notice the missing file after reloading the ARX system.

Symptoms

As a result of a deleted startup-config file, you may encounter the following symptoms:

  • The ARX no longer has a full configuration after a reload.
  • An ARX reload attempt fails with an error message indicating the startup-config file has been deleted. In addition, a prompt asks if you want to return the ARX to its factory defaults.
  • When you issue the reload command using the CLI, you receive the following message:

    1-1-ACM-20846:CLI-0-NOTE-CLI_COMMAND_PROMPT:: You had previously deleted your startup-config. If you would like to restore your configuration, answer 'no' to cancel this reload and then run the 'restore startup-config' CLI command before re-running this command. If you answer 'yes' instead, the ARX returns to its factory defaults. Reload the entire chassis? [yes/no/diags]
Note: If you attempted the reload using the ARX Management GUI, no error message will appear.


  • The ARX no longer has a running-config file or global-config file available after it reloads.
  • The ARX system (versions 6.0.0 and later) is no longer licensed after it is reloaded and indicates license activation is required with the following prompt:
ARX software must be licensed. Please configure the in-band management IP address and DNS for automatic license activation.

Procedures

When experiencing lost configuration, you can use the following steps to determine the root cause and resolve the issue:

  • Reviewing the syslog
  • Recovering from a missing configuration before reboot
  • Recovering from a missing configuration after reboot

Impact of procedure: None.

Reviewing the syslog

To confirm if the configuration has been unintentionally removed from the ARX managment GUI, you may review the syslog files. To do so, perform the following procedure:

  1. Log in to the ARX CLI.
  2. Use the following grep command syntax:

    grep “<search string>” logs <log filename>

    For example:

    grep "srcFilename='startup-config'" logs syslog

    Output will appear similar to the following example:

    1-1-ACM-11368:GUI-0-NOTE-MSG5:: GUI-OP: DeleteDir isDirectory=0 srcDirectory=2
    FilenameRecord.srcFilename='startup-config'

    Note    : Due to the length of time this issue may exist before it is noticed, the logs containing the root cause may have been rotated.

Recovering from a missing configuration before reboot

To restore the startup-config file, you can use the restore startup-config?? command if you have encountered either of the following two situations:

  • Before initiating a reload, you have identified the ARX no longer has a startup-config file.
  • You received the error message identified in the Symptoms section during a switch reload.

    Note: You may back out of the reload by answering with NO to the Reload the entire chassis? request.

Recovering from a missing configuration after reboot

If the ARX has been reloaded while lacking a startup-config file, you may recover using the following guides:

  • To re-license the ARX system refer to K12800: Overview of ARX licensing
  • For instructions on recovering an ARX configuration, refer to the Backing Up the Running Configuration chapter of the CLI Maintenance Guide 

Important: In a redundant pair, the global config file is shared by both switches. If you restore the global config file (either alone or as part of the startup config), you overwrite all global parameters for both switches in the pair. F5 recommends restoring the running-config file first, rejoining the redundant pair, and then restoring the global config file if neccesary.
