K8096: The BIG-IP GTM link autoconf option may prevent the configuration from loading after upgrading to 9.3.0 or later

Type
Known Issue
Published
2008-03-04
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP GTM: 9.4.3, 9.4.1, 9.4.0, 9.3.1, 9.4.2, 9.3.0
Source

Known Issue

This is the result of a known issue. If the link autoconf option is enabled or listed in the wideip.conf file, but the autoconf option is disabled on the server, the gtmparse daemon will fail to properly parse a configuration file previous to BIG-IP GTM 9.3.0 after an upgrade. As a result, the Configuration utility will appear with minimal or no configuration displayed.

The link autoconf option is available when the autoconf option is enabled on a server, allowing the BIG-IP GTM system to add and monitor the available links the server utilizes. If a configuration file from BIG-IP GTM 9.2.2 through 9.2.5 is upgraded to BIG-IP GTM 9.3.0 or later, and contains the link autoconf option but the autoconf option is not enabled on the server, the gtmparse daemon will fail to correctly parse the configuration and prevent it from loading after the upgrade has been completed.

F5 Product Development tracked this issue as CR88397 and it was fixed in BIG-IP GTM 9.4.4. For information about upgrading, refer to the-BIG-IP GTM Release Notes.

This issue still exists in the BIG-IP GTM 9.3.0 software branch. To monitor the status of this CR, refer to the BIG-IP GTM Release Notes.

Resolution

Workaround

You can determine whether the BIG-IP GTM system is subject to this issue if after an upgrade, the configuration fails to load after typing the following command:

gtmparse -l

A warning will display, appearing similar to the following example:

# gtmparse -l
gtmparse: Initializing ...
/usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
/usr/local/gtm/include/base_region.ISP: SUCCESS
/config/gtm/region.user: SUCCESS
/config/gtm/wideip.conf: SUCCESS
gtmparse: SUCCESS
WARNING, recvMCPreply: Got bad result: 01070748:3: Virtual server autoconf must be enabled if link autoconf is enabled.

An error message will also be reported in the /var/log/gtm file.

Correcting the configuration file

You can work around this issue by correcting the configuration file. To do so, perform the following procedure:

Note: The following workaround is only required to be performed once. Once the configuration file has been corrected, the changes are permanent.

  1. Log in to the command line.

  2. Change directories to the /config/gtm/ directory by typing the following command:

    cd /config/gtm/

  3. Make a backup of the wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.original

  4. Use a text editor to edit the wideip.conf file.

  5. Locate any line that contains the following:

    link_autoconf enable

    For example:

    server { // datacenter=dc-SEA_DATA, #VS=0
    name "mybigip-system"
    type bigip
    box { // gtm
    address 10.10.10.40
    unit_id 1
    }
    box { // gtm
    address 10.10.10.41
    unit_id 2
    }
    link_autoconf enable <====== Locate this line within the server objects
    monitor "monitor_BIG-IP_Monitor"
    }

  6. Remove the link_autoconf enable entry or add the autoconf enable option before the link_autoconf enable line by performing one of the following two options:

    • Remove the link_autoconf enable line:

      server { // datacenter=dc-SEA_DATA, #VS=0
      name "mybigip-system"
      type bigip
      box { // gtm
      address 10.10.10.40
      unit_id 1
      }
      box { // gtm
      address 10.10.10.41
      unit_id 2
      }
      monitor "monitor_BIG-IP_Monitor"
      }

    • Add the autoconf enable option before the link_autoconf enable line:

      server { // datacenter=dc-SEA_DATA, #VS=0
      name "mybigip-system"
      type bigip
      box { // gtm
      address 10.10.10.40
      unit_id 1
      }
      box { // gtm
      address 10.10.10.41
      unit_id 2
      }
      autoconf enable
      link_autoconf enable
      monitor "monitor_BIG-IP_Monitor"
      }

  7. Save the changes made to the file.

  8. To ensure all instances have been corrected or removed, type the following command:

    gtmparse -l

    Note: If the gtmparse -l command still reports the link autoconf issue, edit the file and correct the remaining instances.

  9. Load the corrected wideip.conf configuration file by typing the following command:

    gtmload
