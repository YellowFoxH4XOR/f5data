K000162215: VELOS Partition GUI not accessible although ping and TCP port 443 are reachable

Description

On F5OS VELOS platforms, a newly created partition's management GUI may be inaccessible even though the partition management IP responds to ping and SSH connections.

Environment

  • F5OS-C
  • Partition management interface
  • Client system with the network interface MTU set to 9000
  • Network path (switches/routers) configured for the standard Ethernet MTU of 1500 (jumbo frames not supported)

Cause

By default, the partition management interface uses an MTU of 9000.

If the client interface is also configured with an MTU of 9000, but the network path does not support jumbo frames, the TCP session negotiates a large MSS (8940). This results in oversized packets being silently dropped, causing the GUI to become inaccessible.

Answer/Recommended Actions

1. Verify the MTU configured on the client network interface. If the network path does not support jumbo frames, set the client interface MTU to 1500.

Example (Windows): 

netsh interface ipv4 show subinterfaces

or for IPv6:

netsh interface ipv6 show subinterfaces

If the MTU is set to 9000, you can change it to 1500 by running the following command: (for example, on interface Ethernet 1)

netsh interface ipv6 set subinterface "Ethernet 1" mtu=1500 store=persistent

2. If jumbo frames are required, ensure all devices in the network path (switches, routers, client NICs) are configured to support the higher MTU.

3. Alternatively, configure TCP MSS clamping on an intermediate router or gateway to advertise a smaller MSS during the TCP handshake, preventing oversized packets from being transmitted.
