Issue

Error Message

Null in request

Message Location

You may encounter this message in the following locations:

  • The /var/log/asm file
  • Event logs in the BIG-IP ASM Configuration utility

Description

This message occurs when one of the following conditions is met:

  • A NULL or %00 is encountered in the URI, query string, or POST data
  • A NULL is encountered in multipart data with a text based or XML based Content-Type header
  • A NULL is encountered in binary multipart data, does not have a text based or XML based Content-Type header, and no matching parameter is configured in the security policy

When the BIG-IP ASM system encounters a NULL or %00 in the URI, query string, or POST data, the system reports and Null in request sub violation (a sub violation of the HTTP protocol compliance failed violation). This violation can also be triggered when the BIG-IP ASM system encounters a NULL within the data of a multipart request. By default, the BIG-IP ASM system blocks multipart data containing a NULL byte, unless a matching parameter is configured with either of the following:

  • The Parameter Value Type set to Ignore
  • The Parameter Value Type set to User-input value, and the Data Type set to File Upload

    In this case, the BIG-IP ASM system only performs length checks on the binary data.

If a NULL is encountered in binary multipart data, and a matching parameter in the policy is configured with the Parameter Value Type set to User-input value, but does not have File Upload configured as the Data Type, the BIG-IP ASM system reports the following message (instead of the Null in request error message):

Null in multi-part parameter value

Disabling the Null in request and Null in multi-part parameter value violations

For the Null in request and Null in multipart parameter value violations, you cannot automatically update the security policy from the Learning screen. If you determine that the request is legitimate, you can disable either violation by performing one of the three following procedures:

Note: When you disable either violation, the Policy Enforcer no longer generates an alarm for future occurrences of that violation.

  • Configuring the parameter with the NULL to use User-input value as the Parameter Value Type
  • Configuring the parameter with the NULL to use Ignore value as the Parameter Value Type
  • Preventing the Null in request violation message from being reported
  • Preventing the Null in multi-part parameter value violation message from being reported

Configuring the parameter with the NULL to use User-input value as the Parameter Value Type

In this case, the BIG-IP ASM system performs length checks only on the parameter value. To configure the parameter with the NULL to use User-input value as the Parameter Value Type, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Parameters.
  3. Select the name of the parameter to modify or click Create.
    • To create parameters, refer to the Adding Parameters to a Security Policy chapter of the BIG-IP Application Security Manager: Implementations guide.
  4. From the Parameter Value Type menu, select User-input value.
  5. From the Data Type menu, select File Upload.
  6. To add the parameter to the configuration, select Update or Create.
  7. Select the Apply Policy button to immediately put the security policy changes into effect.

Configuring the parameter with the NULL to use Ignore value as the Parameter Value Type

To configure the parameter with the NULL to use Ignore value as the Parameter Value Type, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Parameters.
  3. Select the name of the parameter to modify or click Create.
    • To create parameters, refer to the Adding Parameters to a Security Policy chapter of the BIG-IP Application Security Manager: Implementations guide.
  4. From the Parameter Value Type menu, select Ignore value.
  5. To add the parameter to the configuration, select Update or Create.
  6. Select the Apply Policy button to immediately put the security policy changes into effect.

Preventing the Null in request violation message from being reported

To prevent the Null in request violation (a sub violation of the HTTP protocol compliance failed) from being reported, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings > HTTP protocol compliance failed.
  3. Unselect the Enable check box for Null in request.
  4. Select Save to save the changes.
  5. Select Apply Policy to put the change into effect.

Preventing the Null in multi-part parameter value violation message from being reported

To prevent the Null in multi-part parameter value violation message from being reported or blocked, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings > Parameters.
  3. Unselect the Alarm and Block check boxes for Null in multi-part parameter value.
  4. Select Save to save the changes.
  5. Select Apply Policy to put the change into effect.

Impact

When you configure the security policy to accept requests that generate the Null in request or NULL in multi-part parameter value violation, the Policy Enforcer no longer generates an alarm or blocks future occurrences of the violation. Review the requests that triggered the violation before you disable the violation, to ensure that the requests are not malicious.
