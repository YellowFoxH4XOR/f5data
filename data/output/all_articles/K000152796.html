Description

When configuring remote syslog servers on BIG-IP systems, syslog-ng may produce log entries with repeated severity keywords (such as "notice notice notice...") and duplicate log lines. Log files may fill with these unusual duplications, and messages like the following may appear repeatedly:

Jul 26 05:41:29 bigip.example.com notice syslog-ng[PID]: Configuration reload request received, reloading configuration;
Jul 26 05:41:29 bigip.example.com notice notice syslog-ng[PID]: Configuration reload request received, reloading configuration;
Jul 26 05:41:29 bigip.example.com notice notice notice syslog-ng[PID]: Configuration reload request received, reloading configuration;
Jul 26 05:41:29 bigip.example.com notice notice notice notice syslog-ng[PID]: Configuration reload request received, reloading configuration;
Jul 26 05:41:29 bigip.example.com notice notice notice notice notice syslog-ng[PID]: Configuration reload request received, reloading configuration;

This "staircase" effect in the logs indicates recursive logging behaviour.

Environment

  • BIG-IP LTM
  • Remote syslog servers defined

Cause

The issue is triggered when a remote syslog server is configured with a hostname or IP address that resolves to the local BIG-IP system itself (localhost or its own management/self IP). This causes syslog-ng to send log messages back to itself, resulting in recursive logging. Each message is repeatedly processed and logged again, causing duplicated severity keywords and log line duplication.

Recommended Actions

Ensure that none of the remote syslog server entries point to the local system’s own IP address or "localhost".

If hostnames are used for remote syslog servers, verify via DNS lookup that they do not resolve to any of the local system’s addresses.
