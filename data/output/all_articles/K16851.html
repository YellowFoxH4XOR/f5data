Known Issue

When executing an iRule command, the BIG-IP APM system may stop processing traffic and produce a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM access profile uses a virtual server that is configured with an iRule.
  • The associated iRule includes the ACCESS::policy evaluate command.
  • You attempt to establish a session with the access profile's virtual server.

Impact

Attempts to establish sessions fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs messages in the /var/log/apm file that correlate with the time of session resource access failures. These messages may appear similar to the following example:

    notice apmd[2612]: 01490000:5: ** SIGSEGV **
    notice apmd[2612]: 01490000:5: fault addr: 0xC4
    notice apmd[2612]: 01490000:5: fault code: 0x1
    notice apmd[2612]: 01490000:5: fault time: <date and time of event>
  • The apmd process produces a core file in the /shared/core/ directory, similar to the following example:

    apmd.bld0.0.141.core.gz
