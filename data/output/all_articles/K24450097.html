Description

You would like to block HTTP traffic destined to known undesired domains, based on the value of the Host header in requests.

You would like to do this with AWAF, an iRule, or a Local Traffic Policy.

Environment

  • HTTP traffic
  • ASM and/or LTM provisioned

Cause

None

Recommended Actions

This is possible with AWAF, an iRule, or a Local Traffic Policy.

  • ASM/AWAF
  • iRule
  • Local Traffic Policy

ASM/AWAF

Note: This requires an AWAF license.

From version 15.1 onwards, the Illegal host name violation is available under Security >> Application Security : Policy Building : Learning and Blocking Settings.

Enabling Block for this violation will block requests when the value found in the request's Host header is not a configured Host Name under Application Security >> Headers >> Host Names.

iRule

Here is an example iRule that references a data group containing known undesired domains:

when HTTP_REQUEST {
    if { [class match [string tolower [HTTP::host]] ends_with domain_names] } {
        log local5. "Reset connection: domain [HTTP::host] is disallowed."
        reject
        }
}

ltm data-group internal domain_names {
    records {
        abc.com { }
        xyz.com { }
        example.com { }
    }
    type string
}

In this example, if the value of the Host header ends with abc.com, xyz.com, or example.com, the connection will be reset and a message will be logged to /var/log/pktfilter.

Note: A Local Traffic Policy is technically better performance than an iRule, and in this case very easy to configure.

Local Traffic Policy

Here is an example Local Traffic Policy:

ltm policy /Common/drop_host {
    controls { forwarding }
    requires { http }
    rules {
        hostnames {
            actions {
                0 {
                    forward
                    reset
                }
            }
            conditions {
                0 {
                    http-host
                    host
                    ends-with
                    values { abc.com xyz.com example.com }
                }
            }
        }
    }
    strategy /Common/first-match
}

Similar to the iRule, if the value of the Host header ends with abc.com, xyz.com, or example.com, the connection will be reset.

Note: This article offers configuration examples only. Any configuration changes should be tested thoroughly before implementing into a production environment.

Additional Information

This type of configuration would be most effective when your BIG-IP is load balancing outbound HTTP requests. This isn't a common configuration.
