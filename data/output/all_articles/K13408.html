Topic

This article applies to BIG-IP 11.x - 21.x. For information about other versions, refer to the following article:

  • K8435: Overview of Single Configuration Files (9.x - 10.x)

A single configuration file (SCF) is a flat, text file that contains all of the objects that compose the BIG-IP configuration.

Important: SCF files are intended to help configure additional BIG-IP systems; SCFs are not intended to back up and restore a full BIG-IP system configuration or to restore a BIG-IP configuration to a later BIG-IP version. To back up and restore a full BIG-IP system configuration, or to restore a BIG-IP configuration to a later BIG-IP version, use a user configuration set (UCS) archive file. For information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive. For more information about UCS archives, refer to K4423: Overview of UCS archives.

Description

You can use the TMOS Shell (tmsh) to define all BIG-IP configuration elements in a single, flat SCF. You can use an SCF from one BIG-IP system to configure additional BIG-IP systems, and an SCF is useful when you want to configure a new BIG-IP system. An SCF may also be useful in one or more of the following circumstances:

  • You want to replicate a configuration across multiple BIG-IP systems.
  • You want to migrate a configuration from one platform type to another (for example, from BIG-IP VE to a hardware platform).

When you save an SCF using tmsh, the system gathers all of the objects that compose the running configuration. After the objects are gathered, the system saves the configuration to a flat file in the /var/local/scf/ directory with the name you specify. For example, the tmsh save /sys config no-passphrase file bigip1 command saves the currently running configuration to /var/local/scf/bigip1.

When you install an SCF on a target BIG-IP system, the system first saves the currently running configuration to /var/local/scf/backup.scf and then loads the specified SCF file into running memory. For example, the tmsh load /sys config file bigip1 command saves the currently running configuration to /var/local/scf/backup.scf before loading the /var/local/scf/bigip1 file on the system. In BIG-IP 11.5.0 and later, if the SCF is encrypted, you must specify the passphrase that was used with the passphrase option when you save the SCF.

Data contained in the SCF file

The SCF contains all of the BIG-IP configuration, including BIG-IP objects and the customizations to the UNIX configuration. The following information is contained in an SCF:

  • All native BIG-IP system configuration elements. The SCF contains sufficient data to completely provision a BIG-IP system from one file. Data from the following BIG-IP system files are contained in the SCF:
    • bigip.conf
    • bigip_base.conf
    • bigip_user.conf
    • bigip_script.conf (if non-default iApps templates have been uploaded)
  • BIG-IP module configuration. The SCF file contains BIG-IP module configuration, such as BIG-IP GTM, BIG-IP ASM, and BIG-IP APM.
  • Essential Linux configuration elements. The SCF file contains the BIG-IP configuration stanzas that customize the essential Linux configuration elements. For more information, refer to K14272: Overview of UNIX configuration files (11.x - 21.x). When you use tmsh to modify the Linux configuration files on the BIG-IP system and then save an SCF, customizations to the Linux configuration from the following files are saved in the SCF:
    • /config/bigip/auth/localusers
    • /config/bigip/auth/pam.d/httpd
    • /config/bigip/auth/pam.d/system-auth
    • /config/bigip/auth/userroles
    • /config/httpd/conf/httpd.conf
    • /config/httpd/conf.d/ssl.conf
    • /config/ntp.conf
    • /config/ssh/sshd_config
    • /config/snmp/snmpd.conf
    • /etc/hosts
    • /etc/hosts.allow
    • /etc/logrotate_common.conf
    • /etc/logrotate.conf
    • /etc/resolv.conf
    • /etc/ssmtp/ssmtp.conf
    • /etc/sysconfig/clock
    • /etc/sysconfig/network
    • /etc/syslog-ng/syslog-ng.conf
    • /etc/dhclient.conf
    • /var/run/config/httpd.conf.d/mod_auth_pam.conf
  • Device trust certificates and keys. These are included in the SCF starting in BIG-IP 12.1.0. For more information about the encryption of the SCF, refer to Encryption of the SCF in this article. 

Data not contained in the SCF 

The data files in the BIG-IP filestore in the /config/filestore directory (for example, the SSL certificate/key files, external monitor files and external data group files) are not saved in the SCF. Files in filestore that are referenced by the SCF configuration are automatically saved into a separate TAR file when a copy of the SCF is saved.

Note: You can display the list of data files in this TAR file or view the content of these data files. For more information, refer to K04934737: Viewing the single configuration file TAR file.

By default, the name of the TAR file has the same name as the SCF file and have .tar as the file extension. For example, when you save an SCF using the name myscf1, the default created TAR file is named myscf1.tar, and both files saved in the /var/local/scf directory as follows:

/var/local/scf/myscf1
/var/local/scf/myscf1.tar

Alternatively, you can specify a different name for the TAR file by using the tar-file option, when saving a copy of the SCF. For example, when you save an SCF using the name myscf2, and you use the tar-file option with the name myscf2-tar, both the files are saved in the /var/local/scf directory as follows:

/var/local/scf/myscf2
/var/local/scf/myscf2-tar

Note: When you use the tar-file option, the actual file does not have the .tar file extension by default, unless specified.

Encryption of the SCF

In BIG-IP 11.5.0 and later, you can encrypt both the SCF and its corresponding TAR file. With the TAR file containing sensitive information such as SSL certificate/key files, encrypting these files becomes necessary when you want to transfer them out of the system. You can specify the passphrase option with the passphrase you want when you generate the SCF and its corresponding TAR file. 

For example, tmsh save /sys config file bigip1 passphrase my_passphrase

Similarly, when you want to install an encrypted SCF and its TAR file on a target BIG-IP system, you must specify the passphrase option with the passphrase that was used to generate the SCF.

Starting in BIG-IP 12.1.0, when you generate an SCF, the SCF file itself includes the device trust certificates and keys but not in the corresponding TAR file. As a result, when you generate an SCF, by default you are required to specify the passphrase option with the passphrase. If you want to generate without a passphrase, you need to specify the no-passphrase option. For example, tmsh save /sys config file bigip1 no-passphrase

Saving an SCF file

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: Saving a configuration to an SCF does not affect the running or stored configuration of the BIG-IP system upon which you run the command.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To save the running configuration to an unencrypted SCF in BIG-IP 11.x and 12.0.0, use the following command syntax:

    save /sys config file <SCF_filename>

    To save the running configuration to an unencrypted SCF in BIG-IP 12.1.0 and later, use the following command syntax:

    save /sys config file <SCF_filename> no-passphrase

    To save the running configuration to an encrypted SCF, use the following command syntax:

    save /sys config file <SCF_filename> passphrase <passphrase>

    Alternatively, to specify a custom name for the TAR file when saving the configuration to an unencrypted SCF in BIG-IP 11.x and 12.0.0, use the following command syntax:

    save /sys config file <SCF_filename> tar-file <TAR-FILE_filename>

    To specify a custom name for the TAR file when saving the configuration to an unencrypted SCF in BIG-IP 12.1.0 and later, use the following command syntax:

    save /sys config file <SCF_filename> no-passphrase tar-file <TAR-FILE_filename>

    Note: When you use the tar-file option, the actual file does not have .tar file extension by default, unless specified. Additionally, you cannot specify the passphrase option when you use the tar-file option.

  3. The SCF file and the TAR file are saved to the /var/local/scf/ directory.

Installing an SCF file on the BIG-IP system

Note: Due to a known issue, if you modify, in an SCF, a self IP address for a VLAN on which routes are also configured, the routes may be missing from the Linux kernel route table after you load the SCF. For more information, refer to K14572: Routes configured in a single configuration file may be missing from the Linux kernel route table after loading the single configuration file.

Impact of procedure: Performing a configuration load on an Active device group member can potentially disrupt traffic managed by the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To install an unencrypted SCF on a BIG-IP system, use the following command syntax:

    load /sys config file <SCF_filename>

    To install an encrypted SCF on a BIG-IP system, use the following command syntax:

    load /sys config file <SCF_filename> passphrase <passphrase used to encrypt SCF during generation>

    To load the unencrypted configuration with a TAR file that has a custom name, use the following command syntax:

    load /sys config file <SCF_filename> tar-file <TAR-FILE_filename>

    Note: If you have previously saved the configuration using the tar-file option, you should also load the configuration using the tar-file option.

  3. Enter y at the following prompt to load the SCF:

    Replace the running configuration? (y/n)

  4. Note that the previous steps only install the configuration into the BIG-IP system memory, the configuration is not saved on the BIG-IP system storage. To save the configuration on the BIG-IP system, you should enter the following command:

    save /sys config partitions all

Recommendations

General guidelines for using SCFs are as follows:

  • Build a BIG-IP LTM template configuration by configuring a system using the Configuration utility or tmsh. Most custom Linux configurations must be completed using tmsh.
  • Save an SCF from the fully-configured system using the tmsh save /sys passphrase <passphrase> config file command, and store the SCF in a safe place for future use. The SCF can be used as a template to configure future BIG-IP systems.
  • When you are ready to use the SCF to configure a new BIG-IP system, copy the SCF to the new BIG-IP system and edit the SCF file prior to importing it. For example, change the IP addresses, routing information, interface settings and other common settings, as needed.
  • Install the SCF into a new system using the tmsh load /sys config file passphrase <passphrase used to encrypt SCF> command. 
  • You can install the SCF only to a BIG-IP system running the same version as the version on which the SCF was created.
