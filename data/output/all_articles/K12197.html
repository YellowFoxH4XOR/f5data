K12197: The BIG-IP system no longer sends monitor traffic to nodes or pool members with a status of Forced Offline or Down

Issue

In BIG-IP 9.x, when using the Configuration utility to change the node or pool member status to Forced Offline, or using the command line to change the status to Down, the system continues to send monitoring traffic to the node or pool member, and the bigd process tracks the object's status while it is down. When changing the node or pool members' status from Forced Offline to Enabled, the BIG-IP system can immediately transition the node or pool member to the appropriate state.

Starting in BIG-IP 10.0.0, the behavior has changed, and when the node or pool member status is set to Forced Offline or Down, the BIG-IP system suspends bigd health checks, and does not send monitoring traffic to the node or pool member. When changing the node or pool members' status from Forced Offline to Enabled, the system immediately resumes monitoring the device and updates the status of the device based on the device's ability to respond to monitoring requests. This change was made to prevent the BIG-IP system from continually sending monitor traffic to a downed device.

Note: In BIG-IP 10.0.0 through 10.2.0, the system incorrectly transitions a node or pool member to an unknown state when a user changes the object's status from Forced Offline to Enabled. For more information, refer to K12198: A node or pool member transitions to an 'unknown' state when a user changes the status from Forced Offline to Enabled.
