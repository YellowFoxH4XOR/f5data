Description

  • While changing F5 configuration via GUI, either an F5 service restarts or the whole device froze.
  • Unexpected failover
  • Similar message as the following can be seen on /var/log/kern.log

    Jun 17 15:41:20 LTM1.example.com warning kernel: corehelper invoked oom-killer: gfp_mask=0x201da, order=0, oom_score_adj=0
    Jun 17 15:41:20 LTM1.example.com err kernel: Killed process 1699 (avrd) total-vm:2298676kB, anon-rss:602392kB, file-rss:24340kB, shmem-rss:7496kB

Environment

  • BIG-IP 2000 series
  • 3 modules provisioned along with AVR

Cause

The seen behaviour is the result of memory pressure caused by the current provisioning (3 modules provisioned along with AVR) which is not supported in this platform.

  • BIG-IP 2000 series cannot be provisioned with 4 modules 
  • Application Visibility and Reporting (AVR) can be provisioned with only one other module

Recommended Actions

Deprovision some modules to match supported configuration

  1. On GUI go to System  >  Resource Provisioning
  2. Locate the modules to be deprovisioned and on the Provisioning drop-down menu for the module in question select None
  3. Click Submit
  4. Restart the device

Additional Information

  • No more than three modules should be provisioned together.
  • On the 2000s and 2200s, Application Acceleration Manager (AAM) and Application Visibility and Reporting (AVR) can be provisioned with only one other module
  • To use Access Policy Manager (APM) and Secure Web Gateway (SWG) modules together on platforms with exactly 8 GB of memory, Local Traffic Manager (LTM) provisioning must be set to None.
