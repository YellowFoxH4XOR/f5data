Known Issue

If you use the cpcfg utility to copy the configuration from a BIG-IP version 10.1.x or earlier slot to a BIG-IP version 10.2.x slot on the same unit, the BIG-IP system fails to copy the admin user UID to the destination slot. This causes the SELinux security context for files to be out of sync and as a result, the BIG-IP system is unable to load the configuration.

In version 10.x, you can use the cpcfg utility to copy configurations between slots on the same unit.

Impact

The BIG-IP system is unable to pass traffic when booted to the affected slot.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system is unable to load the configuration file, and reports the following error message to the console:

    01070261:3: Can't create a homdir for username admin (user admin has no UID)
  • The BIG-IP system named process restarts continuously and logs the following error message to the console:

    emerg logger: Re-starting named

  • The BIG-IP system httpd process is unable to start properly, resulting in Configuration utility access failure. In addition, the following error message is reported to the console:

    confpp[PID]: syntax check command FAILURE for unix_config_httpd returned: '256'
    Starting httpd: httpd: Syntax error on line 142 of /etc/httpd/conf/httpd.conf: Cannot load /etc/httpd/modules/libphp5.so into server: /etc/httpd/modules/libphp5.so: cannot open shared object file: Permission denied

Workaround

To work around this issue, you can re-label the file systems and reboot the BIG-IP system to allow the BIG-IP system to rebuild the appropriate file permissions. To do so, perform the following procedure:

Impact of workaround: If the BIG-IP system is the active member of a redundant pair, rebooting will cause a failover. If the BIG-IP system is a standalone unit, rebooting will interrupt traffic processing.

  1. Log in to the BIG-IP command line.
  2. To re-label the file systems, type the following command:

    touch /.autorelabel

  3. To reboot the BIG-IP system, type the following command:

    reboot
