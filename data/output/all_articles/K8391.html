Known Issue

This is the result of a known issue. When a PVA-enabled virtual server processes a fragmented packet, the PVA forwards the packet to the TMM for processing. The TMM then creates a temporary connection flow in memory for the fragmented packet. A memory leak of one connection flow per connection occurs when a PVA-enabled virtual server processes fragmented packets.

Note: Connection flows are referred to as connflows by the bigpipe memory command.

To view the connection flow for the system, run the bigpipe memory command. If the allocated and maximum connection flow values continue to grow, the system is likely leaking connection flows.

F5 Product Development tracked this issue as CR91680 and it was fixed in BIG-IP version 9.4. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF2 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the Hotfix from the F5 Downloads site.
