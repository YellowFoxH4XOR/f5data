K000147148: Why do I get a 200 response code when the WAF has blocked the request?

Type
Support Solution
Published
2024-11-08
Updated
2026-01-01
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000147148

Description

  • A request has been blocked by the WAF but it returns a 200 OK response code.

Environment

  • F5®Distributed Cloud (SaaS)
  • F5 Distributed Cloud Console (XC Console)

 

Cause

The WAF response page is customizable, and the default response code value is set to 200 OK. When the WAF blocks a request, it returns a 200 OK response for the blocking page itself, not for the original (blocked) request.

 

Recommended Actions

The response code can be customized if needed.

  • The response code can be configured under the Advanced configuration in the App Firewall setting.
  • Here, you can scroll down to Blocking Response Page and select Custom where you will be able to configure:
    • The custom Response Code and;
    • The custom Blocking Response Page Body - which can be in either Base64 or plain Text.
  • Make sure the App Firewall you are configuring corresponds to the correct HTTP LB / application.

Additional Information

    • To find out if the request has been blocked by the WAF, look at the action value under the Detection section in the Information tab of the request. 

    For example: 

    • Returning a 200 OK for a blocking page is a common default to avoid leaking information about security controls, but you may configure a different response code (such as 403 Forbidden) if desired.
    • Customizing the blocking page and its response code can help align with application requirements or compliance needs.
