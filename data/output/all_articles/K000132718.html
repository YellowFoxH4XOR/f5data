K000132718: Manually failing over SDC VIP to another FEP

Type
Support Solution
Published
2023-02-22
Updated
2023-02-22
Source
https://my.f5.com/manage/s/article/K000132718

Description

  • During maintenance like hardware replacements, VIP will be manually failed over to the secondary FEP.

Environment

  • SDC 5.1
  • FEP 

Cause

None, this is by design.

 Recommended Actions

  • Verify first on which server the VIP is located, there are 2 methods:

1. via Web_UI

  Topology ->Virtual Servers, click on relative fep. "Open" status will show on which server the VIP is located. 

2. via CLI. 

  Login to each server via ssh as user root and run the following command:

   ip a |grep <VIP IP>


  • How to relocate Virtual Server IP:

For example you found that Virtual Server located on server Fep-01.

 

1. Login via ssh to server Fep-02 as user root

2. run :

monit status

  monit stop keepalived

  monit status

  monit start keepalived

  monit staus

monit stop <FEP PROCESS>

monit status

monit start <FEP PROCESS>

monit status


3. Login via ssh to server Fep-01 as user root

4. run :

   monit status

  monit stop keepalived

  monit status

  monit start keepalived

  monit staus

monit stop <FEP PROCESS>

monit status


5. Login to Web_UI and verify that <FEP PROCESS> in connect state, and all peers are connected 


6. on server Fep-01 execute :

  monit start <FEP PROCESS>

  monit status


Additional Information

None.
