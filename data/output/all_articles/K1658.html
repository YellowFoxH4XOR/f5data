Topic

The short answer

The Broadcom SSL chipset does contain a flaw, however the flaw is in the bulk encryption function of the chipset, which BIG-IP does not use.

Although it is possible to use the chipset to accelerate bulk encryption (if the chipset did not contain this flaw), it is actually faster for the BIG-IP main processors to do this work. Therefore, BIG-IP is designed to off-load the initial asymmetric encryption to the SSL accelerator hardware, while the main processors handle bulk encryption. This architecture is consistent in both the BIG-IP switch appliances and server appliances, regardless of the SSL acceleration chipset.

Detailed information

The ARC4 algorithm used for the Broadcom 5820 SSL chipset uses two index variables called i and j. Both of these variables are set to 0 on the first encrypted or decrypted packet using ARC4. When i and j are set to 0, the 5820 works fine, but on any subsequent packets of a long bulk operation, these variables are likely to be something other than 0. (This is referred to as ARC4 continue mode, since the ARC4 is continuing from a previously initialized operation.) If i and j are not set to 0, then the ARC4 algorithm does not work on the 5820.

BIG-IP does not use the Broadcom 5820 to accelerated bulk encryption, not only because of this flaw, but because any potential performance gains are negated by the overhead of passing the SSL state from the main processors to the chip sets.
