Description

You would like to manage Cacheable HTTPS Responses to prevent from Sensitive Information being cached by Browsers or Intermediary Proxies. If HTTP Responses do not include appropriate Cache Control headers, It can increase the risk of data exposure in your scenario.

Environment

  • LTM Module
  • HTTP Response Header
  • iRule / Local Traffic Policy

Cause

Lack of restrictive Cache Control headers (Cache-Control: no-store, no-cache and Pragma: no-cache) in HTTP responses allows Browsers and Proxies to cache sensitive content.

Recommended Actions

You can create an iRule or Local Traffic Policy object and attach It to your desired Virtual Server to Insert the desired Cache Control - HTTP Response Headers into all the HTTP Responses received from the Back-end Servers to make sure nothing is being cashed on Client side.

Important: Before applying such changes to your Virtual Server, you may need to double-check your App logic and how it works with your Application Team, and make sure applying these changes might not have any negative Impact on normal service operations.

 

1. Using an iRule object to Insert "Cache-Control" and "Pragma" Response Headers:

when HTTP_RESPONSE {
    HTTP::header insert "Cache-Control" "no-store, no-cache"
    HTTP::header insert "Pragma" "no-cache"
}

 

2. Using a Local Traffic Policy object to Insert "Cache-Control" and "Pragma" Response Headers:

1. Go to Local Traffic > Policies > Policy List.
2. Create a new policy or edit an existing one.

3. Add a rule with these actions (at HTTP Response event):
Insert HTTP header: Cache-Control with value no-store, no-cacheInsert HTTP header: Pragma with value no-cache

4. Save and publish the policy.
5. Apply it to the relevant virtual server.
