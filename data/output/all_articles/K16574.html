Known Issue

On rare occasions, BIG-IP APM licensing records on chassis systems may go missing from the sessiondb.

This issue can occur when one of the following conditions is met:

  • Due to an unusual sequence of clustering events, the license records do not install to the sessiondb.
  • The BIG-IP APM system incurs a race condition, which causes the license records to become unavailable.

Impact

The BIG-IP APM sessiondb is unable to retrieve the concurrent connectivity and access session licensing limits, which may prevent user session establishment.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to connect to the BIG-IP APM system and receive an error message that appears similar to the following example:

    The maximum number of concurrent user sessions has been reached. No new user sessions can start at this time.

  • Session limit initialization messages similar to the following are absent from the /var/log/apm file:

    notice tmm[12627]: 01490510:5: 00000000: Initializing Access with max global concurrent access session limit: 500
    notice tmm[12627]: 01490526:5: 00000000: Initializing Access with max global concurrent connectivity session limit: 500

  • Users view messages in the /var/log/apm file that appear similar to the following example:

    err tmm[16223]: 01490514:3: 00000000: Access encountered error: ERR_NOT_FOUND. File: ../modules/hudfilter/access/access_license.c, Function: access_license_session_callback, Line: 865
