Known Issue

The BIG-IP system may fail to send TCP Keep-Alive packets to the client side of an established TCP connection if the client side of the TCP connection is in the FIN-WAIT-2 state.

This issue occurs when all of the following conditions are met:

  • The backend server sends a request to the BIG-IP system to close the TCP connection and the BIG-IP system acknowledges the request.
  • In response, the BIG-IP system sends a request to the client to close the TCP connection and the client acknowledges the request.
  • The BIG-IP system does not receive any subsequent indication that the client is ready to close its TCP connection.
  • The backend server continues to send requests to the BIG-IP system to close the TCP connection.

Impact

Idle TCP connections remain open on the BIG-IP system and consume resources.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe many zombie connections in the BIG-IP connection table, where the Idle Time values exceed the Idle Timeout value (300 seconds by default) configured in their associated TCP profile.
  • The TCP profile statistics report many connections in the CLOSE-WAIT/LAST-ACK or FIN-WAIT/CLOSING states.
