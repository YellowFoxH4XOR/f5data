Description

New HTTP or HTTPS monitor with a receive string is marking pool members down. Curl using the Fully-Qualified Domain Name (FDQN) through the VIP returns the expected result, but curl to the pool FQDN or using the IP address for the domain returns a 400 or 404 response.

Environment

  • HTTP/1.1 monitor

Cause
Monitor has an incorrect host header or doesn't have a host header.
HTTP/1.1 requires a Host: header and most applications require it to be the correct FQDN or blank

Recommended Actions

Add a host header using the value configured on the server or leave the value empty.

Example send string with the host FQDN:
GET /healthcheck.aspx HTTP/1.1\r\nHost: <FQDN of device>\r\nConnection: Close\r\n\r\n

Example send string without a host FQDN:
GET /healthcheck.aspx HTTP/1.1\r\nHost: \r\nConnection: Close\r\n\r\n

Note: In the first example replace <FQDN of device> with the FQDN of the destination device being monitored.

Additional Information
Default HTTP(S) monitor works because it will mark a pool member up when it returns a 4xx status because it does not have a receive string
