Note: This Solution article applies only to BIG-IP 4.x. For information about rewriting redirects on BIG-IP 9.x and later, refer to K6911: Using iRules to rewrite HTTP redirects to match the port used by the virtual server.  

If a virtual server listens on port 80, with web servers listening on a different port, and the web server issues an HTTP redirect because the request does not contain a trailing slash, the web server appends the port to the end of the host portion of the URL.

For example, if the webserver listens on port 8000 and a client makes the following request:

http://www.domain.com/directory1

The client gets redirected to:

http://www.domain.com:8000/directory1/

To solve this problem, you can either create a port redirect rule or use an F5-supplied ISAPI filter to prevent your IIS servers from issuing incompatible redirects. For more information on port redirect rules, see the following process. For more information on the ISAPI filter, refer to K1607: Using an ISAPI filter on Microsoft IIS to rewrite URLs so that it creates redirects that match the protocol and port used by the BIG-IP virtual server or SSL proxy.

Port redirect rule

You can create a BIG-IP system redirect rule that listens on the same port as the web servers.

For example:

rule redirect_to_80 {
    redirect to "http://%h/%u"
}
virtual 192.168.1.1:8000 {
   use rule redirect_to_80
}

With this rule, clients that are redirected from the web servers to port 8000 reconnect to the BIG-IP system on port 8000, and the BIG-IP system redirects them to the correct port (port 80). You can also configure the BIG-IP system to host the website on both port 80 and port 8000 on the same server, which would eliminate the need for redirects.

Trailing slash redirect rule

You can configure the BIG-IP system to issue redirects that append a trailing slash rather than having the web server handle this functionality. To do so, perform the following steps.

Step 1 - Create a class

From the Configuration utility, create a class that contains every possible file extension on your website. For example: html, htm, asp, jsp, jpg, gif, jpeg, png, and so forth. For specific instructions, refer to the BIG-IP manual.

Step 2 - Create a rule

Create a rule that looks at every URI and appends a trailing slash if the URI:

  • Does not end with one of the extensions listed in the extensions class
  • Does not already end with a trailing slash

Note: This rule can be resource intensive, depending on the traffic to your site, the amount of BIG-IP CPU/memory, and the number of connections. F5 recommends that you use this rule only if there is no other alternative.

For example:

if (not (http_uri ends_with one of extensions) and not (http_uri ends_with "/") ) {
   redirect to "http://%h/%u/"
}
else {
   use ( Standard_pool )
}

Note the use of the one of operator to reference all of the extensions contained within the extensions class; you will need to change the Standard_pool to match the pool that contains your web server.
