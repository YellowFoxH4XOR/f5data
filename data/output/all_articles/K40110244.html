Description

You may refer to K13333 to send syslog to a remote syslog server based on log level and facility. But you may want to include an additional log message when only certain events happen, for example, when BIG-IP generates a core dump file. The article introduces how to send a specific log that matches any keyword to remote syslog server.

Environment

  • Core dump.
  • Syslog.
  • Alert event.

Cause

None.

Recommended Actions

When BIG-IP generate a core dump file, it records the events at notice level in /var/log/message file. You can use syslog filter feature to match the following logs and then send them to a remote syslog server. 

  1. The log of core dump event contains keywords /var/log/<process_name>.<x>.bld in /var/log/message.  For example:

    notice logger[21626]: Started writing core file: /var/core/tmm.7.bld0.81.8.core.gz for PID 23945
    notice logger[25089]: Finished writing 6395166611 bytes for core file: /var/core/tmm.7.bld0.81.8.core.gz for PID 23945

  2. Create a new syslog filter f_remote_loghost1 that matches a regular expression /var/core/.*.bld, and send it to the same syslog destination d_remote_loghost 192.168.1.1 on port 514:

    Note: About how to modify the syslog config and more detail, please refer to K13333: Filtering log messages sent to remote syslog servers (11.x - 15.x)

syslog {
    ...
    include "             
    filter f_remote_loghost {
        level(warning..emerg);
    };
    destination d_remote_loghost {
        udp(\"192.168.1.1\" port(514));
    };
    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);  
                  
    filter f_remote_loghost1 {
        match('/var/core/.*.bld');             
        level(notice..emerg);
    };
    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost1);
        destination(d_remote_loghost);
    };
    "
    ...
}
