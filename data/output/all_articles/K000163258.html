Description

ASM configuration synchronization can fail while BIG-IP LTM configuration synchronization reports success and the general device-group status shows In Sync.

Relevant ASM errors include:

01310027:2: ASM subsystem error (asm_start,...):Watchdog detected failure for process.Process name: asm_config_server.pl,Failure: Memory Size reached a threshold(detected memory usage: xxxx, threshold: xxxx).

The following error may also appear:

Sync recovery state timed out. State may be inconsistent with other peers

Environment

  • Product: BIG-IP AWAF
  • High-availability device group with active and standby devices
  • Configuration synchronization between peers
  • ASM configuration synchronization and loading into the peer ASM database
  • The ASM synchronization sequence may include:
    1. The peer enters ASM sync recovery.
    2. The peer requests the complete ASM configuration.
    3. The synchronization data is received.
    4. The ASM configuration begins loading.
    5. The asm_config_server.pl process reaches its memory threshold.
    6. ASM synchronization recovery times out.

Cause

The ASM configuration server process reaches its configured memory threshold while loading the synchronized ASM configuration. This causes ASM synchronization recovery to time out.

The general device-group synchronization status may not accurately represent the ASM synchronization state. Bug ID 457391 describes behavior in which the LTM/CMI status displays In Sync before ASM synchronization has completed and does not reflect ASM synchronization errors.

Recommended Actions

  1. Review the ASM logs on both peers for the following messages:
    • Memory Size reached a threshold asm_config_server.pl
    • ASM is now entering sync recovery state
    • ASM config loaded
    • Sync recovery state timed out
  2. Verify BIG-IP LTM configuration synchronization separately from ASM configuration synchronization. A green In Sync status does not by itself confirm that the ASM configuration has completed loading on the peer.
  3. Verify that:
    • BIG-IP LTM configuration synchronization completes successfully.
    • ASM configuration data is received and loaded on the peer.
    • No ASM memory-threshold or sync-recovery timeout errors occur.
    • ASM logging resumes normally on the peer.
    • ASM configuration and enforcement state are consistent between peers.
  4. Apply the remediation described in K01026149: Error 01310027:2: ASM subsystem error indicating Memory Size reached a threshold, which provides a fix for the asm_config_server.pl memory-threshold error.

Additional Information

  • BIG-IP LTM configuration synchronization can report success even when ASM configuration has not successfully loaded on the peer.
  • ASM configuration data may be received and partially processed before the ASM configuration server reaches its memory threshold.
  • Verify ASM synchronization using ASM logs and configuration-loading results rather than relying solely on the general device-group In Sync indicator.
  • The status-reporting behavior is associated with Bug ID 457391.
