Description

There is no way to delete POST as an Allowed Method in a security policy, at Security >> Application Security : Headers : Methods.
 


Can we do this via CLI, or is there another way to disallow POSTs?

Environment

  • Security Policy
  • Site does not make use of POST
  • Unwanted POST requests

Cause

This is expected behaviour, because adding a new allowed method to the policy must Act As either GET or POST.
 

Recommended Actions

POST can be disallowed on a per-URL basis, by creating an Allowed URL(s) with an override under Methods Enforcement.

You can also configure a Custom Violation and iRule to disallow POSTs.

Here are the steps to do that:

  1. Create a user-defined violation at Security >> Options : Application Security : Advanced Configuration : Violations List

    For example purposes, we'll call it post_req.

  2. Set Trigger ASM iRule Events Mode to Normal in the security policy settings.

  3. Enable Alarm and/or Block for the user-defined violation in the Learning and Blocking settings

  4. Create and apply iRule, utilizing the ASM::raise command

    Example:

    when ASM_REQUEST_DONE {
        if { [HTTP::method] equals "POST" } {
            ASM::raise post_req
       }
    }

    Note: This is an example only and assumes the administrator wants to block all POST requests. Some if logic could be added to selectively raise the violation, for example, on a per-hostname basis, using the value of the Host header, or other request details.

Additional Information

POST requests can also be blocked by using a simple iRule or Local Traffic Policy at the HTTP_REQUEST event. This occurs before ASM processing and has less overhead. However, the disadvantage is reduced visibility of blocked requests in the ASM event logs.

when HTTP_REQUEST {
     if { [HTTP::method] equals "POST" } {
          reject
     }
}
