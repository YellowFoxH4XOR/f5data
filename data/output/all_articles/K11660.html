Known Issue

This is the result of a known issue. BIG-IP configuration changes may not be replicated to secondary blades on VIPRION platforms. This occurs when a secondary mcpd process disconnects from the primary mcpd process and fails to reconnect.

When a secondary daemon disconnects from the primary, the secondary daemon calls a disconnect routine which instructs it to not attempt to re-connect to the primary daemon. When the primary and secondary mcpd processes lose connectivity, configuration changes made on the primary blade are not replicated to the secondary blades. For example, if an administrator disables a pool member, the primary blade shows that the pool member is disabled, but the secondary blade may indicate that the pool member is still enabled. As a result, the BIG-IP system may continue to send connections to a disabled pool member.

F5 Product Development tracked this issue as CR136488 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, BIGIP-10.1.0-3372.0-HF1 has been issued for BIG-IP version 10.1.0, and Hotfix-BIGIP-10.0.1-402.7-HF4 has been issued for BIG-IP version 10.0.1. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Note: For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.
