Known Issue

A virtual server with an iRule using the CACHE::header command to modify an HTTP header variable may cause the replaced string to display garbled text.

This issue occurs when all of the following conditions are met:

  • The virtual server uses a Web Acceleration profile with either the optimized-caching or optimized-acceleration parent profile.
  • The virtual server uses an iRule using a CACHE_RESPONSE event with the CACHE::header command to replace any header variable's value.

Impact

The web content may result in errors or fail to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H379829 on the Diagnostics > Identified > Medium screen.
  • The first HTTP request sent to the virtual server may load the content without errors. The second and subsequent HTTP requests will access using the cache, and the page load may result in errors or fail to load.
  • In addition, when using the curl command to validate the virtual server, you may observe the modified header variable's value might have extra garbled string appended to the end of the replaced string.

    For example, the Server header is modified to bigip-123 on the iRule that appears similar to the following example:

    when CACHE_RESPONSE {
    CACHE::header replace Server bigip-123
    }

    The resulting page HTTP header for Server may appear similar to the following example:

    Server: bigip-123
    17 (Linux/SUSE)
