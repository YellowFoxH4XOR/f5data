Known Issue

Non-administrator BIG-IP users cannot view deployed iApps in the Configuration utility.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is running BIG-IP 12.1.2 HF1 or 13.0.0.
  • You have created an application service using an iApp template which contains a tmsh::include statement.
  • You log on to your BIG-IP system as a non-administrator user and attempt to view or reconfigure the application service.

Impact

Non-administrator BIG-IP users are not able to view or re-deploy iApps.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to view or reconfigure an iApp application service, the Configuration utility displays the following message:

    An error has occurred while trying to process your request.

  • In the /var/log/ltm file, you observe a message similar to the following example:

    err mcpd[1234]: 01070823:3: Read Access Denied: user (test-user) type (application template instance script)

  • In the /var/log/webgui.log file, you observe a message similar to the following example:

    ERROR [TP-Processor3] application.components_jsp:_jspService     - com.f5.mcp.io.McpQueryException: 01070823:3: Read Access Denied: user (test-user) type (application template instance script)

Workaround

To work around this issue, you can either use the TMOS Shell (tmsh) to re-deploy iApps, or you can utilize a direct link in the Configuration utility to the Reconfigure section of the iApp. To utilize a direct link in the Configuration utility, perform one of the following procedures:

Clicking the application name from an object created by the iApp

When objects are created as part of an iApp deployment, a link to the application is created with the associated objects. Clicking this link will take you to the application service Properties page, and allow you to select Reconfigure to re-deploy the iApp.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Locate an object created by the iApp. For example, for a virtual server, navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the virtual server associated with the iApp.
  4. In the General Properties section, click the link in the Application field.

Using an administrator user account to provide a direct link to the iApp

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility as an administrator user.
  2. Navigate to iApps > Application Services > Applications.
  3. Click the name of the application service.
  4. Click the Reconfigure tab.
  5. From the settings menu, click Direct link to this page.
  6. Copy the URL provided in the next screen.
  7. Provide this link to non-administrator users.
