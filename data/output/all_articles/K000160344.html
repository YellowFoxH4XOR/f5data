K000160344: False positive: attack signature 200018064 ('Leading tab in header name') blocking valid requests

Type
Support Solution
Published
2026-03-13
Updated
2026-03-17
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160344

Description

Attack signature ID 200018064 ('Leading tab in header name') blocking valid requests.

Environment

  •  ASM (17.1.3)
  •  Attack signature
  •  Authorization header (Bearer token)

Cause

ASM signature ID 200018064 ("Leading tab in header name") falsely triggers when base64-decoded Authorization header token values contain LF+TAB (0A09).

Answer/Recommended Actions

Create an attack signature exception for signature ID 200018064 on the 'authorization' HTTP header to prevent false positives.

Step-by-Step Configuration:

  1. Log in to the BIG-IP Configuration Utility.
  2. Navigate to Security  ››  Application Security : Security Policies : Policies List  ››  <<policy name>> HTTP Message Protection Headers.
  3. Edit the properties of the 'authorization' HTTP header object.
  4. Within 'Attack Signatures', locate signature ID 200018064 ('Leading tab in header name') and move it to the 'Overridden Security Policy Settings' as 'Disabled'.
  5. Click Update
  6. Save and Apply Policy.

Additional Information

With "Base64 Decoding" disabled in the default HTTP Headers authorization object, Base64 decoding is applied partially to the Authorization header. Only the token portion of the Authorization header is decoded, while the scheme (Basic or Bearer) is not decoded.

Example request: Authorization header with Bearer token:

GET /api/v1/users/profile HTTP/1.1
Host: api.example.com
User-Agent: Mozilla/5.0
Accept: application/json
Authorization: Bearer <REDACTED_TOKEN>
Content-Type: application/json
Connection: keep-alive
