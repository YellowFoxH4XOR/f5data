Known Issue

The BIG-IP ASM system may experience /var partition file system exhaustion.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is configured with multiple security policies.
  • You complete one of the following actions on the BIG-IP ASM device:
    • Load the system configuration from a user configuration set (UCS) archive.
    • Synchronize the local BIG-IP ASM device to itself.
  • Your BIG-IP ASM system is synchronized to the device group.

Impact

The BIG-IP system may use the complete /var disk partition, causing system instability.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the contents of the /ts/dms/policy/policy_versions directory, you observe hundreds of policy history files for non-existent security policies.
  • The /var directory can reach 100 percent utilization when you synchronize the system, causing the synchronization to fail.

Workaround

To work around this issue, for BIG-IP ASM major branch versions 11.5.x only, you can manually remove the orphan history files. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP ASM device.
  2. To query orphaned policy history files, enter the following MySQL command:

    perl -MData::Dumper -MF5::DbUtils -MFile::Find -e '$dbh = F5::DbUtils::get_dbh(); $sql = ($dbh-> selectrow_array(q{show tables in PLC like ?}, undef, q{PL_POLICY_VERSIONS})) ? q{select policy_version, policy_id from PLC.PL_POLICY_VERSIONS} : q{select revision, policy_id from PLC.PL_POLICY_HISTORY}; %known_history_files = map { (qq{$_->[1]/$_->[0].plc} => 1) } @{$dbh->selectall_arrayref($sql)}; find({ wanted => sub { next unless -f $_; $_ =~ m|/policy_versions/(.*)$|; if (! $known_history_files{$1}) { print qq{$_\n} } }, no_chdir => 1, }, q{/ts/dms/policy/policy_versions});'

  3. Review the output of the MySQL command to verify that the listed policy history files do not reference an existing security policy. To obtain a list of existing security policies and the associated policyIDs, enter the following MySQL command:

    mysql -uroot -p`perl -MF5::DbUtils -e 'print F5::DbUtils::get_mysql_password(user => qw{root})'` -e 'SELECT * FROM PLC.PL_POLICIES'  | awk '{print $1,$2,$3}'

  4. If all of the listed policy history files do not reference an existing security policy, you can enter the following command to delete the policy history files:

    perl -MData::Dumper -MF5::DbUtils -MFile::Find -e '$dbh = F5::DbUtils::get_dbh(); $sql = ($dbh->selectrow_array(q{show tables in PLC like ?}, undef, q{PL_POLICY_VERSIONS})) ? q{select policy_version, policy_id from PLC.PL_POLICY_VERSIONS} : q{select revision, policy_id from PLC.PL_POLICY_HISTORY}; %known_history_files = map { (qq{$_->[1]/$_->[0].plc} => 1) } @{$dbh->selectall_arrayref($sql)}; find({ wanted => sub { next unless -f $_; $_ =~ m|/policy_versions/(.*)$|; if (! $known_history_files{$1}) { print qq{$_\n} } }, no_chdir => 1, }, q{/ts/dms/policy/policy_versions});' | xargs rm -f

  5. If you identify policy history files that reference existing security policies, you can manually delete the policy history files that do not reference an existing security policy by using the following command syntax:

    rm -f  /ts/dms/policy/policy_versions/<policy number>/<policy version>.plc

    For example:

    rm -f /ts/dms/policy/policy_versions/5/62.plc

  6. To delete the /var/ts/var/install/recovery_db/conf.tar.gz file, type the following command:

    rm -f /var/ts/var/install/recovery_db/conf.tar.gz
