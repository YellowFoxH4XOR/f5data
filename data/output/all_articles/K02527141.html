Description

When a Windows client establishes a BIG-IP APM Network Access Tunnel connection, it will register it's local client IP's to the remote DNS servers in the corporate network when the Local PC setting, "Register This Connections' address in DNS" is used.  This can cause connectivity trouble for resources that reside in the corporate network when they try to connect to the VPN Tunnel client by DNS name, because they will receive the client's local IP's in an DNS lookup/resolution.

The registration of the client's local IP's is controlled by the client's adapter Properties setting called "Register this connections addresses in DNS". 

This should not be confused with the BIG-IP APM Network Access resource setting by the same name, which when enabled will register the VPN Tunnel's Lease Pool assigned IP in the DNS servers within the corporate network.  It is the Network Access setting that provides the DNS servers with the proper IP used to reach the remote VPN client from inside the corporate network. 

Environment

  • BigIP APM
  • Network Access VPN
  • Windows client PC with network adapters that have "Register this connections addresses in DNS" Enabled.

Cause

Windows client PC's with network adapters that have the local setting: "Register this connections addresses in DNS" enabled, will register their local IP's with the corporate DNS servers.  

Recommended Actions

To mitigate this issue and prevent the Windows client's from registering their local IP's with the corporate network, follow the instructions in Microsoft Knowledge Base article linked below:

  • Clearing the "Register this connection's addresses in DNS" option does not remove DNS records for Windows clients using static IP addresses
