K18484011: BIG-IQ Reclaim unused disk space from postgres database

Type
Support Solution
Published
2021-01-28
Updated

Applies to

Source

Description
In BIG-IQ 7.1.x, the default autovacuum settings for Postgres do not prevent the database from growing in some environments. In order to reclaim disk space and reduce the disk usage of the database, it may help perform a VACUUM FULL on the bigiq_db database to bring the size down. This should be done on recommendation from F5 support. 

Environment

  • BIG-IQ CM
  • /var disk space usage increasing

Cause
The default post autovacuum settings may not prevent database bloat in some environments. 

Recommended Actions
Do a Full vacuum and reindex to reclaim the space
Note: This causes a high load and locks individual tables while working on them. It is recommended that this be performed during a maintenance window.

  1. Do a full vacuum:
    psql -U postgres -d bigiq_db -c "VACUUM FULL;"
  2. After the above finishes reindex:
    psql -U postgres -d bigiq_db -c "REINDEX DATABASE bigiq_db;"

Additional Information

A fix was introduced in 8.2 to address Bug ID 1035277: PostgresDB bloat can cause upgrade to fail, however the cron job (update-top-pg-tables) was placed under cron.daily instead of cron.d. Because of this, the database processes to reduce the size of tables isn't run regularly.

Move the cronjob to the correct location on both BIG-IQ HA systems to rectify this issue:

mv /etc/cron.daily/update-top-pg-tables /etc/cron.d/
