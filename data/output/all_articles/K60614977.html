Description

After upgrading to version 13.1.3.4, or later, the virtual server(s) configured for Oracle E-Business Suite may not load forms or other data.

  • The application will load but some forms might not load when selected or other requested data might not show
  • At the moment of choosing such forms or data, the application will stop working for several minutes and might not come back
When analyzing the issue, you take some packet captures of the virtual server and backend pool members. At the moment of asking the form or desired data that stops the application from working, you notice certain http request that you can see being sent from the client to the Virtual Server, but on the serverside, you might not see the packet, or you see it not decoded by Wireshark or the packet analyzer you are using, but the hex does show such request, many times the request is seen many seconds after it was sent by the client. Also, when enabling the BIG-IP system to log TCP RST packets, you might see the device logging a reset on the clientside with reason "HTTP Blocking a request during body processing". Nothing is sent serverside.

Environment

  • BIG-IP
  • Software upgrade to version 13.1.3.4 or later
  • Virtual Servers configured for Oracle E-Business Suite

Cause

This is caused by a behavior change that was implemented in version 13.1.3.4 with F5 ID858285 which basically adds a function to silently block HTTP requests that have non-encoded white spaces in HTTP URIs and other non-compliant RFC HTTP request or responses ( see RFC 2616 and RFC 7230)

Recommended Actions

To avoid this issue, customers should evaluate how their application interprets HTTP requests in accordance with published RFCs and how any customer-defined conditional traffic handling (for example, iRules or Local Traffic Policies) interprets the same HTTP requests to ensure that the application stack behaves consistently. With that we mean to review all involved HTTP request in the application and ensure that they are encoded to be RFC compliant

Alternatively, you can install version 13.1.4.1 and ask the F5 support team for Engineering HotFix 55.3 which includes a patch in the form of a sys db called "tmm.http.rfc.allowinsecureverfallback" which you can enable with the command "tmsh modify sys db tmm.http.rfc.allowinsecureverfallback value enabled". Once the db is enabled, non-compliant RFC HTTP requests will be permitted serverside. This will allow you to review http requests and responses in detail while having the application working.

Note: This patch is only included in this EHF for this version and will never be added to any mainline BIG-IP software version, this is why the main recommended action is to reconfigure the application to use HTTP requests in compliance with the RFC.
 

Additional Information

For instance, this URI is not RFC compliant: /JAVA/oracle/apps/media/test http request.gif The portion of this URI that is not RFC compliant is the test http request.gif, You can see that portion contains white spaces which are not compliant.
