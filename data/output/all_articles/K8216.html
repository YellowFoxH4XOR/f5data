Topic

The RAM Cache option can be used with BIG-IP ASM to cache validated and commonly requested static content, such as images. Any traffic that does not conform to the BIG-IP ASM policy is blocked and not cached or allowed through. This configuration allows for faster processing as the cache will only be used for static content. This type of configuration will use HTTP Classes to separate the traffic into static or cached content from the rest of the traffic.

Important: This Solution applies to BIG-IP ASM 9.4.3 and later, and requires HotFix-BIG-IP-9.4.3-HF1 or later.

Note: Starting with BIG-IP ASM version 9.4.3, RAM Cache is available without an additional license.

Configuring RAM Cache for use with BIG-IP ASM

To configure RAM Cache for use with BIG-IP ASM, you must perform the following procedures:

Note: The following configuration steps were written under the assumption that you have a virtual server and pool configured for use.

  • Configuring a custom HTTP profile with RAM Cache
  • Configuring a custom HTTP Class to handle static content that is cached using RAM Cache
  • Configuring a custom HTTP Class to handle all other traffic that should not be cached
  • Configuring an iRule to disable RAM Cache if the non-static content HTTP Class is selected 
  • Associating the custom HTTP profile with RAM Cache, the iRule, and the HTTP Class profiles with the virtual server

Configuring a custom HTTP profile with RAM Cache

Important: If you have already created a policy for use, ensure it is in blocking mode before configuring the HTTP class options and the iRules. This will prevent direct and unsecure access to the web servers.

Note: F5 recommends that you create a new profile with desired custom settings rather than modify a default HTTP profile.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Click Create.
  5. Provide a name for the custom HTTP profile.

    For example:

    asm_ramcache

  6. Select the Custom check box in the Settings section if you want to use all of the options available.

    Note: This section is optional, it is not required. All default HTTP settings from the parent profile will be used.

  7. Select the Custom check box in the RAM Cache section.
  8. Select Enabled for the RAM Cache option.
  9. Change the Minimum Object Size option from the default of 500 bytes to 1 byte.
  10. Change the Maximum Object Size option from the default of 50000 bytes to 150000 bytes.
  11. Select Disabled from the RAM Cache drop-down menu.

    Note: After the policy for the media files has been placed in blocking mode, RAM Cache will be enabled. This is to ensure that attempts to bypass security through the use of media are not cached and served to other clients.

  12. Click Finished.

Configuring a custom HTTP Class to handle static content that is cached using RAM Cache

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Protocol.
  5. Select HTTP Class.
  6. Click Create.
  7. Provide a name for the custom HTTP Class.

    For example:

    static_content

  8. Select the Custom check box.
  9. Select Enabled for the Application Security option.
  10. Select the Match Only for URI Paths option.
  11. For the Entry Type, select Regular Expression (regex).
  12. Enter the following regular expression for the URI Path:

    (?i)^/[a-zA-Z0-9_/]+\.(gif|jpg|bmp|png|css)$

  13. Select Add.
  14. For the Actions option, select Custom.
  15. For the Send To option, select Pool.
  16. For the Pool option, select the  name of your pool that references your servers.
  17. Click Finished.

Configuring a custom HTTP Class to handle all other traffic that should not be cached

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Protocol.
  5. Select HTTP Class.
  6. Click Create.
  7. Provide a name for the custom HTTP Class to handle all other content that will not use the cache.

    For example:

    all_content

  8. Select the Custom check box.
  9. For the Application Security option, select Enabled.
  10. For the Actions option, select Custom.
  11. For the Send To option, select Pool.
  12. For the Pool option, select the name of your pool that references your servers.
  13. Click Finished.

    Note: Once you have created both HTTP classes (one for static content that will use RAM Cache and one that will handle all other traffic and not use RAM Cache) you must reload the configuration and ensure that the BIG-IP ASM will correctly read the newly-created HTTP classes. To do so, type the following command:

    bigpipe load

Configuring an iRule to disable RAM Cache if the non-static content HTTP Class is selected

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select iRules.
  4. Select Create.
  5. Provide a name for the iRule.

    For example:

    irule_httpclass_ramcache

  6. Enter the iRule, using the following syntax:

    when HTTP_CLASS_SELECTED {

    if { not ([HTTP::class] eq "<name of static content HTTP Class>") } {
        CACHE::disable
        }
    }



    For example:

    when HTTP_CLASS_SELECTED {

    if { not ([HTTP::class] eq "static_content") } {
        CACHE::disable
        }
    }

  7. After entering the iRule, click Finished.

Note: In the iRule example, when an HTTP Class selected by the system is not the static_content HTTP Class, the cache is disabled and the request is sent to the BIG-IP ASM policy to be evaluated. Alternatively, if the HTTP Class is the static_content HTTP Class, the request is sent to the BIG-IP ASM policy to be evaluated, but the response is allowed to be cached if it is static content matching the regular expression string.

Associating the custom HTTP profile with RAM Cache, the iRule, and the HTTP Class profiles with the virtual server

To associate the custom HTTP profile with RAM Cache, the iRule, and the HTTP Class profiles with the virtual server, perform the following four procedures:

  • Associating the custom HTTP profile with the virtual server
  • Associating the HTTP Classes with the virtual server
  • Enabling RAM Cache in the Custom HTTP profile associated with the virtual server
  • Associating the iRule with the virtual server

Associating the custom HTTP profile with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select the virtual server that you want to configure.

    The Properties screen for the virtual server opens.
  5. Select the custom HTTP profile created in the Configuring a custom HTTP profile with RAM Cache enabled procedure.

    For example:

    asm_ramcache

  6. Click the Update button.

Associating the HTTP Classes with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select the virtual server that you want to associate with the HTTP Class.
  5. Select the Resources tab.
  6. In the HTTP Class Profiles section, click the Manage button.

    The Resource Management screen opens.
  7. In the Available section, select the HTTP class profile created for static content.
  8. Click the << button.

    The HTTP class profile created for static content is moved to the Enabled section.
  9. In the Available section, select the HTTP class profile created for all other content.
  10. Click the << button.

    The HTTP class profile created for all other content will be moved to the Enabled section.
  11. Use the Up and Down buttons below the Enabled list to ensure that the HTTP class profile for static content is listed first.

    Note: The system applies the HTTP classes in the order they are listed.

    For example:

    static_content
    all_content

  12. Click the Finished button.

    You will return to the Resources section.
  13. Click the Update button.

    The changes in the Resources section are now associated and saved with the virtual server.

Once all the requirements above are configured, run traffic to the site and build a policy for the static content web application. It is recommended that you use a policy configured with the following elements:

  • Object types ( File Types in version 10.x )

    Wildcard ( * ) without tightening. Using a wildcard will be case insensitive and eliminate the need to specify both gif and GIF and the tightening is not required since the object type filtering is done at the HTTP class level. 
  • Objects ( URLs in version 10.x )

    Wildcard ( * ) without tightening. Using a wildcard will be case insensitive and eliminate the need to specify every new image in the site--a task that will require configuration and could cause errors for users. As with object types, the filtering is done at the HTTP class level. 
  • Enable blocking on all violations

Set the following options to block the static content that will be handled by the RAM Cache:

  • Cookie not RFC-compliant
  • Evasion technique detected
  • Illegal HTTP format
  • Non-RFC request 
  • Illegal HTTP status in response 
  • Illegal meta character in object
  • Illegal method 
  • Illegal object type 
  • Non-existent object Error    
  • Request length exceeds defined buffer size 
  • Illegal cookie length
  • Illegal header length 
  • Illegal object length 
  • Illegal request length 
  • Failed to convert character
  • Forbidden Null in request 
  • Illegal meta character in header
  • Illegal query string or POST data
  • Null in multi-part parameter value
  • Modified ASM cookie
  • Modified domain cookie(s)
  • Information leakage detected Error    
  • Attack signature detected

Once the policy has been built for the site and blocking is enabled for the policy, RAM Cache and the iRule can be enabled and added to the virtual server to allow static content to be cached.

Enabling RAM Cache in the Custom HTTP profile associated with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select the custom HTTP profile used by the virtual server.

    For example:

    asm_ramcache

  5. From the RAM Cache drop-down menu, select Enabled.
  6. Click the Update button to enable the RAM Cache.

Associating the iRule with the virtual server

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. In the Resources section, select the Edit option for the virtual server that is using the custom HTTP profile with RAM Cache enabled.
  5. In the iRules section, click the Manage button.
  6. In the Available section, select the iRule created previously.
  7. Click the << button to place the iRule into the Enabled section.
  8. Click Finished.

Once RAM Cache and the iRule have been enabled for the virtual server, traffic can be allowed access to the virtual server again. Any static media content that has been validated and cleared by BIG-IP ASM can now use the RAM Cache. This behavior allows content that has been checked by the BIG-IP ASM to be served from the RAM Cache and allows the BIG-IP ASM to focus on checking and validating dynamic content.
