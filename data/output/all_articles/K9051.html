Known Issue

This is the result of a known issue. When a server uses chunked transfer encoding to send a response, the last chunk in the session is indicated by any chunk whose size is 0 (zero), followed by the trailer, and CRLF. When a chunked HTTP response is missing the size zero final chunk, and the server instead terminates the response by sending a FIN, the BIG-IP system does not forward the FIN packet to the client. As a result, the BIG-IP system fails to close the client-side connection, and the browser waits for the remainder of the response.

Note: This issue can occur only when both an HTTP profile and a OneConnect profile are associated with the virtual server.

F5 Product Development tracked this issue as CR103905 and it was fixed in BIG-IP LTM versions 9.4.6 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, Hotfix-BIG-IP-9.4.5-HF2 has been issued for BIG-IP version 9.4.5, and Hotfix-BIGIP-v9.6.1-HF2 for BIG-IP version 9.6.1. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
