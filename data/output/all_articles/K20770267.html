K20770267: The BIG-IP ASM system may not process traffic after a software upgrade

Type
Known Issue
Published
2017-09-20
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 13.0.0, 12.1.2, 12.1.1
Source

Known Issue

The BIG-IP ASM system may not process traffic after a software upgrade.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system has local request logging enabled.
  • You upgrade the software version.

Impact

After a software upgrade, the BIG-IP ASM system does not process traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After a software upgrade and subsequent system reboot, the system logs messages in the /var/log/asm file similar to the following example:

    crit perl[19713]: 01310027:2: ASM subsystem error (asm_start,F5::DbUpgrade::__ANON__): DBD::mysql::db do failed: Too many partitions (including subpartitions) were defined

Workaround

To work around this issue, you can perform a fresh installation without rolling the configuration forward, then load a user configuration set (UCS) archive without loading the request log. To do so, perform the following procedures:

  • Rebooting the BIG-IP system to the pre-upgrade software volume
  • Performing a clean upgrade of the BIG-IP software on a new volume
  • Restoring the configuration from a UCS archive file
    • Restoring from the /var/tmp/AskF5-K20770267 UCS archive file
    • Optional: Restoring from a previously saved UCS archive file

Rebooting the BIG-IP system to the pre-upgrade software volume

Impact of workaround: If the BIG-IP system is the active member of a redundant system, rebooting causes a failover. If the BIG-IP system is a standalone unit, rebooting interrupts traffic processing.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To reboot the BIG-IP system to the pre-upgrade software volume, use the following command syntax:

    reboot volume <pre-upgrade volume name>

    For example, if the name of the software volume that you previously upgraded from is HD1.1, type the following command:

    reboot volume HD1.1

Performing a clean upgrade of the BIG-IP software on a new volume

Impact of workaround: If the BIG-IP system is the active member of a redundant system, rebooting causes a failover. If the BIG-IP system is a standalone unit, rebooting interrupts traffic processing.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To delete the failed software upgrade volume, use the following command syntax:

    delete /sys software volume <failed software volume>

    For example, to delete a failed software upgrade volume named HD1.2, type the following command:

    delete /sys software volume HD1.2

  3. To disable the collection of request log data when saving a UCS archive, type the following command:

    Note: If you already have an up-to-date UCS archive file, you can skip to step 6. The UCS file should have been saved prior to the failed upgrade attempt; ensure that BIG-IP system changes have not occurred since the previous upgrade attempt.

    modify /sys db ucs.asm.traffic_data.save value disable

  4. To create a UCS archive, type the following command:

    save /sys ucs /var/tmp/AskF5-K20770267

    Note: The UCS file is saved as /var/tmp/AskF5-K20770267.ucs.

  5. To revert the database key change from step 3, type the following command:

    modify /sys db ucs.asm.traffic_data.save reset-to-default

  6. To prevent the BIG-IP configuration from rolling forward, type the following commands:

    modify /sys db liveinstall.moveconfig value disable
    modify /sys db liveinstall.saveconfig value disable

  7. To perform the software image or hotfix upgrade, use the following command syntax:

    install /sys software <hotfix or image> <hotfix or image name> volume <volume name> create-volume

    For example:

    • To create a new volume named HD1.2 and install 12.1.2 to that new volume, type the following command:

      install /sys software image BIGIP-12.1.2.0.0.249.iso volume HD1.2 create-volume

    • To create a new volume named HD1.3 and install 12.1.2 HF1 to that new volume, type the following command:

      install /sys software hotfix Hotfix-BIGIP-12.1.2.1.0.271-HF1.iso volume HD1.3 create-volume

  8. To revert the database key change from step 5, type the following commands:

    modify /sys db liveinstall.moveconfig reset-to-default
    modify /sys db liveinstall.saveconfig reset-to-default

  9. To reboot the BIG-IP system into the newly installed software volume, use the following command syntax:

    reboot volume <volume name>

    For example, to reboot to a volume named HD1.2, type the following command:

    reboot volume HD1.2

Restoring the configuration from a UCS archive file

Use one of the following procedures to restore your UCS archive file:

  • If you created the UCS archive during step 4 of the Performing a clean upgrade of the BIG-IP software on a new volume procedure, use the Restoring from the /var/tmp/AskF5-K20770267 UCS archive file procedure.
  • If you already have an up-to-date UCS archive file, and you skipped step 4 of the Performing a clean upgrade of the BIG-IP software on a new volume procedure, then you can use the Optional: Restoring a previously saved UCS archive file procedure.

Note: When restoring a previously saved UCS archive, F5 recommends that you select a UCS file that is up to date.

  • Restoring from the /var/tmp/AskF5-K20770267.ucs archive file
  • Optional: Restoring from a previously saved UCS archive file

Restoring from the /var/tmp/AskF5-K20770267 UCS archive file

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To restore the configuration using the UCS archive file created in step 4 of the Performing a clean upgrade of the BIG-IP software on new volume procedure, type the following command:

    load /sys ucs /var/tmp/AskF5-K20770267.ucs

  3. Type y and press ENTER at the following prompt:

    Replace all configuration on the system? (y/n)

Optional: Restoring a previously saved UCS archive file

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To disable the importing of request log data when restoring a UCS archive, type the following command:

    modify /sys db ucs.asm.traffic_data.load value never

  3. Transfer the saved UCS archive file to the /var/tmp directory of the BIG-IP system. For more information, refer to K175: Transferring files to or from an F5 system.
  4. To restore the configuration, use the following command syntax:

    load /sys ucs /var/tmp/<file name>.ucs

    For example, to restore from a UCS file named MyUCS.ucs, type the following command:

    load /sys ucs /var/tmp/MyUCS.ucs

  5. Type y and press ENTER at the following prompt:

    Replace all configuration on the system? (y/n)

  6. To revert the database key change that you made in step 2, type the following command:

    modify /sys db ucs.asm.traffic_data.load reset-to-default
