Known Issue

This is the result of a known issue. The node status is not propagated to the pool member when the bigpipe load command is used.

This issue occurs when a node is down, or reported down by a node monitor, but no monitor is associated with the pool member that uses the node. If the bigpipe load command is issued, the pool member status changes from inactive, addr down to active, unchecked status.

For example, the virtual server will accept and direct traffic to a down node with the following sequence of events:

  • The following configuration is used:

    virtual myVirtual {
    pool myPool
    destination 10.1.1.19:80
    ip protocol 6
    profiles
    http
    tcp
    }

    pool myPool {
    members 10.2.2.10:80
    }
  • The node is set to a down status using the following command:

    bigpipe node 10.2.2.10 down
  • The status of node change is viewed using the bigpipe node list command. The command output will appear similar to the following example:

    bigpipe pool myPool
    POOL myPool LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/0
    | (cur, max, limit, tot) = (0, 1, 0, 7)
    | (pkts,bits) in = (49, 37464), out = (56, 328440)
    +-> POOL MEMBER myPool/10.2.2.10:80 inactive,addr down <-- Node is in a down inactive state. The virtual server will not accept connections.
    | session enabled priority 0 ratio 0
    | (cur, max, limit, tot) = (0, 1, 0, 7)
    | (pkts,bits) in = (49, 37464), out = (56, 328440)
    | requests (total) = 7
  • The changes are saved by typing the bigpipe save command.
  • The changes are loaded using the bigpipe load command.
  • The status of the pool member/node will appear as follows:

    bigpipe pool myPool
    POOL myPool LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/0
    | (cur, max, limit, tot) = (0, 1, 0, 7)
    | (pkts,bits) in = (49, 37464), out = (56, 328440)
    +-> POOL MEMBER myPool/10.2.2.10:80 active,unchecked <-- Notice the node is reporting active state after the load.
    | session enabled priority 0 ratio 0
    | (cur, max, limit, tot) = (0, 1, 0, 7)
    | (pkts,bits) in = (49, 37464), out = (56, 328440)
    | requests (total) = 7
