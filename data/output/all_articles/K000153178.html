K000153178: BIG-IP HA pair running on VM Workstation might fail to complete config sync

Type
Support Solution
Published
2025-08-27
Updated
2025-08-31
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000153178

Description

BIG-IP LTM Virtual Edition (VE) devices configured in a high-availability (HA) sync-failover device group may fail to complete the initial configuration sync, resulting in one or more devices remaining in "Awaiting Initial Sync" status. Attempts to synchronize do not succeed, and system logs may display messages such as:

Warning generated : cannot set MTU for eth2. No such device. For legacy VE driver

Notice vmxnet3[0b:00.0]: MTU: 9000

The output of show /cm sync-status indicates:

One or more devices awaiting initial config sync - <hostname> is awaiting the initial config sync

Recommended action: Synchronize <hostname> to group <device-group>

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (issue also reproducible on other 17.x versions)
  • Platform: BIG-IP Virtual Edition (VE) running on VMware Workstation
  • Device Group Type: Sync-failover
  • Network Configuration: Default VMware Workstation virtual adapters (e.g., vmxnet3), VLAN and self-IP configured for configsync

Cause

The following appears in the ltm log (HA connection bouncing):

Aug 25 12:16:05 bigip1.f5lab.com notice mcpd[8252]: 01071434:5: No CMI peer devices configured

Aug 25 12:16:47 bigip1.f5lab.com notice mcpd[8252]: 01071436:5: CMI listener established at 172.16.20.11 port 6699

Aug 25 12:16:47 bigip1.f5lab.com notice mcpd[8252]: 01071434:5: No CMI peer devices configured

Aug 25 12:16:56 bigip1.f5lab.com notice mcpd[8252]: 01071436:5: CMI listener established at 172.16.20.11 port 6699

 

BIG-IP running on VM Workstation is NOT supported

BIG-IP VE deployed on VMware Workstation with default virtual network adapters does not support HA config sync operations due to incompatibility of the default adapters (such as vmxnet3). These adapters may not be properly recognized by BIG-IP VE for config sync traffic, causing failures in device trust establishment and configuration synchronization.

Recommended Actions

  • Deploy BIG-IP VE on a supported hypervisor platform (refer to hardware/software compatibility matrix)
  • Workaround for VMware Workstation: If using VMware Workstation for lab or testing purposes:
    1. Power off the BIG-IP VE virtual machines.
    2. Navigate to each VM’s folder and open its `.vmx` file.
    3. Locate all lines beginning with `ethernetX.virtualDev` (where X is adapter number).
    4. Change each ethernet<X>.virtualDev value to `"e1000e"`, e.g: ethernet0.virtualDev = "e1000e"
    5. Save the configuration and power on the VM.
    6. Recreate device trust between the BIG-IP VEs and perform initial configuration synchronization.

    Note:

    The `e1000e` adapter is broadly compatible and recognized by BIG-IP VE for HA operations in unsupported environments like VMware Workstation; however, production deployments should always use a supported hypervisor.
