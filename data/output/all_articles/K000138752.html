Description

The BIG-IP GUI displays the message Pool member is available, user disabled yyyy-mm-dd hh:mm-ss  in the Availability property of a disabled pool member, as shown in the screenshot below.

 

The date and time seen in the above message do not indicate when the pool member was disabled, instead they are referring to when the pool member last transitioned from a failed to a successful health check.

For example, below are ltm logs taken around the same time as above screenshot 

Feb 28 06:35:07 notice mcpd[6160]: 01070639:5: Pool /Common/P1 member /Common/N1:80 session status forced disabled.

Feb 28 06:37:32 notice mcpd[6160]: 01070638:5: Pool /Common/P1 member /Common/N1:80 monitor status down. [ /Common/http: down; last error: ] [ was up for 0hr:8mins:56sec ]

Feb 28 06:37:46 notice mcpd[6160]: 01070727:5: Pool /Common/P1 member /Common/N1:80 monitor status up. [ /Common/http: up ] [ was down for 0hr:0min:14sec ]

1- We can see that the pool member failed Health Check at  06:37:32  then transitioned to a successful health check at  06:37:46, which explains the date and time seen in the above screenshot.

2- The pool member was actually disabled  at 06:35:07, which is much earlier.

Environment

BIG-IP LTM

GUI

Pool member state Disabled

Cause

None

Recommended Actions

To find the time when the pool member was disabled, review historical ltm or audit logs of the affected unit, do not refer to the date and time seen in the pool member Availability property.
