Description

One or more slots on a multi-slot vCMP guest is on the wrong software version

Environment

  • BIG-IP VIPRION
  • Multi-slot vCMP Guest

Cause

Issue was caused by using an unsupported upgrade path on a multi-slot vCMP guest. One or more slots of the multi-slot guest hadn't upgraded and couldn't communicate with the upgraded slot to upgrade itself.

Recommended Actions

Use the slot replication mechanism to redeploy the non-upgraded slots.

Impact of procedure: You are required to shut down the BIG-IP vCMP guest system during the disk-provisioning steps, and the system is not available for traffic processing during that time. You should perform this procedure during a maintenance window.
 
  1. Set vCMP Guest to Configured
    1. Log in to tmsh of the vCMP host by entering the following command:

      tmsh

    2. To shut down the vCMP guest by moving the guest to the configured state, use the following command syntax:

      modify vcmp guest <guest_name> state configured

      For example, the following command moves the vCMP guest named MyGuest to the configured state:

      modify vcmp guest MyGuest state configured

  2. Log into other VIPRION blades and delete the vDisk associated with the guest
    • For VIPRION platforms: After you shut down the vCMP guest, delete the guest's virtual disk using the following command syntax:

      delete vcmp virtual-disk <virtual_disk_name>/<slot_number>

      For example, the following command deletes the virtual disk for the vCMP guest named MyGuest on both slots 1 and 2:

      delete vcmp virtual-disk MyGuest.img/1 MyGuest.img/2

  3. Deploy Guest

    • To start up the vCMP guest by moving the guest to the deployed state, use the following command syntax:

      modify vcmp guest <guest_name> state deployed

      For example, the following command moves the vCMP guest named MyGuest to the deployed state:

      modify vcmp guest MyGuest state deployed

  4. Log into guest and verify things are working on other blades.
  5. Log into the host and verify the guests' status have been corrected.
