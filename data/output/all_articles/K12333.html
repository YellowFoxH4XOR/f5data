Topic

When manually editing the configuration files of the BIG-IP system, you may attempt to swap service ports between virtual servers that share the same virtual address. This operation is not supported and will likely lead to unexpected results.

For example:

  • A BIG-IP system is configured with two virtual servers that share the 10.0.0.100 virtual address. One is listening on port 80 and the other one is listening on port 81. The following are their definitions within the /config/bigip.conf file:

    virtual http_vs_1 {
       pool http_pool_1
       destination 10.0.0.100:80
       ip protocol tcp
       profiles
          http
          tcp
    }
    virtual http_vs_2 {
       pool http_pool_2
       destination 10.0.0.100:81
       ip protocol tcp
       profiles
          http
          tcp
    }
  • The /config/bigip.conf file is manually edited and the service ports of the two virtual servers are swapped. The resulting definitions appear as follows:

    virtual http_vs_1 {
       pool http_pool_1
       destination 10.0.0.100:81
       ip protocol tcp
       profiles
          http
          tcp
    }
    virtual http_vs_2 {
       pool http_pool_2
       destination 10.0.0.100:80
       ip protocol tcp
       profiles
          http
          tcp
    }
  • The configuration is reloaded from disk by executing the bigpipe load command.
  • After the configuration is reloaded, if a client connects to the http_vs_1 virtual server, the BIG-IP system will immediately reset the connection. On the contrary, the http_vs_2 virtual server will work as intended.

This behavior is expected and is the result of an illegal modification. This behavior occurs because when the configuration is reloaded, the http_vs_1 virtual server attempts to bind to the 10.0.0.100:81 socket; however, the operation fails since the socket is still in use by the http_vs_2 virtual server. The http_vs_2 virtual server loads as intended because, by now, the 10.0.0.100:80 socket is no longer in use by the http_vs_1 virtual server.

Note: You can only incur in this behavior if you are manually editing the BIG-IP system configuration files. The Configuration utility, the bigpipe utility, and the tmsh shell do not allow you to modify the service port of a virtual server so that the new IP:PORT combination would conflict with that of another virtual server.

Workaround

To resolve the improper condition described in this Solution, restart the services of the BIG-IP system by running the bigstart restart command.

Important: The bigstart restart command is essentially a soft reboot of the BIG-IP system and it will cause a redundant system to failover if you use it on an active system. Additionally, using the bigstart restart command will cause a traffic disruption on a non-redundant system. F5 recommends that you run the bigstart restart command during a maintenance window to prevent disruption to customer traffic.

To properly swap service ports between two virtual servers that share the same virtual address, use the Configuration utility, the bigpipe utility, or the tmsh shell to:

  • Delete one of the two virtual servers
  • Modify the service port of the other virtual server
  • Recreate the virtual server that was deleted using the correct service port
