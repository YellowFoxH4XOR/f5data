Description

You want to know how set up OWASP high/medium/low/ accuracy signatures to block in AWAF/ASM Security Policy, when following K45215395: Guide introduction and contents | Secure against the OWASP Top 10 for 2021

Note: Keep in mind that achieving high score with OWASP, requires not only the AWAF/ASM module, as well, not only AWAF/ASM Signatures protection
This document is focused only on OWASP related signatures in AWAF/ASM.


The main guiding article is K45215395: Guide introduction and contents | Secure against the OWASP Top 10 for 2021. Under section 'Contents' follow each link in those sections, A1 to A10

Configuration work is done under: Security ›› Options : Application Security : Attack Signatures : Attack Signature Sets 

In Recommended Actions below, there is an example following: 'Broken access control (A1)' . You do the same with the rest, A2-A10 section.
 

Environment

BIG-IP AWAF/ASM 

Cause

N/A

Recommended Actions

1.Within K45215395 , follow the link: Broken access control (A1)  

2. In K44094284: Broken access control (A1) | Secure against the OWASP Top 10 for 2021   search the section "Using BIG-IP Advanced WAF/ASM to mitigate" scroll down to the table below it and read next to 'Attack signatures'.

3. It directs you to: 

Configure 'Authentication/Authorization' attack signatures 

Configure 'Path traversal' and 'predictable resource location' attack signatures 

For more information on Attack Signature properties:

  • In the resources column it points out the 'Chapter' and in which 'Manual'. Go to my.f5.com and find this manual and search it for the chapter.
  • In this chapter look for 'Types of attacks that attack signatures detect'. This tells you what 'Attack Type' you can search for and add in a signatures set.
  • In this chapter look for 'Attack signature properties'. This tells you what to use as a 'filter' when you look for a signature.

Note: You do the same with the rest, A2-A10 section

You may need to create a Signature Set per each 'Attack Type' unless it already exists per your specifications.

If the specific Signature Set may already exists:

1. Browse to Security ›› Application Security : Policy Building : Learning and Blocking Settings

2. Next to Attack Signatures, expand the section, and click 'Change'. 

3. Check the check box to add it to the policy.
Note: If the set does not exist, then skip to 'Create new set'

4. Click 'Change', then set per your need - Learn, Alarm, Block.

5. Scroll down and 'Save'

6. Click 'Apply Policy'.

If you need to create a new Signature set:

1. Browse to Security ›› Options : Application Security : Attack Signatures : Attack Signature Sets. 'Create' new set and give it a name.

2. Use the drop-down list next to 'Attack Type' to select what OWASP directs you.

3. If you wish pick 'Accuracy' or leave 'All'. (or any other filter per your need) Then click 'Create'.

4. Once you have all the sets you need, browse to Security ›› Application Security : Policy Building : Learning and Blocking Settings

5. Next to Attack Signatures, expand the section, and click 'Change'.
Note: You may need to reload this page to see the new sets.

6. Check the check box to add it to the policy.

7. Click 'Change', then set per your need - Learn, Alarm, Block.

8. Scroll down and 'Save'

9. Click 'Apply Policy'.
