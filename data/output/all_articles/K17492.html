Known Issue

When installing BIG-IP 10.1.0 through 10.2.4, the system may not create the Maintenance Operating System (MOS) logical volume or a new boot location due to a lack of disk space, resulting in a failed installation with a disk full error.

Note: A boot location is also referred to as an install location, such as HD1.3 or MD1.4.

This issue occurs when one of the following conditions is met:

  • The BIG-IP WOM is provisioned as Nominal, which does not allow the system to allocate enough space for the new MOS or boot location.
  • The BIG-IP system has too many boot locations configured.
  • The BIG-IP ASM or BIG-IP WebAccelerator is provisioned for multiple boot locations.
  • You attempt to install BIG-IP 10.1.0 or later on an existing BIG-IP 9.x partition, which is too small to hold BIG-IP 10.1.0 or later installations.
  • You are upgrading a 6900 or 8900 platform.
  • The boot partition contains multiple End-User Diagnostics (EUD) images.

    Note: If multiple EUD images exist in the boot partition, the installation will fail due to a full disk, and the tmsh show /sys software status command may indicate the following: "Maintenance OS update failed."

Impact

The BIG-IP software installation will fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H384741 on the Diagnostics > Identified > High screen.
  • When this issue occurs, you may see one of the following Disk full messages indicating that the disk is full:
    • Disk full (boot partition). See SOL#10636
    • Disk full (volume group). See SOL#10636
    • Disk full (filesystem partitions). See SOL#10636

      Note: All failures regarding disk full and boot location creation or deletion are logged in the /var/log/daemon.log file. If an action fails, refer to the log file for more information.

Workaround

To work around this issue, you can either back up your existing configuration and perform a clean installation of BIG-IP 10.1.0 or later, perform a local installation of BIG-IP 10.0.1 and reformat the disk, or reclaim disk space on the device. To do so, perform the procedures that are relevant to your environment:

  • Perform a clean installation of BIG-IP 10.1.0 or later
  • Perform a local installation of BIG-IP 10.0.1 and reformat
  • Reclaim disk space

Perform a clean installation of BIG-IP 10.1.0 or later

Impact of workaround: Performing a clean installation will cause service disruption on the BIG-IP system and destroy all of the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

For more information, refer to K10819: Performing a clean installation of BIG-IP 10.x or Enterprise Manager 2.x. After you complete the installation of BIG-IP 10.1.0 or later, you can reinstall any other boot images you want.

Perform a local installation of BIG-IP 10.0.1 and reformat

Impact of workaround: Performing this procedure will cause service disruption on the BIG-IP system and destroy all of the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Download the BIG-IP 10.0.1 product ISO image and its corresponding MD5 file from the F5 Downloads site.
  2. Compare the checksum of the downloaded ISO image to the pre-computed MD5 checksum for the file. For example, on a Linux system, you would type commands similar to the following example:

    md5sum BIGIP-10.0.1.283.0.iso
    ef9fdbf673d6355a74c2bae7980127f3  BIGIP-10.0.1.283.0.iso

    cat BIGIP-10.0.1.283.0.iso.md5
    ef9fdbf673d6355a74c2bae7980127f3  BIGIP-10.0.1.283.0.iso

    If the two values do not match, the file was corrupted during transfer.

    Important: Do not skip this step. The procedures that follows will not verify the validity of the file. Continuing with a corrupted ISO image may lead to unpredictable results.

    Note: The md5sum utility is a core component of any Linux operating system. On Windows-based systems, use the File Checksum Integrity Verifier utility. For more information about the File Checksum Integrity Verifier utility, refer to the Availability and description of the File Checksum Integrity Verifier utility article from Microsoft. This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

  3. Transfer the ISO image to the BIG-IP device. For more information, refer to K175: Transferring files to or from an F5 system.
  4. Install the ISO image by using the image2disk command, and then specify the format for volumes option, as shown in the following example:

    image2disk --instslot=HD1.1 --format=volumes BIGIP-10.0.1.283.0.iso

    For details about using the image2disk command, and formatting for volumes, refer to the Upgrading from Versions 9.3.x and 9.4.x chapter of the BIG-IP Systems: Getting Started Guide.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  5. After the BIG-IP 10.0.1 installation and reformatting is complete, you can install BIG-IP 10.1.0 or later.

    For details about installing BIG-IP 10.1.0 or later, refer to the Upgrading from 9.6.x, or from earlier versions of 10.x section in the Performing the Installation chapter of the BIG-IP Systems: Getting Started Guide.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Reclaim disk space

Alternatively, if you are upgrading from BIG-IP 10.0.x, you may be able to reclaim sufficient disk space by performing one of the following procedures before continuing with the upgrade:

  • Remove the EUD (6900 and 8900 platforms only)
  • Deprovision BIG-IP WOM
  • Delete existing boot locations using the Configuration utility
  • Delete existing boot locations using the Command Line

After sufficient disk space is reclaimed, you can perform the BIG-IP 10.1.0 or later upgrade again.

Remove the EUD (6900 and 8900 platforms only)

Impact of workaround: Performing this procedure will cause service disruption on the BIG-IP system and may destroy the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

Note: Due to a known issue, the rmeud script contained in the BIG-IP 10.2.0 and 10.2.1 ISO images does not function as expected. Use the rmeud script contained in the BIG-IP 10.1.0 ISO image, or upgrade to 10.2.2 through 10.2.4 before performing this procedure. For more information, refer to K12070: The rmeud script included in some BIG-IP ISO images does not function as expected.

  1. Log in to the BIG-IP command line.
  2. Download the 10.1.0 ISO to the /shared/images directory on the BIG-IP system.
  3. Create the /var/tmp/iso directory by typing the following command:

    mkdir /var/tmp/iso

  4. Mount the image by typing the following command:

    mount -o loop BIGIP-10.1.0.2700.0.iso /var/tmp/iso

  5. Remove the EUD utility by typing the following command:

    /var/tmp/iso/rmeud

Deprovision BIG-IP WOM

Impact of workaround: Performing this procedure will cause service disruption on the BIG-IP system and may destroy the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

Note: For more information about module provisioning, refer to the Completing Post-Installation Tasks chapter of the BIG-IP Systems Getting Started Guide.

To first determine BIG-IP WOM provisioning, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Resource Provisioning.
  3. In the Module Resource Provisioning section, note the value selected for the WAN Optimization (WOM) setting.

To deprovision BIG-IP WOM, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Resource Provisioning.
  3. In the Module Resource Provisioning section, locate the WAN Optimization (WOM) setting.
  4. In the drop-down box, select None (Disabled).
  5. To save the new configuration, click Update.

Delete existing boot locations using the Configuration utility

The installation process supports a maximum of two HDn.n installation locations, or one MDn.n installation location, in addition to the pre-version 10.1.0 or later installation location. To delete a boot location, perform the following procedure:

Note: To determine how the boot locations are configured on your BIG-IP system, from the Configuration utility, go to System > Software Management > Boot Locations.

Impact of workaround: Performing this procedure will cause service disruption on the BIG-IP system and may destroy the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Software Management > Volume Management.
  3. Select the appropriate Volume Set for the boot partition you want to delete.

    Note: The boot partition must be inactive before you can select it.

  4. Click Delete.
  5. To confirm the location, click Delete.

Delete existing boot locations using the Command Line

If you are unable to access the Configuration utility, you can examine and delete boot locations from the command line. To do so, perform the following procedure:

Impact of workaround: Performing this procedure will cause service disruption on the BIG-IP system and may destroy the information on the device. Ensure that you have backed up the configuration by following the steps in K11318: Backing up and restoring BIG-IP configuration files (10.x). F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP command line.
  2. To examine the existing boot location, use one of the following methods:

    Using Bigpipe

    To examine the existing boot location using bigpipe, type the following command:

    bigpipe software show

    The command output appears similar to the following example:

    SOFTWARE
    +-> SOFTWARE STATUS
    |   Key   Slot Product Version Build  Active Status
    |   HD1.1    0 BIG-IP  10.1.0  3341.0 yes    complete
    |   HD1.2    0 BIG-IP  10.0.1  3341.0 no     complete

    The value displayed in the column labeled Key is the name of the boot location where each software image is installed.

    Using tmsh

    To examine the existing boot location using tmsh, type the following command:

    show sys software

    The command output appears similar to the following example:

    Sys::Software Status
    Volume  Product  Version   Build  Active    Status
    --------------------------------------------------
    HD1.1    BIG-IP   10.1.0  3341.0      yes  complete
    HD1.2    BIG-IP   10.0.1  3341.0      no  complete

    The value displayed in the Volume column is the name of the boot location where each software image is installed.

  3. To delete an existing boot location, use one of the two following methods:

    Using bigpipe

    To delete an existing boot location using bigpipe, use the following command syntax where <Key> represents the boot location displayed by the bigpipe software show command in step 2:

    bigpipe software desired <Key> delete

    Note: The boot partition to be deleted must be inactive. To delete the active partition, you must first boot to a different partition.

    For example, to delete the boot location that contains the BIG-IP 10.0.1 installation, type the following command:

    bigpipe software desired HD1.2 delete

    Using tmsh

    To delete an existing boot location using the Traffic Management Shell (tmsh), use the following command syntax where <Key> represents the boot location displayed by the show sys software command in step 2:

    delete sys software volume <Key>

    Note: The boot partition to be deleted must be inactive. To delete the active partition, you must first boot to a different partition.

    For example, to delete the boot location that contains the BIG-IP 10.0.1 installation, type the following command:

    delete sys software volume HD1.2
