Topic

This article provides an overview of the configuration elements and usage of an eviction policy.

Description

Beginning in BIG-IP LTM 11.6.0, the configurable options that affect the BIG-IP system's adaptive connection reaping behavior are configured in eviction policies.

The system-wide adaptive connection reaping behavior is configured by selecting an eviction policy as the system-wide eviction policy. Additionally, you can associate an eviction policy with a virtual server and/or route domain.

By default, the system-wide global setting uses a default eviction policy named default-eviction-policy, and for virtual servers and route domains the default the eviction policy setting is None.

Eviction policy configuration elements

Note: Depending on the settings you configure, you may see only some of the configuration elements described here.

Name

The Name field allows you to specify the desired name of the eviction policy.

Trigger

The High Water and Low Water thresholds configured in an eviction policy trigger when the adaptive connection reaping behavior starts and stops.

  • High Water: Specifies the target maximum load on the context. The adaptive reaper will be more aggressive as this limit is approached. The allowable range is 50 to 100, and the high-water value must be higher than or equal to the low-water value.
  • Low Water: Specifies the aggressive sweeper activation threshold as a percentage of total capacity. The allowable range is 50 to 100, and the low-water value must be lower than or equal to the high-water value.

Slow flow monitoring

Within an eviction policy, you can specify whether slow flows are monitored. A slow flow is defined as a flow that passes less than the number specified in the Bytes/Second field that appears when this setting is enabled. By default, a slow flow is defined as 32 bytes per second. By default slow flow monitoring is disabled.

Grace period

The Grace Period field is displayed when slow flow monitoring is enabled. The grace period is the number of seconds the system will wait before monitored slow flows are throttled, if slow flow throttling is enabled. The default grace period is 10 seconds.

Slow flow throttling

When slow flow monitoring is enabled, you can then specify how to throttle slow flows by selecting one of the following options:

  • Disabled: Slow flows are monitored, but no action is taken (default setting).
  • Absolute: All slow flows above this number of connections are dropped.
  • Percentage: This percentage of detected slow flows are dropped. By default with this setting, all slow flows (100 percent) are dropped.

Algorithms

The algorithms selected within an eviction policy allow you to weigh the decisions for which connection flows are reaped when the high water mark is reached.

Important: All selected algorithms are combined into a master strategy that decides how to discard flows. Each selected algorithm provides a bias that weights the overall strategy, but selecting an algorithm does not guarantee that only those flows are removed.

You can select the following available algorithms within an eviction policy:

  • Bias Idle: Biases flow removal towards the existing flows that have been idle, with no payload bytes, for the longest.
  • Bias Oldest: Biases flow removal towards the oldest existing flows.
  • Bias Bytes: Biases flow removal towards flows with the fewest bytes. When selected, an additional Minimum Time Delay field is displayed in the Strategy Configuration area.
    • Minimum Time Delay specifies the period of time for which a flow is allowed to exist at minimum before it is subject to removal via the Bias Bytes algorithm.
  • Bias Fast Biases flow removal toward the fastest existing flows (BIG-IP version 14.x and higher).
    • Minimum Time Delay specifies the period of time for which a flow is allowed to exist at minimum before it is subject to removal via the Bias Bytes algorithm.
  • Bias Slow Biases flow removal toward the slowest existing flows (BIG-IP version 14.x and higher).
    • Minimum Time Delay specifies the period of time for which a flow is allowed to exist at minimum before it is subject to removal via the Bias Bytes algorithm.
  • Low Priority Route Domains: Biases flow removal towards flows on the route domains you specify as low priority, in the Strategy Configuration section.
  • Low Priority Virtual Servers: Biases flow removal towards flows on the virtual servers you specify as low priority, in the Strategy Configuration section.
  • Low Priority Countries: Biases flow removal towards the countries specified in the Strategy Configuration section (countries are determined by geolocation).
  • Low Priority Ports and Protocols: Biases flow removal towards flows on low priority ports and protocols specified in the Strategy Configuration section.

Specifying low priority virtual servers or low priority route domains in an eviction policy will only have an effect if that policy is associated with that virtual server or route domain and only if the strategy was triggered in the context of the specified virtual server or route domain.

For example, if you create policy Z that specifies virtual servers A and B as low-priority, and apply policy Z to virtual server B. Connection flows for virtual A will not be pruned because policy Z is not applied to virtual A. Similarly, if virtual servers A and B both in route domain N, and you apply policy Z to route domain M, nothing happens to flows for virtual servers A and B when route domain M is the context that triggers adaptive reaping. Similarly, if you create policy X that specifies route domain N as low priority and apply policy X to virtual server A. Only connection flows for virtual server A will be pruned. Even though virtual server B is in route domain N, connection flows for virtual server B are not affected because policy X is not applied to virtual server B.

Recommendations

F5 does not recommend modifying the default eviction policy. If you desire non-default values, you should create a custom eviction policy. For information about creating a custom eviction policy, refer to K15822: Configuring eviction policies.
