Known Issue

Users may not be able to access a default protocol and service on a self IP address that you have configured to allow the system-default protocols and services.

This issue occurs when all of the following conditions are met:

  • You have configured a self IP address, and the allow-service (Port Lockdown) settings contain a default entry and an additional protocol and service entry that is defined in the following list of system-default protocol and service pairs:

    net self-allow {
    defaults {
    ospf:any
    tcp:domain
    tcp:f5-iquery
    tcp:https
    tcp:snmp
    tcp:ssh
    udp:520
    udp:cap
    udp:domain
    udp:f5-iquery
    udp:snmp
    }
    }

  • The BIG-IP configuration contains additional self IP addresses with only the following entry in the allow-service (Port Lockdown) setting:

    default

For example, if the bigip_base.conf file contains the following self IP objects, when you load the configuration, the tcp:https protocol and service pair is added as an allowed-service on the first self IP address in the configuration (for example, 10.10.10.1), however, the system does not add the service pair to any subsequent self IP addresses in the configuration (for example, 10.10.10.2):

net self /Common/10.10.10.1 {
address 10.10.10.1/24
allow-service {
tcp:https
default
}

net self /Common/10.10.10.2 {
address 10.10.10.2/24
allow-service {
default
}

Impact

Users are unable to connect to a self IP address that is configured to allow the system-default protocols and services.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H436975 on the Diagnostics > Identified > Medium screen.
  • Connections fail if the self IP address is configured with an allow-service of default.
  • When attempting to establish a TCP connection on a self IP address that is configured with an allow-service of default, the BIG-IP system responds with a reset.

Workaround

To work around this issue, you can remove the additional protocol and service entry from the self IP address. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Identify any affected self IP addresses by typing the following command:

    list /net self allow-service

    Output similar to the following example appears:

    net self 10.10.10.1 {
    address 10.10.10.1/24
    allow-service {
    tcp:https
    default
    }
    }

    net self 10.10.10.2 {
    address 10.10.10.2/24
    allow-service {
    default
    }
    }

  3. From any self IP addresses that already have an allow-service entry for default, remove any additional protocol and service entries that are included in the list of system-default protocols and services, by using the following command syntax:

    modify /net self <self IP name> allow-service delete { protocol:service }

    For example, to remove the tcp:https protocol and service entry listed in the previous example, type the following command:

    modify /net self 10.10.10.1 allow-service delete { tcp:https }

  4. Save the change by typing the following command:

    save /sys config
