K02506162: Server peer showing closed status for sctp FEP

Type
Support Solution
Published
2022-01-26
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.X, 5.1.0
Source
https://my.f5.com/manage/s/article/K02506162

Description

  • The peer status under  Topology > Specific Site Settings > <Site Name>> Peers is indicated as CLOSED.
  • Seeing the following logs under FEP logs :

    2022-01-01 01:59:16,917 WARN [12579] SCTP alarm down notification was fired. Notification type is: sun.nio.ch.sctp.PeerAddrChange@420e2ef2 [Address: /<SCTP PEER IP>:3868, Association:sun.nio.ch.sctp.AssociationImpl@44ab5186[associationID:620996, maxIn:1, maxOut:1], Event: ADDR_UNREACHABLE], Notification is: LINK_DOWN, association is: 620996. [Silo-EventLoop-thread-3-4_26] [PeerChannelActivityHandler.createSCTPChannelActivityChanged()]

  • Seeing multiple abort message responses in the pcaps from the remote sctp peer : 

    85 2022-01-02 14:44:24.120435 <SCTP PEER IP> <SCTP FEP IP> SCTP 104 ABORT
    86 2022-01-02 14:44:24.120435 <SCTP PEER IP> <SCTP FEP IP> SCTP 100 ABORT
    229 2022-01-02 14:44:57.185434 <SCTP PEER IP> <SCTP FEP IP> SCTP 104 ABORT

Environment

  • SCTP FEP
  • SCTP Peer

Cause

The SCTP Peer <SCTP PEER IP> is sending "ABORT" messages to the SDC FEP <SCTP FEP IP> which in effect will CLOSE the connection in the SDC perspective.

Recommended Actions

The "abort" messages are coming from the server peers.
Hence the SDC Admin needs to work with the server admins to solve this issue why it is sending "abort" messages to the SDC FEP.
