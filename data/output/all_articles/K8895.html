K8895: LDAP group mapping fails if the LDAP filter field contains an OR operator

Known Issue

If you configure an LDAP filter master group or resource group mapping table entry on the Users: Groups: Dynamic Group Mapping page, and you configure the OR operator in the LDAP filter field, the LDAP group mapping fails for that mapping table entry.

For example:

(|(gidNumber=10000)(uidNumber=1000))

Note: The symbol for the OR operator is the vertical bar ( | ) character.

F5 Product Development tracked this issue as CR99133 and it was fixed in FirePass 6.0.3. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass 5.x branch. To monitor the status of this CR, refer to the FirePass release notes.

Additionally, this issue was fixed in cumulative hotfix HF-602-5 for FirePass 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by configuring multiple entries in the LDAP filter mapping table.

In this example, you would not configure the following expression in the LDAP filter field:

(|(gidNumber=10000)(uidNumber=1000))

You would instead configure two entries in the LDAP filter mapping table:

You would set the LDAP filter field for the first mapping table entry to:

(gidNumber=10000)

You would set the LDAP filter field for the second mapping table entry to:

(uidNumber=1000)

For more information about configuring dynamic group mapping, refer to the FirePass Controller Administrator Guide.
