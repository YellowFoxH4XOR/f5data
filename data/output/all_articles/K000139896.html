Description

Attack signature update fails, "failed: Duplicate entry '<signature_name>' for key 'sig_name' "

Environment

ASM

Cause

You are trying to update a device's attack signatures that hasn't been updated for an extended period of time. There have been situations in which signatures have been removed from the list and re-added at a later date.  If this happens and the re-added signature has a different signature ID then it will be seen as a duplicate.

For example, if you are trying to update your signatures from a file in 2020 to a file in 2024 you may see the following logs:

bigip1 crit g_server_rpc_handler.pl[18238]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Sigfile::Update::store_error_and_die): Failed on insert to PLC.NEGSIG_SIGNATURES (DBD::mysql::db do failed: Duplicate entry '"assoc" execution attempt (Header)--' for key 'sig_name')
bigip1 crit g_server_rpc_handler.pl[18238]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::handle_error): Failed update_sigfile on duplicate record for
bigip1 crit g_server_rpc_handler.pl[18238]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback):  already exists.
bigip1 crit perl[18237]: 01310027:2: ASM subsystem error (apply_asm_attack_signatures,F5::LiveUpdate::PayloadHandler::clean_fail): Fail load update files:  already exists.
bigip1 info asm_tables_dump.pl[20617]: ASM config saved

Between 2020 and 2024 the signature mentioned in the logs was removed and later re-added with a different signature ID.

Recommended Actions

To resolve this error you will need to perform a "step upgrade" for your attack signatures. Pick an update that is closer to your installed version and update to it first. Then proceed with further updates as necessary.
