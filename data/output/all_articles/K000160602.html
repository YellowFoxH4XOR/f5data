Description

When upgrading F5OS rSeries appliances from version 1.5.4 to 1.8.3, tenant deployment may fail with status "Pending" and the running version becomes unavailable. The system displays critical ConfD logs:

Upgrade failed: Upgrade transaction failed to validate: /oc-sys:system/aaa/authentication/f5-system-aaa: roles/role{operator}/config/remote-gid (value "9002") : remote-gid cannot equal any other role's gid

This prevents ConfD from starting and blocks tenant deployment after the upgrade.

Environment

  • F5OS rSeries appliances
  • F5OS versions: 1.5.4 (pre-upgrade), 1.8.3 (target upgrade)
  • BIG-IP tenant configuration
  • Configuration: Operator role configured with remote-gid 9002 in F5OS 1.5.4
  • Remote authentication server mapping operator role to GID 9002
  • Upgrade action from F5OS 1.5.4 to 1.8.3

Cause

A stricter validation constraint was introduced in F5OS 1.8.3, prohibiting any role's remote-gid from matching another role's native gid. In this scenario, the operator role was configured with remote-gid 9002, which is the native gid of the built-in user role. This conflict causes the upgrade transaction to fail validation, preventing ConfD from starting.

Answer/Recommended Actions

  1. Roll back to F5OS 1.5.4 if the upgrade fails.
  2. On F5OS 1.5.4, change the operator role's remote-gid to a value that does not conflict with any built-in role's native gid (avoid 9000, 9001, 9002, 9003, 9004, 9100).
  3. Alternatively, temporarily remove the remote-gid configuration for the operator role before upgrading.
  4. Re-attempt the upgrade to F5OS 1.8.3.
  5. After upgrade, ensure the remote authentication server returns the correct GID for the operator role (default 9001), or configure a non-conflicting remote-gid as needed.
  6. Always back up configuration before making changes.

Additional Information

  • After upgrading to F5OS 1.8.3, it is not allowed to configure a role's remote-gid to any system default gid (9000, 9001, 9002, 9003, 9004, 9100).
