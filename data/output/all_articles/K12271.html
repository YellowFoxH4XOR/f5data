K12271: Using the WAM::disable command in an HTTP_RESPONSE event may cause a pvac transaction leak

Known Issue

This is the result of a known issue. If you apply an iRule that uses the WAM::disable command in an HTTP_RESPONSE event, and a client triggers the iRule over an HTTP Keep-Alive connection, that transaction is not released when the pvac process forwards the request to TMM. Over time, these transactions accumulate and count toward the pvac concurrent transaction limit. Once the limit is reached, pvac stops processing new transactions.

F5 Product Development tracked this issue as ID 342746 and it was fixed in WebAccelerator 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

To prevent this issue, add the HTTP::close command directly after the WAM::disable command to close the HTTP connection. For example:

when HTTP_RESPONSE {
      switch [HTTP::status] {
          "404" {
          WAM::disable
          HTTP::redirect "http://www2.example.com/"
          return
}
}
}

To work around this issue, you would change the example iRule to the following:

when HTTP_RESPONSE {
      switch [HTTP::status] {
          "404" {
          WAM::disable
          HTTP::close
          HTTP::redirect "http://www2.example.com/"
          return
}
}
}

After reconfiguring the iRule, you can clear the old transactions by restarting the pvac process. To do so, type the following command:

Note: The bigstart restart pvac command will temporarily interrupt BIG-IP WebAccelerator traffic until the pvac daemon restarts.

bigstart restart pvac
