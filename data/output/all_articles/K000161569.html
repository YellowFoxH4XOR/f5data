Description

When upgrading one device in a BIG-IP High Availability (HA) device group to a newer software version while the peer remains on an older version, configuration synchronization (ConfigSync) may fail. The error message may include:

01070712:3: Caught configuration exception (0), Can't parse MCP message, unknown tag in message current message state: [create_if tag:2911 state:1][bundle_mgr_url_inc_join tag:32340 state:4] status:42270

The sync failure may also present as:

Sync Failed
A validation error occurred while syncing to a remote device
Sync error on <peer_hostname>: Load failed from /Common/<local_hostname>
01070712:3: Caught configuration exception (0), Can't parse MCP message, unknown tag in message current message state: **

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.x (behavior may occur across versions)
  • BIG-IP devices configured in an HA device group (Active/Standby)
  • One device in the HA pair was upgraded to a newer software version while the peer remained on the previous version, resulting in a version mismatch

Cause

Expected behavior. ConfigSync requires all devices in a device group to run the same major, minor, or maintenance software version (Reference articles under Related Content). When a version discrepancy exists, MCP message parsing failures can occur during synchronization, producing the error above.

Answer/Recommended Actions

Confirm that the sync failure is due to a software version mismatch between the HA peers. If so, plan to upgrade both devices in the HA pair to the same software version as soon as possible.

After booting the upgraded device, verify the configuration has fully loaded by running:

tmsh show sys mcp-state

**If the state shows config-load-in-progress for an extended period, manually trigger a config load:

tmsh load sys config

  1. Upgrade the peer device to the same software version.
  2. After the peer completes booting, verify that ConfigSync succeeds automatically between the two devices.
  3. Consider testing failover in both directions to confirm full HA functionality.

**MCPD State may display config-load-in-progress despite it loading successfully on certain versions due to ID1352445. For more information, refer to this article: K000136926: 'tmsh show sys mcp-state' shows 'config-load-in-progress' though config has successfully loaded.

Additional Information

  • ConfigSync between BIG-IP HA peers is not supported when devices are running different software versions.
  • The MCP parse error (01070712:3) is a symptom of the version mismatch and may vary in its exact wording between software versions and configurations.
  • F5 recommends upgrading all devices in a device group as soon as possible after upgrading the first device to minimize the window during which ConfigSync is unavailable.
