K000160694: BD may fail to start when a policy has a large number of associated schema files

Type
Support Solution
Published
2026-04-09
Updated
2026-04-09
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160694

Description

  • BD may fail to start when a policy has a large number of associated schema files
  • BD attempts to start and fails, this repeats over and over.
  • Error messages:
    • BD_XML|ERR |Jan 04 20:30:31.533|1975|xml_validation.cpp:2376|WJESchemaLoad of "/ts/var/account/json/schema_dbd211f5651083481427562d4b45a6a8" Failure
    • Timeout detected while waiting for configuration. time since last config: 60 BD aborting

Environment

  • Advanced WAF (ASM) provisioned
  • Advanced WAF policy with hundreds of schema files associated with it

Cause

A large number of associated schema files can cause BD to exceed its configuration load timeouts resulting in BD failing to start and repeating the cycle continuously.

Answer/Recommended Actions

Option 1: Review the imported policy or swagger file containing the schema files outside of the BIGIP, reduce the number of schemas then delete and re-import the optimized swagger file and/or policy file.
Option 2: Reach out to F5 support to get temporary internal timeout changes to allow BD to load and to complete the same task of reducing the schema files.
