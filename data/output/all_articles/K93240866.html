Description

Cookies may have the secure attribute set to indicate that the cookie should not be included in HTTP requests sent over unencrypted connections. You may wish to enable this attribute to ensure cookies communicated over HTTPS are not shared over insecure plaintext connections, which may be visible to unauthorized parties. The DoSL7 Proactive Bot Defense cookie and Bot Profile Browser Verification cookie (v14.1+) does not have this flag set by default. You can configure the BIG-IP ASM system to set this attribute on the Bot Defense cookie in versions 12.1 or later.

Environment

Relevant environmental factors specific to the topic

  • BIG-IP ASM 12.1 or later provisioned
  • Application DoS profile or Bot Defense profile (v14.1+) attached to Virtual Server with a Client SSL profile
  • TSxxxxxxxx027 or TSxxxxxxxx_27 cookie observed without the 'secure' attribute
  • Other ASM TS cookies have secure flag as expected

Cause

The DOSL7.use_secure_cookies db key enables the 'secure' flag on cookies that are set on a Virtual Server with a client-side SSL profile. This feature is disabled by default.

Recommended Actions
Enable the dosl7.use_secure_cookies db key

Impact of procedure: Enabling this will not allow the cookie to be sent over plaintext HTTP connections. This is a global setting which will affect all profiles with bot defense enabled.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable the dosl7.use_secure_cookies variable, type the following command:

    modify sys db dosl7.use_secure_cookies value enable
