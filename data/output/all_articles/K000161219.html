Description

During a BIG-IP software upgrade, the upgrade process fails with UCS file creation errors caused by insufficient disk space in the /shared partition. You may observe similar logs in the /var/log/liveinstall.log

info: gzip: /var/tmp/im21030/configsync-2.0-1-Linux-3.10.0862.14.4.7.8664.im.gz: No space left on device

info: Fatal: executing: gzip -1 /var/tmp/im21030/configsync-2.0-1-Linux-3.10.0862.14.4.7.8664.im

info: Operation aborted.

info: /var/tmp/configsync.spec: Error creating package

Environment

  • BIG-IP
  • Upgrade
  • UCS
  • APM module

Cause

Insufficient disk space in the /shared partition: The APM module significantly increases the UCS file size. During the upgrade, the UCS creation process exhausted available space in /shared, causing the upgrade to abort.

Answer/Recommended Actions

  1. Remove old, unused EPSEC packages to reduce UCS file size by following steps in this article (K000160709).
  2. Verify disk space allocation using before upgrade and UCS creation by using:
    df -h
  3. Delete old UCS files from /shared to free up space.
  4. If necessary, extend the /var and /shared partitions by following steps from this article (K34126971).
  5. Create a new UCS file to confirm successful operation before proceeding with upgrades.
  6. If UCS creation was successful, delete the dummy UCS and proceed with the upgrade.
