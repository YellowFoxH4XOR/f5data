K000157057: REST API File Uploads Fail with 'A Valid Filename Must Be Supplied' Error on BIG-IP LTM

Type
Support Solution
Published
2025-10-17
Updated
2025-10-23
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1, 16.1.6, 15.1.10, 17.1.3
Source

Description

On certain BIG-IP LTM versions, REST API file upload operations may fail with the following error message:

Install Private Key (<hostname>) failed with error: The remote server returned an error: (400) Bad Request. Server Response: {"code":400,"message":"A valid filename must be supplied",...}

 

 

This occurs even when the filename parameter is present in the request, if the filename contains certain disallowed characters.

Environment

  • Product: BIG-IP LTM
  • Versions enforcing strict REST API filename validation:
    • 17.5.1.3
    • 17.1.3
    • 16.1.6.1
    • 15.1.10.8
  • BIG-IP REST API

Cause

Bug ID 2137653

 

BIG-IP enforces strict validation on filenames used in REST API file upload endpoints for security reasons. Filenames containing any of the following characters will be rejected:

/ & $ | ; ` < > \ : * ?

 

 

This restriction applies to both literal and URL-encoded forms (e.g., %3a for :). Attempts to upload files with these characters in the filename will result in a 400 Bad Request error stating "A valid filename must be supplied."

Recommended Actions

  • Ensure all filenames used in REST API file uploads to BIG-IP do not contain any of the following characters:

/ & $ | ; ` < > \ : * ?

 

 

  • Update scripts, workflows, or third-party tools to generate and use filenames that only include permitted characters--alphanumeric, dash, underscore, and period: a-z A-Z 0-9 - _ .
  • If encountering this error after a software upgrade, review and modify any automated processes or templates that may be generating filenames with disallowed characters.
  • Manual uploads using simplified filenames should succeed without issue.
