Topic

A length violation occurs when an HTTP request contains an entity that exceeds the length setting that is defined in a security policy. Refer to the following table for a summary of the length violations that can occur:

ViolationDescriptionRelated article
Illegal cookie lengthA cookie length violation occurs when the incoming request contains a cookie header and cookie content that exceeds the acceptable length defined in the security policy. By default, the cookie length is set to Any, meaning there are no restrictions on the length of a cookie.K12067: BIG-IP ASM Violation: Illegal cookie length
Illegal header lengthA header length violation occurs when the incoming request contains a header that exceeds the acceptable length defined in the security policy. By default, the header length is set to Any, meaning there are no restrictions on the length of a HTTP header.K000134734: BIG-IP ASM violation: Illegal header length
Illegal parameter value lengthA parameter length violation occurs when the incoming request references an object that exceeds the acceptable length defined in the security policy. The object length is the entire length of the object referenced up to the query string—if a query string exists. By default, the parameter length is Any, meaning there are no restrictions on the length of a parameter.K8230: Error Message: Illegal parameter value length
Illegal POST data lengthA POST data length violation occurs when the incoming POST data exceeds the acceptable length defined in the security policy. The POST data length is the entire length of the POST data payload. By default, the POST data length for a file type is Any, meaning there are no restrictions on the length of a POST request.K000134700: BIG-IP ASM violation: Illegal POST data length
Illegal query string lengthA query string length violation occurs when the incoming request contains a query string that exceeds the acceptable length defined in the security policy. The length of the query string is measured from the end of the object and the question mark to the end of the URI. By default, the query string length for a file type is Any, meaning there are no restrictions on the length of a query string.K24581491: Request blocked due to Illegal query string length
Illegal request lengthA request length violation occurs when the incoming request exceeds the acceptable length defined in the security policy. The request is measured by the total size of the request in bytes, not characters. This type of measurement accounts for encoding used by different languages. By default, the request length set for a file type is Any, meaning there are no restrictions on the length of a request for this file type.K000134767: BIG-IP ASM violation: Illegal request length

Measuring all length violations in number of bytes

The BIG-IP ASM measures all length violations in number of bytes and not by the number of characters. Measuring length violations in number of bytes, accounts for the different types of encoding and the number of characters needed to represent one character for the administrator’s chosen encoding scheme.

For example, if a certain language encoding contains a 2 byte representation for a single character, it may be considered as a length equal to 2, not 1.

By using the number of bytes instead of the number of characters, the BIG-IP ASM correctly determines the length of the entity received, regardless of the number of characters. The BIG-IP ASM recognizes that a specific number of bytes represent a single character as specified by the encoding chosen for the policy.

Note: The specified length also contains internal BIG-IP ASM headers. The length and learning section of the Learning page suggests that lengths should be 30 percent larger than the actual detected lengths of the entity, due to the inclusion of the internal BIG-IP ASM headers.

In order to prevent false positives when specifying the acceptable length, you must take into account the chosen encoding with the length suggestions from the Learning page.

Specifying acceptable length settings checklist

Before you specify acceptable length settings, reference the following checklist:

  • Avoid false positives by using the length recommendations listed in the learning suggestions section of the Learning page.
  • In order to make an educated assumption of the relative length, check the encoding type to determine the number of bytes used to represent the chosen language characters.
  • To avoid false positives, define the necessary length and multiply it by 4 to get the maximum length.
