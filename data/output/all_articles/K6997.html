Topic

The BIG-IP OneConnect feature allows the BIG-IP system to reuse existing server-side connections that have become idle.

Description

When the OneConnect Transformations setting is enabled in the HTTP profile, the BIG-IP system controls the reuse of the server-side connection using the HTTP Connection: Keep-Alive header for HTTP/1.0 requests to keep the connection open after the server has sent its response.

The header is not inserted in HTTP/1.1 requests because HTTP clients and servers use Keep-Alive connections by default in HTTP/1.1. The server-side connection remains open and available for reuse until the BIG-IP system or the server closes the connection for exceeding the TCP connection or Keep-Alive connection idle time or the configured Maximum Reuse setting on the OneConnect profile or the origin web server. As a result, the number of HTTP connections that the BIG-IP system opens to your web servers is minimized and web server performance is improved. Additionally, the OneConnect functionality allows the client side to detach from the server side, making it possible for the BIG-IP system to load balance individual requests.

When a client sends an HTTP request, and there are no available server-side connections in the OneConnect pool, the BIG-IP system establishes a new server-side connection. When the connection is established, the BIG-IP system forwards the client request and inserts a Connection: Keep-Alive header into HTTP/1.0 requests. The Connection: Keep-Alive header prevents the web server from closing the connection, and is inserted in the server-side request even if the client sends a Connection: close header on the client-side connection.

The X-Cnection: close header is also added to server-side connections, using an existing Keep-Alive connection if the client request includes the Connection: close header. The BIG-IP system uses the X-Cnection: close header to track client-side connections that want to close the connection after receiving a response through a virtual server using the OneConnect feature.

Note: If a FastHTTP profile is applied to the virtual server, Connection: close headers in the client-side request are converted to Xonnection: Close headers in the server-side request

For example, the BIG-IP system may behave in the following manner:

  • A virtual server is configured and is associated with a OneConnect profile and an HTTP profile with OneConnect Transformations enabled.
  • Client A sends the following HTTP/1.1 request for a website page:

    GET / HTTP/1.1
    Host: www.somesite.org
    Connection: close

  • Currently there are no established connections to the server.
  • The BIG-IP system opens a connection with the server, but transforms the existing Connection: close header to an X-Cnection: close header: 

    GET / HTTP/1.1
    Host: www.somesite.org
    X-Cnection: close

  • The server responds to the request, ignoring the unrecognized X-Cnection header. However, the BIG-IP system still processes this header and allows OneConnect to track this client's connection request on an established Keep-Alive connection.
  • The BIG-IP system sends the response to the client, and closes the client-side connection, honoring the Connection: close header in the client request. However, the BIG-IP system keeps the connection between itself and the server open for reuse.
  • Client B then sends the following HTTP/1.0 request for another page from the same website:

    GET /path/page.html HTTP/1.0
    Host: www.somesite.org
     

  • Since the BIG-IP system has an open and idle connection already established to the web server, the system sends the following request to the web server and adds the Connection: Keep-Alive header to the HTTP/1.0 request :

    GET /path/page.html HTTP/1.0
    Host: www.somesite.org
    Connection: Keep-Alive

The server-side connection remains open and available for reuse until the BIG-IP system or the server closes the connection for exceeding the Keep-Alive connection idle time or the configured Max Reuse setting on either the OneConnect profile or the origin web server.
