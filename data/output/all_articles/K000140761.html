Description

There are cases where the HSB and switch report FCS errors on the HSB <-> switch interfaces. 
This can be seen in the snmp_dot3_stat table:

name    fcs_errors
---------- ----------
12.1     83233172

This can cause intermittent packet loss, leading to networking errors. This can be observed on the BIG-IP as pool monitor flapping, intermittent networking connectivity, etc.

This issue is tracked as:

Bug ID 1052057: FCS errors on switch/HSB interface impacts networking traffic

 

This document describes the creation of a custom SNMP OID that returns the number of FCS Errors.
This can be used to trigger alerts from an SNMP monitoring tool when this value is increasing, allow action to be taken to mitigate the issue.

Environment

  • BIG-IP platform with HSB
  • SNMP
  • CLI access to the BIG-IP

Cause

Bug ID 1052057: FCS errors on switch/HSB interface impacts networking traffic

Recommended Actions

To configure a custom SNMP OID that returns the number of FCS Errors, perform the following procedure:

1. Log in with administrative privileges to the command line of the target device.

2. Using a text editor, create the following file

   /shared/fcs_errors.sh

3. Enter the following command syntax into the /shared/fcs_errors.sh file

#!/usr/bin/bash
# return the number of FCS Errors
/usr/bin/tmctl -d blade snmp_dot3_stat -s fcs_errors | /usr/bin/tail -n +3 | /usr/bin/awk '{sum += $1} END {print sum}'

4. Save the changes.

5. To change the file permissions, type the following command:

  chmod 755 /shared/fcs_errors.sh

6. Using a text editor, create the following file:

  /config/snmp/custom_mib.tcl

7. Enter the following command syntax in the /config/snmp/custom_mib.tcl file:

Note: if you have existing custom mibs in the custom_mib.tcl file, you will need to change the OID number to suitregister_mib ".1" fcs_errors string

proc fcs_errors {}
{
  set status [catch {exec /usr/bin/bash /shared/fcs_errors.sh } fcs_errors]
  return $fcs_errors
}
8. Save the changes.

9. To restart the SNMP service, type the following command:

tmsh restart /sys service snmpd
10. To verify that the OID is functional, type the following command:

  snmpwalk -Os -c public -v 2c localhost .1.3.6.1.4.1.3375.2.100.1
  bigipTrafficMgmt.100.1.0 = STRING: "0"
