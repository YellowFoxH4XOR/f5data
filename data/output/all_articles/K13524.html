Known Issue

Description

If the TM.PortFind BigDB keys have a custom value, upgrades or UCS conversions to version 11.x may fail.

This issue occurs when all of the following conditions are met:

  • A BIG-IP version 10.2.2 HF-2 or later configuration is being upgraded to version 11.x, or a 10.2.2 HF-2 or later UCS archive is being loaded onto a version 11.x installation.
  • The configuration contains a non-default value for either of the following BigDB keys:
    • TM.PortFind.Linear
    • TM.PortFind.Random

The default values for both of these BigDB keys is 16. If the values have been changed from the defaults, this issue will occur.

Impact

After an upgrade or UCS installation, the system Configuration fails to load.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When rebooting following an upgrade procedure, or after installing an affected UCS archive, messages that appear similar to the following example may be displayed in the Configuration utility:

    This BIG-IP system has encountered a configuration problem that may prevent the Configuration utility from functioning properly.

    To prevent adverse effects on the system, F5 recommends that you restrict your use of the Configuration utility to critical tasks only until the problem is resolved. Beware that attempting to modify your configuration in this state with the Configuration utility may cause your configuration to be overwritten.

  • Messages that appear similar to the following example may be written to the /var/log/ltm file:

    load_config_files: "/usr/libexec/bigpipe base daol" - failed. -- BIGpipe parsing error (/config/bigpipe/bigip_sys.conf Line 19): 012e0021:3: The requested attribute (port find) is invalid for 'ltm'.
    Reading configuration from /config/bigpipe/low_profile_base.conf. Reading configuration from /config/bigpipe/config_base.conf. Reading configuration from /config/bigpipe/bigip_sys.conf.

Workaround

To work around this issue, you can revert to the previous version, reset the db key values, and re-upgrade the device, or remove the db key values from the UCS archive and install the modified archive. To do so, perform either of the following procedures:

Revert to the previous version, reset db key values, and re-upgrade the device

Impact of workaround: This work around requires multiple system reboots which may cause a service interruption.

  1. Log in to the Configuration utility.
  2. Navigate to the System > Software Management > Boot Locations menu.
  3. Choose the appropriate item from the Boot Partition menu for the configuration to which you wish to revert.
  4. Click Activate to reboot the device and activate the selected Boot Partition.
  5. When the reboot is complete, log in to the BIG-IP command line.
  6. Reset the db key values and save the changes by entering the following three commands:

    tmsh modify sys db tm.portfind.linear value 16

    tmsh modify sys db tm.portfind.random value 16

    tmsh save sys config

  7. Using a text editor, open the extracted /config/bigip_sys.conf file by entering the following command:

    vi /config/bigip_sys.conf

  8. Locate the ltm stanza, it will appear similar to the following:

    ltm {
    port find linear 16
    port find random 16
    }

  9. Remove the port find linear and port find random entries from the file, as shown in the following example:

    Note: In this example the port find db keys are the only entries in the ltm stanza. If your file has additional entries, they should not be modified. This may result in a different edited stanza than displayed in this example.

    ltm {
    }

  10. Save and exit the file.
  11. If you found and removed port find linear and port find random entries in steps 8 through 10, you must load the updated configuration file by typing the following command:

    tmsh load sys config
  12. Re-upgrade the configuration to the desired 11.x version by following the steps detailed in the release notes for your version.

Remove the incorrect db key values from the affected UCS archive and install the modified archive

Impact of workaround: Any existing configuration on the BIG-IP system is removed and replaced with the configuration from the UCS archive file.

Note: In this procedure, F5 assumes that the BIG-IP system is still booted into the version 11.x volume following the upgrade operation.

  1. Transfer the UCS archive to the BIG-IP system.

    Note: For assistance transferring the UCS archive from another BIG-IP device using SCP, from a remote FTP server using FTP, or from an attached workstation using HTTPS, refer to K175: Transferring files to or from an F5 system.

    Note: For assistance transferring the UCS archive from your workstation to the BIG-IP system using SCP, refer to the manual of your chosen SCP application.

    For the purposes of this procedure, the example location and name of the UCS archive that has been transferred to the BIG-IP system is:

    /var/tmp/My1022_Archive.ucs

  2. Log in to the command line.
  3. Create a working directory by entering the following command:

    mkdir /var/tmp/UCS

  4. Extract the UCS archive to the working directory created in Step 3 by entering the following command syntax:

    tar -zxf <old archive> -C <working directory>

    For example:

    tar -zxf /var/tmp/My1022_Archive.ucs -C /var/tmp/UCS/

  5. Change to the working directory created in Step 3 by entering the following command syntax:

    cd <working directory>

    For example:

    cd /var/tmp/UCS/

  6. Change the permissions on the BigDB.dat file from the archive to allow write access by entering the following command:

    chmod +w config/BigDB.dat

  7. Using a text editor, open the extracted BigDB.dat file.

    For example:

    vi config/BigDB.dat

  8. Locate the following two stanzas:

    Note: In this example, the values of both db keys have been set to 20. The values in your file may differ.

    display_name=TM.PortFind.Linear
    value=20

    display_name=TM.PortFind.Random
    value=20

  9. Modify the stanzas in Step 8 to the default value of 16, as shown in the following example:

    display_name=TM.PortFind.Linear
    value=16

    display_name=TM.PortFind.Random
    value=16

  10. Save and exit the file.
  11. Set the permissions for the extracted BigDB.dat file back to the default (read-only), by entering the following command:

    chmod -w config/BigDB.dat

  12. Using a text editor, open the extracted bigip_sys.conf file by entering the following command:

    vi config/bigip_sys.conf

  13. Locate the ltm stanza containing the port find linear and port find random entries in the extracted bigip_sys.conf file.

    For example:

    Note: In this example, the values of both db keys have been set to 20. The values in your file may differ.

    ltm {
    port find linear 20
    port find random 20
    }

  14. Remove the port find linear and port find random entries from the file, as shown in the following example:

    Note: In this example the port find db keys are the only entries in the ltm stanza. If your file has additional entries, they should not be modified. This may result in a different edited stanza than displayed in this example.

    ltm {
    }

  15. Save and exit the file.
  16. Create a new UCS Archive with the modified files by using the following command syntax:

    tar -czf <newarchive> *

    For example:

    tar -czf MyRebuiltArchive.ucs *

  17. Install the newly-created UCS Archive by using the following command syntax:

    tmsh load sys ucs /var/tmp/<working directory>/<newarchive>

    For example:

    tmsh load sys ucs /var/tmp/UCS/MyRebuiltArchive.ucs
