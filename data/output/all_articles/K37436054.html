Known Issue

A BIG-IP system using an nPath configuration may erroneously mark a pool member as down.

This issue occurs when all of the following conditions are met:

  • You have configured a pool member in an nPath network environment.
  • You have a transparent health monitor to monitor the status of the pool member.
  • You have enabled the tm.monitorencap system database variable.

With the nPath routing configuration, also called asymmetric routing or direct server return (DSR), you can route outgoing server traffic around the BIG-IP system. For information about nPath configuration, refer to K13403: Configuring L3 nPath load balancing and monitoring and the Introducing nPath Routing chapter of the BIG-IP Local Traffic Manager: Implementations manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Impact

Erroneously marked down pool members cannot process network traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe that a pool member is erroneously marked down by the BIG-IP system.
  • If you enable the tmm.lognonsessionpackets system database variable, you observe log entries in the /var/log/ltm file that appear similar to the following example:

    tmm1[13182]: 01070417:6: ICSA: non-session TCP packet rejected, source: 192.168.1.2 port 80, destination: 192.168.1.3 port:41719
