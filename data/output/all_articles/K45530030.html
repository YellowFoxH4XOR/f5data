Topic

You should consider using this procedure under the following conditions:

  • You want to use F5 Modules for Ansible to configure the BIG-IP system using a declarative model with the F5 Application Services 3 Extension (AS3).
  • You want to use the Jinja2 templating language with your JSON declaration file.

Description

With AS3, you can deploy an application service configuration on the BIG-IP system using a declarative REST API. This involves creating a JSON file with a declaration and using an HTTP client to transmit it to the AS3 REST API. You can automate the task on a single BIG-IP system or numerous BIG-IP systems using Ansible, which is a tool that automates and manages multi-machine configuration and deployment. Additionally, when using Ansible you can take advantage of the Jinja2 templating language and make your JSON declaration files reusable by turning them into templates.

Important: F5 removed the bigip_appsvcs_extension module from Ansible 2.10 and the F5 Modules Collection v1.3.0. Refer to F5 Ansible Collections in F5 Modules for Ansible for equivalent features to replace the functionality.

Example playbook

The following example playbook uses AS3 to deploy a configuration on the BIG-IP system. To create a similar playbook, perform the procedures in this article:

---
- name: Using AS3 to deploy a configuration
  hosts: bigip15-0.example.com
  gather_facts: False
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False
 
  vars_prompt:

    - name: TENANT
      prompt: "What is the tenant name? "
      private: no

    - name: VIP_ADDRESS
      prompt: "What is the virtual IP address? "
      private: no

  tasks:

      - name: Deploy a simple HTTP application
        bigip_appsvcs_extension:
          content: "{{ lookup('template', 'templates/AS3-http-app.j2') }}"
          state: present
          provider: "{{ provider }}"
        delegate_to: localhost
 

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You read the User's Guide on F5 Modules for Ansible.
  • You read the User's Guide on F5 Application Services 3 Extension.
  • You installed the F5 AS3 package on the target BIG-IP device. Refer to the Downloading and installing the AS3 package section of the AS3 User's Guide.
  • You installed Ansible 2.8 or 2.9 on the control machine.
  • If you decide to use collections, you use a F5 Modules Collection prior to 1.3.0.
  • You installed BIG-IP 13.x or later on the devices in the environment.
  • You installed the uuidgen utility on the control machine.
  • You installed the Python packages required for each module you want to use on the control machine. For more information, refer to Module Index in the Ansible User Guide.

Creating the JSON declaration template file

Templating a file is a key feature of Ansible and you can create your JSON declaration file as a template to use with the bigip_appsvcs_extension module. To simply illustrate this concept, the procedure describes how to include variables in an example JSON declaration from the AS3 User Guide. Additionally, the procedure shows how to use variables for only the label, tenant (administrative partition), id, and virtualAddresses parameters. You can however use the procedure as an outline to help you create a more advanced JSON declaration template and use variables of your own choosing. Variables in Jinja2 templates are surrounded by double open ( {{ ) and close ( }} ) braces. The variable names in the example are uppercase to make them more prominent in the template file, but it is not required. The template uses existing nodes in the Common partition.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use the Simple HTTP application example from the AS3 User Guide to create a JSON declaration template file called AS3-http-app.j2 in your playbooks/templates/ directory.
  2. Use a text editor to open the file for modification.
  3. In the ADC class, for the id, use the pipe lookup plugin to execute the uuidgen command on the control machine to generate a UUID.
  4. For label, replace the value with the variable, {{ TENANT }}.
  5. In the Tenant class replace the class name with the variable, {{ TENANT }}.
  6. In the Service class replace the value for virtualAddresses with {{ VIP_ADDRESS }}.
  7. In the Pool class replace the serverAddresses with nodes from your environment, new nodes, or a variable. You can include more than two if desired.

The following JSON declaration template includes the modifications made in this procedure:

{
   "class": "AS3",
   "action": "deploy",
   "persist": true,
   "declaration": {
      "class": "ADC",
      "schemaVersion": "3.0.0",
      "id": "urn:uuid:{{ lookup('pipe','uuidgen') }}",
      "label": "{{ TENANT }}",
      "remark": "Simple HTTP application with RR pool",
      "{{ TENANT }}": {
         "class": "Tenant",
         "Application": {
            "class": "Application",
            "template": "http",
            "serviceMain": {
               "class": "Service_HTTP",
               "virtualAddresses": [
                  "{{ VIP_ADDRESS }}"
               ],
               "pool": "web_pool"
            },
            "web_pool": {
               "class": "Pool",
               "monitors": [
                  "http"
               ],
               "members": [{
                  "servicePort": 80,
                  "serverAddresses": [
                     "192.0.2.1",
                     "192.0.2.2"
                  ]
               }]
            }
         }
      }
   }
}

Defining initial play settings

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Create a playbook file called deploy_AS3_http_app.yml.
  3. Start composing your playbook YML file and set the hosts to the individual BIG-IP or group of BIG-IP devices you want to configure, such as bigip15-0.example.com in the previous example. Gathering system facts is not necessary for this playbook.
  4. In the vars parameter, create a playbook variable called provider. Add the BIG-IP connection details as the values to the provider variable. In the example, group variables from the group the host belongs to are used. You can reference the provider variable in the provider parameter in the BIG-IP module. You can encrypt BIG-IP passwords for the playbook by placing them in the vault. For more information, refer to K64450989: Using the 'ansible-vault' command to encrypt BIG-IP passwords used in a playbook.

The following play settings section from the example playbook shows all of the elements described in this procedure:

---
- name: Using AS3 to deploy a configuration
  hosts: bigip15-0.example.com
  gather_facts: False
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False
 

Including variables from the template in the playbook

There are a variety of methods for including variables in the playbook that the JSON declaration template will have access to. The following procedure describes how to use prompts to define the variables. When the playbook is executed, it prompts the user for input on the command line.

You can follow the procedure to use prompts or you can use another method to include variables. For more information, refer to the Using Variables page of the Ansible User Guide. When creating variables in the playbook, ensure that they match the variable name you used in the template file.

Note: The previous link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Create a vars_prompt section.
  2. Create your variables from the ones used in the template. Include the variable name exactly how it appears in the template file, the prompt that will appear to the user, and include private: no so that the input is echoed to the screen. 

The following var_prompts section from the example playbook shows the elements described in this procedure:

  vars_prompt:

    - name: TENANT
      prompt: "What is the tenant name? "
      private: no

    - name: VIP_ADDRESS
      prompt: "What is the virtual IP address? "
      private: no


Creating a task that deploys a simple HTTP application on the BIG-IP system

With the bigip_appsvcs_extension module you can use Ansible to interact with the AS3 REST API on the BIG-IP system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Start your list of tasks with the tasks statement.
  2. Create a task that uses the bigip_appsvcs_extension module.
  3. For the content parameter use the template lookup plugin and specify the JSON declaration template you created previously.
  4. Add state: present to deploy the configuration.
  5. Include the provider variable you created at the start of the play as the value for the provider parameter.
  6. Add delegate_to: localhost so the task is performed on the control machine itself which is required for all F5 Modules for Ansible.

The following task from the example playbook shows the elements described in this procedure:

  tasks:

      - name: Deploy a simple HTTP application
        bigip_appsvcs_extension:
          content: "{{ lookup('template', 'templates/AS3-http-app.j2') }}"
          state: present
          provider: "{{ provider }}"
        delegate_to: localhost

Running the playbook

You can now run the playbook from your control machine to make configuration changes to the BIG-IP devices in the play.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Change the working directory to the one with your playbooks.
  3. To run the playbook from the command line of your control machine, type the following command:

    ansible-playbook deploy_AS3_http_app.yml

Removing the application

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To remove an AS3-created configuration you can create a task with the bigip_appsvcs_extension module in another playbook that includes the parameter and value, state: absent. Refer to the following examples and for more information refer to the bigip_appsvcs_extension module documentation.

Note: The previous link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

- name: Remove all app service configurations
  bigip_appsvcs_extension:
    tenants: all
    state: absent
    provider: "{{ provider }}"
  delegate_to: localhost

- name: Remove specific tenants from app service configurations
  bigip_appsvcs_extension:
    tenants:
      - My_App1
      - My_App2
    state: absent
    provider: "{{ provider }}"
  delegate_to: localhost

 

Example configuration

If you enter My_App for the TENANT variable and 198.51.100.1 for the VIP_ADDRESS variable when you execute the deploy_AS3_http_app.yml playbook, the AS3 REST API creates the following configuration:

ltm pool /My_App/Application/web_pool {
    members {
        /Common/192.0.2.1:80 {
            address 192.0.2.1
            description "(replaces AS3 192.0.2.1)"
            metadata {
                source {
                    value declaration
                }
            }
        }
        /Common/192.0.2.2:80 {
            address 192.0.2.2
            description "(replaces AS3 192.0.2.2)"
            metadata {
                source {
                    value declaration
                }
            }
        }
    }
    min-active-members 1
    monitor min 1 of { /Common/http }
}
ltm virtual /My_App/Application/serviceMain {
    creation-time 2019-09-10:18:27:26
    description Application
    destination /My_App/198.51.100.1:80
    ip-protocol tcp
    last-modified-time 2019-09-10:18:27:26
    mask 255.255.255.255
    persist {
        /Common/cookie {
            default yes
        }
    }
    pool /My_App/Application/web_pool
    profiles {
        /Common/f5-tcp-progressive { }
        /Common/http { }
    }
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}
ltm virtual-address /My_App/198.51.100.1 {
    address 198.51.100.1
    arp enabled
    inherited-traffic-group true
    mask 255.255.255.255
    traffic-group /Common/traffic-group-1
}
