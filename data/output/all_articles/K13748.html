Topic

To properly maintain resources on the Virtual Clustered Multiprocessing (vCMP) host system, avoid performing concurrent upgrades to multiple vCMP guest instances that reside on the same slot.

Description

vCMP is a BIG-IP feature that allows you to run multiple instances of the BIG-IP software (vCMP guests) on a single hardware platform. The vCMP host allows you to create and manage vCMP guests and virtual disks on the system. The vCMP host also allocates system resources to each guest when the guest moves to the Provisioned state. A vCMP guest is an object that you create on the vCMP host system to run one or more BIG-IP module instances. When performing resource-intensive actions, such as upgrading software or hotfixes for a vCMP guest, it is important to maintain resources on the vCMP host system.

Recommendations

When preparing to upgrade multiple vCMP guest instances, consider the following factors:

  • When preparing to upgrade multiple vCMP guest instances on the same slot, perform the upgrades in succession.

    For example, if Slot-1 on the vCMP host system contains vCMP guests named, Guest-1, Guest-2, and Guest-3, perform the upgrades to the guest instances one at a time; do not perform the upgrades concurrently. Attempting to perform concurrent upgrades to more than one vCMP guest on the same slot will result in high CPU utilization, and in some cases a watchdog reboot on the vCMP host system.

  • When preparing to upgrade multiple vCMP guest instances on different slots, perform the upgrades in succession or concurrently.

    For example, if Slot-1 on the vCMP host system contains a vCMP guest named Guest-1, and Slot-2 on the vCMP host contains a vCMP guest named Guest-2, you can perform the upgrades to the guest instances concurrently or in succession.
