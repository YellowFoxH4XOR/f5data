K19905853: ASM may not pass server responses to a client if the response is incomplete

Issue

Description

The BIG-IP ASM system will attempt to accumulate the entire body of an HTTP response when certain features are enabled in the policy. Responses will not be forwarded until either the content length specified in the response header has been reached, or in the case of a chunked response, when the terminating chunk (0\r\n) has been received indicating the end of the server response. If these conditions are not met then the response will not be forwarded to the client and the BIG-IP ASM may reset the connection. This is to ensure that ASM response checking features are inspecting and enforcing the full response.

As a result, you may encounter the following symptoms:

  • Chunked responses without terminating chunks are not forwarded but no response violation is detected.
  • Responses that do not contain the full content length are not forwarded.
  • Responses specifying chunked transfer encoding that do not contain chunk prefixes per RFC may be reset.

Environment

  • BIG-IP ASM
  • One or more of the following ASM features are enabled:
    • Learn from Responses in the Policy Builder settings
    • DataGuard
    • Dynamic Parameters Extractions
    • Login Page Detection
    • Server Technologies
    • Attack Signatures in the Response
    • Dynamic Session ID in URL
  • The response from the back end server is incomplete

Cause

This is expected behavior. When certain features are enabled in the security policy, the BIG-IP ASM system accumulates the entire body of an HTTP response before forwarding it. This can occur when your web server is using the Server Send Event (SSE) or similar functionality with chunked transfer encoding.

Recommended Actions

  • Verify that the response from the server is incomplete and resolve any unexpected behavior, such as incorrect content length being specified by the server or improper HTTP chunking behavior.
  • If using functionality such as SSE or other response streaming technologies (WebSockets excluded), then disabling the above ASM policy features will remove the response accumulation behavior and responses will be forwarded as received.
