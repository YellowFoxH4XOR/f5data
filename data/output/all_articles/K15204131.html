Description

BIG-IP is not able to send traffic to a node or gateway. Further check shows that the ARP cache table for the node or gateway is incomplete.Refer to the example below:

tmsh show /net arp

--------------------------------------------------------------------------------
Net::Arp
Name           Address        HWaddress          Vlan              Expire-in-sec  Status
--------------------------------------------------------------------------------
10.0.0.1       10.0.0.1       incomplete         /Common/internal  0              unknown    

Environment

  • BIG-IP
  • ARP cache table status shows the node or gateway is incomplete

Cause

Common cause for the ARP cache table not being updated is because BIG-IP does not get the ARP response from the node or gateway.

Recommended Actions

We would need to run a tcpdump and check the ARP packets to properly understand what is happening.

  1. Login to the BIG-IP command line.
     
  2. Run a tcpdump command while replicating the issue to capture arp packets and the node/gateway IP address for tmm interface. The command is as below where x.x.x.x is the node/gateway IP address.
    tcpdump -s 0 -nni 0.0:nnn -w /shared/tmp/arp.pcap host x.x.x.x or arp -v

    Example if the node/gateway IP address is 10.0.0.1:
    tcpdump -s 0 -nni 0.0:nnn -w /shared/tmp/arp.pcap host 10.0.0.1 or arp -v
     
  3. Download the pcap file at /shared/tmp/arp.pcap to your local machine.
     
  4. Open the pcap file on your local machine with Wireshark.
     
  5. Run the following wireshark filter to view the ARP request and ARP response where x.x.x.x is the node/gateway IP address.
    arp.dst.proto_ipv4 == x.x.x.x or arp.src.proto_ipv4 == x.x.x.x

    Example if the node/gateway IP address is 10.0.0.1:
    arp.dst.proto_ipv4 == 10.0.0.1 or arp.src.proto_ipv4 == 10.0.0.1
     
  6. The expected outcome is an ARP request sent by the BIG-IP and an ARP response coming back from the node/gateway IP address. For an example, below the BIG-IP address is 10.0.0.100 with MAC address 00:00:5E:00:53:F5 while the node/gatway IP address is 10.0.0.1 with MAC address 00:00:5E:00:53:00.
    No.     Time               Source                Destination           Protocol Info
        100 14:44:44.000000    00:00:5E:00:53:F5     00:00:5E:00:53:00     ARP      Who has 10.0.0.1? Tell 10.0.0.100
        101 14:44:44.000001    00:00:5E:00:53:00     00:00:5E:00:53:F5     ARP      10.0.0.1 is at 00:00:5E:00:53:00
     
  7. If the pcap is similar with the example above, the BIG-IP should should update the ARP cache table but is is not doing so. Do contact the F5 Support to continue troubleshooting this issue.
     
  8. If the pcap shows that the BIG-IP is sending the ARP request but not getting a ARP response, do a pcap on the node/gateway to confirm if it is receiving the ARP request from the BIG-IP. If it is receiving the ARP request but not responding with the ARP response, you will need to investigate further on the node/gateway.
     
  9. If the node/gateway does not receive the ARP request from the BIG-IP or the node/gateway is sending the ARP response but the BIG-IP is not receiving the response, you will need to do a pcap on the switch or any device between BIG-IP and the node/gateway. This will confirm how the switch or intermediary device process the ARP packets between the BIG-IP and node/gateway.
