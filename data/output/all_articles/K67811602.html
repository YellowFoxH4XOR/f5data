Topic

You should consider using this procedure under the following condition:

  • You want to use a network access (VPN) tunnel to automatically launch a specific client-side Android application.

Description

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP APM system.
  • You have previously uploaded the required valid SSL certificate, key, and intermediary CA certificate for use with the per-app VPN configuration.

Procedures

  • Creating a Connectivity profile
  • Creating a Network Access profile
  • Creating the per-session access profile
  • Creating an ACL to limit network access
  • Configuring the access policy
  • Creating an access policy F5 Access version check
  • Adding resources to the access policy
  • Creating a ClientSSL profile
  • Creating a virtual server for use as a per-app VPN

Creating a Connectivity profile

The following procedure steps create a BIG-IP APM Connectivity profile for use with the network access virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Access > Connectivity / VPN > Connectivity > Profiles.
  2. Click Add.
  3. Enter a profile name.
  4. For Parent Profile, click /Common/connectivity.
  5. Click OK.

Creating a Network Access lease pool

The following procedure steps create a BIG-IP APM lease pool to assign IP addresses to established sessions for use in accessing the destination application.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Access > Connectivity/VPN > Network Access (VPN) > IPV4 Lease Pools.
  2. Click Create.
  3. Enter a name for the new lease pool.
  4. For Type click IP Address Range, for Start IP Address, enter the starting IP address, and for End IP Address, enter the ending IP address.

    or

    For a single-address lease pool, for Type, click IP Address and for IP Address, enter the IP address to use for network access connections.

    Important: The Address Range addresses or single IP Address should be for the application network or able to route to the destination application.

  5. Click Finished.

Creating a Network Access profile

The following procedure steps create a BIG-IP APM Network Access profile for use with the network access virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Access > Connectivity/VPN > Network Access (VPN) > Network Access Lists.
  2. Click Create.
  3. Enter a name for the profile.
  4. For Auto launch, select the Enable check box.
  5. For Caption, enter a caption the users will see.
  6. Click Finished.
  7. Click the Network Settings tab.
  8. Under Client Settings, for Traffic Options, click Use split tunneling for traffic.
  9. For IPV4 LAN Address Space, enter the application IP Address and Mask.
  10. For DNS Address Space, enter the network space IP address.
  11. For Enable Network select the check box for Tunnel Network Tunnel.
  12. For IPV4 Lease Pool click the lease pool configured in the previous procedure or click (+) to create a new lease pool.
  13. If the destination application server is not configured to route addresses in the IPV4 lease pool to the BIG-IP APM, for SNAT Pool click Auto Map.
  14. Click Update.
  15. Click the Launch Applications tab.
  16. For Display warning before launching applications, clear the check box.
  17. Click Add.
  18. For Application Path, enter the Android application name reference.

    Note: When using a hostname as the destination for the client-side application the host name must be resolvable by the Android client.

  19. For Parameters, enter any required parameters to be passed to the application.

    For example:

    Application Path: googlechrome://navigate?url=http://172.16.1.222/application.html

    Note :In this example there are no parameters configured to be sent to the application since the URL contains all the required parameters.

    Note: In the example the connecting client devices must have the Google Chrome browser application installed for the launch to function.

  20. For Operating System, click Android.
  21. Click Finished.

Creating the per-session access profile

The following procedure steps create a BIG-IP APM per-session profile for use with the network access SSL-VPN virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  2. Click Create.
  3. Enter a name for the access policy.
  4. For Profile Type click SSL-VPN.
  5. Under Language Settings, in the Factory BuiltIn Languages list, click the default language(s) for the access profile and move them to the Accepted Languages list.
  6. Click Finished.

Creating an ACL to limit network access

The following procedure steps create a network access Access Control List (ACL) profile to control the level of network access granted to an established network access session.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Access > Access Control Lists.
  2. Click Create.
  3. Enter a name for the ACL.
  4. Click Create.
  5. For ACL Order, click Specify and type 1.
  6. For Match Case For Paths, click No.
  7. Click Create.
  8. For Access Control Entries, click Add.
  9. For Type, click L4.
  10. For Destination address, click Host and enter the Address of the destination application.
  11. For Destination Port(s), click either Port or Port range, designate the ports required to interact with the destination application (for example using the Launch Application example; 80).
  12. For Protocol , click the network protocol used to interact with the application (for example using the Launch Application example; TCP).
  13. For Action, click Allow.
  14. Click Finished.
  15. For Access Control Entries, click Add.
  16. For Type, click L4.
  17. For Action, click Discard.
  18. Click Finished.

Configuring the access policy

The following procedure steps configure the access policy of the per-session Access profile. This access policy utilizes the authentication type of SSL Client certificate inspection, F5 Access version level check, and the resource assignment of the authorized session. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: Alternative methods of authentication can be utilized if SSL Client certificate inspection does not fit your deployment model. For more information regarding access policy authentication options refer to the Authentication and Single Sign-On Authentication Concepts chapter of the BIG-IP APM BIG-IP Access Policy Manager manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

  1. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  2. For the new policy, in the Per-Session Policy column, click the Edit to launch the Visual Policy Editor (VPE).
  3. On the Android branch following the Client OS policy item, click the Add icon (+).
  4. Click the Authentication tab.
  5. Click Client Cert Inspection and click Add Item.
  6. Click Save.
  7. Close the VPE.
  8. Click Apply Access Policy.

Creating an access policy F5 Access version check

The following procedure steps create a policy check to ensure that an Android client connecting to the access profile are running the F5 Access client version 3 or later.

Impact of procedure: The version check limits access to only clients that meet or exceed the version check. If Android clients are not using the F5 Access VPN utility or you are unsure what versions of F5 Access you users will be connecting with, skip this procedure.

  1. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  2. For the new policy, in the Per-Session Policy column, click the Edit to launch VPE.
  3. On the Successful branch of the Client Cert Inspection policy item, click the Add icon (+).
  4. Click the General Purpose tab.
  5. Click Empty, and click Add Item.
  6. On the Properties tab, for Name, type F5 Access Version.
  7. Click the Branch Rules tab.
  8. Click Add Branch Rule.
  9. For Name, type Version Check.
  10. For Expression, click change.
  11. Click the Advanced tab.
  12. Enter the following Tcl stanza into the text box:

    expr { [mcget {session.client.app_version}] >= "3.0" }

    Note: The Tcl expression checks the client request and verifies that the client is using F5 Access version 3 or later.

  13. Click Finished.
  14. Click Save.

Adding resources to the access policy

The following procedure steps configures the access policy to assign specific resources to the established access session.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the fallback branch following the F5 Access Version policy item, click the Add icon (+).
  2. Click the Assignment tab.
  3. Click Advanced Resource Assign.
  4. Click Add Item.
  5. Click Add New Entry.
  6. Click Add/Delete.
  7. Optional: Click the Static ACLs tab select the check box for the ACL profile created in the previous procedure.
  8. Click the Network Access tab.
  9. Select the check box for the Network Access profile created in the previous procedure.
  10. Click the Webtop tab.
  11. Select the check box for the Webtop created in the previous procedure.
  12. Click Update.
  13. Click Save.
  14. On the Successful branch, click the Deny endpoint.
  15. Click Allow.
  16. Click Save.

Creating a ClientSSL profile

The following procedure steps create a BIG-IP ClientSSL profile for use with the network access virtual server. The ClientSSL profile is configured to "request" a client-side certificate, validation of the certificate is handled by the access policy Client Cert Inspection.Therefore, validation of the client-side certificate is not configured as (required) as part of the ClientSSL profile.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > Profiles > SSL > Client.
  2. Click Create.
  3. Enter a name for the profile.
  4. For Configuration, click Advanced.
  5. Select the Custom check box.
  6. For Ciphers, type NATIVE.
  7. Under Client Authentication, select the Custom check box.
  8. For Trusted Certificate Authorities, click your trusted certificate authority.
  9. For Client Certi?ficate , click request .
  10. Click Finished.

Creating a virtual server for processing the network access session

The following procedure outlines the steps required to incorporate the previous procedures into a per-session network access virtual server to allow VPN access to the access policy configured resources.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > Virtual Servers.
  2. Click the name of the virtual server you want to configure with the new access policy.
  3. Under Configuration, for SSL Profile (Client), in the Available list, click the name of the Client SSL profile previously created and move it to the Selected list.
  4. Under Access Policy, for Access Profile, click the previously created access profile.
  5. For Connectivity Profile, click the connectivity profile previously created.
  6. For Application Tunnels (Java & Per-App VPN), select the check box.
  7. Click Update.
