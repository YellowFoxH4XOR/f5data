K000140177: [F5OS] Intermittent packet loss when sending traffic to not responding MAC address

Type
Support Solution
Published
2024-06-28
Updated
2024-07-04
Applies to
  • rSeries Platforms
  • F5OS
  • rSeries 10000
  • rSeries 10900
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000140177

Description

High rate traffic initiated from rSeries 5K/10K or VELOS tenant to a remote device, which does not respond, might be dropped on F5OS layer. Typically, this happens when sending traffic to IDS (Intrusion Detection System) using LTM clone pools or SSLO service chain.

Environment

  • rSeries 5K/10K
  • VELOS
  • Intermittent packet loss
  • LTM clone pool
  • SSLO service chain

Cause

The mentioned platforms have a built-in rate limiter that prevents from overloading all the ports with the traffic that does not have FDB entry.

Recommended Actions

Choose one of the solutions.

1) Configure the not-responding remote device to periodically send some traffic towards the tenant.

2) On F5OS, configure a static FDB (Forwarding Database) entry. The example command below presents rSeries entry for a remote device MAC address reachable on VLAN70 via interface 6.0.

$ appliance-1(config)# fdb mac-table entries entry 00:00:00:00:00:08 70 tag_type_vid interface interface-ref config interface 6.0

Note: The same syntax applies to VELOS partition. Make sure the VLAN exists before carrying out the command.

Additional Information

Tenant is a similar concept to vCMP guest.
K94430632: Clone pool members on a vCMP guest require valid MAC addresses in BIG-IP L2 FDB explains that FDB entry for each remote device must exist. If the remote device does not have a valid FDB entry, the vCMP guest forwards the traffic to the vCMP host as well as all vCMP guests associated with the same VLAN as the destined remote device. clone pool member. When this occurs, the Traffic Management Microkernel (TMM) instances across these affected hosts and guests will use more resources, and discard traffic that they are not supposed to be receiving. As a result, CPU utilization may increase on the affected TMM instances and affect the performance of traffic processing.

Note: This behavior applies to all platforms provisioned for vCMP regardless of the number of HSBs present. For platforms that are not provisioned for vCMP, the behavior applies when there are two HSBs present. For more information, refer to K17567: Clone pool members require L2 FDB entries.
