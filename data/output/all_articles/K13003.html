Known Issue

The radvd process fails to start properly if the radvd.conf file interface definition contains a VLAN name with uppercase letters or a period character ( . ).

This issue occurs when one of the following conditions is met:

  • The /etc/radvd.conf interface definition contains a VLAN name with one or more uppercase letters or a period.

    For example, if you edit the /etc/radvd.conf file and configure the interface definition to match the VLAN name on the system and the name contains one or more uppercase letters, the radvd process fails to start properly. In the following sample radvd.conf file, the interface name is External:

    interface External
    {
    AdvSendAdvert on;
    # IgnoreIfMissing on;
    MinRtrAdvInterval 3;
    MaxRtrAdvInterval 10;
    AdvDefaultPreference low;
    AdvHomeAgentFlag off;
    prefix fc01:e5:1103::/48
    {
    AdvOnLink on;
    AdvAutonomous on;
    AdvRouterAddr off;
    };
    };

The radvd process is the router advertisement process for IPv6. The radvd process listens to router solicitations and sends router advertisements as described in RFC2461.

Impact

The BIG-IP system fails to listen for IPv6 router solicitations and/or supply router advertisements to other hosts on the network.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The radvd process fails to start
  • The BIG-IP system outputs an error message to the console that appears similar to the following example:

    Re-starting radvd

  • The BIG-IP system logs error messages to the /var/log/daemon.log file that appear similar to the following example:

    emerg logger: Re-starting radvd
    err radvd[29375]: syntax error in /etc/radvd.conf, line 1: V
    err radvd[29375]: error parsing or activating the config file: /etc/radvd.conf

Resolution

Status

F5 Product Development has assigned ID 358090 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Note: This issue does not affect BIG-IP 11.1.0 or later. IPv6 router advertisement functionality was integrated into Traffic Management Microkernel (TMM) starting in BIG-IP 11.1.0.

Workaround

To work around this issue, perform the following tasks:

Impact of workaround: Before you can remove a VLAN object from the BIG-IP configuration, you must first disassociate any dependent network objects, such as self IP addresses, from the VLAN.

  • Remove and recreate VLAN object(s) from the BIG-IP configuration and ensure there are no uppercase letters or period symbols in the new VLAN name.
  • Edit the /etc/radvd.conf file and add the new VLAN name.
