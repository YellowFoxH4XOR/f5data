Topic

You should consider using these procedures under the following conditions:

  • You are a new user of the iControl representation state transfer (REST) application programming interface (API).
  • You want basic example REST commands for administering your BIG-IP LTM system.

Description

The following command examples show you how to use REST commands with minimal complexity.

Each REST command has multiple values that you can assign when running the command. When a specific value is not stated in the REST command, the default value is assumed. To understand the values available for a command, refer to the iControl REST User Guide that applies to your BIG-IP version, available on iControlREST Home.

In addition, viewing a currently configured object using a REST command displays all the values for the object, which can help you understand the required syntax to create an object setting value that is not covered in the examples.

In most cases, you can view an object's configuration using the GET method and the Uniform Resource Identifier (URI) of the specific object.

For example, to view the configuration setting for a specific VLAN, you can use the URI path used to create the /mgmt/tm/net/vlan object and append the object name to the /mgmt/tm/net/vlan/<vlan name> URI:

curl -sk -u admin:<password> GET  https://<big-ip address>/mgmt/tm/net/vlan/<vlan name> | jq . -M

Note: The JSON output of the object configuration includes links to view additional nested configuration details.

When using the JSON links, replace localhost with the IP address of the BIG-IP system.

Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output.  The '.' (period) parameter is optional in jq 1.5 and later.

curl -sk -u admin:default  GET https://10.95.0.55/mgmt/tm/sys/software/volume| jq . -M

Typographic conventions

The following typographic conventions are used in the command syntax examples:

  • POST = curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<big-ip address>
  • PATCH = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PATCH  https://<big-ip address>
  • PUT = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PUT  https://<big-ip address>
  • DELETE = curl -sk -u admin:<password>  -H "Content-Type: application/json" -X DELETE https://<big-ip address>
  • GET = curl -sk -u admin:<password>   -H "Content-Type: application/json" -X GET https://<big-ip address>

    Note: When updating an existing object configuration, the recommendation is to use PATCH. Updating a configuration with PUT will modify the object's configuration, however configuration parameters that are not specified as part of the command will acquire their default settings.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Your BIG-IP system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP LTM Configuration utility.
  • You have command line access to a Linux system (or an alternate BIG-IP system) with the curl and jq (command line JSON processor) utilities installed.

Viewing configured components and component statistics

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To gather a list of configured partitions, use the following command syntax:

    <GET> /mgmt/tm/auth/partition | jq -M .

    JSON output can be verbose. To limit the output to just the specific partition names use the following syntax:

    <GET> /mgmt/tm/auth/partition | jq -M . | grep fullPath

    The following is an example of JSON output:

    "fullPath" : "Common",

    Note: The partition name appears following the colon (:) within quotation marks (").

  • To obtain a list of all configured component objects for each component type, use the following command syntax:

    <GET> /mgmt/tm/ltm/<component type> | jq -M .

    Note: Change <component type> to one of the following component types: auth cipher, data-group, default-node-monitor, dns, eviction-policy, global-settings, html-rule, ifile message-routing monitor, nat node, persistence policy, policy-strategy, pool, profile, rule, rule-profiler, snat, snatpool, snat-translation, tacdb, traffic-class, traffic-matching-criteria, or virtual virtual-address.

  • To view a specific configuration type object use the following syntax:

    <GET> /mgmt/tm/ltm/<component type>/<component object name> | jq -M .

  • To view a specific configuration object that resides in a non-default partition include the partition name prefixed and suffixed with the tilde (~) character.

    <GET> /mgmt/tm/ltm/<component type>/~<partition name>~<component object name> | jq -M .

  • To gather statistical information for a configured component type append stats to the URL, use the following command syntax:

    Note: Not all component types maintain statistical information, so not all component types may be compatible with stats URL extension.

    <GET> /mgmt/tm/ltm/<component type>/stats

    or

    <GET> /mgmt/tm/ltm/<component type>/<component object name>/stats

    For example:

    <GET> /mgmt/tm/ltm/pool/http_pool/stats

    Note: This command retrieves the statistics for the pool named http_pool, residing in the default Common partition.

    or

    <GET> /mgmt/tm/ltm/pool/~<partition name>~<pool name>/stats

Creating or replacing the NTP server configuration

Impact of procedure: Device time changes can impact the handling of established connections.

To create or update the device network time protocol (NTP) server configuration, use the following command syntax:

<PATCH> /mgmt/tm/sys/ntp -d '{"servers":["<ntp server ip or fqdn>"]}'

Note: The REST command replaces the current configuration. Include all NTP servers when updating the NTP configuration.

For example, to create an NTP configuration with three NTP servers, enter the following command:

<PATCH> /mgmt/tm/sys/ntp -d '{"servers":["1.us.pool.ntp.org","2.us.pool.ntp.org","3.us.pool.ntp.org"]}'

Setting the NTP time zone

Impact of procedure: The displayed date of the device uses the time zone setting.

To set the NTP time zone for the BIG-IP device, use the following command syntax:

<PATCH> /mgmt/tm/sys/db/ntp.timezone -d '{"value":"<continent/city>"}'

For example, to set the NTP time zone of your device to Chicago, enter the following command:

<PATCH> /mgmt/tm/sys/db/ntp.timezone -d '{"value":"America/Chicago"}'

Creating or replacing the DNS server configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To create or update the device domain name server (DNS) configuration, use the following command syntax:

<PATCH> /mgmt/tm/sys/dns -d '{"nameServers":[""]}'

Note: The REST command replaces the current configuration. Include all DNS servers when updating the DNS configuration.

For example, to create an DNS configuration with two DNS servers, enter the following command:

<PATCH> /mgmt/tm/sys/dns -d '{"nameServers":["192.168.1.224","192.168.1.225"]}'

Performing a ConfigSync

Impact of procedure: The following command synchronizes the local BIG-IP device to the device group.

To perform a configuration synchronization (ConfigSync) of the local BIG-IP device to the configured device group, use the following command syntax:

<POST> /mgmt/tm/cm  -d '{"command":"run","utilCmdArgs":"config-sync to-group <device group name>"}'

For example:

<POST> /mgmt/tm/cm  -d '{"command":"run","utilCmdArgs":"config-sync to-group SFG"}'

Creating and deleting a UCS archive

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a user configuration set (UCS) archive on the referenced device, use the following command syntax:

    <POST> /mgmt/tm/sys/ucs -d '{"command":"save","name":"/var/local/ucs/<archive name>"}'

    For example, to create the test_ucs.ucs UCS archive, enter the following command:

    <POST> /mgmt/tm/sys/ucs -d '{"command":"save","name":"/var/local/ucs/test_ucs.ucs"}'

  • To delete the UCS archive, use the following command syntax:

    <DELETE> /mgmt/tm/sys/ucs/<archive name>

    For example, to delete the test_ucs.ucs UCS archive, enter the following command:

    <DELETE> /mgmt/tm/sys/ucs/test_ucs.ucs

Enabling and disabling the Force Offline state

Impact of procedure: Placing the BIG-IP device in the Force Offline state stops the device from responding and processing traffic.

  • To enable the Force Offline state for the BIG-IP device, use the following command syntax:

    <PATCH> /mgmt/tm/sys/db/failover.forceoffline -d '{"value":"enable"}'

  • To disable the Force Offline state for a BIG-IP device, use the following command syntax.

    <PATCH> /mgmt/tm/sys/db/failover.forceoffline -d '{"value":"disable"}' 

Creating tagged and untagged VLANs

Impact of procedures: Using the following commands should not have a negative impact on your system.

  • To create a new tagged VLAN specifying the interface, use the following command syntax:

    <POST> /mgmt/tm/net/vlan -d '{"name":"<vlan name>","tag":"<numeric value","interfaces":[{"name":"<interface>","tagged":true}]}'

    For example, to create the new MyVlan VLAN with the tagged ID of 900 on interface 1.3, enter the following command:

    <POST> /mgmt/tm/net/vlan -d '{"name":"MyVlan","tag":"900","interfaces":[{"name":"1.3","tagged":true}]}'

    Note: The tagged statement does not use the string quoted syntax; the value of true should not have quotes.

  • To create a new untagged VLAN specifying the interface, use the following command syntax:

    <POST> /mgmt/tm/net/vlan -d '{"name":"<vlan name>","tag":"<numeric value>","tagged":"<numeric value>","interfaces":"<interface>"}'

    For example, to create the MyVlan VLAN with an untagged ID of 900 on interface 1.3, enter the following command:

    <POST> /mgmt/tm/net/vlan -d '{"name":"MyVlan","tag":"900","tagged":"900","interfaces":"1.3"}'

Creating self IPs

Impact of procedure: The following command syntax creates a self IP on the BIG-IP device with the default services allowed.

  • To create a local device self IP address on an existing VLAN, use the following command syntax:

    <POST> /mgmt/tm/net/self -d '{"vlan":"<vlan name>","trafficGroup":"<traffic group name>","name":"<self IP name>","address":"<ip address>/<mask>","allowService":"<allowed services>"}'

    For example, to create a self IP on the MyVlan VLAN assigned to the traffic-group-local-only traffic group with the default services allowed, enter the following command:

    <POST> /mgmt/tm/net/self -d '{"vlan":"MyVlan","trafficGroup":"traffic-group-local-only","name":"MyVlan-Self-IP","address":"10.99.100.10/16","allowService":"default"}'

  • To create a floating self IP address on an existing VLAN, use the following command syntax:

    <POST> /mgmt/tm/net/self -d '{"vlan":"<vlan name>","trafficGroup":"<traffic group name>","name":"<self IP name>","address":"<ip address>/<mask>","allowService":"<allowed services>"}'

    For example, to create a self IP on the MyVlan VLAN assigned to traffic-group-1 (floating address) with the default services allowed, enter the following command:

    <POST> /mgmt/tm/net/self -d '{"vlan":"MyVlan","trafficGroup":"traffic-group-1","name":"MyVlan-Self-IP-Floating","address":"10.99.100.11/16","allowService":"default"}'

Creating and deleting static network routes

Impact of procedure: The following command syntax creates a network route on the BIG-IP device that impacts handling of traffic.

  • To create a static network static, use the following command syntax:

    <POST> /mgmt/tm/net/route -d '{"name":"<route name>","partition":"<partition name>","gw":"<gateway ip address>","network":"<destination address>/<mask>"}'

    For example, to create a static route to the 10.200.0.0/16 network using the 10.0.199.253 gateway address, enter the following command:

    <POST> /mgmt/tm/net/route -d '{"name":"Building2","partition":"Common","gw":"10.0.199.253","network":"10.200.0.0/16"}'

  • To delete a static network route, use the following command syntax:

    <DELETE> /mgmt/tm/net/route/<route name>

    For example:

    <DELETE> /mgmt/tm/net/route/Building2

Creating and deleting a floating traffic group

Impact of procedure: Using the following command should not have a negative impact on your system.

  • To create a new floating traffic group, use the following command syntax:

    <POST>/mgmt/tm/cm/traffic-group -H "Content-Type: application/json" -X POST -d '{"name": "traffic-group name", "partition": <partition name>", "fullPath": "/<partition>/<traffic-group name>", "is-floating": "true"}'

    For example, to create a new floating traffic group in the partition Common with the traffic group name rest-created-traffic-group, enter the following command:

    <POST> /mgmt/tm/cm/traffic-group -H "Content-Type: application/json" -X POST -d '{"name": "rest-created-traffic-group", "partition": "Common", "fullPath": "/Common/rest-created-traffic-group", "is-floating": "true"}'

  • To view the configured traffic groups, use the following command syntax:

    <GET> /mgmt/tm/cm/traffic-group | jq .

    You can narrow the returned results to just the traffic group names. For example:

    <GET> /mgmt/tm/cm/traffic-group | jq . | awk '$1 == "\"fullPath\":" {print $2}'

  • To delete an existing traffic group, use the following command syntax:

    <DELETE> /mgmt/tm/cm/traffic-group/<traffic-group name>

    Note: When deleting a configuration object that resides in a partition other than the default Common partition, use the ~<partition>~<object name> syntax.

    For example to delete the traffic group rest-created-traffic-group residing in the partition Common, enter the following command:

    <DELETE> /mgmt/tm/cm/traffic-group/rest-created-traffic-group

Creating and deleting a SNAT or a SNAT pool

Impact of procedure: Creating a secure network address translation (SNAT) rewrites the source address for the request. Depending on the scope of the SNAT configuration (wildcard), all traffic to a destination may have the sources addresses rewritten.

  • To create a SNAT with a wildcard source, use the following command syntax:

    <POST> /mgmt/tm/ltm/snat -d '{"name":"<snat name>","translation":"<ip address>","vlansEnabled":true,"vlans":["/<partition>/<vlan name>"],"origins":[{"name":"<ip address or network range>"}]}'

    For example, to create a SNAT with a wildcard source network mapped to the IP address 10.95.0.55 on the MyVlan VLAN, enter the following command:

    <POST> /mgmt/tm/ltm/snat -d '{"name":"test_snat","translation":"10.95.0.55","vlansEnabled":true,"vlans":["/Common/MyVlan"],"origins":[{"name":"0.0.0.0/0"}]}'

  • To create a SNAT with a specific source network mapped to an IP address, use the following command syntax:

    <POST> /mgmt/tm/ltm/snat -d '{"name":"<snat name>","translation":"<snat ip address>","vlansEnabled":true,"vlans":["/<partition>/<vlan name>"],"origins":[{"name":"<origin address or network/mask>"}]}'

    For example, to create a SNAT with a specific source network mapped to the IP address 10.95.0.55 on MyVlan VLAN, enter the following command::

    <POST> /mgmt/tm/ltm/snat -d '{"name":"test_snat","translation":"10.95.0.55","vlansEnabled":true,"vlans":["/Common/MyVlan"],"origins":[{"name":"10.0.0.0/8"}]}'

  • To delete an existing SNAT configuration, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/snat/<snat name>

    For example:

    <DELETE> /mgmt/tm/ltm/snat/test_snat

  • To create a SNAT pool using the REST interface, use the following command syntax:

    <POST> /mgmt/tm/ltm/snatpool -d '{"name":"<snat pool name>","members":["/<partition>/<ip address>","/<partition>/<ip address>"]}'

    For example, to create the MySNATPool SNAT pool with the SNAT addresses 10.97.0.30 and 10.97.0.31, enter the following command:

    <POST> /mgmt/tm/ltm/snatpool -d '{"name":"MySNATPool","members":["/Common/10.97.0.30","/Common/10.97.0.31"]}'

Creating and deleting a NAT

Impact of procedure: The NAT configuration rewrites the stated source address to the translation address for all request made by the address for the assigned VLAN.

  • To create a NAT one to one mapping, use the following command syntax:

    <POST> /mgmt/tm/ltm/nat -d '{"name":"<nat name>","originatingAddress":"<origin ip address>","trafficGroup":"/<partition>/<traffic group name>","translationAddress":"<translation ip address>","vlansEnabled":true,"vlans":["/<partition>/<vlan name>"]}'

    For example, to create a NAT one to one mapping of 10.10.10.10 to 10.10.111.11 on the MyVlan VLAN for traffic-group-1, enter the folowing command:

    <POST> /mgmt/tm/ltm/nat -d '{"name":"test_nat","originatingAddress":"10.10.10.10","trafficGroup":"/Common/traffic-group-1","translationAddress":"10.10.111.111","vlansEnabled":true,"vlans":["/Common/MyVlan"]}'

  • To delete a NAT, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/nat/<nat name>

    For example:

    <DELETE> /mgmt/tm/ltm/nat/test_nat

Creating, disabling, enabling, and deleting a node

Impact of procedure:  Using the following command syntax should not have a negative impact on your system.

  • To create a new node, use the following command syntax:

    <POST> /mgmt/tm/ltm/node/ -d '{"name":"<node name>","partition":"<partition name>","address":"<ip address>"}'

    For example, to create a new node named test_node on the Common partition, enter the following command:

    <POST> /mgmt/tm/ltm/node/ -d '{"name":"test_node","partition":"Common","address":"10.99.5.2"}'

  • To create a new node with ICMP monitoring enabled, use the following command syntax:

    <POST> /mgmt/tm/ltm/node/ -d '{"name":"<node name>","partition":"<partition name>","address":"<ip address>","monitor":"icmp"}'

    Note: The configuration object "monitor":"icmp" adds ICMP monitoring of the node.

    For example, to create a new node named test_node with ICMP monitoring enabled in the partition Common, enter the following command:

    <POST> /mgmt/tm/ltm/node/ -d '{"name":"test_node","partition":"Common","address":"10.99.5.2","monitor":"icmp"}'

  • To disable or enable an existing node, use the following command syntax

    <PATCH> /mgmt/tm/ltm/node/~<partition>~<node name>  -d '{"session":"<user-enabled or user-disabled>"}'

    For example, to disable the test_node node, enter the following command:

    <PATCH> /mgmt/tm/ltm/node/~Common~test_node -d '{"session":"user-disabled"}'

  • To delete an existing node, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/node/<node name>

    For example, to delete the test_node node, enter the following command:

    <DELETE> /mgmt/tm/ltm/node/test_node

Creating and deleting a monitor

You can create a new monitor profile based on an existing parent monitor profile as a template. All configuration settings not specifically configured as part of the REST command defaults to the settings of the parent profile.

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a new monitor based on a parent monitor, use the following command syntax:

    <POST> /mgmt/tm/ltm/monitor/http -d '{"name":"<monitor name>","partition":"<partition>","defaultsFrom":"/<partition>/<parent monitor name>","destination":"<destination ip address>.<port>","interval":"<interval value>","timeout":"<timeout value>","send":"<http send string>"}'

    For example, to create the HTTP monitor http_test based on the parent monitor /Common/http with a unique interval, timeout, and send string, enter the following command:

    <POST>/mgmt/tm/ltm/monitor/http -d '{"name":"http_test","partition":"Common","defaultsFrom":"/Common/http","destination":"*.*","interval":"11","timeout":"34","send":"GET /index.html\\r\\n"}'

  • To delete a monitor, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/monitor/http/<monitor name>

    Note: When deleting a configuration object that resides in a partition other than the default Common partition, use the ~<partition>~<object name> syntax.

    For example, if the monitor test_monitor resides in the partition ABC, enter the following command:

    <DELETE> /mgmt/tm/monitor/http/~ABC~test_monitor.

Creating, modifying, and deleting a pool

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a new pool using existing nodes, use the following command syntax:

    <POST> /mgmt/tm/ltm/pool/ -d '{"name":"<pool name>","partition":"<partition name>","monitor":"/<partition>/<monitor name>","members":"<node name>:<port>"}'

    For example, to create the pool test_pool with the http_test monitor and pool member test_node, enter the following command

    <POST> /mgmt/tm/ltm/pool/ -d '{"name":"test_pool","partition":"Common","monitor":"/Common/http_test","members":"test_node:80"}'

  • To create a new pool using new nodes, use the following command syntax:

    <POST> /mgmt/tm/ltm/pool/ -d '{"name":"<pool name>","partition":"<partition name>","monitor":"/<partition>/<monitor name>","members":[{"name":"<new node name:><port>","address":"<ip address of new node>"}],"members":[{"name":"<new node name>:<port>","address":"<ip address of new node>"}]}'

    For example, to create the pool test_pool with the default HTTP monitor and defining new nodes, enter the following command:

    <POST> /mgmt/tm/ltm/pool/ -d '{"name":"test_pool","partition":"Common","monitor":"/Common/http","members":[{"name":"fifty_five:80","address":"10.0.55.55"}],"members":[{"name":"fity_six:80","address":"10.0.56.56"}]}'

  • To add a pool member, use the following command syntax:

    <POST> /mgmt/tm/ltm/pool/<pool name>/members -d '{"name":"/<partition name>/<node name>:<port>"}'

    For example:

    <POST> /mgmt/tm/ltm/pool/test_pool/members -d '{"name":"/Common/abc_node:80"}'

  • To add multiple pool members, use the following command syntax:

    Note: The following command replaces all existing pool members.

    <PATCH> /mgmt/tm/ltm/pool/<pool name> -d '{"partition":"<partition>","members":[{"name":"<node name 1>:<port>"},{"name":"<node name 2>:<port>"}]}'

    For example, to replace the current pool members in pool test_pool with two nodes test_node_1 and test_node_2, enter the following command

    <PATCH> /mgmt/tm/ltm/pool/test_pool -d '{"partition":"Common","members":[{"name":"test_node_1:80"},{"name":"test_node_2:80"}]}'

  • To change the pool monitor, use the following command syntax:

    <PATCH> /mgmt/tm/ltm/pool/<pool name>/ -d '{"monitor":"/<partition>/<monitor name>"}'

    For example:

    <PATCH> /mgmt/tm/ltm/pool/test_pool/ -d '{"monitor":"/Common/tcp"}'

  • To delete a pool member, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/pool/<pool name>/members/<node name>:<port>

    For example:

    <DELETE> /mgmt/tm/ltm/pool/test_pool/members/abc_node:80

  • To delete a pool, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/pool/<pool name>

    For example:

    <DELETE>/mgmt/tm/ltm/pool/test_pool

  • To update properties on pool members, use the following command syntax:

    <PATCH> /mgmt/tm/ltm/pool/~<partition>~<pool name>?expandSubcollections=true -d '{ "name": "<pool name>", "membersReference": { "items": [ { "name": "<pool member name>:<port>", "<property>": <value>}<, include comma followed by a space if more poolmembers follow><additional poolmembers>]}}'

    Note: Include quotes around the value if it's a string such as enabled. Integers do not need quotes.

    For example:

    <PATCH> /mgmt/tm/ltm/pool/~Common~test_pool?expandSubcollections=true -d '{ "name": "test_pool", "membersReference": { "items": [ { "name": "172.16.1.110:80", "ratio": 15}, { "name": "172.16.1.111:80", "ratio": 10}]}}'

Disabling and enabling a pool member

Impact of procedure: Disabling a pool member eliminates the pool member for selection in the processing of new traffic.

To disable or enable a pool member a pool member, use the following command syntax:

<PATCH> /mgmt/tm/ltm/pool/<pool name>/members/~<partition>~<node name>:<port>/ -d '{"session":"<user-disabled or user-enabled>"}'

For example, to disable the pool member test_node:80 for test_pool, enter the following command:

<PATCH> /mgmt/tm/ltm/pool/test_pool_too/members/~Common~test_node:80/ -d '{"session":"user-disabled"}'

Creating and deleting an HTTP profile

You can create a new HTTP profile based on an existing parent HTTP profile as a template. All configuration setting not specifically configured as part of the REST command defaults to the settings of the parent profile.

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a new HTTP profile based on a parent HTTP profile, use the following command syntax:

    <POST> /mgmt/tm/ltm/profile/http -d '{"name":"<new profile name>","defaultsFrom":"/<partition>/<parent profile name>}'

    For example, to create a new HTTP profile based on the parent default HTTP profile with the X-Forwarded-For header insert enabled, enter the following command:

    <POST> /mgmt/tm/ltm/profile/http -d '{"name":"test_http","defaultsFrom":"/Common/http","insertXforwardedFor":"enabled"}'

  • To delete the HTTP profile, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/profile/http/<http profile name>

    For example:

    <DELETE> /mgmt/tm/ltm/profile/http/test_http

Creating, modifying, and deleting a Client SSL profile

To create a new Client SSL profile using existing certificates, keys, and certificate chain stored on the BIG-IP system, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a Client SSL profile, use the following command syntax:

    <POST> /mgmt/tm/ltm/profile/client-ssl  -d  '{"name":"<profile name>","key": "/<partition>/<key name>","cert": "/<partition>/<certificate name>","chain": "/<partition>/<certificate chain name>"}'

    For example, to create a Client SSL profile using the certificate, key, and certificate chain for example.com, enter the following command:

    <POST> /mgmt/tm/ltm/profile/client-ssl  -d  '{"name":"test_client_ssl","key": "/Common/example_com.key","cert": "/Common/example_com.crt","chain": "/Common/example_com.crt"}'

  • To modify Client SSL profile certificates, use the following command syntax:

    <PATCH> /mgmt/tm/ltm/profile/client-ssl/~<partition>~<client ssl profile name>  -d '{"key":"/<partition>/<key name>","cert":"/<partition>/<certificate name>","chain":"/<partition>/<certificate chain name>"}'

    For example, to modify the certificate, key, and certificate chain of the Client SSL profile test_client_ssl, enter the following command:

    <PATCH> /mgmt/tm/ltm/profile/client-ssl/~Common~test_client_ssl  -d '{"key":"/Common/Coffee.key","cert":"/Common/Coffee.crt","chain":"/Common/Coffee-CA.crt"}'

    Note: In the example command, only the SSL certificate and key are updated, and the previously configured CA certificate is not modified. When updating the profile, only the specific SSL object needs to be specified. For example, when updating the certificate when the certificate references the same key, or when updating the CA certificate of the profile.

  • To delete a Client SSL profile, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/profile/client-ssl/<client ssl profile name>

Creating and deleting a persistence profile

You can create a new persistence profile based on an existing parent persistence profile as the template. All configuration setting not specifically configured as part of the REST command defaults to the settings of the parent profile.

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To create a new persistence profile based on a parent profile, use the following command syntax:

    <POST> /mgmt/tm/ltm/persistence/cookie -d '{"name":"<profile name>","defaultsFrom":"/<partition>/<parent profile name>"}'

    For example, to create the new cookie persistence profile test_cookie with the cookie name set to TestCookie, enter the following command:

    <POST> /mgmt/tm/ltm/persistence/cookie -d '{"name":"test_cookie","defaultsFrom":"/Common/cookie","cookieName":"TestCookie"}'

  • To delete a persistence profile, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/persistence/cookie/<profile name>

    For example:

    <DELETE> /mgmt/tm/ltm/persistence/cookie/test_cookie

Creating and deleting a virtual server

Impact of procedure: The following commands creates a new virtual server and the virtual server destination address is exposed (ARP) to the VLAN(s) configured for the virtual server.

  • To create a new virtual server, use the following command syntax:

    Note: When creating a new virtual server, ensure that all supporting objects (for example, profiles, pools, SNATs) are created before you execute the REST command.

    <POST> /mgmt/tm/ltm/virtual  -d  '{"name":"<virtual server name>","destination":"<ip address>:<port>","ipProtocol":"tcp","profiles":"/Common/fastL4","sourceAddressTranslation":{"type":"automap"},"pool":"<pool name>"}'

    Note: Configuration settings that are not specifically configured as part of the REST command acquires the default setting. For example, when you create a virtual server and you do not set the source address, the default 0.0.0.0/0 applies. Additionally, when the VLAN and the Tunnel Traffic setting do not specify the VLANs and/or tunnels, all VLANs and tunnels are enabled by default.

    For example, to create a new test_vs virtual server configured with TCP LAN, WAN, HTTP, and Client SSL profiles, as well as SNAT automap and cookie persistence, enter the following command:

    <POST> /mgmt/tm/ltm/virtual  -d  '{"name":"test_vs","destination":"10.99.0.123:443","mask":"255.255.255.255","source":"0.0.0.0/0","profiles":[{"name":"tcp-wan-optimized","context":"clientside"},{"name":"tcp-lan-optimized","context":"serverside"}],"sourceAddressTranslation":{"type":"automap"},"pool":"test_pool","profiles":"test_http","profiles":"/Common/test_client_ssl","persist":"/Common/test_cookie"}'

  • To delete a virtual server, use the following command syntax:

    <DELETE> /mgmt/tm/ltm/virtual/<virtual server name>

    Note: When deleting a configuration object that resides in a partition other than the default Common partition, use the ~<partition>~<object name> syntax.

    For example if the virtual server my_test_vs resides in the partition ABC, enter the following command:

    <DELETE> /mgmt/tm/ltm/virtual/~ABC~my_test_vs

Disabling and enabling a virtual server

Impact of procedure: Virtual servers in the disabled state does not process traffic.

  • To disable a virtual server, use the following command syntax:

    <PATCH> /mgmt/tm/ltm/virtual/~<partition>~<virtual server name>  -d '{"disabled":true}'

    For example, to disable the test_vs virtual server, enter the following command:

    <PATCH> /mgmt/tm/ltm/virtual/~Common~test_vs  -d '{"disabled":true}'

  • To enable a virtual server, use the following command syntax:

    <PATCH> /mgmt/tm/ltm/virtual/~<partition>~<virtual server name>  -d '{<enabled>":true}'

    For example, to enable the test_vs virtual server, enter  the following command:

    <PATCH> /mgmt/tm/ltm/virtual/~Common~test_vs  -d '{"enabled":true}'

Creating an http responder irule

Impact of procedure: The following command creates a new irule that when added to virtual will respond via http.

  • To create the responder irule, use the following command syntax:

    <POST> mgmt/tm/ltm/rule/http_responder  -d  ''{"apiAnonymous": "when HTTP_REQUEST { \n\n      set content \"Normal up\"\n      HTTP::respond 200 content $content \n      unset content \n    }"}'

    Note: In order to be of use you would need to attach this irule to a virtual server.

    Example curl command to accomplish the above post: curl -k -u admin:admin "https://localhost/mgmt/tm/ltm/rule/http_responder" -H 'Content-Type: application/json' -X POST -d '{"apiAnonymous": "when HTTP_REQUEST { \n\n set content \"Normal up\"\n HTTP::respond 200 content $content \n unset content \n }"}'

Saving the configuration

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To save configuration changes using the iControl REST interface, use one of the following command syntaxes:

    To save the configuration changes to the default partition (Common), enter the following iControl REST interface command:

    <POST> /mgmt/tm/sys/config  -d '{"command":"save"}'

    To save the configuration for BIG-IP systems configured with multiple partitions (BIG-IP version 13.1.0 and later), enter the following iControl REST interface command:

    <POST> /mgmt/tm/sys/config  -d '{"command":"save","partitions":"all"}'

    For BIG-IP versions prior to 13.1.0, the specific partition must be declared when the partition is not the default partition (Common).

    For example, to save configuration changes made to the non-default partition with the name PRODUCTION, enter the following command:

    <POST> /mgmt/tm/sys/config  -d '{"command":"save","partition":"PRODUCTION"}'
