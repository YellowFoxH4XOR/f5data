Known Issue

This is the result of a known issue. When sending a response packet, if the ARX system needs to perform an ARP resolution, the initial packet sent after receiving the ARP reply will be sent using the VLAN tag of the source IP address instead of the VLAN tag of the VIP used for the clients initial request. As a result, in some routing environments the packet may be dropped by the upstream devices. When this issue occurs, the client may experience issues, such as  NFS RPC timeouts, and must retransmit the request. Retransmitted requests will succeed because the subsequent response packets sent after the destination MAC address is known are sent with the correct VLAN tag. This issue only occurs when the MAC address is unknown and ARP is required for the initial response.

F5 Product Development tracked this issue as ID 37892 and it was fixed in ARX 5.1.5. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in a hotfix available for ARX 5.1.0 and 5.0.6. To request the hotfix, contact F5 Technical Support and reference this article number and ID 37892.
