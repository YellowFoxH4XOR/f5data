K000161421: NGINX App Protect Failure – Enforcer Not Starting (Configuration Load Failure)

Type
Support Solution
Published
2026-05-26
Updated
2026-05-26
Applies to
  • NGINX Products
  • NGINX App Protect WAF: 5.6.0
Source
https://my.f5.com/manage/s/article/K000161421

Description

NGINX App Protect WAF may fail to start its enforcer process after a corrupted or incomplete installation. In this condition, NGINX Plus remains running, but nginx -t fails with configuration_load_failure and Timeout waiting for enforcer. The /opt/app_protect/bd_config/ directory may be empty or missing expected generated content, and NGINX App Protect WAF logs may show No such file or directory errors under the bd_config path.




Environment

Relevant environmental factors specific to the topic


  • NGINX App Protect WAF 5.6.0
  • NGINX Plus 1.29.3 (nginx-plus-r36-p3)
  • WAF engine version 11.644.1
  • Ubuntu 24.04.4 LTS (Noble Numbat)
  • Linux deployments where NGINX App Protect WAF files under /opt/app_protect/ are owned by the nginx user rather than UID 101
  • Environments where NGINX Plus is running normally but the NGINX App Protect WAF enforcer process is not running



Cause

Corrupted or incomplete NGINX App Protect WAF installation prevented the enforcer process from starting and caused configuration load failures.



Answer/Recommended Actions


1.Verify the failure symptoms:

    • Run nginx -t and confirm output similar to:
      • configuration_load_failure
      • Timeout waiting for enforcer
    • Check whether the enforcer process is absent while NGINX Plus is still running.
    • Review /var/log/app_protect/ for configuration load failures or No such file or directory messages referencing /opt/app_protect/bd_config/.

2.Check the NGINX App Protect WAF directory state:

    • Verify whether /opt/app_protect/bd_config/ exists and contains expected generated content.
    • If the directory is empty or key NGINX App Protect WAF content appears missing, suspect an incomplete or corrupted installation.


3.Distinguish this issue from other configuration load failures:

    • If nginx -t reports a specific missing policy file such as Failed to read ... no such file or directory, troubleshoot the missing policy file path separately.
    • If the issue is related to SELinux-related or SELinux permissions, follow the appropriate permission troubleshooting guidance instead of treating it as installation corruption.

4.Recover the system:

    • Reinstall NGINX App Protect WAF to restore missing or corrupted files and processes.
    • After reinstalling, verify:
      • the enforcer process is running
      • /opt/app_protect/bd_config/ is populated as expected
      • nginx -t completes successfully
    • Continue monitoring the system after recovery.






Additional Information

This issue can present similarly to other configuration_load_failure conditions, but the distinguishing indicators are an absent enforcer process, empty or incomplete /opt/app_protect/bd_config/ content, and recovery after reinstalling NGINX App Protect WAF.
