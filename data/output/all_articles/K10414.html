Known Issue

This is the result of a known issue. If one of the FirePass power supplies stops providing power to the controller, but the second power supply continues to provide power, the Device Management : Monitoring : System Health page correctly displays an alarm for the affected power supply. For example:

Power Supply 2 Status  ALARM

However, depending on the logging levels configured on the Device Management : Maintenance : Logs page, one of the following two isues may occur:

  • The System Logs report fails to report the alarm event
  • The System Logs report reports the alarm event 30 to 35 minutes after the event occurs

A power supply alarm log message appears similar to the following example:

Jun 11 13:03:30 firepass firepass[23901]: [-] Power Supply 2 Status: : ALARM

F5 Networks Product Development is tracking this issue as CR126393.

Workaround

You can work around this issue by configuring the Information logging level for the Maintenance, Miscellaneous, and SNMP logging events. To do so, perform the following procedure:

  1. Logon to the FirePass Administrative Console.
     
  2. Navigate to the Device Management : Maintenance : Logs page.
     
  3. In the Maintenance menu, select Information.
     
  4. In the Miscellaneous menu, select Information.
     
  5. In the SNMP menu, select Information.
     
  6. Click the Apply Changes button.

Important: Power supply events will not be logged if you select the Emergency or Notice logging levels in Steps 3 through 5. If you select the Warning or Alert logging levels, power supply events will be logged 30 to 35 minutes after the event occurs.
