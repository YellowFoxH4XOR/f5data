What Happened?

You want to know how the authentication happens inside our console

Environment

  • F5® Distributed Cloud (XC) Console

Resolution/Answer

  • F5 Distributed Cloud (F5XC) implements the zero trust security framework for services and applications in the Console
  • The Console generates an X.509 certificate-based identity associated with the service or application which is provided by the F5XC Identity Authority (IA), a Certificate Authority which is part of the F5XC Application Identity Service. This certificate is provided to every application instance and is globally unique; this certificate is also automatically rotated.
  • When you deploy an application, during the Kubernetes POD creation, a Security side-car (called Wingman) is inserted. Wingman requests a certificate to the Identity Authority (IA) for the POD instance and the Identity Authority (IA) provides an instance certificate to Wingman which resides in Wingman’s memory and is valid for the lifetime of the instance. This certificate is used by the POD for mTLS encryption of communication between the services and applications in the Console.
  • If Applications require secrets to talk to database systems or other systems, F5XC provides a secret management service called Blindfold. Blindfold uses advanced cryptographic techniques to keep secrets hidden from all systems, including F5XC, except for the owner of the secret. Blindfold works in conjunction with Wingman; Wingman unseals secrets based on pre-defined policies.
  • The most notable feature of the Blindfold system is that it allows customers to encrypt their secrets while being completely offline and the secret is distributed, can be stored with the workload, and uploaded to the registry. This ensures that the F5XC centralized control plane never gets access to the secret in clear and the secret is only available in the runtime memory of the Pod for the duration of the access.
