K90101303: Aspen Mesh upgrade may fail and not allowing clean reinstall

Type
Support Solution
Published
2022-03-29
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K90101303

Description

Aspen Mesh upgrade may fail, and unable to successfully rollback to a working version, even after manual reinstall due to stale objects.

Environment
  • OpenShift container platform: 3.x, 4.x
  • Aspen Mesh: 1.9.8-am1

Cause

Stale objects from failed upgrade not allowing a clean reinstall.

Recommended Actions

Follow the Aspen Mesh Uninstall Guide and make sure following objects are not present.

  1. Aspen Mesh executes below jobs during the upgrade process, in case of failure it is possible they become stale and will need to be removed manually:

    $ helm get all istiod -n istio-system | grep 'kind: Job' -A2

    kind: Job
    metadata:
      name: configure-aspen-mesh-controlplane
    --
    kind: Job
    metadata:
      name: configure-aspen-mesh-packet-inspector
    --
    kind: Job
    metadata:
      name: aspen-mesh-jaeger-cassandra-schema


    % kubectl get jobs -n istio-system
    NAME                                 COMPLETIONS   DURATION   AGE
    aspen-mesh-jaeger-cassandra-schema   1/1           2m35s      55m
    configure-aspen-mesh-controlplane    1/1           2s         94s

    You can delete these resources using the command syntax below:

    $ kubectl delete job <name> -n istio-system

  2. Make sure no istio validatingwebhookconfiguration or mutatingwebhookconfiguration objects are present in the cluster:

    $ kubectl get mutatingwebhookconfiguration
    NAME                     WEBHOOKS   AGE
    istio-sidecar-injector   4          2m13s

    $ kubectl get validatingwebhookconfiguration
    NAME                           WEBHOOKS   AGE
    aspen-mesh-controlplane        2          2m25s
    istio-validator-istio-system   2          2m29s

    You can delete them using the command syntax below:

    $ kubectl delete mutatingwebhookconfiguration <name> 

    $ kubectl delete validatingwebhookconfiguration <name>  

  3. Make sure no envoyfilter objects are listed in istio-system namespace:

    % kubectl get envoyfilter -n istio-system
    No resources found in istio-system namespace.

    To delete remaining envoyfilters, use the following command syntax:

    $ kubectl delete envoyfilter <name> -n istio-system
