K000147405: Why does my Service policy deny traffic source from a pod to load balancer?

Type
Support Solution
Published
2024-11-08
Updated
2025-02-21
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Apps
  • F5 Distributed Cloud Multi-Cloud App Connect
Source
https://my.f5.com/manage/s/article/K000147405

Description

  • An application pod on the F5® Distributed Cloud Services node accessing another service via the load balancer
  • Service policy is applied to the load balancer (LB)
  • Traffic is blocked and results in a 403 error message from volt-adc, etc.

Environment

  • An application running on the F5® Distributed Cloud Services node

Answer/Recommended Actions

You need to consider the relation between the source pod and load balancer and configure your service policy accordingly.

  • If the source pod and the load balancer are in the same node, you have to use the Client selector (label) instead of IP
  • If the load balancer is located in a different Customer Edge (CE) or a Regional Edge (RE), think about how the packet is reaching the load balancer
    • Public IP: Configure source IP by considering NAT, Proxy, etc  (Most of the cases)
    • Client selector
  • How to configure
    • To use the Client label for service policy, click Custom rule -> "Config Rule Specification" -> For "client selection" select "Group of Clients by Label Selector”. 
    • Check How to secure application on namespace level

Cause

  • Service policy is not configured correctly
  • Traffic is blocked by the "default-deny" rule
