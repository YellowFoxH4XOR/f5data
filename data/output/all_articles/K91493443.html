K91493443: Network Access - Microsoft Teams application not honoring split tunneling exclusion address space

Type
Support Solution
Published
2020-03-20
Updated
2023-02-21
Applies to
  • BIG-IP APM: 16.X.X
Source
https://my.f5.com/manage/s/article/K91493443



Description

Microsoft Teams application traffic continues to be processed through the network access VPN tunnel regardless of the existence of an exclusions list entry pertaining to the Teams application network address space range. Reviewing the routing table on the client will show that the destination IPs for this traffic should be routed out the local interface, but reviewing firewall logs or taking packet captures will still show this traffic passing through the VPN tunnel.

Environment

  • APM Network Access 12.x-15.x
  • Split Tunneling
  • Microsoft Teams application running on client workstation

Cause

Microsoft Teams uses an application-specific routing behavior that can bypass the changes made by Big-IP Edge Client to the client system's routing table.

Recommended Actions

Block the lease pool IP address assignment allocated to VPN Clients from egressing through the enterprise Firewall over to the Microsoft Teams network address space. This will force Teams to reselect the egress interface rather than use the VPN tunnel interface.

Display BIG-IP APM Network Access lease pool assignment. To do so, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Click Access.
  3. Click Connectivity / VPN : Network Access (VPN) : IPV4 / IPV6 Lease Pools.
  4. Click the name of the Least Pool resource objects for a listing of IP assignment.
    Additional Information
    Additional information pertaining to Microsoft Teams network address space range:
    Skype for Business Online and Microsoft Teams

    Starting from APM 16.1.0, APM admins can use address space to automatically create necessary address space and periodically keep them up to date by fetching them from vendor specified APIs.
