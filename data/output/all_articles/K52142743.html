Known Issue

The BIG-IP system applies the DNS command DNS::question set options to the packet but not to the already-parsed dns_msg.

This issue occurs when all of the following conditions are met:

  • You have enabled the DNS transparent cache.
  • You are using an iRule similar to the following example:

    when DNS_REQUEST {
       DNS::question type AAAA
    }

Impact

When the packet goes to the pool, the system reverts the type.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • For certain types of iRules, when you use the DNS command DNS::question for type AAAA, when the DNS transparent cache is involved in the filter, the type can be reverted.

Workaround

To work around this issue, you can enable global server load balancing (GSLB) or DNS Express on the profile. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Delivery > Profiles > DNS.
  3. Select the DNS profile that the system is using.
  4. Enable either GSLB or DNS Express.
  5. To save the change, select Update.
