K10117: The external monitor template allows the template field names to be used as variable names

Published

Status

Applies to

  • BIG-IP LTM: 10.0.1, 10.0.0

Known Issue

This is the result of a known issue. The BIG-IP LTM external monitor template allows the configuration of variable Name/Value pairs using the same names as the fields in the monitor template. As a result, the monitor may not function as expected, causing the bigpipe command to dump core. Only fields that contain a single value evoke this behavior.

A custom monitor based on the external monitor template appears similar to the following example:

monitor linux_1_min_load_yellownet {
defaults from external
interval 30
timeout 91
dest *:*
check until up disable
ignore down response disable
enable
none
partition Common
args "$h $p"
run "linux_1_minute_load_ratio.pl"
instance none
}

If a variable is created that uses the name of a field that typically contains a single unquoted value, such as interval, timeout, dest, partition, or instance, the variable value will overwrite the configured value for the field with the same name. As a result, using the bigpipe command with this configuration will cause a segmentation fault and the bigpipe command will core.

For example, you can configure a monitor to use the following variable Name/Value pair:

timeout 300

You can attempt to list the monitor by typing the following bigpipe command:

bigpipe monitor linux_1_min_load_yellownet list all

However, since the monitor is configured with a variable that overwrites a monitor field name, a segmentation fault causes the bigpipe command to core and the following error message is displayed:

Segmentation fault (core dumped)

If a variable is created that uses the name of a field that typically contains a quoted string, such as args or run, the variable values will overwrite the configured value for the field with the same name. As a result, the monitor will not run as expected.

For example, you can configure a monitor to use the following variable Name/Value pair:

run this is not the script you are looking for

The configuration saves without error, and the resulting monitor may be listed by typing the following command:

bigpipe monitor linux_1_min_load_yellownet list all

The monitor configuration is successfully displayed, and appears similar to the following example:

monitor linux_1_min_load_yellownet {
defaults from external
interval 30
timeout 91
dest *:*
check until up disable
ignore down response disable
enable
none
partition Common
args "$h $p"
run "this is not the script you are looking for"
instance none
}

The value of the run field (labeled External Program in the Configuration utility), which originally contained the name of the external script the monitor should run, has been overwritten by the value of the run variable. When the configuration is saved then loaded from the command line, the following error message is displayed:

BIGpipe monitor parameter modification error:
01070062:3: External monitor program this is not the script you are looking for not found.

This error message indicates that the monitor attempted to run a script whose name matched the variable value, rather than the name configured in the External Program field.

F5 Networks Product Development is tracking this issue as CR119045.

Workaround

You can work around this issue by avoiding the use of monitor template field names as variable names.
