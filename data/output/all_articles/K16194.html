Known Issue

The bigip health monitor incorrectly marks down virtual servers with a duplicate ltm-name.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP GTM system running a software version between 11.3.0 and 11.6.0 HF4.
  • You have a BIG-IP LTM system running a software version prior to 11.3.0.
  • From the BIG-IP GTM system, you are monitoring the BIG-IP LTM virtual servers using the bigip monitor.
  • A BIG-IP GTM server object has two BIG-IP LTM virtual servers with the same ltm-name. For example, the ltm-name one.test.com_webservers occurs twice in the following BIG-IP GTM server object:

    gtm server /Common/local_server {
    addresses {
    192.168.1.100 {
    device-name local_server
    }
    }
    public_web {
    destination 99.88.77.66:443
    ltm-name /Common/one.test.com_webservers
    translation-address 192.168.1.200
    translation-port 443
    }
    private_web {
    destination 192.168.1.200:443
    ltm-name /Common/one.test.com_webservers
    }

Impact

Virtual servers may be unavailable for wide IP load balancing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Virtual server status is available on BIG-IP LTM, but offline on BIG-IP GTM.
  • When viewing the virtual server status on BIG-IP GTM, you observe a no reply from big3d: timed out message.

    For example:

    ------------------------------------------
    | Gtm::Virtual Server: local_server
    ------------------------------------------
    | Status
    | Availability : offline
    | State : enabled
    | Reason : Monitor /Common/bigip from /Common/one.test.com_webservers : no reply from big3d: timed out
    | Destination : 192.168.1.200:443

Workaround

To work around this issue on the BIG-IP GTM system, you can choose a monitor other than bigip to monitor the affected virtual server. To work around this issue on the BIG-IP LTM system, you can replace big3d with an 11.2.1 big3d if that version exists in the /usr/sbin/big3d directory. To do so, perform the following procedure:

Impact of workaround: The following procedure may affect health status for virtual servers monitored on the remote BIG-IP GTM system during the period that you restart the big3d process.

  1. Secure a copy of the 11.2.1 big3d to the /shared/tmp directory on the BIG-IP LTM system.
  2. Log in to the BIG-IP LTM command line.
  3. To verify that the current BIG-IP LTM big3d version is 11.5.1 or later, type the following command:

    /shared/bin/big3d -v
    /shared/bin/big3d version big3d Version 11.5.1.0.0.110 for linux
  4. To replace the current 11.5.1 or later big3d with the 11.2.1 big3d, type the following command:

    bigstart stop big3d && cp -a /shared/tmp/big3d /shared/bin/ && bigstart start big3d
  5. To verify your changes, type the following command:

    /shared/bin/big3d -v
    /shared/bin/big3d version big3d Version 11.2.1.797.0 for linux
