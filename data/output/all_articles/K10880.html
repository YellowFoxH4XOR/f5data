Known Issue

This is the result of a known issue. On VIPRION systems with more than one blade, the Detect ConfigSync Status feature does not function properly. Immediately after a ConfigSync operation is performed, the Configuration utility of the VIPRION system displays ConfigSync: OK. However, the next time the VIPRION system compares its configuration with that of its peer, the Configuration utility displays Sync Recommended, even if the configuration was not changed on either system. This issue usually presents itself within minutes from the last ConfigSync operation.

F5 Networks Product Development tracked this issue as CR89094 and CR98844 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You may be able to determine whether the VIPRION systems are running the same configuration by comparing the timestamp of the bigip.conf file on one system to that of the same file on the peer system. If the timestamps match, usually this is indication that the two files are identical. You can perform this test by executing the ls -lh /config/bigip.conf command on both VIPRION systems.

For example, the following output shows that the bigip.conf file has the same timestamp on both systems:

VIPRION 1:
# ls -lh /config/bigip.conf
-rw-r--r-- 1 root root 720 Dec 18 13:21 /config/bigip.conf

VIPRION 2:
# ls -lh /config/bigip.conf
-rw-r--r-- 1 root apache 720 Dec 18 13:21 /config/bigip.conf
