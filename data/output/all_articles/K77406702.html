Topic

You should consider using these procedures under the following condition:

  • You want to configure an Simple Network Management (SNMP) trap destination using the TMOS Shell (tmsh).

Description

SNMP traps are small alert messages which the BIG-IP system sends to an SNMP management station, or trap destination, when an important event occurs. Because SNMP traps are smaller User Datagram Protocol (UDP) messages, they help to reduce network traffic when the system manages and monitors a large number of remote devices. The following table lists a few examples of the many BIG-IP system SNMP trap messages.

SNMP trap alert
Cpu 1: temperature (80) is too high
Cpu 1: fan speed (0) is too low
Standby
Active
Pool /Common/pool_one member /Common/192.168.10.1:80 monitor status down
Pool /Common/pool_one member /Common/192.168.10.1:80 monitor status up

You can find the full list of default BIG-IP SNMP traps in the /etc/alertd/alert.conf file. You must not edit the alert.conf file. To find out how to disable SNMP traps or to create custom SNMP traps, refer to the following articles:

  • K11234: Disabling default SNMP traps
  • K3727: Configuring custom SNMP traps

To receive SNMP traps from the BIG-IP system, you must configure one or more SNMP trap destinations. The trap destinations can use SNMP v1, v2c, or v3. You can configure only SNMP v3 to use authentication and encryption. This article uses very basic options to configure the SNMP trap destination. For a full list of SNMP configuration options, run the tmsh help sys snmp command from the BIG-IP Advanced Shell (bash). To configure and test SNMP trap delivery, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have bash shell and tmsh access to the BIG-IP system.
  • You have the SNMP management station's IP address and agent information.

Procedures

  • Configure an SNMP v1 or v2c trap destination
  • Configure an SNMP v3 trap destination
  • Test SNMP trap delivery

Configure an SNMP v1 or v2c trap destination

After you have obtained the SNMP trap destination IP address, service port, and community string, you can perform the following procedure to configure an SNMP v1 or 2c trap destination:

Note: The use of destination addresses (host) within non-default route domains is not supported.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To configure a DNS name server, use the following command syntax:

    Note: This step is only necessary if you prefer to use a fully qualified domain name (FQDN) instead of an IP address for the SNMP trap destination.

    modify /sys dns name-servers add { <IP address> }

    For example, to configure the system to use a DNS name server with the IP address 192.168.10.200, enter the following command:

    modify /sys dns name-servers add { 192.168.10.200 }

           Important: Field <IP address> does not support CIDR notation, avoid using any subnet mask portion.

  1. To add an SNMP v1 or v2c trap destination, use the following command syntax:

    Note: The object_name represent the SNMP trap destination object in the BIG-IP configuration. Change the object_name to add additional SNMP trap destinations.

    modify /sys snmp traps add { <object_name> { version <1 or 2c> community <string> host <IP address or hostname> port <service Port> }}

    For example, to add an SNMP v2c trap destination using host name snmp.example.com, service port 162, and network type of other, enter the following command:

    modify /sys snmp traps add { mytrap { version 2c community public host snmp.example.com port 162 }}

    Important: Field <IP address or hostname> does not support CIDR notation, avoid using any subnet mask portion.
  2. To save the configuration, enter the following command:

    save /sys config

Configure an SNMP v3 trap destination

SNMP v3 provides additional security improvements such as authentication and encryption. The BIG-IP system configuration supports the following two SNMP v3 modes:

Note: The no-auth-no-privacy option is not supported.

ModeDescription
Auth, No PrivacySends SNMP traps using authentication (auth) but no encryption (privacy). When you choose this mode, you must provide the following authentication information: Security Name, Authentication Protocol, and Authentication Password
Auth and PrivacySends SNMP traps using authentication (auth) or encryption (privacy) or both. When you choose this mode, you must provide the following authentication and encryption information: Security Name, Authentication Protocol, Authentication Password, Privacy Protocol, and Privacy Password

After you obtain the SNMP management station authentication and encryption information, you can use the following procedure to configure an SNMP v3 trap destination:

Note: If you require the use of a custom engine ID, refer to K15681: Customizing the SNMP v3 engineID for information about obtaining and modifying the BIG-IP system Engine ID.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To obtain the BIG-IP system engine ID, enter the following command:

    cat /config/net-snmp/snmpd.conf | grep oldEngineID

    The command output appears similar to the following example:

    oldEngineID 0x80001f8880c6b6067fdacfb558

  2. Log in to tmsh by entering the following command:

    tmsh

  3. To configure a DNS name server, use the following command syntax:

    Note: This step is only necessary if you prefer to use an FQDN instead of an IP address for the SNMP trap destination.

    modify /sys dns name-servers add { <IP address> }

    For example, to configure the system to use a DNS name server with the IP address 192.168.10.200, enter the following command:

    modify /sys dns name-servers add { 192.168.10.200 }

    Important: Field <IP address> does not support CIDR notation, avoid using any subnet mask portion.
  4. To add an SNMP v3 trap destination using authentication (auth) only, use the following command syntax:

    Note: The object_name represents the SNMP trap destination object in the BIG-IP configuration. Change the object_name to add additional SNMP trap destinations; be aware that the use of destination addresses (host) within non-default route domains is not supported.

    modify /sys snmp traps add { <object_name> { version 3 host <IP address or hostname> port <service port> security-level auth-no-privacy security-name <username>  auth-protocol <md5 or sha> auth-password <password> engine-id <engineID> }}

    For example, to add an SNMP v3 trap destination using object name snmp3, host name snmp.example.com, service port 162, security username snmpuser1, authentication protocol SHA, and authentication password abc123XYZ, enter the following command:

    modify /sys snmp traps add { snmp3 { version 3 host snmp.example.com port 162 security-level auth-no-privacy security-name snmpuser1  auth-protocol sha auth-password abc123XYZ engine-id 0x80001f8880c6b6067fdacfb558}}

    Important: Field <IP address or hostname> does not support CIDR notation, avoid using any subnet mask portion.
  5. To add an SNMP v3 trap destination using authentication (auth) and encryption (privacy), use the following command syntax:

    Note: The object_name represents the SNMP trap destination object in the BIG-IP configuration. Change the object_name to add additional SNMP trap destinations.

    modify /sys snmp traps add { <object_name> { version 3 host <IP address or hostname> port <service port> security-level auth-privacy security-name <username>  auth-protocol <md5 or sha> auth-password <password> privacy-protocol <aes or des> privacy-password <password> engine-id <engineID}}

    For example, to add an SNMP v3 trap destination using object name snmp3, host name snmp.example.com, service port 162, security username snmpuser1, authentication protocol SHA, authentication password abc123XYZ, encryption type aes, and encryption password abc123XYZ, enter the following command:

    modify /sys snmp traps add { snmp3 { version 3 host snmp.example.com port 162 security-level auth-privacy security-name snmpuser1  auth-protocol sha auth-password abc123XYZ privacy-protocol aes privacy-password abc123XYZ engine-id 0x80001f8880c6b6067fdacfb558}}

    Important: Field <IP address or hostname> does not support CIDR notation, avoid using any subnet mask portion.
  6. To save the configuration, enter the following command:

    save /sys config

Test SNMP trap delivery

You can use the following procedure to generate log messages that send BIG-IP system SNMP trap alerts to the configured SNMP trap destination:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. You can use the following command syntax to generate a log message in the /var/log/ltm file and trigger an alert email:

    logger -p local0.notice "<logged error message>"

    For example, you can copy and paste the following commands to test the example SNMP trap alerts mentioned in article introduction:

    Note: You can copy and paste all together or one at a time. You do not need to modify these commands to test trap delivery.

    logger -p local0.notice "010d0001:0: Cpu 1: temperature (80) is too high."
    logger -p local0.notice "010d0002:2: Cpu 1: fan speed (0) is too low."
    logger -p local0.notice "010c0019:5: Active."
    logger -p local0.notice "010c0018:5: Standby."
    logger -p local0.notice "01070638:5: Pool /Common/pool_one member /Common/192.168.10.1:80 monitor status down."
    logger -p local0.notice "01070727:5: Pool /Common/me member /Common/192.168.10.1:80 monitor status up."

  3. You should receive new SNMP trap alerts from the BIG-IP system on your SNMP trap destination.
