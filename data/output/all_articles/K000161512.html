K000161512: Intermittent packet loss caused by transparent VLAN Group with default gateway configured in same subnet

Type
Support Solution
Published
2026-06-02
Updated
2026-06-02
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000161512

Description

Intermittent packet loss and ping failures can occur in a BIG-IP LTM VLAN Group deployment when the VLAN Group is configured in transparent mode and the BIG-IP default gateway is set to an IP address in the same subnet as the VLAN Group. In this condition, BIG-IP may proxy ARP for the gateway IP, resulting in duplicated ARP broadcasts, MAC flapping on the adjacent L3 switch, incomplete ARP resolution, and non-deterministic forwarding behavior. Symptoms can include approximately 50% ping success between hosts in the same subnet, stable communication when the BIG-IP default gateway is removed, and stable communication when the link between the BIG-IP and L3 switch is disconnected.

Environment

  • BIG-IP LTM

  • VLAN Group deployment with two VLANs grouped together

  • VLAN Group mode set to transparent

  • BIG-IP default gateway configured to an L3 switch IP in the same subnet as the VLAN Group

  • Traffic bridged through the VLAN Group between EX VLAN and IN VLAN

Cause

Transparent VLAN Group mode with the BIG-IP default gateway configured in the same subnet as the VLAN Group can cause BIG-IP to proxy ARP for the gateway IP. This can duplicate ARP broadcasts across VLAN Group members, trigger MAC flapping on the adjacent L3 switch, leave ARP entries incomplete, and create non-deterministic forwarding paths that result in intermittent packet loss.

Answer/Recommended Actions

  • Change the VLAN Group mode from transparent to translucent:
    tmsh modify net vlan-group /Common/VG mode translucent

  • Avoid configuring the BIG-IP default gateway to an IP address in the same subnet as the VLAN Group when using transparent mode.

  • If the deployment requires a same-subnet design, validate behavior in translucent mode rather than transparent mode.

  • Use the following commands to validate the condition during reproduction:
    tmsh show net arp
    tmsh show net fdb
    tcpdump -s0 -nni 0.0:nnn arp or icmp -w /var/tmp/test.pcap -vv

  • Look for repeated ARP requests, incomplete ARP entries for the gateway or peer IPs, and MAC learning instability on the VLAN Group path.

  • Note that proxy-excludes may not resolve this scenario if the underlying issue is broadcast duplication and forwarding instability caused by the transparent VLAN Group design.

  • Review the Layer 2 and Layer 3 topology to prevent abnormal traffic paths and MAC flapping.

Additional Information

  • In the investigated scenario, communication became stable when either of the following changes was made:

    • The BIG-IP default gateway was removed

    • The VLAN Group mode was changed from transparent to translucent

  • Testing confirmed that the issue did not reproduce in translucent mode, including when the default gateway remained configured.

  • Observed diagnostics included persistent incomplete ARP entries and excessive ARP broadcasts reflected across VLAN Group member VLANs.

  • Related bug references mentioned during investigation:

    • Bug ID 1494137

    • Bug ID 677525

  • These bug references were noted as fixed in 17.5.x and were not identified as the root cause of this issue.
