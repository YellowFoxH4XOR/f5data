Description

How to upgrade the firmware on an F5 rseries appliance running F5OSA version 1-1.5 as a workaround for bug 1211025 

 

Environment

  • F5OS-A
  • v1.0.1 - v1.5.x
  • rSeries
  • Upgrade
     

Cause

Bug ID 1211025 


Recommended Actions

The recommended action for Bug ID 1211025 is to redo the firmware update that was interrupted by the restart of a daemon during the initial upgrade. The process below walks through that upgrade. 

1. Have Docker show the status of the firmware to confirm the need for this workaround

docker exec platform-fwu psf call GET:firmware


Example output:

Error: 1) LOPd Communication Error: LOP USB Device is not present at either: /dev/ttyAOM or /dev/ttyACM0
Error: 2) Error returned from GET:firmware/lop/app, componentType: lop, componentSubtype: app, componentLocation:
Error: 3) LOPd Communication Error: LOP USB Device is not present at either: /dev/ttyAOM or /dev/ttyACM0
Error: 4) Error returned from GET:firmware/lcd/bootloader, componentType: lcd, componentSubtype: bootloader, componentLocation:
Error: 5) unable to get LCD Bootloader version

Error: 7) Error returned from GET:firmware/lcd/app, componentType: lcd, componentSubtype: app, componentLocation:
Error: 8) unable to get LCD App version

2. List all devices that have firmware that needs updating

docker exec -it platform-fwu dfu-util --l

3. Verify what firmware exists on the box: 

docker exec platform-fwu ls /usr/lib/firmware/ | grep ^lop-vanquish

4. Take the serial number that matches the hex value : f5f5:df11 and use it in the next command along with the version of firmware to upgrade to: 

docker exec -it platform-fwu dfu-util -S 384B356C3431 -D /usr/lib/firmware/lop-vanquish-v1.00.239.0.1.dfu


5. Run the firmware check command again to confirm the firmware update has taken​​​​​​​

docker exec platform-fwu psf call GET:firmware

 

6. Reboot the appliance and recheck to verify the issue is resolved.
