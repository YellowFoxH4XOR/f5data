K000150888: performStaging field in ASM REST API has no effect when signature staging is disabled

Type
Support Solution
Published
2025-04-16
Updated
2025-04-16
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000150888

Description

When managing attack signatures in F5 BIG-IP ASM using the REST API, it may appear that individual signatures can be configured to enter staging using the "performStaging" parameter. However, this setting is ineffective unless signature staging is enabled at the policy level under Learning and Blocking Settings. This behavior can lead to confusion, especially when scripting automated configuration or relying on REST output for verification.

Environment

Product: BIG-IP ASM

Cause

The root of the issue lies in how BIG-IP ASM evaluates the policy-level configuration for signature staging. The performStaging field can technically be set to true on individual signatures via REST API. However, this flag is only meaningful when the global policy setting signatureStaging is set to true. If this global flag is false, staging is entirely disabled for the policy—even if performStaging is true for specific signatures.

Recommended Actions

Additionally the staging status for particular signatures is only reflected in the GUI when Enable Signature Staging is checked, which allows individual signatures to be staged.

However, once "Enable Signature Staging" is unchecked, the staging button disappears from the GUI, and the performStaging parameter becomes irrelevant—since staging is effectively disabled at the policy level.

Additional Information

Relevant REST endpoint for policy signature global staging:

/mgmt/tm/asm/policies/<policy_id>/signature-settings

Relevant REST endpoint for individual signatures:

/mgmt/tm/asm/policies/<policy_id>/signatures/<signature_id>
