K67111200: Unparsable authorization header value violations after upgrade

Type
Support Solution
Published
2021-05-12
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.0.X, 16.0.0, 16.0.1, 13.1.4, 14.1.4, 15.1.3
Source
https://my.f5.com/manage/s/article/K67111200

Description

After the software upgrade Unparsable authorization header value violations occur:

Violation Details
HTTP protocol compliance failed [1]
HTTP Validation
Unparsable request content
Details
Unparsable authorization header value

Environment

  • ASM provisioned
  • Running TMOS versions 13.1.4, 14.1.4.2, 15.1.3, 15.1.3.1, 16.0.0, 16.0.1, 16.0.1.1
  • The Unparsable request content violation is enabled in the security policy
  • The requests contain the Authorization header, except Basic type. For example:
    Authorization: Bearer <token>
    Authorization: Negotiate <token>

Cause

Bug ID 1017645

Recommended Actions

The issue is fixed from versions 13.1.4.1, 14.1.4.3, 15.1.4, 16.0.1.2, 16.1.0.

To work around this issue you can follow one of the following suggestions:

Disable the Unparsable request content violation

You may disable the Unparsable request content violation in the affected security policies.

Impact of workaround: The BIG-IP will no longer trigger violations for any unparseable content, not specifically limited to Authorization headers.

Enable the 'ignore_authorization_header_decode_failure' internal parameter

Consider enabling this internal parameter to ignore only failures to decode authorization headers, leaving the Unparsable request content violation enabled in the policy.

Impact of workaround: Performing the following procedure forces the BIG-IP system offline for a short period of time. F5 recommends that you perform this procedure during a maintenance window, this must be done on each device in the cluster.

  1. Connect to the CLI

  2. Enable ignore_authorization_header_decode_failure

    /usr/share/ts/bin/add_del_internal add ignore_authorization_header_decode_failure 1

  3. Restart ASM:

    bigstart restart asm
