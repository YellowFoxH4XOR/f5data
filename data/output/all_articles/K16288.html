Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file after a configuration change occurs on a suspended iRule.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a universal persistence profile that contains an iRule.
  • The affected iRule contains a suspending command (for example, the persist command).
  • A configuration change occurs on the iRule that is used by the universal persistence profile.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restarting, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H512717 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP system sends a SIGFPE signal to the TMM, causing the system to produce a core file.
  • You observe a TMM core file in the /shared/core directory.
  • The BIG-IP system unexpectedly fails over to another system in the device group.

Workaround

To work around this issue, you can modify the configuration by assigning the affected iRule to the virtual server instead of assigning it to the universal persistence profile.
