K7924: When the Global Availability load balancing mode is configured for a wide IP pool, the BIG-IP GTM may select the incorrect virtual server for load balancing

Known Issue

This is the result of a known issue. When the Global Availability load balancing mode is configured for a wide IP pool, the BIG-IP GTM selects virtual servers from the pool in the order in which they are listed. When the BIG-IP GTM receives a request, the system starts at the top of the list and sends the connection to the first available virtual server in the list. When the current virtual server is unavailable, the BIG-IP GTM moves to the next virtual server in the list.

When the Global Availability load balancing mode is configured for a wide IP pool, the BIG-IP GTM may not select virtual servers in the order in which they are listed in the pool. As a result, the BIG-IP GTM may select a virtual server with a lower priority for load balancing instead of a virtual server with a higher priority.

F5 Product Development tracked this issue as CR79808, and it was fixed in BIG-IP GTM versions 9.3.1 and 9.4.1. For information about upgrading, refer to the BIG-IP GTM release notes.
