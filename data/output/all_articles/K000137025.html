Description

Performed changes on BIG-IP DNS (DNS A) configuration, are not synchronized with another BIG-IP DNS (DNS B). The changes can be seen on BIG-IP DNS A, for example in /var/log/audit.log

Sep 12 01:57:02 dns-bigipA notice mcpd[4828]: 01070417:5: AUDIT - client tmui, user admin - transaction #132567-4 - object 0 - create { gtm_wideip { gtm_wideip_type 1 gtm_wideip_name "/Common/test.example.com" gtm_wideip_minimal_response 1 gtm_wideip_lb_why_log_verbosity 0 gtm_wideip_last_resort_pool_type 0 gtm_wideip_last_resort_pool "" gtm_wideip_ipv6_noerror 0 gtm_wideip_lbmode_pool 2 gtm_wideip_enabled 1 gtm_wideip_topology_prefer_edns0_client_subnet 0 gtm_wideip_persist 0 gtm_wideip_description "" } } [Status=Command OK]

 

or the command 'tmsh show gtm wideip' shows it in the running config.


But it does not exist in bigip_gtm.conf and it's not on the peer device (DNS B in the given example).

 

Environment

  • BIG-IP DNS
  • IQuery synchronization
 

Cause

The device-group '/Common/gtm' shows no devices:
 

cm device-group /Common/gtm {
    hidden true
    network-failover disabled
}

Recommended Actions

If the synchronization was verified with basic steps from article K13690 "Troubleshooting BIG-IP DNS synchronization and iQuery connections (11.x - 17.x)" then modify bigip_base.conf and add relevant device on each BIG-IP.
For example on dns-bigipA it should be:

cm device-group /Common/gtm {
    devices {
        /Common/dns-bigipA 
    }
    hidden true
    network-failover disabled
}

Or run:

tmsh modify cm device-group gtm { devices add { /Common/dns-bigipA  } }


Then restart services:

bigstart restart
