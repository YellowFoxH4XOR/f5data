Topic

You should consider using this procedure under the following condition:
  • You want to generate test syslog-ng messages to test SNMP traps on the BIG-IP system.

Description

SNMP traps are triggered when the alertd process receives input from the syslog-ng utility that matches an alert code. The alert code is matched against entries in the /var/run/bigip_error_maps.dat file in order to locate the corresponding alert name. The alertd process then matches the alert name to its entry in the /etc/alertd/alert.conf file and performs the action specified, such as sending an SNMP trap.

The /var/run/bigip_error_maps.dat file is dynamically generated using entries in the error map files. The error map files are located in the /etc/alertd directory and end with the _maps.h file extension. For more information about error map files, refer to K6420: The /var/run/bigip_error_maps.dat file maps the alertd process input from the syslog-ng utility to an alert name.

The logger utility is a shell based interface to the syslog-ng system. Information found in error map file entries can be used to construct logger commands and generate syslog-ng messages. Use the following procedures to extract data from the error map file entries, and test SNMP traps using the logger command.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP command line.

Procedures

Using the snmptrap command to send SNMP traps

The following example generates an SNMP trap to a destination host with the OID value of .1.3.6.1.4.1.8072.100.1 and the string value of test.

  1. Log in to the BIG-IP command line.
  2. Use the following command syntax to send a SNMP trap from the BIG-IP to a destination device:

    snmptrap -v 2c -c public <host> '' .1.3.6.1.4.1.8072.100 .1.3.6.1.4.1.8072.100.1 s "test" 

    Note: Replace <host> with the destination host IP address that you want to send the snmp trap.

Locating data in error map files

Before you use the logger utility to test SNMP traps, locate the needed data in the relevant entry in the error map files. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To change to the /etc/alertd directory, type the following command:

    cd /etc/alertd

  3. Pre-configured SNMP traps are located in the alert.conf file. To view the pre-configured SNMP traps, type the following command:

    less ./alert.conf

  4. Pre-configured traps contain the word snmptrap. Locate the trap entry of interest and note the alert name. For example, the alert name in the following example is BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS:

    alert BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS {
                  snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.12"
          }

  5. To search all error map files with a .h file extension for the alert name, use the following command syntax:

    grep <alert name> *.h

    Note: The entries in the *_error_maps.h files can change between BIG-IP versions. Always confirm the log information by consulting the local *_maps.h files.

    For example, you can search for entries containing the string BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS by typing the following command:

    grep BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS *.h

    The command output prefixes match lines with the filename and displays two matches in this example, with the first being the best match:

    bigip_mcpd_error_maps.h:0 LOG_NOTICE 01070640 BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS "Node %s address %s monitor status %s."
    bigip_mcpd_error_maps.h:0 LOG_NOTICE 01070728 BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS_UP "Node %saddress %s monitor status up."

  6. Note the syslog-ng facility, log level, alert code, and descriptive message contained in the matched entry:

    0 LOG_NOTICE 01070640 BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_STATUS "Node %s address %s monitor status %s."

    For example:

    Facility: 0
    Log Level: LOG_NOTICE
    Alert Code: 01070640
    Descriptive Message: "Node %s address %s monitor status %s."

Using the logger utility to test SNMP traps

To test SNMP traps using the logger utility, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. While remaining logged in to the BIG-IP command line, construct your logger command with the information you extracted using the following syntax:

    logger -p <facility>.<level> "<alert code>:<log level>: <descriptive message>"

    In the previous syntax, note the following:

    • <facility> is the syslog-ng facility as listed in the /var/run/bigip_error_maps.dat file.
    • <level> is the facility log level, which can include one of any eight available log levels.
    • <alert code> is the alert code as indicated in the *_maps.h file entry.
    • <log level> is the alert log level. This level corresponds with the following values:
       
      Log levelDescriptionCorresponding syslog level
      0System is unusableemerg
      1Action must be taken immediatelyalert
      2Critical conditionscrit
      3Error conditionserr
      4Warning conditionswarning
      5Normal but significant conditionnotice
      6Informationalinfo
      7Debug-level messagesdebug
    • <descriptive message> is the descriptive message string format used to describe the alert. Note that %s in the example will match any string.

    For example, using the information extracted in step 6 of the previous procedure, you can create the following logger command:

    logger -p local0.notice "01070640:5: Node 10.10.64.14 monitor status down."

    This command will output a syslog-ng message to the local0.notice facility (the default destination of which is the /var/log/ltm file) and generate an SNMP trap for this message.
