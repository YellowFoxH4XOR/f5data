Known Issue

The gtmd process may produce a core file when you add a new BIG-IP DNS system (formerly known as BIG-IP GTM) to an existing sync group.

This issue occurs when all of the following conditions are met:

  • A BIG-IP DNS sync currently exists.
  • You add a new BIG-IP DNS system to the existing sync group.

Note: This behavior is very rare. However, F5 recommends that if you want to add a new BIG-IP DNS system to an existing sync group, you should create a backup of the system configuration. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13.x).

Impact

The new BIG-IP DNS system that you want to add to an existing sync group may generate a gtmd core file. Configurations on other production BIG-IP DNS devices within the network may become compromised and require you to restore their configurations from a backup. In addition, the new BIG-IP DNS system may produce a core dump at the moment of sync group corruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When adding a new BIG-IP DNS system to an existing sync group, the new system's configuration conflicts with configurations on the other BIG-IP DNS systems in the sync group and may cause the gtmd process to produce a core file on the newly added unit.
  • The new BIG-IP DNS system may write a core file.
  • Existing BIG-IP DNS systems within the sync group may experience corruption of their existing configuration.
