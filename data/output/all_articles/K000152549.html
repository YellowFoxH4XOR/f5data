K000152549: DDM Alerts Generation Timing Variation after port UP/DOWN

Type
Support Solution
Published
2025-07-12
Updated
2025-07-12
Source

Description

DDM Alerts Generates at different times after Port is Up/DOWN.

Environment

F5OS-A

F5OS-C

DDM

Port-Group

Cause

This is working as Designed.

Digital Diagnostics Monitoring (DDM) that the F5OS layer runs to check the status and health of the fiberoptic transceivers installed. 

 

  • The default DDM polling frequency on F5OS is 30 seconds. This means the system checks the DDM values every 30 seconds by default.
  • Min is '1' and Max is '4289999999' seconds. Default is 30 seconds. Setting Value to '0' seconds disable DDM for that port-group.
  • When a port transitions UP or DOWN, DDM alerts (such as low/high power, temperature, or bias warnings/alarms) will be generated on the next DDM polling cycle. Therefore, the 'minimum time' for a DDM alert to be generated after a port state change is immediately after the next polling interval (which could be almost instant if the event coincides with a poll). The 'maximum time' is one polling interval (e.g., up to 30 seconds by default).

 

Minimum Alert Generation- ~0 seconds. If event coincides with poll.

Maximum Alert Generation- 30 seconds. If event just missed a poll (default setting).

SNMP traps will also be sent if enabled and configured to monitor DDM alerts. Traps will be sent almost immediately to the management server. Some delay could be added by intermediate network to get the SNMP Trap UDP packets reached to the Management Server.

In case of DDM RX power alarm OID is set to '1.3.6.1.4.1.12276.1.1.1.262401' and in case of DDM TX power alarm, OID is set to '1.3.6.1.4.1.12276.1.1.1.262400'.

When alarm is set and when alarm is clear, same OID is seen but 'alertEffect=' will be different.

RX alarm - 1.3.6.1.4.1.12276.1.1.1.262401

TX alarm - 1.3.6.1.4.1.12276.1.1.1.262400

alertEffect=0 => When alarm is cleared

alertEffect=1 => When alarm is set

Recommended Actions

Configure/Program the Network Management/Monitoring Server to handle the DDM alerts accordingly received within 'min' and 'max' interval after Port UP/Down.
