Known Issue

Description

When the BIG-IP ASM system is running on a multi-blade platform, the var directory may fill with temporary files.

This issue occurs when the following condition is met:

  • The BIG-IP ASM system is running on a VIPRION 4400 or VIPRION 2400 platform.

As part of the synchronization process between blades, the BIG-IP ASM system creates numerous temporary files in the /var/ts/var/cluster/temp directory, which are not removed when they are no longer needed.

Impact

System instability that includes intra-blade communication failure, blades going offline, or blades failing over within a cluster.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Intra-blade communication fails, or blades go offline and failover. As a result, the system writes error messages to the /var/log/ltm file that appear similar to the following examples:

    01140029:5: HA mpi_failsafe_t tmm fails action is go offline and down links.
    01340003:3: Cluster error: Local MPI connections failed, bringing down my blade, and an automatic MPI recovery is underway.
  • A kernel panic occurs. As a result, the system writes error messages to the /var/log/kernel.log file that appear similar to the following examples:

    err kernel: BUG: soft lockup - CPU#21 stuck for 67s! [tmm:10681]

    err kernel: INFO: task bd:14245 blocked for more than 120 seconds.
  • The /var file system is full. As a result, the system writes messages to the /var/log/ltm file that appear similar to the following example:

    01560000:3: [rollup.cpp:308 getTempFn] could not create temp file /var/tmstat2/cluster/blade2.tm2.zISODt: No space left on device
  • The /var/ts/var/cluster/temp directory contains a large number of files that appear similar to the following example:

    ucs_sync_file_temp.16082
  • The /var partition reports that it is at or near capacity in the output of the df -u command, as shown in the following example:

    /dev/mapper/vg--db--sda-set.3._var 3.0G 2.1G 736M 95% /var

Workaround

To work around this issue, you can free up disk space by removing the unnecessary temporary files. To do so, perform one of the following procedures:

One-time removal of temporary files

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

To temporarily work around this issue, you can remove the files from the /var file system by entering the following command from the BIG-IP command line:

Note: The BIG-IP ASM system continues to create the temporary files. You may need to repeat this procedure before the directory reaches capacity again.

rm -rf /var/ts/var/cluster/temp/ucs_sync_file_temp.*

Recurring removal of temporary files

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

To permanently work around this issue, you can create a cron job to automatically remove the temporary files once every hour. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Change directories to the cron directory by typing the following command:

    cd /etc/cron.hourly
  3. Using a text editor, create a file named remove_asm_temp_files.sh.
  4. Enter the following data into the file:

    #!/bin/bash
    find /var/ts/var/cluster/temp -mindepth 1 -mmin +120 -exec rm {} \;
  5. Save and exit the file.
  6. Type the following command:

    chmod 700 /etc/cron.hourly/remove_asm_temp_files.sh
