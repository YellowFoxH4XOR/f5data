Topic

You should consider using this procedure under the following condition:

  • You want to adjust the rate at which the BIG-IP system sends reject packets.

Description

The tm.maxrejectrate database key allows you to adjust the number of TCP RSTs or Internet Control Message Protocol (ICMP) unreachable packets that the BIG-IP system sends in response to incoming client-side or server-side packets that cannot be matched with existing connections to BIG-IP virtual servers, self IP addresses, or Secure Network Address Translations (SNATs).

Note: If you suspect the BIG-IP system is experiencing a denial-of-service (DoS) attack, consider lowering the tm.maxrejectrate threshold to decrease the number of reject packets that the system sends in response to unmatched connections.

The default value for the tm.maxrejectrate key is 250 TCP RSTs or 250 ICMP unreachable packets per second. The system allows a minimum value of 1 and a maximum value of 1000.

Note: Please note that this configuration applies per TMM, the Disaggregator (DAG) can have a direct impact on how traffic is distributed among different TMMs. It is possible that one TMM does not reject any traffic, while another has reached the tm.maxrejectrate threshold.\

You can use the tm.maxrejectrate database key to reduce the effects of a DoS for the following protocols:

Note: Due to way the HTSplit feature dedicates and prioritizes resources when enabled, the value configured for the tm.maxrejectrate key is doubled on platforms with Hyper-Threading (HT) Technology. If the value of the tm.maxrejectrate key is set to 250, log messages indicate responses are limited to 500 packets/sec.

TCP

When the number of TCP packets exceeds the tm.maxrejectrate threshold, the BIG-IP system stops sending TCP RST packets in response to unmatched packets, and logs an error message.

For example, when the number of packets that match a local traffic IP address (a virtual IP address) or a self IP address exceeds the tm.maxrejectrate threshold, but the packets specify an invalid port, the system stops sending RST packets in response to the unmatched packets and logs an error message to the /var/log/ltm file that appears similar to the following example:

011e0001:4: Limiting closed port RST response from 299 to 250 packets/sec

When the number of packets that match a local traffic IP address (a virtual IP address) and port, or a self IP address and port, exceeds the tm.maxrejectrate threshold, but the packet is not a TCP SYN packet and does not match an established connection, the system stops sending RST packets in response to the unmatched packets. The system also logs an error message to the /var/log/ltm file that appears similar to the following example:

011e0001:4: Limiting open port RST response from 299 to 250 packets/sec

ICMP

When ICMP exceeds the tm.maxrejectrate threshold, the BIG-IP system stops sending ICMP unreachable packets in response to unmatched packets, and logs a message to the /var/log/ltm file that appears similar to the following example:

011e0001:4: Limiting icmp unreach response from 299 to 250 packets/sec

When ICMP exceeds the tm.maxrejectrate threshold, the BIG-IP system stops sending ICMP ping response packets in response to ping floods, and logs a message to the /var/log/ltm file that appears similar to the following example:

011e0001:4: Limiting icmp ping response from 299 to 250 packets/sec

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Traffic Management Shell (tmsh).

Procedures

Adjusting the rate at which the BIG-IP system issues TCP RSTs or ICMP unreachable packets

Impact of procedure: Increasing the tm.maxrejectrate threshold may cause the BIG-IP system to use more system resources during a DoS attack.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To adjust the tm.maxrejectrate database key, use the following command syntax:

    modify sys db tm.maxrejectrate value <value>

    For example, to change the tm.maxrejectrate to 200, type the following command:

    modify sys db tm.maxrejectrate value 200

  3. Save the change by typing the following command:

    save sys config
