Description

MySQL health monitor on BIG-IP LTM fails with the error:

java.sql.SQLException: Unknown system variable 'transaction_isolation'

ProxySQL query traces show that the following SQL statement is sent during monitoring attempts:

SELECT @@session.auto_increment_increment AS auto_increment_increment,

@@character_set_client AS character_set_client,

@@character_set_connection AS character_set_connection,

@@character_set_results AS character_set_results,

@@character_set_server AS character_set_server,

@@collation_server AS collation_server,

@@collation_connection AS collation_connection,

@@init_connect AS init_connect,

@@interactive_timeout AS interactive_timeout,

@@license AS license,

@@lower_case_table_names AS lower_case_table_names,

@@max_allowed_packet AS max_allowed_packet,

@@net_buffer_length AS net_buffer_length,

@@net_write_timeout AS net_write_timeout,

@@sql_mode AS sql_mode,

@@system_time_zone AS system_time_zone,

@@time_zone AS time_zone,
@@transaction_isolation AS transaction_isolation,
@@wait_timeout AS wait_timeout

This error occurs regardless of the configured "send string" in the BIG-IP MySQL monitor.

Environment

  • BIG-IP LTM
  • ProxySQL
  • MariaDB
  • MySQL monitor

Cause

The error is not caused by the specific "send string" configured in the BIG-IP MySQL monitor. It is triggered by an initial query sent by the JDBC connector used by BIG-IP to retrieve global variables including transaction_isolation. ProxySQL acts as a proxy and presents itself to clients (such as BIG-IP) as a MySQL server version defined by its mysql-server_version setting. If this value is set to greater than 8.0 or matches a MariaDB version number directly (e.g., 10.x), the JDBC connector expects the presence of a transaction_isolation variable which does not exist in MariaDB as it does in MySQL 8+. This mismatch results in the reported error.

Recommended Actions

  • Set ProxySQL's global variable mysql-server_version to a MySQL version compatible with MariaDB (for example: 5.7). This ensures that the JDBC connector uses compatible queries and avoids requesting unsupported variables.
  • After changing mysql-server_version, existing TCP connections from BIG-IP may persist and continue using old session parameters; thus health monitors may not immediately detect changes.
    • To reset connections after changing ProxySQL settings:
      • Restart the bigd process on BIG-IP. 
      • Alternatively, manually delete relevant TCP connections using TMOS commands:

        show sys connection ss-server-addr <IP> ss-server-port <PORT>

        delete sys connection ss-server-addr <IP> ss-server-port <PORT>

        Replace <IP> and <PORT> with your actual ProxySQL server address and port.
  • There is no configuration option on BIG-IP or within JDBC to make it natively recognize MariaDB behind ProxySQL;  compatibility must be managed through correct ProxySQL configuration.
  • Always ensure health monitor connections are reset after any change to how ProxySQL presents its backend database version.
