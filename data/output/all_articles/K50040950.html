Topic

You should consider using this procedure under the following condition:

  • You want to configure high-speed logging (HSL) to use the management interface.

Description

Starting in BIG-IP 12.0.0, you can configure HSL to use the management port to send logs to servers only reachable through the management network.

There are a few caveats to using the management port that do not affect the Traffic Management Microkernel (TMM) interfaces:

  • TMM does not use the management interface, so load balancing between pool members is not available.
  • You cannot use the management port for request logging.
  • Bandwidth is limited on the management port.

If you have specifications to load balancing across multiple log servers, F5 recommends that you use TMM interfaces and the configuration method outlined in K17398: Configuring the High Speed Logging traffic distribution method.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility or tmsh.
  • When configuring using tmsh, you should have a general familiarity with the Linux vi text editor.
  • You have a logging server already configured and reachable through the management network.

Procedures

To configure the HSL traffic to use the management interface, perform either of the following procedures:

  • Creating and applying management port HSL using the Configuration utility
  • Optionally creating a custom iRule for virtual server connection logging
  • Creating a new management port entry using tmsh
  • Modifying an existing management port entry using tmsh
  • Creating a log publisher configuration using tmsh
  • Optionally creating an iRule with HSL management port destination
  • Limiting bandwidth

Creating and applying management port HSL using the Configuration utility

Using the Configuration utility, you can configure HSL traffic to use the management port to send logging traffic to a log server available through the management interface. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Log Destinations.
  3. Click Create.
  4. Enter a Name for the log destination.
  5. For Type, click Management Port.
  6. Enter the IP address of the destination log server.
  7. Enter the listening port of the destination log server.
  8. For Protocol, click the appropriate protocol for the destination log server.

    Note: Alternatively, you can enter the destination port manually.

  9. Navigate to System > Logs > Configuration > Log Publishers.
  10. Click Create.
  11. Enter a name for the log publisher configuration.
  12. In the Available list, click the previously configured log destination name and move it to the Selected list.
  13. Click Finished.

Optionally creating a custom iRule for virtual server connection logging

You can create a custom iRule that can be applied to a virtual server. The iRule enables HSL logging for the virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > iRules > iRule List.
  2. Click Create.
  3. Enter a name for the iRule.
  4. For Definition, enter the following iRules syntax:

    when CLIENT_ACCEPTED {
      set my_hsl [HSL::open -publisher /<partition>/<log publisher>]
    }
    when HTTP_REQUEST {
      HSL::send $my_hsl "Request: [HTTP::host][HTTP::uri]"
      log local0.info "Request: [HTTP::host][HTTP::uri]"
    }
    when CLIENT_CLOSED {
      unset my_hsl
    }

    Note: Replace <partition> and <log publisher> with the partition location and log publisher configuration name created in step 11 of the previous procedure.

  5. Click Finished.
  6. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  7. Click the name of the virtual server to which you want to add logging.
  8. Click the Resources tab.
  9. Click Manage.
  10. In the Available list, click the iRule you previously created move it to the Selected list.
  11. Click Finished.

Creating a new management port entry using tmsh

You can configure HSL traffic to use the management port to send logging traffic to a log server available through the management interface. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create a new log destination to use the management interface, use the following command syntax:

    create /sys log-config destination management-port <name> ip-address <ip address> port <port number> protocol <protocol udp|tcp>

    For example, to create the new log destination MyHSLDest with the management interface using the User Datagram Protocol (UDP), type the following command:

    create /sys log-config destination management-port MyHSLDest ip-address 1.2.3.4 port 514 protocol udp

  3. To save the changes, type the following command:

    save /sys config

Modifying an existing management port entry using tmsh

To configure the HSL traffic to use the management port to send logging traffic using an existing management interface entry, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify an existing log destination to use the management interface, use the following command syntax:

    modify /sys log-config destination management-port <name> ip-address <ip address> port <port number> protocol <protocol udp|tcp>

    For example, to modify the existing log destination MyHSLDest to use the TCP protocol, type the following command:

    modify /sys log-config destination management-port MyHSLDest ip-address 1.2.3.4 port 514 protocol tcp

  3. To save the changes, type the following command:

    save /sys config

Creating a log publisher configuration using tmsh

To configure the HSL traffic to use a log publisher, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create a new log publisher use the following command syntax:

    create /sys log-config publisher <name> { destinations add { <name of log destination management port> } }

    For example:

    create /sys log-config publisher my_publisher { destinations add { MyHSLDest } }

  3. Save the configuration changes by typing the following command:

    save /sys config partitions all

Optionally creating an iRule with HSL management port destination

iRules can use management port destinations for HSL using the HSL::open and HSL::send commands and specifying the publisher as /Common/management-port-pub. For more information, refer to the iRules Wiki on DevCentral.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create a custom log publisher iRule, use the following command syntax:

    create /ltm rule <irule name>

    Note: Replace <irule name> with the name for the iRule.

    Note: This command opens the iRule with the vi text editor.

  3. Using the text editor, place the cursor on the opening brace character ({).
  4. Press o.
  5. Use the following stanza syntax between the opening and closing braces:

    when CLIENT_ACCEPTED {
      set my_hsl [HSL::open -publisher </partition>/<log publisher>]
    }
    when HTTP_REQUEST {
      HSL::send $my_hsl "Request: [HTTP::host][HTTP::uri]"
      log local0.info "Request: [HTTP::host][HTTP::uri]"
    }
    when CLIENT_CLOSED {
      unset my_hsl
    }

    Note: Replace <partition> and <log publisher> with the partition location and log publisher configuration name created in the previous procedure.

  6. Press ESC + :wq to save the configuration and exit the vi text editor.
  7. Confirm saving the changes by pressing the Y.
  8. To modify an existing  virtual server to use the HSL management port for virtual server level logging, use the following command syntax:

    modify /ltm  virtual <virtual server name> rules { <irule log publisher name> }

    Note: Replace <virtual server name> with the name of the virtual server and <irule log publisher name> with the iRule name you previously created.

  9. Save the configuration changes by typing the following command:

    save /sys config partitions all

VIPRION considerations

When you use a management port logging destination, there is no facility to send logs out from a specific blade. This is to ensure scalability, eliminate a potential single point of failure and to maintain logging speed in high-speed-logging. Each log message is sent out directly by the blade which generated the log.

Each blade in the chassis must have its own management IP address so that it can send its own logs out. If the blade which generated the message is currently a primary blade, then the cluster default IP address is used as source-address for outgoing log messages. If the blade which generated the message is currently a secondary blade, then the cluster member IP address is used as source-address for outgoing log messages.

Limiting bandwidth

The mgmt.portlogging.bandwidthcap database variable allows you to limit the amount of bandwidth HSL can use on the management port. The default setting is 60 Mbps. To change the default, type the following command syntax:

tmsh /modify sys db mgmt.portlogging.bandwidthcap <value>   Valid range is 1 - 800.

For example, to set the bandwidth cap to 100 Mbps, type the following command:

tmsh /modify sys db mgmt.portlogging.bandwidthcap 100

Additional variables that control timeout and retries

  • The management port logging listener retry timing in seconds is the amount of time the internal listener for log messages waits before attempting to listen for messages upon failure. For example:

    mgmt.portlogging.listenerretry
     Default: 2 seconds
     Range: 1 - 600

  • The management port logging server timeout in seconds is the amount of time to wait before timing out a server socket that has not received new messages. For example:

    mgmt.portlogging.servertimeout
     Default: 30 seconds
     Range: 1 - 600

  • The management port logging server retry in seconds is the amount of time to wait after a receiving server fails before attempting to reinitialize the connection. For example:

    mgmt.portlogging.serverretry
     Default: 2 seconds
     Range: 1 - 600
