K000134783: Recover the root user password on F5 VELOS system

Knowledge
Published
2023-05-25

  • F5OS Products
  • F5OS: 2.X.X, 2.0.X, 2.0.0
  • F5OS-C: 1.6.4, 1.5.0, 1.6.X, 1.5.X, 1.6.2, 1.6.1, 1.6.0, 1.5.1
Source
https://my.f5.com/manage/s/article/K000134783

Description

If you need to reset a lost or forgotten root user password on the F5 VELOS system, you need to first restart the active system controller (CC-1) to single-user mode before performing a series of commands to reset the root user password. Note that restarting the active system controller (CC-1) would result in the standby system controller (CC-2) taking over as active. You must then restart the currently active system controller (CC-2) so that the currently standby system controller (CC-1) takes over as the active. You must then reset the root user password on the currently active system controller (CC-1) so that the root user password can sync to the previously active system controller (CC-2) when all its services is up and running.

Note: The procedure described in this article has not been verified on VELOS system that is enabled with Appliance mode.

Note: The CC-1 and CC-2 indicators are meant to assist in illustrating which system controller you would be performing the step on and does not indicate the actual system controller number.

Environment

  • F5 VELOS chassis and system controllers
  • F5OS-C 1.5.x and later
  • Serial console access to both F5 VELOS system controllers; for information about serial console access, refer to K65442484: Overview of access to the F5 VELOS system

Cause

You need to reset the password for an administrative account, such as the root user on F5OS-C 1.5.x and later.

Recommended Actions

To reset the root or admin user password on the F5 VELOS system, perform the following procedure:

Impact of procedure: This procedure requires that you restart the F5 VELOS system in single-user mode. While in this mode, the F5 VELOS system may not be able to run any tenants and may not process any traffic. F5 recommends that you perform this procedure during a maintenance window.

  1. Connect a terminal to the F5 VELOS system controller serial console port.
  2. Invoke the AOM Command menu from the serial console by entering Esc ( key sequence. The AOM Command menu should look similar to the following example:

    AOM Command Menu:
    B --- Set baud rate
    C --- Capture blade console
    CC -- Capture system controller console
    I --- Display chassis information
    P --- Power on/off blade
    PC -- Power on/off system controller
    R --- Reset blade CPU
    RC -- Reset system controller CPU
    U --- Front panel USB port
    Q --- Quit menu and return to console

    Enter Command:

  3. To determine if the system controller is active or standby, enter I (capital letter i). The AOM system returns an output that includes the Active LED status located under the system controller information section; green solid indicates it is currently active while off indicates it is currently standby (similar to the following example):

    System controller 1 information:
        Arbitration status : active
        AOM firmware version : 2.01.1176.0.1
        AOM bootloader version : 1.02.1019.0.1
        CPLD version : 01.03.0A
        Serial number : bld123456s
        Power status : on
        Active LED : green solid <---
        Status LED : green solid
        Alarm LED : off
        Front-panel USB port : enabled next boot
        Power on self test status : passed
        Runtime status : healthy

  4. Once you have identified the active system controller (CC-1), enter PC to invoke the power on/off host subsystem option from the active system controller (CC-1) AOM Command menu. Then enter 0 (number zero) to indicate you want to power off the host subsystem. The AOM system prompts for confirmation; enter y to confirm and initiate a power off of the host subsystem. The AOM system will display the AOM Command menu when the host subsystem is powered off. Note that at this point, the standby system controller (CC-2) will take over as active.
  5. From the previously active system controller (CC-1) AOM Command menu, enter PC to invoke the power on/off host subsystem option again. To power on the host subsystem, enter 1 (number one). This is followed by a confirmation prompt by the AOM system; enter y to confirm and initiate a power on of the host subsystem. The AOM system will then display the AOM Command menu on the previously active system controller (CC-1).
  6. From the previously active system controller (CC-1) AOM Command menu, enter Q to exit the AOM Command menu and return to the host subsystem serial console. You should now see the previously active system controller (CC-1) displaying the power on sequence followed by the GRUB menu and counts down before continuing the startup process. Note that steps 7 through 21 are performed on the previously active system controller (CC-1).
  7. Before the countdown expires, enter e to edit the start options for the first boot image.

          CentOS Linux 7 (Core) (ostree:0)    <---enter e to edit this first boot image
          CentOS Linux 7 (Core) (ostree:1)



          Use the ^ and v keys to change the selection.
          Press 'e' to edit the selected item, or 'c' for a command prompt.

    The system should bring up the GRUB edit screen.

  8. Use the arrow keys to move the prompt to the line that starts with linuxefi. For example,

    linuxefi /ostree/velocity-c81314112f0f5be96163956bbb118346d0682be9ebe107ce8c62\
    57c410ee4de7/vmlinuz-3.10.0-1160.62.1.F5.1.el7_8.x86_64 intel_iommu=on iommu=p\
    t acpi_osi=Linux quiet crashkernel=auto rd.lvm.lv=velocity/root rd.lvm.lv=velo\
    city/swap console=ttyS0,115200n8r root=/dev/mapper/velocity-root ostree=/ostre\
    e/boot.0/velocity/c81314112f0f5be96163956bbb118346d0682be9ebe107ce8c6257c410ee\
    4de7/0

    Note: If your terminal app does not support arrow keys, you may want to refer to GNU GRUB Manual for the key combinations to move the cursor around the GRUB edit screen. This link takes you to a resource outside of MyF5. The third party could remove the document without our knowledge. For some examples of the key combinations, CTRL+P and CTRL+N moves the cursor up and down respectively while CTRL+B and CTRL+F moves the cursor left and right respectively.

  9. Use the End key or use the right arrow key to go to the end of line.
  10. Enter a space followed by the word rd.break at the end of the linuxefi line. Using the previous example, it should appear similar to the following example:

    linuxefi /ostree/velocity-c81314112f0f5be96163956bbb118346d0682be9ebe107ce8c62\
    57c410ee4de7/vmlinuz-3.10.0-1160.62.1.F5.1.el7_8.x86_64 intel_iommu=on iommu=p\
    t acpi_osi=Linux quiet crashkernel=auto rd.lvm.lv=velocity/root rd.lvm.lv=velo\
    city/swap console=ttyS0,115200n8r root=/dev/mapper/velocity-root ostree=/ostre\
    e/boot.0/velocity/c81314112f0f5be96163956bbb118346d0682be9ebe107ce8c6257c410ee\
    4de7/0 rd.break

  11. Select Ctrl-X to apply the change.
  12. After the single-user mode startup sequence completes, a command-line prompt displays switch_root:/#. The system is now in single-user mode.
  13. Re-mount the /sysroot and /sysroot/sysroot file systems as read-write by entering the following command:

    mount -o remount,rw /sysroot && mount -o remount,rw /sysroot/sysroot

  14. Change the root file system using chroot:

    chroot /sysroot

    The prompt should now display sh-4.2#

  15. Change the root user password using the following command:

    passwd root

    The system may display errors similar to the following example but it is safe to ignore them:

    /sbin/pam_exec failed: exit code 2
    passwd: Authentication token manipulation error

  16. Load a SELinux policy into the kernel by entering the following command:

    load_policy -i

  17. Restore the default SELinux security context for /etc/shadow file by entering the following command:

    restorecon -v /etc/shadow

  18. Create a shadow.tracker file in the /etc/libnss-udr directory by entering the following command syntax:

    awk -F: '/^root:/{print "root root", $2, $3}' /etc/shadow >> /etc/libnss-udr/shadow.tracker

    The presence of this file ensures that the system syncs up the passwords in both the /etc/shadow as well as the copy of this file in the controller_userman service and the ConfD database. After completion of the operation, the shadow.tracker file will be removed.

  19. Exit the chroot by entering the following command:

    exit

    The command prompt should now display the single-user mode prompt switch_root:/#.

  20. For F5OS-C 1.x: Exit the single-user mode and start up the system by entering the following command:
    exit
    For F5OS 2.x: You must reboot the system controller (CC-1) by entering the following command:
    rebootNote: If you have typed "exit" instead of "reboot", the system will be rendered inoperative until you manually reboot, or until the system reboots automatically after various daemons timeout on system startup. 
  21. When the system controller (CC-1) is fully up and running, login using the new password for the root user which you have changed in step 15. Once you have verified that the new password works for the root user, proceed to the next step.
  22. From the currently active system controller (CC-2) AOM Command menu, enter PC to invoke the power on/off host subsystem option. Then enter 0 (number zero) to indicate you want to power off the host subsystem. The AOM system prompts for confirmation; enter y to confirm and initiate a power off of the host subsystem. The AOM system will display the AOM Command menu when the host subsystem is powered off. Note that at this point, the currently standby system controller (CC-1) will take over as active.
  23. From the currently standby system controller (CC-2) AOM Command menu, enter PC to invoke the power on/off host subsystem option again. To power on the host subsystem, enter 1 (number one). This is followed by a confirmation prompt by the AOM system; enter y to confirm and initiate a power on of the host subsystem. The AOM system will then display the AOM Command menu on the currently standby system controller (CC-2).
  24. Go back to the login session on currently active system controller (CC-1) which you have established in step 21, change the root user password again using the passwd root command. Once you have done so, wait for the currently standby system controller (CC-2) to finish booting up and complete the services startup process. When the services on the currently standby system controller (CC-2) are ready, the new password for the root user should be synced between the two system controllers. You can verify this by logging into the currently standby system controller (CC-2) with the new password for the root user.
