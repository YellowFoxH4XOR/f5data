Known Issue

Secure Sockets Layer (SSL) mirroring may delay SSL handshakes and cause dropped connections after a failover event.

This issue occurs when all of the following conditions are met:

  • Your configuration includes one or more virtual servers with an associated SSL profile.
  • You enable the SSL profile's Session Mirroring option. Session Mirroring is disabled by default.

Impact

The BIG-IP system may delay SSL handshakes and drop SSL connections following a failover event.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe delays in SSL handshakes that the BIG-IP system processes.
  • Client connections no longer respond following a failover event.

Workaround

To work around this issue, you can set the BIG-IP system's SYN Check™ Activation Threshold to 0 (zero) and ensure that the TCP profile's Hardware SYN Cookie Protection option is set to Enabled. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Local Traffic > General.
  3. Under Properties, set SYN CheckTM Activation Threshold to 0 (zero).

    Note: The default SYN CheckTM Activation Threshold value is 16384.

  4. Click Update.
  5. Navigate to Local Traffic > Profiles > Protocol > TCP.
  6. Under Name, select the TCP profile that is associated with the affected virtual server.
  7. Under Security And Quality of Service, for Hardware SYN Cookie Protection, make sure the checkbox for Enabled is selected.
  8. Click Update.

    Note: Some platforms may not support hardware SYN cookies. For more information, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x).
