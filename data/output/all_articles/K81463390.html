Known Issue

Using a STATS iRule command in an ACCESS_SESSION_CLOSED event may cause the Traffic Management Microkernel (TMM) process to exit.

This issue occurs when all of the following conditions are met:

  • You configure a virtual server with an access profile and iRule.
  • The iRule contains a STATS command in the ACCESS_SESSION_CLOSED event.

The ACCESS_SESSION_CLOSED iRule event is triggered outside the context of flows and cannot access all of the connection information. Invoking a command, such as STATS::set, within the ACCESS_SESSION_CLOSED event will fail and cause the TMM process to restart.

Impact

Traffic is disrupted while the TMM process restarts and the device fails over if configured in a high availability group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process generates a core file to the /shared/core/ directory.
  • The BIG-IP APM system temporarily fails to process traffic while TMM restarts.
  • The BIG-IP APM system fails over to another device in the device group.

Workaround

There is no workaround for this issue. To mitigate this issue, do not use STATS iRule commands within the ACCESS_SESSION_CLOSED event.
