Description

Policy deployment is failing when special characters are used in  branch rules

example:
On BIG-IQ  Create Access Policy in Configuration Tab
General Purpose > Empty  and expression added in Advanced

expr { [mcget {session.user.agent}] contains "MSIE" || [mcget {session.user.agent}] contains "Mozilla/5.0 (Windows NT 6.1; WOW64; Trident/7.0; rv:11.0) like Gecko" || [mcget {session.user.agent}] contains "Edge" || [mcget {session.user.agent}] contains "Chrome" || [mcget {session.user.agent}] contains "11.0"}

Environment

  • BIG-IQ Centralized Management
  • APM service discovered for BIG-IP device
  • Configuration deployment for Per-Session Policy
  • branch rule with special characters

Cause

Bug ID 1060745: Special characters in branch rule expression causes deployment failures
 

Recommended Actions

The idea is to url encode UA before UA is compared with the one configured.
  1.  Add UA url encoded in BIGIQ and deploy access policy to APM
    expr { [mcget {session.user.agent}] contains "Mozilla%2F5.0%20(Windows%20NT%2010.0%3B%20Win64%3B%20x64)%20AppleWebKit%2F537.36%20(KHTML%2C%20like%20Gecko)"
  2. Add this irule to VS on APM
    when CLIENT_ACCEPTED {
    ACCESS::restrict_irule_events disable
    }
    when HTTP_REQUEST {
    if { [ACCESS::session exists] }{
    set uenc [URI::encode [HTTP::header User-Agent]]
    binary scan $uenc H* henc
    ACCESS::session data set session.custom.ua $henc
    }
    }
  3. Add this variable assignment in the VPE just before the agent that will compare UAs
    Left: Custom Variable
    session.user.agent
    Right: Custom Expression
    set ua1 [mcget -nocache {session.custom.ua}];
    return [encoding convertfrom utf-8 [binary format H* $ua1]];
