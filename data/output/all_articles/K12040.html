Known Issue

This is the result of a known issue. The RADIUS server may issue an Access-Challenge request when additional information is needed from the user in order to determine the authenticity of the user or to determine the kind of service to provide. If multiple RADIUS servers have been configured on a FirePass controller, the FirePass controller may send the response to the Access-Challenge request to the wrong RADIUS server. As a result, the user's authentication attempt will fail.

For example, if one RADIUS server has been configured for dynamic group mapping, a second RADIUS server is configured in the fallback group, and the dynamic group mapping RADIUS server sends an Access-Challenge request in response to the Access-Request exchange, the FirePass device may send the Access-Challenge response to the fallback group RADIUS server.

Product Development tracked this issue as ID 294133 (formerly CR129422-3) and it was fixed in FirePass version 7.0.0. For information about upgrading, refer to the FirePass release notes.

F5 Product Development is tracking this issue as ID 317617 (formerly CR129422) for version 6.1.0, ID 297311 (formerly CR129422-2) for version 6.0.2, and ID 296537 (formerly CR129422-1) for version 6.0.3.

This issue was fixed in cumulative HF-610-1 issued for FirePass version 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
