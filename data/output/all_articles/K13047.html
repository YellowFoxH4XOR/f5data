Known Issue

The BIG-IP system incorrectly allows you to configure a Server SSL profile with a certificate, but no corresponding key. As a result, virtual servers using that Server SSL profile may cause the Traffic Management Microkernel (TMM) to crash during the Secure Sockets Layer (SSL) handshake.

This issue occurs when the following conditions are met:

  • The Server SSL profile is used by a virtual server.
  • The Server SSL profile is configured with a certificate, but no key.
  • The HTTPS pool member requests verification of the client certificate (CertReqMessage).

Impact

The BIG-IP system may temporarily fail to process traffic and fail over if configured as part of a high-availability pair.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H380204 on the Diagnostics > Identified > High screen.
  • The system logs a TMM core file at the time of the crash in the /shared/core directory.
  • The system generates a SIGSEGV fault and stack trace to the /var/log/tmm file.
  • The system temporarily fails to process traffic and potentially fails over to the standby host.

Workaround

To work around this issue, you can define the appropriate key for the Server SSL profile.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Server.
  3. Open the Server SSL profile that you want to modify.
  4. Select the Key field.

    If the field is set to None, no key is configured.
  5. Specify the appropriate key in the Key field.
