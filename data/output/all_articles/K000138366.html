Description

The purpose of this article is to provide a way of filtering unwanted constantly-repeated /var/log/audit logs

 

Example

When setting up BIG-IQ cluster on version 8.x, working HA scripts are creating syncing and removing user config files.

This generates log messages each 30 seconds similar to:

AUDIT - pid=26385 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=delete sys config file ha-sync-users.scf

Environment

BIG-IP or BIG-IQ local syslog

Cause

N/A

Recommended Actions

NOTE: This change does not persist through upgrades.

 

The following example will show how to filter "delete sys config file ha-sync-users.scf" message from the audit log

 

  • Remount /usr as r+w:
    • mount -o rw,remount /usr
  • Make a backup copy of the template:
    • cp /usr/share/defaults/config/templates/syslog.tmpl /usr/share/defaults/config/templates/syslog.tmpl.orig
  • Add write permissions to the template:
    • chmod +w /usr/share/defaults/config/templates/syslog.tmpl
  • Use text editor to modify syslog template file
  • Find following section # audit log        /var/log/audit with attached filter :
    • filter f_audit {
  • Configure filter as following:

filter f_audit {

facility(local0) and (message("AUDIT") and not message("delete sys config file ha-sync-users.scf"));

};

  • Save the changes and quit 
  • In order for the BIG-IP system to write out the syslog.conf with the modified template, you must change the syslog configuration. To do so, use 'tmsh' to change the 'daemon-from' property to 'info' and then back to the default of 'notice':
    • tmsh modify /sys syslog daemon-from info
    • tmsh modify /sys syslog daemon-from notice
  • Ensure the changes were written to /etc/syslog-ng/syslog-ng.conf.
  • Remove write permissions to the template:
    • chmod -w /usr/share/defaults/config/templates/syslog.tmpl
  • remount /usr as read-only:
    • mount -o ro,remount /usr
  • Verify if delete ... log message is filtered in /var/log/audit
