K000162277: Behavioral Change in APM Session Variable Handling with Trailing Spaces After Upgrade to 17.1.3.2 / 17.5.1.6

Type
Support Solution
Published
2026-07-15
Updated
2026-07-15
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3, 17.5.1
Source
https://my.f5.com/manage/s/article/K000162277

Description

After upgrading from BIG-IP version 17.5.1.3 to 17.5.1.6, Access Policy rules referencing session variable names with trailing spaces (e.g., session.ad.custom.memberOf ) may fail. Symptoms include VPN access issues and the APM session logs may contain log messages similar to the following:

  • "Unable to find session variable used in rule expression."
  • "Rule evaluation failed with error."
  • "Key contains invalid character 0x20 at position <X>"
  • "session_var contains prohibited characters"

Removing the trailing space from the session variable name resolves the issue.

Environment

  • BIG-IP APM module, versions 17.1.3.2 and 17.5.1.6
  • Access Policy referencing session variables
  • memcache library used for session variable storage

Cause

Bug ID 2259173: Introduction of stricter memcache key validation in BIG-IP 17.1.3.2 and 17.5.1.6, prohibiting session variable names containing space characters.

Answer/Recommended Actions

  • Review Access Policy rules for session variable names containing leading or trailing whitespace.
  • Remove any whitespace from session variable names used in Access Policy expressions.
  • Test Access Policy behavior after making configuration changes to confirm successful resource assignment and VPN access.

Additional Information

  • The stricter key validation is expected behavior in BIG-IP 17.1.3.2/17.5.1.6 and later versions
  • Session variable names with prohibited characters (such as spaces) will result in rule evaluation failure and memcache errors.
