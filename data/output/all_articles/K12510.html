Known Issue

This is the result of a known issue. On VIPRION platforms installed with BIG-IP version 10.1.0, using the Configuration utility to reset the statistics for various configuration objects will cause the mcpd process to restart on all secondary blades. This is only known to happen when the object being reset exists in an administrative partition other than the Common partition.

This has been observed to occur when resetting the statistics on the following types of configuration objects:

  • Virtual server
  • Pool
  • Pool member
  • Node

In addition to the mcpd daemon restarting, error messages that appear similar to the following example will be written to the /var/log/ltm file:

01070826:3: Current update Partition Error: The current update partition (Common) does not match the object's partition (partition1), stats not reset
01070734:3: Configuration error: Configuration from primary failed validation: 01070826:3: Current Update Partition Error: The current update partition (Common) does not match the object's partition (partition1), stats not reset

F5 Product Development tracked this issue as ID 335621 (formerly CR140560), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.
