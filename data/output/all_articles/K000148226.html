K000148226: Why is TLSv1.0/1.1 enabled for F5 XC HTTP LB even though TLS setting is "High"

Type
Support Solution
Published
2024-11-08
Updated
2025-06-04
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Apps
  • F5 Distributed Cloud Multi-Cloud App Connect
Source
https://my.f5.com/manage/s/article/K000148226

What Happened?

  • I determined (through nmap, sslscan, or similar tool) that TLSv1.0/1.1 ciphers are enabled for my Distributed Cloud (XC) HTTP LB even though TLS setting on the LB is configured as "High"

 

Environment

  • F5® Distributed Cloud Console

 

Resolution/Answer

  • This can be resolved by decoupling the LB having the Medium/low TLS cipher setting from the others in any of the following ways:

    1. Raise the TLS Security Level to High on all load balancers sharing the same certificate

    2. Set TLS Coalescing to Strict (Advanced settings) on the LB to ensure its settings are independent from other load balancers using the same certificate.

    3. Use a different dedicated VIP for the LB in question

 

Cause

  • This is occurring because the certificate is shared across multiple LBs, and some one of those LBs have a security level of Medium (TLSv1.0+ with PFS ciphers) configured.
  • All LBs that share the same VIP and Certificate must have the same TLS Security Level (aka cipher suites) applied, else it will fall back to the lowest security level available to ensure compatibility.
  • This lowest security level fallback doesn't apply if the LB is using a different dedicated VIP, but the same cert. This is expected because it's a different endpoint, different virtual host and thus has no need to share the SNI list.
