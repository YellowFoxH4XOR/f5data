K62302245: DNS pool member is flapping and BIG-IP DNS did not monitor some remote servers

Support Solution
Published
2021-12-13

Status

Applies to

  • BIG-IP DNS: 12.1.5
Source
https://my.f5.com/manage/s/article/K62302245

Description

In the comlex DNS deployment, you may find the following issues:

  • iQuery connection is not full mesh. For example, the network broken between DNS2 and DNS3:

DNS3 ==> DNS1 OK
DNS3 ==> DNS2 Fail
DNS2 ==> DNS3 Fail
DNS2 ==> DNS1 OK
DNS1 ==> DNS3 OK
DNS1 ==> DNS2 OK

  • Some virtual servers / pool members are flapping.

  • In the data center without BIG-IP, the virtual server count is xx or more, some virtual servers are down, they did not receive the monitor probing traffic (No BIG-IP send out monitor traffic to them).

  • In the /var/log/gtm, get the log below:

notice gtmd[<PID>]: 011ae020:5: Connection in progress to <IP address of other BIG-IP>

Environment

  • BIG-IP DNS
  • SYNC group
  • iQuery

Cause

It is caused by the partial mesh iQuery connection.

Recommended Actions

Full mesh iQuery connection is required, it is the precondition.
If the BIG-IP DNS is offline, other BIG-IP devices can build the full mesh iQuery connection, this issue will not happen. For example, DNS3 is offline:

DNS3 ==> DNS1 Fail
DNS3 ==> DNS2 Fail
DNS2 ==> DNS3 Fail
DNS2 ==> DNS1 OK
DNS1 ==> DNS3 Fail
DNS1 ==> DNS2 OK

Please make sure the network is stable, prevent the partial mesh iQuery connection.

Additional Information

If BIG-IP DNS cannot create iQuery connection to other BIG-IP, it will try to perform all monitor task.
