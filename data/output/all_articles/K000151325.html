K000151325: When a DNS cache has a forward zone with multiple servers, how are the servers selected?

Description

When a DNS cache forward zone with multiple servers is defined and the BIG-IP has a DNS query to be replied to, the BIG-IP will randomly pick a server for whose RTT is measured below 400msec. The DNS query is then sent. When the reply arrives, the RTT for that response is measured and a new smoothed average RTT is calculated for that server. If the reply does not arrive, a new smoothed average RTT is also calculated (having in account the timeout - so, increasing the RTT).


The RTT is constantly being recalculated for each server therefore, with each query, using a smoothed average method.


If a server starts to become unresponsive (RTT goes above 400msec) then a probing scheme is applied in which a few random DNS queries are selected to probe the server (to allow it to recover from the previous high calculated RTT). However, if that probing scheme fails (e.g., server is still not replying or still replying with high RTT) then eventually the server will be blocked for 15 minutes and re-probed after that to calculate RTT again.


Environment

BIG-IP DNS cache


Cause

This is by design. The above mechanism is not currently configurable.


Recommended Actions

If it is believed a server is unresponsive and/or replying with high RTT, then it would be advised to troubleshoot why. Packet captures would be helpful for such troubleshooting.
