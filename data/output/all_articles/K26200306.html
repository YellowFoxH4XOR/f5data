Description

You may find the below message in the /var/log/httpd/httpd_errors:
err httpd[<pid>]: [cgi:error] [pid <pid>] [client <ip:port>] script not found or unable to stat: /usr/local/www/<path>
In this error message, note the following:

  • <pid> is the process ID for the httpd process.

  • <ip:port> is the client IP and source port pair.

  • <path> is the path the client is requesting but actually does not exist on a BIG-IP system.

For example,
If you issue a request using the below command
curl -kvL https://<configuration-utility-ip>/cgi-bin/
You can find an error message recorded as the below in the /var/log/httpd/httpd_errors log file.
err httpd[1038]: [cgi:error] [pid 1038] [client 192.168.1.5:17556] script not found or unable to stat: /usr/local/www/cgi-bin

Environment

  • BIG-IP LTM
  • Request towards a non-existing path to the configuration utility

Cause

None

Recommended Actions

This message is informational and does not cause a system failure. However, the message can be used as an identifier of unauthorized requests. To stats out the suspicious requests, you may use the below command under bash cli mode:
egrep -o "\[client.*script not found or unable to stat.*" /var/log/httpd/httpd_errors*|sort|uniq -c|sort -k1nr
For example, the below outputs show three requests that come from IP 172.16.210.31 with different source ports.
1 [client 172.16.210.31:3726] script not found or unable to stat: /usr/local/www/cgi-bin
1 [client 172.16.210.31:3728] script not found or unable to stat: /usr/local/www/cgi-bin
1 [client 172.16.210.31:3730] script not found or unable to stat: /usr/local/www/cgi-bin
With this client IP address information, you can check its legitimation and restrict the access to the management interface referring to K46122561: Restrict access to the BIG-IP management interface using network firewall rules
