Description

When performing HTTP health checks from F5 BIG-IP LTM devices to backend servers, different curl command options produce different results. Specifically, curl -I returns "HTTP/1.1 405 Method Not Allowed" while curl -v returns "HTTP/1.1 200 OK" for the same endpoint.

This article explains the differences between these curl options and their implications for configuring custom HTTP monitors.

Environment

LTM

Cause

The difference in output is due to the HTTP method used by each curl option:

curl -I uses the HTTP HEAD method, which requests only the HTTP headers without the response body. Some backend servers do not allow the HEAD method, resulting in a "405 Method Not Allowed" response.
curl -v (or plain curl) uses the HTTP GET method by default, which retrieves both headers and content. Most servers support GET requests, typically returning a "200 OK" response.

Recommended Actions

Understanding the curl options:

curl -I option: Sends an HTTP HEAD request that only retrieves headers. If the backend server does not support or allow the HEAD method, it will respond with "405 Method Not Allowed". This is expected behavior and does not indicate a problem with the health check endpoint itself.

curl -v option: Enables verbose output showing detailed connection information. By default, it uses the GET method, which retrieves both headers and content. This method is widely supported by web servers.

Recommendations for configuring custom HTTP monitors:

  • Use the GET or POST method (e.g., GET /healthcheck or POST /healthcheck) rather than HEAD for custom HTTP monitors on BIG-IP.
  • Verify that the HTTP method used in your monitor configuration matches what the backend server supports to avoid false negatives in health checks.
  • It is acceptable for HEAD requests (curl -I) to not return "200 OK" if the server does not support this method. This does not indicate an issue with the monitoring configuration.

Additional Information

The HEAD method is less commonly used and may be disabled on backend servers for security or application-specific reasons.
The GET method is the standard for retrieving web content and is almost universally supported.
When testing health check endpoints, use the same HTTP method that will be configured in your monitor to ensure accurate results.
