Topic

This article applies to BIG-IP 13.x and later. For information about other versions, refer to the following articles:

  • K13915: Configuring network failover for redundant VIPRION systems (11.x - 12.x)
  • K11939: Configuring network failover for redundant VIPRION systems (10.x)

You should consider using these procedures under the following condition:

  • You want to configure network failover for redundant VIPRION systems running 13.x and later versions.

Description

To ensure the most stable network failover configuration for redundant VIPRION systems, configure two channels for network failover communication. F5 considers it best practice to define a unicast and a multicast failover address for each VIPRION system in the device group. The unicast failover configuration uses a self IP address and Traffic Management Microkernel (TMM) switch port to communicate failover packets between each VIPRION system, and the multicast failover entry uses the management port to communicate failover packets between each VIPRION system. As an alternative to configuring the multicast failover option, you can define a unicast mesh using the management port for each VIPRION system. This is listed as an alternative option element.

To define both unicast and multicast failover addresses, and provide additional failover redundancy, perform the following procedures on each VIPRION system in the device group:

  • Create a trunk dedicated for failover
  • Create a VLAN dedicated for failover
  • Create a self IP address and associate the self IP with the failover VLAN
  • Enable network failover for the device group
  • Define the failover unicast address
  • Define the failover multicast address
  • Define a unicast mesh (alternative option)

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the Configuration utility or the TMOS Shell (tmsh).
  • You verified that the VIPRION systems are members of the same sync-failover device group.

Procedures

Create a trunk dedicated for failover

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Network > Trunks.
  3. Select Create.
  4. Enter a trunk name.

    For example:

    HA_TRUNK

  5. Add at least one interface from each blade to the trunk.
  6. Optional: Enable Link Aggregation Control Protocol (LACP), if appropriate, for your environment.
  7. Select Finished.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To create a trunk dedicated for failover, use the following command syntax:

    create /net trunk <trunk_name> interfaces add <{interface_list}> <options>

    For example, the following command creates a trunk with interfaces 1.1 and 1.2 and enables LACP:

    create trunk HA_TRUNK interfaces add {1.1 1.2} lacp enabled

  3. Save the configuration by entering the following command:

    save /sys config

Create a VLAN dedicated for failover

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Network > VLANs.
  3. Select Create.
  4. Enter a VLAN name.

    For example:

    HA_VLAN

  5. Select the trunk created in the previous procedure as the interface to use for the VLAN.
  6. Define the remaining VLAN parameters as appropriate for your environment.
  7. Select Finished.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To create a VLAN dedicated for failover and use the trunk created in the previous procedure as the interface, use the following command syntax:

    create /net vlan <vlan_name> interfaces add <{HA_trunk_name}>

    For example, the following command creates a VLAN with the trunk that you created in the previous procedure as the interface:

    create /net vlan HA_VLAN interfaces add {HA_TRUNK} 

  3. Save the configuration by entering the following command:

    save /sys config

Create a self IP address and associate the self IP with the failover VLAN

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Network > Self IPs.
  3. Select Create.
  4. Enter the IP address and netmask for the failover network.
  5. For VLAN, select the failover VLAN.

    For example:

    HA_VLAN

  6. Configure the Port Lockdown setting by selecting Allow Default or Allow Custom. When choosing Allow Custom, ensure that port 1026 for the UDP protocol is included in the custom port list.
  7. Select Finished.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To create a self IP address and associate the self IP with the failover VLAN, use the following command syntax:

    create /net self <IP_addr/mask> vlan <vlan_name>

    For example, the following command creates a self IP address, references the VLAN created in the previous procedure, and enables the default network protocols and services on the VLAN:

    create /net self 10.1.1.1/16 vlan HA_VLAN allow-service default

  3. Save the configuration by entering the following command:

    save /sys config

Enable network failover for the device group

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Device Management > Device Groups.
  3. Select the sync-failover device group in which the VIPRION systems are members.
  4. For Configuration, select Advanced.
  5. For the Network Failover setting, select Enabled.
  6. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable network failover for the device group, use the following command syntax:

    modify /cm device-group <device_grp_name> network-failover enabled

    For example, the following command enables network failover for the device group named My_Group:

    modify /cm device-group My_Group network-failover enabled

  3. Save the configuration by entering the following command:

    save /sys config

Define the failover unicast address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the local host name.

    For example:

    LTM1.example.com (Self)

  4. Select Failover Network.
  5. For Failover Unicast Configuration, select Add.
  6. For Address, choose the self IP address associated with the failover VLAN.

    For example:

    10.0.0.1 (HA_VLAN)

  7. Accept the default port of 1026.
  8. Select Finished.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To define the failover unicast address for the device, specify the self IP address associated with the failover VLAN. To do so, use the following command syntax:

    modify /cm device <hostname> unicast-address {{ ip <self_ip_address> }}

    For example, the following command defines the failover unicast address using the self IP address associated with the failover VLAN:

    modify /cm device LTM1.example.com unicast-address {{ ip 10.0.0.1 }}

  3. Save the configuration by entering the following command:

    save /sys config

Define the failover multicast address

F5 recommends that you provide additional redundancy by defining both unicast and multicast failover addresses for each VIPRION system. As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the management port of each blade for each VIPRION system. The unicast mesh option is discussed later in the Define a unicast mesh (alternative option) section.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, go to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

To define the failover multicast address, perform one of the following procedures:

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the local host name.

    For example:

    LTM1.example.com (Self)

  4. Select Failover Network.
  5. For Failover Multicast Configuration, select Enabled for Use Failover Multicast Address.
  6. Accept the default multicast address and port.
  7. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To define the failover multicast address, port, and interface for the device, use the following command syntax:

    modify /cm device <hostname> multicast-ip <multicast_ip_address> multicast-port <port> multicast-interface <interface>

    For example, the following command defines the failover multicast settings using the management interface:

    modify /cm device LTM1.example.com multicast-ip 224.0.0.245 multicast-port 62960 multicast-interface eth0

  3. Save the configuration by entering the following command:

    save /sys config

Define a unicast mesh (alternative option)

As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the cluster member IP address of each blade in each VIPRION system. The full mesh of unicast entries includes the cluster member IP address for each slot on the VIPRION system that is configured to communicate with the cluster member IP address for each slot on the peer VIPRION system. If you are unable to use the previous multicast option, you may use the unicast mesh option.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, go to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

Note: An explicit management IP firewall rule may be required if the device is affected by Bug ID 780857.

To define a unicast mesh, perform one of the following procedures:

Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the local host name.

    For example:

    LTM1.example.com (Self)

  4. Select Failover Network.
  5. For Failover Unicast Configuration, select Add.
  6. For Address, choose the cluster member IP address that corresponds to slot 1 on the VIPRION system.

    Important: The cluster IP address is not the same as the cluster member IP address. Use only the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration. You can view the cluster member IP address by going to System > Clusters > Management IP Address.

  7. Accept the default port of 1026.
  8. Select Finished.
  9. Repeat steps 1 through 8 for every slot on the VIPRION system.

    Important: Failure to add the cluster member IP address of each blade in the Failover Unicast Configuration may result in failover daemon (sod) communication issues.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list the cluster member IP addresses, enter the following command:

    list /sys cluster members address

  3. To define the failover unicast address for the device, specify the cluster member IP address that corresponds to slot 1 on the VIPRION system. To do so, use the following command syntax:

    modify /cm device <hostname> unicast-address {{ ip <cluster_member_addr> }}

    Important: The cluster IP address is not the same as the cluster member IP address. Only use the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration.

    For example, the following command defines the failover unicast address using the cluster member IP address that corresponds to slot 1 on the VIPRION system:

    modify /cm device LTM1.example.com unicast-address {{ ip 10.0.0.1 }}

  4. Save the configuration by entering the following command:

    save /sys config

  5. Repeat steps 1 through 4 for every slot on the VIPRION system.

    Important: Failure to add the cluster member IP address of each blade in the Failover Unicast Configuration may result in failover daemon (sod) communication issues.
