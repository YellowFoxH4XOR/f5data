Known Issue

The BIG-IP system may incorrectly advertise an unavailable virtual address after using the tmsh load /sys config command.

This issue occurs when all of the following conditions are met:

  • You have enabled a virtual address with the following configuration options:
    • route-advertisement enabled
    • server-scope any

      For example:

      tmsh list ltm virtual-address 1.1.1.1%300 all-properties

      ltm virtual-address 1.1.1.1%300 {
      address 1.1.1.1%300
      app-service none
      arp enabled
      auto-delete true
      connection-limit 0
      description none
      enabled yes
      floating enabled
      icmp-echo enabled
      inherited-traffic-group true
      mask 255.255.255.255
      metadata none
      partition Common
      route-advertisement enabled
      server-scope any
      traffic-group traffic-group-1
      unit 1
      }

    • Your BIG-IP system marks the virtual address as unavailable (red).
    • You use the tmsh load /sys config command to load the BIG-IP configuration into running memory.

    Impact

    Unavailable routes may appear to be available in the route table, and the BIG-IP system may advertise a route for virtual servers that are unable to process traffic.

    Symptoms

    As a result of this issue, you may encounter the following symptom:

    • The imish utility incorrectly advertises routes as available.

      For example:

      imish -r 300 -e 'show ip route K'

      K 1.1.1.1/32 is directly connected, tmm0

      In this example, the imish utility advertises the 1.1.1.1%300 virtual address as available, even though the system marks the actual virtual address as unavailable.

Workaround

There is no workaround for this issue; however, you can mitigate this issue. After running the tmsh load /sys config command, you can modify the virtual-address server-scope value from any to another value, and then back to the any value. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To change the server-scope value, use the following command syntax:

    modify /ltm virtual-address <IP address> server-scope <all|any|none>

    For example, to set the server-scope value for virtual address 1.1.1.1%300 to all, type the following command:

    modify /ltm virtual-address 1.1.1.1%300 server-scope all

  3. To change the server-scope value back to any, type the following command:

    modify /ltm virtual-address 1.1.1.1%300 server-scope any

Note: You must perform this procedure each time you load the configuration using the tmsh load /sys config command.
