Known Issue

This is the result of a known issue. The iRule AES:decrypt command returns a blank string when the BIG-IP LTM system attempts to decrypt b64decoded data.

For example, the following iRule logs a blank string to the /var/log/ltm file:

when RULE_INIT {
  set ::key [AES::key 128]
}
when HTTP_REQUEST {
  log local0. "Straight encrypt/decrypt w/AES:  
  [AES::decrypt $::key [AES::encrypt $::key "This is a test"]]"
  log local0. "Straight encode/decode w/b64:  
  [b64decode [b64encode "This is a test"]]"
  log local0.  "Encrypt & Encode test:  
  [AES::decrypt $::key [b64decode [b64encode\
  [AES::encrypt $::key "This is a test"]]]]"
}

The example iRule should log the following to the /var/log/ltm file:

This is a test

F5 Product Development tracked this issue as CR79907 and it was fixed in BIG-IP 9.3.1, and 9.4.2.  For information about upgrading, refer to the BIG-IP LTM Release Notes.
