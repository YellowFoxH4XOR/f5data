Description

Creating ASM logging traffic to a virtual server on the BIG-IP, with that virtual server configured with a pool with FQDN member(s).
 

Environment

  • ASM
  • Remote Login servers
  • FQDN

Cause

None

 Recommended Actions

  1. Create VIP for the logging traffic
  2. Create pool with FQDN node/s
  3. Create Security log profile

Additional Information

After implementing the Recommended Actions, your should have the following configured objects:

== VIP ==
ltm virtual /Common/vs_10.10.10.152_udp_514 {
    destination /Common/10.10.10.152:514
    ip-protocol udp
    mask 255.255.255.255
    pool /Common/remote
    profiles {
        /Common/udp { }
    }
    source 0.0.0.0/0
    translate-address enabled
    translate-port enabled
}

== pool ==
ltm pool /Common/remote {
    members {
        /Common/LTM1.example.com:514 {
            fqdn {
                autopopulate enabled
                name LTM1.example.com
            }
        }
    }
} 

== security log profile ==
security log profile /Common/vs_10.10.12.103_asm_logProfile {
    application {
        /Common/vs_10.10.12.103_asm_logProfile {
            filter {
                request-type {
                    values { all }
                }
                search-all { }
            }
            format {
                fields { date_time dest_ip dest_port device_id headers http_class_name ip_client policy_name }
            }
            local-storage disabled
            protocol udp
            remote-storage remote
            response-logging all
            servers {
                10.10.10.152:514 { }
            }
        }
    }
}

Note: The security log profile cannot log directly to an FQDN node.
