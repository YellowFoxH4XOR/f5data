Description

In some use cases the BIG-IP may drop Session Initiation Protocol (SIP) calls due to the "Terminate on BYE" option in the SIP profile.  This article will explain how the "Terminate on BYE" configuration option effects SIP traffic.

Environment

  • SIP Profile
  • System sending multiple Call-ID's over a single connection

Cause

If multiple Call-ID's are being sent over a single connection, the BIG-IP may drop calls because of the "Terminate on BYE" option within the SIP profile.  Incorrect usage of this option might result in SIP traffic being dropped by the BIG-IP or processed by an incorrect Virtual Server.  

Note: The "Terminate on BYE" option is enabled by default in the system default SIP profile.

As a result of this option, upon receiving a SIP BYE message, the BIG-IP will remove the connection flow entry (TCP/UDP session) for the specific Call-ID in the BYE message.  This is the desired behavior in cases where a single SIP call (identified by Call-ID) takes place between the SIP Caller <-> BIG-IP <-> SIP Caller.  Especially in UDP's case, this setting will allow the BIG-IP to delete the connection flow, freeing up resources to allow better handling of traffic.  However, in cases where there are multiple SIP calls (multiple Call-ID's) sent over single connection, receiving a BYE on one call will affect other calls which might still be ongoing over the same connection. 

As a result, the BIG-IP will delete the connection flow associated with the SIP call which ended with BYE, and will treat any new SIP messages arriving on the same connection flow as a new connection. Depending on the configuration that might result in packets being dropped or processed by a Virtual Server different then the one that the initial SIP message was used.

For example,  assume a single SIP Client is sending  2 SIP calls (Call-ID_A and Call-ID_B) over the same connection (source IP, destination IP, source port, destination port). Both calls are treated as a single connection flow entry in the BIG-IP.  However, each call might be sent to a different SIP server based on Call-ID value.  Assuming Call-ID_A is short lived, and the BYE message is received while Call-ID_B is still ongoing, the BIG-IP will delete all information for that specific connection (source IP, destination IP, source port, destination port) used for that call. Now, when the SIP server tries to send a SIP message to the SIP Client on Call-ID_B, the packet from the SIP Server to the BIG-IP might be dropped (if there is no Listener matching this packet on Server side) or forwarded if there is a wildcard forwarding Virtual Server present on the server side.

Recommended Actions

F5 recommends keeping the default "enable" value for the "Terminate on BYE" option in the following use case:

  • UDP connection if each client call comes from a unique IP address and no inbound SNATs are configured


F5 recommends changing the value of the "Terminate on BYE" option to disabled within the SIP profile in the following use cases :

  • SIP proxy scenario
  • Call multiplexing on either client or server side
  • Inbound SNAT and consolidating multiple calls into one server-side connection

To disable the "Terminate on BYE" function:

  1. Log into the BIG-IP
  2. Navigate to Local Traffic > Profiles > Services > SIP
  3. Create a new SIP Profile
  4. Modify the "Terminate on BYE" setting to disabled
  5. Save the changes
