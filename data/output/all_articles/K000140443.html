K000140443: ASM Policy is set to Manual Learning Mode, but Policy Builder automatically changed a Parameter Type

Type
Support Solution
Published
2025-05-30
Updated
2025-05-30
Source
https://my.f5.com/manage/s/article/K000140443

Description

When using BIG-IP Advanced WAF a parameter in a security policy may be automatically updated by the Policy Builder, even if Policy Building mode is set to Manual.

Environment

  • BIG-IP Advanced WAF 
  • ASM Policy with Manual Learning Mode

Cause

"Classify Value Content of Learned Parameters" Check is Enabled under Learning and Blocking Settings > Policy Building Settings > Parameters

Recommended Actions

  • Logs when User Created a Parameter named "parameter_1".
info perl[7418]: 01310053:6: ASMConfig change: Parameter parameter_1 [add]: Parameter Name was set to parameter_1.
info perl[7418]: 01310053:6: ASMConfig change: [add]: IncidentType was set to Access from Malicious or Disallowed Source.
info perl[7418]: 01310053:6: ASMConfig change: [update] { audit: component = Policy Builder }
info perl[7418]: 01310053:6: ASMConfig change: Parameter parameter_1 [add]: Parameter Name was set to parameter_1.
info perl[7418]: 01310053:6: ASMConfig change: [add]: IncidentType was set to Access from Malicious or Disallowed Source.
  • Logs when Policy Builder Changed the Parameter type.
 info perl[7418]: 01310053:6: ASMConfig change: Parameter parameter_1 [update]: Parameter Value Type was set to User input value.
  • The policy has the option “Classify Value Content of Learned Parameters” Enabled. This means that new parameters are added to the policy with parameter value type “ignore” – in order to try and determine the appropriate parameter type based on traffic (e.g xml, json, alphanumeric).
  • During the Classification process, that parameter type is set to “ignore” and is not being enforced. Sometimes there is NOT enough traffic, or NOT enough distinct traffic to determine the parameter type.
  • In order to prevent a security hole where the parameter stays “ignore” (unenforced) indefinitely, we have a Periodic Fallback Mechanism even when policy builder in Manual mode. The Fallback Mechanism policy builder forces default parameter type on parameters that do not complete the classification process.
  • The default type ensures some security checks on that parameter (attack signatures, length etc).
