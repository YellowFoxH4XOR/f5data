Description

IP address information in the X-Forwarded-For header with bad reputation which may be considered malicious can be blocked by BIG-IP ASM/Adv WAF Security Policy IP Intelligence (IPI) configuration and IPI license.

Environment

BIG-IP ASM/Adv WAF licensed and provisioned
IP Intelligence licensed

Cause

During Application attacks, malicious bots accessing the application may have a custom or default X-Forwarded-For HTTP header that contains IP address information and may be tested if it has bad reputation and be blocked using IP Intelligence license and BIG-IP ASM/Adv WAF Security policy and IP Intelligence configuration.

Recommended Actions

For the configurations applied to the relevant Virtual Server, make the following changes thru the Configuration utility as an Administrator role user:

Enable Accept XFF in the HTTP Profile
Local Traffic  ››  Profiles : Services : HTTP: Select the HTTP profile: Enable Accept XFF, click save

Enable Trust XFF header in the ASM/Adv WAF security policy
Security  ››  Application Security : Security Policies : Policies List: Select the Security Policy: Enable Trust XFF Header, click save

On the ASM/Adv WAF Security Policy, enable IP Intelligence and its categories
Security  ››  Application Security : IP Addresses : IP Intelligence: Select the Security Policy: enable IP Intelligence and its categories, click save

On the ASM/Adv WAF Security Policy, enable log and block for Access from malicious IP address violation then save and apply the policy changes
Security  ››  Application Security : Policy Building : Learning and Blocking Settings: Select the Security Policy: Enable log and block for Access from malicious IP address violation

Additional Information

Review the generated Application Security event logs in Security  ››  Event Logs : Application : Requests
Access from malicious IP address violations would be generated for the IP address in the X-Forwarded-For HTTP header should it match an enabled IP Intelligence category in the security policy
