K000147478: Why can my client not connect to the site using Websocket and customer certificate?

Type
Support Solution
Published
2024-11-08
Updated
2025-02-21
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000147478

Description

  • You try to connect to websocket.example.com through WebSocket but it fails

Environment

  • F5® Distributed Cloud Load Balancer
  • Customer certificate

Answer/Recommended Actions

  • If you have two domains A and B sharing the same certificate, both enabled for wss and the clients are without SNI, you can configure an HTTP LB with Default-Load Balancer option set to Yes.

  • If the certs are not common, then you require to advertise them on different public VIPs as shown above and mark those LBs as Default-Load Balancer set to Yes.

  • This option introduces concept of default load balancer per Advertise policy. If SNI is missing in the TLS client Hello, default HTTPS LB is selected and certificate of this HTTPS LB is used for TLS session.

Cause

  • The CLIENT HELLO does not have an SNI set
  • Packet capture shows session where the client does not present a SNI in the TLS-Client-Hello at all.

Additional Information

  • If the certificate for both the wss domains are the same, you can configure a single LB with domains a.com and b.com and have:
      • a route to match Host header a.com and assign origin pool A
      • a route to match Host header b.com and assign origin pool B
