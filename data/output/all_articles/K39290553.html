K39290553: device B restarts when attempting a configsync from it's peer device A

Type
Support Solution
Published
2022-08-06
Updated
2025-02-06
Status
Legacy Content
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K39290553

Description

(standby)peer device guest restarts OR stops services when attempting a configsync to standby guest

  • the Active unit tries to push/sync a FIPS key, the Standby cannot validate it and therefore MCPD segfaults with "Unable to read FIPS140 key <..> from peer".
Ex. sys crypto key /Common/glps_hsm_1year {
             key-size 4096
             key-type rsa-private
             security-type 3 <--------
      }

Environment

  • Peer device(cluster) environment
  • FIPS key configuration
  • MCPD Core

Cause

When you test using a FIPS key and don't commit to full configuration

Recommended Actions

Remove FIPS key from device causing peer to crash with the following command:

# tmsh delete sys crypto key <keyname>

Additional Information

Verify customer is using FIPS. And no other FIPS keys exist on the system, only this one. If so remove from offending device that's causing peer to crash/stop services.
In this particular case customer was trying to sync from Active to Standby and Active had the lone FIPS key and that was causing the Standby to crash/restart services.
