Description

Some urls are failing in the web application after upgrade from 15.x to 17.x

A packet capture shows that responses from the pool member are reset (RST) with the reset cause given as [F5RST: Malformed HTTP header error].

Environment

  • BIG-IP
  • Upgrade from v15.1.10.2 (or lower)  to v17.x 

Cause

This is because the application in the backend pool member server is sending HTTP header(s) that violate the HTTP RFC and can be potentially vulnerable to attack.

In a packet capture showing traffic between a pool member server and the BIG-IP, you may see that Multiple Transfer-Encoding headers are returned from 

the pool member, resulting in the BIG-IP resetting those requests:

<...>
Transfer-Encoding: chunked\r\n   <--- first Transfer-Encoding header
<...>
Transfer-Encoding: chunked\r\n   <--- duplicate Transfer-Encoding header
<...>

Recommended Actions

The best solution is to fix the backend application that is sending non-compliant HTTP headers. 

If you cannot remediate the backend behaviour, you can investigate setting Proxy Mode to Transparent in the HTTP profile being used. 

    It may also be possible to remedy the issue by using an irule to remove non-rfc-compliant headers, but this is beyond the scope of F5 Technical Support. You can engage F5 Professional Services or the DevCentral Community site
