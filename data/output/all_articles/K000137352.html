K000137352: BIGIQ: LDAPs auth not working. The error "java.security.cert.CertificateException"

Type
Support Solution
Published
2023-10-25
Updated
2023-10-25
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000137352

Description

The BIGIQ Administrator may want to configure the remote authentication using LDAPS and observes the following error in GUI during login attempt:

Unable to connect to the authentication server. java.security.cert.CertificateException: No subject alternative names matching IP address 1.1.1.1 found

Environment

  • BIGIQ
  • Remote Authentication
  • LDAPS

Cause

1) In CM GUI under 'System -> User Management -> <LDAPS_provider_name> -> Servers' setting, the BIGIQ administrator may define the Server as IP 1.1.1.1 but not FQDN

2) But at the same time in CM GUI under 'System -> User Management -> <LDAPS_provider_name> -> SSL Certificate', the certificate is defined which has the SAN extension where LDAPS server is defined as FQDN but not IP. For example, we can review the uploaded certificate using openssl tool:

# openssl x509 -in cert-example.crt -text -noout

Certificate:

Data:

Version: 3 (0x2)

Serial Number:

[...]

Signature Algorithm: sha256WithRSAEncryption

Issuer: [...]

Validity

Not Before: Dec 1 03:33:58 2022 GMT

Not After : Dec 1 03:33:58 2023 GMT

Subject: [...] CN=ldaps.example.com

[...]

X509v3 Subject Alternative Name:

DNS:ldaps.example.com <<< (!)

[...]

3) As result of such config, the BIGIQ administrator during login via remote LDAPS will see the error:

Unable to connect to the authentication server. java.security.cert.CertificateException: No subject alternative names matching IP address 1.1.1.1 found

Recommended Actions

Make sure that In CM GUI under 'System -> User Management -> <LDAPS_provider_name> -> Servers' setting, the Server value matches with SAN extension of certificate.
