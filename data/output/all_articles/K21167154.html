Description

When tcp_echo is used as a default monitor, both nodes and pool members are marked in Offline state.
Also, if a customized monitor is created using the TCP Echo monitor as parent, pool members are marked Offline too.
If an icmp monitor is used instead, nodes are marked Available.

When using a TCP Echo monitor, the BIG-IP sends the initial SYN to port 7 but it receives a RST, ACK from node.
10.16.20.1    10.16.20.10    TCP    OUT s1/tmm1 : 40996 → 7 [SYN] Seq=0 Win=29200 Len=0 
10.16.20.10    10.16.20.1    TCP    IN  s1/tmm1 : 7 → 40996 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0

Environment

  • Monitoring of nodes
  • Nodes and pool members are marked in offline state when using a TCP Echo monitor 
  • There is successful connectivity between the BIG-IP and nodes

Cause

The tcp_echo service is not enabled in the server side.


Recommended Actions

  1. Make sure that the node is configured to respond to the tcp_echo monitor, this is a monitor type that requires that you enable TCP echo service on the monitored nodes.

  2. For example, to enable echo service in Linux nodes, install xinetd and adjust settings in file: /etc/xinetd.d/echo

$ apt-get install xinetd
$ nano /etc/xinetd.d/echo
# default: off
# description: An xinetd internal service which echo's characters back to
# clients.
# This is the tcp version.
service echo
{
        disable         = yes  <---- 
        type            = INTERNAL
        id              = echo-stream
        socket_type     = stream
        protocol        = tcp
        user            = root
        wait            = no
}

# This is the udp version.
service echo
{
        disable         = yes
        type            = INTERNAL
        id              = echo-dgram
        socket_type     = dgram
        protocol        = udp
        user            = root
        wait            = yes
}

After changing service echo setting to disable = no restart xinetd: 

$ sudo service xinetd restart
 

    3. TCP Echo monitor now can be used and nodes should be marked as available.
