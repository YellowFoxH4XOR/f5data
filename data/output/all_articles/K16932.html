Topic

You should consider using this procedure under the following condition:

  • You want the BIG-IP system to suppress sending SSL access (ssl_acc) and request (ssl_req) messages to remote syslog servers.

Description

When users navigate the Configuration utility or the BIG-IP services iControl requests, the BIG-IP system's Apache service generates ssl_acc and ssl_req messages on each inbound request. Beginning in BIG-IP 11.0.0, the system suppresses these messages from being logged locally. However, the messages are not suppressed when the BIG-IP system is configured to log to remote syslog servers. As a result, remote log servers may log excessive numbers of log messages similar to the following examples:

  • logger: [ssl_acc] 192.168.10.11 - admin [01/Jan/2015:12:00:01 -0800] "/xui/update/configuration/alert/statusmenu/coloradvisory" 200 1150
    logger: [ssl_req][01/Jan/2015:12:00:01 -0800] 192.168.10.11 TLSv1 DHE-RSA-AES256-SHA "/xui/update/configuration/alert/statusmenu/coloradvisory" 1150
  • logger:.[ssl_acc].127.0.0.1.-.-.[01/Jan/2015:12:05:01.+0900]."/iControl/iControlPortal.cgi".200.755.
    logger:.[ssl_req][01/Jan/2015:12:05:01.+0900].127.0.0.1.TLSv1.RC4-SHA."/iControl/iControlPortal.cgi".755.

The large number of these messages being logged may become a nuisance and hinder your ability to identify meaningful messages that are logged. To filter these messages and suppress them from being sent to a remote syslog server, you can configure syslog to use one of the following filters within an include statement:

filter f_ssl_acc_req {
    not (facility(local6) and level(info) and filter(f_httpd_ssl_acc)) and
    not (facility(local6) and level(info) and filter(f_httpd_ssl_req));
};

If your current syslog configuration already uses an include statement to specify the destination syslog servers, then you need to configure the current include statement to also use the filter listed previously. To do so, perform the following task:

  • Modify existing syslog include statement to use the desired filter

If your current syslog configuration specifies the destination syslog servers using the remote-servers command, you must first remove the currently defined remote-servers and then configure a syslog include statement that defines a filter rule and the destination syslog servers. To do so, perform the following tasks:

  • Removing the currently defined remote syslog servers
  • Defining a syslog include statement with filter rule and destination syslog server

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrator access to the Traffic Management Shell (tmsh).
  • You have some knowledge of syslog filtering rules.
  • You are able to use the vi text editor.
  • The BIG-IP system is configured for remote logging.

Procedures

Modifying existing syslog include statement to use the desired filter

To modify an existing syslog include statement to use a filter to suppress the unwanted SSL access and request messages, perform the following procedure:

Impact of procedure: The BIG-IP system will now suppress (filter) SSL access and request messages from the messages sent to remote syslog servers.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To edit the current syslog configuration, enter the following command:

    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
      auth-priv-from notice
      auth-priv-to emerg
      cron-from warning
      cron-to emerg
      daemon-from notice
      daemon-to emerg
      description none
      include "
        filter f_remote_loghost {
        level(debug..emerg);
      };

      destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
      };

      log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
      };"
      iso-date disabled
      kern-from notice
      kern-to emerg
      mail-from notice
      mail-to emerg
      messages-from notice
      messages-to warning
      remote-servers none
      user-log-from notice
      user-log-to emerg
    }

  3. Modify the filter configuration to include the following filter definitions:

    not (facility(local6) and level(info) and filter(f_httpd_ssl_acc)) and
    not (facility(local6) and level(info) and filter(f_httpd_ssl_req));

    After modifying the include statement, the syslog configuration appears similar to the following example:

    modify syslog {
      auth-priv-from notice
      auth-priv-to emerg
      cron-from warning
      cron-to emerg
      daemon-from notice
      daemon-to emerg
      description none
      include "
        filter f_remote_loghost {
        level(debug..emerg) and
        not (facility(local6) and level(info) and filter(f_httpd_ssl_acc)) and
        not (facility(local6) and level(info) and filter(f_httpd_ssl_req));
      };
        destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
      };
      log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
      };"
      iso-date disabled
      kern-from notice
      kern-to emerg
      mail-from notice
      mail-to emerg
      messages-from notice
      messages-to warning
      remote-servers none
      user-log-from notice
      user-log-to emerg
    }

  4. Exit the text editor by typing the following key sequence:

    :wq!

  5. At the following prompt, enter y to save the changes to the file:

    Save changes? (y/n/e)

    The tmsh utility prompt returns.

    Note: If the syslog filter contained syntax errors, the tmsh utility returns the following prompt: There were errors. Continue editing (y) or discard changes (n) (y/n)

    The BIG-IP system now sends syslog traffic to the remote servers using the defined syslog filter.

  6. Save the configuration by entering the following command:

    save /sys config partitions all

Removing the currently defined remote syslog servers

You must remove the current defined remote syslog servers before you configure the include statement with the filter rule and destination server. To do so, perform the following procedure:

Impact of procedure: Log messages are not sent to the currently defined remote syslog servers until the remote syslog servers are re-added in the following procedure.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list any currently defined remote syslog servers, if configured, enter the following command:

    list /sys syslog remote-servers

    The following is an example of the command output on a BIG-IP system that is configured with a remote syslog server at IP address 10.11.16.252:

    sys syslog {
        remote-servers {
        host 10.11.16.252
        }
    }

    Take note of any currently defined remote syslog server information; you need it in the following procedure.

  3. To remove the currently defined remote syslog servers, enter the following command:

    modify /sys syslog remote-servers none

  4. Save the change by entering the following command:

    save /sys config partitions all

Defining a syslog include statement with a filter rule and destination syslog server

Impact of procedure: The BIG-IP system now suppresses (filters) SSL access and request messages from the messages sent to remote syslog servers.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To define the syslog filter that references the remote server, enter the following command:

    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
      auth-priv-from notice
      auth-priv-to emerg
      cron-from warning
      cron-to emerg
      daemon-from notice
      daemon-to emerg
      description none
      include none
      iso-date disabled
      kern-from notice
      kern-to emerg
      mail-from notice
      mail-to emerg
      messages-from notice
      messages-to warning
      remote-servers none
      user-log-from notice
      user-log-to emerg
    }

  3. Replace the include none line with the syslog filter and destination remote syslog servers.

    For example, to configure syslog to filter out SSL access and request messages when sending messages to a remote syslog server at IP address 10.11.16.252 on UDP port 514, use the following include statement:

    include "
      filter f_ssl_acc_req {
        not (facility(local6) and level(info) and filter(f_httpd_ssl_acc)) and
        not (facility(local6) and level(info) and filter(f_httpd_ssl_req));
      };
      destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
      };
      log {
        source(s_syslog_pipe);
        filter(f_ssl_acc_req);
        destination(d_remote_loghost);
      };"

    After you add the filter rule, the syslog configuration appears similar to the following example:

    Note: It is important to match the format of the file; otherwise this may not work as expected

    modify syslog {
      auth-priv-from notice
      auth-priv-to emerg
      cron-from warning
      cron-to emerg
      daemon-from notice
      daemon-to emerg
      description none
      include "
        filter f_ssl_acc_req {
        not (facility(local6) and level(info) and filter(f_httpd_ssl_acc)) and
        not (facility(local6) and level(info) and filter(f_httpd_ssl_req));
      };
      destination d_remote_loghost {
        udp(\"10.11.16.252\" port(514));
      };
      log {
        source(s_syslog_pipe);
        filter(f_ssl_acc_req);
        destination(d_remote_loghost);
      };"
      iso-date disabled
      kern-from notice
      kern-to emerg
      mail-from notice
      mail-to emerg
      messages-from notice
      messages-to warning
      remote-servers none
      user-log-from notice
      user-log-to emerg
    }

  4. Exit the text editor by entering the following key sequence:

    :wq!

  5. At the following prompt, enter y to save the changes to the file:

    Save changes? (y/n/e)

    The tmsh utility prompt returns.

    Note: If the syslog filter contained syntax errors, the tmsh utility returns the following prompt: There were errors. Continue editing (y) or discard changes (n) (y/n)

    The BIG-IP system now sends syslog traffic to the remote servers using the defined syslog filter.

  6. Save the configuration by entering the following command:

    save /sys config partitions all
