Known Issue

The BIG-IP system may revert a 0 ratio setting of a DNS (formerly known as GTM) pool member to the default value of 1 after upgrading to 11.x or 12.0.0.

This issue occurs when all of the following conditions are met:

  • You upgrade the BIG-IP DNS system from 10.x to 11.x through 12.0.0.
  • You have configured a BIG-IP DNS pool member with the ratio value of 0 so it will not be selected during load balancing.

Impact

BIG-IP DNS pool members that are not intended to be selected during load balancing will be selected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H563576 on the Diagnostics > Identified > High screen.
  • A BIG-IP DNS pool member that previously had a ratio value of 0 will have a ratio value of 1 after upgrading the BIG-IP system from 10.x to 11.x through 12.0.0.

Workaround

To work around this issue, you can change the ratio setting of any affected pool members back to 0 after upgrading the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Change the ratio setting of an affected pool member to 0 by typing the following command:

    modify /gtm pool <pool_name> members modify { <server_name>:<member_name> {ratio 0} }

    For example:

    modify /gtm pool example_pool members modify { example_server:example_member {ratio 0} }

  3. Repeat step 2 for all affected pool members.
  4. Save the configuration change by typing the following command:

    tmsh save sys config gtm-only

    Note: Step 4 is necessary only if Automatic Configuration Save is disabled.

  5. To exit the tmsh utility, type q and press Enter.
