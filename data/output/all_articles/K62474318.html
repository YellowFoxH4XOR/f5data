Description

  • TMM is restarting without any unusually high resource consumption, such as memory pressure or CPU usage.
  • A core was not generated in /var/core around the time TMM was restarted.
  • Logs messages do exist, but many expected messages are not present, as described below:
    • /var/log/kern.log does not show any trace oom killer run.
    • /var/log/tmm* does not show anything that indicates it restarted
      notice detach hsb_lbb0.
      notice ePVA firmware snoop vers(0x2:0x1), features: 0x200691edff, attached:no, pde:9.
      notice ePVA: disable ePVA per request.
      notice hsb3: pde dma stopped
      notice hsb3: pde detached
      notice ---------------------------------------------
      notice Day_of_Week Mon Day HH:MM:SS Timezone YYYY
    • /var/log/daemon.log shows only tmm and tmipsecd restarted
      emerg logger: Re-starting tmm
      emerg logger: Re-starting tmm1
      emerg logger: Re-starting tmm2
      emerg logger: Re-starting tmm3
      emerg logger: Re-starting tmipsecd
    • /var/log/ltm shows tmm interfaces are down, but several minutes before configsync completion was recorded
      notice mcpd[pid]: 010714a0:5: Sync of device group /Partition_Name/Device_Group_Name to commit id ***** ******************* /Partition_Name/Device_Name1 0 from device /Partition_Name/Device_Name2 complete.
      ...
      notice mcpd[pid]: 01070406:5: Removed publication with publisher id TMM*
      warning tmm[pid]: 01230002:4: Interface 0.1: link is down
      warning tmm2[pid]: 01230002:4: Interface 0.3: link is down
      warning tmm3[pid]: 01230002:4: Interface 0.4: link is down

      Or  tcpdump was taken:

      013e0000:5: Tcpdump starting locally on 127.1.1.2:2 from 127.1.1.254:45634

Environment

  • BIG-IP v13.0.0 - 13.1.1
  • TMM restarting

Cause

Memory fragmentation
Bug ID 722893

Recommended Actions

Upgrade to fixed versions 13.1.3 or greater.
 

Additional Information

If you are running on v13.0.0 - 13.1.1 check memory fragmentation status by running below command

cat /proc/buddyinfo
 
Example output is below:
Node 0, zone      DMA      0      1      0      0      2      1      1      0      1      1      3
Node 0, zone    DMA32     84     74     55     38     24     13      4      1      6      2     22
Node 0, zone   Normal  17623   3885    463     81     18      3      0      0      0      0      0

Zeros on the right in the above output indicates that no more memory can be allocated, fragmentation has occurred and TMM is likely to be restarted because of this issue.
According to the above example output, there is 128K of memory available blocks are 3 and larger size of the blocks are 0.

When you see this fragmentation, you will be able to avoid TMM restarts by rebooting BIG-IP, in maintenance window if possible.
