Issue

The BIG-IP system's log files may include error messages that appear similar to the following example:

Note: These particular error messages are from the /var/log/ltm file.

mcpd[2239]: 01070638:6: Cumulative log rate exceeded!  Throttling all non-debug logs.
mcpd[2239]: 01070727:6: Per-invocation log rate exceeded; throttling.
mcpd[2239]: 01070727:6: Resuming log processing at this invocation; held 22 messages.
mcpd[2239]: 01071682:5: Re-enabling general logging; held 25 messages.

These error messages are informative. They indicate that the BIG-IP system is regulating logging for a particular error message.

The first error message indicates that more than 20 log messages were logged from the same module within a two-second interval, not counting logs that have already been throttled. The message ID used in this error message is copied over from the log message that first triggered it, however cumulative throttling can apply to several message ID's belonging to the same module.

The second error message indicates that more than five log messages with the same message ID were logged within a one-second interval.

Note: The message ID is the eight-digit hexadecimal number that precedes the error message being throttled. For example, the message IDs of the previous errors are 01070727 and 01070638. For cumulative log throttling, the first four characters of the message ID identify the module being throttled, so both 01070727 and 01070638, which start with 0107, can count against the threshold for cumulative rate limiting.

The third error message indicates that the BIG-IP system is resuming log processing for the rate limited error message with message ID 01070727. 

The fourth error message indicates that the BIG-IP system is resuming general log processing for the module throttled by cumulative rate limiting and identified by the message ID prefix 0107. The message ID logged here belongs to first message generated by the BIG-IP system after the condition that triggered cumulative rate limiting has subsided and will not necessarily match the message ID logged when cumulative rate limiting started.

Note: Although the log resumption messages indicate that the messages have been held, the held messages are not available for review.

For example, if the BIG-IP system logs the following error message five times within a one second interval, the Per-invocation log rate exceeded; throttling error message is logged to the /var/log/ltm file:

mcpd[2239]: 01070727:5: Pool member 10.10.10.1:80 monitor status up.
