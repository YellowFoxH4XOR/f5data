Description

[2022-07-19T20:34:29.775Z] "POST /post HTTP/1.1" 502 - direct_response - "-" 0 0 0 - "-" "curl/7.83.1" "117e0fc3-fe45-44b2-9bcd-3eb7612a049e" "alex.httpbin-nosidecar.com" "-" - - 10.100.96.14:8000 192.168.27.220:35804 - block_all

Environment

  • Kubernetes: 1.17.x, 1.18.x, 1.19.x, 1.20.x
  • Aspen Mesh: 1.11.x

Cause

The application may be using 127.0.0.x/lo to make the requests out or using one of the ports used by Istio.

Sidecar networking changed in Istio 1.10 by updating the Envoy proxy to send traffic by default to applications on eth0 rather than lo. On older versions of Istio the sidecar would intercept pod traffic and forward it to the user application on localhost. Users had to make sure their apps were listening on localhost for things to work. Starting with 1.10, the sidecar redirects traffic to eth0. This change makes Istio work out of the box with popular stateful applications, but to that end, user applications that are bound exclusively to localhost need to be modified or Sidecar resource needs to be defined as shown in the below Recommend Actions section.

Recommended Actions

  • Make sure the application uses eth0 or 0.0.0.0.

  • Explicitly configure the port using the Sidecar ingress configuration to send to lo, preserving the old behavior.

    For example, to configure request to be sent to localhost for the ratings application:

    apiVersion: networking.istio.io/v1beta1
    kind: Sidecar
    metadata:
      name: ratings
    spec:
      workloadSelector:
        labels:
          app: ratings
      ingress:
      - port:
          number: 8080
          protocol: HTTP
          name: http
        defaultEndpoint: 127.0.0.1:8080
