Known Issue

This is the result of a known issue. When you upload multiple copies of a file through FirePass, the FirePass controller should move the current copy of the file to a new file, which has the original file name with a .bak extension, and discard any existing .bak file. However, when you upload a file through a Microsoft Windows files portal multiple times, the FirePass controller will only create a backup copy if a backup copy does not already exist. Additionally, if the revised file is smaller in size than the original file, the new file will contain the additional data of the original file that exceeds the original file size. For example:

Original file data : 123456
new file data before uploading : acbd
resulting file data after uploading : abcd56

F5 Product Development tracked this issue as ID 294057 (formerly CR112166), and the issue was fixed in FirePass 7.0.0. For information about upgrading, refer to the FirePass release notes.

Additionally this issue has been fixed in cumulative hotfix HF-610-3-1 issued for FirePass 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
