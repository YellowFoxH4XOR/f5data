Description

When using DNS (GTM) virtual server auto-discovery to populate virtual servers found on LTM's, virtual servers that are configured with traffic-matching-criteria (TMC) will not be discovered.  Similarly, if such virtual servers are manually added to the gtm server object, they will not be able to be monitored with the 'bigip' GTM monitor type.

Environment

  • BIG-IP DNS
  • Virtual Server auto-discovery or 'bigip' type monitor
  • LTM Virtual Server(s) with Traffic Matching Criteria (TMC) 

Cause

Starting in BIG-IP 14.1.0, you can configure LTM virtual servers to listen on multiple ports and/or multiple IP addresses using the 'traffic-matching-criteria' feature. However, these types of virtual servers do not have a 'destination' parameter, and as a result they can not be discovered, or monitored, by the 'bigip' monitor type (other monitor types will work)

Recommended Actions

The virtual server details (name, destination, port) can be manually added to the GTM server object's configuration, with auto-discovery set to 'no-delete', but the bigip monitor will still not be able to pull virtual server status information from the LTM for that virtual server, and will set the status down with a reason of "big3d : timed out".  Because it is not possible to remove the 'bigip' type monitor from a GTM server of type BIG-IP,  the affected virtual servers should instead be added to a new or existing GTM server of type 'generic -host', which can be configured with a dummy IP address, but will allow a non-bigip monitor type to be associated with it.  

The virtual server can be added to any GTM server of type generic-host or generic-load-balancer that has the same data-center value, but for ease of administration, it makes sense to create a generic-host for each LTM that has TMC virtuals on it.

The TMC virtual server should also be removed from any GTM server of type BIG-IP, so that a bigip monitor instance is applied to the same target IP and port.

Create, or use an existing  'dummy' GTM server object for the affected virtuals 

  1. Log into the Configuration Utility.
  2. Navigate to DNS > GSLB > Servers > Server List.
  3. Click on an existing GTM server of type Generic Host, or create a new one.
  4. Enter an appropriate name for the new GTM server, for example, it could be a name based on the existing GTM server object, with a _tmc suffix.
  5. Click on the Virtual Servers Tab.
  6. Click on Add, and enter the relevant details (name, IP address, port)
  7. Click Finished.
