Topic

In versions of FirePass controller software up to and including version 6.0.2, you could create self-signed certificates (SSL server certificates, client root certificates and client certificates) that had lifetimes of 30 years using the FirePass internal PKI from the FirePass Administrative Console. However, because certificates with 30-year lifetimes that are created on or after January 19th, 2008 will have their valid to field beyond 2038, these certificates encounter the "Year 2038 Problem".  Because the data structure that stores time in seconds past January 1, 1970 on UNIX and Linux-based systems will reach its maximum value and roll over, a certificate intended to have an expiration date beyond January 19, 2038 will instead be created with the "two's complement" year (1902 instead of 2038; 1903 for 2039, and so on).

In order to avoid issues associated with the Year 2038 Problem, F5 will release hotfixes for supported versions of FirePass software that will remove the option to create self-signed certificates with 30-year lifetimes, and eliminate the possibility of encountering issues associated with these certificates. When creating a self-signed SSL server certificate, client root certificate or client certificate, the drop-down menu to select the Expiration will no longer include the value 30 years.
