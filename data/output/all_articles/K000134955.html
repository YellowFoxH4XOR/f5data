K000134955: TLS/SSL Weak Message Authentication Code Cipher Suites for port 4353 management IP Sync, CMI or Big3d

Type
Support Solution
Published
2023-06-07
Updated
2023-08-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.1
Source
https://my.f5.com/manage/s/article/K000134955

Description

  • Various scanners such as Qualsys will sometimes flag the management interface as having a weak SSL cipher or a weak SSL/TLS algorithm on port 4353
  • Port 4353 is home to both big3d and the internal sync channel however the internal sync channel is not exposed to most ssl handshakes
  • This document will help you determine how to modify the ciphers needed to pass the security scan

Environment

  • Big-IP LTM/DNS/AFM/ASM/APM
  • Management port 4353 ciphers

Cause

Port 4353 is what big3d uses to communicate iquery information to gtmd for dns mesh sync groups and LTM/DNS topology. Big3d isn't accessible without proper certificate authentication but when a security scanner attempts to scan that port it may see the ciphers that we offer. The CMI or sync group daemon also exists on port 4353 but an external scanner can not typically generate a handshake with it because it requires a very specific set of conditions within the data to even trigger it to respond. Big3d will virtually always respond on port 4353 to any requests and not F5 internal synchronization listners.

 

 Recommended Actions

  1. If your scanner returns a weak SSL cipher we suggest using these documents to configure the desired cipher strength. Note: Diffie Hellman and ECDH ciphers don't work due to ID936417
    1. You can configure the desired cipher strength settings using TMSH
      1. https://my.f5.com/manage/s/article/K05713133
    2. You can configure the desired cipher strength settings using TMUI/GUI
      1. https://my.f5.com/manage/s/article/K31434426
    3. You can also configure the minimum TLS version
      1. https://my.f5.com/manage/s/article/K71057100
    4. This document goes into depth on how to then test those ciphers
      1. https://my.f5.com/manage/s/article/K53566503

Additional Information

If you believe that your security scanner is somehow reaching F5's secure sync group then please grab a packet capture during the issue with full noise. Something such as:

tcpdump -s0 -nni 0.0:nnn host <ip of scanner device> -w /var/tmp/scan_test_${HOSTNAME}.pcap

 

Inside that packet capture, you would be looking for a virtual server name in the low details that contains cgc. Please note that this is exceptionally rare to encounter as it is a very well hidden and secured connection.
