Known Issue

A memory leak may occur when Credit-Control-Request Initialization (CCR-I) messages are being dropped by an iRule.

This issue occurs when all of the following conditions are met:

  • An iRule using the DIAMETER_EGRESS event is associated with the diameter virtual server.
  • Incoming diameter traffic with CCR-I messages arrives at the affected virtual server.

Impact

TMM memory may eventually be exhausted and may result in the system producing a core file. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The associated iRule was dropping the CCR-I diameter messages.

    An example of the iRule:

    when DIAMETER_EGRESS {
          if { [DIAMETER::command] == 272 } {
             log local0.info "Dropping this intial"
             DIAMETER::drop
          }
    }

  • The iRule dropping the CCR-I messages prevents the CCR initial request notification from being sent to the application layer.
  • TMM memory consumption steadily increases over time.
  • If configured as a high-availability pair, the BIG-IP system may fail over to the standby system.
  • The BIG-IP system may generate a TMM core file to the /shared/core directory.
