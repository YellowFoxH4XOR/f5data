K000138234: Getting "Cannot detect the AppProtect version, open /opt/app_protect/VERSION: no such file or directory" error when creating Ingress Controller deployment with pre-built images.

Type
Support Solution
Published
2024-01-15
Updated
2024-01-15
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 3.4.0, 3.3.1, 3.3.0
Source
https://my.f5.com/manage/s/article/K000138234

Description

After enabling Nginx App Protect (NAP) using pre-built images, the pod won't start and the error below will be shown in the logs:

        - args:
          - -nginx-plus=true
          - -nginx-reload-timeout=60000
          - -enable-app-protect=true

➜   kubectl get pods -n nginx-ingress
NAME                                            READY   STATUS             RESTARTS           AGE
nic-nginx-ingress-controller-6b7859f457-qf55k   0/1     CrashLoopBackOff   1 (3m59s ago)   3d16h

I0110 14:56:26.600927 1 main.go:260] Kubernetes version: 1.27.8
I0110 14:56:26.610004 1 main.go:406] Using nginx version: nginx/1.25.1 (nginx-plus-r30-p1)
F0110 14:56:26.610039 1 main.go:419] Cannot detect the AppProtect version, open /opt/app_protect/VERSION: no such file or directory

 

Environment

Nginx Ingress Controller: 3.4.0

Cause

This error is shown because the deployment is trying to enable Nginx App Protect (NAP) using a pre-built image that does not include NAP.

Recommended Actions

If you are using pre-built images, make sure you pick the right image that includes NAP, you can see available images here.
If you are building your image from source code, please review the following documentation.

Additional Information

After choosing the right image, the pods should come up with no issues and if we look at the logs from the Ingress Controller pod, we can see App Protect is enabled correctly:

➜   kubectl get pods -n nginx-ingress
NAME                                            READY   STATUS    RESTARTS   AGE
nic-nginx-ingress-controller-7c76d74b6c-g64qx   1/1     Running   0          2m51s
