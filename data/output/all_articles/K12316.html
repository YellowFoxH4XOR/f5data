Known Issue

This is the result of a known issue. On a VIPRION system, the configuration of a child profile may become out of sync between the primary and secondary blades.

For example:

  • A new Client SSL profile named test_clientssl is created on a VIPRION system. Its parent profile is the default Client SSL profile and no settings were changed from their default values when the profile was created. The test_clientssl profile is expected to inherit all settings from its parent profile.
  • If at this stage the bigpipe profile clientssl test_clientssl list command is executed on every blade installed in the system, all blades return the following output:

    profile clientssl test_clientssl {
    defaults from clientssl
    }

    This is the expected behavior and indicates that the profile inherits all settings from its parent profile.

  • However, if the services are restarted on all blades, and the bigpipe profile clientssl test_clientssl list command is executed again, the command output will no longer match across all blades.

    The primary blade will continue to return the expected output:

    profile clientssl test_clientssl {
    defaults from clientssl
    }

    While all secondary blades will return the following output:

    profile clientssl test_clientssl {
    defaults from clientssl
    mode enable
    key "default.key"
    cert "default.crt"
    ciphers "DEFAULT"
    options dont insert empty fragments
    cache size 262144
    cache timeout 3600
    renegotiate period indefinite
    renegotiate size indefinite
    renegotiate max record delay 10
    handshake timeout 60
    alert timeout 60
    authenticate once
    authenticate depth 9
    unclean shutdown enable
    }

    This is not the expected behavior. As it can be observed from the above command outputs, the secondary blades are no longer inheriting all setting for the test_clientssl profile from the default Client SSL profile; instead, a number of settings have been imported from the parent profile and are now directly declared in the test_clientssl profile.

  • As a result, if the parent profile is modified, the test_clientssl profile on all secondary blades will not inherit the changes, and will continue to use the settings that it directly declares. For instance, if the Ciphers setting of the parent profile is changed from DEFAULT to @SPEED:HIGH, all secondary blades will continue to use the DEFAULT setting, because this is directly declared in the test_clientssl profile.

F5 Product Development tracked this issue as ID 338148 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, or PSM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue by reloading the configuration of the VIPRION system from disk. To do so, enter the bigpipe load command from the command line of the primary blade. Performing this operation restores all child profiles on all blades to their expected configuration.
