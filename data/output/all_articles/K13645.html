Known Issue

The BIG-IP system incorrectly creates two persistence entries instead of one. This issue occurs when all of the following conditions are met:

  • A virtual server is configured with a SIP profile
  • The virtual server is assigned an iRule that adds a persistence entry using the SIP traffic Call-ID header by performing the persist add sip <Call-ID> command
  • The received SIP traffic contains a backslash ( \ ) character in the value of the Call-ID header

According to RFC3261, the backslash character is a legitimate value for the Call-ID header.

Impact

The duplication of persistence entries is a cosmetic issue and does not affect traffic processing on the BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you enter the tmsh show ltm persistence persist-records all-properties command, the BIG-IP system displays two SIP persistence entries instead of one. For example, when the BIG-IP system receives SIP traffic that has ab\c@20.20.20.50 as the value of the Call-ID header field, BIG-IP displays the following SIP persistence entries:

    Sys::Persistent Connections
    sip - 20.20.20.30:5060 - 10.10.22.211:5060
    ------------------------------------------
    TMM 1
    Mode sip
    Key ab\c@20.20.20.50
    Age (sec.) 69
    Virtual Name sip-vip
    Virtual Addr 20.20.20.30:5060
    Node Addr 10.10.22.211:5060
    Pool Name sip-pool
    Client Addr 20.20.20.156

    sip - 20.20.20.30:5060 - 10.10.22.211:5060
    ------------------------------------------
    TMM 0
    Mode sip
    Key abc@20.20.20.50
    Age (sec.) 69
    Virtual Name sip-vip
    Virtual Addr 20.20.20.30:5060
    Node Addr 10.10.22.211:5060
    Pool Name sip-pool
    Client Addr 20.20.20.156

    Total records returned: 2
