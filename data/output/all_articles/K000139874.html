K000139874: DEVICE-0206: BIG-IP Next instance discovery error failed to verify certificate

Support Solution
Published
2024-06-05
Updated

Applies to

  • BIG-IP Next Central Manager: 20.2.X, 20.2.0
Source
https://my.f5.com/manage/s/article/K000139874

Description

When you attempt to add a BIG-IP Next instance on the BIG-IP Next Central Manager, the BIG-IP Next Central Manager fails to add returns an error similar to the following example:

DEVICE-0206: BIG-IP Next instance discovery error: Failed to login to instance x.x.x.x with error: rpc error: code = Unknown desc = tls: failed to verify certificate: x509

Environment

  • BIG-IP Next Central Manager 20.2.0 and later

Cause

The BIG-IP Next Central Manager 20.2.0 and later requires that the BIG-IP Next instance uses a TLS certificate with well formed Subject Alternative Names (SAN). The IP option in SAN must equals to the management IP of BIG-IP Next instance.

Recommended Actions

You can run the script below on BIG-IP Next Central Manager or any Linux which installed OpenSSL to create a new TLS certificate and then upload to BIG-IP Next instance to replace the TLS certificate currently used.  Need to change the first 3 lines to match your BIG-IP Next instance settings.

IP=192.168.80.16             #set ip of BIG-IP Next instance
api_username=admin           #set username of BIG-IP Next instance
api_password='admin'      #set password of BIG-IP Next instance
  
#genereate cert contains SAN DNS and IP
token=$(curl -sk -u "$api_username:$api_password" https://$IP:5443/api/v1/login |jq ".token"|tr -d '"')
hostname=$(curl -sk -X GET  -H "Authorization: Bearer $token"  https://$IP:5443/api/v1/systems|jq '._embedded.systems[].hostname'|tr -d '"')
DNS=$hostname
echo "DNS $DNS"
mkdir test_certs 2> /dev/null
n=$RANDOM
openssl genrsa -out test_certs/ca$n_key.pem 4096
openssl req -new -x509 -nodes -days 3600 -key test_certs/ca$n_key.pem -out test_certs/ca$n.pem -subj "/C=US/ST=Washington/L=Seattle/O=$DNS/CN=$DNS" -addext "subjectAltName = DNS:$DNS,IP:$IP"
openssl req -newkey rsa:4096 -nodes -keyout test_certs/key$n.pem -out test_certs/req$n.csr -subj "/C=US/ST=Washington/L=Seattle/O=$DNS/CN=$DNS" -addext "subjectAltName = DNS:$DNS,IP:$IP"
openssl x509 -req -extfile <(printf "subjectAltName = DNS:$DNS,IP:$IP") -days 3500 -set_serial 01 -in test_certs/req$n.csr -out test_certs/cert$n.pem -CA test_certs/ca$n.pem -CAkey test_certs/ca$n_key.pem
  
#uploading cert, key and ca
curl -k -X POST -H "Authorization: Bearer $token" -H 'Content-Type: multipart/form-data'  -F "fileName=@test_certs/cert$n.pem;type=application/x-x509-ca-cert" -F "name=cert$n.pem" https://$IP:5443/api/v1/files
curl -k -X POST -H "Authorization: Bearer $token" -H 'Content-Type: multipart/form-data'  -F "fileName=@test_certs/ca$n.pem;type=application/x-x509-ca-cert" -F "name=ca$n.pem" https://$IP:5443/api/v1/files
curl -k -X POST -H "Authorization: Bearer $token" -H 'Content-Type: multipart/form-data'  -F "fileName=@test_certs/key$n.pem;type=application/pkcs8" -F "name=key$n.pem" https://$IP:5443/api/v1/files
  
#change device-certificate
systemid=$(curl -sk -X GET -H "Authorization: Bearer $token" -H 'Content-type: application/json' https://$IP:5443/api/v1/systems|jq '._embedded.systems[].id'|tr -d '"')
jobid=$(curl -sk -X PUT -H "Authorization: Bearer $token" -H 'Content-type: application/json' -d "{\"cert\": \"cert$n.pem\", \"key\": \"key$n.pem\", \"rootCA\": \"ca$n.pem\"}"  "https://$IP:5443/api/v1/systems/$systemid/device-certificate" | jq .id |tr -d '"')
 
echo "jobid $jobid"
sleep 20
 
#check job status
curl -sk  -H "Authorization: Bearer $token" https://$IP:5443/api/v1/jobs/$jobid |jq .message
