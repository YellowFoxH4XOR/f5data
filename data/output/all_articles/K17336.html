Known Issue

Customizing objects created using iApp application services may fail.

This issue occurs when all of the following conditions are met:

  • You have licensed and provisioned the BIG-IP LTM and BIG-IP APM modules on your BIG-IP system.
  • You have an iApp application service with Strict Updates enabled and configured to deploy the BIG-IP APM system.
  • You have an Access Guided Configuration [AGC] application service with Strict Updates enabled and configured to deploy the BIG-IP APM system.
  • You use the BIG-IP APM customization tool to modify configuration objects created by the iApp or AGC application service.

Impact

After attempting to save the change, the browser spins and never completes the save operation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You are unable to make changes to iApp or AGC-created objects using the BIG-IP APM customization tool.
  • You view messages in the /var/log/ltm file that appear similar to the following example:

    err mcpd[<PID>]: 010715bc:3: The application service (/Common/iapp_<name>.app/iapp_<name>) has strict updates enabled, the object (Customization Group /Common/iapp_<name>.app/iapp_<name>_<configuration object name>) must be updated using an application management interface.

Workaround

To work around this issue, you can temporarily disable Strict Updates in the iApp application service. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to iApps > Application Services and click the name of the affected application service.
  3. Click the Properties tab.
  4. Set Configuration to Advanced.
  5. Clear the check box for Strict Updates.
  6. Click Update.
  7. Re-enable Strict Updates when modifications are complete so that updates to the template propagate to the application service.
