Topic

Note: This article applies to BIG-IP 9.0.0 through 9.4.1. Starting in 9.4.2, the BIG-IP system includes a SIP services profile that you can use to manage Session Initiation Protocol (SIP) traffic. The SIP services profile automatically configures the BIG-IP system to handle persistence for SIP sessions using Call-ID. For more information about the SIP Services profile, refer to the Configuring SIP profile settings section of the BIG-IP LTM Configuration Guide. For information on deploying the BIG-IP for SIP traffic, refer to the Deployment Guide: Deploying the BIG-IP LTM for SIP Traffic Management.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

A SIP virtual server configured with a default UDP profile and SIP persistence profile may not load balance SIP traffic (SIP INVITE with different Call-ID) among pool members using the load balancing method specified. The SIP virtual server may send all SIP traffic to one server.

This behavior is not a defect and not a result of the use of SIP persistence; it is the BIG-IP system's default behavior for handling UDP packets sent from the same IP address and port as part of the same connection.

When Datagram LB is enabled within the UDP profile, the BIG-IP system will load balance each UDP packet individually, regardless of whether they originated from the same IP address and port. For more information, refer to K3605: Configuring BIG-IP to load balance UDP packets individually.

Starting in version 9.4.2, the BIG-IP system includes a SIP services profile that you can use to manage Session Initiation Protocol (SIP) traffic. The SIP profile automatically configures the BIG-IP system to handle persistence for SIP sessions using Call-ID. The Call-ID is a globally unique identifier that groups together a series of messages, which are sent between communicating applications. For more information, refer to the Configuring SIP profile settings section of the BIG-IP LTM Configuration Guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Note: The UDP profile default timeout value is 60 seconds. In configurations where firewalls are used for security purposes for a specific port, such as port 5060, the BIG-IP LTM will increment the source port if a packet from the same source port sends another SIP packet after the idle timeout has expired. This behavior is intended to maintain persistence and to ensure the request is not directed to another server. Additionally, this behavior can cause packets to be dropped in configurations that only allow specific port numbers. To prevent this issue from occuring, the timeout value for the UDP profile used with SIP traffic should be set to Immediate. This setting prevents the BIG-IP LTM from incrementing the source port of the request and prevents the firewall from rejecting the request.

Important: With UDP Datagram LB set to Enabled and Timeout set to Immediate, UDP response traffic is forwarded to the client using the origin server's source IP address and port. As a result, response traffic may not appear to have originated from the virtual server to which the request was sent, and traffic disruption may occur. You can avoid this issue by setting the timeout to a value other than Immediate whenever possible.
