Known Issue

Secure Sockets Layer (SSL) certificate Subject Alternative Name (SAN) domain name character case may affect Transport Layer Security (TLS) Server Name Indication (SNI) certificate selection.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP LTM virtual server is configured with a Client SSL profile.
  • The Client SSL profile is configured for SNI certificate selection.
  • SSL certificates available for the Client SSL profile include a certificate where the SAN contains DNS names with upper-case characters.
  • A client requests a certificate where the SAN contains DNS names with upper-case characters.

Impact

For the connection, the virtual server SSL connection uses the configured default profile for the SNI.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When clients request a certificate where the SNI SAN DNS name is in all lower-case characters, the appropriate SNI profile is selected.
  • When clients request a certificate where the SNI SAN DNS name is mixed or all upper-case characters, the SNI extension is ignored and the default SNI profile is selected.

Workaround

To work around this issue, you can use all lower-case characters for SAN domain names in SSL certificates.

Impact of workaround:  Performing the suggested workaround should not have a negative impact on your system.
