Description

After upgrading your VE to a version 14.x,15.x or 16.x that using a sock driver changed from a vmxnet3 driver, performances issues appear for multiple virtual servers

  • Packet loss is intermittently experienced from VE to backend pool members or clients
  • Packet captures can confirm that some packets are lost after arriving to the VE unit.
  • Output of bash command tmctl -w 999 -d blade -i tmm/ndal_rx_stats show a very similar result as the one documented in Bug ID 882549

Environment

  • Upgrade the VE to version 14.x, 15.x or 16.x
  • VE is using the sock network driver instead of the vmxnet3 driver

Cause

Bug ID 882549

Recommended Actions

In this case you can execute one of the two following procedures:

  1. Workaround: delete the 'tmm_init.tcl' file and restart TMM 
     # rm /config/tmm_init.tcl
 # bigstart restart tmm

NOTE: If the issues persist after deleting the 'tmm_init.tcl', proceed to change the sock driver for the vmxnet3 driver and test the affected virtual servers
  2.  A permanent solution is to upgrade to version 14.1.4.3 where this issue is fixed.
