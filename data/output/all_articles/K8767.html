Known Issue

This is the result of a known issue. When the Do Not Change option is selected for the Client Cache Settings in the acceleration policy, the BIG-IP WebAccelerator will still modify the HTTP Cache-Control header. The HTTP Cache-Control header will be changed from public to private, and other Cache-Control header directives inserted by the origin web server will be removed. The modified HTTP Cache-Control header can result in unexpected caching behavior by the client or by an intermediate caching device between the BIG-IP WebAccelerator system and the client. As a result, objects that should not be cached are cached, and objects that should be cached are not cached.

F5 Product Development tracked this issue as CR95041 and CR99660 and the issue was addressed in BIG-IP WebAccelerator 9.4.6 by adding new HTTP headers that allow an iRule to restore the public Cache-Control directive after WebAccelerator processing. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Note: For more information about the new HTTP headers, refer to K9451: Purpose of the BIG-IP WebAccelerator HTTP X-WAM-RC-MASQ and X-WAM-ORIG-CC headers.

Additionally, this issue was addressed in Hotfix-BIG-IP-9.4.5-HF2 issued for BIG-IP WebAccelerator 9.4.5. You may download this hotfix or later versions of the Hotfix from the F5 Downloads site.

Additionally, F5 Product Development has issued an engineering hotfix that resolves this issue for BIG-IP 9.4.3 and 9.4.4. Customers who are affected by this issue, using one of these versions, and are unable to upgrade at this time should request the hotfix from F5 Technical Support, referencing this article number and CR95041.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.
