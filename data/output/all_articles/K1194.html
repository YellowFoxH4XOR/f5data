K1194: Reasons why Internet Explorer may become unresponsive for several seconds when closing a connection to a BIG-IP SSL proxy

Topic

When Internet Explorer (IE) browsers connect to the SSL proxy on BIG-IP, there can be a 5-second delay before the browser closes the connection. This is caused by Microsoft Internet Explorer's implementation close_notify, which is not compliant with the following section of the Netscape IETF draft.

Each party is required to send a close_notify alert before closing the write side of the connection. It is required that the other party respond with a close_notify alert of its own and close down the connection immediately, discarding any pending writes. It is not required for the initiator of the close to wait for the responding close_notify alert before closing the read side of the connection.

This means that after the BIG-IP Controller sends a close_notify alert, the client follows with a close_notify before closing the write side of the connection.

In BIG-IP Controller versions prior to 3.3.1 PTF-05, the BIG-IP Controller did not send its half of the close_notify to close the connection. This happened to work on Internet Explorer because it sees a FIN and responds with a FIN, instead of the BIG-IP Controller waiting five seconds for the client to send an ALERT.

Examples

The following example shows a server-client exchange from BIG-IP version 3.3.1 PTF-04:

Server->Client, FIN, ACK
Client->Server, ACK
Client->Server, FIN, ACK
Server->Client, ACK

(Notice the similarity to a four-way close.)

The following example shows a server-client exchange from BIG-IP version 3.3.1 PTF-05 and later:

Server->Client, ALERT
Client->Server, ... (five second delay, the BIG-IP is waiting for close_notify alert)
Server->Client, FIN, ACK (By this time BIG-IP figures the client isn't going to respond and 
follows up a FIN, ACK to close the connection.)
Client->Server, ACK
Client->Server, FIN, ACK
Server->Client, ACK

F5 Networks introduced a new feature to improve compatibility with Internet Explorer in BIG-IP version 4.0 PTF-02.

Use one of the following procedures to enable the new feature.

BIG-IP version 4.2 - 4.6.4

Note: SSLUncleanShutdown is enabled by default on BIG-IP version 4.1 and later for fresh installs (upgrades retain their current value).

This setting is a global variable in BIG-IP version 4.2. You can enable or disable this variable using the instructions in the following procedures.

Enabling SSLUncleanShutdown

To enable the SSLUncleanShutdown variable, perform the following steps:

  1. Type the following command:

    bigpipe global sslproxy unclean shutdown enable

  2. Restart proxyd, by typing the following command:

    proxyd

Disabling SSLUncleanShutdown

To disable the SSLUncleanShutdown variable, perform the following steps:

  1. Type the following command:

    bigpipe global sslproxy unclean shutdown disable

  2. Restart proxyd, by typing the following command:

    proxyd

BIG-IP version 4.0 PTF-02 - 4.1.1 PTF-06

Enabling SSLUncleanShutdown

To enable the SSLUncleanShutdown variable, perform the following steps:

  1. Set the Common.Bigip.Proxy.SSLUncleanShutdown database key to 1, by typing the following command:

    bigpipe db set Common.Bigip.Proxy.SSLUncleanShutdown = 1

    Now BIG-IP Controller will not send its half of the close_notify to close the connection.

  2. Restart proxyd, by typing the following command:

    proxyd

Disabling SSLUncleanShutdown

To disable the SSLUncleanShutdown variable, perform the following steps:

  1. Remove the Common.Bigip.Proxy.SSLUncleanShutdown database key by typing the following command:

    bigpipe db unset Common.Bigip.Proxy.SSLUncleanShutdown

    This causes the BIG-IP Controller to send its half of the close_notify to close the connection.

  2. Restart proxyd, by typing the following command:

    proxyd
