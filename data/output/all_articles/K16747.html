Known Issue

Network time protocol (NTP) or rsync traffic over the management network may fail on BIG-IP vCMP guests.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is provisioned for vCMP.
  • The BIG-IP vCMP host is running the affected versions.
  • A BIG-IP vCMP guest attempts to access an NTP server or process rsync traffic over the management network.

Impact

BIG-IP vCMP guests are unable to communicate using NTP or rsync over the management network.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP vCMP guests are unable to access an NTP server over the management network.
  • BIG-IP vCMP guests are unable to process rsync traffic over the management network.

Workaround

To work around this issue, you can configure the BIG-IP vCMP guest to use a self IP address for NTP and rsync communications. However, if this configuration is not possible, you can modify the iptables rules to prevent them from interfering with NTP or rsync traffic on the management network of the BIG-IP vCMP guest. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP vCMP host.
  2. Create a backup of the /config/startup file by typing the following command:

    cp /config/startup /config/startup-sol16747

  3. Using a text editor, edit the /config/startup file.
  4. To ensure that the iptables rules changes persist across a reboot, add the following lines at the end of the file:

    #
    # sol16747
    #
    iptables -t nat -D PREROUTING -m physdev --physdev-in mgmt_vm_tap_+ -j ACCEPT
    iptables -t nat -I PREROUTING 1 -m physdev --physdev-in mgmt_vm_tap_+ -j ACCEPT

  5. Save the /config/startup file and exit the editor
  6. To update the iptables rules, type the following command:

    clsh iptables -t nat -I PREROUTING 1 -m physdev --physdev-in mgmt_vm_tap_+ -j ACCEPT
