Here is the cURL command and associated JSON file you would use to create a certificate with XC API. You can include the private key as instructed below:

curl --location --request POST "https://<tenant-domain>.console.ves.volterra.io/api/config/namespaces/<namespace-name>/certificates" \
--header "Authorization: APIToken $APIToken" \
--header "Content-Type: application/json" \
-d@json_sample.json

 

{
  "metadata": {
    "name": "<desired-cert-name>",
    "namespace": "<desired-namespace>",
    "labels": {},
    "annotations": {},
    "disable": false
  },
  "spec": {
    "certificate_url": "string:///<base64-encoded-cert-should-go-here>",
    "private_key": {
      "blindfold_secret_info": {
        "location": "string:///<base64-encoded-private-key-encrypted-should-go-here>"
      }
    },
    "disable_ocsp_stapling": {}
  }
}

 

Bear in mind that blindfold_secret_info should contain value of encrypted blindfold secret that is base64-encoded. In other words, if you base64 decode this, it should look like encrypted gibberish, not natural language. If you wish to provide a private key that is already decrypted and base64 encoded, you will need to use clear_secret_info instead in the above JSON data. If you base64 decoded this, you would see the beginning of a decrypted private key ("-----BEGIN PRIVATE KEY-----").

For reference, here is the cURL command you would use to retrieve a certificate of interest:

curl --location --request GET "https://<tenant-domain>.console.ves.volterra.io/api/config/namespaces/<namespace-name>/certificates/<object-cert-name>" \
--header "Authorization: APIToken $APIToken" \
--header "Content-Type: application/json"
