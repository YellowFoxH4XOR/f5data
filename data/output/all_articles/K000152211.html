Description

Clients are unable to access an application through an F5 BIG-IP LTM virtual server. When attempting to connect, affected users experience a "Connection Reset" error. Packet captures show that after a successful TCP handshake, the expected SSL/TLS Client Hello is not received by the BIG-IP. You will see the error: "[RST] SSL handshake timeout exceeded"

Environment

  • BIG-IP LTM

Cause

The root cause is a delay in the delivery of the SSL/TLS Client Hello packet from the client to the BIG-IP virtual server.  The default SSL handshake timeout is 10 seconds.

Generating the cipher involves the client preparing the necessary cryptographic parameters, which may include random number generation, key exchange preparation, and assembling the list of supported cipher suites. If the client device is under heavy load, has limited resources, or is running security software that inspects or modifies SSL/TLS handshakes, this process can take longer than usual.

Recommended Actions

1. Increase the SSL handshake-timeout value in the client-ssl profile to accommodate observed delays in Client Hello arrival. 

For example:  ( Local Traffic  ››  Profiles : SSL : Client  ››  clientssl)

ltm profile client-ssl /Common/Client_SSL {
    app-service none
    cert-key-chain {
      .
      .
      .
    defaults-from /Common/clientssl
    handshake-timeout 10                <-------  Change to 15 or 20
    inherit-ca-certkeychain true
}

2. Review and troubleshoot all intermediate network devices between clients and BIG-IP for sources of delay or packet inspection that could impact the timely delivery of SSL/TLS handshakes.
