Description

DNSSEC validation failures occur for a delegated child zone when the parent zone is DNSSEC-signed and served by BIG-IP DNS, but the child zone is not DNSSEC-signed and no insecure delegation entry exists in the parent zone's DNSSEC configuration.

Symptoms include:

  • The parent zone returns an RRSIG signed by the parent zone key for records in the delegated child zone
  • The AD (Authenticated Data) flag is set in responses for the child zone
  • DS record queries to the parent authoritative nameserver time out:

    ;; connection timed out; no servers could be reached

  • DNSSEC-validating resolvers return SERVFAIL for the delegated child zone:

    ;; ->>HEADER<<- opcode: QUERY, status: SERVFAIL

  • With DNSSEC checking disabled (+cd) the delegation succeeds and returns the expected NS records
  • Certificate Authority DNS validation failures

Environment

  • BIG-IP DNS
  • DNSSEC
  • external nameservers

Cause

When BIG-IP DNS performs DNSSEC inline signing for a parent zone, it must be explicitly configured with a delegation entry for each delegated child zone. Without this entry:

  • BIG-IP DNS does not correctly handle DS queries for the delegated child zone
  • The parent authoritative nameserver times out on DS queries instead of returning NOERROR/NODATA
  • DNSSEC-validating resolvers interpret the timeout as a broken chain of trust and return SERVFAIL

Answer/Recommended Actions

To resolve DNSSEC validation failures for an unsigned delegated child zone, add an insecure delegation entry for the child zone under the parent zone's DNSSEC configuration on BIG-IP DNS.

GUI Method

  1. Log in to the BIG-IP Configuration Utility (TMUI).
  2. Navigate to DNS → Zones → DNSSEC Zones.
  3. Click the name of the parent zone example.com
  4. Click the Delegations tab.
  5. Click Add.
  6. In the Name field, enter the delegated child zone nameunsecure.example.com
  7. Uncheck the Secure checkbox.
  8. Leave the DS Record field blank.
  9. Click Finished or Save.

Additional Information

  • Impact of workaround: Adding an insecure delegation entry is a non-disruptive change. It does not affect existing DNSSEC keys (ZSK/KSK), DNSKEY RRsets, RRSIG records, or DS records for the parent zone. Only the handling of DS queries for the specific delegated child zone is modified.
  • Expected behavior after the change: The parent zone will respond to DS queries for the insecure delegated child zone with NOERROR/NODATA, along with an NSEC3 proof of non-existence. This correctly signals to DNSSEC-validating resolvers that the child zone is an insecure delegation, resolving the SERVFAIL responses.
  • Two resolution paths exist for this scenario:
    • Option A (DNSSEC enabled on child): Enable DNSSEC on the child zone, obtain the DS record from the child zone's DNS provider, and publish it as a secure delegation entry in the parent zone on BIG-IP DNS.
    • Option B (DNSSEC not enabled on child): Configure the child zone delegation as insecure in the parent zone's DNSSEC configuration on BIG-IP DNS, as described in the steps above.
