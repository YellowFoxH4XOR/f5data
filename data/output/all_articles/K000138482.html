Description

You have a Virtual Server that requires same data to be replicated to all pool members using tcp connections. 


Environment

Virtual Server with TCP connectivity and more than one member in pool.


Cause

Regularly, requests are forwarded to syslog server pool members using UDP protocol, making it necessary in this case to insert a replication method via an iRule and tcp protocol. Using a syslog server type configuration permits to forward data to all pool members at the same time.


Recommended Actions

Configure an iRule similar to examples below and apply to desired Virtual Server.

  • Single pool iRule.

when CLIENT_ACCEPTED {
    set hsl [HSL::open -publisher /Common/my-log-publisher-tcp]
    TCP::collect
}

when CLIENT_DATA {
   HSL::send $hsl \"[TCP::payload]\"
   TCP::release
   TCP::collect
}

It's important to configure the log destination to use TCP, like:


sys log-config destination remote-high-speed-log my-log-destination-tcp 
{
    app-service none
    description none
    distribution adaptive
    pool-name my-pool0    <----------- Pool in VS
    protocol tcp          <-----------
}


Syslog publisher "my-log-publisher-tcp" must be configured and related to syslog destination "my-log-destination-tcp" accordingly.

 

  • Multi pool iRule

Should several pools replication be required, configuration below might be used: 

when CLIENT_ACCEPTED {

       set pool1 [HSL::open -proto TCP -pool my_pool1]
       set pool2 [HSL::open -proto TCP -pool my_pool2]
       set pool3 [HSL::open -proto TCP -pool my_pool3]
   TCP::collect
}

when CLIENT_DATA {

      HSL::send $pool1 \"[TCP::payload]\"
      HSL::send $pool2 \"[TCP::payload]\"
      HSL::send $pool3 \"[TCP::payload]\"
  TCP::collect
  TCP::release
}

Again, Syslog publisher "my-log-publisher-tcp" must be configured and related to syslog destination "my-log-destination-tcp" accordingly.


In both cases, pools "my-pool0", "my_pool1", "my_pool2", and "my_pool3" must be configured to contain all desired pool members as required.
