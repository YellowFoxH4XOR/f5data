Topic

Systems configured to use SNMP v3 are required to have a unique SNMP engine ID. If the systems do not have a unique SNMP engine ID, SNMP v3 does not function properly and trap messages will not be transmitted.

It is possible to accidentally set the SNMP engine ID on two or more systems to the same value through injudicious use of rsync or something similar. It is also possible to accidentally do so by chance.

If the SNMP engine ID is not unique it must be changed on one of the systems.

The SNMP v3 encrypted passwords and passphrases also depend on the engine ID, so if the engine ID changes you also need to delete and recreate any SNMP Access (v3) records you have defined.

You can delete the SNMP Access (v3) records, change the SNMP engine ID, and recreate the SNMP Access (v3) records by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click SNMP.
  4. For Agent, click Access (v3).

    The SNMP Access (v3) records are displayed.

  5. Select the check box for all of the SNMP Access (v3) records.
  6. Click Delete.
  7. To confirm the deletion, click Delete.
  8. Log in to the BIG-IP command line.
  9. Stop the snmpd daemon, by typing the following command:

    bigstart stop snmpd

  10. Change to the /config/net-snmp directory, by typing the following command:

    cd /config/net-snmp

  11. Using a text editor, edit the snmpd.conf file.
  12. Remove the engineBoots and oldEngineID lines that appear similar to the following examples:

    engineBoots 12
    oldEngineID 0x800007e580e73292406fc23043

  13. Save the snmpd.conf file.
  14. Start the snmpd process, by typing the following command:

    bigstart start snmpd

  15. Recreate the SNMP Access (v3) records that were deleted in step 6 of this procedure.

When the snmpd process is started in step 14 of the procedure above, a new SNMP engine ID is defined, and the engineBoots and oldEngineID entries are created in the /config/net-snmp/snmpd.conf file.
