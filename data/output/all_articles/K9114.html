Topic

The BIG-IP system device certificate is an SSL certificate used for control plane tasks, such as securing connections to the Configuration utility and securing iQuery communication between BIG-IP DNS systems in a synchronization (sync) group configuration. If the current device certificate is corrupted, or you believe the private key was compromised, you can generate a new self-signed device certificate and private key pair. If you need to create a CA-signed certificate, refer to:

  • K42531434: Replacing the Configuration utility's self-signed SSL certificate with a CA-signed SSL certificate
  • K51035715: Replace the Configuration utility's self-signed device certificate with a certificate signed by your organization's CA

When creating BIG-IP device certificates, use the following recommendations to make device certificate management easier:

  • Device certificates should have unique and meaningful subject data. For example, use a common name (CN) that matches the host name of the local BIG-IP system.
  • Create device certificates with an extended expiration date. The default BIG-IP system SSL device certificate is valid for 10 years.
  • Configure the country and locality fields to distinguish each BIG-IP system when viewing BIG-IP device certificates in the BIG-IP DNS trusted certificate store.

The procedures you follow depends on whether the BIG-IP system is a standalone system or a peer member of a BIG-IP DNS sync group peer.

Standalone system

Standalone systems use device certificates to secure connections to the Configuration utility when managing the BIG-IP system. If your BIG-IP system is a standalone device, you can use the following procedure to renew or replace the device certificate:

  • Generating a new self-signed device certificate and private key

Sync group peer

Sync group peers use device certificates to secure connections to the Configuration utility when managing the BIG-IP system, and to secure iQuery communication between sync group peer members. Each sync group peer must obtain and install the device certificate from each of the sync group peers in the Trusted Device Certificate and Trusted Server Certificate stores.

Note: If your BIG-IP DNS system belongs to a sync group, you must perform all of the following procedures in their listed order.

  • Generating a new self-signed device certificate and private key
  • Updating the local BIG-IP system trusted certificate store
  • Updating the trusted certificate stores on remote BIG-IP systems

Generating a new self-signed device certificate and private key

The BIG-IP system device certificate is located in the /config/httpd/conf/ssl.crt/server.crt file on the BIG-IP system and the SSL device key is located in the /config/httpd/conf/ssl.key/server.key file. To generate a new SSL certificate and key, perform the following procedure:

Impact of procedure: This procedure disconnects users from the Configuration utility and forces them to re-authenticate. All new connections use the new device certificate and key.

  1. Log in to the Advanced Shell (bash).
  2. To generate the new device certificate and key, use the following command syntax:

    openssl req -x509 -nodes -days <number> -newkey rsa:<keysize> -sha256 -keyout /config/httpd/conf/ssl.key/server.key -out /config/httpd/conf/ssl.crt/server.crt

    For example, the following command creates a 2048 bit SSL private key and a self-signed certificate that is valid for 10 years:

    openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -sha256 -keyout /config/httpd/conf/ssl.key/server.key -out /config/httpd/conf/ssl.crt/server.crt

    Note: Only RSA BIG-IP device certificates are supported. ECC certificates are not currently supported.

  3. Enter the certificate attributes such as country, locality, common name, etc.
  4. To restart the httpd process, type the following command:

    bigstart restart httpd

Updating the local BIG-IP system trusted certificate store

For successful iQuery communication, the Trusted Device Certificate and Trusted Server Certificate stores on each sync group peer must contain the following:

  • The device certificate of each sync group member
  • The third-party CA certificate used to sign device certificates

Note: For information about installing third party or wildcard certificates, refer to K7717: BIG-IP DNS and Link Controller support for third-party SSL device certificates.

Note: For information about the deprecation of client authentication (clientAuth) extended key usage (EKU) for public certificates generated by Public Key Infrastructure (PKI) certificate authorities (CA) and what you can do to prepare, you may want to refer to the F5 DevCentral article: The End of ClientAuth EKU…Oh Mercy…What to do?.

You must manually update the local Trusted Device Certificate and Trusted Server Certificate stores with the new device certificate. To do so, perform the following procedure:

  1. To copy the new device certificate to the Trusted Device Certificate store, type the following command:

    cat /config/httpd/conf/ssl.crt/server.crt >> /config/big3d/client.crt

    Note: Alternatively, you can add the new certificate to the trusted device certificate file and remove all old certificates by using the cat /config/httpd/conf/ssl.crt/server.crt > /config/big3d/client.crt command.

  2. To copy the new device certificate to the Trusted Server Certificate store, type the following command:

    cat /config/httpd/conf/ssl.crt/server.crt >> /config/gtm/server.crt

    Note: Alternatively, you can add the new certificate to the trusted server certificate file and remove all old certificates by using the cat /config/httpd/conf/ssl.crt/server.crt > /config/gtm/server.crt command.

Updating the trusted certificate stores on remote BIG-IP systems

After you generate a new device certificate and private key pair on a BIG-IP system, you need to re-establish device-to-device communication between BIG-IP DNS synchronization group members and BIG-IP LTM systems that communicate with BIG-IP DNS. To do so, you must exchange device certificates by running the bigip_add utility from the command line of each BIG-IP DNS device that contains a new device certificate. To do so, perform the following procedure:

Important: This procedure must be performed on each BIG-IP DNS system that contains a new device certificate.

Impact of workaround: The BIG-IP DNS system cannot respond to any wide IP queries until the gtmd process is restarting.

  1. Log in to bash.
  2. Run the bigip_add utility to exchange certificates with remote BIG-IP DNS systems by typing the following command:

    Note: The bigip_add utility prompts you for the root password of each BIG-IP system defined in the BIG-IP DNS configuration file.

    bigip_add

  3. To restart the gtmd process, type the following command:

    bigstart restart gtmd

  4. To restart the big3d process, type the following command:

    bigstart restart big3d

  5. To verify that iQuery communication is restored between all devices, use the following command syntax:

    iqdump <remote BIG-IP system>

    For example, to test iQuery to a remote BIG-IP DNS sync group peer with IP address 192.168.10.100, type the following command:

    iqdump 192.168.10.100

    The command output appears similar to the following example:

    <!-- Local hostname: gtm1.example.com -->
    <!-- Connected to big3d at: ::ffff:192.168.10.100:4353 -->
    <!-- Subscribing to syncgroup: default -->
    <!-- Thu Mar 24 08:27:52 2017 -->
    <xml_connection>
    <version>11.5.1</version>
    <big3d>big3d Version 13.0.0.0.0.1645</big3d>
