Description

You want to set a boot loader password to secure the kernel command line to avoid possible intruder modifications with unauthorized console access.

Note: While this procedure adds friction, it cannot completely prevent a determined attacker with datacenter access in the case of BIG-IP platforms or hypervisor access in the case of VE or other virtualised BIG-IP instances from modifying your TMOS installation.

Environment

  • Boot loader Password
  • Securing kernel command line
  • Console access

Cause

None

Recommended Actions

Important: Please note this procedure adds non-standard configuration to the bootloader which TMOS upgrades may not account for. The outcome of TMOS upgrades with this configuration in place is not guaranteed; future TMOS versions may not be compatible with this configuration, the upgrade process itself may break and the password may not always remain intact across upgrades. It is therefore advisable to disable the bootloader password before a major release upgrade and to re-enable it afterwards to ensure there are no unforeseen interactions during the installation process and that the password remains in place after each upgrade. It is recommended to take precautions to safely store the password used, as it could be needed for troubleshooting.

To configure a boot loader password follow these steps:

Before Starting:

  1. Verify console access is available and a recent UCS backup exists before starting in case recovery is needed.
  2. Verify the version of grub installed on your system as per K14658: Determining the GRUB bootloader version on the BIG-IP, BIG-IQ, or Enterprise Manager system.

If your grub version is 0.97

  1. Run this command, and when prompted, enter the password of your choosing:
    openssl passwd -1
    For example:
    [root@example:Active:Standalone] config # openssl passwd -1
    Password:
    Verifying - Password:
    $1$zNQGI7zU$KSMDIndiF9VD.h8JWDFTY.
  2. From the command line, type the following command to edit the grub.conf file:
    vi $(grub_open)
  3. Add the encrypted password obtained in step 1, in the global section of the file, adding the line password --md5 similar to the example below:
    splashimage=(hd0,0)/img/splashimage.xpm.gz
    default=0
    timeout=8
    password --md5 $1$zNQGI7zU$KSMDIndiF9VD.h8JWDFTY. → Paste encrypted password here

    title BIG-IP 14.1.2 Build 0.0.37 - drive vda.1
            root (hd0,0)
            kernel /boot/1/vmlinuz ro root=UUID=56f11167-6211-4946-acf3-a21f14b63393  console=ttyS0 console=tty0 panic=1 platform=Z100 default_cpu_order quiet
            initrd /boot/1/initrd
            # TIC_VS_PROJECT:
            # TIC_VS_PRODUCT: BIG-IP
            # TIC_VS_VERSION: 14.1.2
            # TIC_VS_BUILD: 0.0.37
            # TIC_VS_BASEBUILD: 0.0.37
            # TIC_VS_EDITION: Final
            # TIC_VS_PROJECT:
  4. Close the grub.conf file editing with:
    grub_close
  5. Reboot the device

Note: All BIG-IP boot menu entries will still boot without any manual user interaction, but will require authentication for any change to the kernel command line. You  may want to also edit the grub menu entry titled "TMOS maintenance"  to add the lock keyword on a line by itself below the title to prevent an unauthorised user with console access from modifying your TMOS installations from within the Maintenance OS installation.

Additional Information

Note that if, at any point, you need to restart the BIG-IP system in single-user mode for troubleshooting purposes, you will need access to this password. In case of misplace of the boot loader password, you might need to perform a clean installation using the USB thumb drive option to recover access to the system.
