K84152030: BIG-IQ not able to restore BIG-IP ucs: Timed out waiting for restore task to complete

Type
Support Solution
Published
2021-12-23
Updated
2025-02-07
Applies to
  • BIG-IQ
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K84152030

Description
When using BIG-IQ to restore a UCS backup the following failure was seen in the BIG-IQ restjavad.0.log:

[WARN][30 Nov 2021 19:40:04 SGT][/cm/system/backup-restore/xxxxxxx-xxxx-xxx-xxxx-xxxxxxxxx/worker UcsBackupRestoreTaskWorker] Error occurred during backup/restore operation on 192.0.2.55: java.lang.IllegalStateException: Timed out waiting for restore task to complete

The config from the UCS was not getting loaded to the BIG-IP.

Environment

  • BIG-IQ managing UCS archives for BIG-IPs

Cause
A modified ssh configuration caused this failure on the target BIG-IP where the UCS restore occurred. The sshd configuration on the BIG-IP has a specific KexAlgorithms set that the ssh client on the same BIG-IP does not support in its default configuration. The REST API on the BIG-IP uses ssh internally to perform the UCS restore. The client and the server are both the BIG-IP itself. In this case, the default ssh client does not support the key exchange algorithm that the sshd server configuration is set to use.

Here is the configuration in bigip_base.conf on the BIG-IP that contains the KexAlgorithms setting:

sys sshd {
    include "
MACs hmac-sha2-256,hmac-sha2-512
Ciphers aes128-ctr,aes192-ctr,aes256-ctr
KexAlgorithms diffie-hellman-group-exchange-sha256   <-- This is the part the ssh client can't support
"
}

Recommended Actions

To resolve this we need to configure the ssh client on the BIG-IP to support diffie-hellman-group1-sha1 
  1. On BIG-IP CLI issue the following command to configure the ssh client for the root user to support diffie-hellman-group1-sha1:

    echo "KexAlgorithms +diffie-hellman-group1-sha1" > ~/.ssh/config
