K000149360: BIG-IP Configuration Seemingly Goes Missing

Support Solution
Published
2025-02-06

Applies to

  • BIG-IP LTM: 16.1.0, 16.1.2, 16.1.1, 17.1.X, 16.1.X, 17.1.2, 17.1.1, 17.1.0, 16.1.5, 16.1.4, 16.1.3
Source
https://my.f5.com/manage/s/article/K000149360

Description

Configuration such as a virtual server, pool, node, SSL certificate, etc. was added and then that configuration appears to go missing in a scenario where auto-sync is enabled & save-on-auto-sync is set to false followed by a license activation/reactivation.

Environment

  • BIG-IP
  • Device Service Cluster (DSC) failover sync device group:
    • where auto-sync is set to enabled & save-on-auto-sync is set to false when viewed in tmsh.

      OR

    • where Sync Type is Automatic with Incremental Sync and Save on Automatic Sync is disabled (unchecked) when viewed in the Configuration Utility.

Settings as seen via Configuration utility

A BIG-IP device service cluster (DSC) where Sync Type is Automatic with Incremental Sync and Save on Automatic Sync is disabled (unchecked) when viewed in the Configuration Utility.

Settings as seen via tmsh

A BIG-IP device service cluster (DSC) where auto-sync is set to enabled & save-on-auto-sync is set to false when viewed in tmsh.

root@(big-ip-01a)(cfg-sync In Sync)(Standby)(/Common)(tmos)# list cm device-group Failover all-properties
cm device-group Failover {
  app-service none
  asm-sync disabled
  auto-sync enabled
  description none
  devices {
    big-ip-01a.lab { }
    big-ip-01b.lab { }
  }
  full-load-on-sync false
  incremental-config-sync-size-max 1024
  network-failover enabled
  partition Common
  save-on-auto-sync false
  type sync-failover
}

Cause

With auto-sync set to enabled and save-on-auto-sync set to false in tmsh or Sync Type is Automatic with Incremental Sync and Save on Automatic Sync is disabled (unchecked) in the Configuration Utility, the BIG-IP system receiving the new configuration does not automatically save the configuration even though it is displayed in the Configuration Utility/tmsh. This behavior is by default and by design, so when reactivating the license on the BIG-IP that received the configuration via Automatic Sync, that BIG-IP system reloads its last saved configuration, which becomes the latest configuration and gets synced to the device group. Hence, configuration changes not previously saved (save /sys config) are lost on all cluster members. 

Recommended Actions

It is recommended to enable save-on-auto-sync so the BIG-IP always saves the configuration on peer devices. This keeps the configuration files such as /config/bigip.conf updated. If a license reactivation or another event that reloads the text configuration file occurs, the updated bigip.conf will be used and no configuration changes will be lost.

Configure Automatic Sync to update configuration files on remote devices using the Configuration utility

Impact of procedure: For large configurations, setting this option to true may result in a long ConfigSync duration.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Device Groups.
  3. Select the Device Group from the Device Group List that you want to modify; Failover is the Device Group for this example.
  4. Select Advanced from the Configuration drop-down menu.
  5. Under Device Group Settings for Sync Type, select Automatic with Incremental Sync.
  6. To enable Automatic Sync, select the Save on Automatic Sync check box
  7. Select Update to save the change which will also sync the change to the peer.

Configure Automatic Sync to update configuration files on remote devices using tmsh

Impact of procedure: For large configurations, setting this option to true may result in a long ConfigSync duration.

  1. SSH to the BIG-IP, and if not already at the (tmos) prompt, type tmsh by entering the following command:
    tmsh
  2. To set the save-on-auto-sync option to true for the device group you want, enter the following command:
    modify /cm device-group <device group name> save-on-auto-sync true
  3. For example, to set the save-on-auto-sync option to true for the Failover device group, enter the following command:
    Note: To revert the save-on-auto-sync setting to its default value, set the option to false.
    modify /cm device-group Failover save-on-auto-sync true
  4. Save the change by entering the following command:
    save /sys config

Additional Information

Example Scenario

  1. Add a virtual server on big-ip-01a.
    1. Local Traffic > Virtual Servers > Virtual Server List > Create
      • Name = vs_test
      • Destination Address/Mask = 10.10.10.10
      • Service Port = 443 / HTTPS
    2. Finished
    3. With Sync Type set to Automatic with Incremental Sync and Save on Automatic Sync set to disabled, the new configuration will be synced from big-ip-01a.lab to big-ip-01b.lab.
    4. The new virtual server configuration is visible on big-ip-01a as shown below from tmsh and is also visible in the Configuration Utility though not shown here.
      root@(big-ip-01a)(cfg-sync In Sync)(Active)(/Common)(tmos)# list ltm virtual vs_test
      ltm virtual vs_test {
          creation-time 2025-01-22:08:40:42
          destination 10.10.10.10:https
          ip-protocol tcp
          last-modified-time 2025-01-22:08:40:42
          mask 255.255.255.255
          profiles {
               /Common/tcp { }
          }
          serverssl-use-sni disabled
          source 0.0.0.0/0
          translate-address enabled
          translate-port enabled
          vs-index 2
      }
    5. The new virtual server configuration has been saved to /config/bigip.conf.
      [root@big-ip-01a:Standby:In Sync] config # sed -n '/vs_test/,+13p' /config/bigip.conf
      ltm virtual /Common/vs_test {
          creation-time 2025-01-22:08:40:42
          destination /Common/10.10.10.10:443
          ip-protocol tcp
          last-modified-time 2025-01-22:08:40:42
          mask 255.255.255.255

              /Common/tcp { }
          }
          serverssl-use-sni disabled
          source 0.0.0.0/0
          translate-address enabled
          translate-port enabled
      }
  2. big-ip-01b
    1. The new virtual server configuration is visible on big-ip-01b as shown below from tmsh and is also visible in the Configuration Utility though not shown here.
      root@(big-ip-01b)(cfg-sync In Sync)(Active)(/Common)(tmos)# list ltm virtual vs_test
      ltm virtual /Common/vs_test {
          creation-time 2025-01-22:08:40:42

          translate-port enabled
          vs-index 4

    2. The new virtual server configuration has not been saved to /config/bigip.conf.
      [root@big-ip-01b:Active:In Sync] config # sed -n '/vs_test/,+13p' /config/bigip.conf
      [root@big-ip-01b:Active:In Sync] config #
    3. Reactivate the license; consult K7727 for steps.
    4. The new virtual server configuration is no longer visible on big-ip-01b after the license reactivation from tmsh or the Configuration Utility.
      root@(big-ip-01a)(cfg-sync In Sync)(Active)(/Common)(tmos)# list ltm virtual vs_test
      01020036:3: The requested Virtual Server (/Common/vs_test) was not found.
    5. The new virtual server configuration has not been saved to /config/bigip.conf.
      [root@big-ip-01b:Standby:In Sync] config # sed -n '/vs_test/,+13p' /config/bigip.conf
      [root@big-ip-01b:Standby:In Sync] config #
  3. big-ip-01a
    1. The new virtual server configuration is no longer visible on big-ip-01a from tmsh or the Configuration Utility after the license reactivation was completed on big-ip-01b.
