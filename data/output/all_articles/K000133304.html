K000133304: Istio injection fails due to Envoy out of memory

Type
Support Solution
Published
2023-03-31
Updated
2023-03-31
Applies to
  • Aspen Mesh: 1.11, 1.X.X, 1.14
Source
https://my.f5.com/manage/s/article/K000133304

Description

Ingress Gateway istio-sidecar container crashes with log message "Envoy may have been out of memory killed. Check memory usage and limits".
Worker node shows "Warning SystemOOM 166m kubelet System OOM encountered, victim process: envoy, pid: 3113794".

 

Environment

Red Hat OpenShift
Aspen Mesh 1.11.x, 1.14.x

 

Cause

kubelet kills the istio-sidecar container when the memory limit is reached.

 

Recommended Actions

Modify requests and limits for Ingress gateway in the overrides value file

gateways:
    istio-ingressgateway:
      resources:
        requests:
          cpu: 100m
          memory: 128Mi
        limits:
          cpu: 2000m
          memory: 1024Mi



Additional Information

OOM Kills occur when pods (technically containers) try to access memory that isn't available. Either another pod is using your memory or you requested too little memory to begin with.
