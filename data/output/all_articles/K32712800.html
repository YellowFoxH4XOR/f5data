Description

  • Unable to Import ASM configuration to BIG-IQ
  • The following error appears on BIG-IQ GUI:

    Failed to copy configuration to working-config; reason: Failed copying from source subcollections to target subcollections: java.lang.IllegalArgumentException: Invalid format field value : vs_name

  • The following error messages can be seen on BIG-IQ /var/log/restjavad logs:

    [ERROR][08 Jun 2020 14:23:24 IDT][/cm/security-shared/tasks/config-copy/1fb3587e-b601-49c9-a368-f3782226c884/worker SharedConfigCopyTaskWorker] Failed copying from source subcollections to target subcollections: java.lang.IllegalArgumentException: Invalid format field value : vs_name

    [WARN][08 Jun 2020 14:23:25 IDT][/cm/security-shared/tasks/declare-mgmt-authority/e96f5889-ecf8-4a9b-b35d-048ed2224d3c/worker SharedDMATaskWorker] Failed to copy configuration to working-config; reason: Failed copying from source subcollections to target subcollections: java.lang.IllegalArgumentException: Invalid format field value : vs_name
    [ERROR][08 Jun 2020 14:23:25 IDT][/cm/security-shared/tasks/declare-mgmt-authority/e96f5889-ecf8-4a9b-b35d-048222004d3c/worker SharedDMATaskWorker] Failed to copy configuration to working-config; reason: Failed copying from source subcollections to target subcollections: java.lang.IllegalArgumentException: Invalid format field value : vs_name

Environment

  • BIG-IQ CM
  • BIG-IP with ASM provisioned

Cause

The BIG-IP ASM device is configured with a security logging profile with Storage Format values "microservice" or "vs_name", which currently are not supported on BIG-IQ.

Recommended Actions

Remove the "vs_name" or "microservice" fields from the logging profile Storage Format.

For example, the device is configured with the following security logging profile

security log profile /Common/Example_Log_Profile {
    application {
        /Common/Example_Log_Profile {
            filter {
                request-type {
                    values { all }
                }
            }
            format {
                fields { attack_type avr_id blocking_exception_reason captcha_result client_type date_time dest_ip dest_port device_id fragment geo_location http_class_name ip_address_intelligence ip_client ip_with_route_domain is_truncated login_result management_ip_address management_ip_address_2 method microservice mobile_application_name mobile_application_version password policy_apply_date policy_name protocol query_string request request_status response response_code route_domain salt session_id severity sig_ids sig_names sig_set_names slot_number src_port staged_sig_ids staged_sig_names staged_sig_set_names staged_threat_campaign_names sub_violations support_id threat_campaign_names unit_hostname uri username violation_details violation_rating violations virus_name vs_name websocket_direction websocket_message_type x_forwarded_for_header_value }
            }
            local-storage disabled
            logger-type remote
            protocol udp
            remote-storage remote
            servers {
                10.0.0.1:514 { }
            }
        }
    }
}

  1. On BIG-IP ASM GUI go to Security  >  Event Logs > Logging Profiles
  2. Click on the security logging profile in question
  3. Locate "vs_name" or "microservice" fields on the Storage Format Selected Items list  and moved them to the Available Items: list
  4. Click Update
