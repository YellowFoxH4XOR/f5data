Issue

Error Message

err nlad[<PID>]: 01620000:3: <0x55b80b90> nlclnt[1030310ac] init: Error [0xc000006d,NT_STATUS_LOGON_FAILURE] connecting to DC <IP_address>

In this error message, note the following:

  • <PID> is the process ID for the nlad process
  • <IP_address> is the IP address of the destination Active Directory authentication server

For example:

err nlad[6778]: 01620000:3: <0x55b80b90> nlclnt[1030310ac] init: Error [0xc000006d,NT_STATUS_LOGON_FAILURE] connecting to DC 10.0.0.1

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file

Description

This message occurs when all of the following conditions are met:

  • You have deleted the NT Lan Manager (NTLM) Machine Account in the BIG-IP APM configuration.
  • You have re-created the NTLM Machine Account in the BIG-IP APM configuration using the same name as the one previously deleted.

This occurs because the channel is maintained until the eca and nlad services are restarted.

Impact

The NTLM machine account fails to connect to the Active Directory.

Recommended Actions

When encountering this message, consider the following to work around the issue:

  • Create a new NTLM Machine Account with unique name that is different from the original account.
    See the following article for instruction:  K63324455: APM: NTLM Authentication fails with the error message: Fail (STATUS_NO_LOGON_SERVERS)
  • If creating a new NTLM Machine Account with the same name as the previously deleted one, make to to restart the eca and nlad services before attempting to connect to the Active Directory server. To restart the eca and nlad services, perform the following procedure:

    Impact of procedure: NTLM authentication is unavailable while the eca and nlad processes are restarting.

    1. Log in to the TMOS Shell (tmsh) by typing the following command:

      tmsh

    2. To restart the eca and nlad processes, type the following command:

      restart /sys service eca nlad
