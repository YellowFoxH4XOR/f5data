Description

Tips for troubleshooting SSH virtual server issues.

Environment

  • LTM with SSH virtual server configured

Cause

SSH sessions through a virtual server on the LTM are not functional:  either cyphers aren't matching or some other errors are preventing SSH from functioning.

Recommended Actions

To test SSH you can used increased verbosity settings to get full details.

For example if you are getting disconnected when trying to SSH in you can run 
# ssh -vvv user@hostname

The output will contain the entire SSH key negotiation as well as all other details of the connection.  You will get output similar to:

[root@ltm2:Active:In Sync] config # ssh -vvv root@10.0.0.14
OpenSSH_7.4p1, OpenSSL 1.0.2s-fips  28 May 2019
debug1: Reading configuration data /config/ssh/ssh_config
debug3: kex names ok: [ecdh-sha2-nistp256,ecdh-sha2-nistp384]
debug1: /config/ssh/ssh_config line 75: Applying options for *
debug2: resolving "10.0.0.14" port 22
debug2: ssh_connect_direct: needpriv 0
debug1: Connecting to 10.0.0.14 [10.0.0.14] port 22.
debug1: Connection established.

... you'll then see the details of the connection ending with:

debug1: Next authentication method: password
root@10.0.0.14's password:
debug3: send packet: type 50
debug2: we sent a password packet, wait for reply
Authentication failed.

You can then see from the last part of the output that the Authentication failed showing that the authentication method used (password) was not accepted by the server.
