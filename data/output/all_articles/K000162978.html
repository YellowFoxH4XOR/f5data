K000162978: BIG-IP ConfigSync Fails When a Monitor Is Recreated with a Different Type

Type
Support Solution
Published
2026-08-19
Updated
2026-08-19
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000162978

Description

ConfigSync fails when a health monitor is deleted and recreated with the same name but a different monitor type in a single transaction. The monitor can retain unsupported user-defined parameters, causing the receiving BIG-IP system to reject the configuration with the following error:

01070033:3: Monitor ... contains an argument that is not allowed.

Examples of unsupported parameters include:

  • user-defined DEBUG no
  • user-defined SEND
  • user-defined CIPHERLIST DEFAULT
  • user-defined SSL_PROFILE_NAME ...

Environment

  • BIG-IP LTM systems configured for high availability
  • ConfigSync enabled
  • AS3-managed health monitors
  • A monitor is deleted and recreated with the same name but a different type
  • The deletion and recreation occur in the same transaction
  • Examples include changing an HTTPS monitor to an HTTP monitor or changing an External monitor to an in-TMM monitor.

Cause

MCPD can create an inconsistent monitor state when a monitor is deleted and recreated with the same name but a different type in a single transaction.

MCPD incorrectly retains parameters from the previous monitor type. The resulting monitor contains unsupported user-defined fields, which cause the receiving BIG-IP system to reject the configuration during ConfigSync.

This is an MCPD monitor-state issue, not an AS3 syntax or special-character issue.

Answer/Recommended Actions

  1. Review the monitor configuration on the active BIG-IP system and identify monitors containing unsupported user-defined parameters.
  2. Remove the stale parameters using the approved BIG-IP configuration procedure.
  3. If a monitor cannot be safely repaired, delete it and create a replacement monitor with a new name and the required monitor type.
  4. Validate the monitor configuration on the active system.
  5. Confirm that the configuration is valid before initiating ConfigSync.
  6. Upgrade AS3 to a release containing the fix for this monitor transaction issue.
  7. When changing a monitor type, perform the deletion and creation as separate operations rather than in one transaction.
  8. Alternatively, create the replacement monitor with a new name instead of reusing the original name.

Additional Information

  • The AS3 fix separates monitor deletion and creation into different transactions, preventing new monitors from inheriting stale parameters.
  • Upgrading AS3 does not automatically repair monitors that already contain invalid user-defined fields. Existing affected monitors must be corrected or recreated.
  • The issue can affect multiple monitors, so inspect all relevant monitors rather than only the object identified in the ConfigSync error.
  • The user-defined property is intended for External monitor environment-variable configuration and is not valid for standard HTTP, HTTPS, or other in-TMM monitor types.
