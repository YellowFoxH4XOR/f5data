Issue

You should consider using this procedure under all of the following conditions:

  • You want to troubleshoot network access connection and access issues.
  • Linux users are unable to use f5fpc to connect to the BIG-IP APM system to establish network access sessions or access internal resources.

Symptoms

As a result of network access issues, you may encounter any of the following symptoms:

  • Users cannot establish a network access session with the BIG-IP APM system.
  • Users cannot access configured internal resources after establishing a network access session.

Recommended Actions

This article provides steps for troubleshooting common connectivity and login issues that occur when you access a BIG-IP APM system as a network access user from a Linux system.

Note: For Windows troubleshooting, refer to K17421: Troubleshooting BIG-IP APM client issues on Microsoft Windows systems.

Important: F5 supports BIG-IP APM system software and BIG-IP Edge Client software. F5 does not support third-party software, such as the client operating system or non-F5 applications that are installed on the client system.

Procedures

When you experience network access issues, you can use the following troubleshooting steps to determine the root cause:

  • Verifying whether the issue is client-specific
  • Verifying third-party software conflicts and Linux client f5fpc prerequisites
  • Verifying that the Linux client version matches the BIG-IP APM version
  • Reinstalling or updating the f5fpc client
  • Verifying supportability of the Linux client and BIG-IP APM network access configuration setup
  • Using the f5fpc --info to verify connection status and statistics
  • Verifying basic network connectivity
  • Enabling debug logging and verifying client-side and BIG-IP APM log messages
  • Taking a packet capture on the Linux client and the BIG-IP APM system

Verifying whether the issue is client-specific

To isolate the issue, you should first troubleshoot by verifying whether the issue is due to a specific client machine or a group of clients by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Test the network access connection to the same BIG-IP APM virtual server from a Windows machine.
  2. Test multiple Linux clients running different Linux distributions.
  3. Perform connection tests on different Wi-Fi and mobile networks.
  4. Verify the BIG-IP APM network access virtual server configuration.

When a client connects to the BIG-IP APM system and accesses the network access services, the client goes through the following three phases:

  1. Establishing the VPN tunnel connection with the BIG-IP APM virtual server
  2. Logging in, authenticating, and authorizing as configured in the BIG-IP APM access policy
  3. Enforcing BIG-IP APM network access configuration settings on the Linux client, including PPP IP address, routing, DNS, and so on

To isolate the root cause of the issue, you must identify during which of the three phases the issue occurs. To do this, you should enable debug logging and follow the BIG-IP APM log file. To do so, enter the following command:

tailf /var/log/apm

Note: When you finish troubleshooting, you should return logging to its original setting.

Note: For more information on enabling debug logging for BIG-IP APM, refer to K22373944: Gathering data to investigate BIG-IP Edge Client connection issues.

Verifying third-party software conflicts and Linux client f5fpc prerequisites

Third-party software, in particular antivirus, firewall, and other VPN applications, can block network ports or denylist certain files and traffic required by f5fpc. You must review the security policies and other requirements of third-party applications against the following list of requirements for using the Linux client f5fpc. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Make sure that an administrative account or superuser authority is used to install the Linux network access client.
  • Make sure that the f5fpc client executable is installed in the /usr/local/lib/F5Networks directory and that the user has permissions to execute the files within the directory.
  • Make sure that the f5fpc client requires access to IP address 127.0.0.1 and port 44444. You need to open firewall ports to this address and port.

    For example, after network access is established, you can list the active network connections by typing the following command:

    netstat -pan | grep -i vpn

    The output may appear similar to the following:

    tcp        0      0 127.0.0.1:44444         0.0.0.0:*               LISTEN      3773/svpn_x86_64
    tcp        0      0 192.0.2.20:49226        198.51.100.3:443        ESTABLISHED 3772/svpn_x86_64

Note: The first connection is the loopback TCP connection that the PPP adapter uses to transport traffic to the local svpn process. The svpn process then encapsulates it into PPP packets over SSL and Datagram Transport Layer Security (DTLS) and forwards it to the BIG-IP APM system. The second connection lists the TCP connection between the IP addresses of the Linux client and the BIG-IP APM virtual server.

Verifying that the Linux client version matches the BIG-IP APM version

F5 recommends that the Linux client version match the BIG-IP APM version. Connecting a Linux client running a lower or higher version than the BIG-IP APM may lead to unpredictable behavior.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: For more information on the Linux client version and its corresponding BIG-IP APM version, refer to K13757: BIG-IP Edge Client version matrix.

To display the Linux client f5fpc version, enter the following command:

f5fpc --version

Reinstalling or updating the f5fpc client

Files installed on the client system appear in the following locations:

  • Configuration file: $HOME/.F5Networks/f5networks.conf
  • Executable files: /usr/local/bin/f5fpc
  • Library and VPN components files : /usr/local/lib/F5Networks
  • Log files: $HOME/.F5Networks/

Common installation error causes include the following:

  • Installing the Linux client without administrator privileges
  • Missing components or corrupt system files
  • Software previously improperly uninstalled 
  • Linux client version incompatibility with BIG-IP APM
  • Third-party program conflicts

In any of these listed circumstances, reinstalling or updating the Linux client may resolve the issue. To uninstall and install the f5fpc client, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system as the root user.
  2. Enter the following command:

    /usr/local/lib/F5Networks/uninstall_F5.sh

    For information on installing or updating the client, refer to K47922841: Using the Linux client f5fpc to connect to APM network access for the first time.

Verifying supportability of the Linux client and BIG-IP APM network access configuration setup

For information on the Linux client f5fpc supported features, refer to K23653432: BIG-IP APM client feature matrix. For example, on the CLI for Linux, BIG-IP APM supports only logging in with username and password and does not support any endpoint security features.

Using f5fpc--info to verify connection status and statistics

The --info or -i option provides real-time network access connection status and statistics on the client. When troubleshooting, make sure to closely follow the output of this command. For example, you can use a script to run the command every second while the network access connection is being established. Alternatively, you can use the watch command with the following command syntax:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

watch -n <update interval> "f5fpc --info"

For example, to display the network status every 1 second, enter the following command:

watch -n 1 "f5fpc --info"

Verifying basic network connectivity

The following procedure checks basic network connectivity associated with establishing network access and application access connections.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system using an account with local administrator privileges.
  2. Verify DNS resolution of the BIG-IP APM virtual server and other internal resources by using the dig command with the following syntax:

    dig <domain name>

  3. Verify TCP connectivity with the ping or telnet command from the Linux client with the following command syntax:

    telnet <domain name> <port number>

    For example:

    telnet examplehost.com 443

Enabling debug logging and verifying client-side and BIG-IP APM log messages

You can obtain more information about the root cause of the issue by enabling debug logging on both the Linux client and the BIG-IP APM system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To enable debug logging on BIG-IP APM, refer to K22373944: Gathering data to investigate BIG-IP Edge Client connection issues.
  2. To enable debug logging for f5fpc, refer to K12321: Enabling Network Access debugging for Mac OS X and Linux.

After debug logging is enabled for f5fpc, you can reproduce the issue and following the client-side log files using the following command syntax:

tailf $HOME/.F5Networks/<log filename>

For example, to follow the logs in on the Linux client, enter the following commands:

  • tailf $HOME/.F5Networks/standalone.log
  • tailf $HOME/.F5Networks/svpn.log

Note: When you finish troubleshooting, you should return logging to its original setting.

Taking a packet capture on the Linux client and the BIG-IP APM system

If you've performed the previous procedures and the issue still exists, or if the issue relates to slow application speed, you can perform a packet capture on the Linux client and the BIG-IP APM system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. For information on performing a packet capture on the BIG-IP APM system, refer to K22373944: Gathering data to investigate BIG-IP Edge Client connection issue.
  2. If the issue relates to a problem in establishing the VPN tunnel with the BIG-IP APM virtual server, you can perform a packet capture on the client's network interface using the following command syntax:

    tcpdump -ni <interface> host <APM virtual server IP address>

    For example:

    tcpdump -ni eth0 host 192.0.2.10

    Note: You can display the interface name using the Linux ifconfig command.

    If the Linux client can establish the VPN tunnel but is unable to access internal resources, you can perform a packet capture on the client's tun interface that is filtering the PPP IP address by using the following command syntax:

    tcpdump -ni <tun interface> host <client PPP IP address>

    For example:

    tcpdump -ni tun0 host 192.0.2.10

    Note: After the VPN tunnel is established, you can obtain both the tunnel interface name and the PPP IP address of the client using the Linux ifconfig command.
