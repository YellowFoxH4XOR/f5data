Description
DNSSEC is configured. When querying one BIG-IP DNS the correct signed response is given. But when querying other BIG-IP DNS in the Sync Group, the responses do not contain the RRSIG record.
This can be verified by sending the query directly to each BIG-IP DNS Listener IP address:
dig @<DNS_LISTENER_IP> +dnssec +multi example.com

Also, the following logs may be found in /var/log/ltm:
01010231:4: DNSSEC: Did not add RRSIGs to response RR set (owner: example.com)

When reviewing logs on /var/log/tmm you find "passphrase decryption failure" logs, like this:
<date> <hostname> notice passphrase decryption failure (final stage)
<date> <hostname> notice MCP message handling failed in 0x86ae00 (16908289): <date> on 2 - MCP Message:
<date> <hostname> notice create {
<date> <hostname> notice gtm_dnssec_key_generation {
<date> <hostname> notice gtm_dnssec_key_generation_key_name "/Common/key_example_com"

Environment

  • DNSSEC
  • BIG-IP DNS Sync Group
  • DNSSEC keys do have "generation" associated data

Cause
Master key is different among the BIG-IP DNS devices of the Sync Group. Therefore, DNSSEC key failed to be decrypt with master key on the failing BIG-IP DNS.

Recommended Actions

Master key must be same to make sure DNSSEC work properly in a BIG-IP DNS Sync Group.
Follow this article to re-key the failing the BIG-IP DNS unit:
K13542: Restoring DNSSEC or password protected configuration data to a BIG-IP GTM or BIG-IP DNS RMA unit
