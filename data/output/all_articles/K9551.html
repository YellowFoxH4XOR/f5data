K9551: The BIG-IP WebAccelerator may compress content for a normalized response

Topic

Requests for normalized objects may be compressed even if compression is disabled for the original object type in the acceleration policy. The client determines compression for the normalized objects. If the client request contains the Accept-Encoding=gzip HTTP header, the BIG-IP WebAccelerator response will be compressed.

If compression for an object is not desired, you can prevent normalization for the object by disabling content-based identity in the Advanced Assembly section of the BIG-IP WebAccelerator policy. For more information, refer to K8379: Overview of advanced assembly features for WebAccelerator policies and the Selectively disabling content-based identity section of the Configuration Guide for the BIG-IP WebAccelerator System.

If disabling content-based identity is not desired, you can disable compression for the normalized objects by setting the compressToClient value to none for the object type in the globalfragment.xml file. For more information, refer to the Setting the Enable Content Compression option section of the Configuring Assembly Rules chapter in the Policy Management guide for the BIG-IP WebAccelerator System.

Note: Beginning in BIG-IP WebAccelerator 11.x, URL normalization is no longer supported.
