Description

After the authentication phase, vmware remote desktop cannot be launched and the connection is reset.

APM logs:

Invalid session id: 6fc85561043c8b94e62c402e5a26a8f5 0fd0d64089858ffc441227445a26a8f5 

But after failing-over to the box running an older version, vmware remote desktop can be launched without any problems.

Note: When configured using iApp, the problem doesn't occur. 

Environment

  • Two devices in a cluster, one is upgraded, and the second one is running an old version.
  • VDI deployment configured without iapp

 

Cause

After access policy evaluated, response from tmm to the client did not include http header

"Set-Cookie: JSESSIONID=6fc85561043c8b94e62c402e5a26a8f5" (w/ the right session id)

 so the next requests from client did not include the right session id but the last session rotation id, which caused it to fail

Recommended Actions

Disabling session rotation fixed this issue. 

# tmsh modify /sys db apm.rotatesessionid value disable
# tmsh save /sys config
