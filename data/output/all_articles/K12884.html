Topic

You should consider using this procedure under the following condition:

  • You want to increase the recursion depth for when the system uses the Perl Compatible Regular Expressions (PCRE) to match request data against attack signatures.

    Note: The procedure described in this article only applies to attack signatures that use PCRE, and does not apply to signatures that use the RE2 regular expression library. For information about using the RE2 regular expression library for attack signatures, refer to K13814: Change in Behavior: Attack Signatures now support the RE2 regular expression library

Description

By default, the BIG-IP ASM bd process limits the recursion depth when matching request data against regular expressions. This behavior limits the amount of resources that can be dedicated to any one evaluation operation. Certain combinations of attack signatures and request payloads may result in a long recursive evaluation that reaches the maximum depth before determining if the attack signature matches. By default, the maximum depth for recursions is set to 5,000. When the system reaches the maximum recursion depth, the default behavior is to block the request and log the event as an Attack Signature violation. The ASM system logs an additional message with the violation to distinguish the false positive from a true match, which appears similar to the following example:

The signature is not matched. The matching process exceeded the maximum number of allowed recursions.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You can access the BIG-IP ASM system command line.

Procedures

Modifying the maximum number of allowed recursions

You can modify the maximum number of allowed recursions by setting the pcre_match_limit internal parameter value. To do so, perform the following procedure:

Impact of procedure: Increasing the recursion depth allows more resources to be allocated to a single evaluation operation, potentially exposing the BIG-IP ASM system to performance degradation or denial-of-service (DoS) attacks. Any changes to this setting should be thoroughly tested to determine the best settings for your production environment.

  1. Log in to the BIG-IP ASM command line.
  2. To set the parameter value, use the following command syntax:

    /usr/share/ts/bin/add_del_internal add pcre_match_limit <value>

    For example, to set the pcre_match_limit to 10000, type the following command:

    /usr/share/ts/bin/add_del_internal add pcre_match_limit 10000

  3. Restart the BIG-IP ASM system by typing the following command:

    Important: This step briefly disrupts traffic.

    bigstart restart asm

To return the BIG-IP ASM system to the default setting, you can use the same process and set the pcre_match_limit parameter value to 5000 in step 2.
