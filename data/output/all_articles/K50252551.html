Description

OMM killer triggered killing BD and Java is a top consumer of memory.

Example of Java as a top consumer of memory:

pid  Command                                     Threads    Size (kB)    Rss (kB)    Pss (kB)
-----  ----------------------------------------  ---------  -----------  ----------  ----------
 2504  ./bd tmm_count 8 proc_cpuinfo_cpu_mhz 20         19      4820008      805548      795348
14666  /usr/share/avr/bin/monpd                         20      1995704      536548      531018   
14695  /usr/lib/jvm/jre/bin/java -Dsun.jnu.enco         28      1356392      501640      498665    <==== 
21517  /usr/lib/jvm/jre/bin/java -Dhttps.protoc         60       785120      485552      484100

Environment

  • ASM provisioned

Cause

This behavior is caused by a known issue tracked with the Bug ID 746167

Recommended Actions

Review Bug ID 746167 for fixed versions. 
Alternatively you can use the following steps as a workaround:

  1. Connect to CLI
  2. Mount the following /usr partition as re-write

    mount -o remount,rw,noatime /usr

  3. Modify the /usr/share/nsyncd/bin/nsyncd to disable Java's use of huge-pages

    Change the line from:
    JVM_OPTIONS+=" -Dsun.jnu.encoding=$ENCODING -Dfile.encoding=$ENCODING"

    To:
    JVM_OPTIONS+=" -XX:-UseLargePages -Dsun.jnu.encoding=$ENCODING -Dfile.encoding=$ENCODING"

  4. Mount the partition as read-only

    mount -o remount,ro,noatime /usr

  5. Restart nsyncd-related processes

    pkill -f nsyncd
