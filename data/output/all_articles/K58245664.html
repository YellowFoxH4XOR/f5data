Known Issue

The Traffic Management Microkernel (TMM) may restart when the Reuse Connection option is enabled for an iSession tunnel.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with an iSession profile.
  • The iSession profile has the Reuse Connection option enabled and also has either or both of the following options enabled:
     
    • Deduplication
    • Compression

Impact

Traffic is disrupted while the TMM process restarts. If configured for high availability, the device fails over to another device in the device group. During tunnel reuse, TMM asserts with an Isession data not drained message and restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H526443 on the Diagnostics > Identified > Medium page.
  • An Assertion Isession data not drained message is generated to the /var/log/tmm file that appears similar to the following example:

    notice panic: ../modules/hudfilter/isession/isession.c:2552: Assertion "Isession data not drained" failed.
    notice ** SIGFPE **

  • TMM generates a core file to the /shared/core/ directory.

Resolution

Status
