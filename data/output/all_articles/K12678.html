Known Issue

This is the result of a known issue. If you attempt to reset pool statistics when the pool resides in an administrative partition that is configured with a default route domain with an ID other than zero, the attempt fails.

Note: The default route domain is configured with a route domain ID of zero. For more information about route domains, refer to the TMOS Management Guide for BIG-IP Systems, and the BIG-IP Local Traffic Manager: Implementations guide.

For example, the following partition called partition_abc is configured with a default route domain with an ID other than zero:

partition partition_abc {
   default rd id 1
}

In addition, pool pool_abc resides in partition partition_abc:

pool pool_abc {
   partition partition_abc
   members {
   10.2.63.41%1:http { }
}

If you attempt to reset the pool statistics for pool pool_abc by using the Configuration utility or command line utilities such as the bigpipe or tmsh commands, the attempt fails.

F5 Product Development tracked this issue as ID 341662, and it was fixed in BIG-IP versions 10.2.2 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.
