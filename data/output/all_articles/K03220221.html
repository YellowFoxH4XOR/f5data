K05920565: Software installation fails with Error Message : "failed (Could not access configuration source; sda/vda, 1 )" error during a BIG-IP software upgradeDuring a BIG-IP software upgrade, installing a new software image in a new partition (both via webUI or TMSH) is failing with an error message.
K31992159: After upgrading to 13.1.x you are not able to see configuration objects on the BIG-IP due to a configuration load failureInvalid keyword 'kedh' in ciphers list error triggers configuration load failure. Occurs after upgrading from BIG-IP 13.1.x to another 13.1.x version for example 13.1.3.4 to 13.1.3.6.
K12017200: CPU usage spikes after upgrade or enabling Analytics profile potentially causing GUI to become unavailableWhen the avrd process is initialized after an upgrade and reboot, it communicates with mcpd to process BIG-IP configuration details. If the BIG-IP system contains a large configuration with several thousand objects, this will lead to avrd consuming 100 percent CPU for up to 30 minutes.
K05254522: Out of memory and configuration load failed errors occur after upgradingAfter an upgrade, the BIG-IP system may become unresponsive, perform very slowly, and display out of memory and configuration load errors.
K33233632: After upgrade and reboot with Install Configuration set to Yes, the BIG-IP appears to have hung or lost all configuration and mcpd, gtmd, named and others are in a restart loopAfter you upgrade the BIG-IP system to BIG-IP 14.1.2 and later, certain daemons (e.g. mcpd, gtmd, and named) may be in a restart loop and the BIG-IP appears to have hung or lost all configuration.
