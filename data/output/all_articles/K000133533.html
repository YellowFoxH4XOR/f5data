Description

SYN packet was not forwarded by BIG-IP, the issued SYN packet was marked as 'Flow reuse or SYN retransmit'.This is intended to highlight initial packets that match a pre-existing flow.
For example,
F5 Ethernet Trailer Protocol
    F5 Trailer Header - Version: 1
    Low Details
    Medium Details
    High Details
    [Analysis]
        [Expert Info (Warning/Sequence): Flow reuse or SYN retransmit]
 

Environment

  • Virtual Server type is ip-forward
  • fastl4 profile is used
  • BIG-IP LTM

Cause

This behavior was introduced by Bug ID 536563, F5 has a hard-coded limit of 4 SYNs that can be retransmitted​​​​​​. That means fastL4 VS is forwarding only the first 4 SYNs within a connection. All SYNs after that are dropped.
 

Recommended Actions

  •   The bellowing POA can be applied to verify if the SYN packet matched an existing connection
              1. Clear all the sessions for the issued virtual server
              2. Run while true;do date >> /var/tmp/conn_table.txt;tmsh show sys connection ss-server-addr <>>>/var/tmp/conn_table.txt;sleep 10;done; 
              3. Run step 2 for 1 min, open a second window to run captures.
              4. Stop step 2 and 3 once you replicate the issue.
              5. Upload conn_table.txt, capture,  and a fresh qkview.
  • Check if it's expected behavior to send multiple SYNs which matched the existing connection, this may be due to the connection was not correctly closed, or idle timeout on BIG-IP is too long
  • We can disable the limit by the bellowing command
tmsh modify sys db tm.dupsynenforce value disable
