Issue

Error Message

NET_NFS-0-DBG-NFS_DIRECT_ID_OUT_OF_BOUNDS::File server at <file server> had max inodes of <inodes> at enable time, but just returned a higher inode, <inodes_2>

In this error message, note the following:

  • <file server> is the IP address of the filer that is experiencing the issue.
  • <inodes> is the number of inodes the filer at one time reported.
  • <inodes_2> is the number of inodes the filer is now reporting.

For example:

NET_NFS-0-DBG-NFS_DIRECT_ID_OUT_OF_BOUNDS:: File server at 10.101.0.10 had max inodes of 16777215 at enable time, but just returned a higher inode, 18403875

Message Location

You may encounter this message in the following location:

  • The ARX procdat log file

Note: The procdat log file is included in the /acopia/var/log directory of the ARX system diagnostic information file.

Description

This message occurs when all of the following conditions are met:

  • The ARX system is connecting to an NFS share through a direct volume.
  • The maximum number of inodes has changed since the file server was configured and the namespace share was enabled.

When a share is enabled, the ARX system stores the maximum number of inodes in the filer configuration. This error occurs when the maximum number of inodes on the filer is changed while the ARX shares are enabled. Due to this filer reconfiguration, the ARX may request an inode that is now out of range of the new configuration.

Impact

Clients cannot access files or directories, or list the contents of the parent directories.

Recommended Actions

To recover from this state, you can disable and then re-enable the affected ARX shares. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by entering the following command:

    enable

  3. Enter global mode by entering the following command:

    global

  4. Enter the namespace configuration mode by using the following command syntax:

    namespace [namespace name]

  5. Enter the volume configuration mode by using the following command syntax:

    volume [volume name]

  6. Enter a shares configuration mode by using the following command syntax:

    share [share name]

  7. Disable the share by entering the following command:

    no enable

  8. Exit the share configuration mode by entering the following command:

    exit

  9. Repeat steps 6 and 7 until all of the shares involved have been disabled.
  10. Re-enable the disabled shares by entering the following command in each share's configuration mode:

    enable

  11. Repeat step 10 until all shares involved have been enabled.
  12. End the configuration mode and return to privileged mode by entering the following command:

    end
