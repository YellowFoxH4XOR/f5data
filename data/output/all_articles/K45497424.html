K45497424: ASM bd failing to start with error ''Plugin configuration load timeout.''

Type
Support Solution
Published
2020-07-15
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 13.X.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.X, 13.0.1, 13.0.0, 13.1.0
Source
https://my.f5.com/manage/s/article/K45497424

Description

  • ASM device on OFFLINE state
  • BD process is continuously restarting
  • The following error message is logged on /var/log/ts/bd.log

    BD_MISC|ERR |Jun 05 02:26:26.214|30817|main.c:0415|Plugin configuration load timeout. Exiting.

  • The following messages are logged on /var/log/asm 
    Jun  5 02:26:46 LTM1.example.com crit perl[22089]: 01310027:2: ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog
detected failure for process. Process name: pabnagd, Failure: Insufficient number of threads (required: 2, found: 0).
Jun  5 02:26:50 LTM1.example.com crit perl[22089]: 01310027:2: ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog
detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).

Environment

  • ASM provisioned
  • The virtual server is associated with a websecurity profile (No ASM policy is needed)
  • The virtual server is associated with an LTM policy with external-file data-group is being used
  • There is only one virtual server is using the websecurity profile

Cause

Seen behavior is caused by a known issue tracked with the bug ID 918969

Recommended Actions

There is no fix at the time of creation of this support article. As a workaround you can create a dummy virtual server with websecurity (ASM policy) associated.

Additional Information

None
