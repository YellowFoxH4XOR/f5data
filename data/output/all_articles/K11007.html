Topic

For each request, the BIG-IP WebAccelerator inserts some additional HTTP request headers for internal use. These headers are intended to be removed before the request is sent to the origin webserver (OWS); however, some may not be removed.

Note: For more information, refer to K8658: The BIG-IP WebAccelerator does not remove all internal HTTP headers. 

The X-PvMAC header is inserted to help detect issues that may cause a loop in the application traffic. This functionality is intended to support configurations in which requests pass through the BIG-IP WebAccelerator multiple times for processing.

When the Apache Rewrite module (mod_rewrite) is configured with a RewriteRule that contains the [P] (Proxy) flag, the X-PvMAC header, may cause Apache to respond with an HTTP 502 Bad Gateway response, rather than returning the correct and expected HTTP response to the request.

You can work around this issue for BIG-IP version 9.4.8 or earlier by refactoring your RewriteRule to no longer use the [P] directive, or you can contact F5 Networks Technical Support for more information.

Alternatively, in BIG-IP versions 10.x, you may strip the X-PvMAC header from requests before they are sent to the OWS. To do so, apply an iRule to your BIG-IP WebAccelerator enabled virtual servers that appears similar to the following example:

when HTTP_REQUEST_SEND {
  clientside { HTTP::header remove "X-PvMAC" }
}
