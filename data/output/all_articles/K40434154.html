Description

Copying files using winSCP that references a relative path fail with an error similar to the following:

"SCP transfer fail with error "SCP Protocol error: Invalid control record (r; elative addresses not allowed)" Copying files from remote side failed"

Executing scp commands that reference a relative path fail with an error message similar to the following:

"relative addresses not allowed"

Environment

  • BIG-IP
  • WinSCP
  • SCP 

Cause

  • Bug ID 1097193
  • Bug ID 1112109

 

Recommended Actions

The following workarounds may be used to transfer files from BIG-IP:
 

  1. For WinSCP, select the SFTP protocol instead of SCP.

    Note:  To use SFTP, the user must be assigned the Administrator role and have access to the Advanced Shell (bash). For more information, refer to K82348433: Advanced shell access for non-administrator users may be restricted after an upgrade and K38941195: BIG-IP Resource Administrator vulnerability CVE-2019-6617.

    Regarding default admin and root accounts
    By default, admin account won't have access via WinSCP because it doesn't have advanced shell access.
    root account will trigger this error message when using "Download" option on WinSCP. However, "Copy" and "Paste" options should work instead.

  2. For command-line SCP utility, avoid using relative paths.

    Examples of scp failures with relative paths:

    scp test.log root@10.10.10.1:/shared
    relative addresses not allowed

     scp ./test.log root@10.10.10.1:/shared
    relative addresses not allowed


    Example scp with absolute paths:
                                         
     scp /config/test.log root@10.10.10.1:/shared

           

Additional Information

Remotely authenticated users will fail with SFTP due to not having advanced shell access. 
If you run into issues with a remotely authenticated account then use a local user account with advanced shell access.
