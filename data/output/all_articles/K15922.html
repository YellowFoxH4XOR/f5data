Known Issue

Displaying a large number of persistence records in the Configuration utility may cause the mcpd process to excessively consume memory resources and restart.

This issue occurs when the following condition is met:

  • You attempt to view a large number of persistence records through the Configuration utility.

Impact

The BIG-IP system may temporarily fail to process traffic and fail over if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H495295 on the Diagnostics > Identified > High page.
  • The system experiences high memory usage or exhaustion.
  • The mcpd process restarts, which results in a failover if the system is configured for high availability (HA).
  • In the /var/log/tomcat/catalina.out file, the system logs error messages similar to the following examples :

    SEVERE: Caught exception (java.lang.OutOfMemoryError: Java heap space) executing org.apache.jk.common.ChannelSocket$SocketAcceptor@143df98, terminating thread
    SEVERE: Servlet.service() for servlet org.apache.jsp.tmui.locallb.stats.persistence.stats_jsp threw exception

  • In the /var/log/ltm file, the BIG-IP system logs an error message similar to the following example:

    crit tmm3[14154]: 01010020:2: MCP Connection aborted, exiting

Workaround

For systems with large numbers of persistence records, you can work around this issue by using the Traffic Management Shell (tmsh) to view persistence records and associated statistics. Beginning in BIG-IP 11.5.3 HF2, 11.6.1, and 12.0.0, the following three database keys were introduced to allow an administrator to disable querying persistence records though the Configuration utility:

ui.statistics.modulestatistics.localtraffic.persistencerecords
ui.statistics.modulestatistics.dnsdelivery.persistencerecords
ui.statistics.modulestatistics.dnsgslb.persistencerecords

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

To disable the viewing of persistence records using the Configuration utility, you can set the previously mentioned three database keys to false by using the following command syntax:

modify sys db <db.key> value false

In this command syntax, <db.key> is one of the database keys listed above.

To enable viewing of persistence records from within the Configuration utility, set the database keys above to true.

Note: Beginning in 12.0.0, the default setting for these database keys is false, which disables querying persistence records from the Configuration utility.
