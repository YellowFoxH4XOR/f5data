Known Issue

This is the result of a known issue. The gateway failsafe pool feature contains a threshold option, which specifies the minimum number of gateway pool members that must be available. If the threshold falls below this value, the system triggers the gateway failsafe action.

When you define the threshold setting for a gateway failsafe pool, the BIG-IP system adds the pool min up member entry to the high availability table with a corresponding failover action. If you delete a pool object using the command line or Configuration utility without first removing the gateway failsafe designation for the pool, the pool min up member entry is not removed from the high availability table.

Note: If you remove the gateway failsafe designation for the pool prior to deleting the pool, the pool min up member entry is removed from the high availability table.

F5 Product Development is tracking this issue as ID 249299 (formerly CR117685) and has been fixed in BIG-IP 11.0.0. For information about upgrading, refer to the LTM release notes.

Workaround

You can work around this issue by using the bigpipe command to set the min up members to 0 (zero) for the pool name. For example, if you deleted a pool object without first removing the gateway failsafe designation for the pool, you would perform the following procedure:

  1. Log in to the command line.
  2. To verify that the pool entry remains in the high availability table, type the following command:

    bigpipe ha table show

    For example, in the following bigpipe command output, the pool min up member entry exists in the high availability table with a my_test_pool pool.

    Feature Key Action En? Act Data
    pool min up member my_test_pool failover yes yes 1

  3. To set min up members to zero, use the following bigpipe command syntax:

    bigpipe pool <pool_name> min up members 0

    For example:

    bigpipe pool my_test_pool min up members 0

  4. Save the configuration by typing the following command:

    bigpipe save
