Description

In certain scenarios, you may need to block a specific user from accessing your site. The following iRule will block a user by searching the payload and rejecting the user when they try to POST their credentials.

Environment

  • BIG-IP
  • iRules

Cause

Using iRules you can parse the HTTP::payload and search for specific users and drop them if needed for security reasons.

Recommended Actions

Please modify and create the following iRule to meet your needs:

  1. Log in the BIG-IP WebUI

  2. Navigate to: Local Traffic  ››  iRules : iRule List  ››  Click Create...

  3. Name the iRule and update user1 to the username you would like to reject.
    Note: Ensure the username is lowercase to match.

    when HTTP_REQUEST {
        if { [HTTP::method] eq "POST" } {
            if { [HTTP::header exists "Content-Length"] && [HTTP::header "Content-Length"] ne "" && [HTTP::header "Content-Length"] <= 1048576 } {
                set content_length [HTTP::header "Content-Length"]
            } else {
                set content_length 1048576
            }
            if { $content_length > 0 } {
                HTTP::collect $content_length
    #           log local0. "$content_length"
            }
        }
    }
    when HTTP_REQUEST_DATA {
        set payload [HTTP::payload]
        if  { [string tolower $payload] contains "user1"  } {
            reject
    #        log local0. "REJECT USER"
        } 
        HTTP::release
    }
     

  4. Click Finished

  5. Apply the iRule to the Virtual Server in question.

Additional Information

If you need to block a group of users from accessing your site, you can include the group of usernames in a data group and reference it in the iRule. Specifically changing this line in the iRule from step 3 of the Recommended Actions section:

if  { [string tolower $payload] contains "user1"  } {

to

if  { [class match [string tolower $payload] contains <data group name>]  } {

For example, you can create a data group named payload_usernames that contains three users (user1, user2, user3) using the tmsh utility:

create /ltm data-group internal payload_usernames { records add { user1 { } user2 { } user3 { } } type string }

Verify the data group with three users is successfully created using the tmsh utility:

list /ltm data-group internal payload_usernames

The command should return an output similar to the following example:

ltm data-group internal payload_usernames {
    records {
        user1 { }
        user2 { }
        user3 { }
    }
    type string
}

Alternatively, you can use the BIG-IP Configuration utility to create the data group. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules > Data Group List.
  3. Select Create.
  4. Enter a name for the data group in the Name setting. For example, payload_usernames.
  5. Select String in the Type setting.
  6. Enter the username in the String setting and select Add.
  7. Repeat the previous steps to add all the usernames.
  8. Select Finished to save the changes.

Next, modify the iRule from step 3 of the Recommended Actions section. The final iRule should look similar to the following example:

when HTTP_REQUEST {
        if { [HTTP::method] eq "POST" } {
            if { [HTTP::header exists "Content-Length"] && [HTTP::header "Content-Length"] ne "" && [HTTP::header "Content-Length"] <= 1048576 } {
                set content_length [HTTP::header "Content-Length"]
            } else {
                set content_length 1048576
            }
            if { $content_length > 0 } {
                HTTP::collect $content_length
    #           log local0. "$content_length"
            }
        }
    }
    when HTTP_REQUEST_DATA {
        set payload [HTTP::payload]
        if  { [class match [string tolower $payload] contains payload_usernames] } {
            reject
    #        log local0. "REJECT USER"
        } 
        HTTP::release
    }

Ensure the modified iRule is applied to the Virtual Server in question.
