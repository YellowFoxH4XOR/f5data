Description
You observe one or more of the following symptoms when using SNMP to query the BIG-IP for virtual server statistics data after an upgrade:
  • SNMP polling failing frequently, or monitoring systems getting little data post-upgrade
  • tmsh commands and GUI are slow compared to prior version
  • CLI is sluggish or has low responsiveness
  • iControl REST commands resulting in 400 response codes and timeouts
  • large number of log messages similar to the following in /var/log/kern.log while TMM/dataplane cpu usage appears to be normal
    info kernel: ltm driver: Idle enforcer starting - tid: <pid> cpu: <core ID X>/<core ID Y>

Environment

  • BIG-IP version 14.1 or later
  • Large number of virtual server configuration objects, or virtual servers configured with address or port lists
  • Frequent SNMP queries for virtual server statistics OIDs within F5-BIGIP-LOCAL-MIB::ltmVirtualServStat

Cause
Support for features added in 14.1 caused an additional performance impact when mcpd process is querying the virtual_server_stat table. Bug ID 1008837 has been created for this issue.

Recommended Actions
As a workaround, you may reduce the load on mcpd by increasing the monitoring interval for your network management systems and/or modify the cache settings in the snmpd configuration file to reduce the amount that snmpd queries mcpd for this virtual server table. K13778: Configuring the SNMP subagent cache setting describes how to adjust these cache variables.

Note: Changes to these cache settings will not persist through an upgrade.

Additional Information
The time it takes these mcpd queries to return increases quadratically with the number of virtual servers
