Topic

You should consider using this procedure under the following condition:

  • You need to reset the password for an administrative account, such as the root account on a vCMP guest.

Description

vCMP allows a BIG-IP system to run multiple instances of the BIG-IP software on a single hardware platform. Depending on the hardware platform and BIG-IP software version, a vCMP guest can span more than one blade in a VIPRION chassis or it can reside on one blade or an appliance such as the BIG-IP 10200v.

When you need to reset a lost or forgotten password for an administrative account (such as root on any BIG-IP system), you must boot the system into single-user mode before you can change the password for the account. Booting a BIG-IP system into single-user mode requires access to the BIG-IP serial console port. However, a vCMP guest does not have a physical serial console port. In the place of a physical serial console port, a vCMP guest has a virtual console port, which can be accessed using the vconsole utility on the vCMP host. The vconsole utility can be invoked from the command line on the vCMP host. To do so, use the following command syntax:

vconsole <guest name> <slot number>

Where:

  • <guest name> is the name of the vCMP guest as configured on the vCMP host.
  • <slot number> applies to blade slot for a VIPRION system.

Depending on your vCMP guest configuration, you should perform either one of the following procedures if you want to reset an administrative password:

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have command line access to the vCMP host.

Procedures

  • Resetting a lost or forgotten administrative account password on a vCMP guest that spans more than one blade
  • Resetting a lost or forgotten administrative account password on a vCMP guest that resides on one blade or appliance

Resetting a lost or forgotten administrative account password on a vCMP guest that spans more than one blade

Impact of procedure: This procedure requires that you boot the vCMP guest into single-user mode. While in this mode, the vCMP guest is unable to process traffic.

  1. Log in to the command line on the vCMP host.
  2. Shut down the vCMP guest by using the following command syntax:

    tmsh modify vcmp guest <guest name> state configured

    For example, enter the following command to shut down a vCMP guest myguest1:

    tmsh modify vcmp guest myguest1 state configured

  3. Start the desired vCMP guest by using the following command syntax:

    tmsh modify vcmp guest <guest name> state deployed

    For example, enter the following command to start a vCMP guest myguest1:

    tmsh modify vcmp guest myguest1 state deployed

    Note: You must perform the next step immediately. Otherwise, you may miss the GRUB menu in step 5 and have to repeat from step 2 again.

  4. Connect to the vCMP guest virtual console by using the following command syntax:

    vconsole <guest name> <slot number>

    For example, enter the following command to connect to the vCMP guest myguest1 virtual console on slot 2:

    vconsole myguest1 2

  5. To restart the vCMP guest in single-user mode, refer to one of the following articles:
    • For BIG-IP 5000, 7000, 10000, 12000 series platforms, refer to K4178: Booting the BIG-IP system in single-user mode (GRUB 0.97)
    • For all other platforms, refer to K14662: Restarting the BIG-IP system in single-user mode (GRUB2

      Note: Devices that contain an SSD hard drive may boot so quickly that you may require two console windows open to view the GRUB menu objects; one console window to restart the VCMP guest and the other watching the VCMP vconsole utility.

  6. At the single-user mode prompt, reset the administrative account password by using the following command syntax passwd <account> For example:

    passwd root

    Note: Bash command-line utilities including the passwd utility may not be available unless the system volumes are mounted. For more information refer to: K35811337: How to recover the root password on non-RAID BIG-IP platforms

  7. When prompted, enter a new password.
  8. Enter exit or reboot to return to the normal operating mode.

    Note: For a vCMP guest that spans more than one blade on a VIPRION system, you must perform the next step immediately. Otherwise, you may have to repeat step 2 again.

  9. When the system presents the login prompt, log in with the new password you entered in step 7.
  10. After login, wait for the blade to join the cluster. You can monitor whether the blade has joined the cluster using the tmsh show sys cluster command. For example, if blade 2 has joined the cluster, the command reports an output similar to the following example:

    -----------------------------------------------------------------
    | Sys::Cluster Members
    | ID Address Availability State Licensed HA Clusterd
    -----------------------------------------------------------------
    | 1 :: available enabled true active running
    | 2 :: available enabled true active running
    | 3 :: unknown enabled false unknown shutdown
    | 4 :: unknown enabled false unknown shutdown

    • When the blade joins the cluster, determine which blade is the primary blade by typing the following command:

      tmsh show sys cluster | grep Slot

      For example, if the primary blade is in slot 2, the command returns the following output:

      Primary Slot ID 2

    • Access the primary blade identified in the previous step by entering the following command:

      ssh slot<primary slot ID>

      For example, enter the following command to access the primary blade in slot 2:

      ssh slot2

    • Modify the root password on the cluster by entering the following command:

      tmsh modify auth password root

    • When prompted, enter the new root password.
    • When prompted, re-enter the new root password to confirm.
    • Save the change on the cluster by entering the following command:

      tmsh save sys config

      Note: The cluster propagates the password change to all its member blades.

    • Optional: If you need to modify any other accounts, repeat step 13 to 16 replacing root with the account.

Resetting a lost or forgotten administrative account password on a vCMP guest that resides on one blade or appliance

Impact of procedure: This procedure requires that you boot the vCMP guest into single-user mode. While in this mode, the vCMP guest is unable to process traffic.

  1. Log in to the command line on the vCMP host.
  2. Shut down the vCMP guest by using the following command syntax:

    tmsh modify vcmp guest <guest name> state configured

    For example, enter the following command to shut down a vCMP guest myguest1:

    tmsh modify vcmp guest myguest1 state configured

  3. Start the vCMP guest by using the following command syntax:

    tmsh modify vcmp guest <guest name> state deployed

    For example, enter the following command to start a vCMP guest myguest1:

    tmsh modify vcmp guest myguest1 state deployed

    Note: You must perform the next step immediately. Otherwise, you may miss the GRUB menu in step 5 and may have to repeat from step 2 again.

  4. Connect to the vCMP guest virtual console by using the following command syntax:

    vconsole <guest name>

    For example, enter the following command to connect to the vCMP guest myguest1 virtual console:

    vconsole myguest1

  5. Use the appropriate article for your system to restart the vCMP guest in single-user mode:
    • For BIG-IP 5000, 7000, 10000, and 12000 series platforms, refer to K4178: Booting the BIG-IP system in single-user mode (GRUB 0.97)
    • For all other platforms, refer to K14662: Restarting the BIG-IP system in single-user mode (GRUB2)
       
  6. At the single-user mode prompt, reset the administrative account password by using the following command syntax:

    passwd <account>

    For example:

    passwd root

  7. When prompted, enter a new password.
  8. When you are done resetting the password, enter exit or reboot to return to the normal operating mode.
  9. When the system presents the login prompt, log in with the new password you entered in step 7.
  10. Optional: After login, reset any other accounts as needed by following the applicable procedure described in K13121: Changing system maintenance account passwords (11.x - 15.x).
