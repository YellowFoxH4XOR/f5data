Description

At times it may become necessary to fallback to a previous version of F5OS. Normally that can be done via the GUI. But what if that is not available what do you do?

Environment

Having to fallback to a previous version is not commonplace, but it is still sometimes necessary. In those rare instances the most common reason is due to something about an upgrade that did not go as expected.

Cause

In BIG-IP Classic with TMOS you could reboot and when the GRUB menu came up choose the version to fall back to. You could also use the switchboot command, in most cases, to do so. However, with F5OS nether of those choices exists.

Recommended Actions

To fallback to a previous version via the CLI:

Note: in some cases neither SSH or the GUI is available. In that case you will need to console in and run the commands via that connection. Also, with F5OS an EHF version includes both the EHF and the base version.

  1. Log in as root.
  2. To check the available iso files...echo 'list appliance_os' | nc -U /var/sw-mgmt.unix
    echo 'list appliance_serv' | nc -U /var/sw-mgmt.unix
    1. Example:[root@appliance-1(R5900-1):Active] ~ # echo 'list appliance_os' | nc -U /var/sw-mgmt.unix
      1.8.0-17564
      1.8.3-23493
      [root@appliance-1(R5900-1):Active] ~ # echo 'list appliance_serv' | nc -U /var/sw-mgmt.unix
      1.8.0-17564
      1.8.0-16036
      1.8.3-23493
    2. The first output shows bundled iso images. The second is unbundled. Select bundled to install a full F5OS version. Select Unbundled to install F5OS and service update releases independently. In most all cases bundled is recommended.
  3. Once the version has been selected then run the following one at a time:echo 'switch appliance_os <upgrded_version>' | nc -U /var/sw-mgmt.unix
    echo 'switch appliance_serv <upgrded_version> no_restart' | nc -U /var/sw-mgmt.unix
    reboot
    1. Example:echo 'switch appliance_os 1.8.0-17564' | nc -U /var/sw-mgmt.unix
      echo 'switch appliance_serv 1.8.0-17564 no_restart' | nc -U /var/sw-mgmt.unix
      reboot
  4. Once it is complete you can run the following to check if it booted properly:ls -l /var/docker/config/
    1. Example:[root@appliance-1(R5900-1):Active] ~ # ls -l /var/docker/config/
      total 8
      drwxr-xr-x. 4 root root 4096 Dec 23 00:47 appliance
      lrwxrwxrwx. 1 root root   48 Dec  4 16:19 env_var -> /var/docker/config/appliance/1.8.0-17564/env_var
      lrwxrwxrwx. 1 root root   46 Dec  4 16:19 extra -> /var/docker/config/appliance/1.8.0-17564/extra
      drwxr-xr-x. 3 root root 4096 Dec 23 00:47 patch
      lrwxrwxrwx. 1 root root   53 Dec  4 16:19 platform.yml -> /var/docker/config/appliance/1.8.0-17564/platform.yml
