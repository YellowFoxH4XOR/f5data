Description

After one or more configuration files are created in NIM Config ui, publishing the configuration fails. The following error is reported in the ui:

<nginx_instance>: Config apply failed (write): the file </path/to/file/example.conf> is outside the allowed directory list

If a new, Managed certificate is applied to an NGINX [Plus] instance, publishing the configuration fails via the ui timing out and the following error message is reported:

certs: </path/to/file/example.crt> outside allowed directory, not including in aux payloads

Environment

NGINX Instance Manager

Cause

On the NGINX [Plus] instance, the directory path to the configuration file or files is not specified in the NGINX Agent configuration's config_dirs parameter

Recommended Actions

On the NGINX [Plus] instance, perform the following procedure:

  • Edit the NGINX Agent configuration, /etc/nginx-agent/nginx-agent.conf
  • Add the failing configuration's directory path to the config_dirs parameter
    • Example: config_dirs: "/etc/nginx:/usr/local/etc/nginx:/usr/share/nginx/modules:/etc/nms:/var/log/nginx:/path/to/file"
  • Restart NGINX Agent: 
sudo systemctl restart nginx-agent.service

Additional Information

NGINX Agent only writes configuration files to directory paths that are specified in the NGINX Agent configuration's config_dirs parameter
