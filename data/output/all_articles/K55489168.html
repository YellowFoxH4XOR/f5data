Description

You may decide to remove APM from your BIG-IP configuration altogether and possibly deprovision it. You will be unable to deprovision APM until most APM configuration items are removed from LTM objects, such as virtual servers.

Environment

  • APM provisioned
  • APM configuration, including policies and profiles

Cause

None

Recommended Actions

Before starting:
Although you want to remove everything APM related, it can be a good idea to take a backup of the system with APM configuration object in it.

Removing APM objects:
If you want to completely remove APM and all configuration object related to it, then follow these steps:

  1. Remove the access policy/profile as well as any APM configuration objects from the virtual server. Else, you will get an error message.
  2. Delete the access policies/profiles.
  3. Delete custom profiles you have created in connection to APM.


Note: Additionally, you can remove the EPSEC package, this will stop the UCS files from becoming excessively large.

If you have an HA-pair, you can push the changes to the second device, and save the changes.

Deprovision APM:
You will have to do this (Remove APM from provisioning) on both devices in order to sync again.
In order to remove the APM module from the system, go to the GUI and in the 'System  ››  Resource Provisioning' section, find the 'Access Policy (APM)' and change the Provisioning to None.

Important: This will cause a reload of the configuration and the device will become unavailable for some time, so you might want to do this on the standby first and then do a failover and repeat the process.
