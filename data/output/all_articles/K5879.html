Known Issue

This is the result of a known issue. This issue will most often occur if the /etc/syslog-ng/syslog-ng.conf file contains errors that result in the syslog-ng utility failing to start.

In BIG-IP 9.1.1, 9.1.2, 9.2, and 9.2.2, the following daemons have dependencies in place that require the syslog-ng utility to be running:

VersionDaemons that require syslog-ng
9.1.1bcm56xxd
9.1.2tmm
9.2tmm
bcm56xxd
9.2.2tmm
gtmd
bcm56xxd

If the syslog-ng utility fails to start, the system daemons will not start. Under these circumstances, the BIG-IP system will not pass traffic, and the non-management interfaces and self IP addresses will be non-responsive.

Additionally, when the syslog-ng utility is not running, no log messages will be logged.

F5 Product Development tracked this issue for the BIG-IP 9.2 branch as CR58625 and it was fixed in BIG-IP 9.2.3.

For the BIG-IP 9.1 branch, F5 Product Development tracked the syslog-ng dependency for bcm56xxd issue as CR58627, and it was fixed in BIG-IP 9.1.2.

F5 Product Development tracked the syslog-ng dependency for the tmm daemon issue as CR65653 and it was fixed in version 9.4. For information about upgrading, refer to the LTM, GTM, ASM, or Link Controller Release Notes.

For additional information about this issue, refer to the following solutions:

K5872: BIG-IP does not pass traffic and non-management interfaces are non-responsive after upgrading BIG-IP to versions 9.1.1 or 9.2.2.

K6466: After upgrading BIG-IP to versions 9.1.2 or 9.2.2 the BIG-IP command line prompt indicates INOPERATIVE.

Workaround

Warning: This procedure must be performed from the command line, through the console (accessed through the serial terminal), or using SSH connected through the management interface.

If upgrading is not an immediate option, it is possible to work around this issue by performing the following steps:

  1. Log in to the BIG-IP command line.
  2. Determine why the syslog-ng utility will not start, and correct the issue.

    Note: There are many reasons why the syslog-ng utility may fail or may not start.

  3. Reboot the BIG-IP system by typing the following command:

    reboot
