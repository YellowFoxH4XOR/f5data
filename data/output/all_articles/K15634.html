Known Issue

BIG-IP may truncate large responses returning from an Internet Content Adaption Protocol (ICAP) server.

This issue occurs when all of the following conditions are met:

  • An ICAP profile and either a Request Adapt or Response Adapt profile are assigned to a virtual server
  • An engineering hotfix for ID 429994 has been installed

If you installed an engineering hotfix to address ID 429994, as discussed in K15607: Data returning from an ICAP server may be truncated or cause the session to stop responding, you may experience a related issue in which after a client sends a request to the BIG-IP system, that request is diverted to the ICAP server. The ICAP server responds and the BIG-IP system begins sending the request to the pool member. The TCP window may open or close a few times (normal flow-control behavior). At some point, the BIG-IP system then sets the TCP receive window for the ICAP response to zero, and no more data is accepted from the ICAP server.

Impact

Large files returning from an ICAP server may be truncated.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Responses to large requests appear to stop responding.
