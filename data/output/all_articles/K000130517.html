Description

LDAP remote authentication to BIG-IP fails. LDAP remote users fail to authenticate either via SSH or GUI. Only default admin user works.

There seem to be no helpful logs on /var/log/secure, but when trying to authenticate via SSH you may see similar logs in /var/log/kern.log:

<date> <hostname> info kernel: sshd[19333]: segfault at 0 ip 00007f6b1aa83f3e sp 00007ffde0823b00 error 4 in pam_ldap.so[7f6b1aa81000+7000]

<date> <hostname> info kernel: sshd[22260]: segfault at 0 ip 00007f773be7ef3e sp 00007ffc33e162b0 error 4 in pam_ldap.so[7f773be7c000+7000]

<date> <hostname> info kernel: pam-authenticat[22446]: segfault at 0 ip 00000000f7752cc3 sp 00000000ffda14d0 error 4 in pam_ldap.so[f7750000+8000]

<date> <hostname> info kernel: pam-authenticat[22468]: segfault at 0 ip 00000000f76d5cc3 sp 00000000ff9f7990 error 4 in pam_ldap.so[f76d3000+8000]

 

Environment

• BIG-IP version 14.1.x or 15.1.x

• LDAP remote authentication

• LDAP server is reachable from BIG-IP

• LDAP attribute returned with empty value

 

Cause

Bug ID 950153: LDAP remote authentication fails when empty attribute is returned

 

Recommended Actions

1. Verify if there is an attribute returned with an empty or null value.

Use the following command from bash, replacing the values between <>

ldapsearch -x -LLL -H 'ldaps://<LDAP server IP address>' -b "<search base DN>" -D "<bind DN>" '(uid=<username>)' -W

 

For example:

ldapsearch -x -LLL -H 'ldaps://10.1.6.36' -b "ou=people,dc=domain,dc=com" -D "uid=org,ou=bigipadmins,dc=domain,dc=com" '(uid=myuser)' -W

 

2. On LDAP, set any dummy value on the affected empty attribute to prevent the issue.
