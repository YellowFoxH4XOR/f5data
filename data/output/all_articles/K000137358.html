K000137358: System controller not using configured internal dns

Type
Support Solution
Published
2023-10-25
Updated
2023-10-26
Applies to
  • F5OS
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000137358

Description

When query DNS from Controller Linux shell, it appear that Controller is querying to internal IP address and port.
 

Openshift uses dnsmasq which is running on internal address and port 53. Dnsmasq forwards any requests it can’t resolve by itself to DNS servers listed in /etc/origin/node/resolv.conf.
 

The configured DNS servers which are updated via confd, the entry will be added to /etc/origin/node/resolv.conf file.

 

Environment

F5OS-C

 

Cause

None.

 

Recommended Actions

None.

 

Additional Information

Though it appears in the below query the DNS SERVER address 100.65.3.51 is F5OS internal address, the dnsmasq is acting as a forwarder.

syscon-1-active# show system dns
