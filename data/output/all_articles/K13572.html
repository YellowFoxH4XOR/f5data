Known Issue

When a BIG-IP system is upgraded to version 11.0.0 or 11.1.0, the configuration may fail to load because of its previous high availability (HA) configuration.

This issue occurs when all of the following conditions are met:

  • The system was previously configured to be an HA pair with a unit ID of 2.
  • The system was removed from the HA pair prior to upgrading to BIG-IP version 11.0.0 or 11.1.0.

Impact

After the upgrade, the system fails to load its configuration.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H383432 on the Diagnostics > Identified > Medium screen.
  • The system displays a command prompt of Active and a hostname of localhost.
  • The system has no configuration loaded.
  • The BIG-IP db key Failover.IsRedundant and its value are reported as false. You can review the db key with the tmsh command. For example:

    tmsh list sys db failover.isredundant

  • The BIG-IP db key Failover.UnitID and its value are reported as 2. You can review this db key with the tmsh command. For example:

    tmsh list sys db failover.unitid

Workaround

If you have already upgraded, you can work around this issue. Alternatively, you can prevent the issue from occurring before upgrading.

Impact of workaround: None

To work around the issue if you have already upgraded

You can manually edit the BIG-IP configuration files to remove a section of the configuration that contains the mismatched failover unit ID. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Use a text editor to modify the /config/bigip_sys.conf file, and remove the entire section for failover that appears similar to the following example:  

    failover {
      redundant disable
       standby link down time 0
     }

  3. Use the text editor to modify the /config/bigip_base.conf file, and remove the entire section for failover that appears similar to the following example:  

    failover {
       unit 2
      }

  4. Load the configuration by using the following tmsh following command:

    tmsh load sys config

To prevent the issue from occurring before upgrading

Before upgrading the system, you can modify the failover unit ID to match its standalone configuration. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Modify the failover unit ID using the following tmsh command:

    tmsh modify sys failover unit 1

  3. Save the modified configuration into the UCS file using the following tmsh command:

    tmsh save sys config

    You may now proceed to upgrade the system.
