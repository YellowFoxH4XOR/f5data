Description

Aspen Mesh could have different types of installation depending on your infrastructure. All types are installed via Helm, Aspen Mesh does not support any other tool for installation.

Aspen Mesh release package (tarball) consists of various charts (and sub-charts) which can be individually installed or customized as per your requirements.
In 1.11.x releases few charts has been deprecated and removed from the install tarball.
Beginning Aspen Mesh 1.14 release the structure of charts has been modified and the istio-control chart contains only istiod component. Other components are consolidated into addons"subchart. This article applies only to 1.6.x, 1.9.x and 1.11.x releases.
Here’s a quick layout of the various charts packaged as part of an Aspen Mesh release:

Environment

  • Kuberntes: 1.17x - 1.123.x
  • Aspen Mesh: 1.6.x, 1.9.x, 1.11.x

Cause

You can customize Aspen Mesh installation footprint (CPU & memory resources) by enabling or disabling various Helm charts as described above which in turn turns on or off certain features. Additionally, within every Helm chart, you can tune the resources consumed by individual pods by supplying the resource constraints via an overrides file. In this document we will show various examples of customizing the Aspen Mesh installation, for install guidance please refer to Aspen Mesh installation docs.

Recommended Actions

  1. Aspen Mesh with all options (components) enabled
  2. Minimal Aspen Mesh with Ingress Gateway and Istio in High Availability
  3. Minimal Aspen Mesh with no High Availability

Aspen Mesh with all options (components) enabled

To install Aspen Mesh with all components, you need to create your own override file, here is an example:

aspen-mesh-controlplane:
  # The name of the cluster where Aspen Mesh is being installed.
  clusterId: am-latest
  userAuth:
    # type can be set to `jwt` or `none`. JWT authentication is highly recommended.
    type: none
jaeger:
  enabled: true
citadel:
  enabled: true

Resources Requested

  • CPU – 15 cores
  • Memory – 30 Gi

Note: Please reach Aspen Mesh Support before enabling all options.

Minimal Aspen Mesh with Ingress gateway and Istio in High Availability

The following Helm overrides file installs a minimal Aspen Mesh version with the Istio control plane (istiod) and Istio ingress gateway in High Availability (at least 2 replicas):
Note: Ingress gateways are always optional, for information about installing ingress gateway, refer to K50557252: Install Istio Ingress Gateway using the Aspen Mesh Ingress Helm Chart.

aspen-mesh-controlplane:
  # The name of the cluster where Aspen Mesh is being installed.
  clusterId: am-latest
  userAuth:
    # type can be set to `jwt` or `none`. JWT authentication is highly recommended.
    type: none

jaeger:
  enabled: false

aspen-mesh-dashboard:
  enabled: false

aspen-mesh-secure-ingress:
  enabled: false

traffic-claim-enforcer:
  enabled: false

aspen-mesh-metrics-collector:
  enabled: false

aspen-mesh-event-storage:
  enabled: false

cert-manager:
  enabled: false

external-dns:
  enabled: false

citadel:
  enabled: false

pilot:
  resources:
    requests:
      cpu: 500m
      memory: 2048Mi

global:
  proxy:
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 2000m
        memory: 1024Mi

gateways:
  istio-ingressgateway:
    name: istio-eastwestgateway
    labels:
      app: istio-eastwestgateway
      istio: eastwestgateway
      topology.istio.io/network: network2
    ports:
    - port: 15021
      targetPort: 15021
      name: status-port
      protocol: TCP
    - port: 80
      targetPort: 8080
      name: http2
      protocol: TCP
    - port: 443
      targetPort: 8443
      name: https
      protocol: TCP
    - port: 15012
      targetPort: 15012
      name: tcp-istiod
      protocol: TCP
    - port: 15443
      targetPort: 15443
      name: tls
      protocol: TCP
    - name: tls-webhook
      port: 15017
      targetPort: 15017
    env:
      ISTIO_META_ROUTER_MODE: "sni-dnat"
      ISTIO_META_REQUESTED_NETWORK_VIEW: "network2"
    serviceAnnotations:
      service.beta.kubernetes.io/aws-load-balancer-type: nlb

 

With this overrides file, all custom Aspen Mesh addons are disabled to ensure minimal components required for North/South (Ingress) and East/West (intra-cluster) traffic routing and policies. In this mode, no observability is available as Aspen Mesh metrics collector, dashboard or Jaeger are not installed.

  • Memory – 5 Gi

Minimal Aspen Mesh with no High Availability

Use this Helm overrides values file to install the Aspen Mesh control plane with minimal resource consumption. In this installation, you shouldn’t install the ingress-gateway chart but only install the base and istio-discovery chart with the values file outlined below:

aspen-mesh-controlplane:
  # The name of the cluster where Aspen Mesh is being installed.
  clusterId: am-latest
  userAuth:
    # type can be set to `jwt` or `none`. JWT authentication is highly recommended.
    type: none

jaeger:
  enabled: false

aspen-mesh-dashboard:
  enabled: false

aspen-mesh-secure-ingress:
  enabled: false

traffic-claim-enforcer:
  enabled: false

aspen-mesh-metrics-collector:
  enabled: false

aspen-mesh-event-storage:
  enabled: false

cert-manager:
  enabled: false

external-dns:
  enabled: false

citadel:
  enabled: false

pilot:
  autoscaleMin: 1
  autoscaleMax: 2
  replicaCount: 1
  resources:
    requests:
      cpu: 500m
      memory: 2048Mi

global:
  proxy:
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 2000m
        memory: 1024Mi

 

Resources Requested

  • CPU – 1 core
  • Memory – 2 Gi

Output:

kubectl get pods -n istio-system
NAME                                                  READY   STATUS    RESTARTS   AGE
istiod-6fb96c787b-4nwv7                               1/1     Running   0          18d

 

You can install any variation of these charts/sub-charts depending on your use case and the resources be consumed accordingly.
