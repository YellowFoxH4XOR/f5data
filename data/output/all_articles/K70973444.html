Known Issue

The hostagentd process may leak memory over time on virtual Clustered Multiprocessing (vCMP) hosts.

This issue occurs when the following condition is met:

  • The vCMP host uptime is two months or more.

Note: The hostagentd process runs on a vCMP host for the purpose of receiving information, such as system version, provisioning, high availability, and TMM-related information from the vCMP guest.

Impact

The vCMP host may run out of memory and cause system instability.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A vCMP host shows signs of general instability. For example, your health monitors may work intermittently.
  • The hostagentd process consumes more than 400 MB of resident memory, and continues to grow over time. You can use the following command to view the resident memory (RSS) usage for the hostagentd process:

    ps aux | grep -E '/usr/bin/hostagentd|USER'
    USER       PID  %CPU  %MEM    VSZ   RSS TTY      STAT    START   TIME        COMMAND
    root     23456   0.0   5.8    1.5G  910.4M ?        S    Jan01   00:18:44.71 /usr/bin/hostagentd

Workaround

To work around this issue, you can restart the hostagentd process on the vCMP host. To do so, perform the following procedure:

Impact of workaround: This procedure impacts vCMP statistics received from the vCMP guest

  1. Log in to the command line of the vCMP host. If the device is a VIPRION, ensure you are logged in to the primary blade.
  2. To restart the hostagentd process, type one of the following commands:

    For a standard BIG-IP appliance:

    bigstart restart hostagentd

    For a VIPRION system:

    clsh bigstart restart hostagentd
