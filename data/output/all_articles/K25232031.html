K25232031: BIG-IP ASM includes HTTP security headers for Response and Blocking pages

Type
Knowledge
Published
2020-06-17
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.1.X, 16.0.X, 16.1.3, 16.1.2, 16.X.X, 16.1.0, 16.0.1, 16.0.0, 16.1.1
Source
https://my.f5.com/manage/s/article/K25232031

Issue

Old Behavior

In versions prior to BIG-IP ASM 16.0.0, the system does not include HTTP security headers for response or blocking pages generated by the security policy.

New Behavior

Beginning in BIG-IP ASM 16.0.0, the asm.http_security_headers db variable is enabled by default. The system includes the HTTP security headers for responses generated by the security policy, as shown in the following table.

HTTP security headerDescription
X-Frame-Options = SAMEORIGINProvides protection against clickjacking vulnerabilities. The SAMEORIGIN option only permits the browser to frame content for the current site.
X-XSS-Protection = 1; mode=blockEnables the XSS filter on the browser. The 1; mode=block option enables XSS filtering. Rather than sanitizing the page, the browser prevents rendering of the page if an attack is detected.
X-Content-Type-Options = nosniffProtects against MIME types security risks. This header instructs the browser to consider file types as defined and disallows content sniffing. The value for the X-Content-Type-Options header is nosniff.

For example, when the security policy returns a response or blocking page, such as the default blocking page or CAPTCHA page, the HTTP response appears similar to the following example:

HTTP/1.1 200 OK
X-Frame-Options: SAMEORIGIN
X-XSS-Protection: 1; mode=block
X-Content-Type-Options: nosniff
Cache-Control: no-cache
Connection: close
Content-Type: text/html; charset=utf-8
Pragma: no-cache
Content-Length: 246

Impact

Increased security for response and blocking pages returned by the policy.

Recommended Actions

F5 recommends leaving the HTTP security headers enabled for security reasons. However, you can modify the asm.http_security_headers database variable by performing the following procedure:

Modifying the asm.http_security_headers database variable

To change whether the BIG-IP ASM system returns HTTP security headers with response and blocking pages, perform the following steps:

  1. Log in to the TMOS shell (tmsh) by entering the following command:

    tmsh

  2. To modify the modify the asm.http_security_headers database variable, use the following command syntax:

    modify /sys db asm.http_security_headers value <enable/disable>

    For example to disable the asm.http_security_headers database variable and prevent the system from returning HTTP security headers, enter the following command:

    modify /sys db asm.http_security_headers value disable

Note: This does not apply to application responses.
