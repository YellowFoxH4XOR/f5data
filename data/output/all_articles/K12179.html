Issue

Note: Microsoft introduced the sql_variant data type in SQL Server 2000. The sql_variant data type can be used to store data of an unspecified or inconsistent type.

BIG-IP 9.0.0 through 10.0.1

In BIG-IP versions prior to 10.1.0, you must download and install the Microsoft SQL Server 2000 JDBC Driver on the BIG-IP system before you can start using the MSSQL monitor. Because this version of the driver supports the sql_variant data type, you can configure the MSSQL monitor with a query statement that retrieves a value of the sql_variant data type from the SQL server.

Note: For more information about using the MSSQL monitor, refer to the Configuration Guide for BIG-IP Local Traffic Management.

BIG-IP 10.1.0 and later

Beginning in BIG-IP 10.1.0, you are no longer required to download a JDBC driver and install it on the BIG-IP system before you can start using the MSSQL monitor. By default, the system already includes the Microsoft SQL Server 2005 JDBC Driver.

Because Microsoft has removed support for the sql_variant data type in version 2005 of their JDBC driver, and because you cannot install a different version of the JDBC driver on the BIG-IP system, the MSSQL monitor can no longer be used to retrieve values of the sql_variant data type.

If the MSSQL monitor is configured to retrieve data from a table that contains a column of the sql_variant data type, an exception will occur and the pool member will be marked as unavailable. When this happens and debugging is enabled for the monitor, messages that appear similar to the following example are logged to the /var/log/DBDaemon.log file:

jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): Thread-50 will query.
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): Attempting DB connection.
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): DB connect succeeded.
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): Send Query (The "variant" data type is not supported.)
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): Ping time 14ms.
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): DB server down.
jdbc:sqlserver://10.0.0.200:1433;databaseName=;(Thread-50): Work completed. Exiting.

Note: For more information on which data types are supported by the Microsoft SQL Server 2005 JDBC Driver, refer to this Microsoft TechNet article: http://technet.microsoft.com/en-us/library/ms378878(SQL.90).aspx.

You may be able to work around this limitation by configuring a query statement that tells the Microsoft SQL server to convert the value to a different data type (one that is supported by the JDBC driver). To do so, perform the following procedure:

  1. Log in to the BIG-IP system Configuration utility.
  2. Navigate to Local Traffic > Monitors.
  3. Click on the MSSQL monitor that you want to edit.
  4. Your existing send string should appear similar to the following example:

    SELECT <STATEMENT>

    Replace your existing send string with the following string:

    SELECT CONVERT(<SUPPORTED DATA TYPE>, <STATEMENT>)

    The following is an example of an original send string:

    SELECT DATABASEPROPERTYEX('Master', 'Status')

    You would replace the example original send string with the following:

    SELECT CONVERT(VARCHAR, DATABASEPROPERTYEX('Master', 'Status'))
  5. Click Update.

The Microsoft SQL server should now return the value as a varchar data type, which the JDBC driver understands.
