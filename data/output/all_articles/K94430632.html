Topic

Clone pool members referenced on a Virtual Clustered Multiprocessing (vCMP) guest require valid MAC address entries in the BIG-IP Layer 2 (L2) forwarding database (FDB).

Description

When you use the clone pool feature on a vCMP guest, make sure that each clone pool member has a valid MAC address entry in the L2 FDB. Doing so ensures that the system will forward the clone pool traffic out of the desired external interface to the destined clone pool member. If the clone pool member does not have a valid entry in the BIG-IP FDB, the vCMP guest forwards the clone traffic to the vCMP host as well as all vCMP guests associated with the same VLAN as the destined clone pool member. When this occurs, the Traffic Management Microkernel (TMM) instances across these affected hosts and guests will use more resources, and discard traffic that they are not supposed to be receiving. As a result, CPU utilization may increase on the affected TMM instances and affect the performance of traffic processing.

Note: This behavior applies to all platforms provisioned for vCMP regardless of the number of HSBs present. For platforms that are not provisioned for vCMP, the behavior applies when there are two HSBs present. For more information, refer to K17567: Clone pool members require L2 FDB entries.

Recommendation

When you configure clone pools for vCMP guests, you should confirm that each node in the clone pool has valid ARP and FDB entries. If the nodes do not have ARP and FDB entries, add static entries for the nodes in your clone pool. Because the vCMP guest does not allow you to add FDB entries, you must add these entries on the vCMP host. To do so, perform the following procedure on the vCMP host:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) on the vCMP host by typing the following command:

    tmsh

  2. To verify whether the clone pool member has a valid Address Resolution Protocol (ARP) entry on the vCMP host, type the following command:

    show /net arp

  3. If the ARP entry is missing for the clone pool members, you can add a static ARP entry for each member on the vCMP host by using the following syntax:

    create /net arp <node-ip> mac-address <mac-addr>

    For example, the following command creates a static ARP entry mapping for IP address 192.168.1.1 and MAC address 00:0b:09:88:00:9a:

    create /net arp 192.168.1.1 mac-address 00:0b:09:88:00:9a

  4. To verify whether the clone pool member has a valid FDB entry on the vCMP host, use the following syntax:

    show /net fdb vlan <vlan-name>

    For example, to verify whether the clone pool member has valid FDB entry for the VLAN named internal, type the following command:

    show /net fdb vlan internal

  5. If the FDB entry is missing for the clone pool members, you can add a static FDB entry on the vCMP host for each MAC address in the clone pool by using the following syntax:

    modify /net fdb vlan <vlan-name> records add { <mac-addr> { interface <int-number> }}

    For example, the following command adds a static FDB entry for MAC address 00:0b:09:88:00:9a and VLAN internal:

    modify /net fdb vlan internal records add { 00:0b:09:88:00:9a { interface 1/1.1 } }

  6. To save the configuration, type the following command:

    save /sys config
