K10895: The Vary header may cause caching issues with Internet Explorer

Topic

The BIG-IP WebAccelerator system sends the Vary: Accept-Encoding header in responses when compression is enabled for the requested content. Internet Explorer does not cache content containing the Vary: Accept-Encoding header; it instead sends a conditional GET request the next time the client calls for the same document. As a result, Internet Explorer will experience some performance degradation when requesting cacheable content from the OWS.

According to Microsoft Knowledge Base article 82484, "Internet Explorer does not fully implement the Vary header per Requests for Comments (RFC) 2616. The Internet Explorer implementation of VARY is that it does not cache any data except for Vary: User-Agent."

F5 Networks Product Development is tracking a request for enhancement (RFE) to add a configuration parameter that would strip the Vary header if required as ID 222960 (formerly CR126172).

Workaround

To work around this issue, use one of the following two procedures depending on the version of WebAccelerator you are running:

Version 9.x

For version 9.x systems, you can remove the Vary header by applying the following iRule to the virtual server:

when HTTP_RESPONSE {
   if { [HTTP::header exists "Vary"] } {
      HTTP::header remove "Vary"
   }
}

Version 10.x

For version 10.x systems, you can remove the Vary header by defining a standard virtual server with an iRule that targets the WebAccelerator virtual server.

Note: For more information, refer to K11231: Using an iRule to manipulate egress traffic for BIG-IP WebAccelerator.
