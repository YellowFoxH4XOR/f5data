K000151524: Configuration of http/2 profile with enforce-tls-requirements enabled and SSL profile with renegotiation enabled is sometimes allowed

Type
Support Solution
Published
2025-05-26
Updated
2025-05-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.0.0, 16.1.2, 16.1.1, 16.1.0, 16.0.X, 16.0.1, 17.X.X, 16.X.X, 17.5.X, 17.5.0, 17.1.X, 17.0.X, 17.0.0, 16.1.X, 16.1.6, 16.1.5, 16.1.4, 16.1.3, 17.1.2, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000151524

Description

When trying to attach multiple SSL profiles to a virtual server, the system is asking to enable sni-default setting to at least one of the profiles. After that, if you try to enable renegotiation in SSL profile and attach to the virtual server, the system is adding it without any errors.

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm virtual testVS
ltm virtual testVS {
  creation-time 2025-05-19:23:29:39
  destination 10.97.41.35:https
  ip-protocol tcp
  last-modified-time 2025-05-19:23:29:39
  mask 255.255.255.255
  profiles {
    http { }
    http2 { }
    tcp { }
    testssl1 {
      context clientside
    }
  }
  serverssl-use-sni disabled
  source 0.0.0.0/0
  translate-address enabled
  translate-port enabled
  vs-index 2
} 

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm profile client-ssl testssl1 renegotiation sni-default
ltm profile client-ssl testssl1 {
  renegotiation disabled
  sni-default false
}

If you try to add another SSL profile with sni-default set to 'true' and renegotiation enabled, it is added without any error.

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm profile client-ssl testssl2
ltm profile client-ssl testssl2 {
  app-service none
  cert-key-chain {
    default {
      cert default.crt
      key default.key
    }
  }
  inherit-ca-certkeychain true
  inherit-certkeychain true
  renegotiation enabled
  server-name test
  sni-default true
}
root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# modify ltm virtual testVS profiles add { testssl2 }
root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)#


If you try to add a third SSL profile with sni-default set to 'false' and renegotiation enabled, the system is throwing configuration error.

root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm profile client-ssl testssl3
ltm profile client-ssl testssl3 {
  app-service none
  cert-key-chain {
    default {
      cert default.crt
      key default.key
    }
  }
  inherit-ca-certkeychain true
  inherit-certkeychain true
  renegotiation enabled
  server-name test3
  sni-default false
}
root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# modify ltm virtual testVS profiles add { testssl3 }
01070734:3: Configuration error: In Virtual Server (/Common/testVS) an http2 profile with enforce-tls-requirements enabled is incompatible with client ssl profile '/Common/testssl3'; renegotiation must be disabled
root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)#

Environment

  • BIG-IP LTM
  • HTTP/2 profile with enforce-tls-requirements enabled
  • SSL profile/s with sni-default setting set to 'true' and renegotiation enabled
  • SSL profile/s with sni-default setting set to 'false' and renegotiation enabled

Cause

The problem seems to be related to sni-default setting in SSL profile and is tracked under ID1958033.

Recommended Actions

Correct the configuration as the error message says - either disable enforce-tls-requirements setting in HTTP/2 profile or disable renegotiation in SSL profile/s.

Additional Information

None.
