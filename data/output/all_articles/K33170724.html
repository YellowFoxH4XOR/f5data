Description

You can see the /var/log directory used disk space growing in time, showing a small percentage of available disk space.

When (following K14403) to check for deleted files still using disk space, with open file handles, you can see an output similar to the following example, indicating bigd has the larger amount of entries:

Environment

  • Bigd daemon
  • Monitor logging enabled
  • Disk space

Cause

Bug ID 693582: Monitor node log not rotated for certain monitor types

Recommended Actions

Restarting bigd (tmsh restart /sys service bigd) will resolve temporarily, but the issue can repeat over time.

For a permanent solution, disable monitor logging from nodes and pool members as explained on the "Workaround" section of: K61902543: The BIG-IP system may leak file descriptors when monitor logging is enabled.

Additional Information

BUG ID below can also be related to similar symptoms:

Bug ID 662816: Monitor node log fd leak for certain monitor types
