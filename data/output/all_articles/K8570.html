K8570: Crystal Reports responses compressed by the BIG-IP WebAccelerator cannot be interpreted by ActiveX

Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator compresses Crystal Reports responses when the response contains certain content types. However, the Crystal Reports ActiveX Viewer cannot interpret compressed responses.

The BIG-IP WebAccelerator will compress a Crystal Reports response when it contains one of the following content types:

  • application/x-epf
  • application/x-etf
  • application/x-rpt
  • application/x-emf

F5 Networks Product Development tracked this issue as CR93932 and it was fixed in BIG-IP WebAccelerator version 9.4.5. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Workaround

To prevent the BIG-IP WebAccelerator from compressing certain content types, you can add the content types to the globalfragment.xml file. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /config/wa directory, by typing the following command:

    cd /config/wa
  3. Back up the original globalfragment.xml file by typing the following command:

    cp globalfragment.xml globalfragment.xml.sol8570
  4. Open the globalfragment.xml file in a text editor.
  5. Add the following objType entry to the end of the objTypes section:

    <objType
                    type="compression-exceptions"
                    group="documents"
                    category="common"
                    displayName="Compression Exceptions"
                    ext=""
                    mimeType="
                        application/x-epf
                        application/x-etf
                        application/x-rpt
                        application/x-emf"
                    compressToClient="none"
    />
     
  6. Save the globalfragment.xml file.
  7. Restart the pvac daemon by typing the following command:

    Important: Restarting the pvac daemon will briefly disrupt connections and invalidate objects in the BIG-IP LTM RAM Cache. Restarting the pvac daemon should be scheduled accordingly.  

    bigstart restart pvac
