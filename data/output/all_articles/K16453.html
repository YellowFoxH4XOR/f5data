Known Issue

Egress Virtual eXtended LAN (VXLAN) traffic, on VIPRION or 5000-series platforms, has a bad checksum in its outer User Datagram Protocol (UDP) header.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION or 5000-series BIG-IP platform.
  • You have configured your BIG-IP system to tunnel Ethernet frames using the VXLAN protocol.
  • Your BIG-IP system is processing IP v4 UDP traffic with destination port 8472 (VIPRION) or 4789 (5000-series).

Impact

Egress VXLAN traffic is dropped, due to a bad checksum in the UDP header.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • IPv4 connections that use UDP destination port 8472 (Viprion) or 4789 (5000-series) are failing.

Workaround

To work around this issue, you can set the iptunnel.vxlan.udpport database variable to 0. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the iptunnel.vxlan.udpport database variable to 0, type the following command:

    modify sys db iptunnel.vxlan.udpport value 0
