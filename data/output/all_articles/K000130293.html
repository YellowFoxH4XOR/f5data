Description

When accessing a web application protected by F5 BIG-IP APM, users may experience session loss or authentication failure when switching to another website loaded within an iframe. The issue is characterized by the APM session not being shared between the main portal and the application loaded in the iframe, resulting in a session state mismatch.

Environment

  • The BIG-IP APM system is configured with a portal access profile.
  • Application using iframe
  • Session management using MRHSession cookie

Cause

Browsers may block cookies (such as the MRHSession cookie used by APM) from being sent in cross-site iframe requests due to security policies, especially if the cookie does not have the appropriate SameSite attribute. Additionally, setting the "X-Frame-Options" header can prevent applications from loading within an iframe, further contributing to session loss or authentication issues.

Recommended Actions

Disable APM iRule Event Restrictions and Remove X-Frame-Options Header with an iRule:

when CLIENT_ACCEPTED {
ACCESS::restrict_irule_events disable
 }
 when HTTP_RESPONSE_RELEASE {
HTTP::header remove X-Frame-Options
 }
