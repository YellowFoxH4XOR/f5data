Known Issue

The ARX DNAS Filer-Generated Name (FGN) code may not recognize 8.3 FGN file/directory names using multibyte characters.

This issue occurs when all of the following conditions are met:

  • The filer uses a multibyte character set, such as Japanese or Chinese, for FGN alternate filenames.
  • The ARX system migrates a filename that contains multibyte characters that result in the length of the filename being greater than 8 bytes in length, or the length of the extension after a period character ( . ) exceeding 3 bytes.

When identifying whether a file or directory name is an 8.3 FGN, the ARX system acts as if each character is 1-byte long. However, some filers, such as NetApp, may use multibyte characters that are greater than 1-byte long when creating 8.3 names. The ARX system may misidentify such files as having more than 8 characters before the period, or more than 3 characters after the period.

Impact

The metadata has inconsistencies and the system will  potentially delete a file on the target share to which the system is migrating files.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The ARX system may not detect a name collision when migrating a file, and incorrectly delete a file on the target share.

    For example, when migrating a source file with a primary name of  ???~1.ppt, if the target share has a file with a primary name of ???XYZ.ppt, with an alternate 8.3 FGN name of  ???~1.ppt, the ARX system does not detect that the migration failure is due to an 8.3 alternate name collision and deletes the file on the target share as part of its cleanup logic. This behavior results in metadata inconsistency (the ARX system still has the ???XYZ.ppt name in the metadata) and loss of the file on the target share.

Workaround

To recover from this issue, you must restore any overwritten files and repair the metadata inconsistencies. To repair the metadata inconsistencies, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX command line.
  2. Enable privileged mode by typing the following command:

    enable

  3. Repair the metadata inconsistencies with the sync files command using the following command syntax:

    sync files namespace volume volume path path [share share-name] [recurse] [rename-files]
