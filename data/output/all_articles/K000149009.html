K000149009: wideip returning SOA when return code on failure is enable

Type
Support Solution
Published
2024-12-17
Updated
2025-08-07
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.X, 17.5.1, 17.5.0, 16.1.5, 17.1.1, 17.1.2
Source
https://my.f5.com/manage/s/article/K000149009

Description

SOA is found in response for wideip when return code on failure is trigger.

 

dig AAAA @192.168.10.1 personal.example.com

; <<>> DiG 9.16.33 <<>> AAAA @192.168.10.1 personal.example.com

; (1 server found)

;; global options: +cmd

;; Got answer:

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 4836

;; flags: qr aa rd ad; QUERY: 1, ANSWER: 0, AUTHORITY: 1, ADDITIONAL: 1

;; WARNING: recursion requested but not available

 

;; OPT PSEUDOSECTION:

; EDNS: version: 0, flags:; udp: 4096

;; QUESTION SECTION:

;personal.vanguard.com.        IN     AAAA

 

;; AUTHORITY SECTION:

example.com.          0      IN     SOA    hostmaster.example.com. ns.example.com. 1 10800 3600 604800 0

 

;; Query time: 5 msec

;; SERVER: 10.69.156.34#53(10.69.156.34)

;; WHEN: Fri Nov 08 18:27:40 EST 2024

;; MSG SIZE rcvd: 100

Environment

  • wideip (return code on failure is enable)
  • SOA Negative caching TTL is set to any value
  • All pools for wideip are down
  • Running Version 17.1.1 or above
  • or Version 16.1.5 or above

Cause

With Bug ID 1311169 fixed, the correct behavior for wideip (authoritative zone) is to include SOA for DNS failure reply.

 

Recommended Actions

Depends on the environment. See Additional Information.

Additional Information

  • When bugid 1311169 is not fixed, if SOA Negative caching TTL is set to "0", SOA will be removed from the DNS failure response(wideip).
  • When bugid 1311169 is fixed, SOA will always be returned by wideip regardless of TTL value.
  • Authoritative DNS server must respond with SOA.
  • An Irule is required if the environment requires a failure DNS response without SOA for any failure response(wideip).
  • Sample Irule:  (Testing required for your environment) - LTM must be provisioned to create the iRule with DNS_RESPONSE event
when DNS_RESPONSE {
 
 if { [DNS::answer] eq "" && [DNS::is_wideip [DNS::question name]] } {
 
  DNS::authority clear
 
#  log local0. "customise irule::removing authority section for dns response that does not contain answer"
 
  } else {
 
 #  log local0. "[DNS::question name] is not a wideIP"
 
  }
}
