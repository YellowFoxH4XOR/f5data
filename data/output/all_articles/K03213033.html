K03213033: Kubernetes RBAC permissions error: peerauthentications.security.istio.io is forbidden

Description

When installing an application through helm, the following error may happen similar to the following example:

$ helm install my-application manifests/charts/application --namespace test-namespace
Error: peerauthentications.security.istio.io is forbidden:
User "dummy-test123" cannot create resource "peerauthentications" in API group "security.istio.io" in the namespace "test-namespace"

Environment

  • Kubernetes: 1.16x - 1.22.x

Cause

The user dummy-test123, as shown in the above example output, is not bound to a ClusterRole with enough permissions.

Recommended Actions

Role-based access control (RBAC) is a method for controlling access to computer or network resources based on the roles of individual users .

RBAC is implemented through different resources: Role, ClusterRole, RoleBinding and ClusterRoleBinding. For more information about these different resources, refer to the Kubernetes Documentation - Using RBAC Authorization.

To validate if a user has the right permissions to perform a task, use the command below:

~/ > kubectl auth can-i create peerauthentication --namespace test-namespace --as dummy-test123 

no

This output indicates dummy-test123 does not have the right permissions to list destinationrules in the specified namespace.

Below is an example of what the cluster role should include to have permissions to create peerauthentications:

---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:  
  name: istio-role
rules:
- apiGroups: ["config.istio.io", "networking.istio.io", "rbac.istio.io", "authentication.istio.io", "security.istio.io"]
  resources: ["peerauthentications"]
  verbs: ["get", "list", "watch", "create", "update", "patch", "delete"

Once the role is modified and bound to the user you can check again and the expected output should look like this:

~/ > kubectl auth can-i create peerauthentication --namespace test-namespace --as dummy-test123 

yes

Now confirm user dummy-test123 can perform this task, before reinstalling the application make sure you have deleted the previously failed one, otherwise this won’t allow a clean installation.
