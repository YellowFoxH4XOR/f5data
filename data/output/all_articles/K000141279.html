REST API queries may return 500 response code and MCP Session terminated message in the error stack

  • When the primary admin user is modified via \"tmsh modify sys db systemauth.primaryadminuser\" to a value other than the default \"admin\" user
  • REST queries using the \"admin\" user may fail and the \"admin\" user will not be found in the userrolepartitions file
    cat /config/bigip/auth/userrolepartitions
[root@bigip.local:Active:Standalone] auth # cat userrolepartitions
# Do not edit this file, it is created automatically
root 0 [All]
f5admin 0 [All]
f5hubblelcdadmin 0 [All]
  • The following error maybe returned for queries to the REST API
    [root@bigip.local:Active:Standalone] auth # restcurl -u admin:admin mgmt/tm/ltm/pool
{
  "code": 500,
  "message": "MCP Session terminated",
  "errorStack": [],
  "apiError": 32768003
}

Environment

  • User created BIG-IP auth user configured as primary admin user
  • REST queries initiated to an endpoint using admin user 

Cause

  • Modifying the primary admin user requires REST API queries to be initiated for the user configured as default in the sys db variable \"systemauth.primaryadminuser\"

Recommended Actions

The following REST API query succeeds for the primary admin user

  1.  First the primary admin user is verified by executing the command below:
    root@(bigip.local)(cfg-sync Standalone)(Active)(/Common)(tmos)# list sys db systemauth.primaryadminuser               
sys db systemauth.primaryadminuser {
    value "f5admin"
}
  2. Next a query is made to the REST API endpoint which returns 200 response indicating success of the query 
    [root@bigip.local:Active:Standalone] auth # curl -s -o /dev/null -w "%{http_code}\n" -ku f5admin:f5admin -H "Content-Type:
 application/json" -X GET https://localhost/mgmt/tm/ltm/virtual/
200
