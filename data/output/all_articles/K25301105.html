Topic

You should consider using this procedure under the following condition:

  • You think you are receiving an HTTP SLOWRead attack

Description

HTTP SLOWRead attacks attempt to exhaust system resources by sending multiple concurrent HTTP requests that result in a large response being served to the client. The attacking client then repeatedly closes its TCP window, forcing the target server to stop sending content while maintaining the open connection.

Before the connection times out, the client re-opens a small TCP window and accepts a little more content before closing the window again. In this way, the attacker can exhaust all of the capacity of the server with a very low bandwidth requirement.

The attacker may keep the connection alive with TCP windowprobe ACKs, allowing a very extended period of zero-window, or it may repeatedly cycle the window open and closed.

This attack is designed to cause the target server to exhaust all available resources in serving the malicious requests, leaving no resources remaining to serve legitimate HTTP requests and, therefore, denying service to legitimate consumers.

Since SLOWRead attacks do not typically have large bandwidth requirements, they may be sourced either from a single end-point or from a distributed group of computers that form part of a malicious bot-net.

This article describes a mechanism that can be considered when you need to mitigate an HTTP SLOWRead attack that has saturated either the capacity of the target webservers, or the capacity of the BIG-IP system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have BIG-IP LTM or BIG-IP ASM licensed and provisioned on your system.
  • Your ingress WAN link is not saturated. If your ingress link is saturated, blocking traffic upstream using a cloud scrubbing service such as F5 Distributed Cloud (F5 XC) is preferable to attempting to mitigate on the BIG-IP system.

Procedures

  • Determine the nature of the attack
  • Mitigate an attack using TCP profiles

    To watch a video demo of the Mitigate an attack using TCP profiles procedure, go to  Mitigate HTTP SLOWRead attacks using the Zero Window Timeout in a BIG-IP TCP profile.

Determine the nature of the attack

The first step is to try to determine the nature of the attack by inspecting the HTTP traffic and then look for any commonality between requests that can be identified or are suspected of being malicious. Depending on the configuration already in place, you can do this by using the tcpdump command (if the traffic is encrypted, you need to decrypt the traffic capture in order to see the application data), using logs from the web server, or using BIG-IP ASM request logging.

For more information on using tcpdump to capture traffic, refer the following articles:

  • K411: Overview of packet tracing with the tcpdump utility
  • K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system
  • K13637: Capturing internal TMM information with tcpdump

For more information on decrypting SSL encrypted traffic, refer the following articles:

  • K16700: Decrypting SSL traffic using the SSL::sessionsecret iRules command
  • K19310681: Decrypting SSL/TLS traffic using Wireshark and private keys

For more information on configuring BIG-IP ASM request logging, refer to the Logging Application Specific Events chapter of the BIG-IP Application Security Manager: Implementations manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Mitigate an attack using TCP profiles

Because SLOWRead attacks require the target server to keep the connection open while the client keeps the TCP window size at zero to effectively stall the connection for long periods, you can use the TCP Zero Window Timeout setting within the TCP profile to effectively mitigate these attacks. By default, this timeout is set to 20,000 milliseconds (20 seconds), which is ample to service clients on very low bandwidth links. However, in attack scenarios or if you know that most clients are on modern links, you should consider reducing this timeout until the stress on the target server or BIG-IP system is reduced to an acceptable level.

The attacker can, of course, reduce the amount of time they wait with the TCP window at zero, but doing so increases the bandwidth requirement at the attacker end. Ultimately, this renders the attack unsustainable unless the attacker has access to a distributed attack (bot-net), which can more effectively be mitigated using other mechanisms. For more information, refer to the following articles

  • K44230544: Mitigating GET floods attacks
  • K14235020: Mitigating HTTP POST floods attacks

Impact of procedure: The new TCP profile settings only impact new connections accepted after the profile is applied to the virtual server. Existing connections continue to use the settings that are in effect at the time the connection is accepted. If you need to apply the settings immediately, then you have to delete existing connections using the tmsh delete sys connection command.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Protocol > TCP.
  3. Select Create.
  4. Enter a name for your profile.
  5. For Parent Profile, select the TCP profile already assigned to the virtual server under attack.
  6. For Zero Window Timeout, select the Custom check box and enter a reduced value, such as 10000.
  7. Select Finished.
  8. Go to Local Traffic > Virtual Servers > Virtual Server List.
  9. Select the name of the virtual server under attack.
  10. For Protocol Profile (client), select the profile you created in step 3.
  11. Select Update.
