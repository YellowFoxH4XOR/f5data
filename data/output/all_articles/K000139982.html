K000139982: rSeries unit inaccessible, logs showing k3s issues: "fatal error: concurrent map iteration and map write"

Source

Description

rSeries unit was found to be inaccessible.

Later investigation of the logs revealed many k3s crashes, with logs similar to the following in /var/log/F5/system/log/platform.log:

appliance-1 k3s: fatal error: concurrent map iteration and map write
appliance-1 k3s: goroutine 1417501496 [running]:
appliance-1 k3s: runtime.throw(0x4bcd4e8, 0x26)
appliance-1 k3s: /usr/local/go/src/runtime/panic.go:1116 +0x72 fp=0xc023bbe898 sp=0xc023bbe868 pc=0x439252
<...>
appliance-1 systemd: k3s.service failed.
appliance-1 journal: Suppressed 98686 messages from /system.slice/k3s.service
appliance-1 systemd: k3s.service: main process exited, code=exited, status=255/n/a
appliance-1 systemd: Unit k3s.service entered failed state.
appliance-1 systemd: k3s.service failed.

Environment

  • r2x00/r4x00 rSeries with all vCPUs allocated to single tenant
  • k3s

Cause

System experiencing high CPU utilisation from tenant activities/processes, leading to general instability and eventual k3s crashes.

Recommended Actions

Investigate tenant graphs and logs to determine if a high CPU condition was or is still present.

Address the root cause of the high CPU condition, if found.

If no high CPU issues are found, generate qkviews from tenant(s) and appliance, then open a support case with F5 for investigation.

Additional Information

Bug ID1590173 has been filed to make k3s on rSeries more resilient to this kind of issue.
