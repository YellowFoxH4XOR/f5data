Description

This article describes the conditions and error messages you will observe when a user fails a AD or LDAP Query Assignment.

  • Edge Client or F5 Access connections fail.
  • Users fail to pass the Access Policy check(s).
  • You will observer the following error in /var/log/apm:
<big-ip_hostname> err apmd[23961]: 0149013e:3: /Common/<access_policy_name>:Common:<session_id>: Allow agent: Logon denied due to validation error, Error Code: 4001 (Zero resources assigned)
<big-ip_hostname> err apmd[23961]: 0149018d:3: /Common/<access_policy_name>:Common:<session_id>: Resource validation for webtop '/Common/<webtop_name>' failed with error type 'Zero resources assigned'

In the above log message the session_id is the unique APM Session ID.

K15387: Overview of BIG-IP APM session cookies

Environment

  • Access Policy Manager (APM)
  • Active Directory (AD) or LDAP KDC.
  • AD or LDAP Query object.
  • Resource Assignment based off AD or LDAP group membership.
  • Edge Client of F5 Access client.

Cause

  1. This error occurs when a user fails a AD or LDAP resource assignment.
  2. No Network Access Resource assigned.

Recommended Actions

Verify the user's group membership in the AD or LDAP Server:

  1. Please refer to the vendor documentation for more information on verifying the user group memberships.
Verify a Network Access resource is assigned in the Access Policy:
  1. Login to the Big-IP Admin GUI.
  2. Navigate to Access>Profiles / Policies>Access Profiles (Per-Session Policies).
  3. Click on Edit to open the VPE (Virtual Policy Editor).
  4. Select the Resource Assign.
  5. Click on Add/Delete.
  6. Select the Network Access tab.
  7. Select a Network Access resource.
  8. Click Update.
  9. Click Save.
