Description

FQDN resolution fails intermittently on BIG-IP AFM, resulting in log messages such as:

[FW] FQDN <hostname> resolv failed (retaining current IP Addresses). Next refresh 20 seconds from now.

Despite successful manual DNS lookups (e.g., using nslookup), AFM dynamic firewall rules relying on FQDNs experience resolution failures, especially when the FQDN resolves to a CNAME that points to an external domain (such as AWS ELB hostnames).

Environment

  • BIG-IP AFM
  • No root (".") forward zone configured in the DNS resolver
  • FQDNs that resolve to CNAMEs pointing to external domains

Cause

The DNS resolver configuration lacks a root (".") forward zone. When an FQDN resolves to a CNAME in an external domain, BIG-IP attempts to resolve the CNAME target starting from the root. Without a root forward zone, the resolution fails, causing AFM to retain the previous IP addresses and log resolution errors.

Answer/Recommended Actions

Review the DNS resolver configuration on the BIG-IP AFM device:

  1. Add a root (".") forward zone to the DNS resolver to act as a catch-all for CNAME chains and external domains.
  2. Optionally, add a forward zone for your primary domain if not already present, to ensure all primary FQDNs in firewall rules are covered.
  3. Save the configuration and verify that FQDN resolution succeeds for all dynamic firewall rules.

Additional Information

  1. More specific forward zones (e.g., example.com) will take precedence over the root (".") zone.
  2. The root (".") zone acts as a catch-all for CNAME targets in external domains, such as AWS ELB hostnames.
  3. This behavior is expected when the DNS resolver is not configured for full recursion or lacks
