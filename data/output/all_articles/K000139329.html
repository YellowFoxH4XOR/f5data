Description

Under specific condition, when client accesses to virtual server that uses CRLDP type authentication profile along with client-ssl profile, client access may be rejected and an error "crldp config error: basedn" from tamd may be recorded on "/var/log/ltm" log file.

 

Apr 18 12:36:04 bigip.local warning tamd[19527]: 010b0909:4: crldp config error: basedn
Apr 18 12:36:04 bigip.local warning tamd[19527]: 010b0232:4: pam_authenticate: 6
Apr 18 12:36:04 bigip.local warning tamd[19527]: 010b0235:4: AUTH: Permission denied
Apr 18 12:36:04 bigip.local warning tmm2[24336]: 01260013:4: SSL Handshake failed for TCP 10.1.1.60:58928 -> 10.1.1.151:443

 

When this error happens, client side TLS connection is terminated by RST prior to certificate check with LDAP CRLDP.

Figure: packet capture when error happens

 

Just for comparison, here is normal flow when error does not happen.

  1. Client accesses to TLS virtual server.
  2. TLS virtual server requests certificate to client.
  3. Client submits its certificate to virtual server.
  4. BIG-IP looks up the CRLDP URI inside client certificate.
  5. To get CRL data from CRLDP, BIG-IP first resolves the host name of the CRLDP URI.
  6. After host name is resolved, BIG-IP accesses to LDAP CRLDP server and request CRL data.
  7. After CRL data is fetched from LDAP CRLDP server, BIG-IP checks client certificate against CRL. If client certificate is not revoked, then client is allowed to access to pool member.

Figure: packet capture when error does not happen

 

Here is client certificate used on the above flow. Certificate contains CRLDP information in URI with host name. Certificate with different type of CRLDP may show slightly different flows (i.e., no DNS lookup is done).

$ openssl x509 -in testuser302ldapurlcrldp.crt -text | grep -A 3 "X509v3 extensions"
        X509v3 extensions:
            X509v3 CRL Distribution Points:
                Full Name:
                  URI:ldap://ubuntu2004server1.f5ss.local/cn=crldp,dc=f5ss,dc=local?certificateRevocationList?base?objectClass=cRLDistributionPoint
$

 

Both valid client certificate and revoked certificate can generate the error.

 

Environment

All of the following condition need to be met.

  • CRLDP type authentication profile and client-ssl profile are attached to virtual server.
  • CRLDP type authentication configurations refers to CRLDP Servers object.
  • CRLDP Servers object "Base DN" option is empty (default).
  • The client-ssl profile is configured to request client certificate.

Here is example configuration that meets all of the above conditions.

ltm auth profile my_crldp_auth_profile {
    app-service none
    configuration my_crldp_config
    credential-source http-basic-auth
    defaults-from ssl_crldp
    type ssl-crldp
}
ltm auth ssl-crldp my_crldp_config {
    servers {
        my_crldp_server
    }
}
ltm auth crldp-server my_crldp_server {
    base-dn none
    host 192.168.10.51
}
ltm profile client-ssl my_clientssl_profile {
    app-service none
    authenticate always
    ca-file ubuntu2004server1ca.f5ss.local
    cache-size 0
    cert-key-chain {
        web1.f5ss_ubuntu2004server1ca.f5ss_0 {
            cert web1.f5ss.local
            chain ubuntu2004server1ca.f5ss.local
            key web1.f5ss.local
        }
    }
    defaults-from clientssl
    inherit-ca-certkeychain true
    inherit-certkeychain false
    peer-cert-mode request
}
ltm virtual clientssl_certtificate_ldap_auth_vs {
    auth {
        my_crldp_auth_profile
    }
    destination 10.1.1.151:https
    ip-protocol tcp
    mask 255.255.255.255
    pool http_pool
    profiles {
        my_clientssl_profile {
            context clientside
        }
        tcp { }
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    source-address-translation {
        pool my_snatpool192
        type snat
    }
    translate-address enabled
    translate-port enabled
}

 

Figure: GUI configuration example 1

 

Cause

This is designed behavior. 

 

Recommended Actions

Do not leave 'base-dn' value empty on crldp-server object even if client certificate does not have dirName type X509v3 crlDistributionPoints attribute.

Figure: GUI configuration example 2

 

Or if client certificate does not have dirName type X509v3 crlDistributionPoints (i.e., client certificate contains CRLDP information in URI with host name), you can detach crldp-server object from ssl-crldp authentication configuration object, as 'base-dn' parameter is not used on that specific case.

Figure: GUI configuration example 3
