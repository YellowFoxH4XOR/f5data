Description

TMM memory grows steadily over time, particularly in the xdata subsystem.

Examination of show ltm profile web-acceleration reveals a large cache size, which does not appear to be reducing in size over time.

Environment

  • Web-Acceleration (caching) profiles in use

Cause

This can happen if the Web Acceleration profile is configured such that it will cache a large number of small objects, for example, by having a small cache-object-min-size, and a large cache-max-entries.

This is not a bug, but a mis-configuration. The caching subsystem has additional overhead in addition to the size of the cache itself, which can be significant in the case of many small objects.

Recommended Actions

It is recommended to avoid using a cache-object-min-size of 0. Instead, try a larger value such as 4000 to begin with, and limit the number of cache-max-entries. These values are multiplied by the number of TMMs on a system.

Caching of small objects should generally be avoided, as this is very inefficient.

Additional Information

Objects are not purged from the cache when the cache-max-age value is met. They continue to be stored in memory, but must be re-validated with the origin web server before they can be served again to a client. The result of this behaviour may be that TMM memory continues to grow until the cache is full, or in the case of a misconfiguration, TMM runs out of memory.
