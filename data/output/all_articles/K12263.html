Topic

This article applies to BIG-IP 9.x - 10.x. For information about later versions, refer to the following article:

  • K14403: Maintaining disk space on the BIG-IP system

Monitoring the hard disk capacity on a BIG-IP unit is critical to maintaining a healthy system. If a BIG-IP system is running low on disk space, you may experience performance-related issues, such as the inability to perform upgrades, run ConfigSync operations, or save UCS files. F5 recommends that you periodically check disk space utilization and use industry best practices for keeping disk utilization to a minimum.

Overview of disk-formatting schemes

The BIG-IP system implements different disk-formatting schemes, depending on the software version you are running. BIG-IP 10.x software uses the volumes (LVM) disk-formatting scheme, and BIG-IP 9.x software uses the partitions disk-formatting scheme. The disk-formatting schemes allocate hard drive space differently as described in the following two sections:

Logical volume management (LVM) disk-formatting scheme

In BIG-IP 10.x the systems use a logical volume management (LVM) disk-formatting scheme. On LVM systems, every product module includes a description of the file systems it needs, including a mount point and size for each volume. During installation, the BIG-IP system automatically allocates an appropriate amount of disk space when creating a volume set. For example, on a BIG-IP 8900 platform running 10.2.0, the system allocates disk space for each volume set, which appears similar to the following example:

cname                                lv                    (size) KiB       label
sda.mdm.set.1./                  mdm.set.1.root             262144         set.1./            
sda.mdm.set.1./config            mdm.set.1._config          524288         set.1./config      
sda.mdm.set.1./usr               mdm.set.1._usr             1400832        set.1./usr        
sda.mdm.set.1./var               mdm.set.1._var             3145728        set.1./var

In addition, the system allocates a certain amount of disk space for the shared volume. For example, a BIG-IP 8900 platform running 10.2.0 allocates disk space for the shared volume, which appears similar to the following example:

cname                                                         lv                                 (size) KiB            label
sda.mdm.dat.share                mdm.dat.share                    31457280            dat.share       

Partitions disk-formatting scheme

In BIG-IP 9.4.x the systems use a partitions disk-formatting scheme. On partition systems, the BIG-IP system allocates disk space based on the size of the hard disk. During installation, the system allocates x megabytes for a DOS partition, x megabytes for the first image location, and x megabytes for the second image location. The system then allocates the remainder of the disk space to the /shared partition. For example, on a BIG-IP 6800 platform running 9.4.8 with a 160-gigabyte hard disk, the system allocates disk space for each partition similar to the following example:

cname                           part                     id                       size(KiB)               label
hdc.set.1./                          hdc5                     83                       6352904                 hdc.1-root
hdc.set.1./config                hdc7                     83                       6352903                 hdc.1-config
hdc.set.1./usr                     hdc9                     83                       6352903                 hdc.1-usr
hdc.set.1./var                     hdc8                     83                       38117424               hdc.1-var

The system then allocates the remaining amount of disk space to the /shared partition. For example, a BIG-IP 6800 with a 160-gigabyte drive allocates disk space for the /shared partition that appears similar to the following example:

cname                     part             id             size(KiB)          label
hdc.dat.share.1           hdc1                      83                       32162129                dat.share.1

Best practices for maintaining disk space

To help prevent disk utilization issues, F5 recommends that you use the following guidelines to maintain adequate disk space on the system:

  • Store maintenance-related files in the /shared/tmp directory. Maintenance-related files are those files that an administrator may create while performing maintenance or troubleshooting-related tasks on the system. For example, tcpdump files, UCS archives, or tech.out files should be stored in the /shared/tmp directory. Using the /shared/tmp directory for maintenance-related files is recommended for the following reasons:
     
    • The BIG-IP installer allocates a large amount of disk space to the /shared partition.
    • The /shared/tmp/ directory is shared between all installed images on a system. For example, if you save a tcpdump file to the /shared/tmp directory, each installation image or volume set has access to the tcpdump file.

      Note: On BIG-IP systems that contain a hard drive, /var/tmp/ is a symbolic link to the /shared/tmp directory.

    • Consider storing long-term maintenance files on a network share. If you create files that are suitable for longer-term storage, such as UCS archives or SCF files, consider moving them to a network share.

      Note: For information about transferring files from a BIG-IP system, refer to K175: Transferring files to or from an F5 system.

  • When creating/generating a file, provide the full path location so that the file is saved to the intended location and not the current working directory. For example, the following tcpdump command saves the capture file to the /shared/tmp directory:

    tcpdump -ni 1.1 -w /shared/tmp/example-tcpdump.pcap

    The following qkview commands save the corresponding support file to the /shared/tmp directory:

     
    • BIG-IP 10.x (and Enterprise Manager 2.x)

      qkview -f /shared/tmp/example-qkview.tar.gz

    • BIG-IP 9.x (and Enterprise Manager 1.x)

      qkview /shared/tmp/example-qkview-tech.out

    The following bigpipe and tmsh commands save the corresponding UCS file to the /shared/tmp directory:

    • BIG-IP 10.x (and Enterprise Manager 2.x)

      tmsh save /sys ucs no-private-key /shared/tmp/example-config.ucs

      Note: By default, UCS files are saved in their image-specific partitions, which are not visible to all installed images. If you plan to create an archive that will be used for production (using either the Configuration utility or CLI), no path name is needed and the UCS archive is saved to the default location of /var/local/ucs/.

    • BIG-IP 9.x (and Enterprise Manager 1.x)

      bigpipe config support save /var/tmp/example.ucs

  • Avoid storing files in directories that reside on the root filesystem. The BIG-IP system has a relatively small root filesystem, and separate partitions for filesystems, such as /config, /usr/, and /shared. Directories, such as /home reside on the root filesystem and should not be used for file storage.
  • In BIG-IP 10.x, store image files in /shared/images/. In BIG-IP 10.x, if you upload installation images to the BIG-IP system using the command line, you should store them in the /shared/images directory.

    Note: By default, the BIG-IP system stores installation images in /shared/images when uploading an image file to the BIG-IP system using the Configuration utility.

  • In Enterprise Manager 1.x through 2.x, image files for local and remote installations are stored in the /shared/em/images directory.
  • Periodically check the available disk space on the BIG-IP system.

  • Periodically check the inode usage on the BIG-IP system.

    Note: An inode is a data structure that is allocated to a file on a UNIX-based system. If the system contains a large number of small files, you can run out of inodes before you run out of disk space. If inode usage is at or near 100 percent, move any unnecessary maintenance-related files from the BIG-IP system to a network share and schedule a time to reboot the system.

Symptoms of a full or near full partition

When the BIG-IP file systems become full, undesirable or unpredictable behavior may result. Symptoms may include the following:

  • The diskmonitor utility generates warning messages or traps. The diskmonitor utility is a script that runs periodically on the BIG-IP system and alerts you if the partition space or volumes reach a defined threshold. If one or more of these thresholds are reached, a log message is logged to the /var/log/ltm file.

    For example, the following message indicates that the /shared partition has less than 30 percent free space available:

    diskmonitor: 011d005: Disk partition shared has less than 30% free

    The following message indicates that the /shared partition has 0 percent free space available:

    diskmonitor: 011d004: Disk partition shared has only 0% free

    In addition, the BIG-IP system sends the following SNMP trap alerts when the partition space reaches a defined threshold:

    alert BIGIP_DMON_ERR_DMON_ALERT {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.25"
    }
    alert BIGIP_DMON_ERR_DMON_WARN {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.25"
    }
    alert BIGIP_DMON_ERR_DMON_GROWTH {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.26"

    Note: For more information about the diskmonitor utility, refer to K8865: Overview of the diskmonitor utility.

  • Upgrades or hotfix installations may fail to proceed.
  • Daemons log error messages that appear similar to the following examples:

    Couldn't write to <file> / <partition>

    Failed to open file

  • The system experiences performance degradation, such as slow or failed disk writes.
