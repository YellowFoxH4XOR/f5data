Topic

This article applies to BIG-IP GTM 11.x and BIG-IP DNS 12.x and later. For information about other versions, refer to the following article:

  • K9619: Overview of the BIG-IP GTM configuration files (9.x - 10.x)

A BIG-IP DNS (formerly known as BIG-IP GTM) configuration is comprised of the different components that make up the physical and logical segments of the network. These components are stored in the BIG-IP DNS configuration files and represent the configuration that the BIG-IP DNS system uses to direct DNS traffic to the best available resource.

Description

The BIG-IP system stores all BIG-IP DNS configuration elements in the /config/bigip_gtm.conf file. The bigip_gtm.conf file contains the following BIG-IP DNS configuration elements:

Data center definitions

A data center defines the location where the physical network components reside, such as the server and link objects that share the same subnet on the network.

For example, the following data center section of the bigip_gtm.conf file lists data centers called New York and Los Angeles:

gtm datacenter /Common/New York {
    location "New York"
}
gtm datacenter /Common/Los Angeles {
    location "Log Angeles"
}

In BIG-IP GTM 11.5.0  - 11.6.x and BIG-IP DNS 12.x and later, you define data centers in the Configuration utility under DNS > GSLB > Data Centers > Data Center List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define data centers in the Configuration utility under Global Traffic > Data Centers > Data Center List.

Application definitions

A distributed application defines a collection of wide IPs that serve as a single application to a site visitor.

For example, the following application contains two wide IP objects, one for secure connections and one for non-secure connections:

gtm distributed-app /Common/ecommerce {
    wideips {
        /Common/ecommerce.siterequest.com
        /Common/secure-ecommerce.siterequest.com
    }
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define distributed applications in the Configuration utility under DNS > GSLB > Distributed Applications > Application List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define distributed applications in the Configuration utility under Global Traffic > Distributed Applications > Application List.

Link definitions

A link is a BIG-IP DNS object that defines a physical connection to the Internet. A link is associated with one or more routers on the network that provide a path to the Internet; the link address defines the router IP address on the network that provides a path to the Internet, and the uplink address defines the router IP address on the ISP side of the link.

For example, the following link definition resides in the New York data center and contains a link and uplink address:

gtm link "/Common/New York" {
    datacenter /Common/New York
    monitor /Common/bigip_link
    router-addresses {
        10.10.0.254 {
            device-name "/Common/New York"
        }
    }
    service-provider ISP
    uplink-address 172.20.11.254
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define link objects in the Configuration utility under DNS > GSLB > Links > Link List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define link objects in the Configuration utility under Global Traffic > Links > Link List.

Pool definitions

A pool defines one or more virtual servers that share a common role on the network.

For example:

gtm pool /Common/delme {
    fallback-ipv4 any
    members {
        /Common/3900:delme {
            order 0
        }
    }
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define Pools in the Configuration utility under DNS > GSLB > Pools > Pool List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define Pools in the Configuration utility under Global Traffic > Pools > Pool List.

Server definitions

A server defines a specific system on the network. In the BIG-IP DNS configuration, servers contain the virtual server objects to which name resolution requests are load-balanced.

For example, the following server definition resides in the New York data center, and contains one virtual server:

gtm server /Common/3900 {
    addresses {
        10.24.2.11 {
            device-name 3900
        }
    }
    datacenter /Common/New York
    monitor /Common/bigip
    virtual-servers {
        delme {
            destination 1.1.1.1:http
        }
    }
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define servers in the Configuration utility under DNS > GSLB > Servers > Server List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define servers in the Configuration utility under Global Traffic > Servers > Server List.

Topology definitions

A topology is one or more characteristic that matches the origin of a given name resolution request to the appropriate destination. You can define topologies that belong to one of several categories.

For example:

gtm topology  ldns: subnet 10.10.10.0/32  server: subnet 172.24.65.0/32 {
    order 1
}
gtm topology  ldns: continent AF  server: continent AN {
    order 2
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define the topology records in the Configuration utility under DNS > GSLB > Topology > Records.

In BIG-IP GTM 11.0.0 - 11.4.x, you define the topology records in the Configuration utility under Global Traffic > Topology > Records.

Wide IP definitions

A wide IP defines a mapping of a fully-qualified domain name (FQDN) to a group of virtual servers that host the domain’s content.

For example, the following wide IP definition uses topology load-balancing to distribute connections between two pools:

gtm wideip /Common/www.ecommerce.siteconfig.com {
    pool-lb-mode topology
    pools {
        /Common/pool1 {
            order 0
        }
        /Common/pool2 {
            order 1
        }
    }
}

Note: Zero (0) has a higher priority than One (1). So, a wide IP pool with order 0 is preferred over a pool with a priority of 1.

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define wide IPs in the Configuration utility under DNS > GSLB > Wide IPs > Wide IP List.

In BIG-IP GTM 11.0.0 - 11.4.x, you define wide IPs in the Configuration utility under Global Traffic > Wide IPs > Wide IP List.

Monitor definitions

BIG-IP DNS monitors define a configuration element that checks the status of a pool or virtual server at a set interval.

For example:

gtm monitor bigip /Common/bigip_monitor {
    aggregate-dynamic-ratios none
    defaults-from /Common/bigip
    destination *:*
    interval 30
    timeout 90
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you define monitors in the Configuration utility under DNS > GSLB > Monitors.

In BIG-IP GTM 11.0.0 - 11.4.x, you define monitors in the Configuration utility under Global Traffic > Monitors.

Global definitions

The globals section of the bigip_gtm.conf file defines global variables for the BIG-IP DNS system, including load-balancing, metrics collection, and general configuration parameters.

Note: Global parameters that remain at the default setting are not displayed in the bigip_gtm.conf file.

For example, the following globals section of the bigip_gtm.conf file shows the global parameters that have been changed from the default setting:

gtm global-settings general {
    synchronization-group-name SyncGroup
}
gtm global-settings metrics {
    metrics-collection-protocols { icmp tcp dns-dot }
}
gtm global-settings metrics-exclusions {
    addresses {
        3.0.0.0/8
    }
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you configure global variables in the Configuration utility under DNS > Settings > GSLB > General.

In BIG-IP GTM 11.0.0 - 11.4.x, you configure global variables in the Configuration utility under System > Configuration > Global Traffic.

DNSSEC zones and keys

The DNSSEC section defines DNSSEC zones and keys that are defined on the system.

For example:

ltm dns dnssec key /Common/www.ecommerce.siteconfig.com { }
ltm dns dnssec zone /Common/www.ecommerce.siteconfig.com {
    keys {
        /Common/www.ecommerce.siteconfig.com
    }
}

In BIG-IP GTM 11.5.0 - 11.6.x and BIG-IP DNS 12.x and later, you configure DNSSEC in the Configuration utility under DNS > Zones > DNSSEC Zones > DNSSEC Zone List / DNS > Delivery > Keys > DNSSEC Key List.

In BIG-IP GTM 11.0.0 - 11.4.x, you configure DNSSEC in the Configuration utility under Global Traffic > DNSSEC Zone List / DNSSEC Key List.

Recommendations

  • F5 recommends that you use the Configuration utility or Traffic Management shell (tmsh) to change the BIG-IP DNS configuration. F5 recommends that you do not edit the bigip_gtm.conf file directly.
  • You can load the BIG-IP DNS configuration from the command line by running the tmsh load /sys config gtm-only command. The gtmload command is now deprecated.
