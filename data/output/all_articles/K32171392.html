Security Advisory Description

It was found that the fix to address CVE-2021-44228 in Apache Log4j 2.15.0 was incomplete in certain non-default configurations. This could allows attackers with control over Thread Context Map (MDC) input data when the logging configuration uses a non-default Pattern Layout with either a Context Lookup (for example, $${ctx:loginId}) or a Thread Context Map pattern (%X, %mdc, or %MDC) to craft malicious input data using a JNDI Lookup pattern resulting in an information leak and remote code execution in some environments and local code execution in all environments. Log4j 2.16.0 (Java 8) and 2.12.2 (Java 7) fix this issue by removing support for message lookup patterns and disabling JNDI functionality by default. (CVE-2021-45046)

Impact

This could allow attackers to craft malicious input data using a JNDI Lookup pattern resulting in a denial of service (DOS) attack.

Mitigation

All other F5 products

Although F5 products (except Traffix SDC) are not vulnerable to this issue, you may use F5 products to mitigate the impact of this vulnerability in your infrastructure.

Important: If you log the full contents of requests (for example, full HTTP request logging) to a remote logging system which is vulnerable to CVE-2021-44228, and that system parses the request body as sent by the BIG-IP, the remote logging system may still be vulnerable to exploitation.

For information about using F5 products to mitigate the impact of this vulnerability, refer to the following articles:

  • K59329043: Mitigating the Apache Log4j2 vulnerability with BIG-IP
  • K25643754: Mitigating the Apache Log4j2 vulnerability with NGINX Application Security products

Note: For more robust solution and mitigation options, consider implementing and configuring BIG-IP ASM/Advanced WAF Security Policies or NGINX App Protect to mitigate application attacks to your applications. Contact your F5 Sales Team or Representative for further discussion.

Traffix SDC

To mitigate this vulnerability, you can modify the elastic search configuration files of JVM options, remove the JNDI lookup class file, and restart the elastic search components. For more information, refer to K28202455: Disable JDNI lookups for Traffix EMS ELK.
