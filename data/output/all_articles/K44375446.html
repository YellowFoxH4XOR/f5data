Description

The statsd daemon can sometimes log debug logs in /var/log/ltm even when it is not configured to log debug level logs. This is a known issue being tracked under bug ID 781373. Some examples include:

Oct  7 03:18:20 LTM1 debug statsd[7155]: 011b090c:7: tmstat_query_rollup on table profile_ppp_stat called.
Oct  7 03:18:20 LTM1 debug statsd[7155]: 011b0232:7: CACHE HIT  during rollup, prev=profile_ppp_stat, curr=profile_ppp_stat.
Oct  7 03:18:20 LTM1 debug statsd[7155]: 011b1000:7: got uquad 0 for column max_links source pppmaxlinks
Oct  7 03:18:20 LTM1 debug statsd[7155]: 011b090e:7: getTMValueUNKeyed start.

Environment

  • BIG-IP

Cause

The db variables for log level were modified and then reset to their defaults using the "sys db reset-to-default" command sometime in the past.

Recommended Actions

  1. Change the log level to "debug" via the following command to match the current logs.
      
    tmsh modify sys db log.statsd.level value debug
  2. Change the log level back to the default "warning" value.
      
    tmsh modify sys db log.statsd.level value warning
  3. Reset the default log level (this will set it back to "warning").
      
    tmsh modify sys db log.statsd.level reset-to-default
