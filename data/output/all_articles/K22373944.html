Topic

You should consider using this procedure under the following conditions:

  • You have the BIG-IP APM module licensed and provisioned on your BIG-IP system.
  • You are experiencing either of the following situations and want to collect troubleshooting data for analysis:
    • You are having difficulty installing BIG-IP Edge Client on client systems.
    • Users are unable to connect to the BIG-IP APM system using BIG-IP Edge Client or are experiencing connection issues.

Description

This article identifies several common problems you may experience when connecting to the BIG-IP APM system using BIG-IP Edge Client and provides data-gathering tools you can use to identify potential causes of failure events. You can use the procedures that follow to reinstall the client components and gather diagnostic data, which you can use to troubleshooting problems.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility.
  • You have access to the Advanced Shell (bash).
  • You have access to a test user system that is failing to connect while using BIG-IP Edge Client.

Note: To open a support case with F5 Technical Support, you must have an active support contract and you must be authorized to open support cases. If you are a user of an F5 product or client application, such as BIG-IP Edge Client for IOS, BIG-IP Edge Client for Android, or the FirePass controller, and you require technical support, contact your system administrator or IT department for assistance. Only authorized contacts can open technical support cases with F5 Technical Support.

Procedures

Use the following procedures to review common problems and gather diagnostic data on the BIG-IP APM system:

  • Reviewing common issue causes
  • Reinstalling BIG-IP Edge Client on the client system
  • Enabling and disabling debug logging on the BIP-IP APM system
  • Collecting data on the BIG-IP APM system while reproducing the issue
  • Generating a Client Troubleshooting Utility (CTU) report in HTML format

Reviewing common issue causes

One of the common causes for VPN disconnections is other VPN clients, such as Juniper, Cisco, and others, running at the same time as BIG-IP Edge Client. Running other VPN clients can interfere with the Network Driver Interface Specification Wide Area Network (NDISWAN) and RAS services on a Windows Client and cause BIG-IP Edge Client to fail in various ways. Check if this is the case, disable or remove the other vendor VPN clients if they exist, and then test again.

Another common cause of problems occurs due to recently installed applications, plug-ins, or updates to software. If your issue is new on a previously working system, review the recent install history and identify whether updates or changes may be causing BIG-IP Edge Client to fail.

Another common issue occurs when antivirus, anti-malware, real-time scanning software, or firewall configurations block VPN access to network resources. If yours is a new installation and your users can't connect, disable these services and try again. If you find one of these programs is blocking VPN functions, you can include it on the F5 VPN accept list.

Reinstalling BIG-IP Edge Client on a client system

You can resolve some issues by uninstalling and reinstalling the client components. To remove and reinstall the client components on a Windows system, perform the following procedure:

  1. Log in to the client system as an administrator.
  2. Navigate to %userprofile%\Local Settings\Temp or %temp% on Windows XP, or to %userprofile%\AppData\Local\Temp or %temp% in Windows.
  3. Delete the logterminal.txt and logterminal.txt.bak files.
  4. Launch CTU (f5wininfo.exe) on the affected client machine. Click Tools and ensure that the Enable Logs check box is selected.
  5. Remove the client components by clicking Remove Components in the Tools menu. Allow the removal script to run for 2-3 minutes to complete the removal process.
  6. On the Windows desktop, open Internet Properties from the Control Panel > Internet Options.
  7. Click the Connection tab.
  8. Select the connections that refer to F5 or your BIG-IP APM configuration and click Remove to remove them.
  9. Open the Windows Device Manager and click Show hidden devices in the View menu.
  10. If the F5 VPN adapter appears under Network adapters, right-click F5 Networks VPN Adapter and click Uninstall.
  11. Click Programs in the Windows Control Panel, uninstall any items relating to F5, and then restart the client system.
  12. Reinstall BIG-IP Edge Client and attempt to reconnect to the BIG-IP APM system. If problems persist, perform the remaining procedures to gather diagnostic data.

Enabling and disabling debug logging on the BIG-IP APM system

You can obtain more information about issues when using BIG-IP Edge Client by enabling debug logging for the BIG-IP APM system. Once you've enabled debug logging, you can attempt to reproduce the problem.

Enabling and disabling debug logging in BIG-IP APM 12.x - 14x

Beginning in BIG-IP APM 12.x, you can create separate logging settings per access profile. To enable debug logging for the affected access profile, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log into the Configuration utility.
  2. Navigate to Access > Event Logs > Settings.

    Note: For BIG-IP 12x, navigate to Access Policy > Event logs > Log Settings.

  3. Click Create.
  4. Type a name for Name and select the Enable Access System Logs check box.
  5. Click Access System Logs.
  6. For Access Policy, click Debug.
  7. Click Access Profiles.
  8. From the Available list, click the access profile and move it to the Selected list.
  9. Click OK.

To revert the changes to the access profile logging, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility and navigate to Access > Event Logs > Settings.

    Note: For BIG-IP 12x, navigate to Access Policy > Event Logs > log Settings.

  2. Select the check box for the newly created log settings.
  3. Click Delete.
  4. Click Yes to confirm deletion of the debug log settings and remove the settings from the access profile.

Enabling and disabling debug logging in BIG-IP APM 11.x

In BIG-IP APM 11.x, you can enable and disable access policy debug logging using the Configuration utility or by setting the log.accesscontrol.level database variable.

Enabling and disabling debug logging in BIG-IP APM 11.x using the Configuration utility

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Options.
  3. Scroll down and under Access Policy Logging, in the Access Policy list, click Debug.
  4. Click Update.
  5. After you finish troubleshooting, to revert to default settings, repeat steps 1 and 2, and for step 3, click Notice, and then click Update.

Enabling and disabling debug logging in BIG-IP APM 11.x using tmsh

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable access policy debug logging, type the following command:

    modify /sys db log.accesscontrol.level value debug

  3. After troubleshooting is complete, you can revert access policy logging to the default setting by typing the following command:

    modify /sys db log.accesscontrol.level reset-to-default

Collecting data on the BIG-IP APM system while reproducing the issue

Perform the following procedure to reproduce the issue and capture the debug logs from the BIG-IP APM system.

Impact of procedure: Performing the following procedure should not have a negative impact on your system. However, performing a tail of the logs or running tcpdump for excessive amounts of time can use up system resources and cause poor performance.

  1. Log in to bash as root.
  2. To capture the client traffic with tcpdump, using the following command syntax:

    tcpdump -vvv -ni 0.0:nnn host <client_IP> -s0 -w /var/tmp/edge-client.pcap

    For example:

    tcpdump -vvv -ni 0.0:nnn host 10.90.100.1 -s0 -w /var/tmp/edge-client.pcap

  3. Have a user attempt to connect to the BIG-IP APM system with BIG-IP Edge Client. Note the SessionID of the test user.

    Note: To review the /var/log/apm file during the test, log in to bash using a separate terminal, and use the tail -f /var/log/apm command.

  4. Stop tcpdump by pressing CTRL+C.
  5. To copy the /var/log/apm file to the apm_log.txt file, type the following command:

    cp /var/log/apm /var/tmp/apm_log.txt

  6. To generate a qkview, type the following command:

    qkview -s0

  7. The edge-client.pcap file, apm_log.txt file, and qkview command output appear in the /var/tmp directory.
  8. Return the logs back to their default level with appropriate back-out procedure.

Generating a CTU report in HTML format

Perform the following procedure to generate a diagnostic report using the CTU.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Launch CTU (f5wininfo.exe) on the affected client machine. Click Tools and ensure that the Enable Logs check box is selected.
  2. From the File menu, click Generate Report.
  3. Select all four options.
  4. For Format, click html.
  5. Click Save As and save the report.
  6. Review the report, paying particular attention to the logterminal.txt section.
