K10608: The ARX system may reboot when enabling a shadow copy rule after the target ARX system has been upgraded

Known Issue

This is the result of a known issue. The ARX system will dump core and continuously reboot until the reboot bounce limit is reached under the following circumstances:

  • An ARX system previous to version 5.x is configured with a shadow copy rule targeting shadow volume on a remote ARX system
  • The target ARX system is upgraded to ARX version 5.x, and the source ARX system remains at version 2.x, 3.x, or 4.x
  • A schedule runs and triggers the shadow copy rule on the source ARX system

Additionally, an error message is logged on the source ARX system that appears similar to the following example:

1-1-ACM-6265:POLICY_SHADOW-1-7-MSG7::DPSyncManager:[TheShadowKnows] Volume[ns:/vol1] Protocol packet invalid

F5 Product Development tracked this issue as ID 36421 and it was fixed in ARX version 5.1.0. For information about upgrading, refer to the ARX release notes.

Workaround

To avoid this issue, use one of the following options:

  • Disable all shadow copy rules on the source ARX system until all of the ARX systems have been upgraded to version 5.x
  • Upgrade the source ARX system to version 5.x before upgrading the target ARX system
  • Upgrade both the target and the source ARX systems to version 5.x before re-enabling the shadow copy rules
