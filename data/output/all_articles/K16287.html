Known Issue

The Port Lockdown setting for a self IP address is not incrementally synchronized to standby BIG-IP systems.

This issue occurs when all of the following conditions are met:

  • You use the Configuration utility to change the Port Lockdown setting for a self IP address on an active BIG-IP system.
  • You attempt to perform an incremental configuration synchronization (ConfigSync) operation to members of the device group.

Impact

The Port Lockdown setting for a self IP address is not synchronized to standby BIG-IP systems.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After performing an incremental ConfigSync, you observe that the Port Lockdown setting for a self IP address is not propagated to standby systems.
  • You notice that standby systems use the old Port Lockdown setting for the self IP address.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to modify the self IP Port Lockdown setting. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. From the active BIG-IP system, log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Verify the current selection for the self IP Port Lockdown setting by using the following command syntax:

    list net self <self IP name>

    For example:

    list net self askf5-internal-float

  3. Modify the self IP Port Lockdown setting by using the following command syntax:

    modify net self <self IP name> allow-service <option>

    For example:

    modify net self askf5-internal-float allow-service none

  4. Synchronize the Port Lockdown configuration to the standby systems by using the following command syntax:

    run cm config-sync to-group <device group name>

    For example:

    run cm config-sync to-group bigip-HA-group

  5. Save the configuration by typing the following command:

    save sys config
