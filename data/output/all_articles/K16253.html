Known Issue

The BIG-IP APM apd and apmd processes may fail to start after a file check agent is applied to the access policy. This issue can occur when you add a Windows File, Linux File, or Mac File client-side Endpoint Security check agent to an access policy.

Impact

The BIG-IP APM system fails to process traffic while the apd or apmd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users cannot access resources using the BIG-IP APM system.
  • The apd or apmd process exits and generates a core file to the /shared/core directory.
  • After applying the access policy, the apd or apmd process continually restarts.
  • SIGABRT messages appear in the /var/log/apm file, similar to the following example:

    -- notice apd[<pid>]: 01490000:5: ** SIGABRT **.
    -- notice apmd[<pid>]: 01490000:5: ** SIGABRT **
