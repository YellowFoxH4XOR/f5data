Known Issue

This is the result of a known issue. If the host header is blank or corrupted, the iRule command HTTP::host may cause TMM to crash when the iRule attempts to extract the information.

F5 Product Development tracked this issue as CR77137 and it was fixed in BIG-IP LTM version 9.3.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by using the iRule command HTTP::header to extract the hostname in an HTTP request instead of HTTP::host.

The following iRule may cause TMM to crash if it receives a request that contains a blank or corrupted Host header:

 if {[HTTP::host] !=""} {    <code here>    } else {    <code here>   }}

The following iRule will not cause TMM to crash, as it uses the HTTP::header command to extract the host value:

if [HTTP::header "Host"] !=""} {    <code here>    } else {    <code here>   }}
