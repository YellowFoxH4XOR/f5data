Topic

This article provides the known indicators of compromise (IOCs) associated with malicious software c05d5254 and related activity, and actions to take if IOCs are discovered.

Important: Customers that were using BIG-IP APM on a vulnerable version at any point in time (regardless of current version) are advised to review systems for all of the following indicators of compromise and run the F5 System Scanner. If the Scanner detects a mismatch of the files referenced in this article, then please open a support case, upload the F5 System Scanner results, and upload a QKView through iHealth. If any of the indicators of compromise are present on your BIG-IP system, review the following article: K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system.

Description

You may observe the following indicators of compromise on your BIG-IP system upon the successful deployment of malicious software c05d5254 on your BIG-IP system.

Files on disk

  • Presence of /run/bigtlog.pipe and/or /run/bigstart.ltm.
  • Mismatch of file hashes, file sizes, or timestamps when compared to known good versions of the following files:
    • /usr/bin/umount
    • /usr/sbin/httpd
    • /usr/sbin/chroot
    • /usr/libexec/apmd64
    • /usr/bin/sys-icheck
    • /usr/libexec/sys-eicheck.py
    • /etc/rc.d/rc.local
  • Each release and EHF may have different file sizes and time stamps.
  • Review /config/startup to ensure it only contains authorized changes.

Log entries

  • /var/log/restjavad-audit.<NUMBER>.log

    [ForwarderPassThroughWorker{"user":"local/f5hubblelcdadmin","method":"POST","uri":"http://localhost:8100/mgmt/tm/util/bash","status":200,"from":"Unknown"}

    This entry shows a local user accessing the iControl REST API from localhost.

  • /var/log/auditd/audit.log.<NUMBER>

    msg='avc: received setenforce notice (enforcing=0) exe="/usr/lib/systemd/systemd" sauid=0 hostname=? addr=? terminal=?'

    This entry shows a local user accessing the iControl REST API from localhost to disable SELinux.

  • /var/log/audit

    user=f5hubblelcdadmin folder=/Common module=(tmos)# status=[Command OK] cmd_data=run util bash <VARIABLE_COMMAND>

    These log messages show an echo of Base64-encoded data written into a file and the execution of /run/bigstart.ltm. This entry shows an example of a command being run in the audit log, correlated to the iControl REST request above.

Commands

  • F5 System Scanner (the “Scanner”)
    • Scanner is a software run on BIG-IP that performs file integrity checks against known good hashes. Scanner identifies and reports on mismatches and will also detect mismatches of /usr/bin/umount or /usr/sbin/httpd noted above.
    • If the Scanner detects a mismatch, then please open a support case and upload the Scanner results and upload a QKView through iHealth.
    • For more information, please see K000160515: F5 System Scanner.
  • lsof -n

    The output of this command contains entries for /run/bigtlog.pipe.

  • getenforce

    Verify that SELinux is running in Enforcing mode. If this command returns anything other than Enforcing (e.g., Permissive or Disabled), then consider it as a potential indicator of compromise.

  • semanage permissive -l

    If this command indicates that httpd_t, mount_t, and/or apd_t are set to Permissive, then consider it as a potential indicator of compromise.

Tactics, Techniques, and Procedures (TTPs)

  • You may observe HTTP/S traffic from the BIG-IP system that contains HTTP 201 or 401 response codes and CSS content-type to disguise the attacker's activities.
  • The /usr filesystem being mounted as read-write (rw), instead of its usual read-only (ro) state, could suggest a potential security issue. However, on its own, this is not a strong indicator of compromise.
  • Changes to the following files might signal a potential compromise; however, their presence alone does not indicate a security issue:
    • /var/sam/www/webtop/renderer/apm_css.php3
    • /var/sam/www/webtop/renderer/full_wt.php3
    • /var/sam/www/webtop/renderer/webtop_popup_css.php3
    • /var/sam/www/webtop/missing.php
    • /var/sam/www/webtop/renderer/my.logout.php3

Note: We have observed cases of webshell being written to disk; however, the webshells have been observed to work in memory only, meaning the files listed above might not be modified.

If you suspect a security compromise on your BIG-IP system, review the following article: K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system.
