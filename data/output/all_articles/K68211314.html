K68211314: Configuring an inband monitor for a Diameter pool

Topic

You should consider using this procedure under the following condition:

  • You want to configure an inband monitor for a Diameter pool

Description

The inband monitor passively monitors a configured pool member by inspecting the traffic running to and from that pool member to determine its health status. When an inband monitor is configured to monitor a Diameter peer and the diameter peer fails to respond to a Diameter Watchdog Request (DWR), the BIG-IP system terminates the connection to the Diameter peer and the inband monitor marks the Diameter peer down. You can configure the BIG-IP system to continuously retry connection to the Diameter peer so that the inband monitor marks the Diameter peer up when the BIG-IP connection to the Diameter peer is successful.

In order to monitor a Diameter peer successfully, you must configure the following:
  • The Auto-Initialization Enabled setting check box for the Diameter peer profile must be selected; this allows the BIG-IP system to automatically create outbound connections to the active pool member in the Diameter peer’s specified pool.
  • The value of the Auto-Initialization Interval setting (in milliseconds) for the Diameter peer profile must be slightly greater than the value of the Retry Time setting (in seconds) for the inband monitor; this enables the inband monitor retry timer to expire with an open window to check the status of the Diameter peer just before the Auto-Initialization timer expires and tries to establish the connection to the Diameter peer.
  • The value of the Watchdog Timeout setting (default is 30s) for the diameter session profile must be set to less than the value of the Idle Timeout setting (default is 300s) for the associated protocol (TCP or SCTP) profile. The Watchdog Timeout setting determines the number of seconds that a connection can be idle before a DWR is sent to the Diameter peer.
  • The Reset on Timeout setting for the Diameter session profile must be enabled. This setting allows the system to reset the connection to the Diameter peer when the watchdog failures from the peer exceed the configured value of the Maximum Watchdog Failures setting.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the Configuration utility.
  • The BIG-IP system has an existing Diameter MRF configuration (for example, session profile, transport config profile, and peer profile). 

    Note: For information about configuring Diameter MRF, refer to the Using the Diameter Configuration Wizard and Configuring Diameter Load Balancing and Message Routing chapters of the BIG-IP Service Provider: Message Routing Administration manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Procedures

  • Enabling the Auto-Initialization settings for the Diameter peer profile
  • Configuring an inband monitor for the Diameter pool
  • Configuring Reset on Timeout and Watchdog Timeout setting for the Diameter session profile
  • Assigning the inband monitor to the Diameter pool

Enabling the Auto-Initialization settings for the Diameter peer profile

If you have not already enabled the Auto-Initialization settings for the Diameter peer profile, you should do so by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Message Routing > Diameter.
  3. Select Peers.
  4. Select the Diameter peer profile that contains the pool of which the Diameter peer is a member.
  5. Enable the Auto-Initialization Enabled setting by selecting the check box; the Configuration utility then displays the Auto-Initialization Interval setting.
  6. Enter a value in milliseconds (ms) for the Auto-Initialization Interval setting, for example 60000; this value needs to be slightly higher than the value of the Retry Time setting in the inband monitor.
  7. Select Update to save the changes; you should take note of the name of the transport config profile configured for the Transport Config setting as you need the information to determine which Diameter session profile to modify in a subsequent procedure.

Configuring an inband monitor for the diameter pool

If you have not already created an inband monitor for the Diameter pool, you should configure one and set the value of the Retry Time setting to be slightly less than the value of the Auto-Initialization Interval setting in the Diameter session profile. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. For Name, enter a name for the inband monitor.
  5. For Type, select Inband.
  6. Enter a value in seconds for the Retry Time setting; this value needs to be slightly lower than the value of the Auto-Initialization Interval setting in the Diameter peer profile. For example if the Auto-Initialization Interval setting has a value of 60000ms, then you can consider configuring the Retry Time setting to a value less than or equal to 59s.

Configuring Reset on Timeout and Watchdog Timeout setting for the Diameter session profile

To determine which Diameter session profile to modify, you can verify the Profiles setting in the transport configuration profile associated with the Diameter peer (determined from an earlier procedure). The following procedure provides the steps to determine the Diameter session profile to modify, as well as steps to enable the Reset on Timeout setting in the Diameter session profile and configure the Watchdog Timeout setting if you have not already done so:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Message Routing > Diameter.
  3. Select Transport Config.
  4. Select the transport config profile determined from the previous procedure
  5. Under Configuration, for Profiles, there should be a Diameter session profile as well as a TCP or SCTP profile (depending on which protocol you have configured for your Diameter MRF). Note the name of the Diameter session profile.
  6. Go to Local Traffic > Profiles > Message Routing > Diameter.
  7. Select Session Profiles.
  8. Select the name of the diameter session profile you determined in step 5.
  9. If the Reset on Timeout setting is not already enabled, enable it by selecting the Enabled check box.
  10. Depending on your application environment, adjust the value of the Watchdog Timeout setting as needed while ensuring that it is less than the value of the Idle Timeout setting of the protocol profile (TCP or SCTP) your Diameter MRF is using.
  11. Select Update to save the changes.

Assigning the inband monitor to the diameter pool

After performing the necessary configuration in the previous procedures, you can now assign the inband monitor to the diameter pool. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select the name of the Diameter pool.
  4. For Health Monitors, in the Available list, select the name of the inband monitor which you configured in the first procedure and move the inband monitor to the Active list.
  5. Select Update to save the changes.
