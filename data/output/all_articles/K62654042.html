Topic

You should consider using this procedure under the following condition:

  • You want a general example of how to use the iControl REST API to administer custom attack signatures and signature sets of the BIG-IP ASM system.

Description

This article shows you how to use the iControl REST API to create and apply attack signatures and signature sets.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have administrative access to the BIG-IP ASM Configuration utility.
  • Have a general understanding of the iControl REST API.

Procedures

  • Create a custom attack signature
  • Create a signature set based on user-defined criteria
  • Add a signature set to a security policy
  • Apply the security policy

Create a custom attack signature

The following procedure demonstrates how to use the iControl REST API to create a custom attack signature. The example procedure is centered around an attack signature that is checking for a specific HTTP header value.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Use the following syntax to create a custom attack signature:

    curl -sk -X POST -u admin:<passowrd> -H "Content-Type: application/json" https://<big-ip asm address>/mgmt/tm/asm/signatures -d '{"name":"<signature name>","description":"<description details>","isUserDefined":true,"attackType":{"name":"<attack type name>"},"rule":"<rule type>:\"<rule expression>\";","matchesWithinCookie":false,"keywords":[{"comparison":"string-match","matchCase":true,"value": "<string to match>","context":"<element>"}],"matchesWithinHeader": true,"hasCve": false,"accuracy":"<accuracy level>","risk":"<risk level>","signatureType":"<signature type>"}' | jq -M .

    Important: The command syntax rule is based on an HTTP header element rule syntax. Other elements may require additional configuration options. 

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.
    • <signature name> is the name you want for your custom attack signature.
    • <description details> is a simple one-line sentence regarding the attack signature.
    • <attack type name> is one of the values from the Signature Types list.
    • <rule type> is one of the values from the Rule Type list.
    • <rule expression> is your custom rule stanza.
    • <string to match> is your specific string value to trigger on.
    • <element> is one of the values from the Elements list.
    • <accuracy level> is one of the following values high, medium, or low.
    • <risk level> is one of the following values high, medium, or low.
    • <signature type> is a value from the Signature Check list.

      Values
      Note: The items in this list are not inclusive. F5 recommends that you investigate the attack signature requirements for your custom attack signature.

      • Elements - header, request, uri-without-query-string, uri-with-query-string
      • Signature Check - request, response
      • Accuracy levels - high, medium, low
      • Risk levels - high, medium, low
      • Signature Types - Abuse of Functionality, Authentication/Authorization Attacks, Buffer Overflow, Command Execution, Cross Site Scripting (XSS), Denial of Service, Detection Evasion, Directory Indexing, HTTP Parser Attack, HTTP Response Splitting, Information Leakage, LDAP Injection, Malicious File Upload, Non-browser Client, Other Application Attacks, Path Traversal, Predictable Resource Location, Remote File Include, Server Side Code Injection, Session Hijacking, SQL-Injection, Trojan/Backdoor/Spyware, Vulnerability Scan, XPath Injection, request

    For example:

    curl -sk -X POST -u admin:<passowrd> -H "Content-Type: application/json" https://192.168.1.174/mgmt/tm/asm/signatures -d '{"name":"NotGoodHeader","description":"HTTP header value of NotGood.","isUserDefined":true,"attackType":{"name":"Command Execution"},"rule":"headercontent:\"NotGood\";","matchesWithinCookie":false,"keywords":[{"comparison":"string-match","matchCase":true,"value": "NotGood","context":"header"}],"matchesWithinHeader": true,"hasCve": false,"accuracy":"high","risk":"high","signatureType":"request"}' | jq -M .

  2. Use the following REST GET syntax to note the "id": value of the JSON output in case you need to obtain the id value after the signature is created:

    curl -sk -X GET -u admin:<passowrd> -H "Content-Type: application/json" https://<big-ip asm address>/mgmt/tm/asm/signatures | jq -M . | grep -iB4 <signature name> | egrep '"name":|"id":'

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.
    • <signature name> is the name used to create the custom signature.

Create a signature set based on user-defined criteria

The following procedure demonstrates how to create a custom attack signature set. The signature set is automatically populated with configured attack signatures that match the following signature set criteria.

  • Category: user-defined
  • Signature Type: request
  • Accuracy: high
  • Risk: high

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Use the following syntax to create a new user-defined signature set using the criteria that the previous attack signature was created with (category:User-defined, SignatureType:request, Accuracy:high, Risk:high). The attack signature set automatically includes that signature in the signature set.

    curl -sk -X POST -u admin:<passowrd> -H "Content-Type: application/json" https://<big-ip asm address>/mgmt/tm/asm/signature-sets -d '{"name":"<signature set name>","category":"User-defined","filter":{"riskFilter": "ge","userDefinedFilter": "yes","accuracyValue":"<accuracy level>","hasCve": "all","accuracyFilter": "ge","lastUpdatedFilter":"all","riskValue":"<risk level>","signatureType":"
    <element>","tagFilter":"untagged"},"defaultBlock":<true/false>,"defaultLearn":<true/false>}' | jq -M .

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.
    • <signature set name> is the name of your custom attack signature set name.
    • <accuracy level> is one of the following values high, medium, or low.
    • <risk level> is one of the following values high, medium, or low.
    • <element> is one of the values from the Elements list (header, request, uri-without-query-string, uri-with-query-string).

    For example:

    curl -sk -X POST -u admin:<passowrd> -H "Content-Type: application/json" https://192.168.1.174/mgmt/tm/asm/signature-sets -d '{"name":"UserDefined-SignatureSet","category":"User-defined","filter":{"riskFilter": "ge","userDefinedFilter": "yes","accuracyValue": "high","hasCve": "all","accuracyFilter": "ge","lastUpdatedFilter": "all","riskValue":"high","signatureType":"request","tagFilter":"untagged"},"defaultBlock":true,"defaultLearn":false}' | jq -M .

    The following syntax creates a new user-defined signature set using the signature criteria (category:User-defined, SignatureType:request, Accuracy:all, Risk:all) that includes all user-defined request attack signatures.

    Note: These settings automatically include all attack signatures matching the criteria in the signature set.

    For example:

    curl -sk -X POST -u admin:<passowrd> -H "Content-Type: application/json" https://192.168.1.174/mgmt/tm/asm/signature-sets -d '{"name":"UserDefined-SignatureSet","category":"User-defined","filter":{"riskFilter": "ge","userDefinedFilter": "yes","accuracyValue": "all","hasCve": "all","accuracyFilter": "ge","lastUpdatedFilter": "all","riskValue":"all","signatureType":"request","tagFilter":"untagged"},"defaultBlock":true,"defaultLearn":false}' | jq -M .

Add a signature set to a security policy

Once you have created the custom attack signature and custom attack signature set, you can add the attack signature set to an existing security policy.

Impact of procedure: Performing the following procedure applies the updated security policy and the custom attack signatures to the traffic that is processed by the virtual servers that are configured with the security policy.

Adding the new signature set to a security policy requires that you use the security policy hash value and the attack signature set hash value.

  1. To obtain the security policy hash value, use the following syntax. Locate the security policy name, followed by the "id":, followed by the security policy hash value.

    curl -sk -u admin:<password> -H "Content-Type: application/json" -X GET https://<big-ip asm address>/mgmt/tm/asm/policies | jq -M . | egrep '\"id\": |\"name\": '

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.

    Example output:

          "name": "Policy_A",
          "id": "VZ7laoTg2x7-_-CdIwBNZw",
          "name": "Policy_B",
          "id": "euMwbEcwgGlvVz1Gb0XZCA",
          "name": "Policy_C",
          "id": "7xCx7CHC8EgHBVIwR9bccQ",

    For example, you would use the following syntax to apply the attack signature set fKQEpKws_MjV3KDBs-k_IQ to the security policy VZ7laoTg2x7-_-CdIwBNZw using the hash values:

    curl -sk -X POST -u admin:<password> -H "Content-Type: application/json" https://<big-ip asm address>/mgmt/tm/asm/policies/VZ7laoTg2x7-_-CdIwBNZw/signature-sets -d '{"signatureSetReference":{"link":"https://localhost/mgmt/tm/asm/signature-sets/fKQEpKws_MjV3KDBs-k_IQ"},"selfLink":"https://localhost/mgmt/tm/asm/policies/VZ7laoTg2x7-_-CdIwBNZw/signature-sets/fKQEpKws_MjV3KDBs-k_IQ","kind":"tm:asm:policies:signature-sets:signature-setstate","alarm":true,"block": true,"id":"","learn":true}' | jq -M .

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.
    • Replace all instances of the policy hash value VZ7laoTg2x7-_-CdIwBNZw with the hash value of your security policy.
    • Replace all instances of the signature set hash value fKQEpKws_MjV3KDBs-k_IQ with the hash value of your custom attack signature set.

Apply the security policy

Though the security policy attack signature set list now includes the custom attack signature set, the signatures of the signature set are not applied to traffic until you place the updated security policy into the active configuration. To do so, complete the following procedure:

Impact of procedure: Performing the following procedure applies the updated security policy and the custom attack signatures to the traffic that is processed by the virtual servers that are configured with the security policy.

  1. Use the following syntax to apply the security policy.

    curl -sk -u admin:<password> https://<big-ip asm address>/mgmt/tm/asm/tasks/apply-policy -X POST -d '{"policyReference": {"link": "https://192.168.1.174/mgmt/tm/asm/policies/<policy hash value>"}}'

    In the previous syntax, note the following:

    • <password> is the admin password.
    • <big-ip asm address> is the management IP address of the BIG-IP ASM device.
    • <policy has value> is the security policy hash value that the attack signature set was applied to.

    For example, you would use the following syntax to apply the security policy using the security policy hash value VZ7laoTg2x7-_-CdIwBNZw:

    curl -sk -u admin:<password> https://192.168.1.174/mgmt/tm/asm/tasks/apply-policy -X POST -d '{"policyReference": {"link": "https://192.168.1.174/mgmt/tm/asm/policies/VZ7laoTg2x7-_-CdIwBNZw"}}'

    In the previous syntax, note the following:

    • <password> is the admin password.
    • Replace all instances of the policy hash value VZ7laoTg2x7-_-CdIwBNZw with the hash value of your security policy.
