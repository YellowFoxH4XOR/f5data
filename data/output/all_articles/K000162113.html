Description

You may ge the log messages such as below in the log file /var/log/ltm:

err mcpd[<PID>]: 01071aed:3: Peer <Peer IP> time exceeds threshold 3 sec - difference -4 sec

warning mcpd[<PID>]: 01071aea:4: CMI heartbeat timer expired, status: <Peer IP>

warning mcpd[<PID>]: 01071be0:4: CMI Heartbeat Response <Peer IP> - Mismatched sequence numbers - expecting 962242, received 962241

notice mcpd[<PID>]: 01071aee:5: Peer <Peer IP> time is back in sync

The log above maybe observed during device group configuration sync operations on BIG-IP LTM systems. These events typically occur when full sync operations are triggered, especially in environments with large configuration files and frequent configuration changes. The logs indicate temporary synchronization and communication issues between device group peers.

Environment

  • Product: BIG-IP
  • Device group with auto sync enabled
  • Large /config folder (often due to a high number of partitions)
  • High frequency of configuration updates
  • Incremental syncs frequently escalating to full syncs

Cause

This issue is caused by:

  • Large /config directory size (many partitions or configuration objects)
  • High frequency of configuration changes with auto sync enabled
  • Frequent full syncs causing significant network and resource overhead, leading to temporary congestion of the configsync connection and resulting in time/sequence mismatches between device group peers

Recommended Actions

  • Reduce the frequency of configuration changes, like introduce a delay (e.g., 10 seconds) between each modification to allow sync operations to complete before new ones are triggered.
  • If possible, reduce the size of the /config folder by minimizing the number of partitions or configuration objects.

Additional Information

  • The observed behavior is expected in environments with very large configurations and frequent changes, especially when auto sync is enabled.
