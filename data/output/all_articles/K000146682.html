K000146682: SNI Mismatch due to connection re-use

Type
Support Solution
Published
2024-11-08
Updated
2025-02-22
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000146682

Description

  • You’re experiencing issues with SNI mismatches due to connection re-use on F5 Distributed Cloud (XC) HTTP Load Balancers. This leads to errors when serving multiple domains via the same load balancer.

Environment

  • F5 Distributed Cloud (XC) HTTP Load Balancers

Answer/Recommended Actions

  • To resolve this issue, set SNI Selection to SNI Value in the load balancer configuration. This will ensure that the correct SNI value is passed during each connection.

Cause

F5 Distributed Cloud (XC) implements connection re-use to origins to reduce connection overhead. When a connection is re-used, the SNI value set during the initial TLS handshake can mismatch the Host header of subsequent requests, leading to failures.

Scenario:

  • A request is made to domainABC.example.com. The load balancer establishes a TLS connection with the origin server, setting the SNI value to domainABC.example.com and forwarding the HTTP request with Host: domainABC.example.com.
  • The connection between the load balancer and origin remains open for future requests, even though the client connection is closed.
  • A second request comes in for domainXYZ.example.com. Since the connection is still open, the load balancer re-uses it and sends the new request with Host: domainXYZ.example.com. However, the SNI value still reflects domainABC.example.com, causing a mismatch.
  • The origin server rejects the request due to this SNI/Host mismatch, as it is considered a security risk.

In a testing scenario, once a connection encounters this mismatch, all subsequent requests over that connection fail.

Additional Information

  • This issue commonly arises when a customer’s origins are configured to host multiple domains, where the Host header is used to route traffic accordingly. The SNI mismatch occurs because the SNI value does not align with the new Host header, impacting the handling of requests for different domains.
  • Setting SNI Selection to SNI Value will ensure that the SNI value always matches the Host header, preventing mismatches and connection failures when handling multiple domains.
