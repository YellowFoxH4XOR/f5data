Description

The vCMP feature allows you to provision and manage multiple instances of the BIG-IP software on a single hardware platform.

The vCMP system includes the following components:

  • vCMP host: the system-wide hypervisor that makes it possible for you to create BIG-IP instances, known as guests
  • vCMP guests: instances of the BIG-IP software that you create on the vCMP system for the purpose of processing application traffic

    Note: For security reasons, and to ensure that features such as VLAN failsafe operate as expected, communication between the vCMP host and vCMP guests over the data plane is not allowed.

The following describes communication allowed between the vCMP host and a vCMP guest and between two vCMP guests:

  • The vCMP host drops packets destined for its self IP address that originate from a vCMP guest.
  • The vCMP guest drops packets destined for its self IP address or local traffic object, such as a virtual server, that originate from the vCMP host.
  • The vCMP guest allows packets destined for its self IP address that originate from another vCMP guest, depending on the self IP Port Lockdown settings.
  • The vCMP guest allows packets destined for its local traffic objects, such as a virtual server, that originate from another vCMP guest.

For example, the following configuration shows a vCMP host (Host1) with a defined self IP address and two vCMP guests (Guest1 and Guest2) with defined self IP addresses and virtual servers:

Host1
net self ext {
    address 192.0.2.1/24
    allow-service default
    traffic-group traffic-group-local-only
    vlan internal
}

Guest1
net self int {
    address 192.0.2.10/24
    allow-service default
    traffic-group traffic-group-local-only
    vlan internal
}
ltm virtual G1_virtualserver {
    destination 192.0.2.100:http
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        http { }
        tcp { }
    }

Guest2
net self int {
    address 192.0.2.20/24
    allow-service default
    traffic-group traffic-group-local-only
    vlan internal
}
ltm virtual G2_virtualserver {
    destination 192.0.2.200:http
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        http { }
        tcp { }
    }
