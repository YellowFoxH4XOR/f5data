Topic

You should consider using this procedure under the following conditions:

  • Clients accessing your web application send GZIP-encoded content in HTTP requests.
  • You want to decompress the content in the request to allow inspection by the BIG-IP ASM system.

Description

Clients send requests with compressed web application data to the BIG-IP ASM system. For example, the client can send GZIP-encoded content in the body of a POST request.

By default, the BIG-IP ASM system does not decompress the request. In order for the BIG-IP ASM system to parse the compressed content and prevent false positive violations, local traffic policies or an iRules command must decompress the content. If a request matches the specified conditions, the BIG-IP ASM system decompresses the content, applies the security policy, and proxies the decompressed request to the server.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You configured a virtual server with an HTTP profile.
  • You configured an ASM security policy and associated it with the virtual server.
  • You have administrative access to the BIG-IP Configuration utility.

Procedures

  • Assigning an HTTP compression profile to the virtual server
  • Configuring the BIG-IP ASM system to decompress requests

Assigning an HTTP compression profile to the virtual server

In order for the BIG-IP system to decompress data, you must assign an HTTP compression profile to the virtual server handling the BIG-IP ASM traffic. To do so, perform the following procedure:

Note: By default, HTTP compression profiles compress data when the value of the Content-Type header in the server response is one of the following:

  • application/xml.
  • application/x-javascript.
  • Begins with text/.

Impact of procedure: When you enable compression or decompression, you may increase CPU usage and impact performance. Test to ensure your web application functions properly after performing this procedure.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click the name of the virtual server that is associated with your ASM security policy.
  4. Under Acceleration, in the HTTP Compression Profile list, click an available profile. 
  5. Click Update.

Configuring the BIG-IP ASM system to decompress requests

You can configure the BIG-IP ASM system to decompress request content using either the Configuration utility or an iRules command. To do so, perform one of the following procedures:

  • Decompressing requests using the Configuration utility
  • Decompressing requests using an iRule

Decompressing requests using the Configuration utility

You can configure local traffic polices to decompress requests based on conditions you specify.  For example, you can configure a local traffic policy to decompress a request when the Content-Encoding header contains the string gzip. To do so, perform the following procedure:

Impact of procedure: When you enable compression or decompression, you may increase CPU usage and impact performance. Test to ensure your web application functions properly after performing this procedure.

BIG-IP 12.1.0 and later

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Policies > Policy List.
  3. Click Create.
  4. Under General Properties, in the Policy Name box, type a name for the policy.
  5. In the Strategy section, in the Execute list, click first.
  6. Click Create Policy.
  7. Under Rules, click Create.
  8. In the Name box, type a name for your rule.
  9. Under Match all of the following conditions, click the Expand (+) button.
  10. In the first list, click HTTP Header.
  11. In the named box, type Content-Encoding.
  12. In the next list, click contains.
  13. In the next list, click any of.
  14. In the box next to the Add button, type gzip, and then click Add.
  15. In the last list, click request.

    The resulting condition should appear similar to the following example:

    HTTP Header named Content-Encoding contains any of gzip at request time.

  16. In the same section, click the Expand (+) button again.
  17. In the first list, click CPU Usage.
  18. In the next list, click 1 minute.
  19. In the next list, click less than or equal to.
  20. In the next list, click any of.
  21. In the box next to the Add button, type 5, and then click Add.
  22. In the last list, click request.

    The resulting condition should appear similar to the following example:

    CPU Usage in the last 1 minute less than or equal to any of 5 at request time.

  23. Under Do the following when the traffic is matched, click the Expand (+) button
  24. In the first list, click Enable.
  25. In the next list, click decompression.
  26. In the last list, click request.

    The resulting action should appear similar to the following example:

    Enable decompression at request time.

  27. Click Save.

    The Draft Policy screen displays.

  28. To save the new rule and policy, under General Properties, click Save Draft.

    To save the rule and policy for immediate use, in the Save Draft list, click Save and Publish Policy.

  29. Navigate to Local Traffic > Virtual Servers.
  30. Select the virtual sever that is associated with your ASM security policy.
  31. In the row for for the virtual server with the security policy, in the Resources column, click Edit.
  32. Under Policies, click Manage.
  33. In the Available list, click the local traffic policy you just created, and the click the Move left (<<) button.
  34. Click Finished. 

BIG-IP 12.0.0 and prior

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Policies > Policy List.
  3. Click Create.
  4. Under General Properties, in the Name box, type a name for the policy.
  5. In the Strategy list, click first-match.
  6. In the Requires section, in the Available list, click http, and then click the Move left (<<) button.
  7. In the Controls section, in the Available list, click compression, and then click the Move left (<<) button.
  8. Under Rules, click Add.

    The New Rule page displays.

  9. Under General Properties, in the Rule Name section, type a name for the rule.
  10. Under Rule Properties, in the Conditions section, click the following selections for the noted lists:
    • Operand: http-header
    • Event: request*
    • Selector: all
    • Under Parameters:
      • Name: name*.
      • Value: type Content-Encoding, and then click Add.
    • Condition: contains
    • Under Values:
      • Value: type gzip, and then click Add.
  11. Above the table, click Add to add your settings to it.
  12. In the Actions section, click the following selections in the noted lists:
    • Target: decompress
    • Event: request*
    • Action: enable
  13. Above the table, click Add to add your settings to it.
  14. Click Finished to save the rule and policy.
  15. Navigate to Local Traffic > Virtual Servers.
  16. Select the virtual sever that is associated with your ASM security policy.
  17. In the row for the virtual server with the security policy, in the Resources column, click Edit.
  18. Under Policies, click Manage.
  19. In the Available list, click the local traffic policy you just created, and then click the Move left (<<) button.
  20. Click Finished. 

Decompressing requests using an iRule

You can create an iRules command to decompress requests using the DECOMPRESS:: enable request command. The BIG-IP ASM system decompresses content in the request based on conditions you specify in the iRules command. For example, you can configure the iRules command to decompress the request when the HTTP Content-Encoding header in the request contains the string gzip. To do so, perform the following procedure:

Impact of procedure: When you enable compression or decompression, you may increase CPU usage and impact performance. Test to ensure your web application functions properly after performing this procedure.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the setting.
  5. In the Definition section, type the following code:

    when HTTP_REQUEST {
       if { [HTTP::header "Content-Encoding"] contains "gzip"} {
          DECOMPRESS::enable request
          log local0. "Decompressing request."
       }
    }
     
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Select the virtual sever that is associated with your ASM security policy.
  9. In the row for the virtual server with the security policy, in the Resources column, click Edit.
  10. Under iRules, click Manage.
  11. In the Available list, click the iRule you just created, and then click the Move left (<<) button.
  12. Click Finished.
