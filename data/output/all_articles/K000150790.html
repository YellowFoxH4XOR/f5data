Description

zrd will fail to start after upgrade, if rndc-key defined in named.conf does not match with the rndc-key algorithm and secret defined in /var/named/config/rndc.key file.

The following error is seen;

/var/log/daemon.log
err named[27141]: 08-Apr-2025 01:58:18.590 general: error: invalid command from 127.0.0.1#41641: bad auth

or

warning named[9047]: /config/named.conf:5: couldn't install keys for command channel 127.0.0.1#953: file not found

/var/log/gtm
notice zrd.wait.for.tmm.device[27375]: checking if ip device 'tmm' is ready...
bigip notice zrd.wait.for.tmm.device[27377]: ip device 'tmm' is ready after 0 seconds.

Environment

BIG-IP DNS upgrade

Cause

zrd depends on /var/named/config/rndc.key file. The rdnc-key in /var/named/config/rndc.key is regenerated upon BIG-IP DNS upgrade. The rndc-key algorithm and secret will mismatch if rndc-key is defined in /var/named/config/named.conf, so rndc authorization fails because zrd and named refers to different rndc-key.

Recommended Actions

Update /var/named/config/named.conf, so that rndc-key matches with /var/named/config/rndc.key.

The example /var/named/config/named.conf is following;

key "rndc-key" {
    algorithm hmac-sha256;
    secret "BUc0+FRZyxkbiNF0DzPvNWrMQJ4yAOTD3y08cTmkTA0=";
};

controls {
    inet 127.0.0.1 port 953 allow {
        127.0.0.1;
    }
    keys {
        rndc-key;
    };
};

The algorithm and secret in the key "rndc-key" definition needs to match with the info in the /var/named/confgi/rndc.key file.

# cat /var/named/config/rndc.key
key "rndc-key" {
        algorithm hmac-sha256;
        secret "BUc0+FRZyxkbiNF0DzPvNWrMQJ4yAOTD3y08cTmkTA0=";
};

If /var/named/config/rndc.key does not exist, recreate it as outlined in the following section.

  • If the rndc.key file is missing, the ZRD daemon will be down as it relies on this key for operation.
  • The absence of rndc.key can lead to failures in creating the key, causing the daemon to wait indefinitely for the key creation.
  • To resolve this, you can manually create the rndc.key file using the rndc-confgen command.
  • Follow these steps:
    • Stop the ZRD daemon: bigstart stop zrd
    • Remove any existing rndc.key: rm -f /config/rndc.key
    • Generate a new rndc.key: /usr/sbin/rndc-confgen -t /var/named -a -c /config/rndc.key
    • Create a symbolic link: ln -sf /var/named/config/rndc.key /config/rndc.key
    • Change ownership: chown -f named:named /var/named/config/rndc.key
    • Start the ZRD daemon: bigstart start zrd
  • Ensure that the generated rndc.key matches the configuration in /var/named/config/named.conf to avoid authorization issues.
