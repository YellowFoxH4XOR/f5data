Known Issue

This is the result of a known issue. A file-placement rule may fail during a volume scan if a higher-priority rule with the no volume-scan option enabled matches any of the same files or directories as the lower-priority rule.

When this issue occurs, an error message similar to the following example is logged to the ARX syslog:

2010-02-06T12:42:46.841+0000:tvparx01:2-2-ASM-2099:POLICY_PEP-1-NOTE-RULE_RESCAN_FAILED:: Rule
[ExampleCo:/data:Example-Place-Rule]: Rescan of directory '/data/' in volume 'ExampleCo:/data' failed: No rules were interested in continuing the tree walk.

F5 Product Development tracked this issue as ARX ID 37823 and it was fixed in ARX 5.1.5. For information about upgrading, refer to the ARX Release Notes.

Workaround

You can work around this issue by using the policy order-rule command to change the priority of the policy rules. For example, if the affected rule was named volscan and the higher priority rule was named novolscan, you could run:

policy order-rule volscan before novolscan

As an alternative, you can work around this issue by enabling the volume-scan option on the higher priority rule.

Note: For more information about the policy order-rule and volume-scan commands, refer to the ARX CLI Reference Guide.
