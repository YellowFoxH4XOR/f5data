Description

Similarily to K84260240: Windows Endpoint checks fail with errors ''Access Denied'' after products upgraded

The users accessing the VPN with a browser also need to be running the 'Inspector Service' even though they don't use the Edge Client.

Environment

  • Browser based Network Access VPN 
  • Microsoft Windows
  • BIG-IP APM with configured Access Policy using Endpoint Inspection (version 13.1 onwards)
  • Inspector Service (an optional Component install) is not running

Cause

Some AV products have started to require Privilege escalation to Check Last Scan date and other state information. On Microsoft Windows this is done by an optional component "Inspector Service" that may not be installed or running.

Recommended Actions

Ideally, web users should install a package (with 'run as administrator') with following services selected in the customized windows client package:

  • Inspector Service (that would help with detecting AV/FW,.. that requires admin privileges)
  • Component Installer Service (that would help updating & installing the below client side components for users without admin rights)
  • Endpoint Security
  • Web Browser Add-ons for BIG-IP Edge Client

Additional Information

The following Windows products (for each SDK method) are known to be affected at the time of publication:

  • GetLastScanTime: Windows Defender, BitDefender, Acronis Cyber Protection Agent
  • GetRealTimeProtectionState: ESET File Security for Microsoft Windows Server
  • GetDefinitionState: FireEye Endpoint Agent
  • GetFirewallState: AVG Internet Security, AhnLab V3 Internet Security

If you have no way to distribute an installation package to such web based VPN users, then an admin can create it, store it via hosted content (see link below) and then reference it to end users via a link in the VPE (e.g. in the fallback branch of the AV check) or via email.
