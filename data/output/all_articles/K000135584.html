K000135584: Simplified step-by-step method for decrypting TLSv1.0-v1.2 traffic using SSL::sessionsecret irule

Type
Support Solution
Published
2023-08-07
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K000135584

Description

This is a step-by-step method for how to decrypt TLSv1.0 v1.1 and v.1.2 traffic for one of your services hosted in a Virtual Server using an irule, that has been extracted from the following article:

K12783074: Decrypting SSL traffic using the SSL::sessionsecret iRules command (12.x and later)

It can be useful in situations when you  are troubleshooting an ongoing issue and need to analyze the traffic flow on the client and server side or if Support requests to reproduce the issue for analysis.

Environment

  • Encryption on the Client side with SSL Client Profiles.
  • TLSv.1.0, TLSv.1.1 or TLSv.1.2
  • You want to decrypt the traffic flow between the client and BIG-IP.
  • You need to have a client available for testing the application/website.
Note: Please be aware that the decryption of TLSv.1.3 traffic is not supported using this method. In this case, please refer to: K36120659: Decrypt TLSv1.3 traffic on BIG-IP.

Cause

None.

Recommended Actions

  1. Close all the browser tabs/windows using the affected application/website from the testing client.
  2. Create an iRule on BIG-IP with the following syntax and attach it to the Virtual Server in scope. You need to change <client_IP_addr> for the IP address used by the client to connect to the Virtual Server:
when CLIENTSSL_HANDSHAKE {
  if { [IP::addr [getfield [IP::client_addr] "%" 1] equals <client_IP_addr>] } {
    log local0. "[TCP::client_port] :: RSA Session-ID:[SSL::sessionid] Master-Key:[SSL::sessionsecret]"
  }
}

       3. Run a packet capture on BIG-IP. Please substitute <client_IP_addr> for the IP address used by the client to connect to the Virtual Server as well:
           tcpdump -nnvi 0.0:nnnp -s0 host <client_IP_addr> -w /var/tmp/<case_number>_$(date +%d_%b_%H_%M_%S)_$HOSTNAME.pcap
       4. Reproduce the problem once from the client.
       5. If you see the problem, kill the tcpdump with 'ctrl+c'.
       6. After terminating tcpdump, on the BIG-IP command line, type the following command:
           sed -e 's/^.*\(RSA Session-ID\)/\1/;tx;d;:x' /var/log/ltm > /var/tmp/sessionsecrets.pms
       7. Remove the iRule from your Virtual Server.
       8. Generate a qkview file.
       9. Provide packet capture, session secret, and qkview file to F5 Networks Support.
