Support Solution: Unable to Policy Sync error: "01070712:3: file:(/Common/example.certificate.crt) cannot update (fingerprint)"

Description

You are encountering an error message during the synchronization of the "apm-policy" policy between devices in your sync group. The error message "01070712:3: file:(/Common/example.certificat.crt) cannot update (fingerprint)" typically indicates that a required certificate or key file is either missing or corrupt on one or more devices in the sync group.

Symptoms:

  • Error message displayed: "01070712:3: file:(/Common/example.certificate.crt) cannot update (fingerprint)"
  • "apm-policy" configuration sync fails
  • Potential impact on policy functionality or traffic processing

 

Important: This Knowledge article can only be used as a temporary workaround when employed in the context of APM Policy Sync with JWK automation as this is not a supported configuration.

 

Environment

  • BIG-IP systems configured in a sync-failover device group
  • APM (Access Policy Manager) policies are being synchronized
  • Error occurs during device synchronization
  • Certificate or key files are associated with the "apm-policy"
  • Potential object corruption or missing files on one or more devices

Cause

  • The certificate or key file associated with the "apm-policy" is corrupt, missing, or mismatched between devices in the sync group
  • The fingerprints of the certificates do not match across the devices

Recommended Actions

To resolve this issue, perform the following steps:

  1. On the device where the "apm-policy" was originally configured, verify the certificate and key file presence and integrity:
tmsh show sys file ssl-cert /Common/example.certificate.crt
  1. Check the fingerprints of the certificate on this device using the following command:
tmsh show sys file ssl-cert
  1. On the other devices in the sync group, verify whether the certificate and key file exist with the same name:
    • If the certificate is missing, manually import the certificate and key file to the missing devices with the same name:
  2. Export the certificate and key files from the source device:
tmsh save sys file ssl-cert /path/to/certificate.crt
tmsh save sys file ssl-key /path/to/private.key
  1. Import the files to the other devices:
tmsh install sys file ssl-cert /path/to/certificate.crt
tmsh install sys file ssl-key /path/to/private.key
  1. If the certificate does exist on the devices but the synchronization still fails, check the fingerprints of the certificate on all devices using the "show sys file ssl-cert" command:
tmsh show sys file ssl-cert
  1. If fingerprints do not match, replace the certificate with a consistent one on all devices, ensuring the fingerprints are identical.
  2. Once the certificates are consistent across all devices, attempt to synchronize the policy again.

Additional Information

  • Ensure all certificate and key files related to policies or synchronization are consistent across the devices in the sync group.
  • To prevent fingerprint mismatches, avoid modifying certificates or key files directly on individual devices within the sync group.
