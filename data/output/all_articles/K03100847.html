Issue

RDP (VDI) connections fail with DNS errors on both the Client and in the APM logs.

  • You observe the following error messages in /var/log/apm. Note the SessionID is the unique APM session identifier or cookie:
noticevdi[17080]: 019cffff:5: /<partition>/<access policy name>:Common:<sessionid>: {3228.C} Failed to connect to RDG target <RDP Resource hostname>:3389: asio.netdb:1: Host not found (authoritative)

debug vdi[17080]: 019cffff:7: /<partition>/<access policy name>:Common:<sessionid>: {3228.C} Can't resolve '<RDP Resource hostname>' as IPv4: Temporary failure in name resolution
  • You observe the follow error on the Client: 
Remote Desktop can't find the computer [hostname]. This might mean that [hostname] does not belong to the specified network


Description

If a connection is attempted for a VDI resource before the system DNS is configured, the VDI process will cache the empty DNS configuration. Any attempt to use this VDI thread will fail until the VDI process is restarted. Additionally, if the system DNS configuration is modified, the VDI threads will not update the cached DNS configuration and will continue to use the previous DNS servers until the VDI process is restarted.


Environment

  • Access Policy Manager (APM)

  • Remote Desktop object configuration(s) (RDP, Citrix, VMWare)


Cause

Prior to version 14.1 DNS configuration for the VDI process did not automatically update when the Big-IP system DNS configuration changed. This means that if a connection is attempted for a VDI resource before the system DNS is configured, the VDI process will cache the empty DNS configuration. Any attempt to use this VDI thread will fail until the VDI process is restarted. Additionally, if the system DNS configuration is modified, the VDI threads will not update the cached DNS configuration and will continue to use the previous DNS servers until the VDI process is restarted.


Recommended Actions

To correct this issue you need to configure or modify the Big-IP DNS configuration and then restart the VDI service.
 

Correct the Big-IP DNS configuration:

1. Login to the Big-IP Admin GUI.
2. Navigate to System>Configuration>Device>DNS.
3. Enter the correct DNS server IP Address in the "DNS Lookup Server List" field.
4. Click Update.

Restart the VDI process:

1. Login to the Big-IP command line.
2. Run the following tmsh command:

tmsh restart sys service vdi
