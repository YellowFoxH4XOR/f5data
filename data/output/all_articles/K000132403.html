K000132403: Pool members go down (blue square on GUI), and reason is "Pool member service checking is enabled, but result is not available yet" forever.

Type
Support Solution
Published
2023-02-03
Updated
2025-04-02
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000132403

Description

All/some of health monitor status gone blue square, bigd was restarted, no change

When you run the below command, Availablity is unknown, state is enabled, and Reason is the below reasons .

 

tmsh show ltm pool member

 

--------------------------------------------------------------------

Ltm::Pool: <Pool_Name>

---------------------------------------------------------------------

Status

Availability : unknown

State : enabled

Reason : The children pool member(s) either don't have service checking enabled, or service check results are not available yet

Monitor : tcp

...

  --------------------------------------------------------------

  | Ltm::Pool Member: <Pool_Member_Name>:<Port>

  --------------------------------------------------------------

  | Status

  |   Availability   : unknown

  |   State          : enabled

  |   Reason         : Pool member service checking is enabled, but result is not available yet

  |   Monitor Status : checking

  |   Session Status : enabled

 

ping, telnet, curl works to those pool members.

/var/log/ltm has similar to the below log

err mcpd[<PID>] Caught configuration exception (0), Invalid monitor rule instance identifier: <#>

 

Environment

  • BIG-IP
  • versions: 17.0.0, 16.1.3, 16.1.2.2, 16.1.2.1, 15.1.8, 15.1.7, 15.1.6, 15.1.5.1, 14.1.5, 14.1.4.6, 14.1.4.5, 13.1.5
  • FQDN nodes exist on the configuration

Cause

  • Bug ID 1111473

Recommended Actions

Restart mcpd following workaround in Bug ID 1111473: restart mcpd with K13030: Forcing the mcpd process to reload the BIG-IP configuration

 

Additional Information

  • K000132198: mcpd[<PID>] Caught configuration exception (0), Invalid monitor rule instance identifier: <#>
