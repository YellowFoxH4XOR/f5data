K000162708: BIG-IP Edge Client stuck at "Initializing" after an in-place Windows 11 24H2/25H2 upgrade

Type
Support Solution
Published
2026-08-07
Updated
2026-08-07
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162708

Description

After an in-place Windows feature upgrade to 11 24H2/25H2, the BIG-IP Edge Client for Windows may remain stuck at "Initializing" and never establish the VPN tunnel. The client authenticates and downloads its configuration successfully, but the tunnel does not start.

CTU report shows a repeating failure at UTunnelX.cpp as shown below:

CUTunnelX::_startServer(), (0x80004002) EXCEPTION - cannot create instance

CUTunnelX::WorkerThreadProc() - EXCEPTION

CUTunnelX::get_isWaitUI, server not running. Return false

Environment

  • BIG-IP APM
  • BIG-IP Edge Client for Windows / F5 VPN client
  • Windows 11 24H2/25H2 (reached via in-place feature upgrade)

Cause

The in-place Windows upgrade corrupts or removes the COM (CLSID) registry mappings for TunnelServerX.dll, so the Edge Client cannot instantiate the local tunnel object and never leaves "Initializing".

Note: This is a client-side COM registration issue, independent of hardware model.

Answer/Recommended Actions

Re-register the tunnel component.

  1. In an elevated (Administrator) Command Prompt:

    cd "C:\Windows\Downloaded Program Files"

    regsvr32 TunnelServerX.dll

  2. Then repeat from the install directory:

    cd "C:\Program Files (x86)\F5 VPN"

    regsvr32 TunnelServerX.dll

  3. If there are leftover TunnelServerX.dll copies in C:\Windows\Downloaded Program Files, remove them first, or perform a clean reinstall of the Edge Client.
  4. Confirm the DllRegisterServer succeeded message, relaunch the Edge Client, and reconnect. Restart the client or Windows if required.

For large deployments, automate re-registration as a post-upgrade task and fall back to a clean reinstall where re-registration fails.
