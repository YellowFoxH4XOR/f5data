K000134905: Ingress gateways pods don't get ready after being rebooted

Type
Support Solution
Published
2023-06-05
Updated
2023-07-19
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000134905

Description

When dual-stack mode is enabled in Aspen Mesh 1.14.6-am2 and after installing Ingress gateway pods and executing a rolling reboot, pods will get stuck and won't get in READY state:

➜  aspenmesh-carrier-grade-1.14.6-am2 kubectl get pods -n istio-system
NAME                                    READY   STATUS    RESTARTS   AGE
istio-ingressgateway-7b84d87d4d-xj64m   0/1     Running   0          30s
istio-ingressgateway-7b84d87d4d-z948c   0/1     Running   0          45s
istiod-5bd4d9bb8b-2sxtb                 1/1     Running   0          42s
istiod-5bd4d9bb8b-tg5h6                 1/1     Running   0          57s

Environment

Aspen Mesh 1.14.6-am2

Cause

This is a bug and has been addressed in Aspen Mesh 1.14.6-am3.

Recommended Actions

Upgrade to Aspen Mesh 1.14.6-am3
Follow the "Perform an upgrade " instructions.

Additional Information

Expected behavior after upgrading to 1.14.6-am3. All ingress gateway pods should be in READY state: 
➜  aspenmesh-carrier-grade-1.14.6-am3 kubectl get pods -n istio-system
NAME                                    READY   STATUS    RESTARTS   AGE
istio-ingressgateway-574ccd5589-jkgks   1/1     Running   0          110s
istio-ingressgateway-574ccd5589-pddwj   1/1     Running   0          101s
istiod-5df54d8dff-bjmc8                 1/1     Running   0          5m32s
istiod-5df54d8dff-x6d2n                 1/1     Running   0          5m32s
