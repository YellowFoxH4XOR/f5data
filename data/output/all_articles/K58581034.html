K58581034: Bot defense blocks traffic with anomaly ''Invalid HTTP Headers Presence or Order''

Type
Support Solution
Published
2021-04-29
Updated
2023-02-21
Applies to
  • BIG-IP ASM: 16.X.X
Source
https://my.f5.com/manage/s/article/K58581034

Description

Bot defense blocks traffic with anomaly Invalid HTTP Headers Presence or Order.

Sample requests in bot defense logs show that the request uses HTTP/1.1 and header names are all lower case, similar to the following example:

GET /main/static/scripts.js HTTP/1.1
...
pragma: no-cache
cache-control: no-cache
sec-ch-ua: "Google Chrome";v="89", "Chromium";v="89", ";Not A Brand";v="99"
user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/89.0.4389.90 Safari/537.36
...

You may also observe that the request contains no Connection: keep-alive header.

Environment

  • Bot defense
  • Blocked requests

Cause

A HTTP/2 profile is applied, or a HTTP/2 proxy in front of the BIG-IP is converting the request to HTTP/1.1, retaining the lower case header names.

Browsers typically do not send header names starting with a lower case letter when using HTTP/1.1, they only do this when using HTTP/2.

When bot defense receives a HTTP/1.1 request, it expects to see header names starting with an upper case letter.

Recommended Actions

Enable the botdefense.support_http2_proxy database key to disable the bot defense test that determines whether the header names start with an upper case letter.

tmsh modify sys db botdefense.support_http2_proxy value enable

Note: This should not cause any impact to traffic.

Additional Information

Bot defense performs a number of different JavaScript-free tests by examining the HTTP request line and headers.
