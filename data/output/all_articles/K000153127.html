Description

Unusually high CPU usage may be observed on BIG-IP LTM devices, including those in standby mode. The restjavad process can consume excessive CPU resources (e.g., over 180%). System process listings and REST API logs indicate repeated activity related to device group synchronization and REST framework operations. No specific error messages are present, but overall system performance is degraded.

Environment

  • Restjavad
  • clear-rest-storage 
  • Using UCS file migration
  • Both active and standby devices can be affected

Cause

When migrating device configurations using UCS files across different hardware platforms or vCMP guests, the REST framework database may retain legacy or inconsistent data—such as serial number and device group information—from previous hardware. This can cause the restjavad process to enter an abnormal state, resulting in high CPU usage due to continuous internal synchronization attempts or database inconsistencies. The issue arises if the REST storage is not cleared and rebuilt after such migrations.

Recommended Actions

  1. Clear and Rebuild REST Storage:
    Run the following command on each affected device to clear and rebuild the REST framework database:
    clear-rest-storage
    Reference article for details: K67220984: Clear-rest-storage. What does it do?
  2. Verify REST Database Integrity & CPU Usage:
    After clearing the REST storage, verify that the database has been rebuilt correctly and that CPU usage has normalized by running.
    restcurl shared/device-availability
    restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices
  3. Best Practice for Migration:
    Always perform clear-rest-storage operation after migrating configurations with UCS files between different hardware platforms to prevent REST database inconsistencies and associated high CPU usage.
