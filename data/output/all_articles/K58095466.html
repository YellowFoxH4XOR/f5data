Source

Description

  • Azure Failover does not work after upgrade to BIG-IP VE
  • Error message: Error: getaddrinfo EAI_AGAIN login.microsoftonline.com:443

Environment

  • Upgrading from 13.1.0.2 to 13.1.1.2
  • Azure 
  • Failover Configured

Cause

Azure failover scripts are connecting to wrong API endpoints

Recommended Actions

Re-install cloud-libs using these steps

  1. Download these tarballs to current directory
    1. curl -O https://cdn.f5.com/product/cloudsolutions/f5-cloud-libs/v4.6.0/f5-cloud-libs.tar.gz
    2. curl -O https://cdn.f5.com/product/cloudsolutions/f5-cloud-libs-azure/v2.6.0/f5-cloud-libs-azure.tar.gz
  2. Set cloud libs install directory
    1. CLOUD_LIB_DIR=/config/cloud/azure/node_modules/@f5devcentral
  3. Create the cloud libs directory
    1. mkdir -p $CLOUD_LIB_DIR && cp f5-cloud-libs*.tar.gz* /config/cloud
  4. Create azure directory
    1. mkdir -p /var/log/cloud/azure
  5. Create bigip password file
    1. /usr/bin/install -m 400 /dev/null /config/cloud/.passwd
  6. Create credentials file
    1. /usr/bin/install -m 400 /dev/null /config/cloud/.azCredentials
  7. Create cloud libs install script
    1. /usr/bin/install -b -m 755 /dev/null /config/installCloudLibs.s  
  8. Create managed routes file for moving UDR next hop
    1. /usr/bin/install -b -m 755 /dev/null /config/cloud/managedRoutes
  9. Extract cloud libs 
    1. tar xfz /config/cloud/f5-cloud-libs.tar.gz --warning=no-unknown-keyword -C /config/cloud/azure/node_modules/@f5devcentral
    2. tar xfz /config/cloud/f5-cloud-libs-azure.tar.gz --warning=no-unknown-keyword -C /config/cloud/azure/node_modules/@f5devcentral
    3. touch /config/cloud/cloudLibsReady
  10. Source functions from cloud libs utils
    1. source $CLOUD_LIB_DIR/f5-cloud-libs/scripts/util.sh
  11. Save environment variable to json file:
    clientID: The service principal client ID parameter from the deployment
    tenantID: The service principal tenant ID parameter from the deployment
    secret: The service principal access secret parameter from the deployment
    subscriptionID: The Azure subscription ID
    storageAccount: The name of the Azure data storage account created with this deployment (should end in "data000")
    storageAccounKey: The API access key from the above storage account (might need to be regenerated in the portal UI)
    resourceGroupName: The name of the Azure resource group where this is deployed
    dnsLabel: The dnsLabel parameter value from the deployment
    location: The Azure region where this is running
    echo '{"clientId": "clientId", "tenantId": "tenantId", "secret": "servicePrincipalSecret", "subscriptionId": "subscriptionID", "storageAccount": "storageAccountName", "storageKey": "storageAccountAccessKey", "resourceGroupName": "resourceGroupName", "uniqueLabel": "dnsLabel", "location": "location"}' > creds.json
  12. Clear any previous failures
    rm /tmp/f5-cloud-libs-signals/*
  13. Encrypt credentials from json file
    /usr/bin/f5-rest-node /config/cloud/azure/node_modules/@f5devcentral/f5-cloud-libs/scripts/encryptDataToFile.js --symmetric --data-file creds.json --out-file /config/cloud/.azCredentials
  14. Dump saved credentials to check output
    /usr/bin/f5-rest-node /config/cloud/azure/node_modules/@f5devcentral/f5-cloud-libs/scripts/decryptDataFromFile.js --data-file /config/cloud/.azCredentials --symmetric
  15. Save bigip credentials to bigip password file
  16. This is the svc_usr password (copied from admin at deployment
    echo "myadminpassword" > pass
    /usr/bin/f5-rest-node /config/cloud/azure/node_modules/@f5devcentral/f5-cloud-libs/scripts/encryptDataToFile.js  --data-file pass --out-file /config/cloud/.passwd
  17. Verify saved password
    /usr/bin/f5-rest-node /config/cloud/azure/node_modules/@f5devcentral/f5-cloud-libs/scripts/decryptDataFromFile.js --data-file /config/cloud/.passwd 
  18. Only add failover provider call to failover scripts if it is not already there:
    cat /config/failover/tgactive
    echo "/usr/bin/f5-rest-node $CLOUD_LIB_DIR/f5-cloud-libs-azure/scripts/failoverProvider.js" >> /config/failover/tgactive
    echo "/usr/bin/f5-rest-node $CLOUD_LIB_DIR/f5-cloud-libs-azure/scripts/failoverProvider.js" >> /config/failover/tgrefresh
  19. Delete statusdb file in azure blob storage (if it exists) 
  20. When ready, execute failover

Additional Information

To determine the current available version of f5-cloud-libs and f5-cloud-libs-azure, go to:
https://github.com/F5Networks/f5-azure-arm-templates/blob/master/azure-bigip-version-matrix.md
Select the link to the release tag that includes your desired BIG-IP version.
Download the source code, unzip it, and find the location of the template that applies to your situation.
For example: C:\Users\User\Downloads\f5-azure-arm-templates-7.0.0.0\f5-azure-arm-templates-7.0.0.0\supported\failover\same-net\via-api\n-nic\existing-stack\byol
Locate azuredeploy.json and open the file.
Locate the current versions for "f5CloudLibsTag" and "f5CloudLibsAzureTag"
For example:
"f5CloudLibsTag": "v4.9.1",
"f5CloudLibsAzureTag": "v2.9.1",
and substitute the versions in the curl call:

curl -O https://cdn.f5.com/product/cloudsolutions/f5-cloud-libs/v4.9.1/f5-cloud-libs.tar.gz
?????curl -O https://cdn.f5.com/product/cloudsolutions/f5-cloud-libs-azure/v2.9.1/f5-cloud-libs-azure.tar.gz
