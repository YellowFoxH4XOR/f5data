Topic

A virtual server on the BIG-IP system processes client traffic to the destination. BIG-IP APM provides the ability to capture network access, portal access, and application access egress traffic using a layered virtual server matching the server-side destination address. You can use layered virtual severs in the following use cases:

  • Processing traffic to different backends
  • Applying different SNAT and route domain settings
  • Traffic inspection using iRules
  • Single sign-on (SSO) for web application
  • Secure Web Gateway (SWG)

Description

For server-side traffic, BIG-IP APM searches for virtual servers with a destination address matching the back-end address. If a match is found, the matching virtual server processes the traffic instead of forwarding it directly to the back-end address. This matching virtual server is referred to as a layered virtual server.

BIG-IP APM sets layered virtual server precedence according to the following criteria:

  • Network access: The layered virtual server with the closest destination match and enabled on the connectivity Virtual Local Area Network (VLAN) attached to the virtual server processing inbound traffic
  • Portal access: The layered virtual server with the closest destination match and enabled on the external VLAN of the virtual server processing inbound traffic
  • Application access:
    • Application tunnels: The layered virtual server with the closest destination match and enabled on either the external VLAN or the connectivity VLAN attached to the virtual server processing inbound traffic
    • Virtual Desktop Infrastructure (VDI): The layered virtual server with the closest destination match without any VLAN restriction1 

Scenarios

For example, you have configured the BIG-IP APM system with a client-side virtual server (MyVS0) with destination address 1.1.1.1:443 serving network access, portal access, and application access. The back-end server for all types of connections listens on 10.0.0.100:443.
