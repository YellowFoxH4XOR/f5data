K9521: Users are unable to install SSL Certificate when Private Key is not passphrase protected

Known Issue

This is the result of a known issue. The FirePass Controller requires that any Server SSL Certificate be imported using Private Keys which are encrypted with a passphrase. This is configured on the Device Management: Security: Certificates: Renew/Replace SSL Server Certificate: Install page. If a passphrase was not used when the Private Key was generated, you will receive an error message that appears similar to the following example:

"Your new certificate must be committed together with the corresponding private key and the password."

This is unexpected behavior. Private keys are not required to be passphrase protected and FirePass is incorrectly generating the error message.

F5 Product Development is tracking this issue as CR111580.

Workaround

Users can work around this issue by entering arbitrary characters in the password field for a private key created originally without a password.
