Description

High CPU utilization is observed on BIG-IP systems, primarily caused by the Java process (restjavad). The issue manifests with the following symptoms:

  • Elevated CPU usage (user space CPU consistently above 40-50%)
  • Java process is consuming excessive CPU resources, visible after issuing the top command
    Example: root    18413  7461 153.5  3.5  3.2G  1.1G ?    S  Jan13 223:25:33.77 /usr/lib/jvm/java-1.8.0-openjdk-1.8.0.212.b04-0.el6_10.x86_64/bin/java -Djava.util.logging.manager=com.f5.rest.common.RestLogMan
    Note 'x86_64' and 'RestLogMan'. tomcat Java command line is very similar but has 'i386'
  • Frequent "Full GC (Allocation Failure)" messages
  • Java is unable to allocate sufficient memory for operations
  • System performance degradation

Error messages observed in restjavad-gc.log:

[GC (Allocation Failure) 426637K->247532K(776064K), 0.XXXXXXX secs]

[Full GC (Allocation Failure) 594757K->163756K(776064K), X.XXXXXXX secs]

Environment

  • Product: BIG-IP LTM
  • Version: 16.X.X, 17.X.X, 21.X.X 

Cause

It's worth checking that ID 1826505 isn't a cause before trying anything else.

Insufficient memory allocation for Java processes (restjavad). The default memory settings are inadequate for the system's workload, causing frequent garbage collection cycles and high CPU utilization as Java struggles to allocate memory for operations. When the Java cannot allocate memory for new objects, it triggers garbage collection cycles to free memory, resulting in elevated CPU usage.
Note that garbage collection is a normal part of Java operation, and   'GC (Allocation Failure)'even as frequently as every few seconds is usually not an issue, as the CPU use for this base level of GC is very light. Full GC is much heavier in CPU use and should happen much less frequently, usually at least a few hours separating Full GC runs. 

Please note that while restjavad and tomcat are both processes that use a Java virtual machine, they are entirely separate.
Unless tomcat has issues there is no need to tamper with it when dealing with restjavad issues.
 

Recommended Actions

Important: The following commands will restart restjavad and tomcat services, which may cause a failover event in HA configurations and temporary GUI inaccessibility. Modifying provision.extramb restarts TMM and is traffic-impacting. Perform these changes during a scheduled maintenance window.

  1. Access the BIG-IP system via SSH and enter tmsh:
    tmsh
  2. Modify the database values to increase memory allocation:
    modify /sys db provision.extramb value 2000
    modify sys db provision.restjavad.extramb value 1000
    It's suggested to work upwards ~200MB at a time, so 600 would be a good choice if starting at default of 384.
  3. Restart the restjavad service:
    restart sys service restjavad
  4. Exit tmsh and switch to bash shell:
    exit
  5. Restart additional services from bash:
    bigstart restart restjavad restnoded
  6. Check restjavad startup message in /var/log/ltm. Monitor CPU utilization and garbage collection logs after the changes.
  7. If CPU remains high, incrementally increase provision.restjavad.extramb by 200 at a time:
    • Try 800 MB if 600 MB is insufficient
    • Try 1000 MB if 800 MB is insufficient
    • Restart services after each change
