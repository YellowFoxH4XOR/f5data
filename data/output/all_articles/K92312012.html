Known Issue

BIG-IP Virtual Edition (VE) may display the incorrect state of the network interface when using the ifconfig utility.

This issue occurs when all of the following conditions are met:

  • You disable a network interface on BIG-IP VE using the Traffic Management Shell (tmsh) or the Configuration utility.
  • You attempt to verify the state of the network interface on BIG-IP VE using the ifconfig utility.

On a BIG-IP system, the Traffic Manager Microkernel (TMM) service controls all system interfaces, except for the management (MGMT) interface. The TMM service supports all system and networking components that the BIG-IP system needs to process application and administrative traffic. You can query the state of the TMM interface using the tmsh utility, or you can use the ifconfig utility to query the Linux kernel for the state of the corresponding network interface.

The ifconfig utility performs query operations on the Linux kernel interfaces, not with TMM interfaces. Starting in BIG-IP 11.5.0, you can view the mapping of the TMM interface to the Linux kernel from the /etc/ethmap file to determine the correct network interface to specify in the ifconfig utility.

Important: The /etc/ethmap file is generated by the BIG-IP system automatically and should not be altered.

Impact

You are unable to determine the correct state of the network interface from the ifconfig utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the state of the network interface using the tmsh list net interface command, the command output appears similar to the following example:

    net interface 1.1 {
        disabled
        if-index 48
        mac-address 00:50:56:93:67:f7
        media-fixed 10000T-FD
        media-max 10000T-FD
    }

  • When viewing the state of the network interface using the ifconfig utility, the command output displays the network state as UP and no network traffic passes through the disabled interface as expected.

    The ifconfig utility may show an incorrect state of the network interface that appears similar to the following example:

    [root@bigip:Active:Standalone] config # ifconfig eth1
    eth1      Link encap:Ethernet  HWaddr 00:50:56:93:67:F7  
              inet6 addr: fe80::250:56ff:fe93:67f7/64 Scope:Link
              UP BROADCAST RUNNING PROMISC ALLMULTI MULTICAST  MTU:1500  Metric:1
              RX packets:31076714 errors:0 dropped:0 overruns:0 frame:0
              TX packets:7398 errors:0 dropped:0 overruns:0 carrier:0
              collisions:0 txqueuelen:1000
              RX bytes:7116240085 (6.6 GiB)  TX bytes:321542 (314.0 KiB)

Workaround

To work around this issue, you can verify the state of the network interface on BIG-IP VE using the tmsh utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Verify the state of the network interface on BIG-IP VE using the following command syntax:

    list /net interface <tmm_interface>

    For example, to verify the state of the TMM interface 1.1, type the following command:

    list /net interface 1.1
