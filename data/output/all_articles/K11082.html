K11082: An improper shutdown may result in a long delay while the /wam partition is checked for errors

Source

Topic

The BIG-IP WebAccelerator /wam partition uses the ext2 file system rather than ext3. The ext2 file system is not a journaled file system like ext3. Using ext2 reduces the file system overhead when caching objects to disk. The drawbacks to using ext2 is that the file system needs to be repaired after an improper shutdown and running a file system check (fsck) can take a long time.

The /wam partition is mounted as part of the comm_srv module process startup. The comm_srv module process must complete before the pvac process may start. An improper shutdown and subsequent fsck will delay the pvac process until the fsck process has completed the repair on the file system and the comm_srv has mounted the /wam partition and completed the startup process. During this time, BIG-IP WebAccelerator virtual servers will be unavailable and disrupt all WebAccelerator traffic.

Note: The system will appear operational while the fsck is checking the /wam partition for errors; however, the BIG-IP WebAccelerator will not process any traffic.

To prevent traffic disruption due to an improper shutdown, F5 Networks recommends configuring BIG-IP WebAccelerators in redundant pairs.

F5 Networks is tracking enhancement ID 224309 (formerly CR135393) to notify administrators that the BIG-IP WebAccelerator partition is currently being checked and to avoid rebooting the system.
