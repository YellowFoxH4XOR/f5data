Description
You have a multi SSO domain profile. The issue appears when they start a new APM session accessing a VS working with SAML SSO. The authentication on this application works fine but if they open the intranet VS (it has a Form Login SSO) a blank page appears. 

Environment

  • SAML IDP
  • BIG-IP APM  

Cause
The variable session.server.multidomain_landinguri is set incorrectly causing a series of rewrites.  

Recommended Actions

If an iRule is needed, then likely you need to create/update a session variable whenever F5Networks-SSO-Resp?SSO_ORIG_URI=*** request is redirected by APM to the former requested URL.
Something like this:

Note: This is given as an example. This should be tested before putting in production:

# START
when HTTP_REQUEST {
   set need_landing 0
   if { [HTTP::has_responded] } { return }
   if { [HTTP::uri] starts_with "/F5Networks-SSO-Resp?SSO_ORIG_URI=" } {
      #log local0. "URI internal= [HTTP::uri]"
      set need_landing 1
   }
}

when HTTP_RESPONSE_RELEASE {
   if { [info exists need_landing] && $need_landing == 1 } {
      if { [HTTP::status] == "302" && [HTTP::header exists Location] } {
         #log local0. "Location: [HTTP::header Location]"
         set loc [HTTP::header Location]
         set uri [regsub {https?://[^/]*/} $loc "/"]
         #log local0. "Location uri part: $uri"
         # we could modify this existing variable or pick a custom new one and then use it in form based sso profiles
         ACCESS::session data set session.server.multidomain_landinguri $uri
      }
   }
}
# END

Similar iRule would need to be attached to any VS participating in the multidomain SSO configuration AND where form based SSO is making use of session.server.multidomain_landinguri.
