Known Issue

The BIG-IP system may experience memory exhaustion when SQL monitors are in use.

This issue occurs when the following condition is met:

  • One of the SQL monitor types is assigned to a pool or pool member.

Impact

The BIG-IP system experiences memory exhaustion and performance issues.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system experiences memory exhaustion.
  • The BIG-IP system logs an error message to the /var/log/tmm file that appears similar to the following example:

    System posts message: notice panic: FATAL: mmap of: /dev/mprov/tmm/tmm.4 length 1480589312 offset 4441767936 failed 12 (Cannot allocate memory).

Workaround

To work around this issue, you can restart system services. To do so, perform the following procedure:

Impact of workaround: Restarting system services interrupts traffic processing; you should perform this task during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    bigstart restart
