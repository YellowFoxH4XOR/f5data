Known Issue

This is the result of a known issue. If the BIG-IP ASM processes a POST nearly 10KB in size, and the clientside integrity test causes the size of the request to increase beyond 10KB, the BIG-IP ASM system may experience memory corruption and dump core. When this issue occurs, error messages that appear similar to the following example may log to the /var/log/asm file:

emerg dcc[8835]: 01310003:0: ASM out of memory error: event code F75
crit perl[8908]: 01310027:2: ASM subsystem error (nwd.pl,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).
crit perl[16174]: 01310027:2: ASM subsystem error (exec_core.pl,main::add_ts_log_line): ASM core restarted for recovery purposes

Note: Clientside integrity is activated when Web Scraping is enabled, or when the system detects a Denial of Service (DoS) attack or brute force login attack.

F5 Product Development tracked this issue as ID 226625, ID 335466, ID 330928, ID 328338, and ID 324375 (formerly CR141862) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.

This issue has been fixed in Hotfix-BIGIP-10.1.0-3399.0-HF2 for BIG-IP 10.1.0, and in Hotfix-BIGIP-10.2.0-1744.0-HF1 for BIG-IP 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
