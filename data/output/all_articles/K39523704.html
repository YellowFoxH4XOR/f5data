Environment

  • Upgrade LTM to 14.1.x
  • Configured Database monitor  ( POSTGRESQL Monitor)
  • Monitor applied on Vertica Database pool

Cause

Change in behavior of monitor

Recommended Actions

  1. Configure External Monitor:
  • Create a file such as below (e.g. via notepad++) and upload it to the BIG-IP on GUI > System > File Management > External Monitor Program File List
    #!/bin/bash
    pidfile="/var/run/$MONITOR_NAME.$1..$2.pid"
    if [ -f $pidfile
    then
    kill -9 -`cat $pidfile` > /dev/null 2>&1
    fi
    echo "$$" > $pidfile
    node_ip=`echo $1 | sed 's/::ffff://'`
    psql -h $node_ip -p $2 -U test_user -d test_database -c "SELECT * FROM products" | grep "Cheese" 2>&1 > /dev/null
    status=$?
    if [ $status -eq 0 ]
    then
        rm -f $pidfile
        echo "up"
    fi
    rm -f $pidfile
    Please note that you need to change some parameters above to match the environment.  Refer to the line that starts with "psql".  The above is an example taken from LAB.  You need to modify:
    -U stands for username
    -d stands for database
    -c is for the query being made Cheese is the response expected
  • Create a file called .pgpass on /root/ directory and modify it as necessary.
    [root@test-1-bigip:Active:Standalone] ~ # cat root/.pgpass
    10.0.1.110:5432:test_database:test_user:default
    10.0.1.110 is the IP of my PostgreSQL server
    test_database is the name of the database
    test_user is the usernamedefault is the password
  • Modify file permissions:
    # chmod 0600 /root/.pgpass
    It should then read like this:
    # ls -lh /root/.pgpass
    -rw-------. 1 root root 51 Nov 10 04:19 /root/.pgpass
  • create the external monitor:
    ltm monitor external external_postgresql {
        defaults-from external
        destination *:*
        interval 10
        run /Common/external_postgresql    <--------- this is the file uploaded in the beginning
        time-until-up 0
        timeout 31
    }
  • attach the monitor to the desired pool
