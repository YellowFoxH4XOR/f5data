Description

When viewing the ASM Event Logs in the GUI with certain users, the following error message appears:

Failed to load saved filters

After the filter is deleted, the following error may also appear:

Failed to load requests

Furthermore, you may see 401 messages in /var/log/restjavad-audit.0.log, similar to the following example:

[ForwarderPassThroughWorker] {"user":"tmos/f5-admin","method":"GET","uri":"http://localhost:8100/mgmt/tm/asm/policies?$filter=type+eq+%27security%27&$orderby=fullPath&$select=id,name,fullPath,hasParent","status":401,"from":"10.10.10.1"}

Environment

  • After upgrade
  • ASM request logs

Cause

Bug ID 718796: IControl REST token issue after upgrade

Recommended Actions

  1. Delete the state maintained by iControlRoleMigrationWorker: restcurl -X DELETE "shared/storage?key=shared/authz/icontrol-role-migrator"
  2. Restart the services: tmsh restart /sys service restjavad
  3. After performing the recommended actions logout from from GUI and login again.
  4. If this still does not resolve the issue you can update shared/authz/roles/iControl_REST_API_User userReference list to add all affected users' accounts using PUT. Here you may need to use the UUID path...
    1. Run below API for the impacted user account: curl -ik -u username:XYZ -XPOST https://localhost/mgmt/shared/authn/login --data-binary '{"username":"XYZ", "password":"XYZpass", "loginProviderName":"tmos"}' -H "Content-Type: application/json"
      1. Replace XYZ with the username.
    2. Find the username 'link' path under 'token' in the previous output.
      1. There are two possible formats for the 'link'...
        1. Path will have an UUID. For example "token"->"link"->"https://localhost/mgmt/cm/system/authn/providers/tmos/1f44a60e-11a7-3c51-a49f-82983026b41b/users/<UUID>"
        2. Path will have a username (not a UUID). For example "token"->"link"->"https://localhost/mgmt/shared/authz/users/<username>"
          1. <username> being the applicable user.
    3. Run the below API to get a list of user roles... # restcurl -u "admin:<admin-user-pass>" /shared/authz/roles | tee /var/tmp/rest_shared_authz_roles.json
      1. <admin-user-pass> being the applicable user password.
    4. Check the user's link path from step 2 in the above output. Note:Check under the "userReferences" section for group "iControl_REST_API_User" . You will see the link path in one of the two formats listed in 2.1.1/2.1.2. If you do not see the user link path then you are impacted by this bug
  5. Once you have the UUID:
    1. # restcurl shared/authz/roles/iControl_REST_API_User > role.json
    2. # vim role.json
      1. add { "link": "https://localhost/mgmt/shared/authz/users/[your-user-name]" } object to userReferences list
      2. Or this: add { "link": "https://localhost/mgmt/cm/system/authn/providers/tmos/1f44a60e-11a7-3c51-a49f-82983026b41b/users/<UUID>" } object to userReferences list
    3. curl -u admin:admin -X PUT -d@role.json http://localhost/mgmt/shared/authz/roles/iControl_REST_API_User

Additional Information

Other areas of the GUI may also be affected when this issue occurs.
