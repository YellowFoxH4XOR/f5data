Description

If the /shared directory on the BIG-IP system is nearly full, the following alert is generated on the CLI or in /var/log/ltm:

err diskmonitor[<PID>]: 011d0004:3: Disk partition /shared has only x% free

 

Environment

  • BIG-IP 
  • disk usage
  • /shared

 

Cause

If the shared disk partition (logical volume) 99% usage threshold is reached, an alert is generated to inform you about the usage of the partition. 

alert - Disk partition /shared has only 1% free

 

Recommended Actions

  1. To view disk space usage, log in to the BIG-IP CLI with administrative credentials and run the command:

    df -h

  2. To find large files taking up space in the /shared directory, execute the following command:

    find /shared/ -xdev -type f -exec du {} \; | sort -rn | head -20

  3. Examine the previous output and determine which of the large files are unneeded. Delete these files using the following command syntax:

    rm <full_path/filename>

There is further troubleshooting in

  • K14403: Maintaining disk space on the BIG-IP system

 

Additional Information

F5 recommends that you delete the old image files (.iso) or pcap files (.pcap) you no longer need in /shared/images or /shared/tmp, this will free up space in the /shared directory. 

  • K38276507: /shared/tmp having disk space full message due to many /var/tmp/imXXX files


If you have old version of EPSEC kept in the BIG-IP, this cause the UCS file size large, and will impact the disc space, if UCS size is large and causing space issue for /var partition. Please clean up the old EPSEC files on the Active unit.

  • K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system
  • K000133778: Unable to delete Epsec Packages from GUI or CLI after removing them manually
