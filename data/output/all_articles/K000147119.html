K000147119: Why are my WAAP policies not blocking SQL injection in some cases?

Type
Support Solution
Published
2024-11-08
Updated
2025-02-19
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Apps
  • F5 Distributed Cloud Multi-Cloud App Connect
Source
https://my.f5.com/manage/s/article/K000147119

Description

  • Sometimes WAAP policies are not able to block some SQL injections.
    • The payload admin' or 1 =1 -- is getting blocked.
    • However if I modify the payload to admin' or true --  I get through it and it is not detected as SQL injection.
  • How can I make sure my WAAP policies are blocking SQL injections?

Environment

  • F5® Distributed Cloud Console

Answer/Recommended Actions

  • A single high accuracy attack signature is triggering on it, but the AI/ML model "auto-suppresses " that signature.
  • According to research team " or true --"  is part of the English language and we can't create high accuracy signature from it.
  • The solution to resolve this problem is to disable the "Automatic attack signatures tuning" feature in App firewall policy.

Steps to disable "Automatic Attack Signatures Tuning"

1. Log in to your account (Distributed Cloud Console).

2. Navigate to Manage -> App Firewall

 

3. Select the App Firewall you would like to change, click on 3 dots on right hand side under Actions section and click on Manage Configuration.

4. Click on Edit Configuration as shown in the screenshot below:

 

5. Scroll to Automatic Attack Signatures Tuning option

6. Select Disable

7. Click on Save and Exit button at the bottom right corner.
