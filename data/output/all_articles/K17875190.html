Known Issue

Responses for small BIG-IP AAM accelerated objects may stall.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with a BIG-IP AAM acceleration policy.
  • The acceleration policy is configured to perform an assembly function, and the Cache on first hit option is enabled.
  • The virtual server processes a request that matches a node in the BIG-IP AAM acceleration policy that performs a content assembly function for the response.
  • The original object (response from OWS) is smaller than the Small Object Cache size limit (4kb), but becomes larger than the Small Object Cache size limit once the BIG-IP AAM assembly has occurred.

    Note: Cached objects larger than 4 KB are stored in the BIG-IP AAM system's Datastor/Metastor. However, cached objects that are smaller than 4 KB in size are stored in a Small Object Cache in memory. This 4 KB Small Object Cache size limit is not configurable.

During the assembly of a response from the OWS, the BIG-IP AAM assembler functions may cause the response to increase in size. On rare conditions, this size increase pushes the response size over the small object cache limit and changes where the system caches the response. When this occurs, the assembly of the response may stall waiting on an operation that has already occurred.

Impact

Client requests for affected BIG-IP AAM accelerated objects fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client requests for affected AAM accelerated objects fail to render or experience timeouts.

Workaround

To work around this issue, you can configure the BIG-IP AAM acceleration policy to always proxy requests for the node of the affected object. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to the Acceleration > Web Application > Policies page.
  3. Select the affected Acceleration policy.

    The selected Acceleration policy will be opened in the Policy Editor.

  4. From the Matching Rules menu, select Acceleration Rules.
  5. Select the Proxying tab.
  6. In the Site tree of the Policy Editor, navigate to and select the affected node.
  7. In the Proxying Options section, select the Always proxy requests for this node option.
  8. Click Save.
  9. Click Publish.
  10. Click Publish Now.
