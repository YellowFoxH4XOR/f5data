Topic

You should consider using this procedure under the following condition:

  • You want to create a high availability (HA) configuration between BIG-IP Next tenant instances running on two F5 VELOS systems. For more information about supported hardware and versions, refer to the System Requirements and Compatibility section of the BIG-IP Next Release Notes for your version.

Description

You can setup an HA deployment between BIG-IP Next tenant instances running on separate F5 VELOS systems. For example, if you have two VELOS chassis systems, you can create a chassis partition on each VELOS system and create one BIG-IP Next tenant instance in each chassis partition, then setup HA between the tenant instances. In this configuration, one tenant instance will become the Active instance and the other will become the Standby. If the Active system fails, the application traffic fails over from the Active BIG-IP Next tenant instance to the Standby BIG-IP Next tenant instance.

You can create the BIG-IP Next tenant instances and configure the HA settings all from the BIG-IP Next Central Manager. You first add both VELOS chassis partitions to the BIG-IP Next Central Manager as VELOS Providers, which allows you to create BIG-IP Next tenant instances on the VELOS systems from BIG-IP Next Central Manager. Once both Next tenant instances are up and running, you can then start the HA configuration process on one of the Next instances and reference the other Next instance in the process to create the HA deployment.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a pair of VELOS chassis systems that are licensed and healthy running F5OS-C 1.6.1 or later. For more information about supported hardware and versions, refer to the System Requirements and Compatibility section of the BIG-IP Next Release Notes for your version. For more information about upgrading F5OS versions, refer to the F5 VELOS Systems: Software Installation and Upgrade guide for your version.
  • You configured a chassis partition on each VELOS system that is available for use in the HA deployment.
  • You applied the workaround for ID 1564157 to both VELOS chassis partitions. This is needed to successfully add the VELOS chassis partitions as Providers in BIG-IP Next Central Manager.
  • You uploaded the BIG-IP Next tenant image bundle file to both VELOS chassis partitions. The tenant image is bundled with the YAML configuration file in a .tar.bundle file and can be found on the F5 Downloads site.
  • You have BIG-IP Next Central Manager up and running as a standalone or in HA mode.
  • You have a JSON Web Token (JWT) available in order to license the BIG-IP Next instances. For more information about licensing BIG-IP Next instances, refer to How to: Activate BIG-IP Next instance licenses from BIG-IP Next Central Manager on F5 Cloud Docs.
  • You have two VLANs available for HA traffic, plus any VLANs needed for application traffic.
  • You have a minimum of ten available IP addresses for the application traffic VLANs, HA VLANs, and management interfaces. Each VLAN used for application traffic will have three IP addresses, one for each BIG-IP Next instance plus a floating IP address. Each of the two HA VLANs will have a primary IP address, plus an optional secondary IP address, for each BIG-IP Next instance. The floating management IP address is used for the HA management IP address. Requirements

  • The system controllers and chassis partitions on both VELOS systems must be running the same F5OS-C version.
  • The BIG-IP Next instances and BIG-IP Next Central Manager must be running the same version.
  • The BIG-IP Next instances must use the same instance name.
  • The BIG-IP Next instances must have their management IP addresses on the same L2/L3 network. The ARP protocol is used when determining Active/Standby state.

Procedures

  • Add VLANs to the VELOS chassis partitions and assign them to one or more chassis partition interfaces
  • Add the VELOS chassis partitions as VELOS Providers in BIG-IP Next Central Manager
  • Create the first (Active) BIG-IP Next tenant instance using the BIG-IP Next Central Manager
  • Create the second (Standby) BIG-IP Next tenant instance using the BIG-IP Next Central Manager
  • Create HA between BIG-IP Next tenant instances using the BIG-IP Next Central Manager

Add VLANs to the VELOS chassis partitions and assign them to one or more chassis partition interfaces

When creating an HA deployment with BIG-IP Next instances, you need to provide separate VLANs for the HA control plane and HA data plane. These VLANs, along with any VLANs needed for application traffic, need to be configured on the VELOS chassis partitions prior to BIG-IP Next tenant instance creation. Both chassis partitions need to have the same VLANs configured and the VLANs need to be assigned to one or more interfaces. To configure the VLANs on your VELOS chassis partitions and assign them to one or more interfaces, perform the following procedure on both VELOS chassis partitions:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the VELOS chassis partition webUI.
  2. Go to NETWORK SETTINGS > VLANs.
  3. Select Add.
  4. Enter the VLAN ID and name for the HA data plane VLAN. Using the example above, enter 230 for the VLAN ID and ha-dp-vlan for the Name.
  5. Select Save & Close.
  6. Select Add.
  7. Enter the VLAN ID and name for the HA control plane VLAN. Using the example above you would enter 240 for the VLAN ID and ha-cp-vlan for the Name.
  8. Select Save & Close.
  9. Repeat steps 3 - 5 for any additional VLANs needed for application traffic in your environment.
  10. Go to NETWORK SETTINGS > Interfaces.
  11. Select the name of the interface to add the VLANs. The interface must be enabled and UP.
  12. In Trunk VLANs (Tagged), select the checkbox next to the VLANs you configured.
  13. Select Save & Close.

Add the VELOS chassis partitions as VELOS Providers in BIG-IP Next Central Manager

Before you can create a BIG-IP Next tenant instance on an VELOS system using BIG-IP Next Central Manager, you first need to add each VELOS chassis partition as a VELOS Provider in the BIG-IP Next Central Manager. The VELOS Provider will then appear as a Provider option during the instance creation process. To add the VELOS chassis partitions as VELOS Providers in the BIG-IP Next Central Manager, perform the following procedure for both VELOS chassis partitions:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager.
  2. Select Manage Instances.
  3. Select Providers on the left.
  4. Select +Add.
  5. For Type in Provider Account Information, select VELOS from the dropdown menu.
  6. For Name, enter a name for the VELOS Provider.
  7. For Hostname, enter the fully qualified domain name (FQDN) or IP address of the VELOS chassis partition management interface.
  8. Make sure the Port setting is 8888.
  9. Select Connect.
  10. Enter the administrative username and password for the chassis partition.
  11. Select Submit.
  12. Select Accept to accept the fingerprint.
  13. The new VELOS Provider should appear in the Providers page under VELOS.

Create the first (Active) BIG-IP Next tenant instance using BIG-IP Next Central Manager

When creating BIG-IP Next instances for HA, you can create two new instances using BIG-IP Next Central Manager, or if you have an exiting licensed instance, you can just create a second instance and reference it during HA creation. These procedures create two new BIG-IP Next tenant instances. This procedure creates and licenses the first or Active instance and the next procedure creates the second or Standby instance. During the tenant instance creation process, you must use the same name for each BIG-IP Next tenant instance in order to successfully establish HA. To create and license the first (Active) BIG-IP Next tenant instance for HA, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager.
  2. Select Manage Instances.
  3. Select Start Adding Instances or +Add.
  4. Select Create a New Instance.
  5. Select Next.
  6. For Hostname, enter a FQDN for the instance. The same name must be used for the second instance in the next procedure.
  7. Optionally, enter a description.
  8. Select VELOS Standalone in the Instance Template dropdown menu.
  9. Select Start Creating to continue.
  10. For VELOS Provider, select one of the VELOS chassis partitions you configured previously as a Provider.
  11. Select Next. The BIG-IP Next Central Manager pulls the configuration parameters from the VELOS chassis partition.
  12. For Disk Size, enter a number between 10 and 30. This will be the size in GB.
  13. For CPU Cores, select the number or CPU cores to use for the instance.
  14. For Tenant Image Name, select the BIG-IP Next tenant image file you previously uploaded to the VELOS chassis partition. For example, the version 20.2.1 file would be BIG-IP-Next-20.2.1-2.430.2+0.0.48.
  15. For Tenant Deployment File, select the YAML file associated with the tenant image file you previously uploaded to the VELOS chassis partition. For example, for version 20.2.1, it would be BIG-IP-Next-20.2.1-2.430.2+0.0.48.yaml.
  16. For Slot IDs, select the slots to use for the tenant instance. The available slots should reflect the slots enabled for the chassis partition.
  17. For VLAN IDs, select both HA VLANs plus any application VLANs needed for application traffic. Using the example from above, you would select the HA data plane and control plane VLANs, and the internal and external application traffic VLANs.
  18. Select Next.
  19. Enter the management IP address, network prefix, and default gateway IP address for the instance's management interface. Using the first (Active) instance in the example, you would enter 172.24.20.10, 24, and 172.24.20.254, respectively.
  20. Select Next.
  21. In the Networking page, select L1 Networks. The default network should be named DefaultL1Network and should use interface 1.1.
  22. Select VLANs, and under L1 Network select the default L1 Network in the dropdown list for each VLAN listed.
  23. Select IP Addresses and select +Create to add an entry.
  24. In the first entry, enter the IP address and prefix for the External VLAN on the first (Active) instance. Using the example above, you would enter 10.10.20.10/24, then select the External VLAN from the VLAN dropdown list.
  25. Select +Create again to add another entry for the Internal VLAN.
  26. In this entry, enter the IP address and prefix for the Internal VLAN on the first (Active) instance. Using the example above, you would enter 10.20.20.10/24, then select the Internal VLAN from the VLAN dropdown list.
  27. Select Next.
  28. Enter a password for the admin-cm user and confirm. The admin-cm user is used for communication between the BIG-IP Next Central Manager and the BIG-IP Next tenant instance when troubleshooting.
  29. Select Next. A summary page is shown. Confirm the settings and select Deploy to begin instance creation. It may take a few minutes to complete the process.
  30. Once the instance is up and is Healthy, you need to license the instance. This requires a licensing JWT that will be stored on BIG-IP Next Central Manager for future use. If you need a JWT licensing token, contact your F5 sales representative.
  31. To license the instance, select the name of the instance.
  32. Select License.
  33. Select Activate License.
  34. Select Next.
  35. If you are creating a new token, select New Token and paste the JWT into the JWT Token field. Enter a name for the new token and select Activate to activate the license. If you have an existing JWT, select Existing Token and select the name of the token from the dropdown list, then select Activate. The License Status for the instance will show Active when the instance has been successfully licensed.

Create the second (Standby) BIG-IP Next tenant instance using the BIG-IP Next Central Manager

Along with sharing the same instance name as the first instance, the second instance should share the same configuration parameters and have the same VLANs enabled as the first instance. You do not need to configure self IP addresses for the second instance at this stage, you can specify them later during HA creation. To create the second (Standby) BIG-IP Next tenant instance, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager.
  2. Select Manage Instances.
  3. Select +Add.
  4. Select Create a New Instance.
  5. Select Next.
  6. For Hostname, enter the FQDN hostname you used for the first (Active) instance above.
  7. Optionally, enter a description.
  8. Select VELOS Standalone in the Instance Template dropdown menu.
  9. Select Start Creating to continue.
  10. For VELOS Provider, select the Provider for the other chassis partition.
  11. Select Next. The BIG-IP Next Central Manager pulls the configuration parameters from the other chassis partition.
  12. For Disk Size, enter the number you entered for the Disk Size on the first instance.
  13. For CPU Cores, select the number or CPU cores you selected for the first instance.
  14. For Tenant Image Name, select the BIG-IP Next tenant image file you previously uploaded to the chassis partition. For example, the version 20.2.1 file would be BIG-IP-Next-20.2.1-2.430.2+0.0.48.
  15. For Tenant Deployment File, select the YAML file associated with the tenant image file you previously uploaded to the chassis partition. For example, for version 20.2.1, it would be BIG-IP-Next-20.2.1-2.430.2+0.0.48.yaml.
  16. For Slot IDs, select the slots to use for the tenant instance. The available slots should reflect the slots selected for the chassis partition.
  17. For VLAN IDs, select both HA VLANs plus any application VLANs needed for application traffic. They should be the same VLANs selected for the first instance. Using the example from above, you would select the HA data plane and control plane VLANs, and the External and Internal VLANs.
  18. Select Next.
  19. Enter the management IP address, network prefix, and default gateway IP address for the instance's management interface. Using the example above, for the second (Standby) instance, you would enter 172.24.20.11, 24, and 172.24.20.254, respectively.
  20. Select Next.
  21. In the Networking page, select L1 Networks. The default network should be named DefaultL1Network and should use interface 1.1.
  22. Select VLANs and under L1 Network, select the default L1 Network in the dropdown list for each VLAN listed. You do not need to specify self IP addresses for the second (Standby) instance at this stage, you will specify them during HA creation in the next procedure.
  23. Select Next.
  24. Enter a password for the admin-cm user and confirm. The admin-cm user is used for communication between the BIG-IP Next Central Manager and the BIG-IP Next tenant instance when troubleshooting.
  25. Select Next. A summary page is shown. Confirm the settings and select Deploy to begin instance creation. It may take a few minutes to complete the process. Do not license this instance. If the instance is licensed, the license should be revoked before starting the HA creation process.

Create HA between BIG-IP Next tenant instances using BIG-IP Next Central Manager

You should now be ready to instantiate HA between the BIG-IP Next tenant instances. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager.
  2. Select Manage Instances.
  3. Select Standalone in the row for the first (Active) instance.
  4. Select HA.
  5. Select Enable HA to begin the process.
  6. In the next page, the first instance should be listed as the Active. Select the second (Standby) instance name from the dropdown list under Available Standalone Instances.
  7. Select Next.
  8. Under Control Plane VLAN, select the name of the HA control plane VLAN you created previously from the dropdown list. Be design, no interface is assigned to the HA control plane.
  9. Under Data Plane VLAN, select the name of the HA data plane VLAN you created previously from the dropdown list. This VLAN should be assigned to interface 1.1.
  10. Select Next.
  11. For HA Name, enter a name for this HA instance.
  12. For HA Management (Floating) IP Address, enter the floating management IP address for the HA instance. Using the example above, you would enter 172.24.20.12.
  13. Under Active Node, enter an IP address and prefix for the HA control plane and an IP address and prefix for the HA data plane on the Active instance. You may optionally add a Secondary IP address and prefix for the data plane. Using the above example for the Active instance, enter 10.40.20.10/24 for the HA control plane and 10.30.20.10/24 for the HA data plane.
  14. Under Standby Node, enter an IP address and prefix for the HA control plane and an IP address and prefix for the HA data plane on the Standby instance. You may optionally add a Secondary IP address and prefix for the data plane. Using the above example for the Standby instance, enter 10.40.20.11/24 for the HA control plane and 10.30.20.11/24 for the HA data plane.
  15. Select Next.
  16. Under Traffic VLANs, select the name of the Internal VLAN.
  17. You can now configure the self IPs for the Internal VLAN. You need to enter one IP address and prefix each for the Active and Standby instances, plus one for the floating self IP address. The IP/prefix for the Internal VLAN on the Active instance should be shown in the list. Using the above example, the IP address and prefix would be 10.20.20.10/24. Under HA Details, select Active Node IP Address from the dropdown list.
  18. Select the plus sign (+) to add a new row.
  19. Enter the IP address and prefix for the Internal VLAN on the Standby instance. Using the example, the IP/prefix would be 10.20.20.11/24. Under HA Details, select Standby Node IP Address from the dropdown list.
  20. Select the plus sign (+) to add a new row.
  21. Enter the IP address and prefix for the Floating IP address for the Internal VLAN. Using the example, the IP/prefix would be 10.20.20.12/24. Under HA Details, select Floating IP Address from the dropdown list.
  22. Select Save.
  23. Under Traffic VLANs, select the name of the External VLAN.
  24. The IP/prefix for the External VLAN on the Active instance should be shown in the list. Using the above example, the IP address and prefix would be 10.10.20.10/24. Under HA Details, select Active Node IP Address from the dropdown list.
  25. Select the plus sign (+) to add a new row.
  26. Enter the IP address and prefix for the External VLAN on the Standby instance. Using the example, the IP/prefix would be 10.10.20.11/24. Under HA Details, select Standby Node IP Address from the dropdown list.
  27. Select the plus sign (+) to add a new row.
  28. Enter the IP address and prefix for the Floating IP address for the External VLAN. Using the example, the IP/prefix would be 10.10.20.12/24. Under HA Details, select Floating IP Address from the dropdown list.
  29. Select Save.
  30. Select Next.
  31. Review the details of the summary page and select Deploy to HA to instantiate HA. Select Yes, Deploy to confirm.
  32. It will take a few minutes to complete the setup process. When completed, the HA deployment shows as a single instance entry with the instance name and floating management IP address you provided, and the Mode will show HA.
