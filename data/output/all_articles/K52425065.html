Topic

You should consider using these procedures under the following condition:

  • You want to replace the default SSL certificate used by the Configuration utility.

Description

The Configuration utility uses a self-signed SSL certificate that is valid for 10 years by default. In some cases, you may want to replace the BIG-IQ system's default Configuration utility certificate. For example, you may want to use an SSL certificate signed by a third party Certificate Authority (CA) to eliminate browser pop-up warnings.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have Advanced Shell (bash) access to the BIG-IQ system with administrator credentials.

Procedures

  • Generate a new CSR and a new SSL private key (optional)
  • Generate a new self-signed certificate and a new SSL private key (optional)
  • Replace the BIG-IQ system's default Configuration utility SSL certificate
  • Recover from errors that may occur after replacing the default BIG-IQ device certificate

Generate a new CSR and a new SSL private key

This procedure describes how to generate a new CSR. If you want to generate a new self-signed certificate, skip to the next procedure. To generate a new CSR and new SSL private key, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line.
  2. Generate a new CSR and SSL private key in the /shared/tmp/ directory, using the following command syntax. The OpenSSL req command prompts you to enter certificate attributes:

    openssl req -new <digest> -nodes -newkey rsa:<key_size> -keyout <key_path_and_name> -out <csr_path_and_name>

    Note: The -nodes option removes the passphrase prompt for the key. The BIG-IQ Configuration utility is not compatible with an encrypted SSL private key.
    Note: Some of the CSR (New SSL certificate after singed by CA) need a SAN extension to work properly when implemented Configuration utility for that purpose please follow K11438: Creating SSL SAN certificates and CSRs using OpenSSL

     

  3. The following command generates a new 2048-bit SSL private key in the /shared/tmp/ directory named example.key and generates a new CSR in the /shared/tmp directory named example.csr, using a SHA2 digest:

    openssl req -new -sha256 -nodes -newkey rsa:2048 -keyout /shared/tmp/example.key -out /shared/tmp/example.csr

  4. Submit the CSR you generated in the previous step to your CA to obtain a new SSL certificate.

    Note: Use openssl command to verify the CSR before submitting it. For example: openssl req -in /shared/tmp/example.csr -noout -text

  5. After you have received the new SSL certificate, proceed to the Replace the BIG-IQ system's default Configuration utility SSL certificate procedure to use the new certificate and key with the BIG-IQ Configuration utility.

Generate a new self-signed certificate and a new SSL private key

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To generate a new SSL private key and self-signed certificate in the /shared/tmp/ directory, use the following command syntax:

    openssl req -x509 <digest> -nodes -newkey rsa:<key size> -keyout <key_path_and_name> -out <cert_path_and_name> -days <#_of_days>

    For example, the following command generates a new 2048-bit SSL private key in the /shared/tmp/ directory named example.key, and a self-signed certificate in the /shared/tmp/ directory named example.crt:

    openssl req -x509 -sha256 -nodes -newkey rsa:2048 -keyout /shared/tmp/example.key -out /shared/tmp/example.crt -days 3652

    Note: The -nodes option removes the passphrase prompt for the key. The BIG-IQ Configuration utility is not compatible with an encrypted SSL private key.

  3. Proceed to the Replace the BIG-IQ system's default Configuration utility SSL certificate procedure to use the new certificate and key with the BIG-IQ Configuration utility.

Replace the BIG-IQ system's default Configuration utility SSL certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: Only PEM format is acceptable on the BIG-IQ system.

  1. If necessary, using the Secure Copy (SCP) protocol, upload the new SSL certificate, the SSL private key, and any intermediate SSL certificates from your desktop computer to the /shared/tmp directory on the BIG-IQ system.
  2. Log in to the BIG-IQ command line.
  3. To back up the BIG-IQ system's default SSL certificate, enter the following command:

    mv /config/httpd/conf/ssl.crt/server.crt /config/httpd/conf/ssl.crt/server.crt.default

  4. To back up the BIG-IQ system's default SSL key, enter the following command:

    mv /config/httpd/conf/ssl.key/server.key /config/httpd/conf/ssl.key/server.key.default

  5. Optional: If your new server certificate requires intermediate certificates to create a chain of trust, you must bundle the server certificate with the intermediate certificates. It is necessary that the server certificate appear at the top of the bundle file. To create a certificate bundle, use the following command syntax:

    cat /shared/tmp/<server_certificate_name>.crt <(echo -e \\r) /shared/tmp/<intermediate_certificate_name_1>.crt <(echo -e \\r) ... > /config/httpd/conf/ssl.crt/server.crt

    Note: The <(echo -e \\r) command substitution adds a carriage return after each certificate. The ... characters represent additional certificates to be appended to the chain file.

    Note: The webd configuration requires an SSL certificate file named server.crt.

    For example, to create a certificate bundle (using the files you uploaded to the /shared/tmp directory) in the BIG-IQ web certificate directory and name it server.crt, enter the following command:

    cat /shared/tmp/example.crt <(echo -e \\r) /shared/tmp/intermediate.crt > /config/httpd/conf/ssl.crt/server.crt

    After completing this step, you can proceed to step 7.

  6. Move the new SSL certificate from the /shared/tmp directory to the BIG-IQ system's web certificate directory using the following command syntax:

    Note: The webd configuration requires an SSL certificate file named server.crt.

    mv /shared/tmp/<name>.crt /config/httpd/conf/ssl.crt/server.crt

    For example, to move a new SSL certificate named example.crt into the BIG-IQ web certificate directory and rename it to server.crt, enter the following command:

    mv /shared/tmp/example.crt /config/httpd/conf/ssl.crt/server.crt

  7. Move the new SSL key from the /shared/tmp directory to the BIG-IQ system's web key directory using the following command syntax:

    Note: The webd configuration requires an SSL key file named server.key.

    mv /shared/tmp/<name>.key /config/httpd/conf/ssl.key/server.key

    For example, to move a new SSL certificate named example.key into the BIG-IQ web key directory and rename it to server.key, enter the following command:

    mv /shared/tmp/example.key /config/httpd/conf/ssl.key/server.key

  8. To restart the BIG-IQ system's web server, enter the following command:

    tmsh restart sys service webd

Recover from errors that may occur after replacing the default BIG-IQ device certificate

If the webd configuration detects an error with the new SSL certificate or key (for example, if the SSL certificate and key mismatch or are named incorrectly), the process restarts continuously, making it difficult to use the command line. To reinstall the default BIG-IQ SSL device certificate and key, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line.
  2. To stop the webd service from restarting, enter the following command:

    Note: You can copy and paste this text into the shell and select Enter while the webd process is restarting.

    tmsh stop sys service webd

  3. To reinstall the default BIG-IQ SSL certificate, enter the following command:

    Note: Enter y when asked to overwrite the current server.crt file.

    cp /config/httpd/conf/ssl.crt/server.crt.default /config/httpd/conf/ssl.crt/server.crt

  4. To reinstall the default BIG-IQ SSL key, enter the following command:

    Note: Enter y when asked to overwrite the current server.key file.

    cp /config/httpd/conf/ssl.key/server.key.default /config/httpd/conf/ssl.key/server.key

  5. To restart the BIG-IQ web server, enter the following command:

    tmsh restart sys service webd

If you have issues with Data Collection Devices disconnecting or entering an error state after updating the default BIG-IQ device certificate, refer to K02014651: Removing a DCD association from BIG-IQ Centralized Management.
