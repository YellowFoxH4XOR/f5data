Description

The following symptoms may be observed if the ASM policies fail to restore after an upgrade:

  • ASM policy settings/parameter values have changed (reset to default) after upgrade (such as from Manual learning mode to fully automatic)
  • Unexpected blocking takes place 7 days after upgrade when the staging period expires.

Environment

  • Upgrading BIG-IP ASM
  • ASM Policies are configured
  • ASM policies different after upgrade

Cause

  • After upgrading BIG-IP software individual ASM policies take some time to complete their upgrade.
  • After completing a software upgrade /var/log/asm will begin logging each policy that is upgraded as noted in the example below. 
    /var/log/asm
     debug asm_start[22121]: Restoring active policy - policy /[partition/[policy name] (id = [id#])
  • If the device is rebooted, BD or ASM restarted during the upgrade task the policies will fail to load resulting in policies loading with default settings from templates causing unexpected false positives blocks and other unexpected behavior.
  • Failure to load asm policies can be triggered by issuing commands that require restart of tmm, such as re-allocating memory from tmm to control plane: 

    tmsh modify sys db provision.extramb value xxxx

Recommended Actions

  • Please wait up to a few minutes for each policy to complete the upgrade procedure before making any system changes that will causes processes to restart. Most security policies should take several seconds to several minutes to finish loading, depending on the size of the policy.
  • If needed, verify that the policy has finished loading by reviewing the /var/log/asm file. For example, when the policy load has completed, the system logs an informational message similar to the following:

    ASMConfig change: Apply Policy Task Apply Policy Task (1737581128.447064) [update]: Status was set to COMPLETED

  • If this task is interrupted via restart/reboot or restarting the ASM daemon then policies will fail to load resulting in policies loading with default settings from templates causing unexpected false positives blocks and other unexpected traffic-related behavior.
