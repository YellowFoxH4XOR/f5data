Issue

Error Message

java.lang.OutOfMemoryError

Message Location

You may encounter this message in the following location:

  • The /var/log/tomcat/catalina.out file

Description

This message occurs when the following conditions is met:

  • The tomcat process requires additional memory.

Impact

Access to the Configuration utility may fail.

Recommended Actions

To mitigate receiving this message, you can use the provision.tomcat.extramb database variable to increase the maximum amount of Java virtual memory available to the tomcat process. The additional memory for the tomcat process is allocated from the memory allotted to the Linux host and reduces the amount for other processes that use host memory.; It does not affect available memory for the Traffic Management Microkernel (TMM). To increase the maximum amount of memory available to the tomcat process, perform the following procedure:

Impact of procedure: Allocating additional memory to Apache Tomcat may impact the performance and stability of the BIG-IP system. You should perform this procedure only when directed by F5 Support after considering the impact to Linux host memory resources.

Important: Although the procedures outlined in this article may mitigate the offending error message, it does not substitute for identifying the root cause of the Apache Tomcat Java memory allocation and exhaustion issue.

  1. Log in to the BIG-IP command line.
  2. Look at MemAvailable from 'cat /proc/meminfo' This is the best estimate of free or easily freeable host memory.

    For example, the following output from the free utility shows 686844 kilobytes available:

    total      used         free       shared     buffers     cachedMem:     

    16472868   15786024     686844     807340     827748      2543836
    -/+ buffers/cache:   12414440    4058428
    Swap:      1023996          0    1023996

  3. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  4. View the current value of the provision.tomcat.extramb database variable by entering the following command:

    list /sys db provision.tomcat.extramb

    The command output appears similar to the following example:

    sys db provision.tomcat.extramb {
    value "0"
    }

    A value of 0 (zero) indicates no additional memory is currently allocated. This is the default value.

  5. Set the provision.tomcat.extramb database variable to the preferred amount of additional memory to be allocated using the following command syntax:

    modify /sys db provision.tomcat.extramb value <MB>

    <MB> is the number of megabytes of additional memory you want to add to the default provisioned amount. For example, to allocate an additional 50 MB of additional memory, enter the following command:

    modify /sys db provision.tomcat.extramb value 50

    Note: F5 recommends an initial value of 50 MB, assuming the device has enough Other memory free, but it may not resolve all instances of the error message. If the java.lang.OutOfMemoryError errors continue, you can repeat this procedure, increasing the value by 50 MB each time until you no longer encounter the error message.

    Important: Check output of free before continuing to confirm the device has enough usable memory available.

    If this value goes above 1GB and you still experience the same error, open a support case with F5 Support before continuing

    No additional commands are available to see how close the process is to running out of the memory allocated. Monitoring for the java.lang.OutOfMemoryError errors is the only way to make sure that the condition no longer repeats

  6. Restart the tomcat process by entering the following command:

    restart /sys service tomcat

  7. If the device is part of a high availability (HA) configuration, change the provision.tomcat.extramb database value on all devices by doing one of the following:
    • For BIG-IP 12.1.3.7 and later and 13.1.0 and later, repeat step 1 to step 6 on peer devices.
    • For BIG-IP 11.x, 12.1.3.6 and earlier, and 13.0.1 and earlier, synchronize the peer devices from the command line and refer to K14856: Performing a ConfigSync using tmsh.
    • For BIG-IP 10.x, synchronize to the peer devices from the command line and enter the following command:

      tmsh run sys config-sync

  8. Log in to the command line of each peer device and restart the tomcat process using the command from step 7.
  9. If, after performing the previous steps, your BIG-IP system continues to experience the error message, you should consider reviewing the Provisioning setting for Management (MGMT) and increase it depending on the size of your BIG-IP configuration. For more information, refer to K26427018: Overview of Management provisioning.
  10. If the restjavad process on your BIG-IP system frequently restarts and reports java.lang.OutofMemoryError errors, you should review the following articles and perform the recommended actions or workaround steps:
    • K12410040: restjavad restarts frequently
    • ID 776393: Restjavad restarts frequently due to insufficient memory with relatively large configurations
    • ID 940453: Restjavad restarting with java.lang.OutOfMemoryError
