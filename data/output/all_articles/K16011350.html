Topic

The pva.standby.flush database key allows you to control what the BIG-IP system does with existing accelerated connections in the ePVA hardware when a traffic-group goes standby.

Description

When a traffic-group goes standby, the BIG-IP system stops processing traffic for virtual servers whose addresses are within that traffic group. However, on platforms equipped with an embedded Packet Velocity Accelerator (ePVA), existing flows in the ePVA from fastL4 virtual servers will remain even after a traffic-group has gone standby. If the upstream router or switch continues to direct traffic toward the BIG-IP after the traffic-group has gone standby, the ePVA will continue to forward that traffic if it matches an existing accelerated flow.

This issue is tracked in ID421797 and its impact varies according BIG-IP configuration and the behavior of surrounding network devices. The issue was addressed with the addition of a new database key: pva.standby.flush.

When pva.standby.flush is set to 0 (default value), the ePVA continues to hold existing accelerated flows after a traffic-group has gone standby, until they are eventually evicted once the inactivity timeout is reached (16 seconds by default.) When pva.standby.flush is set to 1, a failover event for any traffic-group will trigger an eviction of all ePVA accelerated flows for all traffic-groups.

For vCMP guests and VELOS tenants, pva.standby.flush is set at the guest/tenant level. Enabling pva.standby.flush in one guest or tenant will not affect accelerated flows for other guests or tenants.

Recommendations

For platforms equipped with an ePVA, if a single traffic-group is in use only, F5 recommends enabling pva.standby.flush by setting the value to 1.

If multiple traffic-groups are in use, and more than one traffic-group uses virtual servers with fastL4 profiles that use pva-acceleration (default), enabling pva.standby.flush may be helpful if your applications experience prolonged disruptions after a failover. The risk of disruptive failovers may be higher for traffic groups that use a mac-masquerade address. However, keep in mind that enabling this setting will evict (but not delete) currently-accelerated flows for other traffic groups that may still be active. Flows that are evicted for an active traffic group will continue to be processed in software, and will perhaps be accelerated by the ePVA again after a brief time.

Procedures

To enable the pva.standby.flush database key, perform the following procedure:
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS shell (tmsh) by running the command: 
    tmsh
  2. To view the current value of the pva.standby.flush database key, run: 
    list /sys db pva.standby.flush
    The output should look like this: 
    sys db pva.standby.flush {
    value "0"
}
  3. To enable the pva.standby.flush database key, run: 
    modify /sys db pva.standby.flush value 1
  4. Save the configuration: 
    save /sys config
  5. Sync the change to HA peers. 
    run /cm config-sync to-group <name-of-sync-failover-device-group>
  6. To reset this value back to the default setting ("0", disabled), run: 
    modify /sys db pva.standby.flush reset-to-default
    Then, save the configuration and run config-sync.
