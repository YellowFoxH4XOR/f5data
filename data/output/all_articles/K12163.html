K12163: Active Directory discovery will fail for DNS servers configured to provide minimal responses

Topic

When the ARX system queries a DNS server to perform discovery of an Active Directory forest, if the DNS server is configured to provide minimal responses, the discovery will fail and the ARX system will log messages to the syslog file that appear similar to the following example:

: ForestDomain ActiveDirDomainRecord.forestName='corp.foo.com'
: GUI-OP: ActiveDirDomain domainType=1 ActiveDirDomainRecord.domainName='corp.foo.com' ActiveDirDomainRecord.domainIp='172.10.20.11' preferred=0
: Failed to add a new domain controller entry because the realm specified on the command line (CORP.FOO.COM) does not match the realm name reported by the computer (FOO.COM) at IP address 172.10.20.11. Check the command and retry.

This behavior has been reported for non-Microsoft DNS servers when BIND is configured with the minimal-responses option set to yes. To allow the ARX system to perform discovery for the Active Directory forest, the minimal-responses option must be set to no. For information about configuring the minimal-responses option, refer to the product documentation for your specific DNS server.

Note: The default value for the minimal-responses option is usually no.

Note: The ARX only supports Microsoft DNS responses for Active Directory discovery. If you are using a non-Microsoft DNS server you may have to check additional settings to ensure the server provides Microsoft DNS compatible responses.
