Description

On BIG-IP ASM systems, a specific virtual server may stop generating event logs, even though security log profiles are correctly configured and other virtual servers on the same device continue to log events normally. The following error messages may be observed in the logs:

IO::LrnPipe::init,,Pipe (type: PBRQL) could not be opened (error code = -1)

RequestLog::send_webhook_events,,Could not connect to asmconfig

IO::ASMConfig::EventListener::init,,Could not open event listener

RequestLog::load_policy_mapping,,Could not connect to asmconfig -- policy mapping will be loaded as needed

Environment

  • Product: BIG-IP ASM
  • Version: 17.5.1
  • Affected virtual server configuration:
    • Two security log profiles attached:
      • One for remote logging (illegal requests only)
      • One for local "Log all requests" logging
    • ASM policy in blocking mode
  • Other virtual servers on the same device are logging events as expected

Cause

The asmlogd service lost its internal communication pipe to the asmconfig service. This prevented asmlogd from loading policy mappings and generating event logs for the affected virtual server. The issue is often triggered by resource exhaustion, especially when "Log all requests" profiles are used on high-traffic virtual servers.

Answer/Recommended Actions

  • Restart the affected services to restore the internal communication pipe:
    pkill -f pabnagd and wait approximately 15 seconds
    pkill -f asmlogd
    Note: Restarting these services does not impact traffic processing on the device.
  • If above restart of serveries won't resolve the problem please restart the asm service with below command:
    bigstart restart asm 
    Impact of workaround: Restarting the asm process causes a brief traffic disruption. F5 recommends performing this restart during a scheduled maintenance window to mitigate the impact on production traffic.
