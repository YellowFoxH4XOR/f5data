K000150181: CFE not working on Oracle Cloud after API key change

Type
Support Solution
Published
2025-02-28
Updated
2025-02-28
Applies to
  • Public Cloud
Source
https://my.f5.com/manage/s/article/K000150181

Description

Failover not working after the customer updated the private keys which are used to communicate with the API endpoint in OCI.
BIG-IP got the below errors after executing the failover on Oracle Cloud Infrastructure.


[OCI-WAF-F5-02:Standby:In Sync] ~ # bash /config/failover/tgactive
oci-curl: {"code":"NotAuthenticated","message":"Failed to verify the HTTP(S) Signature"}
oci-curl: {"code":"NotAuthenticated","message":"Failed to verify the HTTP(S) Signature"}

 

Environment

  • •    BIG-IP VE
    •    Oracle Cloud Infrastructure

Cause

There is a mismatch in the API keys between BIG-IP VE and OCI instance

Recommended Actions

1.    Validate the key file oci_api_key.pem exist under /config/failover directory by entering the below commands
#ls /config/failover/* | grep oci_api_key.pem
2.    On BIG-IP’s CLI, validate the fingerprint 
openssl rsa -pubout -outform DER -in ~/.oci/oci_api_key.pem | openssl md5 -c
it must match the fingerprint in Oracle instance
[OCI-WAF-F5-02:Standby:In Sync] failover# openssl rsa -pubout -outform DER -in ~/.oci/oci_api_key.pem | openssl md5 -c
MD5: 02:11:bc:8f:e2:0e:5a:4f:a9:27:XX:XX:XX:65:f6:ff


On Oracle Instance 
  


2.1    If it does not match , then download again the oci_api_key.pem file from OCI instance and upload it to the BIG-IP on /config/failover directory or generate a new fingerpint and make sure the match.
Or, 
2.2    Generate API key pem file following the ‘Create API keys’ section in this cloud doc
  https://clouddocs.f5.com/cloud/public/v1/oracle/oracle_deploy.html#oci-copy
