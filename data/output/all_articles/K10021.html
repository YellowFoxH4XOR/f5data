Known Issue

This is the result of a known issue. On BIG-IP GTM versions prior to 10.0.0, the BIND max-journal-size option is not configured. As a result, BIND journal files (/var/named/config/namedb/*.jnl) may grow indefinitely. In addition, you may observe the following behavior:

  • Zone file synchronization failure is unable to complete within the allotted five minutes.
  • High CPU utilization due to continuous zone synchronization.
  • Disk space exhaustion due to very large files and temp files left after failed synchronization.
  • ZoneRunner produces a core file or restarts every second.

F5 Product Development tracked this issue as CR109497, and it was fixed in BIG-IP GTM 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You can work around this issue by specifying a maximum journal size of 1000KB in the BIND configuration. To do so, add the following statement into the global options section of the named.conf file:

max-journal-size 1000k;

For example, the following configuration includes the recommended max-journal-size setting in the global options section of the /var/named/config/named.conf file:

options {
listen-on port 53 {
127.0.0.1;
"zrd-acl-000-000";
};
listen-on-v6 port 53 {
::1;
};
directory "/config/namedb";
max-journal-size 1000k;
check-names master warn;
check-integrity yes;
allow-transfer {
localhost;
};
};

When the journal file hits the maximum size, BIND ensures that the affected zone contains all of the updates referenced in the journal file, then deletes the file and starts a new one.
