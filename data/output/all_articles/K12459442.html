Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file when a Session Initiation Protocol (SIP) virtual server fails to process a SIP request.

This issue occurs when all of the following conditions are met:

  • Service Provider Disaggregation (SP DAG) is applied to the internal and external VLANs of the SIP virtual server.
  • Your SIP virtual server receives a SIP request that contains only one CRLF.

This issue may not occur if the SIP request contains more than one CRLF at the end of the request.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system, if configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory with a time stamp that correlates to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Apr 13 15:09 tmm.0.bld2384.0.core.gz
