Known Issue

The BIG-IP system may send extraneous data to the Internet Content Adaptation Protocol (ICAP) server.

This issue occurs when the following conditions are met:

  • The BIG-IP virtual server is configured to process ICAP traffic.
  • After receiving the message preview, the ICAP server returns an HTTP 200 OK status code with an encapsulated 302 redirect response.

After the ICAP server returns the HTTP 200 OK status code with the encapsulated 302 redirect response, the BIG-IP system continues to send the request body until its outgoing TCP window is drained. The extra data flow to the server may consume additional resources on the ICAP server which can cause performance loss.

Impact

Extra data flow may cause performance issues for the ICAP server.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Packet captures indicate that the BIG-IP system continues to send the request body after receiving the 302 redirect response from the ICAP server.
  • The ICAP server experiences performance issues.

Workaround

To work around this issue, you can configure the ICAP server to ignore any trailing request data.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
