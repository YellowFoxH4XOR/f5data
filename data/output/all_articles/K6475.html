Topic

This article discusses the BIG-IP system's Secure Sockets Layer (SSL) transactions per second (TPS) enforcement and how to determine the BIG-IP system's SSL TPS.

Description

Each BIG-IP system is licensed to provide a maximum number of SSL TPS. A BIG-IP system's SSL TPS can be limited by one of two elements:

  • A TPS limit that is specified in the /config/bigip.license file. This limit applies to each instance of the Traffic Management Microkernel (TMM) for non-chassis systems and each blade for VIPRION systems.
  • The system's hardware limitation. In this case, the /config/bigip.license file will specify Unlimited.

    Note: To determine a specific BIG-IP platform's TPS, refer to the BIG-IP System Hardware Datasheet.

    Note: The SSL TPS limit for BIG-IP Virtual Edition has been removed. For more information, refer to K18290319: The SSL TPS limit of 500 per vCPU removed in BIG-IP Virtual Edition.

To understand BIG-IP TPS calculation and enforcement, refer to the following procedures:

  • Determining the SSL TPS
  • SSL TPS Enforcement
  • SSL TPS Exceptions

Determining the SSL TPS

  • Non-chassis BIG-IP systems
  • VIPRION systems

Non-chassis BIG-IP systems 

To determine the SSL TPS limit for which a BIG-IP system is licensed, you must determine the TPS from the bigip.license and the number of TMMs.

  1. Type the following command from the BIG-IP system command line to determine the TPS limit set in the bigip.license file:

    Note: Some systems contain more than one SSL TPS license key; a higher value SSL TPS key overrides any lower value SSL TPS license keys.

    tmsh show sys license detail | grep -i perf_SSL_total_TPS

    The value returned includes both the SSL TPS included in your base registration key and any extra SSL TPS you may have purchased as an add-on. For example, the following output indicates 500 as the maximum number of client-side SSL TPS that the BIG-IP system was licensed to provide per TMM:

    perf_SSL_total_TPS : 500

  2. Type the following command from the BIG-IP system command line to determine the number of TMMs:

    tmsh show sys tmm-info global | grep -i 'TMM count'

    TMM Count 4

  3. Multiply by the numbers gathered in steps one and two to determine the SSL TPS limit. In this example, the BIG-IP system has four TMMs and an SSL TPS limit of 500 for a total SSL TPS limit of 2000.

    Important: Beginning in BIG-IP 11.5.0, BIG-IP platforms that support hyper-threading show half the number of TMMs due to the HTSplit improvement feature. TMM accounts for this condition and doubles SSL TPS when HTSplit is enabled. For more information on HTSplit, refer to K15003: Data plane and control plane tasks use separate logical cores when the BIG-IP system CPU uses Hyper-Threading Technology.

VIPRION systems

To determine the SSL TPS limit for which a VIPRION system is licensed, you must determine the TPS from the bigip.license and the number of installed blades.

  1. Type the following command from the VIPRION system command line to determine the TPS limit set in the bigip.license file:

    Note: Some systems contain more than one SSL TPS license key; a higher value SSL TPS key overrides any lower value SSL TPS license keys.

    tmsh show sys license detail | grep -i perf_SSL_total_TPS

    The value returned includes both the SSL TPS included in your base registration key and any extra SSL TPS you may have purchased as an add-on. For example, the following output indicates 12000 as the maximum number of client-side SSL TPS that the VIPRION system was licensed to provide per blade:

    perf_SSL_total_TPS : 12000

  2. Multiply the numbers gathered in step 1 by the number of blades installed in the VIPRION system to determine the SSL TPS limit. In this example, the VIPRION system has four blades installed and an SSL TPS limit of 12000 for a total SSL TPS limit of 48000.

Note: For information about a licensing change that affects the maximum amount of SSL Mbps throughput allowed, refer to K10693: Default value change for TMOS LIC-0259-00 (BIG-IP, PERFORMANCE SSL, Mbps).

SSL TPS Enforcement

The BIG-IP system measures SSL TPS based on client-side connection attempts to any virtual server configured with a Client SSL profile. Re-encryption and succeeding decryption by an SSL Server profile is not counted against the license limit. For example, if your BIG-IP system is licensed for 1000 TPS, and the BIG-IP system receives 500 new SSL sessions from clients, and then re-encrypts the sessions, this will count as only 500 TPS against the license limit.

SSL TPS is enforced across a sliding time window. The BIG-IP system uses a 10ms window (1/100 of a second) to calculate the current TPS. If the number of TPS requests within any 10ms window exceeds 1/100 of the licensed TPS, the system sends an error message to the /var/log/ltm file indicating that the TPS limit is being reached. For information about these log messages and notification options, refer to K7747: Error message: SSL transaction (TPS) rate limit reached.

Note: The RRD graphs in the Configuration utility may not show a TPS limit being reached, as the data collected for the graph is calculated over a full second or more. It does not take into account the 10ms window used for TPS limit calculation.

For example, if your BIG-IP system is licensed for 5000 TPS, and more than 50 TPS client-side connections are attempted within the 10ms window, the BIG-IP system silently drops connections that exceed the limit for that window and then logs that the TPS limit has been reached. When the number of SSL connection attempts drops below the 1/100 of TPS licenses for the 10ms window, the BIG-IP system can accept and process new SSL connection requests.

The BIG-IP system checks if TPS is available when the system receives a SYN request for a virtual server with a Client SSL profile. If the system has reached its maximum licensed TPS level at the time the SYN request is received, the SYN request is silently dropped and not passed to the SSL accelerator for processing. However, in most cases, the client retransmits the SYN request, typically a few seconds later. Therefore, traffic that slightly exceeds the system's licensed TPS may result in noticeable user connection latency rather than complete failure. Traffic levels that greatly exceed the system's licensed TPS may result in failure to establish some connections.

F5 recommends that you monitor traffic volumes to allow the license limit to be proactively managed. You can configure the BIG-IP system to send an email message to a specified address or to send SNMP traps whenever a message is logged as a result of the SSL TPS limit being reached. For information about configuring SNMP traps, refer to K3727: Configuring custom SNMP traps.

SSL TPS Exceptions

BIG-IP 11.6.0 and later

Beginning in BIG-IP 11.6.0, SSL TPS is based on the key size associated with an SSL profile and the licensed TPS limit. The key-based SSL TPS limit applies per core and only to RSA ciphers. The limits are set as follows.

Example KeyKey SizeTPS Limit
1024 bitsLess than 2048 bitsNo TPS Limit
2048 bitsBetween 2048 and 4095 bitsLicensed TPS
4096 bits4096 bits or greater20% Licensed TPS

F5 Product Development tracked this change as ID 460386.

BIG-IP 11.5.x

In BIG-IP 11.5.x, SSL TPS is based on the key size associated with an SSL profile. The key-based SSL TPS limit applies per core and only to RSA ciphers. The limits are set as follows.

Example KeyKey SizeTPS Limit
1024 bitsLess than 2048 bits5 x Licensed TPS
2048 bitsBetween 2048 and 4095 bitsLicensed TPS
4096 bits4096 bits or greater20% Licensed TPS

F5 Product Development tracked this change as ID 430878.

Client Applications

Client application TPS performance may vary depending on the client resources and the BIG-IP version. In an effort to avoid SSL vulnerabilities, the BIG-IP system prefers newer and stronger SSL cipher suites that are usually added with each new software release. Stronger cipher suites require additional processing power by both the client application and BIG-IP system. When benchmarking BIG-IP SSL performance, you may notice an SSL TPS performance reduction if the client application lacks sufficient resources to process stronger cipher suites effectively. For example, when testing the BIG-IP system's SSL TPS with a simple command line program, such as ApacheBench, the TPS results may be far higher when the negotiated cipher suite is RC4-SHA (11.4.1) than when it is DHE-RSA-AES256 (11.5.2).

To ensure that the BIG-IP system is not the cause of TPS-related issues, ensure that the system is not logging the SSL transaction (TPS) rate limit reached message to the /var/log/ltm file. For more information about the SSL TPS reached message, refer to K7747: Error Message: SSL transaction (TPS) rate limit reached.

In addition, ensure that the BIG-IP system's CPU and memory have not reached peak capacity. For more information, refer to K5670: Overview of adaptive connection reaping (11.5.3 and earlier) and K10095: Error Message: Clock advanced by <number> ticks.
