Known Issue

When the BIG-IP WebAccelerator receives a response that contains a sizeable amount of HTTP header data from the origin web server (OWS), it incorrectly assembles the response and returns a corrupted response to the client. This issue occurs when all of the following conditions are met:

  • The affected WebAccelerator Application is configured to use an unmodified original policy such as Level 2 Delivery or ECommerce
  • The response from the OWS contains HTTP header data with the total size exceeding 8KB

Impact

The client browser receives corrupted responses and may not display correctly.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The corrupted response includes all of the following:

    • All of the original HTTP header data
    • The HTTP header data after the 8KB mark inserted in the HTTP content
    • The original HTTP content truncated to fit the difference between Content-Length and the residual HTTP header data inserted in the HTTP content
  • The client browser may display HTTP header data
  • The client browser may display truncated web pages

Workaround

To work around this issue, you can bypass the BIG-IP WebAccelerator for the affected HTTP objects. To do so, perform the following procedure:

Impact of workaround: Acceleration is disabled for the HTTP object that is configured to bypass the BIG-IP WebAccelerator.

Bypass the WebAccelerator using a HTTP class

You can bypass the BIG-IP WebAccelerator 10.1.0 or later, using HTTP class, by following the procedure described in K9585: Using multiple HTTP classes to bypass BIG-IP WebAccelerator.

Bypass the WebAccelerator using an iRule

You can use an iRule to bypass the BIG-IP WebAccelerator. For more information, refer to the samples described in K10127: Bypassing the BIG-IP WebAccelerator with an iRule in version 10.x.
