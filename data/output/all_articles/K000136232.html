Description

This article will discuss the following error that can be seen under /var/log/apm:

err websso.0[<PID>]: 014d0005:3: Kerberos: can't get S4U2Proxy ticket for server <service_class>/<domain>@<realm> - KDC can't fulfill requested option (-1765328371)

In this error message, note the following:

  • <PID> is the process ID for the websso process.
  • <service_class> is the protocol for the requested service.
  • <domain> is the fully qualified domain name for the service.
  • <realm> is the realm where the service is registered.

For example:

err websso.0[2389]: 014d0005:3: Kerberos: can't get S4U2Proxy ticket for server HTTP/autodiscover.example.com@example.COM - KDC can't fulfill requested option (-1765328371)

This message can occur due to multiple different reasons. The one discussed in K22077121: Error Message: 014d0005:3: Kerberos: can't get S4U2Proxy ticket for server <service_class>/<domain>@<realm> - KDC can't fulfill requested option (-1765328371) is one of them.
The one discussed here is slightly different.
When this message occurs, packet captures of the Kerberos communication between the BIG-IP APM system and the KDC is worth collecting.

In the the use case disclosed here, such data can be seen:

KRB5 887 OUT s1/tmm0 : TGS-REQ
KRB5 296 IN s1/tmm0 : KRB Error: KRB5KDC_ERR_BADOPTION

Further details in the KDC response will show:

Kerberos
    krb-error
        pvno: 5
        msg-type: krb-error (30)
        stime: 2023-09-08 14:30:05 (UTC)
        susec: 594216
        error-code: eRR-BADOPTION (13)
        realm: EXAMPLE.COM
        sname
        e-data: 3081…
            BER Error: Wrong field in SEQUENCE: expected class:CONTEXT(2) tag:1 but found class:UNIVERSAL(0) tag:16
                [Expert Info (Warning/Malformed): BER Error: Wrong field in SEQUENCE: expected class:CONTEXT(2) tag:1 but found class:UNIVERSAL(0) tag:16]

Environment

  • Kerberos Constrained Delegation as a single sign-on (SSO) method in the access policy on the BIG-IP APM system.
  • The SPN pattern is blank or using %s (ie. takes the hostname discovered through reverse DNS lookup using the server IP address)

Cause

This usually happens when the selected hostname from the list retrieved during reverse DNS lookup is not correct (ie. no entry or outdated/invalid entry).

Recommended Actions

Capture and review DNS PTR traffic (related to selected server IP) prior to that TGS-REQ.
Modify that PTR entry on the DNS server so that it matches the service in the Active Directory delegation account (Account Properties > Delegation)
