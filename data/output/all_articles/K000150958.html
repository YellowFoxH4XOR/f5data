Description

In a typical BIG-IP HA deployment, both devices in the pair are provisioned with the same modules (e.g., LTM + DNS). When configuring the HA as a DNS server object, both devices are usually included as members of the server.

However, some customers deploy an HA pair where one device has the LTM+DNS module provisioned, while the other device has only the LTM module. In this scenario, when the customers want to configure the device with DNS module provisioned device to a DNS sync cluster, they may configure the DNS server object to include only the device with the DNS module, excluding the LTM-only device.
 
Example Configuration:
Device Name
Modules Provisioned
Included in DNS Server?
Device ALTM + DNSYes
Device BLTM onlyNo
 
In this scenario:
  • When the device with the DNS module (Device A) is active, the DNS server and its virtual servers are available.
  • When Device A becomes standby, the DNS server and all associated virtual servers become unavailable. The status failure reason is "big3d timeout," regardless of the actual status of the LTM virtual servers.

Environment

  • BIG-IP DNS
  • BIG-IP HA
  • big3d

Cause

This behavior is due to the health check architecture of the DNS cluster:
  • The DNS cluster uses the big3d agent to perform health checks on objects (such as virtual servers) defined in a BIG-IP type server.
  • If the DNS server object contains HA cluster (with multiple devices), the health check request is sent to the big3d agent on each device.
  • Only the big3d agent on the active device responds to the health check.
  • In the described configuration, when the DNS-provisioned device (Device A) is in standby, it does not respond to health check requests. Since Device B is not included in the DNS server object, there is no active big3d agent to respond, resulting in a "big3d timeout" and marking the server and its objects as unavailable.

Recommended Actions

Always include all HA devices in the DNS server object, regardless of whether they have the DNS module provisioned. This ensures that when a failover occurs, the active device's big3d agent can respond to health checks, maintaining the availability of the DNS server and its objects. Refer to Configuring a BIG-IP redundant pair in which one of the units is licensed and provisioned for BIG-IP DNS .
 
Example Correct Configuration:
Device Name
Modules Provisioned
Included in DNS Server?
Device ALTM + DNSYes
Device BLTM onlyYes
 

Additional Information

  • The big3d agent is up and running on all BIG-IP products, not particular for DNS product.
  • The same principle applies to link objects—include all HA devices to avoid availability issues during failover.
