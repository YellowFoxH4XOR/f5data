Description

The best practice when configuring RADIUS authentication for BIG-IP administrative access is to send the traffic through the management interface. If RADIUS traffic for administrative access is sent via the TMM interface, then RADIUS authentication will fail if the TMM process goes down.

Environment

  • BIG-IP configured for remote RADIUS authentication for BIG-IP administrative access.
  • Routing RADIUS traffic through TMM interfaces.

Cause

RADIUS authentication traffic configured to go through TMM interfaces and the TMM process goes down and thus TMM interfaces are down.

Recommended Actions

  1. To determine the IP address the BIG-IP uses to send RADIUS traffic for administrative access, you can use the ip route get command. For example:

    RADIUS server at 10.155.19.169 is reachable via the management interface with management IP address 10.155.19.167:
    # ip route get 10.155.19.169
    10.155.19.169 dev mgmt  src 10.155.19.167 
        cache 

    RADIUS server at 10.118.159.131 is reachable via a TMM interface on vlan Internal with self IP address 10.118.159.129:
    # ip route get 10.118.159.131
    10.118.159.131 dev Internal  src 10.118.159.129 
        cache 

  2. Configure RADIUS authentication for BIG-IP administrative users to be routed through the management interface. So either configure the RADIUS server's IP address on the same subnet as the BIG-IP management IP address or if the RADIUS server is on a separate subnet, configure a management route (tmsh create /sys management-route) to the RADIUS server pointing to a gateway on the management network. For more information refer to K13284: Overview of management interface routing.
  3. Configure more than one RADIUS server. Choose Primary & Secondary on the Users > Authentication page to add another RADIUS server.
