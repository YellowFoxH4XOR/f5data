Topic

In BIG-IP 11.5.0 through BIG-IP 12.0.0, a set of tm.tcpmemorypressure database keys help manage TCP memory pressure to help mitigate memory resource exhaustion and prevent the wide-scale reaping of active connections by the adaptive connection reaping feature.

Beginning in BIG-IP 12.1.0, the tm.tcpmemorypressure.lowater and tm.tcpmemorypressure.hiwater keys are deprecated and no longer serve as the threshold for starting and stopping the TCP packet drops. The system derives the actual threshold from an eviction policy, as described in K15738: Low Water and High Water values for adaptive connection reaping are now configured in an eviction policy. Therefore, to configure the TCP memory threshold for your BIG-IP system, you should configure the the adaptive connection reaper (connection.adaptivereaper) values. For more information on eviction policies and how to configure one, refer to K15821: Overview of eviction policies and K15822: Configuring custom eviction policies, respectively.

Description

The TCP memory pressure feature uses the database keys described in the following table to manage memory pressure.

Database keyDefault valueDescription
tm.tcpmemorypressureenabledDetermines if the feature is enabled or disabled.
tm.tcpmemorypressure.lowater80Specifies the percentage of the Traffic Management Microkernel (TMM) memory utilization at which the system begins dropping ingress TCP packets.
tm.tcpmemorypressure.hiwater90Specifies the percentage of Traffic Management Microkernel (TMM) memory utilization at which the system begins dropping on average 50% of all ingress TCP packets.

When the tm.tcpmemorypressure database key is enabled (default value), if memory utilization reaches the tm.tcpmemorypressure.lowater threshold, the BIG-IP system begins to silently discard some ingress TCP packets. The algorithm used by the TCP memory pressure feature determines how many and what packets to drop and causes more packets to be dropped as memory utilization increases. If the memory pressure reaches the tm.tcpmemorypressure.hiwater threshold, the BIG-IP system randomly drops ingress TCP traffic. On average, this is 50 percent of all packets, but the amount can increase or decrease as packets come in. The BIG-IP system stops discarding packets after the memory utilization drops below the low-water threshold.

Recommendations

If you need to disable or enable the TCP memory pressure feature, or modify the low-water or high-water thresholds, you should consider the following factors:

Important: The impact of modifying the default threshold values depends on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  • Memory utilization is calculated the same way that the adaptive connection reaper sweeper does the calculation. You can determine the percentage of memory (pagemem) that each TMM process uses on the BIG-IP system by entering the following command:

    tmctl -d blade tmm/pagemem

    Depending on the BIG-IP platform, the command output may appear similar to the following example:

    name         used      avail
    ------- --------- ----------
    pagemem 936478624 1103101952

    When you have obtained the figures as described, use the following formula for calculation:

    (used / avail) * 100 = percentage used

    Using the previous example, the percentage of memory calculated would be as follows:

    (936478624 / 1103101952) * 100 = 84.89%

  • By default, the TCP memory pressure feature's low-water threshold (80 percent) is lower than the default adaptive reaping feature's low-water threshold (85 percent), so the TCP memory pressure feature activates earlier than the adaptive reaping feature to prevent wide-scale reaping of active connections, if possible. You can determine if TMM has ever reached the adaptive reaping low-water threshold by entering the following commands:

    tmctl -d blade tmm/tcp -s mem_packets_dropped

    tmctl -d blade tmm/tcp4 -s mem_packets_dropped

    Each entry in the command output represents a TMM instance. If a value other than 0 appears in the output, a TMM instance has at some time reached the adaptive reaping low-water threshold:

    mem_packets_dropped
    -------------------
                      0
                      0
                      0
                      0

  • Prior to BIG-IP 12.1.2, there are no messages logged when the TCP memory pressure feature is triggered.
  • Beginning in BIG-IP 12.1.2, a message similar to the following is displayed in the /var/log/ltm log file when this feature is triggered:

    warning tmm[<pid>]: 01010291:4: TCP: Memory pressure deactivated. Dropped 118 packets, 62186 bytes

  • You can view the current TCP memory pressure database key values using the following tmsh command:

    tmsh list sys db tm.tcpmemorypressure*

    The output will appear similar to the following example:

    sys db tm.tcpmemorypressure {
        value "enable"
    }
    sys db tm.tcpmemorypressure.hiwater {
        value "90"
    }
    sys db tm.tcpmemorypressure.lowater {
        value "80"
    }

  • You can enable or disable the TCP memory pressure feature using the following tmsh command syntax:

    tmsh modify sys db tm.tcpmemorypressure value <enable|disable>

  • In versions prior to BIG-IP 12.1 you can modify the low-water or high-water thresholds using the following tmsh command syntax:

    tmsh modify sys db tm.tcpmemorypressure.lowater value <value>
    tmsh modify sys db tm.tcpmemorypressure.hiwater value <value>
