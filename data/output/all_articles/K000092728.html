K000092728: The SDC is rejecting Client peer handshake with error "the peers admin state is set to Disabled".

Type
Support Solution
Published
2022-11-26
Updated
2024-12-17
Source
https://my.f5.com/manage/s/article/K000092728

Description

  • A peer that was earlier configured as a Server peer and got deleted then the same peer wants to establish as a client peer in SDC.
  • SDC is rejecting it by saying "the peers admin state is set to Disabled".

2020-04-01 07:02:58,707 WARN [11024] SDC does not accept peer <Peer_Name> because the peers admin state is set to Disabled. [Silo-EventLoop-thread-3-4_23] [ClientPeerHandshakeHandler_netty4.createPeerIfNeeded()]

  • This peer will be shown as deleted, client peer and state disabled in the peer's XML configuration file located in /data/backup/<Site>/<Node>_traffix_config_mgr-config1/peerConfigurations

<entry key="IsDeleted" value="true"/>

<entry key="PeerIsServer" value="false"/> 

<entry key="PeerUserState" value="DISABLE"/>

  • This peer is no longer visible in the Webui.
  • The peer is still present in the peer table when checking the FEP logs.

<Peer_Name> Closed_8067391737593737 Signalling Not Available <<< This shows that peer is still in peerTable.

Environment

  • SDC 5.1
  • Client Peer

Cause

The root cause of this issue is having a client and server peer with the same name. In SDC, a server peer is persistent, meaning that its data is kept by the Configuration Manager (CM) in the file system. On the contrary, a client peer is not persisted in the file system and is stored in memory only by the CM, FEP, CPF, and NMS. In addition, the name of a peer is unique per site and the CM uses it as the identifier. When a server peer is deleted in the UI, the configuration is updated marking the peer as deleted but it's data still remains in the file system for rollback purposes.

Recommended Actions

  • Remove the particular peer from peerTable and let the peer to reconnect. Replace the "peer_name" with the actual peer name found in the peer table.

1. Go to : SDC site WEBUI >> Administration >> Engineering Script >> Cluster Node Engineering Script

2. Copy and Paste the script below :
def boolean invokeStackControl(Stack stack, Logger userTraceLogger){

//YOUR_CODE_HERE

stack.getPeerTable().removePeer("peer_name");

}

3. The first two lines are already present in the default script; you need to put "stack.getPeerTable().removePeer("peer_name");" and then submit. In addition, the above script is non-service impacting.

  • Make sure the peer was removed by printing stack status, you can print the stack output by clicking the "Print Status to Log" button (in the same window). The stack output will be shown in FEP and CPF output. Make sure the peer was removed by printing stack status.
