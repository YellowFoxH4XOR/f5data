Issue

Old Behavior

In versions prior to BIG-IP 13.0.0, the BIG-IP system does not support configuring local authentication as a backup method when remote authentication fails.

By default, the BIG-IP system uses its own user directory for user authentication. In versions prior to BIG-IP 13.0.0, if you configure a remote authentication method, such as Lightweight Directory Access Protocol (LDAP), the system does not allow you to use local authentication as a backup method for remotely stored user accounts in the event that remote authentication fails.

New Behavior

Beginning in BIG-IP 13.0.0, you can configure local authentication as a backup method when remote authentication fails; if you configure a remote authentication method, such as Lightweight Directory Access Protocol (LDAP), the system allows you to use local authentication as a backup method for remotely stored user accounts in the event that remote authentication fails.

Note: Local authorization is utilized when the remote authentication server is not available. For more information refer to: K49218438: Configuring local authentication as a backup method for remote authentication (13.x - 14.x).

F5 Product Development tracked this change as ID 340702.

Impact

You can now configure local authentication as a backup method for remotely stored user accounts in the event that remote authentication fails.

Recommended Actions

Configuring local authentication as a backup method for remotely stored user accounts

To configure local authentication as a backup method for remotely stored user accounts in the event that remote authentication fails, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Verify that the User Directory values specifies a remote authentication method, such as LDAP.
  4. Select the Fallback to Local check box.
  5. Select Update.
