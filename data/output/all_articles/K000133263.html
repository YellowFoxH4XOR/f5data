K000133263: BIG-IP becomes offline/inoperative after upgrading to 17.1.0

Type
Support Solution
Published
2023-03-29
Updated
2023-11-03
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000133263

Description

BIG-IP goes into offline/inoperative state when upgraded to v17.1.0.

 

Similar to below messages will be logged under /var/log/ts/bd.log:

BD_MISC|ERR |Mar 16 18:41:01.901|12779|temp_func.c:2292|CONFIG_TYPE_PROTOBUF_FILENAMES message had parsing error: could not parse protobuf message

BD_MISC|ERR |Mar 16 18:41:01.901|12779|table_funcs.cpp:2734|CONFIG_TYPE_PROTOBUF_FILENAMES message had errors in block_index: 196. status=-1

BD_MISC|NOTICE|Mar 16 18:41:01.901|12779|table_funcs.cpp:2734|{"component":"BD","datetime":"1969-12-31T19:00:00Z","jobId":"699f26723cc8578a0b43562e0d05aae0","jobStartDatetime":"1969-12-31T19:00:00Z","jobStatus":"failed"}

BD_MISC|ERR |Mar 16 18:41:01.901|12779|temp_func.c:2285|CONFIG_TYPE_MANIFEST message had parsing error: could not parse protobuf message

BD_MISC|NOTICE|Mar 16 18:41:02.714|12759|signals.c:0047|Received (null) - terminating


For example:
For a Virtual Server with a name like the following, the name starts from the '/' after the partition name, in this case after /Common/

ltm virtual /Common/My_Application_name_ABCDEFGHI_version1.app/My_Virtual_server_name_redirect_vs_example123
 

Environment

  • Upgrading to BIG-IP ASM device to v17.1.0, 17.1.0.1, 17.1.0.2
  • ASM is provisioned
  • Virtual server present with names longer than 64 characters

 

Cause

Bug ID 1281381 

Recommended Actions

    1. Identify virtual server name that is more than 64 characters. Boot into the previous working volume.
        # list ltm virtual | grep "^ltm virtual" | awk 'length($3)>=64{print length , $3}'
    2. Delete the virtual server and recreate virtual server with less than 64 characters 
    3. Alternatively you can request for EHF from F5 technical support.
