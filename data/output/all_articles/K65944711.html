Description

F5 Support may ask you to produce a BIG-IP daemon core file on the BIG-IP system to establish the state of daemon process during an event. You should perform this task only when asked to do so by F5 Support.

Important: The impact of restarting a BIG-IP process depends on the process. For information about a specific BIG-IP process, refer to K89999342: BIG-IP daemons (12.x), K05645522: BIG-IP daemons (13.x), or K67197865: BIG-IP daemons (14.x). Restarting BIG-IP processes can interrupt traffic processing temporarily, and devices configured as an HA pair may fail over. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

Important: A daemon may ignore the kill command if the daemon is in the middle of a task that cannot be interrupted.

Environment

  • BIP-IP
  • F5 Support has requested a diagnostic core file for a specific daemon
  • Adequate amount of disk space for the diagnostic core file
    • K14403: Maintaining disk space on the BIG-IP system

Cause

None

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Disable the watchdog process
    • K13539: Disabling the watchdog process to perform a core dump (11.x - 15.x)
  2. Log in to the BIG-IP command line
  3. To find the process ID (PID) for a specific process (daemon), use the ps ax command and filter the results with the grep command.
    Example: find the PIDs of the bigd process by entering the following command:

    ps ax | grep bigd

    The output of the command appears similar to the following example:

     6962 ?        S      0:00 runsv bigd
     6974 ?        S      0:00 /etc/bigstart/scripts/bigd.start --procs 5
    22009 ?        S      0:01 bigd.2 -P 5 -I 2
    22010 ?        S      0:01 bigd.0 -P 5 -I 0
    22011 ?        S      0:01 bigd.3 -P 5 -I 3
    22012 ?        S      0:01 bigd.1 -P 5 -I 1
    22013 ?        S      0:01 bigd.4 -P 5 -I 4
    24836 pts/0    S+     0:00 grep bigd

    Note: When selecting a PID for a process, exclude processes that are preceded with runsv. Running the kill command on a process preceded with runsv does not produce a usable core dump.

    In this example, you would identify 22009, 22010, 22011, 22012, and 22013 as PIDs for the bigd processes.
     
  4. Use the kill command to signal the desired process to produce a diagnostic core file. To do so, use the following command syntax:

    kill -s FPE <process ID> <process ID> ...

    You should replace the <process ID> placeholders with the PIDs from step 3.

    Example: Force a diagnostic core file for the bigd process from step 3, enter the following command:

    kill -s FPE 22009 22010 22011 22012 22013

    Alternatively, you can run the kill command on each individual process ID as in the following example:

    kill -s FPE 22009
    kill -s FPE 22010
    kill -s FPE 22011
    kill -s FPE 22012
    kill -s FPE 22013
     
  5. The diagnostic core files are written to the /shared/core directory, and the file names appear similar to the following examples:

    bigd.0.bld0.0.606.core.gz
    bigd.1.bld0.0.606.core.gz
    bigd.2.bld0.0.606.core.gz
    bigd.3.bld0.0.606.core.gz
    bigd.4.bld0.0.606.core.gz

    Note: Processes that use a significant amount of memory may require several minutes for the system to complete writing the core files to disk.
     
  6. Once the diagnostic core file creation has completed, re-enable the watchdog process
    • K13539: Disabling the watchdog process to perform a core dump (11.x - 15.x)

Additional Information
For information about generating an md5sum and providing the TMM diagnostic core file to F5 Support, refer to K13002225: Providing diagnostic core files to F5 Support (12.x and later)
