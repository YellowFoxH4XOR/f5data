K000158940: Configuring Required Node Annotations for F5 CIS Static Routes with Cilium CNI

Type
Support Solution
Published
2025-12-29
Updated
2025-12-30
Applies to
  • BIG-IP
  • F5 Automation and Orchestration
  • F5 Application Services 3 Extension
  • F5 BIG-IP Container Ingress Services
Source
https://my.f5.com/manage/s/article/K000158940

Description

  • When deploying F5 Container Ingress Services (CIS) with Cilium CNI in static routing mode, CIS requires specific node annotations to create static routes for pod network traffic. Without these annotations, the following warning appears in CIS logs:
WARNING: Cilium node podCIDR annotation not found on node <node-name>, node has spec.podCIDR ?
  • This issue occurs because newer versions of Cilium do not automatically add the required annotations that CIS uses to discover pod CIDR ranges.
  • While the pod CIDR information exists in the node's spec.podCIDR field, CIS specifically looks for Cilium-specific annotations to configure routing.

Environment

  • Product: F5 Container Ingress Services (K8S-BIGIP-Ctlr)
  • Versions: 2.16.1, 2.20.2, and later
  • CNI: Cilium v1.17.4 or later
  • Kubernetes: v1.33.2 or later
  • Configuration Requirements:
    • static-routing-mode: true
    • orchestration-cni: cilium-k8s
    • pool_member_type: cluster

Cause

  • Newer versions of Cilium do not automatically populate the io.cilium.network.ipv4-pod-cidr or network.cilium.io/ipv4-pod-cidr annotations on Kubernetes nodes.
  • CIS depends on these annotations to read the pod CIDR range and create corresponding static routes on the BIG-IP device.

Recommended Actions

  1.  Retrieve the pod CIDR from the node specification:
kubectl get node <node-name> -o yaml | grep podCIDR
  1. 2. Add the Cilium pod CIDR annotation to each node:
kubectl annotate node/ <node-name> io.cilium.network.ipv4-pod-cidr=<pod-cidr>

For example

kubectl annotate node ciliumk8s-ubuntu-server io.cilium.network.ipv4-pod-cidr=10.42.0.0/16

Note: Use the appropriate annotation format based on your Cilium version:

  • io.cilium.network.ipv4-pod-cidr (newer versions)
  • network.cilium.io/ipv4-pod-cidr (older versions)

Verify F5 CIS has created the static route on the BIG-IP device:

tmsh list net route

Expected output:

net route k8s/-<node-name>-<node-ip> {
    description <virtual-server-ip>
    gw <node-ip>
    network <pod-cidr>
    partition kubernetes
}

Verify routing information to pod

ip r get <pod-ip>

Expected output

<pod-ip> via <node-ip> dev Internal src <F5_Self_IP>

Additional Information

  • CIS automatically detects which annotation format to use (io.cilium.network.ipv4-pod-cidr or network.cilium.io/ipv4-pod-cidr) based on the cilium version
  • The node IP address is parsed from node.Status.Addresses in the node manifest
  • After adding the annotation, CIS automatically creates static routes without requiring a controller restart
  • This configuration is only required when using CIS in static routing mode with Cilium CNI
  • The annotation must be present before deploying applications that require routing through CIS
  • If nodes are added dynamically to the cluster, ensure the annotation is added as part of the node provisioning process
