K000150730: Recovery procedure for HA availability FIPS sync failure caused by defect ID 1136081

Type
Support Solution
Published
2025-04-04
Updated
2025-04-04
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.5
Source
https://my.f5.com/manage/s/article/K000150730

Description

A fipscardsync (fips-card-sync) error, similar to the example below, may occur when attempting to synchronize FIPS in a High Availability (HA) setup between an existing unit and an RMA new replacement unit:

DEBUG: source_generate: Cfm2CloneSourceStage1 returned: 0xad (HSM Error: Operation Failed. Invalid inputs passed)

ERROR: Synchronization failed.

This is because FIPS devices initialized on older specific software versions are not compatible with those initialized on newer releases. 

Environment

  • LTM
  • HA
  • FIPs (HSM)

Cause

Bug ID 1136081: HSM sync issue in high availability (HA) setups

Recommended Actions

To ensure successful FIPS synchronization between a unit originally initialized on a software version unaffected by ID 1136081 and a newer replacement (RMA) unit that includes the fix for ID 1136081 (i.e., versions prior to 16.1.1, 15.1.5.1, 14.1.4.6, 13.1.5), the FIPS on the RMA unit must first be initialized using an older, unaffected software version.

After FIPS initialization, the (RMA) unit should then be upgraded to the desired later version that includes the fix, ensuring it matches the peer unit.

The outlined steps follow a two-phase process:

  • Phase (1) addresses the FIPS sync failure, enabling a successful synchronization upon completion. 
  • Phase (2) involves upgrading FIPS to the latest release version to enhance security.

Note: These steps are intended solely for execution on the newly received RMA device.

 Phase-1

  1. Setup a new boot volume running BIGIP-15.1.5-0.0.10 (A release unaffected by ID 1136081).
  2. Boot into the new BIGIP-15.1.5-0.0.10 boot volume.
  3. Delete the original boot location.
  4. Execute "tmsh stop sys service all".
  5. Execute "fipsutil reset".
  6. Execute "fipsutil init".
    Note: Set the Security Domain and Officer passwords to match those of the active unit.
  7. Execute "bigstart restart".
  8. Set up a new boot location identical (Software version) to the active unit..
  9. Reboot to the newly created boot location identical (Software version) to the active unit.
    Note: Set the system master key to be identical to that of the peer unit. For further information, see: K9420: Installing UCS files containing encrypted passwords or passphrases (11.5.x and later)
  10. Execute the `fipscardsyn` from the 'Active' source device to the new replacement unit.
    Note: Multiple attempts at FIPS card synchronization may be required before a successful sync is achieved.
  11. You can either restore a UCS file, which should succeed since the SIM master key (required to decrypt the UCS backed-up FIPS keys) was transferred using the `fipscardsync` utility, or follow the steps detailed in K11452958.

Phase-2 

  1. Upgrade to the latest FIPs firmware (both units). For more information, refer to - Manual Chapter : Platform and VE FIPS Module and Upgrade Notes

To check the FIPS firmware version of each unit, use the command: 

tmsh run util fips-util info

Additional Information

This article outlines a lower-risk recovery procedure (while operating with only a single unit) that follows a two-phase approach..  

An alternative approach would involve upgrading FIPS (of the single standalone unit) to the latest release compatible with the FIPs of the new replacement (RMA) unit.  

For further details, refer to the "Fix Information" provided here: - Bug ID 1136081: HSM sync issue in high availability (HA) setups
