Description

This issue is related to an AFM object created from iApp. The iApp object has been removed.

When running tmsh load sys config verify the following error message will be seen.

Can't associate firewall IP address list (/partition/folder/file) folder does not exist


For example if the partition is Common, the folder is the name of the iApp such as example-test and the file is the allowlist filename such as fw__example-test.example.com__443__allowlist; the full error message would be:

01070734:3: Configuration error: Can't associate firewall IP address list (/Common/example-test.app/fw__example-test.example.com__443__allowlist) folder does not exist
Unexpected Error: Validating configuration process failed.

Environment

  • BIG-IP
  • AFM
  • Created iApp has been removed

Cause

When the iApp has been removed, some of its object is still in the configuration file. The folder has been deleted but the configuration is still showing the same folder.

Recommended Actions

To resolve the issue, you can edit the bigip_base.conf file to remove the iApp objects or re-create the delete iApp. To do so, follow on of the following procedures:

  • Remove iApp objects from bigip_base.conf
  • Re-create the deleted iApp (can only be done before an upgrade)
Remove iApp objects from bigip_base.conf
  1. Login to the Command Line.
     
  2. Navigate to /config by typing the following command:
    cd /config
     
  3. Make a copy of the bigip_base.conf with the following command:
    cp bigip_base.conf bigip_base.conf.backup
     
  4. Edit the bigip_base.conf file.
    vim bigip_base.conf
     
  5. Delete all object related to the iApp name. This includes all items in the curly bracket. For example if the iApp name is example-test, you will need to delete all object as below:
    XXXX example-test {
    ...
    }
     
  6. Save and exit the editor.
     
  7. Run the following command to verify if the config file has been corrected.
    tmsh load sys config verify
     
  8. If the is no error on the configuration file, you can proceed to load it.
Re-create the deleted iApp
Note: This option solution can only be done before an upgrade. After an upgrade or a reboot, the configuration will not load and you will not be able to create this iApp correctly.
  1. Login to the GUI
     
  2. Navigate to iApps > Templetes
     
  3. Click Create
     
  4. Create the identical iApp with the same name
     
  5. Save the iApp
     
  6. Login to the Command Line
     
  7. Run the following command to confirm if issue has been resolved
    tmsh load sys config verify
