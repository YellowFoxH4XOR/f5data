K64624004: Connection is reset when sending a HTTP HEAD request to APM Virtual Server

Type
Support Solution
Published
2021-08-05
Updated
2023-02-21
Applies to
  • BIG-IP
  • F5 Access
  • BIG-IP APM: 15.1.X, 15.0.X, 15.1.0, 15.0.1, 15.0.0, 15.1.8, 15.1.7, 15.X.X, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.6
Source
https://my.f5.com/manage/s/article/K64624004

Description

In certain circumstances one may need to monitor or probe a virtual server.  However, under the following circumstances a connection reset may happen:

  • You are externally monitoring an APM virtual server
  • You are probing such a virtual server with tools such as curl

Environment

  • A virtual server with APM implemented
  • A HTTP HEAD request is sent to the aforementioned virtual server (for instance, using 'curl -k -L --head https://<VS IP>' or an external monitor similarly configured)
  • Big IP 15.x or later

Cause

F5 have identified the issue and are tracking this with ID 1010809.

Recommended Actions

To work around this issue, implement the following iRule on your virtual server:

when HTTP_REQUEST priority 500 {
    if {[HTTP::method] equals "HEAD"
       && [HTTP::path] equals "/"} {
        HTTP::respond 404
    }
}

If necessary, you may alter the HTTP::respond to your needs.
