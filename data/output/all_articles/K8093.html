Topic

Internet Explorer 5.0 through 8.0 may report downloading issues when you attempt to download files such as Office documents or PDF files over a Secure Sockets Layer (SSL) connection. This issue occurs when the server sends a Cache-control:no-store, Cache-control:no-cache, or Pragma:no-cache header in the response. As a result, Internet Explorer cannot allow you to download and save the file.

This issue is documented in the following Knowledge Base article:

  • KB323308 - Internet Explorer file downloads over SSL do not work with the cache control headers

These headers are used to prevent proxy devices from caching a local copy of the file when handling connections.

To prevent this behavior from occurring, you can disable the use of the Cache-control headers for specific downloads on the server. Alternatively, you can use an iRule to change the value of the header.

For example:

when HTTP_RESPONSE {
   if { [HTTP::header value Content-Type] contains "application/pdf" } {
      HTTP::header replace Pragma public
      HTTP::header replace Cache-Control public
   }
   elseif { [HTTP::header value Content-Type] contains "application/vnd.ms-excel" } {
      HTTP::header replace Pragma public
      HTTP::header replace Cache-Control public
   }
   elseif { [HTTP::header value Content-Type] contains "application/msword" } {
      HTTP::header replace Pragma public
      HTTP::header replace Cache-Control public }
   else {
      return
   }
}

When the example iRule is associated with a virtual server that is handling HTTP traffic, HTTPS traffic (if terminated on the BIG-IP system) looks for the Pragma (HTTP 1.0) or Cache-control (HTTP 1.1) headers and replaces the no-cache or no-store directive with public. This behavior allows Internet Explorer to download Office documents or PDF files over an HTTPS connection.

Note: For more information about the HTTP::header command, refer to the DevCentral wiki page.  A DevCentral login is required to access this content.
