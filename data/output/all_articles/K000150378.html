K000150378: 502 Error Due to Content-Length Header in 1xx or 204 Responses on F5 Distributed Cloud

Type
Support Solution
Published
2026-06-30
Updated
2026-06-30
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000150378

Description

A 502 Bad Gateway error occurs when the upstream server sends a Content-Length header in a response with a status code of 1xx (Informational) or 204 (No Content). The error log includes:

upstream_reset_before_response_started{protocol_error}

"upstream_protocol_error_reason": "http/1.1_protocol_error:_content_length_not_allowed_in_1xx_or_204"

Environment

  • Product: F5 Distributed Cloud (Web App & API Protection)
  • SaaS environment

Cause

The origin server violates RFC 9110 by including a Content-Length header in responses with status codes 1xx or 204.

Answer/Recommended Actions

  • Update the application or origin server configuration to ensure no Content-Length header is included in responses with status codes 1xx or 204.
  • Adjust application logic or server response handling to comply with RFC 9110.
  • Bypassing or allow-listing this behavior for specific URLs is not possible, as it would violate RFC standards.

Additional Information

This behavior is enforced for protocol compliance. F5 Distributed Cloud will return a 502 error if the upstream server does not adhere to RFC 9110 requirements.
