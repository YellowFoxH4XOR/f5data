Known Issue

The Thales client install does not work with the existing remote file system (RFS) that has non-root access.

This issue occurs when the following condition is met:

  • While installing the Thales nethsm client software onto the BIG-IP system, you do not have the root login information for the RFS server.

Impact

You cannot install the Thales nethsm client software using the provided scripts.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The Thales client install does not work with the existing RFS that has non-root access.

Workaround

To work around this issue, you can refer to the following to install the nethsm client software:

Impact of workaround: The following workaround methods should not have a negative impact on your system.

  • As long as the RFS user can run the following command syntax, the existing script will work, even if the user is non-root:

    /opt/nfast/bin/rfs-setup --force -g --write-noauth <BIG-IP IP address>

  • If the BIG-IP system cannot log in to the RFS, you must supply a dummy login for the RFS, because the unpatched script requires an SSH user name and will always attempt to log in to the RFS.

    With a dummy login, although this step fails, the script attempts to recover, as follows:

    • Instructs you to manually run the following command syntax on the RFS:

      /opt/nfast/bin/rfs-setup --force -g --write-noauth <BIG-IP IP address>

    • Asks whether the command completed successfully.
  • As long as you run the previous command on the RFS before starting or continuing the Thales installation, the operation should complete without issue.

    Note: You can run the command on the RFS before you run the Thales installation script on the BIG-IP system.
