Description

Unable to send large packets over IPsec network. Connection over IPsec timed out.

Cause

Potential packet loss and connection failure where oversized ESP frames attempt to traverse a smaller MTU network and cannot be fragmented.

IPsec end points do not participate in path MTU discovery (PMTUD). This is by design.

ICMPv4 unreachable packets with type 3 ("destination unreachable") code 4 ("fragmentation needed") destined to the IPsec endpoint identifying an ESP packet will be dropped and not acted upon. ICMPv6 type 2 ("Packet to big") are treated similarly. Additionally, the IPsec interface tunnel will not generate ICMPv4 type 3 code 4 or ICMPv6 type 2 back towards the sender of the large packet.

Defect ID1311977 applies.

Environment

  • BIGIP as IPsec endpoint connecting to a remote IPsec peer (BIGIP or third party)
  • Traffic to be encrypted has the don't fragment (DF) bit set
  • Network with differing MTU sizes or changes made to MTU size
  • IPv4 or IPv6

Recommended actions

  • Configure suitable smaller MTU size on ingress interface(s) that forward data into the IPsec interface tunnel. This will affect all other traffic ingress to the configured interfaces, not just that which is passed to IPsec.
  • For TCP traffic, configure an appropriate MSS to ensure that fragmentation is not required. Note that IPsec encapsulation will add typically 80-90 bytes of overhead. Third party tools (such as https://ipsec-overhead-calculator.netsec.us/) should give a more accurate value if required. Allowing for an overhead of 100 bytes should suffice in most cases.
  • For UDP traffic,  there is currently no other solution until defect ID1311977 is resolved.
