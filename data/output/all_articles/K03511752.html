Description

Upgraded BIG-IP failed to load configuration, with a message similar to the following seen in /var/log/audit:

notice tmsh[10416]: 01420002:5: AUDIT - pid=10416 user=root folder=/Perimeter module=(tmos)# status=[01070920:3: Application error for confpp: [<date>] [core:warn] [pid 11546] AH00114: Useless use of AllowOverride in line 284 of /var/run/config/httpd.conf. [<date>] [core:warn] [pid 11356] AH00114: Useless use of AllowOverride in line 12 of /etc/httpd/conf.d/xui.conf. Syntax OK 139663064794800:error:0607907F:digital envelope routines:EVP_PKEY_get1_RSA:expecting an rsa key:p_lib.c:287: /usr/bin/openssl command failed. Please ensure your key is not encrypted. Reloading syslog-ng: Restarting ntpd (via systemctl): [ OK ] Stopping dhclient (via systemctl): [ OK ] Stopping dhclient6 (via systemctl): [ OK ]] cmd_data=load sys config partitions all base

The /var/log/httpd/httpd_errors file also shows:

ECC certificate configured for 127.0.0.1:443 does NOT include an ID which matches the server name

The /var/log/ltm file shows an unhelpful error, such as:

err tmsh[10416]: 01420006:3: 01070734:3: Configuration error: Current folder /Prod has been removed. Exit session.
emerg load_config_files[10914]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Loading schema version: 16.1.0

Note: There is no issue with the partition/folder listed.

Environment

  • After upgrade
  • httpd

Cause

This indicates an issue with /config/httpd/conf/ssl.key/server.key. Specifically, it indicates an EC key is in use, which is not supported at the time of this article's publication. Only RSA certificate and key pairs are supported for httpd on the BIG-IP.

This issue will not immediately occur if httpd is restarted on its own after applying an EC key, it will only occur after the configuration is reloaded (for example, after an upgrade).

Recommended Actions

Follow the steps in K9114 to generate a new self-signed RSA certificate and key pair.

Alternatively, you can work around the immediate issue by applying an RSA certificate and key pair, loading the configuration, re-applying the EC certificate and key pair, then restarting httpd. Note that this is not supported and subsequent upgrades will break in the same way described in this article.
