Known Issue

This is the result of a known issue. When a BIG-IP virtual server is configured with a server SSL profile for SSL re-encryption, and the pool member requests a client SSL certificate, the BIG-IP system closes the connection and does not send the client certificate.

F5 Product Development tracked this issue as CR47702 and it was fixed in BIG-IP LTM 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can work around this issue by specifying ALL:!NATIVE as the cipher in the server SSL profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. From the SSL menu, select Server.
  5. Click the server SSL profile used by the virtual server.

    Note: If your virtual server references the default server SSL profile, F5 Networks recommends creating a new profile rather than changing the default profile.
  6. From the Configuration drop-down menu, select Advanced.
  7. In the Ciphers box, enter the following:

    ALL:!NATIVE

    Note: You can still construct a more secure cipher suite if necessary, by appending additional restrictions to the string.

    For example:

    ALL:!NATIVE:!ADH:!SSLv2:!EXPORT40:!EXP:!LOW
  8. Click Update.
