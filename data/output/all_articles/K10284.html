Issue

Note: This article only applies when usage of the bigpipe command resulted with this error message. For a similar error message that occurs when using tmsh command, refers to K14364: Error Message: 01070826:3: Current Update Partition Error: The current update partition does not match the object's partition.

Error Message

BIGpipe <TypeOfObject> modification error:
   01070826:3: Current Update Partition Error: The current update partition (<PartitionName-1>) does not match the object's partition (<PartitionName-2>) (<TypeOfObject>) (<ObjectIdentifier>)

In this error message, note the following:

  • <TypeOfObject> is the type of object. For example pool, VLAN, or virtual.
  • <PartitionName-1> is the name of the current update partition that is set on the user's shell partition write access.
  • <PartitionName-2> is the name of the partition to which the object belongs.
  • <ObjectIdentifier> is the name of the object failed to be modified.

For example:

BIGpipe pool modification error:
   01070826:3: Current Update Partition Error: The current update partition (ResourceA) does not match the object's partition (ResourceB) (pool) (BBpool-1)

Message Location

You may encounter this message in the following locations:

  • Command line
  • Bigpipe shell

Description

This message occurs when either one of the following conditions is met:

  • The current user's write access of the shell partition setting does not match the partition to which the object belongs.
  • For 9.x, when the current user's write access matches the object partition, but the read access is accessing to all partitions.

When you use a bigpipe command with the all option, the command may attempt to modify all objects that the system is able to read based on the user's read access in the shell partition setting. The write access of the shell partition can only be set to one administrative partition at any one time.

For the root user of the BIG-IP system, the default shell partition setting for bigpipe is configured to have read access to all partitions, and have write access to common partition.

For a non-root user with advance shell access or bigpipe shell access, the default shell partition setting is configured to have read access to all partitions, and write access to only one or all partitions, depending on the user configuration setting.

To verify the current shell partition setting, perform one of the following actions:

  • From the command line prompt, type the following command:

    bigpipe shell partition show
  • From the bigpipe shell prompt, type the following command:
     
    shell partition show

For the root user, the output may appear similar to the following example:

SHELL - partition: all (read)   Common (write)

Impact

When you encounter the error message, the execution of the bigpipe command is aborted and no objects are modified.

Recommended Actions

  • If the user did not have the correct write access set to the current update partition, you are required to modify the write access to the correct administrative partition before performing the bigpipe command.

    To change the write access, perform one of the following steps:

    • From the command line prompt, use the following command syntax:

      bigpipe shell write partition <PartitionName>

    • From the bigpipe shell prompt, use the following command syntax:

      shell write partition <PartitionName>
  • For 9.x, if the user has the correct access to the current update partition, the user's shell partition read access is required to set to match the write access before performing the bigpipe command.

    To change the read access perform one of the following steps:

    • From the command line prompt, use the following command syntax:

      bigpipe shell read partition <PartitionName>

      In this command, note the following:

      • <PartitionName> is the name of the partition to which the object belongs.
    • From the bigpipe shell prompt, use the following command syntax:

      shell read partition <PartitionName>

      In this command, note the following:

      • <PartitionName> is the name of the partition to which the object belongs.
