Description

When accessing a backend web application through BIG-IP APM Portal Access, the rewrite engine generates requests to a malformed host by appending the "f5-h-" token directly to the portal virtual server FQDN (e.g., "vpn.example.comf5-h-") without a separator. This results in the host resolving to a reserved address, causing APM to deny the request with errorcode=17. The issue is observed in applications using AngularJS and serving a <base href> tag. Other applications using the same access profile may function correctly.

Error/Log messages:

APM log: 01490585:5: /EXTERNO/SAML_APM_ANS:EXTERNO:: Access to vpn.example.comf5-h- rejected because it points to reserved address.

Browser DevTools: Malformed host in rewritten requests, 302 redirect to /vdesk/my.acl.php3?errorcode=17.

Environment

  • Product: BIG-IP APM
  • Portal Access with SAML authentication
  • Backend application uses AngularJS and serves a <base href> tag
  • Resource patching enabled (HTML, JavaScript, CSS, Flash; Java disabled)
  • Modern JavaScript features (ES8+) may be present in the application

Cause

Known limitation in the APM Portal Access rewrite engine: when the backend application serves a <base href> tag, the rewrite engine concatenates the portal FQDN with the "f5-h-" token without a separator, producing an invalid host. Additionally, the use of ES8+ JavaScript features in the application is not supported by the rewrite engine, further contributing to the failure.

Answer/Recommended Actions

  1. Verify if the backend application serves a <base href> tag. If possible, remove or modify it.
  2. Configure Modern rewrite mode for the affected application using a Rewrite Control List (RCL) entry:
    • Go to Access › Connectivity / VPN : Portal Access : Rewrite.
    • Edit the Rewrite Profile and enable Split Tunneling to expose the RCL section.
    • Add a Rewrite Control List entry:
      • Mode: Modern
      • Protocol: Any
      • Host Match: (e.g., unifi.example.com or ansprunifi.example.com)
      • Path Match: Any String
  3. If Modern mode does not resolve the issue, apply the latest cache-fm-Modern.js file as per F5 guidance.
  4. If the application relies on ES8+ JavaScript features or dynamic imports, migrate to LTM+APM (Web Access Management) mode, which does not perform content rewriting and supports modern JavaScript frameworks.

Additional Information

  • The issue is specific to applications serving a <base href> tag and/or using modern JavaScript features not supported by the Portal Access rewrite engine.
  • LTM+APM mode is the supported alternative for applications requiring ES8+ JavaScript compatibility.
