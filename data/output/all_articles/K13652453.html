Description

You are using a BIG-IP LTM to load balance DNS traffic between your DNS pools (servers).

One of your DNS pool member is flapping from online to offline.

You are using a DNS monitor (or UDP monitor acting as a DNS monitor) for all your DNS pool but only one pool member is flapping.

This issue is seen on your peer BIG-IP LTM in a HA pair.

Environment

  • BIG-IP LTM
  • BIG-IP LTM is used to load balance DNS traffic between multiple DNS servers
  • Only one DNS server is flapping while others are stable (online)
  • Using a DNS monitor to monitor the DNS pool
  • Same issue is seen on the BIG-IP peer which is in HA pair

Cause

This issue is related to the DNS server and not a BIG-IP issue. You will need to do a tcpdump to understand the issue further.

Recommended Actions

To get a better understanding on why the DNS pool member is flapping, you will need to do a tcpdump during the issue.

  1. Login to the Command Line.
  2. Run a tcpdump as per K411.
    An example of the tcpdump command is as below:
    tcpdump -vni 0.0 -s0 -w /var/dns-ip.pcap host <client_ip>
    If the DNS pool member is 10.10.10.10, the command would be:
    tcpdump -vni 0.0 -s0 -w /var/dns-ip.pcap host 10.10.10.10
  3. Run the pcap when the issue is happening.
  4. To stop the tcpdump type Ctrl + c.
  5. Download the pcap to your local machine at /var/dns-ip.pcap. Use scp to transfer as per K175.
  6. From you local machine, use Wireshark to open the pcap file.
  7. Identify if the DNS pool member if responding to each DNS request.
  8. If it is, verify if the DNS pool member is responding in a timely manner with the following Wireshark filter
    dns.time >0.3
    Important: DNS response should never be more than 0.3 seconds. A DNS response higher than 0.3 seconds is not a desired behaviour and will have a negative impact.
  9. Provide the pcap and your findings to the DNS administrator for further investigation.
