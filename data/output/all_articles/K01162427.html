Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file when processing a Message Passing Interface (MPI) message with an invalid length. This issue occurs under rare internal conditions.

Impact

The tmm process reaches excessively high CPU utilization levels, up to 100 percent utilization, and eventually restarts. If the BIG-IP system is part of a redundant configuration, traffic fails over to the standby BIG-IP system while TMM restarts. If the BIG-IP system is not part of a redundant pair, traffic is interrupted while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails over to another system in the device group.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system temporarily fails to process traffic while TMM restarts.
  • Messages similar to the following example are logged to the /var/log/tmm files:

    notice MPI stream: connection to node 127.20.2.3 expired for reason: Internal error (bad magic) (mpi_proxy.c:664)

  • The sod process restarts TMM when it reaches excessively high CPU utilization levels, becomes unresponsive, and fails to send its daemon heartbeat. When this symptom occurs, messages similar to the following example are logged to the /var/log/ltm files:

    notice sod[1234]: 01140029:5: HA daemon_heartbeat tmm fails action is go offline down links and restart.
