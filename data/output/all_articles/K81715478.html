Issue

Error Message

At least one primary shard (and all of its replicas) are missing. This means that you are missing data; searches will return partial results, and indexing into that shard will return an exception.

Message Location

You may encounter this message in the following location:

  • The BIG-IP Health indicator under the Status section on the BIG-IQ Data Collection Cluster Summary page.

    Note: Go to System > BIG-IQ Data Collection > BIG-IQ Data Collection Cluster > Summary > Status in the BIG-IQ user interface.

Description

This message occurs when one or more of the following conditions are met:

  • You've recently upgraded your BIG-IQ system(s).
  • You use the self IP address as the discovery address for the data collection device (DCD), and the elasticsearch process is not stopped properly before a restart.
  • You attempt to remove the last logging node from the data collection cluster (DCC).

If the upgrade instructions are not precisely followed, there is a chance that data corruption may occur. It is possible that the database and search services are cleanly not shut down. When using the self IP as the discovery address from the DCD, manually stop the elasticsearch process before restarting, as part of the upgrade preparation process to prevent index corruption. For more information, refer to the Supplemental Information section of this article.

Impact

Statistical data no longer displays in the BIG-IQ user interface.

Recommended Actions

Important: In BIG-IQ 8.0.0 and later, TLS encryption has been enabled between ElasticSearch nodes in the cluster. As a result, you would need to add the -k flag to the curl command, and prepend https:// to the URL.

Resetting the data collection cluster

To recover the system from this error, you can remove and re-add the DCDs. To do so, perform the following procedure; however, if the BIG-IQ system does not recover from the error, return to this article for the next actions to take:

  1. Follow the steps in K02014651: Removing a DCD association from BIG-IQ Centralized Management.
  2. If the BIG-IQ system does not recover from the error after you have performed the procedure in K02014651, you can enter the following commands on the BIG-IQ system to get information about the health of the DCD cluster, the CPU load on each DCD, the amount of storage used or available on each DCD, and the number of unassigned shards:

    BIG-IQ 8.0.0 and later

    curl -s -k https://localhost:9200/_cluster/health?pretty
    curl -s -k https://localhost:9200/_cat/nodes?v
    curl -s -k https://localhost:9200/_cat/allocation?v
    curl -s -k https://localhost:9200/_cluster/allocation/explain?pretty

    BIG-IQ 7.1.0 and earlier

    curl -s localhost:9200/_cluster/health?pretty
    curl -s localhost:9200/_cat/nodes?v
    curl -s localhost:9200/_cat/allocation?v
    curl -s localhost:9200/_cluster/allocation/explain?pretty

Based on the information from the output of cluster commands, you can decide to reroute the unassigned shards to other available DCDs or delete the unassigned shards if your application environment allows and re-setup from scratch. To do so, perform one of the following procedures:

Rerouting the unassigned shards to other available DCDs (BIG-IQ 6.x and later)

Impact of procedure: The BIG-IQ Centralized Management data collection and search services become temporarily unavailable during this process.

  1. Log in to bash on the BIG-IQ system with administrator credentials.
  2. List the unassigned shards by entering the following command: 

    BIG-IQ 8.0.0 and later

    curl -s -k https://localhost:9200/_cat/shards | grep UNAS

    BIG-IQ 7.1.0 and earlier

    curl -s http://localhost:9200/_cat/shards | grep UNAS

    The following output shows an example of an unassigned shard:

    statistics_tl0_bigip-pool-members_2019-045-07    3 r UNASSIGNED

    Note the index name and shard number as you need this information for the next step. Using the previous example, the index name is statistics_tl0_bigip-pool-members_2019-045-07 and the shard number is 3.

  3. Reroute an unassigned shard using the following command syntax: 

    BIG-IQ 8.0.0 and later

    curl -s -k https://localhost:9200/_cluster/reroute -H "Content-type: application/json"  -d '{"commands": [{"allocate_replica":{"index":"<INDEX_NAME>","shard":<SHARD_NUMBER>,"node":"<NODE_NAME>"}}]}'

    BIG-IQ 7.1.0 and earlier

    curl -s http://localhost:9200/_cluster/reroute -H "Content-type: application/json"  -d '{"commands": [{"allocate_replica":{"index":"<INDEX_NAME>","shard":<SHARD_NUMBER>,"node":"<NODE_NAME>"}}]}'

    Note: <INDEX_NAME> and <SHARD_NUMBER> are determined from the previous step while <NODE_NAME> is the IP address of the available DCD you want.

    For example, to reroute the DCD with IP address 192.168.10.10, you would use the following command:

    BIG-IQ 8.0.0 and later

    curl -s -k https://localhost:9200/_cluster/reroute -H "Content-type: application/json" -d '{"commands": [{"allocate_replica":{"index":"statistics_tl0_bigip-pool-members_2019-045-07","shard":3,"node":"192.168.10.10"}}]}'

    BIG-IQ 7.1.0 and earlier

    curl -s http://localhost:9200/_cluster/reroute -H "Content-type: application/json" -d '{"commands": [{"allocate_replica":{"index":"statistics_tl0_bigip-pool-members_2019-045-07","shard":3,"node":"192.168.10.10"}}]}'

  4. Repeat step 3 for the remaining unassigned shards.

Deleting the unassigned shards
Impact of procedure: Deleting the unassigned shards remove parts of the statistics data. Proceed to do so if you are fine with losing the statistics data.

  1. Log in to bash on the BIG-IQ system with administrator credentials.

  2. Delete the unassigned shards by entering the following command:

    BIG-IQ 8.0.0 and later

    curl -s -k https://localhost:9200/_cat/shards | grep UNAS | awk '{print $1}' | sort | uniq | sed 's/+/%2B/g' | while read line ; do curl -s -k -X DELETE "https://localhost:9200/$line" ; done

    BIG-IQ 7.1.0 and earlier

    curl -s http://localhost:9200/_cat/shards | grep UNAS | awk '{print $1}' | sort | uniq | sed 's/+/%2B/g' | while read line ; do curl -s -X DELETE "localhost:9200/$line" ; done
