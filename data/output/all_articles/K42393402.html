Known Issue

When using the Traffic Management Shell (tmsh) to modify the icmp_enabled or arp_enabled property of a virtual address object, the Traffic Management Microkernel (TMM) does not reset the internal state properly. As a result, TMM uses the Virtual Local Area Networks (VLAN) true Media Access Control (MAC) address as the source MAC instead of the traffic group's MAC masquerade address.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured in a high-availability (HA) environment.
  • You have configured the MAC masquerade address in a traffic group.
  • You change the icmp_enabled or arp_enabled options from false to true, and back to false.

Impact

Switches may drop packets or routing tables may be incorrectly updated.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The TMM process uses the VLANs true MAC masquerade address as the source MAC address, rather than the traffic group's MAC masquerade address.
