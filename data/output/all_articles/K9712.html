Known Issue

This is the result of a known issue. After repeated sync operations, the wideip.conf file may be deleted and replaced with a blank configuration with no objects defined. If the blank configuration then propagates to the other BIG-IP GTM peers, the sync group's configuration will be wiped out and all DNS traffic may be dropped.

BIG-IP GTM systems with the AutoDiscovery feature enabled will perform repeated BIG-IP GTM sync operations with the other members of its sync group every 30 seconds, when either of the following conditions is true:

  • The BIG-IP GTM configuration references a BIG-IP redundant pair with an inconsistent configuration (differences between the virtual servers configured on each member of the pair)
  • The BIG-IP GTM configuration references separate BIG-IP systems that host apparently redundant virtual server objects, such as virtual servers that share the same virtual server name, or the same virtual server destination IP and port combination

This behavior is an attempt by the BIG-IP GTM auto-configuration and synchronization processes to resolve the apparent discrepancies between the configuration items in question.

F5 Product Development tracked this issue as CR117813, and it was fixed in BIG-IP GTM 9.4.7 and 10.1.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You can work around this issue by ensuring that BIG-IP redundant pairs referenced by the BIG-IP GTM system are always synchronized after adding or deleting virtual servers, and by using unique object names and addresses for virtual servers hosted on separate BIG-IP systems.
