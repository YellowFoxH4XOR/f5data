Known Issue

The default value of the ACCESS::restrict_irule_events command may change when you configure a VDI profile.

This issue occurs when the following condition is met:

  • You have configured a BIG-IP APM virtual server with a VDI profile.

By default, the ACCESS::restrict_irule_events command is set to enabled. However, when configuring a VDI profile, the value changes to disable.

Impact

HTTP and higher layer iRules events are not triggered during access policy evaluation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Office Forms Based Authentication (OFBA) implemented by way of the _sys_APM_MS_Office_OFBA_Support iRule fail.
  • In the /var/log/ltm file, you observe error messages that appear similar to the following example:

    err tmm[<pid>]: 01220001:3: TCL error: /Common/stream_vdi_debug <HTTP_RESPONSE> - Operation not supported (line 15)     invoked from within STREAM::expression "@$matchstring@$replacestring@" ".
    err tmm[<pid>]: 01220001:3: TCL error: /Common/stream_vdi <HTTP_REQUEST> - Operation not supported (line 1)     invoked from within "STREAM::disable".

  • iRules commands for higher layer events are not triggered during access policy evaluation.

Workaround

To work around this issue, you can manually set the ACCESS::restrict_irule_events command value to enable. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Select the iRule that triggers higher layer events.
  4. At the beginning of the iRule, add the following lines:

    when CLIENT_ACCEPTED {
      ACCESS::restrict_irule_events enable
    }

  5. Click Update.
