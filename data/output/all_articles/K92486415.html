Known Issue

The BIG-IP ASM system creates empty policy history files that prevent the system configuration from loading after an upgrade.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM file system disk becomes full.
  • You make changes to existing policies.

Empty policy history files are zero-byte files and considered corrupted. Existence of these files can prevent the BIG-IP ASM system from loading the configuration after an upgrade.

Impact

During upgrade, the bd process repeatedly exits and prevents the configuration from loading.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice the existence of empty policy history files in the /ts/dms/policy/policy_versions directory.
  • When you attempt to upgrade the BIG-IP ASM system, you observe messages similar to the following example in the /var/log/ts/ts_debug.log file:

    asm|INFO|...Can't call method "policy_name" on an undefined value at /usr/local/share/perl5/F5/PolicyHistory.pm line 134.

  • You observe that the bd process repeatedly exits and produces core files in the /var/core directory.

Workaround

To work around this issue, you must first address the cause of the disk-full condition. For more information, refer to K14403: Maintaining disk space on the BIG-IP system (11.x - 13.x). After the system disk is no longer full, you can remove the empty policy history files and perform the upgrade. To do so, perform the following procedure:

Impact of workaround: The following procedure requires you to restart your system from the previously active boot location.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Restart your system from the previously active boot location, using the following command syntax:

    reboot volume <volume name>

    For example, to restart from a volume named HD1.1, type the following command:

    reboot volume HD1.1

  3. After the system restarts, log in to the Advanced Shell (bash).
  4. Locate empty policy history files by typing the following command:

    find /ts/dms/policy/policy_versions/ -size 0

    If a zero-byte file exists in the directory, the output appears similar to the following example:

    /ts/dms/policy/policy_versions/8/57.plc

  5. Delete each discovered empty policy history file using the rm command.

    For example:

    rm/ts/dms/policy/policy_versions/8/57.plc

  6. Repeat steps 4 and 5 until you have deleted all existing empty policy history files.
  7. Perform the upgrade and restart your system from the newly upgraded boot location.
