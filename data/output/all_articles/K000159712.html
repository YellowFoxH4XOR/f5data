K000159712: The extra spaces between the HTTP header and value of the Web Acceleration profile

Type
Support Solution
Published
2026-01-27
Updated
2026-01-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source

Description

When the Web Acceleration profile is enabled on BIG-IP LTM, the Content-Length header in HTTP responses contains extra whitespace characters (typically 6-8 spaces) after the numeric value. This behavior occurs when responses are processed through the ramcache component.

  • Content-Length header appears as Content-Length: 26 (with multiple trailing spaces) instead of Content-Length: 26
  • The number of extra spaces varies (typically 6-8 spaces)
  • Issue is visible in packet captures when comparing responses with and without the Web Acceleration profile enabled
  • Behavior is consistent across multiple BIG-IP versions

Environment

  • HTTP profile attached to the virtual server
  • Virtual server with Web Acceleration profile applied
  • Responses being cached by the Web Acceleration (ramcache) module
  • Web Acceleration profile with cache-uri-include configured for specific URIs

Cause

Bug ID 886269- The ramcache component of the Web Acceleration profile adds extra space characters after the Content-Length header value when processing and caching HTTP responses.

Note: While RFC 7230 section 3.2.3 permits Optional Whitespace (OWS) after header values, RFC 2119 recommends that senders should generate only a single space. This behavior may cause issues with clients that do not properly handle the extra whitespace.

Recommended Actions

Option 1: Client-side handling (Recommended)

  • Verify if client applications can properly parse the extra whitespace as required by RFC 7230 compliance
  • If clients handle the whitespace correctly, no action is required

Option 2: iRule workaround

If client applications cannot handle the extra whitespace, implement the following iRule on the virtual server:

when HTTP_RESPONSE_RELEASE {
set content_len [string trim [HTTP::header value Content-Length]]
HTTP::header remove Content-Length
HTTP::header insert Content-Length "$content_len"
}

Important: The iRule workaround may increase CPU usage under heavy traffic conditions. Only implement the iRule if client applications experience parsing issues with the extra whitespace. Monitor CPU utilization after implementing the iRule in production environments.

Additional Information

  • RFC Compliance:
    • RFC 7230 Section 3.2.3 defines Optional Whitespace (OWS) rules for HTTP header fields, which technically permits the extra spaces
    • RFC 2119 defines the "SHOULD" keyword used in RFC 7230's recommendation for single-space generation, meaning there may be valid reasons to deviate but implications should be understood
  • Bug Status:
    • Bug ID 886269 was originally reported in 2020
    • No planned fix as of the time of this publication
