K000160541: How to Display Last Logon Time For End-Users When Connecting to Big-IP APM

Type
Support Solution
Published
2026-03-31
Updated
2026-03-31
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160541

Description

You'd like user's last login timestamp displayed on the APM login screen before the user connects to the VPN or authenticate further. The solution retrieves the lastLogon attribute from Active Directory, converts the Windows FILETIME format to a human-readable format, and adjusts the time to a preferred timezone, in this case Central European Time (CET).

Environment

  • Big-IP APM
  • Active Directory

Cause

None

Recommended Actions

To display the last login time in CET on the login screen, follow these steps:

(1) Configure AD Query in VPE

  • Add an AD Query action before AD Auth.
  • In the AD Query properties, add lastLogon to Required Attributes.
  • The value will be available as: session.ad.last.attr.lastLogon.

(2) Add an iRule Event to Convert Timestamp: 

  • Add an iRule Event action after the AD Query (before AD Auth).
  • Set Agent ID to lastLogon.
  • Attach the following iRule to the virtual server:
when ACCESS_POLICY_AGENT_EVENT {
    if { [ACCESS::policy agent_id] eq "lastLogon" } {
        set offset 11644473610
        set adtime "[ACCESS::session data get session.ad.last.attr.lastLogon]"
        if { $adtime ne "" && $adtime != 0 } {
            set secs [expr {($adtime / 10000000) - $offset}]
            set lastloginstr [clock format $secs -format "%Y-%m-%d %H:%M:%S CET"]
        } else {
            set lastloginstr "No previous login recorded"
        }
        ACCESS::session data set session.custom.lastLoginDisplay $lastloginstr
    }
}

(3) Add a Message Box to Display the Last Login

After the iRule Event, add a Message Box action in the VPE and configure the message to display:

Your last login was: %{session.custom.lastLoginDisplay}
Please click Continue to proceed with your VPN connection.

(4) Apply the Access Policy 

Additional information

(1) iRules do not natively handle time zones or daylight saving time, Manual adjustment is needed.

(2) Considerations for lastLogon vs. lastLogonTimestamp

  • lastLogon is not replicated across Domain Controllers; it reflects the last login on the specific DC queried.
  • lastLogonTimestamp is replicated but may lag up to 14 days.
  • Confirm with your AD team which attribute is best for your environment.
