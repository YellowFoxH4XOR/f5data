K000163182: F5 CIS declaration failure with error code 422 and logs "Invalid Virtual Address, the IP address already exists"

Published

Updated

Applies to

Source

Description

F5 Container Ingress Services (CIS) VirtualServer custom resources report an error when multiple CIS controllers watch the same custom-resource label and deploy the same configuration concurrently.

Typical errors include:

Invalid Virtual Address, the IP address already exists

Big-IP Responded with error code: 422 -- verify the logs for detailed error

[AS3][BigIP] post resulted in FAILURE

[AS3] Response from BIG-IP: code: 422

The F5 IPAM Controller may successfully allocate an address, and the virtual server may appear on BIG-IP, while the VirtualServer custom resource remains in an error state.

Environment

  • BIG-IP LTM managed by F5 Container Ingress Services.
  • F5 IPAM Controller used to allocate virtual addresses.
  • CIS VirtualServer custom resources configured with an IPAM label.
  • AS3 used to deploy the generated BIG-IP configuration.
  • Multiple CIS controllers configured to watch the same custom-resource label.

Example:

spec:
ipamLabel: TEST

Cause

Two or more CIS controllers are configured to watch the same custom-resource label. Each controller processes the same VirtualServer resource and attempts to deploy the same virtual address and related configuration to BIG-IP.

This concurrent processing creates a race condition. One AS3 declaration creates the virtual address successfully, while another declaration attempts to create the same address. BIG-IP rejects the declaration with HTTP 422 and reports that the address already exists.

Recommended Actions

Configure each custom-resource label or watched resource scope to be managed by only one CIS controller.

  1. Identify all CIS controllers deployed in the Kubernetes environment.
  2. Review the custom-resource labels and resource scopes watched by each controller.
  3. Remove overlapping label configurations from additional CIS controllers.
  4. If multiple CIS controllers are required, assign separate, non-overlapping labels or namespaces to each controller.
  5. Confirm that the VirtualServer resources use the intended IPAM label under spec
  6. Reconcile or redeploy the affected VirtualServer resources after correcting controller ownership.
  7. Verify that:
    • Only one CIS controller processes each VirtualServer resource.
    • The F5 IPAM Controller allocates the address successfully.
    • AS3 declarations complete without HTTP 422 errors.
    • VirtualServer custom resources no longer report deployment errors.
    • BIG-IP no longer reports duplicate virtual-address errors.

Additional Information

Successful IPAM allocation does not confirm that the complete BIG-IP declaration succeeded. The IPAM status can show an allocated address while the CIS VirtualServer status reports an AS3 deployment failure.

A virtual server and its address may appear on BIG-IP when one controller successfully creates them, while a second controller's duplicate declaration fails.

Warnings about Kubernetes Services that lack either cis.f5.com/ipamLabel or cis.f5.com/ip are separate from a VirtualServer custom resource that correctly specifies spec.ipamLabel.
