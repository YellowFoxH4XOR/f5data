Description

If NGINX App Protect detects a communication with no content in the HTTP header by default the security policy blocks the request. Can the security policy be modified to allowed specific non-browser based request? 

Environment

  • NGINX App Protect
  • Security policy
  • Non-browser based clients

Cause

Bot protection signatures detects clients that falsely claim to be browsers or search engines.

Recommended Actions

Is it possible to define configure the security policy to allow access for specific client types.

For example, HTTP request using a non-browser based client such as curl can be configured to allowed.

{
    "policy" : {
        "name": "my_policy",
        "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
        "applicationLanguage": "utf-8",
        "enforcementMode": "blocking",
        "bot-defense" : {
             "mitigations" : {
                  "signatures" : [
                          {
                              "name": "curl",
                              "action" : "detect"
                          }
                  ]
             }
        }
     }
}
