Description

Client certificate authentication fails on a BIG-IP LTM virtual server configured for mutual mTLS when the client certificate is not presented during the SSL handshake or is rejected. You can see similar errors in the LTM logs

/common/iRule_for_the_certificate_validation <CLIENTSSL_HANDSHAKE>: mtls_select: unknown serial='aa:00:99:a7:5d:f9:11:77:22:dd:ad:66:d0:15:00:22' - rejecting

Environment

  • Virtual server configuration:
    • Client SSL profile requiring certificate authentication
    • Custom iRule for certificate serial number validation
    • Mutual TLS (mTLS) enabled
  • Client certificates recently renewed with a new certificate authority
  • iRule logic only permits certificates with serial numbers explicitly registered in a static table

Cause

The renewed client certificate's serial number was not included in the iRule's static list of permitted serials. The iRule rejects any certificate whose serial number does not exactly match an entry in this list, regardless of CA validity. F5 displays the serial number without the leading ASN.1 sign byte (00), which is expected behavior and does not affect matching logic.

Answer/Recommended Actions

  1. Update the iRule's static table to include the serial number of the newly issued client certificate.
  2. For any future certificate renewals or replacements, add their serial numbers to the iRule's allowed list.
  3. Confirm that the client is configured to present a certificate during the handshake. If not, troubleshoot the client-side configuration.
