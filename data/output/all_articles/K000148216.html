Answer/Recommended Actions

Q: How many WAF Exclusion Rules can be created?

A: WAF Exclusion Rules are limited to 256 for every HTTP Load Balancer.

 

Q: If many "WAF Exclusion Rules" are created, will the processing load increase and the processing performance decrease?

A: We cannot tell how significant the exclusion rules will be on performance since it depends on the number of rules and content. For example, using regex will be significantly more expensive than an exact match or a prefix match rule.

 

Q: What is the priority of the settings applied to the actual request when setting the request denying/allowing conditions for the following three items?

  1. "WAF Exclusion Rule" of "Web Application Firewall"
  2. "Service Policy" of "Common Security Controls"
  3. "Trusted Client Rules" of "Common Security Controls"

A: The order of mitigation will be [Trusted Client Rules] --> [Defined Service Policies] --> [WAF Exclusion Rules].

 

Q: Are there other main setting items that control the conditions for denying/allowing requests?

A: There are many items that are involved in blocking/allowing events, such as

  • Client Blocking Rules
  • CORS Policy
  • IP Reputation
  • Malicious User Mitigation
  • L7 DDoS
  • Bot Defense and more which can be found in this document: HTTP Load Balancer

 

Q: How does the order of priority for [Client Blocking Rules] compare with the following? - [Trusted Client Rules] --> [Defined Service Policies] --> [Waf Exclusion Rules]

A: In [Client Blocking Rules] and in [Trusted Client Rules], the order will be -> [Client Blocking Rules] --> [Trusted Client Rules] --> [Defined Service Policies] --> [WAF Exclusion Rules]

 

Q. Does WAF exclusion rule support header match?

A. No, but the F5 AppSec team raised a feature request. Unfortunately there is no ETA yet

 

Q. Why the alerts are not generated on the dashboard?

A. An alert is generated only when more than X security events are triggered in a given amount of time; the trigger is 18 events in 5 minutes window for the distinct tenant, namespace, vh_name, src_site label combination.

 

Q: What is the block logic if the rule contains many records, like for sig, it contains 200018151 and 200003143?

A: With this configuration, if any of these signature got detected in the request, our system will not block that request.

Also, Lets say in a req we detected signature id 200018151 and 200018152. Then we will block the request since we haven't configured 200018152 signature id in waf_exclusion_rule.
