Known Issue

BIG-IP APM Security Assertion Markup Language (SAML) service provider (SP) access profile Identity Provider (IdP) assertions may fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM virtual server references an access profile configured as a SAML SP.
  • The configured virtual server receives a signed IdP-initiated assertion with a null Reference URI value.

    For example:

    <Signature xmlns=\"<xml uri namespace path>">
    <SignedInfo><CanonicalizationMethod Algorithm=\"<uri path>"/>
    <SignatureMethod Algorithm=\"<uri path>"/>
    <Reference URI=\"\">
    <Transforms><Transform Algorithm=\"<uri path>"/>
    </Transforms>
    <DigestMethod Algorithm=\"<uri path>"/>
    <DigestValue><value></DigestValue>
    </Reference>
    </SignedInfo>
    <SignatureValue><signature></SignatureValue>
    <KeyInfo>
    <X509Data>
    <X509Certificate><certificate value></X509Certificate>
    </X509Data>
    </KeyInfo>
    </Signature>

Impact

SP authentication fails for the IdP assertion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H524824 on the Diagnostics > Identified > Medium screen.
  • When an IdP sends a signed assertion with a null Reference URI value to the BIG-IP APM SP-configured virtual server, the system returns an error message similar to the following example:

    "no data received"
  • In the /var/log/apm file, messages appear similar to the following example:

    notice apd[<pid>]: 01490000:5: ** SIGSEGV **
    notice apd[<pid>]: 01490000:5: ** STDERR **
    notice apd[<pid>]: 01490000:5: ** END STDERR **
    notice apd[<pid>]: 01490000:5: fault addr: 0x1
    notice apd[<pid>]: 01490000:5: fault code: 0x1
    notice apd[<pid>]: 01490000:5: fault time: <day month day hh:mm:ss yyyy>
  • The apd service produces a core file in the /var/shared/core directory, with time stamps that correlate with the SAML authentication failures.

    For example:

    /var/shared/core/apd.bld608.0.core.gz
  • In the /var/log/apm file, messages appear for each IdP assertion attempt with a null Reference URI value, similar to the following example:

    err apd[<pid>]: 01490000:3: modules/Authentication/Saml/SamlSPAgent.cpp func: "verifyAssertionSignature()" line: 4050 Msg: ERROR: verifying the digest of SAML Response
    err apd[<pid>]: 01490204:3: a4f7e22b: SAML Agent: /<partition>/<access profile> failed to process signed assertion, error: Digest of SignedInfo mismatch
