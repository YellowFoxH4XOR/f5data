Description

After failing over VELOS controllers and PXE booting the formerly active controller, the multus-config.yml playbook may fail when adding the newly PXE booted controller back to the cluster.

Messages similar to the following are observed in /var/log/openshift.log on the active controller:

2026-01-29 21:42:11.000443 - fatal: [controller-1.chassis.local]: FAILED! => {"msg": "The conditional check 'groups.oo_masters_to_config | length > 1' failed. The error was: error while evaluating conditional (groups.oo_masters_to_config | length > 1): 'dict object' has no attribute 'oo_masters_to_config'\n\nThe error appears to be in '/usr/share/ansible/openshift-ansible/roles/openshift_sanitize_inventory/tasks/main.yml': line 131, column 3, but may\nbe elsewhere in the file depending on the exact syntax problem.\n\nThe offending line appears to be:\n\n\n- name: Ensure openshift_master_cluster_hostname is set when deploying multiple masters\n ^ here\n"}

2026-01-29 21:42:11.034223 - fatal: [controller-2.chassis.local]: FAILED! => {"msg": "The conditional check 'groups.oo_masters_to_config | length > 1' failed. The error was: error while evaluating conditional (groups.oo_masters_to_config | length > 1): 'dict object' has no attribute 'oo_masters_to_config'\n\nThe error appears to be in '/usr/share/ansible/openshift-ansible/roles/openshift_sanitize_inventory/tasks/main.yml': line 131, column 3, but may\nbe elsewhere in the file depending on the exact syntax problem.\n\nThe offending line appears to be:\n\n\n- name: Ensure openshift_master_cluster_hostname is set when deploying multiple masters\n ^ here\n"}

Environment

  • VELOS OpenShift cluster
  • After PXE boot

Cause

In some situations, failing over the VELOS controllers may initiate a multus upgrade, which will run the multus-config.yml playbook shortly after the failover. If the newly standby controller is PXE booted while the multus-config.yml playbook is running, the controller may fail to be added to the cluster once the PXE boot completes.

Bug ID 2219949 tracks this issue.

  • Bug ID 2219949: A controller's Multus configuration will fail if the peer controller is PXE-booted during the install

Recommended Actions

To prevent this issue occurring, wait at least 10 minutes after failing over the system controllers, before starting the PXE boot of the standby controller. In addition, review the openshift.log on the newly active controller and ensure no playbooks are currently executing.

To recover from the problem state, perform an OpenShift cluster rebuild:

  • K000152701: How to reinstall the OpenShift cluster on VELOS systems

Additional Information

This should generally be a rare issue. OpenShift cluster install may fail due to numerous reasons, and further review of the openshift.log may be required if this issue does not match your scenario.
