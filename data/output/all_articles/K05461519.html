Description

 Upon blade boot, almost immediately receive "System halted" on console.

Environment

  • VCMP Host
  • Viprion Platform with FIPS140-2 platform checks
Cause

Blade does not have required file /var/named/config/namedb

Recommended Actions

From the command line (SSH) logged in as root on the Primary blade of the Viprion, run the following procedure:

  1.   clsh bigstart stop named
  2.   clsh rmdir /var/named/config/namedb
      Note: remove namedb directory from all blades
  3.   clsh ls -l /var/named/config/namedb
      Note: ensure that all blades do NOT have a /var/named/config/namedb directory
  4.   clsh mkdir -p /var/named/config/namedb
  5.   clsh ls -l /var/named/config/namedb
      Note: ensure that all blades have a /var/named/config/namedb directory
  6.   clsh chown named.named /var/named/config/namedb
  7.   clsh ls -l /var/named/config/namedb
      Note: ensure that all blades have a /var/named/config/namedb directory with the expected permissions and ownership 
  8.   clsh restorecon -R /var/named
  9.   clsh bigstart start named
  10.   sys-eicheck
      Note: make sure no other files are missing or other failure is occurring, please refer to K11402545: Troubleshooting FIPS self-test failure if more are found.
  11.   reboot
      Note: this should be done ONLY on the blade that is halting due to missing /var/named/config/namedb file, the System halt should no longer occur

Additional Information

Essentially during replication the /var/named/config/namedb file does not get copied to the secondary blades (possibly a race condition or simple timeout of the process).

Once this occurs, the named process will begin failing as described in K05117215: BIND error: "/config/named.conf:40: change directory to '/config/namedb' failed: file not found".

This is not likely to be noticed.  However when the blade is rebooted, FIPS detects that file "/var/named/config/namedb" is missing and halts the system per K25205233: BIG-IP System halted while booting. Halt at boot after FIPS Integrity Check Result FAIL

No errors are shown on console but the /config/f5_public/fipserr file will show:

=======================================================
missing     /var/named/config/namedb

1 critical file(s) missing

and

Integrity Check Result: [ FAIL ]

In order see those errors you will likely need to follow the instructions in K42169041: Troubleshooting FIPS power-on self-test failures. As there could be other issues at play please take into consideration the points made in K25205233: BIG-IP System halted while booting. Halt at boot after FIPS Integrity Check Result FAIL and K11402545: Troubleshooting FIPS self-test failure
