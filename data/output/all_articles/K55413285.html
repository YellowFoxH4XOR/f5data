Description

You notice an increase in the ratio of server-side connections to client-side connections for a Virtual server that has SNAT Automap and a Oneconnect profile.

  • Increased server-side connections.
  • Oneconnect does not appear to reuse existing connections.
  • The number of server-side connections is far greater than client-side connections.
As a result Inet port exhaustion messages are logged under /var/log/ltm file. 

For example:01010201:2: Inet port exhaustion on 192.168.10.100 to 10.10.10.11:80 (proto 6)

Environment

  • iApp Exchange 2016
  • SNAT Automap
  • OneConnect

Cause
The iApp configured the Keep-Alive (TCP profile) with an interval less than the Idle Timeout (TCP profile). As a result, the Idle Timeout will never take effect.

Recommended Actions

To avoid unexpected connection accumulation, keep the value of the Keep Alive Interval greater than the Idle Timeout in the TCP profile. 
  1. Login to the Configuration utility
  2. Browse to Local Traffic ›› Profiles : Protocol : TCP ››  <tcp profile_name>  you would like to edit.
  3. Modify the Keep Alive Interval and Idle Timeout as desired for your environment.
  4. Update. 
    Note: You should also take in consideration the TCP configuration of your server. Even when the TCP profile has the recommended values, mismatched configuration from the server side might contribute to hanging connections. This includes when you are using two iApps in tandem that points at a second virtual server.

Additional Information

The SNAT timeout only applies if the connection goes through a SNAT object.  If the connection is handled by a virtual server then the Idle Timeout of the TCP profile is the relevant setting.
