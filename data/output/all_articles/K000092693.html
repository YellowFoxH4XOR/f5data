K000092693: Error importing ASM policy - Failed to insert to PLC.PL_POLICY_NEGSIG_SETS ... line 219

Type
Support Solution
Published
2022-11-22
Updated
2022-11-22
Source
https://my.f5.com/manage/s/article/K000092693

Description

An ASM policy exported from a unit with v14.1.4 fails to be imported on an ASM unit running the same version 14.1.4, with the error message below:

Failed to insert to PLC.PL_POLICY_NEGSIG_SETS (DBD::mysql::db do failed: Cannot add or update a child row: a foreign key constraint fails ('PLC'.'PL_POLICY_NEGSIG_SETS', CONSTRAINT 'PL_POLICY_NEGSIG_SETS_ibfk_2' FOREING KEY ('set_id') REFERENCES 'NEGSIG_SETS' ('set_id') ON DELETE CASCADE) AT /usr/local/share/perl5/F5BatchInsert.pm line 219.
 

Environment

  • BIG-IP ASM
  • Policy Export/Import


Cause

The source and target devices have not the same Attack signatures, and some attack signatures are used in the policy exported from the target device. According to K13905104: Overview of importing and exporting BIG-IP ASM security policies one of the recommendations is: "Make sure to use the same version of ASM Signatures (preferably the newest) on both systems".

It is easy to confirm which version of ASM Attack Signature is being used in the source and target devices:

In the GUI --> System --> Software Management --> Live update and here we can find what is the latest update file name for the ASM-AttackSignatures

But, if in the source device there are user-defined attack signatures, these also need to be copied to the target device.


Recommended actions

You need to export the user-defined attack signatures prior to exporting the policy

On the source unit :

  1.  Navigate to the --> Security --> Options --> Application Security --> Attack Signatures --> Attack Signature List
  2.  Show the filters, select "Yes" for "User-defined", and click "Go"
  3.  Select all of these signatures and click "Export"

 On the target unit :

  1.  Navigate to the --> Security --> Options --> Application Security --> Attack Signatures --> Attack Signature List
  2.  Import the file created with the "Export" in the previous section
  3.  Then import the policy


Additional Information

You could investigate deeper and import only the user-defined signature used in the policy to be imported that is defined in the source device and is missing in the target device, but considering the attack signatures should be the same in all devices on the customer network even the user-defined ones, the recommendation is to import all user-defined signatures.
