Note: Due to current design properties, virtual servers configured with a WebAccelerator-enabled HTTP Class Profile are required to have both port translation and address translation enabled. For more information, including details about the default translation settings for a virtual server, refer to K8469: WebAccelerator-enabled virtual servers require that port and address translation be enabled.

To enable WebAccelerator for a Wildcard Port virtual server that would normally have address translation disabled by default, perform the following three procedures: 

  • Enabling address translation for the virtual server
  • Enabling WebAccelerator for the HTTP Class profile 
  • Creating an iRule to preserve and use the original node destination information

Enabling address translation for the virtual server

To enable address translation for the virtual server, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click the desired virtual server.

    The General Properties and Configuration screen opens.

  5. From the Configuration box, select Advanced
  6. Select the Address Translation check box.
  7. Ensure that the Port Translation check box is selected.
  8. Click Update.

Enabling WebAccelerator for the HTTP Class profile

To enable WebAccelerator for the HTTP Class profile, perform the following procedure:

  1. Click WebAccelerator.
  2. In BIG-IP 9.x, click Classes.

    In BIG-IP 10.x, click Class Profiles.

  3. Click the desired HTTP Class profile.
  4. From the WebAccelerator box, select Enabled.
  5. Click Update.

Creating an iRule to preserve and use original node destination information

To create an iRule to preserve and use the original node destination information, perform the following procedure:

  1. Click Local Traffic.
  2. Click iRules.
  3. Click Create.
  4. In the Definition field, type the following iRule:

    when HTTP_REQUEST {
       node [IP::local_addr]
     }

  5. Click Update.
  6. Configure the virtual server to use the iRule.

Configuring the WebAccelerator to process requests for unmapped hosts 

If you cannot configure all requested domains, you need to configure the WebAccelerator system to process requests for unmapped hosts, using the following procedures:

Note: For example, the following procedures are required if you are configuring the BIG-IP WebAccelerator system to act as a forwarding proxy cache server for clients who access Internet destinations through the BIG-IP WebAccelerator system.

  • Configuring the BIG-IP WebAccelerator system to process Unmapped Hosts
  • Configuring DNS on the BIG-IP WebAccelerator system  

Configuring the BIG-IP WebAccelerator system to process unmapped hosts

  1. Click WebAccelerator.
  2. Click Applications.
  3. Click Unmapped Hosts.
  4. Select the Process requests for unmapped hosts check box.
  5. From the Policy box, select the desired WebAcceleration policy.
  6. Click Save.

Configuring DNS on the BIG-IP WebAccelerator system

To configure DNS on the BIG-IP WebAccelerator system to allow for name resolution of unmapped hosts, perform the following procedure:

  1. Click System.
  2. In BIG-IP 9.x, click General Properties.

    In BIG-IP 10.x, click Configuration.

  3. From the Device box, select DNS.
  4. In the Address field of the DNS Lookup Server List section, type the IP address of the DNS server.
  5. Click Add.
  6. Click Update.
