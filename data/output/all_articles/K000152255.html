Description

Your request is blocked by the ASM security policy, and a Support ID is displayed in the response. You can find this support ID in the security event logs (Security  ››  Event Logs : Application : Requests). However, you also see the same Support ID in the Bot Defence event logs (Security  ››  Event Logs : Bot Defence : Bot Requests), even though Bot Defence is running in Transparent mode. You would like to understand this behaviour.

Environment

  • BIG-IP ASM/advanced WAF
  • Bot-Defence Profile applied to the Virtual Server
  • Same SupportID can be seen in both ASM and Bot-Defence event logs.

Cause

In BIG-IP ASM/Bot Defence, local logging requests are stored in the PRX database (MySQL). Each logged request is assigned a unique identifier, known as the Support ID, which serves as the primary key in the request log table.

Logging can be performed by the ASM logging profile, the Bot Defence logging profile (even though it's in transparent mode), or by both. Regardless of which profile handles the logging, each request will have only one Support ID, since they all relate to the same original client request.

For example, if a request is logged by both the Bot Defence and ASM logging profiles, two entries will be created in their respective tables within the PRX database. However, both entries will share the same Support ID, as they originate from the same request.
