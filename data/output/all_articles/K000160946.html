K000160946: Kerberos Constrained Delegation Fails After Microsoft Update Enforces AES Encryption on BIG-IP APM

Type
Support Solution
Published
2026-04-22
Updated
2026-05-21
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160946

Description

Kerberos Constrained Delegation (KCD) authentication fails on BIG-IP APM after Microsoft server updates enforce AES128/256 as the default encryption for Kerberos tickets. Error messages in APM logs include:

Kerberos: can't decrypt S4U2Self ticket for user john_smith@example.com - Decrypt integrity check failed

Kerberos: Failed to get ticket for User: 'john_smith@example.com' accessing service: 'HTTP'/sso.example.com@EXAMPLE.COM'

Auth header null, Kerberos SSO failed

Disabling RC4 and enforcing AES-only encryption on the service account resolves the issue.

Environment

  • BIG-IP APM version 17.5.1
  • Kerberos SSO profiles for access policies
  • Microsoft Active Directory service accounts initially supporting both AES and RC4 encryption
  • Recent Microsoft server updates enforcing AES128/256 as default Kerberos encryption

Cause

When the Active Directory service account allows both AES and RC4 encryption, and Microsoft updates enforce AES as default, the presence of RC4 as an allowed encryption type causes BIG-IP APM to fail decrypting S4U2Self Kerberos tickets, resulting in authentication failures. Enforcing AES-only resolves the issue.

Answer/Recommended Actions

  1. Disable RC4 encryption on the Active Directory service account used for Kerberos delegation.
  2. Enable only AES128 and AES256 encryption for the service account.
  3. Reset the service account password after changing encryption settings in AD.
  4. Update the password in the BIG-IP Kerberos SSO profile.
  5. Restart the websso service on BIG-IP after making changes (bigstart restart websso).

Additional Information

  • The issue only appears when the service account accepts both AES and RC4 encryption.
  • Forcing the account to use only AES resolves the decryption errors and restores KCD functionality.
  • Debug logging and packet captures can help further diagnose Kerberos SSO failures.
