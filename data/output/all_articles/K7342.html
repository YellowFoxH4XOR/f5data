Topic

The syslog-ng utility is an enhanced version of the standard UNIX and Linux logging utility syslog. It allows for more scalable and flexible logging.

Modifications to the syslog-ng configuration should be conducted through the Configuration utility or the TMOS Shell (tmsh). For more information on tmsh and syslog-ng, refer to K13083: Configuring syslog settings from the command line (15.x - 17.x).

In this article, the syslog-ng.conf file is divided into the following two sections:

  • Global objects
  • Individual properties

Global objects

The first section of the syslog-ng.conf file specifies the Global Objects for syslog-ng to use:

Note: Later versions of the BIG-IP system may contain additional entries but the format is the same for each version. The example explains each section of the syslog-ng.conf file in order to communicate how the file is used for the BIG-IP system. Additionally, the syslog-ng -V command can be used to display which version of syslog-ng is being used.

For example:

options {
   dir_perm(0755);
   perm(0600);
   chain_hostnames(no);
   keep_hostname(yes);
   stats(0);
   log_fifo_size(2048);
};

source local {
   unix-dgram("/dev/log");
   udp(ip(127.0.0.1) port(514));
   udp6(ip(::1) port(514));
   internal();
};

Options section

The options section specifies the following:

OptionDescription
dir_perm(0755)Specifies the directory permissions for the log files. The permissions setting is as follows: 0755 - rwxr-xr-x
perm(0600)Specifies the permissions for the log files it creates. The permissions setting is as follows: 0600 - rw-------

Note: All directories and files created for logging are all owned by root.

chain_hostnames(no)Enable or disable chained hostname format.
keep_hostname(yes)Enable or disable hostname rewriting.
stats(0)Specify the number of seconds between two STATS messages. STATS messages are log messages sent by syslog-ng, containing statistics about dropped logged messages.
log_fifo_size(2048)The number of lines fitting to the output queue.

Source section

The source section is a set of source drivers used for collecting messages. The default for BIG-IP system is local, indicating the set of drivers defined for local use.

SourceDescription
unix-dgram("/dev/log")Opens the specified unix socket to listen for messages
udp(ip(127.0.0.1) port(514))Listens on the specified UDP port and IP address
udp6(ip(::1) port(514))Listens on the specified UDP port and IP address
internal()Allows messages to be generated internally in syslog-ng

Individual Properties

After the global options are defined, the remaining content of the syslog-ng is used to specify the individual properties for the individual log files that are collected.

For example:

# local0.*    /var/log/ltm
filter f_local0 {
   facility(local0);
};
destination d_ltm {
   file("/var/log/ltm" create_dirs(yes));
};
log {
   source(s_syslog_pipe);
   filter(f_local0);
   destination(d_ltm);
};

Log definition

The log definition provides a summary of the facility, log level, and the directory and name of the log file itself.

For example:

# local0.* /var/log/ltm

The log definition example indicates the following:

  • Facility name: local0
  • Facility log level: * (all levels)
  • The location of the log file: /var/log/ltm
  • The name of the log file: ltm

Filter section

The filter section is used to filter out only those messages for the facility specified and levels associated for that facility. The syntax of the filter object consists of the filter parameter followed by the filter name. The syntax within the braces identifies the facility and the log level that should be included.

For example:

filter f_local0 {
   facility(local0);
};

The filter section example indicates the following:

  • Filter name: f_local0
  • Facility name that the filter is filtering information for: local0

Note: For more information about the various log levels, refer to K15934495: Configuring the level of information that syslog-ng sends to log files (12.x - 17.x).

Destination section

The destination section is used to instruct syslog-ng about which file it writes the message information for the facility specified within the filter. The syntax of the destination object consists of destination parameter followed by the destination name. The syntax within the braces identifies the name of the file the facility messages will be written to and the create_dirs (create directories) option that instructs syslog_ng to create the directory if it does not exist.

For example:

destination d_ltm {
   file("/var/log/ltm" create_dirs(yes));
};

The destination section example indicates the following:

  • Name of the destination object: d_ltm
  • File to write to: /var/log/ltm
  • Create directories option: yes (default)

Log section

The log section is responsible for combining the source, filter, and destination objects for syslog_ng to use. The log section is identified by the parameter name of log. Within the braces are the source, filter, and destination objects, which were previously specified.

For example:

log {
   source(s_syslog_pipe);
   filter(f_local0);
   destination(d_ltm);
};

The log section example indicates the following:

  • Source of the messages: s_syslog_pipe
  • Filter to use: f_local0
  • Destination to use: d_ltm

Note: It is possible to specify more than one parameter for source, filter, and destination.
