Known Issue

Description

When you use the no capture session command to end a packet capture, if the size of the collected capture files exceeds 2 GB, the file capture will fail and generate a core file.

This issue occurs when all of the following conditions are met:

  • You are running an ARX 4000 platform
  • The capture session filecount option is 2 or greater
  • The combined file size equals a total of 2 GB or greater

The ARX uses the capture session command to initiate the capture of IP traffic and store it in capture files. When a user stops a packet capture, the ARX uses an internal application (Mergecap) to merge all capture files for that session into one file. The Mergecap application has a limitation of a 2 GB file size. If the combined file size is larger than 2 GB, the file merge will fail and the ARX will generate a core file.

Impact

The ARX does not generate a combined packet capture file; the ARX generates a core file.

Symptoms

As a result of this issue, you may encounter the following symptoms:




  • The ARX generates a core file

    For example:
ARX1#no capture session 1 Core was generated by `/usr/bin/mergecap -w /acopia/var/log/capture/swt.cap /acopia/var/log/capture/sw'. Program terminated with signal 25, File size limit exceeded.
  • A packet capture may not be available

Workaround

If the expected total size of the capture files is greater than 2 GB, you can work around this issue by stopping the capture session. To do so, perform the following procedure:

Impact of workaround:  The ARX system will generate multiple packet capture files instead of one file.

  1. Log in to the ARX CLI.
  2. Stop the capture session using the following command syntax:

    No capture session [session #] no-merge

    For example:

    no capture session 1 no-merge
