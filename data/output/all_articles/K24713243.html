Description

After applying the workaround on ID794417 and upgrade to v15.1.3 successful. Once rolling back the device to v15.1.2, the configuration is successfully loaded but the ConfigSync operation failed, showing as the following error message.

01020036:3: The requested parent profile (/Common/http2) was not found.

Environment

  • BIG-IP LTM
  • http2 default profile has been modified.
  • Successfully upgrade the device to v15.1.3 using the workaround mentioned on ID794417.
  • Roll back the upgrade from v15.1.3 to v15.1.2.1 (previous boot location).

Cause

Modifying a system-supplied (default) profile may cause configuration synchronization (ConfigSync) operations to fail.

Important: Due to a known issue, modifying a default profile may cause ConfigSync to fail. F5 recommends that you do not modify default profiles. For more information about this known issue, refer to K16237: Modifying a default profile may cause ConfigSync operations to fail.

Recommended Actions

  1. On the target device, manually skip the modified profile (http2) from the /config/bigip.conf file by putting comment (#) in the beginning of the line.

    For the example:

    #ltm profile http /Common/http2 {
    #    activation-modes { alpn }
    #    app-service none
    #    concurrent-streams-per-connection 10
    #    connection-idle-timeout 300
    #    defaults-from none
    #    description none
    #    enforce-tls-requirements enabled
    #    frame-size 2048
    #    header-table-size 4096
    #    insert-header disabled
    #    insert-header-name X-HTTP2
    #    partition Common
    #    receive-window 32
    #    write-size 16384
    #}

    And also at the virtual server which is using http2 profile, commenting the http2 profile.

    For the example:

    ltm virtual /Common/TEST_HTTP2_VS {
        destination 10.10.10.10:https
    -- SNIP --
        pool /Common/TEST_HTTP2_Pool
        profiles {
            /Common/Modify_Client_SSL {
                context clientside
            }
    #        /Common/http2 {
    #            context all
    #        }
            /Common/serverssl {
                context serverside
            }
            /Common/tcp {
                context all
            }
        }
        traffic_classes none
        translate-address enabled
        translate-port enabled
        vlans none
        vlans-disabled
    }
     
  2. Load the configuration on the target device (for example, using the tmsh load /sys config command).
  3. Re-attempt the ConfigSync operation (from the initiating device) and choose the option to overwrite the configuration.
