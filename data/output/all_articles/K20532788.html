Description:

When you want to use BIG-IP ASM to protect a BIG-IP APM login page from brute force attacks, you may find that during the launching of APM Network Access, VPN tunnel is not able to be established successfully. This article is a solution to make it work.

Environment:
  • BIG-IP APM with Network Access
  • A layered ASM virtual server to protect a BIG-IP APM login page with brute force prevention is configured
Cause:

ASM is an HTTP based application firewall solution working on OSI Layer 7, which means it mainly parses/works http traffic. And by default, communication between VPN client and back-end server is an end-to-end encrypted tunnel using SSL/DTLS, the ASM is unable to parse/inspect this traffic. However before the VPN tunnel is established, there is a negotiation process which replies on HTTP request and response. ASM security policy may erroneously block these traffic. This cause a failure when launching network access.

Recommended Actions:

Create an irule and associate to the ASM virtual server.

when HTTP_REQUEST {
    set http_asm_disable 0
    if { [HTTP::uri] starts_with "/isession" or [HTTP::uri] starts_with "/myvpn" } {
        set http_asm_disable 1
    }
    else {
        HTTP::enable
        ASM::enable "<asm_security_policy_name>"
    }
}
when HTTP_REQUEST_SEND {
    if { $http_asm_disable != 0 } {
        ASM::disable
        HTTP::disable
    }
}
