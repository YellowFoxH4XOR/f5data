K03263142: Troubleshooting NGINX Controller installation

Type
Knowledge
Published
2020-01-01
Updated
2025-02-06
Applies to
  • NGINX Products
  • NGINX Controller: 2.8.X, 2.9.0, 2.9.X, 2.8.0, 2.8.1
Source

Issue

You should consider using this procedure under the following condition:

  • You are unable to install NGINX Controller 2.8 and later.

Recommended Actions

Procedures

When experiencing issues with installing NGINX Controller, you can use the following troubleshooting procedures:

  • Manually removing Kubernetes installation
  • Reviewing pods status and logs
  • Reviewing installation configuration parameters
  • Reviewing compute resource utilization
  • Manually downloading Docker images
  • Retrieving URLs for all packages and dependencies

Manually removing Kubernetes installation

You can manually remove Kubernetes installation in the following failure scenarios:

  • NGINX Controller installation fails when initializing the database and displays an error message similar to the following:

    kubectl -n nginx-controller logs -l app=controller-init --all-containers
    Running database initialization task...
    error: unable to recognize "/opt/nginx-controller/k8s-namespace.yaml": Get https://10.0.0.1:6443/api?timeout=32s: Forbidden
    unable to recognize "/opt/nginx-controller/k8s-ctrl-init.yaml": Get https://10.0.0.1:6443/api?timeout=32s: Forbidden

  • Kubernetes components fail to install correctly.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the NGINX Controller command line interface.
  2. Remove any existing Kubernetes cluster by entering the following command:

    kubeadm reset -f

  3. Remove Kubernetes client (kubectl) configuration by entering the following command:

    rm -rf ~/.kube

  4. Remove the installation directory by entering the following command:

    sudo rm -rf /opt/nginx-controller

After you manually remove Kubernetes, attempt to reinstall the NGINX Controller.

Reviewing pods status and logs

You can review the status and logs of NGINX Controller pods in the following failure scenarios:

  • A pod or container fails to run or start after installation.
  • api_gw fails to start after installation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the NGINX Controller command line interface.
  2. List all pods to view which ones are not ready by entering the following command:

    kubectl -n nginx-controller get pods -l org=f5.com

  3. Verify whether a pod is scheduled (that is, that there is a node where it can run) and is responding to readiness/liveness probes or has terminated by entering the following command:

    kubectl -n nginx-controller describe pod pods <pod_name>

  4. Review a pod log by entering the following command:

    kubectl -n nginx-controller logs <pod_name> [--all-containers ]

  5. You can customize the output of the logs. For example, to continuously display the last 100 lines with 'ERROR' on pods apimgmt and coreapi, enter the following command:

    kubectl -n nginx-controller logs -l org=f5.com --all-containers --max-log-requests=30 --tail 100 -f | grep ERROR | grep apimgmt\|coreapi

Modifying log levels

You can modify the NGINX Controller pod log level logs by performing the following procedure:

Impact of procedure: Excessive logging may affect NGINX Controller performance.

  1. Log in to the NGINX Controller command line interface.
  2. Retrieve the name for the ConfigMap by entering the following command:

    kubectl -n nginx-controller get cm -o name | grep configmap/controller-config

  3. Modify the log level for the ConfigMap previously retrieved. In the following example, the log level is modified to debug level:

    kubectl -n nginx-controller patch configmap/<configmap_name> -p '{"data":{"LOG_LEVEL":"debug"}}'

  4. To list of all pods and identify the ones you want to restart in order for the log level changes to take effect, enter the following command:

    kubectl -n nginx-controller get pods -l org=f5.com

  5. Delete the pod so it can be recreated with modified log level as passed in the environment variables from the ConfigMap by entering the following command syntax:

    kubectl -n nginx-controller delete pod <pod_name>

Reviewing installation configuration parameters

NGINX Controller installation may fail when configurations settings are incorrectly passed during installation. You can verify the configuration settings by performing the following procedure:

Note: All settings are stored in Kubernetes ConfigMaps and Secrets. Internally, they are kept in the etcd database and are encrypted at rest.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the NGINX Controller command line interface.
  2. Locate the ConfigMap name used for NGINX Controller installation by entering the following command:

    kubectl -n nginx-controller get cm -o name | grep configmap/controller-config-

  3. Review the ConfigMap parameters and assess their accuracy by entering the following command syntax:

    kubectl -n nginx-controller get cm <configmap_name> -o json | jq '.data'

  4. Locate the secret name used for NGINX Controller installation by entering the following command:

    kubectl -n nginx-controller get secret -o name | grep secret/controller-secrets-

  5. Review the secret parameters and assess their accuracy by entering the following command syntax:

    kubectl -n nginx-controller get secret <secret_name> -o json | jq '.data | map_values(@base64d)'

Note: Some user-provided input, such as the administrator username and password, are not stored after installation.

Reviewing compute resource usage

You can install Metrics Server to display nodes and pods CPU and memory usage when metrics are lagging or requests time out.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the NGINX Controller command line interface.
  2. Download Metrics Server 0.3.4 by entering the following command:

    curl -LO https://github.com/kubernetes-incubator/metrics-server/archive/v0.3.4.tar.gz

  3. Extract Metrics Server by entering the following command:

    tar xf v0.3.4.tar.gz

  4. Apply the Metrics Server manifest to your cluster by entering the following command:

    kubectl apply -f metrics-server-$VERSION/deploy/1.8+/

  5. Modify the Metrics Server deployment by entering the following command syntax:

    kubectl -n kube-system patch deployment metrics-server --type json -p='[{"op": "replace", "path": "/spec/template/spec/containers/0/args", "value": ["--kubelet-insecure-tls", "--kubelet-preferred-address-types=InternalIP,ExternalIP,Hostname"]}]'

  6. After you configure the Metrics Server, you can use the top command to view nodes and pods CPU and memory usage. To do so, use enter the following commands, respectively:

    kubectl top nodes

    kubectl top pods -A --containers

  7. You can also review the configured pods' resource limits by entering the following command:

    kubectl -n nginx-controller get pods -o jsonpath='{range .items[*]}{.metadata.labels.app}: {.spec.containers[*].resources.limits}{"\n"}{end}'

  8. You can also review the RabbitMQ queues by entering the following command:

    kubectl -n nginx-controller exec -it $(kubectl -n nginx-controller get pod -l app=rabbitmq -o name) -- rabbitmqctl list_queues -p receiver

Manually downloading Docker images

Your NGINX Controller installation may fail when images are not properly loaded from public Docker registries. To pull all images required by Kubernetes and save them into a single file that can be moved to the target host and loaded manually, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: The following script is for NGINX Controller 2.8, which requires Kubernetes 1.15.3; for a different NGINX Controller version, verify the required Kubernetes version and modify the script accordingly.

  1. Enter the following script:

    # pull and save Docker images
    # list obtained by running:
    # kubeadm config images list --kubernetes-version 1.15.3
    # yq -r '.spec.template.spec.containers, .spec.template.spec.initContainers | select( . != null) | .[].image' files/k8s/kube-flannel.yml | sort -u | grep amd64
    images=(
    k8s.gcr.io/kube-proxy:v1.15.3
    k8s.gcr.io/kube-apiserver:v1.15.3
    k8s.gcr.io/kube-controller-manager:v1.15.3
    k8s.gcr.io/kube-scheduler:v1.15.3
    k8s.gcr.io/coredns:1.3.1
    k8s.gcr.io/etcd:3.3.10
    k8s.gcr.io/pause:3.1
    quay.io/coreos/flannel:v0.11.0-amd64
    )
    for i in "${images[@]}"; do
    docker pull "$i"
    done
    docker save "${images[@]}" | gzip > k8s-images.tar.gz
     

  2. Enter the following command to load the Docker images:

    gunzip -c k8s-images.tar.gz | docker load

Retrieving URLs for all packages and dependencies

Your NGINX Controller installation may fail to install packages from public repositories. To retrieve the list of URLs for all required packages and their dependencies, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Enter the following script for Debian packages - Ubuntu/Debian:

    #!/bin/bash

    # run this as (assuming script is saved as $HOME/tmp/k8s-deb.sh):
    # docker run --rm -it -v $HOME/tmp:/src ubuntu:18.04 /src/k8s-deb.sh

    KUBE_VERSION=1.15.3
    packages=(
    "kubeadm=${KUBE_VERSION}-00"
    "kubelet=${KUBE_VERSION}-00"
    "kubectl=${KUBE_VERSION}-00"
    )
    apt-get update -qq && apt-get install -qq -y apt-transport-https curl gnupg2 >/dev/null
    curl -s https://packages.cloud.google.com/apt/doc/apt-key.gpg | apt-key add -
    echo "deb http://apt.kubernetes.io/ kubernetes-xenial main" | tee -a /etc/apt/sources.list.d/kubernetes.list >/dev/null
    apt-get update -qq

    echo ""
    echo "Fetch the following files:"
    apt-get install --reinstall --print-uris -qq "${packages[@]}" | cut -d"'" -f2

    echo ""
    echo "Install packages:"
    echo "dpkg -i *.deb"

  • Enter the following script for RPM Packages - RedHat/CentOS:

    #!/bin/bash

    # run this as:
    # docker run --rm -it -v $HOME/tmp:/src centos:7 /src/k8s-rpm.sh

    KUBE_VERSION=1.15.3
    packages=(
    "kubeadm-${KUBE_VERSION}-0.x86_64"
    "kubelet-${KUBE_VERSION}-0.x86_64"
    "kubectl-${KUBE_VERSION}-0.x86_64"
    )
    tee -a /etc/yum.repos.d/kubernetes.repo <<EOF 1>/dev/null
    [kubernetes]
    name=Kubernetes
    baseurl=https://packages.cloud.google.com/yum/repos/kubernetes-el7-x86_64
    enabled=1
    gpgcheck=1
    repo_gpgcheck=1
    gpgkey=https://packages.cloud.google.com/yum/doc/yum-key.gpg https://packages.cloud.google.com/yum/doc/rpm-package-key.gpg
    EOF
    yum install -y -q yum-utils 2>/dev/null

    echo ""
    echo "Fetch the following files:"
    yumdownloader -y -q --resolve --urls "${packages[@]}" 2>/dev/null

    echo ""
    echo "Install packages:"
    echo "rpm -i *.rpm"
