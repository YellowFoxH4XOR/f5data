Description

After upgrading a BIGIP VCMP Host, a Guest may fail to start with the following message in /var/log/ltm:

vcmpd[<PID>]: 01510003:2: Guest (<Guest Name>): Child exited with non-zero exit code: 1

In this error message, note the following:

  • <PID> is the process ID of the vcmpd process.
  • <Guest Name> is the name of the Guest that fails to start.

For example:

  • vcmpd[1234]: 01510003:2: Guest (example_guest): Child exited with non-zero exit code: 1

Environment

  • BIG-IP
  • VCMP Host
  • VCMP Guest

Cause

It is currently unknown why the Guest fails to start after an upgrade to the Host.

Recommended Actions

If a case has been raised with F5 Support, debug can be collected to gather information on the behaviour:
  1. From the vCMP Host CLI run the following command to enable debug:
    •   # set log.vcmpd.level=verbose
  2. Set the affected vCMP Guest to Provisioned, then back to deployed.
  3. Revert the debug:
    • # set log.vcmpd.level=informational
  4. From the vCMP Host CLI run the following command to compile a log tarball:
    • # tar -cvzf /shared/${HOSTNAME}_$(date +%d%b_%H%mhrs_%Z)_Guest_No_Start_logs.tgz /var/log/*
  5. Generate QKView and upload the generated files to an open F5 support case.

To clear the unknown condition preventing the vCMP Guest from starting, reboot the vCMP Host with the following command from the CLI:
  # reboot

For multi-blade VIPRION systems:
  # clsh reboot

Note: This command will cause all Active vCMP Guests on the rebooted vCMP Host to fail over to their respective HA peers.
