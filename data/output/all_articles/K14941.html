Known Issue

A TCP virtual server configured with a Message Based Load Balancing (MBLB) profile may fail to close connections in the expected time frame, as configured in the TCP profile.

This issue occurs when the following condition is met:

  • The MBLB profile is associated with the virtual server.

The TCP profile allows the user to modify the timeout settings for the Time Wait, FIN Wait, and Close Wait TCP states. For example, the default FIN Wait timeout for the TCP profile is five seconds. However, you can configure this timeout for a specific time, immediate or indefinite.

The MBLB profile has a non-user configurable timeout of five seconds, when associated to a virtual server, is added on top of any timeout configured for those TCP states.

Impact

A five-second delay occurs when closing a TCP connection, even when the timeout specified in the TCP profile is immediate.

Symptoms

As a result of this issue, you may encounter the following behavior:

  • When a client sends a FIN-ACK to an established TCP connection, the BIG-IP system responds to that client with a TCP ACK response. The BIG-IP system then closes the server-side flow with the pool member. The BIG-IP client-side flow remains in a CLOSE-WAIT state for a period of five seconds due to the non-configurable timeout in the MBLB profile. After this five second period, the BIG-IP system will close the client-side flow by sending a FIN-ACK response to the client.
