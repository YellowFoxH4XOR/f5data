Description
Enabling an Interface causes Self IP's to becomes unavailable.

  • Multiple Self IP's may not be pingable.
  • If the Self IP is used for Unicast failover without the management IP, the devices will go Active-Active.
  • If the Self IP is used for Config Sync, it will show "Disconnected".
Disabling/Enabling and interface may cause a different set of Self IP's to fail.
It may affect more than one interface and more than one device.

Environment

  • You are using an Appliance.
  • You are using point to point links between devices, typically for mirroring or failover.
  • You are using links to a switch without using a trunk.
  • You may be upgrading an older environment that is configured this way.

Cause
STP is setting interfaces to "Blocking". Depending on which interface is enabled and disabled, other interfaces may Block for Forward. This results in the unpredictable behaviour.

To confirm, check the devices.

tmsh show net stp

  | 10.0            interface  20000      128       alternate block(block)
  | 3.0             interface  20000      128       disabled  block(block)
  | 5.0             interface  2000       128       root      forward(forward)
  | 6.0             interface  2000       128       designated forward(forward)
  | 9.0             interface  20000      128       alternate block(block)

This shows STP is engaged on these interfaces. 9.0 and 10.0 are blocking.
 

Recommended Actions

  1. If you are migrating from an older, working configuration, disable STP on all interfaces.
  2. A better solution is to reconfigure your networking to use LACP trunks connected to a switch. You may find that using trunks for data and one and only one point to point connection shared for Config Sync , Failover and Mirroring will work
