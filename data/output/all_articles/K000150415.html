K000150415: Remove unused .img in viprion

Type
Support Solution
Published
2025-05-06
Updated
2025-05-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150415

Description

On BIG-IP systems with vCMP provisioned, disk space on a specific slot (e.g., Slot 1, HD1) may become insufficient due to the presence of unused or orphaned vCMP guest image files (such as guest1_blade2.img). These image files may appear with a status of "ready" in the output of show vcmp virtual-disk detail, indicating they are not currently in use by any active vCMP guest. Administrators may need to determine if such image files can be safely deleted to free up disk space without impacting running vCMP guests.

Example below of an image that is in 'ready' state on Slot1.

(/Common)(tmos)# show vcmp virtual-disk
-----------------------------------------------------------------------------------------
Vcmp::VirtualDisk
Name               Slot ID  Operating System  Status  Disk Use (bytes)  Disk Size (bytes)
-----------------------------------------------------------------------------------------
guest1_blade2.img        1              tmos   ready              4.3G             150.0G
guest1_blade2.img        2              tmos  in-use              6.5G             150.0G

 

If we look at the vcmp guest, it is only using slot2 for its deployment.

(/Common)(tmos)# show vcmp guest
-----------------------------------------------------------------------------------------
Vcmp::Guest
Name           Slot ID   Status  Requested   Request  Retries             Uptime  Comment
                                     State  Complete
-----------------------------------------------------------------------------------------
guest1_blade2        2  running   deployed      true        0  03/12/25 10:24:09

Environment

Viprion

Cause

vCMP guest image files may remain on disk in a "ready" state after a guest has been moved to a different slot or reconfigured. These orphaned image files are not referenced by any active vCMP guest but continue to consume disk space.

Recommended Actions

Important:  Before deletion, consider creating a backup of the relevant vCMP guest and its master key. If unsure about potential impact, test this process in a lab environment first.

1.Identify orphaned image files. Image files with a status of "ready" and not listed as "in-use" are not currently attached to any running vCMP guest. Run the following command to list all vCMP virtual disks and their status:

    show vcmp virtual-disk detail

2. Verify Guest Configuration. Confirm that the image file is not referenced in any vCMP guest configuration by running

          list vcmp guest

3.  If the image file is confirmed to be in "ready" state and not referenced by any guest, it can be safely deleted to free up disk space.

          delete vcmp virtual-disk <image_file_name>/<slot_id>

Example:

          delete vcmp virtual-disk guest1_blade2/1
