Known Issue

In some circumstances, the /var/log/journal directory, used by the system-journald process, is not created. In the absence of this directory, the system-journald process writes to temporary storage in /run/log/journal.

This issue occurs when all of the following conditions are met:

  • You upgrade the BIG-IP system to version 14.1.0 or later from an earlier version.
  • The /usr/lib/systemd/journald.conf.d/f5.journald.conf configuration file has storage set to auto.

Impact

Swap memory usage increases, impacting overall system performance, and may result in the kernel out-of-memory killer running and stopping system processes.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe gradual increase of swap memory.
  • You observe degradation of system performance.
  • An eventual failover occurs due to lack of memory.

Workaround

To work around this issue, you can manually create the var/log/journal directory after the upgrade has been performed. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system if done during planned down time or a maintenance window.

  1. Log in to the Advanced Shell (bash) as the root user.
  2. Enter the following commands:
    • mkdir /var/log/journal
    • chown root:systemd-journal /var/log/journal
    • chmod 2755 /var/log/journal
    • chcon system_u:object_r:var_log_t:s0 /var/log/journal
  3. Restart the system.
