Known Issue

Voice over Internet Protocol (VoIP) users who are connected to Network Access may be unable to launch their VoIP application or may hear only half of the conversation. This issue occurs because Network Access favorites use forwarding virtual servers to make connections. The default behavior of the forwarding virtual server is to change the source port for User Datagram Protocol (UDP) datagrams. Many VoIP applications, such as Nortel's i2050 VoIP software, will generate a network address translation (NAT) error and fail to connect.

Workaround

You can work around this issue by creating a transparent UDP virtual server, which enables the Preserve Strict setting for the Source Port without port or address translation. To do so, perform the following procedure:

  1. Log in to the BIG-IP APM Configuration utility.
  2. Expand Local Traffic.
  3. Click Virtual Servers.
  4. Click Create.
  5. In the Name field, enter a name for the virtual server.

    For example:

    VS_VoIP

  6. In the Destination field, enter the IP address of your VoIP server.

    Note: If you are using a VoIP system that uses a peer-to-peer or other configuration that the IP address is not known in advance, such as Cisco Communicator, you will need to use the wild card address (0.0.0.0). Optionally, if the IP address range is known you can use a network destination and mask that encompasses the range of VoIP addresses.
  7. In the Service Port field, enter the port of your VoIP deployment.

    Note: Port 1719 is a common port used for VoIP. If you are using a VoIP system that uses a peer-to-peer or other configuration that the port is not known in advance, such as Cisco Communicator, you will need to use the wild card port, '*' (asterisk).
  8. Ensure that the Configuration drop-down menu is set to Advanced.
  9. From the Source Port drop-down menu, select Preserve Strict.
  10. From the Protocol drop-down menu, select UDP.
  11. Clear the Enabled check box for Address Translation.
  12. Clear the Enabled check box for Port Translation.
  13. Click Finished.
  14. Click the Virtual Address List tab.
  15. In the Name column, click the address of the virtual server you created in Step 5.
  16. Clear the Enabled check box for ARP.
  17. Click Update.
