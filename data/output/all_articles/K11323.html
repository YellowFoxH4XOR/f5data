Known Issue

This is the result of a known issue. A shadow volume rule will stall when a ShadowDirectory request encounters a path lock on a subdirectory before the parent directory is synchronized. The path lock code is unable to resolve this situation and results in an infinite loop.

The path lock condition can occur when a directory is renamed. For example, the issue would occur if you renamed /home/mydir to /home/mydir/myolddir, and then the /home/mydir/myolddir directory was synchronized before the /home/mydir directory.

When the shadow volume stalls, the show shadow <namespace> <volume> command will indicate the rule's Current Phase is Copying/Publishing. However, the Copy Phase Information indicates zero ( 0 ) for Files/Directores Processed.

F5 Product Development tracked this issue as ID 37815 and it was fixed in ARX version 5.1.5. For information about upgrading, refer to the ARX release notes.

Additionally, a hotfix has been issued for ARX version 4.1.3. Customers affected by this issue should contact F5 Technical Support, referencing this Solution number and the associated ID number, to request the hotfix.
