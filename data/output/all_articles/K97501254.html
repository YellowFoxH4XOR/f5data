Known Issue

After you upgrade to an affected BIG-IP version, the SSL Orchestrator Configuration page in the Configuration utility displays Installation Failed! message.

This issue occurs when all of the following conditions are met:

  • You upgrade to an affected BIG-IP version.
  • In the BIG-IP Configuration utility, you navigate to SSL Orchestrator > Configuration.

Impact

You cannot configure or manage SSL Orchestrator.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The Configuration utility displays a message similar to the following example:

    Failed to load IApp artifacts from f5-iappslx-ssl-orchestrator: java.lang.IllegalStateException: Failed to post templates to block collection

Workaround

F5 recommends that you do not upgrade SSL Orchestrator systems to BIG-IP 14.1.2.8 or 15.1.1. To work around this issue, if you already installed 14.1.2.8 or 15.1.1, you can manually repair the SSL Orchestrator iApp.

Manually repair the SSL Orchestrator iApp

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Note: This procedure requires administrative access to the BIG-IP Configuration utility and the command line; you have to go back forth between the two interfaces to complete the procedure.

  1. Log in to the BIG-IP command line using the Advanced shell (bash).
  2. Get the ID for f5-ssl-orchestrator-dg-data by typing the following command:

    id1=$(restcurl shared/iapp/blocks/ | jq -r '.items[] | select(.name == "f5-ssl-orchestrator-dg-data") | .id')

  3. Get the ID for f5-ssl-orchestrator-dg-template by typing the following command:

    id2=$(restcurl shared/iapp/blocks/ | jq -r '.items[] | select(.name == "f5-ssl-orchestrator-dg-template") | .id')

  4. Temporarily unlink the f5-ssl-orchestrator-dg-data (id1) dependency on f5-ssl-orchestrator-dg-template (id2) by typing the following command:

    restcurl -X PATCH -d "{\"baseReference\": {\"link\": \"https://localhost/mgmt/shared/iapp/blocks/$id1\"}}" shared/iapp/blocks/$id1

  5. Remove all SSL Orchestrator block templates by typing the following command:

    restcurl shared/iapp/blocks | jq -r '.items[] | select(.state == "TEMPLATE") | select(.name | startswith("f5-ssl-orchestrator")) | .id' | for x in $(cat) ; do restcurl -X DELETE shared/iapp/blocks/$x; done

  6. Remove any existing SSL Orchestrator RPM Package Manager (RPM) installation references by typing the following two commands:
    • restcurl -X DELETE shared/iapp/global-installed-packages/9beb912b-4f1c-3f95-94c3-eb1cbac4ab99
    • restcurl -X DELETE shared/iapp/installed-packages/9beb912b-4f1c-3f95-94c3-eb1cbac4ab99
  7. Log in to the Configuration utility.
  8. Go to SSL Orchestrator > Configuration and wait for the configuration page to complete loading.

    Note: This action refreshes the page and installs the SSL Orchestrator RPM. Allow the page to finish loading before moving on to the next step.

  9. Log in to the BIG-IP command line using bash.
  10. Restore the f5-ssl-orchestrator-dg-data dependency on f5-ssl-orchestrator-dg-template by typing the following command:

    restcurl -X PATCH -d "{\"baseReference\": {\"link\": \"https://localhost/mgmt/shared/iapp/blocks/$id1\"}}" shared/iapp/blocks/$id2

  11. Log in to the Configuration utility.
  12. Go to SSL Orchestrator > Configuration and refresh the page.
