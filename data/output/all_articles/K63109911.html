Topic

You should consider using these procedures under the following condition:

  • You want to manually deploy a basic BIG-IP LTM and NGINX environment on Amazon Web Services (AWS) to build a custom configuration or test functionality.

Description

This article guides you through a quick deployment of a standalone (no high-availability) BIG-IP LTM 15.1.0.4 VE system in AWS with HTTP load balancing to two NGINX Plus pool members. The examples provide a basic configuration; you can expand examples as needed for testing or custom configurations.

Note: After performing these procedures, you can optionally update your BIG-IP system to a later version. For more information, refer to the Deploying a single NIC BIG-IP VE section.

Important: You are responsible for the cost of AWS services used in the deployment configuration described in this article. The AWS instance types selected for this article are intentionally configured to be as small as possible to prevent excessive costs for testing and deployment. Before deploying this configuration, F5 recommends that you review the pricing pages for each AWS service for cost estimates. Prices are subject to change.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have an AWS account.

    Note: To sign up, go to https://aws.amazon.com.

  • You have a BIG-IP registration key.

    Note: If you need a registration key, contact your F5 Sales representative or request a trial key at https://www.f5.com/trials.

  • You have two NGINX Plus licenses.

    Note: If you need licenses, contact your F5 Sales representative or request trial licenses at https://www.nginx.com/products/nginx/.

  • You have installed SSH and Secure Copy (SCP) protocol client utilities on your local computer to access the Amazon Elastic Compute Cloud (Amazon EC2) instances that you’ll create in AWS. Linux and Mac systems typically already have these utilities installed, but Windows users must install third-party tools such as PuTTY and WinSCP.

Creating an AWS VPC

This procedure uses the AWS Management Console to create an Amazon Virtual Private Cloud (Amazon VPC) with a single public subnet. The Amazon VPC is the networking layer for Amazon EC2 and is required for communication between the BIG-IP LTM and NGINX systems described in this deployment. For more information about Amazon EC2, Amazon VPC, and the AWS Management Console, refer to the following:

  • What Is Amazon EC2?
  • What is Amazon VPC?
  • Working with the AWS Management Console

    Note: These links take you to resources outside of AskF5. The third party could remove these documents without our knowledge.

Additionally, all AWS objects listed in these procedures use the AWS Name tag with the value <AWS username>-<project>-<object type>. For example, user1-example-subnet. You should ensure that objects are tagged with a common naming convention to make it easier to identify associated resources in the AWS Management Console. For all of the following AWS procedures, replace user1-example-<object type> with your own AWS username, your chosen project name, and the object type you are configuring.

Impact of procedure: You are responsible for the cost of the AWS services used while running this deployment configuration. Some of these settings, such as instance type and elastic IP addresses, increase the cost of deployment. Review cost estimates on the pricing pages for each AWS service. Prices are subject to change.

  1. Log in to the AWS Management Console using your AWS account.
  2. Under Services, enter “VPC” in the search box and then select VPC.
  3. On the VPC Dashboard page, select Launch VPC Wizard.
  4. Select VPC with a Single Public Subnet, then click Select.
  5. Set the following values:
    • VPC name: user1-example-vpc
    • Subnet name: user1-example-subnet

      Note: Use default values for all other options on this page.

  6. Select Create VPC.
  7. Select OK.
  8. Under Virtual Private Cloud, select Subnets.
  9. Hold and select or right-click the subnet that you just created and then select Modify auto-assign IP settings.

    Note: Use the search box at the top of the page to filter if needed.

  10. Select the Auto-assign IPv4 check box and then select Save.

Deploying Ubuntu 18.04 LTS AMIs

You perform this procedure twice to deploy two separate Ubuntu Linux EC2 instances, which you use to host the NGINX Plus web server software. The first time through this procedure, you create an Amazon EC2 instance named user1-example-ww1. The second time, you create an Amazon EC2 instance named user1-example-ww2. Some steps in this procedure are performed only once, the first time through, because you reuse those configuration objects. (For example: creating a new security group and creating a new cryptographic key to access Amazon EC2 instances.)

An Amazon Machine Image (AMI) is a template that contains the software configuration (operating system, application server, and applications) required to launch your Amazon EC2 instance. You can select AMIs that have been created by AWS via Quick Start, AMIs that have been created by trusted Amazon partners via AWS Marketplace, your own AMIs that you have customized and saved, or AMIs from the AWS user community. F5 recommends selecting an AMI from Quick Start or AWS Marketplace. This procedure uses the AWS Marketplace. For more information about AMIs, refer to Amazon Machine Images (AMI).

Note: This link take you to a resource outside of AskF5. The third party could remove these documents without our knowledge.

Impact of procedure: You are responsible for the cost of the AWS services used while running this deployment configuration. Some of these settings, such as instance type, increase the cost of deployment. Review cost estimates on the pricing pages for each AWS service. Prices are subject to change.

  1. Log in to the AWS Management Console using your AWS account.
  2. Under Services, enter “EC2” in the search box and then select EC2.
  3. Under EC2 Dashboard, select Instances.
  4. Select Launch Instance.
  5. In the search box, enter the following:

    Ubuntu 18.04 LTS - Bionic

  6. Select AWS Marketplace, then click Select next to the image named Ubuntu 18.04 LTS - Bionic.
  7. In the pop-up window, review the costs associated with the instance types and then select Continue.
  8. Select the check the box for the smallest available instance type, t2.nano, then select Next: Configure Instance Details.
  9. Set the following values:
    • From the Network list, select your newly created VPC. For example:

      vpc-0a1b2c3d4e5f6g7h8 | user1-example-vpc

    • From the Subnet list, select your newly created subnet. For example:

      subnet-0abc1def2ghi3jkl4 | user1-example-subnet

    • In the Network interfaces section, locate the Primary IP address box for eth0 and enter one of the following IP addresses, depending on which Ubuntu EC2 instance you are deploying:
      • user1-example-ww1: 10.0.0.201
      • user1-example-ww2: 10.0.0.202
  10. Select Next: Add Storage.
  11. Keep the default settings and select Next: Add Tags.
  12. Select Add Tag and then enter the following values:
    • Key: Name
    • Value: user1-example-ww1 (or user1-example-ww2 when creating the second EC2 instance).
  13. Select Next: Configure Security Group.
  14. Enter the following values:
    • Assign a security group: Create a new security group (or Select an existing security group, if deploying user1-example-ww2)
    • Security group name: user1-example-nginx-sg
    • Description: NGINX web server security group
    • Apply the following firewall rule
      TypeProtocolPort rangeSourceDescription
      SSHTCP22IP address used to connect to AWS. For example: 192.0.2.1/32SSH access

    Note: You create only one security group to use with both Ubuntu EC2 instances. When repeating this procedure to create the user1-example-ww2 EC2 instance, reuse the security group that is created for the user1-example-ww1 EC2 instance.

    Important: The security group is the firewall setting for your instance. The default rule allows SSH access from any IP address. The Ubuntu image being installed uses certificates for SSH login, so there is no password assigned by default. However, F5 recommends setting a source address that limits access to either a single known IP address or range of addresses. You can add or modify rules after creation to allow for broader access or fine tuning, as needed.

  15. Select Review and Launch.
  16. Review your settings and, when ready, select Launch.
  17. In the Select an existing key pair or create a new key pair window, select Create a new key pair from the list, enter user1-example-keys for the Key pair name, then select Download Key Pair. The key pair file is in the user1-example-keys.pem format, which you use to connect to your EC2 instances using SSH. If you are repeating this procedure to deploy user1-example-ww2, then select Choose an existing key pair and reuse the user1-example-keys key pair.

    Note: You can create new keys for each EC2 instance to limit security exposure if one key is compromised; however, in this test deployment, you use one key to access all EC2 instances.

    Important: Amazon EC2 uses public key cryptography to encrypt and decrypt login information, using 2048-bit SSH-2 RSA keys. Amazon EC2 stores the public key only, and you store the private key, in the form of the PEM file you are downloading. Anyone who possesses your private key can decrypt your login information, so it is important that you store your private keys in a secure place. Additionally, you won’t get another chance to download this key pair. If you lose this key pair, or fail to download it at this time, you cannot access the new instance you have created; when this happens, you must terminate this image and start over. For more information about key pairs, refer to Amazon EC2 Key Pairs.

    Note: This link take you to a resource outside of AskF5. The third party could remove these documents without our knowledge.

  18. Select Launch Instances.
  19. Select View Instances. The new instance is not available until the Status Checks column changes from Initializing to 2/2 checks passed. This may take several minutes after deploying a new EC2 instance.

    Note: If this is the second time through this procedure, skip the following steps and start the Installing NGINX Plus procedure.

  20. If connecting to AWS using a Linux or Mac computer, restrict permissions on the saved private key file using the following command:

    chmod 400 user1-example-keys.pem

  21. If connecting to AWS using a Windows computer, you must convert the PEM-formatted key file to PPK format for use with the PuTTY and WinSCP utilities:
    1. From the Windows Start menu, open the PuTTYgen utility.
    2. Select Load.
    3. In the pop-up window, change the file type from PuTTY Private Key Files (*.ppk) to All Files (*.*), then select the PEM file you saved in the previous procedure and select Open. The PuTTYgen utility displays a message similar to the following example:

      Successfully imported foreign key
      (OpenSSH SSH-2 private key (old PEM format)).
      To use this key with PuTTY, you need to
      use the "Save private key" command to
      save it in PuTTY's own format.

    4. Select OK.
    5. Select Save private key, and then select Yes at the passphrase warning.

      Note: If you set a passphrase, you must provide this passphrase each time you use the private key to connect to your Ubuntu instance.

  22. Repeat this procedure to create the second Ubuntu 18.04 EC2 instance, user1-example-ww2.

Installing NGINX Plus

You perform this procedure twice; once on each Ubuntu EC2 instance. The procedure describes the process of connecting to your Ubuntu EC2 instance, downloading and installing the NGINX Plus web server software, and configuring a basic HTML page to identify which EC2 instance is serving the web page. When performing this procedure the second time, ensure that you replace references to user1-example-ww1 with user1-example-ww2.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the NGINX Plus Customer Portal.
  2. Download your nginx-repo.crt and nginx-repo.key files to your desktop.
  3. Log in to the AWS Management Console using your AWS account.
  4. Under Services, enter “EC2” in the search box and then select EC2.
  5. Under EC2 Dashboard, select Instances.
  6. Select your user1-example-ww1 EC2 instance.
  7. At the bottom of the page, from the Description tab, make note of the Public DNS (IPv4) name assigned to your EC2 instance. For example:

    ec2-192-0-2-10.us-west-2.compute.amazonaws.com

  8. For Linux and Mac users, use SCP to upload your nginx-repo.crt and nginx-repo.key files to the /home/ubuntu directory of your user1-example-ww1 EC2 instance, using the Public DNS (IPv4) name from the EC2 instance. For example:

    scp -i "user1-example-keys.pem" nginx-repo.crt ubuntu@ec2-192-0-2-10.us-west-2.compute.amazonaws.com:~/
    scp -i "user1-example-keys.pem" nginx-repo.key ubuntu@ec2-192-0-2-10.us-west-2.compute.amazonaws.com:~/

  9. For Windows users, use WinSCP to upload your nginx-repo.crt and nginx-repo.key files:
    1. Open the WinSCP utility on your Windows computer.
    2. In the Login window, for Host name, enter the Public DNS (IPv4) name of the EC2 instance. For example:

      ec2-192-0-2-10.us-west-2.compute.amazonaws.com

    3. For User name, enter ubuntu.
    4. Select Advanced and then go to SSH > Authentication.
    5. In the Authentication parameters section, select the button labeled '...' next to the Private key file box and then open your PPK file. For example:

      user1-example-keys.ppk

    6. Select Login to open a connection to your user1-example-ww1 EC2 instance.
    7. Locate and upload your nginx-repo.crt and nginx-repo.key files to the /home/ubuntu directory of your user1-example-ww1 EC2 instance.
  10. For Linux and Mac users, use SSH to connect to your user1-example-ww1 EC2 instance, using the Public DNS (IPv4) name. For example:

    ssh -i "user1-example-keys.pem" ubuntu@ec2-192-0-2-10.us-west-2.compute.amazonaws.com

  11. For Windows users, use PuTTY to connect to your user1-example-ww1 EC2 instance, using the Public DNS (IPv4) name:
    1. Open the PuTTY utility on your Windows computer.
    2. In the PuTTY Configuration window, for Host Name (or IP address), enter the username ubuntu and the Public DNS (IPv4) name of the EC2 instance. For example:

      ubuntu@ec2-192-0-2-10.us-west-2.compute.amazonaws.com

    3. In the Category menu, go to Connection > SSH > Auth.
    4. Under Authentication parameters, select Browse and then open your PPK file. For example:

      user1-example-keys.ppk

    5. Select Open to open a connection to your user1-example-ww1 EC2 instance.
       
  12. Create and change to the /etc/ssl/nginx directory by entering the following command:

    sudo mkdir /etc/ssl/nginx && cd /etc/ssl/nginx

  13. Copy the nginx-repo.crt and nginx-repo.key files to the /etc/ssl/nginx directory by entering the following command:

    sudo cp /home/ubuntu/nginx-repo.* /etc/ssl/nginx

  14. Download the NGINX signing key from nginx.org by entering the following command:

    sudo wget https://nginx.org/keys/nginx_signing.key

  15. Add the NGINX signing key to your keyring by entering the following command:

    sudo apt-key add nginx_signing.key

  16. Prepare the package manager to use HTTPS and connect to the NGINX repository by entering the following command:

    sudo apt-get install apt-transport-https lsb-release ca-certificates

  17. Configure the NGINX Plus repository by entering the following commands:

    printf "deb https://plus-pkgs.nginx.com/ubuntu `lsb_release -cs` nginx-plus\n" | sudo tee /etc/apt/sources.list.d/nginx-plus.list
    sudo wget -q -O /etc/apt/apt.conf.d/90nginx https://cs.nginx.com/static/files/90nginx

  18. Update the local APT repository and install NGINX Plus by entering the following command:

    sudo apt-get update && sudo apt-get install -y nginx-plus

  19. Start the NGINX Plus web server by entering the following command:

    sudo systemctl start nginx

  20. Create a backup of the original NGINX index.html file by entering the following commands:

    cd /usr/share/nginx/html
    sudo mv index.html index.html.orig

  21. Using a text editor, such as vi, create a new index.html file with the following contents:

    <!DOCTYPE html>
    <html>
    <head>
      <title>user1-example-ww1</title>
    </head>
    <body>
      <h1>You are connected to user1-example-ww1</h1>
    </body>
    </html>

  22. Save the file and then close the text editor.
  23. Confirm the page loads by entering the following command:

    curl localhost

    The output should display the HTML contents added in step 21. If there are errors, review the output of the following two commands:

    systemctl status nginx

    sudo nginx -t

    Note: At this point, you cannot view your web server using the Public DNS (IPv4) name of the EC2 instance because the user1-example-nginx-sg security group is configured only to allow SSH access over TCP port 22.

  24. Repeat this procedure for your user1-example-ww2 EC2 instance.

Deploying a single NIC BIG-IP VE

The F5 BIG-IP VE - ALL (BYOL, 1 Boot Location) uses BIG-IP version 15.1.0.4 and cannot be upgraded. Configuring BIG-IP LTM HTTP load balancing

  • Modifying your AWS security group
  • Creating a pool and virtual server

Modifying your AWS security group

To allow HTTP traffic to flow from the BIG-IP LTM system to the NGINX pool members, you must add a new firewall rule to the user1-example-nginx-sg security group. You can create multiple rules to allow for different types of monitor traffic, such as ICMP, TCP, or HTTP monitors. You can also specify a single IP address, an IP range, all IP addresses, or another security group as the Source for the firewall rule. The more restrictive the firewall rule settings, the more difficult it may be to troubleshoot certain connectivity issues; however, it is considered a best practice to configure rules to only allow expected traffic. In this deployment, you configure a new rule with HTTP as the Type and the user1-example-ltm-sg security group as the Source.

Impact of procedure: Misconfigured firewall rules can unexpectedly block legitimate traffic and can also leave your system vulnerable to illegitimate traffic. Pay close attention to the rules you are configuring.

  1. Log in to the AWS Management Console using your AWS account.
  2. Under Services, enter “EC2” in the search box and then select EC2.
  3. Go to EC2 Dashboard > Network & Security > Security Groups.
  4. Locate your user1-example-ltm-sg security group and copy the Group ID. For example:

    sg-012a345bcd67askf5

  5. Select your user1-example-nginx-sg security group, select the Inbound rules tab, and then select Edit inbound rules.
  6. Select Add rule and then add the following values for the new rule.
     
    TypeProtocolPort RangeSourceDescription
    HTTPTCP80Your user1-example-ltm-sg Group ID.
    For example: sg-012a345bcd67askf5    		HTTP traffic from the BIG-IP LTM system
  7. Select Save rules.

Creating a pool and virtual server

This final procedure creates the HTTP load balancing configuration, including the pool for the NGINX web servers, a health monitor for the pool members, and a virtual server to accept HTTP traffic from web clients.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility. For example:

    https://ec2-192-0-2-20.us-west-2.compute.amazonaws.com:8443

  2. Go to Local Traffic > Pools > Pool List, and then select Create.
  3. For Name, enter pool_nginx.
  4. For Description, enter a short description.
  5. For Health Monitors, select tcp in the Available list and move it to the Active list.
  6. For New Members, enter 10.0.0.201 in the Address box, and 80 in the Service Port box, then select Add.
  7. Repeat the previous step to add 10.0.0.202.
  8. Keep all other settings at default and select Finished.
  9. Go to Local Traffic > Virtual Servers > Virtual Server List, and then select Create.
  10. For Name, enter vs_nginx.
  11. For Description, enter a short description.
  12. For Destination Address/Mask, select Host and then enter 10.0.0.200.
  13. For Service Port, select Port and then enter 80.
  14. For HTTP Profile (Client), select http.
  15. For Source Address Translation, select Auto Map.
  16. For Default Pool, select pool_nginx.
  17. Select Finished.
  18. Open a new browser window and connect to your virtual server using the Public DNS (IPv4) address of your user1-example-ltm EC2 instance and port 80. For example:

    http://ec2-192-0-2-20.us-west-2.compute.amazonaws.com

  19. Reload your browser multiple times, using Ctrl+F5, to observe load balancing between the NGINX pool members.
  20. In the BIG-IP Configuration utility, go to Statistics > Module Statistics > Local Traffic.
  21. For Statistics Type, select Pools to view the load balancing statistics between the NGINX pool members.
