Topic

This article covers how to configure the Link Down Time on Failover setting in conjunction with the network failover timeout setting.

Description

The Link Down Time on Failover setting is used in environments where the upstream device's Address Resolution Protocol (ARP) cache restricts updates until a specific period of time passes, or if the device on the interface is no longer available. When the Link Down Time on Failover setting is enabled and a failover occurs, the failing unit will mark any interfaces for the external Virtual Local Area Network (VLAN) as down. As a result, the upstream device will flush its ARP cache and allow the upstream device to accept the newly active unit's ARP information.

In an active-standby HA pair, by default, one BIG-IP system demotes to standby mode after a failover event is complete and communication between the systems is restored. Since the Link Down Time on Failover is a global setting, it will bring down the interface you use for network failover on the BIG-IP system. If the Link Down Time on Failover setting exceeds the three second default network failover timer value, the network failover timer undergoes 30 unsuccessful attempts to communicate with the partner unit. As a result after failover, the BIG-IP system behaves as though it has lost network connectivity to its peer unit, and both units enter an unintended active-active state if no other working network failover connectivity is present, such as one using management IPs.

Note: The Link Down Time on Failover setting determines how long the links remain down after the unit fails over and enters standby mode. The setting is only available when a BIG-IP pair is configured as a redundant pair. By default, the Link Down Time on Failover is disabled, which means it is set to 0 (zero), on both BIG-IP units in a redundant pair.

The following two database variables specify these timeout values.

Database variableDefinitionDefault setting
failover.standby.linkdowntimeSpecifies the time in seconds the interface is down after a failover occurs.

Note: The failover.standby.linkdowntime database variable is stored as 1/10th of a second.

0
failover.nettimeoutsecSpecifies the time in seconds that the standby unit will wait after the last update from the active unit before the standby attempts to become active.3 seconds

Recommendations

If Link Down Time on Failover setting is less than the network failover timeout setting, but your HA pair enters longer than expected unintended active-active state after a failover, F5 recommends increasing the network failover timeout value to 5 seconds greater than the Link Down Time on Failover setting value even if the Link Down Time on Failover setting is less then the default network failover timeout value of 3.

Also, F5 recommends configuring network failover on the management interface in addition to the TMM interface to create network failover channel redundancy.

To set the failover.standby.linkdowntime and failover.nettimeoutsec database variables, perform the following procedure:

Impact of procedure: Changing the failover.nettimeoutsec to a value that is less than the default of 3 seconds may unnecessarily increase failover events. Conversely, changing the variable to a value that is too high may delay actual failover events.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To set the failover.standby.linkdowntime database variable, enter the following command:

    modify /sys db failover.standby.linkdowntime value 1

  3. To set the failover.nettimeoutsec database variable, enter the following command:

    modify /sys db failover.nettimeoutsec value 5

Note: For most environments, F5 recommends that you use the default failover.nettimeoutsec and failover.standby.linkdowntime setting.
