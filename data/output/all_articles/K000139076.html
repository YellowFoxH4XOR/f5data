K000139076: [SAML] After turning on "Require verification certificates" on Azure (as IDP), Authentication fails with "The request sent by client is not signed while the application requires signed requests" on Azure side

Description

When utilizing SAML for authentication with Azure as the Identity Provider (IDP) , we can encounter an error after enabling the "Require verification certificates" option on Azure. The Azure error states, "The request sent by the client is not signed while the application requires signed requests." - error code 76021.

Here is how it looks on Azure:

Error:

:

 

Environment

  • Azure (as IDP) SAML Authentication
    SAML Request Signing turned ON on Azure

Cause

Single Sign-On Service Binding method set to HTTP-Redirect instead of HTTP-POST, as required by the Azure IDP.

Recommended Actions

  1. Verify the certificate used for signing the SAML requests is correctly configured and is the one expected by Azure IDP.
  2. Change the SSO service binding method from HTTP-Redirect to HTTP-POST in the IDP connector configuration on BIG-IP. This is because Azure IDP expects the SAML request to be sent using the HTTP-POST binding method when the "Require verification certificates" option is enabled.
    Access  ››  Federation : SAML Service Provider : External IdP Connectors
  3. Ensure that the signature type is set to RSA-SHA256, as Azure IDP does not accept RSA-SHA1 by default.
    Access  ››  Federation : SAML Service Provider : External IdP Connectors

Additional Information

For further support and guidance, you can refer to the Azure documentation on enforcing signed SAML requests at: https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/howto-enforce-signed-saml-authentication
