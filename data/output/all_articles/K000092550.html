K000092550: Unable to Monitor the Standby Device using SNMP

Type
Support Solution
Published
2022-11-04
Updated
2022-12-28
Source
https://my.f5.com/manage/s/article/K000092550

Description

SNMP traps are only able to monitor the Active BIG-IP device, however, not the Standby peer device.

When the peer device becomes Active, monitoring works.

Example of SNMP Trap configured for the monitoring:

traps {

/Common/i<name_of SNMP_trap> {

auth-password <encrypted_text>

auth-password-encrypted "<encrypted_text>"

auth-protocol sha

engine-id <encoded_ID>

host <hostname_IP>

privacy-password <encrypted_text>

privacy-password-encrypted <encrypted_text>

privacy-protocol <protocol>

security-level auth-privacy

security-name <text>

version X

}

Environment

  • High Availability
  • SNMPv3


Cause

An SNMP agent defines a unique engineID in order to respond to SNMPv3 requests. When two devices have the same engineID, the configuration does does not work.

 

 Recommended Actions

To change the engineID, refer to K15681 contains the steps to change the engineID .
