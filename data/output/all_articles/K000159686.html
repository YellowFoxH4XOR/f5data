Topic

You should consider using this procedure under the following condition:

  • You want to deploy a BIG-IP Virtual Edition (VE) instance in an existing Proxmox Virtual Environment (PVE) 9.x.

For information on deploying BIG-IP VE instances on PVE prior to 9.x, refer to K85183351: How to deploy BIG-IP VE with Proxmox Virtual Environment.

Description

The PVE 9.x integrates the Kernel-based Virtual Machine (KVM) hypervisor, LXC Linux containers, software defined storage and network functionality into a single management platform that allows configuration, deployment, and monitoring through web-based user interface (webUI). This article assumes that you have installed and configured the appropriate resources for the PVE datastores and network on your PVE host. Prior to deploying a BIG-IP VE instance, you should download the compressed BIG-IP VE qcow2 image file from MyF5 and then upload the file to your PVE host.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a general understanding of the PVE.
  • You are familiar with using the Linux command line.
  • You have access to the PVE web UI on TCP port 8006 and SSH on port 22.
  • You have a BIG-IP registration key and access to the internet.

    Note: The BIG-IP VE instance does not require access to the internet; however, you will need internet access from your local workstation to complete the manual licensing of the BIG-IP VE instance.

Configuring VLANs for PVE host with multiple network interfaces

If your PVE is on a host with multiple network interfaces and these interfaces are plugged into switch ports configured with tagged VLANs, you can create a Linux VLAN as well as the corresponding Linux Bridge for each tagged VLAN in the PVE. To do so, perform the following procedure:

Impact of procedure: Configuring new Linux VLANs and their corresponding bridges may require you to restart the network on the PVE host.

  1. Login to the PVE web UI as the administrative user.
  2. In the Resource Tree window, select Server View.
  3. Select the node name, for example pve.
  4. In the Content Panel window, select System, then Network.
  5. Select Create, then Linux VLAN. The PVE web UI pops up a Create: Linux VLAN dialog.
  6. Enter a name for the VLAN in the Name setting, for example vlan123.
  7. Enter the VLAN ID in the VLAN Tag setting, for example 123.
  8. Enter the interface name in the Vlan raw device setting, for example nic1.
  9. Select Create to save the configuration. The PVE web UI should return to the Network page.
  10. Select Create, then Linux Bridge. The PVE web UI pops up a Create: Linux Bridge dialog.
  11. Enter a name for the bridge in the Name setting, for example vmbr123.
  12. Enter the VLAN name in the Bridge ports setting, for example vlan123.
  13. Select Create to save the configuration. The PVE web UI should return to the Network page.
  14. Repeat steps 4 through 12 for each VLAN you want to configure on the Proxmox VE host.
  15. Select Apply Configuration for the new configuration to take effect. Select Yes when the PVE web UI prompts for a confirmation.

Downloading the compressed BIG-IP VE qcow2 image and uploading to the PVE host

You should download the compressed BIG-IP VE qcow2 image file (BIGIP-<version>.<type>.qcow2.zip) from MyF5 to your local workstation. For information about downloading from MyF5, refer to K000090258: Download F5 products from MyF5.

Note: For more information about image type, refer to K14946: Overview of BIG-IP VE image sizes.

Unzip the compressed BIG-IP VE qcow2 image file (BIGIP-<version>.<type>.qcow2.zip) on your local workstation and upload the BIGIP-<version>.qcow2 image to the PVE host by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the PVE web UI as the administrative user.
  2. In the Resource Tree window, select Server View.
  3. Select the datastore name, for example local (pve).
  4. In the Content Panel window, select Import.
  5. Select Upload. The PVE web UI pops up a Upload dialog.
  6. Select Select File.
  7. Locate the BIGIP-<version>.qcow2 image on your local workstation and select Open.
  8. Select Upload and wait for the image upload to complete. When the upload is successful, the PVE web UI displays a message similar to the following example:

    finished file import successfully
    TASK OK

    You should observe the imported BIG-IP VE qcow2 image in the list.

  9. Proceed to the next procedure to deploy the BIG-IP VE.

Deploying BIG-IP VE in PVE 9.x

To deploy a BIG-IP VE instance in PVE 9.x, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the PVE web UI as the administrative user.
  2. Select Create VM. The PVE web UI pops up a Create: Virtual Machine dialog.
  3. Note the value of the VM ID setting. This is needed in later steps when you attempt to import the BIG-IP qcow2 image. By default, the VM ID is pre-filled by the PVE host based on the available ID.
  4. Enter a name for your BIG-IP VE in the Name setting, for example bigip21x.
  5. Select Next. The Create: Virtual Machine dialog displays the OS tab.
  6. In the OS tab, select Do not use any media. Leave the Guest OS Type setting as Linux and the Guest OS Version setting as 6.x – 2.6 Kernel.
  7. Select Next. The Create: Virtual Machine dialog displays the System tab.
  8. In the System tab, select VirtIO SCSI for the SCSI Controller setting. Leave the remaining settings as default:
    • Graphic card setting – Default
    • Machine setting – Default (i440fx)
    • BIOS setting – Default (SeaBIOS)
    • Qemu Agent setting – unchecked
    • Add TPM setting – unchecked.
  9. Select Next. The Create: Virtual Machine dialog displays the Disks tab.
  10. In the Disks tab, leave all settings as default. This is because the disk configuration will be removed in later steps after importing the BIG-IP qcow2 image.
  11. Select Next. The Create: Virtual Machine dialog displays the CPU tab.
  12. In the CPU tab, enter your preferred values for the Sockets setting and Cores setting. The values for these two settings directly affect the Total cores setting. For example, if you enter 2 for the Sockets setting and 2 for the Cores setting, the Total cores setting should display 4. Note that the number of cores you configure for your BIG-IP VE deployment affects the memory required in the next steps. You may want to review the memory and CPU requirements for KVM deployments in K15796: Hardware requirements to host BIG-IP VE on private cloud platforms.
  13. Select Next. The Create: Virtual Machine dialog displays the Memory tab.
  14. In the Memory tab, enter your preferred value in MB for the Memory (MiB) setting. For every core you have configured in previous steps, you should configure 2 GB or 2048 MB for the Memory (MiB) setting. For example, if you have configured 4 cores, you should configure 8 GB or 8192 MB for the memory.
  15. Select Next. The Create: Virtual Machine dialog displays the Network tab.
  16. In the Network tab, select VirtIO (paravirtualized) for the Model setting and enter your preferred bridge name for the Bridge setting. The bridge name should be a bridge to your PVE host management interface, for example vmbr0. If you want to add more network interfaces to your BIG-IP VE deployment, you can only do so after creating the VM in the PVE web UI.
  17. Select Next. The Create: Virtual Machine dialog displays the Confirm tab.
  18. In the Confirm tab, check the VM configuration and select Finish when you are ready. The PVE web UI returns to the main page.
  19. In the PVE main page, select the newly created VM, for example 103 (bigip21x).
  20. To add more network interfaces, select Hardware and then select Add followed by Network Device. The PVE web UI pops up a Add: Network Device dialog.
  21. In the Add: Network Device dialog, select the VLAN bridge you have previously configured on your PVE host for the Bridge setting, for example vmbr123. Additionally, select VirtIO (paravirtualized) for the Model setting. Select Add to save the configuration.
  22. Repeat steps 20 through 21 for the remaining network interfaces you want to add.
  23. Detach and remove the existing hard disk by selecting the Hard Disk (scsi0) device and then select Detach. Select Yes when the PVE web UI prompts for confirmation. The PVE host will redesignate the Hard Disk (scsi0) device as the Unused Disk 0 device. Then select the Unused Disk 0 device and select Remove. Select Yes when prompted for confirmation.
  24. For the new VM to use the BIG-IP qcow2 image you have uploaded to the PVE host in the previous procedure, select Hardware and then select Add followed by Import Hard Disk. The PVE web UI pops up a Add: Hard Disk dialog.
  25. Select the PVE datastore where the BIG-IP qcow2 image is residing for the Import Storage setting, for example local.
  26. Select the BIG-IP VE qcow2 image you have uploaded in the previous procedure for the Select Image setting, for example BIGIP-21.0.0-0.0.10.qcow2.
  27. Select the PVE datastore for your BIG-IP deployment for the Target Storage setting, for example local-lvm.
  28. Select Add to start the image import process.

    Important: The import procedure can take several minutes depending on your PVE host. When the import is completed successfully, the PVE web UI should return an output similar to the following example:

    scsi0: successfully created disk 'local-lvm:vm-103-disk-0,size=82G'
    TASK OK

    You should observe a new Hard Disk (scsi0) device for your BIG-IP VE deployment.

  29. To configure the VM to boot the imported image, select the VM name followed by Options. Select Boot Order and select Edit.
  30. Select Enabled for the scsi0 device and drag it up to the top. Select OK to save the changes.
  31. Select Start to start the VM. To view the boot up process, select Console.

Configuring the BIG-IP VE deployment

Using the PVE console window launched from the deployed BIG-IP VE instance in the previous procedure, you can login to the deployed BIG-IP VE instance console and perform the basic configuration. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Login to the BIG-IP VE instance console as the root user. The system will prompt you to reset the root user password. For information about the root default password and the password policy requirements, refer to K10612010: Root and admin users must reset default passwords when logging in to the BIG-IP system for the first time.
  2. To access the tmsh utility, enter the following command:

    tmsh

  3. Determine if there is an existing default management IP address by entering the following tmsh command:

    list /sys management-ip

  4. Disable DHCP for the management IP by entering the following tmsh command:

    modify /sys global-settings mgmt-dhcp disabled

  5. If there is an existing default management IP address, delete it by entering the following tmsh command syntax:

    delete /sys management-ip <existing IP address>

  6. Configure your preferred management IP address by entering the following tmsh command syntax:

    create /sys management-ip <IP address>/<netmask>

  7. Configure your preferred management default gateway by entering the following tmsh command syntax:

    create /sys management-route default gateway <gateway IP address>

  8. Save the configuration by entering the following tmsh command:

    save /sys config

  9. You can now proceed to access the BIG-IP Configuration utility of the deployed BIG-IP VE instance to license, provision and configure the virtual server(s) and pool(s). If your BIG-IP VE instance deployment is configured with a single network interface, you should access the BIG-IP Configuration utility using the management IP address you have configured in step 6 and port 8443; that is https://<management IP address>:8443/. If your BIG-IP VE instance deployment has multiple network interfaces, you should access the BIG-IP Configuration utility using https://<management IP address>/
