Description

A POST request requiring JWT validation from an external IDP server fails.

The error.log will have

[warn] 2292589#2292589: *379 upstream server temporarily disabled while reading response header from upstream, client: 1.2.3.4, server: sp.example.com, request: "POST /test/ping/ HTTP/1.1", subrequest: "/_jwks_uri", upstream: "https://4.5.6.7:443/.well-known/openid-configuration/jwks", host: "idp.example.com"

[error] 2292589#2292589: *379 upstream timed out (110: Connection timed out) while reading response header from upstream, client: 1.2.3.4, server: sp.example.com, request: "POST /test/ping/ HTTP/1.1", subrequest: "/_jwks_uri", upstream: "https://4.5.6.7:443/.well-known/openid-configuration/jwks", host: "idp.example.com"

If NGINX debug logging is enabled you see.

GET /.well-known/openid-configuration/jwks HTTP/1.0
Host: idp.example.com
Connection: close
Content-Length: 79 <<<<===== ERROR
Authorization: Bearer <SNIP>
Content-Type: application/json

Environment

NGINX Plus implementing JWT authentication that is configured to fetch JSON Web Keys from remote location (directive auth_jwt_key_request)

For more information, refer to the Setting up JWT Authentication section of the NGINX Plus Admin Guide

        location = /_jwks_uri {
            internal;
            proxy_method      GET;
            proxy_cache       jwk; # Cache responses
            proxy_cache_valid 200 12h;
            proxy_pass        https://idp.example.com/oauth2/keys; # Obtain keys from here
        }

Cause

NGINX forwards client request headers into subrequests. This means the Content-Length and Content-Type headers from the client's POST request are passed to the GET method subrequest. These headers are invalid in a GET method request and may cause the authentication server to fail or timeout.

Recommended Actions

Remove the headers before sending upstream by using Proxy_set_header.

location = /_jwks_uri {
internal;
proxy_method GET;
proxy_cache jwk; # Cache responses
proxy_cache_valid 200 12h;
proxy_set_header Content-Type "";
proxy_set_header Content-Length "";
proxy_pass https://idp.example.com/oauth2/keys; # Obtain keys from here
}

Warning. Setting proxy_set_header in a "Location" overrides all proxy_set_header from a higher level. They are not merged. This is true even for different headers. Any proxy_set_header at "server" must be reproduced in "Location". This is by design.

Additional Information

Similar issues can come from other causes. Confirm that:

  • NGINX can contact the IDP.
  • The IDP returns the JWT in uncompressed form.
  • The upstream resolves to the correct IDP server.

Be aware of limitations on using proxy_pass FQDN's. These are not re-resolved dynamically. If the A record is subject to change, configure using a "Upstream" with a resolve option. For more information, refer to the Using DNS for Service Discovery with NGINX section of Using DNS for Service Discovery with NGINX and NGINX Plus.

If this is the issue but the configuration change does not solve it, restart the host. This may be the case when the NGINX debug binary is in service.
