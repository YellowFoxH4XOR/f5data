Known Issue

Passive FTP connections may fail when a secure network address translation (SNAT) pool is configured.

This issue occurs when all of the following conditions are met:

  • The configuration contains a SNAT pool with more than one member.
  • The SNAT pool is referenced by a virtual server or by a global SNAT object with an origin address of 0.0.0.0/0.
  • The configuration contains an FTP virtual server.

If the FTP virtual server traffic is configured to traverse the SNAT pool, the BIG-IP system may select a different source address for passive FTP control and data channel connections. Under those conditions, the passive FTP connection fails.

Impact

Passive FTP connections fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H459695 on the Diagnostics > Identified > Medium screen.
  • Passive FTP connections fail.
  • Selection of a specific member in a SNAT pool is ignored when using the snatpool iRules command.

Workaround

You can work around this issue by modifying the SNAT pool associated with the virtual server to use only one member.

Impact of workaround: Decreasing the number of SNAT pool members to one increases the potential for ephemeral port exhaustion. If only one SNAT member is used, the maximum concurrent connections are 65,535. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
