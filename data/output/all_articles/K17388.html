Known Issue

Older monitor instances may remain in the system after you perform a configuration merge that modifies an existing pool monitor.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration contains a pool with a health monitor that is actively monitoring pool members.
  • You perform a configuration merge using the following command syntax:

    tmsh load sys config merge <file>

  • The configuration merge modifies the type of health monitor used by the pool.

Impact

Pool members may not be available to process production traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice that your BIG-IP system incorrectly marks pool members down or offline.
  • In the /var/log/ltm file, you observe error messages similar to the following example:

    err mcpd[8793]: 01070712:3: Caught configuration exception (0), Can't find monitor rule: 4619.

Workaround

To work around this issue, you can reload the configuration and restart the bigd monitoring process. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform the workaround during a maintenance window, if possible.

  1. Log in to the command line of the BIG-IP system.
  2. To save the system configuration, type the following command:

    tmsh save sys config

  3. To load the system configuration, type the following command:

    tmsh load sys config

  4. To restart the bigd monitoring process, type the following command:

    bigstart restart bigd

    If this is a multi-blade VIPRION device, type the following command:

    clsh bigstart restart bigd
