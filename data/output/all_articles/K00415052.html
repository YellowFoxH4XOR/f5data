Known Issue

During an upgrade on the iSeries platforms, Always-On Management (AOM) may become stuck as it attempts to update.

This issue occurs when all of the following conditions are met:

  • You have one of the following BIG-IP platforms:
    • i850
    • i2x00
    • i4x00
    • i5x00
    • i7x00
    • i10x00
    • HRC-i2x00
    • HRC-i5x00
    • HRC-i10x00
  • You perform an upgrade from any of the following BIG-IP versions:
    • 13.0.0
    • 12.1.2
    • 12.1.1
  • Your BIG-IP system has been powered on for approximately five weeks or more prior to the upgrade.

Impact

AOM gets stuck in firmware update mode, which causes all subsequent Intelligent Platform Management Interface (IPMI) commands from the BIG-IP system to fail. Additionally, the BIG-IP system cannot be licensed.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The serial console displays output similar to the following example:

    Retrigger udev events[  OK  ]
    Starting sshd: [  OK  ]
    Checking for firmware updates: Updating AOM to /usr/firmware/bmc_shuttle_2.51.ima_enc
    Updating AOM ... DO NOT POWER DOWN ... THIS MAY TAKE UP TO 12 MINUTES TO COMPLETE
    Updating AOM ... DO NOT POWER DOWN ... THIS MAY TAKE UP TO 12 MINUTES TO COMPLETE (elapsed seconds:1)

  • The unit does not boot up to the host.
  • The unit reports firmware upgrade in progress on the LCD.
  • The Configuration utility is unavailable.

Workaround

To work around this issue, you can reset the AOM before performing an upgrade. If you have already performed the upgrade, rebooted, and the AOM is not responding, you can reset the AOM and the host subsystem to recover the system. If the AOM command menu is inaccessible or does not display an option to reset the AOM after the upgrade, you must power cycle the BIG-IP system. To do so, perform one of the following procedures:

  • Resetting the AOM before performing an upgrade
  • Recovering an unresponsive AOM after performing an upgrade and restarting
  • Recovering an unresponsive AOM after performing an upgrade and restarting when the AOM command menu is inaccessible

Resetting the AOM before performing an upgrade

Impact of workaround: F5 recommends performing this procedure during a scheduled maintenance period because you will temporarily be unable to monitor the hardware. In addition, you should perform this procedure only on the standby unit because the CPU usage may increase during the process of resetting the AOM and this may impact the system's performance especially when it is already under a heavy load. When you reset the AOM, the host system logs errors which you can safely ignore.

Using the AOM menu

  1. Access the AOM command menu by way of the serial console.
  2. Reset the AOM by selecting option A --- Reset AOM.

Using the Advanced Shell (bash)

  1. Log in to bash.
  2. To reset the AOM, type the following command:

    ipmiutil reset -k

Recovering an unresponsive AOM after performing an upgrade and restarting

Impact of workaround: You are temporarily unable to monitor the hardware, and the system logs errors (which you can safely ignore) on the host when you reset the AOM. A hardware reset is issued when resetting the host subsystem. The system is unavailable while the host restarts.

  1. Access the AOM command menu by way of the serial console.
  2. Reset the AOM by selecting option A --- Reset AOM.
  3. Access the AOM command menu by way of the serial console after AOM restarts.
  4. Reset the host by selecting option R --- Reset host subsystem.

Recovering an unresponsive AOM after performing an upgrade and restarting when the AOM command menu is inaccessible

Impact of workaround: The following procedure stops all traffic processing while the system is power cycled. Both the AOM and host subsystem are unavailable while powered off. You are temporarily unable to monitor the hardware when you reset the AOM.

Note: The halt command powers off the BIG-IP host subsystem. For more information, refer to K17261: The halt command now powers off the BIG-IP host subsystem.

  1. Log in to bash.
  2. Shut down and power off the host subsystem system by typing the following command:

    halt

  3. Power off the BIG-IP appliance and physically remove the power cable from the PSU, for a few seconds, to reset the AOM.
  4. Insert the power cable back into the PSU and power on the BIG-IP appliance.
