K000090888: NGINX App Protect behind Akamai causes issues for bot detection

Type
Support Solution
Published
2021-11-24
Updated
2026-07-29
Source
https://my.f5.com/manage/s/article/K000090888

Description

  • Trusted Bots (search engines) are blocked
  • bot_anomalies="Search Engine Verification Failed"

Environment

  • NGINX App Protect WAF
  • Access is via Akamai or similar proxy

Cause

Anti Automation uses revers DNS lookups to identify the client. This forms part of the evaluation of requests and identifies Trusted Bots. When the source IP is changed, header information can be used. By default the "X-Forwarded-For" is used when XFF trust is enabled (disabled by default) , but Akamai also inserts the header "True-Client-IP", which is a better choice since it only contains the original client IP.

Recommended Actions

Configure default XFF trust (this will use the "X-Forwarded-For" header):

{
   "policy": {
       "name": "xff_enabled",
       "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
       "applicationLanguage": "utf-8",
       "enforcementMode": "blocking",
       "general": {
           "customXffHeaders": [],
           "trustXff": true
       }
   }
}

Configure XFF trust to use Akamai's "True-Client-IP" header:

{
   "policy": {
       "name": "xff_custom_headers",
       "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },
       "applicationLanguage": "utf-8",
       "enforcementMode": "blocking",
       "general": {
           "customXffHeaders": [
               "True-Client-IP"
           ],
           "trustXff": true
       }
   }
}
