Description

An HTTP redirect iRule stopped working on a BIG-IP Advanced WAF virtual server hosting multiple websites. The issue is characterized by failed redirects and TCL errors in the logs, specifically:

err tmm[21399]: 01220001:3: TCL error: /Common/iRule <HTTP_REQUEST> - Can't call after responding - ERR_NOT_SUPPORTED (line 1) invoked from within "HTTP::uri"

This occurs when multiple iRules are applied to the same virtual server, and one iRule attempts to process an HTTP request after a response has already been sent by another iRule.

Environment

  • Product: BIG-IP Advanced WAF
  • Multiple websites behind a single virtual server
  • Host-header-based routing via iRule
  • Redirect iRule
  • Combined test iRule
  • Additional iRule also triggered on HTTP_REQUEST

Cause

Multiple iRules triggered on the HTTP_REQUEST event. After a redirect was issued (HTTP::redirect), subsequent iRules attempted to process the same request, resulting in the error logged to /var/log/ltm:

err tmm[21399]: 01220001:3: TCL error: /Common/iRule <HTTP_REQUEST> - Can't call after responding - ERR_NOT_SUPPORTED (line 1) invoked from within "HTTP::uri"

Once a response is sent, further HTTP processing in the same event is not supported.

Answer/Recommended Actions

To prevent this error and ensure proper redirect functionality:

  1. Edit each iRule triggered on the HTTP_REQUEST event.
  2. Add the following guard clause at the start of the iRule:
    if { [HTTP::has_responded] } { return }
  3. This ensures the iRule exits immediately if a response has already been sent, avoiding unsupported operations and errors.
  4. Review the order and logic of all iRules attached to the virtual server to ensure compatibility and proper event handling.
