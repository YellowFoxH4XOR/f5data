Known Issue

This is the result of a known issue. Using a Legacy Hosts Favorite, even if left idle, will prevent global or master group-based timeouts from logging out an inactive user.

F5 Product Development tracked this issue as CR67150 and it was fixed in FirePass version 6.0.1. For information about upgrading, refer to the FirePass release notes.

Note: Previously, the FirePass Release Notes for version 5.5.2 erroneously listed CR67150 as fixed.

Workaround

You can use idle timeouts on the remote legacy host to time out the login connected to the Legacy Hosts Favorite. When the connection to the Favorite is broken by logging the user out of the remote host, the FirePass idle timeout will resume functioning, even if the terminal emulator is still in view on the user's webtop.
