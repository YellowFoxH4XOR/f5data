Known Issue

The BIG-IP APM rewrite process may exit and restart when processing large amounts of cookie data.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for portal access.
  • A large amount of application data, such as multiple large HTTP cookies, is being sent to the rewrite process in a single message.
  • The size of the application data message is very close to, but does not exceed, the size limit for the internal communication channel.

The rewrite process uses internal communication channels to facilitate content rewriting for portal access. When the size of the application data in a single communication message reaches approximately 64 kilobytes, the internal size limit may be reached and cause the rewrite process to hang. While rare, this issue occurs most often when the total size of cookie data sent by the applications reaches approximately 32 kilobytes.

Impact

The BIG-IP APM system is temporarily unable to process portal access traffic while it recovers from the rewrite process restarting.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • User requests for portal access resources stall or fail.
  • Client connections to the BIG-IP APM system are dropped.
  • The BIG-IP APM system reports high CPU utilization or CPU utilization increases to 100 percent.
  • The BIG-IP APM rewrite and/or apd processes exit and generate core files to the /share/core directory.

Workaround

While there is no workaround for this issue, you may be able to mitigate the issue by reducing the amount of cookie data sent by the applications.
