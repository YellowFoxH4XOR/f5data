Topic

This article discusses details to consider when you want to deploy BIG-IP systems for high availability (HA) using an active-active configuration.

Description

Network device failures occur for a wide variety of reasons, resulting in unexpected interruptions to your applications and services. These unexpected outages reduce customer satisfaction and confidence, and as a result, incur loss of revenue vital for most organizations that conduct their businesses online. For these reasons, you must avoid outages, and your first step is to ensure application and service availability by deploying devices in an HA configuration. HA ensures that applications fail over seamlessly and service continues uninterrupted. You can also perform troubleshooting while the application or service is still functioning.

You can use an active-active configuration in BIG-IP systems that you are deploying for HA. When you do so, active devices in the same cluster process traffic separately during normal operations and fail over to one another when required. However, F5 does not recommend deploying BIG-IP systems in an active-active configuration without a standby device in the cluster, due to the potential loss of HA. Consider the following points:

  • When each BIG-IP system in the active-active configuration can process the application or services adequately, and with some additional resources in reserve, a failover from one active device to another active device is seamless, which allows applications and services to continue uninterrupted.
  • When each BIG-IP system in the active-active configuration runs at half or greater capacity, a failover from one active device to another active device may cause the device that is taking over to reach its processing threshold. As a result, the device fails and interrupts the applications and services. This condition can continue until both devices are restored to their operational capability.

Starting in BIG-IP 11.0.0, the Device Service Clustering (DSC) feature allows you to configure more than two BIG-IP systems in an HA configuration. The DSC feature also allows you to configure multiple devices as active and one or more devices as standby.

Recommendations

When planning for a deployment that requires HA, consider the following factors:

  • Consider deploying BIG-IP systems in an active-standby configuration.
  • If you must deploy BIG-IP systems in an active-active configuration, consider including at least an additional device in standby to mitigate the risk of loss of HA.
  • For versions prior to BIG-IP 11.5.0, an active-active configuration is not compatible with the HA group feature. Because the system applies an HA group score at the device level, the HA group configuration takes precedence, and one device is active while the others are standby. If you want to use HA groups in an active-active configuration, you must upgrade to BIG-IP 11.5.0 or later. Beginning in BIG-IP 11.5.0, the HA group score is applied at the traffic group level.

Deploying BIG-IP AAM or BIG-IP WAM devices in an active-active environment

In BIG-IP AAM and BIG-IP WAM systems—BIG-IP AAM replaces BIG-IP WAM—the virtual server that you configure with the caching profile determines the cache entities that the system generates. The system stores each cache entity in reference to the virtual server that processes the initial content request. As a result, when you configure active-active devices, they create a local cache that they do not share across devices.

You can see this dynamic in the following configuration example. In this scenario:

  • You configure the virtual servers to reside in separate traffic groups that are active on separate BIG-IP AAM devices.
  • The virtual servers process traffic using the same BIG-IP AAM caching profile.
  • The virtual servers process requests for the same server objects.

You can enable connection mirroring on the virtual servers; however, though the devices share the connection state, they do not share cached entities. In the event of a failover, the newly active device in the traffic group initializes building a cache of objects for the virtual server configured with the BIG-IP AAM caching profile.

Currently there is no method to share cached objects between BIG-IP AAM or BIG-IP WAM devices.
