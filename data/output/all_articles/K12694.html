Known Issue

This is the result of a known issue. When you use your VMware hypervisor product to suspend and then subsequently resume BIG-IP LTM Virtual Edition (VE) or BIG-IP APM VE, the TMM interfaces may hang. As a result, the system will lose connectivity to the production network.

When this issue occurs, error messages that appear similar to the following example are logged to the /var/log/ltm and /var/log/tmm files:

notice vmxnet3:0: rx completion misorder (b88 vs b87)
notice vmxnet3:1: rx completion misorder (9f0 vs 9ef)
notice vmxnet3:2: rx completion misorder (9d6 vs 9d5)
notice vmxnet3:3: rx completion misorder (9b1 vs 9b0)

Additionally, TMM may crash and dump core.

Note: Because the management interface uses a different driver, the management interface is not affected by this issue.

F5 Product Development tracked this issue as ID 224621 (formerly CR137014) and it was fixed in BIG-IP version 10.2.3 and 11.0.0. For information about upgrading, refer to the LTM or APM release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.2-852.0-HF1, which has been issued for BIG-IP version 10.2.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about downloading software from F5, refer to K167: Downloading software and firmware from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

Until this issue has been resolved, suspending BIG-IP LTM VE or BIG-IP APM VE is not supported and you should avoid doing so.

If you are currently affected by this issue, reboot the system to make it resume normal operation. You can do so by entering the reboot command from the command line.
