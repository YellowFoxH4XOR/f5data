Known Issue

This is the result of a known issue. The distributed Network-Attached Storage (dNAS) process may experience a failure for an ARX managed volume with Access-Based Enumeration (ABE) enabled. When an ABE-enabled directory contains more than 100,000 objects, if a client with access to none of the objects performs a directory listing, the dNAS process will fail and dump core. When the dNAS process fails it will automatically restart. However, the ARX system will experience a temporary service interruption until the dNAS process has restarted.

When this issue occurs, error messages that appear similar to the following example are logged to the syslog file:

:DNAS_PGRP-0-CRIT-MSG2:: smbfind.cc:1147: unsigned int smb_processor::find_files_internal(search_ctx*, unsigned int, unsigned int&, unsigned int, unsigned int&, unsigned int&, bool&):  assertion "loopcount < 1024" failed
:DNAS_PGRP-0-CRIT-MSG2:: aborting...
:NET_CIFS-0-ERR-NSM_CIFS_DOWN_DNAS:: Unresponsive DNAS instance at: <IP address>, disconnecting.
:LOG-0-ERR-FILTER:: dnas[9959]: [E:1] Writing core file

F5 Product Development is tracked this issue as ID 337998 and it was fixed in ARX 5.2.0. For information about upgrading, refer to the ARX release notes.

This issue was fixed in ARX 5.1.7 HF1 (build 12059). Customers affected by this issue can request this hotfix or later versions of the hotfix from F5 Technical Support, referencing this article and ID 337998.
