Known Issue

Loading a user configuration set (UCS) file may fail when the UCS contains inconsistent trust certificate/key objects.

This issue occurs when all of the following conditions are met:

  • You attempt to load the BIG-IP configuration using a UCS file.
  • The affected UCS has at least one of the following conditions:

    • Missing trust certificate or key files. For example, one or more files with the following names are not included in the UCS file: dtca.crt, dtca-bundle.crt, dtca.key, device cert, dtdi.crt or dtdi.key.
    • Inconsistent configuration of the trust certificate or key file objects. For example, the cache-path configuration entry for the affected file object in bigip_base.conf file is not consistent with the actual file location in the BIG-IP filestore.

The missing trust file objects or inconsistent configuration may result from one of the following reported known causes:

  • You previously performed a configuration load from a previously defective UCS.
  • You previously performed an incomplete load from a single configuration file (SCF).
  • You created a UCS after a configuration change without performing a config save operation.

Note: Other causes may exist that have not been reported or found. Therefore, this list may not be exhaustive.

Impact

You cannot load the affected UCS file.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H445556 on the Diagnostics > Identified > Medium screen.
  • You cannot load the UCS file.
  • When you load the affected UCS from the command line, you may observe the following error message:

    ERROR: UCS installation failed.
    Operation aborted

  • You may observe the following error message in the /var/log/ltm file:

    01070712:3: Caught configuration exception (0), _identify_jobs_todo:(/Common/dtca.key) :Failed: name (/Common/dtca.key) No copy in trash-bin
