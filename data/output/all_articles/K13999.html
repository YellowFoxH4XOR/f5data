Known Issue

A rare race condition during an installation may allow BIG-IP 10.x installations using the partitions disk-formatting scheme to fail.

This issue occurs when the following conditions are met:

  • Performing a fresh installation of an affected version to a system using the partitions disk-formatting scheme
  • This issue has been reported to affect only the BIG-IP 3400 and 3410 platforms

BIG-IP 10.x installations use the dynamic method for creating device nodes, which may allow for a race condition between modification of the partition table and the creation/deletion of related device nodes. As a result, the installer process may attempt to open a non-existent device node for a logical partition, which causes the installation to fail.

Important: The issue described in this article does not affect systems running volumes.

Impact

Installation failures may occur when using the partitions disk-formatting scheme.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The installation may fail with error messages that appear similar to the following example:

    debug: tm_install::Device::Device_make_fs -- Calling: /sbin/mkfs.ext3 -O ^resize_inode -j -L set.1./usr /dev/hdc9
    error: status 256 returned by command: /sbin/mkfs.ext3 -O ^resize_inode -j -L set.1./usr /dev/hdc9
    info: >++++ result:
    info: mke2fs 1.39 (29-May-2006)
    info: mkfs.ext3: No such file or directory while trying to determine filesystem size
    info: >----
    error: error adding /usr:83 volume to set hdc.1

Workaround

To work around this issue, you can retry the installation using the partitions formatting scheme. For installation information, refer to the BIG-IP release notes for the specific version you are installing and refer to K10819: Performing a clean installation of BIG-IP version 10.x or Enterprise Manager version 2.x.

Important: If you want to run BIG-IP 9.x along with 10.x, you must use the partitions style. However, if you run BIG-IP 10.x exclusively, F5 highly recommends using the volumes style. Additionally, if you want to run BIG-IP 11.x, you must use the volumes style.

Impact of workaround: None
