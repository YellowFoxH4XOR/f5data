K30664517: Create Active-Active topology for BIG-IP devices in two different subnet (no failover, sync-only).

Type
Support Solution
Published
2023-05-25
Updated
2025-04-01
Applies to
  • BIG-IP
Source

Description

You configured a sync-only device group with two BIG-IP inside it but sync does not work. There are no errors but the configuration is not getting synced.

Environment

  • 2x LTM devices on two different subnets

Cause

It's not possible to create sync-only device group that will allow you to sync objects from /Common partition and this is by design as per K63243467:

Note: You must associate a Sync-Only device group with a folder other than the / or /Common folders.

Recommended Actions

You can workaround restriction from K63243467 by following these steps:

Note: We assume that routing between both devices is configured correctly and trust relationship is already established.

1) Create a sync-failover device group without failover addresses and with network failover option disabled.
2) Add both devices to this device group.
3) This setup won't work because all routes from /Common are getting synced with a peer by default ( you can potentially run into K16956 issue). That's why performing following steps is required:

4) Delete the default route (Network > Routes) from the /Common partition
5) Create a new partition to contain the required HA IP routing:

5a) Go to System > Users > Partition List
5b) Click Create
5c) Set a Partition Name
5d) Uncheck all "Inherit..." options
5e) Set Device Group = None
5f) Set Traffic Group = traffic-group-local-only (non-floating)
5g) Click Finished

6. Switch to the new Partition - you can name it 'Routing' for clarity
7. Add all needed routes while being on this new partition
8. The common partition should not have any routes only traffic objects(VIPs, pools, etc).
9. Repeat this process on a peer.
10. Sync the configuration

The idea behind this workaround is to 'hide' the routes that reside on /Common so big-ip won't sync them with peer.
