Topic

BIG-IP CGNAT uses a disaggregation hash (DAG) to balance port blocks across Traffic Management Microkernel (TMM) processes. This article explains how DAG may affect your deployment and port block allocation (PBA) sizing strategy.

Note: Before you read this article, F5 recommends that you first become familiar with the concepts detailed in K14358: Overview of Clustered Multiprocessing.

Description

To localize a subscriber's session information, the TMM process always attempts to forward all packets associated with a particular flow across the same single TMM instance. The BIG-IP platform uses Source/Destination DAG (SP-DAG) to determine which TMM instance should handle a particular packet.

Enabling Endpoint-Independent Filtering (EIF) with the default (XOR port) egress DAG hash typically results in inefficient flow handling. This is because the TMM that creates the translation persistence entry differs from the TMM that accepts the return Internet traffic. The system must then forward packets between different TMMs, which reduces performance and increases latency. For this reason, the SP-DAG hash is mandatory for PBA.

If you select default, an error message similar to the following appears in the /var/log/ltm file and the translation fails:

err tmm[11448]: 01670024:3: Unsupported DAG mode for LSN pool(/Common/pool_name) mode PBA on interface /Common/External
