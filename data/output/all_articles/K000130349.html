K000130349: BIG-IQ server down, keep on restarting webd daemon/services and cannot access GUI

Type
Support Solution
Published
2023-02-02
Updated
2023-02-02
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0
Source
https://my.f5.com/manage/s/article/K000130349

Description

  • It is found out the webd service keeps restarting (loop) and cannot access to the BIG-IQ Configuration Utility (GUI)
  • Tried to resolve the issue by issue shell command # bigstart restart webd or # tmsh restart sys service webd, however, webd service went into restarting loop
  • Checking the "/var/log/webd.out, found alerts that "failed to bind the port 443/80 because they are already in used"
    • # tail -f /var/log/webd.out

webd: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)
webd: [emerg] bind() to [::]:443 failed (98: Address already in use)
webd: [emerg] bind() to 0.0.0.0:443 failed (98: Address already in use)
webd: [emerg] bind() to 0.0.0.0:80 failed (98: Address already in use)
webd: [emerg] bind() to [::]:443 failed (98: Address already in use)
webd: [emerg] bind() to 0.0.0.0:443 failed (98: Address already in use)

  • Make use of Linux Shell command "ss" found ports are used by httpd service instead

Environment

  • BIG-IQ
  • CM
  • Daemon:
    • webd
    • httpd
 

Cause

BIG-IQ httpd service were manually started by user

History logs: (iHealth)

40 1970-01-01 00:00:00 bigstart restart httpd

41 1970-01-01 00:00:00 bigstart restart httpd
 

Recommended Actions

  1. Make sure BIG-IQ httpd service is stopped (not running) # bigstart stop httpd, for details and the reason is because: 
    • BIG-IQ has replaced httpd with nginx service starting BIG-IQ v4.3.0 onward
    • The nginx service were replaced with webd service since BIG-IQ 4.4.0
    • please refer to KB article K14736 for details.
  2. Start/Restart the BIG-IQ webd service # bigstart start webd or # bigstart restart webd 
  3. Then run Linux "ss" command to confirm it is ran by webd service instead
