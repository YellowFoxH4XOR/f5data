Environment

  • BIG-IP CLI or GUI

Cause

"Host Processor Superuser" authorized_keys is missing in /shared/ssh/root/authorized_keys


Example :

[root@bigip:/S1-green-P::Active:Standalone] config # cat /shared/ssh/root/authorized_keys

ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQCi7zrdXAGusFPO0e1SeMbSzQ6AIRpFMzRGv3UQy5CyrO+i3YzRvF3SW3oSgYAsZQkscfGyKZ4+I3VaHyYiT2OffsS9VdhMGL800/U7LEkmmTEm5KZ1buRj27K+TccS7N+lruKmSX/eKvdZOBNEErE5niZ4LcTRgcrVkLsTyhfOKOWR1MYLI+IVOCp4BuLnRXQ5XNupj3Vqq+8IvEpa7PCSWlTtSA6Ziz8QNOiYwQd8/RFXaW98cVatR13QCKLEdDGtZDwT13lman778Ehmcw/j4vOJDNNwKagfNtL2LzsuouTXHqwGmSj/MizDYBI5JEYsjxADR3p6rAm5luYs2L6V Host Processor Superuser


Recommended Actions


1. To check if the "Host Processor Superuser" key is missing, run:

#cat /shared/ssh/root/authorized_keys


On Multi-blade Virpion Chassis , run:

#clsh cat /shared/ssh/root/authorized_keys


2. To regenerate the key, run below command on primary slot:


Impact: User will be logged out of the SSH session and on the next login they will be asked to accept the new host key.


#keyswap.sh sccp


Additional Information

To track when was the file last modified, run :


stat /shared/ssh/root/authorized_keys


For multi-blade systems:

clsh stat /shared/ssh/root/authorized_keys
