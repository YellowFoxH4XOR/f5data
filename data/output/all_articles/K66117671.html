Description

Would like to log the value of the Host header, or other headers, with a security logging profile, without logging the whole request.

Environment

  • Logging
  • Security log profile

Cause

None

Recommended Actions

It is not currently possible to log individual header values from a security logging profile.

If you would like F5 to add support for this feature in the future, please open a Service Request referencing this article.

An alternative option is to use high speed logging to send a custom log message, using an iRule.

Here is an example iRule:

when CLIENT_ACCEPTED {
    set hsl [HSL::open -proto UDP -pool hsl_pool]
}
when ASM_REQUEST_DONE {
    HSL::send $hsl "[clock format [clock seconds] -format {%Y-%m-%d %X}] | [HTTP::method] [HTTP::host][HTTP::path] HTTP/[HTTP::version] | Support_ID: [ASM::support_id] | [ASM::status]"
}

It opens a HSL handle to a pool, which fires the logs straight out of TMM. The pool just needs to be defined with the IP address and port of your log server.

Since it uses ASM_REQUEST_DONE you need to enable iRule events in the security policy settings in order for it to work.

This iRule produces logs like the following:

2020-11-17 13:01:33 | GET www.example.com/test/image.png HTTP/1.1 | Support_ID: 2343410284992921615 | clear

You can completely customize what is sent as necessary. For example if you want the query string as well as the HTTP path, you can use [HTTP::uri] instead. Additional ASM details can also be logged. You can also use TCP with HSL.

Note: This should be considered an example iRule only. iRules should be thoroughly tested before implementing them in a production environment.

Additional Information

If you are not interested in logging ASM details, it is typically better to use a Request Logging Profile, or use an iRule that triggers on an earlier event in the connection such as HTTP_REQUEST.
