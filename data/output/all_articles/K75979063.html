K75979063: Effect of Port Lockdown on OSPF neighborship

Type
Support Solution
Published
2022-07-27
Updated
2026-06-14
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K75979063

Description

  • On physical point-to-point networks, the IP destination is always set to the address AllSPFRouters, 224.0.0.5, for all OSPF packets.
  • On Broadcast networks, OSPF Hello messages use multicast destinations as in point-to-point networks. However DBD packet will be unicasted.
  • For more information RFC 2328 : https://www.ietf.org/rfc/rfc2328.txt
  • Installation of the Advanced Routing Module creates  listener in the TMM for mulitcast destinations of OSPF.
  • Port lockdown is a BIG-IP security feature that allows you to specify particular protocols and services from which the self IP address defined on the BIG-IP system can accept traffic.
  • The Big-IP will still be able to initiate outbound connections using those self-ip addresses to Neighbor Devices over whatever protocol/ports required.

Environment

  • BIG-IP
  • Open Shortest Path First (OSPF)

Cause

None

Recommended Actions

  1. Network type is point-to-point

    Regardless of the port lockdown setting, neighborship will be established and neighbors will be in full state.

    OSPF process 1:
Neighbor ID     Pri   State                 Dead Time       Address         Interface
2.2.2.2          1    Full/ -               00:00:34        10.20.2.2        external
  2. Network type is broadcast

    Port lockdown setting plays a role in neighborship establishment. DBD packest is sent to unicast address. If the port lockdown is set to allow none, neighbors will be stuck in exstart state.

    OSPF process 1:
Neighbor ID     Pri   State                 Dead Time       Address         Interface
2.2.2.2         1     ExStart/DR            00:00:34       10.20.2.2         external

OSPF process 1:
Neighbor ID     Pri   State                 Dead Time       Address         Interface
1.1.1.1         1     ExStart/Backup        00:00:34        10.20.1.2        external

    Changing the port lockdown setting at this state will take effect immediately and they will go to a full state.

  3. Changing the port lockdown setting to None after neighbors are in full state

    New inbound OSPF connections or any existing Neighbor devices broken due to any issue will not come up.

    Pre-existing OSPF communications can still function even after the port lockdown setting is modified to 'none' and you will not see any issues until you've performed something akin to restarting tmrouted.
