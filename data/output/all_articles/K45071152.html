K45071152: ZebOS OSPF neighbor status stuck in Exchange state

Type
Support Solution
Published
2022-09-12
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K45071152

Description

You notice the OSPF neighbor status stuck in Exchange state. BIG-IP VLAN Maximum Transmission Unit (MTU) has been configured to non default value of 1500.

zebos -a cmd show ip ospf neighbor detail

 Neighbor 192.168.1.54, interface address 172.16.1.135
    In the area 0.0.0.0 via interface myospf_vlan
    Neighbor priority is 200, State is Exchange, 4 state changes
    DR is 172.16.1.137, BDR is 172.16.1.135
--
 Neighbor 192.168.1.56, interface address 172.16.1.137
    In the area 0.0.0.0 via interface myospf_vlan
    Neighbor priority is 180, State is Exchange, 4 state changes
    DR is 172.16.1.137, BDR is 172.16.1.135

tmsh list net vlan
net vlan myospf_vlan {
    fwd-mode l3
    if-index 208
    interfaces {
        1.1 {
            tagged
        }
    }
    mtu 9198
    tag 1101
}

 

Environment

  • ZebOS OSPF
  • OSPF neighbor state

Cause

The problem occurs when MTU settings for neighboring router interfaces do not match. If the router with the higher MTU sends a packet larger that the MTU set on the neighboring router, the neighbor router ignores the packet. When this problem occurs, the output of the show ip ospf neighbor detail command displays output similar to the above.

Recommended Actions

Ensure that the OSPF peer interface use the same MTU setting to avoid OSPF stuck in exchange.
