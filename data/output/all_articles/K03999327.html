Description

  • Understanding SSLO Bypass functionality within the SSLO Security Policy

Environment

  • SSLO module deployed
  • SSLO configured

Cause

When a rule within the security policy is configured to "bypass" this does not mean it's bypassing SSLO altogether as the traffic is still processed through the appropriate outbound virtual server including any profiles associated with the virtual server such as TCP, HTTP, Client SSL, etc.

Recommended Actions

If you do not want traffic to be processed through the SSLO virtual servers that are generated when the SSLO configuration is deployed then you must create a forwarding virtual server to accept the traffic before the SSLO virtual server does.

Additional Information

When the bypass option is selected within a rule in the SSLO Security Policy and the configuration is deployed this creates a "IP Based SSL Bypass Set" within the APM visual policy editor per-request profile that is associated to the SSLO topology. The VPE can be accessed by navigating to Access > Profiles / Policies > Per-Request Policies .
