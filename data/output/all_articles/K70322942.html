Organizations rely on a Virtual Private Network (VPN) to provide their employees with continuous, secure, remote access to corporate resources. Use this article to help resolve issues that may arise with your VPN.

BIG-IP APM Network Access is a VPN solution that allows authenticated remote workers to access corporate applications and resources from any location through a secure and encrypted tunnel.

Authentication

You can secure your organization's applications and resources by ensuring that only authenticated and authorized users access them through a VPN.

You can configure the BIG-IP APM system to do the following:

  • Request that remote users authenticate
  • Proxy authentication and authorization requests to your authentication, authorization, and accounting (AAA) servers

BIG-IP APM supports the following authentication methods:

  • Active Directory—authentication and query
  • Lightweight Directory Access Protocol (LDAP)—authentication and query
  • Native RSA SecurID authentication
  • RADIUS—authentication and accounting
  • Terminal Access Controller Access-Control System Plus (TACACS+)—authentication and accounting
  • Kerberos authentication with end user logons
  • HTTP and HTTPS authentication
  • Online Certificate Status Protocol (OCSP) authentication
  • Certificate Revocation List Distribution Point (CRLDP) authentication
  • On-demand certificate authentication
  • One-Time Password (OTP) authentication
  • Step-Up authentication 

As an alternative to proxy authentication, you can create multiple BIG-APM local user databases and provide on-box authentication.

For more information and to configure authentication for your VPN, refer to the BIG-IP Access Policy Manager: Authentication Methods manual.

Multi-factor authentication

The BIG-IP APM system offers multiple multi-factor authentication (MFA) options, including:

  • Native RSA SecurID.
  • Combining multiple authentication mechanisms for a single access policy.
  • Okta with OAuth 2.0.

For more information, refer to K42422282: Configuring Multi-factor Authentication.

Single sign-on

The BIG-IP APM system provides a single sign-on (SSO) feature that leverages credential caching and credential proxying technology. SSO methods that the BIG-IP APM system supports include the following:

  • HTTP Basic
  • HTTP Form-based
  • NT LAN Manager (NTLM) v1 and v2
  • Kerberos
  • Open Authorization (OAuth)
  • Security Assertion Markup Language (SAML)

For more information, refer to the BIG-IP Access Policy Manager: Single Sign-On Concepts and Configuration manual.

Endpoint security

Endpoint security is a strategy for ensuring that a client device does not present a security risk before it is granted a remote access connection to the network.

The BIG-IP APM endpoint security client-side verification actions include the following:

  • Anti-spyware
  • Antivirus
  • Firewall
  • Hard Disk Encryption
  • Linux File
  • Linux Process
  • Mac File
  • Mac Process
  • Machine Cert Auth
  • Machine info
  • Patch Management
  • Public File Sharing
  • System Health Agent
  • Windows Cache and Session Control
  • Windows File
  • Windows Info
  • Windows Process
  • Windows Protected Workspace
  • Windows Registry

For more information about how the BIG-IP APM system performs endpoint security, refer to K15302653: BIG-IP Edge Client operations guide | Chapter 6: Endpoint inspection.

Tunnel encryption

Before data can be exchanged, BIG-IP Network Access establishes a Point-to-Point Protocol (PPP) tunnel over Transport Layer Security (TLS) or Datagram Transport Layer Security (DTLS) to ensure confidentiality. When a user enters the address of the BIG-IP APM system in a web browser or the BIG-IP Edge Client, the client device starts an SSL connection to the BIG-IP APM system.

You can specify multiple certificate/key pairs on the BIG-IP system, one per key type. Doing so enables the system to accept all the types of cipher suites that a client may support as part of creating a secure connection.

For information about configuring a strong TLS cipher, refer to K01770517: Configuring the cipher strength for SSL profiles (14.x - 15.x).

Access control list

You can configure layer 4 (L4), L7, or L4+L7 access control lists (ACLs) to restrict some users to accessing only specific network resources and applications. For example, you can filter connections by the following L4 and L7 properties:

  • L4
    • Source and destination IP address and port
    • Protocol—TCP or User Datagram Protocol (UDP)
  • L7
    • Scheme
    • Host name
    • Paths

You can configure ACLs on a per-session basis to provide individually tailored access for each user.

For more information, refer to the Configuring Access Control Lists chapter of the BIG-IP Access Policy Manager: Network Access manual.
