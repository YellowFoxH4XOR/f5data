Description

Bigip remains in an offline state after rebooting it. Mysql is unable to start causing this condition. mysqld.err contain entries such as the ones below:

250108 10:07:10 mysqld_safe Starting mysqld daemon with databases from /var/lib/mysql
250108 10:07:10 [Note] /usr/sbin/mysqld (mysqld 5.5.53-MariaDB) starting as process 14416 ...
250108 10:07:10 InnoDB: The InnoDB memory heap is disabled
250108 10:07:10 InnoDB: Mutexes and rw_locks use GCC atomic builtins
250108 10:07:10 InnoDB: Compressed tables use zlib 1.2.7
250108 10:07:10 InnoDB: Using Linux native AIO
250108 10:07:10 [ERROR] mysqld: Can't create/write to file '/var/tmp/ibqjEHwU' (Errcode: 13)
250108 10:07:10 InnoDB: Error: unable to create temporary file; errno: 13
250108 10:07:10 [ERROR] Plugin 'InnoDB' init function returned error.
250108 10:07:10 [ERROR] Plugin 'InnoDB' registration as a STORAGE ENGINE failed.
250108 10:07:10 [ERROR] Unknown/unsupported storage engine: InnoDB
250108 10:07:10 [ERROR] Aborting

Environment

  • ASM
  • mysqld
  • /var/tmp

Cause

This behavior can be caused due to a change in the permissions of symlink /var/tmp, which prevents mysqld from using the folder.

Changed permissions:

drwx------. 37 system_u:object_r:tmp_t:s0 root root 24576 Jan 21 07:58 /shared/tmp

Default permissions:

drwxrwxrwt. 18 system_u:object_r:tmp_t:s0 root root 4096 Jan 22 16:07 /shared/tmp

Recommended Actions

To correct the above discrepancy you can either try changing the permissions or recreating the symlink after first removing it.

# chmod 577 /var/tmp

or

# rm /var/tmp
# ln -s /shared/tmp /var/tmp
