Description

When downgrading from v17 using K25205233, big3d may constantly restart uncontrollably.

 

Environment

LTM-DNS v17 with FIPS

Cause

big3d mismatch:

[root@GTM1.example.com:Standby:In Sync] config # find / -name "big3d" | xargs md5sum

c913c8e05b595e2dcce3ba823fc3793a /shared/bin/big3d

980d6c2914f4856ca3ac700f94ec694b /usr/sbin/big3d

(Note: Both binaries above SHOULD match)

 

As a result, big3d keeps trying to restart, and you can see there is an error:

[root@GTM1.example.com:Standby:In Sync] config # /shared/bin/big3d -v

fips.c:204:f5_get_library_path: failed to dlopen libcrypto.so.1.0.2za

/shared/bin/big3d version big3d Version 17.0.0.2.0.0.2 for linux

 

Recommended Actions

  1. Backup the incorrect big3d version:
    mv /shared/bin/big3d /shared/tmp/big3d_v17
  2. Overwrite big3d binaries:
    cp /usr/sbin/big3d /shared/bin/
  3. Restart big3d:
    bigstart restart big3d

Additional Information

This workaround is especially useful when booting onto a previous version from v17 using FIPS. There may be other scenarios this workaround can be used as well.
