Topic

This article applies to BIG-IP 11.x and later. For information about other versions, refer to the following article:

  • K11440: Adding and removing encryption from private SSL keys (9.x - 10.x)

Purpose

You should consider using these procedures under the following conditions:

  • You want to add a passphrase to encrypt a private SSL key.
  • You want to change an existing passphrase for an encrypted private SSL key.
  • You want to remove a passphrase from an encrypted private SSL key.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrator access to the BIG-IP command line.

Description

You can use the openssl utility to add, remove, or change SSL private key passphrases. When you specify a passphrase to encrypt private SSL keys, you must also provide the passphrase to the SSL profile to which the key is assigned. The Secure Vault feature automatically protects the passphrase by encrypting it with a master key so it does not appear as plain text within the SSL profile in the configuration. For more information about the Secure Vault feature, refer to K73034260: Overview of the BIG-IP system Secure Vault feature.

Encrypted passphrase strings in the BIG-IP configuration appear similar to the following example:

$M$Uz$7agz766cNqpbGKxxWxvjvA==

For increased security, the system also protects the master key. When stored on the system, the system always encrypts the master key with a hardware key, and never in the form of plain text.

You cannot load a configuration that contains master key-encrypted passphrases to a device with a different master key. To ensure the master key is the same within a device group, the BIG-IP system can securely exchange the encrypted master key between the units of a device group during the configuration synchronization process, with no intervention by the BIG-IP system administrator.

If you want to move a configuration to a device with a different master key, or you are unable to restore a configuration that contains encrypted passphrases, edit the /config/bigip.conf file by replacing each encrypted passphrase string with its plain text equivalent, and then reload the configuration. The system then re-encrypts the passphrases with the new device's master key. For more information, refer to K9420: Installing UCS files containing encrypted passwords or passphrases.

Procedures

  • Adding a passphrase to encrypt a private SSL key
  • Changing an existing passphrase for an encrypted private SSL key
  • Removing a passphrase from an encrypted private SSL key

Adding a passphrase to encrypt a private SSL key

You can specify a passphrase to encrypt the private SSL keys. To do so, perform the following procedure:

Impact of procedure: If you add a passphrase to a key that a virtual server is currently using, SSL connections to the virtual server may fail until the system updates the related SSL profile configuration with the newly-added passphrase and loads the changes into memory. To avoid service disruption, perform this procedure during a scheduled outage.

  1. Log in to the command line.
  2. Change directories to the /config/filestore/files_d/Common_d/certificate_key_d/ directory.

    For example, use syntax similar to the following command:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  3. To check if the SSL key is already encrypted with a passphrase, enter the following command syntax:

    openssl rsa -text -noout -in <name of key>.key

    Note: Use character escaping for colons in private SSL key file names.

    For example, to check if an SSL key named testkey1 that resides in the Common partition is not encrypted with a passphrase, enter the following command:

    # openssl rsa -text -noout -in \:Common\:testkey1.key
    Private-Key: (2048 bit)
    modulus:
    00:b0:fd:c2:81:60:3f:d2:dc:fe:2d:34:c6:46:1e:
    08:72:c3:78:f3:4d:12:16:b9:39:3e:0b:d3:8b:e7:
    ...

    If the SSL key named testkey1 that resides in the Common partition was already encrypted with a passphrase, output appears similar to the following example:

    # openssl rsa -text -noout -in \:Common\:testkey1.key
    Enter pass phrase for :Common:testkey2.key:
    ...

  4. To add a passphrase and encrypt the SSL key, enter the following command syntax:

    openssl rsa -aes256 -in <name of key>.key -out <encrypted name>.key

    Note: To prevent service interruption, F5 recommends that you specify a different name or use a distinguishing number to encrypt a private SSL key. If you use the same name for the encrypted name, the system overwrites the private SSL key file with the encrypted key, which may interrupt traffic until the system updates the SSL profile with the passphrase that allows it to read the private SSL key.

    For example, to add a passphrase and encrypt the SSL key named testkey1.key and then specify the new name testkey2.key, enter the following command:

    # openssl rsa -aes256 -in \:Common\:testkey1.key -out testkey2.key
    writing RSA key
    Enter PEM pass phrase:
    Verifying - Enter PEM pass phrase:

    Important: Store the passphrase in a secure place. If you lose or forget the passphrase, you cannot retrieve the passphrase and you must create a new private SSL key.

  5. Install the newly encrypted SSL private key in the BIG-IP filestore by entering the following command syntax:

    tmsh install /sys crypto key <key_name> from-local-file <key_path_and_name>

    For example, to import the SSL key named testkey2.key, you enter the following command:

    tmsh install /sys crypto key testkey2.key from-local-file /config/filestore/files_d/Common_d/certificate_key_d/testkey2.key

    Note: Starting from BIG-IP 21.0.0, you must include the passphrase while importing the key by using the command syntax tmsh install /sys crypto key <key_name> from-local-file <key_path_and_name> passphrase <encrypted key passphrase>. If you did not include the passphrase, the BIG-IP system fails to import the key and return an error similar to the following example:

    01b5004d:3: FIPS 140-3 mode supported key sizes (in bits) : 2048 and 4096.

  6. Save your changes by entering the following command:

    tmsh save sys config

  7. Update the corresponding SSL profiles with the correct passphrase and key file name, if changed.
  8. After you verify that the SSL profile is successfully processing traffic with the new key that you created, if you made two copies of the key, you can remove the old copy that has no passphrase.

Changing an existing passphrase for an encrypted private SSL key

You can change the passphrase to encrypt a private SSL key, if needed. To do so, perform the following procedure:

Impact of procedure: If you change a passphrase to a key that a virtual server is currently using, SSL connections to the virtual server may fail until the system updates the related SSL profile configuration with the newly-added passphrase and loads the changes into memory. To avoid service disruption, perform this procedure during a scheduled outage.

  1. Log in to the command line.
  2. Change directories to the /config/filestore/files_d/Common_d/certificate_key_d/ directory.

    For example, enter syntax similar to the following command:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  3. To change a passphrase for an encrypted SSL key, use the following command syntax:

    openssl rsa -aes256 -in <encrypted name>.key -out <changed encrypted name>.key

    Note: To prevent service interruption, F5 recommends that you specify a different name or use a distinguishing number to encrypt a private SSL key. If you use the same name for the encrypted name, the system overwrites the private SSL key file with the encrypted key, which may interrupt traffic until the system updates the SSL profile with the passphrase that allows it to read the private SSL key.

    For example, to change a passphrase and encrypt the SSL key named testkey3.key, and then specify the new name testkey4.key, enter the following command:

    Note: Use character escaping for colons in private SSL key file names.

    # openssl rsa -aes256 -in \:Common\:testkey3.key -out testkey4.key
    Enter pass phrase for :Common:testkey3.key:
    writing RSA key
    Enter PEM pass phrase:
    Verifying - Enter PEM pass phrase:

    Important: Store the passphrase in a secure place. If you lose or forget the passphrase, you cannot retrieve the passphrase and you must create a new private SSL key.

  4. Install the newly encrypted SSL private key in the BIG-IP filestore by using the following command syntax:

    tmsh install /sys crypto key <key_name> from-local-file <key_path_and_name>

    For example, to import the SSL key named testkey4.key, enter the following command:

    tmsh install /sys crypto key testkey4.key from-local-file /config/filestore/files_d/Common_d/certificate_key_d/testkey4.key

    Note: Starting from BIG-IP 21.0.0, you must include the passphrase while importing the key by using the command syntax tmsh install /sys crypto key <key_name> from-local-file <key_path_and_name> passphrase <encrypted key passphrase>. If you did not include the passphrase, the BIG-IP system fails to import the key and return an error similar to the following example:

    01b5004d:3: FIPS 140-3 mode supported key sizes (in bits) : 2048 and 4096.

  5. Save your changes by entering the following command:

    tmsh save sys config

  6. Update the corresponding SSL profiles with the correct passphrase and key file name, if changed.

Removing a passphrase from an encrypted private SSL key

If you do not want to encrypt your private SSL key, perform the following procedure:

Impact of procedure: If you remove a passphrase from a key that a virtual server is currently using, SSL connections to the virtual server may fail until the system updates the related SSL profile configuration without the passphrase and loads the changes into memory. To avoid service disruption, perform this procedure during a scheduled outage.

  1. Log in to the command line.
  2. Change directories to the /config/filestore/files_d/Common_d/certificate_key_d/ directory.

    For example, use syntax similar to the following command:

    cd /config/filestore/files_d/Common_d/certificate_key_d/

  3. Locate the private SSL key that you want to remove a passphrase from, and then use the following command syntax:

    openssl rsa -in <encrypted name>.key -out <unencrypted name>.key

    For example, use syntax similar to the following command:

    # openssl rsa -in \:Common\:encryptedkey.key -out unencryptedkey.key
    Enter pass phrase for :Common:encryptedkey.key:
    writing RSA key

    Notes:

    • Use character escaping for colons in private SSL key file names.
    • If you do not know the passphrase to the private SSL key, you cannot retrieve it and you must create a new private SSL key.
  4. Install the unencrypted SSL private key into the BIG-IP filestore by using the following command syntax:

    tmsh install /sys crypto key <key_name> from-local-file <key_path_and_name>

    For example, to import the SSL key named unencrypted.key, enter the following command:

    tmsh install /sys crypto key unencrypted.key from-local-file /config/filestore/files_d/Common_d/certificate_key_d/unencrypted.key

  5. Save your changes by entering the following command:

    tmsh save sys config

  6. Update the corresponding SSL profiles and remove the passphrase for the SSL keys that are no longer encrypted.
