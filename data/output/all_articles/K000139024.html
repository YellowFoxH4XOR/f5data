Issue:

You should consider using this procedure under the following condition:

  • You want to troubleshoot a link aggregation group (LAG) with Link Aggregation Control Protocol (LACP) enabled on the F5 rSeries or F5 VELOS system.

Symptoms

As a result, you may encounter the following symptoms:

  • The LACP State in NETWORK SETTINGS > LACP Details in the webUI shows LACP_DOWN.
  • You see LACP errors or no LACP statistics for the LAG in NETWORK SETTINGS > LACP Details in the webUI.
  • You are unable to pass traffic on the LAG.

Recommended Actions:

You can create LAGs on F5 rSeries and F5 VELOS systems to group several interfaces together to form a single logical interface. This allows you to increase bandwidth and provide link redundancy in case a link becomes unavailable. For example, you can aggregate four 100 Gb links together to provide a single 400 Gb link. 

When configuring LAGs, you specify the LAG type as either STATIC or LACP. With static LAGs (default), links are manually configured and are not dynamically updated. With LACP enabled, links are automatically bundled and traffic is automatically redistributed to other member links when a link fails.

You can configure the following LACP options on a LAG:

OptionDescription
LACP IntervalInterval at which interfaces send LACP packets. Select FAST (transmit packets every second) or SLOW (transmit packets every 30 seconds).
LACP ModeNegotiation state for LACP. Select ACTIVE (in an active negotiating state) or PASSIVE (do not initiate negotiation until peer contacts first).

When working with LAGs on F5 rSeries and VELOS systems, consider the following:

  • LAG members must be configured with the same type and speed.
  • LAG members can span across chassis blades that are members of the same chassis partition on F5 VELOS systems.
  • The maximum number of members in a single LAG is 32 for F5 rSeries systems. For F5 VELOS systems, the maximum number of members in a LAG is 32 for a chassis partition.
  • The maximum number of LAGs is 256 for F5 rSeries systems and 256 for F5 VELOS chassis partitions.
  • On F5 rSeries, MAC addresses for LAGs, LACP, and tenants are assigned from a pool of MAC addresses offset from the base MAC address for the system. The offset depends on the platform and number of front panel interfaces. For more information about MAC address assignment on F5 rSeries systems, refer to K000133655: MAC address assignement in VELOS and rSeries.
  • On F5 VELOS systems, MAC addresses are assigned to chassis partitions from a chassis-wide global pool of addresses during chassis partition creation. MAC addresses for LAGs, LACP, and tenants are allocated from the group of MAC addresses assigned to the chassis partition. For more information about MAC address assignment on F5 VELOS systems, refer to K000133655: MAC address assignement in VELOS and rSeries.

Procedures

When experiencing issues with LAGs on F5 rSeries and VELOS systems, you can use the following procedures to troubleshoot the issue:

  • Verify the tranceiver and the cable are supported and compatible
  • Verify the interfaces are UP
  • Check the state of the LAG and LACP 
  • Check LACPDUs using tcpdump
  • Review the lacpd logs
  • Verify LAG and LACP configuration on peer switch

Verify the tranceiver and the cable are supported and compatible

We support F5 transceivers, and do not support 3rd party transceivers. Each transceivers has specific compatibility with the cables. Please check in:

K6097: Specifications of the Fiber Gigabit Ethernet SFP, XFP, SFP+, QSFP+, and QSFP28 module ports on BIG-IP system platforms 

Verify the interfaces are UP

Verify the operational state of the member interfaces in the LAG to ensure they are enabled and UP. At least one member link needs to be UP for the LAG to pass traffic. To check the interface status on a F5 rSeries or F5 VELOS system, perform the Check the status of the interface procedure in K000138830: Troubleshooting port groups and interfaces on F5 rSeries and F5 VELOS systems.

Check the state of the LAG and LACP

Verify the state of the LAG on the F5 rSeries or VELOS system to ensure the settings are correct for your environment. If LACP is enabled for the LAG, the peer system must also have LACP configured and at least one of the peers needs to be in Active mode in order to initiate synchronization. To check the current state of a LAG and LACP on the F5 rSeries or VELOS system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

webUI

  1. Log in to the F5 rSeries or F5 VELOS chassis partition webUI.
  2. Go to NETWORK SETTINGS > LAGs.
  3. Select the name of the LAG to view or modify its configuration. If you are using LACP, verify that LACP is enabled and the LACP Mode is correct, either ACTIVE or PASSIVE. You can also verify the LAG members and VLANs are configured correctly. 
  4. If the LAG configuration is correct, go to NETWORK SETTINGS > LACP Details and check the status of LACP. Synchronization should be IN_SYNC and the LACP Pkts In and LACP Pkts Out counters should be incrementing as LACP PDUs are sent and received. Take note of any LACP errors. If Synchronization is OUT_SYNC for any of the member interfaces, verify the interface is enabled and UP using the previous procedure. 

CLI

  1. Log in to the F5 rSeries system or F5 VELOS chassis partition CLI as admin.
  2. Show the LAG state using the following command where <LAG_name> is the name of the LAG:

    show interfaces interface <LAG_name>

Check LACPDUs using tcpdump

If the LACP peers fail to negotiate successfully you can run the system diagnostics tcpdump command on the F5 rSeries system or VELOS chassis partition to capture the LACP Protocol Data Units (LACPDUs) sent between the LACP peers. You can specify the name of the LAG as the interface to capture. Note that it's not possible to capture traffic traversing only specific interface of the LACP trunk. Capturing on a specific interface that is part of the LACP trunk will capture traffic for all the trunk interfaces.

When running tcpdump command while specifying interface of the trunk, the system will issue a warning message as following (starting from F5OS-A 1.8.0):

errbuf WARNING:tcpdumpd interface: <interface number> is a member of LAG interface: <trunk_name>.
Tcpdump cannot capture traffic on an individual LAG member; all traffic on the LAG will be captured

 

To capture LACP traffic on F5 rSeries systems or VELOS chassis partitions, perform the following procedure:

Impact of procedure: Running tcpdump on a LAG can generate large capture files due to the amount of traffic traversing the LAG. Use appropriate filters to limit the size of the capture.

  1. Log in to the F5 rSeries system or F5 VELOS system partition CLI as admin.
  2. To capture LACPDU frames using tcpdump, use the following syntax:

    system diagnostics tcpdump -eni <interface> "ether proto 0x8809" -w <filename>

    In the previous command, note the following:

    • <interface> is the name of the LAG or the LAG member interface on which you want to capture. For example, to capture on interface 1.0 on VELOS chassis blade 1 (slot 1), enter 1/1.0. Keep in mind that capturing on one of the trunk interfaces captures the traffic for all the trunk.
    • <filename> is the name of the file to save the captured traffic.

    For example, to capture LACP traffic on trunk named "lag34" on an rSeries system and save the output to the file lag34_trunk.pcap, enter the following command:

    system diagnostics tcpdump -eni lag34 "ether proto 0x8809" -w lag34_trunk.pcap

    After you have captured the desired traffic, enter Ctl-c to stop the capture. The output file will be located in the /var/F5/system/shared/tcpdump/ directory on F5 rSeries systems or in the /var/F5/partition<#>/shared/tcpdump/ directory on F5 VELOS system controllers.

  3. For F5 rSeries r2000/4000 system only, interface mapping is as the following:
    • Interfaces 1.0 - 4.0 are mapped to x557_1 - x557_4 respectively.
    • Interfaces 5.0 - 8.0 are mapped to sfp_5 - sfp_8 respectively.

To run tcpdump,
1. Log in to F5OS host CLI as root
2. Run the command below specifying x as appropriate number:

tcpdump -nvi sfp_x "ether proto 0x8809" -w /var/F5/system/shared/tcpdump/<filename>
  1. For F5 VELOS systems only, you need to determine the partition ID number for the chassis partition where the tcpdump command was run in order to copy the capture file from the F5 system using the scp utility in the following steps. To do so, log in to the VELOS system controller webUI and go to CHASSIS PARTITIONS. Locate the Partition ID for the chassis partition in which you ran the tcpdump utility.

    Note: To locate the partition ID using the CLI, log in to the VELOS system controller CLI as admin and enter the show partitions partition state id command.

  2. Log in to a workstation that has the scp utility installed in order to download the tcpdump capture file.
  3. Use the following command syntax to download the tcpdump capture file, depending on your F5 system. Enter the password for the F5 system when prompted:

    rSeries

    scp root@<hostname>:/var/F5/system/shared/tcpdump/<filename> ./

    VELOS

    scp  root@<hostname>:/var/F5/partition<#>/shared/tcpdump/<filename> ./

    In the previous commands, note the following:

    • <hostname> is the host name or IP address of the F5 rSeries system or F5 VELOS system controller.
    • <filename> is the name of the tcpdump capture file.
    • <#> is the VELOS chassis partition ID number as determined by the step above. For example, 1, 2, 3, etc.

    For example, if the traffic capture was taken on a VELOS chassis partition with partition ID = 2, and the VELOS system controller floating IP is 10.10.10.100, to download the lag34_member3.pcap file enter the following command:

    scp root@10.10.10.100:/var/F5/partition2/shared/tcpdump/lag34_member3.pcap ./

Review the lacpd logs

You can review the lacpd logs on the F5 rSeries or VELOS system to look for error messages that may point to a problem. The lacpd component logs to the /var/F5/system/log/platform.log file on F5 rSeries systems, and the /var/F5/partition<#>/log/velos.log file on F5 VELOS systems. For example, messages similar to the following are logged on the F5 rSeries system when a working member is removed from aggregation:

appliance-1 lacpd[1]: priority="Notice" version=1.0 msgid=0x3401000000000061 msg="Removing working member." interface="4.0" trunk="LAG34".
appliance-1 lacpd[1]: priority="Info" version=1.0 msgid=0x3401000000000062 msg="Adding message to send queue." type="lacp_state_op::OP_UPDATE" trunk="" interface="4.0".
appliance-1 lacpd[1]: priority="Info" version=1.0 msgid=0x3401000000000038 msg="Link removed from aggregation." key="4.0".
appliance-1 lacpd[1]: priority="Info" version=1.0 msgid=0x3401000000000088 msg="Mux_disable_colldist" port_state="Intf=4.0 partnerDefaulted:0 rxState:4 selected:0 txState:0 actorChurn:0 partnerChurn:0 muxState:3 periodicTxState:1 actorState:00001101 partnerState:00111111".

You can view more detailed logging for LACP by setting the lacpd log setting to DEBUG. Once troubleshooting is complete, be sure to set the lacpd log setting back to the default of INFORMATIONAL.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

webUI

  1. Log in to the F5 rSeries system or VELOS chassis partition webUI.
  2. Go to SYSTEM SETTINGS > Log Settings.
  3. In the Software Component Log Levels section, locate the lacpd log setting. You may need to select Show on the right to display the components.
  4. Select DEBUG for the lacpd component.
  5. Select Save, then OK to accept the changes.
  6. To set the log level back to the default setting, repeat steps 1 - 5 selecting INFORMATIONAL in step 4.

CLI

  1. Log in to the F5 VELOS chassis partition CLI or F5 rSeries system CLI as admin.
  2. Enter the following command to enter configuration mode.

    config

  3. To change the lacpd log level to DEBUG, enter the following command:

    system logging sw-components sw-component lacpd config severity DEBUG

  4. Enter the following command to commit the change and exit config mode:

    commit and-quit

  5. To set the log level back to the default setting, repeat steps 1 - 4 entering the following command in step 3:

    system logging sw-components sw-component lacpd config severity INFORMATIONAL

Verify LAG and LACP configuration on peer switch

When troubleshooting LAGs and LACP between F5 rSeries or VELOS systems and peer devices, you may need to retrieve the configuration from the peer device in order to verify the settings. The procedure will depend on the peer device so you should consult the switch manufacturer's documentation for details. For more information about configuring LAGs with LACP between F5 rSeries or VELOS systems and Cisco Nexus switches, refer to K33431212: Configure LAGs with LACP between the VELOS system and Cisco Nexus 9000 series switches.
