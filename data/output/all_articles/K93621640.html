K93621640: Extend Virtual Edition filesystem size using an additional HDD

Description

  • You have a BIG-IP Virtual Edition.
  • You are unable to extend the filesystem directly due to requirements of having a fully active snapshot at all times
  • You do not have the option to spin up a new VE in parallel

Environment

Relevant environmental factors specific to the topic

  • Virtual Edition BIG-IP
  • VMWare hypervisor
  • low disk space conditions

Cause

VMWare does not allow you to extend a virtual disk when you have snapshots. If you are unable to delete or remove the snapshots for some reason, you will not be able to directly extend the filesystem using the steps in K14952: Extending disk space on BIG-IP VE.

Recommended Actions

To workaround that limitation, you can instead add a secondary disk to the virtual machine, and use the space from this additional HDD to increase the volume group size.

Important Note: Your BIG-IP VE during the disk provisioning steps will not be available for traffic processing. You should perform this procedure during a suitable maintenance window. 

1. Perform necessary backups of your devices.
2. Shutdown the Virtual Machine
3. Add an HDD with the appropriate disk size (total resulting disk space should not exceed 1.9Tb)
4. Power on the Virtual Machiine
5. Confirm from the GUI (System->Disk Management) that you are able to see the newly added HDD
6. Log on the CLI using the 'root' account
7. Confirm the logical blocks:

# lsblk

Note: The existing disk would look like sda1, sda2 (partitions in HD1), etc, but now you should also see sdb which is HD2

8. Create a 'physical' volume using the new disk space.

# pvcreate /dev/sdb

9. Verify the current volume group size.

# vgs

config # vgs
  VG        #PV #LV #SN Attr   VSize   VFree
  vg-db-vda   1   9   0 wz--n- 125.78g 28.91g


10. Extend this by adding the new physical volume into it.

# vgextend vg-db-vda /dev/sdb

11. Confirm new VSize and VFree of the volume group. In this example, I added a 40Gb HDD, hence the vgs increased by 40Gb. PV is also now showing as 2.

config # vgs
  VG        #PV #LV #SN Attr   VSize   VFree
  vg-db-vda   2   9   0 wz--n- 165.78g 47.15g

 

config # vgdisplay
