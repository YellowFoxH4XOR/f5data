Description

When using BIG-IP DNS with a recursive cache configuration, new DNS records created on the remote NS servers may not resolve immediately. Queries for these newly created records get the NXDOMAIN response. Checking the packet capture, it's the BIG-IP returns the NXDOMAIN response to client directly, rather than sends the query to the remote NS servers as configured in cache profiles. After about one hour later, this new created record can be resolved.

Environment

  • BIG-IP DNS
  • Cache resolver profile
  • Negative caching

Cause

This behavior occurs due to negative caching. If you query for a non-existent domain and the remote server responds with NXDOMAIN (along with SOA record), the BIG-IP will cache the response (in 'msg', not 'rrset') and will serve the NXDOMAIN for the same domain for the entire period of negative caching - which is defined in the SOA record, Negative TTL field.

Recommended Actions

To address this issue, consider one of the following solutions or workarounds:

  1. Avoid Querying Non-Existent Domains Before Creation: Ensure that domains are created on the remote NS server before querying them through BIG-IP listeners to prevent NXDOMAIN responses from being cached.
  2. Reduce Negative Caching TTL: Adjust the SOA record's minimum field value on your authoritative DNS server to reduce the duration of negative caching (e.g., change it from 86400/3600 seconds to a lower value).
  3. Manually Clear Cached Records: Use the following command to clear specific cached entries when necessary

tmsh delete ltm dns cache records msg rcode nxdomain cache <cache_profile_name>

 

Additional Information

If you queried a new domain on the BIG-IP listener before it was set up on the remote NS server, the BIG-IP would forward this initial query to the remote server. The remote server would then respond with an NXDOMAIN code and the SOA record for that zone. Due to the negative caching setting, the BIG-IP would cache this NXDOMAIN and SOA record. Consequently, for subsequent queries of the same domain, the BIG-IP would immediately return the NXDOMAIN code, even if the domain had since been created on the remote server. Only after the negative caching duration expired or if you manually cleared the cached record, would the BIG-IP send the query to the remote NS server as initially configured.
