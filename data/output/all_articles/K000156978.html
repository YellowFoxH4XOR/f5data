K000156978: No data listed on the dashboard of "Session Summary"

Type
Support Solution
Published
2025-10-10
Updated
2025-10-13
Applies to
  • BIG-IQ
  • BIG-IP
  • BIG-IQ Centralized Management
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000156978

Description

Session Summary and Access Summary dashboards in BIG-IQ Centralized Management may display no data for certain BIG-IP APM devices, even when active sessions exist. This occurs when APM devices and their virtual servers are configured in a non-Common partition, but remote logging configuration objects (such as pool, remote-high-speed-log, and publisher) exist only in the Common partition. As a result, session and access summary data are not sent to BIG-IQ, resulting in empty dashboards.

Environment

  • BIG-IQ Centralized Management 8.4.0 (and other 8.x versions)
  • BIG-IP APM devices with APM, AVR, and ILX provisioned
  • APM virtual servers and related objects in a non-Common partition
  • Remote logging configuration objects created only in the Common partition
  • Data Collection Devices (DCD) configured for Access reporting

Cause

A partition mismatch between APM virtual servers and remote logging objects prevents access session logs from being sent to the DCD. BIG-IQ only pushes logging objects to the Common partition and does not automatically create or push them to other partitions.

Recommended Actions

  • Manually create the required remote logging configuration objects (pool, remote-high-speed-log, publisher, and log settings) in the same partition as the APM device and its virtual server.
  • Ensure log publisher and associated objects reference the correct pool and destination within the same partition.
  • After manual configuration, verify that session and access summary data appear on the BIG-IQ dashboards.
  • Troubleshooting steps:
    • Check the partition of the APM virtual server and related objects.
    • Confirm the presence and partition of remote logging objects using tmsh or the BIG-IP GUI.
    • If only monitor traffic is seen on the DCD but no access logs, this may indicate a partition mismatch.
    • Use tcpdump on the APM to verify if access logs are being sent to the DCD on port 9997.
  • Note: Manual configuration is required for APM devices in partitions other than Common.
