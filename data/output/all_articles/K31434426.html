Topic

You should consider using this procedure under the following condition:

  • You want to configure a custom cipher list for gtmd daemon (a client for iQuery connections).
  • You want to change the Transport Layer Security (TLS) minimum version requirement for iQuery connections for gtmd.
  • To configure iQuery cipher settings for the server (big3d) you need to follow K05713133.
  • Client (gtmd) and server (big3d) must share common TLS cipher suite and TLS version to be able to establish TLS session.

Description

The BIG-IP DNS system uses the iQuery protocol to securely communicate with other BIG-IP systems. Beginning in BIG-IP DNS 14.1.0, you can harden the iQuery protocol or make the iQuery connection more permissive by customising the default cipher list or changing the TLS version minimum requirement using the Configuration utility.

Note: For more information and default values of iQuery cipher and TLS version settings, refer to K14938: Overview of BIG-IP GTM global variables (11.5.0 and later).

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP DNS system.

Procedures

  • Configuring the SSL cipher list for iQuery global settings
  • Configuring the TLS minimum version for iQuery global settings
  • Configuring the SSL cipher list for iQuery server specific settings
  • Configuring the TLS minimum version for iQuery server specific settings
  • Verifying iQuery ciphers and TLS settings

Configuring the SSL cipher list for iQuery global settings

You can configure the BIG-IP DNS system to enforce a custom cipher list for iQuery connections. To do so, perform the following procedure:

Impact of procedure: Changing the cipher list may cause iQuery connections to fail if the remote BIG-IP system is not compatible with the modified cipher strength. Before applying the change, F5 recommends that you test the connection using the Verifying iQuery ciphers and TLS settings in this article.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Settings > GSLB > General.
  3. Under iQuery Ciphers section, for SSL Cipher List, type the custom cipher string.

    For example, the following cipher string allows the default ciphers except AES256-SHA by removing it from the default cipher list:

    AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1

  4. Click Update.

To configure cipher list for gtmd using 'tmsh' run:

tmsh modify gtm global-settings general iquery-cipher-list <CIPHERLIST> 

for example:

tmsh modify gtm global-settings general iquery-cipher-list AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1'

 

Configuring the TLS minimum version for iQuery global settings

You can modify the TLS minimum version requirement for iQuery connections. To do so, perform the following procedure:

Impact of procedure: Changing the TLS minimum version may cause iQuery connections to fail if the remote BIG-IP system is not compatible with the modified TLS version. Before applying the change, F5 recommends that you test the connection using the Verifying iQuery ciphers and TLS settings in this article.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Settings > GSLB > General.
  3. For iQuery Ciphers, for TLS Minimum Version, click a TLS version.
  4. Click Update.

To configure TLS Minimum Version for gtmd using 'tmsh' run:

tmsh modify gtm global-settings general iquery-minimum-tls-version <TLS_VERSION> 

for example:

tmsh modify gtm global-settings general iquery-minimum-tls-version TLSv1.2

 

Configuring the SSL cipher list for iQuery server specific settings

You can configure the BIG-IP DNS system to enforce a custom cipher list for iQuery connections to a specific BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Changing the cipher list may cause iQuery connections to fail if the remote BIG-IP system is not compatible with the modified cipher strength. Before applying the change, F5 recommends that you test the connection using the Verifying iQuery ciphers and TLS settings in this article.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.
  3. Click the name of the BIG-IP system for which you want to customize the cipher list.
  4. Set Configuration to Advanced.
  5. For iQuery Options, for SSL Cipher List, click Server Specific.
  6. For SSL Cipher List , type the custom cipher string.

    For example, the following cipher string allows the default ciphers except AES256-SHA by removing it from the default cipher list:

    AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1

  7. Click Update.

To configure cipher list for gtmd to a specific server using tmsh run:

tmsh modify gtm server <SERVER_NAME> iquery-cipher-list <CIPHERLIST> 

for example:

tmsh modify gtm server gtm1 iquery-cipher-list AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1'

 

Configuring the TLS minimum version for iQuery server specific settings

You can modify the TLS minimum version requirement for iQuery connections to a specific BIG-IP system. To do so, perform the following procedure:

Impact of procedure: Changing the TLS minimum version may cause iQuery connections to fail if the remote BIG-IP system is not compatible with the modified TLS version. Before applying the change, F5 recommends that you test the connection using the Verifying iQuery ciphers and TLS settings in this article.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.
  3. Click the name of the BIG-IP system for which you want to change the TLS version requirement.
  4. Set Configuration to Advanced.
  5. For iQuery Options, for TLS Minimum Version, click Server Specific.
  6. Click a TLS version.
  7. Click Update.

To configure TLS Minimum Version for gtmd to a specific server using 'tmsh' run:

tmsh modify gtm server <SERVER_NAME> iquery-minimum-tls-version <TLS_VERSION>

for example:

tmsh modify gtm server gtm1 iquery-minimum-tls-version TLSv1.2

 

Verifying iQuery ciphers and TLS settings

You can verify if a custom cipher list and TLS version combination is compatible with a remote BIG-IP system using the iqtest command. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. To verify the iQuery connection using a custom cipher strength, use the following command syntax:

    iqtest -t <TLS_minimum_version> -cipher <cipher_string> <remote_host_IP>

    For example, to test the iQuery connection to a remote BIG-IP system with a custom cipher list and TLS1.2 as the minimum TLS version, type the following command:

    iqtest -t TLSv1.2 -cipher 'AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1:!AES256-SHA' 10.10.10.20

    Note: The cipher and TLS version commands are optional and if not specified, the system uses the defaults values.

 

 

Cleanly reconnecting existing iQuery connections

BIG-IP provides the ability to reconnect existing iQuery connections without service interruption - it does this by standing up a new iQuery connection in parallel, transferring the stream there, and then removing the previous iQuery connection.   There are two ways in which this can be triggered:

  • In the BIG-IP GUI, navigate to DNS  ››  GSLB : Servers, select a GTM server, and click on the "Reconnect" (or "Reconnect All") button.
  • From the BIG-IP commandline (tmsh), use the command "reset-stats gtm server ...".   The syntax allows for reconnection of all iQuery connections, all connections for one gtm server object, or one specific iQuery connection under one gtm server object.  For example:
    To force a global reconnect using tmsh (all connections on all devices on all servers)
     tmsh reset-stats gtm server devices
    To reset all connections on all devices on one server
     tmsh reset-stats gtm server <servername> devices
    To reset all connections on one device on one server
     tmsh reset-stats gtm server <servername> devices { <devicename> }

After triggering the iQuery reconnection, log messages similar to the following will be seen in /var/log/gtm:

 
  Jan 1 13:18:07 bigip1.local notice gtmd[15843]: 011ae057:5: Creating replacement iQuery connection to ip 10.0.0.1. 
  Jan 1 13:18:07 bigip1.local notice gtmd[15843]: 011ae01c:5: Connection complete to 10.0.0.1. Starting SSL handshake 
  Jan 1 13:18:07 bigip1.local notice gtmd[15843]: 011ae01a:5: SSL handshake complete to 10.0.0.1 
  Jan 1 13:18:08 bigip1.local notice gtmd[15843]: 011ae058:5: iQuery connection ID:1 to Remote IP:10.0.0.1 replaced with connection ID:2.
