Topic

This article discusses the behaviour for BIG-IP Edge Client on MAC clients. For Windows clients, refer to K000141526: BIG-IP Edge Client on Windows Systems uses default browser for authentication.

Description

Beginning from APM Client 7.2.5.1, you can now configure BIG-IP Edge Client to use the default browser on your MAC for authentication. Before this, BIG-IP Edge Client uses the embedded browser. This article describes what you should do to configure BIG-IP Edge Client to use the default browser on MAC clients for authentication when connecting to VPN. This includes the following use cases:

  • BIG-IP Edge Client with SAML authentication
  • BIG-IP Edge Client with captive portal

Note: Currently BIG-IP Edge Client Mac supports Default Browser authentication only for Modern Customization.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You configured a BIG-IP APM virtual server with an access policy that authenticates VPN MAC clients with authentication.
  • The access policy uses the Modern customization type.
    To verify on the Configuration utility, go to Access > Profiles / Policies, select the name of your access policy and verify the Customization Type. 
  • You update to APM Clients 7.2.5.1 or later.
  • There is no HTTP/2 profile attached to the VPN Virtual Server ("ACCESS::restrict_irule_events disable" command, used as part of the iRule delivered for this solution, is not compatible with HTTP/2 profile - RFE is tracked with ID 1013173).

Procedure

To configure BIG-IP Edge Client to use the default browser on MAC clients for authentication perform the following procedures:

  1. On the BIG-IP APM
    1. Download the Default_Browser_edgeClient_v5.zip available on F5 downloads.
    2. Extract the zip file and create an iRule on BIG-IP using the code in Default_Browser_edgeClient_V5.txt. To do so on the Configuration utility, go to Local Traffic > iRules > iRule List +. 
    3. Create an iFile for each of the *.js files contained in the extracted Default_Browser_edgeClient_v5.zip. To do so on the Configuration utility, go to Local Traffic > iRules > iFile List +.  (The name of the iFiles should be left unchanged when creating them as the iRule references those files)
    4. Associate the iRule to your BIG-IP APM virtual server.

  2. On MAC Client(s)
    Create a customized BIG-IP Edge Client installer for distribution and installation on MAC clients
    1. Download the BIG-IP Edge Client package from the connectivity profile. On the Configuration utility, go to Access > Connectivity/VPN > Connectivity > Profiles. Select the name of the profile and Customize Package and Download.
    2. Browse the downloaded BIGIPMacEdgeclient folder.
    3. Extract then edit the file config.f5c using a text editor by adding the following config directly below <PROFILE VERSION="2.0">
      <USE_DEFAULT_BROWSER_FOR_AUTH>YES</USE_DEFAULT_BROWSER_FOR_AUTH>

      The configuration looks similar to the following:

      <PROFILE VERSION="2.0">
      <USE_DEFAULT_BROWSER_FOR_AUTH>YES</USE_DEFAULT_BROWSER_FOR_AUTH>
      <ALLOW_HTTP_CONNECTIONS>NO</ALLOW_HTTP_CONNECTIONS>
    4. Install the mac_edgesvpn.pkg on the client machine.

Additional Information

You need to configure additional settings if your deployment contains the following specific use cases:

  • When your deployment contains redirection from one virtual server to another one, append %{session.server.landinguri} to the redirection URL. For example: 

    https://<VS:PORT>%{session.server.landinguri}

  • Review any Landing URI agents in your access policy, and update the expression.
    Note: The Landing URI agent is found in the visual policy editor's Endpoint Security (Server-Side) tab
    From
    expr {[mcget {session.server.landinguri}] == "/uri1" || [mcget {session.server.landinguri}] == "/uri1/"}
    To
    expr {[mcget {session.server.landinguri}] == "/uri1" || [mcget {session.server.landinguri}] starts_with "/uri1"}
