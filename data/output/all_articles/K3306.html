K3306: Configuring BIG-IP or 3-DNS to send an SNMP trap when an SSH login attempt fails

Topic

By default, BIG-IP and 3-DNS will send SNMP traps using OID .1.3.6.1.4.1.3375.1.1.110.2.38 only for failed login attempts from the console. BIG-IP will not generate traps for individual SSH login failures.

To configure BIG-IP or 3-DNS to log SSH login failures and send an SNMP trap, use one of the following two procedures:

  • Log and send a trap whenever a user provides an incorrect password.
  • Log and send a trap whenever a user fails three consecutive login attempts.

Logging and sending a trap for an incorrect password

To log and send a trap whenever a user provides an incorrect password, perform the following steps:

  1. Edit the /config/ssh/sshd_config file.
  2. Locate the following line:

    3. LogLevel ERROR

  3. Change the line to read as follows:

    4. LogLevel DEBUG

  4. Save the file and exit the editor.
  5. Edit the /etc/syslog.conf file.
  6. Locate the following line:
    7. # auth.*	/var/run/trapper
  7. Change the line to read as follows:
    8. auth.*		/var/run/trapper
  8. Save the file and exit the editor.
  9. Edit the /etc/snmptrap.conf file.

  10. At the end of the file, add the following line:

    11. .1.3.6.1.4.1.3375.1.1.110.2.251 (\."Failed password")   Single failed SSH login attempt

    Note: This step assumes that you have not already configured a custom SNMP trap ending in .251. If you have already configured an SNMP trap using that OID, use a different OID.

  11. Save the file and exit the editor.
  12. Restart sshd, by typing the following command:

    13. bigstart restart sshd

  13. Restart syslogd, by typing the following command:

    14. kill -HUP `pidof syslogd`

    An SNMP trap with the following characteristics will now be sent when a user fails a login attempt:

    OID           .1.3.6.1.4.1.3375.1.1.110.2.251
Description   Single failed SSH login attempt

Logging and sending a trap after three failed login attempts

To log and send a trap whenever a user fails three consecutive login attempts, perform the following steps:

  1. Edit the /config/ssh/sshd_config file.
  2. Locate the following line:
    3. LogLevel ERROR
  3. Change the line to read as follows:
    4. LogLevel DEBUG
  4. Save the file and exit the editor.
  5. Edit the /etc/syslog.conf file.
  6. Locate the following line:
    7. # auth.*      /var/run/trapper
  7. Change the line to read as follows:
    8. auth.*      /var/run/trapper
  8. Save the file and exit the editor.
  9. Edit the etc/snmptrap.conf file.
  10. At the end of the file, add the following line:
    11.  .1.3.6.1.4.1.3375.1.1.110.2.252 (\."attempt 3 failures 3")   Multiple failed SSH login attempts

    Note: This step assumes that you have not already configured a custom SNMP trap ending in .252. If you have already configured an SNMP trap using that OID, use a different OID.

  11. Save the file and exit the editor.
  12. Restart sshd, by typing the following command:

    13. bigstart restart sshd

  13. Restart syslogd, by typing the following command:

    14. kill -HUP `pidof syslogd`

    An SNMP trap with the following characteristics will now be sent when a user fails a login attempt:

    OID           .1.3.6.1.4.1.3375.1.1.110.2.252
Description   Multiple failed SSH login attempts
