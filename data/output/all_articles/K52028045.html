Known Issue

ConfigSync operations may fail after you apply a BIG-IP ASM security policy.

This issue occurs when the following condition is met:

  • When you use the Configuration utility to apply a BIG-IP ASM security policy, you view an error message that appears similar to the following example:

    coapi_query failed at /usr/lib/perl5/site_perl/5.8.8/i386-linux-thread-multi/F5/COAPI.pm line 106

Impact

The BIG-IP ASM system applies the security policy locally, but ConfigSync operations are impaired.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you apply the security policy, the BIG-IP ASM system logs an error message in the /var/log/asm file that appears similar to the following example:

    crit g_server_rpc_handler.pl[30418]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::log_error_and_rollback): coapi_query failed at /usr/lib/perl5/site_perl/5.8.8/i386-linux-thread-multi/F5/COAPI.pm line 106

  • After you apply the security policy, ConfigSync operations are impaired.
  • The BIG-IP ASM system applies the security policy locally, but it does not update other devices in the device group.

Workaround

You can work around this issue by applying the security policy using the representational state transfer (REST) interface.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

For example:

POST https://<MGMT_IP>/mgmt/tm/asm/tasks/apply-policy
{
"policy": {
"fullPath": "/Common/<POLICY_NAME>"
}
}
