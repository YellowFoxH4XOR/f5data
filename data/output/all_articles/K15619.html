Issue

You should consider using this procedure under the following conditions:

  • The BIG-IP system is configured to use the TACACS+ protocol for authenticating application traffic.
  • The TACACS+ authentication process fails for virtual server traffic.

Symptoms

As a result of TACACS+ authentication failures, you may encounter the following symptoms:

  • The TACACS+ authentication process fails for BIG-IP application traffic.
  • The BIG-IP system logs error messages related to TACACS+ login failures.

Recommended Actions

You can configure the BIG-IP system to use a remote TACACS+ server to authenticate application traffic passing through the BIG-IP system. To configure remote TACACS+ authentication for application traffic, you must create a TACACS+ configuration object, TACACS+ authentication profile, and virtual server object. The TACACS+ configuration object references the TACACS+ servers that you are using to store the user accounts.

The TACACS+ protocol

The TACACS+ protocol provides access control for network traffic using one or more centralized servers. TACACS+ operates over TCP and provides separate authentication, authorization, and accounting (AAA) services. By separating the AAA services, TACACS+ allows the components to be segregated and handled on separate servers. TACACS+ packets always begin with a 12-byte header. The header is clear text and contains the following fields:

  • major_version: Indicates the major TACACS+ version number.
  • minor_version: Indicates the minor TACACS+ version number.
  • type: Indicates the TACACS+ packet type. Since the AAA services may be handled by different servers, you should be aware of the legal field values:

    TAC_PLUS_AUTHEN := 0x01 (Authentication)
    TAC_PLUS_AUTHOR := 0x02 (Authorization)
    TAC_PLUS_ACCT   := 0x03 (Accounting)

  • seq_no: When reviewing TACACS+ sessions, it is helpful to know that clients (such as a BIG-IP system) should send packets containing odd-numbered TCP sequence numbers, and TACACS+ daemons should send packets containing even-numbered TCP sequence numbers.
  • flags: The flag field contains various bitmapped flags.

    TAC_PLUS_UNENCRYPTED_FLAG := 0x01: The unencrypted flag bit indicates whether the body of the TACACS+ packet is encrypted. If the flag is set, the packet is not encrypted. If the flag is cleared, the packet is encrypted.

  • session_id: The Id for the TACACS+ session. The session ID should be randomly chosen, and should not change for the duration of the TACACS+ session.
  • length: The total length of the TACACS+ packet body.

There may be times when you need to troubleshoot TACACS+ authentication, or connections to the remote TACACS+ server.

Procedures

When experiencing TACACS+ authentication issues for application traffic, you can use the following troubleshooting steps to determine the root cause:

  • Verifying the TACACS+ configuration on the BIG-IP system
    • Verifying the TACACS+ authentication configuration object
    • Verifying the TACACS+ authentication profile
    • Verifying the virtual server object
  • Verifying TACACS+ server availability
  • Reviewing TACACS+ log messages
  • Enabling debug logging for TACACS+ authentication
  • Packet tracing TACACS+ traffic

Verifying the TACACS+ configuration on the BIG-IP system

When you use the TACACS+ protocol for authenticating application traffic, you must define the TACACS+ configuration object, TACACS+ authentication profile, and virtual server object. To verify the TACACS+ configuration, perform the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Verifying the TACACS+ authentication configuration object

To verify the TACACS+ authentication configuration object, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Authentication > Configurations.
  3. Select the relevant TACACS+ configuration object.
  4. Verify that the following TACACS+ configuration object settings match the settings on the remote TACACS+ servers:
    • Secret: Verify that the secret key is the same for the TACACS+ configuration object and the TACACS+ servers. In addition, verify that the pound sign ( # ) is not used as part of the secret key string.
    • Encryption: Verify the encryption settings for the TACACS+ configuration object and TACACS+ servers. By default, the BIG-IP system is configured to encrypt the TACACS+ authentication packets.
    • Service Name: Verify that the service name setting is correct. The majority of TACACS+ implementations use the PPP service type.
    • Protocol Name: Verify that the protocol setting is correct. The majority of TACACS+ implementations use the IP protocol type.

Verifying the TACACS+ authentication profile

To verify the TACACS+ authentication profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Authentication > Profiles.
  3. Select the relevant TACACS+ authentication profile.
  4. Verify that the authentication profile references the correct TACACS+ configuration object.
  5. Verify the remaining profile setting.

Verifying the virtual server object

To verify the virtual server object, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the relevant virtual server object.
  4. For Configuration, select Advanced.
  5. Verify that the correct TACACS+ authentication profile is referenced in the Authentication Profiles section.

Verifying the TACACS+ server availability

When experiencing TACACS+ authentication issues, you should verify that the BIG-IP system can access the TACACS+ servers on the network. To verify the TACACS+ server availability, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Determine the IP addresses of the defined TACACS+ servers by using the following syntax:

    list /ltm auth tacacs <tacacs_authentication_config> servers

    For example, the following command displays the TACACS+ servers for a TACACS+ configuration profile named tacacs_config:

    list /ltm auth tacacs tacacs_config servers

    ltm auth tacacs tacacs_config {
        servers { 10.11.1.1 }
    }

  3. Use a utility, such as ping or traceroute, to verify network availability of the remote TACACS+ server.

    For example:

    ping <tacacs_server_ip>

Reviewing TACACS+ log messages

If the TACACS+ servers are available on the network, but fail to authenticate users, you may need to review the BIG-IP log files for relevant TACACS+ messages. To review the TACACS+ log messages, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Use a Linux text utility, such as less or tail, to review the /var/log/secure file.

    For example:

    tail -f /var/log/secure

  3. Review the log entries for error messages related to TACACS+ login failures.

When reviewing the log entries for TACACS+ login failures, you may view error messages similar to the following examples:

  • User attempting to authenticate using the wrong username or password:

    err tamd[6695]: pam_tacplus: unable to obtain username
    err tamd[6695]: pam_tacplus: auth failed: Login incorrect

  • User attempting to authenticate when the BIG-IP system is configured to use encryption and the TACACS+ server is not using encryption:

    err tamd[6695]: pam_tacplus: auth failed: TART packet (check keys)1

  • The service is misconfigured or not configured the same on the BIG-IP system and TACACS+ server:

    err tamd[6695]: pam_tacplus: TACACS+ authorisation failed for [bigipadmin]

  • The IP address defined as the TACACS+ server is incorrect, or the server is not accepting connections on port 49:

    err httpd[21514]: pam_tacplus: connection failed srv 0: Connection refused
    err httpd[21514]: pam_tacplus: no more servers to connect

Enabling debug logging for TACACS+ authentication

You can enable debug logging for TACACS+ authentication, attempt to log in using the TACACS+ user accounts, and then review the debug log files. To do so, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor performance.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable debug logging, use the following command syntax:

    modify  /ltm auth tacacs <tacacs_authentication_config> debug enabled

    For example, the following command enables debug logging for a TACACS+ configuration profile named tacacs_config:

    modify  /ltm auth tacacs tacacs_config debug enabled

  3. Test TACACS+ authentication by attempting to log in using remote user accounts.
  4. After testing TACACS+ authentication, disable debug logging by using the following command syntax:

    modify /ltm auth tacacs <tacacs_authentication_config> debug disabled

    For example:

    modify /ltm auth tacacs tacacs_config debug disabled

  5. Review the /var/log/secure file for debug log messages.

Packet tracing TACACS+ traffic

You may need to run tcpdump packet captures to troubleshoot TACACS+ sessions. When reviewing TACACS+ tcpdump output, it is helpful to understand the TACACS+ protocol header.

To packet trace TACACS+ traffic, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. You can capture TACACS+ traffic by using the following tcpdump syntax:

    tcpdump -s0 -ni <vlan> port 49 -vw /shared/tmp/tac.pcap

    Note: The -vw switches writes the output to /shared/tmp/tac.pcap, and it also starts a packet counter to show if any packets are being written to the file.

  3. You can view the capture file in packet analysis program for further debugging.
