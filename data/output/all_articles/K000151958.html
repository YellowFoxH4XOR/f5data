Description

This article describes  how  iRule Event agent  works for Per-Request Access Policies (PRP)?

When using a Per-Session Access Policy, the iRule Event agent placed in the policy triggers the execution of the event "ACCESS_POLICY_AGENT_EVENT".
Then, if I need to retrieve the agent ID, I can execute the command "ACCESS::policy agent_id" to return its value.

Environment

  • APM
  • Per-Request Access Policy
  • iRule event agent

Cause

N/A

Recommended Actions

Instead of using the event, "ACCESS_POLICY_AGENT_EVENT", Per-Request uses the event "ACCESS_PER_REQUEST_AGENT_EVENT".

Also, to retrieve the iRule agent ID, the command changes and becomes "ACCESS::perflow get perflow.irule_agent_id".

Additional Information

Here is an example iRule that will only log the iRule agent ID:

when ACCESS_PER_REQUEST_AGENT_EVENT {
    ACCESS::log accesscontrol.notice "ACCESS_PER_REQUEST_AGENT_EVENT: [ACCESS::perflow get perflow.irule_agent_id]"
}
