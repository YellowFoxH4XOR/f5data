K000161673: 011d0004:3 /shared partition full due to Tomcat holding deleted file descriptors

Type
Support Solution
Published
2026-06-22
Updated
2026-06-22
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161673

Description

The /shared disk partition on a BIG-IP LTM device reports 0% free space (99–100% utilization), even after files have been deleted from the filesystem. This prevents operations such as software upgrades that require available disk space on /shared.

Symptoms:

- Error: 011d0004:3: Disk partition /shared has only 0% free
- df -h /shared shows 98–100% disk usage
- Files appear deleted from the filesystem, but disk space is not reclaimed
- Large deleted files visible under /shared/images/ (e.g., upload_*.dat files) and /shared/tmp/ held open by Java/Tomcat processes

Environment

  • LTM
  • /shared partition is full

Cause

Tomcat (Java process) held open file descriptors to large files under /shared/images/ (e.g., upload_*.dat files) that had been deleted from the filesystem. On Linux, when a process holds an open file descriptor to a deleted file, the disk blocks are not released until the process closes the file handle or is restarted. This caused the /shared partition to remain at high usage despite the files being removed from the directory listing.

Answer/Recommended Actions

1. Identify deleted files still held open by processes on /shared:

lsof +L1 | grep /shared

Look for entries showing (deleted) in the file path — these are files that have been removed from the filesystem but whose disk blocks are still held by a running process.

2. Identify the largest files consuming space on /shared (optional, for further investigation):

find /shared/ -xdev -type f -exec du -m {} \; | sort -rn | head -20

3. Restart the Tomcat service to release the held file descriptors:

bigstart restart tomcat

4. Verify disk space has been recovered:

df -h /shared

Impact of restarting Tomcat: Restarting the Tomcat service (bigstart restart tomcat) temporarily interrupts access to the BIG-IP Configuration Utility (GUI) and iControl REST API for the duration of the restart. Traffic processing on the data plane (LTM, AFM, ASM, etc.) is not affected, as Tomcat handles only the management plane (REST/iControl interface and GUI).
