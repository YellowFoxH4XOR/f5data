Description

WAF policy is configured on manual Learning in the BIG-IP ASM automatically accepts the learning suggestions.

Audit logs indicate that the Policy Builder is making these changes despite the policy is  being set to accept manual learning.

 

Entries in /var/log/asm are similar to:

asm info perl[26462]: 01310053:6: ASMConfig change: Parameter example [update]: Parameter Value Type was set to User input value. Data Type was set to Alpha-Numeric. { audit: policy = /Common/example, component = Policy Builder }

Environment

  •  BIG-IP ASM

Cause

The issue is due to the "Classify Value Content of Learned Parameters" option being enabled under the learning and blocking settings. This setting is disabled by default. When enabled, the Policy Builder attempts to classify parameter types based on traffic data, leading to automatic parameter updates even in manual learning mode. If the Policy Builder cannot classify the parameter type due to insufficient traffic data, a fallback mechanism forces a default parameter type to ensure some level of security. This is a fallback mechanism that changes parameter attributes when the policy builder is unable to classify the traffic. This is expected behavior designed to maintain some security checks.

Recommended Actions

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Navigate to the learning and blocking settings of your desired security policy.
    2. Under parameter setting, ensure that the "Classify Value Content of Learned Parameters" option is disabled to prevent automatic parameter classification.
