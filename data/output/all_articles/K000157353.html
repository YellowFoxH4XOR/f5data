Description

PEM policy didn’t immediately block non-whitelisted URLs due to the tmm.cec.max_packets database key setting

Environment

  • PEM
  • Non Whitelisted URLs
  • PEM policy did not immediately block access to non-whitelisted URLs for users not allowed by policy
  • tmm.cec.max_packets DB key set to default (10)
  • URL filtering

 

Cause

The PEM policy enforces domain whitelisting as expected; however, the sys db value tmm.cec.max_packets allows up to 10 packets before classification action triggers, causing curl/telnet tests with small responses to appear allowed for non-whitelisted domains.

 

The PEM policy applies GATE:DROP only after classification, which occurs after receiving up to tmm.cec.max_packets packets. With the default value (10), some packets are allowed through before blocking occurs. Lowering the value to 5 enables earlier classification and immediate blocking of non-whitelisted URLs. If SNI or Host header information is not available within the set packet limit, classification may not occur as intended.

 

 

Recommended Actions

 

Avoid using CURL or TELNET to test non whitelisted URLs because from packet captures its observed that curl/telnet tests to non-whitelisted domains appear allowed due to small response content length fitting within the first 10 packets.

 

Identified sys db value controlling packet allowance:

 

sys db tmm.cec.max_packets {

    default-value "10"

    scf-config "true"

    value "10"

    value-range "unsigned_integer min:1 max:64"

}

 

Real browser/SIM tests correctly block non-whitelisted domains, while curl/telnet may show allowed due to packet limit logic.

 

 

Additional Information

To check whether packet is dropped enable Subscriber Activity logs from GUI> Subscriber Management> Activity Log
