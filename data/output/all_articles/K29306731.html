Description

This article describes a method to fix configuration problems that cause the BIG-IP chassis based system to fail when reconfiguring an iApp. The secondary blade mcpd will restart and the blade will recover but in this situation, the iApp cannot be reconfigured.

Under rare conditions modifying an iApp may cause a secondary blade to restart. The following error messages will be observed:

err mcpd[29298]: 010715bd:3: The parent folder is owned by application service (/Common/<APPNAME>.app/<APPNAME>), the object ownership cannot be changed to ().
err mcpd[29298]: 01070734:3: Configuration error: Configuration from primary failed validation: 010715bd:3: The parent folder is owned by application service (/Common/<APPNAME>.app/<APPNAME>), the object ownership cannot be changed to ().... failed validation with error 17241533.
info sod[5322]: 010c0009:6: Lost connection to mcpd - reestablishing.
notice sod[5322]: 010c008b:5: Unable to send to unreachable unicast address <IP_address> port 1026. (Network is unreachable)
notice promptstatusd[3669]: 01460006:5: semaphore mcpd.running(1) held
warning promptstatusd[3669]: 01460005:4: mcpd.running(1) held, wait for mcpd
notice chmand[8827]: 012a0005:5: resetting chmand services
err clusterd[7715]: 013a0004:3: IO error on recv from mcpd - connection lost

<APPNAME> is the iApp being reconfigured.

Environment

The problem can happen under the following conditions:

  • A chassis system with multiple blades.
  • An iApp is deployed and subsequently modified.
  • This problem is more frequently noticed after an upgrade.
 

Cause

Some configuration objects lose their association with the iApp.

Recommended Actions

Manually edit the bigip.conf file on the Primary blade to re-associate the configuration objects. Search the file for objects that bear the iApp name and add in the application association line. In general, you will find that some Virtual Servers have lost the app-service line.

Before editing any conf file, make a backup copy.

For example here is a correct association using the "app-service" configuration line:

ltm virtual MY_IAPP.app/MY_IAPP_https {
    app-service /Common/MY_IAPP.app/MY_IAPP

Once the app-service line is reinstated for configuration objects that have lost their association, run "tmsh load sys config verify" to check that the manual changes will load. Then use "tmsh load sys config" to load the configuration into running memory.

Important: Running the "tmsh load sys config" load command will cause a service interruption. Perform these activities during a maintenance window.
