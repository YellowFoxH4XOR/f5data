K000134483: Assertion is invalid, error: Invalid Session, possible use of different host names to access SAML SP

Type
Support Solution
Published
2023-07-10
Updated
2026-03-09
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000134483

Description

Session rejected with the error message found in /var/log/apm:

SAML Agent: /Common/<policyname>_act_saml_auth_ag SAML assertion is invalid assertion, error: Invalid Session, possible use of different host names to access SAML SP

Environment

  • APM policy configured
  • The Big-IP is configured as SP with external IDP

The following describes an example use case:

  1. the client tries to access the BIG-IP, Service Provider (SP) at https://myservice.example.com on the browser.
  2. The SP redirects the client to the Identity Provider (IdP) to be authenticated.
  3. The IdP successfully authenticates the client and redirects the client back to the SP at https://supportservice.example.com
  4. The SP BIG-IP expects the URL at step 1. Access is rejected with the error message logged.

Cause

  • The IDP redirect the traffic with different host name other than the one that was sent and expected, so it reject the session.
  • The client use a url with extra characters after the host name that does not match the configured entity ID.

Recommended Actions

Consider the following:

  • Make sure the client use the same URI that is configured that the IDP expects.
    For example, if the issue is happening for only for some users, these users may be accessing with a URL stored in a bookmark that contains a different hostname or with additional extensions and parameters. Try typing the URL manually on the browser to test.
  • Also check with IDP vendor with any wrong behavior redirecting with the wrong host name
  • Verify your configuration referring to Using APM as a SAML Service Provider.

Additional Information

You can troubleshoot by capturing the URLs accessed on the browser level using a browser developer tool, fiddler or HTTPWatch.

  • Observe the URLs that the client is accessing when connecting to the SP, IdP and back to the SP respectively.
  • Compare the SAML assertion with the configuration on the IdP and SP. Refer to a configuration example Using APM as a SAML Service Provider.
