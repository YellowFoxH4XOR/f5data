Description

The setting for "Check maximum number of parameters" in the "HTTP protocol compliance failed" section when you go to Security  ››  Application Security : Policy Building : Learning and Blocking Settings will not go beyond 5000. If you try to go beyond that limit you will get an error message that says "invalid value".

Environment

  • In certain cases an issue may occur where parameter names do exceed 5000.
  • Parameters, Web Application, iRule, LTM Local Traffic Policy
  • ASM/AdvWAF
Cause

There is no specific limit in ASM enforcement to any particular number of parameters. With that being said, the purpose of the enforcement level (and the limitation of 5000 in the GUI) chosen is to deal with a situation in which a large number of parameter names in a request might cause a hash collision vulnerability (such as in a PHP web application). Beyond 5000 parameters, a hash collision becomes much more likely.

HTTP Request parameters are stored in a dictionary for fast and easy lookup and the most common implementation of the dictionary is a hash table.

A common algorithm is used for the dictionary/hash tables of all the major web service platforms (Java, ASP.NET, and Apache).

In late 2011 a clever attack was released that took advantage of the ubiquity of this hashing algorithm.

By sending a single POST message filled with thousands of variables, the hashing function would overload and a server could be tied up processing this single request for as long as an hour. This is a hash denial-of-service (DoS) attack.

By addressing this problem at the Application Delivery Controller (ADC), the F5 BIG-IP system protects all of the back-end web server platforms at the same time, ensuring the hash DoS attack is never seen by the web server.

Recommended Actions

If the need were to arise that the limit of 5000 is too restrictive for your particular environment there a couple of possible ways to deal with this:

  1. Create an iRule that would provide an exception for a certain URI path and ASM::disable if the "Check maximum number of parameters" value is exceeded.
  2. The Local Traffic Policy feature disable BIG-IP ASM processing for traffic that matches certain conditions.
Note: Per F5 policy to get help configuring an LTM Local Traffic Policy or writing an iRule would be the purview of F5 Professional Services.
For more information about both iRule and LTM Local Traffic Policy to disable BIG-IP ASM processing for certain requests, refer to K22021244: Bypassing the BIG-IP ASM system (12.1.0 and later).
