Description

Configuration synchronisation fails in a BIG-IP LTM high-availability device group when the config-sync VLAN is configured with jumbo frames (MTU > 1500). Symptoms include devices stuck in "Sync Failed" state, error messages such as "There is an unfinished full sync already being sent for device group /Common/Sync-ha...", "A validation error occurred while syncing to a remote device", and "Sync error on <peer>: Load failed from <originator> 01070712:3: Caught configuration exception (0), Failed to sync files." Commit ID mismatches and repeated log entries indicate full sync attempts are not completing.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1.3 (also applies to BIG-IP 14.1.0 and later)
  • Two or more devices in HA device group
  • Config-sync VLAN configured with jumbo frames (MTU > 1500)
  • Intermediate network devices may not support jumbo frames end-to-end

Cause

Starting with BIG-IP 14.1.0, the CMI channel (used for ConfigSync) derives its TCP Maximum Segment Size (MSS) from the VLAN MTU. If the config-sync VLAN is set to a jumbo MTU (e.g., 9000), BIG-IP will advertise a large TCP MSS (e.g., ~8960 bytes). If any intermediate network device does not support jumbo frames, these oversized TCP segments are silently dropped, causing the sync process to hang indefinitely and never complete.

Answer/Recommended Actions

  1. Use Standard MTU for ConfigSync VLAN
    • Set the VLAN used for config-sync to a standard MTU (1500 bytes).
    • If jumbo frames are required for data-plane traffic, use a separate VLAN for config-sync with MTU 1500.
  2. Verify End-to-End MTU Support
    • If jumbo frames must be used for config-sync, confirm all intermediate network devices between BIG-IP peers support the same MTU value end-to-end.
  3. Restore Sync
    • After adjusting the MTU, force a full config sync:
      tmsh run cm config-sync force-full-load-push to-group <device-group-name>
    • Monitor sync status with:
      tmsh show cm sync-status
  4. Reference Documentation
    • Review F5 KB articles for further details and prerequisites.

Additional Information

  • Prior to BIG-IP 14.1.0, the CMI channel always used a fixed TCP MSS of 1448 bytes, so jumbo frame settings did not affect config-sync traffic.
  • With newer versions, the MTU setting directly impacts the TCP MSS for config-sync, making network path MTU consistency critical.
  • Typical log messages for this issue include repeated "unfinished full sync" and connection resets.
