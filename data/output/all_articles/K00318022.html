K00318022: Virtual Edition boot location does not activate to correct version.

Type
Support Solution
Published
2023-09-21
Updated
2025-02-06
Status
Legacy Content
Applies to
  • BIG-IP
  • Virtual Editions
Source
https://my.f5.com/manage/s/article/K00318022

Description

  • You activate a boot location for a new version.
  • After booting, you are back in the original version.

Environment

  • Virtual Edition
  • 2 disks installed

Cause

  • Both disks are marked bootable
  • The Hypervisor is booting the wrong disk. The updated grub config that controls the booting is not read because its on the wrong disk

Recommended Actions

  1. A system in this state is not in a supportable configuration. Create a replacement device.
    1. Record the masterkey with   f5mku -K
    2. Take and download UCS archive
    3. Record the License String
    4. Revoke the License
    5. Stop the Virtual machine
    6. Create new Virtual machine and reinstall from clean OVA source
    7. Perform minimal setup.
    8. Restore the masterkey with f5mku -r <key>
    9. Restore the UCS archive

Additional Information

For testing this state:
in the cli run
fdisk /dev/sda
p      to print the partition table      it should be bootable
q to quit

fdisk /dev/sdb
p      to print the partition table      it should be not be bootable
q to quit
