Description

 

Declarative Onboarding reboots device when a new Device Certificate/Key is defined.

Declarative Onboarding reboots device when subsequent declarations are deployed with missing Device Certificate/Key definition (triggering roll back procedure).

 

Environment

 

  • BIG-IP
  • Declarative Onboarding
  • DeviceCertificate

 

Cause

AUTOTOOL-3579

The BIG-IP system is rebooted when submitting a declaration with change in Device Certificate/Key

 

Recommended Actions

 

Use the latest rpm version currently Declarative Onboarding v1.49

 

 

Additional Information

If the Device Certificate/Key is not defined in subsequent DO deployments, they (including Trust Certs used for iQuery) may roll back to previously configured cert/key files due to the following DO backup files:

/config/httpd/conf/ssl.crt/server.crt.DO.orig
/config/httpd/conf/ssl.key/server.key.DO.orig
/config/big3d/client.crt.DO.orig
/config/gtm/server.crt.DO.orig

 

If this behaviour is not desired, you can delete the above files before deploying DO declaration.

Alternatively use the Skip Device Certificate check introduced in DO v1.51 (not available at time of writing), to avoid triggering the roll back process:

https://clouddocs.f5.com/products/extensions/f5-declarative-onboarding/latest/schema-reference.html#devicecertificate

"deviceCertificate": {
"class": "DeviceCertificate",
"skipDeviceCertificates": true,
}
