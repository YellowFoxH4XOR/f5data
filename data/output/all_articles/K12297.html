Known Issue

This is the result of a known issue. When the Custom XFF Header feature is enabled, and another header with the same name is configured elsewhere on the BIG-IP system, the system may not recognize the specified header as a trusted XFF header.

This namespace collision may occur across classes, as well as across the BIG-IP ASM and BIG-IP PSM modules on the same system. All of the following examples are considered as a namespace collision, resulting in the BIG-IP system not recognizing the MyHeader1 header:

  • MyHeader1 exists as Custom XFF Header or mandatory header in the ASM configuration, and MyHeader1 exists as Custom XFF Header or mandatory header in the PSM configuration.
  • MyHeader1 exists as Custom XFF Header, and MyHeader1 exists as mandatory header in the ASM configuration, in a single class.
  • MyHeader1 exists as Custom XFF Header, and MyHeader1 exists as mandatory header in the PSM configuration, in a single class.
  • MyHeader1 exists as Custom XFF Header or mandatory header in Class1, and MyHeader1 exists as Custom XFF Header or mandatory header in Class2, in the ASM configuration.
  • MyHeader1 exists as Custom XFF Header or mandatory header in Class1, and MyHeader1 exists as Custom XFF Header or mandatory header in Class2, in the PSM configuration.

F5 Product Development tracked this issue as ID 226189 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP ASM release notes.

In addition, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
