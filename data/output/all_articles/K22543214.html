Description

In some scenarios it is necessary to manually clear the AVR data. For example, to recover from a database issue.

This article outlines the procedure.

Important: The steps in this article should typically only be used when recommended by F5 Support. In most scenarios you are encouraged to first use the procedure in K14956 to reset the AVR stats.

Environment

  • AVR, ASM, AFM or APM provisioned

Cause

Various issues may necessitate use of this procedure. Typically mysql errors or database issues, which have numerous symptoms. For example:

  • Upgrade failure
  • UCS save failure
  • Disk space full
  • Daemon failures
  • GUI not working

Recommended Actions

Follow the procedure below to clear the AVR statistics by manually removing the AVR data files and resetting the database.

Important: This procedure causes a failover at step 6 when mysql is restarted, so a maintenance window is recommended.

  1. Log in to the command line and access bash.

  2. Back up the existing data to /shared/tmp/avr.dmp.gz:

    mysqldump -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR | gzip -9 > /shared/tmp/avr.dump.gz

    Note: This step is optional.

  3. Stop the monpd process:

    tmsh stop /sys service monpd

  4. Remove the AVR files:

    rm -rf /var/lib/mysql/AVR/*

  5. Create the /var/avr/init_avrdb file:

    touch /var/avr/init_avrdb

  6. Restart the mysql process:

    tmsh restart /sys service mysql

  7. Restart the monpd process:

    tmsh restart /sys service monpd

The AVR statistics have now been reset.

Additional Information

AVR is implicitly provisioned if any of the modules listed in the Environment of this article are provisioned. The AVR database will be used for statistical purposes even if AVR is not explicitly provisioned.
