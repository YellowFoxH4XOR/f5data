K68489751: ElasticSearch Cluster not Healthy After Adding DCD

Type
Support Solution
Published
2020-11-05
Updated
2025-02-06
Applies to
  • Virtual Editions
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K68489751

Description

Elasticsearch may show an unhealthy status and log messages similar to the following in /var/log/elasticsearch/eslognode.log

2020-07-14T00:04:13,292][INFO ][o.e.d.z.ZenDiscovery     ] [xxxxxxxx-xxxx-xxxx-xxxxxxxxxxxx] master_left [{xxxxxxxx-xxxx-xxxx-xxxxxxxxxxxx}{xxxxxxxxxxx}{xxxxx}{192.0.2.3}{192.0.2.3:9300}{zone=default}], reason [failed to ping, tried [3] times, each with  maximum [30s] timeout]
[2020-07-14T00:04:13,293][WARN ][o.e.d.z.ZenDiscovery     ] [xxxxxxxx-xxxx-xxxx-xxxxxxxxxxxx] master left (reason = failed to ping, tried [3] times, each with  maximum [30s] timeout), current nodes:

Environment

  • BIG-IQ with DCD cluster

Cause

There are long-lived TCP connections on port 9300 between CM, and DCDs. Those connections send keepalive probes after being idle for 299 seconds. If an intermediate device idle-times out this TCP connection in less than 299 seconds, the ES cluster will experience stability problems.

Recommended Actions

  1. Edit the file /etc/bigstart/scripts/elasticsearch and modify the following setting to meet the needs of the environment:

    sysctl -w net.ipv4.tcp_keepalive_time=299 \
    net.ipv4.tcp_keepalive_intvl=60 \

  2. Set net.ipv4.tcp_keepalive_time to the number of seconds a connection is idle before keepalives are sent.
  3. Set net.ipv4.tcp_keepalive_intvl to the interval between keepalives
    Example values that work in most environments:
    sysctl -w net.ipv4.tcp_keepalive_time=20 \
    net.ipv4.tcp_keepalive_intvl=20 \
     
  4. To set the values for the currently running system enter the following commands on the CLI:
    Note: The values set in /etc/bigstart/scripts/elasticsearch take effect on the next boot. 

    sysctl -w net.ipv4.tcp_keepalive_time=20
    sysctl -w net.ipv4.tcp_keepalive_intvl=20
Note: The above action should be performed on all CMs and DCDs.
Note: It will not persist an upgrade

Additional Information

This is caused by bug id 1021149. This issue is fixed in version 8.1.0.2.
