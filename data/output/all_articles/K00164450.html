Issue

Old Behavior

In versions prior to BIG-IP 13.0.0, the BIG-IP system uses hardware-syn-cookie and software-syn-cookie command options to protect against SYN flood attacks. You can modify SYN cookie protection options using the TMOS Shell (tmsh) for TCP, FastL4, and Fast HTTP protocol profiles. BIG-IP platforms equipped with the high-speed bus (HSBe2) chip can perform both hardware and software SYN cookie protection, while other platforms perform software-only SYN cookie protection. For more information about SYN cookie protection and the BIG-IP platforms that support the hardware SYN cookie feature, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x) and K74451051: Configuring SYN cookie protection (13.x - 16.x).

Note: The hardware-syn-cookie option is disabled in the Fast HTTP profile, and the system uses the software-syn-cookie option by default.

New Behavior

Beginning in BIG-IP 13.0.0, the software-syn-cookie and hardware-syn-cookie options are deprecated and replaced with the syn-cookie-enable option. You can use the syn-cookie-enable [enabled / disabled] option to enable or disable the hardware or software SYN cookie protection in the TCP and FastL4 profiles; this option is enabled by default in the TCP and FastL4 profiles.

       syn-cookie-enable
            Enables syn-cookies capability on this virtual server.  For the
            details on the threshold at which syn-cookies are triggered please
            see default-vs-syn-challenge-threshold and global-syn-challenge-
            threshold or the tcp-half-open vector in the DoS profile. The
            default is enabled.

The following table describes the SYN Challenge Handling settings and definitions:

SettingDefault ValueDescription
SYN Challenge HandlingNominalSpecifies the default number of embryonic connections (if no denial-of-service [DoS] profile is associated) that are allowed on any virtual server, before SYN Cookie challenges are enabled for that virtual server. The default is Nominal.
  • Nominal: Initiates SYN cookie challenges after a relatively low number of embryonic connections.
  • Challenge and Remember: Specifies whether SYN packets subsequent to a successful challenge response, from the same Source IP address, should be challenged or allowed to pass unchallenged (up to some timeout period). Enabling this feature prevents hardware acceleration for SYN challenges, but may be needed/useful in some deployments (for example, direct server return (DSR) mode or when no hardware acceleration is available). Essentially, Challenge and Remember adds the packet's TCP address to the SYN Cookie White List.
  • Disable Challenges: Does not initiate SYN Cookie challenges, regardless of the number of embryonic connections.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

F5 Product Development tracked this change as ID 628735.

Impact

The hardware-syn-cookie and software-syn-cookie protection options are no longer valid. You can use the syn-cookie-enable option for either hardware or software SYN cookie protection.

When upgrading from a version prior to BIG-IP 13.0.0 to BIG-IP 13.0.0 or later, the syn-cookie-enable setting is enabled by default in the profile. However, when upgrading from a version prior to BIG-IP 13.0.0 in which both the hardware-syn-cookie and software-syn-cookie values are set to disabled in the profile, the new setting, syn-cookie-enable, is also disabled in the profile.

Recommended Actions

F5 recommends that you do not disable the syn-cookie-enable option. This feature helps to prevent the BIG-IP SYN queue from becoming full during a SYN flood attack, so that normal TCP communication can continue. You can perform the following procedure to modify the syn-cookie-enable option in the protocol profiles:

Impact of procedure: The impact of the following procedure depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the syn-cookie-enable settings for a protocol profile, use the following command syntax:

    modify /ltm profile <protocol_profile> <profile_name> syn-cookie-enable default-value | disabled | enabled

    For example, to disable the syn-cookie-enable settings for the FastL4 profile named test-fastl4 , type the following command:

    modify ltm profile fastl4 test-fastl4 syn-cookie-enable disabled

  3. Save the configuration by typing the following command:

    save /sys config
