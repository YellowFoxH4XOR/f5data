K45285291: TLS Handshake Failure after Client Hello

Type
Support Solution
Published
2021-06-15
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K45285291

Description

When any client tries to establish an SSL/TLS connection with a virtual server in the BIG-IP, it sends a reset packet after the client hello.

On the /var/log/ltm file, you see logs similar to these:

warning tmm1[19811]: 01260009:4: Connection error: ssl_hs_rxhello:10351: unsupported version (70)
warning tmm1[19811]: 01260013:4: SSL Handshake failed for TCP x.x.x.x:5555 -> y.y.y.y:443

On a pcap you will see the following packets every time a connection is received by the virtual server:

  • The normal TCP 3-way handshake packets
  • Client Hello packet
  • Alert packet with a description similar to this: TLSv1.2 Record Layer: Alert (Level: Fatal, Description: Handshake Failure)
  • FIN packet

Environment

  • BIG-IP
  • SSL Profile options
  • Virtual Server

Cause

You have enabled the 'No TLS' option on your Client SSL profile.

Recommended Actions

  1. On the GUI go to: Local Traffic  ››  Profiles: SSL: Client ›› <clientssl name>
  2. Change the Configuration view to Advance
  3. Validate your Cipher Suites
  4. Validate that in the Options List you have not enabled the 'No TLS' Option
  5. If you have the 'No TLS' Option enable, remove it from the list.
