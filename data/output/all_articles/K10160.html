Known Issue

This is the result of a known issue. As part of the BIG-IP upgrade process, it is possible to roll the current system configuration forward to the new version of BIG-IP software. One of the configuration elements carried forward during the upgrade is the sshd portion of the Pluggable Authentication Module (PAM).

F5 has determined that the sshd PAM authorization configuration that is carried forward during an upgrade may cause issues if remote roles are used for authentication. As a result, all users authenticated by a remote authentication server for console access are granted guest privileges rather than their actual privileges.

F5 Product Development tracked this issue as CR121641 and it was fixed in BIG-IP versions 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, WOM, or WebAccelerator Release Notes.

Workaround

To work around this issue and configure console authentication to work correctly for remote roles, you must use a text editor and modify the /config/bigip/auth/pam.d/sshd file to appear as follows:

#%PAM-1.0
auth required pam_audit.so
auth required pam_stack.so service=system-auth
auth required pam_nologin.so
account required pam_audit.so
account required pam_stack.so service=system-auth
account required pam_bigip_authz.so
password required pam_audit.so
password required pam_stack.so service=system-auth
session required pam_audit.so
session required pam_stack.so service=system-auth
