Known Issue

Note: The HA Group feature was introduced in BIG-IP 10.1.0. A high availability group uses a set of trunks, pools, clusters (or any combination of these) to calculate the health scores for units in redundant system configurations. For more information about configuring the HA Group feature on the BIG-IP system, refer to the TMOS Management Guide for BIG-IP Systems. For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

This is the result of a known issue. When you configure the HA Group feature from the Configuration utility, the BIG-IP system may incorrectly set the value for the Active Bonus setting to zero. However, if you configure the HA Group feature from tmsh or the bigpipe command, the Active Bonus setting uses the default value of ten. If the HA Group configuration stanza in the /config/bigip_local.conf file does not include the Active Bonus statement, the Active Bonus value is ten. In the following HA Group configuration example, the Active Bonus setting is not explicitly configured; therefore, the Active Bonus setting uses the default value:

ha group myhagroup-cli {
pools http-pool-all {
scoring {
weight 10
}
}
}

You can determine the Active Bonus value by entering the bigpipe ha group list all command in the command line. Output appears similar to the following example:

ha group myhagroup-cli {
enable
active bonus 10
clusters none
pools http-pool-all {
attribute percent up members
scoring {
threshold 0
weight 10
}
}
trunks none
}

F5 Product Development tracked this issue as ID 338362, and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.
