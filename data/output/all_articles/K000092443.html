Description

The BIG-IP Next instance REST API relies on token authentication. All clients that connect to BIG-IP Next will use the API to log in and obtain a token. This includes clients like the GUI, CLI, Postman, and Ansible. This article explains how it works at the API level.

Environment

  • BIG-IP Next for Virtual Edition, VELOS, or rSeries

Procedure

Assumptions and notes

  • By default, the API server for BIG-IP Next listens on port 5443.
  • Although any tool capable of sending HTTPS requests can be used, curl will be used in the examples. The -s parameter enables silent mode and the -k parameter enables insecure mode
    • If the HTTP method is not specified, curl uses GET as the default.
  • When JSON is returned the command will make use of the "jq" utility to render the JSON in pretty form

Step 1 - log in with your username and password.

If the BIG-IP Next instance is managed by the BIG-IP Next Central Manager, login with the admin-cm user and the password you created when you added the Next instance. If the BIG-IP Next instance has never been added to BIG-IP Next Central Manager, login with the admin user and the password you created during instance onboarding. When the login is successful, the HTTP response code is 200 OK and the response body contains a JSON payload with a "token" parameter in it.

curl -sku admin:password https://10.10.10.10:5443/api/v1/login | jq

Possible errors

If you entered the wrong password, the HTTP response code will be 401, you won't get the token in the response, and an error will indicate that it failed to authenticate. You can set the correct password and try again.

curl -sku admin:wrongpassword https://10.10.10.10:5443/api/v1/login | jq
{
  "_errors": [
    {
      "id": "77e77e5f-d050-495a-b01e-6603434fc45e",
      "code": "13158-00134",
      "title": "",
      "detail": "Failed to authenticate.",
      "status": "401",
      "_links": {
        "about": "https://clouddocs.f5.com/api/mbip/errors/13158-00134"
      }
    }
  ]
}

If HTML is returned, you're probably connecting to the default port of 443. 

curl -sku admin:password https://10.155.74.72/api/v1/login
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<title>Error</title>
</head>
<body>
<pre>Cannot GET /api/v1/login</pre>
</body>
</html>

Change the URL to point to port 5443 if this occurs.

Additional Information

Here are some commands that do not require token authentication

  • Logging in via /api/v1/login
  • Changing password via /api/v1/me
