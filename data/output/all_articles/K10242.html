Known Issue

This is the result of a known issue. The bigpipe import default command is intended to reset the running configuration of the system to the factory defaults while retaining the management port networking configuration. However, when the bigpipe import default command is used to reset the configuration on a system which is configured with more than one management route, only the first management route is preserved.

F5 Product Development tracked this issue as CR122222 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization release notes.

This issue still exists in the BIG-IP 9.4.x, 9.6.x, and 10.0.x software branches.

Workaround

Prior to using the bigpipe import default command, you may avoid this issue by removing all management routes but the default route.

If multiple management routes are required, you can reconfigure the missing management routes. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. To list the management routes configured on the system prior to resetting the configuration, type the following command:

    bigpipe mgmt route show

  3. To reconfigure the default management route after resetting the configuration, use a command similar to the following example:

    bigpipe mgmt route default gateway 172.16.1.254

  4. To reconfigure the remaining management routes, use commands similar to the following example:

    bigpipe mgmt route 10.10.10.0 netmask 255.255.255.0 gateway 172.16.1.254

Note: Depending on the single route preserved after resetting the configuration, you may need to log in to the system from the serial console or from a system on the locally connected management network.
