Description

The following article describes how to try achieve a better throughput when connecting to Network Access VPN using a Windows machine.

Environment

  • APM is configured to provide VPN access to Windows machines.
  • Poor throughput is achieved when connected to the VPN.

Cause

There are many factors that can limit the throughput (BIG-IP CPU, Windows CPU, compression, TCP profiles, latency, vpn buffer size, TLS/DTLS, AV/Firewall software on Windows machine, type of connection, etc).
That solution focuses on one known Microsoft limitation.

While running performance tests, we have identified some packet loss and slow down at times when VPN is enabled.
After bringing the matter to Microsoft, they have isolated the behavior of packets being dropped in the PacketQueue in the NDISWAN layer.

NDISWAN is a system-supplied NDIS intermediate driver that provides functionality such as data compression, encryption, loopback, and simple PPP framing that is used by WAN miniport drivers.

In order to try avoid such packet loss, Microsoft has provided some registry keys that can be applied on a Windows machine.
 

Recommended Actions

The following registry entries will set the packet queue large enough that there should be no loss of packets due to queue overrun.

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\NdisWan\Parameters]
"ProtocolType"=dword:00000800
"PPPId"=dword:00000021
"PacketQueueDepth"=dword:00100000

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\NdisWan\Parameters\Protocols]
"ProtocolType"=dword:00000800
"PPPId"=dword:00000021
"PacketQueueDepth"=dword:00100000

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\NdisWan\Parameters\Protocols\0]
"ProtocolType"=dword:00000800
"PPPId"=dword:00000021
"PacketQueueDepth"=dword:00100000

Reboot the Windows machine once these entries have been created.
