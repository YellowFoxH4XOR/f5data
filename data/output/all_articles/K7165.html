Topic

This article applies to BIG-IP 9.0.0 through 9.3.x. For information about other versions, refer to the following articles:

  • K11127: Testing SNMP traps on the BIG-IP system (9.4.x - 12.x)

SNMP traps are triggered when the alertd process receives input from the syslog-ng utility that matches an alert code. The alertd process then performs the action specified in the /etc/alertd/alert.conf file, such as sending an SNMP trap.

Note: For more information, refer to K3727: Configuring custom SNMP traps and K3667: Configuring alerts to send email notifications. The Custom SNMP Traps article at the F5 DevCentral site contains additional helpful information. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

When configuring or troubleshooting SNMP traps or email alerts on the BIG-IP system, you may want to generate test syslog-ng messages that the BIG-IP system will send as SNMP traps or email alerts.

To generate test syslog-ng messages, you can use the logger utility, which is a shell command interface to the syslog-ng system log module. You can use the logger utility to make entries in the syslog-ng system log.

To use the logger utility to generate test SNMP traps or email alerts, perform the following procedure:

  1. Log in to the command line.
  2. To view pre-configured SNMP traps in the /etc/alertd/alert.conf file, type the following command:

    less /etc/alertd/alert.conf
  3. Find one of the pre-configured traps, or an alert that has been configured to send an email notification.

    For example, pre-configured traps contain the word snmptrap, similar to the following example:

    alert BIGIP_MCPD_MCPDERR_NODE_ADDRESS_MON_DOWN "Node (.*?) monitor status down." {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.12"
    }

    Alerts which have been configured to send an email notification contain the word email, similar to the following example:

    alert BIGIP_SHELL_BP_CONFIGURATION_LOADED {
            snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.28";
            email toaddress="alerts@example.com"
            fromaddress="root@bigip1.example.com"
            body="The test of this Solution worked!"
    }

  4. Identify the log message that triggers the alert.

    For example, in the pre-configured SNMP trap example above, all log messages are compared against the following match expression string, and syslog messages that match the expression trigger the alert:

    Node (.*?) monitor status down.

    In the email alert example, the match string is not defined in the alert definition in the alert.conf file. You can locate the match expression for the alert by using the following command to search in the bigip_error_maps.dat file for the alert name:

    grep BIGIP_SHELL_BP_CONFIGURATION_LOADED /var/tmpfs/run/bigip_error_maps.dat

    The command returns the line from the bigip_error_maps.dat file, which includes the following match expression string, and those syslog messages that match the expression triggering the alert:

    The configuration was successfully loaded.
  5. Use the extracted match expression string to define your logger command, as in the following example:

    logger -p local0.warning "Node 10.10.64.14 monitor status down."

    This command will output a syslog-ng message to the local0.warning facility (the default location is the /var/log/ltm file), and the corresponding SNMP trap for this message will be generated.
