K000132345: unable to update the epsec version on the APM

Type
Support Solution
Published
2023-01-31
Updated
2023-04-26
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000132345

Description

When attempting to update the epsec version on the BIG-IP APM, it is not getting updated, for some reason. It still shows the 'old' epsec version.


Also, when running the 'epsec version' command, it returns an error something similar to the below:

[root@bigip1:Active:Standalone] ~ # epsec version

error: db5 error(11) from dbenv->open: Resource temporarily unavailable

error: cannot open Packages index using db5 - Resource temporarily unavailable (11)

error: cannot open Packages database in /var/apm/lib/rpm


Environment

  • BIG-IP APM
  • epsec


Cause

The most likely cause of this is that the rpm database on the BIG-IP is corrupted.


 Recommended Actions

Run this command on the BIG-IP CLI to repair/rebuild the rpm db:

# /bin/rpm --root /var --dbpath /apm/lib/rpm -vv --rebuilddb


There may be times when running the above command alone is not enough to fix the corrupted rpm db. In these instances, you may need to do a refresh of the epsec using this command:

# epsec -f refresh


In some extreme cases, if the issue still persists even after running the 2 above-mentioned commands, an mcpd forceload of the device might be necessary to get it back to a working state again. You can follow the procedures in this article K13030: Forcing the mcpd process to reload the BIG-IP configuration
