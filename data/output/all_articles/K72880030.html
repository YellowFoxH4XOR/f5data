Description

You may have seen something block due to something in the query string, or maybe you have found that for versions 15.1.x and 16.1.x the steps to create one have changed.

  • You may see a connection blocked due to "Illegal Parameter"

A review of the AdvWAF/ASM Event Log shows this...

Violation Details 
Parameter LocationQuery String
Parameter NameDonut
Parameter ValueOld_fashioned

It came from this request:

GET /api/nga-login-page-info?Donut=Old_fashioned HTTP/1.1

Environment

Since version 14.0.0 the BIG-IP has been able to deal with positional arguments in the URL instead of the more common string/value pair type of parameter. However, the GUI for AdvWAF used for creating/configuring positional parameters has changed and there are new options within the configuration. The article for version 14.0.0/14.1.x goes into a what and why about the positional parameter... K52644614: Creating positional parameters for a URL

  • AdvWF/ASM is blocking parameters after the query string.
  • Allowed URLs, Parameters

Cause

Sending a special or secret parameter that could trigger some hidden activity of the web application, which was not intended to be exposed to the public could cause an issue. So, for example, if parameter Donut=Old_fashioned is not defined in the security policy it will be blocked.

Recommended Actions

To deal with these positional parameters follow these steps.

First you need to setup an 'Allowed URL'.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
  3. Select Create.
  4. For 'Create New Allowed URL' select Advanced in the dropdown.
  5. For URL select Wildcard.
  6. Select the Positional Parameters check box.
  7. Choose either HTTP or HTTPS. Depending on your network you may need to do one for both.
  8. For URL with Positional Parameters, select the Request Method the query used.
  9. To create a new parameter, select "Add Segment" and perform the following steps, as appropriate

If you need to create a New Positional Parameter, follow these steps:

  1. In the pop-up window that shown when you clicked "Add Segment", select Parameter and select Add new parameter.
  2. For Name, enter the parameter.
  3. For Wildcard Expression, use fnmatch syntax or leave the value as the default asterisk (*) character.
  4. Select OK.
  5. Define the remaining URL options as needed.
  6. Select Create.
  7. Select Apply Policy.

If you already have a parameter, follow these steps:

  1. In the pop-up window, select Parameter, select "Select parameter", and for Name, select an existing parameter.
  2. Select OK.
  3. Define the remaining URL options as needed.
  4. Select Create.
  5. Select Apply Policy.

Note: Once a method is used to create a positional parameter for a URL that Method cannot be used again for other positional parameters. See below to create additional positional parameters for the same Method.

Note: Check the Wildcards Order tab to make sure the security policy has the right URL order to avoid any conflicts with URL matching. This is important since the wildcard matching strategy is first-match, starting from the top of the list.

Important: After the positional parameter has been created it becomes Global and explicit for that policy irregardless of Method.

Once you have created/configured the 'Allowed URL' with the positional parameter you can then configure anything needed for the new parameter you just created.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Parameters > Parameter List for the policy the positional parameter was created for.
  3. In the Parameter Name column, select the positional parameter that you created in the previous procedure.
  4. Configure the parameter options as needed. For example, to disable an attack signature for the parameter, select the Attack Signatures tab and select the check box for "Check attack signatures and threat campaigns on this parameter". Then you can search for the attack signature you want to disable and mvoe it over to the 'Overridden Security Policy Settings' box.
  5. Select Update, and the Apply Policy if you have made any changes.

As stated above, once a method has been used it cannot be used for that policy again. That brings up the question of how do I add additional positional parameters to the method.

  1. To do that go to Security >  Application Security > URLs > Allowed URLs > Allowed HTTP URLs and click the Protocol, Method, and URL you want to add a positional parameter to. That will bring you to Security >  Application Security > URLs > Allowed URLs >: Allowed HTTP URLs  > Allowed HTTP URL Properties by default.
  2. At the top click on 'URL Properties'.
  3. Click 'Create' and you can create a new positional parameter for a Method that has already been used.
  4. Select Update, and the Apply Policy if you have made any changes.
  5. You can then go to Security  >  Application Security > Parameters > Parameters List, find the positional parameter you created, and make any changes needed for that parameter.

Note: When a new one is added via this add-on method it can be Global or Method specific.
