K000160989: F5OS Local User Password Creation Fails Despite Meeting Password Policy

Type
Support Solution
Published
2026-04-26
Updated
2026-04-26
Applies to
  • F5OS
  • F5OS-A: 1.8.3
Source
https://my.f5.com/manage/s/article/K000160989

1. Description

Local user password creation on F5OS fails with error messages indicating the password does not meet policy requirements, even though the password satisfies the configured policy. Error message:


set-password failed. Rejected, Configured password-policy: min-length:8, reject username in password.


Symptoms:

  • Unable to create or update local user passwords
  • Error messages in logs and GUI indicating password rejection
  • LDAP user creation and login are unaffected

2. Environment

  • Product: F5OS
  • Version: 1.8.3
  • Password policy settings:
    • Minimum length: 8
    • Username not allowed in password
    • No requirements for numeric, uppercase, lowercase, or special characters
    • No other constraints active
  • Issue affects only local users (not LDAP users)
  • Attempts made via both GUI and CLI

3. Cause

A malfunction or stale state in the user-manager service prevented local user password changes from being accepted, despite valid input. Restarting the user-manager service resolved the issue.

4. Answer/Recommended Actions

  1. Enable debug logging for the user-manager component:
  • GUI:
      • Go to SYSTEM SETTINGS → Log Settings
      • Click 'Show' Software Component Log Levels
    • Set Debug for user-manager
  • CLI:
  • config
  • system logging sw-components sw-component user-manager config severity DEBUG
    • commit
  1. Restart the user-manager service:
  • Run the following command:
  • docker container restart system_user_manager
  • or
    • docker restart system_user_manager
  1. Verify service status (optional):
  • Confirm ConfD callpoints are properly registered:
    • docker exec system_manager confd --status | grep userman
  1. Test user creation and password setting:
    • Attempt to create a new local user and set the password via GUI or CLI.
  1. If the issue persists:
    • Collect debug logs and a new qkview for further analysis.

5. Additional Information

  • Enabling debug logging and restarting the user-manager service does not impact LDAP users or their authentication.
  • The issue was not reproducible in lab environments with the same configuration, indicating an environment-specific or service state problem.
