Description

SSL Handshake fails when ECDSA cipher is agreed on between client and BIG-IP. The connection is reset before the SSL Handshake generating an SSL fatal alert. You can see the following log on /var/log/ltm:

warning tmm1[<PID>]: 01260009:4: Connection error: ssl_select_suite:8192: no shared ciphers (40)

Environment

  • ECDSA ciphers are offered in the client SSL profile
  • RSA certificate and key are configured in the client SSL profile

Cause

If an ECDSA cipher is agreed upon between the F5 and a client but we have no ECDSA certificate and key to offer then the BIG-IP will terminate the SSL handshake with a fatal alert.

Recommended Actions

If you want to use ECDSA ciphers you need to add ECDSA certificate and matching key to the relevant SSL profile.

Alternatively you can:

  • Review the Client Hello for the failing request and modify F5 ciphers to include a non-ECDSA cipher that matches the client.
  • Require the client to offer non-ECDSA ciphers and include a cipher that matches your current cipher string on the F5 client SSL profile.
