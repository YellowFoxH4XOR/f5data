Description

Configuring HTTP Strict Transport Security (HSTS) on an LTM virtual server. You should consider using this procedure under the following conditions:

  • You want to protect against HTTP downgrade attacks (SSL stripping attacks) by requiring all traffic to use HTTPS.
  • You want to protect against mixed content on your website. HSTS automatically upgrades fetches to HTTPS in situations where a domain has mixed content.

You can configure the BIG-IP system to insert an HTTP Response 'Strict-Transport-Security' response header to enforce HTTP Strict Transport Security. You can create a custom HTTP Profile with HTTP Strict Transport Security enabled.

Environment

  • The virtual server in question must have a Client SSL Profile applied.

Cause

None

Recommended Actions

Configure HSTS using the BIG-IP Configuration utility

To watch a video demo of this procedure, go to Configure HSTS on a BIG-IP system virtual server using the Configuration utility.

The following procedure allows you to enable HSTS. 

Impact of procedure : Performing the following procedure will force HSTS-compatible clients to request only HTTPS pages from your website. If your site requires non-HTTPS content to be served, some resources may become unavailable.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. For Services, select HTTP.
  4. Select Create.
  5. Enter the name for the HTTP profile.
  6. In the HTTP Strict Transport Security section, select the Enabled check box for Mode to enable HSTS.
  7. Optional: Change the value of Maximum Age to a value you want. (Default: 16070400).
  8. Optional: Deselect the Enabled check box for Include Subdomains to not include includeSubDomains in the Strict-Transport-Security HTTP Response Header.
  9. Optional: Select the Enabled check box for Preload to include ; preload in the Strict-Transport-Security HTTP Response Header.
  10. Select Finished.
  11. Associate the HTTP profile with the virtual server.
