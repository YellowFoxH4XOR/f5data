K54416090: Tenant will not start after upgrade from 1.3 to 1.5 of controllers in VELOS Chassis

Type
Support Solution
Published
2022-10-05
Updated
2023-03-23
Applies to
  • F5OS
Source
https://my.f5.com/manage/s/article/K54416090

Description
After upgrading system controllers from version 1.3.1 to 1.5.0 tenant will not start.
Tenant details on the partition flips between: 'Allocating resources to tenant is in progress' and 'Error starting VirtualMachine the server is currently unable to handle the request'
After upgrading to 1.5.0 controller-manager is in CrashLoopBackOff state and Tenant is not running.

Environment

  • F5OS-C
  • Upgrade
  • Allocating resources to tenant is in progress
  • Error starting VirtualMachine the server is currently unable to handle the request

Cause
BugID 1154089

Recommended Actions

Note : All steps below are required. 

Delete all the kubevirt pods that are in the Unknown state.
1.  oc get pods -n kubevirt | grep -i unknown
Important : for following step 2 , you need to do this for each pod in a separate linux shell since the delete will hang.
2.  oc delete pod <pod-name> -n kubevirt  

Modify kubevirt install script
1.  cd /usr/share/omd/kubevirt/
2.  cp omd-kubevirt-velos-install.sh /tmp
3.  cd /tmp
4.  vi omd-kubevirt-velos-install.sh
5.  On or about line 128 of that script look for this line -->  kubepods=$(oc get pods -n kubevirt | grep -c virt-)
6.  Right after that line insert this line  -->   kubepods=0
7.  On or about line 272 of that script look for this line -->  kubepods=$(oc get pods -n kubevirt | grep -c virt-)
8.  Right after that line insert this line  -->   kubepods=0
9.  Save and exit the file

Rerun the kubevirt install script
1.  /tmp/omd-kubevirt-velos-install.sh /usr/share/omd/kubevirt/

Check kubevirt pods status  - they should all be in the running state.
1.  oc get pods -n kubevirt
