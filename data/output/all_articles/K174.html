Topic

To configure BIG-IP to resolve its own host name and the name of the next-hop mail relay locally (without using DNS) perform the following procedure:
 
  1. Using a text editor, open the /config/sendmail.cf file and find the line that begins with # "Smart".

    For example:

    Note: Your sendmail file may be named /config/sendmail.cf.off. If this is the case, rename it by typing: mv /config/sendmail.cf.off /config/sendmail.cf

    # "Smart" relay host (may be null)
    DS

  2. Immediately after the DS, add the DNS name of your mail server. The file section should now appear similar to the following example: 
    # "Smart" relay host (may be null)
DSmail.mycompany.com
  3. Find the following line:

    O ServiceSwitchFile=/etc/mail/service.switch

    Verify that it is uncommented (is not preceded by the # character). If it is preceded by the # character, remove it.

  4. Save the sendmail.cf file.
  5. Exit the text editor.
  6. Create an /etc/mail/service.switch file, by typing the following command:

    echo "hosts files" > /etc/mail/service.switch

  7. Open the BIG-IP's /etc/hosts file in a text editor.
  8. Add the IP address and name of the mail server (that you defined it in Step 2) to the /etc/hosts file using the following format: 
    # Local name
192.168.103.186 bigip1.mycompany.com
# My mail server
192.168.10.50     mail.mycompany.com

Testing the configuration

To test the configuration, perform the following procedure:

  1. Send an email to yourself, by using the following command syntax: 
    mail <your_email_address>

    For example:

    mail me@myco.com
  2. Press Enter.

    This step will return you to a blank line, which is the body of the email.

  3. Enter a few words or lines of text.
  4. At the beginning of a blank line, press the CTRL+D keys. The email should appear similar to the following example:

    bigip1:/config# mail me@myco.com This is a test email. This is the body of the email. EOT

     

    The EOT designates the end of the email and is triggered when the CTRL+D keys are pressed. At this point, the mail process will attempt to send the message using the sendmail configuration.

  5. View the /var/log/maillog file. If the email is successful, you should receive a message that appears similar to the following example:

    Dec 17 11:51:36 bigip1 sendmail[27278]: LAA27276: to=me@myco.com, ctladdr=root (0/0), delay=00:00:00, xdelay=00:00:00, mailer=relay, relay=mail.mycompany.com [192.168.10.50], stat=Sent (2.6.0 <200312171951.LAA27276@bigip1.mycompany.com> Queued mail for delivery)

    The stat=Sent line indicates that the email was transferred successfully to the relayhost (for this example, 192.168.10.50).

  6. If you do not receive the email, verify that the relayhost you specified is reachable from BIG-IP on port 25, by testing with the telnet utility as follows:

    telnet <relayhost> 25

  7. If you can connect, type the following command: 
    HELO

    The command output should appear similar to the following example:

    bip-sol2926:~# telnet mail.mycompany.com 25
Trying 192.168.10.50...
Connected to mail.mycompany.com.
Escape character is '^]'.
220 mail.mycompany.com Microsoft ESMTP MAIL Service, 
Version: 5.0.2195.5329 ready at  Wed, 17 Dec 2003 18:25:18 -0800 
HELO
250 mail.mycompany.com Hello [192.168.103.186]

    Some mail servers are configured to deny such mail as a security precaution. If telnet works, but your emails fail, confirm that the email server will accept relayed mail for sending, which is beyond the scope of this solution.
