Known Issue

Changing the Limit Type setting for the OneConnect profile may cause the Traffic Management Microkernel (TMM) to produce a core file.

This issue occurs when the following condition is met:

  • The virtual server references a OneConnect profile in which the Limit Type setting was changed from the default value of None to Idle or Strict.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/tmm file, the system generates a stack trace and logs a panic message that appears similar to the following example:

    notice panic: ../modules/hudfilter/hudfilter.c:1303: Assertion "valid target" failed.

  • If configured for HA, the BIG-IP system fails over to the standby system.

Workaround

To work around this issue, you can modify the OneConnect profile and set the Limit Type setting back to the default value of None.

Impact of workaround: The BIG-IP system will no longer limit the type of connections that are eligible for reuse.
