Description

You have a Virtual Server configured with Source Address Affinity Persistence Profile. The Persistence Profile has the option match-across-services enabled.

Sometimes when the same client makes a subsequent connection to the Virtual Server, you notice it is load balanced to a different pool member. This second connection is handled by a different tmm.

The issue causes an error in the user experience, such as not being able to find a recently uploaded file to pool member 1, when subsequent connection is load balanced to pool member 2.

Environment

  • Virtual Server with Source Address Persistence Profile
  • Persistence Profile has the option match-across-services enabled

Cause

Unknown at the time of publication.

Recommended Actions

Disable the option match-across-services from the source address persistence profile.

Note: Only disable the above option, provided it is not required in your configuration. Normally this is used when one of these conditions apply:

  • Configurations that have multiple virtual servers with the same IP address but have different services specified
  • Configurations that have pool members sharing the same address but have different services specified

Additional Information

You can save the persistence records to a file by using a similar script:

while true;do echo -e $(date)"\n\r" >> /var/tmp/persist.txt;tmsh show ltm persistence persist-records client-addr 10.0.0.1 all-properties >> /var/tmp/persist.txt;echo -e "-----------------------------------------\n\r" >> /var/tmp/persist.txt; sleep 10; done
