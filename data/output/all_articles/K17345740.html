Known Issue

The BIG-IP system may delete monitor instances after an incremental configuration synchronization (ConfigSync).

This issue occurs when all of the following conditions are met:

  • You have either enabled, disabled, or forced offline a pool member within a pool or the parent node of a pool member.
  • The modified pool has a health monitor enabled.
  • You synchronize the state change to the device group peers using incremental ConfigSync.

Impact

Not all device group members monitor the same pool members after an incremental ConfigSync. The ConfigSync operation may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The ConfigSync operation fails and reports an error message that appears similar to the following example:

    'Caught configuration exception (0), Invalid monitor rule instance identifier: [id]'

  • The list in Local Traffic > Monitors > <monitor_name> > Instances of the Configuration utility is not in sync among the device group members.
  • The output of the tmsh show ltm monitor <monitor_type> <monitor_name> command is not in sync among the device group members.

Workaround

To work around this issue, you can temporarily enable full ConfigSync before synchronizing a pool member or node state change. Alternatively, you can reload the configuration of the device that received the pool member or node state change after an incremental ConfigSync. To do so, perform one of the following procedures:

  • Temporarily enabling full ConfigSync before synchronizing a pool member or node state change
  • Reloading the configuration of the device that received the pool member or node state change after an incremental ConfigSync

Temporarily enabling full ConfigSync before synchronizing a pool member or node state change

Impact of workaround: Performing the following procedure should not have a negative impact on the system that is initiating the ConfigSync. However, the full ConfigSync will cause a configuration reload on the devices receiving the ConfigSync.

  1. Log in to the Configuration utility of the BIG-IP system that will be initiating the ConfigSync.
  2. Navigate to Device Management > Device Groups.
  3. Click the device group you plan to sync.
  4. In the device group configuration screen, select the Full Sync check box.
  5. Click Update.
  6. Navigate to Device Management > Overview.
  7. Select the device group you plan to sync.
  8. Select the self device.
  9. Select Sync Device to Group.
  10. Click Sync.
  11. Repeat steps 2 and 3, and then clear the Full Sync box to undo the change made in step 4.
  12. Click Update.

Reloading the configuration of the device that received the pool member or node state change after an incremental ConfigSync

Impact of workaround: Performing a configuration reload on an Active device group member, or pushing a ConfigSync to an Active device group member can potentially disrupt the service of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Traffic Management Shell (tmsh) of the device that received the pool member or node state change ConfigSync by typing the following command:

    tmsh

  2. To reload the configuration, type the following command:

    load /sys config

  3. To verify that monitor instances have loaded, type the following command:

    show /ltm monitor <monitor_type> <monitor_name>

    For example:

    show /ltm monitor http http

  4. Log in to the Configuration utility of the BIG-IP system that initiated the pool member or node state change ConfigSync.
  5. Navigate to Device Management > Overview.
  6. Select the device group you plan to sync
  7. Select the self device.
  8. Select Sync Device to Group.
  9. Select the Overwrite Configuration check box.

    Note: Since the configuration reload that you performed in step 2 updated the commit ID time of the affected device, you must select the Overwrite Configuration check box to once again sync in the same direction.

  10. Click Sync.
