Description

Client connections are being discarded and LTM logs contains entries similar to the following one:

RST sent from 200.1.12.12:443 to 198.50.100.0:50355, [0x2b7eb63:2468] No flow found for ACK.

Note: The logging of the TCP RST segments should be enabled in order for the previously mentioned message to appear in the LTM logs.

Environment

  • Virtual server Resets
  • iRules

Cause

The "No flow found for ACK" message can be generated for a variety of reasons. One of them is the usage of the drop command on an iRule which is applied on the respective virtual server.

The drop command will cause the current packet or connection to be discarded.

Below you will find an example iRule which permits only connections from the following two ip addresses 192.0.2.13 and 192.0.2.14

when CLIENT_ACCEPTED {
  if { not ([IP::addr [IP::client_addr] equals 192.0.2.13] or [IP::addr [IP::client_addr] equals 192.0.2.14]) } {
  drop
  }
}

Any other connection will be discarded and if the logging of the TCP RST segments is enabled, the RST log message will show in the LTM logs.

Recommended Actions

Verify if the respective virtual server is using an iRule with a drop command. If yes, then remove this iRule or change the iRule logic accordingly.

Additional Information

You might also note on a packet capture that the RST comes right after a Client Hello, if the drop command is on a CLIENT_ACCEPTED event on the irule. And the Flow ID for the Client Hello will show as "Flow ID: 0x0000000000000000", for example:
