Description

BIG-IP APM as SAML SP session variables session.saml.last.identity and session.saml.last.nameIDValue can contain the same value from the same source however this may not be true all use cases. Both variables are populated with values obtained by APM from an IdP Response/Assertion. One of them is mutable while the other is not:

  1. Session variable session.saml.last.identity will associate with one of two values depending on how the Assertion Settings>Identity Location attribute found in the IdP connector object is configured:
  • When the IdP connector settings' Identity Location attribute is set to Subject (default), session variable session.saml.last.identity will associate with the value of the NameID attribute of the Subject within the received IdP Response/Assertion:
         <saml2:Subject>
              <saml2:NameID...>**value**</saml2:NameID>
              ...
         </saml2:Subject>
     
  • When the IdP connector settings' Identity Location attribute is set to Attribute, session variable session.saml.last.identity will associate with the **value** of the named attribute found in the Attribute Statement within the received IdP response/assertion:
         <saml2:AttributeStatement>
              <saml2:Attribute...>
                   <saml2:AttributeValue...>**value**</saml2:AttributeValue>
              </saml2:Attribute>
         </saml2:AttributeStatement>
  1. Session variable session.saml.last.nameIDValue will always associate with the value of the NameID attribute of the Subject within the received IdP Response/Assertion (see AttributeStatement response/assertion snippet above).

Environment

  • BIG-IP Access Policy Manager (APM) as SAML Service Provider.
  • Requirement of implementing Access Policy logic based on the value of either of the reported session variables

Functioning as designed
