Description

Request are blocked with "Cookie not RFC-compliant" violation, last space between the values of Cookies header value identified as not RFC Compliant.

Example:

Cookie received in the client request:

cookie: param1=value1; param2="{\"sord\":\"desc\",\"page\":\"0\",\"nd\":\"1617864648351\",\"sidx\":\"l.VERSION_NO\",\"rows\":\"10\"}"; param3=value3; param4=value4

Detected Violation:

  • Cookie not RFC-compliant: Invalid character after cookie value
  • Cookie Buffer: value3;0x20param4=

The observed behaviour is due to the presence of param2 (in this example), which contains double quote (") in the value itself. This results in adverse effects like invalid parsing and cookie truncation. 

Environment

  • BIG-IP ASM
  • Cookie not RFC-compliant : Invalid character after cookie value (0x20)

Cause

Related to ID1014973

Recommended Actions

As part of the fix to ID1014973 a new db variable is introduced, however this is disabled by default. Please perform below actions to enable it.

 

1.Log in to the CLI BASH and execute the below command.

/usr/share/ts/bin/add_del_internal add include_double_quotes_in_cookie_value 1

 

2. Restart asm

bigstart restart asm

 

3. Verify the variable value correctly changed from BIG-IP UI by navigating to Security ›› Options : Application Security : Advanced Configuration : System Variables and looking for this variable.

 

Important: This change will be included in the configuration sync to the peer device. However, you must restart ASM on each device individually. Restarting ASM can trigger a failover, so it's recommended to perform this during a maintenance window.

 

Additional Information

The above variable is only available in ID1014973 fixed versions, please refer the bug tracker article to check the fixed versions. Bug ID 1014973: ASM changed cookie value.
