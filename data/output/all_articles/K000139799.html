Description

No response to SYN request sent by BIG-IP

Environment

  • VIrtual edition (VE/Z100) platform

  • Sys db tm.tcpsegmentationoffload is enabled (default)

  • Sys db tm.tcpudptxchecksum is set to Hardware-enabled (default)

Cause

TCP header checksum calculated incorrectly.

Recommended Actions

Configure sys db tm.tcpudptxchecksum to Software-only.

tmsh modify sys db tm.tcpudptxchecksum value Software-only
tmsh save sys config

Additional Information

  • Wireshark analysis of the packets on ingress, might show as "partially correct" and indicate TCP offload as being the cause.
  • Packets ingress to BIG-IP should have the correct IP and TCP header checksums. See tmctl tables ip-stat and profile_tcp_stat for checksum error counters.
  • Packets egress from BIG-IP should be captured off-the-box. ie: tcpdump on BIG-IP will likely have the wrong IP & TCP header checksums (due to checksum offload).
  • Be aware that with products such as SSLO, SYN packet sent egress from BIG-IP might be emerge as ingress on another vlan.
  • The same issue can be resolved by disabling TCP segmentation offload (TSO) by disabling  sys db tm.tcpsegmentationoffload.
  • Its possible that the same issue is responsible for poor performance through VE platforms (incorrect TCP header checksum in non-SYN packets). ie: first packet is dropped due this issue, the re-transmit is processed by tmm (rather than offloaded to the NIC (network interface card).
