Known Issue

The Enterprise Manager does not properly log the IP address when receiving device update requests from unknown devices. This issue occurs when all of the following conditions are met:

  • The Enterprise Manager manages a BIG-IP device which becomes unreachable
  • A user removed the BIG-IP device from the managed device list
  • The BIG-IP device then sends an update request to the Enterprise Manager either due to configuration changes or a reboot

Impact

Users cannot identify the formerly managed device in the Enterprise Manager logs. Otherwise, there is no functional impact even though the error message may suggest otherwise.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Enterprise Manager logs error messages to the /var/log/em file. The error messages appear similar to the following example:

    0402010f:3: EX! Daemon.cpp:917::handleClientRequest:f5em::DaemonException Error while processing client request 'Received event notification message from unknown device  (uid: 16).  Ignoring. == (f5em::DaemonException) Stack trace: [ 1: /usr/lib/libf5util.so [0xf7dfa27b]; 2: /usr/lib/libf5util.so(TraceableException::TraceableException()+0x47); 3: /usr/bin/emdeviced(f5em::EMException::EMException(std::string const&)+0x1e); 4: /usr/bin/emdeviced(f5em::DaemonException::DaemonException(f5em::Response::Code, std::string const&, std::string const&, bool)+0x48); 5: /usr/bin/emdeviced [0x812b405]; 6: /usr/lib/libem.so(f5em::Daemon::processClientRequest(std::string const&, f5em::Dictionary const&, f5em::Dictionary&)+0x3f2); 7: /usr/lib/libem.so(f5em::Daemon::handleClientRequest(int)+0x1673); 8: /usr/lib/libem.so(ClientHandler::run()+0x126); 9: /usr/lib/libf5util.so(f5util::Thread::threadStartup(void*)+0x3c); 10: /lib/libpthread.so.0 [0xf7c0f61b]; 11: /lib/libc.so.6(clone+0x5e) ]'

Workaround

None. However, you may prevent the unknown device from contacting the Enterprise Manager. To do so, perform the following procedures:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Identifying the offending BIG-IP device from the Enterprise Manager

  1. Log in to the command line of the Enterprise Manager.
  2. Perform a tcpdump and wait for the offending BIG-IP device to send an update again by typing the following command:

    tcpdump -n -v dst <EM mgmt IP address> and port 443 and 'tcp[tcpflags] & (tcp-rst) != 0'

  3. Press CTRL+C when you have captured the request from the offending BIG-IP device.
  4. Review tcpdump capture and note the IP address of the offending BIG-IP device.

Modifying the BIG-IP config file on the offending BIG-IP device

  1. Log in to the command line of the offending BIG-IP device.
  2. Backup a copy of the /config/eventd.xml file by entering the following command:

    cp -p /config/eventd.xml /var/tmp/eventd.xml.sol13744

  3. Edit the /config/eventd.xml file using a text editor of your choice.
  4. Locate the configuration stanza between the <consumer> and </consumer> tags.
  5. Remove the stanza including the <consumer> and </consumer> tags.
  6. Save the changes and exit the text editor.
  7. Restart the eventd process by entering the following command:

    bigstart restart eventd
