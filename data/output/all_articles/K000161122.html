K000161122: Resolving Legitimate User Blocks Due to "Zeus" Bot Detection in F5 Distributed Cloud WAF

Type
Support Solution
Published
2026-05-05
Updated
2026-06-12
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000161122

Description

Legitimate users accessing web applications via certain mobile devices may be blocked by F5 Distributed Cloud Web Application Firewall (WAF) due to detection of the "Zeus" bot signature. This occurs when the User-Agent string in HTTP requests contains the term "zeus," which matches a known bot signature, resulting in the request being flagged as malicious and blocked. Error logs show blocks with bot_info indicating "zeus" as the detected bot, and the block reason is "Malicious bot detected" with anomaly "Suspicious HTTP Headers."

Environment

  • Product: F5 Distributed Cloud Web App & API Protection
  • Impacted Service: HTTP Load Balancer
  • User-Agent: Contains "zeus" as part of device codename
  • WAF Policy: Signature-based bot protection enabled
  • Enforcement Mode: Blocking

Cause

Certain mobile devices use "zeus" as an internal device codename, which appears in the User-Agent string. The WAF bot signature database includes a "Zeus" bot signature. As a result, legitimate requests are incorrectly flagged and blocked as malicious.

Answer/Recommended Actions

  1. WAF Exclusion Rule
    • Create a WAF exclusion rule to exclude only the specific "Zeus" bot detection for the affected endpoints.
    • All other WAF protections remain enforced.
    • In the F5 XC Console, use the Action → Create WAF Exclusion Rule directly from the security event log for accuracy.
    • Use the bot signature ID or the bot name "zeus" in the exclusion configuration.
    • Ensure the exclusion rule for "zeus" is ordered first in the exception list.
  2. Trusted Client Rule (Conditional Bypass)
    • If immediate relief is required, create a Trusted Client Rule to bypass WAF checks.
    • This approach will bypass all WAF checks for matched requests, use with caution and scope as narrowly as possible.
  3. Testing and Validation
    • After implementing the rule, test with affected devices to confirm legitimate requests are no longer blocked.
    • Monitor security event logs to ensure no unintended traffic is bypassing WAF protections.
  4. If Exclusion Rule Does Not Work
    • Verify the configuration order of exceptions; the "zeus" exclusion should be first.
    • If the signature ID is not visible, using the bot name "zeus" should be sufficient.

Additional Information

  • The WAF is functioning as designed; the block is due Zeus bot signature matching.
  • WAF exclusion rules are lower risk as they only exclude the specific detection, while Trusted Client Rules bypass all WAF checks for matched requests.
  • Signature-based bot detections (like "zeus") are of low accuracy.
  • If using Trusted Client Rules, ensure the match conditions are as specific as possible to minimize risk.
