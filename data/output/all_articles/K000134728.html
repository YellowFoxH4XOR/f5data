K000134728: Server side connection not initiated with Verified Accept enabled in TCP profile

Type
Support Solution
Published
2023-05-22
Updated
2023-05-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000134728

Description

With Verified Accept enabled on TCP profile, LTM needs to initiate a connection with SYN packet to the server side validating the server is ready and able to receive connections. These SYN to the server side connection are maintained in cache on the LTM until answered by the server.

 

Note: Enabling Verified Accept is validation that a monitor is working and correctly marking a pool member up. F5 does not recommend this configuration, because of increased memory usage and increased latency of the connection.

 

Environment

  • Verified Accept enabled in TCP profile

Cause

LTM has cache of SYN packets to server side connections. Functions as designed.

 

Recommended Actions

Increase the amount of sys db connections.preestablished.threshold, doubling the number until the problem goes away. However, if the backend pool members are overloaded and cannot handle the traffic, altering this variable might not have any effect.

 

  1. On the CLI(command line interface) review current cache threshold
    1. tmsh list sys db connections.preestablished.threshold
    2. 8096 is the default setting for this value
  2. Alter the cache threshold
    1. tmsh modify sys db connections.preestablished.threshold value <double of current value>
