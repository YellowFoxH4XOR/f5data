Description

Attempts to generate a UCS backup or save the configuration via the BIG-IP GUI or CLI may fail with an error similar to:

Unexpected Error: Can't add value (01800) to container, it should have been validated by a ParseNode, name (unlock_time) tag (63720)

Error during config save. Unexpected Error: UCS saving process failed.

This error may also appear with other values such as "09600" and different tags, but follows the same pattern. The name, such as unlock_time, is typically part of a DB variable name, here password.unlock_time. The value is the value of this DB variable.

Environment

  • Product: BIG-IP
  • Configuration context: System > Users > Authentication settings, particularly the "User lockout: Automatically enable locked-out users after" field (password.unlock_time DB variable).
  • Triggered when entering numeric values with a leading zero followed by other digits with at least one '8' or '9' (e.g., "01800") in certain password policy fields.

Cause

The system interprets numeric values with a leading zero as octal numbers. Octal numbers cannot contain digits '8' or '9', so entering such values for password-related DB variables (like password.unlock_time) results in a parsing failure and prevents configuration saves and UCS backup generation.

Recommended Actions

  • Do not use leading zeros in numeric fields within password policy settings, especially for fields like "User lockout: Automatically enable locked-out users after" (password.unlock_time).
  • If this error occurs, review and update any affected DB variable to remove leading zeros from its value (for example, change "01800" to "1800").
  • After correcting the value(s), retry saving the configuration or generating the UCS backup.
  • This issue is tracked under software Bug ID 1971941; monitor release notes for future updates addressing this behavior.
  • For similar errors in other fields, check for and remove any leading zeros from numeric entries.
