Description

The /usr filesystem has almost no free space

Environment

  • BIG-IP
  • i7000 and i5000 series
  • /usr disk space close to 99% full

Cause

The /usr partition is created upon installation for system files and it is mounted as read-only. The amount of free space should not change during normal operation.

#df -h
Filesystem                             Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-set.5.root     427M   89M  316M  22% /
devtmpfs                                48G  4.0K   48G   1% /dev
tmpfs                                   48G  2.6M   48G   1% /dev/shm
tmpfs                                   48G  4.1M   48G   1% /run
tmpfs                                   48G     0   48G   0% /sys/fs/cgroup
/dev/mapper/vg--db--sda-set.5._usr     5.3G  4.9G  124M  98% /usr   --> 4.9G utilization is expected.

This is tracked under the BUG ID 1046093.

Recommended Actions

You do not need to monitor /usr disk space utilization from their SNMP station.

If there is an issue as such need to install additional package installation failure due to /usr low available disk space, then you can do a work around as below:

Extending: /usr filesystem:

1. Login to the SSH of the device and then run the command  vgdisplay

 # vgdisplay
  --- Volume group ---
  VG Name               vg-db-sda
...
  Alloc PE / Size       32277 / 126.08 GiB
  Free  PE / Size       4276 / 16.70 GiB

That shows my system's volume group has 16.7gb free that can be used for creating new volumes or extending existing volumes.

2. Now run the command without quotes "mount -o remount,rw /usr"

 # mount -o remount,rw /usr

3. Run the command without quotes "df -h /usr"

# df -h /usr
Filesystem                          Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-set.4._usr  5.0G  4.0G  717M  85% /usr

4. Increase the filesystem size by 500Mb as per the example below:

# lvextend --resizefs -L +500M /dev/mapper/vg--db--sda-set.4._usr

5. Remount the /usr as read only.

# mount -o remount,ro /usr
