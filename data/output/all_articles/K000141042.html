K000141042: Using use_fqdn(no) in syslog configuration still includes the hostname/FQDN in the logs.

Type
Support Solution
Published
2024-09-12
Updated
2025-02-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.0.0, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.X, 16.0.1, 16.X.X, 16.1.X, 17.X.X, 17.1.X, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000141042

Description

You are experiencing issues with the syslog-ng on various BIG-IP releases where the logs still contain fully qualified domain names (FQDNs) despite using the use_fqdn(no) option. This has been identified as a bug and is documented here: Bug Tracker ID 998649. As a workaround, you can add a rewrite filter to remove the domain name from the logs.

Environment

  • BIG-IP systems

  • syslog-ng configuration

  • use_fqdn(no) option in syslog

  • Remote syslog setup

Cause

The underlying issue is a bug in syslog-ng on certain BIG-IP releases that causes fully qualified domain names (FQDNs) to appear in the logs even when the use_fqdn(no) option is specified.

Recommended Action

To address this issue, you can implement a workaround by adding a rewrite filter to remove the domain name. Follow these steps:

  1. Log in to the BIG-IP system.
  2. Run the command

    tmsh

  3. Edit the syslog configuration by running edit sys syslog
  4. Enter the following configuration: 
    sys syslog {
    include "
    # short hostnames
    options {
        keep_hostname(no);
        use_fqdn(no);
    };
    # F5 use-fqdn is broken in
    # https://cdn.f5.com/product/bugtracker/ID998649.html
    # so replace '\\.*' with ''
    rewrite r_domain {
        subst(\"\\\\..*\", \"\", value(\"HOST\"));
    };
    destination d_remote_loghost {
        # put your syslog IP here in place of the 0.0.0.0
    syslog(0.0.0.0 port(514));
    };
    log {
        source(s_syslog_pipe);
        rewrite(r_domain);
        destination(d_remote_loghost);
    };
    "
}

Additional Information

Note: This workaround does not produce RFC5424 compliant output. For instance, system output includes a priority field following the hostname, which is not part of the RFC5424 specification.
