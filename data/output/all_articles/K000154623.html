K000154623: Malformed packet when dns.udptruncate is enabled

Type
Support Solution
Published
2025-09-05
Updated
2025-09-05
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.1
Source
https://my.f5.com/manage/s/article/K000154623

Description

When BIG-IP DNS is configured with DNS Express and the database variable dns.udptruncate is enabled, certain UDP DNS responses may be flagged as "Malformed Packet" by network analysis tools. These responses typically have the TC (truncated) flag set and may lack ANSWER, AUTHORITY, and ADDITIONAL sections—even if the packet size does not exceed 512 bytes. This can result in DNS resolution failures or warnings in client applications and monitoring systems.

 

Environment

  • DNS express
  • dns.udptruncate database variable enabled (default)
  • TC (truncated) flag set in DNS response

 

Cause

With dns.udptruncate enabled, if a DNS query does not include the EDNS0 option, BIG-IP DNS Express may truncate UDP responses by setting the TC (truncated) flag and omitting ANSWER, AUTHORITY, and ADDITIONAL sections. While this behavior complies with DNS protocol specifications, some network analysis tools and client implementations expect more data in these packets and therefore flag them as malformed.

 

Recommended Actions

  • Enable DNS Express minimal-responses by setting the dnsexpress.minimalresponse database key to reduce Authority and Additional Records section sizes. Reference: F5 Knowledge Article K41004650: Enable DNS Express minimal-responses for the Authority and Additional Records sections
  • Ensure that all DNS clients support EDNS0 and TCP fallback for large responses to avoid issues with truncated UDP packets.
