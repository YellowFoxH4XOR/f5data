Issue

Error Message

syslog-ng[<pid>]: Suspending write operation because of an I/O error; fd='<fd>', time_reopen= '60'

In this error message, note the following:

  • <pid> is the process ID of the syslog-ng process.
  • <fd> is the File Descriptor for the syslog-ng process.

For example:

syslog-ng[24740]: Suspending write operation because of an I/O error; fd='37', time_reopen= '60'

Message Location

You may encounter this message in the following location:

  • The /var/log/messages file

Description

This message may occur when the following conditions are met:

  • You are using a remote syslog-ng server to log messages and the syslog-ng server, or a device between the BIG-IP system and the server, has responded with an Internet Control Message Protocol (ICMP) destination port unreachable message.
  • You reboot a blade-based platform, such as a VIPRION (in this case the system may log the error message, even though a remote syslog-ng server is not configured).

Impact

The BIG-IP system may not log messages to the remote syslog-ng server. The BIG-IP system may also show an increase in CPU usage by the syslog-ng process.

Recommended Actions

If this message persists, investigate the reasons that the remote syslog-ng server is refusing a connection from the BIG-IP syslog-ng. For more information about troubleshooting remote syslog issues, refer to K86480148: Troubleshooting issues sending logs to a remote syslog server.

To view the current remote syslog-ng server configuration on the BIG-IP system using the Traffic Management Shell (tmsh), perform the following procedure:

Listing the remote syslog-ng server configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To list the configuration of the remote syslog servers, type the following command:

    list /sys syslog remote-servers

    The command output on a BIG-IP system configured with two remote syslog servers appears similar to the following example:

    sys syslog {
        remote-servers {
            mysyslogA {
                host 172.28.31.40
            }
            mysyslogB {
                host 172.28.31.37
                local-ip 172.28.68.42
            }
         }
    }
