Description

The FQDN node DNS query interval when using the Interval = TTL setting is 5 seconds longer than the actual TTL.

Environment

  • BIG-IP LTM
  • 11.6.0 and later
  • FQDN ephemeral nodes configured with Interval = TTL

Cause

When Interval for a FQDN node is set to TTL instead of a specific second value, the BIG-IP determines the interval of the next DNS query based on the received TTL from the current query's A/AAAA record response.

Per design, the BIG-IP adds 5 seconds (the default DNS retransmit timeout value) to the received TTL to determine the next Interval value.
Note: When an NXDOMAIN response is received, the TTL is set to 0.

This is to ensure that new DNS queries are not created faster than old queries are timed out.

Example:

  • FQDN node www.example.com is configured with Interval = TTL
  • BIG-IP performs a query and receives a response containing an A record with a TTL of 25
  • BIG-IP schedules the next query for 30 seconds (25+5=30)
  • 30 seconds later the Interval has elapsed and another query is sent however this time the received record has a TTL of 13
  • BIG-IP then schedules the next query for 18 seconds in the future (13+5=18)

Recommended Actions

If an Interval less than 5 seconds is required, set the interval to a specific second value.
Note: The Interval value must be an integer and therefore the smallest value can be 1, meaning 1 second between each DNS query for the FQDN.
