Issue

You should consider using this procedure under the following condition:

  • You have deployed your BIG-IP Secure Web Gateway (SWG) to filter traffic using the following methods:
     
    • URL Filtering
    • Subscription-based URL Categories 

Symptoms

As a result of an incomplete SWG database download, you may encounter the following symptoms:

  • When you view the categorization of processed traffic, you notice that all traffic matches the Uncategorized category.
  • The BIG-IP SWG is not blocking access to content.

Recommended Actions

The BIG-IP APM SWG uses the ACE, Master, and RTU databases to identify and categorize traffic. By default, the SWG attempts to download and update the Master database once a day and the RTU and ACE databases several times an hour. When the SWG has not completed the initial download and indexing of the databases, and actively processes traffic, the system cannot determine the traffic categories, and all traffic is categorized as Uncategorized.

Procedures

When all processed traffic is listed as Uncategorized, you can use the following troubleshooting steps to determine the root cause:

  • Verify that the ACE, Master, and RSU databases have been successfully downloaded.
  • Verify that the BIG-IP APM system can DNS resolve the database download domain names.
  • Ensure that the BIG-IP APM management interface can route to external networks.

Verify that the ACE, Master, and RSU databases have been successfully downloaded

For the BIG-IP APM SWG system to appropriately categorize processed traffic, you must download and index the ACE, Master, and RSU databases.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Secure Web Gateway > Database Settings.
  3. Set the Download Results > Type of Download to Show All.
  4. Verify that the three databases (Master, RSU and ACE) are present and that the Result section contains a green Success ball icon for each database.
    Note: If all three databases are represented with the Success green ball icon, you do not need to complete the following steps and procedures.
  5. Set Downloads to Enabled (default setting).
  6. Click the Download Now button.
  7. You can monitor the download progress from the command line of the BIG-IP (version 13.0.0 and higher) by viewing the timestamp value for the database files (newest is last) with the following commands:

    During the download process:
    ls -ltrR /appdata/mprov/global/urldb/staging/current/

    After the downloads have completed:
    ls -ltrR /appdata/mprov/global/urldb/rtu
    ls -ltrR /appdata/mprov/global/urldb/master

    Note: It can take 60 minutes or more when you are downloading and indexing the databases, before the databases are ready for categorization.
    Important: If the databases are not present, and you are unable to initiate a download of the databases, proceed to the following procedures.

Back out procedure: None

Verify that the BIG-IP SWG can DNS resolve the database download domain names

The BIG-IP SWG needs to resolve the domain name download.websense.com to download the ACE, Master, and RSU databases.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP SWG device.
  2. To determine if the BIG-IP SWG is able to successfully resolve the download site domain name, type the following command.

    nslookup download.websense.com

    The following shows an example command and successful output:

    nslookup download.websense.com
    Name:   download.websense.com
    Address: 204.15.67.80

  3. If you are unable to resolve the domain name, verify the BIG-IP system DNS configuration.
  4. Log in to the Configuration utility.
  5. Navigate to System > Configuration > Device > DNS.
  6. Verify that the DNS Lookup Server List contains DNS servers that are appropriate for your deployment environment.

Ensure that the BIG-IP SWG management interface can route to external networks

The BIG-IP SWG will need to access the download server on HTTP port 80.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP SWG device.
  2. Type the following command to verify that the download server is accessible on HTTP port 80.

    curl http://download.websense.com/

    Note: The expected response is HTML code sent from the download server.
