Topic

In BIG-IP 13.1.0.2, F5 introduces the F5 Advanced Web Application Firewall, which includes the DataSafe profile feature. This profile protects data and credentials entered into sensitive fields in your web application by encrypting data at the application layer on the client side. Transport Layer Security (TLS)/SSL protects traffic in transit, while application layer encryption protects users at the browser level, where TLS/SSL terminates. The extra layer of security can defend users from malware tampering and man-in-the-middle (MiTM) attacks.

Description

To use the DataSafe profile you must license the BIG-IP system with the Advanced Web Application Firewall license module and provision Fraud Protection Service. For more information about licensing an add-on license module, refer to K7752: Licensing the BIG-IP system. For more information about resource provisioning, refer to K12111: Provisioning licensed BIG-IP modules.

The DataSafe profile is a class of anti-fraud profile. You can only apply the profile to a virtual server that also has an HTTP profile applied.

The DataSafe profiles are located under Security > Data Protection > DataSafe Profiles. To apply a DataSafe profile to a virtual server navigate to Local Traffic > Virtual Servers > Virtual Server List then click the name of the virtual server and navigate to Security > Policies. On this page you can apply the profile by enabling Anti-Fraud Profile and clicking a DataSafe profile.

Application Layer Encryption

You enable Application Layer Encryption on specific URLs, for example /myapp/login.php and the URL to which the form is submitted. These may be the same URL. For example, the HTML code for /myapp/login.php may appear similar to the following:

<form action="/myapp/login.php" method="POST">
Username : <input type="text" name="username" />
Password : <input type="password" name="password" />

You enable the Inject Main Javascipt setting on the URLs that you want to be protected. You have the option to adjust the Location of Main JavaScript Injection setting on any URL if the DataSafe profile JavaScript interferes with the web application functionality. The setting allows you to pick a tag in the page to inject the JavaScript before or after. The default is before the head end tag (/head).

After you specify URLs, you can add the parameters that DataSafe should protect. Using the previous HTML example these would be username and password. For the POST method, parameters are contained in the request body. For example:

username=user1&password=user1

For the GET method, parameters appear in the query string of the URL. For example:

www.example.com/myapp/login.php?username=user1&password=user1

You can encrypt the values of the parameters as well as substitute them with random values to further defend against malware attacks. You have the choice to identify the parameter as a username and, when you designate a URL as a login page, the system allows alerts to include username information and indicate whether the log-in is successful.

Additionally, when you enable HTML Field Obfuscation, you can obfuscate the parameter name into a random string, and you have the option to remove the ID attribute from HTML elements that you obfuscate. You also have the option to make the profile randomly and continuously generate and remove decoy <input> fields to the web page. Enabling decoy inputs in the profile makes it harder for an attacker to identify sensitive information.

Automatic Transactions

Starting in BIG-IP 16.0.0, the DataSafe profile includes Automatic Transactions detection feature that checks for automated non-human (bot) transactions occurring on a URL or view, as well as removal of Transaction Data cookie. To configure the check for automated bot transactions on a URL or view, you must enable the Automatic Transactions attribute in the Automatic Transactions tab of the URL configuration. This attribute is enabled by default when you create a new URL for the DataSafe profile. To configure the check for Transaction Data cookie removal, you must enable the Check for Security Context Integrity attribute. Similarly, this attribute is also enabled by default when you create a new URL. 

Additionally, the Automatic Transaction detection feature can check if an automated manipulation of data has occurred on URL parameters and AJAX requests. This can be configured by enabling the Check Data Manipulation attribute under the Automatic Transactions section of the Parameter Settings page. This attribute is disabled by default when you create a new parameter and cannot be enabled if the parameter is already enabled with the Substitute Value attribute. If you want to enable the Check Data Manipulation attribute, you must disable the Substitute Value attribute.

When BIG-IP DataSafe detects any of the described activity occurring on the configured URL (and its parameters) or view, it triggers an alert. The system writes the alert to the local syslog facility or any configured log publisher, such as high-speed logging (HSL) facility, when you have not deployed BIG-IP DataSafe as part of BIG-IP ASM/Advanced Web Application Firewall (AWAF). If BIG-IP DataSafe is deployed as part of BIG-IP ASM/AWAF, then the system passes the alerts to BIG-IP ASM/AWAF for mitigation.

Recommendations

When configuring the DataSafe profile, note that it offers many security features, such as Real-Time Encryption, Identify Stolen Credentials, and Full AJAX Encryption, other than those highlighted in this article. Contextual help and online help in the BIG-IP Configuration utility explains what each feature does.
