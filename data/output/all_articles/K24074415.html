Topic

Beginning in BIG-IP 16.0.0 with APM Clients 7.2.1, F5 introduces BIG-IP APM network access VPN support for Datagram Transport Layer Security (DTLS) 1.2 as defined in RFC6347.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Description

Over unreliable networks on which packets may be lost or reordered, using the TLS protocol can result in performance or connection issues with your VPN. In these circumstances, using DTLS, which employs connectionless datagrams, can improve your VPN experience. If you already have a BIG-IP APM network access virtual server on TLS, you can create a DTLS virtual server by referring to K54955814: How to create a DTLS Virtual Server for Network Access VPN. 

To deploy DTLS 1.2, you must have BIG-IP 16.0.0 or later installed and upgrade the APM Clients version on the system to 7.2.1 or later.

Enabling DTLSv1.2 for network access

As an administrator, to enable DTLS 1.2 on your current DTLS 1.0 network access VPN virtual server, perform the following steps:

  1. Upgrade the APM Clients system to 7.2.1 or later: Beginning in BIG-IP 13.1.0, APM Clients administrators can update the Edge Client version on the BIG-IP system without the need to upgrade the entire BIG-IP system. To upgrade the APM Clients version of the BIG-IP system, perform the procedure in K52547540: Updating BIG-IP Edge Client for the BIG-IP APM system.
  2. Upgrade the Edge Client version on user devices: After you upgrade the APM Clients version on the BIG-IP system, you also need to update the Edge Client version on each user device to 7.2.1 or later. To do so, you can configure component update in the connectivity profile. Perform the procedure in K15302: Understanding BIG-IP Edge Client Component Update behavior for Windows, Mac OS, and Linux CLI.

    Note: In BIG-IP Edge Client Linux, you cannot update the clients by configuring component update in the connectivity profile. You need to distribute the Linux Edge Client installer that you can find in the BIG-IP Configuration utility by going to Access > Connectivity / VPN > Connectivity Client Downloads.

  3. Enable DTLS 1.2 in the Client SSL profile of the virtual server: In BIG-IP 16.0.0, DTLS 1.2 is disabled by default in the Client SSL and Server SSL profiles. You need to explicitly enable it in the Client SSL profile associated to the network access VPN virtual server. To do so, refer to the Configuring DTLSv1.2 procedure in K52355764: BIG-IP support for DTLS 1.2

Verifying the network access VPN DTLS version

After you configure DTLS 1.2 on your BIG-IP APM system, you should verify that the network access VPN established is actually using DTLS 1.2. To do so, perform the following as appropriate for your client operating system after your client connects to network access VPN:

Windows and Mac

  1. On your client device, select the BIG-IP Edge Client icon.
  2. Select View Details.
  3. On the Connection Details tab in Windows or the Connection tab in Mac, for Protocol Version, verify the DTLS version. You may observe output similar to the following:

    Protocol/Port: UDP/4433
    Protocol Version: DTLSv1.2

  4. Optional: Verify the BIG-IP Edge Client version on the client device by selecting the Miscellaneous tab. The Version Information section displays the Edge Client version. For more information on BIG-IP Edge Client version with APM Client version, refer to K13757: BIG-IP Edge Client version matrix.

Linux

  1. On your Linux client, to view the DTLS version used to establish the network access VPN, enter the following command:

    f5fpc --info

    You may observe output similar to the following:

    Favorites Extended Info:
    ________________________
    Fav-Id: 418  Fav-Name: /Common/na_na_res
    Tunnel Port:                    4433
    Tunnel Protocol:                UDP
    Tunnel Security Protocol:       DTLSv1.2

  2. (Optional): To verify the BIG-IP Edge Client version on the Linux client, enter the following command:

    f5fpc --version

Troubleshooting

If you are unable to establish DTLS 1.2 network access VPN after performing the steps in this article, you can troubleshoot the issue by performing the following steps.

Verify that the BIG-IP system is configured to support DTLS 1.2. by referring to the VPN log files on the client system. To do so, perform one of the following as appropriate for your client operation system:

Windows

  • Refer to the log file %TEMP%\logterminal.txt. When the BIG-IP system supports DTLS 1.2, you should observe an output similar to the following:

    8976,40812,HOST, 48, , 177, CHostCtrl::Load properties, HostCtrl information: property #49, name="dtls_v1_2_supported", value="1".

Mac

  • Refer to the log file ~/Library/Logs/F5Networks/svpn.log. When the BIG-IP system supports DTLS 1.2, you should observe an output similar to the following:

    svpn, 1, /svpn.cpp, 320, SSLVpn::SetProperties(), dtls_v1_2_supported, 1, 1

Linux

  • Refer to the log file /var/log/svpn.log. When the BIG-IP system supports DTLSv1.2, you should observe an output similar to the following:

    svpn, 1, , 320, SSLVpn::SetProperties(), dtls_v1_2_supported, 1, 1
