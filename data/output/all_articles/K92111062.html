Known Issue

The BIG-IP AFM system may drop IPv4 DNS requests as denial-of-service (DoS) IPv6 atomic fragments.

This issue occurs when all of the following conditions are met:

  • A Virtual Clustered Multiprocessing (vCMP) guest on your BIG-IP system is running a different software version than the host.
  • The BIG-IP AFM module is licensed and provisioned on the guest.
  • Your BIG-IP system is processing DNS requests that exceed the configured rate limit for IPv6 atomic fragments (defaults to 10 KB).

Impact

The BIG-IP system drops packets that may be legitimate, thus reducing throughput.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The throughput for DNS traffic is lower than expected.
  • Your BIG-IP system intermittently drops legitimate DNS requests.

Workaround

To work around this issue, you can increase the detection limit for IPv6 atomic fragments in the BIG-IP AFM system. To do so, perform the following procedure:

Note: BIG-IP AFM DoS protection in the hardware requires both the vCMP guest and the host to run the same software version. If you are running dissimilar versions, you can work around this issue by disabling hardware DoS protection using the tmsh modify /sys db dos.forceswdos value true command.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > Device Configuration > Network Security.
  3. Expand the Fragmentation category.
  4. Click IPv6 Atomic Fragment.
  5. Increase the value for the Rate Limit Threshold PPS setting appropriately for your environment.
  6. Click Update.
