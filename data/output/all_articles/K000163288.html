K000163288: Backend Apache Keep-Alive Timeout Causes Intermittent Page Freezes on BIG-IP LTM

Type
Support Solution
Published
2026-09-10
Updated
2026-09-10
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163288

Description

Web applications behind BIG-IP LTM intermittently freeze after a period of inactivity. Opening the application in a new browser tab restores responsiveness.

  • Packet captures may show the backend closing the connection with a FIN or RST.
  • The customer has configured and attached both persistence and OneConnect profiles.
  • HAR data may show:
    • Server: Apache
    • Connection: Keep-Alive
    • Keep-Alive: timeout=5

Environment

  • BIG-IP LTM
  • Persistence profile
  • OneConnect profile

Cause

The backend Apache servers close idle keep-alive connections after five seconds, while BIG-IP retains server-side connections for up to 300 seconds.

When a user performs the next action after the Apache connection has been closed, BIG-IP attempts to use the stale connection. The closed connection must be detected and replaced with a new connection, which can cause the page to appear frozen.

Recommended Actions

Increase the Apache KeepAliveTimeout on every affected backend pool member to a value greater than the BIG-IP server-side TCP idle timeout.

For a BIG-IP server-side idle timeout of 300 seconds, use:

KeepAliveTimeout 305

After changing the Apache configuration:

  1. Reload or restart the Apache/HTTPD service according to the application team's procedures.
  2. Confirm that all pool members have the same effective keep-alive configuration.
