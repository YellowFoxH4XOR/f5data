Introduction

nPath mode rewrites outbound traffic and directs it to outbound routes, other than those on BIG-IP. This is done by assigning a source address that is the same as the virtual server used on BIG-IP, which requires specific configuration changes to your nodes and BIG-IP.

nPath mode is generally used in the following two scenarios:

  • You want to save bandwidth and route outbound traffic away from BIG-IP.
  • You have an existing outbound route that you do not want to alter by making BIG-IP an alternate default route.

In nPath mode, it appears to the client that the traffic it receives, in response to a request to a virtual server, actually comes from the virtual server. In actuality, the traffic comes directly from the node. This is accomplished by configuring the node to listen on the same address as the virtual server. This configuration can introduce some of the issues, which can be resolved as follows:

  • Bind to a loopback adapter.
  • Create a virtual server with address translation disabled.

Binding to a loopback adapter

Since the virtual server and node cannot both advertise availability of the same address, without causing network issues, you need to bind to the loopback adapter to prevent the node from responding to ARP requests for the address. The loopback adapter is entirely internal to the operating system; it will not advertise any address bound to it.

Creating a virtual server with address translation disabled

To get traffic to a node that does not advertise its address, you must create a virtual server on BIG-IP with address translation disabled. This will allow BIG-IP to forward traffic to the next hop, which is determined by the virtual server choosing from its available nodes, without changing the destination address. The traffic is then forwarded to the selected node still bearing the destination address of the virtual server.

When the traffic arrives at the node, it will check for any address that matches the destination. Since it has this address bound to its loopback adapter, it will send the traffic there. Once the traffic has been properly serviced, the node will send the traffic back to the client using its default gateway and, because the traffic is coming from the loopback adapter with the same address as the virtual server, the requirement for a consistent session is met.

Setting up nPath Mode: Configuring BIG-IP and Virtual Servers

Once defined, you can configure existing virtual servers or new virtual servers to use nPath mode.

Disabling Address Translation

You must disable address translation for the virtual server so the packets arrive at the nodes, specified by the virtual server, still bearing their initial destination address (the address of the virtual server).

From the Command Line

To disable address translation on a VIP from the command line, type the following command, where 10.10.10.10:80 is the address of the VIP you want to modify:

bigpipe virtual 10.10.10.10:80 translate addr disable

From the Configuration utility

To disable address translation on a VIP from the Configuration utility, perform the following steps where 10.10.10.10:80 is the address of the VIP you want to modify:

  1. From the left navigation pane of the Configuration utility, click Virtual Servers.

  2. Click the address of the virtual server you want to modify. For example, 10.10.10.10:80.

  3. On the line beginning with Enable, uncheck the box next to Address.

  4. Click Apply.

Setting TCP and UDP service timeouts

In nPath mode, traffic is not returned through BIG-IP; therefore, connections are never closed. This makes idle connection reaping even more critical than normal. Verify that TCP and UDP service timeouts have been set for each service used by an nPath virtual server.

Depending on traffic load, you may want to set connection timeouts to be very short. For protocols that require long-term connectivity, consider the maximum duration of the sessions. Protocols such as telnet and FTP can be long term, while protocols such as HTTP and DNS will generally be short-lived. For connections that perform keep-alives (such as SSH), timeouts should be only as long as their keep-alive frequency.

From the Command Line

To set connection timeouts for TCP on port 80 and UDP on port 53 from the command line, type the following commands:

bigpipe service 80 tcp enable
bigpipe service 53 udp enable
bigpipe service 80 tcp timeout 10
bigpipe service 53 udp timeout 15

From the Configuration utility

To set connection timeouts for TCP on port 80 and UDP on port 53 from the Configuration utility, perform the following steps:

  1. From the left navigation pane of the Configuration utility, click Virtual Servers.
  2. Click the Virtual Services tab.
  3. Click the virtual service you want to modify. For example, 80.
  4. Verify that the TCP Service check box is checked.
  5. Type in the number of seconds you want for timeout idle connections. For example, 10.
  6. Click Apply.

Binding the Virtual Server Address to the Loopback

Each node behind a virtual server using nPath must bind the virtual server IP address to the node's own loopback adapter, allowing the node to listen for traffic that arrives bearing the same destination IP address as the virtual server without responding to ARP requests for the virtual server address. This allows the BIG-IP only to respond to ARP requests, avoiding multiple conflicting ARP replies for the same IP address.

Binding to the loopback in UNIX

In most cases, you can bind an address to the loopback adapter on UNIX platforms by using the ifconfig command, as follows:

ifconfig <interface> add <ip_address> netmask <mask> broadcast <broadcast>

For example:

ifconfig lo0 add 10.10.10.10 netmask 255.255.255.0 broadcast 10.10.10.255

To confirm the changes, type the following command:

ifconfig lo0

The output would appear as follows:

lo0: flags=8109<UP,LOOPBACK,PROMISC,MULTICAST>
link type loop mtu 1536
inet 127.0.0.1 netmask 255.0.0.0
inet 10.10.10.10 netmask 255.255.255.255

Note: The loopback device is usually named lo or lo0. In some UNIX platforms there may be multiple loopback interfaces; in these cases, always use lo0.

Installing the loopback adapter on Microsoft Windows NT®

In order to use the loopback adapter with Microsoft Windows NT®, you must first install it.

To install a loopback adapter in Microsoft Windows NT®, perform the following steps:

  1. In the Network Control Panel, choose Adapters.
  2. Click Add.
  3. From the list, select MS Loopback Adapter.

You are asked to select from 802.3, 802.5, or FDDI:

  • For Ethernet, select 802.3.
  • For Token Ring, select 802.5.
  • For other, or where appropriate, select FDDI.

Binding to the loopback adapter in Microsoft Windows NT®

To bind to the loopback adapter in Microsoft Windows NT®, perform the following steps:

  1. In the Network Control Panel, select Protocols, TCP/IP.
  2. Select Loopback Adapter from the list of adapters.
  3. Click Advanced options.
  4. Under the IP Addresses box, click Add.

    This will allow you to bind addresses to the loopback adapter.

Configuring the service to listen on the loopback

After you bind the address, you must configure the service (HTTP, HTTPS, telnet, smtp, etc.) to listen on the loopback-bound virtual address. This is the most complex part of the nPath configuration; in most cases you must rely on extended knowledge of your server software in order to accomplish this step. For specific instructions about, refer to the BIG-IP manual.

Cookie Persistence

Most modes of persistence will work fine with nPath. Cookie persistence, however, is a notable exception. When cookie persistence is used, BIG-IP manages the persistence when packets return through the controller as follows. All of these cases require the BIG-IP Controller to read the return packets.

  • In Insert Mode, a cookie is added.
  • In Rewrite Mode, a cookie is modified.
  • In Passive Mode, BIG-IP keeps track of the node on which the cookie originated.

Since traffic is never returned to BIG-IP in nPath Mode, there is no way for cookie persistence to work.

Other Advanced Features

Some other advanced features will also not work when nPath is used. Most notably, all header insertion features, which do not work withnPath because data is inserted into the header as the packet passes through BIG-IP. This causes the sequence numbers to no longer match what the client expects.

It is important to keep in mind when using nPath is that as a general rule BIG-IP cannot modify the in any way packets as the pass through . If the packets are modified in some way, the connection will fail.

For more information about nPath, refer to the BIG-IP Solutions Guide for the version of BIG-IP you are running.
