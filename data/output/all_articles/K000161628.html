Description

Configuration synchronization between two BIG-IP tenants fails with error:

Sync error on <device_name>: Load failed from /Common/<device_name> 01071bae:3: The certificate (/Common/<certificate>) already has another OCSP cert-validator (/Common/<ocsp>) configured.

This occurs during config load on the receiving device, even when both tenants have identical OCSP responder profiles attached to the same SSL certificate.

Environment

  • BIG-IP
  • rSeries
  • Two tenants configured with identical OCSP responder profiles attached to the same SSL certificate
  • Certificate validation options set to OCSP

Cause

This behavior is a design limitation. ConfigSync attempts to apply the new OCSP validator on the standby device without first removing the existing validator.

Answer/Recommended Actions

In order to mitigate this issue, you can perform following steps:

  1. On the standby device, manually remove the validator reference and disable OCSP in affected certificate before syncing:

System  ››  Certificate Management : Traffic Certificate Management : SSL Certificate List  ››  <certificate>

   2. Initiate ConfigSync from the active device.

After sync, the OCSP should be set on standby device too. If not; disable and enable it on the Active device, they should sync without failure.
