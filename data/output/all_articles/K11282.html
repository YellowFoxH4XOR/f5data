Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator Intelligent Browser Referencing (IBR) and MultiConnect features do not properly handle images referenced in form input tags.

If IBR is enabled for a page containing an input form that specifies an input type of image, the BIG-IP WebAccelerator system should assign a pv tag to the image referenced in the form input tag, and populate it within the etag cache. However, only images specified within image tags are assigned a pv tag and cached.

For example, the image named myImage.jpg which is referenced within the following form object is not assigned a pv tag and cached as expected:

<form><input type="image" src="myImage.jpg"></form>

However, the same image referenced within an image tag is assigned a pv tag and cached:

<img src="myImage.jpg">

When is MultiConnect is enabled for a page containing an input form that specifies an input type of image, the BIG-IP WebAccelerator system fails to properly rewrite the URI.

For example, the image named object.png that is referenced within the following form object is not rewritten as expected by the MultiConnect feature:

<form><input type="image" src="/object.png"></form>

Note: The Intelligent Browser Referencing and MultiConnect check boxes may be found on the Acceleration Rules>>Assembly tab.

F5 Product Development is tracking this issue as ID 222510 (formerly CR120534).
