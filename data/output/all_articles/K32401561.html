Known Issue

Deletion of health monitors may fail.

This issue occurs when all of the following conditions are met:

  • You create a custom health monitor on your BIG-IP DNS (formerly known as BIG-IP GTM) or Link Controller system.
  • You configure an existing link to use the custom health monitor.
  • You remove the health monitor from the link configuration.
  • You attempt to delete the custom health monitor.

Impact

Deletion of the custom health monitor fails.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you attempt to delete the custom health monitor, the system displays an error message similar to the following example:

    01070083:3: Monitor /<partition>/<custom health monitor name> is in use.

Workaround

To work around this issue, you can reload the BIG-IP DNS configuration to allow the removal of the unused custom health monitor. To do so, perform the following procedure:

Impact of workaround: This procedure temporarily interrupts processing by the BIG-IP DNS or Link Controller system while the configuration is loading.

  1. Log in to the Traffic Management Shell (tmsh) of the affected system by typing the following command:

    tmsh

  2. Load the configuration by typing the following command:

    load /sys config gtm-only

    Note: This command is the same for all BIG-IP system types (DNS, GTM, or Link Controller).

  3. Remove the custom health monitor using the following command syntax:

    delete /gtm monitor <base monitor> <custom health monitor name>

    Note: <base monitor> is the system monitor that was used (defaults-from) to create the custom health monitor.

    For example:

    delete /gtm monitor gateway-icmp delete_me_monitor

  4. To exit the tmsh utility, type the following command:

    quit
