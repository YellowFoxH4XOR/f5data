K000163525: Tenants unable to deploy after blade reboot when using mgmt-vlans: containers with unready status: [compute]

Published
2026-10-02

Source

Description

Tenants configured to use a mgmt-vlan may fail to deploy after a blade reboot, including after an upgrade.

The show tenants command shows the tenant instances reporting containers with unready status: [compute].

The oc get pods -n partition-<id> command shows the virt-launcher pods for the tenant stuck in ContainerCreating state.

The /var/log/messages on blades in question include many Multus errors similar to the following example:

Multus: [partition-1/virt-launcher-tenant01-2-zfbxn]: error adding container to network "mgmt-conf-tenant01": delegateAdd: error invoking conflistAdd - "mgmt-conf-tenant01": conflistAdd: error in getting result from AddNetworkList: failed to lookup master "team0.57": Link not found

Environment

  • Tenant configured to use mgmt-vlan
  • After VELOS blade reboot

Cause

  • Bug ID 2449101: Rebooting a VELOS blade with deployed tenants using a mgmt-vlan may cause the tenants not to return to Running state

The issue occurs because the orchestration agent fails to re-create the team0 interfaces on the blade for each tenant's management interface to be bound to, for example team0.57.

Recommended Actions

To work around this issue, move affected tenants to Configured running state, then back to Deployed.

At the time of this article's publication, there is no fix for ID2449101 in a released version of F5OS-C, but a fix is available via an Engineering Hotfix if desired.

Additional Information

It is possible only some tenant instances will be affected by this issue, even if all use a mgmt-vlan.
