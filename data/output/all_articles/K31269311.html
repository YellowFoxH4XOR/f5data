Known Issue

The BIG-IP management port may drop egress Ethernet multicast traffic when certain routing techniques are used in the network segment the management port connects to.

This issue occurs when the following condition is met:

  • You have non-standard routing configurations on the BIG-IP management port.

    For example, the BIG-IP default gateway on the management network is a pair of Check Point Secure Gateways configured in Load Sharing Multicast mode.

Impact

As a result of this issue, you may not be able to reach some destinations or services by way of the BIG-IP management port.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The IP address of the default gateway resolves to a Layer 2 (L2) multicast address, and the BIG-IP management port drops traffic destined for the default gateway.

Workaround

To work around this issue, you can disable the Linux multicast snooping feature. The Linux host configures a single-interface bridge over the management port to make some tasks simpler. This issue goes away when multicast snooping is disabled for said bridge. To disable the Linux multicast snooping feature, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system

  1. Log in to the BIG-IP system as the root user.
  2. Type the following command into the command line:

    echo 0 > /sys/class/net/mgmt/bridge/multicast_snooping
