Known Issue

Compression hardware may stop responding and require the Traffic Management Microkernel (TMM) to perform compression functions.

This issue occurs when the following condition is met:

  • Hardware compression is enabled on any of the following:
    • The BIG-IP 5000, 7000, 10000, or 12000 series platforms
    • The VIPRION chassis with B22xx blades

Errors and exceptions encountered by the hardware compression engine are not correctly propagated to compression clients. As a result, a progressive failure of the hardware compression engine causes compression functions to slowly and progressively be performed in software by TMM, causing increased CPU usage.

Impact

Over time, the HTTP compression that should be performed by hardware is instead performed by software, resulting in increased CPU usage.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system's CPU usage increases over time when performing compression.
  • The BIG-IP system experiences performance degradation.
  • Messages similar to the following example are logged to the /var/log/ltm file:

    crit tmm5[PID]: 01010025:2: Device error: n3-compress0 Nitrox 3, Hang Detected

Workaround

To work around this issue, you can disable compression if CPU usage is too high. To do so, perform the following procedure:

Impact of workaround: You may experience higher bandwidth usage from the BIG-IP system to the client. The full impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server for which you want to disable compression.
  4. In the HTTP Compression Profile box, select None.
  5. Click Update.
