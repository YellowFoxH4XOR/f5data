Known Issue

The BIG-IP APM portal access may incorrectly rewrite URLs with CSS-style HTML entities.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a portal access profile.
  • Content processed by the portal access profile includes CSS-style HTML entities.

    Following is an example CSS with an HTML entity:

    <div style="background:url(&#39;image.jpg&#39;)">

Impact

The system incorrectly rewrites the CSS HTML entities.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Content is missing or does not render correctly.

  • Web application functionality is impacted.

  • When you view the CSS HTML entity before the rewrite, it appears similar to the following example:

    <div style="background:url(&#39;image.jpg&#39;)">

  • When you view the CSS content rewritten by the BIG-IP APM portal access rewrite process, the content HTML entity appears similar to the following example:

    <div style="background:url(&#39?F5CH=I;image.jpg&#39;)">

Workaround

To work around this issue, you can create and apply a customized iRule to the affected virtual server that converts the rewritten HTML entities to their original characters. To do so, refer to the following example procedure:

Impact of workaround: F5 recommends that you perform the following procedure in a lab environment before implementing it into a production environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > Create.
  3. In the Name box, type a name for the iRule.
  4. In the Definition box, type the following example text:

    when REWRITE_REQUEST_DONE {
    # HTML entities in inline CSS style attributes may cause incorrect rewriting of URLs
        if { [HTTP::path] ends_with "<url>" } {
            set bug_rewrite1 1
            REWRITE::post_process 1
        } elseif { [info exists bug_rewrite] } {
            unset bug_rewrite
        }
    }
    when REWRITE_RESPONSE_DONE {
        if { [info exists bug_rewrite] } {
            set indices [regexp -all -inline -nocase -indices \
                    {url\(\s*&#39(\?F5CH=I;)/} [REWRITE::payload] ]
            for {set idx [llength $indices]} {[incr idx -1] >= 1} {} {
                set i_start [lindex [lindex $indices $idx] 0]
                set i_len   [lindex [lindex $indices $idx] 1]
                set i_len   [expr {$i_len - $i_start + 1}]
                # remove incorrectly added context hint;
                # Note: Add hex encoded destination resource (http://www.example.com) for absolute-path URLs
                REWRITE::payload replace $i_start $i_len \
                    {;/f5-w-687474703A2F2F7777772E6578616D706C652E636F6DDA$$}
                # skip full match and move to next capturing group
                incr idx -1
            }
            unset -nocomplain indices idx i_start i_len data bug_rewrite
        }
    }

    Note: In this example, the iRule corrects the rewritten HTML entity &#39?F5CH=I;image.jpg&#39; back to the original &#39;image.jpg&#39;.

    Important: You must modify the iRule stanza to use the correct hex encoded host string that appears in the rewrite payload section of the iRule after the f5-w- prefix.

    For example:

    {;/f5-w-687474703A2F2F7777772E6578616D706C652E636F6DDA$$}

    Important: In some deployment instances, you may need to modify the URL rewrite regular expression. For example, when the URL references a full URL path:

    Example full URL path regular expression:

    ({url\(\s*&#39(\?F5CH=I;https:\/\/content.example.com)} [REWRITE::payload] ])

  5. Click Finished.
  6. Click Virtual Servers.
  7. Click the name of the virtual server that is affected by this issue.
  8. Click the Resources tab.
  9. In the iRules section, click Manage.
  10. From the Available column, select the iRule you previously created.
  11. Click the << button.

    The iRule moves to the Enabled column.

  12. Click Finished.
