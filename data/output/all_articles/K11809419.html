Issue

Description

When connecting with a server, the client can ask for confirmation that the information is received by setting the ACK flag. Such requests require the server to do more work than with other types of requests. By flooding a server with spurious ACK requests, an attacker can prevent the server from responding to valid traffic. This technique is called an ACK flood. Since ACK messages are a part of standard traffic flow, a huge flood of these messages alone indicates abuse. You can use a full-proxy architecture to manage every conversation between the client and the server to quickly distinguish and eliminate abuse.

The BIG-IP AFM is built on full-proxy architecture, and it can determine valid traffic flow and drop ACK traffic floods so they never pass to the protected network.

Environment

BIG-IP AFM module is licensed and provisioned.

Cause

TCP ACK Flood traffic is suspected to be hitting the BIG-IP system.

Recommended Actions

Configure the thresholds for TCP BADACK Flood attack type in the BIG-IP AFM DOS Protection device configuration.

  1. Log in to the Configuration utility.
  2. Navigate to Security > DoS Protection > Device Configuration. 
  3. Expand the Flood option list.
  4. Click TCP BADACK Flood.
  5. Under Configuration, modify the values for the following options:
    • Detection Threshold PPS
    • Detection Threshold Percent
    • Rate Limit
      Note: For the BIG-IP AFM DOS protection device configuration, the threshold and rate limit values are applied per-TMM. For more information, refer to K15023: The BIG-IP AFM system enforces configured thresholds and limits for each TMM.

Note: The previous reference configuration is based on a BIG-IP AFM 12.x DOS Protection device configuration. For information about the specific BIG-IP AFM version configuration and locate the F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

For the Detection Threshold PPS value, as a sample possible value, allow an acceptable value to accommodate expected increase of this type of traffic. For example, if the Stats rate value has an average value of 5000 packets per second, there are four TMMs in the BIG-IP AFM being configured, and the Detection Threshold PPS value is set to 8000, this allows the BIG-IP AFM to potentially handle a total of 31996 TCP ACK flood packets before BIG-IP AFM detects the TCP bad ACK flood attack vector. However, if one of the TMMs exceeds the Detection Threshold PPS value of 8000, the BIG-IP AFM detects the TCP ACK flood and generates a log message in the /var/log/ltm file.

Additional Information

  • To learn more about the Flood attacks and the F5 recommended configuration, refer to Flood under BIG-IP AFM DoS vectors in K49869231: BIG-IP AFM operations guide | Chapter 5: Denial of Service.
  • To learn more about the threshold setting for Detect and Rate Limits, refer to Detect and rate limits thresholds under Device DoS in K49869231: BIG-IP AFM operations guide | Chapter 5: Denial of Service.
  • The TCP BADACK Flood attack type in the BIG-IP AFM DoS vector setting is not hardware-accelerated, so the attack vector does not use the ePVA/sPVA. To learn more about the characteristics of the different attack types classified in the BIG-IP AFM DoS vectors, refer to K41305885: BIG-IP AFM DoS vectors.
  • Across the versions of BIG-IP AFM, the TCP BADACK Flood Attack Type parameter is located different locations in the Configuration utility. The following list describes how to navigate to the location of the parameter in different BIG-IP versions:

    Note: TCP ACK Flood changed to TCP BADACK in BIG-IP 11.6.x.

    • In BIG-IP 14.x through 15.x, navigate to Security > DoS Protection > Device Protection > Network, then click Attack Type options and locate TCP BADACK Flood.
    • In BIG-IP 13.x, navigate to Security > DoS Protection > Device Configuration > Network Security, then click Category options for Flood, and locate TCP BADACK Flood.
    • In BIG-IP 11.6.x through 12.x, navigate to Security > DoS Protection > Device Configuration, then click Category options for Flood, and locate TCP BADACK Flood.
    • In BIG-IP 11.5.x, navigate to Security > DoS Protection > Device Configuration, click Category options for Flood, and locate TCP ACK Flood.
  • To locate the possible TCP bad ACK flood attack using /var/log/ltm log messages, messages appear similar to the following examples:

    Apr  1 18:09:33 f5 err tmm[13396]: 01010252:3: A Enforced DOS attack start was detected for vector TCP bad ACK flood, Attack ID 1960737678.
    Apr  1 18:23:24 f5 notice tmm1[13396]: 01010253:5: A Enforced DOS attack has stopped for vector TCP bad ACK flood, Attack ID 1960737678.

    The referenced BIG-IP AFM logs are triggered after the detection threshold is exceeded on receiving the TCP ACK Flood traffic on the BIG-IP self IP.
