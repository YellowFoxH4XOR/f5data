Known Issue

This is the result of a known issue. The Auto Refresh setting can be enabled for Configuration utility pages, such as the Performance graphs or Traffic Summary pages. When Auto Refresh is set, the system automatically updates the statistical information at the interval rate you specify.

If you leave a Configuration utility page open for several hours with Auto Refresh enabled, the tomcat4 process runs out of memory and will eventually crash.

When this issue occurs, you may observe one or more of the following symptoms:

  • The Configuration utility becomes inaccessible, and displays the following error message:

    Major application error, please see logfile
  • Error messages are logged to the /var/log/tomcat4/catalina.out file that appear similar to the following example:

    java.lang.OutOfMemoryError
    java.lang.OutOfMemoryError
    java.lang.OutOfMemoryError
    ERROR: \'null\'
    FATAL ERROR: \'Could not compile stylesheet\'
    javax.xml.transform.TransformerConfigurationException: Could not compile stylesheet
  • Error messages are logged to the /var/log/webui.log file that appear similar to the following example:

    ERROR [Thread-3] util.FeatureFlags:loadFeatureFlags - Exception trying to instantiate feature flag list. java.sql.SQLException: out of memory

F5 Networks Product Development tracked this issue as CR100784 and it was fixed in BIG-IP version 9.4.8 and version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator Release Notes.

Workaround

To work around this issue and restore access to the Configuration utility, restart the tomcat4 process by typing the following command:

bigstart restart tomcat4
