Known Issue

The TMM process may produce a core file and restart when a Classification profile is enabled on a virtual server.

This issue occurs when all of the following conditions are met:

  • A virtual server has the Classification profile enabled
  • The BIG-IP PEM module is not provisioned
  • The virtual server receives a connection

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H425753 on the Diagnostics > Identified > High screen.
  • The BIG-IP system fails over to the standby system, if configured as a high-availability pair.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you can remove the Classification profile from the virtual server. To do so, perform the following procedure:

Impact of workaround: This procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. To remove the Classification profile from the affected virtual server, use the following command syntax, where <virtual-server-name> is the name of the affected virtual server:

    modify ltm virtual <virtual-server-name> profiles delete { classification }

  3. To save the change, type the following command:

    save /sys config
