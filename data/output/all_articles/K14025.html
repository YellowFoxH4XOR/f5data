Known Issue

A VIPRION system may experience a connectivity failure on the management port.

This issue occurs when all of the following conditions are met:

  • The VIPRION system has more than one blade.
  • The management port of all the blades is configured with valid IP addresses.
  • A network route has been added and is within the IP subnet range of the VIPRION system's management port configuration.

As a result of this issue, the mgmt local-net route is not properly added to IP route table 245 when the cluster member IP address is registerd as primary address for eth0.

Impact

  • The VIPRION system's secondary blades may experience connectivity failure to the management IP addresses.
  • For a high-availability (HA) pair VIPRION chassis with full mesh of unicast entries configured, the HA configuration may fail to communicate directly over the management ports. As a result, an undesired active-active condition may cause an interruption to production traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The remote host on the same IP subnet may experience connectivity failure to the management IP addresses of all the secondary blades.
  • For an HA pair VIPRION chassis with full mesh of unicast entries configured, in addition to the symptom stated above, the HA configuration may fail to communicate directly over the management ports. As a result, both VIPRION chassis must be in Active mode.

Workaround

To work around this issue, you can manually add a route for the local network on all blades on a standalone chassis. For an HA pair VIPRION chassis, you can configure a multicast entry or unicast over a dedicated VLAN. To do so, perform the following procedure:

Impact of workaround: For a standalone chassis, a reboot is required on all the blades; therefore, F5 recommends performing this workaround during a maintenance window. For an HA chassis, the HA reconfiguration may cause temporary disruption to the availability of the systems. F5 recommends that you also perform this workaround during a maintenance window.

Standalone VIPRION chassis (11.x)

For a standalone VIPRION chassis 11.x, change the startup script to include a route for the local network on all blades.

  1. Log in to the command line.
  2. Make a copy of the backup for the /etc/rc.local file.

    For example, to back up to the /shared directory with the rc.local-backup filename, you would type the following command:

    cp -a /etc/rc.local /shared/rc.local-backup

  3. Use an editor of your choice to append a line to the /etc/rc.local file. Appending a line creates a management route onto IP route table 245 when the blade boots up.

    For example, the blade's management IP subnet is 10.2.2.0/24, blade/slot 1, and the management IP address is 10.2.2.11.

    The entry of the IP route added on blade/slot 1 will appear as follows:

    ip route add table 245 10.2.2.0/24 dev eth0 scope link src 10.2.2.11

  4. Repeat Step 1 and 2 for the rest of the blades/slots. For the remaining blades in Step 2, you will be required to modify the management IP address according to the respective blade/slot configuration.
  5. Reboot all blades from the primary blade by entering the following command:

    clsh shutdown -r now

Standalone VIPRION chassis (10.x)

For a standalone VIPRION chassis 10.x, configure the user_alert.conf file to include a route for the local network on all blades. Using this method, the system will load the route after a reboot when the syslog utility generates the HA reports tmm ready log message.

  1. Log in to the command line.
  2. Make a copy of the user_alert.conf file.

    For example:

    cp /config/user_alert.conf /config/user_alert.conf.SOL14025

  3. Use a text editor to append the management route to /config/user_alert.conf.

    For example, if management route subnet is 172.28.69.0/24, the stanza would appear as follows:

    alert mgmt_route_workaround "HA reports tmm ready" {
    exec command="ip route show table 245 172.28.69.0/24 | grep 172.28.69 || ip route add table 245 172.28.69.0/24 dev eth0 scope link src $(b mgmt | awk '{print $2}')"
    }

  4. Save the changes and exit the file.
  5. Reboot the system by entering the following command:

    clsh shutdown -r now

HA pair VIPRION chassis

For an HA pair VIPRION chassis, configure a multicast entry for HA setup instead of full mesh unicast on the management port. Alternatively, you can configure unicast on a dedicated failover VLAN. For more information, refer to the following articles:

  • K11939: Configuring network failover for redundant VIPRION systems (10.x)
  • K13915: Configuring network failover for redundant VIPRION systems (11.x)
