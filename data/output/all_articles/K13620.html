Known Issue

The BIG-IP GTM and BIG-IP Link Controller systems may lose wide IP pool members from the wide IP pool configuration. This issue occurs when the following condition is met:

  • You have performed a user configuration set (UCS) archive installation on the affected system while the gtmd process is performing the virtual server auto-discovery task.

This issue occurs because the gtmd process is attempting to auto-discover the virtual servers from the BIG-IP devices (the BIG-IP LTM configuration in the case of BIG-IP Link Controller), while the UCS archive installation is in progress. Depending on the auto-discovery configuration, virtual servers that had previously been correctly discovered may be removed from the BIG-IP GTM configuration. If the virtual servers are removed from the BIG-IP GTM configuration, the gtmd process removes these affected virtual servers from the pools that they are assigned as pool members.

Impact

BIG-IP GTM and BIG-IP Link Controller systems may fail to respond appropriately to queries for the affected wide IP.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Virtual server auto-discovery is enabled for one or more server objects.
  • The BIG-IP GTM and BIG-IP Link Controller systems fail to respond appropriately to queries for the affected wide IP.
  • You notice in the /config/bigip_gtm.conf file (11.x), or the /config/gtm/wideip.conf file (10.x), that the pool assigned to the affected wide IP is missing pool members.

    For example, the following pool configuration includes the 10.10.31.22:80 and 10.10.31.31:80 pool members:

    pool {
    name "www.test.com"
    ttl 30
    preferred rr
    fallback null
    partition "Common"

    member 10.10.31.22:80
    member 10.10.31.31:80
    }

    After this issue occurs, the pool configuration no longer has the two pool members and appears similar to the following example:

    pool {
    name "www.test.com"
    ttl 30
    preferred rr
    fallback null
    partition "Common"
    }

Workaround

If you encounter this issue, you can recover the system by installing the UCS archive again. The issue is unlikely to occur again, and the UCS restore operation should restore the wide IP pools to their previous configuration.

To avoid this issue, you can temporarily shut down the gtmd process on the BIG-IP GTM or BIG-IP Link Controller system before installing the UCS archive and restarting when the UCS archive installation is complete. Alternatively, if you are unable to restart the gtmd process on a production system, you can disable the BIG-IP GTM auto discovery configuration by modifying the UCS archive before proceeding to install the UCS archive. To do so, perform either of the following procedures:

  • Temporarily shutting down the gtmd process, installing the UCS archive, and then restarting the gtmd process
  • Disabling the BIG-IP GTM auto discovery configuration by modifying the UCS archive

Temporarily shutting down the gtmd process, installing the UCS archive, and then restarting the gtmd process

Impact of workaround: The BIG-IP GTM or BIG-IP Link Controller system will not be able to respond to any wide IP queries until the gtmd process is started.

  1. Log in to the command line.
  2. Shut down the gtmd process by typing the following command:

    bigstart stop gtmd

  3. Install the UCS archive on the system.
  4. Start the gtmd process by typing the following command:

    bigstart start gtmd

Disabling the BIG-IP GTM auto discovery configuration by modifying the UCS archive

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

  • Extracting the UCS archive to a temporary directory
  • Modifying the configuration and related files from the UCS archive
  • Repacking the UCS archive
  • Installing the modified UCS archive

Extracting the UCS archive to a temporary directory

  1. Log in to the command line.
  2. Create a temporary directory by typing the following command:

    mkdir /var/tmp/SOL13620

  3. Extract the UCS archive into the temporary directory using the following command syntax:

    tar -zxvf <path/to/UCS archive> -C /var/tmp/SOL13620

    For example, to extract the /var/tmp/myconfig.ucs UCS archive, type the following command:

    tar -zxvf /var/tmp/myconfig.ucs -C /var/tmp/SOL13620

Modifying the configuration and related files from the UCS archive

  1. Edit the following file that applies to your BIG-IP system:

    • BIG-IP 11.x

      Using a text editor, edit the /var/tmp/SOL13620/config/bigip_gtm.conf file.

    • BIG-IP 10.x

      Using a text editor, edit the /var/tmp/SOL13620/config/gtm/wideip.conf file.

  2. Disable the BIG-IP GTM auto discovery configuration by adding the following syntax to the global settings that apply your BIG-IP version:

    • BIG-IP 11.x

      auto-discovery no

      For example, before adding the described syntax to the /var/tmp/SOL13620/config/bigip_gtm.conf file, the general global-settings configuration stanza may appear similar to the following:

      gtm global-settings general {
      synchronization yes
      synchronization-group-name mygtmsyncgrp
      }

      After adding the described syntax, the /var/tmp/SOL13620/config/bigip_gtm.conf file includes the following general global-settings configuration stanza:

      gtm global-settings general {
      auto-discovery no
      synchronization yes
      synchronization-group-name mygtmsyncgrp
      }

    • BIG-IP 10.x

      autoconf no // Default=yes

      For example, before adding the described syntax to the /var/tmp/SOL13620/config/gtm/wideip.conf file, the general global-settings configuration stanza may appear similar to the following:

      globals {
      probe_protocol {
      icmp
      }
      sync_group "mygtmsyncgrp" // Default="default"
      autosync yes // Default=no
      }

      After adding the described syntax, the /var/tmp/SOL13620/config/gtm/wideip.conf file includes the following global settings configuration stanza:

      globals {
      probe_protocol {
      icmp
      }
      sync_group "mygtmsyncgrp" // Default="default"
      autoconf no // Default=yes
      autosync yes // Default=no
      }

  3. Save the changes and exit the text editor.

  4. Generate the md5 checksum of the modified BIG-IP GTM configuration file by typing the command that applies to your BIG-IP version:

    • BIG-IP 11.x

      md5sum /var/tmp/SOL13620/config/bigip_gtm.conf

      In this example, the previous command generates the following output:

      1defe1480dc89a4322b695b6d9284c2a /var/tmp/SOL13620/config/bigip_gtm.conf

    • BIG-IP 10.x

      md5sum /var/tmp/SOL13620/config/gtm/wideip.conf

      In this example, the previous command generates the following output:

      1defe1480dc89a4322b695b6d9284c2a /var/tmp/SOL13620/config/gtm/wideip.conf

  5. Using a text editor, edit the /var/tmp/SOL13620/SPEC-Files file.
  6. Locate the line that contains the BIG-IP GTM configuration file entry. The line appears similar to one of the following examples:
    • BIG-IP 11.x

      N /config/bigip_gtm.conf 5e5595742b7b57a053016b7c65eeb62b 33188 0 0 7729 1320-20089

    • BIG-IP 10.x

      N /config/gtm/wideip.conf 5e5595742b7b57a053016b7c65eeb62b 33188 0 0 7729 1320-20089

  7. Replace the previous md5 checksum with the md5 checksum that you generated in step 4. For this example, the modified line will appear similar to one of the following examples:

    • BIG-IP 11.x

      N /config/bigip_gtm.conf 1defe1480dc89a4322b695b6d9284c2a 33188 0 0 7729 1320-20089

    • BIG-IP 10.x

      N /config/gtm/wideip.conf 1defe1480dc89a4322b695b6d9284c2a 33188 0 0 7729 1320-20089

  8. Save the changes and exit the text editor.

Repacking the UCS archive

  1. Change directories to the /var/tmp/SOL13620 directory by typing the following command:

    cd /var/tmp/SOL13620/

  2. Repack the UCS archive by typing the following command:

    tar -zcvf /var/tmp/modified_myconfig.ucs *

Installing the modified UCS archive

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Install the modified UCS archive /var/tmp/modified_myconfig.ucs file by typing the following command:

    load /sys ucs /var/tmp/modified_myconfig.ucs
