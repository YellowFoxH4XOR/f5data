Known Issue

If an iRule refers to a pool by the full path, the virtual server will not obtain the pool status.

This issue occurs when all of the following conditions are met:

  • A virtual server uses an iRule that refers to a pool by the full path.

    For example:

    if { [HTTP::uri] contains "http1"} {
    pool /Common/pool_http

  • The virtual server has no associated default pool.

Impact

The BIG-IP system continues to send traffic to the pool, regardless of pool status. The BIG-IP system does not remove the virtual server IP address when dynamic routing protocols such as Border Gateway Protocol (BGP) are enabled.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H496791 on the Diagnostics > Identified > Medium screen.
  • The system sends traffic to pool members, regardless of pool status.
  • The system does not remove virtual server IP addresses from dynamic routing protocols when all pools are unavailable.

Workaround

To work around this issue, you can make sure that the iRule refers to the pool member by name only, not by the full path.

For example:

if { [HTTP::uri] contains "http1"} {
pool pool_http
