K000157180: License reactivation or upgrade on standby BIG-IP may trigger loading of old configuration

Type
Support Solution
Published
2025-11-09
Updated
2025-11-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000157180

Description

During a license reactivation and upgrade on a BIG-IP HA pair with device-group auto-sync enabled, the standby device reloads services/reboots, and it may load an outdated configuration from disk and push the old configuration to the device group. This results in the loss of recent configuration changes, causing a service outage, and may require manual recovery.

Environment

  • BIG-IP LTM
  • HA pair with device group configured for auto-sync (sync-failover)

Cause

The root cause is the default behavior of BIG-IP device groups when auto-sync is enabled and save-on-auto-sync is disabled. (This option exists, but it is not visible in Basic mode; you must switch to Advanced to see it.)

With auto-sync enabled but save-on-auto-sync disabled, BIG-IP synchronizes changes to the peer device’s running configuration but does not write them to disk unless the configuration is manually saved or save-on-auto-sync is enabled. If the peer device reloads or reboots without saving its configuration, it loads the last saved (and possibly outdated) configuration from disk and may overwrite newer configurations on the active peer during synchronization.

Important: Enabling the save-on-auto-sync option can unexpectedly impact system performance when the BIG-IP system automatically saves a large configuration change to each device.

Recommended Actions

Before license reactivation or upgrades, disable auto sync and manually save the configuration and create a UCS backup.

tmsh modify /cm device-group <device_group_name> auto-sync disabled
tmsh save sys config
tmsh save sys ucs $(echo $HOSTNAME | cut -d'.' -f1)-$(date +%H%M-%m%d%y)
