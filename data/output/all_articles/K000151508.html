Description

You have configured auto-discovery of JWT token and key in the OAuth provider configuration (Access >> Federation: OAuth Client / Resource Server: Provider). You expect that new keys discovered by the auto-discovery process will be updated on both units in HA since it's an automated process; however, this is not the case in HA pair without having auto-sync configured for the device sync-failover group.

 

  • auto-discovery task is handled by restjavad process and the discovery tasks are running through a rest worker called OIDC Gossip Worker. Gossip Worker synchronizes rest framework related configuration but not the newly discovered JWT keys.  New JWT keys discovered via auto-discovery task will be sync'd to the Standby unit via the device sync process.  If your HA is not configured with auto-sync, the sync status will switch to "Changes Pending" whenever the auto-discovery process runs on the Active unit then finds and downloads a new key:

[root@bigip2:Active:Changes Pending] config # tmsh list apm oauth jwt-config auto_jwt_test_provider

apm oauth jwt-config auto_jwt_test_provider {

    allowed-keys {

        auto_jwk_test_provider1 { }

        auto_jwk_test_provider2 { }

        auto_jwk_test_provider3 { }        <--- A new key discovered and downloaded

    }

    allowed-signing-algorithms { RS256 }

    auto-generated true

    issuer https://accounts.google.com

    jwks-uri https://www.googleapis.com/oauth2/v3/certs

}

 

[root@bigip1:Standby:Changes Pending] config # tmsh list apm oauth jwt-config auto_jwt_test_provider

apm oauth jwt-config auto_jwt_test_provider {

    allowed-keys {

        auto_jwk_test_provider1 { }

        auto_jwk_test_provider2 { }

    }

    allowed-signing-algorithms { RS256 }

    auto-generated true

    issuer https://accounts.google.com

    jwks-uri https://www.googleapis.com/oauth2/v3/certs

}

  • The task itself runs on both Active and Standby units in HA and it can be started on either units by clicking 'Start' (under Access >> Federation: OAuth Client / Resource Server: Provider > click 'Start' under Discovery Task column). 

     
    Note:  If HA is NOT configured with device auto-sync and if you click Start on either units, the sync status will switch to "Changes Pending".  Once you manually sync, the Task Status gets marked "STARTED" on the peer unit (refreshing the browser is required).  If device auto-sync is configured, the Task Status changes to STARTED on both units once you click Start on either units.

  • When clicking your provider under Access > Federation : OAuth Client / Resource Server: Provider, OpenID URI section shows "Last discovery time".  This prints the last time when the Active unit discovered the new key and saved it in the configuration; therefore, it does not get updated every time the task runs at configured interval and it only gets updated when a new key is discovered:

     

(Note:  Both units in HA should show the same Last discovery time)

  • On the other hand, "Last Run Time" under Discovery Task shows the last time that the system ran the discovery task.  This time should get updated at the configured interval.

     

    (Note:  Both units in HA should show the same time when working properly)

    In the example above, the interval is set to 5 (min).  Therefore, the Last Run Time gets updated every 5 minutes.  Also, the Active unit's /var/log/restjavad.0.log should show "we will schedule the next discover after 5 minutes" every 5 minutes when working properly.

Environment

  • BIG-IP APM HA pair
  • OAuth Provider configuration with auto-discovery (Use Auto JWT and Discovery Task)

Cause

N/A

 

Recommended Actions

  • If Standby unit becomes Active (due to a network failover) and does not have the new key, APM policy with OAuth can fail where the APM session log shows "error: None of the configured JWK keys match the received JWT token, JWT Header".  Therefore, F5 recommends to configure auto-sync for device sync-failover group when configuring auto-discovery task for OAuth provider.
  • OAuth can also fail with the same error "None of the configured JWK keys match the received JWT token, JWT Header" when the auto-discovery task itself isn't running properly on the Active unit due to Bug ID 1473701: Oauth Discovery task is struck at "SAVE_AND_APPLY" state.  Please make sure your device runs the version that has a fix for ID 1473701 when using auto-discovery feature.
  • Please note that the discovery task may show 'failed' after a network failover (or even manual failover) due to Bug ID 1750397: The system reached the maximum wait time for gossip worker to sync-oAuth Discovery failure.  In that case, please follow the workaround documented in this bug to fix the failed task.
