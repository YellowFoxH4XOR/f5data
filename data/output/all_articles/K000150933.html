Description

In BIG-IP DNS (GTM) environments, iQuery connections are critical for device synchronization and GSLB operations. These connections rely on mutual SSL authentication using device certificates. A common cause of iQuery connection failure is certificate authentication issues, which can be identified by specific log messages and resolved by following the correct certificate management procedures.

There are two main log messages that indicate authentication failures: , "ssl3_get_server_certificate:certificate verify failed" and "ssl3_get_client_certificate:certificate verify failed".

Apr 20 10:00:18 gtm-a.com iqmgmt_ssl_connect: IP: 10.10.10.1 SSL error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed 

Apr 20 10:12:38 gtm-a.com err big3d[31932]: 012b300e:3: SSL Error: error:14089086:SSL routines:ssl3_get_client_certificate:certificate verify failed on connection to ::ffff:10.10.10.1:51874.

Here are procedures for initiating iQuery connection and when those two logs would appear. Suppose BIGIP_1 (gtmd) initiates a connection to BIGIP_2 (big3d): 

  1. BIGIP_1 sends Client Hello to BIGIP_2, requests the certificate for BIGIP_2.
  2. BIGIP_2 responds Server Hello to BIGIP_1, including its certificate (/config/httpd/conf/ssl.crt/server.crt on BIGIP_2 device) and the Client Certificate Request.
  3. BIGIP_1 receives the certificate for BIGIP_2 and then verify the validation for this certificate (based on /config/gtm/server.crt). If it is validated, the BIGIP_1 sends its certificate (/config/httpd/conf/ssl.crt/server.crt on local device) to BIGIP_2.
  4. After BIGIP_2 receives the client certificate for BIGIP_1, it will verify the validation for this certificate (based on /config/big3d/client.crt).
  5. The iQuery connection is established only if both certificate authentications succeed.

If the authentication fails on step #3, the BIG-IP_1 logs the message "SSL routines:ssl3_get_server_certificate:certificate verify failed".

If the authentication fails on step #4, the BIG-IP_1 logs the message "SSL routines:ssl3_get_client_certificate:certificate verify failed".

Environment

  • BIG-IP DNS
  • iQuery
  • Authentication failure

Cause

Missing or outdated peer device certificates in /config/big3d/client.crt or /config/gtm/server.crt

Recommended Actions

To resolve this issue, use the bigip_add command to exchange certificates with peer devices:bigip_add 10.10.10.1This command updates and synchronizes device certificates among GTM devices in the sync group. Running it once per device is usually sufficient but running it on both devices ensures all certificates are exchanged.

Additional Information

The bigip_add script appends the local BIG-IP DNS system's SSL certificate to the remote BIG-IP system's list of authorized certificates (contained in the /config/big3d/client.crt file). The script then appends the remote BIG-IP system's iQuery SSL certificate to the BIG-IP DNS system's local list of authenticated iQuery SSL certificates (/config/gtm/server.crt).
