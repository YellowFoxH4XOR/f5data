Issue

You should consider using this procedure under the following condition:

  • There may be active security policies that have not been configured on the BIG-IP ASM system.

Symptoms

As a result of unconfigured active security policy, you may encounter the following symptoms:

  • The BIG-IP ASM system does not perform any security checks on the affected virtual server.
  • The affected security policy has its name changed to Configure Security Policy on the Security Policy page of the ASM Configuration utility.
  • The BIG-IP ASM Configuration utility reports a message similar to the following examples on the Policy Properties page:

    BIG-IP ASM 11.2.0 and later

    The security policy application language is not defined

    BIG-IP ASM 11.1.0

    The security policy language is not defined

    BIG-IP ASM 11.0.0

    The web application language is not defined

Recommended Actions

When an unconfigured security policy is associated with a virtual server, the BIG-IP ASM system will not perform any security checks on the traffic processed by that virtual server. In BIG-IP ASM 11.3.0 and earlier, an unconfigured active security policy is usually created right after the Application Security option is enabled in a HTTP Class profile. However, it is possible that other issues may result in an active security policy that is unconfigured. For example, the failure of a configuration load or a roll forward during an upgrade may result in an active security policy that is unconfigured. A clear indication of this issue is when all the active security policies on the Security Policy page of the BIG-IP ASM Configuration utility have their names changed to Configure Security Policy.

Although BIG-IP ASM 11.4.0 and later does not create an unconfigured active security policy when adding an ASM rule to a Local Traffic Policy profile, it is possible that other issues may result in active security policy that is unconfigured. For example, the failure of a configuration load or a roll forward during an upgrade may result in an active security policy that is unconfigured.

Procedures

When experiencing unconfigured security policy issues, you can use the following troubleshooting steps to determine the root cause:

Identifying unconfigured active security policy
Identifying misconfiguration or policy building process interruption
Removing the BIG-IP ASM configuration from the affected virtual server
Reviewing system configuration load issues
Recovering the affected security policy

Identifying unconfigured active security policy

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the Configuration utility.
    2. Navigate to the Active Policies page using the appropriate path:

      BIG-IP ASM 13.0.0

      Security > Application Security > Security Policies > Policies List

      BIG-IP ASM 11.3.0 through 12.1.2

      Security > Application Security > Security Policies > Active Policies

      BIG-IP ASM 11.1.0 through 11.2.1

      Application Security > Security Policies > Policies List > Active Policies

      BIG-IP ASM 11.0.0

      Application Security > Web Applications > Web Application List

    3. Check for any security policy with the name Configure Security Policy.

      If all of the security policies have their names changed to Configure Security Policy, it may indicate a configuration load issue. Proceed to the Review system configuration load issues procedure for further troubleshooting steps.

      If one or more of the security policies have their names changed to Configure Security Policy, proceed to the Identifying misconfiguration or policy building interruption procedure for further troubleshooting steps.

    Identifying misconfiguration or policy building process interruption

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the Configuration utility.
    2. Navigate to the Active Policies page using the appropriate path:

      BIG-IP ASM 13.0.0

      Security > Application Security > Security Policies > Policies List

      BIG-IP ASM 11.3.0 through 12.1.2

      Security > Application Security > Security Policies > Active Policies

      BIG-IP ASM 11.1.0 through 11.2.1

      Application Security > Security Policies > Policies List > Active Policies

      BIG-IP ASM 11.0.0

      Application Security > Web Applications > Web Application List

    3. Verify if the affected security policy is intended to be assigned to the virtual server listed under the Virtual Servers column.

      If the affected security policy is not intended to be assigned to the virtual server due to misconfiguration, proceed to the Removing ASM configuration from the affected virtual server procedure.

      If the affected security policy is intended to be assigned to the virtual server, it may have been interrupted during the policy building process. You may be able to confirm this by navigating to the policy properties page and verifying if it is reporting that the application language is not defined. Proceed to complete the policy building process. For instructions on resuming the policy building process for the affected security policy, refer to the Building a Security Policy Automatically chapter of the Configuration Guide for BIG-IP Application Security Manager manual.

    Removing the BIG-IP ASM configuration from the affected virtual server

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    BIG-IP ASM 11.4.0 and later

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
    3. Click the affected virtual server.
    4. Click Resources.
    5. In the Policies section, click Manage.
    6. Under the Enabled column, select the policy that is configured with a BIG-IP ASM rule referencing the unconfigured active security policy.
    7. To move the selected policy to the Available column, click >>.
    8. Click Finished.
    9. Navigate to Local Traffic > Policies > Policy List.
    10. Select the affected Local Traffic policy.
    11. Click Delete.

    BIG-IP ASM 11.0.0 through 11.3.0

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
    3. Click the affected virtual server.
    4. Click Resources.
    5. In the HTTP Class Profiles section, click Manage.
    6. In the Enabled column, select the HTTP Class profile that has the Application Security option enabled.
    7. To move the selected HTTP Class profile to the Available column, click >>.
    8. Click Finished.
    9. Navigate to Local Traffic > Profiles > Protocol.
    10. Click HTTP Class.
    11. Select the affected HTTP Class profile.
    12. Click Delete.

    Reviewing system configuration load issues

    When all of the security policies have their name changed to Configure Security Policy, it may indicate a configuration load issue. Proceed to review the following list of ASM-specific issues that may result in unconfigured active security policies due to configuration load failures:

    • K13945: The BIG-IP ASM MySQL database is not installed completely if BIG-IP ASM is not provisioned when the UCS is loaded

    If none of the ASM-specific issues apply, troubleshoot other possible BIG-IP system configuration load issues by reviewing the list of system configuration load failures in the following Supplemental Information section.

    Recovering the affected security policy

    Alternatively, you can attempt to recover the affected security policy by deleting the affected security policy and then importing the security policy XML file that was exported from a working system. If you do not already have an export of the desired security policy, you may need to export it from a working peer system, or export it from a previous version if the BIG-IP ASM system is a standalone system. To do so, perform the following procedure.

    Impact of procedure: If you need to boot to a previous version to export a security policy, the BIG-IP ASM system will not process traffic during the reboot. You should perform this procedure during an appropriately scheduled maintenance window.

    1. If you already have an exported XML file format of the desired security policy, you can skip to step 3. If you need to obtain an export of the desired security policy from a previous version, you need to reboot the system to its previous known working version. Once you have rebooted the system to its previous known working version, perform the Exporting a security policy procedure described in K13905104: Overview of importing and exporting BIG-IP ASM security policies.
    2. When you have obtained an exported XML file format of the security policy you want, reboot the system back to the version you want if it is not in the slot you want.
    3. Log in to the Configuration utility of the BIG-IP ASM system.
    4. Navigate to the following paths:

      BIG-IP ASM 13.0.0

      Security > Application Security > Security Policies > Policies List

      BIG-IP ASM 11.3.0 through 12.1.2

      Security > Application Security > Security Policies > Active Policies

      BIG-IP ASM 11.1.0 through 11.2.1

      Application Security > Security Policies > Policies List > Active Policies

      BIG-IP ASM 11.0.0

      Application Security > Web Applications > Web Application List

    5. Select the policy you want to delete.
    6. Perform the following actions appropriate for your version:

      BIG-IP ASM 13.0.0

      1. Click Delete.
      2. To confirm the deletion, click OK.

      BIG-IP ASM 11.3.0 through 12.1.2

      1. Click Deactivate.
      2. To continue, click OK.
      3. Click Inactive Policies, and select the recently deactivated security policy.
      4. Click Delete.

      BIG-IP ASM 11.1.0 through 11.2.1

      1. Click Delete.
      2. To confirm the deletion, click OK.
      3. Click Policies List > Inactive Policies,  and select the recently deactivated security policy. 
      4. Click Delete.

      BIG-IP ASM 11.0.0

      1. Click Delete. 
      2. To confirm the deletion, click OK.
    7. When you have deleted the affected security policy, import the exported XML file format of the security policy you want by performing the Importing a security policy procedure described in K13905104: Overview of importing and exporting BIG-IP ASM security policies.
