Introduction

To configure FirePass to access sites that are running complex applications without configuring Web Application content processing scripts, you can use the Minimal Content-Rewriting Bypass feature. Unlike typical FirePass content processing, FirePass does not obscure URLs or rewrite cookies that are sent to the client when the Minimal Content-Rewriting Bypass feature is enabled.

Requirements

Configuration requirements for the Minimal Content-Rewriting Bypass feature are as follows:

  • Your application must reside on a single server. The Minimal Content-Rewriting Bypass cannot process URLs for multiple servers.
  • If there is client-side JavaScript that directly processes cookies, you must configure cookie pass-through on the FirePass controller in order to use the Minimal Content-Rewriting Bypass feature.
  • You must manually enable cookie pass-through for the bypassed server. Automatic cookie pass-through does not work when the Minimal Content-Rewriting Bypass feature is enabled.
  • For FirePass version 5.4 1 - 5.5.2 and 6.0.0 - 6.0.1, you cannot use the Minimal Content-Rewriting Bypass feature if Compatibility Mode is enabled. For FirePass versions 6.0.2 and later, you can use the Minimal Content-Rewriting Bypass feature with Compatibility Mode 2 but not with Compatibility Mode 1.

Note: You can configure cookie pass-through and Compatibility Mode on the Portal Access: Web Applications: Content Processing page under the Global Settings tab.

Before using the Minimal Content-Rewriting Bypass, you must have one of the following combinations of FirePass software and hotfixes:

  • FirePass version 5.4.1 and hotfix HF-45904-45906-45921-45923-45989-45999-46054-46055-
    46063-46107-46269-46312-46415-46457-46529-46533-46551-46552-46578-2
  • FirePass version 5.4.2 and hotfix HF-47749-1
  • FirePass version 5.5 or later

For information about upgrading, refer to the FirePass release notes.

Configuration mode options

You can configure the Minimal Content-Rewriting Bypass feature using one of following two modes:

  • Alternative Port/Host Based Proxy
    This mode provides a dedicated IP address and TCP port through which the FirePass controller proxies connections to the application server. When configuring the FirePass controller in Alternative Host/Port-based mode, you must configure one FirePass controller port for each port the application server uses. If your application uses SSL encryption, you must also install on the FirePass controller the same SSL certificate and private key that is installed on the application server.

    The Alternative Port/Host Based Proxy mode requires less FirePass configuration than the Pattern Based Bypass mode; therefore, F5 recommends that you use the Alternative Port/Host Based Proxy mode if it is easy for you to make the necessary changes to your network, such as possible DNS and firewall changes as well as SSL certificate installation.

  • Pattern Based Bypass Proxy
    This mode provides a pattern-matching mechanism for URLs. You specify a protocol, host, and path for the FirePass controller to match. If a URL matches the pattern-based bypass rule you configured, FirePass does not modify URLs on the returned page.

    You can implement the Pattern Based Bypass Proxy mode without making network changes, but it does require you to enter the protocol, host, and directories that are used by your application so that FirePass can match the incoming URLs. F5 recommends that you use the Pattern Based Bypass Proxy mode if it is difficult for you to make the network changes required by the Alternative Port/Host Based Proxy mode.

Configuring Minimal Content-Rewriting Bypass

To configure the Minimal Content-Rewriting Bypass feature, determine whether you want to use the Alternative Port/Host Based Proxy mode or the Pattern Based Bypass Proxy mode and then perform one of the following procedures.

Minimal Content-Rewriting Bypass with Alternative Port/Host Based Proxy

To configure the Minimal Content-Rewriting Bypass feature using an Alternative Port/Host Based Proxy, perform the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. From the navigation pane, click Device Management.
  3. Click Configuration.
  4. From the sub-menu, click Network Configuration.
  5. Click the Web Services tab.
  6. In the Add new service section, select an IP address from the IP menu.
  7. In the Port field, enter a port number that is not already in use by another FirePass web service.
  8. In the Name field, enter an IP address or a fully qualified domain name (FQDN) which resolves to the IP address you configured in Step 6.
  9. Select the SSL check box.
  10. Click the Add New button.
    The Web Service Configuration page displays.
  11. In the Certificate menu, select an SSL certificate to use with the new web service.
  12. Select the WebAccess Bypass check box.
  13. Click the Update button.
  14. Click the Finalize tab.
  15. Click the Finalize changes button.
  16. Click the Apply Changes and Restart button.
  17. Click the Restart button.
  18. After the FirePass controller restarts, click Portal Access.
  19. Click Web Applications.
  20. Click Master Group Settings.
  21. From the Master Group menu box, select the master group that will use the application.
  22. Locate the WebAccess Bypass web service you just created in the Alternative Host/Port-based area of the Minimal Content-Rewriting Bypass section.
  23. Next to the WebAccess Bypass web service you just created, enter the URL for your application in the http[s]://<IP Address/Name>[:Port] field.

    For example:
    https://app.siterequest.com
  24. Click the Update button.

Your application is now configured to use the Minimal Content-Rewriting Bypass using an Alternative Port/Host Based Proxy. When users access the application, FirePass replaces the host name and port of the target server with the host name and the port(s) you configured in this procedure.

Minimal Content-Rewriting Bypass with Pattern Based Bypass Proxy

To configure the Minimal Content-Rewriting Bypass feature using a Pattern Based Bypass Proxy, perform the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. From the navigation pane, click Portal Access.
  3. Click Web Applications.
  4. Click Master Group Settings.
  5. From the Master Group menu box, select the master group that will use the application.
  6. In the Comma separated list of patterns field of the Minimal Content-Rewriting Bypass section, enter the application directories that you do not want FirePass to translate. Separate each directory with a comma.
    For example, if you do not want FirePass to translate the following URLs:

    https://tech.f5.com/appdir1/
    https://tech.f5.com/appdir2/
    https://tech.f5.com/appdir3/text.html

    Enter the following text:

    /appdir1/,/appdir2/,/appdir3/text.html

  7. Enter the protocol and host portion of the URL for your application in the http[s]://<IP Address/Name>[:Port] field.

    For example, if you do not want FirePass to translate the following URL:

    https://tech.f5.com/appdir1/

    Enter the following text:

    https://tech.f5.com

  8. Click the Update button.

    Your application is now configured for minimal content rewriting using pattern-based bypass. When users access the application, FirePass replaces all references to the target server's protocol://address:port with the FirePass controller protocol://address:port.

Cookie pass-through

By default, the FirePass proxy engine proxies cookies that are sent from a web server to the browser. The default configuration is not desirable when using Minimal Content-Rewriting Bypass. F5 recommends that you configure cookie pass-through for the server configured in the Minimal Content-Rewriting Bypass.

To configure the cookie pass-through, perform the following procedure:

  1. From the navigation pane, click Portal Access.
  2. Click Web Applications.
  3. Click Content Processing.
  4. Click the Global Settings tab.
  5. Under the Web Applications Global Settings section, select the Do not block cookies at FirePass <X>, pass them to the browser for specified URL patterns check box, where X is the FirePass platform number.
    For example:

    4100

  6. In the text box for the cookie pass-through pattern, enter the same URL patterns used to configure the Minimal Content-Rewriting Bypass.
  7. Click the service restart link.
    The Restart Services page appears.
  8. Click the Restart button.
    FirePass restarts the web services.
