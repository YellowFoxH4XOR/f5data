K11798: Snapshot generation expiration may affect extended sessions

Known Issue

After a user's session successfully completes the access policy inspection, the BIG-IP APM system creates a configuration snapshot and stores the users session configuration setting. The snapshot has a generation. When an administrator changes the access policy, the BIG-IP APM system creates a new generation of configuration snapshots and expires the old generation after 24 hours. Sessions that use the old generation can access the old session snapshot for only 24 hours. As a result, extended sessions may fail to retrieve secure network address translation (SNAT) settings when a new application connection is attempted over a Network Access tunnel after the snapshot generation has expired. When the BIG-IP APM system cannot find SNAT information in the connection flow table, the BIG-IP APM system logs an error message that appears similar to the following example to the log file:

TCL error: _tmm_apm_acl_rule &lt;CLIENT_ACCEPTED&gt; - Failed to retrieve SNAT TCL efrom session: c8c14fd9 invoked from within "NETWORKACCESS::snat -session"

This error message may indicate that the connection exceeded the snapshot generation expiration time, and that the session does not exist in the current snapshot generation.

F5 Product Development tracked this issue as ID 226090 (formerly CR140763) and it was fixed in BIG-IP APM 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

Workaround

To resolve this issue, the user needs to log out and log back in to be assigned to the new snapshot. If multiple users need to remain connected for more than 24 hours, you may want to consider making configuration changes to the access policy only during maintenance windows, and notifying your users prior to making the changes.
