K10061: The HTTP/1.0 Requests HTTP profile option is not honored when serving a cached response

Known Issue

This is the result of a known issue. The HTTP/1.0 Requests setting in the HTTP profile specifies whether the BIG-IP system compresses responses to HTTP/1.0 client requests. The default setting is disabled. When both HTTP compression and RAM Cache are configured in the HTTP profile, and the HTTP/1.0 Requests HTTP option is disabled, the BIG-IP system does not honor the setting and returns compressed responses from the cache to HTTP/1.0 clients.

F5 Product Development tracked this issue as CR74404 and it was fixed in BIG-IP 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Important: In BIG-IP 9.3, 9.4.2, and later, if compression and RAM Cache are configured in the HTTP profile, you must enable the Insert Age Header RAM Cache setting to ensure that compressed responses are not returned from the cache to HTTP/1.0 clients.

Workaround

You can work around this issue with an iRule similar to the following example, which disables caching only for HTTP 1.0 requests:

when HTTP_REQUEST {
CACHE::enable
if { [HTTP::version] eq "1.0" } {
CACHE::disable
}
}

Note: In versions prior to 10.0.0, using the CACHE::enable iRule command with some HTTP requests may cause the system to crash. For more information, refer to K9617: TMM may crash if it receives a request without a URI or Host Header and RAM Cache is enabled through an iRule.
