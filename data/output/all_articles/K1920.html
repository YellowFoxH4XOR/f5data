Topic

This type of DNS implementation, where clients should get different answers for the same request based upon their origin, is known as split DNS.

With the 3-DNS Controller, you can configure split DNS using topology load balancing. Topology load balancing is flexible and can be configured several different ways to accomplish the same behavior.

Topology load balancing example

The following example shows one way to set up the 3-DNS Controller using topology load balancing. For specific configuration instructions and general topology information, refer to the 3-DNS Controller Reference Guide.

To configure topology load balancing in a split DNS configuration where the external users are sent to an external wide IP and the internal users are sent to an internal wide IP, perform the following steps:

  1. Create one pool for external addresses (in this example, no_access pool), which is configured with no virtual servers (just return to DNS load balancing mode).
  2. Create a second pool for internal addresses (in this example, wip_pool), which is configured to use only internal addresses with standard/dynamic load balancing.
  3. Configure the wide IP to use topology load balancing by creating a topology rule that specifies that all users connected from an external network use the no_access pool.
  4. In NameSurfer, delete the internal network mappings for the wide IP and point it to an external address. You could also replace the no_access pool for external users with a list of external addresses and load balance both internal and external connections appropriately.

For this example, the internal network is 172.16.0.0/24, any other network is considered external. The topology is configured as follows:

pool wip_pool  172.16.0.0/24
pool ext_pool 172.16.0.0/24

Following is the wideip.conf file section for this configuration:

wideip {
    address           192.168.14.39
	port              80 // http
	ttl               30
	name              ''int.desknet.sea'' // num_requests 0

	qos_coeff {
	   rtt             50
	   hops            0
	   completion_rate 5
	   packet_rate     1
	   vs_capacity     0
	   topology        0
	   kbps            3
	}

   pool_lbmode       topology
       ecv { protocol none }

   pool {
       name           ''wip_pool''
	   ratio          1
	   last_resort    no
	   limit { /* none */ }
	   ttl            30
	   preferred      ga
	   alternate      leastconn
	   fallback       hops
	   address        172.16.0.1
	   address        172.16.0.2
	}

   pool {
       name           ''no_access''
	   ratio          1
	   last_resort    no
	   limit { /* none */ }
	   ttl            30
	   preferred      ret2DNS
	   alternate      ret2DNS
    }
 }
