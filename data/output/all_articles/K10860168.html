Description

Client has Network Access connection and has Layer 7 ACL set on the Access Policy, but it does not adhere to it.

Environment

  • APM , Network Access 
  • Layer 7 ACL applied (https)
Cause

With Network Access, you can use a Layer 7 ACL that is configured to provide access control for port 80 HTTP connections only.

Recommended Actions

If you want to provide access control for anything that is not on port 80:
  • Create a second virtual server, with the IP address to which the ACL entry applies, and the default access profile.
Note: For HTTPS Network Access connections, you can use Layer 7 ACL entries only if the virtual server has the private key of the backend server.
 

Workaround :

  1. Following 4 steps will help you to understand L7 ACL with SSL traffic.
    1. import the cert and key for the server you wish the L7 https ACL to be applied to
    2. create a client ssl profile and link these
    3. create a virtual server with the same ip / same port as the backend server you with to apply the L7 https ACL to
    4. attach to this virtual server, the client ssl profile you created, an http profile, and the same access profile as exists on your NA vip
  2. Allow the proxy Pac file to check the path , URI or host and then pass the traffic through proxy so you can monitor the same.
  3. Just keep Layer 4 ACL for them.
