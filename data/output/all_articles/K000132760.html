Description

Traffic flows to a vCMP guest via its host. Sometimes, as part of troubleshooting, it may be necessary to perform concurrent packet captures on the guest and host to verify that the host passes traffic correctly to the guest.

Environment

  • BIG-IP
  • vCMP guest
  • vCMP host

Cause

You have a need to troubleshoot traffic flow between vCMP guest and its host.

Recommended Actions

tcpdump command to run on the guest:

# tcpdump -s0 -ni 0.0:nnn -w <filename.pcap> <filter>

tcpdump command to run on the host:

# tcpdump -s0 -ni <physical-interface> -w <filename.pcap> <filter>

Note: When capturing on a physical interface, the :nnn option should not be used. Additionally, if the host is a VIPRION system, you need to run the command on the blade where the physical interface resides. For more information, refer to K49375773: tcpdump limitations on BIG-IP VIPRION systems .

Example

A vCMP guest is showing "Disconnected" sync status. You would like to capture configsync traffic on the guest and its host to verify that configsync traffic is flowing normally. The guest uses self IP 192.168.0.1 for configsync. Besides capturing traffic for the self IP, it will be useful to also capture ICMP and ARP so that we can check if there is an ARP issue. The filter we will use in this case is "host 192.168.0.1 or icmp or arp".

tcpdump command to run on the guest:

# tcpdump -s0 -ni 0.0:nnn -w /shared/tmp/guest-configsync.pcap host 192.168.0.1 or icmp or arp

To identify the physical interface on the host to capture on, identify the VLAN the self IP is associated with, and check which interface(s) the VLAN uses.

On the guest, check the VLAN the self IP uses:

(tmos)# list cm device

cm device /Common/guest-1.example.com {

  - snip -

  configsync-ip 192.168.0.1

  - snip -

}

(tmos)# list /net self

net self /Common/HA-self-ip {

  address 192.168.0.1/24

  - snip -

  vlan /Common/HA-VLAN

}

On the host, check the interface/trunk used for the VLAN

(tmos)# list /net vlan

net vlan /Common/HA-VLAN {

  - snip -

  interfaces {

    - snip -

    HA-trunk {

      app-service none

      tag-mode service

      tagged

    }

    - snip -

  }

  - snip -

}

(tmos)# list /net trunk

net trunk HA-trunk {

  - snip -

  interfaces {

    1.1

    1.2

  }

  - snip -

}

Note: When capturing on a trunk, you just need to specify any one of the interfaces (1.1 or 1.2 in this case). For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system .

tcpdump command to run on the host:

# tcpdump -s0 -ni 1.1 -w /shared/tmp/host-configsync.pcap host 192.168.0.1 or icmp or arp
