Topic

SSLO Topology
The SSLO topology creates a variety of helper and supporting objects when it is initially created.  These objects are available to be used by other topologies.

SSLO Topology objects and deletions
When you delete the SSLO topology, it deletes the Virtual Servers, virtual server profiles, and iRules that are owned by the SSLO topology iApp, but not the supporting iApps, such as Interception Rules, Services, Service Chains, Security Policies, and SSL Configurations.  As a result you will still have a variety of APM policies, VLANS,  IPs, and other objects that were created with the topology but are still present in the configuration.

Deleting Everything
In the upper right corner of the SSLO Configuration screen is a hyperlink that says "Delete Configurations".  This link will prompt you with a warning and will delete all of the SSLO configuration including any supporting objects.  Note that this can take a while.  You can also manually delete the iApps under each subsection if you would prefer more granular control
Note: If you use the iAppLX application list instead of the SSLO configuration screen to delete objects configuration will remain.  This is because the iApp system does not have a complete picture of the SSLO configuration and is a limitation of the iAppLX interface.  SSLO objects should ideally only be created, modified, or deleted under the SSLO configuration screen.
