K000136145: Splitting large packet captures to smaller sizes and extracting packet information

Support Solution

Applies to

Source

Description

Splitting large size packet captures to smaller sizes may be necessary for further analysis such as in extracting packet information. Packet captures taken during network or application attacks on applications served thru BIG-IP Virtual Servers contain packet details such as source IP addresses of the attack and from it, geolocation information. A BIG-IP with IP Intelligence license can also check the extracted IP addresses reputation.

 

Environment

Large size packet captures taken thru packet capture utility, example, tcpdump

editcap utility for extracting and limiting number of packets to output packet capture files 

tshark utility for extracting packet information

administrator role access to a BIG-IP device

IP Intelligence license on BIG-IP

iprep_lookup command on BIG-IP to check IP address IP reputation

geo_lookup command on BIG-IP to check IP address geolocation information

 

Cause

Packet captures taken during network or application attacks on applications served thru BIG-IP Virtual Servers may be too large and would be better if its smaller size packet capture for manageability for network traffic analysis.

 

 Recommended Actions

Use editcap utility to split large size packet capture file

On a BIG-IP system or secure systems with the editcap utility, split large size packet capture files

With a large packet capture file in the /var/tmp directory, create temporary file location and change directory to it

mkdir scatch
cd scratch

Use editcap utility to extract packets by specifying a number with the "-c" option and provide a pcap output file name. The output file name will include a file number to note the start and end of the extracted packet file sequence

$ editcap ddos.pcap -c 30000 split30k.pcap

#ddos.pcap is the large size packet capture file
#"-c <packets per file>" editcap option -  split the packet output to different files based on uniform packet counts with a maximum of <packets per file> each.
#"-c 30000" instructs editcap to split and extract packet capture output files with 30000 packets each.
#In this example, packet capture file ddos.pcap is 8.8 GB file, after splitting it to output packet capture files with 30000 packets each, it created 306 output files

$ ls -lah ddos.pcap
8.8G Sep 8 03:17 ddos3.pcap

$ ls scratch/ | head
split30k_00000_20230908000155.pcap
split30k_00001_20230908000156.pcap
split30k_00002_20230908000156.pcap
...
$ ls scratch/ | tail
...
split30k_00303_20230908000305.pcap
split30k_00304_20230908000305.pcap
split30k_00305_20230908000306.pcap

$ ls scratch/ | wc -l
306

 

Extracting packet information using tshark

Note: These procedures do not need to be executed on the BIG-IP system

Extract source IP addresses that initiated a connection from the smaller packet capture files. Use tshark to filter packets with SYN flag but no ACK flag - the first SYN packet

As there are many packet capture files to check, use a script file to iterate/loop over the pcap files and run tshark to extract the source IP addresses and redirect output to a file .

As an example, use script format from https://www.cyberciti.biz/faq/bash-loop-over-file/ and use tshark command " tshark -nr "$f" -Y "tcp.flags.syn == 1 and tcp.flags.ack == 0" -T fields -e ip.src >> /path/ddos_pcap_src_ips.txt" to extract the source IP addresses that initiated the initial packet with only the SYN flag set and redirect the output to text file.

Note variable "$f" is each pcap file from list of files from the directory defined in the "FILES" script variable

cat file[.]sh
#!/bin/bash
# NOTE : Quote it else use array to avoid problems #
FILES="/pcapfiles/path/*"
for f in $FILES
do
echo "Processing $f file..."
# take action on each file. $f store current file name
tshark -nr "$f" -Y "tcp.flags.syn == 1 and tcp.flags.ack == 0" -T fields -e ip.src >> /path/ddos_pcap_src_ips.txt
done

Modify the file[.]sh script to be an executable and run the script file

$ chmod +x file[.]sh
$ ./file[.]sh
Processing /var/tmp/scratch/split30k_00020_20230908000159.pcap file...
Processing /var/tmp/scratch/split30k_00021_20230908000200.pcap file...
Processing /var/tmp/scratch/split30k_00022_20230908000200.pcap file...
....

 

Sorting and removing duplicate IP addresses 

Non unique extracted source IP addresses from the split packet capture files

cat ddos_pcap_src_ips.txt | wc -l
69983

Sorted source IP addresses with 'sort' command and removed duplicates with 'uniq' command

cat ddos_pcap_src_ips.txt | sort | uniq > ddos_pcap_uniq_src_ips.txt

Unique source IP addresses from the sample 306 split packet capture files

cat ddos_pcap_uniq_src_ips.txt | wc -l
6372

Checking IP addresses with iprep_lookup and geo_lookup commands in the BIG-IP

Note: These procedures needs to be executed in a BIG-IP system

Using a manually created script file (iprep[.]sh) to check source IP address reputation thru iprep_lookup command on a IP Intelligence licensed BIG-IP device, 39 of the 6372 unique source IPs have bad reputation from the split packet capture files.

./iprep[.]sh < ddos_pcap_uniq_src_ips.txt 2>&1 | grep "threats list" - | wc -l
39

Using the sample iprep[.]sh script file, 531 of the 69983 non unique source ip addresses have bad reputation from the split packet capture files to show how many times IP addresses with bad reputation sent a packet.

 ./iprep[.]sh < ddos_pcap_src_ips.txt 2>&1 | grep "threats list" - | wc -l
531

Use a manually created script file (geo[.]sh) to check source IP address geolocation information. The list of geolocations for each of the source IP addresses can be then sorted and de-duplicated to get the number of times a source Geolocation sent a packet, in this case to initiate a connection.

./geo[.]sh < ddos_pcap_uniq_src_ips.txt 2>&1 | grep country_code | awk -F "=" '{print $2}' | sort | uniq -c | sort -rnk 1 | head -20
.....
 

Additional Information

Here is the "iprep[.]sh" script used to check the extracted IP address information IP reputation. This requires an IP Intelligence license on a BIG-IP as it uses iprep_lookup command.

[admin@BIG-IP]tmp # cat iprep[.]sh
#!/bin/bash
while read -r line;
do
 iprep_lookup "$line"
done
wait

If IP Intelligence is not licensed and iprep_lookup is used, error is returned

# iprep_lookup 15.15.2.2
opening database in /var/IpRep/F5IpRep.dat, /var/IpRep/F5IpV6Rep.dat
ERROR: Failed to access IP reputation memory-map
ERROR initializing IP reputation database.

Here is the "geo[.]sh" script used to check source IP address geolocation information. It uses the geoip_lookup command. The geoip_lookup command does not require additional license on the BIG-IP.

[admin@BIG-IP]# cat geo[.]sh
#!/bin/bash
while read -r line;
do
 geoip_lookup "$line"
done
Wait
