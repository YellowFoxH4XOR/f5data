Known Issue

This is the result of a known issue. A last hop pool configuration directs reply traffic to the last hop router defined in the specified pool. If a virtual server is configured with both a load balancing pool and a last hop pool, the BIG-IP system should mark the virtual server Unavailable when either the load balancing pool or last hop pool is Unavailable. However, the BIG-IP system currently marks the virtual server Unavailable only when both the last hop pool and the load balancing pool are Unavailable. When the load balancing pool is Unavailable, and the last hop pool is Available, the BIG-IP system incorrectly marks the virtual server as Available even though no load balancing pool members are Available. Likewise, when the last hop pool is Unavailable, and the load balancing pool is Available, the BIG-IP system incorrectly marks the virtual server as Available even though no last hop pool members are Available.

F5 Product Development is tracking this issue as ID 250995 for the BIG-IP 9.x software branch. F5 Product Development tracked this issue as ID 213425 (formerly CR80616) for the BIG-IP version 10.x software branch and it was fixed in version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.
