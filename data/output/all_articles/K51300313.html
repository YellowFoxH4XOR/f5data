Description

UCS save operation from GUI or CLI stalls and times out.

  • The following error is appearing in the GUI after 5 minutes:

Internal Server Error

The server encountered an internal error or misconfiguration and was unable to complete your request.

Please contact the server administrator at support@f5.com to inform them of the time this error occurred, and the actions you performed just before this error.

More information about this error may be available in the server error log.

  • UCS save from the CLI will run indefinitely and cancelling the operation with CTRL+C produces output similar to the following:

^CTraceback (most recent call last):
  File "/usr/libexec/iAppsLX_save_pre", line 158, in <module>
    taskResult = getFinishedTask(taskUri, 1.0, subprocess.check_output("getdb iapplxrpm.timeout", shell=True))
  File "/usr/libexec/iAppsLX_save_pre", line 86, in getFinishedTask
    time.sleep(delay)
KeyboardInterrupt
^CError executing 'pre-save' configsync script /var/tmp/cs_save_pre_script.
^C/var/tmp/configsync.spec: Error creating package

WARNING:There are error(s) during saving.
        Not everything was saved.

  • Errors similar to the following are appearing in /var/log/ltm:

err iAppsLX_save_pre[<PID>]: Failed to get task response within timeout for: /shared/iapp/build-package/16d78253-a7fb-449c-8c90-1c04a57a3af3
err iAppsLX_save_pre[<PID>]: Failed to get getRPM build response within timeout for f5-iappslx-waf-bot-protection

Environment

  • UCS save
  • iAppsLX

Cause

As part of a UCS save, the system runs a script which attempts to build an RPM of the various iAppsLX packages that are installed. This can take some time and in some cases will time out.

This issue is exacerbated if there are numerous iAppsLX applications installed.

Recommended Actions

Increase the value of sys db iapplxrpm.timeout:

tmsh modify sys db iapplxrpm.timeout value 300
tmsh restart sys service restjavad

This db key is only available from 14.1.4.4, 15.1.4.1, 16.1.2 and later releases in those branches.

There should be no adverse impact to the system from increasing the value. The default value is 60 and the maximum value is 600.

Additional Information

In some cases a buildup of tmsh save processes can accumulate while UCS saving is unsuccessful, particularly if there is an automated backup script. or BIG-IQ performing daily backups. It may be necessary to investigate the running processes and kill off any old/stalled tmsh processes:

ps aux | grep -iE '[t]msh|[c]s_save_pre|[i]appslx'

lslocks | grep '/run/config_lock'

To kill off all running tmsh, run the following command:

killall -9 tmsh

A tmsh save cannot complete while a previous save is still running.
