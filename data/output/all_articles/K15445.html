Known Issue

Certain URL parameter formatting may cause BIG-IP APM single sign-on (SSO) resource authentication to fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access profile is configured for Multidomain SSO.
  • The application encoded URL includes an ampersand (&) character.
  • The parameter separating ampersand (&) character is not followed by an HTML Form standards name=value declaration with an equal sign (=).

When the BIG-IP APM SSO profile parses a URL for resource authentication, it attempts to determine the URL parameters by using the parameter separator ampersand (&) followed by a name=value pairing that includes the use of the equal sign (=). A parameter separator (&) that is not followed by a context including the equal sign (=) can cause the parsing of URL parameters to be misread. The parameters read by the BIG-IP APM system are passed to the destination resource with the successful authentication. However, the misread parameters are forwarded to the destination resource and can trigger an authentication failure.

For more information about HTML Forms, refer to Forms in HTML Documents.

Example application URL parameters

Non-functioning application URL parameters:

  • http://url.testparameters.local/?arg1=value&
  • http://url.testparameters.local/?arg1=value&arg2

Functioning application URL parameters:

  • http://url.testparameters.local/?arg1=value&=
  • http://url.testparameters.local/?arg1=value&arg2=

    Note: All ampersand (&) separated parameters must be followed by an equal sign (=) or an equal sign (=) and parameter "name=value".

Impact

Attempts to access the BIG-IP APM resource fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Resource authentication fails if initial access to the BIG-IP APM system results in a misreading of the URL-encoded parameters.
  • When successfully authenticating using a URL with multiple parameters, authenticated access to the destination resource fails with an error message similar to the following example:

    Access policy configuration has changed on gateway. Please login again to comply with new access policy configuration.

Workaround

There is no workaround for this issue. However, you can URL-encode "&" and "=" in the original application URL before passing it to the BIG-IP APM system. This suggested workaround requires changes on the external application.
