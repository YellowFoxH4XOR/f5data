Known Issue

This is the result of a known issue. The master control program daemon (mcpd) is the messenger daemon that enables communication between userland processes and TMM. When a process that communicates with mcpd fails to process one or more messages, mcpd queues those pending messages in memory. Over time, if the pending message queue continues to grow, mcpd may eventually core.

F5 Product Development tracked this issue as ID 205003 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WAN Optimization release notes.

Additional Information

In BIG-IP versions 10.1.0 and later, mcpd terminates a process once the number of pending messages for that process exceeds an acceptable limit. If mcpd is unable to terminate the process, mcpd terminates its connection to the process, which clears the pending messages from memory.
