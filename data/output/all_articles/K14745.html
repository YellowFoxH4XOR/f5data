Topic

The Routing Information Protocol (RIP) is a distance-vector routing protocol. RIP is one of the advanced routing protocols that the BIG-IP system supports.

Description

The BIG-IP system has the following two routing tables:

  • The kernel table routes BIG-IP system management traffic.
  • The Traffic Management Microkernel (TMM) table routes load-balanced traffic.

To add routes to the BIG-IP system, you can enter the routes statically, using the Configuration utility or the TMOS Shell (tmsh), or dynamically, if the system is licensed for the BIG-IP Advanced Routing Module (BIG-IP ARM). This feature is included for Better and Best licenses.

Note: You can determine if your system is licensed for BIG-IP ARM by checking for Routing Bundle under Active Modules on the License page in the Configuration Utility or by typing show sys license in tmsh.

RIP protocol, which is a distance-vector routing protocol, is one of the advanced routing protocols supported by the BIG-IP system.

The following elements must be in place before you configure RIP on the BIG-IP system:

  • The BIG-IP system is licensed for BIG-IP ARM.
  • The tmrouted process is running.

    To verify whether tmrouted is running, type the following command at the command line:

    bigstart status tmrouted

    To start the tmrouted process, type the following command:

    bigstart start tmrouted

  • RIP must be enabled in ZebOS. To verify whether RIP is enabled in ZebOS, type the following command at the command line:

    zebos check

    If RIP is enabled in ZebOS, the zebos check command returns output that appears similar to the following example:

    zebos check
    === route domain: 0 ===
    nsm     is running [19071]
    imi     is running [19070]
    ripd    is running [19198]

    If RIP is not enabled in ZebOS, refer to the following articles for information about starting BIG-IP ARM:

    • K13802: Enabling dynamic routing protocols for a route domain
    • K8261: Enabling a dynamic routing protocol (9.x - 11.1.0)
  • Port lockdown must be configured to allow User Datagram Protocol (UDP) 520 on all self IP addresses with which the routers communicate. For information about port lockdown, refer to K13250: Overview of port lockdown behavior (10.x - 11.x).

Advanced routing daemons

The tmrouted process is the routing table management daemon that updates the TMM routing table based on the kernel routing table. The tmrouted process depends on the mcpd and tmm processes. If either of these processes restarts, tmrouted also restarts.

The tmrouted process starts and supervises the ZebOS daemons. ZebOS daemons are divided into the following two categories:

  • Core daemons:
    • nsm

      The nsm daemon is the ZebOS Net­work Services Module daemon.

    • imi

      The imi management daemon allows the system administrator to configure and monitor ZebOS daemons through a centralized connection.

  • Protocol daemons:
    • bgpd
    • isisd
    • ospfd
    • ospf6d
    • ripd
    • ripngd

ZebOS daemon startup is controlled by the presence of BIG-IP ARM license keys. Protocol daemons are started if they are licensed and enabled. Core daemons are started if at least one protocol daemon is licensed and enabled.

The tmrouted process handles SIGCHLD signals and restarts ZebOS daemons as necessary. The tmrouted process performs the following actions when a ZebOS daemon restarts:

  • Core daemon exits
    • Removes all dynamic routes
    • Stops all remaining ZebOS daemons
    • Exits and restarts
  • Protocol daemon exits
    • Restarts the protocol daemon

Advanced routing daemon logging

The ZebOS logs to the /var/log/zebos.log file. Additional messages are logged to the /var/log/daemon.log and /var/log/ltm files. The RIP daemon information is logged for RIP daemon-specific issues, and nsm and imi daemon information is logged for core ZebOS daemon-related issues.

If a core ZebOS daemon exits, an error message that appears similar to the following example is logged to the /var/log/daemon.log file:

mybigip LOGIN: Re-starting tmrouted

In addition, error messages that appear similar to the following example are logged to the /var/log/ltm file:

mcpd[5157]: 01070410:5: Removed subscription with subscriber id ripd

Debug logging

When you troubleshoot an issue with a ZebOS daemon, you may need to create a debug log file and enable debug logging. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the IMI command line shell, type the following command:

    imish

  3. Enter enable mode by typing the following command:

    enable

  4. Enter configuration mode by typing the following command:

    config terminal

  5. Create the debug log file by typing the following command:

    log file /var/log/zebos.log

  6. Exit configuration mode by typing the following command:

    end

  7. Write the configuration by typing the following command:

    write

  8. After the debug log file is defined, enable RIP debug logging by typing the following command:

    debug rip all

  9. Verify that RIP debug logging is enabled by typing the following command:

    show debug rip

    For example, the following output indicates that RIP debug logging is enabled:

    RIP debugging status:
    RIP event debugging is on
    RIP packet detail debugging is on
    RIP NSM debugging is on

  10. To enable debug logging for the Networking Services Module (NSM), type the following command:

    debug nsm all

  11. To verify that NSM debug logging is enabled, type the following command:

    show debug nsm

    For example, the following output indicates that NSM debug logging is enabled:

    NSM debugging status:
    NSSM event debugging is on
    NSM packet detail debugging is on
    NSM kernel debugging is on
    NSM HA all debugging is on

  12. You can disable RIP or NSM debugging by typing the following commands:
    • RIP:

      undebug rip

    • NSM:

      undebug nsm

Verifying RIP routes

You should verify that the routes are advertised from the imish shell. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the IMI command line shell, type the following command:

    imish

  3. Show the IP route information by typing the following command:

    show ip route

    For example, the following command output displays the IP route information:

Capturing RIP protocol traffic

In certain cases when peering is not establishing or updates are not correct or not appearing to arrive at the peer, the tcpdump command may help to track the routing updates. To capture the RIP traffic, use the following tcpdump commands concurrently:

 tcpdump -ni 0.0:nnn -s0 -w /shared/tmp/0.0_rip.pcap port 520

 tcpdump -ni <vlan>:hnnn -s0 -w /shared/tmp/vlan_hostside_rip.pcap port 520

In this command, note the following:

  • <vlan> is the Virtual Local Area Network (VLAN) name in which RIP is enabled.
