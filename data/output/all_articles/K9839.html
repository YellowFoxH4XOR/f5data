Topic

When the Client SSL profile is configured to require client certificate authentication, the Advertised Certificate Authorities option is set to None by default. When set to None, the BIG-IP system does not advertise a list of trusted Certificate Authorities (CA) to the remote client in the Secure Sockets Layer (SSL) handshake certificate request.

The Advertised Certificate Authority setting defaults to None and remains an optional setting for the following reasons:

  • Sending a list of trusted CAs in each new SSL handshake creates larger packets and may consume additional computing resources.
  • Most SSL clients will prompt the user to select the appropriate client certificate.

However, with certain clients such as Nokia phones and PDAs, this missing information may cause SSL handshake failures for some HTTP clients that do not prompt the user. You can resolve this issue by selecting the appropriate trusted CA SSL certificate from the Advertised Certificate Authorities menu in the Client Authentication section of the Client SSL profile that is applied to the virtual server. The trusted CA SSL certificate is typically the same as the Trusted Certificate Authorities certificate.
