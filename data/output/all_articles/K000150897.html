K000150897: Machine Cert Auth Pattern Matching

2025-04-17

2025-04-17
Applies to

Source

Description

Machine Certificate Authentication (MCA) is a method of checking a certificate stored in the computers system certificate store against a specified trusted authority. For more information about configuring and setup of MCA, see Overview of the access policy Machine Cert Auth action. You may have a pattern configured in the APM Machine Certificate Auth agent that should be valid but still the client logs show the pattern "doesn't match pattern" and the policy goes through the fallback branch. This article is about how pattern matching works.


Environment

  • Bigip APM configured to perform Machine Certificate Authentication
  • Windows OS with machine certificates installed

Cause

Incorrectly configured pattern. The library used to implement this feature requires that the pattern matches the entire string being tested, not just one part of the string


Recommended Actions

  • Get the correct pattern to match against

Some tools may reverse the order of the string being checked so it's important to make sure to match against the correct pattern. The correct pattern is shown using the local computer certificates mmc, and viewing the windows certificate's details page or using the windows certutil command (certutil --dump <path\to\certificate>). For example, openssl may show the following:

$ openssl x509 -noout -issuer -in certs/Win11.pem

issuer=C = CountryCode, ST = SomeState, L = SomeCity, O = Org, OU = Lab, CN = MyCN, emailAddress = testuser@company.com


using the windows certificate utility for local computer and selecting the details of a certificate, you see this:

The correct pattern would be the order (top down) from the windows details page (i.e. E=testuser@company.com, CN=MyCN, OU=Lab, O=Org, L=SomeCity, S=SomeState, C=CountryCode)

NOTE: the lack of spacing between the = sign and spacing after the , matters.


  • Matching
  1. When matching, you MUST match the entire string. So using the above example, if I'm matching against the issuer, whatever pattern I use must match the entire pattern. Failing to do so will result in a failure
    1. A pattern of OU=Lab,.* will fail because the E-testyser@company.com and CN=MyCN are not included in the match pattern
  2. If multiple certs exist on the client machine, the OS will present 1 at a time. If that first one matches the pattern, then that certificate will be sent to APM to check against the configured issuer.
    1. NOTE: If not using a pattern and the machine has multiple certs, the OS may present the incorrect cert and not check the remaining certs. This is why searching with a pattern is helpful because if the first presented cert doesn't match the pattern, the next cert will be attempted.
  • Examples

Given a machine with 2 certs and APM configured to trust the issuer of cert 2 below, here's the results of the following patterns

CERTS

  1. CN=127.0.0.1, T=test, C=US, S=California, L=San Jose, O=Duo Security LLC, OU=Lab
  2. E=testuser@f5.com, CN=Test Root Certificate Authority, OU=Support Department, O=Support, L=Seattle, S=Washington, C=US

NOTE: log file is located at %tmp%/f5mcertcheck.txt


No Patterns Specified - Cert 1 is presented first and is sent to APM. Cert 2 is never checked. This fails because cert 2 issuer is configured as the trust cert

E=.* - This works

Cert 1 may be presented first but since the pattern doesn't match, cert 2 is then checked and the pattern matches because the string begins with E= and the pattern .* matches the remainder of the certificate. This works

Logs

  • first cert presented doesn't match
    • 2025-03-07,12:51:58:541, 12172,19248,, 48, \certinfo.cpp, 1297, CCertInfo::MatchCertificate, CN=127.0.0.1, T=test, C=US, S=California, L=San Jose, O=Duo Security LLC, OU=Lab doesn't match pattern "E=.*"
  • second cert presented matches
    • 2025-03-07,12:51:58:541, 12172,19248,, 48, \certinfo.cpp, 1300, CCertInfo::MatchCertificate, E=testuser@f5.com, CN=Test Root Certificate Authority, OU=Support Department, O=Support, L=Seattle, S=Washington, C=US matches pattern E=.*(extracted content="")
  • Total certs checked = 2
    • 2025-03-07,12:51:58:541, 12172,19248,, 48, \certinfo.cpp, 1424, CCertInfo::FindCertificateInStoreExt: , Total certs tested: 2

C=US - This fails because the entire string is not mached. Logs will show that both certs are checked and no match is found


These patterns work

E=.*, CN=Test Root Certificate Authority, OU=Support Department, O=Support, L=Seattle, S=Washington, C=US

.*CN=Test Root Certificate Authority, OU=Support Department, O=Support, L=Seattle, S=Washington, C=US

.*CN=Test Root Certificate Authority.*

  • each match the entire certificate and is preferred as the intent of which cert to match is clear. They help to ensure if another machine cert is added, only the one matching those patterns will be evaluated
