Known Issue

Custom monitors using regular expressions may incorrectly detect the member state.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP DNS system is configured with custom monitors that use regular expressions.
  • A custom monitor uses the backslash character ( \ ) to escape regular expression metacharacters or Perl (non-POSIX) backslash sequences.

    Example monitor:

    gtm monitor http backslash_monitor {
    defaults-from http
    destination *:*
    interval 10
    probe-timeout 5
    recv "^HTTP\/\d\.\d"
    send "GET /dns_monitored_object HTTP/1.1\r\nHost:www.example.com\r\n\r\n"
    timeout 31
    }

Impact

The monitor may not correctly determine the state of the monitored object.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system marks objects monitored by custom monitors that use regular expression as unavailable.

Workaround

To work around this issue, you can translate regular expression shortened classes, such as \d and \s, to POSIX equivalents, such as [:digit:] and [:space:]. Additionally, you can use the expression \x5C as a substitute for the backslash.

For example:

gtm monitor http backslash_monitor {
defaults-from http
destination *:*
interval 10
probe-timeout 5
recv "^HTTP/[:digit:].[:digit:]"
send "GET /dns_monitored_object HTTP/1.1\r\nHost:www.example.com\r\n\r\n"
timeout 31
}

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
