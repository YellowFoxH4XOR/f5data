Topic

You should consider using this procedure under the following condition:

  • You are running a BIG-IP GTM configuration script or using secure shell (SSH) to connect to the remote system and your system receives the following SSH warning:

    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!

  • You want to verify the remote BIG-IP system's SSH host key prior to acceptance.

Description

To prevent man-in-the-middle attacks, SSH maps host names to public host keys using the known_hosts file. When using SSH to connect to a remote host for the first time, the system prompts you to verify and install the remote systems public host key in the local known_hosts file. For example:

The authenticity of host '192.168.10.100 (192.168.10.100)' can't be established.
RSA key fingerprint is e1:2c:1c:52:58:d4:c0:41:65:6b:63:2d:95:11:eb:fb.
Are you sure you want to continue connecting (yes/no)? yes
Warning: Permanently added '192.168.10.100' (RSA) to the list of known hosts.

After it is verified and accepted, the host key is used to verify the authenticity of the remote host during subsequent SSH connections. When using SSH or one of the GTM configuration scripts; gtm_add, big3d_install or bigip_add to connect to a remote BIG-IP system that has been replaced or has changed its SSH host key, host key verification will fail, and a warning message similar to the following will be displayed on the console:

WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!

To resolve this issue, the old host key must be removed from the local known_hosts file and the new one verified and installed.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have command-line access to the BIG-IP system encountering the warning message.
  • You have command-line access to the remote system for SSH host key verification.

Procedures

Removing SSH host keys from the known_hosts file

You must use a text editor to open and remove the old host key from the known_hosts file.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system displaying the SSH warning message. For example, if you are running big3d_install from HostA (IP address 192.168.22.7) to HostB (IP address 192.168.22.222), log in to the command line of HostA.
  2. To back up the known_hosts file, type the following command:

    cp /root/.ssh/known_hosts /root/.ssh/known_hosts.save

  3. Use a text editor to open the /root/.ssh/known_hosts file. For example:

    vi /root/.ssh/known_hosts

  4. Locate the IP or hostname of the remote system and delete the old host key. For example, the known_hosts file on HostA will contain an entry with HostB's IP address and public host key. To remove the host key for HostB, highlight the line containing its IP address (192.168.22.222), and delete the line.

    Note: The following host keys are truncated for clarity.

    192.168.22.7 ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIEA5MsOVknb7ShYHs7Ca7sUOwNnWomlQ
    192.168.22.5 ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIEAsSOVn9LVtT44prLbOHu3yvZbpeETYCqF
    192.168.22.222 ssh-rsa AAAAB3NzaC1yc2EAAAABIwAAAIEAsASDFkjsfdgkjerBF3657dfgDHljdrtkjSDR

  5. Save the file and exit the text editor.

Verifying SSH host key fingerprint

You can verify the remote host's SSH key fingerprint on the remote host prior to accepting it locally. This helps to mitigate the possibility of a man-in-the-middle attack. The BIG-IP system's SSH host key resides in the /config/ssh/ssh_host_rsa_key.pub file.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the remote system you are connecting to. In the previous procedure, this is HostB.
  2. To verify the fingerprint of the BIG-IP systems SSH host key, run the following command:

    ssh-keygen -lf /config/ssh/ssh_host_rsa_key.pub
    1024 e1:2c:1c:52:58:d4:c0:41:65:6b:63:2d:95:11:eb:fb /config/ssh/ssh_host_rsa_key.pub (RSA)

  3. Log in to the command line of the local system you are connecting from. In the previous procedure, this is HostA.
  4. Run SSH or the BIG-IP GTM configuration script. In the previous procedure, big3d_install was the intended command:

    big3d_install 192.168.22.222
    The authenticity of host '192.168.22.222 (192.168.22.222)' can't be established.
    RSA key fingerprint is e1:2c:1c:52:58:d4:c0:41:65:6b:63:2d:95:11:eb:fb.
    Are you sure you want to continue connecting (yes/no)?

  5. Compare the RSA key fingerprints from steps 2 and 4. If the fingerprints match, it is safe to accept and install the host key.
