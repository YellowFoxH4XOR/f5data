K000151377: APM Secure Session Variables cannot be accessed, evaluated or parsed in Access Policy logic

Type
Support Solution
Published
2025-05-16
Updated
2025-05-16
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000151377

Description

When session variables are set as "Secure" in BIG-IP APM, access policy evaluation that relies on reading or parsing these variables fails. Logs may show session variables set to '*****' and policy branches to fallback or deny actions.


Environment

Any session variable set as "Secure" in Variable Assign or similar policy items


Cause

Secure session variables are stored in encrypted form in the session database. This encryption prevents their values from being accessed or interpreted by runtime logic, such as iRules, TCL-based policy macros, or any policy evaluation that requires reading the variable's value. As a result, any logic that attempts to evaluate, parse, or use the value of a secure variable will fail, leading to unexpected policy behavior (such as access denial).


Recommended Actions

Secure variables are intended for data that must remain confidential and not be processed during the session.. Only use the "Secure" flag for session variables that do not require further evaluation, parsing, or use in policy logic or iRules. If a variable must be processed or evaluated during the session, do not set it as "Secure."
