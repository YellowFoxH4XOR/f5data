Known Issue

This is the result of a known issue. When an SNMP query is performed for either of the following OIDs on a BIG-IP system configured with a large number of pools and pool members, the mcpd and snmpd processes may experience high CPU utilization:

  • f5.bigipTrafficMgmt.bigipLocalTM.ltmPools.ltmPoolStat
  • f5.bigipTrafficMgmt.bigipLocalTM.ltmPools.ltmPoolMember

The high load is a result of the mcpd parsing the monitors assigned to the pools and pool members. Configurations with a larger number of monitors assigned to the pools may cause the SNMP query to time out.

Note: The high CPU load will not affect the BIG-IP LTM system's ability to load balance of traffic.

F5 Product Development tracked this issue as CR123307, and it was fixed in BIG-IP version 9.4.8. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can prevent the query from timing out by using the -t flag with the SNMP query for configurations that contain a larger number of pools and pool members with monitors.

For example:

snmpwalk -t 60 -v2c -Of -c public 127.0.0.1
iso.org.dod.internet.private.enterprises.f5.bigipTrafficMgmt.
bigipLocalTM.ltmPools.ltmPoolStat

Note: The example has been divided into three lines for formatting purposes only.

In the example, the -t flag tells the snmpwalk to wait 60 seconds before timing out the request.
