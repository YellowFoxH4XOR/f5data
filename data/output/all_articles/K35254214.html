Known Issue

A network access session may fail to re-establish after a user device is placed in sleep mode.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is running BIG-IP 12.1.2 or 12.1.1 HF1.
  • Your BIG-IP APM system is configured with a network access profile.
  • The network access profile is configured as a Full Tunnel with Allow Local Subnet Access disabled.
  • The user device is running the Mac OS X 10.12.1 operating system.
  • The user established a network access session using the Mac OS Edge Client 7131.2016.0602.1.
  • Users connected to a network access profile place their device in sleep mode.
  • The user wakes their Mac OS X device before the access session timeout.

Impact

The Edge Client fails to re-establish the network access session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the Mac OS Edge Client log, you observe repeating messages similar to the following example:

    11167,11167,edge, 2, , 171, TunnelController, Disconnected state, Error code, Wrong Tunnel configuration

  • In the /var/log/apm file on the BIG-IP APM system, you observe repeating log messages similar to the following example:

    notice tmm[<pid>]: 01490505:5:<path><na name>:<value>:<session id>: PPP tunnel 0x57032d6a9e00 started.
    notice tmm[<pid>]: 01490505:5:<path><na name>:<value>:<session id>: PPP tunnel 0x57032d6a9e00 closed.
    notice tmm[<pid>]: 01490549:5:<path><na name>:<value>:<session id>: Assigned PPP Dynamic IPv4: <lease pool ip> Tunnel Type: VPN_TUNNELTYPE_DTLS NA Resource: <path><na name> Client IP: <ip address - Reconnect

Workaround

To work around this issue, you can modify the network access profile enabling Allow Local Subnet Access. To do so, perform the following procedure:

Impact of workaround:  Performing the following procedure enables network access users to access devices in the local subnet. 

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to Access Policy > Network Access > Network Access List.
  3. In the Name box, click the name of the affected access network access profile.
  4. Click the Network Settings tab.
  5. Click the Enable box for Allow Local Subnet.
  6. Click Update.
  7. In the upper right corner of the Configuration utility click Apply Access Policy.
  8. Click the Apply Access Policy button.
