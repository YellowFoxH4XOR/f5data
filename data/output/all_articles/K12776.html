Known Issue

This is the result of a known issue. The BIG-IP VIPRION system uses the MPI channel to exchange messaging information between Traffic Management Microkernels (TMMs) across all blades. If you run the tcpdump command on interface 0.0, a multi-blade VIPRION system incorrectly prioritizes tcpdump traffic over MPI channel traffic and disrupts communication between TMMs. Although the MPI channel communication disruptions can recover quickly, a BIG-IP VIPRION system processing a heavy load may prolong the loss of MPI channel communications. As a result, the BIG-IP VIPRION system triggers a failover.

In addition, the BIG-IP VIPRION system logs messages that appear similar to the following example to the /var/log/tmm file, indicating the loss of MPI channel communications:

notice CDP: exceeded 1/2 timeout for slot 2
notice CDP: exceeded 1/2 timeout for slot 3
notice CDP: exceeded 1/2 timeout for slot 3
notice Immediately transitioning dissaggregator to state 0x1
notice cmp state: 0x1
notice cmp state: 0x7
notice CMP transition complete, transitioning dissaggregator to state 0x7
notice MPI stream: connection to node 127.10.2.7 lost
notice hsb0 warning: lost 25 consecutive loopback packets.
notice MPI stream: connection to node 127.10.2.7 lost
notice MPI stream: connection to node 127.10.2.7 lost
notice MPI stream: connection with node 127.10.2.7 established
notice MPI dgram: connection with node 127.10.2.7 established
notice hsb0 warning: lost 25 consecutive loopback packets.
notice MPI stream: connection to node 127.10.3.4 lost
notice hsb interface 0 soft resetting due to receive failure

F5 Product Development tracked this issue as ID 353116 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, and PSM release notes.

For information about downloading software from F5, refer to K167: Downloading software and firmware from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You may be able to work around this issue by running tcpdump on a VLAN. In addition, you can use an external traffic sniffer device to capture traffic on multiple interfaces.

Note: For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.
