Known Issue

This is the result of a known issue. BIG-IP 8400 and 8800 systems fail to pass full-size Ethernet frames through the 10 gigabit interfaces. This behavior results in communication failures between the BIG-IP system and the network devices connected to the 10 gigabit ports.

Note: A full-size Ethernet Type II frame, as defined in RFC894, is 1518 bytes in size; the MAC Header uses 14 bytes, the size of the data being transmitted is 1500 bytes and the CRC Checksum uses 4 bytes.

F5 Product Development tracked this issue as ID 226188 (formerly CR140968), and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, GTM, Link Controller, or WebAccelerator release notes.

Additionally, this issue has also been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You may be able to work around this issue by setting the MTU of all VLANs associated with the 10 gigabit interfaces to a smaller value. F5 recommends initially reducing the MTU to 1464 bytes. However, some customers have reported an MTU value as small as 1282 is necessary to completely eliminate communication failures resulting from this issue.
