K17556: Using wildcard characters when defining custom URL categories in BIG-IP APM SWG

Issue

Old Behavior

In BIG-IP APM versions prior to BIG-IP APM Secure Web Gateway (SWG) 12.0.0, the system interprets wildcard characters, such as asterisks (*), literally when you define custom URL categories. Although, when you view an Associated URL with the Prefix Match option selected, it shows a trailing asterisk in the Configuration utility. The asterisk is merely intended to indicate that the entry can match multiple URLs. Configuring URL definitions with wildcard characters for use in glob pattern matching or regular expressions will produce unintended results.

New Behavior

Beginning in BG-IP APM 12.0.0, you can use the Glob Pattern Match option to enable glob pattern matching when you define custom URL categories. You can now, also, configure custom URL categories into base BIG-IP APM functionality. Without a pre-defined set of URL categories, users can now define their own categories using glob pattern matching capability. You can use custom URL categories, for example, to acceptlist and denylist web sites. URL categories are available on the Secure Web Gateway menu, but you do not need to have an SWG subscription to use the functionality.

F5 Product Development tracked this change as ID 424827.

Impact

You can now perform glob pattern matching using wildcard characters when you configure custom URL categories.

Recommended Actions

When you configure custom categories in SWG prior to BIG-IP APM 12.0.0, do not include wildcard characters in the URL definitions. To use wildcard characters in Associated URLs for globbing, you should upgrade to BIG-IP 12.0.0 and select the Glob Pattern Match check box next to the URL definition.
