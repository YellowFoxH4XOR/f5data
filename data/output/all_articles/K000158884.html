Description

When clients use BIG-IP DNS as their primary DNS server, name resolution may appear to “skip” BIG-IP DNS and succeed only after the client tries the next (secondary) DNS server. Typical symptoms:

  • nslookup displays: Got recursion not available from 10.1.1.1, trying next server,
  • dig shows the query is sent with RD (Recursion Desired), for example:
    • flags: qr aa rd (RD set in the query)
    • BIG-IP DNS response does not indicate RA (Recursion Available)

This can be confusing when the record exists on BIG-IP DNS and resolves when directly querying the BIG-IP DNS listener IP.

Environment

  • Product: BIG-IP DNS
  • Version: 17.1.2 (behavior described is not specific to a single version in this case)
  • Configuration/state:
    • BIG-IP DNS listeners configured correctly
    • Recursion is not enabled on BIG-IP DNS BIND/named
    • Client tools (nslookup/dig) send queries with RD by default
    • Another DNS server in the client’s resolver list has recursion enabled and can answer the query

Cause

Normal behavior: BIG-IP DNS is not configured to provide recursive resolution (BIND/named recursion disabled), while clients/tools request recursion (RD). Some clients/tools (notably nslookup) treat “recursion not available” as a reason to try the next configured DNS server, even if BIG-IP DNS is authoritative for the name.

Recommended Actions

  • Validate that the client is requesting recursion:
    • dig sample.example

Impact of workaround: Enabling recursion may allow clients to receive answers for records outside your authoritative zones; consider security implications.

    1. If you want authoritative-only responses: Test authoritative response behavior (no recursion requested):
      1. dig +norecurse sample.example

 

    If you want BIG-IP DNS to answer recursive queries from clients:

        1. Edit named.conf on BIG-IP and enable recursion.

          Example:

          # In /etc/named.conf
          # Add or modify:
          # options {
          # ...
          # recursion yes;
          # };

    Note: If you only enable recursion under "DNS > Settings > GSLB > General", this enables WideIP processing but does NOT enable full BIND/named recursion for general client queries. For that you must enable it in named.conf.

    Additional Information

        • The tools nslookup  & dig typically send queries with RD by default. Their behavior differs: dig will usually show any answer returned even if recursion is not available.
