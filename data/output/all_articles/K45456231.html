Known Issue

TCP connections may become orphaned when the server-side connection times out.

This issue occurs when all of the following conditions are met:

  • The client establishes a connection to the BIG-IP system.
  • The pool member fails to respond with a TCP ACK when the BIG-IP system sends a server-side TCP FIN or responds with a TCP RST when the BIG-IP system sends a TCP FIN.
  • The server-side connection times out.

The client-side connection is orphaned by the BIG-IP system indefinitely, regardless of the configured idle timeout value.

Impact

As orphaned connections accumulate, memory exhaustion may result in degraded performance or interruptions in traffic processing.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You cannot delete the orphaned client-side connections using the tmsh delete sys connection command.
  • Memory usage increases over time.
  • New connections that attempt to use the port already in use by an orphaned connection are reset with a reason similar to the following example:

    [0x2830261:5357] TCP closed

  • In the output of the tmsh show sys connection protocol tcp command, you notice orphaned connections similar to the following example:

    Sys::Connections
    10.0.0.1:5854  10.0.0.250:80  any6.any  any6.any  tcp  449  (tmm: 0)  none  none
    10.0.0.1:5847  10.0.0.250:80  any6.any  any6.any  tcp  449  (tmm: 0)  none  none

Workaround

To delete the orphaned connections, you must restart the Traffic Management Microkernel (TMM) or restart the BIG-IP system. To restart the BIG-IP system, perform the following procedures:

  • Restart the BIG-IP system
  • Restart all blades on a VIPRION system

Restart the BIG-IP system

Impact of workaround: Service will be interrupted. If configured for high availability (HA), the BIG-IP system fails over to another device in the device group.

  1. Log in to the Advanced Shell (bash).
  2. To restart the system, enter the following command:

    reboot

Restart all blades on a VIPRION system

Impact of workaround: Service will be interrupted. If configured for HA, the BIG-IP system fails over to another device in the device group.

  1. Log in to bash.
  2. To restart all the blades on the VIPRION system, enter the following command:

    clsh shutdown -r now
