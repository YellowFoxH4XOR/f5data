Description

Windows 11 VPN frequently disconnects/reconnects when Microsoft connectivity probes (http://www.msftconnecttest.com/connecttest.txt) are redirected during VPN.

Environment

BIG-IP APM any versions

Windows 11

Cause

This is due to Microsoft Windows 11 OS behavior.

- Windows Event logs may show logs like:

Event Viewer -> Applications and Services Logs -> Microsoft -> Windows -> NCSI -> Operational:

Hotspot detected on interface ...
Capability change on ... Family: V4 Capability: Local ChangeReason: ActiveHttpProbeFailedHotspotDetected)
Capability change on ... Family: V4 Capability: None ChangeReason: CapabilityReset)
Capability change on ... Family: V4 Capability: Internet ChangeReason: PassivePacketHops)

Event Viewer -> Windows Logs -> System:

... The connection to _Common_Test_NetworkAccess - APM-VS-FQDN made by user  using device GENERIC1-0 was disconnected.
... The user  successfully established a connection to _Common_Test_NetworkAccess - APM-VS-FQDN.com using the device GENERIC1-0.

- %temp%\logterminal.txt may show logs like:

URDialer.cpp, 1820, CURDialer::OnTimer, :RasGetConnectStatus failed, 6 (0x6) The handle is invalid.
RAS Connection Dropped - VPN IP: <IP-address>, Tunnel IP: <APM-VS-FQDN>

- %temp%\f5TunnelServer.txt may show logs like:

USocketChannel.cpp, 68, USocketChannel::Read(), read error, -1
UTunnel.cpp, 876, UTunnel::RunObjectProc(), >> ServerChannel->Read() return error, -1

* Please note that such logs can be logged for other reasons.

Recommended Actions

Allow Microsoft connectivity probes (http://www.msftconnecttest.com/connecttest.txt) during VPN. This Microsoft behavior can also be disabled by creating a registry key on the Windows 11 clients:

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\NlaSvc\Parameters\Internet\EnableActiveProbing = 0
Here, EnableActiveProbing registry key is of type REG_DWORD.
