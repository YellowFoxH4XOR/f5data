Description

Running bigip_software_image command in Ansible playbook results in the error: "Failed to create a resource".  As an example see below:

# ansible-playbook -i /root/ansible/inventory/hosts /root/ansible/playbooks/bigip_software_image.yaml -vvv
[...]

TASK [upload image to the bigip] *************************************************************************
[...]
fatal: [bigip -> localhost]: FAILED! => {
    "changed": false,
    "invocation": {
        "module_args": {
            "force": true,
            "image": "/var/tmp/dummy_file.iso",
            "provider": {
                "auth_provider": null,
                "password": "VALUE_SPECIFIED_IN_NO_LOG_PARAMETER",
                "server": "10.201.195.41",
                "server_port": null,
                "ssh_keyfile": null,
                "timeout": null,
                "transport": "rest",
                "user": "root",
                "validate_certs": false
            },
            "state": "present"
        }
    },
    "msg": "Failed to create the resource."
}

Environment

  • Ansible
  • BIG-IP

Cause

Corrupt BIG-IP iso image.

Recommended Actions

Ensure the BIG-IP iso image to upload from Ansible to the BIG-IP unit is not corrupt, this is by checking its md5sum.

For example, if you are uploading BIGIP-15.1.3.1-0.0.18.iso:

# cat BIGIP-15.1.4-0.0.47.iso.md5; echo
730e547a35be0c6a3ee6d832fe425c64 BIGIP-15.1.4-0.0.47.iso

# md5sum BIGIP-15.1.4-0.0.47.iso
730e547a35be0c6a3ee6d832fe425c64 BIGIP-15.1.4-0.0.47.iso

The result should match each other.

If the output does NOT match, download the iso file again from the F5 Downloads site.

Run the Ansible playbook again for  bigip_software_image and it should be successful.
 

Additional Information

  • Optionally, you can use the 'force' and/or 'state' parameters of bigip_software_image command to ensure what action is required by the run. See the following article for more information about this:

                       bigip_software_image – Manage software images on a BIG-IP

  • For troubleshooting, in your Ansible playbook run, use -vvv to provide verbose output information.
