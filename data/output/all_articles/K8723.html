Known Issue

This is the result of a known issue. Modifying an HTTP class may result in the BIG-IP ASM incorrectly reinitializing the class. As a result, the BIG-IP ASM will reinsert the modified HTTP class with a different priority.

Since the HTTP classes are order-dependent, an HTTP class in the wrong position in the list may cause the BIG-IP ASM to incorrectly evaluate the traffic and allow it to bypass the BIG-IP ASM.

If an HTTP class is modified, and a virtual server uses multiple HTTP classes, F5 Networks recommends that you verify class order before allowing the virtual server to handle traffic, in order to prevent traffic from bypassing the BIG-IP ASM.

F5 Product Development tracked this issue as CR96928 and it was fixed in BIG-IP ASM 9.4.5. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.4-94.0-HF3 issued for BIG-IP 9.4.4. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
