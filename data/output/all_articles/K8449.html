Known Issue

This is the result of a known issue. When you create a self-signed SSL server certificate on the FirePass controller after January 19, 2008, if the expiration of the certificate (the valid to field of the certificate) is chosen to be 30 years, the certificate will be created with an incorrect expiration date due to the "Year 2038 Problem." The data structure that stores time past January 1, 1970 will reach its maximum value and roll over. Therefore, a certificate intended to have an expiration date beyond January 19, 2038 will instead be created with the "two's complement" year (1902 instead of 2038; 1903 for 2039, and so on).

An SSL server certificate enables SSL/TLS-based communication between the FirePass controller and its remote access clients. The SSL server certificate contains a valid to field which indicates the date and time that the certificate will expire. When you create a self-signed SSL server certificate by using the FirePass built-in Public Key Infrastructure, you must select an expiration date using a drop-down menu. If  30 Years is selected, the valid to field is filled with the incorrect year. When the certificate database is subsequently displayed, by clicking on the Configure SSL Certificates >> link under the Web Services tab of the Device Management: Configuration: Network Configuration page, a different incorrect expiration date will be displayed in the row for that certificate under the Expiration column.

In the following example, the incorrect year of 2019 is visible:

Configuring a web service with this certificate will typically produce warning pop-up messages in client browsers due to the expired validity.

F5 Product Development tracked this issue as CR93025 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

Additionally, this issue was fixed in cumulative hotfix HF-601-11 issued for FirePass version 6.0.1, and in cumulative hotfix HF-602-3 issued for FirePass version 6.0.2. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

To work around this issue, do not select the 30-year option for self-signed certificates. Remove any such certificates and replace them with certificates that have a shorter validity period.

Important: When deleting a certificate, ensure that it is not used on a web service. If the certificate is being used by a web service, ensure that the replacement certificate is available, so that you may first switch the web service to the replacement certificate, and then delete the 30-year certificate. For more information regarding configuring web services with certificates, consult the Administration Guide and the online help for configuring Web Services.
