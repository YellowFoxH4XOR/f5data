Known Issue

The zxfrd process produces a core file and restarts when importing a zone file that contains a WINS resource record (RR) (TYPE65281).

This issue occurs when all of the following conditions are met:

  • You configure or update a DNS Express zone.
  • The zone that is imported contains a WINS RR (TYPE65281).

Impact

The zone transfer fails and the zxfrd process continually restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H438065 on the Diagnostics > Identified > Medium screen.
  • The system logs messages similar to the following example to the console:

    emerg logger: Re-starting zxfrd
    emerg logger: Re-starting zxfrd
    emerg logger: Re-starting zxfrd

  • The zxfrd process produces a core file in the /shared/core directory.
  • Host name lookups fail for the affected zone.

Workaround

To work around this issue, perform all of the following procedures:

  • Removing the affected DNS Express zone from the BIG-IP system
  • Configuring the Microsoft DNS server to exclude any WINS RR (TYPE65281) from zone transfers
  • Reimporting the zone on the BIG-IP system

Removing the affected DNS Express zone from the BIG-IP system

Impact of workaround: The BIG-IP system does not process DNS requests for the affected zone.

  1. Log in to the Configuration utility.
  2. Click the Local Traffic tab.
  3. Select the DNS Express Zones menu.
  4. Select the box next to name of the affected zone.
  5. Click Delete.

Configuring the Microsoft DNS server to exclude any WINS RR from zone transfers

Impact of workaround: The excluded WINS RR is excluded from any subsequent zone transfers.

  1. To identify any WINS RR (TYPE65281) in the zone, you can use the dig command. For example, if the zone you are transferring is example.com, and the DNS server you are transferring from is 192.0.2.50, type the following command:

    dig @192.0.2.50 AXFR example.com

  2. Identify any TYPE65281 RR in the output, and then refer to the following link for instructions on how to configure the Microsoft DNS Server to filter out proprietary WIN RR before transferring the zone.

    http://technet.microsoft.com/en-us/library/bb962024.aspx#ID0E1EAC

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Reimporting the zone on the BIG-IP system

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click the Local Traffic tab.
  3. Select the DNS Express Zones menu.
  4. Click Create.
  5. In the Name box, type the name of the DNS Express zone.
  6. In the Target IP Address box, type the IP address of the DNS server from which you want to transfer records.
  7. Optional: Specify an already-defined TSIG Key from the TSIG Key menu.
  8. Optional: Choose the action to take when a NOTIFY query is received for a configured zone, by selecting the appropriate setting from the Notify Action menu.
  9. Click Finished.
