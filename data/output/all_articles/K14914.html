Known Issue

BIG-IP APM Citrix application access profiles may trigger a Traffic Management Microkernel (TMM) restart.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM Citrix application access with at least one of the following:
    • The Citrix application access profile references a layered virtual server.
    • The Citrix application access remote desktop profile has the destination resource defined with a pool.
    • The virtual server used for the Citrix application access has been configured with an Analytics profile.
  • The Citrix destination resource is running a standalone Citrix XML Service (ctxxmlss.exe) and is not using Microsoft Internet Information Services (IIS) port sharing.
  • A user initializes access to the Citrix application access profile.

Impact

TMM may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system logs an error message similar to the following example, in the /var/log/tmm file, at the time of the event:

    notice ** SIGSEGV **
    notice fault addr: 0x60
  • The BIG-IP APM system generates a TMM core file, similar to the following example, to the /shared/core directory:

    76636 -rw-r--r-- 1 root root 78388884 Dec 17 20:54 2013 tmm.0.bld608.0.core.gz
    76204 -rw-r--r-- 1 root root 77946424 Dec 17 21:12 2013 tmm.0.bld625.0.core.gz

  • The active system experiences an unexpected reboot.
  • The active system fails over to a peer device.

Workaround

To work around this issue, you can reconfigure the destination Citrix resource to use IIS port sharing. Alternatively, you can modify the BIG-IP APM Citrix application access profile configuration removing the Citrix pool reference, and/or removing the Analytics profile for the virtual server. To do so, perform the following procedures, as needed:

Configuring the backend Citrix XML Broker Service to use IIS port sharing

Modifying the BIG-IP APM Citrix application access resource from referencing a pool to referencing a single IP address

Removing the Analytics profile from the BIG-IP APM Citrix application access virtual server


Configuring the backend Citrix XML Broker Service to use IIS port sharing

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

To perform this procedure, refer to the following article:

How to Configure XML Service to Share a Port with IIS on 32 and 64 Bit Versions of Windows Server 2008

Modifying the BIG-IP APM Citrix application access resource from referencing a pool to referencing a single IP address

Impact of workaround: The available destination resources will be restricted to a single destination without high availability.

  1. Navigate to Access Policy > Application Access > Remote Desktops.
  2. Click the name of the affected Remote Desktop.
  3. In the Destination box, select IP Address.
  4. In the IP Address box, type the IP Address of the destination Citrix resource.
  5. In the Port box, type the port of the destination Citrix resource.
  6. Click Update.

Removing the Analytics profile from the BIG-IP APM Citrix application access virtual server

Impact of workaround: Analytics data will no longer be available for the virtual server.

  1. Navigate to Local Traffic > Virtual Servers.
  2. Click the name of the affected virtual server.
  3. In the Configuration box, select Advanced.
  4. In the Analytics Profile box, select None.
  5. Click Update.
