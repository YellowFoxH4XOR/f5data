Description

BIG-IP Virtual Edition instances deployed on Microsoft Azure in an Active-Standby high-availability pair and configured using the Cloud Failover Extension (CFE) may not complete reassignment of the required IP address configuration (the secondary/floating IPs on the network interfaces to the new active device after failover is initiated.

The following logs in /var/log/restnoded/restnoded.log are symptoms of this issue

Sun, 09 Jul 2023 03:45:16 GMT - warning: [f5-cloud-failover] f5_cloud_failover_nic_map tag values do not match or doesn't exist for a interface

Environment

  • BIG-IP Virtual Edition (VE)

  • Microsoft Azure cloud

  • High-Availability (Active/Standby) deployments

Cause

Missing 'f5_cloud_failover_nic_map' tags on Microsoft Azure network interfaces as described in the documentation below:

Define the Failover Addresses in Azure

"NIC mapping tag: a key-value pair with the reserved key named f5_cloud_failover_nic_map and a user-provided value that can be anything. For example "f5_cloud_failover_nic_map":"external"

Recommended Actions

The same tag (matching key:value) must be placed on corresponding Network Interface Cards (NIC) on each peer BIG-IP. 

For example, each BIG-IP would have their external NIC tagged with: "f5_cloud_failover_nic_map":"external"

And the internal NIC tagged with "f5_cloud_failover_nic_map":"internal"

Once the matching tags are configured on both devices, reset the statefile using the following commands:

curl -su admin: -X POST -d '{"resetStateFile":true}' http: //localhost :8100/mgmt/shared/cloud-failover/reset | jq .

Then query the inspect endpoint to validate IP addresses and routes associated with each peer BIG-IP

curl -su admin: http: //localhost :8100/mgmt/shared/cloud-failover/inspect | jq .

We can also use the trigger endpoint to perform a DRY-RUN on the standby device to validate IP/route configuration that would be re-mapped to the peer BIG-IP after failover

curl -su admin: -X POST -d '{"action":"dry-run"}' http: //localhost: 8100/mgmt/shared/cloud-failover/trigger | jq .

Check the toActive section of the response to confirm re-mapping
