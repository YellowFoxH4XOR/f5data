K000147503: Why HTTP/2 Health check is failing?

Type
Support Solution
Published
2024-11-08
Updated
2024-11-08
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000147503

Description

  • HTTP2 Health check fails on load balancer and you want to know how to fix it
  • cURL (and different tools on the web) shows that the origin server supports HTTP/2.

Environment

  • F5® Distributed Cloud
  • F5 Distributed Cloud HTTP Load Balancer

Resolution/Answer

  • The issue occurs because the server requires ALPN negotiation for HTTP/2. To resolve this, configure the server to accept HTTP/2 without ALPN.
  • Add h2c to the protocol list in your Apache configuration. Then test using the following curl command:

curl -vk <host_header>/<path> --resolve <host_header>:<port>:<origin-server ip address> --http2-prior-knowledge --no-alpn

If the request succeeds, the HTTP/2 health check probes should also pass.

Cause

  • When HTTP2 health probes are configured, ALPN is not used to negotiate the http protocol (http2 prior knowledge)
  •  Server does not accepts HTTP2 requests made without ALPN

Additional Information

This workaround applies only when ALPN negotiation is disabled.
