Description

Application Security Operations Admin role doesn't the ability to create attack signature sets. The UI page will show as below with buttons been greyed out.

However, they can create an attack signature set when they embed it within the policy declaration.

Environment

  • Application Security Operations Admin User Role

Cause

This is by design.

Recommended Actions

User-defined Signature Sets can be exported within the policy file for all WAF (ASM) policy export formats: binary, XML, and declarative (JSON). Likewise, they are imported from all formats as well. 

While user-defined Signature Sets (and Signatures) are "global" in the sense that they are not within a policy, they are handled as global only for the purposes of potential reusability. This is similar to the general concept of "Shared Objects".

Furthermore, imported user-defined Signature Sets will never overwrite or modify an existing Set. If the Set definition does not match the existing Set with the same name, a new Set will be created with a unique numeric suffix. The new Set will be associated with the newly imported policy. If a user only works from policy import, user-defined Signature Sets could be considered immutable.

In summation, this is the designed behaviour and has been for many years.
