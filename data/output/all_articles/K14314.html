Known Issue

IP Datagram fragmentation may cause ARX fastpath failure when a datagram is split into more frames than the number defined as the ARX system's internal limit.

This issue occurs when the following condition is met:

  • The maximum number of fragments for an entire packet exceeds the ARX system's 76 fragments per packet limit.

Fragmentation happens when TCP segments that are packaged into IP datagrams are too large, based on the Maximum Segment Size (MSS), and the sending system breaks the datagram up to meet the MSS, and then attempts to send the datagram. For example, if you have a packet with a total length of 64k, and the filer sends only 524 bytes per fragment, for the filer to transmit the full datagram, the number of fragments would exceed the ARX limit of 76 fragments.

Impact

The client does not receive the file request response.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • An error message that appears similar to the following example appears in the ARX syslog and fastpath log:

    NET_APP-4-DBG-DEBUG_TRACE_MESSAGE:: connMan.c:2771: TCP xbuf_send_iovec error (cifs cifss) 10.10.100.200:55551. Length 61503

Note: The fastpath log file is located in the /acopia/var/log directory of the ARX diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.

Workaround

To work around this issue, you must work with the filer vendor to resolve why the filer is fragmenting data.
