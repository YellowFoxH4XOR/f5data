Known Issue

The HTTPS monitor may mark down servers that do not support the Transport Layer Security (TLS) protocol.

This issue occurs when all of the following conditions are met:

  • You have configured a pool or specific pool member with an HTTPS monitor.
  • The monitored pool members do not support the TLS protocol.

The HTTPS monitor fails to complete a handshake to establish a secure connection with the pool member.

Impact

The BIG-IP system cannot monitor certain servers with the HTTPS monitor.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A packet trace indicates that the monitor completes a TCP three-way handshake with the pool member, but it does not receive a response to a Client Hello message during the TLS handshake.
  • The HTTPS monitor marks pool members down permanently.
  • The BIG-IP system logs messages to the /var/log/ltm file that appear similar to the following examples:

    notice mcpd[2964]: 01070638:5: Pool member 10.1.1.1:443 monitor status down

    tmm err tmm[4779]: 01010028:3: No members available for pool examplePool

Resolution

Workaround

There is no workaround to this issue. However, you can avoid a lack of monitoring by using a TCP monitor on affected pool members. The TCP monitors are limited to checking that pool members are available up to the transport layer.
