K000150481: Failed to add the peer device to device trust.

Type
Support Solution
Published
2025-03-25
Updated
2025-03-25
Source
https://my.f5.com/manage/s/article/K000150481

Description

When attempting to create device trust (Device Trust >> Device Trust Members >> Add), an error message "This device is not found" appears after entering the IP address and credentials for the remote device and clicking on "Retrieve Device Information". We can see the below iControl connection failed logs in LTM logs at the same time. 

Mar 20 05:54:04 bigip1.local err devmgmtd[8584]: 015a0000:3: iControl connection to 192.168.10.20 failed
Mar 20 05:54:04 bigip1.local err devmgmtd[8584]: 015a0000:3: iControl connection to 192.168.10.20 failed

Environment

BIG-IP LTM
Rebuilding the device trust
Security firewall management rule
 

Cause

The iControl connection is failing due to missing of management ip's in the configured security firewall management rule. 

# list /security firewall management-ip-rules
security firewall management-ip-rules {
    rules {
        mgmt_ip_filter {
            action accept
            ip-protocol tcp
            rule-number 1
            destination {
                addresses {
                    192.168.10.10 { }
                    192.168.10.20 { }
                }
                ports {
                    https { }
                    ssh { }
                }
            }
            source {
                addresses {
                    192.168.10.100 { }
                }
            }
        }
        mgmt_filter_deny {
            action drop
            ip-protocol any
            rule-number 2
        }
    }
}

 

Recommended Actions

The iControl SOAP is required for the operation of adding new devices to device trust. Allow both management ip's of BIG IP units in security firewall management rule. 

security firewall management-ip-rules {
    rules {
        mgmt_ip_filter {
            action accept
            ip-protocol tcp
            rule-number 1
            destination {
                addresses {
                    192.168.10.10 { }
                    192.168.10.20 { }
                }
                ports {
                    https { }
                    ssh { }
                }
            }
            source {
                addresses {
                    192.168.10.10 { }
                    192.168.10.20 { }
                    192.168.10.100 { }
                }
            }
        }
        mgmt_filter_deny {
            action drop
            ip-protocol any
            rule-number 2
        }
    }
}
