K79124020: BIG-IP breaks backend servers outbound traffic

Type
Support Solution
Published
2022-04-11
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.X, 15.1.5, 15.1.4, 14.1.4, 16.1.3, 16.1.0, 16.1.1, 16.1.2
Source
https://my.f5.com/manage/s/article/K79124020

Description

After implementing fix for CVE-2022-23029, BIG-IP might break outbound traffic that is using nPath/async routing,

Environment

  • BIG-IP
  • FastL4 profile with 'Loose Close' set as Disabled
  • Using nPath/async routing

Cause

Due to CVE-2022-23029, there has been a change in the FastL4 profile - this was in order to address the CVE where an attacker could cause a degradation of service in a virtual server using the FastL4 profile.
CVE's fix is breaking traffic that is using nPath/async routing which goes through the virtual server with the FastL4 profile

Recommended Actions

In case that VS's traffic is using nPath/async routing, the solution is to enable the 'Loose Close' option in the FastL4 profile:

From WebUI:

Local Traffic  >  Profiles : Protocol : Fast L4 > <Profile name>
Settings > Loose Close
Mark checkbox to enable

From CLI:

# tmsh modify ltm profile fastl4 <Profile name> loose-close enabled
# save sys settings

Additional Information

The Loose Close option allows the system to remove a connection when the system receives the first FIN packet from either the client or the server.
This helps trim connection table entries because the system can remove the connection entry as soon as the connection officially closes, and the system does not need to maintain the connection table entry.
