K000154631: Will Border Gateway Protocol (BGP) and Dynamic Routing Configuration Persistence During BIG-IP Upgrade

Description

When upgrading F5 BIG-IP systems, it is critical to ensure that BGP and other dynamic routing configurations persist after the upgrade. The persistence of these configurations depends on the method used for configuration (ZebOS/imish, TMSH, or iControl REST) and the backup procedures followed prior to the upgrade.

Environment

  • BIG-IP LTM
  • BGP configured via ZebOS (imish)
  • Dynamic Routing Configuration

Cause

If BGP or dynamic routing configurations are not explicitly saved to disk prior to a BIG-IP software upgrade, there is a significant risk of configuration loss. During an upgrade or system reboot, the running configuration is discarded and only the last saved configuration file is retained. As a result, unsaved changes will be irretrievably lost, potentially causing routing outages, loss of BGP peering, or disruption of network traffic.

Recommended Actions

How to save BGP and Dynamic Routing Persistence:

    1. Using ZebOS/imish for BGP Configuration
    • When configuring BGP using the ZebOS IMI shell (imish), your router configuration will only persist if you explicitly save it to disk. This is done by running the "write memory" (or write) command within the imish shell.
    • If you make changes interactively or via scripts and do not save them with write memory, those changes will be lost after a system reboot or software upgrade.
    • Standard BIG-IP backup procedures—such as tmsh save sys config or creating a UCS archive—only capture the last written ZebOS configuration file. Any unsaved running state in imish will not be included in these backups.

    1. Using TMSH for BGP Configuration
    • There are known issues where BGP configuration may not load correctly after a reboot if it was configured using TMSH, particularly in certain failover scenarios.
    • F5 recommends using the IMI shell (imish) for BGP configuration rather than TMSH to avoid these issues.
    • If you must use TMSH for BGP configuration, you may need to trigger a configuration update after a reboot. For example, toggling the BGP instance between enabled and disabled states can force the configuration to reload.

    1. Using TMSH/iControl REST for Dynamic Routing
    • When BGP or dynamic routing is configured via TMSH or iControl REST, the configuration is stored in the main BIG-IP configuration. This means it will persist through upgrades as long as you perform a standard configuration save and backup (such as a UCS archive).
    • To ensure your configuration is saved, always run tmsh save sys config before performing an upgrade.
    • By following these guidelines, you can ensure that your BGP and dynamic routing configurations are safely preserved across system changes and upgrades.

     

Additional Information

Proper backup and restore procedures are essential to ensure the persistence and recoverability of your BGP and dynamic routing configurations on BIG-IP systems. The following requirements and best practices should be followed:

Manual Backup/Restore Requirements

1. Save Changes in imish (ZebOS Shell):

  • Always run the "write memory" command in the imish shell before making or after completing any configuration changes. This ensures that your BGP configuration is written to disk and will persist through reboots and upgrades.

2. Save BIG-IP Configuration and Create UCS Backup:

  • Before performing any upgrade, always save your BIG-IP configuration using:
    tmsh save sys config partitions all
  • Then, create a UCS (User Configuration Set) backup. This captures the current state of your system, including dynamic routing configurations that have been saved to disk.

3. Verify Persistent Configuration:

  • Before upgrading, verify that all intended changes are present in the persistent ZebOS.conf file on disk. This ensures that the configuration you expect to be restored is actually saved.

4. TMSH-Based Configurations:

  • For configurations made using TMSH, ensure you have a recent UCS backup. After an upgrade, be prepared to trigger a configuration update (such as toggling the BGP instance enabled/disabled) if the configuration does not load automatically.

5. Restoration Considerations:

  • When restoring from a UCS archive, only the last saved ZebOS configuration file will be restored. Any changes made in imish that were not saved with "write memory" will be lost.

By following these steps, you can ensure that your BGP and dynamic routing configurations are reliably backed up and can be restored as needed, minimizing the risk of configuration loss during upgrades or system recovery.
