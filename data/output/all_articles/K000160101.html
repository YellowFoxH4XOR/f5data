K000160101: OAuth AS/RS split design: Resource Server WebSSO cannot use logon variables created on Authorization Server

Type
Support Solution
Published
2026-02-20
Updated
2026-02-20
Applies to
  • BIG-IP
  • BIG-IP APM: 21.0.0, 17.0.0, 17.5.1, 17.5.0, 17.1.2, 17.1.1, 17.1.0, 21.0.X, 17.1.3
Source
https://my.f5.com/manage/s/article/K000160101

Description

When BIG-IP APM is configured with separate OAuth Authorization Server (AS) and OAuth Resource Server / Client (RS) access profiles (on different virtual servers), the RS access policy does not inherit the APM session context from the AS access policy. As a result, SSO profiles attached to the RS access profile cannot reference “logon” session variables (for example, session.logon.last.username) that were populated during authentication on the AS virtual server unless another block, other than just OAuth client exists.

Environment

  • BIG-IP APM using OAuth Authorization Server + OAuth Resource Server/Client
  • Separate access profiles / policies (AS policy and RS policy)
  • RS Policy not including Logon Page / similar elements
  • WebSSO

Cause

APM maintains separate session contexts per access policy/virtual server.

When OAuth authentication happens on the AS virtual server and the protected application is served from a different RS virtual server, the RS policy session does not automatically receive the AS policy’s session variables.

Therefore, any WebSSO configuration attached to the RS access profile cannot reference variables that only exist in the AS session, including typical logon variables (for example session.logon.last.username) unless that information is also established within the RS policy session.

 

Answer/Recommended Actions

We have a few options.

  • Design RS WebSSO around variables that exist in the RS session
  • Move (or recreate) identity establishment into the RS policy
  • Redesign so a single access policy owns both auth and app traffic
  • Custom iRule set
  • Ask your Account Team or F5 Support about status of feature request (RFE Bug ID 1404109) to allow session variable sharing across access policies
