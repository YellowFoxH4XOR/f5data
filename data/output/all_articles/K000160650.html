K000160650: Access restricting iRule allows users to enter after refreshing the web page

Type
Support Solution
Published
2026-04-13
Updated
2026-04-13
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000160650

Description

You can observe that the iRule which was intended to restrict access for users to specific URL, successfully blocks first access but subsequent requests (such as page refreshes) allows them to enter the site.

Environment

  • BIG-IP
  • iRule logic: restrict access to specific URL based on client IP address

Cause

The root cause was the use of event disable all in the iRule after issuing an HTTP::respond command. 
This combination caused the iRule engine to improperly handle subsequent HTTP requests for the same connection, in result allowing user to enter restricted area.

Recommended Actions

Remove event disable all from the iRule after the HTTP::respond command to ensure proper handling of subsequent HTTP requests.

With example iRule presented below, you should delete the line for event disable all:

when HTTP_REQUEST {
    set restrict_area [string tolower [HTTP::path]]

    if {$restrict_area eq "/example/f5"} {
        if { !(
            [IP::addr [IP::client_addr] equals 192.0.2.41] ||
            [IP::addr [IP::client_addr] equals 192.0.2.128/25]

        )} {
            HTTP::respond 403 content "<html>Example Access Denied Syntax</html>" noserver
            event disable all
            return
        }
    }
}
