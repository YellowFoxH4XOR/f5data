Topic

When configuring the properties of a BIG-IP APM access profile, the following three timeout setting are available:

  • Inactivity Timeout
  • Access Policy Timeout
  • Maximum Session Timeout

To access these settings on the BIG-IP Configuration utility, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to Access > Profiles / Policies.
  3. Select the name of the access profile.
  4. In the Settings section, make the appropriate changes.

Description

Inactivity Timeout

The Inactivity Timeout setting controls how long (in seconds) a client can keep a live session without sending traffic. If the Inactivity Timeout value is reached the BIG-IP APM system will terminate the session. The default value is set to 900 seconds.

There are optional settings located in the Network Access configuration Advanced settings titled Session Update Threshold and Session Update Window. If these settings are configured and byte rate activity falls below the configured ranges for the Session Update Threshold and the Session Update Window, the Inactivity Timeout will not be reset.

Access Policy Timeout

The Access Policy Timeout setting controls how long a client has to complete an access policy (complete the logon process). This setting tells the BIG-IP APM system that if a client does not reach an Allow action before the time specified in this setting, the system should terminate the attempt. This setting prevents resources from being used for sessions that will most likely not complete the access policy's requirements. This setting is designed to mitigate denial-of-service (DoS) attacks. The default value is set to 300 seconds, but it can be changed depending on the needs of the environment. F5 recommends keeping this setting as low as possible to fully benefit from mitigating DoS attacks.

Maximum Session Timeout

The Maximum Session Timeout setting configures a limit on the maximum amount of time a user's session is active without needing to reauthenticate. If the value is set to 0 (zero), the user's session is active until either the user terminates the session or the Inactivity Timeout value is reached (the default value is set to 604,800 seconds). When determining how long the maximum user session can last, it may be useful to review your access policy. For example, if the access policy requires that the user's antivirus signatures cannot be older than 24 hours, you would not want the Maximum Session Timeout to exceed that time limit. You would not be able to enforce the policy regarding the age of the user's antivirus signatures. Most organizations that use this setting will generally not allow users to be connected longer than their scheduled work day.
