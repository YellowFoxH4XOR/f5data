Topic

This article lists the common third-party software applicable to BIG-IP Next. For information about the full list of third-party software used in the latest versions of BIG-IP Next, refer to the following:

  • BIG-IP Next LTM/WAF Containers and HostOS
  • BIG-IP Next Attribution report

For information about BIG-IP, refer to K11398383: BIG-IP third-party software matrix (17.x).

For information about BIG-IP Next Central Manager, refer to K000141392: BIG-IP Next Central Manager third-party software matrix.

Description

The following matrices list the common third-party software that are installed/used in the HostOS and/or the pods/containers on the BIG-IP Next systems.

Important: F5 patch releases may include upgrades and security fixes for the third-party software packages listed in the following table. As a result, when you evaluate vulnerability status for third-party software, F5 recommends that you refer to security advisory articles to determine if a BIG-IP Next release is vulnerable.

1The HostOS refers to the base operating system in BIG-IP Next Virtual Edition (VE) instance only. It does not include a BIG-IP Next instance deployed on a F5OS-C/A system.

Important: By default, F5 does not allow ssh access to a BIG-IP Next Virtual Edition (VE) instance as well as a BIG-IP Next instance deployed on a F5OS-C/A system. You can get to the command line of the BIG-IP Next VE instance using the console access provided by the hypervisor which you have deployed the VE instance. For BIG-IP Next instance deployed on a F5OS-C/A system, you will need the root user access to the F5OS-C/A system; however F5 does not encourage the use of the root user access to the F5OS-C/A system.

For the third-party software in the HostOS, you can log in to the VE instance base operating system as the admin user using the console access provided by the hypervisor and issue the commands listed in the previous table directly in the command line to view the third-party software version information. If you have deployed the BIG-IP Next VE instance locally on your hypervisor, you would have changed the password for the admin user as part of the process of creating BIG-IP Next VE instance locally on a hypervisor. For information about creating BIG-IP Next VE instance locally on a hypervisor, refer to following: 

  • Create BIG-IP Next Instance Locally on VMware
  • Create BIG-IP Next instance locally on KVM

For information about the console access provided by the hypervisor, refer to your hypervisor vendor's documentation.
