K73331542: Traffic object availability does not change when the BIG-IP system is forced offline

Type
Support Solution
Published
2021-05-24
Updated
2025-02-07
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.1, 13.1.1
Source
https://my.f5.com/manage/s/article/K73331542

Description

When you have a BIG-IP which is online; virtual servers, pool members, and nodes are available as a result of successful monitor probes. 

When you force offline the BIG-IP, this would result in the same virtual servers, pool member and nodes; all retaining the previous up (green) status even though no monitor probe is currently being sent to any of the traffic objects.

Environment
  • BIG-IP
  • BIG-IP sends monitor probe when it is online
  • BIG-IP does not send monitor probe it is offline
  • BIG-IP still maintains traffic object status even when it is offline

Cause

This behavior is by design. This is because the monitoring daemon (bigd) does not send monitor probes while the system is forced offline.
The status of the traffic objects will not change until the system has been released from offline and confirmation of a successful or failed monitor probe has been received.
The system simply retains the status from the last monitor probe when the system was online.
