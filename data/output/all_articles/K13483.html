Known Issue

The move command does not remove report files after the file transfer has completed. The local report file is still on the ARX system even though the move command reports that the file was removed.

This issue occurs when the following condition is met:

  • The file type being moved is a report file.

Impact

None. However, the source file remains on the ARX system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The move command reports that the target report file copy completed successfully and that the local report file was removed. The move command output appears similar to the following example:

    % INFO: Formatted file will be 3790 bytes in size.
    % INFO: For a large report, the copy operation may cause a high CPU load while the report is being formatted.
    % INFO: The copy of source file 'import.13.share2.16.rpt' to destination file 'test_report_123.rpt' completed successfully.
    % INFO: Local file 'import.13.share2.16.rpt' removed.

  • The show reports command continues to list the report file that was moved.

Workaround

To work around this issue, you can use the delete reports command to delete the local report file. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Delete the affected report file by using the following command syntax:

    delete reports <report_name>

    For example:

    delete reports import.13.share2.16.rpt
