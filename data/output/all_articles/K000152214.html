Description

Cloud solutions do not officially support High Availability (HA) failover for IPsec. This includes using the Cloud Failover Extension (CFE).

After a failover, the established tunnel or tunnels may fail to work until the related IPsec Security Associations (SAs) are deleted.

Results may vary, depending on the Cloud and the solution. Most customers report no impact.

Environment

  • IPsec
  • Cloud environment
  • High Availability failover with IPsec mirroring

Cause

Cloud environments do not allow the same IP to be in two places at the same time. To work around that, it is possible to move the address from Standby to Active during a failover event, to emulate the concept of a floating IP.

The limitation surrounds the move of the BIG-IP's IPsec local-address from Standby to Active. When that happens and a tunnel is already established on that IP, the Standby may sometimes hold on to the IP and continue to send ESP packets. The result is that the peer believes the BIG-IP is out of sync because both Active and Standby devices send ESP packets for the same SPI but with different SEQ numbers, such that all ESP packets are dropped as "out of order" or considered a replay attack.

An enhancement to improve this behaviour is being tracked as ID1967897 

Recommended Actions

The effect of this can be mitigated if the Cloud provider drops packets sourced from an address that the sending host does not own. In other words, if the Standby no longer owns the address that moved, the Cloud rules should consider the packet illegal and refuse to forward it. However, this will depend on the Cloud provider and how the IPsec solution itself is implemented.

After an HA failover in Cloud, if problems immediately occur with a tunnel or tunnels, delete the IKE and IPsec SA for the tunnel on the Active BIG-IP. This will cause the tunnel to re-establish and the Standby will also stop sending any IPsec related packets.

# tmsh delete net ipsec ike-sa peer-ip <remote-peer-ip>


# tmsh delete net ipsec ipsec-sa traffic-selector <traffic-selector-name>

Above, the traffic-selector-name is the name of all traffic-selectors associated with the peer.

You can delete based on other criteria and you can see the details of the established SAs with:

# tmsh show net ipsec ike-sa

# tmsh show net ipsec ipsec-sa

You can delete all SAs with (this will interrupt all established tunnels):

# tmsh delete net ipsec ike-sa

# tmsh delete net ipsec ipsec-sa

More detailed information about SAs can be found here:
