K000156763: F5OS-A - Interface shows "down" in tenant, even though the relevant interface on host is not mapped to the tenant

Type
Support Solution
Published
2025-10-02
Updated
2025-12-24
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.0
Source
https://my.f5.com/manage/s/article/K000156763

Description

On rSeries device running F5OS 1.8.0, interface X.0 is shown as "DOWN" in the F5OS host, and the corresponding tenant interface 1.X also displays a "DOWN" status instead of the expected "UNINIT" state. No LAG or VLAN is configured for this interface in the host, and no VLAN is associated with interface 1.X in the tenant configuration. Persistent SNMP alarms may be generated due to this unexpected "DOWN" status.

Note: X is the interface number. Example (7.0 in the F5OS host, and the corresponding tenant interface 1.7)

Relevant command outputs:

  • Optic state: NOT_QUALIFIED for portgroups X
  • Transceiver vendor: "Intel Corp", part number "AFCT-701SDZ-IN2", media type "1000BASE-LX"

Environment

  • Software: F5OS-A version 1.8.0
  • Tenant software: BIG-IP v17.5.1
  • No LAG or VLAN configured for host interface X.0
  • No VLAN associated to tenant interface 1.X
  • Unsupported/third-party transceivers installed in interface X.0

Cause

F5OS-A version 1.8.0 has reduced tolerance for unsupported or third-party transceivers compared to previous versions. The installed transceivers in interfaces X.0 are not qualified by F5OS, resulting in both host and tenant reporting these interfaces as "DOWN" rather than "UNINIT". This leads to persistent SNMP alarms and incorrect interface status reporting.

Recommended Actions

Replace unsupported or third-party transceivers with F5-supported optics.
