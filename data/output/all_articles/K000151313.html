K000151313: After upgrade GTM/DNS to 16.1.0 or later, virtual server status remains as "available/disabled" (black circle icon) after disabling virtual server which is managed by remote LTM device.

Type
Support Solution
Published
2025-05-15
Updated
2025-11-12
Applies to
  • BIG-IP
  • BIG-IP DNS: 16.1.0, 16.1.2, 16.1.1, 16.1.X, 17.1.X, 17.5.X, 17.5.0, 17.1.2, 17.1.1, 17.1.0, 16.1.6, 16.1.5, 16.1.4, 16.1.3

Description

Starting from BIG-IP GTM/DNS version 16.1.0, virtual server status remains as "available/disabled" (black circle icon) when virtual server object, which is managed/monitored by remote LTM device, is disabled on GTM/DNS device.

On 16.0.1.2 or prior GTM/DNS device, after disabled virtual server managed by LTM device and waited for a few minutes, "no reply from big3d: timed out: disabled directly" message is recorded on GTM/DNS device and virtual server status changes to "offline/disabled" (black diamond icon) from "available/disabled" (black circle icon) status. Here is example log messages on /var/log/gtm log file and virtual server status icon on 16.0.1.2.

May  9 11:15:11 bigipdns.local alert gtmd[8821]: 011a6007:1: SNMP_TRAP: VS (10.1.1.141:80) disabled
May  9 11:16:40 bigipdns.local alert gtmd[8821]: 011a6006:1: SNMP_TRAP: VS /Common/vs1 (ip:port=10.1.1.141:80) (Server /Common/bigipltm) state change green --> red ( Monitor /Common/bigip : no reply from big3d: timed out: disabled directly)

 

Figure: 16.0.1.2 virtual server status after disabling it

 

On 16.1.0 or later, after disabled virtual server managed by LTM device, virtual server status stays as "available/disabled" (black circle icon) and does not change to "offline/disabled" (black diamond icon) like v16.0.1.2 or prior did.

Figure: 16.1.0 virtual server status after disabling it

 

Environment

All of the following conditions need to be met.

  • GTM/DNS has remote LTM device object. Iquery connection is established and properly working between GTM/DNS device and LTM device.
  • Remote LTM device has virtual-server object.
  • On remote LTM device, virtual server's load-balancing pool is monitored by LTM device (i.e., pool monitor is configured).
  • On GTM/DNS, no monitor is directly attached to virtual server managed by LTM.
  • On GTM/DNS, "Monitor Disabled Objects" setting (GSLB : General) is default "no (unchecked)".
  • GTM/DNS software version 16.1.0 or later.

 

Here is example configuration of GTM/DNS device and remote LTM device. GTM/DNS device manages remote LTM device "bigipltm". Remote LTM device "bigipltm" has virtual server "vs1" and its pool "p1" is monitored by TCP monitor.

gtm datacenter /Common/MYDC { }
gtm server /Common/bigipdns {
    datacenter /Common/MYDC
    devices {
        bigipdns {
            addresses {
                10.1.1.150 { }
            }
        }
    }
    monitor /Common/bigip
    product bigip
}
gtm server /Common/bigipltm {
    datacenter /Common/MYDC
    devices {
        bigipltm {
            addresses {
                10.1.1.140 { }
                192.168.10.140 { }
            }
        }
    }
    monitor /Common/bigip
    product bigip
    virtual-server-discovery enabled
    virtual-servers {
        /Common/vs1 {
            destination 10.1.1.141:80
        }
    }
}
gtm global-settings metrics {
    metrics-collection-protocols { icmp }
}

 

Remote LTM device configuration is here.

ltm pool p1 {
    members {
        192.168.10.51:80 {
            address 192.168.10.51
        }
    }
    monitor tcp
}
ltm virtual vs1 {
    destination 10.1.1.141:http
    ip-protocol tcp
    mask 255.255.255.255
    pool p1
    profiles {
        tcp { }
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

Cause

Behavior change is expected and it is due to change in ID808829.

 

Recommended Actions

None. 16.1.0 or later behavior is normal behavior.
