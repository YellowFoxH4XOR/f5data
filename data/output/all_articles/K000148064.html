K000148064: If an origin pool is unhealthy due to a failed health check what happens to any existing connections to the pool?

Type
Support Solution
Published
2024-11-08
Updated
2025-02-27
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000148064

Description

I want to know what happens to any existing connections to a pool if the origin pool is unhealthy due to a failed health check.

Environment

  • F5® Distributed Cloud (XC)
  • Origin Pools
  • HTTP Load Balancer
  • Health Checks

Cause

None

Answer/Recommended Actions

  • All the existing connections will be drained. If a route is pointing to an unhealthy origin pool, the unhealthy origin pool will be retracted. If the route doesn't point to any healthy origin pools, the route itself will be retracted.
  • The Health Check will continue trying to connect to the Origin to test if the Origin Server is still  down or is up depending on the settings in the Healthy and Unhealthy Threshold you have configured:

Additional Information

The Performance Dashboard of the HTTP Load Balancer is a bit delayed in related to the information that is received once the Health Check is marked as Healthy or Unhealthy.

[IMPORTANT] The panel with the health information is also slightly delayed (It will take up to 3 minutes to see the Healthy or Unhealthy status of the Origin Pool).
