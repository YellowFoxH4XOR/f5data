Note: For information about chunked transfer coding, refer to section 3.6 in RFC:2616: Hypertext Transfer Protocol - HTTP/1.1 .

Many web applications that use chunked transfer encoding do not include the terminating zero-sized chunk in their responses. By default, the BIG-IP WebAccelerator does not consider the response complete until it receives the final zero-sized chunk. As a result, when the BIG-IP WebAccelerator is configured to optimize such an application, clients may receive an HTTP 500 error that appears similar to the following example, instead of the server response:

HTTP/1.0 500 Internal Server Error
Content-Type: text/html
Content-Length: 70
X-WAM-ORIG-CC:private, max-age=10
Expires:  Thu, 18 Jun 2009 22:59:07 GMT
Cache-Control: private, s-maxage=0, max-age=10
X-WAM-RC-MASQ: On
X-PvInfo: [S10201.C14036.A16496.RA16464.G0.U3A782A24].[OT/html.OG/pages]
Connection: Keep-Alive
Vary: Accept-Encoding
Accept-Ranges: none

The Using HTTP Headers chapter in the Policy Management Guide for the BIG-IP WebAccelerator System includes the following content regarding chunked transfer coding:

If you do not use the Content-Length header for the response, you must use chunked transfer coding. If you use chunked transfer coding, the BIG-IP WebAccelerator system does not consider content complete until it receives the final zero-sized chunk.

However, you can configure the allowIncompleteChunkedResponses setting in the /config/wa/pvsystem.conf file. This global setting allows the BIG-IP WebAccelerator to process the incorrectly chunked responses.

To enable the BIG-IP WebAccelerator to process incomplete chunked responses, perform the following procedure:

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Open the /config/wa/pvsystem.conf file in a text editor.
  3. Locate the allowIncompleteChunkedResponses setting, and change the value from false to true.
  4. Save the file.
  5. Exit the editor.
  6. Restart the pvac process by typing the following command:

    bigstart restart pvac
