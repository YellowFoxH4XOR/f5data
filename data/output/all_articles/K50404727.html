K50404727: "AbstractDigestAuthHandler does not support the following scheme: 'X-Auth-Token'" in Ansible after upgrading BIG-IP

Type
Support Solution
Published
2021-07-24
Updated
2025-04-02
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K50404727

Description

After upgrading BIG-IP version, you are getting the following error in Ansible when running the playbooks that was working prior to the BIG-IP version upgrade:

An exception occurred during task execution. To see the full traceback, use -vvv. The error was: ValueError: AbstractDigestAuthHandler does not support the following scheme: 'X-Auth-Token'

Environment

  • Upgraded BIG-IP version to 14.1.0 or higher
  • Running Ansible automation
  • Remote Authentication (LDAP or Active Directory) with User Template is configured for BIG-IP access.  For example:

    # tmsh list auth ldap system-auth
    auth ldap system-auth {
        login-attribute sAMAccountName
        search-base-dn CN=Users,DC=test,DC=local
        servers { 10.154.158.155 }
        ssl-check-peer enabled
        user-template %s@test.local                <===  User Template is used 
    }

    Note:  "User Template" does not appear in GUI under System  >  Users > Authentication when checking your current remote auth configuration.  See the Additional Information section below.

Cause
The user authentication for RestAPI is failing due to Bug ID 872165.  For more details, refer to K62336401.  

Recommended Actions

To workaround the issue, try one of the followings:

1. Create a local BIG-IP user account with the same name as the remote user that runs Ansible playbooks

     1)  Go to System > Users > User List
     2)  Hit Create (appearing on the right)
     3)  Enter User Name.  This should be the same user name as the remote user
     4)  Choose "Administrator" for the Role and choose Partition
     5)  Hit Add
     6)  Click Finished

Note: Password field does not appear in this Creation and it's expected.  While the authentication is set to remote, BIG-IP system lets you create a local user account but since the authentication goes to the remote authentication server, you can't set a local password.

2.   Change the LDAP/Active Directory Remote authentication from using a User Template to using a Bind account instead

       1)  Go to System > Users > Remote Authentication
       2)  Click Change
       3)  Configure Bind
       4)  Remove the current configuration for "User Template"
       5)  Hit Finished

Note:  If the Bind account is not correct, this would create an authentication issue when making a connection to BIG-IP GUI (not only for RestAPI).  Make sure to test the new configuration with Bind before making changes.

Additional Information
In order to verify if the User Template is currently used in your remote auth configuration via GUI, follow the steps below:

  1. Go to System > Users > Remote Authentication
  2. Click Change (Note:  By clicking Change, it will not change the current configuration).  You should see the User Template field.
