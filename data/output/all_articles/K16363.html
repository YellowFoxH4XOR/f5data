Known Issue

Connections may be directed to an incorrect pool member.

This issue occurs when all of the following conditions are met:

  • A Secure Socket Layer (SSL) virtual server is configured to use both of the following:

    • SSL persistence as the primary persistence method
    • Source address affinity as the fallback persistence method
  • The SSL persistence record lookup fails. For example, the client can send a different SSL session ID.

Even if a source address persistence record exists, when SSL persistence record lookup fails, the existing source persistence record is not used as fallback for a second SSL request from the same source.

Impact

Requests are load balanced to different pool members instead of persisting. Fallback persistence, in this case, does not work.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP iHealth lists Heuristic H515832 on the Diagnostics > Identified > Medium screen.
  • Connections that depend on session persistence fail to display content correctly.
