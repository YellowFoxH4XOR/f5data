Description

iApp configuration may have lost its association with one or more objects in the configuration. For instance:

  • iApp configuration screen shows incorrect virtual server name or IP
  • Virtual server overview screen does not show correct iApp name
 

Environment

  • BIG-IP version 11 - 15
  • iApp template was used to create a service
 

Cause

Manual modifications were made to the configuration which deleted the association.
 

Recommended Actions

Manually add the iApp name to the configuration objects in /config/bigip.conf

Impact of procedure: Edit errors in the /config/bigip.conf configuration file may prevent it from loading. F5 recommends using caution when editing the file and testing any changes during a maintenance window with consideration to the possible impact on your specific environment. F5 recommends taking a fresh backup before making configuration changes, and use appropriate caution while making manual changes.

Example: The following virtual server definition in /config/bigip.conf is missing a line which indicates the iApp service name:

  ltm virtual /Common/AD_SecureLDAP.app/AD_SecureLDAP_vs {
    creation-time 2019-11-21:15:29:34
    destination /Common/10.182.22.61:636
    ip-protocol tcp
    last-modified-time 2020-01-07:15:17:17
    mask 255.255.255.255
    ....etc.
    
Although it appears this was setup using an iApp and given the name "AD_SecureLDAP.app", the definition is missing an "app-service" entry and the virtual server will not show up as an iApp deployment.

You can fix this by manually adding the correct association back to the configuration using your preferred text editor:

  ltm virtual /Common/AD_SecureLDAP.app/AD_SecureLDAP_vs {
    app-service /Common/AD_SecureLDAP.app/AD_SecureLDAP                  <----add the 'app-service' entry with the correct name
    creation-time 2019-11-21:15:29:34
    destination /Common/10.182.22.61:636
    ip-protocol tcp
    last-modified-time 2020-01-07:15:17:17
    mask 255.255.255.255
    ....etc.

Save your changes and exit the editor, then run the command tmsh load sys config to reload the system configuration.

You may need to modify the "sys" stanza for the iApp as well, to update any stale or outdated information. Example:

  sys application service /Common/AD_SecureLDAP.app/AD_SecureLDAP {
    device-group ...etc.
    ...scroll down through the settings:
        vs_pool__vs_addr {
            value 10.182.23.183                  <----change this to correct IP
        }
        
Remember to run the tmsh load sys config command after making manual changes to the file.
