Known Issue

This is the result of a known issue. In BIG-IP version 10.2.0, following a reboot of a VIPRION appliance or an individual blade within a VIPRION cluster, a condition may occur in which clusterd incorrectly calculates the time skew between the blades and subsequently initiates a reboot of one or more of the blades. As a result, the system logs messages to the /var/log/tmm file that appear similar to the following example:

013a0005:4: Clusterd: rebooting system for time synchronization

01140029:5: HA cluster_time_sync clusterd fails action is reboot.emerg

01140043:0: Ha feature cluster_time_sync reboot requested.

This issue occurs after ntpd has updated the time forward on a blade. As ntpd continues to attempt to adjust the time following the reboot, it is possible that the same condition will occur after a reboot, and clusterd will reboot the blade repeatedly.

F5 Product Development tracked this issue as ID 342976 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, or PSM release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

If you are unable to upgrade to a fixed version, you can work around this issue by manually correcting the time skew condition between the blades.
