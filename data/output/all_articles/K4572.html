K4572: The /etc/login.conf file is overwritten during upgrade, which may prevent remote authentication

Known Issue

This is the result of a known issue. When you are running a version of 4.5.x or 4.6.x and upgrade to a later version of 4.5.x or 4.6.x, the /etc/login.conf file is overwritten. If you configured remote authentication (RADIUS or LDAP) for SSH, you will no longer be able to log in using remote accounts.

F5 Networks Product Development tracked this issue as CR47235 and CR47236 and it was fixed in BIG-IP and 3-DNS version 4.5.13 for the 4.5 software branch. For information about upgrading, refer to the BIG-IP or 3-DNS Release Notes.

This issue still exists in the 4.6 software branch.

Workaround

To work around this issue, perform the following steps.

  1. Log in to the command line as root.

    Note: You will be able to log in using the root account, because it is locally authenticated.

  2. Change directories to the /usr/local/ucs directory, by typing the following command:

    cd /usr/local/ucs

  3. Extract the login.conf file from the UCS archive that was saved during the upgrade process, by typing the following command:

    tar -zxvf backup_upgrade.ucs etc/login.conf

  4. Copy the previous login.conf file into the /etc directory, by typing the following command:

    cp etc/login.conf /etc/login.conf

  5. Remove the temporary copy of the login.conf file that you extracted, by typing the following command:

    rm /usr/local/ucs/etc/login.conf

  6. Remove the temporary directory that was created when you extracted the file, by typing the following command:

    rmdir /usr/local/ucs/etc

The old login.conf file is now restored and remote authentication should work correctly.
