Topic

You must enable Auto Last Hop for hardware SYN cookie protection to function.

Description

When you use the hardware SYN cookie protection feature on BIG-IP platforms that support the feature, you must also enable the Auto Last Hop feature. If you disable Auto Last Hop for a listener (for example, a virtual server, self IP address) SYN cookie protection is handled by the software instead of the hardware.

The following BIG-IP platforms are equipped with the HSBe2 chip, and you can configure the platforms to perform hardware SYN cookie protection:

  • BIG-IP 5000 series (C109)
  • BIG-IP 7000 series (D110)
  • BIG-IP 10000 series (D113)
  • BIG-IP 12000 series (D111)
  • BIG-IP i5600, i5800 (C119)
  • BIG-IP i7600, i7800 (C118)
  • BIG-IP i10600, i10800 (C116)
  • VIPRION B4300 series blade (A108, A110)
  • VIPRION B2250 blade (A112)
  • VIPRION B2100/2150 blade (A109, A113)

Note: Hardware SYN cookie protection may not function as expected on a wildcard virtual server, because hardware SYN cookie protection requires a destination IP/port pair to function properly. However, software SYN cookie protection will function as expected.

Note: If you are using an Auto Last Hop pool, hardware SYN cookie protection functions as expected, but it reverts to the default MAC address after SYN cookie protection becomes active.

For example:

  • When SYN cookie protection is not active for a virtual server, it uses a return MAC address that is specified in the last hop pool.
  • When SYN cookie protection is active for a virtual server, it uses Auto Last Hop, and the SYN cookies are generated in hardware.
