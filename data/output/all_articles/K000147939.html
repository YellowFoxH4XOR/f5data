Description

  • I'm not receiving logs in my SIEM
  • I'm getting inconsistent logs in my SIEM
  • I'm having log parsing issues with my SIEM

Environment

  • F5® Distributed Cloud Console

  • Global Log Receiver (GLR)

Cause

None

Answer/Recommended Actions

IBM QRadar

  • If you're not receiving any logs from Global Log Receiver to your QRadar instance, enable QRadar's debug mode. Debug mode will show any errors as well as any logs Global Log Receiver (GLR) is shipping to QRadar. Without enabling debug mode, QRadar gives no indication of an issue or that any logs have been received
    • Example Scenario(s): logs are being shipped successfully from Global Log Receiver (GLR) however QRadar discarded the logs due to parsing issues or payload sizes being exceeded all while giving zero indication that this was occurring in QRadar's interface
  • Ensure that the Max Payload Size in QRadar is set to a higher value than the Batch Bytes in your Global Log Receiver (GLR) configuration
  • If you are receiving inconsistent logs in QRadar or experiencing parsing issues, updating the Message Pattern configuration in QRadar to be (\{\"@timestamp\") is recommended for optimal log parsing

Splunk

  • When configuring your Splunk HEC Logs Endpoint do not include a path (e.g. /services/collector), the Splunk Receiver automatically configures the path to /services/collector/event and doing so will result in failures in log delivery
  • When configuring the Splunk HEC Token, do not include the "Splunk" portion of the token:
    • Token you may receive from Splunk: Splunk 3bfde684-b110-5f8c-90ef-28024c9b928g
    • Configure in Global Log Receiver Splunk Receiver as: 3bfde684-b110-5f8c-90ef-28024c9b928g
  • The endpoint path used by the Test Connection option in Global Log Receiver is /services/collector/health/1.0, if your Splunk Collector is not configured to accept this path, the Connection Test will report a failure however you should see logs being delivered successfully (assuming everything is configured properly)
