Description

Certain BIG-IP appliances include an internal FIPS card (HSM module) that provides a pool of dedicated RISC crypto cores for private-key operations. Depending on platform the card exposes up to 63 crypto cores (“accel devs”) for workload use.

In a multi-tenant deployment (BIG-IP tenants / vCMP guests), each tenant/guest can be assigned a dedicated FIPS partition. Partitions are isolated: keys and allocated crypto cores are not shared across partitions.

Note: Crypto cores allocated to one FIPS partition are not available to any other partition.

Environment

BIG-IP with internal FIPS card:

  • BIG-IP R10920DF
  • BIG-IP R5920DF
  • BIG-IP 10350F
  • BIG-IP i7820DF
  • BIG-IP i5820DF

Cause

This is expected behaviour. The FIPS card resources are partitioned to provide strict tenant isolation. Additionally on BIG-IP R10920DF and BIG-IP 10350F one core is reserved for management/FIPS services. 

Answer/Recommended Actions

When creating a FIPS partition, you configure:

  • Key capacity - maximum number of keys stored in that partition.
  • Crypto cores (shown as accel devs) allocated to the partition.

Sizing guidance

  • SSL/TLS performance (e.g., handshake TPS) for a tenant/guest is primarily driven by the number of crypto cores assigned to that tenant’s FIPS partition for operations using HSM-stored private keys with each core being able to handle around 500 TPS when using RSA 2048 keys. 
  • Crypto core allocation is independent of the number of TMM cores assigned to the tenant.
  • Use expected workload (TLS handshakes/sec, DNSSEC signing rate, etc.) to size accel devs.

Note: The “~500 TPS per core for RSA 2048” figure should be treated as a rough baseline and validated with representative testing.

Note: Only operations involving private keys stored on the HSM consume FIPS crypto cores. Private keys stored outside the HSM do not use these cores.
