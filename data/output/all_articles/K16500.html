Topic

Summary

Beginning in BIG-IP 11.3.0, systems that support collaborative hardware/software SYN cookie protection allow you to use the connection.syncookies.algorithm database key to change the location where the BIG-IP SYN cookie-encoded secret is generated and validated. The options for the key are hardware, software, or both. For more information about which BIG-IP systems support collaborative hardware/software SYN cookie protection, refer to K14779: Overview of BIG-IP SYN cookie protection (11.3.x - 12.x).

Note: In order to use hardware SYN cookie protection, you must enable the autolasthop feature. For more information, refer to K16887: Autolasthop must be enabled for hardware SYN cookie protection to function.

In BIG-IP 11.3.0 to 11.4.1, the default setting is software. Starting in BIG-IP 11.5.0 and later, to optimize performance, the default setting is hardware.

Important: This database key does not modify where SYN cookie protection is performed, it affects only where the SYN cookie-encoded secret is generated and validated.

Description

SYN cookie protection is activated when the SYN Activation Threshold setting value is exceeded. After the system is in SYN cookie mode, it responds to client SYN requests by sending a SYN-ACK response that contains an encoded secret. The BIG-IP system can use either the hardware or software algorithms for generating and validating SYN cookie-encoded secrets. When you modify the connection.syncookies.algorithm database key, generation and validation of SYN cookie-encoded secrets occurs as follows:

  • When set to hardware, the High-Speed Bridge (HSB) hardware always generates and validates all encoded secrets using the hardware algorithm.
  • When set to software, the Traffic Management Microkernel (TMM) generates and validates the initial encoded secrets using the software algorithm and notifies the HSB hardware that a specific virtual server is under attack. The HSB hardware makes a flow cache entry for the virtual server and for all subsequent SYN packets destined to the virtual server. The HSB begins generating and validating SYN cookie-encoded secrets using the hardware algorithm.

    Note: The SYN cookie has a bit set to indicate whether the encoded secret was generated using the hardware or software algorithm. From the initial SYN flood, SYN cookie responses tagged as software algorithm are passed back to TMM for processing.

  • For BIG-IP versions prior to 14.1.0: When set to both, the BIG-IP system automatically chooses the optimal setting for the platform after detecting any available HSB hardware.

Viewing the current setting

To view where the BIG-IP system currently calculates the value for the SYN cookie secret, type the following command from the BIG-IP command line:

Impact of procedure: Using the following command should not have a negative impact on your system.

tmsh list sys db connection.syncookies.algorithm

Modifying the current setting

To modify whether the BIG-IP system calculates the encoded SYN cookie secret in hardware or software, type the following command from the BIG-IP command line:

Impact of procedure: Using the following command may increase CPU usage.

tmsh modify sys db connection.syncookies.algorithm value <hardware> | <software> | <both>

For example, to perform the SYN cookie secret calculation in software only, you would type the following command:

tmsh modify sys db connection.syncookies.algorithm value software

Recommendation

The connection.syncookies.algorithm database key affects only where the SYN cookie-encoded secret is generated and validated. You should only modify the connection.syncookies.algorithm database variable when instructed by F5 Technical Support.

To configure where SYN cookie protection is performed in hardware or software, modify the affected protocol profile. For more information, refer to K14805: Configuring SYN cookie protection.
