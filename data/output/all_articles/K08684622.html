Known Issue

The BIG-IP APM rewrite process may utilize a high amount of memory.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a virtual server that is configured with an access profile and a rewrite profile.
  • Content processed through the virtual server contains files that exceed 20 MB.

Impact

A slow memory leak occurs. On devices with limited memory resources, this can cause the BIG-IP system to experience memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view memory allocated by the rewrite process, the allocated memory continually increases.
  • Over time, system performance degrades and the system eventually becomes unresponsive when configured for high availability (HA) failover to a peer in the device group.

Workaround

To work around this issue, you can restart the rewrite process. To do so, perform the following procedure:

Impact of workaround: The BIG-IP APM system is temporarily unable to process portal access traffic while it recovers from the rewrite process restarting.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the rewrite process, type the following command:

    restart /sys service rewrite

  3. To exit tmsh, type the following command:

    quit
