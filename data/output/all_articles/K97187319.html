K97187319: How to Limit Weak Cipher Suites for Port 9300 on a BIG-IQ DCD

Type
Support Solution
Published
2022-04-28
Updated
2026-04-06
Applies to
  • Virtual Editions
  • BIG-IQ
Source

Description

This article covers how to limit cipher suites for port 9300 on a BIG-IQ Data Collection Device (DCD). For information about how to limit TLS protocols for port 9300, refer to:

  • K000133411: How to limit TLS protocols for port 9300 on a BIG-IQ DCD

By default, the BIG-IQ Data Collection Device (DCD) has TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA384 configured as the default cipher suites for TCP port 9300. The Elasticsearch component uses this default configuration to transport data between nodes. However, it might accept some weak ciphers when you specifically use one to connect, for example, the TLS_DHE_RSA_WITH_AES_128_CBC_SHA.

There are some circumstances in which you might want to limit the acceptable cipher suites on TCP port 9300, for example, you may have security concerns when your VA Scan Report shows it supports weak ciphers. To limit the acceptable cipher suites, follow the Recommended Actions below.

Environment

  • BIG-IQ DCD
  • TCP port 9300
  • Cipher suites strength

Cause

The default Elasticsearch configuration for the BIG-IQ may accept weak ciphers.

Recommended Actions

If you want to limit the acceptable cipher suites, please consider following the below procedure:
Note: The below procedure is not a standard procedure. It might not be migrated during upgrade and it might be incompatible with future versions.

  1. Edit the Elasticsearch configuration file using an editing tool like vim:
vim /var/config/rest/elasticsearch/config/elasticsearch.yml
  1. Find the opendistro_security > ssl > transport settings displayed below:
 opendistro_security:
  disabled: false
  ssl:
    transport:
      pemcert_filepath: es_node.pem
      pemkey_filepath: es_node-key.pem
      pemtrustedcas_filepath: es_root-ca.pem
      enforce_hostname_verification: false
  1. Add the following lines to the transport settings. Do not modify the http settings.
enabled_ciphers:
- TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA384

For example,
opendistro_security:
  disabled: false
  ssl:
    transport:
      pemcert_filepath: es_node.pem
      pemkey_filepath: es_node-key.pem
      pemtrustedcas_filepath: es_root-ca.pem
      enforce_hostname_verification: false
      enabled_ciphers:
      - TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA384
 
Note: These can be specified using IANA cipher suite names, for example,
      TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
      TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
  1. Save the configuration file. If you use vim, press ESC then : and x.
  2. Restart the Elasticsearch process.
Impact of procedure: Elasticsearch will be temporarily unavailable during the restart.
bigstart restart elasticsearch

Additional Information

The communication between DCD nodes on port 9300 uses a model like mTLS, thus it should be safe even if it accepts weak ciphers. When a client uses a weak cipher to connect, it will finally fail as it does not have the correct client certificate.
