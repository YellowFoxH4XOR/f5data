Security Advisory Description

Inconsistent Interpretation of HTTP Requests ('HTTP Request Smuggling') vulnerability in mod_proxy_ajp of Apache HTTP Server allows an attacker to smuggle requests to the AJP server it forwards requests to. This issue affects Apache HTTP Server Apache HTTP Server 2.4 version 2.4.54 and prior versions. (CVE-2022-36760)

Impact

The connection is not closed when there is an invalid Transfer-Encoding header, allowing an attacker to smuggle requests to the AJP server, where it forwards requests.

Mitigation

You can mitigate this vulnerability using the following methods:

BIG-IP

  • Enforce RFC Compliance on the affected virtual server
  • Secure access to the management interface and self IP addresses of BIG-IP systems

F5OS-A and F5OS-C

  • Disable the proxy_ajp_module in the httpd container
  • Restrict the management interface to only trusted networks and users.

BIG-IP

Enforce RFC Compliance on the affected virtual server

You may block the attack in some cases by enabling the Enforce RFC Compliance option in the HTTP profile of the affected virtual server. To enforce RFC compliance, your BIG-IP system must contain the fix for the known issue described in K27551003: The BIG-IP system may not interpret an HTTP request the same way the target web server interprets it. To enforce RFC compliance, refer to the Recommended Actions section of that article.

Secure access to the management interface and self IP addresses of BIG-IP systems

If you follow best practices in securing access to the management interface and self IP addresses of BIG-IP systems, you help to minimize the attack surface. Review the following articles for guidance:

For self IP addresses

  • K13092: Overview of securing access to the BIG-IP system
  • K17333: Overview of port lockdown behavior (12.x - 17.x)
  • K31003634: The Configuration utility of the Single-NIC BIG-IP Virtual Edition now defaults to TCP port 8443
  • K51358480: The single-NIC BIG-IP VE may erroneously revert to the default management httpd port after a configuration reload

For the management interface

  • K46122561: Restrict access to the management interface using network firewall rules
  • K69354049: Use iptables to restrict access to the BIG-IP management interface for Configuration utility and iControl REST services

F5OS-A and F5OS-C

Disable the proxy_ajp_module in the httpd container

To disable the proxy_ajp_module in the httpd container in F5OS-A and F5OS-C, perform the following procedure:

  1. Log in to the management interface as root.
  2. To enter the bash shell of the http-server container, enter the following command:

    docker exec -it http-server /bin/bash

  3. To determine if the proxy_ajp_module command is loaded, enter the following command:

    httpd -M | grep proxy_ajp

    You may observe output similar to the following example:

    [...]
      proxy_ajp_module (shared)

  4. Using vi, open the /etc/httpd/conf.modules.d/00-proxy.conf file by entering the following command:

    vi /etc/httpd/conf.modules.d/00-proxy.conf

  5. Prepend a # character at the line for proxy_ajp_module.

    For example:

    #LoadModule proxy_ajp_module modules/mod_proxy_ajp.so

  6. To exit the editor, enter the following command:

    :wq!

  7. To determine if the proxy_ajp_module command is loaded, enter the following command:

    httpd -M | grep proxy_ajp

  8. Verfiy that proxy_ajp_module (shared) is no longer in the output.
  9. To exit the http-server container and management CLI, enter exit twice.
