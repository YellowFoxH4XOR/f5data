K000139050: Default wildcard virtual server will show all ports open when scanned through Nmap.

Type
Support Solution
Published
2024-03-27
Updated
2024-03-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000139050

Description

Scanning for open ports using Nmap on virtual IP address configured on the BIG-IP shows mutiple port opens. The status open for a port means service is listening for connections on these ports, this is determined when SYN/ACK packet is recevied for SYN packet send on that port.

nmap --open XX.XX.XX.XX <====
<......>
Host is up (0.055s latency).
<......>
Some closed ports may be reported as filtered due to --defeat-rst-ratelimit
PORT STATE SERVICE
<......>
20/tcp open ftp-data
23/tcp open telnet
24/tcp open priv-mail
26/tcp open rsftp
30/tcp open unknown
32/tcp open unknown
33/tcp open dsp
37/tcp open time
42/tcp open nameserver
43/tcp open whois
49/tcp open tacacs
53/tcp open domain

Environment

  • BIG-IP LTM
  • Wildcard virtual server 

Cause

This is expected behaviour with a wildcard virtual server which is special type of virtual server that has a network IP address as the specified destination address instead of a host IP address.

Whenever the BIG-IP does not find a specific virtual server based on the client's destination IP adress, it tries to match a wildcard virtual server that have the designated IP address of 0.0.0.0.

There are two types of wildcard virtual servers, default wildcard servers and port-specific wildcard servers. Default will have the port and address of 0.0.0.0:0 and port specific will have address 0.0.0.0 with a particular port example 80 (HTTP).

Recommended Actions

To understand the which IP address on the device is acknowledging the SYN packet send by the Nmap scanner on diferent ports, you should perform the below given steps.

  1. Take a packet capture and add the IP address of the client device from where nmap scanner will be executed, the file be stored in /var/tmp folder.
    tcpdump -envi 0.0:nnn -s0 host <client IP address> -w /var/tmp/Nmap.pcap

  2. On the client device run the nmap query with different combination. XX.XX.XX.XX is the destination IP address on which port scan needs to be performed, examples are given below
    nmap --open XX.XX.XX.XX ; nmap --sS XX.XX.XX.XX

  3. Once the output is provided by the nmap scanner, close the capture file (Ctlr + C). Download the file from the device and analysis the same using Wireshark.
  4. Look for SYN/ACK packets which are going towards the client IP address
    Note: To narrow down the results - suggest to use the following filters, XX.XX.XX.XX is the client IP address from nmap is executed:
    ((tcp.flags.ack == True && tcp.flags.syn == True) && (ip.dst == XX.XX.XX.XX)) 

  5. Refer the Low Details tab from the F5 Ethernet Trailer Protocol section, this will give us the name of the virtual server that is responding to the SYN packet:
    F5 Ethernet Trailer Protocol
      F5 Trailer Header - Version: 1
      Low Details
        F5 Trailer Header, Provider: 1, Type: 1
        [Ingress: False (OUT)]
        Flags: 0x00, Ingress: Out, Hardware Action: Not set
        Slot (1-based): 1
        TMM (0-based): 0
        Associated config object names
        Virtual Server: /Common/XXXXXXX
          Type: Virtual Server (0)
          Length: 22
          Name: /Common/XXXXXXX <=====
        Port: XX.XX
        Trunk: 
      Medium Details
      High Details

  6. Check the destination IP and port configured for the VS and also confirm the vlans traffic allowed through the VS

Additional Information

  • Check the port lockdown settings on the self-ips and config sync IP configured on the BIG-IP, refer K17333: Overview of port lockdown behavior (12.x - 17.x)
