Organizations rely on a Virtual Private Network (VPN) to provide their employees with continuous, secure, remote access to corporate resources. Use this article to help resolve issues that may arise with your VPN.

BIG-IP APM Network Access is an SSL VPN that does the following:

  • Authenticates employees, partners, and customers
  • Establishes a secure and encrypted tunnel to access corporate applications and resources
  • Uses standard a web browser, the BIG-IP Edge Client, or F5 Access

Overview

BIG-IP APM Network Access implements a point-to-point network connection over SSL that provides a secure solution, including when your network has firewalls and proxy servers.

BIG-IP APM Network Access works by doing the following:

  • A remote user enters the IP address or URL of a BIG-IP APM system in to a web browser, BIG-IP Edge Client, or F5 Access.
  • The browser starts an SSL connection to the BIG-IP APM system.
  • The system runs the access policy you configured. 
  • Depending on how you defined the access policy, it can validate authentication and authorization, and run client-side checks and other security controls.
  • The system assigns a BIG-IP APM Network Access resource to the remote worker's session. 

When you configure BIG-IP APM Network Access, you specify IP address pools, which the system assigns to the virtual network adapter on the remote user's device. This process enables the user to connect to organization applications and resources through a secure tunnel.

BIG-IP APM Network Access uses two types of transport layers: Transport Layer Security (TLS) and Datagram Transport Layer Security (DTLS). TLS uses TCP for transport, while DTLS uses User Datagram Protocol (UDP). DTLS has lower overhead than TCP and may be better suited for Voice over Internet Protocol (VoIP) and virtual desktop infrastructure (VDI) solutions. Both TLS and DTLS BIG-IP APM Network Access work in either an IPv4-only environment or a mixed IPv4 and IPv6 environment.

BIG-IP APM Network Access optimizes application access by supporting deflate, LZO, and bzip2 compression methods. BIG-IP APM also uses adaptive compression, which automatically selects the compression type based on network and traffic characteristics.

BIG-IP APM access policy evaluation

In order for remote users to access corporate applications and resources, their BIG-IP APM Network Access connections must conform to the security controls that you define in the BIG-IP APM access profile.

For example, the following diagram illustrates that the user must meet the following security controls to access network resources:

  1. User authenticates using Active Directory (AD).
  2. User's device has an up-to-date antivirus application.
  3. User's device possesses a valid machine certificate.

When users pass all security controls, they can connect to network resources.

 

Figure 2.2: Security controls for access to network resources

For more information about security controls you can use in access policy evaluations, refer to the Access Policy Item Reference chapter of the BIG-IP Access Policy Manager: Visual Policy Editor manual.

BIG-IP APM Network Access configuration operations

A BIG-IP APM Network Access configuration requires:

  • A Network Access resource.
  • An access profile, with an access policy that assigns:
    • A Network Access resource.
    • A Network Access or full webtop.
  • A lease pool that provides internal network addresses for tunnel clients.
  • A connectivity profile.
  • A virtual server that assigns the access profile.
