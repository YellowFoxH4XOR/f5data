Known Issue

BIG-IP APM authentication may fail under heavy load.

This issue occurs when the following condition is met:

  • The BIG-IP APM system is processing a large number of authentication requests and the back-end authentication server is slow or down.

Impact

User authentication fails for the access profile.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When receiving many authentication requests, the apd accept connection queue becomes full and the system logs error messages similar to the following example in the /var/log/apm file:

    err apd[<pid>]: 01490107:3: <session_ID>: AD module: authentication with ‘1439805563539620’ failed: Too many open files

  • You cannot authenticate to the BIG-IP APM system.
  • The apd process runs out of available file descriptors.

Workaround

To work around this issue, you can use the sysctl utility or the Traffic Management Shell (tmsh) to adjust the soconnmax, connlwm, and connhwm values.

Impact of workaround: Setting soconnmax, connlwm, and connhwm to unsuitable values may have a negative impact on your system and exhaust memory resources.

To set the soconnmax value to 1024, type the following command:

sysctl -w net.core.somaxconn=1024

To set the connlwm value to 480, type the following command:

tmsh modify sys db apm.apd.connlwm value 480

To set the connhwm value to 512, type the following command:

tmsh modify sys db apm.apd.connhwm value 512
