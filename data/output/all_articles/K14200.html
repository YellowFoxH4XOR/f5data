Known Issue

The BIG-IP system resets the Stream Control Transmission Protocol (SCTP) Payload Protocol Identifier (PPI) value to zero.

This issue occurs when all the following conditions are met:

  • You have an SCTP profile associated with a virtual server.
  • The BIG-IP system receives SCTP data with a non-zero PPI field.

Impact

Applications expecting a non-zero PPI value may fail.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • A packet trace of incoming and outgoing PPI data on the BIG-IP system will show the PPI ingress value as a non-zero value and the egress as a zero value.

Workaround

To work around this issue, you can use an iRule. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility as the administrative user.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the iRule.
  5. In the Definition box, copy and paste the following iRule:

    when CLIENT_ACCEPTED {
    set ppi 0
    set ppi_server 0
    SCTP::collect 1
    }

    when CLIENT_DATA {
    set ppi [SCTP::payload ppi]
    SCTP::release
    }

    when SERVER_DATA {
    set ppi_server [SCTP::payload ppi]
    clientside {SCTP::ppi $ppi_server}
    SCTP::release
    }

    when SERVER_CONNECTED {
    SCTP::ppi $ppi
    SCTP::collect 1
    }
  6. Click Finished.
  7. Associate this new iRule with the affected virtual server.
