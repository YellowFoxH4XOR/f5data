Description

On F5OS Chassis platforms, log messages such as sub_receiver: PSU insert/remove may appear repeatedly in the chassis-manager logs. These are often accompanied by related entries like cm_set_cdb_psu: No PSU data to push to confd, cm_update_confd_operation_data: cm_set_cdb_psu: Unable to update all PSU data, will retry, and Lost connection to ConfD.

Environment

  • Product: F5OS - Chassis
  • Platform: VELOS CX1610 + SX1610 (R100)
  • Software Version: 1.8.1
  • Configuration context: Chassis with multiple power supply unit (PSU) slots (some possibly empty), dual system controllers configured for high availability (active/standby).

Cause

This behavior is expected during a system controller failover event. When the active controller changes, the new active controller must re-discover and synchronize the state of all PSUs in the chassis. Only the currently active controller can read and broadcast PSU states; the standby controller does not maintain this information. During failover, a burst of PSU-related events is generated as part of this re-synchronization process, resulting in repeated PSU insert/remove log entries and associated messages. This is normal operation and does not indicate hardware failure or misconfiguration.

Recommended Actions

No action is required if these messages coincide with or immediately follow a system controller failover.
