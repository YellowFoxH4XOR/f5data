Topic

This article applies to BIG-IP ASM 9.4.x through 11.3.0. For information about other versions, refer to the following articles:

  • K15099: Configuring the BIG-IP ASM system in transparent bridge mode (11.4.0 and later)

Beginning in BIG-IP ASM 9.4.2, you can configure the BIG-IP ASM system in transparent bridge mode. This configuration allows the BIG-IP ASM system to be deployed within an existing network without making changes to the network, allowing traffic to be passed through the BIG-IP ASM system that is not checked by a security policy.

Before configuring the BIG-IP ASM system in transparent bridge mode

Before configuring the BIG-IP ASM system in transparent bridge mode, you must have the following information:

  • If tagging is used on the network, you must note the 802.1q VLAN tag number to be used.

    Important: If you are using tagging within your network you need to re-tag and supply separate tags on the client and server-side VLANs.

  • Note free or available IP address from the network to which the BIG-IP ASM system will be deployed; this is required for configuring the self IP address.
  • Note any known IP addresses and ports of the web services that will be secured by the BIG-IP ASM system.

Configuring the BIG-IP ASM system in transparent bridge mode

To configure the BIG-IP ASM system in transparent bridge mode, perform the following procedures:

Important: In this Solution, F5 assumes that the BIG-IP ASM system has already been through the basic Licensing and Configuration steps outlined in the Installation, Licensing, and Upgrades for BIG-IP systems manual and is ready to continue to the next step of configuring the traffic management network.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • Configuring the VLAN Group
  • Specifying default gateway to be used by the BIG-IP ASM system (Optional)
  • Configuring the BIG-IP ASM system to secure HTTP services
  • Advanced Configuration for handling HTTPS traffic

Configuring the VLAN Group

To configure the VLAN Group, perform the following procedures:

  • Creating the client-side VLAN
  • Creating the server-side VLAN
  • Creating the VLAN Group
  • Configuring a Self IP address to assign to the VLAN Group

Creating the client-side VLAN

  1. Log in to the Configuration utility.
  2. Select Network.
  3. Select VLANs.
  4. Click Create.
  5. Name the VLAN using the following syntax:

    clientside_vlan

  6. Specify the interface to use for the client-facing VLAN.
  7. You can optionally specify a VLAN tag.

    Note: This tag must be different from the one used on the server-side VLAN.

  8. Click Finished.

This will return you to the VLAN creation screen.

Creating the server-side VLAN

  1. Log in to the Configuration utility.
  2. Select Network.
  3. Select VLANs.
  4. Click Create.
  5. Name the VLAN using the following syntax:

    serverside_vlan

  6. Specify the interface to use for the server facing VLAN.
  7. You can optionally specify a VLAN tag.

    Note: This tag must be different from the one used on the client-side VLAN.

  8. Click Finished.

You will return to the VLAN creation screen.

Creating the VLAN Group

  1. Log in to the Configuration utility.
  2. Select Network.
  3. Select VLANs.
  4. Click Create.
  5. From the VLAN Groups menu, select the List option.
  6. Click Create.
  7. Name the VLAN Group using the following syntax:

    client_server_group

  8. Select the client and server-side VLANs created previously from the Available box.
  9. Move the VLANs to the Members box using the << button.
  10. Select Opaque for the Transparency Mode, which specifies that the system will use Proxy ARP with Layer 3 forwarding.
  11. Select the Bridge All Traffic check box, which allows the system to forward all frames including non-IP traffic.
  12. Clear the Bridge in Standby check box, which is for use in redundant configurations to prevent the standby unit from passing traffic.
  13. Click Finished.

Configuring a self IP address to assign to the VLAN Group

  1. Select Network.
  2. Select Self IPs.
  3. Click Create.
  4. Specify the IP address and subnet mask to be used by the BIG-IP ASM system.
  5. Select the VLAN Group created previously for the VLAN.
  6. Click Finished.

Specifying a default gateway to be used by the BIG-IP ASM system (Optional)

Note: This procedure is optional and used only for traffic that is generated locally by the BIG-IP ASM system.

  1. Select Network.
  2. Select Routes.
  3. Click Add.
  4. Specify the necessary information for the gateway that should be used by the BIG-IP ASM system.
  5. Click Finished.

Configuring the BIG-IP ASM system to secure HTTP services

The following two options are available when securing HTTP services with a BIG-IP ASM system in bridge mode:

  • Process and protect all sites with a single wildcard forwarding virtual server

    Advantage: If you are protecting a small number of individual sites, using a single forwarding virtual server and multiple HTTP Classes to separate and direct the traffic to different security policies is easier to initially configure.

    Disadvantage: If you are protecting a large number of individual sites, using a single forwarding virtual server and multiple HTTP Classes to separate and direct the traffic to different security policies can quickly become overwhelming.

  • Process and protect individual sites with a host-specific IP forwarding virtual servers and HTTP Classes configured with the specific sites IP address

    Advantage: Using multiple specific forwarding virtual servers and individual HTTP Classes to protect traffic for individual sites allows the administrator to keep traffic separated and security policies manageable.

    Disadvantage: Using multiple specific forwarding virtual servers and individual HTTP Classes to protect traffic for a large number of individual sites introduces additional configuration steps to ensure that traffic is handled and passed correctly. For example, you must disable ARP on the virtual servers to prevent ARP overwrites and interruption of traffic flow.

Configuring a single forwarding virtual server or specific IP virtual servers, Pools, and HTTP Classes

To configure a single forwarding virtual server, or specific IP virtual servers, Pools, and HTTP Classes, perform the following procedures:

  • Creating a Pool for each host
  • Creating an HTTP Class Profile
  • Creating a single wildcard forwarding 0.0.0.0:80 virtual server
  • Creating host-specific IP forwarding virtual servers

Creating a Pool for each host

  1. Select Local Traffic.
  2. Select Pools.
  3. Click Create.
  4. Enter a name for the pool.

    Note: For easy reference, name the pool after the host with which it will be associated.

    For example:

    www.askf5.com

  5. Select a monitor from the Available list.
  6. Use the << button to add the monitor to the Active Health Monitor box.
  7. Enter the address and port number of the server associated with the hostname.
  8. Click Add.

    Repeat Steps 5 and 6 if more than one server is associated with the same hostname.
  9. Click Finished.

    Repeat and create a pool for each hostname that will be secured using the BIG-IP ASM system.

Creating an HTTP Class profile

  1. Select Local Traffic.
  2. Select Profiles.
  3. Select HTTP Class from the Protocol menu.
  4. Click Create.
  5. Name the HTTP Class after the name of the site that the class will protect.

    Note: Using the host name of the site will allow for easier administration.

    For example:

    www.askf5.com

  6. Select the Application Security check box.
  7. Select Enabled.
  8. Select the Hosts check box.
  9. Select Match Only for the Host option.
  10. Enter the host name for the site to protect.

    For example:

    www.askf5.com

  11. Select the Send To check box.
  12. Select the Pool to be associated with the HTTP Class.

    Note: At this point in the procedure, you have the option to configure any additional requirements for the HTTP Class profile. For more information about available options that can be set within the HTTP Class, refer to the Configuration Guide for BIG-IP Application Security Management. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  13. Click Finished.

    Repeat and create an HTTP Class for each hostname and associate that HTTP Class with the appropriate pool.

    Note: Any HTTP traffic that does not match any HTTP Class Profile will be forwarded directly back to the server without inspection. If you do not want this behavior to occur, F5 recommends that you create a catch all HTTP Class profile that either redirects or allows the BIG-IP ASM system to scan the content before forwarding it to the server.

Creating a single wildcard forwarding 0.0.0.0:80 virtual server

  1. Select Local Traffic.
  2. Select Virtual Servers.
  3. Click Create.
  4. Enter a name for the virtual server.
  5. Select Network for the Type.
  6. Enter 0.0.0.0 for the address.
  7. Enter 0.0.0.0 for the netmask.
  8. For the Service Port, enter port 80 or select HTTP from the Service Port list.
  9. Select HTTP from the HTTP Profile box.
  10. In the Resources section, select the appropriate HTTP class profile from the HTTP Class Profiles setting.
  11. Click the << button to add the class profile to the Enabled section.
  12. Click Finished.

Creating host-specific IP forwarding virtual servers

  1. Select Local Traffic.
  2. Select Virtual Servers.
  3. Click Create.
  4. Enter a name for the virtual server.

    Note: For ease in administering multiple hosts, use the hostname of the site for which the virtual server will handle traffic.

    For example:

    www.askf5.com

  5. Enter the IP address of the host.

    Note: This will be the same address as the IP address of the host server.

  6. For the Service Port, enter port 80 or select HTTP from the Service Port list.
  7. Select Advanced from the Configuration box.
  8. Select HTTP from the HTTP Profile box.
  9. In the Resources section, select the appropriate HTTP class profile that is associated with the hostname from the HTTP Class Profiles setting.
  10. Click << to add it to the Enabled section.
  11. Clear the Address Translation check box.
  12. Click Finished.

    This will return you to the Virtual Servers screen. Repeat Steps 3 through 12 for each virtual server you want to add.

    Important: The following steps are important. They allow the BIG-IP ASM virtual servers to answer requests for the given IP address and port, but prevent the virtual servers from advertising the IP address as belonging to the BIG-IP ASM MAC address, which allows the BIG-IP ASM system to be transparent with the devices in the network that it bridges.

  13. Select the Virtual Address List.
  14. Click the IP address that was just assigned to the previously-created virtual server.
  15. Clear the ARP check box.
  16. Click Update.

    Repeat Steps 14 through 16 for each virtual server address you added.

    Note: Any HTTP traffic that does not match any HTTP Class Profile will be forwarded directly back to the server without inspection. If you do not want this behavior, F5 recommends that you create a catch all HTTP Class profile that either redirects or allows the BIG-IP ASM system to scan the content before forwarding it to the server.

Advanced Configuration for handling HTTPS traffic

You can use the previous steps for handling HTTPS traffic if the system is licensed to allow termination of SSL traffic on the BIG-IP ASM system.

To set up the system for handling and terminating SSL traffic, and allowing the BIG-IP ASM system to handle SSL communication between itself and the client, you must take the following additional considerations into account:

  • Determine whether to create a forwarding virtual server or individual IP specific virtual servers. Only a single Client SSL profile can be associated with a virtual server, which means all web servers behind a 0.0.0.0 forwarding virtual server would use the same SSL certificate.
  • Configure single or multiple Client SSL Profiles. This option depends on the type of virtual server configuration you choose.
  • Determine if SSL will be terminated on the BIG-IP system itself. If security requirements specify that SSL communication must be determined on the web server, then a Client SSL Profile and a Server SSL profile must be created to allow the BIG-IP ASM system to decrypt and parse the content before re-encrypting and sending the information to the appropriate web server.

Configuring the BIG-IP ASM to secure and monitor HTTPS services

For the BIG-IP ASM system to handle and monitor HTTPS traffic, the system must be allowed to terminate SSL traffic. This type of configuration introduces challenges that must be addressed in order to properly secure, monitor, and direct traffic to the correct web server. The advantages and disadvantages for each configuration are listed below.

  • Forwarding 0.0.0.0:443 virtual server with a single Client SSL profile

    Advantage: Single forwarding 0.0.0.0:443 virtual server with a single Client SSL profile is the simplest SSL configuration for the BIG-IP ASM system, allowing one first server and certificate to handle all SSL requests received by the BIG-IP ASM system.

    Disadvantage: While this is the simplest of the SSL configurations, it means that all web servers handled by the single virtual server will need to use the same SSL certificate. If all of the web sites are within the same domain, a wild card certificate can be used. This type of certificate allows multiple servers with the same domain name to be validated while allowing unique host names. If there are multiple web server domains, this is not the best method to use as user browsers/applications will report certificate mismatch errors if the domain names do not match.

  • Individual IP SSL forwarding virtual servers and individual Client SSL profiles

    Advantage: Individual web servers are handled by their own unique SSL virtual server, HTTP profile, and Client SSL profile. This is easier to administer as each site is handled by its own unique configuration and does not share profiles with other websites.

    Disadvantage: This requires an administrator to create individual virtual servers, HTTP profiles, and Client SSL profiles. For a large number of websites, this can be tedious.

  • Re-encrypt communication to the web server using a Server SSL profile

    This option will work with either previously-listed scenario, and has the same advantages and disadvantages of either scenario. The only difference is the introduction of a Server SSL profile that will allow the BIG-IP ASM system to re-encrypt the communication before it is sent to the web server.

Creating a Client SSL profile

Important: With the following procedure, F5 assumes that you have followed the previously-listed steps for creating the necessary pools and HTTP Class Profiles, as this section just documents the creation of the SSL profiles and virtual servers.

Note: F5 assumes that you have already created an SSL key and obtained an SSL certificate from a Certificate Authority, and it has already been imported. For more information about creating and importing SSL keys and certificates, refer to the Configuration Guide for BIG-IP LTM. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  1. Select Local Traffic.
  2. Select Profiles.
  3. Select Client from the SSL menu.
  4. Click Create.
  5. Enter a name for the New Client SSL Profile.

    For example, if you are creating an individual Client SSL profile for a specific website, you could enter the following:

    www.askf5.com

    Alternatively, if you are creating an individual Client SSL profile that will be used by multiple websites with the same domain name but different host names, you could enter the following:

    askf5.com

  6. Select the Certificate and Key check boxes.

    Note: This requires the use of a wildcard SSL certificate. For more information regarding wildcard certificates, contact your Certificate Authority.

  7. You also have the option to select the Custom check box to enable all of the options available in the Client SSL Profile, which would allow you to modify any of the options listed.

    Note: For information regarding the various options available to the Client SSL profile, refer to the Configuration Guide for BIG-IP LTM. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  8. In the Certificate menu, select the name of the SSL certificate that will be used for the website.
  9. In the Key menu, select the name of the SSL key associated with the SSL certificate in Step 8.
  10. Click Finished.

    Repeat Steps 3 through 9 if you want to create additional individual client SSL profiles.

Creating a forwarding 0.0.0.0:443 virtual server

Important: F5 assumes that you have followed the previously-listed steps for creating the necessary pools and HTTP Class Profiles, as this section just documents the creation of the SSL Profiles and virtual servers.

  1. Select Local Traffic.
  2. Select Virtual Servers.
  3. Click Create.
  4. Enter a name for the virtual server.
  5. Select Network for the Type.
  6. Enter 0.0.0.0 for the address.
  7. Enter 0.0.0.0 for the netmask.
  8. For the Service Port, enter port 443 or select HTTPS from the Service Port list.
  9. Select HTTP from the HTTP Profile box.
  10. In the Resources section, select the appropriate HTTP class profile from the HTTP Class Profiles setting.
  11. Click << to add to the Enabled section.
  12. Select the previously-created SSL profile from the SSL Profile (Client) menu.
  13. Click Finished.

Creating a specific IP forwarding virtual server

Important: F5 assumes that you have followed the previously-listed steps for creating the necessary pools and HTTP Class Profiles, as this section just documents the creation of the SSL Profiles and virtual servers.

  1. Select Local Traffic.
  2. Select Virtual Servers.
  3. Click Create.
  4. Enter a name for the virtual server.

    Note: For ease in administrating multiple hosts, use the hostname of the site for which the virtual server will handle traffic.

    For example:

    www.askf5.com

  5. Enter the IP address of the host.

    Note: This will be the same address as the IP address of the host server.

  6. For the service port, enter port 443 or select HTTPS from the Service Port list.
  7. Select Advanced from the Configuration box.
  8. Select HTTP from the HTTP Profile box.
  9. In the Resources section, select the appropriate HTTP class profile that is associated with the hostname from the HTTP Class Profiles setting.
  10. Click << to add it to the Enabled section.
  11. Clear the Address Translation check box.
  12. Select the previously-created SSL profile from the SSL Profile (Client) menu.
  13. Click Finished.

    This will return you to the Virtual Servers screen. Repeat Steps 3 through 13 for each virtual server you want to add.

    Important: The following steps are important as they allow the BIG-IP ASM virtual servers to answer requests for the given IP address and port, but prevent the virtual servers from advertising the IP address as belonging to the BIG-IP ASM MAC address, which allows the BIG-IP ASM system to be transparent with the devices in the network that it bridges.

  14. Select the Virtual Address List.
  15. Click the IP address that was just assigned to the previously-created virtual server.
  16. Clear the ARP check box.
  17. Click Update.

    Repeat Steps 14 through 16 for each virtual server address that you added.

    Note: Any HTTP traffic that does not match an HTTP Class Profile will be forwarded back to the server without inspection. If you do not want this behavior, F5 recommends that you create a catch-all HTTP Class profile that either redirects or allows the BIG-IP ASM system to scan the content before forwarding it to the server.

Re-encrypting communications before sending to web server

Configuring re-encryption requires the addition of a Server SSL profile; the pool members must be configured with port 443 or the appropriate SSL port on which to listen.

Note: If the SSL port for the pool members is different than port 443, the corresponding forwarding virtual server must also be configured to use the same port.

Creating a Server SSL profile

You can use the default Server SSL profile if you do not intend or require any special configuration. Otherwise, you can use the following procedure to create a generic Server SSL profile whose options can be changed at a later date, if necessary. To create a Server SSL profile, perform the following procedure:

Important: F5 assumes that you have followed the previously-listed steps for creating the necessary pools and HTTP Class Profiles, as this section just documents the creation of the SSL Profiles and virtual servers.

Note: The following configuration is a basic Server SSL profile for which the BIG-IP ASM system will appear as though it is a client to the web server. If your security requirements specify that the client must pass credentials or identify itself with an SSL certificate, refer to the Configuration Guide for BIG-IP Local Traffic Management. 

  1. Select Local Traffic.
  2. Select Profiles.
  3. Select Server from the SSL menu.
  4. Click Create.
  5. Enter a name for the New Client SSL profile.

    For example, if you are creating an individual Server SSL profile for a specific website, you could enter the following:

    www.askf5.com

    Alternatively, if you are creating an individual Server SSL profile that will be used by multiple websites, you could enter the following:

    askf5.com

  6. Click Finished.

    Repeat Steps 4 through 6 if you want to create additional individual Server SSL profiles. You must also associate the Server SSL profiles with the corresponding SSL virtual server that you previously created, to which you want to have SSL encryption to the back end server.
