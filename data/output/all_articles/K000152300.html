K000152300: How to block traffic towards virtual server matching ip addresses that belong to specific bgp ASN

Type
Support Solution
Published
2025-07-01
Updated
2025-07-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 17.1.2, 17.1.1, 17.5.X, 17.1.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000152300

Description

To block traffic towards virtual server matching ip addresses that belong to specific  BGP Autonomous System Number (ASN) 

Environment

  • Big-IP LTM only

Cause

BIG-IP LTM does not have visibility into ASN information for incoming traffic because ASN data is not included in packet headers. Blocking by ASN requires mapping the ASN to its announced IP prefixes externally 

Recommended Actions

Automate retrieval of BGP ASN IP prefixes from external sources, update an external data group, and apply an iRule to drop matching traffic.

Following in one such example:

1.Retrieve the list of IP prefixes for the target ASN (e.g., AS65535) and save it to  a file

 # curl https://stat.ripe.net/data/announced-prefixes/data.json?resource=AS65535 2>/dev/null | grep "prefix\"" | awk '{print $2}' | cut -d '"' -f 2 | sed 's/^/network /g; s/$/,/g' > /var/tmp/blockipfromAS65535.txt

Note: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge

2.Using above file create external datagroup

# tmsh create ltm data-group external blockip-dg2 source-path file:/var/tmp/blockipfromAS65535.txt type ip 

3.Create an irule using above data group 

Example:

when FLOW_INIT {
   if { [class match [IP::remote_addr] equals blockip-dg2]} {
      log local0. "IP [IP::client_addr] matches ASN"
      drop
    }
}

4. Finally attach this iRule to each relevant virtual server. 

5. One can make this task automated after creating it manually for the first time to update changing BGP ASN prefixes in the datagroup

copy the following content into a file 

#!/bin/bash

#Get the list from external link for AS65535
curl https://stat.ripe.net/data/announced-prefixes/data.json?resource=AS65535 2>/dev/null | grep "prefix\"" | awk '{print $2}' | cut -d '"' -f 2 | sed 's/^/network /g; s/$/,/g' > /var/tmp/blockipfromAS65535.txt

#modify the data-group to get it updated
tmsh modify ltm data-group external blockip-dg2 source-path file:/var/tmp/blockipfromAS65535.txt

#notify once done to ltm log file
logger -p local0.notice "IP list for AS65535 has been updated at $(date)"

6. make it executable

# chmod +x /var/tmp/scripts/blocklistforAS65535

7. Edit crontab using below command to add a new job

#crontab -e 

Example : Below will run everyday 8AM and update datagroup file 

# crontab -l

0 8 * * * /var/tmp/scripts/blocklistforAS65535

Additional Information

The filestore containing the external data group will sync between HA units, but custom scripts and cron jobs will not—ensure automation exists on all units as needed. 

This method requires ongoing maintenance to keep up with changes in ASN allocations and their associated prefixes. Blocking by BGP ASN remains unsupported natively and relies entirely on external mapping and automation.
