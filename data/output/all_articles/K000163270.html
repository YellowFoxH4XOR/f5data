K000163270: Edge Client is looping when an endpoint check precedes an OAuth Scope agent

Description

A limitation exists when using the Edge Client with BIG-IP APM and OAuth authentication.

If an Endpoint Security check (client side), such as a Firewall check or any other, is evaluated immediately before the OAuth Scope agent, the Edge Client will run and execute all the agents as expected but will never establish the VPN.

Instead, the Edge Client will end up starting a new session and re-evaluating the Access Policy over and over again.

Environment

  • Windows or Mac Edge Client
  • An Access Policy containing an Endpoint Security (client side) check immediately before an OAuth Scope agent

Example:

Start -> Firewall -> OAuth Scope -> Advanced Resource Assign -> Allow

Cause

The precise root cause has not been confirmed.

This behavior is tracked in bug ID 2444321 on Windows and bug ID 925549 on Mac.

Recommended Actions

Use one of the following Access Policy arrangements:

  • Place the endpoint check after the OAuth Scope agent:
Start -> OAuth Scope -> Firewall -> Advanced Resource Assign -> Allow
  •  Insert a user-interaction agent between the endpoint check and the OAuth Scope agent. A Message Box or a Selection Box can be used:
Start -> Firewall -> Message Box -> OAuth Scope -> Advanced Resource Assign -> Allow
