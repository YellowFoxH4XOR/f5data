Topic

BIG-IQ Centralized Management can act as a remote proxy for representational state transfer (REST) calls to a BIG-IP device. This capability can remove the need to send REST requests directly to a BIG-IP device and allows a single authentication point.

You should consider using these procedures under the following conditions:

  • You have a BIG-IQ system available within your network, and the system can communicate with the BIG-IP device directly.
  • You have BIG-IP devices within your environment that you want to manage from a central point.

Description

You can proxy iControl REST calls to BIG-IP devices through the BIG-IQ system. To use the REST proxy for a BIG-IP device, you must enable that feature in the BIG-IQ object reference for that BIG-IP device. This feature is disabled by default.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • The BIG-IQ device must have network connectivity to the BIG-IP management (MGMT) interface.
  • The BIG-IQ user must have administrative privileges on the BIG-IQ device.

Procedures

BIG-IQ administrators can enable the REST proxy feature on a managed BIG-IP device either during the discovery process or on a previously discovered device. Choose one of the two following procedures, depending on which scenario applies to you:

  • Enable the BIG-IQ system as a REST proxy during the BIG-IP discovery process
  • Enable the BIG-IQ system as a REST proxy after BIG-IP discovery is complete

After you have enabled the REST proxy feature, the following procedure explains how to use it

  • Using the REST proxy on the BIG-IQ system

Enable the BIG-IQ system as a REST proxy during the BIG-IP discovery process

If you have BIG-IP devices you would like to discover, you can enable the REST proxy feature during the discovery process. When you discover a device using iControl REST, you must add it to both the cm-bigip-allDevices and cm-bigip-allBigIpDevices groups. The following procedure creates two JSON text files, one for each group, that include the BIG-IP MGMT IP address, the admin username and password, the directive to update the REST framework, and for one file, the directive to enable the REST proxy feature. You will send the JSON data as the payload in an HTTP POST request using the cURL utility. The following options are used with the cURL command:

  • -k

    Ignores SSL certificate warnings.

  • -s

    Enables silent mode. With this option, the cURL command does not show the progress meter or error messages.

  • -H "X-F5-Auth-Token: <token>"

    By default, you must authenticate with a token to access the iControl REST API on the BIG-IQ system.

  • -X POST

    Changes the request method from the default of GET, to an HTTP POST.

  • -d@filename

    Allows the cURL command to load data from the given file name, URL-encode the contents, and pass the contents on in the POST.

Impact of procedure: The BIG-IQ system communicates with the restjavad interface on the BIG-IP device, and this process restarts when the REST framework is updated. This update does not affect traffic that traverses the BIG-IP system. Enabling the REST proxy feature for a BIG-IP device on the BIG-IQ system should have no impact on the BIG-IQ system.

  1. Log in to the BIG-IQ command line or a remote Linux host.
  2. Go to the /var/tmp directory by entering the following command:

    cd /var/tmp

  3. Use your preferred text editor to create a text file named discover.json.
  4. In the file, use the following example text and replace the BIG-IP IP address, username, and password values to reflect your environment. The key, address, should have the BIG-IP system's MGMT IP address as the value.

    Note: The automaticallyUpdateFramework attribute is required because the REST framework on the BIG-IP device must be the same as the version on the BIG-IQ system.

    {
      "address": "192.0.2.1",
      "userName": "admin",
      "password": "admin",
      "automaticallyUpdateFramework": "true"
    }

  5. In the /var/tmp directory, make a copy of the discover.json file by entering the following command:

    cp discover.json discover_and_enable_proxy.json

  6. Use a text editor to edit the text file named discover_and_enable_proxy.json.
  7. Add the isRestProxyEnabled property to the existing JSON object in discover_and_enable_proxy.json file. For example:

    {
      "address": "192.0.2.1",
      "userName": "admin",
      "password": "admin",
      "automaticallyUpdateFramework": "true",
      "properties": {
        "isRestProxyEnabled": "true"
      }
    }

  8. Obtain a BIG-IQ authentication token. For more information, refer to K04452074: Overview of using the BIG-IQ system authentication token.
  9. Create a shell variable called f5token to store the BIG-IQ authentication token using the following syntax:

    export f5token=<BIG-IQ authentication token obtained in step 8>

    Note: The authentication token has a timeout of 300 seconds, so you may need to repeat this step during the procedure.

    Note: If you have the jq utility installed on the client system, you can use command substitution to assign the f5token variable. For example:

    export f5token=$(curl -ks -X POST -d '{"username":"admin", "password":"admin"}' https://192.0.2.210/mgmt/shared/authn/login|jq .token.token)

  10. Use the cURL utility to discover your BIG-IP device and add it to the cm-bigip-allDevices group, by using the following syntax where you reference the BIG-IQ authentication token with $f5token:

    Note: If you are logged into the BIG-IQ system, you can direct the cURL commands to localhost. Also, the pipe to the JSON formatting utility is optional as it may not be present on your system.

    curl -ks -H "X-F5-Auth-Token: $f5token" -X POST -d@discover.json https://<mgmt IP address of BIG-IQ>/mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices[|json formatting utility]

    For example:

    curl -ks -H "X-F5-Auth-Token: $f5token" -X POST -d@discover.json https://192.0.2.210/mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices|json_pp

Enable the BIG-IQ system as a REST proxy after BIG-IP discovery is complete

If the BIG-IP devices were previously discovered and do not have the REST proxy feature enabled, you can update the devices after discovery is complete. The following procedure adds or updates the value using the cURL utility and the appropriate JSON payload. 

The following options are used with the cURL command:

  • -k

    Ignores SSL certificate warnings.

  • -s

    Enables silent mode. With this option, the cURL command does not show the progress meter or error messages.

  • -H "X-F5-Auth-Token: <token>"

    By default, you must authenticate with a token to access the iControl REST API on the BIG-IQ system.

  • -X PATCH

    Changes the request method from the default of GET, to an HTTP PATCH.

  • -d@filename

    Allows the cURL command to load data from the given file name, URL-encode the contents, and pass the contents on in the PATCH.

Impact of procedure: Enabling the REST proxy feature for a BIG-IP device on the BIG-IQ system does not affect the BIG-IQ system unless items found in the existing properties are not included in the JSON payload.

  2. Obtain a BIG-IQ authentication token. For more information, refer to K04452074: Overview of using the BIG-IQ system authentication token.

Use the REST proxy on the BIG-IQ system

After you enable the REST Proxy feature for a given BIG-IP device, you can now send iControl REST calls to that BIG-IP device through the BIG-IQ system. To do so, perform the following procedure:

Impact of procedure: Using the REST proxy feature does not affect the BIG-IQ system. However, making changes to the BIG-IP system in the request can impact the BIG-IP system.

  1. Log in to a remote Linux host.
  2. Obtain a BIG-IQ authentication token. For more information, refer to K04452074: Overview of using the BIG-IQ system authentication token.
  3. Create a shell variable called f5token to store the BIG-IQ authentication token using the following syntax:

    f5token=<BIG-IQ authentication token obtained in step 2>

    Note: If you have the jq utility installed on the client system, you can use command substitution to assign the f5token variable. For example:

    f5token=$(curl -ks -X POST -d '{"username":"admin", "password":"admin"}' https://192.0.2.210/mgmt/shared/authn/login|jq .token.token)

  4. Find the UUID  for the BIG-IP device that you want to proxy to by entering the following command where you reference the BIG-IQ authentication token with $f5token:

    Note: Also, the pipe to the JSON formatting utility is optional as it may not be present on your system.

    curl -ks -H "X-F5-Auth-Token: $f5token" https://<mgmt IP address of BIG-IQ>/mgmt/shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices[|json formatting utility]

    For example:

    curl -ks -H "X-F5-Auth-Token: $f5token" https://192.0.2.210/mgmt/shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices|json_pp

    The output returns all discovered devices on the BIG-IQ system and can be challenging to search through when locating a single device. However, if you have the json_pp utility (or another JSON formatting tool), you can combine it with the egrep utility to print only the host name and UUID of each device. For example:

    curl -ks -H "X-F5-Auth-Token: $f5token" https://192.0.2.210/mgmt/shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices/|json_pp|egrep '(hostname|uuid)'

  5. After you have found the UUID, you append /rest-proxy/ to the full device URI on the BIG-IQ system followed by the iControl REST URI path on the BIG-IP system. For example, if you want to view the BIG-IP system global settings, use the following syntax where you reference the BIG-IQ authentication token with $f5token:

    curl -ks -H "X-F5-Auth-Token: $f5token" https://<mgmt IP of BIG-IQ>/mgmt/shared/resolver/device-groups/cm-bigip-allBigIpDevices/devices/<uuid>/rest-proxy/<REST uri path on BIG-IP>[|json formatting tool]

    For example:
