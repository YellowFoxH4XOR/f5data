K000136031: After NMS upgrade, licensing/re-licensing fails

Type
Support Solution
Published
2023-08-30
Updated
2023-08-30
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.12.X, 2.12.0, 2.13.0, 2.13.X
Source
https://my.f5.com/manage/s/article/K000136031

Description

After upgrading from a version prior to v2.12 to v2.12 or higher licensing/re-licensing NMS fails. The following error may occur:

Failing to validate Request

Environment

NMS

Cause

Starting in NMS v2.12 the license api has been moved from being processed by the core-api-service to being processed by the integrations-api-service. If during an upgrade to v2.12 or higher the updated version's NGINX nms-http.conf file does not replace the current nms-http.conf file then this issue will occur.

Recommended Actions

Replace the current nms-http.conf file with the updated version's nms-http.conf file. If there are any customizations in the current nms-http.conf file them move them to the new nms-http.conf. Restart NGINX service.

sudo nginx -t
sudo systemctl restart nginx.service

Additional Information

This issue commonly occurs when the current NGINX nms-http.conf file is customized and this file is chosen to not be replaced during the upgrade process.

The nms-http.conf file is located within /etc/nginx/conf.d

If the current nms-http.conf file was kept during the upgrade process then a copy of the upgraded version of that file is placed in the same directory.

/etc/nginx/conf.d/nms-http.conf.dpkg-dist
