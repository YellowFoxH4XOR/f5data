K000091644: JWT authentication fails with error "invalid JWK set while sending to client"

Type
Support Solution
Published
2022-06-29
Updated
2026-07-22
Source
https://my.f5.com/manage/s/article/K000091644

Description

  • You configured NGINX Ingress Controller to perform JWT Authentication
  • JWT Keys are retrieved from an external Identity Provider (IDP) via subrequest
  • JWT authentication fails and Nginx Ingress controller logs the following error :

22/06/27 10:07:22 [info] 28#28: *11085 invalid JWK set while sending to client, client: 192.168.1.1, server: example.local.com

Environment

  • NGINX Ingress Controller
  • JWK set
  • oAuth Identity Provider {for example, Keycloak}
  • Kubernetes
  • JSON

Cause

The reported error may occur due one of the following causes:

  • Malformed JSON data in the HTTP response
  • The JSON data is compressed but the NGINX Ingress Controller is not configured to handle compressed data

Recommended Actions

To validate if JSON data is malformed:

  • Identify the URL of the authentication server where the JWT keys reside
location /jwt_authentication {
proxy_pass http://10.0.0.1/auth/certs;
}
  • Run the following command to retrieve the JWT keys manually:

Note: Make sure you have curl and jq installed on the system you use for testing and replace the URL with your actual URL

curl http://10.0.0.1/auth/certs | jq

  • If the above command returned any parsing errors, then you need to check on the server side or any other upstream devices why the JSON data arrives malformed on the NGINX Ingress Controller
  • If the command returned the JWK set successfully, then proceed with the steps in the next section to check compression

To Validate if the response is compressed:

  • Check if the header Content-Encoding is present in the output of the following command:

curl -v -H "Accept-Encoding: gzip , deflate" http://10.0.0.1/auth/certs

  • If response is confirmed to include Content-Encoding header, then you can either turn off compression on the upstream side or configure NGINX Ingress Controller to handle compressed data as following:

1. Edit the existing ConfigMap for the ingress pod as following:

kubectl edit cm <ConfigMap_NAME> -n <NAMESPACE>

2. Add the line "gunzip on ;" under "http-snippets:" and then save the change and exit

kind: ConfigMap
apiVersion: v1
metadata:
 name: my -ingress-controller-nginx-ingress
 namespace: default
 labels:
   app: my-ingress-controller
data:
  http-snippets: |
      gunzip on ;
/// YOUR CONFIG CONTINUES HERE ///

3. To verify the change

kubectl exec -it <INGRESS POD NAME> -n <NAMESPACE> -- nginx -T | grep gunzip

4. Perform a new test and confirm solution
