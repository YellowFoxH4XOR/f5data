Description

There are questions about the NGINX App Protect TS Cookies.

Environment

The TS cookies are used for various purposes such as validating the integrity of the cookies generated by the application.

Cause

The App Protect TS cookie functions much like the AdvWAF/ASM TS cookie. They both share the same basic architecture. They can be used for session management, CSRF protection, bot detection, or other security mechanisms

K6850: Overview of ASM cookies

As part of that you may encounter the secure cookie attributes. The system adds these Secure attribute only when the traffic protocol is HTTPS. The Secure cookie attribute directs a web browser to only use cookies on secure or encrypted sessions. The HttpOnly attribute directs browsers to use cookies by way of the HTTP and HTTPS protocols only, ensuring that the cookie is not available by other means, such as JavaScript function calls.

IMPORTANT: Using the HttpOnly can cause an issue for L7 DoS/Proactive Bot Defence client side Java script. Adding the HttpOnly flag will cause these features to malfunction and legitimate users will get blocked. "Can" being the operative word as depends on configuration.

Recommended Actions

There is direction provided for "best practices" found here...

Version 5

Version 4 and Earlier

Note: If there is a need to scale up NAP instances (in any way) - you should configure the app_protect_cookie_seed so that the generated TS cookie would be the same among multiple enforcers and there won't be false positives. That setting creates..."A long randomized string that serves to generate the encryption key for the cookies generated by App Protect. The string should contain only alphanumeric characters and be no longer than 1000 characters." Global Directives
