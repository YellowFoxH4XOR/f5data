K7190: The redirect rewrite filter does not add non-standard ports to the rewritten Location URI

Known Issue

This is the result of a known issue. The Redirect Rewrite setting specifies whether the BIG-IP LTM rewrites the scheme to https:// for URLs referenced in HTTP redirect (3XX) server responses. If Redirect Rewrite is set to All in the HTTP profile, and the BIG-IP LTM virtual server is configured on a non-standard port, the BIG-IP system rewrites the scheme, but does not add the non-standard port to the rewritten Location URI.

F5 Networks Product Development tracked this issue as CR67241, CR67505, and CR67509, and it was fixed in BIG-IP LTM version 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue still exists in the BIG-IP LTM 9.1, 9.2, and 9.3 software branches.

Workaround

You can work around this issue by creating an iRule that will redirect rewrites for non-standard ports. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule and paste the following iRule into the Definition box: 
    when HTTP_RESPONSE {  if { [HTTP::header exists Location] } {       # extract original redirect hostname, including port if any    set oldhost [findstr [HTTP::header Location] "//" 2 "/"]    # strip the old port (if any) & append the VS port to the hostname    set newhost [getfield $oldhost ":" 1]:[clientside { [TCP::local_port] } ]    # replace http:// with https://    set newloc [string map {http:// https://} [HTTP::header Location]]    # replace host + old port with host + new port    set newloc [string map [list $oldhost $newhost] $newloc]     # replace entire location header with new value    HTTP::header replace Location $newloc  }}
  6. Click Finished.

You must then associate the iRule with the virtual server configured on the non-standard port.
