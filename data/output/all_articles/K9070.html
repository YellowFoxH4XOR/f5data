Known Issue

This is the result of a known issue. When the BIG-IP WebAccelerator does not cache an object as a result of the newObjectCacheRatio setting, content assembly is disabled and the object is not compressed. If the WebAccelerator caches the object later, the WebAccelerator will perform content assembly and the object will be compressed in accordance with the assembly rules. The inconsistent compression behavior may cause issues for some intermediate proxies.

Note: For information about the newObjectCacheRatio setting, refer to K9062: Overview of the newObjectCacheRatio setting.

F5 Networks Product Development tracked this issue as CR103836 and it was fixed in BIG-IP WebAccelerator 9.4.6. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.
