Description

  • NGINX Plus instances configured to send usage/license reporting through a shared HTTP forward proxy, received intermittent HTTP error 429 (Too Many Requests) responses from product.connect.nginx.com.
  • The 429 errors occurred in bursts, particularly during periods of frequent NGINX configuration reloads, and were not observed on Amazon Linux 2 under similar conditions.

Environment

  • NGINX Plus version
  • Usage reporting enabled
  • Outbound traffic routed through a shared Forward proxy
  • Multiple NGINX Plus instances per node, with frequent configuration reloads
  • product.connect.nginx.com as the license/usage reporting endpoint

Cause

  • Frequent NGINX configuration reloads caused usage reporting to occur much more often than the default interval, resulting in bursts of usage report requests to product.connect.nginx.com. This excessive reporting triggered rate limiting on the F5 licensing server, leading to intermittent HTTP 429 responses.
  • The 429 errors are transient and occur only during high-frequency reporting bursts. 

Answer/Recommended Actions

  • Reduce the frequency of NGINX configuration reloads to minimize bursts of usage reporting.
  • Ensure the usage_report interval parameter is not set below the default (1 hour).
  • Treat transient HTTP 429 responses as harmless if subsequent usage reports succeed.
  • For environments where eliminating 429 responses is required, consider deploying NGINX Instance Manager (NIM) to aggregate usage reports before forwarding to the licensing server.
  • No changes are required to proxy configuration; the issue is not proxy-related.
