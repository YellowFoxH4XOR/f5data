K30371285: Configuring email alerts for BIG-IP system configuration changes

Topic

You should consider using this procedure under the following condition:

  • You want to receive email alerts when the BIG-IP system configuration changes.

Description

You can configure the BIG-IP system to deliver email alerts when a system configuration occurs. When configuration changes occur, the system sends audit messages to the /var/log/audit file, containing the following information:

  • Date / Time: The date and time of change.
  • Interface: The interface on which the change was made, which is either the Configuration utility (tmui) or the TMOS shell (tmsh).
  • User: The username of the account that performed the changed.
  • Modification type: The type of change (create, modify, or delete).
  • Change detail: The configuration object changed and the object's value.

Log message examples

In the following example, a create message is logged to the /var/log/audit file when user bill uses the Configuration utility to create new user nancy :

Jan 01 12:12:34 bigipb notice mcpd[1234]: 01070417:5: AUDIT - client tmui, user bill - transaction #170778-3 - object 0 - create { user_role_partition { user_role_partition_user "nancy" user_role_partition_partition "[All]" user_role_partition_role 0 } } [Status=Command OK]

The following example show the three types of audit messages (create, modify, and obj_delete) that are sent to the /var/log/audit file when a configuration change occurs on the BIG-IP system:

Note: For the sake of brevity, configuration change details are removed and replaced by an ellipsis within braces ({…}).

01070417:5: AUDIT - client tmui, user bill - transaction #226095-3 - object 0 - create {...}
01070417:5: AUDIT - client tmui, user bill - transaction #226095-4 - object 0 - modify {...}
01070417:5: AUDIT - client tmui, user bill - transaction #226095-5 - object 0 - obj_delete {...}

Email examples

You can create custom logging filters to catch the create, modify,, and obj_delete messages and send an email to one or more recipients. Emails sent from the BIG-IP system appear similar to the following:

Note: The email Subject is the exact message logged to the /var/log/audit file and cannot be modified.

Date: Mon, 01 Jan 2018 12:12:34 -0900
From: root <root@bigipa.example.com>
To: bigadmins@example.com
Subject: 1070417:5: AUDIT - client tmui, user bill - transaction #170778-3 - object 0 - create { user_role_partition { user_role_partition_user "nancy" user_role_partition_partition "[All]" user_role_partition_role 0 } } [Status=Command OK]

A config change has occurred

You can use the following procedures to configure the system to send email alerts when a change occurs to the BIG-IP system configuration.

Note: This configuration does not synchronize with peer devices and must be separately performed on each BIG-IP system.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have Advanced shell (bash) and TMOS Shell (tmsh) access to the BIG-IP system.
  • You have an SMTP mailhub (mail server) and a DNS name server.
  • Configuring the SMTP mailhub and DNS name server
  • Configuring the log message filter
  • Testing email delivery

Procedures

Configuring the SMTP mailhub and DNS name server

You must first configure the SMTP mailhub, or mail server, to deliver BIG-IP system email alerts. You must also configure a DNS name server if you intend to resolve DNS hostnames. Perform the following procedure to configure the SMTP mailhub and DNS name server:

Note: If you are running BIG-IP 13.0.0, you must follow the Workaround procedure in the following article: K15188934: Emails generated by the BIG-IP system may fail after upgrading to 13.0.0.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To configure a DNS name server, use the following command syntax:

    modify sys dns name-servers add { <IP address> }

    For example, to configure the system to use a DNS name server with the IP address 192.168.10.200, type the following command:

    modify sys dns name-servers add { 192.168.10.200 }

  3. To configure the system to send locally generated email messages, use the following command syntax:

    modify sys outbound-smtp mailhub <mail_server>:<port>

    For example, to configure the system to send locally generated email messages to host mail.example.com using TCP service port 587, type the following command:

    modify sys outbound-smtp mailhub mail.example.com:587

  4. To save the configuration, type the following command:

    save /sys config

Configuring the log message filter

You must define a log message filter in the /config/user_alert.conf file, which the system uses to send emails when a configuration change event, such as create, modify, or delete, occurs. Perform the following procedure to define the log message filter:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the bash shell.
  2. Using a text editor, open the /config/user_alert.conf file for editing.

    Note: When syntax errors occur in the user_alert.conf file, the alertd process enters a restart loop. Type bigstart stop alertd into the shell to stop the restart messages. After the syntax errors are resolved, type bigstart start alertd.

  3. Use the following filter examples to catch configuration change log message and send email notifications:

    Note: The toaddress requires the full email address. However, the fromaddress appends @<BIG-IP hostname>.

    alert <filter_name> "object (.*) - create" {
    email toaddress="<email address>"
    fromaddress="<bigip user>"
    body="<text message>"

    }     alert <filter_name> "object (.*) - obj_delete" {
    email toaddress="<email address>"
    fromaddress="<bigip user>"
    body="<text message>"

    }     alert <filter_name> "object (.*) - modify" {
    email toaddress="<email address>"
    fromaddress="<bigip user>"
    body="<text message>"
    }

    For example, adding the following log message filters to the user_alert.conf file sends email notifications to the bigadmin users at example.com with the message A config change has occurred when a configuration occurs:

    alert config_create "object (.*) - create" {
    email toaddress="bigadmin@example.com"
    fromaddress="root@bigipa.example.com"
    body="A config change has occurred"
    }

    alert config_delete "object (.*) - obj_delete" {
    email toaddress="bigadmin@example.com"
    fromaddress="root@bigipa.example.com"
    body="A config change has occurred"
    }

    alert config_modify "object (.*) - modify" {
    email toaddress="bigadmins@example.com"
    fromaddress="root@bigipa.example.com"
    body="A config change has occurred"
    }

  4. Save and exit the file.

Testing email delivery

The most effective way to verify email delivery is to create, modify, and then delete a simple object, such as a pool, on the BIG-IP system. If creating an object on the BIG-IP system is not possible, you can use the following procedure to generate log messages and trigger an email:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the bash shell.
  2. Use the following command syntax to generate a log message in the /var/log/ltm file to trigger an alert email:

    logger -p local0.notice "<logged error message>"

    For example, you can copy and paste the following commands to test all of the email alerts configured in this article:

    Note: You can copy and paste all of the commands at one time. You do not need to modify these commands to test email delivery.

    logger -p local0.notice "object 0 - create"
    logger -p local0.notice "object 0 - modify"
    logger -p local0.notice "object 0 - obj_delete"

  3. You should receive emails from the BIG-IP system on your remote device or workstation.
