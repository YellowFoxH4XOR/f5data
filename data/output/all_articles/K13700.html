Known Issue

Users in a Windows-management-authorization (WMA) group may not be granted appropriate permissions.

This issue occurs when the following condition is met:

  • When a namespace has two or more WMA groups configured per namespace

A WMA group is a list of Windows clients who can use Windows-management applications, such as MMC or snapshots, in one or more namespaces. The permit command establishes a permissible management action for the current WMA group. When an ARX namespace is configured with more than one WMA group, users from one WMA group may be granted permissions assigned to another WMA group configured for the namespace.

Impact

WMA group members may be granted permissions assigned to another WMA group.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A user with full administrative permissions may be granted limited permissions, such as snapshot only. As a result, attempting to close a session may fail with an RPC call failed error.
  • A user with limited administrative permissions, such as snapshot only, may be granted full permissions.

Workaround

To work around this issue, you can reduce the configured WMA groups to one per namespace.

Impact of workaround: Configuration possibilities are limited.

  • Edit the WMA configuration through the ARX Manager GUI > Authentication > Windows Mgmt. Access Control Lists page
  • Edit the WMA configuration through the ARX CLI using the windows-mgmt-auth and permit commands
