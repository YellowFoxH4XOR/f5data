Topic

This article provides an overview of iControl representational state transfer (REST) permissions, which determine whether or not a BIG-IP user is allowed to access the iControl REST API.

Description

In versions prior to BIG-IP 11.6.0, the only available authentication method available for iControl REST is basic authorization. In BIG-IP 11.6.0 and later, the BIG-IP system provides a token-based authentication method in addition to basic authorization.

iControl permissions for local users

In BIG-IP 11.5.x to 13.0.x, by default, only users with the Administrator role are granted access to the iControl REST API. In BIG-IP 13.1.x and later, any user you create regardless of role is automatically given access to the iControl REST API, but are limited by their role to what objects they can view and edit. When users who do not have access to the configuration objects make a request to the iControl REST, the BIG-IP system rejects the request with an HTTP 40x status code depending on the user role and configuration objects.

Allowing users without the administrator role to access iControl (not necessary for BIG-IP 13.1.x and later)

The BIG-IP system determines iControl access permission according to which users belong to the iControl_REST_API_User role. Starting in BIG-IP 11.6.0, the system provides the administrator role with a mechanism for adding users to this special system role and therefore granting access to iControl for users who are not assigned the administrator role. The administrator must perform an iControl request to update the list of BIG-IP users who are granted access to iControl. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. Add the user to the iControl_REST_API_User role using the following command syntax:

    curl -sk -u <admin_username>:<admin_password> https://localhost/mgmt/shared/authz/roles/iControl_REST_API_User -H "Content-Type: application/json" -X PATCH -d '{ "userReferences":[{"link":"https://localhost/mgmt/shared/authz/users/<username>"}] }'

    In this command syntax, note the following:

    • Replace <admin_username> and <admin_password> with the username and password of a BIG-IP user account with the administrator role
    • Replace <username> with the username of the user to whom you want to grant iControl access

    For example:

    If you create a user named iCR_cert_mgr with the Certificate Manager role that you want to give access to the iControl REST interface, type the following command:

    curl -sk -u admin:admin https://localhost/mgmt/shared/authz/roles/iControl_REST_API_User -H "Content-Type: application/json" -X PATCH -d '{ "userReferences":[{"link":"https://localhost/mgmt/shared/authz/users/iCR_cert_mgr"}] }'

    The non-administrator user should now be able to access iControl without restrictions.

For more information about creating user accounts, refer to K45818846: Managing BIG-IP system user accounts using the iControl REST API or the Local User Account Management chapter of the BIG-IP Systems: User Account Administration manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

iControl permissions for remote users

BIG-IP 11.6.0 and later

In BIG-IP 11.6.0 and later, the system provides remote users with a token-based method of authentication. For more information regarding token-based authentication for iControl, refer to the following DevCentral article:
Demystifying iControl REST Part 6: Token-Based Authentication

You can also configure a local user account to allow remote users to authenticate to iControl using basic authentication. To do so, refer to the following Allowing remote-user access to iControl with basic authorization credentials procedure.

BIG-IP 11.5.x

In BIG-IP 11.5.x, the basic authorization method for authenticating to iControl is disabled for all remote users, so there is no default authentication mechanism for remote users. However, you can create a local user account for a remote user to whom you want to grant iControl access. To do this, perform the following procedure:

Allowing remote-user access to iControl with basic authorization credentials

Impact of procedure: A remote user account will have the permissions (Role) assigned to the local user account having the same name.  For example, if you have a remote user (User1) configured with the Auditor Role, and a local user (User1)configured with the Administrator Role. The User1 will have Administrator privileges.

  1. Log in to the Configuration utility.
  2. Navigate to System > Users > User List.
  3. Click Create.
  4. For User Name, type the username of the remote user to whom you want to grant access.
  5. For Role, click Administrator.
  6. Click Finished.
