Known Issue

The OneConnect profile prevents TCP connections to Internet Content Adaption Protocol (ICAP) servers from being terminated.

This issue occurs when all of the following conditions are met:

  • A OneConnect profile is enabled for an ICAP internal virtual server.
  • The ICAP server unexpectedly encapsulates an HTTP 302 redirect response.

After sending an ICAP Preview message, the BIG-IP system waits for a response from the ICAP server. If the BIG-IP system receives the complete ICAP response before it has completed sending the ICAP request (for example, when the response contains an encapsulated HTTP 302 redirect), it stops sending the request payload and closes the connection. However, when a OneConnect profile is enabled for the ICAP internal virtual server, the TCP connection to the ICAP server is not terminated, so that subsequent client requests may re-use that existing server-side TCP connection.

Impact

The ICAP server may not be able to detect the end of the ICAP client request.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system appears to continue sending data when the ICAP server expects the connection to have been previously closed.

Workaround

To work around this issue, you can either remove the OneConnect profile from the ICAP internal virtual server, or configure your ICAP server to ignore any further input from the client until it detects another RESPMOD or REQMOD, indicating the beginning of a new transaction. Configuring the ICAP server to ignore any further input from the client would allow connection reuse in the case where the server completes its response before the request is complete. To remove the OneConnect profile from your ICAP internal virtual server, perform the following procedure:

Impact of workaround: Performance may be significantly impacted by disabling connection re-use. For more information, refer to K7208: Overview of the OneConnect profile.

Disabling OneConnect for your ICAP internal virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select your ICAP internal virtual server.
  4. Under the Acceleration section of the virtual server, set the OneConnect Profile to None.
  5. Click Update.
