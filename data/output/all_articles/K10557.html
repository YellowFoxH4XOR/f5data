K10557: Timeout configuration for a PVA-assisted FTP profile

Topic

When using the FTP profile on a virtual server running on a PVA-enabled platform, the minimum recommended value for the idle timeout in the TCP profile assoicated with the virtual server is 90 seconds.

An FTP session typically uses two related connections, one of which carries the control channel, the other a data channel. The FTP control channel is active only when commands are exchanged between the user and the server. During data transfers, the command channel is typically idle.

When using an FTP profile, the control channel is managed by TMM, while the data channel may be promoted to PVA assist for acceleration by the PVA. In order to keep both the control channel and data channel active while traffic is flowing through either of the related connections, the PVA periodically sends a refresh packet to TMM. This refresh packet updates the control channel's idle time, preventing the control channel from being reaped while the related FTP data connection is still active. Since the default PVA refresh interval may take up to 88 seconds, the TCP connection timeouts should be set to at least 90 seconds.

Note: Beginning in BIG-IP version 9.4.2, FTP data channels are automatically promoted to PVA assist on PVA-enabled platforms.

The maximum value should not exceed the following:

  • 65,527 seconds for PVA1 (BIG-IP 2400 platforms) and PVA2 (3400, 6400, 6800 platforms)
  • 32,760 seconds for PVA10 (8400 and 8800)

Note: For information about the maximum functional timeout values for PVA accelerated connections, refer to K6792: Idle timeouts that exceed the PVA maximum value allowed result in a demotion of the PVA acceleration level and K10533: PVA version 1 and 2 chips may prematurely delete FastL4 profile connections configured with a large idle timeout.

Note: The timeout value should be set to an appropriate value reflecting the length of time for which an FTP session is allowed to remain idle. The TCP profile default timeout value of 300 seconds is appropriate for most applications.

If the idle timeout for the TCP profile is set below or above the recommended values, or if the data channel is not promoted to PVA assist, PVA refresh packets will not update the control channel and the FTP control channel may prematurely time out before the user finishes the FTP data transfer.

Note: For information about configuring profile timeouts, refer to the Managing Protocol Profiles chapter of the Configuration Guide for BIG-IP Local Traffic Management.
