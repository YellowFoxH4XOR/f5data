Known Issue

A peer discovery error may occur if the BIG-IP device credentials contain XML special characters.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system in a device group.
  • Your BIG-IP target device name or password contains XML special characters. For example, less than (<), greater than (>), or ampersand (&) characters.
  • You attempt to retrieve the peer device information that contains the special characters using the Configuration utility (Device Management > Device Trust > Peer List > Add).

Impact

You are unable to add the BIG-IP device to the device trust domain.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility displays the following error message:

    java.io.IOException: Could not read response from server: ParseError at [row,col]:[1,225] Message: Element type 'bigip2' must be followed by either attribute specifications, '>' or '/>'.

  • You are not able to add the BIG-IP device to the device trust domain.

Workaround

To work around this issue, you can modify the device name and password if the current device contains special characters. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Microkernel (tmsh) utility by typing the following command:

    tmsh

  2. To modify the device name, use the following command syntax:

    mv /cm device <source-name> <target-name>

    For example, to modify the device name from <bigip1> to bigip1, type the following command:

    mv /cm device <bigip1> bigip1

  3. To modify the password for the admin account, type the following command:

    modify auth user admin prompt-for-password

  4. When prompted, type the new admin password.
  5. When prompted, retype the new admin password to confirm.
  6. To save your changes, type the following command:

    save /sys config
