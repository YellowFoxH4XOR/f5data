Topic

This article applies to BIG-IP versions 9.x through 10.x. For information about other versions, refer to the following article:

  • K13392: Configuring the BIG-IP system to send traffic to an intrusion detection system

The BIG-IP LTM system supports using the clone pool or port mirroring features when copying traffic to a dedicated intrusion detection system (IDS) or a sniffer device for troubleshooting purposes. In general, the clone pool feature is the recommended method for copying production traffic to IDS systems or sniffer devices. Clone pools are more versatile than port mirroring, and clone pool traffic is processed by TMM while port mirroring is processed by the switch fabric.

Clone pools

Clone pools are designed to copy traffic to intrusion detection systems. A clone pool is a property of a virtual server, and it receives all of the same traffic as the load-balancing pool. Only new connections are copied by a clone pool, existing connections are not copied when a clone pool is added to a virtual server.

Clone pool characteristics

Clone pools contain the following characteristics:

  • Clone pool traffic is processed by TMM
  • Clone pools can be configured to copy client-side traffic, server-side traffic, or both
  • An unlimited number of clone pools can be configured on the BIG-IP system
  • Clone pools are not compatible with asymmetric routing

Note: When the Connection.VlanKeyed BigDB key is set to disable, the BIG-IP system allows asymmetric connections across multiple VLANs.

Configuring clone pools

You can configure clone pools to copy client-side traffic, server-side traffic, or both. A client-side clone pool causes the virtual server to replicate client-side traffic (prior to address translation) to the clone pool member. A server-side clone pool causes the virtual server to replicate server-side traffic (after address translation) to the clone pool member.

To configure a clone pool, create a pool with the IDS device as the member IP address, and configure the pool to be a clone pool for the virtual server.

Configuring a clone pool using the Configuration utility

To configure a clone pool using the Configuration utility, you must perform the following two procedures:

  • Creating a pool containing the IDS IP address
  • Assigning the pool as a clone pool for the virtual server

Creating a pool containing the IDS IP address

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click Create.
  5. Type a name for the pool.
  6. Enter the IP address of the IDS system in the Address field.
  7. Enter the port number in the Service Port field, and click Add.
  8. Click Finished.

Assigning the pool as a clone pool for the virtual server

  1. Click Virtual Servers.
  2. Select the virtual server for which you want to assign the clone pool.
  3. Select Advanced from the Configuration drop-down menu.
  4. Select the pool containing the IDS device from the Clone Pool (Client), or Clone Pool (Server) drop-down menu.
  5. Click Update.

Configuring a clone pool from the command line

To configure a clone pool from the command line, perform the following two procedures:

  • Creating a pool containing the IDS IP address
  • Assigning the pool as a clone pool for the virtual server

Creating a pool containing the IDS IP address

  1. Log in to the command line.
  2. Use the following bigpipe command to create the pool containing the IDS device:

    bigpipe pool <pool_name> { members <IDS_server> }

    For example, the following bigpipe command creates a pool named clone_pool with an IDS IP address of 10.0.0.1:

    bigpipe pool clone_pool { members 10.0.0.1:80 }

Assigning the pool as a clone pool for the virtual server

  1. Use the following bigpipe command to assign the pool containing the IDS device to the virtual server:

    bigpipe virtual <virtual_name> clone pool <clone_pool_name> clientside | serverside

    For example, the following command configures the clone_pool pool to be a client-side clone pool for the virtual server named my_virtual:

    bigpipe virtual my_virtual clone pool clone_pool clientside

  2. Type the following command to save the configuration:

    bigpipe save

Troubleshooting clone pool traffic

Clone pool traffic is sent from the BIG-IP system to the IDS system (clone pool member) using the IDS system's L2 MAC address. Other packet header information contained in the clone pool traffic, such as the L3 addressing, remains the same as in the original packet sent to the virtual server pool member.

Port Mirroring

Port mirroring is a feature that allows you to copy traffic from any port or set of ports to a separate port where a sniffing device is attached. Port mirroring is useful for sending traffic at wire speed to a dedicated device for troubleshooting purposes.

Port mirroring characteristics

Port mirroring characteristics are as follows:

  • Port mirroring traffic is not processed by the PVA ASIC or TMM
  • Port mirroring always copies both client-side and server-side traffic
  • The port mirroring mirror-to port can copy traffic from several ports
  • The port mirroring mirror-to port is a dedicated port and cannot be associated with any VLAN or trunk
  • The port mirroring mirror-from port can be only a physical port and not a VLAN or trunk
  • The port mirroring mirror-from ports can be a member of several VLANs or a trunk
  • Only one port mirror instance can be configured on the BIG-IP system
  • Port mirroring is compatible with asymmetric routing

Note: Running tcpdump on a mirror-to port is not supported. For more information, refer to K9354: Running tcpdump on a mirror-to port leaves the port inoperable.

Configuring port mirroring

Using port mirroring, you can mirror traffic from many ports to one port. The mirror-to port is dedicated to mirroring and cannot be a VLAN or a trunk member.

Configuring port mirroring using the Configuration utility

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click Interfaces.
  4. Click the Interface Mirroring menu.
  5. Select Enabled from the Interface Mirroring State drop-down menu.
  6. Select an interface from the Destination Interface drop-down menu.
  7. Select an interface(s) from the Mirrored Interfaces list, and click the arrow button to move the interface(s) to the Selected box.
  8. Click Update.

Configuring port mirroring from the command line

  1. Log in to the command line.
  2. To configure a port mirror, type the following bigpipe command:

    bigpipe mirror <destination_interface> interface <mirrored_interface>

    For example, the following command creates a port mirror, 1.1, that includes interfaces 1.2, 1.3, and 1.4. All traffic processed by the interfaces 1.2, 1.3, and 1.4 is mirrored to the interface 1.1:

    bigpipe mirror 1.1 interface 1.2 1.3 1.4

  3. To save the base network configuration, type the following command:

    bigpipe base save
