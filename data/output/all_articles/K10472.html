Known Issue

This is the result of a known issue. Intense disk drive I/O activity on a BIG-IP system can cause extra memory to be used for caching and higher CPU usage. These conditions may lead to the memory used by essential BIG-IP processes to be swapped out in favour of less important ones, or essential BIG-IP processes to be descheduled from the CPU. When this issue occurs, a process may not have enough resources to send its heartbeat signal. If a heartbeat is missed, a corrective action is initiated by the BIG-IP system, for example a failover, which in this case is unnecessary and undesired.

Note: On a BIG-IP system, some critical processes are required to send a heartbeat signal before a timer expires; this lets watchdog know that the process is running and healthy. These critical processes include the sod, clusterd, overdog, TMM, lacpd and bcm56xxd processes. For more information about the daemons running on a BIG-IP system, refer to K8035: Overview of BIG-IP daemons.

For example, rotation of large log files can sometimes generate enough disk drive I/O activity to trigger this issue.

Note: By default on a BIG-IP system, logs are rotated daily at 4:02AM. This is dictated by the cron.daily script. For more information, refer to K7115: Managing log files on the BIG-IP system.

F5 Networks Product Development tracked this issue as CR112231 and it was fixed in BIG-IP version 9.4.7 for the 9.4 software branch and BIG-IP version 10.0.0 for the 10.0 branch. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator or PSM Release Notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.6.1-839.0-HF3, which has been issued for BIG-IP version 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
