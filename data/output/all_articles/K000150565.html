K000150565: Edge Client is stuck in initializing state after upgrade to 16.1.6, 17.1.2, 17.5.1

Type
Support Solution
Published
2025-03-27
Updated
2026-04-06
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1, 16.1.6, 17.1.1, 17.1.2
Source
https://my.f5.com/manage/s/article/K000150565

Description

After upgrading the BIG-IP system software version to:

  • 16.1.6,
  • 17.1.2
  • 17.1.2.1
  • 17.1.2.2
  • 17.5.1
  • 17.5.1.2
  • 17.5.1.3

The Windows Edge Client or Browser VPN remains in a persistent "Initializing" state.

You notice errors in /var/log/ltm during the connection attempt, similar to:

iSession: Connection error: isession_handle_syn:3737: No peer:4
iSession: Connection error: isession_handle_syn:3740: No peer:4

If RST cause is enabled, you observe F5 send a reset with a cause - F5RST: iSession error (err: isession_handle_syn:3737, No peer, ERR_ARG) in the packet capture.

Environment

  • BIG-IP APM
  • Software upgrade
  • Edge Client
  • SSL VPN

Cause

ID 1758029: VPN tunnels fail to establish when a virtual server is on a non-default route domain

ID 2047445: VPN connection may fail when access policy is configured in route domain

Recommended Actions

In the affected route domain configuration, assign the default route domain as the parent by selecting 'Parent Name = 0'.

Reapply the corresponding access policy by modifying something (e.g., add a space in the Logon Page agent, save and reapply the access policy).
