Description

You may need to change the management-IP address for devices in an HA pair. You may be required to perform the procedure of changing the management IP address in the following condition(s):

  • Network requirement changes mean you need to change the management IP address.
  • You may need to break the device trust as part of troubleshooting issues when your HA devices are unable to config sync.

Environment

  • Two BIG-IP in an HA pair environment.
  • BIG-IP LTM

Cause

None

Recommended Actions

Note: When changing the management IP, please check the management IP firewall rules configured on the existing management IP to ensure that the new state of the machine (i.e. new management IP) will be accessible after the change. Reference: K46122561: Restrict access to the BIG-IP management interface using network firewall rules.

Example

Trying to change the management-IP for devices BIG-IP A and BIG-IP B and both devices are set in an HA pair environment between them. BIG-IP B is set as the standby device while BIG-IP A is set as the Active unit.

Set the standby BIG-IP B system offline

Before restarting the system, to prevent the standby system from becoming Active and disrupting traffic in the process, it is good practice to set it Offline first. To do so, perform the following procedure:

Impact of procedure: The standby system is not available to process traffic when in Offline state.

  1. Log in to the Configuration utility of the standby BIG-IP system with administrative privileges.
  2. Go to Device Management > Devices.
  3. Select the standby BIG-IP system.
  4. Select Force Offline.
  5. Select OK to confirm.

Breaking the trust (Repeat this procedure on the standby device)

To break an established trust, you must remove the devices from the device group before you can delete the device trust. To do so, perform the following procedure:

For information about the impact of breaking the HA configuration on the primary device, refer to K40307688.

Impact of procedure: Performing this procedure will remove the HA configuration from your environment. F5 recommends that you schedule this procedure during a maintenance window to minimize the impact in mission-critical environments.

Note: After performing these procedures, the active device should have a status.

Forced offline Standalone.

Change the Management-IP from the CLI

  1. Log into the command-line interface (CLI) using the console port or a self IP; this is vital because if you access using the management IP address you will lose connectivity during this procedure.
  2. Overwrite existing management IP:

    tmsh create /sys management-ip [ip address/prefixlen]

    For example:

    tmsh create /sys management-ip 192.168.1.245/24

  3. Change management-route:

    tmsh modify /sys management-route default gateway [gateway ip address]

  4. To view the management IP configurations:

    tmsh list /sys management-ip

    tmsh list /sys management-route
  5. Save system configuration:

    tmsh save sys config

Recreate HA and return systems to service

  • From BIG-IP A create an Active-Standby Configuration using the Configuration utility.

    Note: See Related Content for references for this step.

  • Release from offline, the updated BIG-IP standby devices.

Impact of procedure: Depending on your HA configuration and state, releasing the BIG-IP system from Force Offline may result in the system becoming Active. F5 recommends that you perform this procedure during a maintenance window.

  1. Log in to the Configuration utility of the active BIG-IP system.
  2. Go to Device Management > Devices.
  3. Select the name of the standby BIG-IP system.
  4. Select Release Offline.
  5. Select OK to confirm.

Force the active BIG-IP to standby

Impact of procedure: This procedure interrupts traffic during failover. F5 recommends that you perform this procedure during a maintenance window. If you encounter any problems with the newly upgraded system after failover, you must repeat this procedure on the newly upgraded system to fail back to the previously active system.

  1. Log in to the Configuration utility of the active BIG-IP system.
  2. Go to Device Management > Devices.
  3. Select the name of the active BIG-IP system.
  4. Hover your mouse over the status of the devices to determine the active system.

    Note: You cannot force the active system to standby using the Configuration utility of the standby system.

  5. To move the modified system to the active role, force the active BIG-IP system into standby mode by selecting Force to Standby.
  6. Test client traffic to the modified BIG-IP system to confirm that the system is processing traffic as expected.
  7. After confirming the health of the modified system, repeat the following steps in the BIG-IP A system:
  • Set the standby BIG-IP A system offline.
  • Breaking the trust (Repeat this procedure on both the Active and the Standby unit).
  • Change the Management-IP from the CLI.
  • From BIG-IP A create an Active-Standby Configuration using the Configuration Utility.
  • Release offline the updated BIG-IP A system.
