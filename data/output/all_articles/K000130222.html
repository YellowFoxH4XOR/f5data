K000130222: Autodosd log file (/var/tmp/autodosd.out) not truncated when it is rotated

Type
Support Solution
Published
2022-12-15
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP AFM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000130222

Description

It was found that when /var/tmp/autodosd.out is rotated by logrotate, the size of the log file, never reduces. After a number of months, it size can approach a gigabyte. While the size is not really an issue, logroate has to compress a 1 gigabyte file, every hour, and if you have a number of VE's all running on the same Physical Host, it can cause a lot of IO wait, which is completely unnecessary.

The following is a sample output:

-rw-r--r--. 1 root root 62K Oct 10 19:58 /var/tmp/autodosd.out.2.gz
-rw-r--r--. 1 root root 62K Oct 10 20:59 /var/tmp/autodosd.out.1.gz
-rw-r--r--. 1 root root 63M Oct 10 21:52 /var/tmp/autodosd.out

Environment

  • AFM Provisioned

Cause

This is due to ID 1196053 LTM 14.1 - autodosd log file not truncating when it rotates

 

Recommended Actions

At the time of this article's publishing, no release is fixed.

Therefore, please open a Service Request and request for an Engineering Hot Fix.
 

Workaround

# sed -i -e 's/\ >\ /\ >>\ /g' /etc/bigstart/scripts/autodosd


Then restart the autodosd service:-

# tmsh restart sys service autodosd
This can be done on an Active BIG-IP, without causing a loss of service, but make sure you follow best practice for change management.
