Description
Checking the web accelerator cache is working.

To view or configure the your web acceleration profile on the Configuration utility, go to Local Traffic > Local Traffic > Profiles > Web Acceleration.

Environment

  • BIG-IP LTM, WebAccelerator
  • Cache HTTP objects 

Cause
None

Recommended Actions

The easiest way to confirm that the web accelerator cache is working is to capture the upstream traffic.

Assuming you have 2 pools members, 192.168.1.1:443 and 192.168.1.2:443, then you can use the following command on the cli of the BIGIP:

  • tcpdump -vv -ni 0.0:nnn host (192.168.1.1 or host 192.168.1.2) and port 443 | grep -v 'lis= '

(The reason for "| grep -v 'lis= '" is to exclude the health monitor traffic)

The packets displayed will show 'lis=<virtual server name>'

If you repeat the same web request from the client again, you will observe that no packets are captured, as the response to the client is served by the web accelerator cache.

To view the content of the cache you can use the command:
(tmos)# show ltm profile ramcache <cachename>

Ltm::Ramcaches /Common/<cachename>

Host: 172.16.1.1
URI : /index.htm

  Last Sent        2020-01-06 18:17:13
  Expires          2020-01-06 18:19:11

  Source Slot/TMM  1/0
  Owner Slot/TMM   1/2
  Rank             1

  Size (bytes)     638
  Hits             3
  Received         2020-01-06 18:14:41

  Expires          2020-01-06 18:19:11
  Vary Type        none
  Vary Count       1
  Vary User Agent  none
  Vary Encoding    none


You may find that there is an entry present for each tmm that you have. In the first example above It states that the "Owner slot/TMM" is 1/2. This means that when the first request that came in, was made via tmm 2 (and slot 1). The value of "Source slot/TMM" means that a subsequent request came in via tmm 1 (and slot 1), but the cached version from which the response is sent is still identified as being from tmm 2.

If you have 4 TMMS, then you can expect to see up to 4 references of the cached object , one for each TMM, but there will only ever be 1 copy of the object in the ram cache.

To view the cache stats, enter the command:
(tmos)# show ltm profile web-acceleration <cachename>

And here you can see that the used cache size is 638 bytes, which is the same as each cached object. It is important to note that it is not 1276 bytes (638*2), as there is only one copy of the object in ramcache, despite there being multiple references via the different tmms.
