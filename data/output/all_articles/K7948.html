K7948: FirePass duplicates drive mappings after Network Access is relaunched

Known Issue

This is the result of a known issue. If a user clicks the Relaunch button in the Network Access window, and drive mappings were configured for that Network Access connection, FirePass will prompt the user to select from the following three options:

  • Choose other drive letter
  • Disconnect existing
  • Cancel

If the user selects Choose other drive letter, FirePass will map the network drive to the specified drive letter even if the same network drive is already mapped to another drive letter. When the user closes the Network Access connection, FirePass will only disconnect the network drives that were mapped when the user last clicked the Relaunch button. Drive mappings that were mapped when the user initially opened the Network Access connection or when the user previously clicked the Relaunch button will not be disconnected.

Note: If the user did not click the Relaunch button during the Network Access connection, FirePass will correctly disconnect all network drives mapped by the Network Access connection.

When a user clicks the Relaunch button, the correct behavior for FirePass is to determine which drive mappings currently exist, and only map network drives that are not currently mapped. Furthermore, when a user disconnects from the Network Access connection, FirePass should disconnect all network drives mapped by the Network Access connection.

F5 Product Development tracked this issue as CR67273 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

Workaround

You can work around this issue by manually disconnecting network drives after closing a Network Access connection. For more information about disconnecting network drives, refer to your Microsoft Windows documentation.
