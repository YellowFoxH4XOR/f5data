K000156510: Understanding 503 upstream_reset_before_response_started{remote_reset} Errors in HTTP/2 Connections

Description

In F5® Distributed Cloud, the error 503 upstream_reset_before_response_started{remote_reset} indicates that the origin (upstream) server reset the connection before sending any response headers. The reset is initiated by the origin application server, not by the F5XC load balancer.

Environment

  • HTTP Load Balancer using HTTP/2 connections

Cause

The number of concurrent streams in an HTTP/2 connection exceeds the negotiated limit between client (F5XC) and server.

When that happens, the upstream server may reject additional streams with a remote_refused_stream_reset or similar signal, causing the connection to be reset before any headers are sent.

F5XC reports this as a 503 upstream_reset_before_response_started{remote_reset} error.

Answer/Recommended Actions

To mitigate or resolve this error, consider the following steps:

  1. Increase the maximum concurrent streams on the origin server to allow more HTTP/2 streams in a single connection.

  2. Monitor server performance to ensure your origin has sufficient capacity (CPU, memory, I/O, etc.) to handle more concurrent streams without degradation.

  3. Review application and server logs for related errors, warnings or resets that provide context (e.g. which component is refusing streams).

  4. If the issue remains after these, further investigate origin server configuration, including resources, stream limits, HTTP/2 settings (timeouts, idle timeouts), and possibly network issues.
