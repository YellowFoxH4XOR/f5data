Known Issue

Form-based Single Sign-On (SSO) parameters may be incorrectly URL-encoded.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a form-based SSO (v1) profile.
  • The form includes hidden parameters containing any of the following special characters:
     
    • Dash ( - )
    • Underscore ( _ )
    • Period ( . )
    • Exclamation ( ! )
    • Tilda ( ~ )
    • Asterisk ( * )
    • Open parenthesis ( ( )
    • Closing parenthesis ( ) )
    • Backslash ( \ )

Impact

SSO fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewing the HTTP content encoded by the BIG-IP APM system sent to the destination resource, the encoding may appear similar to the following examples:
     
    • Pre-URL encoded parameter:

      ABC-YZ-10.somesite.local

    • Post-URL encoded parameter:

      ABC%2DYZ%2D10%2Esomesite%2Elocal

  • The form does not function correctly.

Workaround

To work around this issue, you can use form-based client initiated SSO, or create a custom iRule to rewrite the encoded parameter special characters to the pre-encoded format.
