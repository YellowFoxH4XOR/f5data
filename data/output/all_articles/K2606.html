Topic

The 3-DNS Controller does not currently load balance IPv6 DNS requests, which are also referred to as quadA and AAAA requests. 

In versions 4.0 through 4.6.2, IPv6 requests destined for the 3-DNS Controller will not be handled by the 3dnsd process; these requests will be sent back to BIND for resolution.

Note: Beginning with version 4.6.3 of  3-DNS, BIG-IP and BIG-IP Link Controller, the 3dnsd process can intercept AAAA and A6 record requests and send a NOERROR response. This response allows IPv6 name resolution compatibility, regardless of whether the named process is running.

In most cases the 3-DNS controller BIND zone files contain A records which are automatically populated when the wide IP is created. However; AAAA records only exist for the zone if they are manually added by an administrator. This does not cause an issue because BIND will answer the query for the IPv6 record with a NOERROR response. This response will cause the requesting host (or LDNS) to repeat the request; however, this time the host (or LDNS) will issue the request for an A record, at which point 3dnsd will process and load balance the request.

If your zone records are properly maintained, you should not experience any issues. However, if the host (or LDNS) issues a quadA request, and there is no AAAA or A record for the zone, BIND will respond to the requester with an NXDOMAIN response, instead of the NOERROR response. The requester will receive the NXDOMAIN response as an indication that there are no records of any type for the zone. If the requester is an LDNS server, the LDNS server will respond with the NXDOMAIN message to any of its clients requesting that zone (whether it is an A or AAAA request) until the zone TTL limit is reached and the LDNS server makes the request again.

Important: This issue is more common with the recent adoption of IPv6 and BIND v9.x (currently the most recent ISC version of BIND). The proper resolution is to ensure that the underlying BIND configuration is correct, and the zone files contain the proper DNS records.

To avoid issues, verify that the wide IP contains an A record and that the wide IP aliases contains CNAME records. This ensures that BIND will not return a NOERROR reply which would cause the LDNS to re-request the record using an A query.
