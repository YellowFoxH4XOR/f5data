K000139327: BIG-IP as Web Gateway sends ICMP TTL Exceeded with an unexpected Source IP

Type
Support Solution
Published
2024-04-19
Updated
2024-04-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000139327

Description

When BIG-IP is used as a web gateway, traceroute from an internal client to a public IP shows an unexpected Self-IP being used on the BIG-IP hop.

 

Environment

  • BIG-IP is used as a web gateway
  • No TMM route from BIG-IP back to the client that initiates traceroute is configured
  • Auto Last Hop is enabled on the virtual server that processes the traceroute probes
  • Regular return traffic from pool member is passed towards client by Auto Last Hop mechanism
  • TMM default route is configured to a certain gateway device

Cause

Traceroute works by sending probes (e.g., dummy TCP/UDP segments, or ICMP Echo requests), with the value of Time-to-live on the IP packets as 1, 2, 3, and so on. When the first hop device receives the IP packet with TTL of 1, it should drop and send back an ICMP Time-to-live exceeded packet. The traceroute program uses the Source IP of this ICMP message to display as the IP address of the hop. This process repeats for the subsequent hops (TTL = 2, 3, 4, ...) until the end destination is reached.

 

On BIG-IP, the routing table can be used to determine which Self-IP will be the Source IP of ICMP time-to-live exceeded sent back to the client. However, with Auto Last Hop enabled on the virtual server, regardless of the Source or Destination address, the ICMP message will be sent back to the L2 address of the previous-hop device.

 

If the route on the routing table does not point back to the client, the Self-IP shown on the traceroute could be unexpected.

 

Example

 

For example, let's assume the following topology:

 

Client <--> Firewall device <--> BIG-IP <--> ISPs A and B on different VLANs

 

Traffic to www.f5.com is configured to go through a certain virtual server which uses ISP A as the only pool member. However, the default TMM route points to ISP B. Hence, when a traceroute to www.f5.com is initiated from the client, it may appear that Self-IP of VLAN for ISP B is used.

 

In this example, the Source of ICMP Time-to-live exceeded is the Self-IP on VLAN to ISP B, but because of Auto Last Hop, it is sent directly to the previous hop device, which is the Firewall.

 

Recommended Actions

Add a static route towards the client. Please refer to K13833: Managing static routes in BIG-IP and BIG-IQ.

 

Additional Information

The behavior of Source IP selection described above does not apply to normal return traffic from pool member. For return traffic, BIG-IP uses the original Destination IP of client to BIG-IP packets, as the Source IP for BIG-IP to client response packets.
