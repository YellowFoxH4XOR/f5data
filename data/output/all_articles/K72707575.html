Topic

You should consider using this procedure under the following conditions:

  • The application is under a Predictable Resource Location attack.
  • You want to mitigate Predictable Resource Location attacks.

You can use the BIG-IP ASM system to mitigate Predictable Resource Location attacks. A Predictable Resource Location attack is a common attack against a web application and targets hidden content and functionality of a web application. By guessing common names for directories or file names, the attack can uncover hidden parts that are not linked to the main web application, such as an administrative directory of files that are not publicly published. Some common examples include the following:

  • /backup
  • /logs/
  • 2019.report.html
  • temp_login.html

Note: This attack can also occur with brute forcing directories and file names, which is different from login brute force.

Description

The BIG-IP ASM system can mitigate Predictable Resource Location attacks using appropriate attack signatures or defined meta characters. The following procedure includes the steps you need to take to mitigate Predictable Resource Location using the attack signatures since this is the fastest and easiest configuration.

The procedure includes instructions for assigning the relevant attack signature set, enabling, and configuring it to mitigate Predictable Resource Location attacks. After you perform this procedure, you can verify mitigation by reviewing the request logs.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP ASM system.
  • A security policy is assigned to the virtual server.
  • You configure the ASM request log to log illegal requests.

Procedures

  • Enabling and enforcing the Predictable Resource Location signatures
  • Reviewing the request logs for verification

Enabling and enforcing the Predictable Resource Location signatures

To enable and enforce the Predictable Resource Location signatures, perform the following procedure:

Impact of procedure: Adding attack signatures to the security policy can generate false positives. For example, known false positives for Predictable Resource Location can occur due to the presence of English words, such as 'select' and 'from' in the HTTP request. In such cases, you should remove false positives from the Traffic Learning page by accepting any learning suggestions for disabling the signature. Adding the Predictable Resource Location attack signature set covers various types of servers. This step provides protection, regardless of the type of server on the back end.

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. At the top-right of the page, click Advanced.
  3. On Attack Signatures, click to the expand the settings.
  4. Click Change.
  5. Click Predictable Resource Location and click Change.
  6. Verify that the signature set has learn Alarm and Block enabled.
  7. Click Save and then click Apply Policy. The page will reload.
  8. On Attack Signatures, click to expand the settings.
  9. Clear the Enable signatures staging option.
  10. Click Save, then click Apply Policy.
  11. In General Settings at the top of the page under Enforcement Mode, click Blocking.
  12. Click Save.
  13. Click Apply Policy.

Reviewing the request logs for verification

To review the request logs for verification, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Security > Event Logs > Application >  Requests.
  2. To open the filter, click Show Filters Details. Next, perform the following steps for your version:

    • 13.x and later

      1. Click the Open Filter icon.
      2. Click the IP / Username / URL tab.
      3. For Violation, select Attack signature detected.
      4. Click Apply Filter.
    • 12.x
      1. Under Violation, choose Attack signature detected.
      2. Click Go.
  3. The request log should list the blocked request with the Predictable Resource Location, displaying the attack type name.
