Known Issue

This is the result of a known issue. The BIG-IP ASM loads policies with certain XML profiles slowly. In some cases this causes a startup timer to expire, resulting in continous restarts of the BIG-IP ASM bd process.

When this issue occurs, error messages will be logged to the /var/log/asm file that appear similar to the following example:

perl[18372]: 01310027:2: ASM subsystem error (nwd.pl,main::log_failure): Watchdog detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).

CommandMsg[18365]: [ERR, Thu Sep 18 04:03:45 2008, 18365, fbagent, CommandMsg::check_command_timeout, ] Command: code=1 ack=2 dropped on timeout

In addition, error messages will be logged to the /var/ts/log/bd.log file that appear similar to the following example:

BD_SSL|CRIT |20/09/08 00:29:45|17345|main.c:520|Timeout detected while waiting for configuration. BD aborting

F5 Product Development tracked this issue as ID216719 (formerly CR105970) and it was fixed in BIG-IP ASM version 9.4.6. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, Hotfix-BIG-IP-9.4.5-HF2 has been issued for BIG-IP ASM version 9.4.5. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Note: BIG-IP ASM version 9.4.6, and version 9.4.5 Hotfix-BIG-IP-9.4.5-HF2 include code to increase the default timeout from 10 to 30 seconds. If you upgrade to BIG-IP ASM version 9.4.6, or version 9.4.5 Hotfix-BIG-IP-9.4.5-HF2 and the issue persists, contact F5 Technical Support for assistance with increasing the timeout, or optimizing the existing policy to load faster.
