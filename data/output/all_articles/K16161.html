Known Issue

The Mozilla Firefox browser may be unable to connect to the BIG-IP Configuration utility.

This issue occurs when all of the following conditions are met:

  • You are using the Firefox 31 or later.
  • You attempt to establish a connection with the BIG-IP Configuration utility.

Starting in Firefox 31, the browser no longer accepts certificates generated with the basic constraints isCA=TRUE option; BIG-IP self-signed SSL certificates include the isCA=TRUE option.

Impact

Users cannot access the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H501131 on the Diagnostics > Identified > Medium screen.
  • You can successfully connect to the Configuration utility using a different browser or with a Firefox release prior to 31.
  • You can successfully connect to the Configuration utility when the BIG-IP SSL certificate is signed by a public certificate authority.
  • You cannot connect to the Configuration utility when the BIG-IP SSL certificate is a self-signed certificate using the isCA=TRUE option.

Workaround

To work around this issue, you can use a different browser or regenerate the BIG-IP system's SSL certificate without the isCA=TRUE option. To do so, perform the following procedure:

Impact of workaround: Restarting the httpd process will interrupt the web browser's connection to the BIG-IP system. If the device is a GTM or an LTM that is part of a GTM mesh, connectivity between the devices will fail. Review and perform the following procedures.

Manually regenerating a new SSL certificate for the BIG-IP system that does not include the isCA=TRUE option

  1. Log on to the command line of the affected BIG-IP system.
  2. To regenerate a new SSL certificate, type the following command:

    /usr/bin/openssl req -rand /dev/random -new -sha256 -key /config/httpd/conf/ssl.key/server.key -x509 -days <expiration days> -out /config/httpd/conf/ssl.crt/server.crt -extensions usr_cert

    You will be prompted to supply the following certificate information:

    Country Name
    State or Province Name
    Locality Name
    Organization Name
    Organizational Unit Name
    Common Name
    Email Address

  3. Restart the Configuration utility by typing following command:

    bigstart restart httpd

The SSL certificate was regenerated on an LTM device monitored by a GTM device

  1. Log in to the command line of the monitoring GTM system.
  2. To run bigip_add and receive the newly regenerated SSL device certificate, use the following command syntax:

    bigip_add <LTM IP Address>

    For example, to receive a newly regenerated SSL device certificate from an LTM device with IP address 192.168.10.100, type the following command:

    bigip_add 192.168.10.100

The SSL certificate was regenerated on a GTM device monitoring remote LTM devices

  1. Log in to the command line of the monitoring GTM system.
  2. To run bigip_add and send the newly regenerated SSL device certificate to all of the remote devices listed in the GTM configuration, type the following command:

    bigip_add
