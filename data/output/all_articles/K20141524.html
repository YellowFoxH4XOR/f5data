Description

This solution article provides the steps necessary to successfully migrate the configuration from a non-iSeries platform to an iSeries platform.  Additional considerations are required when AFM and ASM are provisioned as these will need additional steps to migrate the configuration successfully.
 

Environment

  • BIG-IP AFM
  • BIG-IP ASM
  • Platform Migrate from 10200 to iSeries i7820

Cause
This is caused by ID990849/ID995629 and ID981485
AFM on iSeries does not have turboflex-security profile enabled

Recommended Actions

Pre-requisites

  1. Ensure there are no errors in the config on the non-iSeries platform prior to saving UCS.
    tmsh load sys config verify
  2. Save UCS as per K82540512 - refer to the section: Saving UCS files on the device to be replaced

On New iSeries Platform:

  1. Boot into the new volume on iSeries Platform (must be same software version as old device)
  2. If AFM is provisioned in UCS, enable turboflex-security on GUI by navigating to
    System > Resource Provisioning: TurboFlex > Enable turboflex-security 
    Services restart automatically with a message on GUI which says "Please wait while the Configuration Utility starts.'
  3. If CLI continuously displays "Re-starting neurond" messages then a reboot is required on the system. This is caused due to ID981485
  4. Perform manual reboot on CLI by running the below command
    # reboot
  5. After reboot, verify turboflex-security is made active by navigating to 
    System  >  Resource Provisioning : TurboFlex
  6. Provision AFM and other Modules EXCEPT for ASM.
    System  >  Resource Provisioning: Module Allocation
    Modules will be provisioned accordingly when loading the UCS.  The purpose of this step is to identify any errors with provisioning modules.
    Important: For ASM policies to load successfully, DO NOT provision ASM due to ID995629
  7. Restore UCS as per K82540512 - refer to the section: Loading UCS configurations on the new device
    The below message will be displayed.
    Platform migrate loaded successfully. Saving configuration
  8. If stuck here after 10 mins, then hit Ctrl+c to exit the script and manually save the config by running the below command :
    # tmsh save sys config
  9. Clear mcpd database and reload config:
    # touch /service/mcpd/forceload && pkill mcpd
  10. Review log messages for progress whilst services restart:
    For ltm logs, use tailf /var/log/ltm 
    For ASM logs, use tailf /var/log/asm
    The message "Restoring active policy" messages show ASM policies are restoring correctly.
  11. Device should come online after the configuration has successfully loaded.  This may take some time depending on the size of the configuration.
  12. Resolve any outstanding network issues in the base configuration such as updating trunks and vlans.

Additional Information

For more information on TurboFlex profiles, access this page:  TurboFlex Profiles Overview
