Description

You would like to know how BIG-IP deletes the session in the bellowing scenario:
  • BIG-IP is in LAST-ACK state, which means in the server-side connection, the server sends FIN to end the session, BIG-IP acknowledges the FIN packets and sends FIN as well, however, the server doesn't send ACK packets to acknowledge the FIN packets
  • You can refer to the sample capture bellow, BIG-IP sends 1st retransmission FIN packets in packet #10, the retransmission interval was controlled by minimum-rto in the TCP profile, the default is 1s. After each retransmission, the interval is doubled. You will see the retransmission interval will be 1s, 2s, 4s, 8s,16s
  • The close-wait-timeout controls when the connection will be marked as deletion, by default it's 5s. Please note this parameter will only mark the connection for deletion and will not be used to delete the connection.  For example, the 1st retransmission is in 652.47s, the connection will be marked for deletion in 657.47s. If the 2nd retransmission arrives between 652.47s to 657.47s, the mark will be removed.
  • Other than close-wait-timeout, there is an internal timer called sweeper which runs every 6.4s. The sweeper then comes through at its regular interval and removes any connections that are marked for deletion. In packet#14, BIG-IP runs the sweeper at  674s and finds the connection was marked as deletion, then it sends RST to delete the session.
