Description

  • SSO with NTLM not working, credential mapping fails

Environment

  • APM
  • NTLM

Cause

  • Access Policy is configured to authenticate with NTLM2,
  • Configured SSO /Common/NTLMV2 maps username and password,
  • Password received by the APM is encrypted,
    • session.sso.token.last.password, ConfigVal ***encrypted***
  • This result in the APM not able to populate SSO, 
  • The APM also logs the below weeor message in /var/log/apm file
    • debug apmd[7507]: 0149013d:7: /Common/<name of access-policy>:Common:6b6f7c2d: CREDENTIAL MAPPING agent: Master encrypt failed, null plain password

Important:  APM must receive an unencrypted password for most SSO to function

Recommended Actions

  • Since the configuration does not or can't associate password, either remove SSO password requirement or adjust policy configuration so that the required credential can be mapped to subsequent applications.
