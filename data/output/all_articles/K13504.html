Known Issue

The sync subshares from-service command fails to replicate shares to the backend filers when there is a case mismatch between the ARX export definition and the directory on the backend filer, identified as the master.

Impact

Subshares are not synchronized to the backend filers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX sends an SNMP trap that appears similar to the following example:

    subshareExportDegradedRaise (728) : The export Directory_Share is degraded. Run 'sync subshares from-service myvip.corp.com to-namespace cifs-ns volume /volume1 tentative' command to see a detailed report.

  • The procdat log file contains a message that appears similar to the following example:

    :SUBSHRMGT-0-DBG-MSG7::change.cc:648:execute - layer::change::execute([ADD \\10.10.10.13\Directory_Path_Name, native]) failed: Directory 'Directory_Path_Name' does not exist in this volume, the subshare 'Directory_Share' cannot be synchronized to the backend filers.

  • The sync subshares report contain an error message that appears similar to the following:

    Problem: Share missing.
        Share Name: share1
        Relative Path: adir\dir1
        Import Share: share_root
        Filer Name: filer1
        Filer IP: 10.10.10.65
        Status: Attempt to synchronize failed: Directory 'adir\dir1' does not
                exist in this volume, the subshare 'share1' cannot be
                synchronized to the backend filers.

Workaround

To work around this issue, you can manually create the shares on the backend filers or you can edit the ARX export definition to resolve the case mismatch between the export and the directory name on the backend filer, using the following procedure:

Edit the ARX export definition

To change the case used in an ARX export definition, you must remove the export and re-add the export using the desired case. To do so, perform the following procedure:

Impact of workaround: Clients may be required to reconnect to the affected ARX export (share).

  1. Log in to the ARX CLI.
  2. Enter privileged mode by typing the following command:

    enable

  3. Enable global mode by typing the following command:

    global

  4. Enter the affected CIFS service configuration mode using the following command syntax:

    cifs <global_server_name>

    In this command syntax, note the following:
    • <global_server_name> is the name of the global server hosting this CIFS service.
  5. Remove the affected export using the following command syntax:

    no export <namespace> <directory_path> as <share_name>

    In this command syntax, note the following:
    • <namespace> is the affected namespace.
    • <directory_path> is the affected directory path within the namespace.
    • <share_name> is the affected share name.
    For example:

    no export namespace1 \dir1 as share1

  6. Re-add the export using the proper case to match the directory name on the backend filer. To do so, use the following command syntax:

    export <namespace> <directory_path> as <share_name> filer-subshare

    For example:

    export namespace1 \Dir1 as share1 filer-subshare

  7. Repeat Steps 5 and 6 for each affected export.
  8. Exit global configuration mode by typing the following command:

    end

  9. Once you have corrected all of the case mismatches, you can re-run the sync subshares from-service command.
