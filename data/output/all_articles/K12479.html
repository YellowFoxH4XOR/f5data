Issue

When enabling a Windows filer share, the import scan may fail. In addition, an error message in the syslog file may appear similar to the following example:

:DNAS_IMPORT-2-ERR-IMPORT_SCAN_FAILED:: Import scan for share SHARENAME$ (\\10.10.11.11\SHARENAME$ [33]) has failed, Error: 'Network error occurred during operation [-308]'.

Additionally, the ARX system may send SNMP traps that appear similar to the following example:

: SNMP TRAP: shareImportFail (650) shr 'Fileserver.com:/MV-VD01:SHARENAME$', name winfiler.fileserver.com', ip '10.10.11.11', Error: Network communications failure during import scan. Check the import report for more details.

: SNMP TRAP: shareOffline (670) shr 'Fileserver.com:/MV-VD01:SHARENAME$', name 'winfiler.fileserver.com', ip '10.10.11.11',

This issue has been reported to occur when the Windows filer is configured with an autodisconnect setting of 0 instead of the default value of 15. When set to 0, the Windows server will disconnect idle connections after a few seconds, rather than the default time of 15 minutes. As a result, the Windows filer may prematurely close the import TCP connection.

You can change this setting on the Windows filer by using the following command syntax:

net config server /autodisconnect:<time>

For example, to return to the default value of 15, you would type the following command:

net config server /autodisconnect:15

Note: For more information about the autodisconnect setting, refer to the following Microsoft KB article. The following link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge:

http://support.microsoft.com/kb/138365
