Known Issue

This is the result of a known issue. When using the persist command in an iRule, TMM may fail to decrement the persistence timeout clock for pool members. When this behavior occurs, TMM cores with a SIGFPE panic that appears similar to the following example:

panic: ../base/persist.c:206: Assertion "valid npersist count" failed.

F5 Product Development is tracking this issue as CR108086.

This issue was fixed in Hotfix-BIGIP-9.4.8-396.1-HF3 issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
