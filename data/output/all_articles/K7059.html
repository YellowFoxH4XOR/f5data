K7059: Pre-logon check fails with Symantec Confidence Online server

Topic

This issue is caused by a third party component, and not a problem with the FirePass controller. Consult the ActiveX control documentation for information about fixes for this third party issue.

If a FirePass controller is configured to perform a pre-logon sequence using Symantec's Confidence Online Server, and the FirePass controller's SSL server certificate creates a warning condition in the browser, the pre-logon sequence will fail and logon will be denied.

The Confidence Online Server's ActiveX control is downloaded to the host from the FirePass, and run whenever required by a pre-logon sequence using the Inspector for the Confidence Online Server. The ActiveX control does not properly handle certificate events in the SSL negotiation.

The FirePass controller integrates with the Symantec Confidence Online Server, which provides policy-based management for endpoint systems.

A FirePass pre-logon sequence configured to use the Confidence Online Server collects information about the host endpoint system, which is then reported to the Confidence Online Server. In turn, the FirePass receives a pass or failure notification from the Confidence Online Server, depending on whether the host meets the policy specified by the Confidence Online Server.

If the FirePass controller is using an SSL server certificate which creates a warning message in the browser, then the check for the Confidence Online Server will fail. Warnings occur when a certificate has expired, the Common Name does not match the hostname used in the URL, the certificate chain did not end in a trusted root CA certificate, or other reasons.

Users will not see a certificate warning pop-up window, but will see a pop-up window with a message similar to the following example:

Server Connection Failed
 The server returned an error.
 Please contact the Help Desk

Users will then be directed to the logon denied page.
