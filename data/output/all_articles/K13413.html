Known Issue

The Configuration utility incorrectly reports the Trusted Certificate Authorities option for the Certificate Authority profile as None. This issue occurs when all of the following conditions are met:

  • The affected BIG-IP system is licensed and provisioned with BIG-IP APM
  • A Certificate Authority profile is created with the Trusted Certificate Authorities option set to any value except None

This issue occurs because the Configuration utility incorrectly returns the certificate filename without the full path (for example, ca-bundle.crt) while the configuration database stores the configured certificate filename with the full path (for example, /Common/ca-bundle.crt). As a result of the mismatch, the Configuration utility reports the Trusted Certificate Authorities option with the default value of None.

Impact

This is purely cosmetic and does not affect traffic processing capability of the BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The Configuration utility incorrectly reports the Trusted Certificate Authorities option as None, but the tmsh list /ltm profile certificate-authority command reports the correctly configured certificate file.

Workaround

To work around this issue, you can view the Certificate Authority profile with the correctly configured certificate file using the tmsh shell. To do so, perform the following procedure:

Impact of procedure: None.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. View the Certificate Authority profile with the correctly configured certificate file by entering the following command:

    list /ltm profile certificate-authority <profile name>

    For example, to view the MyCAprof profile, you would enter the following command:

    list /ltm profile certificate-authority MyCAprof
