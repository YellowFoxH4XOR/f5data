Description

Answer/Recommended Actions

Timeout settings on Load Balancer in XC are used on both sides of a connection.

  • Idle Timeout -  the amount of time that a connection can remain open without any activity between the client and the load balancer. In other words, if there is no data exchange between the client and the load balancer within the specified time period, the connection is considered idle and may be terminated by the load balancer.

  • Connection Timeout - typically refers to the time period during which the load balancer and the backend server are trying to establish a TCP connection, which involves a three-way handshake. (The SYN - SYNACK -ACK).

  • HTTP Idle Timeout - the amount of time that the load balancer waits for an HTTP request to complete after TCP connection has been established. If the request takes longer than the specified time period to complete then the load balancer terminates the connection and marks the backend server as unavailable. HTTP Idle Timeouts are typically used to prevent long-running requests from tying up resources on the backend servers, and to ensure that connections are released promptly after requests are completed.

Additional Information

  • What is the difference between Connection Timeout and Idle Timeout?

    Connection Timeout occurs during the initial phase of establishing TCP connection while Idle Timeout occurs after the connection has been already established.
  • If you setup Routes in your HTTP Load Balancer then the HTTP Idle Timeout on the Route will override the HTTP Idle Timeout on the Load Balancer. (more details in What does each idle timeout inside of the Load Balancer mean?)

  • If you configure the timeout of the Route's or Origin Pool's configuration to be longer than you have it on your own server then you will get an HTTP 5xx response code (probably 503 or 504) (see also I am receiving HTTP 504 Gateway timeout, what should I do?).
