Issue

Old Behavior

In versions prior to BIG-IP 13.0.0 and BIG-IP 12.1.3.3, when using the FQDN (fully-qualified domain name) option to populate node addresses, the system generates names for the ephemeral node objects using the following naming convention:

FQDN-ipaddr

For example, if you configure www.f5.com as the FQDN for the node, and the name resolves to IP address 10.20.30.40, the system generates the following name for the ephemeral node object:

www.f5.com-10.20.30.40

New Behavior

Beginning in BIG-IP 13.1.0 and BIG-IP 12.1.3.3, when using the FQDN option to populate node addresses, the system generates names for the ephemeral node objects using the following naming convention:

_auto_ipaddr

For example, if you configure www.f5.com as the FQDN for the node, and the name resolves to IP address 10.20.30.40, the system generates the following name for the ephemeral node object:

_auto_10.20.30.40

Note: If an FQDN node resolves to an IP Address which has been manually created as an LTM node, then the node and any pool members which use that node will not begin with _auto_

F5 Product Development tracked this change as ID 677439. The change was made to address cases when more than one FQDN resolves to the same IP address.
