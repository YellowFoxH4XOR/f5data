Description

Telemetry Streaming (TS) iHealthPoller is defined, however the daily qkview is not uploaded. Sample declaration:

=Showing the TS iHealthPoller section=

      "iHealthPoller": {
        "trace": true,
        "username": "REDACTED",
        "passphrase": {
          "cipherText": "REDACTED",
          "class": "Secret",
          "protected": "SecureVault"
        },
        "interval": {
          "timeWindow": {
            "start": "18:00",
            "end": "23:59"
          },
          "frequency": "daily"
        },
        "enable": true
      },

restnoded log file printing error message:

finest: [telemetry.IHealthPoller.f5telemetry_default::My_System::iHealthPoller_1] Error caught (state = uploadQkview)
Traceback:
Error: Bad status code: 404 404 for https://api.f5.com/auth/pub/sso/login/ihealth-api

 

Environment

  • TS iHealthPoller not uploading qkview as expected

Cause

Due to the authentication changes in F5 iHealth as described in K000132249, TS iHealthPoller qkview upload will fail and abort after 5 retries.

Bug ID 1603397 has been assigned to this issue.

 

Recommended Actions

There is no workaround in TS. This workaround may be considered:

  1. Follow the steps in K04396542 to generate the qkview
  2. Use K000135241 to upload the qkview to iHealth
