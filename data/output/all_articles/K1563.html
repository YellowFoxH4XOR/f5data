Topic

If BIG-IP or 3-DNS encounter errors when reading from or writing to a disk, errors similar to the following may be displayed.

Error message: kernel: wd0: hard error <reading | writing> fsbn...

These errors occur when one or more blocks on the hard drive have gone bad. To correct this, you must add these blocks to the hard drive?s bad block table.

Important: If you are running BIG-IP versions 4.1 through 4.2 PTF-05 on a BIG-IP 2000 or BIG-IP 5000 switch appliance, refer to the special section at the end of this Solution.

To add these blocks to the hard drive?s bad block table and eliminate this error, perform the following steps:

  1. Boot the system into single-user mode. For instructions, refer to the following version-specific solutions:
    • For BIG-IP and 3-DNS versions 4.0 through 4.6.4, refer to K2230: Booting BIG-IP or 3-DNS into single user mode.
    • For 3-DNS versions 3.0 through 4.0.2, refer to Booting the 3-DNS Controller into single user mode.
    • For BIG-IP versions 1.8.3 through 3.3.1 PTF-06, refer to Booting BIG-IP into single user mode.
  2. Mount all partitions in read/write mode, by typing the following command:

    /sbin/mount -a

  3. Rewrite the bad block table, by typing the following command:

    Note: If this is the first time you are running diskdefect on this system, do not use the -a flag.

    /sbin/diskdefect -a -swcv wd0

    Note: This command can take up to 45 minutes to run.

  4. Crosscheck all the inodes for the hard drive and correct inconsistencies, by typing the following command:

    /sbin/fsck -y

  5. After you complete the crosscheck, type the following command to reboot the controller:

    /bin/reboot

    When the controller powers up, allow it to boot normally into multi-user mode.

Preventing Disk Errors on the BIG-IP 2000 and BIG-IP 5000 Platforms

In versions 4.1 through 4.2 PTF-05, BIG-IP performed more writes to the compact flash memory than the device was capable of reliably sustaining. As a result, the compact flash device could develop bad sectors at an unacceptable rate.

F5 Networks recommends that you immediately upgrade to a fixed version in order to avoid damage to your compact flash drive.

To recover bad sectors caused by this problem, refer to K1815: Recovering a corrupt compact flash drive.

F5 Networks Product Development tracked this issue as CR21375, CR21376, CR21397, CR21657, CR21659, CR21660, and CR21663 and it was fixed in BIG-IP version 4.1.1 PTF-06 for the BIG-IP version 4.1 branch and BIG-IP version 4.2 PTF-06 for the BIG-IP version 4.2 branch.
