Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator creates multiple connections to MCP with each triggered invalidation. However, one of the connections is not terminated. Rebooting the BIG-IP WebAccelerator will not clear these connections, and the connections are reestablished due to outstanding invalidations.

F5 Networks Product Development tracked this issue as CR96373 and it was fixed in BIG-IP WebAccelerator version 9.4.5. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.4-HF1 issued for BIG-IP version 9.4.4. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about how to manage F5 Networks product hotfixes, refer to K6845: Managing F5 Networks product hotfixes.

Workaround

You can manually clear the connections by deleting the triggers file and restarting the pvac process. To do so, perform the following procedure:

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Change directories to the /var/wa/esi_journal/triggers directory by typing the following command:

    cd /var/wa/esi_journal/triggers
  3. Delete the triggers file by typing the following command:

    Note: In the following command, replace <triggers_file> with the name of the triggers file located in the /var/wa/esi_journals/triggers directory.

    rm <triggers_file>
  4. Restart the pvac process by typing the following command:

    Important: Restarting the pvac daemon will briefly disrupt connections and invalidate objects in the BIG-IP LTM RAM Cache. Restarting the pvac daemon should be scheduled accordingly.  

    bigstart restart pvac
