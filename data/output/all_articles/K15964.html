Known Issue

Link Aggregation Control Protocol (LACP) links may not be properly removed from aggregation groups.

This issue occurs when the following condition is met:

  • The BIG-IP system does not receive LACPDU packets from the upstream peer, due to unidirectional packet loss.

When the BIG-IP system removes a link from aggregation, it sends an LACPDU packet with the sync flag set, which may prevent the upstream peer from properly removing the link from the aggregation group.

Note: Packet loss that occurs in only one direction is unusual. While this behavior can be induced in a simulated environment, it is more common for LACP monitoring from both end points to catch packet loss, with both end points properly removing the suspect link from the link aggregation group.

Impact

The peer device in an aggregation group may continue to aggregate a link which should be removed from the aggregation group.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system indicates removal of a link from the aggregation group by setting the link as expired, similar to the following example:

    show net trunk detail

    -----------------------------------
    | Net::LACP Status (interface: 1.3)
    -----------------------------------
    | PortID Key State
    | Actor 16974083 3 expired
    | Partner 16974083 3 up

    However, the upstream peer system continues to indicate that the link is still part of the aggregation group, similar to the following example:
    show net trunk detail

    -----------------------------------
    | Net::LACP Status (interface: 1.3)
    -----------------------------------
    | PortID Key State
    | Actor 16974083 3 up
    | Partner 16974083 3 defaulted
