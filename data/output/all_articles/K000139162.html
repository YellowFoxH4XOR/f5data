K000139162: Scheduled Backup files are generating in BIG-IP instead in BIGIQ.

Type
Support Solution
Published
2024-04-10
Updated
2024-07-01
Applies to

  • BIG-IQ Centralized Management: 8.2.X, 8.3.X, 8.3.0, 8.2.0
Source
https://my.f5.com/manage/s/article/K000139162

Description

You have a scheduled daily backup of UCS files from the BIG-IP on BIG-IQ in BACKUP & RESTORE >> Backup Schedules , but after a couple of days, the UCS schedules have started failing and the BIG-IQ started creating the UCS backups on the BIG-IPs devices instead on BIG-IQ with the following errors:

Schedule failed. Task example.ucs failed: No space left on the device.

Also the df -h command show the /shared partition is full where BIG-IQ store the ucs files from BIG-IP devices :

df -h

Filesystem               Size Used Avail Use% Mounted on

/dev/mapper/vg--db--vda-set.2.root   419M  98M 295M 25% /

devtmpfs                16G 4.0K  16G  1% /dev

tmpfs                  16G 2.3M  16G  1% /dev/shm

/dev/mapper/vg--db--vda-dat.share.1   30G  30G   0 100% /shared <-----------

 

If /shared is not currently showing 100% use, then some space may have freed up since the event.

/var/log/ltm will log the following entry at the time /shared is full:

err diskmonitor[11701]: 011d0004:3: Disk partition /shared has only 0% free

Environment

  • BIG-IQ
  • BIG-IP
  • Backups schedules

Cause

The /shared partition full on BIG-IQ

Recommended Actions

There are several solutions for the problem depending on your environmental requirements:

  •  Delete the old ucs files from the GUI of the BIG-IQ in BACKUP & RESTORE >> Backup Files or using the CLI and navigate to the following path:

cd /shared /ucs_backups

  • Resize /shared partition for extra space on BIG-IQ based on the following article:

K30902515: Resizing the /var, /var/log, or /shared file system on a BIG-IQ Virtual Edition

  • Modify the Local Retention Policy in the BACKUP & RESTORE >> Backup schedules for less copies stored.
