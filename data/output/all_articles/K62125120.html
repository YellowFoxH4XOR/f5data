Issue

Error Message

01071470:3: Disconnecting from CMI device <device_name>, the device is not in a trust domain.

In this error message, note the following:

  • <device_name> is the remote device attempting to create a centralized management infrastructure (CMI) connection to the local device that has logged the error.

For example:

01071470:3: Disconnecting from CMI device /Common/lb01.example.com, the device is not in a trust domain.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when the following condition is met:

  • A remote BIG-IP system attempts to create a CMI connection, but the device does not belong to the local device trust due to one of the following reasons:

    • The remote BIG-IP system was removed from the device trust while it was in an offline state.
    • The remote BIG-IP system attempts to create a CMI connection, but the local device has no self device.
    • The local BIG-IP system belongs to a device trust and has been rebooted to a partition where device trust is not configured.

Impact

If the remote BIG-IP system is expected to be part of the local device trust, synchronization or failover does not occur. If the remote device is not expected to be part of the local device trust, there is no impact other than moderate disk space consumption due to the additional logging messages.

Recommended Actions

If this device should not be a member of the local device trust, use the Removing the device from the device trust procedure. If the device should belong to the local device trust, use both the Removing the device from the device trust and the Adding the device to the device trust procedures.

  • Removing the device from the device trust
  • Adding the device to the device trust

Removing the device from the device trust

To stop the error message, log in to the remote BIG-IP system attempting the connections and remove it from the trust domain. This is the device noted in the <device_name> portion of the error message.

Impact of procedure: Deleting the device trust may cause another device to become active and begin processing traffic. Perform this procedure only during a planned maintenance window.

  1. Log in to the Configuration utility of the remote BIG-IP system making the connection attempts.
  2. To prevent the device from becoming active and processing traffic, navigate to Device Management > Devices.
  3. Select the device name indicated with (Self).

    For example:

    lb01.example.com (Self)
  4. Click Force Offline.
  5. Navigate to Device Management > Device Trust.
  6. Click Reset Device Trust.
  7. For the Reset Device Trust option list, select Generate new self-signed authority.
  8. Click Update.

Adding the device to the device trust

To add the remote device back to the local trust domain, perform the following procedure.

Impact of procedure: Perform this procedure only during a planned maintenance window.

  1. Log in to the Configuration utility of the local device where error messages are being logged.
  2. Navigate to Device Management > Device Trust.
  3. Select the device group.
  4. Select Peer List or Subordinate List.

    Note: A subordinate device cannot sign a certificate for another device.
  5. Click Add, and enter the remote system's information for the Device IP address, Administrator Username, and Administrator Password fields.
  6. Click Retrieve Device Information.
  7. Verify that the Device Certificate information for the remote device being added is correct.

    Note: The Device Certificate information can be viewed in the remote system's Configuration utility by navigating to System > Device Certificates > Device Certificate.
  8. Click Finished.
  9. Log in to the Configuration utility of the remote BIG-IP system that you just added.
  10. To enable the device for high availability (HA), navigate to Device Management > Devices.
  11. Select the device name indicated with (Self).

    For example:

    lb01.example.com (Self).
  12. Click Release Offline.
