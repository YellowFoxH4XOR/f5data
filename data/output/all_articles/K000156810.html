Description

Deploying a single-NIC BIG-IP VE on Microsoft Azure using the Standard_D8s_v5 instance type may result in data-plane interfaces not displaying correctly within the BIG-IP configuration. Running tmsh show net interface only shows the management interface as follows:

# tmsh show net interface

--------------------------------------------------------------
Net::Interface
Name  Status   Bits   Bits  Pkts   Pkts  Drops  Errs     Media
                 In    Out    In    Out
--------------------------------------------------------------
mgmt      up  19.2G  20.6G  8.4M  10.0M      0     0  100TX-FD

In TMUI, the interface list appears empty as follows:

 

Environment

  • Product: BIG-IP VE (Virtual Edition)
  • Platform: Microsoft Azure
  • Instance Type: Standard_D8s_v5

Cause

Single-NIC deployments on Azure D8s_v5 series instances are not supported due to ID2098861.

Recommended Actions

To work around this issue, you can either:

  1. Use Ds_v4 Instance Sizes for Single-NIC Deployments
    The Ds_v4 series supports single-NIC configurations for BIG-IP VE.
  2. Use Smaller Ds_v5 Sizes
    Certain smaller sizes in the Ds_v5 family (e.g., D2s_v5) have been shown to work with single-NIC setups.
  3. Migrate to a Multi-NIC Configuration
    Deploy BIG-IP VE with separate NICs for management and TMM/data traffic.
    Each NIC must reside in a different subnet.
    Key steps for reconfiguration:
    • Ensure you can connect to serial console and login to the BIG-IP VE with a local admin account before starting.
    • Make a note of self-IP's and static routes configured on BIG-IP VE before starting.
    • Create a new subnet and route table dedicated for management.
    • Create a new management NIC in this subnet.
    • Move your management public IP address to the new NIC.
    • Attach the new management NIC to your VM, detach the old one, and start the BIG-IP VE with only the new management NIC in place.
    • Shutdown BIG-IP VE and reattach your data NIC to the instance.
    • Reconfigure VLANs and Self IPs as needed, ensuring VLANs are created as untagged on their respective interfaces.
    • Save configuration changes and reboot if necessary.
