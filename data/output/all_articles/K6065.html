Issue

This article applies to BIG-IP 9.x - 10.x. For information about other versions, refer to the following article:

  • K72087447: Error Message: HA Connection with peer [address:port] for traffic-group /Common/[traffic-group_name] lost. (11.x - 13.x)

Error Message

err tmm [PID#]: 01340002:3: HA connection with peer [address:port] lost.

In this error message, note the following:

  • [PID#] is the process ID number of the reporting TMM process
  • [address:port] is the IP address:port of the mirroring connection to the peer BIG-IP system

For example:

err tmm[4883]: 01340002:3: HA Connection with peer 10.12.15.11:32772 lost.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when the following condition is met:

  • The connection used for mirroring connection and persistence state information, between members of a redundant pair, has encountered an interruption.

    Note: The message could be a result of an expected interruption, such as the reboot of a peer system.

Note: A message similar to the following example is logged when the mirroring connection has been successfully re-established:

notice tmm[PID#]: 01340001:5: HA Connection with peer [address:port] established.

Impact

Mirroring information for established connections may not have been mirrored to the peer system. As a result, connections may not continue or persist as expected in the event of a failover.

Note: If the error message was the result of an expected mirroring connection interruption, you can safely disregard the message.

Recommended Actions

If the error message was the result of an unexpected mirroring connection interruption, you will need to determine the cause of the mirroring connection interruption. Performing the following actions may help you identify the cause:

  • Verifying the IP addresses used for Network Mirroring
  • Verifying that Port Lockdown on the failover VLAN(s) is set to allow the appropriate port (1028). For more information, refer to K7317: Overview of port lockdown behavior (9.x) and K9057: Service port and protocol used for BIG-IP network failoverOverview of the BIG-IP LTM network failover transport protocol.
  • Verifying other network device that mirroring connection may transit between the peer systems.
Verifying the IP addresses used for Network Mirroring

To verify that each member of the redundant pair is configured with the Network Mirroring IP addresses of its peer, perform the following procedure that applies to your specific version:

Note: F5 Product Development has made changes across 9.x and 10.x versions regarding Network Mirroring, ConfigSync, Connection Mirroring, and Failover in general. For more information regarding the various changes made, refer to K11736: Defining network resources for BIG-IP high availability features (9.x - 10.x).

BIG-IP 10.0.0 - 10.2.4

  1. Log in to the Configuration utility for the Active Unit.
  2. Click System.
  3. Click High Availability.
  4. Click Network Mirroring.
  5. Verify the Mirroring Address Self and Peer fields contain the failover IP address of the current unit (Self) and the failover IP address of the peer unit (Peer).
    The system automatically uses these addresses for ConfigSync unless you specify another address.
  6. Repeat steps 1 through 5 for the Standby Unit.

BIG-IP 9.4.0 - 9.4.8

  1. Log in to the Configuration utility for the Active unit.
  2. Click System.
  3. Click High Availability.
  4. Verify the Failover Address Self and Peer fields contain the failover IP address of the current unit (Self) and the failover IP address of the peer unit (Peer).
  5. Repeat steps 1 through 4 for the Standby unit.

BIG-IP 9.0 - 9.3.1

  1. Log in to the Configuration utility for the Active unit.
  2. Click System.
  3. Click High Availability.
  4. Verify the Primary Failover Address Peer field contains the failover IP address of the peer unit.
  5. Optional: To use a secondary failover address, the Secondary Failover Address Peer field should contain the secondary failover IP address of the peer unit.
  6. Repeat steps 1 through 5 for the Standby unit.
