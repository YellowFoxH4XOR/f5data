K000135005: Telemetry streaming local listener VIP (telemetry pool) being marked down by the health monitor

Type
Support Solution
Published
2024-09-12
Updated
2024-09-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0
Source
https://my.f5.com/manage/s/article/K000135005

Description

You have followed F5 Clouddocs documentation for Telemetry Streaming but the traffic is not getting sent to the remote end.


Environment

- BIG-IP v17

- Set up Telemetry streaming based on F5 Clouddocs:


Quick Start

https://clouddocs.f5.com/products/extensions/f5-telemetry-streaming/latest/quick-start.html

Event Listener class

https://clouddocs.f5.com/products/extensions/f5-telemetry-streaming/latest/event-listener.html#standard



Cause

If you do not use the default route domain (RD0) for TMM traffic, there is no TMM route in RD0 and only a default MGMT route exist in RD0. In this case, the telemetry pool/Listener VIP you create (which can be any IP address) will be marked down by the health monitor and the traffic would be never sent to the remote end.


Recommended Actions

If you have followed the docs properly and if your telemetry pool is marked down, check your system and see if you have tmm route in the default route domain. If not, give a dummy /32 route for 255.255.255.254 (Telemetry pool/Listener VIP) on any TMM interface in RD0. For example;

------------

tmsh create net route 255.255.255.254 network 255.255.255.254/32 interface INTERNAL

tmsh save sys config

------------


Additional Information

In telemetry streaming set up, the local listener VIP/telemetry pool needs to be marked UP by the health monitor. Removing the health monitor would not fix a problem.
