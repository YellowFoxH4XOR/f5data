Issue

Description

When the BIG-IP system detects an issue related to the Cavium Nitrox PX or Nitrox 3 SSL encryption hardware, you may observe one or more of the following symptoms:

  • You notice performance degradation, as hardware offloading of SSL traffic stops and all SSL processing is done in software.
  • You observe one or more of the following messages in the /var/log/ltm file:
    • tmm3[13326]: 01010025:2: Device error: crypto codec cn-crypto-3 queue is stuck
    • tmm3[13326]: 01010260:2: Hardware Error(Co-Processor): n3-crypto1 request queue stuck

Environment

  • The BIG-IP system uses either the Nitrox PX or the Nitrox 3 encryption hardware, including the following platforms:
    • BIG-IP 800, 1600, 3600, 3900, 6900, 89xx, 5xxx, 7xxx, 10xxx, 11xxx, and 12xxx
    • VIPRION B41xx-B43xx, B21xx, and B22xx blades
  • You are using hardware-based SSL encryption.

Cause

Problems related to the Cavium Nitrox PX or Nitrox 3 SSL encryption hardware may be caused by the following factors:

  • Software-based issues
  • Communications issues between the hardware components
  • Hardware failure

Recommended Actions

To troubleshoot problems related to the Cavium Nitrox PX or Nitrox 3 SSL encryption hardware, refer to the following section:

Software issues

Software-based issues can be resolved by ensuring that the BIG-IP system is running the latest software version for the current release. If the BIG-IP system is running an older software version, the system may be experiencing a software-related SSL processing bug. To determine if your software version is covered by the software support policy, refer to K5903: BIG-IP software support policy.

Communication issues between the hardware components

If the BIG-IP system is running updated software, the 'queue stuck' messages may be caused by a communication issue between various hardware components. To resolve communication issues between hardware components, refer to the following actions:

  • Generate a QKView file while the system is in the degraded condition. For information about generating a QKView file, refer to K12878: Generating diagnostic data using the qkview utility.

    Note: For vCMP systems, run the qkview script on the vCMP host.

  • Schedule a time to reboot the BIG-IP system to restart communication between the affected components. For information about rebooting the BIG-IP system, refer to K7369: Shutting down and restarting the BIG-IP system.

Hardware failure

If the system is still experiencing 'queue stuck' messages after rebooting, it may be experiencing a hardware failure. To address a potential hardware issue, generate a QKView file and contact F5 Support.

Additional Information

  • Beginning in BIG-IP 11.5.4 HF3, 11.6.1 HF2, and 12.1.2 HF1, the nitrox_diag utility was created to help diagnose hardware errors associated with Cavium Nitrox SSL hardware accelerator cards. For more information, refer to K95944198: Overview of the nitrox_diag diagnostic utility.
  • Bug ID 571651 added functionality to the Nitrox 3 that can clear and reset a stuck queue without impacting other functionality. This only resolves issues with the Nitrox and does not resolve hardware communication issues or true hardware failure. Upgrading to the latest version of a current release ensures that this new functionality is present along with the fixes for software-based Nitrox issues.
