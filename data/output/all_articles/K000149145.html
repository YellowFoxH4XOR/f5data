K000149145: VLAN fail-safe not triggering failover on F5OS Tenant

Description

When using fail-safe mechanisms for VLANs on F5 BIG-IP systems, unexpected behavior can occur where the fail-safe does not trigger a failover during a network disruption. This issue can arise due to the fail-safe mechanism's reliance on traffic flow across the entire VLAN rather than individual interfaces.

This behavior is particularly observed in F5OS tenants on R5000/R10000 platforms, such as the R5600. These platforms utilize virtual NICs mapped to physical resources, making them operate differently compared to older systems with direct physical interface visibility.

Environment

  • F5 BIG-IP Hosted as a tenant on R5000/R10000 platforms 

Cause

Fail-safe mechanisms monitor traffic on a VLAN basis rather than specific interfaces. If traffic continues through other interfaces tagged on the same VLAN, the fail-safe condition is not met, preventing failover.

On R5000/R10000 platforms like the R5600, tenants lack direct visibility into physical interfaces or Link Aggregation Groups (LAGs). Instead, they operate with virtual interfaces tied to specific TMM cores. 

Recommended Actions

Consider alternative methods for detecting network disruptions instead of relying solely on VLAN fail-safe. These methods can provide more reliable failover detection and response.

Additional Information

A similar behaviour is documented for vCMP guests, If you configure more than one guest on a Virtual Clustered Multiprocessing (vCMP) host to use the same VLAN, you should avoid using the VLAN failsafe feature for the guest instances. When a vCMP guest detects a loss of network traffic on the VLAN and attempts to generate VLAN failsafe traffic, the other guests that are configured on the same VLAN may respond to the failsafe requests and prevent a failover event from occurring.
