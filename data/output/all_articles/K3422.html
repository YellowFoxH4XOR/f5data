Topic

The concept of content spooling is inherent to the design of the BIG-IP system and is enabled by default in the base TCP profile. Content spooling is managed through the following TCP profile settings:

SettingDescription
auto proxy bufferBIG-IP 13.0.0 and later. Specifies, when enabled, that the system uses the network measurements to set the optimal proxy buffer size. The default is disabled.
This feature allows for, instead of analyzing traffic captures and setting send buffer/receive buffer sizes manually, you can now select the auto option for send/receive buffer sizes and high/low watermarks for the TCP Proxy buffers.
Note: Each TCP flow, an estimate of the send/receive side bandwidth, is calculated and the send/receive buffer is sized, dynamically, based on the bandwidth delay product (BDP).
auto receive window
When enabled, the system uses the network measurements to set the optimal receive window size. The default is disabled.
auto send buffer
When enabled, the system uses the network measurements to set the optimal send buffer size. The default is disabled.
proxy buffer lowProxy buffer level at which the receive window is opened. For more information, refer to the Description section below the table.
proxy buffer highProxy buffer level at which the receive window is no longer advanced. For more information, refer to the Description section below the table.
send bufferThe upper limit of how much unacknowledged (ACK) data can be outstanding within a TCP connection. Large send buffers are necessary to achieve good throughput for hosts with high-latency links, or more specifically, high bandwidth-delay products.
recv windowThe upper limit (in bytes) that the BIG-IP advertises on the TCP receive window size. It is similar to the send buffer, in that a large receive window is necessary to achieve good throughput for hosts with high-latency links.

Description

Proxy buffer high

Proxy buffer high is the level at which the receive window is no longer advanced. For example, if the BIG-IP system is forwarding an HTTP response to a client and both the client and the server are equally fast, then the BIG-IP system does not need to buffer much of the TCP data. However, if there is packet loss to the client, or if the client is slow to acknowledge data and falls behind, the BIG-IP system will begin to accumulate data in the proxy buffer. Rather than accumulate an arbitrary amount of data, the BIG-IP system stops advancing the receive window to the server when the proxy buffer high threshold is exceeded. If the client continues to fall behind, the advertised receive window to the server will eventually be exhausted with each acknowledgement of TCP data. Once exhausted, the BIG-IP system closes the receive window by sending a packet with a window size value of zero. This stops the server from sending further TCP data until the window is opened up again.

It is important to note that even when the proxy buffer high threshold is exceeded, the BIG-IP system can still receive and buffer up to its advertised receive window's worth of data; the BIG-IP system will always honor its advertised receive window.

Proxy buffer low

Proxy buffer low is the level at which the receive window is opened. To continue with the example from the previous section, when the amount of data buffered in the proxy buffer has drained to the proxy buffer low threshold setting, the BIG-IP system opens the receive window to the server again, allowing the server to send more data. The BIG-IP system opens the receive window by sending a packet that has a window size value greater than zero.

Benefits and impacts of increasing the content spooling values

Generally, the connection between the client and the BIG-IP system is slower than the connection between the BIG-IP system and the pool member servers. Thus, the BIG-IP system can accept the servers' data more quickly, allowing valuable resources on the pool member servers to remain available. Increasing the content spooling setting values increases the amount of data the BIG-IP system will buffer while waiting for a given connection to accept it. Increasing these values can substantially reduce the load for pool member servers as they can offload the data more quickly to BIG-IP system, rather than waiting for the client to be ready to accept and retrieve more data. The feature works symmetrically, in that it can also offload faster clients and slower servers when uploads are occurring (for example, large POST data entity-bodies.)

Important: Increasing these values may cause the BIG-IP system to use more memory per connection, as the BIG-IP system will buffer more TCP data in order to be more efficient. Administrators must consider system memory utilization and traffic load before changing these parameters. F5 has determined that the default values in the TCP profile to be suitable for most deployments.
