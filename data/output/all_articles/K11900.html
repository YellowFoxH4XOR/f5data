Issue

Beginning in BIG-IP 10.0.1 HF4, 10.1.0 HF2, 10.2.0 HF1, and 10.2.1, log messages that report a pool member status change are no longer throttled.

In previous BIG-IP 10.x versions, log messages that report a pool member status change may exceed logging rate limits when a large number of pool members suddenly become unavailable. When this event occurs, the BIG-IP system logs a message similar to the following example to the /var/log/ltm file:

01070638:6: Per-invocation log rate exceeded; throttling.

Note: For more information about the error message and a description of throttling, refer to K10524: Error Message: Per-invocation log rate exceeded.

Note: In BIG-IP 9.x, log messages that report a pool member status change are not throttled.

The former BIG-IP 10.x behavior may hide critical information from log sifting utilities. For example, if ten different pool members simultaneously become unavailable, the BIG-IP system is likely to only log five pool member status change messages and one log rate exceeded message. As a result, examining the logs may not reveal which additional pool members have also become unavailable.

F5 Product Development tracked this change in behavior as ID 224090, ID 324272, ID 328278, and ID 330157 (formerly CR133929).
