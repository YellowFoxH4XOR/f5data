Known Issue

The X509 iRules commands may incorrectly parse SSL certificate attributes.

This issue occurs when all of the following conditions are met:

  • You are using the following X509 iRules commands to parse the subject and issuer attributes from the X509 certificate:
    • X509::issuer <X509 certificate>
    • X509::subject <X509 certificate>
  • Your iRule uses a command, such as HTTP::header, to pass the previously listed certificate attributes to the server.

Important: Depending on the iRules you have configured for your system, this change impact application functionality that is dependent on a format prior to that in BIG-IP 13.0.0  format. If your application expects the X509::subject output to be formatted as it is in versions prior to BIG-IP 13.0.0, make sure to modify your iRules after you upgrade.

Impact

The system may fail to pass properly formatted certificate information to the servers. 

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to pass properly formatted certificate information to the server.
  • You observe messages similar to the following example in the /var/log/ltm file, displaying incorrectly parsed attributes:

    tmm1[12345]: Rule /Common/test <HTTP_REQUEST>: BEFORE subject: serialNumber=1234567892020,CN=John Smith,SN=Smith,GN=John,OU=individuals,ST=Washington,C=US

    tmm1[12345]: Rule /Common/test <HTTP_REQUEST>: BEFORE issuer: CN=TRUST Root,2.5.4.97=#123456415453492D3137363539393123,O=Example,C=US

Workaround

None. The output of the X509::issuer and X509::subject commands are now Openssl X509-compatible and include a space between attributes.

For example:

C=US, O=COMPANY, OU=DEPT, OU=PKI, OU=CONTRACTOR, CN=USERNAME

Additionally, commas within attributes are now escaped using quotation marks rather than a backslash character.

For example:

C=US, O="COMPANY, INC," OU=DEPT, OU=PKI, OU=CONTRACTOR, CN=USERNAME

When writing iRules to validate the string, escape the quotation marks using a backslash character:

For example:

set dn_validation "C=US, O=\"COMPANY, INC,\" OU=DEPT"
