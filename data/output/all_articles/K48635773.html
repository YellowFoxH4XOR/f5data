Topic

The rate class feature is not supported when defined on a targeted virtual server in a VIP-targeting-VIP configuration.

Description

When an iRule or LTM policy assigned to a virtual server directs connections to another virtual server on the same BIG-IP system that also has a rate class configured, the rate limit does not function as expected. Depending on the configuration, resulting traffic may either be too fast or too slow. An example of this type of configuration using an iRule is similar to the following example:

This vs_rate_fastl4 virtual server has no rate limit set and uses an iRule named testrate to direct connections to the vs_viptarget virtual server:

ltm virtual vs_rate_fastl4 {
    destination 192.0.2.1:http
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        /Common/fastL4 { }
    }
    rules {
        /Common/testrate
    }
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

ltm rule testrate {
    when CLIENT_ACCEPTED {
        virtual vs_viptarget
    }
}

The rate class configured in the example vs_viptarget virtual server will not work when connections are directed to it by the vs_rate_fastl4 virtual server using the testrate iRule, however, the rate class will work as expected when a client connects directly to the vs_viptarget virtual server in this configuration.

ltm virtual vs_viptarget {
    destination 192.0.2.2:http
    ip_protocol tcp
    mask 255.255.255.255
    pool pool_router02
    profiles {
        tcp { }
    }
    rate-class limit_10Kbps
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

Recommendations

Use one of the following alternatives to configure rate limiting in place of using the rate class feature within the target virtual server configuration:

  • Configure the rate class within the VIP-targeting-VIP iRule using the iRules rateclass command. For more information about the iRules rateclass command, refer to the iRules rateclass page on CloudDocs.
  • Configure a bandwidth controller policy and apply it to the target virtual server configuration. For more information about bandwidth controllers, refer to the The Managing Traffic with Bandwidth Controllers chapter of the BIG-IP TMOS: Implementations guide.
