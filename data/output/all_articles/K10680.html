Known Issue

This is the result of a known issue. If Virtual Server Discovery is enabled for a BIG-IP LTM system that is being added to the configuration of a BIG-IP GTM system, and the BIG-IP LTM system features at least one IPv6 virtual server, the BIG-IP GTM system will fail validating the new configuration if it is not licensed for the IPv6 Gateway module. When this issue occurs, the BIG-IP GTM system logs a message to the /var/log/gtm file that appears similar to the following example:

ERROR, recvMCPreply: Got bad result: 01070636:3: IP V6 not licensed (GTM virtual server 2a00:d30:239:102::10).

If you experience this issue, you may find that the BIG-IP GTM Configuration utility stops displaying some or all virtual servers, including those that may have been previously discovered correctly. This behavior occurs because after the BIG-IP GTM system has discovered an IPv6 virtual server, the system fails to parse the configuration until a BIG-IP administrator manually fixes the configuration. You can verify the BIG-IP GTM configuration from the command line by running the following command:

gtmparse -l

This configuration should fail similar to the following example:

gtmparse: Initializing ...
/usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
/usr/local/gtm/include/base_region.ISP: SUCCESS
/config/gtm/wideip.conf: SUCCESS
gtmparse: SUCCESS
ERROR, recvMCPreply: Got bad result: 01070636:3: IP V6 not licensed (GTM virtual server 2a00:d30:239:102::10).

Note: This issue does not occur in BIG-IP GTM 10.0.x because the IPv6 Gateway module is automatically licensed on all BIG-IP products beginning in BIG-IP 10.0.0.

A BIG-IP GTM system that is not licensed for the IPv6 Gateway module should discover all virtual servers except IPv6 virtual servers, which should be ignored and not added to the wideip.conf file.

F5 Product Development is tracking this issue as CR130375.

Workaround

Before you add a BIG-IP LTM system that features IPv6 virtual servers to the configuration of your BIG-IP GTM system, ensure that Virtual Server Discovery is disabled for the BIG-IP LTM system. You will then have to manually create all required IPv4 virtual servers on the BIG-IP GTM system.

Note: For more information about adding virtual servers manually, refer to the Managing Virtual Servers section in the Configuration Guide for BIG-IP Global Traffic Management.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

If you do not want to perform this option, you can allow the BIG-IP GTM system to discover all virtual servers and then fail to validate the new configuration. Once this action has occurred, to restore your BIG-IP GTM configuration to a working state, you must perform the following procedures:

  • Disable Virtual Server Discovery for the BIG-IP LTM system that is advertising an IPv6 virtual server.
  • Remove the virtual server statement from the wideip.conf file.

Disable Virtual Server Discovery

  1. Log in to the BIG-IP GTM Configuration utility.
  2. Expand the Global Traffic section.
  3. Click Servers.
  4. Click the BIG-IP LTM server that is advertising an IPv6 virtual server.
  5. Click the Virtual Servers tab.
  6. Using the drop-down box, change Virtual Server Discovery to Disabled.
  7. Click Update.

Remove the virtual server statement from the wideip.conf file

  1. Log in to the BIG-IP GTM command line interface.
  2. Change directories to the /config/gtm/ directory by typing the following command:

    cd /config/gtm/

  3. Back up the current wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.backup

  4. Using a text editor, edit the /config/gtm/wideip.conf file.
  5. Scroll down the file until you find the server that advertised an IPv6 virtual server.
  6. Remove the IPv6 virtual server.

    Using the IPv6 virtual server as an example, you would delete the following lines:


    vs {
    name "ipv6-test-vip"
    address 2a00:d30:239:102::10.80 // http
    }

    Note: If more than one IPv6 virtual server is advertised to the BIG-IP GTM system, you must remove all of the IPv6 virtual servers.

  7. Save the wideip.conf file.
  8. Quit the text editor.
  9. Using the gtmparse -l command, reload the BIG-IP GTM configuration and verify that no errors are returned.

    For example:

    gtmparse: Initializing ...
    /usr/bin/monitors/builtins/gtm_base_monitors.conf: SUCCESS
    /usr/local/gtm/include/base_region.ISP: SUCCESS
    /config/gtm/wideip.conf: SUCCESS
    gtmparse: SUCCESS

    All IPv4 virtual servers now appear in the BIG-IP GTM Configuration utility.
