Known Issue

You cannot delete partitions other than the common partition. Errors occur even when you delete all associated objects.

This issue occurs when all of the following conditions are met:

  • You create a partition other than the common partition using the tmsh utility.
  • You created the partition using the update-partition command.
  • You have added a user-defined route domain to the affected partition.

When you create a user-defined partition from the tmsh utility with the update-partition option, and you apply a user-defined route domain to the partition, the system creates hidden VLAN members on the partition. These hidden VLANs prevent the partition from being deleted because the BIG-IP system views active objects within the partition.

Impact

You are unable to delete the affected partitions.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When attempting to delete the partition, you receive an error message that appears similar to the following example:

    All objects must be removed from a partition (partition_name) before the partition may be removed, type ID (456) when attempting to delete the partition

  • You cannot delete the affected partitions

Workaround

To work around this issue, you can manually remove the partition from the command line. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system is unresponsive while it loads the new configuration. F5 recommends that you perform this procedure during a maintenance window, if possible.

  1. SSH to the BIG-IP system as root.
  2. Stop the mcpd process by typing the following command:

    bigstart stop mcpd

  3. Find any references to the partition you want to delete in the grep <partition_name> /config files.

    Note: Replace <partition_name> with the name of your partition.

  4. Remove all references to the partition from the configuration files.
  5. Remove the existing mcpd database by typing the following command:

    rm -f /var/db/mcpd*

  6. Restart the mcpd process by typing the following command:

    bigstart restart mcpd

    Note: The BIG-IP system becomes unresponsive while it loads the new configuration
