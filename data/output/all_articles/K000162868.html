K000162868: vCMP guest shows an incorrect hostname after rebooting the Host

Applies to

Source

Description

After rebooting a vCMP Host, the following symptoms are observed  for some of the guests:

 

  • Guest Prompt status from the Host shows offline instead of Standby
  • Unable to ping the guest or connect to it via GUI or SSH 
  • vConsole attempt to the guest lands on a different guest 

 

Environment

Multi blades VIPRION system

vCMP guests distributed across chassis blades.

vCMP Host reboot

 

 

Cause

ID2293577

 

 

Answer/Recommended Actions

  1. Confirm the affected guest’s process ID while it is deployed:
    tmsh show vcmp guest all-properties | grep -i -e deployed -e ID

  2. Move the affected guest from the deployed state to the configured state:
    tmsh modify vcmp guest <guest_name> state configured

  3. Verify that the previous guest process ID has terminated on all chassis blades:
    clsh 'ps aux | grep <previous_process_id>'

  4. Redeploy the guest:
    tmsh modify vcmp guest <guest_name> state deployed

  5. Confirm that a new process ID has been assigned and the guest is now working correctly.
    tmsh show vcmp guest all-properties | grep -i -e deployed -e ID
