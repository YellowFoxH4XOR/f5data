Description

When virtual server is configured with Destination/Source address persistence in Fallback persistence, uneven load balance among pool member maybe observed. You may see all connections going to a single pool member.
 

Environment

  • BIG-IP all versions
  • Virtual server
  • Destination/Source address persistence for fall back persistence.
     

Cause

  • Destination/Source persistence in fallback persistence.

    Recommended Actions

    1. In the GUI, remove fall-back persistence from the virtual server.
       
    2. Log in to CLI and check what table entry in the command:
      tmsh

      NOTE: if the virtual is in the partition, then also run
      cd <partition name where the virtual server locate>

      then run
      show ltm persistence persist-records <virtual server name>

    • Delete persistence record.
      To delete specific entries from a specific virtuals server for a specific client IP address you can run:
      delete ltm persistence persist-records virtual <virtual server name> client-addr <client IP address>

      Or entire persistence record for virtual server
      delete ltm persistence persist-records virtual <virtual server name>
       

      • Additional Information

      The below example shows the logic behind this scenario.

      1. When virtual server 172.16.0.1 is created, there is no persistence record (in this case main persistence is Source address persistence)
        Persistence record for this virtual server is like
          Source address persistence
      Client IPVirtual server IP:portPool member IPTimeout
      ----
        Destination address persistence
        Virtual server IP:portPool member IPTimeout
        ---
            
        • Client 10.0.0.1 connected to the virtual server 172.16.0.1. There is no persistence record so Pool make load balance decision to pool member 192.168.0.1. Now persistence record table has similar to below data:
            Source address persistence
          Client IPVirtual server IP:portPool member IPTimeout
          10.0.0.1172.16.0.1:443192.168.0.1180
            Destination address persistence
            Virtual server IP:portPool member IPTimeout
            172.16.0.1:443192.168.0.1180
              
            • Client 10.0.0.2 connected to the virtual server 172.16.0.1. There is no persistence record for main persistence, but there is one in fallback persistence, Destination address persistence, so destination address persistence record is used for choosing pool member:
                Destination address persistence
              Virtual server IP:portPool member IPTimeout
              172.16.0.1:443192.168.0.1170
                
              • Now the persistence table for this virtual server is updated:
                  Source address persistence
                Client IPVirtual server IP:portPool member IPTimeout
                10.0.0.1172.16.0.1:443192.168.0.1170
                10.0.0.2172.16.0.1:443192.168.0.1180
                  Destination address persistence
                  Virtual server IP:portPool member IPTimeout
                  172.16.0.1:443192.168.0.1180 (renewed)
                    
                  • All new connections within the destination address persistence record will be connected to pool member 192.168.0.1 and the timeout values for the destination address persistence records will be renewed.
