Description

After upgrading BIG-IP LTM, the system may fail to load its configuration and remains offline. The following error message is displayed:

 

1070712:3: Failed: name (/Common/<policy_VPE_name>) Cache path (/config/filestore/files_d/Common_d/customization_group_d/:Common:policy_name_vpe_test_86108_1) does not exist and there is no copy in trash-bin to restore from.

or you get error message as 

 

010713cf:3: Validation error for customization-group (/Common/<policy_vpe_name>). Failed to parse (/config/filestore/files_d/Common_d/customization_group_d/:Common:policy_name_vpe_test_86108_1) because XML parser had fatal error parsing file. Error: invalid document structure at line:

Unexpected Error: Validating configuration process failed.

This results in all services being impacted and the device remaining in an offline state.

 

Environment

  • APM
  • Configuration includes APM customization groups or web app customizations

 

Cause

The issue occurs when APM customization cache files referenced in the configuration are missing from the filestore directory after an upgrade. The configuration load process fails because it cannot locate these required XML files, and there is no backup copy available in the trash-bin directory.

 

Recommended Actions

  1.  Identify Missing Files:

 Review the error message(s) to determine which APM customization files are missing from /config/filestore/files_d/Common_d/customization_group_d/.

    2. get the config details from bigip.conf file 

#grep -i  "<policy_VPE_name>" -A 5 /config/bigip.conf

    3.  Restore or Recreate Files: 

 

  • If a backup (UCS or filestore copy) exists, restore the missing XML files to their appropriate directory.

If no backup is available, manually create empty XML files with the required names as placeholders. For example

 

    cat > "/config/filestore/files_d/Common_d/customization_group_d/:Common:policy_name_vpe_test_86108_1" << 'EOF'

    <customization_group name="Common/<policy_VPE_name>" type="<get_this_from_bigip.conf file>">

    </customization_group>

     EOF

 

  • Repeat this step for each missing file indicated by error messages.

  4. After restoring or creating all missing files, reload the configuration:

# tmsh load sys config

  5. Confirm that the device transitions to an online state and that all services are restored.
