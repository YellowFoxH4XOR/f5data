Topic

BIG-IP APM and Edge Gateway devices have a security feature that performs a packet level inspection on all traffic passed in a network access tunnel on port 80 traffic. The inspection validates whether the passed traffic is legitimate HTTP traffic. The BIG-IP system will drop packets that do not pass the inspection. Therefore, applications that want to send non-HTTP traffic through the network access tunnel will need to use a port other than port 80.

F5 Product Development tracked a request for enhancement as ID 222063 (formerly 111406) that will allow the administrators of a BIG-IP APM or Edge Gateway to override this security inspection and allow non-HTTP traffic to pass successfully through a network access tunnel.

Note: This feature has been supported since 11.3.0.

Workaround

As a temporary workaround, you can configure an IP forwarding virtual server to pass the non-HTTP traffic on port 80. For example, the following IP forwarding virtual server has a target subnet of 10.0.0.0/8:

virtual port80-without-http {
translate service disable
srcport change
ip forward
snat automap
destination 10.0.0.0:http
mask 255.0.0.0
ip protocol tcp
profiles fastL4 {}
}

Note: For more information about configuring an IP forwarding virtual server, refer to K7595: Overview of IP forwarding virtual servers.
