K7349: The HTTP parser stalls on the HTTP CONNECT method

Published

Applies to

Known Issue

This is the result of a known issue. Proxy servers use the HTTP CONNECT method to establish a proxy tunnel through HTTP. In many cases, this method enables SSL connections to be established through an HTTP proxy.

The BIG-IP LTM HTTP parser is enabled when the HTTP profile is associated with a virtual server. The parser stalls when it receives an HTTP 200 response sent by the server in reply to an HTTP CONNECT method request. This behavior prevents the HTTP parser from switching into pass-through mode to allow a tunnel to be established.

F5 Networks Product Development is tracking this issue as CR77233 and it was fixed in BIG-IP LTM version 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, configure the following iRule to disable the BIG-IP HTTP parser after the client detects an HTTP CONNECT request. To do so, perform the following procedure:

  1. Log in to the BIG-IP LTM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.

  6. Enter the following iRule syntax in the Definition field:

    when HTTP_REQUEST {
    if { [HTTP::method] equals "CONNECT" }{
       HTTP::disable }
    }


  7. Click Finished.
