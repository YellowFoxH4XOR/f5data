Known Issue

You can delete a pool from your BIG-IP system, even when a BIG-IP LTM policy item references it as a clone pool.

This issue occurs when all of the following conditions are met:

  • You have a system with BIG-IP LTM policies configured on it.
  • Your system is running a BIG-IP LTM policy in which a policy item forwards to the deleted pool as a clone pool.
  • No other objects reference the pool.
  • You delete the pool referenced.

Impact

Although you can delete the pool without experiencing a system error, the policy continues to references the pool, which no longer exists. As a result, configuration synchronization (ConfigSync) operations fail and the configuration does not load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system does not report an error when you delete a pool that a BIG-IP LTM policy references as a clone pool.
  • ConfigSync fails.
  • The BIG-IP configuration fails to load.

Workaround

To work around this issue, F5 recommends that you remove the referenced pool from BIG-IP LTM policies before deleting it from the system.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
