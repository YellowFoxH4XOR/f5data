Description

SOCKS profile does not immediately expire connections if client sends TCP reset before server connected.
Client side connection remains in connection table until TCP idle timeout.

Environment

SOCKS virtual server.

Client sends reset before server server is connected.

Cause

Bug ID1350921

Recommended Actions

Use iRule below until bug ID1350921 has been fixed.

when LB_FAILED {
TCP::idletime 1
}

Additional Information

Two scenarios where client TCP reset which does not result in the connection being terminated.

 

i) Client sends a TCP reset followed by TCP SYN.

BIGIP responds with TCP reset "[F5RST: TCP closed]". After server side SYN retransmit timeout sends [F5RST: TCP retransmit timeout] to the server and to the client "[F5RST(peer): TCP retransmit timeout]" as expected.

The connection does not get cleared, stays in the connection table until TCP idle timeout.

 

ii) Client sends a TCP reset only.

BIGIP ignores the TCP reset until server side TCP SYN retransmit timeout then it sends TCP reset "TCP retransmit timeout]" to the server as expected but to the client TCP reset [F5RST: TCP bad shutdown state.]

The connection does not get cleared, stays in the connection table until TCP idle timeout.
