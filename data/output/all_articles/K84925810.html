K84925810: Remove JMSAppender class from Log4j for EMS and SDC

Type
Support Solution
Published
2021-12-28
Updated
2023-02-21
Applies to
  • Traffix SDC: 5.X.X, 5.1.X, 5.0.X, 5.2.0, 5.2.X, 5.0.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K84925810

Description

SDC (Signaling Delivery Controller) and EMS (Element Management System) are using Log4j for its logging framework. Log4j allows logging requests to print to output destination, which is called an appender. JMS (Java Message Service) is one of Log4j appenders. JMSAppender publishes events to JMS and can perform JNDI requests that leading to possible vulnerability. SDC does not use JMSAppender and recommended to be removed to mitigate this flaw.

You may use the following steps to check if Log4j is included in JMSAppender before apply the recommended actions.

  • salt '*' cmd.run 'cd /; find . -name "*log4*" | grep .jar'
If the log4j jar version is 1.2.x please proceed the following.

Environment

  • Traffix SDC 5.1 -CF0 and above
  • Traffix SDC 5.2 -CF0 and above

Cause

A trusted or an untrusted user who has write access to the Log4j configuration may add JMSAppender that performs JNDI lookup to JMS broker.

Recommended Actions

Apply the following on all SDC and EMS nodes.

  1. Install zip package
salt '*' cmd.run 'yum -y install zip'
Note: Replace the "sdc<version>" and "<apache-tomcat-version>" in "/opt/traffix/" path as per the running SDC version and apache-tomcat version respectively.
  1. Remove JMSAppender from "lib" path 
salt '*' cmd.run 'jar tvf /opt/traffix/sdc<version>/lib/log4j-1.2.17.jar | grep JMSAppender | wc -l'
salt '*' cmd.run 'zip -q -d  /opt/traffix/sdc<version>/lib/log4j-1.2.17.jar org/apache/log4j/net/JMSAppender.class'
salt '*' cmd.run 'jar tvf /opt/traffix/sdc<version>/lib/log4j-1.2.17.jar | grep JMSAppender | wc -l'
  1. Remove JMSAppender from "utils" path
salt '*' cmd.run 'jar tvf /opt/traffix/sdc<version>/utils/slrfClient/lib/log4j-1.2.16.jar | grep JMSAppender | wc -l'
salt '*' cmd.run 'zip -q -d  /opt/traffix/sdc<version>/utils/slrfClient/lib/log4j-1.2.16.jar org/apache/log4j/net/JMSAppender.class'
salt '*' cmd.run 'jar tvf /opt/traffix/sdc<version>/utils/slrfClient/lib/log4j-1.2.16.jar | grep JMSAppender | wc -l'
 
  1. Remove JMSAppender from "webui" path
salt '*' cmd.run 'jar tvf /opt/traffix/<apache-tomcat-version>/webapps/webui/MgmtConsole/WEB-INF/lib/log4j-1.2.17.jar  | grep JMSAppender | wc -l'
salt '*' cmd.run 'zip -q -d  /opt/traffix/<apache-tomcat-version>/webapps/webui/MgmtConsole/WEB-INF/lib/log4j-1.2.17.jar org/apache/log4j/net/JMSAppender.class'
salt '*' cmd.run 'jar tvf /opt/traffix/<apache-tomcat-version>/webapps/webui/MgmtConsole/WEB-INF/lib/log4j-1.2.17.jar | grep JMSAppender | wc -l'
  1. Remove JMS config
salt '*' cmd.run 'ls /opt/traffix/sdc<version>/config/defaultJmsLBConfiguration.xml | wc -l'
salt '*' cmd.run 'rm -f /opt/traffix/sdc<version>/config/defaultJmsLBConfiguration.xml'
salt '*' cmd.run 'ls /opt/traffix/sdc<version>/config/defaultJmsLBConfiguration.xml | wc -l'
  1. Stop all the SDC services and reboot nodes one by one

Stop all services

  • monit stop all
Wait until all the service stop 
  • monit summary
Reboot the node
 
  1. Once node rebooted start all the service
  • monit start all
  • monit summary
  1. Make sure the SDC services (check port 3868 & 1812 where the FEP is active)
salt '*' cmd.run 'monit summary'
salt '*' cmd.run 'netstat -nap | grep 3868'
salt '*' cmd.run 'netstat -nap | grep 1812'
