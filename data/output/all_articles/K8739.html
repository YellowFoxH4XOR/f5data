Known Issue

This is the result of a known issue. Specifying data port 0 (zero) in the FTP profile does not open all ephemeral ports on all VLANs for FTP data.

Specifying 0 for the FTP data port allows the support of all ports. When the FTP data port is configured to use all ports, the ephemeral listener should listen on all VLANs, unless the VLAN-Keyed option is enabled. This option ensures communication by allowing the BIG-IP system to accept and correctly map the active FTP data connection across VLANs.

Due to the current behavior, the BIG-IP system does not open the ephemeral ports on the VLANs. As a result, communication does not work properly.

F5 Product Development tracked this issue as CR99298 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF3, issued for BIG-IP version 9.3.1, and in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP version 9.4.5. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue, you can configure the specific control and data ports for FTP use.

Note: For more information, refer to K6831: Configuring FTP Profile to work with an alternate FTP Control and Data port.
