K000138400: Frequent audit logs in BIG-IQ CM when device is in HA

Type
Support Solution
Published
2024-01-30
Updated
2024-01-30
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X, 8.3.X, 8.3.0, 8.2.X, 8.2.0, 8.1.X, 8.1.0, 8.0.X, 8.0.0
Source
https://my.f5.com/manage/s/article/K000138400

Description

When BIG-IQ devices are configured to work in High Availability, System administrator may be confused by number of audit logs generated in both devices of system.


Example of logs:


Primary unit /var/log/audit:


AUDIT - pid=6061 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=save sys config user-only file ha-sync-users.scf no-passphrase


AUDIT - pid=26385 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=delete sys config file ha-sync-users.scf


Secondary unit /var/log/audit:


AUDIT - client tmsh, tmsh-pid-12574, user root - transaction #140506685-7 - object 0 - obj_delete { user_role_partition { user_role_partition_user "admin" } } [Status=Command OK]




Environment

  • BIG-IQ CM 8.x HA pair
  • Audit Logs

Cause

ha-sync task triggers ha_sync_files script which is working to synchronize data between both CM nodes in the cluster


Recommended Actions

Perform one of following actions:

  • Ignore logs mentioned in the description
  • Change interval to make it less intensive

NOTE: Do not set interval too high to avoid being out of sync for long. There is no way to tune each of the different files that kept in sync, so modifying for one affects all of them. The files that are copied are outside of the database replication, so the DB replication remains the same.


  • Filter logs according to K000138366 : Filtering unwanted /var/log/audit log 


Additional Information

Interval can be changed in the UI under System -> Big-IQ HA -> Big-IQ HA Settings. 


You can check actions performed by ha_sync_files script by reviewing file /usr/bin/ha_sync_files
