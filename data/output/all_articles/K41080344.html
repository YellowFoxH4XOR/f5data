K41080344: Portal access with Multidomain SSO may fail to encode the redirect

Type
Known Issue
Published
2017-09-23
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.0.0, 12.1.2, 12.1.1
Source
https://my.f5.com/manage/s/article/K41080344

Known Issue

Portal access with Multidomain single sign-on (SSO) may fail to encode the redirect.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM access profile is configured with SSO Across Authentication Domains with the Domain Mode set to Multiple Domains.
  • The access policy of the access profile is configured with a portal access resource.
  • A user authenticates to the access profile and is redirected by the BIG-IP APM system to the portal access resource.

Impact

The access session to the portal access resource fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the BIG-IP APM redirect, you notice that the URI does not point back to the BIG-IP APM system.
  • When you access the resource specified by the BIG-IP APM redirect, the URI access fails.

Workaround

To work around this issue, you can craft an iRule and configure the affected virtual server with the iRule. To do so, perform the following procedure:

Impact of workaround:  F5 recommends that you perform the following procedure during a scheduled maintenance window. 

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name .
  5. In the Definition box, enter the following iRule syntax rewrite for the portal access redirect.

    when HTTP_REQUEST {
     if { [string tolower [HTTP::path]] contains "f5-w-" && ([HTTP::cookie value MRHSession] == "" || !([ACCESS::session exists -state_allow -sid [HTTP::cookie value MRHSession]])) } {
      set http_path [HTTP::path]
      log local0. "Found request for   [URI::path $http_path 1 2]"
      set end [string first "$" [URI::path $http_path 1 2]]
      set end [expr { $end - 1 }]
      set myf5 [string range [URI::path $http_path 1 2] 6  $end ]
      log local0.  "PATH $myf5"
      HTTP::path "/-w-f5${myf5}$$[URI::path $http_path 2][URI::basename $http_path]"
     }
      if { [string tolower [HTTP::path]] contains "-w-f5"  && ([ACCESS::session exists -state_allow -sid [HTTP::cookie value MRHSession]]) }{
      set http_path [HTTP::path]
      log local0. "Found request for   [URI::path $http_path 1 2]"
      set end [string first "$" [URI::path $http_path 1 2]]
      set end [expr { $end - 1 }]
      set myf5 [string range [URI::path $http_path 1 2] 6  $end ]
      log local0.  "PATH $myf5"
      HTTP::redirect  "/f5-w-${myf5}$$[URI::path $http_path 2][URI::basename $http_path]"
      }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the Name link of the affected virtual server.
  9. Click the virtual server's Resources tab.
  10. In the iRules section, click Manage.
  11. Select your newly created iRule and move it to the Enabled box.
  12. Click Finished.
