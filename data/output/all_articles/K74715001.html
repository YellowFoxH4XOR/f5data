Description

VMWare Desktop connections fail to launch.
VMWare Desktop connections fail with SSL Handshake errors.
 

Environment

  • VMWare Horizon View iApp deployment
  • External NAT IP for connections to the APM virtual server

Cause

When deploying VMWare Horizon View with APM if using a NAT IP Address the APM Access Policy must be configured with the variable assign for the NAT Address. If this NAT variable assign is configured for an IP Address instead of the FQDN connections to the VMWare Desktops with fail with SSL Handshake errors. The NAT variable assign should be configured for the FQDN of the NAT IP Addr

Recommended Actions

When experiencing VMWare Desktop connection issues related to NAT, you can use the following steps to correct the issue:

Reconfigure the f5.vmware_view iApp.
  1. Log in to the Configuration utility
  2. Navigate to iApps > Application Services > Applications
  3. Click on the name of your VMware View deployment
  4. Select the Reconfigure tab
  5. Locate the question "If external clients use a network translated address to access View, what is the public-facing IP address?" under the BIG-IP Access Policy Manager section
  6. Enter the FQDN of your NAT IP Address
  7. Click Finished

Manually change the NAT variable assign.

The following procedure can be used to manually change the NAT variable assign configuration in an iApp deployment.
  1. Log in to the Configuration Utility
  2. Navigate to iApps > Application Services > Applications
  3. Click on the name of your VMware View deployment
  4. Select the Properties tab
  5. Select Advanced in the Application Service drop-down menu
  6. Disable Strict Updates
  7. Navigate to Access Policy > Access Policies > Access Policy List
  8. Click Edit under the Access Policy column
  9. In the Virtual Policy Editor click on the NAT Variable Assign
  10. Click the change link and change the session variable "view.proxy_addr" to the FQDN of the NAT IP Address
  11. Click Finished
  12. Click Save
  13. Click Apply Access Policy
