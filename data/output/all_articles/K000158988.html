K000158988: [SSLo] - Authentication of users not working via iRules after upgrade

Support Solution
Published
2026-01-02

Source

Description

After upgrading BIG-IP SSL Orchestrator from version 15.x to 17.1.3, authentication via iRules may fail, resulting in downstream proxy devices rejecting connections due to missing authentication headers. The iRule code responsible for inserting HTTP headers (such as X-Authenticated-User and X-Authenticated-Group) may be altered or incomplete after the upgrade, causing authentication failures and access denial errors from the proxy.

Environment

  • BIG-IP SSL Orchestrator
  • Software Version: Upgraded from 15.x to 17.1.3
  • Service chain includes downstream HTTP proxy
  • Custom iRules attached to SSL Orchestrator services for authentication header insertion
  • BIG-IP APM provisioned and used for user authentication

Cause

Unexpected modification or loss of iRule logic during the upgrade process to BIG-IP 17.1.3. The iRule responsible for inserting authentication headers may be altered, resulting in missing or incomplete headers and breaking authentication with downstream proxies.

Recommended Actions

  • Compare the iRule code before and after the upgrade to identify any discrepancies or missing logic.
  • Restore or correct the iRule to ensure all required headers (e.g., X-Authenticated-User and X-Authenticated-Group) are inserted in HTTP requests.

- Example working iRule logic:

when HTTP_REQUEST {

  if { [ACCESS::session exists] } {

    set sessionID [ACCESS::session sid]

    set user [ACCESS::session data get "session.logon.last.username"]

    HTTP::header insert "X-Authenticated-User" $user

    set memberof [ACCESS::session data get "session.ad.last.attr.memberOf"]

    HTTP::header insert "X-Authenticated-Group" $memberof

  }

}

  • After upgrade, verify the integrity of custom iRules attached to SSL Orchestrator services.
  • Test authentication flows to confirm that all required headers are present and accepted by downstream proxies.
  • Document and preserve custom iRule logic prior to performing upgrades to prevent loss or alteration.

Additional Information

  • Authentication offload in SSL Orchestrator relies on BIG-IP APM to perform user authentication and iRules to pass identity information to downstream proxies via HTTP headers.
  • Loss or alteration of iRule logic during upgrade can result in authentication failures.
  • Best practice is to export and review all custom iRules before and after upgrade, and to maintain version-controlled backups of configuration.
