Known Issue

The iSession subsystem may leak memory when configured on the BIG-IP APM system.

This issue occurs when one of the following conditions is met:

  • The BIG-IP APM system is configured for Network Access with Optimized Applications.
  • The BIG-IP APM system is configured with Application Access App Tunnels.

Impact

Memory utilization on the BIG-IP APM system steadily increases and can eventually consume all available memory.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H500934 on the Diagnostics > Identified > Medium|High screen.
  • The amount of memory allocated for and used by the iSession subsystem will increase over time.

    To inspect the memory usage for the iSession subsystem, you can use the following Traffic Management Shell (tmsh) command:

    # tmsh show /sys memory | egrep 'Max\ Alloc|^isession\ '

    The output of the command appears similar to the following example:

    SubSystem Alloc (bytes) Max Alloc (bytes) Object Size
    isession 5.3G 5.3G 1

    Repeating the command will show an increase over time.

  • The BIG-IP APM system may fail over to the standby system if the system is configured as a high-availability pair.
  • The BIG-IP APM system may generate a Traffic Management Microkernel (TMM) core file to the /shared/core directory.
  • Prior to the TMM process becoming unresponsive, the sweeper may start terminating connections for network access users and report error messages similar to the following example:

    warning tmm2[11028]: 011e0003:4: Aggressive mode sweeper: 29 Connections killed
