Known Issue

This is the result of a known issue. The following disk monitoring variables are missing from the bigdb database:

  • platform.diskmonitor.freelast.dev_shm
  • platform.diskmonitor.time.dev_shm

The missing variables do not affect how the BIG-IP LTM handles traffic; they are used internally by the system for monitoring the hard drive.

F5 Product Development tracked this issue as CR79328 and it was fixed in BIG-IP LTM versions 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

The missing disk monitoring variables may cause the reporting of error messages and use disk space if email alerts are configured. The diskmonitor will report error messages each time it is run; the information will be mailed to the local root account.

To prevent this behavior from occurring, manually add the missing variables to the bigdb database by performing the following procedure:

  1. Change directories to the /var/tmp directory by typing the following command:

    cd /var/tmp
  2. Create a file to hold the information to be added to the bigdb database by typing the following command:

    touch My.dat
  3. Use an editor to copy the following information into the My.dat file:

    [platform.diskmonitor.freelast.dev_shm]
    display_name=Platform.DiskMonitor.FreeLast.dev_shm
    default=0
    realm=local
    type=integer
    value=99
    [platform.diskmonitor.time.dev_shm]
    display_name=Platform.DiskMonitor.Time.dev_shm
    default=0
    realm=local
    type=integer
    value=1171855860
  4. Save the changes to the My.dat file.
  5. Load the DB variables into the system by typing the loaddb command:

    /usr/bin/loaddb -local My.dat
  6. Save the changes loaded into the system to BigDB.dat file by typing the following command:

    bigpipe save
