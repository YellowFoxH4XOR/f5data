Known Issue

This is the result of a known issue. Loading a large configuration at startup may result in heartbeat failure and promotion of a new primary blade.

Note: This issue affects only the VIPRION platform.

If a blade is rebooted on a VIPRION system that contains a sufficiently large configuration, the clusterd process may generate a false heartbeat failure on startup. When this occurs, the clusterd process on the affected blade behaves as though it is the only blade available in the cluster, and incorrectly promotes itself as the primary of the cluster. This results in conflicts with the actual primary blade in the cluster and the transfer of the primary status to another blade.

F5 Product Development tracked this issue as CR126117 and it was fixed in BIG-IP LTM 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
