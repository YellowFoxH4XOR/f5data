Description

I would like to know about the impact of restarting named on all members of the BIG-IP DNS sync group cluster. Will this create a DNS outage? Will temporarily stopping or restarting named even on one instance will create an outage, since the DNS listener will supply incorrect information?

Environment

  • BIG-IP DNS sync group

  • named process

Cause

None

Recommended Actions

Restarting the named service may adversely affect the BIG-IP DNS system's ability to respond to DNS queries, especially if you are using configurations such as the following:

  • Your BIG-IP systems use some DNS records that are not managed by a wide IP. For example, you used ZoneRunner or a manual process to configure DNS zone files.
  • Your system has a listener object that is configured to use the local BIND service. For example, a virtual server with a DNS profile is configured with the Use BIND Server on BIG-IP option.
  • You have a GSLB pool that uses the Return to DNS load balancing method, or its Alternate and Fallback load balancing methods are set to None, and all pools associated with the wide IP are unavailable.
  • The local BIND configuration is enabled with the non-default recursion yes; option.

In these cases, F5 recommends scheduling a maintenance window prior to stopping or restarting the named service.

Additional Information

The extent to which restarting the named service affects DNS queries depends on your configuration and deployment. For BIG-IP DNS systems a DNS query may never reach the local bind instance if a GSLB configuration object in the resolution hierarchy, such as a wide IP, is able to provide an appropriate answer. For example, if you are mostly using the BIG-IP GSLB functionality to process DNS queries, then the impact of restarting named will be limited as your wide IPs will continue to respond even when named is restarted.
