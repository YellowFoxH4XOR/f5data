Known Issue

The ARX Secure Agent (ASA) may fail to authenticate using NTLMv2 for a username that includes multibyte Unicode UTF-8 characters.

This issue occurs when all of the following conditions are met:

  • The client is attempting to connect to a share from the command line.
  • The authentication protocol is NTLMv2.
  • The username includes multibyte Unicode UTF-8 characters.

When a multibyte username tries to connect to a share from the command line using the net use command, authentication fails when using NTLMv2, even though the same username and password can connect when using Windows Explorer.

Impact

The client is unable to access a share from the command line.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A client is able to connect to a share when using Windows Explorer. However, the net use command fails when using the same username and password, as in the following syntax:

    net use [driveletter:]  \\arxvip1.domain.com\share1 /user:<domain>\<multibyte username> <password>

    For example:

    net use * \\arxvip1.domain.com\share1 /user:DOMAIN\????? password

  • The procdat log file contains an error message that appears similar to the following example:

    :VCIFS-1-INFO-CLIENTAUTHFAIL:: Client authentication failure for service arxvip1.domain.com: user DOMAIN\ from
    10.10.12.34. Reason: client authentication failure.

    Note: The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.

Resolution

Status

F5 Product Development has assigned ID 363263 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of Fix
Versions Fixed
Related Solutions
ReleaseNoneNone
HotfixARX Secure Agent version 5.1.7 Hotfix 4 (build-12064)*None

*Customers affected by this issue should request ARX Secure Agent version 5.1.7 Hotfix 4 (build-12064) from F5 Technical Support. The ARX Secure Agent version 5.1.7 Hotfix 4 software is compatible with ARX systems running versions 5.1.x, 5.2.x, and 6.0.x.

Important: This issue is not fixed by upgrading the ARX software. You must upgrade the ARX Secure Agent software on the Domain Controller.

Workaround

To work around this issue you can configure the ARX CIFS service and domain controller for constrained delegation. When you use constrained delegation, the ARX Secure Agent is no longer required.

Impact of workaround: None. F5 strongly recommends that you use constrained delegation.
