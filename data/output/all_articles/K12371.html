Known Issue

This is the result of a known issue. A virtual server may fail to terminate a connection flow when the client sends pipelined requests followed by a TCP half-closed sequence. This issue may occur when all of the following conditions are met:

  • The virtual server references an HTTP profile that is configured with the Fallback Host setting, or an iRule that uses the HTTP::fallback command
  • The client sends pipelined requests followed by a TCP half-closed sequence to terminate its side of the connection
  • The server is unresponsive or aborts the connection

When these conditions are met, the presence of pipelined data causes the BIG-IP system to fail to remove the connection flow.

You may observe behavior similar to the following on a unit affected by this issue:

  • The memory performance graphs display a constant increase in the amount of memory utilized by TMM
  • A high number of zombie connections in which the idle connection time exceeds the profile connection limit. For example, the following bigpipe conn show all command output displays a connection that has been idle for 95,096 seconds although the TCP profile has an idle timeout of 700 seconds:

    VIRTUAL 10.10.10.1:https <-> NODE any6 TYPE any 1/0
    CLIENTSIDE 192.168.1.1:64925 <-> 10.10.10.1:https
    (pkts,bits) in = (50, 2813) out = (42, 2048)
    SERVERSIDE any6 <-> any6
    (pkts,bits) in = (0, 0) out = (0, 0)
    PROTOCOL tcp UNIT 1 IDLE 95096 (700) LASTHOP external 00:12:12:12:12:e2

  • The TMM process cores and restarts

F5 Product Development tracked this issue as ID 227368 (formerly CR99057) and it was fixed in BIG-IP 10.2.3 and 11.3.0 For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

This issue has been fixed in Hotfix-BIGIP-10.2.2-911.0-HF2 issued for BIG-IP 10.2.2. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
