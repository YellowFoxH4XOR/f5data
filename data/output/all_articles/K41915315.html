Description

Server-side connection does not use the expected SNAT IP when connecting via HTTPS to a Virtual Server configured for HTTP Explicit Proxy.

Environment

  • SNAT
  • HTTP profile configured in Explicit proxy mode

Cause

When using HTTP Explicit proxy mode, HTTPS connections require a virtual server to be listening on the tunnel for the requested outbound connection. This virtual server processes the traffic before it leaves the system. This is the default behavior.

If the virtual server configured as the outbound listener has a SNAT configuration, then this SNAT takes effect after any SNAT configuration in place on the Virtual Server receiving the client's proxy requests.

Recommended Actions

Control the SNAT behavior on the outbound listener virtual server.

Alternatively, consider setting the Default Connect Handling setting of the associated HTTP profile to Allow. With a setting of Allow, an outbound listener Virtual Server is not required for HTTPS connections.

Important: If there is an outbound listener virtual server configured that matches the destination IP, the system will still attempt to use this virtual server, even if Default Connect Handling is set to Allow, or the virtual server is disabled.

Additional Information

A typical HTTP Explicit proxy connection flow works in this way when processing a HTTPS connection:

Note: This is a high level overview and may not be indicative of every HTTP Explicit proxy configuration.

  1. Client establishes a TCP connection with Explicit proxy Virtual Server
  2. Clients sends a HTTP CONNECT request to establish a tunnel
  3. BIG-IP performs DNS resolution for the FQDN specified in the HTTP request
  4. BIG-IP establishes a TCP connection to the outbound listener virtual server
  5. BIG-IP establishes a TCP connection to the destination system via the outbound listener virtual server

    Note: SNAT will be performed at this stage if the listener virtual server has SNAT configured

  6. BIG-IP returns a 200 Connected response to the client
  7. BIG-IP performs a TLS handshake with the destination
  8. BIG-IP sends the HTTP request
  9. When the BIG-IP receives the HTTP response, it is returned to the client via the Explicit proxy Virtual Server

Note: HTTP connections do not require an outbound listener virtual server to be configured and the connection flow differs because of this.

If any of these steps fail, the BIG-IP typically returns a HTTP 503 Service Unavailable response to the client. When troubleshooting, it can be useful to look at the body of this response.
