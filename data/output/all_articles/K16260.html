Known Issue

BIG-IP systems that are configured with Virtual Local Area Network (VLAN) groups may leak memory.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a VLAN group.
  • The VLAN group includes only one VLAN member.

Note: A VLAN group is a logical container that includes two or more distinct VLANs. VLAN groups are intended for load balancing traffic in a Layer 2 (L2) network, when you want to minimize the reconfiguration of hosts on that network. For more information about BIG-IP VLAN groups, refer to the VLANs VLAN Groups and VXLAN chapter of the BIG-IP TMOS: Routing Administration guide.

Impact

System performance may degrade over time, and the system may eventually become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H511632 on the Diagnostics > Identified > Medium|High screen.
  • The Traffic Management Microkernel (TMM) memory utilization graph grows constantly.
  • The TMM restarts and generates a core file in the /shared/core directory.
  • The system logs error messages to the /var/log/ltm file, similar to the following example:

    011e0002:4: sweeper_update: aggressive mode deactivated
    011e0002:4: sweeper_update: aggressive mode activated

Workaround

To work around this issue, you can remove the affected VLAN group.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system; a VLAN group with only one VLAN member is not a valid VLAN group configuration.
