Description

You notice initial TCP retransmissions are happening after the specified time configured for syn-rto-base, instead of expected minimum-rto value, configured on the TCP profile.

You can see the values configured, when listing the profile settings with tmsh list /ltm profile tcp all-properties, notice the following values, similar to this example output:

ltm profile tcp /Common/Example_TCP_Profile {

    minimum-rto 600  -->>  Configured to 600 ms         

    syn-max-retrans 3

    syn-rto-base 200 -->> Configured to 200 ms

You can see the retransmissions happening after syn-rto-base value, 200 ms, on a wireshark capture similar to the following example:

02:51:30.667002000 PDT     10.0.0.1    192.168.1.1   10500   49500   OUT s1/tmm0 : 10500 → 49500 [PSH, ACK] Seq=1 Ack=643 Win=150 Len=174

02:51:30.867002000 PDT     10.0.0.1    192.168.1.1   10500   49500   OUT s1/tmm0 : [TCP Retransmission] 10500 → 49500 [PSH, ACK] Seq=1 Ack=643 Win=150 Len=174

Note: The timestamp on the retransmission of the segment is 200 ms later than the initial transmission, (667 and 867), matching the syn-rto-base value configured.

Environment

  • TCP profile
  • TCP re-transmissions

Cause

Bug ID 897437: First retransmission might happen after syn-rto-base instead of minimum-rto

Recommended Actions

To make the initial retransmissions for a segment, happen at the configured value for minimum-rto, change the syn-rto-base value, to match the minimum-rto on the TCP profile associated to the affected Virtual Server.

For example:

ltm profile tcp /Common/Example_TCP_Profile {

    minimum-rto 600  -->>  Configured to 600 ms         

    syn-max-retrans 3

    syn-rto-base 600 -->> Configured to 600 ms

Additional Information

For additional details on this issue refer to: K28358052: BIG-IP may send TCP retransmission after syn-rto-base instead of min-rto interval.
