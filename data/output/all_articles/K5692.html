K5692: The BIG-IP ASM active policy for an HTTP class is removed if the HTTP class is disabled

Known Issue

This is the result of a known issue. When Application Security is disabled on an HTTP class, the active policy for the web application referenced by the HTTP class is moved to the Policy Recycle Bin.

To restore the policy, perform the following procedure:

  1. From the main navigation pane, expand the Application Security section.
  2. Click Web Applications.
  3. Click on the Web Application name referenced by the HTTP class you would like to restore.
  4. Click Import.
  5. Select the policy you would like to restore from the Policy Recycle Bin section.
  6. Click Restore.
  7. Click Yes to initiate the restoration process.

A message will be displayed confirming the policy has been restored and reactivated.

F5 Product Development tracked this issue as CR57551 and CR56287 and it was fixed in BIG-IP ASM 9.2.3 and 9.4.0. For information about upgrading, refer to the BIG-IP ASM release notes.

F5 Product Development is tracking this issue as CR71227 for the BIG-IP ASM 9.3.0 software branch.

Workaround

To work around this issue, do not disable Application Security on an HTTP class.

To disable Application Security on a single virtual server, remove the HTTP class profile from the virtual server, by performing the following procedure:

  1. From the main navigation pane, expand the Local Traffic section.
  2. Click Virtual Servers.
  3. Click on the Virtual Server name from which you wish to remove the HTTP class profile.
  4. Click the Resources tab.
  5. Under HTTP Class Profiles, click Manage.
  6. Click on the Enabled profile to be removed, and then move the profile to the Available list by clicking >>.
  7. Click Finished.

To disable Application Security on all HTTP classes, refer to K5889: Disabling and enabling Application Security on all virtual servers.
