K000137603: Does F5 Support Encrypt-then-MAC TLS extension

Type
Support Solution
Published
2023-11-16
Updated
2023-12-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000137603

Description

TLS handshake failure with Alert (Level: Fatal, Description: Bad Record MAC) from F5 to the client.


Environment

  1. TLS connection from client to F5.
  2. Client using Encrypt-then-mac extension.
  3. proxy-ssl in play wherein both client and target server supports encrypt-then-mac.

Cause

F5 doesnt support Encrypt-then-mac TLS extension. Considering the industry moved to AEAD based ciphers, the encrypt-then-mac is no longer needed.


https://tools.ietf.org/html/rfc7366:


Note from the GenericBlockCipher annotation that this only applies to

standard block ciphers that have distinct encrypt and MAC operations.

It does not apply to GenericStreamCiphers or to GenericAEADCiphers

that already include integrity protection with the cipher. If a

server receives an encrypt-then-MAC request extension from a client

and then selects a stream or Authenticated Encryption with Associated

Data (AEAD) ciphersuite, it MUST NOT send an encrypt-then-MAC

response extension back to the client.



Recommended Actions

Do not use Encrypt-then-mac TLS extension, especially, with Proxy-SSL.
