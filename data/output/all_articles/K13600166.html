Description

During a BIG-IP software upgrade, installing a new software image in a new partition (both via webUI or TMSH) is failing with an error message similar to the one below:

 failed (Could not access configuration source; sda, 1 )

In /var/log/liveinstall.log, logs similar to the one below can be seen:

info: Updating system tm_install files from /shared/images/BIGIP-13.1.0.8-0.0.3.iso
...........................................................................
7645 blocks
info: Installer on image is newer, reexec
Can't exec "/var/tmp/install/pkgcpio/usr/sbin/image2disk": Permission denied at /usr/sbin/image2disk line 824.
info: Platform id is Z100
info: Basic disk format validation passed.
error: tm_install::VolumeSet::VolumeSet_prep_root -- symlink failed; /mnt/tm_install/951.PRQfhI/var/tmp to ../shared/tmp : File exists
Terminal error: Could not access configuration source; sda, 1
*** Live install end at 2019/05/06 17:19:57: failed (return code 255) ***

Environment

  • upgrading a BIG-IP device to a newer software version

Cause

This issue can occur when /var/tmp loses its symbolic link to the /shared/tmp directory.

Recommended Actions

Re-create the /var/tmp symbolic link:

  1. Log in to the command line of the BIG-IP system as the root user.

  2. Change directory to /var.

    # cd /var

  3. Remove the tmp folder from the /var directory.

    # rm -rf tmp

  4. Re-create the /var/tmp symbolic link using the below command:

    # ln -s ../shared/tmp tmp

  5. Change the SELinux security context of the symbolic file:

    # chcon -v -h --reference=/shared/tmp /var/tmp

Additional Information

The /var/tmp directory is used internally by BIG-IP daemons. If the /var/tmp symlink to /shared/tmp is lost, for some reason, some functionality may be rendered unusable until it is restored.
