Description

BIG-IP configuration loading or validation fails during module provisioning with the following error:

01071008:3: Provisioning failed with error 1 -'Disk limit exceeded. 20338 MB are required to provision these modules, but only 19720 MB are available.'
Unexpected Error: Validating configuration process failed.

Environment

  • BIG-IP LTM tenant
  • Tenant disk allocation: 77, 83 GB
  • Provisioned modules and features:
    • BIG-IP LTM
    • BIG-IP ASM
    • BIG-IP APM
    • AVR
  • Configuration validation performed with:
    tmsh load sys config verify
  • Required disk space: 20,338 MB

Cause

Insufficient tenant disk space prevents provisioning of the configured BIG-IP modules during configuration validation.

The disk space requirement for F5OS tenants may increase when you upgrade. For example, when upgrading from BIG-IP 15.x to BIG-IP 17.x, requirements increased from 77GB to 86GB. Systems with less than the required disk space fail during provisioning due to insufficient resources.

Answer/Recommended Actions

The following procedure lists the required high level steps to increase disk space on the BIG-IP tenant. For more information on the commands to run, refer to the Extending disk space for upgrading software, or installing point releases on an additional slot procedure in K000137433: Extending disk space for BIG-IP tenants running on F5 VELOS and rSeries.

  1. Determine the minimum disk size required for the tenant image you are upgrading to. To do so, refer to the appropriate image tenant type tables and the Identifying the virtual disk size from an image file procedure in K45191957: Overview of the BIG-IP tenant image types.
    For example, increase the allocation to at least 86 GB when upgrading to BIG-IP 17.x and 88GB when upgrading to BIG-IP 21.1.0.
  2. Login to bash as root to the BIG-IP tenant.
    1. Run configuration validation to determine whether the failure is caused by insufficient disk space:
      tmsh load sys config 
    2. Review the error output for the required and available disk-space values.
  3. Login as root to the F5OS system.
    1. Place the tenant into the appropriate Provisioned mode.
    2. Increase the tenant disk allocation to the size you determined in step 1. 
      Important: Increasing the disk size for a BIG-IP tenant is irreversible because F5 does not support disk shrinking.
    3. Place the tenant into the running state by setting it to Deployed.
    4. Restart or redeploy the tenant so that the updated disk allocation is applied.
  4. Return to bash on the BIG-IP tenant.
    1. Load the configuration again:
      tmsh load sys config
  5. Before future BIG-IP upgrades, verify that the tenant has sufficient disk capacity for all provisioned modules. For more information, refer to Verify sufficient disk capacity on BIG-IP tenant before upgrade.

Additional Information

  • The failure occurs during provisioning, before configuration validation can complete.
  • Required disk space depends on the combination of provisioned modules and features.
  • Configuration warnings related to deprecated compliance objects, duplicate log destinations, or regular-expression definitions may also appear during validation. These warnings are not the cause of the provisioning failure described here.
  • Increasing the tenant disk allocation by 1 GB resolves the provisioning failure in this configuration.

Verify sufficient disk capacity on BIG-IP tenant before upgrade

Before you upgrade, verify sufficient disk is allocated to the tenant to meet the minimum disk size required for the tenant image you are upgrading to. To do so, 

  • Determine the minimum disk size required for the tenant image type.
    • refer to the appropriate image tenant type tables and the Identifying the virtual disk size from an image file procedure in K45191957: Overview of the BIG-IP tenant image types. 
  • Determine the current disk allocated to the BIG-IP tenant
    • Login to the webUI of your F5OS system. 
    • Go to TENANT MANAGEMENT > Tenant Deployments.
    • Select the tenant
    • Verify the Virtual Disk Size.

If needed, increase the disk space first before the upgrade.

If possible, as appropriate your environment, you can also perform the following to surface any other potential issues in advance:

  • perform the upgrade in a test environment
  • perform the upgrade in a High Availability (HA) pair.
