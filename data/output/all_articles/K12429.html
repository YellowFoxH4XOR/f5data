Topic

All general-purpose DNS implementations must support both the User Datagram Protocol (UDP) and TCP transport protocols. However, F5 has determined that most customers who configure the BIG-IP system to load balance DNS traffic only create a UDP virtual server listening on port 53. It is a common misbelief that DNS only uses the TCP transport protocol for zone transfers.

Note: For more information, refer to Internet Engineering Task Force (RFC 5966).

The majority of DNS transactions take place over UDP; however, TCP can also be used for the same purpose. Specifically, a client will always reissue a DNS request over TCP if the response is too large to fit inside a UDP response.

Traditionally, the maximum size for a DNS message over UDP is 512 bytes. When a response is larger than this value, the server truncates the response and sends it to the client. Additionally, the server sets the Truncated flag to signal that the response may be unusable and should not be cached, and that additional measures are needed to resolve the request.

When a client receives a truncated response, normally it will initiate a TCP connection to the DNS server and resend the request over TCP, allowing for a larger response. If the BIG-IP system is not configured with a TCP virtual server listening on port 53, these reissued requests will fail, and the client will not be able to resolve the name.

Therefore, when load balancing DNS traffic, F5 recommends that you create two virtual servers listening on port 53, one for the UDP transport protocol and one for the TCP transport protocol.

For example:

pool dns_servers {
members
10.0.0.10:domain
10.0.0.11:domain
10.0.0.12:domain
10.0.0.13:domain
}
virtual dns_vs_udp {
pool dns_servers
destination 192.168.1.100:domain
ip protocol udp
}
virtual dns_vs_tcp {
pool dns_servers
destination 192.168.1.100:domain
ip protocol tcp
}

Note: Beginning in BIG-IP 10.2.0, you can also start load balancing DNS traffic by using the Generic DNS application template (in BIG-IP 11.0.0 and later, use the f5.dns iApp template). This template automatically creates a virtual server for each transport protocol, in line with the recommendation discussed in this article.

Note: A similar recommendation can also be made for BIG-IP GTM systems. While wide IP responses are almost always small enough to fit in a UDP response, some queries could fall through to BIND. Even more likely, you could use the BIG-IP GTM system as a recursive nameserver. In these instances, it is possible for the BIG-IP GTM system to encounter large DNS responses that require the TCP transport protocol. Therefore, F5 recommends that you configure both a UDP and TCP listener. For more information, refer to K14923: Configuring the BIG-IP GTM to answer TCP or UDP DNS requests (11.x - 14.x).
