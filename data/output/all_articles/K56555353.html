Description
The relationship between a BIG-IP and BIG-IQ are heavily interwoven. Because of this it can be critical to know whether this relationship exists.

Environment

  • BIG-IP
  • BIG-IQ
  • GUI (Web UI) Access
  • Command Line (CLI) Access

However, what if you do not have access to the Web UI, or are reviewing a qkview, or viewing the bigip.conf. How could you determine if the BIG-IP is being managed by a BIG-IQ?

Cause
None

Recommended Actions
You can determine if a BIG-IP is managed by a BIG-IQ using any of the following methods:

  • Using the Web UI to determine if a BIG-IP system is managed by a BIG-IQ
  • Using the CLI to determine if a BIG-IP system is managed by a BIG-IQ
  • Using a QKView to determine if a BIG-IP system is managed by a BIG-IQ

Using the Web UI to determine if a BIG-IP system is managed by a BIG-IQ

  • On the BIG-IP:
    1. Log in to the Web UI.
    2. If Managed by BIG-IQ appears in the top-left corner, the device is managed by a BIG-IQ.
       
  • On the BIG-IQ:
    1. Log in to the Web UI.
    2. Go to Devices > BIG-IP DEVICES.
    3. Ensure the list displays All BIG-IP Devices. The BIG-IP appears in the list of devices.

Using the CLI to determine if a BIG-IP system is managed by a BIG-IQ
Determine if a BIG-IP system is managed by BIG-IQ by using the iControl REST API

  1. SSH to log in to the Advanced Shell (bash) of the BIG-IP system.
  2. To determine if a BIG-IQ is managing the BIG-IP use the following syntax:

    restcurl -u <username>:<password> /mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices

    For example:

    restcurl -u admin:admin /mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices

    The output lists the BIG-IP device itself, as well as the BIG-IQ device that is managing it. The BIG-IQ details appear similar to the following:

Determine if a BIG-IP system is managed by BIG-IQ by reviewing the analytics global settings
In BIG-IP 13.1.0.5 and later, when a BIG-IP is discovered by a BIG-IQ, if statistics collection is enabled (regardless of whether BIG-IP Analytics is provisioned or not), there is a change to the default config of the BIG-IP analytics global-settings.  This configuration change can be seen in /config/bigip.conf. 

The analytics entry is the first entry in bigip.conf so it is easy to find.

  1. SSH to log in to the Advanced Shell (bash) of the BIG-IP system.
  2. Enter the following command:

    sed -n -e '/analytics global-settings/,/^}/ p' /config/bigip.conf

    Output  appears similar to the following:
    Note: This configuration object only appear if the BIG-IP system is managed by BIG-IQ.

    analytics global-settings {
        avrd-interval 30
        ecm-port 443
        enable-bigiq-configuration enabled
        offbox-protocol https
        offbox-tcp-addresses { <DCD> }
        offbox-tcp-port 443
        source-id <machine-ID>_<IP of BIG-IP>
        use-offbox enabled
    }
    • <DCD> is the IP of the BIG-IQ Data Collection Device (DCD) that the analytics data is sent to.
    • If there is no DCD it will be the IP of the BIG-IQ Centralized Manager (CM).
    • <machine-ID> is the machine ID of the BIG-IP
    • <IP of BIG-IP> is the IP Address of the BIG-IP
       
  3. Alternatively, you can also display the analytics global settings with the TMOS shell (tmsh) by entering the following command:

    tmsh list analytics global-settings all-properties

          Output  appears similar to the following:
          Note: This configuration object only appear if the BIG-IP system is managed by BIG-IQ.

          analytics global-settings {
                          avrd-interval 30
                          ecm-port 443
                          enable-bigiq-configuration enabled
                          offbox-protocol https
                          offbox-tcp-addresses { 10.10.10.10 }
                          offbox-tcp-port 443
                          source-id 1234-ab12-5678cd-9cf
                          use-offbox enabled
                          }

Using a QKView to determine if a BIG-IP is managed by a BIG-IQ
If you have uploaded a QKView to https://ihealth.f5.com then you can review the /config/bigip.conf file to determine if a BIG-IP is managed by a BIG-IQ

  1. Go to https://ihealth.f5.com.
  2. Open the link to the QKView in question.
  3. Go to Files > Config > bigip.conf.
  4. At the top, if the BIG-IP is managed by a BIG-IQ, the previous config object is present at the top of the bigip.conf file.

Note: When analytics has not been enabled, you can review the Files >> All section of a qkview for the /shared/em/ssl.crt/ directory (files present here indicate the box is managed by BIG-IQ system; however, these files remain on the BIG-IP even after it is no longer managed by a BIG-IQ).
