Topic

Slow login is most frequently due to name resolution configuration or hardware issues with the network configuration. Of the two possibilities, name resolution problems are considerably more common.

DNS Name Resolution

Each time a user logs into a BIG-IP or 3-DNS using SSH, the sshd daemon performs a reverse name lookup on the client's IP address. If name resolution is not working correctly, this may delay the login.

You can resolve this issue in one of the following ways:

  • Correct the configuration for the accessible DNS servers.
  • List the SSH clients in the hosts file.
  • Disable sshd reverse name lookups. (This option is available starting in version 4.5 PTF-08.)
  • Disable DNS lookups globally. (This option is available for versions prior to 4.5 PTF-08.)

Correct the configuration for the accessible DNS servers

You must configure the DNS server for name resolution or SSH reverse name lookup will not work. If a server is not configured, or if an incorrect server is specified, it can cause sshd to wait several seconds for the request to time out before continuing. For specific information about configuring name resolution, refer to K3624: Configuring DNS name resolution on a BIG-IP or 3-DNS Controller.

List the SSH clients in the hosts file

As an alternative to DNS name lookups, you can configure local lookups using the hosts file. This is the best alternative when you do not have access to a DNS server with client system information, and the number of clients is reasonable enough to enter manually. For specific instructions, refer to K3625: Configuring local host name resolution on a BIG-IP or 3-DNS Controller.

Disable sshd reverse name lookups

Starting in version 4.5 PTF-08, you can disable the sshd reverse name lookup. For specific instructions, refer to K3623: Disabling sshd reverse name lookups.

Disable DNS lookups globally

If you are using a version prior to version 4.5 PTF-08, you cannot disable sshd reverse name lookups. As an alternative, you can disable DNS name lookups. To do this, rename the /etc/resolv.conf file (in this example, to /etc/resolv.conf.OFF), by typing the following command:

mv /etc/resolv.conf /etc/resolv.conf.OFF

The controller will no longer attempt DNS lookups. You can retrieve this file later if you want to reinstate DNS lookups.

Hardware issues

A slow SSH login can also be caused by network cabling or network interface card errors. Common problems include:

  • Mismatched media speed.
  • Mismatched duplex settings.
  • Other hardware network issues resulting in packet loss and retransmission.

Mismatched media speed

In some cases, leaving an interface media speed setting to auto will result in an incorrect link speed selection. To correct this, you can manually configure the controller's copper interface to match the speed of the network to which you are connected.

Note: You cannot manually configure some fiber gigabit interfaces and some copper gigabit interfaces.

Mismatched duplex settings

Most switches are compatible with full or half duplex settings, but the settings must be the same at both ends of the link. Some switches do not auto-negotiate duplex settings. Most hubs require half duplex settings.

Both BIG-IP and the hub, or switch to which it is connected, must have the same setting. If they do not have the same setting, it will result in an latency or the inability to pass traffic. To correct this, you can manually configure the controller's copper interface to match the duplex setting of the switch or hub to which you are connected.

F5 Networks recommends that you manually configure the media speed and duplex settings for all interfaces that allow it. For instructions about how to change duplex settings, refer to the following Solutions:

For BIG-IP and 3-DNS versions 4.0 through 4.6.4, refer to K522: Configuring the media type and speed for network interfaces.

For BIG-IP and 3-DNS versions prior to 4.0, refer to K521: Configuring the media type and speed for network interfaces.

Note: You cannot manually configure some fiber gigabit interfaces and some copper gigabit interfaces.

Other hardware network issues

The SSH login process will slow if there is any packet loss or retransmission. To troubleshoot issues, you can view the errors for the interfaces on the hub or switch to which the BIG-IP is connected. For information about how to view these errors, refer to the following Solutions:

For BIG-IP and 3-DNS versions 4.0 through 4.6.4, refer to K3628: Viewing network interface statistics from the command line with the netstat command.

For BIG-IP and 3-DNS versions prior to 4.0, refer to K3627: Viewing network interface statistics from the command line with the netstat command.
