Description

  • Noticed heavy logs generated from f5:

    <HOST_NAME> notice audispd: node=my.ltm1.02.net type=PROCTITLE msg=audit(1642437012.319:1247794): slot2/LTM notice audispd: node=my.ltm1.02.net type=EOE msg=audit(1642437012.319:1247794):
    <HOST_NAME> notice audispd: node=my.ltm1.02.net type=SYSCALL msg=audit(1642437012.320:1247795): arch=40000003 syscall=11 success=yes exit=0 a0=8ec5db4 a1=91d5a00 a2=ffcaf0cc a3=92183d8 

Environment

  • Using remote syslog
  • Syslog configuration looks similar to the following: 
    list /sys syslog all-properties
sys syslog {
    auth-priv-from notice
    auth-priv-to emerg
    console-log enabled
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include filter f_audit { facility(local0) and match(AUDIT) and not match("user mcpd-primary"); };

Cause

While using f_audit in the include filter, the BIG-IP will send log files from the auditd log.

Recommended Actions

Note: In the actions below, the new setting will include none only, which is the default value.
  1. To stop audit filter to applied and set it to none, from tmsh run the following:
    modify sys syslog include 'none'
  2. To see current include option for the syslog-ng, run the following from tmsh:
    list sys syslog include
    sys syslog { 
    include none;
    }

Additional Information

For further filters options, use K13333: Filtering log messages sent to remote syslog servers (11.x - 15.x)
