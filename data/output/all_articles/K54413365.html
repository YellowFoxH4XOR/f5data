Description

Sometimes there is an incompatibility between supported ciphers and the SSL/TLS handshake won't be able to complete.

If this is the case, you should see the following logs in /var/log/ltm

01260026:4: No shared ciphers between SSL peers <client_IP>:<server_IP>

Environment

  • Client SSL configuration
  • Cipher suites

Cause

Incompatibility between the ciphers that the BIG-IP uses and the one the client supports.

Recommended Actions

  1. Identify the virtual server in question.
  2. Take a packet capture trying to capture a failed connection attempt between the client and the virtual server
  3. Have a look at the Client Hello message coming from the user, this will include the ciphers that the client supports, an example can be:

        TLS_DHE_DSS_WITH_3DES_EDE_CBC_SHA
        TLS_DH_DSS_WITH_AES_128_CBC_SHA
        TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA
        TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384

    Once the supported ciphers from the client have been identified, you'll need to change the names so you can get the correct cipher string. You can use the external websites indicated under the related content section as a reference.

  4. From the example in step 3, and converting it to the Open SSL name, you should get the following equivalent string.

    DHE-DSS-DES-CBC3-SHA:DH-DSS-AES128-SHA:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-GCM-SHA384

  5. Modify the cipher string in the Client SSL profile that is used in the virtual server so it includes the previous cipher

    Note: Not all of the ciphers might be supported.
