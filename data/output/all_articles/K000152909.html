Description

On F5OS-Appliance version 1.8.0, running the system diagnostics tcpdump command with complex or multiple/long BPF (Berkeley Packet Filter) expressions—specifically when using three/four or more filters—can cause the tcpdump process to crash. The error message observed is:

*** Error in `<sCRub_LINUXPATH_gIREc3JFJkXLAjiGzBRUt66ASx> free(): invalid next size (normal): 0x00000000006fa580 ***

This is accompanied by a core dump and a backtrace referencing libpcap and libc. The issue does not occur when using simpler BPF expressions (such as a single host/port filter).

For example:

system diagnostics tcpdump interface LAG_TEST outfile dump.pcap bpf "host 10.200.200.201 or host 10.200.200.202 or host 10.200.200.203 or host 10.200.200.204"
Capture file size will be limited to 62622083 1KB blocks.

Environment

  • Product: F5OS - Appliance
  • Version: 1.8.0 (build 17564)
  • Platforms: F5-BIG-LTM-R10800, C128, and similar rSeries hardware
  • Command: system diagnostics tcpdump with BPF expressions containing long filters (for example, multiple host or port conditions combined with and/or)

Cause

  • Bug ID 2009765
  • A software defect in the tcpdump or underlying libpcap library on F5OS-A 1.8.0 leads to memory corruption when parsing and compiling BPF expressions with long filters, resulting in a process crash.

Recommended Actions

  • Limit BPF expressions in system diagnostics tcpdump to fewer/shorter filters to avoid triggering the crash.
  • For advanced filtering needs, consider capturing broader traffic and applying additional filtering post-capture using external tools.
  • Track internal reference ID2009765 for updates regarding this issue.
