K000161254: Server-Side Dynamic CRL Validation Fails for Certificates Without CRLDP URL in BIG-IP SSLO Deployments

Published

Updated

Applies to

Source

Description

This article addresses an issue in BIG-IP SSL Orchestrator (SSLO) deployments where enabling Dynamic CRL checking on the server SSL profile causes handshake failures if the presented server certificate does not contain a CRL Distribution Point (CRLDP) URL. This is commonly observed with self-signed certificates that lack a CRLDP extension. The connection is terminated during the SSL handshake, and log messages such as "unable to build certificate trust chain" and "ssl_hs_do_crl_validation:7302: alert(46) unknown certificate error" may be seen.

Environment

  • Product: BIG-IP SSLO
  • Feature: Dynamic CRL checking (not strict mode)
  • Server SSL profile with Dynamic CRL enabled
  • Backend servers presenting self-signed certificates without CRLDP URL

Cause

Server-side Dynamic CRL validation fails for certificates that do not include a CRLDP URL, resulting in handshake termination. There is currently no mechanism to bypass CRL checks for such certificates. Bug ID 2287865

Answer/Recommended Actions

  • If possible, add the self-signed certificates to the trusted CA list of the server SSL profile.
  • Alternatively, ensure that all backend server certificates include a valid CRLDP URL.
  • Be aware that there is no granular control to bypass CRL checks for certificates without CRLDP when Dynamic CRL is enabled.
  • Monitor Bug ID 2287865 for future updates or fixes.

Additional Information

  • This behavior is consistent with previously observed client-side issues (see Bug ID 2044457).
  • The issue is specific to server-side Dynamic CRL validation in SSLO deployments.
