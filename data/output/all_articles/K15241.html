Topic

You should consider using this procedure under the following condition:

  • You want to detect and block attacks targeting certain Apache Struts vulnerabilities on your origin web server (OWS).

Description

The Apache Struts web application framework uses and extends Java Servlet API for developing Java EE web applications, and is commonly deployed on the OWS. A number of vulnerabilities have been announced for the Apache Struts web application framework. Some of these attacks typically exploit the ClassLoader through the getClass method by using the class parameter and then execute arbitrary code using a crafted request. These vulnerabilities are documented in the following CVEs:

  • CVE-2014-0094
  • CVE-2014-0112
  • CVE-2014-0113
  • CVE-2014-0114
  • CVE-2014-0116

The proper fix to these vulnerabilities is to upgrade the Apache Struts to version 2.3.16.2 as recommended in the official security advisory. However, if you are unable to upgrade your affected Apache Struts in the meantime, you can configure your BIG-IP ASM system to detect and block malicious attacks that exploit the previously described Apache Struts vulnerabilities. You can do so by creating attack signatures to detect and block requests that contain one of the following case-insensitive strings in their parameters:

  • class.
  • [“class”]
  • [‘class’]
  • class[

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have an existing BIG-IP ASM system provisioned and one or more security policies configured on the system to protect your OWS.
  • You should be familiar with either the Perl Compatible Regular Expressions (PCRE) and RE2 regular expression syntax.
  • You must have administrative access to the Configuration utility.

Procedures

  • Creating and assigning a user-defined attack signature in BIG-IP ASM 11.4.0 through 11.5.1
  • Creating and assigning user-defined attack signatures in BIG-IP ASM 11.2.0 through 11.3.0
  • Creating and assigning user-defined attack signatures in BIG-IP ASM 10.1.0 through 11.1.0

Creating and assigning a user-defined attack signature in BIG-IP ASM 11.4.0 through 11.5.1

In BIG-IP ASM 11.4.0 through 11.5.1, you need to create only one user-defined attack signature and assign it to your desired security policy in order to detect and block malicious requests that target the previously described Apache Struts vulnerabilities. To do so, perform the following procedure:

Impact of procedure: The user-defined attack signature may lead to false positives for customers who use parameters that include the class keyword in their name.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature List.
  3. To create a new user-defined attack signature, click Create.
  4. Enter a unique name in the Name setting for the new user-defined attack signature.

    Note: The user-defined attack signature name must not be the same as a system-supplied attack signature, otherwise subsequent signature updates may fail.

    For example:

    ApacheStrutsClassParameter

  5. For the Signature Type setting, select Request.
  6. Select the appropriate system for the Systems setting by moving the selected entry from the Available Systems to the Assigned Systems.

    For example:

    Apache
    Apache Tomcat

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  7. Select the appropriate attack type for the Attack Type setting.

    For example:

    Other Application Attacks

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  8. Enter the following rule syntax in the Rule setting:

    valuecontent:"class"; norm; nocase; re2:"/(?:\bclass[.\[]|\[\x22class\x22\]|\['class'\])/Vi"; norm;

  9. Configure the remaining settings as desired.
  10. To save the configuration for the user-defined attack signature, click Create.
  11. Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature Sets.
  12. To create a new user-defined attack signature set, click Create.
  13. For the new user-defined signature set, enter a unique name in the Name setting.

    For example:

    ApacheStrutsSet

  14. For the Type setting, select Manual.
  15. Select the filters as appropriate in the Signatures Filter section based on your selection for the Systems and/or Attack Type settings during the creation of the user-defined attack signature. The Configuration utility will then refresh the Signatures list. For example, if you have selected Apache for the Systems setting and Other Application Attacks for the Attack Type setting, the Configuration utility should refresh the Signatures list to display the user-defined attack signature created in previous steps.

    Note: Depending on the number of available attack signatures on your system, the Configuration utility may take some time to refresh the Signatures list.

  16. Select both the user-defined attack signatures created in previous steps in the Available signatures list and move them to the Assigned signatures list by clicking <<.
  17. To save the configuration for the user-defined attack signature set, click Create.
  18. Navigate to Security > Application Security > Attack Signatures > Attack Signatures Configuration.
  19. From the Current edited policy list, select the desired security policy.
  20. In the Attack Signature Sets Assignment setting, select the user-defined attack signature set you have created in previous steps from the Available Signature Sets list and move it to the Assigned Signature Sets list by clicking <<.
  21. To save the changes, click Save.
  22. To activate the change, click Apply Policy.

Creating and assigning the user-defined attack signatures in BIG-IP ASM 11.2.0 through 11.3.0

In BIG-IP ASM 11.2.0 through 11.3.0, you need to create two separate attack signatures to detect and block malicious requests that target the previously described Apache Struts vulnerabilities using parameters and cookies. To do so, perform the following procedure:

Impact of procedure: The user-defined attack signature may lead to false positives for customers who use parameters that include the class keyword in their name.

  1. Log in to the Configuration utility.
  2. Navigate to one of the following locations:
    • BIG-IP ASM 11.3.0

      Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature List

    • BIG-IP ASM 11.2.x

      Navigate to Application Security > Options > Attack Signatures > Attack Signature List

  3. To create a new user-defined attack signature, click Create.
  4. Enter a unique name in the Name setting for the new user-defined attack signature.

    Note: The user-defined attack signature name must not be the same as a system-supplied attack signature, otherwise subsequent signature updates may fail.

    For example:

    ApacheStrutsClassParameter

  5. For the Signature Type setting, select Request.
  6. Select the appropriate system for the Systems setting by moving the selected entry from the Available Systems to the Assigned Systems.

    For example:

    Apache

    Apache Tomcat

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  7. Select the appropriate attack type for the Attack Type setting.

    For example:

    Other Application Attacks

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  8. In the Rule setting, enter the following rule syntax:

    valuecontent:"class"; norm; nocase; re2:"/(?:\bclass[.\[]|\[\x22class\x22\]|\['class'\])/Vi"; norm;

  9. Configure the remaining settings as desired.
  10. To save the configuration for the user-defined attack signature, click Create.
  11. To create another new user-defined attack signature, click Create.
  12. Enter a unique name in the Name setting for the new user-defined attack signature. The user-defined attack signature name must not be the same as a system-supplied attack signature, otherwise subsequent signature updates may fail.

    For example:

    ApacheStrutsClassCookie

  13. For the Signature Type setting, select Request.
  14. Select the appropriate system for the Systems setting by moving the selected entry from the Available Systems to the Assigned Systems.

    For example:

    Apache

    Apache Tomcat

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  15. Select the appropriate attack type for the Attack Type setting.

    For example:

    Other Application Attacks

    Note: This step will aid in the creation of a user-defined attack signature set in later steps.

  16. In the Rule setting, enter the following rule syntax:

    headercontent:"class"; nocase; re2:"/Cookie:.*?(?:\bclass[.\[]|\bclass\[|\[\x22class\x22\]|\['class'\])/Hi";

  17. Configure the remaining settings as desired.
  18. To save the configuration for the second user-defined attack signature, click Create.
  19. Navigate to one of the following locations:
    • BIG-IP ASM 11.3.0

      Navigate to Security > Options > Application Security > Attack Signatures > Attack Signature Sets

    • BIG-IP ASM 11.2.x

      Navigate to Application Security > Options > Attack Signatures > Attack Signature Sets

  20. To create a new user-defined attack signature set, click Create.
  21. Enter a unique name in the Name setting for the new user-defined signature set.

    For example:

    ApacheStrutsSet

  22. For the Type setting, select Manual.
  23. Select the filters, as appropriate, in the Signatures Filter section based on your selection for the Systems and/or Attack Type settings during the creation of the user-defined attack signature. The Configuration utility will then refresh the Signatures list. For example, if you have selected Apache for the Systems setting and Other Application Attacks for the Attack Type setting, the Configuration utility should refresh the Signatures list to display the user-defined attack signatures created in previous steps.

    Note: Depending on the number of available attack signatures on your system, the Configuration utility may take some time to refresh the Signatures list.

  24. Select both the user-defined attack signatures created in previous steps from the Available signatures list and move them to the Assigned signatures list by clicking <<.
  25. To save the configuration for the user-defined attack signature set, click Create.
  26. Navigate to one of the following locations:
    • BIG-IP ASM 11.3.0

      Navigate to Security > Application Security > Attack Signatures > Attack Signatures Configuration

    • BIG-IP ASM 11.2.x

      Navigate to Application Security > Attack Signatures > Attack Signatures Configuration

  27. Select the desired security policy from the Current edited policy list.
  28. In the Attack Signature Sets Assignment setting, select the user-defined attack signature set you have created in previous step in the Available Signature Sets list and move it to the Assigned Signature Sets list by clicking <<.
  29. To save the changes, click Save.
  30. To activate the change, click Apply Policy.
