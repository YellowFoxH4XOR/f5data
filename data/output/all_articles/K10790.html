K10790: BIG-IP WebAccelerator version 9.4.x may report more traffic compared to version 10.x

Topic

When you perform an upgrade to the BIG-IP WebAccelerator version 10.x from a BIG-IP WebAccelerator version 9.4.x system, you may notice previously that the BIG-IP WebAccelerator version 9.4.x system reports more traffic count in statistics such as Total Connections and performance graphs such as Throughput and HTTP Requests as compared to the BIG-IP WebAccelerator version 10.x system.

This behavior is expected, and is a result of the architecture required to accommodate BIG-IP WebAccelerator traffic flows in BIG-IP version 9.4.x. When the BIG-IP WebAccelerator cannot serve a client request from any of its caches, the pvac process will send the request back to TMM via an internal TCP connection, so that TMM may request the HTTP object to the origin web server (OWS). This architecture may cause TMM to process some requests multiple times and inaccurately account for the additional request. When several requests are inaccurately counted, they may result in the related performance graphs and statistics to report a higher traffic count versus the actual traffic count received by the WebAccelerator system.

Beginning in BIG-IP WebAccelerator version 10.0.0, the plugin architecture was adopted. The plugin architecture simplifies the communication between the pvac process and TMM by facilitating messages describing a request/response as well as the actions to be taken on the request/response rather than passing on the entire request/response payload via an internal TCP connection. This architecture provides TMM the means to process any requests only once. As a result, the BIG-IP WebAccelerator version 10.x system reports a more accurate traffic count versus the actual traffic count.
