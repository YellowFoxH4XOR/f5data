Known Issue

TMM may become unresponsive when Multipath TCP (MPTCP) JOIN arrives in the middle of a flow.

This issue occurs when all of the following conditions are met:

  • The Multipath TCP (MPTCP) option is enabled in the TCP profile.
  • TMM receives MPTCP join (new TCP connection) packets in the middle of a flow.

Note: The MPTCP option is disabled in the TCP profile, by default.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the BIG-IP system is configured as part of a high-availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system logs a message in the /var/log/tmm file that appears similar to the following example:

    mptcp_handle_mpjoin_option (node=0x570308046bc0, cf=0x570307a2e600, pkt=0x5703041ab580) at ../modules/hudfilter/tcp/tcp.c:2804
