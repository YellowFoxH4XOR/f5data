Description

On certain BIG-IP platforms with software RAID, upgrading to v14,v15, or v16 may fail with a "Disk full" error.

If the BIG-IP has software RAID, and If the /dev/md/ directory does not have the symlink that the install script expects upgrading can fail.

When this issue occurs, /var/log/liveinstall.log will contain a log message similar to the following

error: tm_install::Process::Process_full_install -- predicted size for BIGIP14125 is 12315728, current location size is 11120640, and vg has 0 remaining.

And the output of tmsh show sys software will look similar to the following
--------------------------------------------------------
Sys::Software Status
Volume  Product  Version   Build  Active  Status
--------------------------------------------------------
MD1.1    BIG-IP 13.1.3.2   0.0.4      no  complete
MD1.2    BIG-IP 13.1.3.3   0.0.6     yes  complete
MD1.3    BIG-IP 14.1.2.5   0.0.3      no  failed (Disk full (volume group). See SOL#10636)

This occurs even when there is adequate disk space available
[root@bigip1:Active:Standalone] images # vgs
  VG             #PV #LV #SN Attr   VSize   VFree
  vg-db-cpmirror   1  24   0 wz--n- 372.60g 19.78g
  vg-db-sda        1   0   0 wz--n-      0      0
  vg-db-sdb        1   0   0 wz--n-      0      0

Environment

  • BIG-IP with software RAID
  • Software Update Failure

Cause

Bug ID 927033

Recommended Actions

You may upgrade to a version where Bug ID 927033 is fixed or use the following workaround:
  1. Check to see if the /dev/md/ directory has a symlink similar to localhost:0. If this symlink exists, then the installer will fail to find the MD array and return a disk space error.

    [root@bigip1] images # ls -l /dev/md/
    total 8
    -rw-r--r--. 1 root root  5 2020-07-09 16:12 autorebuild.pid
    lrwxrwxrwx. 1 root root  8 2020-07-09 16:51 localhost:0 -> ../md127
    -rw-------. 1 root root 66 2020-07-09 16:11 md-device-map
     
  2. The workaround is to create the expected symlink manually:

    cd /dev/md
    ln -s ../md127 _none_\:0

    Note:  If your array is not installed as md127, adjust the above command accordingly.  For example, some BIGIPs will use /dev/md0
