Description

This article provides steps to assist in APM Kerberos SSO testing from command line without modifying the /etc/krb5.conf config.

Environment

  • BIG-IP APM
  • SSO
  • Kerberos

Cause

Undetermined

Recommended Actions

  1. SSH to APM to access the CLI
  2. Create a copy of the /etc/krb5.conf to home directory
  3. Modify krb5.conf as the example below:

default_realm = SG.F5NET.LOC
dns_lookup_realm = true
dns_lookup_kdc = true

Note: The realm name must be capital.

  1. Run the following command:

    export KRB5_CONFIG=$HOME/krb5.conf

  2. Assuming the delegation account is HTTP/apm.f5net.loc, run the command below

kinit -f HTTP/apm.f5net.loc@SG.F5NET.LOC

Password for HTTP/apm.f5net.loc @SG.F5NET.LOC:
##Enter the password for the delegation account>

If this steps throw error:

  • Verify, delegation account, NTP, DNS
  • tcpdump on port 53 and 88 on a separate window . This should give hints on the issue

tcpdump -ni 0.0:nnn port 53 or 88

Note: This step will verify if S4U ticket is working as expected

  1. Assuming the user account is user@SG.JOSEPH.LOC

kvno -C -U user1@SG.F5NET.LOC  HTTP/apm.f5net.loc@SG.F5NET.LOC

HTTP/apm.f5net.loc@SG.F5NET.LOC: kvno = 3

Note: If this step throws error, do packet capture as mentioned above and check the data for hints of the issue.
Note: This step will verify if user1@SG.F5NET.LOC can get S4U2Self ticket

  1.  Run klist to verify the tickets created:

klist

  1. Additionally,  curl cmd  will  be helpful to check if the back end server configured for Kerberos
