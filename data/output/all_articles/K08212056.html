K08212056: FQDN firewall rule stopped working

Type
Support Solution
Published
2021-09-29
Updated
2026-03-09
Applies to
  • BIG-IP
  • BIG-IP AFM: 16.0.0, 14.1.2, 13.1.1, 15.1.0, 12.1.5
Source
https://my.f5.com/manage/s/article/K08212056

Description

Your FQDN firewall rules don't appear to function after two or more FQDNs point to the same IP address

Environment

  • BIG-IP AFM
  • FQDN Firewall rules

Cause

The issue may be caused by ID926417, which prevents FQDN firewall rules from functioning correctly if two different FQDNs ever point at the same IP address.

Recommended Actions

Review your device's current FQDN resolutions to see if there are more than one FQDN pointing to the same IP address

  1. To view the current entries that the BIG-IP system has cached, use the following command:
    tmsh show security firewall fqdn-info fqdn all
  2. If you are not able to find a duplicate in the current data, you may need to enable debug logging and see if any of your FQDNs even land on the same IP address. You can do this by enabling the system variable to debug option using the following command:
    tmsh modify sys db log.fw_fqdn.level value debug
  3. When you have completed the data collection, you can change the logs level back to notice (which is the default log level), using the following command:
    tmsh modify sys db log.fw_fqdn.level value notice
  4. Review the logs collected in /var/log/tmm*
    Note: For most users, this can be done quickly in iHealth using log test search for "[FW] IP Address"
  5. If you are able to verify that two or more of your FQDN answers pointed to the same IP address at some point, reset TMM which will clear the issue temporarily using the following command:
    bigstart restart tmm
    Note: Restarting TMM is disruptive to traffic and should only be performed during off hours, a maintenance window. Failing over to a peer device will prevent this disruption.
