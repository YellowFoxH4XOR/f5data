K51646193: Unable to recover Postgres during ha_generate_cert command

Type
Support Solution
Published
2021-10-11
Updated

Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • Public Cloud
  • BIG-IQ
Source

Description
You are trying to recover your secondary BIG-IQ device but you are encountering Postgres issues when running ha_generate_cert command

Example:

Unable to connect to Postgres. Error code: 2
Postgres is not accepting connections via localhost. Error code: 2

You are also getting these logs from /var/log/postgres/postgresql-YYYY-MM-DD.log

Example:

YYYY-MM-DD TT:HH:MM.SSS TMZ [19029] LOG:  startup process (PID XXXXX) exited with exit code 1
YYYY-MM-DD TT:HH:MM.SSS TMZ [19029] LOG:  aborting startup due to startup process failure
YYYY-MM-DD TT:HH:MM.SSS TMZ [19029] LOG:  database system is shut down
YYYY-MM-DD TT:HH:MM.SSS TMZ [19154] LOG:  database system was shut down in recovery at YYYY-MM-DD TT:HH:MM.SSS TMZ
YYYY-MM-DD TT:HH:MM.SSS TMZ [19154] FATAL:  requested timeline 2 is not a child of this server's history
YYYY-MM-DD TT:HH:MM.SSS TMZ [19154] DETAIL:  Latest checkpoint is at XXX/52D293C4 on timeline 2, but in the history of the requested timeline, the server forked off from that timeline at 0/0.
YYYY-MM-DD TT:HH:MM.SSS TMZ [19152] LOG:  startup process (PID XXXXX) exited with exit code 1
YYYY-MM-DD TT:HH:MM.SSS TMZ [19152] LOG:  aborting startup due to startup process failure
YYYY-MM-DD TT:HH:MM.SSS TMZ [19152] LOG:  database system is shut down

Environment

  • Secondary BIG-IQ
  • Attempting to recover secondary CM 2 for HA Pairing
  • BIG-IQ v7.1.0
  • Postgres is restarting 

Cause
Postgres database corruption

Recommended Actions

Follow the steps in the below article to reset the Postgres Database:

K000150361: Resetting the Big-IQ Postgres database

Wait for a few minutes until you can see the GUI login page.
