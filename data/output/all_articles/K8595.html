Known Issue

This is the result of a known issue. Synchronizing configurations that contain large policies may timeout and fail to install.

This issue is a result of internal timeouts that expire during the time it takes to create a UCS file, push or pull the configuration file, install and then activate the policies on the peer or current system. When this issue occurs, an error message similar to the following example is returned when the configsync process times out:

SOAPException: 'Unexpected return Content-Type: text/html; charset=iso-8859-1'
Saving active configuration...
Transport and install failed
Error running config sync all.
BIGpipe parsing error:
01110001:3: Error running config sync all

F5 Networks Product Development tracked this issue as CR92630 and it was fixed in BIG-IP ASM version 9.4.5. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP version 9.4.3, and Hotfix-BIG-IP-9.4.4-HF1 issued for BIG-IP version 9.4.4. You may download these hotfixes or later versions of the hotfixes from the F5 Networks Downloads site.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about how to manage F5 Networks product hotfixes, refer to K6845: Managing F5 Networks product hotfixes.

Workaround

This behavior occurs primarily when synchronizing the configuration through the Configuration utility. If this behavior is encountered, F5 Networks recommends to synchronize the configuration using the command line.

To push a configuration from a system you are currently logged into, type the following command:

bigpipe config sync all

To pull a configuration from the peer system to the system you are currently logged into, type the following command:

bigpipe config sync pull
