Description

When you're using iRule with control structures like if, if-else, or switch, you should take special care with the condition cases as those checks on the provided condition are case sensitive. For the below example, checks on the variable $auth, $secondary, and the result of the [HTTP::uri] will be case-sensitive.
Example for if and if-else control structures:

if { $auth starts_with "conditionA" } {
    pool auth_pool
} elseif { $secondary eq "conditionB" } {
    pool secondary_pool
} else {
    default_pool
}

Example for switch control structures:

switch [HTTP::uri] {
    "/PathA" {
        pool http_pool
    }
    "/PathB" {
        pool http_pool2
    }
    "/PathC" {
        pool http_pool3
    }
}

Environment

  • iRule with a control structure
  • BIG-IP LTM

Cause

iRule control structure "if", "If-else" and "switch" are case-sensitive

Recommended Actions

If you want to let the checks be equally case-insensitive, you may consider using string tolower. For example:
if { [string tolower $auth]  starts_with "conditionA" } {
    pool auth_pool
} elseif { [ string tolower [HTTP::uri] ] eq "conditionB" } {
    pool secondary_pool
} else {
    default_pool
}
