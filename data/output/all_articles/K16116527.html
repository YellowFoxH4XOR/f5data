Description

Attack signature update not working.

  • ASM Attack Signature updates fail after upgrading to 14.1.x
  • Errors in /var/log/asm during signature update:

crit g_server_rpc_handler.pl[<PID>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::Sigfile::Update::store_error_and_die): Couldn't open /ts/var/tmp/sigfile.tmp.7859/sigs/200001000_xss/200101032/stirling__version_2.xml:
crit g_server_rpc_handler.pl[<PID>]: 01310027:2: ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::handle_error): Code: 999, Error message = Couldn't open /ts/var/tmp/sigfile.tmp.7859/sigs/200001000_xss/200101032/stirling__version_2.xml:

Environment

  • BIG-IP ASM 
  • ASM Attack signature update

Cause

The system performs a file cleanup and removes necessary files before the Attack Signature update has completed. This is likely due to the known issue tracked in ID852437. 

Recommended Actions

If the workaround listed in the Bug Tracker article fails, an alternative workaround of temporarily increasing the temp file cleanup interval has also been effective as a workaround based on past cases reported to F5 Support. To do so, perform the following procedure:

  1. Adjust the interval in the /etc/ts/tools/asmcrond.cfg
    From:
    [CleanFiles]
    Interval=300
    To:
    [CleanFiles]
    Interval=3000
    Important: Don't extend the Interval too much, 50 minutes should be enough for everything.

  2. Restart the asmcrond
    ps -ef | grep asmcrond
    kill <pid>

    For example:
    [root@C3222964-bigip1:Active:Standalone] tmp # ps -ef | grep asmcrond
    root     24036     1  0 21:54 ?        SN     0:01 /usr/bin/perl /usr/share/ts/bin/asmcrond
    root     24894 14376  0 22:02 pts/1    S+     0:00 grep asmcrond

    [root@C3222964-bigip1:Active:Standalone] tmp # kill 24036

    The asmcrond will be respawning after several seconds.
    You may see the following log in /var/log/asm
    Mar 20 21:54:42 C3222964-bigip1.chopra crit perl[22490]: 01310027:2: ASM subsystem error (asm_start,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: asmcrond, Failure: Insufficient number of threads (required: 1, found: 0).
    But nothing should be impacted.

  3. Monitor the asmcrond.log until you see another Cleanfiles log.
    tailf /var/log/ts/asmcrond.log | grep CleanFiles
    You are looking for something similar to:
    asmcrond|INFO|Mar 20 21:54:44.389|24036|F5::PeriodicTask::Base::run,,Running Task: CleanFiles

  4. Now you can install the ASU, the temp files can be staying in the folder for 50 minutes.

  5. After the ASU been installed, change the interval to back to 300 and restart the asmcrond (similar steps to 1 and 2 above)
    /etc/ts/tools/asmcrond.cfg
    [CleanFiles]
    Interval=300
    ps -ef | grep asmcrond
    kill <pid>

  6. Make sure the asmcrond has been started correctly.
    ps -ef | grep asmcrond
    tailf /var/log/ts/asmcrond.log
