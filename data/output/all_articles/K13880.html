Known Issue

Attempting to remove a service on an ARX disaster recovery cluster may fail.

This issue occurs when all of the following conditions are met:

  • You used the remove service command on the backup disaster recovery ARX cluster.
  • You added the disaster recovery configuration after the ARX global configuration was already in place.
  • An external filer has been identified in the sam-reference configuration.

As of 5.2.0 the ARX system supports disaster recovery for ARX clusters that reside at geographically separate sites. Disaster recovery works by failing over services, volumes, and shares from an active ARX cluster that is unable to continue operating. When you add a disaster recovery configuration on an ARX that already has a namespace with a CIFS sam-reference configuration option in place, this situation creates a false entry in the configuration database. The issue will not be apparent until a user attempts to use the remove service command to remove the namespace configuration and the objects that are exclusively dedicated (such as global servers, proxy users, and NFS access-lists).

Note: For further information about the ARX Disaster recovery configuration, refer to the ARX Disaster Recovery chapter in the ARX CLI Maintenance Guide.

Impact

Removal of the ARX service configuration fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You get error messages that appear similar to the following examples when using the remove service command:

ERROR: EXT_FILER_IN_USE (41353266): External filer 'example_filer1' has shares which are currently in use.

INFO: REMOVE_SERVICE_FAILED (42860680): The remove service command failed see previous error.

Workaround

To work around this issue, you may manually remove the namespace configuration, global server, and external-filer, or remove the ARX system global configuration. To do so, perform one of the following procedures:

Manual removal of the namespace configuration, global server, and external-filer

To minimize downtime and remove as many of the components as possible, perform the following procedure to manually remove the namespace:

Impact of workaround: External-filer reference remains in the ARX configuration.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Remove all namespace configuration items except the global server and external filer by typing the following command syntax:

    remove namespace [namespace name]

    For example:

    remove namespace ARXtestNS_CIFS1

  4. Enter global mode by typing the following command:

    global

  5. Show the current global server configuration by typing the following command:

    show global server

  6. Remove the global servers that are no longer needed, by typing the following command syntax:

    no global server [server FQDN]

    For example:

     no global server GS1.example.com

  7. Show the current external filer configuration by typing the following command:

    show external-filer

  8. Remove the external filers that are no longer needed, by typing the following command syntax:

    no external-filer [filer name]

    For example:

    no external-filer example_filer1

    Note: The system may fail to remove the external filer that was identified in the ERROR: EXT_FILER_IN_USE error. If this happens, the only method to completely remove the filer is to complete the following procedure on how to remove the global configuration.

  9. Return to privileged mode by typing the following command:

    end

Remove the ARX system global configuration

If you are unable to remove the configuration components using the manual procedure, you must clear the global configuration for complete service removal.

Impact of workaround:  The ARX system will no longer have a global configuration and you need to reconfigure the system before use.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Remove the global config by typing the following command:

    clear global-config

  4. Reload the ARX system to complete the process by typing the following command:

    reload
