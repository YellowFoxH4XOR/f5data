Description

When the BIG-IP communicates with the pool members (server) it will always change the Source IP address.

This can be confirmed by running "tmsh show sys connection cs-server-addr x.x.x.x" where x.x.x.x is the IP of the virtual server.

Assume the Client IP is 203.0.113.1, Virtual Server IP is 198.51.100.2 and pool member (server) IP is 172.16.3.3, the output will be shown as below:

[root@LTM-01:Active:In Sync] config # tmsh show sys connection cs-server-addr 198.51.100.2
Sys::Connections
203.0.113.1:52207  198.51.100.2:443  10.10.10.10:52207   172.16.3.3:80  tcp  17  (tmm: 1)  none  none
203.0.113.1:51079  198.51.100.2:443  10.10.10.12:51079   172.16.3.3:80  tcp  5   (tmm: 0)  none  none
203.0.113.1:51077  198.51.100.2:443  10.10.10.13:51077   172.16.3.3:80  tcp  10  (tmm: 0)  none  none
203.0.113.1:51078  198.51.100.2:443  10.10.10.11:51078   172.16.3.3:80  tcp  9  (tmm: 1)  none  none

The third column will show the IP address used by the BIG-IP to communicate with the pool member (server). For example:

  • 10.10.10.10
  • 10.10.10.11
  • 10.10.10.12
  • 10.10.10.13

Environment

  • The virtual server is using secure network address translation (SNAT) for its Source Address Translation.
  • The SNAT pool has more than one IP address.

Cause

This is an expected behavior when using a SNAT pool for your virtual server configuration. When using a SNAT pool, the source address of different server-side connections can change even if the source address of the client-side is the same. This is because a primary reason for using a SNAT pool is to avoid port exhaustion. Port Exhaustion can occur if too many connections are attempted from a single IP address (or a small number of IP addresses). So, it is generally recommended to permit the BIG-IP system to dynamically chose which Source IP to use when connecting to the pool members (servers).

Recommended Actions

If you purchased the CGNAT/AFM license, you could implement this feature by referring to K14823:Overview of CGNAT Persistence.
Note: For version later than v15.x, CGNAT functionality has been migrated in to the BIG-IP AFM module. For more information, please refer to K50685218: After upgrade to V15.* GUI does not show CGNAT LSN pool and can not apply LSN pool to Virtual server

However, if you don't have a CGNAT/AFM license,  then you can follow the below DevCentral article for this feature:
