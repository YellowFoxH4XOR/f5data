Issue

The BIG-IP ASM system sets the following types of cookies to enforce elements in the security policy:

  • ASM Frame cookies
  • ASM Main cookies

Note: For more information about BIG-IP ASM cookies, refer to K6850: Overview of BIG-IP ASM cookies.

The BIG-IP ASM system signs the cookies with an MD5 digest signature, which is stored in the first 32 bytes of each cookie. When a returning client presents an ASM cookie, the BIG-IP ASM validates the digest stored in the cookie header against a message key stored on the BIG-IP ASM system.

When the BIG-IP ASM receives a request that contains an ASM Frame cookie and an ASM Main cookie that were generated with different MD5 digest keys, a violation that appears similar to the following example is logged to the /var/log/asm file and on the ASM Reporting screen in the Configuration utility:

Wrong message key

The violation can occur after modifying the cookie_digest_key internal parameter. For example, when a client accesses an application flow in the security policy, the BIG-IP ASM system signs the ASM Frame cookie and ASM Main cookie using the same MD5 digest key, and embeds the cookies into the response. The client browser stores the cookies for the default expiration time. If the cookie_digest_key internal parameter is then changed on the BIG-IP ASM system, it is possible for the client to send a request containing only the ASM Main cookie and not the Frame cookie. When this occurs, the browser retains ASM cookies containing different MD5 digest signatures. The next time that the client accesses an application flow, the BIG-IP ASM system issues the violation.

Note: For more information about the cookie_digest_key internal parameter, refer to K6990: Changing the BIG-IP ASM MD5 cookie digest key.
