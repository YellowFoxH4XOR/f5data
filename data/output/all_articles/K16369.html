Known Issue

BIG-IP health monitors may erroneously mark node and pool members up and down.

This issue occurs when the following condition is met:

  • A very large number of health monitors are configured.

The bigd monitor daemon provides system health checks. When thousands of monitors are configured, the bigd process may not be able keep up with the load. The number of configured monitors that the BIG-IP system can manage depends on several factors, such as the type of monitor used and the frequency (interval) at which the system issues the monitor check. For example, ICMP and TCP half-open are lightweight monitors, while HTTP and HTTPS monitors require more resources.

Note: Each pool member with a monitor assigned is considered as single monitor and each node with a monitor assigned is considered as separate monitor.

Impact

Monitored node or pool members may flap even when the services are not down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Monitored pool members appear to be marked up and down frequently.
  • The bigd process produces a core file in the /shared/core directory.

Workaround

To work around this issue, you can increase the monitor interval setting (decrease the frequency that monitors are sent), or switch to simpler monitor types. For example, choose ICMP or TCP half-open instead of HTTP or HTTPS.

Impact of workaround: Certain monitor types may not provide enough detail to accurately determine the health of your pool members. For example, ICMP monitoring determines whether the status of a node is up or down, however the status of individual protocols, services, or applications running on the node are not checked. Ensure any modification is compatible with your environment.
