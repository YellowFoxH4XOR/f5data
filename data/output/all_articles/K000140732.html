Security Advisory Description

Resolver caches and authoritative zone databases that hold significant numbers of RRs for the same hostname (of any RTYPE) can suffer from degraded performance as content is being added or updated, and also when handling client queries for this name. This issue affects BIND 9 versions 9.11.0 through 9.11.37, 9.16.0 through 9.16.50, 9.18.0 through 9.18.27, 9.19.0 through 9.19.24, 9.11.4-S1 through 9.11.37-S1, 9.16.8-S1 through 9.16.50-S1, and 9.18.11-S1 through 9.18.27-S1. (CVE-2024-1737)

Impact

A remote attacker can trigger excessive resource consumption on the vulnerable BIG-IP DNS system to cause a denial-of-service (DoS).

The following BIG-IP DNS configuration is not affected by this vulnerability:

  • Listener (virtual server) with Use BIND Server on BIG-IP setting disabled on the attached DNS profile.

The following BIG-IP DNS resolver caches are not affected by this vulnerability and authoritative zones are much less likely to affected by this vulnerability:

  • Listener (virtual server) with Use BIND Server on BIG-IP setting enabled on the attached DNS profile. However, the named configuration must include recursion no, which is the default setting, and it cannot have large (greater than 100 resource records with a single name) authoritative zones.

Mitigation

To mitigate this vulnerability on the BIG-IP DNS system, you can limit the quantity of stored resource records (RRs) or enable connection rate limiting. To do so, perform one or both of the following procedures:

  • Limit the quantity of stored RRs
  • Enable connection rate limiting

Limit the quantity of stored RRs

If possible, you should flush RRs with the same hostname from resolver caches and delete unnecessary RRs from authoritative zone databases to reduce your risk of a successful attack. Administrators should keep RR sets with a single name to less than 100 records of the same type, and less than 100 records of different types, per recommendations from ISC. To remove RRs from authoritative zone databases, refer to the following procedure:

Impact of procedure: The impact of removing RR depends on the specific environment. F5 recommends that you test any changes during a maintenance window and consider the possible impact on your specific environment. You cannot undo the procedure.

  1. Log in to the BIG-IP DNS Configuration utility.
  2. Go to DNS > Zones > ZoneRunner > Resource Record List.
  3. Select a View Name, Zone Name, Type or set to All.
  4. Select Search.
  5. Review the list of RRs to determine if any are unnecessary and can be removed. Administrators should keep resource record sets with a single name to less than 100 records of the same type, and less than 100 records of different types, per recommendations from ISC.
  6. Select the box next to the records you want to remove.
  7. Select Delete and Delete again to confirm.

Enable connection rate limiting

Impact of procedure: Applying an incorrect value for the Connection Rate Limit setting causes unexpected limiting of connections to the virtual server being configured. Ensure that the value configured is acceptable per the normal traffic pattern of the virtual server and accommodates an expected increase of traffic.

  1. Log in to the BIG-IP DNS Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the virtual server (listener) you want to rate limit.
  4. For Configuration, select Advanced.
  5. Enter the Connection Rate Limit value, as appropriate.
  6. For Connection Rate Limit Mode, select the appropriate setting. For example, Per Virtual Server and Source Address.

    Note: If Connection Rate Limit Mode is set to Per Virtual Server, the sample Connection Rate Limit value limits the connections for the virtual server. If Connection Rate Limit Mode is set to Per Virtual Server and Source Address, the Connection Rate Limit value limits the virtual server and the source IP address to connections sharing the same subnet.

  7. If applicable, enter the Connection Rate Limit Source Mask value.
  8. Select Update.

For more information, refer to K44660650: Mitigating UDP flood using the virtual server connection rate limit.
