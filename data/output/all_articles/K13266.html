Known Issue

Persistence profiles may cause connection resets on a BIG-IP LTM+APM mode virtual server.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured in LTM+APM mode
  • A source address or a cookie persistence profile is applied to the virtual server
  • The virtual server is configured to use a pool

Impact

Connections will experience resets on affected virtual servers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Client sessions may repeatedly drop
  • Client sessions may exhibit unusual slowness
  • Monitoring TCP traffic to the client system shows multiple connection resets

Workaround

To work around this issue, you can apply an iRule that selects the pool. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log on to the Configuration utility.
  2. Expand Local Traffic.
  3. Click iRules.

    The iRules list opens.
  4. Click the Create... button.

    The iRule editor opens.
  5. In the Name text box, enter a name for the iRule.
  6. In the Definition text box, enter the following text:

    when HTTP_REQUEST {
    pool <my_pool>
    }

    In the above example, note the following:
    • <my_pool> is the name of the pool to associate to the virtual server
  7. Click the Finished button.
  8. Click Virtual Servers.

    The Virtual servers list opens.
  9. Click the name of the virtual server to edit.
  10. Click the Resources tab.
  11. In the iRules section, click the Manage... button.
  12. Click the name of the iRule entered in Step 5 from the Available list.
  13. Click the << button.

    The iRule moves to the Enabled list.
  14. Click the Finished button.
