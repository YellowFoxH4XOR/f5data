Known Issue

Large Scale NAT (LSN) translation may occur after the system experiences an iRule error.

This issue occurs when the following condition is met:

  • A virtual server is using source-address-translation type LSN and has an iRule that does not handle errors.

Impact

Following are a number of possible side effects of this issue, depending on how the iRule is written:

  • The system may ignore any LSN commands in the failing iRule.
  • LSN pool translation statistics may be incremented.
  • The system may output a log message indicating a successful translation.
  • The system may send multiple RST packets for the halted connection.
  • The system may allocate port block allocation (PBA) port blocks.
  • The system may create persistence mapping entries.
  • The system may create inbound mapping entries.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When an iRule throws an error, the default is to stop the connection.
  • When the error occurs in the CLIENT_ACCEPTED event and the virtual server is using the LSN type of source address translation, the system may run the source address translation before the connection is stopped.
  • The address translation may succeed even though the connection fails.

Workaround

To work around this issue, you can use the Tool Command Language (Tcl) catch command to handle Tcl errors. When an error occurs, use the LSN::disable command to prevent the translation.

For example:

ltm rule lsnrule {
    when LB_SELECTED {
        if { [catch {LSN::address 4.4.1.1}] } {
            log local0. "caught tcl error in LSN::address command"
        }

    }
}
