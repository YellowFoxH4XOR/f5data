Known Issue

This is the result of a known issue. If the BIG-IP WebAccelerator receives a subsequent request on the same connection in the brief interval after the last HTTP data from the previous request has been sent to the client, but before the plugin has signaled to TMM that the response is finished, the BIG-IP WebAccelerator incorrectly identifies the subsequent request as a pipelined request. Since pipelined requests are not supported in HTTP version 1.0, the BIG-IP WebAccelerator sends an ACK in response to the subsequent request, then silently drops it. Since the BIG-IP system acknowledged the request, the client will not automatically retransmit the requests, and the connection will hang.

F5 Product Development is tracking this issue as ID 225749 (formerly CR140073).

This issue has been fixed in BIGIP-10.1.0-3402.0-HF2, which has been issued for BIG-IP version 10.1.0, and Hotfix-BIGIP-10.2.0-1755.1-HF1 which has been issued for version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

Note: When a client uses the Keep-Alive header to establish HTTP/1.0 connections, it creates what is referred to as a persistent connection over which multiple requests may be sent without the overhead of establishing a new connection for each. This concept of persistence is slightly different from BIG-IP persistence, which attempts to load balance all requests in the same session to the same server.
