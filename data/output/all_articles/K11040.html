Known Issue

This is the result of a known issue. The BIG-IP ASM and BIG-IP WebAccelerator systems require that you unchunk content so it can properly process responses. When the HTTP profile Response Chunking setting is set to Preserve, the profile does not unchunk the responses before passing the information to the BIG-IP ASM or BIG-IP WebAccelerator system for processing. This issue may result in high CPU utilization, or may cause the BIG-IP ASM or BIG-IP WebAccelerator system to misprocess gzipped responses or responses chunked from the originating server.

F5 Product Development is tracking this issue as ID 331693 (formerly CR134141).

Workaround

You can work around this issue by changing the HTTP profile Response Chunking setting to Unchunk. To do so, perform the following procedure:

Note: After you perform the following procedure, the BIG-IP LTM system buffers and unchunks any response that was originally chunked by the backend webserver, before passing the information to the BIG-IP ASM module. For more information regarding the behavior of the Response Chunking option, refer to the Managing Application Layer Traffic chapter of the Configuration Guide for BIG-IP Local Traffic Management.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Services.
  5. Select HTTP.
  6. Click the HTTP profile that you want to modify.
  7. Below Settings for the HTTP profile, locate Response Chunking.
  8. Select Unchunk from the menu.
  9. Click Finished.

Depending on the nature of your traffic, you can also set the Response Chunking setting to Rechunk or Selective, as needed, by choosing those options in step 7. For information about the different settings, refer to the Managing Application Layer Traffic chapter of the Configuration Guide for BIG-IP Local Traffic Management.
