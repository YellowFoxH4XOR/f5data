Topic

This article applies to BIG-IP ASM 12.x - 13.x. For information about other versions, refer to the following articles:

  • K13410341: Overview of L7 DDoS attack protection (14.x - 16.x)

Layer 7 (L7) DDoS attacks target the application layer of the OSI model and attempt to exploit features of the web application with the intention of disabling and preventing access to those features. The BIG-IP ASM system helps recognize L7 DDoS attacks based on client-side and server-side factors and take steps to protect the web application from the effects of such attacks.

Description

L7 DDoS attacks target specific areas of a web application with the intention of impacting web application functionality and availability. L7 DDoS attacks are frequently difficult to identify because the attacks tend to start gradually over time and initially appear to be legitimate user traffic. As the attack intensifies, the server and web application become overburdened and can no longer respond to legitimate requests as expected.

L7 DDoS attacks often use techniques to amplify the effects of the attack and target the hardware resources of the affected server. For example, an attack might force a web application to perform a resource-intensive task, such as a database search, with the intention of consuming additional server resources each time the search is performed. Or, the attack may target a particular web page or application element, such as a graphic, which consumes resources each time the page or graphic is downloaded.

L7 DDoS attacks are distinct from other types of DDoS attacks in the following ways:

  • Most L7 DDoS attacks involve legitimate requests, such as those from clients that are capable of storing session cookies. By contrast, layer 4 (L4) DDoS attacks typically generate bogus requests.
  • L7 DDoS attacks are more difficult to identify than other DDoS attacks because L7 attacks do not always depend on a high volume of traffic and the requests appear to be from legitimate clients.
  • L7 DDoS attacks may attempt to exploit vulnerabilities in the web application software. By contrast, other types of DDoS attacks rely more on brute-force methods used to overwhelm the network.
  • Most L7 DDoS attacks use techniques to amplify the effects of the attack and specifically target the CPU and memory utilization of the origin web server.

L7 DDoS detection profile settings

The L7 DDoS profile offers the following settings to detect and mitigate L7 DDoS attacks:

  • Heavy URL protection - A heavy URL is a URL that might consume considerable server resources for each request. Use this setting to configure one or more heavy URLs in the profile, and the system protects the URLs using the methods enabled in the profile.
  • Geolocations - Use this setting to allow or block traffic from certain countries during a DDoS attack. This setting overrides the DDoS profile's TPS-based Geolocation threshold settings.
  • Trigger iRule - Use this setting to have the system trigger a custom iRule to manage and mitigate DDoS events.
  • Single Page Application - An SPA is a web application that loads a single HTML page and dynamically updates that page as the user interacts with the application.  Use this setting to enable protection for Single Page Applications (SPAs).
  • URL Patterns - Use this setting to create logical sets of similar URLs with the varying part of the URL acting like a parameter. For example, /path/*.php.
  • Performance Acceleration (BIG-IP 13.1.0 and later) - Use this setting to configure the system to use a fastL4 profile as a performance enhancement for DDoS detection and mitigation. When enabled, this option combines L4 and L7 options and adds performance for DDoS mitigation. During normal operation, most traffic processed using the fast-path acceleration mode. Once the system detects an attack, suspicious flows switch to full-proxy mode.
  • Proactive bot defense - Use this setting to have the system provide defense against bot attacks by detecting and mitigating the attacks.
  • Bot signatures - Use this setting to configure the system to automatically detect legitimate bots and instruct the system on how to handle malicious bots. For example, you can configure the system to ignore, log, or block malicious bots.
  • TPS-based detection - Use this setting to configure the system to detect DDoS attacks based on the volume (transactions per second) of incoming traffic. The Automatic TPS setting sets the DDoS protection thresholds automatically and changes the default settings to accommodate traffic to your web application.
  • Behavioral and stress-based detection - Configure this setting when you want the system to automatically detect an increase in server stress and mitigate resultant DDoS attacks. This protection provides accurate DDoS detection based on requests per second thresholds.
  • Record Traffic - Use this setting to configure the system to automatically record and store traffic during DDoS attacks as tcpdump files to the /shared/dosl7/tcpdumps directory.

Creating the L7 DDoS profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > DoS Protection > DoS Profiles.
  3. Select Create.
  4. Type a name for the DoS profile and select Finished.
  5. On the DoS Profiles tab, select the name of the new DoS profile.
  6. Select the Application Security tab.
  7. Under Application Security > General Settings, enable Application Security by selecting Edit and the Enabled check box.
  8. Configure the settings in each of the following profile sections, as needed to address L7 DDoS attacks:
    • General Settings
    • Proactive bot defense
    • Bot signatures
    • TPS-based detection
    • Behavioral and stress-based detection
    • Heavy URL protection
    • Record Traffic
  9. Select Update.

Associating the DDoS profile with the virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the name of the virtual server for which you want to associate the DDoS profile.
  4. Hover on the Security tab and select Policies.
  5. Under Policy Settings, for DoS Protection Profile, select Enabled and the name of the DDoS profile.
  6. Select Update.

Recommendations

Before you configure L7 DDoS protection, you should configure the BIG-IP system to resolve DNS host names and create a DNS resolver. For more information, refer to K13205: Configuring the BIG-IP system to resolve DNS hostnames (11.x and later).
