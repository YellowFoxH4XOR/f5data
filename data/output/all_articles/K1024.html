K1024: SSL sessions may time out before the SSL Session ID Persistence has expired

Topic

Some browsers, including older versions of Microsoft Internet Explorer (IE), and Microsoft Internet Information Services (IIS) web servers force a short timeout for their SSL sessions. This timeout value will act as the maximum SSL Session ID Persistence timeout for these browsers, since the browser will force a session ID renegotiation at the designated timeout value.

Some browsers and IIS web servers have this timeout value set as low as two minutes. This breaks any SSL-based application that requires persistence for more than two minutes, regardless of the SSL Persistence ID timeout settings on the BIG-IP system.

The following three options can resolve this issue:

Option 1: Configure simple persistence on the BIG-IP Controller

Simple persistence uses the client browser's source IP address, so it is not affected by SSL Session ID changes.

The downside to using simple persistence is that load balancing becomes less granular if large groups of your clients have their source addresses masked by a proxy or NAT.

Option 2: Apply fixes for the affected Microsoft web browsers and/or IIS web servers

Microsoft discusses this issue, and lists the versions of IIS web servers and IE browsers that are affected, in Microsoft Knowledge Base Article - 247658: HOW TO: Configure Secure Sockets Layer Server and Client Cache Elements.

Microsoft has published a hotfix for specific browsers and it is included in Microsoft Knowledge Base Article - 265369: Internet Explorer Renegotiates Secure Sockets Layer Connection Every Two Minutes.

The downside to the hotfix is that it may require patching a large number of user browsers; therefore, if you have a large user base, or one that you cannot control, this fix will be impractical to deploy.

Option 3: Configure an SSL to server proxy and terminate SSL connections on the BIG-IP system

The BIG-IP system can be configured to decrypt and re-encrypt SSL encrypted communications. This allows the full range of persistence methods and L7 iRules to be applied on SSL-encrypted applications.

This does not stop the affected browsers from renegotiating the SSL sessions, but the BIG-IP system will still be able to keep persistence by using data inside the SSL session itself.

For more information about configuring an SSL to server proxy, refer to the BIG-IP manual specific to the version that you are running.

Note: iRules are only available for BIG-IP 4.5 and later. For information about upgrading, refer to the BIG-IP Release Notes.
