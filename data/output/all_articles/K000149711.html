Description

After upgrading BIG-IP tenants on VELOS chassis or rSeries to version 17.1.2.2 or above, ICMP node monitors may incorrectly mark nodes as down or flapping, even though packet captures show successful ICMP echo requests and replies. The following logs may display in /var/log/ltm

Jun 14 14:50:01 slot1/bigip-f5.com notice mcpd[7820]: 01070727:5: Pool /pool-https member /pool:443 monitor status up. [ /pool-https: up ]  [ was node down for 0hr:0min:4sec ]
Jun 14 14:50:01 slot2/bigip-f5.com notice mcpd[6569]: 01070728:5: Node /pool01 address 10.0.0.3 monitor status up. [ /Common/gateway_icmp: up ]  [ was down for 0hr:0min:4sec ]
Jun 14 14:50:01 slot2/bigip-f5.com notice mcpd[6569]: 01070727:5: Pool /pool-https member /pool:443 monitor status up. [ /pool-https: up ]  [ was node down for 0hr:0min:4sec ]
Jun 14 14:50:01 slot4/bigip-f5.com notice mcpd[8864]: 01070728:5: Node /pool01 address 10.0.0.3 monitor status up. [ /Common/gateway_icmp: up ]  [ was down for 0hr:0min:4sec ]

Environment

  • BIG-IP 17.1.2 or above upgrade
  • VELOS or r5000, r10000, or r12000-series appliance
  • F5OS older than v1.8

Cause

This issue is due to Bug ID1785385, which affects the processing of ICMP monitor responses on BIG-IP tenants running on VELOS or rSeries with F5OS older than v1.8.

Recommended Actions

Workaround 1: Upgrade the VELOS host F5OS to version 1.8.0 or later, where this bug is resolved.
Workaround 2: If an immediate upgrade of F5OS is not possible, request and install an Engineering Hotfix (EHF) for BIG-IP 17.1.2.2 or later that addresses Bug ID1785385.
