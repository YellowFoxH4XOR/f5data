Topic

System memory requirements in BIG-IP ASM 12.x and later may exceed system memory capacity.

Description

In BIG-IP ASM 12.x and later, certain features and provisioning requirements may exceed available memory. This issue can prevent certain provisioning combinations and can cause low memory conditions that adversely affect functionality.

For example, when certain BIG-IP ASM features, such as DoS profiles and attack signatures, are configured on a BIG-IP system in a production environment, memory requirements may exceed provisioned memory on the system. This can result in excessive swap usage, degraded performance, and system malfunctions due to out-of-memory conditions.

Additionally, in BIG-IP 12.1.3 and later, due to memory constraints, you may not be able to provision the BIG-IP LTM and BIG-IP ASM systems together as is possible in previous versions. You can only provision the BIG-IP ASM system as Dedicated, which provisions the BIG-IP LTM system as None. If you attempt to provision both the BIG-IP LTM and BIG-IP ASM systems on these versions, the system may generate an error message similar to the following example:

01071008:3: Provisioning failed with error 1 - 'Memory limit exceeded. 4190 MB are required to provision these modules, but only 3966 MB are available.'

Note: The noted memory limit is specific to the amount of memory allocated for the BIG-IP system (either hardware device or virtual edition) and the required memory for the provisioned modules.

If you attempt to upgrade to BIG-IP ASM 12.1.3 or 13.x with both the BIG-IP LTM and BIG-IP ASM systems provisioned, the upgrade process completes but the configuration fails to load and the system generates the previous error message.

Recommendations

To avoid capacity issues in BIG-IP 12.x and later, you should provision the BIG-IP ASM module on systems with at least 8 GB or more of memory. The system permits provisioning both BIG-IP ASM and BIG-IP LTM as Nominal in an 8 GB Virtual Clustered Multiprocessing (vCMP) guest (dependent on configured BIG-IP ASM features). However, you should provision the BIG-IP ASM system as Dedicated to allocate the maximum available memory for the BIG-IP ASM system. For BIG-IP VE and vCMP guests, you should allocate 8 GB or more of memory to the BIG-IP instance before provisioning the BIG-IP ASM system.

Note: Because of kernel changes in version 13, swap reporting was changed from earlier versions.  Units with only 8GB of RAM will frequently show high swap under normal conditions, even after changes in provisioning.  A better indicator than the graphs as to readily freeable memory is the MemAvailable statistic in the /proc/meminfo output.

When a unit with 8GB of RAM (or less) has both ASM and APM provisioned, then LTM should be provisioned as None.  ASM and APM should be provisioned as Nominal.
Procedure is in K17173140: Setting LTM Provision NONE does not disable licensed LTM functionality.

Note: LTM None provisioning does not turn off licensed LTM functionality.
Note: If a unit is configured to use iApps that do enforce an LTM provisioning requirement, then they should be modified to remove this requirement before changing the LTM provisioning.
