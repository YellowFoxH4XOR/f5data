Known Issue

The iControl API allows a server object to be created without specifying an IP address, and further allows deletion of all box definitions to which an already-defined server object is associated. The resulting object is visible in the Configuration utility, but cannot be read by the mcpd process. As a result, the object is not written to the wideip.conf configuration file or synchronized among members of the BIG-IP GTM sync group, and cannot be deleted.

F5 Product Development tracked this issue as CR118614 and it was fixed in BIG-IP GTM 10.1.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

You can work around this issue by deleting the invalid objects. To do so, reboot the BIG-IP GTM system.

You can avoid this issue altogether by observing the following recommendations:

  • When creating a server object, ensure that you specify an IP address
  • Before deleting a box definition, ensure that each associated server object is associated with at least one other box definition
