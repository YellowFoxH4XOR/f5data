Description

After upgrading to version 14.1.4, the pool members monitored by an oracle DB healtchecks are marked as down

  • Oracle pool members are marked as unavailable in the GUI
  • Logs on /var/log/ltm indicate that the members are marked as down because they didn't successfully respond to the monitor during the configured threshold
The configuration of your monitor is similar to the following: 
ltm monitor oracle /Common/oracle-db-test {
    count 0
    database (DESCRIPTION=(ADDRESS=(PROTOCOL=tcp)(HOST=hostname.com)(PORT=15333))(CONNECT_DATA=(SERVICE_NAME=test))(SERVER=dedicated))
    debug yes
    defaults-from /Common/oracle
    interval 10
    password ***scrubbed***
    recv none    <------ No received string configured
    recv-column 1
    recv-row 1
    send "select status from v$instance"   <------- Send string configured
    time-until-up 0
    timeout 31
    username "TEST"
}

/var/log/DBDaemon-0.log shows similar to below

Environment

    • A 'send' string is set.
    • A 'receive' string is not set.

Cause

Bug ID 912517
 

Recommended Actions

Please follow this procedure:

  1. Take the oracle monitor out of the pool member configuration.
  2. Run the configured query in the monitor directly on to the database and confirm that the receive row and send row match up with what is configured in the monitor.
  3. Note the receive string in the query and configure it as received string on the monitor configuration in Local Traffic > Monitors > (Monitor's name)  or add a valid received string in the monitor configuration.
  4. Re-add the monitor to the pool member and test.
