Known Issue

This is the result of a known issue. Using dynamic updates through BIND on BIG-IP GTM can cause BIG-IP GTM to use excessive memory, and to eventually start using swap space.

Note: This issue occurs only in version 9.3.4 of BIND.

This issue, tracked by ISC BIND as RT17377, occurs due to a bug in the BIND software that causes a memory leak in the update prerequisite processing.

When you perform dynamic updates in BIND, the named process can grow larger than normal. This behavior eventually causes the BIG-IP GTM system to start using swap space as it pages memory. As a result, the BIG-IP GTM system performance drops, and you are required to restart the named process.

F5 Product Development is tracking this issue as CR99427.

Workaround

To work around this issue, you must restart the named process. To do so, enter the following command from the command line:

Important: F5 recommends that you perform this procedure during a maintenance window to prevent interruption to client requests or server updates.

bigstart restart named
