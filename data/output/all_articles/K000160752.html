Description

When tenants are created via API or ConfD CLI and later modified through the GUI, the referenced tenant image may unexpectedly go missing. This results in the image status showing as "Not present" in the WebUI, and attempts to provision or deploy the tenant leave it stuck in a "Pending" state. It results in the following error logged to velos.log (chassis partition) or platform.log (rSeries platform):

Environment

  • Product: F5OS (VELOS or rSeries)
  • Tenant creation via API or CLI (defaulting to "Configured" state)
  • Tenant configuration changes and provisioning or deployment via GUI

Cause

The API or ConfD CLI currently allows tenants to reference images that do not exist or are missing, bypassing the validation enforced by the GUI. As a result, subsequent GUI operations such as moving tenant to Provisioned state fails when the image is not present.

F5OS APIs are declarative and it's considered to be acceptable to pass in an invalid image name (or value, in general), as a result of which the behavior observed via API is to be expected.

This issue is caused by a product defect that are tracked under these two bug IDs:

  • ID2277317: To address an issue where the WebUI confusingly shows tenant to be in a "Pending" state.
  • ID2277237: To add a warning within CLI when a tenant is created referencing non-existent image.

Answer/Recommended Actions

The only workaround when encountering such a scenario is to re-upload the tenant image file, which blocks further migration and provisioning.

To avoid hitting the scenario in the first place, ensure that the desired tenant image is imported as well as properly referenced when creating the tenant via API or ConfD CLI.

Additional Information

To list the current tenant images available on the Velos chassis partition, use the following API Call:

GET /restconf/data/f5-tenant-images:images
