K000133416: HSL Logs through Management Port do not use Management IP as Source

Type
Support Solution
Published
2023-06-16
Updated
2025-12-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000133416

Description

You want to use the management network to send logs to Syslog servers through High Speed Logging (HSL), but HSL logs are being sent out with a self-IP address as the source IP rather than the management IP. Even with a proper management route and using management IP as local IP to bind HSL, logs are still sent from a Self IP.

For example:

sys log-config destination management-port remote-syslog-udp {
  ip-address 192.168.1.1  <<<=== Remote syslog server
  port 514
  protocol udp
}
sys management-route /Common/syslog_route {
    gateway 10.1.1.1
    network 192.168.1.1/32   <<<=== Remote syslog server
}

Environment

  • Remote Syslog servers
  • Management route configured

Cause

Existing syslog active connections for HSL are using a Self IP as the source IP even though the management route has been configured to syslog server through management interface.  Process errdefsd may need to be restarted to start using the Management IP.

Recommended Actions

  •  Please run this command to check and confirm if HSL logs are somehow sent out with Self IP as the source: 
    netstat -pan|grep -E 'syslog-ng|errdefsd'
Output example, where IP 192.168.1.3 is a Self IP and 192.168.1.1 is syslog server:

   udp       0      0 127.0.0.1:3794          0.0.0.0:*                           7871/errdefsd
   udp       0      0 192.168.1.3:50119       192.168.1.1:514         ESTABLISHED 7871/errdefsd
  • If it is confirmed that the existing active connection is using a Self IP, restart the errdefsd process:
    bigstart restart errdefsd
    Confirm if errdefsd is now sending HSL logs using the Management IP as the source: 
    netstat -pan|grep -E 'syslog-ng|errdefsd'
Output example, where IP 1.2.3.4 is the management IP now:

   udp       0      0 127.0.0.1:3794          0.0.0.0:*                           7871/errdefsd
   udp       0      0 1.2.3.4:50119           192.168.1.1:514         ESTABLISHED 7871/errdefsd

Additional Information

  • This can occur when the route to the remote syslog server is changed from egressing via the self-IP address to egressing via the management interface. When syslog-ng starts logging to the destination, a socket is created. The source address will be based on the route used to the destination. BIgIP by default uses tmm route if there is no management route is defined. When you create the route, the Linux kernel will start using it to send traffic to the destination via the management interface. However, it is still using the source address as self-ip from the existing socket.
  • Verify the connectivity to the syslog server over the management network using below commands: 
    ping -I <mgmt_ip> <destination_ip>
nc -vu -s <mgmt_ip> <destination_ip> <port>
