Description

Failed to upgrade from v14.x to v15.x, the tomcat process is continue restarting as per the following example.

"slot2 logger[31300]: tomcat can't start because /var is at 100%."

Environment

  • BIG-IP VIPRION platform.
  • Fail to upgrade from v14.x to v15.x.

Cause

This issue is cause by Bug ID 1045277: The /var partition may become 100% full requiring manual intervention to clear space.

Recommended Actions

  1. Login to the BIG-IP CLI.
  2. Access to the slot which is having the issue.

    ssh slot <number>

    For the example:

    ssh slot 2
     
  3. Check files inside /var/config/rest/.

    ls -lrt /var/config/rest
     
  4. If it has many files inside this directory, following the workaround on Bug ID 1045277: The /var partition may become 100% full requiring manual intervention to clear space.

    Important: This workaround is temporary, and may need to be periodically performed either manually or from a script.
    Impact of Workaround: While these steps are performed, the BIG-IP REST API will be temporarily inaccessible, and higher disk IO may be seen.

    Run the following commands, in sequence:

    bigstart stop restjavad
    rm -rf /var/config/rest/storage*.zip
    rm -rf /var/config/rest/*.tmp
    bigstart start restjavad
     
  5. Check if you still see the tomcat error message appear. If not, try to upgrade the BIG-IP again.

Additional Information

You may need to check further on the following articles if the issue still persists.

K14403: Maintaining disk space on the BIG-IP system
K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system
