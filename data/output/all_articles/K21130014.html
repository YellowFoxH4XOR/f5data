Topic

You should consider using this procedure under any of the following conditions:

  • You want to view information related to the high availability (HA) status of the VELOS system controllers.
  • You want to configure the system redundancy state setting on the system controller.
  • You want to manually trigger a failover of the system controllers.

Description

To enable HA for the VELOS chassis, you must install the chassis with two system controllers. For more information about how HA functions on the system controllers, refer to K19204400: Overview of the VELOS system architecture: High availability.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have a chassis administrator privileged account.
  • You must have access to the command-line interface (CLI) of the floating management IP address of the desired system.

Procedures

The following procedures provide ways to view the different aspects of the HA status, configure the system redundancy state setting, trigger a manual failover of the controllers, check the log file for failover event(s) and enable debug level logging for HA events:

  • View the system redundancy state setting
  • Configure the system redundancy state setting
  • Manually trigger a failover of the system controllers
  • Determine if a failover occurred
  • Enable debug level logging for HA events
  • View the status of the system redundancy state
  • View the status of the applied tests for active controller determination

View the system redundancy state setting

To view the system redundancy state setting in the CLI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. View the system redundancy state setting by entering the following command:

    show system redundancy state

    The following example output shows that the system redundancy state setting is set to auto and the currently active controller is controller-2:

    system redundancy state mode auto
    system redundancy state current-active controller-2

Configure the system redundancy state setting

To configure the system redundancy state setting in the CLI, perform the following procedure:

Impact of procedure: Depending on the state of your system controllers, changing the setting may trigger a failover of the system controllers.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. Enter the configuration mode terminal by entering in the following command:

    config

  3. Change the system redundancy state setting using the following command syntax:

    system redundancy config mode <auto/prefer-1/prefer-2>

    For example, to set the system redundancy state setting to prefer-1, enter the following command:

    system redundancy config mode prefer-1

    Note: By default, this setting is set to auto. For optimal performance, F5 recommends leaving this setting at the default value of auto.

  4. Save the change by entering the following command:

    commit

  5. Exit the configuration mode terminal by entering in the following command:

    exit

Manually trigger a failover of the system controllers

To manually trigger a failover of the system controllers in the CLI, perform the following procedure:

Impact of procedure: SSH connections to floating management IP address are terminated during the failover. If you logged in to the active controller using SSH prior to triggering the failover, you will need to reestablish your SSH connection to the newly promoted active controller.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. Trigger the manual failover of the controllers by entering the following command:

    system redundancy go-standby

    Important: You can only use this command when the system redundancy state setting is set to auto and the standby controller is available and healthy.

Determine if a failover occurred

The HA event logs for the system controllers are logged in the /var/log_controller/cc-confd file. To determine if a failover occurred, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the floating management IP address as the root user.
  2. Look for log messages related to role change by the maintain_confd process:

    grep maintain_confd /var/log_controller/cc-confd

    The following example log entries indicate a failover occurred from controller 2 to controller 1:

    <info> Oct 12 17:41:50 maintain_confd: role change detected 2 -> 1
    <info> Oct 12 17:41:50 maintain_confd: setting up ConfD as active
    <info> Oct 12 17:41:50 maintain_confd: ConfD is now Active

Enable debug level logging for HA events

To enable debug level logging for HA events related to the system controllers, perform the following procedure:

Impact of procedure: Enabling debug logging increases the resource usage on the system and may impact the system load.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. Enter the configuration mode terminal by entering in the following command:

    config

  3. Set the ha-state-machine database variable for the confd process to true by entering the following command:

    system dbvars config debug confd ha-state-machine true

  4. Save the change by entering the following command:

    commit

  5. Exit the configuration mode terminal by entering the following command:

    exit

  6. Disable the debug level logging by repeating steps 1 through 5 while replacing true with false in step 3:

    system dbvars config debug confd ha-state-machine false

View the status of the system redundancy state

To view the status of the system redundancy state of both controllers in the CLI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. View status of the system redundancy state by entering the following command:

    show system redundancy-details state hardware

    The following example output shows the existing status of the system redundancy state:

                LOCAL             LOCAL    PEER              PEER     
    CONTROLLER  ACTIVE   LOCAL    ACTIVE   ACTIVE   PEER     ACTIVE   
    NUMBER      DESIRED  HEALTHY  GRANTED  DESIRED  HEALTHY  GRANTED  
    ------------------------------------------------------------------
    1           true     true     true     false    true     false    
    2           false    true     false    true     true     true    

View the status of the applied tests for active controller determination

To view the status of the tests applied and the results from both controllers, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of the floating management IP address as the chassis administrator.
  2. View the status of the tests applied and the results from both controllers by entering the following command:

    show system redundancy-details state software | tab
