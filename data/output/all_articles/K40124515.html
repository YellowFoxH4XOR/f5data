Known Issue

The Configuration utility adds a .key extension to Secure Sockets Layer (SSL) key names.

This issue occurs when all of the following conditions are met:

  • You attempt to create an SSL certificate using the Configuration utility.
  • The SSL certificate name ends with a .key or .crt extension.

For example, if you attempt to create an SSL certificate using the name example.key, the BIG-IP system creates a key named example.key.key.

Impact

SSL certificate creation fails, but an SSL key is created with an extra .key extension appended to its name.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When viewed using the Traffic Management Shell (tmsh), SSL key names have an extra .key extension appended. However, in the Configuration utility, SSL key names do not have an extra .key extension.
  • When you attempt to create a new SSL certificate, a "Not Found" error appears in the Configuration utility.

Workaround

To work around this issue, you can delete and then recreate the key without the .key extension in the name. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To view the list of SSL keys, type the following command:

    list /sys crypto key

  3. Take note of any SSL key names with an extra .key extension.
  4. Log in to the Configuration utility.
  5. Navigate to System > File Management > SSL Certificate List.
  6. Select the check boxes for any key names that you noted in step 3.
  7. To delete the keys, click Delete and confirm.
  8. Click Create.
  9. Recreate the certificate using a name without a .key or .crt extension.
  10. Click Finished.
