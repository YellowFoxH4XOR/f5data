Topic

When a client initiates a connection to a server configured with an ECDH_RSA or ECDHE_RSA server certificate, the server presents a certificate that contains an RSA public key authorized for signing. During the session initiation (TLS handshake), the client proposes elliptical curve cipher suites and compression (ECC) in its ClientHello and the client and server negotiate to establish a transient, temporary, ephemeral key for data encryption. This is based on the server's ability to honor the client proposed ECC suites.

When using ECDHE_RSA, the server sends its ephemeral ECDH public key and a specification of the corresponding curve in the ServerKeyExchange message signed using the RSA private key corresponding to the public key in the server's certificate. The client then generates an ECDH key pair on the same curve as the server's ephemeral ECDH key and sends its public key in the ClientKeyExchange message. At this point, both the client and the server perform an ECDH operation using the resulting shared secret as the premaster secret.

When using ECDH_RSA, the server does not send a ServerKeyExchange message, because the server's public certificate contains all of the necessary keyring information required by the client to generate the premaster secret. The client generates an ECDH key pair on the same curve as the server's long-term public key and sends its public key in the ClientKeyExchange message. At this point, both the client and the server perform an ECDH operation using the resulting shared secret as the premaster secret.

Description

Typical client/server negotiation (SSL handshake) of a ECDH(E) RSA session appears as follows:

Client                               Server
ClientHello --------->
                                ServerHello
                                Certificate
                          ServerKeyExchange*
                         CertificateRequest
           <---------       ServerHelloDone
Certificate
ClientKeyExchange
CertificateVerify
ChangeCipherSpec
Finished  ----------->
                           ChangeCipherSpec
                       <---------- Finished
Application Data <-------> Application Data

*Message sent when using ECDHE_RSA, but not when using ECDH_RSA.

Server Key Exchange

The server selects elliptic curve domain parameters and an ephemeral ECDH public key corresponding to these parameters and conveys this information with the client in the ServerKeyExchange message. This message is used to convey the server's ephemeral ECDH public key (and the corresponding elliptic curve domain parameters) to the client.

Client Key Exchange

The client generates an ECDH key pair on the same curve as the server's long-term public key and sends its public key in the ClientKeyExchange message.

Actions of the receiver/client

The client verifies the signature and retrieves the server's elliptic curve domain parameters and ECDH public key from the ServerKeyExchange message.

Note: The server certificate includes the RSA public key.

Note: When the server cannot satisfy the client ECC requirements, the server does not choose a ECC cipher suite in the ServerHello message that is to be sent to the client. Depending on the other cipher suites proposed by the client and the ability to support these by the server, the lack of common cipher suites between the client and server can result in a fatal handshake failure.

Differences between ECDH_RSA and ECDHE_RSA

ECDH_RSA The server sends its long-term ECDH public key and a specification of the corresponding curve within the server's certificate.  

These parameters must be signed with RSA using the private key corresponding to the public key in the server's certificate.

ECDHE_RSA The server sends its ephemeral ECDH public key and a specification of the corresponding curve in the ServerKeyExchange message.

These parameters must be signed with RSA using the private key corresponding to the public key in the server's certificate and the RSA server certificate must contain authorized for signing.
