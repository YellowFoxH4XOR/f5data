Known Issue

When you import a FIPS-exported Secure Sockets Layer (SSL) key into the FIPS card of another BIG-IP device, the imported SSL key will have an incorrect publicExponent value.

Note: This issue does not affect FIPS cards on the older 6900 or 8900 platforms.

This issue occurs when all of the following conditions are met:

  • You have two or more BIG-IP systems in the same FIPS security domain.
  • The BIG-IP systems are not in a high-availability configuration.
  • You export a FIPS .exp key file on one of the BIG-IP systems.
  • You import the FIPs .exp key file on a second BIG-IP system.
  • You create a new corresponding SSL certificate on the second BIG-IP system.

Impact

This issue may impact the second BIG-IP system with the following behaviors:

  • SSL connections will fail if the corresponding SSL certificate is new, and you use the certificate in an SSL profile to process traffic.
  • Attempts to create an SSL profile will fail if you import the corresponding SSL certificate from another BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client SSL connections fail through the second BIG-IP system.
  • When comparing multiple BIG-IP systems, the publicExponents private key does not match.
  • When trying to create an SSL profile on the second BIG-IP system, you may view the following error message:

    01070317:3: profile /Common/ssl_test key and certificate do not match
