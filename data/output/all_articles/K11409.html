Known Issue

This is the result of a known issue. If a managed BIG-IP device is configured with a wildcard route (0.0.0.0), the Enterprise Manager can discover the device, but may mark the device as Impaired and log an error message to the /var/log/em file. An issue with the BIG-IP LTM affects the Enterprise Manager's ability to discern the status of the managed device.

Note: Routes are configured in the Network >> Routes screen of the BIG-IP Configuration utility, or by using the bigpipe route command.

In BIG-IP version 9.4.8 through 10.0.1, and 10.0.1 HF2, if Route Domains are not cofigured and a valid wildcard route is created using a 32-bit mask (0.0.0.0/255.255.255.255), the Enterprise Manager marks the device Impaired and logs the following error message:

discoveryd[1904]: 04010568:3: [08ad2bb0] Error found on device 192.168.1.1
(UID: 0): get change control info: iControl error: 'iControl::OperationFailed - primary code:2(0x2) secondary code: 0(0x0) string: BIGpipe static route query error: 01020036:3: The requested static route (none none) was not found. '

Note: If wildcard routes are created using a zero-bit mask (0.0.0.0/0.0.0.0), the Enterprise Manager is able to discern the device's status, and no error messages are logged.

In BIG-IP version 10.0.1 and 10.0.1 HF2, if Route Domains are configured and a valid wildcard route is created for any Route Domain, the Enterprise Manager marks the device Impaired and logs the following error message:

discoveryd[1904]: 04010568:3: [04c25bb0] Error found on device 192.168.1.1
(UID: 0): get change control info: iControl error: 'iControl::OperationFailed - primary code:0(0x0)
secondary code: 16908342(0x1020036) string: MCP call failed: MCP error 0x1020036: 01020036:3: The
requested static route (:: ::) was not found.'

This issue occurs regardless of the netmask or format used to specify wildcard routes for route domains. For example, all of the following valid route configuration formats result in Impaired status for the device:

Route 0.0.0.0%360/255.255.255.255 pointing to 10.136.64.1%360
Route 0.0.0.0%360/0.0.0.0 pointing to 10.136.64.1%360
Route 0.0.0.0%360/0.0.0.0%360 pointing to 10.136.64.1%360
Route 0.0.0.0%360/255.255.255.255%360 pointing to 10.136.64.1%360
'Type' = Default Gatway, Route Domain ID = 360, Gateway Address = 10.136.64.1%360

F5 Product Development tracked this issue as CR130922, and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, WOM, or Enterprise Manager release notes.

Workaround

For devices that do not utilize Route Domains, modify the wildcard route to use the 0.0.0.0 network mask.

For devices that utilize Route Domains, you must upgrade to BIG-IP version 10.1.0 for wildcard route support.
