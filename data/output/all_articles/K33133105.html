K33133105: High cpu due to rpm on VCMP guest

Type
Support Solution
Published
2021-08-24
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K33133105

Description

Rise in CPU can be observed on VCMP guests on one or more slots due to rpm. Top output will show output something like below:

  PID USER      PR  NI    VIRT    RES    SHR S  %CPU %MEM     TIME+ COMMAND
 5995 root      20   0  174248   1984   1140 R  13.3  0.0   2556:21 /bin/rpm -qa            <<<------------------
28225 root      20   0   70696   1908   1080 R  13.3  0.0   8560:02 rpm -q --queryformat %{version}-%{release} f5-rest-java-libs
27499 root      20   0  621836 289816   5856 S  10.0  5.0  70:31.69 /usr/lib/jvm/jre/bin/java -Djava.util.logging.manager=com.f5+
 6619 root      20   0   32396  16960  14236 R   6.7  0.3   1417:10 /usr/bin/csyncd
 

Environment

  • VCMP guest
  • High cpu on one or more blades. 
     

Cause

"rpm" is related to qkview generating process and seems failed but still consuming CPU resource.
Possible cause could be some process may be in odd state. 
 

Recommended Actions

  1. Check the md5sum to check the file integrity of /bin/rpm using below command and compare the value with some other VCMP guest of same version:
    Impact of procedure: Performing the following procedure should not have a negative impact on your system.
     # md5sum /bin/rpm
    Note: This command will show you the md5sum value. Run the same command on another VCMP host with same version and build as this device and compare the values. The values should match.
     
  2. Restart the blade on which CPU is showing high.  K44259537: Rebooting VIPRION vCMP host or guest systems
    Impact of procedure: Performing the following procedure should not have a negative impact for vCMP guest systems provisioned on more than one slot. This procedure may halt traffic processing for a single-slot vCMP guest provisioned on the rebooted blade. If you are unsure about the current vCMP guest slot count, you should perform this procedure during a scheduled maintenance period. This procedure should not have a negative impact on the vCMP host or other vCMP guests.
