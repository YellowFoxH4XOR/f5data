Description

The 'nslookup' command will try to resolve both 'A' and 'AAAA' resource records (rr) when there is no record type specified.

For example, the following command will send both type 'A' and type 'AAAA' DNS queries:

nslookup www.example.com <Listener IP address>


If there is only a matching type 'A' Wide-IP on the BIG-IP DNS system, the 'AAAA' query will either be processed by the internal BIND server (only intended for use by DNS Express) or timeout, depending on the configuration of the DNS Listener's DNS Profile.
If there is no such DNS domain name in BIND, then BIND will respond to the 'AAAA' query with 'NXDOMAIN'.
The nslookup result will show "NXDOMAIN" result, even though the type 'A' query was successfully received
For example:

nslookup  www.example.com
Server:         10.10.10.1
Address:        10.10.10.1#53

Name:   www.example.com
Address: 10.10.10.1
** server can't find www.example.com: NXDOMAIN

Environment

  • BIG-IP DNS/GTM
  • Listener
  • Wide IP
  • BIND

Cause

This issue is caused by Windows' nslookup behavior and your BIG-IP DNS system's configuration.

Recommended Actions

Use one of the following methods to resolve this.

 

Option 1:

Configure a type  'AAAA' Wide-IP for the same DNS FQDN and enable the "Return Code On Failure" option, found in the Advanced settings. Set RCODE to NOERROR.

Alternatively, the same setting can be enabled within tmsh, using the following command:

tmsh create gtm wideip aaaa <affected wideip> failure-rcode-response enabled

For example:

tmsh create gtm wideip aaaa wip.example.com failure-rcode-response enabled

 

Option 2:

If there is no IPv6 in your network, you may create an iRule similar to the following example and attach it to the inbound DNS Listener, to respond with 'NOERROR', instead of 'NXDOMAIN':

Note: You should not create the iRule from the DNS > GSLB > iRules page, otherwise you may encounter an error described in K66565108: Can't create iRule using DNS_RESPONSE event. You should create the iRule either from the DNS > Delivery > iRules page or the Local Traffic > iRules > iRule List page.

when DNS_RESPONSE {
    if {([DNS::header rcode] equals "NXDOMAIN") and (([string toupper [DNS::question type]] equals "A") or ([string toupper [DNS::question type]] equals "AAAA"))}{
        #log local0. "response rcode is: NXDOMAIN"
        DNS::header rcode NOERROR
    }
}

 

Option 3:

Assign a custom DNS profile to the BIG-IP's 'DNS Listener' (virtual server). In the custom DNS profile, set "Unhandled Query Action" to "No Error".
