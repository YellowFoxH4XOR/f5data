Description

Active System Controller had oom killer and failovered.

 /var/log/messages has similar log below at the time of the incident:

MMM DD HH:MM:SS controller-x kernel: registry invoked oom-killer: gfp_mask=0x201da, order=0, oom_score_adj=0
...
MMM DD HH:MM:SS controller-x kernel: Out of memory: Kill process 20353 (etcd) score 1045 or sacrifice child
NOTE: sacrificed processes can be any other process than etcd

This caused inaccessibility to partition, and some of blade was not joined to cluster, and all tenants which were on the blade failed to join to cluster were rebooted.

There were thermal fault events on all blades.

 

Environment

  • F5OS-C
  • Controller failover
  • Tenant lost ha connection through management IP

 

Cause

  • Bug ID 1629257
  • Bug ID 1629277

Memory leak caused active controller failover, this triggered K000148655: [F5OS-C] Controller failover caused tenant failover

 

Recommended Actions

Monitor memory usage, and in maintenance window restart the services

To check the memory usage, on Controller CLI in bash, run

docker container stats platform-diag

CONTAINER           CPU %               MEM USAGE / LIMIT       MEM %               NET I/O             BLOCK I/O           PIDS
platform-diag       0.10%               10.16 GiB / 31.29 GiB   0.03%               11 GB / 4.71 GB     0 B / 8.19 kB       18

If the memory usage is more than 10GB best to restart by

docker container restart platform-diag

NOTE: There should have no impact to any tenants. The diag-agent service performs diagnostic activities such as Power-On Self-Test, On-Line diagnostics, Off-Line diagnostics on the system.
