Description

Purpose of this article is to show how to configure statistics retention on BIG-IQ Centralized Management.

Raw data statistics are generated in real time and stored in what are called tl0 indices. Saving real time data is very demanding in storage so we need to aggregate the real data to save space in the long term. In BIQ we aggregate data in 3 additional levels:

tl0: raw data, no aggregation

tl1: aggregation of real time data in hours (1 minute samples).

tl2: aggregation of hourly data in days (1 hour samples).

tl3: aggregation of daily data in months (1 day samples).

All the statistics are stored at ElasticSearch indices that are kept on /var partition of DCD nodes.

Important: THE DEFAULT CONFIGURATION USES retention values which does not necessarily meet the storage needs of your environment. Stats could fill up /var partition on DCD nodes and break up stability of the cluster depending of the amount of stats generated by the devices monitored by the BIG-IQ.

Environment

  • BIG-IQ statistics data collection

Cause

You want to modify the retention policy for statistics data collection

Recommended Actions

Go to System > BIG-IQ DATA COLLECTION > BIG-IQ DATA COLLECTION CLUSTER > Configuration > Statistics Data Collection  and click in Configure Retention.
You can tune different values according to you retention needs but values have a minimum to allow aggregation. Aggregation task is done by CM every hour.

If required re-size /var partition by referring to:
K30902515: Resizing the /var, /var/log, or /shared file system on a BIG-IQ Virtual Edition

Additional Information

Once data is aggregated to a higher level we delete it once the retention period expires.

By default we store 10 hours of raw data (tl0 indices), 168 hours (7 days) of 1 minute samples (tl1 indices), 31 days of hourly data (tl2 indices), and 12 months of daily data (tl3 indices). You can also modify the number of days that events are retained and the amount of days that traffic captures are kept.

Since 8.2 If you want to keep different retention policies per type of data you can do that. Use the values under Group Properties to configure custom values.
