Known Issue

This is the result of a known issue. BIG-IP GTM systems running version 9.4.2 or 9.4.3 continually mark the standby BIG-IP LTM system in a redundant pair down and then back up every 60 seconds. This issue occurs because the Big3d.CertificateDepth BigDB variable is present on BIG-IP version 9.4.2 and higher systems, but absent on BIG-IP version 9.4.1 or earlier systems. For example, when the BIG-IP GTM version 9.4.2 system copies the big3d daemon to the BIG-IP LTM version 9.4.1 or earlier system, iQuery communication does not function properly between the systems, and the BIG-IP GTM system will continually mark the standby BIG-IP LTM system down and then up.

F5 Networks Product Development tracked this issue as CR87940 and it was fixed in BIG-IP GTM 9.4.4. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF2 issued for BIG-IP version 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by manually adding the Big3d.CertificateDepth BigDB key to the /config/BigDB.dat file of both BIG-IP LTM systems in the failover pair. To do so, perform the following procedure:

Important: This procedure requires you to shut down the BIG-IP services, which will interrupt traffic. F5 Networks recommends performing this procedure on the standby BIG-IP or during a maintenance window.

Important: You must perform this procedure from the console or management interface. If you are connected to the BIG-IP through a self IP address and perform this procedure, you will lose connectivity to the BIG-IP system.

  1. Log in to the BIG-IP LTM command line using the console or management interface.
  2. Change directories to the /config directory by typing the following command:

    cd /config
  3. Back up the original BigDB.dat file by typing the following command:

    cp BigDB.dat BigDB.dat.SOL8163
  4. Shut down the BIG-IP services by typing the following command:

    bigstart shutdown
  5. Change the file permissions for the BigDB.dat file to read/write by typing the following command:

    chmod 666 BigDB.dat
  6. Using a text editor, edit the BigDB.dat file.
  7. Add the following entry to the bottom of the file:

    [Big3d.CertificateDepth]
    default=0
    type=integer
    realm=local
    min=0
    max=9
    display_name=Big3d.CertificateDepth
  8. Save the BigDB.dat file.
  9. Restart BIG-IP services by typing the following command:

    bigstart startup
