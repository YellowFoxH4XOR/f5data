Description

HTTP status code response string returned by CURL command does not work for HTTP2 monitor receive string

Environment

  • BIG-IP configured with custom HTTP2 monitor specifying status code receive string based on CURL output.

Cause

CURL using HTTP2 precedes response code (eg: "200") with "HTTP/2.0". ie: "HTTP/2.0 200".

The correct receive string configured in monitor should be "200 OK".

Recommended Actions

Collect tcpdump with with the "--f5 ssl" option to enable decryption by wireshark/tshark and configure monitor receive string with the ":status:" header string (ie; "200 OK").

Additional Information

With HTTP/1.1, the returned string is the same as that shown by CURL. ie: "HTTP/1.1 200 OK".

The same behaviour applies to other response codes, eg: "401 Unauthorized" is shown by CURL as "HTTP/2.0 401".
