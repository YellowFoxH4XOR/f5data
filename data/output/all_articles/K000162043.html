Description

When deploying the F5 Container Ingress Services (CIS) controller in an OpenShift cluster using NodePort mode, all CIS-managed objects (Virtual Servers, Pools, Policies, Monitors) were correctly created in the intended partition and route domain, but node objects were always created in the /Common partition. The customer sought confirmation if this was expected behavior and whether any workaround existed to place node objects in a custom partition.

Environment

• F5 Container Ingress Services (CIS) version 2.20.4

• OpenShift cluster integration

• NodePort mode (--pool-member-type=nodeport)

• Custom partition (CISPOC) with route domain 3460

• All CIS-managed objects except nodes intended for the custom partition

Cause

The root cause is a product design limitation: In NodePort mode, CIS uses AS3 with shareNodes: true hardcoded, which forces all node objects to be created in the /Common partition for multi-tenancy support. The --share-nodes=false parameter is only valid for ClusterIP mode and is ignored in NodePort mode. As a result, there is currently no supported method to place node objects in a custom partition when using NodePort mode.

Answer/Recommended Actions

  • This is expected and by-design behavior in NodePort mode.
  • No configuration change or workaround is currently available to alter node object placement in NodePort mode.
  • ClusterIP mode with --share-nodes=false would allow node objects in a custom partition, but is incompatible with non-default route domains and some network architectures.
  • F5 has an active Request for Enhancement (RFE) to support node object creation within the designated partition in NodePort mode. Monitor future CIS and AS3 releases for updates on this enhancement

Additional Information

  • The  --share-nodes parameter only applies to ClusterIP mode. In NodePort mode, it is ignored and node objects will always be created in /Common.
  • This behavior is part of the AS3 multi-tenancy design and is not a misconfiguration.
  • There is currently no ETA for the RFE to address this limitation.
  • CIS documentation reference: https://clouddocs.f5.com/containers/latest/userguide/config-parameters.html
