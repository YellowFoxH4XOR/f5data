K000139354: Adjusting Envoy TCP Timeout in Aspen Mesh

Type
Support Solution
Published
2025-03-31
Updated
2025-03-31
Applies to
  • Aspen Mesh: 1.14, 1.11
Source

Description

In Aspen Mesh, Envoy acts as a proxy that handles traffic routing and connection management. By default, Envoy enforces a request timeout of 10 seconds for TCP requests. If an application has an endpoint that requires more than 10 seconds to respond, this default timeout can cause request failures. This article explains how to configure Istio to increase the timeout limit to accommodate longer-running requests.

Environment

  • Aspen Mesh 1.11.X 1.14.X
  • Istio Destination Rule
  • Envoy

Cause

Envoy enforces a default timeout of 10 seconds for TCP requests. When an endpoint takes longer than 10 seconds to respond, Envoy will terminate the connection, leading to failed requests. This behavior can affect applications requiring extended processing time for certain operations.

Recommended Actions

To increase the timeout, you can configure either a per-service DestinationRule or modify the global meshConfig:

Option 1.  Modify Timeout per Service with DestinationRule.

                 Apply the following DestinationRule to extend the timeout for a specific service:

apiVersion: networking.istio.io/v1alpha3
kind: DestinationRule
metadata:
  name: example
spec:
  host: example-svc.example.com
  trafficPolicy:
    connectionPool:
      tcp:
        connectTimeout: 12s

Option 2.   Modify Global Timeout via meshConfig.

                   For a global timeout change, add the following meshConfig at the Aspen Mesh override values file:

meshConfig:
  connectTimeout: 12s

        And then upgrade your control plane(istiod) with helm:

helm upgrade istiod manifests/charts/istio-control/istio-discovery \
    --namespace istio-system \
    --values <aspenMeshOverrideValuesFilename>

Additional Information

Use istioctl to check if the timeout configuration is applied correctly:

istioctl pc clusters <podName>.<namespace> --fqdn <serviceFqdn> -o json | grep connectTimeout
