Description

Starting with Cisco ISE (Identity Services Engine) version 2.7 (possibly starting in version 2.6), the User-Agent HTTP Header is required in all HTTP requests sent to the ISE servers. Without a User-Agent HTTP Header configured in any HTTP or HTTPS Health Monitors, those Monitor Health-Checks will fail with a "500" "Internal Server Error" due to the missing User-Agent HTTP Header.

Environment

Relevant environmental factors:

  • BIG-IP supporting LTM functionality
  • Cisco ISE servers as Pool-members with HTTP or HTTPS Health Monitor applied.

Cause

Cisco made security changes to their ISE product code in version 2.7 (possibly 2.6; but was not present in 2.4; there is no 2.5) that now Requires a User-Agent HTTP Header be included in any HTTP requests sent to the ISE servers.

Recommended Actions

Modify any HTTP or HTTPS Health Monitors assigned to Cisco ISE Pools so that their Send String value includes User-Agent: in the string.

  1. Pull up the given HTTP Health Monitor
  2. Edit the Health Monitor's Send String so that the string includes User-Agent:, as shown in the example Send String shown below:
    GET /index.html HTTP/1.1\r\nHost: \r\nUser-Agent: \r\nConnection: Close\r\n
  3. Then save the changes using the Update button.

Additional Information

Cisco Identity Services Engine 2.7
