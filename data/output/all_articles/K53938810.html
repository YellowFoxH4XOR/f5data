Known Issue

Custom SNMP v1 or v2c community views may not be accessible.

This issue occurs when all of the following conditions are met:

  • You define multiple v1 or v2c SNMP views with the same community name.
  • You attempt to access one of the community views by using an SNMP application, such as snmpwalk.
For example, the following configuration contains two SNMP community views that use the same 'test1' community name. When using an SNMP application, such as snmpwalk, users can access only the first definition of this example configuration:

communities {
        comm-public {
            access ro
            community-name public
            description none
            ipv6 disabled
            oid-subset none
            source default
        }
        itest1_1 {
            access ro
            community-name test1
            description none
            ipv6 disabled
            oid-subset .1.3.6.1.2.1.1.9.1.2
            source localhost
        }
        itest1_2 {
            access ro
            community-name test1
            description none
            ipv6 disabled
            oid-subset .1.3.6.1.2.1.1.9.1.3
            source localhost
        }
    }

Impact

SNMP community views may not be accessible.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to access the affected SNMP view, the system reports an error message similar to the following example:

    SNMPv2-MIB::sysORID.8 = No more variables left in this MIB View (It is past the end of the MIB tree)
  • Users cannot access custom SNMP community views.
