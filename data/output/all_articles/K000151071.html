Description

This article outlines how to configure an F5 BIG-IP system to restrict HTTP requests based on the value of the Origin header. By allowing only specific, approved origin domains, administrators can enhance application security and prevent unauthorized cross-origin requests. This can be achieved using either Local Traffic Manager (LTM) policies or iRules.

 

Environment

  • Web applications requiring cross-origin resource sharing (CORS) protection
  • Use cases involving the restriction of client-originating domains to trusted sources only

 

Cause

Restricting access based on the Origin header is a key security measure in scenarios where applications must only accept requests from certain domains. Without such restrictions, unauthorized or malicious domains could make cross-origin requests, potentially leading to data exposure or security breaches.

 

Recommended Actions:

Note: Implement either via an LTM policy or an iRule.

  1. LTM Policy Implementation ( Preferred)

LTM policies are generally preferred for handling HTTP header-based conditions due to their performance advantages and ease of management.

  1. Create the LTM Policy
    • Go to Local Traffic > Policies > Create
    • Enter a policy name and set Strategy to First Match

       2. Add Matching Conditions

    • Under Rules, add a condition for the Origin header
    • Set Match Type to Contains
      Use the regex:
      • ^(https?://.*\.exampledomain\.com$)

        3. Add Actions

    • If the condition does not match, configure the policy to Reject the request
    • Optionally, respond with 403 Forbidden or redirect to a custom error page

        4. Apply the Policy

  • Attach the policy to the desired virtual server:
    • Local Traffic > Virtual Servers > [Your Virtual Server] > Resources > Policies > Attach

 

        2. Using iRule for Origin Validation (Less Preferred)

Note: An iRule can be used when additional logic or customization is required.

Example iRule Script:

 

when HTTP_REQUEST {

   set origin_header [HTTP::header "Origin"]

   if { $origin_header ne "" && !([string match -nocase {*exampledomain.com} $origin_header]) } {

       HTTP::respond 403 content "Unauthorized Cross-Origin Request"

       return

   }

}

 

 

Important:

  • The iRule checks whether the Origin header is present and whether it contains exampledomain.com
  • If the request originates from an unapproved domain, it returns a 403 Forbidden response

 

Impact of Workaround: 

Validate changes in a staging or non-production environment

Ensure only approved origins are allowed, and others are correctly blocked
