K000149679: REST API calls are failing after upgrade to 17.1.2

Type
Support Solution
Published
2025-02-06
Updated
2025-06-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000149679

Description

 

After upgrading to 17.1.2, users authenticating via iControlREST start to receive 400 responses with the message "user <username> has reached maximum active login tokens", preventing them from sending requests. This starts to happen after the user has requested 100+ tokens since the BIG-IP system booted up.

Environment

  • Recently upgraded BIG-IP system to 17.1.2 or above
  • Affected user is getting 400 responses from iControlREST token endpoint
  • Response message is "user <username> has reached maximum active login tokens"

Cause

This is due to ID1787517. iControlREST auth tokens are not getting deleted after they expire.

Auth token expiration is set to 1200 seconds by default. This is controlled by the "timeout" value in the token response. The maximum timeout value allowed for a token is 36000 seconds (10 hours).

After a token expires, the AuthTokenWorker should send a message to mcpd to delete the relevant token file located in /run/pamcache, and log the following message in the restjavad.0.log file:

[I][425][06 Feb 2025 16:45:55 UTC][8100/shared/authz/tokens AuthTokenWorker] Message sent to mcpd to delete the token file.

If you do not see the above log message written to the log file on a regular basis when using iControlREST tokens, you may be affected by ID1787517.

Note: Some actions may still trigger this log message in an affected version, such as a user clicking 'logout' in the WEBUI after a rest token has been generated for the user's WEBUI session.

 

Another way you can verify if this affects you is by checking the status of all the tokens in /var/pamcache for the affected user. Replace <affecteduser> in the following command with the user who is having the issue. This command will query iControlREST for each token assigned to this user, so its recommended to perform this while the system is not under heavy load and during a maintenance window.:

AFFECTEDUSER=<affecteduser>; for i in $(find /run/pamcache -regextype posix-extended -type f -regex '/run/pamcache/[A-Z0-9]{26}' -print); do if [ "$AFFECTEDUSER" == "$(head -n1 $i)" ]; then TOKEN=$(echo $i | awk -F/ '{print $4}'); echo -e "Modified: $(date -r $i)\t\tAbs path: $i\t\tUser: $AFFECTEDUSER\t\tStatus: $(curl -sk https://localhost/mgmt/shared/authz/tokens/$TOKEN -H "X-F5-Auth-Token: $TOKEN" | jq -r ".message")"; fi; done

This will print the last modified date of the token file, the absolute path to the token, the user its assigned to, and the status of the token. Example output:

Modified: Thu Feb  6 07:07:15 PST 2025          Token file: /run/pamcache/5ZL6WPNEXLU2HWPBPFD3N7MGVD            User: new_admin         Status: X-F5-Auth-Token has expired.
Modified: Thu Feb  6 07:07:14 PST 2025          Token file: /run/pamcache/GDB5DH4OJ3O2S2E2BIAHBV62DH            User: new_admin         Status: X-F5-Auth-Token has expired.
Modified: Thu Feb  6 07:07:14 PST 2025          Token file: /run/pamcache/3PCJ7EAMKW6RMPNJ7OPRDUCAJU            User: new_admin         Status: X-F5-Auth-Token has expired.
Modified: Thu Feb  6 07:07:14 PST 2025          Token file: /run/pamcache/6XBIY5SDAIMAFQCJW2QE7NVBCC            User: new_admin         Status: X-F5-Auth-Token has expired.
Modified: Thu Feb  6 07:07:14 PST 2025          Token file: /run/pamcache/GITJCRJQUDD64VUHCNZHHCHPML            User: new_admin         Status: X-F5-Auth-Token has expired.

If the status is 'null', it means there was no message object in the json response, this is normal if the token is still valid.

If the status is 'X-F5-Auth-Token has expired', then the token has expired. Review the modification date. If it is significantly past the token timeout value (1200s by default), then you are affected by ID1787517.

Recommended Actions

Upgrade to a version that contains a fix for ID1787517. If there is no version available that contains a fix, open a support case to request an EHF for ID1787517.
