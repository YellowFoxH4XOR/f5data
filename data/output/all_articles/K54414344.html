Description

You noticed that UDP traffic persists to a node, even though it was removed from the configuration or is down.

Environment

  • UDP Virtual Server 
  • High connection timeout
  • Constant traffic

Cause

When UDP connections are brief, they never actually time out so they persist to one server, even if the node is disabled or forced offline. Additionally, by default, these UDP sessions are written to the connection table so they must be deleted for the traffic to use the new configuration.

Recommended Actions

To ensure the BIG-IP immediately routes traffic according to recent changes to UDP configurations, there are a couple options. Either way, the existing connections must be deleted per the instructions below.

  1. On the UDP profile, enable Datagram LB so a load balancing decision is made for each packet and this traffic is never added to the connection table.
    • K3605: Configuring the BIG-IP system to load balance UDP packets individually
  2. In the Pool settings, enable "action on service down" so connections are reset when a node is disabled/offline. Traffic is redirected to the new pool member.
    • K15095: Overview of the Action On Service Down feature

Regardless of the option above, the existing connections must be deleted so the traffic routes to the new node.

  • To view current connections:
    tmsh show sys connection cs-server-addr <virtual server IP> > /var/tmp/cs-server-addr-curr-conns.txt
    tmsh show sys connection ss-server-addr <pool member IP> > /var/tmp/ss-server-addr-curr-conns.txt
  • To delete these connections:
    tmsh delete sys connection cs-server-addr <virtual server IP>
    tmsh delete sys connection ss-server-addr <pool member IP>
