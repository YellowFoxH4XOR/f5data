Known Issue

The BIG-IP system may leak file descriptors when performing remote Terminal Access Controller Access-Control System Plus (TACACS+) authentication.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured to use remote TACACS+ authentication for administrative access.
  • The BIG-IP system is accessed for administrative connections, such as the BIG-IP Configuration utility, iControl, or iControl REST.
  • The BIG-IP system is running an affected version. For version 11.2.1, only HF3 or later hotfixes are affected.

The BIG-IP system fails to release file descriptors when administrative access is authenticated using a remote TACACS+ authentication. Repeated automated access, using iControl for example, can lead to file descriptor exhaustion and authentication failures.

Impact

Administrative access using remote authenticated accounts may not be possible.

Note: The root account always uses local authentication and is not affected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H429388 on the Diagnostics > Identified > High screen.
  • If the leak is allowed to accumulate to the point that no file descriptors are available, administrative access using remote authenticated accounts is no longer possible. This also includes access from secure shell (SSH) and console.
  • You may observe an error message in the /var/log/secure file. The error message may appear similar to the following example:

    httpd[###]: PAM [error: /lib/security/pam_bigip_authz.so: cannot open shared object file: Too many open files]. This can eventually lead to lack of access to the BIG-IP system from all but the root account.

Workaround

If the BIG-IP system has reached the state where you are unable to authenticate, you can recover from this issue by restarting the httpd service. To do so, perform the following procedure:

Impact of workaround: Access to the BIG-IP Configuration utility will not be available while the httpd service restarts.

  1. Log in to the BIG-IP command line using the root account.
  2. Restart the httpd service by typing the following command:

    bigstart restart httpd

To work around this issue, you can configure the BIG-IP system to use local authentication or a remote authentication method other than TACACS+. To configure the BIG-IP system to perform local authentication, perform the following procedure:

Impact of workaround: The BIG-IP system will require local user accounts for administrative access.

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Users.
  4. Click Authentication.
  5. Click Change.
  6. From the User Directory menu, select Local.
  7. Click Finished.
