Known Issue

This is the result of a known issue. The LCD display of a BIG-IP system may not report the following system states:

  • Unit going active
  • Unit going standby

This behavior occurs when the front panel display daemon (fpdd) is restarted. Once in this condition, the system will not log the system state until the alertd process is restarted.

This behavior may cause a circumstance in which one system in a high availability pair correctly reports messages of entering an active or standby state, but the partner system does not report those messages. Additionally, this behavior may cause the status LEDs to function incorrectly.

F5 Product Development tracked this issue as ID 207593 (formerly CR120551) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, PSM, Link Controller, WebAccelerator, or WOM release notes.

This issue still exists as ID 327744 (formerly CR120551-1) for the BIG-IP version 9.4.x software branch, and ID 329762 (formerly CR120551-2) for the BIG-IP version 10.0.x software branch.

This issue has been fixed in a hotfix in BIG-IP version 10.0.1. To request the hotfix, contact F5 Technical Support, referencing this Solution number and the associated ID numbers.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Important: Due to a different issue, certain platforms may experience the behavior described in this Solution even if they are running BIG-IP version 10.1.0. For more information, refer to K11050: The BIG-IP system does not display the unit state on the LCD.

Workaround

You can work around this issue by restarting the alertd process to allow the system to correctly log and reconnect with the fpdd process. This action will allow the information to be displayed on the LCD.

To restart the alertd process, enter the following command at the command line and then press Enter:

bigstart restart alertd

Note: BIG-IP SAM users may continue to see the Initializing message on the LCD display even after restarting the alertd process. This issue is cosmetic and can be safely ignored.
