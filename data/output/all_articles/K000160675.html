Description

The customer was unable to successfully run the F5 system scanner on a BIG-IP instance while investigating CVE-2025-53521. The scanner process may be repeatedly terminated with "Killed" errors due to out-of-memory (OOM) conditions. There may be also some logs visible in the Diagnostic Section in the qkview or /var/log/kern.log.

The following daemons invoked oom-killer: 'merged', 'icrd_child', 'java', and 'systemd-journal'

Environment


  • BIG-IP


Cause


Insufficient memory allocated to management processes on the BIG-IP VE. Running multiple resource-intensive modules (APM and LTM) without increasing management memory allocation causes the Linux OOM killer to terminate the F5 system scanner process during execution.


The scanner requires between 140 MB–850 MB of memory to complete, which exceeds available management memory when multiple large modules are provisioned at default settings.


Answer/Recommended Actions


  1. Increase management memory allocation by setting the MGMT resource provisioning to "Large" in the Configuration utility.
  2. If the issue persists, further increase memory allocation using the following commands:
    tmsh modify /sys db provision.extramb value 1024
    tmsh modify /sys db provision.tomcat.extramb value 128
    tmsh modify sys db provision.restjavad.extramb value 500


Note: Changing these values will restart TMM and other services; expect a brief service interruption.


After increasing memory, rerun the F5 system scanner to confirm successful completion.
