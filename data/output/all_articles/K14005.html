Known Issue

The TMM process may crash when the BIG-IP resolver cache receives a slow response or no response to recursive queries. This issue occurs when all of the following conditions are met:

  • A virtual server is associated with a DNS profile.
  • The DNS profile is configured with the Use BIND Server on BIG-IP setting set to disabled and a DNS Cache type of Resolver.
  • The BIG-IP resolver cache receives slow or no response to its recursive queries.

When the BIG-IP resolver cache performs a recursive lookup, and there is either no response or a slow response, the BIG-IP system has to increase its memory usage to keep up with the incoming DNS requests. As a result, the system memory utilization increases over time and eventually cause the TMM process to crash due to memory exhaustion.

Impact

The BIG-IP system fails to respond to client DNS queries. If configured as part of a high availability system, the BIG-IP system may temporarily fail to process traffic and fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process crashes and produces a core file in the /var/core directory.
  • The BIG-IP system fails to respond to the client DNS queries.
  • The BIG-IP system reports an error message in the /var/log/ltm file, similar to the following example:

    comm_point_send_udp_msg reports failure
