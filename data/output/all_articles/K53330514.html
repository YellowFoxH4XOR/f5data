Known Issue

For Amazon Web Services (AWS) high availability (HA) instances in the same availability zone (AZ), two or more failover objects sharing the same IP address may not fail over.

This issue occurs when all of the following conditions are met:

  • You have HA failover configured between AWS instances in the same availability zone.
  • You have the same IP address configured for two or more objects, such as virtual addresses, self IPs, NATs, or SNATs, in the same traffic group.

Impact

The affected failover objects in the traffic group are not transferred to the active BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system fails to reattach floating addresses to the active device's interface during failover and logs an error message similar to the following example to the /var/log/ltm file:

    err logger: /usr/libexec/aws/aws-failover-tgactive.sh (traffic-group-1): Failed to reassign some or all address(es): 192.168.1.1 192.168.1.1 on interface <eni address>

    • Resolution

    Workaround

    To work around this issue, you can modify the configuration to use unique IP addresses for conflicting objects. To do so, perform one of the following procedures:

    • Modifying a SNAT IP address
    • Modifying an IP address in a SNAT pool
    • Modifying an IP address in NAT
    • Modifying an IP address of a virtual server
    • Modifying a self IP address

    Modifying a SNAT IP address

    Impact of workaround: Modification of the affected configuration may disrupt services that are already in use. F5 recommends that you perform this procedure during a scheduled maintenance window for the affected BIG-IP system.

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Address Translation > SNAT List.
    3. Click the name of the SNAT Pool you want to modify.
    4. For Translation, modify the IP address.
    5. Click Update.

    Modifying an IP address in a SNAT pool

    Impact of workaround: Modification of the affected configuration may disrupt services that are already in use. F5 recommends that you perform this procedure during a scheduled maintenance window for the affected BIG-IP system.

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Address Translation > SNAT Pool List.
    3. Click the name of the SNAT you want to modify.
    4. For Member List, click the IP address you want to modify and click Edit.
    5. For IP Address, modify the address.
    6. Click Add.
    7. Click Update.

    Modifying an IP address in NAT

    Impact of workaround: Modification of the affected configuration may disrupt services that are already in use. F5 recommends that you perform this procedure during a scheduled maintenance window for the affected BIG-IP system.

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Address Translation > NAT List.
    3. Click the name of the NAT you want to modify.
    4. For Origin Address, modify the IP address.
    5. Click Update.

    Modifying an IP address of a virtual server

    Impact of workaround: Modification of the affected configuration may disrupt services that are already in use. F5 recommends that you perform this procedure during a scheduled maintenance window for the affected BIG-IP system.

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Virtual Server List.
    3. Click the name of the virtual server you want to modify.
    4. For Destination Address/Mask, modify the IP address.
    5. Click Update.

    Modifying a self IP address

    Impact of workaround: Modification of the affected configuration may disrupt services that are already in use. F5 recommends that you perform this procedure during a scheduled maintenance window for the affected BIG-IP system.

    • Creating a new self IP address
    • Replacing the previous self IP address in all instances where the previous self IP address is configured
    • Deleting the conflicting self IP address

    For more information about self IP addresses, refer to the Self IP Addresses chapter of the BIG-IP TMOS: Routing Administration manual.

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

    The new self IP address that you create to replace the existing one must match the private IP address assigned to the AWS instance network interface. For more information, refer to Amazon EC2 Instance IP Addressing.

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

    Creating a new self IP address

    Take note of the configuration of the existing self IP address and create the new self IP address with the same settings.

    1. Log in to the Configuration utility.
    2. Navigate to Network > Self IPs.
    3. Click Create.
    4. Enter the new network information, including Name, IP Address, and Netmask as appropriate.
    5. Configure the remaining settings using the same settings as the previous self IP address.
    6. Click Finished.

    Replacing the previous self IP address in all instances where the previous self IP address is configured

    You cannot delete a self IP address if it is already in use in a configuration, such as configuration synchronization (ConfigSync), failover network, and so on. If necessary, use the Configuration utility to navigate to the appropriate configuration and replace the existing self IP with the new one.

    Deleting the conflicting self IP address

    When you have replaced the previous self IP address with the new self IP address in all configured instances, you can delete the previous self IP address using the following procedure.

    1. Log in to the Configuration utility.
    2. Navigate to Network > Self IPs.
    3. Select the check boxes next to the previous self IP address and click Delete.
    4. To confirm removal, click Delete.
