K000162062: Blade Config Load Failure Due to AFM Policy iRule Reference

Type
Support Solution
Published
2026-07-02
Updated
2026-07-02
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.3, 17.1.1, 17.1.0, 17.1.X, 17.1.2
Source
https://my.f5.com/manage/s/article/K000162062

Description

Configuration fails to load on a newly promoted Viprion blade due to an AFM policy referencing an iRule.

Example configuration that can cause the issue:

/config/bigip.conf

ltm rule /Common/test_irule {
    when FLOW_INIT {
        log local0. "afm test irule"
    }
}

/config/bigip_base.conf

/config/bigip_base.conf
security firewall policy /Common/fw_policy_1 {
    rules {
        rule1 {
            action accept
            ip-protocol any
            irule /Common/test_irule
        }
    }
}

The following messages may appear in /var/log/ltm:

slot2/viprion.lab err mcpd[42962]: 01070830:3: The iRule (/Common/test_irule) cannot be deleted because it is in use by a fw_rule (rule1) in Policy (/Common/fw_policy_1).
slot2/viprion.lab emerg load_config_files[33156]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- 01070830:3: The iRule (/Common/test_irule) cannot be deleted because it is in use by a fw_rule (rule1) in Policy (/Common/fw_policy_1).
slot2/viprion.lab err mcpd[42962]: 01070422:3: Base configuration load failed.

Environment

  • Viprion chassis with multiple blades
  • Firewall (AFM) policy referencing an iRule
  • Primary blade failure, leading to promotion of a new blade

Cause

When a new blade is promoted to primary, it may attempt to reload the base configuration. During this process, an AFM policy attempts to delete or validate an iRule that is still referenced. This is not a valid procedure and it results in configuration load failure. You can track this issue with ID2326237.

Recommended Actions

Run the following command to load the configuration:

tmsh load sys config
