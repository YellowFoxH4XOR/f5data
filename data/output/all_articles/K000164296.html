K000164296: SSL Handshake failed with Alert (Level: Fatal, Description: Unknown CA)

Description

TLS handshakes fail with a BIG-IP LTM HTTPS virtual server that uses a Client SSL profile. The BIG-IP logs show the handshake failing after an alert 48 is received from the client:

warning tmm3[20873]: 01260009:4: <client_IP>:<port> -> <VS_IP>:443: Connection error: ssl_null_parse:3926: alert(48) received alert

warning tmm3[20873]: 01260013:4: SSL Handshake failed for TCP <client_IP>:<port> -> <VS_IP>:443

A packet capture taken on the BIG-IP shows the server Certificate message sent by the BIG-IP, followed immediately by a client-side fatal alert:

Alert (Level: Fatal, Description: Unknown CA)

The alert is sent from the client, in cleartext, directly after the Certificate message. Alert 48 (Unknown CA) means the client cannot build a trusted path from the server certificate chain to a CA it trusts. 

Environment

  • BIG-IP LTM (classic TMOS)
  • HTTPS virtual server with a Client SSL profile (clientside context) and a server SSL profile (serverside context)
  • The Client SSL profile's cert-key-chain referenced the leaf certificate for the cert, the chain, and the key. The chain was set to the same leaf certificate instead of the intermediate chain.
  • The leaf certificate was issued by an intermediate CA. The intermediate CA was not included in the chain the BIG-IP sent.

Cause

The Client SSL profile's certificate chain was incomplete. The BIG-IP sent only the leaf certificate, and the issuing intermediate CA was not sent. The client could not build a trusted path to a CA it trusts and sent a fatal Unknown CA alert.

The client's trust store may also need to contain the intermediate or root CA, particularly for clients that use custom trust stores and do not fetch missing intermediates. 

Answer/Recommended Actions

  1. Capture traffic on the BIG-IP during a failed handshake, for example with tcpdump -s0 -nni 0.0:nnnp host <client_IP> and host <VS_IP> -w <capture_file> -v. 
  2. In the packet capture, confirm that the client sends Alert (Level: Fatal, Description: Unknown CA) immediately after the server Certificate message.
  3. Review the Client SSL profile: tmsh list ltm profile client-ssl <profile_name>. Check the cert-key-chain entry. The chain must reference a certificate chain that includes the issuing intermediate CA, not the leaf certificate itself.
  4. Validate the certificate and chain files (cert, chain, key) and confirm the chain is correct for the issuing CA.
  5. Update the Client SSL profile so that the chain includes the intermediate CA, then retest the handshake from the affected client.
  6. If the handshake still fails after the chain is corrected, check whether the client's trust store contains the required intermediate or root CA. F5 does not manage the client's trust store.

Additional Information

  • The alert 48 "Unknown CA" from the client indicates a chain or trust problem. It does not indicate that the BIG-IP has a defect.
