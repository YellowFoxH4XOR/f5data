Known Issue

Deleting a BIG-IP APM access profile may fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access profile that references customization group files.
  • You attempt to delete the access profile.
  • One or more of the customization group files are deleted.
  • The imported access policy includes LDAP or AD queries.

Impact

Deleting the access profile fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to delete the access profile, the system displays an error message that appears in the following syntax:

    ?01071349:3: File object by name (/<partition>/<example_name>.png) is in use.

    For example:

    01071349:3: File object by name (/Common/my_webtop_img.jpg) is in use.

    In this example, note the following:

    • (/Common) is the BIG-IP APM access partition
    • (/my_webtop_img.jpg) is the object
  • When reviewing the BIG-IP APM access profile configuration, the profile intended for deletion is listed.
  • The system logs error messages to the /var/log/apm file that appear similar to the following example:

    01071349:3: File object by name (/<partition>/<custom file name>) is in use.
    01071193:3: Cannot delete aaa active directory server (/<partition>/<aaa profile name>) because it is referenced by an agent (AD Query - for Global Domain Users) in access profile (/<partition>/<access profile name>).
    01071193:3: Cannot delete aaa active directory server (/<partition>/<aaa profile name) because it is referenced by an agent (AD Query - for SAP_ALL Domain Users) in access profile (/<partition>/<access profile name>).
    01071108:3: Cannot delete aaa radius server (/<partition>/<name SecurID-Radius) because it is referenced by an agent (<aaa agent>) in access profile (/<partition>/<access profile name>).

Workaround

To work around this issue, you can first disassociate the objects from the access policy and delete the access policy. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access Policy > Access Profiles.
  3. Select the check box for the imported access profile that you want to delete.
  4. On the access profile delete page, clear the check boxes of the access profile objects below the access policy name.

    Important: Be sure to note the access profile objects and their names. Object names are based on the name given to the imported access policy. You need to delete these manually.

  5. Select Delete.

    Note: A typical access profile contains many objects. As with a network access profile, lease pool and webtop are based on the configuration of the imported access policy. The objects of an imported access policy vary for each access policy configuration. You should delete any unused objects that become disassociated from the deleted access profile.
