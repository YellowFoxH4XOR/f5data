Description

There is a device alert from a managed BIG-IP Device after upgrading BIG-IQ CM from 6.1 to 7.1 (and later versions). 

The subject of the email is similar to the following:
The BIG-IP device bigipa.example.com:0 health status is critical due to: device-inactivity crossed the critical threshold.

Body of the email:
Alert: The BIG-IP device bigipa.example.com:0 health status is critical due to:
device-inactivity crossed the critical threshold.

Alert details
---------------
Alert Rule Name: default-active-device-health
Type: device-health
Severity: Critical
Module: health-calculator
Start time: 2020-07-15T23:19:01.868Z
Category: system
Sub-category: system-health
Reported object: bigipa.example.com:0 Reported object type: BIG-IP Blade Alert context

Environment

  • BIG-IQ Centralized Management
  • Managed BIG-IP Device Health
  • REST commands
  • Device Alert

Cause
This alert triggers when a Big-IP drops to one percent (by default) utilization and is considered inactive. The "device-inactivity crossed the critical threshold" message is based on the currently detected CPU utilization metric. This is in the default alert config, but there is no way to change it in the UI.

Recommended Actions

  1. At a minimum it should be considered that the default value for device-inactivity be changed to "false" instead of "true" until the ability to configure it manually is provided.

    A one-liner command to change the alerts for built-in alert default-active-device-health would be:

    restcurl -X PATCH  /cm/shared/policymgmt/alert-rules/default-active-device-health -d '{"nestedRules":[{"unit":"percent","enabled":true,"operator":"greater-than","alertTypeId":"device-cpu","alertRuleType":"nested-metric","errorThreshold":80,"warningThreshold":65},{"unit":"percent","enabled":true,"operator":"greater-than","alertTypeId":"device-memory","alertRuleType":"nested-metric","errorThreshold":80,"warningThreshold":65},{"unit":"percent","enabled":false,"operator":"less-than","alertTypeId":"device-inactivity","alertRuleType":"nested-metric","errorThreshold":0,"warningThreshold":1},{"unit":"Mbps","enabled":false,"operator":"greater-than","alertTypeId":"device-throughput-in","alertRuleType":"nested-metric","errorThreshold":0,"warningThreshold":0},{"unit":"Mbps","enabled":false,"operator":"greater-than","alertTypeId":"device-throughput-out","alertRuleType":"nested-metric","errorThreshold":0,"warningThreshold":0},{"unit":"percent","enabled":false,"operator":"greater-than","alertTypeId":"asm-memory","alertRuleType":"nested-metric","errorThreshold":0,"warningThreshold":0},{"unit":"percent","enabled":false,"operator":"greater-than","alertTypeId":"asm-bypass","alertRuleType":"nested-metric","errorThreshold":0,"warningThreshold":0}]}'


    Note: If the alert being triggered is for a custom alert, the PATCH command should be made on that alert rule name (ie. /cm/shared/policymgmt/alert-rules/{ALERT_NAME}).
