Description

You want to replace an existing blade in a VELOS system that has only a single blade installed. The replacement blade could be a Return Materials Authorization (RMA) replacement blade or a spare blade that you may have.

  • To replace an existing blade in a VELOS system that has multiple blades installed, refer to K08485448: Replacing a blade in a VELOS system that has multiple blades installed.
  • To replace a VELOS system controller, refer to K000133249: Replacing VELOS system controller after a Return Materials Authorization.

Depending on the state of the existing blade, you may be able to restore configuration to the BIG-IP tenant(s) on the new blade using the following methods:

  • If the existing blade is still functional, you can create a UCS file from each of the BIG-IP tenants and download the UCS files to a remote location so that you can restore them to the BIG-IP tenants after installing the replacement blade.
  • If the existing blade is no longer functional and you have previous copies of the UCS file taken from each of the BIG-IP tenants, you can restore the configuration to the BIG-IP tenants using these UCS files after installing the replacement blade.
  • If the existing blade is no longer functional and you do not have any UCS files taken from the BIG-IP tenants, you must manually re-configure the tenants again.

If the BIG-IP tenant(s) is the active member of a high-availability pair with its peer on another separate VELOS system, you should fail over the tenant to its functional peer before attempting to perform the replacement. For information about forcing an active BIG-IP tenant to standby mode, refer to K30371289: Forcing an active BIG-IP system to standby mode using the Configuration utility. Additionally, F5 recommends that you should always perform blade replacement during a scheduled maintenance window to avoid any potential disruptions to your application environment.

Environment

  • VELOS chassis with only one blade installed.
  • You have physical access to the VELOS system.
  • You have serial console access to the VELOS system.
  • You have administrative access to the VELOS system.

Cause

None.

Recommended Actions

Note: If replacing a blade that is not a member of a VELOS partition, the system will be unable to add the blade to the cluster until the root user's password on the blade is changed, or the blade is added to an enabled partition.  Refer to Bug ID 1575585 for more information.

Note: If replacing a blade that is a member of a VELOS partition, make sure that the root account is not disabled (expiry status of "locked" or a expiry date of "1"). Refer to Bug ID 1397145 for more information.

    Replacing a functional blade

    The following is a high-level summary of the procedure to perform a blade replacement in a VELOS chassis that has only one blade installed, and the blade is still functional:

    1. Save a UCS file from the BIG-IP tenant(s) to a remote location, for example, another workstation. You should perform this step either through the BIG-IP tenant's Configuration utility or CLI. For information about creating a UCS file from a BIG-IP tenant, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive. For information on transferring a UCS file from the BIG-IP tenant to a remote location, refer to K175: Transferring files to or from an F5 system.
    2. Set the State of the BIG-IP tenant(s) to Configured. This will shutdown the BIG-IP tenant(s). For information about shutting down a tenant, refer to K21121803: Shut down and restart a tenant on the VELOS and F5 rSeries systems.
    3. Ensure you have serial console connected to the VELOS active system controller’s serial console port. For information about VELOS console access, refer to K65442484: Overview of access to the F5 VELOS system.
    4. Power off the blade. You can use the AOM to power off the blade. For information about powering off a blade, refer to the Turn off the VELOS blades procedure in K19230226: Turn off or turn on a VELOS system using the AOM Command Menu.
    5. Note the network cables and optical modules configuration before you physically remove them from the blade. You need to restore them after inserting the new blade in a later step. Disconnect all cables and remove the optical modules.
    6. Remove the blade from the chassis. Press the blue latch release on the front of the blade to release the ejector handle. Grasp the ejector handle and pull towards you, ensure that you support the weight of the blade as you remove it from the chassis.
    7. Insert the new blade into the same slot as the previous blade. For example, if the blade removed in the previous step was in slot 1, ensure that you insert the new blade into slot 1. Press the blue latch release on the front of the blade to release the ejector handle. Slide the blade in until the ejector contacts the catch in the chassis. Press the ejector handle until the blade is locked in place.
    8. Restore the optical modules and cables back to the blade's interfaces as noted in step 5.
    9. Power on the new blade if it is not already automatically powered on. For information about powering on a blade, refer to K19230226: Turn off or turn on a VELOS system using the AOM Command Menu.
    10. Log into the VELOS system controller CLI as the chassis admin user.
    11. Wait for the new blade to be ready. You can monitor the status of the new blade by entering the following command:

      show cluster | repeat

      When the blade is ready, the command will report the cluster-status summary-status as Openshift cluster is healthy, and all controllers and blades are ready.

    12. Additionally, you must wait for the new blade to be the replica in the partition that it is assigned. You can monitor this status by logging into the partition CLI as the partition admin user and enter the following command:

      show system redundancy

      When the blade is ready as the replica, the command should report the STATUS of the blade as replica.

    13. Verify that the portgroup modes are properly set and the optic-state is showing QUALIFIED. You can verify this by logging into the partition CLI as the partition admin user and enter the following command:

      show portgroups

    14. Ensure that the interface(s) is present and up. You can verify the interfaces' status by logging into the partition CLI as the partition admin user and enter the following command:

      show interfaces

      This will display all interfaces in the partition. Alternatively, if you want to verify only a specific interface, you can enter the following command syntax:

      show interfaces interface <interface number> state

    15. If you have configured LACP LAG for the partition, you should ensure that the LACP LAG is up. You can verify the status of the LACP LAG by logging into the partition CLI as the partition admin user and enter the following command syntax:

      show interfaces interface <LAG name>

      Alternatively, you can enter the command show lacp and verify that there are active members listed in the output.

    16. When you have verified the blade’s readiness and its network connectivity, you can then proceed to set the State of the BIG-IP tenant(s) to Deployed so that the VELOS system can start up the tenant(s). For information about starting up a tenant, refer to K21121803: Shut down and restart a tenant on the VELOS and F5 rSeries systems.
    17. Wait for the BIG-IP tenant to boot up completely. You can monitor the bootup of the tenant using the BIG-IP tenant console via the system controller console. For information about accessing the BIG-IP tenant console, refer to K65442484: Overview of access to the F5 VELOS system.
    18. When the BIG-IP tenant has booted up, you can upload the UCS file saved from an earlier procedure step to the BIG-IP tenant. For information on transferring a UCS file from a remote location to the BIG-IP tenant, refer to K175: Transferring files to or from an F5 system.
    19. Proceed to restore the BIG-IP configuration to the BIG-IP tenant using the uploaded UCS file. For information about restoring a UCS file to a BIG-IP tenant, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

    Replacing a non-functional blade and restoring BIG-IP tenant's configuration using a previous copy of the UCS file

    3. Power off the blade if it is not already powered off. You can use the AOM to power off the blade. For information about powering off a blade, refer to K19230226: Turn off or turn on a VELOS system using the AOM Command Menu.

Press the blue latch release on the front of the blade to release the ejector handle. Slide the blade in until the ejector contacts the catch in the chassis. Press the ejector handle until the blade is locked in place.

    18. Proceed to restore the BIG-IP configuration to the BIG-IP tenant using the uploaded UCS file. For information about restoring a UCS file to a BIG-IP tenant, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

    Replacing a non-functional blade without any UCS file for the BIG-IP tenant

    If the existing blade is no longer functional, and you have no UCS files taken from the BIG-IP tenants on the existing blade, you must manually rebuild the BIG-IP tenants’ configurations. F5 does not store customer’s configuration files and is unable to provide any information pertaining to the specific application environment in which the system is deployed. To rebuild the configuration, you may reference the manuals that are relevant to your application environment.

    Additional Information

    As this article describes the procedure to replace a blade in a VELOS system with only one blade installed, it is expected that traffic will be disrupted unless you have high availability configured for your BIG-IP tenants on another VELOS system. F5 recommends performing this procedure during a maintenance window.
