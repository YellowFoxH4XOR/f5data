Description 

ASM removes high ASCII bytes as part of the normalization process. Removing these bytes may lead to false-positive detection of attack signatures when the remaining bytes exactly compose an attack signature.

Environment

  • ASM security policy with attack signatures enforced.
  • The web application uses non-English encoding where high ASCII bytes are legal.

Cause

ASM, by default, normalizes all the payload when the selected content for the payload is form-data.

Recommended Actions

To ensure ASM doesn't remove high ASCII bytes during normalization process, you can run the following commands:

Impact of workaround: Restarting the ASM process causes a brief traffic disruption as it will result in the device going offline and subsequently result in a failover event.

  1. Set the ASM's internal parameter dont_norm_high_ascii to 1:
    /usr/share/ts/bin/add_del_internal add dont_norm_high_ascii 1
  2. Restart ASM daemon to ensure the change takes effect:
    bigstart restart asm
