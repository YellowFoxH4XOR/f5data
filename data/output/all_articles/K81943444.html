Topic

Starting in BIG-IP 15.0.0, you can use the BIG-IP Guided Configuration to import an existing OpenAPI specification (OAS) file to convert your API elements into BIG-IP Advanced WAF / ASM security policy entities. This article discusses how OAS parameter objects map to BIG-IP Advanced WAF / ASM parameters in your security policy.

Description

The OAS defines a schema for RESTful API machine-readable interface files. You can use a OAS file (in JSON or YAML format) to create and maintain your BIG-IP Advanced WAF API security policies. This process makes it possible to design your APIs and integrate your OAS files and API security policies into your CI/CD development cycle. This article discusses how the following OAS parameter objects are converted to Advanced WAF / ASM security policy parameters:

Query parameters
Path parameters
Header parameters
FormData Parameters

Query parameters

A query parameter is a key-value pair that is appended to the URL and passed to the application. A query parameter is separated from the URL path by a question mark (?) . For example, in the following query string the parameter key is month and the value 12:

https://example.com/report/users?month=12

The OAS specification uses the in: query statement to define a query parameter. The following OAS example includes the path, /report/users and the query parameters, month and week:

"/report/users": {
    "get": {
        "summary": "Users report",
        "parameters": [
            {
                "in": "query",
                "name": "month",
                "description": "Monthly users report",
                "type": "integer"
            },
            {
                "in": "query",
                "name": "week",
                "description": "Weekly users report",
                "type": "integer"
            }
                      ],

The BIG-IP Advanced WAF system converts the previous OAS example to the security policy elements in the following table.
 
URLAllowed methodParameter
The policy defines the following explicit URL:
  • /report/users
The policy defines the allowed HTTP method for the URL:
  • GET
The in: query statement defines the location of the parameter as part of the query string. The security policy defines the following query string parameters, at least one of which must appear as part of the query string in the request:
  • month
  • week

Path parameters

A path parameter is a request parameter that points to a specific resource and is attached to the URL with a slash (/). Path parameters are typically used in RESTful URLs, in which the parameter name is not present in the request but in which the values are embedded in URL between slashes (/). For example, the in the following URL the parameter value is 123,456:

https://example.com/fields/123,456

The OAS specification uses the in: path statement to define the location of the parameter as part of the URL path. The following OAS example includes the endpoint, /fields/{fieldId} and the path parameter, fieldId:

"/fields/{fieldId}": {
    "get": {
      "summary": "Retrieve a field",
      "parameters": [
        {
          "in": "path",
          "name": "fieldId",
          "description": "The Field ID",
          "type": "string",
          "required": true
        }
      ],

The BIG-IP Advanced WAF system converts the previous OAS example to the security policy elements in the following table.
 
URLAllowed methodParameter
The security policy defines the following wildcard URL:
  • /fields/*
The security policy defines the allowed HTTP method for the URL:
  • GET
The in: path statement defines the location of the parameter as part of the URL path. The security policy defines the following positional parameter:
  • fieldId

Header parameters

The OAS specification uses the in: header statement to define header parameters that are expected as part of the request. The following OAS example includes the endpoint, /cache and the header parameters, If-Modified-Since and If-None-Match:

"/cache": {
  "get": {
    "parameters": [
      {
        "in": "header",
        "name": "If-Modified-Since"
      },
      {
        "in": "header",
        "name": "If-None-Match"
      }
    ],
    "produces": [
      "application/json"
    ],
    }
},

The BIG-IP Advanced WAF system converts the previous OAS example to the security policy elements in the following table.
 
URLAllowed methodParameter
The security policy defines the following wildcard URL:
  • /cache
The security policy defines the allowed HTTP method for the URL:
  • GET
The in: header statement defines a header parameter which is an HTTP request header. In this example, the policy defines the following header parameters:
  • If-Modified-Since
  • If-None-Match


FormData parameters

The in: formData statement defines a parameter that comes in form data. The following OAS example includes the endpoint, /users/photo, and the formData parameter, photo:

"/users/photo": {
    "post": {
        "summary": "Upload a user's photo",
            {
                "name": "photo",
                "in": "formData",
                "type": "file",
                "required": true
            }
    }
}

The BIG-IP Advanced WAF system converts the previous OAS example to the security policy elements in the following table.
 
URLAllowed methodParameter
The security policy defines the following URL:
  • /users/photo
The security policy defines the allowed HTTP method for the URL:
  • POST
The in: formData statement defines the location of the parameter as part of the form data. The security policy defines the following parameter:
  • photo
