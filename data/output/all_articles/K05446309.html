Description

You expect the default topology takes effect when the pool of preferred topology is offline, while the preferred topology still takes effect.

For example:
With following topology records

gtm topology ldns: subnet 192.168.11.0/24 server: pool /Common/pool_example01 {
    order 1
    score 100
}
gtm topology ldns: subnet 172.16.11.0/24 server: pool /Common/pool_example02 {
    order 2
    score 100
}
gtm topology ldns: subnet 0.0.0.0/0 server: pool /Common/pool_default {
    order 3
    score 50
}

When the pool pool_example01 or pool_example02 is offline, you expect the last default topology takes effect and resolves the DNS query to pool_default.

But you find BIG-IP still resolves the DNS query from 192.168.11.0/24 to pool_example01 or resolves the DNS query from 172.16.11.0/24 to pool_example02 and get the resolved result of all member IPs in the pool.

Environment

  • BIG-IP DNS

  • Wide IP uses the topology load balancing method

  • DNS pool uses default load balancing method

  • DNS pool status is offline

Cause

  • This is by design that the topology of wide IP does not take pool status into account, so the preferred topology takes effect but not the default one.

  • There are load balancings of Preferred, Alternate, and Fallback. By default, the method for each of them is Round Robin, Round Robin, and Return to DNS, when the pool is offline, load balancings of Preferred and Alternate fail, so the Fallback returns all the member IPs as the resolution result.

Recommended Actions

You can change the BIG-IP DNS behavior under this situation base on your requirement, for more information, you can refer to K39000314: BIG-IP DNS resolving IP when all pool members are down/disabled.
