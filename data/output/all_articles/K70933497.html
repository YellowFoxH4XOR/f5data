Description

When the BIG-IP is running on an impacted version, it will not process TMM traffic upon boot up.

Restarting the BIG-IP will not fix this issue.

Restarting tmm service would allow BIG-IP to process the tmm traffic. The command would be:
bigstart restart tmm

Environment

This issue occurs when all the conditions are met:

  • BIG-IP 15.1.0.4, 15.1.0.3, 15.1.0.2, 15.1.0.1, 15.1.0, 14.1.2.6, 14.1.2.5 and 14.1.2.4.
  • sFlow receiver is enabled.

Cause

This issue is related to Bug ID 889209.

Recommended Actions

To permanently fix the issue, perform one of the following tasks.

  • Disable sflow receiver if it is not used
  • Upgrade to BIG-IP 16.0.0 or install and EHF to resolve the issue
Disable sflow receiver if it is not used
  1. Log in to the BIG-IP system command line.
  2. Navigate to System  ››  sFlow ›› Receiver List.
  3. Click on the sFlow object name.
  4. In State option, select Disable.
  5. Click Finished.
Upgrade to BIG-IP 16.0.0 or install and EHF to resolve the issue
  1. Follow article K84554955 to upgrade to BIG-IP 16.0.0.
  2. If you require an EHF, contact F5 support to acquire the EHF and follow article K13123 to install it.

Additional Information

Pcap will show that ARP request is sent and an ARP response is received by ARP table is not properly updated.
