Description

POP3 and IMAP monitors configured with Exchange iApp, stop working after an upgrade.

Monitors use external script with curl-apd commands.

The monitors fail with an authentication error similar to this example:

< -ERR Authentication failure: unknown user name or bad password.
* Closing connection 0
* TLSv1.2 (OUT), TLS alert, Client hello (1):
curl: (67) Login denied

Environment

  • Using Exchange iApp
  • POP3 and IMAP monitors
  • After upgrade to 13.0.0 and above

Cause

Bug ID 820965: f5.microsoft_exchange_2016 iApp needs to be updated to account for curl changes.

Recommended Actions

To workaround this issue, you can modify the imap_adv_eav and pop3_adv_eav external monitor files, so that the curl-apd commands in those files now contain login lines as example shown below. You can do this in the GUI under System > File Management > External Monitor Program File List.

Two modifications will need to be done to set it correctly:

Note: The commands are longer but not displayed here for brevity.

First change:

  1. Find the current script command:

    /usr/bin/curl-apd -k -v

  2. Change it to:

    /usr/bin/curl-apd -k -v --login-options "AUTH=PLAIN;AUTH=LOGIN;AUTH=NTLM"

    Note: Adding the login-options switch is important for the script to successfully login in the iApp for Exchange 2016 and Exchange 2019.

Second change:

  1. Find the 'RECV' String:

    RECV='successfully logged on'

  2. Change it to:

    RECV='successfully authenticated'

Example script:

After changing with the above, the script should look like the following example:

/usr/bin/curl-apd -k -v --login-options "AUTH=PLAIN;AUTH=LOGIN;AUTH=NTLM" -u ${??????USER}??????:${??????PASSWORD}?????? pop3s://${??????NODE}??????:${??????PORT}?????? 2>&1 | grep "${??????RECV}??????" > /dev/null
#!/bin/sh
# These arguments supplied automatically for all external monitors:
# $1 = IP (nnn.nnn.nnn.nnn notation)
# $2 = port (decimal, host byte order)
#
# This script expects the following Name/Value pairs:
#  USER  = the username associated with a mailbox
#  PASSWORD = the password for the user account
#  DOMAIN = the Windows domain in which the account lives
#
# Remove IPv6/IPv4 compatibility prefix (LTM passes addresses in IPv6 format)
NODE=`echo ${1} | sed 's/::ffff://'`
if [[ $NODE =~ ^[0-9]{1,3}.[0-9]{1,3}.[0-9]{1,3}.[0-9]{1,3}$ ]]; then
    # node is v4
    NODE=${NODE}
else
    # node is v6
    NODE=[${NODE}]
fi
PORT=995
PIDFILE="/var/run/`basename ${0}`.my_new_iapp_test_2010_${USER}_${NODE}_ad.pid"
RECV='User successfully authenticated'
# kill of the last instance of this monitor if hung and log current pid
if [ -f $PIDFILE ]
then
   echo "EAV exceeded runtime needed to kill ${NODE}:${PORT}" | logger -p local0.error
   kill -9 `cat $PIDFILE` > /dev/null 2>&1
fi
echo "$$" > $PIDFILE
/usr/bin/curl-apd -k -v --login-options "AUTH=PLAIN;AUTH=LOGIN;AUTH=NTLM" -u ${USER}:${PASSWORD} pop3s://${NODE}:${PORT} 2>&1 | grep "${RECV}" > /dev/null
STATUS=$?
rm -f $PIDFILE
if [ $STATUS -eq 0 ]
then
    echo "UP"
fi
exit

Additional Information

Monitors are configured with an external script that uses curl-apd with similar commands:

imap_adv_eav:

/usr/bin/curl-apd -k -v -u ${DOMAIN}\\${USER}:${PASSWORD} -X "SELECT ${FOLDER}" imaps://${NODE}:${PORT} 2>&1 | grep "${RECV}" > /dev/null

pop3_adv_eav:

/usr/bin/curl-apd -k -v -u ${DOMAIN}\\${USER}:${PASSWORD} pop3s://${NODE}:${PORT} 2>&1 | grep "${RECV}" > /dev/null

Note: Tests show that removing the "${DOMAIN}\\" part from the script's command fixed it as well.
