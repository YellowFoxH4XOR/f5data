K000158110: Pool member down on one device where HA pair shows pool member up

Type
Support Solution
Published
2025-12-08
Updated
2025-12-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000158110

Description

bigd publishes pool member status to mcpd on state change only by default. Having bigd publish pool members state each time a monitor is fired to mcpd consumes additional cpu resources that normally do not need to be consumed. However, at times bigd and mcpd could get out of sync with each other these service do not agree on the status of the pool member.

Note: This is one possible cause, please contact support if you need assistance with validation of this issue.

Environment

  • BIG-IP

Cause

ID722657 was the cause of bigd and mcpd getting out of sync.

Recommended Actions

There are two possible solutions to this:

Solution 1:

bigd publishes pool member status to mcpd on state change, so triggering a state change via the pool member will force bigd to update mcpd with status.  This could be handled by restarting the services on the pool member if acceptable.  

Solution 2:

Update the sys db bigd.stateupdateinterval to a value that is not 0.  This will trigger bigd to issue state messages to mcpd each number of intervals the monitor is fired.  It is not recommened to issue state each time a monitor is fired, because of the additional cpu usage.  However, this value should be set low enough to prevent long outages.  This setting applies to interval not time.  If the sys db bigd.stateupdateinterval is set to 10, a monitor with a 30 second interval would only have an update every 5 minutes.  However, a monitor with interval of 5 seconds would have an update every 50 seconds.
