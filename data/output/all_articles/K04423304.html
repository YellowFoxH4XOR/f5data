Description
  • Health check packets (TCP half-open monitor) starting from F5 SSL device are forwarded to the real server via F5 L4_Switch_Device using "forwarding_ssl" Virtual Service.
  • It appears that F5 L4_Switch_Device does not forward SYN packet to the server, but sends back SYN/ACK immediately because HW Syncookie is enabled
  • tcpdump pcap file
2 2021-06-25 15:08:50.763797 192.168.99.1 192.168.98.101 TCP 65 0 0 0 4094 16390 → 80 [SYN] Seq=0 Win=512 Len=0
3 2021-06-25 15:08:50.764590 192.168.98.101 192.168.99.1 TCP 69 0 1 0 4094 IN s1/tmm3 : 80 → 16390 [SYN, ACK] Seq=0 Ack=1 Win=29200 Len=0 MSS=1460
4 2021-06-25 15:08:50.764717 192.168.99.1 192.168.98.101 TCP 65 1 0 0 4094 16390 → 80 [RST] Seq=1 Win=0 Len=0

Environment

  • BIP-IP 12.1.2
  • Hardware SYN Cookie enabled

Cause

Bug ID 667618: Hardware SYN Cookies may not deactivate after the SYN attack ends and valid TCP traffic starts

Recommended Actions

Rebooting the device is helpful for customer to resolve the issue as stated in Bug ID 667618 because customer Hardware SYN Cookie has been not deactivated even though Syncookie HW mode exited.

"Jan 25 17:44:06 L4_Switch_Device notice tmm2[12674]: 01010241:5: Syncookie HW mode exited,    server = 0.0.0.0:0, HSB modId = 2 from HSB"

  1. Login to the Configuration Terminal
  2. Navigate to System  > Configuration > Device > General
  3. Click Reboot
  4. Click OK
