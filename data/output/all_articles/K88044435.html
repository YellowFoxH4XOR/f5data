Description

After adding a new DNS TXT record to ZoneRunner, it can't be found and no errors are displayed

Environment

  • BIG-IP DNS/GTM, 
  • DNS TXT record

Cause

BIG-IP DNS does not allow for a TXT record to be configured when there is an existing matching CNAME record in the zone. The reverse is also true: A CNAME-record cannot exist with any other records for the same name, because a name cannot both be an alias (CNAME) and something else at the same time. The GUI does not display an error message, but rather it just refreshes and the new record is not created.

Recommended Actions

Remove other records (A, TXT, SRV, etc.) for the subdomain. You can then create the TXT or CNAME and it will display correctly in the GUI. Or, instead of the CNAME-record, you can leave the existing records in place and setup an A-record pointing directly to the IP address of the actual server the aliased name is pointing to.

Additional Information

If you create a zone example.com RFC 2181 states that a CNAME record can only exist along with an SIG, NXT, or KEY RRs records. Since an SOA is mandatory at the apex of a zone, a CNAME cannot exist at the apex along with it. For this reason, the F5 will not allow the creation of a CNAME at the apex of the zone. In zonerunner, you will be able to create a CNAME for sub zones, but not for the root/ or apex zone.

You can create a CNAME for:
   test.example.com
   x.example.com
   redirect.example.com

You cannot create a CNAME for:
   example.com
