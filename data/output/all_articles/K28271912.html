Known Issue

BIG-IP APM network access and optimized applications may fail when iClient processes multiple messages in a single payload.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for network access or optimized applications.
  • The BIG-IP APM system process multiple iClient messages in a single iSession/TCP payload.
    .

Impact

BIG-IP APM resources are not available, with the possibility of a memory leak.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The amount of memory allocated for and used by the iSession subsystem will increase over time.

    To inspect the memory usage for the iSession subsystem, you can use the following Traffic Management Shell (tmsh) command:

    tmsh show /sys memory | egrep 'Max\ Alloc|^isession\ '

    The command output appears similar to the following example:

    SubSystem Alloc (bytes) Max Alloc (bytes) Object Size
    isession 5.3G 5.3G 1

    Repeating the command will show an increase over time.

  • BIG-IP APM network access fails to establish or the optimized application does not function correctly.
  • The BIG-IP Edge Client Log displays error messages that appear similar to the following example:

    1,2014-12-11,14:30:05:149,,7096,5308,EXCEPTION - invalid state (state),
    ISESSION_STATE_CLOSED1,2014-12-11,14:30:05:149,,7096,5308,EXCEPTION caught1,2014-12-11,14:30:05:149,,
    7096,5308,closed in transition state (state), ISESSION_STATE_CLOSED48,2014-12-11,14:30:05:150,,7096,7968,enter1,2014-12-11,14:30:05:150,,7096,5308,closeTunneledConnection() failed, -1, ISESSION_STATE_CLOSED48,
    2014-12-11,14:30:05:150,,7096,5308,changing state (old, new), ISESSION_STATE_CLOSED, ISESSION_STATE_CLOSED
