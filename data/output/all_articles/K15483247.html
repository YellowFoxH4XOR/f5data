Description

After updating the device certificate, the GUI access becomes inaccessible. The following message will appear in CLI if you run tmsh load sys config 

load_config_files[10121]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- 01070920:3: Application error for confpp: Syntax OK
The certificate does not match the key.  To change them try 'tmsh modify sys httpd { ssl-certfile /etc/httpd/conf/ssl.crt/server.crt ssl-certkeyfile /etc/httpd/conf/ssl.key/server.key }'

SSL Library Error: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch

Environment

  • Using CA certificate and key for management access
  • GUI

Cause

Failing to import both the CA Certificate and key may cause the system to incorrectly use the right certificate/key match and make the GUI inaccessible.  
 

Recommended Actions

1) Log in to the Advanced Shell (bash).

2) To generate the new device certificate and key, use the following command syntax: openssl req -x509 -nodes -days 3650 -newkey rsa:2048 -sha256 -keyout /config/httpd/conf/ssl.key/server.key -out /config/httpd/conf/ssl.crt/server.crt

3) Enter the certificate attributes such as country, locality, common name, etc. NOTE: We just hit "enter" to just take defaults on all of the various questions.

4) To restart the httpd process, type the following command:

bigstart restart httpd

5) Import again both the Certificate and Key
