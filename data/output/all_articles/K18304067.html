Security Advisory Description

The BIG-IP ASM system may fail to properly mask the value of a configured sensitive positional parameter that appears in a Referer header.

This issue occurs when all of the following conditions are met:

  • You configure a positional parameter for an Allowed URL in the BIG-IP ASM security policy.
  • You enable the Mask Value in Logs setting for the resulting positional parameter.
  • The BIG-IP ASM system receives a request in which the configured sensitive positional parameter appears in both the request URL and an HTTP Referer header.

When the request URI and HTTP Referer header in a request both contain the same sensitive positional parameter, the positional parameter in the Referer header is not masked in logs and, therefore, may be sent unmasked to remote log systems of lower privilege than the BIG-IP ASM system.

The following example request matches an Allowed URL configured in the security policy with the positional parameter param. The param positional parameter has the Mask Value in Logs setting enabled. In this example, both the request URL and the Referer header contain the sensitive positional parameter param that causes the BIG-IP ASM system to log the positional parameter in the Referer header unmasked:

GET /default/param HTTP/1.1
Host: host.com
Referer: http://example.com/default/param

Impact

Sensitive positional parameters in the Referer header are not masked in the BIG-IP ASM system request event logs and may be sent unmasked to remote log servers.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Sensitive positional parameters are masked in logs when they appear in the URL, but they are not masked when they also appear in the HTTP Referer header.
