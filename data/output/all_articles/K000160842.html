Description

When restoring a UCS archive containing an empty configuration to a BIG-IP device that is in Forced Offline state, the device temporarily transitions to Active status and sends Gratuitous ARP (GARP) messages for virtual servers from the running configuration before loading the empty configuration and returning to Offline. 

Environment

  • BIG-IP LTM
  • Device initially in Forced Offline state
  • UCS archive taken when device was in Online state with empty configuration
  • UCS restore performed on the device

Cause

The observed behavior occurs because restoring a UCS archive taken while the device was Online causes the BIG-IP to temporarily transition to Active status, which triggers GARP messages for any virtual servers present in the running configuration.
Once the empty configuration is loaded, the device returns to Offline state. This is consistent with documented F5 behavior regarding UCS restores and Forced Offline status.

Answer/Recommended Actions

Advise that this behavior is expected when restoring a UCS archive taken in Online state to a device in Forced Offline.
To avoid unintended GARP broadcasts, ensure the UCS archive reflects the desired device state and configuration before restoration.
Reference relevant F5 documentation for further clarification.
