K000148997: The health monitor may fail when the pool member has the same IP address and port as the virtual server

Type
Support Solution
Published
2024-12-16
Updated
2024-12-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000148997

Description

In a scenario where you have configured the pool member with the same IP address and port number as the existing virtual server you may notice that the pool member health check does fail and/or the BIG-IP is not sending the health probes to the pool member. Under certain circumstances this problem could be triggered when the pool member and virtual server become unavailable. 

Environment

  • BIG-IP LTM
  • The pool member has the same IP address and the port number as the existing virtual server
  • Health check is configured to send monitor probes to the pool member IP address and port combination

Cause

The BIG-IP is sending monitor probes internally to the virtual server instead of the pool member. This can be seen when taking the packet capture on the egress VLAN with “hnnn” - this option shows the internal TMM traffic. In a situation where the virtual server is unavailable you may see that the TMM resets the connection with “No pool member available”.

For example:

Recommended Actions

As a workaround, disable ARP on the virtual address level and disable the VLAN towards pool member or towards the gateway (of the monitor probes) on the virtual server level.

You may also investigate using a health monitor with an alias port number which the BIG-IP does not have any virtual server listening on.
