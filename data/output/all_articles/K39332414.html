Known Issue

When you update an access profile that contains a Machine Cert Auth agent, the apmd process leaks 12096 bytes of memory each time.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system contains an access profile configured with a Machine Cert Auth agent.
  • You update the access profile using the Apply Access Policy option or the TMOS Shell (tmsh).

For more information on updating an access profile, refer to K15176: Applying a new or updated BIG-IP APM access profile to the active configuration.

Impact

The memory that the apmd process uses on the BIG-IP system steadily increases, which may eventually affect other services and overall system performance.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Every time you update an access profile that is configured with a Machine Cert Auth agent, the following occurs:
    • Over time, system performance may degrade and the system may eventually become unresponsive.
    • The amount of memory allocated for and used by the apmd process may increase by 12096 bytes.

      To inspect how much memory the apmd process uses, type the following tmsh command:

      # tmsh show sys service apmd memstat

      The command output appears similar to the following example:

      Service             Limit(kB)   Current(kB)

      apmd                <none>        260420
