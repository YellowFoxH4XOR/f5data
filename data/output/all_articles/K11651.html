Known Issue

This is the result of a known issue. When the HTTP::respond and LB::reselect iRule commands are triggered simultaneously within an LB_FAILED event, TMM will crash. For example, this issue can occur with either of the following iRule configurations:

  • When two iRules are configured for a virtual server and one iRule uses the HTTP::respond command, and the other iRule uses the LB::reselect command, TMM crashes when a high number of connections to the virtual server trigger the commands simultaneously.

    An iRule configuration displays similar to the following example:

    irule_one {
    when LB_FAILED {
    HTTP::respond 500 content "F5 error";
    }
    }

    irule_two {
    when LB_FAILED {
    pool fallback_pool;
    LB::reselect;
    }
    }
  • When a single iRule references both the HTTP::respond and LB::reselect commands and the iRule is configured for multiple virtual servers, TMM crashes when a high number of connections to the virtual servers trigger the commands simultaneously.

    An iRule configuration displays similar to the following example:

    rule irule_multiple_vips {
    when LB_FAILED {
    if { [LB::server pool] == "some_pool" } {
    HTTP::respond 503 "This service is currently unavailable"
    } else {
    LB::reselect pool some_pool
    }
    }
    }

F5 Product Development tracked this issue as ID 222533 (formerly CR120879) and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, or WOM release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about downloading software from F5, refer to K167: Downloading software from F5.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by avoiding the use of the HTTP::respond and LB::reselect iRule commands in the LB_FAILED event.
