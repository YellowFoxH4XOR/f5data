K000139303: PKCS11d daemon is down and cannot be restarted

Type
Support Solution
Published
2024-05-08
Updated
2024-05-08
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000139303

Description

  • Symptoms

           Restarting the PKCS11d daemon using command "restart /sys service pkcs11d" didn't work and the daemon remained down as shown below.

           # pkcs11d down, initializing ...

  • Error messages

            The following logs was observed in /shared/nfast/log/hardserver.log :

             t00f79620b67f0000: Hardserver [FP]: Serious internal error, trying to continue: Device <any> failed GenerateRandom for new client ID (ServerAccessDenied)

Environment

  • HSM

Cause

When restarting pkcs11d, it should by right also restart hardserver which is used to interact with the external HSM. There is a possibility that the hardserver is not restarted somehow.

Recommended Actions

1. Check the status of the hardserver if it is active
    systemctl status nc_hardserver

2. If the status is "inactive", perform a restart of the service:
    systemctl restart nc_hardserver

3. Check again and see if the status of the hardserver is active.

4. If status of hardserver is active, check and see if the pkcs11d daemon is back up. If is not attempt to restart it again:
    restart /sys service pkcs11d

5. If the status of the hardserver is down or pkcs11d still doesn't recover after performing step 4 then perform the below command in big-ip and see if the pkcs11d daemon or hardserver will resume active status:
    opt/nfast/sbin/init.d-ncipher restart

Additional Information

  • "opt/nfast/sbin/init.d-ncipher restart " command is a Linux command for restarting the hardserver (which will communicate with a remote HSM) on a Linux client. 
  • The pkcs11d process acts as an interface between the BIG-IP daemons and utilities that need to access the third-party network- connected HSMs (like Thales and Safenet). If this daemon is not running, SSL connections cannot be established on a virtual server that is associated with an SSL profile that references the affected certificate/key pair stored on the Thales HSM.
