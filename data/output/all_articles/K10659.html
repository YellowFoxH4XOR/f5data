Known Issue

This is the result of a known issue. The libpcap library supports the packet-capture and filtering engines for the BIG-IP system. The libpcap library runs out of internal registers after about 15 calls.

For example, the following packet filter will fail to load after about 15 successful load operations:

packet filter xxx {
order 1
action discard
filter { udp[12:1] & 0xff == 0x123 }
}

After issuing approximately 15 bigpipe load commands, an error message that appears similar to the following example is generated to the system console:

BIGpipe packet filter creation error:
01070087:3: Packet filter rule 'xxx': too many registers needed to evaluate expression

F5 Product Development tracked this issue as CR126264 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

Important: Restarting the mcpd process should be performed on the standby system or during a maintenance window. The mcpd process is the messaging component of the BIG-IP system; other daemons rely on mcpd to communicate with each other.

You can temporarily work around this issue by running the bigstart restart mcpd command to restart the mcpd process. Restarting the mcpd process will allow you to load the configuration; however, the issue will recur after 15 successful load operations.
