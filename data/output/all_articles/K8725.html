Known Issue

This is the result of a known issue. If a OneConnect-enabled virtual server receives a request that uses a universal persistence record, but the second request does not use a universal persistence record, the BIG-IP assigns a stale persistence entry to the second request. As a result, connections that should not use universal persistence are persisted.

Note: For more information, refer to K7392: Overview of universal persistence

F5 Product Development tracked this issue as CR97341 and it was fixed in BIG-IP LTM 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

In addition, this issue has been fixed in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
