Description

  • Using an iRule to set a nexthop. Working under CLIENT_ACCEPTED but not LB_SELECTED
  • LB_SELECTED triggers but the nexthop value is ignored
  • No errors or iRule validation issues
  • nexthop under LB_SELECTED is supported based on documentation

Environment

  • BIG-IP
  • iRule defined using a nexthop value 
  • When used under LB_SELECTED the traffic is routed as per the Virtual server configuration
  • When used under CLIENT_ACCEPTED the traffic is routed as per the nexthop value

Cause

It seems, once a pool member is selected it cannot be overridden by the nexthop command. LB_SELECTED is trigger after a pool member server is selected whereas CLIENT_ACCEPTED is triggered before the pool member selection is made. 

Recommended Actions

If the requirement is to use nexthop under a LB_SELECTED event then you need to specify the LB::reselect option as follows:

when LB_SELECTED {
          LB::reselect nexthop <IP Address>
}
