Known Issue

This is the result of a known issue. When outbound FTP traffic that is either originated from a monitor, or initiated from the command line travels through a gateway pool, it incorrectly uses 127.1.1.1 as the source IP address. As a result, the connection fails, as it is unable to be established because the 127 network address is reserved for internal system use only.

F5 Product Development tracked this issue as CR80111, and it was fixed in BIG-IP LTM versions 9.3.1 and 9.4.4. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.3-HF4, issued for BIG-IP version 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

You can work around this issue by specifying static routes for the destinations specified in the FTP monitors or when you are using FTP from the command line. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Network > Routes.
  3. Select Add.
  4. Select Route for the Type.
  5. Specify the Destination IP address or Network IP address.
  6. Specify the Netmask.
  7. Specify the IP address to use for the gateway.
  8. Click Finished .
