Known Issue

This is the result of a known issue. If a service is removed from the bigstart utility using the bigstart remove <service> command, the service will restart continuously if one of the following operations is performed:

  • A configsync process is initiated and the configuration is pushed to the unit where the service was removed (this applies to BIG-IP high availability pairs only)
  • An attempt to restart the removed service is performed by running the bigstart restart <service> command

Note: Restarting a service using the bigstart restart <service> command, after the service had previously been removed from the bigstart utility, is an illegal operation. The bigstart utility cannot be used to manage a service that was removed from its configuration. Beginning in BIG-IP versions 9.6.0 and 10.0.0, if a BIG-IP administrator tries to restart a service using the bigstart utility, after the service was removed from the bigstart configuration, the following message is returned:

Service <service> has not been added to bigstart.

Note: The bigstart utility is used to control the services running on the BIG-IP system. For more information, see the bigstart man page.

Assuming that the named service was removed from the bigstart utility, and that one of the operations mentioned above was performed, the BIG-IP system will return an error message that appears similar to the following example:

Can't exec "/service/named/stopit.sh": No such file or directory at /usr/lib/perl5/vendor_perl/5.8.0/daemon.pm line 203.
runsvctrl: warning: /service/named: unable to open supervise/control: file does not exist
runsvctrl: warning: /service/named: unable to open supervise/control: file does not exist

Additionally, running the bigstart status named command will show that the service has restarted many times. For example:

named run (pid 6583) 0 seconds, 3140 restarts

This issue occurs because the bigstart utility attempts to restart a service that was removed from its configuration.

F5 Networks Product Development is tracking this issue as CR82164.

This issue does not affect the BIG-IP version 9.6.x and 10.x software branches.

Workaround

Removing a service from the bigstart utility is generally not necessary, therefore the bigstart remove and bigstart add commands should only be run by a BIG-IP administrator if instructed to do so by F5 Networks Technical Support. Instead, the bigstart disable and bigstart enable commands should be used to enable or disable a service running on the BIG-IP system. For example, named can be disabled by running the bigstart disable named command. The service will remain disabled until re-enabled with the bigstart enable named command.

If you have already removed a service from the bigstart utility, contact F5 Networks Technical Support to receive help in re-adding the service. The required commands will vary depending whether the service needs to start at boot time, be part of the default set of services or both.

Additional information

Due to a different known issue, if a service is stopped from within the Configuration utility, the service is removed from the bigstart utility. Therefore, stopping a service from within the Configuration utility also creates the condition which may cause the issue described in this Solution to occur.

For more information, refer to K9073: Stopping or starting services from the Configuration utility results in an error message.
