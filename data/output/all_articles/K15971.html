Known Issue

HTTP 4xx server response may trigger a connection reset.

This issue occurs when all of the following conditions are met:

  • A BIG-IP virtual server is configured with an HTTP profile.
  • The client initiates a connection to the virtual server with the HTTP method CONNECT.
  • The destination resource replies to a connection request with a client error 4xx status code that includes a Content-Length header.

Impact

The BIG-IP system resets the connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H499657 on the Diagnostics > Identified > Medium screen.
  • Clients receive an unexpected reset when attempting to access resources provided by the virtual server.
  • You may encounter log messages in /var/log/ltm that appear similar to the following example:

    err tmm3[19210]: 011f0007:3: http_process_state_prepend - Invalid action EV_INGRESS_DATA during ST_HTTP_PREPEND_HEADERS (Server side: vip=/<partition>/<virtual server name> profile=http pool=/<partitiopn>/<virtual server pool> server_ip=10.20.142.1)
    err tmm3[19210]: 01230140:3: RST sent from 10.1.147.80:80 to 10.10.132.1:12044, [0x18f7e62:9888] {peer} HTTP Unexpected server data past end of response
    err tmm3[19210]: 01230140:3: RST sent from 10.20.147.1:12044 to 10.20.142.1:8080, [0x18f7e62:9888] HTTP Unexpected server data past end of response

  • When viewing the server response headers, the response includes a Content-Length header.

Workaround

To work around this issue, you can implement an iRule to disable HTTP filtering when clients use the HTTP method CONNECT. To do so, perform the following procedure.

Impact of workaround: F5 recommends that you perform this procedure during a scheduled maintenance window. If possible, test the iRule in a staging environment to ensure effectiveness.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule Name box, type a name for the iRule.

    For example:

    http_filter_disable

  5. In the Definition box, enter the following text:

    when HTTP_REQUEST {
    if { [HTTP::method] eq "CONNECT" } {
    HTTP::disable
    }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. In the Name box, click the name of the virtual server that is affected by this issue.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. From the Available column, select the iRule you have previously created.
  12. To move the iRule to the Enabled column, click the << button.
  13. Click Finished.
