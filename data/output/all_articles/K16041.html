Known Issue

The cascading style sheets (CSS) minification feature in the BIG-IP AAM system may erroneously add spaces to content.

This issue occurs when all of the following conditions are met:

  • You use the BIG-IP AAM system to accelerate traffic.
  • You have the CSS minification feature enabled in the acceleration policy.
  • The system processes CSS content that has previously been minified.

Impact

Spaces are unexpectedly added to CSS content during the minification process, causing a buffer overflow condition that can, in rare cases, cause the Traffic Management Microkernel (TMM) to exit.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP AAM system alters CSS content, and increases the size of the file.
  • The BIG-IP system experiences a decrease in performance or becomes unstable.
  • The TMM process exits and restarts. If configured as part of a high availability (HA) group, the BIG-IP system fails over to the standby system.
  • A TMM core file is generated to the /shared/core directory.

Workaround

To work around this issue, you can disable the CSS minification feature in the acceleration policy. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure disables minification for all JavaScript and CSS files.

  1. Log in to the BIG-IP AAM Configuration utility.
  2. Navigate to Acceleration > Web Application > Policies.

    The Policies screen displays a list of existing acceleration policies.

  3. Click the name of the affected acceleration policy.
  4. Expand the Policy Tree to a branch node or leaf node, and click the node.
  5. From the Matching Rules menu, select Acceleration Rules.
  6. On the menu bar, click Assembly.

    The screen refreshes to show assembly options.

  7. Clear the Enable JavaScript and CSS Minification check box.
  8. Click Save.
  9. Click Publish.
  10. Click Publish Now to publish the changes to the policy.
