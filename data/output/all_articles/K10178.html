Known Issue

This is the result of a known issue. On rare occasions, the PVA2 chip sends corrupted data in response to a virtual server statistics query. When this issue occurs, error messages logged to the /var/log/ltm file appear similar to the following example:

pvad[1707]: 01130004:4: ../Pva2AsicFactory.cpp:724 - Dropping stats msg. VSO deserialize failed.
pvad[1707]: mra_lbdb_vxo_basic_::deserialize(): wrong type 1
pvad[1707]: 01130004:4: ../Pva2AsicFactory.cpp:724 - Dropping stats msg. VSO deserialize failed.
pvad[1707]: mra_lbdb_vxo_basic_::deserialize(): wrong type 1

The issue does not affect system functionality, except for virtual server statistics collection.

The PVA2 chip is present only on the BIG-IP 3400, BIG-IP 6400, and BIGIP-6800 platforms. F5 has not seen this issue on the PVA10 chipset.

F5 Product Development is tracking this issue as ID 323648 (CR119531).

Workaround

If the error message persists, you can work around the issue by restarting the pvad process. To do so, type the following command:

bigstart restart pvad
