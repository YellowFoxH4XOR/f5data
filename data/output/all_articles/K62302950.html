Known Issue

The ospfd process may restart during a high availability (HA) failover event.

This issue occurs when all of the following conditions are met:

  • You have multiple BIG-IP systems in an HA configuration
  • You have configured your BIG-IP system to use the Open Shortest Path First (OSPF) dynamic routing protocol.
  • You have configured OSPF to redistribute Not-So-Stubby Area (NSSA) routes.
  • You have configured your BIG-IP system to use the HA group feature.
  • The active BIG-IP system has the highest HA health score.
  • You manually fail over the active BIG-IP system to a standby BIG-IP system with a lower HA health score.

    Note: You should not manually fail over a BIG-IP system when the HA group feature is enabled. For more information refer to K14515: The Force to Standby feature should not be used when the HA group feature is enabled.

  • The standby system momentarily becomes active and immediately fails over to the previously active BIG-IP system.

Impact

The BIG-IP system will not process OSPF routing information while the ospfd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After manually failing over the active BIG-IP system, the ospfd process produces a core file in the /shared/core directory.
  • Your BIG-IP system logs a sequence of events to the /var/log/ltm file that appears similar to the following example:

    010c0044:5: Command:  go standby /Common/traffic-group-1 GUI.
    010c0052:5: Standby for traffic group /Common/traffic-group-1.
    010c0018:5: Standby
    010c006d:5: Leaving Standby for Active (best ha score).
    010c0053:5: Active for traffic group /Common/traffic-group-1.
    010c0019:5: Active
