Description

Set sys db logpublisher.atomic to false, following:

  • K03912652: Enable Log Publisher to log when a logging destination becomes unavailable

Configured both remote and local destinations in log publisher, for example:

sys log-config publisher /Common/hsl-publisher {
    destinations {
        /Common/hsl_dst_splunk { }
        /Common/hsl_dst_syslog { }
        /Common/local-db { }
        /Common/local-syslog { }
    }
}

Observing that local logging also stops when all remote destinations are unavailable. Is this expected?

Environment

  • Logging

Cause

This is the expected behavior. The logpublisher.atomic database key only applies to remote logging. If the configured remote destinations in the publisher are unavailable, there will be no local logging.

Recommended Actions

To work around this limitation, ensure that one of the log destinations is always available - by using a local listener such as a virtual server, for example, or a pool with a monitor that won't fail.

This may not be necessary in most cases, as there should ideally always be a pool available for receiving logs.
