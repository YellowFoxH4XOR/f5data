K000136119: Monitors on Standby Peer are marking nodes continuously UP/DOWN

Type
Support Solution
Published
2023-09-07
Updated
2023-09-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000136119

Description

You observed abnormal behavior on your Standby Peer in HA, monitors are flapping Up/Down, even the connectivity is stable and no similar behavior is not presented on the Active peer. On standby you can observe the following logs:

notice mcpd[2964]: 01070638:5: Pool <Pool_name> member <ServerIP_port> monitor status down [ <MonitorA_name>: down, <MonitorB_name>: down ] [ was up for <#>hrs:<#>mins:<#>sec ]
notice mcpd[2964]: 01070727:5: Pool <Pool_name> member <ServerIP_port> monitor status up. [ <MonitorA_name>: down, <MonitorB_name>: up ] [ was down for <#>hrs:<#>mins:<#>sec ]

Additionally, on the switch where BIG IPs are connected in ARP table for Standby device you can observe wrong MAC address - which will be the same as  MAC masquerade configured on your BIG IP.


Environment

  • BIG IP
  • Virtual Server 0.0.0.0 (wildcard) configured with ARP enabled
  • MAC masquerade is configured
Cause
Unknown at time of publication
 

 Recommended Actions

1. Identify the VS configured on your BIG IP with IP address 0.0.0.0 and check if ARP is enabled: 
ltm virtual-address /Common/0.0.0.0 {
address any
arp enabled
icmp-echo disabled
mask any
traffic-group /Common/traffic-group-1
}
2. If ARP is enabled, you have to disable it, and monitors will work as expected.
3. If ARP is disabled and the issue still persists, troubleshoot the monitors following the article from Related Content section.
