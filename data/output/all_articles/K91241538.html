K91241538: OWA authentication broken with 'F5RST: Detach during a transaction' in a packet capture

Type
Support Solution
Published
2022-05-03
Updated
2023-10-16
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP APM: 15.1.2
Source
https://my.f5.com/manage/s/article/K91241538

Description
Webmail authentication broken, when taking a packet capture next reset message is found: 

F5RST: Detach during a transaction

Environment

  • Exchange iApp
  • OneConnect profile in Virtual Server
  • iRule with next code portion: 
    when HTTP_RESPONSE {
        if { ( [HTTP::header exists "WWW-Authenticate"] &&
            [string tolower [HTTP::header values "WWW-Authenticate"]] contains "negotiate" ) ||
            ( [HTTP::header exists "Persistent-Auth"] &&
            [string tolower [HTTP::header "Persistent-Auth"]] contains "true" ) } {
            ONECONNECT::reuse disable
            ONECONNECT::detach disable
            NTLM::disable
       }
       if {[HTTP::header exists "Transfer-Encoding"]} {
            HTTP::payload rechunk
       }
    }

Cause
Unknown

Recommended Actions

To resolve the issue follow next steps:
  1. Comment out ONECONNECT and NTLM lines in the iRule, like next:
    when HTTP_RESPONSE {
        if { ( [HTTP::header exists "WWW-Authenticate"] &&
            [string tolower [HTTP::header values "WWW-Authenticate"]] contains "negotiate" ) ||
            ( [HTTP::header exists "Persistent-Auth"] &&
            [string tolower [HTTP::header "Persistent-Auth"]] contains "true" ) } {
            # ONECONNECT::reuse disable     <-------------
            # ONECONNECT::detach disable    <-------------
            # NTLM::disable                 <-------------
       }
       if {[HTTP::header exists "Transfer-Encoding"]} {
            HTTP::payload rechunk
       }
    }
  2. Remove the OneConnect profile from the Virtual Server
