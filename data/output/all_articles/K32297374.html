K32297374: BIG-IQ error message ''Postgres replication slot is not found''

Type
Support Solution
Published
2021-03-29
Updated
2025-09-09
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.X, 8.3.X, 8.4.0, 8.3.0
Source
https://my.f5.com/manage/s/article/K32297374

Description

On top the BIG-IQ GUI, a yellow banner will show Postgres replication slot is not found.

The BIG-IQ CM are in HA pair and viewing var/log/postgres/postgresql logs on either devices will show the following messages.
ERROR:  replication slot "ha_replication" does not exist
FATAL:  role "root" does not exist

Environment

  • BIG-IQ CM are in HA pair
  • Postgres replication slot is not found. yellow banner when login to the BIG-IQ GUI
  • Following error messages in var/log/postgres/postgresql
ERROR:  replication slot "ha_replication" does not exist
FATAL:  role "root" does not exist

Cause

There is an issue with the HA pair which is causing the Postgres replication slot is not found. error message in the yellow banner.

Recommended Actions

You will need to repair HA between the BIG-IQ CM devices. 

  1. Login to the BIG-IQ GUI.
  2. From the active BIG-IQ, at the top of the screen, click System 
  3. On the left, click BIG-IQ HA
  4. Click the BIG-IQ HA Settings button
  5. Click the Repair Database button to re-synchronize the database between the active and standby BIG-IQ systems
  6. This button displays only if the database needs to re-synchronized.
  7. Click the Save & Close button.

Additional Information

After following the above Recommended Action you may observe similar below error message. 

An error occurred while repairing DB: ERROR: Failure executing pg_basebackup. status: 1 /bin/ha_streaming_replication: line 98: 6075 Terminated ( sleep "$sleep_time" & local sleep_pid="$!"; trap "kill $sleep_pid 2>/dev/null" EXIT; wait "$sleep_pid"; kill "$cmd_pid" 2> /dev/null ) ERROR: Failure establishing streaming replication on the standby. Error code: 1 ERROR: Failure establishing streaming replication with standby. Restored the standby database to its previous state ERROR: Failure establishing streaming replication on the standby

This is likely due to expired HA certificate. You can run below command to check the certificate validity of BIG-IQ HA certificate. If the certificate is expired, you can follow this article K000135043: Secondary is not actively streaming. Postgres may be down. on how to renew BIG-IQ HA certificate.

openssl x509 -in /var/lib/pgsql/config/server.crt -issuer -subject -startdate -enddate -noout
