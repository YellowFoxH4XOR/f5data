Description

F5 Distributed Cloud provides multiple rate-limiting and traffic-protection options at different network and application layers.

Use packet-based controls for L3/L4 traffic, HTTP or API rate limiting for application requests, and L7 DDoS Protection for abnormal application-layer attack traffic.

Environment

  • F5 Distributed Cloud

  • Customer Edge (CE) and Regional Edge (RE)

  • HTTP Load Balancers

  • Web App & API Protection

  • Fast ACLs and Network Policies

Cause

Different F5 Distributed Cloud features are available depending on whether traffic must be limited by packet rate, network protocol, HTTP request rate, client identity, or API endpoint.

Answer/Recommended Actions

L3/L4 Packet Rate Limiting

Use a Policer to define a general packet-rate limit in packets per second (pps). A Policer defines the committed packet rate, burst size, and whether the rate limit is shared between references.

Use a Protocol Policer when different packet-rate limits are required for TCP, UDP, ICMP, or DNS traffic. A Protocol Policer references one or more Policer objects and adds protocol-specific classification.

These controls can be applied through Fast ACLs. Fast ACLs evaluate ingress packets and can apply actions such as allow, deny, Policer, or Protocol Policer. The Fast ACL determines which traffic is matched, while the referenced Policer defines the actual packet-rate limit.

For Customer Edge sites, Fast ACLs can be applied through the applicable Network Firewall and Fleet. For Regional Edge Internet VIPs, Fast ACLs can be configured using the Fast ACLs for Internet VIPs object in the Routed DDoS workspace.

Fast ACLs are currently not supported for Kubernetes Sites or Secure Mesh Site v2 deployments and are evaluated for every ingress packet, unlike session-based ACLs.

HTTP Load Balancer Rate Limiting

Use HTTP Rate Limiting to control how many HTTP requests a client can send during a configured time period.

Limits can be configured per second, minute, or hour and can include burst handling and temporary blocking when the configured limit is exceeded.

By default, clients can be identified by source IP. User Identification can also use values such as HTTP headers, cookies, or query parameters.

Rate Limiter Policies

Use Rate Limiter Policies when HTTP rate limiting must apply only to specific traffic.

Rules can match criteria such as source IP, ASN, country, source segments, HTTP method, domain, path, and headers. Matching traffic can use the default rate limiter, a different custom rate limiter, or bypass rate limiting.

API Rate Limiting

Use API Rate Limiting when limits need to be applied specifically to APIs.

Limits can be associated with API server URLs, base paths, individual endpoints, and HTTP methods. API Rate Limiting can also use conditions such as headers, cookies, and query parameters and can use User Identification to distinguish clients.

For example, API Rate Limiting can restrict how frequently a client can call a login or other sensitive API endpoint.

L7 DDoS Protection

Use L7 DDoS Protection to detect and mitigate abnormal application-layer attack traffic rather than to enforce a fixed request quota.

L7 DDoS Protection evaluates application behavior and metrics such as request rate, error rate, latency, throughput, and origin health to determine when mitigation should be applied.

Feature Selection Summary

  • Policer: General packet-per-second limits.

  • Protocol Policer: Packet-per-second limits based on TCP, UDP, ICMP, or DNS traffic.

  • HTTP Rate Limiting: General HTTP request limits and per-client throttling.

  • Rate Limiter Policies: Conditional HTTP rate limiting based on request or client attributes.

  • API Rate Limiting: Limits for specific APIs, base paths, endpoints, methods, or API request conditions.

  • L7 DDoS Protection: Detection and mitigation of abnormal application-layer attack traffic.
