Known Issue

This is the result of a known issue. When a discard statement in a rule prompts BIG-IP to send a reset to a client, the reset does not use the lasthop information for the connection; therefore, the reset message may not reach the client or the client may ignore the message.

F5 Networks Product Development tracked this issue as CR43927 and CR43928. It was fixed in BIG-IP version 4.5.12 for the 4.5 software branch and version 4.6.3 for the 4.6 software branch. For information about upgrading, refer to the BIG-IP Release Notes.

In addition to the problem described above, the fixed version made it possible for BIG-IP to send the reset to the incorrect VLAN. The VLAN would then drop the reset, and the node would still not receive the reset. This problem exists only in BIG-IP versions 4.5.12, 4.6.3, and 4.6.4.

F5 Networks Product Development tracked this issue as CR50382 and CR50383 and it was fixed in BIG-IP version 4.5.13 for the 4.5 software branch. For information about upgrading, refer to the BIG-IP Release Notes.

CR50382 and CR50383 were not resolved in the BIG-IP version 4.6 branch.
