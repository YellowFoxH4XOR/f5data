K000130605: "Name of service not know" error when DNS query goes over TCP

Type
Support Solution
Published
2023-01-13
Updated
2023-01-13
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K000130605

Description

The DNS server controls the switch to TCP.
By default, all DNS queries are performed over UDP however when a client receives a response that is too large, it switches to TCP.


Environment

Kubernetes: 1.19.x, 1.20.x, 1.21.x

Aspen Mesh: 1.11.x, 1.14.x


Cause

The server sets a special bit TC in the response when a client receives a response that is too large forcing the client to switch to TCP.


Recommended Actions

Since the DNS resolution is going over TCP, this port needs to be excluded from being proxied. One way to do this is using annotations in the pod/deployment spec as follows:

annotations:
   traffic.sidecar.istio.io/excludeOutboundPorts: "53"
apiVersion: v1
kind: Pod
metadata:
  name: nettools
  namespace: default
  annotations:
    traffic.sidecar.istio.io/excludeOutboundPorts: "53"

Another way is to use a destination rule, which will disable MTLS when talking to the DNS service:

apiVersion: networking.istio.io/v1alpha3
kind: DestinationRule
metadata:
  name: disable-mtls-to-dns
spec:
  host: "dns-default.openshift-dns.svc.cluster.local"
  trafficPolicy:
    tls:
      mode: DISABLE
