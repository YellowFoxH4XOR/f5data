K30610132: Large untruncated NAPTR DNS responses may be dropped when AFM is configured

Type
Support Solution
Published
2022-07-08
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K30610132

Description
When a large MTU is configured a DNS server may respond with a NAPTR record that exceeds 512 bytes.   If AFM is configured on the BIG-IP these responses may be silently dropped as malformed packets.

Environment

  • AFM is configured
  • MTU is set larger than 1500
  • DNS NAPTR request is sent, either locally or via a port 53 UDP listener

Cause
This is caused by ID 1112781

Recommended Actions
You may work around this by setting:

tmsh modify sys db dos.dnsport value <port>
where <port> is a value other than 53, such as: 
tmsh modify sys db dos.dnsport value 54
Note that this will prevent AFM from analyzing incoming DNS traffic.

Alternately, you may use TCP, which works as expected.

Additional Information
Bug ID 1112781: DNS query drops on Virtual Edition platform if the packet size is above 1500 for NAPTR record.
Note: while the bugtracker entry notes that size must be above 1500, this has been reproduced at smaller sizes
