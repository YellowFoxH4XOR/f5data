Known Issue

This is the result of a known issue. When you configure multiple Static App Tunnels for a resource group, and those tunnels share the same value for the Remote Host field, the FirePass controller displays the Local Host value that is set for the first Static App Tunnel for all tunnels instead of the individual Local Host values you configured.

You can safely ignore this issue; the correct Local Host values are saved in the FirePass configuration.

For example, if you configure a Static App Tunnel that maps 172.16.100.1:80 to 127.248.51.252:80, and then you configure a second Static App Tunnel within the same resource group that maps 172.16.100.1:22 to 127.159.135.120:22, the FirePass controller displays the Local Host value of the second tunnel as 127.248.51.252 instead of its actual value of 127.159.135.120. However, when users launch the second tunnel, the FirePass controller correctly sets the local host IP address to 127.159.135.120.

F5 Product Development tracked this issue as CR134396 and it was fixed in FirePass version 7.0.0. For information about upgrading, refer to the FirePass release notes.
