Description

F5 Insight Software Installation Job Readiness Check generates a certificate-related error and returns an HTTP 500 response.

Example Error

vault read f5-insight/device/DUMMY-DEVICE-ID/password: vault: auth: vault: cert login returned 500 500 Internal Server Error

Environment

  • Product: F5 Insight
  • Version: 1.2.2
  • Affected component: Software Installation Job Readiness Check

Cause

This is a known issue documented in the Known Issues section of the latest F5 Insight 1.2.2 release notes.

Provisioning and other operations that require securely stored credentials might fail after an internal authentication certificate expires, even when a replacement certificate has been generated. Affected services continue using the previous certificate until you restart them.

Recommended Actions

  1. Check the provisioning component state:
    sudo kubectl -n f5-insight get all | grep -i provisioning
  2. Stop the provisioning deployment:
    sudo kubectl scale deployment/provisioning -n f5-insight --replicas=0
  3. Verify that the provisioning deployment has no running replicas:
    sudo kubectl -n f5-insight get all | grep -i provisioning
    The deployment should report 0/0.
  4. Start the provisioning deployment:
    sudo kubectl scale deployment/provisioning -n f5-insight --replicas=1
  5. Verify that the deployment is ready:
    sudo kubectl -n f5-insight get deployment/provisioning
    Expected status: 
    NAME           READY   UP-TO-DATE   AVAILABLE
provisioning   1/1     1            1
  6. Retry the F5 Insight validation operation.
  7. If the validation continues to fail, restart the service associated with the failure and the Vault service, then retry validation.
  8. If the issue persists, generate and upload a new F5 Insight support bundle for further investigation.

Additional Information

Ensure that the provisioning deployment reaches an available 1/1 state before retrying validation.
