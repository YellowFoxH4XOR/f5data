Security Advisory Description

An issue in the swagger-ui, the third-party component bundled in the NGINX Plus packages, may expose an XSS security risk. The purpose of the swagger-ui is to provide interactive documentation for the API specification supplied in a swagger YAML file and used in the NGINX Plus release. But it is not intended for production usage.

Impact

An NGINX Plus instance is vulnerable when the swagger-ui is configured and no proper Content Security Policy (CSP) settings are applied. This issue may allow a remote attacker who knows the swagger-ui URL to launch a reflected XSS attack against a victim who clicked a forged URL.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by installing a version listed in the Fixes introduced in column. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch and F5 recommends upgrading to a version with the fix (refer to the table).

If the Fixes introduced in column lists a version prior to the one you are running, in the same branch, then your version should have the fix.

Mitigation

To mitigate this issue, F5 recommends that you turn off swagger-ui in your production NGINX Plus instances. The simplest way to do this is to delete the swagger-ui folder (for example, /usr/share/nginx/html/swagger-ui). Alternatively, you should ensure that the swagger-ui pages are not served from your NGINX Plus instances. For the non-production instances, F5 recommends that you apply appropriate CSP settings using the Content-Security-Policy HTTP header.

  • For information about enabling/disabling the swagger-ui, refer to the following resource:
    • The Swagger UI in the Live Activity Monitoring section of the of the NGINX Plus Admin Guide
  • To configure the Content-Security-Policy HTTP header, add the following statement to the location block where you serve the swagger-ui in your NGINX configuration file:
    • add_header Content-Security-Policy "default-src 'self'";
