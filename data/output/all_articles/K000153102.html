Description

You access a web application through BIG-IP APM Portal Access, and the application, or part of it, does not load or work as expected. The application works as expected when you access it directly, without BIG-IP APM.

When you troubleshoot this issue, you may observe the following symptoms:

  • The browser developer console (F12) shows an error similar to the following example (the URLs vary):

    Access to fetch at 'https://api.example.com/resource' from origin 'https://portal.example.com' has been blocked by CORS policy: The value of the 'Access-Control-Allow-Origin' header in the response must not be the wildcard '*' when the request's credentials mode is 'include'.

  • The failed request is a JavaScript fetch request. The console output may point to the Portal Access rewriter file, for example cache-fm.js: 1194.

  • The browser sends the same request again and again, and the page does not finish loading.

Environment

  • BIG-IP APM 17.1.x, 17.5.x or 21.x

  • Portal Access resource and rewrite profile

  • Back-end application JavaScript that uses fetch requests, often to a third-party host (for example, an OpenID Connect discovery endpoint)

  • The server that answers the request returns the response header Access-Control-Allow-Origin: *

Cause

The Portal Access browser-side rewriter (cache-fm.js or cache-fm-Modern.js) changes fetch requests so that the request credentials mode is include. When a request is sent with credentials, browsers do not accept a response with Access-Control-Allow-Origin: *, and block the response. The application then fails or repeats the request.

This issue is tracked as Bug ID 1065913.

Answer/Recommended Actions

  1. Confirm that the issue matches this article:

    1. Open the browser developer console (F12), and reproduce the issue through Portal Access.

    2. Check that the console shows the CORS error from the Description section, with the text must not be the wildcard '*' when the request's credentials mode is 'include'.

    3. Note the URL in the message (Access to fetch at '<URL>'). This is the host whose response is blocked.

  2. Open a support case, and request the workaround for Bug ID 1065913 (this article). Provide the following data:

    • The full console error, and the URL of the blocked request.

    • The data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications.

    • The rewrite mode of the Portal Access resource (Modern or Legacy). For more information, refer to K000130439: Configuring the Rewrite Control List (RCL) to use Modern JavaScript rewriting for Portal Access.

Note: An iRule on the Portal Access virtual server that removes or changes the Access-Control-Allow-Origin header has no effect on requests that do not pass through the BIG-IP system. For example, with split tunneling, the browser may send the blocked request directly to the third-party server. Before you try such an iRule, check whether the blocked request reaches the BIG-IP system.
