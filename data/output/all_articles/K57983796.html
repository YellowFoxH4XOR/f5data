Known Issue

The Domain Name System (DNS) transparent cache may leak memory due to specific DNS Security Extensions (DNSSEC) messages.

This issue occurs when all of the following conditions are met:

  • The BIG-IP transparent cache is populated with messages where the DNSSEC OK (DO) bit is set to true.
  • Another query with the DO bit set to true, arrives at or after the expiration of a previous message TTL.
  • Subsequent queries arrive with the DO bit set to false.

Impact

Multiple queries can lead to larger memory consumption over a short period of time. The BIG-IP system may temporarily fail to process traffic while the Traffic Management Microkernel (TMM) restarts. Failover to the standby device may occur, if configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM memory consumption steadily increases over time. You can monitor TMM memory usage using following tmsh command:

    tmsh show /sys memory

  • TMM sweeper starts aggressively ending connections, due to lack of memory. The system may log messages to the /var/log/ltm file that appear similar to the following example:

    warning tmm2[12345]: 011e0003:4: Aggressive mode sweeper: 1200 Connections killed
    warning tmm1[12345]: 011e0003:4: Aggressive mode sweeper: 1300 Connections killed

  • For HA configurations, the BIG-IP system fails over to the standby device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
