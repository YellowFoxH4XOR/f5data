Description

On macOS devices using BIG-IP APM Edge Client, repeated VPN tunnel reconnections may occur. This is indicated by frequent PPP tunnel start and close events in BIG-IP APM logs and corresponding connectivity change and tunnel reconnection events in Edge Client logs. Both the primary Wi-Fi interface (en0) and the awdl0 interface (used by AirDrop and Continuity) may be active during the issue. Disabling AirDrop and Continuity features on the Mac resolves the repeated reconnection behavior.

Environment

  • Product: BIG-IP APM
  • Virtual server
  • Access profle
  • Network Access
  • Client: macOS device running BIG-IP Edge Client
  • macOS features: AirDrop and Continuity enabled

Cause

The issue is triggered by macOS network interface state changes, specifically activation or changes in the awdl0 interface due to AirDrop and Continuity features. These changes are detected by the BIG-IP Edge Client as network connectivity changes, which can trigger unnecessary PPP tunnel reconnections.

Answer/Recommended Actions

  • Disable AirDrop and Continuity features on macOS clients to prevent awdl0 interface state changes from triggering Edge Client tunnel reconnections.
  • Optionally, check and the Client Side Security: Prohibit routing table changes during Network Access connection setting in the BIG-IP APM Network Access configuration if further issues occur.
  • If the issue persists, collect detailed client and server logs for further analysis.

Additional Information

The behavior is related to how the Edge Client monitors network interface changes on macOS. When auxiliary interfaces such as awdl0 (used by AirDrop and Continuity) change state, the Edge Client may interpret this as a general connectivity change, leading to tunnel reconnections. Disabling the relevant macOS features stabilizes the VPN connection.
