K000150775: Device certificate not visible in GUI due to presence of non UTF character in Device certificate CSR file names

Type
Support Solution
Published
2025-04-09
Updated
2025-04-09
Source
https://my.f5.com/manage/s/article/K000150775

Description

When accessing these locations in GUI, Error occurs as 'An error has occurred while trying to process your request' and Page can not be seen.

System  ››  Certificate Management : Device Certificate Management : Device Certificate

System  ››  Certificate Management : Device Certificate Management : Device Key

System  ››  Certificate Management : Device Certificate Management : Device Certificate Chain

System  ››  Certificate Management : Device Certificate Management : Device Certificate Signing Request

 

Environment

BIG-IP GUI

Cause

Presence of non UTF character in the Device Certificate Signing Request file names in location '/config/ssl/ssl.csr/'

Example:

# ll

-rw-r--r--. 1 root root   1151 Apr  9 03:22 server.csr▒??

Recommended Actions

  1.  Find the CSR file name which has non UTF characters and delete it. 

          # cd /config/ssl/ssl.csr/

          # ls | perl -ne 'print "$. $_" if m/[\x80-\xFF]/'

Additional Information

Below  error can also be seen in '/var/log/tomcat/catalina.out' or '/var/log/webui.log'  due to presence of non UTF characters in file name of CSR's.

"ERROR [ajp-bio-127.0.0.1-8009-exec-9] ssl_005fcertificate.properties_jsp:_jspService - com.sun.org.apache.xerces.internal.impl.io.MalformedByteSequenceException: Invalid byte 2 of 2-byte UTF-8 sequence.
com.f5.model.security.PKIStoreException: com.sun.org.apache.xerces.internal.impl.io.MalformedByteSequenceException: Invalid byte 2 of 2-byte UTF-8 sequence."
