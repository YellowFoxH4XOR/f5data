Description

You want to use the command "tmsh reboot slot <slot number>" described in K44259537 to reboot a specific slot, but you may get the below errors:

Slot slot<slot number> could not be rebooted, cannot connect to the slot

Or

You want to use the "clsh" command described in K11333 to shut down or to restart one or more blades in a VIPRION system but it's failing.

Environment

  • VIPRION with multiple blades
  • SSHD not listening on default port 22
  • Reboot slot using "tmsh reboot slot <slot number>"
  • Shutdown all blades using "clsh shutdown -h now"
  • Shutdown one blade using "clsh --slot=<slot number> -h"
  • Restart  all blades using "clsh shutdown -r now"
  • Restart  one blade using "clsh --slot=<slot number> -r"

Cause

The tmsh reboot command requires the SSHD listen on the default port 22, but you changed the default to another port, and we are tracking this issue from Bug ID 1018765: Changing the sshd port breaks some BIG-IP utilities on a multi-bladed system.

Recommended Actions

To work around the issue, you can reconfigure the SSHD back to listen on the default port 22.

You can refer to the command below:
# tmsh modify sys sshd port 22

Note: You can use the command "tmsh list sys sshd all-properties" to check the current SSHD listening port.

Or you may use the alternative command to reboot or shutdown one slot/blade:

  • Reboot the slot/blade:
    bladectl -b <blade#> -r

  • Shut down the slot/blade:
    bladectl -b <blade#> -p 0

For example, to reboot slot 2, you may try the command "bladectl -b 2 -r", or if you want to shut down slot 2, you may run this command "bladectl -b 2 -p 0".

Or the methods described from the ID1018765.

Additional Information

For the detailed steps, you may refer to K07557518: VIPRION cluster shell utility(clsh) commands.
