Description

For HTTP/1.x VS, when the traffic is reset due to exceeding max-header-count or max-header-size settings, this fact is logged in /var/log/ltm.

For example:

---

Aug 18 06:55:01 bigip1 err tmm[16414]: 011f0011:3: HTTP header count exceeded maximum allowed count of 16 (Client side: vip=/Common/http-vs profile=/Common/my-http pool=/Common/http-pool client_ip=192.168.1.1)


The same error is not being logged for HTTP/2 VS (with http2 profile applied).


Environment

- HTTP/2 VS

- max-header-count or max-header-size error not logged


Cause

This is an intended change of behavior.

It is better not to log the exceeding max-header-count on HTTP/2 and remove the logging from HTTP/1.x to avoid potential log-spamming attack.

BIG-IP admins can check the RST cause in the HTTP profile stats.



 [root@bigip1:Active:Standalone] config # tmsh show ltm profile http2 all

  . . .

  GoAway Reasons

   Compression Error          0

   Decompression Error 0                             

   Timeout               0

   Parse Error             0

   Out Of Memory Error 0

   Stream Error 0

   Max Streams Exceeded  0

   Max Headers Exceeded 2                             

   Insufficient Security        0


In the future, we will remove logging for HTTP/1.x to have a consistent behavior.
