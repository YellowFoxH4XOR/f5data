Description

When accessing ASM configuration within BIG-IP Configuration Utility, for example, the policies list, you observe 'ASM Failed to load policies' error. At the same time, traffic is not impacted and you may see 're-starting restjavad' messages in the CLI.

Environment

  • ASM is provisioned
  • Device is running out of memory allocated to administrative tasks.

Cause

Certain information, including list of ASM policies are retrieved using REST calls when navigating the web user interface (GUI). When device is running out of management memory, the calls may not succeed when restjavad daemon is restarting or unable to obtain required memory. The resulting error does not mean that the policies were not loaded from the configuration; rather it means that the GUI cannot display it.

Recommended Actions

  1. Confirm that device is running out of management memory by checking the top command output and examining free memory output. Alternatively, you can search /var/log/kern.log for out-of-memory entries which are logged when device encounters out of memory situation.
  2. Check if tmm reserved memory can be repurposed for management by issuing tmsh show sys memory command. If a lot of it is unused, some of it can be allocated to management.
  3. Follow steps outlined in K26427018: Overview of Management provisioning to provision additional memory to the management.
