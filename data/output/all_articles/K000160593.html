Description

When uploading qkview files to F5 iHealth via the BIG-IP GUI with an HTTP proxy configured, the upload fails if the BIG-IP system cannot resolve iHealth endpoint hostnames locally. DNS queries for iHealth endpoints (e.g., identity.account.f5.com, ihealth2-api.f5.com) return "No such name" errors, and no traffic is sent to the proxy. Even with a proxy configured, BIG-IP requires local DNS resolution for iHealth endpoints before attempting the upload.

Environment

  • HTTP proxy configured (e.g., with SSL inspection)
  • DNS servers unable to resolve iHealth endpoints
  • Upload performed via BIG-IP GUI (System → Support)
  • Error messages: "No such name" DNS errors

Cause

Bug ID 2257425

Recommended Actions

1. Add Static Host-to-IP Mappings:

Add static host entries for the following iHealth endpoints using dummy or real IP addresses:

  • api.f5.com
  • identity.account.f5.com
  • ihealth2-api.f5.com
  • ihealth-api.f5.com

Example (using tmsh):

tmsh modify sys global-settings remote-host add {

   api.f5.com { addr <any_IP> hostname api.f5.com }

   identity.account.f5.com { addr <any_IP> hostname identity.account.f5.com }

   ihealth2-api.f5.com { addr <any_IP> hostname ihealth2-api.f5.com }

   ihealth-api.f5.com { addr <any_IP> hostname ihealth-api.f5.com }

}

tmsh save /sys config

2. Configure DNS Servers:

Ensure the BIG-IP system's DNS servers can resolve the required iHealth hostnames.

3. If you Using SSL Inspection Proxy: 

Add the proxy's root CA certificate to /config/ssl/ssl.crt/ca-bundle.crt on the BIG-IP. Save the file and reboot the system for changes to take effect.

Additional Information

  • Dummy IP addresses are sufficient for static host entries; actual connectivity is handled by the proxy.
