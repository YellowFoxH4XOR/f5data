Known Issue

The BIG-IP system will not reconnect to an external hardware security module (HSM) after a reboot, when Traffic Management Microkernel (TMM) interfaces are used.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system configuration uses an external HSM for Secure Sockets Layer (SSL) certificate and key management.
  • You have configured the BIG-IP system to reach the external HSM through a TMM interface, or self IP, instead of the management port or the eth0 interface.
  • You reboot the BIG-IP system.

Impact

SSL connections or Domain Name System Security Extensions (DNSSEC) operations will fail if they reference a certificate and key stored on the external HSM.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to connect to the external HSM.
  • Connections that reference a certificate and key stored on the external HSM are failing.

Workaround

To work around this issue, you can restart the pkcs11d process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the advanced shell (bash) of the BIG-IP system.
  2. Type the following command:

    tmsh restart sys service pkcs11d
