Known Issue

RSA SecurID authentication may succeed for a number of authentication transactions, then fail when the RSA SecurID fails to launch new threads to process new requests. When this occurs, the BIG-IP APM system's Access Policy Daemon logs an error message for each subsequent authentication request that appears similar to the following example:

err apd[4446]: 01490122:3: 29f97644: SECURID module: authentication with 'username' failed in queryAuthPort(): Exception: Could not read from socket. , code: -1, state: SECURID_AUTH_STATE_ACCESS_DENIED

When authentication fails, the BIG-IP APM system blocks access to the requested resources even when valid credentials are supplied.

F5 Product Development tracked this issue as CR137479, and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP APM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

Workaround

You can work around this issue by clearing the Node Secret on the BIG-IP APM system and on the SecureID server, then reapplying the access policy.
