Description

You may want to disable all SSL protocol versions or a specific TLS protocol version for a web site, application, or virtual server.

For example, TLS / SSL tests, such as SSL Labs, give ratings based on whether specific protocols are enabled or not. For example, you may only want TLS 1.2 and TLS 1.3 enabled but TLS 1.0 and TLS 1.1 disabled. To get a higher rating in such tests, it is required to disable protocols such as SSL or TLSv1.1 or to remove ciphers that use those protocols from the Ciphers List in the Client SSL profile.

SSL Labs may show a report similar to the following:
This server supports TLS 1.1. Grade capped to *.

Disable protocols on an SSL profile using the Configuration utility

To watch a video demo of this procedure, go to  K000150826: Disable protocols on an SSL profile using the Configuration utility.

  1. In the Configuration Utility, go to Local Traffic > Profiles > SSL > Client.
  2. Enter the Client SSL profile used in the virtual server
  3. For Configuration, select Advanced.
  4. For Options, select the Custom check box.
  5. For option List, select the targeted protocol or protocol versions. For example, no TLSv1.1, no SSL.
  6. Select Enable.
  7. Select Update

Alternatively, you can use the following steps:

  1. In the Configuration Utility, go to Local Traffic > Profiles > SSL > Client.
  2. Select the Client SSL profile used in the virtual server
  3. For Configuration, select Advanced.
  4. For ciphers, input cipher string to disable targeted protocol or protocol versions. For example, DEFAULT:!SSLv3:!TLSv1:!TLSv1_1.
  5. Select Update

Disable protocols on an SSL profile using the command line (tmsh):

  1. Log in to tmsh by entering the following command:

    tmsh

  2. View the current options of the profile by listing its properties by entering the following command:

    list ltm profile client-ssl <profile_name>

    Note: Replace <profile_name> with the name of your SSL profile.

  3. Edit the profile to specify the TLS versions by entering the following command:

    modify ltm profile client-ssl <profile_name> options { no-tlsv1.1 no-ssl }

    Note: This example blocks TLS 1.1 and SSL. You can see the possible option values by using tab after the 'options' argument.

    If you want to modify the versions with a cipher string instead, use the following command:

    modify ltm profile client-ssl test-cli ciphers DEFAULT:!SSLv3:!TLSv1_1

  4. Check the profile's properties again to verify the changes have been applied by entering the following command:

    list ltm profile client-ssl <profile_name>

  5. Save the configuration to make the changes persistent by entering the following command:

    save sys config

Additional Information

After you disable TLS v1.0 in the Client SSL profile applied to the virtual server, you can use the openssl command to confirm TLS 1.0 is disabled. To do so, perform the following procedure:

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. Enter the following command, replacing <vip> and <port> with the IP address and port of the virtual server:

    openssl s_client -connect <vip>:<port> -tls1

    The resulting SSL handshake should fail.
