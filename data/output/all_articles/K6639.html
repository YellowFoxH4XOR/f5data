Known Issue

This is the result of a known issue. A persistent connection to a BIG-IP ASM-enabled virtual server may be aborted when the first request matches an HTTP class with BIG-IP ASM disabled, and the second request matches an HTTP class with BIG-IP ASM enabled.

When this issue occurs, the system logs a message in the /var/log/ltm directory that appears similar to the following example:

Rule _ASM_clientside <HTTP_REQUEST_SEND> - can't read "tmm_ts_lbserver": no such variable

F5 Product Development tracked this issue as CR69314 and it was fixed in BIG-IP ASM 9.2.4. For information about upgrading, refer to the BIG-IP ASM release notes.
