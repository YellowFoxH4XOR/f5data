Description

The server is receiving TCP window full from BIG-IP. I would like to monitor when BIG-IP sends a TCP window full.

Environment

  • BIG-IP LTM
  • iRule

Cause

It is not possible to output logs when BIG-IP sends a TCP window full.

Recommended Actions

It is possible to output logs of the receive window advertised to the peer and the maximum size of BIG-IP's TCP receive buffer using an iRule.

・TCP::recvwnd

It returns the effective value of the receive window currently being advertised to the peer (counterpart).

・TCP::rcv_size

At that point, it returns the maximum size (upper limit) of the BIG-IP TCP receive buffer (receive window) in bytes.

This corresponds to the receive window defined in the TCP profile.

Example of log output:

Nov 26 16:02:53 bigip2.local info tmm1[20174]: Rule /Common/test <CLIENT_ACCEPTED>: BIGIP's rcv wnd size: 14600

Nov 26 16:02:53 bigip2.local info tmm1[20174]: Rule /Common/test <CLIENT_ACCEPTED>: Current TCP receive window: 65535

Example of TCP profile configuration:

--------------------------------------
# tmsh list ltm profile tcp Test_TCP
ltm profile tcp Test_TCP {
  app-service none
  defaults-from tcp
  receive-window-size 65535
}
--------------------------------------
