Description

There may be a situation where virtual server closes some of the connections with reason [F5RST: No server selected].

Environment

  • BIG-IP LTM
  • Virtual server with iRule applied

Cause

Reason of that behaviour is caused due to LB::detach being used after the pool selection in the iRule. You can observe that first connection is working properly, but second request trigger pool selection in the iRule point to the same pool and this time the server-side connection is already present. LB::detach is triggered and server-side connection is detached from the client-side connection. There's no server-side connection so F5 sends out RST "No server selected".

Recommended Actions

To solve this issue you need to insert LB::detach just before the pool selection in HTTP_REQUEST, like in the following example:

when HTTP_REQUEST {
 LB::detach
 pool pool-1
}
