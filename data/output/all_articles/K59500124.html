K59500124: Log Message: Source buffer high watermark reached

Type
Support Solution
Published
2022-04-07
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K59500124

Description

BIG-IQ AppIQ agentmanager log (/var/log/appiq/agentmanager.log) shows the following message:

INFO c.f.a.a.r.ReactorPipeline [XNIO-2 task-17] Source buffer high watermark reached (available-capacity: <ac>, max-capacity: <mc>, usage: <us>%, please retry later
WARN c.f.a.a.c.RawDataAPIController [XNIO-2 task-17] Sending HTTP response 504 Gateway Timeout with Retry-After : <mils> ms

In this error message, note the following:

<ac> is an integer representing the remaining capacity in the AppIQ pipeline buffer.
<mc> is an integer representing the maximum capacity configured in the AppIQ pipeline buffer.
<us> is the percentage of usage that results from the above terms division.
<mils> is a random number of milliseconds. 

BIG-IQ statistic collection may not work as expected, including loss of arbitrary stats/events data received from managed BIG-IP, which might result in incomplete graphs for certain periods of time, certain managed devices or certain dimensions.

Environment

  • BIG-IQ DCD
  • Statistic collection is enabled and DCD is receiving a high rate of stats and/or events per second

Cause

AppIQ is the module in charge of processing stats and events received by the DCD, normalize them and save them to the ElasticSearch cluster.

The AppIQ agentmanager on DCD keeps a buffer of the statistics data it receives from the BIG-IP, before it writes it to ElasticSearch. The function of the buffer is to handle spikes. But the buffer can reach a watermark if the rate at which agentmanager is able to write to ElasticSearch is significantly slower to the rate of incoming alerts or events from the BIG-IP.

The error is indicating that AppIQ agentmanager is unable to process all the incoming messages with the current buffer size.

Recommended Actions

  1. For BIG-IQ VE, make sure the virtual machine allocated hardware resources meet the minimal requirement of BIG-IQ DCD VE. If needed, increase the buffer size by increasing the system RAM to the next power of two (for instance, if the unit has 32GB, upgrade it to 64GB) and reboot the unit. During startup, the provisioning system will automatically detect the extra memory and will increase the size of the AppIQ agentmanager buffer.
  2. Read the DCD Sizing Guidelines to find the recommended numbers of DCDs needed in the cluster. Add more DCDs into the cluster if needed, this will divide the load among all the members and will decrease the number of messages received per DCD.
