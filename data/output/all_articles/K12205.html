Known Issue

This is the result of a known issue. When a virtual server is configured with a diameter profile, the BIG-IP system may attempt to remove connections that have already been removed due to a race condition. As a result, TMM will core and the BIG-IP system will failover or restart. An error message that appears similar to the following example may be logged to the /var/log/tmm file:

notice panic: ../modules/hudfilter/dime/diameter.c:277: Assertion "dime_ctx refs > 0" failed.

F5 Product Development is tracking this issue as ID 227062 (formerly CR142636) and ID 327393 (formerly CR142636-1).

This issue was fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2, which has been issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
