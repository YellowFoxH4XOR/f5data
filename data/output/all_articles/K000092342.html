K000092342: Azure Defender says that “Kubernetes clusters should disable automounting API credentials”

Type
Support Solution
Published
2022-08-26
Updated
2022-10-19
Source
https://my.f5.com/manage/s/article/K000092342

Description

Azure defender is telling you to disable automounting API credentials for the NGINX Ingress Controller Pod

 

 Environment

Azure Kubernetes Service (AKS)

Nginx Ingress Controller

 

 Cause

Azure defender will flag any pod in AKS that does not have the "automountServiceAccountToken: false" flag set in the deployment.

This is a security recommendation that Azure defender applies to all pods in the cluster.

The purpose is to restrict Kubernetes API access from pods in the cluster, so if one is compromised it cannot cause further damage to the rest of the cluster. See the below articles under "Additional Information" for further details.

 

This is a problem for the Nginx Ingress Controller because it requires API access to Kubernetes in order to function properly.

When you set this flag in the Ingress Controller deployment, the pod will fail to start properly.

 

 Recommended Actions

It is recommended that you ignore the Azure Defender warning for the Ingress Controller.

If you use our rbac policies that are included with the deployment manifests, we have already restricted the Ingress Controller's access to only the necessary functions needed to operate.

 

To further reduce the possibility of the Ingress Controller becoming compromised, it's recommended that you implement a strong rbac policy in your cluster to restrict access to the Ingress Controller to only trusted individuals.
