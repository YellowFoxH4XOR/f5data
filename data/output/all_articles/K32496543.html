Topic

Cross-site request forgery (CSRF) attacks work by tricking the user into making unintended requests on a website to which the user is currently authenticated.

Description

In a CSRF attack, the attacker may inject code into a web object that forces the user to request a specific URL without the user's knowledge. The user may subsequently be forced to perform an undesired action, such as transferring funds.

When you enable the CSRF protection feature in the ASM security policy, the system uses JavaScript to insert a CSRF token into the response pages of protected web applications, allowing the system to differentiate between legal requests and forged requests. The BIG-IP ASM system then verifies the ingress requests, and attempts to match the HTTP parameter value with the token value in the request.

If you enable the CSRF expiration time, users are allowed to browse the web application with the same token as long as the difference between requests is not greater than the CSRF expiration time. If a request is sent after the CSRF token expires, the BIG-IP ASM system generates the following violation to the Reporting screen:

CSRF authentication expired

Configuring the CSRF expiration time

To configure or change the CSRF expiration time, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Security > Application Security > CSRF Protection.
  3. In the Policy menu, ensure that the security policy is the one you want to update.
  4. Enter the desired number of seconds in the Expiration Time field; the default expiration time is 600 seconds.
  5. Click Save.
  6. Click Apply Policy.
