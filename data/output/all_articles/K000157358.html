Description

F5 WAF for NGINX (formally NGINX App Protect) appears to be blocking due some Attack Signatures that are set to block: false.

A review of the violation displays a long string of data. There a couple of lines that point out what is going on. They are similar to...

attack_type="Command Execution,Other Application Activity",blocking_exception_reason="N/A",date_time="2025-10-14 13:29:40",dest_port="443",ip_client="10.54.36.144",is_truncated="truncated",method="PUT",policy_name="TV2Policy",protocol="HTTPS",request_status="blocked",response_code="0",severity="N/A",sig_cves="N/A,N/A,N/A,N/A,N/A,N/A,N/A",sig_ids="200103353,200103465,200003098,200103486,200003026,200103362,200003087",sig_names="Unix/Linux ""ss"" execution attempt (Parameter),Windows ""at"" execution attempt (Parameter),Unix/Linux ""at"" execution attempt (Parameter)...",sig_set_names="{Command Execution Signatures;OS Command Injection Signatures},{Command Execution Signatures;OS Command Injection Signatures},{Command Execution Signatures;OS Command Injection Signatures}...",src_port="57074",sub_violations="N/A",support_id="1188822474533225750"
outcome="REJECTED",outcome_reason="SECURITY_WAF_VIOLATION",violations="Attack signature detected,Violation Rating Threat detected"

Environment

  • Attack Signature Sets:
  • Individual Attack Signatures
  • Attack signatures rating...
    • 0: No violation
    • 1-2: False positive
    • 3: Needs examination
    • 4-5: Threat

Cause

The underlying cause is false positive detection by multiple Low-Accuracy attack signatures during inspection of payloads...for example JPG files. Although these signatures are set to "block: false" by default, they contribute to the Violation Rating calculation if their "alarm" setting is true. When several such signatures trigger simultaneously (as seen in the list in the violation example above) on a binary file upload, the cumulative Violation Rating can exceed the default blocking threshold—resulting in the request being blocked by the "Violation Rating Threat" violation.

That "SECURITY_WAF_VIOLATION" tells us that " Attack signatures have been detected, and due to the rating accumulation the violation is..."Violation Rating Threat detected".

  • The base Default Policy enforces violations by Violation Rating, the F5 WAF for NGINX computed assessment of the risk of the request based on the triggered violations. This is true even if the other violations and signatures detected in that request have the Block flag turned OFF.
  • The base Strict Policy is customized from the base template, so it detects and blocks everything the default policy does.
    • In addition the strict policy also blocks the following:
      • Requests that have a Violation Rating of 3, "Needs examination". This occurs because the VIOL_RATING_NEED_EXAMINATION violation’s block flag is enabled in the strict policy.
      • Requests with the VIOL_EVASION violation (evasion techniques).
      • Requests with violations that restrict options in the request and response: HTTP method, response status code and disallowed file types.

Note: Other violations, specifically attack signatures and metacharacters, which are more prone to false positives, still have only Alarm turned on, without blocking, contributing to the Violation Rating as in the Default policy. 

Recommended Actions

  1. If this is an issue in your environment you may wish to set the Low-Accuracy signature set to alarm: false.
  2. Because some attack signatures are in more than one set it may be necessary to set some or all of the individual attack signatures to alarm: false.
  3. Review K14230463: Reduce false positive violations in NGINX App Protect WAF for further information.
