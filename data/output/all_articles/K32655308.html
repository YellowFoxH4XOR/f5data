Topic

You should consider using this procedure under the following conditions:

  • You want to limit the Certificate Authorities (CAs) that can issue certificates for your domain.
  • You want to deter an attackers ability to maliciously request SSL/TLS certificates for your domain from a CA.

Description

In BIG-IP DNS 14.x and later, you can configure CAA DNS records for your DNS zones. Using CAA DNS records for your domain makes it more difficult for attackers to maliciously request SSL/TLS certificates for your domain from CAs.

The DNS Certification Authority Authorization (CAA) is an Internet security policy mechanism described in RFC 8659. CAA DNS resource records allow DNS domain name holders to specify one or more CAs to issue certificates for their domain name(s); CAs that are not specified in the CAA resource records are not permitted to issue certificates for the domain name.

The CAA DNS record process operates as follows:

  • CAs must perform a DNS lookup for an organization's CAA DNS records before issuing a SSL/TLS certificate for the domain.
  • If no CAA records are found, the CA is permitted to issue a certificate for the organization's domain.
  • If CAA records are found, the CA is permitted to issue a certificate for the domain under the following conditions:
    • The CAA DNS records specifically authorizes the CA to issue certificates for the domain.
    • The CAA DNS records do not contain the issue or issuewild property tags needed to authorize a CA to issue certificates.

CAA DNS record example

An organization has the following CAA DNS records for their domain, example.com.

  • The following CAA record indicates that only the CA, ca3.example.net is authorized to issue certificates for mail.example.com:

    mail.example.com.  IN  CAA 0 issue "ca3.example.net"

  • The following two CAA records indicate that only the CAs ca1.example.net and ca2.example.net are authorized to issue certificates for example.com and all subdomains (except for the mail.example.com subdomain):

    example.com.  IN  CAA 0 issue "ca1.example.net"
    example.com.  IN  CAA 0 issue "ca2.example.net"

  • The following CAA record provides contact information about any requests for invalid certificates:

    example.com.  IN  CAA 0 iodef "mailto:admin@example.com"

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Create the CAA DNS records

To create the CAA DNS records, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Zones > ZoneRunner > Zone List.
  3. Select the name of the zone for which you will add the CAA records.
  4. Select the Resource Records tab.
  5. Select Create.
  6. For Name, enter the domain name for the CAA record.
  7. For TTL, enter the length of time that a name server can cache the resource record.
  8. For Type, select CAA.
  9. For Flags, enter one of the following values:
    • Enter 0 (zero) to indicate that the CA can use the zone information to issue a certificate regardless of whether it has a clear understanding of the property.
    • Enter 1 for critical records. The value 1 indicates that the CA can use the zone information to issue a certificate only if it has a clear understanding of the property.
  10. For Property Tag, enter one of the following values:
    • Enter issue to authorize a single CA to issue an SSL/TLS certificate for the domain name.
    • Enter issuewild to authorize a single CA to issue an wildcard SSL/TLS certificate for the domain name.
    • Enter iodef to provide contact information for any requests for invalid certificates.
  11. For Property Value, enter the following information as required:
    • Enter the Certificate Authority domain which you will authorize to issue certificates for the domain (for issue or issuewild property tags).
      Note: Refer to the Certificate Authority's site for the appropriate FQDN for the CA.
    • Enter the contact information for any requests for invalid certificates (for iodef property tags).
  12. Select Finished.
