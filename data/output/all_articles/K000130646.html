K000130646: Changing long_request_buffer_size from the CLI

Type
Support Solution
Published
2023-01-18
Updated
2023-01-18
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000130646

Description

  • Sometimes it may be necessary to set the long_request_buffer_size ASM system variable from the CLI. One reason is because an administrator may need to tune this value larger than the 30MB GUI-enforced limit.

Important: It is not recommended to set a long_request_buffer_size value to be larger than 30MB except under guidance from F5 Support as this may cause performance issues.

Environment

  • ASM/Advanced WAF

Cause

  • An error message like the following appears in /var/log/ts/bd.log: Request length exceeds defined buffer size
  • long_request_buffer_size has already been changed to the 30MB max allowed by the GUI (see K7935)

 Recommended Actions

  1. Log in to the CLI
  2. /usr/share/ts/bin/add_del_internal update long_request_buffer_size <value>
  3. tmsh restart /sys service asm


Important: The <value> is specified in bytes.  For example, to set long_request_buffer_size to 30MB, use this command: /usr/share/ts/bin/add_del_internal update long_request_buffer_size 30000000

Impact of Workaround: The restart of ASM services is disruptive to traffic on an active unit.

Note: After this setting is modified from the command line, the GUI will no longer enforce the 30MB limit and its value can be set without extra checks thereafter.
