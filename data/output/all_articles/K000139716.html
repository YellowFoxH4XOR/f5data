Description

If you notice that your devices cannot establish synchronization after deleting the one of the previous certificate (it can be device or traffic certificate), this may indicate a problem with the certificate reference in the configuration. You can see the symptoms of this behaviour in /var/log/ltm right after trying to synchronize devices: 

Apr 30 13:56:15 example-big-ip.local err mcpd[id]: 0107134a:3: File object by name (/[partition]/cert-name) is missing.

Environment

  • BIG-IP VE
  • device group with auto-sync enabled

Cause

After removal of certificate and sync, the change was not written to file. This may cause the config to be loaded from file again - but now with the reference for the cert that was previously deleted which can be found in /config/bigip.conf:

sys file ssl-cert /[partition]/cert-name {
cache-path /config/filestore/files_d/[partition]/certificate_d/:cert-name
revision 1
source-path /var/run/key_mgmt/test/ssl.crt/cert-name
}

Recommended Actions

To solve the issue and synchronize the configuration follow the steps below:

  1. Start by disabling auto-sync on both boxes: On the Min tab, click Device Management > Device Groups, then select the Manual (with Incremental Sync or Full Sync),
  2. Copy /config/partitions/[partition]/bigip.conf from device with proper configuration to second BIG-IP.
  3. Then perform MCPD Forceload on the second BIG-IP (see K13030).
  4. Force a full config sync on the first BIG-IP.

Additional Information

Once config is verified to be back in-sync, then you can re-enable auto-sync if you desire it. To avoid hitting this type of issue again, F5 strongly recommend to enable save on auto-sync.
