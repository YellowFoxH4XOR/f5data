Description

I want to view the status of the following GSLB data center objects for my BIG-IP DNS system using the tmsh utility:

  • Data center
  • Links
  • GSLB server objects

Environment

  • data center
  • virtual server
  • dns metrics

Cause

None

Recommended Actions

To view the status of the GSLB Datacenter objects for your BIG-IP DNS system using the tmsh utility, perform the following procedure:

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Run the following command:

    show gtm datacenter all detail | grep -i -e "Datacenter\|Destination\|Availability" grep -i -e Gtm::Link grep -i -e Gtm::Server grep -i -e GTM::Virtual

  3. Review the output which may appear similar to the following example:

    Gtm::Datacenter: West
      Availability : available
      | Gtm::Link: Link1     
      |   Availability : available
      | Gtm::Server: bigip2   
      |   Availability : available
         | Gtm::Virtual Server: vip
         |   Availability : available   
         |   Destination  : 172.16.0.140:80
         | Gtm::Virtual Server: vip1    
         |   Availability : available   
         |   Destination  : 172.16.0.142:80
         | Gtm::Virtual Server: vip2    
         |   Availability : offline     
         |   Destination  : 172.16.0.145:80
         | Gtm::Virtual Server: vip3    
         |   Availability : available   
         |   Destination  : 172.16.0.147:80

    For example, the above output indicates that GSLB objects in the West data center are available with the exception of the virtual server, vip2 which is marked offline.

Additional Information

For your BIG-IP DNS system, all of the resources on your network are associated with a GSLB data center. The BIG-IP DNS consolidates the metrics data collected from the servers, virtual servers, and links in the data center and uses that data to make load balancing decisions. Knowing the status of the GSLB objects in your data centers helps you understand why the system is routing traffic to a particular resource. For example, the BIG-IP DNS might send all requests to one data center when another data center is marked down.
