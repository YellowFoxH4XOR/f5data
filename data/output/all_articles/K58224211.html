Known Issue

Use of iRules with asynchronous commands on a BIG-IP APM-enabled virtual server may silently fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM virtual server is configured with an access profile.
  • You apply a custom iRule to the same virtual server that triggers on the ACCESS_SESSION_CLOSED iRule event.
  • Your iRule attempts to evoke an asynchronous command.

    For example:

    when ACCESS_SESSION_CLOSED {
    table set -subtable <your subtable name> Key_ACCESSCLOSED "<your specified value>"
    log local0. "table keys: [table keys -subtable <your subtable name> -notouch]"
    }

Impact

The table set value is inconsistently set with no error on failure.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The asynchronous value set by the iRule is inconsistently set.

Status

*In this fix, the system now logs an error message in the /var/log/apm file when an asynchronous command runs in ACCESS_SESSION_CLOSED events in iRules. You may observe a message similar to the following in the /var/log/apm file:

err tmm[<pid>]: 01490568:3: /Common/<AcessProfile_name>:<apm_session ID>: Asynchronous iRule command not supported in ACCESS_SESSION_CLOSED event

Note: This fix does not add support for asynchronous commands in ACCESS_SESSION_CLOSED events in iRules.
