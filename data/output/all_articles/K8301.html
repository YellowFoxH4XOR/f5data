Known Issue

When SSL connections using the native (Default) SSL stack receive an SSL record consisting of exactly 32 fragments, the connection will fail as the trailing MAC parameter cannot be inserted.

Note: This behavior occurs when a client generates a 16K record through an interface with a 580 byte MTU.

F5 Product Development tracked this issue as CR89559 and it was fixed in BIG-IP LTM 9.4.4 and 9.6.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF1 issued for BIG-IP version 9.3.1 for the BIG-IP 9.3 software branch, and in Hotfix-BIG-IP-9.4.3-HF2 issued for BIG-IP 9.4.3 for the BIG-IP 9.4.0 software branch. You may download these hotfixes or later versions of these hotfixes from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue, disable the native (Default) SSL stack within the SSL profile and specify compat SSL stack.

For information about the type of SSL ciphers used by the native and compat, refer to K6808: SSL Ciphers supported on BIG-IP 1500, 3400, 6400, 6800, 8400 platforms.
