Description

When reviewing IP Intelligence (IPI) event logs under Security >> Event Logs >> Network >> IP Intelligence, the Geolocation column displays "Unknown" for source IP addresses, even though:

  • The Geo-IP database is present and up-to-date
  • Network Firewall event logs display Geolocation information correctly
  • The BIG-IP system can successfully connect to BrightCloud reputation feed servers
  • The "geoip_lookup" command returns correct geolocation data for public IP addresses

    This behavior may be observed on BIG-IP AFM systems running with IP Intelligence policies configured at the global context level.

    Environment

    • BIG-IP Advanced Firewall Module (AFM)
    • IP Intelligence (IPI) with global policy configuration
    • IP Intelligence policy applied at global context
    • Local database logging enabled for IP Intelligence events

    Cause

    This behavior is expected by design. The IP Intelligence logging mechanism operates separately from the GeoIP lookup system:

    • IPI Database (iprep_lookup): Contains threat categories (botnets, scanners, spam, exploits, custom categories).
    • GeoIP Database (geoip_lookup): Contains geographic location data.

    These are two independent databases serving different purposes. IPI logging does not automatically cross-reference the GeoIP database for every IP address, because:

    • IPI operates earlier in the packet processing pipeline than GeoIP lookups to drop malicious traffic quickly
    • The IPI database does not perform GeoIP lookups as part of its threat evaluation
    • The logging mechanism for IPI-triggered events does not include automatic GeoIP database queries
    • This is a global configuration where IPI performs packet processing before GeoIP lookup to ensure rapid threat mitigation

    Recommended Actions

    Understanding Expected Behavior:

    The "Unknown" geolocation status in IP Intelligence event logs is expected and does not indicate a configuration issue or database problem.

    Manual Geolocation Lookup:

    If geolocation information is required for specific IP addresses blocked by IPI policies, perform manual lookups using the following command:

    # geoip_lookup <IP_ADDRESS>

    Example:

    # geoip_lookup 198.235.24.248

    Additional Information

    Database Independence:

    • Network Firewall logs may display geolocation information because firewall rule processing occurs at a different stage in the packet processing pipeline where GeoIP lookups are performed
    • IP Intelligence policies prioritize rapid threat identification and blocking over geolocation attribution
    • This design ensures optimal performance for security operations by allowing IPI to drop malicious traffic at Layer 3 before additional processing overhead

    Packet Processing Order:

    IP Intelligence operates at the global context level and processes packets before other security features. This early-stage processing is intentional to:

    • Minimize resource consumption on malicious traffic
    • Reduce attack surface exposure
    • Ensure fastest possible threat mitigation

    Local Database Logging Considerations:

    If experiencing issues with local database logging not recording IPI events at all (separate from the geolocation field issue), this may indicate a different problem requiring database maintenance or system reboot per K000132223.

    Logging Volume:

    Extensive logging to the local database (particularly logging all TCP events) can impact system performance. The local-db-publisher has a cap of 1.25 million messages, with oldest logs automatically removed. Review logging profiles to ensure only necessary events are captured, and consider using external log servers for high-volume logging environments.
