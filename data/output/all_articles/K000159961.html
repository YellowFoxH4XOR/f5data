Description

Under certain circumstances, large file transfers through a BIG-IP LTM virtual server can be much slower than expected when vCMP guest slot allocation is not aligned with client-facing trunk member locality. In packet captures, the affected flow may show repeated TCP Zero Window and Window Full behavior with periodic data stalls.

Environment

  • BIG-IP LTM

Cause

The issue occurs when the vCMP guest spans slots that do not have the relevant client-side trunk member interfaces. When traffic is processed on non-local slots, BIG-IP must forward traffic across the internal chassis dataplane to reach the physical egress path. This can create internal pause/backpressure behavior, BIG-IP paces the client-side flow, and BIG-IP then advertises server-side zero windows to the pool member.

  • Throughput through the affected VIP was heavily reduced compared with direct server access.
  • Zero-window events were seen on the server-side BIG-IP to pool-member direction.
  • No TCP retransmission/loss pattern was observed in the failing capture.
  • Internal host counters showed high rx_pause and drop values on internal forwarding paths compared with a working baseline.

Recommended Actions

Review the current vCMP guest slot allocation and external trunk membership, and align guest slots with the slots that carry the client-facing trunk members to reduce internal cross-slot forwarding. After the change, re-test large file transfers through the same virtual server and confirm improved transfer time with reduced TCP zero-window and window-full behavior.

tmsh list vcmp guest <GUEST-NAME> assigned-slots
tmsh list net trunk
tmsh show net interface all-stats

Note: changing guest slot allocation requires redeploying the guest and temporarily interrupts traffic, so perform this during a maintenance window.

Additional Information

  • This behavior can appear without a classic TCP loss signature.
  • Environments where guest slot allocation is aligned to external trunk-member locality are less likely to experience this pattern.
  • This condition is different from typical HSB drop-driven issues; in this case internal pause/backpressure indicators were the key signal.
