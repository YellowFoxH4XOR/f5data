Description

Sometimes while upgrading from version 13.X to 14.X the configuration wont load due a mismatch in the CLi version described in the bigip_gtm.conf

In /var/log/ltm you could find the following messages:

Aug 2 07:21:48 LTM1.Example.com notice tmsh[13019]: 01420012:5: Loading schema version: 13.1.1.3
Aug 2 07:21:49 LTM1.Example.com err tmsh[13019]: 01420006:3: Can't find specified cli schema data for 13.1.1.3
Aug 2 07:21:49 LTM1.Example.com emerg load_config_files[13017]: "/usr/bin/tmsh -n -g -a load sys config partitions all gtm-only" - failed. -- Loading schema version: 13.1.1.3 Aug 2 07:21:49 LTM1.Example.com info mprov:12797:[12797]: 'getDiskMiB_Available: 324934'
Aug 2 07:21:49 LTM1.Example.com info mprov:12797:[12797]: 'getDiskMiB_Potential: 344145' Aug 2 07:21:49 LTM1.Example.com err mcpd[8130]: 01070678:3: Full gtm configuration load failed ( Original ). 

Environment

  • Running version BIG-IP GTM  V13.X
  • Upgrade to version BIG-IP GMT V14.X
  • GTM provisioned
  • GTM provisioned in the past

Cause
Upgrade script failed to convert the schema data for bigip_gtm.conf

Recommended Actions

  1. Once you are in the 14.X partition version

  2. Verify the file /config/bigip_gtm.conf
    #TMSH-VERSION: 13.1.1.3     <---------- I will show a wrong version. gtm global-settings metrics { metrics-collection-protocols { icmp } } gtm global-settings metrics-exclusions { addresses none }

  3. Please edit with vi the bigip_gtm.conf
    #TMSH-VERSION: 14.1.0     <----------  simply change 13.1.1.3 to 14.1.0 and save.

  4. After that, you could try to load the configuration again or reboot.
    # tmsh load sys config

Additional Information

F5 has identified this behaviour with the BUG-ID 714449
