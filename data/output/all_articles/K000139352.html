Description

Traffic-group, ha-group and support pages cannot be displayed in BIG-IP GUI. It shows as 'an error occurred'. After several refresh of the page the error goes away and then again occurs back.

Journal logs:

Mar 27 16:48:39 BIGIP_ltm_1A logger[11284]: [ssl_acc] 10.10.10.10 - - [27/Mar/2024:16:48:38 +0100] "/mgmt/shared/authn/login" 200 930

Mar 27 16:48:40 BIGIP_ltm_1A logger[11284]: [ssl_acc] 10.10.10.10 - - [27/Mar/2024:16:48:40 +0100] "/mgmt/tm/cm/traffic-group/~Common~traffic-group-1" 401 381

Mar 27 16:48:49 BIGIP_ltm_1A logger[11284]: [ssl_acc] 10.10.10.11 - - [27/Mar/2024:16:48:49 +0100] "/mgmt/tm/cm/traffic-group/stats" 401 381Edit Analysis

 

Environment

  • WebUI

Cause

Logs indicate that client's source IP address is dynamically changing and being responded with a 401 on certain source address after a successful login from a different source address.

This is due to the introduction of db variable "httpd.matchclient" via ID1033837. The default value is true, which means BIG-IP will check client IP addresses that are using same tokens. This results in failure for clients which is dynamically changing within a session.

Recommended Actions

If the client IP address is expected to change on a single session (ie. dynamic NAT'ing), disable httpd.matchclient db variable and restart HTTPD.

tmsh modify sys db httpd.matchclient value false

tmsh restart sys service httpd
