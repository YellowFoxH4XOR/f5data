Known Issue

WSDL files that do not contain a correctly defined targetNamespace may fail to load when you import them using the BIG-IP ASM Configuration utility.

This issue occurs when either of the following conditions are met:

  • The WSDL file contains no targetNamespace.
  • The WSDL file contains a targetNamespace that is not correctly defined with regard to the wsdl:part element.

WSDL files with no targetNamespace may load correctly in development environments such as SoapUI and Microsoft Visual Studio, however undeclared targetNamespace attributes as shown in the following example will not be loaded by the BIG-IP ASM WSDL parser, and can cause the known issue:

<wsdl:definitions xmlns:s="http://www.w3.org/2001/XMLSchema"
xmlns:soap12="http://schemas.xmlsoap.org/wsdl/soap12/"
xmlns:mime="http://schemas.xmlsoap.org/wsdl/mime/"
xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/"
xmlns:tm="http://microsoft.com/wsdl/mime/textMatching/"
xmlns:http="http://schemas.xmlsoap.org/wsdl/http/"
xmlns:soapenc="http://schemas.xmlsoap.org/soap/encoding/"
targetNamespace=""
xmlns:wsdl="http://schemas.xmlsoap.org/wsdl/">

Impact

The system may not be able to correctly create XML profiles.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A WSDL with no targetNamespace defined may fail to load and generate an error that appears similar to the following example:

    ===>Exception: Schema Document cannot be parsed (too big or bad syntax): must not undeclare prefix at line 1, column 38, byte 38

  • A WSDL with a targetNamespace defined incorrectly with regard to the wsdl:part element may fail to load and generate an error that appears similar to the following example:

    An error has occurred while processing the schema. (Schema parsing error at: <xsd:element ref="HelloWorldResponse"/>: $VAR1 = { 'ns_uri_id' => 4, 'namespace' => '', 'local_name' => 'HelloWorldResponse', 'prefix' => '' };

Workaround

To work around this issue, you can define an appropriate targetNamespace in the WSDL file.

Impact of workaround: None

Note: This workaround is intended only as an example and may not be applicable to your configuration, depending on the design of your specific web application. For additional information, consult your WSDL documentation.

The following examples demonstrate a defined targetNamespace including an appropriate wsdl:part definition, based on the WSDL definition shown previously in this Solution:

<wsdl:definitions xmlns:s="http://www.w3.org/2001/XMLSchema"
xmlns:soap12="http://schemas.xmlsoap.org/wsdl/soap12/"
xmlns:mime="http://schemas.xmlsoap.org/wsdl/mime/"
xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/"
xmlns:tm="http://microsoft.com/wsdl/mime/textMatching/"
xmlns:http="http://schemas.xmlsoap.org/wsdl/http/"
xmlns:soapenc="http://schemas.xmlsoap.org/soap/encoding/"
targetNamespace="myNamespace"
xmlns:tns="myNamespace"
xmlns:wsdl="http://schemas.xmlsoap.org/wsdl/">

<wsdl:part name="parameters" element="tns:HelloWorld" />
</wsdl:message>
<wsdl:message name="HelloWorldSoapOut">
<wsdl:part name="parameters" element="tns:HelloWorldResponse" />
</wsdl:message>
<wsdl:message name="ProcessPacketSoapIn">
<wsdl:part name="parameters" element="tns:ProcessPacket" />
</wsdl:message>
<wsdl:message name="ProcessPacketSoapOut">
<wsdl:part name="parameters" element="tns:ProcessPacketResponse" />
</wsdl:message>
<wsdl:message name="HelloWorldHttpPostIn" />
<wsdl:message name="HelloWorldHttpPostOut">
<wsdl:part name="Body" element="string" />
<wsdl:part name="Body" element="tns:string" />
</wsdl:message>
