Known Issue

The alertd process produces a core file on the BIG-IP system.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has a pool associated with a large number of monitors.
  • A monitor status changes to down.

This issue occurs when the BIG-IP system processes long monitor status messages, while a large number of monitors are associated with a pool. For example, the alertd process may produce a core file if 40 HTTP monitors are associated with a pool member, and the monitors change status.

Impact

The alertd process restarts, and the BIG-IP system fails to send SNMP traps when the alertd process stops.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The alertd process restarts, and creates a core file in the /shared/core directory.
  • A message similar to the following example appears in a BIG-IP command line:

    # emerg logger: Re-starting alertd

  • The BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example: ..

    mcpd[5772]: 01070638:5: Pool /Common/ubunto-server member /Common/10.10.10.1:80 monitor status down. [ /Common/http: up, /Common/my_test/MyNewHTTPMonitor1: down ] [ was up for 3hrs:25mins:24sec ]
    mcpd[5772]: 01070640:5: Pool /Common/ubunto-server member /Common/10.10.10.2:80 monitor status down. [ /Common/http: up, /Common/my_test/MyNewHTTPMonitor2: down ] [ was up for 3hrs:25mins:24sec ]
    ..
