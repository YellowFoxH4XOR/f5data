Known Issue

This is the result of a known issue. As required by the IPv6 addressing scheme, an IPv6 host automatically assigns each of its interfaces a link-local IPv6 address. This functionality uses the fe80::/10 prefix and is based on the MAC address of the interface. In BIG-IP versions 9.4.2 through 9.4.6, TMM fails to accept an IPv6 static route that uses a link-local IPv6 address as its gateway.

For example, a BIG-IP Administrator would run the following command to route traffic destined to the 2000::/64 address range using the fe80::203:47ff:fe08:cb1e link-local gateway on the external VLAN:

b route 2000::/64 gateway fe80::203:47ff:fe08:cb1e vlan external

Although no errors are returned on the CLI when the command is executed, an error message is logged to the /var/log/tmm file that appears similar to the following example:

Oct 2 13:27:06 - MCP Message:
Oct 2 13:27:06 bigip1 create {
Oct 2 13:27:06 bigip1 route_static_entry {
Oct 2 13:27:06 bigip1 route_static_entry_dest 2000::
Oct 2 13:27:06 bigip1 route_static_entry_netmask ffff:ffff:ffff:ffff::
Oct 2 13:27:06 bigip1 route_static_entry_object_id 1463
Oct 2 13:27:06 bigip1 route_static_entry_type 0
Oct 2 13:27:06 bigip1 route_static_entry_vlan_name "external"
Oct 2 13:27:06 bigip1 route_static_entry_gateway fe80::203:47ff:fe08:cb1e
Oct 2 13:27:06 bigip1 route_static_entry_pool_name ""
Oct 2 13:27:06 bigip1 route_static_entry_mtu 0
Oct 2 13:27:06 bigip1 route_static_entry_transaction_id 65
Oct 2 13:27:06 bigip1 }
Oct 2 13:27:06 bigip1 }
Oct 2 13:27:06 bigip1 mcp error: 1031000 in mcpmsg_to_database

Additionally, the BIG-IP system will not forward traffic destined to the 2000::/64 address range.

F5 Product Development tracked this issue as CR116450 and it was fixed in BIG-IP 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator, or PSM Release Notes.
