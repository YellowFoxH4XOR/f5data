Description
In some cases the when log files are adjusted or removed it may cause permissions issues related to SELinux

Environment

  • BIG-IP

Cause
Manual adjustment of files in the logging directory

Recommended Actions

  1. Verify permission issue is cause for failure
    [root@den-apm02:Active:In Sync] config # logrotate -f /etc/logrotate.conf

    If the permissions aren't in a proper state the result will be similar to this:
    error: stat of /var/log/boot.log failed: Permission denied
    error: stat of /var/log/platform_check failed: Permission denied
    error: stat of /var/log/tomcat/catalina.out failed: Permission denied
  2. Remediate the permission state
    1.  The following commands disable SELinux temporarily and restarts syslog-ng

    # setenforce 0
    # bigstart restart syslog-ng

    2.  The following command restores the default security context for the /var partition

    # restorecon -R /var

    3.  The following commands re-enable SELinux and restarts syslog-ng again

    # setenforce 1
    # bigstart restart syslog-ng

    4.  The following commands relabel SELinux permissions during startup to defaults and reboots the unit

    # touch /.autorelabel
    # reboot

Additional Information
Security Hardening F5’s BIG-IP 12.0 with SELinux
