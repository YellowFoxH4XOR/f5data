Known Issue

This is the result of a known issue. Under certain traffic patterns, the BIG-IP system may incorrectly activate SYN cookie protection. This issue may occur when the system erroneously increments the number of embryonic TCP connections to a FastL4 virtual server or a self IP address.

Note: An embryonic connection refers to a connection that has not yet completed the three-way TCP handshake.

Over time, the embryonic connection count may increase and cause the BIG-IP system to activate SYN cookie protection for subsequent TCP connections for FastL4 virtual servers. This issue may also result in the BIG-IP system incorrectly activating SYN cookie protection for inbound connections to self IP addresses.

Note: The BIG-IP software includes the SYN Check Activation Threshold setting, which prevents the BIG-IP SYN queue from becoming full during a SYN flood attack. For more information, refer to K7847: Overview of BIG-IP SYN cookie protection.

You can determine whether the system is sending SYN cookies for FastL4 profiles by viewing the bigpipe profile <fastL4_profile> command output. For example, the following output indicates that virtual servers using the fastl4_test profile issued 251940 SYN cookies:

bigpipe profile fastl4_test
PROFILE FASTL4 fastl4_test parent fastL4
| idle timeout: 300 PVA acceleration: none
| Conn (open, accept, not accept, expires) = (0, 5, 0, 5)
| Errors (rx unreachable, rx bad unreachable) = (0, 0)
| Errors (rx packet, rx checksum, tx) = (0, 0, 0)
| SYNcookies (issue, accept, reject) = (251940, 0, 0)
| SYNcookies (server SYN rtx) = 0

F5 Product Development tracked this issue as ID 241649 (formerly CR130925), and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.
