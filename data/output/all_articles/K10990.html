Topic

Note: This behavior only affects Apple devices running a version of iOS older than iOS4. The behavior was changed by Apple to allow prompting for client certificates starting in iOS4.

When you enable the Request Client Certificate option for a FirePass SSL web service, FirePass sets the mod_ssl parameter SSLVerifyClient to optional for that web service. The optional parameter allows the browser to decide whether to send a client certificate in response to a certificate request. Most browsers will send a client certificate request when SSLVerifyClient is set to optional; however, the iPhone version of Safari only sends a client certificate when SSLVerifyClient is set to require. Therefore, if you configure a master group that requires client certificate authentication, users in that master group cannot log on to FirePass using an iPhone.

FirePass sets the SSLVerifyClient parameter to optional to allow the SSL handshake to complete when a browser does not present a client certificate. If the SSLVerifyClient parameter is instead set to require, users who do not have a client certificate installed will receive a browser error when attempting to access the FirePass logon page. This is not the desired behavior for environments with mixed authentication methods. Additionally, even in environments where all master groups require client certificate authentication, users who cannot reach the FirePass logon page due to a lack of a client certificate may incorrectly assume that the FirePass controller is inaccessible or not functioning properly.

F5 Product Development is tracking a request for enhancement (RFE) as ID 294218 (formerly CR134070) for a new configuration setting that changes the SSLVerifyClient parameter to require on a per-web service basis.
