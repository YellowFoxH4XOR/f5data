Description

iQuery failures contribute to most issues encountered within the GTM/ DNS infrastructure and having a way to identify failing iQuery connections is useful for mitigating impact. BIG-IP does not currently implement an SNMP OID that returns failed iQuery connection counts. As an alternative,  a custom SNMP OID can be configured.
This allows alerting on unexpected iQuery failures using SNMP monitoring, which can be used to mitigate disruption when iQuery failures occur.
This OID returns the current count of iQuery connections that are either in the 'not-connected' or 'connecting' state, which implies that there is a failure.

In a fully-functional iQuery mesh, all servers will show as connected, and this OID will return 0.
The count will increase if iQuery failures occur, and the connections are not re-established.

Setting an appropriate threshold for iQuery failures and a suitable poll interval is dependent on the environment, but iQuery failure can introduce instability into BIG-IP DNS deployments, so monitoring for iQuery failures can allow a rapid response and resolution.

Environment

  • BIG-IP GTM/ BIG-IP DNS implementations
  • SNMP

Cause

None

Recommended Actions

To configure a custom SNMP OID that returns the iQuery connection failure count, perform the following procedure:

1. Log in with administrative privileges to the command line of the target device.
2. Using a text editor, create the following file

    /config/snmp/iqueryfailures.sh

3. Enter the following command syntax into the /config/snmp/iqueryfailures.sh file

#!/bin/sh
    count=$(tmsh show /gtm iquery |  grep -e "not-connected" -e "connecting" | wc -l)
  echo $count       
4. Save the changes.
5. To change the file permissions, type the following command:

 chmod 755 /config/snmp/iqueryfailures.sh
6. Using a text editor, create the following file:
    /config/snmp/custom_mib.tcl
7. Enter the following command syntax in the /config/snmp/custom_mib.tcl file:

Note: if you have existing custom mibs in the custom_mib.tcl file, you will need to change the OID number to suit

register_mib ".1" iqueryfailure_count GAUGE
    proc iqueryfailure_count {} {
        set status [catch { exec /bin/bash /config/snmp/iqueryfailures.sh } result]
        return $result
    }


8. Save the changes.
9. To restart the SNMP service, type the following command:

tmsh restart /sys service snmpd
10. To verify that the workaround is functional, type the following command:
    snmpwalk -Os -c public -v 2c localhost .1.3.6.1.4.1.3375.2.100.1
