Description
The BIG-IP APM  system's default logging levels are set to capture useful information about BIG-IP APM system events while maintaining minimal impact on system resources. There may be an occasion when the default logging level is not providing enough detail, and you have to enable Debug logging to gather more detailed diagnostic information.

IMPORTANT: F5 does performance and sizing tests with logging set at default levels. While our products offer more verbose logging at debug level for troubleshooting purposes, we do not recommend using debug logging in production scenarios because the additional load incurred may cause instability. If debug logging is required for your deployment, the system capacity may be greatly reduced.  In rare cases, the additional resource demands of Debug logging may cause poor performance or a system failure if the BIG-IP system is at high resource utilization before you enable Debug logging.

Increasing the log levels to investigate an issue should only be done by increasing the level during an active troubleshooting event.   As soon as the Troubleshooting event has completed, you should return the Log levels to their default level.

APM Logs are generally found in:  Access > Overview > Event Logs > Settings  where they can be applied to specific APM profiles. 

There are 2 APM Log setting options located in:  System > Logs > Configuration > Options that should not be used unless explicitly directed by F5 Support during an active Support Incident. 

  • Portal Access
  • Policy Trace

 Portal Access logging injects javascript in to the Portal access traffic stream, which will cause issues with your application behavior.   It also modifies the use of the Caching function to use cache-fm-debug.js instead of cache-fm.js, resulting in detrimental effects on speed and reliability.    



Policy Trace logging injects policy tracing information for per-session and per-request policies which includes the policy execution path with policy item information in the APM log.   Modifying this value may increase the verbosity of the logs to an unmanageable level, resulting in poor performance or system failure.   Most of this logging can be seen other logs with less impact.



Environment

  • BIG-IP APM
  • Some issue is requiring troubleshooting
  • Default Log levels are not sufficient to record the required information.

Cause
None

Recommended Actions

Impact of procedure: Enabling APM debug logging may cause excessive logging in a system with a large number of user logins. You should only enable debug logging when troubleshooting and disable debug logging after you've finished troubleshooting. 

  1. Log into the Configuration utility.
  2. For BIG-IP 13.x and later, navigate to Access > Overview > Event Logs > Settings.

    Note: For BIG-IP 12x, navigate to Access Policy > Event logs > Log Settings.

  3. Click Create.
  4. Type a name for Name and select the Enable Access System Logs check box.
  5. Click Access System Logs.
  6. For the affected logging object,  select the minimum level required to show the information.
  7. Click Access Profiles.
  8. In the Available list, click the appropriate access profile and move it to the Selected list.
  9. Click OK.
  10. Select the "default-log-setting" log profile
  11. Click Access System Logs.
  12. Click Access Profiles.
  13. Move the Access profile that you have enabled in the new policy to the right column.
  14. Click OK. 

Procedure back out

To revert the changes to the access profile logging, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. For BIG-IP 13.x and later, navigate to Access > Overview > Event Logs > Settings.

    Note: For BIG-IP 12.x, navigate to Access Policy > Event Logs > Log Settings.

  3. Select the check box for the newly created log settings.
  4. Click Delete.
  5. Click Yes to confirm deletion of the debug log settings and remove the settings from the access profile.
  6. Select the "default-log-setting" log profile
  7. Click Access System Logs.
  8. Click Access Profiles.
  9. Move the Access profile that you have enabled in the new policy to the left column to enable Default logs for the policy
  10. Click OK.
