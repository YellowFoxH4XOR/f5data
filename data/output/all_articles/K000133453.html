Description

FIPS Synchronization Failure with an error message.
 

DEBUG: officer_login: Cfm2LoginHSM returned: HSM Error: RET_USER_LOGIN_FAILURE
 

Environment

  • FIPS Module
  • High Availability Pair

Cause

FIPS synchronization fails due to mismatched Security Officer password used between the existing device's FIPS and the RMA device's FIPS card.

 

# tmsh fips-card-sync -v -u root 10.10.10.10

Enter FIPS Security Officer password for the local device:

or press <ENTER> if same as the local one:

Recommended Actions

If the Security Officer password is known, use that Security Officer password to initialize the RMA device's FIPS card.

Note: Due to the security nature of FIPS, there is no method available to recover the FIPS Security Officer's password.

If the Security Officer's password is unknown, you will need to rebuild and restore the FIPS keys to both devices using a new Security Officer password. Use the following steps as a guideline:

  1. Import and convert the SSL keys into the RMA unit as FIPS keys.
  2. Verify the RMA unit is working with the newly converted FIPS keys.
  3. Reinitialize FIPS on the peer device with the unknown Security Officer password using the new FIPS domain name and new Security Officer password.

    Note: Running the fipsutil init command deletes all keys in the HSM and makes any previously exported keys unusable.
  4. Sync the FIPS cards.

Further information can be found from the manual Hardware HSM Setup and Administration .

Additional Information

For FIPS synchronization to be successful, the FIPS domain and Security Officer Passwords are required. It is recommended to use the same FIPS password for each device in the HA pair; it is not required. FIPS synchronization will fail if any of the requirements are not met.
