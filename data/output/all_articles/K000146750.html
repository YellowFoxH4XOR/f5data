K000146750: Why might a visitor be blocked when you specifically allowed traffic from their country?

Applies to

Source

Description

You have a load-balancer with a service policy explicitly allowing a specific country, however a visitor from this country is blocked. What is happening, and what can you do?

Environment

  • F5® Distributed Cloud (XC) load-balancer

Answer/Recommended Actions

You may contact our support team and request an update of the GeoIP database to solve this issue for your visitors, but there’s a faster way to allow them: adding another policy for all the IP addresses that are wrongly blocked.

Assuming that you already have a service policy X allowing users from a specific country:

  1. In the Load-balancer service, select the namespace that your load-balancer belongs to
  2. Navigate to the Security > Service Policies > Service Policies section
  3. Create a new service policy and select Allowed Sources in the Rules section
  4. The form now gives you the possibility to configure an IPv4 Prefix List
  5. Click Configure to add one
  6. For each of the IP addresses that were blocked, add an entry. Make sure that you enter them in the form of a CIDR (ending in /32 when you want to enter a single IP address). For example, to add the address 192.0.2.4, simply type 192.0.2.4/32.
  7. Click Apply
  8. Ensure the Default action is set to Next policy
  9. Click Save and exit
  10. Go to Manage > Load-balancer > HTTP Load-balancer section
  11. Select the load-balancer you need to allow traffic from these IP addresses to
  12. Edit the configuration
  13. Scroll down to the Security section and find the Service policies entry
  14. Select Apply Specified Service Policies if it was not already selected
  15. Click Configure
  16. In the form presented to you, find the policy you just created and place it at the top
  17. Find the policy X that allows visitors from the country you already had, and place it just below
  18. Click Apply
  19. Click Save and exit

Visitors from the IP addresses that were blocked should now be allowed.

Cause

Knowing in which country an IP address is located is not automatic, as IP addresses are not allocated on a geographical basis (at least not down to the country). Moreover, address blocks are bought and sold, change owners and sometimes countries. Therefore, knowing in which country an IP address is located relies on a so-called "GeoIP database" which is regularly updated with the changes. However, that kind of database is never updated ahead of a change, always after. Moreover, it’s not stored in a central location as a service available to anyone, but rather distributed as a copy of the main database to operators (like F5) who purchased it, and the local copy of the operator is updated on a regular basis (monthly, typically). All that means that by design, its local information is never 100% up-to-date.

A direct consequence is that, if a visitor is reaching your website or app from an IP address that has recently changed country, F5XC local copy of the GeoIP database might still see it located in the previous country it belonged to and our load-balancer would in turn consider the visitor is coming from a country you did not allow.
