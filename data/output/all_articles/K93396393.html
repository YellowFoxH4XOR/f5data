K93396393: SSID Message length exceeds maximum handshake size

Type
Support Solution
Published
2022-03-17
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.2
Source
https://my.f5.com/manage/s/article/K93396393

Description

Informational messages similar to the example below are seen logged to the /var/log/ltm file.

SSID Message length exceeds maximum handshake size set for TMM

Environment

  • BIG-IP LTM running software version 11.4.0 or later

Cause

The BIG-IP system encountered a very large SSL handshake record, exceeding the F5 handshake record length of (default 32KB), from an SSL client/server. In most cases, this is due to large SSL certificate chains that are exhausting the SSL handshake buffer.

Recommended Actions

When the SSL handshake record length of 32KB is exceeded, BIG-IP will report the /var/log/ltm log info message and switch to PASSTHROUGH mode where the BIG-IP system simply forwards the encrypted SSL request over to the back-end server(s) without decryption absolving itself from any SSL related workload. One may want to consider increasing the maxhandshakesize value as deemed necessary in order to avoid any potential functionality loss while processing (iRules, etc) of the certs; otherwise the log messages can simply be ignored as informational only.

Additional Information

Starting in BIG-IP 11.4.0, the size of the SSL handshake buffer is configurable. Under certain conditions, you may want to increase the default 32KB size of the SSL handshake buffer on the BIG-IP system. Refer to the following procedure for instructions on how to increase the size of the SSL handshake buffer length on the BIG-IP system.

Note: Proceed with caution as increasing the maxhandshakesize value increases the amount of system memory that is allocated to the processing of large handshake records.  

Procedures:

Increasing the size of the SSL handshake buffer if deemed necessary:

Note: The SSL handshake buffer maximum message size is set by the tmm.ssl.maxhandshakesize system database key. 

Impact of procedure: The impact of the suggested procedure depends on the specific environment. F5 recommends that you test any such changes during a maintenance window, with consideration to the possible impact on your specific environment.

  1. Log in to the tmsh utility by typing the following command:
    tmsh

  2. To list the current size of the SSL handshake buffer, type the following command:
    list sys db tmm.ssl.maxhandshakesize

  3. The size of the SSL Hanshake buffer is displayed, as in the following example:
    sys db tmm.ssl.maxhandshakesize {
           value "32768"
       }

  4. To increase the size of the SSL Handshake buffer, use the following command syntax:
    modify sys db tmm.ssl.maxhandshakesize value <value>

  5. In the previous syntax, <value> is the number of bytes of memory to allocate.
    For example, to double the size of the SSL handshake buffer from the default value of 32768, type the following command:

       modify sys db tmm.ssl.maxhandshakesize value 65536

       [root@march247:Active:Standalone] config # tmsh list sys db tmm.ssl.maxhandshakesize
       sys db tmm.ssl.maxhandshakesize {
           value "65536"
       }

  6. Save the change by typing the following command:
    save /sys config
