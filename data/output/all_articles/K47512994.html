Topic

You should consider using these procedures under the following conditions:

  • You want to back up your rSeries system configuration data.
  • You want to restore your rSeries system configuration data.

Description

The confd process manages the F5OS-A configuration on an rSeries system. The system stores the configuration in its configuration database. When you back up the configuration, the backup file contains data that includes the following:

  • SNMP configuration
  • Portgroup configuration
  • VLAN configuration
  • Tenant configuration

    Note: The tenant configuration contains tenant name, type, image, management IP address, gateway, VLANs, assigned vCPUs, memory, storage size, and so on. It does not include the BIG-IP configuration of the tenant. To create a backup copy of the BIG-IP configuration of the tenant, you must perform the backup in the tenant itself. For information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

  • DNS servers
  • Network Time Protocol (NTP) servers
  • Logging severity settings
  • User Management settings
  • Password policy settings

Note: Beginning in F5OS-A versions that contain the fix for ID 1080041, when the database config-backup is performed, the license file is not included in the backup file. You must manually backup the appliance license information (Registration key and any add-on keys).

The backup file is saved in an XML ASCII format and does not require a file extension. The backup file is located in the /var/F5/system/configs directory on the file system, which is also known as the configs/ file path when you are logged in as the administrator user. When you are logged in to the system CLI as the administrator user you can use the file list path configs/ command to list the backup files available in the directory.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrator user access to the rSeries system command line (CLI).

(Required) Set the primary key

Important: Before saving the configuration file, you must complete this procedure in case you need to restore the config file on a different appliance.

The F5 rSeries system uses a primary key to perform encryption and decryption of highly sensitive passwords/passphrases in the configuration database. You should periodically reset this primary key for additional security. You should set this primary key prior to performing any configuration backup if you have not already done so. However, F5 recommends setting this primary key before every backup to avoid unnecessary issues due to intermittent configuration or upgrade issues. In the case of a configuration migration such as moving configuration to a replacement device due to RMA, it is important to set the primary key to a known value so that the same key can be used to decrypt the passwords/passphrases in the configuration restored on the replacement device.

  1. Log in to the CLI with the administrator user.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. Set the strings for a passphrase and salt by entering the following command syntax:

    system aaa primary-key set passphrase

    The system prompts you separately for the passphrase and its confirmation, followed by the salt and its confirmation similar to the following example:

    Value for 'passphrase' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'confirm-passphrase' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'salt' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'confirm-salt' (<string, min: 6 chars, max: 255 chars>): ********

  4. Exit the configuration mode terminal by entering the following command:

    end

  5. Check the primary key hash by entering the following command:

    show system aaa primary-key state hash

    Output appears similar to the following:

    system aaa primary-key state hash <hash_key>

    Note that the hash key can be used to check and compare the status of the primary key on both the source and the replacement devices.

  6. Record the salt and passphrase strings for later use because they are required to restore the configuration on a replacement system.

    For more information, refer to Manual Chapter : Additional System Tasks in the F5 rSeries Systems: Administration and Configuration manual.

Back up your rSeries system configuration data using the webUI

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the webUI of your rSeries system as the administrator user.
  2. Go to SYSTEM SETTINGS > Configuration Backup.
  3. Select Create.
  4. For Name, enter the name you want to use for the configuration backup file.
  5. Select Create.
  6. Prior to F5OS 2.0.0, the webUI displays a message to indicate the status of the configuration backup. Select Dismiss to exit.
  7. If you need to move the backup file off the system, the system allows you to directly download it from the SYSTEM SETTINGS > Configuration Backup page starting in F5OS-A 1.8.0. Select Download next to the configuration backup file you want to download to your local workstation. For versions prior to F5OS-A 1.8.0 or if you prefer to export the backup file to a remote HTTPS server, refer to the Export a backup file using the webUI procedure.

Back up your rSeries system configuration data using the CLI

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of your rSeries system as the administrator user.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. Back up the configuration data by using the following command syntax:

    system database config-backup name <backup file name>

    For example, to save the configuration data to a backup file named myconfig.backup, enter the following command:

    system database config-backup name myconfig.backup

  4. Exit the configuration mode terminal by entering the following command:

    exit

  5. If you need to move the backup file that you created in step 3 off the system, refer to the Export a backup file using the CLI procedure.

Restore your rSeries system configuration data

If the configuration backup file is located at a remote location, you should import the backup file prior to restoring the configuration. To import the backup file, refer to the Import a backup file using the CLI procedure. Restoring configuration data from a backup file can only be performed in the system CLI. To restore the configuration data from a backup file, perform the following procedure:

Impact of procedure: Performing this procedure overrides any existing configuration on your rSeries system with the configuration data in the backup file.

  1. Log in to the CLI of your rSeries system as the administrator user.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. If you are restoring configuration data to a different location, you must set the appliance to use the same passphrase string and salt string as the original appliance does by entering the following command syntax:

    system aaa primary-key set passphrase

    The system prompts you separately for the passphrase and its confirmation, followed by the salt and its confirmation similar to the following example:

    Value for 'passphrase' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'confirm-passphrase' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'salt' (<string, min: 6 chars, max: 255 chars>): ********
    Value for 'confirm-salt' (<string, min: 6 chars, max: 255 chars>): ********

    Note: Before you run the previous command, you can also check the hash by running following command and comparing it to the one you have already saved:

    show system aaa primary-key state hash

  4. Restore the configuration data by using the following command syntax:

    system database config-restore name <backup file name>

    For example, to save the configuration data to a backup file named myconfig.backup, enter the following command:

    system database config-restore name myconfig.backup

    The system displays a warning similar to the following example about requiring a clean configuration prior to restoring to a previous configuration:

    A clean configuration is required before restoring to a previous configuration.
    Please perform a reset-to-default operation if you have not done so already.
    Proceed? [yes/no]:

    F5 recommends that you perform a reset-to-default operation to clear the existing configuration before attempting to restore to a previous configuration. For more information about performing a reset-to-default operation, refer to K20024872: Restoring the rSeries configuration to factory default settings. If you have completed the reset-to-default operation on your rSeries system, enter yes to proceed with the configuration restoration to the system.

  5. Exit the configuration mode terminal by entering the following command:

    exit

  6. The appliance may automatically reboot.

Export a backup file using the webUI

You can export a backup file from your rSeries system to a remote HTTPS server using the webUI or download the backup file to your workstation. To do so, perform the following procedure:

Note: For the transfer to complete properly, the remote HTTPS server must be able to accept PUT/POST requests and use an SSL certificate signed by a public certificate authority (CA). If the remote HTTPS server is using a self-signed SSL certificate or an SSL certificate signed by a non-public CA, you can check the Ignore Certificate Warnings to disable verification of the remote system identity.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the webUI of your rSeries system as the administrator user.
  2. For F5OS 2.0.0 and later, go to System Monitoring > File Utilities. Prior to F5OS 2.0.0, go to SYSTEM SETTINGS > File Utilities.
  3. Under File Transfer Operations, for Base Directory, select configs.
  4. For configs, select your backup file.
  5. If you are downloading the backup file to your workstation, select Download. The webUI prompts you for the location on your workstation to save the backup file.
  6. If you are exporting the backup file to a remote HTTPS server, select Export. The webUI displays File Export.
  7. For Server (F5OS 2.0.0 and later) or Server URL (prior to F5OS 2.0.0), enter the remote HTTPS server URL.
  8. If the remote HTTPS server requires basic authentication, for Username and Password, enter the username and password.
  9. If you want to skip certificate warnings when exporting files to the remote HTTPS server, select the Ignore Certificate Warnings check box.
  10. Select Export File.
  11. You can monitor the status of the file export under File Transfer Status.

Export a backup file using the CLI

You can export a backup file from your rSeries system to a remote HTTPS or SCP or SFTP server using the CLI. To do so, perform the following procedure:

Note: For the transfer to complete properly, the remote HTTPS server must be able to accept PUT/POST requests and use an SSL certificate signed by a public CA. If the remote HTTPS server is using a self-signed SSL certificate or an SSL certificate signed by a non-public CA, you can use the insecure option to disable verification of the remote system identity.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of your rSeries system as the administrator user.
  2. To verify that the backup file exists in the directory, enter the following command:

    file list path configs/

  3. To export a backup file, use the following syntax:

    file export local-file <path/to/backup_file> remote-host <host_address> remote-file <path/to/remote_file> protocol <https | scp | sftp> [username <user>] [insecure]

    For example, to export the myconfig.backup chassis backup file to the remote SCP host at 192.168.207.97, enter the following command:

    file export local-file configs/myconfig.backup remote-host 192.168.207.97 remote-file myconfig.backup protocol scp username myscphostadmin insecure

    Note: If the export using scp/sftp fails and you observe the error message Host identity could not be verified from the file transfer-status command output, you may want to refer to K000162039: Error "Host identity could not be verified" when exporting/importing file from/to F5OS using scp/sftp to/from a remote host for information about resolving it.

  4. To check the status of the file transfer, enter the following command:

    file transfer-status

    When the transfer is complete, the system displays output similar to the following example:

    result
    S.No.|Operation  |Protocol|Local File Path           |Remote Host         |Remote File Path          |Status            |Time                
    1    |Export file|SCP     |configs/myconfig.backup   |192.168.207.97      |myconfig.backup           |         Completed|Tue Dec 14 07:33:06 2021

Import a backup file using the webUI

You can import a backup file from a remote HTTPS server to your rSeries system using the webUI or upload a backup file from your workstation. To do so, perform the following procedure:

Note: For the transfer to complete properly, the remote HTTPS server must be able to accept PUT/POST requests and use an SSL certificate signed by a public CA. If the remote HTTPS server is using a self-signed SSL certificate or an SSL certificate signed by a non-public CA, you can check the Ignore Certificate Warnings to disable verification of the remote system identity.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the webUI of your rSeries system as the administrator user.
  2. For F5OS 2.0.0 and later, go to System Monitoring > File Utilities. Prior to F5OS 2.0.0, go to SYSTEM SETTINGS > File Utilities.
  3. Under File Transfer Operations, for Base Directory, select configs.
  4. If you are uploading the backup file from your workstation, select Upload. The webUI prompts you for the location of the backup file on your workstation.
  5. If you are importing the backup file from a remote HTTPS server, select Import. The webUI displays File Import.
  6. For URL, enter the full URL of the backup file on the remote HTTPS server.
  7. If the remote HTTPS server requires basic authentication, for Username and Password, enter the username and password.
  8. If you want to skip certificate warnings when importing files to the remote HTTPS server, select the Ignore Certificate Warnings check box.
  9. Select Import File.
  10. You can monitor the status of the file export under File Transfer Status.

Import a backup file using the CLI

You can import a backup file from a remote HTTPS or SCP or SFTP server to your rSeries system using the CLI. To do so, perform the following procedure:

Note: For the transfer to complete properly, the remote HTTPS server must be able to accept PUT/POST requests and use an SSL certificate signed by a public CA. If the remote HTTPS server is using a self-signed SSL certificate or an SSL certificate signed by a non-public CA, you can use the insecure option to disable verification of the remote system identity.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the CLI of your rSeries system as the administrator user.
  2. To import a backup file, use the following syntax:

    file import remote-host <host_address> remote-file <path/to/remote_file> local-file <path/to/backup_file> protocol <https | scp | sftp> [username <user>] [insecure]

    For example, to import the mytest.backup chassis backup file to the remote host at 192.168.207.97, enter the following command:

    file import remote-host 192.168.207.97 remote-file mytest.backup local-file configs/mytest.backup protocol scp username myscphostadmin insecure

    Note: If the import using scp/sftp fails and you observe the error message Host identity could not be verified from the file transfer-status command output, you may want to refer to K000162039: Error "Host identity could not be verified" when exporting/importing file from/to F5OS using scp/sftp to/from a remote host for information about resolving it.

  3. To check the status of the file transfer, enter the following command:

    file transfer-status

    When the transfer is complete, the system displays output similar to the following example:

    result 
    S.No.|Operation  |Protocol|Local File Path           |Remote Host         |Remote File Path          |Status            |Time                
    1    |Export file|SCP     |configs/myconfig.backup   |192.168.207.97      |myconfig.backup           |         Completed|Tue Dec 14 07:33:06 2021
    2    |Import file|SCP     |configs/mytest.backup     |192.168.207.97      |mytest.backup             |         Completed|Tue Dec 14 07:39:23 2021

  4. To verify that you imported the backup file into the directory, enter the following command:

    file list path configs/
