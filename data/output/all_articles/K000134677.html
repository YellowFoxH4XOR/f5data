K000134677: Configuring sFlow monitor on vCMP Guest

Type
Support Solution
Published
2024-07-16
Updated
2024-07-16
Applies to

Source
https://my.f5.com/manage/s/article/K000134677

Description

You enable sFlow monitor on vCMP Guest and sFlow data is reaching the sFlow collector successfully. However, the collector is ignoring the data as the vCMP Guest is using 0.0.0.0 as Agent Address.

tcpdump -nnvvvXi 0.0 -s0 port 6343

19:45:04.793885 IP (tos 0x0, ttl 255, id 18270, offset 0, flags [DF], proto UDP (17), length 752)
  10.7.7.1.30337 > 10.7.7.3.6343: [bad udp cksum 0x24ff -> 0x503f!] sFlowv5, IPv4 agent 0.0.0.0, agent-id 1, seqnum 748, uptime 241697000, samples 6, length 724

 

Environment

  • vCMP Guest
  • sFlow monitoring

Cause

Bug ID 645635

 Recommended Actions

Configure cluster blade IP addresses on the vCMP guest.

For example, to set the slot-specific management IP address on a VCMP guest which runs on a single slot, use a command similar to the following:

tmsh modify sys cluster default members { 1 { address 10.200.71.133 } }

Perform a traffic capture to confirm the sFlow data is populating the Agent IP using the cluster blade IP on the vCMP Guest:

19:50:55.048821 IP (tos 0x0, ttl 255, id 26887, offset 0, flags [DF], proto UDP (17), length 752)
  10.7.7.1.30337 > 10.7.7.3.6343: [bad udp cksum 0x24ff -> 0xf87f!] sFlowv5, IPv4 agent 10.200.71.133, agent-id 1, seqnum 818, uptime 242048000, samples 6, length 724
