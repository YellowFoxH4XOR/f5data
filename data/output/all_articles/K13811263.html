Known Issue

The BIG-IP system may not evenly disaggregate Internet Control Message Protocol (ICMP) traffic if there is not enough entropy from the ICMP header.

This issue occurs when all of the following conditions are met:

  • ICMP traffic has low entropy in the ICMP header.
  • You configure the BIG-IP system to disaggregate traffic.

Impact

The BIG-IP system may not efficiently load balance ICMP traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You notice that the system does not efficiently load balance ICMP traffic between Traffic Management Microkernel (TMM) processes.

Resolution

Status

F5 Product Development has assigned ID 507240 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

* In BIG-IP 13.0.0 and later, you must use the tmsh modify net dag-globals icmp-hash ipicmp command to enable ICMP disaggregation.
** In BIG-IP 12.1.3, you must use the tmsh modify sys db dag.icmp_hash value ipicmp command to enable ICMP disaggregation.

Note: You cannot use the ICMP disaggregation feature if the BIG-IP system translates IP addresses for ICMP traffic.
