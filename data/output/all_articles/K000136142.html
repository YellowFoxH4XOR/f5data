Description

AWS Cloud BIG-IP VE were taking a very long time on rebooting which take about an hour plus to come up and pool doesn't come online during the booting time.
 

Environment

  • BIG-IP
  • LTM
  • AWS Cloud
  • VE
  • Booting time very slow
     

Cause

Insufficient memory, during starting up the AWS BIG-IP VE, it would have very limited host memory, which can result in frequent memory thrashing.
 

Recommended Actions

Allocating additional memory for the VE should effectively address the issues. While 5GB might do the job, a more reliable solution would involve allocating 6GB of memory.
In addition, consider reallocating more host memory. This isn't related to the hypervisor host; it's the standard 4KB page memory that remains after allocating huge pages to tmm.

1. Once you have increased memory for the AWS BIG-IP VE, you can adjust the memory allocation for TMOS as follows:

# tmsh modify sys db provision.extramb value 1000

2. If not maybe reserve smaller ram instead (so as not to take so much from tmm):

# tmsh modify sys db provision.extramb value 500

Important: Changing the value of "provision.extramb" does not sync automatically between cluster peers. You need to manually change it on each peer one at a time. Keep in mind that when you change this value, it may cause a few minutes of service disruption.
