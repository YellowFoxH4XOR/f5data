Known Issue

Concurrent session limits for the BIG-IP APM system may not be distributed properly during the licensing process

This issue occurs when the following condition is met:

  • The APM Base feature module is licensed on a VIPRION chassis together with either of the following:
     
    • The APM Max Access Sessions feature module
    • The APM Max CCU feature module

For example, if the APM Base and APM Max CCU modules are licensed together, the accumulated session limits are reflected in the /config/bigip.license file:

Note: The APM Base and APM Max feature modules are not intended to be licensed together on the same BIG-IP system and should be applied separately.

# Accumulated Tokens for Modules
# APM, Base, C4800 apm_access_sessions 200000 key
# APM, Max CCU, C4800 apm_access_sessions 200000 key
#
# Accumulated Tokens for Modules
# APM, Base, C4800 apm_sessions 500 key
# APM, Max CCU, C4800 apm_sessions 200000 key
#
# Accumulated Tokens for Modules
# APM, Base, C4800 apm_urlf_limited_sessions 80000 key
# APM, Max CCU, C4800 apm_urlf_limited_sessions 80000 key
#
apm_access_sessions : 400000
apm_sessions : 200500
apm_urlf_limited_sessions : 160000

In this example, the values for apm_access_sessions, apm_sessions, and apm_urlf_limited_sessions are incorrectly added together resulting in larger than expected values. This can effectively double the values in some cases, which may exceed the platform's capabilities.

Impact

The licensing limits for user access sessions accumulate improperly, resulting in increased values. BIG-IP APM systems running near capacity can experience system instability and degraded performance.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The following features show increased values in the /config/bigip.license file:
     
    • apm_access_sessions
    • apm_sessions
    • apm_urlf_limited_sessions
  • Clients attempting to access resources using the BIG-IP APM system receive server errors.
  • The BIG-IP APM system becomes unresponsive or is unable to process traffic
  • TMM on the affected system generate error messages to the /var/log/tmm file

Workaround

The licensing server has been updated with the correct values for VIPRION platforms. To work around this issue, you can renew the license for the BIG-IP system using the Configuration utility or the Traffic Management Shell (tmsh). To do so, perform one of the following procedures:

Impact of workaround: Performing the following procedures will cause a brief traffic disruption while the license is re-activated.

Renewing the license using the Configuration utility

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > License and click Re-activate.
  3. Select Automatic (requires outbound connectivity) and the appropriate Outbound Interface, as needed.
  4. To re-activate the license, click Next.

Renewing the license using tmsh

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To re-activate the license, type the following command:

    install /sys license
