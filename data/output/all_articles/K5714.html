Issue

When you associate a cookie persistence profile with a virtual server, the BIG-IP system inserts a cookie into the HTTP response, which clients include in subsequent HTTP requests until the cookie expires. The cookie expiration is based on the time-out configured in the persistence profile. The cookie value contains the encoded IP address and port of the destination server. For information about BIG-IP cookie encoding and how to decode cookies, refer to the Supplemental Information section.

The following are some of the most common reasons for cookie persistence failure:

  • Cookie persistence timer issues
  • BIG-IP HTTP parsing

Cookie persistence timer issues

When you configure cookie insert or cookie rewrite persistence profiles, the BIG-IP system encodes information about the server to which the client connects and uses the Set-Cookie header to store the encoded information in the HTTP response from the server. The BIG-IP cookie uses the following format:

BIGipServer<pool_name>; expires=<expiration_date>; path=<path>

Cookie persistence timer issues are normally the result of one or both of the following issues:

  • The system clocks are not correct

    The BIG-IP system sets the expires value in the cookie based on the system clock. If either the BIG-IP or the client system clock is set incorrectly, the cookie may appear to be expired to the client.

  • The time zone is not correctly offset from Greenwich Mean Time (GMT)

    When the client receives the cookie, the expiration date is in GMT time. The client must then convert the expiration date to the local time. If the client does not convert the time correctly there may be cookie persistence issues.

Troubleshooting cookie persistence timer issues

To mitigate cookie persistence timer issues, you can try the following:

  • Ensure the date and time are set correctly on the BIG-IP system

    For information about setting the time and date on the BIG-IP, refer to K3381: Setting the time and date on the BIG-IP system.

  • Configure a public NTP server

    For information about configuring the BIG-IP system to use a public NTP server, refer to K3122: Using the BIG-IP Configuration utility to add an NTP server.

    Note: You may also consider configuring a session cookie persistence profile. For information about configuring a session cookie persistence profile, refer to K7168: Configuring a session cookie persistence profile.

BIG-IP HTTP parsing

By default, the BIG-IP system performs load balancing for each TCP connection rather than for each HTTP request. This behavior may cause the virtual server using cookie persistence to send HTTP requests to the wrong pool member. For more information about this behavior, refer to K7964: The BIG-IP system may appear to ignore persistence information for Keep-Alive connections.
