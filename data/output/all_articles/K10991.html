K10991: Proxy IP addresses may be inaccessible when created using the proxy-address count flag

Known Issue

When you use the count flag with the proxy-address command, the ARX system should configure a sequential range of proxy IP addresses.

For example:

ip proxy-address 192.168.1.10 255.255.255.0 vlan 10 count 12

The example command should produce entries similar to the following in the running-config:

ip proxy-address 192.168.1.10 255.255.255.0 vlan 10 mac 1 processor 2.1
ip proxy-address 192.168.1.11 255.255.255.0 vlan 10 mac 2 processor 2.2
ip proxy-address 192.168.1.12 255.255.255.0 vlan 10 mac 3 processor 2.3
ip proxy-address 192.168.1.13 255.255.255.0 vlan 10 mac 4 processor 2.4
ip proxy-address 192.168.1.14 255.255.255.0 vlan 10 mac 5 processor 2.5
ip proxy-address 192.168.1.15 255.255.255.0 vlan 10 mac 6 processor 2.6
ip proxy-address 192.168.1.16 255.255.255.0 vlan 10 mac 7 processor 2.7
ip proxy-address 192.168.1.17 255.255.255.0 vlan 10 mac 8 processor 2.8
ip proxy-address 192.168.1.18 255.255.255.0 vlan 10 mac 9 processor 2.9
ip proxy-address 192.168.1.19 255.255.255.0 vlan 10 mac 10 processor 2.10
ip proxy-address 192.168.1.20 255.255.255.0 vlan 10 mac 11 processor 2.11
ip proxy-address 192.168.1.21 255.255.255.0 vlan 10 mac 12 processor 2.12

In some instances, using the count flag produces entries in which there is a skew between the mac index numbers and processor numbers.

For example:

ip proxy-address 192.168.1.23 255.255.255.0 vlan 10 mac 1 processor 2.2
ip proxy-address 192.168.1.24 255.255.255.0 vlan 10 mac 2 processor 2.3
ip proxy-address 192.168.1.25 255.255.255.0 vlan 10 mac 3 processor 2.4
ip proxy-address 192.168.1.26 255.255.255.0 vlan 10 mac 4 processor 2.5
ip proxy-address 192.168.1.27 255.255.255.0 vlan 10 mac 5 processor 2.6
ip proxy-address 192.168.1.28 255.255.255.0 vlan 10 mac 6 processor 2.7
ip proxy-address 192.168.1.29 255.255.255.0 vlan 10 mac 7 processor 2.8
ip proxy-address 192.168.1.30 255.255.255.0 vlan 10 mac 8 processor 2.9
ip proxy-address 192.168.1.31 255.255.255.0 vlan 10 mac 9 processor 2.10
ip proxy-address 192.168.1.32 255.255.255.0 vlan 10 mac 10 processor 2.1
ip proxy-address 192.168.1.33 255.255.255.0 vlan 10 mac 11 processor 2.11
ip proxy-address 192.168.1.34 255.255.255.0 vlan 10 mac 12 processor 2.12

When this issue occurs, the proxy addresses that have a skewed mac/processor pair may be inaccessible to other devices on the network.

F5 Product Development tracked this issue as ARX ID 36393 and it was fixed in ARX version 5.1.0. For information about upgrading, refer to the ARX release notes.

Workaround

You can work around this issue by removing the proxy address entries that have a skewed mac/processor pair and then configuring them individually. Using the previous example, you would run the following commands to reconfigure the proxy address entries for 192.168.1.23 and 192.168.1.24:

no ip proxy-address 192.168.1.23
ip proxy-address 192.168.1.23 255.255.255.0 vlan 10 mac 1 processor 2.1
no ip proxy-address 192.168.1.24
ip proxy-address 192.168.1.24 255.255.255.0 vlan 10 mac 2 processor 2.2
