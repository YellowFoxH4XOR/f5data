Description

SNMP access to a BIG-IP system allows an SNMP management system to remotely monitor and manage a BIG-IP system's statistical data. By default, the BIG-IP system allows SNMP access from the localhost (127.0.0.1) only. In order to allow remote SNMP access you need to perform the following:

  • Configure access to the BIG-IP's SNMP agent from your remote systems.
  • Grant community access to v1 or v2c SNMP data, or Grant user access to v3 SNMP data.

Recommended Actions

To watch a video demo of these procedures, go to  Configure SNMP access to the BIG-IP system.

  • Configure access to the BIG-IP SNMP agent from your remote systems
  • Grant community access to v1 or v2c SNMP data
  • Grant user access to v3 SNMP data
  • ConfigSync the SNMP configuration changes to peer devices

Configure access to the BIG-IP SNMP agent from your remote systems

Before you start this task, you should gather the IP addresses or subnets of the remote systems that require access to the SNMP agent on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Go to System > SNMP > Agent > Configuration.
  3. In Client Allow List, for Type, select either Host or Network, depending on whether the IP address you specify is a host system or a subnet.

    Note: By default, SNMP is enabled only for the BIG-IP system loopback interface (127.0.0.1).

  4. For Address, enter either an IP address or network address from which the SNMP agent can accept requests.
  5. If you selected Network in step 2, type the netmask in the Mask field.
  6. Select Add.
  7. Select Update.

The BIG-IP system now contains a list of IP addresses from which SNMP requests are accepted.

To do this through the TMOS shell, perform the following procedure:

  1. Log in to tmsh.
  2. Use the following command syntax:

    modify sys snmp allowed-addresses add { <Host/Network address> }

    Note: For more details and options, refer to the sys snmp section of the F5 TMSH reference guide on CloudDocs.

    For example:

    modify sys snmp allowed-addresses add { 10.10.1.5 }
    modify sys snmp allowed-addresses add { 10.10.1.0/24 }

Grant community access to v1 or v2c SNMP data

To better control access to SNMP data, you can assign an access level to an SNMP v1 or v2c community.

Note: SNMPv1 does not support Counter64 OIDs, which are used for accessing most statistics. Therefore, for SNMPv1 clients, an snmpwalk command skips any OIDs of type Counter64. F5 recommends that you use only clients that support SNMPv2 or later.

  1. Log in to the Configuration utility.
  2. Go to System > SNMP > Agent > Access (v1, v2c).
  3. Select Create.
  4. From the Type list, select either IPv4 or IPv6.
  5. For Community, enter the name of the SNMP community for which you are assigning an access level.
  6. From the Source list, select All, or select Select and enter the source IP address.
  7. For OID, enter the OID for the top-most node of the SNMP tree to which the access applies.
  8. From the Access list, select an access level, either Read Only or Read/Write.

    Note: When you set the access level of a community or user to read/write, and an individual data object has a read-only access type, access to the object remains read-only. Therefore, the access level or type that is the most secure takes precedence when there is a conflict.

  9. Select Finished.

To do this through the TMOS shell, perform the following procedure:

  1. Log in to tmsh.
  2. Use the following command syntax:

    modify sys snmp communities add { <name> { access <ro|rw> community-name <name> ipv6 <enabled|disabled> source <IP address> } }

    Note: For more details and options, refer to the sys snmp section of the F5 TMSH reference guide on CloudDocs.

    For example:

    modify sys snmp communities add { exampleName { access ro community-name commName ipv6 enabled source 1.1.1.10 } }

Grant user access to v3 SNMP data

To better control access to SNMP data, you can assign an access level to an SNMP v3 user.

  1. Log in to the Configuration utility.
  2. Go to System > SNMP > Agent > Access (v3).
  3. Select Create.
  4. For User Name, enter the name of the user for which you are assigning an access level.
  5. In Authentication, for Type, select a type of authentication to use, and then enter and confirm the user password.
  6. In Privacy, for Protocol, select a privacy protocol, and either enter and confirm the user password, or select the Use Authentication Password check box.
  7. For OID, enter the OID for the top-most node of the SNMP tree to which the access applies.
  8. For Access, select an access level, either Read Only or Read/Write.
  9. Select Finished.

Note: When you set the access level of a user to read/write, and an individual data object has a read-only access type, access to the object remains read-only. In short, the access level or type that is the most secure takes precedence when there is a conflict.

To do this through the TMOS shell, perform the following procedure:

  1. Log in to tmsh.
  2. Use the following command syntax:

    modify sys snmp users add { <name> { username john oid-subset <OID> auth-protocol <protocol> auth-password <password> privacy-protocol <protocol> privacy-password <password> }

    Note: For more details and options, refer to the sys snmp section of the F5 TMSH reference guide on CloudDocs.

    For example:

    modify sys snmp users add { exampleUser { username john oid-subset 1.3.6.1.4.1.3375 auth-protocol sha512 auth-password myAuthPassword privacy-protocol aes privacy-password myPrivacyPassword } }
