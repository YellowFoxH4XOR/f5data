K11652: Server-side connections may be reset when the diameter profile is applied to a virtual server

Published

Updated

Status

Applies to

Source

Topic

When a diameter service profile is applied to a virtual server, the BIG-IP system passes the first Capabilities-Exchange-Answer (CEA) to the client regardless of the result code included in the answer. For subsequent responses from the server within the same connection, the BIG-IP system examines the CEA result code. If a subsequent CEA answer contains a result code in the 5,000 range (5xxx), the BIG-IP system performs the following actions:

  • Resets the server-side connection
  • Performs a load balancing decision to select the new Diameter server
  • Establishes a transport connection with the new Diameter server
  • Retransmits the original Capabilities-Exchange-Request (CER) submitted by the client

This behavior is by design; as described in RFC3588, a 5xxx result code indicates a permanent failure. If the BIG-IP system continues to receive CEA answers with 5xxx result codes, the BIG-IP system repeats the sequence above until the client connection ages out of the connection table.
