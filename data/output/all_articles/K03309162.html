Topic

You should consider using this procedure under the following condition:

  • You want to manage the virtual disk template created on Virtual Clustered Multiprocessing (vCMP) hypervisors.

Description

BIG-IP 11.6.0 introduced the virtual disk template to speed up vCMP guest deployment. By default, this feature is enabled on vCMP-capable platforms with a solid-state drive (SSD). F5 does not recommend this feature on non-SSD platforms due to higher latency on spinning disks.

When you enable this feature, during a vCMP guest creation, the BIG-IP system checks if a virtual disk template exists for the specific version (initial-image and if present, initial-hotfix) when provisioning a new guest. If there is no existing virtual disk template for the desired initial-image/hotfix software version, the BIG-IP system will proceed with the vCMP guest creation and create a virtual disk template for that BIG-IP software version. On subsequent vCMP guest creations with the same initial-image/hotfix software version, the BIG-IP system makes a copy of the existing virtual disk template as the virtual disk for the new vCMP guest.

By default, the virtual disk template feature is enabled on hardware platforms with SSD and disabled on non-SSD platforms. If you want to use virtual disk templates on non-SSD platforms, you must explicitly enable the feature, using the vcmp.installer.use_vdisk_templates database variable.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have vCMP provisioned on your BIG-IP platform.
  • You have administrative access to the vCMP hypervisor.

Procedures

  • Determining if the vCMP hypervisor is configured to use the virtual disk template
  • Enabling the virtual disk template on a vCMP hypervisor
  • Disabling the virtual disk template on a vCMP hypervisor
  • Viewing the existing virtual disk template using the tmsh utility
  • Viewing the existing virtual disk template using the Configuration utility
  • Deleting the existing virtual disk template using the tmsh utility
  • Deleting the existing virtual disk template using the Configuration utility

Determining if the vCMP hypervisor is configured to use the virtual disk template

To verify if the vCMP hypervisor is configured to use the virtual disk template, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To determine if the vCMP hypervisor is configured to create the virtual disk template upon a vCMP guest creation, use the following command syntax:

    list /sys db vcmp.installer.use_vdisk_templates

    Note: The initial system database variable value is set to default. By default, the BIG-IP system is configured to use the virtual disk template on SSD platforms. If you want to use virtual disk templates on non-SSD platforms, you must enable this database variable explicitly.

Enabling the virtual disk template on a vCMP hypervisor

To enable the virtual disk template on the vCMP hypervisor, perform the following procedure:

Note: F5 does not recommend enabling the virtual disk template for non-SSD platforms due to the effect of a higher latency on spinning disks.

Impact of procedure: The BIG-IP system will perform additional tasks to check for available disk template and perform virtual disk template creation or copy operation when a new vCMP guest gets created.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To enable the use of the virtual disk template on the vCMP hypervisor, use the following command syntax:

    modify /sys db vcmp.installer.use_vdisk_templates value enabled

Disabling the virtual disk template on a vCMP hypervisor

To disable the virtual disk template on the vCMP hypervisor, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system. All existing templates will remain in the BIG-IP system, even after performing this procedure.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To disable the creation of the virtual disk template on the vCMP hypervisor, use the following command syntax:

    modify /sys db vcmp.installer.use_vdisk_templates value disabled

Viewing the existing virtual disk template using the tmsh utility

To use the tmsh utility to view the existing virtual disk template on the vCMP hypervisor, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To view the existing virtual disk template on the vCMP hypervisor, use the following command syntax:

    list /vcmp virtual-disk-template one-line

    For a virtual disk template created from a previous BIG-IP 12.1.0 guest installation, the command output appears similar to the following example:

    vcmp virtual-disk-template BIGIP-12.1.0.0.0.1434.iso.img.deflated/1 { iso-version BIGIP-12.1.0.0.0.1434.iso operating-system tmos }
    vcmp virtual-disk-template BIGIP-12.1.0.0.0.1434.iso.img.deflated/2 { iso-version BIGIP-12.1.0.0.0.1434.iso operating-system tmos }
    vcmp virtual-disk-template BIGIP-12.1.0.0.0.1434.iso.img.deflated/3 { iso-version BIGIP-12.1.0.0.0.1434.iso operating-system tmos }
    vcmp virtual-disk-template BIGIP-12.1.0.0.0.1434.iso.img.deflated/4 { iso-version BIGIP-12.1.0.0.0.1434.iso operating-system tmos }

Viewing the existing virtual disk template using the Configuration utility

You can use the Configuration utility to view the existing virtual disk template on the vCMP hypervisor by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the vCMP hypervisor.
  2. Navigate to vCMP > Template List.

Deleting the virtual disk template using the tmsh utility

To use the tmsh utility to delete the existing virtual disk template on the vCMP hypervisor, perform the following procedure:

Impact of procedure: Performing the following procedure will remove the virtual disk template from the BIG-IP system. Subsequent vCMP guest creation will still work without the template. And if the vCMP hypervisor is still configured to allow the use of virtual disk template, the BIG-IP system will create a new virtual disk template.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To delete the virtual disk template on the vCMP hypervisor, use the following command syntax:

    delete /vcmp virtual-disk-template <template_name>

    For example, to delete the virtual disk template named BIGIP-12.1.0.0.0.1434.iso.img.deflated/1, use the following command syntax:

    delete /vcmp virtual-disk-template BIGIP-12.1.0.0.0.1434.iso.img.deflated/1

  3. To delete all of the virtual disk templates on the vCMP hypervisor, type the following command:

    delete /vcmp virtual-disk-template all

Deleting existing virtual disk template using the Configuration utility

To use the Configuration utility to delete the existing virtual disk template on the vCMP hypervisor, perform the following procedure:

Impact of procedure: Performing the following procedure will remove the virtual disk template from the BIG-IP system. Subsequent vCMP guest creation will still work without the template. If the vCMP hypervisor is still configured to allow the use of virtual disk template, the BIG-IP system will create a new virtual disk template.

  1. Log in to the Configuration utility of the vCMP hypervisor.
  2. Navigate to vCMP > Template List.
  3. Select the check box next to the name of the virtual disk template that you want to delete.
  4. Click delete.
  5. On the delete confirmation page, click delete.
