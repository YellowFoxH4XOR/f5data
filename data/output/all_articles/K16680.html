Topic

You should consider using this procedure under the following conditions:

  • You would like to process Voice over Internet Protocol (VoIP) communication with a BIG-IP APM Network Access profile.
  • Your VoIP application is not compatible with network address translation, or you want to retain the source address of the VoIP clients.

Description

The VoIP technology transmits voice traffic across IP-based networks. Deploying VoIP in a data network requires careful planning and engineering, since these networks must be engineered to support the unique nature of voice-based data. For example, VoIP is typically intolerant of data loss, delays, and retransmissions that affect the quality of the call. Additionally some VoIP vendor solutions are intolerant of network address translation, requiring the client's IP address to remain unchanged between the client and the VoIP application.

VoIP implementations are typically UDP-based and function using isochronous communications. Networks designed to support VoIP typically deploy IP Quality of Service (QoS) policies to guarantee the bandwidth required by VoIP applications. This is normally implemented through the use of a strict priority or low latency queue. Depending on the voice codec deployed, voice packets are sent consistently every five to 30 milliseconds isochronously. Lost or delayed packets due to routing changes, busy networks, or congested network links may cause jitter (the time variation between packets arriving). Jitter negatively impacts the quality of the VoIP communication.

Users can transmit VoIP data over a BIG-IP APM Network Access connection, and many existing BIG-IP APM customers have deployed Network Access-based solutions for protecting VoIP data. However, there are several considerations, which are outlined in the Procedures section of this article to help improve processing of VoIP communications.

VoIP and QoS

Networks designed for VoIP typically implement QoS policies to prioritize time-sensitive applications such as VoIP. Your BIG-IP system can be configured for QoS packet handling. For additional information about BIG-IP and QoS refer to the following articles:

  • K7535: Overview of the UDP profile
  • K74767112: Overview of the TCP profile (15.x)
  • K29377715: Overview of the TCP profile (14.x)
  • K10711911: Overview of the TCP profile (13.x)
  • K70025261: Overview of the TCP profile (12.x)
  • K13924148: Overview of the TCP profile (11.x)
  • K7559: Overview of the TCP profile (9.x - 10.x)

Note: When a user makes or receives a VoIP call through a Network Access connection, the user may want to close other network applications to increase available bandwidth for the VoIP data. For example, if the email client remains open during the call, and the email client downloads a new message with a large attachment, the quality of the VoIP call may be affected.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Have administrative access to the BIG-IP APM system.
  • Have an existing Network Access profile, intended for use with VoIP traffic.

    Note: For information about configuring a Network Access profile, refer to BIG-IP Access Policy Manager: Network Access manual for your release version.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Procedures

Reviewing the Network Access profile configuration used with VoIP (BIG-IP 11.3.0 and later)

The following procedure outlines the recommended network access settings for processing VoIP communications.

Impact of procedure: The address translation lease pool IP address of the network access profile will no longer be applied to the client request when sending the request to the destination resource. Ensure that network routing routes the VoIP packets back to the BIG-IP APM system.

Note: VoIP users connected to a Network Access connection may experience call degradation prior to BIG-IP APM 11.3.0. For more information, refer to K12387: Network Access users may experience issues using VoIP.

  1. Go to Network Access List.
    • BIG-IP 13.x through 15.x: Access > Connectivity/VPN > Network Access (VPN) > Network Access List
    • BIG-IP 11.x and 12.x: Access Policy > Network Access > Network Access List.
  2. Select the name of the Network Access profile.
  3. Select the Network Settings tab.
  4. Under General Settings, leave the Compression setting to the default setting of No Compression.
  5. For SNAT Pool, select None.
  6. Enable the Preserve Source Port Strict feature:
    • BIG-IP 11.6.0 and later

      Select the Enable check box for the Preserve Source Port Strict setting in the General Settings section.

    • BIG-IP 11.3.0 - 11.5.x

      Select All for the Preserve Source Port Strict setting in the Client Settings advanced section.

  7. If you have already created a DTLS virtual server for network access, select the DTLS check box.
  8. Select Update.
  9. Select Apply Access Policy.

Reviewing the BIG-IP APM virtual server configuration settings for VoIP (BIG-IP 11.2.1 and earlier)

The following procedure outlines recommended virtual server settings for processing VoIP communications.

Impact of procedure: Address translation for packets processed by the virtual server will no longer be applied to client request. Ensure that network routing routes VoIP packets back to the BIG-IP APM system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the name of the virtual server.
  4. For Source Address Translation, select None.
  5. Clear the Enabled check box for Address Translation.
  6. Clear the Enabled check box for Port Translation.
  7. For Source Port, select Preserve Strict.
  8. Optional: The following two steps require that you configure the BIG-IP APM system with a separate port-specific virtual server.

    For information about DTLS configurations, refer to the Configuration Guide for BIG-IP Access Policy Manager Configuring Virtual Servers.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

    1. Select the DTLS check box.
    2. In the DTLS Port box, type the Datagram Transport Layer Security (DTLS) port number (the default is 4433).
  9. Click Update.

Note: Most VoIP data is compressed before transmission and receives little, if any, additional compression from gzip. If you enable gzip compression for a BIG-IP APM Network Access connections, the additional processing overhead required by gzip may reduce the quality of VoIP transmissions.
