Topic

You should consider using this procedure under the following condition:

  • You want to reconfigure the traffic group definition that was erroneously removed from folders or partitions and various objects after an upgrade.

Description

When you upgrade your BIG-IP system to a certain version, the upgrade process erroneously removes the traffic group definition from various objects and folders or partitions. For more information about this issue, refer to K14104: The traffic group definition may be missing from the '/ ' and '/Common' partitions.

After you encounter the issue, if you upgrade the affected BIG-IP system to a version that is fixed, or a version later than the fixed versions, the system does not restore the traffic group definition back to the affected objects. This is because the traffic group definition for the various objects are no longer in the BIG-IP configuration files.

For example, after you upgrade the affected BIG-IP system to 11.6.0, the /config/bigip_base.conf file that contains the missing traffic group definition may appear similar to the following example:

sys folder / {
device-group /Common/bigip_sync_failover
hidden false
inherited-devicegroup false
inherited-traffic-group false
traffic-group none
}
sys folder /Common {
device-group /Common/bigip_sync_failover
hidden false
inherited-devicegroup true
inherited-traffic-group true
traffic-group none
}

To prevent the issue documented in K14104: The traffic group definition may be missing from the '/ ' and '/Common' partitions from manifesting when you upgrade the affected BIG-IP system in the future, you should upgrade the system to a fixed version, and perform the procedure discussed in this article.

Prerequisites

You must meet all of the following prerequisite to use this procedure:

  • Have Advance Shell (bash) access to the affected BIG-IP system.
  • The affected system must have at some point experienced or continue to experience the issue described in K14104: The traffic group definition may be missing from the '/ ' and '/Common' partitions.

Procedures

To manually reconfigure the appropriate traffic group definition for each affected folder or partition and failover object, perform all of the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

  • Configuring the appropriate traffic group for affected folders
  • Identifying affected failover objects
  • Configuring the appropriate traffic group for affected failover objects

Configuring the appropriate traffic group for affected folders

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To configure the appropriate traffic group for the / and /Common folders, use the following command syntax:

    modify /sys folder /Common/ / traffic-group <traffic-group_name>

    For example, to configure the default traffic group traffic-group-1 for the / and /Common folders, type the following command:

    modify /sys folder /Common/ / traffic-group traffic-group-1

  3. To identify any other folders to inherit the issue from the default root ( / ) folder, type the following command:

    list /sys folder

    Take note of the affected folders and list the traffic group as traffic-group none.

  4. To configure the appropriate traffic group for these specific folders, use the following command syntax:

    modify /sys folder <folder_name> traffic-group <traffic-group_name>

    For example, to configure the default traffic group traffic-group-1 for the /abc123 folder, type the following command:

    modify /sys folder /abc123/ traffic-group traffic-group-1

    Optional: You may correct multiple folders with a single command by using the following command syntax:

    modify /sys folder <folder_name_1> <folder_name_2> <folder_name_3> traffic-group <traffic-group_name>

  5. Save the configuration by typing the following command:

    save /sys config partitions all

Identifying affected failover objects

  1. Log in to the BIG-IP command line.
  2. To identify affected failover objects in the /Common partition, type the following command:

    grep 'traffic-group none' /config/*

  3. To identify affected failover objects in other partitions, type the following command:

    grep 'traffic-group none' /config/partitions/*/*

Configuring the appropriate traffic group for affected failover objects

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To configure the appropriate traffic group for each specific failover object identified in the previous procedure, use the following command syntax:

    modify <module> <object_type> <object_name> traffic-group <traffic-group_name>

    For example, to configure the LTM module, where the default traffic group is traffic-group-1 for all virtual addresses in the /Common partition, type the following command:

    modify /ltm virtual-address all traffic-group traffic-group-1

    Optional: You may correct multiple objects of the same type with a single command using the following command syntax:

    modify <module> <object_type> <object_name_1> <object_name_2> <object_name_3> traffic-group <traffic-group_name>

  3. Save the configuration by typing the following command:

    save /sys config partitions all
