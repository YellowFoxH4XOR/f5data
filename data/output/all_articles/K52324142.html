Description

  • You find that the snmpd process, on your BIG-IP system is constantly restarting.
  • The BIG-IP command line may frequently display a message similar to: 
    Broadcast message from systemd-journald@big-ip.local (Tue 2020-09-15 08:30:56 CEST):
    logger[19254]: Re-starting snmpd
  • You may find log events, similar to:
    /var/log/audit:
    type=ANOM_ABEND msg=audit(2020-11-15T16:45:56EST:64136): auid=4294967295 uid=0 gid=0 ses=4294967295 subj=system_u:system_r:snmpd_t:s0 pid=26330 comm="snmpd" reason="memory violation" sig=6
     
    /var/log/daemon.log:
    Nov 16 03:40:11 big-ip.local err sflow_agent[5558]: unknown snmp version 193
    Nov 16 03:40:13 big-ip.local emerg logger[14072]: Re-starting snmpd
     
    /var/log/crashinfo/snmpd.crashlog: snmpd SIGABRT or SIGSEGV events.
     
    /var/log/ltm:
    Nov 16 03:48:12 big-ip.local info snmpd[23271]: 0114002b:6: HA daemon_heartbeat %snmpd enabled.
    Nov 16 03:50:13 big-ip.local info snmpd[25819]: 0114002b:6: HA daemon_heartbeat %snmpd enabled.
    Nov 16 03:52:13 big-ip.local info snmpd[28203]: 0114002b:6: HA daemon_heartbeat %snmpd enabled.
     
    /var/log/messages.log:
    Nov 16 03:40:10 big-ip.localm notice logger[14003]: Started writing core file: /var/core/snmpd.bld0.0.8.core.gz for PID 11675
    Nov 16 03:40:11 big-ip.local warning OSPF[32469]: OSPF : AgentX: read, connection (sock 6) closed: length is zero
    Nov 16 03:40:11 big-ip.local warning NSM[32464]: NSM : AgentX: read, connection (sock 7) closed: length is zero
    Nov 16 03:40:11 big-ip.local notice logger[14029]: Finished writing 16607310 bytes for core file: /var/core/snmpd.bld0.0.8.core.gz for PID 11675

  • 'tmsh show /sys service snmpd' indicates an unusually-high number of snmpd restarts: 
    snmpd        run (pid 35899) 54 seconds, 5432 restarts
  • Multiple snmpd core files, in the /var/core directory

Environment

  • BIG-IP TMOS, versions: 15.1.0.4, 15.1.0.5, 16.0.0.x
  • snmpd process

Cause

  • This issue is related to the K45212738: SNMP vulnerability CVE-2019-20892

Recommended Actions

  1. Configure SNMPv3 to restrict access with a password, and to only trusted IP addresses. To do so, refer to K13535: Restricting SNMP access to the BIG-IP system.

    NOTE: To set password on GUI, you will need to recreate v3 configuration
NOTE: If the workaround cannot be used, an Engineering Hotfix may be available from F5 Support.
