Description

You should consider using this procedure under the following conditions:

  • You have configured your F5OS system to send logs to a remote syslog server.
  • Log messages from your F5OS system do not appear on the remote syslog server.

As a result of issues with sending logs to a remote syslog server, you may encounter the following symptom:

Log messages from your BIG-IP system are not visible on the remote syslog server.

Environment

  • F5OS-A
  • Remote Syslog server

Cause

 None

Recommended Actions

When you experience issues sending logs to a remote syslog server, you can use the following troubleshooting steps to confirm or rule out the F5OS system as the cause:

  1. Verify the syslog settings on F5OS System
  2. Perform the connectivity tests and routing
  3. Check the syslog container status
  4. Use tcpdump to verify if traffic is leaving from the right source

Verify the syslog settings on F5OS System
You should verify the syslog settings to confirm that they are configured correctly for your environment.
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5OS appliance with admin account with command line.
  2. Display the BIG-IP syslog configuration by typing the following command:
    # show running-config | begin remote-servers
    For example:
    # show running-config | begin remote-servers
          system logging remote-servers remote-server 1.1.1.1
          config remote-port 514
          config proto udp
          selectors selector LOCAL0 WARNING

Note: The remote port will not be displayed in the remote-servers section if port 514 is configured.


Perform the connectivity tests and routing
You can use either the ip route get command or the route command to determine the interface that the BIG-IP system uses to reach the remote syslog server.

Note: the interface selected will always be mgmt interface only by default.

  1. This can be verified by logging into controller or appliance floating IP via root account as per below command.
     # ip route get <remote syslog IP>
    For Example
    #ip route get 1.1.1.1
        1.1.1.1 via 10.154.81.254 dev mgmt-fixed src 10.154.81.6
        cache
  2. Test the server with the ping utility by using the following syntax. Login with root account as per previous step.
    # ping  <IP_address_of_syslog_server>

Check the syslog container status

  1. Container used for the remote syslog is the rsyslogd. Check the status of the respective as per below command on the appliance via root access.
    # docker ps | grep rsyslog

    For example
    # docker ps | grep rsyslog
       38ad773d1442 localhost:2005/velocity_rsyslogd:4.1.8-f5os-a-1-6-0-candidate.2023-08-22-23-47-47.S144b235f "/usr/local/sbin/d..."  7 days ago      Up 7 days   system_velocity_rsyslogd
        5cd4969a2206 localhost:2005/rsyslogd:1.10.11-f5os-a-1-6-0-candidate.2023-08-22-23-47-55.Sd3319512 "/usr/local/sbin/d..."  7 days ago     Up 7 days  system_rsyslogd

  2. If the container is up, then fine otherwise can restart the services via below command.
    # docker restart system_rsyslogd
    # docker restart system_velocity_rsyslogd

 

Use tcpdump to verify if traffic is leaving from the right source.

  1. Log in to the F5OS command line via root account.
  2. To capture traffic sent to the remote syslog server, use the following command
    # tcpdump -nni mgmt host <remote syslog IP> and port 514                       

Note: To initiate the logs can disable and enable the interfaced not in use and see the traffic in captures  

After running tcpdump  can verify if the logs initiated are going to remote syslog server.
