Known Issue

When an iRule attempts to execute a command using violation details, such as attack signatures or malicious fingerprints, the iRule may encounter a runtime error that causes the connection containing a legal request to reset.

This issue occurs when all of the following conditions are met:

  • An ASM iRule that uses violation details in a command is attached to the virtual server.
  • The HTTP or HTTPS request contains violations.

Impact

The iRule fails to run successfully and the BIG-IP system resets the affected connection that contained the legal request.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system resets connections with legal requests.
  • The BIG-IP ASM system logs error messages to the /var/log/ltm file that appear similar to the following example:

    err tmm9[27831]: 01480002:3: Command failed.
    err tmm9[27831]: 01220001:3: TCL error: /Common/sig_print <ASM_REQUEST_DONE> - plugin_tcl_command_execute: Command error.     invoked from within "ASM::signature ids"

  • If you have configured your BIG-IP system to log TCP RST (reset) packets, you observe additional error messages in the /var/log/ltm file that appear similar to the following example:

    Note: For more information about configuring the BIG-IP system to log TCP RST packets, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

    err tmm9[27831]: 01230140:3: RST sent from 10.1.1.1:80 to 172.16.1.1:56200, [0x27f26d8:1410] iRule execution error
