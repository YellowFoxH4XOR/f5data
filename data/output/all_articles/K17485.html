Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when an iRules event is disabled within the event.

This issue occurs when all of the following conditions are met:

  • An iRules event is executed.
  • The iRule uses a parking command that suspends iRules processing after the event is disabled.

    For example:

    when HTTP_REQUEST {
       if { $a == $b } {
           event disable HTTP_REQUEST
       }
       after 100
       log local0. "foo"
    }

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • In the /var/log/tmm file, you observe messages that appear similar to the following example:

    notice panic: ../base/tclrule.c:1219: Assertion "valid ctx lrule_cnt" failed.
    notice ** SIGFPE **

  • The BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption, similar to the following example:

    tmm.0.bld3.36.412.core.gz

Workaround

To work around this issue, you can disable the iRules event as the last command before exiting the event in your iRule.

For example:

when HTTP_REQUEST {
   if { $a == $b } {
       event disable HTTP_REQUEST
       return
    }

}

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
