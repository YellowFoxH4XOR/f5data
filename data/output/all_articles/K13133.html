Topic

You should consider using this procedure under the following condition:

  • You want to change the root backing share in an ARX managed volume.

Description

The root backing share is the default share designated to hold all new files created in the root of an ARX managed volume. The default root backing share for a managed volume is the first share imported into the volume, which is typically the first share configured.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • The ARX managed volume must have more than one share.

Procedures

Changing the root backing share

To configure the ARX to use a different share as the root backing share, perform the following procedure:

Impact of procedure: None.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode by using the following command syntax, and replacing <namespace> with the name of your namespace:

    namespace <namespace>

    For example:

    namespace ns1
  5. Enter volume configuration mode by using the following command syntax, and replacing <volume> with the name of your volume:

    volume <volume>

    For example:

    volume /vol1

    You are now in gbl-ns-vol mode.
  6. Configure a new filename fileset named root by typing the following command:

    filename-fileset root
  7. At the Create object 'root'? [yes/no] prompt, type the following:

    yes

    You are now in gbl-ns-vol-fs mode.
  8. Configure the fileset to use the root (/) directory by typing the following command:

    path exact /
  9. Exit the fileset configuration mode by typing the following command:

    exit
  10. Configure a new fileset placement policy rule named promote-root by typing the following command:

    place-rule promote-root
  11. At the Create object 'promote-root'? [yes/no] prompt, type the following:

    yes

    You are now in gbl-ns-vol-plc mode.
  12. Configure the promote-root placement rule to use the root fileset as a source, matching directories only and enable directory promotion by typing the following command:

     from fileset root match directories promote-directories
  13. Configure the promote-root placement rule's target to be the new root backing share by using the following command syntax. Replace <share_name> with the name of the share you want to be the new root backing share:

    target share <share_name>

    For example:

    target share share2
  14. Configure the promote-root placement rule's report prefix to be promote-root by typing the following command:

    report promote-root verbose
  15. Enable the promote-root placement rule by typing the following command:

    enable
  16. Exit the placement rule configuration mode by typing the following command:

    exit
  17. Monitor the status of the promote-root placement rule by typing the following command:

    show policy

    When the promote-root placement rule has completed, the output of the show policy command will appear similar to the following:

                                                             Status
    Namespace      Volume         Rule              Vol. Scan     Migration
    -------------  -------------  ----------------  ---------------------------
    ns1            /vol1          promote-root      Complete      Complete
  18. After the promote-root placement rule has completed, verify which share the ARX is using as the root backing share for the managed volume using the following command syntax. Replace <namespace_name> with the name of the namespace and replace <volume_name> with the name of the volume:

    show namespace <namespace_name> volume <volume_name>

    For example:

    show namespace ns1 volume /vol1

    The share designated as the root backing share will have the following entry:

     Volume Root Backing         Yes

    Once you have confirmed the ARX is using the desired share as the root backing share, you should delete the promote-root placement rule and root fileset created for this procedure.
  19. Delete the promote-root placement rule by typing the following command:

    no place-rule promote-root
  20. Delete the root fileset by typing the following command:

    no filename-fileset root
  21. Exit the gbl-ns-vol configuration mode and return to privileged mode by typing the following command:

    end
