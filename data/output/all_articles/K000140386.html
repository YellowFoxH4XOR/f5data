Description

Executed cpcfg command in attempt to copy configuration from one boot location to another. Process does not complete.

Running with --verbose option shows the cpcfg stuck at this step:

debug: Opening temp UCS file /mnt/tm_install/...

When examined with ls or du, the UCS file is 0 bytes in size.

Environment

  • cpcfg
  • Upgrade

Cause

A child of the cpcfg process is likely stuck executing a command.

Recommended Actions

Review the process list to determine what the cpcfg is stuck on.

You can use the following command, for instance:

pstree -ap $(pgrep cpcfg)

The direction of further troubleshooting will depend on what process is getting stuck.

One instance of cpcfg getting stuck was due to a large amount of AVR data causing avr_db_backup.sh to take a very long time to back it up. In that instance, a reset of the AVR statistics (K14956) resolved the issue.

Additional Information

Installing a software image or hotfix will automatically copy the entire configuration from the current boot location to the target boot location.

That is the default behaviour, as described in K13438:

  • K13438: Controlling configuration import when performing software upgrade/installation

In most cases there is no need to run cpcfg. Running cpcfg will just copy the configuration across again unnecessarily.
