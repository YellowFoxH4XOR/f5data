Description

When connecting to a Virtual Server using port list option to listen on various ports, client does not get the reply from the corresponding port from the pool members.

Environment

  • Virtual server listening on port list (port1, port2, port3) or on all ports
  • Pool containing pool members listening on different ports (port1, port2, port3)

Cause

When this configuration is in place, if the pool member selected by load balancing method, is the one listening on port1 and the client request to the Virtual Server was on port 2, the pool member response will arrive at the pool member with the wrong port (port1). This is expected behaviour for this configuration.

Recommended Actions

  1. If you want the same port from the client request to be used for the responding pool member, you can modify this configuration to use three (or more) separate Virtual Servers and 3 separate Pools. One listening on each separate port (port1, port2, port3).
  2. If you wish to keep them on the same Virtual Server, using port list, but separate the pool members into 3 different pools for each service (pool1, pool2 and pool3), any of these 2 possible solutions can work for you:
  • Using an irule to select the pool based on the client's remote port
  • Using an LTM policy to select the pool based on the client's remote port

Using an irule to select the pool based on the client's remote port: 

Configure an iRule with a similar sintax and attach to the Virtual Server:

when CLIENT_ACCEPTED {
  switch -glob [TCP::local_port] {
    port1 { pool name_pool_1
       }
    port2 { pool name_pool_2
       }
    port3 { pool name_pool_3
       }
  }
}

Using an LTM policy to select the pool based on the client's remote port:
  1. In the GUI navigate to: Local Traffic >> Policies >> Create...
  2. Match all of the following conditions: TCP - port - is - any of - <port1> - at - Client Accepted - time (Options: Apply to traffic on local side of external interface)
  3. Do the following when the traffic is matched: Forward Traffic - to - pool - <Name of pool1> - at - Client accepted - time
  4. Repeat steps 2 and 3 for port2 and port3, selecting the corresponding pool (pool2 and pool3)
  5. Attach the LTM policy to the Virtual Server

Additional Information

The solution proposed using an LTM policy has the advantage of also showing the pools related to the Virtual Server in the GUI, Local Traffic >> Network Map. The solution using an iRule, will only show the default pool attached to the Virtual Server on the Network Map.
