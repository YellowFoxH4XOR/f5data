K000161667: Telemetry Streaming fails to collect statistics due to HTTP 403 Forbidden errors

Type
Support Solution
Published
2026-06-10
Updated
2026-08-11
Applies to

  • BIG-IP
  • F5 BIG-IP Telemetry Streaming
Source

Description

Telemetry Streaming is unable to collect statistics from BIG-IP endpoints. The primary symptom is the logging of HTTP 403 Forbidden errors, which prevents Telemetry Streaming from successfully polling and reporting metrics.

 

Environment

  • Product: BIG-IP
  • Telemetry Streaming (TS) configured for system polling
  • Typical endpoints: "apmState", "diskLatency", /mgmt/tm/util/bash, etc.

Cause

Telemetry Streaming, by default, attempts to access certain REST API endpoints using the loopback address ("localhost") for management API requests. In recent BIG-IP versions, this access method is restricted, resulting in HTTP 403 Forbidden errors. This occurs when the "host" property in the declaration is set to "localhost" (the default). To prevent these errors, the declaration should be updated to use a non-loopback management IP address or hostname and explicit credentials.

 

Answer/Recommended Actions

To resolve this issue, you must update your Telemetry Streaming declaration so that:

  • The host property is set to the management IP address or hostname of your BIG-IP device (for example, <management-IP or hostname> ), not "localhost" or "127.0.0.1".
  • The port property is set to the management port used by your BIG-IP device (commonly 443 or 8443).
  • Both a valid username and passphrase (password) are provided for authentication. The username must be a BIG-IP user account with the Administrator role.

These changes ensure Telemetry Streaming uses authenticated requests to access the necessary endpoints, preventing 403 Forbidden errors.

Apply the following updates to the Telemetry_System or Telemetry_System_Poller object in your declaration:

Example:

{

 "class": "Telemetry",

 "My_System": {

   "class": "Telemetry_System",

     "systemPoller": {

           "interval": 60

   },

   "host": "<management-IP or hostname>",

   "port": "<management-port>",

   "protocol": "https",

   "allowSelfSignedCert": true,

   "username": "admin",

   "passphrase": {

          "cipherText": "<your-password-here>"

    }

  }

}

 

Note:

This workaround can be applied to either the Telemetry_System or Telemetry_System_Poller object, depending on your configuration. Update the relevant object in your declaration to ensure authenticated requests are used

 

Additional Information

Example Error Messages in /var/log/restnoded/restnoded.log:

Message: Poller.collectStats: unable to collect stats: Collector.collect unexpected error on attempt to collect stats for "apmState" (apmState::commandResult): Unable to get response from endpoint "apmState": Bad status code: 403 Forbidden for http://localhost:8100/mgmt/tm/util/bash
