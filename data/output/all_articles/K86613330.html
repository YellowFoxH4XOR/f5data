Known Issue

The localdbmgr process might exit and produce a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM configuration uses the local user database for authentication.
  • Your BIG-IP APM system is internally logging configuration changes.

Impact

The localdbmgr process consumes high CPU, may become unresponsive, and creates a core file when CPU resources are exhausted.  

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users cannot authenticate to the BIG-IP APM system.
  • When viewing resource utilization using the Linux top command, the command output shows the localdbmgr process is consuming a high percentage of available CPU.
  • In the /var/log/ltm file, you observe log messages similar to the following example:

    notice ** SIGABRT **
    notice sender pid: 16314 (/bin/bash)
    notice fault code: 0x0
    notice version: pgo_use x86_64 padc TMM Version 12.1.1.0.0.184

  • In the /shared/core directory, you observe core files for the localdbmgr process similar to the following example:

    localdbmgr.bld2440.0.core.gz

Workaround

To work around this issue, the localdbmgr process should automatically restart. However, you can manually restart the localdbmgr process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Type the following command:

    restart /sys service localdbmgr

  3. To exit tmsh, type the following command:

    quit
