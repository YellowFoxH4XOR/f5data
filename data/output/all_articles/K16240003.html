Topic

BIG-IP 15.1.0.1 introduced F5 HTTP/3 and QUIC as experimental features.

Form v15.1.2.1 and v16.1.0.2, BIG-IP supports RFC9114 version 1.

You should consider using these procedures under the following conditions:

  • You have configured a BIG-IP virtual server that uses HTTP/3 over the QUIC protocol.
  • You want to browsers to be able to discover your HTTP/3 virtual server.

    Note: For more information about configuring an HTTP/3 virtual server, refer to K60235402: Overview of the BIG-IP HTTP/3 and QUIC profiles

Description

A BIG-IP virtual server using HTTP/3 over QUIC uses the UDP protocol. You need to configure HTTP/3 discovery so browsers can discover the HTTP/3 service that your BIG-IP virtual server provides and communicate with the BIG-IP virtual server using the UDP protocol instead of TCP. An HTTP/3 origin can indicate that an HTTP/3 service is available by including the following header syntax in an HTTP response:

Alt-Svc: h3-<version>=":<port number>"; ma=<age in seconds>

For example, to indicate that an HTTP/3 service is available at port 8443 at the same host name and implements HTTP/3 over QUIC draft version draft-ietf-quic-http-24, insert the following header:

Alt-Svc: h3-24=":8443"; ma=3600

The following examples of configurations may be useful for your environment:

Alt-Svc: h3-25=":443"; ma=2592000;
Alt-Svc: h3-25=":443"; ma=2592000; persist=1
Alt-Svc: h3="alt.example.com:443", h2=":443"
Alt-Svc: h3-25=":443"; ma=3600, h2=":443"; ma=3600

Note: Only implementations of the final, published RFC can identify themselves as h3. Until such an RFC exists, implementations must not identify themselves using the h3 string.

When a client receives a response with this header, the client may attempt to establish a QUIC connection to the indicated host and port. In the event of failure to connect to the service, the client should continue using the existing connection. For more information, refer to Hypertext Transfer Protocol Version 3 (HTTP/3) draft-ietf-quic-http-24draft-ietf-quic-http-24 section-3.2.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have a working HTTP/1.1 or HTTP/2 virtual server providing a web service.
  • You have a working HTTP/3 virtual server using QUIC to provide a web service.

Procedures

You can insert the Alt-Svc header into your BIG-IP virtual server's response to the browser by using either an iRule or a BIG-IP LTM policy To do so, perform one of the following procedures:

  • Inserting an Alt-Svc header using an iRule
  • Inserting an Alt-Svc header using a BIG-IP LTM policy

Inserting an Alt-Svc header using an iRule

You can insert the Alt-Svc header by creating an iRule and associating it to your HTTP/1.1 or HTTP/2 virtual server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. To create an iRule to insert the Alt-Svc header, go to Local Traffic > iRules.
  3. Select Create.
  4. Name the iRule as follows:

    http3_discovery_irule

  5. To insert an Alt-Svc header with a maximum age of 3600s, for Definition, enter the following iRules syntax:

    when HTTP_RESPONSE {
    #log local0. "Inserting header"
    HTTP::header insert Alt-Svc "h3-24=\":8443\"; ma=3600"
    }

    Note: In this example, the h3-24 token indicates that the client implements HTTP/3 over QUIC draft version draft-ietf-quic-http-24. For the final, published RFC, use the h3 string.

  6. Select Finished.
  7. Associate the iRule you just created to your HTTP/1.1. or HTTP/2 virtual server by going to Local Traffic > Virtual Servers.
  8. Select the name of your HTTP/1.1. or HTTP/2 virtual server.
  9. Select the Resources tab.
  10. For iRules, select Manage.
  11. For iRule, in the Available list, select the name of the iRule you created earlier and move it to the Enabled list.
  12. Select Finished.

Inserting an Alt-Svc header using a BIG-IP LTM policy

You can insert the Alt-Svc header by creating a BIG-IP LTM policy and associating it with your HTTP/1.1 or HTTP/2 virtual server. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. To create a BIG-IP LTM policy to insert the Alt-Svc header, go to Local Traffic > Policies.
  3. Select Create.
  4. For Policy Name, enter an appropriate name.
  5. For Description, enter the following:

    Insert Alt-Svc header for HTTP3 discovery

  6. For Strategy, select Execute all matching rule.
  7. For Type, select Traffic Policy.
  8. Select Create Policy.
  9. For Rules, select Create.
  10. For Name, enter the following:

    insert-alt-svc

  11. For Match all of the following conditions: select + to expand the section and select and enter values to create the following statement:

    HTTP Status code is any of 200 at response

  12. For Do the following when the traffic is matched: select + to expand the section and select and enter values to create the following statement:

    Insert HTTP Header named Alt-Svc with the value h3-24=\":8443\" response time

  13. Select Save.
  14. Select Save and Publish Policy.
  15. To associate the BIG-IP LTM policy you just created with your HTTP/1.1. or HTTP/2 virtual server, go to Local Traffic > Virtual Servers and select the name the virtual server.
  16. Select the Resources tab.
  17. For Policies, select Manage.
  18. For Policies, in the Available list, select the name of the BIG-IP LTM policy you created earlier and move it to the Enabled list.
  19. Select Finished.

Note: In this example, the h3-24 token indicates that the client implements HTTP/3 over QUIC draft version draft-ietf-quic-http-24. For the final, published RFC, use the h3 string.
