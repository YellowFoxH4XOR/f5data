Description

When deploying NGINX Instance Manager (NIM) using Helm with custom deployment names via fullnameOverride in the values.yaml file, pod creation may fail with service account lookup errors. The error found from output of kubectl describe replicaset -n <namespace> typically appears as:

Error creating: pods "<pod-name>" is forbidden: error looking up service account <namespace>/nms: serviceaccount "nms" not found

This occurs because the deployment references a service account name that doesn't match the actual service account created when using name overrides. The service account is created with the overridden name, but the pod specifications still reference the default "nms" service account name.

Environment

  • Product: NGINX Instance Manager
  • Version: 2.20.0 (and potentially other versions)
  • Deployment Method: Helm chart
  • Platform: Kubernetes
  • Configuration:
    • fullnameOverride set in values.yaml
    • Default serviceAccount configuration (without explicit name)
  • Namespace: Custom namespace (e.g., nim)

Cause

When fullnameOverride is set in the Helm values.yaml file, it changes both the name of the Helm chart deployment and the name of the service account used by NIM pods. However, if the serviceAccount.name field is not explicitly configured to match the fullnameOverride value, the deployment manifests will reference the default service account name (typically "nms"), which does not exist. This mismatch causes Kubernetes to reject pod creation attempts.

Answer/Recommended Actions

To resolve the service account mismatch issue when using name overrides:

  1. Open your Helm values.yaml file for editing.
  2. Locate or add the serviceAccount section.
  3. Set the serviceAccount.name field to match your fullnameOverride value:

    fullnameOverride: "nim"

    serviceAccount:
      name: nim

  4. Apply the updated Helm chart configuration:

    helm upgrade <release-name> nginx-stable/nim \

      -n <namespace> \

      -f values.yaml \

      --wait

  5. Verify that pods are created successfully:

    kubectl get pods -n <namespace>

    kubectl describe replicasets.apps -n <namespace>

  6. Confirm the correct service account is being used:

    kubectl get serviceaccounts -n <namespace>

    kubectl describe deployment <deployment-name> -n <namespace>

Additional Information

  • The fullnameOverride parameter affects multiple resources in the Helm chart, including the service account name. When this parameter is used without explicitly setting serviceAccount.name, a mismatch occurs between the created service account and the service account referenced in pod specifications.
  • The nameOverride parameter changes only the deployment name, while fullnameOverride changes both the deployment name and the service account name used for deploying NIM pods.
  • The complete NIM Helm chart values are not publicly documented. The nim.nameOverride and nim.fullnameOverride parameters are not included in the public Helm configuration settings documentation.
  • This configuration is typically needed in special circumstances such as:
    • Running multiple NIM instances in the same namespace
    • Meeting specific organizational naming conventions
    • Integrating with existing Kubernetes RBAC policies
