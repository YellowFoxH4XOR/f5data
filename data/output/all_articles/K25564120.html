Known Issue

The BIG-IP system may display an incorrect Quality of Service (QOS) topology load balancing score in logs generated by the Load-Balancing Decision Log feature.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP GTM system is configured to use the Topology load balancing method.
  • You have enabled the Load-Balancing Decision Log setting of a wide IP.
  • A query processed through the configured topology records is matched.

Impact

The logged QoS match virtual server value is represented incorrectly as 0 (zero); however, this issue is cosmetic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe messages similar to the following example:

    info tmm[<pid>]: 2016-02-29 12:18:48 <hostname> qid <qid> from <ip address>#37540: view none: query: <fqdn> IN A + (<virtual server address>%0)
    info tmm[<pid>]: 2016-02-29 12:18:48 <hostname> qid <qid> from <ip address>#37540 [<fqdn> A] [round robin selected pool (<pool name>)] [pool member check succeeded (<pool member name>:<ip address>) - pool member state is available (green)] [QoS selected pool member (<pool member name>:<ip address>) - QoS score (0) is higher]
  • When you view the virtual server configuration with the tmsh list ltm virtual <ltm virtual server name> gtm-score command syntax, the virtual server gtm-score is set to a value greater than 0 (zero).
  • When you use the tmsh show gtm server <server object name> detail command syntax, the Virtual Server Score is 0 (zero).
