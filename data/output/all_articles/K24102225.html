K24102225: Extended high CPU usage caused by JavaScript obfuscator after upgrade to 16.1.x or later

Type
Support Solution
Published
2022-07-22
Updated
2024-12-24
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.1.3, 17.0.0, 17.0.X, 17.1.0, 17.1.X, 17.X.X, 16.1.0, 16.1.1, 16.1.2, 16.1.X
Source
https://my.f5.com/manage/s/article/K24102225

Description

After upgrade to a version of 16.1.x or later, higher CPU usage for extended time may be seen.

Log messages similar to the following are logged to /var/log/datasync/datasyncd.log:

DATASYNCD|NOTICE|Jul 07 14:23:07.566|22888|datasyncd_main.c:5991|extgen_obfuscator_run: executing:
DATASYNCD|NOTICE|Jul 07 14:33:35.038|14844|datasyncd_main.c:6607|generator_complete: table CS_ASM_DOSL7 pid 22888 exit status 0

Note: The logs show that obfuscation took around 10 minutes to generate multiple copies in a single run. Typically it should about 2 minutes.

 

Environment

  • Post upgrade
  • ASM or Advanced WAF
  • FPS

Cause

BUG ID1060393 

 

Recommended Actions

Upgrade to a fixed version (16.1.5 and 17.1.2 and later).

Additional Information

Whilst the CPU usage is high on the odd cores due to ID1060393, production ( TMM ) should not be impacted.
Nevertheless, there could be other environmental factors that may affect performance such as BIG-IP under load from other process and tasks running which could be from ASM side ( policy builder, signature checking ) or even LTM ( syslog, iRules, monitors ) etc.
If that is the case, contact F5 Support for further assistance.
