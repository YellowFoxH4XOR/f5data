K90363355: The wamd process goes down after a BIG-IP upgrade.

Description

Upgrading a unit from version 11.5.4 that used WAM may fail due to a corrupt file in the configuration, this causes wamd to continuosly reboot.

err mcpd[5618]: 01070734:3: Configuration error: Policy "/Common/dev.backoffice.cfahome.com Policy", node "pv Includes", matching rule "path-segment:PV Tag(R0,key)": attribute arg_ordinal must be set to non-zero value.
err WA[12859]: Tmsh load failed: 01070734:3: Configuration error: Policy "/Common/dev.backoffice.cfahome.com Policy", node "pv Includes", matching rule "path-segment:PV Tag(R0,key)": attribute arg_ordinal must be set to non-zero value. Unexpected Error: Loading configuration process failed.

Environment

  • Upgrade from version 11.x
  • WAM Policy

Cause

File /config/policyDBDumpFixed.cfg gets corrupted and prevents wamd from starting.  This file was used to facilitate migrations between very old versions--version 10 to version 11, for example.

Recommended Actions

You can get wamd to start up by renaming the corrupt file and restarting wamd.  From the CLI:

  mv /config/policyDBDumpFixed.cfg /config/policyDBDumpFixed.cfg.orig
  bigstart restart wamd

None.
