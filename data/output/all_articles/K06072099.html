Description

Environment

  • RMA device
  • BIG-IP devices configured in an HA Pair
  • TMOS versions starting with 16.1.1, 15.1.5.1, 14.1.4.6, 13.1.5
  • FIPS hardware security module (HSM)

Cause
Issue is related to ID1136081 and occurs when the FIPS HSM card has been initialized on an impacted version.

Recommended Actions
Apply the following workaround steps on the impacted BIG-IP device (RMA) to resolve the fipscardsync issue:

  1. Downgrade the TMOS version to a non-impacted version (example, if the BIG-IP is currently running 14.1.4.6, downgrade to 14.1.4.4).
  2. Once the downgrade is completed, login to the BIG-IP CLI Advanced shell.
  3. Stop all of the service running on the BIG-IP. The prompt will read INOPERATIVE.
tmsh stop sys service all
  1. Reset the FIPS card
tmsh fips-util reset
  1. Initialize the FIPS card
tmsh fips-util init
  1. Restart services on the BIG-IP
bigstart restart
  1. Check the health of the FIPS card
tmsh show sys crypt fips key
Expected command output: 
root@localhost:Active:Standalone] config # tmsh show sys crypto fips key
-------------------------------------------
FIPS 140 Hardware Device
-------------------------------------------
no private keys found
  1. Build a new volume for the original version and boot into that volume. Don't boot back into the original volume.
  2. From the Active peer/source device sync FIPs configuration to the RMA device.
tmsh run util fips-card-sync -v <management IP of RMA device>

Additional Information
If you have not initialized the FIPS HSM card already, the issue can be avoided by initializing the FIPS HSM card on a non-impacted version of TMOS (ie versions prior to 16.1.1, 15.1.5.1, 14.1.4.6, 13.1.5).
