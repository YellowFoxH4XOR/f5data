Topic

You should consider using these procedures under the following condition:

  • You want to deploy a basic NGINX environment into a Docker container to build a custom configuration or test functionality.

Description

This article guides you through the process of deploying the default NGINX image from Docker Hub into your own Docker container environment and updating the default web page in the container.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have a test environment with Docker installed and configured. For more information about installing Docker, refer to Get Docker.

Procedures

  • Download and deploy the NGINX Docker image file
  • Stop, restart, and remove an existing container
  • Update web pages and view NGINX log files within a running container

Download and deploy the NGINX Docker image file

When you use the docker run command, Docker first checks your local system to see if the image already exists. If no image exists locally, the Docker default behavior is to attempt to pull the image from Docker Hub.

The following procedure pulls the latest NGINX official build from Docker Hub and deploys an NGINX container using the following options.

OptionDescription
-dDetached, this runs the container in the background and allows the container to continue running if you exit the command line.
--name <container name>Names the container to provide a simple way of referencing the running container.
-p <host port>:<container port>Specifies which external port should be published for mapping to the internal container listening port.
--restart=<policy>Defines the restart policy for when the container exits. The always policy allows the container to restart automatically if the host system is rebooted.
  • For more information about docker run options, refer to docker run.
  • For more information about restart policy options, refer to Start containers automatically.

    Note: These links take you to a resource outside of AskF5. The third party could remove the documents without our knowledge.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open a command prompt on your host system running Docker, with administrative privileges.
  2. Deploy the default NGINX image by entering the following command:

    docker run -d --name myNGINX_1 -p 8081:80 --restart=always nginx

Stop, restart, and remove an existing container

You can stop a running container by using the docker stop <container name> command syntax. When you stop a running container, unless the --rm run option was used when the container was created, the container remains on the system and can be restarted at a later time. To see stopped containers on your system, you must use the docker container ls -a command. By default, the command lists only running containers, but the -a option shows both running and stopped containers. To restart a stopped container, use the docker start <container name> command syntax. The container restarts using the same options that were used when the container was initially deployed. To remove a running container, you must first stop the container or use the -f (force) option together with the rm command, which sends a SIGKILL to the container.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open a command prompt on your host system running Docker, with administrative privileges.
  2. List the currently running Docker containers by entering the following command:

    docker container ls

    The output appears similar to the following example:

    CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS          PORTS                  NAMES
    4f69bfba060c   nginx     "/docker-entrypoint.…"   23 minutes ago   Up 23 minutes   0.0.0.0:8081->80/tcp   myNGINX_1

  3. Stop the myNGINX_1 container by entering the following command:

    docker stop myNGINX_1

    No output is returned.

  4. View stopped containers by entering the following command:

    docker container ls -a

    The output appears similar to the following example:

    CONTAINER ID   IMAGE                                 COMMAND                  CREATED          STATUS                      PORTS     NAMES
    4f69bfba060c   nginx                                 "/docker-entrypoint.…"   30 minutes ago   Exited (0) 5 seconds ago              myNGINX_1

  5. Restart the myNGINX_1 container by entering the following command:

    docker start myNGINX_1

    No output is returned.

  6. View the running containers by entering the following command:

    docker container ls

    The output appears similar to the following example:

    CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS          PORTS                  NAMES
    4f69bfba060c   nginx     "/docker-entrypoint.…"   32 minutes ago   Up 41 seconds   0.0.0.0:8081->80/tcp   myNGINX_1

  7. Stop and remove the running container by entering the following commands:

    docker stop myNGINX_1
    docker rm myNGINX_1

    No output is returned for either command.

Update web pages and view NGINX log files within a running container

One common method for accessing the container file system to perform tasks such as viewing NGINX log files or updating NGINX web pages is to attach to the container Bash shell and run interactive commands within the container. This is typically done by using a command similar to docker exec -it <container name> /bin/bash.

However, when deploying a new container, you can bind a local volume which allows you to map a directory within your container directly to a directory on your host system. This allows you to access container files such as web pages and log files, without having to use Docker to attach interactively to the container shell.

The following procedure demonstrates mapping the NGINX log directory and the default NGINX web root directory to directories on the local host.

Note: This procedure is performed on a Linux host. If you are using Windows or Mac, you must substitute file paths and system commands.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Open a command prompt on your host system running Docker, with administrative privileges.
  2. Create directories on your host system to use for mounting the container directories by entering the following commands:

    cd ~/
    mkdir -p nginx/logs nginx/html

    The output appears similar to the following example:

    mkdir: created directory 'nginx'
    mkdir: created directory 'nginx/logs'
    mkdir: created directory 'nginx/html'

  3. Deploy the default NGINX image, binding volumes for the logs and web root directories, by entering the following command:

    Note: Replace user1 with your actual username.

    docker run -d --name myNGINX_2 -p 8082:80 --restart=always -v "/home/user1/nginx/logs:/var/log/nginx" -v "/home/user1/nginx/html:/usr/share/nginx/html/" nginx

  4. List the currently running containers by entering the following command:

    docker container ls

    The output appears similar to the following example:

    CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS          PORTS                  NAMES
    761a666dcc1f   nginx     "/docker-entrypoint.…"   7 seconds ago    Up 6 seconds    0.0.0.0:8082->80/tcp   myNGINX_2

  5. Confirm that the NGINX logs appear in the ~/nginx/logs directory by entering the following command on your host system:

    ls -lh ~/nginx/logs

    The output appears similar to the following example:

    total 8.0K
    -rw-r--r-- 1 root root 729 Mar  3 12:08 access.log
    -rw-r--r-- 1 root root 625 Mar  3 12:08 error.log

  6. Using a text editor, create a file named index.html that contains the following text, and then save it in the ~/nginx/html directory:


    <!DOCTYPE html>
    <html>
      <head>
        <title>Hello World</title>
        <style>
          body {
            width: 35em;
            margin: 0 auto;
            font-family: Tahoma, Verdana, Arial, sans-serif;
          }
        </style>
      </head>
      <body>
        <h1>Hello World</h1>
        <p>Nice to meet you!</p>
        <p><em>Thanks for stopping by...</em></p>
      </body>
    </html>

  7. Use curl or your local web browser to connect to http://localhost:8082 to confirm that the new web page is served by the container instance of NGINX.
  8. Optional: Delete the container by using the steps in the Stop, restart, and remove an existing container procedure.

    Note: If you delete containers that have attached volumes, volumes remain intact by default. This is by design and intended to prevent data loss. If you want to remove volumes along with the container, you can use the -v option. For example: docker rm <container> -v. For more information, refer to docker rm.
