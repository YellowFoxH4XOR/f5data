K83093212: The BIG-IP ASM system may stop enforcing attack signatures after applying a security policy that includes a new signature

Type
Security Advisory
Published
2018-09-18
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 12.1.3, 12.1.2
Source
https://my.f5.com/manage/s/article/K83093212

Security Advisory Description

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system is running versions 12.1.2 through 12.1.3.6.
  • You configure multiple security policies on the BIG-IP ASM system.
  • One of the security policies includes a new attack signature not included in the other policies.
  • You apply the security policy that includes the new signature. For example, you click the Apply Policy button or import the policy and associate it with a virtual server.

When the security policy is applied, the system regenerates the base signature collection with an incremented ID.  When this issue occurs, only the newly applied security policy is updated to reference the new signature collection ID.

Impact

The BIG-IP ASM system stops enforcing attack signatures in other security policies.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After applying a security policy, the BIG-IP ASM system stops enforcing attack signatures.
  • In the /var/log/ts/bd.log file, you notice error messages for all other policies that appear similar to the following example:

    ATTACK_SIG|ERR   |<date> <time>|19061|attack_patterns_funcs.cpp:0123|Can't run patterns - no set attached.

Security Advisory Recommended Actions

Workaround

Note: The workaround does not fix the root cause of this issue or eliminate the possibility of the issue reoccurring. To eliminate the possibility of the issue reoccurring, you must upgrade to a version listed in the Fixes introduced in column of the previous table.

To work around this issue, you can update the other security policies to reference the new signature collection ID. To do so, perform the following procedure:

Impact of workaround: The following procedure applies any pending changes to the security policies.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy > Policy Properties.
  3. In the Current edited security policy list, click the security policy.
  4. Make a spurious change to the selected policy. For example, you can modify the policy description or add a new custom attack signature and remove the signature.
  5. Click Save.
  6. Click Apply Policy.
  7. Repeat steps 3 and 4 for the other affected security policies configured on the system.
