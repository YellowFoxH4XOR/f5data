Known Issue

This is the result of a known issue. When the BIG-IP system exceeds its compression license limit, a message reporting this fact should be logged to the /var/log/ltm file once per day. However, the BIG-IP system logs this message once after TMM starts up, and thereafter every 1,000 days.

Note: For more information about how the BIG-IP system is expected to behave when it exceeds its compression license limit, refer to K3741: Determining whether a compression license has been exceeded.

F5 Product Development tracked this issue as ID 344037, and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the LTM, ASM, Link Controller, or WebAccelerator release notes.

Workaround

You can determine whether you are exceeding your compression license limit by using one of the following methods:

  • Checking the Throughput performance graph in the BIG-IP Configuration utility (under Overview >> Performance).
  • Checking the compression statistics by running the bigpipe http show command from the BIG-IP command line.

    Note: The following example output shows that NULL compression traffic is not 0 (zero). NULL compression traffic is the traffic that the BIG-IP system received, but did not compress because the compression license limit was exceeded. If NULL compression traffic is not 0, you have exceeded your compression license limit:

    | COMPRESSION STATISTICS --
    | total bytes (pre, post, null, saved) = (23.79T, 4.465T, 13.76G, 81.23%) <------
    | HTML bytes (pre, post, saved) = (474.5G, 88.75G, 81.30%)
    | CSS bytes (pre, post, saved) = (291.7G, 47.72G, 83.64%)
    | JS bytes (pre, post, saved) = (1.242T, 312.2G, 74.87%)
    | XML bytes (pre, post, saved) = (132.7M, 28.93M, 78.21%)
    | plain text bytes (pre, post, saved) = (33891, 6754, 80.07%)
    | other bytes (pre, post, saved) = (21.78T, 4.017T, 81.56%)
