K26330618: Communication issue between vCMP Guests due to HSB error in vCMP Host

Type
Support Solution
Published
2022-10-23
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K26330618

Description

In a typical vCMP environment you may experience packet loss between specific vCMP Guests causing communication issues due to High-Speed Bridge internal interface(s) reporting interface flapping in the vCMP Host. This can avoid the vCMP Guests to communicate for config-sync and failover operations through TMM self-ips.

The BIG-IP device can perform an unexpected reboot.

You may see similar logs like the following in the vCMP Host:
Apr 27 11:01:51 slot7/example info bcm56xxd[13585]: 012c0015:6: Link: 7/9.2 is DOWN
Apr 27 11:01:51 slot7/example info bcm56xxd[13585]: 012c0012:6: HSB 37 HGM 1 LBB address 0x90000008 XLMACs status updated

Environment

  • BIG-IP
  • Platform that utilizes HSB interfaces, such as Viprion or iSeries

Cause

The HSB interface flapping is related to interface errors.

Recommended Actions

Rebooting the blade that is experiencing the errors should clear the errors and return the blade to normal functionality.

To reset a single blade in a VIPRION system, perform the following procedure:
  1. Log in to the command line of the VIPRION blade.
  2. To verify the slot number of the blade to which you are connected, type the following command:
    bladectl -g slot
     
  3. To reset the blade, use the following command syntax:
    bladectl -b <blade#> -r

    For example, if you are logged in to blade1 and want to reset blade7, type the following command:
    bladectl -b 7 -r
iSeries
Reboot the system to clear the errors and restore functionality
  1. Log in to the command line of the BIG-IP
  2. Reboot the system
    reboot

Additional Information
These errors may indicate a hardware error in the HSB SRAM that impedes traffic through embedded Packet Velocity Acceleration (ePVA). To confirm if there is hardware issue we will recommend to Run an End User Diagnostics on the unit in question.
