Known Issue

Dynamic routes, for the default route domain (route domain 0), may not function after performing configuration changes on non-default route domains.

This issue occurs when the following conditions are met:

  • A dynamic routing protocol is configured for the default route domain and one or more non-default route domains.
  • You perform a configuration change on a non-default route domain.

    For example, this condition exists when you remove a routing protocol from the non-default route domain or delete the non-default route domain.

Impact

Routing for the default route domain may be impacted.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Dynamically learned routes, in the default route domain, are not reachable even though the routes appear as expected in the routing table.

Workaround

To work around this issue, you can avoid reconfiguring or deleting non-default route domains.

To recover from this issue, and re-enable the routes for the default route domain, you can run the bigstart restart tmrouted command.

Impact of workaround: The tmrouted process is responsible for routing table management. While this process is down, the Traffic Management Microkernel (TMM) cannot learn or advertise routes.
