Description

RSA Authentication is observed to work on one device but after failing over to the peer device, RSA does not work. 
This solution article describes how to configure RSA authentication for BIG-IP APM devices configured in HA.

Environment

  • APM configured in Active-Standby HA setup
  • RSA authentication 

Cause

RSA authentication failing after HA is failed over to standby device.
In case a non-floating Self-IP is configured as the source IP for RSA , the standby device will not be able to use this IP as it doesn't own it and authentication will fail.

Recommended Actions
To setup RSA for BIG-IP in HA configuration, we need to setup the RSA source IP to a floating Self-IP so that authentication doesn't fail after the HA is failed over to Standby.
 

  1. On RSA server,
    • Create a Standard Authentication Agent (not Radius) using Floating Self-IP of BIG-IP as the primary IP and add the non-floating Self-IP from both devices as Alternate IPs
    • Generate the configuration file 
    • Extract this Configuration file on your system (you need to import the sdconf.rec file extracted here to the BIG-IP device in step 2.
  2.  On BIG-IP , create a new SecurID AAA object using Floating Self-IP of BIG-IP and sdconf.rec configuration file generated above.
  3.  Apply the policy changes 
  4. Test the authentication (you can use secureidtest utility as well)
  5. Sync the changes from Active to Standby 
  6. Using Command line , in the config/aaa/ace/Common/<AAA object name>/ directory, find the securid and sdstatus.12 files and copy them to the same folder on the standby device. These are the node secret and status files. 
  7. Restart the aced service on standby device using command: tmsh restart sys service aced
  8. Failover to Standby device and test
