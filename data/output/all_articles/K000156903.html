Description

The BIG-IP system frequently logs idle enforcer activation and deactivation messages to /var/log/kern.log:

info kernel: ltm driver: Idle enforcer starting
info kernel: ltm driver: Idle enforcer exiting

These messages appear every several minutes, with the idle enforcer being deactivated within the same second of invocation. System performance graphs show low overall CPU usage, indicating the idle enforcer is triggered by very short CPU spikes that are not visible in standard monitoring. This behavior occurs even when no performance degradation is observed.

Environment

  • Low overall CPU usage observed in system graphs
  • Idle enforcer starting and exiting logs in /var/log/kern.log
  • SSL profiles configured and in use

Cause

ID1306249

Recommended Actions

Disable the tmm.ssl.useffdhe database variable to stop periodic key pair generations.

1) Set tmm.ssl.useffdhe to 'false' using the following commands:

tmsh modify sys db tmm.ssl.useffdhe vale false

2) Save the configuration:

tmsh save sys config

Important: Disabling tmm.ssl.useffdhe stops periodic key pair generations. In active production environments where SSL profiles are used, key material is generated as necessary and cached. This change should not adversely affect SSL handshakes or client connections on virtual servers.

Additional Information

  • The Idle Enforcer is a kernel process activated when data plane CPU usage on a hyperthread exceeds 80% for at least 100ms. It temporarily pauses the control/analysis plane hyperthread to prioritize data plane processing, ensuring high data plane activity does not negatively impact control or analysis plane tasks on the same physical core.

  • According to K10337613, infrequent Idle Enforcer messages can be ignored as transient spikes. However, frequent messages may indicate the system is operating at or near its maximum data plane capacity, potentially causing delays in control plane tasks or affecting management responsiveness.

  • On fixed versions (17.1.2.1, 17.5.0, and later), the new database variable tmm.ssl.useffdhe has been implemented as part of the bug fix. Upgrading to a fixed version alone is not sufficient to eliminate the idle enforcer messages; the database variable must be explicitly set to false.

  • If no performance impact is observed (such as issues with traffic handling, GUI responsiveness, or monitor intervals), the idle enforcer messages are likely caused by brief, transient CPU spikes from periodic key generation rather than sustained high CPU usage.
