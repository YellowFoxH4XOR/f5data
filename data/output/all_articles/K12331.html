K12331: Mac OS X users may experience routing issues if the local LAN subnet and lease pool address space intersect

Known Issue

This is the result of a known issue. A Mac OS X user's route table may not include a route for the local LAN subnet if all of the following conditions exist:

  • A MAC OS X user initiates a Network Access session
  • Network Access is configured to use a lease pool that intersects with the local LAN subnet
  • Network Access is configured to use split tunneling

For example, if the lease pool is using 10.10.10.100/30 and the local LAN subnet is 10.0.0.0/8, the user can run the netstat -rn command from the client's command line to see that the route for 10.0.0.0/8 is missing.

F5 has confirmed that this issue exists in the products listed in the Applies To box. ID #341234 has been assigned to this issue.

Fixed versionsNoneK2200: Most recent versions of F5 software

Workaround

You can work around this issue using one of the following two options:

  • Change the lease pool address space to avoid intersecting with the local LAN subnet. In the example above, if 172.16.1.1/30 is used for the lease pool address space, the route for 10.0.0.0/8 will appear in the user's route table.

    Note: For instructions about creating a new lease pool, refer to the FirePass Controller Administrator Guide.
  • Do not use split tunneling. All traffic will go to your FirePass device and will circumvent the missing route if you select the Force all traffic through tunnel Traffic option in the Network Access General Properties.
