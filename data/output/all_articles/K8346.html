Known Issue

This is the result of a known issue. If a FastHTTP-enabled virtual server containing a pool is switched to a pool with members that are down, TMM may crash.

This issue occurs under the following conditions:

  • Open client connections exist with a pool that is accessed through a virtual server using a FastHTTP profile.
  • Another pool containing members that are down is assigned to the virtual server.

In this situation, TMM does not correctly remove the connection references for the previous pool members, and attempts to associate the connection references with the new pool members.

F5 Product Development tracked this issue as CR90456 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IPLTM release notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.3-14.3-HF3 issued for BIG-IP version 9.4.3. You may download this hotfix or a later version of this hotfix from the F5 Downloads site.
