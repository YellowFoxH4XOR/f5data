K000162833: AS3 declaration timeouts when it reaches the filesystem link-count limit

Type
Support Solution
Published
2026-08-07
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000162833

Description

AS3 declarations may be accepted but eventually timed out, when the configuration-history directory reaches the filesystem directory link-count limit. The affected directory is:

/config/.diffVersions/config/partitions/

When this directory contains 32,000 subdirectories, BIG-IP may be unable to create additional configuration-history subdirectories required for new partitions.

Environment

  • AS3 declarations that frequently create new partitions
  • AS3 declarations configured for persistent storage

Cause

The underlying cause is the filesystem link-count limit for the /config/.diffVersions/config/partitions/ directory. The limit is approximately 32,000 subdirectories. The directory tracks configuration changes for partitions. Deleting a partition from the active configuration does not automatically remove its corresponding configuration-history directory. Repeated creation of uniquely named partitions can therefore cause historical subdirectories to accumulate.

Recommended Actions

  1. Move or remove historical subdirectories for partitions that are no longer needed. Moving them to separate storage preserves the data while reducing the number of entries in the affected directory.
  2. If the customer keeps sending new configs in new partitions, it will reach the limit again sooner or later. So, the best way to avoid this issue is to properly design and reuse the partition names if possible.
