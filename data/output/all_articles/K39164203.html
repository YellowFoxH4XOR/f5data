Description

An error message similar to the following is generated when attempting to enter the imish shell from the command line:

Dynamic routing is not enabled in route domain <route domain ID>

Environment

  • Advanced Routing Module

Cause

This message is returned when attempting to enter the imish shell if a dynamic routing protocol is not enabled for a route domain, the tmrouted daemon is not running, the Advanced Routing Module isn't licensed, or the device is in an offline state.

Recommended Actions

Perform the following procedures to troubleshoot this issue:

  • Verifying that a routing protocol is enabled
  • Verifying the tmrouted daemon
  • Verify the Advanced Routing Module is licensed
  • Verifying the state of the device

Verifying that a dynamic routing protocol is enabled

Run the following command to determine if a dynamic routing protocol is enabled for the route domain:

list /net route-domain <route_domain_name> routing-protocol

The example output below indicates that there are no dynamic routing protocols enabled for route domain 0:

net route-domain 0 {
    routing-protocol none
}

Refer to the following article to enable a dynamic routing protocol for a route domain:

  • K13802: Enabling dynamic routing protocols for a route domain

Verifying the tmrouted daemon

If the tmrouted daemon is not running, dynamic routing will not function and the imish shell will be inaccessible.

Run the following command to verify the status of the tmrouted daemon:

show /sys service tmrouted

The example output below indicates that the tmrouted daemon is not running:

tmrouted     down 23 hours, normally up

Run the following command to start the tmrouted daemon:

start /sys service tmrouted

Verify the Advanced Routing Module is licensed

You can determine if your system is licensed for BIG-IP ARM by checking for Routing Bundle under Active Modules on the License page in the Configuration Utility or show sys license in the TMOS Shell (tmsh).

Verifying the state of the device

If the device is in an offline state, the imish shell will be inaccessible, even if the tmrouted daemon is running.

The command line prompt will indicate if the device is in an offline state. Additionally, the configuration utility will display OFFLINE in the top left of the screen.

You may also verify if the device is in an offline state with the following command:

show /sys failover
