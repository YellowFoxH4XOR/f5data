BIG-IP platforms support NATIVE and COMPAT SSL stacks. Each SSL stack supports a different set of SSL ciphers.

NATIVE SSL stack

The NATIVE SSL stack contains cipher suites that are optimized for the BIG-IP system. You can use these suites to leverage hardware acceleration for bulk crypto operations. The NATIVE SSL stack is faster than the COMPAT SSL stack and supports SSL ciphers that address most SSL connections. However, not all cipher suites in the NATIVE stack are hardware accelerated. When you use a NATIVE cipher that hardware acceleration does not support, it results in higher CPU utilization on the BIG-IP system. For more information about hardware accelerated cipher suites on varying platforms, refer to K13213: SSL algorithms that are hardware accelerated (11.x - 12.x).

To view the current NATIVE cipher list for the specific version and hotfix level that your system is running, run the following command from the command line:

tmm --clientciphers NATIVE

COMPAT SSL stack

The COMPAT stack supports ciphers from the OpenSSL suite. The COMPAT stack is slower than the NATIVE SSL stack and requires more memory per connection than the NATIVE stack. The COMPAT SSL stack does not make use of hardware acceleration.

Note: Beginning in BIG-IP 12.0.0, the COMPAT stack contains no ciphers. For additional information, refer to K17373: The COMPAT SSL stack has been deprecated and contains no SSL ciphers by default.

To view the current COMPAT cipher list for the specific version and hotfix level that your system is running, run the following command from the command line:

tmm --clientciphers COMPAT

Supported ciphers

Note: For information about the specific ciphers supported in default SSL profiles, refer to K13156: SSL ciphers used in the default SSL profiles (11.x - 13.x).

The SSL ciphers that BIG-IP systems support vary across BIG-IP versions. View the SSL ciphers supported by the NATIVE and COMPAT stacks in the following BIG-IP versions:

  • BIG-IP 13.0.0 - 13.1.0
  • BIG-IP 12.0.0 - 12.1.3
