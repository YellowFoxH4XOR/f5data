Known Issue

This is the result of a known issue. The mcpd process does not provide proper validation checks for high availability group names. Therefore, you can use the Configuration utility to create a high availability group object with a space in the name, or a number as the first character of the object name. If you subsequently attempt to load the configuration by running the bigpipe load, tmsh command, or as the result of a ConfigSync operation, the system returns a bigpipe parsing error message.

Note: Starting in BIG-IP version 10.1.0, you can configure high availability groups, which are a set of configuration objects that the BIG-IP system uses to calculate an overall health score for a unit in a redundant system configuration. For more information, refer to TMOS Management Guide for BIG-IP Systems.

For example, the following tmsh command output displays a high availability group named bogus group, which was created using the Configuration utility:

# tmsh list /sys ha-group

sys ha-group "bogus group" {
active-bonus 50
pools {
syslog_pool {
weight 20
}
ubuntu-test {
percent-up 100
weight 10
}
}
}

If you attempt to load the configuration containing the high availability group in which the name contains a space, or begins with a number, the system returns a bigpipe parsing error message that appears similar to the following example:

# tmsh load /sys config

Reading configuration from /config/low_profile_base.conf.
Reading configuration from /defaults/config_base.conf.
Reading configuration from /config/bigip_sys.conf.
Reading configuration from /config/bigip_base.conf.
Reading configuration from /usr/share/monitors/base_monitors.conf.
Reading configuration from /config/profile_base.conf.
Reading configuration from /config/daemon.conf.
Reading configuration from /config/bigip.conf.
Reading configuration from /config/bigip_local.conf.
BIGpipe parsing error (/config/bigip_local.conf Line 1):
012e0020:3: The requested item (group {) is invalid (<ha group arg> | show | list | edit | delete) for 'ha group'.

F5 Product Development tracked this issue as ID 345791 and it was fixed in BIG-IP version 10.2.2.

For information about upgrading, refer to the BIG-IP release notes.

Workaround

You can work around this issue by ensuring that you do not create high-availability groups in which the name contains a space or begins with a number.
