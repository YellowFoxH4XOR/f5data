Known Issue

This is the result of a known issue. 3-DNS is not able to learn the addresses of a virtual server's nodes when the virtual server is not configured with a default pool. Because of this, 3-DNS is unable to obtain the node status for the virtual server's nodes and will consider the virtual server to be down.

F5 Product Development tracked this issue as CR44570 and it was fixed in BIG-IP LTM 9.0.5. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by defining a default pool for the virtual server that is using a rule. 3-DNS will then be able to obtain the status of the nodes that are associated with the pool and will correctly mark the status of the virtual server based on the status of its nodes.

If you use this workaround, it is best to define a new pool that contains all the nodes that can be accessed through the rule so that the status of the virtual server is based on the status of the nodes that it uses.

For specific information about configuring default pools, refer to the 3-DNS Reference Guide.
