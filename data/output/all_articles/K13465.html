Known Issue

The BIG-IP system may fail to properly flush database entries for interface 1.1 from the Layer 2 Forwarding table (FDB) for a five minute period. This issue is due to the Broadcom switch configuration on BIG-IP 1600 and 3600 platforms, which creates a default hidden trunk containing interface 1.1.

This issue occurs when the following conditions are met:

  • You are running a BIG-IP 1600 or 3600 platform
  • The network cable is disconnected from interface 1.1

Impact

This issue may result in a traffic disruption if the VLAN contains interfaces in addition to 1.1.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system may attempt to send traffic through interface 1.1 after it is disconnected. This may result in a traffic disruption if the VLAN contains interfaces in addition to 1.1.
  • Running simultaneous tcpdump commands on the affected VLAN and another interface on the VLAN will show traffic is not correctly flooded to the alternate interfaces after interface 1.1 is disconnected. For example:

    • A VLAN named external contains interfaces 1.1 and 1.2
    • You disconnect interface 1.1 while running the tcpdump command on the VLAN (tcpdump -ni external)
    • The capture will show TMM attempting to forward traffic on the VLAN
    • However, running a simultaneous tcpdump command on interface 1.2 (tcpdump -ni 1.2) shows that no traffic is flooded to interface 1.2

Status

Workaround

To work around this issue, disconnect interface 1.1 during a maintenance window. You can safely bring the system online after the five minute period has elapsed. Alternatively, you can work around this issue by refraining from using interface 1.1.
