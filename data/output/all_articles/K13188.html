Known Issue

Description

When CLI commands encounter conflicts, the CLI engine automatically retries (up to 50 times). However, in the case of an at schedule command, each retry causes a duplicate entry to be made in the Linux at schedule. When this occurs, the ARX will execute the duplicate instances of the same CLI script concurrently. Concurrent updates to the AtScheduleRecord in the at database may cause a rootd segmentation fault.

This issue occurs when all of the following conditions are met:

  • A recurring task is configured in the at schedule. 
  • A conflict is encountered requiring the task to be rescheduled.
  • Multiple concurrent updates are attempted to the AtScheduleRecord in the at database.

Note: Multiple tasks scheduled to start at the same time will increase the likelihood of this issue occuring.

Impact

Scheduled tasks may not be performed.

Workaround

There is not a work around for this issue. However, to minimize the likelihood of this issue occurring, you should schedule your jobs to not start at the same time.

To recover from this issue, you must remove all of the scheduled at tasks, then re-enter the desired tasks with individual start times. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Remove at entries from the database by typing the following command:

    clear at
  4. Enable configuration mode by typing the following command:

    config
  5. Re-enter desired tasks using the at command. Ensure each scheduled task has a unique start time.
