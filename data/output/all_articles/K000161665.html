K000161665: F5OS rSeries Tenant: Only One Self-IP Reachable at a Time When Two VLANs in Different Route Domains Share the Same Subnet

Type
Support Solution
Published
2026-06-10
Updated
2026-06-10
Applies to
  • F5OS
  • F5OS-A: 1.8.3
Source
https://my.f5.com/manage/s/article/K000161665

Description

On an F5OS rSeries appliance, when a BIG-IP tenant has two VLANs assigned to different route domains with self-IPs configured on the same subnet, only one self-IP is reachable at a time. Pinging one self-IP succeeds while the other fails, and the reachable self-IP may alternate unpredictably. 

Environment

  • F5OS-A
  • Single BIG-IP tenant with multiple VLANs assigned
  • VLANs assigned to different route domains
  • Self-IPs on the same or overlapping subnet across route domains
  • Tenant configured with mac-block-size one (default)
  • The F5OS FDB (Forwarding Database) shows both VLAN entries registered with the same MAC address

Cause

By default, F5OS allocates a MAC block size of one (mac-block-size one) to each BIG-IP tenant. This means the tenant receives only a single MAC address, which is shared across all VLANs configured within that tenant regardless of route domain assignment.

When two self-IPs on different route domains share the same subnet and the same MAC address across two VLANs on the same LAG or interface, the upstream switch/router ARP table becomes ambiguous. Both VLANs advertise ARP replies with the same source MAC address. The upstream device can only maintain one ARP entry per IP, so the last ARP reply received wins making only one self-IP reachable at a time. 

Answer/Recommended Actions

  1. On the F5OS host CLI, confirm the current MAC block size:  
    show running-config tenants tenant <tenant-name>
  2. Verify duplicate MAC in FDB  
    show fdb
  3. Verify duplicate MAC on the BIG-IP tenant  
    tmsh show net vlan
  4. Set the tenant to provisioned state  
    config
tenants tenant <tenant-name> config running-state provisioned
commit
  5. Change the MAC block size: (Small 8 MAC, Medium 16 MAC and Large 32 MAC)   
    tenants tenant <tenant-name> config mac-data mac-block-size <small/medium/large>
commit
  6. Redeploy the tenant:  
    tenants tenant <tenant-name> config running-state deployed
commit
top
  7. Verify the new MAC pool:  
    show tenants tenant <tenant-name> state mac-data
  8. Verify connectivity

Additional Information

The maximum MAC block size per tenant on rSeries is 32. If more than 32 VLANs require unique MACs.
