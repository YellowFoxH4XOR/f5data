K000148991: Weak ciphers are present in the security scanner results even they had been removed from the BIG-IP

Type
Support Solution
Published
2024-12-15
Updated
2025-03-10
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.0.0, 16.1.0, 16.0.X, 16.0.1, 17.X.X, 16.X.X, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0, 16.1.X, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 15.1.10
Source
https://my.f5.com/manage/s/article/K000148991

Description

We observe in the security scanner two weak ciphers not being removed:

  • TLS_ECDHE_RSA_WITH_AES_256_CBC_SHA384
  • TLS_ECDHE_RSA_WITH_AES_128_CBC_SHA256

After checking the configuration of the BIG-IP, it turns out they have already been removed.

Environment

  • BIG-IP LTM
  • Ciphers
  • Vulnerability Scans

Cause

There can be different reasons for this behavior.

Recommended Actions

You can consider one of the possible approaches to solving this problem:

  • Suggested the article to check for the problematic ciphers:

K26146603: SSL scan fails with 'server does not support Authenticated encryption (AEAD) cipher suites'

  • Also, suggested failover to clear up some of the old SSL connections:

K42061352: How to perform a Manual Failover of a BIG-IP High Availability Traffic Group from the Webui

  • Disabling the SSL cache by setting below two values to 0 (to the SSL profile):

cache-size 0
cache-timeout 0
