Description


phonehome_upload output Failed to obtain certificate cache path error on /var/log/ltm

Oct 27 11:40:53 test.bigip.lab err phonehome_upload[20198]: 01a70131:3: Error: Failed to obtain certificate cache path

Environment

  • BIG-IP

Cause


An SSL certificate named "f5_api_com.crt" is missing from the BIG-IP configuration.  One way this can happen is via Bug ID 1070393, where the certificate is added to the configuration automatically during the licensing process, but the configuration is (incorrectly, due to the bug) not saved to disk afterwards.

As a result, the  phonehome_upload script logs an error, due to not being able to locate the f5 API certificate.

Recommended Actions

In some cases, the certificate file may still be present in the file system, under /config/ssl/ssl.crt/, in which case the related BIG-IP configuration object can simply be recreated using the following steps:
 

  1.  Access the tmsh commandline prompt
  2.  Create the certificate:  (bigip-1)# tmsh create sys file ssl-cert f5_api_com.crt source-path file:///config/ssl/ssl.crt/f5_api_com.crt
  3. . Save the config: (bigip-1)# tmsh save sys config
 

Additional Information

If the certificate is missing from /config/ssl/ssl.crt/, you can pull down a new copy from the f5 license server, by reactivating your BIG-IP license with the 'automatic' reactivation method in the GUI.
 
Note that reactivating the license will cause the configuration to be loaded again, and may create a short service outage.  F5 recommends this is done during a maintenance window, or on the standby device of an HA pair, to minimise impact.
