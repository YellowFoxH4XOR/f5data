Known Issue

A VIPRION system may experience a snmpd memory leak.

This issue occurs when the following condition is met:

  • You run continuous snmpbulkwalk operations against the VIPRION system.

Impact

The snmpd process memory usage increases, and may eventually result in the process restarting and creating a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe messages similar to the following example:

    err mcpd[2345]: 01071087:3: Killed process for snmpd as current count of messages (965505855) keeps building.

  • In the /var/log/messages file, you observe messages similar to the following example:

    notice out of memory [1234]
    notice logger: Started writing core file: /var/core/snmpd.bld0.0.555.core.gz for PID 1234
    notice logger: Finished writing 220379369 bytes for core file: /var/core/snmpd.bld0.0.555.core.gz for PID 1234

Workaround

To work around this issue, you can proactively reset memory usage and prevent the snmpd process from creating a core file. To do so, perform the following procedure:

Impact of workaround: While the snmpd process is restarting, SNMP will not be available.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the snmpd process by typing the following command:

    restart /sys service snmpd
