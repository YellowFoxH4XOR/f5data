Known Issue

Configuration changes on 1.x ports may disrupt ongoing traffic on other 1.x ports.

This issue occurs when all of the following conditions are met:

  • The affected BIG-IP platforms include the following series:
    • BIG-IP 2000 series (C112)
    • BIG-IP 4000 series (C113)
  • You apply either of the following configuration changes to the 1.x network ports:
    • Disable and re-enable the affected network port
    • Force media on the affected network port
  • The grouping of the ports affecting other ports include the following:
    • Group A: ports 1.1, 1.2, 1.3, and 1.4
    • Group B: ports 1.5, 1.6, 1.7, and 1.8

Configuration changes made to any ports in a group affect the remaining ports that belong to the same group, even when the other ports' configurations were not modified. This issue occurs even if the affected interfaces belong to different Virtual Local Area Networks (VLANs).

Impact

Traffic is disrupted or halted on the affected group of 1.x ports.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you modify ports, the system experiences disruptions or halted traffic on other 1.x ports that were not modified.

    For example, if one or more ports in Group A has been modified, the traffic on ports 1.1, 1.2, 1.3, and 1.4 are affected.
  • Traffic remains disrupted or halted until further action is taken.

Workaround

To work around this issue, you can perform one of the following procedures:

  • Resetting port 1.2
  • Resetting port 1.6
  • Restarting the TMM process

Resetting port 1.2

To work around this issue when the affected port belongs to Group A, you can reset port 1.2 to restore traffic processing for the affected group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Network.
  3. Click Interfaces.
  4. Click Interface List.
  5. For the affected ports that belong to Group A, select 1.2 from the interface list.
  6. From the State menu, select Disabled.
  7. Click Update.
  8. From the State menu, select Enabled.
  9. Click Update.
  10. Verify that affected ports have restored traffic processing.
  11. Optional: Perform the Restarting the TMM process procedure.

Resetting port 1.6

To work around this issue when the affected port belongs to Group B, you can reset port 1.6 to restore traffic processing for the affected group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Network.
  3. Click Interfaces.
  4. Click Interface List.
  5. For the affected ports that belong to Group B, select 1.6 from the interface list.
  6. From the State menu, select Disabled.
  7. Click Update.
  8. From the State menu, select Enabled.
  9. Click Update.
  10. Verify that affected ports have restored traffic processing.
  11. Optional: Perform the Restarting the TMM process procedure.

Restarting the TMM process

Alternatively, if the previous procedures are unable to restore traffic processing on the affected group of network ports, you can restart the Traffic Management Microkernel (TMM) to clear the errors affecting the ports.

Impact of workaround: Restarting TMM interrupts traffic processing; you should perform this procedure in a maintenance window. If the system is configured as part of a high-availability pair, the device may fail over.

To restart the TMM process, type the following command from the BIG-IP command line:

bigstart restart tmm
