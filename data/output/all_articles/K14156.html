Known Issue

The BIG-IP system may drop packets for connections to a self IP that is defined on a non-default route domain.

This issue occurs when the following conditions are met:

  • The client connects to a BIG-IP LTM system on a self IP address.
  • The self IP address is defined on a non-default route domain.

For example, a client connecting to the Configuration utility, or a BIG-IP GTM system connecting to a BIG-IP LTM system through iQuery would cause this issue. The BIG-IP system internally translates all IPv4 addresses to IPv6. This issue is due to the ingress MTU value set by the BIG-IP system for the IPv4 connection, which results in the IPv6 connection being unable to send full-sized frames.

Impact

  • Clients are unable to use the Configuration utility as expected.
  • BIG-IP GTM is unable to auto-discover BIG-IP LTM virtual servers.
  • BIG-IP GTM stats for BIG-IP LTM virtual servers are unreliable.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client connections to the BIG-IP LTM Configuration utility are sporadic or time out.
  • The BIG-IP GTM auto-discover function does not return objects from a BIG-IP LTM system.
  • BIG-IP GTM reports that BIG-IP LTM virtual servers are frequently changing state.
  • A packet trace from the VLAN of the non-default route domain may include the following message:

    ICMP6, packet too big

Workaround

There is no workaround for this issue. However, you may be able to mitigate this issue by setting the MTU on the client device to 1460 or smaller. If the client device is a BIG-IP GTM system, you can set the MTU to 1460 on the VLAN that is used to connect to the self IP address on the non-default route domain of the BIG-IP LTM system.

Impact of workaround: Setting the client MTU to a smaller size may have an impact on network capacity.
