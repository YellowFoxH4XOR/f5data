Description
Upgrade F5OS-A (rSeries 4000 series) to 1.2.0 is failing. 

error-type : application
error-tag : malformed-message
error-path : /openconfig-system:system/f5-system-image:image/set-version
error-message : System database upgrade compatibility check failed.

on CLI (log in as root), running below command and  F5OS-A-1.1.1-9159.R2R4.iso is NOT listed but F5OS-A-1.2.0-10139.R2R4.iso

ls -l /var/import/staging/
/var/import/staging/:
total 3665936
      4 drwxr-xr-x. 2 root root       4096 Oct  3 11:49 .
      4 drwxr-xr-x. 7 root root       4096 Oct  3 11:51 ..
3665928 -rw-------. 1   48   48 3753902592 Oct  3 11:49 F5OS-A-1.2.0-10139.R2R4.iso
 

Environment

  • F5OS-A
  • rSeries 2xxx/4xxx appliance
  • Upgrade to 1.2.0

Cause

  • A limited number of BIG-IP rSeries 2xxx/4xxx systems do not have the base ISO image file (F5OS-A version 1.1.0) installed.  This issue, combined with an inability to upgrade if the image file does not exist on the disk, will prevent the upgrade from completing.
  • Note that F5OS-A version 1.1.0 is no longer available on the F5 Downloads site.

Recommended Actions

  1. Log in to Appliance CLI with root account
  2. make a backup for /var/import/import.json
    cp /var/import/import.json /var/import/import.json.bk
     
  3. open the import.json file and check what "port" is assinged to "1.2.0" in the file.
    If "port" is find only for v1.2.0, then change the value to 1 above
    e.g.
         "date": "2022-07-28",
         "platform": "R2R4",
         "status": "100",
         "source": "/var/export/chassis/import/.mounts/iso/R2R4/1.2.0-10139/m3/*-services/F5OS*.img",
         "version": "1.2.0-10139",
         "component": "services",
         "port": "2000",   <<<------------------------------This needs to be "2001"
         "size": 2108215808,
         "error": "",
         "subcomponents": []
    if there are multiple port number for each versions, change to 1 above of highest port number
    e.g. NOTE: below is due to admin manually imported 1.1.1 iso to this system.
         "date": "2022-07-28",
         "platform": "R2R4",
         "status": "100",
         "source": "/var/export/chassis/import/.mounts/iso/R2R4/1.2.0-10139/m3/*-services/F5OS*.img",
         "version": "1.2.0-10139",
         "component": "services",
         "port": "2000",   <<<------------------------------------------This needs to modify to "2002"
         "size": 2108215808,
         "error": "",
         "subcomponents": []
       ...
           "date": "2022-07-01",
           "platform": "R2R4",
           "status": "100",
           "source": "/var/export/chassis/import/.mounts/iso/R2R4/1.1.1-9159/m3/*-services/F5OS*.img",
           "version": "1.1.0-7645",
           "component": "services",
           "port": "2001",   <<<-------------------------Because this is "2001"
           "size": 2608562688,
           "error": "",
           "subcomponents": []
  4. Then modify it with a text editor and save.
    e.g.
         "source": "/var/export/chassis/import/.mounts/iso/R2R4/1.2.0-10139/m3/*-services/F5OS*.img",
         "version": "1.2.0-10139",
         "component": "services",
         "port": "2002",
  5. Run following command in order
    systemctl restart sw-mgmt
    mount | grep <new_port_value>
    systemctl restart platform-services-deployment.service

    e.g. if you changed value like step 4's example
    systemctl restart sw-mgmt
    mount | grep 2002
    systemctl restart platform-services-deployment.service
    wait till last command is completed. (take a couple of minutes)
     
  6. install v1.2.0. From CLI, you can run below command in order
    su admin
    # config
    (config)# system image set-version iso-version 1.2.0-10139 proceed yes
     
  7. It will reboot automatically, wait till it is up. Once it is accessible, log in to CLI as admin and run below command to see installation is succeed
    show system image

    VERSION OS   STATUS  DATE        USE
