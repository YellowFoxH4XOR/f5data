Description

LACP trunk may go down and services stop working

  • In /var/log/ltm following logs from lacpd daemon observed
    01160010:6: Link 2.3 removed from aggregation
01160011:6: Link 2.3 Actor Out of Sync
01160012:6: Link 2.3 Partner Out of Sync
  • No traffic is passing via LACP trunk
  • Packet capture made on the affected BIG-IP shows no LACPDU frames received from the peer, whereas LACP peer has LACPDU  frames received from the BIG-IP.
  • The interface between the HSBe2 and switch experience a high number of pause frames, which can be observed on the HSBe2 chip interface stats hgm_tx_pause_cnt value.
    tmctl  -i -f /var/tmstat/blade/tmm0 tmm/hsbe2_internal_lbb_hgm -s name,hgm_tx_pause_cnt,hgm_rx_pause_cnt
name               hgm_tx_pause_cnt hgm_rx_pause_cnt
------------------ ---------------- ----------------
hsbe2_lbb1_core[0]       1081929830                0
hsbe2_lbb0_core[0]                0                0

Environment

  • Platform with HSBe2 chip is in use. The following BIG-IP platforms are equipped with the HSBe2 chip.
    BIG-IP 5000 series (C109)
    BIG-IP 7000 series (D110)
    BIG-IP 10000 series (D113)
    BIG-IP 12000 series (D111)
    BIG-IP i5600, i5800 (C119)
    BIG-IP i7600, i7800 (C118)
    BIG-IP i10600, i10800 (C116)
    VIPRION B4300 series blade (A108, A110)
    VIPRION B2250 blade (A112)
    VIPRION B2100/2150 blade (A109, A113)
    VIPRION B4450N blade
  • LACP trunk is configured

Cause

The issue is caused by a bug ID819281: HSB and switch interface pause frames

Recommended Actions

The fix for this issue was added to HSBe2 firmware images for BIG-IP v14.1.x. This includes the B4450N and iSeries platforms.
As a workaround reboot the system
