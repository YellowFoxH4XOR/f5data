Topic

Auto Last Hop is a setting that allows the BIG-IP system to track the source MAC address of incoming connections and return traffic from pools to the source MAC address, regardless of the routing table.

Description

When enabled, Auto Last Hop allows the BIG-IP system to send return traffic from pools to the MAC address that transmitted the request, even if the routing table points to a different network or interface. As a result, the BIG-IP system can send return traffic to clients even when there is no matching route. For example, if the BIG-IP system does not have a default route configured and the client is located on a remote network. Additionally, Auto Last Hop is useful when the BIG-IP system is load balancing transparent devices that do not modify the source IP address of the packet. Without the last hop option enabled, the BIG-IP system can return connections to a different transparent node, resulting in asymmetric routing.

You can configure the Auto Last Hop setting globally and on an object level. The objects that have the Auto Last Hop setting are Virtual Server, NAT, SNAT, VLAN group, VLAN, and Tunnel. 

The setting of Auto Last Hop on each object is defined in the following table.

Behavior of Auto Last Hop configured across multiple network objects

When you configure Auto Last Hop with a value of Default at the Tunnel/VLAN group/VLAN//SNAT/NAT/virtual server object, it inherits the Global setting. When you configure Auto Last Hop with a value other than Default at the Tunnel/VLAN group/VLAN/SNAT/NAT/Virtual Server object, its setting takes precedence over the Global setting.

The following examples illustrate Auto Last Hop configurable at different object levels, and how it takes precedence. The SNAT/NAT/virtual server objects are configured to reference the same VLAN object:

Example 1
Global Auto Last Hop setting: Enabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Default
Virtual Server Auto Last Hop setting: Default
SNAT/NAT Auto Last Hop setting: Default

In this example, Auto Last Hop is enabled on all objects.

Example 2
Global Auto Last Hop setting: Disabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Default
Virtual Server Auto Last Hop setting: Default
SNAT/NAT Auto Last Hop setting: Default

In this example, Auto Last Hop is disabled on all objects.

Example 3
Global Auto Last Hop setting: Disabled
Tunnel Auto Last Hop setting: Disabled
VLAN Auto Last Hop setting: Disabled
Virtual Server Auto Last Hop setting: Enabled
SNAT/NAT Auto Last Hop setting: Disabled

In this example, Auto Last Hop is enabled only on the virtual server.

Example 4
Global Auto Last Hop setting: Enabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Disabled
Virtual Server Auto Last Hop setting: Default
SNAT/NAT Auto Last Hop setting: Default

In this example, Auto Last Hop is disabled on the specific VLAN object as well as on the virtual server and SNAT/NAT objects that reference that VLAN object.

Example 5
Global Auto Last Hop setting: Enabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Disabled
Virtual Server Auto Last Hop setting: Enabled
SNAT/NAT Auto Last Hop setting: Enabled

In this example, Auto Last Hop is disabled on the specific VLAN object, but enabled on the virtual server and SNAT/NAT objects that reference that VLAN object.

Example 6
Global Auto Last Hop setting: Enabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Default
Virtual Server Auto Last Hop setting: Default
SNAT/NAT Auto Last Hop setting: Disabled

In this example, Auto Last Hop is enabled on the tunnel, VLAN, and virtual server objects, but disabled on the SNAT/NAT object.

Example 7
Global Auto Last Hop setting: Enabled
Tunnel Auto Last Hop setting: Default
VLAN Auto Last Hop setting: Default
Virtual Server Auto Last Hop setting: Disabled
SNAT/NAT Auto Last Hop setting: Default

In this example, Auto Last Hop is enabled on the tunnel, VLAN, and SNAT object, but disabled on the virtual server object.

Tunnel specific requirement of Auto Last Hop

Tunnels like DS-Lite require remote address setting to be Any, and you cannot configure a route over a tunnel interface since the remote IP address terminating the tunnel is not known. In such case, tunnel Auto Last Hop needs to be enabled for returning the traffic over the tunnel. For P2P tunnels, you can configure a route directly through a tunnel endpoint or tunnel interface, and you can disable the tunnel Auto Last Hop .

Access Auto Last Hop settings using the Configuration utility

  • Global Auto Last Hop
  • Tunnel Auto Last Hop
  • VLAN group Auto Last Hop
  • VLAN Auto Last Hop
  • Virtual Server Auto Last Hop
  • SNAT Auto Last Hop
  • NAT Auto Last Hop

Global Auto Last Hop

  1. Go to System > Configuration > Local Traffic > General.
  2. To enable Auto Last Hop, select the check box under Properties.

    Note: To disable Auto Last Hop, clear the check box.

  3. Select Update.

Tunnel Auto Last Hop

  1. Go to Network > Tunnels > Tunnel List.
  2. Select on the Name of the tunnel.
  3. For Auto-Last Hop, select Disabled or Enabled.
  4. Select Update.

VLAN group Auto Last Hop

  1. Go to Network > VLANs > VLAN Groups > VLAN Groups List.
  2. Select the Name of the VLAN group.
  3. For Auto Last Hop, select Disabled or Enabled.
  4. Select Update.

VLAN Auto Last Hop

  1. Go to Network > VLANs > VLAN List.
  2. Select the Name of the VLAN.
  3. For Auto Last Hop, select Disabled or Enabled.
  4. Select Update.

Virtual server Auto Last Hop setting

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.
  2. Select the Name of the virtual server.
  3. If needed, select Advanced in the Configuration drop-down menu.
  4. For Auto Last Hop, select Disabled or Enabled.
  5. Select Update.

SNAT Auto Last Hop setting

  1. Go to Local Traffic > Address Translation > SNAT List.
  2. Select the Name of the SNAT.
  3. For Auto Last Hop, select Default, Disabled or Enabled.
  4. Select Finished.

NAT Auto Last Hop

  1. Go to Local Traffic > Address Translation > NAT List.
  2. Select the Name of the NAT.
  3. For Auto Last Hop select Default, Disabled or Enabled.
  4. Select Finished.

Recommendations

For most network configurations, Auto Last Hop is enabled by default. F5 strongly recommends that you leave Auto Last Hop enabled unless you have a specific reason for disabling it.

When configuring in an environment where you may be required to disable Auto Last Hop, you should consider the following factors:

  • If the last hop is a set of redundant routers or firewalls that do not use a shared MAC address, you can configure a last hop pool for the virtual server instead of disabling Auto Last Hop. For more information, refer to K2211: Using last hop pools to correctly return traffic to upstream redundant devices.
  • For BIG-IP system compatibility with VRRP and HSRP, refer to K9487: BIG-IP support for neighboring VRRP/HSRP routers.
