Known Issue

The BIG-IP APM aced process may continually restart if the parent process is unable to start

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured to authenticate using a SecurID AAA server.
  • The aced process exits unexpectedly while the BIG-IP APM system is actively processing traffic.
  • A child aced process erroneously starts listening on server port 60000, which prevents the parent process from binding properly upon restart.

Impact

The aced process is unable to start properly and users are unable to authenticate using RSA SecurID.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to authenticate to the BIG-IP APM system using SecureID.
  • An aced core file is generated to the /shared/core directory.
  • The BIG-IP APM console repeats messages similar to the following example:

    emerg logger: Re-starting aced

  • Messages appear in the /var/log/apm file similar to the following example:

    err aced[30823]: 01490000:3: Main: exception: Could not bind to port, function: bind, error: Address already in use. exiting main...
