K000160128: Resolver Timeout Preventing DNS Failover in NGINX Plus

Type
Support Solution
Published
2026-02-25
Updated
2026-02-25
Applies to
  • NGINX Products
  • NGINX Plus: R33, R34, R35, R36, R32
Source
https://my.f5.com/manage/s/article/K000160128

Description

NGINX DNS failover configuration with multiple resolvers but doesn't allow failover to occur when the first resolver is unavailable. It returns "502 Bad Gateway" status error as the result. 

 

Environment

NGINX Plus

 

Cause

NGINX contains an internal, hard-coded resend timeout of 5 seconds before attempting the next DNS server in a configured resolver list. This timeout setting is not configurable.

When resolver_timeout is set to 5 seconds or less, the configured timeout expires before NGINX's internal mechanism can initiate failover to the secondary DNS server. This prevents the secondary resolver from being queried, resulting in resolution failure and 502 Bad Gateway errors.

 

Answer/Recommended Actions

Configure the resolver_timeout directive to a value greater than 5 seconds to ensure proper DNS failover functionality.

Example: 

 resolver_timeout 6s;

Important notes:

  • The 5-second internal resend timeout is not configurable.
  • resolver_timeout must be greater than 5 seconds (minimum 6 seconds) for failover to function.
  • DNS failover occurs approximately 5 seconds after the first resolver fails to respond.
  • Setting resolver_timeout to 5 seconds or less will prevent failover from occurring.

 

Additional Information

  • Resolver timeout documentation: https://nginx.org/en/docs/http/ngx_http_core_module.html#resolver_timeout
