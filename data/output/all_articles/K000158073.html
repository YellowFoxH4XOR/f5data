K000158073: BIG-IP LTM HTTP Health Monitor Marks Pool Members as DOWN with custom Send String configured

Type
Support Solution
Published
2025-12-26
Updated
2026-05-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000158073

Description

A custom HTTP health monitor on BIG-IP LTM marks pool members as DOWN with no responses received, even though the backend server is available and responds to direct HTTP requests. Monitor logs show rcv_cnt=0 (no response received) for the affected monitor profile. 

Below is an example of pool member monitor logs illustrating this behavior:

Environment

  • Product: BIG-IP LTM version 17.1.3
  • Custom HTTP health monitor configured for a pool member on a non-default route domain
  • Monitor send string: GET HTTP/1.1\r Host: <hostname>\r \r
  • Monitor receive string: 200
  • Path field in the new HTTP monitor profile is empty
  • A previously working monitor profile specifies a valid path (e.g., /kiosk)

Cause

Leaving the Path field empty in the HTTP health monitor configuration causes the monitor to send an invalid HTTP request, resulting in no responses from the backend server and pool members being marked as DOWN. A valid HTTP/1.1 GET request requires at least a / as the request URI. Please refer to below on example of non-working Sent String.

GET HTTP/1.1\r\nHost: host.example.com\r\nConnection: Close\r\n\r\n

Recommended Actions

  1. Navigate to Local Traffic > Monitors and open the affected HTTP health monitor profile.
  2. Enter / in the Path field if no specific resource is required, or specify the appropriate URI path, below are two example of working Sent String. 
    GET / HTTP/1.1\r\nHost: host.example.com\r\nConnection: Close\r\n\r\n
GET /index.html HTTP/1.1\r\nHost: host.example.com\r\nConnection: Close\r\n\r\n
  3. Save the monitor configuration.
  4. Enable monitor logging on the pool member and verify that rcv_cnt value increases and the pool member status changes to UP.
  5. Disable monitor logging after confirming the issue is resolved to reduce log volume.

Additional Information

  • An empty Path field is not equivalent to / and prevents the BIG-IP system from constructing a valid HTTP/1.1 request.
  • Enabling monitor logging and reviewing rcv_cnt vs snd_cnt values is useful for troubleshooting health monitor issues.
  • Monitor logging should be disabled after troubleshooting to avoid unnecessary log overhead.
