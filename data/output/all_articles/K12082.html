K12082: Partial GET requests for large files may increase the IOWAIT time

Topic

Clients may request certain media file types, such as MP3 files in chunks, by sending partial GET requests. A partial GET request includes the Range HTTP header, which specifies the range of bytes requested.

For example:

GET /NYNY.mp3 HTTP/1.1
Host: www.example.com
Range: bytes=0-255

The origin web server (OWS) responds to a partial GET request with the requested bytes and an HTTP 206 Partial Content response code. If the total file size of the object is larger than the value configured for the imcMaxItemSize parameter, the object will not be cached to in-memory cache (IMC). However, if the total file size is smaller than the value configured for the maxResponseDataSize parameter, BIG-IP WebAccelerator caches the full object to disk on the first request.

Note: The imcMaxItemSize and maxResponseDataSize parameters are defined in the BIG-IP WebAccelerator configuration file (pvsystem.conf). The default value for imcMaxItemSize is 4 kilobytes and the default value for maxResponseDataSize is 64 megabytes.

Each time the BIG-IP WebAccelerator receives a partial GET request for a file larger than the imcMaxItemSize parameter, the full object must be reprocessed as it is loaded from the disk cache, increasing the system IOWAIT time. For larger media files, there may be numerous partial GET requests and HTTP 206 Partial Content responses exchanged before the client has fully retrieved the object. On a busy BIG-IP WebAccelerator system serving numerous media files, this increase in IOWAIT time may lead to a performance bottleneck.

To work around this behavior, you can configure an HTTP class to bypass the BIG-IP WebAccelerator for specific content types. Alternately, you can configure an iRule to bypass the BIG-IP WebAccelerator for specific content types.

Note: Bypassing the BIG-IP WebAccelerator for specific content using an additional HTTP class profile is more efficient than using an iRule. However, using an iRule may be more flexible.
