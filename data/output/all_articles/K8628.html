K8628: Uploading files using Portal Access Windows Files fails if the directory path contains a plus (+) character

Known Issue

This is the result of a known issue. If a user attempts to upload a file through a Portal Access Windows Files favorite, and the remote directory path contains a plus ( + ) character, the FirePass controller replaces the plus character with a space character. As a result, the upload fails.

For example, if a user attempts to upload the somefile.txt file to the \\fileserver1\public\Q+A\test directory through a Portal Access Windows Files favorite, the FirePass controller instead attempts to upload the file to the \\fileserver1\public\Q A\test directory. If the \\fileserver1\public\Q A\test directory does not exist, the upload fails and the FirePass controller reports an error message that appears similar to the following example:

Couldn't create somefile.txt in \\fileserver1\public\Q A\test !

F5 Product Development tracked this issue as CR95797 and it was fixed in FirePass 6.0.3. For information about upgrading, refer to the FirePass release notes.

Additionally, Cumulative Hotfix HF-601-11 has been issued for FirePass 6.0.1 and Cumulative Hotfix HF-602-4 has been issued for FirePass 6.0.2. You may download these hotfixes or later versions of the Cumulative Hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by removing the plus character from the directory name on the back-end file server.
