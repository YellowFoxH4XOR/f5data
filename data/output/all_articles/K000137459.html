Description

Some event logs are not sent to the remote syslog server when queue for remote logging is full.

Environment

  • BIG-IP ASM
  • MySQL
  • ASM event logging
  • Remote logging

Cause

Queue for remote logging is full.

The following logs can be seen on  /var/log/ts/bd.log:

 /var/log/ts/bd.log

IO_PLUGIN|DEBUG |Oct 03 22:37:35.240|12755|io_plugin.c:4154|generate new support_id 7134386629405xxxxx
...
BD_MISC|INFO |Oct 03 22:37:35.246|12755|proxy_log.c:1786|response_log_omit_reason(5) resp len(0) resp()
BD_MISC|DEBUG |Oct 03 22:37:35.246|12755|proxy_log.c:0742|put_wake_queue failed
BD_MISC|DEBUG |Oct 03 22:37:35.246|12755|proxy_log.c:2567|free_remote_logger_inputs
BD_PB|DEBUG |Oct 03 22:37:35.246|12755|bd_pb_msg.cpp:4601|destroy_main_msg 0x7fadcd0ee7c0
IO_PLUGIN|DEBUG |Oct 03 22:37:35.247|12755|io_plugin.c:2394|TMEVT_SHUTDOWN_PEER

Recommended Actions

Increase prx_batch_queue_len value and restart asm:

# /usr/share/ts/bin/add_del_internal add prx_batch_queue_len 1024
# bigstart restart asm

NOTE: Restarting the BIG-IP ASM service disables traffic processing for the entire device while it is marked Offline. If the unit is part of a high-availability (HA) cluster, this behavior causes a failover event.
