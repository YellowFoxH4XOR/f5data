Description

When configuring BIG-IP LTM systems, TMM (Traffic Management Microkernel) logs are not included by default in standard syslog forwarding. To ensure comprehensive logging, both standard syslog and TMM logs may need to be forwarded to one or more remote syslog servers using TCP or UDP.

Environment

  • BIG-IP LTM
  • syslog-ng

Cause

The default BIG-IP syslog-ng configuration does not automatically forward TMM logs to remote destinations. Additional configuration is required to pipe each TMM log source and direct it explicitly to the desired remote servers.

Recommended Actions

To enable forwarding of both standard syslog and all available TMM logs to multiple remote syslog servers:

1. Modify the syslog-ng configuration via tmsh: 

Copy and paste the following commands to the CLI (Bash) to achieve the objective.

Change the following information and match it with your environment:

  • Number of TMMs
  • <FQDN or IP Address of the Syslog Server1>
  • <FQDN or IP Address of the Syslog Server2>
  • <syslog_server_name1>
  • <syslog_server_name2> 
  • (TCP/UDP_PORT)

 

tmsh modify sys syslog include "
source s_syslog_pipe { pipe(\"/var/run/syslog.pipe\"); };
source s_tmm { pipe(\"/var/run/tmm.pipe\"); };
source s_tmm1 { pipe(\"/var/run/tmm1.pipe\"); };
source s_tmm2 { pipe(\"/var/run/tmm2.pipe\"); };
source s_tmm3 { pipe(\"/var/run/tmm3.pipe\"); };

destination <syslog_server_name1> { tcp/udp(\"<FQDN or IP Address of the Syslog Server1>\" port(TCP/UDP_PORT)); };
destination <syslog_server_name2> { tcp/udp(\"<FQDN or IP Address of the Syslog Server2>\" port(TCP/UDP_PORT)); };

log { source(s_syslog_pipe); destination(<syslog_server_name1>); destination(<syslog_server_name2>); };
log { source(s_tmm); destination(<syslog_server_name1>); destination(<syslog_server_name2>); };
log { source(s_tmm1); destination(<syslog_server_name1>); destination(<syslog_server_name2>); };
log { source(s_tmm2); destination(<syslog_server_name1>); destination(<syslog_server_name2>); };
log { source(s_tmm3); destination(<syslog_server_name1>); destination(<syslog_server_name2>); };"

 

2. Save the updated configuration:

tmsh save sys config

3. Restart the syslog-ng service:

bigstart restart syslog-ng

Additional Information

1.-Always verify the number of active TMM processes, so you include all necessary sources. You can use the following command:

tmsh show /sys tmm-traffic

2. Test any changes in a non-production environment before deploying in production.

3. Incorrect syntax or misconfiguration can disrupt logging; review changes carefully before applying.
