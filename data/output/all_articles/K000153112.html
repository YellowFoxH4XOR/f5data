Description

How to re-sync SCIM Users After an Email Domain Change?

Environment

  • F5® Distributed Cloud Console
  • SCIM

Cause

None

Answer/Recommended Actions 

Currently, changing user email addresses directly through SCIM is not supported because the email ID is used as a primary identifier for users and related objects. To reflect the new email domain, the customer needs to disable and re-enable SCIM integration.

Steps to perform:

  1. Stop provisioning in Azure.
  2. Disable SCIM in XC.
  3. Re-enable SCIM in XC (this will generate a new SCIM token).
  4. Update the new SCIM token in the Azure configuration.
  5. Restart provisioning in Azure.

⚠️ Important Note: These steps will delete the existing SCIM-provisioned users in XC and recreate them with the updated email IDs. As a result, the new users will not be associated with the old accounts, which can impact items such as API tokens, support tickets  and other resources tied to the old email accounts.

Additional Information

  • Changing a user’s email address while SCIM provisioning is enabled is not supported and can lead to widespread provisioning and access issues.
  • SCIM synchronization runs on an hourly interval; after disabling SCIM, it is recommended to wait at least one hour before re‑enabling it to ensure the previous sync cycle has fully stopped.
  • Any required email address changes must be performed while SCIM is disabled to avoid breaking user provisioning and account associations.
