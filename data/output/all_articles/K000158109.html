How to Investigate Failover Events on BIG-IP DNS (GTM) When Log Data Is Unavailable


1. Description

This article provides guidance for troubleshooting failover events on BIG-IP DNS (GTM) devices when the relevant log data is missing due to log rotation or insufficient retention. Failover may occur unexpectedly, and without access to logs from the time of the event, root cause analysis is limited. Typical triggers include network issues, resource exhaustion, configuration changes, HA group/gateway/VLAN fail-safe mechanisms, or manual actions. The sod (switch-over daemon) process manages HA status and initiates failover.


2. Environment

Product: BIG-IP DNS (GTM), version 17.1.3

Platform: F5-BIG-BT-I7800, C118

High Availability sync group with network failover enabled

Default log retention (~30 days)

No remote syslog or external log archiving configured

Investigation performed after logs had rotated out

3. Cause

Unknown at time of publication.


4. Recommended Actions

Increase local log retention settings on BIG-IP devices.

Configure remote syslog to archive logs externally for longer-term storage.

If a failover occurs:

Immediately collect a qkview and export relevant system logs before they are rotated.

Review system logs such as /var/log/ltm and /var/log/messages for entries related to sod, HA group, fail-safe, or network failover.

Use CLI commands for targeted searches:

grep -i sod /var/log/ltm

grep -Ei 'sod|failover' /var/log/ltm*

For specific timestamps: grep "Oct 21 00" /var/log/ltm* | grep sod

Enable sod debug logging if deeper analysis is required (see K55591231).

Regularly monitor iQuery mesh health and network failover configuration.

For future events, promptly collect diagnostic data after any failover.

5. Additional Information

Failovers can result from various factors including network instability, resource exhaustion, configuration changes, or manual intervention. The sod daemon monitors HA status and triggers failovers as needed; reviewing its activity in system logs is essential for diagnosis but only possible if logs are retained or archived externally.
