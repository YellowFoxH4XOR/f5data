Topic

Note: This behavior only occurs when systems are in the same synchronization group and you upgrade the group to BIG-IP GTM 10.1.0 and later. This behavior does not pertain to new, BIG-IP GTM 10.1.0 and later installations.

After you upgrade an existing BIG-IP GTM synchronization group to BIG-IP GTM 10.1.0 or later, the system does not synchronize the master key to all members within the synchronization group. The key-signing key and the zone-signing key do not load. As a result, Domain Name System Security Extensions (DNSSEC) configurations do not load on synchronization group members that do not contain the same master key as the unit for which you implemented DNSSEC.

The system may log the following error message to the /var/log/gtm file:

  • 01010231:4: DNSSEC: Did not add RRSIGs to response

In BIG-IP GTM 10.1.0 and later, the Secure Vault feature protects passphrases for Secure Sockets Layer (SSL) keys. Secure Vault uses an internal mechanism within the BIG-IP system to automatically create a master key for the purpose of encrypting SSL certificate passphrases. Within BIG-IP GTM 10.1.0, the master key encrypts the key-signing key and zone-signing key used by DNSSEC. The system writes the key-signing key and zone-signing key to the /config/wideip.conf file.

Recommended action

You can manually copy the master key by completing one of the following two procedures:

  • Running the gtm_add command on BIG-IP GTM systems that are not answering DNSSEC requests
  • Using the f5mku utility to align the master key on each BIG-IP GTM system

Running the gtm_add command on BIG-IP GTM systems that are not answering DNSSEC requests

  1. Determine which BIG-IP GTM is correctly handling DNSSEC requests or choose the BIG-IP GTM for which you implemented DNSSEC. This system is the master unit from which gtm_add pulls its configuration.
  2. Run the gtm_add script on all other members of the synchronization group, specifying the IP address of the BIG-IP GTM system that you chose in step 1.
  3. After all systems within the synchronization group have the same master key, test to ensure that they correctly answer DNSSEC requests.

Using the f5mku utility to align the Master Key on each BIG-IP GTM system

  1. Determine which BIG-IP GTM system is correctly handling DNSSEC requests or choose the BIG-IP GTM for which you implemented DNSSEC. You use this system master key to re-key the other BIG-IP GTM systems.

    Important: Do not alter the master key that you obtain from the known good system; you use this key to re-key all other members within the synchronization group. Also, altering the master key prevents that system from correctly answering and signing DNSEC requests.

  2. Log in to the command line of the BIG-IP GTM from step 1.
  3. Type the following command:

    f5mku -K

    The output appears similar to the following example:

    9m7LJ03LPTM5cOcSdAgs9Q==

  4. Copy the output. The output is the master key that you use to re-key the other systems within the synchronization group.
  5. Log in to the command line of a BIG-IP GTM system that needs the master key.
  6. Type the following command using the output from step 3:

    f5mku -r <key_value>

    Your command is similar to the following example:

    f5mku -r 9m7LJ03LPTM5cOcSdAgs9Q==

    Repeat for each system within the synchronization group that needs the master key.

  7. Verify that the master key is the same on all BIG-IP GTM synchronization group members by typing the following command:

    f5mku -K

  8. Save the configuration changes:

    tmsh save sys config

  9. Reboot any systems on which you re-keyed their master.
