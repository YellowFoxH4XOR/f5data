Topic

The BIG-IP system offloads Layer 4 (TCP and UDP) checksum calculations to the switch hardware by default. You can control this behavior by setting the value of the TM.TcpUdpTxChecksum database variable. However, if you use the tcpdump utility on the BIG-IP system and specify a Virtual Local Area Network (VLAN) name as the interface from which to capture, Layer 4 (L4) hardware checksum offloading is temporarily disabled, and the checksum is instead calculated in software by the Traffic Management Microkernel (TMM).

When the BIG-IP system performs the checksum calculation in software, the calculation takes place in TMM before the switch hardware has processed the frame. When the BIG-IP system performs the checksum calculation in hardware, the calculation takes place in the switch hardware after the switch hardware has processed the frame. As a result, if the switch hardware is responsible for corrupting frames, the corruption will only be detected when the BIG-IP system performs the checksum calculation in software prior to processing by the switch hardware.

For example, testing may reveal that the upstream switch is receiving corrupt frames, but not discarding them. When you run the tcpdump utility on the BIG-IP system to capture all frames on the offending VLAN, the upstream switch is able to detect the corrupt frames and discard them, alleviating the issue. Intentionally disabling hardware checksum offloading using the database variable produces the same result. Since upstream switch detects corruption only when the BIG-IP system performs the checksum calculation in software, the switch hardware is confirmed as the cause of the corruption.

To change the L4 checksum calculation database variable, use the following syntax:

Note: The possible database values are as follows: Software-only or Hardware-enabled (default).

  • BIG-IP 11.x

    tmsh modify sys db tm.tcpudptxchecksum value <value>

  • BIG-IP 9.x through 10.x

    bigpipe db TM.TcpUdpTxChecksum <value>
