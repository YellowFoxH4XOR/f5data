Known Issue

Configuration may fail to load when you upgrade from BIG-IP 10.x versions.

This issue occurs when all of the following conditions are met:

  • You upgrade from a BIG-IP 10.x version to a version listed in the Applies To box, in the upper-right corner of this article.
  • The BIG-IP 10.x configuration contains a custom user-created monitor (child_monitor) that inherits from another custom user-created monitor (parent_monitor).
  • The (parent_monitor) monitor does not have a destination attribute configured.
  • The (child_monitor) monitor does have a destination attribute configured.
  • Following the upgrade, the system writes the configuration file with the (child_monitor) monitor configured before the (parent_monitor) monitor.

Impact

The configuration fails to load following an upgrade.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • After an upgrade, the configuration fails to load with the following error message:

    01070734:3: Configuration error: Invalid primary key on monitor_param object () - not a full path 2.

Workaround

To work around this issue, in the BIG-IP 10.x configuration, ensure that all custom user-created monitors are configured to inherit properties from a system-supplied base monitor.

If you have already performed the upgrade, you can modify the BIG-IP 11.x configuration file in one or both of the following ways:

  • Re-order the monitors within the configuration file so that the (parent_monitor) monitor appears in the configuration file before the (child_monitor) monitor.
  • Add a destination attribute (for example, destination *:*) to the (parent_monitor) monitor.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment.
