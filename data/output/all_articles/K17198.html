Known Issue

The BIG-IP system sends IPv6 neighbor advertisements for all MAC masquerade addresses on all Virtual Local Area Networks (VLAN).

This issue occurs when the following condition is met:

  • You have configured MAC masquerading for two or more traffic groups in your BIG-IP configuration.

The Traffic Management Microkernel (TMM) creates a new link-local address for each masquerading MAC address. The same link-local address may be used on all interfaces. Therefore, the system may use the same MAC on different VLANs.

In the following example configuration, you may expect that traffic-group-1 and the associated MAC address are bound only to VLAN Internal. However, you can create another self IP address, assign it to different VLANs or route domains, and include them as part of the same traffic group:

net self 10.10.10.10%1 {
    address 10.10.10.10%1/23
    allow-service {
        default
    }
    floating enabled
    traffic-group traffic-group-1
    unit 1
    vlan Internal
}

Impact

Although this is intended functionality, this behavior may not be expected. Although switches typically build up forwarding tables per VLAN, some switches may not perform correctly, which results in failure to forward packets as expected. This behavior may impact other traffic, including IPv4.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • If you set up two or more traffic groups on a device and use a MAC masquerade address on each, you can use the tcpdump utility to confirm that all MAC masquerade addresses are visible on all VLANs. For more information about the tcpdump utility, refer to K411: Overview of packet tracing with the tcpdump utility.

Workaround

To work around this issue, you can set the BIG-IP database variable tm.macmasqaddr_per_vlan to true. This ensures that a single source MAC is associated with a single VLAN ID, and is guaranteed to be unique per VLAN. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Set tm.macmasqaddr_per_vlan to true by typing the following command:

    modify /sys db tm.macmasqaddr_per_vlan value true

  3. Confirm the change by typing the following command:

    list /sys db tm.macmasqaddr_per_vlan

    The command output should appear similar to the following example:

    sys db tm.macmasqaddr_per_vlan {
        value "true"
    }
