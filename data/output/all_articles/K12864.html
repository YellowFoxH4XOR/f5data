Issue

Error Message

apd[<pid>]: 0149013e:3: <sessionid>: Allow agent: Logon denied due to validation error, Error Code: 3000 (No Webtop)

In this error message, note the following:

  • <pid> is the process ID
  • <sessionid> is the BIG-IP APM user session ID

For example:

err apd[8952]: 0149013e:3: 0d976ab3: Allow agent: Logon denied due to validation error, Error Code: 3000 (No Webtop)

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file

Description

This message occurs when one of the following conditions are met:

11.x

  • An Access Policy Portal Access or Network Access Advanced Resource Assign action has no associated webtop.
  • An ACL Assign action is configured after a Portal Access or Network Access Advanced Resource Assign action in the visual policy editor processing chain.

10.x

  • An Access Policy Web Application or Network Access Resource Assign action has no associated webtop.

In addition to the initial error message, users receive the following error message:

Your session could not be established.

The session reference number: <sessionid>

Configuration error. Webtop configuration is required. Webtop configuration is not necessary for App Tunnel Control, or a Portal Access connection with minimal patching configured. Please contact your system administrator for assistance.

Impact

Users are unable to log in to the BIG-IP APM system.

Recommended Actions

To prevent this error message, you can perform the following procedures:

  • Configure an appropriate webtop with the Advanced Resource Assign action(s) associated with the error in the affected Access Policies (10.x - 11.x).
  • Remove any access control list (ACL) Assign actions appearing after an Advanced Resource Assign action in the visual policy editor (11.x).

Configuring an appropriate webtop with the Advanced Resource Assign action (10.x - 11.x)

Note: Advanced Resource Assign is referred to as Resource Assign in 10.x.

  1. Log in to the BIG-IP Configuration utility.
  2. Expand Access Policy.
  3. Click Access Profiles.
  4. Click Edit next to the name of the Access Policy you want to edit.

    The visual policy editor opens.

  5. Click the Advanced Resource Assign action box.

    The Advanced Resource Assignment window opens. The assigned resources are listed in the Properties tab.

    Note: There may be multiple Advanced Resource Assign actions in an Access Policy.

  6. Determine which assignment is failing by reviewing the resource assignment list, and then locate the entry that does not have an associated webtop.
  7. Click Add/Delete in the affected Advanced Resource Assignment (skip this step for 10.x)
  8. Click Webtop.

    The Webtop options window opens.

  9. If the option is set to none, click the desired webtop configuration.
  10. Click Update.

    The Webtop option window closes.

  11. Click Save.
  12. To apply the changes, click Apply Access Policy in the top left corner of the visual policy editor.

Removing ACL Assign actions (11.x)

  1. Log in to the BIG-IP Configuration utility.
  2. Expand Access Policy.
  3. Click Access Profiles.
  4. Click Edit next to the name of the Access Policy you want to edit.

    The visual policy editor opens.

  5. Review the configuration of any ACL Assign actions appearing after the last Webtop Advanced Resource Assign action so they can be recreated after deleting.
  6. Click the x on the ACL Assign action box and confirm to delete.
  7. Recreate the ACL Assign action to appear either before the Webtop Advanced Resource Assign or within an Advanced Resource Assign action and click Save.
  8. To apply the changes, click Apply Access Policy in the top left corner of the visual policy editor.
