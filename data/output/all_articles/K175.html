Topic

During the ongoing maintenance of your F5 device, you may need to transfer a file to or from the device. For example, you may want to transfer a product ISO to the device for installation or a PCAP file from the device to your workstation for analysis. The following four options are available for transferring files to or from F5 devices:

  • Secure Copy
  • Secure File Transfer Protocol 
  • File Transfer Protocol from F5 device to remote FTP server
  • HTTPS to transfer UCS files using the Configuration utility
  • Integrity check of the copy

To watch a video demo of this procedure, go to Transferring files to or from an F5 system.

Secure Copy

Secure Copy (SCP) protocol is the preferred means of transferring files to or from an F5 device. SCP securely transfers files between hosts using the SSH protocol for authentication and encryption. Unlike File Transfer Protocol (FTP), SCP provides an option to preserve the original date stamp on the file during file transfers. You can use SCP to transfer files between an F5 device and a remote host using either command line SCP or Windows-based SCP:

Note: To use SCP, the user must be assigned the Administrator role and have access to the Advanced Shell (bash). For more information, refer to K82348433: Advanced shell access for non-administrator users may be restricted after an upgrade, K22885182: SFTP Access to the BIG-IP System is Now Disabled for Users with tmsh-shell Access and K03585731: F5 secure shell vulnerability CVE-2020-5873.
  • Using command line SCP to transfer files
  • Using Windows-based SCP to transfer files

Using command line SCP to transfer files

You can transfer a file between an F5 device and a remote host using command line SCP. To do so, perform the following procedure:

  1. Log in to the F5 device/remote host command line.
  2. Run SCP by choosing one of the following options:

    To upload a local file to a remote host use the following syntax:

    • scp -p <local_path_to_file> <username>@<server IP/hostname>:<remote_directory>

    To download a remote file to the local host use the following syntax:

    • scp -p <username>@<server IP/hostname>:<remote_path_to_file> <local_directory>

    Note:-p preserves the modification times, access times, and modes from the original file.

    For example:

    • upload: scp -p /user1/myfile.bin root@10.90.101.50:/var/tmp/
    • download: scp -p root@10.90.101.50:/var/tmp/myfile.bin /user1/
  3. Follow the prompts to accept the key of the remote system and supply a password.

    You should receive output that appears similar to the following example:

    The authenticity of host '10.90.101.50 (10.90.101.50)' can't be established.
    DSA key fingerprint is b5:0c:53:97:d2:72:78:ab:37:be:e4:0a:56:58:14:7d.
    Are you sure you want to continue connecting (yes/no)? yes
    Warning: Permanently added '10.90.101.50' (DSA) to the list of known hosts.
    root@10.90.101.50's password:
    myfile.bin 100% 99 0.0KB/s 00:00

    This output indicates that the file transferred successfully.

Using Windows-based SCP to transfer files

You can transfer a file between an F5 device and a Windows host using Windows-based SCP from the Windows host. You must first obtain a copy of a Windows-based SCP software that is SSH version 2 compatible, such as WinSCP, and install it on the Windows host. For instructions on installing the software, refer to your software vendor documentation. After the successful installation, you can proceed to configure the Windows-based SCP software to connect to the F5 device using the following information:

  • Hostname/IP address: <Enter the IP address of either your F5 device Management Port or self IP that is configured to accept SSH traffic on port 22>
  • Port: 22
  • Username: <Enter the F5 device user account that is configured with Advanced Shell (bash) access>
  • Password: <Enter the password for the F5 device user account>

When you have successfully established an SCP connection to the F5 device, refer to your software vendor documentation for instructions on navigation and uploading/downloading files.

Secure File Transfer Protocol

The Secure File Transfer Protocol (SFTP), also known as the SSH File Transfer Protocol, is designed to securely transfer files between networked hosts. The key difference between SFTP and SCP is that SFTP provides remote file system management functionality very similar to an FTP client, which allows the recovery of interrupted file transfers, listing the contents of the remote directory, and the deletion of files remotely. You can establish an SFTP connection to or from the F5 product. The two hosts transfer data between themselves over an encrypted connection. When performing SFTP transfers, the original file date stamp is not preserved.

Note:  To use SCP, the user must be assigned the Administrator role and have access to the Advanced Shell (bash). For more information, refer to K82348433: Advanced shell access for non-administrator users may be restricted after an upgrade , K22885182: SFTP Access to the BIG-IP System is Now Disabled for Users with tmsh-shell Access and K03585731: F5 secure shell vulnerability CVE-2020-5873

To transfer files using SFTP, perform the following procedure:

  1. Log in to the F5 device/remote host command line.
  2. Change local directories to the directory that contains the file that you want to transfer. To do so, use the following command syntax:

    cd <directory>

    For example:

    cd /var/tmp

  3. Execute SFTP by using the following command syntax:

    sftp <username>@<server>

    For example:

    sftp root@10.90.101.50

  4. Follow the password prompt to log in. You should now see the following prompt:
    sftp>
  5. From the sftp> prompt, change remote directories to the directory where you want to transfer to. To do so, use the following command syntax:

    cd <directory>

    For example:

    cd /var/tmp

  6. Transfer the file, using the following command syntax:

    put <filename>

    For example:

    put myfile.bin

  7. Exit SFTP by entering the following command:

    bye

File Transfer Protocol from F5 device to remote FTP server

You can use File Transfer Protocol (FTP) to exchange and manipulate files over a network. An FTP client connects to an FTP server to manipulate files on that server. Since the FTP server daemon is no longer included in F5 product builds for security reasons, you cannot FTP to the F5 device to transfer files. You must establish an outbound FTP connection from the F5 product to an FTP server running on the remote host. Login passwords and data are transmitted in cleartext (not encrypted) when performing FTP transfers, and the original date stamp is not preserved upon transfer.

To transfer files using FTP, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. From the F5 product, change directories to the directory that contains the file that you want to transfer. To do so, use the following command syntax:

    cd <directory>

    For example:

    cd /var/tmp

  3. Execute FTP by using the following command syntax:

    ftp <server>

    For example:

    ftp myftpserver.mydomain.com

  4. Follow the prompts to log in.
  5. Verify that you are in binary file transfer mode, by entering the following command:

    binary

  6. Transfer the file, using the following command syntax:

    put <filename>

    For example:

    put myfile.bin

  7. Exit FTP by entering the following command:

    bye

The file is transferred.

HTTPS to transfer UCS files using the Configuration utility

Note: You can also use this method for the EoL software Enterprise Manager.

Hypertext Transfer Protocol Secure (HTTPS) securely transfers files between hosts using HTTP for data transport and authentication, and the TLS protocol for encryption. The Configuration utility, which uses an HTTPS server already installed and configured to provide secure web-based administrative access, also provides the means to upload and download files to and from the system.

To download a user configuration set (UCS) archive file from the BIG-IP system to a drive attached to your workstation, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. Select the name of the archive you want to download.
  4. Select Download.

To upload a UCS archive file from a drive attached to your workstation, to the BIG-IP system, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Go to System > Archives.
  3. Select Upload.
  4. Browse and select the name of the UCS archive file you want to upload.

Integrity check of the copy

After the file has been copied, it may be important to confirm that the copy is correct (for example, did not end prematurely). This integrity check can be done by either validating the checksum or comparing the hash/fingerprints

Some file formats (usually archives) include among their fields a checksum which can be validated using a specialised utility. For example gzip, 7Zip, etc.

A more general approach, however, is using one of the popular utilities calculating over the contents of any given file a hash/fingerprints value. The calculation algorithms are designed in a manner to minimise the probability of two slightly different contents producing the same hash value. The most available [though not the most secure] hash is MD5 fingerprints

Calculating MD5 fingerprints in bash CLI of a BIG-IP or BIG-IQ

Utility md5sum is included in the distribution

$ md5sum /var/tmp/support.qkview
dda590ee7b4fb28c5403b63f7c37362b */var/tmp/support.qkview
$
