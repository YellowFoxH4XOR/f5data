Description

A lot of SSH connection / login attempts are being made.

You observe many log messages similar to the following in /var/log/secure:

alert sshd[25737]: pam_tally2(sshd:auth): Tally overflowed for user root
notice unix_chkpwd[25738]: password check failed for user (root)
notice sshd[25737]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=10.10.10.1  user=root

Note: In this example, a private IP (10.10.10.1) is given. Most likely you will see login attempts from public IPs in a production environment.

Environment

  • SSH
  • Management interface allowing access from public IP addresses
  • Or TMM self IP allowing public access and TCP port 22 connections

Cause

SSH brute force login attempts from malicious sources.

Recommended Actions

If you believe that your BIG-IP system may have been compromised, refer to your internal security policies and procedures in the first instance. You may also refer to:

  • K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system

If you are confident that the system hasn't been compromised, and you would like to prevent malicious SSH traffic, perform the following procedures:

Restrict management access

If at all possible, restrict management IP access to trusted networks - it is best practice that the management interface is not exposed to the internet.

Additionally, ensure that Port Lockdown configuration does not allow TCP port 22 connections unless necessary:

  • K17333: Overview of port lockdown behavior (12.x - 16.x)

Restrict the sshd allowed IP range

All IP addresses are permitted to establish SSH sessions by default:

[root@v15:Active:Standalone] config # tmsh list sys sshd allow
sys sshd {
    allow { ALL }
}

You can restrict SSH access to known trusted IPs, by following the procedures in:

  • K5380: Specifying allowable IP ranges for SSH access

Advanced configuration

Some advanced configuration options are available for restricting SSH access. For more information, refer to:

  • K13454: Configuring SSH public key authentication on BIG-IP systems
  • K46122561: Restricting access to the management interface using network firewall rules

Note: If you do not use exclusively public key authentication, ensure that you enforce complex passwords that are not easy to brute force.

A password policy is another option:

  • K4139: Configuring the BIG-IP system to enforce the use of strict passwords

Additional Information

There are URL/IP lookup services that can be used to verify if an IP address found in the logs is a known malicious source.

One such tool is available from BrightCloud:

  • URL/IP Lookup | Webroot BrightCloud
