Description

Getting HTTP2 compression errors on HTTP2 Virtual Server.

  • When an end client faces this error, refreshing does solve the issue
  • Closing the browser and clearing the cookies will allow them to temporarily regain access to the webpage
  • Mainly Chrome users have this issue
  • On end client side, you might see this error on the browser: ERR_HTTP2_PROTOCOL_ERROR

On a packet capture of the Virtual Server traffic, you can see this error: Error: COMPRESSION_ERROR (9), for example:

Frame 1900: 249 bytes on wire (1992 bits), 249 bytes captured (1992 bits)
Internet Protocol Version 4, Src: 10.0.0.1, Dst: 192.168.1.1
Transmission Control Protocol, Src Port: 443, Dst Port: 58518, Seq: 164372, Ack: 22497, Len: 46
Transport Layer Security
HyperText Transfer Protocol 2

        Length: 8
        Type: GOAWAY (7)
        Flags: 0x00
            0000 0000 = Unused: 0x00
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0000 = Stream Identifier: 0
        0... .... .... .... .... .... .... .... = Reserved: 0x0
        .000 0000 0000 0000 0000 0000 0000 0111 = Promised-Stream-ID: 7
        Error: COMPRESSION_ERROR (9)   → Note!
F5 Ethernet Trailer Protocol

Environment

  • Mainly using Chrome browser
  • Using HTTP2 profile

Cause

If header count is higher than the max-header-count from HTTP profile, HTTP2 stream sends GOAWAY with COMPRESSION ERROR. This issue is tracked with BUG ID below:

Bug ID 1004897: 'Decompression' is logged instead of 'Max Headers Exceeded' GoAway reason

Recommended Actions

You can workaround this issue on affected versions, by changing max-header-count in HTTP profile, here is an example to increase max-header-count to 128:

tmsh modify ltm profile http <profile_name> enforcement {max-header-count 128}

Note: Header count can be increased to 128 or 256.

Additional Information

Default max-header-count for HTTP profile is 64:

tmsh list /ltm profile http all-properties

ltm profile http /Common/http {
    accept-xff disabled
    adaptive-parsing disabled
    app-service none
    basic-auth-realm none
    defaults-from none
    description none
    encrypt-cookie-secret ***scrubbed***
    encrypt-cookies none
    enforcement {
        excess-client-headers reject
        excess-server-headers reject
        max-header-count 64    → Note!
        max-header-size 32768
        max-requests 0
