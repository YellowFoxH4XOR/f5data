Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when processing UDP traffic with a FastL4 virtual server.

This issue occurs when all of the following conditions are met:

  • A BIG-IP system is configured with a FastL4 virtual server for UDP traffic.
  • The system hardware includes an embedded Packet Velocity Acceleration (ePVA) chip.

    Note: For more information about ePVA based platforms, refer to K12837: Overview of the ePVA feature

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if configured for HA.
  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    notice sod[8810]: 01140045:5: HA reports tmm NOT ready.
  • The system logs messages to the /var/log/messages file that appear similar to the following example:

    notice logger: Started writing core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
    notice logger: Finished writing 236194271 bytes for core file: /var/core/tmm.0.bld2384.0.core.gz for PID 13897
  • The BIG-IP system generates TMM core files to the /shared/core directory, with a time stamp that correlates to the traffic interruption, similar to the following example:

    -rw-r--r-- 1 root root 226M Apr 13 15:09 tmm.0.bld2384.0.core.gz
