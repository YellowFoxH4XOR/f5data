Known Issue

BIG-IP AFM rule-matching actions may appear inconsistent when compared with the logging for ephemeral connections.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP AFM system is configured with a Global Reject-All rule.
  • A virtual server uses ephemeral connections (for example, FTP data traffic) that match the BIG-IP AFM rule with the Drop or Reject action.
  • The system is enabled with logging to a remote syslog server.

For example, when passing traffic over an FTP data channel, which is related to a control channel active on a virtual server with an FTP profile, BIG-IP AFM logs indicate that the system has triggered an inappropriate global rule.

Impact

The issue is cosmetic; the logged ephemeral connections are not rejected by the BIG-IP AFM system and the connections remain operational.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP AFM reject rule logs indicate that the system has dropped or rejected the affected ephemeral connections; however, the physical connections are not affected.
  • Affected ephemeral connections remain operational.
