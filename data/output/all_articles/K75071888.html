Description

After the a request is redirected by the BIG-IP with an iRule that is using the command  HTTP::redirect the new redirection request will use the GET method. So if the original request did use a different HTTP method this could cause problems with the request to the new location.

Environment

  • A virtual server configured with a redirect iRule using the command HTTP::redirect
Example of an redirect iRule using the command HTTP::redirect

when HTTP_REQUEST {
      HTTP::redirect https://[HTTP::host][HTTP::uri]
}

Cause

  • The command HTTP::redirect sends an HTTP 302 response code which changes the HTTP method in the next request to GET.

Recommended Actions

  • Create a new iRule using the command HTTP::respond and set the response code as 307 or 308, these response codes should preserve the HTTP method from the initial request.
Example of an redirect iRule using the command HTTP::respond

when HTTP_REQUEST {
  HTTP::respond 307 Location "https://[HTTP::host][HTTP::uri]"
}

or

when HTTP_REQUEST {
  HTTP::respond 308 Location "https://[HTTP::host][HTTP::uri]"
}
