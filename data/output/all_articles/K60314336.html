Description

How to disable replicas or change the number of shards for events and alerts.

Note: In certain scenarios, we may want to change the default number of shards or replicas in the template for these indices. By default restjavad creates indices with 5 shards and 1 replica. 


Environment

  • BIG-IQ DCD Cluster
  • Enabled one of DCD services ( example: Access, Web Application Security)
  • Changing number of shards in index or replicas

Cause

None

Recommended Actions
 

Please follow one of procedures below to update template for future indices or for existing indices :
  • Changing current number of replicas 
This can be done to any index, replicas can be increased, or reduced down to 0 by changing the settings of the index. This can be done in the alias so that the new setting gets applied to all indices, example: 

curl localhost:9200/websafe/_settings -X PUT -d '{"index":{"number_of_replicas":0}}'

  • Changing the template for future indices
​​​​​​​​​​​​​​When changing the template, we can set the new value both for replicas and default number of shards. Example:
curl -s localhost:9200/_template/websafe |jq .websafe > /var/tmp/template_websafe          ;
sed -i 's/"number_of_replicas": "1"/"number_of_replicas": "0"/g' /var/tmp/template_websafe ;
sed -i 's/"number_of_shards": "5"/"number_of_shards": "1"/g' /var/tmp/template_websafe ;
curl -s localhost:9200/_template/websafe -X PUT -d @/var/tmp/template_websafe              ;

Additional Information

Indices and aliases 

The BIG-IQ uses an indexed database called ElasticSearch to store events and alerts generated by the BIG-IP. This events are stored in different indices that are created when a service are enabled for a specific Data Collection Device. 
 
ServiceIndices

Access

access-stats, oauth-requests, oauth-summary, oauth-client-stats, access-utility, access-application-logs, vdi, access-active-sessions, access-sessions, session-entity, access-sessions, access-event-logs, oauth-profile-stats

Dos Protection 

doslogindex, dossummaryindex, ddosindex

websafe

IPsec

ipsec-event-logs

Network Securityafmlogindex
Web Application Securitybotindex, bruteforcesecindex, bruteforceprimindex, asmindex

In order to write to the latest index, and read every index, we create two aliases per index. The one we use to read points to every index, and the writer points to the latest index only, for example: 

websafe -> websafe_2019-09-29t00-00-00+0100  , websafe_2019-09-25t00-00-00+0100 , websafe_2019-09-20t00-00-00+0100

websafe_writer -> websafe_2019-09-29t00-00-00+0100
