Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP iSeries device is running 12.1.2 or later.
  • You want to install more than three TMOS software volumes.

Description

The BIG-IP iSeries platform includes a new, logical volume named appdata for storing dynamic data from provisioned modules such as BIG-IP Analytics, ASM, APM, and Virtual Clustered Multiprocessing (vCMP). On iSeries platforms running BIG-IP 12.1.2 or later, the TMOS installer expands the size of the appdata volume. The increased volume size may prevent the installation of more than three TMOS images. For more information, refer to K41812306: The appdata volume on BIG-IP iSeries platforms is now larger. If you want to install more than three TMOS software volumes, use the following procedure to reduce the size of the appdata volume.

Note: To prevent the expansion of the appdata volume, ensure that you have three TMOS software volumes with BIG-IP 12.1.1 installed before you create a fourth TMOS software volume with a 12.1.2 or later upgrade.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You can access the Advanced Shell (bash) of the BIG-IP system.

Note: For more information on the commands used in this article (e.g. lvreduce, vgs, fsck and so on), refer to the man pages. For example, enter man lvreduce.

Procedures

Reducing the size of the appdata volume by using the lvreduce utility

After the appdata volume has been increased through an upgrade or clean installation of 12.1.2 or later, you can use the lvreduce utility to manually reduce the volume size.

Impact of procedure: While system services are stopped, the system does not pass traffic and the Configuration utility is unavailable; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window. Additionally, the specific lvreduce command string in this procedure reduces the file system first, so data is not lost by the logical volume reduction; however, while unlikely, any reduction to a file system or logical volume has the potential for data loss.

  1. Create a user configuration set (UCS) backup of the BIG-IP system. If vCMP guests are deployed on the system, create UCS backups of all guests. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).
  2. Log in to the BIG-IP command line using the management IP address or the serial console port.

    Note: If you access the BIG-IP command line using a self IP address, you lose access in step 5.

  3. Verify the amount of free space in the volume group by entering the following command:

    vgs

    Output appears similar to the following example:

    # vgs
      VG        #PV #LV #SN Attr   VSize   VFree
      vg-db-sda   1  17   0 wz--n- 447.12g 9.88g

  4. Verify the size of the appdata volume by entering the following command:

    lvs | grep appdata

    Output appears similar to the following example:

    # lvs | grep appdata
      dat.appdata   vg-db-sda -wi-ao--- 341.44g  

  5. To allow the lvreduce utility to unmount the /appdata directory, stop all system services by entering the following command::

    tmsh stop sys service all

  6. If your BIG-IP device is running BIG-IP 16.1.2.2 and later, your BIG-IP device may be affected by ID 1121169. You will need to stop the jitterentropy-rngd process by entering the following command:

    systemctl stop jitterentropy-rngd

  7. Reduce the size of the appdata volume by 40 GB by entering the following command:

    lvreduce --resizefs --size -40G /dev/vg-db-sda/dat.appdata

  8. When prompted, enter y to confirm that you want to unmount the /appdata directory from the appdata volume.
  9. Confirm that the lvreduce command completes successfully by locating output similar to the following example:

    fsck from util-linux-ng 2.17.2
    dat.appdata: 4200/22380544 files (2.8% non-contiguous), 1444031/89505792 blocks
    resize2fs 1.41.12 (17-May-2010)
    Resizing the filesystem on /dev/mapper/vg--db--sda-dat.appdata to 79020032 (4k) blocks.
    The filesystem on /dev/mapper/vg--db--sda-dat.appdata is now 79020032 blocks long.

      Reducing logical volume dat.appdata to 301.44 GiB
      Logical volume dat.appdata successfully resized

  10. After the lvreduce command has completed, confirm the amount of free space in the volume group is increased by 40 GB by entering the following command:

    vgs

    Output appears similar to the following example:

    # vgs
      VG        #PV #LV #SN Attr   VSize   VFree
      vg-db-sda   1  17   0 wz--n- 447.12g 49.88g

  11. Confirm the appdata volume size is reduced by entering the following command:

    lvs | grep appdata

    Output appears similar to the following example:

    # lvs | grep appdata
    dat.appdata vg-db-sda -wi-ao--- 301.44g

  12. Start all system services by entering the following command:

    tmsh start sys service all

  13. If your BIG-IP device is affected by ID 1121169 and you have stopped the jitterentropy-rngd process in an earlier step, you must ensure that the BIG-IP device is fully operational and the TMM process is up and running before you attempt to start the jitterentropy-rngd process. You can start the jitterentropy-rngd process by entering the following command:

    systemctl start jitterentropy-rngd

After this procedure is complete, you can proceed with installing TMOS images to more than three TMOS software volumes.

Note: During the system boot process, hardware BIG-IP platforms attempt to expand the  /appdata directory to take advantage of the free disk space available.  Disk space freed from /appdata by performing the procedure in this article but not used for a software installation is added back to /appdata the next time the BIG-IP system is restarted. Therefore, you should proceed with the TMOS image installation before the BIG-IP system restarts so that  /appdata does not revert to its previous size after the restart.
