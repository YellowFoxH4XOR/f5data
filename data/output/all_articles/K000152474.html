K000152474: ASM false positives after upgrade

Type
Support Solution
Published
2025-07-08
Updated
2025-10-14
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.0
Source
https://my.f5.com/manage/s/article/K000152474

Description

After upgrading to BIG-IP ASM version 17.5.0, multipart/form-data requests may trigger the violation "Forbidden NULL in multipart parameter" (for example: Forbidden NULL in multipart parameter: ctl00$cp1$upfile). This occurs when a NULL character (binary 00) is present in multipart parameter names or values. The issue can arise even if there have been no changes to the application or security policy, and was not observed in previous versions.

Environment

  • Product: BIG-IP ASM
  • Version: 17.5.0
  • Security Policy Configuration: Parameters set with Data Type as Alpha-Numeric
  • Typical Use Case: Multipart/form-data requests, such as file uploads

Cause

A change introduced in ASM version 17.5.0 increased detection sensitivity for NULL (binary 00) characters within multipart parameter names or values. If parameters are configured as Alpha-Numeric but receive binary data (such as file uploads containing NULL bytes), this triggers the violation. This behavior is a side effect of a bug fix and has been resolved starting with version 17.5.1.

Recommended Actions

  • Upgrade to BIG-IP ASM version 17.5.1 or later where this issue is fixed.
  • As an immediate workaround, review your security policy and set affected parameters (such as file upload fields) with the Data Type "File Upload" instead of "Alpha-Numeric."
  • For file upload parameters, consider enabling "Disallow File Upload of Executable" for enhanced security.
  • Ensure that all parameters expected to handle binary data are properly configured in the security policy to prevent false positives.
  • Consider integrating ICAP Antivirus scanning for additional protection on file uploads.
