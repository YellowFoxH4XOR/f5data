K000151791: F5OS-A becomes unresponsive after an upgrade

Type
Support Solution
Published
2025-06-11
Updated
2025-06-11
Applies to
  • F5OS
  • F5OS-A: 1.5.X, 1.8.X, 1.8.0, 1.5.3, 1.5.2, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000151791

Description

  • Upgrading F5OS-Appliance (F5OS-A) version 1.5.0 to 1.8.0 can result in the appliance failing to boot after the upgrade process completes.
  • The system may become unresponsive, with no access via console, AOM (Auxiliary Management Controller), or GUI interfaces.
  • Recovery is only possible through a manual power cycle (hard reboot).
  • System Event Log (SEL) entries similar to the following can be seen on  /var/log/platform/sel:

    MCA Error-Reporting Registers Capture. Bank: 6 Core: 0 STATUS Register: 0x0419 Value: 0xb980000000000e0b
    MCA Error-Reporting Registers Capture. Bank: 6 Core: 0 MISC Register: 0x041b Value: 0x0000000000180000

Environment

  • Product: F5OS - Appliance
  • Platform: rSeries 2000/4000
  • Upgrade from 1.5.0 to 1.8.0
  • Typical configuration: Licensed appliance with active tenants; standard upgrade procedure

Cause

This issue is due to a hardware/firmware interaction tracked as F5 Bug ID 1338645. During the upgrade, the appliance may experience a CPU Machine Check Error (MCERR) and the AOM controller may enter "MFG Lockout" mode, resulting in a hung state that prevents normal booting.

Recommended Actions

  • Disable ASPM (Active State Power Management) and L1 Substate options in the system BIOS to prevent drives from entering low power mode. Refer to F5 article K000151762 for detailed workaround steps.
  • If the appliance becomes unresponsive after an upgrade, perform a manual power cycle (hard reboot).
