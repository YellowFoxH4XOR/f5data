Description

This article details one possible scenario where a BIG-IP LTM module fails to discover from BIG-IQ.

  • error messages similar to the one below in /var/log/restjavad.0.log:

[ERROR][16 Apr 2020 10:51:42 NZST][/cm/adc-core/tasks/discover-config/f2c10afe-0bd8-4e7b-8903-ed21091bd09a/worker AdcDiscoveryTaskWorker] Unable to query rewrite profiles: java.net.ProtocolException: status:500, body:{"code":500,"message":"Input length = 1","referer":"http://localhost:8100/cm/adc-core/tasks/discover-config/f2c10afe-0bd8-4e7b-8903-ed21091bd09a/worker","restOperationId":700057,"kind":":resterrorresponse"}
 

  • output from the BIG-IP for the command tmsh show sys hardware | grep -i manufacturer returns non-UTF8 characters for the manufacturer field as below

tmsh show sys hardware | grep -i manufacturer
     Manufacturer Western Digital
     Manufacturer ARTESYN?? <<<<<<<<<
 

Environment

  • BIG-IP appliance with a power supply unit (PSU)
  • BIG-IQ Centralized Manager
     

Cause

As part of the LTM module discovery process, the BIG-IP gathers the hardware information for collation to the BIG-IQ.
Due to the non-UTF8 characters in the output, the REST API fails to process the non-UTF8 character set in the response.
 

Recommended Actions

Check the power supply of the BIG-IP and work with F5 support to identify how to fix or replace.
