Known Issue

This is the result of a known issue. When a persistence profile is assigned to a CMP-enabled virtual server (that is, when there are multiple TMM instances running on the unit and the virtual server is not pinned to a single TMM), changing the configuration of the virtual server while a persistent connection is open may cause a loop within TMM. This behavior results in a CPU utilization spike and eventually in a memory exhaustion situation. Typically, the memory exhaustion will cause TMM to crash in an unrelated area of code (simply the next instruction that attempts to allocate a TMM memory segment), at which point TMM will dump core and restart. After TMM has restarted, the BIG-IP system will resume normal operations; however, the issue will occur again the next time the configuration is changed.

F5 Product Development tracked this issue as CR128753 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator or WAN Optimization release notes.
