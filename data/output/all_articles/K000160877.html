K000160877: Troubleshooting Upstream Errors in F5 Distributed Cloud Load Balancers with Multiple Origin Pools

Type

Source

Description

Upstream errors are reported by the F5 Distributed Cloud TCP or HTTP Load Balancer when one of multiple origin pools is intentionally taken offline, even though at least one origin pool remains healthy and reachable. Health checks fail with timeouts for the offline origin pool, and traffic is not consistently routed to the healthy origin pool, resulting in upstream errors.

Symptoms:

  • Upstream errors reported by F5 Distributed Cloud TCP or HTTP Load Balancer.
  • Health checks failing with timeouts for one origin pool.
  • Traffic not consistently routed to the healthy origin pool when the other is offline.

Error/Log Messages:

  • Health check logs indicate failures/timeouts for the offline origin.
  • Upstream errors observed in the load balancer logs.

Environment

  • Product: F5 Distributed Cloud
  • Service: TCP Load Balancer or HTTP Load Balancer
  • Multiple origin pools configured
  • "Retract cluster" option changed from default (enabled) to disabled during testing
  • Scenario: One origin pool intentionally taken offline to test failover

Cause

The "retract cluster" option was set to disabled, which impacted the load balancer's ability to reroute traffic to the healthy origin pool when one pool was offline, resulting in upstream errors.

Answer/Recommended Actions

  1. Verify the "Retract Cluster" Option:
    • Check the configuration of the TCP or HTTP Load Balancer and confirm the status of the "retract cluster" option.
    • The default setting for this option is "enabled."
  2. Testing and Resolution:
    • If the option was set to "disabled," revert it to the default ("enabled").
    • Retest the failover scenario by taking one origin pool offline and observe the traffic routing behavior.
    • Confirm that traffic is correctly routed to the healthy origin pool and that upstream errors are no longer observed.
  3. General Recommendations:
    • Always validate configuration changes when troubleshooting unexpected load balancer behavior.
    • Use health check logs to monitor the status of origin pools during testing.

Additional Information

  • When the "retract cluster" option is set to its default (enabled), the TCP or HTTP Load Balancer correctly reroutes traffic to healthy origin pools during failover scenarios.
  • Disabling this option may result in traffic being sent to unhealthy or offline origins, causing upstream errors.
  • After restoring the default setting, the system behaves as expected and the issue is resolved.
