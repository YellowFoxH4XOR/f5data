K000163210: mTLS is not working using Self-Signed certificate

Type
Support Solution
Published
2026-09-04
Updated
2026-09-04
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163210

Description

Mutual TLS (mTLS) client-certificate validation fails when a self-signed certificate is configured as a trusted Certificate Authority (CA) but lacks the required CA key usage.

After the client presents its certificate, BIG-IP terminates the TLS handshake and logs messages such as:

  • Peer cert verify error: unable to get local issuer certificate
  • Connection error: ssl_shim_vfycerterr:4593: alert(48) unable to get local issuer certificate
  • SSL Handshake failed

Environment

  • BIG-IP LTM
  • Client SSL profile configured for mutual TLS
  • Client certificate authentication enabled
  • Trusted Certificate Authorities configured through the Client SSL profile ca-file
  • A self-signed certificate configured as the trusted CA

Cause

The configured self-signed certificate was marked CA:TRUE.

CA:TRUE alone is insufficient to identify a certificate as a suitable issuing CA. The certificate should also have appropriate CA key usage, including Certificate Sign; CRL Sign is normally included for a complete CA profile.

Answer/Recommended Actions

1.) Inspect the certificate configured in the Client SSL profile trusted CA bundle:

openssl x509 -in <certificate-file> -noout -text

Verify that the certificate contains the following extensions:

X509v3 Basic Constraints: critical
  CA:TRUE

X509v3 Key Usage: critical
  Certificate Sign, CRL Sign

2.) Check the certificate purpose:

openssl x509 -noout -purpose -in <certificate-file> | grep -iE 'client|server'

The CA certificate should report:

SSL client CA : Yes
SSL server CA : Yes

3.) If the existing certificate is an end-entity certificate or has incorrect CA extensions, obtain or generate a replacement CA certificate with at least:

Basic Constraints: critical, CA:TRUE
Key Usage: critical, Certificate Sign, CRL Sign

 

Additional Information

A certificate containing TLS Web Client Authentication and TLS Web Server Authentication Extended Key Usage values is not automatically suitable for issuing other certificates.

Digital Signature and Key Encipherment support end-entity operations but do not provide the Certificate Sign usage required for a certificate issuer.

Refer to X.509 - Wikipedia to see sample of a root certificate (a self-signed root certificate representing a certificate authority) that is valid to sign leaf certificate.
