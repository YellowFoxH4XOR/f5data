Known Issue

This is the result of a known issue. The BIG-IP ASM Requests page displays a list of all objects requested by users of the web application. When a large number of requests are stored in the BIG-IP ASM database, the clean_db.pl script may consume a large amount memory, and a high percentage of CPU time.

This behavior is the result of the way that the clean_db.pl script prunes the size of the request log database (PROXY_LOG). The BIG-IP ASM system attempts to prune the database evenly between all web applications so that each web application maintains the same share of entries in the logs. This behavior may cause the script to consume large amounts of processor time as the log grows.

F5 Product Development tracked this issue as ID 204951 (formerly CR112818) and it was fixed in BIG-IP ASM 9.4.8 and 10.1.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

You can resolve this issue by commenting out two lines in the /ts/tools/clean_db.cfg configuration file. To modify the /ts/tools/clean_db.cfg configuration file, perform the following procedure:

  1. Log in to the command line.
  2. Use a text editor to edit the /ts/tools/clean_db.cfg file.
  3. Comment out the following lines by adding a number sign ( # ) to the beginning of each line:

    #SqlCond=account_id
    #SqlCondLimit=1000000
  4. Save the changes.

Note: If the MySQL PROXY_LOG consumes more than 200Mb of SQL data, and the BIG-IP ASM Requests page loads slowly or times out, refer to K9161: The BIG-IP ASM Requests page may load slowly or time out.
