Description
Depending on a version you initially deploy BIG-IP VE ova file, how BIG-IP allocates storage space for MYSQL may differ.
This may impact how you pay attentions for monitoring the MYSQL storage space on your environment.
Please note for the case of upgrade that if you deploy one of your environment that behaves the old behavior and upgrade to upper version that behaves new behavior, the BIG-IP takes over the old behavior.

The old behaviour in version with v11 and v12, MYSQL storage space is allocated to dedicated partition on /var/lib/mysql.
The output is similar to the following example.

# df -h /var/lib/mysql
Filesystem            Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-app.ASWADB.set.1.mysqldb
                       12G  139M   12G   2% /var/lib/mysql


The new behaviour with v13 and later, MYSQL storage space is allocated to appdata partition and /var/lib/mysql is a symbolic link to /appdata
The output is similar to the following example.

# df -h /var/lib/mysql
Filesystem            Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--vda-dat.appdata
                       25G  186M   24G   1% /appdata

# ls -l /var/lib/mysql
lrwxrwxrwx. 1 mysql mysql 34 2020-09-10 16:51 /var/lib/mysql -> /appdata/mprov/local/HD1.1/mysqldb

Environment

  • BIG-IP AFM VE
  • BIG-IP ASM VE
  • BIG-IP AVR VE
