K000156845: How do I know if BIG-IP APM is configured on a virtual server?

Type

Published
2025-10-06
Updated
2025-10-20
Applies to

  • BIG-IP APM
Source

Description

This article provides detailed instructions on how to determine if a virtual server on BIG-IP is using the Access Policy Manager (APM) module. It includes diagnostic steps, common configurations required, and considerations for troubleshooting issues related to APM virtual server setup.

Environment

  • BIG-IP system with APM module.
  • Virtual server with access policies or connectivity profiles attached.
  • System GUI and CLI references.
  • APM provisioning and licensing considerations.

Cause

None

Answer/Recommended Actions

  • Verify if APM is provisioned:
    • GUI: Navigate to System > Resource Provisioning and ensure APM is provisioned (Nominal or higher).
    • CLI: Run tmsh list sys provision apm. If APM is not provisioned, the Access Policy tab will not appear.
      # tmsh list sys provision apm
      sys provision apm {
          level nominal
      }
  • Check the virtual server configuration in the GUI:
    • Go to Local Traffic > Virtual Servers > Virtual Server List, and select the virtual server.
    • Scroll down to the Access Policy section:
      • If Access Profile is listed (e.g., /Common/my_access_profile), APM is enabled.
      • If None, APM is not enabled.
      • If a Per-Request Policy or a Connectivity Profile is present, additional APM features like SWG/forward proxy or VPN access may be in use.
    • An alternative view: Go to Access > Profiles/Policies > Access Profiles (Per-Session Policies) and check the Virtual Servers column to identify linked access profiles.

  • Check the virtual server configuration in the CLI:
    • Run the following command to display the configuration of the "Example_VS"virtual server:
      tmsh list ltm virtual /Common/Example_VS
      • Look for lines that match the names of your Access Profiles, Per-Request-Policies, and Connectivity Profiles.
    • Use grep for quick searches:
      tmsh list ltm virtual /Common/Example_VS | egrep -i '<access-profile-name>|<per-request-policy-name>|<connectivity-profile-name>'
    • To find all APM-enabled virtual servers:
      tmsh list ltm virtual one-line | egrep -i '<access-profile-name>|<per-request-policy-name>|<connectivity-profile-name>'

Additional Information

  • What “counts” as APM configured:
    • Minimum: An Access Profile is attached to the virtual server.
    • Often present: Per-Request Policy for URL/category decisions or a Connectivity Profile for VPN Access.
    • Tip: If the Access Policy section does not exist in the virtual server configuration page, APM is not provisioned, and APM cannot be enabled.
  • Common gotchas:
    • APM not provisioned or licensed: Access Policy options won’t appear on the VS.
    • Missing supporting profiles: HTTP profiles are needed for web use-cases; Connectivity Profiles are typically required for VPN use-cases.
    • Wrong partition: Ensure you are in the correct partition for both the virtual server and access profiles.
