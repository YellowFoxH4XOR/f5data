Description

Similar to how we can force a failover from Active device in the device group via TMUI or CLI, it is also possible to force a failover by leveraging REST API. 

Environment

  • BIG-IP devices configured in HA environment
  • REST API

Cause

With there being a larger drive towards automation, REST API can be leveraged as a convenient approach to force a failover from the Active device in the group. 

Recommended Actions

The following cURL command can be run on or against the Active device to force a failover such that it goes into Standby state:

curl -ks -H "Content-Type: application/json" -u admin:admin "https://localhost/mgmt/tm/util/bash" -d "{\"command\":\"run\", \"utilCmdArgs\":\"-c 'tmsh run sys failover standby'\"}" | jq .

Example output:
{
  "kind": "tm:util:bash:runstate",
  "command": "run",
  "utilCmdArgs": "-c 'tmsh run sys failover standby'"
}

If there are more than one traffic group or more than two devices, then you will need to explicitly specify the traffic group or device name in the tmsh command within the above API call's payload using the approach described in K15455872: Forcing an active BIG-IP system into standby mode using tmsh

Additional Information

Similarly, if there is desire to force device into an offline state, the following cURL command can be used:

curl -ks -H "Content-Type: application/json" -u admin:admin "https://localhost/mgmt/tm/util/bash" -d "{\"command\":\"run\", \"utilCmdArgs\":\"-c 'tmsh run sys failover offline'\"}" | jq .
