K11208: The Policy Wizard inserts an incorrect session variable when used to create an RSA SecurID access policy

Known Issue

This is the result of a known issue. If the Network Access Setup Wizard for Remote Access wizard is used to create an access policy that uses SecurID as its method of authentication, the resulting access policy is created with an incorrect session variable. The incorrect session variable will make all attempts to authenticate fail.

F5 Product Development tracked this issue as CR132861 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP APM release notes.

Workaround

To manually correct the session variable, perform the following procedure:

  1. Log in to the BIG-IP APM Configuration utility.
  2. Expand the Access Policy tree.
  3. Click Access Profiles.
  4. Click Edit for the Access Policy that was created using the Wizard.

    Note: A new browser window will pop up with the access policy.
  5. Click the RSA SecurID macro.

    Note: A new box will pop up to edit the macro.
  6. Click the Branch Rules tab.
  7. Click the change link next to Expression: expr {[mcget {session.securid.last.authresult}] == 1}.

    Note: A new box will pop up to edit the session variable.
  8. Click the Advanced tab.
  9. Remove the session.securid.last.authresult session variable.
  10. Replace the session variable with session.secureid.last.result.
  11. Click the Finished button.
  12. Click the Save button.
  13. Click the Close button located in the upper right-hand corner.
  14. You will need to activate the policy by selecting the check box next to the name of the access policy created by the wizard.
  15. Click the Apply Access Policy button.
