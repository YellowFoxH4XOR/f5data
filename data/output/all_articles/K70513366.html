Issue

Error Message

01150216:5: Notice from named-checkconf: zone <name>

In this error message, note the following:

  • <name> is the name of the DNS zone file.

For example:

01150216:5: Notice from named-checkconf: zone com/IN: NS 'example.com' has no address records (A or AAAA)

Message Location

You may encounter this message in the following location:

  • The /var/log/gtm file

Description

This message occurs when one of the following conditions are met:

  • The named-checkconf command parses a bind zone file and finds no errors, the system logs messages in the /var/log/gtm file that appear similar to the following example:

    01150216:5: Notice from named-checkconf: zone example.com 

  • The named-checkconf command parses a bind zone file and finds an error in the zone, the system logs messages in the /var/log/gtm file that appear similar to the following example:

    01150216:5: Notice from named-checkconf: zone com/IN: NS 'example.com' has no address records (A or AAAA)

Note: The BIG-IP DNS system uses the named-checkconf utility to verify that DNS zone files use correct syntax prior to loading zone information into memory.

  • The named-checkconf utility parses a bind zone file that contains host names with underscore, the system logs messages in the /var/log/gtm file that appear similar to the following examples even though the domain-name-check setting for the BIG-IP DNS global-settings is set to allow-underscore:

    01150216:5: Notice from named-checkconf: db.external.0.0.15.in-addr.arpa.:17: warning: lsf2_041001.176.com: bad name (check-names)
    01150216:5: Notice from named-checkconf: db.external.0.0.15.in-addr.arpa.:18: warning: bad_name.176.com: bad name (check-names)
    01150216:5: Notice from named-checkconf: db.external.176.com.:14: bad_name.176.com: bad owner name (check-names)

Impact

  • If syntax errors are associated with the error message, new zone files or updates to existing zone files will not load into memory.
  • If the error message reports bad name (check-names) and the affected host name are verified to have underscore, it is safe to ignore the error message. However, if you prefer the system to stop logging the error message, you can modify the named configuration to disable the check-names configuration. To do so, perform the Modifying named configuration to ignore check-names procedure described in the Recommended Actions section.

Recommended Actions

After you identify the zone file syntax error, refer to the following article for assistance with editing the zone file: K7032: Freezing zone files to allow manual update to ZoneRunner-managed zone files. 

If you have determined that the error message is reporting a bad name due to an underscore and you want the system to stop logging the error message, perform the following procedure:

Modifying named configuration to ignore check-names

Impact of procedure: Modifying the check-names setting to ignore in the named configuration would prevent the system from logging any hostname in a zone file that is non-compliant to various DNS RFCs such as RFC952 and RFC 1123.

  1. Log in to the BIG-IP DNS Configuration utility.
  2. Go to DNS > Zones > ZoneRunner > named Configuration.
  3. Under named Options, locate the following configuration in the Options setting: 

    check-names master warn;

  4. Change the value warn to ignore; the modified configuration would look like the following: 

    check-names master ignore;

  5. Select Update to save the changes.
