K000149990: VPN Connectivity issues caused by DNS64 mechanisms on DNS server in BIG-IP APM

Support Solution
Published

Updated
2025-03-06
Applies to

  • BIG-IP APM: 17.1.0, 17.1.1, 17.0.X, 17.0.0, 16.1.5
Source

Description

Users are unable to connect to the VPN when using a mobile hotspot. The following error message may appear:

The VPN connection has failed because it attempted to connect to an insecure network. Please switch to a secure network.

Logs may show entries such as:DNS Resolved IP a_serverIpAddress: <IPv6 Address starts with 64:ff9b> is NOT a Valid APM Server IP, seems the VS IP is spoofed. The connected network is vulnerable for tunnel crack attack due to server IP attack, please change the network. Stopping the VPN connection initialization.

This issue persists even after following the solutions provided in articles K000138683: Users cannot connect to BIG-IP APM virtual servers "The VPN connection has failed because it attempted to connect to an insecure network" with BIG-IP Edge Client 7246 and above and K000140218: Insecure Network Prompt even after populating the vpn.serveriplist DB Variable per K000138683.

Important: This article only applies to environments in which actions from article K000138683: Users cannot connect to BIG-IP APM virtual servers with BIG-IP Edge Client 7246 (f5.com) and K000140218: Insecure Network Prompt even after populating the vpn.serveriplist DB Variable per K000138683 were already followed, yet the issue persists. 

Cause

The issue occurs because the DNS server resolves an IPv6 address for the connection server that is not included in the vpn.serveriplist database variable on BIG-IP APM. This IPv6 address may be part of NAT64/DNS64 translation mechanisms used by mobile hotspots, which embed IPv4 addresses into IPv6 format (e.g., prefix). The resolved IPv6 address is flagged as invalid by the system, causing the connection attempt to fail.

DNS64 is a mechanism that works in conjunction with NAT64 to allow IPv6-only clients to resolve and access IPv4-only resources. DNS64 servers synthesize AAAA records (IPv6) from A records (IPv4), enabling IPv6 clients to communicate with IPv4 servers through NAT64.

Environment

  • Edge Client version 7250 or older
  • Mobile hotspot connection with DNS servers using DNS64 mechanism

Recommended Actions

Verify DNS Server response using nslookup

To confirm whether the issue is related to incorrect or unexpected DNS responses, use the nslookup command to check how the VPN server's IP address is resolved by your current DNS server:

  1. Open a terminal or command prompt.
  2. Run the following command:
    nslookup <VPN Server FQDN>
  3. Review the output for any unexpected results, such as an IPv6 address being returned when only an IPv4 address should be used.

If you notice that an unexpected IPv6 address is being returned (e.g., NAT64-translated), consider disabling IPv6 on the affected network adapter or change the DNS server setup:

Disable IPv6 on the client device

To avoid using IPv6 for DNS queries on affected devices:

  1. Open the "Control Panel" on Windows.
  2. Navigate to "Network and Sharing Center."
  3. Click "Change adapter settings."
  4. Right-click on the network connection (mobile hotspot) and select "Properties."
  5. Uncheck "Internet Protocol Version 6 (TCP/IPv6)."
  6. Click "OK" and close all windows.

Change DNS servers on the affected network adapter

  1. Open the "Control Panel" on Windows.
  2. Navigate to "Network and Sharing Center."
  3. Click "Change adapter settings."
  4. Right-click on the network connection (mobile hotspot) and select "Properties."
  5. In the properties window, select "Internet Protocol Version 4 (TCP/IPv4)" and click "Properties".
  6.  In the IPv4 properties window, select "Use the following DNS server addresses"
  7. Enter the IP addresses of the standard DNS servers you wish to use. For example:
    The preferred DNS server: 1.1.1.1 (Cloudflare DNS)
     
    Alternate DNS server: 8.8.8.8 (Google DNS)

    8. Click "OK" to save the settings
