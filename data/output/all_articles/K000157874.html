Description

Creating BIG-IQ Autofailover configuration or promoting Secondary BIG-IQ CM to Primary may result in errors  in  GUI and restjavad.log such as:

stderr: ERROR: Failure executing pg_basebackup. status: 1/usr/bin/ha_streaming_replication: line 105: 6532 Terminated ( sleep "$sleep_time" & local sleep_pid="$!"; trap "kill $sleep_pid 2>/dev/null" EXIT; wait "$sleep_pid"; kill "$cmd_pid" 2> /dev/null )

ERROR: Failure establishing streaming replication on the standby. Error code: 1

when device  has large configuration or there are performance issues with one of the devices.

Process of establishing HA is failing at pg_basebackup script  /var/log/ha.log

Fri Jul 18 15:47:37 IST 2025 - SETUP RECEIVER] INFO: Execute pg_basebackup
Fri Jul 18 15:51:50 IST 2025 - SETUP RECEIVER] ERROR: Failure executing pg_basebackup. status: 1

Manual failover configuration  may succeed, but Autofailover fails due to delays in PostgreSQL startup and replication. 

Environment

  • BIG-IQ CM Cluster 
  • Failing to Establish HA Cluster

or

  • Failing to promote  BIG-IQ CM Secondary to Primary
  • Large configuration or performance issues of one of the CM nodes in cluster

Cause

The underlying cause is excessive delay in the standby device’s PostgreSQL startup process during Autofailover HA setup. The default PostgreSQL parameter wal_sender_timeout (set to 1 minute) does not allow enough time for the database to become ready, causing timeout and failure of the streaming replication step (pg_basebackup).

Recommended Actions

  1. Increase PostgreSQL wal_sender_timeout
    Edit the PostgreSQL configuration file on both BIG-IQ devices:
    vi /var/lib/pgsql/data/postgresql.conf
    Add or update:
    wal_sender_timeout = 5min
    Reload the configuration:
    psql -U postgres -d bigiq_db -c "select pg_reload_conf();"
  2. Re-attempt HA Configuration
    Break any existing manual HA setup.
    Attempt Autofailover configuration again. (Adding a Standby BIG-IQ to Create a High Availability Auto Failover Configuration)
