Description

This article provides an overview of Client SSL profiles and detailed steps to check their configuration and functionality on a BIG-IP system. A Client SSL profile is used to terminate HTTPS traffic at the BIG-IP virtual server, facilitating features like Layer 7 protocols and traffic management.

Environment

  • BIG-IP systems configured with Client SSL profiles
  • Virtual servers requiring HTTPS traffic termination
  • Certificates, keys, and ciphers configured in BIG-IP

Cause

None.

Answer/Recommended Actions

What it is:

  • A Client SSL profile is the set of TLS/SSL settings BIG-IP uses to terminate HTTPS from clients at the virtual server.
  • It contains the certificate, private key, (optional) chain/intermediate certs, allowed TLS versions, ciphers, SNI settings, OCSP stapling, session resumption, etc.
  • When you attach a Client SSL profile to a virtual server, BIG-IP decrypts client traffic (SSL offload/termination) so L7 features (HTTP, WAF, iRules) can operate on cleartext. Without it, the VS either does TCP/SSL passthrough or won’t complete TLS handshakes on its own.

How to check in the GUI (TMUI):

  1. Go to Local Traffic -> Virtual Servers -> Virtual Server List.
  2. Click the virtual server name.
  3. Switch View to Advanced if needed.
  4. Find SSL Profile (Client). If one or more profiles are listed there (for example /Common/clientssl or a custom name), the VS has a client SSL profile attached.

How to check in TMSH (CLI):

  • See profiles on a specific virtual server: tmsh list ltm virtual /Partition/VS_Name Then look in the profiles { … } block for entries showing context clientside. Those entries are your client SSL profiles (commonly named clientssl or a custom name).
  • Focus just on the profiles section: tmsh list ltm virtual /Partition/VS_Name profiles
  • Inspect a specific client SSL profile’s key parts (cert/key/chain): tmsh list ltm profile client-ssl /Partition/Profile_Name cert key chain ciphers options

How to quickly verify from a client:

  • Use OpenSSL to connect to the VIP and see the certificate the BIG-IP presents: openssl s_client -connect VIP_Address:443 -servername hostname If you see the cert that’s configured in the BIG-IP client SSL profile, the profile is active and terminating TLS. If you see the backend server’s cert instead, the virtual is likely doing SSL passthrough (no client SSL profile attached).

Notes:

  • Multiple client SSL profiles can be attached to one VS; BIG-IP will select based on SNI if configured.
  • Don’t confuse Client SSL with Server SSL profiles. Server SSL profiles handle re-encryption from BIG-IP to the pool members (backend). You only need Server SSL if you want TLS between BIG-IP and servers after offload.
