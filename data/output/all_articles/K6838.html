K6838: BIG-IP GTM or Link Controller Listener virtual server can not be configured with a lasthop pool using the Configuration utility

Topic

When a Listener IP address is configured on a BIG-IP Link Controller or BIG-IP GTM, a virtual server is created. If the BIG-IP Link Controller or BIG-IP GTM is configured for two or more links for inbound requests, this virtual server will use auto_lasthop by default to ensure responses use the same link as the request was received on. 

However, if you globally disable the auto_lasthop feature, the BIG-IP Link Controller or BIG-IP GTM will then use the routing table when sending the replies for requests to the Listener virtual server. The replies will be load balanced properly if the routing table dictates that the replies will be sent through the default gateway pool that contains the two or more links. Therefore, if you want the replies to be returned through the same link from which the request was received, you must configure a lasthop pool for the Listener virtual server.

Important: The BIG-IP GTM 9.x is not licensed for lasthop pool functionality. Therefore, if you globally disable the lasthop feature you can not configure the Listener virtual server with a lasthop pool on 9.x BIG-IP GTM only systems.

Additionally, the Configuration utility does not provide the ability to configure a lasthop pool for the Listener virtual server. To do so for BIG-IP Link Controller you must manually configure the Listener virtual server with a lasthop pool using the following workaround.

Note: Beginning in BIG-IP 10.0.0 both GTM and Link Controller allow you to configure a lasthop pool for the Listener virtual server using the tmsh utility.

Workaround

In BIG-IP Link Controller 9.x versions, you can manually configure the Listener virtual server to use a lasthop pool by performing the following procedure:

Important: The BIG-IP GTM 9.x is not licensed for lasthop functionality. Therefore, this workaround is not possible on BIG-IP GTM systems.

  1. Log in to the BIG-IP Link Controller command line.
  2. To change directories to the /config directory, type the following command:

    cd /config

  3. Edit the bigip.conf file using a text editor.
  4. To insert the lasthop pool command into the Listener virtual server configuration, use the following syntax:

    lasthop pool <pool_name>

    For example, a lasthop pool named default_gateway_pool has been added in the following example:

    virtual vs_1_1_1_1_53_gtm {
    destination 1.1.1.1:domain
    lasthop pool default_gateway_pool
    ip protocol udp
    translate address disable
    translate service disable
    profile dns udp
    }

  5. Save the file.
  6. To load the new configuration file, type the following command:

    bigpipe load

After completing this procedure, replies to requests for the Listener virtual server will be returned to the device indicated by the lasthop pool functionality.
