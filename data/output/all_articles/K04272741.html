K04272741: Delay in the authentication to the Configuration Utility

Type
Support Solution
Published
2022-07-05
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K04272741

Description

While login into the Configuration Utility you may experience a long delay to access.
After capturing and decrypting management interface traffic, you may see the client IP sending an internal server error to the GUI similar to the following:

HTTP/1.1 500 Internal Server Error (text/html)

Environment

  • BIG-IP Configuration Utility
  • Local Authentication

Cause

Daemons related to the BIG-IP Configuration Terminal (GUI) have stalled, or tomcat daemon requires more memory.

Recommended Actions

  1. Restart daemons related to BIG-IP Configuration Terminal (GUI).
      # tmsh restart sys service httpd restjavad tomcat
Monitor behavior after restarting daemons. If you are still presenting delays, proceed to step #2.
       
        2. Check tomcat memory.
           
            # tmsh list /sys db provision.tomcat.extramb

The command output should be similar to the following example:

         sys db provision.tomcat.extramb {
         value "0"
         }

If the value is set to 0, Set the provision.tomcat.extramb database variable to the preferred amount of additional memory to be allocated using the following command syntax:

       # tmsh modify /sys db provision.tomcat.extramb value <MB>

Note: F5 recommends an initial value of 50 MB, assuming the device has enough Other memory free,  you can repeat this procedure, increasing the value by 50 MB each time until you no longer encounter the error message.

Important: Check output of free before continuing to confirm the device has enough usable memory available.

          3. Restart the tomcat process by entering the following command:

       # restart /sys service tomcat

Note: If the device is part of a high availability (HA) configuration, change the provision.tomcat.extramb database value on all devices.

None.
