Topic

You should consider using these procedures under the following condition:

  • You want to configure allowed or disallowed HTTP or HTTPS URLs in a BIG-IP ASM security policy.

Description

In some cases, you may want to add allowed or disallowed HTTP or HTTPS URLs to a BIG-IP ASM security policy. Allowed URLs are those that are permitted when accessing the web application; disallowed URLs are those that are not permitted when accessing the web application.

URLs can be added to the security policy as follows:

  • If you are using automatic policy building, the system can learn which URLs to add to the policy based on the traffic to the web application.
  • You can manually add allowed or disallowed URLs to the security policy as required.

When you create a security policy, * wildcard URLs (representing all HTTP or HTTPS URLs) are added to the Allowed HTTP lists. During the enforcement readiness period, the system examines the URLs in the traffic and makes learning suggestions that you can review and add the URLs to the policy as needed. This way, the security policy includes the HTTP or HTTPS URLs that are typically used. When you think all the required URLs are included in the security policy, you can remove the * wildcards from the allowed URLs lists. For more information refer to the Adding Entities to a Security Policy chapter of the BIG-IP Application Security Manager: Implementations guide.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have access to the Configuration utility.

Procedures

  • Add allowed HTTP or HTTPS URLs to the security policy
  • Add disallowed HTTP or HTTPS URLs to the security policy
  • Configure learning and blocking settings for disallowed URLs

Add allowed HTTP or HTTPS URLs to the security policy

To add an allowed URL to the security policy, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
  3. In the Current edited policy list, verify that the listed security policy is the one you want to work on.
  4. Select Create.
  5. In the URL section, define the URL properties, as follows:
    • Select Explicit or Wildcard.
      • Explicit URL - Indicates that the URL name will be explicitly defined and contain no wildcard characters. For example, /index.html.
      • Wildcard URL - Indicates that the URL name will contain one or more wildcard characters; any URL that matches the wildcard expression is considered legal. For example, */wildcard/*.
    • Select HTTP or HTTPS.
    • Enter the name for the URL.
  6. If you want the system to place the URL in staging, leave the Perform Staging check box selected. When staging is enabled for a URL, the system logs learning suggestions to the Learning screen and does not block requests for the URL.
  7. On the Attack Signatures tab, ensure that Check attack signatures and threat campaigns on this URL is selected so attack signatures and threat campaigns are detected on traffic to and from this URL.
  8. (Optional) Select the option to load signatures and from the Overridden Security Policy Settings section you can disable individual attack signatures for the URL. Doing so overrides the security policy settings for the attack signature. For more information refer to K8866: Disable attack signature checks for specific entities.
  9. On the Meta Characters tab (wildcard URLs), you can change the system’s default settings for characters that may appear in the name of the specific URL.
  10. Select Create.
  11. Select Apply Policy.

Add disallowed HTTP or HTTPS URLs to the security policy

In some cases, you may want to deny requests for specific URLs. To add a disallowed URL to the security policy, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > URLs > Disallowed URLs > Disallowed HTTP URLs.
  3. In the Current edited policy list, verify that the listed security policy is the one you want to work on.
  4. Select Create.
  5. In the URL section, define the URL properties as follows:
    • Select Explicit or Wildcard (14.x and later)
    • Select HTTP or HTTPS.
    • Enter the explicit name for the disallowed URL. For example, /index.html.
  6. Select Create.
  7. Select Apply Policy.

Configure learning and blocking settings for disallowed URLs

After you have defined one or more disallowed URLs, you can configure the learning and blocking settings as required. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the General Settings area, select Advanced (13.x - 15.0.1 only)
  4. Expand URLs.
  5. Configure the Learn, Alarm, and Block settings for the Illegal URL violation, as required.
  6. Select Save.
  7. Select Apply Policy.
