Description

The BIG-IP ASM system can mitigate Predictable Resource Location attacks by using appropriate attack signatures or defined meta-characters. 

Predictable Resource Location attacks, also known as forced browsing attacks, target hidden content and functionality of a web application. By guessing common names for directories or file names, the attacker may be able to access resources that are not linked to the main web application. A Predictable Resource Location attack is a common attack against a web application and targets hidden content and functionality of a web application. By guessing common names for directories or file names, the attack can uncover hidden parts that are not linked to the main web application, such as an administrative directory of files that are not publicly published.

Common examples

  • /backup
  • /logs/
  • 2019.report.html
  • temp_login.html

Note: Attackers can also use Brute Force attacks on directories and file names, which is different from login Brute Force.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • Access to the BIG-IP ASM Configuration utility.

Procedures

  • Add Predictable Resource Location attack signatures to the policy
  • Enable and enforcing the Predictable Resource Location signatures
  • Switch the policy to Blocking mode
  • Verify that Predictable Resource Location attacks are blocked

To watch a video demo of these procedures, go to  Use BIG-IP ASM to mitigate Predictable Resource Location attacks.

Add Predictable Resource Location attack signatures to the policy

Impact of procedure: Adding attack signatures to the security policy can generate false positives. For example, known false positives for Predictable Resource Location can occur due to the presence of English words such as “select” and “from” in the HTTP request. In these cases, you should remove false positives from the Traffic Learning page by accepting any learning suggestions for disabling the signature.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under Policy Building Settings, select Attack Signatures.
  4. Under the Attack Signatures table, select Change.
  5. Select the Predictable Resource Location Signatures check box, and then select Change.
  6. Select Save.
  7. Select Apply Policy.

Enable and enforcing the Predictable Resource Location signatures

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under Policy Building Settings, select Attack Signatures.
  4. For the Predictable Resource Location Signatures set, select Change Signature Properties and then select Enforce and Enable all Attack Signatures in the Signature Set.
  5. Under the attack signatures list, clear the Enable Signature Staging check box.
  6. Select Save.
  7. Select Apply Policy.

Switch the policy to Blocking mode

  1.  Go to Security > Application Security > Policies List.
  2. Select the policy.
  3. Under Learning and Blocking, for Enforcement mode, select Blocking.
  4. Select Save.
  5. Select Apply Policy 

Verify that Predictable Resource Location attacks are blocked

  1. Log in to the Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select the filter icon.
  4. For Attack Type, select Predictable Resource Location, and then select Apply Filter.
  5. Locate Attack Signature Detected violations and determine if the requests were blocked due to Predictable Resource Location attacks.
