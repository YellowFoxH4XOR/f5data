K000152494: Virtual Edition Upgrade failed to 17.5.1 using Azure Hypervisor

Type
Support Solution
Published
2025-07-09
Updated
2025-07-09
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000152494

Description

After upgrading a BIG-IP Virtual Edition (VE) instance in Azure to version 17.5.1, the device may become inoperative, with the Traffic Management Microkernel (tmm) service repeatedly restarting. The following error may be observed in the logs:

<hostname>.azure.com notice sock(1.1)[00:e1.0]: Waiting for tmm1 to reach state 4...

<hostname>.azure.com crit tmm1[22062]: 01010020:2: MCP bulk Connection aborted, exiting

<hostname>.cloudapp.azure.com crit tmm1[22062]: 01010020:2: MCP Connection aborted, exiting

 

Environment

- Product: BIG-IP AFM

- Version: 17.5.1

- Platform: F5-BIG-LTM-VE-1G-V18, BIG-IP VE deployed in Microsoft Azure

- Provision: Virtual Edition (VE) running in Azure cloud environment

 

Cause

This issue is triggered by known problem ID1292345, explained in K000151341: Device INOPERATIVE with TMM restarting loop in Azure VE instance affecting BIG-IP VE instances in Azure after an upgrade to version 17.5.1. The tmm process enters a restart loop due to an underlying issue with the virtual machine state that is not resolved by a standard reboot.

 

Recommended Actions

To resolve the issue, perform a full shutdown and restart of the affected BIG-IP VE instance from the Azure portal. A simple reboot is not sufficient. Follow these steps:

1. Log in to the BIG-IP VE instance and run:

shutdown -h now

2. In the Azure portal, locate the affected VE instance.

3. Stop the VE instance from the Azure portal.

4. Wait at least 2 minutes to ensure the instance is fully powered down.

5. Start the VE instance from the Azure portal.

 

This process resets the virtual machine state and allows the tmm service to start normally.
