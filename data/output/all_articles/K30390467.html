Description

You need to update the certificate bundle before the current certificate expires.

Environment

You add the new certificate to the bottom of the bundle via the text import option

  • The current certificate hasn't expired
  • Server Certificate is set to "request" in the server SSL profile
  • This bundle is applied as the "Trusted Certificate Authority"
  • The application server updates its certificate

Cause

The Subject is the same in both certificates. Matching is on a First-Match basis so the Big-IP selects the top certificate, but then the signature/signing information doesn't match what the server sent.

Recommended Actions

Utilize a certificate chain where the intermediate certificate signs each server certificate. The Intermediate certificate then authenticates any of the server certificates it has issued.

  1. Create a root certificate authority (CA) and import it onto the Big-IP since it is the client.
  2. Create intermediate certificates that are signed by this root CA.
  3. Import these intermediate certificates onto the Big-IP and add them to the certificate bundle in the server SSL profile.
  4. Sign each server certificate with this intermediate certificate.

Additional Information

The Intermediate certificate typically has a longer lifespan so will continue to validate certificates, even after server certificates are renewed, as long as these new certificates signed by this Intermediate certificate.

Command to check the subject & issuer of certificates:

  • openssl x509 -noout -text -in /config/filestore/files_d/Common_d/certificate_d/:Common:<cert_bundle_name_here>_xxxxxx_x
