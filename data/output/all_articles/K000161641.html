Description

Config sync between BIG-IP LTM devices fails after a GUI/httpd certificate is changed or renewed. The sync operation returns a validation error, and the peer device's GUI becomes inaccessible due to the httpd service being down.

Error message below:

Sync error on <peer-device>: Load failed from /Common/<source-device>
01070920:3: Application error for confpp:
[core:warn] AH00114: Useless use of AllowOverride in line 283 of /var/run/config/httpd.conf.
[core:warn] AH00114: Useless use of AllowOverride in line 12 of /etc/httpd/conf.d/xui.conf.
Syntax OK
unable to load certificate
error:0906D06C:PEM routines:PEM_read_bio:no start line:pem_lib.c:697:Expecting: TRUSTED CERTIFICATE
/usr/bin/openssl command failed.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.x
  • Configuration: High Availability (HA) pair with config sync enabled
  • Recent Change: GUI/httpd SSL certificate was recently renewed or replaced on one or both of the HA peer devices

Cause

The SSL certificate file (server.crt) and/or private key file (server.key) on the peer device became corrupted after a certificate renewal. Specifically, the required PEM header strings were truncated (e.g., -----BEGIN CERTIFICATE----- was reduced to N CERTIFICATE-----), causing the httpd service to fail to start and preventing config sync from completing.

Recommended Actions

  1. Verify whether the GUI of the peer device is accessible. If not, check the httpd service status via CLI:
    bigstart status httpd
  2. Attempt to start httpd and observe the error output:
    bigstart start httpd
  3. Inspect the server.crt file for corruption:
    cat /config/httpd/conf/ssl.crt/server.crt
    • Verify the file begins with the correct PEM header: -----BEGIN CERTIFICATE-----
    • If the header is truncated (e.g., N CERTIFICATE-----), manually edit the file and restore the full header string.
  4. Inspect the server.key file for similar corruption:
    cat /config/httpd/conf/ssl.key/server.key
    • Verify the file begins with the correct PEM header: -----BEGIN RSA PRIVATE KEY----- (or equivalent)
    • If initial characters are missing, manually restore them.
  5. If certificate or key file is damaged (not just the headers), generate a new certificate and key pair. Steps can be found in K000140327
  6. After correcting both files, restart the httpd service:
    bigstart restart httpd
  7. Confirm httpd starts successfully without errors.
  8. Initiate a config sync from the BIG-IP Configuration Utility or via tmsh and verify it completes successfully.

Additional Information

  • The corruption of certificate/key files may occur during a certificate renewal or replacement process if the file write operation is incomplete or interrupted.
  • Both server.crt and server.key should be inspected, as either or both may be affected.
  • A corrupted httpd certificate not only prevents GUI access on the affected device but also blocks config sync operations across the HA pair, as the sync process relies on httpd being operational on all peer devices.
