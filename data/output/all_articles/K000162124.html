K000162124: Incorrect available tenant resources reported for newly added VELOS BX520 blade

Support Solution
Published

Updated
2026-07-07
Applies to

  • F5OS-C: 1.8.X, 1.8.2, 1.8.1, 1.8.0
Source

Description

After adding a BX520 blade to a VELOS chassis with a running partition, the available tenant resources reported in the partition GUI or show cluster command are incorrect.

For example:

state node-info available-tenant-vcpu 22
state node-info available-tenant-memory 101292MB
state node-info available-tenant-disk 700GB

Values may also be reported as all 0 for the blade, despite there being available resources:

state node-info available-tenant-vcpu 0
state node-info available-tenant-memory 0MB
state node-info available-tenant-disk 0GB

Environment

  • BX520 blade added to a chassis with a running partition

Cause

  • Bug ID 2346965: Incorrect available resources reported for newly added BX520 blade

This is a cosmetic issue that causes the system to initially report BX110 resources for the BX520 blade. If you have created a tenant with more resources than a BX110 blade could accommodate, available resources will incorrectly be reported as 0.

Recommended Actions

The issue can be cleared by restarting the orchestration agent container on the controller that is running-active for the partition:

docker container restart partition<id>_TPOB
