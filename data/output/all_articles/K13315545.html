Topic

You should consider using this procedure under the following condition:

  • You want to use BIG-IP ASM to protect a BIG-IP APM login page from brute force attacks.

Description

By default, when BIG-IP APM is configured with BIG-IP ASM, BIG-IP APM receives and processes traffic before BIG-IP ASM does.

To use BIG-IP ASM brute force protection with BIG-IP APM, you need to create a layered virtual server to allow BIG-IP ASM to trigger before traffic arrives at the BIG-IP APM login page. This article outlines how to do this.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your system has BIG-IP APM and BIG-IP ASM provisioned and licensed.
  • You have BIG-IP APM set up with a login page on a virtual server. For example: /my.policy.

    Note: This configuration applies only when BIG-IP ASM and BIG-IP APM virtual servers both reside on the same BIG-IP system. For other scenarios, additional configuration may be required.

Procedures

  • Creating an iRule for a BIG-IP ASM layered virtual server
  • Creating a layered virtual server
  • Creating a BIG-IP ASM security policy and applying it to the layered virtual server
  • Configuring BIG-IP ASM settings for the BIG-IP APM login page
  • Configuring brute force attack protection
  • Enabling blocking for brute force attack protection
  • Updating DNS records to route traffic through the BIG-IP ASM layered virtual server

Creating an iRule for a BIG-IP ASM layered virtual server

Create an iRule to point your BIG-IP ASM layered virtual server to the BIG-IP APM virtual server you've configured with a BIG-IP APM login page.

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Type the name of the iRule and enter the following iRules text to the Definition box.

    Note: In the following iRule, replace <apm_vip> with the name of the BIG-IP APM virtual server.

    when CLIENT_ACCEPTED {
        virtual <apm_vs_name>
    }

  5. Click Finished.

Creating a layered virtual server

Create a BIG-IP ASM layered virtual server to intercept and process traffic before it gets to the BIG-IP APM virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click Create.
  4. Under General Properties, for Name, type the name of the BIG-IP ASM virtual server.
  5. For Address, type the IP address of the virtual server.
  6. For Service Port, type the listening port number of the virtual server.
  7. Under Configuration, for HTTP Profile, click the appropriate HTTP profile.
  8. For SSL Profile (Client), in the Available box, click an appropriate profile and move it to the Selected box.
  9. For SSL Profile (Server), in the Available box, click the default serverssl and move it to the Selected box.
  10. For Source Address Translation, click Auto Map.
  11. Under Resources, for iRules, click the iRule you created in the previous procedure in the Available box and move it to the Enabled box.
  12. Click Finished.

Configuring BIG-IP ASM settings for the BIG-IP APM login page

Follow this procedure to define the login page that BIG-IP ASM protects and the URLs that define the BIG-IP APM login page.

Note: For security reasons, you should only use HTTPS URLs for login pages.

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Sessions and Logins > Login Pages List.
  3. Click Create.
  4. Under Login Page Properties, for Login URL click Explicit, click HTTPS and type the name of the BIG-IP APM login page you want to protect.
  5. For Authentication Type, click HTML Form.
  6. For Username Parameter Name, type the static user name parameter written in the code of the HTML form.
  7. For Password Parameter Name, type the static password parameter written in the code of the HTML form.
  8. Under Access Validation, for A string that should not appear in the response, type The user name or password is not correct. Please try again.
  9. For Expected HTTP response code, type 302.
  10. Click Create to save the configuration.

Note: The steps for this procedure are outlined in the Creating Login Pages for Secure Application Access chapter of the BIG-IP Application Security Manager: Implementations manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Configuring brute force attack protection

Perform this procedure to define the Brute Force Attack Prevention settings and thresholds on the login page.

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Anomaly Detection > Brute Force Attack Prevention.
  3. Click Create.
  4. Under Brute Force Protection Configuration, for Login Page, click the name of the page you previously created in the previous procedure.
  5. Under Source-based Brute Force Protection (BIG-IP ASM 13.1.0 and later) or Session-based Brute Force Protection (versions prior to BIG-IP ASM 13.1.0), configure the settings to meet your needs. For more information, refer to the following article, as appropriate for your system version:
    • K18650749: Configuring brute force attack protection (13.1.0 and later)
    • K54335130: Configuring brute force attack protection (12.1.2 - 13.0.x)
  6. Click Create to save the configuration.

Enabling blocking for brute force attack protection

To enable brute force attack prevention on your BIG-IP ASM virtual server, perform one of the following procedures, as appropriate for your BIG-IP system version:

Impact of procedure: Performing the following procedure should not have a negative impact on the system.

BIG-IP 12.x and later

  1. Log in to the Configuration utility
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. For General Settings, click Advanced.
  4. For Enforcement Mode, click Blocking.
  5. Click Sessions and Logins to expand the settings.
  6. For Brute Force: Maximum login attempts are exceeded, select the check boxes for Alarm and Block.
  7. Click Save.

BIG-IP 11.x

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Blocking > Settings.
  3. Under Violations List, for Enforcement Mode click Blocking.
  4. Under Input Violations, for Brute Force: Maximum login attempts are exceeded, select the check boxes for Alarm and Block.
  5. Click Save.

Updating DNS records to route traffic through the BIG-IP ASM layered virtual server

Impact of procedure: After DNS record updates are complete, traffic routes through the BIG-IP ASM layered virtual server, pointing to the BIG-IP APM virtual server. The brute force prevention applied to the BIG-IP ASM layered virtual server protects the traffic that passes through to the BIG-IP APM login page.

Contact the administrator who handles your DNS records, and request an update to the BIG-IP APM DNS records so that they point at the new, BIG-IP ASM layered virtual server that you've created in front of the BIG-IP APM virtual server.
