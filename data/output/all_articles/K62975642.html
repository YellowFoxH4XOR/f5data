Known Issue

Virtual Clustered Multiprocessing (vCMP) guests may fail to deploy after the vCMP host reboots.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is either:
    • A VIPRION system with two or more blades installed
    • A vCMP guest instance is configured to deploy across multiple blades
  • The VIPRION system is licensed and provisioned as a vCMP host (hypervisor).
  • The vCMP host has restarted.

Impact

One or more deployed vCMP guest instance fails to enter the deployed state after the host restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice traffic is not being processed by one or more vCMP guests after a vCMP host reboot.
  • You notice one or more vCMP guest instances has failed to deploy after a vCMP host restart.
  • In the /var/log/confpp.log file of the host, you notice an error message similar to the following example:

    confpp[6789]: rollback FAILED for 'unix_config_syslog'

Workaround

There is no workaround. This issue occurs due to the syslog-ng process restarting a second time after the host reboot, which impacts the Master Control Program Daemon's (MCPD) ability to properly deploy the vCMP guest. If the vCMP host does not fully recover, and you are unable to deploy the vCMP guest, gather a QKView file from the vCMP host and open a case with F5 Technical Support for further troubleshooting assistance.
