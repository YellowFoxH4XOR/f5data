Topic

When you insert a VIPRION blade installed with BIG-IP 11.5.3 or earlier to an existing VIPRION system that is running a BIG-IP point release, the VIPRION system does not automatically upgrade the newly inserted blade. It is possible that the replacement blade you received as a result of a Service Order may experience this behavior.

Description

Typically when you add a VIPRION blade to an existing VIPRION system, the system automatically copies software images from the primary blade to the newly inserted blade and installs the software, as well as the configuration, to the newly inserted blade. This behavior ensures that the software images for each boot location match the other blades in the cluster. For more information, refer to K13965: Overview of the automated process of joining a newly installed or RMA replacement VIPRION blade to the cluster.

Due to a limitation, when you insert a blade that is installed with BIG-IP 11.5.3 or earlier into a VIPRION system running a BIG-IP point release version, the newly inserted blade cannot recognize the BIG-IP point release version running in the system. As a result, the blade does not upgrade its software to match the system and remains in an inoperative state. For example, when you insert a blade installed with BIG-IP 11.5.3 into a VIPRION system running BIG-IP 13.1.0.5, the newly inserted blade does not upgrade its software to BIG-IP 13.1.0.5 and remains in an inoperative state. For more information about BIG-IP point releases, refer to K8986: F5 product support policies.

You may experience this limitation when you receive a replacement blade from F5 as a result of a service order (RMA) from a Forward Stock Location (FSL)/Service Location. A replacement blade from a FSL/Service Location is typically a result of an RMA-4 (four-hour RMA) or Next Business Day (NBD) replacement.

You may observe repeating log messages in the /var/log/ltm file on the newly inserted blade that appear similar to the following examples:

Recommended action

To upgrade the newly inserted blade and join it with the VIPRION system, F5 recommends that you manually copy the desired BIG-IP image ISO file to the newly inserted blade and perform a software installation on the newly inserted blade using the image2disk utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. As a precautionary measure, you should back up BIG-IP configuration files on the VIPRION system and transfer the created user configuration set (UCS) file to another location. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive. For information about transferring the UCS file to another location, refer to K175: Transferring files to or from an F5 system.
  2. Log in to the primary blade of the VIPRION system using the secure shell (SSH) or serial console with a privileged user, such as root.
  3. Locate the desired BIG-IP ISO image file in the /shared/images directory on the primary blade and copy it to the newly inserted blade using the following command syntax:

    scp /shared/images/<BIG-IP ISO image file name> root@<newly inserted blade slot>:/shared/images

    For example, you have BIGIP-13.1.0.5-0.0.5.iso in the /shared/images directory and you want to copy this ISO image file to the newly inserted blade in slot 2, type the following command:

    scp /shared/images/BIGIP-13.1.0.5-0.0.5.iso root@slot2:/shared/images/

    Note: You can safely ignore the following error message:

    error: mcpd never came up... using /config/BigDB.dat.

  4. Log in to the newly inserted blade through the primary blade using the following command syntax:

    ssh slot<X>

    For example, to log in to the newly inserted blade in slot 2, type the following command:

    ssh slot2

    Important: Ensure that you log in to the correct blade by verifying the prompt; it should report INOPERATIVE like the following example:

    [root@VIP2400:/S1-green-P::Active:Standalone] config # ssh slot2
    Last login: Tue May 8 14:26:39 2018 from 127.3.0.1
    [root@localhost:/S2--S:INOPERATIVE:] config #

  5. Perform a manual software installation using the image2disk utility on the newly inserted blade using the following command syntax:

    image2disk --format=volumes --nosaveconfig /shared/images/<desired ISO image file name>

    Using the previous examples, to install BIG-IP 13.1.0.5 on the newly inserted blade, type the following command:

    image2disk --format=volumes --nosaveconfig /shared/images/BIGIP-13.1.0.5-0.0.5.iso

  6. Wait for the blade to reboot into MOS, reformat its disk, and complete its installation of the specified BIG-IP version. To monitor the progress of the manual installation, you will need to connect to the serial console. For VIPRION B4xx0 blades (B4200, B43x0 and B4450), you may be able to monitor the serial console using the bladectl command syntax:

    bladectl -b <slot number> -c

    For example, to monitor the serial console of the newly inserted blade in slot 2, type the following command:

    bladectl -b 2 -c

    Note: The bladectl utility may not be as reliable as a physical serial console connection and may report errors, such as failed: Unable to capture blade 2 console. The B21x0 and B2250 blades do not support console port redirection.

  7. Once the installation completes, the blade will boot into the installed version and initiate the process of joining the VIPRION cluster. The VIPRION system may initiate further software installations and/or reboots while it attempts to ensure that the newly inserted blade is installed with the BIG-IP versions in boot locations that are the same as the rest of the blades in the cluster.
