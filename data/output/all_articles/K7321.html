Known Issue

This is the result of a known issue. Enabling or disabling compression in the HTTP profile when ramcache is enabled causes HTTP to attempt to free an invalid pointer, crashing the TMM process.

F5 Networks Product Development tracked this issue as CR77092, and it was fixed in BIG-IP LTM versions 9.1.3, 9.3.1, and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.
