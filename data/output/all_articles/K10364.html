K10364: A place rule fails with a STATUS_NOT_SAME_DEVICE error message

Topic

When using a place-rule to migrate files and directories from a fileset whose path starts from a qtree, and the source filer share has the migrate retain-files setting enabled, the rule will fail with the following error message:

:1-1-ACM-7881:TRANFS-2-4-MSG4:: cifsx_rename failed from /data/images/image1.tif at <\\10.10.10.1\share$> to /~acopia_msnap/data/images/image1.tif at <\\10.10.10.1\share$> - STATUS_NOT_SAME_DEVICE

The error message is returned by a filer when an attempt is made to rename a file across devices that cannot be successfully renamed across.

When the migrate retain-files setting is enabled for a filer share, the ARX system requires the ability to create a migrate archive directory at the share root. However, it is not possible if the share spans multiple devices or qtrees. You must either disable the migrate retain-files setting or import at the qtree boundary.
