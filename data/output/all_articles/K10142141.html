Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP Virtual Edition (VE) system to use the SOCK network driver.

Description

You can configure the BIG-IP VE system to use the SOCK driver instead of the default network driver. To do so, perform the following procedure.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP VE system.
  • BIG-IP VE is not in Azure.

Procedures

Configuring the BIG-IP VE system to use the SOCK network driver

Impact of procedure: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the VE instance. Network traffic is disrupted while the system restarts.

Important: The /config/tmm_init.tcl file is not included with a configuration synchronization (ConfigSync); you must perform the procedure on each device individually. For members of a high availability (HA) device group, you must perform the following procedure on each member of the device group. Additionally, the procedure must be performed for each boot location you want to boot to.

  1. Log in to the BIG-IP command line.
  2. To locate the ethernet controller vendor/device ID, enter the following command:

    lspci -nn | grep -i eth

    For example, the following output shows 15ad:07b0 for vendor/device ID:

    03:00.0 Ethernet controller [0200]: VMware VMXNET3 Ethernet Controller [15ad:07b0] (rev 01)
    0b:00.0 Ethernet controller [0200]: VMware VMXNET3 Ethernet Controller [15ad:07b0] (rev 01)
    13:00.0 Ethernet controller [0200]: VMware VMXNET3 Ethernet Controller [15ad:07b0] (rev 01)
    1b:00.0 Ethernet controller [0200]: VMware VMXNET3 Ethernet Controller [15ad:07b0] (rev 01)

  3. To display the current configuration (available_drivers and driver_in_use), enter the following command:

    tmctl -d blade tmm/device_probed

    The output appears similar to the following example:

    pci_bdf      pseudo_name type      available_drivers     driver_in_use
    ------------ ----------- --------- --------------------- -------------
    0000:03:00.0             F5DEV_PCI sock, vmxnet3, unic,
    0000:0b:00.0 1.1         F5DEV_PCI sock, vmxnet3, unic,  vmxnet3
    0000:13:00.0 1.2         F5DEV_PCI sock, vmxnet3, unic,  vmxnet3
    0000:1b:00.0 1.3         F5DEV_PCI sock, vmxnet3, unic,  vmxnet3

  4. To append the device driver assignment line to the /config/tmm_init.tcl file, use the following command syntax:

    Note: If the /config/tmm_init.tcl file does not already exist, this command creates it and adds the following line.

    echo "device driver vendor_dev <vendor_dev_ID> sock" >> /config/tmm_init.tcl

    For example, to append the SOCK driver with vendor/device ID 15ad:07b0, enter the following command:

    echo "device driver vendor_dev 15ad:07b0 sock" >> /config/tmm_init.tcl

  5. If your BIG-IP VE is not on AWS Cloud, skip to step 6.

    Perform this step only for BIG-IP VE on AWS.

    Disable the force_sw_tcs flag by entering the following command:

    Note: The force_sw_tcs flag is used to improve performance with the XNet DPDK/ENA driver on AWS.

    echo "ndal force_sw_tcs off 1d0f:ec20" >> /config/tmm_init.tcl

    In the previous command, 1d0f:ec20 is the AWS vendor/device ID.

  6. Reboot the BIG-IP VE instance by entering the following command:

    reboot

  7. After the system reboot, confirm the driver in use by examining the output of the following command:

    tmctl -d blade tmm/device_probed

    The output appears similar to the following example:

    pci_bdf      pseudo_name type      available_drivers     driver_in_use
    ------------ ----------- --------- --------------------- -------------
    0000:03:00.0             F5DEV_PCI sock, vmxnet3, unic,
    0000:0b:00.0 1.1         F5DEV_PCI sock, vmxnet3, unic,  sock
    0000:13:00.0 1.2         F5DEV_PCI sock, vmxnet3, unic,  sock
    0000:1b:00.0 1.3         F5DEV_PCI sock, vmxnet3, unic,  sock
