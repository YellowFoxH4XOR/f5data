K000162647: HA cluster not operational

Type
Support Solution
Published
2026-07-29
Updated
2026-07-29
Applies to

Source
https://my.f5.com/manage/s/article/K000162647

Description

Can not create HA between BIG-IP Tenants, constantly getting when trying to add the device trust members:


Jul 27 19:47:12 f5-tenant1 info tmm1[12495]: CMI peer 1.1.1.5 certificate rejected, error 19: self signed certificate in certificate chain

 

Environment

BIG-IP LTM

Tenant

 

Cause

The trust certificates changed possibly during the UCS load or load default config. The issue is a mismatch between the certificate/key combinations configured in /config/bigip_base.conf and the cert/key pairs in the file store.


Looking closely at the ltm logs:


Jul 27 20:48:33 f5-tenant1 crit tmm[12788]: 01260029:2: Profile _ha_cgc_serverssl - /config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_128898_4 reading: Unknown error.

Jul 27 20:48:33 f5-tenant1 crit tmm[12788]: 01260030:2: Profile _ha_cgc_serverssl - cannot load key/cert/chain: /config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtdi.key_128892_3//config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtdi.crt_128890_5//config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_128898_4: Unknown error.


 

Answer/Recommended Actions

1) You can run these commands from bash to confirm what certificates and keys exist in the BIG-IP:


[root@BIG-IP-17-1A:Active:Standalone] config # ls -l config/filestore/files_d/Common_d/trust_certificate_d/

:Common:dtca-bundle.crt_128898_5

:Common:dtca.crt_128894_5

:Common:dtdi.crt_128890_5


[root@BIG-IP-17-1A:Active:Standalone] config # ls -l /config/filestore/files_d/Common_d/trust_certificate_key_d/

:Common:dtca.key_128896_5

:Common:dtdi.key_128892_6


2) As you can from the Cause logs the configuration is trying missing the files:

/config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_128898_4

/config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtdi.key_128898_3


3) Then you can just rename the existing certificates and key with the missing ones, i.e:


cp /config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_128898_5 /config/filestore/files_d/Common_d/trust_certificate_d/:Common:dtca-bundle.crt_128898_4


cp /config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtdi.key_128892_6 /config/filestore/files_d/Common_d/trust_certificate_key_d/:Common:dtdi.key_128892_3


4) Load the config (Impact: configuration will reload)

tmsh load sys config


5) Reload mcpd (Impact: BIG-IP will reboot)


touch /service/mcpd/forceload

reboot
