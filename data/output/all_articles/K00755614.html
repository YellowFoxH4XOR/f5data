Issue

Description

NTLM Single Sign On (SSO) fails when BIG-IP APM is configured for NTLM Authentication or Kerberos Authentication. 

  • You observe the following log messages in /var/log/apm:
err websso.2[PID]: 014d0027:3: /Common/<access_policy>:Common:<sessionID>: Could not find SSO password for user '<username>'

In this error message note the following:

  • <PID> is the process ID for the websso process.
  • <access_policy> is the name of the affected access policy.
  • <sessionID> is the unique APM session identifier.
  • <username> is the username that failed to authenticate.

Environment

  • Access Policy configured to use NTLM as its SSO method
  • Access Policy configured to use NTLM or Kerberos Authentication
  • Access Policy Manager

Cause

This happens because BIG-IP APM does not have the user's password which is required for NTLM SSO (as well as other SSO Methods).

Recommended Actions

Configure the Access Policy to use a SSO method that is compatible with NTLM Authentication or Kerberos Authentication. For example Kerberos Constrained Delegation (Single Sign On) does not require a user's password. For information refer to the Configuring Kerberos Constrained Delegation deployment manual.

Additional Information

When deploying BIG-IP APM to use NTLM authentication (or Kerberos authentication) this can provide seamless (transparent) authentication for local clients. However since this requires no user input NTLM authentication (or Kerberos authentication) does not provide access to the user's password; therefore, NTLM Authentication is not compatible with SSO methods that requires the user password, such as NTLM (or Forms Based and Forms - Client Initiated).
