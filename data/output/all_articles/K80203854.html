Known Issue

The BIG-IP system may erroneously convert the IPv4 destination address of a health monitor into an IPv6 format during the software upgrade process.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is running 10.2.x.
  • You have a health monitor configured using an IPv4 wildcard (*) alias address with a specific alias service port (for example, port 80). The health monitor configuration may look similar to the following example:

    monitor http_test {
       defaults from http
       dest *:http
    }

    Note: The IPv4 destination address uses a colon (:) as a separator between the IP address and the port number.

  • You perform a software upgrade to one of the BIG-IP versions listed in the Applies to (see versions) box, located in the upper-right corner of this article.

Impact

There is no impact; the BIG-IP health monitor should function as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H553910 on the Diagnostics > Identified > Medium screen.
  • After the software upgrade you observe that the health monitor configuration in the /config/bigip.conf file displays the destination address in an IPv6 format. The configuration may look similar to the following example:

    ltm monitor http /Common/http_test {
        defaults-from /Common/http
        destination *.80
        interval 5
        ip-dscp 0
        send "GET /\\r\\n"
        time-until-up 0
        timeout 16
    }

    Note: An IPv6 destination address uses a period (.) as a separator between the IP address and the port number.

Resolution

Status

F5 Product Development has assigned ID 551349 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article.
