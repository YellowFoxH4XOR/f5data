Issue

Prior to BIG-IP LTM 9.4.2, the FastL4 profile used normal checksum methods performed by hardware (Network Interface level), and within software for IPv6 TCP and UDP packets. Due to the size and complexity of IPv6 headers, this method is CPU intensive (software side). As a result, packet drops and retransmissions can occur under high packet load.

The FastL4 profile now supports incremental checksum checks for IPv6 traffic, which allow for greater throughput and less CPU usage when handling large amounts of IPv6 TCP and UDP packets.

F5 Product Development tracked this issue as CR80569 and it was fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.
