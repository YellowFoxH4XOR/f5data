Description

It may sometimes be beneficial to identify the BIG-IP Edge Client version, a client is using to connect to BIG-IP APM, for example for troubleshooting purposes.

Note: If you need to identify a specific Client type during a user's login process, F5 recommends configuring the Endpoint Security (Server-Side)'s Client Type agent. For more information, refer to the About Client Type chapter in the BIG-IP Access Policy Manager: Visual Policy Editor manual.


This can be done by examining the APM logs looking for log events containing Received User-Agent header and EdgeClient, such as in the following example:

Jan 22 13:38:39 BIG-IP-01 notice tmm[18600]: 01490506:5: /Common/AccessPolicyExample:Common:ABCDEFG: Received User-Agent header: Mozilla%2f5.0%20(Windows%20NT%2010.0%3b%20WOW64%3b%20Trident%2f7.0%3b%20rv%3a11.0)%20like%20Gecko%20EdgeClient%2f7172.2018.1130.2122.

Note: The Edge Client version follows EdgeClient%2f. So in the example above, the version is 7172.2018.1130.2122.

Environment

Relevant environmental factors:

  • BIG-IP with APM Provisioned
  • Clients using BIG-IP Edge Client to access APM

Cause

None

Recommended Actions 

To examine the logs in order to identify the Edge Client version:

1. Create an iRule with below code and apply it to the virtual server

    when ACCESS_SESSION_STARTED {
         log local0. "Setting User-Agent based on HTTP data - [HTTP::header User-Agent]"
    }

2. Establish a Command line connection to the BIG-IP's Mgmt Interface using SSH.

Type bash and hit the Enter key.

3. Then run a search of the APM log file using the following command:

grep User-Agent /var/log/apm

The above command will output all log events, including the example type log event above, to the CLI.
