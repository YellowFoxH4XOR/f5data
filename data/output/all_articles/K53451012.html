Description
  • You need to restrict TLS version 1.1 from accessing the Configuration Utility.

Environment

  • BIG-IP Configuration Utility
  • tmsh access to the BIG-IP device

Cause

To increase the security of connections to the BIG-IP Configuration Utility

Recommended Actions

To modify which SSL Protocols are to be used when accessing the configuration please follow the below steps.

  1. Verify the current settings within the httpd configuration:
    1. # tmsh list sys httpd ssl-protocol
      sys httpd {
          ssl-protocol "all -SSLv2 -SSLv3 -TLSv1"
      }
      TLSv1.1 is not specified.
       
  2. Add TLSv1.1 to the ssl-protocol field within httpd
    1. # tmsh modify /sys httpd ssl-protocol "all -SSLv2 -SSLv3 -TLSv1 -TLSv1.1"
      Note: -TLSv1.1 was added to the end of the string
       
  3. Confirm the httpd ssl-protocol is updated with -TLSv1.1
    1. # tmsh list sys httpd ssl-protocol
      sys httpd {
          ssl-protocol "all -SSLv2 -SSLv3 -TLSv1 -TLSv1.1"
      }
       
  4. Restart the httpd process to update the daemon to use the new string
    Note: This will interrupt anyone connected to the BIG-IP Configuration Utility and cause them to login again.
    1. # tmsh restart sys service httpd
       
  5. Save the configuration:
    1. # tmsh save sys config
       
  6. Test the change from another linux device or from the peer BIG-IP:
    1. # openssl s_client -connect <mgmt IP>:443 -tls1_1
       
    2. This command should return an output similar to below showing the failure of the handshake to complete:
