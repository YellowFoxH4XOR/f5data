K000161262: ZoneRunner "Resolver returned no such record" Error When Viewing A Records Under Delegated Subdomain in BIG-IP DNS

Type
Support Solution
Published
2026-05-13
Updated
2026-05-13
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161262

Description

When using the BIG-IP DNS ZoneRunner GUI to create or view A records under a subdomain, the error message "Resolver returned no such record" is displayed. DNS queries for these records do not return the expected results, even though the zone file loads successfully and DNS services appear operational. This issue specifically affects A records under a subdomain that has NS delegation records within the parent zone file.

Environment

  • Product: BIG-IP DNS
  • Version: 17.1.3
  • ZoneRunner managing DNS zones
  • Zone file contains NS delegation records for a subdomain (e.g., gslb NS ns1, gslb NS ns2)
  • Example affected record: dev.gslb.example.com

Cause

NS delegation records for a subdomain within the parent zone file cause BIND to treat the subdomain as delegated. When ZoneRunner queries for A records under the delegated subdomain, BIND returns a referral (NS record) instead of an authoritative answer. This leads ZoneRunner to display the error "Resolver returned no such record" and prevents management of those A records in the GUI.

Answer/Recommended Actions

To resolve the issue and allow A records under the subdomain to be viewable and manageable in ZoneRunner:

  1. Freeze the Zone for Safe Editing
  2. bigstart stop zrd
  3. rndc freeze <zone_name> in external
  4. rndc sync -clean
  5. Edit the Zone File
  • Open /var/named/config/namedb/db.external.<zone_name>. in a text editor.
  • Remove the NS delegation records for the affected subdomain (e.g., lines like gslb NS ns1 and gslb NS ns2).
  1. Increment the SOA Serial Number
  • In the SOA record at the top of the file, increase the serial number by 1.
  1. Validate the Zone File
  2. named-checkzone <zone_name> /var/named/config/namedb/db.external.<zone_name>.
  • Ensure the output shows loaded serial ... OK with no errors.
  1. Thaw the Zone and Restart ZoneRunner
  2. rndc thaw <zone_name> in external
  3. bigstart start zrd
  4. Verify in the ZoneRunner GUI
  • Go to DNS ›› Zones : ZoneRunner : Resource Record List in the BIG-IP GUI.
  • Confirm that A records under the subdomain are now visible and manageable.
  1. Test DNS Resolution
  2. dig a <record_name> @localhost
  • Confirm that the ANSWER section contains the expected A record.

Additional Information

  • This error is expected behavior when NS delegation records are present for a subdomain within a ZoneRunner-managed zone. Removing these records allows ZoneRunner to manage and display A records under the subdomain.
  • If subdomain delegation is required, manage the delegated subdomain in a separate zone file.
