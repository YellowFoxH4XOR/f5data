Description

In this article we discuss the best practices to optimize the control plane performance and potentially reduce resources utilization.

 

Environment

Aspen Mesh 1.11.x and Aspen Mesh 1.14.x

 

Cause

The resource usage and performance of the control plane can be impacted by:

 

[1] Rate of Changes: A higher rate of changes means more processing is needed to keep the data plane synchronized.

[2] Allocated Resources: If the demand exceeds the resources allocated to istiod, work gets queued, resulting in slower distribution of updates.

[3] Number of Workloads to Update: More processing power and network bandwidth are required to distribute updates to a greater number of workloads.

[4] Configuration Size: Larger Envoy configurations require more processing power and network bandwidth to distribute. 

 

Recommended Actions

consider the following solutions: 

 

[1] Allocating Additional Resources:

You can scale out the istiod deployment to reduce load by splitting the number of workloads managed among pilot instances. You can also scale up the istiod deployment to speed up the generation of the Envoy configuration and enable the processing of more push requests concurrently. 

 

[2] Using the Sidecar Resource:

By defining a sidecar configuration, we inform the control plane about the relevant configuration for a workload. This has the advantage of reducing the configuration size sent to a service proxy and also reduces the number of proxies updated for a single event.

apiVersion: networking.istio.io/v1beta1
kind: Sidecar
metadata:
 name: default
 namespace: prod
spec:
 workloadSelector:
  labels:
   app: foo
 egress:
 - hosts:
  - "./bar.prod.svc.cluster.local"
  - "istio-system/*" 

In this example:

workloadSelector limits the workloads to which the sidecar configuration applies.

ingress specifies the handling of inbound traffic to the application. If omitted, Istio configures the service proxy automatically by looking up the Pod definition.

egress specifies the handling of the application's outbound traffic through the sidecar. If omitted, the configuration inherits the egress configuration from a more generic sidecar.

 

When a Sidecar resource applies to a workload, the control plane uses the egress field to determine which services the workload requires access to, allowing only relevant configurations and updates to be sent to respective proxies. This approach reduces CPU, memory, and network bandwidth consumption. 

 

Additional Information

Note that sidecar configurations can be applied on different scopes:

Mesh-wide sidecar configurations apply to all workloads within the mesh.

Namespace-wide sidecar configurations override mesh-wide configurations and apply to all workloads within a namespace.

Workload-specific sidecar configurations target specific workloads that match the workloadSelector property, and override both mesh-wide and namespace-wide configurations.
