Topic

Important: The information in this Solution applies to versions of FirePass software prior to version 6.0.2 with Cumulative Hotfix HF-602-6. Starting in FirePass version 6.0.3 and version 6.0.2 with Cumulative Hotfix HF-602-6, the Portal Access reverse-proxy engine supports the HTTP/1.1 protocol for communicating with back-end web application servers. For more information, refer to K9105: Change in behavior: Added back-end HTTP/1.1 support to reverse-proxy engine.

The FirePass controller reverse-proxy engine supports both HTTP/1.0 and HTTP/1.1 client requests. The reverse-proxy engine proxies the HTTP/1.0 or HTTP/1.1 request from a client, and then sends an HTTP/1.0 request to the back-end web application server. Most HTTP/1.1 web servers are designed to accept both HTTP/1.0 and HTTP/1.1 requests; in typical configurations, the back-end web application server should be able to respond to the HTTP/1.0 request from the FirePass controller.

If your web application server cannot process HTTP/1.0 requests, or if you configure a network device such as an application-aware firewall to block HTTP/1.0 requests, users will be unable to access the web application through the Portal Access reverse-proxy engine.

Workaround

You can work around this issue by ensuring that your web application server accepts HTTP/1.0 requests from the FirePass controller. Additionally, ensure that all network devices that filter HTTP traffic to the web application server allow HTTP/1.0 requests from the FirePass controller.

If you do not want to allow HTTP/1.0 requests to your web application server, or if your web application server cannot process HTTP/1.0 requests, you can bypass the Portal Access reverse-proxy engine by performing the following procedure:

Important: Bypassing the Portal Access reverse-proxy engine can impact the security of your network. Additionally, internal URLs will not be rewritten, which may prevent clients from accessing some or all web application data. For more information, refer to K7001: Security implications of Portal Access options that turn off URL rewriting.

  1. Log in to the FirePass Administrative Console.
  2. Navigate to the Portal Access: Web Applications: Master Group Settings page.
  3. In the Master Group drop-down menu, select the Master Group you want to configure.
  4. In the Split Tunneling section, select the Use URL patterns for split tunneling check box.
  5. In the Bypass: text box, enter a list of URLs or URL match patterns for your HTTP/1.1 web applications.

    For example:

    http://www.siterequest.com/webapp1.html
    http://www.siterequest.com/webapp2.html
    http://apps.siterequest.com/apps/*
  6. If the Use URL patterns for split tunneling check box was already selected before you began this procedure, skip this step and proceed to Step 7. Otherwise, perform one of the following two steps, depending on which version of FirePass you are running:

    • If you are running FirePass version 6.0.0 or later, select Rewrite in the Default action: drop-down menu.

    • If you are running FirePass version 5.5.2 or earlier, enter * (asterisk) in the Rewrite: text box.
  7. Click the Update button.

Repeat Steps 3 through 7 for each Master Group you want to configure.
