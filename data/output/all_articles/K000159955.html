Description

Intermittent SSL certificate errors occur on BIG-IP LTM virtual servers after the expired certificate was renewed. In some connections, clients still receive a “certificate expired” warning.

Environment

  • BIG-IP LTM

Cause

The root cause is unsynchronized certificate configuration between the active and standby BIG-IP LTM devices. After the certificate is renewed on the active unit, the standby unit does not receive the updated certificate because configuration sync was not performed. This can happen when the BIG-IP sync configuration is set to manual, and not automatic. As a result, the standby continues to present the old (expired) certificate, leading to intermittent SSL handshake failures when traffic hits that device.

Recommended Actions

To resolve and prevent this issue when configuration changes occur, perform the following actions:

1. Verify HA Sync Status:

tmsh show /cm sync-status

Check for "Changes Pending" status, which indicates unsynchronized configuration.

2. Perform a manual configuration Sync:

From the active BIG-IP device, perform a configuration sync to the standby device:

  • GUI Method: Navigate to Device Management > Overview, select the device group, choose Sync Device to Group, and click Sync.
  • CLI Method:
    tmsh run cm config-sync to-group <device-group-name>

3. Verify Certificate Consistency:

a. Confirm that certificate serial numbers and metadata match on both devices:

tmsh list /sys file ssl-cert <certificate-name>

b. Check certificate files exist on both devices in 

/config/filestore/files_d/Common_d/certificate_d/

4. Remove Old or Unused Certificates:

Review and remove outdated certificates from both devices to prevent confusion:

tmsh delete /sys file ssl-cert <old-certificate-name>
tmsh delete /sys file ssl-key <old-key-name>

5. Enable Auto-Sync (optional)

Consider configuring the device group to automatic sync instead of manual sync. So future changes will apply automatically to the other pair.
