Issue

Old Behavior

In versions earlier than iWorkflow 2.1.0, when iWorkflow discovers a BIG-IP system with iApps application templates, the iWorkflow system imports the templates. The system makes the templates available so you can create and deploy services by way of the Cloud Connector. When you create new catalog templates, you can choose which Input Parameters to include; this is where the user can select Accept Defaults or Common Options for the seven common iApps templates. The value you set for Input Parameters limits the type of options that the tenant can configure for the application services they want. During the application service deployments, the iWorkflow system assumes that you have installed the same version of iApps in all managed BIG-IP systems. The iWorkflow system does not account for the BIG-IP system version-based restrictions.

New Behavior

Beginning in iWorkflow 2.1.0, you must directly import the iApps service templates into the iWorkflow system and include the template version details. When a cloud service provider creates the initial L4 - L7 services template (in versions prior to 2.1.0, this is the panel labelled as Catalog), the cloud service provider must review all the options and set the Application Tier Information parameters as required. These service templates can create the Child Service Template, which can display the Common Options that are based on the selections that the cloud service provider defined in the base template. These Child or Derivative Service Templates created from a base Service Template also offer the Accept Defaults view of configurable options. When you directly import a Child Service Template into the iWorkflow system, the template provides the configurable options Accept Defaults and Common Options for the Input Parameter options of its L4 - L7 services template.

Impact

  • All L4 - L7 services created with iWorkflow 2.0.x are preserved when you upgrade to 2.1.0 and later; however, you must create the services using new Service Templates.
  • L4 - L7 Service Templates that are in use are also preserved when you upgrade to 2.1.0, but you cannot use the templates to create new services or to reconfigure existing services. The associated iApps Templates and iApps Application Services on the BIG-IP system are unchanged during the upgrade process, but you cannot reconfigure them until you have migrated them to the new Service Templates.
  • After the upgrade, the Service Templates panel no longer includes Service Templates for which you did not create descendant services.
  • If the iWorkflow administrator did not remove the services, the iWorkflow tenants may be able to select L4 - L7 services that will not successfully deploy in iWorkflow 2.1.0 and later environments.

Recommended Actions

  • After you upgrade to iWorkflow 2.1.0, you must create new Service Templates and L4 - L7 services to replace those you previously created. To ensure that you are aware of this requirement, the system marks each service template as unhealthy, and displays a message indicating that you need to upgrade the template.
  • The iWorkflow tenant is required to migrate to the new Service Templates, and you should import supported versions of the F5 iApp templates from existing BIG-IP devices. For more information refer to F5 Downloads site and What is iWorkflow? on DevCentral.
