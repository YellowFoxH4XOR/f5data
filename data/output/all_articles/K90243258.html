Known Issue

BIG-IP ASM synchronization operations may fail for secondary cluster members in a VIPRION chassis.

This issue occurs when the following condition is met:

  • You create a new policy after making a series of other configuration changes in quick succession.

Impact

BIG-IP ASM security policy components or other configuration elements may be in an inconsistent state across VIPRION blades.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system logs error messages to the /var/log/asm file that appear similar to the following example:

    ----------------------------------------------------------------------
    asm_config_server.pl|ERR|Feb 22 03:07:46.059|28817|F5::SetActive::Impl::set_active,,Setting policy active failed: Failed on insert to DCC.ACCOUNT_CHARSET_TEMPLATES (DBD::mysql::db do failed: Cannot add or update a child row: a foreign key constraint fails (`DCC`.`ACCOUNT_CHARSET_TEMPLATES`, CONSTRAINT `ACCOUNT_CHARSET_TEMPLATES_ibfk_1` FOREIGN KEY (`account_id`) REFERENCES `ACCOUNTS` (`account_id`) ON DELETE CASCADE))
    ----------------------------------------------------------------------
  • Security policy components or other configuration elements are in an inconsistent state across VIPRION blades.

Resolution

Status

F5 Product Development has assigned ID 574451 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can force the system to synchronize to all blades in the chassis by making another system-wide configuration change, such as creating a user-defined attack signature. Alternatively, you can wait until the hourly synchronization occurs.
