Known Issue

When you change the Internet Key Exchange (IKE) IKEv1 auth algorithm to sha256, sha384, or sha512, the change does not take effect until you restart the system.

This issue occurs when the following condition is met:

  • When you change the ike-phase2-auth-algorithm attribute (inside an instance of the ipsec-policy) to a value of sha256, sha384, or sha512, a parse error occurs when the racoon daemon receives the attribute.

Impact

You cannot switch the IKEv1 ipsec-policy to sha256, sha384, or sha512 authentication without either restarting the BIG-IP system or restarting the tmipsecd process.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you change the IKEv1 phase2 authentication algorithm to sha256, sha384, or sha512, the new algorithm does not work without you restarting the tmipsecd process.

Workaround

To work around this issue, you can restart the tmipsecd process, which causes a restart of all racoon processes, which causes the system to re-read the configuration. Then IKEv1 IPsec works correctly with SHA authentication algorithms. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the tmipsecd service, type the following command:

    restart /sys service tmipsecd

  3. To exit tmsh, type the following command:

    quit
