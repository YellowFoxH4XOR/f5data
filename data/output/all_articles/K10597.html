Known Issue

This is the result of a known issue. If you delete RAM Cache entries while documents are being served from the cache, TMM will crash. When the RAM Cache is cleared, the size of the cache is forced to zero. If any documents were being served while the cache was being cleared, the subsequent deletion of the document causes the cache size to be erroneously reduced by the size of the document, resulting in a negative cache size. As a result, the TMM process crashes.

Note: For more information about displaying and deleting the contents of the RAM Cache from the BIG-IP command line, refer to K10200: Displaying and deleting RAM Cache entries.

F5 Product Development tracked this issue as CR129418 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

In addition, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
