K000139517: Attack signature 200004124 detected

Type
Support Solution
Published
2024-05-06
Updated
2024-05-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.1.4, 15.1.10, 17.1.1, 17.1.0, 15.1.9
Source
https://my.f5.com/manage/s/article/K000139517

Description

Requests containing the Authorization header with type Bearer are triggering the attack signature 200004124. The Authorization header should be checked and if this is a false positive appropriate action should be taken to allow the request.


Environment

  • ASM attack signatures
  • Authorization Header type Bearer

Cause

The Authorization header with type Bearer parsing for attack signatures was skipped in the past. This behavior is tracked by bug ID1106937. In newer versions where this bug ID has been fixed the Authorization header is being checked for signature matching.


If the format of the Authorization header type Bearer is not proper, this would result in triggering this signature.


Recommended Actions

The formatting of the JWT contained in the Authorization header should have 3 parts: the header, the payload, and the signature.


To work around this issue, the signature can be disabled for the Authorization header. The instructions in K8866 can be followed.
