Topic

This article covers creating SSL Subject Alternative Name (SAN) certificates using the Configuration utility or TMOS Shell (tmsh).

For information about creating SSL SAN certificates using OpenSSL, refer to the following article:

  • K11438: Creating SSL SAN certificates and CSRs using OpenSSL

For information about creating SSL SAN certificates for BIG-IP Next products, refer to the following article:

  • K000141431: Creating SSL SAN certificates and CSRs using BIG-IP Next Central Manager

Description

SAN certificates or Unified Communication (UCC) certificates allow control of the subject alternative name field to secure multiple domains, subdomains, and IP addresses through a single certificate. This type of certificate is similar to a wildcard certificate; however, it allows you to specify multiple alternative domains instead of a single domain, as in a wildcard certificate.

You should consider using these procedures under the following condition:

  • You want to use the Configuration utility or tmsh to create an SSL certificate or CSR that contains the SAN extension.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You can access the Configuration utility or tmsh.

You can use the Configuration utility or tmsh to create SSL certificates, keys, and CSRs that contain the SAN extension. A SAN SSL certificate allows you to associate multiple name values and IP addresses with a single SSL certificate, avoiding the cost of purchasing multiple similarly named certificates. For example, you can create a single SAN certificate that contains all of the following domains and IP addresses:

  • www.example.com
  • www.exchange.example.com
  • www.example.internal.net
  • IP Address:203.0.113.100

Procedures

  • Using the Configuration utility to create SSL SAN certificates, keys, and CSRs
  • Using tmsh to create SSL SAN certificates, keys, and CSRs

Using the Configuration utility to create SSL SAN certificates, keys, and CSRs

To watch a video demo of this procedure, go to  Creating SSL SAN certificates and CSRs.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Certificate Management > Traffic Certificate Management > SSL Certificate List.
  3. Select Create.
  4. To create a self-signed certificate, from the Issuer list, select Self. Alternatively, to create a CSR, from the Issuer list, select Certificate Authority.
  5. For Common Name, enter the first domain (domain order is not important).

    For example:

    www.example.com

  6. For Subject Alternative Name, enter additional domain names that you want to associate with the SSL certificate. Separate each domain name with a comma.

    For example, to associate the previous domain names with the SSL certificate, add the following comma-separated entries to Subject Alternative Name:

    DNS:www.example.com, DNS:www.exchange.example.com, DNS:www.example.internal.net, IP:203.0.113.100

  7. Complete the remaining fields for the certificate or CSR.

    If you need multiple email IDs, you can use a space or a semicolon {;) as a separator between email IDs.

  8. Select Finished.
  9. Optional: You can view the contents of the certificate using the following command syntax:

    openssl x509 -in <certificate name> -noout -text

    For example:

    openssl x509 -in sol13471.crt -noout -text

    Certificate:
    Data:
    Version: 3 (0x2)
    Serial Number: 1552 (0x610)
    Signature Algorithm: sha1WithRSAEncryption
    Issuer: C=US, CN=www.example.com
    Validity
    Not Before: Apr 2 15:53:57 2014 GMT
    Not After : Apr 2 15:53:57 2015 GMT
    Subject: C=US, CN=www.example.com

    X509v3 extensions:
    X509v3 Subject Alternative Name:
    DNS:owa.example.com, DNS:www.example2.com, DNS:www.example.net, IP:203.0.113.100

Using tmsh to create SSL SAN certificates, keys, and CSRs

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create the SAN certificate and key pair using the following command syntax:

    create /sys crypto key <key_name> gen-certificate <key_options> lifetime <value> subject-alternative-name <string>

    For example, to create a SAN certificate and key pair named example, with a lifetime of 10 years, and a subject name alternatives string of www.exchange.example.com and www.example.com, use the following command, separating each domain name with a comma:

    create /sys crypto key example gen-certificate common-name "Example Inc." country "US" lifetime 3650 subject-alternative-name "DNS:www.exchange.example.com, DNS:www.example.com, IP:203.0.113.100"

    Additionally, to generate a certificate signing request, with the SAN certificate and key pair, add the gen-csr option to the command.

    For example:

    create /sys crypto key example gen-certificate gen-csr common-name "Example Inc." country "US" lifetime 3650 subject-alternative-name "DNS:www.exchange.example.com, DNS:www.example.com, IP:203.0.113.100"

  3. Save the change by entering the following command:

    save /sys conf
