Known Issue

This is the result of a known issue. When the BIG-IP system boots, the master control program daemon (mcpd) may be in a ready state and start communicating with the front panel display daemon (fpdd) before the fpdd has finished initializing. As a result of this race condition, the BIG-IP system may not display any messages on the LCD during boot time, and the Alarm LED may light up later than expected. For example, when a unit boots up and sets itself in standby mode, it should display the Unit going standby message on the LCD; however, due to this known issue, the message may not display, and the Alarm LED may turn yellow later than expected. You can safely ignore this issue.

F5 Product Development tracked this issue as ID 225915 (formerly CR140427) and ID 365370, and it was fixed in BIG-IP 11.1.0. For information about upgrading, refer to the BIG-IP release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIG-IP-11.0.0-8131.0-HF1, which has been issued for BIG-IP 11.0.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

To work around this issue, you can set the lcdwarn priority to Informational. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Back up the /etc/alertd/alert.conf file by typing the following command:

    cp /etc/alertd/alert.conf /etc/alertd/alert.conf.SOL12532

  3. Modify the permissions on the alert.conf file to include write access by typing the following command:

    chmod 644 /etc/alertd/alert.conf

  4. Using a text editor, in the /etc/alertd/alert.conf file, locate the following section:

    /*
    * from failover(sod) (CR36393)
    */
    alert BIGIP_SOD_SODERR_SOD_STANDBY {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.14";
    lcdwarn description="Unit going standby." priority="0"
    }
    alert BIGIP_SOD_SODERR_SOD_ACTIVE {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.15";
    lcdwarn description="Unit going Active." priority="0"
    }

  5. In the previously-described section, change priority="0" to priority="5".

    Note: Customizations to the alert.conf file are not saved in the UCS archive. To ensure that customized files are saved when you create a UCS archive, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

    The modified section appears similar to the following example:

    /*
    * from failover(sod) (CR36393)
    */
    alert BIGIP_SOD_SODERR_SOD_STANDBY {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.14";
    lcdwarn description="Unit going standby." priority="5"
    }
    alert BIGIP_SOD_SODERR_SOD_ACTIVE {
    snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.15";
    lcdwarn description="Unit going Active." priority="5"
    }

  6. Modify the permissions back to read-only access by typing the following command:

    chmod 444 /etc/alertd/alert.conf

  7. Restart the alertd process by typing the following command:

    bigstart restart alertd
