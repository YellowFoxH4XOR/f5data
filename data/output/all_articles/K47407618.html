K47407618: iRule to reject CVE-2021-26855 type requests

Source

Description

Use an iRule to reject CVE-2021-26855 type requests. iRule is based on information from https://msrc-blog.microsoft.com/2021/03/05/microsoft-exchange-server-vulnerabilities-mitigations-march-2021/

Environment

  • BIG-IP LTM provisioned
  • Virtual Server with HTTP Profile
  • MS Exchange Backend Server

Cause

Alternative if BIG-IP ASM/ Advanced WAF is not licensed and provisioned on BIG-IP device where attack signatures exists to mitigate CVE-2021-26855 and related MS Exchange CVEs.   

Recommended Actions

Create an iRule to reject CVE-2021-26855 type requests

Impact of procedure: Enabling the iRule may increase CPU usage of the BIG-IP depending on how much traffic a Virtual Server is receiving 
  1. Logon to BIG-IP Configuration Utility, Open iRules Menu and click Create
  2. Provide a Name for the iRule
  3. Paste the following iRule Code

    Note: You can remove the # character before each log local0 statement when troubleshooting.

    when HTTP_REQUEST {
        set uri [HTTP::uri]
        set ip [IP::client_addr]
        if { [catch { set cookie_names [HTTP::cookie names] }] } then {
            #log local0. "ERROR: Attempting to assign cookie_names. HTTP URI: $uri -- Client Address: $ip"
        }
        else {
            #log local0. "[IP::client_addr]:[TCP::client_port]: \$cookie_names ([llength $cookie_names]): $cookie_names"
            foreach acookie $cookie_names {
                #log local0. "checking $acookie"
                if { [string tolower $acookie] contains "x-anonresource-backend" } {
                    #log local0. "event 1: rejected $acookie"
                    reject
                    return
                }
                elseif {[string tolower $acookie] contains "x-beresource" } {
                    #log local0. "event 2: checking $acookie value if contains / "

                    if {[HTTP::cookie $acookie] contains "/"} {
                        #log local0. "[HTTP::cookie $acookie] is the cookie value in event 2 and contains a / - rejecting"
                        reject
                    }
                }
                else {
                    return
                }
            }
        }
    }

    Save the iRule
  4. Apply the iRule to the Virtual Server
  5. Test the iRule

BIG-IP ASM / Advance WAF have existing Attack Signatures is much suitable to mitigate the related MS Exchange CVEs, see https://devcentral.f5.com/s/articles/HAFNIUM-APT-Group-Exploiting-Microsoft-Exchange-Vulnerabilities
