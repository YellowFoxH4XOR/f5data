Known Issue

The BIG-IP system may experience memory exhaustion caused by the monpd process.

This issue occurs when the following condition is met:

  • The BIG-IP AFM, AVR, APM, ASM, PEM, or vCMP modules are licensed and provisioned.

A memory leak in the monpd process causes a gradual increase in memory usage, regardless of whether the BIG-IP system is processing traffic.

Note: The monpd process runs on vCMP hosts for BIG-IP 11.6.0, however, the monpd process does not run on vCMP hosts for BIG-IP 11.5.1.

Impact

BIG-IP system memory usage increases over time, which may eventually cause a decrease in performance or a system reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H504826 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP performance graphs indicate high swap memory usage.
  • The top command indicates high resident memory (RES) usage for the monpd process, similar to the following output example:

    top -p `pidof monpd`

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    21645 root 20 0 800m 300m 4m S 1.4 9.8 692:10.42 monpd

    Note: In this output example, the resident memory (RES) corresponds to the amount of actual physical memory that the monpd process is using.

Workaround

To work around this issue, you can monitor memory usage and restart the monpd process before the system runs out of memory. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the BIG-IP system.
  2. Monitor the current resident memory usage for the monpd process by typing the following command:

    top -p `pidof monpd`

    For a system where monpd has recently been restarted, the output would look similar to the following example:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND
    22349 root 20 0 56356 21m 13m S 0.0 0.1 0:00.09 monpd

    In the previous output example, the resident memory (RES) corresponds to the amount of actual physical memory that the monpd process is using.

    Note: F5 recommends that you monitor memory usage on at least a weekly basis.

  3. If the resident memory exceeds 100m, restart the monpd process by typing the following command:

    tmsh restart sys service monpd
