K000138432: Thousands of logs with "[warn] 41#41: *201025 using uninitialized <value> variable"

Type
Support Solution
Published
2024-02-09
Updated
2024-02-09
Source

Description

Nginx-ingress logs flooded with the following warning:

2023/11/25 18:30:36 [warn] 41#41: *201025 using uninitialized "default_connection_header" variable, client: 10.64.0.xx, server: *****, request: "GET /tea HTTP/1.1", host: "*****"

Environment

Nginx Ingress Controller 3.x

Cause

Nginx is trying to access a variable that has not been initialized, check the following link for more details.

Recommended Actions

From the nginx perspective, these checks for uninitialized variables can be skipped by using the uninitialized_variable_warn directive.

Assuming that you are working with ingress resources please add the following snippet. Please consider that this directive can be applied at http, server, and location context.

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  annotations:
...
    nginx.org/location-snippets: |
      uninitialized_variable_warn off;
...
spec:

 

Additional Information

After applying the snippet your configuration should look like this:

	location /tea {
		set $service "tea-svc";
		status_zone "tea-svc";
		proxy_http_version 1.1;
		uninitialized_variable_warn off;
...
	}
	location /coffee {
		set $service "coffee-svc";
		status_zone "coffee-svc";
		proxy_http_version 1.1;
		uninitialized_variable_warn off;
...
	}
	location /nginx {
		set $service "nginx-v1-8444";
		status_zone "nginx-v1-8444";
		proxy_http_version 1.1;
		uninitialized_variable_warn off;
...
	}
}
