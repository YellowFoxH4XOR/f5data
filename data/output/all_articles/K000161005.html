Description

MCPD (Master Control Program Daemon) may experience timeouts when processing very large bcm56xxd L2 Forwarding Database (FWD DB) dumps, leading to bcm56xxd daemon crashing.

This occurs when the system exports the entire Broadcom ARL (Address Resolution Logic) table, resulting in oversized messages (e.g., around 16MB) that MCPD cannot handle.

Symptoms include process crashes, timeouts, or SNMP polling failures. This issue is associated with Bug ID 1573601 and can affect BIG-IP running LTM, AFM and other modules.

Symptoms:

  • MCPD process timeout
  • bcm56xxd daemon crashes
  • SNMP polling failures or timeouts
  • Core files generated (e.g., bcm56xxd core)
  • System instability during statistics collection or diagnostic data gathering

Environment

  • Product: BIG-IP LTM, AFM
  • Version: 17.1.x (and potentially other versions, including v17.5.x)
  • High-churn or large-scale environments
  • SNMP polling or automated diagnostic collection (e.g., iHealth, qkview) in use
  • If using AFM, more than 20k firewall rules are configured, and pccd.overlap.check is enabled.
  • Large statistics tables are present.
  • SNMP performs table walks over MCP-backed statistics.

Cause

Bug ID 1573601

The issue is caused by the system exporting the entire Broadcom ARL table, even if most entries are empty. This results in a very large message that MCPD cannot process, leading to a crash or timeout. The trigger can be SNMP polling, qkview/iHealth data collection, or other background statistics consumers.

Recommended Actions

  • Disabling pccd.overlap.check is not required in LTM-only environments and has no impact if AFM is not present. If using AFM, you may disable the db key as a workaround, or reduce the number of firewall rules.
  • There is no specific workaround for this exact trigger for LTM. To reduce risk:
    • Avoid unnecessary SNMP polling or qkview/iHealth generation unless required.
    • Monitor for large statistics queries that may trigger the issue.
  • A fix is under evaluation and will be released when available.

Additional Information

  • The issue is not caused by excessive accumulation of data, but by a bug in how the system dumps the complete ARL table.
  • The exact trigger for the full L2 FWD stat dump could not be definitively identified, but is most likely due to background processes such as SNMP polling or automated diagnostic tools.
  • No explicit tmsh or bash command was found to have triggered the dump in the reviewed case.
  • Disabling pccd.overlap.check is only relevant for AFM rule overlap checks and does not impact LTM-only environments.
