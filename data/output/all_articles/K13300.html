Topic

You should consider using this procedure under the following condition:

  • You want to assign a static IP address to a BIG-IP APM Network Access tunnel based on the evaluation of an expression.

Description

A BIG-IP APM Network Access tunnel uses a lease pool to dynamically assign an IP address to a client when the client connects. A lease pool specifies a collection of IP addresses as a single object. The lease pool is then used to associate that collection of IP addresses with a network access resource. Using actions in an access policy, you can evaluate an expression and assign a static address, overriding the dynamic assignment of a lease pool address to the client.

Note: For more information about lease pools, refer to the Using Lease Pools section of the Configuration Guide for BIG-IP Access Policy Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP APM system is configured with a network access policy.
  • You understand access policies and session variables.
  • You understand BIG-IP data groups.
  • You understand iRules.

Procedures

  • Configure an access policy to assign a limited set of static IP addresses
  • Configure an access policy to assign a large set of static IP addresses using a data group

Configure an access policy to assign a limited set of static IP addresses

This procedure adds a custom action to check a condition and assigns a static IP if the condition evaluates to true.

Impact of procedure: You must ensure that the static IP is not part of the lease pool and that the decision action does not have multiple matches. If the static address is in use, the client is not assigned the IP address and receives an error that appears similar to the following example:

Status: a connection to the remote computer could not be established, so the port used for this connection was closed.

  1. Log in to the Configuration utility.
  2. Go to Access Profiles > Access Profiles List.
  3. For the access profile name, select Edit to open the Visual Policy Editor (VPE) displays.

     

  4. On the successful branch of the resource assign action, select the add icon (+). 
    Note: This should be before Advanced Resorce assign as this create a rule who/what condition match will get static IP.
  5. Select the General Purpose tab.
  6. Select Empty.
  7. Select Add Item.
  8. In the Add Item pop-up window, select the Branch Rules tab.
  9. Select Add Branch Rule.
  10. For Name, enter a name for the branch.

    For example:

    IsAdmin

  11. Select change.
  12. Select the appropriate condition from the simple expression or select the Advanced tab and enter an expression to be evaluated.

    For example, the following expression evaluates login attempts for the user login 'admin':

    expr {[ mcget {session.logon.last.username}] eq "admin" }

    Note: Use of "eq" or "==" are acceptable forms of evaluation for the expression. For more information, refer to the Session Variables chapter of the Configuration Guide for BIG-IP Access Policy Manager.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

    Important: There should be no space between curly brackets and square brackets and no space between the curly brackets and the session variable.

  13. Select Save.
  14. On the new branch, select Deny.
  15. Select Allow.
  16. Select Save.
  17. On the new branch of the Resource Assign action, select the add icon (+).
    Note: This need to be AFTER the Empty rule you created above, and does not matter after or before the Resource Assign,
  18. In the New Item pop-up window, select the Assignment tab.
  19. Select the Variable Assign.
  20. Select Add Item.
  21. In the Add Item pop-up window, select Add new entry.
  22. Select change of the new entry.
  23. Select Predefined Session Variable.
  24. For Variable, select Network Access client IPv4.
  25. For Custom Expression enter an expression using the following syntax:

    return {<ip address>}

    In the previous syntax, note the following:

    • <ip address> is the static IP address to assign to the user.

    For example:

    return {10.1.1.10}

  26. Select Finished.

Configure an access policy to assign a large set of static IP addresses using a data group

This procedure creates a data group when usernames are mapped to static IP addresses. The data group is then utilized by an access policy using an iRule and an access policy iRules event item.

Impact of procedure: You must ensure that the static IP addresses are not part of the network access lease pool. If a static address is in use, the client is not assigned the IP address and receives an error that appears similar to the following example:

Status: a connection to the remote computer could not be established, so the port used for this connection was closed.

  1. Log in to the Configuration utility.
  2. Go to iRules > Data Group Lists.
  3. Select Create.
  4. Enter a name for the data group.
  5. Select String.
  6. For String, enter the intended user name.
  7. For Value, enter the IP address that you want to map to the user from step 6.
  8. Select Add.

    Repeat steps 5 through 8 for each unique user IP address combination.

    Note: To use an external data group or import a data group, refer to the following guides for your BIG-IP APM version:

    • The iRules Concepts chapter of the BIG-IP LTM BIG-IP System manual

    • The External File Management chapter of the BIG-IP TMOS: Concepts manual

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  9. After all users are added to the data group, select Finished.
  10. Go to iRules > iRules Lists.
  11. Select Create.
  12. For Name, enter a name for the iRule.
  13. In the iRule, for Definition, enter the following text:

    Important: Ensure that the <data-group name> sections of the iRule are modified to match the name of your data group.

    when ACCESS_POLICY_AGENT_EVENT {
    if { [ACCESS::policy agent_id] eq "<data-group name>" } { ACCESS::session data set session.requested.clientip [class lookup [ACCESS::session data get "session.logon.last.username"] <data-group name> ] } }

  14. Select Finished.
  15. Go to Local Traffic > Virtual Servers.
  16. Select the name of the BIG-IP APM virtual server.
  17. Select the Resources tab.
  18. For iRules, select Manage.
  19. In the Available list, select the iRule you created and move it to the Enabled list.
  20. Select Finished.
  21. Go to Access Policy > Access Profiles > Access Profiles List.
  22. For your access profile, select Edit to open the VPE.
  23. After the resource assign section of the access policy, just prior to the Allow policy ending section, select the add icon (+) to add a policy item.
  24. Select the General Purpose tab.
  25. Select the iRule Event item.
  26. Select Add Item.
  27. For Custom iRule Event Agent ID, enter the exact name of the data group.
  28. Select Save.

    Important: Network access profiles, including profiles with the static IP assignment configuration, still require that an IPv4 lease pool is set in Network Settings of the profile.
