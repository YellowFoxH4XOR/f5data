Known Issue

The BIG-IP ASM system may incorrectly add, to the list of allowed URLs, a URI that contains a question mark (?). This issue occurs when all of the following conditions are met:

  • The Automatic Policy Builder is enabled with the Always Trust Responses (10.2.1) or the Learn from Responses (10.2.2 and later) option.
  • The Automatic Policy Builder is actively running.
  • The origin web server (OWS) response contains an escaped question mark (?) in the URI.

    For example, if the OWS returns the following response, the BIG-IP ASM system incorrectly adds the URI /search.php?q=or+%271%27%3D%271%27&aaa=%00& to the Allowed URLs list:

    HTTP/1.1 302 Found
    Date: Fri, 18 Jan 2013 14:48:19 GMT
    Server: Apache/1.3.26 (Unix) PHP/4.1.2 mod_ssl/2.8.10 OpenSSL/0.9.6b
    X-Powered-By: PHP/4.1.2
    Location: /search.php?q=or+%271%27%3D%271%27&aaa=%00&
    Transfer-Encoding: chunked
    Content-Type: text/html

    <html><head><title>Object moved</title></head><body>\n<h2>Object moved to <a href="%2Fsearch.php%3Fq=or+%271%27%3D%271%27&aaa=%00&">here</a>.</h2>\n</body></html>

Impact

The Allowed URLs list may be populated with the URI unexpectedly. Depending on the application, the list may become very large if each parameter/value pair creates a unique URI.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Allowed URLs list is populated with the affected URI.

Workaround

To work around this issue, you can disable the Always Trust Responses (10.2.1) or Learn from Responses (10.2.2 and later) option from the Automatic Policy Building configuration. To do so, perform the following procedure:

Impact of workaround: The Automatic Policy Building may require more time to learn the application since it is relying on only requests.

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Automatic Policy Building > Configuration.
  3. Clear the Always Trust Responses (10.2.1) or Learn from responses (10.2.2 and later) option.
  4. Click Save.
  5. Click Apply Policy to activate the change.
