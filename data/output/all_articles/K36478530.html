Description

Prior to 12.0.0 releases, if a HTTP request consists of both the standard X-Forwarded-For (XFF) header and a custom header containing the true client IP address (for e.g. Akamai's True-Client-IP header), then address within the X-Forwarded-For header takes precedence. This can be undesirable depending on application requirements, as the incorrect client IP address can be used within iRule, IP Intelligence or Geolocation Enforcement.

Environment

  • HTTP profile configured with Accept XFF option enabled
  • Security policy configured with Trust XFF option enabled
  • HTTP request consisting of both X-Forwarded-For and custom headers, potentially with multiple addresses specified in either or both headers

Cause

The behavior in versions prior to 12.x with normal XFF header taking priority over custom headers is tracked by F5 Product Engineering as a known issue at ID 475556.

As part of addressing this bug, you have the ability to configure the system to prioritize custom headers over the normal XFF header and that can be done through avr.customheaderoverridexff database variable setting.

To list the default-value, the current value, and the possible value-range of this system database key, use the following command syntax:

tmsh list sys db avr.customheaderoverridexff all-properties

For example, here is what the output would appear like when running the above command:

sys db avr.customheaderoverridexff {
    default-value "1"
    scf-config "true"
    value "1"
    value-range "unsigned integer min:0 max:1"
}

With the value set to "1", the custom headers take precedence over normal XFF headers. This database key doesn't exist in versions impacted by ID 475556.

Recommended Actions

  • 12.0.0 and later releases
  • 11.6.x and earlier releases

12.0.0 and later releases

For 12.0.0 and later releases, the avr.customheaderoverridexff database key allows for prioritizing custom headers, by default. If there is desire to revert this back to behavior that was in place prior to 12.0.0, you can modify this database key by setting it to 0.

To modify the value of this database key, use the following syntax:

tmsh modify sys db avr.customheaderoverridexff value 0

11.6.x and earlier releases

For versions affected by ID 475556, the standard XFF header will take priority over custom header and there is no way to workaround the issue.
