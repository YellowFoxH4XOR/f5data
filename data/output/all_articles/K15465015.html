Description
You have Request Logging profile configured in your existing BIGIP and the profile is used in multiple virtual servers. 

Example:

ltm profile request-log /Common/<profile_name> {
    app-service none
    defaults-from /Common/request-log
    log-response-by-default yes
    log-response-logging-errors disabled
    response-log-error-pool none
    response-log-error-protocol mds-udp
    response-log-error-template none
    response-log-pool /Common/<example_pool>
    response-log-protocol mds-udp
    response-log-template "category=\"response_logging\",date=\"$DATE_NCSA\",virtual_name=\"$VIRTUAL_NAME\",virtual_pool_name=\"$VIRTUAL_POOL_NAME\",virtual_ip=\"$VIRTUAL_IP\",virtual_port=\"$VIRTUAL_PORT\",server_ip=\"$SERVER_IP\",server_port=\"$SERVER_PORT\",snat_ip=\"$SNAT_IP\",client_ip=\"$CLIENT_IP\",request=\"$HTTP_REQUEST\",referer=\"$Referer\",user_agent=\"${User-agent}\",reponse_code=\"$HTTP_STATCODE\",response_size=\"$RESPONSE_SIZE\",latency=\"$RESPONSE_MSECS\""
    response-logging enabled
}


You are adding a new BIGIP to the existing HA system, a configuration synchronization (ConfigSync) operation failed.
The system logs error messages in the /var/log/ltm file that appear similar to the following example

0107148c:6: Received advertisement for device group /Common/<device_group_name> from remote device /Common/LTM2.example.com, force false, error 'Load failed from /Common/LTM1.example.com 01070283:3: The profile (/Common/<profile_name>) is currently associated with one or more virtual servers or transport configs.' commit_id 3 7102249069396191621 /Common/LTM2.example.com 0, local commit id is 12 7102249979076829225 /Common/LTM1.example.com 0 cached remote device data 0

Environment

  • HA
  • Config sync
  • Request logging profile is used in multiple virtual servers

Cause
Seen behavior is caused by a known issue tracked with the Bug ID 1115301.

Recommended Actions

To work around the issue, you can perform the following procedures:
  1. Remove the Request Logging Profile from all the virtual servers of the existing BIGIP.
  2. Initiating a ConfigSync process from the existing BIGIP to the device group and ensure all units are in sync.
  3. Next, configuring the Request Logging Profile back to all the virtual servers.
  4. Initiating another ConfigSync process again.
