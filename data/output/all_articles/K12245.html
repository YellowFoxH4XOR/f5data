Known Issue

This is the result of a known issue. In certain situations, using the table keys -subtable iRule command can cause a memory leak.

This issue is known to occur when the command is used to return a list of the keys in a specified subtable.

For example, the following command leaks memory:

set tablekeys [table keys -subtable "mytable"]

This issue does not occur when the command is used to return a count of the keys in a specified subtable.

For example, the following command does not leak memory:

set tablecount [table keys -subtable "mytable" -count]

You can observe the memory leak by viewing the performance graphs in the Configuration utility, or by watching the output of the bigpipe memory | grep "tcl (variable)" command over time. If a memory leak is occurring, you observe a gradual rise in memory utilization.

For example, the following output was generated by running the bigpipe memory | grep "tcl (variable)" command in 30 second intervals, and shows a gradual rise in memory utilization:

| tcl (variable) 82.92M 82.99M 1
| tcl (variable) 84.31M 84.47M 1
| tcl (variable) 85.99M 86.18M 1
| tcl (variable) 87.80M 87.92M 1
| tcl (variable) 89.42M 89.54M 1
| tcl (variable) 91.04M 91.10M 1
| tcl (variable) 92.70M 92.87M 1
| tcl (variable) 94.48M 94.62M 1
| tcl (variable) 96.18M 96.25M 1

Note: The table iRule command was introduced in BIG-IP 10.1.0, and like the session iRule command, provides a way of accessing the session table. For more information about the table iRule command, refer to the following DevCentral wiki page. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary):

https://devcentral.f5.com/wiki/iRules.table.ashx

F5 Product Development tracked this issue as ID 342010, and it was fixed in BIG-IP 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.
