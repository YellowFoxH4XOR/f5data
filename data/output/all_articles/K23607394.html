Description

The /usr partition can utilize more than 90% upon installation of system files but is mounted as read-only. The df command shows a high amount of disk usage.

For example:

# df -h

Filesystem                           Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-set.1._usr   3.3G  3.0G  98M  97% /usr

Environment

  • BIG-IP
  • BIG-IQ

Cause

This is expected behavior.

Recommended Actions

Important:

High disk space usage reported for the /usr partition (including 100% utilization as shown by df) is often expected behavior on BIG-IP systems, especially after upgrades that increase the disk footprint (such as recent EHF releases). The df command excludes filesystem blocks reserved for the root user (typically 5%), which can cause the available space to appear as zero even when the system remains fully operational.

Resizing the /usr partition is optional and should only be considered if you are experiencing actual system issues (such as failed upgrades, inability to install hotfixes, or error messages indicating disk exhaustion). In most cases, no action is required, and manual deletion of files from /usr is not recommended, as it may cause system instability.

If you are unsure whether resizing is necessary, or if you observe errors related to disk space, please contact F5 Support for guidance before making changes.

 

Optional Resizing:

There should not have any impact on performance in BIG-IP services and we can resize /usr partition by following below steps.

Impact of procedure: This procedure does not impact traffic; however, F5 recommends that you perform this procedure only during a maintenance window.

    1. Log in to the BIG-IP using command line.
    2. Verify disk space usage in /usr partition using below command:

      df -h /usr

      Additionally, note the raw path for the /usr partition. You will need the raw path in subsequent steps.

    3. Check your free disk space by running command:

      vgdisplay

      Note the amount of storage space available on your BIG-IP device; this is typically indicated in the Free PE / Size output.

    4. Run below commands to allocate additional storage space to /usr partition:
      mount -o remount,rw /usr
      lvresize -L +<amount of storage in MB>M -r <the raw path for /usr partition>
      mount -o remount,ro /usr

      Using the example in the Description section, run the following commands to allocate an additional 200MB of storage space to /usr partition (raw path: /dev/mapper/vg--db--sda-set.1._usr):

      mount -o remount,rw /usr
      lvresize -L +200M -r /dev/mapper/vg--db--sda-set.1._usr
      mount -o remount,ro /usr

      This will add 200M to the /usr filesystem which will drop the utilization percent to ~91%, using a larger value will lower down /usr partition utilization. This is dynamic, so the system can remain online while executing the command.

    Additional Information

    • The /usr partition is created upon installation for system files and it is mounted as read-only. The amount of free space should not change during normal operation.
    • This will not impact performance.
    • During software upgrade, the upgrade process will create a volume partition for /usr that is of the correct and appropriate size.
    • There is no need to monitor /usr in any monitoring tool as this is expected behavior.
