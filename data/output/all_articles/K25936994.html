Issue

Description

During BIG-IP LTM service import to the BIG-IQ, if the BIG-IP has a logging profile configured in the non-Common administrative partition, the service import to BIG-IQ fails and logs an error message with the following syntax:

Failed to apply Shared namespace conflicts; reason: Failed to copy configuration to working-config; reason: Failed copying from source to target: java.lang.IllegalArgumentException: dosApplication remoteLogPublisher '/<non-Common administrative partition>/<remote log publisher>' has incompatible partition.

In this error message, note the following:

  • <non-Common administrative partition> is the non-Common partition where the logging profile resides.
  • <remote log publisher> is the log publisher referenced by the logging profile.

For example,

Failed to apply Shared namespace conflicts; reason: Failed to copy configuration to working-config; reason: Failed copying from source to target: java.lang.IllegalArgumentException: dosApplication remoteLogPublisher '/MyExamplePartition/MyLogPublisher' has incompatible partition.

You may encounter this message in the following locations:

  • The BIG-IQ user inteface
  • The /var/log/restjavad.x.log (for example, restjavad.0.log, restjavad.1.log, restjavad.x.log) files

Environment

  • BIG-IQ 5.4.0
  • A logging profile configured in non-Common administrative partition on the BIG-IP system

Cause

The BIG-IQ 5.4.0 performs enforcement to ensure that log profiles refer to log publishers in the same partition. For information, refer to ID 707962.

Recommended Actions

To work around this issue, you must ensure that the logging profiles configured in the BIG-IP device is not using a log publisher in the non-Common administrative partition:

  • Creating a new log publisher in the Common partition on the BIG-IP system
  • Deleting the log publisher from the non-Common administrative partition on the BIG-IP system
  • Re-discovering and importing the BIG-IP LTM service configuration to the BIG-IQ
Creating a new log publisher in the Common partition on the BIG-IP system

Create a new log publisher in the Common administrative partition with same configuration as the log publisher from the non-Common administrative partition. To do so, perform the following procedure:

Important: Ensure that a UCS backup is taken prior to any configuration change on the BIG-IP system. Save the UCS backup from the BIG-IP system to a secure file location where you can retrieved it later.

Impact of procedure: Performing the following procedure should not have a negative impact on your system

  1. Log in to the Configuration Utility
  2. Ensure you are in the Common administrative partition, then navigate to System  > Logs > Configuration > Log Publishers.
  3. Click Create.
  4. Provide a name for the log publisher.
  5. Under Log Destinations, use the existing the Log destination in the non-Common administrative partition.
  6. Click Finished.

Deleting the log publisher from the non-Common administrative partition on the BIG-IP system

Important: Ensure that the log publisher in the the non-Common administrative partition is not being used by any logging profiles.

Note: For BIG-IP systems that have BIG-IP ASM provisioned, if you navigate to Security  >  Event Logs > Logging Profiles, under DOS Application Protection, there is a configured logging profile referencing a log publisher when DoS Protection is enabled for Remote Publisher. For more information on references to log publisher configuration use, refer to the External Monitoring of BIG-IP Systems: Implementations Manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Impact of procedure: This procedure deletes the log publisher in the non-Common administrative partition.   

  1. Log in to the Configuration utility
  2. Under the non-Common administrative partition, navigate to System > Logs > Configuration > Log Publishers.
  3. Click the log publisher referenced in the BIG-IQ error and delete it.

Re-discovering and importing the BIG-IP LTM service configuration to the BIG-IQ

Impact of procedure: Performing the following procedure should not have a negative impact on your system

  1. Log in to the BIG-IQ user interface.
  2. Click the Devices tab.
  3. Click the BIG-IP device from which you want the configuration discovered and imported. 
  4. Under Local Traffic, click configuration Discover.
  5. After service discovery is successful, click Configuration Import.

Additional Information

The following steps describe how you may experience this error message from the BIG-IQ user interface:

  • On the BIG-IQ user interface, on the Devices tab, click the BIG-IP device from which you want the configuration discovered and imported.
  • Under Local Traffic, click configuration Discover.
  • After discovery is successful, click Configuration Import. The following error syntax is returned: 

    Failed to apply Shared namespace conflicts; reason: Failed to copy configuration to working-config; reason: Failed copying from source to target: java.lang.IllegalArgumentException: dosApplication remoteLogPublisher '/MyExamplePartition/MyLogPublisher' has incompatible partition.

The following example shows a snippet of the BIG-IP log publisher configuration in a non-Common administrative partition, as well as the related log destination and remote high speed log referencing a BIG-IP LTM pool:

sys log-config publisher /MyExamplePartition/MyLogPublisher {
    destinations {
        /MyExamplePartition/logserver_splunk { }
    }
}

sys log-config destination splunk /MyExamplePartition/logserver_splunk {
    forward-to /MyExamplePartition/splunk_rhsl
}

sys log-config destination remote-high-speed-log /MyExamplePartition/splunk_rhsl {
    pool-name /MyExamplePartition/splunk_pool
    protocol udp
}
