K45440934: RDG not working with native RDP resources when using RDG-RPC

Type
Knowledge
Published
2019-06-07
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP APM: 15.0.0, 14.1.X, 14.0.X, 14.1.5, 14.1.4, 14.1.3, 14.X.X, 14.1.0, 14.0.1, 14.0.0, 14.1.2
Source
https://my.f5.com/manage/s/article/K45440934

Issue

Description

  • When connecting to native Remote Desktop Protocol (RDP) resources, RDG-RPC is not supported for launching Native RDP resources. Only RDG-HTTP is supported.
  • Clients that don't work are requesting /rpc/rpcproxy.dll?localhost:<port> with Microsoft Remote Procedure Call (MSRPC) user agent.
  • If for some reason RDP connection uses or falls back to RDG-RPC, the native RDP resource isn't launched and messages similar to the following, indicating RDG-RPC use, may appear in the /var/log/apm file:

    debug tmm6[<PID>]: 019cffff:7: /Common/example_ap:Common:00000000: Request (RPC_OUT_DATA /rpc/rpcproxy.dll HTTP/1.1 User-Agent: MSRPC Content-Length: 0)
    debug tmm6[<PID>]: 019cffff:7: /Common/example_ap:Common:00000000: Client-type (rdg-rpc)
    err tmm6[<PID>]: 019cffff:3: /Common/example_ap:Common:00000000: VDI profile on /Common/example_ap.app/example_ap_https_virtual does not have associated NTLM Auth profile or ECA profile is missing
    debug tmm6[<PID>]: 019cffff:7: (null):Common:00000000: Got rdg-rpc OUT on tmm 0 6 ntlm_done 0
    debug tmm6[<PID>]: 019cffff:7: /Common/example_ap:Common:00000000: RD: [C] <IP_address>.2573 i <IP_address>.443: server-side connection was reset, reason: iRule execution

Environment

  • BIG-IP APM using native RDP resources
  • Windows client attempting to connect using RDG-RPC

Cause

  • For native RDP resources, BIG-IP APM acts as RD Gateway and it supports only RDG-HTTP.
  • Normally, RDP clients use RDG-HTTP transport, but they could use RDG-RPC due to the following possible reasons:
    • The Windows registry key on the client device is set to use RDG-RPC.
    • The RDP client used is downloaded from the Microsoft App store and is currently not supported.
    • The client device is configured to use a proxy server which blocks outgoing RDG-HTTP requests.

Recommended Actions

  • Change the client's registry entry in Windows to force the client to connect with RDG-HTTP using the following procedure:

    Important: F5 is not responsible for potential side effects of modifying client registry keys; ensure this is applicable for your environment.

    1. Log in to the affected Windows client machine.
    2. Launch the regedit.exe program to edit the registry.
    3. Locate the following registry key:

      HKCU\Software\Microsoft\Terminal Server Client\RDGClientTransport

      If the registry key is present and has a value of 1, it enforces RDG-RPC transport.

    4. Delete this registry value to prefer RDG-HTTP transport.
  • If a proxy server is blocking outgoing RDG-HTTP requests, use the following commands:
    • Run the following command on the client device to display the proxy server:

      netsh winhttp show proxy

    • Run the following command on the client device to reset the proxy server settings:

      Note: This command clears the proxy server settings on the client device.

      netsh winhttp reset proxy

Additional Information

Starting with BIG-IP APM 13.0.0, BIG-IP APM has the capability to proxy RDP connections from client computers to RDP servers. This is similar to the functionality offered by Microsoft RD Gateway.

Normally, RDP clients use RDG-HTTP transport and fall back to RDG-RPC only if RD Gateway does not support RDG-HTTP. If for some reason the RDP client program uses or falls back to RDG-RPC, the native RDP resource won't be launched.

In general, it is possible to determine if the client is using RDG-RPC or RDG-HTTP by referring to the /var/log/apm logs. Alternatively, it is also possble by looking at a packet capture or logging the header of the requests with an iRule. Both transports use HTTP underneath, but RDG-RPC uses RPC_IN_DATA and RPC_OUT_DATA HTTP methods and RDG-HTTP uses RDG_OUT_DATA and RDG_IN_DATA methods.
