Topic

Note: This article applies to only BIG-IP platforms that contain an SCCP (1500, 3400, 3410, 4100, 6400, 6800, 8400, and 8800).

The Switch Card Control Processor (SCCP) is a separate sub-system that controls the F5 switch hardware. If the SCCP is unable to boot from its firmware image, it will attempt to recover by initiating a netboot recovery procedure.

The netboot recovery procedure attempts to locate an external PXE server working image from which to boot, instead of attempting to use the firmware image. If the BIG-IP system is rebooted while the SCCP firmware is being flashed, such as during an installation or upgrade, the SCCP may be unable to boot.

You can recover from this condition by using one of the two procedures listed below. Review the requirements and the procedures in full before proceeding. Based on the requirements, choose the procedure that is most appropriate for your environment.

SCCP recovery procedure using a PXE server

SCCP recovery procedure using a TFTP server

Important: Review this article in its entirety before beginning. The procedures that follow have numerous complex steps that require you to use additional hardware and software that are not provided by F5.

Important: Do not attempt to perform these procedures unless your BIG-IP system has already displayed the error message. Performing these procedures before you have received the error message may render the system unusable, and require you to return the system under the Return Materials Authorization (RMA) process.

SCCP recovery procedure using a PXE server

To recover from this condition, you must perform the following procedures:

  • Configuring a network boot (PXE) server
  • Restoring the SCCP image

Configuring a network boot (PXE) server

  1. Locate a system to use as a network boot server. The system must meet the criteria outlined in K3469: Hardware requirements for the BIG-IP network boot server.
  2. Connect the network boot server to the same network to which the BIG-IP system's management interface is connected.

    Important: You must use the BIG-IP system management interface. If you connect the network boot server directly to the BIG-IP system management interface, you must use an Ethernet cross-over cable.

  3. Insert the BIG-IP installation CD into the CD-ROM drive of the system designated to be the network boot server, and reboot the system.
  4. When prompted for the terminal type, enter vt100.

    Note: If you used different terminal software than the vt100, you should enter the terminal type used, when prompted.

    A menu that appears similar to the following example is displayed:

    Select installation option:
    Serve Provide network installation services
    Install Install software onto hard disk
    Reboot Reboot system
    Exit Exit to maintenance shell

  5. Type S to select the Serve option.
  6. Press the Enter key.
  7. When prompted, select the network interface you would like to use for the network boot server. Choose the interface that is connected to the same network as the BIG-IP system management interface.
  8. When prompted, choose either your existing DHCP server or the network boot server to act as a DHCP server, using the following guidelines:
    • If you have an existing DHCP server on the subnet that you want to use, type yes. The server configuration will complete automatically.

      Once configured, proceed to step 15.

    • If you do not have an existing DHCP server that you want to use, type no, and follow the prompts to enter the addresses you would like to use with the DHCP.

      Once configured, proceed to step 10.

  9. When prompted, use the following criteria to enter the IP network that you want to use with the DHCP server:
    • If you are connected to an existing network, choose an IP address range that is compatible.
    • If you are not connected to an existing network, use the default address range.
  10. When prompted, use the following criteria to enter the IP address that you want to use for the network boot server:
    • If you are connected to an existing network, choose a compatible IP address that is not already in use.
    • If you are not connected to an existing network, use the default IP address.
  11. When prompted, use the following criteria to enter the lowest IP address that you want available for the BIG-IP system to use during the installation process:
    • If you are connected to an existing network, choose a compatible IP address that is not already in use.
    • If you are not connected to an existing network, use the default IP address.
  12. When prompted, use the following criteria to enter the highest IP address that you want available for the BIG-IP system to use during the installation process:
    • If you are connected to an existing network, choose a compatible IP address that is not already in use.
    • If you are not connected to an existing network, use the default IP address.
  13. The BIG-IP system displays the settings that you have selected. If the settings are correct, press the Enter key to continue.

    If any of the settings are incorrect type no, press the Enter key, and return to Step 8.

  14. When prompted to choose the installation protocol, select HTTP.

    The configuration of the network boot server is now complete and you are placed in a shell. The system displays the following messages:

    Server ready for installations
         bash: no job control in this shell

Restoring the SCCP image

  1. Ensure that the BIG-IP system management interface is connected to the netboot PXE server.
  2. Power cycle the BIG-IP system to boot the SCCP from the PXE server.
  3. When the command prompt appears, simultaneously press the ESC, Shift, and 9 keys to access the SCCP Command Menu.

    The SCCP Command Menu opens.

  4. From the SCCP Command Menu, type L to log in to the SCCP.

    Log in as root. The password should be the same as the BIG-IP system or default password.

  5. Copy the SCCP image files from the PXE server to the /boot directory on the SCCP, by typing the following commands:

    wget http://<PXE IP>/cdserver/tftpboot/vmlinux.img /boot
    wget http://<PXE IP>/cdserver/tftpboot/vmlinux.md5 /boot
    wget http://<PXE IP>/cdserver/tftpboot/initrd.img /boot
    wget http://<PXE IP>/cdserver/tftpboot/initrd.md5 /boot

    Replace <PXE IP> with the IP address of the PXE server.

  6. Change directories to the /boot directory, by typing the following command:

    cd /boot

  7. Verify the md5sum of the vmlinux.img and initrd.img files, by typing the following command:

    md5sum -c vmlinux.md5; md5sum -c initrd.md5

    Note: If the md5 message digests match, you will receive the following output:

    vmlinux.img: OK
    initrd.img: OK

  8. Reboot the SCCP, by typing the following command:

    reboot

  9. When the system reboots, verify that you have access to the SCCP menu.

    Note: To ensure that you can access the SCCP, follow the procedures in K3454: Overview of the SCCP.

  10. If required, you may also need to reinstall the BIG-IP system software.

    For installation instructions, refer to the BIG-IP LTM, GTM, or ASM release notes for the product and version you would like to install.

SCCP recovery procedure using a TFTP server

Note: To complete these procedures, you must have a BIG-IP software CD for the BIG-IP version you are running. You can download the ISO image and burn it to a CD if you do not already have one. For more information about downloading software, refer to K167: Downloading software and firmware from F5. Also, you must have an available TFTP server; the TFTP server may be on the same client system you will use to connect to the BIG-IP system command line.

  • Preparing a TFTP server to transfer files to the BIG-IP system
  • Restoring the SCCP boot image
  • Preparing a network boot server (optional)
  • Reinstalling host system software (optional)
  • Saving the SCCP boot image to flash memory

Preparing a TFTP server to transfer files to the BIG-IP system

  1. Start the TFTP server.

    Note: The TFTP server must reside on the same network segment as the BIG-IP management port.

    Note: If the workstation you plan to configure as a TFTP server is running Microsoft Windows, you may download and use the Tftpd32 utility for this purpose. The Tftpd32 utility is a free and lightweight TFTP server; you may obtain this utility from http://tftpd32.jounin.net/. This link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

  2. Copy the following files from the BIG-IP software CD to the TFTP server directory:

    /tftpboot/vmlinux.img
    /tftpboot/initrd.img

Restoring the SCCP boot image

  1. Restart the BIG-IP system.
  2. When prompted, press any key to stop the autoboot process.
  3. Configure a temporary IP address for the BIG-IP system by typing the following command:

    setenv ipaddr <address>

    You can use the IP address that is normally associated with the management interface.

  4. Enter the IP address of the TFTP server by typing the following command:

    setenv serverip <address>

  5. TFTP the files to the BIG-IP system by typing the following two commands:

    tftp 1000000 vmlinux.img
    tftp 2000000 initrd.img

  6. Boot the SCCP by typing the following command:

    bootm 1000000 2000000

The SCCP is now booted from files in RAM. Do not reboot the SCCP or the files will be lost, requiring you to begin the procedure again.

If the SCCP is configured to boot locally, it will now attempt to boot the host system. The host system should boot normally. If the host system does not boot normally, proceed to the Preparing a network boot server procedure. Otherwise, proceed to the Saving SCCP boot image to flash memory procedure.

Note: The Preparing a network boot server and Reinstalling host system software procedures outline how to re-install the software using a PXE server. However, you may choose to re-install the software using another installation method, for example using a USB thumb drive or a USB CD-ROM drive. To determine which installation methods are available for your software version, refer to the release notes for that particular version.

Preparing a network boot server (optional)

Note: You can skip this procedure if you do not need to re-install the host system software.

For instructions about how to prepare a network boot server for BIG-IP version 9.x, refer to K4411: Reinstalling system software from a network boot server.

For instructions about how to prepare a network boot server for BIG-IP version 10.x, refer to K10819: Performing a clean installation of BIG-IP version 10.x.

Reinstalling host system software (optional)

Note: You can skip this procedure if you do not need to re-install the host system software.

If the host system will not boot (for example, if an installation previously failed) the BIG-IP system will now hang while booting the host system.

To reinstall the host system software, perform the following procedure:

  1. Enter the SCCP menu by simultaneously pressing the ESC, SHIFT, and 9 keys.
  2. Configure the host system to network boot, by selecting option 4, Select Host subsystem boot mode: netboot from external server.
  3. Reset the host system, by selecting option 7, Reset Host subsystem (issues hardware reset--USE WITH CARE!).
  4. Switch back to the host system console to view the software installing progress, by selecting option 1, Connect to Host subsystem console.

    Note: If you are installing BIG-IP version 10.x, the installation will not begin automatically. Refer to K10819: Performing a clean installation of BIG-IP version 10.x on how to continue.

Saving the SCCP boot image to flash memory

At this point, both the SCCP and host system have booted successfully, but the SCCP boot files are still held in RAM. You can save the files to flash memory by performing the following procedure:

  1. Log in to the BIG-IP system command line.
  2. Copy the files to the SCCP by running the following commands:

    scp /opt/F5/sccp/vmlinux.img sccp:/boot/
    scp /opt/F5/sccp/initrd.img sccp:/boot/

The boot files are now saved to the SCCP flash memory, and the SCCP should boot properly after being restarted.
