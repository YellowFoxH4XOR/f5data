K000161539: After renewing certificate GUI isn't accessible

Type
Support Solution
Published
2026-06-03
Updated
2026-06-03
Source
https://my.f5.com/manage/s/article/K000161539

Description

After the device certificate was renewed, the GUI becomes inaccessible. When trying to start httpd, there's an error message about private key not matching like below:

certificate routines:X509_check_private_key:key values mismatch

Because of this error, GUI is inaccessible while SSH is working fine.
Even after generating a self signed certificate with steps from K000140327, the error still persists.
The modulus of the certificate and the key are matching after following steps from K13349. However, httpd still complains about key not matching.

 

Environment

BIG-IP LTM with recently renewed or changed device certificate.

Cause

This can happen if there are multiple certificates in the /config/httpd/conf/ssl.crt/ folder and the device is pointing to some other certificate other than server.crt.

​​​​​​​

Recommended Actions

Use the tmsh to point to the server.crt and server.key file using command below:
# tmsh modify sys httpd ssl-certfile /config/httpd/conf/ssl.crt/server.crt ssl-certkeyfile /config/httpd/conf/ssl.key/server.key

Then restart httpd using command below:
# bigstart restart httpd

Note: Running the commands above should not cause any impact to traffic.

Now, httpd should start without errors and GUI should become accessible.

Additional Information

If the issue persists, please open a case with F5 support.
