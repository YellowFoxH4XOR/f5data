K71290763: Client browser reports ERR_CERT_AUTHORITY_INVALID security warning for sites accessed via SSLO forward proxy

Type
Support Solution
Published
2021-07-31
Updated
2023-02-21
Applies to
  • F5 SSL Orchestrator: 15.1.X
Source
https://my.f5.com/manage/s/article/K71290763

Description

When accessing sites that are using 'untrusted' certificates (such as self-signed certs) via SSLO Forward Proxy, the site does not load and the browser reports certificate verification warning ERR_CERT_AUTHORITY_INVALID.

Also, when looking at the forged certificate details, it says "Issued by: Unknown CA"

Environment

  • SSLO used in a Forward proxy deployment
  • sites using untrusted certs or self-signed certs
  • Untrusted Certificate Response Control option in the serverSSL profile is set to "Ignore"

Cause

Previously, with the Untrusted Certificate Response Control option in the serverSSL profile set to Ignore, when the backend server sends self-signed untrusted certificate, SSLO ignores it, treats the certificate as valid, and continues with the handshake.

In recent BIG-IP versions (15.1.x and later), this behavior seems to have changed.

Recommended Actions

To workaround the issue, change Untrusted Certificate Response Control in the serverSSL profile to "Mask"

1. Log in to the Configuration utility
2. navigate to SSL Orchestrator  ››  Configuration
3. under SSL Configurations, if the SSLo deployment you were wanting to modify is showing as 'locked', unlock it first (by clicking on the lock icon under Protected/Unprotected Configurations to unlock it)
4. once unlocked, click on the "+ Show All" under Server SSL Profile
5. click on the serverSSL profile for your deployment (e.g. /Common/ssloT_ep.app/ssloT_ep-sssl-vhf)
6. once in the serverSSL profile properties page, under the Server Authentication section, change 'Untrusted Certificate Response Control' to "Mask"
