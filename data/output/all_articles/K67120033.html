Topic

The BIG-IP system uses Master Control Program (MCP)-encoded messages transported over User Datagram Protocol (UDP) to communicate a device's availability and failover status to device group peers. The messages contain information that can be useful for troubleshooting failover communication.

Description

When you configure network failover for a BIG-IP device group, the sod daemon on each device group member advertises the list of IP addresses on which the device listens for network failover traffic. The local sod daemon determines its failover state and communicates its status to peer systems by sending heartbeat messages to peer systems using UDP (port 1026) for unicast configurations and UDP (port 62960) for multicast configurations.

Note: For chassis-based systems, each blade runs a sod daemon instance. One blade receives the inbound network failover packets and communicates the failover status to the other blades over the management backplane.

The network failover messages contain parameters that indicate a device's availability and failover status and appears similar to the following example:

 in slot1/tmm0 lis=
10:45:16.559888 IP 10.11.16.49.53475 > 10.11.16.48.cap: failover_packet {
   failover_packet_cluster_mgmt_ip ip_address 10.154.20.34
   failover_packet_slot_id uword 0
   failover_packet_state ulong 7
   failover_packet_sub_state ulong 0
   failover_packet_monitor_fault ulong 0
   failover_packet_hop_cnt uword 0
   failover_packet_peer_signal ulong 0
   failover_packet_version ulong 2
   failover_packet_msg_bits ulong 2
   failover_packet_traffic_grp_score ulong 3482
   failover_packet_device_load ulong 1
   failover_packet_device_capacity ulong 0
   failover_packet_traffic_group_load ulong 0
   failover_packet_build_num ulong 2452438734
   failover_packet_next_active ulong 0
   failover_packet_traffic_grp string `/Common/traffic-group-1`
   failover_packet_previous_active ulong 0
   failover_packet_active_reason ulong 0
   failover_packet_left_active_reason ulong 0
}

The network failover message parameters are defined in the following table.

Failover packet parameterDescription
failover_packet_cluster_mgmt_ipThe management IP address of the cluster for chassis systems or the management IP address for appliance systems.
failover_packet_slot_idThe blade number for chassis systems (indicates zero for appliance systems).
failover_packet_stateIndicates the high availability state. For example, Active = 7, Standby = 5, Forced Offline = 3.
failover_packet_sub_stateIndicates the high availability substate.
failover_packet_monitor_faultIndicates whether there is a monitor fault for the traffic group.
failover_packet_hop_cntIndicates HA order index for the traffic group.
failover_packet_peer_signalIndicates the failover serial port signal.
failover_packet_versionThe version number for the failover packet.
failover_packet_msg_bitsThe bitmask indicating high-priority message.
failover_packet_traffic_grp_scoreThe unique machine score ID based on management IP and device name.
failover_packet_device_loadThe device load factor for traffic groups using load aware failover.
failover_packet_device_capacityThe device capacity factor for traffic groups using load aware failover.
failover_packet_traffic_group_loadIndicates the load of the next active device in the traffic group.
failover_packet_build_numIndicates the CRC checksum of the current mcpd configuration.
failover_packet_next_activeIndicates whether the sender is the next active device for the traffic group.
failover_packet_traffic_grpThe name of the traffic group.
failover_packet_previous_activeIndicates whether the sender is the previously active device for the traffic group.
failover_packet_active_reasonIndicates the reason for the active designation.
failover_packet_left_active_reasonIndicates the reason the device no longer holds the active designation.
