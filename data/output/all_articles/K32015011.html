Description

Steps in this article are describing procedure for relocating VIPRION devices to new location.

Environment

  • BIG-IP VIPRION Chassis and Blades
  • Hardware migration.

Cause

Devices needs to change location.

Recommended Actions

  1. Take UCS archive.

    # bash mode required:
    # tmsh save sys ucs $(echo $HOSTNAME | cut -d'.' -f1)-$(date +%H%M-%m%d%y)

    K13132: Backing up and restoring BIG-IP configuration files with a UCS archive
     
  2. Shutdown all blades:

    # clsh halt

    K11333: Using the clsh command to restart or shut down one or more blades in a VIPRION system

    K98142338: Using the bladectl command to reset or power off a single blade in a VIPRION system
     
  3. Remove cables, blades, transport appliance to new location.
     
  4. Re-seat blades one by one, making breaks to allow each blade to boot up.

    NOTE: Primary blade assignment may change as it is dynamically assigned.
    Refer to section "Determining the primary blade on a VIPRION system using tmsh":

    K24826954: BIG-IP TMOS operations guide | Chapter 6: VIPRION
     
  5. Connect cables (network and HA) and check for connectivity - HA/trunks/vlans/gateways/poolmembers

    K75975904: Troubleshooting network failover
     
  6. If device has connectivity, force active device to standby:

    6.1 Log in to the Configuration utility on the active BIG-IP system.
    6.2 Go to Device Management > Devices.
    6.3 Select the name of the local device (Self).
    6.4 To force the system to standby mode, select Force to Standby.

    K30371289: Forcing an active BIG-IP system to standby mode using the Configuration utility
     
  7. Check if device moved is processing traffic without issues.
     
  8. Repeat steps for second device.
     
  9. Please consider running platform Check and EUD test after moving devices:

    K15442: Using the BIG-IP platform diagnostics tool

    K7172: Overview of the End User Diagnostics software

None.
