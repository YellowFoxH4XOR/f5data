K91977112: BIG-IQ ''Audit Log Syslog Server'' not sending logs to syslog server

Type
Support Solution
Published
2021-04-07
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ Platforms
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K91977112

Description

One or more "Audit Log Syslog Server" objects are configured in BIG-IQ however the remote syslog server(s) are not receiving anything from the BIG-IQ. There are a number of reasons this could be occurring.

Environment

  • BIG-IQ
  • Remote syslog server(s)

Cause

Sending Syslog messages from BIG-IQ to a remote server requires network connectivity between the BIG-IQ and remote server, ICMP protocol availability if using TCP and there are two bugs (ID945389 and ID1017125) which can interfere with functionality if everything else is working. Each of these potential blocking events should be investigated.

Recommended Actions

  1. (If version 7.1.x) All 7.1.x versions are affected by ID945389 which prevents all Audit Log Syslog Server objects from transmitting logs. Unless running an EHF containing the fix for ID945389, upgrade to an EHF containing the bugfix or upgrade to an 8.x release.
  2. (If version 8.x or 7.1.x EHF containing ID945389) Review /var/log/restjavad.X.log for messages containing "Did not find own device , continue...". If they are present, issue "bigstart restart restjavad" and confirm messages no longer occur. This is due to ID1017125.
  3. Ensure that no more than two Audit Log Syslog Server objects have been created on the BIG-IQ as a maximum of two are supported. Reduce the number to two if higher and try again.
  4. Test and review network path from BIG-IQ to remote syslog servers. Ensure all routing and intermediate firewalls are configured properly to allow traffic on the specific port.
  5. (If using TCP) Ensure that ICMP protocol has been allowed on the network path to remote syslog servers. Once ICMP has been allowed, test by pinging the remote syslog server(s) from the BIG-IQ and ensure a successful response.

Additional Information

  • If TCP is used for the syslog transmission and ICMP protocol is blocked, /var/log/restjavad.X.log will display messages like below
    [/cm/firewall/audit-logger FWAuditLoggerCollectionWorker] Failed to create socket to 10.0.0.21(514) : java.io.IOException: The remote syslog server 10.0.0.21 is not reachable
  • When attempting to create an Audit Log Syslog Server object in 7.1.x versions, a Null Pointer Exception will be reported in /var/log/restjavad.X.log due to ID945389 like below (edited):
    [ERROR][06 May 2021 10:59:23 PDT][ RestServer] java.lang.NullPointerException
            at com.f5.rest.workers.configmgmtbase.auditLogger.syslogServer.SyslogClient.tryAndEstablishConnection(SyslogClient.java:263)
  • Versions containing the fix for ID945389 (8.x and higher or some 7.1.x EHFs) will constantly report messages to /var/log/restjavad.X.log and fail to transmit until restjavad is restarted due to ID1017125. Examples:
    [INFO][06 May 2021 05:36:09 PDT][/cm/adc-core/audit-logger AdcAuditLoggerCollectionWorker] Did not find own device , continue...
    [INFO][06 May 2021 05:36:09 PDT][/cm/global/audit-logger GlobalAuditLoggerCollectionWorker] Did not find own device , continue...
    [INFO][06 May 2021 05:36:09 PDT][/cm/shared/audit-logger SystemAuditLoggerCollectionWorker] Did not find own device , continue...
    [INFO][06 May 2021 05:36:09 PDT][/cm/firewall/audit-logger FWAuditLoggerCollectionWorker] Did not find own device , continue...
    [INFO][06 May 2021 05:36:10 PDT][/cm/access/audit-logger AccessAuditLoggerCollectionWorker] Did not find own device , continue...
