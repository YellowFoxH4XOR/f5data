Known Issue

Application Tunnel may fail to establish with Resources Items configured in a combination of protocol type and port range.

This issue occurs when all of the following conditions are met:

  • The Application Tunnel configuration includes multiple resource items.
  • The first resource item in order 1 is configured with a protocol type.
  • The subsequent resource item in order 2 is configured with port range.

Impact

The Application Tunnel may fail to establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When a user initiates an application tunnel, the application tunnel does not launch.
  • You observe log messages similar to the following examples in the Diagnostic Report of the BIG-IP Client Troubleshooting Utility (CTU):

    <date>, 2952,3268,HOST, 1, \HostCtrl.cpp, 515, CHostCtrl::Load(), port range supported for generic tunnels only <date>, 2952,3268,HOST, 1, \HostCtrl.h, 1478, CHostCtrl::Failed, Firing OnError event (message: Invalid arguments)

Workaround

To work around this issue, you can reverse the resource items order by making the port range resource item order 1 and the protocol type order 2. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Application Access > App Tunnel.
  3. Click the name of the relevant App Tunnel.
  4. In Resource Items section, click Change Order.
  5. Select the port range resource item and click Up.
  6. Click Finished.
  7. Click Apply Access Policy.
