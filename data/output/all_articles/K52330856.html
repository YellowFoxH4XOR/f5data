Description

When accessing the BIG-IP GUI via it's management interface from a jumphost server, you are intermittently getting a "Unable to contact BIG-IP device" message. After some time, you will regain access to the GUI again but issue will repeat.

The jumphost server is configured with the same subnet mask of the BIG-IP GUI. For example, the jumphost server's IP and BIG-IP management interface IP are configured in 10.10.10.0/24 subnet.

When accessing the BIG-IP GUI via a device not from the same subnet, the issue does not happen. For example, the issue does not happen when you are access the BIG-IP GUI from your local machine which is not the same subnet as the BIG-IP management interface IP.

The jumphost server is a Microsoft Server with more than one NIC (network interface card). These NICs are group together using NIC teaming.  NIC Teaming groups between one and 32 physical Ethernet network adapters into one or more software-based virtual network adapters.

Environment

  • BIG-IP
  • Intermittent "Unable to contact BIG-IP device" error message when accessing BIG-IP GUI
  • Issue only happens when accessing from a jumphost server in the same subnet as the BIG-IP management interface IP
  • Jumphost is a Microsoft Server using NIC Teaming
  • Jumphost has more than one NIC
  • Issue does not happen when accessing from a machine not in the same subnet
     

Cause

When using NIC Teaming on the Windows Server, multiple NICs can be grouped together using a single IP address.

However, the Windows Server will still use the MAC addresses of each NICs. This causes the BIG-IP to send and receive packets to the wrong interface on the Windows Server.
 

Recommended Actions

The solution is to make changes on the Windows Server. There are two solutions.

Use one NIC for the NIC Teaming configuration

  1. Navigate to the team adapter
  2. Remove all NICs leaving only one NIC

Create a Virtual MAC for the Teaming NIC
  1. Navigate to the team adapter
  2. Using Microsoft Load Balancing/Failover Provider and creating a virtual MAC
