Known Issue

This is the result of a known issue. A SIP virtual server referencing an iRule with the drop or reject command may experience TMM crashes. When a packet destined for a SIP virtual server triggers a drop or reject iRule command, the TMM issues a HUDEVT_ABORTED control message informing the SIP proxy to abort the packet. The abort message causes the proxy to immediately release all internal resources. If the proxy is simultaneously processing an egress packet, the TMM process may crash as a result of a SIGSEGV.

For example, the following virtual server references an iRule with the drop command. When the virtual server processes a SIP request, the TMM process may crash:

virtual virtual_a {
   rule sip_drop
   pool pool-A
   destination 10.10.10.100:5060
   profiles {
      sip {}
      udp {}
   }
}

rule sip_drop {
    when SIP_REQUEST_SEND {
       drop
    }
}

F5 Product Development tracked this issue as ID 225618 (formerly CR139811) and it was fixed in BIG-IP versions 10.2.1 and 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM or Edge Gateway release notes.
