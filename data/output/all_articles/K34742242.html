Known Issue

An access policy Active Directory query may fail.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM system with an Active Directory AAA profile that is not configured with Active Directory administrative credentials.
  • You have configured your access policy with an Active Directory authentication agent with the Cross Domain Support option enabled.
  • Your access policy includes a subsequent post authentication AD Query agent.
  • The logon name queried by the AD query agent is different from the user's PREWIN2k/UPN username.

Impact

The Active Directory query fails.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users attempting to establish an access session receive an error message that appears similar to the following example:

    Access was denied by the access policy. This may be due to a failure to meet access policy requirements.

  • The system logs messages to the /var/log/apm file at the time of the Active Directory query failure:

    err apd[<pid>]: 01490107:3: <sessionid>: AD module: query with 'userPrincipalName=<username@domain>' failed: Client '<username@domain>' not found in Kerberos database, principal name: <username@domain>. Please verify Active Directory and DNS configuration.  (-1765328378)
    info apd[<pid>]: 01490019:6: <sessionid>: AD agent: Query: query with 'userPrincipalName=<username@domain>' failed
    info apd[<pid>]: 01490004:6: <sessionid>: Executed agent '/KI4000/KI4000_1944777_politest_policy_act_active_directory_query_ag', return value 0

Workaround

To work around this issue, you can configure the affected Active Directory AAA server profile with administrative credentials. 

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
