Known Issue

This is the result of a known issue. When you update an expired SSL server certificate associated with a web service on the FirePass controller, a service restart is required before the edit takes effect. However, the FirePass Administrative Console does not indicate that a service restart is required. SSL server certificates are configured  from the Web Services tab of the Device Management: Configuration: Network Configuration page of the Administrative Console.

The expiration date for the certificate in the SSL Server Certificate section will be highlighted in red text, in the Expiration column.

Clicking the Edit link in the row of the expired certificate will allow the administrator to enter a new certificate.  Once the certificate information (certificate, private key, and optional chain certificates) is entered and saved, the new certificate information will replace the expired certificate information (including the red text formatting) in the SSL Server Certificate section.  A message at the top of the section will appear, stating the valid date range:

The certificate that you entered is valid from Feb-14-2008 till Oct-13-2008 !

However, no message stating that the services need to be restarted is presented. The old SSL server certificate will continue to be used until the next service restart. Clients connecting to the FirePass controller can see the details of the certificate if they instruct their browser to view the details of the certificate.

F5 Networks Product Development is tracking this issue as CR88257.

Note: If the certificate is not currently associated with a web service, then changes can be made without restarting services, as a service restart will be required when the certificate is assocated with a web service.

Workaround

You can work around this issue by manually restarting the FirePass services after editing an SSL certificate. You can restart the FirePass services on the Device Management : Maintenance : Restart Services page.
