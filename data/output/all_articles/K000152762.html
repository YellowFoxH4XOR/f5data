Description

I want to manage multiple ports on the HTTP Load Balancer or TCP/UDP Load Balancer without conflicts. How could I do this?

 

Environment

  • F5® Distributed Cloud HTTP Load Balancer
  • F5® Distributed Cloud TCP Load Balancer
  • F5® Distributed Cloud UDP Load Balancer

 

Answer/Recommended Actions

LB port selection can be managed by two options:

  • Listen Port
  • Port Ranges

"Port Ranges" selection has two options to set the range: Span ("-") and List ",".

  • Span:  dash "-", specifies a contiguous range of ports (maximum of 64 ports).
  • List: comma-separated ",", specifies multiple discrete ports that do not need to be consecutive.

 

Further Information

Distinct ports can be shared between multiple LBs only if the LBs are assigned separate VIPs/Advertise Policy, or SNI is in effect.  SNI is used to distinguish virtual hosts (LBs) having unique domains configured on the same listener for LBs of the following types 

  1. HTTP(s) LBs
  2. TCP LBs with SNI enabled

 

Configuration of a Port Range as a Span creates a listener for all ports in the set that cannot be shared by another LB on the same VIP or Advertise Policy, regardless of domain/SNI uniqueness.  For instance, if a TCP LB is configured with the Port Range [8000-8020], no other LB sharing the same VIP or Advertise Policy can be configured with any port in the range 8000-8020.  This exclusivity applies across all namespaces regardless of SNI/domain uniqueness.  The restriction does not apply if the LB is configured with the equivalent List definition (e.g. 8000, 8001, 8002... 8020).

For separate non-TLS or SNI-incapable applications (or prod/non-prod replicas of the same application) that must listen on the same TCP port, TCP LBs must be assigned separate VIP/Advertise Policy.

CE advertised LBs - port ranges limitation (does not apply to RE)

On CE, overlapping ports are prohibited on the same VIP. If you use custom VIP Advertisement policy on CE with port ranges, there may occur a problem with overlapping ports. LB that is in port conflict with different LB will not be installed and will reject all the traffic. 

Example of CE overlapping port conflict:

LB1: VIP Advertisement (10.1.1.10) on CE site "example-site-1" - port ranges configured "443,445,8080"

LB2: VIP Advertisement (10.1.1.10) on CE site "example-site-1" - port ranges configured "443,445,8077"

In above config, only 1 LB will work (first one that we configured). 2nd one will fail to deploy listener on CE. 

Same situation will occur with below configuration:

LB1:  HTTP Listen Port: 810

LB2: Port Ranges: 810,8022

Only one of above LB will work because of overlapping ports conflict. 

CE port ranges correct configuration

If you want to use port ranges on CE advertised VIP make sure that one of below is true:

  • Ports used in port range are assigned only to one LB/IP.
  • Port ranges on LBs are identical if they use the same advertisement IP e.g. LB1 ports: 445,543 and LB2 ports: 445,543.
    If you will use exactly the same port ranges on different LBs, there is no problem with listeners deployments.
