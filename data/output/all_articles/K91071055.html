Issue

Old Behavior

In versions prior to 11.5.3 HF2 and 11.6.0 HF6, when a BIG-IP system fails over, the newly active unit sends out gratuitous ARPs (GARPs) once per second, up to five times for each floating self IP, SNAT translation IP, and virtual server IP address, to update the Address Resolution Protocol (ARP) cache of the devices on the network.

New Behavior

Beginning in 11.5.3 HF2 and 11.6.0 HF6, when a BIG-IP system fails over, the newly active unit sends GARPs as quickly as possible, up to five times for each floating self IP, SNAT translation IP, and virtual server IP address, to update the ARP cache of the devices on the network.

F5 Product Development tracked this change as ID 503652.

Impact

By increasing the number of GARPs, and reducing the time between each, a BIG-IP system failover event happens more quickly and with less interruption to established connections.

Recommended Actions

To modify the BIG-IP system's GARP behavior, refer to K11985: Overview of the arp.gratuitousrate and arp.gratuitousburst database variables.
