Planning the upgrade

F5 Networks does not support high availability/redundant pair configurations that are running different software versions, as this can have a detrimental effect on the failover process. The failover pair must be running the exact same revision of BIG-IP software. If the existing BIG-IP is at a later version number (maintenance or otherwise), you must upgrade the peer system so that they match. For information about upgrading, refer to the BIG-IP Release Notes.

Because the existing BIG-IP will need to be rebooted, you must perform this configuration change during a low-traffic period or maintenance window. This procedure may also result in a short period (as low as 2 to 5 minutes) in which both BIG-IPs are in active/active mode. During this period, performance will be severely reduced.

Configuration examples

Original single controller configuration

In the following original single controller configuration example, the existing external and internal IP addresses (external_IP_1 and internal_IP_1) from the single BIG-IP will become the new shared addresses on the redundant system.

external_IP_1 is the IP address to which the external router directs traffic.
internal_IP_1 is the default route for the servers being load balanced.

Two additional external and two additional internal IP addresses are required for the full configuration.

Redundant configuration

In the following new redundant configuration example, external_IP_2 and external_IP_3 are the new primary external interface addresses for each controller, and internal_IP_2 and internal_IP_3 are the new primary internal interfaces. The external_IP_1 and internal_IP_1 addresses are changed to the floating addresses that are shared between the units. This eliminates the need to modify the upstream router or downstream nodes.

BIG-IP 2 configuration (new BIG-IP that being added to the configuration)

external_IP_2 is the new primary external interface.
internal_IP_2 is the new primary internal interface.
external_IP_1 and internal_IP_1 are the new shared addresses.

BIG-IP 1 (original stand-alone BIG-IP)

external_IP_3 is the new primary external interface.
internal_IP_3 is the new primary internal interface.
external_IP_1 and internal_IP_1 are the new shared addresses.

Configuring the new BIG-IP in a redundant pair

To configure the new BIG-IP Controller in a redundant pair, perform the following steps:

  1. Connect the new BIG-IP Controller with a fail-over cable to the existing BIG-IP Controller and turn on the power.

    Important: Do not connect the network cabling to the new BIG-IP as this could cause a network disturbance after the system reboots.

  2. Run the Setup utility.
  3. When asked if you are running a redundant system, respond with Yes.
  4. When prompted for the UnitID, type 1. Be sure to use the existing BIG-IP's interface addresses as the new shared addresses (in this example, internal_IP_1 and external_IP_1).
  5. When prompted for a fail-over IP address, type the new internal primary address of the peer unit in the redundant system (in this example, internal_IP_3).

    Important: Do not use the IP address that the existing system is currently using, because that address will be the shared/floating address for the redundant pair. Additionally, it is crucial that the VLANs on the new BIG-IP (note that the name is case sensitive) and the web username and password are named the same as the existing system. If this is not set correctly, the configurations will not be synchronized.

  6. Reboot the new BIG-IP.

    When BIG-IP comes back up, it will be the standby controller in a redundant pair configuration (provided the failover cable was connected).

    To verify the state of the BIG-IP, type the following command:

    b fo

    If the BIG-IP is in active mode, check to see if the failover cable is securely connected in the failover port.

    Note: The failover port resembles the serial port. Both ports are labeled.

  7. Review the base IP configuration, by typing the following command:

    b base list

Configuring the original BIG-IP as a standby system in a redundant pair

To configure the original BIG-IP Controller as the redundant standby system, perform the following steps:

  1. Reconfigure the original BIG-IP Controller as the redundant system, by typing the following command:

    config

  2. Select the (R) Steps for Redundant systems option.
  3. Follow the steps to configure the shared IP addresses, VLANs, and so forth, using the IP addresses you prepared.

    For this example, the self IP addresses are external_IP_2 and internal_IP_2 and the floating IP addresses are internal_IP_1 and external_IP_1.

  4. When prompted for the UnitID, type 2.
  5. Reboot the BIG-IP.

    Important: Rebooting the BIG-IP will result in a temporary site outage.

    When BIG-IP comes back up, it will be in a redundant pair configuration in standby mode (provided the failover cable was connected), because the new BIG-IP is in active mode.

  6. To fail back to the original BIG-IP and start traffic flowing, type the following command on the new BIG-IP:

    b fo standby

Synchronizing configurations

To synchronize the configuration between the standby and the active system, perform the following steps:

  1. The existing BIG-IP should now be active mode and the new BIG-IP should be standby. Verify this by typing the following command on each system:

    b fo

    Important: It is imperative that the new BIG-IP is in standby mode before you connect it to the network, or the two units will both send ARP requests for the floating addresses, which can stop all traffic.

  2. After you confirm the state of the BIG-IP systems, connect the new BIG-IP to the network.
  3. Synchronize the configuration, by typing the following command:

    b configsync all

  4. Confirm that the new BIG-IP has the correct configuration by typing the following command:

    b list

  5. Verify that the /config/bigip.conf file is the same size on both systems.

    At this point both units should have the same configuration and should failover seamlessly. F5 Networks recommends that you test the configuration synchronization and fail over in both directions during the maintenance window.
