Known Issue

This is the result of a known issue. Running the EUD from the lights-out management command menu (hostconsh) can lock up the SCCP and put the host system in an inoperative state.

In previous versions of the End-User Diagnostics: Field Testing BIG-IP Hardware Release Note, the following four EUD installation methods were documented:

  • Booting the EUD from a USB CDROM drive
  • Booting the EUD from a USB mass storage device
  • Starting the EUD from the grub boot menu
  • Starting the EUD from the lights-out management command menu

When you run the EUD from the lights-out management command menu, the SCCP copies the EUD kernel and initrd files to memory so that the host system can boot the EUD from the SCCP. If you run EUD version 11.x from the lights-out management command menu, the SCCP locks up, and the host system becomes inoperative. When this occurs, the following messages are logged to the system console:

scp: /tmp/eud/hsibj-eud-initrd.386: No space left on device
sed: couldn't write 128 items to {standard output}: No space left on device
Rebooting the host processor; please wait...

This issue occurs because the EUD version 11.x kernel and initrd files are too large to be copied to the SCCP.

F5 Development tracked this issue as CR99632 and it does not affect versions 11.2.0 and later. The platforms affected by this issue are no longer supported after version 11.1.0.

Workaround

If you ran the EUD version 11.x from the lights-out management command menu, and the SCCP and the host system are inoperable, you must manually power cycle the device.
