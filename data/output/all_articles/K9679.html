Known Issue

This is the result of a known issue. When the 32-bit Linux uptime counter wraps around to 0 (zero), the BIG-IP system stops sending external lacpd messages and never resumes. This failure may trigger VLAN failsafe on the BIG-IP, and may also cause any trunks configured with neighboring switches to fail.

Note: If the BIG-IP GTM or LC module is licensed on the BIG-IP system, internal lacpd communications may also be disrupted, which may in turn disrupt local, global, and link load balancing. For more information, refer to K9683: The gtmd, tmm, or bcm56xxd daemons may crash after 497 day Linux uptime wraparound.

F5 Networks Product Development tracked the lacpd communications failure issue as CR82423, and it was fixed in BIG-IP version 9.4.2. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, or Link Controller Release Notes.

Additionally, this issue has been fixed in Hotfix-BIG-IP-9.3.1-HF5 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K6845: Managing F5 Networks product hotfixes.

For information about F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

Note: The root cause of this issue, the Linux uptime counter wrap, is being separately tracked as CR74550. For details and the current status of this issue, refer to K7036: The Linux uptime counter wraps after 497 days.

Workaround

If the symptoms described in this Solution are encountered on a system with an uptime of 497 days or more, you can work around this issue by rebooting the system. Alternatively, you can avoid this issue by rebooting the system prior to the 497 day counter wrap. Upon restart, the uptime counter is reset to zero, and lacpd communications will no longer be interrupted.

Note: For platforms with SCCP, reboot the system using the full_box_reboot command.

To determine how long the system has been up, use the Linux uptime command. The uptime command produces output that appears similar to the following example:

19:52:48 up 20 days, 9:24, 1 user, load average: 0.09, 0.05, 0.11

Note: For platforms with SCCP, execute the uptime command while logged in to the SCCP.
