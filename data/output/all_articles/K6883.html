Known Issue

This is the result of a known issue. An iRule event declaration specifies an event within an iRule that causes the BIG-IP LTM system to trigger that iRule whenever the event occurs. When an iRule contains multiple event declarations of the same type in a single iRule, the BIG-IP LTM system will process the first iRule event declaration, but subsequent event declarations of the same type will not be processed.

For example, in the following iRule, the BIG-IP LTM system should process both HTTP_REQUEST iRule event declarations. When the iRule is processed, however, only the first HTTP_REQUEST iRule event declaration is processed, and the second is not processed, regardless of the priority number specified.

rule multi_event {
when HTTP_REQUEST priority 100 {
  log local0. "Priority 100"
}

when HTTP_REQUEST priority 200 {
  log local0. "Priority 200"
}
}

F5 Product Development tracked this issue as CR67851, CR70630, and CR70698 and it was fixed in BIG-IP LTM and ASM 9.2.4, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM or ASM Release Notes.
