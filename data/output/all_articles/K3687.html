Adding static routes to IP subnets on the same physical network segment

By default, BIG-IP and 3-DNS can only route to network addresses that are located on attached segments when they match a BIG-IP self IP address. To add multiple IP subnets on the same physical network segment, you must add a self IP address that belongs to each new network.

To add a static route to IP subnets on the same physical network segment, perform the following steps:

  1. Create a new self IP address on the new network, by typing the following command:

    bigpipe self <address> vlan internal netmask <netmask>

  2. Create a new floating self IP address on the new network, by typing the following command:

    bigpipe self <address> vlan internal netmask <netmask> floating enable

  3. Save the base configuration, by typing the following command:

    bigpipe base save

  4. Save the shared configuration, by typing the following command:

    bigpipe save

  5. Reload the full configuration, by typing the following command:

    bigstart reinit

You should now be able to access the new network.

Note: If you have nodes on the newly-added network that use the BIG-IP system as their default gateway, you must configure those nodes to use the new floating self IP address for their gateway address. For more information about configuring the default gateway for your nodes, refer to your operating system documentation.

Adding static routes to IP subnets on a different physical network segment

By default, the BIG-IP system and 3-DNS system can only route to network addresses that are on attached segments that match a BIG-IP self IP address or to networks that can be reached through the BIG-IP system's default gateway. Since the default gateway is generally upstream of the BIG-IP system, it is often necessary to add static routes to nodes that are reached through a downstream router.

To add a static route to an IP subnet on a different physical network segment, perform the following steps:

  1. Add a static route to the IP subnet, by typing the following command:

    route add -net <subnet> <router>

    Important: The BIG-IP system and 3-DNS system build the routing table by loading static routes and then loading the configuration. If you add routes after you have loaded the configuration, it may result in incorrect routing. Because of this, you should always reload the BIG-IP system or 3-DNS system configuration using the bigpipe load command after you add new static routes.

  2. If nodes on the new subnet do not route outbound traffic through the BIG-IP system or 3-DNS system, use the following command to create a SNAT so that traffic will return to the BIG-IP system or 3-DNS system:

    bigpipe snat map external to <address>

Saving static routes

Static routes are stored in the /config/static_routes file in the following format:

<destination IP address> <gateway IP address> <route options>

To add static routes to /config/static_routes, perform the following steps:

  1. Log in to the command line.
  2. Verify that the update_cached_routes global variable is enabled, by typing the following command:

    bigpipe global update_cached_routes

  3. Add the static routes to the /config/static_routes file, by typing the following command:

    Important: The double chevron (>>) appends the modifications to the /config/static_routes file, rather than overwriting the file. If the file does not exist, this command will create it. Use this command with caution; if you use a single chevron (>), this command will overwrite the entire contents of the /config/static_routes file with the new entry.

    echo '<destination IP address> <gateway IP address> <route options>' >>/config/static_routes

    In the previous command, note the following:

    • <destination IP address> is an individual IP address or a network IP address with a CIDR netmask.
    • <gateway IP address> is the individual IP address of the next hop route.
    • <route options> is any option that you use with the route command.

    For example, to add a route with the destination IP address 10.1.1.1, the gateway IP address 10.1.1.254, and an option to expire in sixty seconds, you would use the following command:

    echo '10.1.1.1 10.1.1.254 -expire 60' >>/config/static_routes

    To add the same route, but also restrict the MTU to 200 bytes, you would use the following command:

    echo '10.1.1.1 10.1.1.254 -expire 60 -mtu 200' >>/config/static_routes

  4. Load the new routing configuration, by typing the following command:

    bigstart reinit static-routes

Static routes are also automatically loaded each time the base or full configuration is loaded and when a unit in a redundant configuration becomes active.

Modifying the Maximum Transfer Unit (MTU) for BIG-IP and 3-DNS static routes

To lock an MTU value to a specific route in the routing table, log in as root and type the following command where DESTINATION is the route destination, GATEWAY is the next-hop router used to get to the DESTINATION, and PMTU is the MTU value for the path from the host to the route destination:

route [change|add] [-[host|net]]{DESTINATION}{GATEWAY} [-mtu PMTU]

For example:

route add -net 10.0.0.0 192.168.1.1 -mtu 1450

or

route change -net 10.0.0.0 -mtu 400
