Description

Failover order does not work as defined, the next active device is chosen by the best HA score. Additionally, one or more devices from HA cluster may not be able to become active.

Environment

  • BIG-IP
  • HA cluster with 3 devices or more
  • HA failover set in order

Cause

Configuration CRC values are different among cluster members. Only devices with the same and proper CRC can become active.

Answer/Recommended Actions

  1. Verify configuration on all cluster members by running a command from CLI:

    # tmsh load sys config verify

    Note: It should not have any negative impact in traffic processing and device stability. 

    If no error is displayed, please proceed to step 2.

  2. Inspect /var/log/ltm searching for entries similar to:

    notice sod[8385]: 010c006d:5: Leaving Standby for Active: Best TG score, peers disagree on config.

    and

    err sod[6767]: 010c006a:3: Configuration CRC values disagree amongst peers. Suggest configsync peers.

    If mentioned entries were found, please proceed to step 3.

  3. Synchronize configuration between cluster members. The best practice is to push the configuration from the active device to the group. More information about ConfigSync can be found K13920: Performing a ConfigSync using the Configuration utility.

  4. If ConfigSync has not solved this problem and the log entries from step  3 have not disappeared, please follow the solution K000140928: BIG-IP traffic-group showing warning: "The traffic group configuration on this device does not match with other devices" even after ConfigSync
