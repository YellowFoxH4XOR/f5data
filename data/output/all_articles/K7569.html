General Information

Provide the following information when you open a case with F5 Technical Support:

  • A full description of the issue, including the following:

    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have attempted to resolve the issue
  • A description of the impact the issue is having on your site, using the following definitions:

    • Site Down

      Your network or application is down, or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important, because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Technical Support will work directly with you to resolve the issue over the phone and through email; however, this approach can often be more time consuming and may require file transfers, replication, and additional testing.

Product specific information

Collect the following information from the affected systems and provide the information when you open the case.

Note: For information about sending this information to F5, refer to K2486: Providing files to F5 Technical Support.

qkview

The qkview utility generates a file that contains the configuration files that F5 Technical Support most frequently needs when troubleshooting an issue. You should run the qkview utility on the Enterprise Manager system before opening a case. F5 Technical Support may also request qkview output files from one or more managed devices. For more information about qkview, refer to K12878: Generating BIG-IP diagnostic data using the qkview utility (10.x - 11.x)

Log files

The qkview file contains 5 MB of log files from the Enterprise Manager system. If the issue requires that you collect all system log files on the system, perform the following procedure:

  1. Log in to the command line.
  2. Create a tar archive named logfiles.tar.gz in the /var/tmp directory (which contains all the files in the /var/log directory) by typing the following command:

    tar -czpf /var/tmp/logfiles.tar.gz /var/log/*

Packet Traces

If the issue involves the network, perform a packet trace while the issue is occurring and provide the packet trace when you open the case. For more information about performing packet traces with tcpdump, refer to K4714: Performing a packet trace and providing the results to F5 Technical Support.

Note: For information about gathering and interpreting encrypted packet traces from the Enterprise Manager system, refer to K7823: Troubleshooting and debugging Enterprise Manager iControl connectivity.

UCS archive

If you cannot give F5 Technical Support remote access to your system, you must provide a UCS archive of the current configuration. In some cases, UCS archives for managed systems may also be requested. For more information, refer to K4423: Overview of UCS archives.

Core files

Core files contain the contents of the system memory at the time a crash occurred. If the system is crashing and producing core files, the core files will be located in the /var/savecore directory. Please submit any existing core files when you open the case. For information about identifying and submitting core files, refer to K10062: Submitting core files for analysis to F5 Technical Support.
