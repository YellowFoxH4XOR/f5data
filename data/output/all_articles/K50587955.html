Description

  •  IPSEC tunnel establishes but then fails after configured Security Association (SA, IKE phase 2) timeout

Environment

  • BIG-IP
  • IKEv2
  • ECP Diffie Hellman Group used for Perfect Forward Security (PFS)

Cause
Software defect wherby BIG-IP does not compute the correct encryption key after IPSEC SA renegotiation when using ECP DH groups. For information refer to Bug ID 900933.

Recommended Actions

Do not use ECP for PFS so you can use Modular Exponential (MODP) instead of ECP. To do so, perform the following procedure:

Impact of workaround:  Performing the following work around should not have a negative impact on your system.

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Network > IPsec > IPsec Policies.
  3. Click the relevant IPsec policy.
  4. Under Perfect Forward Secrecy, click the MODP encryption of your choice.
  5. Click Update.
  6. Navigate to Network > IPsec > IKE Peers.
  7. Select the relevant IKE peer.
  8. Under Perfect Forward Secrecy, click the same MODP encryption as in step 4.
  9. Click Update.

Aditionally, you can refer to Bug ID 900933 for fixed versions or new information.
