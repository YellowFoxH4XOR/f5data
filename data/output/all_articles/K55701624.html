Description

  • Address translation fields are not being logged when the firewall policy is staged
  • They are logged when the policy is enforced though

Environment

  • BIG-IP AFM
  • Firewall policy enabled under the staged setting for the virtual server
  • Address translation configured in the AFM policy
  • Remote logging of address translation fields enabled

Cause

The purpose of a staged policy is basically for testing the policy. To make sure it receives a matching flow, the system will be taking this action and then logging the details without actually taking the action. So there is no interest in anything other than what flow was matched and what action would have been taken if the policy was really enforced. There is no interest in the details used for server-side forwarding. This is the reason server-side information is not logged in the case of a staged policy. Also, due to no interest in server-side flows, the staged policy information is logged much earlier in the flow, whereas enforced policies are logged much later. This is why the system does not log translation fields in a staged rule. This is true whether any source translations are used like AFM NAT, CGNAT, SNAT etc or use LTM pool. Enforced rules will log this information.

Recommended Actions

None, this is functioning as designed.
