Topic

This article covers the XML profile configuration settings.  You can configure the XML profile by navigating to Security > Application Security > Content Profiles > XML Profiles in the BIG-IP ASM Configuration utility.

 

Description

You can configure the BIG-IP ASM system to provide security for XML content in your web applications.  By configuring an XML profile, you can use the BIG-IP ASM system to inspect, validate, and protect XML transactions. With XML security, you can protect the following applications:

  • Web services that use HTTP as a transport layer for XML data.
  • Web services that use encryption and decryption in HTTP requests.
  • Web services that require verification and signing using digital signatures.
  • Web applications that use XML for client-server data communications, such as Outlook Web Access.

Note: Depending on your BIG-IP version, some sections or settings may not be available on your system.

Defense configuration

Use this section to configure the security policy’s XML defense level. First, select the type of options you want to configure:

  • Basic: Specifies that you want to configure the security policy’s XML defense level, and which XML applications the system should protect.
  • Advanced: Specifies that you want to configure XML settings, in addition to the security policy’s basic defense configuration settings.
SettingsDescription
Defense LevelSpecifies the level of protection the system supplies to XML documents, applications, and services. The defense level you select impacts the advanced defense configuration default settings, and the type of patterns that the system protects against. Select: High, Medium, or Low. If you change any of the default settings, the system automatically changes the defense level to Custom.
Allow DTDsSpecifies, when selected (enabled), that the system allows references to Document Type Definitions (DTDs) in the XML document part of a request. Specifies, when cleared (disabled), that the system prohibits references to DTDs in the XML document part of a request. If you upload a schema file, the default is disabled. If you upload a WSDL file and there are valid SOAP methods, this setting is inactive and disabled.

Allow External ReferencesSpecifies, when selected (enabled), that the system allows external references in the XML document part of a request. Specifies, when cleared (disabled), that the system forbids external references. The default setting is disabled.
Tolerate Leading White SpaceSpecifies, when selected (enabled), that the system allows a carriage return, new line, tab, or space at the beginning of the XML document part of a request. Specifies, when cleared (disabled), that the system does not allow those at the beginning of the XML document. The default setting is disabled.
Tolerate Close Tag ShorthandSpecifies, when selected (enabled), that the system treats the byte pattern <⁄> as a closed element for the most-recently-opened element, whatever it may be. Specifies, when cleared (disabled), that the system does not recognize the byte pattern <⁄> as a closed element. This syntax is used by Outlook Web Access. The default setting is disabled.
Tolerate Numeric NamesSpecifies, when selected (enabled), that the system accepts XML element names that begin with a number. Specifies, when cleared (disabled), that the system does not permit XML element names that begin with a number. The default setting is disabled.
Allow Processing InstructionsSpecifies, when selected (enabled), that the system allows processing instructions in the XML document part of a request. Processing instructions allow XML documents to contain instructions for applications. The XML parser does not check processing instructions, but passes them through to the application. Specifies, when cleared (disabled), that the system disallows processing instructions in the XML document part of a request. If you are concerned that a hacker may send a harmful processing instruction to the application through the XML document, clear this setting. If you upload a schema file, the default is enabled. If you upload a WSDL file and there are valid SOAP methods, this setting is inactive and disabled.
Allow CDATASpecifies, when selected (enabled), that the system permits the existence of character data (CDATA) sections the XML document part of a request. The default is disabled.
Maximum Document SizeSpecifies the largest size, in bytes, of the XML document part of a request that the security policy allows. To configure no limit, select Any. The default value is based on the defense level: high or medium is 1024000, and low is Any.
Maximum ElementsSpecifies the largest number of elements allowed in a single XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 65536, medium is 512000, and low is Any.
Maximum Name LengthSpecifies the longest length, in bytes, of an element name or attribute name allowed in the XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 256, medium is 1024, and low is Any.
Maximum Attribute Value LengthSpecifies the longest length, in bytes, an attribute value is allowed in the XML document part of a request according to the security policy. To configure no limit, select Any. The default value is based on the defense level: high is 1024, medium is 4096, and low is Any.
Maximum Document DepthSpecifies the greatest depth of nested elements in the XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 32, medium is 128, and low is Any.
Maximum Children Per ElementSpecifies the largest number of child elements allowed for any one parent element in the XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 1024, medium is 4096, and low is Any.
Maximum Attributes Per ElementSpecifies the largest number of attributes allowed for any one element in the XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 16, medium is 64, and low is Any.
Maximum NS DeclarationsSpecifies the largest number of namespace declarations the system allows in the XML document part of a request. To configure no limit, select Any. The default value is based on the defense level: high is 64, medium is 256, and low is Any.
Maximum Namespace LengthSpecifies the largest size the system allows for a namespace in the XML document part of a request. The size is specified in bytes. To configure no limit, select Any. The default value is based on the defense level: high is 256, medium is 1024, and low is Any.

Web services security configuration

In this area of the screen you can specify how the system verifies digital signatures of SOAP messages, digitally signs SOAP messages, and encrypts and decrypts SOAP messages in XML documents.

You can upload client and server certificates. Client and server certificates are used to encrypt and decrypt SOAP messages from a web client to a web server. You can configure when the system validates and encrypts both requests and responses.

Regarding requests:

  • The system does not automatically detect what to decrypt. You should define it with an XPath query, done in the Elements setting of the Namespaces and Elements area after setting Apply to to Request.
  • The system performs XML decryption before WSDL enforcing.
  • The system decrypts the XML payload, checks for an attack, but does not then re-encrypt the payload.

Regarding responses, the system does not automatically encrypt the entire response. If you want the entire response encrypted, enable the Apply Action To Entire Response Body Value setting. If you want to process specific elements in the XML document, then you must write an XPath query to it. This is done in the Elements setting of the Namespaces and Elements area after setting Apply to to Response.

ElementsIn this area you specify which part of the XML document the system processes.

XPath expression rules:

  • Apply to: Specifies what the system verifies. Select either Request or Response from the list.
  • XPath: Specifies which parts of the XML document the system processes by using XPath expressions. Type an XPath expression.
    • Express the queries in abbreviated form.
    • Map all prefixes to a namespace (using the prefix-namespace mechanism).
    • Do not use predicates.
    • For query matches, use elements, not attributes.
    • Relative paths are allowed, for example, /emp:employee/emp:name (where emp is mapped to http://employee.com).
    • Wildcard usage is allowed, for example, //emp:employee/* (where emp is mapped to http://employee.com).
    • If the element name uses general UTF-8 encoding, the query may contain non-English characters.
    • For prefixes, do not use non-ASCII letters.
    • Attributes are not allowed in the query.
  • Encryption Method:Specifies what the system encrypts:
    • With markup: Specifies that the system encrypts the selected element along with the element’s XML markup.
    • Value only: Specifies that the system encrypts only the selected element’s value, that is, the child text and child elements of the selected element.
  • Add: Click the Add button to include the element to be encrypted in the web services security configuration.
  • XPath: Displays the XPath expression you entered in the XPath box.
  • Apply To: Displays what you selected in the Apply To list.
  • Encryption Method: Displays the encryption method you selected in the Encryption Method list.
  • Delete: Click the Delete button to remove the selected element to be encrypted from the web services security configuration.
