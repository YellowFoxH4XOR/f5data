Known Issue

The eam daemon may enter a restart loop when AccessGate is disabled

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured to integrate with Oracle Access Manager (OAM).
  • The OAM AccessGate on the back-end server is disabled.
  • You change the log level for OAM ASDK logging. For example, when implementing the workaround outlined in K82304591: OAM ASDK log files may grow to consume excessive disk space.

Impact

Users are unable to authenticate through OAM while the eam daemon produces a core file and restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You are unable to authenticate to BIG-IP APM resources using OAM.
  • The eam daemon produces core files to the /shared/core/ directory.
  • The eam daemon enters a restart loop.

Workaround

To work around this issue, you can either enable the disabled AccessGate on the OAM server, or remove AccessGate from the BIG-IP APM system. To remove AccessGate from the BIG-IP APM system, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > AAA Servers > Oracle Access Manager.
  3. Click the OAM server.
  4. In the AccessGate List, select the check box next to the unwanted AccessGate.
  5. Click Remove.
