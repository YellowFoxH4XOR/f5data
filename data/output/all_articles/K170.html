Configuring email notification

To configure email notification on BIG-IP or 3-DNS, perform the following steps:

  1. While logged in at the command prompt, check to see if your DNS server is already defined by typing the following command:

    more /etc/resolv.conf

  2. If your DNS server's IP address does not appear, use a text editor, such as vi or pico, to add your network's DNS server IP address(es) to the /etc/resolv.conf file.

    The format for the DNS server in the resolv.conf file is as follows, with one DNS server definition per line:

    nameserver <IP address>

    For example, for two DNS servers with the addresses 172.16.100.1 and 172.16.100.2, the /etc/resolv.conf file would appear as follows:

    nameserver 172.16.100.1
nameserver 172.16.100.2
  3. Verify the DNS resolution for the domain to which you will be sending email, by typing the following command:

    dig <domain> mx

    For example, to query type MX and askf5.com, which is where email is delivered, you would type the following command:

    dig askf5.com mx

    The controller provides the following response, indicating that it is able to resolve the mail exchanger:

    ; <<>> DiG 9.2.2 <<>> askf5.com mx
;; global options:  printcmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 16174
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0
;; QUESTION SECTION:
;askf5.com.                     IN      MX
;; ANSWER SECTION:
askf5.com.              86400   IN      MX      10 mail.f5.com.
;; Query time: 65 msec
;; SERVER: 172.16.100.1#53(172.16.100.1)
;; WHEN: Mon Nov  8 14:32:07 2002
;; MSG SIZE  rcvd: 51
  4. Once you have verified DNS resolution is working correctly, copy the /etc/sendmail.cf.off file to /etc/sendmail.cf by typing the following version-specific command:

    For BIG-IP versions 4.2 - 4.6.2, type:

    cp /config/sendmail.cf.off /config/sendmail.cf

    For BIG-IP versions 2.1.4 - 4.1.1 or 3-DNS 2.0 - 3.0, type:

    cp /etc/sendmail.cf.off /etc/sendmail.cf

  5. Using vi or pico, edit the /etc/sendmail.cf file and edit the DS variable to specify the mail exchange server that the controller resolved through DNS in step 3.

    For example, change:

    #'Smart' relay host (may be null)
DS

    To the following:

    # 'Smart' relay host (may be null)
DSyourmailserver.yournetwork.com
  6. Using vi or pico, edit the /etc/crontab file and remove the comment mark from the last line to prompt Sendmail to send all queued email every 15 minutes. It should now appear as follows:

    0,15,30,45 * * * * root /usr/sbin/sendmail -q > /dev/null 2>&1

Undelivered messages

Because BIG-IP and 3-DNS accept only local email, bounced or undelivered messages go unnoticed. To avoid this, perform the following steps:

  1. Using vi or pico, edit the /etc/aliases file, create an entry that will forward any mail sent to root to a site administrator.

    For example, the following line will cause all email sent to the root account on the BIG-IP or 3-DNS to be forwarded to the email address, youradmin@yournetwork.com:

    root: youradmin@yournetwork.com

  2. The aliases text file is not read directly. To create the aliases.db database file, type the following command:

    newaliases

    You should receive output similar to the following:

    /etc/aliases: 19 aliases, longest 10 bytes, 208 bytes total

The controller is now configured to forward any emails sent to the root account to a remote address.
