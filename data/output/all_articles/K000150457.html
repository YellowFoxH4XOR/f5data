Description

When you try to generate UCS backup either from GUI or CLI, you gets below error message.

Unexpected Error: Can't create temp directory, /var/tmp/.config.tmp/cfNlgL, errno 28] No space left on device
Error during config save.
Unexpected Error: UCS saving process failed.

There is enough space left in /var directory but /shared directory is 100% utilized.

Environment

  • BIG-IP

Cause

/shared directory is 100% full

Recommended Actions

Though the backup are stored in /var/local, the shared directory is full, this can cause the UCS backup generation to fail. You will need to idenify which files are consuming largest disk space and delete this. You can refer K14403: Maintaining disk space on the BIG-IP system.

Run the below command to display the 20 largest files/folders, excluding files/folders that are expected to be large:
find /shared/ -xdev -type f -exec du -h {} \; | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -20

For example if you see a long list of shared/tmp/rpm-tmp files even though you are not using iApps. You can delete them by running below command.
rm -rvf /shared/tmp/rpm-tmp*

These files may reappear. For more information check out  K90721117: The /shared/tmp directory is full of rpm-tmp files.
