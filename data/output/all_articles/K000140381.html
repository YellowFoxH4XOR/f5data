K000140381: Websocket traffic is failing when ASM Policy is removed from Virtual Server

Type
Support Solution
Published
2024-07-18
Updated
2024-07-19
Applies to
  • BIG-IP
  • BIG-IP ASM: 15.1.7
Source
https://my.f5.com/manage/s/article/K000140381

Description

When removing ASM Security Policy from a Virtual Server, websockets traffic is Not being passed to the back-end pool member.

When applying ASM Security Policy back to the Virtual Server, websockets traffic is being passed to the back-end pool member.

 

  • tcpdump will show that after 'Switching Protocols', the LTM is not passing 'WebSocket Binary' frame from the client to the back-end server.
  • There is no error message. But tcpdump will show: Connection Close (8) with status: WebSocket Status code: Going Away (1001)
  • The configuration in bigip.conf will show the Virtual Server still has /Common/websecurity profile applied. Not visible from GUI.
  • The configuration in bigip.conf will show the LTM Policy pointing to the ASM Policy (when applied to VS), has a name that is not the default, like when managed from the GUI. (asm_auto_l7_policy__Virtual-Server-Name)

 

 

Environment

  • BIG-IP ASM Security Policy
  • BIG-IP LTM Policy

 

 

Cause

The websecurity profile stops traffic when ASM is not used, and the HTTP profile is placed in passthrough mode.

 

Recommended Actions

The workaround is to manually remove the websecurity profile, when removing ASM policies from the Virtual Server.

Command: tmsh modify ltm virtual [Virtual_Server_Name] profiles delete { [websecurity_profile_name] }

 

Additional Information

When ASM policy is removed from a virtual server via tmsh, the websecurity profile is *not* removed. When ASM policy is removed through the GUI, the websecurity profile is removed automatically. The websecurity profile appears to be completely hidden through the GUI.

 

Note: That can happen with HTTP::disable or websockets - possibly other situations.
