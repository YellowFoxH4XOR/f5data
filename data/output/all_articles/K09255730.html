K09255730: MySQL down after upgrade

Type
Support Solution
Published
2025-08-14
Updated

Applies to

  • Private Cloud

Source
https://my.f5.com/manage/s/article/K09255730

Description
After the upgrade, MySQL is down.

Environment

  • ASM is provisioned
  • AVR is provisioned

Cause
This issue could be caused for multiple reasons, the most commons are: lack disk space, insuffient memory, files corrupt.

An example of the issue, could be: 

# tmsh show sys service | egrep down | egrep -v 'Not provisioned|unsupported|not enabled|not required|No action'
asm          down, waiting for mysql to release running semaphore
botd         down, waiting for asm to release ready semaphore

localdbmgr   down, waiting for mysql to release running semaphore
logmysqld    down, waiting for mysql to release running semaphore
mdmsyncmgr   down, waiting for mysql to release running semaphore
monpd        down, waiting for mysql to release running semaphore
mysql        down, Failed to initialize MySQL
oauth        down, waiting for mysql to release running semaphore

Recommended Actions

To resolve this issue, here are the possible options:

Option 1. Restore the configuration from UCS file.

Option 2. Move ibdata1, ib_logfile0 and ib_logfile1 to /shared, restart msql and then load ucs if needed.

# mv ibdata1 ib_logfile0 ib_logfile1 /shared/
# tmsh restart /sys service mysql


Option 3.  If  1 does not fix this, rollback to previous version and reinstall software.
