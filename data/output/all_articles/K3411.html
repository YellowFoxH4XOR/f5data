K3411: Creating a new CSR without overwriting the existing key and certificate

Topic

When you create a certificate request, you have the option of giving the key/certificate pair a Key Identifier. The Key Identifier is the name of the key file that is stored on the file system in BIG-IP.

Note: For information about creating Client Signing Requests, refer to the SSL Accelerator Proxies chapter in the BIG-IP Reference Guide.

Note: For BIG-IP 9.x and later, refer to K7573: Renewing Certificate Authority signed SSL certificates based on new private SSL key or the Managing SSL Traffic chapter in the Configuration Guide for BIG-IP Local Traffic Management.

When naming your key file, F5 recommends (as stated in the BIG-IP online Help file) that you use your fully qualified domain name as the file name. To overwrite an existing Key Identifier, you would select the Key Identifier from the list next to the input box.

However, if your company security policy dictates that you generate a new CSR for each renewal, you can use a Key Identifier naming convention that aids in compliance with this policy. Instead of overwriting the old key when you create a new CSR, use a Key Identifier that includes the expiration date. This makes each of the keys unique.

For example, instead of using www.company.com, use www.company.com_04APR2011.

This Key Identifier naming convention will prevent the BIG-IP system from invalidating active key/certificate pairs that exist on the BIG-IP system when you create a new CSR. Creating a unique key each time avoids the problem of overwriting data that the BIG-IP system is using. Your Certificate Authority will issue a new, signed certificate, which you would associate with the newly generated key. Once you install and test the new CSR, you can safely remove the old key and CSR.
