Known Issue

Access sessions may unexpectedly terminate.

This issue occurs when all of the following conditions are met:

  • You configure the access policy to run continuous Client-Side Endpoint Security software checks.
  • Users establish access sessions using Windows devices.
  • There is an end user device configuration or state change during the access session.

    For example:

    • The antivirus database version is updated
    • The last antivirus scan time is updated
    • The monitored software version changes

Impact

The access session is terminated.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The established access session is terminated after the connected device has a configuration or state change.
  • In the /var/log/apm file, you observe log messages similar to the following example:

    notice apd[<pid>]: 01490113:5: 06a75616: session.check_software.last.pm.item_1.errors is -41 - No route to server - Invoke(MID_PATCHMANAGEMENTAGENT_DETECTMISSINGPATCHES, &searchCriteria, &missingPatches)

  • In the BIG-IP Edge Client log, you observe log messages similar to the following example:

    48,2014-12-03,14:49:20:182,OesisInspector,2784,1692,server configuration check list ===>Type: av
    48,2014-12-03,14:49:20:450,OesisInspector,2784,1692,testing product: id=6009
    48,2014-12-03,14:49:20:450,OesisInspector,2784,1692,found property,state=1
    48,2014-12-03,14:49:20:453,OesisInspector,2784,1692,leave (check passed)
    48,2014-12-03,14:49:20:453,POLICY_SERVER,2784,3964,Check result changed (reference:"<reference value>").
    0,2014-12-03,14:49:20:454,POLICY_SERVER,2784,3964,Policy check failed (session ID:"<session id value>").
