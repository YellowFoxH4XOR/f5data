Description

  • after upgrading vCMP guests, the initial-image and initial-hotfix parameters on the vCMP host configuration retain their original values
  • administrators may want to perform housekeeping or update the parameter to reflect the actual version running on the guests
  • out of support or end-of-life 'initial' software definitions need to be updated to recent, supported versions

Environment

  • vCMP platforms

Cause

It is important to understand what the initial-image and/or initial-hotfix parameters are used for. These settings are used when deploying guests for the first time. It is also used to expand guests to additional slots later on. Lastly,  these parameters are used when a blade is added or replaced, to restore the guest configuration to the new/ replacement hardware. The configuration lines added on the vCMP host's configuration file are not updated when the vCMP guests are upgraded. While these settings do not have any relevance to succeeding startups or reboots of existing vCMP guests, the "initial-image" ISO file must remain present on the device. 

Recommended Actions

On the vCMP host, the following commands can be used to modify the parameters:

# tmsh modify /vcmp guest <guest_name) state configured
# tmsh modify /vcmp guest <guest_name> initial-image <image_iso_filename> initial-hotfix <hotfix_iso_filename>
# tmsh save /sys config
# tmsh modify /vcmp guest <guest_name> state deployed


Additional Information

1. The initial-image and initial-hotfix parameters only matter if you are using a bladed system.

2. The initial-image can be set to any version as long as it does not go higher than the lowest version installed on the guest, i.e. if you have a version 14.1.4 and a 16.1.2 boot volume on the vCMP guest, then your initial-image can be anything lower than 14.1.4.

3. If you are using a non-bladed vCMP system, then you should be able to set the initial-image and initial-hotfix parameters to 'none' safely as you will need use an ISO and UCS to restore your vCMP guests anyway. This will also allow you to avoid having to store an extra ISO in the vCMP host /shared/images directory.

4. You should have the ISO files for the declared initial-image and initial-hotfix parameters stored on the vCMP host system.
