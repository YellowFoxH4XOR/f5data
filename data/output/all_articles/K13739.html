Topic

Purpose

You should consider using this procedure under the following condition:

  • You want to enable the NSM warm restart feature on an ARX system upgraded from a version prior to 6.1.0.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You are running version 6.1.0 or later
  • Your ARX platform includes one of the following:

    • ARX-1000
    • ARX-2000
    • ARX-4000
    • ARX-6000

Description

In versions prior to 6.1.0, the ARX system used an NSM recovery (reanimation) feature to recover from NSM cores. An issue with the NSM recovery feature is that once an NSM reanimates, not all cores within the same device can be Up again without reloading.

Starting in version 6.1.0, the NSM warm restart feature restarts only the NSM core that crashed; other cores within the same device are unaffected. When restarted, the NSM comes back Up (not in Standby) and resumes its normal traffic load. On upgrade from prior versions, the NSM warm restart feature remains off. On new installations of versions 6.1.0 or later, the NSM warm restart feature is enabled by default.

Note: While the NSM is in the process of restarting, the state is visible through the show processor command.

Procedures

Enable the NSM warm restart feature

Impact of procedure: None.

  1. Log in to the ARX CLI using the console.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter config mode by typing the following command:

    config
  4. Enable the NSM warm start feature by typing the following command:

    nsm warm-restart

Supplemental Information

  • For more information about the nsm warm-restart command, refer to the ARX CLI Reference Guide
  • For more information about the NSM recovery feature, refer to the Redundant Pairs chapter in the ARX CLI Reference Guide
