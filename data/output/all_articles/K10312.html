Known Issue

This is the result of a known issue. Under certain circumstances, such as installing a UCS file on the system from a previous versions, or performing an upgrade, the Events data may be present and cause configsync operations to timeout.

Note: Beginning in BIG-IP ASM version 9.4.5, the BIG-IP ASM UCS archive no longer contains the Events data. For more information, refer to K7233: Change in Behavior: The BIG-IP ASM UCS no longer contains Forensic and Events data. 

F5 Product Development tracked this issue as CR104630 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

If you have installed a UCS file from a version of BIG-IP ASM prior to 9.4.5 and the configsync process is failing or timing out, you can prevent the system from synchronizing Events data by performing the following procedure:

  1. Log in to the command line.
  2. Use a text editor to edit the /usr/libdata/configsync/cs.dat file.
  3. If the following lines in the file /usr/libdata/configsync/cs.dat file are uncommented in the UCS file, change them to the following:

    # ASM events -
    #save.xxxx.save_pre      = ([ -e /ts/tools/event_backup.pl ] && /ts/tools/event_backup.pl save 1>&2 )
    #save.xxxx.file          = /var/tmp/ts_events.tar.gz.cstmp
    #save.xxxx.save_post     = (rm -f /var/tmp/ts_events.tar.gz.cstmp)
  4. Save the changes and exit the file.
