K000161645: UCS Backup Failure with iAppLX Timeout After UCS Restore on RMA-Replaced BIG-IP LTM Unit

Type
Support Solution
Published
2026-06-09
Updated
2026-06-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161645

Description

  • UCS backup creation fails on a BIG-IP LTM unit after hardware replacement and UCS restore. 
  • Attempts to save UCS via CLI or GUI result in timeouts and errors related to iAppLX, such as "Failed to wait for restnoded rpm-spec-creator: java.util.concurrent.TimeoutException."
  • The issue is isolated to the replaced unit
  • the HA peer operates normally.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1
  • Deployment: Active/Standby HA pair
  • iAppLX extensions installed 
  • Recent actions: Hardware replacement (RMA) and UCS restore performed on one unit

Cause

After UCS restore on the RMA-replaced unit, the restnoded process failed to start critical workers due to missing or unavailable dependencies. This left the iAppLX REST infrastructure in a degraded state, preventing the RPM build process required during UCS save from completing within the default timeout period.

Answer/Recommended Actions

Immediate workaround: Restart REST services

 

  1. Log in to the affected BIG-IP unit via SSH.
  2. Restart the restjavad and restnoded services:

    bigstart restart restjavad restnoded

  3. Wait for services to fully restart, then attempt the UCS backup again:

    tmsh save sys ucs <filename>.ucs
