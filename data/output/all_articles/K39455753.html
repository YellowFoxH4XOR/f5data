Known Issue

A FastL4 virtual server using an iRule that suspends processing may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

Note: The term "suspend" is commonly referred to as "park" or "parking."

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server to use a FastL4 profile.
  • The virtual server references an iRule that uses a command that suspends processing. For more information, refer to K12962: Some iRule commands temporarily suspend iRule processing.
  • The iRule command is triggered by a SERVER_CLOSED event.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system unexpectedly fails over to another system in the device group.
  • The BIG-IP system temporarily fails to process traffic.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

To work around this issue, you may be able to reconfigure your iRule to either not use commands that suspend processing, or not have them triggered by the SERVER_CLOSED event.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window, with consideration to the possible impact on your specific environment.
