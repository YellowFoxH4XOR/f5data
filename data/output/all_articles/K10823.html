K10823: TMM may restart due to a slow memory leak when persistence and mirroring is enabled

Known Issue

This is the result of a known issue. When a high availability pair is configured to use persistence, and mirroring is enabled within the persistence profile, the BIG-IP improperly stores mirrored persistence records. This prevents the associated memory from being released when the idle timeout expires. As a result, memory consumption will increase over time and TMM may restart due to memory exhaustion.

F5 Product Development tracked this issue as CR126550 and it was fixed in BIG-IP LTM version 10.1.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
