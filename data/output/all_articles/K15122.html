Topic

Force Offline is a maintenance operation that puts the BIG-IP system into an offline state; systems in this state do not pass traffic.

Description

Force Offline puts the BIG-IP unit system an offline state, during which time the device does not respond to or process local traffic connections. A typical use for this feature is when you want to perform maintenance on a BIG-IP system. When the maintenance is complete and the system is functional, you can return the unit to an online state.

Force Offline behavior

The following describes the behavior when Force Offline is enabled for the BIG-IP system:

  • Enabling Force Offline does not prevent BIG-IP DNS (formerly BIG-IP GTM) systems from performing metrics collection and monitoring functions. To prevent the BIG-IP DNS system from performing metrics collection and monitoring functions, you can stop the big3d process after enabling Force Offline, and then restart the process after disabling Force Offline. To do so, refer to the Enabling Force Offline using tmsh procedure.
  • Enabling Force Offline does not prevent BIG-IP DNS from responding to queries when the listener is a self IP address.
  • When the BIG-IP system enters the Force Offline state, the BIG-IP system terminates existing connections to local traffic objects (virtual server, SNATs, and so on) and does not allow new connections.
  • In BIG-IP 11.1.0 and later, the Force Offline status persists through system restarts and upgrades. In previous versions, the Force Offline status does not persist through system restarts.
  • The BIG-IP system allows administrative connections to the management address to continue.
  • The BIG-IP system handles administrative connections to self IP addresses differently, depending on the platform:
    • On appliance systems, the system maintains connections to self IP addresses.
    • On VIPRION systems, the system terminates connections to self IP addresses and does not allow new connections.

      Note: When you enable Force Offline, the Traffic Management Microkernel (TMM) interfaces remain configured until the unit is restarted. If the system is restarted while Force Offline is enabled, the system marks all TMM interfaces as Uninitialized or Missing. This behavior is by design; the system does not attempt to initialize and bring up TMM interfaces while the system is in the offline state.

    • On Virtual Clustered Multiprocessing (vCMP) guests and F5OS tenants, access to self IP addresses operates as follows:
      • For vCMP guests on appliance platforms and F5OS tenants on r2000 and r4000 series systems, the system maintains connections to self IP addresses.
      • For F5OS tenants on r5000, r10000, and r12000 series systems, the system maintains connections to self IP addresses.

        Note: As a result of Bug ID 1291121, a tenant that is Forced Offline on an r5000, r10000, or r12000 series system may terminate most connections to self IP addresses, and does not allow new connections.

      • For vCMP guests and F5OS tenants on VIPRION or VELOS platforms, the system terminates connections to self IP addresses, and does not allow new connections.

    Important: To place a VIPRION system, a vCMP guest on a VIPRION, or a VELOS tenant into an offline state while still allowing self IP connectivity, refer to the Setting Minimum Blades Up on VIPRION systems, clustered vCMP guests, or VELOS tenants procedure.

  • Using Force Offline feature on guest systems running on VIPRION or VELOS platforms, affects an update of management IP for the guest system. Host system correctly informs guest system about new management IP, but the guest system remains reachable on the previous management IP until Force Offline is released. This behavior is by design. F5 recommends using Setting Minimum Blades Up before updating management IP for guest systems.
  • In BIG-IP 11.5.3, 11.6.0 HF6, 12.0.0 and later, the bigd process does not send monitor traffic to pool members and nodes when the system is offline and does not update the state of the monitored objects. This results in the following behavior:
    • When the BIG-IP system starts with Force Offline enabled, monitored nodes and pool members are initially marked Unchecked, then remain Unchecked until Force Offline is released.
    • While the BIG-IP system has Force Offline enabled, newly created nodes and pool members are initially marked Unchecked, then remain Unchecked until Force Offline is released.
    • Monitored nodes and pools that are green (Available) when enabling Forced Offline remain Available while Force Offline is enabled.
  • The BIG-IP system displays the Force Offline (enabled) status as follows:
    • The command line prompt displays the following:

      ForcedOffline

    • The Configuration utility displays FORCED OFFLINE in the top left corner of the screen.
  • Selecting Force Offline activates the Release Offline button.
  • Selecting Release Offline releases the unit from its forced offline state.

Procedures

To watch a video demo of the Configuration utility procedures, go to  K000156768: Force Offline your BIG-IP device using the BIG-IP Configuration utility.

  • Enabling Force Offline using the Configuration utility (device group)
  • Enabling Force Offline using the Configuration utility (standalone)
  • Enabling Force Offline using tmsh
  • Enabling Force Offline using iControl REST
  • Setting Minimum Blades Up on VIPRION systems, clustered vCMP guests, or VELOS tenants

Enabling Force Offline using the Configuration utility (device group)

Impact of procedure: The BIG-IP system terminates existing connections to local traffic objects and does not allow new connections.

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. Select the local device (Self).
  4. Select Force Offline.

    Note: To release the unit from its Forced Offline state, select Release Offline.

Enabling Force Offline using the Configuration utility (standalone)

Impact of procedure: The BIG-IP system terminates existing connections to local traffic objects and does not allow new connections.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to System > Configuration > Device > General.
  3. Select Force Offline.

    Note: To release the unit from its Forced Offline state, select Release Offline.

Enabling Force Offline using tmsh

Impact of procedure: The BIG-IP system terminates existing connections to local traffic objects and does not allow new connections.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable Force Offline, type the following command:

    run /sys failover offline

  3. Save the configuration by typing the following command:

    save /sys config

  4. For BIG-IP DNS systems, to disable metrics collection and monitoring functions, type the following command:

    stop /sys service big3d

    Note: To release the unit from its Forced Offline state, use the tmsh run /sys failover online command.

    Note: For BIG-IP DNS systems, type the following command to re-enable metrics collection and monitoring functions: tmsh start /sys service big3d.

Enabling Force Offline using iControl REST

Impact of procedure: The BIG-IP system terminates existing connections to local traffic objects and does not allow new connections.

  1. Log in to a workstation with curl and jq utilities.
  2. To enable Force Offline, type the following iControl REST command:

    curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<management IP address>/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh run /sys failover offline\""}' | jq -M .

    For example,

    curl -sku admin:admin -H "Content-Type: application/json" -X POST https://192.168.1.100/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh run /sys failover offline\""}' | jq -M .

    Note: To release the unit from its Forced Offline state, change the offline in the iControl REST command to online: curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<management IP address>/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh run /sys failover online\""}' | jq -M .

  3. For BIG-IP DNS systems, to disable metrics collection and monitoring functions, type the following i Control REST command:

    curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<management IP address>/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh stop /sys service big3d\""}' | jq -M .

    For example,

    curl -sku admin:admin -H "Content-Type: application/json" -X POST https://192.168.1.100/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh stop /sys service big3d\""}' | jq -M .

    Note: For BIG-IP DNS systems, change stop to start in the iControl REST command to re-enable metrics collection and monitoring functions: curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<management IP address>/mgmt/tm/util/bash -d '{"command":"run", "utilCmdArgs":"-c \"tmsh start /sys service big3d\""}' | jq -M .

Setting Minimum Blades Up on VIPRION systems, clustered vCMP guests, or VELOS tenants

On a VIPRION system, a vCMP guest running on VIPRION, or a tenant running on VELOS, you can force it offline while maintaining self IP connectivity using the Minimum Blades Up setting to intentionally trigger a failsafe condition.

Impact of procedure: While the system is offline it does not accept connections to local traffic listeners, such as virtual servers or SNATs.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Set Minimum Blades Up to a number that is greater than the total number of blades, or in the case of a guest or tenant, greater than the number of slots assigned to it. For example, in a VIPRION chassis with four blades, set Minimum Blades Up to 5, by typing the following command:

    modify /sys cluster default min-up-members 5

  3. Enable the Minimum Blades Up setting by typing the following command:

    modify /sys cluster default min-up-members-enabled yes

  4. To revert, perform steps 1 through 3, then for Minimum Blades Up in step 2, enter a value lower than the number of current available blades. The VIPRION system should change to Standby mode if you recently added it to a device group or Active if it is a standalone system.

Recommendations

When using the Force Offline, consider the following factors:

  • When using Force Offline for VIPRION or VELOS platforms, make sure to manage the system by using the management port or console; connections to self IP addresses are terminated when Force Offline is enabled. If you need to maintain self IP connectivity, for example to perform DSC maintenance work, do not use Force Offline. Instead, refer to Setting Minimum Blades Up on VIPRION systems, clustered vCMP guests, or VELOS tenants.
  • If you are making changes to a BIG-IP system that affects the redundancy state, such as resetting the device trust for a device group, F5 recommends that you enable Force Offline for the standby devices in the device group before performing the procedure. Doing so prevents a standby device from unexpectedly going active. After you perform this procedure, you should set standby devices that were set to Force Offline to Release Offline.
  • When Force Offline is enabled in BIG-IP 11.5.3, 11.6.0 HF6, 12.0.0, and later, the BIG-IP system stops sending monitor traffic to pool members and node and does not update monitor states. Monitored pool members and nodes remain in the last known state until you release Force Offline.
