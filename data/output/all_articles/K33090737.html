Description

BIG-IP management interface is inaccessible via HTTPS/SSH after a management IP address change

Environment

  • One or more BIG-IP devices configured in an HA pair
  • Changes made to the management Interface IP address of  the first BIG-IP device (BIG-IP-1) 
  • BIG-IP-1 is only accessible via HTTPS/SSH through the management Interface from peer BIG-IP device
Cause

The new management IP address is potentially duplicated on the network.  No information is logged regarding a duplicate IP address on the network.
Additionally, by virtue of the Device Trust, the new (duplicate) IP address is communicated to the peer, enabling HTTPS/SSH communication between the peers, despite the duplicate IP address on the network.

Recommended Actions

Ensure the BIG-IP management IP address is a unique address on the network. For information on changing the management IP address, refer to K13284: Overview of management interface routing (11.x - 16.x)

Attempt to ping the management-route gateway IP address from the CLI of the BIG-IP where the management IP address change was made. 

Additional Information

The management-route gateway information can be found using the following command:
tmsh list /sys management-route

Example Command Output:
tmsh list /sys management-route
sys management-route default {
    gateway xxx.xxx.xxx.xxx
    network default
}


Using the command below, confirm whether or not ARP entries exist in the ARP table for the configured management-route gateway.  If this ARP entry does not exist, this is an indicator of a potential duplicate IP address.
arp -a | grep <gateway IP Address>
