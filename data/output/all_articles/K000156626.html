K000156626: TACACS+ account unable to login to the GUI after F5OS upgrade

Type
Support Solution
Published
2025-09-25
Updated
2025-09-25
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.0
Source
https://my.f5.com/manage/s/article/K000156626

Description

After upgrading F5OS from version 1.7 to 1.8.0, logging into the GUI with a TACACS+ account may fail. However, logging in via SSH with the same TACACS+ account succeeds. Audit logs may show repeated entries similar to:

2025-08-18T16:22:32.468481+09:00 HOSTNAME audit-service[16]: priority="Notice" version=1.0 msgid=0x1f03000000000002 msg="audit" user="[withheld]/0" cmd="external token authentication failed via rest from 172.27.121.4:0 with http: ERROR: PAM validation failed: User role modified".

2025-08-18T16:22:32.470499+09:00 HOSTNAME audit-service[16]: priority="Notice" version=1.0 msgid=0x1f03000000000002 msg="audit" user="[withheld]/0" cmd="login failed via rest from 172.27.121.4:0 with http: noauth".

Environment

  • F5OS 1.8.0
  • Authentication: TACACS+ (Cisco ISE as TACACS+ server)
  • Typical TACACS+ profile attributes:
    • F5-F5OS-UID
    • F5-F5OS-GID
    • F5-F5OS-HOMEDIR
    • F5-F5OS-USERINFO

Cause

F5OS 1.8.0 GUI authentication fails if the TACACS+ profile’s home directory attribute (F5-F5OS-HOMEDIR) contains a trailing whitespace (e.g., "/tmp "). This whitespace causes the session token to be parsed incorrectly, resulting in failed GUI authentication, while SSH authentication remains unaffected.

Recommended Actions

  • Review the TACACS+ profile configuration on the authentication server (e.g., Cisco ISE).
  • Ensure that the F5-F5OS-HOMEDIR attribute does not contain any trailing whitespace. For example, use:

    F5-F5OS-HOMEDIR="/tmp" 

  • After correcting the attribute, attempt GUI login again with the TACACS+ account.
