K000152859: After upgrading the device from 16.x to 17.1.X unable to failover the traffic

Type
Support Solution
Published
2025-08-02
Updated
2025-08-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000152859

Description

After upgrading BIG-IP LTM devices from version 16.x to 17.1.2.2 in an Azure High Availability (HA) environment, HA failover does not operate as expected. When a failover is triggered, the device status changes but traffic does not shift to the new active device. 

Attempts to validate the Cloud Failover Extension (CFE) installation using curl commands to the CFE REST endpoint return a 404 error:

{

"code": 404,

"message": "",

"referer": "Unknown",

"errorStack": []

}

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.2.2 (upgraded from 16.x)
  • Platform: Azure VM
  • Configuration: High Availability (HA) pair
  • Feature: Cloud Failover Extension (CFE)

Cause

The Cloud Failover Extension (CFE) is not functioning correctly after the upgrade, resulting in HA failover not properly shifting traffic.

Recommended Actions

  • Validate CFE installation by querying its REST endpoint; a 404 response indicates it is missing or malfunctioning.
  • Uninstall and reinstall the Cloud Failover Extension (CFE) using the official package from F5’s GitHub repository.
  • After reinstalling, verify that queries to the CFE REST endpoint return valid responses.
  • Perform HA failover testing to confirm that traffic shifts correctly between devices.
  • Ensure both units in the HA pair have CFE installed and upgraded if both are running BIG-IP version 17.x.
