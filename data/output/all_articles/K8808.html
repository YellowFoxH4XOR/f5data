Topic

Terminal Access Controller Access-Control System Plus (TACACS+) is a protocol used to provide access control for network devices through the use of one or more centralized servers. It provides for separate authentication, authorization and accounting services over TCP. By default, TACACS+ uses TCP port 49.

Note: TACACS+ is a Cisco-designed protocol based off of the TACACS protocol. TACACS+ is not compatible with previous versions of TACACS.

BIG-IP supports TACACS+ authentication for application authentication through a virtual server and for local BIG-IP administrative user authentication. Additionally, starting in BIG-IP 10.2.0, TACACS+ accounting is also supported.

Important: The BIG-IP system must be licensed for client authentication in order to use TACACS+ application authentication through a virtual server. Local BIG-IP administrative user authentication does not require a license for client authentication but is only available on BIG-IP 9.4.2 and later.

Authentication using TACACS+ is comprised of two separate objects:

  • The authentication configuration object that specifies the servers, secret or password, protocol to use, and general behavior to communicate with the TACACS+ server(s).
  • The authentication profile that is associated with the virtual server, to allow the virtual server to pass authentication requests to the TACACS+ server(s).

Authentication Configuration object for TACACS+

The authentication configuration object provides the general configuration that the authentication profile will used to communicate information with the TACACS+ server(s).

General Properties

The TACACS+ authentication configuration object consists of the following General Properties:

  • Name: Name of the configuration, used by the TACACS+ authentication profile to reference the TACACS+ configuration object
  • Type: Used to specify the type of authentication configuration, in this case TACACS+

Configuration

The TACACS+ authentication configuration object consists of the following configuration elements:

Servers
Specifies the IP address(es) of the TACACS+ server(s) that will be used to authenticate users.

Secret
Specifies the shared key used to encrypt/decrypt packets that are sent or received from the server(s).

Note: This key must be identical to the shared key configured on the TACACS+ servers or encryption/decryption will not occur.

Confirm Secret
Specify the same key used in the Secret field.

Encryption (Default - Enabled)
Specifies whether you want to use encryption. If disabled, no encryption occurs and the username, password, and response from the server is sent in clear text.

Service Name
Specifies the name of the service that the user who is requesting to be authorized will use. Identifying the service name enables the TACACS+ server to behave differently for different types of authorization requests. Specifying this setting is required. You can use the following values:

Note: The following values are those specified by the TACACS+ specification from Cisco Systems.

  • slip: Serial Line Internet Protocol SLIP authorization check.
  • ppp: Point-to-Point Protocol PPP authorization check.
  • arap: AppleTalk Remote Access Protocol AppleTalk Remote Access authorization check.
  • shell: EXEC startup and EXEC command authorization checks.
  • tty-daemon: TTY daemon authorization checks.
  • connection: Enables accounting or authorization checks for outbound telnet and rlogin.
  • system: Enables accounting or authorization checks for all system-level events not associated with users, such as reloads.
  • firewall: Enables account or authorization checks for firewall communication.

Protocol Name
Specifies the protocol associated with the value specified in Service Name, which is a subset of the associated service being used for client authorization or system accounting. You can use the following values:

Note: The following values are those specified by the TACACS+ specification from Cisco Systems.

  • lcp: LCP (lower layer of PPP) authorization request.
  • ip: Modifier used with service=slip or service=ppp to indicate protocol layer for authorization check.
  • ipx: Modifier used with service=ppp to indicate protocol layer for authorization check.
  • atalk: Modifier used with service=ppp or service=arap to indicate protocol layer for authorization check.
  • vines: Modifier used with service=ppp for VINES over PPP.
  • lat: Local Area Transport used by DEC
  • xremote: Compressed transformation of the X Window System protocol, used on relatively slow serial lines
  • tn3270: Telnet 3270 used for sending and receiving 3270 data streams using the Telnet protocol
  • telnet: Telnet protocol
  • rlogin: Remote Login protocol
  • pad: Packet Assembler/Disassembler, communication protocol that provides multiple asynchronous terminal connectivity to an X.25 network
  • vpdn: Virtual Private Dial-Up Networking
  • ftp: File Transport Protocol
  • http: HyperText Transport Protocol
  • deccp: DECnet Control Protocol, commonly referenced as DNCP - DecNet Control Protocol
  • osicp: OSI Control Protocol commonly refered OSINLCP - PPP OSI Network Layer Control Protocol RFC1377
  • unknown: Used with undefined or unsupported conditions.

The following options are displayed when the Advanced Configuration option is selected.

Authentication
Specifies the process the system employs when sending authentication requests.

The options available for Authentication are the following:

  • Authenticate to first server: (Default) Specifies that the system sends authentication attempts to only the first server in the list.
  • Authenticate to each server until success: Specifies that the system sends an authentication request to each server until authentication succeeds, or until the system has sent a request to all servers in the list.

    Note: If all servers on the list are attempted but no response occurs, authentication will fail.

Accounting Information
Specifies how the BIG-IP system returns accounting information, such as which services users access and how much network resources they consume, to the TACACS+ server.

Note: Support for TACACS+ accounting was introduced in BIG-IP 10.2.0. Although the Accounting Information menu appears in earlier versions, it is only used by BIG-IP systems running versions 10.2.0 and later.

  • Send to first available server: (Default) Specifies that the system transmits accounting information back to the first available TACACS+ server in the list.
  • Send to all servers: Specifies that the system transmits accounting information back to all TACACS+ servers configured within the authentication object.

Debug Logging
Enable or disable syslog debugging information at LOG_DEBUG level. Enabling this setting is not recommended for normal use. The default setting is Disabled.

Note: When enabled, debug logging information is logged to the /var/log/secure file.

  • Enabled: Turns on debugging information.
  • Disabled: Turns off debugging information.

Authentication Profile for TACACS+

The authentication profile specifies which authentication configuration object should be referenced, allows specification of alternate iRule to use, and idle timeout to use. The authentication profile is associated and used by the virtual server that will communicate with TACACS+ servers for user authentication.

General Properties

The TACACS+ authentication profile consists of the following General Properties:

Name
Name of profile, allows for easy reference

Type
Type of authentication profile, in this case TACACS+

Parent Profile
The name of the parent profile this profile (child profile) inherits its configuration from.

Configuration

The TACACS+ authentication profile consists of the following configuration elements:

Mode
Specifies whether you want to enable or disable remote authentication.

  • Enabled: (Default) Turns on remote application authentication.
  • Disabled: Turns off remote application authentication.

Configuration
Select the name of the TACACS+ authentication configuration object you previously created.

Rule
Select an existing iRule that corresponds to the profile type. For each profile type, there is a default, system-supplied iRule. You can select the default iRule or select a custom iRule that you have created.

Idle Timeout
Select the duration in seconds that an authentication or authorization request is idle before timing out.

  • Specify: Specifies the number of seconds that an authentication or authorization request can be idle before timing out. The default is 300.
  • Indefinite: Specifies that an authentication or authorization request should remain idle indefinitely.
