Description

Unable to access the device via GUI with the following error in  /var/log/httpd/httpd_errors 
emerg httpd[11199]: [ssl:emerg] [pid 11199] AH02204: Init: Pass phrase incorrect for key of localhost.localdomain:443
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D0680A8:asn1 encoding routines:ASN1_CHECK_TLEN:wrong tag
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D08303A:asn1 encoding routines:ASN1_TEMPLATE_NOEXP_D2I:nested asn1 error
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D0680A8:asn1 encoding routines:ASN1_CHECK_TLEN:wrong tag
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D07803A:asn1 encoding routines:ASN1_ITEM_EX_D2I:nested asn1 error (Type=RSA)
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:04093004:rsa routines:OLD_RSA_PRIV_DECODE:RSA lib
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D0680A8:asn1 encoding routines:ASN1_CHECK_TLEN:wrong tag
emerg httpd[11199]: [ssl:emerg] [pid 11199] SSL Library Error: error:0D07803A:asn1 encoding routines:ASN1_ITEM_EX_D2I:nested asn1 error (Type=PKCS8_PRIV_KEY_INFO)
 

Environment

BIG-IP configuring httpd setup using a private key with a passphrase


Cause

This log is related to the Configuration utility's device certificate issue and the message usually indicates an issue reading the passphrase file for the device certificate key.

emerg httpd[29379]: [ssl:emerg] [pid 29379] AH02204: Init: Pass phrase incorrect for key of localhost.localdomain:443


Recommended Actions

Please verify that the certificate matches the checksum of the key and set the correct permission.
1. Connect to CLI
2. Verify that the certificate matches the checksum of the key.Try these commands:
- To get the md5sum of the cert

 openssl x509 -in /config/httpd/conf/ssl.crt/server.crt -pubkey -noout | md5sum

- To check the md5sum of the key

 openssl rsa -in /config/httpd/conf/ssl.key/server.key -pubout | md5sum

Note: If not match, please review and consider the following article first: K46055636: Device GUI is not loading / CLI working fine

3. If the above md5sum has the same value, you can try to below steps.

- To verify if /config/httpd/conf.d/passphrase.<sh> file permission is set correctly. 
Note: The actual file extension is .sh instead of .<sh>.

The name of passphrase.<sh> can be different such as pass.<sh>

Its permission should be

passphrase.<sh> -r-x------

- If not set correctly, change /config/httpd/conf.d/passphrase.<sh> mode to 500

chmod 500 /config/httpd/conf.d/passphrase.<sh>

4. Make a dummy change so that MCPD picks up the template.

  tmsh modify sys httpd ssl-verify-depth 11
  tmsh modify sys httpd ssl-verify-depth 10

5. Restart httpd
  bigstart restart httpd

If the above does not help, please verify and confirm you followed the correct steps described in the below article.
K9114: Creating a new SSL device certificate and key pair
K42531434: Replacing the Configuration utility's self-signed device certificate with a CA-signed device certificate
