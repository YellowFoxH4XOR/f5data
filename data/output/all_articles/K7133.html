K7133: Adding the RULE_INIT event to an iRule after it has been assigned to a virtual server causes configuration issues

Known Issue

If the RULE_INIT event is added to an iRule after the iRule has been assigned to a virtual server, it can cause configuration errors if the iRule is later removed from the virtual server. The iRule engine does not initialize variables and events until the iRule is added to a virtual server. Therefore, if you remove an iRule from the virtual server, the RULE_INIT event will not work and may prevent the iRule from being added back to the virtual server.

If the iRule is removed from the virtual server, the following error message is logged in the /var/log/tmm file:

mcp error: 1031000 in mcpmsg_to_database

F5 Product Development tracked this issue as CR74553, and it was fixed in BIG-IP LTM 9.1.3, 9.3, and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can add the RULE_INIT event to an iRule without causing this issue to occur by performing the following procedure:

Important: This procedure requires you to remove the iRule from the virtual server, in order to update the iRule to use the RULE_INIT event. The virtual servers will not be able to use the iRule once it has been removed. In order to prevent interruptions to client connections, F5 Networks recommends that you perform the following procedure during a maintenance window.

  1. Remove the iRule from all virtual servers that are utilizing it.
  2. Make the necessary changes to the iRule to add the RULE_INIT event.
  3. Add the iRule back to the virtual servers.
