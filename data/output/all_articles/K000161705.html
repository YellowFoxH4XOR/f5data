Description

After upgrading BIG-IP LTM, the management GUI becomes inaccessible despite the tomcat and httpd services running. System logs (/var/log/messages) show repeated syslog-ng configuration reload requests and broken syslog connections cycling continuously, which interferes with GUI accessibility.

Observed log messages in /var/log/messages:

syslog-ng[2782]: Configuration reload request received, reloading configuration;

syslog-ng[2782]: Syslog connection broken; fd='0', server='AF_INET(<remote_syslog_server>:515)', time_reopen='60'

syslog-ng[2782]: Syslog connection established; fd='79', server='AF_INET(<remote_syslog_server>:515)', ...

syslog-ng[2782]: Configuration reload request received, reloading configuration;

syslog-ng[2782]: Syslog connection broken; fd='79', server='AF_INET(<remote_syslog_server>:515)', time_reopen='60'

This pattern repeats in a tight loop, indicating a continuous cycle of syslog-ng reloads and broken connections to the remote syslog server.

Environment

  • Product: BIG-IP LTM
  • Software Version: 17.5.1.6 (with hotfix installed)
  • Configuration: Remote syslog servers configured in bigip_base.conf
  • Condition: GUI inaccessible post-upgrade; tomcat and httpd services confirmed running

Cause

Bug ID 1040277 — Remote syslog server configuration causes repeated syslog-ng reloads and broken connections, resulting in GUI inaccessibility post-upgrade.

Answer/Recommended Actions

  1. Confirm that tomcat and httpd services are running:
    tmsh show sys service
  2. Review /var/log/messages for repeated syslog-ng configuration reload and broken connection messages.
  3. Review bigip_base.conf to confirm the presence of remote syslog server configuration.
  4. Ensure syslog-ng server configuration is valid, and that the server is reachable. If a remote server is not reachable, remove it from the BIG-IP syslog configuration.
  5. Restart the syslog-ng process to restore management GUI access:
    bigstart restart syslog-ng
  6. After applying the workaround, verify that GUI access is restored and that the syslog-ng reload loop has stopped.

Additional Information

  • The root cause is related to the remote syslog configuration interacting with syslog-ng post-upgrade.
  • This issue may not be immediately apparent, as the core services (tomcat, httpd) responsible for the GUI appear to be running normally.
  • If the workaround does not resolve the issue, a UCS file from before the upgrade may be needed to reproduce the issue in a lab environment for further investigation.
