Topic

The System Load page, which is located at Device Management: Monitoring: System Load, contains several graphs that are helpful for understanding system performance and network activity. The rrdcollect process updates the graphs at 1-minute intervals, and the graphs are stored in a database file in the FirePass controller. The graphing function is generic. Therefore, the top of the scale is determined by the largest number in the dataset. Metric suffixes are used to indicate multipliers (for example, m = n * .001, k = n * 1000).

For a list of the statistical graphs, refer to the following table:

Note: For more information about these graphs, refer directly to the Linux kernel statistics. In addition, information about these statistics is available on the Internet.

Note: The statistics for the Active Sessions, CPU Usage, Swap Usage, Swap Paging, Disk I/O, and Process Creation Rate graphs come from the /proc/stat directory.

Statistical graphDescription
Active SessionsIndicates the number of entries in the FirePass session database. Each remote session ID is counted as one entry.
CPU UsageIndicates the types of CPU usage currently in the system by percentage. Each CPU core counts as 100; therefore, a system with 4 CPU cores will have a maximum of 400. The graph is divided into three types:

  • User

    Amount of CPU used by user-space programs. Examples include HTTP serving processes, SSL-VPN transport mechanisms, compression, reverse-proxy processing, and synchronization.
  • System

    Amount of CPU used by kernel-space processes. Examples include TCP/IP stack handling, memory management, and disk IO.
  • Idle

    Amount of CPU time spent in the idle loop. In an idle system, the idle line should stay near the top of the graph.
Swap UsageIndicates the amount of swap (virtual memory) currently allocated in bytes. As in any operating system using virtual memory, it is normal that some swap will be allocated most of the time. Allocation and deallocation occur dynamically as the system is running according to decisions made by the virtual memory manager.
Swap PagingIndicates the amount of swap page change since the last polling interval.
Disk I/OIndicates the number of read or write disk operations since the last polling period.
Process Creation RateIndicates the rate of increase of the next process ID value. Each spawned process will increase this counter by one. 

Load Average		Indicates the average number of processes waiting for CPU time. This number should generally be less than 10 to avoid slowed user responses, but can be as high as 20 to 30 on busy systems.

Note: This number comes directly from the /proc/loadavg directory.
Java Patcher StatisticsIndicates the number of channels and sockets used by the Java Patcher, Java Application Tunnels, and Java RDP mechanisms in FirePass. The FirePass controller has a protocol for Portal Access Java applets to do TCP or UDP socket communication.
Traffic through X interface
  • input

    Number of bytes received by the given interface
  • inErrors

    Number of received errors detected on the given interface
  • output

    Number of bytes transmitted by the given interface
  • outErrors

    Number of transmit errors detected on the given interface

Note: This statistic comes from the /proc/net/dev directory.
