Description

How to log specific user VPN properties locally or to a remote log server

Environment

  • APM
  • Network Access
  • Remote logging 

Cause

These values have to be manually extracted from session variables 

Recommended Actions

  1. Go to Local Traffic > iRule
  2. Create below iRule 
    when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}
when HTTP_REQUEST {
  if { [HTTP::uri] starts_with "/myvpn?sess=" } {
    after 5000 {
      log local0.notice "User_Name=[ACCESS::session data get session.logon.last.username] Session_ID=[ACCESS::session data get session.user.sessionid] Assigned PPP Dynamic IPv4: [ACCESS::session data get session.assigned.clientip] NA Resource: [ACCESS::session data get session.assigned.resources.na] Client IP: [ACCESS::session data get session.user.clientip]"
    }
  }
 }
}
    Note: if you are using APM Clients 7240 or later, see K000132750
  3. Apply the iRule to the Virtual Server

Additional Information

  • These lines will get logged in the LTM logs and you can extract the values and send to remote server
  • If you need some more parameters, you can run below command and see some more session parameters which can be called in the iRule:

    sessiondump -sid <sessionid>   (only active or pending session)

  • You can modify the iRule provided in the Recommended Actions section to your meet your requirements. For example, if you observe the iRule logging the information numerous times over the life of the Network Access session, you can add further conditions to the if condition of the iRule. For example, you can use the following iRule with an additional variable, session_logged so that the iRule will log only once per IP address during a session:

    # Since the URI can be sent more than once during an APM SessionID, this iRule uses the session_logged variable to track what IP Address was assigned.
    # The iRule will only log once per IP Address assigned during a session. 

    when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
  set session_logged "" 
}
when HTTP_REQUEST {
    if { [HTTP::uri] starts_with "/myvpn?sess=" } {
      if { $session_logged != [ACCESS::session data get session.assigned.clientip] } {
      set session_logged [ACCESS::session data get session.assigned.clientip]
      after 5000 {
        log local0.notice "User_Name=[ACCESS::session data get session.logon.last.username] Session_ID=[ACCESS::session data get session.user.sessionid] Assigned PPP Dynamic IPv4: [ACCESS::session data get session.assigned.clientip] NA Resource: [ACCESS::session data get session.assigned.resources.na] Client IP: [ACCESS::session data get session.user.clientip]"
      }
    }
}

 

Note that if DTLS is enabled, this iRule must be applied as well to the DTLS virtual server.

For the iRule to work on the DTLS virtual server, you'd need to include an http profile as well as the Access Profile used on the TLS virtual server.

You will also need to amend the iRule to disable HTTP for the myvpn request, like this:

when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}
when HTTP_REQUEST {
  if { [HTTP::uri] starts_with "/myvpn?sess=" } {
    after 5000 {
      log local0.notice "User_Name=[ACCESS::session data get session.logon.last.username] Session_ID=[ACCESS::session data get session.user.sessionid] Assigned PPP Dynamic IPv4: [ACCESS::session data get session.assigned.clientip] NA Resource: [ACCESS::session data get session.assigned.resources.na] Client IP: [ACCESS::session data get session.user.clientip]"
   }
   HTTP::disable
  }
 }
}
