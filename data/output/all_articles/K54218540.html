Description

In cases when multiple BIG-IP devices are in the traffic path and traffic passes through an upstream virtual server with an HTTP profile prior to arriving at the BIG-IP APM system where the VPN endpoint virtual server is located, the control channel information for tunnel establishment (iSession) can be obstructed.

Environment

  • BIG-IP APM
  • Multiple BIG-IP devices in traffic path
  • Virtual server with HTTP profile (or any non-F5 device that enforces HTTP protocol processing)
  • VPN endpoint virtual server behind the virtual server with the HTTP profile

Cause

The HTTP profile on the upstream virtual server can interrupt the data sent to the VPN endpoint using the iSession paths, specifically /isession and /myvpn.

Recommended Actions

The following iRule definition can be placed on the upstream virtual server using the HTTP profile to resolve the behavior:

  1. Log in to the upstream BIG-IP Configuration utility (GUI).
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. For Name, enter a name for the iRule.
  5. For Definition, enter the following code:

    when HTTP_REQUEST {
       set http_disable 0

       if { [HTTP::uri] starts_with "/isession" or [HTTP::uri] starts_with "/myvpn" } {
          # This is an isession/vpn request, we need to disable http for this request
          set http_disable 1
       }
    }
    when HTTP_REQUEST_SEND {
       if { $http_disable != 0 } {
          HTTP::disable
       }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. In the Resources column, click Edit next to the name of the upstream virtual server with the HTTP profile.
  9. Next to iRules, click Manage.
  10. In the Available section, click the name of the newly created iRule, then click << to move it to the Enabled section.
  11. Click Finished.
