Known Issue

In rare cases, the BIG-IP AFM Traffic Management Microkernel (TMM) restarts and produces a core file when activating a new binary large object (BLOB).

This issue occurs when the following condition is met:

  • You add, remove, or modify a network firewall rule.

Beginning in BIG-IP 12.0.0, BIG-IP AFM maintains two compiled rule sets, called BLOBs, in two different memory locations: pktclass1 and pktclass2. When you update or create a new firewall rule set, the system uses the non-active BLOB to compile the rule set. After the system compiles the new firewall rule set, it unlocks the previous firewall rule set and locks the new firewall rule set. TMM is notified of the change and uses the new BLOB.

Impact

BIG-IP systems in the standby state for a traffic group are not operational until TMM restarts. If the BIG-IP system is active for a traffic group, that traffic group fails over.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system generates a TMM core file in the /shared/core directory.

Workaround

To work around this issue, you can set the firewall compilation mode to manual, then add an IP address to all policies that are not currently used in any of the existing network firewall rules. To do so, perform the following procedure:

Impact of workaround: The following procedure disrupts traffic processing and should only be performed during a maintenance window.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Set the firewall compilation mode to manual by typing the following command:

    modify /security firewall on-demand-compilation mode enabled

  3. Confirm the configuration change by typing the following command:

    list /security firewall on-demand-compilation

    The output should appear similar to the following example:

    security firewall on-demand-compilation {
        mode enabled
    }

  4. Make note of an IP address that is not used in any existing rule configuration (for example, 1.1.1.1).
  5. Add the unused IP address to all rules in all configured policies using the following command syntax:

    modify /security firewall policy <policy-name> rules modify { all { source { addresses add { <unused IP address> } } } }

    For example, if the unused IP address for your system is 1.1.1.1, and your policy name is example-policy, type the following command:

    modify /security firewall policy example-policy rules modify { all { source { addresses add { 1.1.1.1 } } } }

  6. Repeat step 5 for all configured policies on the BIG-IP AFM system.
  7. Restore the rules in all policies using the following command syntax:

    modify /security firewall policy <policy-name> rules modify { all { source { addresses delete { <IP address added in step 5> } } } }

    For example, if the IP address added in step 5 was 1.1.1.1, and your policy name is example-policy, type the following command:

    modify /security firewall policy example-policy rules modify { all { source { addresses delete { 1.1.1.1 } } } }

  8. To start the new BLOB compilation, set the firewall compilation mode back to automatic by typing the following command:

    modify /security firewall on-demand-compilation mode disabled

  9. Repeat step 3 to confirm the configuration change. The output should appear similar to the following example:

    security firewall on-demand-compilation { }
