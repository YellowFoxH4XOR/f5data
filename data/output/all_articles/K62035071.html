Topic

You should consider using this procedure under the following condition:

  • You want to enable or disable the BIG-IP Force Offline state using the iControl representation state transfer (REST) API.

Description

Force Offline is a maintenance operation that puts the BIG-IP system into an offline state. For more information, refer to K15122: Overview of the Force Offline option.

The REST procedure provided in this article is an example of a common BIG-IP maintenance task. You can use the iControl REST API to perform most of the BIG-IP system management and configuration tasks that you can perform using the TMOS Shell (tmsh). For example, you can generate a QKView diagnostic file for upload to F5 iHealth. For more information about the iControl REST API, refer to the iControl REST User Guide that applies to your BIG-IP version, available on F5 Cloud Docs.

curl and jq utilities

Performing the following procedure requires command-line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems but can also be installed on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure from an alternate BIG-IP system; however, the jq utility is not available on systems running versions earlier than BIG-IP 12.0.0. You can still use the curl portion of commands, but the resulting output is a single string rather than formatted JSON. For more information about the jq utility, refer to https://stedolan.github.io/jq.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command-line access to a system with the curl utility and, optionally, the jq utility installed. From more information, refer to curl and jq utilities in this article.
  • You have access to F5 Cloud Docs to review iControl REST API documentation.

Procedures

Enabling and disabling the BIG-IP Force Offline state

Force Offline is a maintenance operation that puts the BIG-IP system into an offline state. For more information, refer to K15122: Overview of the Force Offline option.

The example procedure uses the following BIG-IP system configuration.

Configuration objectValue
BIG-IP hostnameLTM1.example.com
BIG-IP administrative usernameadmin
BIG-IP administrative passwordtesting

Impact of procedure: BIG-IP systems in the Force Offline state do not pass traffic. In Force Offline state, the BIG-IP system terminates existing connections to local traffic objects and does not allow new connections. This state takes effect immediately upon enabling the option, and all traffic is immediately dropped. F5 recommends enabling this option only during a maintenance window.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to enable or disable the BIG-IP Force Offline state:

    curl -sku admin:<password> -H "Content-Type: application/json" -X PUT https://<BIG-IP hostname or management IP address/mgmt/tm/sys/db/failover.forceoffline -d '{"value":"<enable | disable>"}' | jq -M .

    For example, to enable the Force Offline state using the configuration previously described, type the following command:

    curl -sku admin:example -H "Content-Type: application/json" -X PUT https://LTM1.example.com/mgmt/tm/sys/db/failover.forceoffline -d '{"value":"enable"}' | jq -M .

    The output looks similar to the following example. The value parameter represents the current Force Offline state:

    {
      "kind": "tm:sys:db:dbstate",
      "name": "failover.forceoffline",
      "fullPath": "failover.forceoffline",
      "generation": 542,
      "selfLink": "https://localhost/mgmt/tm/sys/db/failover.forceoffline?ver=12.1.3",
      "defaultValue": "disable",
      "scfConfig": "false",
      "value": "enable",
      "valueRange": "disable enable"
    }

    To disable the Force Offline state using the example configuration, type the following command:

    curl -sku admin:example -H "Content-Type: application/json" -X PUT https://LTM1.example.com/mgmt/tm/sys/db/failover.forceoffline -d '{"value":"disable"}' | jq -M .

    The output looks similar to the following example. The value parameter represents the current Force Offline state:

    {
      "kind": "tm:sys:db:dbstate",
      "name": "failover.forceoffline",
      "fullPath": "failover.forceoffline",
      "generation": 548,
      "selfLink": "https://localhost/mgmt/tm/sys/db/failover.forceoffline?ver=12.1.3",
      "defaultValue": "disable",
      "scfConfig": "false",
      "value": "disable",
      "valueRange": "disable enable"
    }

  3. Optionally, to confirm the current Force Offline state without making any changes using the example configuration, type the following command:

    curl -sku admin:example -H "Content-Type: application/json" -X GET https://LTM1.example.com/mgmt/tm/sys/db/failover.forceoffline | jq -M .

    The output looks similar to the following example. The value parameter represents the current Force Offline state:

    {
      "kind": "tm:sys:db:dbstate",
      "name": "failover.forceoffline",
      "fullPath": "failover.forceoffline",
      "generation": 548,
      "selfLink": "https://localhost/mgmt/tm/sys/db/failover.forceoffline?ver=12.1.3",
      "defaultValue": "disable",
      "scfConfig": "false",
      "value": "disable",
      "valueRange": "disable enable"
    }
