Known Issue

When using the Secure Sockets Layer (SSL) renegotiation feature of the SSL client profile, the Traffic Management Microkernel (TMM) fails to regularly reap the ssl_session cache buffer. This may cause the SSL cache to use up to its maximum allocated size.

This issue occurs when the following condition is met:

  • You are passing SSL traffic through a virtual server with a Client SSL profile configured to allow SSL renegotiation.

Impact

On BIG-IP systems with a high volume of SSL renegotiation sessions, the SSL session cache may stay at its maximum allocated size. This issue does not affect SSL traffic or performance.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The bigpipe memory show command output shows that the Alloc and Max values match, similar to the following example:

bigpipe memory show | grep -E "SUBSYSTEM|ssl_session"

| SUBSYSTEM Alloc Max Obj size
| ssl_session 352 352 176

Workaround

You can work around this issue by releasing all TMM memory with a restart of the TMM process. To do so, restart the TMM process by typing the following command:

bigstart restart tmm

Impact of workaround: Performing this procedure will cause an interruption of service. F5 recommends that you only perform this command during a maintenance window.
