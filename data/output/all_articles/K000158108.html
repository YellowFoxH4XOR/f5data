Description

This article explains the cause and impact of repeated log messages similar to below in velos.log of partition:

2025-11-20T20:30:54.702592+08:00 user platform-stats-bridge[11]: nodename=controller-1(p2) priority="Err" version=1.0 msgid=0x4305000000000008 msg="" msg="DmaTenantTcpCopOperHdlr, couldn't find stats for tenant".

These log messages indicate that statistics could not be collected from non-running tenants. There is no negative impact on system operation—the errors simply reflect the absence of active tenants to report statistics.

You can safely ignore these messages as long as they correspond to tenants that are intentionally left in a configured (not running) state.

Environment

  • F5OS
  • VELOS chassis systems
  • Multiple tenants, some deployed/running and others only configured

Cause

The 'platform-stats-bridge' service is responsible for collecting resource utilization statistics (such as memory and CPU usage) from tenants via the tmstat service running within each tenant or blade. When a tenant exists in a "configured" state but is not running, there is no tmstat service available to provide statistics. As a result, when platform-stats-bridge attempts to query these non-running tenants, it cannot retrieve any data and logs the error:

DmaTenantTcpCopOperHdlr, couldn't find stats for tenant

Recommended Actions

  • No action required: If you expect some tenants to be configured but not running, these log entries can be ignored.
  • Review your configuration: If you see this error unexpectedly or believe all tenants should be running, verify the status of your tenants.
  • Please reach out to F5 Technical Support if you need further support.
