Topic

This article discusses the behavior of the BIG-IP LTM FTP monitor. For information about the FTP monitor settings, refer to the Monitors Settings Reference chapter of the BIG-IP Local Traffic Manager: Monitors Reference guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Description

You can display or create an FTP monitor by navigating to Local Traffic > Monitors in the Configuration utility.

The FTP monitor Mode setting has two options which dictate how the system establishes the data connection (separate from the control connection for commands):

  • Passive mode, in which the BIG-IP system connects to a port on which the FTP server is listening.
  • Port mode (also called active mode), in which the FTP server connects to a port on which the BIG-IP system listens.

The most significant difference among BIG-IP versions occurs with passive mode. In BIG-IP 12.1.2 and later, the BIG-IP system establishes a data connection with the IP address which the FTP server provides in the passive mode reply instead of the pool member IP address. This is inconsequential if you've configured the FTP server to supply the IP address of the pool member in the passive mode reply. The following sections describe the behavior of each mode in relation to BIG-IP versions:

  • FTP Monitor behavior in Passive mode
  • FTP Monitor behavior in Port (active) mode

FTP Monitor behavior in Passive mode

BIG-IP 12.1.0 and later

  • The BIG-IP system establishes a control connection to the FTP server, logs in, prints the current directory, and transmits a request for passive mode with a PASV command. The FTP server replies with a 227 reply code, indicating that it is entering passive mode. If you've configured the FTP server to specify a different IP address for the data connection, it does so in the 227 response. In the following example, the BIG-IP system establishes a control connection to a pool member with the IP address 172.16.1.112. The connection includes packet details similar to the following:

    BIG-IP                                         FTP server

    172.16.1.145:41796  ->  172.16.1.112:21 : Request: PASV
    172.16.1.145:41796  <-  172.16.1.112:21 : Response: 227 Entering Passive Mode (192,168,1,110,224,142).

  • The BIG-IP system requests binary mode and the file size and to transfer the file specified in the Path / Filename setting of the monitor configuration. The FTP server replies, indicating that it will open a data connection.
  • The FTP server listens on the port it provided in the 227 reply (57486 in the example: [224* 256] + 142= 57486). The BIG-IP system establishes a separate data connection to the FTP server using the IP address that the FTP server provides in the 227 reply (192.168.1.110 in the example) and not the IP address of the pool member (172.16.1.112 in the example). The system transfers the file over the data connection and then removes both control and data connections. If the file transfer does not complete for any reason, the system marks the pool member down. The data connection establishment includes packet details similar to the following example:

    BIG-IP                                         FTP server

    192.168.1.145:31027  ->  192.168.1.110:57486 : [SYN]
    192.168.1.145:31027  <-  192.168.1.110:57486 : [SYN, ACK]
    192.168.1.145:31027  ->  192.168.1.110:57486 : [ACK]

BIG-IP 11.6.0 - 12.0.0

  • The BIG-IP system establishes a control connection to the FTP server, logs in, prints the current directory, and transmits a request for extended passive mode with an EPSV command. The FTP server replies with a 229 reply code indicating that it is entering extended passive mode. The 229 reply does not specify an IP address. In the following example, the BIG-IP system establishes a control connection to the a pool member with the IP address 172.16.1.112. The connection includes packet details similar to the following:

    BIG-IP                                       FTP server

    172.16.1.145:36365  ->  172.16.1.112:21 : Request: EPSV
    172.16.1.145:36365  <-  172.16.1.112:21 : Response: 229 Entering Extended Passive Mode (|||57486|).
  • The BIG-IP requests binary mode, the file size, and requests to transfer the file specified in the Path / Filename setting of the monitor configuration. The FTP server replies indicating that it will open a data connection.
  • The FTP server listens on the port it provided in the 229 reply (57486 in the example). The BIG-IP establishes a separate data connection to the FTP server on this port. The file is then transferred over the data connection and both control and data connections are torn down. If the transfer does not complete for any reason, the pool member will be marked down. The establishment of the data connection includes packet details similar to the following:

    BIG-IP                                       FTP server

    172.16.1.145:50567  ->  172.16.1.112:57486 : [SYN]
    172.16.1.145:50567  <-  172.16.1.112:57486 : [SYN, ACK]
    172.16.1.145:50567  ->  172.16.1.112:57486 : [ACK]

BIG-IP 11.5.4 and earlier

  • There is no significant difference in control connection and file transfer behavior with BIG-IP 12.1.0 and later; however, data connection behavior is different as noted in the next point.
  • The FTP server listens on the port it provided in the 227 reply (57486 in the previous example). The BIG-IP system establishes a separate data connection to the FTP server using the IP address of the pool member (172.16.1.112 in the previous example) and ignores the IP address in the 227 reply (192.168.1.110 in the previous example). The system transfers the file over the data connection and then removes both control and data connections. If the transfer does not complete for any reason, the system marks the pool member down. The data connection establishment includes packet details similar to the following:

    BIG-IP                                       FTP server
    172.16.1.145:59706  ->  172.16.1.112:57486 : [SYN]
    172.16.1.145:59706  <-  172.16.1.112:57486 : [SYN, ACK]
    172.16.1.145:59706  ->  172.16.1.112:57486 : [ACK]

FTP Monitor behavior in Port (active) mode

BIG-IP 12.1.0 and later, BIG-IP 11.5.4 and earlier
  • The BIG-IP system establishes a control connection to the FTP server, logs in, prints the current directory, and requests port mode with a PORT command. In the following example, the BIG-IP system establishes a control connection to a pool member with the IP address 172.16.1.112. The FTP server replies with a 200 reply code indicating that it is entering port mode:

    BIG-IP                                       FTP server

    172.16.1.145:59341  ->  172.16.1.112:21 : Request: PORT 172,16,1,145,109,108
    172.16.1.145:59341  <-  172.16.1.112:21 : Response: 200 PORT command successful. Consider using PASV.

  • The BIG-IP system requests binary mode and the file size, and to transfer the file specified in the Path / Filename setting of the monitor configuration. The FTP server replies, indicating that it will open a data connection.
  • The BIG-IP system listens on the port specified in the PORT command, (28012 in the example: [109 * 256] + 108= 28012) and the FTP server establishes the data connection with the BIG-IP system. The system then transfers the file over the data connection and then removes both control and data connections. If the transfer does not complete for any reason, the system marks the pool member down. The data connection establishment includes packet details similar to the following example:

    BIG-IP                                       FTP server

    172.16.1.145:28012  <-  172.16.1.112:48147 : [SYN]
    172.16.1.145:28012  ->  172.16.1.112:48147 : [SYN, ACK]
    172.16.1.145:28012  <-  172.16.1.112:48147 : [ACK]

BIG-IP 11.6.0 - 12.0.0

  • The BIG-IP system establishes a control connection to the FTP server, logs in, prints the current directory, and requests extended port mode with a EPRT command. The FTP server replies with a 200 reply code indicating that it is entering extended port mode. In the following example, the BIG-IP system establishes a control connection to a pool member with the IP address 172.16.1.112:

    BIG-IP                                      FTP server

    172.16.1.145:50125  ->  172.16.1.112:21 : Request: EPRT |1|172.16.1.145|28012|
    172.16.1.145:50125  <-  172.16.1.112:21 : Response: 200 EPRT command successful. Consider using EPSV.

  • The BIG-IP system requests binary mode and the size of the file and to transfer the file specified in the Path / Filename setting of the monitor configuration. The FTP server replies, indicating that it will open a data connection.
  • The BIG-IP system listens on the port specified in the EPRT command, (28012 in the example) and the FTP server establishes the data connection with the BIG-IP system. The system then transfers the file over the data connection and then removes the control and data connections. If the transfer does not complete for any reason, the system marks the pool member down. The data connection establishment includes packet details similar to the following example:

    BIG-IP                                       FTP server

    172.16.1.145:28012  <-  172.16.1.112:48147 : [SYN]
    172.16.1.145:28012  ->  172.16.1.112:48147 : [SYN, ACK]
    172.16.1.145:28012  <-  172.16.1.112:48147 : [ACK]
