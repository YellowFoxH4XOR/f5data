Known Issue

The BIG-IP Virtual Edition (VE) system may restart and produce a core file if descheduled by the hypervisor for extended periods of time.

This issue occurs when all of the following conditions are met:

  • You over-provision resources on a hypervisor without sufficient CPU reservation on a BIG-IP system.
  • Your BIG-IP system is heavily loaded and may not be scheduled to run for more than ten seconds.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from Traffic Management Microkernel (TMM) restarting, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process produces a core file with a SIGABRT message.
  • The BIG-IP system temporarily fails to process traffic while TMM restarts.
  • The BIG-IP system generates a TMM core file in the /shared/core directory.
  • In the /var/log/kern.log file, you observe messages that appear similar to the following example:

    notice kernel: overdog[4444]: Overdog scheduling exceeded 1/2 timeout of 5 seconds (measured:7630 ms)

Workaround

To work around this issue, you can reserve ample CPU resources to guarantee that TMM gets an opportunity to run its watchdog process within ten seconds. You can also prevent the hypervisor host from over-subscribing by limiting the number of jobs so that the BIG-IP system is allotted sufficient CPU cycles.
