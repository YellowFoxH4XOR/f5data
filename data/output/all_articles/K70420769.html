Issue

Error Message

err get_dossier[<PID>]: 01170005:3: <file> stat fails: No such file or directory.

In this error message, note the following:

  • <PID> is the process ID for the get_dossier process.
  • <file_name> is the name and location of the required file.

For example:

err get_dossier[8484]: 01170005:3: /config/ssl/ssl.csr/f5_api_com.csr stat fails: No such file or directory.

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message could appear under the following conditions:

  • The f5_api_com interface tries to extract information from the version and the certificate signing request (CSR) files.
  • One or more of the required files are missing.
  • The BIG-IP system does not have access to F5 host servers such as activate.f5.com and api.f5.com, including the DNS server to resolve these F5 host names.

The f5_api_com interface provides secure connections between the BIG-IP system and various F5 services, such as licensing and the Phone Home feature. The interface checks information about the current version from the /VERSION file, the /proc/version file, and the CSR file before the communication can be initialized.

Impact

Communication between the BIG-IP system and the API servers cannot be established, resulting in failed API calls.

Recommended Actions

  • While failed API calls do not impact service, the missing CSR file message can indicate a license issue. You should review and verify your F5 license if the message persists.
  • If your BIG-IP system does not have access to F5 host servers (for example, pinging api.f5.com or nslookup fails), this error is expected at the time of license reactivation and can be safely ignored. For more information, refer to the Connectivity requirements section in K15000: Overview of the Automatic Update Check and Automatic Phone Home features.
