K000150424: Wrong pool member selected when multiple conditionals or iRules are applied

Type
Support Solution
Published
2025-03-18
Updated
2025-03-18
Source
https://my.f5.com/manage/s/article/K000150424

Description

When multiple iRules are used on a Virtual Server to select pools based on different conditions, BIG-IP evaluates all assigned iRules. If conditions are not correctly defined, a later-evaluated iRule will overwrite the pool selection made by a previous iRule, leading to unexpected load balancing behavior.

Cause

BIG-IP does not stop evaluating iRules once a pool has been selected unless explicitly instructed. Without proper conditions in place, subsequent iRules may overwrite the existing pool selection.

Recommended Actions

To prevent an iRule from overwriting an already selected pool, add a condition to check if a pool has already been assigned before proceeding with further selection logic. If a pool is already set, the iRule should exit without making changes.

Example iRule Implementation:

when HTTP_REQUEST {
    # Check if a pool is already assigned
    if { [LB::server pool] ne "" } {
        log local0. "Pool already selected: [LB::server pool], skipping further selection"
        return
    }
    
    # Logic to select the pool based on conditions
    if { [HTTP::host] contains "example.com" } {
        pool pool_example
    }
}
