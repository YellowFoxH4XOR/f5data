Description

  • SAML logon HTTP 302 response allows a browser to change the method in subsequent request

Environment

  • iRule
  • APM
  • SAML

Cause

  • HTTP 302 REDIRECT is received by a browser 
  • HTTP 302 response allows a browser to change the method in subsequent request

Recommended Actions

  • If the browser is required to act on a specific way following an HTTP response, one  can use iRule 
  • An iRule can be used to change some of the 302 redirects to a 307 or 303 or any other http method.
  • HTTP response 307 does not allow a browser to change the method.
  • The iRule event used is HTTP_RESPONSE_RELEASE

 

Additional Information

  • Add the following iRule to the virtual server after making the necessary change
    when HTTP_REQUEST {
      set uri [HTTP::uri]
    }
    when HTTP_RESPONSE_RELEASE {
      if { [HTTP::status] contains "302" && ([HTTP::header value "Location"] contains "<given value>") } {
         HTTP::header replace ":S" "307 Temporary Redirect"
      }
    }

Note: The following pseudo-header codes can be used in iRules as part of HTTP::header replace:

  • ":S" for handling Status
  • ":M" for handling Method
  • ":U" for handling URI
