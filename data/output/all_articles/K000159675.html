Description

MQTT service experiences packet loss when traffic is load balanced through a BIG-IP virtual server, while direct connections to pool member servers show no loss. Packet capture analysis reveals TCP ZeroWindow advertisements being sent from the BIG-IP to the MQTT servers, indicating buffer exhaustion on the proxy device.

Symptoms:

  • Packet loss observed for MQTT clients connecting through the F5 load balancer
  • No packet loss when clients connect directly to MQTT servers
  • TCP ZeroWindow advertisements visible in packet captures (Win=0)
  • Performance degradation for MQTT service

Environment

  • BIG-IP LTM version 17.1.3
  • Platform: F5-BIG-BT-R4800, C131
  • Virtual server with MQTT profile configured
  • TCP profiles: f5-tcp-wan (clientside) and f5-tcp-lan (serverside)
  • Load balancing pool with MQTT servers on port 1883
  • Source NAT: Automap enabled
  • Standard TCP virtual server configuration

Cause

The TCP proxy buffer on the BIG-IP fills up due to inadequate buffer sizing in the default TCP profiles. When the proxy buffer reaches capacity, the system advertises TCP ZeroWindow conditions to the MQTT servers, preventing them from sending additional data until buffer space becomes available. This results in transmission delays and packet loss. The default f5-tcp-lan profile's receive window and proxy buffer settings are insufficient to handle the MQTT traffic volume and pattern.

Recommended Actions

Step 1: Create a custom TCP profile with optimized buffer settings

create ltm profile tcp mqtt-optimized-serverside {
defaults-from f5-tcp-progressive
idle-timeout 86400
push-flag auto
receive-window-size 1048576
send-buffer-size 1048576
proxy-buffer-high 2097152
proxy-buffer-low 2031616
}

Step 2: Apply the optimized profiles to the virtual server

tmsh modify ltm virtual <virtual_server_name> profiles replace-all-with {
f5-tcp-progressive { context clientside }
mqtt-optimized-serverside { context serverside }
mqtt { }
}

Step 3: Monitor traffic for improvement

  • Capture packet traces after implementing the changes
  • Verify that TCP ZeroWindow advertisements are eliminated or significantly reduced
  • Confirm packet loss is resolved

Alternative approach (if TCP profile optimization does not fully resolve the issue):

Consider testing with a FastL4 profile as an alternative configuration approach.

Additional Information

Understanding the optimized settings:

  • Receive window size (1048576 bytes): Larger receive window allows the BIG-IP to accept more data before advertising flow control
  • Proxy buffer high (2097152 bytes): Increased buffer capacity prevents buffer exhaustion during traffic bursts
  • Proxy buffer low (2031616 bytes): Threshold for resuming normal operations after buffer pressure
  • f5-tcp-progressive base profile: Provides Auto Receive Window and Auto Proxy Buffer features that dynamically adjust based on network measurements

Key features of f5-tcp-progressive profile:

  • Auto Receive Window: Enabled - Uses network measurements to set optimal receive window size
  • Auto Proxy Buffer: Enabled - Sets optimal proxy buffer size based on network measurements
  • Congestion Control: Woodside algorithm for improved performance on high-speed networks
  • Larger default buffer sizes to accommodate more data before advertising zero window
