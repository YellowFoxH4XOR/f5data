Known Issue

This is the result of a known issue. The BIG-IP system sends Device-Watchdog-Answer messages with empty Origin-Host and Origin-Realm fields. This may result in the Diameter peer unexpectedly closing the connection.

Note: The Diameter protocol uses Device-Watchdog-Request and Device-Watchdog-Answer messages to detect transport failures. According to RFC3588, Origin-Host and Origin-Realm fields are used to identify a Diameter peer and must be present in Diameter messages and be populated with the appropriate values.

F5 Product Development tracked this issue as CR137617 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Note: Additionally, the Diameter profile Overwrite Destination Host setting does not overwrite the destination host value in the request with the pool member's IP address. For more information, refer to K11768: The Diameter profile 'Overwrite Destination Host' setting does not overwrite the destination host value in the request with the pool member's IP address.
