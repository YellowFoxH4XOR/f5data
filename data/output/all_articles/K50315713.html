Known Issue

VLAN listeners and forwarding database (FDB) entries are not automatically created in the partition configuration on VELOS.

This issue occurs when all of the following conditions are met:

  • You deploy a new tenant or add a VLAN to a tenant configuration.

    Note: When you deploy a new BIG-IP tenant, the deployment may take 5-10 minutes to create the VLAN listeners and FDB entries.

  • The BIG-IP tenant is running BIG-IP 14.1.x
To view VLAN listener and FDB entries, use the following methods:
  • Log in to the partition management CLI of the system and enter the following commands:
    • show fdb
    • show tenant
  • Log in to the controller CLI of the system and view the following logs:

    /var/F5/partition<ID>/log/velos.log

    You may observe entries similar to the following:

    msg="Listener request" vlanname="/Common/test-example-xxxx" vlantag=xxxx mac="00:xx:xx:xx:xx:xx" cmphash="ports" tunnel="outer".

Impact

Traffic on the affected VLAN does not function correctly on the tenant.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You observe on a BIG-IP tenant, there is no network connectivity on the affected VLANs.

Workaround

To work around this issue, you can deploy or upgrade a tenant with a BIG-IP version later than 14.1.x or remove the affected VLANs from the tenant and re-add them to trigger a re-creation of the VLAN listener and FDB entries.

To remove the affected VLANs from the tenant and re-add them, perform the following procedure:

Impact of procedure: There is no network connectivity for the affected VLANs on the tenant when you remove them from the tenant configuration. F5 recommends performing this during a scheduled maintenance for the affected tenant.

  1. Log in to the command line of the VELOS partition floating management IP address as the partition administrator.
  2. Enter the configuration mode terminal by entering the following command:

    config

  3. Use the following command syntax to display the VLANs associated to a tenant.

    show full-configuration tenants tenant <tenant name> config vlans

  4. Use the following command syntax to remove a VLAN from a tenant:

    no tenants tenant <tenant name> config vlans <vlan number>

    For example, enter the following command:

    no tenants tenant exampleTenant config vlans 101

  5. Enter the following command to commit the changes:

    commit

  6. Use the following command syntax to re-add the VLAN to the tenant:

    tenants tenant exampleTenant config vlans <vlan number>

    For example, enter the following command:

    tenants tenant exampleTenant config vlans 101

  7. Enter the following command to commit the changes:

    commit
