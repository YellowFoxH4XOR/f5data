Topic

The FirePass controller Web Applications engine trace feature provides an easy way for you to capture logs of user sessions through the Web Applications feature of Portal Access. The logs provide detailed information about how the FirePass reverse-proxy engine translates the data stream.

Clear Caches

Before generating a trace file, it is advantageous to clear both the client browser cache and the dynamic cache on the FirePass controller. If the cache is not cleared, the web engine trace will not include the traffic that is necessary to troubleshoot outstanding issues. For information about clearing the browser cache, refer to the browser vendor documentations. To clear the FirePass cache, perform the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. Navigate to the Portal Access: Web Applications: Caching and Compression page.
  3. Click on the Clear Cache button below WebApplications cache section.

Generating and downloading a trace file

  1. Start a user session to the FirePass controller.

  2. Log in to the FirePass Administrative Console from a separate browser window using a superuser admin account.

    Note: Administrator accounts other than the superuser account will not have the necessary permissions to properly capture Web Applications engine trace data.

  3. From the main navigation pane, click Device Management.

  4. In the upper navigation pane, click Maintenance.

  5. From the Maintenance menu, click Troubleshooting Tools.

  6. In the User field of the Web Applications engine trace section, type the logon name of the user in Step 1.

  7. Click the Get user sessions button.

    All of the user's current sessions are displayed.

  8. To begin the trace, click the Connect link to the right of the user's session ID.

  9. Return to the user session browser window.

  10. Start a Portal Access Web Application session.

  11. Navigate to the web page that is manifesting the error.

  12. Switch back to the FirePass Administrative Console browser window.

  13. Navigate back to the Troubleshooting Tools page.

  14. To download the trace file, click the Download link to the right of the user's session ID in the Web Applications engine trace section.

  15. Save the file to your local machine.

Analyzing the trace file for FirePass version 5.5 and later

The trace information that you generated in the previous procedure is contained in a compressed (zip) file. Extract the files contained in the zip file, and then open the index.html file in your browser. The index.html page contains the following four sections:

  • Requests
    A list of HTTP requests that the client sent to the FirePass controller. Click the request that you want to examine, which will populate the corresponding data in the other three sections of the index.html page.

  • Request log
    Data that the content processing engine and content processing scripts changed. This is a commented list of the reverse-proxy actions the FirePass controller performed on the associated client request.

  • Front-end request/response
    The request the client sent to the FirePass controller, and the responses the FirePass controller sent back to the client. Note that the response sent by the FirePass controller contains the Web Application content after it was processed by the FirePass reverse-proxy engine.

  • Back-end request/response
    The request the FirePass controller sent to the web server, and the response the web server sent back to the FirePass controller. Note that the response sent by the web server contains the Web Application content before it was processed by the FirePass reverse-proxy engine.

    Note: The zip file contains additional files that may be useful for troubleshooting. For more information about these files, refer to the FirePass Controller Administrator Guide.

By comparing the data in the Front-end request/response to the data in the Back-end request/response, you may be able to determine why a user is experiencing issues with a Portal Access Web Application.

Note: For more information about the Web Applications engine trace feature, refer to the FirePass Controller Administrator Guide.

Analyzing the trace file for FirePass versions 5.0 through 5.4.2

The trace information that you generated in the previous procedure is contained in a zip file. The zip file includes the following file types for each Process-ID:

  • IN
    The input data stream coming into the FirePass content processing engine from the site that you are accessing.

  • OUT
    The output data stream leaving the FirePass content processing engine after it has been processed by FirePass.

  • LOG
    A log of everything that was changed by the content processing engine and content processing scripts.

  • DBG
    The output data stream augmented with some additional state-change information.

By comparing the data in the .IN files to the data in the .OUT files, you may be able to determine why a user is experiencing issues with a Portal Access Web Application.

Note: For more information about the Web Applications engine trace feature, refer to the FirePass Controller Administrator Guide.
