K000162023: Syslog Forwarding Fails After Upgrade to BIG-IP LTM 17.x.x Due to Missing local-ip in Remote Syslog Configuration

Type
Support Solution
Published
2026-07-01
Updated
2026-07-01
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000162023

Description

After upgrading to BIG-IP LTM version 17.x.x, syslog messages are not forwarded to the configured remote syslog server. The syslog configuration appears intact, but logs are not received by the remote server. This issue can impact compliance requirements where remote logging is mandatory.

Environment

  • BIG-IP LTM, version 17.x.x
  • Remote syslog server configured without an explicit local-ip parameter
  • Air-gapped network environment
  • Recent upgrade or reboot

Cause

A race condition where syslog-ng may start before routing tables are fully populated after a reboot or upgrade, causing it to bind to an incorrect source IP. Without an explicit local-ip defined in the remote syslog server configuration, syslog-ng cannot reliably send logs to the intended destination.

Answer/Recommended Actions

  1. Restart syslog-ng to restore log forwarding without disrupting traffic:
    bigstart restart syslog-ng
  2. Verify syslog-ng is running:
    bigstart status syslog-ng
  3. Permanently resolve the issue by explicitly setting the local-ip parameter in the remote syslog server configuration to a valid management or self-IP address:
    tmsh modify sys syslog remote-servers modify { /Common/remotesyslog2 { local-ip <correct_source_IP> } }
    tmsh save sys config
  4. Ensure the specified local-ip exists on the system to prevent syslog-ng from failing to bind after future reboots.
  5. Confirm network connectivity and routing to the syslog server, and verify the syslog server is configured to accept logs from the BIG-IP's source IP.

Additional Information

  • If the syslog server is configured to accept logs only from specific source IPs, ensure the BIG-IP is sending from the expected IP after the upgrade or reboot.
  • An invalid local-ip will prevent syslog-ng from binding after a reboot.
