Known Issue

Fragmented IP packets traveling through an Internet Protocol Security (IPsec) tunnel cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • You configure a BIG-IP system with multiple TMMs and an IPsec tunnel.
  • The BIG-IP system receives fragmented IP packets that match the IPsec policy.
  • The system forwards the fragmented packets to another TMM for processing.

When identifying the connection flow associated with the fragmented IP packet, the TMM that is processing the packet selects a stale flow. This causes the system to incorrectly forward the internal MCP flows to the tunnel and results in MCP heartbeat failures.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may temporarily fail to process traffic as it recovers from a TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.

Workaround

There is not a work around for this issue if IPsec packet fragmentation occurs. However, you may be able to prevent this issue by using either of the following methods:

Impact of workaround: The impact of the suggested preventative methods depends on the specific environment. F5 recommends that you test any such changes during a maintenance window, and consider the possible impact on your specific environment.

  • If possible, ensure that the system reassembles fragmented packets before the IPsec policy processes them.
  • If possible, configure your adjacent network maximum transmission unit (MTU) configuration so the system does not fragment the affected packets.
