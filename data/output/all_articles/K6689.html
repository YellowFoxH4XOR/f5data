Known Issue

This is the result of a known issue. When you log on to a FirePass controller from a client running a Microsoft Windows operating system and launch a Network Access Favorite from within Protected Workspace, you may lose your default gateway when you subsequently leave Protected Workspace. This issue occurs when you terminate Protected Workspace without first explicitly closing the Network Access connection.

Normally, the Network Access connection makes changes to the client's routing table when the connection is launched, and it removes all changes when the connection is terminated. However, the default gateway will not be restored to its original configuration if all of the following conditions are met:

  • You are switched into protected Workspace when logging on to the FirePass controller
  • You launch a Network Access Favorite that uses the Force all traffic through tunnel setting (from the Client Settings section of the Network Access: Resources page)
  • You log off the FirePass controller without first terminating your Network Access connection

    Note: Logging off the FirePass controller without first terminating your Network Access connection can occur in the following manner:

    • Clicking the Logout button on the Webtop
    • Double-clicking the Exit Protected Workspace shortcut on the Desktop
    • Powering off the client computer

F5 Product Development tracked this issue as CR68042 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue was fixed in cumulative HF-601-10 issued for FirePass version 6.0.1 and cumulative HF-602-2 issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

To work around this issue, explicitly terminate the Network Access Favorite prior to logging off the FirePass controller when inside Protected Workspace. To explicitly close the Network Access connection, click the terminate box in the Network Access pop-up window.

If you fail to explicitly close the Network Access connection, you may be able to restore the default route by typing the following command in a command window:

route add 0.0.0.0 mask 0.0.0.0 <ip.address.of.gateway>

Additionally, you may also need to type the following command:

route add <local.network.address> mask <local.network.address.mask> <ip.address.of.gateway>
