Known Issue

The BIG-IP configuration fails to load if a duplicate SNAT translation object exists.

This issue occurs when all of the following conditions are met:

  • You have created a SNAT translation object and given it a name that is not the IP address.
  • You use the TMOS Shell (tmsh) to create a SNAT, and reference the IP address of the SNAT translation object and do not reference the name.

This issue causes the BIG-IP system to create a duplicate SNAT translation object.

For example:

ltm snat-translation 10.1.1.1 {
  address 10.1.1.1
  inherited-traffic-group true
  traffic-group traffic-group-1
}
ltm snat-translation example_translation {
  address 10.1.1.1
  inherited-traffic-group true
  traffic-group traffic-group-1
}

The system will successfully save the configuration; however, if you manually load the configuration file through a UCS install, the upgrade will fail.

Impact

The BIG-IP configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility displays a message indicating that the configuration has not yet loaded.
  • In the /var/log/ltm file of the affected system, you may observe messages similar to the following example:

    0107176c:3: Invalid SNAT Translation, the IP address 10.1.1.1 already exists.
    Unexpected Error: Loading configuration process failed.

Workaround

After the configuration has failed to load, you can remove the duplicate SNAT translation object and replace references to the object in the configuration by editing the /config/bigip.conf file, and performing a manual configuration load to recover. Alternatively, to prevent the configuration load failure from occurring, you can create SNATs with the Configuration utility or reference the non-address name of the SNAT translation object when you create a SNAT using tmsh. To recover from or prevent the issue, perform one of the following procedures:

To prevent the issue

To recover from the issue

To recover from the issue, remove the duplicate SNAT translation object and replace references to the object in the configuration by editing the /config/bigip.conf file and performing a manual configuration load, as follows.

Impact of workaround: Performing a configuration load on an Active device group member can potentially disrupt the service of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP command line.
  2. Make a copy of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.K19415206

  3. Use a text editor such as vi or pico to edit the /config/bigip.conf file.
  4. Locate the duplicate ltm snat-translation stanza within the file. It should appear next to the original.

    For example:

    ltm snat-translation 10.1.1.1 {
  address 10.1.1.1
  inherited-traffic-group true
  traffic-group traffic-group-1
}
ltm snat-translation exampleTranslation {
  address 10.1.1.1
  inherited-traffic-group true
  traffic-group traffic-group-1
}
  5. Remove the entire duplicate ltm snat-translation stanza including the close brace ( } ).

    Important: Make sure that you delete the correct closing brace for the ltm snat-translation stanza, or the load process will fail.

  6. Locate any SNAT objects that reference the duplicate SNAT translation object and replace the duplicate with the original.

    For example, locate the following object:

    ltm snat exampleSNAT {
    origins {
        0.0.0.0/0 { }
    }
    translation /Common/10.1.1.1
}


    Change it to the following:

    ltm snat exampleSNAT {
    origins {
        0.0.0.0/0 { }
    }
    translation /Common/exampleTranslation
}
  7. Save changes to the file, and exit the text editor.
  8. Reload the configuration using tmsh by typing the following command:

    tmsh load sys config

To prevent the issue

To prevent the issue, when you create a SNAT using the tmsh utility, reference the non-address name of the SNAT translation object, as follows.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Create the SNAT and reference the non-address name of the SNAT translation object by using the following command syntax:

    create ltm snat <SNAT name> origins add { <address/mask> } translation <pre-existing SNAT translation object>

    For example:

    create ltm snat exampleSNAT origins add { 0.0.0.0/0 } translation exampleTranslation

  3. Save the configuration change by typing the following command:

    save /sys config

  4. To exit tmsh, type q and press Enter.
