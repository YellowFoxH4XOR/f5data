Topic

When a pool uses Least Sessions load balancing, the BIG-IP system directs traffic to the pool member with the least number of entries in the persistence table. For this load balancing method to work effectively, the pool must be assigned to a virtual server that uses a persistence profile. Additionally, that persistence profile must use the persistence table. Persistence profiles that do not store records in the persistence table are incompatible with the Least Sessions load balancing method.

Refer to the following list for the Persistence profiles that are not compatible with the Least Sessions load balancing method:

  • Hash Persistence in CARP mode
  • Cookie Persistence in Insert mode
  • Cookie Persistence in Rewrite mode
  • Cookie Persistent in Passive mode

The Least Sessions load balancing method works best in environments where the equipment or servers that you are load balancing have similar capabilities.

Note: The Least Sessions load balancing method should not be confused with the Least Connections load balancing method, which directs traffic to the pool member with the least number of entries in the connection table.
