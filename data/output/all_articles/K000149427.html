Description

High CPU utilization is observed during peak traffic times. One of the virtual servers significantly contributes to the high control plane CPU usage, specifically the "bd" process, when an ASM security policy is attached. This virtual server handles an application that processes file uploads using the Content-Type: multipart/form-data.

Example scenario:

$ tmctl proc_pid_stat -s proc_name,processor,cpu_usage_recent |sort -nrk 3 |head -n 10

bd 4 61160 <-- Causing High CPU 

java 1 4970

bigd 3 1830

tmm.0 0 1770

icrd_child 7 1560

bigd 7 1560

mysqld 7 860

mcpd 1 840

avrd 3 800

rtstats 5 790

 

$ tmctl asm_cpu_util_stats -OK avg_5_min -O | head

policy_name_crc vs_name avg_5_sec avg_1_min avg_5_min slot_id

-------------------- -------------------------------------------------------- --------- --------- --------- -------

5560902413583376394 /Common/test_VS_443 8158 6574 6601 0 <-- Causing High CPU

12804012726969174306 /Common/test1_VS_443 33 954 918 0

Environment

  • ASM Security Policy Attached
  • File Uploads (multipart/form-data)
  • High Control Plane CPU caused by bd process.

Cause

None, expected behaviour (file-upload parameters with binary values).

Recommended Actions

Perform following on the security policies consuming high CPU.

1.Identify the URL under the files are uploaded. Create in the allowed URL list. 

2. Identify the parameter which contains file data. Create under the above created URL.

3. Disable the attack signature checks for the created parameter.

4. Save and Apply the policy.

Additional Information

  • If high control plane CPU utilization persists, open an F5 Support Case through the F5 Portal. Refer: K2633: Submit a support case
  • F5 recommends using an external ICAP server for checking the binary file data. Refer: K70941653: Configuring BIG-IP ASM antivirus protection
