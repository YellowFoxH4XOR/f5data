Known Issue

Virtual eXtensible Local Area Network (VXLAN) misconfigurations can cause inconsistent Address Resolution Logic (ARL) entries across Traffic Management Microkernel (TMM) instances.

This issue occurs when the following condition is met:

  • A misconfiguration exists in the network, which causes the BIG-IP system to receive alternating encapsulated frames with the same source media access control (MAC) address from two different endpoints.

    Examples of network misconfigurations include the following scenarios:
     
    • The same MAC address is configured at two different VXLAN Tunnel Endpoints (VTEPs).
    • The VXLAN topology contains a Layer 2 (L2) forwarding loop.

Impact

During the period of inconsistency, TMM instances may incorrectly forward packets that are destined for the same remote MAC address to different endpoints; this behavior occurs until the network misconfiguration is corrected and the conflicting ARL entries expire.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The output of the tmsh show net fdb tunnel command displays multiple members for the same MAC address.

    For example:

    tmsh show net fdb tunnel

    -----------------------------------------------------------------------
    Net::FDB
    Tunnel            Mac Address        Member                     Dynamic
    -----------------------------------------------------------------------
    vx_test           00:17:a4:3f:f6:24  interface:10.11.12.22      yes
    vx_test           00:17:a4:3f:f6:24  interface:10.11.12.23      yes

Workaround

None. To mitigate this issue, you can first address the network misconfiguration, and then optionally modify the vlan.fdb.timeout database key value to use a shorter ARL timeout and expire ARL entries more quickly. The default ARL timeout is 300 seconds (five minutes). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. View the current ARL timeout value by typing the following command:

    list sys db vlan.fdb.timeout all-properties

    The output should appear similar to the following example:

    sys db vlan.fdb.timeout {
        default-value "300"
        scf-config "false"
        value "300"
        value-range "unsigned integer min:0 max:2147483647"
    }
  3. Modify the timeout value by using the following command syntax:

    modify sys db vlan.fdb.timeout value <seconds>

    For example, to set the value to 150 seconds, type the following command:

    modify sys db vlan.fdb.timeout value 150
  4. Confirm the change by repeating step 2.
