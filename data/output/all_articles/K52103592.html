K52103592: Double Fragmented packets may not defragment correctly

Type
Support Solution
Published
2020-12-16
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K52103592

Description
In environments where Large MTU (greater than 1500 bytes) packets cause fragmentation, and VPN tunnels are involved,  you may run into a situation where a large packet is fragmented more than 1 time. In this case, you may run into default IP fragmentation protections configured on the BIG-IP.   

Beginning in BIG-IP 11.4.0, as part of the firewall integration, F5 introduced the tm.minipfragsize BigDB variable. You can use this database variable to modify the minimum IP fragment size that the system accepts, which affects packets that have the More Fragments (MF) flag set to 1. When the payload length of an IP packet with MF set to 1 is below the value of the tm.minipfragsize BigDB variable, the IP packet is dropped. Because this functionality only applies to packets with the MF flag set to 1, this does not apply to packets which are the final fragment in an IP datagram or unfragmented IP datagrams.

When a large MTU environment is fragmented 2 times, it commonly has a second or third small fragment, one of which will have the MF Bit set. By default, this will be dropped, resulting in mangled or failed packets. 

For example:
1800 byte packet going through a 1500 MTU network, and a 1424 MTU VPN tunnel:

1800 - 1500 (300 MF bit set) 1500 - 1436 - (64 byte packet (final packet))

So you have 3 fragmented packets, 300 MF bit unset, 1436 MF bit set, and 64 bit MF bit set. Because of the tm.minipfragsize BigDB variable being defaulted to 552 bytes the 64 byte packet is dropped. 

Environment

  • BIG-IP LTM
  • Oversized packets fragmenting through a complex network.
  • Multiple fragmentation events happening on the path. 

Cause
TCP protections to avoid fragmentation flood attacks is set to drop packets smaller than 552 bytes, when the MF bit is set.

Recommended Actions

  1. The best course of action is to reduce the MTU of the source packets so they fit within the Path MTU (PMTU) of your network. This ensures that fragmentation and the increase in traffic because of it doesn't occur. 
  2. When you cannot avoid the MTU issue, and must address the packet sizes as they are you can reduce the BigDB variable, tm.minipfragsize to the minimum size of an MF bit marked fragment.
