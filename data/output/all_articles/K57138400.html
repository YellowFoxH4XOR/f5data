Known Issue

HTTP Keep-Alive connections may be reset when an iRule uses the HTTP::respond command within an HTTP_REQUEST_SEND event.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with an HTTP profile and an iRule.
  • The iRule uses an HTTP::respond command within an HTTP_REQUEST_SEND event.
  • After an initial HTTP request to the virtual server, the client uses the same TCP connection for a subsequent HTTP request.

Impact

HTTP Keep-Alive connections are reset when a second HTTP request is sent following the initial HTTP request.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • HTTP Keep-Alive connections are reset prematurely.
  • The reset reason displayed in the /var/log/ltm file or a packet capture appears similar to the following example:

    HTTP Unexpected server data past end of response

  • The /var/log/ltm file contains error messages that appear similar to the following example:

    err tmm[12345]: 011f0007:3: http_process_state_egress_data - Invalid action:0x10b080 serverside (172.16.1.1:80 -> 172.16.1.2:46670) clientside (172.16.1.101:46670 -> 172.16.1.102:80) (Server side: vip=/Common/example profile=http pool=/Common/example server_ip=172.16.1.1)

Workaround

To work around this issue, you can use the HTTP::close command before the HTTP::respond command occurs in the iRule, forcing the client to make one HTTP request per connection. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRule > iRule List.
  3. Select the affected iRule to modify.
  4. To force the client to make one HTTP request per connection, add the HTTP::close command prior to the occurrence of the HTTP::respond command. For example:

    when HTTP_REQUEST_SEND {
        clientside {
            if {[HTTP::path] eq "/example.html"} {
                HTTP::close
                HTTP::respond 200 content "This is my response"
            }
        }
    }

  5. Click Update.
