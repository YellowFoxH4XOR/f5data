Description

F5 BIG-IP platforms include an Always-On Management (AOM) subsystem, which provides out-of-band management capabilities such as remote console access and hardware health monitoring. Because the AOM subsystem represents a separate management surface from the BIG-IP host, it is essential to secure and minimize exposure of its interfaces.

Platform capabilities

  • Out-of-band management: The AOM subsystem allows management of BIG-IP platforms using SSH or the serial console. On platforms that support AOM network capabilities, the network interface is disabled by default.
  • Network services: When the AOM network interface is enabled on supported platforms, you can make SSH, Remote Management Control Protocol (RCMP), and Serial over LAN Secure Shell (SOL SSH) available through configuration. Service availability will vary by platform; always refer to platform-specific manuals for details on which services and capabilities are supported. Note that VIPRION systems do not support any AOM network services.
    • SSH (TCP port 22): Accessible after the AOM network interface is assigned an IP address on supported platforms.
    • RMCP (TCP and UDP port 623): Accessible only when Intelligent Platform Management Interface (IPMI) is explicitly enabled on supported platforms.
    • SOL SSH (TCP and UDP port 52123): Accessible only when IPMI is explicitly enabled on supported platforms.
  • User accounts: User account management on the AOM subsystem varies between platforms and hardware revisions. Always refer to platform-specific documentation for details and procedures related to AOM user management.
    • On some platforms, the default root account and password from the host system may be synchronized with the AOM.
    • On others, no user accounts exist by default and must be explicitly created. Support for multiple user accounts also varies and may not be available on all platforms.

Recommendations

Out-of-band management

  • For comprehensive protection, keep BIG-IP platforms in a locked server room or cabinet, with access restricted to authorized personnel. Secure and monitor the serial console port and LCD, and never leave systems unattended or accessible to untrusted individuals.
  • If you do not require out-of-band access from a network source, then leave the AOM management network interface disabled. If enabled, then place it on a trusted, isolated management network and never expose it to the public Internet.
  • Always run supported, up-to-date versions of TMOS or F5OS on BIG-IP platforms, as AOM firmware is automatically updated during operating system upgrades. Regularly check for F5 updates and follow recommended upgrade practices to maintain security and integrity.
  • On TMOS-based BIG-IP platforms, the AOM subsystem can be configured in a read-only mode. This restricts user capabilities to monitoring and viewing status information and prevents any actions that could modify system settings or configurations. If your use case requires monitoring only, then enable the readonly option for AOM to reduce risk and enhance security by limiting access to read-only operations.
  • On F5OS-based platforms (including rSeries and VELOS), enabling appliance mode on the AOM subsystem disables root and shell access to the host operating system, preventing direct maintenance or administrative shell operations. Although appliance mode does not provide a direct equivalent to the TMOS AOM read-only setting, it enforces operational boundaries by restricting users to only those actions allowed by their assigned roles. This approach strengthens security and helps minimize the risk of unauthorized system changes.

Network services

  • On most platforms, assigning an IP address to the AOM network interface makes SSH accessible, regardless of whether you intend to use it. For this reason, it is essential to carefully control and monitor which network interfaces are enabled.
  • Never expose management ports, including the AOM interface, to untrusted networks or the public Internet. If remote access is necessary, then ensure the AOM is placed on a dedicated, trusted management network that is isolated from other networks, and strictly limit access to only authorized users and systems.
  • When configuring the AOM network, avoid assigning the same IP address as the BIG-IP management interface. Do not rely on shared addresses or network address translation (NAT) that could unintentionally expose the AOM.
  • Restrict access to the AOM by source IP using external firewall controls, as the BIG-IP management port firewall does not filter traffic destined for the AOM. If SSH is not required, then keep it disabled.

User accounts

  • If AOM is enabled, then create a dedicated AOM user with a strong, unique password and rotate it regularly. Note that on some platforms, a default root account and password from the host system may be synchronized to AOM, while others require you to explicitly configure AOM accounts. Always refer to platform-specific documentation for user management procedures, as implementation details may vary slightly across hardware revisions.
