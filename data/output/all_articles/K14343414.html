Description

  • ASM DoS profile inject CSPM script
  • Page load problem when enable DoS profile.
  • Analytics profile not in use

Environment

  • ASM DoS profile

Cause

Seen behaviour is caused by a new feature introduced to increase DoS Visibility. Having this enabled will inject JavaScript which can break some applications.

Bug ID 838709

Recommended Actions

You can disable the feature or use an iRules to control which pages should get the JavaScript injection.

Disable the feature :

Note: If you have an http analytics profile assigned to the virtual server by disabling collect-all-dos-statistic only the "Page Load Time" will be not collected . If no http analytics profile is assigned to the virtual server no functionality will be affected by disabling collect-all-dos-statistic
  1. Connect to CLI
  2. Run the following command
    tmsh modify security analytics settings collect-all-dos-statistic disabled
iRules to control which pages should get the JavaScript injection:
  1. On GUI go to Local Traffic  >  iRules : iRule List
  2. Click Create
  3. Type a name for the iRule.
  4. In the iRule definition box, enter the following:
    when HTTP_RESPONSE {
         AVR::disable_cspm_injection
    }
  5. Click Finished.
  6. Navigate to Local Traffic > Virtual Servers.
  7. In the Virtual Servers List, locate the affected virtual server and click the Edit link under the Resources column.
  8. For iRules, click Manage.
  9. In the Available column, locate the iRule you created in step 3, and click it.
  10. Assign the iRule to the virtual server by clicking <<.
  11. Click Finish.
