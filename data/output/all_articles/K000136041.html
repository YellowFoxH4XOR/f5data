K000136041: LDAP login fail if nslcd works abnormally

Type
Support Solution
Published
2023-09-26
Updated
2023-09-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000136041

Description

Each BIG-IP system requires one or more administrative user accounts. Rather than store these BIG-IP user accounts locally on the BIG-IP system, you can store BIG-IP user accounts on a remote authentication server, for example LDAP.
The nslcd daemon controls the functionality of the new nss-pam-ldapd LDAP PAM authentication module. If not running normally, LDAP authentication may fail.
 

Symptoms

Configuration Utility login by LDAP may fail and get error Remote authentication serve unreachable, local authentication failed.
 

Environment

  • LTM
  • LDAP
 

Condition

  • Telnet port 636 works.
  • No LDAP packets on port 636 and mgmt interface.
  • systemctl status nslcd and get error message failed to start naming services LDAP client daemon.
  • Daemon log includes message nslcd.service: main process exited, code=exited, status=1/FAILURE.


Cause

Zombie nslcd exists, leading new nslcd process unable to start properly.


Recommended Action

1. Manually stop nslcd daemon
 #systemctl stop nslcd 

2. Look for PID of nslcd in process list
#tmsh show sys proc-info

3. Kiill nslcd in process    
#kill -9 <nslcd pid>  

4. Manually start  nslcd daemon
#systemctl start nslcd
