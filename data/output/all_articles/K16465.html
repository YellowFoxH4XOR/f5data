Known Issue

The Configuration utility cannot display a child health monitor.

This issue occurs when all of the following conditions are met:

  • You have created at least two health monitors: a parent monitor derived from a built-in monitor and a child monitor derived from the parent monitor.

    For example:

    ltm monitor tcp /Common/parent {
    defaults-from /Common/tcp
    destination *:*
    interval 5
    ip-dscp 0
    time-until-up 0
    timeout 16
    }

    ltm monitor tcp /Common/child {
    defaults-from /Common/parent
    destination *:80
    interval 5
    ip-dscp 0
    time-until-up 0
    timeout 16
    }
  • The two monitors appear in reverse order in the bigip.conf file.

    For example:

    ltm monitor tcp /Common/child {
    defaults-from /Common/parent
    destination *:80
    interval 5
    ip-dscp 0
    time-until-up 0
    timeout 16
    }

    ltm monitor tcp /Common/parent {
    defaults-from /Common/tcp
    destination *:*
    interval 5
    ip-dscp 0
    time-until-up 0
    timeout 16
    }
  • You run the tmsh load sys config command from the command line.

Note: Health monitors may appear in reverse order if the child monitor name precedes the parent monitor name alphabetically, or if the bigip.conf configuration file was manually edited, placing the health monitors in reverse order.

Impact

Possible undefined behavior in the bigd health monitor daemon and failing iControl calls.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H600831 on the Diagnostics > Identified > High screen.
  • When selecting the child health monitor, the Configuration utility displays the following error message:

    An error has occurred while trying to process your request.
  • Running the tmsh load sys config verify command results in an error message that appears similar to the following example:

    01070740:3: Performance monitor /Common/http-a may not have the manual resume feature. Unexpected Error: Validating configuration process failed.

Workaround

You can work around this issue by deleting and recreating the affected health monitors, and verifying that the monitors are named in alphabetical order.

Impact of workaround: Performing this workaround should not have a negative impact on your system.
