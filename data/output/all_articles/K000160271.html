Description

On BIG-IP VE, high rates of incomplete TCP connection attempts can cause one or more virtual servers to reach the syncookie threshold. When this occurs, BIG-IP may log repeated syncookie threshold events, and TMM CPU usage may also increase during the same time window.

Environment

  • BIG-IP LTM

Cause

This behavior occurs when BIG-IP receives a large number of TCP connection attempts that do not complete the three-way handshake at a normal rate. As the number of outstanding incomplete connections increases, affected virtual servers can reach the per-virtual-server syncookie threshold and BIG-IP logs syncookie threshold events for those listeners.

  • This can occur during a SYN flood, large-scale scanning, or an unusually large burst of legitimate clients that do not complete the TCP handshake normally.
  • On BIG-IP VE, syncookie handling is software-based rather than hardware-assisted.
  • Because the mitigation path is software-based, TMM CPU usage may also increase during the same event.
  • Repeated events across multiple virtual servers in the same short interval can indicate that the condition is broad and not limited to a single virtual server.

Recommended Actions

  1. Determine whether the incomplete connection rate is expected or excessive:
    Review packet captures, connection setup rate, and TCP handshake completion behavior to determine whether the event is caused by legitimate traffic growth or by a likely SYN flood or other half-open connection pattern.
  2. Check the scope of the event:
    Determine whether the syncookie threshold event is limited to one virtual server or occurs across multiple virtual servers in the same short interval. Multiple affected virtual servers suggest a broader connection-surge condition.
  3. Correlate with platform impact:
    Check TMM CPU usage and service impact in the same time window. On BIG-IP VE, increased TMM CPU during repeated syncookie threshold events can indicate that software-based mitigation is under pressure.
  4. Choose mitigation based on the traffic pattern:
    If the traffic is legitimate, review client connection behavior and application scaling. If the traffic is malicious or sustained, consider upstream filtering, scrubbing, or additional DDoS protections. Avoid increasing thresholds without first confirming the nature and scope of the traffic.

Additional Information

  • BIG-IP logs the event in a format similar to 01010038: Syncookie counter <CURRENT COUNT> exceeded vip threshold <THRESHOLD> for virtual = <IP ADDRESS>:<PORT NUMBER>.
  • The event is logged per virtual server.
  • Repeated events across multiple virtual servers in the same short interval can be an important indicator that the issue is broader than a single virtual server.
  • The log event alone does not prove malicious intent, and it does not by itself prove CPU exhaustion without same-window CPU validation.
