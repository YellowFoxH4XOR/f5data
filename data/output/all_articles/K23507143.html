K23507143: BIG-IP Configuration utility(GUI) becomes unresponsive and terminate session after few seconds

Source

Description

The BIG-IP management GUI (HTTPS) becomes unstable and unresponsive, with sessions dropping shortly after login or the GUI failing to load completely. You can observe similar errors in /var/log/messages logs:

 Nov 25 03:14:01 localhost.localdomain notice syslog-ng[12452]: Syslog connection established; fd='14', server='AF_INET(192.168.1.1:514)', local='AF_INET(0.0.0.0:0)'
  Nov 25 03:14:01 localhost.localdomain notice syslog-ng[12452]: Syslog connection broken; fd='14', server='AF_INET(192.168.1.1:514)', time_reopen='60'

Environment

  • Syslog logging configured
  • High CPU
  • BIG-IP Configuration utility

Cause

Bug ID 1040277: Syslog-ng issue may cause logging to stop and possible reboot of a system

Recommended Actions

Immediate Workaround:

Restart the syslog-ng process to restore management GUI access:

bigstart restart syslog-ng

Impact of workaround: This procedure does not impact production traffic; only remote logging is temporarily stopped while the process restarts.

Diagnostic Steps:

  1. Verify high CPU usage by syslog-ng:
    tmctl proc_pid_stat -s proc_name,cpu_usage_5mins -OK cpu_usage_5mins -L 10
    Look for syslog-ng showing abnormally high CPU usage (near or above 100%).

  2. Check for syslog connection issues in logs:
    grep "syslog-ng" /var/log/messages
    Example errors: 
    Nov 25 03:14:01 localhost.localdomain notice syslog-ng[12452]: Syslog connection established; fd='14', server='AF_INET(192.168.1.1:514)', local='AF_INET(0.0.0.0:0)'
    Nov 25 03:14:01 localhost.localdomain notice syslog-ng[12452]: Syslog connection broken; fd='14', server='AF_INET(192.168.1.1:514)', time_reopen='60'
  3. Verify CPU usage using top command:
    top
    Confirm syslog-ng process is consuming excessive CPU.

Long-term Resolution:

  1. Investigate and resolve connectivity issues with remote syslog servers
  2. Ensure remote syslog destinations are reachable and stable
  3. If a remote syslog server is unreachable, remove it from the BIG-IP syslog configuration:
    • Navigate to System > Logs > Configuration > Remote Logging in the GUI
    • Remove the unreachable remote syslog server
    • Click Update
  4. Monitor syslog-ng CPU usage after implementing fixes
