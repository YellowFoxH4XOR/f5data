Issue

Error Message

arp: info overwritten for <IP_address> by <MAC_address>

In this error message, note the following:

  • <IP_address> is the IP address associated with a given MAC address
  • <MAC_address> is the MAC address associated with a given IP address

For example:

arp info overwritten for 10.1.1.6 by 00:08:c7:4b:3e:d6

Message Location

You may encounter this message in the following locations:

  • The BIG-IP console
  • The /var/log/messages file

Description

The message indicates that the ARP table has been updated in response to ARP reply packets seen on the local network advertising the MAC address responsible for the IP address in question.

Note: ARP replies may be sent to a specific requester in response to an ARP who-has broadcast, or broadcast gratuitously upon startup or status change (gratuitous ARP or GARP). For example, redundant systems, such as BIG-IP, may send a gratuitous ARP broadcast to advertise a new MAC address for the shared IP address upon startup or failover.

Impact

The impact may depend on the frequecy and duration of the arp messages. Refer to the Recommend Actions section for details.

Recommended Actions

If this message is seen once, it may indicate a physical interface or device has been replaced. If a device or interface was intentionally replaced, the warning message may safely be ignored. If the MAC address change is unexpected, you should investigate further.

If the message is seen occasionally, it usually indicates that multiple devices are successfully sharing an IP address. For example, a redundant BIG-IP system shares an IP address on each VLAN, and broadcasts a new MAC address for each shared IP address upon startup or failover. If this is an expected pattern, the warning may safely be ignored; if not, you should investigate further.

If the message is seen repeatedly in rapid succession, it usually indicates that multiple network devices are advertising that they are responsible for the same address. When multiple systems send ARP replies, the ARP table entry on neighboring systems for the address in contention repeatedly flaps between the MAC addresses seen in each ARP reply.

For example, if a server that has just been added to the network is configured in error to use the IP address that is already assigned to the upstream router interface, the following set of error messages is repeatedly logged to the console:

WARNING: arp info overwritten for 10.1.1.6 by 00:08:c7:4b:3e:d6
WARNING: arp info overwritten for 10.1.1.6 by 00:03:47:08:A4:D4
WARNING: arp info overwritten for 10.1.1.6 by 00:08:c7:4b:3e:d6
WARNING: arp info overwritten for 10.1.1.6 by 00:03:47:08:A4:D4

This behavior occurs because the system logging the messages is seeing ARP replies or broadcasts regarding 10.1.1.6 from a device with MAC address 00:08:c7:4b:3e:d6, and also from a device with MAC address 00:03:47:08:A4:D4. The two devices should be located and their configurations examined for the source of the contention.
