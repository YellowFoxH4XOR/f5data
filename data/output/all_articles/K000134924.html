Description

Sometimes, the /var/log/restjavad-audit.*.log file could contain the following messages logged every second:

[I][316][20 Apr 2023 01:31:27 UTC][ForwarderPassThroughWorker] {"user":"local/admin","method":"GET","uri":"http://localhost:8100/mgmt/tm/sys/available","status":400,"from":"com.f5.rest.common.RestAvailabilityEntry"}

Environment

  • BIG-IP environment where REST API calls are issued

Cause

This situation is typically observed when you start sending queries to an endpoint that isn't supported or ready.

/mgmt/tm/sys/available is an endpoint which will register when actual underlying API endpoint being queried is successfully registered. There are REST availability monitoring in place which will check for availability of actual endpoints by adding /available for every second. The /mgmt/tm/sys/available endpoint is not visible in a packet capture as this executes internally inside the restjavad service and not something that would be visible in a communication between restjavad and icrd_child process.

Recommended Actions

None.
