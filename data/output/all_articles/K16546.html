Known Issue

The BIG-IP system does not validate traffic group object dependencies.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system has at least two traffic groups configured with the following:

    • A virtual server and virtual address in one of the traffic groups

    • A SNAT translation address in another traffic group

The BIG-IP system incorrectly allows you to create a virtual server (which creates the virtual address) in traffic-group 2 and a SNAT translation IP in traffic-group 1, and then assign the SNAT IP to the virtual IP address. If the two traffic groups are active on separate BIG-IP systems, response traffic from pool members would be incorrectly sent to the wrong BIG-IP system.

Impact

This configuration may cause asymmetric routing to occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A symptom of asymmetric routing is connection timeout and failure. To confirm the presence of this behavior, packet captures can be taken concurrently at the BIG-IP and pool members. For more information, refer to K1893: Packet trace analysis.

Workaround

There is no workaround for this issue. To avoid asymmetric routing, verify that SNAT translation IP addresses reside in the same traffic-group as the virtual address for which they are assigned.
