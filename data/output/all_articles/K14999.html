Known Issue

The diameter virtual server fails to rewrite attributes with the configured settings. This issue occurs when all of the following conditions are met:

  • The associated diameter profile is configured with a non-zero value for the Watchdog Timeout setting.
  • The associated diameter profile has any of the following attributes configured:

    • Origin Host setting under the To Client section (origin-host-to-client)
    • Origin Realm setting under the To Client section (origin-realm-to-client)
    • Origin Host setting under the To Server section (origin-host-to-server)
    • Origin Realm setting under the To Server section (origin-realm-to-server)
  • The diameter virtual server sends a Device Watchdog Request (DWR) message to both the client and server when the watchdog timeout is triggered.

When this issue occurs, the diameter virtual server sends out DWR messages with the cached attributes in the CER from diameter client and CEA from the diameter server. For example, the Origin Host attribute from the client's CER is used as the Origin Host attribute in the DWR sent to the server instead of the configured Origin Host setting under the To Server section of the associated diameter profile. Conversely, the Origin Host attribute from the server's CEA is used as the Origin Host attribute in the DWR sent to the client instead of the configured Origin Host setting under the To Client section of the associated diameter profile.

Impact

Diameter sessions may terminate unexpectedly.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H440745 on the Diagnostics > Identified > Medium screen.
  • A packet capture on the affected traffic shows the diameter virtual server sending DWR messages with an incorrect Origin Host or Origin Realm attribute to the client. Similarly, a packet capture on the affected traffic shows the diameter virtual server sending DWR messages with an incorrect Origin Host or Origin Realm attribute to the server.
