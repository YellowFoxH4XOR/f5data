Topic

You can add an NTLM authentication server by performing the following two procedures:

  • Adding an NTLM authentication Server for a domain
  • Associating the NTLM authentication server with the namespace 

Important: Adding a first, or removing the last, NTLM authentication server from a namespace requires for the namespace to be temporarily disabled. Plan for a service interruption in either of those cases.

Note: Beginning in ARX 5.1.0, the new ARX Secure Agent supports NTLMv2. For more information about the Secure Agent software, refer to K10026: Overview of the ARX Secure Agent software.

Note: Beginning with ARX 5.2.0, with the introduction of support for constrained delegation, F5 made available NTLM authentication support without the dependency on the ARX Secure Agent software. Constrained delegation eliminates the requirement for the ARX Secure Agent software in order to use NTLM authentication. For information about constrained delegation, refer to K12239: Overview of constrained delegation. F5 strongly recommends using constrained delegation to support NTLM authentication.

Add an NTLM Authentication Server for a domain

You can define NTLM authentication servers for the domains of any clients who need to use NTLM authentication using the GUI or the CLI.

Using the ARX Manager GUI

  1. Log in to the ARX Manager GUI.
  2. Expand Authentication.
  3. Select NTLM Auth. Servers.

    The NTLM Authentication Server Summary page will display.
  4. Click Add.

    The Add NTLM Authentication Server page will display.
  5. In the NTLM Auth. Server Name field, assign a name for the new NTLM authentication server configuration object.

    Note: This name only identifies the object; it has no impact on functionality.
  6. In the IP Address field, input the IP address of the NTLM authentication server.
  7. In the Windows Domain field, input the Windows domain for which this NTLM authentication server is used.
  8. In the Secure Agent Password field, input the password defined on the ARX Secure Agent software running on that authentication server.

    Note: For more information about installing the ARX Secure Agent software on that authentication server, refer to the ARX Secure Agent Installation Guide.
  9. Confirm the password in the Confirm Secure Agent Password field.
  10. If you redefined the port that the ARX Secure Agent uses on that authentication server, input the correct port into the Agent Port field.

    Note: In most cases, you will leave this value as the default port of 25805.
  11. Click OK.

    The page display will return to the NTLM Authentication Server Summary page, and the new authentication server that you just defined will now be listed.

Using the ARX CLI

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Enter global configuration mode by typing the following command:

    global

    You are now in gbl configuration mode.

  4. Define the new NTLM authentication server using the following command syntax:

    ntlm-auth-server <name>

    Replace <name> with a sensible name for the configuration object. This name does not affect functionality.

    For example:

    ntlm-auth-server lm1
  5. Confirm to create this new NTLM authentication server configuration object by typing the following word:

    yes

    You are now in gbl-ntlm-auth-srv configuration mode.
  6. Specify the IP Address of the NTLM authentication server, using the following command syntax:

    ip address <address>

    Replace <address> with the IP address of the NTLM authentication server.

    For example:

    ip address 10.0.0.1
  7. Specify the Windows Domain that this NTLM authentication server will be used, using the following command syntax:

    windows-domain <domain>

    Replace <domain> with the relevant Windows Domain.

    For example:

    windows-domain ask.f5.com
  8. Specify the password for the ARX Secure Agent software running on that NTLM authentication server, by typing the following command:

    password

    You will be prompted to input and to confirm the password.
  9. Return to privileged mode by typing the following command:

    end

Associate the NTLM authentication server with the appropriate namespace

You can associate the new NTLM authentication servers with the appropriate namespace by using the GUI or CLI.

Using the ARX Manager GUI

  1. Log in to the ARX Manager GUI.
  2. Select Namespace.

    The Namespace Summary page will display.
  3. If this is the first NTLM authentication server for this namespace, you must disable the namespace prior to adding it. To do so, select the check box next to the namespace, and click Disable.

    Important: Disabling the namespace will disrupt access to exports of volumes in this namespace to all clients.

    A dialog box will appear and ask you to confirm that you want to disable the namespace and all associated volumes.

    Confirm the warning dialog box by pressing OK.

    The page display will return to the Namespace Summary page.
  4. Select the check box next to the namespace.
  5. Click Edit.

    The Edit Namespace page will display.
  6. Select the Use NTLM check box.

    The list of NTLM Authentication Servers will become enabled.
  7. Select the NTLM Authentication Server that you defined earlier from the list.

    Note: You may select multiple NTLM Authentication Servers from the list, if necessary. 
  8. Select OK.

    The Namespace Summary page will display.
  9. If you disabled the namespace in an earlier step, select the check box next to the namespace, and click Enable.

Using the ARX CLI

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode by using the following command syntax:

    namespace <name>

    Replace <name> with the name of the relevant namespace.

    For example:

    namespace ns1

    You are now in gbl-ns configuration mode.
  5. If this is the first NTLM authentication server for this namespace, you must disable the namespace by typing the following command:

    no enable

    Important: Disabling the namespace will disrupt access to exports of volumes in this namespace to all clients.
  6. Associate the NTLM authentication server with the namespace using the following command syntax:

    ntlm-auth-server <server>

    Replace <server> with the name of the NTLM authentication server that you defined in the prior procedure.

    For example:

    ntlm-auth-server lm1
  7. If you disabled the namespace in an earlier step, then re-enable the namespace by typing the following command:

    enable
