Known Issue

When a Microsoft Windows 7 client enters protected workspace, some of the protected workspace features do not function properly. Specifically:

  • The red desktop wallpaper does not appear.
  • The web browser does not automatically resume the connection to the FirePass controller. Instead, an error message similar to the following example is displayed, where <username> is the user's Windows username:

    Cannot find
    'file:///C:/Users/<username>/AppData/Local/Temp/toSandbox/HTMLToResume.html'. Make sure the path or Internet address is correct.

  • The Windows Start menu is not updated.
  • The Exit Protected Workspace and Switch temporarily from Protected Workspace icons may disappear after a few seconds. If they remain on the desktop, they are not functional. In order to exit protected workspace, users must select Log off from the Windows Start menu.

F5 Product Development tracked this issue as CR121109 and it was fixed in FirePass 7.0.0. For information about upgrading, refer to the FirePass Release Notes.

In addition, this issue has been fixed in cumulative hotfix HF-610-1, which has been issued for FirePass 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

Although you cannot work around the specific issues described in this solution, you may want to configure the pre-logon sequence to perform a different set of actions for Windows 7 clients. For example, denying logon access to Windows 7 clients or bypassing the protected workspace requirement for Windows 7 clients.

Note: For information about detecting Windows 7 clients in a pre-logon sequence, refer to K10663: Detecting Microsoft Windows 7 clients in a pre-logon sequence.
