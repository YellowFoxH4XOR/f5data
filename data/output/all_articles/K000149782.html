Data and model poisoning

Data and model poisoning is a critical vulnerability in large language models (LLMs) in which malicious actors inject manipulated data (pre-training, fine-tuning, or embedding or a combination of these) into the training dataset to introduce vulnerabilities, back doors, or biases. This can lead to compromised model integrity, degraded performance, and unintended behaviors.

Data and model poisoning attack scenario

In this example attack scenario, a malicious actor aims to compromise the integrity of a LLM used by a financial institution for customer service automation. The attacker identifies the financial institution’s LLM deployment and gathers information about the data sources used for training the model. The attacker discovers that the financial institution uses publicly available customer feedback data and internal transaction records for training.

The attacker then creates multiple fake customer accounts and submits biased and misleading feedback through the institution’s online feedback system. Additionally, the attacker exploits a vulnerability in the institution’s API to inject manipulated transaction records into the internal database. The compromised data is included in the next training cycle of the LLM where it learns from the poisoned data, incorporating the biases and vulnerabilities introduced by the attacker.

The attacker interacts with the deployed LLM through the customer service chatbot and triggers the model to generate biased responses, leading to customer dissatisfaction. As a result, the financial institution faces reputational damage and potential financial losses due to customer dissatisfaction.

General strategies for mitigating data and model poisoning attacks

The general mitigation approaches include (but not limited to the following):

  • Data validation and sanitization

    Implementing rigorous data validation checks to ensure the integrity of the training data during all model development stages. For example, validate model outputs against trusted sources of data.

  • Robust training processes

    Using techniques like differential privacy and adversarial training to enhance model robustness.

  • Continuous monitoring

    Regularly monitor model outputs and retrain it with clean data to detect and mitigate poisoning attempts.

Secure against LLM data and model poisoning attacks using defense-in-depth strategies with F5 products

This section discusses the defense-in-depth strategies involving multiple layers of security controls and measures using F5's range of products and services that can assist in mitigating the threat at different layers:

Figure: Defense-in-depth with F5 products

Using F5 products and a defense-in-depth security strategy for your LLM applications can help reduce the likelihood of OWASP LLM vulnerabilities. This approach involves using multiple layers of security to protect your accounts, workloads, data, and assets. By doing so, you can ensure that if one security measure is compromised, additional layers can effectively help isolate threats and manage security events. You can enhance security and resilience by integrating various strategies, including F5 services and solutions, at each layer.

Integration with OAuth providers

BIG-IP APM integrates with your OAuth provider to implement secure authentication. Depending on your application logic, configure the following agents in a per-request policy:

  • An OAuth Client agent in a per-request policy with OpenID Connect to authenticate API requests with your OAuth provider.
  • An OAuth Scope agent in a per-request policy to validate tokens issued by your OAuth provider. You can configure the BIG-IP APM to validate JWT tokens either internally or externally.

In both configurations, implement the following to add a layer of protection against broken user authentication attacks:

  • Access token expiry
  • Access token denylist
  • Validate that the access token is signed with a secure signing algorithm

Summary

Data and model poisoning is a significant threat to the integrity and performance of LLMs. By implementing robust data validation, continuous monitoring, and leveraging F5’s comprehensive security solutions, organizations can effectively mitigate this threat and ensure the reliability of their AI deployments.
