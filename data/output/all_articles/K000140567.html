K000140567: Change in permissions to sshd causes users to fail ssh to device

Type
Support Solution
Published
2024-08-27
Updated
2024-08-27
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000140567

Description

User cannot access the BIGIP device using CLI.

/var/log/secure logs shows 

 

Jan  1 00:09:02 bigip.f5.com crit sshd[18328]: fatal: /var/empty/sshd must be owned by root and not group or world-writable.
Jan  1 00:09:07 bigip.f5.com crit sshd[18331]: fatal: /var/empty/sshd must be owned by root and not group or world-writable.
Jan  1 00:09:11 bigip.f5.com crit sshd[18333]: fatal: /var/empty/sshd must be owned by root and not group or world-writable.
Jan  1 00:09:23 bigip.f5.com crit sshd[18345]: fatal: /var/empty/sshd must be owned by root and not group or world-writable.
Jan  1 00:10:27 bigip.f5.com crit sshd[18426]: fatal: /var/empty/sshd must be owned by root and not group or world-writable.

 

Upon checking the permissions for /var/empty/sshd, it has read, write, and execute permissions allowed to it for the user groups and other.

 

config # ls -lhd /var/empty/sshd
drwxrwxrwx. 2 root root 4.0K Jan 1 03:49 sshd

 

It can also be seen that sshd is down or failed to start.

 

config # systemctl status sshd.service
* sshd.service - OpenSSH server daemon
Loaded: loaded (/usr/lib/systemd/system/sshd.service; enabled; vendor preset: enabled)
Active: failed (Result: exit-code) since Thu 2024-01-01 00:02:31 PDT; 2min 29s ago    

Environment

LTM
SSHD

Cause

Permissions were changed to the directories.

Recommended Actions

Change back the permissions back to its default for /var/empty/sshd.

 

  1. Login to BIGIP CLI using Console or to the terminal which still has access to the device (existing connection).
  2. Enter commands below.

                     bash

                     chmod 755 /var/empty/sshd

                     bigstart restart sshd
