Description
Packet capture reveals that F5 using non-floating self IP when connecting to backend pool members.

Environment

  • LTM
  • Floating self IP
  • Traffic group

Cause
Floating self IP and virtual address not in the same traffic-group.

ltm virtual-address /example/10.0.0.1%2 {
    address 10.0.0.1
    arp enabled
    mask 255.255.255.255
    traffic-group /Common/abc
}

net self /example/Internal_Floating_IP_Address {
    address 172.16.0.1/29
    allow-service all
    traffic-group /Common/traffic-group-1
    vlan /example/INTERNAL_VLAN
}

Recommended Actions

Both floating self IP and virtual address must be part of the same traffic-group
