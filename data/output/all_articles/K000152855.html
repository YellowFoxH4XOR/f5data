Description

Attempts to delete a CA certificate from the BIG-IP system may fail with the following error message:

01070265:3: The Certificate File (<certificate_name>.crt) cannot be deleted because it is in use by a AAA OCSP Responder (<ocsp_responder_profile>).

This issue persists even when the Access Policy Manager (APM) module is not currently provisioned, and the referenced OCSP Responder profile is not visible or accessible via the GUI.

Environment

  • Product: BIG-IP APM
  • Configuration:
    • APM module previously provisioned and later deprovisioned
    • CA certificate assigned to an OCSP Responder profile
    • High Availability (HA) pair configuration

Cause

The CA certificate remains referenced by an OCSP Responder profile, which is an object managed by APM. When APM is deprovisioned, these objects persist in the configuration but are hidden from the GUI, preventing removal of either the responder or its associated certificate.

Recommended Actions

To remove a CA certificate that is still referenced by an OCSP Responder after APM has been deprovisioned:

  • Preparation
    • Schedule a maintenance window; provisioning/deprovisioning APM restarts certain services and causes temporary unavailability.
    • Take a UCS backup before making changes.
  • Procedure
    1. Provision APM on Standby Unit
      Set APM provisioning to "Minimum" or "Nominal" on the standby device.
      The system will reload configuration and restart services such as named, iprepd, avrd, aced, vxland (no full reboot required).
    2. Remove OCSP Responder Profile
      In GUI: Navigate to Access > Authentication > OCSP Responder.
      Delete any OCSP Responders referencing the target certificate.
    3. Delete CA Certificate
      Go to System > Certificate Management > Traffic Certificate Management > SSL Certificate List.
      Delete the desired CA certificate.
    4. Deprovision APM
      Set APM provisioning back to "None" on the standby device.
      The same services will restart as during provisioning.
    5. Sync Configuration
      Perform a device group sync from standby to active unit.
      Confirm that both devices no longer have the responder or certificate present.
    6. Repeat if Necessary
      If objects remain on active unit after sync, perform failover and repeat steps 1–5 on new standby unit.

Note: No full device reboot occurs; only service restarts are triggered. Always verify removal of both responder and certificate after sync completes. For details about restarted services during this process, refer to F5 documentation for daemon management.
