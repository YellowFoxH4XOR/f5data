Topic

When a BIG-IP failover event occurs, the newly active BIG-IP system sends out gratuitous ARPs (GARPs) for floating self IP addresses and virtual server addresses in order to update the Address Resolution Protocol (ARP) cache of devices on the network. If a large number of IP addresses are configured for a VLAN, the GARPs may be sent out too quickly for network devices to process. This may result in stale ARP entries on the device.

This behavior occurs most often on network devices that have the following characteristics:

  • Devices that accept only a limited number of broadcast frames per second before dropping the rest
  • Devices that have large ARP cache timeouts
  • Devices that prevent ARP updates

You can prevent this behavior by enabling MAC masquerading on the BIG-IP system. MAC masquerading allows the floating self IP addresses and virtual server addresses to share a floating MAC address. When the BIG-IP system fails over and the GARP is issued for all the floating and virtual server addresses, the same MAC address is sent. Because the same MAC address is used, no MAC update occurs. However, the device changes the port on which the ARP updates were received.

Note: For information about configuring MAC masquerading, refer to the Managing Failover chapter of the BIG-IP Device Service Clustering: Administration manual. For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

If enabling MAC masquerading on the BIG-IP system is not an option, F5 recommends that you make the following modifications on the relevant network devices:

  • Increase the number of allowed broadcast frames, per second, before dropping the rest
  • Increase the input buffer size
  • Allow ARP updates to occur on the device

Changing these options will vary on different network devices. For information about altering these behaviors, consult the manufacturer's documentation for your specific device.

With Cisco IOS, you can change the size of the input hold queue by using the hold-queue configuration command on the interface that is attached to the network that contains the BIG-IP system.

For example:

hold-queue 400 in

Consult the Cisco documentation for the applicability to your specific device.

Note: For information about adjusting the number of GARPs that the BIG-IP system sends out per second, refer to K11985: Overview of the arp.gratuitousrate and arp.gratuitousburst database variables.
