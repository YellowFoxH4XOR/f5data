Description

When attempting to bind a DoS Protection Profile containing a whitelist to a Virtual Server with a wildcard or subnet destination address (Traffic Matching Criteria) on BIG-IP AFM systems with sPVA hardware, the following error occurs:

01b90064:3: Virtual Server (<virtual_server_name>) with DoS Protection Profile Whitelist cannot contain wildcard destination addresses.

This error appears when:

  • Modifying a Virtual Server configuration in the GUI or CLI
  • Attempting to attach a DoS Protection Profile with a whitelist to a Virtual Server with destination address masks less than /32 (IPv4) or /128 (IPv6)

The error message may appear in:

  • GUI configuration interface during Virtual Server modification
  • /var/log/ltm log file

Note: This error may not appear during system upgrades or configuration loads, but will occur when attempting to modify the Virtual Server configuration after upgrade.

Environment

  • Product: BIG-IP AFM (Advanced Firewall Manager)
  • Platforms: sPVA-capable hardware including:
    • rSeries: F5-BIG-R5800, F5-BIG-R5900, F5-BIG-R10900, F5-BIG-R12900, F5-BIG-R15900
    • iSeries: i5600, i5800, i7600, i7800, i10600, i10800, i12600, i12800, i15600, i15800
    • C-Series: C121, C122, C123
  • Software Versions: BIG-IP 16.1.0 and later 
  • Configuration:
    • DoS Protection Profile with whitelist configured
    • Virtual Server with destination address mask less than /32 (IPv4) or /128 (IPv6)
    • Examples: 0.0.0.0/0/0 (wildcard), 10.1.1.0/24 (subnet)
  • Recent Actions:
    • Upgrading from versions prior to 16.1.0 (e.g., 15.1.x) to 16.1.0 or later
    • Attempting to modify Virtual Server or DoS Protection Profile configuration

Cause

Design limitation for sPVA hardware. sPVA does not support DoS Protection Profile whitelists on Virtual Servers with destination address masks less than /32 (IPv4) or /128 (IPv6). 

Answer/Recommended Actions

To resolve this issue, use one of the following approaches:

  1. Configure host-specific Virtual Servers (Recommended):
    • Create individual Virtual Servers for each host IP address with /32 mask (IPv4) or /128 mask (IPv6)
    • Attach the DoS Protection Profile with whitelist to these host-specific Virtual Servers
    • Example: Instead of one Virtual Server with destination /0.0.0.0/0, create separate Virtual Servers for each public IP (e.g., ,203.0.113.1/32, 203.0.113.2/32))
  2. Remove whitelist from DoS Protection Profile:
    • If wildcard or subnet Virtual Servers are required, remove the whitelist configuration from the DoS Protection Profile
    • Use alternative methods for trusted source identification if needed

Important: This limitation is by design and not a software defect. It aligns with sPVA hardware capabilities and resource constraints.

Additional Information

  • Configurations created in versions prior to 16.1.0 (e.g., 15.1.x) may load successfully after upgrade, but the error will appear when attempting to modify the Virtual Server or DoS Protection Profile
  • This limitation applies specifically to sPVA-capable hardware platforms and does not affect Virtual Edition (VE) deployments
