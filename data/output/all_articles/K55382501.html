Issue

You should consider using these procedures under the following condition:

  • Your BIG-IP system is unable to generate BIG-IP APM reports.

Symptoms

As a result of unexpected events, you may encounter the following symptoms:

  • When you try to run BIG-IP APM reports to track user-session information, you encounter the following error message:

    Query Error: Error running the report.

  • You cannot view BIG-IP APM session IDs.

Recommended Actions

When you experience trouble generating BIG-IP APM session reports, you can use the following troubleshooting procedures to determine the root cause:

Procedures

  • Verifying that the required services are running
  • Verifying there is enough available disk space
  • Checking the log files for errors

Verifying that the required services are running

Some system services must be running in order for the BIG-IP APM system to generate session reports. You can perform the following procedure using the TMOS Shell (tmsh) to ensure that required services are running:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view a list of all the system services and their current status, enter the following command:

    show sys service all

    Output appears similar to the following example:

    aced run (pid 25705) 65 days, 2 starts
    adfs_proxy run (pid 27276) 65 days, 2 starts
    admd down, Not provisioned
    alertd run (pid 5455) 83 days
    antserver down, Not provisioned
    apm_websso run (pid 27283) 65 days, 2 starts
    apmd run (pid 25707) 65 days, 2 starts
    asm down, Not provisioned
    autodosd down, Not provisioned
    avrd run (pid 25709) 65 days, 2 starts

  3. Ensure that the following services are running:
    • The AVR daemon (avrd), which the BIG-IP APM system uses with the monpd process for reporting and charts.
    • The mysqld process, which is the database server storing data for reporting, charts, and event logs reports.
    • The monpd process, which the BIG-IP APM system uses with the avrd process for reporting and charts.
    • The fslogd and logmysqld processes, which populate the MySQL database with the event logs generated by the Traffic Management Microkernel (TMM) and other related daemons.
    • The tomcat daemon, which provides web server functions for the BIG-IP web utility. tomcat is an open-source implementation of Java servlet and JavaServer pages developed under the Jakarta project at the Apache Software Foundation.

    You can stop, start, restart, or view the status of a daemon using tmsh by using the following command syntaxes:

    • stop /sys service <service name>
    • start /sys service <service name>
    • restart /sys service <service name>
    • show /sys service <service name>

    Note: Replace <service name> with the BIG-IP service name. For example, to restart the named process, enter the restart /sys service named command.

Verifying there is enough available disk space

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Monitoring the hard disk capacity on a BIG-IP device is critical to maintaining a healthy system. If a BIG-IP system is running low on disk space, you may experience a number of performance-related issues as well as the inability to generate reports. F5 recommends that you periodically check disk space usage and use industry best practices for keeping disk usage to a minimum.

To check that a disk partition has not run out of space, perform the following procedure:

  1. Log in to the BIG-IP APM command line.
  2. Enter the following command:

    df -h

    Output appears similar to the following example:

    Filesystem Size Used Avail Use% Mounted on
    /dev/md8 380M 216M 145M 60% /
    /dev/md10 3.0G 294M 2.6G 11% /config
    /dev/md9 2.7G 2.0G 564M 79% /usr
    /dev/md11 3.0G 813M 2.1G 29% /var
    /dev/md1 30G 7.9G 21G 29% /shared
    /dev/md2 6.9G 6.9G 0 100% /var/log

    Note: In the example output, note that the filesystem /dev/md2 and the configured mount point /var/log columns Use% = 100 and the Avail = 0. This file system has maximized the available disk space for that partition.

    Important: If your /var/log directory (mount point) is fully used, refer to: K14403: Maintaining disk space on the BIG-IP system.

Checking the log files for errors

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Check the following log files for the following errors, which may indicate a report generation failure.

  • /var/log/webui.log
  • /var/log/tomcat/catalina.out
  • /var/log/avr/monpd.log

If you see Error: Error running the report, you can restart the monpd process and try to view the BIG-IP sessions by entering the following command:

bigstart restart monpd

If you are still unable to generate the reports, you can restart all of the following processes and try and view the BIG-IP APM session reports by entering the following command:

Impact of procedure: The following command may cause the BIG-IP system to stop processing traffic momentarily.

bigstart restart logmysqld fslogd monpd tomcat mysql
