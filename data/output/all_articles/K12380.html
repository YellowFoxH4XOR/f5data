Topic

When you replace a faulty hard drive, you should first disassociate the hard drive from the redundant array of independent disks (RAID) before you physically remove the hard drive and insert the replacement drive.

If a hard drive is physically detached without being disassociated from the RAID array on the BIG-IP 6900, 7000s, 7200v, 8900, 8950, 10000s, 10200v, 11000, or 11050 platforms running BIG-IP 10.1.0 and later, the RAID Status reports as Degraded in the Configuration utility. The status remains as degraded even after the RAID array is successfully rebuilt with the replacement hard drive.

Note: The array rebuild process takes approximately 30 to 60 minutes to complete. However, if the BIG-IP system actively passes traffic, the process may take considerably longer.

The RAID array reports as degraded because the removed drive remains associated with the RAID array with a status of missing. To view the status of the RAID array, use the tmsh show sys raid array command on the CLI.

For example, if a system administrator physically removes the hard drive with serial number WD-WCAT1F023504 from bay 1 without first disassociating the hard drive from the RAID array, and then inserts a replacement hard drive with serial number WD-WCAT1F339643 into bay 1, as expected, the Configuration utility displays the RAID Status as Degraded, while the RAID array rebuilds. However, after the RAID array replication is complete, the Configuration utility continues to display the RAID status as degraded. From the CLI, the output of the tmsh show sys raid array command appears similar to the following example:

Sys::Raid::Array: MD1

---------------------
Size (MB) 305245

Sys::Raid::ArrayMembers
Bay ID Serial Number Name Array Member Array Status
---------------------------------------------------------
- WD-WCAT1F023504 --- yes missing
1 WD-WCAT1F339643 HD2 yes ok
2 WD-WCAT1F339596 HD1 yes ok

The Array Status of ok for disk 1 and 2 indicates the RAID array is restored. However, the Configuration utility reports the RAID status as degraded until the removed drive disassociates from the RAID array.

You can disassociate the removed hard drive from the RAID array by performing one of the following procedures:

Disassociating the removed hard drive from the RAID array using the array utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Remove the missing drive from the RAID array using the following command syntax:

    array --erase <hard drive serial number>

    Replace <hard drive serial number> with the serial number of the removed drive as displayed in the output of the tmsh show sys raid array command.

    For example:

    array --erase WD-WCAT1F023504

Disassociating the removed hard drive from the RAID array using the BIG-IP Configuration utility (BIG-IP 11.x and later)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Disk Management.
  3. Select the check box of the disk with the Missing Array Status from the Software and Mixed Mode Disks view.
  4. Click Remove Disk From Array.
  5. To confirm the disk removal operation, click the OK prompt. 
The Configuration utility now reports a RAID Status of OK.
