K40154406: None of the configured JWK keys match the received JWT token

Type
Support Solution
Published
2023-01-31
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K40154406
Description
APM logs an error like this:

"Agent created variable name: perflow.oauth.scope.auth_hdr_value, value: Bearer error="invalid_token",error_description="None of the configured JWK keys match the received JWT token, JWT Header: <...>"

Environment
VS configured with a Per Request Policy that includes a Subroutine with an OAuth Scope agent.
APM receives a request including an Authorization Bearer header with a JWT token.

Cause
APM can not find a JWK key to validate the JWS signature

APM uses these claims from the JWS header (in that order) to identify the JWK used to verify the JWS signature
1)x5t
2)x5t_s256
3)kid

"x5t" claim is the X.509 Certificate Thumbprint and usually is included in the JWS Header when "x5t" and "x5c" are included in the "jwks_uri".

APM uses "x5c" to store a certificate, populating "cert", "cert-thumbprint-sha1" and "cert-thumbprint-sha256" when that certificate is added to the JWK configuration.

If "x5t" is included in the JWS header but "jwks_uri" does not include "x5t" or "x5c". It is not possible to match a JWK on the system

{
  "x5t": "<...>",
  "kid": "<...>",
  "alg": "RS256"
}

"jwks_uri"
  "keys": [
    {
      "kty": "RSA",
      "e": "AQAB",
      "use": "sig",
      "kid": "<...>",
      "alg": "RS256",
      "n": "<...>"
    }

Recommended Actions
Add "cert-thumbprint-sha1" to the Key Configurations (JWK) on APM that matches "x5t" claim in the JWT header.

apm oauth jwk-config  {
    alg-type RS256
    cert-thumbprint-sha1 <...>
