Known Issue

Note: The issue described in this article affects only BIG-IP 10.2.0-HF2.

This is the result of a known issue. Secure Sockets Layer (SSL) sessions that perform client authentication cannot be resumed by Client SSL profiles that are configured to not require client authentication.

Consider the following example:

  • A virtual server is configured with a Client SSL profile that does not require client authentication. Specifically, the Client Certificate setting in the Client SSL profile is set to Ignore.
  • The virtual server is also configured with an iRule that performs selective client certificate authentication. This technique allows users to access specific areas of a website without having to type in their username or password, providing a smooth browsing experience and increased security (as it is more difficult to spoof a client certificate than a password).

    Note: For more information, refer to the Selective Client Cert Authentication article on DevCentral. A separate DevCentral login is required to access this content.

  • A user connects to the virtual server and accesses a restricted area that requires client certificate authentication. The iRule takes care of renegotiating the SSL session so that the user must provide a valid client certificate. Additionally, the iRule extracts valuable certificate information and inserts it into HTTP headers to be passed to the application servers for authentication/authorization purposes. At this point, the user has accessed the restricted area.
  • Later, using a new TCP connection, the client sends a new request to the virtual server. The client attempts to reuse the SSL session ID that was generated during the renegotiation discussed in the previous step; however, resumption of the SSL session fails. As a result, a new SSL session ID is generated, the iRule no longer has a client certificate to extract information from, and the application returns some sort of access denied or please login error message.

This is not the intended behavior. A Client SSL profile configured to not require client authentication should be able to resume an SSL session that previously performed client authentication by way of an iRule.

Note: The actual effects of this issue will vary widely depending on your specific deployment. For example, the iRule, the configuration of the application servers, and the way the clients behave will influence the end result. The failure described in the above scenario is only an example.

F5 Product Development is tracking this issue as ID 348372.

F5 Product Development has issued a hotfix that resolves this issue for BIG-IP 10.2.0. To obtain this hotfix, contact F5 Technical Support, referencing this article number and ID 348372.
