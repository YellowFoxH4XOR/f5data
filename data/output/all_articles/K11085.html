Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator may remove a comma delimiter from the Cache-Control header in the client-side response. This behavior occurs when the WebAccelerator Client Cache setting is configured to Do not change, and an OWS sends a Cache-Control header containing a no-store directive along with a custom directive. As a result, the BIG-IP WebAccelerator system incorrectly stores a document that should not be cached.

For example, the following HTTP header was sent from the OWS with a Cache-Control header containing a no-store directive, a comma delimiter, and a custom directive:

HTTP/1.1 200 OK
Date: Tue, 19 Jan 2010 15:02:29 GMT
Server: Apache/2.2.3 (CentOS)
Last-Modified: Wed, 13 Jan 2010 15:52:31 GMT
ETag: "38027-87-c2144dc0"
Accept-Ranges: bytes
Content-Length: 135
Cache-Control: no-store, custom=0
Content-Type: text/html; charset=UTF-8

The BIG-IP WebAccelerator system alters the above header by removing the comma delimiter from the Cache-Control header in the client-side response as follows:

HTTP/1.1 200 OK
Connection: Keep-Alive
Server: Apache/2.2.3 (CentOS)
Content-Type: text/html; charset=UTF-8
Date: Wed, 20 Jan 2010 01:34:50 GMT
Content-Length: 135
ETag: "pve5dec45fdd9e0dda951e99e5e3f3a428"
Last-Modified: Wed, 13 Jan 2010 15:52:31 GMT
Cache-Control: no-storecustom=0
X-PvInfo: [S10201.C36692.A49834.RA0.G0.UB30EAC39].[OT/html.OG/pages]
Vary: Accept-Encoding
Accept-Ranges: none

F5 Product Development tracked this issue as CR135535 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP version 10.0.1, BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue by performing the following configuration steps:

  • Clone the original node in the WebAccelerator Policy Editor.
  • Configure the new node to recognize the affected page using Matching Rules.
  • On the Acceleratior Rules > Lifetime tab, change the Client Cache settings to Insert no-cache directive into header.
  • Save and publish the policy.
