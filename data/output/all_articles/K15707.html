Known Issue

AAA authentication may fail after you manually restart the Master Control Program Daemon (MCPD) service.

This issue occurs when all of the following conditions are met:

  • You have configured a BIG-IP APM AAA profile to use a pool of AAA servers.
  • An Access Profile references the AAA profile for authentication in an access policy.
  • You restart the MCPD service with one of the following command line bigstart commands.
    • bigstart restart
    • bigstart restart mcpd

Impact

User authentication fails for the access profile.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H484748 on the Diagnostics > Identified > Medium screen.
  • After you manually restart the MCPD service, users are unable to authenticate when accessing the access profile virtual server.
  • In the /var/log/apm file, the system logs repeated error messages similar to the following example:

    err tmm6[20370]: 01490514:3: 00000000: Access encountered error: ERR_NOT_FOUND. File: ../modules/hudfilter/access/access.c, Function: hud_access_handler, Line: 1891
    err tmm5[20369]: 01490514:3: 00000000: Access encountered error: ERR_NOT_FOUND. File: ../modules/hudfilter/access/access.c, Function: access_process_state_client_get_license, Line: 5170

Workaround

To work around this issue, you can reload the system configuration using the Traffic Management Shell (tmsh). To do so, perform the following procedure:

Impact of workaround: This workaround will temporarily interrupt active BIG-IP APM sessions.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To load the system configuration, type the following command:

    load /sys config

  3. To exit tmsh, type the following command:

    quit
