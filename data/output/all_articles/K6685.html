Known Issue

This is the result of a known issue. The mcpd utility fails to handle a large number of transaction objects (2000+) when parsing and loading a BIG-IP GTM configuration.

This issue occurs because the mcpd utility database attempts to duplicate portions of the transactions during the process of parsing and loading the BIG-IP GTM configuration. There is not enough space in the database to house the duplicate portions and the transaction fails, logging a No more memory error in the /var/log/ltm directory, similar to the following example:

mcpd[20406]: 01070082:3: The extreme DB size in mcpd has reached its storage limit.
mcpd[20406]: 01070399:3: No more memory - exiting

The mcpd utility restarts every time the gtmload process is called to load the configuration. The BIG-IP LTM system then becomes inoperative, as it is unable to load the configuration.

F5 Product Development tracked this issue as CR69277 and it was fixed in BIG-IP GTM 9.3. For information about upgrading, refer to the BIG-IP GTM Release Notes.
