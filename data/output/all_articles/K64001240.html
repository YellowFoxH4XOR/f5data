Topic

You should consider using this procedure under the following conditions:

  • You want to troubleshoot issues on the NGINX Controller Agent.
  • You want to enable NGINX Controller Agent debug logging in the /var/log/nginx-controller/agent.log file.

Description

To retrieve additional information, you can enable debug logging for the Controller Agent installed on your NGINX Plus system. This feature is helpful for troubleshooting issues related to the NGINX Controller Agent, including Controller Agent installation and metrics collection issues. After you enable debug logging for the Controller Agent, you can attempt to reproduce the issue and then review the logs.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the NGINX Plus system.

Procedures

Enable NGINX Controller Agent debug logging

The NGINX Controller Agent configuration is located in the /etc/controller-agent/agent.conf file, and the default logging level is info/INFO. You can enable debug logging or modify the current logging level by editing the configuration file. To do so, perform one of the following procedures:

  • NGINX Controller 3.7.0 and later
  • NGINX Controller 3.6.0 and earlier

Impact of procedures: Enabling Controller Agent debug logging may cause excessive logging. You should enable debug logging only when troubleshooting and then disable debug logging after you've finished troubleshooting.

NGINX Controller 3.7.0 and later

  1. Log in to the NGINX Plus system where the Controller Agent is installed.
  2. Back up the /etc/controller-agent/agent.conf file by entering the following command:

    sudo cp /etc/controller-agent/agent.conf /etc/controller-agent/agent.conf.K64001240

  3. Edit the /etc/controller-agent/agent.conf file using a text editor of your choice, such as nano or vi.

    For example, if using vi, enter the following command:

    sudo vi /etc/controller-agent/agent.conf

  4. Under the [loggers] section, change the value of level to debug. For example:

    [loggers]
    level = debug
    keys = root,devnull,agent-default

  5. Save the changes and exit the editor.
  6. To restart the Controller Agent, enter the following command:

    sudo service controller-agent restart

Note: After you finish troubleshooting, you should revert the changes and disable debug logging. To do so, repeat the previous procedure with the following modification: in step 4, restore the logging level to the default value of info.

NGINX Controller 3.6.0 and earlier

  1. Log in to the NGINX Plus system where the Controller Agent is installed.
  2. Back up the /etc/controller-agent/agent.conf file by entering the following command:

    sudo cp /etc/controller-agent/agent.conf /etc/controller-agent/agent.conf.K64001240

  3. Edit the /etc/controller-agent/agent.conf file using a text editor of your choice, such as nano or vi.

    For example, if using vi, enter the following command:

    sudo vi /etc/controller-agent/agent.conf

  4. Under the [logger_agent-default] section, change the value of level to DEBUG. For example:

    [logger_agent-default]
    level = DEBUG
    qualname = agent-default
    handlers = agent-default
    formatter = simpleFormatter
    propagate = 0

  5. Under the [handler_agent-default] section, change the value of level to DEBUG. For example:

    [handler_agent-default]
    class = logging.handlers.WatchedFileHandler
    level = DEBUG
    formatter = simpleFormatter
    args = ('/var/log/nginx-controller/agent.log', 'a', None, 1)

  6. Save the changes and exit the editor.
  7. To restart the Controller Agent, enter the following command:

    sudo service controller-agent restart

Note: After you finish troubleshooting, you should revert the changes and disable debug logging. To do so, repeat the previous procedure with the following modification: in steps 4 and 5, restore the logging level to the default value of INFO.
