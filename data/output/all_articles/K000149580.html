Description

You can configure the BIG-IP for remote Lightweight Directory Access Protocol (LDAP) client certificate authentication for BIG-IP administrative users with the Remote-ClientCert LDAP setting. This article will describe how to do that.

This configuration allows you to use smart cards as an authentication method. For example BIG-IP administrators can use their Common Access Card (CAC) or Personal Identity Verification (PIV) cards for authenticating to the BIG-IP configuration utility. These are smart cards that have an encrypted private key and public certificate stored on them.

Prerequisites

  • BIG-IP system accounts on a remote LDAP authentication server
  • Client certificates
  • OCSP Responder to check the client certificate status
  • CA bundle or certificate to import to the BIG-IP

Procedures

Configure remote role groups with the Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to System > Users > Remote Role Groups.
  3. Click Create.
  4. For Group Name, type the name you want for the remote role group. For example: mgmt_group.
  5. For Line Order, type the line number you want. For example: 1001.
  6. For Attribute String, type the LDAP attribute you want. For example: memberOf=CN=BIGIPadmins,OU=Groups,DC=example,DC=com
  7. For Assigned Role, select a role.
  8. For Partition Access, select a partition.
  9. For Terminal Access, select the terminal access you want.
  10. Click Finished.

Configure remote role groups with TMSH

  1. Log into the CLI and enter the command tmsh to access TMSH.
  2. Create a remote role group using the following syntax:

    modify auth remote-role { role-info add { <group name> { attribute <attribute string> line-order <integer> role <assigned role> user-partition <partition name or all> }}} 

    For example:

    modify auth remote-role { role-info add { bigipusers { attribute memberOf=CN=BIGIPadmins,OU=Groups,DC=example,DC=com line-order 1001 role administrator user-partition all }}}

  3. Save the configuration by entering the following command:
    save sys config

Import a CA with the Configuration utility

  1. Log in to the Configuration utility
  2. Go to System > Certificate Management > Device Certificate Management > Device CA Certificate List > Import
  3. For File Name, select Browse.
  4. Select the CA bundle or certificate in the file window.
  5. Select Open.
  6. For Name, enter a unique name for the CA certificate object.
  7. Select Import.

Import a CA with TMSH

  1. Log into the CLI and enter the command tmsh to access TMSH.
  2. Copy the CA bundle or certificate to the BIG-IP /var/tmp directory using scp or similar utility.
  3. Import the CA file with the following command syntax:
    create sys file apache-ssl-cert <choose a name for the cert object> source-path file:/var/tmp/<CA file name>
  4. Add the CA file to the Device CA Certificate List with the following command syntax:
    modify sys http ssl-ca-cert-file /Common/<cert object name you chose in step 3>
  5. Save the configuration by entering the following command:
    save sys config
  6. Restart httpd by typing the following command:
    restart sys service httpd

Configure the BIG-IP system to use Remote-ClientCert LDAP with the Configuration utility

  1. Log in to the BIG-IP Configuration utility.
  2. Go to System > Users > Authentication. 
  3. In the Authentication list, select Advanced.
  4. Select Change.
  5. For User Directory, select Remote-ClientCert LDAP.
  6. In the Host section, enter the IP address or host name of the of the remote LDAP server.
  7. In the Remote Directory Tree section, enter the LDAP location for the user account database. For example, dc=example,dc=com.
  8. For Scope, select the LDAP search scope. For example, Sub.
  9. In the Bind section, enter the LDAP server search account username and password information. 
  10. Complete the SSL section if your LDAP server requires an SSL connection otherwise select Disabled for SSL.
  11. For CA Certificate, select the CA certificate imported from the previous procedure.
  12. For Login Name, enter the LDAP directory attribute containing the client name. For example cn.
  13. For Login LDAP Attribute, enter the LDAP attribute to search for using the extracted client certificate username. For example uid.
  14. For Login Filter, enter the filter to be applied to the username extracted from the SSL client certificate. For example, [\w\.]*(?=@).
  15. For Client Certificate Name, select the x.509 attribute to search in the SSL client certificate. For example the common name (CN). The value needs to match the Login LDAP Attribute. For example the login filter extracts jsmith from the CN and uses that to locate the jsmith LDAP account using the uid.
  16. For OCSP Override, select on.
  17. For OCSP Responder, fill in the IP address or hostname and port for the OCSP responder.
  18. Since you configured a remote role group, you can leave the External Users section with the default settings.
  19. Select Finished.

Configure the BIG-IP system to use Remote-ClientCert LDAP with TMSH

  1. Log into the CLI and enter the command tmsh to access TMSH.
  2. To change the authentication method to Remote-ClientCert LDAP enter the following command:

    create auth cert-ldap system-auth servers add { <ldap_server> } bind-dn <search_user_dist_name> bind-pw <search_user_password> login-attribute <ldap_attribute> search-base-dn <remote_directory> login-name <ssl_cert_attribute> login-filter <filter_expression> sso on

    For example:

    create auth cert-ldap system-auth servers add { 10.155.1.1 } bind-dn cn=admin,dc=askf5,dc=example,dc=com bind-pw secret login-attribute uid search-base-dn dc=example,dc=com login-name cn login-filter [\w\.]*(?=@) sso on
    Note: The previous command does not enable SSL, refer to tmsh help auth cert-ldap for information about what properties to include if you're using an SSL connection when accessing the LDAP server.

  3. Enable OCSP using the following command:

    modify sys httpd ssl-ocsp-override-responder on ssl-ocsp-enable on ssl-ocsp-default-responder http://<OCSP responder IP:port>

    For example:

    modify sys httpd ssl-ocsp-override-responder on ssl-ocsp-enable on ssl-ocsp-default-responder http://10.155.20.1:2560

  4. Update the auth source configuration property:
    modify auth source type cert-ldap
  5. Save the configuration by entering the following command:
    save sys config.

Troubleshooting

You can use the openssl ocsp command to validate your client certificate by sending a request to an OCSP responder. Use the following syntax:

  • openssl ocsp -issuer <CA cert> -cert <client cert> -text -url http://<OCSP responder>
    For example:
    openssl ocsp -issuer myCA.crt -cert myClientCert.crt -text -url http://10.155.1.1:2560

You can also use the openssl ocsp command to act as an OCSP responder for testing. Use the following syntax:

  • openssl ocsp -index <CA index file> -port <port number> -rsigner <CA cert> -rkey <CA key> -CA <CA cert> -text -out <log file>
    For example:
    openssl ocsp -index index.txt -port 2560 -rsigner myCA.crt -rkey myCA.key -CA myCA.crt -text -out log.txt
