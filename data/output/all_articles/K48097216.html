K48097216: Cloud failover stopped working after upgrade

Type
Support Solution
Published
2021-03-16
Updated
2025-02-06
Applies to
  • Public Cloud
  • BIG-IP
  • BIG-IP Cloud Edition
  • Amazon Web Services
  • Microsoft Azure
  • Google Cloud
Source
https://my.f5.com/manage/s/article/K48097216

Description

  • When performing a failover, traffic does not get directed to the newly-Active BIG-IP instance.
  • The BIG-IP instances swap Active/Standby roles, but virtual servers are not accessible by clients.

Environment

  • BIG-IP virtual instance in AWS, Azure, or Google cloud.
  • High-Availability / HA failover

Cause

Due to BugID929213 and BugID1079817 in the BIG-IP TMOS upgrade, certain iAppLX packages are not rolled forward after a BIG-IP upgrade or restoring a UCS file generated from an affected system.

The defect has been resolved in BIG-IP versions 17.0.0, 16.1.3, 15.1.6.1, 14.1.5.1

Recommended Actions

Uninstall and reinstall the missing packages on both BIG-IP HA peers.

  1. From the Configuration Utility, Navigate to 'iApps > Package Management LX'
  2. Select the Cloud Failover package and click Uninstall
  3. Uninstalling packages in the Configuration Utility does not remove the package from the file system. The stored state of the REST framework should be cleared, since BIG-IP also retains index files pointing to the package in the file system. In the bash prompt, run clear-rest-storage -l.  

    Do note that /var/log/ should be backed up and any qkviews should be taken prior to running this command. No disruption to traffic is expected when running this command. 
    clear-rest-storage completely clears the stored state for the REST framework.
It first stops restjavad and restnoded, then deletes the index and storage
 directories, and then restarts those services.

The -l option deletes the restjavad log files as well as the stored state

    The -d option resets the system configuration to default by running
tmsh load sys config default
along with deleting the stored state
  4. Import the f5-cloud-failover RPM file that you were previously using.
