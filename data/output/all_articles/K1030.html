K1030: Reasons why the DNS proxy may fail to bind to addresses on BIG-IP systems

Topic

When you configure a Domain Name System (DNS) proxy on a BIG-IP system, it will try to bind to all IP addresses by default. The BIG-IP system does not allow a process to bind to more than 128 IP addresses.

When this problem occurs, the DNS proxy fails to bind to any addresses in excess of the first 128, and logs a message, similar to the following example, to the /var/log/messages file:

socket(SOCK_STREAM): Too many open files

To fix this problem, edit the named.conf file and specify only the IP addresses on which you want named to listen. Following is an example of a BIND 8 syntax named.conf file. The pertinent directive is the listen-on directive:

options {

forward only;

        forwarders {
        192.168.13.10; 192.168.6.11;
        };

        /*
         * If there is a firewall between you and nameservers you want
         * to talk to, you might need to uncomment the query-source
         * directive below.  Previous versions of BIND always asked
         * questions using port 53, but BIND 8.1 uses an unprivileged
         * port by default.
         */

        query-source address * port 53;
        listen-on { 10.0.0.1; 10.0.0.2; 172.16.64.1; 
        127.0.0.1; 192.168.243.97;};            

         };
