Known Issue

SQL monitor processes may become unresponsive and fail to exit.

This issue occurs when the following condition is met:

  • Your BIG-IP system has a high number of SQL (Oracle, MSSQL, MySQL, PostgresSQL) monitors configured.

Note: Slow SQL responses from monitored resources can increase the likelihood of this issue occurring.

Impact

The SQL monitor process may stop functioning and experience frequent stops and restarts. The system may frequently, erroneously mark up and mark down the monitored pool members.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Monitored pool members are erroneously marked up and down frequently (flap).
  • The DBDaemon debug log contains messages indicating that a hung connection is stopped, and that the address is already in use. These error messages appear similar to the following examples:

    : jdbc:oracle:thin:@10.10.10.11:1521:DPDB3CP2(Thread-6335): Hung Connection. Aborting.
    : (main): UNABLE TO OPEN server socket 1527: Address already in use
    : (main): UNABLE TO OPEN server socket 1527: Address already in use
    : (main): UNABLE TO OPEN server socket 1527: Address already in use

Workaround

To work around this issue, you can reduce the load on the SQL monitor process by taking one or more of the following actions:

  • Reduce the number of monitored pool members.
  • Reduce the interval frequency that the monitors are performed.
  • Split monitors among multiple devices.
  • Run monitors on bladed systems.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
