Known Issue

The BIG-IP APM system may convert Unicode incorrectly when using the HTML <meta> tag.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for portal access.
  • A UTF-8 encoded response specifies the character encoding using a <meta> tag containing the charset=unicode attribute.
  • The origin web server (OWS) does not specify the character encoding in the HTTP Content-Type response header.

If the server response uses the meta http-equiv element to specify Unicode as the character encoding for a UTF-8 encoded document, but does not also specify the encoding in the charset parameter of the HTTP Content-Type header, the BIG-IP APM system may not convert the encoding correctly.

The following example displays a portion of a susceptible response:

Last-Modified: Fri, 01 Jan 1971 00:08:00 GMT
Accept-Ranges: bytes
Vary: Accept-Encoding
Content-Length: 142
Connection: Keep-Alive
Content-Type: text/html

<html>
<head>
<meta http-equiv="Content-Type" content="text/html; charset=unicode" />

Impact

UTF-8 encoded HTML pages are not displayed properly in the browser.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Portal Access web application response pages display garbled characters.

Workaround

You can work around this issue by configuring the OWS to specify UTF-8 for the charset parameter in the HTTP Content-Type header. For example, you could change the Content-Type header from the previous example to appear as follows:

Content-Type: text/html; charset=UTF-8
