Description

Some clients are encountering a SSL error while connecting to NGINX server running NGINX Plus. Mutual TLS authentication has been enabled for this communication on port 8443. The clients failed to connect with the below error. 

client SSL certificate verify error: (68:CA signature digest algorithm too weak) while SSL handshaking, client: 10.10.10.10, server: 0.0.0.0:8443
SSL_shutdown() failed (SSL: error:0A000123:SSL routines::application data after close notify) while SSL handshaking, client: 10.10.10.10, server: 0.0.0.0:8443


Environment

NGINX Plus
OpenSSL 3.1.1

Cause

error message 68:CA signature digest algorithm too weak is caused by the OpenSSL version running which considers the signature algorithm SHA-1 in the certificate as obsolete.


Recommended Actions

Change the signature algorithm to SHA-256 or SHA-512.


Additional Information

OpenSSL 1.1.1 may not complain about the SHA-1 signature algorithm however please consider changing it to SHA-256 or SHA-512 to improve your security posture.
You can find out the signature algorithm used in your certificate by running the openssl x509 -in rootCert.pem|cert.crt -text -noout | grep -i "Signature Algorithm" command. The option -in takes the name of the certificate.

As workaround, you can decrease the security level in OpenSSL by modifying the openssl.cnf configuration file or by appending @SECLEVEL=0 to the ciphers list in the NGINX configuration. This approach is not recommended as it lowers the security standards to allow the SHA-1 signature algorithm.
E.g.

ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:@SECLEVEL=0;
