1. Description

This article addresses the issue where the BIG-IP LTM system generates repeated log messages similar to:

  • "Limiting closed port RST response from <IP>:<port> to <IP>:<port>"

These logs indicate that the BIG-IP is sending TCP RST packets in response to connection attempts on ports where no service is listening, and the rate of these RSTs has exceeded the system threshold.


2. Environment

  • Product: BIG-IP LTM
  • All supported versions

3. Cause

The log message is triggered when the BIG-IP receives repeated connection attempts to closed ports, resulting in RST responses. When the rate of these RSTs exceeds the system-defined threshold, the system logs the "Limiting closed port RST response" message.


4. Answer/Recommended Actions

To identify and address the source of these log messages:

Capture RST Packets

Use tcpdump to capture RST packets:

tcpdump -nni 0.0 'tcp[tcpflags] & (tcp-rst) != 0' -c 1000


Capture Full TCP Flows

To correlate incoming connection attempts (SYN) with RSTs, capture a broader set of packets:

tcpdump -nni 0.0 host <target_ip> and tcp port <target_port> -c 1000 -w /var/tmp/closed_port_test.pcap

Replace <target_ip> and <target_port> with the relevant values.


Analyze with Wireshark or tshark

Open the capture file in Wireshark.

Filter for RST packets:

tcp.flags.reset == 1

Review the flows to determine which clients are attempting to connect to closed ports.


Identify and Address the Source

Use the analysis to identify the source IPs generating unwanted traffic.

Investigate and remediate the source of these connection attempts as appropriate.


5. Additional Information

  • Capturing only RST packets does not provide the full context of the TCP flow. It is recommended to capture both SYN and RST packets to fully understand the traffic pattern.
  • These log messages are informational and indicate that the BIG-IP is protecting itself from excessive RST generation.
