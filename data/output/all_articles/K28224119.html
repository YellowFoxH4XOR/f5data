K28224119: While upgrading a vCMP guest, ''upgrade needed'' in a vCMP guest across to another blade

Type
Support Solution
Published
2023-03-20
Updated
2024-10-02
Status
Legacy Content
Applies to
  • VIPRION Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K28224119

Description
"upgrade needed" while the vCMP guest is being upgraded

Environment

  • Viprions - Host
  • vCMP guests deployed in at least two slots

Cause

  • Installing the image in the host, the vCMP guest is not able to access to the host to pull the iso and span it to another blade.
  • This issue will trigger emer-logs, "emerg logger: Re-starting lind"
(tmos)# show sys software
------------------------------------------------------------------
Volume  Slot  Product   Version      Build  Active          Status
------------------------------------------------------------------
HD1.1      1   BIG-IP    14.1.2     0.0.37      no        complete
HD1.1      2     none      none       none      no  upgrade needed  <----

    Recommended Actions

    On the host:
// changing the permissions
# chmod 644 /shared/images/BIGIP*

// changing the permissions
On the guest:
# chmod 644 /shared/images/BIGIP*
# clsh bigstart restart lind
# clsh bigstart restart mcpd
# clsh bigstart restart guestagentd

Please capture the out of this command from HOST and GUEST:
# ls -ll /shared/images/BIGIP*

Then reboot the unit with:
# clsh touch /service/mcpd/forceload ; clsh touch /forcefsck ; clsh reboot
