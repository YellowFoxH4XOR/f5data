Topic

The BIG-IP LTM system sends a TCP RST (reset) to terminate a nascent Secure Network Address Translation (SNAT) connection once the retransmission back-off time increases to a value in excess of the handshake timeout configured for the FastL4 profile associated with the connection. This behavior is normal and expected when multiple SYN retransmissions fail to establish the requested connection.

Note: SNAT connections traversing a virtual server are associated with the FastL4 profile associated with the virtual server. SNAT connections that do not traverse a virtual server use an internal forwarding mechanism that references the default FastL4 profile.

When a client does not receive a response to a SYN packet, the TCP stack implements a fallback and retry algorithm to allow a busy server enough time to honor the connection request. If no response is received for the first SYN request, the client retransmits the SYN request multiple times, implementing a typical back-off timer algorithm between retransmissions. The first retransmission is sent after waiting a specified time for a response to the first SYN, typically three seconds. If no response is received to the first retransmission, the wait time is doubled, and another retransmission is sent. The wait time is again doubled after each subsequent failed attempt. Most TCP stacks send a maximum of five SYN retransmissions before abandoning the connection request. A packet trace of the connection attempt demonstrates the following progression:

11:26:27.452465 172.24.2.41.55507 > 172.24.2.200.http: S ...
11:26:33.452465 172.24.2.41.55507 > 172.24.2.200.http: S ...
11:26:45.452465 172.24.2.41.55507 > 172.24.2.200.http: S ...
11:27:09.452481 172.24.2.41.55507 > 172.24.2.200.http: S ...
11:27:57.452466 172.24.2.41.55507 > 172.24.2.200.http: S ...
telnet: connect to address 172.24.2.200: Connection timed out

The connection request times out after 93 seconds, and a total of six SYN packets were sent at the following intervals:

  • 1st SYN: 0
  • 2nd SYN: +3 seconds
  • 3rd SYN: +6 seconds
  • 4th SYN: +12 seconds
  • 5th SYN: +24 seconds
  • 6th SYN: +48 seconds

When the BIG-IP system attempts to establish a connection to a server, and the interval between the retransmissions exceeds the configured TCP Handshake Timeout, the BIG-IP system resets the connection.

For example, if the TCP Handshake Timeout is set to five seconds, the SNAT connection would be reset between the third and fourth SYN packets.

If you want to allow the BIG-IP system more time to establish a SNAT connection with slow-to-respond servers before terminating the connection with a reset, you can apply to the virtual server processing the traffic a custom FastL4 profile with a longer TCP Handshake Timeout value.

Note: The BIG-IP system may allow idle connections to exist slightly longer than the idle timeout value. For more information, refer to K5401: Connection reaping occurs within an 8.4 second window around the idle timeout.
