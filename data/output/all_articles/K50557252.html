K50557252: Install Istio Ingress Gateway using the Aspen Mesh Ingress Helm Chart

Applies to

Description

Aspen Mesh can integrate with other Ingress Controller using Ingress Resource but to make use of all Istio features it is recommended to install Istio Ingress Gateway. Istio Gateway is based on the same Envoy proxy used by the istio-proxy sidecar container in the Service Mesh. Aspen Mesh install package contains the Helm Chart to deploy the Istio Ingress Gateway. In this article we are going to describe how to install and configure Istio Ingress Gateway.
 

Environment

  • Kubernetes: 1.17x,1.18.x,1.19.x,1.20.x  
  • Aspen Mesh: 1.6.x, 1.9.x, 1.11.x, 1.14.x


Cause

To expose a service outside of the Aspen Mesh service cluster we can use the Kubernetes Ingress Controller and Kubernetes Ingress Resource.
 

    Recommended Actions

    • The default values.yaml file
    • Create your custom values yaml file
    • Install Istio Ingress Gateway
    Istio Ingress Gateway is an optional Helm Chart that you can install during the Aspen Mesh installation. After extracting the Aspen Mesh install tarball, the Ingress Chart can be found in the following directory:

    manifests/charts/gateways/istio-ingress
     

    The default values.yaml file

    You can customize the Ingress Gateway configuration by creating Helm values in a yaml file. The default settings for the Chart are stored under the following directory and file:

    manifests/charts/gateways/istio-ingress/values.yaml 

    You can use the above default values file as a reference for your custom values yaml file. Default values configure the Ingress Gateway as such:

    • as a LoadBalancer type
    • The gateway is called istio-ingressgateway
    • HorizontalPodAutoscaler is enabled to scale the number of Istio Ingress Gateway pods between 2-5 based on the CPU usage. targetAverageUtilization is configured to be 80%.
    • The gateway is labeled with app: istio-ingressgateway. You can use this label later as a Selector to the Gateway manifest to select which gateway to receive the configuration.
    • 5 ports are defined and exposed by default by the LoadBalancer service:
      • 15021
      • 80
      • 443
      • 15012
      • 15443
     

    Examples from the default configuration:

    gateways:
  istio-ingressgateway:
    name: istio-ingressgateway
    labels:
      app: istio-ingressgateway
      istio: ingressgateway
    ports:
    - port: 15021
      targetPort: 15021
      name: status-port
      protocol: TCP
    - port: 80
      targetPort: 8080
      name: http2
      protocol: TCP
    - port: 443
      targetPort: 8443
      name: https
      protocol: TCP
    - port: 15012
      targetPort: 15012
      name: tcp-istiod
      protocol: TCP
    # This is the port where sni routing happens
    - port: 15443
      targetPort: 15443
      name: tls
      protocol: TCP
 
    # Scalability tuning
    replicaCount: 2
    rollingMaxSurge: 100%
    rollingMaxUnavailable: 25%
    autoscaleEnabled: true
    autoscaleMin: 2
    autoscaleMax: 5
 
    cpu:
      targetAverageUtilization: 80
 
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 2000m
        memory: 1024Mi
 
    podAnnotations: {}
    type: LoadBalancer
 
    nodeSelector: {}
 
   <TRUNCATED>
      

    Create your custom values yaml file

    To override any of the above default configuration, you can create your custom values yaml file that you will use later for the installation. Using the example below you can increase the CPU and memory limits assigned to every Ingress Gateway pod. You will also add pod annotation to the Envoy Proxy to enable cluster.outbound metrics. You should use the NodePort service type if you do not have Cloud Controller installed in your Kubernetes cluster.

    gateways:
  istio-ingressgateway:
    replicaCount: 1
    autoscaleMin: 1
    autoscaleMax: 5
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 3000m
        memory: 2048Mi
    podAnnotations:
      "sidecar.istio.io/statsInclusionPrefixes": "cluster.outbound”
    type: NodePort


    Install Istio Ingress Gateway

    To install Istio Ingress Gateway, run the following command:

    helm install istio-ingress manifests/charts/gateways/istio-ingress --namespace <NAMESPACE> --values <OVERRIDE_VALUES_FILE>

    You can install Istio Ingress Gateway Helm Chart in any namespace you want. The Gateway does not have to be installed in the istio-system namespace. If you do not specify your custom OVERRIDE_VALUES_FILE, then the default settings will be used.
     

    You can install more than 1 instance of Istio Ingress Gateway on your cluster, but you should modify the name of the deployment and the label that is used in the Gateway manifest as Selector.
