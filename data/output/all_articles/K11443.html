K11443: VLAN failsafe may not be enabled if the VLAN name is a superset of another VLAN name

Known Issue

This is the result of a known issue. If you configure two VLANs so that one VLAN name is a superset of another VLAN name, and enable VLAN failsafe on both VLANs, VLAN failsafe may not be applied to the VLAN with the longer name.

This issue occurs when the VLAN with the longer name is defined before the VLAN with the shorter name in the bigip_base.conf file. For example, in the following configuration, VLAN failsafe would be enabled for sales-525, but not for sales-5251:

vlan sales-5251 {
tag 1427
failsafe enable
failsafe failover
timeout 90
interfaces 1.4
}
vlan sales-525 {
tag 2391
failsafe enable
failsafe failover
timeout 90
interfaces 1.3
}

F5 Networks Product Development tracked this issue as CR86999 and it was fixed in BIG-IP LTM version 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can work around this issue by ensuring that the VLAN with the subset (shorter) name is defined before the VLAN with the superset (longer) name in the /config/bigip_base.conf file. After editing the file, run the bigpipe load command to load the change, and then the bigpipe save command to save the change.

To verify which VLANs have VLAN failsafe enabled, use the bigpipe ha table command.
