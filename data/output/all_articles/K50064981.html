Introduction

Use this chapter to upgrade BIG-IP VE instances in an Azure virtual machine scale set (VMSS). An Azure VMSS resource manages BIG-IP instances and scales them up and down on-demand, which makes these types of upgrades different from others.

Important: Due to the heavy customization requirements of external cloud resources and BIG-IP configurations in F5 Azure ARM Templates 2.0, F5 does not provide technical support for deploying, customizing, or troubleshooting the templates themselves or the procedures in this article. However, the various underlying products and components used (for example, F5 BIG-IP Virtual Edition) are F5-supported. For more information, refer to the Getting Help section in F5 Azure ARM Templates 2.0 on GitHub

General procedure

The upgrade procedure for BIG-IP instances depends on how you initially created and managed the VMSS. In general, the procedure is to do the following:

  1. Change the current image Uniform Resource Name (URN) to the URN for the BIG-IP version you are upgrading to. The VMSS uses the new URN to launch new BIG-IP instances.
  2. Perform the upgrade by updating the deployment. 
  3. The deployment uses the VMSS upgrade policy to replace your old BIG-IP instances with new ones running the BIG-IP version you are upgrading to.
  4. Load the BIG-IP configuration on the new BIG-IP instances.

The last step varies. You can load the BIG-IP configuration in a number of ways:

  • From a UCS archive generated before the upgrade.
  • From a configuration sync process from another upgraded BIG-IP instance.
  • In the case of the F5 Azure ARM Templates 2.0 on GitHub, F5 Declarative Onboarding (DO), Application Services 3 Extension (AS3), and F5 Telemetry Streaming (TS) load the BIG-IP configuration using the configuration file runtime-init-conf-payg.yaml, which you specify at the time of deployment.

Procedure for BIG-IP instances launched from F5 Azure ARM Templates 2.0

This chapter primarily covers how to update BIG-IP VE instances that you created and manage using the F5 Azure ARM Templates 2.0. To update BIG-IP VE instances in a VMSS that you did not deploy from F5 Azure ARM Templates 2.0, consider re-deploying them using it. Doing so enables you to take advantage of the features and benefits that F5 Azure ARM Templates 2.0 provide. Alternatively, you can follow the general procedure in the previous section.

Important: F5 deprecated the F5 Azure ARM Templates 1.0 and replaced them with F5 Azure ARM Templates 2.0. F5 recommends using the latter.

The steps to update BIG-IP VE instances in an Azure VMSS deployed from F5 Azure ARM Templates 2.0 are as follows:

  1. Determine and note the image URN you want the F5 Azure ARM template to use to create new BIG-IP instances. This image contains the BIG-IP version you want to upgrade to.
  2. Redeploy the last successful deployment in the resource group.
  3. Edit the deployment template replacing the image URN with the one determined in step 1.

When the upgrade begins, the system upgrades each BIG-IP instance according to the upgrade policy set in the VMSS resource, including the following options:

  • Rolling—Upgrades roll out in batches with optional pause (default setting in F5 Azure ARM Templates 2.0).
  • Manual—Existing instances must be manually upgraded.
  • Automatic—Instances start upgrading immediately in random order.

Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You previously deployed your BIG-IP VE instances and VMSS from F5 Azure ARM Templates 2.0.
  • You have the required Azure credentials to log in to the Azure portal to manage the Azure deployment and the resources it manages. 
  • You have both SSH key pair and username/password credentials to log in into the primary BIG-IP VE instance.

Prepare for the update or upgrade

Impact of procedure: Performing the procedures in this section should not have a negative impact on your system.

Determine the Azure image URN you want to update or upgrade to

To upgrade, you must provide the Azure deployment with the Azure image URN you want to upgrade to. To determine the Azure image URN, perform the following procedure:

  1. Log in to the Azure portal.
  2. In the upper right, next to notification and settings, select the Cloud Shell icon.

     

    Note: If you set up the Azure command line, you can also perform the remaining steps using it.

  3. Enter the following command syntax to display all the BIG-IP image URNs available in Azure:

     

    az vm image list --offer big-ip --all --output table

  4. Filter the results for the BIG-IP image and license you want.

     

    For example, enter the following command to filter for BIG-IP 16.0.1:

    az vm image list --offer big-ip --all --output table | grep 16.0.1 | grep 25m-best

  5. Note the Azure URN, because you need it in a future step.

    For example, you note the following Azure URN:

    f5-networks:f5-big-ip-best:f5-bigip-virtual-edition-25m-best-hourly:16.0.101000

Identify the upgrade policy in the VMSS

You must identify the upgrade policy configured in the VMSS. To do so, perform the following procedure:

  1. Log in to the Azure portal.
  2. Go to Resource Group.
  3. Select the name of your resource group.
  4. Select the name of your VMSS.
  5. Select Upgrade Policy.
  6. Identify the Upgrade mode.

Update or upgrade

You upgrade the BIG-IP VE instances in a VMSS by updating the Azure image URN in the Azure ARM template. F5 recommends that you make only one change in the template, as described in this procedure.

Impact of procedure: When the system launches the new Azure ARM template, it upgrades BIG-IP VE instances one-at-a-time. If you have more than one BIG-IP VE instance, services may not be disrupted. However, the VMSS may have BIG-IP VE instances with different BIG-IP versions at any one time. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Azure portal.
  2. Go to Resource Group.
  3. Select the name of your resource group.
  4. Select Deployments.
  5. Select the last successfully deployed Microsoft Template.

    For example, you select:

    Microsoft.Template-20210414114538

  6. Select Redeploy.
  7. Select Edit Template.
  8. Search for the image URN and replace it with the URN you identified in Determine the Azure image URN you want to update or upgrade to.

    For example, you enter:

    "image": "f5-networks:f5-big-ip-best:f5-bigip-virtual-edition-25m-best-hourly:16.0.101000",

  9. Select Save.
  10. Verify the rest of the settings.

    Note: The Azure portal may reset settings in the web form to default values that are not currently used in the deployment. You must go through each setting to ensure the portal deploys the right ones.

  11. Select I agree to the terms and conditions stated above.
  12. Select Purchase.
  13. Follow the upgrade progress by selecting the bell notification icon and selecting Deployment in progress.
  14. Open a new browser tab, and then go to the name of your resource group > name of your VMSS > Instances.

    For each instance, in the Latest model column, the values displays as No. Upon completion, each instance is set to Yes.

  15. Do one of  the following:
    • If you set the upgrade policy for your VMSS to Rolling or Automatic, the system performs the update and no further action is required.
    • If you set the upgrade policy for your VMSS to Manual, upgrade each BIG-IP instance manually by continuing to the next step.
  16. Select the BIG-IP instance.
  17. Select Upgrade.
  18. Repeat steps 16 and 17 until all instances are upgraded.

Recommendations

  • Understand how the Azure deployment updates the BIG-IP VE instances using F5 Azure ARM Templates 2.0 and F5 BIG-IP Runtime Init on GitHub.
  • When you modify the image URN of the deployment, perform only one change at a time. Making multiple changes may result in issues whose root cause you are unable to determine.
  • The Azure deployment updates each BIG-IP instance one-at-a-time, including time to initialize each instance. Each instance upgrade and initialization constitute the following processes:
    1. The system destroys the old virtual machine.
    2. The system launches a new virtual machine based on the image URN you provided.
    3. The system downloads and runs F5 BIG-IP Runtime Init.
    4. F5 BIG-IP Runtime Init downloads, installs, and applies DO, AS3, and TS to load the BIG-IP configuration.

    The more instances you have, the more time is required.

    Optional: Depending on your environment, before performing the update, you can set the maximum capacity of the VMSS to reduce the number of instances to update. For example, you can set the maximum capacity to two instances. After you successfully upgrade two instances, you can increase the capacity again.

Troubleshoot

After selecting Purchase to upgrade the BIG-IP instances, follow the events to ensure there are no errors.

The following table lists common issues, possible causes, and resolutions.

Table 19.1 Common issues, possible causes, and resolutions
Common issuesPossible causesResolutions
The new BIG-IP instance takes a long time to initialize.Each instance upgrade and initialization goes through the following processes:
  1. The system destroys the old virtual machine.
  2. The system launches a new virtual machine based on the image URN you provided.
  3. The BIG-IP system downloads and runs F5 BIG-IP Runtime Init.
  4. F5 BIG-IP Runtime Init downloads, installs and applies DO, AS3, and TS to load the BIG-IP configuration.
As the deployment launches each BIG-IP VE instance, you can optionally log in to follow the initialization process in the following files:
  • /var/log/cloud/bigIpRuntimeInit.log
  • /var/log/cloud/startup-script.log
  • /var/log/ltm
  • /var/log/restnoded/restnoded.log
The status of the new BIG-IP instance displays Failed or Error, or the Health State is Unhealthy.There are errors launching the BIG-IP image, or the system did not load the BIG-IP configuration successfully. Depending on the specific error, you can perform the following:
  • Repeat the upgrade procedure to redeploy the deployment again.
  • Delete the affected BIG-IP instance and wait for the VMSS to relaunch the BIG-IP instance.
The new BIG-IP instance does not contain any objects or configuration.The system did not successfully load the bigIpRuntimeInitConfig file that contains the BIG-IP configurations, and DO, AS3, and TS are not running as a result. Enter the following command:

grep "version:" /var/log/restnoded/restnoded.log

When DO, AS3, and TS are running, you see output similar to the following example:

info: [f5-declarative-onboarding: restWorker.js] Running DO version: 1.19.0
warning: [appsvcs] {"message":"AS3 version: 3.26.0","level":"warning"}
info: [telemetry] Application version: 1.18.0
  • Verify the bigIpRuntimeInitConfig parameter. It should contain a valid URL to a YAML file that your Azure account has access to.
  • Verify the contents of the bigIpRuntimeInitConfig YAML file. When there are errors in the file, the configuration does not load.
  • Perform one change at a time.
  • Review the following log files:
    • /var/log/cloud/bigIpRuntimeInit.log
    • /var/log/cloud/startup-script.log
    • /var/log/ltm
    • /var/log/restnoded/restnoded.log
The deployment reports errors on the Azure portal Refer to F5 Azure ARM Templates 2.0 and F5 BIG-IP Runtime Init on GitHub.. Select Issues to view the common issues, error messages, and workarounds that others have encountered.
