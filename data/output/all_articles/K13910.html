Known Issue

Description

The BIG-IP APM content rewrite engine does not properly rewrite the JavaScript @cc_on command.

This issue occurs when the following condition is met:

  • You use the BIG-IP APM web portal to access a web page containing the @cc_on command.

Impact

  • Portions of the web page may not display.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The @cc_on command will not execute.
  • The page source will be rewritten to appear similar to the following example:

    eval(F5_Invoke_eval(null,'\n'+/*@cc_on ... )

F5 Product Development has assigned ID 383313 to this issue, and has confirmed that this issue exists in the products listed in the Applies To box. For information about releases or hotfixes that resolve this issue, refer to the following table:

Type of FixFixes Introduced InRelated Articles
Release11.2.0K2200: Most recent versions of F5 software

Workaround

To work around this issue, you can prevent the BIG-IP APM system from rewriting the @cc_on command. To do so, perform one of the following two procedures:

  • Creating an iRule to prevent the BIG-IP APM from rewriting the @cc_on command
  • Using the <apm_do_not_touch> tag to instruct the content rewrite engine to ignore the @cc_on command

Creating an iRule to prevent the BIG-IP APM from rewriting the @cc_on command

Note: This iRule will not work if the cc_on command is included in a .js file.

Impact of workaround: iRules may increase processing overhead and require more system resources per connection.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Enter a name into the Name text box.

    For example:

    fix-cc_on
  6. Copy the following iRule into the Definition text box:

    when REWRITE_REQUEST_DONE {
    switch -glob "[HTTP::host][HTTP::path]" {
    "*" {
    REWRITE::post_process 1
    set match 1
    }

    default {
    set match 0
    }
    }

    if { [info exists match] && $match } {
    if { [HTTP::version] eq "1.1" } {
    if { [HTTP::header is_keepalive] } {
    HTTP::header replace "Connection" "Keep-Alive"
    }
    HTTP::version "1.0"
    }
    }
    }

    when HTTP_RESPONSE {
    if { [info exists match] && $match } { HTTP::collect 1048576 }
    }

    when HTTP_RESPONSE_DATA {
    if { [info exists match] && $match } {
    regsub -all {/\*@cc_on} [HTTP::payload] "==f5-cc_on= =f5-cc_on==" npayload
    regsub -all {@\*/} $npayload "==f5-cc_end= =f5-cc_end==" npayload
    HTTP::payload replace 0 [HTTP::payload length] $npayload
    }
    HTTP::release
    }

    when REWRITE_RESPONSE_DONE {
    if { [info exists match] && $match } {
    regsub -all {=f5-cc_on==} [REWRITE::payload] "" npayload
    regsub -all {==f5-cc_on=} $npayload "/*@cc_on" npayload
    regsub -all {=f5-cc_end==} $npayload "" npayload
    regsub -all {==f5-cc_end=} $npayload "@*/" npayload
    set nlength [REWRITE::payload length]
    REWRITE::payload replace 0 $nlength {}

    while {1} {
    set nsegment [string range $npayload [expr $nlength - 63999] $nlength]
    REWRITE::payload replace 0 0 $nsegment
    set nlength [expr $nlength - 64000]

    if { $nlength < 0 } {
    break
    }
    }
    }

    set match 0
    }

  7. Click Finished.
  8. Click Virtual Servers.
  9. Click the name of the virtual server to which you want the iRule to attach.
  10. Click the Resources tab.
  11. Click Manage in the iRules section.
  12. Select the iRule created above from the the Available list.
  13. Click <<.
  14. Click Finished.

Using the <apm_do_not_touch> tag to instruct the content rewrite engine to ignore the @cc_on command

Impact of workaround: Any statements inside the tags will not be processed by the content rewrite engine and portions of the web page may not reload correctly.

  1. Open the HTML source that you want to modify.
  2. Insert the <apm_do_not_touch> tag prior to the @cc_on statement.
  3. Insert the </apm_do_not_touch> tag after the @*/ statement.
  4. Save the HTML source.
