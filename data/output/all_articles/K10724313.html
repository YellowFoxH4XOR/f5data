K10724313: Dynamic multi-connect client peers unable to connect to SDC.

Type
Support Solution
Published
2021-12-07
Updated
2023-02-21
Applies to
  • Traffix SDC: 5.X.X, 5.1.X, 5.0.X, 5.2.0, 5.2.X, 5.0.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K10724313

Description

Dynamic multi-connect client peers are unable to connect to SDC. It gives below error

2021-08-19 18:14:55,671 WARN  [12294] Peer aaa://abcd.rx.f5test.com.sgk_SN_1:5403;transport=sctp is rejected because it exceeded allowed maximum number of peers of 5000 [Silo-EventLoop-thread-3-2_23] [PeerTableImpl.incrementBusinessPeersCounter()]

Environment

  • SDC

Cause
The issue happens because of a known SDC Bug CPF-25116

Recommended Actions

***Procedure needs to be performed during planned maintenance.
  1. Open the Webui and navigate to the engineering script and Tab Cluster Nodes Engineering Script.
    • Enter the following lines after the //YOUR CODE HERE:
      •     //YOUR_CODE_HERE
            userTraceLogger.info(" number of business peer in site  " + stack.getPeerTable().businessPeersCounter.get())
            stack.getPeerTable().businessPeersCounter.set(1)
            userTraceLogger.info(" after updating number of business peer in site  " + stack.getPeerTable().businessPeersCounter.get())
      • Click submit
  2. Verify if the remaining client peer handshake is established successfully.
  3. If the engineering script does not resolve the issue, then proceed to restart the sdc process below -
    1. Take a backup from WebUI > Administration tab > Backup and restore > click Backup
    2. Generate TTA log file on all SDC nodes. Run command: /opt/traffix/scripts/tta-ng.sh -c 7 -n 5
      • option -c: collect last 7 days of modified configurations [by default it collects 30 days]
        option -n: collect last 5 copies of log files [by default it collects 3 copies]
      • As the processes need to stop/start, please perform due diligence to divert the traffic to the other SDC site before restarting the SDC processes using 'monit stop all' and 'monit start all'
    3. Stop the SDC processes on all nodes(in a site).
      • Run command: monit stop all
    4. Monitor all processes are in 'Not monitored' before proceeding
      • Run command: monit summary
      • The time taken depends on the size of configuration, and Tripo storage records. Est: 20-30mins
      • Sample out from lab environment. It may differ from your output:
