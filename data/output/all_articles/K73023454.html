K73023454: The MCC and MNC values are now available separately with the 'GTP::ie get value' iRule command

Type
Knowledge
Published
2020-12-11
Updated
2023-10-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.0, 14.1.2, 13.1.3
Source
https://my.f5.com/manage/s/article/K73023454

Issue

Old Behavior

In versions prior to BIG-IP 13.1.3.4, 14.1.2.7, and 15.1.0.5, the GTP::ie get value command for the Serving Network GTP element (83) treats the values of mobile country codes (MCC) and mobile network codes (MNC) as a single entity.

Note: The old behavior was introduced to address a known issue. For more information, refer to Bug ID 749704 in F5 Bug Tracker.

New Behavior

Beginning in BIG-IP 13.1.3.4, 14.1.2.7, and 15.1.0.5, the return value format of the GTP::ie get value command changed. Namely, the MCC and MNC values are available separately, under index 0 and 1 respectively. Any additional optional data is available under index 2.

F5 Product Development tracked this change as ID 696330.

Impact

The GTP::ie get value command now returns MCC and MNC values in a different format. For example, the following iRule retrieves the Serving Network GTP element from the client data, and logs the value, index 0, and index 1 of the value separately:

when CLIENT_DATA {
  set gtp_message [GTP::parse [UDP::payload]]
  set val_83 [GTP::ie get value -message $gtp_message 83]
  set len_83 [GTP::ie get length -message $gtp_message 83]
  log local0. "val=$val_83  val0=[lindex $val_83 0]  val1=[lindex $val_83 1]  len=$len_83"
}

The log entry produced from the old behavior appears similar to the following example. Note that the MCC and MNC elements are treated as a two-element list, which are returned under index 0. The value of index 1 is empty, unless extra data is presented in the Serving Network element:

info tmm[8484]: Rule /Common/testGTP_irule <CLIENT_DATA>: val={440 20}  val0=440 20  val1=  len=3

The log entry produced from the new behavior appears similar to the following example. The values of the MCC and MNC elements are available separately, and stored under index 0 and index 1:

info tmm[8485]: Rule /Common/testGTP_irule <CLIENT_DATA>: val=440 20  val0=440  val1=20  len=3
