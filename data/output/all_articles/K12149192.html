Description

Observing the HTTP protocol compliance failed violation, due to null in request.

  • K7931: Error Message: Null in request

The request contains a null byte in the body, specifically a parameter value.

Can we remove or strip out the null before ASM?

Environment

  • POST request
  • Null byte
  • Legacy application that cannot be changed

Cause

None

Recommended Actions

In the first instance, it is recommended, if possible, to fix the application so that POST requests do not contain the null.

It is also possible to disable the Null in request subviolation, or set parameter value type to ignore value.

If those options are not suitable or preferred, you can use a Stream profile and iRule to remove the null from the body in the HTTP_REQUEST event. This event occurs before ASM processing and therefore the violation will be avoided.

Here is an example iRule:

when HTTP_REQUEST {
    if {[HTTP::header value Content-Type] starts_with "text"} {
        STREAM::expression {@\u0000@@}
        STREAM::enable
    }
}
when HTTP_RESPONSE {
    STREAM::disable
}

This searches for the unicode null \u000 in the body of the HTTP request, and replaces it with the replacement value, which in this case is empty - between the @ delimiters. Effectively, this will remove the null.

The iRule should be applied with a blank Stream profile, and a HTTP profile with Request Chunking set to Rechunk.

Important: Using the stream profile causes HTTP requests to be chunked when they are sent to the server. This may or may not cause an issue for the application. This is required, as using the stream profile affects the content length of the POST, without updating the Content-Length header (it is removed).

Note: The iRule is an example, and should be tested thoroughly before implementing in production. It may not be suitable for all environments. Adding additional if logic is recommended to ensure the iRule doesn't run unnecessarily.

Additional Information

The solution presented in this article is only applicable if the null appears in the body of the request. If it appears elsewhere, a different solution would be needed.
