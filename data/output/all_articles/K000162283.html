Description

The IPPORT cmp-hash mode on BIG-IP platforms and Virtual Editions (VE) enables traffic disaggregation using a 4-tuple hash: {local IP, remote IP, local Port, remote Port}.

This article explains how IPPORT works, its advantages over other DAG modes, performance considerations on VE versus hardware platforms, and important deployment caveats.

It is intended for customers evaluating or deploying cmp-hash ipport in their environments, especially where optimal traffic distribution and CPU efficiency are critical.

Environment

  • Product: BIG-IP platforms and Virtual Editions (VE)
  • Software: BIG-IP v14.1.0 and above releases
  • Features: CMP (Clustered Multiprocessing), CMP has configuration (Default DAG, SP-SAG, RR-DAG and IPPORT)

IPPORT Functionality — How It Works

  • IPPORT is a CMP hash mode that disaggregates ingress traffic based on a 4-tuple: {local IP, remote IP, local Port, remote Port}.
  • The Default DAG hashes only on L4 source and destination ports. This works well when ephemeral ports provide sufficient entropy, but fails in scenarios such as:
    • Uncommon IP protocols (ICMP, GRE, ESP, etc.) with no L4 ports, causing all traffic to hash to port 0 and pin to a single TMM.
    • Low-entropy port traffic (e.g., SIP on port 5060/5060), where both ports are fixed and all traffic hashes to the same TMM.
    • Artificially generated load traffic, where test tools use predictable port patterns, resulting in poor distribution with port-only hashing.
  • Source/Destination DAG (SP-DAG) hashes on source and destination IP addresses and is recommended when ports are hardcoded.
  • Round Robin DAG (RR-DAG) is hardware-only and not available on VE. It distributes UDP traffic evenly by sending each packet to a different TMM, regardless of IP or port.
  • IPPORT addresses the above limitations by hashing on the full 4-tuple, providing higher entropy and better distribution across a wider range of traffic types.

Performance Considerations — VE vs. Hardware

  • On hardware platforms (e.g., iSeries, VIPRION), DAG can be performed in hardware (NIC/HSB/FPGA) or in software (daglib in TMM). Hardware DAG is extremely fast with near-zero CPU cost.
  • On BIG-IP VE, there is no hardware DAG. All DAG operations are performed in software by the daglib library in TMM.
  • The "ipport" mode hashes over more fields than "src-ip" (4-tuple vs. 1-tuple), resulting in a marginally higher computational cost per packet. However, this is a minor software computation difference and not a hardware-offload penalty. The practical impact is negligible for standard TCP/UDP traffic.

Platform/Module Guidance — Scenarios Requiring Additional Consideration

  • Here are the list of platforms that support Hardware-Accelerated DAG:
    • r5000/r10000/r12000 series platforms
    • VELOS BX110 & BX520 blades
    • i5820-DF
    • VIPRION B4450N & B4460N blades 
  • Hardware platforms without IPPORT hardware acceleration should review KB K43542321 for potential CPU overhead.

Additional Information — Caveats and Insights

VE DAG behavior may depend on the hypervisor and driver. Always verify the actual algorithm in use with:

# tmctl -d blade tmm/daglib -s tmid,hash_type,hash_name
