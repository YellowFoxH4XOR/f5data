Known Issue

This is the result of a known issue. Using mixed letter case in BIG-IP volume names may prevent the BIG-IP from booting from some volumes. The disk management system is fully case-sensitive, and allows creation of names containing uppercase letters, and also allows creation of duplicate volume names which vary only in case. However, the BIG-IP boot partition uses the FAT32 file system format, which is not case-sensitive, yet preserves case for long file names. This discrepancy in case sensitivity between these two boot volume management components can prevent the BIG-IP system from booting from some volumes. For example:

  • Short Volume Names

    For volume names 8 characters or shorter, the BIG-IP system will fail to boot from that volume if the volume name contains any uppercase letters.

  • Long Volume Names

    For volume names longer than 8 characters, the BIG-IP system may fail to boot from the volume if the volume name is a case-insensitive duplicate of another volume name on the same system.

Note: This issue only affects units running BIG-IP version 10.0.x which have been deployed using the volumes disk-formatting scheme introduced in BIG-IP version 10.0.0. The volumes disk-formatting scheme allows a BIG-IP Administrator to create multiple volumes running different versions of the BIG-IP software. For more information about the volumes disk-formatting scheme, refer to the Working with volumes section in the BIG-IP Systems: Getting Started Guide.

F5 Product Development tracked this issue as CR117810 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Short volume names

When you give a new volume a name of 8 characters or less, the BIG-IP system will use the FAT32 Short File Name (SFN) standard to create the matching directory in the boot partition. When this standard is used, all directories are written in lowercase. When the GRUB boot loader looks for a boot directory matching the case of the volume name, it is unable to find the boot directory for volume names containing uppercase letters. As a result, the system is unable to boot from that volume.

For example, if you install BIG-IP version 10.0.x on a volume named PREPROD, the GRUB boot loader will look for the kernel and initrd files in the /boot/PREPROD/ directory, but it will fail to find them as the directory name on the FAT32 file system is /boot/preprod/. As a result, the BIG-IP system will fail to boot and will display an error message on its console that appears similar to the following example:

root (hd0,0)
Filesystem type is fat, partition type 0xb
kernel /boot/PREPROD/vmlinuz ro root=UUID=858e2631-ff6b-4aeb-852b-65914d3701a7
console=ttyS0,19200 panic=1 platform=Mercury quiet

Error 15: File not found

Press any key to continue...

The BIG-IP system will then wait for user interaction. During this time the unit will be down, and no traffic will be processed.

Note: The disk management system will also allow duplicate short volume names differing only in case, but any short volume name containing an uppercase letter will fail to boot.

Long volume names

When you give a new volume a name longer than 8 characters, the BIG-IP system will use the FAT32 Long File Name (LFN) standard to create the matching directory in the boot partition. This standard preserves the case of the directory name, but is case-insensitive when comparing file and directory names, and thus cannot differentiate between files or directories whose names differ only in case. As a result, if you create a volume whose name duplicates an existing volume name, differing only in case, the system is unable to create a directory matching the case of the new volume name. When the GRUB boot loader looks at boot time for a boot directory matching the case of the volume name, it is unable to find it, and the system is unable to boot from that volume.

For example, if you create a volume named PREPRODUCTION, and a volume named PreProduction, the disk management system will be unable to create a directory named /boot/PreProduction, as it is a case-insensitive duplicate of the existing directory named /boot/PREPRODUCTION. When you attempt to boot from the volume named PreProduction, the GRUB boot loader will look for the kernel and initrd files in the /boot/PreProduction/ directory, but it will fail to find them. As a result, the BIG-IP system will fail to boot and will display an error similar to one above. The BIG-IP system will then wait for user interaction. During this time the unit will be down, and no traffic will be processed.

Workaround

To avoid running into this issue, ensure that you only use lowercase letters for your volume names.

If you have already run into this issue, and your BIG-IP system is now failing to boot, perform the following three procedures:

Booting the BIG-IP system from a working volume

  1. Connect to the BIG-IP system using the serial console.

    Note: For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system.
  2. Power the BIG-IP system off and on again.
  3. The non-working volume is the default boot location of the BIG-IP system; when you see the GRUB screen come up, interrupt the automatic boot sequence by pressing the UP and DOWN arrow keys repeatedly.
  4. Using the UP and DOWN arrow keys, select a working volume.
  5. Press Enter to boot the BIG-IP system from the selected working volume.

Changing the default boot location of the BIG-IP system

  1. Connect to the BIG-IP system using SSH.
  2. Enter the switchboot command.

    An interactive screen comes up.
  3. Using the UP and DOWN arrow keys, select a working volume.
  4. Confirm by pressing Enter.
  5. Enter the reboot command.

    Note: The BIG-IP system will now automatically boot from the working volume you have selected.

Deleting the non-working volume

  1. Once the BIG-IP system has completed booting, log in to the Configuration utility.
  2. Expand System.
  3. Click on Volume Management under the Software Management section.
  4. Select the check box next to the non-working volume.
  5. Press Delete.
  6. In the next screen you will be asked to confirm your action. Click Delete.
