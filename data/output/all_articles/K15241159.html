Description
After upgrade of a BIG-IP VE or vCMP guest, the device may no longer respond to ARP request causing pool members to become unreachable on the network.

Logs similar to the following are found in /var/log/kern:

  kern <date/time> Info BIG-IP kernel: bridge: filtering via arp/ip/ip6tables is no longer available by default.\
  Update your scripts to load br_netfilter if you need this.
  kern <date/time> Info BIG-IP kernel: kernel: [52.181972] bridge: filtering via arp/ip/ip6tables is no longer available by default.\
  Update your scripts to load br_netfilter if you need this.

Logs similar to the following are found in /var/log/ltm:

  tmm <date/time> Notice BIG-IP <13 user-level notice> vmxnet3(1.2)[19:0.0]: Waiting for tmm0 to reach state 2...
  tmm <date/time> Notice BIG-IP <13 user-level notice> vmxnet3(1.3)[27:0.0]: Waiting for tmm1 to reach state 2...
  tmm <date/time> Notice BIG-IP <13 user-level notice> vmxnet3(1.3)[27:0.0]: Waiting for tmm3 to reach state 2...
  tmm  <date/time> Notice BIG-IP <13 user-level notice> vmxnet3(1.3)[27:0.0]: Waiting for tmm0 to reach state 2...

Environment

  • BIG-IP VE software upgrade
  • BIG-IP vCMP guest software upgrade

Cause
Unknown

Recommended Actions

Initiate an MCPD reload, as per the relevant procedure in the following article:
  K13030: Forcing the mcpd process to reload the BIG-IP configuration
