Description

F5 Access for iOS 3.x fails to connect to VPN when Proxy PAC file is accessed via HTTP instead of HTTPS 

  • iOS users report being unable to establish VPN
  • Access Policy Evaluation completes for these clients successfully
  • PacketTunnel.log may report the following error: 
367,21523[com.apple.NSXPCConnection.user.endpoint],PacketTunnel, 48, PacketTunnelProvider.swift:1265, stopTunnel(with:completionHandler:), Map stop reason to hangup code ErrUserInitiated(1)


Environment
  • BIG-IP Access Policy Manager (BIG-IP APM)
  • F5 Access for iOS 3.x
  • Network Access resource configured with a Client Proxy Autoconfig Script (PAC) specifying http:// instead of https://

Cause

Starting with F5 Access version 3.0, the client is distributed with App Transport Security enabled. App Transport Security (ATS) requires that beginning with iOS 9 apps no longer be allowed to initiate insecure plain text HTTP connections or TLS connections that don't comply with stricter requirements. The changes include:

  • The app will not be allowed to initiate plain text HTTP connections, and will be required to use HTTPS with the strongest TLS configuration (TLS 1.2 and PFS cipher suites)
  • TLS connections require compliance with best practices: TLSv1.2 with forward secrecy, no known-insecure cryptographic primitives (RC4 encryption, SHA-1 certificate signatures), and key size requirements (2048 bits for RSA, 256 bits for EC).

Recommended Actions

Move the PAC file to an HTTPS resource

Or

Enable the "Ignore Client Proxy Autoconfig Script Download Failure" setting in the Network Access Resource:
  1. Login to the Admin GUI.
  2. Navigate to Access›Connectivity / VPN>Network Access (VPN)>Network Access Lists.
  3. Select the Network Access resource.
  4. Click on Network Settings.
  5. In the Client Settings menu select "Advanced."
  6. Enable "Ignore Client Proxy Autoconfig Script Download Failure."
  7. Click Update.
