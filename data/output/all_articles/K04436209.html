Topic

You should consider using this procedure under the following conditions:

  • The Qualys security scan run on a BIG-IP HTTP virtual server reports security threat QID 11827: HTTP Security Header Not Detected. For example:

    ////////////////////////////////////
    CVSS Base Score:    4.3    AV:N/AC:M/Au:N/C:N/I:P/A:N
    CVSS Temporal Score:    3.5    E:U/RL:U/RC:UR
    Severity:    2     
    QID:    11827

    THREAT:
    This QID reports the absence of HTTP Security Headers according to CWE-693: Protection Mechanism Failure
    ////////////////////////////////////

  • One or more of the following HTTP security headers are not detected in the HTTP response:
    • X-Frame-Options: This HTTP response header improves the protection of web applications against clickjacking attacks. Clickjacking, also known as a UI redress attack, allows an attacker to use multiple transparent or opaque layers to trick a targeted user into clicking a button or link on another page when they intend to click the top-level page.
    • X-XSS-Protection: This HTTP header enables the browser built-in cross-site scripting (XSS) filter to prevent cross-site scripting attacks. The header X-XSSProtection: 0; disables this functionality.
    • X-Content-Type-Options: This HTTP header prevents attacks based on MIME-type mismatch. The only possible value is nosniff. If your server returns X-Content-Type-Options: nosniff in the response, the browser refuses to load the styles and scripts in case they have an incorrect MIMEtype.
    • Strict-Transport-Security (HSTS): This response header is a security feature that lets a web site tell browsers that it should only be communicated with using HTTPS instead of HTTP.

Description

To mitigate the identified security threat, you can insert the missing HTTP security headers into HTTP responses processed by the affected virtual server. To do so, you can configure the BIG-IP system to insert the HTTP security headers shown in the following table.

HTTP headerDescription
X-Frame-OptionsInsert the X-Frame-Options response header to provide protection against clickjacking vulnerability for your website. By implementing this header, you instruct the browser when and if content may be embedded in a frame or iframe.
You can set the X-Frame-Options header to one of the following values:
  • DENY prevents the browser from embedding content in any frame or iframe.
  • SAMEORIGIN only permits the browser to frame content for the current site.
  • ALLOW-FROM uri only permits the browser to frame content for the specified URI, such as ALLOW-FROM http://www.example.com.
The DENY value is recommended unless your application requires framing.

For more information about the X-Frame-Options header, refer to RFC7034.

X-XSS-ProtectionInsert the X-XSS-Protection response header to enable the XSS filter on the browser.

You can set the X-XSS-Protection header to one of the following values:

  • 0  disables XSS filtering.
  • 1  enables XSS filtering. If a cross-site scripting attack is detected, the browser sanitizes the page (removes the unsafe parts).
  • 1; mode=block enables XSS filtering. Rather than sanitizing the page, the browser prevents rendering of the page if an attack is detected.
The recommended value is 1; mode=block.
X-Content-Type-OptionsInsert the X-Content-Type-Options response header to protect against MIME types security risk. This header instructs the browser to consider files types as defined and disallows content sniffing. The value for the X-Content-Type-Options header is nosniff. 
Strict-Transport-SecurityInsert the Strict-Transport-Security (HSTS) response header to instruct the browser to only use HTTPS protocol when communicating with the application. This protects web applications against protocol downgrade and cookie hijacking attacks

The recommended value is max-age=16070400; includeSubDomains.

Note: Beginning in BIG-IP 12.0.0, the HSTS can be enabled in an HTTP profile.

For more information about the Strict-Transport-Security header, refer to RFC6797.

Note: Additional options to secure HTTP virtual servers can be configured, such as a Content-Security-Policy header and a Secure flag for cookies. For information refer to the Tightening the Security of HTTP Traffic  DevCentral articles listed in the Supplemental Information section of this article.

You can use either of the following procedures to insert the missing security HTTP response headers:

  • Using iRules to insert security HTTP headers
  • Using a BIG-IP local traffic policy to insert security HTTP headers

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the Configuration utility.
  • The affected BIG-IP virtual server processes both the HTTP request and HTTP response for the origin web server.

    Note: The procedures in this article do not work with BIG-IP virtual servers configured for nPath load balancing (also known as Direct Server Return or Asymmetric Routing).

    Note: Due to the order in which iRules events the system processes, the procedures in this article may not work correctly with some BIG-IP APM deployments. For more information about iRules event processing in BIG-IP APM, refer to the HTTP Event Order -- Access Policy Manager article on DevCentral.

Procedures

Using iRules to insert security HTTP headers

To configure the BIG-IP system to use iRules to insert the missing security HTTP response headers into HTTP responses for the affected virtual server, perform the following procedure:

Impact of procedure: The impact of the following procedure depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter a name for the iRule. For example, QID11827_mitigation.
  5. For Definition, enter an iRule similar to the following example:

    Important: The following iRule inserts all four security HTTP response headers discussed in this article and uses the recommended values for common environments. You may need to adjust the iRule for your specific environment.

    when HTTP_RESPONSE_RELEASE {
        if {!([HTTP::header exists "X-Frame-Options" ])} {
            HTTP::header insert "X-Frame-Options" "DENY"
        }
        if {!([HTTP::header exists "X-XSS-Protection"])} {
            HTTP::header insert "X-XSS-Protection" "1; mode=block"
        }
        if {!([HTTP::header exists "X-Content-Type-Options"])} {
            HTTP::header insert "X-Content-Type-Options" "nosniff"
        }
        if {!([HTTP::header exists "Strict-Transport-Security"])} {
            HTTP::header insert "Strict-Transport-Security" "max-age=16070400; includeSubDomains    "
        }
    }

  6. Select Finished.
  7. Select Virtual Servers.
  8. Select the name of the affected virtual server.
  9. Select the Resources tab.
  10. For iRules select Manage.
  11. In the Available list, select the iRule you previously created and move it to the Enabled list.
  12. Select Finished.

Using a BIG-IP local traffic policy to insert security HTTP headers

To configure the BIG-IP system to use a local traffic policy to insert the missing security HTTP response headers into HTTP responses for the affected virtual server, perform the following procedure:

Note: Prior to version BIG-IP 16.0.0, when the BIG-IP ASM module is configured on the BIG-IP system, the security HTTP response headers are not inserted into rejection responses generated by the BIG-IP ASM security policy. Starting in BIG-IP ASM 16.0.0, the system includes HTTP security headers for all response and blocking pages generated by the policy.

Impact of procedure: The impact of this procedure depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

Important: The following procedure creates a local traffic policy with rules for all four security HTTP response headers discussed in this article and uses the recommended values for common environments. You may need to adjust the policy rules for your specific environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Policies.
  3. Select Create.
  4. Enter a name for the policy. For example, QID11827_mitigation.
  5. For Strategy, select all.
  6. Select Create Policy.
  7. Create a policy rule to insert the X-Frame-Options rule by performing the following steps:
    1. For Rules, select Create.
    2. Enter a name for the X-Frame-Options rule. For example, X-Frame-Options header
    3. Under Match all of the following conditions, select the add icon (+).
    4. Construct the following rule statement:

      HTTP Header full string named X-Frame-Options is not any of DENY at response.

    5. Under Do the following when the traffic is matched, select the add icon (+).
    6. Construct the following rule statement:

      Insert HTTP Header named X-Frame-Options with value DENY at response time.

    7. Select Save.
  8. Create a policy rule to insert the X-XSS-Protection rule by performing the following steps:
    1. For Rules, select Create.
    2. Enter a name for the X-XSS-Protection rule. For example X-XSS-Protection header
    3. Under Match all of the following conditions, select the add icon (+).
    4. Construct the following rule statement:

      HTTP Header full string named X-XSS-Protection is not any of 1; mode=block at response.

    5. Under Do the following when the traffic is matched, select the add icon (+).
    6. Construct the following rule statement:

      Insert HTTP Header named X-XSS-Protection with value 1; mode=block at response time.

    7. Select Save.
  9. Create a policy rule to insert the X-Content-Type-Options rule by performing the following steps:
    1. For Rules, select Create.
    2. Enter a name for the X-Content-Type-Options rule. For example, X-Content-Type-Options header
    3. Under Match all of the following conditions, select the add icon (+).
    4. Construct the following rule statement:

      HTTP Header full string named X-Content-Type-Options is not any of nosniff at response.

    5. Under Do the following when the traffic is matched, select the add icon (+).
    6. Construct the following rule statement:

      Insert HTTP Header named X-Content-Type-Options with value nosniff at response time.

    7. Select Save.
  10. Create a policy rule to insert the Strict-Transport-Security rule by performing the following steps:
    1. For Rules, select Create.
    2. Enter a name for the Strict-Transport-Security rule. For example, Strict-Transport-Security header
    3. Under Match all of the following conditions, select the add icon (+).
    4. Construct the following rule statement:

      HTTP Header full string named Strict-Transport-Security is not any of max-age=16070400; includeSubDomains at response.

    5. Under Do the following when the traffic is matched, select the add icon (+).
    6. Construct the following rule statement:

      Insert HTTP Header named Strict-Transport-Security with value max-age=16070400; includeSubDomains at response time.

    7. Select Save.
  11. Select Save Draft > Save Draft Policy.
  12. Under Draft Policies, select the check box for the draft policy you just saved.
  13. Select Publish.
  14. Go to Local Traffic > Virtual Servers.
  15. Select the name of the affected virtual server.
  16. Select the Resources tab.
  17. For Policies, select Manage.
  18. In the Available list, select the policy you previously created and move it to the Enabled list.
  19. Select Finished.
