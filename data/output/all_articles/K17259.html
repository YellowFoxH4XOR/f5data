Known Issue

BIG-IP APM session count statistics may be inaccurate.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM device has established active sessions.
  • One of the following actions occurs:

    • A blade restarts on the active chassis.
    • The tmm process restarts on the active device and triggers a failover event.
  • After the action occurs, multiple established session users log out.
  • You use the Traffic Management Shell (tmsh), TMCTL, or SNMP to view the Current Active Sessions and Current Established Sessions statistics.

Impact

Session count information may be skewed.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When using the tmsh utility to view access profile session information for Current Active Sessions and Current Established Sessions, the session count is skewed.

    For example, tmsh utility output may appear similar to the following:

    tmsh show /apm profile access <access profile name>
    ----------------------------------------------------------
    ACCESS Profile: <access profile name>
    ----------------------------------------------------------
    User Session Statistics:
    ----------------------------------------------------------
    total sessions: 24.6K
    total established sessions: 21.2K
    current active sessions: 18.4E
    current pending sessions: 0
    current established sessions: 18.4E
    sessions terminated due to user logged out: 8.7K
    sessions terminated due to admin termination: 0
    sessions terminated due to timeout or errors: 15.9K
    sessions resulted into allow ending: 21.2K
    sessions resulted into deny ending: 1.0K
    sessions resulted into redirect ending: 0
    sessions resulted into redirect ending with session: 0
    requests allowed by ACL: 3.2K
    requests denied by ACL: 9
