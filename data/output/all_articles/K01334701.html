Issue

Error Message

502 Bad Gateway The proxy server received an invalid response from upstream

In this error message, note the following:

  • The 502 Bad Gateway error message is an HTTP status code.

Message Location

You may encounter this message in the following location:

  • The /var/log/tomcat/catalina.out file

Description

This message occurs when the following condition is met:

  • The tomcat process requires additional Java virtual memory.

Impact

You are unable to access the Configuration utility.

Recommended Actions

To mitigate receiving this message, you can use the provision.tomcat.extramb database variable to increase the maximum amount of Java virtual memory available to the tomcat process. The additional memory for the tomcat process reduces the amount of memory available for the Linux host and does not affect available memory for the Traffic Management Microkernel (TMM). To increase the maximum amount of memory available to the tomcat process, perform the following procedure:

Impact of procedure: Allocating additional memory to Apache Tomcat may impact the performance and stability of the BIG-IP system. You should perform this procedure only when directed by F5 Support after considering the impact to Linux host memory resources.

Important: Although the procedures outlined in this article may mitigate the offending error message, it does not substitute for identifying the root cause of the Apache Tomcat Java memory allocation and exhaustion issue.

  1. Log in to the BIG-IP command line.
  2. Using a utility, such as free or top, determine if you have enough free memory available to use this procedure. For example, the following output from the free utility shows 686844 kilobytes available:

    total      used         free       shared     buffers     cachedMem:     
    16472868   15786024     686844     807340     827748      2543836
    -/+ buffers/cache:   12414440    4058428
    Swap:      1023996          0    1023996

  3. View the current amount of memory allocated to the tomcat process by typing one of the following commands:
    • BIG-IP 11.x and later

      ps | grep " -client" | egrep -o Xmx'[0-9]{1,5}m'

      The command output appears similar to the following example:

      Xmx260m
      Xmx260m

    • BIG-IP 10.x

      ps | egrep -o Xmx'[0-9]{1,5}m'

      The command output appears similar to the following example:

      Xmx120m
      Xmx120m

  4. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  5. View the current value of the provision.tomcat.extramb database variable by typing the following command:

    list /sys db provision.tomcat.extramb

    The command output appears similar to the following example:

    sys db provision.tomcat.extramb {
    value "0"
    }

    A value of 0 (zero) indicates no additional memory is currently allocated. This is the default value.

  6. Set the provision.tomcat.extramb database variable to the desired amount of additional memory to be allocated using the following command syntax:

    modify /sys db provision.tomcat.extramb value <MB>

    In this command, note the following:

    • <MB> is the number of megabytes of additional memory you want to add to the default provisioned amount.

    For example, to allocate an additional 20 MB of additional memory, type the following command:

    modify /sys db provision.tomcat.extramb value 20

    Note: F5 recommends an initial increase of 20 MB, but it may not resolve all instances of the error message. If the java.lang.OutOfMemoryError errors continue, repeat this procedure, gradually increasing the value of <MB> until you no longer encounter the error message.

  7. Restart the tomcat process by typing the following command:

    restart /sys service tomcat

  8. If the device is part of a high availability (HA) configuration, the provision.tomcat.extramb database value should be synchronized to the peer devices from the command line.
    • For BIG-IP 11.x through 12.x, refer to K14856: Performing a ConfigSync using tmsh.
    • For BIG-IP 10.x, type the following command:

      tmsh run sys config-sync

  9. Log in to the command line of each peer device and restart the tomcat process using the command from step 6.
