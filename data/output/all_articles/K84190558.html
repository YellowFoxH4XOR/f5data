Description

Virtual-address configured on BIG-IP should respond to a icmp request with an icmp echo response.

Environment

  • BIG-IP
  • AFM (optional)
  • ICMP

Cause

There may be one or more causes:
- AFM blocking
- Virtual-address configuration
- Network routing and connectivity

Recommended Actions

  1. Use AFM packet tester to see if AFM is blocking this traffic (see K13723376).
  2. Review virtual-address configuration to identify the value of icmp-echo (see additional information section below)
    tmsh list ltm virtual-address <virtual-address> all-properties
  3. Verify routing and NDP table (for icmpv6) has the correct entries to route icmp-echo response back to client IP.  Can you ping the client IP from BIG-IP?
    tmsh show net route
    tmsh show net ndp (for icmpv6)

     

Additional Information

K13723376: BIG-IP AFM operations guide | Chapter 9: Troubleshooting

icmp-echo:

Specifies how the system sends responses to Internet Control Message Protocol (ICMP) echo requests on a per-virtual address basis. When enabled, the BIG-IP system intercepts ICMP echo request packets and responds to them directly. When disabled, the BIG-IP system passes ICMP echo requests through to the backend servers.

        Disabled: Does not send ICMP responses.
        Always: Always sends ICMP responses, regardless of availability status. This requires an enabled virtual address.
        Selective: Internally enables or disables responses based on virtual server state: any virtual server, all virtual servers, or always, regardless of the state of any virtual server.
        Any: Responds when any virtual server is available.
        All: Responds only when all virtual servers are available.
    Important: For Selective, you must configure each relevant virtual server to notify the virtual address of its status.
