Topic

You should consider using this procedure under the following condition:

  • You want to disable a specific BIG-IP ASM violation for a URL.

Description

In some cases, you may want to override the security policy blocking action for a specific violation and forward the request to the origin server (OWS). For example, while building the security policy, you may want to disable a specific BIG-IP ASM violation for a URL while leaving the violation enabled for other URLs. To do so, you can use the ASM::unblock iRules command.

The following applies to using the ASM::unblock iRules command:

  • Violations from an unblocked request do not generate learning suggestions.
  • The command applies to requests only.
  • The command does not apply to requests that are part of attacks such as web scraping or brute force attacks.
  • The command takes effect even if it is followed by an iRules command with a blocking violation.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the BIG-IP ASM Configuration utility.
  • You have identified the specific violation that you want to forward to the OWS.

Procedures

  • Enable BIG-IP ASM iRules events
  • Determine the violation name
  • Define the iRule to disable a specific violation for a URL

Enable BIG-IP ASM iRules events

Before you configure the iRule to disable a specific violation for a URL, you must enable ASM iRules events for the security policy. To do so, perform one of the following procedures, depending on the version of BIG-IP ASM you are running.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Enable BIG-IP ASM iRules events (BIG-IP 15.1.x and later)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy that you want to edit.
  4. Select the General Settings tab.
  5. For Trigger ASM iRule Events Mode, select Normal.
  6. Select Save.
  7. Select Apply Policy.

Enable BIG-IP ASM iRules events (BIG-IP 14.x through 15.0.x)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy that you want to edit.
  4. On the Policy Properties tab, select Advanced.
  5. For Trigger ASM iRule Events, select Normal Mode.
  6. Select Save Changes.
  7. Select Apply.

Enable BIG-IP ASM iRules events (BIG-IP 13.x)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy > Policy Properties.
  3. For Current edited security policy, select the policy that you want to edit.
  4. For Policy Properties, select Advanced.
  5. For Trigger ASM iRule Events, select Enabled.
  6. Select Save.
  7. Select Apply Policy.

Determine the violation name

You must determine the name of the specific violation that you want to disable. You can then specify the violation name when you define the iRule. To determine the name of the violation, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule list.
  3. Select Create.
  4. For Definition, enter the following iRule code:

    when ASM_REQUEST_DONE {
    log local0. "ASM violation name: [ASM::violation names]"
    }

  5. Select Update.
  6. Associate the iRule with the appropriate virtual server.
  7. Send a request that triggers the violation that you want to forward to the OWS.
  8. Log in to the BIG-IP command line and search for the name of the violation.

    For example:

    grep -i violation /var/log/ltm

    The following log entry shows an example of a violation name as it should be used in the iRule:

    tmm[25875]: Rule /Common/asm_violation <ASM_REQUEST_DONE>: ASM violation name: VIOLATION_ILLEGAL_METHOD

  9. After you determine the violation name that you want to use in the iRule, you can remove the previous iRule from the virtual server configuration.

Define the iRule to disable a specific violation for a URL

To disable a specific violation for a URL using an iRule, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule list.
  3. Select Create.
  4. Define the iRule that disables the violation for the URL.

    For example:

    when ASM_REQUEST_DONE {
    if {[ASM::violation names] contains "VIOLATION_ILLEGAL_METHOD" and [string tolower [HTTP::uri]] contains "/index.html"}
    {
    ASM::unblock
    log local0. "ASM unblocking [HTTP::uri]"
    }
    }

  5. Select Create.
  6. Associate the iRule with the virtual server.
