Known Issue

This is the result of a known issue. If a Network Access connection has a policy check enabled, and a user launches that Network Access connection using Microsoft Internet Explorer, the Network Access connection may fail even if the client system passed the policy check. This issue occurs when Internet Explorer is configured to use a proxy server. As a result, the Network Access connection fails with an error message that appears similar to the following example:

Status: The modem (or other connecting device) has reported an error.

Note: Policy checks are configured on the Network Access: Resources page, under the Policy Checks tab.

Additionally, the FirePass client-side component may log error messages to the trace log file that appear similar to the following example:

Fri Feb 29 19:05:07 2008 GMT (TUNNEL:6008,5076)  USSLChannel::beginConnection()   write return = 160
Fri Feb 29 19:05:07 2008 GMT (TUNNEL:6008,5076)  USSLChannel::beginConnection()   server return HTTP code=404
Fri Feb 29 19:05:07 2008 GMT (TUNNEL:6008,5076)  code=-404 (<html><H1>Error</H1>FirePass server could not handle the request<br>Reason: <STRONG>Invalid parameters.</STRONG></html>)
Fri Feb 29 19:05:07 2008 GMT (TUNNEL:6008,5076)  <html><H1>Error</H1>FirePass server could not handle the request<br>Reason: <STRONG>Invalid parameters.</STRONG></html>Fri Feb 29 19:05:07 2008 GMT (TUNNEL:6008,5076)

Note: The trace log file is located at %USERPROFILE%\Local Settings\Temp\logterminal.txt on Windows client systems.

F5 Networks Product Development tracked this issue as CR94318 and it was fixed in FirePass versions 6.0.3 and 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

This issue was fixed in cumulative HF-602-3 issued for FirePass version 6.0.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

Workaround

You can work around this issue by adding the hostname or IP address of the FirePass controller to the proxy server exceptions list in Internet Explorer.

For more information about configuring the proxy server exceptions list, refer to the following location:

http://www.microsoft.com/technet/prodtechnol/ie/ieak/techinfo/deploy/60/en/corpprox.mspx.
