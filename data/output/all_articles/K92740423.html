K92740423: Recover the root user password on BIG-IQ Virtual Edition

Type
Knowledge
Published
2021-11-15
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X, 7.X.X, 6.X.X
Source

Topic

You should consider using this procedure under the following condition:

  • You want to recover the root user password on a BIG-IQ Virtual Edition (VE) system.

Description

If you need to reset a lost or forgotten root user password on the BIG-IQ VE system, you need to first restart the BIG-IQ VE system to single-user mode.  Depending on the version of your BIG-IQ VE, you mount the file systems as writable using different methods prior to changing the root user password using the passwd command.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have console access to your BIG-IQ VE system.
  • You have command-line access to your BIG-IQ VE system.

Note: If you are running BIG-IQ in a high availability (HA) pair, you should reset the root password on the primary BIG-IQ. In a BIG-IQ HA configuration, every 30 seconds, the BIG-IQ system replicates configuration changes since the last synchronization from the primary device to the secondary device. 

Procedures

  • BIG-IQ 8.0.0 and later
  • BIG-IQ 7.1.0.x or earlier

BIG-IQ 8.0.0 and later

To reset the root user password on BIG-IQ 8.0.0 and later, perform the following procedure:

Impact of procedure: This procedure requires that you restart the BIG-IQ VE in single-user mode. While in this mode, the BIG-IQ VE is unable to manage BIG-IP devices.

  1. Restart the BIG-IQ VE in single-user mode. For information about restarting BIG-IQ 8.0.0 and later in single-user mode, refer to the procedure relevant to BIG-IQ 8.0.0 and later in K4178: Restarting the BIG-IP system in single-user mode (GRUB 0.97) or K14662: Restarting the BIG-IP system in single-user mode (GRUB2).

    After the system boots into single-user mode, the command prompt appears similar to the following example:

    switch_root:/#

  2. Verify the current mounting path for later reference by entering the following command:

    mount | grep /dev/mapper/vg--db

    The command should return an output similar to the following example (note that these directories are mounted in read-only mode by default in single-user mode):

    /dev/mapper/vg--db--vda-set.1.root on /sysroot type ext4 (ro,relatime,data=ordered)
    /dev/mapper/vg--db--vda-set.1._usr on /sysroot/usr type ext4 (ro,noatime,discard,data=ordered)

  3. Remount both the /sysroot and /sysroot/usr directories to read-write mode by entering the following commands:

    mount -o remount,rw /sysroot
    mount -o remount,rw /sysroot/usr

  4. Mount the /sysroot/config and /sysroot/var directories using the appropriate volume path:

    /dev/mapper/vg--db--vda-set.<volume ID>._config
    /dev/mapper/vg--db--vda-set.<volume ID>._var

    The volume path should follow that observed in step 2. Using the example output in step 2, you should mount these two directories with the volume path residing in volume ID 1 using the following commands:

    mount /dev/mapper/vg--db--vda-set.1._config /sysroot/config
    mount /dev/mapper/vg--db--vda-set.1._var /sysroot/var

  5. Verify the mounted directories are in read-write mode by entering the following command:

    mount | grep /dev/mapper/vg--db

    The command should return an output similar to the following example (note that these directories are now mounted in read-write mode):

    /dev/mapper/vg--db--vda-set.1.root on /sysroot type ext4 (rw,relatime,data=ordered)
    /dev/mapper/vg--db--vda-set.1._usr on /sysroot/usr type ext4 (rw,noatime,discard,data=ordered)
    /dev/mapper/vg--db--vda-set.1._config on /sysroot/config type ext4 (rw,relatime,data=ordered)
    /dev/mapper/vg--db--vda-set.1._var on /sysroot/var type ext4 (rw,noatime,discard,data=ordered)

  6. Change the root directory to the /sysroot directory by entering the following command:

    chroot /sysroot

    The command prompt should now change to the following:

    sh-4.2#

  7. Change the root user password by entering the following command:

    passwd root

    Enter your preferred root user password when prompted. When the root user password is reset successfully, the command should return an output similar to the following example:

    passwd.bin: all authentication tokens updated successfully.

  8. Force the system to re-label the file system on the next boot by entering the following command:

    touch /.autorelabel

  9. Exit the chroot environment by entering the following command:

    exit

  10. Exit the single-user mode environment and restart the system by entering the following command:

    exit

  11. After the BIG-IQ VE is restarted to its normal operating mode, log in to the root user account using the password you entered in step 7.

BIG-IQ 7.1.0.x or earlier

To reset the root user password on BIG-IQ 7.1.0.x or earlier, perform the following procedure:

Impact of procedure: This procedure requires that you restart the BIG-IQ VE in single-user mode. While in this mode, the BIG-IQ VE is unable to manage BIG-IP devices.

  1. Restart the BIG-IQ VE in single-user mode. For information about restarting BIG-IQ 7.1.0.x or earlier in single-user mode, refer to the procedure relevant to BIG-IQ 7.1.0.x or earlier in K4178: Restarting the BIG-IP system in single-user mode (GRUB 0.97) or K14662: Restarting the BIG-IP system in single-user mode (GRUB2).

    After the system boots into single-user mode, the command prompt appears similar to the following example:

    [@!:!:!] / #

  2. Mount all directories by entering the following command:

    mount -a

  3. Change the root user password by entering the following command:

    passwd root

    Enter your preferred root user password when prompted.

  4. Exit the single-user mode environment and restart the system by entering the following command:

    exit

  5. After the BIG-IQ VE restarts to its normal operating mode, log in to the root user account using the password you entered in step 3.
