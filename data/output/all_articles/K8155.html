K8155: Network Access component does not load proxy automatic configuration (PAC) script if script address contains a backslash character

Known Issue

This is the result of a known issue. If a user configures a proxy automatic configuration (PAC) script in the client browser, and the PAC script address contains a backslash ( \ ) character, the FirePass Network Access client component fails to load the PAC script when the user launches a Network Access connection. For example, the following PAC script address contains a backslash character and would be affected by this issue:

file://C:\proxy_config.pac

Additionally, when this issue occurs the Network Access client component logs an error message similar to the following example to the trace log on the client system:

Wed Dec 12 22:38:27 2007 GMT (DIALER:4088)  URLConnectEx::BeginConnection() - Invalid file (C:\ proxy_config.pac)
Wed Dec 12 22:38:27 2007 GMT (DIALER:1924)  CURDialer:WritePACFileFromURL:error Connect(file://C:\proxy_config.pac) failed

F5 Product Development tracked this issue as CR82700 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

Workaround

Users can work around this issue by changing each backslash ( \ ) character to a forward slash ( / ) character in the PAC script address.

For example:

file://C:\proxy_config.pac

Change the example PAC script address to appear similar to the following:

file://C:/proxy_config.pac

For more information about viewing or changing the Use automatic configuration script option in Microsoft Internet Explorer 5 through 7, refer to http://technet.microsoft.com/en-us/library/bb496443.aspx.

For more information about viewing or changing the Automatic proxy configuration URL option in Mozilla Firefox, refer to http://support.mozilla.com/kb/Options+window.

For more information about viewing or changing the PAC setting in other browsers, refer to your browser documentation.
