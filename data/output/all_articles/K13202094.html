Description

When querying a domain name that belongs to Unbound’s "Default Local-zones", also known as “Special-Use Domain Names,” through a DNS listener with cache enabled, the system returns an NXDOMAIN response. The DNS cache does not pass the queries to the DNS pool member or continue resolution.

The default zones include the following:

onion.RFC 7686
test.RFC 6761
invalid.RFC 6761
home.arpa.RFC 8375
resolver.arpaRFC 9462
service.arpaRFC 9665

Environment

  • BIG-IP v14.1.2.7 and later
  • DNS cache

Cause

Between Unbound 1.5.8 and 1.23.0, Unbound gradually began blocking these “Default Local-zones” for specific reasons.

In BIG-IP DNS cache, when "Answer Default Zones" setting is disabled, the cache is expected to override the default Unbound behavior and pass the DNS queries through. However, this setting does not work as expected due to known Bug ID2377749.

Recommended Actions

If you need to pass the queries to the DNS pool member, for a transparent cache, or continue resolution, for a resolver cache, configure the affected zone or record as a local zone in the DNS cache profile.

# tmsh modify ltm dns cache transparent DNSCache_Test local-zones { { name test. type type-transparent } }

# tmsh modify ltm dns cache transparent DNSCache_Test local-zones { { name _dns.resolver.arpa. type type-transparent } }

Additional Information

BIG-IP implements the same behavior change in the DNS Cache feature from the upstream Unbound software.
