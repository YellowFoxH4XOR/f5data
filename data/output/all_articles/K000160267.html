Description

Under rare situations, the sdmd daemon may restart continously.

The following error messages may be logged repeatedly.

In /var/log/ltm:

err sdmd[<PID>]: 018e001a:3: can't start extension: Can't start extension /usr/bin/nodejs /var/sdm/plugin_store/plugins/:Common:<example>/extensions/<example>, can't change the current directory to /var/sdm/plugin_store/plugins/:Common:<example>/extensions/<example>, No such file or directory

In /var/log/message:

notice logger[<PID>]: Started writing core file: /var/core/sdmd.bld0.0.11.core.gz for PID <PID>

Environment

  • BIG-IP
  • iRules Language Extensions (iRulesLX) provisioned

Cause

The specified directory used by sdmd is missing for unknown reasons, including the possibility of accidental deletion.

Recommended Actions

In a HA setup, if the peer device does not exhibit the same issue, copy the missing directories (or the entire /var/sdm directory) from the peer device. 

 

  1. On a healthy HA peer, archive the /var/sdm/ directory:

    cd /var

    tar -zcvf sdm.tar.gz sdm

  2. Transfer sdm.tar.gz to /var/ on the affected device.
  3. Extract the directory:

    cd /var

    tar -zxvf sdm.tar.gz

  4. Repeat the extraction on each relevant slot in a multi-slot environment.
  5. Start the service:

    clsh bigstart start sdmd

  6. Confirm that sdmd remains running without additional crashes or core dumps.

Avoid deleting /var/sdm/ during disk-space cleanup.
