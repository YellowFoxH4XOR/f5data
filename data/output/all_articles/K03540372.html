Known Issue

When the system rewrites the portal access content, the system selects the meta tag setting over the HTTP header setting.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a portal access profile.
  • HTML content processed by the portal access profile contains conflicting meta tag and HTTP header character set statements.

Impact

The system rewrites characters, using the meta tag character set statement.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The HTML content that depends on the HTTP header character set may appear garbled when the system rewrites the content and uses the meta tag character set.

Workaround

To work around this issue, you can create a custom iRule and apply it to the affected virtual server. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform the workaround during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > Create.
  3. In the Name box, type a name for the iRule.
  4. In the Definition box, paste the following iRule example text:

    when HTTP_REQUEST {
        if { [HTTP::path] ends_with "<content url>" } {
            set SETCHARS "text/html; charset=<prefered character set>"
            HTTP::header remove Accept-Encoding
            if { [HTTP::version] eq "1.1" } {
                if { [HTTP::header is_keepalive] } {
                    HTTP::header replace "Connection" "Keep-Alive"
                }
                HTTP::version "1.0"
            }
        } elseif { [info exists SETCHARS] } {
            unset SETCHARS
        }
    }
    when HTTP_RESPONSE {
        if { [info exists SETCHARS] && \
                [HTTP::header Content-Type] contains "text/html" } {
            # Collect no more than 1024 bytes.
            if { [HTTP::header exists "Content-Length"] and \
                    [HTTP::header "Content-Length"] > 0 and \
                    [HTTP::header "Content-Length"] <= 1024 } {
                HTTP::collect [HTTP::header Content-Length]
            } else {
                HTTP::collect 1024
            }
        } elseif { [info exists SETCHARS] } {
            unset SETCHARS
        }
    }
    when HTTP_RESPONSE_DATA {
        if { [info exists SETCHARS] } {
            set location [string first " content=\"$SETCHARS\"" [HTTP::payload]]
            set location [expr {$location + 10}]
            if { $location > 10 && \
                $location < [expr {[HTTP::payload length] - [string length $SETCHARS] - 1}]
            } {
                HTTP::payload replace $location [string length $SETCHARS] {text/html; charset=utf-8}
            }
            unset SETCHARS location
        }
    }

  5. Modify <content url> to match the path and content file of the affected content.
  6. Modify <prefered character set> to match the character set of the content.
  7. Click Finished.
  8. Navigate to Local Traffic > Virtual Servers > Virtual Server Lists.
  9. Click the name of the virtual server that is affected by this issue.
  10. Click the Resources tab.
  11. In the iRules section, click Manage.
  12. From the Available column, select the iRule you previously created.
  13. Click the << button to move the iRule into the Enabled column.
  14. Click Finished.
