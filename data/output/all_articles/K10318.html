K10318: Cache-Control headers may still be modified when the client cache policy is set to 'Do not change'

Known Issue

This is the result of a known issue. When the client cache policy is set to Do Not Change, the BIG-IP WebAccelerator should not modify any of the Cache-Control HTTP headers in the response from the origin webserver to the client. However, the BIG-IP WebAccelerator may modify or remove the Cache-Control, Pragma, and Expires HTTP headers even if the client cache policy is set to Do Not Change.

F5 Product Development is tracking this issue as ID 222320 (formerly CR117405).

Workaround

In BIG-IP WebAccelerator version 9.4.x, you can work around this issue by preserving the Cache-Control HTTP headers with a server-side iRule, then restoring them with a client-side iRule. The server-side iRule saves the original Expires, Cache-Control, and Pragma headers as new headers named OWS-Expires, OWS-Cache-Control, and OWS-Pragma. The client-side iRule restores the original header values, and optionally deletes the temporary headers. You must first create and apply the client-side iRule to your existing virtual server before modifying the system server-side iRule. To do so, perform the following procedures: 

Creating and applying the client-side iRule to your existing virtual server

  1. Log in to the BIG-IP Configuration utility.
  2. Browse to Local Traffic > iRules, and click Create.
  3. Enter a name for your iRule.

    For example:

    CacheControlHeaderRestore
  4. Copy the following code into the Definition field:

    when HTTP_RESPONSE {
       if {[HTTP::header exists "OWS-Cache-Control"]} {
          HTTP::header replace Cache-Control [HTTP::header value "OWS-Cache-Control"]
          # HTTP::header remove OWS-Cache-Control
       }
       if {[HTTP::header exists "OWS-Pragma"]} {
          HTTP::header replace Pragma [HTTP::header value "OWS-Pragma"]
          # HTTP::header remove OWS-Pragma
       }
       if {[HTTP::header exists "OWS-Expires"]} {
          HTTP::header replace Expires [HTTP::header value "OWS-Expires"]
          # HTTP::header remove OWS-Expires
       }
    }

    Note: To remove the temporary OWS-* headers, uncomment those commands by removing the leading # symbol.

  5. Browse to Local Traffic > Virtual Servers, and select the affected virtual server.
  6. Click Resources.
  7. Above the iRules field, click Manage.
  8. Select the iRule you just created from the Available list, and move it to the Enabled list by clicking the << button.

Modifying the system server-side iRule

  1. Log in to the BIG-IP command line.
  2. To back up the original /config/profile_base.conf file, type the following command:

    cp /config/profile_base.conf /config/profile_base.conf.sol10318
  3. Open the /config/profile_base.conf in a text editor.
  4. Locate the _sys_WA_serverside iRule, which begins at approximately line 1490 with the following line:

    rule _sys_WA_serverside {
  5. Add the following code to the bottom of the HTTP_RESPONSE event:  

       if { [HTTP::header value "Expires"] <= "0" } {
          set exp_time [HTTP::header value "Expires"]
       } else {
          set exp_time [ clock scan "[ HTTP::header value "Expires" ]" ]
       }
       if {$exp_time <= 0 } {
          set header_date "Thu, 01 Jan 1970 00:00:01 GMT"
          HTTP::header replace "Expires" $header_date
       }
       if {[HTTP::header exists Content-Type] && ([HTTP::header Content-Type] starts_with "text/html")} {
          if {[HTTP::header exists Cache-Control]} {
             HTTP::header insert OWS-Cache-Control [HTTP::header value "Cache-Control"]
          }
          if {[HTTP::header exists Pragma]} {
             HTTP::header insert OWS-Pragma [HTTP::header value "Pragma"]
          }
      }
  6. Save and close the profile_base.conf file.
  7. Reload the configuration by typing the following command:

    bigpipe load
  8. Clear the BIG-IP WebAccelerator cache by typing the following command:

    wa_clear_cache

Important: Clearing the cache on the BIG-IP WebAccelerator system will temporarily increase traffic to the origin web servers until the BIG-IP WebAccelerator system repopulates its cache.
