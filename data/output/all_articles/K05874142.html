Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file when the DoS Protection Profile is enabled.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured to use a DoS protection profile.
  • The Device ID feature is enabled in the DoS protection profile.
  • An HTTP/2 profile is configured on the same virtual server.

Impact

The BIG-IP system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is part of a redundant configuration, traffic fails over to a peer BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • The BIG-IP system logs a SIGSEGV to the /var/log/tmm file when TMM produces a core file and restarts.

Workaround

You may be able to work around this issue by removing the HTTP/2 profile in the affected virtual server. To do so, perform the following procedure:

Impact of workaround: The virtual server can no longer handle HTTP/2 requests after removing the HTTP/2 profile. The impact of the suggested mitigation depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.  

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the virtual server that is associated with the HTTP/2 profile you want to remove.
  4. Under HTTP/2 Profile, select None.
  5. Click Update.
