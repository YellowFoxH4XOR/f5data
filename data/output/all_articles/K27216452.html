Known Issue

Terminal Access Controller Access Control System Plus (TACACS+) system authentication leaks file descriptors.

This issue occurs when all of the following conditions are met:

  • You have a remote system authentication configured to use TACACS+.
  • You access the BIG-IP system using HTTP-based communication, such as the Configuration utility, iControl, or iControl REST.

Impact

In some circumstances, the leak may accumulate to the point that no file descriptors are available and administrative access using remote authenticated accounts is no longer possible. This also includes access from SSH and console. The root account, which always uses local authentication, is not affected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Administrative access to the system with remote authenticated accounts fails, and you observe messages that refer to "too many open files," including those similar to the following, in the /var/log/secure file:

    httpd[###]: PAM [error: /lib/security/pam_bigip_authz.so: cannot open shared object file: Too many open files].
    httpd[###]: PAM audit_open() failed: Too many open files

  • You cannot access the BIG-IP system using HTTP-based access methods.

Workaround

To work around this issue, F5 recommends that you only use SSH for administrative access and that you restart the httpd process when you need access to the Configuration utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Alternatively, you can work around by switching to another remote authentication option, such as LDAP, RADIUS, or Active Directory.

  1. Log in to SSH at the command line using the root account.
  2. Restart the httpd process by typing the following command:

    bigstart restart httpd
