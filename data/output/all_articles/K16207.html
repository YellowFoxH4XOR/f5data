Known Issue

If you perform an SNMP query on the ipCidrRouteTable object, the system may produce an error message.

This issue occurs when all of the following conditions are met:

  • The affected BIG-IP system has duplicated routes in the management route table. For more information refer to K16162: Duplicated routes may exist in the management route table.
  • You attempt to perform an SNMP query on the ipCidrRouteTable object.

Impact

The SNMP query will stop and generate an error message.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The SNMP query will stop and display an error message similar to the following example:

    Error: OID not increasing: IP-FORWARD-MIB::ipCidrRouteDest.10.1.1.0.255.255.255.0.0.0.0.0.0
    >= IP-FORWARD-MIB::ipCidrRouteDest.10.1.1.0.255.255.255.0.0.0.0.0.0

  • The snmpd process may generate a core file in the /shared/core directory.

Workaround

To work around the issue, you can remove the second entry of the duplicated management routes before you perform the SNMP query. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system command line prompt.
  2. Display the current management route table by typing the following command:

    ip route show

  3. Take note of the dual management route entries.

    For example, the command output in step 2 on a BIG-IP system with duplicated management routes may appear similar to the following example:

    10.1.1.0/24 dev eth0 proto kernel scope link src 10.1.1.114
    10.1.1.0/24 dev eth0 scope link src 10.1.1.114 metric 9

  4. Delete the second entry of the duplicated routes.

    For example, referencing the output example from step 3, the second entry would be as follows:

    10.1.1.0/24 dev eth0 scope link src 10.1.1.114 metric 9

    To delete the entry, type the following command:

    ip route del 10.1.1.0/24 dev eth0 scope link src 10.1.1.114 metric 9

    Note: The duplicated management routes will reoccur when you reboot the BIG-IP system.
