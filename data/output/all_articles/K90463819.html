Known Issue

Excessive traffic on the Message Passing Interface (MPI) channel may cause the Traffic Management Microkernel (TMM) to produce a core file on chassis systems.

This issue occurs when the following conditions are met:

  • Your BIG-IP system is a chassis-based platform.
  • The system is experiencing excessive internal traffic resulting from abnormal load distribution or excessive session database usage. The session database usage may be the result of module traffic or custom iRules that store session data.

Impact

Congestion on the MPI channel may cause message drops between blades and may also cause TMM to restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and systems configured as part of a high availability (HA) group may fail over.
  • TMM has restarted and a core file is created in the /var/core directory.
  • Your BIG-IP system logs error messages to the /var/log/tmm file that appear similar to the following example:

    notice MPI stream: connection to node <IP_addr> expired for reason: TCP retransmit timeout (tcp4.c:8714)
    notice MPI stream: connection with node <IP_addr> established
    notice MPI stream: connection to node <IP_addr> aborted for reason: TCP RST from remote

Workaround

To work around this issue, you can limit the amount of session data that is stored by iRules. If the affected virtual server is using iRules to create custom keys and data, you can partially mitigate this issue by consolidating multiple keys and using smaller key lengths as possible.
