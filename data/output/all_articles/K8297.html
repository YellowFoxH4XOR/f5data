Known Issue

This is the result of a known issue. When eventd has events in queue for processing, the sweeper timer does not correctly allow the queue to be swept. As a result, eventd consumes a large amount of CPU time while events are in queue.

Note: This behavior can occur during iControl communication, but does not occur when Enterprise Manager is used. Enterprise Manage controls eventd queues locally and terminates communication when completed.

F5 Product Development tracked this issue as CR87866, and it was fixed in BIG-IP 9.4.4. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator Release Notes.

Additionally, this issue was fixed in HOTFIX-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).
