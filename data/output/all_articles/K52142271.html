Known Issue

Configuration synchronization (ConfigSync) may fail validation when the BIG-IP APM configuration contains policy items with conflicting agents.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM systems are configured in a Sync-Failover device group.
  • An access policy item shares the same name on both systems but references a different agent on each system.
  • You perform a ConfigSync operation.
This issue may occur when you copy access policies on the BIG-IP APM system and then attempt to synchronize the configuration.  For example, performing the following sequence of events cause this issue:
  • You create a macro named example with one or more agents, add it to the access policy on one of the BIG-IP APM systems, and synchronize the configuration to the other BIG-IP APM system in the device group.  
  • On one of the BIG-IP APM systems, you modify the example macro and add another agent.  On the other BIG-IP APM system, you create a copy of the access policy.
This results in conflicting policy items on the BIG-IP APM systems similar to the following example configuration:

BIG-IP APM1

apm policy policy-item /Common/example_act_message_box_1 {
    agents {
        /Common/mac_act_message_box_1_ag {

BIG-IP APM2

apm policy policy-item /Common/example_act_message_box_1 {
    agents {
        /Common/mac_act_message_box_ag_1 {

The macro is modified on BIG-IP APM1 and the access policy is copied on BIG-IP APM2.  The resulting policy item name is example_act_message_box_1 on both BIG-IP APM systems, but they reference different agents.  This causes the ConfigSync process to fail due to validation errors.
 

Impact

You are unable to synchronize the configuration in the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system generates an error message similar to the following example when it attempts to synchronize the configuration:

    err mcpd[9221]: 01070734:3: Configuration error: DB validation exception, unique constraint violation on table (access_policy_item_agent) object ID (/Common/example_act_message_box_1 /Common/example_act_message_box_1_ag). A duplicate value was received for a non-primary key unique index field. DB exception text (Cannot update_indexes/checkpoint DB object, class:access_policy_item_agent status:13)
     
  •  ConfigSync fails.

Workaround

To work around this issue, you can delete the access policies containing the policy items referenced in the error message on the target system, then perform a ConfigSync to overwrite the configuration . To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility on the ConfigSync target BIG-IP APM system.
  2. Navigate to Access > Profiles / Policies.

    Note: for BIG-IP 11.6.x - 12.x, navigate to Access Policy > Access Profiles.

  3. Select the check boxes next to all access policies containing the policy items referenced in the error message.
  4. Click Delete and confirm the deletion.
  5. Navigate to Device Management > Overview.
  6. Under Device Groups, click the affected device group.
  7. Under Devices, click the source BIG-IP APM system for the ConfigSync.
  8. Click Push the selected device configuration to the group.

    Note: For BIG-IP 11.6.x - 12.x, click Sync Device to Group and select the Overwrite Configuration check box. 

  9. Click Sync.
  10. (BIG-IP 13.x and later only) Click Sync and Overwrite to confirm overwrite of the configuration on the target BIG-IP APM system.
