Known Issue

An imported external monitor may erroneously mark resources down.

This issue occurs when all of the following conditions are met:

  • You created or modified the external monitor using an editor that added trailing CR/LF new line control characters.
  • You used the BIG-IP Configuration utility to import the monitor.

Impact

The system may erroneously mark down resource objects assigned with the affected monitor and may not direct traffic to the expected resources.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Resource objects assigned with the affected monitor may fail to execute or interpret the scripted language executable and result in the monitor erroneously marking the resource object down.
  • The affected monitor marks pool members down and the system logs messages to the /var/log/ltm file that appear similar to the following example:

    notice mcpd[2964]: 01070638:5: Pool member <ServerIP_port> monitor status down

  • The external monitor script file imported into the BIG-IP system is not adapted to the UNIX host file representation.

    An example of content in an affected file that contains extra trailing CR/LF new line control characters may appear similar to the following example:

    #!/usr/bin/perl^M

    ^M

    print "Hello World\n";^M

    ^M

Resolution

Status

F5 Product Development has assigned ID 401443 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Type of fixFixes introduced inRelated articles
ReleaseNoneNone
Point release/hotfixNoneNone

Workaround

To work around this issue, you can use one of the following two procedures:

  • Use the BIG-IP Configuration utility to load and re-save the external monitor (11.5.0 and later only)
  • Use the vi editor to set the file format to UNIX file representation

Use the BIG-IP Configuration utility to load and re-save the external monitor (11.5.0 and later only)
Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility as an administrative user.
  2. Navigate to System > File Management > External Monitor Program File List.
  3. Open the external monitor you want to fix.
  4. Click Update.

    Repeat these steps for all external monitors.

Use the vi editor to set the file format to UNIX file representation

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line interface.
  2. Use the vi editor to modify the affected external monitor script file using the following command syntax:

    vi /config/filestore/files_d/<Partition>/external_monitor_d/<External-Monitor-Filename>

    For example, to modify an external monitor file in the /Common partition named extmon_sol14271, type the following command:

    vi /config/filestore/files_d/Common_d/external_monitor_d/\:Common\:extmon_sol14271

  3. While in the vi editor mode, set the file format to the UNIX file representation by typing the following command:

    :set fileformat=unix

    Note: The command requires you to press the colon (:) symbol, enter the string set fileformat=unix and press the Enter key.

  4. To save and exit the vi editor, type the following command:

    :wq!

    Note: The command requires you to press the colon (:) symbol, enter the string wq! and press the Enter key.
