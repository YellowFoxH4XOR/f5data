Issue

Error Message

01490000:3: AccessPolicyD.cpp func: "process_request()" line:<line_number> Msg: EXCEPTION AccessPolicyD.cpp line:<line_number>  function: writeSessionVarToSessionDb - Error:Set pipeline: mc_finish_set_pipeline failed

In this error message, note the following:

  • <line_number> is the line number of the code that triggered the error.

For example:

err apd[16902]: 01490000:3: AccessPolicyD.cpp func: "process_request()" line: 820 Msg: EXCEPTION AccessPolicyD.cpp line:1765  function: writeSessionVarToSessionDb - Error:Set pipeline: mc_finish_set_pipeline failed

Message Location

You may encounter this message in the following locations:

  • The /var/log/apm file
  • When you view a report for a particular BIG-IP APM session in the BIG-IP Configuration utility.

Description

This message occurs when the following condition is met:

  • The amount of data the system is saving to the session database for a single session variable exceeds 64KB.

Impact

While attempting to complete access policy evaluation, users receive an HTTP 500 error message in their browser, the BIG-IP APM system deletes their session, and they are denied access to the BIG-IP APM protected services.

Recommended Actions

A common cause of this error is an AAA session variable larger than 64 KB. You can modify any AD/LDAP query agents in the access policies so they retrieve only the user attributes required to complete the access policy evaluation. To do so, perform the following procedure:

Impact of procedure: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to the Access Policy List:

    For 13.x and later, navigate to:  Access > Profiles / Policies

    For 12.x and earlier, navigate to:  Access Policy > Access Profiles

  3. Click Edit for the affected Access Policy.
  4. Locate and click the affected AD or LDAP query agent in the policy flow.
  5. Click Add new entry.
  6. Type the AD/LDAP attribute name (with correct uppercase/lowercase syntax) into the field that appears.

    Repeat this step for each required AD/LDAP attribute.

  7. To save the AD/LDAP Query agent configuration change, click Save.

    Repeat steps 4-7 for each AD/LDAP Query agent in the policy.

  8. Click Apply Access Policy.
