Known Issue

This is the result of a known issue. If a third party SSL certificate that is signed by an external certificate authority (CA) is used to authenticate iQuery connections between BIG-IP systems, the value of the Big3d.CertificateDepth variable is not always honored. When this issue occurs, the systems cannot verify the certificates required for authentication. As a result, objects hosted by the affected BIG-IP system will be marked as unavailable.

You can verify this behavior by examining an iqdump of the traffic between the BIG-IP systems for the following error message:

12848:error:14094418:SSL routines:SSL3_READ_BYTES:tlsv1 alert unknown ca:s3_pkt.c:1052:SSL alert number 48

F5 Product Development tracked this issue as CR80402 and it was fixed in BIG-IP version 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Note: For more information about using third party SSL certificates to authenticate between BIG-IP systems, refer to K7717: The BIG-IP GTM and Link Controller support for third party SSL certificates.

Workaround

You can work around this issue by configuring the big3d agent to correctly traverse the required depth into the CA certificate chain, which allows the BIG-IP to verify third party SSL certificates. To do so, perform the following procedure on each system participating in iQuery conversations authenticated using third party SSL certificates:

  1. Log in to the BIG-IP command line.
  2. Change directories to the /etc/bigstart/scripts directory by typing the following command:

    cd /etc/bigstart/scripts
  3. Make a copy of the big3d script file by typing the following command:

    cp big3d big3doriginal
  4. Using a text editor, edit the big3d script file.
  5. Locate the following line:

    exec /usr/sbin/big3d
  6. Change the line to appear similar to the following example:

    exec /usr/sbin/big3d -c <certificate_depth> -c <certificate_depth>

    Note: You must specify the -c <certificate_depth> option twice. For more information, refer to K7548: The big3d agent -c option fails to load the certificate level.

    The value of <certificate_depth> is a number from 0 (zero) to 9, which represents the depth to which the CA certificate chain will be traversed when verifying certificates.

    Note: For a BIG-IP to verify only self-signed certificates, <certificate_depth> may be set to the default value of zero. For a BIG-IP to verify certificates that are directly signed by a root CA, the value must be at least 1. For BIG-IP to verify certificates signed by a CA whose certificate is signed by a root CA, the value must be at least 2. If you are unsure about the depth of your CA chain, set the value to 9.
  7. Save the changes to the file.
  8. Set the Big3d.CertificateDepth bigdb variable to the same value as configured in Step 6 by typing the following command:

    b db Big3d.CertificateDepth <value>
  9. Restart the big3d agent by typing the following command:

    bigstart restart big3d

Repeat this procedure for each affected BIG-IP system.
