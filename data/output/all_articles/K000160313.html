K000160313: SNMP Fails to Retrieve cpuTotal Statistics on F5OS Partitions

Type
Support Solution
Published
2026-03-12
Updated
2026-03-12
Applies to
  • F5OS
  • F5OS-C: 1.8.2
Source
https://my.f5.com/manage/s/article/K000160313

Description

SNMP walk operations targeting cpuTotal statistics (such as cpuTotal1minAvg and cpuTotal5minAvg) on F5OS partitions fail to return data. The error message observed is:

  • .1.3.6.1.4.1.12276.1.2.1.1.2.1.4 = No Such Instance currently exists at this OID"
  • Other SNMP OIDs continue to respond normally, and the issue is isolated to the cpuTotal OIDs.

Environment

F5OS

SNMP

Cause

The platform-stats-bridge container may intermittently fail to fetch or parse the required CPU statistics, resulting in missing SNMP data for the affected OIDs. This is a rare occurrence and may not persist after a service restart.

Answer/Recommended Actions

To resolve the issue and restore SNMP polling for cpuTotal statistics:

  1. Log in to the F5OS-C system controller command line as the root user.
  2. Restart the affected services for the impacted partition(s) using the following commands:
    • docker restart partition<n>_snmpd
    • docker restart partition<n>_platform-stats-bridge
    • Replace <n> with the partition ID (e.g., 1, 2, etc.).
  1. After restarting these services, verify that SNMP walk operations for cpuTotal OIDs return the expected data.

Note: Restarting these containers is not traffic impacting.

Monitor the system to ensure the issue does not recur. If the problem persists, further investigation may be required.
