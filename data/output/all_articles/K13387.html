Issue

Old Behavior

Previously, in BIG-IP 9.x through 10.x, Traffic Management Microkernel (TMM) memory allocation was limited to blocks of 4 MB or smaller.

New Behavior

In versions starting from BIG-IP 11.0.0, TMM can allocate larger blocks of memory, as detailed below.

               - 10.x.x  :    4 MB (  4,194,304 bytes)
        11.0.0 - 11.3.0  :   32 MB ( 33,554,432 bytes)
        11.4.0 - 14.1.x  :   64 MB ( 67,108,864 bytes)
        15.0.0 - 17.0.0  :  256 MB (268,435,456 bytes)

Impact

This larger allocation limit causes a congruent increase in the maximum size of a Tool Command Language (TCL) variable that may be set in an iRule.
Note: TCL has an 8-byte overhead, so the actual maximum size is 8 bytes less than the values listed above.
 

Recommended Actions

While the larger variable size limit may provide increased flexibility in iRule design, you should only use large variable sizes with extensive testing. The additional resources needed to process such variables may have a detrimental effect on system performance.

Additionally, the TCP::collect or HTTP::collect commands should not be used with unbounded values or variables that exceed the relevant limits stated above.
