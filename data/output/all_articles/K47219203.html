Known Issue

The BIG-IP ASM bd process may exit and restart when parsing XML traffic under low memory conditions.

This issue occurs when all of the following conditions are met:

  • The security policy is configured with an XML profile.
  • Your BIG-IP ASM system is consuming much or all of the available system memory.

Although rare, the bd process can exit when all available memory for the XML parser is exhausted.

Impact

The BIG-IP ASM system fails to process traffic temporarily while the bd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H584734 on the Diagnostics > Identified > High|Medium screen.
  • Your BIG-IP ASM system logs messages to the /var/log/asm file that appear similar to the following example:

    emerg dcc[17189]: 01310003:0: ASM out of memory error: event code X239 Exceeded maximum memory assigned for XML/JSON processing

  • A bd core file is generated to the /shared/core/ directory.

Workaround

You may be able to work around this issue by increasing the value for the total_xml_memory system variable. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure requires restarting the asm service, which will cause a brief traffic disruption.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Options > Application Security > Advanced Configuration > System Variables.
  3. Enter the desired value in the total_xml_memory variable box.
  4. Click Save.
  5. Log in to the BIG-IP ASM command line.
  6. Restart the asm service by typing the following command:

    tmsh restart /sys service asm
