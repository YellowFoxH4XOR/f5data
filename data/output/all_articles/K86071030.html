K86071030: iRule to log connection on SSL/TLS versions with client IP address

Type
Support Solution
Published
2022-02-24
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.2
Source
https://my.f5.com/manage/s/article/K86071030

Description

This articles describes an iRule used to log the connection made on specific SSL/TLS version with client IP address. 
This contains methods for logging connections for both successful and failed SSL connections. 

Environment

  • HTTPS virtual server
  • SSL Offload
  • iRule

Cause

None

Recommended Actions

Impact of procedure: This procedure should only be used on a production system for testing or troubleshooting scenarios. Depending on your environment, using an iRule to continually log SSL/TLS connection information may cause an increased load on the BIG-IP system and result in instability.

1. Below iRule can be added to log the SSL/TLS cipher version along with cipher name and client IP address connecting to virtual server on HTTPS.

Example stanza:
when CLIENTSSL_CLIENTHELLO {
    log local0. "From IP: [IP::client_addr] - cipher: [SSL::cipher name] - version: [SSL::cipher version]"
}

2. Optionally, in order to log the line informing the connection is successful you can use the following iRule example: 

when CLIENTSSL_HANDSHAKE {
    if { ( [SSL::cipher version] equals "TLSv1" ) }
    {
        log local0. "DETECTED-TLSv1.0-CONNECTION - LOG_SSL_LEVEL - Client: [IP::client_addr] successfully negotiates [SSL::cipher version] - [SSL::cipher name] - [SSL::cipher bits] - For the VIP - [virtual name]"
        }
    elseif { ( [SSL::cipher version] equals "TLSv1.1" ) }
    {
        log local0. "DETECTED-TLSv1.1-CONNECTION - LOG_SSL_LEVEL - Client: [IP::client_addr] successfully negotiates [SSL::cipher version] - [SSL::cipher name] - [SSL::cipher bits] - For the VIP - [virtual name]"
    }
    elseif { ( [SSL::cipher version] equals "TLSv1.2" ) }
    {
        log local0. "DETECTED-TLSv1.2-CONNECTION - LOG_SSL_LEVEL - Client: [IP::client_addr] successfully negotiates [SSL::cipher version] - [SSL::cipher name] - [SSL::cipher bits] - For the VIP - [virtual name]"
    }
}

Important: Above iRules will not log the connection which are failed due to unsupported SSL/TLS versions in case where old SSL/TLS versions like TLSv1 or TLSv1.1 are disabled in ClientSSL profile on virtual server. The reason its not logging the log like from iRule when we access the VS on the disabled TLS versions (TLSv1 & TLSv1.1), because the iRule is not getting fired because the handshake is denied at the protocol level before the iRule fires. 

3. In the case where you need to see the client IP address communicating on old SSL/TLS versions or the versions which are disabled in Clientssl profile, enable SSL logging to debug in the Configuration utility (gui)  System > Logs > Configuration > Options > SSL > Debug.

Once this is configured, the failed SSL communication logs will look like below under  /var/log/ltm file:
 01260009:4: 10.1.115.236:41334 -> 10.1.116.75:443: Connection error: ssl_hs_rxhello:10611: alert(70) unsupported version
 01260013:4: SSL Handshake failed for TCP 10.1.115.236:41334 -> 10.1.116.75:443
