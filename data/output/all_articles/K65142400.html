Issue

Error Message

Access was denied by the access policy.

Message Location

You may encounter this message in the following locations:

  • Client-side browser or client access software.

Description

This message occurs when any of the following conditions are met:

  • The user's access session fails to meet an access policy configuration item settings for server-side checks.
  • The user's access session fails to meet an access policy configuration item setting for client-side checks.
  • Authentication fails when authentication encounters an authentication issue that is not related to credentials or communication with the authentication server.
  • Authentication uses a BIG-IP APM local user database and the system encounters one of the following issues:
    • An access-policy-expression-based check fails.
    • Users are imported into the local user database multiple times.
    • The database is corrupted.

Impact

When the BIG-IP APM system determines that an access session request does not meet the configured access policy item for server-side or client-side checks and the fallback branch of the access policy is set to Deny, the following generic error is displayed on the connecting client's device, often with a secondary error message, and the user's access session fails to establish:

Access was denied by the access policy.

Recommended Actions

Viewing additional information for a failed access session

To view information for a failed access session you can review the log messages in the /var/log/apm log file using the user's session ID of the failed session.

Using the information from the log messages you can review the access policy configuration and the affected user device to determine why the user was denied an access session.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Alternatively you can view user session information through the BIG-IP APM Configuration utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Access > Overview > Access Reports.
  2. For Report Parameters, select Cancel.
  3. For All Sessions, select Session Details.
  4. For SESSION_ID, enter the failed access session ID.
  5. Select Run Report.
