Known Issue

A BIG-IP GTM iRule with the cname command may result in an error when the time-to-live value is specified.

For example, the following BIG-IP GTM iRule called my_rule is configured to use the cname command with a time-to-live value of 120 seconds.

gtm rule my_rule {
when DNS_REQUEST {
cname host2.example.com 120
}
}

When the cname command is used without specifying a time-to-live value, the default time-to-live is zero.

Impact

The iRule using the cname command with a time-to-live value will result in an error.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • On the Configuration utility, you may observe error message that appear similar to the following example:

    01070151:3: Rule [my_rule] error:
    line 2: [wrong # args] [cname host2.example.com 120]
  • In the /var/log/ltm file, you may observe error messages that appear similar to the following example:

    01070151:3: Rule [my_rule] error: line 2: [wrong # args] [cname host2.example.com 120]

Workaround

To work around this issue, you can use the check none and check strict directives in the affected iRule. To do so, perform the following procedure:

Impact of workaround: The check none directive is to stop the iRule syntax verification. Additionally, the check strict directive should be used following the event to resume iRule syntax verification.

  1. Log in to the Configuration utility.
  2. Click Global Traffic.
  3. Click iRules.
  4. Select the name of the affected iRule.
  5. In the Definition text box, modify the iRule by inserting the check none directive before an event using the cname command. In addition, insert the check strict directive after the event if there are other events in the iRule.

    For example, before modifying the affected iRule, it may appear as follows:

    when DNS_REQUEST {
    cname host2.example.com 120
    }

    After including the check none and check strict directives, the affected iRule may appear as follows:

    check none
    when DNS_REQUEST {
    cname host2.example.com 120
    }
    check strict
