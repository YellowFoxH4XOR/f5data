Known Issue

BIG-IP Virtual Edition (VE) may fail to process traffic after deployment on a VMware ESXi 6.5 host.

This issue occurs when all of the following conditions are met:

  • You deploy a BIG-IP VE instance on VMware ESXi hypervisor version 6.5.
  • BIG-IP VE is configured to use the vmxnet3 network interfaces driver.

    Note: BIG-IP VE uses the VMXNET3 network interface driver by default.

Impact

BIG-IP VE system fails to process traffic through non-management interfaces.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP VE does not process traffic when deployed on a VMware ESXi 6.5 hypervisor.

Workaround

To work around this issue, you can configure BIG-IP VE to use the SOCK driver instead of the default VMXNET3 driver. To do so, perform the following procedure:

Impact of workaround: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the Traffic Management Microkernel (TMM). Network traffic is disrupted while TMM restarts.

Important: The /config/tmm_init.tcl file is not included with a configuration synchronization (ConfigSync); you must perform the procedure on each device individually. For members of a high availability (HA) device group, you must perform the following procedure on each member of the device group. Additionally, the procedure must be performed for each boot location you waht to boot to.

  1. Log in to the BIG-IP command line.
  2. Enter the following command for your version to append the line to the /config/tmm_init.tcl file:

    Note: If the /config/tmm_init.tcl file does not already exist, this command creates it and adds the following line, depending on version.

    echo "device driver vendor_dev 15ad:07b0 sock" >> /config/tmm_init.tcl

  3. Restart TMM to reload the driver by entering the following command:

    bigstart restart tmm

  4. After TMM restarts, confirm the driver in use by examining the output of the following command:

    tmctl -d blade tmm/device_probed

    Output appears similar to the following example:

    tmctl -d blade tmm/device_probed
    pci_bdf      pseudo_name type      available_drivers     driver_in_use
