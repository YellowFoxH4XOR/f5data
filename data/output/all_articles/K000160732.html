K000160732: Even after changing the password using Force Password Change, you can still log in with the pre-change password on the next login.

Type
Support Solution
Published
2026-04-15
Updated
2026-04-15
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000160732

Description

With Force Password Change enabled, even if you change the password at login, you can log in with the initial password on the next login and are prompted again to change the password.

 

During a password change, messages like the following are logged to /var/log/apm.

 

Example of log output:

Mar 4 09:29:23 BIGIP.local notice localdbmgr[20045]: 01ab0105:5: Cannot map session val to user data [err = -1]

Mar 4 09:29:23 BIGIP.local notice localdbmgr[20045]: 01ab0117:5: Could not persist the local user (/Common/cp-local-user-db:username) changes to the database. The changes will be persisted during the regular memcache to database sync cycle.Error code (-1)

 

Environment

  • BIG-IP APM
  • Force Password Change

 

Cause

It is possible that the localdb is not functioning properly.

 

Recommended Actions

Please restart the localdbmgr daemon, which is responsible for managing the localdb, and check whether this resolves the issue. You can restart the localdbmgr daemon by running the following command.

 

# bigstart restart localdbmgr

 

Additional Information

If the daemon is restarted while credentials (user ID/password) are being entered on the VPN login screen, authentication may fail or be impacted.

Therefore, we recommend performing the restart during a maintenance window or during periods of low traffic.
