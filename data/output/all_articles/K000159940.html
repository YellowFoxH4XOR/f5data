Description

A BIG-IP ASM system experiences intermittent High Availability (HA) failover events caused by critical ASM processes being terminated due to system memory exhaustion. The following symptoms and log messages may be observed like 

  • Intermittent HA failover events
  • Out of Memory (OOM) killer messages in /var/log/kern.log`, such as:

    Out of memory: Kill process 26145 (bd) score 49 or sacrifice child

    Killed process 26145 (bd) total-vm:2623704kB, anon-rss:564596kB, file-rss:3208kB, shmem-rss:7780kB

  • ASM processes (bd, pabnagd) crashing or restarting

System logs indicating HA state changes:

HA proc_running bd fails action is go offline and down linksSod requests links down

Offline for traffic group traffic-group-1

Environment

  • Physical or virtual appliances with limited RAM (e.g., 10 GB or less)
  • Multiple BIG-IP modules provisioned (5 or more modules)
  • Default or low values for:
    • provision.extramb (default)
    • provision.tomcat.extramb (default)
    • provision.restjavad.extramb (default)
  • High Availability (HA) configuration

Cause

Insufficient system memory due to over-provisioning of BIG-IP modules relative to available hardware resources. When the system exhausts available memory, the Linux OOM (Out of Memory) killer terminates critical ASM processes such as bd and pabnagd. This triggers the Switch-Over-Daemon (SOD) to detect process failures and initiate HA failover events to protect traffic processing.

Recommended Actions

  1. Review and reduce module provisioning:
    • Disable or deprovision non-essential modules (e.g., AVR, APML) to free up memory
    • Navigate to System > Resource Provisioning in the Configuration utility
    • Set unused modules to None
  2. Increase management memory allocation for below db variables according to the recommendation from K26427018 and K000133258:
    • provision.extramb 
    • provision.tomcat.extramb 
    • provision.restjavad.extramb

    Execute the following commands via TMOS Shell (tmsh):

    tmsh modify sys db provision.extramb value <MB>

    tmsh modify sys db provision.tomcat.extramb value <MB>

    tmsh modify sys db provision.restjavad.extramb value <MB>

    Important: These changes will cause TMM to restart and may trigger an HA failover. Perform during a scheduled maintenance window.

Additional Information

  • The OOM killer is a Linux kernel mechanism that terminates processes when the system runs critically low on memory to prevent complete system failure
  • Over-provisioning modules on hardware with limited resources can lead to system instability and unexpected failover events
  • The bd process is a critical ASM daemon responsible for security policy enforcement and traffic processing
  • When SOD detects that a critical process like bd has failed, it instructs the BIG-IP to go offline and bring links down, triggering failover in HA configurations
  • The bd process will automatically restart after being killed, and the system will return to active/standby status once the process is healthy
  • Management provisioning recommendations based on K26427018:
    • For units with 2+ provisioned modules running BIG-IP 14.1 or later: select Large for Management (MGMT)
    • For units running BIG-IP 15.x or later: select Large for Management (MGMT)
    • For units with 3+ modules on BIG-IP 15.x or later: set provision.extramb to 2048 MB or higher
