Topic

If a server defined in a BIG-IP DNS configuration is a BIG-IP system, such as a BIG-IP LTM, the BIG-IP DNS system can delegate certain probe tasks to that system, rather than conducting the probes itself.

Description

Probe delegation allows the BIG-IP DNS system to efficiently gather information on the availability of the network resources it manages. Each BIG-IP system is configured by default with the ability to conduct the following probes:
  • Service Check
  • Path
  • SNMP

However, in some environments, the BIG-IP DNS system may delegate probing tasks to the big3d agent on a BIG-IP system which is incapable of completing them successfully, due to environmental contraints.. For example, network ACLs, or intenal routing specific to particular data centres, which prevent the BIG-IP from communicating with the target device. As a result, a pool member's status may be martked unavailable, because the probe was not able to complete successfully when originating from the selected device.

Note: The BIG-IP DNS may delegate probing tasks to any BIG-IP server that is capable of performing that type of probe. With no configured contrains, and depending on load and availability, different BIG-IP systems may be chosen to probe a given remote system at different times.

The most common way to address this issue is by creating and using Proper Pools to specify, at the data-center, gtm pool, or gtm server virtual server levels, which gtm servers objects may be used to perform probing of those targets. For more information prober-pools, refer to K08433560

Note: The bigip and bigip_link monitor types are an exception to the rule, and do not consider prober-pools when selecting a big3d agent, as the agent selected will always be a member of the HA device-group containing the target virtual-server.

Alternatively, by limiting the permitted prober types  for a given BIG-IP server object, you can restrict which big3d agent(s) the BIG-IP DNS system may delegate monitoring tasks to. To do so, perform the following procedure:

BIG-IP DNS 11.5.0 and later

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.
  3. Under Name, select the BIG-IP server object you want to modify.
  4. In the Configuration section, select Advanced from the drop-down menu.
  5. Configure one or more of the following iQuery Options:
  • To disable delegation of service checks (monitors), clear the Service Check check box

    Note: If Service Check is disabled on all BIG-IP members of the iQuery group, then the following symptoms will develop
    1. gtmd cannot be expected to perform its own monitoring any big3d is available. The resources can be marked down with the following diagnostics:

    Mon DD HH:MM:SS example-bigip2 notice gtmd[12846]: 011ae108:5: Prober Selection: no preferred or fallback probers are available
    Mon DD HH:MM:SS example-bigip2 notice gtmd[12846]: 011ae108:5: Prober Selection: no preferred or fallback probers are available

    2. The behaviour outlined in p. 1 above does not apply to resources directly configured on iQuery members with monitor set to bigip or bigip_link. Even if Service Check is disabled, these members still can use and report their other monitoring performed independently of the GTM/DNS functionality

     

  • To disable delegation of path probes, clear the Path check box
  • To disable delegation of SNMP probes, clear the SNMP check box
