Issue

Error Message

From the BIG-IP command line or TMOS shell (tmsh):

<path to command>: <path to command>: cannot execute binary file

From the iControl REST interface:

"commandResult": "<path to command>: <path to command>: cannot execute binary file\n"

In this error message, note the following:

  • <path to command> is the full path of the command on the file system.

For example:

From the BIG-IP command line or tmsh:

/bin/date: /bin/date: cannot execute binary file

From the iControl REST interface:

"commandResult": "/bin/date: /bin/date: cannot execute binary file\n"

Message Location

You may encounter this message in the following locations:

  • BIG-IP command line
  • tmsh
  • iControl REST interface

Description

This message occurs when all of the following conditions are met:

  • The -c option is omitted when the Advanced Shell (bash) interpreter is invoked.
  • The file argument to the bash interpreter is a binary file, such as a Linux command.

If there is no -c option, bash expects the first argument to be a shell script, and when the argument is a Linux command such as date or grep, you are telling bash to run a binary file which it cannot do, and it raises an error. You are most likely to encounter this error when invoking bash using tmsh or iControl REST. For example, the following POST to the /mgmt/tm/util/bash URI lacking the -c option will trigger the error:

# curl -sku 'admin:admin' -H 'Content-Type: application/json' -X POST -d '{"command": "run", "utilCmdArgs": "date"}' https://localhost/mgmt/tm/util/bash | jq .
{
"kind": "tm:util:bash:runstate",
"command": "run",
"utilCmdArgs": "date",
"commandResult": "/bin/date: /bin/date: cannot execute binary file\n"
}

Impact

The command you are attempting to run is not run.

Recommended Actions

Ensure you include the -c option when running a Linux command by invoking the bash interpreter.

This example demonstrates the correct usage of the -c option with tmsh:

# run /util bash -c date
Mon Jan 27 17:45:47 PST 2020

If the full Linux command string you want to run has spaces, you must enclose the command in quotes.

For example:

# run /util bash -c "date -u"
Tue Jan 28 01:57:50 UTC 2020

This example demonstrates the correct usage of the -c option with iControl REST:

# curl -sku 'admin:admin' -H 'Content-Type: application/json' -X POST -d '{"command": "run", "utilCmdArgs": "-c date"}' https://localhost/mgmt/tm/util/bash | jq .
{
  "kind": "tm:util:bash:runstate",
  "command": "run",
  "utilCmdArgs": "-c date",
  "commandResult": "Mon Jan 27 17:59:04 PST 2020\n"
}

If the full Linux command string you want to run has spaces, you must enclose the command in quotes and escape them.

For example:

# curl -sku 'admin:admin' -H 'Content-Type: application/json' -X POST -d '{"command": "run", "utilCmdArgs": "-c \"date -u\""}' https://localhost/mgmt/tm/util/bash | jq .
{
  "kind": "tm:util:bash:runstate",
  "command": "run",
  "utilCmdArgs": "-c \"date -u\"",
  "commandResult": "Tue Jan 28 01:59:57 UTC 2020\n"
}
