Description

F5 Distributed Cloud Customer Edge (CE) sites can be deployed on KVM-based hypervisors using available CE images. Proxmox Virtual Environment (VE) is an open-source enterprise virtualization platform built on KVM and Linux Containers. Deploying F5 Distributed Cloud CE sites on Proxmox VE using Terraform automation is not explicitly documented in the standard F5 Distributed Cloud deployment guides, and the specific steps for creating CE templates, configuring virtual networks, and automating multi-node deployments on Proxmox require additional guidance.

  • How can an F5 Distributed Cloud Secure Mesh Site be deployed on Proxmox VE?
  • How can an F5 Distributed Cloud AppStack Cluster be deployed on Proxmox VE?
  • How is an F5 XC CE template created on Proxmox VE from the KVM image?
  • How is Terraform used to automate the deployment of CE sites on Proxmox VE?
  • How are virtual networks configured on Proxmox VE for CE SLO and SLI interfaces?
  • How can the number of AppStack worker nodes be scaled after initial deployment?

Environment

  • F5 Distributed Cloud (SaaS)
  • Customer Edge (CE) software — Secure Mesh Site and AppStack personas
  • Proxmox Virtual Environment (VE) — single server or cluster (example uses a 3-node cluster)
  • KVM-based CE image (RHEL qcow2 format) sourced from https://docs.cloud.f5.com/docs/images
  • Terraform CLI with Telmate Proxmox Provider
  • F5 Distributed Cloud API credentials (API Token or P12 file)
  • Linux Bridge virtual networks on Proxmox VE:
    • vmbr0 — Internet-facing network for CE SLO interfaces
    • vmbr1 or vmbr0 with VLAN tag (e.g., VLAN 100) — internal network for CE SLI interfaces and AppStack node connectivity
  • Minimum hardware requirements:
    • 24 vCPU total (9 nodes × 4 vCPU each)
    • 144 GB RAM total (9 nodes × 16 GB each)
    • ISO file storage for cloud-init disks (local or CephFS)
    • Block storage for VM disks and templates (local-lvm or Ceph pool)

Cause

None

Answer/Recommended Actions

Deploy a redundant 3-node Secure Mesh Site and a 6-node AppStack Cluster on Proxmox VE using Terraform automation. The Secure Mesh Site provides SLO connectivity to the internet and SLI connectivity (including DHCP services) to the AppStack nodes on an isolated internal network.

Logical Topology

----------------- vmbr0 (with Internet Access)
     |      |      |
   +----+ +----+ +----+
  | m0 | | m1 | | m2 |  3-node Secure Mesh Site
   +----+ +----+ +----+
     |      |      |
-------------------------------------  vmbr1 (or vmbr0 VLAN 100)
  |      |      |     |      |      |
+----+ +----+ +----+ +----+ +----+ +----+
| m0 | | m1 | | m2 | | w0 | | w1 | | w2 |  6-node AppStack Site
+----+ +----+ +----+ +----+ +----+ +----+
  • The 3-node Secure Mesh Site connects via SLO interfaces to vmbr0 for internet access and control plane connectivity to F5 Distributed Cloud.
  • The Secure Mesh Site provides DHCP services and internet connectivity to AppStack nodes via its SLI interfaces on the internal network (vmbr1 or VLAN-tagged vmbr0).
  • Each AppStack node receives DHCP and internet connectivity through the Secure Mesh Site's SLI interfaces.

Prerequisites

  • Proxmox VE server or cluster meeting the minimum hardware requirements listed in the Environment section.
  • F5 Distributed Cloud account with appropriate permissions and API credentials (API Token or encrypted P12 file with password available as environment variable VES_P12_PASSWORD).
  • Terraform CLI installed on the deployment workstation.
  • Access to the Terraform example configuration repository: https://github.com/mwiget/f5xc-proxmox-site

Step 1: Clone the Example Repository

$ git clone https://github.com/mwiget/f5xc-proxmox-site
$ cd f5xc-proxmox-site

Step 2: Download the F5 XC CE KVM Image

Run the following helper script from the Proxmox server shell to download the latest CE KVM qcow2 image. Modify environment variables to match your setup before executing:

$ cat download_ce_image.sh
#!/bin/bash
image=$(curl -s https://docs.cloud.f5.com/docs/images/node-cert-hw-kvm-images | grep qcow2\" | cut -d\" -f2)
if test -z $image; then
  echo "can't find qcow2 image from download url. Check https://docs.cloud.f5.com/docs/images/node-cert-hw-kvm-images"
  exit 1
fi
if ! -f $image; then
  echo "downloading $image ..."
  wget $image
fi

Step 3: Create the F5 XC CE Template on Proxmox

Run the following script directly on the Proxmox server shell. Adjust the qcow2 path, id (template VM ID), and storage values to match your environment before executing:

$ cat create_f5xc_ce_template.sh
#!/bin/bash
# Adjust full path to downloaded qcow2 file, target template id, and storage
qcow2=/root/rhel-9.2024.11-20240523024833.qcow2
id=9000
storage=cephpool

echo "resizing image to 50G ..."
qemu-img resize $qcow2 50G
echo "destroying existing VM $id (if present) ..."
qm destroy $id
echo "creating vm template $id from $image ..."
qm create $id --memory 16384 --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-pci
qm set $id --name f5xc-ce-template
qm set $id --scsi0 $storage:0,import-from=$qcow2
qm set $id --boot order=scsi0
qm set $id --serial0 socket --vga serial0
qm template $id

Step 4: Configure Terraform Variables

Copy the example variables file and populate it with values specific to your environment:

$ cp terraform.tfvars.example terraform.tfvars

The following variables must be configured in terraform.tfvars:

VariableDescription
project_prefixPrefix applied to site and node names (e.g., your initials)
ssh_public_keySSH public key provided to each CE node
pm_api_urlProxmox API URL
pm_api_token_idProxmox API Token ID (e.g., root@pam!prox)
pm_api_token_secretProxmox API Token Secret
pm_target_nodesList of Proxmox server nodes to use for VM placement
iso_storage_poolProxmox storage pool for cloud-init ISO disks
pm_storage_poolProxmox storage pool for VM disks
pm_cloneName of the F5 XC CE template created in Step 3
pm_poolOptional resource pool to which VMs will be added
f5xc_api_urlhttps://<tenant>.console.ves.volterra.io/api
f5xc_api_tokenF5 XC API Token
f5xc_tenantF5 XC Tenant ID
f5xc_api_p12_filePath to the encrypted F5 XC API P12 file. Password must be set via the VES_P12_PASSWORD environment variable

Step 5: Enable the Firewall and AppStack Modules

Edit the file lab-firewall.tf and set count=1 in both the firewall and appstack modules to enable deployment. Setting count=0 disables a module; setting it to a value greater than 1 deploys multiple instances of that site type, with the count index appended as a suffix to the site name.

Step 6: Deploy the Sites Using Terraform

$ terraform init

$ terraform plan

$ terraform apply

Terraform will display periodic progress output, including site status, until both sites reach ONLINE status. Once deployed, verify the sites in the F5 Distributed Cloud Console under Cloud & Edge Sites → Site Management. Confirm both the Secure Mesh Site and the AppStack site show a Health Score of 100/100 and a Site Admin State of Online.

DHCP leases assigned to AppStack nodes can be verified in the F5 Distributed Cloud Console by navigating to the Secure Mesh Site dashboard and reviewing the DHCP management section. The AppStack cluster can also be queried directly using the auto-generated kubeconfig:

$ source env.sh
$ kubectl get nodes -o wide

Scaling Worker Nodes

To add or remove AppStack worker nodes after initial deployment, edit the worker node count in lab-firewall.tf and re-apply the Terraform configuration:

$ terraform apply

Destroying the Deployment

To remove all site objects from F5 Distributed Cloud and delete all Virtual Machines and disks from Proxmox, run:

$ terraform destroy

Additional Information

The Terraform example repository (https://github.com/mwiget/f5xc-proxmox-site) includes additional configuration examples beyond the dual-NIC Secure Mesh + AppStack topology documented in this article:

  • secure-mesh-single-nic.tf — Single-NIC Secure Mesh Site deployment
  • secure-mesh-dual-nic.tf — Dual-NIC Secure Mesh Site deployment (standalone, without AppStack)
  • appstack.tf — AppStack-only deployment

Proxmox VE provides multiple options for creating a second virtual network for CE SLI interfaces. The approach used in this article is a VLAN-tagged sub-interface on vmbr0 (e.g., VLAN 100). Alternative methods include dedicated physical Ethernet ports or Proxmox Software Defined Networking (SDN). The choice depends on available hardware and network architecture.

The F5 XC CE KVM image is the same image used for all KVM-based deployments, including standard KVM/libvirt environments. The template creation process in this article resizes the image to 50 GB before importing it as a Proxmox VM template. This template is reused for both the Secure Mesh Site and AppStack node VMs, as the CE software determines the operational persona (Secure Mesh or AppStack) based on the site configuration applied from the F5 Distributed Cloud Console.

The Terraform Proxmox Provider used in this example is the Telmate Proxmox Provider. Refer to its documentation for advanced Proxmox-specific configuration options such as resource pools, storage pool types, and cluster node targeting.
