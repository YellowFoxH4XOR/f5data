K000091151: "Connection reset by peer" log is stored on NIC

Type
Support Solution
Published
2021-12-13
Updated
2026-07-30
Source
https://my.f5.com/manage/s/article/K000091151

Description

Nginx Ingress Controller stored follwing logs when TCP reset received from upstream:

2021/12/09 09:43:51 \[error\] 123#123: \*68 recv() failed (104: Connection reset by peer) while proxying and reading from upstream, client: 10.244.94.186, server: 0.0.0.0:3306, upstream: "10.200.145.21:3306", bytes from/to client:792/2564, bytes from/to upstream:2564/792

Environment

The configuration has been applied with Steam Snippet on configmap like below:

apiVersion: v1
data:
 stream-snippets: |
  upstream mysql-tcp {
    zone mysql-tcp 64k;
    server 10.200.145.24:3306;
  }
  server {
    listen 3306 backlog=50000;
    proxy_pass mysql-tcp;
    proxy_timeout 10s;
    status_zone mysql-tcp;
  }
kind: ConfigMap
metadata:
name: nginx-config

above config shows like below on Nginx-Ingress-Controller:

$kubectl exec -it <Nginx-Ingress-Controller pod name> -- nginx -T

stream {
  log_format stream-main '$remote_addr \[$time_local\] '
           '$protocol $status $bytes_sent $bytes_received '
           '$session_time "$ssl_preread_server_name"';

  access_log /dev/stdout stream-main;


  upstream mysql-tcp {
    zone mysql-tcp 64k;
    server 10.200.145.24:3306;
  }
  server {
    listen 3306 backlog=50000;
    proxy_pass mysql-tcp;
    proxy_timeout 10s;
    status_zone mysql-tcp;
  }

Cause

Once you applied stream-snippet on configmap, nginx-ingress-controller applied default logs format like below:

  log_format stream-main '$remote_addr \[$time_local\] '
           '$protocol $status $bytes_sent $bytes_received '
           '$session_time "$ssl_preread_server_name"';

therefore, this log appears when upstream send TCP reset packet with above logs format

Recommended Actions

Not NIC side issue, You may need to check the upstream device
