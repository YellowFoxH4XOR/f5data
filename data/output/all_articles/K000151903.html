Topic

This article provides an overview of what you can monitor for high TMM memory usage on your BIG-IP system. This article focuses on TMM memory. For more information on BIG-IP memory allocation, refer to K16419: Overview of BIG-IP memory usage.

Description

TMM memory utilization may increase due to a variety of reasons. BIG-IP provides the following facilities that you can use to monitor for symptoms of high TMM memory usage, create alerts when usage is high and respond as appropriate.

DescriptionSymptoms of high TMM memoryResources
Monitor log messages in /var/log/ltm011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (0) (global memory) <x> Connections killed

Refer to the different log messages that an eviction policy generates that you should monitor in K15740: Overview of adaptive connection reaping (11.6.0 and later).

01010004:3: Memory allocation failed: <tmm memory object>

This error message displays the specific TMM memory object that is consuming memory. Focus your troubleshooting on this object using tmsh and tmtcl commands.

Monitor TMM memory utilization graphs from the Configuration utility and iHealth

The diagram above illustrates an example of high TMM memory use, resulting in TMM restarts. The graph shows increasing TMM memory usage. When the system experiences memory exhaustion, TMM restarts.

On the Configuration utility, go to Statistics > Performance Reports.
On iHealth, go to Graphs > Standard, select Memory used.

Monitor TMM memory from command outputs
  • tmsh show sys memory
  • tmsh show sys tmm-info
  • tmctl commands

From the output, use the following formula for calculation:
Percentage used = (used / avail) * 100

Monitor TMM memory with SNMP

Monitor with SNMP. For example:

  • total TMM memory, sysGlobalTmmStatMemoryTotal
    snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.21.28.0
  • global used TMM memory, sysGlobalTmmStatMemoryUsed
    snmpget -Of -c public -v2c localhost .1.3.6.1.4.1.3375.2.1.1.2.21.29.0
  • individual used TMM memory, sysTmmStatMemoryUsed 
    snmpwalk -c public localhost .1.3.6.1.4.1.3375.2.1.8.2.3.1.32

Other common failure symptoms

You may observe the other failure symptoms on your system as a result of insufficient memory. Note that these symptoms may also be a result of other causes not related to memory usage:

  • application and traffic performance impact
  • TMM and other daemons and internal services restarts
  • Core files generated in /shared/core
  • Network interface goes down
  • High availability failover.
  • System reboot.

Recommended Actions

When understanding or investigating TMM memory usage, consider the following:

  1. monitor and use a combination of 2 or more facilities to analyze TMM memory usage.
  2. on iHealth,
    1. generate different graphs over different time periods including using the Custom option to focus on a specific time period.
    2. cross reference information from the different graphs with information from a combination of different commands described in this article.
