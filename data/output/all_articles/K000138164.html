Description

You are reviewing BIG-IP APM logs on var/log/apm and you find messages similar to these:
 
19686 Nov 7 07:01:54 APM1.example.com notice apmd[14890]: 0149016a:5: Initiating snapshot creation: tmm.session.403d3e286f8998_29ooooooooooooooo for access profile: /Common/vpn-example-access-profile
19687 Nov 7 07:01:54 APM1.example.com notice apmd[14890]: 0149016b:5: Completed snapshot creation: tmm.session.403d3e286f8998_29ooooooooooooooo for access profile: /Common/vpn-example-access-profile
21423 Nov 7 08:05:38 APM1.example.com notice tmm[20320]: 01490538:5: tmm.session.403d3e286f8998_29ooooooooooooooo: Configuration snapshot deleted by Access.
21424 Nov 7 08:05:38 APM1.example.com notice tmm1[20320]: 01490538:5: tmm.session.403d3e286f8998_29ooooooooooooooo: Configuration snapshot deleted by Access.
21425 Nov 7 08:05:38 APM1.example.com notice tmm2[20320]: 01490538:5: tmm.session.403d3e286f8998_29ooooooooooooooo: Configuration snapshot deleted by Access

Environment

  • BIG-IP APM
  • Access Policies

Cause

This is functioning as designed.

Access Policy changes are designed to be non-volatile, meaning active users connected to an APM policy will not be affected by a change to the Access Policy. The method for doing so is using a configuration snapshot. Every time you create or apply an access policy it creates a snapshot, this is what runs in apd's memory. Those messages belong to snapshots being purged when they are no longer needed. This is an expected behavior and works as designed when creating/applying Access Policies.

Recommended Actions

 These errors may safely be ignored.
