Description
 

After upgrading to version 16.1.2, a Virtual Server with an html profile stopped working.

If you take a packet capture you will see RST flags from the BIG-IP to the backend server-side with an error similar to the next one:

[RST, ACK] Seq=XXXX Ack=XXXX Win=0 Len=XXXX [F5RST(peer): Compression error]

This error may be displayed even though the Virtual Server doesn't have a compression profile.

On the GET request, you will see that the client is accepting compression like the following example:

Hypertext Transfer Protocol
    GET /mytestsite/site.xml HTTP/1.1\r\n
    <...>
    Accept-Encoding: gzip, <...>

Environment

  • BIG-IP LTM
  • HTML profile
  • Compression
 

Cause
 

On the GET request, the client is accepting or requesting compression.
 

Recommended Actions

NOTE: It is recommended to perform these changes in a maintenance window.

  1. Using the GUI, go to the HTTP profile you are using on the Virtual server:
    Local Traffic  ››  Profiles : Services : HTTP  ››  <http profile's name>
  2. Under the Settings config, you will find the option: Request Header Erase
    Write Accept-Encoding to remove this header from the request.
  3. Click update and test
 

Additional Information

If the HTTP profile in question is being used in many Services, you can create another profile using the current as a parent. This will help to prevent possible impacts on your environment.
