Known Issue

This is the result of a known issue. The Secure Sockets Layer (SSL) certificate store that the BIG-IP system returns to the client when a COMPAT cipher is negotiated does not include the chain certificates specified in the Chain setting of the Client SSL profile. Therefore, when the BIG-IP system negotiates a COMPAT cipher for a connection request to a virtual server using a Client SSL profile with a chain certificate bundle configured, the client may receive a warning that the server certificate could not be verified.

Note: This issue affects SSL profiles which specify a custom cipher list instead of using the DEFAULT cipher list, or if clients force the negotiation of COMPAT ciphers.

Note: If a NATIVE cipher is negotiated, the SSL certificate store returned to the client includes the certificate included in the configured chain certificate bundle and the root CA certificate.

F5 Product Development is tracking this issue as ID 249536 (formerly CR54400).

Workaround

You can work around this issue by disabling COMPAT ciphers on affected virtual servers. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Select the SSL profile which is applied to the affected virtual server.
  4. Add the following string to the custom ciphers list specified in the Ciphers box:

    !compat

    For example, the full string may appear similar to the following example:

    DEFAULT !compat

    Note: This string disables COMPAT ciphers, forcing the profile to use NATIVE ciphers, which correctly includes any specified chain certificates.

  5. Click Finished.
