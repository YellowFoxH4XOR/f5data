Description

Wildcard * Allowed URL entity keeps getting deleted in ASM Security Policy, requiring it to be recreated.

Messages similar to the following are observed in /var/log/asm:

info perl[3967]: 01310053:6: ASMConfig change: URL * [delete] { audit: policy = /Common/very-secure, component = Policy Builder }

Application URLs may be dynamic in nature, so this is undesirable behaviour.

Environment

  • Security Policy
  • Allowed URLs
  • Automatic learning mode

Cause

Security Policy has Learn New HTTP URLs set to Always in Learning and Blocking settings. With this configured, it is expected for the wildcard * to be deleted once the policy tightens.

Recommended Actions

Depending on your application environment, use a learning option (such as Compact or Selective) that does not delete the wildcard once the policy tightens.

Brief summary of each option:

  • Compact - Attempts to add only the most commonly used entities.
  • Selective - Adds anything that doesn't match the wildcard.
  • Always - Adds every URL. Removes the wildcard once policy is stable.
  • Never - Doesn't add explicit entities, only modifies the wildcard.

Note: If parameters learning is also set to Always, you may also wish to change this to prevent the wildcard * parameter being deleted.

Additional Information

When using automatic learning, a policy will tighten or stabilize once a sufficient amount of traffic has been seen, from multiple sources.
