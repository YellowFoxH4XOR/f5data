Description
While trying to patch your VIPRION B2250 blade, you experience an upgrade failure.  This may also result in additional symptoms such as:

  • Devices that the upgrade was attempted on are stuck in a boot loop

  • Re-starting chmand messages coming in frequently
    chmand[5575]: 012a0000:0:  No HSBe2_v2 PCIs found yet. possible restart to recover Dataplane.  : File sw/A112SwSvc.cpp Line 238
    chmand[5575]: 012a0000:0: Dataplane INOPERABLE -  No HSBe2_v2 found on the platform (A112).  : File sw/A112SwSvc.cpp Line 516
    chmand[5575]: 01550004:0: Dataplane init error: Dataplane INOPERABLE -  No HSBe2_v2 found on the platform (A112).

  • chmand daemon is not able to start and a core file being generated
    K10062:  Overview of managing BIG-IP core files


Environment

  • VIPRION B2250 blade
  • upgraded to 13.1.3.3 or 13.1.3.4
Note: This does NOT apply vCMP Guests running on VIPRION B2250 blade.

Cause

Bug ID 749738


Recommended Actions

Roll back to the previous version

Engage F5 Support

  1. Open a proactive support case to plan for the upgrade day/time.
    K16022:  Opening a proactive service request with F5 Technical Support

  2. Request the engineering hotfix for Bug ID 749738.
    EHF for 13.1.3.4 with just ID749738 fix:
    Hotfix-BIGIP-13.1.3.4.0.38.5-ENG
     

iHealth Diagnostics

Upload qkviews from all vCMP hypervisor and guests before upgrade to iHealth.  This diagnostic data will help in troubleshooting the issue with F5 Support.

Hotfix Installation
K55025573: Engineering hotfix installation overview
Note: Engineering Hotfixes follow the same guidelines.

  1. As indicated above take back ups of all guests and vCMP hypervisor first and store if off the device.   Shutdown all guests gracefully.

  2. Ensure that the base 13.1.3.4 ISO is also in /shared/images and then install the ENG-HF; the base ISO image will be installed automatically along with the ENG-HF.

  3. Take a UCS backup and store it off box.   (You should have backups of current state that you took before you started the install as well as a state after you install and before booting into the new image)

  4. Boot / Activate into the new 13.1.3.4 with EHF image. 

  5. Validate that the upgrade was successful.  If not successful troubleshoot and engage F5 support.   Restore UCS or revert back to the previous version as guided by F5 support.

  6. Once the vCMP hypervisor is operational and stable then upgrade one guest at a time following similar process.  License activation is for vCMP hypervisor so guest won’t need that. 


Additional Information
When you upgrade software on vCMP systems, keep the following information in mind:

  • When you upgrade a vCMP hypervisor, it is normal to see the guests go offline.
  • Upgrading the vCMP hypervisor does not upgrade individual guests.
  • To avoid excessive disk and CPU usage, upgrade only one vCMP guest at a time.
  • Each guest inherits the license of the vCMP hypervisor, and the vCMP hypervisor license includes all BIG-IP modules available for use with vCMP guest instances. If you need to reactivate the license, you reactivate it at the vCMP hypervisor only.
  • While not required, F5 recommends that you configure your vCMP hypervisor to run the same BIG-IP version as the latest version used by any of its vCMP guests.
  • F5 hardware platforms with multiple blades manage and share software image ISO files between blades automatically. Starting in 11.6.0, BIG-IP software images that are stored and managed on the vCMP hypervisor are also available for vCMP guests to install.
  • vCMP hypervisor and guests use unique UCS configuration files. For example, virtual servers configured within a BIG-IP guest are not contained in the UCS file created on the vCMP hypervisor.
