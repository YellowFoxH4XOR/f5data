Topic

The BIG-IP system can load balance traffic to pool members that are configured to use Active/Standby redundant network interfaces that share a MAC address. If PVA processing is disabled, the BIG-IP system can also load balance traffic to pool members that are configured to use Active/Standby redundant network interfaces which do not share a MAC address, but send a Gratuitous ARP reply upon failover to update the MAC address tables for the shared IP address on the surrounding network devices.

Note: Platforms that include a PVA chip are 3400, 6400/6800, and 8400/8800. Platforms that include an ePVA chip are 5000 series, 7000 series, 10000 series, and VIPRION blades B2100, B2150, B2250, and B4300. 

Active/Standby redundant interfaces implement failover by sharing a single IP address between two interfaces. The interfaces may also share a MAC address, or may each be assigned a unique MAC address. When the BIG-IP system load balances traffic, the system sends the traffic to the MAC address associated with the IP address of the load balancing target. In a redundant interface implementation in which each interface uses a unique MAC address, the MAC address associated with the IP address must be updated in the BIG-IP ARP cache upon failover. In most cases, if the system sends a Gratuitous ARP for the new MAC address upon failover, the BIG-IP is able to send traffic to the newly Active interface. However, if the virtual server is accelerated by the PVA/ePVA (that is, it uses FastL4 profiles with PVA acceleration set to assist or full), the BIG-IP system does not detect a change in the MAC address. In either case, if the BIG-IP system is not aware that the MAC address changed, the BIG-IP system continues to send traffic to the new Standby interface.

Note: If there is an intermediate hop (for example, a router) between the BIG-IP system and the device with redundant interfaces, the MAC address change is hidden from the BIG-IP system and neither limitation applies.

F5 recommends that you use the 802.3ad protocol for load balancing and link aggregation, instead of using the proprietary redundant interface features. If you cannot use 802.3ad, you can work around this limitation by ensuring that the virtual server that load balances to pool members with redundant interfaces does not use the PVA. To do so, perform the following procedure:

Note: By demoting a virtual server to pva acceleration none, the traffic is processed by TMM instead of the PVA. As a result, host CPU utilization is increased commensurately.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > FastL4.
  3. To create a new profile, click Create.
  4. In the Name field, enter a unique name for the new profile.
  5. Select an appropriate parent profile, such as the default FastL4 profile.
  6. Select the Custom check box next to the PVA Acceleration setting, and set the value to None.
  7. Apply this new profile to the affected virtual servers.
