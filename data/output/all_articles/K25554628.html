Known Issue

The tomcat process may experience an out of memory exception, become unresponsive, and fail to automatically restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has a large number of virtual servers and pools configured (3000+).
  • You access the Local Traffic > Network page in the Configuration utility.

Impact

The Configuration utility becomes unresponsive, and you are unable to start it until you manually restart the tomcat process.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility becomes unresponsive.
  • In the /var/log/tomcat/catalina.out log file, you may observe error messages similar to the follow example:

    SEVERE: Caught exception (java.lang.OutOfMemoryError: Java heap space) executing org.apache.jk.common.ChannelSocket$SocketAcceptor@f14c7c, terminating thread

Workaround

To work around this issue, you can restart the tomcat process. Optionally, if the tomcat process repeatedly encounters this issue, you can increase the amount of memory allocated to the tomcat process. To do so, perform the following procedures:

Restart the tomcat process
Increase the amount of memory allocated to the tomcat process

Restart the tomcat process

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  3. Restart the tomcat process by typing the following command:

    restart /sys service tomcat

Increase the amount of memory allocated to the tomcat process

If the tomcat process continues to encounter this issue and becomes unresponsive, you can increase the amount of memory allocated to the tomcat process. To do so, perform the following procedure:

Impact of procedure: The following procedure requires that you restart the tomcat process. The Configuration utility will not be accessible while the tomcat process restarts.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. View the current value of the provision.tomcat.extramb database variable by typing the following command:

    list /sys db provision.tomcat.extramb

    The command output appears similar to the following example:

    sys db provision.tomcat.extramb {
    value "0"
    }

    A value of 0 (zero) indicates that no additional memory is currently allocated. This is the default value.

  3. Set the provision.tomcat.extramb database variable to the amount of additional memory that you want to allocate, using the following command syntax:

    modify /sys db provision.tomcat.extramb value <MB>

    In this command, note the following:

    • <MB> is the number of megabytes of additional memory you want to add to the default provisioned amount.

    For example, to allocate an additional 20 MB of additional memory, type the following command:

    modify /sys db provision.tomcat.extramb value 20

    Note: F5 recommends that you initially increase the amount of memory to 20 MB, but doing so may not resolve all instances of the error message. If the java.lang.OutOfMemoryError errors continue, repeat this procedure, gradually increasing the value of <MB> until you no longer view the error message.

  4. Restart the tomcat process by typing the following command:

    restart /sys service tomcat 

  5. If the device is part of a high-availability (HA) configuration, you should synchronize the provision.tomcat.extramb database value to the peer devices from the command line.

    For BIG-IP 11.x - 12.x, refer to K14856: Performing a ConfigSync using the tmsh utility

    .
  6. Log in to the command line of each peer device, and restart the tomcat process by typing the following command:

    restart /sys service tomcat
