Description

When one system controller is active all management interfaces are unreachable even though both management interfaces show in an "UP" status .

Environment

  • F5 Velos Controllers
  • Un-aggregated Management ports

Cause

All management traffic flows exclusively through the management port of the active controller. F5OS disables frame forwarding on the standby controller's mgmt port. If an active controller loses all management connectivity (for both controller-1, controller-2 and floating), this is usually caused by a misconfiguration on the upstream switch.

Answer/Recommended Actions

Validate the upstream switch interface connectivity and configuration for the interface of the controller that lost connectivity.   For example if the ports are un-aggregated, they should not be configured as a trunk port.  

Validate that the interface is up on the Controllers.

show interfaces interface */mgmt0 state admin-status | select state oper-status | select state counters in-pkts | select state counters out-pkts | repeat 1

          ADMIN   OPER             OUT
NAME     STATUS  STATUS  IN PKTS  PKTS
-------------------------------------------
1/mgmt0  UP      UP      5741151  2502518
2/mgmt0  UP      UP      3716710  0

         ADMIN   OPER             OUT
NAME     STATUS  STATUS  IN PKTS  PKTS
-------------------------------------------
1/mgmt0  UP      UP      5741479  2502678   <--- incrementing packets on the active controller
2/mgmt0  UP      UP      3716921  0

Check the logging to see if the links are bouncing.

grep "Linkstatus change" /var/log_controller/velos.log | grep mgmt

Validate mac addresses are learned in upstream switch.

Additional Information

When un-aggregated the port on the standby system controller will be put in a blocking mode to prevent a bridge loop from occurring so you will be limited to 10Gb of bandwidth. The internal switchd process monitors the HA status of the local controller and will disable forwarding on the mgmt port if the system controller is in standby mode. If a controller’s mgmt interface goes down, it will fail over to the other system controller and will not assume the active role.

Controller-2 is active and controller-1 is standby. The mgmt interface on each controller is 'UP'. While both controllers show incrementing ingress packets, only the active controller shows egress packets incrementing. This is because the front-panel mgmt port on the standby controller has forwarding disabled, so it egresses nothing. Yet the standby controller still has full L2 connectivity since its traffic is ultimately carried over the management port of the active controller.
