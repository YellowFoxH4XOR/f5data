Known Issue

This is the result of a known issue. The ARX system may have file inconsistencies after restarting a failed share import. When a seamless import fails due to name collisions, and the import is restarted by re-enabling the share after fixing the collisions, the import may appear to finish successfully. However, the ARX system does not clear the state of the already processed or currently processing directories in a seamless import. Therefore, when the share is re-enabled, the ARX system will skip the previously processed directory to avoid duplicate processing. As a result, users may be unable to find some files using the ARX system, and an ARX inconsistencies report will indicate file inconsistencies.

F5 Product Development tracked this issue as ID 39343 and it was fixed in ARX version 5.1.7. For information about upgrading, refer to the ARX Release Notes.

Additionally, this issue has been fixed in ARX version 5.1.5 HF6 (build 11980). Customers affected by this issue can download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

Workaround

To prevent imports from failing due to name collisions, set the import rename-files, import rename-directories, and import sync-attributes options for all shares being imported.

Note: For more information about these commands, refer to the ARX CLI Reference Guide.

If file inconsistencies are present as a result of this issue, you must rebuild the ARX metadata for the volume using the nsck <namespace> volume /vol rebuild force command. 

Note: For more information about the nsck command, refer to the ARX CLI Reference Guide.
