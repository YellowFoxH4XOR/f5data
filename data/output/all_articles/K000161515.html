K000161515: F5 DNS resolver query refused

2026-06-02
Applies to

Source

Description

On BIG-IP DNS, intermittent DNS "Query Refused" (RCODE=5) responses are observed when a DNS Cache Resolver profile is configured on a virtual server. DNS queries to external domains sometimes succeed and sometimes fail. The nslookup or dig tests return:

;; ->>HEADER<<- opcode: QUERY, status: REFUSED

Packet capture analysis (filtering for dns.flags==0x8105) shows that REFUSED responses originate from the local BIND instance on the BIG-IP, even though a DNS Cache Resolver profile with forward zones and root hints is configured and enabled.

Environment

LTM DNS Cache Resolver (ltm dns cache resolver) configured with forward zones and root hints

LTM DNS profile (ltm profile dns) with enable-cache yes

use-local-bind enabled (default) in the DNS profile

Virtual server using the DNS profile with the cache resolver attached

DNS queries to external domains not covered by any configured forward zone

Cause

When a DNS Cache Resolver profile is configured on a BIG-IP DNS virtual server, the system follows a DNS resolution precedence order. If the DNS cache (resolver) fails to answer a query — for example, due to a cache miss and an inability to reach root hints servers, or a transient resolution failure — the system falls through the resolution chain and ultimately reaches the local BIND instance (when use-local-bind is enabled in the DNS profile). Since BIND on BIG-IP is not configured to perform recursive resolution for external domains, it returns a "Query Refused" response. This causes intermittent failures: queries succeed when resolved from cache or via root hints, and fail when they fall through to BIND.

Answer/Recommended Actions

To resolve the intermittent "Query Refused" behavior, perform the following steps:

  1. Disable the local BIND instance in the DNS profile to prevent DNS queries from falling back to BIND when the cache resolver cannot answer them:
    • Log in to the BIG-IP Configuration utility.
    • Navigate to Local Traffic > Profiles > Services > DNS.
    • Select the DNS profile attached to the affected virtual server.
    • Set Use BIND Server on BIG-IP to Disabled.
    • Set Unhandled Query Action to Allow (if a DNS cache or pool is configured to handle remaining queries).
    • Click Finished.

      Alternatively, using tmsh:

           tmsh modify ltm profile dns <profile_name> use-local-bind disabled

  2. Verify that the root hints configured in the DNS cache resolver are valid and reachable. Unreachable root hints cause cache misses that trigger fallback to BIND. Update root hints if needed:

             tmsh modify ltm dns cache resolver <cache_name> root-hints replace-all-with { <valid_root_hint_ip_1> <valid_root_hint_ip_2> }

  3. Verify and troubleshoot using the following commands:

  • Capture DNS traffic to identify the source of REFUSED responses:

      tcpdump -nni 0.0:nnnp port 53 -s0 /var/tmp/resolverissue.pcap

  • Identify sources returning REFUSED responses (local BIND instance on BIG-IP can be identified by its IP in packet captures):

      tshark -r /var/tmp/resolverissue.pcap -Y dns.flags==0x8105 -T fields -e ip.src | sort | uniq

  • Inspect the DNS cache resolver state:

      tmsh show ltm dns cache resolver <cache_name>
      tmsh show ltm dns cache records msg cache <cache_name>
      tmsh show ltm dns cache records rrset cache <cache_name>

Additional Information

This scenario is distinct from K22928504: Local DNS bind server returns 'Query refused' error when querying external domains, which describes a "Query Refused" error caused by BIND misconfiguration (incorrect named.conf settings) when BIND is the sole DNS resolution method. In the scenario described here, a DNS Cache Resolver profile is the primary resolution method, and BIND acts as an unintended fallback due to the use-local-bind default setting being enabled. The intermittent nature of the failures — queries sometimes succeeding and sometimes failing — is a key differentiator, as it reflects cache hits succeeding while cache misses fall through to BIND.

Note: F5 does not recommend using the local BIND instance as a resolver for external domains. For environments requiring resolver-based DNS caching on BIG-IP, configure the DNS cache resolver with valid forward zones and/or reachable root hints, and disable BIND fallback in the DNS profile.
