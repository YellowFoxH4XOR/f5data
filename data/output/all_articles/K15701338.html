The Kubernetes certificates that NGINX Controller applies during installation are valid for one year. If you take longer than one year to update NGINX Controller, Kubernetes will be impacted by this issue. As a result, NGINX Controller normal operation is affected.

This issue occurs when the following condition is met:

  • NGINX Controller is not updated for longer than one year.

Impact

  • NGINX Controller fails to start.
  • The kubectl commands fail with "invalid certificate" or "unauthorized" errors.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Kubernetes stops or fails to start, and NGINX Controller fails to start.
  • You can confirm that the kubelet certificate expired by entering the following command:

    kubeadm alpha certs check-expiration

  • kubectl fails with an error message that appears similar to the following example:

    The connection to the server <host>:6443 was refused - did you specify the right host or port?

  • The container logs, such as kubeapi-server, display error messages that appear similar to the following example:

    441585 1 clientconn.go:1251] grpc: addrConn.createTransport failed to connect to {127.0.0.1:2379 0 <nil>}. Err :connection error: desc = "transport: authentication handshake failed: x509: certificate has expired or is not yet valid". Reconnecting...

Workaround

Note: Upgrading NGINX Controller after the kubelet certificate expires will not fix the issue.

To work around this issue, you can renew all of the kubelet certificates. To do so, perform the following procedures:

  • Verify the kubernetes service certificates
  • Verify the kubelet certificate status

Note: In a multi-cluster environment, you should perform this procedure on all nodes individually.

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Verify the Kubernetes service certificates

  1. Log in to the command line as the user who installed NGINX Controller.
  2. Verify expiration information for the Kubernetes service certificates by entering the following command:

    sudo kubeadm alpha certs check-expiration

    If there are one or more expired certificates, proceed with the rest of this procedure.

  3. Renew the service certificates by entering the following command:

    sudo kubeadm alpha certs renew all

  4. Change directories to the home directory of the user who installed NGINX Controller by entering the following command:

    cd "$(dirname "$(find /home/ -name '\.kube')")"

  5. Back up the current /.kube/config by entering the following command:

    mv .kube/config .kube/config.old

  6. Copy admin.conf to /.kube/config by entering the following command:

    sudo cp -i /etc/kubernetes/admin.conf ./.kube/config

  7. Change the owner and group of /.kube/config as root by entering the following command:

    sudo chown $(id -u):$(id -g) ./.kube/config

  8. Set the environmental variables of KUBECONFIG by entering the following command:

    export KUBECONFIG=.kube/config

  9. Reboot NGINX Controller by entering the following command:

    sudo shutdown now -r

Verify the kubelet certificate status

  1. Log in to the command line as the user who installed NGINX Controller.
  2. Check to see if the kubelet server certificate is expired by entering the following command and observing the validity date: 

    openssl x509 -in /var/lib/kubelet/pki/server.pem -text -noout

    If the certificate is expired, continue to the next step to renew the kubelet server certificate.

  3. Stop kubelet by entering the following command:

    sudo systemctl stop kubelet

  4. Back up and remove the server.csr, server.key, and server.pem files in /var/lib/kubelet/pki by entering the following command:

    mkdir ~/kubelet-server-certs && sudo cp /var/lib/kubelet/pki/server.{csr,key,pem} ~/kubelet-server-certs/ && sudo rm /var/lib/kubelet/pki/server.{csr,key,pem}

  5. Using your preferred text editor, create a Bash script with the following content and save as ~/kube-certs.sh:

    #!/bin/bash
    function join_by { local IFS="$1"; shift; echo "$*"; }
    usrmask=$(umask)
    mapfile -t altnames < <(awk '/32 host/ { print "IP:"f } {f=$2}' /proc/net/fib_trie | sort -u)
    umask u=rwx,go=
    sudo openssl genrsa -out /var/lib/kubelet/pki/server.key 2048
    sudo openssl req -new -key /var/lib/kubelet/pki/server.key \
      -subj "/C=US/ST=Washington/L=Seattle/O=F5, Inc./OU=Controller/CN=kubelet" \
      -out /var/lib/kubelet/pki/server.csr
    sudo bash -c "openssl x509 -req -in /var/lib/kubelet/pki/server.csr \
      -extfile <(printf \"subjectAltName=$(join_by , "${altnames[@]}")\") \
      -CA /etc/kubernetes/pki/ca.crt \
      -CAkey /etc/kubernetes/pki/ca.key -CAcreateserial \
      -out /var/lib/kubelet/pki/server.pem -days 365 -sha256"
    umask "$usrmask"

  6. Set executable permissions on the kube-certs.sh file and then run the file to re-create the kubelet server certificates:

    chmod 755 ~/kube-certs.sh && ~/kube-certs.sh

  7. Confirm that the server.csr, server.key, and server.pem files are created in the /var/lib/kubelet/pki directory by entering the following command:

    ls -l /var/lib/kubelet/pki

  8. Back up kubelet.conf in /etc/kubernetes by entering the following command:

    sudo cp /etc/kubernetes/kubelet.conf /tmp/kubelet.conf

  9. Remove the existing kubelet.conf file in /etc/kubernetes by entering the following command:

    sudo rm -rf /etc/kubernetes/kubelet.conf

  10. Remove the client certs in /var/lib/kubelet/pki by entering the following command:

    sudo rm -rf /var/lib/kubelet/pki/kubelet-client-*

  11. Initialize kubelet by entering the following command:

    sudo kubeadm init phase kubeconfig kubelet

  12. Restart kubelet by entering the following command:

    sudo systemctl restart kubelet

  13. Stop the NGINX Controller system by entering the following command:

    sudo /opt/nginx-controller/helper.sh controller stop

  14. When all pods have terminated, start the NGINX Controller system by entering the following command:

    sudo /opt/nginx-controller/helper.sh controller start
