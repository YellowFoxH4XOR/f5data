Known Issue

This is the result of a known issue. A SNAT pool represents a pool of translation addresses that you configure on the BIG-IP system. When a SNAT pool processes a request, the original IP address is mapped to a translation address in the pool.

When a SNAT pool configuration contains a self IP address, it is possible for the mcpd process to return incorrect statistics for that SNAT pool member. The mcpd process queries the pool_member_stat tmstat table when collecting the necessary statistical information for the SNAT pool. The pool_member_stat table also returns statistical entries for the self IP address that are irrelevant to the SNAT pool member. As a result, the statistical information for the SNAT pool is incorrect.

The following example configuration includes a SNAT pool called mysnatpool that contains a floating self IP address:

self 10.10.21.102 {
netmask 255.255.0.0
unit 1
floating enable
vlan internal
allow default
}
snatpool mysnatpool {
members 10.10.21.102
}

If you run the bigpipe snatpool mysnatpool command for the above configuration, the resulting statistical information will be incorrect.

F5 Product Development tracked this issue as ID 225209 (formerly CR138809), and it was fixed in BIG-IP 11.0.0. For information on upgrading, refer to the BIG-IP LTM release notes.

In addition, BIG-IP iHealth lists Heuristic H383265 on the Diagnostics > Identified > High screen.

Workaround

You can work around this issue by defining a SNAT pool that uses unique IP addresses and does not include a self IP address.
