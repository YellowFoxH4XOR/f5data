Known Issue

The ADAPT iRules event is not disabled when the system calls HTTP::disabled from within an iRule.

This issue occurs when all of the following conditions are met:

  • A virtual server exists with an HTTP profile and a Request Adapt or Response Adapt profile.
  • An iRule uses HTTP::disable to, for example, pass non-HTTP traffic.

Impact

Despite HTTP being disabled, the ADAPT iRules event attempts to handle ingress traffic, without parsed HTTP headers, so the iRule fails. It is possible that the ADAPT iRules event can buffer the ingress traffic indefinitely, because it does not receive an expected message from the HTTP filter.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When an iRule disables the HTTP profile in events such as the CLIENT_ACCEPTED event, you cannot use ADAPT::enable to disable the adaptation. Though you may assume that, because ADAPT depends on HTTP, it is disabled along with HTTP, that is not the case.

Workaround

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

To work around this issue, you can disable request-adapt or response-adapt in the profile by doing the following: 

  • For cases in which the system handles HTTP traffic, place an iRule on the HTTP_REQUEST or HTTP_RESPONSE event call ADAPT::enable true.
