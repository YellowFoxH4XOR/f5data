Description

Administrators will sometimes want to track users via the webui and Active connections page or an apm report. However if the users are getting authenticated via Saml the session variable used to capture the username may not be populated resulting in no username information being available.

Environment

  • APM Provisioned
  • Saml Authentication
  • Access policy without a login page
  • APM report not showing username

Cause

Because the Access policy does not have a login page where the user is entering their username. The Session variable session.logon.last.username is not populated. As a result the Active session list  (Access => Overview => active sessions) contains no username.

Recommended Actions

  1. Perform a Session dump for a users session ID:
    # sessiondump -allkeys | grep <session_id> > /shared/tmp/sessiondump.txt
     
  2. Review the users session variables for one you would like to use to create the variable.

    Example session Variables to choose from:

    session.saml.last.identity                       JSmith
    session.ldap.last.attr.sAMAccountName            JSmith
    session.ldap.last.attr.sn                        Smith
     
  3. Login to the webui and go to the VPE of the Access policy.
  4. Add new variable assign just before the Resource assign:
        
          On Variable Assign: Add Entry and change
        
        On the left: Custom Variable: session.logon.last.username
        On the right: Session Variable: session.saml.last.identity
