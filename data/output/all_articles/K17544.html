Known Issue

The BIG-IP ASM bd process may produce a core file after a BIG-IP ASM sync.

This issue occurs when all of the following conditions are met:

  • BIG-IP devices are in a full-sync device group and a sync-only BIG-IP ASM enabled device group.
  • Devices are set to manually sync.
  • A BIG-IP ASM policy is deactivated, and subsequently, the BIG-IP ASM configuration is pushed to another host in the device group.

Impact

The BIG-IP system may fail over to a standby system in the device group. The BIG-IP ASM configuration may be left in an inconsistent state.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The bd process will produce a core file in the /var/core directory.
  • The BIG-IP system may fail over to a standby host in the device group.
  • In the /var/log/ltm log file, you may observe an error message similar to the following example:

    ASM subsystem error (asm_config_server.pl,F5::ASMConfig::Handler::SyncHandler::sync_ucs_file_complete): Could not load configuration while in sync recovery state: MCP Validation error -
    01071726:3: Cannot deactivate policy action '/Common/<policy_name>'. It is in use by ltm policy '/Common/<policy_name>'.
