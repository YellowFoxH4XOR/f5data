Topic

The hardware failover cable for some BIG-IP platforms has been revised to provide more reliable failover state output.

Description

The hardware failover cable has been revised for the following BIG-IP platforms:

  • BIG-IP i2000 series
  • BIG-IP i4000 series
  • BIG-IP i5000 series
  • BIG-IP i7000 series
  • BIG-IP i10000 series
  • BIG-IP 2000 series
  • BIG-IP 4000 series
  • BIG-IP 5000 series
  • BIG-IP 7000 series
  • BIG-IP 10000 series

When you use the revised hardware failover cable CBL-151-01 for hardwired failover between systems in a high availability (HA) configuration, the revised cable provides a more reliable failover state output from the tmsh show cm traffic-group command.

The existing hardware failover cable CBL-151-00 may intermittently provide inaccurate failover state output when you use the tmsh show cm traffic-group command to verify the failover status. For example, you may observe that when you power down device1.lab.f5net.com, and on device2.lab.f5net.com you verify the failover status using the tmsh show cm traffic-group command, device2.lab.f5net.com may indicate that the device1.lab.f5net.com is still active:

--------------------------------------------------------------------------------
CM::Traffic-Group
Name Device Status Next
Active
--------------------------------------------------------------------------------
traffic-group-1 device1.lab.f5net.com active false
traffic-group-1 device2.lab.f5net.com active false
traffic-group-local-only -

Recommendations

When you use the existing hardware failover cable CBL-151-00 for hardwired failover between HA systems, you should consider the following factors:

  • When you shut down an active system and rely on the tmsh show cm traffic-group command for the failover state information, you must remove the hardware failover cable from the powered down system to provide a reliable failover state output. Otherwise, the failover state may indicate the powered down system as being active. In some instances, the newly active unit forces itself to standby to clear the active-active state. The faulty indication is intermittent and not related to licensing or software version.
