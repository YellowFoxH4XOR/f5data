Description

The customer is running BIG-IP instances in a Robin.io cloud environment, which appears to be based on a KVM hypervisor. After performing the CPU core change on the platform the device is unstable when using the SIR-IOV driver 

Environment

  • KVM platform
  • SR-IOV (iavf driver)
  • Robin cloud Native Platform (CNP)

Cause

The issue is caused by SR‑IOV Virtual Function (VF) queue misalignment after the reduction in the BIG‑IP vCPU count. As a result, the iavf queue allocation and BIG‑IP’s internal TMM distribution became fall out of sync, leading to packet drops and traffic instability. There is no supported method to manually tune NIC queues on BIG‑IP VE.

 

Although CPU reduction is performed with the VM fully shut down state, in accordance with the K000151479, the observed behavior is specific to SR‑IOV (iavf) queue handling rather than the vCPU change proocedure itself.  

 

When CPU resources are reduced, SR‑IOV Virtual Function queue allocation is not guaranteed to be renegotiated to match the new vCPU count. This bheaviour is due to an architectural limitation of SR‑IOV driver and is not caused by a BIG‑IP software bug or version‑specific defect.

  1. If the selected driver is iavf, this behavior is expected on the BIG-IP system. The recommended mitigation is to either redeploy the instance with the target vCPU count, or use the sock driver instead of the iavf driver.
  2. To change the driver type, refer to the following article K10142141 to change the Network Driver on BIG-IP VE.
    Important : Changing the driver type requires a system reboot.
  3. If you wish not to reboot the system completely, restart only the TMM process after modifying the driver type by running the following command.

 #bigstart restart tmm

 

 

Additional Information

Sock is a Linux kernel's interrupt-based raw socket mechanism and has indirect access to the NIC, so performance impacts like latency, high CPU, and memory usage. Hence, the packet path is that TMM receives packets via raw socket through the Linux kernel.

Iavf driver is SR-IOV Virtual Function-based poll-mode on which has direct access to the NIC; the packet processing path is TMM, which accesses the NIC VF directly, bypassing the kernel.
