Description

Access profile properties

BIG-IP APM security is based on the way BIG-IP APM sessions function and terminate. For details about the security protections that function at the session level, refer to the following table.

Access profile settingDescriptionResource
Session ID rotationThe BIG-IP APM system tracks all client sessions using a unique, proprietary session ID. During the course of an access policy evaluation, the session ID randomly rotates to prevent session hijacking and fixation attempts.K18390492: BIG-IP APM operations guide | Chapter 6: Security
Access Profile ScopeIn the BIG-IP APM system, the configurable Profile Scope establishes additional criteria to ensure that a user who has established a session on one virtual server or access profile cannot use that same session cookie to access other virtual servers and the resources behind them.
Maximum Session TimeoutThe Maximum Session Timeout setting is an important attribute for a BIG-IP APM access profile because it defines the maximum length of time a session can be active before it is automatically terminated. By limiting the duration of each session, you can mitigate the risk of session hijacking where an attacker could steal or use the session cookie to gain unauthorized access to confidential resources.
Authentication Failure DelaysYou can enable the Minimum Authentication Failure Delay and Maximum Authentication Failure Delay options to slow or mitigate brute-force attacks against the BIG-IP APM system.
Max Sessions Per UserFor some access profile types, you can set a custom value for the maximum number of valid sessions a user can have open at one time. Since each session consumes an access license, malicious attacks to consume all BIG-IP APM licenses fail.
Max In Progress Sessions Per Client IP

The Max In Progress Sessions Per Client IP setting in a BIG-IP APM access profile is a security configuration that limits the number of simultaneous sessions that a client can initiate from a single IP address. This is particularly helpful in preventing a type of attack known as a session flood, where an attacker might attempt to overwhelm the system by initiating a large number of sessions from a single source. By restricting the number of sessions per IP address, this setting can help maintain the system's stability and integrity while also providing a layer of protection against such potential attacks.

Note: There is a possibility of a false positive detection of this protection due to a group of users operating behind a shared proxy. As a preventative measure, F5 encourages a thorough review of the access reports provided by the BIG-IP APM system. This review should help you identify any recurring IP sources within your user community.

Restrict to Single Client IP

The Restrict to Single Client IP setting is an essential security measure within a BIG-IP APM access profile. When enabled, this setting ensures that a session can be accessed only from the same IP address from which it was initially created. This is a potent safeguard against attacks such as session hijacking or cookie theft, as even if an attacker manages to steal a session cookie, they cannot use it from a different IP address. This setting effectively ties the user session to a specific IP address, further enhancing the security of the BIG-IP APM access profiles.

Important: Consider the user behavior and environments when using this setting. A group of users operating behind a shared proxy or users who roam between home or mobile networks may result in false positive detection. As a preventative measure, F5 encourages a thorough review of the access reports provided by the BIG-IP APM system. This review should help you identify any recurring IP sources or users roaming between networks within your user community.

HTTP Only cookies

It is of paramount importance to minimize the risk of session cookie hijacking, which can lead to unauthorized access and potential security breaches of the devices that you are using the BIG-IP APM system to secure. To this end, if your browser permits, F5 recommends enabling the HTTP Only option. This measure is designed to mitigate the risk of client-side scripts gaining access to the BIG-IP APM session cookies, thus enhancing the security of your sessions.

Note: This option is applicable only to the LTM+APM access profile type. Other access profiles necessitate access to various session cookies. Consequently, it’s essential to understand and adapt to the specific needs and capabilities of your chosen access profile in order to maximize security.

SamesiteBeginning in BIG-IP APM 16.0, you can enable this setting to add the samesite attribute to the APM session cookie. This attribute enforces same-site usage and prevents the cookie from being included with cross-site requests.

Mitigate Session Hijacking using TLS and mTLS

Mutual Transport Layer Security (mTLS) is a robust security solution that significantly elevates the safety of online communications and effectively counteracts threats such as cookie hijacking and server-side exploits. Unlike the traditional TLS that only authenticates the server, mTLS necessitates a two-way authentication process, verifying both the client and the server. This heightened level of authentication not only ensures encrypted data transfer but also guarantees exchanges between verified entities, adding an extra layer of security. In the case of cookie hijacking, where unauthorized users seek to steal session cookies, mTLS requires the client to present a valid certificate, thereby greatly reducing the chances of intrusion and session hijacking.

Simultaneously, mTLS minimizes server-side exploits that capitalize on server vulnerabilities to gain unauthorized access or disrupt operations. By requiring mutual authentication before any communication, it becomes significantly challenging for attackers to impersonate a client or server and exploit vulnerabilities. Additionally, the encryption of all data transmitted between the client and server ensures that even if an attacker intercepts the data, it remains unintelligible without the correct keys.

On-Demand Client Certificate Authentication or Client Certificate Inspection

Client certificates offer a cryptographically secure way to validate the authenticity of connecting clients. The BIG-IP APM system can validate client certificates either continuously by setting the Client SSL profile’s Client Certificate setting to Require, or once at the beginning of access policy execution, by setting the Client Certificate setting to Ignore. By using the Require setting, each HTTP connection is automatically authenticated. This negates cookie hijacking attacks by allowing only these mutually authenticated connections.

Note: Setting the Client SSL profile to require a client certificate may have varying impacts on different clients and environments. You should evaluate the use of this setting in each environment.

Mitigate broken access control attacks

You can use the Zero Trust-Identity Aware Proxy template in the F5 Access Guided Configuration (AGC) guide to implement the zero-trust security architecture to protect your apps against broken access control. By using the BIG-IP APM system's features together with AGC to deploy your infrastructure, you can address broken access control by doing the following:

  • Enforce the authorization and verification of every user and device and every request with per-request policies.
  • Simplify the implementation of granular user-access control and address security misconfiguration.
  • Implement step-up authentication to authenticate users at any time during a session to limit access to specific areas of an application to a shorter list of authorized users.
  • Continuously verify client device posture and security compliance to ensure that all devices maintain trust at all times.

Mitigate vulnerable and outdated component attacks

Vulnerable and outdated component attacks target both client and server side components. You can use the BIG-IP APM system to validate the security posture of incoming web connections from remote Windows and Mac clients.

BIG-IP APM access policy Client-Side Endpoint Security lets you configure the BIG-IP system to continuously verify the security compliance of client devices accessing your applications. The end point checks include checking the status of operating system information from OS and browser versions and updates to details such as BIOS version, CPU vendor, and network adapter information.
