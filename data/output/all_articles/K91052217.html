Known Issue

A large number of in-TMM monitors may result in unexpected behavior.

This issue occurs when all of the following conditions are met:

  • You enable in-TMM monitoring.
  • You configure and enable a large number of in-TMM monitors.

Impact

You experience unexpected monitor behavior or status when you configure in-TMM monitors, which could have an impact on load-balanced traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Pool members are erroneously marked down.
  • in-TMM monitor objects continue to poll after being removed.
  • You are unable to create or delete in-TMM monitors.

Workaround

To work around this issue, you can disable in-TMM monitoring. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure configures the BIG-IP system to perform monitor functions using the bigd process instead of Traffic Management Microkernel (TMM).

Disabling In-TMM monitoring

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Enter the following command to disable in-TMM monitoring:

    modify sys db bigd.tmm value disable
