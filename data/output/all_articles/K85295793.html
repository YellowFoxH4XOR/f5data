Description

You can customize your metrics in such a way that groups request to a fixed number of logical operations. This article describes the procedure with an example.

Environment

  • Aspen Mesh: 1.9.x

Cause

None

Recommended Actions

In bookinfo application, for example, we would like to count the number of review request for element review_id. The basic structure of the request is:

GET /reviews/{review_id}

Attributes are the contextual properties provided by Envoy sidecar during request and connection processing. For more information, refer to the official documentation. You can create your own classification rule based on attributes. In the following example, we will be creating an operation called GetReviews which will count the number of time GET requests for various review_id has been called. That makes the request GET /review/1 followed by GET /review/2 count as 2 requests. In similar fashion, we will be creating operations like ListReviews and CreateReviews.

  1. Create an Envoy filter with following configuration. In this example, we are creating a new attribute called istio_operationId and it has values from 3 operations listed above. This filter is applied to the inbound connection for review pod as stated in the label:

    apiVersion: networking.istio.io/v1alpha3
    kind: EnvoyFilter
    metadata:
      name: istio-attributegen-filter
    spec:
      workloadSelector:
        labels:
          app: reviews
      configPatches:
      - applyTo: HTTP_FILTER
        match:
          context: SIDECAR_INBOUND
          proxy:
            proxyVersion: '1\.9.*'
          listener:
            filterChain:
              filter:
                name: "envoy.http_connection_manager"
                subFilter:
                  name: "istio.stats"
        patch:
          operation: INSERT_BEFORE
          value:
            name: istio.attributegen
            typed_config:
              "@type": type.googleapis.com/udpa.type.v1.TypedStruct
              type_url: type.googleapis.com/envoy.extensions.filters.http.wasm.v3.Wasm
              value:
                config:
                  configuration:
                    "@type": type.googleapis.com/google.protobuf.StringValue
                    value: |
                      {
                        "attributes": [
                          {
                            "output_attribute": "istio_operationId",
                            "match": [
                              {
                                "value": "ListReviews",
                                "condition": "request.url_path == '/reviews' && request.method == 'GET'"
                              },
                              {
                                "value": "GetReview",
                                "condition": "request.url_path.matches('^/reviews/[[:alnum:]]*$') && request.method == 'GET'"
                              },
                              {
                                "value": "CreateReview",
                                "condition": "request.url_path == '/reviews/' && request.method == 'POST'"
                              }
                            ]
                          }
                        ]
                      }
                  vm_config:
                    runtime: envoy.wasm.runtime.null
                    code:
                      local: { inline_string: "envoy.wasm.attributegen" }

  2. You will have to create the Envoy filter mentioned above in the istio-system namespace with the following command:

    kubectl -n istio-system apply -f attribute_gen_service.yaml

  3. Open your override value file and add the telemetry with the necessary dimension. For more information on customizing you mesh, refer to the Aspen Mesh article: Customizing your mesh.

    #Custom metrics
    telemetry:
      v2:
        prometheus:
          configOverride:
            inboundSidecar:
              metrics:
                - name: requests_total
                  dimensions:
                      request_operation: "istio_operationId"
            outboundSidecar:
              metrics:
                - name: requests_total
                  dimensions:
                     request_operation: "istio_operationId"
            gateway:
              metrics:
                - name: requests_total
                  dimensions:
                     request_operation: "istio_operationId"

  4. Upgrade the helm installation for istiod using the newly edited file with the following command syntax:

    helm upgrade istiod <path to release>/manifests/charts/istio-control/istio-discovery -n istio-system --values sample_overrides-aspenmesh.yaml

  5. After the upgrade is done, you can check the envoy filter if the new metrics are added correctly. The output example below shows that we have successfully added request_operation as dimensions for requests_total metric:

    Note: The name of the envoy filter is stats-filter-1.9 because of the Aspen Mesh version 1.9.

    kubectl get envoyfilters -n istio-system stats-filter-1.9 -o yaml | grep metrics -A 3 –B3

  6. This step is the same as step 4 from the article K48274816: Custom metrics in Aspen Mesh, where you can see how to get your DefaultStatTags list. The only difference is the tag in this example is request_operation:

    apiVersion: apps/v1
    kind: Deployment
    spec:
      template: # pod template
        metadata:
          annotations:
            sidecar.istio.io/extraStatTags: request_operation

    As you can see request_operation is already in the DefaultStatTags list, so there was no need to annotate. If the dimension was not in the list, you would have to add the annotation.

  7. To verify if the new dimensions are collected in Prometheus, port-forward the pod to 15090 port and curl to grep for dimensions. For example:

    kubectl port-forward <review pod> <namespace>  15090:15090

    curl localhost:15090/stats/prometheus | grep 'request_operation'

    # TYPE istio_requests_total counteristio_requests_total{response_code="200",reporter="destination",source_workload="productpage-v1",destination_app="reviews",destination_version="v3",destination_service="reviews.default.svc.cluster.local",destination_service_name="reviews",destination_service_namespace="default",destination_port="9080",request_protocol="http",request_operation="GetReview",request_host="reviews:9080"} 291372

    Note: the GetReview operation is matched only when a GET request are generated for the reviews pod. You can do that via running a curl from a sleep pod in the same namespace with the following command syntax:

    kubectl exec -it <sleep-pod> -c sleep -- curl http://reviews.default.svc.cluster.local:9080/reviews/0
