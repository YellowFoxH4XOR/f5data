Known Issue

BIG-IP APM access sessions may log out unexpectedly.

This issue occurs when one of the following conditions are met:

  • The BIG-IP APM system is configured with a Citrix or VMWare View remote desktop access profile.
  • The BIG-IP APM portal access profiles use JavaPatcher settings.
  • A MobileSDK is used when accessing the BIG-IP APM system for per app Network Access or portal access profiles.

The probability of this issue occurring increases when the BIG-IP APM system is running 10 or more TMM processes.

Note: You can determine the number of TMM instances running on the BIG-IP APM system using the following command from the command line:

ps Hax | grep -c "tmm.[0-9]"

Impact

The BIG-IP APM system logs off established sessions.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H453736 on the Diagnostics > Identified >High screen.
  • The BIG-IP APM Access Policy > Manage Sessions active sessions counters for Bytes In and Bytes Out of the affected session may not increment.
  • The BIG-IP APM Access Policy > Manage Sessions session expiration timer for the affected session may not update.
  • The BIG-IP APM system logs out users when the Inactivity Timeout access policy is reached, regardless of session activity.
  • The /var/log/apm file may display error messages similar to the following example:

    notice tmm[tmm number][pid]: 01490505:5: a7538b22: RD: Connect to 10.10.19.18 port 2598 err ERR_OK
    notice tmm[tmm number][pid]: Session deleted due to user inactivity or errors.

    Note: These error messages will have a different tmm[tmm number] and [pid] values.
