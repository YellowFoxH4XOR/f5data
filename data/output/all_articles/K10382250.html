Description

When sending traffic through the BIP-IP and the virtual server is a wildcard ip-forward, then the traceroute will show the destination IP instead of the self IP.

Next is an example:

root@desktop:~# traceroute 1.1.9.2
traceroute to 1.1.9.2 (1.1.9.2), 30 hops max, 60 byte packets
 1  1.1.9.2 (1.1.9.2)  0.789 ms  0.719 ms  0.719 ms    >>>>>>>> Traffic arrives at BIG-IP and the hop shows destination IP instead of BIG-IP´s Self-ip 
 2  1.1.9.2 (1.1.9.2)  1.161 ms  1.151 ms  1.149 ms

Where 2.2.9.2 is the Big-ip´s Self-ip.

Environment

- Wildcard IP forwarding Virtual Server 
- Wildcard Virtual Address with ARP enabled

Cause

The reason is when ARP enabled (which is not the default value for network virtual-address on the BIG-IP) makes the BIG-IP system own from an ARP perspective all addresses in the IP/MASK range. Setting ARP enabled basically tells TMM we own this IP address.

For example>
ltm virtual-address /Common/0.0.0.0%1 {
    address any%1
    arp enabled  <<<<<< !!!
    icmp-echo disabled
    inherited-traffic-group true
    mask any
    server-scope none
    traffic-group /Common/traffic-group-1
}

Recommended Actions

Disable ARP in the Virtual Address
1. Navigate to Local Traffic  ››  Virtual Servers : Virtual Address List.
2. Disable ARP using the checkbox.

When ARP disabled, the output of the traceroute will be like
root@desktop:~# traceroute 1.1.9.2
traceroute to 1.1.9.2 (1.1.9.2), 30 hops max, 60 byte packets
 1  2.2.9.2 (2.2.9.2)  0.789 ms  0.719 ms  0.719 ms      <<<<<<====== Traceroute shows the self IP instead of destination IP
 2  1.1.9.2 (1.1.9.2)  1.161 ms  1.151 ms  1.149 ms
