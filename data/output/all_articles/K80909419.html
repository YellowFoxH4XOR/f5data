Topic

You should consider using this procedure under the following condition:

  • You want to configure in-TMM monitoring for Diameter pool members.

Description

Beginning in BIG-IP 16.0.0, you can configure in-TMM monitoring for Diameter pool members. The In-TMM monitor framework enables monitors to run in the context of a TMM instance rather than in the context of bigd, the BIG-IP monitoring process, which operates outside of TMM. The in-TMM monitor can significantly improve performance and allow for sub-second monitor requests.

When you configure in-TMM monitoring for Diameter, a monitor agent within TMM initiates the Diameter monitor probe messages according to parameters provided by the bigd and mcp processes. The monitor agent collects the Diameter responses and conveys the status information back to bigd, which marks pool members up or down. By performing the messaging inside TMM, both latency and the volume of communication outside TMM are reduced.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility or the TMOS shell (tmsh).

Procedures

Configuring in-TMM monitoring for Diameter pool members using the Configuration utility

To configure in-TMM monitoring for Diameter pool members using the Configuration utility, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Enter a name for the monitor.
  5. For Type, select Diameter.
  6. For Mode, select Message Routing and select either TCP or SCTP.
  7. Define the following remaining Diameter monitor options:
    • Interval: The number of seconds in which the system issues the monitor check when either the resource is down or the status of the resource is unknown. The default is 10.
    • Up Interval: The interval for the system to use to perform the health check when a resource is up. The default is Disabled.
    • Time Until Up: The number of seconds to wait after a resource first responds correctly to the monitor before setting the resource to up.
    • Timeout: The number of seconds the target has to respond to the monitor request. The default is 31 seconds.
    • Manual Resume: Whether the system automatically changes the status of a resource to Enabled at the next successful monitor check.
    • Origin Host: Indicates the IP address or host name from which the Diameter message originates. The default value is the fully-qualified domain name of the BIG-IP system.
    • Origin Realm: The Origin Realm, also referred to as the origin domain, identifies the source of the Diameter message, and must be present in all Diameter messages. The default is f5.com.
    • Host IP Address: Indicates the IP address of the diameter server.
    • Vendor ID: The vendor identification number assigned to your diameter server by the Internet Assigned Numbers Authority (IANA). The default is 3375, the IANA ID for F5.
    • Product Name: Indicates the vendor-assigned name for the product. The default is F5 BIGIP Diameter Health Monitoring.
    • Auth Application ID: The Authentication and Authorization (AA) identifier for a specific application, as specified in RFC 3588. The default is None.
    • Acct Application ID: The Accounting identifier for a specific application, as specified in RFC 3588. The default is None.
    • Vendor Specific Application ID: The vendor-specific grouped values for the diameter application, as specified in RFC 3588. The default is None.
    • Vendor Specific Vendor ID: The vendor identification number for the vendor-specific application.
    • Vendor Specific Auth Application ID: The authentication identification number for the vendor-specific application.
    • Vendor Specific Acct Application ID: The accounting identification number for the vendor-specific application.
  8. Select Finished.
  9. Associate the Diameter monitor with the appropriate pool resource.

Configuring in-TMM monitoring for Diameter pool members using the TMOS shell

To configure in-TMM monitoring for Diameter pool members using the TMOS shell, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the TMOS shell by entering the following command:

    tmsh

  2. Use the following syntax to create an in-TMM monitor for Diameter pool members:

    create /ltm monitor diameter <monitor_name> mode <mr-tcp/sctp> [options]

    For example, the following command creates an in-TMM Diameter monitor named MyDiameterMonitor using the TCP message routing mode, an interval of 5 seconds and timeout of 16:

    create /ltm monitor diameter MyDiameterMonitor mode mr-tcp interval 5 timeout 16

  3. Display the monitor configuration by entering the following command:

    list /ltm monitor diameter <monitor_name>

    For example, the following command lists the MyDiameterMonitor monitor configuration:

    list /ltm monitor diameter MyDiameterMonitor
    ltm monitor diameter MyDiameterMonitor {
        defaults-from diameter
        interval 10
        mode mr-tcp
        origin-realm f5.com
        product-name "F5 BIGIP Diameter Health Monitoring"
        time-until-up 0
        timeout 31
        vendor-id 3375
    }

  4. Save the configuration by entering the following command:

    save /sys config

  5. Associate the Diameter monitor with the appropriate pool resource.

Debugging the in-TMM Diameter monitor

You can troubleshoot issues with the in-TMM Diameter monitor by temporarily setting the log.tma.level db variable to Debug and reviewing debug log data for the monitor instance. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS shell by entering the following command:

    tmsh

  2. Set the log.tma.level db key to Debug by entering the following command:

    modify /sys db log.tma.level value Debug

  3. After allowing the monitor to run for a short time, set the log.tma.level database key back to the default value, Notice, by entering the following command:

    modify /sys db log.tma.level value Notice

  4. Review debug log data by entering the following command:

    show /sys log ltm
