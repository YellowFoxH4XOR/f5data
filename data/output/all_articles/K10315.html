Known Issue

This is the result of a known issue. The BIG-IP WebAccelerator may incorrectly insert the PvInfo S10201 code into a response that is configured in the policy to not be cached.

This issue can occur with multiple HTTP response codes. For example, a 307 (Temporary Redirect) response code from the web server will result in a PvInfo S10201 code when the response is sent to the client.

Note: HTTP code 307 is configured by default within the Level 2 delivery policy to not be cached.

The S10201 code states the following:

Request was sent to the origin web server, because it was for new content. The WebAccelerator system caches the response from the origin web server for future requests, before responding to the request. The WebAccelerator system will respond to future request for this content, from cache.

This message implies that the response will be cached by the BIG-IP WebAccelerator; however, the request will be proxied according to the policy configuration, and the response will not be cached.

Instead, the BIG-IP WebAccelerator should insert the more appropriate S10203 code, which is defined as follows:

Response was sent to the origin web server, in accordance with an acceleration policy. When the WebAccelerator system matches a request to a node with an acceleration rule set to always proxy, the WebAccelerator system will send that request to the origin web server, rather than serving it from cache.

Note: For a list of PvInfo codes, refer to the Using HTTP Headers chapter of the Policy Management Guide for the BIG-IP WebAccelerator System.

Note: The behavior described in this Solution is cosmetic only and does not affect the functionality of the BIG-IP WebAccelerator.

F5 Product Development tracked this issue as ID 222774 (formerly CR124262) and it was fixed in BIG-IP WebAccelerator version 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.
