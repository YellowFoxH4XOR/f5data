Known Issue

Traffic Management Microkernel (TMM) may exit and restart on standby devices when connection mirroring is enabled.

This issue occurs when all of the following conditions are met:

  • The standby unit in a high availability system has a User Datagram Protocol (UDP) Session Initiation Protocol (SIP) monitor configured.
  • The BIG-IP system has connection mirroring enabled for either of the following two listener objects:

    • A virtual server using a FastL4 profile configured with a wildcard IP address and port
    • A secure network address translation (SNAT) listener object configured with a wildcard IP address and port
  • SIP monitor packets sent by the standby system are routed to the active unit, possibly by a routing loop, and are sent back to the standby system due to the mirroring configuration.

Impact

The standby unit is unavailable for failover events while the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system generates a TMM core file to the /shared/core/ directory.
  • The BIG-IP system logs a message in the /var/log/tmm file that appears similar to the following example:

    panic: ../modules/hudproxy/ha/ha_proxy.c:1804: Assertion "non-zero ha_unit required for mirrored flow" failed.

  • The BIG-IP system logs messages in the /var/log/ltm file that appear similar to the following example:

    emerg logger: Re-starting tmm

Workaround

If the pool members being monitored allow for the use of TCP, you may be able to mitigate this issue by changing the SIP monitor to use TCP mode rather than UDP mode. To do so, perform the following procedure:

Note: This workaround requires BIG-IP 11.4.1 HF6 or later, due to the fix provided for the issue described in K14752: The TMM daemon on the standby device may unexpectedly restart when receiving mirrored connections.

Impact of workaround: The following procedure configures the SIP monitor to use the TCP protocol and will not work for services using UDP only.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Local Traffic > Monitors and click the name of the SIP monitor.
  3. Change the Mode setting for the monitor to TCP.
  4. To save the change, click Update.
