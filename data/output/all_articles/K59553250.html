Description

When attempting to restore a UCS file, on GUI installation status or the following command output has similar to the below:
tmsh show /sys software
--------------------------------------------------------
Sys::Software Status
Volume  Product  Version   Build  Active  Status
--------------------------------------------------------
MD1.1    BIG-IP 12.1.5.2  0.0.10     yes  complete
MD1.2    BIG-IP   13.1.5  0.0.32      no  failed (UCS application failed; unknown cause.)

/var/log/liveinstall.log has similar to the below output: 
 
Installing full UCS (15.1.0.2) data, excluding license file.
Extracting manifest: /var/local/ucs/<ucs_filename>.ucs
/var: Not enough free space
        1647800320 bytes required
        1572659200 bytes available
/var/local/ucs/<ucs_filename>.ucs: Not enough free disk space to install!
Operation aborted.
Unexpected Error: UCS loading process failed.
 

Environment

  • BIG-IP
  • v11.6 - v16.1.x
  • UCS restore 
  • Upgrade / installation
     

Cause

The cause could be related to one of the following issues:

  • Available size of /var 
  • Bug ID 924429
  • UCS file size is more than 1GB 
     

Recommended Actions

If UCS file is more than 1GB then follow: K92426918: Upgrade failed with /var/local/ucs/config.ucs: Not enough free disk space to install

To determine which issue the BIG-IP is experiencing, refer to the following steps.
  • Verify the available size of /var by running the following command:

    df -B1

    If the output of the available size of /var is less than the bytes required reported in the aforementioned error message, then refer to K14403: Maintaining disk space on the BIG-IP system, to find out what is occupying the partition.
  • Check the actual space required to restore the UCS for /var partition by running the following command:

    tar ztvf </path/to/ucs> | grep var/ | grep -v var/tmp/ | awk 'BEGIN {sum=0} {sum+=$3} END {print sum}'

    If the command output is less than the df command output of the available size of /var, then you may be encountering Bug ID 924429. 
     
  • Check the actual required space to restore the UCS for /var/tmp partition, by running the following command:

    tar ztvf </path/to/ucs> |grep var/tmp | awk 'BEGIN {sum=0} {sum+=$3} END {print sum}' 

    If the command output is less than the df command output of the available size of /shared, then you may be encountering Bug ID 924429. 
     
  • Check the actual size of the UCS file. Refer to the recommended actions section of the following KB article for details: K92426918: Upgrade failed with /var/local/ucs/config.ucs: Not enough free disk space to install


Once you confirmed your issue is due to Bug ID 924429, then

  1. Make it offline
     
  2. Create UCS archive, and save to local machine (check md5sum is recommended)
    NOTE: On BIG-IP CLI, you can run one of them:
    sha1sum /var/tmp/<file_name>
    md5sum /var/tmp/<file_name>
     
  3. Disable making ucs and transferring ucs while installing new ios, running:
    tmsh modify sys db liveinstall.moveconfig value disable
    tmsh modify sys db liveinstall.saveconfig value disable
    NOTE: please refer what this change means: K13438: Controlling configuration import when performing software installations
     
  4. Install new OS to new boot location and reboot.
    NOTE:  the new boot location have only basic config.
     
  5. Once it is booted, run the below command to make it offline:
    tmsh run /sys failover offline
     
  6. Then upload the ucs file taken in step 2, and restore the ucs file on GUI.
     
  7. Once config is loaded, double check the config then release offline, and initiate configsync from Active to Standby.
