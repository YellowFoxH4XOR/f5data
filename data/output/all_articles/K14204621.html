Description
X509::subject iRules command is not working after upgrading to BIG-IP 12.1.4.1 and above (for BIG-IP 12.x) or BIG-IP 13.0.0 and above (for other BIG-IP products).

Environment

  • BIG-IP 13.0.0 and above
  • BIG-IP 12.1.4.1 and above for BIG-IP 12.x family

Cause
Old Behavior

In versions prior to BIG-IP 13.0.0 and BIG-IP 12.1.4.1, the X509::subject iRules command returns the subject of the specified X509 certificate in an order similar to the following example:

CN=USERNAME,OU=CONTRACTOR,OU=PKI,OU=DEPT,O=COMPANY,C=US

New Behavior

Beginning in BIG-IP 13.0.0 and BIG-IP 12.1.4.1, the X509::subject iRules command returns the subject of the specified X509 certificate in an order that is compatible with OpenSSL. The new order is similar to the following example:

C=US,O=COMPANY,OU=DEPT,OU=PKI,OU=CONTRACTOR,CN=USERNAME

F5 Product Development tracked this change as Bug ID 607410.

If you have existing iRules that depend on the order of the output of the X509::subject iRules command in a version prior to BIG-IP 13.0.0, and you upgrade the system to BIG-IP 13.0.0 or later, the iRules may not function as expected.

Recommended Actions
Depending on your existing iRules, you may need to modify your existing iRules to expect the new order of output from the X509::subject iRules command after an upgrade to BIG-IP 13.0.0 or later.

Additional Information
The X509::issuer command is also impacted by this formatting change.
