K000161770: Changing the BIG-IP AWAF Attack Signature Set configuration through the REST API may cause signatureCount to display as 0

Type
Support Solution
Published
2026-07-29
Updated
2026-07-29
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000161770

Description

A REST API PATCH request to an AWAF Attack Signature Set can return HTTP status 200 while reporting signatureCount: 0 in the response and Configuration utility. The same cosmetic value may appear in the Attack Signature Set list even though the signatures remain associated and enforced.

Environment

  • BIG-IP ASM/AWAF
  • REST API endpoint:

    /mgmt/tm/asm/signature-sets/<signature_set_id>

  • Attack Signature Set types:
    • User-defined, filter-based signature sets

Cause

A known BIG-IP issue can cause the signatureCount value to be reported as 0 when a REST API PATCH request contains an incorrectly structured JSON payload or when the same request is submitted repeatedly. This is a cosmetic issue; the associated signatures remain available and enforced.

Recommended Actions

  1. Use a correctly structured JSON payload when updating an existing Attack Signature Set.
  2. Ensure that the request changes at least one parameter.
  3. Treat signatureCount: 0 as a cosmetic reporting issue when the set otherwise functions correctly.
  4. Verify the Attack Signature Set and associated policies after the update.
