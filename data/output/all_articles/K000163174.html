K000163174: BIG-IQ Centralized Management MCPD instability after copying SNMP configuration from a different appliance

Type
Support Solution
Published
2026-09-03
Updated
2026-09-03
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.4.X, 8.4.2, 8.4.1, 8.4.0
Source
https://my.f5.com/manage/s/article/K000163174

Description

A BIG-IQ Centralized Management HA pair may become inaccessible through the GUI while CLI commands fail because MCPD repeatedly disconnects and restarts. The license may display as INOPERATIVE as well.

Logs may contain:

Error: failed to reset strict operations; disconnecting from mcpd.
The connection to mcpd has been lost, try again.
Master Key decrypt failure - decrypt failure - final
Unable to encrypt application variable

Environment

  • BIG-IQ Centralized Management
  • SNMP trap and user configuration copied and pasted from a different system

Cause

  • Bug ID 1455805: MCPD unstable or inoperative after copying SNMP configuration from another BIG-IP system.
  • Encrypted SNMP attributes were copied from a different system and pasted on to the BIG-IQ Centralized Management device configuration. Because the encrypted values cannot be decrypted with the receiving device's master key, MCPD becomes unstable or inoperative.

Answer/Recommended Actions

  1. Remove the entire SNMP trap and user configuration blocks (not only the line with the encrypted value) from the affected BIG-IQ base configuration (/config/bigip_base.conf)
  2. Run the "tmsh load sys config" command.
  3. Follow steps 4 and 5 from section K13030.
  4. Perform the same recovery procedure on the peer BIG-IQ system if it exhibits the same MCPD instability.
  5. Confirm that the GUI, CLI, MCPD service, and license status have returned to normal.
  6. Re-establish the BIG-IQ HA relationship after both systems are operational.
  7. Configure SNMP independently on each BIG-IQ system. Do not copy SNMP configuration containing encrypted attributes between disparate devices.
