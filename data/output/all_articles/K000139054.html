Description

  • Getting 404 error while Loading FAST Templates on "iApps >> Application Services : Aplications LX -> F5 Application Services Templates"
  • An error similar to the following appear on the GUI

Failed to get data from /mgmt/shared/fast/templatesets?userAgent=FASTGUI/NA: 404 Not Found

  • A log message similar to the following can be seen on var/log/restnoded/restnoded.log

info: FAST Worker: Entering UNHEALTHY state: Unable to read data group /Common/f5-appsvcs-templates/dataStore: Unexpected string in JSON at position 46

Environment

  • BIG-IP
  • FAST v1.25.0
  • Custom FAST template named with spaces (Ex: My custom Fast Template.zip)

Cause

The seen behaviour is caused by a known issue tracked with the Bug ID 1396949 "Installing template set named with a space breaks a FAST on update".

Recommended Actions

This issue will be fixed in the next FAST release v1.26.0. To workaround the issue, you can perform the following steps:

1. Connect to device CLI

2. Locate the internal data-group faulty records on f5-appsvcs-templates/dataStore that needs to be deleted

tmsh list ltm data-group | grep -A46 "f5-appsvcs-templates/dataStore" | grep -v data | grep -v "bigip-fast-" | egrep -v "}"

Example:  If the uploaded custom FAST template name is "My Custom Fast Template.zip" the output should look like:

tmsh list ltm data-group | grep -A46 "f5-appsvcs-templates/dataStore" | grep -v data | grep -v "bigip-fast-" | egrep -v "}"
records {
My {
Custom0 {
Custom1 {
Fast {
Template {
examples0 {

3. Delete faulty data-groups records from f5-appsvcs-templates/dataStore

Example:

tmsh modify ltm data-group internal f5-appsvcs-templates/dataStore { records delete { My Custom0 Custom1 Fast Template } }

4. Save the configuration changes

tmsh save sys config

5. Restart restjavad and restnoded

bigstart restart restjavad restnoded

6. Verify access to the FAST templates via GUI

7. Re-import the "My-Custom-Fast-Template.zip" Template set, making sure that there are no spaces in the folder/file name.
