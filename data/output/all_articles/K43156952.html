Description

  • You upgrade your BIG-IP to version range 13.1.0 to 14.0.1.1
  • You boot onto the new volume and notice that application/virtual server stopped processing traffic
  • However, all the configuration on the BIG-IP seem in good working order 
  • A tcpdump output would show the virtual server resetting connection with 'No local listener' cause

2    13.985464    1.1.1.1    2.2.2.2    TCP    112    IN  s1/tmm3 : 55192 → 443 [SYN] Seq=0 Win=64240 Len=0 MSS=1452 WS=256 SACK_PERM=1
3    13.985485    2.2.2.2    1.1.1.1    TCP    126    OUT s1/tmm3 : 443 → 55192 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0 [F5RST: No local listener]   <---
6    14.646047    1.1.1.1    2.2.2.2    TCP    112    IN  s1/tmm3 : [TCP Retransmission] 55192 → 443 [SYN] Seq=0 Win=64240 Len=0 MSS=1452 WS=256 SACK_PERM=1
7    14.646067    1.1.1.1    1.1.1.1    TCP    126    OUT s1/tmm3 : 443 → 55192 [RST, ACK] Seq=1 Ack=1 Win=0 Len=0 [F5RST: No local listener]          <----

RST cause: [28dffda:2289] No local listener
    Length: 26

    .... ...0 = Peer: 0

    Line: 2289
    Cause: No local listener        <---- 

  • On the BIG-IP, a 'No local listener' reset cause is as a result of system receiving a SYN packet for a non-existent port on a virtual address or the source address not matching the virtual server allowed source address configuration.

 

Environment

  • LTM
  • Virtual Server

 

Cause

  • Bug ID 815825

 

Recommended Actions

  • You would need to delete and recreate all affected virtual-servers.
  • Affected virtual servers must be deleted from all BIG-IPs in a cluster
  • If the BIG-IP is an HA mode and auto sync is not enabled, the deletion and recreation of virtual servers must be synced at each stage.  

 

Additional Information

  • To verify if you are affected by described issue, enable reset cause on the BIG-IP and take a packet capture
  • To enable reset cause, access the BIG-IP from Command line and issue tmsh command 

tmsh modify /sys db tm.rstcause.log value enable

tmsh modify /sys db tm.rstcause.pkt value enable

  • Use tcpdum syntax filtering using a < client's IP address >

 tcpdump -nni 0.0:nn -s0 host < client's IP address > -w /var/tmp/<filename>.pcap

  • To disable reset cause, access the BIG-IP from Command line and issue tmsh command 

tmsh modify /sys db tm.rstcause.log value disable

tmsh modify /sys db tm.rstcause.pkt value disable
