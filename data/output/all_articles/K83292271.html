Description

  • The asm process keeps restarting
     
  • The /var/log/ltm file shows messages similar to below, indicating the unit has become offline 
    warning sod[8794]: 01140029:4: HA proc_running bd fails action is go offline and down links.
    notice sod[8794]: 010c0054:5: Offline for traffic group traffic-group-1.
    notice sod[8794]: 010c003e:5: Offline
     
  • The /var/log/asm file shows repeated messages similar to below
    crit perl[2437]: 01310027:2: ASM subsystem error (asm_start,F5::ASMStart::__ANON__): DBD::mysql::db column_info failed: Can't create/write to file '/var/tmp/#sql_6468_0.MAI' (Errcode: 13) at /usr/local/share/perl5/F5/DbUtils.pm line 205.
     

Environment

  • BIG-IP ASM
  • ASM process restarting
  • Offline Status

Cause

  • /var/tmp has become inaccessible to ASM as a result of a recent change to SELinux permissions.
     
  • As shown below the SELinux user context is showing as 'unconfined_u:' instead of 'system_u' .
    ls -Z /var/tmp /shared/ | egrep tmp
    lrwxrwxrwx. root root unconfined_u:object_r:tmp_t:s0   /var/tmp -> ../shared/tmp
    drwxrwxrwt. root root   unconfined_u:object_r:tmp_t:s0   tmp 

Recommended Actions
Use the restorecon command to restore the context to the correct value.

  1. First, run a passive test, to confirm the expected result without actually making any changes.
    restorecon -Fvn /var/tmp /shared/tmp
    restorecon reset /var/tmp context unconfined_u:object_r:tmp_t:s0->system_u:object_r:tmp_t:s0
    restorecon reset /shared/tmp context unconfined_u:object_r:tmp_t:s0->system_u:object_r:tmp_t:s0
     
  2. Make the actual changes after confirming the expected results.
    restorecon -Fv /var/tmp /shared/tmp
     
  3. Validate the expected changes have taken place.
    ls -Z /var/tmp /shared/ | egrep tmp
    lrwxrwxrwx. root root system_u:object_r:tmp_t:s0       /var/tmp -> ../shared/tmp
    drwxrwxrwt. root root   system_u:object_r:tmp_t:s0       tmp
     
  4.  Restart the asm process 
    tmsh restart sys service asm
