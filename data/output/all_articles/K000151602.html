K000151602: VLAN listeners re-created as RBCAST listeners after VELOS system controller reboot

Type
Support Solution
Published
2025-05-30
Updated
2025-05-30
Applies to
  • F5OS
  • F5OS-C: 1.6.X, 1.5.X, 1.6.2, 1.6.1, 1.6.0, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000151602

Description

After rebooting VELOS system controllers, one or more VLAN listeners were incorrectly created as RBCAST listeners, with additional service ID 1.

default-1# show vlan-listeners | nomore
                                          NDI                                             SERVICE
INTERFACE  VLAN  ENTRY TYPE     OWNER     ID    SVC  VTC  SEP  DMS  DID  CMDS  MIRRORING  IDS
---------------------------------------------------------------------------------------------------
lag01      1100  RBCAST-LISTENER rbcast    4095  5    56   15   3    -    -     disabled   [ 1 10 ]
...

Environment

  • VLAN listeners
  • Static FDB entries configured

Cause

  • Bug ID 1355277: Incorrect Vlan Listeners when a Static FDB is configured

Recommended Actions

Bug ID 1355277 is fixed in F5OS-C 1.8.0 onwards, so an upgrade is recommended in the first instance.

Otherwise, to avoid this issue, remove any static FDB entries and add them back after rebooting the VELOS system controllers.

To recover from the issue once the errant RBCAST listeners are created, delete the static FDB entries and reboot the controllers once more. Then remove and re-attach the VLAN from any tenants that use it.

Additional Information

The problem could also happen without a reboot:

  • Disable and re-enable of the partition
  • Crash of the network-manager process
  • OOM kill towards the network-manager process
  • User action towards the network-manager process

The problem does not happen if the partition fails over to the peer controller.
