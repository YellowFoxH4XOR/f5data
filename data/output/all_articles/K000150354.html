Source

Description

  • You have LTM and APM provisioned. After changing APM resource provisioning from Nominal to Minimum, Tomcat daemon continuously restarts and unable to access BIG-IP GUI.
  • You see no java.lang.OutOfMemoryError messages.
  • But you see OOM killer for java.
  • Messages similar to the following can be seen on /var/log/secure and you had followed this K000139561: Standby device tomcat getting OutOfMemoryError and constantly restarting and issue did not get fixed.
    notice su[8660]: (to tomcat) root on none
    warning su[8660]: pam_lastlog(su:session): corruption detected in /var/log/btmp

Environment

  • LTM and APM provisioned

Cause

OOM killer logs are caused by the system having insufficient 4KB page (also known as host) memory. The Linux kernel OOM killer typically will kill a process holding large amounts of resident 4KB page memory, and restjavad is a typical victim.

You can think of 4KB page memory as ordinary memory and it's the default page size. The other type, huge pages gets set up soon after startup. Depending on what modules are provisioned between 50% and 90% of physical memory will be provisioned as huge pages, the rest left as the default 4KB pages.

The sys db provision.extramb can be used to shift the boundary between 4KB page memory and huge page memory so that there will be more 4KB page memory. This may be necessary if the problem is simply more 4KB page memory is needed rather than say a process, or the kernel, using unusually high amounts of 4KB page memory.

Recommended Actions

Check and Increase the memory of below db variables. If accessing tmsh directly you can omit 'tmsh'.

tmsh list sys db provision.extramb 

It may be sensible to increase the value found above by 500 to 1000 MB. It's rarely needed for the total to be above 2000.

tmsh modify sys db provision.extramb value 1000

Important: Changing the value of sys db provision.extramb causes an immediate reprovisioning that restarts all F5 processes and will be service affecting on active units. It needs to be changed on each peer of a Device Service Cluster, one at a time,  as the value is purposefully not synchronised between peers. It usually completes within five minutes on a LTM only system and may take up to 15 minutes with ASM provisioned.
