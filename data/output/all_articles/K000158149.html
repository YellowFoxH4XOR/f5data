K000158149: Specific user randomly losing permissions using remote LDAP authentication

Type
Support Solution
Published
2025-12-10
Updated
2025-12-10
Source
https://my.f5.com/manage/s/article/K000158149

Description

A user account loses all permissions on multiple BIG-IP HA pairs. When this occurs, the user cannot access the system, and audit logs display errors for example:

error: PAM: User account has expired for xxxxxx from X.X.X.X

user xxxxxx - RAW: httpd(pam_audit): user=xxxxx(xxxxxx) partition=(unknown) level=(unknown)

Unable to authenticate using any of the configured authentication methods.

Environment

BIG-IP

Authentication Method: Remote authentication via LDAP (no local accounts used)

Cause

The issue is caused by a problem with the remote LDAP authentication server.

The error message "User account has expired" originates from the LDAP server, not from the BIG-IP device.

Since local accounts are not used, BIG-IP cannot change or lock user account status, only remote authentication controls access.

Recommendations

Restoring access is possible by manually re-adding the role to the affected user account in the remote authentication server.

Check the LDAP server for issues related to account status, expiration, or policy restrictions affecting impacted users.

Confirm that affected LDAP accounts are active and not expired or locked.
