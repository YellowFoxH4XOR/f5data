Known Issue

Access policy network access handling may trigger the Traffic Management Microkernel (TMM) to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access policy that assigns the network access IP address for the Virtual Private Network (VPN) access session.
  • Your BIG-IP APM configuration does not have a lease pool configured.
  • The access policy processes an access session.

Impact

The TMM process produces a core file and restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system generates a TMM core file in the /shared/core directory.
  • Your BIG-IP APM system logs a SIGSEGV to the /var/log/tmm file.
  • Your BIG-IP APM system temporarily fails to process traffic and may fail over to another host in the device group.

Workaround

To work around this issue, you can create an unreferenced network access lease pool. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to Access Policy > Network Access > Lease Pools IPv4 Lease Pools.
  3. Click Create.
  4. Enter a name for the lease pool in the Name text box.
  5. Click Finished.

Note: You do not need to assign the lease pool to the network access profile or access policy configuration.
