K000152523: After creating a 40 Gb bundle 1.x members display UNINITIALIZED

Type
Support Solution
Published
2025-09-10
Updated
2026-01-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0
Source
https://my.f5.com/manage/s/article/K000152523

Description

After creating a 40 Gb bundle, Network › Interfaces and tmsh show net interface display the 1.x members as UNINITIALIZED, while the 2.x bundled interface shows the operational state and counters.

Symptoms

  • 1.x interfaces report UNINITIALIZED and have no traffic stats.
  • Only the 2.x bundled interface carries link state, speed, and counters.

Error messages

  • None; only the UNINITIALIZED state appears for 1.x entries.

Environment

  • BIG-IP platforms that support 40 Gb bundles (e.g., iSeries/rSeries/VELOS).
  • A 40 Gb logical interface (2.x) is configured using underlying 10 Gb lanes (1.x).

Cause

When 10 Gb ports (shown as 1.x) are combined into a 40 Gb bundled port (2.x) on BIG-IP, the individual 10 Gb entries appear as UNINITIALIZED. This is expected.

Recommended actions

  • Do nothing: This state is expected behavior and has no impact on traffic.

Additional information

At this time, there is no way to change the state of the 1.x interface entries when they’re part of a bundled 2.x interface; they remain UNINITIALIZED because they’re no longer assigned to an active physical interface. This is how the software currently functions.

An interface bundle is a collection of interfaces which work as a single interface in order to support the aggregate bandwidth of all of them. For example, QSFP+ interfaces form a 40Gbps interface bundle out of 4 SFP+ interfaces. On platforms that include 40GbE interface ports, they can be configured as a single 40GbE port (bundled) or as four 10GbE SFP+ ports (unbundled).
