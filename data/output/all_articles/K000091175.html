K000091175: Use default wildcard certificate for virtualserver type resources in Nginx Plus Ingress Controller

Type
Support Solution
Published
2021-12-16
Updated
2021-12-16
Source
https://my.f5.com/manage/s/article/K000091175

Description

  • A requirement to use VirtualServer resources
  • When not specifying/indicating a TLS secret, VirtualServer does not support https
  • Can we force VirtualServer resources to use a default cert/key when not specifying a custom TLS

 Environment

  • VirtualServer resources
  • VirtualServerRoute resources
  • Ingress resources

 Cause

  • None

 Recommended Actions

  • None

 Additional Information

  • VirtualServer and VirtualServerRoute resources are an alternate to Ingress resource and the objectives are to enable use cases not supported with the Ingress resource.
  • TLS termination is one of the features available for us to use but is NOT a required filed.
  • Meaning, when not specifying secret, it would assume the connection to be of type HTTP.
  • When defining 'secret',
    • It must belong to the same namespace as the VirtualServer.
    • The secret must be of the type kubernetes.io/tls
    • It must contain Certificate/key named tls.crt and tls.key
  • https://docs.nginx.com/nginx-ingress-controller/configuration/virtualserver-and-virtualserverroute-resources/
  • If the secret doesn’t exist or is invalid, NGINX will break any attempt to establish a TLS connection to the host of the VirtualServer". If we do not define cert/key in VirtualServer.TLS secret filed, then NIC would not provide https.
