Description

After upgrading to v15.*, Carrier Grade NAT does not show LSN pool and there is no apparent way to apply LSN pools to virtual server.
Existing CGNAT virtual server is working as normal.

Environment

  • BIG-IP v15.* and later
  • CGNAT
  • LSN pool
     

Cause

CGNAT functionality has been migrated in to the BIG-IP AFM module.

The new AFM CGNAT implementation and legacy (v14.* and previous) CGNAT implementation are not compatible. However, the legacy CGNAT functionality and objects are still available on v15.

Recommended Actions

To access the legacy CGNAT implementation configuration in the GUI:
  1. Navigate to Carrier Grade NAT >> Options
  2. Check Enabled for Legacy LSN Pools Editor
  3. Click Update

    NOTE: CGNAT virtual should be created and modified on CGNAT module on GUI.
     

Additional Information

Legacy CGNAT implementation and new AFM + CGNAT implementation are not compatible and can not be both configured.
If you want to migrate legacy CGNAT implementation to the new AFM CGNAT implementation, please contact our Professional service.


To configure CGNAT object in new AFM CGNAT implementation in the GUI:
Note: AFM CGNAT configuration objects required the system to be provisioned for CGNAT, but do not require the system to licensed or provisioned for AFM.

    LSN pool: 
    1. Carrier Grade NAT >> Policies >> Source Translation
    2. Click Create
    3. Select dynamic-pat for Type 
    4. fill others as required.
    5. Click Save


      CGNAT rules (legacy CGNAT virtual)
      1. Carrier Grade NAT >> Policies >>
         Policy List
      2. Click Create
      3. Fill object name
      4. Click Add Rule
      5. Select LSN pool for Translated Source
      6. Fill others as required
      7. Click Commit Changes to System.
