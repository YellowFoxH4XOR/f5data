Topic

The Client Certificate Constrained Delegation (C3D) feature enables the BIG-IP system to perform client authentication tasks when end-to-end encryption in a reverse proxy environment is required.

Description

When the C3D feature is enabled for a virtual server, the BIG-IP system dynamically generates a client certificate on behalf of the client when receiving a certificate request message from the backend server. The C3D feature is designed to address the following security requirements:

  • Client certificate authentication
  • End-to-end encryption in a reverse proxy environment
  • Perfect Forward Secrecy (PFS)
  • Ability to validate the client certificate using the Online Certificate Status Protocol (OCSP)

When the C3D feature is enabled, the BIG-IP system can dynamically create a delegated client certificate by inserting constraining values into the client certificate. The C3D feature works as follows:

  • The client completes a TCP handshake with the BIG-IP virtual server.
  • The client initiates the SSL handshake by sending a ClientHello message to the BIG-IP system.
  • The BIG-IP system replies with a ServerHello message.
  • If C3D is configured, the BIG-IP system sends a certificate request to the client.
  • The client responds with a client certificate.
  • If OCSP is configured, the BIG-IP system contacts the OCSP responder to validate the client certificate.
    • The OCSP responder returns the certificate status to the BIG-IP system. (If the certificate is revoked or the status is unknown, the BIG-IP system drops the connection.)
  • The client-side SSL handshake is complete.
  • The BIG-IP system initiates the SSL handshake with the server.
  • The server sends a client certificate request.
  • The BIG-IP system dynamically creates a new client certificate based on the information in the original certificate obtained from the client.
  • The server-side SSL handshake is complete.

Recommendations

When planning the C3D feature, you should consider the following factors:

  • Verify that the following SSL certificates are in place:
    • A Certificate Authority (CA) bundle that contains the root or intermediate CA certificates needed to validate any expected clients.
    • The SSL certificates and keys required for the SSL profile.
    • A CA certificate and key that has the ability to create new certificates. The BIG-IP system uses this certificate/key pair to forge the client certificates.
  • If you plan to use OCSP to validate client certificates, you should have a valid OCSP object. For more information, refer to K75106155: Configuring OCSP stapling (13.x - 15.x).
  • For information about configuring the C3D feature, refer to the SSL Traffic Management chapter of the BIG-IP System: SSL Administration manual.
