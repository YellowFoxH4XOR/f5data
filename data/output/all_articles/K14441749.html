K14441749: Configuration does not load after upgrade with error: Load_config_files: ''/usr/bin/tmsh -n -g load sys config partitions all '' - failed. -- Loading schema version: 13.1.3

Type
Support Solution
Published
2022-04-08
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.1.3
Source
https://my.f5.com/manage/s/article/K14441749

Description
After an upgrade of the BIG-IP device and error similar to the following is logged to /var/log/ltm:

load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- Loading schema version: 13.1.3 Loading schema version: 13.1.3.6 01070712:3: Failed: name (/Common/epsec-1.0.0-679.0.iso) Cache path (/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-679.0.iso_41376_1) does not exist and there is no copy in trash-bin to restore from. Unexpected Error: Loading configuration process failed.

Note: This error message can be reproduced on the affected device by running the following TMSH command: tmsh load /sys config verify.

Environment

  • BIG-IP APM
  • Upgrade

Cause
There is a missing reference to file in configuration

Recommended Actions

Revert upgrade to the previous partition and verify syntax of the configuration using below procedure:
  1. Log on to the command line of the BIG-IP.
  2. If you are not comfortable with troubleshooting the BIG-IP system and editing the /config/bigip.conf file, proceed to step 3.

    If you are comfortable and familiar with troubleshooting the BIG-IP system, you can try addressing the error. To do so, refer to the following:

    • Determine the configuration objects causing the load failure and investigate a resolution procedure in K02091043: Error Message: The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.

    • The Recommended Actions in K23934354: Cache path (/config/filestore/files_d/<Partition>_d/ifile_d/:<Partition>:<Filename>_<revision number>) does not exist and there is no copy in trash-bin to restore from. for more information on addressing the error.

  3. Boot the BIG-IP back to previous volume:
    switchboot
  4. Save configuration:
    tmsh save sys config
  5. Perform configuration verification:
    tmsh load sys config verify
  6. If no warnings are present boot back from the Configuration utility in to the new volume with copy configuration
    Example Configuration utility path:
    System > Software Management > Boot Locations > Click on newly installed boot location > Copy Configuration > YES
  7. If the configuration fail to load such as with the error in the Description section, you need to address the error before upgrading again. To do so, refer to the Determine the configuration objects causing the load failure and investigate a resolution procedure in K02091043: Error Message: The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
