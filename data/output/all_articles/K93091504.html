K93091504: Cannot see any event logs for BIG-IP ASM. Security logging stopped working

Type
Support Solution
Published
2020-01-28
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K93091504

Description

  • BIG-IP ASM logs are not stored locally and remote logging may have also stopped
  • BIG-IP ASM event logs are not displayed in the GUI on Security  > Event Logs  > Application > Requests
  • BIG-IP ASM stopped logging new application security events
  • Messages similar to the following appear in pabnagd.log:

    account |NOTICE|... src/Account.cpp:183|Skipped 36 repeated messages. Request Log protobuf subscription queue is full. Message dropped.
    rqlgwriter |WARNIN|... src/RequestLogWriter.cpp:137|Skipped 599 repeated messages. No space to write in shmem.

Environment

  • BIG-IP ASM application security event logs previously working

Cause
Bug ID 727107: Request Logs are not stored locally due to shmem pipe blockage

Recommended Actions

Upgrade to a version where the issue is fixed.  Visit the above link to ID727107 for information on which BIG-IP versions include a fix for this issue.

Alternatively, as a workaround you can perform the following procedure:

Note: Traffic on the device is not impacted when restarting these services for ASM. 

  1. Connect to BIG-IP CLI
     
  2. Restart pabnagd by executing following command from BIG-IP bash shell:
    pkill -f pabnagd
     
  3. Wait for around 15 seconds
     
  4. Restart asmlogd by executing following command from BIG-IP bash shell:
    pkill -f asmlogd
     
  5. Wait for around 15 seconds

Additional Information
Upgrading to BIG-IP software version 15.1 and later may help prevent similar issues due to changes included in ID 767941. In version 15.1 and later, the system now handles Policy Builder errors gracefully and reduces Policy Builder down time upon connectivity loss with ASM.
