Known Issue

This is the result of a known issue. If an unrecognized HTTP method does not contain a specified content-length or chunking header, it can cause the connection to stall.

This behavior occurs on virtual servers configured with an HTTP profile. In these configurations, the HTTP profile waits for headers before it begins processing the body of the message. Additionally, this behavior occurs in configurations where these headers do not exist and no body exists. As a result, the request is never passed to the server.

F5 Product Development tracked this issue as CR73219, and it was fixed in BIG-IP LTM versions 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Note: Web-based Distributed Authoring and Versioning (WebDAV) uses the following HTTP methods, which may provoke this behavior: PROPFIND, PROPPATCH, MKCOL, DELETE, COPY, MOVE, LOCK, UNLOCK.
