Issue

This article applies to BIG-IP 11.x and later. For information about other versions, refer to the following article:

  • K10278: Error Message: A virtual server may reference a virtual address in the same partition or the common partition

Error Message

01070726:3: virtual server <Partition/Virtual_Name> in partition <Partition> cannot reference virtual address <Partition/Virtual_Addr> in partition <Partition>

In this error message, note the following:

  • <Partition/Virtual_Name> is the partition and name of the affected virtual server.
  • <Partition> is the partition in which you are attempting to create the new virtual server.
  • <Partition/Virtual_Addr> is the partition and IP address of the affected virtual address.
  • <Partition> is the partition that contains the virtual address object.

For example:

01070726:3: virtual server /Common/myvip in partition Common cannot reference virtual address /Uncommon/0.0.0.0 in partition Uncommon

Message Location

You may encounter this message in the following locations:

  • The /var/log/ltm file
  • The Configuration utility

Description

This message occurs when the following condition is met:

  • You attempt to create a virtual server that references a virtual address in another partition.

When you configure a virtual server, the BIG-IP system creates two local traffic objects: a virtual server and a virtual address. A virtual address can be referenced by one or more virtual servers. For example, the virtual address 172.0.0.10 can be referenced by virtual servers 172.0.0.10:80 and 172.0.0.10:22. In addition, a virtual server and corresponding virtual address both reside in the partition in which the virtual server was created. For example, if you create a virtual server of 172.0.0.10:80 in the default /Common partition, the virtual address 172.0.0.10 also resides in the default /Common partition.

When working with partitions, you should be aware of the following:

  • Virtual addresses that reside in the default /Common partition:

    A virtual address that resides in the default /Common partition can be referenced by a virtual server in any other partition. For example, if virtual server 172.0.0.10:80 and virtual address 172.0.0.10 reside in the /Common partition, you can create another virtual server such as 172.0.0.10:22 in a non-default partition, such as /MyPartition.

  • Virtual addresses that reside in a non-default partition:

    A virtual address that resides in a non-default partition can only be referenced by virtual servers that reside in the same partition. For example, if virtual server 172.0.0.10:80 and virtual address 172.0.0.10 reside in a non-default partition such as /MyPartition, other virtual servers such as 172.0.0.10:22 must also reside in the same non-default partition.

Impact

Users may need to plan accordingly before creating virtual servers in multiple partitions.

Recommended Actions

You can make the virtual address available in other partitions by deleting the virtual server from the non-default partition and recreating it in the /Common partition. To do so, perform one of the following procedures:

  • Using the Configuration utility to delete and re-create the virtual server and address
  • Using tmsh to delete and create the virtual server and address

Note: For multiple virtual servers to share the same destination address, source address, and service port, you must specify unique Virtual Local Area Networks (VLANs) for which the virtual servers are enabled.

Using the Configuration utility to delete and re-create the virtual server and address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. From the Partition menu (located in the upper-right corner of the page), select the non-default partition.
  3. Navigate to Local Traffic > Virtual Servers > Virtual Servers List.
  4. Select the check box next to the virtual server that is causing the error message.
  5. Click Delete.
  6. From the Partition menu, select the default partition (Common).
  7. Navigate to Local Traffic > Virtual Servers > Virtual Servers List.
  8. Click Create.
  9. Re-define the virtual server that originally caused the error message.

You can now create additional virtual servers that reference the virtual address in other non-default partitions.

Using tmsh to delete and create the virtual server and address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Change to the non-default partition by using the following command syntax:

    cd /<non-default_partition>

    For example:

    cd /MyPartition

  3. Delete the virtual server by using the following command syntax:

    delete /ltm virtual <virtual_server>

    For example:

    delete /ltm virtual MyVirtual

  4. Change to the default partition by typing the following command:

    cd /Common

  5. Create the new virtual server by using the following command syntax:

    create /ltm virtual <virtual_name> destination <ip_addr:port> mask <netmask> vlans add { <vlan_name> }

    For example:

    create /ltm virtual MyVirtual destination 172.0.0.10:80 mask 255.255.255.0 vlans add { external }

  6. Save the configuration by typing the following command:

    save /sys config partitions all

You can now create additional virtual servers that reference the virtual address in other non-default partitions.
