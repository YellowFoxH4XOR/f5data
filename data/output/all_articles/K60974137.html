General information

Note: F5 has changed the name F5 Container Connector to F5 Container Ingress Services.

Provide the following information when you open a case with F5 Support. For information about sending this information to F5, refer to K000090853: Exchange files with F5 Support.

  • A full description of the issue, including the following details:
    • The symptoms of the issue, including a brief description of any systems related to the configuration
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have taken in an attempt to resolve the issue
    • Whether this is a new implementation
    • A high-level description of the environment in which the instance is running

      For example:

      • Is the device in a testing or production environment?
      • What version of orchestration system is used (for example, Kubernetes, OpenShift, Mesos/Marathon)
    • Whether you have already uploaded a Phone Home bundle to the iHealth portal
  • A description of the impact that the issue is having on your site, using the following definitions:
    • Site Down

      All network traffic has ceased, causing a critical impact to your business.

    • Site at Risk

      The primary unit has failed, resulting in no redundancy. The site is at risk of going down.

    • Performance Degraded

      Network traffic is partially functional, causing some applications to be unreachable.

    • General Assistance Required

      Questions regarding configurations. Troubleshooting a non-critical issue, or request for product functionality that is not part of the current product feature set.

  • The hours that you are available to work on the issue (including the time zone) and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Collect the following product-specific information from the affected systems and provide this information, as well, when you open the case.

Support information

  1. Collect a QKView from the BIGIP system the F5 Container Ingress Services is managing.
  2. Log in to a cluster node.
  3. Collect the logs from the F5 Container Ingress Services pod.  Logs are generated with the command kubectl logs {$POD_NAME} -n {$NAMESPACE}.   The following example should work for most installations.
    • kubectl logs -n kube-system $(kubectl get pods --all-namespaces | awk '/k8s-bigip-ctlr/ {print $2}') > controller-logs.txt
  4. Collect the controller deployment parameters.
    • kubectl describe pod -n kube-system $(kubectl get pods --all-namespaces | awk '/k8s-bigip-ctlr/ {print $2}')
  5. Collect copies of the service,ingress, or route deployment yaml files that are being used to reproduce the issue.
  6. Include this information when you open the case.

Finalizing initial information gathering

Upload log files and the kubectl command output to F5 Support. For more information, refer to K000090853: Exchange files with F5 Support.

F5 Support will be alerted about the information posted to the case, start analyzing the information you provided, and reach out to the case contact with further instructions.

Troubleshooting

For detailed troubleshooting and debugging steps for Kubernetes and OpenShift, refer to F5 CloudDocs.
