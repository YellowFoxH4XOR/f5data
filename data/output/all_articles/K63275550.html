Topic

You should consider using this procedure under the following condition:

  • You want to modify the BIG-IP system's ephemeral port exhaustion threshold warning.

Description

When the BIG-IP system processes large numbers of new connections, the pool of available service ports can in rare instances become exhausted. This condition may cause a disruption of service during peak production periods. Beginning in 12.0.0, to help administrators identify and avoid this condition early, the BIG-IP system will issue an early warning when it detects that the pool of available service ports is nearing exhaustion.

A common configuration that may experience this condition is when a secure network address translation (SNAT) is configured on a BIG-IP virtual server. The source IP address of a new connection is translated using the configured SNAT address and the source service port, also known as an ephemeral port, is mapped using a pool of available service ports. The range of ephemeral ports for each SNAT address is from 1024 to 65,535. Therefore, each IP address has a pool of approximately 64,512 available ephemeral ports.

When the virtual server processes a large number of new connections, the ephemeral port pool may become exhausted and the system sends a message to the /var/log/ltm file that appears similar to the following example:

01010201:2: Inet port exhaustion on 192.168.10.100 to 172.28.21.10:53 (proto 17)
01010201:2: Inet port exhaustion on 192.168.10.100 to 172.28.21.11:80 (proto 6)

This condition is usually resolved by adding additional SNAT addresses to obtain more ephemeral ports. However, from the time the condition is realized until the new SNAT addresses are added, clients may experience a degradation of service.

Note: The previous error messages are not specific to SNAT and may be logged whenever the Traffic Management Microkernel (TMM) detects port exhaustion for a traffic management object.

Beginning in 12.0.0, the BIG-IP system will issue a threshold reached warning when approximately 80 percent of the available ephemeral ports are in use. This allows administrators to respond to and resolve ephemeral port exhaustion issues before clients experience degradation of service. By default, when 80 percent of ephemeral ports in the pool are in use, a port exhaustion threshold message similar to the following will also be sent to the /var/log/ltm file:

01010281:4: Inet port exhaustion threshold reached on 192.168.10.100 to 172.28.21.12:80 (proto 6)

The percentage of ephemeral ports in use is determined by the number of attempts the Traffic Management Microkernel (TMM) must make to find an available port from the ephemeral port pool when creating a new connection. For example, when TMM makes 8 attempts to find an available ephemeral port, 80 percent of the available ports are estimated to be in use. The following table, shows a partial correlation between number of attempts to find an available port and the estimated percentage of ports in use. Each additional attempt to find a port is equivalent to approximately 2.5 percent total port usage.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Administrative access to the TMOS Shell (tmsh).

Procedures

Modifying the threshold message trigger

You can modify the port exhaustion threshold trigger, or the point at which the system sends a warning message, by modifying the number of attempts to find an unused port. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the port exhaustion threshold trigger value, use the following command syntax:

    Note: The port-find-threshold-trigger option accepts a value between 1 and 12. The default setting is 8.

    modify ltm global-settings traffic-control port-find-threshold-trigger <attempts>

    For example, to configure TMM to trigger the ephemeral port exhaustion threshold message when 75 percent of all ports are in use, run the following command:

    modify ltm global-settings traffic-control port-find-threshold-trigger 6

  3. To save the configuration, type the following command:

    save sys config

Modifying the threshold message logging rate

You can modify the rate, in seconds, at which the port exhaustion threshold message is logged to the /var/log/ltm file by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the port exhaustion threshold timer value, use the following command syntax:

    Note: The port-find-threshold-timeout option accepts a value between 0 and 600. The default setting is 30.

    modify ltm global-settings traffic-control port-find-threshold-timeout <seconds>

    For example, to configure TMM to log the ephemeral port exhaustion threshold message every minute while the threshold remains exceeded, type the following command:

    modify ltm global-settings traffic-control port-find-threshold-timeout 60

  3. To save the configuration, type the following command:

    save sys config

Disabling the threshold message

You can disable the port exhaustion threshold message by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To disable the port exhaustion threshold message, type the following command:

    Note: The port-find-threshold-warning option is enabled by default.

    modify ltm global-settings traffic-control port-find-threshold-warning disabled

  3. To save the configuration, type the following command:

    save sys config
