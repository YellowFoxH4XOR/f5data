Known Issue

The BIG-IP system may unnecessarily retransmit Diameter messages.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system configuration includes a virtual server with an associated diameter profile and an iRule.
  • The diameter profile that has the Retransmit Timeout option set to a value greater than zero.
  • The iRule uses the LB_FAILED event and the LB::reselect command.

    For example:

    rule example {
        when LB_FAILED {
        LB::reselect
    }
  • The diameter handshake fails between the BIG-IP system and the back-end server.

Impact

You may experience additional Diameter traffic on the network.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Diameter servers receive duplicate Diameter messages from the BIG-IP system.

Workaround

To work around this issue, you can disable retransmission in the Diameter profile configuration. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Diameter.
  3. Click the name of the diameter profile associated with the affected diameter virtual server.
  4. Select the Maximum Retransmit Attempts check box if it is not already selected, and set the value to zero (0).
  5. Select the Retransmit Timeout check box if it is not already selected, and set the value to zero (0).
  6. To save the changes, click Update.
