Topic

Virtualized Clustered Multiprocessing (vCMP) allows you to run multiple BIG-IP instances on a single hardware platform. The vCMP host allocates a portion of the hardware platform's resources each time a BIG-IP instance, or vCMP guest is created. This article describes how the vCMP host allocates and uses virtual disk space and how to view and recover virtual disk space.

Description

Each time you create a vCMP guest, the vCMP host creates a virtual disk file, or image, that is the vCMP guest file system. The virtual disk file is a special file type known as a sparse file, and it optimizes the hardware platform's disk space. Using sparse file technology, disk space is used only as needed, and the vCMP guest's allocated virtual disk size does not represent the actual amount of disk space in use, but rather the maximum amount of space that can be used. This means each virtual disk has two sizes associated with it; the allocated or maximum growth size and the actual amount of disk space in use. For this reason, you may notice that the total size of all vCMP guest virtual disks exceeds the size of the hardware platform's hard drive.

Once a vCMP guest uses disk space, for example, when creating a User Configuration Set (UCS) file or uploading a new software ISO image, that disk space is not automatically recovered, even after the files have been deleted. Recovering disk space used by a vCMP guest requires manual intervention. You can use the following procedures to view a vCMP guest's allocated virtual disk size, the amount of actual disk space used, and if necessary, recover unused virtual disk space.

Viewing virtual disk sizes

vCMP guest virtual disk files, or images, are stored in the /shared/vmdisks directory. The virtual disk file name is based on the name of the vCMP guest and ends with the .img extension. You can use the following procedure to view the size of all vCMP guest virtual disks as well as actual disk space in use.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash) of the vCMP host.
  2. To view all vCMP guest virtual disk sizes and the actual disk space in use by each, type the following command:

    ll -sh /shared/vmdisks | grep img

  3. In the following example, the vCMP guest named guest_one has been allocated a 150G (gigabyte) virtual disk and the virtual disk is currently using 5.1G of disk space.

    5.1G -rw-r--r--. 1 root root 150G 2016-11-25 05:59 guest_one.img

Recovering Disk Space

You can use the following procedure to recover disk space that is no longer being used by the vCMP guest. 

Important: To maximize disk space recovery, first remove all files that may no longer be in use. For more information refer to K14403: Maintaining disk space on the BIG-IP system.

Impact of procedure: Performing the following procedure requires that you disable the vCMP guest, which disrupts all traffic being processed by the vCMP guest. F5 recommends that you perform this procedure only during a planned maintenance period.

  1. To log in to the Traffic Management Shell (tmsh) type the following command on the vCMP host:

    tmsh

  2. To disable the vCMP guest, use the following command syntax:

    modify vcmp guest <guest_name> state configured

    For example, to disable the vCMP guest named guest_one, type the following command:

    modify vcmp guest guest_one state configured

  3. To verify that the virtual disk is ready for the disk space recovery procedure, use the following command syntax:

    show vcmp virtual-disk <guest_name>.img

    For example, to verify that the virtual disk for the vCMP guest named guest_one is ready to continue with the disk space recovery procedure, type the following command:

    show vcmp virtual-disk guest_one.img

  4. Ensure that the vCMP guest virtual disk Status has changed from in-use to ready:

    ---------------------------------------------------------------
    Vcmp::VirtualDisk
    Name                 Operating System  Status  Disk Use (bytes)
    ---------------------------------------------------------------
    guest_one.img                   tmos   ready              50.1G

  5. To exit tmsh and return to the Advanced Shell (bash), type q. 
  6. To change into the directory where the vCMP guest virtual disk images are stored, type the following command:

    cd /shared/vmdisks

  7. To make a copy of the vCMP guest virtual disk image and recover unused disk space, use the following command syntax:

    cp --sparse=always <guest_name>.img <guest_name_recover>.img

    For example, to copy a virtual disk image named guest_one to a space recovered file named guest_one_recover, type the following command:

    Note: This command make take additional time to complete based on vCMP host resource utilization and vCMP guest image file size.

    cp --sparse=always guest_one.img guest_one_recover.img

  8. Log in to tmsh again by typing the following command:

    tmsh

  9. To view the recovered virtual disk size, use the following command syntax:

    show vcmp virtual-disk <guest_name_recover>.img

    For example, the view the size of the recovered virtual disk named guest_one_recover, type the following command:

    show vcmp virtual-disk guest_one_recover.img

  10. In the following example, the recovered virtual disk size has been reduced from 50.1G to 5.0G:

    ---------------------------------------------------------------
    Vcmp::VirtualDisk
    Name                 Operating System  Status  Disk Use (bytes)
    ---------------------------------------------------------------
    guest_one_recover.img                   tmos   ready              5.0G

  11. To associate the vCMP guest with the recovered virtual disk image, use the following command syntax:

    modify vcmp guest <guest_name> virtual-disk <guest_name_recover>.img

    For example, to associated the vCMP guest named guest_one with the recovered virtual disk image named guest_one_recover, type the following command:

    modify vcmp guest guest_one virtual-disk guest_one_recover.img

  12. To redeploy the vCMP guest, use the following command syntax:

    modify vcmp guest <guest_name> state deployed

    For example, to redeploy the vCMP guest named guest_one, type the following command:

    modify vcmp guest guest_one state deployed

  13. To save the configuration, type the following command:

    save sys config

Recommendations

When you configure and deploy vCMP guests, you should consider the following factors:

  • The disk space recovery procedure may be helpful if you are unable to create new vCMP guests due to disk space exhaustion on the vCMP host.
  • Virtual disk images remain, even after a vCMP guest has been deleted. For virtual disks no longer in use, consider either deleting or moving the virtual disk images to a backup storage server.
