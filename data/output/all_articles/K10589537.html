Known Issue

Under rare conditions, the Traffic Management Microkernel (TMM) may restart and produce a core file when using dynamic load balancing methods.

This issue occurs when all of the following conditions are met:

  • A pool is configured to use one of the following dynamic load balancing methods:
    • Dynamic Ratio
    • Least Connections
    • Predictive
    • Fastest
    • Observed
  • A dynamic pool member receives a new connection request.

The dynamic load balancing methods use the session database to share data among all TMM instances. Under extremely rare conditions, the session database may become unreliable.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The system logs an error message in the /var/log/tmm file that appears similar to the following example:

    notice ** SIGSEGV **

  • Your BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.
