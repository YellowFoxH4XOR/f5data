Description

Due to a functional limitation in IKEv1 and IKEv2 IPsec, each IKE version must use a different self IP address as the tunnel local-address. Failure to use different local self IP addresses can lead to intermittent problems such as an IPsec tunnel failing to re-key or refusing to initiate.
The BIG-IP system will permit an Administrator to create multiple IPsec tunnels using the same local self IP as the local-address for the tunnel. However, the same self IP cannot be used for both IKEv1 and IKEv2 tunnels. In other words, all IKEv1 tunnels must use self IP address A, while all IKEv2 tunnels must use self IP B.
This limitation holds true for all IPsec tunnels within the same route-domain. This means IPsec configurations within separate route-domains will not interfere with each other.

When this duplication exists, the ltm log will report errors similar to:

017c0003:3: Listener binding ERR=12 (DUPLICATE) v1 listener $_ike_2a3e6_in_10.1.1.10 10.1.1.10:500 FAIL
017c0004:5: NOTE: Avoid common IPsec v1 and v2 tunnel local addr
 

Environment

  • IPsec on BIG-IP
  • v11.6.* and later
     

Cause

None
 

Recommended Actions

When the BIG-IP Administrator needs to mix IKEv1 and IKEv2 tunnels within the same route-domain (including the default route-domain 0), the two options are:
  • Convert all IPsec tunnels to use the same IKE version
    or
  • Create two self IP addresses, one for IKEv1 tunnels and the other for IKEv2 tunnels.
Note:
The self IP addresses do not need to be dedicated for IPsec only.
The addresses can be self or floating IPs.

 
In the following examples, we see firstly how to create two self IP addresses, secondly how to switch the IKE version of the IPsec tunnel and thirdly how to create the IPsec objects using different local IPs.
  • Example - Create Self IP Addresses
  • Example - Change the IKE Version of the IPsec Tunnel
  • Example - Create the IPsec Objects Using Different Local IPs


Example - Create Self IP Addresses

IPsec local addresses are defined in either one of two places.
  1. IPsec "interface" mode: the local and remote addresses for the tunnel are configured in the tunnels object.
  2. IPsec "policy" mode: the local and remote addresses for the tunnel are configured in the ipsec-policy.
     
    Create Self IPs
    1. in the configuration utility, navigate to: Network  ››  Self IPs
    2. Create a self or floating IP
    3. Configure the IP address in the same route-domain as the IPsec tunnel is configured in
    4. Repeat step 2 and 3, to create second self or floating IP
    Alternatively via tmsh run command below for each self or floating IP: 

         tmsh create net self <name> address <ip>/<netmask> vlan <vlan-name>

    Where:
    • <name> is an arbitrary name for the self IP object
    • <ip> is the new local IP to create
    • <netmask> is the numeric network mask of the IP address
    • <vlan-name> is the name of the VLAN to attach the self IP
     
    For example:
    tmsh create net self my-self-1 address 10.1.1.1/24 vlan myvlan
    tmsh create net self my-self-2 address 10.1.1.2/24 vlan myvlan

    Assume in this example that the first policy is associated with all IKEv1 IPsec peers and the second IP address is associated with all IKEv2 peers.


    Example - Change the IKE Version of the IPsec Tunnel
    Existing ike-peers can be easily modified to change the IKE version.

      Procedure

      Impact of Procedure: Modifying an existing ike-peer configuration will cause that tunnel to go down, if it is up at the time of the modification.
      1. In the configuration utility, navigate to Network  ››  IPsec : IKE Peers
      2. Select the ike-peer to alter.
      3. In the Version section, select either Version 1 or Version 2.
        Important: Under no circumstances enable both version 1 and 2 at the same time. The IPsec tunnel will perform unpredictably if both are enabled.


      Or in tmsh, the version can be changed using the following command: 

      tmsh modify net ipsec ike-peer <name> version replace-all-with { <v1|v2> }

      Where:

      • <name> is the name of the ike-peer configuration object to change.
      • <v1|v2> is one of v1 or v2, denoting the IKE version.


        Example
        tmsh modify net ipsec ike-peer myike version replace-all-with { v2 }


        Example - Create the IPsec Objects Using Different Local IPs

        The following example will show how to create the tunnel object and define the local IP. However, the same steps can be followed to modify existing objects.

        Impact of Procedure: Modifying existing IPsec objects may cause the IPsec tunnel to go down if it up at the time of modification.

        The following procedures are given for IPsec policy mode and then IPsec interface mode. An IPsec tunnel cannot be both in policy (tunnel) mode and interface mode. Therefore, only one of these procedures should be followed, depending on the mode that the IPsec tunnel is being configured for.
         

          Procedure - IPsec Policy Mode

          Create two ipsec-policies using the different local addresses defined above. It is possible to use these steps to modify existing tunnels to correct the local self IPs.
          1. In the configuration utility, navigate to: Network  ››  IPsec : IPsec Policies
          2. Click Create and select "Mode" to be "Tunnel"
          3. In the Tunnel Local Address, use one of the newly created self IP addresses
          4. In the Tunnel Remote Address add the IP address of the remote IKEv1 IPsec peer
          5. Set the rest of the fields in accordance with the specific authentication and encryption parameters required for the tunnel
          6. Click "Finished"
          7. Return to the IPsec Policies screen
          8. Click Create again to add the IKEv2 tunnel, using the second newly created self IP address as the Tunnel Local Address.

          Note: the ike-peer configuration defined the IKE protocol in use. Creating the necessary ike-peer, traffic-selectors, routes and virtual servers are not documented here.

          Alternatively, via tmsh: 

          tmsh create net ipsec ipsec-policy <name> tunnel-local-address <self-ip> tunnel-remote-address <remote-ip>
           

          Where:
          • name is an arbitrary name for the ipsec-policy
          • self-ip is the local self or floating address to use
          • remote-ip is the IP address of the remote peer.

            Example
            tmsh create net ipsec ipsec-policy policy-1 tunnel-local-address 10.1.1.1 tunnel-remote-address 192.168.1.1
            tmsh create net ipsec ipsec-policy policy-2 tunnel-local-address 10.1.1.2 tunnel-remote-address 172.31.1.1


              Procedure - IPsec Interface Mode

              The mode of a tunnel is set in the ipsec-policy. When an ipsec-policy is in "interface" mode the IP endpoints of the tunnel are defined as a tunnel object, not the ipsec-policy.
              1. In the configuration utility navigate to: Network  ››  Tunnels : Tunnel List
              2. Click Create and select an "ipsec" Profile 
              3. In the Local Address field, use one of the newly created self IP addresses
              4. In the Remote Address field add the IP address of the remote IKEv1 IPsec peer. The rest of the fields are normally left at the defaults
              5. Click "Finished"
              6. Return to the Tunnel List screen
              7. Click Create again to add the IKEv2 tunnel, using the second newly created self IP address as the Local Address

              Note: A custom IPsec profile may have been created earlier, but creating the peripheral tunnel configuration is beyond the scope of this example. Refer to the supplemental information section.

              Alternatively, via tmsh:
               
              tmsh create net tunnels tunnel <name> profile ipsec local-address <self-ip> remote-address <remote-ip>
               
              Where:
              • <name> is an arbitrary name for the tunnel
              • <self-ip> is the local self or floating address to use
              • <remote-ip> is the IP address of the remote peer.

                Example
                tmsh create net tunnels tunnel mytunnel-1 profile ipsec  local-address 10.1.1.1 remote-address 192.168.1.1
                tmsh create net tunnels tunnel mytunnel-2 profile ipsec  local-address 10.1.1.2 remote-address 172.31.1.1

                Note: A custom IPsec profile may have been created earlier, but creating the peripheral configuration is beyond the scope of this example. Refer to the Related Content section below.
