Known Issue

This is the result of a known issue. If you associate a basic TCP monitor (no send/receive strings specified) with a pool or pool member, and the pool member is not listening on the monitored port, the TCP monitor may intermittently mark that pool member as up for several seconds. As a result, the BIG-IP system may send traffic to that pool member until the monitor marks it down again.

F5 Product Development tracked this issue as ID 340407, and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Workaround

You can work around this issue by configuring the TCP Half Open monitor instead of the basic TCP monitor. The TCP Half Open monitor sends a TCP SYN packet to the pool member, and marks the service as up after receiving a SYN-ACK response from the server.
