Description
The requests sent by the clients are blocked by the Signature 200019139 when the HTTP header "X-requested-with" has a NULL value.

Example: The request sent below with "x-requested-with: \r\n" i.e. NULL value.

echo -ne 'GET / HTTP/1.1\r\nHost:10.77.26.140\r\nx-requested-with: \r\nConnection: Closed\r\n\r\n' | nc 192.168.50.11 80
HTTP/1.1 200 OK
Cache-Control: no-cache
Connection: close
Content-Type: text/html; charset=utf-8
Pragma: no-cache
Content-Length: 247

The ASM reject the request with Support ID. You can see the violation in the GUI.

<html><head><title>Request Rejected</title></head><body>The requested URL was rejected. Please consult with your administrator.<br><br>Your support ID is: 14818215149243990020

Violation:

Attack signature detected
Attack Types    Trojan/Backdoor/Spyware, Buffer Overflow, Forceful Browsing

Environment

  • ASM
  • AWAF
  • Attack Signature
  • Request blocked

Cause

X-Requested-With HTTP header has a NULL value as shown below:

headercontent:"X-Requested-With: |0d 0a|"; nocase; <<<<

Running the below command in CLI shows the information about the Signature ID and the cause. 

# mysql -E -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e "select rule from PLC.NEGSIG_SIGNATURES where (sig_id like 200019139);"

*************************** 1. row ***************************
rule: headercontent:"X-Requested-With: |0d 0a|"; nocase; reference:url,https://www.flashpoint-intel.com/blog/wirex-botnet-industry-collaboration/;

The X-Requested-With matches the below;

"0d" is carriage return \r
"0a" is line feed \n

If you would like to know more about the signature, you can refer to the link - https://www.flashpoint-intel.com/blog/wirex-botnet-industry-collaboration/

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Recommended Actions

  • Ensure that the X-Requested-With header doesn't have a NULL value. It is expected behavior to block the request by the Signature.
  • If you think your application may accept valid input that matches these signatures please disable this signature either on the policy level or for a specific URL.
