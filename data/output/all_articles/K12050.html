Description

Introduced in BIG-IP ASM 10.1.0, the Report Detected Anomalies feature was added to the logging profile for use with remote storage. This feature adds remote logging support for the following attack types:

  • Brute Force
  • Denial-of-Service (DoS)
  • IP Enforcer
  • Web Scraping

The Report Detected Anomalies logging formats are predefined and cannot be altered by a user.

Note: For more information about the listed attack types and how to configure anomaly detection, refer to the Configuring Anomaly Detection chapter of the Configuration Guide for BIG-IP Application Security Manager. For information about how to configure a logging profile for remote storage, refer to the Configuring General System Options chapter of the Configuration Guide for BIG-IP Application Security Manager. For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

DoS and Brute Force logging format

The DoS and Brute Force logging format both use the following format string:

unit_hostname="%s",management_ip_address="%s",web_application_name="%s",
policy_name="%s",policy_apply_date="%s",anomaly_attack_type="%s",uri="%s",
attack_id="%llu",attack_status="%s",operation_mode="%s", detection_mode="%s",
detection_average="%ld",current_mitigation="%s",ip_list="%s",url_list="%s",date_time="%s",
severity="%s"

Note: The %s symbol represents the field value. This value is dynamic.

Field nameField value
unit_hostnameHost name of the BIG-IP ASM system reporting the attack
management_ip_addressManagement IP address of the BIG-IP ASM system reporting the attack
web_application_nameName of the web application experiencing the attack
policy_nameName of the current active security policy associated with the web application
policy_apply_dateLast date any changes were made to the current active security policy
anomaly_attack_typeType of attack reported: DoS or Brute Force
uriLogin URI attacked (applies to Brute Force attack only)
attack_id

Unique identifier associated with the attack

Note: This value is not a support ID as displayed in the Configuration utility; it is typically used by remote logger display tools to correlate between start, stop, and ongoing attack messages.

attack_statusStatus of the attack; options reported are Started, Ended, or Ongoing
operation_modeCurrent operation mode of the security policy: Transparent or Blocking
detection_modeTransactions per second (TPS) or Latency Increased detected (DoS attacks only) or Number of Failed Logins Increased (Brute Force attacks only)
detection_averageDetected historical average of TPS/Latency/Failed Logins
current_mitigationCurrent mitigation technique used to stop the attack: Source IP-Based Client Side Integrity Defense, URL-Based Client Side Integrity Defense, Source IP-Based Rate Limiting, URL-Based Rate Limiting, Transparent
ip_list

Colon-separated list of attacker IP addresses, geographical location, and number of drops for each prevented IP in the following format: client_ip_addr:geo_location:drops_counter

The ip_list is relevant only for ongoing events.

url_listComma separated list of URLs attacked
date_timeCurrent date and time
severitySeverity level reported. This value always has a severity level of Emergency (Local0.Emerg).

policy_name="%s",policy_apply_date="%s", anomaly_attack_type="%s",attack_id="%llu",
