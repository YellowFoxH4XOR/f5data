Description

You notice a health monitor is constantly marking a pool down, but this only happens on one of the HA pairs. You have checked that:

  • The monitor is always marked UP on the other HA pair, and works as normal.
  • The backend server can be reached directly and has been confirmed to be responsive.

On a packet capture of the failing monitor traffic, you notice a MAC address discrepancy in the SYN sent from BIG-IP and the SYN-ACK response from the server, similar to this example:

Note: on first SYN, the source MAC address from the BIG-IP is 00-00-5E-00-53-00, this MAC does not belong to the HA pair with the failing monitor.

Frame 10: 74 bytes on wire (592 bits), 74 bytes captured (592 bits)
Ethernet II, Src: F5Networ_00:53:00 (00-00-5E-00-53-00), Dst: Vmware_01:53:02 (00-00-5E-01-53-02)
    Destination: Vmware_01:53:02 (00-00-5E-01-53-02)
    Source: F5Networ_00:53:00 (00-00-5E-00-53-00) → Note
        Address: F5Networ_00:53:00 (00-00-5E-00-53-00)
        .... ..0. .... .... .... .... = LG bit: Globally unique address (factory default)
        .... ...0 .... .... .... .... = IG bit: Individual address (unicast)
    Type: IPv4 (0x0800)

Note: The SYN-ACK from backend server to BIG-IP, is destined to MAC address: 00-00-5E-00-53-6b, which belongs to the HA pair in question, with the failing monitor:

Frame 11: 74 bytes on wire (592 bits), 74 bytes captured (592 bits)
Ethernet II, Src: Vmware_01:53:02 (00-00-5E-01-53-02), Dst: F5Networ_00:53:6b (00-00-5E-00-53-6b)
    Destination: F5Networ_00:53:6b (00-00-5E-00-53-6b) → Note
        Address: F5Networ_00:53:6b (00-00-5E-00-53-6b)
        .... ..0. .... .... .... .... = LG bit: Globally unique address (factory default)
        .... ...0 .... .... .... .... = IG bit: Individual address (unicast)
    Source: Vmware_01:53:02 (00-00-5E-01-53-02)
    Type: IPv4 (0x0800)

Environment

  • LTM monitors down
  • HA pairs
  • MAC address discrepancy

Cause

There is a duplicated IP on a third F5 device, to one of the local Self-IPs configured on the affected HA pair, that is being used for monitoring.

Recommended Actions

Remove the duplicated IP causing the conflict.

Additional Information

To check the MAC addresses that belong to your unit, you can run the command:

tmsh show /sys mac-address
