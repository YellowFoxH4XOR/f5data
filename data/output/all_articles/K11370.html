Topic

Note: Beginning in BIG-IP ASM 11.6.0, the system no longer writes request data to the MySQL PROXY_LOG table. Starting in 11.6.0, the asmlogd process writes request data to a binary log file. For more information, refer to K05450930: The asmlogd process writes request log data to a binary log file.

The BIG-IP ASM Requests screen displays a list of web objects requested by client systems for a web application. The request information is stored in the PROXY_LOG table of the MySQL database. You can clear request information using the Requests screen in the Configuration utility; however, use one of the following three procedures when clearing a large number of requests from the MySQL PROXY_LOG table:

  • Clearing request information older than X number of days from the MySQL PROXY_LOG table
  • Clearing request information from the MySQL PROXY_LOG table, leaving X number of newest records
  • Clearing successful request information from the MySQL PROXY_LOG table
  • Clearing all request information from the MySQL PROXY_LOG table

Clearing request information older than X number of days from the MySQL PROXY_LOG table

If you want to clear request information older than X number of days from the MySQL PROXY_LOG table, perform the following procedure:

Important: Completing this procedure will permanently delete select data from the MySQL PROXY_LOG table and temporarily interrupt traffic until you have completed the procedure.

  1. Log in to the BIG-IP ASM command line.
  2. Stop the asm process by typing the following command:

    bigstart stop asm

  3. Start the MySQL process by typing the following command:

    bigstart start mysql

  4. Log in to the MySQL database using one of the following commands, depending on your version of the BIG-IP ASM system:

    • 11.4.x through 11.5.4

      You must reset the MySQL password and then log in to the database using the new password. To do so, refer to the following command syntaxes:

      To reset the MySQL password, use the following syntax:

      # /usr/share/mysql/mysqlpw -p <newpassword>

      To log in to the database using the new password, use the following syntax:

      # mysql -uroot --password=<newpassword>

    • 10.1.0 through 11.3.0

      # mysql -uroot --password=`perl -MF5::GenUtils -e "print get_mysql_password.qq{\n}"`

    • 9.4.x through 10.0.1

      # mysql -uroot -p`perl -I/ts/packages -MGenUtils -e 'print get_mysql_password().qq{\n}'`

      From the MySQL prompt, use the following command syntax, where <NUM> is the number of days of requests that you want to retain in the PROXY_LOG (9.x - 11.5.4) table:

    • 9.x through 11.5.4

      mysql> DELETE FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG WHERE log_time > unix_timestamp(curdate()-INTERVAL <NUM> DAY)) Alias);

      For example, to leave only five days of requests, change <NUM> to 5, as in the following command:

      mysql> DELETE FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG WHERE log_time > unix_timestamp(curdate()-INTERVAL 5 DAY)) Alias);

      Note: If the PROXY_LOG table contains a large number of records, the command may take some time to complete.

      Note: You may also find the following MySQL queries useful. Respectively, they return the total number of requests in the PROXY_LOG table and the number of requests that the system would delete if you only kept requests newer than X days:

      mysql> SELECT COUNT(*) FROM PRX.PROXY_LOG;

      mysql> SELECT COUNT(*) FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG WHERE log_time > unix_timestamp(curdate()-INTERVAL <NUM> DAY)) Alias);

      For example, to determine how many requests the system would delete if you kept requests from only the last five days, you would enter the following command:

      mysql> SELECT COUNT(*) FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG WHERE log_time > unix_timestamp(curdate()-INTERVAL 5 DAY)) Alias);

  5. Restart the asm process by typing the following command:

    bigstart restart asm

  6. Verify that the asm process has restarted properly. When the BIG-IP ASM system has restarted, a log message that appears similar to the following example is logged to the /var/log/asm file:

    ASM started successfully

Clearing request information from the MySQL PROXY_LOG table, leaving X number of newest records

If you want to clear request information from the MySQL PROXY_LOG table, and leave only a certain number of newest records, perform the following procedure:

Important: Following this procedure will permanently delete select data from the MySQL PROXY_LOG table and temporarily interrupt traffic until you have completed the procedure.

  1. Log in to the BIG-IP ASM command line.
  2. Stop the BIG-IP ASM process by typing the following command:

    bigstart stop asm

  3. Start the MySQL process by typing the following command:

    bigstart start mysql

  4. Log in to the MySQL database using one of the following commands, depending on your version of the BIG-IP ASM system:
    • 11.4.x through 11.5.4

      You must reset the MySQL password and then log in to the database using the new password. To do so, refer to the following command syntaxes:

      To reset the MySQL password, use the following syntax:

      # /usr/share/mysql/mysqlpw -p <newpassword>

      To log in to the database using the new password, use the following syntax:

      # mysql -uroot --password=<newpassword>

    • 10.1.0 through 11.3.0

      # mysql -uroot --password=`perl -MF5::GenUtils -e "print get_mysql_password.qq{\n}"`

    • 9.4.x through 10.0.1

      # mysql -uroot -p`perl -I/ts/packages -MGenUtils -e 'print get_mysql_password().qq{\n}'`

  5. From the MySQL prompt, use the following command syntax, where <NUM> is the number of newest records you want to retain in the PROXY_LOG (9.x - 11.5.4) table:

    9.x through 11.5.4

    mysql> DELETE FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG ORDER BY log_time DESC LIMIT <NUM>) Alias);

    For example, to leave only 2,000 of the most current records, change <NUM> to 2000 as in the following command:

    mysql> DELETE FROM PRX.PROXY_LOG WHERE id NOT IN (SELECT id FROM (SELECT id FROM PRX.PROXY_LOG ORDER BY log_time DESC LIMIT 2000) Alias);

    Note: If the PROXY_LOG table contains a large number of records, the command may take some time to complete.

  6. Restart the asm process by typing the following command:

    bigstart restart asm

  7. Verify that the asm process has restarted properly. When the BIG-IP ASM system has restarted, a log message that appears similar to the following example is logged to the /var/log/asm file:

    ASM started successfully

Clearing successful request information from the MySQL PROXY_LOG table

There may be occasions when you want to clear successful request information from the MySQL PROXY_LOG table. For example, if you change the logging profile from Log all requests to Log illegal requests, you may want to remove the successful requests from the MySQL PROXY_LOG table and retain the violations. To clear successful request information from the MySQL PROXY_LOG table, perform the following procedure:

Important: Following this procedure will permanently delete select data from the MySQL PROXY_LOG table and temporarily interrupt traffic until you have completed the procedure.

  1. Log in to the BIG-IP ASM command line.
  2. Stop the asm process by typing the following command:

    bigstart stop asm

  3. Start the MySQL process by typing the following command:

    bigstart start mysql

  4. From the MySQL prompt, use the following command syntax to clear successful request information from the MySQL PROXY_LOG table:

    • 10.1.0 and later

      mysql -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "DELETE FROM PRX.PROXY_LOG where status = 0;"

    • 9.4.x through 10.0.1

      mysql -uroot -p`perl -I/ts/packages -MGenUtils -e 'print get_mysql_password().qq{\n}'` -e "DELETE FROM PRX.PROXY_LOG where status = 0;"

Clearing all request information from the MySQL PROXY_LOG table

To clear all request information from the PROXY_LOG table, perform the following procedure:

Note: Performing this procedure permanently clears all request information from the BIG-IP ASM request logs. This procedure does not require a restart of the asm process.

  1. Log in to the BIG-IP ASM command line.
  2. Stop the asm process by typing the following command:

    bigstart stop asm

  3. Start the MySQL process by typing the following command:

    bigstart start mysql

  4. Log in to the MySQL database using one of the following commands, depending on your version of the BIG-IP ASM system:

    • 11.4.x through 11.5.4

      You must reset the MySQL password and then log in to the database using the new password. To do so, refer to the following command syntaxes:

      To reset the MySQL password, use the following syntax:

      # /usr/share/mysql/mysqlpw -p <newpassword>

      To log into the database using the new password, use the following syntax:

      # mysql -uroot --password=<newpassword>

    • 10.1.0 through 11.3.0

      # mysql -uroot --password=`perl -MF5::GenUtils -e "print get_mysql_password.qq{\n}"`

    • 9.4.x through 10.0.1

      # mysql -uroot -p`perl -I/ts/packages -MGenUtils -e 'print get_mysql_password().qq{\n}'`

  5. From the MySQL prompt, access the PRX database by typing the following command:

    mysql> use PRX;

  6. Clear the PROXY_LOG table by typing the following command:

    TRUNCATE TABLE PROXY_LOG;

  7. Exit the MySQL database by entering the following command:

    QUIT;
