Topic

You should consider using this procedure under the following condition:

  • The BIG-IP WebAccelerator system fails to start due to a MySQL database corruption.

Description

The BIG-IP WebAccelerator 10.x configuration and performance data is stored in a MySQL database.  In version 11.x, only performance data is stored in MySQL.  As a result of a MySQL database corruption, you may encounter the following symptoms:

  • The BIG-IP WebAccelerator system fails to start and pass traffic.
  • You may see errors in the /var/log/mysql.out file that appear similar to the following example:

    Starting MySQL.. ERROR! Manager of pid-file quit without updating file

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have root access to the BIG-IP system

Procedures

When experiencing MySQL corruption issues, you can use the following procedure to resolve the corruption:

Repairing a corrupt MySQL Database

You might be able to repair a database using the MySQL database tools. To do so, perform the following procedure:

Impact of procedure: This procedure may not resolve the database corruption. You may not be able to access the BIG-IP Configuration utility until you have completed all of the following steps.

  1. Log in to the BIG-IP command line as the root user.
  2. Stop any mysql process with the following commands:

    bigstart stop mysql
    kill -9 $(pidof mysqld)

  3. Stop the BIG-IP WebAccelerator and Tomcat processes.

    For version 10.x, use the following command:

    bigstart stop pvac comm_srv tomcat

    For version 11.x, use the following command:

    bigstart stop wamd tomcat
  4. To perform the database repair, run the following command:

    mysqlcheck -r -p$(perl -MF5::GenUtils -e "print get_mysql_password.qq{\n}") --all-databases

  5. Restart MySQL by typing the following command:

    bigstart start mysql

  6. Restart the BIG-IP WebAccelerator and Tomcat processes.

    For version 10.x, use the following command:

    bigstart start pvac comm_srv tomcat

    For version 11.x, use the following command:

    bigstart start wamd tomcat

  7. Check the /var/log/mysql.out file for the following message, confirming a successful MySQL start:

    Starting MySQL SUCCESS!

If the previous steps do not resolve the MySQL corruption, you need to restore a previous configuration from a UCS backup.  For further information on backing up or restoring BIG-IP systems, refer to the articles in the following  Supplemental Information section.
