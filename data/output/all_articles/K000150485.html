Description

 BIG-IP Virtual Edition (VE) virtual machines retain their original VM version compatibility even when upgraded. An older VM version will cause the hypervisor to mask off more modern CPU feature flags. The VE guest will not be aware of and able to make use of modern CPU instructions when this happens and this can hamper crypto processing performance.

 

Environment

  • BIG-IP VE originally installed with earlier version of TMOS software, where VM version was 10 or lower, before 15.1.6.1, 16.1.2.2 or 17.0.0.
  • Broadcom (VMware) ESXi hypervisor running v6.5 or later
  •   Usually noticed after upgrade due to heavier CPU use by tmm due to use of more recent crypto.

Cause

  Newly installed VE had VM version 10 hardware from TMOS version 13.1.0, and version 13 from TMOS version 15.1.6.1, 16.1.2.2 or 17.0.0.

  In vSphere you can check version under VM Hardware Compatibility, for example: 

         ESXi 5.5 and later (VM version 10)
    ESXi 6.5 and later (VM version 13)

   

  If you upgrade a VE with VM version 10 hardware, for instance TMOS version 15.1.3, to a later TMOS version such as TMOS version 17.1.2.1, the VM hardware version will remain at 10 unless you take action to change it.

   

  There is another feature, VMware EVC, that can mask CPU flags, and this is combined with that due to VM machine type to impose the most restrictive setting.

  This is used to mask a newer host CPU to make it compatible with an older host CPU so the guest can potentially be live migrated from newer to older host.

  It is set and managed at cluster level. It generally shouldn't be an issue for VE as even compatibility with unsupported ESXi 6.5 (VM version 13) will be enough to get critical CPU flags such as avx2 unmasked.

   

  The command below shows how much CPU the tmm process uses handling crypto loads as a percentage (100% = equivalent of one core fully loaded).

  Typically devices affected by this issue have high CPU crypto loads, and high as a proportion of tmm process CPU use.

   tmctl crypto_cpu

  To check the instruction sets that are available to the BIG-IP, you can review cat /proc/cpuinfo | grep flags

  Note the following examples are taken from a VE running on AMD CPUs. The results from Intel CPUs will be very similar but may vary slightly in the details

  Example of CPU flags on VE 16.1.3.4 with VM version 10 (upgraded from v14.1.0)

  Example of CPU flags when VM version was changed to 13, 'ESXi 6.5 and later (VM version 13)' compatibility

  Unmasked flags (VM version 13 compared with version 10) - these may vary based on CPU type. Some version of avx2 is likely to be added in VM version 13 and this is important.

  eagerfpu avx2 bmi2 rdseed adx smap clflushopt clwb xsaveopt xsavec

 

Recommended Actions

  If the VM version for the VE guest is 10 or lower change it in vSphere to 13 or higher. The VE will need to be shutdown to enable this, but after that it is a quick operation.

  Save a UCS on the BIG-IP VE. Save a snapshot of the guest VE. Right click on the guest, choose compatibility from menu and 'Upgrade VM compatibility', and note warning.

  It is suggested to upgrade to VM version 13 which is current for BIG-IP on ESXi. A higher version isn't expected to be problematic but hasn't been fully tested by F5.
