K000159931: How to monitor kubeapiservers from LTM

Applies to

Description

When BIG-IP LTM fronts Kubernetes or OpenShift API servers (kube-apiserver) on TCP port 6443, intermittent connectivity issues may occur between kubelets and the kube-apiserver during control-plane rollouts, such as:

  • kube-apiserver restarts
  • Certificate renewals
  • Control-plane maintenance operations

Symptoms include:

  • Kubelets failing lease renewals and API requests
  • Timeouts and connection resets
  • Nodes being marked NotReady
  • HTTP/2 connection losses

The issue occurs when the BIG-IP LTM health monitor does not correctly poll the Kubernetes /readyz readiness endpoint, causing traffic to be sent to API backends that are in a draining or NotReady state during kube-apiserver restarts.

Environment

LTM

Cause

The BIG-IP LTM health monitor was configured to monitor only basic connectivity (e.g., GET /) without targeting the Kubernetes /readyz endpoint. This results in the monitor marking pool members as UP based solely on port availability, rather than application readiness. Consequently, BIG-IP continues to send traffic to API backends that are not ready or are draining during kube-apiserver restarts. 

Answer/Recommended Actions

Configure the BIG-IP LTM HTTPS health monitor to properly check the Kubernetes /readyz endpoint with appropriate timeout and HTTP compliance settings.

ltm monitor https readyz_monitor {

adaptive disabled

defaults-from https

destination *.6443

interval 10

ip-dscp 0

recv "200 OK"

recv-disable none

send "GET /readyz HTTP/1.1\r\nHost: kube.hostname.com\r\nConnection: Close\r\n\r\n"

time-until-up 0

timeout 31

}
