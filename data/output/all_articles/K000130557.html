Description

  • Error seen when trying to retrieve a virtual server list using the following restcurl command:
restcurl -u admin:admin mgmt/cm/adc-core/working-config/ltm/virtual | jq -r '.items[] | {device: .deviceReference.name,name,destinationAddress,destinationPort,state} | join(", ")'

              

  • Response from the BIG-IQ:
[root@BIG-IQ-Lab:Active:Standalone) config # restcurl -u admin:admin mgmt/cm/adc-core/working-config/ltm/virtual | jq -r '.items[] | {device: .deviceReference.name,name,destinationAddress,destinationPort,state} | join(", ")'
{
  "code": 400,
  "message": "Java heap space",
  "restOperationId": 1,
  "errorStack": [],
  "kind": ":resterrorresponse"
}

 

Environment

  • BIG-IQ managing a large amount of virtual servers, more than three thousand
  • restcurl command

 

Cause

Java heap memory is exhausted

 Recommended Actions

  1. Split the request in batches (pagination), using the top and skip query parameters in the restcurl tool
       In the example below, the first command will retrieve the first 2500 items, the second command will retrieve items from 2501 to 5000, the third command items from 5001 to 7500 and so on: 
restcurl /cm/adc-core/working-config/ltm/virtual?\$top=2500 | jq -r '.items[] | {device: .deviceReference.name,name,destinationAddress,destinationPort,state} | join(", ")' > /var/tmp/Virtual-List-part1-txt

restcurl /cm/adc-core/working-config/ltm/virtual?\$top=2500\&\$skip=2500 | jq -r '.items[] | {device: .deviceReference.name,name,destinationAddress,destinationPort,state} | join(", ")' > /var/tmp/Virtual-List-part2-txt

restcurl /cm/adc-core/working-config/ltm/virtual?\$top=2500\&\$skip=5000 | jq -r '.items[] | {device: .deviceReference.name,name,destinationAddress,destinationPort,state} | join(", ")' > /var/tmp/Virtual-List-part3-txt

    All the Virtual server list is contained in three files, Virtual-List-part1-txt, Virtual-List-part2-txt and Virtual-List-part3-txt
