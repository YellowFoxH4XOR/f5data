Description

A request was blocked by a signature and was identified as a false positive. (legitimate request)

  • The context of the block is Parameter. The specific Parameter does not exist.
  • The Parameter is under a specific URL page.
  • You want to allow the request, but with a more granular configuration, to limit the change to a specific Parameter under specific URL page.

Environment

BIG-IP Advanced WAF

Cause

The security policy interprets certain HTML tags and content within a parameter as suspicious, resulting in false positive detections by specific attack signatures.

Recommended Actions

To resolve false positive detections for this endpoint URL and parameter

  • Note: You need to create the URL entry first. You will select it in step two.
  • Note: The information to complete the below steps, is in the request ID violation report.

Step one - For URL configuration:

Note: If the URL already exists - skip this step.

  • Go to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs
  • Add the URL, specify the Method and HTTP or HTTPS.
  • Uncheck Perform Staging.
  • Click Create.
  • Click Update.

Step two - Disable Attack Signature for the Parameter:

Note: If the Parameter already exists - skip creating the parameter and update its configuration under the 'Attack Signatures' tab.

  • Go to Security > Application Security > Parameters.
  • Select the relevant security policy.
  • Click Create to add a new parameter.
  • Set the name (Explicit).
  • Set Parameter Level instead of Global, select URL. Select the URL you created in Step one.
  • Uncheck 'Perform Staging' .
  • Scroll down to 'Attack Signatures' tab.
  • Search for signature ID or Name, then move it to the left. (State should show 'Disabled'.)
  • Click 'Create'
  • Click Update.
  • Click Apply Policy.
