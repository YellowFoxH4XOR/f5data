Issue

Malformed XML/JSON violation can be triggered for unicode characters that are valid unicode and allowed in XML/JSON specifications. ASM XML/JSON parser uses a bitmap table where many of unicode characters are added but there are many unicode characters that are not in the bitmap table, which are valid in terms of XML/JSON specifications. For those not in the bitmap table cause Malformed XML/JSON violation, even it is valid. Because of the bitmap implementation, ASM XML/JSON parser is sometimes too strict for some customers, and customer gets Malformed XML/JSON violation, which is false positive. 

This typically happens, when the XML Data contains letter that have accents, such as Á, É, Í, Ó, Ú, Ñ, Ç etc.

Old Behavior

With releases that are earlier than v12, v11.5.1 HF6, 11.6.0 HF4, there is no way to workaround such false positive, except disabling Malformed XML/JSON data violation entirely. Disabling the violation allows not only unsupported unicode characters but also other part of protections such as data format verifications etc.
 

New Behavior

Via ID 476191, with v12, v11.5.1 HF6, 11.6.0 HF4 and later releases, some of additional characters were added into the bitmap table to relax it a little bit.  Also this ID introduced two internal parameters below that can bypass unicode characters handling.

  • relax_unicode_in_xml
  • relax_unicode_in_json

With the parameter set to 1 (default is 0), parser skips unicode characters handling within the XML/JSON payload so there will be no Malformed XML/JSON violation triggered due to illegal characters (even with real illegal characters and illegal byte sequences). This helps users dealing with unsupported unicode characters without losing entire protection from Malformed XML/JSON data violation. 

In order to change the internal parameter, you need to execute below command 


# /usr/share/ts/bin/add_del_internal add relax_unicode_in_xml 1
IMPORTANT: this causes the unit going offline temporary
If you do this on the Active unit of an HA Pair, it will cause a failover
# bigstart restart asm


# /usr/share/ts/bin/add_del_internal add relax_unicode_in_json 1
IMPORTANT: this causes the unit going offline temporary
If you do this on the Active unit of an HA Pair, it will cause a failover
# bigstart restart asm
 

Can you also do this in the GUI

Security -› Options -› Application Security -› Advanced Configuration -› System Variables

Click the Create... button

Parameter Name: relax_unicode_in_xml
Parameter Value: 1
Description: 1 = enabled, 0 = disabled

For JSON, just change the Parameter Name to relax_unicode_in_json

Then click Create
Then you need to restart asm, for the parameter to take affect.

IMPORTANT: this causes the unit going offline temporary
If you do this on the Active unit of an HA Pair, it will cause a failover
# tmsh restart sys service asm

Impact
 

  • XML/JSON parser will skip unicode characters handling and be tolerant of any unicode characters that helps dealing with false positive Malformed XML/JSON violation.
  • The change skipping unicode characters handling, it also applies to real illegal characters and byte sequences. So possible false negatives.
  • The configuration change requires asm restart that forces the unit going offline temporary.
