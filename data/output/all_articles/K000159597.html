Description

The /var/log/messages file on the standby, PXE-booted controller shows repeated entries similar to the following:

etcdmain: rejected connection from "100.65.3.51:50788" (error "tls: \"100.65.3.51\" does not match any of DNSNames [\"etcd3.chassis.local\"] (lookup etcd3.chassis.local on 100.65.3.52:53: no such host)", ServerName "", IPAddresses ["100.65.3.50"], DNSNames ["etcd3.chassis.local"])

Environment

  • F5OS-C 1.6.x
  • PXE booted or RMA controller

Cause

  • Bug ID 1399105: etcd scale-up operation fails after PXE boot of VELOS system controller

Recommended Actions

Add the etcd3.chassis.local entry to the /etc/hosts file on the standby, PXE-booted controller.

# If the active controller is controller-1, controller-2 /etc/hosts should contain:
100.65.3.51 controller-1.chassis.local etcd3.chassis.local

# If the active controller is controller-2, controller-1 /etc/hosts should contain:
100.65.3.52 controller-2.chassis.local etcd3.chassis.local

Note: The IP addresses may be different if you are using RFC1918 addressing for the internal network IP range. The important part is the presence of the etcd3.chassis.local entry.

After adding the etcd3.chassis.local entry, allow up to 1 hour for the etcd scaleup and OpenShift install to complete.

Additional Information

In versions with the fix for ID1399105, including all 1.8.x releases, the Orchestration Manager adds the etcd3.chassis.local entry to the standby /etc/hosts prior to etcd scaleup.

OpenShift install can fail due to various reasons. If you do not find the symptoms described above on your system, it is unlikely that this issue is being encountered, and further review of the openshift.log would be required to determine the exact root cause.
