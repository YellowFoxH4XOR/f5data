Known Issue

The Configuration utility removes a 0.0.0.0 netmask from the Simple Network Management Protocol (SNMP) Client Allow List.

This issue occurs when any of the following condition is met:

  • You add a client with a 0.0.0.0 netmask to the SNMP Client Allow List.
  • The SNMP Client Allow List already contains an entry with a 0.0.0.0 netmask and you click the Update button.

Impact

The Configuration utility removes the 0.0.0.0 netmask.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The Configuration utility reports the client address, minus the 0.0.0.0 netmask.
  • When you attempt to add the same host without a netmask, the Configuration utility displays the following message:

    List entry already exists

Workaround

To work around this issue, you can add or modify SNMP allowed clients with 0.0.0.0 netmasks using the Traffic Management Shell (tmsh) utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

    Note: If you are currently logged in to the tmsh utility, you can skip this step.

  2. (Optional) View the list of currently allowed clients by typing the following command:

    list /sys snmp allowed-addresses

  3. Add/delete the client and netmask that you want to allow for SNMP access using the following tmsh syntax:

    modify /sys snmp allowed-address add/delete {ip address/netmask}

    For example, to allow all clients access, type the following command:

    modify /sys snmp allowed-address add {0.0.0.0/0.0.0.0}

  4. Save the configuration changes by typing the following command:

    save /sys config
