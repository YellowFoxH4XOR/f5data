Description

When BIG-IP devices intended for clustering are imported into BIG-IQ as standalone devices, analytics and statistics are not collected or displayed in the BIG-IQ dashboard, and sessions with Data Collection Devices (DCDs) are not established. This results in missing data collector graphs and non-functional DCD services, even if network connectivity and DCD health appear normal.

Environment

  • BIG-IQ Centralized Management version 8.3.0
  • Multiple BIG-IP LTM devices managed by BIG-IQ Centralized Management
  • Two Data Collection Devices (DCDs)
  • Devices intended to be managed as a cluster, but imported as standalone devices

Cause

BIG-IP LTM devices that should be managed as a cluster were imported as standalone devices, preventing analytics and statistics collection and blocking proper session establishment with DCDs.

Recommended Actions

  1. Remove the affected BIG-IP LTM devices from BIG-IQ Centralized Management.
  2. Delete the bigiq-analytics iApp and f5.bigiq-analytics template from each BIG-IP LTM device.
  3. Re-discover and import the BIG-IP LTM devices into BIG-IQ Centralized Management using the same cluster display name.
  4. Enable statistics on one device (this will enable statistics on both devices in the cluster).
  5. Verify that the configuration is visible in BIG-IQ Centralized Management and that sessions with the DCDs are established.
  6. If analytics global-settings list the DCDs in offbox-tcp-addresses but no connection is established, restart the AVRD process on the BIG-IP LTM devices.
  7. After reconfiguration, generate and provide new QKViews for further analysis if issues persist.
  8. If the issue persists after these steps, open a new case as this would be a new problem.
