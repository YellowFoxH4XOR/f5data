K22702505: Error Message: Got exception while handling EM auth token request: Invalid Token: Could not decrypt authentication token

Type
Support Solution
Published
2020-02-28
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.X, 13.1.4, 13.1.3, 13.1.1, 13.1.5, 13.1.0
Source
https://my.f5.com/manage/s/article/K22702505

Description

Errors similar to the following are continuously seen:

/var/log/httpd/httpd_errors

err httpd[12402]: [error] [client 10.10.10.1] Got exception while handling EM auth token request: Invalid Token: Could not decrypt authentication token: Could not RSA decrypt authentication token., referer:

/var/log/restjavad.0.log

[RestOperation] Unable to generate error body for POST https://10.10.10.1:443/mgmt/shared/gossip

Environment

  • BIG-IQ not in use
  • EM not in use
  • REST API not in use
  • HA pair

Cause

Bug ID 694485: Configuration sync does not sync iControl LX or iApp LX objects

Recommended Actions

Perform the following steps to resolve this issue:

  1. Execute the following command on both units:

    clear-rest-storage
    For multi-bladed platform use: clsh clear-rest-storage

    Note: This will clear REST tokens in storage and restart both restjavad and restnoded. This is not disruptive to traffic, however you will need to re-add the BIG-IP back into BIG-IQ to re-establish trust.

  2. If the logs are still appearing, proceed to the next step.
  3. Set one device into 'Forced Offline' state to prevent an active/active state.

  4. Reset trust on both devices under Device Management >> Device Trust >> Reset Device Trust.

    Note: Ensure that 'Generate new self-signed authority' is selected.

  5. From one device, add the peer device to the trust domain under Device Management >> Device Trust >> Device Trust Members.
  6. Once the trust is established, from one device, add both devices to Includes in device groups under Device Management >> Device Groups.
  7. Perform a ConfigSync.
  8. Release the offline device from offline state.

  9. Run the following command on both units:

    clear-rest-storage
    For multi-bladed platform use: clsh clear-rest-storage
    Note: This will clear REST tokens in storage and restart both restjavad and restnoded. This is not disruptive to traffic, however you will need to re-add the BIG-IP back into BIG-IQ to re-establish trust.

Additional Information

iControl LX or iApp LX are not required for this issue to occur. Without those features, the symptoms are benign aside from the logging.
