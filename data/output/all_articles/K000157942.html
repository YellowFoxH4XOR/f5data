Description

This article explains the relationship between the throughput values listed in the BIG-IP LTM datasheet (such as 95 Gbps for Layer 4 and 85 Gbps for Layer 7) and the throughput metrics displayed in the BIG-IP GUI summary graphs. It clarifies whether separate throughput metrics for L4 and L7 are available in the GUI, and provides guidance on interpreting these values for audit or reporting purposes.

Recommended Actions

    1. Datasheet vs. GUI Throughput Values

    • Datasheet Values:
      • F5 datasheets specify maximum throughput for Layer 4 (L4) and Layer 7 (L7) traffic (e.g., "95 Gbps L4 / 85 Gbps L7").
      • These are theoretical maximums, measured under ideal lab conditions using specific virtual server types:
        • L4 throughput: Measured with Performance (Layer 4) virtual servers using FastL4 profiles (hardware offload, no deep inspection).
        • L7 throughput: Measured with Standard virtual servers using full proxy and L7 processing (HTTP profile, iRules, etc.), which is more CPU-intensive and results in lower throughput than L4.
      • Example: i2600 supports "10 Gbps L4/L7"; Viprion B4300 supports "80 Gbps L4, 40 Gbps L7".
      • Datasheet values are for reference and capacity planning, not real-time monitoring.
    • GUI Values:
      • The BIG-IP GUI summary graphs (Dashboard > Throughput) display only overall system throughput.
      • There is no separate breakdown for L4 and L7 throughput in the GUI; all traffic is aggregated.
      • GUI throughput reflects real-world conditions and may differ from datasheet values due to environmental and operational factors.

     2. L4 vs. L7 Throughput Explained

    • L4 Throughput: Refers to raw TCP/UDP processing capability, typically higher due to less processing overhead.
    • L7 Throughput: Includes application layer processing (e.g., HTTP parsing, iRules), resulting in lower maximum rates compared to L4.

     3. GUI Graph Limitations and Data Averaging

    • The GUI uses a minimum sampling interval of one minute, averaging all data within that period.
    • Short-lived spikes or peaks in traffic may be smoothed out and not visible in the graphs.
    • GUI graphs can be misleading due to known issues (e.g., spikes after TMM restarts, incorrect PVA/ePVA calculations, dashboard/TMM stat mismatches).

    4. Audit and Reporting Considerations

    • For audits or reports, datasheet values are theoretical and based on lab conditions.
    • Real-world observed values in the GUI may differ due to operational factors.
    • If you need to validate L4/L7 throughput, refer to the official datasheet or perform controlled tests using specific virtual server types and external measurement tools.
    • There is no built-in feature in BIG-IP GUI to display separate L4 and L7 throughput graphs.

    Additional Information

    The difference between L4 and L7 throughput arises from extra processing required at the application layer (L7), which reduces total possible throughput compared to transport layer (L4).
    The GUI’s averaging mechanism is intended for general monitoring rather than capturing instantaneous peak performance.
