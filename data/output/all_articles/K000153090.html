K000153090: Cannot provision VE through ARM Template

Type
Support Solution
Published
2025-08-20
Updated
2025-08-20
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000153090

Description:


Deployment of BIG-IP VE High Availability (HA) pairs in Azure using the terraform-azure-bigip-module or F5 BIG-IP Azure ARM Templates 2.0 may fail. Common errors include issues with waagent and SSH key (re)generation, OS provisioning errors, and failed configuration initialization. Error messages may reference failed SSH key provisioning, "config failed to load," or "Long running operation failed with status 'Failed'." Initialization logs in /var/log/cloud/ may show errors from F5 cloud scripts.


Environment:


Product: BIG-IP LTM

Version: 17.5.1

Platform: F5-BIG-VE-BTA-1G-V18

Cloud: Microsoft Azure

Deployment method: terraform-azure-bigip-module or F5 BIG-IP Azure ARM Templates 2.0

Scenario: High Availability (HA) pair deployment

Cause:


Missing or misconfigured Azure Key Vault secrets and parameters (e.g., bigIpPasswordSecretId, BIGIP_PASSWORD) required for OS provisioning.

Lack of outbound internet access in the Azure environment, preventing the download of necessary cloud libraries and scripts.

Configuration errors or incomplete initialization, resulting in failed SSH key provisioning and inability to log in via SSH.

Recommendations:


Ensure all required Azure Key Vault secrets and parameters are created and correctly referenced before deployment, including bigIpPasswordSecretId and BIGIP_PASSWORD.

Confirm that the deployment environment allows outbound internet access to download necessary cloud libraries and scripts.

If deployment fails, access the BIG-IP VE instance via the Azure serial console and manually set the admin password if needed.

Review initialization logs in /var/log/cloud/ on the BIG-IP VE for errors from F5 cloud scripts.

If further troubleshooting is required, generate a qkview file for diagnostic analysis (see F5 documentation for instructions).
