Issue

There are several reasons why a newly created BIG-IP virtual server might not work properly.

To start troubleshooting the issue, check the packet activity by typing the following command:

bigtop

Review the counters for Packets In and Packets Out.

  • If both counters show no activity or if there is only activity in the Packets Out counter, it may indicate that there is a configuration issue with BIG-IP or with the upstream device, such as a router or firewall. To troubleshoot this issue, check the following:

    • Virtual server service
    • Upstream device configuration
    • Router configuration

  • If there is activity only in the Packets In counter, it may indicate that there is a configuration issue with BIG-IP or with a node. To troubleshoot this issue, check the Node configuration.

  • If both counters show activity, it indicates that at least some of the connections are working. If this is the case, you may have problems with the client system on which you are testing. Try testing from another client system.

Node configuration

Verify that the nodes are properly configured for the default gateway with the shared internal address for BIG-IP. If the nodes are not configured to send return traffic to BIG-IP, the clients will not receive a response from the virtual server.

Virtual server service

Some versions of BIG-IP do not automatically enable the service port on a newly created virtual server. If the service is not enabled, type the following command to enable it:

bigpipe service <port> <protocol> enable

For example, to configure HTTP, type the following command:

bigpipe service 80 tcp enable

To configure DNS, type the following command:

bigpipe service 53 udp enable

Upstream device configuration

The upstream devices, such as routers and firewalls, must be configured to pass traffic to the virtual server. If configured incorrectly, router ACLs or firewall rules can prevent traffic to any of the following:

  • The port the virtual server uses.
  • The virtual server IP address.
  • The subnet to which the virtual server belongs.

Check the configuration for all the upstream devices to verify that they are configured properly to pass traffic to BIG-IP.

Router configuration

If BIG-IP is new to your network, you may need to configure your router with the IP address for the BIG-IP. To test this, connect to the BIG-IP from the router. If it cannot connect, it most likely means that you need to add a route.

Contact F5 Technical Support for further assistance if these troubleshooting steps do not solve the problem.
