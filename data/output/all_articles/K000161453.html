K000161453: Access encountered an error (Operation not supported) after upgrade when accessing an app behind APM

Description

After upgrading to BIG-IP version 17.1.3, you may receive a "Access encountered an error (Operation not supported)." RST when trying to access an app behind APM.

Environment

Virtual server with APM profile

Application sending URIs containing non-encoded characters (e.g., {, }, |)

Cause

This is the result of a know issue being tracked as Bug ID 2298245 [APM]Access Profile Rejects HTTP Requests with Unencoded characters in URI 

Introduction of stricter URI validation in the APM HUD filter in BIG-IP 17.1.x, enforcing RFC 3986 compliance. Requests containing characters not defined as reserved or unreserved by RFC 3986 (such as {, }, and |) must be percent-encoded. Non-compliant requests triggered the APM HUD filter to reject them

Answer/Recommended Actions

Ensure all application URIs are percent-encoded before being sent to BIG-IP, especially for characters not allowed by RFC 3986.

Alternatively, or until the compliance is achieved, as a workaround, implement an iRule to encode problematic characters ({, }, |) in the URI before APM processing:

when HTTP_REQUEST {
	if { [HTTP::has_responded] } { return }
	# Get the current URI
	set original_uri [HTTP::uri]

	# Check if URI contains curly braces that need encoding
	if { [string length $original_uri] > 0 &&
	([string first "\{" $original_uri] != -1 ||
	[string first "\}" $original_uri] != -1) } {

		# Replace opening and closing curly braces
		set encoded_uri [string map [list \{ %7B \} %7D] $original_uri]

		# Set the new URI if it changed
		if { $original_uri ne $encoded_uri } {
			HTTP::uri $encoded_uri
		}
	}
}

Advise application developers to always encode URIs per RFC 3986 to prevent future issues.
