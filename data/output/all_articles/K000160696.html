K000160696: AS3 "Invalid Virtual Address, the IP address <Virtual_IP_Address> already exists" error when combining Service_Address and Net_Address_List

Description

When deploying AS3 declarations that use both a Service_Address object for virtualAddresses and a Net_Address_List for sourceAddress within the same Service class (such as Service_HTTP, Service_HTTPS, Service_TCP, etc.), you may encounter the error:


0107176c:3: Invalid Virtual Address, the IP address <Virtual_IP_Address> already exists.


This occurs because AS3 attempts to create multiple objects referencing the same IP address with different names in a single transaction, which is not permitted by BIG-IP.


The useIpName parameter, when set to true in the Service_Address class, instructs AS3 to use the IP address itself as the object name. This prevents naming conflicts and allows the declaration to succeed.

 

Environment

BIG-IP

AS3

 

Cause

By default, AS3 generates the Service_Address object name from the declaration’s object name (for example, "<Server_Address_Name>"). When a declaration also creates a Traffic Matching Criteria (TMC) object (such as when using a Net_Address_List for sourceAddress), AS3 attempts to create two objects with the same IP address but different names in the same transaction.


BIG-IP does not allow multiple objects with the same IP address but different names to be created in a single transaction, resulting in a duplicate IP error.

 

Answer/Recommended Actions

If you encounter the error message Invalid Virtual Address, the IP address <Virtual_IP_Address> already exists when using Service_Address and Net_Address_List together in an AS3 declaration, add "useIpName": true to your Service_Address object.


Example:


"My_Service_Address": {

 "class": "Service_Address",

 "virtualAddress": "<Virtual_IP_Address>",

 "useIpName": true

},

"My_Allowed_Sources": {

 "class": "Net_Address_List",

 "addresses": [

  "<Source_IP_1>/32",

  "<Source_IP_2>/32"

 ]

},

"My_HTTP_Service": {

 "class": "Service_HTTP",

 "virtualPort": 80,

 "virtualAddresses": [

  { "use": "My_Service_Address" }

 ],

 "sourceAddress": {

  "use": "My_Allowed_Sources"

 },

 "pool": "My_Pool"

}


This will ensure that both the Service_Address and Traffic Matching Criteria objects reference the same named object, preventing the conflict.

If you require Service_Address-specific properties (such as arpEnabled, icmpEcho, etc.), verify that these are still applied as expected when using useIpName.


Note: You must upgrade to at least AS3 v3.56.0 to use the "useIpName" parameter. This option is not available in earlier versions.


Additional Information

If the issue persists after using useIpName, collect AS3 trace logs and escalate to F5 Support for further analysis.


How to enable AS3 trace logging:


Add a Controls section to your AS3 declaration as shown below:


"controls": {

 "class": "Controls",

 "trace": true,

 "logLevel": "debug",

 "traceResponse": true

}
