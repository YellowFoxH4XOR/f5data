Known Issue

The Traffic Management Microkernel (TMM) may restart when a Dynamic Host Configuration Protocol (DHCP) server connects to a subscriber that is already connected but not released.

This issue occurs when all of the following conditions are met:

  • You are using Policy Enforcement Manager (PEM) DHCP to discover subscribers.
  • You have configured a DHCP relay virtual server with an associated DHCPv6 profile.
  • A remote DHCP server attempts a new connection to a PEM subscriber.
  • The PEM subscriber is connected to a remote DHCP server and has not been released.

Impact

Traffic processing will be interrupted while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system may fail to process traffic for a brief period.
  • Your BIG-IP system may fail over to another host in the device group.
  • You notice a TMM core file in the /var/core directory.
