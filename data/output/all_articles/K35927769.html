Description

After upgrading from 11.x to 13.1.x additional WideIP records are created when iRule is applied to WideIP

What are the triggers/logic to create a AAAA and a CNAME wideip in 13.1.x when upgrading from 11.x?

Environment

  • BIG-IP GTM, BIG-IP DNS
  • Upgrade from 11.x to 13.1.x and above
  • WideIP
  • iRules

Cause

When upgrade from 11.x to 13.1.x, a wideip with a simple irule will create addtional aaaa and cname wideip.

Recommended Actions

Remove unnecessary WideIP's

tmsh delete gtm wideip <record type> <name>

For example: tmsh delete gtm wideip cname cname.wideip.local

Additional Information

When upgrade from 11.x to 13.1.x, a wideip with a simple irule will create addtional aaaa and cname wideip. A, AAAA, and CNAME pools are created during the upgrade using the same pool name for each record type. When the original pool has IPv4 members, an A record type pool is created. The same process is performed when the original pool contains IPv6 members a pool for the record type AAAA is created. This is also true for CNAME members of the original pool in which a CNAME pool is created.
