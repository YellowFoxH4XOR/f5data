Description

Following the conceptual and design guidance in Part 1, this article provides step-by-step implementation instructions for deploying BGP and ECMP with F5 Distributed Cloud Customer Edge (CE) nodes. It covers BGP peering and routing policy configuration in the F5 Distributed Cloud Console, and includes ready-to-use configuration examples for Fortinet FortiGate and Palo Alto Networks firewalls.

  • How is BGP peering configured on a Customer Edge node in the F5 Distributed Cloud Console?
  • How are BGP routing policies configured to allow VIP prefix advertisement and deny all other prefixes?
  • How is BGP and ECMP configured on a Fortinet FortiGate firewall for CE peering?
  • How is BGP and ECMP configured on a Palo Alto Networks firewall for CE peering?
  • How is a CE node isolated for maintenance by withdrawing BGP VIP advertisements?
  • How is BGP route withdrawal verified on the upstream firewall after CE isolation?

Environment

  • F5 Distributed Cloud (SaaS)
  • Customer Edge (CE) nodes — Secure Mesh Sites v2 (SMSv2) on AWS or on-premises
  • Two CE nodes with the following IP configuration (example):
    • CE1 Outside interface: 10.154.4.160/24
    • CE2 Outside interface: 10.154.4.33/24
    • Firewall Inside interface: 10.154.4.119/24
    • Global VIP: 192.168.100.10/32
    • VIP subnet: 192.168.100.0/24
  • BGP AS Numbers: CE nodes — AS 65002; Upstream Firewall/Router — AS 65001
  • Upstream firewall: Fortinet FortiGate or Palo Alto Networks (Advanced Routing Engine mode)
  • ECMP enabled on upstream firewall with maximum paths configured

Step 1: Configure BGP Peering in F5 Distributed Cloud Console

  1. Navigate to Multi-Cloud Network Connect → Manage → Networking → External Connectivity → BGP Peers & Policies.
  2. Click Add BGP Peer and configure the following:
    • Name: A descriptive name for the BGP peer object (e.g., bgp-peer-ce1)
    • Where: Select Site and specify the CE site reference
    • ASN: 65002
    • Router ID: Select From Interface Address
  3. Click Peers → Add Item and fill in the relevant peer fields:
    • Peer IP address (upstream firewall inside interface IP: 10.154.4.119)
    • Peer AS number: 65001
    • Interface to use for peering (e.g., the CE's outside/SLO interface)
  4. Save the BGP Peer configuration. Repeat for each CE node.

Step 2: Configure BGP Routing Policies in F5 Distributed Cloud Console

  1. Navigate to Multi-Cloud Network Connect → Manage → Networking → External Connectivity → BGP Peers & Policies → BGP Routing Policies.
  2. Click Add BGP Routing Policy. Create the following two policies:

Policy 1 — Allow VIP Advertisement (Outbound):

  1. Provide a name (e.g., allow-vip) and click Configure under Rules.
  2. Click Add Item and configure a rule to permit /32 prefixes from the VIP subnet:
    • Match prefix: 192.168.100.0/24 with le 32 (matches all /32 VIP prefixes within the subnet)
    • Action: Permit
  3. Save the policy.

Policy 2 — Deny All (Inbound and for isolation use):

  1. Provide a name (e.g., filter-all) and click Configure under Rules.
  2. Click Add Item and configure a rule to deny all prefixes.
  3. Save the policy.

Apply the policies to the BGP Peer objects:

  • Inbound policy: filter-all — applied to ALL nodes
  • Outbound policy: allow-vip — applied to ALL nodes

Fortinet FortiGate Configuration

Step 1: Configure Router ID, AS Number, and ECMP

config router bgp
  set as 65001
  set router-id 10.154.4.119
  set ebgp-multipath enable

Step 2: Configure BGP Neighbors

config neighbor
  edit "10.154.4.160"
    set remote-as 65002
    set route-map-in "ACCEPT-CE-VIPS"
    set route-map-out "DENY-ALL"
    set soft-reconfiguration enable
  next
  edit "10.154.4.33"
    set remote-as 65002
    set route-map-in "ACCEPT-CE-VIPS"
    set route-map-out "DENY-ALL"
    set soft-reconfiguration enable
  next
end

Step 3: Create Prefix List for VIP Range

config router prefix-list
  edit "CE-VIP-PREFIXES"
    config rule
      edit 1
        set prefix 192.168.100.0 255.255.255.0
        set ge 32
        set le 32
      next
    end
  next
end

Note: The ge 32 and le 32 parameters ensure only /32 prefixes within 192.168.100.0/24 are matched — exactly what CE nodes advertise for VIPs.

Step 4: Create Route Maps

config router route-map
  edit "ACCEPT-CE-VIPS"
    config rule
      edit 1
        set match-ip-address "CE-VIP-PREFIXES"
      next
    end
  next
  edit "DENY-ALL"
    config rule
      edit 1
        set action deny
      next
    end
  next
end

Step 5: Verify BGP and ECMP

get router info bgp summary
get router info routing-table bgp

Expected output showing ECMP (two paths to VIP):

B 192.168.100.10/32 [20/255] via 10.154.4.160, 00:00:11
                             via 10.154.4.33, 00:00:11

Palo Alto Networks Configuration (Advanced Routing Engine Mode)

Step 1: Configure ECMP Parameters

set network logical-router default vrf default ecmp enable yes
set network logical-router default vrf default ecmp max-path 4
set network logical-router default vrf default ecmp algorithm ip-hash

Step 2: Configure BGP Peer Group and Peers

set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE1 peer-as 65002
set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE1 local-address interface ethernet1/2
set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE1 peer-address ip 10.154.4.160
set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE2 peer-as 65002
set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE2 local-address interface ethernet1/2
set network logical-router default vrf default bgp peer-group BGP_PEERS peer CE2 peer-address ip 10.154.4.33

Step 3: Configure Prefix Lists and Routing Profiles

set network routing-profile filters prefix-list ALLOWED_PREFIXES type ipv4 ipv4-entry 1 prefix entry network 192.168.100.0/24
set network routing-profile filters prefix-list ALLOWED_PREFIXES type ipv4 ipv4-entry 1 prefix entry greater-than-or-equal 32
set network routing-profile filters prefix-list ALLOWED_PREFIXES type ipv4 ipv4-entry 1 prefix entry less-than-or-equal 32
set network routing-profile filters prefix-list ALLOWED_PREFIXES type ipv4 ipv4-entry 1 action permit

Step 4: Verify BGP and ECMP

run show advanced-routing bgp peer status logical-router default
run show advanced-routing route logical-router default

Implementing CE Isolation for Maintenance

  1. In the F5 Distributed Cloud Console, navigate to the BGP Peer object for the CE to be isolated.
  2. Edit the Peer and change the Outbound BGP routing policy from allow-vip to filter-all (or another policy that denies VIP prefix advertisement).
  3. Save the configuration. The CE will stop advertising its VIP routes; the upstream firewall removes it from ECMP paths within seconds.

Verification on FortiGate after isolation:

get router info bgp summary
# Verify 0 prefixes received from isolated CE peer

get router info routing-table bgp
# Verify only one ECMP path remains (through the non-isolated CE)

Restoring the CE after maintenance:

  1. In the BGP Peer configuration, restore the outbound policy to allow-vip.
  2. Save the configuration. The CE resumes advertising VIP routes and is automatically added back to ECMP paths on the upstream firewall.

Additional Information

This article is Part 2 of a two-part series. Part 1 covers the conceptual and design principles behind BGP and ECMP for CE deployments, including VIP architecture, filtering design philosophy, and the maintenance isolation concept. It is recommended to read Part 1 before implementing the configurations in this article.

The Palo Alto Networks configuration in this article assumes the firewall is operating in Advanced Routing Engine mode using the logical router named default. Standard mode configurations will differ.

The BGP-based approach transforms CE deployments from traditional Active/Standby models into full Active/Active topologies where every node contributes to handling traffic, and any node can be gracefully removed for maintenance without impacting application availability.
