Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file that includes the 'Assertion "we always have room in tx ring!" failed' error message.

This issue occurs when the following condition is met:

  • TCP segmentation offload (TSO) is enabled on the BIG-IP system.

    Note: TSO support was introduced in BIG-IP 11.4.0 and was initially enabled, by default, only for BIG-IP Virtual Edition (VE). However, beginning in BIG-IP 11.5.0, TSO is enabled, by default, for all platforms.

Impact

The BIG-IP system may temporarily fail to process traffic and failover if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H499530 on the Diagnostics > Identified > High screen.
  • The TMM process restarts and produces a core file in the /var/core directory.
  • The BIG-IP system logs a message similar to the following example in the /var/log/tmm* files:

    panic: ../dev/hsb/if_hsb.c:5360: Assertion "we always have room in tx ring!" failed.

  • ID 509782 documented in K16780: The BIG-IP system may drop TSO packets

Workaround

To work around this issue, you can disable TSO by setting the value of the tm.tcpsegmentationoffload BigDB key to disable, and restarting the Traffic Management Microkernel (TMM). To do so, perform the following procedure:

Impact of workaround: Disabling TSO may cause increased CPU usage as segmentation offload will be performed in the software when TSO is disabled. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your specific environment. Additionally, restarting TMM temporarily interrupts traffic processing, and devices configured as a high-availability pair may fail over.

  1. Log in to the BIG-IP command line.
  2. Disable TSO by typing the following command:

    tmsh modify sys db tm.tcpsegmentationoffload value disable

  3. Restart TMM by typing the following command:

    bigstart restart tmm
