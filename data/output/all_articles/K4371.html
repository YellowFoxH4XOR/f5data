The maximum number of segments held in the reassembly queue defaults to 1024. In rare circumstances, it may be necessary to increase this number.

Starting in BIG-IP and 3-DNS versions 4.5.11 and 4.6.3, you can set the size of the TCP reassembly queue. This feature is also available if you have installed the patch for VU#395670 and CAN-2004-0171, provided in K3369: Security advisory: TCP reassembly queue vulnerability - CAN-2004-0171.

Viewing the current TCP assembly queue setting

To display the current TCP reassembly queue size, type the following command:

sysctl net.inet.tcp.reass_maxqlen

Changing the TCP assembly queue setting

To change the size of the TCP reassembly queue, use the following command syntax, replacing <number> with the desired queue size:

sysctl -w net.inet.tcp.reass_maxqlen=<number>
