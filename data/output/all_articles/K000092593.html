K000092593: TLS fallback behavior in HTTPS monitor

Type

Published
2022-11-10
Updated

Source

Description

When a HTTPS monitor is configured, bigd probes a pool member with TLS version from TLSv1.2 and falls back to match pool member's TLS version if necessary.

The packet capture below shows the TLS version used by bigd.

Note: The "Version" column refers to TLS handshake version (tls.handshake.version in Wireshark).

In the above, we see that when bigd probes a pool member for the first time, it uses TLSv1.2 . The server responds with Server Hello with TLSv1. Sensing the pool member uses TLSv1, bigd falls back to using TLSv1 in subsequent probes for the pool member.
 

Environment

  • BIG-IP

  • HTTPS monitor

  • bigd monitoring (In-TMM monitoring is not in use. In-TMM is disabled, by default. For more information, refer to K11323537: Configuring In-TMM monitoring.)
     

Cause

None
 

Recommended Actions

The TLS fallback behavior works under normal situations, and there is no corrective action needed.

However, if you wish to configure a pool member to use higher TLS version (eg. TLSv1.2) and reject lower versions (eg. TLSv1.1 and TLSv1), you will encounter Bug ID 944173. If that is the case, you may restart bigd so that it attempts from TLSv1.2 again or you may use the workaround in Bug ID 944173.
