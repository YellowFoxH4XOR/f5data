K22830401: Disk partition /var (slot #) has only 0% free

Type
Support Solution
Published
2021-01-18
Updated
2025-12-03
Applies to
  • VIPRION Platforms
  • BIG-IP
  • BIG-IP LTM: 14.1.2, 13.1.1, 13.1.0
Source
https://my.f5.com/manage/s/article/K22830401

Description

The /var partition may become 100% full, impacting future disk IO to the partition.  There may be periodic restjavad and bigd daemons restart related to disk space exhaustion.

Possible console warnings could be noticed during the time of issue.
Disk partition /var (slot #) has only 0% free

Environment

  • BIG-IP LTM
  • Multi-blade VIPRION
  • Processing traffic, while the DoS dashboard is open

Cause

Issue is due to a Bug ID 745809

Recommended Actions


Impact of procedure: Performing the following procedure, the BIG-IP REST API is temporarily inaccessible, and higher disk IO may be seen.

Run the following commands, in sequence:
bigstart stop restjavad
rm -rf /var/config/rest/storage*.zip
rm -rf /var/config/rest/*.tmp
bigstart start restjavad

Additional Information

Executing the following command will give information to check files that occupy more space in /var directory                        

find /var/ -xdev -type f -exec du {} \; | sort -rn | head -20

You should see similar output as below:

11212   /var/config/rest/storagexxxx.zip
11212   /var/config/rest/storagexxxx.zip
