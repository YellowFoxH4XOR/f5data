K40720923: An iRule with event HTTP_RESPONSE or HTTP_REQUEST fails to execute on a APM Virtual Server.

Type
Support Solution
Published
2022-04-05
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K40720923

Description

This solution will describe the situation in which an iRule applied to a Virtual Server with an Access Policy fails to execute and how to resolve this issue.

  • An iRule applied to an APM enabled Virtual Server fails to execute.
  • You will observe no error messages.

Environment

  • LTM Virtual Server
  • APM
  • Access Policy
  • iRule that uses the HTTP_RESPONSE or HTTP_REQUEST events.

Cause

HTTP_RESPONSE event is executed on the server side where HTTP_RESPONSE_RELEASE is executed on the client side (as well as HTTP_REQUEST).

Recommended Actions

Edit the iRule and change the event.

  1. Login to the BIG-IP admin GUI.
  2. Navigate to Local Traffic>iRules>iRule List.
  3. Click on the name of the iRule.
  4. Change the event from HTTP_RESPONSE to HTTP_RESPONSE_RELEASE (or HTTP_REQUEST to HTTP_REQUEST_RELEASE).
  5. Click Update.

Additional Information

HTTP_RESPONSE is typically used to handle HTTP response data within the context of a server response in a load balancing scenario. With APM policy execution, the BIG-IP itself is APM's server and the request/response comes from within BIG-IP itself. Because of this, HTTP_RESPONSE event is not raised and cannot be used.
