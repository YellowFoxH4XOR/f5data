K12255: The ARX system sends SNMP trap if sntpc fails to receive a response

Issue

To maintain time synchronization between the ARX Adaptive Services Module and the System Control Module (SCM), the Adaptive Service Module's sntpc process requests time updates from the SCM. If the sntpc process does not receive an NTP response from the SCM, the request will time out and a new request is sent.

Note: There is a known issue where only the initial sntpc request will time out but the subsequent request will not time out. For information, refer to K11709: The sntpc process may fail to time out and indefinitely wait for a response.

For ARX 5.1.5 and earlier, the ARX system will not provide indication when the Adaptive Service Module's sntpc process fails to receive an NTP update from the SCM.

Beginning in ARX 5.2.0, if the Adaptive Service Module's sntpc process has not received a response in 10 minutes, the ARX system will send an SNMP trap that appears similar to the following example:

:SYNC_CLOCK-0-WARN-SCM_TIME_POLL_FAILURE:: Failed to poll SCM for time synchronization: 'sntpc failed to provide data'. Scheduled polling continues.

Additionally, an entry in the show health command output will appear similar to the following example:

System Health Information
Date                     ID      Event                       Description
---------------------------------------------------------------------------------------
Wed Jun  2 15:56:34 2010 (35)  - clockSyncFailRaise          Processor 3.2 failing to querying
SCM time server.

F5 Product Development introduced this change in behavior as part of ID 39300.
