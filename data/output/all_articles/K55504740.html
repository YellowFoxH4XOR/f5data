Issue

Old Behavior

In versions prior to BIG-IP 13.0.0, when a virtual server is configured with multiple Client SSL profiles, the BIG-IP system tries to select a Client SSL profile for a connection based on the requested host name. The BIG-IP system matches the requested host name using the following order of precedence:

  1. Server name configured in the Client SSL profiles.
  2. Common name (CN) of an SSL certificate used by the Client SSL profiles.
  3. Subject alternative name of an SSL certificate used by the Client SSL profile.

However, this order of precedence is not in accordance with RFC-6125, which states the common name should be used as a "last resort." Therefore, the BIG-IP system should try and match a subject alternative name before trying to match common name.

New Behavior

Beginning in BIG-IP 13.0.0, the BIG-IP system matches a requested hostname using the following order of precedence:

  • Server Name configured in the Client SSL profiles.
  • Subject Alternative Name of an SSL certificate used by the Client SSL profiles.
  • Common Name of an SSL certificate used by the Client SSL profiles.

The system first tries to match a requested host name with a server name configured in the Client SSL profiles. If no match, it tries to match a subject alternative name of an SSL certificate used by the Client SSL profile. If there is no match, then the system tries to match a common name of an SSL certificate used by the Client SSL profiles.

F5 Product Development tracked this change as ID 584471.

Impact

The BIG-IP selects a Client SSL profile that uses a certificate configured with a matching subject alternative name before selecting a Client SSL profile that uses a certificate with a matching common name. This may affect which Client SSL profile is selected for virtual servers configured to use multiple Client SSL profiles and use SSL certificates configured with subject alternative names.

Recommended Actions

When configuring a virtual server to use multiple Client SSL profiles, you should consider the order of precedence used for the selection of those Client SSL profiles. 

Additionally, when upgrading from a version that uses the previous behavior to a version that uses the new behavior, you should review your configuration to determine whether the new behavior may adversely affect how your traffic is processed.
