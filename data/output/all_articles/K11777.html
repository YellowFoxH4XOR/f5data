K11777: Choosing an HTTP profile for a BIG-IP WebAccelerator-enabled virtual server

For optimal performance, F5 recommends using the default http-acceleration profile when configuring a BIG-IP WebAccelerator virtual server.

The BIG-IP WebAccelerator Smart Cache is fast, and is capable of sophisticated dynamic object management. However, due to its flexibility, it is not as fast or as efficient as the RAM Cache feature that is configured in the BIG-IP LTM HTTP profile. Static objects, such as images and style sheets that do not require the dynamic caching provided by the BIG-IP WebAccelerator system's Smart Cache, are more efficiently served from the BIG-IP LTM RAM Cache. When static objects are served from RAM Cache instead of Smart Cache, the number of requests that must be handled by the BIG-IP WebAccelerator system's pvac process is greatly reduced, improving the performance and increasing the overall scalability of the BIG-IP WebAccelerator system.

Note: It is possible to realize the performance optimization noted above by applying a custom HTTP profile that uses RAM Cache settings similar to those of the http-acceleration profile. However, in some versions, the http-acceleration profile is required to produce accurate performance graphs. For more information, refer to K10206: The http-acceleration profile is required for accurate performance graphs.

F5 Product Development tracked a Request for Enhancement (RFE) as ID 246750 (formerly CR101468) to verify that an appropriate HTTP profile is applied before enabling BIG-IP WebAccelerator on a virtual server. This RFE no longer applies to BIG-IP WebAccelerator version 11.0.0 and later due to architectural changes. In BIG-IP WebAccelerator version 11.0.0, the RAM Cache configuration is now under the WebAcceleration profile instead of the HTTP profile and is required when configuring a BIG-IP WebAccelerator virtual server.
