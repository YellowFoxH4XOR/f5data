Description

Kerberos authentication is failing intermittently causing authentication popup to show up in the browser.
Similar logs can be observed under /var/log/apm:

Apr 26 14:10:16 bigip1 info apmd[13078]: 01490006:6: /Common/AP_EXAMPLE:Common:2478fdc8: Following rule 'Negotiate' from item 'HTTP 401 Response' to item 'Kerberos Auth'
[...]
Apr 26 14:10:16 bigip1 debug apmd[13078]: 01490266:7: /Common/AP_EXAMPLE:Common:2478fdc8: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'display_status_1()': 94: 3278fdb8 : GSS-API error gss_accept_sec_context: 10000 : An unsupported mechanism was requested
Apr 26 14:10:16 bigip1 debug apmd[13078]: 01490266:7: /Common/AP_EXAMPLE:Common:2478fdc8: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'display_status_1()': 94: 3278fdb8 : GSS-API error gss_accept_sec_context: 186a8 :

 

Environment

  • A virtual server is configured with an APM Access Profile
  • Configured Access Policy is using "Kerberos Auth" type of agent (for transparent client side authentication with Kerberos)
  • BIG-IP has one or multiple DNS configured
  • At least one of the configured DNS has multiple PTR records for the configured virtual server IP
  • Users are intermittently being prompted with an authentication popup window.

Cause

Upon receiving TGS ticket from client, BIG-IP kerberos library will attempt 'A/AAAA' queries for the requested virtual server hostname as well as a PTR query for the resolved IP.
In the event that multiple PTR records are returned by the DNS for the resolved virtual server IP, authentication may fail if the first returned record isn't the one being requested by the browser (as part of the Host header value).

F5 kerberos library does not support more than one PTR record for a given virtual server IP.

Recommended Actions

On your DNS server, search for multiple PTR records attached to the IP address used by the virtual server and delete any non used ones, so that only one remains.
