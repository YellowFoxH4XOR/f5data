Known Issue

The TCP::close iRule command may cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured to use an iRule with the TCP::close command within the HTTP_REQEST event.
  • The virtual server is also configured with a profile that enables HTTP cache (referred to as RAM Cache in BIG-IP 10.x).

Note: In BIG-IP 11.x and later, HTTP cache is enabled by associating a Web Acceleration profile with the virtual server. In BIG-IP 10.x, RAM Cache is enabled in an HTTP profile.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic while TMM restarts.

Workaround

To work around this issue, you can disable HTTP caching for the affected virtual server. To do so, perform one of the following procedures for your specific version:

  • Removing the associated Web Acceleration profile (11.x and later)
  • Disabling RAM Cache in the HTTP profile (10.x)

Removing the associated Web Acceleration profile (11.x and later)

To disable HTTP caching for BIG-IP 11.x and later, modify the affected virtual server to remove the associated Web Acceleration profile. To do so, perform the following procedure:

Impact of workaround: Disabling HTTP caching may increase the load for back-end resources. However, the impact will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to the Local Traffic > Virtual Servers page.
  3. Select the name of the affected virtual server.
  4. In the Acceleration section, select None from the Web Acceleration Profile drop-down menu.
  5. Click Update.

Disabling RAM Cache in the HTTP profile (10.x)

To disable HTTP caching for BIG-IP 10.x, disable RAM Cache in the HTTP profile used by the affected virtual server. To do so, perform the following procedure:

Impact of workaround: Disabling RAM Cache may increase the load for back-end resources. However, the impact will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to the Local Traffic > Profiles > Services > HTTP page.
  3. Click on the name of the affected HTTP profile.

    The selected HTTP profile's configuration page opens.

  4. In the RAM Cache section, select Disabled from the RAM Cache drop-down menu.
  5. Click Update.
