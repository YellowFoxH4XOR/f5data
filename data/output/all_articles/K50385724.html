K50385724: BIG-IQ DCD disk partition /var has only 0% free

Type
Support Solution
Published
2021-07-30
Updated
2025-04-01
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K50385724

Description

BIG-IQ Data Collection Device disk partition /var has only 0% free.
Thus BIG-IQ Data Collection Device is unable to receive the event logs from BIG-IP devices and  ES cluster status is turned to red.
Similar errors will be logged under  /var/log/elasticsearch/eslognode.log

low disk watermark [85%] exceeded on [spL3oMY3QvWG2LnatmLc5w][7ff494ac-fce7-422f-8691-6a818b81b78e][/var/config/rest/elasticsearch/data/nodes/0] free: 240.1gb[12.8%], replicas will not be assigned to this node
 

Environment

  • BIG-IQ Data Collection Device
  • /var is 100% for BIG-IQ Data Collection Device

Cause

 Index size is contributing to disk space

Recommended Actions

  1. Increase the disk space of /var as mentioned in the article  https://my.f5.com/manage/s/article/K58621633
    If the disk space in BIG-IQ Data Collection Device cannot be extended further or it is required to free up the space in BIG-IQ Data Collection Device then follow below steps
  2.  Login into BIG-IQ Data Collection Device using the root.
  3.  Identify indices which are consuming the high disk space from the BIG-IQ Data Collection Device bash prompt.
    # curl localhost:9200/_cat/indices?v | sort
     
  4. Identify the older raw indices to be deleted based on date. Lower number at the end of index name means older data
  5.  Delete the older raw indices, using below command

     # curl -X DELETE localhost:9200/<index name>

    Impact of the procedure :Deleting the index remove the statistics data contained in that index. Proceed to do so if you are fine with losing the statistics data.

    For example:
    # curl -s localhost:9200/_cat/indices?v   # List the index 

    health  status   index                                 uuid                     pri rep docs.count docs.deleted store.size pri.store.size
    yellow  open   asm-correlation_2021-04-01t00-41-22+0700 9b6PX5eARoW7tyItNz-tqQ   5   1          0            0         955b     955b
    yellow  open   websafe_2020-11-06t00-00-00+0700         dg2CQ8MxRvG2gFjSwSTi9g   5   1     153571916       588238    207.5gb   207.5gb
    yellow  open   websafe_2020-10-07t00-00-00+0700         vTPcVb9xSGuIrErBCexRMQ   5   1     146176545         2540     192.2gb   192.2gb

    In above example we intend to delete the index websafe_2020-10-07t00-00-00+0700 which is occupying 192.2 gb space.

    # curl -X DELETE localhost:9200/websafe_2020-10-07t00-00-00%2B0700

    Note :In the above example '+' is replaced with '%2B' under curl command.
     
  6. Confirm that the index is deleted by running:
    #curl -s localhost:9200/_cat/allocation?v   <-----<  disk percent should go down
    #curl -s localhost:9200/_cat/indices?v         <-----<  deleted index is not present
    #df -h                                                                          <-----<  check the disk space
     
  7. If the percentage of disk used by /var is still high, delete the next high size index. Follow the step again mentioned in step 5.
     
  8. After getting the disk usage under 85%, ES will allocate the shards that are currently unassigned, and the cluster will go from red to yellow to green. Then BIG-IQ Data Collection Device will start to receive the event logs from BIG-IP devices.
