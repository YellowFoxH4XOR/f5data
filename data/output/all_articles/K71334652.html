K71334652: BIG-IP APM Edge Client not auto-populating username

Type
Support Solution
Published
2021-08-10
Updated
2023-02-21
Applies to
  • BIG-IP APM: 16.X.X
Source
https://my.f5.com/manage/s/article/K71334652

Description

BIG-IP APM Edge Client does not auto-populate username.

Environment

  • BIG-IP APM Edge Client

Cause

BIG-IP APM Edge Client will auto-populate username when the following three Access Policy Logon Page Agent fields, or a subset there of, are implemented, in any order:

TypePost Variable Name
textusername
passwordpassword
password<any_name>

Note: if custom field Type password and Post Variable Name <any_name> is implemented, it must be Type password and there must be a Variable Assign implemented before the Logon Page Agent that sets custom variable session.logon.page.softToken.fieldId to value <any_name>. For example, if the Logon Page Agent contains a field Type password with custom Post Variable Name "token" then there needs to be a Variable Assign before that Logon Page Agent where 'session.logon.page.softToken.fieldId = token'.
 

Recommended Actions

  1. Review your Access Policy's Logon Page Agent settings and confirm the following:
    • The username field is Type text and the Post Variable Name is "username" (default)
    • The password field is Type password and the Post Variable Name is "password" (default)
    • If there is a Type password field with a custom Post Variable Name (not "password") then make sure there is a Variable Assign before the Logon Page Agent that sets variable session.logon.page.softToken.fieldId to the value of the custom Post Variable Name (can only be implemented once)

Additional Information

The BIG-IP APM Edge Client auto-populate username criteria addressed above is enforced by server-side web code/logic which can be found under Advanced Customization and within the logon.inc page of a Standard Customization Type Access Policy. 

// check whether logon form is compatible with the client for auto-population and auto-submission
// only "username", "password" and soft token field (the name is stored in softTokenFieldId ) are supported
// fields can be configured in either order, but can only be text, password or checkbox types
// form is not considered compatible if it contains any additional fields not supported by the client
// The form is compatible even if it contains a subset of the supported fields
// In this case the client will auto-populate only those fields
...
    // Check if there are any custom fields that are not supported by Edge Client for auto-population and auto-submission
    for( var i=0; i<inputs.length; i++ ){
       if((inputs[i].type == "text" && inputs[i].name == "username") ||
          (inputs[i].type == "password" && inputs[i].name == "password") ||
          (softTokenSupported && inputs[i].type == "password" && inputs[i].name == softTokenInput.name)){
               continue;
       }else {
          return false;
       }
    }
    return true;
}
