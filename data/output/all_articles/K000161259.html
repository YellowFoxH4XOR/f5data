Description

Clarifies whether there is a limit to applying the same Behavioral DoS (BADoS) profile to more than two virtual servers in BIG-IP ASM/Advanced WAF and the relevance of the adm.max.vs database key.

Environment

  • Product: BIG-IP ASM / Advanced WAF
  • Version: 17.x, 21.x
  • Feature: Behavioral DoS (BADoS) profiles
  • License: Advanced WAF

Cause

The two-virtual-server limit for BADoS-enabled DoS profiles applies only to legacy ASM licenses. With the Advanced WAF license, this restriction is removed. The adm.max.vs database key is no longer applicable in Advanced WAF or DDoS Hybrid Defender (DHD).

Answer/Recommended Actions

  • No Hard Limit with Advanced WAF License:
    There is no hard-coded limit on the number of virtual servers that can share a BADoS-enabled DoS profile when using the Advanced WAF license.
  • adm.max.vs Database Key:
    The adm.max.vs database key is irrelevant in Advanced WAF or DHD and can be disregarded.
  • Per-Virtual Server Statistics:
    BADoS statistics and behavioral learning are collected per virtual server, so sharing a profile does not negatively impact detection accuracy.
  • Recommended Best Practice:
    Limit the number of virtual servers per BADoS profile to approximately 70, based on system resources and traffic volume. This is a guideline, not a strict limit.
  • Monitor System Resources:
    Monitor the monpd process and overall system resource usage, especially as the number of protected virtual servers increases.
  • Reducing False Positives:
    • Avoid combining Behavioral DoS with TPS/Stress-Based DoS, as TPS limits can interfere with BADoS learning.
    • Consider disabling signatures if not required.
    • Adjust ADM sensitivity settings as needed.
