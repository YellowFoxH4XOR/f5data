Known Issue

Prepending a BIG-IP APM session variable value with a hyphen (-) may cause access policy execution to fail. 

In the following iRule example, attempting to set the session.logon.last.password session variable value to -password fails because the first character in the value is a hyphen (-):

    when ACCESS_POLICY_AGENT_EVENT {
       if { [ACCESS::policy agent_id] eq "test" } {
          ACCESS::session data set session.logon.last.password "-password"
        }
    }

Impact

Including a hyphen as the first character in a BIG-IP APM session variable impairs access policy functionality.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H526975 on the Diagnostics > Identified > High screen.
  • If session variable values are prepended with hyphens, access policy execution is impaired or fails.
  • Messages similar to the following example appear in the /var/log/ltm file:

    err tmm3[12741]: 01220001:3: TCL error: /Common/pass <ACCESS_POLICY_AGENT_EVENT> - bad option name (line 1)setting variable session.logon.last.password for sid (null) failed (line 1)Illegal argument (line 1) (line 1) invoked from within "ACCESS::session data set session.logon.last.password "-password""
