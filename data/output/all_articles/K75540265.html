Security Advisory Description

An attacker may be able to bypass APM's internal restrictions and retrieve static content that is hosted within APM by sending specifically crafted requests to an APM Virtual Server. CVE-2021-23016

Impact

This vulnerability may allow an attacker to retrieve static content hosted on the BIG-IP system that they would otherwise not be able to, allowing them to fingerprint a device more effectively. It does not allow any modification of data nor the exposure of any sensitive information or personally identifiable information (PII) in the standard, default, or recommended configurations.

Mitigation

To mitigate this vulnerability, you can create an iRule and associate it with the affected virtual server. To do so, perform the following procedure:

Impact of action: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. For Name, enter a name for the iRule.
  5. For Definition, enter the following code:

    when CLIENT_ACCEPTED {
      ACCESS::restrict_irule_events disable
    }

    when HTTP_REQUEST {
       if {[HTTP::uri] starts_with "/public/images/customization/" && ([HTTP::path] contains ".." || [HTTP::path] contains "%2") } {
         set removeDots [string map [list ".." "" ".%2e" "" ".%2E" "" "%2e." "" "%2E." "" "%2e%2e" "" "%2E%2e" "" "%2e%2E" "" "%2E%2E" "" ] [HTTP::uri]]
         HTTP::redirect http://[HTTP::host]$removeDots
         # log local0. "Redirect to [HTTP::host]$removeDots"
      }
    }

  6. Select Finished.
  7. Go to Local Traffic > Virtual Servers > Virtual Server List.
  8. Under the Resources column for the affected virtual server, select Edit. 
  9. Under iRules, select Manage.
  10. In the Available list, select the name of the newly created iRule.
  11. Select << to move it to the Enabled list.
  12. Select Finished.
