Issue

Error Message

01490290:3: <accessprofile_name>:<apm_sessionID>:<accesspolicy_agent>: OAuth Client: failed for server '<OAuth_server_name>' using '<grant type>' grant type (), error: <error message>

In this error message, note the following:

  • <accessprofile_name> is the name of the access profile associated to the BIG-IP APM virtual server.
  • <apm_sessionID> is the BIG-IP APM session ID.
  • <accesspolicy_agent> is the name of the access policy agent found in the Visual Policy Editor (VPE) where the error is triggered.
  • <OAuth_server_name> is the name of the OAuth server. This is configured in Access ›› Federation : OAuth Client / Resource Server : OAuth Server
  • <grant_type> is the name of the grant type. This is configured in the OAuth Client agent in the VPE and can be either Authorization Code or Password.
  • <error_message> is the error message describing the type of error and can be one of the following:
    • HTTP error 503, DNS lookup failed
    • HTTP error 503, Connect failed

For example:

01490290:3: /Common/exampleAP:Common:a11b314f:/Common/exampleAP_act_oauth_client_ag: OAuth Client: failed for server '/Common/example_server' using 'authorization_code' grant type (client_id=exampleID), error: HTTP error 503, Connect failed
01490290:3: /Common/exampleAP:Common:b6e14800:/Common/exampleAP_act_oauth_client_ag: OAuth Client: failed for server '/Common/example_server' using 'authorization_code' grant type (client_id=exampleID), error: HTTP error 503, DNS lookup failed

Message Location

You may encounter this message in the following location:

  • The /var/log/apm file

Description

This message occurs when all of the following conditions are met:

  • You configure your BIG-IP APM system as an OAuth Client/Resource server.
  • Your BIG-IP APM OAuth Client/Resource server is unable to connect to the OAuth Authorization server.

Impact

The BIG-IP APM OAuth Client/Resource server is unable to contact the Authorization Server and authentication fails.

Recommended Actions

In BIG-IP APM as OAuth Client/Resource server, the BIG-IP system needs to connect to the OAuth Authorization server for OAuth token request. When this fails, the system logs the HTTP error 503 message to indicate the Service Unavailable HTTP status.

Depending on your error message, perform the appropriate recommended actions below:

HTTP error 503, DNS lookup failed

When the BIG-IP APM system is unable to contact the OAuth Authorization server due to a failure in DNS lookup, the system logs this message with the following possible causes:

  • DNS Server environment: Ensure the DNS name of the OAuth Authorization server is resolvable on the BIG-IP APM system. To do so, perform the following procedure:

    Note: The names must be DNS resolvable. Configuring the host file on the BIG-IP APM does not work.

    1. Log in to the Configuration utility.
    2. Navigate to Access > Federation > OAuth Client / Resource Server > Provider.
    3. Click the name of the appropriate provider. Refer to the the OAuth Server column for the corresponding OAuth server.
    4. Ensure all the names in all the URIs are resolvable on the BIG-IP APM, in particular, the Token URI and the Token Validation Scope URI.

      Note: The Authentication URI is the Authorization Server URI the client device is redirected to for authentication and must be resolvable on all the client devices.

  • DNS resolver: Also review the configuration of the DNS resolver of your OAuth Client. To do so, perform the following procedure:

Note: Further detail about the DNS resolver, please refer to: K12140128: Overview of the DNS resolver 

    1. Log in to the Configuration utility.
    2. Navigate to Access > Federation > OAuth Client / Resource Server > OAuth Server.
    3. Click the appropriate OAuth Client.
    4. Identify the name of your DNS Resolver in the DNS Resolver field.
    5. Navigate to Network > DNS Resolvers > DNS Resolver List.
    6. Click your DNS Resolver.
    7. Review the settings. If you have created forward zones, the name of the forward zone should be the FQDN for the forward zone or alternatively a dot character ( . ).

HTTP error 503, Connect failed

The system can log this message message for any network issues related to network routing, IP addresses, port numbers, and SSL connectivity.

Note: BIG-IP APM currently does not support OAuth token request through a non-default route domain. For example, if the Authorization server is configured on a non-default route domain from the BIG-IP APM system, the system will log this error message.

  • Network Reachability: Ensure that the OAuth Authorization server URI is reachable from the BIG-IP APM system. To verify the name of the authorization server, perform the following procedure:
    1. Log in to the Configuration utility.
    2. Navigate to Access > Federation > OAuth Client / Resource Server > Provider.
    3. Click the name of the appropriate provider. You can refer to the the OAuth server column for the corresponding OAuth server.
    4. Ensure the names in all the URIs are reachable from the BIG-IP APM, in particular, the Token URI and the Token Validation Scope URI.

      Note: The Authentication URI is the Authorization Server URI the client device is redirected to for authentication and must be reachable from all client devices.

  • SSL Connectivity: When the root cause of the failure is due to SSL connectivity, you may also observe an error message in the /var/log/ltm file logged at the same time. The system logs the following example when the BIG-IP APM  does not trust the certificate presented by the Authorization server due to its configuration of the Server SSL profile:

    warning tmm[11194]: 01260006:4: Peer cert verify error: unable to get local issuer certificate (depth 1; cert /C=US/O=Example Trust Services/CN=Example Internet Authority G3)
    warning tmm[11194]: 01260009:4: Connection error: ssl_shim_vfycerterr:4031: unable to get local issuer certificate (48);

    In this case, you should review the Server SSL profiles of your OAuth Client. To do so, perform the following procedure:

    1. Log in to the Configuration utility.
    2. Navigate to Access > Federation > OAuth Client / Resource Server > OAuth Server.
    3. Click the appropriate OAuth Client.
    4. Review the Server SSL profiles listed in the ServerSSL Profile Name fields.

      Note: The BIG-IP APM system uses the Server SSL Profile Names to connect to the OAuth Authorization server.

      For example, for the Client's ServerSSL Profile Name field, you use the default apm-default-serverssl profile. The default apm-default-serverssl profile has Server Certificate set to require and Trusted Certificate Authorities set to ca-bundle.crt. If the OAuth Authorization server uses a certificate that is not trusted in the chain of trust to ca-bundle.crt, the SSL handshake will fail. For security, F5 recommends using a Server SSL profile that has the Server Certificate field set to require.
