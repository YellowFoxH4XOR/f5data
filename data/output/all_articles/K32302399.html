Known Issue

The Traffic Management Microkernel (TMM) may restart when processing certain requests.

This issue occurs when all of the following conditions are met:

  • You configure a feature in a security policy or denial-of-service (DoS) profile that uses the device ID for fingerprinting.
  • The BIG-IP ASM system experiences a floating point exception while processing a request.

Impact

The BIG-IP ASM system stops processing traffic while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM restarts and generates a core file to the /shared/core/ directory.
  • The BIG-IP ASM system fails over to another device in the device group if configured for high availability (HA).
  • TMM logs a message to the /var/log/tmm file that appears similar to the following example:

    notice ** SIGFPE **

Workaround

To work around this issue, you can change the device ID matching mode from complex to simple. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the value of the did.match_mode database variable by typing the following command:

    modify /sys db did.match_mode value simple
