Description

NGINX Instance Manager (NIM) is unable to update and deploy WAF policies, including the latest attack signatures and threat campaigns, to managed NGINX Plus instances. Policy publication results in errors such as:

  • Deserialization failed: Unexpected EOF inside delimited string at /opt/nms-nap-compiler/app_protect-5.442.0/bin/../lib/perl/F5/ProtobufDataFile.pm line 431
  • APP_PROTECT No "error_line_number" found in error message
  • Cannot unmarshal binary to proto message: proto: cannot parse invalid wire-format data
  • Failed on insert to PLC.BOT_SIGNATURE_FILE_STATUS (SQLite do failed: attempt to write a readonly database)

These errors prevent successful policy deployment and signature updates, causing NGINX reloads to fail and NIM to roll back to previous configurations.

Environment

  • NGINX Instance Manager version 2.2x
  • F5 WAF for NGINX versions: 5.442.0, 5.575.0, 5.575.2, 5.11.2
  • Managed NGINX Plus instances (clustered, active/standby)
  • NIM configured to push WAF policies and signature updates
  • WAF compiler installed on NIM host
  • Policy deployment attempted via NIM, both with and without security logging enabled
  • Recent upgrades and manual compiler installations attempted
  • Configuration directories under /opt/app_protect/bd_config/tables/ present

Cause

Corrupted configuration table generations (directories 002–005) under /opt/app_protect/bd_config/tables/ on the WAF data plane prevented proper loading and updating of attack signatures and threat campaigns, resulting in policy compilation and deployment failures.

Answer/Recommended Actions

To resolve the issue:

  1. Remove all directories numbered 002 through 005 under /opt/app_protect/bd_config/tables/:
    • rm -rf /opt/app_protect/bd_config/tables/002
    • rm -rf /opt/app_protect/bd_config/tables/003
    • rm -rf /opt/app_protect/bd_config/tables/004
    • rm -rf /opt/app_protect/bd_config/tables/005
  2. Copy the manifest files from the 001 generation to restore the original state:
    • cp /opt/app_protect/bd_config/tables/001/bd_cfg_manifest.* /opt/app_protect/bd_config/tables/
  3. Re-attempt policy deployment from NIM to managed NGINX instances.
  4. Monitor for successful policy application and absence of previous error messages.

Additional Information

  • Errors such as "No 'error_line_number' found in error message" and "Cannot unmarshal binary to proto message" are symptomatic of corrupted configuration tables.
  • Upgrading F5 WAF for NGINX NIM compiler versions may not resolve the issue if the configuration tables are corrupted.
  • Manual intervention in the configuration directories is required to restore proper operation.
