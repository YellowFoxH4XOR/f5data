Known Issue

This is the result of a known issue. The f5isapi.dll process, used by the WMI monitor to gather statistics for dynamic ratio load balancing, does not support multicore or multiprocessor Microsoft Windows systems.

As a result, the WMI monitor is prevented from gathering the CPU information through the GetCPUInfo command. When the WMI monitor uses the GetCPUInfo command on a multicore or multiprocessor system, the following error message is returned to the monitor:

GetCPUInfo command: IEnumWbemClassObject::Next() failed (0x40004)

F5 Product Development tracked this issue as CR71764 and it was fixed in BIG-IP LTM 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

You can work around this issue by removing the GetCPUInfo command from the command list and removing the LoadPercentage command from the metrics list in the WMI monitor template.

The WMI can still use the GetDiskInfo and GetOSInfo commands and use the information returned to calculate a dynamic ratio value to assign to the member.
