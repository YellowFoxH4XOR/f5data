K000158869: Why BIG-IP Rest API certificate uploads fail with 'A valid filename must be supplied' error, even with valid filenames?

Description

 Customer used valid certificate "valid-certificate.test.com-31ODec27-DBEC" without any forbidden character " / & $ | ; ` < > \ : * ? "  and got and error:

Install Certificate Chain (<hostname>) failed with error: The remote server returned an error: (400) Bad Request. Server Response: {"code":400,"message":"A valid filename must be supplied","referer":"10.0.0.0","restOperationId":40461178,"kind":":resterrorresponse"}

Install Private Key (<hostname>)) failed with error: The remote server returned an error: (400) Bad Request. Server Response: {"code":400,"message":"A valid filename must be supplied","referer":"10.0.0.0","restOperationId":30084876,"kind":":resterrorresponse"}

 

Environment

  • BIG-IP 17.x
  • Certificate and key installation
  • Rest API (e.g., Venafi integration or similar automation)

Cause

Starting with certain BIG-IP versions (including 17.x), the REST API enforces strict validation on filenames for security reasons. Any filename containing forbidden characters (including their URL-encoded forms, e.g., %3a for :) is rejected with a 400 error and the message "A valid filename must be supplied."

  • Even if the filename sent by the client does not contain forbidden characters, the internal REST API path on BIG-IP uses a colon (:) to separate the partition and filename (e.g., :Common:valid-certificate.test.com-31ODec27-DBEC).
  • The bug in question (Bug ID 2137653) caused the REST API to incorrectly reject uploads if the internal path contained a colon, even though this is standard for BIG-IP.
  • Additionally, if any part of the filename or its URL-encoded form contained restricted characters, the error would also be triggered.

Recommended Actions

  • F5 Engineering provided an Engineering Hotfix (EHF) that includes the fix for Bug ID 2137653. The hotfix allows the colon (:) character in the internal path, but all other forbidden characters remain disallowed.
  • The fix is included in BIG-IP version 21.0.0 and later. For affected versions (e.g., 17.x), the EHF must be applied.

Additional Information

The error can occur even if the literal filename is valid because:

  • The REST API checks both the literal and URL-encoded forms of the filename for forbidden characters.
  • The internal handling of the path (with colons) can trigger the bug, causing the REST API to reject the upload.
