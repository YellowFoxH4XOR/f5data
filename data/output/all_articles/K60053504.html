Known Issue

You are missing the BIG-IP APM client software after you install the BIG-IP Virtual Edition (VE).

This issue occurs when the following condition is met:

  • You perform a new installation of BIG-IP VE 13.1.0 or 13.1.0.1 using one of the .ova image files available on the F5 Downloads site.

For example, this issue can occur when you install BIG-IP VE using one of the following .ova files:

  • BIGIP-13.1.0.0.0.1868.ALL-scsi.ova
  • BIGIP-13.1.0.1.0.0.8.ALL-scsi.ova

Note: This issue does not affect .iso image files and does not occur when you perform software upgrades.

Impact

This issue has the following impact:

  • The BIG-IP APM system cannot perform client-side, endpoint, third-party security software checks, such as antivirus and firewall checks for Windows, Mac OS X, and Linux systems.
  • Administrators cannot deploy customized client packages with endpoint security enabled to clients.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP APM client-side, endpoint, security checks fail after you perform a new BIG-IP VE installation.
  • Attempts to download the client package from your BIG-IP APM system fail with an error similar to the following:

    An error has occurred while trying to download the requested file. /var/sam/www/webtop/public/download/OesisInspector.cab (No such file or directory)

Workaround

To work around this issue, you can manually refresh the epsec package. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP APM Advanced Shell (bash).
  2. To remove all environment locks on the shared RPM database and refresh the epsec package, type the following commands:

    rm /shared/lib/rpm/__db.*
    epsec refresh
