Description

NGINX [Plus] Ingress Controller (NIC) fails to start when deployed. The STATUS reports "CrashLoopBackOff". The following error message is reported: 

IngressClass with name nginx has an invalid Spec.Controller k8s.io/ingress-nginx; expected nginx.org/ingress-controller

Environment

NGINX Ingress Controller

Cause

The K8s cluster that the NIC is being deployed in contains an IngressClass object with name nginx and spec.controller value k8s.io/ingress-nginx (part of Kubernetes ingress controller community deployment).

Recommended Actions

Any one of the following actions will resolve the issue:

  • For the NIC deployment, rename the IngressClass object and configure the NIC deployment with command line argument -ingress-class with the name of the IngressClass object's new name:
    -ingress-class=<new_ingressclass_name>
  • Rename the existing, k8s.io/ingress-nginx IngressClass object in the Kubernetes cluster
  • Delete the existing, k8s.io/ingress-nginx IngressClass object in the Kubernetes cluster

Additional Information

NIC deployments, by default, implement with IngressClass name nginx. NIC expects this IngressClass object's spec.controller value to be nginx.org/ingress-controller, or else NIC will not start.
