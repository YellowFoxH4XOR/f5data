Known Issue

This is the result of a known issue. When either a Mac OS X or Linux client establishes a Network Access connection to FirePass, the FirePass Controller will install a static route into the clients local routing table. The static route is assigned to the interface that is connected, and will direct traffic to the public IP address of the FirePass Controller. This route is used to ensure that the client maintains a connection to the FirePass throughout the duration of the Network Access session.

When Network Access is disconnected and the client logs out of the FirePass Controller, the static route to the public IP address of the FirePass Controller persists. This erroneous route may cause issues if there is overlapping IP address space between the users' local network and the networks behind the FirePass Controller.

F5 Product Development tracked this issue as CR112733 and it was fixed in FirePass 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

Note: As a result of this known issue, if a Mac OS X user disconnects from FirePass, and then enables Wireless LAN and disables Ethernet LAN access, the static route will persist and reference the disabled Ethernet LAN interface. This issue does not affect Linux clients.

Additionally, this issue has been fixed in cumulative hotfix HF-603-2.1, which has been issued for FirePass 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

Customers can work around this issue by rebooting the client machine after logging out of FirePass. This reboot will clear the route.
