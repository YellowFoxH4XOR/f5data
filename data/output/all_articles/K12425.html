Known Issue

This is the result of a known issue. If a Mac OS X or Linux user has a missing or corrupted /dev/ppp device file, the user will be unable to successfully connect to Network Access. They may receive an error message that appears similar to the following example:

FirePass server closed connection (code 38)

This error message occurs because the VPN client only checks to see if the /usr/sbin/pppd binary file exists, but does not check the return value of pppd. In the event that the /dev/ppp file is corrupt or missing, the VPN client will continue to attempt to use the file and the connection will fail.

F5 Product Development is tracking this issue as ID 213440 (formerly CR84402).

This issue has been fixed in cumulative hotfix HF-610-4, which has been issued for FirePass version 6.1.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

To fully address this issue, you must create or fix the /dev/ppp device file. For full instructions about how to create or fix the /dev/ppp file, refer to your vendor documentation. Most Mac OS X and Linux users can fix the file by performing the following procedure:

Important: The following steps are only suggestions. Before deploying, you should evaluate this procedure for your unique environment.

Note: You must have root permissions to complete the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. From the command line, remove the existing /dev/ppp file if it currently exists.

    For example:

    rm /dev/ppp
  3. Create a new /dev/ppp file.

    For example:

    mknod /dev/ppp c 108 0
  4. Connect to FirePass using your VPN client.
