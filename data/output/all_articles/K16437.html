Known Issue

Failure to detect an external hardware security module (HSM) can cause the Traffic Management Microkernel (TMM) to restart repeatedly.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured to use an external HSM for Secure Socket Layer (SSL) or Domain Name System Security Extensions (DNSSEC) key management.
  • The BIG-IP system is unable to detect the external HSM due to HSM software misconfiguration or corruption.

Important: After a system software or hotfix upgrade, you must run the Thales or SafeNet Luna client setup script to restore your default configuration.

Impact

TMM may restart repeatedly and fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.
  • An error message is logged to the /var/log/ltm file, and appears similar to the following example:

    err pkcs11d[6789]: 01680024:3: Signal 15 received.
