Audit logging is configured using the BIG-IP Configuration utility by navigating to the System > Logs > Options page. Currently, you cannot define audit log levels for the BIG-IP ASM policy editor using the Configuration utility.

You can use the following methods to audit changes to the BIG-IP ASM security policy:
  • Determining when the security policy was applied by an administrator
  • Viewing the changes made between security policy versions

Determining when the security policy was applied by an administrator

You can determine the date and time that an administrator applied the security policy. To do so, perform one of the following two procedures, depending on whether you are using the command line or the Configuration utility:

Command line

To use the command line to determine the date and time that an administrator applied the security policy, perform the following procedure:
  1. Log in to the command line.
  2. Change directories to the /var/log directory by entering the following command:

    cd /var/log/
  3. To view when the security policy was applied by an administrator, enter the following command:

    cat asm |grep USER_ACTIVITY

    If the security policy was applied by an administrator on the log file date, the log entries will appear similar to the following example:

    Jan 7 09:16:36 asm log_manager[2810]: 01310019:5: [USER_ACTIVITY] User admin performed Apply Policy operation on acme_httpclass_default policy that is associated with Web Application. 2008.

    Jan 7 09:16:36 asm log_manager[2810]: 01310019:5: [USER_ACTIVITY] User admin created history version for acme_httpclass_default policy that is associated with Web Application. 2070.

Configuration utility

To use the Configuration utility to determine the date and time that an administrator applied the security policy, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Select Application Security.
  3. Select Web Applications.
  4. Select the web application for which you want to view the security policy changes.
  5. Select Policy.
  6. Select the History menu.

    The Security Policy History shows the dates and times that each policy version was applied, along with the ability to restore an earlier policy version.

Viewing the changes made between security policy versions

You can view the changes made between security policy versions by performing the following procedure:

Important: The following procedure changes the currently active policy, and should be run on the standby system, or during a maintenance window.

At this point in the procedure, you have the option to re-import the original policy. To do so, perform the following three steps.

  1. Log in to the Configuration utility.
  2. Select Application Security.
  3. Select Web Applications.
  4. Select the web application for which you want to view the changes made between security policy versions.
  5. Select Policies List.
  6. Select Export.
  7. Choose a location to save the exported policy.
  8. Select Policy.
  9. Select History.
  10. In the Security Policy History section, select the policy version which you want to compare to the current policy.
  11. Select Restore.

    Note: Selecting the Restore button opens the Restore Policy pop-up window. In this pop-up window, you can confirm the security policy that you want to be restored, and you can designate this security policy to be the active security policy.
  12. Once the previous policy version is restored, select Policies List.
  13. Select the button next to the active policy, which should be the policy you restored in step 10.
  14. Select Merge.
  15. Ensure the Target Security Policy displayed is the policy you restored in step 10, then select Browse and locate the policy you exported in step 6.
  16. Select Verbose Mode.
  17. Select Merge.

    Once the policies are merged, a Merge Report will be displayed listing the differences between the latest security policy and the previous policy.
  18. If you want to view the Merge Report in a text file, select Download Full Report.

    Note: Although the Merge Report does not list which Administrator made the changes to the policy, you can view the changes made between security policy versions.
  19. Select Policies List.
  20. Select the policy that was exported in step 6.
  21. Select Import.
