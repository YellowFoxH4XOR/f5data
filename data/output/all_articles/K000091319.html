K000091319: After a failover in an autofailover HA configuration one of the devices stays as 'Waiting for BIG-IQ services to become available'

Type
Support Solution
Published
2022-03-11
Updated
2022-03-11
Source
https://my.f5.com/manage/s/article/K000091319

Description

There is an HA pair configured with the autofailover enabled. For some reason, the quorum decides that a failover needs to happen, and a new Active device is elected. The former Active device recovers but it continually shows 'Waiting for BIG-IQ services to become available.'

After restarting the device, or restarting restjavad, the GUI briefly becomes available but a 'Gateway unreachable' message pops up and the GUI returns to 'Waiting for BIG-IQ services to become available.'

When you try to add the standby device to the currently active device, it says that it cannot reach the standby device. Connectivity through telnet and ping shows that the standby is reachable.

 Environment

  • HA Pair.
  • Autofailover option enabled.
  • Failover event happened.

 

 Cause

Unknown at the time of publication.

 Recommended Actions

  • Log in via SSH to the crashed device.
  • Run the command

ha_reset <local discovery address>

  • Then, restart the restjavad daemon.

bigstart restart restjavad

  • After the GUI becomes available if needed, remove the HA configuration in the crashed device.
  • Repeat the three above steps for the current Active device.
  • Re-create the HA.
