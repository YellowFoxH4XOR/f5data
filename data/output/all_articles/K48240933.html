Description

The virtual server is configured with an HTTP profile, and the BIG-IP system receives a response from the pool member that either contains more data than indicated in the Content-Length header or has additional data following the ending chunk of a chunked response. This is not compliant with RFC and BIG-IP system may reset the connection. You may observe the error message similar to the following logged to /var/log/ltm:

 

011f0016:3: http_process_state_prepend - Invalid action:0x109010 Server sends too much data...

 

Environment

  • BIG-IP system
  • Virtual server
  • Pool member
  • HTTP profile

Cause

This issue should be located at the server side, not at F5 BIG-IP system side, since the server's behavior is not compliant with RFC.

 

Recommended Actions

  1. The correct way to fix this issue is to correct the server's misbehavior and make sure it is RFC compliant. If the server cannot correct its misbehavior, you may consider 2 or 3.

  2. Follow the recommendation in

    K42151600: Error Message: 011f0016:3: http_process_state_prepend - Invalid action:<code> Server sends too much data.

    Note: The referred to db key in the article only works when the additional segment data is present in the same packet.

  3. If the additional segment data is present in separated packets, you may consider trying to apply a oneconnect profile to the virtual server, for example the default oneconnect profile.
