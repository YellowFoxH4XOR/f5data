Known Issue

Multidomain single sign-on (SSO) access may trigger a decoded redirect request.

This issue occurs when all of the following conditions are met:

  • The Access Policy has been created using SSO for multiple domains using primary and non-primary virtual servers.
  • An access URL request is initially sent to a non-primary virtual server that redirects the client to the primary virtual server for authentication.
  • The initial access URL request is repeated by the client while the Access Policy is still processing the initial authentication request.

Impact

The session fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H426658 on the Diagnostics > Identified > Low screen.
  • A TCP reset is sent from the BIG-IP APM system terminating the session.
  • The requested URL fails.

Workaround

To work around this issue, you can apply the following iRule to the primary virtual server. To do so, perform the following procedure:

Impact of workaround: None.

Creating an iRule to properly encode the BIG-IP APM redirect

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Enter the Name for the iRule.
  6. In the Definition text box, enter the following text:
  7. In the Definition text box, enter the following text:

    when HTTP_REQUEST {
    if { [HTTP::uri] starts_with "/F5Networks-SSO-Req?SSO_ORIG_URI=https" }{
    HTTP::uri "/F5Networks-SSO-Req?SSO_ORIG_URI=[b64encode [string range [HTTP::uri] 33 end]]"
        }
    }
  8. Click Finished.
  9. Apply the iRule to the primary virtual server.
