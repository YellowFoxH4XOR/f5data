Topic

You should consider using this procedure under the following conditions:

  • Users access a service provided by a web server protected by the BIG-IP APM.
  • You want to configure one BIG-IP APM in LTM-APM mode to authenticate users using OAuth authentication. 
  • You want to configure another BIG-IP APM as an OAuth authorization server (AS) to authenticate and authorize users.

Description

The purpose of this article is to configure a basic OAuth authentication using two BIG-IP APM systems. The devices following devices are required:

  • One BIG-IP APM system (BIG-IP APM 1) as OAuth authorization server with Active Directory authentication.

    Note: Instead of Active Directory, you can use any other appropriate authentication service, for example the BIG-IP APM local user database authentication.

  • One BIG-IP APM system (BIG-IP APM 2) as OAuth client and LTM-APM virtual server for user access.
  • A client device with a web browser.
  • A web server as a BIG-IP LTM pool, protected by BIG-IP APM 2, the OAuth client.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have already have a BIG-IP LTM pool on the BIG-IP APM, with servers providing a web service.
  • There is network connectivity from your client devices to both of your BIG-IP APM devices.
  • There is network connectivity between both your BIG-IP APM devices.

Procedures

Perform the following procedures to build these objects:

  • Creating BIG-IP APM 1 as an OAuth authorization server
    • Creating OAuth AS components for BIG-IP APM 1
    • Creating the access profile and access policy for BIG-IP APM 1
    • Creating the virtual server for BIG-IP APM 1
  • Creating BIG-IP APM 2 as an OAuth client
    • Creating OAuth client and resource server components for BIG-IP APM 2
    • Creating the access profile and access policy for BIG-IP APM 2
    • Creating the virtual server for BIG-IP APM 2
  • Accessing the service from a client

Creating BIG-IP APM 1 as an OAuth authorization server

The BIG-IP APM 1 OAuth authorization server contains the OAuth profile, which in turn contains the following components:

  • The OAuth AS resource server
  • The OAuth AS client application
  • The OAuth AS scope

Creating OAuth AS components for BIG-IP APM 1

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Creating two OAuth AS scopes

  1. Log in to the Configuration utility.
  2. Navigate to Access > Federation > OAuth Authorization Server > Scope.
  3. Click Create.
  4. For Name, Scope Name, and Caption, enter email-scope.
  5. Click Finished.
  6. Repeat these steps and create another scope object using the value name-scope for the value in step 4.

Creating an OAuth AS client application

  1. Navigate to Access > Federation > OAuth Authorization Server > Client Application.
  2. Click Create.
  3. For Name, Application Name, and Caption, enter oauth-as-clientapp.
  4. For Grant Type, select the check boxes for all of the options.
  5. For Redirect URI(s), enter https://apm2app.example.com/oauth/client/redirect .

     

    Note: This is the URL to which the OAuth AS redirects users after successful authentication. It is hosted by the virtual server on BIG-IP APM 2.

  6. For Authentication Type, click Secret.
  7. For Scope, in the Available list, select email-scope and name-scope and move them to the Selected list.
  8. Click Finished.
  9. Click the newly created client application to view its properties.
  10. Record the Client ID and Secret values.

Creating an OAuth AS resource server

  1. Navigate to Access > Federation > OAuth Authorization Server > Resource Server.
  2. For Name, enter oauth-as-resourceserver.
  3. For Authentication Type, click Secret.
  4. Click Finished.
  5. Click the newly created Resource Server.
  6. Record the Resource Server ID and Secret values.

Creating an OAuth profile

  1. Navigate to Access > Federation > OAuth Authorization Server > OAuth Profile.
  2. Click Create.
  3. For Name, enter oauth-as-profile.
  4. For Client Application, click oauth-as-clientapp, the client application you created earlier.
  5. For Resource Server, click oauth-as-resourceserver, the resource server you created earlier.
  6. Click Finished.

Creating the access profile and access policy for BIG-IP APM 1

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  3. Click Create.
  4. For Name, enter oauth-as-accessprofile.
  5. For Profile Type, click All.
  6. For OAuth Profile, click oauth-as-profile.

    Note: This is the OAuth profile you created in step 4 of the Creating an OAuth profile procedure.

  7. For Languages, in the Factory BuiltIn Languages list, select English and move it to the Accepted Languages list.
  8. Click Finished.
  9. For the access profile you just created, click Edit to open the Visual Policy Editor (VPE).
  10. Create a Logon Page policy item:
    1. Click the Add icon (+ ) on the fallback branch following the Start item.
    2. On the Logon Page tab, click Logon Page and click Add Item.
    3. Click Save.
  11. Create an AD Auth policy item.
    1. Click the Add icon (+ ) on the fallback branch following the Logon Page policy item.
    2. Click the Authentication tab.
    3. Click AD Auth and click Add Item.
    4. For Server, click your existing AD server.

      Note: If you do not have an existing AD Server, create one first or consider using any other authentication mechanism, for example the BIG-IP APM local database authentication.

    5. Click Save.
  12. Create an OAuth Authorization policy item.
    1. Click the Add icon (+ ) on the Successful branch following the AD Auth policy item.
    2. Click the Authentication tab
    3. Click OAuth Authorization and click Add Item.

      Note: The Prompt for Authorization option prompts the user with a consent screen. If you don't want this screen to appear, you can disable it by clicking Disabled.

    4. For Authorize Message, enter the following message:

      This consent page is customized in the VPE of BIG-IP APM 1, the authorization server. It describes the name of the client application on BIG-IP APM 2 that is requesting authorization. Do you authorize this request?

    5. Click Save.
  13. On the Successful branch following the OAuth Authorization policy item, click the Deny item, click Allow, and then click Save.
  14. Click Close.

Creating the virtual server for BIG-IP APM 1

The virtual server you configure in this procedure is the OAuth authorization server and contains the access profile you configured in the Creating the access profile and access policy for BIG-IP APM 1 procedure.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers .
  3. Click Create.
  4. For Name, enter OAuthAS-VS.
  5. For Destination Address/Mask, enter the appropriate IP address. For example:

    10.10.10.4

  6. For Service Port, enter 443.
  7. For SSL Profile (Client), click clientssl.
  8. For HTTP Profile, click http.
  9. For Source Address Translation, click AutoMap.
  10. For Access Profile, click oauth-as-accessprofile.

    Note: This is the access profile you created in the Creating the access profile and access policy for BIG-IP APM 1 procedure.

  11. Click Finished.

Creating BIG-IP APM 2 as an OAuth client

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

The OAuth client and resource server components consist of the provider and an OAuth server.

Creating OAuth client and resource server components for BIG-IP APM 2

Creating an OAuth provider

  1. Log in to the Configuration utility.
  2. Navigate to Access > Federation > OAuth Client /Resource Server > Provider.
  3. Click Create.
  4. Fill in the General Properties with the values listed in the following table.

    Note: For the following URI endpoints, replace the default f5-oauth.local with 10.10.10.4 and the IP address of the virtual server of BIG-IP APM 1 that you created in step 5 of the Creating the virtual server for BIG-IP APM 1 procedure.

    Important:& In production, instead of using an IP address 10.10.10.4, you should configure this address as a hostname that is resolvable to a DNS server that is available to both BIG-IP APM 2 and the client device.

    SettingValue
    Nameoauth-provider
    TypeF5
    OpenID URIhttps://10.10.10.4/f5-oauth2/v1/.well-known/openid-configuration
    Authentication URIhttps://10.10.10.4/f5-oauth2/v1/authorize
    Token URIhttps://10.10.10.4/f5-oauth2/v1/token
    Token Validation Scope URIhttps://10.10.10.4/f5-oauth2/v1/introspect
    UserInfo Request URIhttps://10.10.10.4/f5-oauth2/v1/userinfo
  5. Click Save.

Creating an OAuth Server

  1. Log in to the Configuration utility.
  2. Navigate to Access > Federation > OAuth Client / Resource Server > OAuth Server.
  3. Click Create.
  4. For DNS Resolver, click the appropriate one. If you do not have one, click + and create one named apm-dns-resolver.
  5. Fill in the other settings with the values listed in the following table.
    SettingValue
    Nameapm-oauth-server
    ModeClient + Resource Server
    TypeF5
    OAuth Provideroauth-provider 

    Note: This is the name of OAuth provider you created in the previous procedure.

    Client IdEnter the Client Id from step 2 of the Creating OAuth AS components for BIG-IP APM 1 procedure.
    Client SecretEnter the Client Secret from step 2 of the Creating OAuth AS components for BIG-IP APM 1 procedure.
    Client's ServerSSL Profile Name

    serverssl 

    Note: This is the SSL profile BIG-IP APM 2 uses in its SSL handshake with BIG-IP APM 1, the OAuth authorization server. You should configure your own SSL profile and trusted certificate authorities in production.

    Resource Server IDEnter the Resource Server ID from step 3 of the Creating OAuth AS components for BIG-IP APM 1 procedure.
    Resource Server SecretEnter the Resource Server ID from step 3 of the Creating OAuth AS components for BIG-IP APM 1 procedure.
    Resource Server's ServerSSL Profile Name

    serverssl 

    Note: This is the SSL profile BIG-IP APM 2 uses in its SSL handshake with BIG-IP APM 1, the OAuth authorization server. You should configure your own SSL profile and trusted certificate authorities in production.

  6. Click Finished.

Creating the access profile and access policy for BIG-IP APM 2

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  3. Click Create.
  4. For Name, enter oauth-client-accessprofile.
  5. For Profile Type, click All.
  6. For Languages, in the Factory BuiltIn Languages list, select English and move it to the Accepted Languages list.
  7. Click Finished.
  8. For the access profile you just created, click Edit to open the VPE.
  9. Create an OAuth Client to authenticate the user:
    1. Click the Add icon (+ ) on the fallback branch following the Start item.
    2. Click the Authentication tab, click OAuth Client, and click Add Item.
    3. Fill in the settings with the following values:
      SettingValue
      Server/Common/apm-oauth-server 

      Note: This is the OAuth server created in step 2 of the Creating OAuth client and resource server components for BIG-IP APM 2 procedure.

      Grant TypeAuthorization Code
      OpenID ConnectDisabled
      Authentication Redirect Request/Common/F5AuthRedirectRequest
      Token Request/Common/F5TokenRequestByAuthzCode
      Refresh Token Request/Common/F5TokenRefreshRequest
      Redirection URIUse the default value.
      Scopeemail-scope name-scope
    4. Click Save.
  10. Create a Pool Assign policy item to direct users to the resource.
    • Click the Add icon (+) on the Successful branch following the OAuth Client policy item.
    • Click the Assignment tab.
    • Click Pool Assign and click Add Item.
    • Click Add/Delete and click the appropriate BIG-IP LTM pool that has the resource servers.
    • Click Save.
  11. On the fallback branch following the Pool Assign policy item, click the Deny item, click Allow, and then click Save.

Creating the virtual server for BIG-IP APM 2

Perform the following procedure to create the virtual server that your users connect to access the service provided by the BIG-IP LTM pool servers.

  1. Log in to the Configuration Utility
  2. Navigate to Local Traffic > Virtual Servers .
  3. Click Create.
  4. For Name, enter OAuthClient-VS.
  5. For Destination Address/Mask, enter an IP address. For example:

    10.10.10.5

  6. For Service Port, enter 443.
  7. For SSL Profile (Client), click clientssl.
  8. For SSL Profile (Server), click serverssl.

    Note: Do this only if your BIG-IP LTM pool member supports HTTPS.

  9. For HTTP Profile, click http.
  10. For Source Address Translation, click AutoMap.
  11. For Access Profile, click oauth-client-accessprofile

    Note: This is the access profile you created in the Creating an access profile and access policy for BIG-IP APM 2 procedure.

  12. Click Finished.

Accessing the service from a client

Perform the following procedure on your client device to access the service you have configured in the previous procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your client device.
  2. Add the following entry to the host file:

    10.10.10.5    apm2app.example.com

    Note: This is the IP address you assigned to the virtual server created in step 5 of the Creating the virtual server for BIG-IP APM 2 procedure.

  3. Access BIG-IP APM 2's virtual server by pasting the following into a browser address box:

    https://apm2app.example.com

  4. Enter your credentials in the BIG-IP APM logon page.
  5. If configured, you see the BIG-IP APM consent page configured on BIG-IP APM 1's access policy.
  6. Verify which application is requesting for authorization and click Authorize.
  7. When login is successful you are taken back to BIG-IP APM 2's access policy to the pool assign to access the backend service.
