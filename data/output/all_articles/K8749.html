Known Issue

This is the result of a known issue. The FTP monitor does not correctly terminate the RETR command when attempting to retrieve a file.

When an FTP health monitor issues the RETR command to retrieve a file, the monitor incorrectly terminates the command with a new line ( \n ) character instead of properly terminating the command with a carriage return and new line ( \r\n ) character. Correct termination of the RETR command appears similar to the following example:

RETR test.txt\r\n

As a result, some FTP servers can truncate part of the filename when parsing the command, due to the missing carriage return. This behavior causes the server to report that the requested file was not found, and the FTP monitor marks the node as down.

Note: The FTP health monitor properly terminates all other FTP commands (USER, PASS, CWD, QUIT) with a carriage return.

F5 Product Development tracked this issue as CR98705 and it was fixed in BIG-IP LTM version 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To prevent the FTP server from truncating the filename when parsing the RETR command, you can specify a carriage return within the FTP health monitor request string. To do so, perform the following procedure:

  1. Click Local Traffic in the Configuration utility.
  2. Click Monitors.
  3. Click the affected custom FTP health monitor.
  4. Add the carriage return ( \r ) character to the end of the filename.

    For example:

    /somedir/test.txt\r
  5. Click the Update button.
