Description

Config-sync fails. The following error appears in /var/log/ltm:

Inbound CMI connection from IP (x.x.x.x) denied because it came from VLAN (mgmt), not from expected VLAN (<vlan_name>).


 

Environment

- BIG-IPs in HA,

- config-sync group,

- self-ip in VLAN X intended for config-sync and traffic is correctly received in this VLAN,

- when checking the linux kernel routing table for the config-sync IP, it incorrectly shows mgmt instead of the HA VLAN.

For example:

# ip route get 172.16.1.1

172.16.1.1 dev mgmt src 10.1.1.1

   cache mtu 1500 advmss 1460 hoplimit 64


instead of:

# ip route get 172.16.1.1

172.16.1.1 dev VLAN-HA src 172.16.1.2

   cache

 

Cause

This issue can happen when traffic from peer device (with config-sync self-ip as source IP of the packet) to the management interface triggers mgmt-auto-last-hop, causing kernel route for config-sync IP to revert to mgmt VLAN instead of HA VLAN.

This, in consequence, causes invalid verification of the traffic origin and error log:

---

01071bd1:3: Inbound CMI connection from IP (x.x.x.x) denied because it came from VLAN (mgmt), not from expected VLAN (<vlan_name>).


Answer/Recommended Actions

Stop any traffic from peer device to the management interface to prevent route change.

Optionally, disable mgmt-auto-last-hop (with proper routing in place).
