K000148505: Connections to virtual server are reset when using HTTP::respond and HTTP::header in separate iRules

Description

You have a virtual server with iRules attached that separately invoke HTTP::respond and HTTP::header commands in the HTTP_REQUEST event.

Connections to this virtual server intermittently fail and log the following error to /var/log/ltm:

err tmm7[19316]: 01220001:3: TCL error: /Common/http_rule <HTTP_REQUEST> - Can't call after responding - ERR_NOT_SUPPORTED (line 1)

Environment

  • LTM
  • HTTP Profile
  • Separate iRules that modify HTTP headers and respond to the HTTP request

Cause

This issue is due to the iRules attached to the virtual server executing in the wrong order.

Unless iRule priorities are used to define execution order, it is undetermined whether the iRule with HTTP::respond or the iRule with HTTP::header will be executed first.

The HTTP::header command can only be used to modify request headers in the HTTP_REQUEST event. If the HTTP::respond command is executed first, the HTTP_RESPONSE event will fire which causes subsequent HTTP::header commands to fail and reset the connection to the virtual server.

Recommended Actions

Review K12090273: iRule Priority command controls the order of iRule execution and implement iRule event priorities to ensure that the HTTP::header command is always called before HTTP::respond.
