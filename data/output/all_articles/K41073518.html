Known Issue

The ospfd process may restart and produce a core file when ASE OSPF debugging is enabled.

This issue occurs when the following condition is met:

  • You have used one of the following imish commands to enable ASE debugging within an OSPF Not-So-Stubby Area (NSSA):

    • debug ospf all
    • debug ospf route
    • debug ospf route ase

Impact

Dynamic routing is interrupted while the ospfd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You may observe a core file in the /var/core directory, similar to the following example:

    ospfd%0.bld5.0.429.core.gz

  • In the /var/log/ltm file, you may observe messages similar to the following example:

    notice logger: Started writing core file: /var/core/ospfd%0.bld5.0.429.core.gz for PID 1234
    notice logger: Finished writing 2658117 bytes for core file: /var/core/ospfd%0.bld5.0.429.core.gz for PID 1234
