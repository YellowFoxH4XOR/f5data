Description

Restoring a BIG-IP UCS archive after upgrading may fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP UCS configuration references service ports based on the service name, not the service port numeric value.
  • You have upgraded the BIG-IP system.
  • You have restored the UCS archive that was created before the upgrade.

    This issue manifests when the UCS archive configuration references port names, rather than numeric port values. The Traffic Management Shell (tmsh) is set with the global setting service value is name. This implies that the BIG-IP configuration ports are saved by their names and not port numbers. When loading the UCS archive configured port names are checked against the /etc/services file for their associated numeric port value. When there is no matching numeric port value located in the /etc/services file, loading of the UCS archive will fail.

Impact

Restoration of the UCS archive fails.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When attempting to restore the UCS archive, the system logs error messages to the console and the /var/log/ltm file that appear similar to the following example:

    localhost emerg load_config_files: ""/usr/libexec/bigpipe load"" - failed. -- BIGpipe parsing error (/config/bigpipe/bigip.conf Line 210):

    012e0010:3: The requested value (*:<unrecognize port service> }) is invalid (<ip addr> | <member>) for 'dest' in 'monitor'

    In the previous example, note the following:
    • <unrecognized port service> is the port service name in the BIG-IP configuration that does not match an existing entry in the upgrade /etc/services file.

Recommendation

You can avoid this issue by using the Traffic Management Shell (tmsh) to set the global setting port service value as a number prior to upgrading. To do so, perform the following procedure:

Impact of recommendation: Configuration service names are saved using their numeric port values.

  1. Log on to tmsh.
  2. Type the following command:

    tmsh cli global settings service number
  3. Save the configuration change by typing the following command:

    save /sys config
  4. To exit tmsh, type the following command:

    quit
  5. Perform the system upgrade.
