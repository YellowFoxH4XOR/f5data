Topic

In BIG-IP versions 9.4.3 and earlier, BIG-IP software shipped with ZebOS version 5.4. Starting with BIG-IP version 9.4.4, F5 upgraded the ZebOS version that shipped with BIG-IP software to version 7.5. The upgraded version includes some of the following changes:

  • IS-IS, OSPFv3, RIP version 2, and RIPng modules have been added, as well as IPv6 support for BGP.
  • The vtysh program has been replaced with the imish program. The vtysh program is now symlinked to imish.
  • The ZebOS.conf file is no longer created when the dynamic routing subsystem is enabled. The file is created when the ZebOS configuration is saved from the imish shell.
  • Some of the arguments for the BIG-IP system zebos command have changed; the zebos start and the zebos stop commands have been replaced with the zebos enable and the zebos disable commands.
  • You configure the startup of advanced routing module daemons using the F5 zebos script. For example:

    zebos (enable | disable) [bgp | isis | ospf | ospf6 | rip | ripng]
    zebos (check | rotate)
    zebos (cmd command1)[,command2]

  • The zebos.* bigdb keys in ZebOS version 5.4 have been replaced by the following TMRouted bigdb keys:

    TMRouted.bgp = disable
    TMRouted.isis = disable
    TMRouted.NetlinkCmdIdleTimeout = 5
    TMRouted.NetlinkListenIdleTimeout = 5
    TMRouted.ospf = enable
    TMRouted.ospf6 = disable
    TMRouted.QueryPeriod = 10
    TMRouted.RHIFailoverDelay = 0
    TMRouted.rip = disable
    TMRouted.ripng = disable

    Note: The system sets the TMRouted.<protocol> bigdb key to enable when you license and start the routing protocol by using the zebos enable <protocol> command.

  • If you install a UCS from a previous version, the system automatically configures the new database keys.
  • The BIG-IP system starts the tmrouted daemon automatically when dynamic routing is enabled. If you need to restart the entire routing module, run the following command:

    bigstart restart tmrouted

  • Failover-related bigdb keys are removed in version 7.5. These actions are now performed automatically. By default, when a unit running the OSPF protocol enters standby mode, the routing module will increase the interface costs and withdraw its routes.

    For example, in ZebOS version 5.4, the unit displays the standby failover actions in running config as follows:

    ip ospf cost 65535
    summary-address 0.0.0.0/0 not-advertise

    In ZebOS version 7.5, failover actions are not displayed; however, the actions are still performed automatically.
  • The syntax between ZebOS versions has changed slightly. When upgrading an existing system, F5 recommends that you check the status of the configuration. Most configurations will be rolled forward seamlessly; however, if elements were dropped or modified unexpectedly, they may need to be reconfigured.

To check the running ZebOS configuration and verify the correct configuration was loaded appropriately, perform the following procedure:

  1. To access the VTY command line shell, type the following command:

    vtysh

  2. To enter enable mode, type the following command:

    enable

  3. To verify that the correct configuration was loaded, type the following command:

    show running-config

  4. If needed, modify the configuration and save it to disk.
