Known Issue

A Secure Socket Layer (SSL) key that is exported from a FIPS device, and installed using the Traffic Management Shell (tmsh), may cause a device group synchronization failure.

This issue occurs when all of the following conditions are met:

  • You have multiple BIG-IP devices configured in a device group.
  • The BIG-IP systems use a FIPS module to protect SSL keys.
  • You install a FIPS exported key file (.exp key) on one of the BIG-IP systems.
  • The .exp key file originates from a FIPS device that belongs to the same FIPS security domain.

Impact

Configuration synchronization (ConfigSync) fails between peer devices in the device group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • ConfigSync fails between peer devices in the device group.
  • The system logs an error message, similar to the following example, to the /var/log/ltm file:

    err mcpd[6789]: 010713e4:3: FIPS subsystem reported error while attempting file object operation: import_key: error on import, key file for /Common/example.com.key is corrupt or invalid..
    err mcpd[6789]: 01070712:3: Caught configuration exception (0), Error importing FIPS140 key (/Common/example.com.key) to hardware..

Workaround

To work around this issue, you must use Secure Copy (SCP) protocol to copy the SSL certificate and .exp key file to all peer devices in the device group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the workstation or server that contains the SSL certificate and .exp key files.
  2. Use SCP to copy the SSL certificate and .exp key files (to the peer BIG-IP system that does not have the SSL certificate and .exp key files) by using the following command syntax:

    scp <file> root@<ip_address>:/shared/tmp

    For example, to copy the example.com SSL certificate and key to the BIG-IP system at IP address 192.168.10.1, use the following commands:

    scp example.com.crt root@192.168.10.1:/shared/tmp/
    scp example.com.exp root@192.168.10.1:/shared/tmp/

  3. From the peer BIG-IP system that you securely copied the SSL certificate and .exp key to, log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  4. To install the SSL certificate, use the following command syntax:

    install sys crypto cert <name> from-local-file /shared/tmp/<file>

    For example, to install an SSL certificate named example.com using the example.crt file, use the following command:

    install sys crypto cert example.com from-local-file /shared/tmp/example.crt

  5. To install the SSL .exp key file, use the following command syntax:

    install sys crypto key <name> from-local-file /shared/tmp/<file> security-type fips

    For example, to install an SSL .exp key file named example.com using the example.com.exp file, use the following command:

    install sys crypto key example.com from-local-file /shared/tmp/example.com.exp security-type fips

  6. Save the configuration by typing the following command:

    save sys config
