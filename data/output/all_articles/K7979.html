Known Issue

This is the result of a known issue. When the Least Connections (member) load balancing mode is enabled for a pool, the BIG-IP system always selects the first pool member among equivalent candidate members.

For example, if the pool contains three members and each pool member has one current connection, BIG-IP LTM will send the next connection request to the first pool member in the pool. As a result, BIG-IP LTM has a load balancing bias, in terms of number of requests, to pool members at the top of the list.

Note: When pool members in a Least Connections (member) pool are tied with an equal and fewest number of connections, the BIG-IP system should attempt to distribute the next request evenly amongst those members.

F5 Product Development tracked this issue as CR82851 and it was fixed in BIG-IP LTM 9.3.1 and 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP 9.4.5, for the BIG-IP 9.4 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Note: The Least Connections (node) load balancing mode selects the same pool member among equivalent candidate members, and the issue is still outstanding.
