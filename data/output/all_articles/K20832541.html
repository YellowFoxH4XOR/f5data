BIG-IP ASM: Device group sync state shows "In Sync" but ASM configuration is not synced

Description

When you attempt to run a sync to the configured device group, one or more device group members log an error message similar to the following in /var/log/ts/asm_config_server.log:


asm_config_server.pl|ERR|Feb 08 04:12:47.348|6677|ASMConfig::Handler::spawn_relay_handler,,Sync recovery state timed out. State may be inconsistent with other peers

ASM sync normally resolves itself within a few minutes and outputs a Sync recovery state resolved successfully message in /var/log/ts/asm_config_server.log.

However, under some rare conditions, ASM sync does not resolve itself and the Sync recovery state resolved successfully message does not appear in the log.

To check the current sync recovery state on the config sync receiving device, run the following command:

# grep -i 'Sync recovery state' /var/log/ts/asm_config_server.log

If the issue is present, the output resembles the following — note the absence of a resolved successfully message:


asm_config_server.pl|ERR|Feb 18 09:49:44.633|15133|ASMConfig::Handler::spawn_relay_handler,,Sync recovery state timed out. State may be inconsistent with other peers
asm_config_server.pl|INFO|Feb 18 09:53:48.935|15133|ASMConfig::Handler::SyncHandler::sync_general_ucs_request,,ASM is now entering sync recovery state. Requesting complete configuration from /Common/<hostname_of_config_sync_source_device>

If the issue has resolved itself, the output includes a final line similar to:


asm_config_server.pl|INFO|Feb 18 09:55:22.702|15133|(eval),,Sync recovery state resolved successfully

Environment

  • BIG-IP Application Security Manager (ASM)
  • High availability (HA) pair configuration
  • Application Security Synchronization enabled on the device group

Cause

A full sync is pushed from one device to another and the sync recovery state times out before the operation completes, leaving the ASM configuration in an inconsistent state across peers.

Recommended Actions

Workaround

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected device.
  2. Change to the /ts/var/sync directory:

    # cd /ts/var/sync

  3. Delete the contents of the /ts/var/sync directory:

    # rm -f /ts/var/sync/*

  4. Restart the asm_config_server.pl process:

    # pkill -f asm_config_server

  5. Verify that the asm_config_server.pl process has restarted:

    # ps ax | grep asm_config_server.pl

  6. Repeat steps 1 through 5 on all peer devices.
  7. Initiate a device group full sync from the primary BIG-IP ASM device.

Additional Information

None.
