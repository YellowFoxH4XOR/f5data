Known Issue

Incorrect syslog-ng syntax prevents the BIG-IP configuration from loading after an upgrade.

This issue occurs when the following condition is met:

  • You use the syslog-ng include field.

    For example:

    tmsh modify sys syslog include "test"

In BIG-IP versions prior to 11.2.0, the syslog-ng.conf file is updated when you specify the include field with the Traffic Management Shell (tmsh). However, the system fails to perform validations, and does not report errors in syntax or content.

Impact

It is possible to upgrade a BIG-IP system that has a syslog-ng configuration with invalid syntax. As a result, the BIG-IP system fails to load the configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Prior to an upgrade, restarting syslog-ng when the syslog-ng.conf file contains invalid syntax returns an error message that appears similar to the following example:

    Shutting down syslog-ng: [  OK  ]
    Starting syslog-ng: syntax error at 916
    [FAILED]
  • After an upgrade, the Configuration utility displays a message that appears similar to the following example:

    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
  • Attempting to manually load the configuration after an upgrade includes messages that appear similar to the following example:

    01070920:3: Application error for confpp: STDERR/STDOUT text begins
    syntax error at 916
    STDERR/STDOUT text ends
    *************************************************************
    Mar  4 07:31:17 localhost confpp[8285]: syntax check command FAILURE for unix_config_syslog returned: '256'
    Restarting syslog-ng:
    Shutting down syslog-ng: [  OK  ]
    Starting syslog-ng: [  OK  ]

    Unexpected Error: Loading configuration process failed.
  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    err mcpd[5089]: 01070920:3: Application error for confpp: STDERR/STDOUT text begins syntax error at 916 STDERR/STDOUT text ends

    confpp[8588]: syntax check command FAILURE for unix_config_syslog returned: '256' Restarting syslog-ng:  Shutting down syslog-ng: [  OK  ]  Starting syslog-ng: [  OK  ]

    err tmsh[8485]: 01420006:3: Loading configuration process failed.

Workaround

To work around this issue, you can validate the syslog-ng syntax prior to performing an upgrade. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Validate the syslog-ng syntax by typing the following command:

    syslog-ng -s

    If the syslog-ng.conf file contains no invalid syntax, this command will not return any output.

    Note: After you have upgraded the system, this command will not return any errors because the system does not load the configuration and copy the invalid syntax to the syslog-ng.conf file.
  3. Correct any errors noted by the syslog-ng validation command listed in step 2, using the appropriate tmsh commands. For example, to completely remove an existing include statement, you would type the following command:

    tmsh modify sys syslog include none

    Note: Do not edit the syslog-ng.conf file directly. Use the appropriate tmsh commands to modify the syslog-ng include syntax.
