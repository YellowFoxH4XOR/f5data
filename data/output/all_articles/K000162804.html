SSH Virtual Server on TCP/22 Does Not Receive Traffic in a Single-NIC AWS BIG-IP VE Deployment

Product: BIG-IP LTM VE

Cloud platform: Amazon Web Services

Deployment: Single-NIC

Issue

An SSH virtual server configured on TCP/22 does not receive client traffic in a single-NIC AWS BIG-IP VE deployment.

Typical symptoms include:

  • SSH connections to the BIG-IP self IP succeed.
  • The SSH virtual server uses TCP/22 and has a valid pool configuration.
  • The virtual-server IP is registered as a secondary private IP on the AWS ENI.
  • AWS security-group rules appear to permit the traffic.
  • No client SYN packets are observed arriving at the virtual server.

Cause

In a single-NIC cloud deployment, management and data-plane traffic share the same interface. TCP/22 is also used by the BIG-IP management sshd service.

When the management SSH service and an SSH virtual server both use TCP/22, the traffic is handled as management traffic instead of being delivered to the virtual server. This is a limitation of the single-NIC deployment model.

The issue is not necessarily caused by an invalid virtual-server configuration, pool configuration, AWS ENI assignment, or security-group rule.

The port-handling behavior is consistent with the guidance in K27312387, which documents changing the default BIG-IP management SSH port in a single-interface cloud deployment. K27312387 is Azure-specific, but the BIG-IP management-port procedure is applicable to this configuration.

 

Resolution

Move the BIG-IP management SSH service from TCP/22 to an unused port, such as TCP/2222. Add the new port to the self-allow list and save the configuration.

Procedure

  1. Establish an administrative SSH session to the BIG-IP self IP.
  2. Change the BIG-IP management SSH port: 
    tmsh modify sys sshd port 2222
  3. Permit the new management SSH port on the self IP: 
    tmsh modify net self-allow defaults add { tcp:2222 }
  4. Save the configuration: 
    tmsh save sys config
  5. Update the AWS security group associated with the BIG-IP ENI to permit inbound TCP/2222 from the required administrative source addresses.
  6. Start a new SSH session to the BIG-IP self IP using TCP/2222.

After the change, management SSH is no longer available on TCP/22. The SSH virtual server can continue listening on TCP/22 and forward traffic to the SSH pool members on TCP/22.

Validation

AWS ENI validation

Confirm that:

  • The virtual-server IP is assigned as a secondary private IP on the BIG-IP data-plane ENI.
  • The AWS security group permits inbound TCP/22 to the virtual-server IP from the client source range.
  • AWS routing and network ACL configuration permit the traffic.
  • The client is connecting to the virtual-server IP rather than the BIG-IP self IP.

 

BIG-IP validation

Confirm that:

  • The virtual server is configured for TCP/22.
  • The virtual server has a valid SSH pool member.
  • The virtual-server IP is configured as an AWS secondary private IP.
  • TCP/2222 is permitted for management access on the self-allow list.
  • The management SSH service is configured to use TCP/2222.

Packet capture validation

Initiate a connection to the virtual-server IP on TCP/22 while capturing traffic on BIG-IP. After the management SSH service is moved to TCP/2222, the client SYN should arrive at the SSH virtual server instead of being handled by the management SSH service.

Alternative

Use a multi-NIC BIG-IP VE deployment when separate management and data-plane paths are required. Deploying multiple interfaces avoids relying on the same interface and management-port handling for both management and application traffic.
