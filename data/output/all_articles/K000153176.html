K000153176: VIPRION C4800 blades in slots 5–8 fail to join the cluster after upgrading to BIG-IP 17.5.x

Description

After upgrading a BIG-IP VIPRION C4800 chassis (platform: B4450N [A114]) to version 17.5.x, blades installed in slots above 4 (such as slots 5, 6, 7, or 8) may fail to come online and are reported as "offline" or "slot failed" in tmsh show sys cluster.

ltm logs on the affected blades display errors, including:

err chmand[xxxx]: 012a0003:3: HAL exception publishing switch config: Unknown slot for ChassisBase
err chmand[xxxx]: 012a0003:3: error chman main loop: Unknown slot for ChassisBase
err chmand[xxxx]: 012a0003:3: HAL unexpected init failure (continuing) : Unknown slot for ChassisBase
err clusterd[xxxx]: 01290003:3: HalmsgTerminalImpl_::sendMessage() Unable to send to any Host_CHman address

Note: libhal and mcpd debug mode should be activated to view the logs.

Enable the debug mode for mcpd and libhal:

tmsh modify sys db log.libhal.level { value "debug" }
tmsh modify sys db log.mcpd.level { value "debug" }
tmsh save sys config

Disable the debug mode after troubleshooting:

tmsh modify sys db log.libhal.level { value "notice" }
tmsh modify sys db log.mcpd.level { value "notice" }
tmsh save sys config

Environment

  • BIG-IP LTM
  • F5-VPR-C4800-AC, S100 (B4450/A114 blades)
  • vCMP provisioned

Cause

The issue is related to bug ID 2047593. The problem is due to a failure in the hardware abstraction layer (HAL) initialization during blade bootup. The error "Unknown slot for ChassisBase" indicates that the blade cannot correctly identify its physical slot or communicate with the chassis base module, resulting in chmand and MCPD failures on that blade. This can be triggered by firmware update issues or slot mapping inconsistencies, especially when blades are installed in non-contiguous slots after a major software upgrade.

Recommended Actions

Option 1 – Upgrade Path

1. Upgrade the blades to BIG-IP v21.x.

2. Install the related EHF for version 17.5.x. ( Check the release notes to confirm that bug ID 2047593 is included.)

Option 2 – Rollback / Re-image

1. Boot into the previous BIG-IP version and check if the issue clears.

2. If not resolved, re-image each blade with BIG-IP 17.1.2.x or earlier and confirm each blade comes online normally.

3. If any vCMP guests or vmdisks are lost during re-imaging, restore them from the UCS backups.
