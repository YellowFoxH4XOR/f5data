Topic

You should consider using this procedure under the following conditions:

  • You want to perform one of the following tasks on the BIG-IP system using the iControl representation state transfer (REST) API:
    • View a list of installed software images and which software image is currently active
    • View a list of software images that are available for installation
    • Install or delete a system software image or point release
    • Restart the BIG-IP system and boot into the current or another software volume

Description

The BIG-IP system allows you to install and delete additional software images on separate boot locations, also called volumes. You can then boot the BIG-IP system to a specific volume and begin processing traffic using that specific software version. For more information, refer to K34745165: Managing software images on the BIG-IP system using tmsh.

The REST procedures provided in this article are examples of common BIG-IP maintenance tasks. You can use the iControl REST API to perform most of the BIG-IP system management and configuration tasks that you can perform using the TMOS Shell (tmsh). For more information about the iControl REST API, refer to the iControl REST User Guide that applies to your BIG-IP version, available on F5 Cloud Docs.

curl and jq utilities

Performing the following procedures requires command-line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems but can also be installed on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure from an alternate BIG-IP system; however, the jq utility is not available on systems running versions earlier than BIG-IP 12.0.0. You can still use the curl portion of commands, but the resulting output is a single string rather than formatted JSON. For more information about the jq utility, refer to https://stedolan.github.io/jq.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command-line access to a system with the curl utility and, optionally, the jq utility installed. From more information, refer to curl and jq utilities in this article.
  • You have access to F5 Cloud Docs to review iControl REST API documentation.

Procedures

  • Viewing the currently installed BIG-IP software volumes
  • Viewing the software images, point releases, and hotfixes available for installation on the BIG-IP system
  • Installing a software image or point release to a new volume
  • Installing a software hotfix to a new volume
  • Viewing the progress of a software installation
  • Booting the system to a different software volume
  • Deleting a non-active software volume

Viewing the currently installed BIG-IP software volumes

You can view the list of currently installed software images prior to installing or deleting a software volume or determining which volume to activate.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to view a list of the currently installed BIG-IP software images:

    curl -sku admin:<password> -H "Content-Type: application/json" -X GET https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/software/volume | jq -M .

    For example, to view the software images on a BIG-IP using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X GET https://LTM1.example.com/mgmt/tm/sys/software/volume | jq -M .

    The output looks similar to the following example for each software volume. In this example, BIG-IP 13.1.0 is the only installed software version:

    [

        "kind": "tm:sys:software:volume:volumestate",

Installing a software image or point release to a new volume

You can install a software image or point release from the list of locally available software images to a new volume, using the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to install a software image to a new volume:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/software/image -d '{"command":"install","name":"<image name>","volume":"<volume>","options":[{"create-volume":true}]}' | jq -M .

    Note: The create-volume option is only required if the volume does not currently exist. If you are installing over an existing volume, you can omit this option. Additionally, you can provide the reboot option to automatically restart and boot into the new volume after installation is complete; however, the reboot option restarts the system as soon as the installation is complete. Doing so halts all traffic processing until the restart is complete. F5 recommends using the reboot option only during a maintenance window. For more information about booting into the new volume after installation, refer to the Booting the system to a different software volume procedure.

    For example, to create a new volume named HD1.2 and install the BIGIP-13.1.1-0.0.4.iso image to that volume on a BIG-IP using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/sys/software/image -d '{"command":"install","name":"BIGIP-13.1.1-0.0.4.iso","volume":"HD1.2","options":[{"create-volume":true}]}' | jq -M .

    The output looks similar to the following example:

    {
      "kind": "tm:sys:software:image:installstate",
      "command": "install",
      "name": "BIGIP-13.1.1-0.0.4.iso",
      "volume": "HD1.2",
      "options": [
        {
          "create-volume": true
        }
      ]
    }

    Note: The command prompt returns immediately, but the software installation continues on the BIG-IP system until complete.

Installing a software hotfix to a new volume

The procedure for installing a software hotfix is similar to installing a software image or point release; however the BIG-IP system must have a copy of both the hotfix image that is intended for installation and the software image for that hotfix. For example, to install BIG-IP 13.0.0 HF3, you must have the BIG-IP 13.0.0 software image and the HF3 hotfix image copied to the BIG-IP system. To determine which software versions and hotfixes you have available, refer to the Viewing the software images, point releases, and hotfixes available for installation on the BIG-IP system procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed
  2. Use the following command syntax to install a software image to a new volume:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/software/hotfix -d '{"command":"install","name":" <hotfix name>","volume":"<volume>","options":[{"create-volume":true}]}' | jq -M .

    Note: The create-volume option is only required if the volume does not currently exist. If you are installing over an existing volume, you can omit this option. Additionally, you can provide the reboot option to automatically restart and boot into the new volume after installation is complete; however, the reboot option restarts the system as soon as the installation is complete. Doing so halts all traffic processing until the restart is complete. F5 recommends using the reboot option only during a maintenance window. For more information about booting into the new volume after installation, refer to the Booting the system to a different software volume procedure.

    For example, to create a new volume named HD1.3 and install the Hotfix-BIGIP-13.0.0.3.0.1679-HF3.iso hotfix to that volume on a BIG-IP system using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/sys/software/hotfix -d '{"command":"install","name":"Hotfix-BIGIP-13.0.0.3.0.1679-HF3.iso","volume":"HD1.3","options":[{"create-volume":true}]}' | jq -M .

    The output looks similar to the following example:

    {
      "kind": "tm:sys:software:hotfix:installstate",
      "command": "install",
      "name": "Hotfix-BIGIP-13.0.0.3.0.1679-HF3.iso",
      "volume": "HD1.3",
      "options": [
        {
          "create-volume": true
        }
      ]
    }

    Note: The command prompt returns immediately, but the software installation continues on the BIG-IP system until complete. The BIG-IP system first creates the HD1.3 volume, then it installs the BIG-IP 13.0.0 software image, and then it installs the HF3 hotfix.

Viewing the progress of a software installation

You can view the progress of a software image, point release, or software hotfix installation using the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to view the software installation status:

    curl -sku admin:<password> -H "Content-Type: application/json" -X GET https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/software/volume/<volume name> | jq -M .

    For example, to view the software installation status for a volume named HD1.2 on a BIG-IP system using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X GET https://LTM1.example.com/mgmt/tm/sys/software/volume/HD1.2 | jq -M .

    The output looks similar to the following example:

    {
      "kind": "tm:sys:software:volume:volumestate",
      "name": "HD1.2",
      "fullPath": "HD1.2",
      "generation": 271,
      "selfLink": "https://localhost/mgmt/tm/sys/software/volume/HD1.2?ver=13.1.0",
      "basebuild": "0.0.4",
      "build": "0.0.4",
      "product": "BIG-IP",
      "status": "installing 36.000 pct",
      "version": "13.1.1"
    }

    The status line in this example indicates that the installation is 36 percent complete. When the installation is finished, the status line looks similar to the following example:

      "status": "complete",

    Note: When you install a software hotfix to a new volume, the software install progress first displays the base software image being installed. Then, when the base image installation is complete, the hotfix installation begins, and the progress for the hotfix installation is displayed.

Booting the system to a different software volume

You can restart and boot the BIG-IP system to another software volume using the following procedure. You can do this during a maintenance window to complete a new version installation.

Impact of procedure: Restarting the BIG-IP system halts all traffic processing on that BIG-IP system. You should do this during a maintenance window to allow time for the BIG-IP system to come back online.

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the following command syntax to restart and boot to the new volume:

    curl -sku admin:<password> -H "Content-Type: application/json" -X POST https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys -d '{"command":"reboot","volume":"<volume name>"}' | jq -M .

    For example, to restart and boot to a volume named HD1.2 on a BIG-IP system using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/sys -d '{"command":"reboot","volume":"HD1.2"}' | jq -M .

    The output looks similar to the following example:

    {
      "kind": "tm:sys:rebootstate",
      "command": "reboot",
      "volume": "HD1.2"
    }

    Note: If you omit the volume name from the reboot command, the BIG-IP system restarts and boots to the currently active volume, as in the following example:

    curl -sku admin:testing -H "Content-Type: application/json" -X POST https://LTM1.example.com/mgmt/tm/sys -d '{"command":"reboot"}' | jq -M .

    The output looks similar to the following:

    {
      "kind": "tm:sys:rebootstate",
      "command": "reboot"
    }

Deleting a non-active software volume

You can delete non-active software volumes using the following procedure. To delete the active volume, you must first restart the system and boot to an alternate software volume. For more information, refer to the Booting the system to a different software volume procedure.

Impact of procedure: There is no confirmation and no output when you delete a non-active software volume, and the action cannot be reversed. F5 recommends that you back up your BIG-IP configuration prior to deleting volumes. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13.x).

  1. Log in to the command line of a system with the curl and jq utilities installed.
  2. Use the Viewing the currently installed BIG-IP software volumes procedure to confirm the volume you want to delete.
  3. Use the following command syntax to delete a non-active software volume:

    curl -sku admin:<password> -H "Content-Type: application/json" -X DELETE https://<BIG-IP hostname or mgmt IP address>/mgmt/tm/sys/software/volume/<volume name> | jq -M .

    For example, to delete a volume named HD1.1 on a BIG-IP using the previously listed Example configuration, type the following command:

    curl -sku admin:testing -H "Content-Type: application/json" -X DELETE https://LTM1.example.com/mgmt/tm/sys/software/volume/HD1.1 | jq -M .

    No output is returned for non-active volumes. If you attempt to delete the active volume, the output looks similar to the following example:

    {
      "code": 400,
      "message": "01071075:3: The active volume (HD1.2) cannot be modified.",
      "errorStack": []
    }

    Note: Although no output is returned when you successfully delete a non-active software volume, the system logs messages similar to the following to the /var/log/audit file:

    notice mcpd[<pid>]: 01070417:5: AUDIT - client tmsh, tmsh-pid-30330, user admin - transaction #158287-2 - object 0 - obj_delete { software_desired { software_desired_volume "HD1.1" } } [Status=Command OK]
    notice icrd_child[<pid>]: 01420002:5: AUDIT - pid=30330 user=admin folder=/Common module=(tmos)# status=[Command OK] cmd_data=delete sys software volume HD1.1
