Topic

This article explains the three update phases of the BIG-IP Edge Client on Windows, which components are updated in each phase, and how the Component Update setting (Yes, No, or Prompt) affects the update behavior.

  • BIG-IP APM
  • BIG-IP Edge Client for Windows
  • APM Clients 7.x
  • Connectivity profile with Component Update configured as Yes, No, or Prompt

Description

When a BIG-IP Edge Client connects to a BIG-IP APM Virtual Server, the system compares the client-side component versions with the server-side versions. If the client version is lower than the server version, an update process is triggered. This update process runs in three sequential phases, and the behavior of each phase is controlled by the Component Update setting in the BIG-IP APM Connectivity profile.

The three auto-update phases:

  • Phase 1: Edge Client Components
    When does this run? Immediately upon the BIG-IP Edge Client connecting to the BIG-IP Virtual Server, before user authentication when auto-update is enabled on the BIG-IP system.
    What gets updated? The update applies to the core BIG-IP Edge Client application binary and its related service components. A few examples of the modules involved are listed below:
    • f5fpclientW.exe — BIG-IP Edge Client for Windows binary
    • Component Installer Service
    • Installer Control
    • DNS Relay Proxy Service
    • Credential Manager Service"
      Note: SuperHost is always updated automatically regardless of the Component Update setting. This behavior cannot be suppressed.
  • Phase 2: Endpoint Inspection (EPI / EPSEC) Components:
    When does this run? After user authentication and session establishment, during the endpoint inspection (posture assessment) phase of the access policy execution. 
    What gets updated?  The update applies to the endpoint inspection and security posture components. A few examples of the modules involved are listed below:
    • EPSEC / OPSWAT inspection libraries
    • Endpoint inspection agents configured in the access policy
  • Phase 3: VPN Components
    When does this run? Just before VPN tunnel establishment — during the Initializing phase — after authentication and EPI checks are complete.
    What gets updated?  The update applies to the core VPN tunnel components. A few examples of the modules involved are listed below:
    • urxhost.dll — Host Control
    • TunnelServerX.dll — TunnelServer
    • urxdialer.dll / urxvpn.cab — VPN Dialer
    Note that during Phase 3, if a Machine Tunnel is running, it is paused by design to allow the VPN driver components to be updated without conflict. The Machine Tunnel resumes automatically once the VPN components are updated and the tunnel is established. This is logged on the client as:
    CHostCtrl::PauseMachineTunnelOnVpnUpgrade, VPN is about to upgrade hence Pausing Machine tunnel

Component update setting behavior

The following section describes the 3 component update settings:

  • Component Update = Yes
    All three phases run and all components across all phases are updated automatically without any user interaction.

  • Component Update = No
    Phase 1 Edge Client components and Phase 3 VPN components are not updated. However, Phase 2 EPI/EPSEC components are still updated regardless of this setting, as endpoint inspection components are always pushed to the client to maintain consistent security posture assessment.

  • Component Update = Prompt
    A one-time prompt is displayed to the user at BIG-IP Edge Client launch, asking whether to proceed with the update.

    • User selects Yes
      If the user selects Yes, all three phases run and all components are updated — identical to the Yes setting behavior.
    • User selects No
      If the user selects No at the prompt, only Phase 1 BIG-IP Edge Client components are blocked. Phase 2 (EPI/EPSEC) and Phase 3 (VPN) components are still updated automatically, regardless of the user's selection.
    Important: The Component Update prompt applies exclusively to Phase 1 BIG-IP Edge Client components. EPI/EPSEC (Phase 2) and VPN (Phase 3) components are not included in the prompt and will always be updated to the latest server version regardless of the user's Yes/No selection. This is by design.
