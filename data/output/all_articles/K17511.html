Known Issue

The Traffic Management Microkernel (TMM) may leak memory when a Virtual Clustered Multiprocessing (vCMP) guest allocates only one CPU per blade.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION system that is licensed as a vCMP host.
  • You have deployed one or more vCMP guests with a single CPU allocated per blade.

Impact

Over time, performance may degrade and the vCMP guest may become unresponsive or reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms on the vCMP guest:

  • Log messages similar to the following example appear in the /var/log/ltm file:

    tmm tmm[1234]: 011e0002:4: sweeper_update: aggressive mode activated. (123456/234567 pages)

  • You notice a progressive increase in the amount of memory that the connflow buffer uses.

    For example:

    # tmsh show sys memory | grep -E 'SubSystem|connflow'
    Sys::SubSystem Memory
    SubSystem Alloc (bytes) Max Alloc (bytes) Object Size
    connflow 4.0G 4.0G 6000000

  • The system unexpectedly reboots or fails over to another system in the device group.
  • The system generates a TMM core file in the /shared/core directory.

Resolution

Workaround

To work around this issue, you can allocate more than one CPU per blade.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
