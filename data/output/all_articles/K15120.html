Topic

You should consider using this procedure under the following condition:

  • You want to set up an IPSec tunnel between two BIG-IP AFM systems using the tmsh utility.

Description

You can configure an IPSec tunnel whenever you require traffic to traverse between two BIG-IP AFM systems that are separated by a wide area network (WAN) like the Internet. The basic configuration of an IPSec tunnel between two BIG-IP AFM systems is the same as any other BIG-IP systems, except for the requirement to configure the firewall rules for the BIG-IP AFM system. The configuration discussed in this article derives from a network setup similar to the following example:

In the previous example, note the following:

  • The gateways between the Site-1 and Site-2 are routed over a WAN, for example the Internet.
  • The gateway is directly connected to the BIG-IP AFM system on VLAN81 (public VLAN) for each site.
  • The client is directly connected to the BIG-IP AFM system on VLAN1555 (private VLAN) for each site.

In this scenario, the IPSec tunnel is configured to establish from the BIG-IP AFM system in Site-1 to the BIG-IP AFM system in Site-2, and the other way around, so that the traffic from clients on both sides traverses through this IPSec tunnel.

You must configure the following list of objects for IPSec to function properly:

  • Public VLANs and IP addresses for both BIG-IP systems to reach each other over the WAN
  • Private VLANs and IP address ranges for the private networks behind each BIG-IP system
  • Default route or a specific route on each BIG-IP system that points to the other end of the private network
  • IKE Peers configuration
  • IPSec Policies configuration
  • IPSec Traffic Selectors configuration
  • IP forwarding virtual servers for handling the unencapsulated traffic egressing from the IPSec tunnel between the two private networks

Considerations for the BIG-IP AFM system

To establish the IPSec tunnel, you must configure the global firewall rules for the BIG-IP AFM system so the system accepts both the IPSec Encapsulating Security Payload (ESP) and Internet Security Association and Key Management Protocol (ISAKMP) traffic. If you require more granular control on the types of unencapsulated traffic flowing between the two private networks, you can configure firewall rules in the forwarding virtual servers on both BIG-IP AFM systems.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You should have a basic understanding of how IPSec works in tunnel mode.
  • You must have administrative access to the tmsh utility and the command line on the BIG-IP AFM systems.
  • You must have a client residing on each of the internal networks for each BIG-IP AFM system; thee system uses these clients to bring up the IPSec tunnel for verification purposes.
  • You must prepare a public IP address as the self IP address for each BIG-IP system. Note: When the BIG-IP system is behind a NAT device, you may use a private IP address as the public IP, and you may have to configure your NAT device to forward the appropriate traffic to the BIG-IP AFM systems.

  • You must prepare a range of private IP addresses for the private networks residing behind each BIG-IP system.

Procedures

To configure the IPSec tunnel between both BIG-IP AFM systems using the tmsh utility, perform the following procedures:

  • Configuring the public and private VLANs
  • Configuring the public and private self IP addresses
  • Configuring the route to the private networks
  • Configuring the IKE Peers
  • Configuring the IPSec Policies
  • Configuring the IPSec Traffic Selectors
  • Configuring the Virtual Servers for the private networks
  • Configuring the firewall rules for the BIG-IP AFM system (11.6.0 and later) 
  • Configuring the firewall rules for the BIG-IP AFM system (11.3.0 - 11.5.1)
  • Establishing and verifying the IPSec tunnel

Configuring the public and private VLANs

You must configure a public VLAN and a private VLAN on each BIG-IP AFM system if you do not have existing VLANs configured or if you do not wish to use the existing VLANs for IPSec traffic. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility.
  2. Configure the public VLAN using the following command syntax:

    create /net vlan <vlan name> interfaces add { <interface 1> <interface 2>...} tag <VLAN Tag ID>

    Using the example in the Description section, you must enter the following command to configure the public VLAN VLAN81 with VLAN tag 81 and use interface 1.1:

    create /net vlan vlan81 interfaces add { 1.1 } tag 81

  3. Configure the private VLAN using the same command syntax as the previous step.

    Using the example in the Description section, you must enter the following command to configure the private VLAN VLAN1555 with VLAN tag 1555 and use interface 1.2:

    create /net vlan vlan1555 interfaces add { 1.2 } tag 1555

  4. Save the changes by typing the following command:

    save /sys config

  5. Repeat steps 1 through 4 on the other system.

Configuring the public and private self IP addresses

You must configure at least one public self IP address on each BIG-IP AFM system so they can establish a connection with each other over the WAN. Additionally, you must configure at least one private self IP address on each BIG-IP AFM system as the gateway for the private network behind each system. You may skip this procedure if you have existing IP addresses that you wish to use as the public and private self IP addresses for the BIG-IP AFM systems. To configure the public and private self IP addresses, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure the public IP address using the following command syntax:

    create /net self <self IP name> address <self IP address/with netmask> allow-service <allowed ports> traffic-group <traffic group name> vlan <VLAN name>

    Using the example in the Description section, you must enter the following command on Site-1 BIG-IP AFM system to configure the public VLAN VLAN81 with IP address 1.1.1.2/28, and allow all ports for the self IP:

    create /net self vlan81-self1 address 1.1.1.2/28 allow-service all traffic-group traffic-group-local-only vlan vlan81

  3. Configure the private VLAN using the same command syntax as the previous step.

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to configure the private VLAN VLAN1555 with IP address 172.16.1.254/24 and allow all ports for the self IP:

    create /net self vlan1555-self1 address 172.16.1.254/24 allow-service all traffic-group traffic-group-local-only vlan vlan1555

  4. Save the changes by typing the following command:

    save /sys config

  5. Repeat steps 1 through 4 on the other system using the appropriate IP addresses.

Configuring the route to the other site's BIG-IP AFM system and their private networks

If no existing routes for the IPSec traffic are configured on the systems, you must configure the route to the other site's BIG-IP AFM system and the corresponding private networks. To do so, perform the following procedure:

Impact of procedure: Configuring an incorrect route may affect the traffic flow on your systems.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure a route to the destination host, which is the public IP address of the other site's BIG-IP AFM system, using the following command syntax:

    create /net route <route name> gw <next hop IP address> network <destination host>

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to route traffic to the Site-2 BIG-IP AFM system through the next hop gateway 1.1.1.1:

    create /net route site2-public-route gw 1.1.1.1 network 2.2.2.2/32

    Note: If there is no default route configured on the system, or if the IPSec traffic path does not use the default route that is configured on the system, then you must complete this step.

  3. Configure a route to the private network directly behind the other site's BIG-IP AFM system using the following command syntax:

    create /net route <route name> gw <next hop IP address> network <destination network>

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to route traffic to the private network directly behind the Site-2 BIG-IP AFM system using the same next hop gateway 1.1.1.1:

    create /net route site2-private-route gw 1.1.1.1 network 172.16.2.0/24

    Note: If there is no default route configured on the system, or if the IPSec traffic path does not use the default route that is configured on the system, then you must complete this step.

  4. Save the changes by typing the following command:

    save /sys config

  5. Repeat steps 1 through 4 on the other system using the appropriate IP addresses.

Configuring the IKE Peers

When you have configured the necessary network objects, you can configure the IKE peer on each site's  BIG-IP AFM system. To do so, perform the following procedure:

Impact of procedure: Configuring an incorrect encrypted preshared key may result in the IPSec tunnel failing to establish in a later procedure.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure the other site's BIG-IP AFM system as the IKE peer on this system by using the following command syntax:

    create /net ipsec ike-peer <name of IKE peer> { lifetime <lifetime of IKE phase 1 security association in minutes> nat-traversal <on|off|force> phase1-auth-method pre-shared-key preshared-key-encrypted <string of encrypted preshared key> remote-address <public IP address of the other site's BIG-IP> verify-cert true }

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to configure the Site-2 BIG-IP AFM system as its IKE peer, using the following, encrypted preshared key:

    create /net ipsec ike-peer site2-ikepeer { lifetime 30 nat-traversal off phase1-auth-method pre-shared-key preshared-key-encrypted "UWXTD5JHqAkKPZF1\?ibMR4\?7CM7;>]k)*fOCJ/XS2BFmt_t" remote-address 2.2.2.2 verify-cert true }

  3. Save the changes by typing the following command:

    save /sys config

  4. Repeat steps 1 through 3 on the other system using the appropriate settings.

Configuring the IPSec Policies

After configuring the IKE peers on the BIG-IP AFM systems in both sites, you can configure the IPSec policy for the BIG-IP AFM systems for each site. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility.
  2. Configure the IPSec policy by entering the following command syntax:

    create /net ipsec ipsec-policy <IPSec policy name> { ike-phase2-lifetime <lifetime of IKE phase 2 security association in minutes> mode tunnel tunnel-local-address <local public IP address> tunnel-remote-address <destination IP address> }

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to configure its IPSec policy:

    create /net ipsec ipsec-policy ipsecpol-site1-site2 { ike-phase2-lifetime 30 mode tunnel tunnel-local-address 1.1.1.2 tunnel-remote-address 2.2.2.2 }

  3. Save the changes by typing the following command:

    save /sys config

  4. Repeat steps 1 through 3 on the other system using the appropriate settings.

Configuring the IPSec Traffic Selectors

When you have configured the IPSec policies on both BIG-IP AFM systems, you may proceed to configure the IPSec traffic selectors to define which source and destination addresses can send traffic through the IPSec tunnel. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility.
  2. Configure the IPSec traffic selector by entering the following command syntax:

    create /net ipsec traffic-selector <name of traffic selector> { destination-address <private network address behind the other site's AFM> ipsec-policy <name of IPSec policy to apply> source-address <private network address behind this AFM> }

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to configure its IPSec traffic selector:

    create /net ipsec traffic-selector selector-site1-site2 { destination-address 172.16.2.0/24 ipsec-policy ipsecpol-site1-site2 source-address 172.16.1.0/24 }

  3. Save the changes by typing the following command:

    save /sys config

  4. Repeat steps 1 through 3 on the other system using the appropriate settings.

Configuring the Virtual Servers for the private networks

Once you have completed the IPSec configurations, you must configure IP forwarding virtual servers on both BIG-IP AFM systems. To simplify administration and configuration, you can configure one IP forwarding virtual server that listens on both the private and public VLANs on each BIG-IP AFM system. If you require more granular control over the traffic flow, you can configure a virtual server that listens on the private VLAN of the local BIG-IP AFM system and another virtual server that listens on the public VLAN of the remote BIG-IP AFM system. This will process client traffic initiated from the private VLAN in the local site to the private VLAN in only the remote site. To allow the system to initiate client traffic from the private VLAN in the remote site to the private VLAN in the local site, you can configure a virtual server that listens on the private VLAN of the remote BIG-IP AFM system, and configure another virtual server that listens on the public VLAN of the local BIG-IP AFM system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure the IP forwarding virtual server that listens on the private VLAN of the local site by using the following command syntax:

    create /ltm virtual <name of VS> { destination <private network address and port> ip-forward mask <private network netmask> source <private network address and mask> profiles add { fastL4 { } } vlans add { <VLAN 1> ... } vlans-enabled }

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system to configure its IP forwarding virtual server:

    create /ltm virtual ipsec-encap { destination 172.16.2.0:any ip-forward mask 255.255.255.0 source 172.16.1.0/24 profiles add { fastL4 { } } vlans add { vlan1555 } vlans-enabled }

  3. If you require the system to initiate client traffic from the private VLAN in the remote site to the private VLAN in the local site, you must configure an IP forwarding virtual server that listens on the private VLAN in the remote site on the remote BIG-IP AFM system, and another IP forwarding virtual server that listens on the public VLAN in the local site on the local BIG-IP AFM system.

    Using the example in the Description section, you must enter the following command on the Site-1 BIG-IP AFM system:

    create /ltm virtual ipsec-decap { destination 172.16.1.0:any ip-forward mask 255.255.255.0 source 172.16.2.0/24 profiles add { fastL4 { } } vlans add { vlan81 } vlans-enabled }

  4. Save the change by typing the following command:

    save /sys config

  5. Repeat steps 1 through 4 on the other system using the appropriate settings.

Configuring the firewall rules for the BIG-IP AFM system (11.6.0 and later) 

When you have configured the IP forwarding virtual servers on both BIG-IP AFM systems, you must configure global firewall rules in the BIG-IP AFM system, and the firewall rules in the IP forwarding virtual server. The global firewall rules will allow the BIG-IP AFM system to accept incoming IPSec ESP and ISAKMP traffic for the IPSec tunnel, while the IP forwarding virtual server firewall rules will allow the BIG-IP AFM system to accept the unencapsulated private network traffic between the two sites. To do so, perform the following procedure:

Impact of procedure: Configuring an incorrect firewall rule may result in IPSec traffic failing to establish between the two systems.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure the global firewall rules so the BIG-IP AFM system can accept incoming IPSec ESP traffic, by using the following command syntax:

    create|modify /security firewall policy <name of policy> rules add { <name of FW rule> { <place-before|place-after> <first|last> action accept-decisively ip-protocol <name of IPSec protocol> log <yes|no> destination { ports add { <port>... } } source { ports add { <port>... } vlans add { <vlan1>... } } } }

    Using the example in the Description section, you must enter the following command on the BIG-IP AFM system to configure the global firewall rule to accept IPSec ESP traffic on VLAN81:

    create /security firewall policy my_fw_policy rules add { esp { place-before first action accept-decisively ip-protocol esp log yes source { vlans add { vlan81 } } } }

    Note: Ensure that the VLAN you added is the public VLAN on the local BIG-IP AFM system.

  3. Configure the global firewall rules for the BIG-IP AFM system to accept incoming IPSec ISAKMP traffic by entering the same command syntax as in the previous step, except use modify instead of create, use UDP for the ip-protocol and port 500 for both the source and destination ports. Using the example in the Description section, you must enter the following command on BIG-IP AFM system to configure the global firewall rule to accept IPSec ISAKMP traffic on VLAN81:

    modify /security firewall policy my_fw_policy rules add { isakmp { place-after first action accept-decisively ip-protocol udp log yes destination { ports add { 500 } } source { ports add { 500 } vlans add { vlan81 } } } }

    Note: Ensure that the VLAN that you added is the public VLAN on the local BIG-IP AFM system. Additionally, you must add port 4500 if you are using IPSec NAT traversal (NAT-T).

  4. Assign the new policy to the global firewall rules, using the following syntax:

    modify /security firewall global-rules <enforced-policy|staged-policy> <name of policy>

    Using the example in the Description section, you must enter the following command on the BIG-IP AFM system to assign the new policy to the global firewall rules:

    modify /security firewall global-rules enforced-policy my_fw_policy
  5. If you require more granular control on the types of unencapsulated traffic flowing between the two private networks, you can configure a firewall policy for use by the IP forwarding virtual server for the BIG-IP AFM system by using the same syntax as in step number 2. For example, you can enter the following command on the BIG-IP AFM system to configure a firewall policy to accept any traffic destined for the Site-2 private network (172.16.2.0/24) from the  Site-1 private network (172.16.1.0/24) :

    create /security firewall policy my_VS_policy rules add { private_net_allow { place-before first ip-protocol any action accept log yes destination { addresses add { 172.16.2.0/24 } } source { addresses add { 172.16.1.0/24 } } } }

    Note: You should configure the virtual server firewall rules that are appropriate for your application environment.

  6. Assign the new policy to the virtual server, using the following syntax:

    modify /ltm virtual <name of VS> <fw-enforced-policy|fw-staged-policy> <name of policy>

    Using the example in the Description section, use the following command:

    modify /ltm virtual ipsec-encap fw-enforced-policy my_VS_policy
  7. Save the changes by typing the following command:

    save /sys config

  8. Repeat steps 1 through 5 on the other system using the appropriate settings.

Configuring the firewall rules for the BIG-IP AFM system (11.3.0 - 11.5.1)

When you have configured the IP forwarding virtual servers on both BIG-IP AFM systems, you must configure global firewall rules in the BIG-IP AFM system, and the firewall rules in the IP forwarding virtual server. The global firewall rules will allow the BIG-IP AFM system to accept incoming IPSec ESP and ISAKMP traffic for the IPSec tunnel, while the IP forwarding virtual server firewall rules will allow the BIG-IP AFM system to accept the unencapsulated private network traffic between the two sites. To do so, perform the following procedure:

Impact of procedure: Configuring an incorrect firewall rule may result in IPSec traffic failing to establish between the two systems.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Configure the global firewall rules so the BIG-IP AFM system can accept incoming IPSec ESP traffic, by using the following command syntax:

    modify /security firewall global-rules rules add { <name of FW rule> { <place-before|place-after> <first|last> action accept-decisively ip-protocol <name of IPSec protocol> log <yes|no> destination { ports add { <port>... } } source { ports add { <port>... } vlans add { <vlan1>... } } } }

    Using the example in the Description section, you must enter the following command on the BIG-IP AFM system to configure the global firewall rule to accept IPSec ESP traffic on VLAN81:

    modify /security firewall global-rules rules add { esp { place-before first action accept-decisively ip-protocol esp log yes source { vlans add { vlan81 } } } }

    Note: Ensure that the VLAN you added is the public VLAN on the local BIG-IP AFM system.

  3. Configure the global firewall rules for the BIG-IP AFM system to accept incoming IPSec ISAKMP traffic by entering the same command syntax as in the previous step, except use UDP for the ip-protocol and port 500 for both the source and destination ports. Using the example in the Description section, you must enter the following command on BIG-IP AFM system to configure the global firewall rule to accept IPSec ISAKMP traffic on VLAN81:

    modify /security firewall global-rules rules add { isakmp { place-after first action accept-decisively ip-protocol udp log yes destination { ports add { 500 } } source { ports add { 500 } vlans add { vlan81 } } } }

    Note: Ensure that the VLAN that you added is the public VLAN on the local BIG-IP AFM system. Additionally, you must add port 4500 if you are using IPSec NAT traversal (NAT-T).

  4. If you require more granular control on the types of unencapsulated traffic flowing between the two private networks, you can configure a firewall rule in the IP forwarding virtual server for the BIG-IP AFM system by using the following command syntax:

    modify /ltm virtual <name of VS> fw-rules add { <name of firewall rule> { <place-before|place-after> <first|last> ip-protocol <protocol> action accept log <yes|no> destination { addresses add { <private network address behind the other site's AFM> } ports add { <allowed protocol port> } } source { addresses add { <private network address behind this AFM> } vlans add { <vlan1> ...} } } }

    For example, you can enter the following command on the BIG-IP AFM system to configure the firewall rule in its IP forwarding virtual server to accept any traffic destined for the Site-2 private network (172.16.2.0/24) from the  Site-1 private network (172.16.1.0/24) :

    modify /ltm virtual ipsec-encap fw-rules add { private_net_allow { place-before first ip-protocol any action accept log yes destination { addresses add { 172.16.2.0/24 } } source { addresses add { 172.16.1.0/24 } } } }

    Note: You should configure the virtual server firewall rules that are appropriate for your application environment.

  5. Save the changes by typing the following command:

    save /sys config

  6. Repeat steps 1 through 5 on the other system using the appropriate settings. 

Establishing and verifying the IPSec tunnel

When you have completed all the necessary configuration on the BIG-IP AFM system, you can establish the IPSec tunnel between the two private networks by sending traffic from a client residing in each private network. You can do so by sending ping packets from a client in Site-1 private network to another client in Site-2 private network, and the other way around.  To verify whether the IPSec tunnel is established between the two BIG-IP AFM systems, you can enter the following commands to view the security associations:

racoonctl show-sa isakmp

racoonctl show-sa ipsec

If the IPSec tunnels are properly established, you should see matching values on both systems for the Cookies parameter from the racoonctl show-sa isakmp command and the SPI parameters from the racoonctl show-sa ipsec command.
