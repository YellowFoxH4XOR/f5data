Topic

You should consider using this procedure under the following conditions:

  • You want to use Terraform and F5 Declarative Onboarding (DO) to configure the BIG-IP system.
  • You want to create a template from a JSON file used for DO so that Terraform can pass variables to it.

    Note: Terraform can call your DO JSON file to apply your object definitions. However, when you create a Terraform template file, do.tpl, Terraform can pass variables to your DO definitions, and you can define variables at runtime.

Description

With DO, you can configure your BIG-IP system using a declarative representational state transfer (REST) API. To do so, you create a JSON file with a declaration and use an HTTP client to transmit it to the DO REST API. You can automate the task on a single or numerous BIG-IP systems using Terraform, which is an orchestration tool that automates and manages multi-machine configuration and deployment.

If you want to use Terraform to automate installing the DO package, refer to K17621261: Using Terraform to install DO on the BIG-IP system.

After you complete your initial installation using DO, if you want to use a declarative model to configure applications and services on your BIG-IP system, you can use F5 Application Services 3 extension (AS3). For more information about Terraform and AS3, refer to K23449665: Using Terraform and AS3 to configure the BIG-IP system.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You read the F5 Resources for Terraform User Guiide.
  • You read the F5 Declarative Onboarding documentation.
  • You installed the DO package on the target BIG-IP device. For more information, refer to Downloading and installing the Declarative Onboarding package.
  • You installed Terraform 0.12.10 or later on your control machine.
  • You installed BIG-IP 13.1 or later on the devices in your environment.

Procedures

To configure Terraform to use DO to initially configure the BIG-IP system, you create the following three files in the same directory:

  • main.tf—The Terraform file that specifies the BIG-IP system as the provider and calls the do.tpl file. You can give the file an arbitrary name, such as main, but it must have the .tf extension.
  • terraform.tfvars—Contains all the variables you want to declare at runtime. You must use this filename and extension.
  • do.tpl—You create this template file from a JSON file that contains definitions of the objects on your BIG-IP system. You can provide an arbitrary name for this file, such as do.

To create these three files and apply them to your BIG-IP system, perform the following procedures:

Note: To apply your object definitions, instead of using a do.tpl file, you can have Terraform call a do.json file directly. However, using Terraform's template file, do.tpl, enables Terraform to pass variables to your object definitions and you to define these variables at runtime.

  • Creating the JSON declaration template file
  • Creating the main.tf Terraform file
  • Creating the variable definition file
  • Running Terraform to apply the definitions
  • Destroying the DO definitions

Creating the JSON declaration template file

File templating is a Terraform feature, and you can create a JSON declaration file as a template to use with the with the bigip_declarative_onboarding module.

For example, the following procedure:

  • Describes how to include variables, using an example JSON declaration from the "F5 Declarative Onboarding" documentation.
  • Describes how to use variables for only the hostname, DNS servers, NTP servers, and password parameters.
  • Provides an outline to help you create more advanced JSON declaration templates and use variables of your choosing.

Notes:

  • In Terraform templates, variables are enclosed in open (${) and close (}) braces.
  • The template uses existing nodes in the Common partition. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Create a JSON declaration file using the Sample declaration for a standalone BIG-IP example in Composing a Declarative Onboarding declaration for a standalone BIG-IP, and name it do.tpl.

    Note: The JSON declaration template in this procedure is only a subset of the sample in the "F5 Declarative Onboarding" documentation.

  2. Use a text editor to open the file for modification.

  3. For hostname, replace the value with the following variable: ${ HOSTNAME}.

  4. In the DNS class, replace the nameServers value with the following variable: ${ DNS_ADDRESS}.

  5. In the NTP class, replace the value for servers with ${ DNS_ADDRESS}.

  6. In the User class, replace the password value with ${GUEST_PASSWORD}.

The following example is a a JSON declaration template that includes the modifications in this procedure:

Notes: The following JSON declaration template is a subset of the one in the "F5 Declarative Onboarding" documentation.

{
    "schemaVersion": "1.0.0",
    "class": "Device",
    "async": true,
    "webhook": "https://example.com/myHook",
    "label": "my BIG-IP declaration for declarative onboarding",
    "Common": {
        "class": "Tenant",
        "hostname": "${HOSTNAME}",
        "myDns": {
            "class": "DNS",
            "nameServers": [
                "${DNS_ADDRESS}"
            ],
            "search": [
                "f5.com"
            ]
        },
        "myNtp": {
            "class": "NTP",
            "servers": [
                "${NTP_ADDRESS}"
            ],
            "timezone": "Singapore"
        },
        "guestUser": {
            "class": "User",
            "userType": "regular",
            "password": "${GUEST_PASSWORD}",
            "partitionAccess": {
                "Common": {
                    "role": "guest"
                }
            }
        }
    }
}

Creating the main.tf Terraform file

You create the Terraform file, main.tf, in the same directory as the template and variable files from the previous procedures.

In the following example:

  • The first six objects declare the address and password variables for the BIG-IP system, and other variables required by the DO template file, do.tpl.
  • The next objects define the BIG-IP provider and the template file.
  • The template_file object reads your do.tpl file and passes it the variables you defined in terraform.tfvars at runtime.
  • The bigip_do resource object calls and applies the DO that you defined in do.tpl.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.

  2. In the code in the following step, step 3, in the terraform -> bigip stanza, replace "1.22.2" with the latest version found in the  F5Networks/terraform-provider-bigip provider in the Terraform registry.
  3. In a text editor, copy, paste, and save the following as main.tf:

    variable "bigip_address" {
      type = string
    }
    variable "admin_password" {
      type = string
    }
    variable "guest_password" {
      type = string
    }
    variable "bigip_hostname" {
      type = string
    }
    variable "dns_address" {
      type = string
    }
    variable "ntp_address" {
      type = string
    }

    terraform {
      # Terraform configuration settings (optional)
    required_providers {
          # Define required providers here
          bigip = {
              source  = "F5Networks/bigip"
              version = "~> 1.22.2" #Replace with latest version
          }
        }
    }

    provider "bigip" {
        address = "${var.bigip_address}"
        username = "admin"
        password = "${var.admin_password}"
    }
    data "template_file" "init" {
      template = "${file("do.tpl")}"
      vars = {
        HOSTNAME = "${var.bigip_hostname}"
        DNS_ADDRESS = "${var.dns_address}"
        NTP_ADDRESS = "${var.ntp_address}"
        GUEST_PASSWORD = "${var.guest_password}"
      }
    }
    resource "bigip_do"  "do-example" {
         do_json = "${data.template_file.init.rendered}"
    }

Creating the variable definition file

There are various ways that you can define variables in Terraform. When you do not provide default values, such as the bigip_address, admin_password, and guest_password variables in this example, the system prompts you to enter them at runtime.

For other variables, you can declare them in a file that you must name terraform.tfvars and locate in the same directory as your Terraform .tf file.

To create this file and declare your variables, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. In a text editor, copy and paste the following:

    bigip_address="10.10.10.1"
    bigip_hostname="host1.example.com"
    dns_address="10.10.4.1"
    ntp_address="10.10.4.1"

  3. Edit the values to make them appropriate for your environment.
  4. Save the file as terraform.tfvars.

Running Terraform to apply the definitions

To apply the DO definitions to your BIG-IP system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.

  2. Enter the following command:

    terraform apply

Destroying the DO definitions

To remove the DO-created configuration you applied in the previous procedure, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Enter the following command:

    terraform destroy -auto-approve
