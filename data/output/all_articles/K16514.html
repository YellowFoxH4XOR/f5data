Known Issue

Disabling and re-enabling the primary blade on an Active failover status VIPRION may cause a failover event if a high-availability (HA) group is configured.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP VIPRION with multiple blades installed.
  • You have configured the BIG-IP system as a peer in a device group.
  • You have configured the BIG-IP system to use the HA group feature.
  • The HA group score is weighted equally among all peer members in a device group.
  • You disable and then reenable the primary blade on the Active failover status member in a traffic group.

Impact

Possible failover due to HA group score re-calculation.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A failover event occurs after you disable and re-enable the primary blade on an Active failover status VIPRION.

Workaround

To work around this issue, you can fail over the BIG-IP system by disabling all of the blades on the Active failover status system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will cause the BIG-IP system to fail over to the peer device, and you should perform this procedure during a maintenance window.

  1. Log in to the Configuration utility of the Active status BIG-IP system.
  2. Navigate to System > Clusters > Properties.
  3. Select the check mark symbol under Cluster Members to select all blades.
  4. Select the Disable/Yield button.
