Description

This article provides you with a checklist of actions that can help you troubleshoot common issues on F5 hardware.

Environment

  • Standard series
  • iSeries
  • VIPRION
  • rSeries
  • VELOS
  • BIG-IQ

Cause

F5 Hardware is not performing as expected

Recommended Actions

  1. Check that you don't have the incorrect PSU for the system The size and shape of the three AC power supplies (PSUs) are the same for iSeries and rSeries platforms. You need to verify the correct power supply designed for your specific iSeries or rSeries platform model prior to its installation into the device. For more information and images of the PSUs refer to the following article:
    • K36588206: AC power supply units for iSeries and rSeries platform models should not be interchanged
  2. Power on the host OS from the AOM menu If the system is powered on and the GUI and CLI are not accessible, it's possible that the host OS that runs F5 software needs to be powered on manually. You can do this with the AOM command menu. For more information refer to the following articles:
    • K14594: Accessing the AOM Command Menu
    • K19230226: Turn off or turn on a VELOS system using the AOM Command Menu
    • K000132560: rSeries appliance does not boot up, shows only AOM menu prompt on console
    For example you select P to power on the host OS: 
    AOM Command Menu:
    B --- Set console baud rate
    I --- Display platform information
    P --- Power on/off host subsystem
    R --- Reset host subsystem
    N --- Configure AOM network
    S --- Configure SSH Server
    A --- Reset AOM
    Q --- Quit menu and return to console
  3. Perform a full system power cycle after an upgrade After an upgrade, depending on the platform version being upgraded, in certain circumstances you will need to power cycle the F5 device to allow all processes to function correctly. Refer to the AOM instructions in the previous item to power off and power on your device.
  4. Confirm the baud rate for the console session You can access the command line of your F5 device through the serial console port. This is useful when network access to the system is not available; however, if you cannot access the system via the console, you must confirm the console settings on the F5 device match the settings in your terminal emulator (such as PuTTY) or console server. Typically, you should configure your workstation or console server with the default serial port settings unless you changed the defaults on the F5 system. For more information refer to the following articles:
    • K13885: Setting the baud rate of the serial console port
    • K000139070: Setting the baud rate of the VELOS system controller serial console port
    • K000139071: Setting the baud rate of the rSeries system serial console port
    • K7683: Connecting a serial terminal to a BIG-IP system
    • K000139067: Connecting to the serial console on the rSeries and VELOS
    If the the console settings match on each end and you're still not getting CLI output, try the following:
    1. Move the cable to another unit, hit enter a few times. Do you get a reply there? If not, try a new cable.
    2. Are you using a non-standard cable or a long unshielded cable? Try a different known working cable.
    3. If you're using a laptop with a USB to serial interface adapter, are the Device Manager/COMM settings correct in the Windows OS?
  5. Gather VELOS hardware information when there is no CLI access You can use the AOM Command Menu to gather additional information about the hardware if your VELOS system controllers and blades become unresponsive or fail to boot properly. For more information, refer to the following article:
    • K13428255: Get VELOS and rSeries hardware diagnostics when CLI access is not available
  6. Reseat the blade on a chassis-based F5 system Reseating the blade to ensure a good connection with the chassis is a great troubleshooting step. For more information refer to the following articles:
    • K14764: Troubleshooting possible hardware issues on the VIPRION backplane
    • K000138669: VELOS system controller unresponsive after upgrade
