K000157884: Inability to view or send emails via Outlook Web App (OWA) when the ASM policy is attached to the virtual service.

Description

This article addresses an issue where users were able to send and read emails when accessing Outlook Web App (OWA) through a BIG-IP virtual server with an ASM (Application Security Manager) policy enabled. Symptoms include:

 

→ Inability to view or send emails via OWA.

→ HTTP 449 status code for read and send email requests in the browser developer tool.

→ Application works normally when the ASM policy is removed.

→ The "X-OWA-CANARY" header in requests may contain the value "X-OWA-CANARY_cookie_is_null_or_empty".

 

Environment

* BIG-IP ASM 

* Virtual server configured for Outlook Web App (OWA) traffic

* ASM security policy in transparent mode and attached to the virtual server.

* OWA application requires correct handling of the custom HTTP header and cookie "X-OWA-CANARY"

 

Cause

The ASM policy was created with the fundamental template, and this policy did not properly support OWA’s requirements for the "X-OWA-CANARY" cookie and header. This resulted in the client failing to set the correct header value, causing the OWA server to return HTTP 449 errors and block access.

 

Recommended Actions

1. Create a new ASM policy using the "OWA Exchange 2016" template.

2. Map the new OWA-specific ASM policy to the affected virtual server.

3. Test OWA access to confirm that the "X-OWA-CANARY" header is correctly populated and email functionality is restored.

 

Additional Information

- The ASM policy in Transparent Mode does not block requests, but incorrect policy configuration can interfere with required header/cookie handling for OWA.

- The "X-OWA-CANARY" header and cookie must be correctly propagated between client and server for successful session validation in OWA.
