Known Issue

This is the result of a known issue. Allowing infinite reuse of HTTP connections prevents some connections from expiring. For example, by default the BIG-IP system does not limit the number of HTTP requests per connection. When a new profile is added or removed from a virtual server, the system clones the HTTP listener and the existing connections are allowed to expire. When the Maximum Requests setting is left at the default setting of 0 (zero), long-lived HTTP connections may persist indefinitely.

F5 Networks Product Development is tracking this issue as CR51406.

Workaround

To work around this issue, specify a value for the Maximum Requests setting in your HTTP profiles. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select HTTP from the Services menu.
  5. Click the appropriate HTTP profile.

    Note: F5 Networks does not recommend editing the default HTTP profile. Instead, you should create a child profile based on the default HTTP profile.

  6. Add a non-zero value to the Maximum Requests field.
  7. Click Update.
