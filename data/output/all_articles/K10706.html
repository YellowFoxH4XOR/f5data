Known Issue

This is the result of a known issue. When RAM Cache is in the process of collecting a document and the connection is aborted, and the document was previously evicted from the RAM Cache during collection, the document and associated entity held by the connection flow are not released from memory. This issue shrinks the effective size of the cache by the document size, which eventually causes the system to run out of memory and TMM to core.

F5 Product Development tracked this issue as ID 330903 (formerly CR127675) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, or WebAccelerator release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
