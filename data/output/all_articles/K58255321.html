Known Issue

The BIG-IP system may fail to warn about an invalid port lockdown setting for a self IP address the system uses in network failover.

If you use invalid port lockdown settings for a self IP address that the BIG-IP system uses for network failover, and if there is no other interface configured for network failover, then network failover fails. As a result, the peer systems in your configuration may change to an active-active HA state, which may cause network disruption.

Note: To ensure a more stable network failover configuration, F5 recommends that you configure HA network failover channels with both management and Traffic Management Microkernel (TMM) networks. In this configuration, if you misconfigure the self IP address, the management network should remain available for network failover and prevent your peer systems from changing to an unwanted active-active HA state. For more information, refer to K16049: Limiting network failover disruptions.

This issue occurs when all of the following conditions are met:

  • You configure network failover on two or more BIG-IP devices in a high availability (HA) configuration.
  • You use the Traffic Management Shell (tmsh) to configure the port lockdown settings of a self IP address configured for network failover with allow-service set to none or in a way that blocks the network failover port (UDP port 1026).

Impact

A misconfigured self IP address may lead to an unwanted active-active HA state, which causes network disruption.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system does not warn you when you use tmsh to modify the port lockdown setting to block the network failover port for a self IP address that the BIG-IP system uses for network failover.
  • Your network experiences disruption after you modify the port lockdown setting to block the network failover port of the self IP addresses that the BIG-IP system uses for network failover.
  • You notice that all of the members in a Sync-Failover device group report Active for all traffic-groups and Offline for all peers. The command syntax and output of the failover state on a device named BIGIP1.example.com may appear similar to the following example:

    tmsh list /cm device failover-state

    cm device BIGIP1.example.com {
    failover-state active
    }
    cm device BIGIP2.example.com {
    failover-state offline
    }

    Note: Although the failover state of the peer device is incorrect, configuration synchronization (ConfigSync) may work as expected.

Workaround

There is no workaround for this issue. To recover from the active-active HA state, you can reconfigure the port lockdown self IP address settings for each affected network failover BIG-IP system. To do so, perform one of the following procedures:

  • Modifying the port lockdown setting of the self IP address using the default option
  • Adding the network failover port (UDP port 1026) to the port lockdown setting of the self IP address

Modifying the port lockdown setting of the self IP address using the default option

Performing the following procedure enables the pre-defined default ports on the unicast network failover self IP address.

Impact of workaround: Port lockdown configuration depends on your network's application environment. F5 recommends that you use the port lockdown feature to allow only the protocols or services required for a self IP address. For more information, refer to K17333: Overview of port lockdown behavior (12.x - 13.x) or K13250: Overview of port lockdown behavior (10.x - 11.x), as appropriate for your BIG-IP version.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To modify the port lockdown settings of a self IP address to use the default option, use the following command syntax:

    modify /net self <self_IP> allow-service default

    For example, to modify the port lockdown setting to use the default option for self IP address 10.10.10.1, type the following command:

    modify /net self 10.10.10.1 allow-service default

  3. Save the change by typing the following command:

    save /sys config

Adding the network failover port (UDP port 1026) to the port lockdown setting of the self IP address

Performing the following procedure enables access to the UDP port 1026 of the unicast network failover self IP address in addition to the existing port lockdown setting.

Impact of workaround: Port lockdown configuration depends on your network's application environment. F5 recommends that you use the port lockdown feature to allow only the protocols or services required for a self IP address. For more information, refer to K17333: Overview of port lockdown behavior (12.x - 13.x) or K13250: Overview of port lockdown behavior (10.x - 11.x), as appropriate for your BIG-IP version.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To add the network failover port to the port lockdown setting of a self IP address, use the following command syntax:

    modify /net self <self_IP> allow-service add {<network_failover_port>}

    For example, to add the network failover port (UDP 1026) to the port lockdown setting for self IP address 10.10.10.1, type the following command:

    modify /net self 10.10.10.1 allow-service add {udp:1026}

  3. Save the change by typing the following command:

    save /sys config
