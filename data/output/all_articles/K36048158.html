Known Issue

Remote logging is incorrectly sent from a loopback network when the destination logging server matches the virtual server address.

This issue occurs when all of the following conditions are met:

  • You have configured a forwarding or transparent virtual server.
  • The destination for the remote logging server is the same as for the configured virtual server.

Impact

Remote logging may be dropped due to a source IP from a non-routable network.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Remote logging traffic is sent from the loopback network (for example, 127.1.1.1).

Workaround

To work around this issue, you can create a separate transparent host virtual server that matches the remote logging destination with SNAT Auto Map enabled. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click Create.
  4. In the IP address box, specify the IP address for the remote logging destination.
  5. In the Destination Port box, specify the destination port.

    For example:

    514

  6. In the Type box, select Forwarding (IP).
  7. If required, in the Protocol Profile (Client) box, select the appropriate custom protocol profile.

    The default is fastL4.

  8. In the Source Address Translation box, select Auto Map.
  9. Select Finished.
