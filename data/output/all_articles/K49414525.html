K49414525: Web Application Security Policy Parameter Name may report Duplicate unexpectedly during creation

Description
When creating a new Parameter for a Web Application Security Policy in BIG-IQ, the Parameter Name may unexpectedly report "Duplicate" as an error and prevent the new Parameter from being created. This is working as designed and typically indicates further configuration is needed before the Parameter can be created.

Environment

  • BIG-IQ 5.0.0 and later
  • WAS (Web Application Security) and BIG-IP with ASM

Cause
In both WAS and ASM, each Security Policy can have a number of Parameters, each with a unique, non-duplicate name. The name of the Parameter is the value the policy looks for in parameters when parsing data. There are two levels to Parameters: Global (looking at all parameters in payload) and URL (looking at parameters for a specific URL). The URL-level parameters can then be broken into HTTP and HTTPS protocol categories, for a total of three potential "types" of parameters.

The same Parameter Name can be used in each of the different types, however the Parameter Name must be unique within each type.

Depending on the Security Policy's global settings, it may or may not differentiate between HTTP and HTTPS URLs. If it differentiates between them then URLs must be assigned to HTTP or HTTPS types (with the same URL allowed in both types). If the policy does not differentiate then URLs are given a single type and apply to both HTTP and HTTPS protocol. In an undifferentiated policy there is only one type of URL-level parameter, consequently two potential types (global and URL). Since the Parameter Names must be unique per type, a differentiated policy can have three types and three different instances of the same Parameter Name while an undifferentiated policy has only two.

BIG-IQ provided the ability to scan fields during configuration creation on-the-fly and determine if a selected value violates a constraint, like the uniqueness of the Parameter Name field. If during creation of a Parameter, the Parameter Name field is filled out before the Parameter Level field, BIG-IQ can report a duplicate Parameter name if that name already exists for the default Parameter Level. This error is correctly raised and will resolve if the Parameter Level is then subsequently changed to something else.

Recommended Actions

  1. When creating a new Parameter, set the Parameter Level field to the desired value before entering the Parameter Name.

Additional Information
If the Parameter Name is set prior to the Parameter Level field and raises a Duplicate Name alert, simply set the Parameter Level field to appropriate unique values and the issue will resolve. If it does not, cancel the new Parameter configuration and review all existing Parameters for the Security Policy to ensure the Parameters are configured as desired.
