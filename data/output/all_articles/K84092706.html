Description
  • TLS Handshake fails with "Alert Fatal" error, despite matching ECDHE existing ciphers between client and  SSL client profile
  • "No shared ciphers between SSL peers"   is logged  in /var/log/ltm
Environment
  • BIG-IP LTM
  • Version prior to 12.1.3
  • SSL/TLS
  • ECDHE ciphers only
Cause
CLIENT_HELLO handshake  does not contain Elliptic Curves nor Points Format extensions. The affected versions do not correctly process this case.

Impact:
If there are no elliptic curves nor ec points to use, the BIG-IP avoids using ECDHE ciphers (this is by design), and rejects the TLS connection with an "Alert/Fatal" error because there are no other ciphers to choose from.
 
Recommended Actions
Upgrade to version 12.1.3 or later.

Additional Information
  • Bug ID 623940: SSL Handshake fails if client tries to negotiate EC ciphers but does not present ec_point_formats extension in ClientHello
     
  • Elliptic Curves and Points format are described in RFC 4492:

    Note: The aforementioned RFC link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.
     
    "A TLS client that proposes ECC cipher suites in its ClientHello message SHOULD include these extensions.  Servers implementing ECC cipher suites MUST support these extensions, and when a client uses these extensions, servers MUST NOT negotiate the use of an ECC cipher suite unless they can complete the handshake while respecting the choice of curves and compression techniques specified by the client."
