Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP APM access policy is configured to perform authentication with an authentication, authorization, and accounting (AAA) server.
  • An authentication server or firewall requires a specific source IP address for received authentication packets.

Description

BIG-IP APM AAA server definitions do not allow you to specify the source IP address used for authentication packets, which may be inconvenient in an environment with strict firewall rules and situations where authentication can require a specific source address in the IP header (such as with RSA SecurID and RADIUS). For example, when BIG-IP APM systems are configured for high availability (HA) and a failover occurs, the source IP address used for authentication packets changes to that of the newly active BIG-IP APM system. If the authentication server is not configured to use this new IP address, authentication fails.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the BIG-IP APM Configuration utility.

Procedures

To specify a source IP address to be used for authentication traffic, you must configure a secure network address translation (SNAT) pool with the IP address to use as the source IP address, and then associate the SNAT pool with a layered virtual server to proxy traffic to the AAA server. To do so, perform the following procedures:

Note: The following changes must be synchronized across all BIG-IP APM systems in an HA configuration.

  • Creating a SNAT pool
  • Creating a layered virtual server

Creating a SNAT pool

To specify the source IP address your AAA server expects to receive authentication traffic from in a SNAT pool, perform the following procedure:

Note: The BIG-IP APM system can only use a SNAT pool that is in the default route domain.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Address Translation > SNAT Pool List.
  3. Click Create.
  4. In the Name box, type a name for your SNAT pool.   
  5. For Member List, in the IP Address box, type the address of the self IP your AAA server expects to see as the source IP address for authentication traffic.

    Note: For BIG-IP APM systems in an HA configuration, use a floating self IP address common to all HA members. 

  6. Click Add.
  7. Click Finished.

Creating a layered virtual server

To create a layered Forwarding (IP) type virtual server and associate the new SNAT pool, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click Create.
  4. In the Name box, type a name for your virtual server.
  5. In the Type list, click Forwarding (IP).
  6. In the Destination Address box, type the IP address of your AAA server.
  7. From the Service Port menu, enter the port for which your AAA server is configured to accept authentication traffic.
  8. In the Protocol list, click UDP.
  9. In the Source Address Translation list, click SNAT, and then in the SNAT Pool list, click the name of the SNAT pool you created in the previous procedure.
  10. Click Finished.
  11. Navigate to Local Traffic > Virtual Servers > Virtual Address List.
  12. Click the IP address of your AAA server.
  13. Clear the ARP check box.
  14. Click Update.
