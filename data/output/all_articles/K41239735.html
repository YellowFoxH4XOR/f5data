Known Issue

The BIG-IP system may fail to load a User Configuration Set (UCS) file created with the default admin and root accounts disabled.

This issue occurs when all of the following conditions are met:

  • You create a new administrative account (for example user1) on a BIG-IP system to replace the default admin and root accounts.
  • You perform one of the following actions:
    • You manually create a UCS file on a BIG-IP system and attempt to load the UCS configuration file for a system where the newly created administrative account does not exist, for example, on another BIG-IP system.
    • You perform a software upgrade, where the system would automatically create a UCS file to be loaded into the upgraded software volume as part of the upgrade process.

The systemauth.disablerootlogin system db key (which has a value of false, by default) and the systemauth.primaryadminuser system db key (which has a value of admin, by default) will determine whether the default root and admin accounts, respectively, have been disabled. For more information, refer to K15632: Disabling the admin and root accounts using the BIG-IP Configuration utility or the Traffic Management Shell.

Impact

The BIG-IP system fails to load the required configuration file. As a result, the system is unable to process any traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When the BIG-IP system attempts to load the UCS configuration file, you notice an error message in the /var/log/ltm file similar to the following example:

    loaddb[20786]: 01080023:3: Error return while getting reply from mcpd: 0x10718e6, 010718e6:3: The requested primary admin user (user1) must exist in local user database.

Workaround

To avoid this issue, when you attempt to load the affected UCS file onto another system, you can re-enable the default admin and root accounts on the original BIG-IP system before you manually create the UCS archive file to be restored to the BIG-IP system. If you are planning to perform a software upgrade on the original BIG-IP system, you should re-enable these accounts before performing the software upgrade. To do so, perform the following procedure:

Impact of workaround: Because the default accounts could have been disabled due to security reasons in your environment, F5 recommends that you carefully assess the security of your environment before you re-enable the default accounts.

  1. Log in to the Traffic Management shell (tmsh) by typing the following command:

    tmsh

  2. To re-enable the default root account, type the following command:

    modify /sys db systemauth.disablerootlogin value 'false'

  3. To re-enable the default admin account, type the following command:

    modify /sys db systemauth.primaryadminuser value 'admin'

  4. Save the changes by typing the following command:

    save /sys config

  5. You can now create a new UCS file for loading on another system. If you are attempting to perform a software upgrade, you can do so now.
  6. Optional: If you want to, you can disable the default admin and root accounts on the BIG-IP system after the BIG-IP configuration fully loads successfully. For more information, refer to K15632: Disabling the admin and root accounts using the BIG-IP Configuration utility or the Traffic Management Shell.
