Known Issue

This is the result of a known issue. The Linux kernel portion of the BIG-IP system incorrectly sends ARP requests with the incorrect source IP address of 127.0.0.1. This is a result of Linux optimization efforts with TMM. The default behavior of the ARP code will solicit responses with the same source IP address as the outgoing packet.

This issue is seen in rare situations in which a host with multiple IP address on multiple interfaces is able to send traffic on one interface with a source IP address that resides on a separate interface on the host. If the request is sent to BIND and no ARP entry exists for the source IP address, BIND will trigger an ARP request. The Linux kernel issues an ARP request with the same source IP address on which it received the packet (127.0.0.1).TMM proxies the request without changing the source IP address.

F5 Networks Product Development tracked this issue as CR70081 and CR70245, it was fixed in BIG-IP versions 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM or GTM Release Notes.
