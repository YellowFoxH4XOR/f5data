Known Issue

The vCMP guest may not have the default boot volume set correctly.

This issue occurs when the following condition is met:

  • You initially created the vCMP guest with both a base software and a hotfix applied.
Note: You can create the vCMP guest with both a base software and a hotfix starting in vCMP guest 11.4.0.

Impact

After performing a software installation onto another software volume from within the vCMP guest, the vCMP guest will automatically mark the newly installed software volume as the default boot volume. As such, the vCMP guest may not boot into the intended software volume upon a system reboot.

Symptoms

As a result of this issue, you may encounter one of the following symptoms:

  • When you run the grub_default -d | grep 'default=' command on a vCMP guest with only the default software volume installed the command output may not display, which means that the default boot volume was not set. The vCMP guest should still boot into HD1.1 because it is the only software volume available.

    For example:

    [root@bigip:Active:Standalone] ~ # grub_default -d | grep 'default='
    [root@bigip:Active:Standalone] ~ #

    The correct command output should display similar to the following example:

    [root@bigip:Active:Standalone] ~ # grub_default -d | grep 'default='
    default=0

    A default value of 0 in the previous example indicates the first entry of the kernel configuration for the BIG-IP system to boot up with. In this case, software volume HD1.1 has been set as the default boot volume.
  • After performing a software installation onto another software volume (HD1.2) from within the vCMP guest, the newly installed software volume may not be automatically set as the default boot volume. When you run the grub_default -d | grep 'default=' command, you will view command output that appears similar to the following example:

    [root@bigip:Active:Standalone] ~ # grub_default -d | grep 'default='
    default=1

    A default value of 1 indicates the second entry of the kernel configuration for the BIG-IP system to boot up with. In this case, the second entry, which refers to the newly installed software volume HD1.2, has been set as the default boot volume.

Workaround

To work around this issue, you can define the default boot volume using the switchboot utility on the vCMP guest. To do so, perform the following procedure:

Impact of workaround: If the selected boot volume is not the currently active volume, running the switchboot utility may result in an immediate system reboot of the vCMP guest to the alternate boot volume. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IP command line.
  2. Define the desired default boot volume using the following command syntax:

    switchboot -b <desired_boot_volume>

    For example, to define HD1.1 as the desired default boot volume, type the following command:

    switchboot -b HD1.1
