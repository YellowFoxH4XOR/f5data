Description

In some cases, an HTTPS redirect generated by a BIG-IP LTM policy can be returned without the Strict-Transport-Security header, even when HSTS insertion is configured. This is commonly seen when redirect logic is handled locally on BIG-IP and not by the backend application response path.

Environment

  • BIG-IP LTM

Cause

When a policy uses http-reply redirect, BIG-IP generates a local response. In this flow, response-time header insertion is not always applied as expected, and an iRule HTTP_RESPONSE event may not run because there is no backend response. As a result, the redirect can be sent without HSTS even though HSTS logic exists in policy or iRule configuration.

Recommended Actions

Use a single redirect mechanism that inserts HSTS in the same locally-generated response. The most reliable approach is to generate the redirect with HTTP::respond in an iRule and include both the Location and Strict-Transport-Security headers in that same response. Avoid overlapping policy and iRule redirect logic for the same request path to prevent conflicting local responses and runtime errors.

HTTP::respond 302 -version auto noserver "Location" "https:////" "Strict-Transport-Security" "max-age=; includeSubDomains" "Content-Length" 0

As an alternative, allow the backend application to generate the redirect and include HSTS directly in the backend response.

Additional Information

This behavior is specific to local response handling and is different from normal backend response header insertion behavior.
