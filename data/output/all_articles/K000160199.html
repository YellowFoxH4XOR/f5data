Description

As part of every BIG-IP TMOS firmware release, we include a bundle of Certificate Authorities (CAs), both root and intermediate, for trusted public CAs commonly used to sign certificates. This article outlines some of the steps we use to create, select, and update these bundles.

Environment

For a given BIG-IP Firmware release, the relevant CA bundles are:

  • ca-bundle.crt - The provided bundle that is pre-defined and released with each ISO image we provide.
    • File location: /config/ssl/ssl.crt/
  • blended-bundle.crt - These are incremental CA bundle updates that can be downloaded from F5 outside of an ISO release.  This is also used during a firmware release cycle to create the ca-bundle.crt file for the next upcoming release. 

Cause

None

Answer/Recommended Actions

F5 monitors and updates the 'blended_bundle.crt' approximately every 30 days. This process has several steps:  

Root Certificates: (CA)

  • Sourced from Microsoft and Mozilla. Lists are combined and sorted to remove duplication.   

Intermediate Certificates: 

  • A curated list of websites is formed from publicly available lists of top websites. 
  • Intermediate certificates are fetched by connecting to each website individually, retrieving AIA (Authority Information Access X.509 extension) information from the server certificate for each website.
  • The resulting list is sorted to remove duplication, expired certificates, and any "non-CA" related certificates.

Creating the bundles:

  • The final lists from the root CA and intermediate CA validation are combined to form the "blended-bundle.crt" file.
  • The blended-bundle.crt continues to be evaluated and updated approximately every 30 days. 
  • Upon release of a new BIG-IP TMOS Firmware release, we pull from the latest available blended-bundle.crt, and provide it as the ca-bundle.crt file with the new release.

Additional Information

Please review the "Related Content" field for articles on how to maintain and update the provided ca-bundle.crt file.   These files can also be modified and customized based on your environment to include internal or trusted PKI infrastructure unique to your environment.   

NOTE:  Custom modification of the ca-bundle is 'not' updated during an upgrade, while a custom-named file you created is retained and continues to be used, it will not be updated with 'new' information from the default ca-bundle.crt file provided with the updated release. You must modify the file manually after upgrading to update your custom file. If you modified the existing 'ca-bundle.crt', it may be overwritten with the updated 'default' file upon upgrade.
