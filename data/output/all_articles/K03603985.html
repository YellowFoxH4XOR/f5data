Topic

You should consider using this procedure under the following condition:

  • You want to install NGINX Controller on your Linux device.
  • Your Linux device has insufficient storage resources on the /var partition.
  • Your Linux device has sufficient storage resources located in a different partition.

Description

Installing NGINX Controller requires a minimum of 15 G of storage space on the /var partition of the Linux device. If you attempt to install Docker and kubelet resources for an NGINX Controller installation with insufficient storage resources on the /var partition of the Linux device, the installation will fail.

If your Linux device has sufficient storage resources located on an alternate partition, you can create two directories that reside in the partition and use the Linux ln command to create a symbolic link to the new directories using the required directory path of NGINX Controller.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Administrative (root or have the ability to use sudo) access to the command line of the Linux device.
  • A general familiarity with the Linux commands df, mkdir, and ln.

Procedures

  • Determine the available storage resources of the Linux device
  • Create the destination installation directories for Docker and kubelet
  • Create symbolic links to the installation-expected directories

Determine the available storage resources of the Linux device

Determine a destination partition for the Docker and kubelet installation of NGINX Controller using the Linux df command.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log on to the command line of the Linux device.
  2. To view storage use, enter the following command:

    df -ht ext4

  3. Determine a partition on the Linux device that has greater than 15 GB available.

    Example output:

    Filesystem      Size  Used Avail Use% Mounted on
    /dev/sda1        28G  4.3G   22G  17% /
    /dev/sda6        95G   14G   76G  16% /home
    /dev/sda7        100G   10G   90G  10% /apps

    Note: In the Avail column, locate a partition with greater than 15 G and note the Mounted on name.

    Note: In this example, the Avail column with the greatest amount of available storage is the /apps partition with 90 G available.

Create the destination installation directories for Docker and kubelet

Once you identify a partition with sufficient storage resources, create the NGINX Controller installation directories for Docker and kubelet in the partition using the Linux mkdir command.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Create the destination installation directories in the alternate installation partition using the following command syntax:

sudo mkdir /<partition>/docker

sudo mkdir /<partition>/kubelet

Note: Replace <partition> with the partition name identified in the previous procedure.

For example:

sudo mkdir /apps/docker
sudo mkdir /apps/kubelet

Create symbolic links to the installation-expected directories

After you create the destination installation directories for Docker and kubelet, use the Linux ln command to create a symbolic link to each directory using the expected directory path of NGINX Controller.

Impact of procedure: Performing the following procedure will direct the system to execute all file-related functions for files referenced in the /var/lib/docker and /var/lib/kubelet directories in the specified alternate directories.

Create symbolic links to the alternate installation directories with the expected installation directories for NGINX Controller using the following command syntax:

sudo ln -s <created directory name for docker> /var/lib/docker
sudo ln -s <created directory name for kubelet> /var/lib/kubelet

Note: Replace <created directory name> with the directory name you created in the alternate installation partition for each Docker and kubelet installation type.

For example:

sudo ln -s /apps/docker /var/lib//docker
sudo ln -s /apps/kubelet /var/lib/kubelet
