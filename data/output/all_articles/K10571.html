Known Issue

This is the result of a known issue. If you configure a network virtual server on an active-active high availability redundant system with ARP disabled for the virtual address, then change the unit ID of the virtual server, the virtual server will only listen on the unit corresponding to the newly-assigned unit ID until the configuration is reloaded.

Note: In an active-active high availability pair, a network virtual server whose virtual server address has ARP disabled is active on both units. As a result, both units will process traffic arriving for that virtual server, regardless of the configured Unit ID. This behavior is intentional, providing a highly-available path for network virtual server traffic in the event of failover. When ARP is disabled for the virtual server address, the standard method of notifying next-hop devices of a Layer 2 path change for the virtual server address (gratuitous ARP) is not available. Intentionally allowing both units to process traffic for this type of virtual server prevents outages upon failover.

For example, if you have an ARP-disabled network virtual server configured with the default Unit ID of 1, then log into Unit 1 and change the Unit ID for the virtual server to Unit 2, the virtual server will no longer listen on Unit 1 until its configuration is reloaded. As a result, traffic for that virtual server which is sent to Unit 1 by next-hop devices will be dropped until the configuration is reloaded, at which time the virtual server on Unit 1 will resume processing traffic.

F5 Product Development tracked this issue as ID 222912 (formerly CR125788) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

You can avoid this issue by not reassigning the Unit ID for a network virtual server whose virtual address is configured with ARP disabled.

You can work around this issue by reassigning the default Unit ID 1 to the virtual address on the affected device and reloading the configuration.
