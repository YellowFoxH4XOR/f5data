K000159907: APM guided config metadata deployment error

Applies to

Description

Deployment errors occur in BIG-IP APM when using APM Guided Configuration (AGC) if there are duplicate AGC deployment names that differ only by case (e.g., "App1" and "app1") or if the same virtual server/profile is assigned to multiple AGC deployments. These conflicts result in REST/MCP database inconsistencies, leading to errors such as "transaction failed:01070712:3: file:(...).crt cannot update (cert_type)", missing objects, and profile duplication. Additional errors may include "virtual server not found" or "duplicate profiles" during deployment modification.

Environment

  • APM Guided Configuration (AGC) deployments
  • Multiple AGC deployments with names differing only by case
  • Shared use of the same virtual server/profile across multiple AGC deployments

Cause

  • AGC deployment names are case-insensitive; "App1" and "app1" are considered duplicates.
  • Assigning the same virtual server/profile to multiple AGC deployments is not supported and will cause deployment failures.

Recommended Actions

  1. Remove or rename AGC deployments with conflicting names, ensuring all deployment names are unique regardless of case.
  2. Assign each virtual server/profile to only one AGC deployment.
  3. If errors persist, uninstall and reinstall the f5-iappslx-access-framework package to restore AGC functionality.
  4. If a deployment is broken, export its template, delete the problematic object, and re-import it with a new, unique name.
  5. After resolving conflicts, redeploy the AGC configuration.
