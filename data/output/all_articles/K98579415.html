Description

This article covers a Splunk timestamp recognition failure for two-digit years that will begin Jan 1, 2020.

The issue appears when you have configured the input source to automatically determine timestamps, and can result in one or more of the following problems:

  • Incorrect timestamping of incoming data
  • Incorrect rollover of data buckets due to the incorrect timestamping
  • Incorrect retention of data with incorrect timestamps
  • Incorrect search results due to data ingested with incorrect timestamps

This document describes the Splunk modification procedure required to support 2-digit format year timestamp.

Environment
This workaround is applicable to Splunk version 6.5.3 which is part of:

  • SDC 5.1 CF7 and above
  • SDC 4.4 CF22 and above
    CF = Cumulative Hotfix

Older SDC versions contain Splunk version 5.0.1 which doesn’t support this fix.
In case it is needed, SDC product will have to be upgraded to a supported version as stated above.

Cause
The Splunk platform input processor uses a file called datetime.xml to help the processor correctly determine timestamps based on incoming data. The file uses regular expressions to extract many different types of dates and timestamps from incoming data.
 
On un-patched Splunk platform instances, the file supports the extraction of two-digit years of "19", that is, up to December 31, 2019. Beginning on January 1, 2020, these un-patched instances will mistakenly treat incoming data as having an invalid timestamp year, and could either add timestamps using the current year, or misinterpret the date incorrectly and add a timestamp with the misinterpreted date.
 
Please find the following reference from Splunk’s portal:
Timestamp recognition of dates with two-digit years fails beginning January 1, 2020

Recommended Actions

Preface
Procedure will modify Splunk configuration on Master Splunk (EMS) and
Splunk Forward agent (SDC).
There are 2 ways to execute this procedure:

  1. Modify existing datetime.xml file on your Splunk platform instances.
  2. Use the updated datetime.xml version attached in item 3 below.
Estimated Time
  • No Traffic impact on SDC, however viewing statistics on EMS may unavailable during the service restart
  • The procedure should take up to 30 minutes to complete
  • Only Splunk restart is required, therefore can be done daytime


In general, to patch the system, Download an updated version of datetime.xml and apply it to each of your Splunk platform instances by replacing the existing datetime.xml file in the following EMS & SDC folders:

/opt/splunk/etc
/opt/splunkmaster/splunk/etc
/opt/splunksearch/splunk/etc
/opt/splunkforwarder/etc

And on the following SDC folder as well:

/opt/splunkforwarder/etc/

Once done, a Splunk services restart is required.
 

Modification using pre edited “datetime.xml” file
Restart Splunk service

Modification using pre edited “datetime.xml” file
Make a backup copy of datetime.xml file:

EMS:

  1. Splunk master
    #cd /opt/splunkmaster/splunk/etc
    #cp datetime.xml datetime.xml.bkp

  2. Splunk indexer
    #cd /opt/splunk/etc
    #cp datetime.xml datetime.xml.bkp

  3. Splunk search
    #cd /opt/splunksearch/splunk/etc
    #cp datetime.xml datetime.xml.bkp

  4. Splunk forwarder
    #cd /opt/splunkforwarder/etc
    #cp datetime.xml datetime.xml.bkp

SDC:
  1. Splunk forwarder
    #cd /opt/splunkforwarder/etc/
    #cp datetime.xml datetime.xml.bkp
Extract the attached file and copy “datetime.xml” file to the following folders:

Restart Splunk service

  • In SDC 5.1

    • Login to individual nodes in EMS and run “monit summary”, take note the process name for splunk master, splunk indexer, splunk search and splunk forwarder. And use the following syntax to restart all the services;
      Example:
      #monit restart EMS01_splunkmaster  

    • Login to individual nodes in SDC and run “monit summary”, take note the process name for splunk forwarder and restart the service as mentioned above.  

  • In SDC 4.4

    • Login to any one of the EMS node and run “crm_mon -1r”, take note the splunk cluster resource, splunk forwarder resource and splunk indexer clone . Restart the service as follows.
      Example:
      #crm resource restart traffix_splunk_cluster-grp

    • Login to any one of the SDC node and run “crm_mon -1r”, take note the splunk forwarder resource name, Restart the service as mentioned above.


Additional Information

Manual change

We recommend to avoid executing a manual change, however, if you have no other option the following are the changes to be made in the “datetime.xml” file. 
Important: Manually editing configuration files is not supported by F5 Support and is done at your own risk.
Note: Please don’t copy paste from this document to Linux system. This may cause character formatting.  Files in all the folders mentioned in the above section need to be edited. Backup the files before editing and restart Splunk instances once complete.

Search for and replace the following strings, according to this table:
Search for this stringReplace with this string
<text><![CDATA[(20\d\d|19\d\d|[901]\d(?!\d))]]></text><text><![CDATA[(20\d\d|19\d\d|[9012]\d(?!\d))]]></text>
<text><![CDATA[(?:^|source::).*?(?<!\d|\d\.|-)(?:20)?([901]\d)(0\d|1[012])([012]\d|3[01])(?!\d|-| {2,})]]></text><text><![CDATA[(?:^|source::).*?(?<!\d|\d\.|-)(?:20)?([9012]\d)(0\d|1[012])([012]\d|3[01])(?!\d|-| {2,})]]></text>
<text><![CDATA[(?:^|source::).*?(?<!\d|\d\.)(0\d|1[012])([012]\d|3[01])(?:20)?([901]\d)(?!\d| {2,})]]></text><text><![CDATA[(?:^|source::).*?(?<!\d|\d\.)(0\d|1[012])([012]\d|3[01])(?:20)?([9012]\d)(?!\d| {2,})]]></text>
