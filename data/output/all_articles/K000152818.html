K000152818: F5OS VELOS Partition GUI Session Termination Due to Time Desynchronization

Type

Published

Description

On F5OS VELOS platforms, accessing the partition GUI may result in unexpected session terminations and logouts, displaying errors such as:

User Session Terminated
User Session Terminated. You will be logged out of the appliance.

This occurs even when SSH access to controllers and partitions remains stable and no obvious errors are present in system logs.

In the velos logs from platform-mgr you can see the progressive time synchronization between the controllers and the blades (diff=):

velos.log:2025-07-14T21:38:44.613236+03:00 <partition-name> platform-mgr[12]: nodename=blade-1(p1) priority="Info" version=1.0 msgid=0x104000000000014 msg="LOP RTC updated." diff=-34.
velos.log:2025-07-14T21:38:51.583158+03:00 <partition-name> platform-mgr[12]: nodename=blade-2(p1) priority="Info" version=1.0 msgid=0x104000000000014 msg="LOP RTC updated." diff=-22.
velos.log:2025-07-14T21:39:06.065366+03:00 <partition-name> platform-mgr[12]: nodename=blade-3(p1) priority="Info" version=1.0 msgid=0x104000000000014 msg="LOP RTC updated." diff=-14.

Environment

  • Product: F5OS - Chassis (VELOS)
  • Platform: F5-VEL-CX410-AC, F101
  • Software Version: F5OS 1.8.1 (and other F5OS-C versions)
  • Configuration: NTP configured on system controller; partition GUI accessed via web browser

Cause

Partition GUI session instability is caused by significant time desynchronization between the system controller and partition/blade hardware clocks. When NTP is newly configured or changed, the system uses a gradual time slewing process (via chronyd/platform-mgr) to synchronize clocks. If there is a large initial time difference, this process can take many hours or days. During this period, session/token validation fails due to clock mismatches, resulting in repeated GUI logouts.

Recommended Actions

  • Before enabling or changing NTP configuration, ensure that the system controller and all blades/partitions have closely synchronized clocks to minimize required adjustment.
  • After configuring NTP, allow sufficient time for gradual synchronization—this is by design to avoid abrupt changes that could disrupt services.
  • To check current NTP status and synchronization:
    show system ntp
  • If urgent synchronization is needed (for example, if GUI access must be restored immediately), advanced users may SSH into each blade and run:
    chronyc makestep 0.1 -1

Important: Forcing a time step can disrupt running applications/services; use with caution and avoid on production systems if possible.
