Description

This issue happens after upgrading the BIG-IP to version 12.0.0.0 and above.

When you get "Malformed HTTP header error" the BIG-IP will also reset the connection.

Environment
  • Before upgrade: BIG-IP v11.x or lower
  • After upgrade: BIG-IP v12.x or higher
  • HTTP in use
  • HTTP request or response which does not conform to to RFC 7230
  • Getting message "Malformed HTTP header error" and the connection will be reset

Cause

Beginning BIG-IP 12.0.0 HTTP profile enforces strict header checks. HTTP request or response that does not conform to RFC 7230, will be considered a malformed HTTP header and the BIG-IP system will reset the connection.

You can read further on this here K38905534.

Recommended Actions

The workaround to this is to change your current http profile to http transparent profile.
  1. Login to the BIG-IP Configuration Terminal.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click on the Virtual Server which is having the issue.
  4. Under HTTP Profile, select http-transparent.
  5. Click Update.
Important: If you need to modify the http-transparent profile, create a new HTTP profile where the Parent Profile is http-transparent. Use this newly created http-transparent instead.

Additional Information

The HTTP profile provides three proxy modes: Reverse, Explicit, and Transparent. You can configure a custom HTTP profile that uses a specific proxy mode, and assign the custom HTTP profile to a virtual server to manage proxying of HTTP traffic, as necessary.

The Transparent Proxy Mode enables the BIG-IP system to forward invalid HTTP traffic to a specified server, instead of dropping the connection. By configuring an HTTP profile to forward invalid HTTP traffic, you can manage various atypical service provider scenarios, such as HTTP traffic from non-browser clients that function as web browsers.
