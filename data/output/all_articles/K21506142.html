Description

The VPN users are required to re-authenticate when the IP address of the client device changes while connected to VPN. 

Environment

  • APM
  • VPN
  • ISP reassignment / IP changes

Cause

The user is authenticated and connected to the VPN, but the IP address changes (perhaps due to a policy of the ISP), and the VPN tunnel does not re-establish automatically.

The following APM logs can be seen for the session:
Jan 1 12:00:00 bigip.local notice tmm1[12345]: 01490545:5: abcd1234: User session was terminated due to IP address change during session.
Jan 1 12:00:00 bigip.local notice tmm[12345]: 01490567:5: /Common/VPN_access_profile:Common:abcd1234: Session deleted (security_check).

This is due to the option being enabled that binds a session to a single IP address.

Recommended Actions

  1. Navigate to :
    Access >> Profiles / Policies >> Access Profiles (Per-Session Policies) and click on the Access Profile name, for which this VPN applies.
  2. Locate the line "Restrict to a single IP" and remove the checkbox. If the checkbox is locked, ensure that the checkbox on the far right of the line is enabled.
  3. Click Update to save changes.
  4. Click Apply Access Policy in the top left corner of the screen.
