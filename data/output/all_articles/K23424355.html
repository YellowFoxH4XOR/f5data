Description

BIG-IP DNS/GTM fails to load bigip_gtm.conf after upgrade

  • Offline:Standalone prompt after upgrade
  • Log file /var/log/ltm contain errors similar to:
    err mcpd[8170]: 01070726:3: Pool [pool name] in partition [auth user partition 1] cannot reference GTM wideip pool member [cname pool member] in partition [auth user partition 2]
    err tmsh[10120]: 01420006:3: Loading configuration process failed.
    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all gtm-only" - failed
    err mcpd[8170]: 01070678:3: Full gtm configuration load failed ( Original )

Environment

  • static target string as cname pool member has same name as wideip
  • static target string as cname pool member created before same name as wideip

Cause

When static target string as cname pool member has same name as wideip created after a conflict is created that will show up when the config is loaded and can also break upgrades.  This is due to Bug ID 987709.

Recommended Actions

The issue can be worked around by removing the conflicting static target cname pool members and then re-adding them after upgrade.
