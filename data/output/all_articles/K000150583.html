K000150583: BIG-IP PEM doesn't send a CCR-I to the OCS when both Gx and Gy endpoints are configured

Description

In Big-IP PEM, when both the Gx and Gy sessions are configured for a subscriber. The BIG-IP PEM can be configured to dynamically detect the subscriber based on the Radius traffic. Once a dynamic subscriber is detected, PEM creates a local session and sends a request for the subscriber policy configuration to the PCRF server. The BIG-IP PEM does this by sending a diameter CCR-I to the PCRF, and expects the CCA-I response.

Environment

BIG-IP PEM

 

Cause

In the response from the PCRF to enable quota management ( Gy session ), the PCRF needs to include the Online AVP and set the value to "ENABLE_ONLINE". Once this is received from PEM, if a default rating group, or a specific rating group is configured for one of the policy assigned to the subscriber, BIG-IP will initiate a Gy session towards the OCS.

The AVP Online can be provided at command level or at the charging-Rule-Definition level. If provided at command level, and set to ENABLE_ONLINE, then PEM will do quota management for all of the associated PCC rules. If provided at Charging-Rule_Definition level, then PEM will do quota management for that specific rule.

 

Recommended Actions

Ensure that the PCRF includes the "Online" AVP in it's CCA-i response and that the value is set to 1 (ENABLE_ONLINE).
