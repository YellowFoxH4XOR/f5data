Issue

You should consider using these procedures under the following conditions:

  • You have multiple BIG-IP systems in a high availability (HA) configuration.
  • You have enabled connection mirroring on the BIG-IP systems.
  • Your BIG-IP systems are failing to process established connections during a failover event.

Symptoms

As a result of an HA failover event, you may encounter the following symptom:

  • The newly active BIG-IP system fails to process connections.

Recommended Actions

Connection mirroring is designed to be used between identical BIG-IP platforms with identical configurations. Connection mirroring issues typically involve a simple misconfiguration of the BIG-IP system or local network. Before you troubleshoot a connection mirroring issue, review and ensure that the following connection mirroring requirements are met:

BIG-IP hardware

  • Connection mirroring will only function between identical hardware platforms.
  • VLANs used for the mirroring channel must have the same name on all of the BIG-IP devices.
  • VLANs used for the default gateway for data mirroring must have the same name on all of the BIG-IP devices.
  • VIPRION systems must change the default mirroring option from Within Cluster to Between Clusters. 

BIG-IP Virtual Edition (VE)

  • The VE hypervisor (host) systems must be identical to support mirroring.
  • VE systems must have the same number of Traffic Management Microkernels (TMMs).
  • VLANs used for the mirroring channel must have the same name on all BIG-IP instances.

Note: Due to a known issue, the VE hypervisor host systems must run the same software version to support mirroring. For more information, refer to Bug ID 629787.

BIG-IP Virtual Clustered Multiprocessing (vCMP)

  • The vCMP hypervisor (host) systems must be identical to support mirroring.
  • Guests must change the default mirroring option from Within Cluster to Between Clusters.
  • Guests must have the same number of Cores Per Guest.
  • VLANs used for the mirror channel must have the same name on all guests.
  • VIPRION guests must have the same Cores Per Slots, Minimum Number of Slots, and Number of Slots configured.  
  • VIPRION guests must be configured to use the same Slot ID on their respective VIPRION hosts. 

BIG-IP F5OS tenants

  • The F5OS appliance or VELOS systems must be identical to support mirroring.
  • VELOS tenants must change the default mirroring option from Within Cluster to Between Clusters.
  • Tenants must have the same number of vCPUs.
  • VLANs used for the mirror channel must have the same name on all tenants.
  • VELOS tenants must have the same vCPUs Per Slot, Memory Per Slot and Allowed Slots configured.  
  • VELOS tenants must be configured to use the same Slots (nodes) on their respective VELOS partitions. 

General networking

  • Each BIG-IP system in the HA configuration must be reachable by hosts on both the client and server sides of the mirrored connection. 
  • You must allow TCP connectivity between all BIG-IP systems in the HA configuration for the following service ports: 1029-1055.

After you have reviewed and ensured that these basic mirroring requirements are met, continue with the troubleshooting steps in the following section.

Procedures

You can use the following troubleshooting steps to determine the root cause of, and resolve, connection mirroring issues.

  • Verifying the traffic groups
  • Verifying the HA mirror status
  • Verifying the mirror IP addresses
  • Verifying the virtual server or SNAT mirror setting
  • Verifying TCP connectivity between BIG-IP systems
  • Verifying the mirrored connections

Verifying the traffic groups

Traffic groups represent collections of shared objects such as virtual servers and secure network address translations (SNATs). BIG-IP systems can belong to multiple traffic groups. When a BIG-IP system is active for a particular traffic group, the system will process traffic for that set of shared objects. To determine the number of traffic groups and the HA status of the BIG-IP systems in each traffic group, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. View the configured traffic groups and the BIG-IP system HA status by entering the following command:

    show cm traffic-group

    The following example shows a single traffic group and the HA status (active or standby) of the BIG-IP systems:

    traffic-group-1           one.example.net  active   false
    traffic-group-1           two.example.net  standby  true

Verifying the HA mirror status

Beginning in BIG-IP 12.0.0, the tmsh show sys ha-mirror command was added to better determine the status of the HA mirroring channel. To determine the current status of the HA mirroring channel, perform the following procedure: 

Note: The BIG-IP system creates a separate mirroring channel for each traffic group. For more information on number of traffic group supported, refer to K41291441: The BIG-IP system allows up to 127 traffic groups for a Sync-Failover device group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

    • Verifying the mirroring IP addresses

  4. If the mirroring channels are in the connected state, but you are still experiencing mirroring issues, review the following procedure:
    • Verifying the virtual server or SNAT mirror setting

Note: If you find large number of aborts or overflows, this would typically mean that the HA channel is suffering to mirror all the connections due to drops on the mirroring link or slowness or other network issue affecting the link. In some cases the sys db statemirror.queuelen value can be increased to accomodate for delays in mirroring channel, however if the overflows are higher than normal then the best action is to make sure the mirroring link is sufficient to mirror all traffic without any drops or latency.

Verifying the mirroring IP addresses

The BIG-IP systems must have at least one mirroring IP address defined; however, F5 recommends that you define both Primary and Secondary mirroring IP addresses. To verify that the mirroring IP addresses have been defined, or to define them if they are not defined, perform the following procedure:

Impact of procedure: Performing steps 1 and 2 should not have a negative impact on your system. Performing step 3 may increase CPU if the mirroring channel becomes connected.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. View the BIG-IP system's mirroring IP addresses by entering the following command:

    show cm device | grep -E 'Device:|Mirror'

    Mirroring IP                    ::
    Mirroring Secondary IP          ::

    In the following example, the Primary and Secondary mirroring IP addresses for the BIG-IP systems have been defined, as indicated by the IP address entries:

    CentMgmt::Device: one.example.net
    Mirroring IP                    192.168.10.1
    Mirroring Secondary IP          192.168.20.1
    CentMgmt::Device: two.example.net
    Mirroring IP                    192.168.10.2
    Mirroring Secondary IP          192.168.20.2

  3. If the BIG-IP systems have no mirroring IP addresses defined, review and perform the Choosing a VLAN for mirroring traffic and Configuring mirroring IP addresses procedures in K13478: Overview of connection and persistence mirroring (11.x - 12.x).
  4. After the mirroring IP addresses have been defined on all BIG-IP systems in the HA configuration, review the Verifying the HA mirror status procedure.

Verifying the virtual server or SNAT mirror setting

Even when the mirroring channel has reached the connected state, mirroring will not occur until the mirroring option for the virtual server or SNAT has also been enabled. To verify if mirroring has been enabled for the virtual server or SNAT, perform the following procedure.

Impact of procedure: Performing steps 1 and 2 should not have a negative impact on your system. Performing steps 3 and 4 may increase CPU if the mirroring channel begins transmitting connection-related data between the BIG-IP systems.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. View the mirror option for a virtual server by using the following command syntax:

    list ltm virtual <name> mirror

    For example, to view the mirror option for a virtual server named example, enter the following command:

    list ltm virtual example mirror

    In the following example, the mirror option for the virtual server named example is disabled:

    ltm virtual example {
        mirror disabled
    }

  3. Enable the mirror option for a virtual server by using the following command syntax:

    modify ltm virtual <name> mirror enabled

    For example, to enable the mirror option for a virtual server named example, enter the following command:

    modify ltm virtual example mirror enabled

  4. View the mirror option for a SNAT by using the following command syntax:

    list ltm snat <name> mirror

    For example, to view the mirror option for a SNAT named example, enter the following command:

    list ltm snat example mirror

    In the following example, the mirror option for a SNAT named example is disabled:

    ltm snat example {
        mirror disabled
    }

  5. Enable the mirror option for a SNAT by using the following command syntax:

    modify ltm snat <name> mirror enabled

    For example, to enable the mirror option for a SNAT named example, enter the following command:

    modify ltm snat example mirror enabled

  6. Save the configuration by entering the following command:

    save sys config

Verifying TCP connectivity between BIG-IP systems

BIG-IP systems create a separate mirroring channel for each traffic group. Each mirroring channel is a TCP connection, beginning with port 1029 and ending with port 1055. You must configure the BIG-IP system Port Lockdown feature to allow connectivity to these ports. The Port Lockdown setting of Allow Default allows connectivity to these ports. The local network must be configured to allow TCP connectivity to ports 1029-1055, as well. You can use the following procedure to verify TCP connectivity between the BIG-IP systems.

Note: For more information on number of traffic group supported, refer to K41291441: The BIG-IP system allows up to 127 traffic groups for a Sync-Failover device group.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. Verify TCP connectivity between the BIG-IP systems by using the following command syntax:

    Note: The tcpdump command syntax limits the number of packets captured, to ten.

    tcpdump -ni 0.0 port <mirror port> and 'tcp[13] == 16' -n -c10

    For example, to verify TCP connectivity for the first mirror channel, 1029, enter the following command:

    tcpdump -ni 0.0 port 1029 and 'tcp[13] == 16' -n -c10

    In the following example, both BIG-IP systems in the HA configuration are acknowledging (ack) data received on the first mirror port, 1029:

    IP 192.168.20.2.32774 > 192.168.20.1.1029: Flags [.], ack 2326423492
    IP 192.168.10.2.32774 > 192.168.10.1.1029: Flags [.], ack 3216266448
    IP 192.168.20.1.1029 > 192.168.20.2.32772: Flags [.], ack 3618464177
    IP 192.168.10.1.1029 > 192.168.10.2.32772: Flags [.], ack 702547717
    IP 192.168.20.1.1029 > 192.168.20.2.32775: Flags [.], ack 2419239043
    IP 192.168.10.1.1029 > 192.168.10.2.32775: Flags [.], ack 4048480197
    IP 192.168.20.2.32773 > 192.168.20.1.1029: Flags [.], ack 3419625175
    IP 192.168.10.2.32773 > 192.168.10.1.1029: Flags [.], ack 2320267320
    IP 192.168.20.1.1029 > 192.168.20.2.32774: Flags [.], ack 9
    IP 192.168.10.2.32774 > 192.168.10.1.1029: Flags [.], ack 10

    If the BIG-IP systems are not acknowledging (ack) received data on the mirror channel, the tcpdump command produces no output.

  3. If the system is not receiving any data, enter control + c to stop the capture and ensure that there are no local area network devices blocking mirror channel connectivity between the BIG-IP systems, and that the BIG-IP system Port Lockdown setting is configured correctly. For more information about configuring Port Lockdown, refer to K17333: Overview of port lockdown behavior (12.x - 15.x).

Verifying the mirrored connections

Both BIG-IP systems should show the same number of mirrored connections regardless of their HA status. There are a few occasions when the number of mirrored connections may differ between the BIG-IP systems.

For example:

  • The standby BIG-IP system is in the process of rebooting while new connections are received by the active BIG-IP system.
  • The mirroring channel has become saturated (overflowed) while new connections are received by the active BIG-IP system.

You can use the following procedure to verify the number of mirrored connections.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. View the active-standby status of the BIG-IP systems by entering the following command:

    show cm traffic-group

    The following example shows the HA status of the active-standby BIG-IP systems:

    ----------------------------------------------------------
    CM::Traffic-Group
    Name                      Device           Status   Next
                                                        Active
    ----------------------------------------------------------
    traffic-group-1           one.example.net  active   false
    traffic-group-1           two.example.net  standby  true

  3. View the mirrored connections on the BIG-IP system by entering the following command:

    show sys connection type mirror

    In the following example, two connections are mirrored:

    Sys::Connections
    10.11.23.139:45700  10.11.23.137:22  10.11.23.110:45700  10.11.23.111:22  tcp  34  (tmm: 2)  none
    172.12.31.88:33097  172.12.31.89:22  172.12.31.201:33097  172.12.31.202:22  tcp  31  (tmm: 3)  none
    Total records returned: 2

  4. Log in to the HA peer BIG-IP system determined in step 2, and repeat step 3. To determine which system you are currently logged in to, enter the following command:

    list sys global-settings hostname
