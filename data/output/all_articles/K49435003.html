Topic

You should consider using these procedures under the following condition:

  • You want to know which self IP address is used to source monitor traffic from the BIG-IP system.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the BIG-IP command line.

Procedures

Use the following procedures to determine which self IP address is used as the source IP address for health monitoring when multiple non-floating self IP addresses are configured for the same VLAN.

  • Route domain considerations
  • Using the ip addr show command to determine the self IP address used for monitoring
  • Using the ip route get command to determine the self IP address used for monitoring

Route domain considerations

To learn how to use the ip addr show and ip route get commands with route domains, refer to K13472: Userland applications on a BIG-IP system can connect to hosts in non-default route domains.

Using the ip addr show command to determine the self IP address used for monitoring

You can use the ip addr command to determine the primary BIG-IP self IP address that the system uses when sending health monitor traffic to the destination pool member.

Note: The primary address is the first address added to the associated VLAN.

Impact of procedure: Performing the following procedure should not have any negative impact on your system.

  1. Log in to the command line of the BIG-IP device.
  2. Type the following command:

    ip addr show

    The command returns output similar to the following:

    10: internal_vlan: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UNKNOWN qlen 1
        link/ether 00:50:56:86:4c:a5 brd ff:ff:ff:ff:ff:ff
        inet 10.20.4.3/24 brd 10.20.4.255 scope global internal_vlan 
           valid_lft forever preferred_lft forever                     
        inet 10.20.4.4/24 brd 10.20.4.255 scope global secondary internal_vlan
           valid_lft forever preferred_lft forever
        inet6 fe80::250:56ff:fe86:4ca5/64 scope link
           valid_lft forever preferred_lft forever

    Note: The ip addr show command may produce verbose output, depending on the number of interfaces, VLANs and self IPs configured on the device. If you know the VLAN name in which the pool member resides, use the ip addr show |grep <vlan name> syntax to parse out the self IPs on the relevant VLAN.

  3. In the command output, locate the VLAN name in which the pool member resides.

    The VLAN prefix contains a numeric value followed by a colon. In the previous example, the 10: <vlan name> syntax shows the destination in which the monitored pool member resides.

  4. Within the VLAN network information, locate the lines containing the prefix inet.

    The first inet line is the primary self IP address (in the example, 10.20.4.3) that the BIG-IP system uses when initiating health-monitor connections to a destination pool member. The second inet line is the secondary self IP address (in the example, 10.20.4.4) that the BIG-IP system uses when initiating health-monitor connections to a destination server.

    Note: While it's not recommended, it's possible for the BIG-IP system to send health monitor traffic on the mgmt interface. In this scenario, you want to look for the inet line under the mgmt or eth0 interface.

Using the ip route get command to determine the self IP address used for monitoring

Using the ip route get command, you can determine the primary self IP address that the BIG-IP system uses when sending health monitor traffic to the destination monitored server.

The command displays the associated VLAN name, the BIG-IP self IP address, and the destination address.

You are able to see the IP address you are attempting to reach, the VLAN, and the source IP address.

Note: This command always shows you an IP address for one of your non-floating self IP addresses.

Impact of procedure: Performing the following procedure should not have any negative impact on your system.

  1. Log in to the command line.
  2. Use the following command syntax to obtain the self IP address and VLAN used to connect to the destination server:

    ip route get <server ip address>

    Note: Replace <server ip address> with the IP address of the destination server.

    Output appears similar to the following example, which uses the destination server address 10.20.4.100:

    ip route get 10.20.4.100
    10.20.4.100 dev internal_vlan  src 10.20.4.3
    cache

    Note: In the example, the server 10.20.4.100 is associated with VLAN internal_vlan and the self IP address for health monitoring is 10.20.4.3.
