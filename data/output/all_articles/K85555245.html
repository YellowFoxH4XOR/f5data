Description

After renewing the self-signed device certificate on BIG-IP DNS, iquery connection failed with the other BIG-IP DNS.

You may encounter below messages in /var/log/gtm:
notice gtmd[PID]: 011ae01c:5: Connection complete to <IP_address>. Starting SSL handshake
err gtmd[PID]: 011ae0fa:3: iqmgmt_ssl_connect: SSL error: SSL connect (1)
iqmgmt_ssl_connect: IP: <IP_address>. SSL error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed
err gtmd[PID]: 011ae114:3: iqmgmt_ssl_connect: SSL error: error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed (xxxxxxxxx) from connection <IP_address>.
 

Environment

  • v14 and above
  • BIG-IP DNS
  • After renewing device certificate 

 

Cause

The certificate exchange between BIG-IP DNS systems is successful but the old certificate of one DNS system is still in the Trusted device certificates(/config/big3d/client.crt) and Trusted server certificates(/config/gtm/server.crt) of the other DNS system.
 

Recommended Actions

1. First of all, please follow the guidelines in K9467 to exclude all other possible issues.

2. Check the new device certificate on the BIG-IP DNS system you updated the device on:

Device certificates: System > Certificate Management > Device Certificate Management > Device Certificate

3. Then check below two places on other BIG-IP DNS systems in the iQuery mesh to see if the new certificate has been exchanged successfully and if there are old certificates there; Delete the old ones.

Trusted device certificates System > Certificate Management > Device Certificate Management > Device Trust Certificates 
Trusted server certificates DNS > GSLB > Servers > Trusted Server Certificates

4. You may have to restart big3d on the remote system and/or gtmd on the local system

Note: Be aware that restarting big3d and/or gtmd causes the iQuery connection to be torn down and re-established and causes iQuery to fail to connect.

tmsh restart sys service gtmd
tmsh restart sys service big3d
