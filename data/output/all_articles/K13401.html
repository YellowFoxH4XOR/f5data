Known Issue

When a virtual server is configured with both a BIG-IP APM access policy and BIG-IP ASM, BIG-IP APM modifies the HTTP requests for internal processing, which may generate BIG-IP ASM security policy violations.

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with both a BIG-IP APM access policy configured with single sign-on (SSO), and a BIG-IP ASM HTTP class profile.
  • The BIG-IP ASM security policy has the following HTTP Protocol Compliance violations enabled:

    • A header name with no header value
    • The No Host header in an HTTP/1.1 request
    • The Host header contains an IP address
  • The BIG-IP ASM security policy has the following cookie violation enabled:

    • Modified domain cookie(s)

Impact

Requests to the origin web server (OWS) will generate BIG-IP ASM violations, and may be blocked if the BIG-IP ASM policy is in Blocking Mode.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • BIG-IP ASM will generate violations similar to the following examples:

    • Host header contains IP address Host header with IP value: 127.1.1.2
    • Header name with no header value: Header 'snapshot-id' has no value
    • No Host header in HTTP/1.1 request
    • Modified domain cookies (LastMRH_Session, MRHSession)

Workaround

To work around this issue, you can modify the BIG-IP ASM security policy. To do so, perform the following procedures:

Impact of workaround: Relaxing HTTP Protocol Compliance will apply to all client requests processed by the BIG-IP ASM security policy. Ensure that such a change is appropriate and meets the security policies for your environment.

Relaxing HTTP Protocol Compliance

  1. Log in to the BIG-IP ASM Configuration utility.
  2. From the Application Security menu, select Policy.
  3. Verify that the correct Web Application and Security Policy are selected for the policy you want to modify.
  4. From the Blocking tab, select Settings.
  5. Click HTTP protocol compliance failed.
  6. Clear the check box next to the following HTTP Validation options:

    • A header name with no header value
    • The No Host header in HTTP/1.1 request
    • The Host header contains IP address
  7. Click Save.
  8. Click Apply Policy.

Adding BIG-IP APM cookies to security policy

  1. Log in to the BIG-IP ASM Configuration utility.
  2. From the Application Security menu, select Policy
  3. Verify that the correct Web Application and Security Policy are selected for the policy you want to modify.
  4. From the Headers menu, select Cookies.
  5. In the Allowed Modified Cookies section, click Create.
  6. In the Cookie Name field, enter the following content:

    LastMRH_Session
  7. To create the LastMRH_Session cookie, click Create.
  8. Click Create.
  9. In the Cookie Name field, enter the following content:

    MRHSession
  10. To create the MRHSession cookie, click Create.
  11. Click Apply Policy.
