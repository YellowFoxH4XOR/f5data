Known Issue

The SSL::session invalidate iRule command may not invalidate sessions for CMP-enabled virtual servers. Sessions are only invalidated for the Traffic Management Microkernel (TMM) on which the iRule was executed.

Impact

SSL sessions will not be invalidated as expected, which may pose a security risk.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Clients may be able to re-use session IDs that have been invalidated by an iRule.

Workaround

To work around this issue, you can disable CMP on affected virtual servers. To do so, perform the following procedure:

Impact of workaround: Processing for the modified virtual servers will take place on tmm0. This may have a performance impact on heavily loaded hosts.

Disabling CMP for a virtual server

  1. Log in to the command line.
  2. Use the following command syntax:

    bigpipe virtual <virtual_server_name> cmp <disable/enable>

    For example:

    bigpipe virtual CMP_vip cmp disable
  3. Save the changes made to the virtual server by typing the following command:

    bigpipe save
