Description

You want to understand BIG-IP ASM TPS-based DoS detection. For example, you are configuring TPS-based DoS Detection, with manual threshold and transparent mode, and you would like to know how to check the value of TPS for a DoS profile.

Environment

  • BIG-IP ASM
  • DoS Profile

Cause

None

Recommended Actions

You can check the value of TPS for a DoS profile by using the following command:

#tmsh show security dos profile my_dos_profile

-------------------------------------
Security::DoS Profile: my_dos_profile

-------------------------------------

  ---------------------------------------------------
  | Virtual Server Name: http-vs
  | Application Security Statistics
  ---------------------------------------------------
  | Mitigation Information
  |   Mitigation            : Transparent
  |   Stress                : no
  |   Attack Detected       : yes
  |   Most Recent Attack ID : 1944915324
  |
  | Maximum TPS             Current  1 Minute  1 Hour
  |   Source IP                  77        59      24
  |   Device ID                   0         0       0
  |   URL                        92        77      78
  |   Geolocation                 0         0       0
  |   Site Wide                  92        77      78


The TPS shown on the above output is for all IP address, however the mitigation is done based on per source IP address thresholds configured. For example in the above output the configuration is:
 

            tps-based {
                ip-maximum-tps 25
                ip-minimum-tps 20
                ip-tps-increase-rate 100
                mode transparent
                url-rate-limiting disabled
            }

Additional Information

In TPS-based detection mode, if the ratio of the transaction rate detection interval to the transaction rate history interval is greater than the specific percentage you configure on this screen (the TPS increased by percentage), the system detects the URL/site to be under attack, or the IP address/geolocation to be attacking. In order to stop the attack, the system blocks some, or all, requests from the detected IP address/geolocation and/to the attacked URL/site, depending on the configuration of the DoS profile.

For example if you have configured Relative Threshold: TPS increased by: 100% and reached at least 40 transactions per second. In simple words, TPS increased by 100% would mean, as per the historic data (which is snapshot of connections very 60 seconds and 60 mins), the increase in traffic is 100% and 40 TPS would trigger the mitigation.

For the other question of whether we can change TPS ( transaction per second ) to be ( transactions per time range ), the answer is no. It is transaction per second.
