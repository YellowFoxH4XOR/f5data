Known Issue

Description

UCS archives created on BIG-IP ASM version 10.2.1 may fail to load correctly on later versions of the software, causing bd to become unresponsive.

This issue occurs when all of the following conditions are met:

  • The UCS archive is version 10.2.1, and has not been rolled forward by the upgrade process
  • The software version on the device where the UCS is being installed is 10.2.1 with either Hotfix 1, Hotfix 2, or Hotfix 3
  • The configuration in the UCS archive has an XML profile including XSD or WSDL files

Impact

The BIG-IP ASM may temporarily fail to either pass or process traffic as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The bd process dumps core, creating files in the /var/core/ directory that have names similar to the following example:

    bd.bld473.0.core.7328.gz

  • The system may write log entries to the /var/log/asm file that appear similar to the following example:

    01310027:2: ASM subsystem error (nwd.pl,F5::NwdUtils::Nwd::log_failure): Watchdog detected failure for process. Process name: bd, Failure: Insufficient number of threads (required: 8, found: 0).

    01310027:2: ASM subsystem error (exec_core.pl,main::add_ts_log_line): ASM core restarted for recovery purposes

  • Policy changes may not take effect, and the observed behavior of policy enforcement may be incongruent with the policy as it is configured.

Workaround

To work around this issue, you can reapply all polices that use XML profiles. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the Configuration utility.
  2. Navigate to the Application Security > Policies menu.
  3. In the Security Policies list, click the Security Policy Name of the affected policy.
  4. Click Apply Policy.
  5. Repeat Steps 2 through 4 for any additional polices that use an XML profile.
