K000162977: BIG-IP LTM Configuration Load Failure After ConfigSync Between iSeries and VE Platforms

Type
Support Solution
Published
2026-10-29
Updated
2026-10-29
Applies to
  • BIG-IP
Source

Description

A BIG-IP VE in a high-availability deployment that mixes iSeries and VE platforms may fail to load its configuration after reboot following ConfigSync from the iSeries device.

The system reports:

01020036:3: The requested user (f5hubblelcdadmin) was not found.

Environment

  • BIG-IP LTM high-availability deployment.
  • Device group containing an iSeries platform and a BIG-IP VE.
  • ConfigSync performed from the iSeries platform to the VE.
  • VE hosted on a virtual infrastructure platform.
  • The synchronized configuration contains the internal user f5hubblelcdadmin.

Cause

Bug ID 2386673 tracks a regression associated with Bug ID 2258981.

The regression removes the internal f5hubblelcdadmin user from non-LCD platforms while retaining it on iSeries and other LCD-capable platforms. When user configuration is synchronized from an iSeries platform to a VE:

  1. The VE receives the iSeries-specific internal user record.
  2. The VE removes the unsupported user during initialization.
  3. Configuration validation still encounters references to the removed user.
  4. Configuration loading fails with error 01020036:3.

Recommended Actions

  1. SSH to the device and change to the /config directory if the session does not open there.
  2. Open bigip_user.conf in a text editor, comment out the auth user f5hubblelcdadmin { ... } block, and save.auth user admin {
        description "Admin User"
        encrypted-password none
        partition-access {
            all-partitions {
                role admin
            }
        }
        session-limit -1
        shell bash
    }
    #auth user f5hubblelcdadmin {
    #    description f5hubblelcdadmin
    #    encrypted-password none
    #    partition-access {
    #        all-partitions {
    #            role admin
    #        }
    #    }
    #    session-limit -1
    #    shell none
    #}
    auth user root {
        description root
        encrypted-password none
        session-limit -1
        shell bash
    }
  3. Run tmsh load sys config verify.
  4. If no other issues are reported, runtmsh load sys config (without verify used in the last command)
    1. Warnings during the config load can be ignored

NOTE: Caution should always be used when manually altering .conf files. If you need assistance please contact F5 Support.
