K000157110: Tenant state suddenly changed to "Retrying tenant deployment...", the status is "Tenant deployment failed - Server is not responding"

Description

F5OS tenants is running, suddenly it enter status "Tenant deployment failed - Server is not responding." and the state is "Retrying tenant deployment...", the tenant cannot work. This behavior is caused by out of memory, the SNMP daemon (snmpd) occupy too much memory on F5OS appliances.

Check the log /var/log/messages, when the tenant crash, we should see the OOM log, for example:

kernel: Out of memory: Kill process <PID> (virt-api) score 1001 or sacrifice child
kernel: Killed process <PID> (virt-api), UID 1001, total-vm:1630456kB, anon-rss:59452kB, file-rss:0kB, shmem-rss:0kB

Environment

  • F5OS
  • SNMP
  • Tenant

Cause

A known issue with the SNMP daemon (snmpd) on F5OS appliances can cause excessive memory resource utilization when SNMP is configured and receives certain undisclosed requests. This leads to failures in tenant deployment and management access issues. The problem is documented as F5OS SNMP vulnerability CVE-2025-47150 (see article K000149820).

Recommended Actions

Please follow the Mitigation steps in K000149820: F5OS SNMP vulnerability CVE-2025-47150, restore the tenant, resboot the device will fix the issue temporarily too. Then schedule the maintenance window to upgrade the F5OS to the version which contain the fix.
