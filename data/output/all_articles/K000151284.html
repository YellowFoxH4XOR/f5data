Description

In some network designs, monitoring traffic (such as ICMP pings) is routed through the BIG-IP data plane before reaching the management interface. If the Virtual Server handling this traffic is configured to allow only TCP and UDP, ICMP packets will be dropped and will not reach the management interface. This results in failed ping attempts, even though other management protocols (SSH, SNMP) may work.

  • ICMP (ping) requests to the BIG-IP management IP do not receive replies.
  • Packet captures show ICMP echo requests arriving at the BIG-IP self/floating IP (data plane), but no ICMP echo replies are observed.
  • Other protocols (e.g., SSH, SNMP) to the management IP work as expected.
  • The issue is specific to environments where traffic to the management IP traverses a Virtual Server configured for TCP/UDP only.

Environment

  • BIG-IP LTM (Virtual Edition or Appliance) v15 onward
  • Management IP is on a separate, dedicated interface (control plane)
  • Monitoring or management traffic (ICMP) routed through the data plane (self/floating IP) and Virtual Server
  • Virtual Server(s) configured for TCP and/or UDP protocols only

Cause

The Virtual Server is not configured to process ICMP traffic. As a result, ICMP packets are dropped at the data plane and never reach the management interface. This is by design: BIG-IP Virtual Servers only process protocols they are explicitly configured for.

Recommended Actions

To allow ICMP (ping) traffic to reach the management IP through the BIG-IP data plane, update the Virtual Server configuration as follows:

Option 1: Create a new Virtual Server for ICMP
        Set the protocol to "Other" and specify protocol number 1 (ICMP).
        See K5867: Configuring an ICMP-only virtual server for step-by-step instructions

Option 2: Allow All Protocols
       Modify the existing Virtual Server to set the protocol to "All Protocols" if appropriate for your security policy.

(Optional) Restrict Source/Destination
       For added security, restrict the Virtual Server to only allow traffic from the monitoring subnet/host and/or to the management IP.

Note: The data plane and control plane are separate; traffic cannot be routed between them unless explicitly allowed by a properly configured Virtual Server.
