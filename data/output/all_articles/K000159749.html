K000159749: VELOS configuration wiped after a PXE boot or controller RMA with system redundancy config mode set to prefer-1 or prefer-2

Source

Description

VELOS configuration was wiped after a PXE boot, with the following configuration in use:

system redundancy config mode prefer-1

controller-2 was active and controller-1 was PXE booted.
controller-1 became active immediately after the PXE boot and synced an empty/default configuration to controller-2.

Environment

  • VELOS controllers
  • system redundancy config mode

Cause

This is an expected result when system redundancy config mode is set to prefer-1 or prefer-2, and the preferred active controller is PXE booted. Bug ID2208685 tracks this issue.

Recommended Actions

Do not use prefer-1 or prefer-2. Use the default of auto.

The only time system redundancy config mode should ever be set to prefer-1 or prefer-2 is when troubleshooting specific issues related to failover. For example, if the controllers are constantly failing over, you can use that option to temporarily control which controller is active.

In all other situations, that option should always be set to auto. It should never be left on prefer-1 or prefer-2. Using prefer-1 or prefer-2 means that the controllers will not fail over in the event the preferred active becomes unhealthy.
