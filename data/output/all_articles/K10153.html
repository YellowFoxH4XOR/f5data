Known Issue

This is the result of a known issue. The BIG-IP ASM system interprets white space as a delimiter when parsing cookie information. As a result, additional values within a cookie are evaluated as a separate cookie.

For example, if the BIG-IP ASM system receives a cookie that appears similar to the following example, the BIG-IP ASM system will incorrectly parse the cookie information and report the cookie as a violation:

Cookie: Cookie1=value_element1 value_element2; cookie2=value2

The output of the cookies will be reported in the full request log:

Note: The full request log is displayed when a violation is selected and opened from the log within the Configuration utility.

Cookie Name Cookie Value Reason
-----------------------------------------------
Cookie_name1 value_element1 New Cookie
value_element2 New Cookie
cookie_name2 value2 New Cookie

In the example above, value_element2 is reported as a separate cookie when it should be associated with value_element1, which is part of Cookie_name1.

Note: For more information about instances when the cookie value is missing from the log output, refer to K9938: The BIG-IP ASM Traffic Learning page displays a blank cookie value for modified domain cookie violations.

F5 Product Development tracked this issue as CR104824 and it was fixed in BIG-IP ASM 10.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.
