Description

When configuring an http health monitor on a pool, the pool members remain unchecked, even when the pool member is reachable from the BIG-IP.  The output 'show ltm pool member' show the next line

Reason         : Pool member service checking is enabled, but result is not available yet

After enabling monitor logging for the pool member, following K12531, there logs similar to the next one on /var/log/monitors/<MonitorPartition>_<MonitorName>-<NodePartition>_<NodeName>-<port>.log

(_analyze_pings): visit UNKNOWN, now=[1618500767.635417][2021-04-15 15:32:47] [ addr=::ffff:<x.x.x.x>%0:80 mon=/Common/<Pool_member> fd=-1 pend=0 #conn=0 up_intvl=5 dn_intvl=5 timeout=16 time_until_up=0 immed=0 next_ping=[1618500730.286417][2021-04-15 15:32:10] last_ping=[0.000000][1970-01-01 00:00:00] deadline=[1618500772.635417][2021-04-15 15:32:52] on_service_list=True snd_cnt=0 rcv_cnt=0 ]

Additionally, no egress packets are seen with pool member's IP address as the destination

Environment

  • BIG-IP
  • HTTP health monitor
  • Pool member reachable

Cause

Unknown at the time of publication.

Recommended Actions

Restart the bigd daemon
tmsh restart /sys service bigd
