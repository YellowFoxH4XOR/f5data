K000159811: SWG Proxy with default action bypass behavior differs if client sends no SNI

Type
Support Solution
Published
2026-01-29
Updated
2026-01-29
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000159811

Description

When using BIG-IP Secure Web Gateway (SWG) as an explicit proxy with SSL default action bypass configuration, the BIG-IP will complete an additional server-side SSL handshake if the client did not send a SNI in its ClientHello. This can cause additional delays for the client-side SSL handshake and possibly problems for the client application.

You may observe:

  • SSL handshake failures logged in /var/log/ltm
  • Client applications timing out during SSL handshake establishment

Error messages observed in /var/log/ltm:

"SSL Handshake failed for TCP <target_IP>:443 -> <BIG-IP_IP>:<port>"

Environment

  • Product: BIG-IP SWG
  • Configuration:
    • Explicit proxy using iApp SWG proxy template
    • SSL Bypass enabled by default
  • Conditions:
    • ClientHello packets sent by client without Server Name Indication (SNI) extension

Cause

When the client sends a ClientHello without the SNI extension, the BIG-IP establishes a server-side connection first using its own ClientHello, then makes a second connection using the client's ClientHello. This process introduces additional latency for the client SSL handshake and application.

Answer/Recommended Actions

To force the BIG-IP to only forward the client's ClientHello even when the client's ClientHello does not contain a SNI, follow the steps below:

  1. Navigate to Access › Profiles / Policies : Per-Request Policies
  2. Click Edit for the relevant Per-Request Policy
  3. Click on the SSL Bypass Set VPE item (add this item if it is not already present)
  4. Change Bypass on SSL Client Hello to Enabled
  5. Click Save

Please note that any Category Lookup VPE item in the path will not work if it uses SNI since no SNI exists.

Additional Information

Understanding the SWG Explicit Proxy with default action "bypass" SSL Handshake behavior:

With SNI in the client's ClientHello:

  • BIG-IP makes a server-side connection using the client's ClientHello
  • The ServerHello is then passed back to the client

Without SNI in the client's ClientHello:

  • BIG-IP makes an initial server-side connection using its own ClientHello
  • Upon success, it makes a second server-side connection using the client's ClientHello
  • The ServerHello is then passed back to the client
  • This process adds latency that may cause problems with the client application
