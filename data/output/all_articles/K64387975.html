K64387975: Creating large pools caused BigD to crash

Support Solution

Description

Environment

  • BIG-IP
  • Multiple LTM Pools with large numbers of nodes (100+)
  • Multiple custom External SNI monitors

Cause
External monitors can cause high CPU impacting performance of the BIG-IP.  On underprovisioned devices, the bigd process can become overwhelmed and require a restart.

Recommended Actions

  • If the bigd process becomes unresponsive, restart it in the BIG-IP CLI with the command:
bigstart restart bigd
  • Consider using a standard LTM monitor with SNI support
  • Replace resource intensive commands in the external SNI monitor script (such as, openssl) with more efficient commands (such as, curl)
