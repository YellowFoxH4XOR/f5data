Description

You observe one of the following in the CPU utilization graph once every 24 hours, for a two to four hour period:

  • In Hyper Threading (HT)-split-enabled systems: an increase on the control-plane CPUs
  • In non-HT-split-enabled systems: an increase on all CPUs

Environment

  • BIG-IP ASM or BIG-IP FPS
  • The system is a member of a device group

Cause

In BIG-IP 11.6.0, F5 added the datasyncd process to manage JavaScript that the BIG-IP ASM and BIG-IP FPS generate and send to clients as part of their protection features. When the datasyncd process runs, it temporarily increases CPU usage. The protection features require different amounts of CPU and run on different schedules. However, the system triggers the most prominent protection features to run every 24 hours.

Recommended Actions

Rescheduling the daily start time for the datasyncd process (BIG-IP 14.0.0 and later)

If you determine that the system CPU usage is high during high load periods, you may need to reschedule the daily start time for the datasyncd process. To do so, perform the following steps:

  1. Log in to the Configuration utility.
  2. Navigate to Security > Options > Background Tasks.
  3. Click Show to display the current, next, and following start times for the obfuscation process.

    Note: When changing a start time, the new time cannot be within 2 hours of the current configured start time.

  4. Under Daily Start Time, in Obsfuscation for ASM / DoS, enter the new daily start time.

    Note:  All times are in local time according to the BIG-IP time zone. The times are stored as UTC so changing the BIG-IP time zone will change the local display but not the underlying UTC start time.

  5. Click Update.

Note: Prior to BIG-IP ASM 14.0.0, the only way to reschedule the daily start time for the datasyncd process is by using a set of commands which can render your system inoperable and cause a production outage if not performed properly. It is for this reason that we recommend leaving the setting as-is for these versions. Should you discover that this process is impacting production traffic, contact F5 Support for assistance.

Additional Information

  • The datasyncd process is used to manage JavaScript that the BIG-IP ASM and BIG-IP FPS generate and send to clients as part of their protection features. These features include, but are not limited to, CAPTCHA challenges, pro-active bot defense, client side integrity defense, session awareness, device ID, and application layer encryption. The process obfuscates the JavaScript to protect against reverse-engineering.
  • The increase in CPU usage is expected behavior and corresponds to the odd-numbered cores on HT-split-enabled systems.
  • The datasyncd process consumes available resources with a lower priority. If more important processes need CPU/memory, the obfuscation is de-prioritized or waits until resources are available.
  • The datasyncd process runs when BIG-IP ASM is first provisioned or when a device receives a sync on the datasync-global-dg device group.
