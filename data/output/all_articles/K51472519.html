Known Issue

A FastL4 virtual server may drop a FIN packet when mirroring is enabled.

This issue occurs when all of the following conditions are met:

  • The tm.fastl4_ack_mirror database variable is enabled.

    Note: This database variable is enabled by default.

  • The client or server sends a FIN packet, then immediately sends an RST packet.

Impact

Connection flows may stall or time out, and the application or web content may fail to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Connection flows stall or time out, and the application or web content fails to load.
  • Packet captures show the BIG-IP system fails to pass the FIN packet sent by one of the TCP endpoints; the RST packet is subsequently dropped by the other TCP endpoint.

Workaround

To work around this issue, you can disable the tm.fastl4_ack_mirror database variable. To do so, perform the following procedure:

Impact of workaround: If you restart the Traffic Management Microkernel (TMM), traffic processing is interrupted. You should perform this procedure during a maintenance window. In addition, when the tm.fastl4_ack_mirror database setting is disabled, the active BIG-IP system no longer waits for the peer to acknowledge a mirrored connection before completing the connection. As a result, the active system may have established connections that are not mirrored to the standby system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Disable the tm.fastl4_ack_mirror database variable by typing the following command:

    modify /sys db tm.fastl4_ack_mirror value disable

  3. Save the changes by typing the following command:

    save /sys config

  4. Restart TMM by typing the following command:

    restart /sys service tmm
