Known Issue

The Simple Mail Transfer Protocol (SMTP) monitor may mark IPv6 pool members down.

This issue occurs when the following condition is met:

  • You associate the SMTP health monitor with a pool containing IPv6 pool members.

Impact

The BIG-IP system marks the IPv6 pool members down.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When monitor logging is configured, the BIG-IP system logs an error message to the /var/log/monitors/<monitor_name>.log file that appears similar to the following example:

    ERROR: failed to connect <IPv6_addr> error: couldn't open socket: host is unreachable
  • The BIG-IP system marks the IPv6 pool members down, and traffic to the affected pool is disrupted.

Workaround

To work around this issue, you can import and configure the SMTP_monitor external monitor script. To do so, perform the following procedure:

Impact of procedure: The SMTP_monitor external monitor is a built-in monitor script available on the BIG-IP system; you may need to modify the monitor behavior to suit your environment.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Import the SMTP_monitor external monitor script by typing the following command:

    create /sys file external-monitor /Common/SMTP_monitor source-path file:///usr/share/monitors/SMTP_monitor
  3. Create the external monitor using the following tmsh command syntax:

    create /ltm monitor external <monitor_name> run <monitor_script>

    For example, for an external monitor named MySMTPMonitor and a script named SMTP_monitor, you would enter the following command:

    create /ltm monitor external MySMTPMonitor run SMTP_monitor
  4. Save the change by typing the following command:

    save /sys config
  5. Associate the monitor with the pool.
