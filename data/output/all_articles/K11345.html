Known Issue

This is the result of a known issue. BIG-IP APM currently only has the ability to examine one variable per AD Query and LDAP Query actions in an access policy profile.

For example, a (&(cn=%{session.custom.givenName})(givenName=%{session.custom.firstName})) query will fail with the following log messages:

apd[3630]: 01490107:3: 7aa6fe49: AD module: query with '(&(cn=jsmith)(givenName=%{session.custom.firstName}))' failed in queryActiveDirectoryUser(): no matching user found with filter (&(cn=jsmith)(givenName=%{session.custom.firstName})) (-1)
apd[3630]: 01490019:6: 7aa6fe49: AD agent: Query: query with '(&(cn=jsmith)(givenName=%{session.custom.firstName}))' failed
apd[3630]: 01490004:6: 7aa6fe49: Executed agent 'rbible_act_active_directory_query_ag', return value 0

F5 Product Development is tracking this issue as CR137746 and has been fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP APM release notes.

Workaround

You can work around this issue by using nested actions in an access policy profile, or by using an iRule.

Creating a nested query within an access policy

  1. Log in to the BIG-IP Configuration utility.
  2. Click Access Policy.
  3. Click the Create button.
  4. Enter a name for the access policy under General Properties.
  5. Click the Finished button.
  6. Click the Edit link next to the access policy you just created.
  7. Click the + to add an action.
  8. Select AD Query under Authentication.
  9. Click Add item.
  10. Select your Active Directory server from the Server drop-down menu.
  11. In the SearchFilter field, enter one variable you would like to examine. For example:
    cn=%{session.custom.givenName}
  12. Click the Save button.
  13. On the success branch of that rule, click the + to add a new action.
  14. Select AD Query under Authentication.
  15. Click Add item.
  16. Select your Active Directory server from the Server drop-down menu.
  17. In the SearchFilter field, enter the second variable you would like to examine. For example:
    givenName=%{session.custom.firstName
  18. Click the Save button.
  19. Continue with your access policy profile as normal.

Creating an iRule event

Follow the steps listed in K11225: Configuring an iRule event in an access policy to create an iRule event in an access policy. In step 6 of that procedure, enter the iRule you want to use.

For example:

Note: The following iRule is from a specific use case where the username is entered as firstname.lastname on the login page.

when ACCESS_POLICY_AGENT_EVENT {
if { [ACCESS::policy agent_id] eq "modifyUsername" } {
set myUsername "[ACCESS::session data get session.logon.last.username]"
set myFirstname [getfield $myUsername "." 1]
set myLastname [getfield $myUsername "." 2]
ACCESS::session data set session.custom.querystring "(cn=$myFirstname)(givenName=$myLastname)"
}
}
