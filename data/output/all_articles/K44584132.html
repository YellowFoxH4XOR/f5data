Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP system to protect your RESTful APIs.

Description

API security is often overlooked in the area of application security because APIs are less visible to end users than UI-designed web applications. However, APIs are subject to many of the same types of attacks as web applications and may be especially vulnerable to attacks related to authentication, authorization, and excessive data exposure.

The BIG-IP APM and Advanced WAF products include features that provide API protection, such as URL and parameter validation, Rate Limiting, OAuth authorization, and attack signatures to name a few. When BIG-IP APM and Advanced WAF are provisioned together on the system, you can use the F5 BIG-IP Guided Configuration along with your OpenAPI specification (OAS) file to quickly set up features that provide API protection and ensure that your API endpoints are protected.

In addition, you can integrate the API security protection policy along with your OAS file into your CI/CD development cycle. Doing so allows you to deploy your API code and API security policy together using a more automated approach; more frequent and reliable updates to your API software and security policy results in an agile workflow for DevOps teams.

Integrate API security protection into your CI/CD development cycle

Starting in BIG-IP 15.0.0, you can use an existing OpenAPI specification file to create and maintain your BIG-IP APM and Advanced WAF API security policies. You can then integrate the OAS file and API security policies into your CI/CD development cycle. The OAS file must be in JSON or YAML format.

A design-first approach to creating APIs involves planning and documenting the API using an OAS file (formerly called Swagger). After the initial design phase, the OAS file can be used to generate server-side code for the API during the CI/CD build cycle. The design-first approach to creating APIs can also be used to configure the features that provide API protection on your BIG-IP system. When you go to Security > BIG-IP Guided Configuration, select the API Security Protection followed by the REST API Security (Open API Spec) options, you are prompted to import an existing OAS file and then define additional API security settings. Importing the OAS file converts API elements, such as paths, parameters, and responses from your OAS file into BIG-IP APM and Advanced WAF security policy entities. APM and Advanced WAF API security policy options

When you run the BIG-IP Guided Configuration, go to Security > Guided Configuration and select API Security Protection. Then select the REST API Security (Open API Spec) option and configure the following objects and protection options:

  • General Properties
    • You can import an OpenAPI specification file to configure the API security policy. The BIG-IP Guided Configuration generates the BIG-IP APM and Advanced WAF API security policy by importing API definitions from an industry standard OpenAPI specification file. The file must be in JSON or YAML format. You can also choose whether to include additional API security options, such as rate limiting, allowlist/denylist, and the OAuth authorization method.
  • Paths
    • The paths (URLs) and base path properties are imported from the OAS file. The OpenAPI specification defines a path as an object that designates the relative paths to the individual API endpoints. The BIG-IP Guided Configuration converts path objects from your OAS file to URL security policy entities.

      For example:

      • The OpenAPI specification path /accounts/{accountId} is converted to the /accounts/* URL in your security policy. The asterisk (*) indicates a wildcard positional parameter.
      • The OpenAPI specification path /groups/{groupId}/members is converted to the /groups/*/members URL in your security policy. The asterisk (*) indicates a wildcard positional parameter.
  • Responses
    • The responses are imported from the OAS file and used for the Access Control, Rate Limiting, and Blacklisting features. The OpenAPI specification defines a response as an object that maps an HTTP response code to the expected response. The BIG-IP Guided Configuration converts response objects from your OAS file to API responses in your BIG-IP APM API protection profile.

      For example:

      • The following OpenAPI specification response is converted into an API response in your BIG-IP APM API security policy and used for appropriate responses for the Rate Limiting and Blacklisting features:
        "responses": {
            "404": {
                "description": "User not found"
            }
          },

        Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

  • Security Settings
    • Configure how the BIG-IP system processes a request coming from an attacking IP address as follows:
      • In Blocking enforcement mode, the system blocks either connection from the attacking IP address.
      • In Transparent enforcement mode, the system reviews and logs the violation event but does not block requests either from the attacking IP address or to the attacked URLs.
  • OAuth Provider
    • Configure an OAuth provider and enable the BIG-IP system to obtain JSON web tokens (JWTs) from an OAuth authorization server that supports the tokens. When an OAuth provider supports discovery from a well-known endpoint, the system can discover JWTs and JSON web key (JWK) configurations from the provider.
  • Rate Limiting (Optional)
    • Configure rate limiting thresholds to limit the network traffic for API endpoints. A rate limit determines the maximum number of calls allowed in a particular time interval.
  • Whitelist / Blacklist (Optional)
    • Configure the system to allow or deny requests.
  • Virtual Server
    • Provide the IP address and port for the network traffic and select a client-side SSL profile.
  • Pool
    • Select an existing pool or configure a pool of one or more servers that will be associated with the virtual server.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • BIG-IP APM and Advanced WAF are licensed and provisioned on your system.
  • You have an existing OpenAPI specification 2.0 file (JSON or YAML format) that defines your RESTful API.
  • You have configured the following configuration elements on the BIG-IP system:
    • Network components, such as VLANs, self IP addresses, and routes.
    • Administrative components, such as DNS resolver, network time protocol (NTP), the management IP address, and licensing.
  • Your BIG-IP system is running Guided Configuration 10.0 or later.

Procedures

Configure API security protection using the BIG-IP Guided Configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Guided Configuration.
  3. Select API Security Protection.
  4. Under API Security Protection, select REST API Security (Open API Spec).
  5. On the REST API Security (Open API Spec) page, review the list of configuration objects under the Configuring the solution using the below steps will create the required objects list, and select Next.
  6. On the API Protection Properties page, select Show Advanced Setting, and complete the following options:
    1. For Configuration Name, enter a name for the configuration.
    2. Under Import OpenAPI Spec File, select Import to import an existing OpenAPI specification 2.0 file.
    3. Select Use Rate Limiting. (optional)
    4. Select Use Whitelist / Blacklist. (optional)
    5. For Authorization Method, select OAuth 2.0.
    6. Select a DNS resolver.
    7. Under API Authentication Policy Settings, complete the following options:
      1. For Inactivity Timeout, enter the maximum amount of time to keep an inactive session alive, or leave the default of 300 seconds.
      2. For Max Subsession, enter the number of seconds after validation when the subsession is considered expired, or leave the default value of 900 seconds.
      3. For Lifetime Subroutine Timeout, enter the number of seconds that the user has to complete the subroutine.

        A subroutine is interactive; the user must acknowledge all requests (such as typing credentials or making a choice) within this time. The setting defaults to 120.

    8. Select Save and Next.
  7. On the API Protection Configuration page, review the paths and base path properties imported from the OpenAPI specification file.

    Note: If necessary, you can edit the path properties after the policy is complete.

  8. Select Save and Next.
  9. On the API Protection Responses page, review the responses that are used for the Access Control, Rate Limiting, and Blacklisting features.
  10. Select Save and Next.
  11. On the Web Application Security Policy Properties page, select one of the following options from the Enforcement Mode menu, depending on how you want the BIG-IP system to process a request coming from an attacking IP address:
    • In Blocking enforcement mode, the system blocks either connections from the attacking IP address or the requests to the attacked URLs.
    • In Transparent enforcement mode, the system does not block requests either from the attacking IP address or to the attacked URLs. However, the system reviews and logs the violation event. Transparent mode is often used when deploying a new security policy or testing new policy features.
  12. On the OAuth General Properties page, complete the following options:
    1. For OAuth Provider Type, select a type of application for which you are configuring the client/resource server.
      Note: You can find this resource object at Access > Federation > OAuth Client / Resource Server > Provider.
    2. For Choose OAuth Provider, select an already configured OAuth provider from the list or select Create New to configure a new provider.
      • If you selected Create New to configure a new provider, configure the OAuth provider settings to enable the BIG-IP system to obtain JSON web tokens (JWTs) from an OAuth authorization server.
    3. Select Save and Next.
  13. On the Rate Limiting Configuration page, complete the following options:
    1. For the Rate Limiting Factor option, select one of the following rate limiting factors:
      Note: The remaining rate limiting options change depending on the factor you select.
      • Service Tier
      • Organization
      • Client Application
      • User
      • User Group
      • SAL Enforcement
      • Source IP
    2. Complete the remaining rate limiting options.
    3. Select Save and Next.
  14. On the Whitelist/Blacklist Properties page, complete the following options:
    1. For Whitelist/Blacklist Factor, select one of the following options:
      • User Group
      • User
      • Client Application
      • Organization
    2. For Organization ID Key, enter the JSON tag that references the ID key value in the JWT token. For example, organizationId.
    3. Select Whitelist/Blacklist, as required, to specify values that determines when to accept or reject a request.
    4. Select + to add values per User, User Group, Client Application, or Organization to the Whitelist or Blacklist table.
    5. Select Save and Next.
  15. On the Virtual Server Properties page, complete the following options:
    1. Select Assign Policy to Virtual Server(s).
    2. For Virtual Server, select Create New or Use Existing, depending on whether you want to create a new virtual server or assign your API security policy to an existing virtual server.
    3. Complete the remaining virtual server settings.
    4. Select Save and Next.
  16. If you chose to create a new virtual server, complete the following options on the Pool Properties page:
    1. Configure a new pool for the virtual server or assign an existing pool.
    2. Select Save and Next.
  17. On the There are pending changes for your application page, complete the following options:
    1. Review the configuration summary.
    2. Select the pencil icon to make changes on any step.
    3. If you are ready to deploy the policy, select Deploy.

After you have created and deployed the API security policy, you can use test traffic to refine the policy and reduce false positive violations. The system generates learning suggestions for requests that cause violations and do not pass the security policy checks. The system also suggests revising entities such as URLs, file types, or parameters that often appear in requests. Once the test phase has concluded, you can deploy the policy to your production environment.
