Description

When you provision a tenant, you observe that it is booted up but not functioning as expected or not reachable by the configured management IP address. You might notice it is always showing NO LICENSE under the CLI like the below using the virtual console by following K33373310: Accessing an F5 rSeries tenant console.

 

[root@testv15:NO LICENSE:]

 

When you check the ltm logs(/var/log/ltm) inside the tenant, you observe there are lots of logs indicating communication problems like the below generated by the platform_agent daemon:

Jun  3 00:31:41 testv15 warning platform_agent[5598]: 01d50005:4: Unable to subscribe to tmstats. Retrying...
Jun  3 00:31:41 testv15 warning platform_agent[5598]: 01d50005:4: Unable to subscribe for stats
Jun  3 00:31:51 testv15 warning platform_agent[5598]: 01d50005:4: Unable to subscribe for stats

 

Environment

  • F5OS-A v17.1.0.0 and earlier
  • FIPS 140 is licensed
  • BIG-IP tenant

Cause

For tenant versions before 17.1.0.1, the FIPS 140 is not supported. We track this as the ID 1286905.

 

Recommended Actions

Using tenant versions that support the FIP 140, which are 17.1.0.1 and afterward.

 

Additional Information

To check whether you have FIPS-140 licensed, you can use the below command after login to your F5OS confd terminal:

show system licensing

If it is licensed, it should show a line like the one below:

FIPS 140 License
