Description

BIG-IP currently has no way of triggering a post-handshake CertificateRequest with TLS 1.3.

Environment

  • TLS 1.3

Cause

TLS 1.3 Post-Handshake Authentication is not currently supported.

Recommended Actions

Consider if Post-Handshake Authentication is required before enabling TLS 1.3.

Additional Information

With earlier versions of TLS, an iRule with SSL::renegotiate may be used to enforce new encryption settings or certificate requirements.

Renegotiation may not be used with TLS 1.3. To implement conditional certificate requirements, TLS 1.3 introduces the Post-Handshake Authentication feature. This feature allows a server to send a CertificateRequest after the initial TLS handshake has completed. For example, certain URIs may require client authentication.

A server may only send a Post-Handshake CertificateRequest if a client initially presented the post_handshake_auth extension in its Client Hello. A server must not send a Post-Handshake CertificateRequest if a client does not present this extension. However, a server may send a CertificateRequest during the initial TLS handshake, regardless of whether a client presented the post_handshake_auth extension.

Refer to RFC 8446 for more information about Post-Handshake Authentication with TLS 1.3.
