Known Issue

This is the result of a known issue. BIG-IP high availability pairs exchange messages that indicate the date and time stamp for their current configuration files. The BIG-IP systems use the information in these messages to determine whether the configsync process is needed. When systems in the high availability pair have identical configurations, the BIG-IP system's configsync auto detect indicator may incorrectly show that a configsync is required. When this occurs, the BIG-IP system Configuration utility will report one of the following messages:

  • Sync Required
  • Sync Recommended

F5 Product Development tracked this issue as CR64075 and CR69389 and it was fixed in BIG-IP versions 9.3.0 and 9.4.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM and Link Controller release notes.

Workaround

You can work around this issue by setting the Configsync.LocalSyncedTime database key to the same value on both systems in the BIG-IP high availability pair. To do so, perform the following procedure:

  1. Log in to the command line of each BIG-IP system in the high availability pair.
  2. Reset the Configsync.LocalSyncedTime database key on each device to the current date and time by typing the following command:

    bigpipe db Configsync.LocalSyncedTime `date +%s`

    Note: Specify the same timestamp on each system in the pair. For instructions about converting time into seconds since the Unix epoch, refer to K148: Converting a date and time into the number of seconds since the beginning of the UNIX epoch.
