Description

Log messages produced by the iRule aren't appearing in /var/log/ltm, even though you are using the local0 facility.

For example:

when RULE_INIT {
  log local0. "log message"
}

Environment

iRule logging default level (informational):

sys db log.rules.level {
    default-value "Informational"
    scf-config "false"
    value "Informational"
    value-range "Debug Error Informational Notice Warning"
}

Syslog 'include' within the bigip.conf

sys syslog {
    clustered-host-slot disabled
    include "
        filter f_local0 {
            facility(local0) and level(warning);
        };
        filter f_remote_loghost {
            facility(local0) and level(warning);
        };
}

Cause

By default, iRules log with severity level "informational".

If a custom syslog filter has been configured in /config/bigip.conf, it may not be allowing 'informational' level log messages to be forwarded to the syslog. In the example shown above, the syslog filter is only including "warning" level messages, so "informational" will be filtered-out.

Recommended Actions

You can change the log filter, to include 'informational' level messages. This can be found in the /config/bigip_base.conf file

filter f_local0 {
    facility(local0) and level(info..warning);
};

Or you can change the sys db log.rules.level to a different level (such as 'notice', 'warning', 'error', etc)

tmsh
modify sys db log.rules.level value Warning

Or, you can set the log severity level in your iRule command.

log local0.<severity level>

For example:

when HTTP_REQUEST {
    log local0.warning "message"
}
