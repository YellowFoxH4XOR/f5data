Issue

Description

This article discusses areas in the APM Configuration and the BIG-IP Edge Client to investigate and detect issues with BIG-IP APM Network Access Client Proxy Settings and the associated Proxy PAC file integration on the client.

Environment

  • BIG-IP APM Network Access 
  • BIG-IP Edge Client installed on local User Windows device
  • Client Proxy settings, configured with Static server or Proxy Auto-config PAC script file.
  • Users are having issues connecting or accessing outbound web Traffic due to Proxy specific issues. 

Cause

None.

Recommended Actions

Troubleshooting

  • Is a remote PAC file configured in the APM Network Access resource?
  • Did the PAC file fail to download after the VPN tunnel connected?
  • Check if the PAC file has a syntax error resulting in failure?
  • Is the user having issues browsing a certain site after VPN is connected?
  • Check if the BIG-IP Edge client is detecting a local proxy?  

APM Network Remote Proxy or Proxy PAC 

Is a remote PAC file configured in the APM Network Access resource?

Configuration: 

Verify a Proxy configuration was added to the APM Network Access resource settings:
Access  ››  Connectivity / VPN : Network Access (VPN) : Network Access Lists  ››  Resource Name

  • Look for Client proxy settings to be enabled, and various settings are filled in.

 
Note: Client proxy settings enabled, and Client Proxy AutoConfig script is filled out

Did the PAC file fail to download after the VPN tunnel connected? 

Check the Log Files: 

  • %temp%\logterminal.txt
  • EdgeClient Event Viewer
    • Open the BIG-IP Edge Client
    • Select "View Details"
    • Select "View Logs"

Example Log Message: 

Error 2019-01-02 19:54:23:848 DIALER \PACHelper.cpp, WritePACFileFromURL, Failed to connect for downloading a PAC file (URL: http://10.10.10.253)

Suggestions:

Confirm Basic Networking (Routing, DNS, HTTP) and PAC Script availability from the BIG-IP command line.

[root@1-3009487461-bigip1:Active:Standalone] config # ip route get 10.10.10.253
10.10.10.253 dev Internal  src 10.10.10.152
    cache
[root@1-3009487461-bigip1:Active:Standalone] config # curl http://10.10.10.253/sample1.pac
function FindProxyForURL(url, host) {
 
// If the hostname matches, send direct.
    if (dnsDomainIs(host, "intranet.domain.com") ||
        shExpMatch(host, "(*.abcdomain.com|abcdomain.com)"))
        return "DIRECT";
 
// If the requested website is hosted within the internal network, send direct.
    if (isPlainHostName(host) ||
        shExpMatch(host, "*.local") ||
        isInNet(dnsResolve(host), "172.16.0.0",  "255.240.0.0") ||
        isInNet(dnsResolve(host), "192.168.0.0",  "255.255.0.0") ||
        isInNet(dnsResolve(host), "127.0.0.0", "255.255.255.0"))
        return "DIRECT";
 
// If the IP address of the local machine is within a defined
// subnet, send to a specific proxy.
    if (isInNet(myIpAddress(), "10.10.5.0", "255.255.255.0"))
        return "PROXY 10.2.3.4:8080";
 
// DEFAULT RULE: All other traffic
    return "PROXY 10.155.48.253:3128";
 
}

If the above tests fail,  use tcpdump on the connectivity profile  and the target vlan to determine if the PAC is failing because of a network issue. 

(https://support.f5.com/kb/en-us/products/big-ip_apm/manuals/product/apm-network-access-13-1-0/9.html)

Review the capture from your favorite network analysis tool (Wireshark, tcpdump, tshark..etc).  (example is WireShark output)

Check if the PAC file has a syntax error resulting in a failure?

Log File: 

  • %temp%\logterminal.txt
  • EdgeClient Event Viewer
    • Open the BIG-IP Edge Client
    • Select "View Details"
    • Select "View Logs"

Log Message: 

Error 2019-01-02 17:49:41:393 DIALER \PACHelper.cpp, WritePACFileFromURL, Failed to load proxy auto-configuration script

Suggestions:

Review the PAC file for syntax errors or use a PAC file validator

Is the user having issues browsing a certain site after the VPN is connected? 

Download a copy of the F5 generated pac file from the local webserver: 

Start > Control Panel > Network and Internet > Internet Options > Connections tab > LAN Settings

 
Note: The above images show a local proxy server is configured, or a local PAC File was statically configured on the client.

From a browser navigate to "http://127.0.0.1:45554/" and download the contents locally. This references the local computer copy of the modified PAC file.  Review with a text editor, or use PAC file validator in order to determine if traffic is targeting the correct path. 

Check if the BIG-IP Edge Client is detecting a local proxy

Is a local proxy or PAC script configured on the client or should traffic leaving the client target a Local proxy server in order to reach the BIG-IP virtual server?Log File: 
%temp%\logterminal.txt or the EdgeClient Event Viewer

Log Message: 

The EdgeClient detects a proxy or PAC Script via Wininet. The APPCTRL component will have a log message like: 

Info 2018-12-18 21:38:06:555 APPCTRL CAppTunnelEx::OnLoadConfigStatus, INTERNET_STATUS_DETECTING_PROXY - WinInet notifies the client application that a proxy has been detected.
