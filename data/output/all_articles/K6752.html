Topic

This article applies to BIG-IP ASM 9.2.0 through 9.4.1. For information about other versions, refer to the following articles:

  • K14342: Preserving or modifying the Server HTTP response header for BIG-IP ASM (11.x)
  • K10089: Preserving or modifying the Server HTTP response header for BIG-IP ASM (9.4.2 through 10.x)

The Server HTTP header allows an HTTP server to identify information about the software it uses to handle HTTP requests. The Server HTTP header field can contain product and version information, as well as comments identifying the server and any significant sub-products. For security reasons, the BIG-IP ASM system removes the Server HTTP header from responses to the client. You can use an iRule to preserve or manipulate the Server HTTP header.

You can use the following iRule examples to preserve or manipulate the Server HTTP header:

Creating an iRule that preserves the original Server HTTP header

To create an iRule that preserves the original Server HTTP header that was sent from the HTTP server, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. In the Definition field, paste the following iRule:
     when HTTP_RESPONSE {    set ts_delete_server_header 0 }
Creating an iRule that replaces the Server HTTP header

To create an iRule that replaces the Server HTTP header with a user-definable value, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. In the Definition field, paste the following iRule:
     when HTTP_RESPONSE {    set ts_delete_server_header 0    HTTP::header replace Server new_value }
