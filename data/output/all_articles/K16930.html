Known Issue

The apmd process may exit and produce a core file when running a logging agent.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy is configured with a logging agent that references session variables.
  • The logging agent is configured to log a session variable that returns a null value.

Impact

The BIG-IP APM system fails to process traffic while the apmd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are temporarily unable to access BIG-IP APM system resources.
  • In the /var/log/apm file, messages appear similar to the following example:

    err apmd[<pid>]: 01490000:3: **ERROR** memcache.c func: "mc_rcv_set_cmd()" line: 2622 Msg: Error: NOT_STORED ERR_OK (0)
    err apmd[<pid>]: 01490000:3: **ERROR** memcache.c func: "mc_rcv_set_cmd()" line: 2622 Msg: Error: NOT_STORED ERR_OK (0)
    err apmd[<pid>]: 01490000:3: **ERROR** memcache.c func: "mc_rcv_set_cmd()" line: 2622 Msg: Error: NOT_STORED ERR_OK (0)

  • The apmd process produces a core file in the /shared/core/ directory, similar to the following example:

    apmd.bld2.0.231.core.gz

  • The system logs messages in the /var/log/apm file that correlate with the time that the apmd core file in the /shared/core directory is created. These messages may appear similar to the following example:

    notice apmd[<pid>]: 01490000:5: ** SIGSEGV **
    notice apmd[<pid>]: 01490000:5: fault addr: 0x0
    notice apmd[<pid>]: 01490000:5: fault code: 0x1
    notice apmd[<pid>]: 01490000:5: fault time: <date and time of event>

Workaround

To mitigate this issue, you can ensure that the logging agent is configured to log only session variables that return a valid value.
