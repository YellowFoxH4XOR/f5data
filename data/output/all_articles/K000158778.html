Description

Configuration sync between the Primary Device (Active) and Secondary Device (Standby) in a BIG-IP LTM high-availability pair failed.

The sync operation generated the error: "01070920:3: Application error for confpp: SysExe: fork error; errno (12) at SysExeCmd.cpp:97," indicating a validation error during the sync process

In /var/log/ltm you may also notice logs similar to:

Jan 19 10:05:27 LTM1.example.com err mcpd[4450]: 0107134b:3: (Failed to fork to exec mcpd syncer script.) errno(12) errstr(Cannot allocate memory).
Jan 19 10:05:27 LTM1.example.com err mcpd[4450]: 01070712:3: Caught configuration exception (0), Failed to sync files..
Jan 19 10:05:27 LTM1.example.com err mcpd[4450]: 01071488:3: Remote transaction for device group /Common/device-group-failover-example to commit id 5395 7582568245656237878 /Common/LTM2.example.com 0 failed with error 01070712:3: Caught configuration exception (0), Failed to sync files...

Environment

  • BIG-IP LTM
  • High-availability device group with two devices (Active/Standby)
  • Device group configuration with manual sync

Cause

The root cause is insufficient available memory on the Standby device's management plane, resulting in the operating system being unable to fork new processes required for configuration sync. 

This condition was evidenced by MemAvailable: 0 kB (checked with cat /proc/meminfo command), nearly exhausted swap, and high swap usage by management processes such as tomcat. 

Recommended Actions

Increase management resource provisioning on both devices - for reference: K26427018: Overview of Management provisioning
