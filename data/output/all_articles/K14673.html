Known Issue

When you add iRules to virtual servers using the representational state transfer (REST) interface for iControl, the process fails.

This issue occurs when all of the following conditions are met:

  • You have added the iControl REST service to the BIG-IP system.
  • You have attempted to add an iRule to a virtual server using the iControl REST service

Impact

You cannot associate an iRule to a virtual server using the REST interface for iControl.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • RESTful requests to the iControl service return with an "HTTP 400 - Bad Request" error message similar to the following example:

    {"code":400,"message":"Status code:400, uri:http://localhost:8110/tm/ltm/virtual

Workaround

To work around this issue, you can add iRules to virtual servers using  tmsh. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Adding an iRule to a virtual server using the tmsh utility

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Add the iRule to the virtual server configuration using the following syntax:

    modify /ltm virtual <virtual_server_name> rules { <irule_name> }

    For example, to add an iRule named rule_example to a virtual server named vs_http, you would use the following command:

    modify /ltm virtual vs_http rules { rule_example }

  3. Save the change by typing the following command:

    save /sys config
