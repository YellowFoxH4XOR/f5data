Known Issue

Live update installation of an ASM Attack Signature update may fail.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM system has downloaded an Attack Signature update file.
  • You attempt to install the update file using one of the following Configuration utility methods:
    • In the upper-left corner, you select Live Updates Available.
    • You go to System > Software Management > Live Update.

Impact

The attack signature update fails with an error.

Workaround

The default clean interval is 300 seconds (5 minutes). To work around this issue, you can reinstall the update file immediately after the file cleanup task has run, or you can increase the clean interval to ensure it does not run while you install the update. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. To monitor the clean activity, enter the following command:

    tailf /var/log/ts/asmcrond.log | grep CleanFiles

  3. In the output, look for a message similar to the following example:

    asmcrond|INFO|Mar 20 21:54:44.389|24036|F5::PeriodicTask::Base::run,,Running Task: CleanFiles

  4. After the message appears, upgrade the ASU immediately. If the update process completes successfully, you are done. If 5 minutes is not enough time for the update process to complete, you can increase the clean interval using the remaining steps.
  5. Using a file editor such as vi, open the /etc/ts/tools/asmcrond.cfg file for editing.
  6. Under [CleanFiles], increase the Interval value. The following examples demonstrate increasing the Interval value to 3000:

    Important: Do not set the Interval value too high; 50 minutes (3000 seconds) should be enough.

    Original, default value:

    [CleanFiles]
    Interval=300

    Modified value:

    [CleanFiles]
    Interval=3000

  7. Save the changes to the file.
  8. Locate the process ID (pid) for the asmcrond process by entering the following command:

    ps -ef | grep asmcrond

  9. Force the asmcrond process to restart by specifying the <pid> in the kill command, using the following command syntax:

    kill <pid>

  10. Enter the following command to monitor asmcrond.log until you see another CleanFiles log message:

    tailf /var/log/ts/asmcrond.log | grep CleanFiles

  11. After the message appears, upgrade the ASU immediately. The temp files can stay in the folder for 50 minutes.
  12. After the ASU is installed, repeat steps 5 through 9 to change the Interval value back to 300 and restart the asmcrond process.
  13. To verify the asmcrond process started correctly, enter the following command:

    ps -ef | grep asmcrond

    Output should appear similar to the following example:

    root     15711     1  0 Mar12 ?        SN     6:31 /usr/bin/perl /usr/share/ts/bin/asmcrond

    You can also use the following tailf command to monitor the asmcrond.log file for startup messages:

    tailf /var/log/ts/asmcrond.log

    A message similar to the following example should appear:

    asmcrond|INFO|Apr 17 07:29:13.688|1192|,,Starting asmcrond
