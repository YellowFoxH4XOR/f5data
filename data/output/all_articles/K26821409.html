Description

https monitor gets immediately reset by backend server

  • backend server got patched/upgraded
  • https monitor now fails 
  • Error in logs: protocol mismatch

Environment 

  • BIG-IP DNS/LTM
  • https monitors
  • Server Name Indication (SNI) extension requirement
  • Microsoft Webserver IIS 8.0

Cause

Because Server Name Indication has been selected as required in the website configuration on Microsoft IIS 8.0, now the https monitors on the BIG-IP DNS/LTM fail even when it has worked before.

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Create an external monitor that includes the hostname/domain. Example from devcentral: https://devcentral.f5.com/s/articles/https-sni-monitor
  2. Follow recommendation from Microsoft listed here: https://docs.microsoft.com/en-us/iis/get-started/whats-new-in-iis-8/iis-80-server-name-indication-sni-ssl-scalability 

Additional Information

Server Name Indication (SNI) allows the server to safely host multiple TLS Certificates for multiple sites, all under a single IP address. It adds the hostname of the server (website) in the TLS handshake as an extension in the CLIENT HELLO message. This way the server knows which website to present when using shared IPs. See for more details https://www.globalsign.com/en/blog/what-is-server-name-indication/
