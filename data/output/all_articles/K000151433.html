K000151433: Using a Web Acceleration profile with an L7 DoS profile in transparent mode can result in the BIGIP issuing TCP resets for static content

Type
Support Solution
Published
2025-05-20
Updated
2025-05-20
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151433

Description

  • Using a Web Acceleration profile with an L7 DoS profile in transparent mode can result in the BIGIP issuing TCP resets for static content
  • Requests for static content receive a TCP reset from the BIGIP
  • Error messages: [F5RST: Internal error: dosl7-avr abort (Hudfilter abort)]
    • Observed in /var/log/ltm or packet capture when reset cause logging is enabled.

Environment

  • L7 DoS Protection Profile configured and applied to a virtual server
  • Web accleration profile applied to the same virtual server

Cause

This is due to an internal behavior in how the BIGIP passes requests from the AVR module to the DoS profile.
The AVR profile will serve the static content but still forward the request to the DoS profile for processing resulting in a conflict.

Recommended Actions

1) Modify a DB variable to disable this behavior globally:
   # tmsh modify sys db dosl7d.static_uri_protection value disable
2) Remove the web acceleration profile.
3) Use a vip-target-vip architecture where the cache lives on VIP1 and the dos profile on VIP2.

Additional Information

The following command can be used to see how many dosl7-avr abort resets have been logged on the device:
# tmctl rst_cause_stat | grep -i 'dosl7-avr abort'
