Known Issue

The bd process may restart and produce a core file when attack signature configuration is changed and the BIG-IP ASM system is processing a heavy traffic load. For example, when you perform a configuration synchronization (ConfigSync) or delete a policy attached to a virtual server.

This issue occurs when all of the following conditions are met:

  • The attack signature configuration is changed.
  • The BIG-IP ASM system is processing a heavy traffic load.

The configuration change under load may cause excessive logging, which creates conditions that could lead to the bd process restarting and producing a core file.

Impact

The BIG-IP ASM system stops processing traffic and may fail over to a peer device when configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP ASM system generates a bd core file to the /shared/core directory.
  • The BIG-IP ASM system sends a SIGSEGV to the bd process and logs a message to the /var/log/ts/bd.log file similar to the following example:

    BD_MISC|CRIT  |<date and time>|<pid>|signals.c:0076|Received SIGSEGV - Core Dumping

  • In the /var/log/bd.log file, you observe the system continuously repeating the following log messages:

    ATTACK_SIG|ERR   |Jan 04 01:17:48.356|16468|attack_patterns_funcs.cpp:0150|Can't run patterns - no set attached.
    ATTACK_SIG|ERR   |Jan 04 01:17:48.356|16468|attack_patterns_funcs.cpp:0633|Going to match patterns without available rdas.
