Description

Incremental synchronization may fail after a tenant is redeployed, necessitating a force-full-load-push to restore incremental sync functionality.

Environment

  • Product: BIG-IP tenants running versions prior to 17.1.2 deployed on any version of F5OS.
  • Configuration: Incremental ConfigSync in a multi-tenant environment

Cause

The root cause of the issue is a known bug ID1105021 in BIG-IP TMOS versions prior to 17.1.2 release. After a tenant is redeployed after having it's status set to Provisioned and then back to Deployed state, or rebooted, it can lead to incremental sync not working until a force-full-load-push sync is initiated. After this push, incremental sync starts working again. This is due to the fact that MCPD process loads the configuration from the text config file rather than the binary database.

Recommended Actions

To resolve this issue, the recommendation is to upgrade the tenants to BIG-IP version 17.1.2.

The testing in 17.1.2 release has confirmed that the bug causing the incremental synchronization failure is fixed in this version.

Additional Information

After upgrading, the synchronization behavior of F5OS tenants will match that of vCMP guests, and incremental sync should work as expected after tenant redeployment without the need for a force-full-load-push.
