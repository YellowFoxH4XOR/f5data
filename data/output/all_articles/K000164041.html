K000164041: CIS cannot deploy configuration after BIG-IP fast failover

Published
2026-10-29
Updated
2026-10-29
Applies to

Source

Description

When CIS 2.20.4 connects to a BIG-IP Active-Standby pair through a Floating Self IP, an AS3 POST sent shortly after a failover can be rejected by the newly Active device:

[ERROR] [Request: 4][AS3] authentication failed, Error response from BIGIP with status code: 401 Message: X-F5-Auth-Token does not exist.

The affected VirtualServer shows status: ERROR

The condition clears when CIS obtains a new token, or when a POST succeeds after the old token expires.

Environment

  • Product: F5 Container Ingress Services (CIS) 2.20.4
  • BIG-IP: Active-Standby HA pair
  • CIS connection: Floating Self IP configured as bigip-url

Cause

  • Token Manager logs showed CIS continuing to use the token issued by the previously Active BIG-IP after failover.
  • The AS3 POST returned 401 X-F5-Auth-Token does not exist until the token was refreshed.
  • A failover followed by a CIS deployment within roughly 30–60 seconds may fail, because AS3 on the new Active device may not be ready yet.
  • The 401 occurs because CIS reuses a token from the former Active device, or sends a deployment before AS3 on the new Active device is ready.

Answer/Recommended Actions

Method A: Wait for token expiry, then trigger a POST

  1. Wait for the token to expire (default is 20 minutes ).
  2. Trigger a configuration update so CIS sends a POST.
  3. CIS obtains a token from the newly Active BIG-IP.

Method B: Restart (roll out) CIS

kubectl -n kube-system rollout restart deploy/cis-k8s-f5-bigip-ctlr

Confirm the deployment name in your cluster before running the command.

Verification (read-only)

kubectl -n kube-system logs deploy/cis-k8s-f5-bigip-ctlr --since=3m | grep -Ei 'x509|certificate|tls|401|403|refused|timeout|\[ERROR\]|post resulted'

kubectl -n kube-system logs -f deploy/cis-k8s-f5-bigip-ctlr --timestamps | grep --line-buffered -E 'Token Manager|UNAUTHORIZED|post resulted|AS3\]\[POST\]'

kubectl get virtualserver <name> -n <namespace> -o yaml

Preventive measure

Avoid starting a CIS deployment within about 60 seconds of an HA failover. Confirm that the newly Active BIG-IP is responding before you change configuration.
