K000138750: Configure the Allowed IP Addresses on the VELOS system

Type
Knowledge
Published
2024-03-11
Updated
2025-06-06
Applies to
  • F5OS
  • F5OS-C: 1.8.X, 1.8.1, 1.8.0, 1.6.2, 1.6.0, 1.6.1, 1.6.X
Source

Topic

You should consider using this procedure under the following condition:

  • You want to restrict access to the management interface to only trusted sources.

Description

You can use the Allow IP Addresses feature on the VELOS system to restrict access to ports on the management interface to only trusted source IP addresses. The Allow IP Addresses feature only restricts access to the management interface and does not affect data plane traffic. You can add entries to the Allow IP Addresses to allow access from a specific IPv4 or IPv6 address or a range of IP addresses. In F5OS-C 1.6.0 and later, the Allow IP Addresses restricts access to the following ports on the VELOS system's management interface:

  • 22 (SSH)
  • 80 (HTTP)

    Note: The only purpose of port 80 (HTTP) is to redirect access to port 443 (HTTPS). The F5OS-C webUI and API is not available on port 80 (HTTP) directly.

  • 161 (SNMP)
  • 443 (HTTPS)
  • 7001-7008 (VCONSOLE)

    Note: If you are configuring VCONSOLE access to tenants that have instance ID other than 1, you must configure using either CLI or REST API. For information about accessing tenants' VCONSOLE, refer to K65442484: Overview of access to the F5 VELOS system.

  • 8888 (RESTCONF)

By default, the VELOS system does not impose any restriction on access to this list of ports except for port 161 (SNMP). For port 161 (SNMP), you have to configure an entry to the Allow IP Address feature before the VELOS system allows access. Note that you may need to perform additional SNMP configuration before you can perform an SNMP query to the VELOS system. For information about enabling SNMP on the VELOS system, refer to the VELOS F5OS SNMP Monitoring and Alerting guide.

Adding an entry for a specific port only restricts access for that port. If no other entries are configured, access to the other ports remains open. For example, if you configured only one entry with an IPv4 address 192.168.207.1, prefix length of 32 and port 443, then port 443 can only be accessed by IPv4 address 192.168.207.1 while all other IP address is denied access to port 443. There are no restrictions to the remaining ports in the list except for port 161 (SNMP).

Important: If you configure an entry with the value of All for the Port setting in the webUI or if you omit the port setting in the CLI/API, the VELOS system allows access to all ports in the list from the specific IP address or subnet. Any IP address that is not the configured IP address or not within the configured subnet will be denied access to all ports in the list. You should ensure you have added the IP address of the workstation you are configuring from and the relevant port(s); for example, port 443 for webUI and API or port 22 for SSH/CLI before you attempt to configure for other source IP address(es). Otherwise you should ensure you have console access to the VELOS system in case you need to recover access to the VELOS system.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the F5OS-C webUI, CLI and REST API.
  • If you are configuring using API from your local workstation, your local workstation should have the curl utility installed.
  • If you are configuring using CLI from your local workstation, your local workstation should have either the ssh utility installed or have console access to the VELOS system.

Procedure

  • Viewing the Allow IP Addresses entries on the VELOS system
  • Adding an entry to the Allow IP Addresses on the VELOS system
  • Modifying an entry to the Allow IP Addresses on the VELOS system
  • Deleting an entry to the Allow IP Addresses on the VELOS system

Viewing the Allow IP Addresses entries on the VELOS system

To view the existing entry/entries to the Allow IP Addresses, perform one of the following procedures:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the VELOS chassis or partition as the chassis or partition administrator.
  2. Navigate to SYSTEM SETTINGS -> System Security.
  3. The Allowed IP Addresses section displays the existing entry/entries.

Use the CLI

  1. Log in to the CLI of the VELOS chassis or partition as the chassis or partition administrator.
  2. To view the existing entry/entries to the Allow IP Addresses, enter the following command:

    show running-config system allowed-ips allowed-ip

    The output should appear similar to the following example:

    system allowed-ips allowed-ip allow_my_host
     config ipv4 address 192.168.207.1
     config ipv4 prefix-length 32
    !

Use the REST API

  1. Log in to a workstation with the curl utility installed.
  2. To view the existing entry/entries to the Allow IP Addresses, enter the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address>/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips"

    In the command syntax, note the following:

    • <management IP address> is the hostname or management IP address of the VELOS system.
    • <username> and <password> are the username and password combination that provides administrative access to the VELOS system. If you omit <password> the system will prompt for one.

    For example, you would enter the following command to list the entries from management IP address 192.168.81.108 using the admin user:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X GET "https://192.168.81.108/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips"

    Output should appear similar to the following example:

    Note: The command does not return an output if there are no existing entry to the Allow IP Addresses.

    {
      "f5-allowed-ips:allowed-ips": {
        "allowed-ip": [
          {
            "name": "allow_my_host",
            "config": {
              "ipv4": {
                "address": "192.168.207.1",
                "prefix-length": 32
              }
            }
          }
        ]
      }
    }

Adding an entry to the Allow IP Addresses on the VELOS system

To add an entry to the Allow IP Addresses, perform one of the following procedures:

Impact of procedure: Ensure you have entered the correct source IP address and port. Once you have saved the configuration, you may not be able to access the VELOS system management interface (webUI/CLI/API) if you are attempting to access from an IP address that is not within the configured source IP address or a port that is not within the configured port. Ensure the IP address of the workstation you are configuring from and the relevant port(s) is in the Allow IP Addresses; for example, port 443 for webUI and API or port 22 for SSH/CLI before you attempt to configure for other source IP address(es).

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the VELOS chassis or partition as the chassis or partition administrator.
  2. Navigate to SYSTEM SETTINGS -> System Security.
  3. Select Add under the Allowed IP Addresses section; webUI displays the Add Allow List Entry page.
  4. Enter an name for the Name setting.
  5. Select either IPv4 or IPv6 for the IPv4/IPv6 setting.
  6. Enter the source IP address you want to allow in the Address setting.
  7. Enter the netmask in the Prefix Length setting.
  8. Select an appropriate port to allow for the source IP address for the Port setting.

    Note: If you are configuring for VCONSOLE access to the tenants that have instance ID other than 1, you must configure using either CLI or API instead of webUI. The webUI only accepts configuring port 7001 for VCONSOLE access.

  9. Select Save & Close to save the changes.

Use the CLI

  1. Log in to the CLI of the VELOS chassis or partition as the chassis or partition administrator.
  2. To enter the configuration mode, enter the following command:

    config

  3. To add a new entry to the Allow IP Addresses, enter the following command syntax:

    system allowed-ips allowed-ip <entry name> config <ipv4|ipv6> address <source IP address> prefix-length <netmask> port <port>

    In the command syntax, note the following:

    • <entry name> is the name for the Allow IP Addresses entry.
    • <ipv4|ipv6> is the IP protocol; you can only select either ipv4 or ipv6.
    • <source IP address> is the source IP address or subnet to allow access.
    • <netmask> is the netmask of the source IP address or subnet. For example, the netmask should be 32 for a single source IP address. 
    • <port> is the port you want to allow access.

    For example,

    system allowed-ips allowed-ip ssh_access_only config ipv4 address 192.168.207.15 prefix-length 32 port 22

    Note: If you want to configure the port setting to All, you must omit the port setting.

  4. To commit the change and exit configuration mode, enter the following command:

    commit and-quit

Use the REST API

  1. Log in to a workstation with the curl utility installed.
  2. To add a new entry to the Allow IP Addresses, enter the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X POST "https://<management IP address>/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips" -d '{ "allowed-ip": [ { "name": "<entry name>", "config": { "<ipv4|ipv6>": { "address": "<source IP address>", "prefix-length": <netmask>, "port": <port> } } } ] }'

    In the command syntax, note the following:

    • <management IP address> is the hostname or management IP address of the VELOS system.
    • <username> and <password> are the username and password combination that provides administrative access to the VELOS system. If you omit <password> the system will prompt for one.
    • <entry name> is the name for the Allow IP Addresses entry.
    • <ipv4|ipv6> is the IP protocol; you can only select either ipv4 or ipv6.
    • <source IP address> is the source IP address or subnet to allow access.
    • <netmask> is the netmask of the source IP address or subnet. For example, the netmask should be 32 for a single source IP address. 
    • <port> is the port you want to allow access.

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X POST "https://192.168.81.108/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips" -d '{ "allowed-ip": [ { "name": "ssh_access_only", "config": { "ipv4": { "address": "192.168.207.15", "prefix-length": 32, "port": 22 } } } ] }'

    The command does not return an output. To verify whether the configuration was committed successfully, refer to Viewing the Allow IP Addresses entries on the VELOS system.

Modifying an entry to the Allow IP Addresses on the VELOS system

To modify an existing entry to the Allow IP Addresses, perform one of the following procedures:

Impact of procedure: Ensure you have entered the correct source IP address and port. Once you have saved the configuration, you may not be able to access the VELOS system management interface (webUI/CLI/API) if you are attempting to access from an IP address that is not within the configured source IP address or a port that is not within the configured port. Ensure the IP address of the workstation you are configuring from and the relevant port(s) is in the Allow IP Addresses; for example, port 443 for webUI and API or port 22 for SSH/CLI before you attempt to configure for other source IP address(es).

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the VELOS chassis or partition as the chassis or partition administrator.
  2. Navigate to SYSTEM SETTINGS -> System Security.
  3. Under the Allow IP Addresses section, select the entry you want to modify.
  4. Modify the settings as needed.
  5. Select Save & Close to save the changes.

Use the CLI

  1. Log in to the CLI of the VELOS chassis or partition as the chassis or partition administrator.
  2. To enter the configuration mode, enter the following command:

    config

  3. To modify an existing entry to the Allow IP Addresses, enter the following command syntax:

    system allowed-ips allowed-ip <entry name> config <ipv4|ipv6> address <source IP address> prefix-length <netmask> port <port>

    In the command syntax, note the following:

    • <entry name> is the name for the Allow IP Addresses entry.
    • <ipv4|ipv6> is the IP protocol; you can only select either ipv4 or ipv6.
    • <source IP address> is the source IP address or subnet to allow access.
    • <netmask> is the netmask of the source IP address or subnet. For example, the netmask should be 32 for a single source IP address. 
    • <port> is the port you want to allow access.

    For example, you would enter the following command to change the config from the previous example of allowing only one IP address 192.168.207.15 access port 22 to a range of IP addresses 192.168.207/24 access port 22:

    system allowed-ips allowed-ip ssh_access_only config ipv4 address 192.168.207.0 prefix-length 24 port 22

    Note: If you want to change the port setting to All, you must first remove the existing entry and configure a new entry without the port setting. This is because the CLI accepts only fixed port numbers, for example 22, 80, 161, 443. Alternatively, you can modify the entry to change the port setting to All using the webUI or API instead of using the CLI.

  4. To commit the change and exit configuration mode, enter the following command:

    commit and-quit

Use the REST API

  1. Log in to a workstation with the curl utility installed.
  2. To modify an existing entry to the Allow IP Addresses, enter the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X PATCH "https://<management IP address>/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=<entry name>/config" -d '{ "config": { "<ipv4|ipv6>": { "address": "<source IP address>", "prefix-length": <netmask>, "port": <port> } } }'

    In the command syntax, note the following:

    • <management IP address> is the hostname or management IP address of the VELOS system.
    • <username> and <password> are the username and password combination that provides administrative access to the VELOS system. If you omit <password> the system will prompt for one.
    • <entry name> is the name for the Allow IP Addresses entry.
    • <ipv4|ipv6> is the IP protocol; you can only select either ipv4 or ipv6.
    • <source IP address> is the source IP address or subnet to allow access.
    • <netmask> is the netmask of the source IP address or subnet. For example, the netmask should be 32 for a single source IP address. 
    • <port> is the port you want to allow access.

    For example, you would enter the following command to change the config from the previous example of allowing only one IP address 192.168.207.15 access port 22 to a range of IP addresses 192.168.207/24 access port 22:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PATCH "https://192.168.81.108/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=ssh_access_only/config" -d '{ "config": { "ipv4": { "address": "192.168.207.0", "prefix-length": 24, "port": 22 } } }'

    The command does not return an output. To verify whether the configuration was committed successfully, refer to Viewing the Allow IP Addresses entries on the VELOS system.

    If you are looking to change the port setting to All, then you should enter the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X DELETE "https://<management IP address>/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=<entry name>/config/<ipv4|ipv6>/port"

    In the command syntax, note the following:

    • <management IP address> is the hostname or management IP address of the VELOS system.
    • <username> and <password> are the username and password combination that provides administrative access to the VELOS system. If you omit <password> the system will prompt for one.
    • <entry name> is the name for the Allow IP Addresses entry.
    • <ipv4|ipv6> is the IP protocol; you can only select either ipv4 or ipv6.

    For example, you would enter the following command to change the port setting from the previous example of allowing IP address 192.168.207.15 access only port 22 to all ports:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X DELETE "https://192.168.81.108/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=ssh_access_only/config/ipv4/port"

    The command does not return an output. To verify whether the configuration was committed successfully, refer to Viewing the Allow IP Addresses entries on the VELOS system.

Deleting an entry to the Allow IP Addresses on the VELOS system

To delete an existing entry to the Allow IP Addresses, perform one of the following procedures:

Impact of procedure: Ensure you have deleted the correct source IP address and port. Once you have saved the configuration, you may not be able to access the VELOS system management interface (webUI/CLI/API) if you are attempting to access from an IP address that is not within the configured source IP address or a port that is not within the configured port. Ensure the IP address of the workstation you are configuring from and the relevant port(s) is in the Allow IP Addresses; for example, port 443 for webUI and API or port 22 for SSH/CLI before you attempt to configure for other source IP address(es).

  • Use the webUI
  • Use the CLI
  • Use the REST API

Use the webUI

  1. Log in to the webUI of the VELOS chassis or partition as the chassis or partition administrator.
  2. Navigate to SYSTEM SETTINGS -> System Security.
  3. Under the Allow IP Addresses section, check the entry you want to delete.
  4. Select Delete, then followed by OK to confirm the deletion.

Use the CLI

  1. Log in to the CLI of the VELOS chassis or partition as the chassis or partition administrator.
  2. To enter the configuration mode, enter the following command:

    config

  3. To delete an existing entry to the Allow IP Addresses, enter the following command syntax:

    no system allowed-ips allowed-ip <entry name>

    In the command syntax, note the following:

    • <entry name> is the name for the Allow IP Addresses entry.

    For example, you would enter the following command to remove the config from the previous example:

    no system allowed-ips allowed-ip ssh_access_only

  4. To commit the change and exit configuration mode, enter the following command:

    commit and-quit

Use the REST API

  1. Log in to a workstation with the curl utility installed.
  2. To delete an existing entry to the Allow IP Addresses, enter the following command syntax:

    curl -sku <username>:<password> -H "Content-Type: application/yang-data+json" -X DELETE "https://<management IP address>/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=<entry name>"

    In the command syntax, note the following:

    • <management IP address> is the hostname or management IP address of the VELOS system.
    • <username> and <password> are the username and password combination that provides administrative access to the VELOS system. If you omit <password> the system will prompt for one.
    • <entry name> is the name for the Allow IP Addresses entry.

    For example, you would enter the following command to remove the config from the previous example:

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X DELETE "https://192.168.81.108/api/data/openconfig-system:system/f5-allowed-ips:allowed-ips/allowed-ip=ssh_access_only"

    The command does not return an output. To verify whether the configuration was committed successfully, refer to Viewing the Allow IP Addresses entries on the VELOS system.
