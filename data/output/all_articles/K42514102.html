Topic

You should consider using this procedure under the following conditions:

  • You want to display all the properties of a virtual server including any attached policies in a single page of output.
  • You want to display virtual servers and only their attached policies.
  • You want to search for a specific policy and display the associated virtual server.

Description

When you use the Configuration utility to display a virtual server configuration, the Configuration utility does not list certain properties, such a local traffic policies, and you can only view them by going to the Resources tab of the virtual server. However, you can see all the basic properties or all properties of a virtual server in a single page of output using the TMOS shell (tmsh) or the iControl REST API. The output from these include the local traffic policies attached to the virtual server.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to tmsh.
  • You have access to the iControl REST API.
  • You have command-line access to a system with the jq utility for the last iControl REST procedure. For more information about the jq utility, refer to the jq manual.

Display basic properties, all properties, or only the policies of a virtual server in a single output using tmsh

When displaying a virtual server without a list option the system outputs the basic properties. You can expand property output with the all-properties option or narrow the output to a specific property by including the property such as policies in the command string.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Choose one of the following options:
    • To display all basic properties, use the following syntax:

      list /ltm virtual <virtual server name>

      For example:

      list /ltm virtual example_vs

    • To display all properties, use the following syntax:

      list /ltm virtual <virtual server name> all-properties

      For example:

      list /ltm virtual example_vs all-properties

    • To display only the policies for a virtual server, use the following syntax:

      list /ltm virtual <virtual server name> policies

      For example:

      list /ltm virtual example_vs policies

Display all virtual servers and only their attached policies or searching for a specific policy and displaying the associated virtual server using tmsh

By changing directory to the root administrative partition in tmsh and using the recursive option, you can recursively display all virtual servers in every partition you have access to, along with their attached policies. The one-line option displays the entire virtual server configuration in a single line, which makes it easier to search with grep for a policy and display the associated virtual server.

For example:

ltm virtual Common/example_vs { destination Common/172.16.1.207:http ip-protocol tcp last-modified-time 2019-04-19:14:44:12 mask 255.255.255.255 policies { Common/example_policy { } } profiles { Common/http-insert-headers { } Common/tcp { } } serverssl-use-sni disabled source 0.0.0.0/0 source-address-translation { type automap } translate-address enabled translate-port enabled vs-index 3 }

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Change directory to the root administrative partition by entering the following command:

    cd /

  3. Choose one of the following options:
    • To display all virtual servers in every partition you have access to and only their attached policies enter the following command:

      list /ltm virtual recursive policies

    • To search for a specific policy in every partition and display its associated virtual server by piping the output to the grep utility, use the following command syntax:

      list /ltm virtual recursive one-line | grep <policy name>

      For example:

      list /ltm virtual recursive one-line | grep example_policy

Display all properties or only the policies of a virtual server in a single output with the iControl REST API

By sending a request to the virtual server URI and including the expandSubcollections=true query string, you can display all the virtual server properties including the attached policies. You can narrow the output to a specific property by including the property in the URI.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a system you can use to access the iControl REST API on the BIG-IP system.
  2. Use curl or similar utility to make a request to the API choosing one of the following options:
    • To display all properties for a specific virtual server, use the following syntax:

      curl -sku <username>:<password> https://<IP address of BIG-IP>/mgmt/tm/ltm/virtual/~<partition>~<virtual server name>?expandSubcollections=true

      For example:

      curl -sku admin:admin https://192.0.2.1/mgmt/tm/ltm/virtual/~Common~example_vs?expandSubcollections=true

    • To display only the policies for a specific virtual server, use the following command syntax:

      curl -sku <username>:<password> https://<IP address of BIG-IP>/mgmt/tm/ltm/virtual/~<partition>~<virtual server name>/policies?expandSubcollections=true

      For example:

      curl -sku admin:admin https://192.0.2.1/mgmt/tm/ltm/virtual/~Common~example_vs/policies?expandSubcollections=true

Display all virtual servers that have attached policies or all virtual servers with a specific attached policy using the iControl REST API

By redirecting the output from a request to the virtual server URI to the jq utility and using its filter functionality, you can display all virtual servers which have attached policies in every partition you have access to and only their attached policies. To search for a policy and display the associated virtual server, you can redirect the virtual server URI output to the jq utility and use its select function.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to a system you can use to access the iControl REST API on the BIG-IP system.
  2. Use curl or similar utility to make a request to the API and pipe the output to the jq utility choosing one of the following options:
    • To display all virtual servers in every partition you have access to and only their attached policies, use the following command syntax:

      curl -sku <username>:<password> https://<IP address of BIG-IP>/mgmt/tm/ltm/virtual/?expandSubcollections=true | jq '.items[].policiesReference | select(.items != null) | .items[]'

      For example:

      curl -sku admin:admin https://192.0.2.1/mgmt/tm/ltm/virtual/?expandSubcollections=true | jq '.items[].policiesReference | select(.items != null) | .items[]'

    • To search for a specific policy and display its associated virtual servers, use the following command syntax:

      Note: Ensure that the filters for the jq utility and its pipe (|) operator and select functions are enclosed in the single quotation marks, as shown in the following command syntax.

      curl -sku <username>:<password> https://<IP address of BIG-IP>/mgmt/tm/ltm/virtual/?expandSubcollections=true | jq '.items[].policiesReference | select(.items != null) | .items[] | select(.name == "<policy name>")'

      For example:

      curl -sku admin:admin https://192.0.2.1/mgmt/tm/ltm/virtual/?expandSubcollections=true | jq '.items[].policiesReference | select(.items != null) | .items[] | select(.name == "example_policy")'
