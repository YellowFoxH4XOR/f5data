K000162643: CNF CGNAT 2.2.0 EHF1 dnsapp with transparent cache fails to forward resolver.arpa DNS requests to pool members

Type
Support Solution
Published
2026-07-29
Updated
2026-07-29
Applies to
  • BIG-IP Next CGNAT CNF: 2.2.0
  • BIG-IP Next CNF
Source
https://my.f5.com/manage/s/article/K000162643

Description

A transparent DNS cache may fail to load into TMM when a configured local-zone TXT record contains embedded double quotes, such as:

example.com. IN TXT "dummy"

The ingress component may report successful custom-resource processing, while the cache resolver is absent from TMM. DNS queries then fail to use the configured local-zone response.

Queries for _dns.resolver.arpa without a valid overriding local-zone configuration may receive a local Unbound response instead of being forwarded to the configured DNS pool.

Environment

  • BIG-IP Next CGNAT CNF
  • F5BigDnsApp
  • F5BigDnsCache
  • Transparent DNS cache
  • DNS listener with configured backend pool members
  • Local-zone records configured under F5BigDnsCache
  • TXT records containing embedded double quotes
  • Unbound reserved local zones, including:
    • resolver.arpa
    • service.arpa

Cause

Two separate behaviors can produce similar symptoms:

  1. Quoted TXT record configuration

    The ingress component inserts local-zone record strings into the TMM configuration message without properly escaping embedded double quotes. The resulting malformed JSON/gRPC message is rejected by TMM.

    The cache is therefore not created in TMM, even though the custom resource may appear to have been processed successfully.

  2. Unbound reserved local zones

    When no valid overriding local-zone configuration exists, queries for resolver.arpa are handled by Unbound’s built-in reserved local zone. These queries receive a local response and are not forwarded to the configured DNS pool.

    This behavior is expected for the built-in reserved zone and is independent of the quoted TXT record configuration problem.

Recommended Actions

  1. Review the F5BigDnsCache configuration for TXT records containing embedded double quotes.
  2. For single-word TXT values, remove the quotation marks. For example, change:

    - example.com. IN TXT "dummy"

    to:

    - example.com. IN TXT dummy

  3. Reapply the corrected F5BigDnsCache configuration.
  4. Verify that the cache resolver is present in TMM and that query and response counters increase.
  5. Review ingress logs if the cache is not created. A malformed configuration may generate an error similar to:

    invalid character 'd' after object key:value pair

  6. Test the configured local-zone record and confirm that the response is returned locally without being forwarded to the backend DNS pool.
  7. For _dns.resolver.arpa queries:
    • Configure a valid local zone if the query must be answered by the CNF cache.
    • Do not expect the query to be forwarded to the backend pool when it is handled by Unbound’s built-in resolver.arpa local zone.
    • answer-default-zones no does not disable the built-in reserved-zone behavior.
  8. Avoid quoted multi-word TXT values until a product fix for the configuration serialization issue is available. Multi-word TXT RDATA normally requires quotation marks, but the affected configuration path cannot safely process those values.

Verification

A valid local-zone configuration should produce the following results:

  • The cache resolver is present in TMM.
  • TMM query and response counters increase.
  • The configured local-zone response is returned to the client.
  • The query is not forwarded to the backend DNS pool when answered locally.

An immediate response containing an SOA with local host information, such as:

resolver.arpa. 10800 IN SOA localhost. nobody.example.net.

indicates that the response was generated locally by Unbound rather than returned by a backend pool member.
