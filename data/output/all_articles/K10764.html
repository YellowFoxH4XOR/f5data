Known Issue

This is the result of a known issue. The BIG-IP ASM system may incorrectly detect a cookie violation when the following conditions are met:

  • The BIG-IP ASM system is processing a 10 Kilobyte or larger POST request
  • The POST request is slow-to-arrive and there is a delay between incoming POST payload packets
  • One or both of the following blocking violations in the security policy is set to Alarm and/or Block:
    • Cookie not RFC-compliant
    • Modified domain cookie(s)

This issue occurs when the BIG-IP ASM system overwrites the cookie processing buffer for the POST with a subsequent request before the POST can be read by the BIG-IP ASM enforcement process thread. When this issue occurs, the BIG-IP ASM associates the incorrect cookie data with the POST request, and triggers one of the following violations:

  • Cookie not RFC-compliant
  • Modified domain cookie(s)

Note: The violation that is triggered depends on the particular blocking mask in the security policy.

F5 Product Development tracked this issue as ID 241783 (formerly CR131812) and it was fixed in BIG-IP ASM 10.2.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.8-385.0-HF2 issued for BIG-IP ASM 9.4.8, Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP ASM 10.0.1, and in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP ASM 10.1.0.
