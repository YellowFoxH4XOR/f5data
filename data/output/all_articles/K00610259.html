Known Issue

A Secure Sockets Layer (SSL) handshake fails if a server certificate contains multiple common names (CNs).

This issue occurs when all of the following conditions are met:

  • The external server certificate's Subject field contains multiple CNs.
  • The certificate does not contain a subjAltName extension (or if it does, the same names are not included in the subjAltName's dNSName list).

Impact

You cannot establish a connection with the external server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • SSL connections fail to establish. In the case of a forward proxy, a bypass or intercept fails.

Workaround

To work around this issue, you can perform one of the following recommendations that addresses the current configuration:

  • Forward proxy bypass configuration
  • Multiple CNs listed within the certificate

Impact of workaround: Performing the suggested actions should not have a negative impact on your system.

Forward proxy bypass configuration

In the case of a forward proxy bypass, configure an IP address bypass instead of a host name bypass, because the IP address bypass check occurs before the SSL handshake. Refer to the SSL Forward Proxy Bypass chapter of the BIG-IP Access Policy Manager: Secure Web Gateway Implementations manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Multiple CNs listed within the certificate

Update the external server's certificate to include the list of CNs in the subjAltName extension and list them as dNSName.
