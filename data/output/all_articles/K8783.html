K8783: Cluster or failover synchronization fails after installing OPSWAT 2.5.7

Resolution

This is the result of a known issue. If you install OPSWAT 2.5.7 (hotfix-99074) on a primary cluster node in a FirePass cluster configuration, or on an active controller in a FirePass high availability configuration, synchronization does not resume until you restart the primary cluster node or the active controller. Prior to FirePass version 6.0.1 with Cumulative HF-601-11 and FirePass version 6.0.2 with Cumulative HF-602-4, FirePass automatically restarted after installing an OPSWAT hotfix. Starting in FirePass version 6.0.1 with Cumulative HF-601-11 and FirePass version 6.0.2 with Cumulative HF-602-4, FirePass does not restart after installing an OPSWAT hotfix. Instead, FirePass reports a message that appears similar to the following example after the OPSWAT hotfix installation completes:

Update has been successfully installed
Reboot is not required by this update

Note: For more information, refer to K8629: Change in Behavior: OPSWAT hotfixes no longer require a restart.

FirePass prevents synchronization during a hotfix installation, and synchronization resumes after the FirePass controller restarts. When a restart is not required to complete the hotfix installation, the correct behavior is for FirePass to resume synchronization once the hotfix installation completes.

F5 Networks Product Development tracked this issue as CR99818 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue was fixed in hotfix-99915 (OPSWAT 2.5.7 Update) issued for FirePass version 6.0.1 and 6.0.2. You may download this hotfix or later versions of the OPSWAT hotfix from the F5 Networks Downloads site.

For instructions about obtaining and installing an OPSWAT hotfix, refer to K6664: Obtaining and installing OPSWAT hotfixes.

Workaround

In a cluster configuration, you can work around this issue by manually restarting the primary cluster node after installing an OPSWAT hotfix. In a high availability configuration, you can work around this issue by manually restarting the active node after installing an OPSWAT hotfix.

To restart the FirePass controller, click the Restart Controller link on the Device Management: Maintenance: Restart Services page in the FirePass Administrative Console.
