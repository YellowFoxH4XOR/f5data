Description

When applying an ASM policy to a virtual server, client connections to the application may be reset. This issue is observed during or after migration, particularly from Viprion to Virtual Edition (VE) platforms

 

/var/log/ts/asm_config_server.log

asm_config_server.pl|INFO|Jul 25 02:05:48.864|29939|F5::DbSync::_log_print,,Adding Policy '/common/test_policy' in ASM

asm_config_server.pl|INFO|Jul 25 02:05:48.865|29939|F5::ASMConfig::Handler::handle_error,,Failed add policy using on nonexistent record for PolicyTemplate

asm_config_server.pl|INFO|Jul 25 02:05:48.865|29939|F5::ASMConfig::Handler::log_error_and_rollback,,Could not add policy using the Policy Template 'test_Template', No matching record was found.

 

var/log/asm

Jul 25 02:15:19 test.lab info perl[29003]: 01310012:6: ASM bad request: event code I4681 Request has an unknown HTTP selector: /common/test_policy

 

Connection reset cause :

F5RST: Internal error (ASM requested abort (plugin abort error))

 

Environment

  • ASM policy
  • Migration from Viprion to VE
  • Missing or improperly loaded Policy Template

Cause

After migrating from a Viprion chassis to a VE deployment, policy templates referenced by ASM policies may not be properly carried over. While the configuration may reference the correct policy in bigip.conf, the associated template (example, 'test_Template') is either missing or not loaded correctly.

This results in:

  • The ASM module failing to apply the policy

  • Unexpected connection resets (RST packets)

  • Internal ASM errors during policy handling

 

 Recommended Actions

  1. Recreate the Missing Policy Template
    Manually re-create the policy template in the VE system if it no longer exists.
    Ensure it matches the name and structure expected by the applied policy.

  2. Check and Reload Configuration (if template exists)
    •  If the template exists in bigip.conf but isn't loading:

    • Reload the configuration using mcpd (K13030):
      tmsh load sys config

      Or restart the mcpd daemon if needed:
      bigstart restart mcpd

 

Note: Restarting mcpd may temporarily disrupt services. Perform this action during a maintenance window.

 

Additional Information

  • Best Practice During Migration: Always export and verify ASM policy templates alongside the policy itself when migrating between F5 systems.

  • Policy Consistency: Ensure all references in the policy (e.g., custom signatures, templates) exist and are valid in the target environment.

  • Backup First: Before modifying or reloading configurations, back up your current configuration
