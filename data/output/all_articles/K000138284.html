K000138284: BIG-IP traffic-group status may show both HA devices as active when management IP addresses are duplicated

Type
Support Solution
Published
2026-09-11
Updated
2026-09-11
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000138284

Description

The tmsh show cm traffic-group command may report both devices as active when HA group scores are equal and the peer device definitions contain duplicate management IP addresses.

Example output from one device:

 

CM::Traffic-Group
Name              Device      Status  Auto Failback  Failover Time (in sec)  Score
traffic-group-1   device-A    active  60              <score>
traffic-group-1   device-B    active  60              <score>
traffic-group-local-only -    -       60              -
The peer may report:

 

CM::Traffic-Group
Name              Device      Status   Auto Failback  Failover Time (in sec)  Score
traffic-group-1   device-A    standby  60              <score>
traffic-group-1   device-B    active   60              <score>
traffic-group-local-only -    -        60              -

 

Environment

  • High-availability pair
  • HA group associated with the traffic group

Cause

Both peer device definitions contain the same management IP address:

cm device /Common/device-A {
    management-ip 1.1.1.1
}

cm device /Common/device-B {
    management-ip 1.1.1.1
}

 

When HA group scores are equal, BIG-IP uses the failover score, which includes the management IP address, as a tie-breaker when selecting the next-active device. Duplicate management IP addresses prevent the devices from being uniquely distinguished and can result in inconsistent traffic-group status or an Active/Active indication.

Recommended Actions

Assign a unique management IP address to each device in the HA pair.
