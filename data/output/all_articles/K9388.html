Topic

This article applies to BIG-IP ASM 9.4.x - 10.x. For information about other versions, refer to the following articles:

• K14211: Using an iRule to parse post-ASM requests and responses (11.x)

Starting in BIG-IP ASM 9.4.2, the BIG-IP ASM module is a traffic plugin that hooks directly into the Traffic Management Microkernel (TMM) data path. With the introduction of the BIG-IP plugin architecture, response-based iRule events are triggered after the server response but before the plugin has manipulated the response.

For example, the HTTP_RESPONSE iRule event is triggered after the BIG-IP system parses all of the response status and header lines from the server, but before the BIG-IP ASM module manipulates the response. Note: In BIG-IP 9.4.1 and earlier, response-based iRule events set with a low priority (such as HTTP_RESPONSE priority 1000), are triggered after the BIG-IP ASM system has manipulated the response.

Defining a VIP-to-VIP configuration to parse the post-ASM processing response

VIP-to-VIP is a configuration in which two virtual servers can be used to parse the post Big-IP ASM processing response. The "front" virtual server hosts the post BIG-IP ASM processing iRule, and the "back" virtual server contains the BIG-IP ASM-enabled HTTP Class. To define a VIP-to-VIP configuration, use configuration elements similar to the following:

Configuring the iRule

Configure an iRule that performs post BIG-IP ASM processing and associate the iRule with the "front" virtual server. For example, to define an iRule which parses the post BIG-IP ASM response and logs the BIG-IP ASM cookie to the /var/log/ltm file, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Enter a name for the iRule.

    For example:

    post_asm_irule

  6. Enter the following iRule in the Definition box:

    when RULE_INIT {
    # Define a global variable which references the ASM-enabled VIP name
    set ::targetvip "back_vip"
    }

    when HTTP_REQUEST {
    virtual $::targetvip
    }

    when HTTP_RESPONSE {
    # Define the post-ASM response action
    set myValues [HTTP::header values Set-Cookie]
    log local0. "\[HTTP::header values Set-Cookie\]: $myValues"
    }

Configuring the "front" virtual server

Configure the virtual server that references the post_asm_irule iRule. For example, to define a "front" virtual server that processes connection requests from clients, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Create.
  5. Enter a name for the virtual server.

    For example:

    front_vip

  6. Enter the virtual server address and port.

    For example:

    172.29.24.226:http

  7. From the Configuration menu, select Advanced.
  8. From the HTTP profile menu, select http.
  9. From the SNAT Pool menu, select automap.
  10. In the iRules section, click the iRule that you defined in the previous procedure, and move it to the Enabled window.
  11. Click Finished.

The virtual server should appear similar to the following example:

virtual front_vip {
snat automap
destination 172.29.24.226:http
ip protocol tcp
rules post_asm_irule
profiles
http
tcp
}

Configuring the "back" virtual server

Configure the virtual server which references the BIG-IP ASM-enabled HTTP Class. For example, to define a "back" virtual server which sends connections through the BIG-IP ASM module, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Create.
  5. Enter a name for the virtual server.

    For example:

    back_vip

  6. Enter the virtual server address and port.

    For example:

    172.29.24.225:http

  7. From the Configuration menu, select Advanced.
  8. From the HTTP profile menu, select http.
  9. From the SNAT Pool menu, select automap.
  10. In the HTTP Class Profiles section, click the appropriate HTTP Class that directs requests to the security policy, and move it to the Enabled window.
  11. Click Finished.

The virtual server should appear similar to the following example:

}
virtual back_vip {
snat automap
pool testpool
destination 172.29.24.225:http
ip protocol tcp
httpclass abc_class
profiles
http
tcp
}

The previous configuration allows the iRule to perform post BIG-IP ASM processing and log the BIG-IP ASM cookie header, which is sent to the client, to the /var/log/ltm file.

For example:

tmm tmm[1602]: Rule front_vip <HTTP_RESPONSE>: [HTTP::header values Set-Cookie]: {SESSION=5acc37bc2de7ad58d5077788b5387b72; path=/} {TSb950f4=caf35f0d7e504fe92e6667802886299d9665fa4ac1ecb75d4919b8abc38daefa0007083d; Path=/}
