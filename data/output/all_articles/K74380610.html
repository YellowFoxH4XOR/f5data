K74380610: Virtual server resets connection when receiving HTTP request with a long URI

Type
Support Solution
Published
2021-06-18
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • VIPRION Platforms
  • Public Cloud
  • Private Cloud
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K74380610

Description
HTTP requests with a request line that is 1404 or more characters long receive a connection reset instead of being sent to the backend server. Requests with a shorter URI length are proxied to the pool members as expected.

When enabling reset cause logging or viewing a packet capture taken on the BIG-IP with TMM noise enabled,  you see the following reset cause:
HTTP Blocking a request during body processing

Environment

  • BIG-IP version 13.1.3.4
  • Virtual server with HTTP profile
  • tmm.http.rfc.enforcement db variable set to enable

Cause
Bug ID 946581

Recommended Actions
Upgrade to a fixed BIG-IP version

Additional Information
You can verify the value of the relevant database variable with this command:
# tmsh list sys db tmm.http.rfc.enforcement
sys db tmm.http.rfc.enforcement {
    value "enable"
}
