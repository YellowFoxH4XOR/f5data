Known Issue

Note: BIG-IP 11.x is not affected by this issue. The bigpipe command is removed from BIG-IP software starting in 11.0.0.

This is the result of a known issue. If you encounter an error during the initial base configuration load after an upgrade to BIG-IP 9.4.2 or later, several of the bigpipe commands will not function. As a result, a bigpipe parsing error message displays

The following bigpipe commands are affected by this issue:

  • cli
  • configsync
  • confpp
  • daemon
  • dns
  • failover
  • httpd
  • logrotate
  • ltm
  • ntp
  • password
  • persist
  • profile
  • remoteusers
  • remoterole
  • snmpd
  • sshd
  • statemirror
  • syslog
  • system

For example, you may encounter this issue if you upgrade to BIG-IP 9.4.2 or later, and state mirroring configuration is allowed on the management interface for the version you were upgrading from. The initial base configuration load will fail because state mirroring configuration is no longer allowed on the management interface. As a result, typing the bigpipe system hostname command will display an error message that appears similar to the following example:

BIGpipe parsing error:
012e0008:3: The requested command (system) is invalid

F5 Product Development is tracking this issue as ID 248446 (formerly CR87226).

Workaround

You can work around this issue by recovering the functionality for the bigpipe commands. To do so, you must manually correct the issue that is causing the configuration load to fail. You can determine the error that causes the configuration load to fail by entering the following command:

bigpipe load

Once you have manually corrected the issue and reloaded the configuration successfully, the bigpipe commands will continue to function properly, even if subsequent configuration failures occur.
