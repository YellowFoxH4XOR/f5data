K000161624: HSL publisher naming convention in f5ingress causes iRule to fails in f5-tmm

Description

In BIG-IP Next CNF (Container Networking Functions) / SPK, iRules that use the HSL::open command to reference an HSL (High-Speed Logging) publisher by its configured name fail at runtime with a TCL error indicating the publisher is unavailable.

Symptoms

The following TCL error appears in the system logs:

01220001:3: "ErrorMessage"="<iRule_name> <EVENT> - publisher unavailable: <publisher_name> (line N)
    invoked from within
    \"HSL::open -publisher \"<publisher_name>\"\""

Example log entry:

<131>Jul  9 19:14:26 f5-tmm-c6c79df7-wg886 tmm1[24]: 01220001:3:
"ErrorMessage"="select-snatpool <CLIENT_ACCEPTED> - publisher unavailable: publisher1 (line 5)
    invoked from within
    \"HSL::open -publisher \"publisher1\"\""

Environment

  • Product: BIG-IP Next CNF / SPK (Modular BIG-IP)
  • Component: f5ingress / f5-tmm
  • Affected Version: SPK/CNF 1.4.0 / 2.0.0

Cause

The f5ingress component automatically appends the suffix -hslpublisher to the HSL publisher name when translating the F5BigLogHslpub Kubernetes custom resource into the internal gRPC declaration sent to f5-tmm.

For example, a publisher defined with metadata.name: publisher1 is registered in f5-tmm as publisher1-hslpublisher, as visible in the gRPC message:

{
  "@type": "declTmm.hsl_publisher",
  "id": "default-publisher1-hsl-publisher",
  "name": "publisher1-hslpublisher"
}

This behavior differs from Classic BIG-IP, where the publisher name used in HSL::open matches the configured object name exactly. iRules migrated from Classic BIG-IP or written following standard TMSH documentation will not include the -hslpublisher suffix and will therefore fail.

Impact

Any iRule using HSL::open -publisher "<name>" without the -hslpublisher suffix will fail to open the HSL queue. HSL logging will not function, and a TCL error will be logged for every connection that triggers the iRule event.

Workaround

Append -hslpublisher to the publisher name in all HSL::open calls within iRules deployed on BIG-IP Next CNF / SPK.

Incorrect (fails):

when CLIENT_ACCEPTED {
    set hsl [HSL::open -publisher "publisher1"]
}

Correct (works):

when CLIENT_ACCEPTED {
    set hsl [HSL::open -publisher "publisher1-hslpublisher"]
}

The general naming convention is: HSL::open -publisher "<F5BigLogHslpub_metadata_name>-hslpublisher"

Fix

No code fix is available. Bug ID 1980681 was resolved as WONTFIX because SPK/CNF 2.0.0 is no longer a supported release. The workaround above is the only available mitigation.
