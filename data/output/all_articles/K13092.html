Topic

Depending on your requirements for securing networked systems to meet organizational security policies and industry standards, such as PCI compliance, you may want to modify the amount and types of access available on a default BIG-IP configuration.

You should consider using the following recommendations under the following conditions:

  • You want to review or improve your currently configured access controls for the BIG-IP system.
  • You want to secure access to the BIG-IP system during initial setup.

Description

Each of the following sections provides information regarding access controls for various parts of the BIG-IP configuration. You can evaluate each of the sections to determine if the specific configuration modification is appropriate for your environment.

  • Managing passwords and user accounts
  • Managing network access
  • Managing administrative ports access
  • Managing services
  • Monitoring login attempts

Managing passwords and user accounts

F5 strongly recommends that you modify the passwords for BIG-IP maintenance accounts from their default values. During installation, the BIG-IP system creates a default root user called root, with the default password default and a default administrative user called admin, with the default password admin. Strong passwords are fundamental to mitigating automated brute-force login attacks. For information about how to modify passwords, refer to the following articles:

  • K13121: Changing system maintenance account passwords 
  • K3350: Changing system maintenance account passwords (9.x - 10.x)

You have the option to create a security policy for generating passwords for local BIG-IP system user accounts. For information about how to configure secure password policy, refer to the following articles:

  • K15497: Configuring a secure password policy for the BIG-IP system
  • K5962: Configuring a secure password policy for the BIG-IP system (9.x - 10.x)

In addition, if a user account is not actively in use, you should remove it to prevent any possibility of inappropriate use. If necessary, you can also disable the administrator and root accounts or remove the default BIG-IP administrative user.  For more information, refer to the following articles:

  • K15632: Disabling the admin and root accounts using the Configuration utility or tmsh
  • K14943: Removing the default BIG-IP administrative user

Managing network access

Port lockdown controls network ports that are accessible on a self IP. F5 recommends that you review and determine if the port lockdown setting follows the idea behind the principle of least privilege. For example, an organization may require that the allowed ports to be more, less, or exactly what the Allow Default setting is. By default, the BIG-IP system allows access to only a limited set of the available ports, and the default set includes those ports required for administrative access and inter-device communication, such as in a high-availability configuration.

For example:

  • Port 4353 allows BIG-IP DNS deployments to transfer sync-group data.
  • Port 443 allows access to the Configuration utility on a Traffic Management Microkernel (TMM) switch interface and the management (MGMT) interface.
  • Port 22 allows access to the command line on a TMM switch interface and the MGMT interface.

Important: F5 strongly recommends that you consult your corporate business and security policies for guidelines regarding enabling administrative ports on self IP interfaces that are accessible to the Internet. More specifically, F5 strongly recommends that you consider disabling administrative ports (443 and 22), either directly or through an intermediate NAT device or firewall, on any self IP interfaces that are accessible to the Internet when there are no operational requirements for such access.

The default port lockdown configuration and information regarding modifying the port lockdown settings for a given interface are available in the following articles:

  • K17333: Overview of port lockdown behavior (12.x - 21.x)
  • K13250: Overview of port lockdown behavior (10.x - 11.x)
  • K7317: Overview of port lockdown behavior (9.x)

While some ports may need to be open to ensure a properly-functioning configuration, you can use packet filters to further control access to these ports, based on combinations of criteria that include source IP address, destination IP address, MAC address, and so on. For more information about enabling packet filters, refer to K13383: Configuring CIDR Network Addresses for the BIG-IP packet filter.

Managing administrative ports access

F5 recommends that you limit the exposure of administrative ports to only trusted and allowed IP addresses or IP ranges. A BIG-IP system provides administrative access to the Configuration utility and the Secure Shell (SSH). By default, the current list allows all IP addresses to connect to the Configuration utility and SSH.

Restricting access is important to avoid security threats such as DoS attacks or brute force attacks against the management interface, which may overload the system and cause instability.

For information about restricting access to the management interface in BIG-IP 14.1.0 or later using network firewall rules, refer to K46122561: Restricting access to the management interface using network firewall rules.

Using AAA servers for restricting user accounts allowed to log in via the management interface is advisable but cannot be a substitute to limiting physical access to the management interface.

For information about how to restrict access to the Configuration utility by source IP address, refer to the following articles:

  • K13309: Restricting access to the Configuration utility by source IP address
  • K7448: Restricting access to the Configuration utility by source IP address (9.x - 10.x)

For information about how to restrict access to SSH by source IP address, refer to the following article:

  •  K5380: Specifying allowable IP ranges for SSH access

Managing services and add-on modules

To further limit access to the BIG-IP system, you can disable unused services in your current configuration. You can disable primary services from the command line using the bigstart utility, and you can manage secondary services through the Configuration utility. For complete details on the individual services and on using bigstart and the Configuration utility to manage services, refer to the following articles:

  • K48615077: BIG-IP daemons (15.x - 21.x)
  • K67197865: BIG-IP daemons (14.x)
  • K05645522: BIG-IP daemons (13.x)
  • K89999342: BIG-IP daemons (12.x)
  • K13444: BIG-IP daemons (11.x)
  • K8035: BIG-IP daemons (9.x - 10.x)

You can also disable unused licensed add-on modules on the BIG-IP system by unprovisioning them. For more information about unprovisioning licensed add-on modules, refer to K12111: Provision licensed BIG-IP modules.

Monitoring login attempts

F5 strongly recommends that you closely monitor login attempts to the BIG-IP system. Distributed brute-force login attacks use automated botnets to repeatedly attempt to log in to target hosts using a dictionary of potential usernames and passwords. If a weak password exists on user accounts configured on any system with public internet access, the password may be guessed. There is no way to completely prevent brute-force password attacks, but it is possible to mitigate the risk of such attacks with the recommendations in this article.

Other than applying mitigation techniques, monitoring login attempts to your system remains an important part of network security, and F5 strongly recommends that you monitor login attempts to your BIG-IP system on an ongoing basis for the possibility of any unauthorized access. The following list includes several, but not all, conditions that may indicate a brute-force attack:

  • A large number of failed logins from the same IP address
  • Login attempts with multiple accounts from the same IP address
  • Login attempts for a single account coming from many different IP addresses
  • Failed login attempts from alphabetically sequential account usernames

For information about how to monitor successful and failed login attempts to your BIG-IP system, refer to the following articles:

  • K13426: Monitoring login attempts on BIG-IP system
  • K10261: Monitoring login attempts (9.x - 10.x)
