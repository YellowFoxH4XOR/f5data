Source

Description

Would like to modify the ASM's Response and Blocking pages using the REST API.

Environment

  • ASM
  • Response and Blocking Pages - Regular or AJAX
  • REST API

Cause

None

Recommended Actions

To modify a blocking page using the REST API, send a PATCH to /mgmt/tm/asm/policies/{policy id}/response-pages/{response page id}.

Example 1 "Regular Response Page"

An example below illustrates how to achieve this.

Note: In the example, the policy name is scott_policy and we are modifying the default blocking page to Redirect URL from BIG-IP's bash. "admin:password" does not require modification.

1. Retrieve the policy ID by sending a GET request to /mgmt/tm/asm/policies:

curl -sku admin:password 'https://localhost/mgmt/tm/asm/policies?%24select=name%2Cid&%24filter=name%20eq%20scott_policy' | jq .

Response:

{
  "kind": "tm:asm:policies:policycollectionstate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies?$select=name%2Cid&ver=15.1.1&$filter=name%20eq%20scott_policy",
  "totalItems": 1,
  "items": [
    {
      "kind": "tm:asm:policies:policystate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ?ver=15.1.1",
      "name": "scott_policy",
      "id": "J6TXJCszaX5qUf0sMOI0EQ"        <----
    }
  ]
}


**Note: If the policy name contains characters such as the dot "." the policy name will need to be single quoted and the single quotes escaped.

Examples for policy name 'test.local.com':

$ curl -sku admin:password 'https://localhost/mgmt/tm/asm/policies?$select=name,id&$filter=name+eq+'\'test.local.com\' | jq -r '.items[]|[.name, .id, .selfLink]'
[
  "test.local.com",
  "YQn-f-VsZZmxoMJzlR7PPg",        <----
  "https://localhost/mgmt/tm/asm/policies/YQn-f-VsZZmxoMJzlR7PPg?ver=14.1.0"
]

Fully escaped example:

$ curl -sku admin:password https://localhost/mgmt/tm/asm/policies?\$select=name,id\&\$filter=name+eq+\'test.local.com\' | jq -r '.items[]|[.name, .id, .selfLink]'
[
  "test.local.com",
  "YQn-f-VsZZmxoMJzlR7PPg",        <----
  "https://localhost/mgmt/tm/asm/policies/YQn-f-VsZZmxoMJzlR7PPg?ver=14.1.0"
]

2. Get the response page ID in that policy for default blocking page, by sending a GET to /mgmt/tm/asm/policies/{policy id}/response-pages

curl -sku admin:password 'https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages?%24filter=responsePageType%20eq%20default' | jq .

Response:

{
  "kind": "tm:asm:policies:response-pages:response-pagecollectionstate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages?ver=15.1.1&$filter=responsePageType%20eq%20default",
  "totalItems": 1,
  "items": [
    {
      "kind": "tm:asm:policies:response-pages:response-pagestate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages/xMpCOKC5I4INzFCab3WEmw?ver=15.1.1",
      "responseActionType": "default",
      "responsePageType": "default",
      "lastUpdateMicros": 1613041232000000,
      "id": "xMpCOKC5I4INzFCab3WEmw"        <----
    }
  ]
}

Note: You will only see some properties if they already differ from the defaults.

3. Send a PATCH to /mgmt/tm/asm/policies/{policy id}/response-pages/{page id}, changing response type from default to redirect

curl -sku admin:password -X PATCH 'https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages/xMpCOKC5I4INzFCab3WEmw' --data '{
"responseRedirectUrl": "www.example.com",
"responseActionType": "redirect"
}' | jq .

Response:

{
  "kind": "tm:asm:policies:response-pages:response-pagestate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages/xMpCOKC5I4INzFCab3WEmw?ver=15.1.1",
  "responseRedirectUrl": "www.example.com",     <----
  "responseActionType": "redirect",             <----
  "responsePageType": "default",
  "lastUpdateMicros": 1613041283000000,
  "id": "xMpCOKC5I4INzFCab3WEmw"
}

Note: You can also have the body in a separate file and reference it with curl, e.g. --data @<filename>

4. Apply the policy by sending a POST to /mgmt/tm/asm/tasks/apply-policy, with the id of the policy in the body:

curl -sku admin:password -X POST https://localhost/mgmt/tm/asm/tasks/apply-policy --data '
{
    "policyReference": {
        "link": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ"       <----
        }
}' | jq .

Response:

{
  "kind": "tm:asm:tasks:apply-policy:apply-policy-taskstate",
  "selfLink": "https://localhost/mgmt/tm/asm/tasks/apply-policy/r_OWYM9GTMEMsdUskS4axw?ver=15.1.1",
  "policyReference": {
    "link": "https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ?ver=15.1.1",
    "fullPath": "/Common/scott_policy"
  },

  "id": "r_OWYM9GTMEMsdUskS4axw",
  "startTime": "2021-02-11T11:01:41Z",
  "lastUpdateMicros": 1613041301000000
}

5. Confirm the change has been effected by repeating the GET to /mgmt/tm/asm/policies/{policy id}/response-pages

curl -sku admin:password 'https://localhost/mgmt/tm/asm/policies/J6TXJCszaX5qUf0sMOI0EQ/response-pages?%24filter=responsePageType%20eq%20default' | jq .

Response:

Example 2 "Enabling and modifying AJAX Response Page"

An example below illustrates how to achieve this.

Note: In the example, the policy name is test_policy, we are enabling and modifying the AJAX Default Response Page's Popup Message from BIG-IP's bash. "admin:password" does not require modification.

1. Retrieve the policy ID by sending a GET request to /mgmt/tm/asm/policies:

curl -sku admin:password 'https://localhost/mgmt/tm/asm/policies?%24select=name%2Cid&%24filter=name%20eq%20test_policy' | jq .

Response:

{
  "kind": "tm:asm:policies:policycollectionstate",

      "name": "test_policy",

Note: See policy name note and examples from Example 1 is policy name contains characters such as the dot "."
