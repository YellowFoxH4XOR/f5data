Description

In certain cases, parameters and URLs in a BIG-IP ASM/Advanced WAF policy may be automatically removed by Policy Builder. This behavior can occur when traffic used for learning is classified as originating from automated clients (bots) and the setting “Learn only from non-bot traffic” is enabled. As a result, legitimate application parameters or URLs may not be updated in the policy and may eventually be removed, potentially causing application issues.


Environment

  • BIG-IP ASM or Advanced WAF
  • Policies using Automatic Learning mode
  • Policies with Learn only from non-bot traffic enabled


Cause

When Learn only from non-bot traffic is enabled, Policy Builder excludes requests that are classified as automated or bot-generated based on their User-Agent string or other detection methods.


If application traffic relies on non-browser User-Agents (for example, APIs using libraries such as axios, curl, or custom clients), Policy Builder will not update parameters or URLs learned only from this traffic. Over time, Policy Builder may consider these parameters/URLs unused and remove them from the policy. This can lead to unexpected application downtime if those parameters/URLs are required for normal functionality.


Recommended Actions

To prevent this issue:


  • Disable Learn only from non-bot traffic if your application relies on API clients, mobile apps, or other automated traffic patterns.


  • If the policy is already mature and stable:
    • Consider disabling automatic policy building to avoid unexpected policy changes.
    • Manually maintain parameters and URLs to ensure application stability.


Additional Information

Policy Builder uses request classification (based on User-Agent and other factors) to determine which traffic is trusted for learning.


Automated clients (e.g., axios/0.19.2, curl, test frameworks) are typically categorized as bots and ignored if the above option is enabled.


This behavior is expected when the configuration is set to exclude bot traffic from learning.
