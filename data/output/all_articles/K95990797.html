K95990797: Recovering StatefulSet pods in Aspen Mesh from CrashLoopBackOff errors

Type
Support Solution
Published
2022-01-21
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K95990797

Description

The following example shows that after going through the logs on pods with volumes, the errors were thrown with the specific compaction log files:

ERROR [main] 2021-12-30 01:22:09,152 LogTransaction.java:497 - Unexpecteddisk state: failed to read transaction log[md_txn_compaction_b49c57d0-62f4-11ec-b238-ed6de66b875e.log in/opt/cassandra/data/data/system/local-7ad54392bcdd35a684174e047860b377]Files and contents follow:ERROR [main] 2021-12-30 01:22:09,155 CassandraDaemon.java:803 - Cannotremove temporary or obsoleted files for system.local due to a problem withtransaction log files. Please check records with problems in the logmessages above and fix them. Refer to the 3.0 upgrading instructions inNEWS.txt for a description of transaction log files.

In the above error, we can see the location of log file. In these cases, either you can log into your Persistent Volume (PV) to run repair commands following the official Cassandra documentation or you can delete the compaction log file from the PV.

Environment

  • Aspen Mesh: 1.9.x

Cause

None

Recommended Actions

In cases where the status of the pod is CrashLoopBackOff and you are not able to log into the shell of the pod, we would need to find ways to debug the PV where our data is stored. In Aspen Mesh, we have two StatefulSet with three replicas for each one:

> kubectl get sts -n istio-system

NAME                       READY   AGE
aspen-mesh-event-storage   3/3     38d
istiod-cassandra           3/3     38d

When querying the istio-system namespace, we see six pods with each having PV attached to them:

> kubectl  get pods -n istio-system   | grep 'istiod-cassandra\|aspen-mesh-event-storage'

In the above example, PV pvc-67ada514-5817-4473-bb00-ca6f97ae7f65 is associated with claim data-aspen-mesh-event-storage-0. You would need these values to create your debug pod.

Here are the steps to move the PV from the StatefulSet to a debug pod from where we can access it:

  1. Scale down the StatefulSet to 0 replicas:

    > kubectl scale --replicas=0 statefulset/aspen-mesh-event-storage -n istio-system

  2. Once you know the claim being used, you would need to create a pod with the following specifications which mounts the PV that is having issue to a debug pod:

    kind: Pod
    apiVersion: v1
    metadata:
      name: volume-debugger. # you can name this whatever is appropriate
      namespace: istio-system
    spec:
      volumes:
        - name: pvc-67ada514-5817-4473-bb00-ca6f97ae7f65. 
          persistentVolumeClaim:
           claimName: data-aspen-mesh-event-storage-0.  # name of the claim from the previous step
      containers:
        - name: debugger
          image: busybox.# I am using a busybox image, you can use curl image if you want
          command: ['sleep', '3600']
          volumeMounts:
            - mountPath: "/data"
              name: pvc-67ada514-5817-4473-bb00-ca6f97ae7f65 # name of the claim 

  3. Exec into the pod and go to the mountPath directory:

    > kubectl exec –it volume-debugger –n istio-system – sh
    > cd /data

  4. In this case, we decided to delete the compaction file that was throwing an error:

    > rm /data/system/local-7ad<truncated>/md_txn_compaction_<truncated>.log

  5. Exit the volume debugger pod and delete it:

    > kubectl delete volume-debugger –n istio-system

  6. After removing the affected files, we would scale the StatefulSet back to three replicas:

    > kubectl scale --replicas=3 statefulset/aspen-mesh-event-storage -n istio-system

Additional Information

To use the nodetool command to repair the node, you would need a running Casssandra pod. But in this case, our pod was in CrashLoopBackOff, so we were not able to use that. Hence, we took the route of deleting the files. For more details, refer to the error message article. We recommend to setup backups for your databases used in Aspen Mesh.
