K000152237: Why are request body parameters not explicitly created in BIG-IP ASM/WAF API Security policies when using OpenAPI schema files?

Description

Parameters included in the request body—defined as "in": "body" in OpenAPI 2.x or under "requestBody" in OpenAPI 3.x—are not created as individual parameters in the security policy. As a result, you cannot configure their attributes in the same way as you can for query, path, header, or formData parameters.

When creating an API security policy using an OpenAPI schema file on BIG-IP Advanced ASM/WAF, the handling of parameters depends on how they are defined in the schema. Parameters specified as "in": "query", "in": "path", "in": "header", or "in": "formData" are correctly mapped to individual parameters within the security policy, allowing for their attributes to be configured. K81943444: OpenAPI Specification (OAS) to Advanced WAF / ASM parameter mapping

Environment

  • BIG-IP ASM/WAF
  • Creating API Security Policies via OpenAPI Schema Files
  • Swagger

Cause

According to the OpenAPI specification, parameters defined as "in": "body" (OpenAPI 2.x) or under "requestBody" (OpenAPI 3.x) are validated based on the JSON schema associated with each endpoint in the specification file.

In BIG-IP Advanced ASM/WAF, these body parameters are not created as individual configurable parameters within the security policy. Instead, the system enforces validation using the schema defined for the request body under each URL path. (Each URL will be created with it's own Content-Profile and a schema) 

Any input that does not conform to the defined schema will be flagged as illegal or blocked, depending on the policy’s learning and enforcement settings.If strict validations are required, include them in the OpenAPI schema file itself. This will ensure they are reflected in the generated JSON schema profile.

Recommended Actions

None, functioning by design.

Additional Information

BIG-IP ASM/WAF does not require any custom syntax for OpenAPI (Swagger) specification files. The file must simply adhere to the official OpenAPI Specification (OAS) standards. As long as the schema is valid according to OAS 2.0 or 3.x, it can be used directly to create an API security policy on the system. OpenAPI Specification
