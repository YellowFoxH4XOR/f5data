Description
After retrieving a the displayName from a LDAP query which contains special characters with UTF8 encoding, the resulting string is in hex format

Environment

  • BIG-IP APM
  • AD/LDAP query response
  • special characters with UTF8 encoding

Cause
Any string retrieved via a AD/LDAP query that contains special characters will be presented as hex
For example if the displayName is "X Æ A-12" it will be presented as 0x5820c38620412d3132

Recommended Actions

  1. Open the VPE for the impacted policy
  2. Insert a variable assign on the successful branch immediately after the AD/LDAP query, where the displayName had been fetched 
  3. In the variable assign window, click Add new entry,

     
     
  4. Click Change on the line that appears

     
     
  5. In the left pane, select 'Custom Variable' and 'Unsecure' 
  6. Enter the value: session.custom.displayName
  7. In the right pane, select 'Custom Expression'
  8. Enter the value: mcget -decode {session.ad.last.attr.displayName}

     
     
  9. Click Finished

Additional Information
This solution is not just limited to session variables that have been retrieved by a AD/LDAP query, it can apply anywhere.
Also, when implementing the solution, multiple variables can be converted in the same variable assign activity.
