K000138746: iRule event LB_FAILED not working as expected if pool has connection limits

Type
Support Solution
Published
2024-02-28
Updated
2024-02-29
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.9
Source
https://my.f5.com/manage/s/article/K000138746

Description

When a pool is configured with a connection limit to trigger iRule event when the connection reaches the limit, you would expect that an LB_FAILED event is generated. However,  instead of LB_FAILED event we see the request is sent a reset. 

Environment

  • iRule event LB_FAILED
  • Pool configuration
  • Connection limit
  • HTTP profile
  • Fallback-host

Cause

The issue is caused by ID 1497369, http redirect not always working when there is a http profile fallback-host.  

Recommended Actions

  • Workaround
  1. Set the fallback-host to /
  2. The request that hits the connection limit will be redirected to [HTTP::protocol]::/[HTTP::host]/
  3. The redirected request will generate an LB_FAILED event and iRule will process as expected
  • Alternatively you can contact F5 Support to request an Engineering Hotfix for this issue.

Additional Information

When a pool with a connection limit reaches the limit, you would expect that an LB_FAILED event is generated.

However, what we see is that the request is sent a Reset, unless a fallback-host is configured in the HTTP Profile.

If a fallback-host is configured, then we see that an HTTP_REJECT event is generated, and the HTTP::reject_reason is "No pool member available". Then the request is redirected with a 302 to the fallback-host
