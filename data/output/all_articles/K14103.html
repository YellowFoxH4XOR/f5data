Topic

F5 has recently discovered and corrected a number of issues that affect customers running ARX 6.3.0. F5 recommends that all customers currently running ARX 6.3.0 install the latest cumulative rollup hotfix available.

The following table lists the rollup hotfixes available for ARX 6.3.0. Each hotfix lists the ID number and description for the issues fixed by the hotfix:

Note: These rollup hotfixes are cumulative; each hotfix contains the fixes included in the previous hotfixes.

420150 An option has been added to allow the Domain Controller health check to use In-Band IP instead of Proxy IP (XIP).
420465 Importing a new share while a dNAS operation is pending in the same volume could lead to a deadlock situation. This problem has been fixed.
420922 The dNAS code for MPNS (multi-protocol namespace) was updated to improve resiliency in the event of internal inconsistency.
420993 The virtual snapshot timeout did not use the value provided by term debug command mgmt-cmd-timeout. This issue has been fixed.

422421 Using the GUI, it was possible to submit a Domain Join request without selecting any Delegation. This causes afnrootd to core.  This problem has been fixed.
422937 NSM encountered an assertion failure when trying to insert a CIFS transaction record into internal database. NSM has been enhanced to avoid a core in this scenario.
423185 A logic error which caused afnrootd to dump core has been fixed.
423365 A combination of directory rename and an invalid metadata record caused dNAS to dump core repeatedly. This problem has been fixed.
424144 An error in the calculation of message block size in NSM which could cause a core dump has been fixed.
   
**6.3.0 HFRU3
(build-14791)		408318 Due to a bug in the kernel scheduler, 2 CPUs on the control plane could get into a race and block clock interrupts, causing the ARX to lock. The watchdog  timer would time out and disable the links on the switch ports. This issue has been fixed.
409259An error in handling TREE_DISCONNECT SMBs from Windows Server 2003 clients could cause CLIENT_CONN_TEARDOWN errors to be written to syslog. This has now been fixed.
411883A failure of the NSM stats daemon caused the ARX to reload. This failure has been addressed.
413272An error that was occurring in the kernel that caused NFS metadata and NFS imports to fail on some configurations has been fixed. The fix targets the ARX-1500, ARX-2500, and ARX-VM platforms.
413480A problem with a snapshot process starting in the middle of a switch replacement rendezvous and causing a failure to rejoin has been fixed.
413481During HA rendezvous, when redundancy is first enabled, it is possible to "no enable" redundancy on the ARX that will become the backup switch before it is fully established.  As part of rolling back redundancy, all global scope data is removed from the joining ARX.  Previously, it was possible for a database transaction conflict to prevent removal of this data.  This would cause numerous split-brain conditions when the joining ARX resumed stand-alone function.
413681Fixed a race condition in VCIFS which could cause ACLs of a directory to be deleted after a share migration using staged method.
414314During a rename operation if the new filename were to collide with the alternate name (the 8.3 name) of an existing file, a memory allocation problem could cause dNAS to core repeatedly. This problem has been fixed.
414433A design limitation on the number of outstanding notify-change requests could cause syslog to be flooded with 'No available message id for notify-change request' messages. The excessive logging has been curtailed. Consideration is being given to addressing the limitation in a future ARX release.
414439SMTP behaved incorrectly by sending reports to e-support@f5.com (the default) regardless of the email address specified as the target. This behavior has been fixed and SMTP now sends reports (and emails with attachments) to the target email address.
415805In cases of MPNS (multi-protocol namespace) and with clients using NFS2 to mount to a NetApp filer where a qtree exists inside a volume, a destructive rename operation that occurs in the qtree could cause dNAS to core and the unit to reload. This problem has been fixed.
416424The ARX now recognizes and reacts properly to the response "Use of vfilers requires a multistore license." from a NetApp filer.
419045A log handle leak problem that caused resource exhaustion and krbconfd to core has been fixed.
   
**6.3.0 HFRU2
(build-14789)		398043 This release contains an upgrade to the latest version of Apache Tomcat (6.0.36).  The upgrade resolves security vulnerabilities found by a vulnerability scan run against the ARX platform.
405558 On ARX-4000 platforms, intermittent hardware watchdog resets were reported. These occurred because the ARX hardware watchdog petting daemon was “starved” of CPU time long enough to trigger the reset. The ARX Metalog driver is believed to be the root cause under certain CPU core scheduling conditions.
406544 Various commands that are intended to modify an existing configuration object erroneously create an invalid partially-initialized object if applied to a non-existing object. This can happen if an object (namespace, volume, or share) is deleted in one session, while there is a CLI session currently in that configuration mode. The result is an invalid global-config that cannot be repaired or modified. This problem has been fixed.
407240  The "no report" option is the default for snapshot rules. However, when a snapshot archive location was configured, where a snapshot is automatically deleted following a successful copy to the archive, a remove report would always be generated. This behavior has been modified so that the remove report is generated only when a report prefix is configured.
407477  A watchdog timeout issue caused the NSM to core. This has been fixed.
407922 Fixed an assertion failure problem in the handling of SMB find command that caused DNAS to core.
409184 A problem that caused the NSM to core because of memory exhaustion due to flow control issues on the filer has been fixed.
410221 The MAC address for the management port of ARX 1500/2500 is not displayed correctly in the CLI ‘show interface mgmt’ command. This problem has been fixed.
410707 When the client establishes more than one user session in a connection and SMB signing is required, the subsequent tree connect operation will fail due to a parsing issue. This problem has been fixed.

394709There was a problem in the NSM logic where responses from DNAS are processed. This problem, which could cause NSM to core, has been fixed.
398376A race condition between NSM and DNAS for file close can cause NSM to core. The problem has been fixed.
403513NLAD could core due to memory exhaustion in a large configuration where there are multiple Domain Controllers and tens of virtual services.
403902When a large packet was fragmented into many frames and the number of frames exceeded an internal limit, the packet would not get processed correctly.

405711The “show interface …” command for 2/13 and 2/14 are now included in the collect diag-info.
405849The NSMD on ARX 1500/2500 could generate cores due to an internal packet buffer being exhausted.
