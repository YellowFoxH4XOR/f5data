Description

The application is not working for some users. Those users connect in the same way, and in the same L2/L3 manner, but you observe the server-side TCP SYN does not get a response, despite being received by the server. This ultimately leads to a TCP reset on the client-side.

172.16.5.100 → 172.16.5.85 TCP OUT s1/tmm3 : [TCP Retransmission] 47392 → 443 [SYN]
172.16.5.100 → 172.16.5.85 TCP OUT s1/tmm3 : [TCP Retransmission] 47392 → 443 [SYN]
172.16.5.100 → 172.16.5.85 TCP OUT s1/tmm3 : [TCP Retransmission] 47392 → 443 [SYN]
10.10.10.100 → 192.168.1.4 TCP OUT s1/tmm3 : 443 → 47392 [RST, ACK] [F5RST(peer): TCP retransmit timeout]

Environment

  • Virtual server
  • Linux server

Cause

Some Linux servers do not respond to TCP SYNs when the TCP timestamps option is not provided. This commonly occurs when TCP timewait recycle is enabled on the server.

In its default configuration, the BIG-IP proxies the TCP timestamps option server-side. This means that if the client provides the option in its initial SYN, then the BIG-IP will also provide this option in its server-side SYN. Conversely, if the client does not provide this option, then the BIG-IP won't provide it to the server either.

Recommended Actions

Verify if TCP timewait recycle is enabled on your Linux server:

cat /proc/sys/net/ipv4/tcp_tw_recycle

Or:

sysctl -a | grep net.ipv4.tcp_tw_recycle

You may consider disabling this feature if it is enabled. TCP time wait recycle is generally disabled by default on most Linux distributions. However, you should first verify why it has been enabled.

Additional Information

TCP timestamps can improve TCP performance, especially with very large data streams. The primary functions of timestamps are Protection Against Wrapped Sequence Numbers (PAWS), and Round-Trip Time Measurement (RTTM). For more information about TCP timestamps, see RFC 7323:

  • RFC 7323 - TCP Extensions for High Performance

TCP timestamp behaviour on the BIG-IP can be controlled with the Proxy Options and Timestamps Extension for High Performance options in the TCP profile, but there is no explicit toggle to enable TCP timestamps.
