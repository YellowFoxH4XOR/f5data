Module provisioning for a Virtual Clustered Multiprocessing (vCMP) guest fails after the system boots into a newly upgraded software volume.

This issue occurs when all of the following conditions are met:

  • You deploy the vCMP guest with the default-sized 100 gigabytes (GB) virtual disk image.
  • You provision the vCMP guest with a combination of the Secure Web Gateway (SWG) and any of the following modules:
    • BIG-IP AAM
    • BIG-IP AFM
    • BIG-IP Analytics
    • BIG-IP APM
    • BIG-IP ASM
    • BIG-IP PEM
  • You provision the vCMP guest with module combinations that require a large amount of disk space, such as BIG-IP APM, BIG-IP ASM, BIG-IP Analytics, and BIG-IP LTM.
  • You then upgrade the vCMP guest to a newer software version on a second software volume.

Impact

The vCMP guest fails to boot properly into the newly upgraded software volume due to insufficient disk space and remains inoperative. The system does not process any traffic because the vCMP guest is inoperative.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The vCMP guest is unable to provision the modules after booting into the newly upgraded software volume.
  • The vCMP guest is inoperative.

Workaround

To work around this issue, you can back up the configuration from the affected vCMP guest, redeploy the vCMP guest on a new virtual disk image with the software version you want, and then restore the saved configuration on the redeployed vCMP guest. To do so, perform the following procedure:

Notes:

  • Before you proceed, ensure that your vCMP host has sufficient resources to deploy a new virtual disk image.
  • You must perform this workaround for every subsequent upgrade to an affected software version listed in the Applies to (see versions) box, located in the upper-right corner of this article.

Impact of workaround: The affected vCMP guest cannot process traffic until you restore the configuration on the redeployed vCMP guest. F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the affected vCMP guest and boot back to the previous software volume.
  2. Create a user configuration set (UCS) file. For information about UCS files, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13.x).
  3. Copy the UCS file to another system. For information about copying the UCS archive file to another system, refer to K175: Transferring files to or from an F5 system.
  4. On the vCMP host that has the affected vCMP guest, log in to the Traffic Mangement Shell (tmsh).
  5. To shut down the guest, change the state of the affected vCMP guest to configured using the following tmsh command:

    modify vcmp guest <guest name> state configured

    For example, to shut down a vCMP guest named guest247, type the following tmsh command:

    modify vcmp guest guest247 state configured

  6. To create a new virtual disk image for the vCMP guest, specify a new virtual disk image name and set the software version you want using the following tmsh command syntax:

    modify vcmp guest <guest name> virtual-disk <new virtual disk image name> initial-image <desired software image name>

    For example, to create a new virtual disk image named newguest247 and install BIGIP-11.5.4.0.0.256.iso to a vCMP guest named guest247, type the following tmsh command:

    modify vcmp guest guest247 virtual-disk newguest247 initial-image BIGIP-11.5.4.0.0.256.iso

  7. To redeploy the vCMP guest with the new virtual disk image and software version, change the state of the vCMP guest to deployed using the following tmsh command syntax:

    modify vcmp guest <guest name> state deployed

    For example, to redeploy a vCMP guest named guest247, type the following tmsh command:

    modify vcmp guest guest247 state deployed

    Wait for the software to finish installing on the new virtual disk image.

  8. Log in to the vCMP guest.
  9. Copy the backup UCS file from step 3 to the vCMP guest. F5 recommends that you copy the UCS file to the /var/tmp directory. For information about copying the UCS archive file to the vCMP guest, refer to K175: Transferring files to or from an F5 system.
  10. Restore the UCS file to the vCMP guest. For information about restoring a UCS file, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 13x).
