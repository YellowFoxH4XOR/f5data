Known Issue

The BIG-IP system may fail to load the configuration when file objects created in the /config directory begin with a period ( . ) character.

This issue occurs when the following conditions are met:

  • You upgrade from 10.x to 11.x or 12.x and roll forward the 10.x configuration.
  • You install a 10.x user configuration set (UCS) file on a BIG-IP system running 11.x or 12.x.

When you create a UCS file under BIG-IP 10.x (either manually or as part of an upgrade), file objects located in the /config directory path are automatically included in the UCS archive. When upgrading from 10.x to 11.x or 12.x, or installing a 10.x UCS file on 11.x or 12.x, the bigpipe utility creates a transitional bigip.conf file as part of the 10.x to 11.x or 12.x conversion. The bigpipe utility accounts for the file objects included in the UCS file by creating a file object configuration stanza in the transitional bigip.conf file. If a file object for a file's name begins with the period character, the transitional bigip.conf configuration will fail to load.

For example, the vi text editor automatically creates a backup of files that you are editing named .name_of_the_file.swp. Normally when you exit the text editor, it removes the .swp file. However, if you close the secure shell (SSH) session before closing vi, the text editor does not have the opportunity to clean up, and the .swp file remains in the directory.

Assume that the BIG-IP administrator logs into the BIG-IP system using SSH and modifies an external monitor named my_external_monitor.pl using the vi text editor. At some point, the administrator accidentally closes the SSH session to the BIG-IP system before closing the file in the text editor. A file now exists named /config/monitors/.my_external_monitor.pl.swp. Unless you manually remove this file, it will be included in all future UCS files.

Impact

The configuration fails to load after an upgrade or UCS installation.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H487373 on the Diagnostics > Identified > High screen.
  • Loading a BIG-IP 10.x UCS on an 11.x or 12.x system using the Traffic Management Shell (tmsh) produces and error message that appears similar to the following example:

    Configuration loading error: high-config-load-failed
    For additional details, please see messages in /var/log/ltm

    WARNING: There were one or more errors detected during installation.
    Check the error messages and take the proper actions if needed.
    ERROR: UCS installation failed.
    Operation aborted.
    /tmp/configsync.spec: Error installing package
    Config install aborted.
    Unexpected Error: UCS loading process failed.

  • The /var/log/ltm file logs an error message that appears similar to the following example:

    err load_config_files: "/usr/libexec/bigpipe load" - failed. -- BIGpipe parsing error (/config/bigpipe/bigip.conf Line 2): 012e0017:3: The requested item (.my_external_monitor.pl.swp {) is invalid (<external monitor file object key> | show | list | help) for 'external monitor file object'

Workaround

If you encounter this issue after upgrading to 11.x or 12.x, F5 recommends that you reboot to the previous 10.x boot location, rename the associated file name, and then perform the upgrade again. Alternatively, from within 11.x or 12.x, you can edit the /config/bigpipe/bigip.conf file and remove the references to file object. To remove the references to the file object from 11.x or 12.x, perform the following procedure:

Impact of workaround: If this procedure fails to resolve the issue, you may need to reboot to the previous 10.x boot location, rename the associated file name, and then perform the upgrade again.

  1. Log in to the BIG-IP command line.
  2. Edit the /config/bigpipe/bigip.conf file using either the vi or pico text editor.
  3. Locate and remove the configuration stanza for the object that failed to load.

    For example:

    external monitor file object .my_external_monitor.pl.swp {
    cache path "/config/filestore/.file_object_upgrade_staging/.my_external_monitor.pl.swp"
    }

  4. Save the changes and exit the text editor.
  5. Reload the configuration by typing the following command:

    Important: You should use the following command only when instructed to do so in an article or by F5 Support.

    /usr/libexec/bigpipe daol

  6. Save the configuration using the tmsh utility by typing the following command:

    tmsh save /sys config

  7. Reload the configuration using the tmsh utility by typing the following command:

    tmsh load /sys config
