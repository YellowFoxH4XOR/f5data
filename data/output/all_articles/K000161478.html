K000161478: Adding SWG service to SSLO causes webpages to partially load.

Description

When an SWG (Secure Web Gateway) service is added to an SSL Orchestrator (SSLO) service chain, proxied client's web pages only partially load and blocked pages display the APM blocking page. 
APM logs show (ERR_LICENSE) URL category lookup failed and (ERR_REJECT) Error processing URL Classification query from CatEngine, with the category lookup agent returning an "Aborted" status. 

Environment

  • SSLO deployment with SWG added as a service chain.

Cause

When SWG is deployed as a service chain within SSLO, no full APM session is created. The URL category lookup mechanism in the SWG per-request policy requires a valid APM session context to perform complete URL and path categorization queries against the CatEngine. Without this session, the category lookup fails with ERR_LICENSE and ERR_REJECT errors, causing the per-request policy agent to abort and resulting in pages only partially loading or being incorrectly blocked. This is expected behavior when SWG is used as an SSLO service chain, as opposed to being deployed as a standalone APM/SWG product where a full APM session exists.

Answer/Recommended Actions

Understand that SWG deployed as an SSLO service chain does not support full URL and path category lookup, as this functionality requires a full APM session that is not present in the service chain context.
If full URL categorization and filtering capabilities are required, deploy SWG as a standalone APM/SWG product rather than as an SSLO service chain.
If SWG must remain in the SSLO service chain, design the per-request policy to account for the absence of a full APM session and avoid relying on URL category lookup agents that require session context.
Review the SSLO and SWG deployment architecture with F5 Professional Services or consulting to determine the appropriate integration model for the environment's requirements.
