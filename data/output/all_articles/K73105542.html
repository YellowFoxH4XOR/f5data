K73105542: Migrate a BIG-IQ configuration from a 7000 series hardware platform to a BIG-IQ VE system

Type
Support Solution
Published
2021-04-29
Updated
2022-12-28
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.X.X
Source
https://my.f5.com/manage/s/article/K73105542

Description

Use the following procedure to migrate the configuration on the BIG-IQ 7000 series hardware platform to a newly installed BIG-IQ VE instance using the user configuration set (UCS) backup file. If the BIG-IQ hardware is currently in production, ensure that the target BIG-IQ VE is isolated from the production environment before the system cut over.

Environment

  • BIG-IQ 7000 series hardware unit
  • BIG-IQ Virtual Edition unit

Recommended Actions

For a BIG-IQ Centralized Management system configured with Data Collection Devices (DCD), you should remove the associated DCDs after the migration and re-associate the system with the new or existing DCD instances. For more information, refer to K02014651: Removing a DCD association from BIG-IQ Centralized Management.

Prerequisites


You must meet the following prerequisites to use this procedure:

  • Have administrative access to the BIG-IQ systems.
  • Both source and target BIG-IQ devices have version 8.0.0 or later installed.
  • The BIG-IQ VE has the identical software version and master key passphrase as the BIG-IQ hardware platform.
  • The target BIG-IQ system is newly created with no existing configuration and is in Standalone mode.

Procedures


Reset the master key on the target BIG-IQ VE (Optional)
Reset the BIG-IQ device key using f5mku utility
Back up the configuration on the BIG-IQ 7000 series platform
Migrate the configuration to the target BIG-IQ VE
Roll back the migration

 

 Reset the master key on the target BIG-IQ VE 

When specifying a master passphrase during the initial setup of your target BIG-IQ VE system, you must use the same passphrase as is on the source BIG-IQ hardware platform so the configuration can be loaded on the target system. If the target VE system was set with a different master key passphrase than the BIG-IQ hardware, you should prepare the target BIG-IQ VE device by resetting the master key with the passphrase obtained from the BIG-IQ 7000 series platform. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure resets the BIG-IQ master key. The system will be re-launched on the target BIG-IQ VE.

  1. Log in to the target BIG-IQ VE user interface.
  2. Go to System > THIS DEVICE > General Properties.
  3. Select Edit.
  4. For Master Key, select Change Master Key.
  5. For Current Passphrase, enter the master key passphrase of the BIG-IQ VE system.
  6. For New Passphrase, enter the master key passphrase of the BIG-IQ hardware platform.
  7. For Confirm New Passphrase, enter the BIG-IQ hardware passphrase again.
  8. Select Save.
  9. Reset the BIG-IQ device key using f5mku utility

 

Reset the BIG-IQ device key using f5mku utility

The BIG-IQ device key, also referred as the Secure Vault master key, must be identical between the source BIG-IQ 7000 and the target VE before you start the configuration migration process. You can reset the device key of the target VE with the key obtained from the source device using the f5mku utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure resets the Secure Vault master key. F5 recommends that you do not use the f5mku utility on a BIG-IQ system under any circumstances other than platform migration and RMA unit restoration.

  1. Log in to the source BIG-IQ 7000 command line.
  2. To obtain the device key from the source BIG-IQ device, enter the following command:
    f5mku -K
    The command output appears similar to the following example: 
    oruIVCHfmVBnwGaSR/+MAA==
  3. Copy the output.
    Note: The output is the device key that you will use on the target BIG-IQ VE system.
  4. Log in to the target BIG-IQ VE system command line.
  5. Install the device key that you copied in step 3 to the target BIG-IQ VE system using the following command syntax:
    f5mku -r <key_value>
    For example: 
    f5mku -r oruIVCHfmVBnwGaSR/+MAA==
  6. Verify that the device key is the same on the source BIG-IQ 7000 and the target BIG-IQ VE by typing the following command from the command lines of both systems:
    f5mku -K

Back up the configuration on the BIG-IQ 7000 series platform


You can back up the current configuration on the BIG-IQ hardware platform by creating a UCS archive file from the BIG-IQ user interface. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the source BIG-IQ hardware user interface.
  2. Go to System > BACK UP & RESTORE > Backup Files.
  3. Select Create.
  4. For Name, enter a name you would like to use to identify the backup file.
  5. For Devices, move the BIG-IQ device to the Selected field.
  6. Select Start.
  7. To download a local copy of the UCS file, check the newly created backup and select Download.
  8. Migrate the configuration to the target BIG-IQ VE

Migrate the configuration to the target BIG-IQ VE


You can migrate the configuration, excluding the license file, to the target BIG-IQ VE system with the UCS file created from the source BIG-IQ platform. To do so, perform the following procedure:

Impact of procedure: Performing this procedure erases the existing configuration on the target BIG-IQ VE system. Configuration restoration may take several minutes, and the system may be unavailable during that time.

  1. Use an SCP client to copy the downloaded UCS file to the /shared/ucs_backups directory of the target BIG-IQ VE system. For information about transferring files, refer to K175: Transferring files to or from an F5 system .
  2. From the target BIG-IQ VE command line, log in to the TMOS Shell (tmsh) by typing the following command:
    tmsh
  3. To restore the configuration on the target VE system, use the following command syntax:
    load /sys ucs /shared/ucs_backups/<UCS_file_name> no-license no-platform-check
    For example, to restore the configuration from the previously saved UCS file example_BIQ_20210101.ucs, enter the following command: 
    load /sys ucs /shared/ucs_backups/example_BIQ_20210101.ucs no-license no-platform-check
  4. To restart the restjavad service after you successfully complete the configuration migration, enter the following command:
    restart /sys service restjavad
  5. From the source BIG-IQ 7000 command line, log in to tmsh by typing the following command:
    tmsh
  6. Perform a system cutover and stop the restjavad service on the source BIG-IQ 7000 system using the following command:
    stop /sys service restjavad
  7. For BIG-IQ Centralized Management, check that all the managed BIG-IP devices can be managed by the new BIG-IQ VE system.
  8. Perform a post-migration health check by verifying that all the managed applications and services are working properly.

Roll back the migration

In the event of an unsuccessful migration or failed services after the migration, you can roll back the migration by restarting the restjavad service on the original BIG-IQ 7000 system. To do so, perform the following procedure:

Impact of procedure: This procedure involves stopping/starting the restjavad processes, but this does not have a negative impact on your system because the migration or services have already failed. Performing this procedure restores the services on the original BIG-IQ 7000 system.

  1. From the BIG-IQ 7000 command line, log in to tmsh by typing the following command:
    tmsh
  2. To start the restjavad service on the BIG-IQ 7000 system, enter the following command:
    start /sys service restjavad
  3. From the target BIG-IQ VE command line, log in to tmsh by typing the following command:
    tmsh
  4. To stop the restjavad service on the BIG-IQ VE system, enter the following command:
    stop /sys service restjavad
  5. Check that all the managed BIG-IP devices can be managed by the BIG-IQ 700 system, and verify that all the managed applications and services are working properly.
