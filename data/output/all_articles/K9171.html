Known Issue

This is the result of a known issue. Persistence entries that are associated with a mirrored Layer 7 flow are not re-mirrored to the standby unit after it has been rebooted. As a result, the BIG-IP LTM may send connections to the incorrect server in the event the active unit fails over after the standby unit has been rebooted. The reboot of the standby system will delete the persistence entries for the Layer 7 connections, and persistence information for existing connections will not automatically be re-mirrored by the active unit.

Note: This behavior does not affect cookie persistence, as the persistence information is contained within an HTTP cookie that is read each time BIG-IP receives an HTTP GET or POST that contains the HTTP cookie with the persistence information.

F5 Product Development tracked this issue as CR99386 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue has been fixed in Hotfix-BIG-IP-9.4.5-HF2, which has been issued for BIG-IP version 9.4.5, and in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP version 9.3.1. You may download these hotfixes or later versions of the hotfixes from the F5 Networks Downloads site.
