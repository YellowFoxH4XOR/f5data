Known Issue

This is the result of a known issue. When a VIPRION system is configured with multiple user partitions and multiple users make configuration changes to different partitions within a short period of time, the other blades may report concurrency issues and error messages that appear similar to the following example in the /var/log/ltm file:

err mcpd[4660]: 01070726:3: A virtual server may reference a virtual address in the same partition or the common partition
err mcpd[4660]: 01070734:3: Configuration error: Configuration from primary failed validation: 01070726:3: A virtual server may reference a virtual address in the same partition or the common partition

The error message indicates that a secondary blade went offline to reload the configuration changes from the primary blade in the system.

F5 Product Development tracked this issue as CR133045 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.0.1-402.7-HF4, issued for BIG-IP 10.0.1, and BIGIP-10.1.0-3372.0-HF1, issued for BIG-IP 10.1.0. You may download these hotfixes or later versions of these hotfixes from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix and point release matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.
