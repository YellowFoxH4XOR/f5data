K000140282: Multicast traffic does not reach to BIG-IP VE hosted on ESXi for few Intel NIC's configured for SR-IOV

Type
Support Solution
Published
2024-07-09
Updated
2025-02-07
Applies to
  • BIG-IP
  • Virtual Editions
  • Vmware ESXI and vCloud Director
Source
https://my.f5.com/manage/s/article/K000140282

Description

Multicast traffic does not reach to BIG-IP VE hosted on ESXi for few Intel NIC's configured for SR-IOV which causes failure in protocols which depends on multicast like Routing Protocol neighborship failure i.e OSPF

Environment

  • Multicast
  • VE
  • ESXi
  • Intel NIC's like  X710, XXV710, E810-C

Cause

Lack of required configuration in VE and ESXi

Recommended Actions

Please follow below steps in ESXi and BIG-IP VE to allow multicast traffic to reach SR-IOV enable VE's

Note: Please note that running steps in VE will require to restart tmm which will disrupt the traffic and should be done in maintenance window.

ESXi:

(a) Login to ESXi CLI. Before proceeding to execute further steps in ESXi, please make sure that Intel® esxcli plug-in for Managing Intel® Ethernet Network Adapters is installed in ESXi.

(b) First check if Spoof Check and Trust is enabled in Virtual Functions which is attached to BIG-IP VE. Replace 'vmnic8' in below output with the physical NIC name in your ESXi environment connected to External Switch.

[root@localhost:~] esxcli intnet sriovnic vf get -n vmnic8

VF ID     Trusted    Spoof Check

-----     -------    -----------

0       false     true

1       false     true

2       false     true

(c) If 'Trusted' is set to 'false' then change it to 'true'.

[root@localhost:~] esxcli intnet sriovnic vf set -n vmnic8 -v 0 -t on

Trusted mode is set to true and spoof check is set to true

[root@localhost:~] esxcli intnet sriovnic vf set -n vmnic8 -v 1 -t on

Trusted mode is set to true and spoof check is set to true

[root@localhost:~] esxcli intnet sriovnic vf set -n vmnic8 -v 2 -t on

Trusted mode is set to true and spoof check is set to true

(d) Verify  if changes is implemented and 'spoof' and 'trust' is set to 'true' now.

[root@localhost:~] esxcli intnet sriovnic vf get -n vmnic8

VF ID     Trusted    Spoof Check

-----     -------    -----------

0       true      true

1       true      true

2       true      true

BIG-IP VE:

Note: Please note that running below steps in VE will require to restart tmm which will disrupt the traffic and should be done in maintenance window.

(a) Login to BIG-IP VE CLI.

(b) Verify that 'xnet' is in use with driver loaded as 'iavf' or 'ixlv'

# tmctl -d blade tmm/device_probed

pci_bdf     pseudo_name type     available_drivers    driver_in_use

------------ ----------- --------- --------------------- -------------

0000:03:00.0            F5DEV_PCI xnet, vmxnet3, sock,

0000:0b:00.0 1.1        F5DEV_PCI xnet, sock,          xnet

 

# tmctl -d blade tmm/xnet/device_probed

id          available_drivers driver_selected driver_in_use

------------ ------------------ --------------- -------------

0000:0b:00.0 iavf, sock, dpdk, iavf           Yes

(c) Run below command to find out Intel NIC Virtual Function Device ID.

# lspci -nn | grep -i Ethernet

03:00.0 Ethernet controller [0200]: VMware VMXNET3 Ethernet Controller [15ad:07b0] (rev 01)

0b:00.0 Ethernet controller [0200]: Intel Corporation Device [8086:1889] (rev 01) --------------> Use this Intel Device ID in below command.

(d) Now, run the following command in BIG-IP VE. Use the value from square brackets from above output in below command like 8086:1889 in this example.

# touch /config/tmm_init.tcl; echo -e "ndal rx_devq_sz 1024 8086:1889\nndal tx_devq_sz 1024 8086:1889" > /config/tmm_init.tcl

# bigstart restart tmm

(e) Now, Verify by running tcpdump in VE to confirm if multicast packets is being received by VE.

# tcpdump -s0 -nni 1.1 ip proto ospf

Additional Information

This issue does not occur with  SR-IOV enabled NIC 'Intel(R) 82599 10 Gigabit Dual Port Network Connection'  in ESXi running driver 'ixgben' 1.7.1.35 and firmware version 17.0.12.
