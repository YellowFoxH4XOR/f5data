Description

End user notices "200 OK" response code with Support-ID generated by ASM on on the web browser for the response codes blocked by ASM. 

If the response code received by server is not in "Allowed Response Status Code" under ASM policy, the respective response code will be blocked by ASM. And in this condition, BIG-IP ASM issues a Support-ID to the client from an internal web server running on BIGIP. The response code client sees i.e. 200 OK is from BIGIP ASM internal web server and NOT from the origin web server, which issued blocked xxx HTTP Response. In other words, BIGIP ASM proxied the xxx HTTP Response Code with 200 OK response using its internal web server.

Environment

  • BIG-IP ASM
  • ASM blocked request
  • ASM support-ID
  • HTTP status code
  • HTTP response

Cause

This is an expected behavior for any "Blocking" event for ASM

Recommended Actions

Verify the response code received from server is part of Security > Application Security > Security Policies > Security Policy Name > General Settings > "Allowed Response Status Codes" or not. If it is allowed and desired outcome is to see "Blocking Page", ASM would display 200OK with a Blocking page as expected.
