Security Advisory Description

JMSAppender in Log4j 1.2 is vulnerable to deserialization of untrusted data when the attacker has write access to the Log4j configuration. The attacker can provide TopicBindingName and TopicConnectionFactoryBindingName configurations causing JMSAppender to perform JNDI requests that result in remote code execution in a similar fashion to CVE-2021-44228. Note this issue only affects Log4j 1.2 when specifically configured to use JMSAppender, which is not the default. Apache Log4j 1.2 reached end of life in August 2015. Users should upgrade to Log4j 2 as it addresses numerous other issues from the previous versions. (CVE-2021-4104)

Impact

An attacker can use this vulnerability to create a Log4j configuration that can lead to remote code execution.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by installing a version listed in the Fixes introduced in column. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch.

Mitigation

To mitigate this vulnerability, you can remove JMSAppender from the affected Traffix SDC system. For F5 products are not vulnerable to this issue, you may use F5 products to mitigate the impact of this vulnerability in your infrastructure, for example if you are logging HTTP traffic to a vulnerable third party system.

Note: The following mitigation articles that apply to the Log4j 2 vulnerability also apply to Log4j 1.2 vulnerability.

For information about using F5 products to mitigate the impact of this vulnerability, refer to the following articles:

  • K59329043: Mitigating the Apache Log4j2 vulnerability with BIG-IP
  • K25643754: Mitigating the Apache Log4j2 vulnerability with NGINX Application Security products
