Topic

You should consider using this procedure under the following conditions:

  • You are currently experiencing a technical issue with your BIG-IP system.
  • You are currently working with an F5 Support representative to gather additional diagnostic information from your BIG-IP system.

Important: Do not set the Traffic Management Microkernel (TMM) to debug mode unless requested to do so by an F5 Support representative, who will assist you in interpreting the debug output.

Description

The tmm.debug TMM daemon enables debug symbols that allow additional information to be included in TMM core files produced on the system. Core files created with debug information greatly improve the ability to effectively troubleshoot the issue. However, the tmm.debug TMM daemon performs slower than the tmm.strict or tmm.default TMM daemons. You should use them only when instructed to do so by F5 Support for troubleshooting purposes.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have command-line access to the BIG-IP system.

Procedures

  • Set TMM to debug mode with system kernel
  • Set TMM to debug mode with F5 Support-supplied kernel
  • Set TMM back to default mode

Set TMM to debug mode with system kernel

Impact of procedure: Restarting TMM causes the BIG-IP system to drop all current connections. You should perform this action only during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Create a new symbolic link that points to the debug TMM by entering the following command:

    ln -sf /usr/bin/tmm.debug /etc/alternatives/tmm

  3. Restart TMM by entering the following command:

    bigstart restart

  4. When TMM is running in debug mode, a log message similar to the following will appear in the /var/log/tmm file:

    notice debug x86_64 padc TMM Version 11.4.0.2384.0 (4x0.00GHz GenuineIntel) 5448MB physical

Set TMM to debug mode with F5 Support-supplied kernel

F5 Support may ask you to deploy a custom TMM image (for example, custom-tmm.debug). To do so, perform the following procedure:

Impact of procedure: Restarting TMM causes the BIG-IP system to drop all current connections. You should perform this action only during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Upload the supplied image to /shared.
  3. Set the image to executable by entering the following command:

    chmod a+x  /shared/custom-tmm.debug

    Important: If you do not perform this step, TMM does not load and the console displays emerg logger messages. The device becomes inoperative.

  4. Create a new symbolic link that points to the debug TMM by entering the following command:

    ln -sf /shared/custom-tmm.debug  /etc/alternatives/tmm

  5. Restart TMM by entering the following command:

    bigstart restart

  6. When TMM is running in debug mode, a log message similar to the following appears in the /var/log/tmm file:

    notice debug x86_64 padc TMM Version 11.4.0.2384.0 (4x0.00GHz GenuineIntel) 5448MB physical

Set TMM back to default mode

Impact of procedure: Restarting TMM causes the BIG-IP system to drop all current connections. You should perform this action only during a maintenance window.

  1. Log in to the command line of the BIG-IP system.
  2. Create a new symbolic link that points back to the default TMM by entering the following command:

    ln -sf /usr/bin/tmm.default /etc/alternatives/tmm

  3. Restart TMM by entering the following command:

    bigstart restart

BIG-IP 11.5.0 and later

When TMM is running in default mode, you may view a log message in the /var/log/tmm file that appears similar to the following example:

notice pgo_use x86_64 padc TMM Version 11.5.0.0.0.221 (4x2.40GHz GenuineIntel) 6384MB physical

BIG-IP 10.2.0 through 11.4.1

When TMM is running in default mode, you may view a log message in the /var/log/tmm file that appears similar to the following example:

notice default x86_64 padc TMM Version 11.4.0.2384.0 (4x0.00GHz GenuineIntel) 5448MB physical
