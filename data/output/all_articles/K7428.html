Known Issue

This is the result of a known issue. When ZebOS processes a high volume of routing updates, ZebOS may fail to communicate all of the route information to TMM. As a result, TMM delivers traffic to the incorrect next-hop address.

ZebOS uses a Netlink socket to send routing updates to the Linux kernel, which uses a Netlink socket to communicate the updates to the tmrouted process. The tmmrouted process then updates the routing table used by TMM. When ZebOS sends a large volume of updates through the Netlink socket in a short period of time, such as when OSPF adjacencies are first established, the Netlink buffer to the tmrouted process can overflow. As a result, updates may be lost.

To see if any routes are missing, compare the ZebOS routing table (zebos cmd sho ip route) to the TMM routing table (b route). The following message will also be logged in the /var/log/user.log file:

nsm: netlink-listen recvmsg overrun: No buffer space available

F5 Product Development tracked this issue as CR58743 and it was fixed in BIG-IP 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, or WebAccelerator Release Notes.

Workaround

Important: The following workaround requires a reboot. F5 recommends that this workaround be performed during a maintenance window to prevent disruption to clients and other network communication.

Note: The following procedure increases the buffer size used by the Netlink socket from the default size of 65535 bytes to 104857 bytes.

Note: The 9.3 implementation of CR58743 includes an additional rate-limiting mechanism, as well as the increase in buffer size, that cannot be enabled as part of this workaround.

To prevent ZebOS dynamic routing updates from being lost, perform the following procedure:

  1. Log in to the command line.
  2. Back up the /etc/sysctl.conf file by typing the following command:

    cp /etc/sysctl.conf /etc/sysctl.conf.original

  3. Using a text editor, edit the /etc/sysctl.conf file.
  4. Add the following lines to the end of the /etc/sysctl.conf file:

    net.core.rmem_max=104857
    net.core.rmem_default=104857

  5. Save your changes.
  6. Reboot the system by typing the following command:

    reboot
