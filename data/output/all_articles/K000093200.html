K000093200: APM "Do not change password" not honoured when RSA auth with ondemand token present

Source

Description

Standard Access policy is configured with RSA auth with on-demand RSA tokens (sent via email). 
AD query is configured to prompt user to change password.

When users are prompted and they click on the checkbox for "Do not change password", they see the "New password" and "verify password" fields are greyed out which is expected behaviour.  But if they click on "logon" button they get the below page instead of the APM Webtop (because APM is still contacting the AD server):

The domain password change operation failed.
Your current password must be at least 1 days old before you can change it.

New Password
Verify Password

If you Click on "logon" button again then you are redirected to the APM Webtop.

Environment

  • BIG-IP APM standard access policy
  • VPE with RSA Auth (on demand token configured to be received by email)
  • AD query (prompt user to change password)
     

Cause
 

The information regarding the checkbox for the Do not change password being enabled is not sent back to the APM.
 

Recommended Actions
 

Workaround:


Modify the logon.inc of the specific access policy which is having the issue: 
 

Access  ››  Profiles / Policies : Customization : Advanced

Access Profile >> <specific access policy> >> Access Policy >> Logon Pages >> Logon Page >> logon.inc
 

Inside function verifyNewPassword() after line 621 please add the following line:
 

------------

inputs[0].disabled = false;

------------

It should look like:

 else {
            // Not sending the second field.
            inputs[0].disabled = false;
            inputs[1].disabled = true;

            try{
                  if( externalWebHost.hasWebLogonPassword() ){
                      externalWebHost.setWebLogonPassword(inputs[0].value);
                  }
            } catch(e) { }
        }

 

Note: This change will persist through reboots but not through upgrades.
