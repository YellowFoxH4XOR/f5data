Description

SNMPv3 trap configuration on BIG-IP LTM may fail to send traps to the trap manager, even though SNMPv2c traps function correctly. Additionally, tcpdump traces show that no SNMPv3 traps are observed leaving the device.

Environment

  • BIG-IP 
  • SNMPv3 Trap

Cause

SNMPv3 traps are not sent if the "Engine ID" field is not configured or there is no matching security-name.

Recommended Actions

When configuring SNMPv3 trap destinations SNMPv3 trap must match a security-name to an snmpv3 user or populate the "Engine ID" field with an administratively unique identifier. The Engine ID can be found in /config/net-snmp/snmpd.conf as the value of the oldEngineID token.

Additional Information

  • If EngineID is not manually specified in the configuration or changed, it will be subjected to an alteration after upgrade activities. See K15681 Customizing the SNMPv3 engine ID. "This ID is normally determined automatically, using a combination of a pseudorandom number and the current time, in seconds."
  • Use only IP addresses (not hostnames) for trap destination fields in your configuration.
