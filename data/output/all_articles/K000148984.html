K000148984: VPN Connections Fail on Windows 11 PCs after upgrade to 7.2.5.0 client

Type
Support Solution
Published
2024-12-13
Updated
2026-03-04
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000148984

Description

You may see impact from upgrade to APM client 7.2.5.0 with "Client OS" and "Windows Info" VPE objects on Windows 11 clients where the correct Windows version is not detected and access being denied by the access policy.

 

Environment

BIG-IP APM
APM Clients 7.2.5.0

 

Cause

Expected due to 1060689-2 fix in APM Clients

 

Recommended Actions

Adjust "Client OS" branch rule to include Win11:

Client OS >> Windows (change link) >> From the Advanced tab make the following adjustment:

From:
expr {[mcget {session.client.platform}] == "Win10"}

To:
expr {[mcget {session.client.platform}] == "Win10" || [mcget {session.client.platform}] == "Win11"}

 

Adjust "Windows Info" branch rule to include Win11:

Windows Info >> Windows 10 (change link) >> From the Advanced tab make the following adjustment:

From:
expr {[mcget {session.windows_info_os.last.platform}] == "Win10" || [mcget {session.windows_info_os.last.platform}] == "Win1064"}

To:
expr {[mcget {session.windows_info_os.last.platform}] == "Win10" || [mcget {session.windows_info_os.last.platform}] == "Win1064" || [mcget {session.windows_info_os.last.platform}] == "Win11" || [mcget {session.windows_info_os.last.platform}] == "Win1164"}

Alternatively, create a new branch rule "Windows 11" containing:
expr {[mcget {session.windows_info_os.last.platform}] == "Win11" || [mcget {session.windows_info_os.last.platform}] == "Win1164"}
