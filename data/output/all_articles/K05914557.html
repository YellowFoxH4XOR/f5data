Description

You may encounter issues adding new devices to device trust when

  • You have two devices in a cluster and wish to add another device
  • You have RMA'd a system and want to add the new device to the device-trust. 

When trying to create device trust you may see either one of the following error messages under /var/log/ltm:

  • err devmgmtd[pid]: 015a0000:3: getDeviceInfo failed: [xmlHelpers.cpp:90 getXPathValue] expected 1 node for //faultstring, got 0
  • err devmgmtd[pid]: 015a0000:3: getDeviceInfo failed: iControl authorization failed

 Environment

  • BIG-IP LTM HA
    • v17, 16, 15, 14, 13
  • Restricted iControl SOAP IP Addresses
  • iControl SOAP basic authentication is disabled via DBkey "icontrol.basic_auth"
  • Adding new device to device trust

Cause

iControl SOAP is required for the operation of adding new devices to device trust.

Restricting device trust IP's for iControl SOAP or disabling iControl SOAP Basic authentication interferes with iControl SOAP operation. The latter of which is being tracked as ID 1190777 Disabling Basic Auth for iControl SOAP prevents adding new device trust

Recommended Actions

Verify if iControl access is restricted or basic auth is disabled by following the respective procedure below that matches your scenario.

Important: By default iControl SOAP access is unrestricted and basic auth is enabled. A potential reason for having these values changed is to mitigate a vulnerability. For example K94221585: iControl SOAP vulnerability CVE-2022-41622.  If you changed the defaults for these reasons please consider reverting them back after making the modifications to Device Trust.

If iControl SOAP IP addresses are restricted

  1. Display current iControl SOAP allowed list

    # tmsh list /sys icontrol-soap

  2. If a peer device IP is not listed in the allow list, add the peer IP

     

    # tmsh modify /sys icontrol-soap allow add { <IP address or IP address range> } 
    For example, tmsh modify /sys icontrol-soap allow add { 172.16.1.1 }

     

  3. Rebuild device trust K42161405: Rebuilding device trust using the Configuration utility (11.x - 16.x)

  4. Change the allow list to original list (Output from step 1)
    # tmsh modify /sys icontrol-soap allow replace-all-with { <IP address or IP address range> }
    For example, tmsh modify /sys icontrol-soap replace-all-with {172.16.1.1 172.16.2.1 }

  5. Save the change by typing the following command:
    # tmsh save /sys config

If Basic Auth for iControl SOAP is disabled

  1. Verify if basic auth for iControl SOAP on target device is enabled
    # tmsh list sys db icontrol.basic_auth

  2. Enable Basic Auth for iControl SOAP on target device
    # tmsh modify sys db icontrol.basic_auth value enable

  3. DB key basic auth setting needs an httpd restart to take effect
    # bigstart restart httpd

  4. Rebuild  device trust K42161405: Rebuilding device trust using the Configuration utility (11.x - 16.x)

  5. Disable Basic Auth for iControl SOAP after the device trust is complete
    # tmsh modify sys db icontrol.basic_auth value disable

  6. Save the change by typing the following command
    # tmsh save /sys config

  7. Restart httpd after disabling DB key basic auth
    # bigstart restart httpd
