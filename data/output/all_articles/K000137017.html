Description

ASM end user using mobile might be blocked when CSRF is enabled. 
 

Environment

  • BIG-IP ASM
  • CSRF errors
  • ASM client
  • Mobile app

Cause

CSRF Vulnerability doesn't exist on mobile apps. Add Trusted User-Agent for Mobile apps to disable CSRF Protection for it.
 

Recommended Actions

Impact of workaround: Performing the following procedure forces the BIG-IP system offline for a short period of time. F5 recommends that you perform this procedure during a scheduled maintenance window.
 

After the fixed of the ID640842,a new internal parameter csrf_excluded_user_agent_patterns is added. If it is noticed that thee unexpected block by CSRF for the mobile apps, then use the internal parameter to exclude the user_agent, like below.

  1.  Send an HTTP request with custom user agent (Example:  KUKU) and see that the request is blocked
  2.  Setting user agent patterns, a request with that user agent will be ignored. The value is set internal system parameter. In the command, KUKU is an example. Replace it with the desired keyword.
# /usr/share/ts/bin/add_del_internal add csrf_excluded_user_agent_patterns "*KUKU*"

       3. To restart the BIG-IP ASM system, enter the following command

# bigstart restart


       4. Send an HTTP request with custom user agent (defined by the above variable)

Example: 
Send from Firefox browser and define csrf_excluded_user_agent_patterns to be "*KU*" - see that this request is not blocked
