Known Issue

If you provision WOM on a BIG-IP system that has a disk drive larger than 500GB, the disk drive will not be provisioned for WOM and will be unavailable to the WOM module. As a result, you will be unable to configure the system to use disk mode for symmetric deduplication.

Note: This issue affects only WOM symmetric deduplication disk mode. You can still configure WOM symmetric deduplication to use memory mode.

Beginning June 20, 2011, new 6900, 8900, and 8950 hardware platforms began shipping with 1TB disk drives and are affected by this issue. The 11050 platform ships with a 600 GB drive, and is also affected by this issue. Additionally, field replaceable drives that are replaced through RMA with the new larger drive size are affected.

This issue occurs when all of the following conditions are met:

  • WOM is provisioned on the BIG-IP system
  • The BIG-IP system has a hard disk larger than 500 GB

Impact

WOM is unable to use the disk mode for symmetric deduplication.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Disk mode symmetric deduplication is not available in the Mode drop-down menu on the symmetric deduplication properties screen.
  • An error message that appears similar to the following is seen in /var/logdatastor.provision logs :

    error: status 1280 returned by command: /usr/sbin/lvcreate -L 497266688K -n
    mdm.app.datastor.dat.datastor vg-db-sda
    info: >++++ result:
    info:   logical volumes cannot contain more than 65534 extents.
    info: >----
    error: Disk full (volume group). See SOL#10636 datastor volume_add(datastor, direct, 497266688,
    datastor, 1) said 1 (not enough space on physical volume)

    Note: The reference to SOL10636 is erroneously displayed because LVM is unable to create the volume. To distinguish this error from the installation errors it was intended to report, look for the info: logical volumes cannot contain more than 65534 extents entry on the third line preceding the error in the log file.

  • The pvscan utility reports a drive size larger than 500 GB. You can run the pvscan utility from the BIG-IP CLI. The output will appear similar to the following example:

    [root@jt-8950-12-141:Active] config # pvscan
    PV /dev/sdb3   VG vg-db-sdb   lvm1 [557.41 GB / 249.07 GB free]
    PV /dev/sda3   VG vg-db-sda   lvm1 [557.41 GB / 249.07 GB free]
    PV /dev/hda3   VG vg-db-hda   lvm1 [6.76 GB / 6.57 GB free]
    Total: 3 [1.10 TB] / in use: 3 [1.10 TB] / in no VG: 0 [0   ]

    This example shows 2 hard disks, each with a size of 557.41 GB, and 1 hard disk with a size of 6.76 GB. The 557.41 GB disks are typically configured in a RAID 1 (mirrored) configuration giving a total space of 557.41 GB.

Workaround

To work around this issue, you can configure BIG-IP WOM to use Memory mode for symmetric deduplication. To do so, perform the following procedure:

Impact of workaround: Memory mode deduplication limits the data cache size to the available amount of system memory of the hardware platform.

  1. Log in to the Configuration utility.
  2. Expand WAN Optimization.
  3. Click Symmetric Deduplication.
  4. Enter the number of remote endpoints in the Maximum Number of Remote Endpoints text box.
  5. Select Yes from the Enable Symmetric Deduplication drop-down menu.
  6. Select Memory from the Mode drop-down menu.
  7. Click the Update button.
