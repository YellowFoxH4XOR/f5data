Known Issue

This is the result of a known issue. The BIG-IP system constructs an array of entities to report on when the ramcache entry show command is issued. The response is chunked, so the array is processed in sections. In-between sections, client traffic may be processed. If an entity in the array is removed from the cache prior to being displayed, TMM may core when attempting to display the entity that has since been freed.

For example, using the following command on a BIG-IP system that is actively processing traffic may result in a TMM core:

bigpipe profile http all ramcache entry max response 10000 show

F5 Product Development tracked this issue as CR123171, and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or Edge Gateway release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
