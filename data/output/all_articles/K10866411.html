Topic

You should consider using this procedure under the following conditions:

  • You want to configure a custom cipher group for a Secure Sockets Layer (SSL) profile.
  • You want to perform the related tasks using the Configuration utility.

Note: To perform these tasks using the TMOS Shell (tmsh), refer to K65292843: Creating a custom cipher group using the tmsh utility.

Description

Beginning in BIG-IP 13.0.0, you can use cipher groups to specify which cipher suites are allowed when the BIG-IP system negotiates new SSL connections. Cipher groups allow you to select from cipher rules or sets of cipher suites to allow, restrict, or exclude those sets of cipher suites used by SSL profiles when the system processes new SSL connections. If the F5-provided cipher rules do not meet your configuration requirements, you can create custom cipher rules by following the Create a custom cipher rule procedure detailed below. Understanding the following terms can be helpful when you manage cipher groups and cipher rules:

  • Cipher suite: A set of authentication, encryption, message authentication code (MAC), and key exchange algorithms used when negotiating a new SSL connection.
  • Cipher rule or Cipher string: A configuration object representing a list of cipher suites.
  • Cipher group: A configuration object representing a list of cipher rules.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have basic knowledge of SSL cipher suites and protocols.
  • You have access to the Configuration utility.

Create a custom cipher rule

The following F5-provided cipher rules are available to use depending on the BIG-IP version:

  • f5-aes
  • f5-cc-stip
  • f5-default
  • f5-ecc
  • f5-fips
  • f5-hw_keys
  • f5-quic
  • f5-secure

To view the cipher string and other parameters of the pre-defined cipher rules, go to Local Traffic > Ciphers > Rules and select the rule you want to view. If the F5-provided cipher rules do not meet your configuration requirements, you can create a custom cipher rule. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Rules.
  3. Select Create.
  4. In General Properties, enter a unique Name for the rule.
  5. In Rule Creation, for Cipher Suites, enter the required cipher string value.

    For example, to exclude all ciphers using the TLSv1 protocol, use the Cipher Suites value TLSv1 in a cipher rule and apply the custom rule to the Cipher Group by following the Exclude ciphers procedure detailed previously.

    Note: For BIG-IP version 13.x, under Cipher Creation type the cipher string value for the Cipher String configuration.

  6. For DH Groups (Available in BIG-IP 14.0.0 and later), enter the Elliptic Curve Diffie-Hellman (ECDH) key exchange algorithms, or enter the special keyword DEFAULT to use the recommended algorithm set.
  7. For Signature Algorithms (Available in BIG-IP 14.0.0 and later), enter the signature algorithms, or enter the special keyword DEFAULT to use the recommended algorithm set. You can view the syntax to use as well as the available signature algorithms by selecting the Help tab on the left side of the page.
  8. In Rule Audit (in BIG-IP 14.0.0 and later), view Cryptographic Parameters to ensure that you get the results you expect.
  9. Select Finished.

Allow ciphers 

When creating a custom cipher group, you must first add one or more cipher rules to the allow list. To do so, perform the following procedure:

Important: F5 strongly recommends that you add the f5-default cipher rule before you allow or exclude additional cipher suites.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Groups.
  3. Select Create.
  4. Enter a unique Name for the cipher group.
  5. In Group Creation, select the check box for one or more cipher rules from Available Rules and move them to Allow the following.

    Note: To add a custom cipher rule, use the Create cipher rules procedure.

  6. In Group Audit, view Cryptographic Parameters to ensure that you get the results you expect.

    Note: For BIG-IP 13.x, review Cipher String in Cipher Audit .

  7. Select Finished.

Restrict ciphers

When you restrict cipher suites from the allowed cipher list, the BIG-IP system chooses only cipher strings that the allow and restrict lists have in common. The following table demonstrates the effect of restricting ciphers.

CAMELLIA256-SHA/TLS1.1		AES256-SHA/TLS1.2
AES256-SHA/TLS1.1		AES256-SHA/TLS1.2
AES256-SHA/TLS1.1

To restrict cipher suites from the Allowed ciphers list, perform the following procedure:

Impact of procedure: If the cipher group is not yet associated with an SSL profile, performing the following procedure should not have a negative impact on your system. If the cipher group is associated with an SSL profile, remote clients will be unable to use restricted ciphers for negotiation.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Groups.
  3. Select the Name of the cipher group that you want to modify.
  4. In Group Creation, for Available Rules, select the check box for one or more cipher rules and move them to Restrict the Allowed List to the following.

    Note: To add custom cipher rules, use the Create cipher rules procedure.
    Note: For BIG-IP 13.x, in Cipher Creation select from Available Cipher Rules.

  5. In Group Audit, view Cryptographic Parameters to ensure that you get the results you expect.

    Note: For BIG-IP 13.x, review Cipher String in Cipher Audit.

  6. Select Finished.

Note: You must have a custom cipher rule available to successfully perform this procedure. If you do not, first follow the Create a custom cipher rule procedure in this article to create a rule suited to your needs.

To exclude cipher suites from the allowed ciphers list, perform the following procedure:

Impact of procedure: If the cipher group is not yet associated with an SSL profile, performing the following procedure should not have a negative impact on your system. If the cipher group is associated with an SSL profile, remote clients will be unable to use excluded ciphers for negotiation.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Groups.
  3. Select the cipher group that you want to modify.
  4. In Group Creation, for Available Rules, select the check box for one or more cipher rules and move them to Exclude the following from the Allowed List.

    Note: To add custom cipher rules, use the Create cipher rules procedure.
    Note: For BIG-IP 13.x, in Cipher Creation select from Available Cipher Rules.

  5. In Group Audit, view the Cryptographic Parameters list to ensure that you get the results you expect.

    Note: For BIG-IP 13.x, in Cipher Audit, review Cipher String.

  6. Select Finished.

Create an SSL profile

The SSL profile Ciphers option allows you to associate a cipher group to specify which ciphers the system allows when negotiating new SSL connections. To create a new Client SSL profile with an associated cipher group, perform the following procedure:

Impact of procedure: If the SSL profile is not yet associated with a virtual server, performing the following procedure should not have a negative impact on your system. If the SSL profile is associated with a virtual server, remote clients will negotiate using the allowed ciphers.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create.
  4. Enter a unique Name for the profile.
  5. For Configuration, select Advanced.
  6. Select the Custom check box.
  7. For Certificate Key Chain, select Add.
  8. Select the appropriate Certificate and Key.
  9. Select Add.
  10. For Ciphers , select Cipher Group and select the custom cipher group from the list.
  11. Select Finished.

You can now associate the Client SSL profile with a virtual server to process SSL connections.
