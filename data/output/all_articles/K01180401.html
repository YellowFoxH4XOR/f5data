K01180401: The ''Audit'' logs not getting stored locally (stopped logging)

Support Solution
Published

Applies to

  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K01180401

Description

The local and remote "Audit" logging stopped and there is no Audit Logs either on "GUI >> System >> Logs >> Audit >> List" or in the "/var/log/audit" file.

Note: You may see some contents in "/var/log/audit.1" or "/var/log/audit.2" files, but these contents are related to the other days, and not related to Audit logs for today.

Environment

  • Audit logging is Enabled for both "MCP" and "tmsh"
  • "MCP" logging is set to "Notice"
  • There is no content in "/var/log/audit"
  • There is no content for Audit logs in GUI
  • No Audit log is sent to Remote Logger
  • You restarted the "syslog-ng" daemon, but without any positive outcome

Cause
This issue is related to "journald" daemon as it stopped due to any temporary disk space issue, or even any unseen problems. As a result of such behavior, the "Audit" logs are missing either locally or for remote loggers.
 

Recommended Actions

The "journald" daemon should be restarted to start "Audit" logging as normal, by using the below simple command:

systemctl restart systemd-journald.service

Note: The above command does not have any impact on your TMM traffic or other services. So, you can issue the mentioned command without any concern.
