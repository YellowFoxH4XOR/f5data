Description

Observing high CPU usage from systemd-journald process.

Numerous log messages similar to the following are present:

info systemd-journal[478]: Suppressed 157522 messages from /system.slice/sshd.service
info systemd-journal[478]: Suppressed 210629 messages from /system.slice/sshd.service
info systemd-journal[478]: Suppressed 190182 messages from /system.slice/sshd.service

In addition, /var/log/httpd/httpd_errors is full of many messages containing:

Failed Read: User, referer:

Environment

  • High CPU
  • systemd-journald
  • httpd

Cause

This can happen due to bug ID1103369, which can cause a large amount of pamcache auth tokens to build up over time in the /run/pamache tmpfs filesystem.

This issue will happen even if the workaround for ID1103369 has been applied. The workaround only prevents high CPU from csyncd attempting to sync the tokens between slots.

  • Bug ID 1103369: DELETE of REST Auth token does not result in deletion of the pamcache token file on a multi-slot VIPRION chassis, vCMP guest, or VELOS tenant

The large amount of pamcache tokens results in log churn on every login due to bug ID1111629. This in turn increases systemd-journald CPU utilisation.

  • Bug ID 1111629: Messages with "Failed Read: User, referer" are logged in /var/log/httpd/httpd_errors

Recommended Actions

Both bugs are already fixed in the latest point releases at the time of this article's publication. Planning an upgrade is recommended.

To mitigate the immediate issue, the tokens can be removed from /run/pamcache by rebooting the system. As the tokens are stored in a RAM filesystem, this is sufficient to delete them.

Additional Information

systemd-journald can exhibit high CPU in other situations. Further investigation may be needed if your system is not affected by the bugs listed above.
