K000160353: BIG-IP AFM SSH Proxy Only Advertises First Alphabetical Host Key Algorithm in SSH Profile

Type
Support Solution
Published
2026-03-15
Updated
2026-03-15
Applies to
  • BIG-IP
  • BIG-IP AFM
Source
https://my.f5.com/manage/s/article/K000160353

Description

When configuring a BIG-IP AFM virtual server with an SSH proxy profile containing multiple host key algorithms (e.g., RSA, ECDSA, ED25519, DSS) in the auth-info section, only the first entry (alphabetically) is advertised to connecting SSH clients. As a result, clients that require a different host key algorithm may fail to connect, receiving errors such as:

Unable to negotiate with <ip> port 22: no matching host key type found. Their offer: rsa-sha2-512,rsa-sha2-256,ssh-rsa

This behavior prevents simultaneous support for multiple host key algorithms on a single SSH proxy profile.

Environment

  • BIG-IP AFM (Advanced Firewall Manager)
  • Multiple auth-info entries in the SSH profile, each specifying a different host key algorithm (e.g., ssh-rsa, ssh-ed25519, ecdsa-sha2-nistp256, ssh-dss)

Cause

Bug ID 2222185

Recommended Actions

  • Upgrade to an Engineering Hotfix that includes the fix for Bug ID 2222185.
    - After applying the fix, the SSH proxy will correctly advertise all configured host key algorithms in the auth-info section, allowing clients to negotiate using any of the supported types.
  • If unable to upgrade immediately, as a temporary workaround:
    • Configure only the preferred host key algorithm in the SSH proxy profile (remove other auth-info entries).
    • Alternatively, create separate SSH proxy profiles (each with a single key type) and assign them to different virtual servers or IPs, allowing clients to connect to the appropriate endpoint based on their supported algorithms.

Additional Information

  • Prior to the fix, the SSH proxy only advertises the host key algorithm from the first auth-info entry (alphabetically), regardless of how many are configured.
  • After applying the Engineering Hotfix, all configured host key algorithms are advertised, matching standard SSH server behavior.
  • Use modern algorithms such as ECDSA or ED25519 for stronger security, as RSA is deprecated in recent SSH implementations.
