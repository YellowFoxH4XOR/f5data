Issue

You should consider using this procedure under the following conditions:

  • Your BIG-IP APM access policy authenticates users with Microsoft Active Directory (AD).
  • The AD domain is configured with Password Settings Objects (PSOs).

Symptoms

As a result of an AD PSO misconfiguration, you may encounter the following symptoms:

  • The system displays an erroneous password expiration message when you attempt to establish an access session.
  • You observe log messages similar to the following in the /var/log/apm file:

    debug apd[<pid>]: 01490132:7: <sessionid>: AD PSO Cache: Can't find policy object 'CN=Administrator Passwords,CN=Password Settings Container,CN=System,DC=<domain>,DC=<domain suffix>' from cache of server '/<partition>/<server name>'
    warning apd[<pid>]: 01490185:4: <sessionid>: Can't get PSO for domain '<domain name>'
    warning apd[<pid>]: 01490183:4: <sessionid>: Failed to get maximum password age from domain '<domain name>' for user '<username>@<domain name>'

Recommended Actions

The BIG-IP APM system queries the AD server to create a cache of PSOs. To create a cache of PSOs, the BIG-IP APM system requires that the AD authenticating domain administrative user name has PSOs applied to the user.

Procedures

Determining if PSOs are applied

To determine if the configured authentication, authorization, and accounting (AAA) AD profile authenticating domain administrative user name has PSOs applied to the user, use the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line on the affected BIG-IP APM device.
  2. Use the following ldapsearch command syntax to query an AD server for the applied PSOs:

    ldapsearch -xLLL -H 'ldaps://<ad server hostname or ip address>' -b "CN=Administrator Passwords,CN=Password Settings Container,CN=System,<ad domain>" -s sub -D "cn=<administrative user name>,cn=Users,<domain>" -w '<password>' "(objectClass=msDS-PasswordSettings)"

    Note: <ad domain> is the fully qualified domain name using AD domain components.

    The fully qualified domain name appears similar to the following example:

    ad.example.com

    The fully qualified domain name using AD domain components appears similar to the following example:

    dc=ad,dc=example,dc=com

    The ldapsearch command returns a verbose amount of data which includes references to the PSO common names (CNs).

    A misconfigured AD PSO does not return attributes but instead returns an error message similar to the following example:

    No such object (32)
    Matched DN: CN=Password Settings Container,CN=System,DC=ad,DC=example,DC=com
    Additional information: 0000208D: NameErr: DSID-0310020A, problem 2001 (NO_OBJECT), data 0, best match of:
    'CN=Password Settings Container,CN=System,DC=as,DC=example,DC=com'

    A successful query returns data that includes PSOs. The following example shows a successful ldapsearch query and output returning the PSOs CN=abc-pso and CN=xyz-pso:

    ldapsearch -xLLL -H 'ldaps://10.0.0.41' -b "CN=Password Settings Container,CN=System,dc=ad,dc=example,dc=com" -s sub -D "CN=Administrator,CN=Users,dc=ad,dc=example,dc=com" -w 'default' "(objectClass=msDS-PasswordSettings)"
