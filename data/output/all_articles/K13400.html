Security Advisory Description

  • CVE-2011-3389

    The SSL protocol, as used in certain configurations in Microsoft Windows and Microsoft Internet Explorer, Mozilla Firefox, Google Chrome, Opera, and other products, encrypts data by using CBC mode with chained initialization vectors, which allows man-in-the-middle attackers to obtain plaintext HTTP headers by way of a blockwise chosen-boundary attack (BCBA) on an HTTPS session, in conjunction with JavaScript code that uses (1) the HTML5 WebSocket API, (2) the Java URLConnection API, or (3) the Silverlight WebClient API, also known as a BEAST attack.

  • CVE-2012-1870

    The CBC mode in the TLS protocol, as used in Microsoft Windows XP SP2 and SP3, Windows Server 2003 SP2, Windows Vista SP2, Windows Server 2008 SP2, R2, and R2 SP1, Windows 7 Gold and SP1, and other products, allows remote web servers to obtain plaintext data by triggering multiple requests to a third-party HTTPS server and sniffing the network during the resulting HTTPS session, aka "TLS Protocol Vulnerability."

Impact

This vulnerability discloses data over an SSL session to an attacker.

BIG-IP

This vulnerability is exploited on the client-browser side of an SSL connection to either a virtual server or to the Configuration utility. In the case of client-browser access to a virtual server, the vulnerability is exploitable without server access, and no exploited packets are sent to the remote server. The following mitigations for this vulnerability are available for SSL profiles and the Configuration utility:

SSL profiles

You can mitigate this vulnerability for virtual servers using an SSL profile by configuring the SSL profile to use only TLS 1.2 and/or TLS 1.3 compatible ciphers.

Note: Support for TLS 1.3 was introduced in BIG-IP 14.1.0.1. By default, TLS 1.3 is disabled. For more information, refer to K10251520: BIG-IP support for TLS 1.3.

For information about configuring the ciphers used by an SSL profile, refer to the following articles:

  • K01770517: Configuring the cipher strength for SSL profiles (14.x - 17.x)
  • K17370: Configuring the cipher strength for SSL profiles (12.x - 13.x)

Note: When you modify cipher strings, it is helpful to understand the exclamation (!) and minus (-) negation symbols. When you use the ! symbol preceding a cipher, the SSL profile permanently removes the cipher from the cipher list, even if it is explicitly stated later in the cipher string. When you use the - symbol preceding a cipher, the SSL profile removes the cipher from the cipher list, but it can be added back to the cipher list if there are later options that allow it. For more information about building and viewing custom cipher lists, refer to K15194: Overview of the BIG-IP SSL/TLS cipher suite.

Configuration utility

Mitigation of this vulnerability is possible for the Configuration utility by restricting the Configuration utility to use only TLS 1.2. For more information, refer to the following resources:

  • K02321234: Managing the SSL protocols and ciphers allowed by Configuration utility
  • K83070749: How to determine what TLS ciphers and protocols are negotiable using the Configuration utility

For example, to restrict the Configuration utility to use only TLS 1.2, perform the following procedure:

Impact of workaround: The Configuration utility will use only TLS 1.2. Clients who do not support TLS 1.2 may not be able to connect.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Before you change the SSL cipher string, you should review the existing string for your specific BIG-IP version. To list the currently configured cipher string, type the following command:

    list /sys httpd ssl-protocol

    For example, the BIG-IP 14.1.0 system displays the following cipher string:

    ssl-protocol "All -SSLv2 -SSLv3 -TLSv1"

  3. To restrict Configuration utility access to clients using TLS 1.2, type the following command:

    modify /sys httpd ssl-protocol "all -SSLv2 -SSLv3 -TLSv1 -TLSv1.1"

  4. Save the configuration change by typing the following command:

    save /sys config

BIG-IQ

This vulnerability is exploited on the client-browser side of an SSL connection to the BIG-IQ. Mitigation of this vulnerability is available for the BIG-IQ user interface by removing all SSL and TLS 1.0 protocols from the BIG-IQ user interface configuration. To do so, perform the following procedure:

Impact of workaround: This procedure restarts the webd process and temporarily disrupts traffic to the BIG-IQ system. You should perform this procedure during a maintenance window.

  1. Log in to the BIG-IQ command line.
  2. Back up a copy of the /etc/webd/webd.conf file by typing the following command:

    cp -p /etc/webd/webd.conf /var/tmp/webd.conf.k13400

  3. Edit the /etc/webd/webd.conf file using a text editor of your choice, for example vi.
  4. In the /etc/webd/webd.conf file, locate the following line:

    ssl_protocols SSLv2 SSLv3 TLSv1 TLSv1.1 TLSv1.2;

  5. Remove all SSL and TLS 1.0 protocols from this line. After editing, this line should appear similar to the following example:

    ssl_protocols TLSv1.2;

  6. Save the changes and exit the text editor.
  7. Restart the webd process by typing the following command:

    tmsh restart sys service webd
