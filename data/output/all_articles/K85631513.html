K85631513: Restrict traffic based on geographic location with NGINX Plus

Topic

You should consider using this procedure under the following condition:

  • You want to restrict web application traffic based on geographic location.

Description

You can use NGINX Plus and third-party MaxMind databases to restrict web application traffic based on the client’s geographical location. For example, you can use the MaxMind GeoIP2 module to differentiate user traffic based on geographical location and allow users from certain geographic locations to access the application while denying access to users from other locations.

Note: The procedures in this article use the GeoLite2 databases which are free IP geolocation databases provided by MaxMind. For production use, refer to MaxMind for information about the commercial GeoIP2 databases. This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have one or more Ubuntu Linux instances which are hosting the NGINX Plus software.

Procedures

Register for a MaxMind account and obtain your account ID and registration key

To install the GeoLite2 database on NGINX Plus, you need to sign up for a free GeoLite2 account and obtain your account ID and registration key. For more information, refer to GeoLite2 Free Geolocation Data. Save your GeoLite2 account ID and registration key for later use.

Install the geoipupdate package and dependencies

To install the geoipupdate package and dependencies for Ubuntu systems which are hosting NGINX Plus, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the NGINX Plus system.
  2. To add the MaxMind personal package archives (PPAs) repository, enter the following command:

    sudo add-apt-repository ppa:maxmind/ppa

  3. To update available packages, enter the following command:

    sudo apt update

  4. To install the geoipupdate package and dependencies enter the following command:

    sudo apt install geoipupdate libmaxminddb0 libmaxminddb-dev mmdb-bin

Install the GeoIP license key

To install the GeoIP license key and update the GeoIP database, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Obtain your GeoLite2 account ID and registration key.
  2. Log in to the command line of the NGINX Plus system.
  3. Use a text editor to edit the /etc/GeoIP.conf file.

    For example:

    vi /etc/GeoIP.conf

  4. Replace <YOUR_ACCOUNT_ID_HERE> and <YOUR_LICENSE_KEY_HERE> with the account ID and license key you obtained from MindMax.

    For example, the GeoIP.conf file appears similar to the following:

    # /etc/GeoIP.conf
    # Replace YOUR_ACCOUNT_ID_HERE and YOUR_LICENSE_KEY_HERE with an active account
    # ID and license key combination associated with your MaxMind account. These
    # are available from https://www.maxmind.com/en/my_license_key.
    AccountID <YOUR_ACCOUNT_ID_HERE>
    LicenseKey <YOUR_LICENSE_KEY_HERE>

    # Enter the edition IDs of the databases you would like to update.
    # Multiple edition IDs are separated by spaces.
    EditionIDs GeoLite2-ASN GeoLite2-City GeoLite2-Country

  5. Save the changes and exit the file.
  6. Update the GeoIP database by entering the following command:

    geoipupdate

Look up an IP address and review the GeoIP data structure

To look up an IP address in the specified MaxMind database file and review the GeoIP data structure, use the mmdblookup utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the NGINX Plus system.
  2. To query to the databases use the following syntax:

    mmdblookup –file <db_path> –ip <IP_addr> <date_path>

    For example,

    mmdblookup --file /usr/share/GeoIP/GeoLite2-Country.mmdb --ip 8.8.8.8

Configure GeoIP2 in NGINX Plus

To configure GeoIP2 in NGINX Plus and enable the GeoIP2 dynamic module in the NGINX Plus configuration file, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the NGINX Plus system.
  2. To install the GeoIP2 dynamic module for NGINX Plus, enter the following command:

    apt-get install nginx-plus-module-geoip2

  3. To enable the GeoIP2 dynamic module, use a text editor to edit the NGINX configuration file and add the following load_module directives to the main configuration level:

    load_module modules/ngx_http_geoip2_module.so;
    load_module modules/ngx_stream_geoip2_module.so;

    For example,

    vi /etc/nginx/nginx.conf

    load_module modules/ngx_http_geoip2_module.so;
    load_module modules/ngx_stream_geoip2_module.so;
    http {
        # ...
    }

  4. Add the paths to the database files using the geoip2 {} block for the http {} context, stream {} context, or both.

    For example,

    http {
         geoip2 /usr/share/GeoIP/GeoLite2-Country.mmdb {
         #...  
    }

  5. Add custom variables to the geoip2 block that will pass data from the GeoIP2 database to the map directive:

    For example,

    http {
         geoip2 /usr/share/GeoIP/GeoLite2-Country.mmdb {
              $geoip2_data_continent_code   continent code;
              $geoip2_data_country_iso_code country iso_code;
    }

  6. Add a map directive to restrict traffic for specified countries.

    For example,

    http {
         geoip2 /usr/share/GeoIP/GeoLite2-Country.mmdb {
              $geoip2_data_continent_code   continent code;
              $geoip2_data_country_iso_code country iso_code;
         map $geoip2_data_country_iso_code $allowed_country {
               default yes;
               CN no;
               RU no;
    }

  7. Save the changes and exit the file.
  8. Reload the NGINX configuration by entering the following command:

    nginx -s reload
