Description

VMware View application stream does not work with a security policy applied, even when it is in transparent mode.

Environment

  • VMware View
  • Security Policy

Cause

WebSocket profile not attached to the virtual server.

Recommended Actions

Apply a WebSocket profile to the virtual server.

VMware View uses the WebSocket protocol, and ASM cannot parse WebSocket traffic without a WebSocket profile applied.

Additional Information

Error messages similar to the following may be seen in /var/log/ts/bd.log:

101 Switching Protocols HTTP status arrived, but the websocket handshake failed.
Possible reasons are websocket profile isn't assigned on a virtual server or handshake is illegal.

A packet trace may show that the BIG-IP successfully load balances the WebSocket upgrade request, but does not load balance the WebSocket traffic, even after acknowledging it. See the following example:

10.10.10.80 → 10.10.10.15 HTTP IN       s1/tmm0 : HTTP/1.1 101 Switching Protocols
10.10.10.15 → 10.10.10.80 TCP OUT       s1/tmm0 : 52768 → 443 [ACK]
10.10.30.80 → 10.10.30.60 HTTP OUT      s1/tmm0 : HTTP/1.1 101 Switching Protocols
10.10.30.60 → 10.10.30.80 WebSocket IN  s1/tmm0 : WebSocket Binary [FIN] [MASKED]
10.10.30.80 → 10.10.30.60 TCP OUT       s1/tmm0 : 443 → 52768 [ACK]
10.10.30.60 → 10.10.30.80 WebSocket IN  s1/tmm0 : WebSocket Binary [FIN] [MASKED]
10.10.30.80 → 10.10.30.60 TCP OUT       s1/tmm0 : 443 → 52768 [ACK]

Note: In the first three packets, the WebSocket upgrade is completed. The client 10.10.30.60 then sends some WebSocket data, which doesn't get passed to the backend server.
