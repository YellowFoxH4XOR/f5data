Known Issue

This is the result of a known issue. The X-UA-Compatible http-equiv header allows web developers to specify which compatibility mode Internet Explorer (IE) should use when displaying a web page. This header is placed between the HTML head tags.

For example:

<head>
<title>Some Web Page</title>
<meta http-equiv="X-UA-Compatible" content="IE=EmulateIE7" />
</head>

Currently, when the Portal Access for FirePass or the web applications for BIG-IP APM reverse-proxy engines rewrites a page, it inserts the FirePass or BIG-IP APM JavaScript code above the X-UA-Compatible header. As a result, IE ignores the header.

Note: For more information about the X-UA-Compatible http-equiv header, refer to the following location. The following link will take you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge:

http://msdn.microsoft.com/en-us/library/cc817574.aspx.

F5 Product Development is tracking this issue as ID 317638 (formerly CR130782) for FirePass.

F5 Product Development tracked this issue as ID 223606 (formerly CR130782-1) for BIG-IP APM and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP APM release notes.

In addition, this issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

Workaround

For FirePass, you can work around this issue by configuring a Web Applications content processing script with the following parameters:

Note: For detailed instructions on configuring a Web Applications content processing script, refer to K9688: Overview of Web Applications content processing scripts.

  • Processing script name

    Enter a name for the script.

    For example:

    IE-Compat
  • URL match patterns

    Enter a list of affected URLs, optionally using wildcard characters.

    For example:

    http://www.example.com/db/index.html, http://app.example.com/*
  • Content Type

    Enter the following:

    text/html
  • Sed processing script

    Enter the following code, where <content-attribute> is the name of the content tag listed in the HTML source code (such as IE=7 or IE=EmulateIE7):

    s@<head>@<head><meta http-equiv="X-UA-Compatible" content="<content-attribute>" />@

    For example:

    s@<head>@<head><meta http-equiv="X-UA-Compatible" content="IE=7" />@
  • Processing

    Select Post-process response data (after content patching)
