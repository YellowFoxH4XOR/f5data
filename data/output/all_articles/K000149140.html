K000149140: bd not sending messages to other processes after an upgrade

Description

Sometimes after an upgrade, the ASM module may not log any traffic—either locally or remotely—even though otherwise ASM inspection and enforcement appears to function as expected.  The tmctl stats confirm that bd is not sending messages to other processes.

To confirm that bd is not sending messages to other processes, use this command: tmctl -f /var/tmstat/blade/asm_bd asm/bd_remote_log_pipe

If the output shows all 0's, then no messages are leaving the bd process:

name           internal_drop external_drop successful
-------------- ------------- ------------- ----------
sampling                   0             0          0
tightening                 0             0          0
violation                  0             0          0
statistic_msgs             0             0          0
request_log                0             0          0
remote_logger              0             0          0

Environment

One of the following modules is provisioned and configured:

  • ASM
  • AFM

Cause

Unknown at time of publication.

Recommended Action

Restart ASM from the CLI: bigstart restart asm

Note: This is disruptive to traffic passing through the unit and will result in a failover in HA environment.
