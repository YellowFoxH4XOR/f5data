K000139754: BIG-IP VXLAN tunnel fragmenting packets even after change the MTU size

Type
Support Solution
Published
2024-05-23
Updated
2024-05-23
Source
https://my.f5.com/manage/s/article/K000139754

Description

When using VXLAN tunnels in the BIG-IP with something shorter than the biggest jumbo frame, then updating the vxlan's tunnel MTU to something higher, the BIG-IP doesn't honor it and keeps fragmenting the packets to shorter frames than the previous MTU.

Environment

  • VXLAN tunnels
  • Jumbo frames
  • Fragmentation
  • Network MTU changed directly in the bigip_base.conf

Cause

That way to update the tunnel config (as in the GUI is grayed out) doesn't work, the BIG-IP don't take the change.

Recommended Actions

Delete all the tunnel's configuration objects. Normally in this order: 

  1. Routes
  2. Self IPs
  3. FDB records
  4. Tunnel

Additional Information

None
