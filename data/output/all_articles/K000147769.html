K000147769: How to use the second origin pool as a maintenance one during downtime of primary origin pool.

Description

I have two or more origin pools active;

  1. For the main application
  2. Displays a maintenance page

I want the maintenance page to show during downtime of my primary origin pool.

Environment

  • F5® HTTP Load Balancer

Cause

  • None

Answer/Recommended Actions

Your use case will be a “failover maintenance” page to be displayed in the event of the high priority pool failing. The secondary pool will have just one host and needs to have that DNS name in the Host header in order to work.

 

You have to use Routes for this use case:

In the above window you have to change the following:

  1. App-origin in the place of redirect-op
  2. Maintenance-origin in the place of example-op

Note: Make sure that you set the priority and weight as shown in the picture.

With this, whenever App-origin is down for maintenance, the traffic will be directed to Maintenance-origin.

 

Additional Information

This is fully controlled by Health Check configurations.

When you decided to take down App-origin for maintenance, health check configured on this origin pool should be failing for all public ip endpoints (2 in his case). Only in that case, you can expect the traffic to go to Maintenance-origin.

Once App-origin is back up and running post maintenance, the traffic starts going back to it by the virtue of priority settings we have done. Hope this helps.
