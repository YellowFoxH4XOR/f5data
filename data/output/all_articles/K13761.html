Topic

This article applies to BIG-IP DNS (formerly BIG-IP GTM) and Link Controller 11.x through 17.x. For information about other versions, refer to the following article:

  • K12175: The BIG-IP Link Controller requires a unique VLAN and IP subnet for each link you configure (9.x - 10.x)

Purpose

You should consider using this procedure under the following condition:

  • You want BIG-IP DNS or Link Controller to monitor multiple ISP links that reside on the same Virtual Local Area Network (VLAN) and IP subnet.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You can access the Configuration utility and TMOS Shell (tmsh).
  • You have an additional IP address ready to configure as a self IP address for each ISP link.

Description

As part of the procedure, you must define the physical connections to the Internet. To do this, create link objects using the IP addresses of routers on the network that provide a path to the Internet. To monitor the availability and status of the links, you must use the bigip_link health monitor.

A requirement exists for each link to be associated with a unique VLAN and IP subnet. If multiple links are defined in the same IP subnet, the bigip_link health monitor only marks one link as up. The system marks links as up depending on the order of the links in the configuration; this behavior is by design.

For example, the following configuration shows that all three ISP links reside on the same VLAN and IP subnet. When these links are monitored by the bigip_link health monitor, only one of the three links is marked up:

Figure: Configuration with all ISP links residing on the same VLAN and IP subnet

The following configuration shows that each of the three ISP links reside on a different VLAN and IP subnet. When these links are monitored by the bigip_link health monitor, all three links are marked up:

Figure: Configuration with three ISP links residing on different VLAN and IP subnet

You may be able to use the following techniques to ensure that each link resides on a unique VLAN with a unique IP subnet:

  • VLAN tagging

    If the BIG-IP platform does not have sufficient interfaces to accommodate all links and internal networks, you can use the IEEE 802.1Q standard (also known as VLAN tagging) to host multiple VLANs on the same interface. For example, the internal, isp1, isp2, and isp3 VLANs can all reside on the same physical interface as long as VLAN tagging is used.

  • IP subnetting

    If you cannot dedicate an entire IP network to each link, you may be able to more efficiently use the address space that is available to you by performing subnetting. For example, you do not need to dedicate an entire class C network to each link. Depending on your specific requirements, the following subnets may suffice: 192.168.1.0/30 for isp1, 192.168.1.4/30 for isp2, and 192.168.1.8/30 for isp3.

F5 strongly recommends that each link reside in a different VLAN and IP subnet. However, if this configuration is not possible, performing the following procedures allow the bigip_link monitor to correctly verify the availability and status of all links.

Procedures

  • Configuring additional self IP addresses so that one self IP address exists for each upstream router
  • Configuring a one-to-one mapping between links and self IP addresses

Configuring additional self IP addresses so that one self IP address exists for each upstream router

When multiple links reside in the same VLAN and IP subnet, you must create a self IP address for each link. To create the required additional self IP addresses, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Network > Self IPs > Create.
  3. Enter an appropriate IP address.
  4. Enter an appropriate subnet mask.
  5. Select the VLAN used to communicate to the upstream routers.
  6. Select Finished.
  7. Repeat this procedure until one self IP address exists for each upstream router.

Configuring a one-to-one mapping between links and self IP addresses

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Inspect the configuration to ensure that the links have been configured, by entering the following command:

    list gtm link

    For example, if you have defined the three ISP links correctly, you should see the command return output similar to the following example:

    gtm link isp1 {
    datacenter /Common/default
    monitor bigip_link
    router-addresses {
    192.168.1.251 {
    device-name /Common/isp1
    }
    }
    }

    gtm link isp2 {
    datacenter /Common/default
    monitor bigip_link
    router-addresses {
    192.168.1.252 {
    device-name /Common/isp2
    }
    }
    }

    gtm link isp3 {
    datacenter /Common/default
    monitor bigip_link
    router-addresses {
    192.168.1.253 {
    device-name /Common/isp3
    }
    }
    }

  3. Inspect the configuration to ensure that the self IP addresses have been added, by using the following syntax:

    list gtm server <name of BIG-IP>

    For example, to view the configuration of LinkController.example.com, you would enter the following command:

    list gtm server LinkController.example.com

    For this example, the command should return output similar to the following example:

    gtm server /Common/LinkController.example.com {
    addresses {
    192.168.1.1 {
    device-name LinkController.example.com_1
    }
    192.168.1.2 {
    device-name LinkController.example.com_1
    }
    192.168.1.3 {
    device-name LinkController.example.com_1
    }
    }
    datacenter /Common/default
    monitor /Common/bigip
    virtual-server-discovery enabled
    }

  4. Configure the one-to-one mapping between links and self IP addresses using the following syntax:

    modify gtm server <name of BIG-IP> addresses modify { <self IP address> { explicit-link-name <link name> } }

    For example, to associate link isp1 with self IP address 192.168.1.1 on LinkController.example.com, you would enter the following command:

    modify gtm server LinkController.example.com addresses modify { 192.168.1.1 { explicit-link-name isp1 } }

    Repeat this command for each one-to-one mapping.

  5. Save the change by entering the following command:

    save sys config
