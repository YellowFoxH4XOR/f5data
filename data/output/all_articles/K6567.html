Description

MAC addresses are stored in two places for BIG-IP systems:

  • Layer 2 (L2) Forwarding Database (FDB). The FDB is stored on the switch chip, sometimes called application-specific integrated circuits (ASIC), which are self-contained integrated circuit chips with a limited amount of built-in memory. This database is integral to L2 switching decisions.
  • The Traffic Management Microkernel (TMM) Address Resolution Protocol (ARP) table is a software cache that utilizes the BIG-IP system RAM and may be greater in size compared to memory available on the ASIC. The ARP table is maintained by TMM and is used for Layer 3 (L3) routing and proxying decisions.

L2 forwarding database

Various BIG-IP platforms support a large number of entries in their L2 forwarding table. Depending on the platform, the maximum number of entries may be 8,192 or 16,384 or 32,768 or 131,072 or 557056.

# These hardware products have a different hardware design compared to the other rSeries hardware products; as a result, they do not have a FDB table.

The maximum L2 forwarding entries is a hardware limit and you cannot configure it. When the FDB table is full, if a unicast packet arrives and the destination MAC is unknown, the packet will be flooded. As a result, packet loss should not occur, but the local LAN will see increased traffic due to the flooding of these packets.

You can view the entries in the L2 forwarding table. To do so, type one of the following commands from the command line:

  • BIG-IP 11.4.x and later

    tmsh list net fdb vlan <vlan_name> all-properties

  • BIG-IP 10.x - 11.3.x

    tmsh show net fdb all

Note: In BIG-IP 11.2.1 through 11.3.0, the tmsh show net fdb all command may cause system instability if the configuration contains VXLAN or EtherIP tunnels combined with VLAN groups.

TMM ARP table

By default, the TMM process allows up to 8,192 entries in the ARP table:

You can modify the maximum number of entries in the TMM ARP table. To do so, type the following command from the command line:

tmsh modify sys db arp.maxentries { value <number> }

Replace <number> with the number of entries you want in the TMM ARP table.

If the arp.maxentries value is changed to a value that is lower than the current number of ARP table entries, the existing entries will not be affected. The system will allow the existing ARP entries to remain until they time out.

Additionally, static ARP entries cannot be created if the value of arp.maxentries will be exceeded. If you attempt to add a static ARP entry when the table is full, the system may log a "connect: No buffer space available" error message.

To view the entries in the TMM ARP table, type the following command from the command line:

tmsh show net arp
