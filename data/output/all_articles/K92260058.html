K92260058: SCP automated backup gives error ''no matching key exchange method found''.

Type
Support Solution
Published
2024-05-01
Updated
2024-05-02
Applies to
  • BIG-IP Platforms
Source
https://my.f5.com/manage/s/article/K92260058

Description

When trying to secure copy SCP/SFTP from BIG-IP to a remote system (Server), you encounter the following error:

no matching key exchange method found: client ecdh-sha2-nistp256,ecdh-sha2-nistp384,ext-info-c server diffie-hellman-group1-sha1,diffie-hellman-group14-sha1,diffie-hellman-group-exchange-sha1,diffie-hellman-group-exchange-sha256

Environment

  • BIGIP (SCP/SFTP client)
  • Remote (SCP/SFTP server)
  • CLI

Cause

Difference in Key Exchange (KEX) algorithms supported by BIGIP scp/sftp client and remote server 

Recommended Actions

It can be solved two ways:

  • Adding support of ecdh-sha2-nistp256 or ecdh-sha2-nistp384 on server side. This would be the better solution from security point of view, or

 

  • Enabling Diffie-Hellman-group14-sha1 on BIGIP client.
  1. Login to the BIG-IP via CLI and make a copy of the current SSH client configuration file:
    # cp /config/ssh/ssh_config /config/ssh/ssh_config.bak
  2. Check the current configured KEX:
    cat /config/ssh/ssh_config

    Example: Default KEX algorithms:

           KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384

           Example: Updated KEX algorithms:

     KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,diffie-hellman-group14-sha1
