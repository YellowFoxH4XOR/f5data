Description

High CPU usage was observed on the control plane processes (TMM, BD, and Java) after adding device members to the device trust.
The issue is related to spurious REST requests to:

http://localhost:8100/mgmt/shared/resolver/device-groups/tm-shared-all-big-ips/devices/

and errors in the restjavad logs. Relevant error messages include:

Failed to discover 192.168.1.1: java.lang.IllegalStateException: Could not connect to host 192.168.1.1. Please ensure there are no licensing, firewall, port lockdown or network connectivity issues. Error: Connection refused.
AsyncContext completed and/or Request lifecycle recycled.

Additionally, audit logs showed configuration changes such as modifying SelfIP and HA settings.

Environment

  • Product: BIG-IP LTM
  • Device trust was established between two BIG-IPs.
  • Changes were made to SelfIP and HA configurations during this process.

Cause

The high CPU usage was caused by a misconfiguration in the High Availability (HA) setup due to changes in the SelfIP used for HA communication (configsync-ip). This triggered excessive REST API calls related to tm-shared-all-big-ips, which is part of BIG-IP REST initialization.

Recommended Actions

To resolve this issue, follow these steps:

  • Workaround Option 1:
    • Follow the workaround provided in K38984252. This involves clearing REST storage and rebuilding the device trust.
  • Workaround Option 2:  Rebuild the HA configuration entirely by performing these steps:
    • Rebuild the device trust.
    • Clear REST storage using appropriate commands.
    • Reconfigure HA settings with correct SelfIP values.

Note: Ensure that all IP addresses used for configsync-ip are correctly configured and accessible without any network restrictions or conflicts.
         Monitor CPU usage after applying these changes to confirm resolution.
