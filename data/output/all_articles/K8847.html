K8847: The BIG-IP WebAccelerator Content-Type matching precedence occurs when duplicate MIME Type or ext values are defined for multiple objects in the globalfragment.xml file

Topic

The globalfragments.xml file contains a list of object types that the BIG-IP WebAccelerator system uses to classify responses from the origin server. Several elements are taken into account when classifying responses, including the respective object type and precedence to the selection.

The request and response headers are processed to identify a response in the following order:

  • The extension from the Filename field in the Content-Disposition header of a response.
  • The extension from the Extension field in the Content-Disposition header of a response.
  • The Content-Type field of the response, unless it is of an ambiguous MIME type, such as application/octet-stream. If no other matching criteria succeeds, the object will fall under the other type.
  • The extension of the path in the request.
  • If none of these options are present and do not match, you can match the other type and perform the actions you would for the least invasive media group.

Important: If you defined a duplicate MIME type or ext value for multiple object types, the object type defined in the higher position within the globalfragments.xml file has precedence.

For example, the following static and dynamic object types are both defined with a MIME type of text/html. Server responses with a MIME type of text/html will be classified as static because the static object type is defined higher than the dynamic object type in the globalfragments.xml file:

<objType
type="static"
group="pages"
category="common"
displayName="static"
ext="htm, html, wml"
mimeType="text/html, text/vnd.wap.wml, text/wml"
compressToClient="policyControlled"
/>
<objType
type="dynamic"
group="pages"
category="common"
displayName="dynamic"
ext="jsp, asp, aspx, wml, xhtml"
mimeType="text/html,
application/vnd.wap.wmlc, application/vnd.wap.xhtml+xml,
application/xhtml+xml"
compressToClient="policyControlled"
/>
