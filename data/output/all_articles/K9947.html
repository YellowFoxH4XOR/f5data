Known Issue

The BIG-IP system goes offline when the Peer Management Address setting is not configured. This issue occurs when one of the following conditions is met:

  • A 9.x redundant system that is configured to use the network failover feature is upgraded to BIG-IP 10.0.x
  • A 10.x redundant system that is configured to use the network failover does not have the Peer Management Address setting defined

Beginning in BIG-IP 10.0.0, the Peer Management Address setting is used to identify the management IP address of the peer unit to the sod process. When the Peer Management Address setting is properly configured, the sod process uses the value to identify which network failover packets are from the peer system. This setting does not exist in BIG-IP 9.x.

Impact

The BIG-IP redundant system is unavailable to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system does not process traffic and reports the status of Offline in its command line prompt that appears similar to the following example:

    [root@1500ltm:Offline] config#

  • The BIG-IP system logs an error message similar to the following example to the /var/log/ltm file:

    010c0043:5: Peer management address is not set, network failover is not operational

  • The Configuration utility reports an error message that appears similar to the following example:

    Peer management address is required

Workaround

To work around this issue, you can configure the Peer Management Address setting. To do so, perform the following procedure:

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. Click Network Failover.
  5. In the Peer Management Address field, enter the management IP address of the peer system.
  6. To save the modifications, click Update.
  7. Repeat all the steps on the peer redundant system.

Note: Configuring the Peer Management Address setting does not by itself enable network failover traffic. To enable network failover traffic, you must define one or more unicast or multicast Configuration Identifier objects on the Network Failover screen. For more information, refer to the Configuring High Availability section of the TMOS Management Guide for BIG-IP Systems.
