K000148758: BIG-IP DNS synchronization is failing after device hostname was changed.

Type
Support Solution
Published
2024-11-27
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP DNS
Source
https://my.f5.com/manage/s/article/K000148758

Description

BIG-IP DNS synchronization is failing after hostnames were changed.

 

'tmsh show gtm iquery' lists related BIG-IP DNS systems as successfully "connected".

 

debug logs in /var/log/gtm:

Nov 21 23:01:31 bigip1 debug big3d[13050]: 012b1002:7: Got a connection from ::ffff:10.10.10.3:45254 to ::ffff:10.10.10.2:4353

Nov 21 23:01:31 bigip1 debug big3d[13050]: 012b9102:7: The GTMD at ::ffff:10.10.10.3:45254 has requested a config SYNC from this box.

Nov 21 23:01:31 bigip1 debug big3d[13050]: 012b1003:7: Sending a message to ::ffff:10.10.10.3:45254

Nov 21 23:01:31 bigip1 debug big3d[13050]: 012b9101:7: GTM SYNC request for commit_id range FROM 0 0 (null)

Nov 21 23:01:31 bigip1 err big3d[13050]: 012b0012:3: sync request error: mcp message construction failed

Nov 21 23:01:31 bigip1 err big3d[13050]: 012b0012:3: Gtm sync request failed from error: ::ffff:10.10.10.3:45254

Nov 21 23:01:31 bigip1 debug big3d[13050]: 012b1004:7: Removing connection between ::ffff:10.10.10.3:45254 and ::ffff:10.10.10.2:4353

 

Environment

  • BIG-IP DNS
  • iQuery

 

Cause

Unknown

 

Recommended Actions

Use the gtm_add command to manually reestablish the synchronization. Automatic synchronization functionality should then return.

 

Additional Information

None
