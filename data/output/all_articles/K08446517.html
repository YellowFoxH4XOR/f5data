Chapter 0: Guide introduction and contents

Introduction

An Application Programming Interface (API) is a software component that is commonly used to integrate applications and microservices with existing applications and software systems. As API use increases, attacks against APIs have become more prevalent; a recent Gartner study suggests that API attacks are among the most-frequent attack vector. In addition, APIs are subject to many of the same types of attacks as web applications and may be especially vulnerable to attacks related to authentication, authorization, and excessive data exposure.

Note: This guide pertains to the Open Web Application Security Project (OWASP) Top 10 risks for APIs. For information about the OWASP Top 10 risks for web applications and how to secure your F5 products and web applications against the OWASP Top 10 risks, refer to K45215395: Guide introduction and contents | Secure against the OWASP Top 10 for 2021.

About the OWASP API Security Top 10

The OWASP API Security Top 10 (2019) defines the most serious security risks for APIs. For more information, refer to the OWASP API Security Top 10.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

F5 products provide controls that enable you to secure your F5 products and APIs against the OWASP API Security Top 10 risks.

Secure your APIs against OWASP API Top 10 risks with F5 products

This guide describes how to use the security controls available in F5 products to secure your APIs against the OWASP API Security Top 10 risks. Bear in mind that your configuration and the level of security protection you implement depend on the specifics of your API.

F5 BIG-IP Advanced WAF and BIG-IP ASM

Security controls are available in the Advanced WAF and BIG-IP ASM systems, which use both positive and negative security models to secure your APIs against OWASP API Security Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and application response. The negative security model uses attack signatures to detect and thwart OWASP API Security Top 10 attacks.

BIG-IP APM

You can enhance API security against OWASP API Security Top 10 risks by using the BIG-IP APM system, which provides authentication, authorization, and other different controls such as rate limiting, clearly defined URI endpoints and methods for API protection.

NGINX App Protect

Security controls are available in the NGINX App Protect system, which uses both positive and negative security models to secure your APIs against OWASP API Security Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and API response. The negative security model uses attack signatures to detect and thwart OWASP API Security Top 10 attacks.

Contents

Broken object level authorization (Ch-1)

Broken object level authorization occurs when authorization rules that dictate which object can be accessed by which users do not exist or are not applied properly. This allows attackers to manipulate API request parameters to access objects to which they are not authorized to access. This chapter includes the following topics:

  • Broken object level authorization
  • Secure your APIs against broken object level authorization attacks with F5 products

Broken user authentication (Ch-2)

Broken user authentication occurs when the API authentication mechanisms are lacking or are not implemented correctly, allowing attackers to assume other users' identities. Attacks that target authentication endpoints include brute-force, credential stuffing, and credential cracking. This chapter includes the following topics:

  • Broken user authentication
  • Secure your APIs against broken user authentication attacks with F5 products

Excessive data exposure (Ch-3)

Excessive data exposure occurs when the API is designed to expose all properties of an object without considering the sensitivities of each property. The design assumption relies on the client side to perform the data filtering before displaying the results to the end user. This leads to the API returning more data than required by the end user, thereby increasing the risk of exposure of sensitive data. This chapter includes the following topics:

  • Excessive data exposure
  • Secure your APIs against excessive data exposure attacks with F5 products

Lack of resources and rate limiting (Ch-4)

Lack of resources and rate limiting occurs when there are inadequate restrictions on the number, content, and type of requests made by users of the API. This chapter includes the following topics:

  • Lack of resources and rate limiting
  • Secure your APIs against lack of resources and rate limiting attacks with F5 products

Broken function level authorization (Ch-5)

Broken function level authorization occurs when API user functions are not clearly defined or are too complex and, as a result, authorization checks are not completely implemented based on clear user group and roles. This chapter includes the following topics:

  • Broken function level authorization
  • Secure your APIs against broken function level authorization attacks with F5 products

Mass assignment (Ch-6)

Mass assignment occurs when API endpoints accept user input and bind them to code variables or internal object properties without proper filtering. This chapter includes the following topics:

  • Mass assignment
  • Secure your APIs against mass assignment attacks with F5 products

Security misconfiguration (Ch-7)

Security misconfiguration occurs when an API component is susceptible to attack due to a misconfiguration or insecure configuration option. Misconfiguration vulnerabilities are configuration weaknesses that may exist at any level of the API stack. This chapter includes the following topics:

  • Security misconfiguration
  • Secure your APIs against security misconfiguration attacks with F5 products

Injection (Ch-8)

Injection attacks occur when the API interpreter/parser does not properly filter or validate data being passed to the backend database management system (DBMS) or other integrated service. This may allow an attacker to send malicious requests that are incorrectly processed by the backend service. This chapter includes the following topics:

  • Injection
  • Secure your APIs against injection attacks with F5 products

Improper assets management (Ch-9)

Improper assets management vulnerabilities can occur when security best practices are not followed during the API development cycle. Not following security best practices in the design phase may lead to vulnerabilities such as old API versions, unpatched systems, outdated API documentation, and unnecessarily exposed API endpoints. This chapter includes the following topics:

  • Improper assets management
  • Secure your APIs against improper assets management attacks with F5 products

Insufficient logging and monitoring (Ch-10)

Insufficient logging and monitoring failures occur when there is a failure to sufficiently log, monitor, or report security events, such as login attempts. This chapter includes the following topics:

  • Insufficient logging and monitoring
  • Secure your APIs against insufficient logging and monitoring attacks with F5 products
