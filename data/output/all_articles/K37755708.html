Description

Users are experiencing intermittent connectivity issues with the BIG-IP Edge Client while connecting to a BIG-IP APM device that is load balanced via BIG-IP DNS (F5 BIG-IP DNS or equivalent products in this space).

As a result of GSLB (Global Server Load Balancing) being configured with a single name, a user may encounter the following symptoms:

  • Edge Client authenticates and then reconnects intermittently
  • Edge Client remains in an initializing state for longer than normal periods of time

Environment

  • DNS load balancing
  • BIG-IP APM
  • Edge Client

Cause
Variable depending on configuration and environment.  Use the steps below to troubleshoot and gather data on this issue.

Recommended Actions
First ensure that the environment is deployed as per the topology or HA recommendations at Deploying BIG-IP GTM with APM for Global Remote Access.

Note: The deployment guide is applicable to all current BIG-IP APM and GTM versions even though the Product / Version section of the guide does not reflect this.

Then if still not functioning and experiencing the symptoms previously mentioned, follow the next steps.

  1. Review the Edge Client log files to determine if it is redirecting the user to a BIG-IP APM with a unique name, such as vpn.apmlab.io redirects to west.vpn.apmlab.io

  2. If this is not the case & the environment is configured to utilize DNS based GSLB such as BIGIP DNS, then the following condition may occur:

    1. BIG-IP DNS attempts to establish an APM session on one BIG-IP with my.policy.   GET /my.policy
    2. When the client attempts to continue the session they are redirected to a BIG-IP where there is no session present.  GET /myvpn?<sid=abcdefgh>
    3. Resulting in uneven GSLB between BIG-IP APMs.
  3. Reviewing the Edge Client logs will provide a better indication.
