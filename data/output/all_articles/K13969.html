Known Issue

The BIG-IP system may not honor the route domain Strict Isolation setting. This issue occurs when all of the following conditions are met:

  • A virtual server is associated with a FastHTTP profile
  • The FastHTTP virtual server resides in one route domain while its pool members reside in another route domain
  • The two route domains do not have a parent-child relationship or do not have the same parent
  • One or both route domains are enabled with the Strict Isolation setting

Enabling the Strict Isolation setting on route domains isolates the traffic within those route domains and prevents the BIG-IP system from forwarding traffic between them. If there is any attempt to forward traffic between the route domains, the BIG-IP system should not forward and reports a log message to the /var/log/ltm file that appears similar to the following example:

01200011:4: Connection rejected from IP 192.168.20.12%2 port 33845 to IP 192.168.10.20%1 port 80: One of the route domains is strict.

The Strict Isolation setting was added and enabled by default beginning BIG-IP 10.1.0.

Impact

Traffic is erroneously routed across route domains.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Traffic is erroneously routed across route domains to the pool members.

Workaround

If you intend to strictly isolate traffic on their respective route domain, configure using another HTTP profile other than the FastHTTP profile.

Impact of workaround: F5 recommends you configure a virtual server that may work best for your environment and test any such changes in an appropriate environment.

However, if the desired behavior is to allow traffic across route domains, you can disable the Strict Isolation setting on the route domains by performing the following procedure:

Impact of workaround: Disabling the Strict Isolation setting on the affected route domains will allow traffic to be forwarded between the affected route domains.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Route Domains > Route Domain List.
  3. Click on the name of the affected route domain.
  4. Clear the Strict Isolation check box.
  5. To save the modification, click Update.
  6. Repeat steps 2 to 5 for the other affected route domain.
