K000160188: Audit log displays 'localhost.localdomain' instead of system hostname for GUI actions on BIG-IP

Description

When reviewing audit logs on BIG-IP systems, users may observe that certain entries - specifically those generated by GUI actions - display 'localhost.localdomain' as the hostname in the syslog header, rather than the expected system hostname. This can cause confusion when attempting to identify which device generated a particular log entry. In contrast, audit log entries generated by CLI actions display the correct system hostname in the syslog header.

Example:

GUI action:
Jul 3 13:37:00 localhost.localdomain info GUI[...]
CLI action:
Jul 3 13:37:41 testdevice_name.net notice tmsh[...]

Environment

  • BIG-IP

Cause

The difference in hostname display is due to the logging context:

  • GUI processes (httpd/restjavad) run in a restricted/chrooted environment, where the hostname defaults to 'localhost.localdomain'. As a result, syslog headers for GUI actions are stamped with this name.
  • CLI actions run in the base OS context, using the system's configured hostname, so their syslog headers reflect the correct hostname.
  • The actual device hostname is included in the message body of GUI audit log entries for identification.

Recommended Actions

This is expected system behavior. For device identification in audit logs, refer to the hostname included in the message body of GUI audit log entries. Continue to use the syslog header for CLI actions, as it will reflect the correct system hostname.
