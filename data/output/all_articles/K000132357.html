Description

The article provide useful information to support troubleshooting issues relating ASM/AWAF local logs.

Environment

  • Logging All Requests
  • High CPU ( and Memory )
  • Pending Suggestions
  • Bot Defense enabled

Cause

The most common issue experienced by BIG-IP ASM Administrators is the "Missing Logs".

The most common reason is the allocated resources reaching the limits. The most common configuration which lead to this is the use of Logging All Requests.

The limited resources are the Disk Space and Database table's row limit.

For Non-Virtual Platforms, it is 5 GB while for Virtual Editions ( and vCMPs ), 2 GB is allocated.

The row limit is set to 3 Million records.

Note: These are fixed in the code and cannot be changed.

Recommended Actions

The directory /var/asmdata1/request_log is what is limited to 3 GB ( or 5 GB for non-Virtual ) or 3 Million records. Whichever limit is reached first, process clean_db cleans up the request logs by dropping the older partitions to make room for new incoming entries that are being logged locally (if the virtual servers have a logging profile to log requests locally). This prevents /var/asmdata1/request_log from becoming full or being oversubscribed beyond its limit.

Note: This directory contains binary files in which all the request log information is stored.

To Check which of the limits have reached, refer to the following:

  • Row limit; the following command shows the number of requests that exist within MySQL database:
# mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` -e "select COUNT(*) from PRX.REQUEST_LOG"
 
  • Disk space:
# cd /var/asmdata1/request_log/
# du -ach


Note: A higher number from this output compared to what appears on the GUI ( event logs ) may be seen. This is because the database table PRX.REQUEST_LOG may contain some learning suggestions and logs with flag that indicates not to display). The same table also contains Bot defense request logs.

Logs from the GUI could be deleted, however, in some cases, new logs may still be missed as the system has not yet run the scheduled task to clean the files from /var/asmdata1/request_log and the database table.
 

Additional Information

There are some logs that may have a flag to indicate the log should not be displayed. For more information refer to K70045451: Some Request logs are missing on GUI but found fin the MySQL database

Pending suggestions can have an impact on the logging as well. These can also increase CPU and memory utilisation. These suggestions are in fact samples collected for Traffic Learning from the events that are triggered ( and logged ). Therefore, ensuring action is taken on them is essential to avoid performance impact. For more information, refer to K01121054: Limitations of ASM Event logging

Some events may trigger Support ID, however, these IDs may not be found. It is possible that they might have been generated by Bot Defense Protection. For more information, refer to K02120103: Unable to find the Support ID displayed in Response Blocking page
