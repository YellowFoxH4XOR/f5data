Issue

Old Behavior

In versions prior to BIG-IP 13.1.0, when the BIG-IP system inserts an X-Forwarded-For entry into a request, the BIG-IP system creates a new X-Forwarded-For header containing the source IP address and inserts the new header into the request, in addition to existing X-Forwarded-For headers.

For example, the BIG-IP system may receive a request from source IP address 172.17.100.100 that traversed multiple proxy servers and contains multiple X-Forwarded-For entries in separate headers:

  • X-Forwarded-For: 172.16.16.25
  • X-Forwarded-For: 172.16.34.20

If the Insert X-Forwarded-For setting is enabled in the HTTP profile, the BIG-IP system inserts an additional X-Forwarded-For header into the request before sending the request to the pool member:

  • X-Forwarded-For: 172.16.16.25
  • X-Forwarded-For: 172.16.34.20
  • X-Forwarded-For: 172.17.100.100

New Behavior

Beginning in BIG-IP 13.1.0, when the BIG-IP system inserts an X-Forwarded-For entry into a request, the BIG-IP system appends the source IP address in the request to the value of the existing X-Forwarded-For header. If multiple X-Forwarded-For headers are present in the request, the BIG-IP system appends the source IP address to the value of the last X-Forwarded-For header in the request.

Using the previous example, the modified X-Forwarded-For headers sent from the BIG-IP system to the pool member would appear as follows:

  • X-Forwarded-For: 172.16.16.25
  • X-Forwarded-For: 172.16.34.20, 172.17.100.100

F5 Product Development tracked this change as ID 632532.

Impact

When the BIG-IP system receives an HTTP request with an X-Forwarded-For header, the BIG-IP system appends the source IP address in the request to the existing X-Forwarded-For header rather than inserting an additional X-Forwarded-For header.

Additional Information

If you are running BIG-IP 13.1.0 or later and your backend servers still require the old behavior in versions prior to BIG-IP 13.1.0, where the system creates a new X-Forwarded-For header containing the source IP address and inserts the new header into the request, you can use an iRule with a definition similar to the following:

HTTP::header insert X-Forwarded-For [IP::remote_addr]

For more information, including applying the iRule securely, refer to the Using an iRule to insert the original client IP address in an X-Forwarded-For HTTP header procedure in K4816: Using the X-Forwarded-For HTTP header to preserve the original client IP address for traffic translated by a SNAT object.
