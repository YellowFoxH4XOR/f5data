Topic

You should consider using these procedures under the following conditions:

  • You want to renew or replace the BIG-IP system device certificate.
  • You want to use the Configuration utility to perform the required tasks.
  • If BIG-IP DNS (GTM) is provisioned, you should have less than four BIG-IP DNS systems in a DNS synchronization (sync) group configuration.

If you have four or more BIG-IP DNS systems in a DNS sync group, using the command line is more efficient. For more information, refer to one of the following articles:

  • K6353: Updating an SSL device certificate on a BIG-IP system
  • K9114: Creating a new SSL device certificate and key pair

Description

The BIG-IP system device certificate is an SSL certificate used to secure connections to the Configuration utility and to secure iQuery communication between BIG-IP DNS systems. The BIG-IP system device certificate can be either renewed or replaced with a self-signed or third-party-signed SSL certificate. The procedure you follow to update a device certificate depends on whether the BIG-IP system is a standalone system or a peer member in a DNS sync group.

Standalone system

Standalone systems use device certificates to secure connections to the Configuration utility when managing the BIG-IP system. If your BIG-IP system is a standalone device, you can use one of the following procedures to renew or replace the device certificate: 

  • Renew the device certificate
  • Replace the device certificate

Also perform the following procedure:

  • Update the device certificate intermediate CA if applicable

DNS sync group peer

DNS sync group peers use device certificates to secure connections to the Configuration utility when managing the BIG-IP system, and to secure iQuery communication between DNS sync group peer members. Each DNS sync group peer must obtain and install the device certificate from each of the DNS sync group peers in the Trusted Device Certificate and Trusted Server Certificate stores. If your BIG-IP system belongs to a DNS sync group, you must perform either the Renewing the device certificate or the Replacing the device certificate procedure, and then perform all of the remaining procedures that follow, in the listed order:

  • Renew the device certificate
  • Replace the device certificate
  • Update the device certificate intermediate CA if applicable
  • Update DNS sync group peers
  • Remove old certificate from local BIG-IP DNS device
  • Reinitialize iQuery
  • Verify iQuery

Prerequisites

You must meet the following prerequisites to use these procedures:

  • Have administrative access to the BIG-IP Configuration utility.
  • Have the new SSL certificate and key if you are replacing the device certificate.
  • Have the third-party CA certificate used to sign replacement device certificates.

Procedures

Renew the device certificate

If your BIG-IP system is part of a DNS sync group, F5 recommends that you renew the device certificate for 10 years to avoid unexpected iQuery failures caused by expired certificates. You can use the following procedure to renew the device certificate.

To watch a video demo of this procedure, go to Renew the BIG-IP device SSL certificate using the Configuration utility.

Impact of procedure: Your web browser may prompt you to add a new security exception. The system reports BIG-IQ-managed systems as Not Available until rediscovered.

  1. Log in to the Configuration utility.
  2. Go to the device certificate:
    • BIG-IP 13.0.0 and later:

      System > Certificate Management > Device Certificate Management > Device Certificate

    • BIG-IP 12.1.2 and earlier:

      System > Device Certificate

      Note: It is helpful for this and other procedures if you note the current information for Serial Number and Expires.

  3. Select Renew. 
  4. From the Issuer list select one of the following:

    Self to renew a self-signed certificate. The default BIG-IP DNS device certificate is self-signed.
    Certificate Authority to renew a previously installed CA signed device certificate.

  5. You must provide values for the following device certificate information:

    Common Name:  F5 recommends that you use the BIG-IP DNS system host name.
    Country: Enter a two-letter country code.
    Lifetime: F5 recommends 3650 (10 years).

  6. Select Finished.
  7. To ensure that the device certificate has successfully updated, review the Certificate Properties.
  8. If this device is a member of a DNS sync group, select Export. 
  9. Select the entire device certificate, including the ----BEGIN CERTIFICATE---- and ----END CERTIFICATE---- lines.
  10. Copy the device certificate for importing in the Updating DNS sync group peers procedure.

Replace the device certificate

If you intend to replace the BIG-IP device certificate, ensure that the new SSL key and certificate includes the client authentication (clientAuth) and server authentication (serverAuth) extended key usage (EKU) extensions. Refer to the following article for help in determining EKU extensions, K7717: BIG-IP DNS and Link Controller support for third-party SSL certificates. You have the option to include EKU extensions in your certificate request and you can do this from the BIG-IP command line; however, the CA that signs your request determines the extensions to add and can choose not to copy your requested extensions. F5 recommends contacting the CA to confirm that the aforementioned purposes are added to signed certificates. For more information refer to K51035715: Replace the Configuration utility's self-signed device certificate with a certificate signed by your organization's CA.

F5 recommends that you refer to the following suggestions when you create a new device certificate:

  • To help easily identify the device certificate, use unique values for the certificate Subject. For example, use a Common Name value that matches the BIG-IP DNS system hostname.
  • To avoid unexpected iQuery connection failures, create device certificates with extended validity periods. The default F5 device certificate has a 10 year validity period.

You can use the following procedure to replace the default device certificate.

To watch a video demo of this procedure, go to Replace the BIG-IP device SSL certificate using the Configuration utility.

Impact of procedure: Your Web browser may prompt you to add a new security exception. BIG-IQ-managed systems are reported as Not Available until rediscovered.

  1. Log in to the Configuration utility.
  2. Go to the device certificate:
    • BIG-IP 13.0.0 and later:

      System > Certificate Management > Device Certificate Management > Device Certificate

    • BIG-IP 12.1.2 and earlier:

      System > Device Certificate

      Note: It is helpful for this and other procedures if you note the current information for Serial Number and Expires.

  3. Select Import.
  4. From the Import Type list, select Certificate and Key.
  5. For Certificate Source and Key Source, select either Upload File or Paste Text.
  6. After you upload or paste the SSL certificate and key, select Import.
  7. Review Certificate Properties to ensure that the new device certificate has been successfully imported.
  8. If this device is a member of a DNS sync group, select Export. 
  9. Select the entire device certificate, including the ----BEGIN CERTIFICATE---- and ----END CERTIFICATE---- lines.
  10. Copy the device certificate for importing in the Updating DNS sync group peers procedure.

Update the device certificate intermediate CA if applicable

If your device certificate requires a chain certificate file so Configuration utility clients can establish a chain of trust, perform the following procedure. This procedure must be performed from the BIG-IP command line.

Impact of procedure: Access to the Configuration utility will be temporarily disrupted while the httpd process restarts.

  1. Log in to the command line of the BIG-IP device where you installed the new device certificate.
  2. Transfer the chain certificate to the /config/httpd/conf/ssl.crt/ directory. For more information, refer to: K175: Transferring files to or from an F5 system.
  3. To configure the BIG-IP to apply the chain certificate for the management interface, enter the following command:

    tmsh modify sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/<chain file>.crt

    For example:

    tmsh modify sys httpd ssl-certchainfile /config/httpd/conf/ssl.crt/myfile.crt

  4. To verify the chain certificate for the management interface, enter the following command:

    tmsh list sys httpd ssl-certchainfile

  5. To load the new certificate into the running configuration, restart the httpd process using the following command syntax:

    tmsh restart sys service httpd

Update DNS sync group peers

For successful iQuery communication, the Trusted Device Certificate and Trusted Server Certificate stores on each DNS sync group member must contain the following:

  • The device certificate of each DNS sync group member
  • The third-party CA certificate used to sign device certificates if applicable

The local Trusted Device Certificates and Trusted Server Certificate stores are automatically updated with the renewed or replaced device certificate. However, you must manually update the trusted certificate stores on remote DNS sync group peers. You can use the following procedure to update the trusted certificate stores on a remote DNS sync group peer.

Important: If the new device certificate has been signed by a third-party CA, follow these procedures to import both the device certificate and the third-party CA certificate.

Trusted Device Certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of a peer DNS sync group member.
  2. Go to the trusted device certificates:
    • BIG-IP 13.0.0 and later:

      System > Certificate Management > Device Certificate Management > Device Trust Certificates

    • BIG-IP 12.1.2 and earlier:

      System > Device Certificate > Trusted Device Certificates

  3. Select the old certificate.
  4. Select Remove.
  5. Confirm the removal.
  6. Select Import.
  7. For Import Method, select Append.
  8. Paste the device certificate to Certificate Source.
  9. Select Import. 
  10. Review Certificate Properties to ensure that the new certificate has successfully imported.
  11. Repeat the procedure starting at step 6 to import any third-party CA certificates if applicable.

Trusted Server Certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to DNS > GSLB > Servers > Trusted Server Certificates.
  2. Select the old certificate.
  3. Select Remove.
  4. Confirm the removal.
  5. Select Import.
  6. Ensure that the Import Method is Append.
  7. Paste the device certificate to Certificate Source.
  8. Select Import. 
  9. For Certificate Subject(s), select the device certificate.
  10. To ensure that the new certificate has successfully imported, review Certificate Properties.
  11. Repeat the procedure starting at step 5 to import any third-party CA certificates if applicable.
  12. Verify that the new device certificate and any intermediate or root certificates are in both the Trusted Device Certificates and the Trusted Server Cerificates lists.

Remove old certificate from local BIG-IP DNS device

You must manually remove the old certificate from the local Trusted Device Certificates and Trusted Server Certificate stores on the local BIG-IP DNS device.

Trusted Device Certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the BIG-IP DNS device where you installed the new device certificate.
  2. Go to the trusted device certificates:
    • BIG-IP 13.0.0 and later:

      System > Certificate Management > Device Certificate Management > Device Trust Certificates

    • BIG-IP 12.1.2 and earlier:

      System > Device Certificate > Trusted Device Certificates

  3. Select the old certificate.
  4. Select Remove.
  5. Select OK.
  6. Confirm the removal.

Trusted Server Certificate

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the BIG-IP DNS device where you installed the new device certificate
  2. Go to DNS > GSLB > Servers > Trusted Server Certificates.
  3. Select the old certificate.
  4. Select Remove.
  5. Select OK.
  6. Confirm the removal.

Reinitialize iQuery if DNS is provisioned 

You must reinitialize the iQuery connection to use the new device certificate by restarting the gtmd and big3d processes. You can use the following procedure to restart gtmd and big3d.

Impact of procedure: Performing the following procedure briefly halts iQuery communication with this DNS sync group peer.

  1. Log in to the Configuration utility of the DNS sync group member with the newly installed device certificate. 
  2. Go to System > Services.
  3. Select the check box for big3d and gtmd.
  4. Select Restart.
  5. Continue to Verifying iQuery.

Verify iQuery

If the configuration synchronization (ConfigSync) peers are being monitored using the bigip monitor, you can verify iQuery connection status to the remote DNS sync group peers using the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of any DNS sync group member.
  2. Go to DNS > GSLB > Servers.
  3. Under Status, verify that the iQuery communication status is Available (green).
