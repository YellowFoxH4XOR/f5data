K000151630: Controllers not responsive after F5OS-C upgrade from v1.6 to 1.8.0

Description

You tried to upgrade both Controllers and/or Chassis Partition(s) from v1.6.x to 1.8.0. The upgrade seems to be completed initially, but the Controller's console shown as below sample status for longer time:
[root@controller-1:Cluster update in-progress ~]#

You even tried to Reboot both Controllers as a workaround, but still same problem is there for two system controllers, as below console status:
[root@controller-1:Cluster update failed ~]#
[root@controller-2:Cluster update in-progress ~]#

Environment

  • F5OS-C (VELOS Platform)
  • Upgrade from v1.6.x to 1.8.0

The "show cluster" command at Controller-level shows "Openshift cluster is NOT initialized", like below sample output:

Cause

The Openshift cluster was not Initialized / completed successfully during upgrade, and It needs to be Re-installed again, manually.

Recommended Actions

Perform the following to prepare the Re-installation of Openshift cluster on your F5OS-C system.

Impact of workaround: As tenants on F5OS-C are down during the process, you should perform this only during a scheduled maintenance window. 

1. Ensure you have a backup of your VELOS chassis, partition data and all tenants. Refer to K50135154: Back up and restore the F5OS-C configuration on a VELOS system.

2. Shutdown all tenants in all partitions on the F5OS-C system by setting their running-state to provisioned.

3. Perform procedures on the active controller by using the management floating IP address. For example, you enter "touch /var/omd/CLUSTER_REINSTALL" command only on the 'Active' system controller to start the Re-installation process. The process typically takes around 90-110 Mins. Below is the referenced Article:
K000139870: Troubleshoot the Openshift cluster installation in F5OS-C

4. Once completed, check again for the "show cluster" command output and make sure the Openshift cluster is successfully Initialized and ready now.

5. Change the status of all tenants to deployed state one-by-one, and check for the tenant status to come up normally. In some rare cases, if the tenant failed to come up, and the "show tenants" command output at Partition-level shows "Allocating resources to tenant is in progress" on some slots (blades), you may need to manually Reboot the problematic blades to resolve this last Issue.
