Topic

SubDomain is a Linux kernel module, developed by Immunix, and is integrated into the BIG-IP system in version 9.2.

Note: SubDomain is also known as: Immunix and Day Zero Intrusion detection.

SubDomain's purpose is to profile daemons, and ensure the daemons' activity is restricted to a predefined profile. If a profiled daemon attempts to deviate from its defined profile, its actions are blocked at the Linux kernel.

Daemons that are protected by SubDomain have a profile that outlines the operations that the daemon will be allowed to perform. The profiles are located in the /etc/subdomain.d directory, and are named after the daemon's full path, for example: usr.sbin.httpd.

If a daemon attempts to perform an operation that is not allowed, a message is logged to the /var/log/ messages file, similar to the following example:

SubDomain: REJECTING r access to /proc/cmdline (mcpd(839) profile /bin/mcpd active /bin/mcpd)

Configuring SubDomain

Because SubDomain is intended to be transparent to the user, F5 recommends that you do not attempt to configure the SubDomain Linux kernel module.

Viewing currently protected daemons

To verify the daemons that are currently profiled on your BIG-IP system, perform the following procedure:

  1. Log in to the BIG-IP command line.

  2. Change directories to the /etc/subdomain.d directory, by typing the following command:

    cd /etc/subdomain.d

  3. Use the ls command to view the current SubDomain profiles, by typing the following command:

    ls -al

Allowing valid operations that are blocked by SubDomain

SubDomain may block a daemon from performing an operation you believe to be a valid operation, and log error messages to the /var/log/messages file. If this occurs, you should contact F5 Technical Support and request the error message be reviewed to determine if SubDomain is blocking a daemon from performing a valid operation. It is possible that a valid action was inadvertently blocked by SubDomain, requiring you to either install a hotfix or edit the daemon's profile, enabling SubDomain to allow the action once more.

For further information about protected daemon operations that are blocked by the Linux kernel, refer to K5915: Error Message: SubDomain: REJECTING access.

Until a fix is provided by F5 Technical Support, and if you are confident that SubDomain is blocking a daemon from performing a valid operation, you can perform the following procedure to prevent SubDomain from protecting the daemon:

  1. Log in to the BIG-IP command line.

  2. Change directories to the /etc/subdomain.d directory, by typing the following command:

    cd /etc/subdomain.d

  3. Move the SubDomain profile for the daemon to the /var/tmp directory, by typing the following command:

    mv /etc/subdomain.d/<daemon.profile.filename> /var/tmp

  4. Restart the SubDomain Linux module, by typing the following command:

    /etc/init.d/subdomain restart
