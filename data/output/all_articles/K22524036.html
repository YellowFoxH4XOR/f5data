Description

Due to the New Behavior documented in K86025623, the virtual server state in BIG-IP v13.x, v14.x and 15.0.x is reported as 'Available (Disabled Parent)' when all pool members are disabled manually by the BIG-IP administrator or by the health monitor with disable string.  Additionally, with this state, a new connection to the virtual server is NOT required to complete 3-way TCP handshake, and the BIG-IP sends TCP RST just right after the initial TCP SYN arrives from the client.

However, this new reset behavior created undesired outcome, where the existing iRule to display maintenance/sorry page has stopped working after upgrading to these BIG-IP versions as the iRule does not even get triggered due to the TCP RST behavior.  Also, the BIG-IP refuses a connection to the virtual server even if the client connection matches with the existing persistence record/table on the BIG-IP.
 

Therefore, this new reset behavior was readdressed in Bug ID 783617.  With this ID fix, a new connection to the virtual server is now required to complete a 3-way TCP handshake even when the virtual server state is 'Available (Disabled Parent)' in BIG-IP v15.1.0 and later, and:

  • Displaying maintenance or sorry page via iRule now works again when all pool members are disabled manually or marked disabled by the health monitor with disable string configured.
  • BIG-IP now load balances the incoming client connection if it matches with existing persistence record/table.

For example:

  • Virtual server has the following or similar iRule to display maintenance or sorry page:

    when HTTP_REQUEST {
        if { [active_members [LB::server pool]] == 0 } {
          HTTP::respond 200 content "Sorry, this page is not currently available."
        }
    }
     
  • All pool members are disabled manually or marked disabled by the health monitor (with disabled string configured), and the virtual server state shows Available (Disable Parent):

    # tmsh show ltm virtual my_vs_1510 | head -12

    ------------------------------------------------------------------
    Ltm::Virtual Server: my_vs_1510
    ------------------------------------------------------------------
    Status
      Availability     : available
      State            : disabled-by-parent
      Reason           : The children pool member(s) might be disabled
      CMP              : enabled
      CMP Mode         : all-cpus
      Destination      : 10.97.192.35:80
     
  • If a client connects to the virtual server above, the iRule is now triggered and the sorry page is displayed:

    # curl http://10.97.192.35/
    Sorry, this page is not currently available.
     
  • Additionally, the BIG-IP now load balances the incoming client connection if it matches with existing persistence record/table.

    # tmsh show ltm persistence persist-records mode source-address
    Sys::Persistent Connections
    source-address  10.97.192.34  10.97.192.35:80  10.97.192.2:80  (tmm: 0)
    Total records returned: 1

    <connection from client 10.97.192.34>
    # curl http://10.97.192.35/
    <html><body>Hello</body></html>
     

Environment

  • BIG-IP v15.1.0 and later (or any versions that include ID 783617 fix)
  • All pool members are disabled, and virtual server state is 'Available (Disabled Parent)'
  • iRule to display maintenance/sorry page
  • Persistence profile

Cause
This change is due to the fix for ID 783617
