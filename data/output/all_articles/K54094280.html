Topic

You should consider using this procedure under the following condition:

  • You want to secure your applications against Spring Framework (CVE-2022-22965 aka Spring4Shell) and Spring Cloud vulnerability CVE-2022-22963 with NGINX Application Security products

Description

You can use NGINX App Protect to mitigate the impact of the Spring4Shell and Spring Cloud vulnerabilities in your infrastructure. For more information about these vulnerabilities, refer to K11510688: Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities CVE-2022-22965, CVE-2022-22950, and CVE-2022-22963.

Important: If you log the full contents of requests (for example, full HTTP request logging) to a remote logging system which is vulnerable to CVE-2022-22965, CVE-2022-22950, or CVE-2022-22963, and that system parses the request body as sent by the BIG-IP, the remote logging system may still be vulnerable to exploitation.

Note: As stated in the security advisory, NGINX is not vulnerable to the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You are using one or more of the following NGINX Application Security products:
    • NGINX App Protect WAF
    • NGINX Controller App Security
    • NGINX Controller API-Management with Advanced Security

Procedures

Find specific guidance for your product in one the following sections:

  • Mitigate the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX App Protect WAF
  • Mitigate the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX Controller App Security and NGINX Controller API-Management with Advanced Security

Mitigate the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX App Protect WAF

To mitigate the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX App Protect WAF, perform the following procedures:

Download and apply the latest signature updates

Download and apply the latest signature updates for NGINX App Protect WAF to ensure that all the signatures you need are available.

For information about downloading and updating signatures, refer to Updating App Protect Attack Signatures in the NGINX App Protect WAF Configuration Guide.

Note: F5 recommends that you regularly update attack signatures for NGINX App Protect WAF. To be notified of attack signature updates, refer to K9970: Subscribe to email notifications regarding F5 products and security announcements.

For the broadest protection, ensure you have done the following:

  • Enabled Apache Tomcat, Spring Boot, and Java Servlets/JSP server technologies in your security policy
  • Set blocking mode as follows:
    • Include the Server Side Code Injection Signatures signature set.

      - OR -

      Enable the following individual signatures: 200003437, 200003438, 200003439, 200003443, 200003444, 200003445, 200004161, 200004453, 200104262, 200104263, 200104796, 200104797, 200104798, and 200104799.

    • Include the Generic Detection Signatures (High/Medium Accuracy) signature set.

If you use the original, preinstalled JSON policy files, such as NginxDefaultPolicy.json, NginxStrictPolicy.json, or NginxApiSecurityPolicy.json, you already have this signature set.

A JSON policy with the previously mentioned protections set to block appears similar to the following example:

{  
  "policy": {  
    "name": "block_spring4shell_policy",  
    "template": { "name": "POLICY_TEMPLATE_NGINX_BASE" },  
    "signature-sets": [  
      {  
        "name": "Server Side Code Injection Signatures",  
        "block": true,  
        "alarm": true  
      },  
      {  
        "name": "Generic Detection Signatures (High/Medium Accuracy)",  
        "block": true,  
        "alarm": true  
      }  
    ], 
    "server-technologies": [  
      { "serverTechnologyName": "Apache Tomcat" },  
      { "serverTechnologyName": "Spring Boot" },  
      { "serverTechnologyName": "Java Servlets/JSP" }  
    ]  
  }  
} 

Note: After you update attack signatures or make configuration changes to a policy, you must reload NGINX Plus to make the changes effective.

Note: F5 recommends that you perform adequate testing to ensure that application functionality is not impeded as a result of configuration changes. For more information, refer to the NGINX App Protect WAF Configuration Guide.

Mitigate the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX Controller App Security and NGINX Controller API-Management with Advanced Security

Note: NGINX Controller does not manage signature updates on NGINX instances. Therefore, you must perform the signature update process in Mitigating the Spring Framework (Spring4Shell) and Spring Cloud vulnerabilities with NGINX App Protect WAF on each NGINX instance on which you installed NGINX App Protect WAF.

If you are using NGINX Controller, you can modify the Controller default security policy to add the previously mentioned protections by using the Bring Your Own (BYO) NGINX App Protect Policy feature, available on NGINX Controller ADC 3.20 and later. However, note the limitation of the feature as indicated in Bring Your Own WAF Policy.
