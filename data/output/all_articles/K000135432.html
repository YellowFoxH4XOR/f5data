K000135432: NMS OIDC automation access fails with response code 403

Type
Support Solution
Published
2023-07-10
Updated
2023-07-10
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.11.0
Source
https://my.f5.com/manage/s/article/K000135432

Description

OIDC auth is successful to the NMS UI however OIDC automation and api requests (using curl, postman, etc) fails with response code 403.
OIDC log error: 

js: OIDC Token validation error: missing claim(s) sub

Environment

NMS
OIDC

Cause

NMS username becomes malformed. For example, an invalid "aud" claim value within the OIDC access token (with Azure AD OIDC as the IdP, NMS expects the "aud" claim value to be in the form of <aud_claim_id>@<oidc_domain>).

Recommended Actions

Check the "aud" claim value within the OIDC access token and ensure its in valid format.
Check the OIDC domain value within configuration file /etc/nms/nginx/oidc/openid_configuration.conf and ensure it's valid.
Remove the malformed username(s) from NMS:

  • Install dqlite: 
    sudo add-apt-repository -y ppa:dqlite/dev 
sudo apt install dqlite-tools libdqlite-dev
  • Connect to the core db: 
    dqlite -s 127.0.0.1:7891 core
  • Find the malformed username(s): 
    SELECT name FROM users;
  • Delete the malformed username(s): 
    DELETE FROM users WHERE name = "<malformed_username>";
  • Exit database: 
    <Ctrl+D>
