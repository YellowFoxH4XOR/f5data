Description

A BIG-IP virtual wire (vWire) configuration allows the BIG-IP system to be inserted transparently into an existing network path and operate at Layer 2 without requiring self IP addresses or changes to the surrounding Layer 3 network configuration.

 

A virtual wire logically connects two interfaces or trunks and forwards traffic between them in either direction. This makes vWire useful when you want to place the BIG-IP system inline for purposes such as security monitoring, traffic inspection, packet capture, or troubleshooting without making the BIG-IP system a routed hop. A forwarding virtual server is optional in a virtual wire configuration.

 

When you create a virtual wire, the BIG-IP system creates the supporting Layer 2 objects, including two VLANs and a VLAN group that logically connects those VLANs.

 

A VLAN group allows Layer 2 forwarding between its member VLANs. When the VLAN group is configured in virtual-wire mode, traffic is forwarded between two configured members while the Ethernet header remains unchanged from ingress to egress, making the BIG-IP system transparent to the devices on either side.

 

The vlangroup.forwarding.override database key determines which forwarding behavior takes precedence when the BIG-IP system has both:

 

  • A VLAN group
  • An applicable wildcard forwarding virtual server

 

The database key applies specifically to traffic whose destination MAC address does not match one of the BIG-IP system's local MAC addresses.

 

The default value is:

 

enable

 

When vlangroup.forwarding.override is enabled, traffic with a destination MAC address that does not match a local BIG-IP MAC address is bridged by the VLAN group, even when an applicable wildcard forwarding virtual server exists.

 

When vlangroup.forwarding.override is disabled, the applicable wildcard forwarding virtual server handles the traffic instead of allowing the VLAN group to bridge it directly.

 

Changing this database key is therefore not required simply because a virtual wire has been configured. The appropriate value depends on whether the intended forwarding behavior is transparent Layer 2 forwarding through the VLAN group or processing through an applicable wildcard forwarding virtual server.

 

Environment

  • BIG-IP
  • Virtual Wire
  • VLAN groups
  • Wildcard forwarding virtual servers
  • vlangroup.forwarding.override

 

Note: K16528 documents the vlangroup.forwarding.override database key for BIG-IP 11.x through 17.x. Availability and support for virtual wire configurations depend on the BIG-IP version, platform, and provisioned modules.

 

Cause

None. This is expected behavior.

 

The default value of vlangroup.forwarding.override allows the VLAN group to perform its intended Layer 2 bridging function when the destination MAC address is not local to the BIG-IP system.

 

A virtual wire configuration does not inherently require traffic to be processed by a wildcard forwarding virtual server. In the absence of a matching virtual server, BIG-IP Layer 2 transparency forwards traffic at Layer 2. A forwarding virtual server is optional and can be configured when security policy or other virtual-server processing is required.

 

Answer/Recommended Actions

Leave vlangroup.forwarding.override at the default value when Layer 2 forwarding is the intended behavior

 

Leave the database key enabled when the purpose of the virtual wire is to provide transparent Layer 2 forwarding and there is no requirement for the affected traffic to be processed by an applicable wildcard forwarding virtual server.

 

For example, a virtual wire may be used to insert the BIG-IP system transparently into an existing network path so that traffic can be monitored, captured, or inspected without changing the addressing, gateways, or routing configuration of the devices on either side.

 

In this type of deployment, the VLAN group is performing the Layer 2 forwarding function for which the virtual wire was configured. Changing vlangroup.forwarding.override is not necessary simply because a virtual wire exists.

 

Virtual wire interfaces operate transparently, bridge tagged and untagged traffic, preserve the MAC addresses, and base forwarding decisions on the ingress interface.

 

Disable vlangroup.forwarding.override when wildcard forwarding virtual server processing is required

 

Set the database key to disable when the design specifically requires traffic that would normally be bridged by the VLAN group to instead be processed by an applicable wildcard forwarding virtual server.

 

This may be necessary when functionality associated with the wildcard forwarding virtual server must apply to the traffic. Examples include:

 

  • FastL4 profile settings such as connection idle timeouts
  • Security policy associated with the forwarding virtual server
  • Other processing that depends on the traffic matching the wildcard forwarding virtual server

 

K16528 identifies FastL4 protocol-level settings as an example of why an administrator may want wildcard forwarding virtual server processing to take precedence over VLAN-group bridging. A forwarding virtual server can also be used to apply security policy to ingress traffic before forwarding it through the virtual wire.

 

For example, if the BIG-IP system is deployed using virtual wire so that it can transparently inspect traffic and the required security policy is associated with a wildcard forwarding virtual server, leaving vlangroup.forwarding.override enabled may allow the VLAN group to bridge applicable non-local-MAC traffic instead of allowing the wildcard forwarding virtual server to process it.

 

In this situation, disabling the database key is appropriate because virtual-server processing is an explicit requirement of the design.

 

Note: The presence of a wildcard forwarding virtual server alone does not mean that the database key must be disabled. The deciding factor is whether the traffic must be processed by that virtual server rather than bridged directly by the VLAN group.

 

Verify the current value

 

To display the current setting, enter the following command:

 

tmsh list sys db vlangroup.forwarding.override

 

The default value is enable.

 

Disable VLAN-group forwarding override

 

If wildcard forwarding virtual server processing is required, enter the following commands:

 

tmsh modify sys db vlangroup.forwarding.override value disable

tmsh save /sys config

 

Verify the change:

 

tmsh list sys db vlangroup.forwarding.override

 

Restore the default behavior

 

To restore VLAN-group Layer 2 forwarding precedence, enter the following commands:

 

tmsh modify sys db vlangroup.forwarding.override value enable

tmsh save /sys config

 

Verify the change:

 

tmsh list sys db vlangroup.forwarding.override

 

Important: vlangroup.forwarding.override is a system database key and is not a setting associated with an individual virtual wire. Before changing the value, consider whether other VLAN-group and wildcard forwarding virtual server configurations on the BIG-IP system rely on the existing behavior.
