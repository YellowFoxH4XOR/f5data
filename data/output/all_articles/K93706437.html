Description

You have a rule with "Conditions: URL Match is Glob Match(www.example.com)" created in your security policy of the topology
Example: the configuration is shown as below image

But you're unable to access that URL www.example.com thru this SSL orchestrator even the action is set to "Allow"

Symptoms you may see: 

  • In Internet Explorer browser you get "Can't reach this page"

    Note: Microsoft announced the end of support for Internet Explorer on June 15, 2022. You should use supported browsers such as Microsoft Edge, Google Chrome or Mozilla Firefox.

  • In Chrome browser you get "This site can't be reached"
  • With TCP RST cause enabled, in /var/log/ltm log, you would see SSL handshake failure and RST messages

  • With Debug enabled in Per-Request Policy of the topology,  in /var/log/apm log, you would see failed with reason (UNKNOWN) for that particular session id 4b36ea2d
May 10 09:53:45 sslo.lab.local info tmm1[11902]: 01870024:6: /Common/sslo_topology_name.app/sslo_topology_name_accessProfile:Common:4b36ea2d: Executed agent (/Common/ssloP_topology_name.app/ssloP_topology_name_per_req_policy_end_allow_ag) failed with reason (UNKNOWN)

Environment

  • BigIP SSLO
  • BigIP version v15.1.2
  • RPM 7.5.2
  • a rule with "Conditions: URL Match is Glob Match" is used in the security policy of the topology

Cause

  • Bug alias 1017053 [SSLO] Policy fails to complete when URL branching is configured

Recommended Actions

Use of "Category Lookup (All)" with a custom category that is configured with the URL and Glob Pattern Match enabled instead of using "URL Match" is Glob Match(www.example.com).
