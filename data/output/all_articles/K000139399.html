K000139399: Wrong LAG speed shown on rSeries r2000/r4000 when port speed 1G in use with 8x10G port-profile

Type
Support Solution
Published
2024-04-25
Updated
2024-04-25
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.5.X, 1.7.0, 1.5.2, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000139399

Description

Wrong speed is shown by rSeries LAG when member interfaces are operating at 1G speed with 8x10G port-profile in use.

LAG speed displayed indicates that the interfaces are operating at 10G.

interfaces interface 1.0
 state type               ethernetCsmacd
 state mtu                9600
 state enabled            true
 state oper-status        UP
 ...
 ethernet state port-speed SPEED_1GB            <--- Correct

interfaces interface 2.0
 state type               ethernetCsmacd
 state mtu                9600
 state enabled            true
 state oper-status        UP
 ...
 ethernet state port-speed SPEED_1GB            <--- Correct

interfaces interface INTERNAL_TRUNK
 state type  ieee8023adLag
 state mtu   9600
 state oper-status UP
 aggregation state lag-type LACP
 aggregation state lag-speed 20                 <--- Incorrect (should be 2)
 ...
MEMBER  MEMBER  
NAME    STATUS  
----------------
1.0     UP      
2.0     UP   

Environment

  • rSeries r2000/r4000
  • 8x10G port-profile in use
  • Interfaces operating at 1G speed (auto-negotiated with peer switch)

Cause

Bug ID 1470917

This bug is not yet fixed at the time of this article's publication, but is expected to receive a fix in due course.

Recommended Actions

No action is required. This is a display issue.

There should be no functional impact on the bandwidth of the LAG.

Additional Information

The trunk will display the correct speed within tenants.
