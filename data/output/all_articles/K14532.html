Known Issue

The Traffic Management Microkernel (TMM) may respond to client requests with an ICMP Fragmentation Needed (Type 3 Code 4) message based on the cached route metric learned from the upstream router for a pool member to client response.

This issue occurs when all of the following conditions are met:

  • The virtual server is a FastL4 virtual server.
  • When sending a response back to a client, the BIG-IP system receives the ICMP Fragmentation Needed message from the upstream route and sets the advertised route metric.
  • Subsequently, the BIG-IP system receives a packet from a client that exceeds the route metric value.

The ICMP Fragmentation Needed message should be sent to the pool member, not the client. The client-side connection should continue using the maximum transmission unit (MTU) specified by the client.

Impact

This issue may cause network congestion or possible connection failures.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Clients receive ICMP Fragmentation Needed messages from the BIG-IP system.
  • Clients experience network congestion or connection failures to the virtual server.

Workaround

To work around this issue, you can disable the route.metrics.mtu setting to prevent the BIG-IP system from obtaining MTU information from route metrics. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will no longer use the cached metrics from router advertised maximum segment size (MSS) or Internet Control Message Protocol (ICMP) messages. However, disabling the route.metrics.mtu setting is less impactful than disabling the tm.enforcepathmtu or tm.pathmtudiscovery settings because the BIG-IP system will continue obeying advertised MSS and ICMP Fragmentation Needed messages per connection.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To disable the route.metrics.mtu setting, type the following command:

    modify sys db route.metrics.mtu value disable

  3. Save the change by typing the following command:

    save /sys config
