Description

Users may not able to perform a config sync operation on the BIG-IP system by navigating to Device management >> Overview and the system GUI may also hang without showing any data.

Environment

  • BIG-IP LTM
  • Device Management
  • Config sync
  • Configuration Management (CM)
  • GUI

Cause

Unknown at time of publication

Recommended Actions

 Follow the below troubleshooting steps to fix the issue.

Config Sync using CLI
Restart http and tomcat 
Rebuild HA
Verify if device hitting ID 621452

  • Perform force sync using the CLI K13887

Impact of procedure: The force-full-load-push command option forces the device to initiate a one-time ConfigSync operation to the device group. You may lose configuration on other devices after the ConfigSync operation. The command is not persistent and you must re-run it upon every attempt to initiate the ConfigSync process from a device with an older configuration.

  1. Log in to tmsh by typing the following command:
    tmsh
  2. To set the device as the synchronization leader of the device group and force the device to initiate the ConfigSync process, use the following command syntax:
    run cm config-sync force-full-load-push to-group <group name>
  3. For example, to force a full-load ConfigSync operation from the current device to the MyDeviceGroup device group, type the following command:
    run cm config-sync force-full-load-push to-group MyDeviceGroup
  • Restart httpd & tomcat daemons using the CLI K05645522

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Log in to the Traffic Management Shell (tmsh) by typing the following command:
    tmsh
  3. Restart the tomcat & Httpd process by typing the following command:
    restart /sys service httpd
    restart /sys service tomcat
  • Reset Device trust and rebuild the HA config, and try to perform config sync again K42161405
  • Refer to the known issue:  ID621452, to verify if the same conditions exist in your environment. 

After performing above mentioned steps the issue is still occurring, perform a reboot of the active device.
