Known Issue

This is the result of a known issue. Currently, the HTTP Profile filter includes TAB as part of the header value. As a result, POSTs with a Content-Length header value preceded by TAB do not forward the POST body.

The HTTP Profile should treat the leading TAB as WS (White Space) when determining the header value.

RFC2616 states HTTP header values may be preceded by spaces or TABs, which are not considered to be part of the header value.

F5 Product Development tracked this issue as CR69767 and CR69924 and it was fixed in BIG-IP LTM versions 9.1.3, 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM release notes.
