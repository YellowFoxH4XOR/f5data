Known Issue

BIG-IQ Logging Node (also known as ASM Logging Node) does not restore historical logs after you upgrade from BIG-IQ 4.4.0 to BIG-IQ 4.5.0.

Impact

The BIG-IQ logging node will no longer have the historical logs to send to the primary BIG-IQ system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you upgrade, the primary BIG-IQ system will have no historical logs from the BIG-IQ Logging Node to display.

Workaround

To work around this issue, you can back up and then restore the historical logs on the BIG-IQ Logging Node by creating and running two script files. To do so, perform the following procedures:

Obtaining the backup and restore scripts

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your local workstation.
  2. Create a new file named backup_analytics_index.sh, and copy and paste the following script syntax into the file:

    Note: F5 recommends that you use a program such as Microsoft Notepad that does not add formatting.

    #!/bin/bash

    ###############################################################################
    ###

    ###     No part of this software may be reproduced or transmitted in any
    ###     form or by any means, electronic or mechanical, for any purpose,
    ###     without express written permission of F5 Networks, Inc.
    ###
    ###############################################################################

    proc_user=$(id -u)
    if [ $proc_user -ne 0 ]; then
        echo "Please log in as a privileged user (root) to ensure no permission
    issues are encountered"
        exit 1
    fi

    function yes_no_prompt() {
        read -p "Do you wish to continue?  Y/N " -n 1 -r
        echo
        if [[ $REPLY != [Yy] ]]; then
            exit 0
        fi
    }

    function pause(){
       read -p "$*"
    }

    function stop_restjavad() {
        echo "Attempting to stop restjavad services"
        bigstart stop restjavad
        wait $!
    }

    function start_restjavad() {
        echo "Restarting restjavad services on the device"
        bigstart start restjavad
        wait $!
    }

    echo "This script will STOP RESTful services on your device to restore your analytics
    index. Execution time can vary based on the amount of data to be moved,
    so it is helpful to plan for down time or re-route any necessary traffic"

    yes_no_prompt

    if [[ -d '/var/config/rest/analytics' ]]; then
        analytics_dir_size=$(du -ks /var/config/rest/analytics | cut -f1)
        compression_estimate="$((($analytics_dir_size / 100) * 10))"
        echo -e "Analytics directory size is $analytics_dir_size KB before compression\n"
        echo -e "Post compression size will be approximately $compression_estimate KB\n"
        stop_restjavad
    else
        echo -e "The /var/config/rest/analytics directory does not seem to exist
    on this machine. No index found to back up\n"
        exit 1
    fi

    shared_available=$(df -Pk /shared | awk 'NR==2 {print $4}')
    if [[ "$compression_estimate" -ge "$shared_available" ]]; then
        diff=$(($compression_estimate - $shared_available))
        echo -e "The /shared partition does not have the required space to hold this backup.
    The space needed is approximately $diff KB.
    Please attempt to free some space in this directory to allow for a seamless backup.\n"
        start_restjavad
        exit 1
    fi

    analytics_dir=/var/config/rest/analytics
    output_dir="$(date +%Y-%m-%d)"_analytics_index_backup
    mkdir -p /shared/"$output_dir"
    output_file=/shared/"$output_dir"/analytics_index_backup.tar.gz
    echo -e "Compressing the index.  This can vary in execution time based on size\n"
    echo -e "Your compressed index will be in: $output_file\n"
    pause 'Press [ENTER] to continue'
    cd $analytics_dir
    tar -czf "$output_file" --exclude '*.lock' *

    if [[ ! -f "$output_file" ]]; then
        echo "The backup was unable to be compressed and moved to $output_file"
        start_restjavad
        exit 1
    fi

    start_restjava

  3. Save the file to disk.
  4. Create a new file named restore_analytics_index.sh, and copy and paste the following script syntax into the file:

    Note: F5 recommends that you use a program such as Microsoft Notepad that does not add formatting.

    #!/bin/bash

    ###############################################################################
    ###
    ###     Copyright (c) 2013-2014, F5 Networks, Inc. All rights reserved.
    ###     No part of this software may be reproduced or transmitted in any
    ###     form or by any means, electronic or mechanical, for any purpose,
    ###     without express written permission of F5 Networks, Inc.
    ###
    ###############################################################################

    proc_user=$(id -u)
    if [ $proc_user -ne 0 ]; then
        echo "Please log in as a privileged user (root) to ensure no permission issues are encountered"
        exit 1
    fi

    function yes_no_prompt() {
        read -p "Do you wish to continue?  Y/N " -n 1 -r
        echo
        if [[ $REPLY != [Yy] ]]; then
            exit 0
        fi
    }

    function pause(){
       read -p "$*"
    }

    function stop_restjavad() {
        echo "Attempting to stop restjavad services"
        bigstart stop restjavad
        wait $!
    }

    function start_restjavad() {
        echo "Restarting restjavad services on the device"
        bigstart start restjavad
        wait $!
    }

    echo "This script will STOP RESTful services on your device.
    Execution time can vary based on the amount of data to be moved,
    so it is helpful to plan for down time or re-route any necessary traffic"

    yes_no_prompt

    stop_restjavad

    backup_today=/shared/"$(date +%Y-%m-%d)"_analytics_index_backup
    backup_yesterday=/shared/"$(date -d "yesterday" +%Y-%m-%d)"_analytics_index_backup
    if [[ -d "$backup_today" ]]; then
        backup_dir="$backup_today/analytics_index_backup.tar.gz"
    elif [[ -d "$backup_yesterday" ]]; then
        backup_dir="$backup_yesterday/analytics_index_backup.tar.gz"
    else
        echo -e "No backup directory was found labeled with yesterday or today's date.
    To make sure your indexes are as current as possible, boot into the volume with your
    index(s) and run backup_analytics_index again.\n"
        exit 1
    fi

    var_available_space=$(df -k /var | grep "/var" | awk '{print $3}')
    unzipped_backup=$(gzip -l $backup_dir | grep ".tar" | awk '{print $2}')
    unzipped_backup_size=$(($unzipped_backup / 1000))

    if [[ -d "/var/config/rest/analytics" ]]; then
        echo -e "The analytics directory has been created already on this device. This means
    REST services were started and potential created indexes after the upgrade.
    If this is the case, the directories noted below will need to be manually deleted
    for the restoration of the backed up versions."
        cd /var/config/rest/analytics
        analytics_dirs=(*)
        analytics_guids=()
        backup_file=( $(tar -tzf "$backup_dir") )
        backup_guids=()
        analytics_count=0
        for task in "${analytics_dirs[@]}"; do
            analytics_guids[$analytics_count]=$(echo ${task##*/})
            analytics_count=$(($analytics_count + 1))
        done
        backup_count=0
        for dir in "${backup_file[@]}"; do
            backup_guids[$backup_count]=$(echo $dir | cut -d'/' -f1)
            backup_count=$(($backup_count + 1))
        done
        backup_unique_guids=($(echo "${backup_guids[@]}" | tr ' ' '\n' | sort -u | tr '\n' ' '))
        echo -e "GUID directories in /var/config/rest/analytics that are replicated in the backup
    and should be deleted to properly restore state:\n"
        for x in "${analytics_guids[@]}"; do
            for y in "${backup_unique_guids[@]}"; do
                if [[ $x == $y ]]; then
                    echo "$x"
                fi
            done
        done
        exit 1
    elif [[ "$unzipped_backup_size" -gt "$var_available_space" ]]; then
        echo "The /var partition only has $var_available_space, and the unzipped backup is
    $unzipped_backup_size.  Space will need to be freed up or a new volume mounted to this
    partition to accommodate restoring the backup"
        exit 1
    else
        mkdir /var/config/rest/analytics
        cd /var/config/rest/analytics
        tar -xvzf "$backup_dir"    
    fi

    start_restjavad

    echo -e "Your log index should be restored to the state it was in when backed up and
    REST services have been restored. Please validate that your logs are present and continue
    with your upgrade process

  5. Save the file to disk.

Backing up the historical logs

Impact of workaround: Performing the following procedure will disrupt access to the BIG-IQ user interface, as well as any BIG-IQ operations.

  1. Prior to upgrading, secure copy (SCP) the backup_analytics_index.sh script to the /shared/tmp directory on the BIG-IQ Logging Node.
  2. Log in to the command line of the BIG-IQ Logging Node.
  3. To set the proper permissions on the backup_analytics_index.sh script, type the following command:

    chmod +x /var/tmp/backup_analytics_index

  4. To run the backup_analytics_index.sh script, type the following command:

    /shared/tmp/backup_analytics_index.sh

  5. The backup_analytics_index.sh script prompts you with the following message:

    This script will STOP RESTful services on your device to restore your analytics
    index. Execution time can vary based on the amount of data to be moved,
    so it is helpful to plan for down time or re-route any necessary traffic
    Do you wish to continue?  Y/N Y

    To continue, type Y.
  6. Once completed, the backup_analytics_index.sh script shows the location of the backup:

    Your compressed index will be in: /shared/2015-03-04_analytics_index_backup/analytics_index_backup.tar.gz

    Press [ENTER] to continue
    Restarting restjavad services on the device

    To complete the process, click Enter.
  7. Upgrade the BIG-IQ Logging Node.

Restoring the historical logs

Impact of workaround: Performing the following procedure disrupts access to the BIG-IQ user interface, as well as any BIG-IQ operations.

  1. After the upgrade has completed, make sure that you have booted the BIG-IQ Logging Node to the partition that is running the new software.
  2. Secure copy (SCP) the restore_analytics_index.sh script to the /shared/tmp directory on the BIG-IQ Logging Node.
  3. Log in to the command line of the BIG-IQ Logging Node.
  4. To remove the contents of the analytics folder, type the following command:

    rm -rf /var/config/rest/analytics/ 

  5. To set the proper executable permissions on the restore_analytics_index.sh script, type the following command:

    chmod +x /var/tmp/restore_analytics_index.sh

  6. To run the restore_analytics_index.sh script, type the following command:

    /shared/tmp/restore_analytics_index.sh

  7. The restore_analytics_index.sh script prompts you with the following message:

    This script will STOP RESTful services on your device to restore your analytics
    index. Execution time can vary based on the amount of data to be moved,
    so it is helpful to plan for down time or re-route any necessary traffic
    Do you wish to continue?  Y/N Y

    To continue, type Y.
  8. The primary BIG-IQ system now gathers the necessary historical logging information from the BIG-IQ Logging Node.
