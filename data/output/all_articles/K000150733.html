Description

When you enable Bot Defense on F5 Distributed Cloud, it typically operates transparently—meaning it doesn’t explicitly tell the backend “this is a bot” or “this request is malicious.” However, it does inject or modify a few headers, primarily for observability and tracing.

Environment

 F5®Distributed Cloud (XC)

Answer/Recommended Actions

Here are headers F5 often appends when Bot Defense is enabled, before forwarding to the backend:

  • x-forwarded-for
  • x-forwarded-proto
  • x-envoy-external-address
  • x-request-id
  • x-envoy-expected-rq-timeout-ms

Additional Information

By default, F5 Distributed Cloud Bot Defense adds headers for observability, tracing, and client IP transparency, but not headers that say “this is a bot.” The backend would not know the request was flagged unless:

  • You explicitly configure it to send bot-related headers.

  • Or the backend reacts to side effects (e.g. missing tokens, header size changes, etc.).
