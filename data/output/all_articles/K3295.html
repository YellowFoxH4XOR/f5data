Topic

Following are the general guidelines to use when making a change to a redundant pair. For instructions about specific processes, refer to the TMOS Management Guide for BIG-IP Systems.

Backing up your configuration

Before you make changes to your redundant pair, you must first back up your current configuration.

For specific instructions, refer to the following articles:

  • For BIG-IP 10.x, refer to K11318: Backing up and restoring BIG-IP version 10.x configuration files.
  • For BIG-IP 9.x, refer to K3499: Backing up and restoring BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator configuration files.

Applying configuration changes

When you make configuration changes to the BIG-IP system, F5 recommends you apply the changes to the standby unit first. After you make the desired configurations changes to the standby unit, perform the following procedure to bring it into the active state and test the new configuration:

  1. Using the Configuration utility or the command line, verify that the configuration is correct and all the pool members and nodes are marked up.
  2. Fail over to the peer unit.
  3. Once the standby unit (with the new configuration) becomes active, verify that the site and applications are working properly.

    Note: If you observe issues after failing over to your standby unit, force a second failover to return traffic processing to the original active unit and restore functionality.

  4. When you have confirmed that everything is working properly, apply the changes to the peer system by synchronizing the configuration.

Installing an upgrade on a BIG-IP redundant pair

Important: F5 recommends that you have local access to your BIG-IP controllers when you install an upgrade. This will prevent loss of access to the BIG-IP in case of configuration errors.

When you are required to upgrade a BIG-IP redundant pair, F5 recommends you begin with the standby unit. After you have successfully installed the new software, perform the following steps on the standby node to bring it into the active state and test the new software:

  1. Using the Configuration utility or the command line, verify that the configuration is correct and all the pool members and nodes are marked up.
  2. Fail over to the peer unit.
  3. Once the standby unit (running the new software version) becomes active, verify that the site and applications are working properly.

    Note: If you observe issues after failing over to your standby unit, force a second failover to return traffic processing to the original active unit and restore functionality.

  4. When you have confirmed that everything is working properly, upgrade the other BIG-IP unit, which will now be standby.
