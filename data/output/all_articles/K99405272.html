K99405272: The BIG-IP ASM system may not forward WebSocket traffic

Type
Known Issue
Published
2017-06-01
Updated

Status

Source

The BIG-IP ASM system may not forward WebSocket traffic.

This issue occurs when subset of the following conditions are met:

  • The virtual server processing the traffic is configured with a WebSocket profile.
  • Multiple header values are present in the Connection header or the WebSocket server reply with a Connection:upgrade header.

Impact

The BIG-IP ASM system does not forward WebSocket traffic to pool members.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When processing WebSocket frames, the BIG-IP ASM system returns a frame containing the following error message:

    FAILED: not a response payload event: 'responseTimeout' expected: 'read'

  • The BIG-IP ASM system does not forward WebSocket traffic to pool members.

Workaround

To work around this issue, you can create an iRule that modifies the value of the Connection header. To do so, perform the following procedure:

Impact of workaround: The following example iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment. For more information about iRules commands, refer to the iRules wiki page on DevCentral. A DevCentral login is required to access this content.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Give your new iRule a name, and enter an iRule similar to the following example, in the Definition box:

    when HTTP_RESPONSE {
        if { [HTTP::status] == 101 } {
            HTTP::header replace "Connection" "Upgrade"
        }
    }

  5. Click Finished.
  6. Assign the iRule to the virtual server
