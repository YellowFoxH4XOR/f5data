K000137299: NGINX App Protect DoS blocks traffic with anomaly "Invalid HTTP Headers Presence or Order"

Type
Support Solution
Published
2023-10-19
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX App Protect DoS
Source
https://my.f5.com/manage/s/article/K000137299

Description

NGINX App Protect DoS blocks traffic with anomaly Invalid HTTP Headers Presence or Order.

Sample requests in logs show that the request uses HTTP/1.1 and header names are all lower case, similar to the following example:

GET /main/static/scripts.js HTTP/1.1
...
pragma: no-cache
cache-control: no-cache
sec-ch-ua: "Google Chrome";v="89", "Chromium";v="89", ";Not A Brand";v="99"
user-agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/89.0.4389.90 Safari/537.36
...

Environment

  • NGINX App Protect DoS
  • Bot defense
  • Blocked requests

Cause

A HTTP/2 profile is applied, or a HTTP/2 proxy in front of NGINX is converting the request to HTTP/1.1, retaining the lower case header names.

Recommended Actions

Configure caseSensitiveHttpHeaders to false:

"bot-defense": {
   "settings": {
    "isEnabled": true,
    "caseSensitiveHttpHeaders" : false
   }
  }

Additional Information

  • https://docs.nginx.com/nginx-app-protect-waf/declarative-policy/policy/

caseSensitiveHttpHeaders
booleanIf false the system will not check header name with case sensitivity for both relevant anomalies: Invalid HTTP Headers, Suspicious HTTP Headers.
