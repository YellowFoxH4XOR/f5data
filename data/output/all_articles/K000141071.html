Topic

You should consider using these procedures under the following condition:

  • You want to reclaim disk space used by a BIG-IP tenant.

Description

The BIG-IP tenant image is available in multiple sizes, for example T1, T2, T4 and ALL. When a classic BIG-IP tenant image is deployed, the system uses sparse mode to write the image to the file system. In sparse mode, the system allocates storage space only when the space is needed; virtual disk space is dynamically expanded as the needs of the BIG-IP tenant change.

In most cases sparse mode is advantageous as storage capacity is conserved. However, there is no utility available to reclaim disk space that may have been used at one point but is no longer used. For example, there may be instances where a tenant is running in production for a long period of time and ends up with extra space consumed on disk. This may be due to conditions such as, multiple in-place software upgrades, local logging, or old core file retention. In some cases this can result in low space on the host system, even after the extraneous files have been removed. To reclaim disk space used by a BIG-IP tenant, perform the below procedures.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have root and admin access to the F5OS system.
  • You have sufficient access rights (admin user access) to modify the BIG-IP tenant settings.

Procedures

  • Determine the disk space used by the existing tenant
  • Back up the existing BIG-IP configuration
  • Shutdown the BIG-IP tenant by setting its running-state to provisioned
  • Delete the existing tenant
  • Create a new BIG-IP tenant
  • Restore the BIG-IP configuration on the new tenant
  • Start the new BIG-IP tenant by setting its running-state to deployed

Determine the disk space used by the existing tenant

You can determine the disk space currently used by the BIG-IP tenant by logging into the F5OS command line and listing the contents of the /var/F5/system/cbip-disks/<tenant> directory. Use the following procedure to show the amount of space the tenant is using on the disk:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5OS CLI as the root user.
  2. Change to the /var/F5/system/cbip-disks directory by entering the following command:

    cd /var/F5/system/cbip-disks

  3. Determine the disk space used by the tenant by entering the following command syntax:

    ls -lsh <tenant-directory/>

    For example, the following command output indicates that the tenant named MyTenant-1 is using 74 GB out of 82 GB allocated to the tenant:

    ls -lsh MyTenant-1/
    total 74G
    74G -rw-r--r--. 1 107 107 82G Sep 16 09:06 MyTentant-1.raw

  4. Repeat the above steps for other tenants that may be consuming excessive disk space.

Back up the existing BIG-IP configuration

Before deleting the tenant you must back up the existing BIG-IP configuration so that you can later restore the configuration on the new tenant. For information about how to back up your BIG-IP configuration data using a UCS configuration archive, refer to the following article:

  • K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

Shutdown the BIG-IP tenant by setting its running-state to provisioned

To shutdown the BIG-IP tenant by setting the running-state to Provisioned, perform the following procedure:

Impact of procedure: The BIG-IP tenant will be shut down during and the system will not be available for traffic processing. F5 recommends you perform this procedure during a suitable maintenance window.

  1. Log in to the webUI of the F5OS system as admin user.
  2. Go to Tenant Management > Tenant Deployments.
  3. Select the box next to the tentant that is consuming excessive disk space.
  4. Select Provision.
  5. The tenant's running state changes to Provisioned.

Delete the existing BIG-IP tenant

To delete the existing BIG-IP tenant, perform the following procedure:

Impact of procedure: The BIG-IP tenant configuration will be deleted. F5 recommends you back up the existing BIG-IP configuration prior to performing this procedure.

  1. Log in to the webUI of the F5OS system as admin user.
  2. Go to Tenant Management > Tenant Deployments.
  3. Select the tenant that is consuming excessive disk space.
  4. Record any relevant tenant information, such as the IP address and resource settings and select Cancel.
  5. Select the box next to the tenant that is consuming excessive disk space.
  6. Select Delete.

Create a new BIG-IP tenant

The new tenant configuration should match the old tenant configuration that you just deleted (unless you want to make specific changes to the tenant configuration, such as changing the name or IP address). To create a new BIG-IP tenant, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the webUI of the F5OS system as admin user.
  2. Go to Tenant Management > Tenant Deployments.
  3. Select Add.
  4. Type a name for the tenant.
  5. For Type, select BIG-IP.
  6. Complete the remaining configuration settings for the BIG-IP tenant.
  7. Select Save and Close.

Restore the BIG-IP configuration on the new tenant

For information about how to restore your BIG-IP configuration data using a UCS configuration archive, refer to the following article:

  • K13132: Backing up and restoring BIG-IP configuration files with a UCS archive

Start the new BIG-IP tenant by setting its running-state to deployed

To shutdown the BIG-IP tenant by setting the running-state to Deployed, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the webUI of the F5OS system as admin user.
  2. Go to Tenant Management > Tenant Deployments.
  3. Select the box next to the new tentant.
  4. Select Deploy.
  5. The tenant's running state changes to Deployed.
