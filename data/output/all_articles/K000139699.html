K000139699: SWG wildcard HTTP virtual server does not capture all HTTP traffic

Applies to

Description

After deploying Secure Web Gateway you notice some HTTP traffic does not get captured by the HTTP wildcard virtual server and instead is routing out the default gateway on the F5.

  • There’s a setting in the HTTP explicit proxy profile, “Default Connect Handle”, which basically defines whether or not you need a TCP tunnel VIP for Connect traffic. With it set to “deny” (default), you do need the TCP tunnel VIP to handle Connect. With it set to “allow”, you don’t. In any case, the TCP tunnel only by default handles CONNECT requests, and does not handle GET requests.  Any unencrypted HTTP requests are handled directly by the proxy VIP and will forward directly to the system-defined gateway. For this reason, there’s an iRule we can use to force all HTTP traffic through the tunnel VIP:

Environment

  • Standard iapp SWG deployment 
  • HTTP wildcard virtual server to proxy and categorize HTTP traffic.

 

Cause

The wildcard HTTP wildcard virtual server will only capture CONNECT requests by default.  GET requests will be routed out the default gateway.

 

Recommended Actions

The actions or steps required to address the topic covered in the description.

 

Add this irule to the Proxy virtual server to force all HTTP traffic through the port 80 tunnel virtual server so it is not rejected and handled by policy:

when HTTP_REQUEST {

   virtual vs-name [HTTP::proxy addr] [HTTP::proxy port]

}
