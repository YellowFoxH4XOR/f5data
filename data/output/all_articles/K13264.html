Known Issue

BIG-IP GTM servers that host a large number of domains may report numerous error messages and take longer than expected to complete the zone transfers.

This issue occurs when all of the following conditions are met:

  • The BIG-IP GTM hosts more than ~100-200 domains

    Note: The exact number of domains that are needed to trigger this issue depends on the size of the individual zone files, network congestion, the load on the servers, etc.

  • Zone transfers for the domains are initiated at the same time. For example, the box is rebooted or the zones are added to the server in bulk.

Due to buffer constraints, the BIG-IP GTM system may overwrite existing zone transfer queries before receiving a response. As a result, when a response to an overwritten query is received, the BIG-IP GTM system must make the request again. The BIG-IP GTM system will continue to send requests until all queries have been answered, however the process may take longer than expected to complete, due to the retransmitted queries.

Impact

Zone transfer performance is degraded.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • An error message that appears similar to the following example may echo to console:

    Dec 6 15:09:28 gtm emerg logger: Re-starting zxfrd

  • An error message that appears similar to the following example may appear in the BIG-IP LTM log:

    Dec 6 15:09:28 gtm info zxfrd[11166]: 01531023:6: Per-invocation log rate exceeded; throttling

  • The DNS Express zone statistics may report an error that appears similar to the following example:

    General database error retrieving information

  • It takes much longer than expected for the zone transfers to complete.
