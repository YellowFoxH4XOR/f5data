Topic

As of version 4.2, BIG-IP uses OpenSSH to provide compatibility for both SSH1 and SSH2 protocols and clients. The SSH daemon uses tcpwrappers to determine if a connection is allowed or denied to the server and BIG-IP manages the addresses of these hosts through the /etc/hosts.allow and /etc/hosts.deny files.

You can use the hosts.deny file to explicitly prevent certain hosts or networks from accessing the BIG-IP through SSH; however, by default all addresses are denied access except those in the hosts.allow file.

Note: For more information about the BIG-IP hosts.allow and hosts.deny, including the syntax and expressions used in the files, refer to the hosts_access man pages.

To add an IP address for remote access by SSH clients, perform the following steps:

  1. Using a text editor, such as vi or pico, open the /etc/hosts.allow file.
  2. Find the sshd line at the end of the file and add the IP address of the host(s) or network(s) you would like to grant access to. You can use standard netmasks to designate a network range, or leave a trailing dot (.) at the end of a subnet octet to act as a wildcard character.

    For example, to allow the specific IP address, 172.20.1.74, you would add the following:

    sshd 172.20.1.74

    To allow access from any host on the 172.20 subnet, you would add the following:

    sshd 172.20.

    Or

    sshd 172.20.0.0/255.255.0.0

    You can also use a beginning dot (.) in combination with domain names to grant access from specific domains. This is helpful when you want to allow access from computers at a certain company, but don't know the network addresses.

    Note: For this to work correctly, the connecting host's hostname must be added to the domain's Reverse DNS zone and the BIG-IP must be configured to perform DNS lookups.

    For example, to allow any computer that can be resolved to the f5.com domain to connect, you would add the following line:

    sshd .f5.com
