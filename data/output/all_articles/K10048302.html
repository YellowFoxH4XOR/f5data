Description

Pop3 monitors to some pop3 servers may stop working after upgrading the system. After an upgrade to a version that this article applies to, the pop3 monitor will mark down pop3 servers that do not have GSSAPI authentication.

Symptom: When pool member monitor logging is enabled, you may see the following log message in your monitor log file.

For example:
# less /var/log/monitors/Common_my_pop3_monitor-Common_10.10.10.100-110.log
10:53:46.582993:(_Tcl /Common/my_pop3_monitor): No known authentication mechanisms supported!

Note: To turn on monitor logging, refer to the monitor logging section in K12531: Troubleshooting health monitors.

 

Environment

  • BIG-IP is upgraded to the Applies-To Versions
  • A built-in pop3 monitor is configured
  • The pop3 server being monitored does not have GSSAPI authentication

Cause

F5 changed pop3 monitors to support pop3 servers with GSSAPI authentication in versions listed in the Applies-To list of this article (see Bug ID 675367). However, this change caused pop3 monitors to fail for pop3 servers without GSSAPI authentication.
 

Recommended Actions

  • Option 1: Create a custom external monitor (EAV) bash script to monitor any of your affected pop3 servers (reconfiguration needed to change the affected pop3 monitors)
  • Option 2: Modify the default pop3 monitor in your system (does not survive an upgrade)
     

Option 1

Create a custom external monitor (EAV). This configuration will be saved in your standard .ucs configuration and will survive future system upgrades and RMA replacements. This option requires that you reconfigure all pools/pool members/nodes to use your custom EAV monitor, in place of any built-in pop3 monitors.

Configuration steps:

Review the steps outlined in K71282813: Overview of BIG-IP EAV external monitors.
Customize the existing script /config/monitors/sample_monitor to monitor a pop3 server.

Create a custom script

Create a custom script that contains the logic to determine the health of your back-end server and save it to your client desktop. Use the sample monitor script found on the BIG-IP system as a template.

  1. Go to System > File Management > External Monitor Program File List.
  2. Select sample_monitor.
  3. Copy out the script and paste it into a text editor.

    Comment out this line from the sample_monitor:
    echo "GET /" | /usr/bin/nc $node_ip $2 2> /dev/null | grep -E -i $3 > /dev/null

    And add this line to the script:
    ## uncomment the line below to log the command to the monitor debug logs
    # echo "curl -v pop3://$node_ip:$2/ -u $user:$cred" >> $MON_INST_LOG_NAME
    curl -v pop3://$node_ip:$2/ -u $user:$cred 2>> $MON_INST_LOG_NAME

    Your resulting script then should have these lines:
    #echo "GET /" | /usr/bin/nc $node_ip $2 2> /dev/null | grep -E -i $3 > /dev/null
    ## uncomment the line below to log the command to the monitor debug logs
    # echo "curl -v pop3://$node_ip:$2/ -u $user:$cred" >> $MON_INST_LOG_NAME
    curl -v pop3://$node_ip:$2/ -u $user:$cred 2>> $MON_INST_LOG_NAME

    The $user and $cred arguments are environment variables which will need to be configured when you create the BIG-IP monitor in the subsequent procedure.

  4. Save the edited script in your text editor into a file. Example: eav_custom_pop3_monitor_script

Import the script to the BIG-IP system

Import the script to the BIG-IP system through the Configuration utility or the command line. To import through the Configuration utility, perform the following procedure:

  1. Go to System > File Management > External Monitor Program File List.
  2. Select Import.
  3. Select Browse.
  4. Select the custom script you created.
  5. Enter a name for the script.
    Example:
    eav_custom_pop3_monitor_script
     
  6. Select Import.
  7. Some editors, such as Notepad on Windows, add trailing CR/LF new line characters to the script that causes the monitor to fail erroneously. For more information, refer to K14271: An imported external monitor may erroneously mark resources down. You can perform the following workaround to eliminate the extra CR characters:
    1. Select the name of the script, eav_custom_pop3_monitor_script, you just imported.
    2. Select Update.

The script is imported and saved at this location in the file system /config/filestore/files_d/Common_d/external_monitor_d. If you use a command line tool, such as scp, to import the script, ensure the system has at least 0700 and execute permissions to the script.

Create a BIG-IP external monitor referencing the script

  1. Go to Local Traffic > Monitors.
  2. Select Create.
  3. Enter a name.

    For example:

    my_custom_eav_pop3_monitor

  4. For Type, select External.
  5. For External Program, select the script you created in the previous procedure, eav_custom_pop3_monitor_script.
  6. In the Variable parameter, define the variable values used by the curl command that you added to the script in the previous procedure:

    curl -v pop3://$node_ip:$2/ -u $user:$cred 2>> $MON_INST_LOG_NAME

    To do so, supply the following Name and Value pairs to the Variable parameter:

    NameValue (Example)Description
    useruser1This is the username being passwd to the pop3 server to check its up/down status
    creduser1passwordEnter the pop3 user's password


Example:
 

Then, assign the monitor to the appropriate pool/member or node objects.


Option 2.

Modify the existing pop3 monitor.
This option does not survive an upgrade and must be repeated when upgrading to any new software slot.
However, this option does not require a reconfiguration of your existing monitors.

Steps:
Remount the /usr filesystem and backing up the pop3 script file
Customizing the Pop3 monitor to send a plain pop3 login
Remounting the /usr filesystem with read-only permissions

Remounting the /usr filesystem and backing up the pop3 script file
Before modifying the pop3_monitor file, you must remount the /usr filesystem with read/write permissions and back up the pop3_monitor file. To do so, perform the following procedure:
Impact of procedure: The following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Remount the /usr filesystem with read/write permissions by entering the following command:

    mount -o remount,rw /usr
     
  3. Make a copy of the /usr/share/monitors/pop3_monitor file by entering the following command:

    cp -p /usr/share/monitors/pop3_monitor /usr/share/monitors/pop3_monitor.original.K10048302
     
  4. Perform any of the following procedures, as necessary.

Customizing the Pop3 monitor to send a plain pop3 login
You can customize the pop3 monitor to send a plain pop3 login. To do so, perform the following procedure:
Important: All existing configured pop3 monitors may fail to properly monitor pop3 servers if the script file is incorrectly modified.

  1. If you have not done so, log in to the command line.
  2. Make sure that you have performed the 
      remount and backup procedure, described previously.
    • Edit the /usr/share/monitors/pop3_monitor file using a text editor of your choice.
    • Locate the following line:

      set loginoptions "-loginoptions \"AUTH=PLAIN;AUTH=LOGIN;AUTH=NTLM\""
      # set loginoptions ""

      Uncomment the second line and uncomment the first line as follows:

      # set loginoptions "-loginoptions \"AUTH=PLAIN;AUTH=LOGIN;AUTH=NTLM\""
      set loginoptions ""
       
    • Save the changes and exit the text editor when you are done.

    Remounting the /usr filesystem with read-only permissions
    After you have modified the /usr/share/monitors/pop3_monitor file, you must remount the /usr file system with read-only permissions. To do so, perform the following procedure:
    Impact of procedure: The following procedure should not have a negative impact on your system.

    1. If you have not done so, log in to the command line.
    2. Remount the /usr filesystem with read-only permissions by entering the following command:

      mount -o remount,ro /usr

    Note: This procedure (Option 2) does not survive an upgrade. When using this option, this procedure must be repeated for any new installations or after any software upgrade.
