K000134488: F5 Big-IP reverts DNS IP to old servers

Type
Support Solution
Published
2023-05-18
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP APM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000134488

Description

After updating the DNS and NTP IPs on the Big-IP, these IPs randomly change back to their original values. 

Environment

  • APM traffic objects configured with these IPs
  • Big-IP VE hosted by Amazon Web Services (AWS)
  • AWS Virtual Private Cloud (VPC) use DHCP servers
  • Migrating from Active Directory (AD) 2012 Server to AD 2022 server
  • Big-IP management objects are configured using DHCP

Cause

  • Some traffic objects, such as, APM Network Access profiles, explicitly used the original DNS and NTP IPs.
  • The DNS and NTP settings on the Big-IP include description "configured-by-dhcp". This indicates that these values are managed by a DHCP server. 
tmsh list sys dns

sys dns {
    description configured-by-dhcp
    name-servers { x.x.x.x  x.x.x.x }
    search { example.com localhost }
}

Recommended Actions

  1. Search the shared configuration for objects that use these DNS and NTP IPs.
From the command line: grep -i <ip> /config/bigip.conf -A 5 -B 5
The switches include the 5 lines after and 5 lines before the match. Adjust this value as necessary.
  1. Find these objects within the WebUI and update them to the new IPs.
  2. Find the DHCP server.
    • Either use tcpdumps that listen on the management (eth0) or all traffic (0.0) interfaces to determine the source of the DHCP updates or contact the AWS administrator. 
Listening on the management tier: tcpdump -vni eth0 port 67 or port 68 -s0 -w /var/tmp/dhcp-traffic-eth0.pcap
Listening on all traffic interfaces: tcpdump -vni 0.0:nnn port 67 or port 68 -s0 -w /var/tmp/dhcp-traffic-00.pcap

Note: The Big-IP broadcasts a DHCP Request via its gateway which is configured in its management route. This is an internal IP that is used as the gateway for the Big-IP, but this IP doesn't exist in the AWS VPC network. The Big-IP itself doesn't include any specific reference to a DHCP server, it just has DHCP enabled.

  1. Update the DNS and NTP IPs on the DHCP server.
  2. Assign this DHCP server to the VPC that hosts the Big-IPs.

Additional Information

Check the current DHCP settings on the Big-IP.

tmsh list management-dhcp
tmsh show running-config sys management-dhcp

Restart the DHCP process to test whether the IPs remain or change on the Big-IP.

bigstart restart dhclient
