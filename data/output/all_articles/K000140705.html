K000140705: Portal Access - application slowness issue

Type
Support Solution
Published
2025-07-03
Updated
2025-07-03
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000140705

Description

Portal Access suddenly just showed latency.

All other APM access policy (without Portal Access) works fine.

LTM side works fine as well.

No changes was done on the APM.

 

Environment

BIG-IP APM

 

Cause

"sys db log.webapplications.level" is set to Debug

The rewrite.*.log files which are destination for Portal Access Resources are truncated/big in qkview file.

This means the rewrite related logs are not set to default level.

 

Recommended Actions

Set "sys db log.webapplications.level" to Notice (Default level)

# tmsh modify sys db log.webapplications.level value notice

 

Additional Information

What does "sys db log.webapplications.level" is used for and why is it affecting the portal access resource?

This is for Portal Access debugging. In General, any debugging enabled may impact performance, so this is usually enabled only during troubleshooting.

There is also general guideline in terms of enable of debugging and impact to performance:

Overview of diagnostic logging and BIG-IP system resource utilization (f5.com)

It's clearly stated that debug log level should be set only during troubleshooting sessions. This rule is applicable to any APM log level destinations (not only related to portal-access resources).
