K04230239: Updating iRules on a Virtual Server with a Traffic Matching Criteria removes the Virtual Address

Type
Support Solution
Published
2021-01-27
Updated
2023-02-21
Source
https://my.f5.com/manage/s/article/K04230239

Description

ConfigSync fails with an error about a Virtual Address that cannot be deleted, after adding or removing an iRule associated with a Virtual Server (VS) that has a Port List or Address List.

  • ERROR: Sync error on host.device.B.local: Load failed from /Common/host.device.A.local 01070344:3: Cannot delete referenced virtual address /Common/10.0.0.1

Environment

  • VS with TMC
  • iRule list on VS is modified
  • Virtual Address has the default setting of true, or checked, for the Auto Delete option
  • Virtual Address is not referenced by any other VS

Cause

If the VS has Traffic Matching Criteria (TMC) instead of a Destination IP Address because a Port List or Address List is in use, and any iRule is either added or removed from it, then the Virtual Address associated with that VS will be removed, unless it is referenced by another VS, or unless it has the default setting of true, or checked, for the Auto Delete option.

Recommended Actions

Once the Virtual Address is added back to the device with the configuration you want to sync to its peer, you can uncheck the Auto Delete box so that it is not removed if you update an iRule, and then you can perform the ConfigSync without error.
