Known Issue

This is the result of a known issue. User-defined iRule events are processed before internal BIG-IP ASM iRule events. Currently, all BIG-IP ASM internal iRule events are set to priority 1000. As a result, the BIG-IP ASM user-defined iRule events do not work correctly.

For example, you can use the HTTP_RESPONSE iRule event to reselect a pool member after the web server outputs an HTTP 404 Not Found response. An iRule containing the HTTP_RESPONSE event should be processed after the internal BIG-IP ASM iRule. However, due to the priority setting of the BIG-IP ASM internal iRule, the BIG-IP ASM user-defined iRule event does not work correctly.

F5 Product Development tracked this issue as CR70380, CR70691, and CR70699 and it was fixed in BIG-IP versions 9.2.4, 9.3.0, and 9.4.0. For information about upgrading, refer to the BIG-IP ASM or LTM release notes.
