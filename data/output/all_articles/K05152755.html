Known Issue

A packet filter configured to filter a specific protocol or port number will not capture IPv6 fragments.

This issue occurs when all of the following conditions are met:

  • IPv6 protocol is being used.
  • Your BIG-IP system has packet filtering enabled.
  • The packet filter is based on a specific port number or protocol (for example, UDP or TCP).
  • Your BIG-IP system processes fragmented IPv6 packets.
  • Filter default action is discarded.

Impact

The BIG-IP system cannot process fragmented IPv6 traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system is not forwarding fragmented IPv6 packets to clients.

Workaround

To work around this issue, you can filter using a rule that is based on raw fragment offsets instead of a specific destination port. To do so, refer to the following example:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

To provide an example of this known issue, you would typically use the following filter rule to match port 50000:

dst port 50000

To work around the issue, you would use the following filter instead:

((udp dst port 50000) or (ip6[6]=44 and ip6[40]=17 and ip6[50]=50000))
