K000161777: After upgrading BIG-IP is in Offline state

Type
Support Solution
Published
2026-06-21
Updated
2026-06-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 21.X.X, 21.1.X, 21.1.0, 21.0.X, 21.0.0, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000161777

Description

  • BIG-IP is in Offline state after upgrade.
  • You observe below services are down in the BIG-IP but mcpd and tmm are up.

    asm          down, waiting for mysql to release running semaphore
    botd         down, waiting for asm to release ready semaphore
    fslogd        down, waiting for logmysqld to begin
    localdbmgr      down, waiting for mysql to release running semaphore
    logmysqld       down, waiting for mysql to release running semaphore
    mdmsyncmgr      down, waiting for mysql to release running semaphore
    monpd         down, waiting for mysql to release running semaphore
    mysql         down, Not enough disk space.
    oauth         down, waiting for mysql to release running semaphore

Environment

  • BIG-IP provisioned modules - APM, ASM, AVR and LTM

Cause

/ directory 100% utilization

Answer/Recommended Actions

  1. Check if there are unwanted files in / directory.
    # find / -xdev -type f -exec du -h {} \; | sort -rh | head -20
    # find /  -xdev -type f -exec du -h {} \; | sort -rh | grep -Ev $(mount | awk '/\/var\// {print $3}' | sed -e :a -e N -e 's/\n/|/' -e ta) | head -20

  2. If files / seems important, then increase disk space for / directory. First check if you have free space in BIG-IP to increase disk space for a directory. You can use pvs command to check for free space (PFree). 
    Important: Check the Filesystem of / directory. Enter "df -h" to see filesystem path. If you enter incorrect filesystem name to increase size of directory, BIG-IP will not boot up properly.

    For example:

    # df -h
    Filesystem                             Size  Used Avail Use% Mounted on
    /dev/mapper/vg--db--vda-set.1.root             419M  417M    0M   20% /
    devtmpfs                               3.9G  4.0K  3.9G   1% /dev
    tmpfs                                  3.9G  2.3M  3.9G   1% /dev/shm
    tmpfs                                  3.9G  2.3M  3.9G   1% /run
    ---small snippet of the output---

    Below command is to increase the size of / directory by 50MB.
    # lvextend -L +50M /dev/mapper/vg--db--vda-set.1.root
    # resize2fs /dev/mapper/vg--db--vda-set.1.root
