Known Issue

The configuration may fail to load on secondary blades when you reboot the chassis.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION chassis with two or more blades installed.
  • You have configured a user account (other than admin or root) with administrator privileges.
  • You reboot a single blade, all of the blades, or the entire chassis.

Impact

The configuration fails to load on secondary blades that are offline.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H546958 on the Diagnostics > Identified > High screen.
  • Following a chassis reboot, the configuration fails to load on secondary blades.
  • The secondary blade will log error messages in the /var/log/ltm file that appear similar to the following example:

    err mcpd[8115]: 01070821:3: User Restriction Error: User (Unknown) may not change the role of Administrator (t004576a).
    err mcpd[8115]: 01070935:3: Unexpected exception caught in MCPProcessor::rm_DBLowHighWide().
    err mcpd[8115]: 01070734:3: Configuration error: MCPProcessor::check_initialization:.
  • The tmsh show sys cluster command will show the secondary blade as offline.

Workaround

To recover from this issue, you must force the mcpd process on the affected secondary blade to reload the configuration. To do so, perform the following procedure:

Impact of workaround: Rebooting the BIG-IP system disrupts traffic processing until the system is back up. However, because the secondary blade is already offline, performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected secondary blade.
  2. Create a null file with the filename forceload in the /service/mcpd directory by typing the following command:

    touch /service/mcpd/forceload
  3. Reboot the affected secondary blade by typing the following command:

    reboot
