Known Issue

Enabling FIPS for a DNSSEC zone causes TMM to produce a core file.

This issue occurs when the following condition is met:

  • The BIG-IP platform supports the Federal Information Processing Standard (FIPS).

Impact

The BIG-IP system is unable to process traffic while the TMM process restarts, and the system fails over if it is configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H546713 on the Diagnostics > Identified > High screen.
  • The TMM process restarts, and the BIG-IP system temporarily fails to process traffic.
  • The system logs the stack trace to the /var/log/tmm file.
  • In the /var/log/ltm file, the BIG-IP system logs error messages that appear similar to the following example:

    010713e4:3: FIPS subsystem reported error while attempting file object operation: Identical key already exists in FIPS card with handle (9). Cannot import duplicate key (/Common/<key_name>.key).
    01070712:3: Caught configuration exception (0), Error importing FIPS140 key (/Common/<key_name>.key) to hardware..
