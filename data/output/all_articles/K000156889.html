K000156889: controller-manger pods still down, API Server Certificate errors even after using Bug ID 1962261 workaround

Type
Support Solution
Published
2025-10-06
Updated
2025-10-06
Applies to
  • F5OS
  • F5OS-C: 1.8.0
Source
https://my.f5.com/manage/s/article/K000156889

Description


The API server certificates may expire and then controller-manager pods may enter CrashLoopBackOff after a controller restart. This is Bug ID 1962261: The controller-manager pods can enter CrashLoopBackOff due to expired API server certificate.


However, the workaround may fail to restore the controller-manager pods


Environment


F5OS-C 1.8.0


Cause

The metrics-server pod is not in the running state.


This can be observed by running this command as the root user


# kubectl get pods --all-namespaces -o wide | grep -v 'Running\|Completed'

NAMESPACE              NAME                      READY   STATUS  RESTARTS  AGE    IP       NODE             NOMINATED NODE

kube-service-catalog pod/controller-manager-<UUID> 0/1 CrashLoopBackOff 7 37m 100.77.0.149 controller-1.chassis.local <none>

kube-service-catalog pod/controller-manager-<UUID> 0/1 CrashLoopBackOff 5 37m 100.76.0.121 controller-2.chassis.local <none>

kube-system pod/metrics-server-<UUID> 0/1 ContainerCreating 0 4d <none> controller-2.chassis.local <none>


Recommended Actions

Log in as root user and restart the metrics-server pod. This should not have a negative impact and the pod will get recreated shortly after


# oc delete -n kube-system pod/<pod-name>


Example:


# oc delete -n kube-system pod/metrics-server-55d7cbdbc-f985p
