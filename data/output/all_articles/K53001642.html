K53001642: Updating the BIG-IQ iApp to prevent BIG-IP performance issues on managed BIG-IP systems and improve DNS statistics collection

Type
Knowledge
Published
2020-05-21
Updated
2023-02-21
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0, 7.1.0
Source
https://my.f5.com/manage/s/article/K53001642

Topic

You should consider using these procedures under the following conditions:

  • You use BIG-IQ to manage BIG-IP LTM or BIG-IP DNS configurations.
  • The managed BIG-IP system has large number of configured virtual servers.
  • You use BIG-IQ data collection devices (DCDs) for statistic collection.

Description

When BIG-IQ manages a BIG-IP LTM system and collects analytics information using BIG-IQ Data Collection Device (DCD), it periodically gathers statistics and status information of the configuration objects, including virtual servers, nodes, and pool members. This is accomplished using an iApp installed on each BIG-IP system that has statistic collection enabled. The data collection behavior may cause CPU utilization spikes every two minutes when the managed BIG-IP system has a large number of configured virtual servers. The BIG-IP system may also log error messages in the /var/log/ltm file while the iApp executes. The error output appears similar to the following example:

To improve the statistic collection performance and reduce the CPU spikes on the managed BIG-IP systems, ensure that the latest BIG-IQ Analytics iApp is installed on the BIG-IQ system. This article describes the procedures to download the necessary files and update your BIG-IQ iApp to the latest version.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the BIG-IQ system.

Procedures

Note: These procedures apply to BIG-IQ 7.1.0 and 8.0.0. If your BIG-IQ version has ID908505, ID872237, and ID996601 bug fix included in the engineering hotfix, the improved iApp is already installed on the BIG-IQ system. You can further improve the statistics collection performance, as suggested in step 11 of the Download the latest BIG-IQ Analytics iApp file procedure.

  • Download the latest BIG-IQ Analytics iApp file
  • Update BIG-IQ iApp to the latest supported version

Download the latest BIG-IQ Analytics iApp file

You can find and download the latest BIG-IQ iApp file on the F5 Downloads site. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to the F5 Downloads site.
  2. Select Find a Download.
  3. Select Centralized Management.
  4. Choose the version you are currently running from the list.
  5. Select iApp-Templates.
  6. Download all of the following files to your workstation. You need to accept the EULA and choose a location from which to download.
    • analytics-iapp-<version>.noarch.zip
    • analytics-iapp-<version>.noarch.zip.md5
    • analytics-iapp2-<version>.noarch.zip (Introduced in BIG-IQ 8.0)
    • analytics-iapp2-<version>.noarch.zip.md5 (Introduced in BIG-IQ 8.0)

Note: Before unzipping and extracting the rpm package from the downloaded zip file, you can verify the MD5 checksum by transferring the MD5 file to the BIG-IQ system and using the following syntax to perform the verification: md5sum --check analytics-iapp-<version>.noarch.zip.md5.

Update BIG-IQ iApp to the latest supported version

To prevent the CPU spikes introduced by the statistic collection behavior, you can update the BIG-IQ iApp to the latest supported version. To do so, perform the following procedure:

Impact of procedure: The procedure involves stopping and starting restjavad, which interrupts BIG-IQ system functionality. The restjavad service on the BIG-IP system is interrupted during the restart. F5 recommends performing this procedure during a maintenance window.

Note: If the BIG-IQ system is part of high availability (HA) configuration, you must perform the iApp updating procedure on both active and standby BIG-IQ devices.

Note: Before updating the BIG-IQ analytics iApp, F5 recommends that you verify and ensure all managed BIG-IP systems in the device groups are in sync.

  1. Log in to the BIG-IQ Centralized Management (CM) command line.
  2. To remount the /usr file system in read-write mode, enter the following command:

    mount -o remount,rw /usr

  3. Upload the new analytics iApp rpm file to the /usr/lib/dco/packages/upd-adc/bigip/ directory of the BIG-IQ system using a file transfer client, such as WinSCP.
  4. To change the current directory to the rpm file location, enter the following command:

    cd /usr/lib/dco/packages/upd-adc/bigip/

  5. To back up the existing older analytics iApp, use the following command syntax:

    mv <old_iApp_rpm> <old_iApp_rpm>.BU

    For example, to back up the analytics-iapp-7.1.0-0.0.1480.noarch.rpm file, enter the following command:

    mv analytics-iapp-7.1.0-0.0.1480.noarch.rpm analytics-iapp-7.1.0-0.0.1480.noarch.rpm.BU

    For BIG-IQ 8.0, you should back up both iApp and iApp2 rpm files. For example:

    mv analytics-iapp-8.0.0-0.0.1480.noarch.rpm analytics-iapp-8.0.0-0.0.1480.noarch.rpm.BU
    mv analytics-iapp2-8.0.0-0.0.1480.noarch.rpm analytics-iapp2-8.0.0-0.0.1480.noarch.rpm.BU

  6. To stop restjavad, enter the following command:

    tmsh stop /sys service restjavad

  7. To install the new iApp rpm file, enter the appropriate following command, depending on your BIG-IQ and BIG-IP version combination:

    • For BIG-IQ 7.0, enter rpm -i analytics*7*rpm.
    • For BIG-IQ 8.0.0 with BIG-IP 15.1.x or earlier, enter rpm -i analytics-iapp-*rpm.
    • For BIG-IQ 8.0.0 with BIG-IP 16.0.0, enter rpm -i analytics-iapp2-*rpm.

    Note: BIG-IQ 8.0 contains two analytics iApp RPMs (analytics-iapp and analytics-iapp2). You should run RPM commands against both iApp and iApp2 RPM files if the BIG-IQ 8.0 managed devices include both BIG-IP 16.0.0 and earlier versions.

    Note: You can revert the BIG-IQ iApp version with an older rpm build. To do so, enter the following command as appropriate:

    • For BIG-IQ 7.1.0, enter rpm -Uvh --oldpackage analytics*7*rpm.
    • For BIG-IQ 8.0.0, enter rpm -Uvh --oldpackage analytics*8*rpm.
  8. To start restjavad, enter the following command:

    tmsh start /sys service restjavad

    After the restjavad service is up and running, the BIG-IQ system starts to deploy the new iApp to managed BIG-IP devices and logs processes to the /var/log/restjavad.0.log file. The log messages appear similar to the following example:

    [/cm/shared/stats-mgmt/device-monitor-task/84f3483b-2387-427a-9f4d-1e9d9cb89984/worker DeviceMonitorTaskWorker] iApp version on device 10.10.0.84 (7.1.0) not equal to version on BIG-IQ (7.1.0.0.2), reinstalling
    [/cm/shared/stats-mgmt/agent-install-and-config-task/84dae3c3-e486-4548-b394-e5a59745c484/worker AgentInstallAndConfigTaskWorker] complete installation and configuration workflow for task 84dae3c3-e486-4548-b394-e5a59745c484 on device 10.10.0.84, version 14.1.0.3 build 0.0.6

  9. To remount the /usr file system in read-only mode, enter the following command:

    mount -o remount,ro /usr

  10. If the BIG-IQ device is affected by ID 996601, entering the following command to restart appiqagent:

    bigstart restart appiqagent

  11. Optionally, you can further improve the statistics collection performance by setting the useAppIqDcd parameter to true. To do so, enter the following command:

    restcurl -X PUT /cm/adc-core/current-config/stats-refresh -d '{"isMonitorRunning": true, "useAppIqDcd": true}'

    Note: To further reduce the CPU utilization impact, F5 recommends that you use DCD for BIG-IP data collection tasks by setting the useAppIqDcd parameter to true. For more information, refer to K91114310: Reducing the performance impact of BIG-IQ statistics gathering on managed BIG-IP systems.
