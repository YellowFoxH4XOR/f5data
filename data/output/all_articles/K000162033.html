K000162033: Generic Host Servers Health Monitor and DNS Response Behaviour when using Address Translation

Type
Support Solution
Published
2026-07-02
Updated
2026-07-02
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 21.X.X, 21.1.X, 21.1.0, 21.0.X, 21.0.0, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000162033

Description

  • DNS queries to a generic host server configured with a translation address might return the Internal IP address instead of the expected External IP address. 
  • Health monitors may probe the wrong address, resulting in health check failures.

Environment

    • GTM/DNS server object
    • Generic Host
    • translation-address configured
    • Health monitor
    • Prober pool (optional)

Cause

Most likely a misconfiguration. When using Address Translation, specific configuration requirements must be met for proper functionality.

Answer/Recommended Actions

  1. Configure the address field with the external IP (returned to DNS queries and used by upstream NAT devices).
  2. Configure the translation-address field with the internal/real IP (actual server or pool member IP).
  3. Ensure address and translation-address fields are different; do not use 1:1 mapping.
  4. If multiple addresses are configured for a server object, each must have a corresponding translation address.
  5. Assign health monitors at the correct level:
    • TCP-based monitors: virtual server level (port defined)
    • ICMP-based monitors: server level

Example configuration:

}
gtm server /Common/GTMServerObject {
    datacenter /Common/DC1
    devices {
        GTM_local {
            addresses {
                10.1.2.3 {
                    translation 172.16.2.3
                }
                10.3.2.1 {
                    translation 172.16.2.1
                }
            }
        }
    }
    monitor /Common/bigip
    product bigip
    virtual-server-discovery enabled
    virtual-servers {
        /Common/listener {
            destination 10.3.3.3:53
        }
    }
}
gtm server /Common/GenericHost {
    datacenter /Common/DC1
    devices {
        genhost {
            addresses {
                172.16.33.34 {
                    translation 192.168.33.34
                }
            }
        }
    }
    monitor /Common/custom_icmp_based
    product generic-host
    virtual-servers {
        sample_server {
            destination 172.16.33.34:80
            monitor /Common/custom_tcp_based
            translation-address 192.168.33.34
            translation-port 80
        }
    }
}

Additional Information

    • Translation on the generic host server level is only required if monitoring the server object.
    • The real IP (self-IP) should be placed in the translation field; the address field should reflect the external IP.
    • It is recommended to use prober pools when working with generic hosts to limit probers only to those within the same DC or BIG-IPs that are able to reach the monitored objects.
    • Flapping or inconsistent health status occurs if not all addresses have translation or if multiple addresses are used without proper mapping.
    • If the probing address (GTM server object type bigip) is not configured with a translation address, it will probe the destination address instead of the translation-address
