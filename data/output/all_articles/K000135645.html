Description

The BIG-IP may be configured with multiple IP addresses, for example, a management IP and multiple self-IP. When you configure the BIG-IP to log to a remote syslog server, the the local IP used by BIG-IP may not be one that you desire. This article describes how to configure the BIG-IP to bind to a local IP address in a HA environment.

For an overview on how to configure remote logging on the BIG-IP, refer to K13080: Configuring the BIG-IP system to log to a remote syslog server (11.x - 17.x).

Example scenario

Remote syslog server: 10.0.5.55/24

BIG-IP 1: 

  • Management IP: 10.200.50.1/24
  • Self-IP 1: 10.0.0.1/24
  • Self-IP 2: 10.0.1.1/24
  • Self-IP 3: 10.0.2.1/24 (desired local IP for syslog)
  • Self-IP (Floating): 10.0.0.3/24

BIG-IP 2:

  • Management IP: 10.200.50.2/24
  • Self-IP 1: 10.0.0.2/24
  • Self-IP 2: 10.0.1.2/24
  • Self-IP 3: 10.0.2.2/24 (desired local IP for syslog)
  • Self-IP (Floating): 10.0.0.3/24

In the example above, you would like to use 10.0.2.1 and 10.0.2.2 as the local IP on BIG-IP 1 and 2 respectively.

Environment

  • BIG-IP in HA environment (2 or more BIG-IP devices in a device group)
  • Logging to remote syslog server
  • You would like the BIG-IP devices to bind to a specific IP address (as source IP address)

Cause

None

Recommended Actions

In the example above, the objective is to use 10.0.2.1 as local IP on BIG-IP 1, and 10.0.2.2 on BIG-IP 2.

You can achieve this with any of the following methods:

  • Specifying local IP in the remote syslog server setting (GUI)
  • Specifying local IP in the remote syslog server setting (SSH/tmsh)
  • Specifying "include" setting (SSH/tmsh)

Specifying local IP in the remote syslog server setting (GUI)

  1. Login to BIG-IP 1's Configuration Utility (GUI)
  2. Navigate to System > Logs > Configuration > Remote Logging
  3. Enter Remote IP (10.0.5.55), Remote Port (514), and Local IP (10.0.2.1)
  4. Click "Add"
  5. Click "Update"
  6. Navigate to Device Management > Overview
  7. Push the configuration of BIG-IP 1 to the device group
    Note: The remote logging settings is sync'ed to BIG-IP 2. However, on BIG-IP 2, only Remote IP (10.0.5.55) and Remote Port (514) are populated, Local IP is not. Local IP is a local setting for each device and is not sync'ed between devices.
  8. Login to BIG-IP 2's Configuration Utility (GUI)
  9. Navigate to System > Logs > Configuration > Remote Logging
  10. Select the remote syslog server and click "Edit"
  11. Enter Local IP (10.0.2.2) and click "Add"
  12. Click "Update"
    Note: Both devices should still show "In Sync" status. This is because the Local IP setting changed on BIG-IP 2 is local and does not need to be sync'ed to the group.

Specifying local IP in the remote syslog server setting (SSH/tmsh)

  1. login to BIG-IP 1 via SSH
  2. launch tmsh
    # tmsh
  3. add the remote syslog server
    (tmos)# modify /sys syslog remote-servers add { remotesyslog1 { host 10.0.5.55 remote-port 514 local-ip 10.0.2.1 } }
    (tmos)# save /sys config
  4. sync the changes to the device group
    (tmos)# run /cm config-sync to-group <device-group-name>
    Note: The remote logging settings is sync'ed to BIG-IP 2. However, on BIG-IP 2, only Remote IP (10.0.5.55) and Remote Port (514) are populated, Local IP is not. Local IP is a local setting for each device and is not sync'ed between devices.
  5. login to BIG-IP 2 via SSH
  6. launch tmsh
    # tmsh
  7. specify local IP
    (tmos)# modify /sys syslog remote-servers modify { remotesyslog1 { local-ip 10.0.2.2 } }
    (tmos)# save /sys config
    Note: Both devices should still show "In Sync" status. This is because the Local IP setting changed on BIG-IP 2 is local and does not need to be sync'ed to the group.

Specifying "include" setting (SSH/tmsh)

You can also use the "include" setting to specify custom configuration for syslog. The "include" setting is sync'ed between devices, hence it needs to be formatted in a certain way.

Note: Modifications to the syslog configuration properties that are made by using this procedure may not be reflected in the Configuration utility.

Destination syslog servers, log levels and other settings will be specified within the "include" setting. When using the "include" setting, all other settings should be reverted to the default value.

  1. login to BIG-IP 1 via SSH
  2. launch tmsh
    # tmsh
  3. specify the "include" setting
    (tmos)# edit /sys syslog all-properties
    Note: You may type ":set paste" so that vi does not auto-indent when you paste the following config
  4. remove all existing syslog config, paste the following and customize it to fit your environment
    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
        destination d_remote_loghost {
            udp(\"10.0.0.21\" port(514) localip(\"10.0.0.76\") persist-name(r1));
            udp(\"10.0.0.21\" port(514) localip(\"10.0.0.77\") persist-name(r2));
        };
        log {
            source(s_syslog_pipe);
            destination(d_remote_loghost);
        };
        "
        iso-date disabled
        kern-from debug
        kern-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }
    Note: There should be an "udp" line per-syslog server per-device. The "localip" option in each "udp" line requires a valid IP. The first "udp" line (with BIG-IP 1's self IP) will take effect on BIG-IP 1, but ignored on BIG-IP 2. Conversely, the second "udp" line (with BIG-IP 2's self IP) will take effect on BIG-IP 2, but ignored on BIG-IP 1. The net result is that, both BIG-IP 1 and 2 will be able to send logs to the destination syslog server.
    Note: The "persist-name" option is a unique name for each "udp" line. "persist-name" is not strictly required, but recommended in order to avoid     Bug ID 740589: Mcpd crash with core after 'tmsh edit /sys syslog all-properties' on affected versions.
  5. exit the vi editor
    :wq!
  6. at the following prompt, enter y to save the changes
    Save changes? (y/n/e)
  7. save the configuration
    (tmos)# save /sys config
  8. sync the changes to the device group
    (tmos)# run /cm config-sync to-group <device-group-name>
