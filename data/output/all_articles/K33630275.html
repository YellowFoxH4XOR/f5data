Known Issue

The BIG-IP system may erroneously remove an iApp association from the virtual server when performing a configuration merge.

This issue occurs when all of the conditions are met for one of the following scenarios:

  • Your virtual server is associated with an iApp and configured with a persistence profile.
  • You perform the following configuration merge using either the Traffic Management Shell (tmsh) or iControl:
    • tmsh load /sys config merge from-terminal
    • iControl::Management::ChangeControl::put_config

OR

  • You have systems in a device group configured for high availability (HA) with Incremental Sync enabled
  • An iApp with one or more associated virtual servers is deployed to one or more peers in the device group
  • The iApp is reconfigured on one of the peers, with no modifications to the virtual server configuration, and synchronized to the device group

Impact

The BIG-IP system removes the iApp association from the virtual server.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You observe the iApp association is removed from the virtual server configuration.

    For example, the following iApp configuration snippet is missing from the virtual server configuration:

    app-service /Common/iApp-config-test

Workaround

To work around this issue, you should add the affected virtual server name to the list of commands during the merge process.

For example, you should add ltm virtual server iApp-test_vs { } to the tmsh merge script during the merge process:

cli admin-partitions { update-partition Common } ltm persistence source-addr /Common/put-config-test { app-service none defaults-from /Common/source_addr mirror enabled timeout 300 } ltm virtual iApp-test_vs { }
