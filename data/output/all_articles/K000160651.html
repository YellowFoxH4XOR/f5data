K000160651: FIPS Key Migration from BIG-IP iSeries to F5OS rSeries: Incomplete Key Import and Workaround

Description

This article addresses the issue of incomplete FIPS key migration when moving from a BIG-IP iSeries to an F5OS rSeries platform. During migration, the n3fipsutil utility may report successful import of all exported FIPS keys, but a lower number of keys are actually present on the destination device. This can result in errors such as:

  • FIPS manager failed to synchronize FIPS key (/Common/<keyname>) from file (/config/filestore/files_d/Common_d/certificate_key_d/:Common:<keyname>_<id>_1)
  • unable to synchronize FIPS key (/Common/<keyname>)
  • UCS load failures and missing FIPS keys in tmsh show sys crypto fips output

The issue may also manifest as missing key labels or truncated key names after import, and only a subset of keys are visible on the destination, despite the import utility reporting all keys as imported.

Environment

  • Source: BIG-IP iSeries hardware appliance, version 17.5, with 3rd generation HSM (3.0G)
  • Target: F5OS rSeries, tenant running BIG-IP version 17.1.0.1 or later
  • FIPS HSM partition created with backup option enabled
  • Security Officer (SO) password and security domain label available
  • Migration attempted using n3fipsutil and fipsutil_v2_r utilities
  • UCS file migration using F5 Journeys
  • Key names may contain multiple dots (.) as part of the label

Cause

Bug ID 1854633

The n3fipsutil utility may fail to import all FIPS keys when key labels contain dots (.) or due to other internal limitations. The utility reports successful import, but not all keys are actually loaded into the HSM.

Answer/Recommended Actions

To ensure all FIPS keys are successfully migrated and available on the destination device, follow these steps:

1.Export FIPS Keys from Source Device

    • Use n3fipsutil -exportAll <dir-name> [ -n <partition-name> ] on the source BIG-IP to export all FIPS keys.
    • Verify the keys subdirectory contains all expected .key.p8 files (one per key).

2.Import FIPS Keys on Destination Device

    • Use n3fipsutil -importKeys <dir-name> [ -n <partition-name> ] on the destination rSeries tenant.
    • After import, check the number of keys with tmsh show sys crypto fips.
  1. If Keys Are Missing After Import
    • Compare the list of key handles (IDs) on the source and destination using tmsh show sys crypto fips.
    • For each missing key, manually import using:
    • tmsh install sys crypto key <label> from-local-file <path-to-keyfile> security-type fips passphrase <export-passphrase>
      • <label>: Any temporary label (BIG-IP will update the label when loading the UCS).
      • <path-to-keyfile>: Path to the .key.p8 file for the missing key.
    • <export-passphrase>: Passphrase used during export.
    • It may help to add a short delay (e.g., sleep 3) between imports if importing many keys in a script.

       2. Load the UCS File

    • Once all keys are present, load the UCS file using the recommended platform-migrate procedure.
    • If UCS load fails with FIPS key sync errors, ensure all keys are present and repeat the manual import as needed.

        3. Verify

    • After UCS load, confirm all FIPS keys are present and associated with their correct labels.

Additional Information

  • The n3fipsutil utility may not handle all key labels correctly, especially those with multiple dots (.) in the name.
  • Manual import using tmsh install sys crypto key ... is a reliable workaround to ensure all keys are loaded.
  • The workaround should be performed before loading the UCS file.
  • The issue is tracked under K000152125 and may not be resolved in current releases.
  • If the UCS load fails due to unrelated configuration (e.g., network objects), remove or adjust those objects as needed.
