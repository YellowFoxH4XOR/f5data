Known Issue

iRules referencing an SSL profile may cause TMM to core.

This issue occurs when all of the following conditions are met:

  • A virtual server is associated with an iRule that references an SSL profile.
  • The Client SSL connection is terminated during an SSL transaction.

In this situation, the BIG-IP system removes the connection flow and references, but does not relay the information to SSL hardware. As a result, the SSL hardware continues processing. Once the SSL hardware is finished, it attempts to communicate with the de-referenced and cleared connection flow, which results in a segmentation violation (SEGV).

Note: This issue does not occur if the virtual server is associated with an SSL profile directly.

Impact

If the BIG-IP is a member in a redundant configuration, traffic will fail over to the standby BIG-IP system. If the BIG-IP is not part of a redundant pair, traffic will be interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP generates a stack trace and SIGSEGV segmentation fault to the /var/log/ltm file.
  • The TMM process dumps core and restarts.

Workaround

To work around this issue, you can modify the iRule to remove the SSL profile statement, and ensure that the SSL profile is referenced directly from the virtual server.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.
