Description

  • An HA group goes active active due to a network event.
  • Network connectivity is restored but applications do not become available for 30 minutes.

Environment

  • An HA group running active-standby

Cause

The network event breaks the heartbeat connection between the device and the Standby goes active as intended. It sends GARP's for the traffic group objects to acquire traffic.
The primary Active device is unaware of this as the network is down. When connectivity is restored, the Secondary device returns to Standby. The primary device is unaware of the changes and does not GARP to restore connectivity.
Traffic continues to go to the Standby device which will not process it. When the ARP cache in the switch expires, new ARPs go to the active device and function is restored. This is typically 30 minutes.


Recommended Actions

  1. A manual failover and failback will restore function.

Additional Information

This is more likely to occur if the unicast failover network doesn't have the management IP included. Typically the management network is separate from the dataplane.
