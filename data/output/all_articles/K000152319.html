Description

Enabling the same external VLAN on multiple F5OS-Appliance (rSeries) devices connected to the same network segment can result in connectivity failures for external IP addresses and frequent server disconnections.

Typical symptoms include broadcast storms, MAC address flapping, and general network instability affecting all devices on the impacted VLAN. Interface errors or abnormal traffic patterns may be observed.

Environment

  • Low-end rSeries models (r2000 and r4000)
  • High-end rSeries models (r5000, r10000, and r12000)
  • VLAN

Cause

When the same VLAN is enabled simultaneously on multiple devices connected to the same broadcast domain without proper loop prevention mechanisms (such as STP), Layer 2 loops can occur.

The r2000 and r4000 platforms do not support spanning tree protocols and restrict each VLAN to a single interface or LAG per device by design. For more information, refer to K000151396: Rseries appliance support on STP.

If both devices are active on the same VLAN within the same network segment, this can result in broadcast storms, MAC address flapping, and overall network instability.

Although the r5000, r10000, and r12000 platforms support spanning tree protocols (STP), it is not enabled by default. When adding a VLAN on multiple interfaces or LAGs on the r5000, r10000, or r12000 platform, be aware that this action will bridge the VLAN traffic between all interfaces assigned to the VLAN and introduces a risk for L2 loop between the r5000, r10000, or r12000 platform and the switch fabric. Measures to detect and prevent the loop relevant to the deployed architecture should be implemented. These measures may include using STP variants or running multi-chassis link aggregation mechanisms on switch fabric.

Recommended Actions

  • Avoid enabling the same VLAN on multiple F5OS devices connected to the same network segment unless robust loop prevention (e.g., STP) is implemented at the switch.
  • If migrating services from an old device to a new one, disable the relevant VLAN on the old device before enabling it on the new device.
  • Always configure VLANs at the F5OS host (appliance) level rather than inside tenants unless there is a specific requirement.
  • Verify correct configuration of VLAN tagging and trunking at the host level, especially when using Link Aggregation Groups (LAGs).
  • Review switch configurations to ensure that loop prevention mechanisms such as STP are active on ports connecting to F5 appliances.
  • If both appliances must remain active with access to the same VLAN, ensure switches are configured appropriately to prevent Layer 2 loops.
  • In case of detected broadcast storms or severe instability, immediately disconnect one of the devices from the affected VLAN.
