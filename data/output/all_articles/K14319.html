Known Issue

BIG-IP APM Active Directory authentication may fail to recognize that an offline domain controller has been restored.

This issue occurs when the following conditions are met:

  • A BIG-IP APM access policy is configured with an Active Directory AAA server.
  • The Active Directory Domain Controller goes from an offline to an online state.

The BIG-IP APM Active Directory AAA server implementation uses a cache to track the state of the domain controllers. This cache is used to reduce the constant querying and delays associated with a down domain controller. If a domain controller is unreachable for more than 30 seconds, the Access Policy daemon (APD) flags it as down in the cache. The APD process checks downed domain controllers every 10 minutes, which may result in a delay before the APD process marks a domain controller as available again. This can cause issues in an environment where there are limited domain controllers available for authentication.

Impact

Users are unable to access resources through the BIG-IP APM system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The user authentication may fail.
  • The user receives an error message that appears similar to the following example:

    The username or password is not correct. Please try again.
