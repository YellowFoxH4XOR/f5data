Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file when using the SSL::disable client-side iRules command within an HTTP_REQUEST event.

This issue occurs when the following conditions are met:

  • You have configured a virtual server that uses an iRule.
  • The iRule contains the SSL::disable client-side iRules command within an HTTP_REQUEST event.
  • The virtual server processes traffic that triggers the HTTP_REQUEST event while processing encrypted traffic.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic.

Workaround

There is no workaround for this issue. However, you can mitigate this issue by avoiding the SSL::disable client-side iRules command in an HTTP_REQUEST event.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure any modification is compatible with your environment.

For more information about iRules commands, refer to the iRules Home on F5 Cloud Docs.
