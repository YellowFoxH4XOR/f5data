Topic

The Payment Card Industry (PCI) Data Security Standard (DSS) requires that all entities that process, store, or transmit cardholder data and/or sensitive authentication data discontinue use of the SSL and Transport Layer Security (TLS) 1.0 protocols by June 30, 2018.

Description

PCI DSS is the global data security standard adopted by the payment card brands for all entities that process, store, or transmit cardholder data and/or sensitive authentication data.

PCI DSS 3.2 no longer considers SSL and TLS 1.0 secure. Entities using SSL and TLS 1.0 must implement a more secure encryption protocol, such as TLS 1.1 or higher (TLS 1.2 is strongly encouraged) by June 30, 2018. For more information, refer to Are You Ready for 30 June 2018? Saying Goodbye to SSL/early TLS.

This change directly affects the PCI DSS requirements described in the following table.

RequirementsDescription
2.2.3Implement additional security features for any required services, protocols, or daemons that are considered to be insecure.
2.3Encrypt all non-console administrative access using strong cryptography.
4.1Use strong cryptography and security protocols to safeguard sensitive cardholder data during transmission over open, public networks.

For more information about the PCI DSS 3.2 specification, refer to the PCI Security Standards Council library.

Recommendations

When using a BIG-IP system to process or transmit card payment, make sure the BIG-IP system is not configured to use SSL (SSLv2, SSLv3) and TLS 1.0 (TLSv1).

To watch a video demo of this procedure, go to  PCI DSS deprecation of SSL and TLS 1 0 with BIG-IP 13 x demo.

To enforce compliance, you can configure the SSL profile on the BIG-IP system to use a specific protocol. To do so, perform one of the following procedures:

  • Configuring the BIG-IP SSL profile to use a specific protocol using the Configuration utility
  • Configuring the BIG-IP SSL profile to use a specific protocol using tmsh
  • Configuring the BIG-IP SSL profile to not use SSL and TLS 1.0 using the Configuration utility
  • Configuring the BIG-IP SSL profile to not use SSL and TLS 1.0 using tmsh
  • Configuring the Configuration utility to not use SSL or TLS 1.0 ciphers
  • Configuring the Configuration utility to use a specific protocol

Configuring the BIG-IP SSL profile to use a specific protocol using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create for a new profile or select the name of an existing profile.
  4. If you are creating a new profile, for Name, type a name for the SSL profile.
  5. For Configuration, select Advanced.
  6. If you are creating a new profile, under Ciphers, select the Custom check box.
  7. In BIG-IP 13.0.0 and later, select Cipher String.
  8. For Ciphers, type the cipher string.

    For example, the following string configures an SSL profile to use only TLS 1.2 protocol ciphers with SSLv3 and TLSv1 disabled:

    TLSv1_2 !SSLv3:!TLSv1

  9. Select Update.

Configuring the BIG-IP SSL profile to use a specific protocol using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Configure the SSL profile to use a specific protocol using the following command syntax:

    modify /ltm profile client-ssl <profile_name> ciphers <protocol>

    For example, to modify the clientssl1 profile to use only TLS 1.2, type the following command:

    modify /ltm profile client-ssl clientssl1 ciphers TLSv1_2

Configuring the SSL profile to not use SSL and TLS 1.0 using the Configuration utility

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create for a new profile or select the name of an existing profile.
  4. If you are creating a new profile, for Name, enter a name for the SSL profile.
  5. For Configuration, select Advanced.
  6. If you are creating a new profile, under Options, select the Custom check box.
  7. For Options, select Options List.
  8. Under Options List, for Available Options, press Shift, select No SSL, No SSLv2, No SSLv3, and No TLSv1, and then click Enable.
  9. Select Update.

Configuring the SSL profile to not use SSL and TLS 1.0 using tmsh

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Configure the SSL profile to not use SSL and TLS 1.0 using the following command syntax:

    modify /ltm profile client-ssl <profile_name> options {no-ssl no-sslv2 no-sslv3 no-tlsv1}

    For example, to modify the clientssl1 profile to not use SSL and TLS 1.0, enter the following command:

    modify /ltm profile client-ssl clientssl1 options {no-ssl no-sslv2 no-sslv3 no-tlsv1}

Configuring the Configuration utility to not use SSL or TLS 1.0 ciphers

Impact of procedure: The Configuration utility does not use ciphers that are compatible with SSL and TLS 1.0. Clients that do not support TLS 1.1 and TLS 1.2 may not be able to connect.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list the currently configured cipher string, enter the following command:

    list /sys httpd ssl-ciphersuite

    The output of this command varies by version. For example:

    • BIG-IP 11.5.1 displays the following cipher string:

      ALL:!ADH:!EXPORT:!eNULL:!MD5:!DES:RC4+RSA:+HIGH:+MEDIUM:+LOW:+SSLv2

    • In BIG-IP 12.1.2 and later, the cipher string provides a more explicit list. For example:

      ssl-ciphersuite ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-SHA:ECDHE-RSA-AES128-SHA256:ECDHE-RSA-AES256-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-SHA:ECDHE-ECDSA-AES256-SHA:ECDHE-ECDSA-AES128-SHA256:ECDHE-ECDSA-AES256-SHA384:AES128-GCM-SHA256:AES256-GCM-SHA384:AES128-SHA:AES256-SHA:AES128-SHA256:AES256-SHA256:ECDHE-RSA-DES-CBC3-SHA:ECDHE-ECDSA-DES-CBC3-SHA:DES-CBC3-SHA

  3. To restrict the Configuration utility from negotiating SSL or TLS 1.0 ciphers, use the following command syntax:

    modify /sys httpd ssl-ciphersuite <protocol>

    For example:

    • For BIG-IP 11.5.1, use the following command:

      modify /sys httpd ssl-ciphersuite 'ALL:!ADH:!EXPORT:!eNULL:!MD5:!DES:!SSLv2:!TLSv1:!SSLv3'

    • For BIG-IP 12.1.2 and later, use the following command:

      modify /sys httpd ssl-ciphersuite '!TLSv1:!SSLv3:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-SHA:ECDHE-RSA-AES128-SHA256:ECDHE-RSA-AES256-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-SHA:ECDHE-ECDSA-AES256-SHA:ECDHE-ECDSA-AES128-SHA256:ECDHE-ECDSA-AES256-SHA384:AES128-GCM-SHA256:AES256-GCM-SHA384:AES128-SHA:AES256-SHA:AES128-SHA256:AES256-SHA256:ECDHE-RSA-DES-CBC3-SHA:ECDHE-ECDSA-DES-CBC3-SHA:DES-CBC3-SHA'

  4. Save the configuration change by entering the following command:

    save /sys config

Configuring the Configuration utility to use a specific protocol

Impact of procedure: With this procedure, the Configuration utility only allows access using TLSv1.1 and TLSv1.2 protocols. Due to Bug ID 490801 described in K17491: Unable to limit Configuration utility access to clients using only TLSv1.1 or TLSv1.2, this recommendation should only be applied to versions not impacted by Bug ID 490801 (such as 11.5.4 HF2 and later); otherwise, these affected versions prevent users from accessing the Configuration utility, as those earlier releases do not have support for TLSv1.1 and TLSv1.2.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To list the currently configured protocols allowed for httpd, enter the following command:

    list /sys httpd ssl-protocol

    The output of this command appears similar to the following:

    sys httpd {
        ssl-protocol "all -SSLv2 -SSLv3"
    }

  3. To restrict the Configuration utility from negotiating specific protocols, use the following command syntax:

    modify /sys httpd ssl-protocol "ALL -<undesired_protocol> -<undesired_protocol>"

    In this syntax, <undesired_protocol> is the protocol you want to restrict. For example, to restrict the Configuration utility from negotiating TLSv1.0, SSLv2, or SSLv3, use the following command:

    modify /sys httpd ssl-protocol "ALL -TLSv1 -SSLv2 -SSLv3"

  4. Save the configuration change by entering the following command:

    save /sys config partitions all
