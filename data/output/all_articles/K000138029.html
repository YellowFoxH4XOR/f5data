K000138029: How to check if Cassandra OAM-DB had a successful repair

Type
Support Solution
Published
2023-12-28
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000138029

Description

  • There are certain logs that tells you when a cassandra repair activity was successful.
  • These logs are found in /var/log/rsyslog/OAM-DB.cassandra-repair.log
  • Example logs of successful repair: 

    /var/log/rsyslog$ grep -B1 -iP "(repairing keyspace|repair complete)" f5_ems01.OAM-DB.cassandra-repair.log
     [2023-03-17 01:05:37,974] INFO - acquireLock: succeeded
     [2023-03-17 01:05:39,742] Starting repair command #1091, repairing keyspace nms_f5dra01_ems with repair options (parallelism: parallel, primary range: false, incremental: true, job threads: 1, ColumnFamilies: [], dataCenters: [], hosts: [], # of ranges: 1536)
    --
     [2023-03-17 01:02:22,314] INFO - acquireLock: succeeded
     [2023-03-17 01:02:23,942] Starting repair command #1090, repairing keyspace topology with repair options (parallelism: parallel, primary range: false, incremental: true, job threads: 1, ColumnFamilies: [], dataCenters: [], hosts: [], # of ranges: 1536)
    --
     [2023-03-17 01:05:08,151] Repair session 63326990-c41c-11ed-a991-9300059aa258 for range (6891137425829552550,6892141786015376707] finished (progress: 100%)
     [2023-03-17 01:05:08,263] Repair completed successfully
    --
     [2023-03-17 01:05:37,974] INFO - acquireLock: succeeded
     [2023-03-17 01:05:39,742] Starting repair command #1091, repairing keyspace nms_f5dra01_ems with repair options (parallelism: parallel, primary range: false, incremental: true, job threads: 1, ColumnFamilies: [], dataCenters: [], hosts: [], # of ranges: 1536)

Environment

  • Traffix SDC 5.x
  • OAM-DB
  • Repair logs

By design.
