Known Issue

This is the result of a known issue. Time zone changes, performed from either the CLI or Configuration utility, may not synchronize correctly with the Always-On Management (AOM) subsystem.

Note: This issue only affects platforms with the AOM, 1600, 3600, and 6900 systems. Systems with an SCCP are not affected; they use Universal Time by default.

When a time zone change is performed on the host portion of the system, a script is run to convert the region and city information into a second time zone format that is currently used on the AOM subsystem. In some region/city selections, the information is not converted correctly due to an incorrect or missing corresponding time zone value. If there is no corresponding time zone value in the /usr/share/zoneinfo/F5zone.tab file for AOM, AOM will default to UTC time.

For example, the Configuration utility contains an entry for Africa/Cairo, but the time zone Africa/Cairo does not exist in the F5zone.tab file used to convert the selected region/city information for the AOM. Since an entry does not exist, the AOM will default to using UTC for the time zone.

If an incorrect time value is listed in the F5zone.tab file for AOM, the result will be a time zone mismatch between the host system and the AOM subsystem.

Note: This mismatch will only affect AOM log entry timestamps and will not affect the operation of BIG-IP or timestamp logging outside of AOM.

Most time zones are covered by the script; however, the F5zone.tab file may not have a corresponding entry for some region/city selections.

F5 Product Development tracked this issue as ID 205649 (formerly CR115682) and it was fixed in BIG-IP versions 9.4.7 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

If the host system time zone does not have a corresponding time zone entry in the F5zone.tab file for the AOM time zone, select another city that shares the same time zone or you can let the AOM default to using UTC time.

To check the date and time on both the host system and the AOM, type the following command:

date ; ssh aom date

The output will appear similar to the following example:

Wed Feb 18 09:42:05 CST 2009
Wed Feb 18 09:42:08 CST 2009
