K000149107: Telemetry Streaming declarations fail with a 422 error when a non-default admin user is used

Type
Support Solution
Published
2025-01-15
Updated
2025-02-07
Applies to
  • F5 Automation and Orchestration
  • BIG-IP
  • F5 BIG-IP Telemetry Streaming
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000149107

Description

Your BIG-IP system is configured with an alternate username for the primary admin user and you are unable to configure telemetry streaming. When posting the Telemetry Streaming declaration you receive a 422 response with an error message as follows:

{
"code": 422,
"message": "java.net.ProtocolException: status:422, body:{\"code\":422,\"error\":[{\"status\":\"rejected\",\"reason\":{\"message\":\"validation failed\",\"errors\":[{\"dataPath\":\"/My_Consumer/passphrase\",\"propertyName\":\"passphrase\",\"keyword\":\"f5secret\",\"message\":\"Bad status code: 500 Server Error for http://localhost:8100/mgmt/tm/ltm/auth/radius-server\",\"params\":{}}],\"validation\":true,\"ajv\":true}}],\"message\":\"Unprocessable entity\"}",
"referer": "10.10.10.10",
"restOperationId": 10523,
"kind": ":resterrorresponse"
}

Environment

  • Telemetry Streaming
  • Non-default admin user configured

Cause

Telemetry Streaming only supports systems using the default username, admin, for the primary administrator.

Recommended Actions

To work around this issue, you must switch back to using "admin" as the default admin username. To make the switch, you can issue the following command:

tmsh modify sys db systemauth.primaryadminuser value admin

Note: This workaround may not be feasible if you have changed the primary admin user for security compliance reasons.  There are no other workarounds at the moment, but F5 is considering implementing the functionality of this feature into a future software release.
