K000133278: DestinationRules with same host are not merger by Istio

Published
2023-03-30

Applies to

Source

Description

DestinationRules with same host are not merger by Istio

 

Environment

Aspenmesh 1.9.x, 1.11.x, 1.14.x

Cause

DestinationRules using same "host" field are not merger properly by Istio and Aspenmesh. The first deployed DestinationRule will be applied to the service and every next rule with same host name will be silently ignored by Istio.

Istio is tracking the progress of fixing this problem on the following issue:

https://github.com/istio/istio/issues/22997

Recommended Actions

The host name is used by Istio as a "key" for service map structure.

As a result the host field cannot be reused by multiple DestinationRules and VirtualServices in the same scope.

Only the first deployed rule will be applied to the service and every next rule will be silently ignored.

To workaround the problem all DestinationRules or VirtualServices with same host name have to be combined into one rule including all settings.

The problem can be also solved by changing the scope of rules and services by using exportTo or workloadSelectors.

workloadSelectors for DestintionRules are supported only in Istio and Aspenmesh 1.13+.

 

Example:

2 DestinationRules using same host:

apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: tls-dr-mesh-2
  namespace: ns1
spec:
  host: 'tls.test.local.com'
  trafficPolicy:
    portLevelSettings:
    - port:
        number: 6611
      tls:
        mode: SIMPLE
---
kubectl apply -n ns1 -f - <<EOF
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: tls-dr-mesh-1
  namespace: ns1
spec:
  host: 'tls.test.local.com'
  trafficPolicy:
    portLevelSettings:
    - port:
        number: 4422
      tls:
        mode: SIMPLE
---

should be integrated into 1 rule:

apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: tls-dr-mesh-combined
  namespace: ns1
spec:
  host: 'tls.test.local.com'
  trafficPolicy:
    portLevelSettings:
    - port:
        number: 6611
      tls:
        mode: SIMPLE
    - port:
        number: 4422
      tls:
        mode: SIMPLE
