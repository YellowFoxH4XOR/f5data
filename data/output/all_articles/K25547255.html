Description

After an upgrade from v13 to v15, some pools with default https monitors assigned, stop working as the pool members are marked down. The monitors were working and marking the pool members UP prior to the upgrade.

On a traffic capture you can see the Client Hello sent from BIG-IP to server, to establish an SSL connection, however, the server closes the connection with a FIN straight after. For example:

10.10.20.4 → 10.10.10.1  TCP   OUT s1/tmm1 : 41418 → 443 [SYN]
10.10.10.1 → 10.10.20.4  TCP   IN  s1/tmm1 : 443 → 41418 [SYN, ACK]
10.10.20.4 → 10.10.10.1  TCP   OUT s1/tmm1 : 41418 → 443 [ACK]
10.10.20.4 → 10.10.10.1  TLSv1 OUT s1/tmm1 : Client Hello
10.10.10.1 → 10.10.20.4  TCP   IN  s1/tmm1 : 443 → 41418 [FIN, ACK]
10.10.20.4 → 10.10.10.1  TCP   OUT s1/tmm1 : 41418 → 443 [FIN, ACK]

On the previous software version, the SSL handshake is completed correctly between BIG-IP and backend server, when capturing the monitor probes.

Environment

  • Pool members using default HTTPs monitor

Cause

On newer versions of BIG-IP, the default HTTPs monitor tries to negotiate a newer version of TLS, in this case TLS1.2, on the Client Hello for the SSL handshake, some pool members do not support this version of TLS and the monitor probes fail. TLS 1.0 and TLS 1.1 are deprecated and considered no longer secure.

Recommended Actions

Allow pool member to use TLS1.2.
