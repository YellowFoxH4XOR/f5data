Known Issue

The mcpd process can crash while waiting for input from a background process.

This issue occurs when the following condition is met:

  • A background process, such as an external monitor or shell command, hangs.

This issue has been known to occur when the mcpd process spawns a child process to run a script or shell command. If the script or command hangs, mcpd attempts to kill the process and subsequently fails to obtain any further status from the affected script or command.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic may fail over to the standby BIG-IP system. If the BIG-IP is not part of a redundant pair, traffic may be interrupted.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • If the BIG-IP system is a member in a redundant configuration, traffic may fail over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic may be interrupted.
  • The system may experience an mcpd process heartbeat failure and log error messages to the /var/log/ltm file that appear similar to the following example:

    notice overdog[5451]: 01140029:5: HA daemon_heartbeat mcpd fails action is restart all.
  • The BIG-IP system may log an error message indicating that the system failed to kill a command. The error is logged to /var/log/ltm and appears similar to the following example:

    01071392:3: Background command '<command>' failed. Failed to kill the command: Permission denied.
