Known Issue

Modifying a Secure Sockets Layer (SSL) profile associated with a virtual server may result in the Traffic Management Microkernel (TMM) producing a core file.

This issue occurs when all of the following conditions are met:

  • The associated virtual server is configured with multiple SSL profiles, one of which is the default server name indication (SNI) profile.
  • You perform one of the followings actions:
    • You reload the configuration, either manually or automatically, after a configuration synchronization (ConfigSync).
    • You make a change to any of the SSL profiles associated with the virtual server.
    • You add or remove SSL profiles from the associated virtual server's profile list.
    • You modify or delete the virtual server.

Impact

The BIG-IP system may temporarily fail to process traffic while TMM restarts, and the system fails over if it is configured for high availability (HA).

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system sends an invalid memory access segmentation fault (SIGSEGV) or floating point error (SIGFPE) signal to TMM, resulting in a stack trace that appears in the /var/log/tmm file.
  • TMM restarts and produces a core file in the /shared/core directory.
  • Your BIG-IP system generates an assertion failure panic string in the /var/log/tmm file that appears similar to the following example:

    panic: ../kern/umem.c:3881: Assertion "valid type" failed
