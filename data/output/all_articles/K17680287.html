Topic

This article describes the fields the BIG-IP ASM system uses when generating bot defense logs for remote logging.

Description

When you configure remote logging for the bot defense feature, the BIG-IP ASM system generates logs for bot-defense events that you can view remotely. 

The following table lists the various fields used for remote logging when reporting bot defense events.

actionThe action taken by bot defense when handling the received HTTP request. The returned value is one of the following strings:
  • undetermined: The action has not yet been determined. The system returns this only due to an error.
  • allow: The system allows the HTTP request to go up the chain.
  • browser_challenge: A browser challenge (HTML + JavaScript) responds to the client.
  • captcha_challenge: A CAPTCHA challenge responds to the client.
  • redirect_challenge: A redirection challenge (307 redirect) responds to the client.
  • tcp_rst: The TCP connection closes using TCP RST (drop).
  • redirect_to_referring_domain: The system sends a 307 redirect response to the client, redirecting the client to the referring domain.
  • redirect_with_cookie: The system sends a 307 redirect response to the client, and this response is an internal port of the Bot Defense mechanism.
  • custom_response : The system sends a custom response to the client.
  • custom_redirect: The system sends a custom redirect response to the client
  • alarm: The system allows the HTTP request to go up the chain and reports to log according to log profile.
  • block: The system blocks the request.

Recommendations

In the following bot defense remote logging example, note the following:

  • The request is categorized as a suspicious browser due to the presence or order of HTTP headers, but the request occurred after having the client correctly answered the CAPTCHA challenge:

    configured_mitigation_action="CAPTCHA", configured_mitigation_action_reason="/Common/Suspicious HTTP Headers Presence or Order", actual_mitigation_action="Alarm", actual_mitigation_action_reason="CAPTCHA valid",

  • A valid device ID is present, so the system takes no action for device ID:

    device_id_status="Device ID Is Valid",device_id_action="None",

  • Browser verification is configured, but the page is not yet qualified, so the system takes no no browser verification action:

    browser_configured_verification_action="Verify after Access (Blocking)", browser_actual_verification_action="Challenge-Free Verification", browser_actual_verification_action_reason="URL Not Qualified for Injection",
