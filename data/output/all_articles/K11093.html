Known Issue

This is the result of a known issue. The httpd process fails to start if the syslog-ng utility is not running.

Note: Generally, the syslog-ng utility is always running on the BIG-IP system. If syslog-ng is not running, it was either stopped manually or it failed to start. If it failed to start, that is usually due to a syntax error in the syslog-ng configuration. To determine if syslog-ng is running, run the bigstart status syslog-ng command.

This issue occurs because the httpd process depends on syslog-ng, and it cannot start if syslog-ng is not running. Once the httpd process has failed to start, it does not release the terminal and continues to run in the foreground.

For example, consider the following scenario:

  • You connect to the BIG-IP system using SSH and you are assigned the pts/0 virtual terminal.
  • You run the bigstart stop syslog-ng command to stop the syslog-ng daemon. The command is successful and the system returns the following output:

    Shutting down syslog-ng: [ OK ]

  • You run the bigstart stop httpd command to stop the httpd daemon. The command is successful and the system returns the following output:

    Stopping httpd: [ OK ]

  • You run the bigstart start httpd command to start the httpd daemon. However, the httpd process does not start, does not return any output, and does not release the terminal.
  • The pts/0 virtual terminal remains busy until you press Ctrl+C key combination to terminate the previous command.

Note: You can also start the httpd process using other commands, for example /etc/init.d/httpd start. However, if syslog-ng is not running, the httpd process always fails to start, regardless of the command.

When the httpd process is not running, the BIG-IP system Configuration utility is not available.

In addition, this issue may occur at boot time if syslog-ng fails to start when it is spawned by the init process. In this case, the httpd process also fails to start, causing the boot process to stall indefinitely. The BIG-IP system remains inoperative, requiring user intervention.

For example, a BIG-IP system running version 10.1.0 that experiences this issue at boot time appears to hang after the httpd process is started:

Starting syslog-ng: [ OK ]
Starting irqbalance: [ OK ]
Mounting other filesystems: [ OK ]
Starting sshd: [ OK ]
Checking for firmware updates: [ OK ]
Starting ntpd: [ OK ]
Starting httpd:

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.2-852.0-HF1, which has been issued for BIG-IP version 10.2.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

To resolve this issue, you must start the syslog-ng daemon and then the httpd daemon. If the syslog-ng daemon fails to start due to an invalid configuration, then you must first fix the syslog-ng configuration.

If you are experiencing this issue on a BIG-IP system that has already completed booting, you may be able to restore the system to its normal operating conditions by performing the following procedure:

  1. If your terminal is still busy, regain control of it by pressing the Ctrl+C key combination.
  2. Verify that syslog-ng is not running, by entering the following command:

    bigstart status syslog-ng

    The system should return a message that appears similar to the following example:

    syslog-ng is stopped

  3. Verify that syslog-ng fails to start, by entering the following command:

    bigstart start syslog-ng

    The system should return a message that appears similar to the following example:

    Starting syslog-ng: syntax error at 742
    [FAILED]

  4. Reset the syslog-ng configuration by entering the following commands:

    bigpipe syslog include none
    bigpipe syslog remote server none

    Note: Beginning in BIG-IP version 9.4.2, the /etc/syslog-ng/syslog-ng.conf file is dynamically generated by the BIG-IP system. F5 assumes in this step that if the syslog-ng configuration was modified, it was done so using the bigpipe utility.

    Important: This step clears any customization you may have made to the syslog-ng configuration.

  5. Save the configuration by entering the following command:

    bigpipe save all

  6. Start the syslog-ng daemon by entering the following command:

    bigstart start syslog-ng

  7. If the command in the previous step did not fail, start the httpd process by entering the following command:

    bigstart start httpd

If you are experiencing this issue at boot time, contact F5 Technical Support for further assistance.
