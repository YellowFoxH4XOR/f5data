K000156811: TMM crash with "Failed to open" log message in /var/log/tmm

Type
Support Solution
Published
2025-10-04
Updated
2026-06-02
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.3, 17.5.1
  • BIG-IP LTM: 17.1.3, 17.5.1
Source
https://my.f5.com/manage/s/article/K000156811

Description

The TMM process may crash and trigger an HA failover during periods of elevated traffic, such as a DDoS audit.

The following log messages are repeatedly logged in the /var/log/tmm* files

<13> Oct  2 09:42:02 bigip1.example.com notice Failed to open /var/IpRep/F5IpRep.dat
<13> Oct  2 09:42:02 bigip1.example.com notice Failed to open /var/IpRep/F5IpV6Rep.dat

Environment

  • BIG-IP 17.1.3, 17.1.3.1, 17.5.1 to 17.5.1.5
  • IP Intelligence is configured but both the IP intelligence databases are missing because AFM  or IP Intelligence are not licensed

Cause

When IP Intelligence is configured/enabled without a valid license, TMM attempts to load the /var/IpRep/F5IpRep.dat and /var/IpRep/F5IpV6Rep.dat IP databases but fails. 

In BIG-IP 17.5.1, a fix for ID 1132449 introduced "Failed to open" log message in /var/log/tmm* log files.

During high traffic events, along with thousands of log entries per second and failed attempts to load the IP intelligence database, TMM stalls and triggers a SIGABRT from the sod process due to a missing heartbeat.

Recommended Actions

  • The simplest solution is to upgrade to a version that has the fix for ID 2218157
  • Disable IP Intelligence globally if it is not licensed or required as this prevents TMM from attempting to load missing databases and stops excessive logging.
  • After disabling IP Intelligence, verify that "Failed to open" messages no longer appear in the /var/log/tmm* log files.
    Note: If ASM is provisioned IP Intelligence lookups may be being invoked via mechanisms not dealt with here, and upgrade is likely the best option. 

Disable IP Intelligence from the BIG-IP GUI (If GUI access to the AFM module is available)

Impact of procedure: If AFM is not licensed or provisioned, there is no impact.

  1. Go to Security > Network Firewall > IP Intelligence > Policies.
  2. Ensure Global Policy Assignment > IP Intelligence Policy is set to None.
  3. Ensure that there is no IP Intelligence policy applied to a virtual server by going to Local Traffic > Virtual Servers.
  4. Select your virtual server.
  5. Select Security > Policies.
  6. Ensure that IP Intelligence is Disabled.
  7. Repeat for all virtual servers.

Disable IP intelligence from the TMOS shell (tmsh):

Impact of procedure: If AFM is not licensed or provisioned, there is no impact.

  1. Log into tmsh by typing the following command:
    tmsh
  2. Ensure global-policy is empty:
    list security ip-intelligence global-policy all-properties(tmos)# list security ip-intelligence global-policy all-properties
    security ip-intelligence global-policy {
        description none
        ip-intelligence-policy none
        partition Common
    }
  3. If a policy is configured, remove it:
    modify security ip-intelligence global-policy ip-intelligence-policy none
  4. Ensure that there is no IP Intelligence policy applied to a virtual server:
    cd /;list ltm virtual recursive ip-intelligence-policy(tmos)# cd /;list ltm virtual recursive ip-intelligence-policy
    ltm virtual Common/http_vs {
        ip-intelligence-policy none
    }
    ltm virtual Common/http_vs_internal {
        ip-intelligence-policy none
    }
  5. For virtual servers that have an IP Intelligence policy, you can remove it with this syntax:
    modify ltm virtual <your virtual server> ip-intelligence-policy none
  6. Save the changes you made to the the global policy and virtual servers:
    save sys config
