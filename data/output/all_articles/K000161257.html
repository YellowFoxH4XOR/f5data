Description

During installation of the f5ingress component of SPK version 1.8.0, the TMM pod failed to start due to an  error caused by the container attempting to pull an image from an internal F5 registry that was inaccessible from the customer's environment. The customer had attempted to disable the fluentbit component by commenting out its section in the values file, but this approach did not prevent the container from being included in the deployment. 

 

 

Environment

- Product: F5 SPK (Service Proxy for Kubernetes), version 1.8.0

- Deployment platform: OpenShift Container Platform

- f5ingress component being installed with a custom values file (ingress-values.yaml)

- The f5-toda-fluentbit sidecar container (artifactory.f5net.com/f5-toda-docker/f5-fluentbit:v0.6.2) was being injected into the TMM pod

- The customer's environment had no network access to the internal F5 artifact registry artifactory.f5net.com

- Customer's intent: deploy only the TMM and debug containers, without the fluentbit logging component

Cause

The ImagePullBackOff error was caused by the f5-toda-fluentbit sidecar container being included in the TMM pod deployment despite the customer's attempt to disable it by commenting out its subsection in the values file. In SPK 1.8.0, the correct method to exclude this container is to explicitly set f5-toda-logging: enabled: false at the top level of the values file, positioned before the controller: section. Commenting out the fluentbit-specific block is insufficient to suppress container injection. Since the customer's environment had no access to the internal F5 registry hosting the fluentbit image, the pod remained in a failed state. 

Answer/Recommended Actions

- To disable the f5-toda-fluentbit logging container in SPK 1.8.0, add the following parameter to the ingress-values.yaml file before the controller: section:

f5-toda-logging:
enabled: false
controller:
...

- Do not rely on commenting out the f5-toda-fluentbit subsection alone, as this does not prevent the container from being injected into the TMM pod.

- After updating the ingress-values.yaml file, perform a full uninstall and reinstall of the f5ingress component for the change to take effect.
