Security Advisory Description

scp in OpenSSH through 8.3p1 allows command injection in the scp.c toremote function, as demonstrated by backtick characters in the destination argument. NOTE: the vendor reportedly has stated that they intentionally omit validation of "anomalous argument transfers" because that could "stand a great chance of breaking existing workflows." (CVE-2020-15778)

Impact

This flaw is found in the SCP program shipped with the openssh-clients package. An attacker having the ability to SCP files to a remote server could run arbitrary commands on the remote server by including a command as a part of the filename being copied on the server. This command runs with the user permissions used to copy the files on the remote server. The most serious threats from this vulnerability are to data confidentiality and integrity, as well as to system availability.

Mitigation

BIG-IP

To mitigate this vulnerability, you can use one of the following mitigations:

  • use the rsync command instead of scp. For more information about the rsync command, enter rsync -h to view the help menu.
  • restrict SCP access to the BIG-IP Configuration utility to only trusted administrators through local or network firewalls and block SCP access by changing the Port Lockdown setting to Allow None for each self IP in the system. If you must open any ports, you should use the Allow Custom option, taking care to disallow SSH access. For more information, refer to the following articles:
    • K13092: Overview of securing access to the BIG-IP system
    • K13309: Restricting access to the Configuration utility by source IP address
    • K17333: Overview of port lockdown behavior (12.x - 21.x)

F5OS

On F5OS versions 1.8.0 and later, you can mitigate this vulnerability by preventing the root user from logging in using SSH or SCP by setting the deny-root-ssh option to enabled. Enabling this feature prevents the root user from logging in using SSH and SCP while still allowing non-root users SSH and restricted SCP access. The root user can still log in using the console, as long as appliance mode is disabled. Additionally, you can enable bash access for non-root users by setting the superuser-bash-access option to true and configuring the users secondary role as superuser, which allows SSH access and only restricted SCP access. To do so, perform the following procedures:

  • Set deny-root-ssh to enabled
  • Set bash as the default shell for the admin user

Set deny-root-ssh to enabled

Impact of procedure: Once enabled, this setting will prevent the root user from accessing the system via SSH and SCP. F5 recommends that you confirm console access and alternative administrative access prior to making any changes. For more information about the deny-root-ssh option, refer to the following documentation:

  • https://clouddocs.f5.com/training/community/rseries-training/html/rseries_security.html#configuring-ssh-and-cli-timeouts-deny-root-ssh-settings-via-cli
  • https://clouddocs.f5.com/training/community/velos-training/html/velos_security.html#session-timeouts-token-lifetime-and-deny-root-over-ssh
  1. Log in to the F5OS system CLI using the admin account.
  2. Enter configuration mode by typing the following command:

    config terminal

  3. Set deny-root-ssh to enabled by entering the following command:

    system security config deny-root-ssh enabled

  4. Save the changes by typing the following command:

    commit

  5. Exit configuration mode by typing the following command:

    exit

  6. Confirm the changes by typing the following command:

    show system security state deny-root-ssh

    The output should appear similar to the following example:

    system security state deny-root-ssh enabled

Set bash as the default shell for the admin user

Impact of procedure: The superuser role provides sudo privileges and bash access to the system. F5 recommends that before assigning this role, you refer to the following documentation:

  • https://clouddocs.f5.com/training/community/rseries-training/html/rseries_security.html#superuser-role
  • https://clouddocs.f5.com/training/community/velos-training/html/velos_security.html#superuser-role
  1. Log in to the F5OS system CLI using the admin account.
  2. Enter configuration mode by typing the following command:

    config terminal

  3. Enable bash shell access for users assigned the superuser role by typing the following command:

    system aaa authentication config superuser-bash-access true

  4. Assign superuser as the secondary role for the admin user by typing the following command:

    system aaa authentication roles role superuser config users admin

  5. Optionally, remove the admin user from the superuser group by typing the following command:

    no system aaa authentication roles role superuser config users admin

  6. Save the changes by typing the following command:

    commit

  7. Exit configuration mode by typing the following command:

    exit

  8. Confirm the changes by typing the following commands:

    Confirm enabled

    show system aaa authentication state superuser-bash-access

    The output should appear similar to the following example:

    system aaa authentication state superuser-bash-access true

    Confirm user role

    show system aaa authentication roles role superuser

    The output should appear similar to the following example:
