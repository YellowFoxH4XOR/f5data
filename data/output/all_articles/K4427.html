Topic

If you modify the BIG-IP configuration before you perform an upgrade and do not test the configuration, the BIG-IP system may fail to boot. As a result, the BIG-IP system will display the following error message:

process cannot complete

If the configuration was not properly converted to work with the new version, or if the modified configuration was corrupted, the BIG-IP system will unsuccessfully attempt to load the configuration. If this occurs, the system will not function properly. The Configuration utility may not be available and the system may not pass traffic.

You can resolve this issue by performing the following procedure:

  1. Connect a serial console to the BIG-IP system.
     
  2. Reboot the system.
     
  3. Press the Enter key to interrupt loading of the configuration as soon as the following message appears:

    Waiting for system initialization to complete

    The command prompt appears.

  4. Back up the configuration, using the following command syntax:

    bigpipe config save <filename>

    Replace <filename> with the name of the UCS archive that you want to use.

  5. Attempt to load the configuration by typing the following command:

    bigpipe load

    You should receive an error message that provides the specific line in the configuration that is failing.

  6. Using a text editor, open the bigip.conf file and view the failing line.

    If the problem is obvious, such as a typo or syntax issue, correct the typo or syntax error to resolve the issue.

    If you cannot see an obvious problem, remove the line entirely.

  7. Save the changes to the bigip.conf file.
     
  8. Attempt to load the configuration by typing the following command:

    bigpipe load

    You should receive an error message that provides the specific line in the configuration that is failing.

    Once you have fixed or removed all the problematic lines, the configuration will load successfully.

  9. After the configuration successfully loads, use the Configuration utility or the command line to recreate the configuration statements that you removed.

The configuration should now load properly for the new version.
