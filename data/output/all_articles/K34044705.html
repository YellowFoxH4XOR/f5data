K34044705: Troubleshooting high CPU in Bigd due to external monitors using curl

Description

The BIG-IP system may have a high CPU in the Bigd process which could be caused by external monitors which can provoke delays in the control plane operations. (Configuration Utility, generation of qkview, etc..)
Note: In order to detect the amount of CPU percentage external monitors are consuming in the Bigd process, you can run the script mentioned in the following article: K45456222: Preventing and/or troubleshooting high CPU impact by external monitors. 
 

Environment

  • BIG-IP LTM
  • External monitors using curl
  • High CPU in Bigd ephemeral processes.

Cause

External monitors using curl that do not need to authenticate to the server can be processing the large system CA cert file and this can cause a high CPU usage by the BigD ephemeral processes. (Also called spawned processes)

Recommended Actions

Specify a Dummy Cert for the external monitors:

  1. Create the Dummy Cert:

      # touch /config/ssl/ssl.crt/dummy-ca.crt

       2. Add the flag --cacert /config/ssl/ssl.crt/dummy-ca.crt to all curls made in the script of the external monitor.
           
           Example: 

      curl \
            --verbose \
            --insecure \
            --max-time "$max_time" \
            ..... etc....
      
      Change it to:
      curl \
            --cacert /config/ssl/ssl.crt/dummy-ca.crt \
            --verbose \
            --insecure \
            --max-time "$max_time" \
            ..... etc....

 

Additional Information

After applying the changes to the external monitor scripts, it is recommended to run the perl script mentioned in K45456222: Preventing and/or troubleshooting high CPU impact by external monitors. in order to detect the CPU percentage changes in the Bigd ephemeral processes.
