Topic

The license limits are based on the bandwidth of data prior to compression.

In a typical client-server scenario, browsers and servers can be configured to compress and uncompress HTTP content. HTTP compression reduces the amount of data to be transmitted, thereby significantly reducing bandwidth usage.

You can create an HTTP profile that causes the BIG-IP system to compress server responses using well-defined algorithms, such as gzip and deflate. You can configure several options when defining an HTTP profile, including the following:

  • The specific content that is compressed
  • Dynamic methods of applying compression with iRules

The BIG-IP system only counts the uncompressed data that is specified for compression to determine license compliance. The BIG-IP system does not count HTTP headers or any other content, including HTTP content, that is not being compressed.

Note: For additional information about the BIG-IP compression feature, refer to the Managing HTTP and FTP traffic chapter of the Configuration Guide for Local Traffic Management.
