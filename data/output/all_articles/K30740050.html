K30740050: BIG-IQ GUI is unavailable due to corrupted PostgreSQL database

Type
Support Solution
Published
2022-09-12
Updated
2025-03-12
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0, 7.1.0, 8.X.X, 8.3.X, 8.3.0, 8.2.X, 8.2.0, 8.1.X, 8.1.0, 8.0.X
Source
https://my.f5.com/manage/s/article/K30740050

Description
When an administrator cannot access the GUI of BIG-IQ, it is recommended to assess the symptoms presented by the BIG-IQ. One of the causes where BIG-IQ is not able to serve the GUI is an issue with PostgreSQL database since the BIG-IQ's configuration used by the GUI is stored in a database.

A common symptom of a database issue is when postgres daemon keeps restarting. This can be seen when executing 'tmsh show sys service postgres'. An output similar to the following can be seen where there is a high count of restarts:

# tmsh show sys service postgres
postgres     run (pid xxxx) 1 seconds, xxx restarts
 

Environment

  • BIG-IQ CM version 7.1 or 8.x
  • Administrator cannot access GUI of BIG-IQ

Cause
Corrupted PostgreSQL database.

Recommended Actions

If postgres was restarted many times, it is worth reviewing logs stored in /var/log/postgres/. Log file names would have the format of postgresql-yyyy-mm-dd.log, with the latest logs being written on the current date.

When postgres repeatedly tries to bring the database up, entries similar to the following would appear in the logs:

  FATAL:  the database system is starting up

You may verify by running the following commands:

  # cd /var/log/postgres
  # grep "database system is starting" *

When the symptoms above are observed, PostgreSQL database needs to be reinitialized.

Reinitialize the database using these following the steps in K000150361: Resetting the Big-IQ Postgres database

Wait for a few minutes until you can see the GUI login page.
