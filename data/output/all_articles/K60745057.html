Known Issue

The BIG-IP ASM system triggers false positives for ASM Cookie Hijacking violations.

This issue occurs when all of the following conditions are met:

  • You configured the security policy for multiple hosts on the web application.
  • The BIG-IP ASM system inserts TS cookies with a higher domain level than you configured.
  • The system incorrectly processes a request from one host as a request from another host.
  • The BIG-IP ASM configuration does not use the Device ID feature for session tracking.

Note: The ASM Cookie Hijacking violation option is most effective when the Device ID feature is enabled.

Impact

The BIG-IP ASM system triggers a false positive ASM Cookie Hijacking violation.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP ASM system triggers a false positive ASM Cookie Hijacking violation.

Workaround

To work around this issue, you can disable the ASM Cookie Hijacking option. You must disable the Device ID feature before you can disable the ASM Cookie Hijacking option.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the Current edited security policy list, click the relevant security policy.
  4. From the Settings drop-down menu, select Advanced.
  5. Under Policy Building Settings, click Sessions and Logins.
  6. In the ASM Cookie Hijacking row, clear the Learn, Alarm, and Block check boxes.
  7. Click Save.
  8. Click Apply Policy.
