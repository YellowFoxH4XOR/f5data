K67220623: iHealth reports ''QkView Failed Processing'' after upload

Applies to

Source

Description

iHealth fails to process qkview with error "The file is not a QKView or the QKView is truncated. Critical files are either missing or truncated : 'VERSION'".

Environment

  • BIG-IP
  • iControl SOAP 
  • SSL Key Management

Cause

Thousands of files can accumulate in /var/run/key_mgmt when using iControl SOAP for key export. Files in /var/run/key_mgmt increase the size of one section of the qkview file causing iHealth to fail processing. F5 is tracking this under Bug ID1013649.

Recommended Actions

Clean up the files on the BIG-IP by removing the files in /var/run/key_mgmt, for example from the bash command line:

  rm /var/run/key_mgmt/*

Note : The solution above will enable you to regenerate a new qkview. Below are other methods to implement on existing qkviews. 

If you already have the qkview you may be able to extract it and remove those files and then re-create it on a linux machine.

 

  1. First create a folder: mkdir qkview
  2. Then copy the file into that folder: cp name_of_qkview.tgz /qkview/name_of_qkview.tgz
  3. Now change directory to the folder cd /qkview 
  4. Extract the contents: tar -xvzf name_of_qkview.tg
  5. Remove the files: rm -rf ./var/run/key_mgmt/*
  6. Now proc_module.xml needs to be edited to remove references to the files:
  7. Open the file with vi proc_module.xml and run this command -  :g/^ <file name=\".*\" filepath=\"\/var\/run\/key_mgmt/,/<\/file>/d
    • Alternatively, You can use this command and sed (likely takes longer): sed -i '/^ <file name=\".*\" filepath=\"\/var\/run\/key_mgmt/,/<\/file>/d' proc_module.xml
  8. Now verify that the proc_module.xml file is good still by running xmllint proc_module.xml
    • If it is good no errors will be returned
  9. Tar everything back up from within the qkview folder (this will put it one folder up): tar -czvf ../new_qkview.tgz *
  10. Post the new_qkview.tgz to ihealth???????
