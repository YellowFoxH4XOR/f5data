Known Issue

The Configuration utility erroneously allows you to import a duplicated FIPS key.

This issue occurs when all of the following conditions are met:

  • You import the FIPS key using the Configuration utility.
  • The same FIPS key already exists in the BIG-IP system configuration.

Impact

Duplicated keys imported into the system may result in inconsistencies in the configuration, due to the different FIPS handle on the duplicated keys.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You may find the same FIPS keys with a different FIPS handle number when displaying the imported FIPS keys using the tmsh show sys crypto fips command.
  • In a high availability (HA) deployment, both units may display a different FIPS handle number for the same key.

Resolution

Status

F5 Product Development has assigned ID 412790 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of the article. For information about releases or hotfixes that resolve this issue, refer to the following table.

Workaround

There is no workaround for this issue. F5 recommends that you avoid using the Configuration utility to import a FIPS key when using the affected versions.

For information about managing FIPS keys using the Traffic Management Shell (tmsh), refer to the About managing FIPS keys using tmsh chapter of the BIG-IP Platform FIPS Administration guide.
