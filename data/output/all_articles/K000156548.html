Description

During normal operation on an SSLO unit, an error similar to the below may be logged in the /var/log/ltm file:

 

err tmm2[25236]: 01c80018:3: CONNECTOR: Listener=/Common/vs_test, Profile=/Common/ssloS_test_ipv6.app/ssloS_test_ipv6-t-6-connector: Error forwarding event HUDCTL_XOFF to return virtual server (null) - ERR_CONN

 

This error in itself is not a cause for alarm, although an explanation of it (given in this article) may help an admin determine if it is related to an actual failure or something benign.

 

Environment

BIG-IP SSLO

 

Cause

HUDCTL_XOFF is an internal setting which can be set to true or false automatically during normal operation of a Big-IP, and it is used to pause or resume the ingress flow to a VS internally on the Big-IP.

For the error message given as an example above, ERR_CONN (connection error / connection closed or reset) has already occurred on this chain, and hence the return virtual server is "null", and so we are getting ERR_CONN when we try to send a HUDCTL_XOFF to pause the ingress flow to this object (ssloS_test_ipv6-t-6-connector) from whatever virtual server was on the other side (which is now null because the other side of the connection has already been closed).

 

Recommended Actions

From the above, this message should not be a cause for concern in itself, unless the admin has some reason to believe that the other side of the connection should not have been closed at that point - for example, if clients are seeing unexpectedly reset or closed connections without full data being received, etc. The expectation here in the absence of such reports is that these connections were closed as per usual operation on the other side.

However if the admin has seen problems with their client connections, then a pcap showing the unexpected reset/close on the connection should be investigated as per usual procedures.
