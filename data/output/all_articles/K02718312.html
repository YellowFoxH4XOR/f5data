Description

When attempting to delete a partition, the similar to below error message is seen in GUI or /var/log/ltm and can not be deleted:

0107082a:3: All objects must be removed from a partition (<partition_name>) before the partition may be removed, type ID (<ID>)

Environment

  • BIG-IP 
  • Partitions
  • Delete

Cause

  • You have network object configured for the partition (vlan, self IP etc)

or

  • The error is due to orphaned objects still reference to the partition.

Recommended Actions

  • Check if there is any network object left in the partition you want to delete on GUI.

e.g. on CLI

cat /config/paritions/<partition_name>/bigip_base.conf

 

  • Check if the /config/partitions/<partition_name>/bigip.conf has only this entry
#TMSH-VERSION: 17.1.1.1

apm client-packaging /<partition_name>/client-packaging { }
apm resource sandbox /<partition_name>/citrix-client-package {
    ...
}
apm resource sandbox /<partition_name>/hosted-content {
    ...
}

And your BIG-IP version is 13.0.0 and later, then this entry does not affect to delete the partition, leave it.

If your BIG-IP version is older than 13.0.0, please check workaround 

    • K42807763: Deleting a BIG-IP partition may fail

 

  • To workaround for the other orphaned objects.
  1. Log in to the BIG-IP command line.
  2. Move the partition folder that you want to delete to a temporary backup location like /shared/tmp.
For example, run the following command:
mv /config/partitions/<PARTITION_NAME> /shared/tmp
 
  1. Edit bigip_base.conf file using the VI editor:

(1) Backup current configuration file:

cp -a /config/bigip.conf /config/bigip.conf_backup
 

(2) Comment out the following sections related to the partition name in the /config/bigip_base.conf file using the VI editor:

auth partition PARTITION_NAME {
}
sys folder /PARTITION_NAME {
    device-group /Common/your-device-group
    hidden false
    inherited-devicegroup true
    inherited-traffic-group true
    traffic-group /Common/your-traffic-group
}

to

# auth partition PARTITION_NAME {
# }
# sys folder /PARTITION_NAME {
#     device-group /Common/your-device-group
#     hidden false
#     inherited-devicegroup true
#     inherited-traffic-group true
#     traffic-group /Common/your-traffic-group
# }
 

(3) Search the file for any other references to the named partition folder and comment out those references.

(4) Save changes in the VI editor by typing the below and press [Entre] key:

:wq!
 
  1. Verify the system configuration by typing the following command:
tmsh load sys config verify
Note: If you missed a reference to the moved partition folder in /config/bigip_base.conf, this command will throw an error and indicate what reference you missed. Go back and edit the /config/bigip_base.conf file to remove that reference. Save the file after making new changes, and run the tmsh load sys config verify command. Repeat this process until no missing references are found. Warning can be safely ignored.


       5. Reload the system configuration by typing the following command:


tmsh load sys config
Note: Performing a configuration reload on an active device group member may cause a service disruption of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.
 

        6. The partition should be gone after refreshing the configuration utility website.,
