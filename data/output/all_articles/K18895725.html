Description

Getting error messages logged about  /appdata  having low free space in /var/log/ltm:

err diskmonitor[3380]: 011d0004:3: Disk partition /appdata has only XX% free

Environment

  • VCMP Host
  • /appdata partition

Cause

In some versions guest disk images may be stored in /appdata causing the /appdata partition to fill.

 

Recommended Actions


Free up disk space

  • In the vCMP host check if any templates are defined. Delete as many as possible.
  • Delete any unused vCMP guests and delete their disk images.
  • Migrate Guests to other environments to free space.
  • Create Guest UCS and deploy new Guest and restore UCS, see link in Related Content below

Increase disk space

Increasing the size of the appdata volume with the lvextend utility. For additional information, please refer to K13355459

Recover disk space

  • Create a UCS backup from each vcmp guest, then delete, recreate and deploy new guests and restore the configuration from UCS on each guest. This allows the new vmdisks volumes to be recreated using less disk space. Refer to K000140235
  • Delete any unused vCMP guests and delete their disk images.
  • Migrate Guests to other environments to free space.Increasing the size of the appdata volume with the lvextend utility

 

 

 

Additional Information

There is no ability to shrink guest disk images, you can only delete the virtual disk and create a new one.
Upgrading a guest will cause the disk image to expand as the new boot location will acquire space.
