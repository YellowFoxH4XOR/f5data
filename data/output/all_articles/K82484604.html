Known Issue

The Traffic Management Microkernel (TMM) may restart on the standby BIG-IP system when processing mirrored connections.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is part of a high availability (HA) group.
  • Your BIG-IP system uses a FastL4 virtual server with connection mirroring enabled.
  • The Auto Last Hop feature is disabled (globally or for the specific virtual server).

Impact

The standby BIG-IP system is unavailable for failover events while the TMM process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The standby BIG-IP system temporarily becomes unavailable as it recovers from a TMM restart.
  • Your BIG-IP system generates a TMM core file to the /shared/core/ directory.

Workaround

To work around this issue, you can enable the Auto Last Hop feature for the affected FastL4 virtual server. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To enable the Auto Last Hop feature on the virtual server, use the following command syntax:

    modify /ltm virtual <virtual_server_name> auto-lasthop enabled

    For example, to enable the Auto Last Hop feature on virtual server vs_1, type the following command:

    modify /ltm virtual vs_1 auto-lasthop enabled

  3. Save the change by typing the following command:

    save /sys config
