Topic

You should consider using this procedure under the following conditions:

  • You want to create a custom local traffic profile using the TMOS Shell (tmsh) from the command line of the BIG-IP system.
  • You want to apply a custom profile to a virtual server using tmsh from the command line of the BIG-IP system.

Description

Local traffic profiles are configuration objects that contain configurable properties for controlling the behavior of a particular type of network traffic, such as HTTP requests and responses. You can create custom profiles using tmsh from the BIG-IP command line. A custom profile is a profile that is derived from a parent profile that you specify. A parent profile is a profile from which your custom profile inherits its settings and their default values. The BIG-IP system includes a default parent profile for each profile type that you can use when you create custom profiles. You can also use a custom profile as a parent profile for other profiles you create. When you have completed configuring your custom profile, you apply it to a virtual server that then processes traffic according to the property settings in the profile.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have administrative access to the BIG-IP command line or tmsh.

Procedures

  • Get help from tmsh
  • Create a custom profile
  • Apply custom profiles to a virtual server when you need to replace existing profiles
  • Apply custom profiles to a virtual server when you don't need to replace existing profiles
  • Delete a custom profile

Get help from tmsh

When creating a profile from tmsh you can use the tab key to see the next available option, including if an open brace or close brace is necessary.

For example:

# create ltm profile http example_http_profile <tab>
Properties:
  accept-xff    description    fallback-status-codes    lws-separator    proxy-type    response-headers-permitted   via-response                 

Note: Output is truncated.

Or

# create ltm profile http example_http_profile insert-xforwarded-for enabled server-agent-name "server01" enforcement <tab>
Properties:
{

Use a question mark (?) to see descriptions of each of the properties.

For example:

# create ltm profile http example_http_profile insert-xforwarded-for enabled server-agent-name "server01" enforcement { ?
Properties:
"}" Close the left brace
excess-client-headers Specifies the behavior when too many client headers are received. If enabled, will switch to pass through mode instead of rejecting the connection.
excess-server-headers Specifies the behavior when too many server headers are received. If enabled, will switch to pass through mode instead of rejecting the connection.

Note: Output is truncated.

For more information about tmsh help, refer to K20393414: Using the tmsh Help feature.

Create a custom profile

Create a custom local traffic profile to control the behavior of a particular type of network traffic.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create a profile by using the following syntax:

    create /ltm profile <type> <name> [<property> <value>] [<additional properties and values>]

    For example:

    • create /ltm profile one-connect example_oneconnect_profile limit-type idle max-age 172800 max-reuse 500 source-mask 255.0.0.0
    • create /ltm profile http example_http_profile insert-xforwarded-for enabled server-agent-name "server01" enforcement { max-header-count 32 }

    Note: Properties that you do not specify will take the default value from the parent profile. If you do not want to use the default parent profile, you can specify a custom profile with the defaults-from property.

  3. Save the configuration change to disk by entering the following command:

    save /sys config

Apply custom profiles to a virtual server when you need to replace existing profiles

Once you have configured your custom profile, put it into operation by adding it to a virtual server. Use the following procedure when any profile needs to be replaced when you're applying new profiles.

Impact of procedure: The impact of the following procedure depends on the changes you apply through the local traffic profile. Always ensure modifications are compatible with your environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Remove any duplicate profile types before adding a new profile. For example, if the virtual server already has an HTTP profile, you need to remove it before you add a new HTTP profile. To avoid errors when a profile has dependencies, make the changes in batch mode. Use the following syntax to create a transaction and enter into batch mode:

    Note: You can use the replace-all-with option instead of making changes in batch mode, but you need to specify all existing profiles you want to keep and the new profiles you want to add.

    create /cli transaction

    The command line displays [batch mode]

    Note: You can get help by entering the command help /cli transaction.

  3. Add a command to the transaction to remove the profiles you want to replace. To do so, use the following syntax:

    modify /ltm virtual <virtual name> { profiles delete { <profile name> }}

    For example:

    modify /ltm virtual example_vs { profiles delete { http }}

    If you want to remove multiple profiles, use the following syntax:

    modify /ltm virtual <virtual name> { profiles delete { <profile name 1> [<additional space delimited profiles>]}} 

    For example:

    modify /ltm virtual example_vs { profiles delete { http oneconnect }}

  4. Add the profiles to a virtual server by using the following syntax:

    modify /ltm virtual <virtual name> { profiles add { <profile name> }}

    For example:

    modify /ltm virtual example_vs { profiles add { example_http_profile }}

    If you want to add multiple profiles to a virtual server, use the following syntax:

    modify /ltm virtual <virtual name> { profiles add { <profile name 1> [<additional space delimited profiles>]}}

    For example:

    modify /ltm virtual example_vs { profiles add { example_http_profile example_oneconnect_profile }}

  5. (Optional) Review the commands in the transaction by entering the following command:

    list /cli transaction

  6. Submit the transaction by entering the following command:

    submit /cli transaction

  7. Save the configuration change to disk by entering the following command:

    save /sys config

Apply custom profiles to a virtual server when you don't need to replace existing profiles

Once you have configured your custom profile, put it into operation by adding it to a virtual server. Use the following procedure when no profiles need to be replaced when you're applying new profiles.

Impact of procedure: The impact of the following procedure depends on the changes you apply through the local traffic profile. Always ensure modifications are compatible with your environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Add the profiles to a virtual server by using the following syntax:

    modify /ltm virtual <virtual name> { profiles add { <profile name> }}

    For example:

    modify /ltm virtual example_vs { profiles add { example_http_profile }}

    If you want to add multiple profiles to a virtual server, use the following syntax:

    modify /ltm virtual <virtual name> { profiles add { <profile name 1> [<additional space delimited profiles>]}}

    For example:

    modify /ltm virtual example_vs { profiles add { example_http_profile example_oneconnect_profile }}

  3. Save the configuration change to disk by entering the following command:

    save /sys config

Delete a custom profile

You can delete a local traffic profile when it becomes obsolete or you no longer use it. Before you can delete a profile, you first need to dissociate it from its virtual server.

Impact of procedure: When you save the changes, the profile you delete is permanently removed from the configuration and is only recoverable from a configuration file backup or a UCS backup.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Delete a profile by using the following syntax:

    delete /ltm profile <type> <profile name>

    For example:

    delete /ltm profile http example_http_profile

  3. Save the configuration change to disk by entering the following command:

    save /sys config
