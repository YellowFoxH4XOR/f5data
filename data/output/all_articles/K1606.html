Topic

You can use SNMP to monitor file system partitions for a minimum amount of available disk space. Additionally, you can use SNMP to ensure processes have at least a minimum number of instances running, and do not exceed a maximum number of instances running.

To verify the file system partitions and processes being monitored by SNMP on your specific version of BIG-IP, you can view the /etc/snmpd.conf file. You will find entries similar to the following example:

proc    bigd 1 1
proc    cron 1 1
proc    init 1 1
proc    syslogd 1 1
proc    sshd
proc    sod 1 1
proc    big3d 1 1
proc    ITCMPortal      1 1
proc    LocalLBServer   1 1
proc    ITCMSystemServer        1 1
proc    ITCMManagementSe        1 1
proc    ITCMNetworkingSe        1 1
# Check mount points for free disk space
# not check disk /usr because
# switch box doesn't have /usr partition in /etc/fstab,
# ucd code complains.
disk / 2000
disk /var 10000

You can configure SNMP to monitor additional hard drive partitions or processes for information.

Monitoring partition information

To configure SNMP to monitor additional file system partitions, such as /config, perform the following procedure:

Important: Only configure SNMP to monitor file systems defined in the /etc/fstab file.

  1. Log in to the BIG-IP command line.
  2. Edit the /etc/snmpd.conf file.
  3. Add an entry to the file system section of the file, using a numeric value equal to the amount of KB of free space expected in the partitions. The entry will look similar to the following:

    disk /config 100

  4. Save the /etc/snmpd.conf file.
  5. Restart the SNMP daemon, by typing the following command:

    bigstart restart snmpd

After you restart SNMP to implement the changes, SNMP will provide partition information similar to the following example:

.1.3.6.1.4.1.2021.9.1.1.1 = 1
.1.3.6.1.4.1.2021.9.1.1.2 = 2
.1.3.6.1.4.1.2021.9.1.1.3 = 3
.1.3.6.1.4.1.2021.9.1.2.1 = /
.1.3.6.1.4.1.2021.9.1.2.2 = /var
.1.3.6.1.4.1.2021.9.1.2.3 = /config 
enterprises.ucdavis.dskTable.dskEntry.dskPath.1 = / 
enterprises.ucdavis.dskTable.dskEntry.dskPath.2 = /var
enterprises.ucdavis.dskTable.dskEntry.dskPath.3 = /config
enterprises.ucdavis.dskTable.dskEntry.dskDevice.1 = /dev/wd0a
enterprises.ucdavis.dskTable.dskEntry.dskDevice.2 = /dev/wd0g
enterprises.ucdavis.dskTable.dskEntry.dskDevice.3 = /dev/wd0f
enterprises.ucdavis.dskTable.dskEntry.dskMinimum.1 = 2000
enterprises.ucdavis.dskTable.dskEntry.dskMinimum.2 = 10000
enterprises.ucdavis.dskTable.dskEntry.dskMinimum.3 = 100

Process information

You can configure SNMP to monitor an additional process, such as /httpd, by performing the following procedure:

  1. Log in to the BIG-IP command line.
  2. Edit the /etc/snmpd.conf file.
  3. Add an entry to the process section, by typing the following syntax:

    proc <daemon> <max> <min>

    Replace <daemon> with the process to be monitored, such as httpd. Replace <max> with the maximum number of instances expected for that process. Replace <min> with the minimum number of instances expected for that process.

    For example, to monitor for the httpd daemon to ensure at least one instance and not more than ten instances are present, the entry would appear as follows:

    proc httpd 10 1

  4. Save the /etc/snmpd.conf file.
  5. Restart the SNMP daemon, by typing the following command:

    bigstart restart snmpd

After you restart SNMP to implement the changes, SNMP will provide process information similar to the following example:

enterprises.ucdavis.prTable.prEntry.prNames.1 = bigd
enterprises.ucdavis.prTable.prEntry.prNames.2 = cron
enterprises.ucdavis.prTable.prEntry.prNames.3 = init
enterprises.ucdavis.prTable.prEntry.prNames.4 = syslogd
enterprises.ucdavis.prTable.prEntry.prNames.5 = bigdnode
enterprises.ucdavis.prTable.prEntry.prNames.6 = sshd
enterprises.ucdavis.prTable.prEntry.prNames.7 = sod
enterprises.ucdavis.prTable.prEntry.prNames.8 = bigsnmpd
enterprises.ucdavis.prTable.prEntry.prNames.9 = big3d
