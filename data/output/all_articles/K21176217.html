Description

Failover script is not being executed when moving BIG-IP virtual address from traffic-group-1 to traffic-group-2 or other way around. Because of this issue, application traffic does not resume after the virtual address is moved from one traffic-group to another.


Environment 

  • Two BIG-IP VMs in an Active/Active configuration running in MS Azure or GCP
  • BIG-IP HA cluster (Active/Active) was deployed from one of the following templates:
  1. MS Azure (template version v7.3.0.0 or below): https://github.com/F5Networks/f5-azure-arm-templates/tree/v7.3.0.0/supported/failover/same-net/via-api/n-nic/existing-stack/byol
  2. GCP (template version v3.3.0 or below): https://github.com/F5Networks/f5-google-gdm-templates/tree/v3.3.0/supported/failover/same-net/via-api/3nic/existing-stack/byol
  • BIG-IP systems are members of a sync-failover device group
  • Two traffic groups are configured and virtual addresses are distributed between traffic-group-1 and traffic-group-2 on BIG-IP
  • Failover script (called failoverProvider.js in Azure and failover.js in GCP) which comes with f5-cloud-libs package is used to remap secondary IP(s) to external NIC of Active BIG-IP. Cloud Failover Extension (CFE) is not installed/configured on BIG-IP.


Cause

ID868701 - virtual address does not get mapped correctly when virtual server is moved from one traffic-group to another


Recommended Actions

None
