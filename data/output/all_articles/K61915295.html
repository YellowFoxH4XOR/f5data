Description

BIG-IP Not Caching Files/Objects with Query String Parameters

  • Files with query strings are not getting cached (ex: jquery.js?version=203).
  • "show ltm profile ramcache <web-acceleartion-profile-name>" doesn't show the file to be cache

Environment

  • BIG-IP LTM
  • Virtual server with web acceleration profile with include filters
  • Other files without query string parameters are getting cached but files with query string parameters are not getting cached.

Cause

There are two possible causes:

  1. Due to incorrect Regex match specified in include filter.
  2. Due to the presence of "cache-control: no-cache" header from the back-end server.

Recommended Actions

    Solution for Cause - 1:

    BIG-IP uses POSIX based RegEx. Make sure the query entered is POSIX RegEx compliant.

    For caching files including query strings, the filter should be something like:
    /path/jquery.js?version=203 -> .*jquery\.js.+ (this will cache files with any js file with query string parameter)
    /path/jquery.js?version=203 -> .*jquery\.js.* (this will cache files with any js file with or without query string parameter)

    After configuring, access the file and then check using "show ltm profile ramcache <web-acceleartion-profile-name>" if the file is cached in ramcache.

      Solution for Cause - 2: If the resource which is configured to be cached, is deemed non cachable, i.e., the back-end server is responding with "cache-control: no-cache" along with the resource. In this case, BIG-IP won't cache this, which is expected. If needs to be cached, modify the back-end doesn't have "cache-control: no-cache" in it's response.
