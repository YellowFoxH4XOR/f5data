Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when the Verified Accept option is enabled on a customized TCP profile.

This issue occurs when the following conditions are met:

  • The virtual server uses a customized TCP profile with the Verified Accept option enabled.
  • Out of order TCP events occur with the connections of the affected virtual server in one of the following two situations:

    • The three-way handshake completes with a FIN/ACK instead of an ACK.
    • The sequence number on the final ACK of the three-way handshake is not validated, and an invalid sequence number is accepted.

When the three-way handshake is completed with a FIN/ACK instead of an ACK, subsequent connections to that virtual server will fail. If the sequence number on the final ACK of the three-way handshake is not validated, and an invalid sequence number is accepted, TMM might produce a core file.

Impact

The connections to the affected virtual server will fail. Additionally, TMM might produce a core file, causing the BIG-IP system, if configured as part of a high availability (HA) system, to temporarily fail to process traffic and fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H425794 on the Diagnostics > Identified > Medium screen.
  • The subsequent connections to that virtual server will fail.
  • TMM may produce a core file, and your BIG-IP system may temporarily fail to process traffic and fail over.
