Known Issue

An Identity Provider (IdP)-initiated Security Assertion Markup Language (SAML) connection on a BIG-IP APM system may fail with an HTTP 404 response.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as an SAML IdP.
  • A portal access resource for SharePoint is configured for paths /*.
  • The SharePoint portal access resource is configured for SSO.
  • The user accesses the SharePoint portal access resource before initiating the SAML IdP connection.

Impact

The SAML IdP-initiated connection from the BIG-IP APM system is sent to the incorrect back-end resource causing the authentication to fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • SAML IdP-initiated connections fail when a Portal Access connection for SharePoint is open.
  • The end user receives a 404 Not Found page.

Workaround

To work around this issue, you can view disable SSO from the portal access application for SharePoint. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will disable SSO functionality for your SharePoint application.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Portal Access.
  3. From the Portal Access List, click the portal access name for SharePoint.
  4. In the Resource Items section of the portal access for SharePoint, click the item with path "/*".
  5. In the Resource Item Properties, for the SSO Configuration, select None from the menu.
  6. Click Update.
