Description

You can observe issues with loading of Configuration Utility (Graphical User Interface) on your BIG-IP unit. This article will include initial troubleshooting steps to identify root cause and possibly find a solution to the problem you are experiencing. Below article will present troubleshooting steps and log files where you may find evidence and root cause of GUI loading issues, with examples of most known issues. 
Perform the following troubleshooting steps to try and diagnose the problem. If you need assistance with investigation, please collect data requested in Additional Information section and share results for F5 Support verification.

Environment

  • BIG-IP
  • BIG-IP VE
  • Configuration Utility / GUI
  • Failing GUI display screen can be seen as:
    • A complete lack of access to the device login page,
    • Sluggish responsiveness,
    • Whole or partial loading components issues, like in example below:

Cause

Multiple possible causes exist, further analysis required.

Recommended Actions

You can use the following steps to troubleshoot GUI issues:

  • Confirm communication with BIG-IP Web Server
  • Restart and verify status of GUI related daemons
  • Verification of /tomcat/catalina.out log file
    • Known issues which you can find in /tomcat/catalina.out
  • Verification of /httpd/httpd_errors log file
    • K​​​nown issues which you can find in /httpd/httpd_errors
  • Additional known problems with displaying GUI

Confirm communication with BIG-IP Web Server

Collect traffic filtering it for management connection, review if proper communication is established and there are no huge delays within communication between client and BIG-IPs management. For such packet capture you can use below CLI command template:
tcpdump -nni mgmt -s0 -vw /var/tmp/<file_name>.pcap host <BIG-IP_management_communication_IP> and port 443

For example:
tcpdump -nni mgmt -s0 -vw /var/tmp/K000133532.pcap host 10.0.0.10 and port 443

Note: Such generated file will be created in /var/tmp/ directory and possible to be downloaded using eg. WinSCP application.
 

Restart and verify status of GUI related daemons

Impact of procedure: Performing the following procedure should not have a negative impact on your services configured on BIG-IP unit. GUI will be restarted during this activity.

  • Restart httpd and tomcat daemons

bigstart restart httpd tomcat

  • Verify status of restart daemons and check BIG-IPs GUI responsibility

bigstart status httpd tomcat

Verification of /tomcat/catalina.out log file and known issues which can be found

Search potential failure logs during time when GUI wasn't fully responsive in /var/log/tomcat/catalina.out file.
If issue can be still reproduced on your machine we suggest to follow below steps to review potential logs from that location:

  • Log into the BIG-IP Advanced shell (bash)
  • Use below command to monitor and instantly display any new log lines which are going to appear:

tail -f /var/log/tomcat/catalina.out

  • Log into BIG-IP Configuration Utility (GUI) and reproduce issue which you observe
  • Check CLI log lines which appeared during reproduced steps

Note: You can stop the "tail -f" command by pressing "Ctrl+C" on your keyboard.
 

Known issues which you can find in /tomcat/catalina.out

  • Out of memory issue on BIG-IP:

You will be able to find below log entries which contains phrases about OutOfMemoryError similar to example provided below:

# java.lang.OutOfMemoryError: Java heap space
# -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat"
# Executing /bin/sh -c "/usr/bin/restart_tomcat"

Verification of /httpd/httpd_errors log file

Similarly to previous log file, to check potential failure logs during time when GUI isn't fully responsive you may search a reason for that in /var/log/httpd/httpd_errors file.
If issue can be still reproduced on your machine we suggest to follow below steps to review potential logs from that location:

  • Log into the BIG-IP Advanced shell (bash)
  • Use below command to monitor and instantly display any new log lines which are going to appear:

tail -f /var/log/httpd/httpd_errors

  • Log into BIG-IP Configuration Utility (GUI) and reproduce issue which you observe
  • Check CLI log lines which appeared during reproduced steps

Note: You can stop the "tail -f" command by pressing "Ctrl+C" on your keyboard.

Issue described in below article:
K31094581: LTM GUI sluggish and showing a blank page

The "Child runner thread was interrupted" log can also be caused by allocating the same amount of extra memory to provision.restjavad.extramb and provision.extramb. The extra memory needed to interface with the GUI can intermittently be used up by restjavad during peak usage. 

"Increases above the default size do require sys db provision.extramb to be at least the size of the increment. An alternative way of looking at that is you can have the value of provision.extramb you need and size restjavad memory size so as not to use all that extra host memory."

When assigning a new value to provision.extramb, perform on the Standby unit to prevent disruptions to traffic while BIG-IP services are restarted.

K000133258: Provisioning restjavad memory with provision.restjavad.extramb
