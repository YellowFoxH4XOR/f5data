Known Issue

The BIG-IP system may fail to create a self IP address.

This issue occurs when all of the following conditions are met:

  • You use the Traffic Management Shell (tmsh) to create a self IP address and save it to a single configuration file (SCF).
  • You use tmsh to delete the self IP address and recreate a self IP address with the same name but a different IP address.
  • You load the saved SCF file, delete the self IP address, and then attempt to recreate the self IP using tmsh.

After you load the SCF, you may also observe that the incorrect self IP route is configured in the Linux kernel route table. This situation is a result of deleting the original self IP address and recreating it with a different IP address, and not saving it to the SCF.

For example:

  • The SCF is saved with the self IP address 10.10.10.1.
  • You delete the self IP address and recreate it using the same name but with the address of 10.10.10.2.
  • You load the SCF.
  • The BIG-IP system does not display the following expected route entry in the route table:

        # ip route
            ..
        10.10.10.0/24 dev internal  proto kernel  scope link  src 10.10.10.2
            ..

Impact

You are unable to create a self IP address using tmsh.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe an error message when you attempt to use tmsh to create a self IP address with a different IP address after you load the SCF.

    For example, the following tmsh command attempts to create a self IP address with a different IP address than the self IP address in the SCF file:

    tmsh create net self internal address 10.10.10.2/24 traffic-group traffic-group-local-only vlan internal allow-service default

    Output appears similar to the following:

    01070712:3: Cannot create IP address 10.10.10.2/24 in vlan 'internal' in rd0 - netlink error: 17 (File exists)

  • After you load the SCF, you may observe an incorrect self IP route entry (a self IP route that is different from the SCF self IP address) in the Linux kernel route table for the route that is in the running configuration.

Workaround

To work around this issue, you can restart the mcpd process. To do so, perform the following procedure:

Impact of workaround: The bigstart restart command temporarily interrupts traffic processing, and you should perform the command during a maintenance window.

  1. Log in to the BIG-IP command line.
  2. Restart the mcpd process by typing the following command:

    bigstart restart mcpd

    The system displays output similar to the following example:

    # bigstart restart mcpd
    emerg logger: Re-starting merged
    emerg logger: Re-starting lind
    emerg logger: Re-starting statsd
    .....

  3. Create the self IP address you want by using the following command syntax:

    tmsh create /net self <self_ip> address <mask> allow-service default vlan <vlan>

    For example:

    tmsh create net self internal address 10.10.10.2/24 allow-service default vlan internal

  4. Save the SCF file by using the following command syntax:

    tmsh save /sys config file <filename>

Alternatively, you can mitigate this issue by using the following procedure before loading the SCF.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Type the following command:

    delete net self <self_name>

    For example:

    delete net self internal

  3. Use the following command syntax from the Linux kernel shell:

    ip addr delete <IpAddress>/<netmask> dev <vlan_name>.

    For example:

    ip addr delete 10.10.10.2/24 dev internal

  4. Load the SCF by typing the following command:

    load sys scf <SCF_filename>
