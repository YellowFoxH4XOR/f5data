Known Issue

This is the result of a known issue. The iRule reject command is not honored when used in conjunction with a virtual server using a FastL4 profile.

If an iRule that is configured with a virtual server using the FastL4 profile contains the reject command, FastL4 will not issue a reset to the client when the reject command is executed. As a result, the client connection may be maintained until the idle connection timer removes the client's connection.

F5 Product Development tracked this issue as CR72171and CR72172, and it was fixed in BIG -IP versions 9.1.3 and 9.3.0. For information about upgrading, refer to the BIG-IP LTM release notes.

F5 Product Development is tracking this issue as CR72170 for the BIG-IP LTM 9.4 software branch.
