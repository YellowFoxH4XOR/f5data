Known Issue

The BIG-IP system may not properly update a congestion metrics cache entry when the path maximum transmission unit (MTU) value changes.

This issue occurs when all of the following conditions are met:

  • You have a TCP profile applied to a virtual server with the Congestion Metrics Cache setting enabled.
  • The BIG-IP system receives an Internet Control Message Protocol (ICMP) message indicating a path MTU value change for an existing congestion metrics cache entry.

The BIG-IP erases only the congestion window (cwnd) and bandwidth values in an entry when the path MTU changes. This may result in the BIG-IP system using invalid TCP metrics for congestion control on a subsequent connection.

Impact

The BIG-IP system may delay data transmission during the next TCP connection.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When you run the Traffic Management Shell command tmsh show net cmetrics, you observe in the output that after the path MTU value changes, the bandwidth value changes to 0 (zero).

    For example:

    
# tmsh show net cmetrics
Net::RouteMetric
Destination IP  HWaddress        TMM  rtt      rttvar   ssthresh    bandwidth  MTU
10.1.1.1        0:50:56:1:6e:15  0    2149992  2353750  1103142000  2438       0
Total records returned: 1

# tmsh show net cmetrics
Net::RouteMetric
Destination IP  HWaddress        TMM  rtt      rttvar   ssthresh    bandwidth  MTU
10.1.1.1        0:50:56:1:6e:15  0    2149992  2353750  1103142000  0          1200
Total records returned: 1
  • The iRule commands ROUTE::cwnd and ROUTE::bandwidth show 0 (zero) as their values when you use them within a connection-closed iRule event after the path MTU changes.
