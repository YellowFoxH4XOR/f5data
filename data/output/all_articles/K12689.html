Known Issue

This is the result of a known issue. The LCD panel fails to update the configuration of the management interface when a non-default management route is present. This occurs, for example, when the following configuration is in place:

mgmt 172.16.1.1 {
netmask 255.255.255.0
}
mgmt route 10.0.0.0/24 { # this is a non-default management route
gateway 172.16.1.100
}
mgmt route default inet {
gateway 172.16.1.254
}

When you attempt to modify the IP address, network mask, or default gateway of the management interface by way of the LCD panel, the system does not accept your changes and continues to use the old settings.

F5 Product Development tracked this issue as ID 351722 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, GTM, Link Controller, WebAccelerator, or WOM release notes.

Workaround

If you have defined one or more non-default management routes, do not use the LCD panel to update the configuration of the management interface. Instead, use the Configuration utility, the bigpipe utility, the tmsh shell, or simply run the config command from the command line of the BIG-IP system and follow the on-screen instructions.
