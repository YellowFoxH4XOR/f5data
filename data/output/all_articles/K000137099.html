K000137099: ELK component certificate expired

Type
Support Solution
Published
2023-12-09
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.X, 5.1.0
Source
https://my.f5.com/manage/s/article/K000137099

Description

  • Regarding the certificate on ELK, it expired on 2023-Aug-30 for all SDC sites.
  • This problem will occur once the ELK component (Kibana, Fluentd, elastisearch_master, elasticsearch_data) restarts.
  • You can verify the certificate from this command openssl x509 -in <path_to_certificate> -text -noout | grep 'Issuer' -A 4
    • Certificate in salt-master path (both EMS and SDC)
      • Path: /srv/salt/<SDC_version>/elk/global/ca.crt
      • Command: openssl x509 -in /srv/salt/5.1_32-1/elk/global/ca.crt -text -noout | grep 'Issuer' -A 4
      • For example:

openssl x509 -in /srv/salt/5.1_32-1/elk/global/ca.crt -text -noout | grep 'Issuer' -A 4
Issuer: CN=Elastic Certificate Tool Autogenerated CA
Validity
Not Before: Sep 8 08:29:37 2023 GMT
Not After : Sep 5 08:29:37 2033 GMT
Subject: CN=Elastic Certificate Tool Autogenerated CA

  • certificate in the distributed path on EMS
    • Path:
      • /etc/pki/certs/ca.crt
      • /etc/elasticsearch/certs/
      • /etc/elasticsearch/elasticsearch_master/certs/
      • /etc/elasticsearch/elasticsearch_data/certs/
    • For example:

openssl x509 -in /etc/pki/certs/ca.crt -text -noout | grep 'Issuer' -A 4
Issuer: CN=Elastic Certificate Tool Autogenerated CA
Validity
Not Before: Sep 8 08:29:37 2023 GMT

Subject: CN=Elastic Certificate Tool Autogenerated CA

Environment

  • SDC
  • ELK


Cause

The SDC system default image was distributed by a software package, so the ELK certificate expired on 2023-Aug-30


Recommended Actions

Regenerate the self-sign certificate and apply it on EMS and SDC nodes

1. Backup current certificate  ***Both EMSs and SDC
Command:
cd /srv/salt/<version>/elk/global
mkdir orig
cp instance.* orig
cp ca.crt orig

Note: It will be better if you can keep the certificate out of the box

2. Generate a new certificate on EMS01 ***For EMS02 and SDC sites can copy the certificate from EMS01
Command:
mkdir /var/tmp/new_cert
cd /var/tmp/new_cert
openssl req -new -newkey rsa:4096 -nodes -text -out ca.csr -keyout ca.key -subj "/CN=Elastic Certificate Tool Autogenerated CA"
chmod og-rwx ca.key
openssl x509 -req -in ca.csr -text -days 3650 -extfile /etc/pki/tls/openssl.cnf -extensions v3_ca -signkey ca.key -out ca.crt
openssl req -new -newkey rsa:4096 -nodes -text -out instance.csr -keyout instance.key -subj "/CN=instance"
chmod og-rwx instance.key
openssl x509 -req -in instance.csr -text -days 3650 -CA ca.crt -CAkey ca.key -CAcreateserial -out instance.crt

3. Copy the certificate files from EMS01 to EMS02 and SDC sites to /srv/salt/<version>/elk/global/

4. Only EMS01, apply the salt configuration
Command: salt '*' state.highstate

5. Run the below command to verify the new files were successfully distributed on EMS01 and EMS02
Command:
ls -ltr /etc/pki/certs/
ls -ltr /etc/elasticsearch/elasticsearch_master/certs/
ls -ltr /etc/elasticsearch/elasticsearch_data/certs/

6. Restart ELK components (Fluent, Elasticsearch_master, Elasticsearch_data, Kibana) on EMS01 and EMS02
Command: monit restart <component_name>
