K28202455: Disable JDNI lookups for Traffix EMS ELK

Type
Support Solution
Published
2021-12-14
Updated
2023-02-21
Applies to
  • Traffix SDC: 5.2.X, 5.1.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K28202455

Description

From SDC (Signaling Delivery Controller)  5.1 CF30 and above, EMS (Element Management System) introduced ELK as a Splunk replacement. EMS ELK comprises three components called Fluentd, Elasticsearch and Kibana. Elasticsearch uses Log4j 2 for its logging framework. Log4j 2 added lookups feature, including JNDI lookups. JNDI lookups are not restricted, leading to possible vulnerability. EMS ELK does not use JNDI lookups and should be disabled to prevent exploit from JNDI lookups.

You may use the following steps to check if Log4j 2 is included in EMS ELK before apply the recommended actions.

  • rpm -qa | grep elasticsearch
Replace the correct elasticsearch version from above output.

rpm -ql elasticsearch-7.8.0-1.x86_64 | grep log4j 
/etc/elasticsearch/log4j2.properties
/usr/share/elasticsearch/lib/log4j-api-2.11.1.jar
/usr/share/elasticsearch/lib/log4j-core-2.11.1.jar
/usr/share/elasticsearch/modules/x-pack-core/log4j-1.2-api-2.11.1.jar
/usr/share/elasticsearch/modules/x-pack-identity-provider/log4j-slf4j-impl-2.11.1.jar
/usr/share/elasticsearch/modules/x-pack-security/log4j-slf4j-impl-2.11.1.jar

Environment

  • Traffix EMS 5.1 -CF30 and above

Cause

Elasticsearch component of EMS ELK uses Log4j 2 with lookups feature, such as JNDI lookups. An attacker can use this vulnerability to construct a specifically crafted packet and can lead to remote code execution.

Recommended Actions

Apply the following on EMS nodes.

  1. Add -Dlog4j2.formatMsgNoLookups=true to the following files
    • /etc/elasticsearch/elasticsearch_data/jvm.options
    • /etc/elasticsearch/elasticsearch_master/jvm.options
  2. Go to the above mentioned location
    • vi jvm.options
      ## JVM temporary directory
      -Djava.io.tmpdir=${ES_TMPDIR}
      -Dlog4j2.formatMsgNoLookups=true   <<------add this line
  3. Repeat the steps on second EMS node
  4. Remove Jndi Lookup class
Install zip package
  • salt '*' cmd.run 'yum -y install zip'
Search path of Elasticsearch Log4j 2 jar file
  • salt '*' cmd.run 'find / -name "*log4j-core*.jar" -type f | grep .jar'

emselk1-MmYxOGVkMzM5MTkyNzM3MWJjNGRlNzcz:
    /usr/share/elasticsearch/lib/log4j-core-2.11.1.jar
 
  • salt '*' cmd.run 'jar tvf /usr/share/elasticsearch/lib/log4j-core-2.11.1.jar | grep JndiLookup.class | wc -l'

emselk2-MmZhYjc5ZmI1OTkzMTEzYmMzMGFiZGM1:

    1

1 indicates Jndi class exists in the Log4j 2 jar file and run next command to remove it whilst 0 means Jndi class is removed or does not exist.
  • salt '*' cmd.run 'zip -q -d /usr/share/elasticsearch/lib/log4j-core-2.11.1.jar org/apache/logging/log4j/core/lookup/JndiLookup.class'
  • salt '*' cmd.run 'jar tvf /usr/share/elasticsearch/lib/log4j-core-2.11.1.jar | grep JndiLookup.class | wc -l'
  1. Restart both elasticsearch_master and elasticsearch_data on both EMS nodes
    • monit summary  
      Replace the "EMS_NodeName" as per the monit summary output
      monit restart <EMS_NodeName>_elasticsearch_data
      monit restart <EMS_NodeName>_elasticsearch_master
      monit summary
  2. Check the mitigation is added in the ELK process (on both elasticsearch_master and elasticsearch_data)
ps -ef | grep --color Dlog4j2.formatMsgNoLookups
