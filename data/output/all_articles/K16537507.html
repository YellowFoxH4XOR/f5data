K16537507: Utilization issue with disk partition /

Type
Support Solution
Published
2022-01-31
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.X, 5.1.0
Source
https://my.f5.com/manage/s/article/K16537507

Description

  • Utilization issue with disk partition /
  • Getting the alarm "This machine is using % of its disk partition /, which is above the defined "Critical" threshold of %. The previously measured percentage was %. The previous severity of this alarm was major."

Environment

  • SDC 5.x
  • Disk partition /

Cause

There are likely duplicate files in the directory of /tmp

Recommended Actions

  1. Identify the top 15 largest directories in /
    • du -ah /* | sort -rn | head -n 15
  2. Identify the top 15 largest files on the system
    • find / -type f -exec du -Sh {} + | sort -rh | head -n 15
  3. Check if the output of the above commands shows that /tmp and files in /tmp utilizing a lot of space. 
  4. Identify if those files are currently used by the system and check with the customer if they placed any large files in the /tmp folder. 
    • Example : 
    • 1.3G    /tmp/nms_site_f5sdc_ems/time_aggregated_statistics_peer_hour-b6d2397051c111ea985ca7977794b903/snapshots/SITENAME_08052020/lb-351378-big-Data.db
    • 1.3G    /tmp/nms_site_f5sdc_ems/prod_view_agg_statistics_peer_hour-9643b8a051c111eab67ff10c9bc0aff9/snapshots/SITENAME_08052020/lb-262880-big-Data.db
    • 1.2G    /tmp/nms_site_ems/prod_view_agg_statistics_peer_hour-b45c70405cbe11eab8666daaecc5222a/snapshots/SITENAME_08052020/lb-244636-big-Data.db
    • These files are cassandra sstable files and are not suppose to be kept in /tmp. These files are created when cassandra write the data in memory to files. It is also needed when the db performs db repair for compact/integrity checking. OAMdb data are kept in /data/cassandra. We suspect that these were added in /tmp by probably some action/s that was done unknowingly.
  5. Run "lsof" so that we can check if there is any running process that is using/opening this files in /tmp. 
    • Example : 
    • lsof /tmp/nms_site_f5sdc_ems/time_aggregated_statistics_peer_hour-b6d2397051c111ea985ca7977794b903/snapshots/SITENAME_08052020/lb-351378-big-Data.db
    • lsof /tmp/nms_site_f5sdc_ems/prod_view_agg_statistics_peer_hour-9643b8a051c111eab67ff10c9bc0aff9/snapshots/SITENAME_08052020/lb-262880-big-Data.db
    • lsof /tmp/nms_site_ems/prod_view_agg_statistics_peer_hour-b45c70405cbe11eab8666daaecc5222a/snapshots/SITENAME_08052020/lb-244636-big-Data.db
    • Note : If the output is blank or empty you can proceed to delete or remove these files. If there is a process running and using these files then please upload the result and a TTA for further checking.
  6. Delete the files from the /tmp folder that are not system generated and currently not used by any process in the system. 
    • Example : 
    • rm /tmp/nms_site_f5sdc_ems/time_aggregated_statistics_peer_hour-b6d2397051c111ea985ca7977794b903/snapshots/SITENAME_08052020/lb-351378-big-Data.db
    • rm /tmp/nms_site_f5sdc_ems/prod_view_agg_statistics_peer_hour-9643b8a051c111eab67ff10c9bc0aff9/snapshots/SITENAME_08052020/lb-262880-big-Data.db
    • rm /tmp/nms_site_ems/prod_view_agg_statistics_peer_hour-b45c70405cbe11eab8666daaecc5222a/snapshots/SITENAME_08052020/lb-244636-big-Data.db
