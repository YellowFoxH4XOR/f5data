Topic

This article applies to BIG-IP platforms with the embedded Packet Velocity Acceleration (ePVA) chip. For information about older BIG-IP platforms with the Packet Velocity ASIC (PVA) feature, refer to the following article:

  • K4832: Overview of PVA Acceleration

Description

The ePVA chip is a hardware acceleration Field Programmable Gate Array (FPGA) that delivers high-performance Layer 4 (L4) IPv4 throughput. The use of an FPGA allows the ePVA firmware to be updated, as required, for future upgrades and hotfixes. The ePVA chips are included on the following hardware platforms.

You can enable and configure ePVA through a FastL4 profile on a virtual server, or enable ePVA implicitly when you configure Address Translation (NAT/SNAT) in certain versions:

ePVA using a FastL4 profile

The FastL4 profile's PVA Acceleration option determines the ePVA mode. The options are:

  • Full - Both Full and Assisted modes operate in the same manner for ePVA.
  • Assisted - The system applies ePVA hardware acceleration for eligible connections after the connection has been established.
  • None - No connections are processed by the ePVA.
  • Dedicated - All TCP FastL4 connections are forced to be ePVA accelerated even when they become idle. This license feature option is used for the Financial Information eXchange (FIX) protocol.

    Note: For BIG-IP versions prior to 12.1.0 this setting is represented as Guaranteed.

The FastL4 profile's Offload State determines the TCP state at which the ePVA begins to process the connection. The options including the following:

  • SYN - The ePVA performs hardware offload at the first client SYN. It also performs the EST time snoop if the previous SYN time snoop fails.
  • EST - The ePVA performs hardware offload at the client ACK when in SYN/ACK state, when the connection is transitioning towards established.

Note: Even if SYN option is chosen, the offloading may be deferred until completion of the TCP three-way handshake based on internal algorithms for the pending embryonic connection.

ePVA acceleration eligibility

  • A connection flow is accelerated in hardware, based on connection establishment time.
  • IPv4 TCP connections can be accelerated.
  • IPv4 UDP connections can be accelerated (11.5.0 and later).
  • Virtual servers with or without secure network address translation (SNAT) enabled can be accelerated.
  • iRules commands operating on Layer 3 (L3) and L4 are accelerated.
  • Accelerated connection flows are evicted from ePVA when the connection is closed, and the TCP Close 4-way handshake is processed in software.
  • iRules that attempt to operate on Layer 7 (L7), or payload data, prevent acceleration with the exception of some FIX irules when Late Binding is enabled on a fastl4 profile.
  • IPv4 User Datagram Protocol (UDP) traffic prevents acceleration (10.2.2 - 11.4.1).
  • IPv6 TCP or UDP traffic prevents acceleration (10.2.2 - 11.5.x).
  • Virtual servers configured with a last hop pool that contains more than one member are not eligible for acceleration.
  • Virtual servers configured with auto last hop disabled and are configured with client-side dynamic routes (OSPF, BGP) are not eligible for acceleration.

ePVA can apply acceleration independently to either side of a connection. Therefore, connections may accelerate on both sides of the BIG-IP system, or the acceleration may be applied solely to the client- or server-side of a given connection.

You can determine the current ePVA status of a virtual server by using the TMOS Shell (tmsh). To do so, perform the following procedure:

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Display the statistics for a given virtual server by using the following command syntax:

    show ltm virtual <name of virtual server>

The ePVA Acceleration status is shown under the Status section of the output, similar to the following example:

PVA Acceleration : <status>

In the previous example, <status> can be one of the following:

  • Partial - ePVA Assisted mode
  • None - no ePVA assistance
  • Dedicated - ePVA Guaranteed mode

    Note: For BIG-IP versions prior to 12.1.0 this setting is represented as Guaranteed.

ePVA eviction policy

  • The ePVA no longer processes idle connections. In the event that the connections become active again, they become eligible for processing by the ePVA, dependent on the PVA Offload Dynamic setting.
  • The PVA Flow Evict setting in the FastL4 profile controls eviction behavior when new connections have hash collisions with existing ePVA accelerated connections. When hash collisions occur and the PVA Flow Evict setting is Enabled (default), the new connection is processed by the ePVA and the existing connection is evicted and processed by the Traffic Management Microkernel (TMM).  When the PVA Flow Evict setting is not enabled and hash collisions occur, TMM processes the new connection, and the ePVA continues to process the existing connection.

ePVA using Address Translation

Beginning in BIG-IP 11.5.1, NAT traffic processed without a virtual server is implicitly accelerated using Assisted (Embryonic) mode.

Beginning in BIG-IP 11.2.0, SNAT traffic processed without a virtual server is implicitly accelerated using Assisted (Embryonic) mode.
