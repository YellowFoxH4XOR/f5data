Description
Users get an error when trying to change their password via the APM.
Error Message:
The domain password change operation failed. Your new password must be more complex to meet domain password complexity requirements.

Environment

  • BIG-IP APM
  • Active Directory AD passwords
  • Password change not working

Cause
AD Auth/Query uses KPASSWD protocol to change the user password(s). Kerberos library may try to repeat UDP request or send a TCP request if it doesn't get a timely response. If the first packet is just delayed for some reason and finally reaches the backend server, then server gets two password change requests and replies with KRB5KRB_AP_ERR_REPEAT error back to the BIG-IP. The error code is returned to AD module by Kerberos library and Access policy fails.
Note: In some cases the password has been changed but the users still sees the error and therefore believes it has not been changed.

Recommended Actions

  1. First please confirm that the password meets domain password complexity requirements.
  2. Next you will want to confirm with tcpdump that the back-end server is sending KRB5KRB_AP_ERR_REPEAT
Solution 1: Block UDP traffic from BIG-IP to backend server on port 464 (KPASSWD) with a downsteam Firewall.
The problem can be worked around by blocking UDP traffic from BIG-IP to backend server on port 464 (KPASSWD) with a downsteam Firewall or on the AD servers themselves.
In this case Kerberos library switch to TCP right away and the password change succeeds.

Solution 2: For versions 14 or later iptables is no longer an option, Therefore as an alternative you can create a Virtual server and iRule to block the UDP 464 traffic from the Self IP address of the APM to your AD servers.
Steps to create the Virtual server:
  1. Login to the Webui
  2. Local Traffic  ››  Virtual Servers : Virtual Server List  ›› Click Create
  3. Name the Virtual Server: Block_udp_464
  4. Configure the Type to fastl4
  5. Configure the Source IP address to be your Self IP address
  6. Configure the Destination IP address to be your AD server
    Note: If you have multiple AD servers you can configure an Address List.
  7. Configure the Service Port: 464
  8. Configure the Protocol: UDP
  9. Click Update to save the Virtual Server
Steps to create Reject udp 464 irule:
  1. Login to the Webui
  2. Local Traffic > iRules
  3. Click Create
  4. Name the iRule: Reject_udp_464
  5. For Definition, enter the following:
    when CLIENT_ACCEPTED {
        reject 
    }
  6. Click Update
Steps to add iRule to Virtual server:
  1. Go to the virtual server created above, select the Resources tab.
  2. Select Manage iRules, and add the new iRule.
Solution 3: For versions Prior to v14 you can work around this issue by modifying the iptables on the BIG-IP.
Note: For versions 14 or later iptables is no longer an option
The recommended workaround is to modify iptables on the BIG-IP using the following command:
    iptables -I OUTPUT 1 -p udp --dport 464 -j DROP

If you encounter issues after applying this command. The following will reverse this change and allow the traffic on 464 UDP again:
    iptables -I OUTPUT 1 -p udp --dport 464 -j ACCEPT
Important: The above iptables rules will need to be reapplied after a reboot or an upgrade.
