K000132282: Convert AKAMAI True-Client-IP header to X-Forwarded-For using an iRule

Type
Support Solution
Published
2023-08-29
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000132282

Description

Akamai is configured with the True-Client-IP header and passes the HTTP traffic to the F5 load balancer, so you need the X-Forwarded-For header to give the pool members the real client IP address.


Environment

  • Akamai True-Client-IP header
  • Virtual Server with HTTP profile


Cause

Normally the True-Client-IP header includes the real IP of the clients when requests are coming from Akamai. It will be unaffected and be sent as part of the request to the pool member. So, your backend servers could look for that header and do something with its value. However, if you want the F5 to translate it to the X-Forwarded-For header, you can use an iRule to convert the Akamai True-Client-IP header to the X-Forwarded-For header.


Recommended Actions

Apply to the Virtual Server the iRule below that checks for the existence of the True-Client-IP header first which should only apply to Akamai traffic, and if it does exist, it then overwrites the existing X-Forwarded-For header with the same value: 
when HTTP_REQUEST { 
    if { [HTTP::header exists True-Client-IP] } {
        set trueclientip [HTTP::header True-Client-IP]
        HTTP::header replace X-Forwarded-For $trueclientip
    }
}
Note: Depending on your existing configuration, you might need to combine the iRule code above with an existing iRule or create a new one and apply it to your Virtual Server(s).
