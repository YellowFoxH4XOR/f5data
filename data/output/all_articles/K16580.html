Known Issue

The vCMP host may experience system stability issues, such as system lockups and daemon restarts. This issue occurs when the following condition is met:

  • You are performing moderate to heavy storage activities on the vCMP host.

    For example, a VIPRION system installed with four blades can safely handle four simultaneous live installations within vCMP guests with each live installation running on a separate blade. Initiating a fifth simultaneous live installation increases the vCMP host storage activity and may cause the system to behave undesirably.

Impact

The vCMP host experiences system stability issues, such as system lockup and daemon restarts. As a result, you may experience traffic disruption and device failover if you have configured the host as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The vCMP host experiences system lockups and daemon restarts.
  • The vCMP host fails over to its standby peer if you have configured the host as part of a high-availability system.

Workaround

There is no workaround for this issue. To mitigate this issue, you can limit and stagger live installations or upgrades on vCMP guests to one vCMP guest per blade at any time. Additionally, F5 recommends that you perform activities, such as live installations, UCS restores, tcpdump operations, and qkview collections, during off-peak utilization hours.
