K000149878: Enabling cors_match_protocol_port and cors_default_port_80 Triggers False-Positive

Type
Support Solution
Published
2025-02-19
Updated
2025-02-19
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.2, 16.1.5, 17.1.1
Source
https://my.f5.com/manage/s/article/K000149878

Description

When enabling Cross-Domain Request Enforcement on URL with Enforce on ASM mode, the Origin header is compared to list of hostnames in policy and the allowed origins for the respective URL. Otherwise, requests from the application's origins will only be allowed.

Environment

  • Adv.WAF
  • Cross-Domain Request Enforcement
  • False-Positive Block

Cause

Enabling cors_match_protocol_port and cors_default_port_80 without adding the application's hostname in [ HTTP Message Protection > Headers > Host Names ] triggers False-Positive even though the request's hostname and origin headers share the same hostname, protocol, and port.

Recommended Actions

To enforce Cross-Domain Requests without matching protocol and port on the request to the application's origins, add the application's hostname in [ HTTP Message Protection > Headers > Host Names ].
