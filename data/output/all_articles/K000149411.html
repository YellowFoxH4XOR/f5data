Description

When running the SSLOFIX tool, a cipher mismatch error occurs with the message: "ERROR: no matching key exchange method found: client ecdh-sha2-nistp256, ecdh-sha2-nistp384, ext-info-c server diffie-hellman-group14-sha256." This indicates that the key exchange (KEX) methods proposed by the client do not match those configured on the server. 

Environment

  • Product: BIG-IP SSLO
  • Custom SSHD configuration

Cause

The issue was attributed to a mismatch in the key exchange algorithms between the client and server. The client did not support the server's configured diffie-hellman-group14-sha256 algorithm, leading to the failure in running SSLOFIX.

Recommended Actions

To resolve the key exchange method mismatch error, update the client-side SSH configuration to include the server's KEX algorithm:

  1. Edit the SSH configuration file (typically located at /etc/ssh/ssh_config
  2. Update the KexAlgorithms line to include the server's KEX algorithm:
    KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,diffie-hellman-group14-sha256
  3. Save the configuration file.
  4. Run the SSLOFIX again and test to ensure the changes have resolved the issue. 

Note: SSHD service restart is not required after the above ssh_config file modification.
