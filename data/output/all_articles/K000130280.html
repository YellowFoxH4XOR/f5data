K000130280: ASM doesn't send event logs to remote server

Type
Support Solution
Published
2023-03-01
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000130280

Description

You may find the remote server doesn't receive the event logs from ASM.

  • You have configured a security logging profile and sent ASM event log to the remote server.

  • The network connectivity is fine between ASM and the remote server.

  • The related virtual server work in non-default route domain 0.

Environment

  • Event log

  • Security logging profile

  • Route domain

  • Remote log server

Cause

The behavior is expected. ASM BD process has some limits when sending event logs to the remote server, and it only sends event logs to the remote server through the routing table of route domain 0.

 Recommended Actions

If you need to send event logs to a remote server, avoid the virtual server working on a non-default route domain, or let the event log sent to the remote server be forwarded through the routing table of route domain 0.
For example, when you configure a virtual server in a route domain 1, and there is a route entry to the remote server in that route domain 1, you can consider refining the route entry in the route domain 1 and 0, by removing the route entry to the remote server in the route domain 1, and adding a route entry to the remote server in route domain 0. When the bd process finds no route entry to the remote server in the non-default route domain, it will check the routing table of the default route domain 0 and then send the event logs through the route entry of route domain 0.
