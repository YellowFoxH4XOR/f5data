Known Issue

This is the result of a known issue. The BIG-IP ASM bd process may core when processing XML-RPC traffic.

You can configure an XML profile within the BIG-IP ASM security policy to protect XML-based web traffic. The XML profile accepts WSDL and XSD documents as input describing a web service. Both WSDL and XSD are web service definitions specific to SOAP (Simple Object Access Protocol).

XML-RPC uses a service definition language called XRDL. In its current implementation, the XML profile does not support XRDL documents, and the BIG-IP ASM bd process may crash when the XML profile attempts to process XML-RPC traffic.

F5 Product Development tracked this issue as ID 339290 and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP ASM release note.

Workaround

You can prevent the BIG-IP ASM bd process from coring while parsing XML-RPC traffic by creating a basic XML profile without WSDL/XSD documents and applying it to a URL, and then enabling blocking for an XML-related violation. To do so, perform the following two procedures:

Creating a basic XML profile without WSDL/XSD documents and applying it to a URL

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click XML Profiles.
  4. Enter a name for the XML profile.
  5. Click Create.
  6. Navigate to URLs.
  7. Click the URL that is associated with the XML-RPC traffic.
  8. Click Apply XML Profile and select the XML profile from the drop-down list.
  9. Click Update.

Enabling blocking for an XML-related violation

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Policy.
  3. Select Settings from the Blocking menu.
  4. Click Block for one or more of the following XML-related violations:

    Illegal attachment in SOAP message
    Malformed XML data
    XML data does not comply with format settings
  5. Click Save.
  6. Apply the Security Policy.
