Known Issue

The BIG-IP system may incorrectly process chunked server responses.

This issue occurs when all of the following conditions are met:

  • The BIG-IP virtual server is configured with a rewrite profile and/or an access profile with a single sign-on (SSO) configuration.
  • The virtual server is also configured with a OneConnect profile and/or an NT LAN Manager (NTLM) profile.

Impact

The BIG-IP system misinterprets chunk boundaries and mangles the response content that is sent to the client.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H540614 on the Diagnostics > Identified > Medium page.
  • Hexadecimal numbers are occasionally inserted into requested pages.
  • Requested content fails to load or is partially missing.
  • Unchunked content that is sent by the server is unaffected.

Workaround

To work around this issue, you can use an iRule to rechunk all content returned by the BIG-IP system. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround depends on your specific environment, and the provided iRule may require customization. F5 recommends that you test any changes during a maintenance window, with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name.

    For example:

    rule_sol16778

  5. In the Definition box, enter the following:

    when REWRITE_REQUEST_DONE {
    set sol16778 1
    }
    when HTTP_RESPONSE {
    if {$sol16778 == 1} {
    set sol16778 0
    HTTP::payload unchunk
    }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. In the row for the affected virtual server, click Edit.
  9. In the iRules section, click Manage.
  10. Move the rule that you created to the Enabled section.
  11. Click Finished.
