Known Issue

The radvd process is the router advertisement daemon for IPv6. The radvd process records interface indexes (ifIndex) when it starts, and uses the ifIndex value to identify interfaces during router solicitations and router advertisements.

When certain BIG-IP processes, such as mcpd or tmm restart, the mapping between the interface names and interface index values on the host changes, and radvd can no longer reach interfaces because it continues to use the old interface index values. As a result, radvd cannot send router advertisements, and it cannot receive multicast messages on interfaces for which the ifindex values have changed.

When this issue occurs, error messages that appear similar to the following example are logged to the /var/log/daemon.log file:

radvd[18885]: resetting ipv6-allrouters membership on i1
radvd[18885]: can't join ipv6-allrouters on i1
radvd[18885]: sendmsg: Network is unreachable

F5 Product Development is tracking this issue as ID 247213 (formerly CR112091).

Workaround

You can work around this issue by restarting the radvd process. To do so, type the following command:

bigstart restart radvd
