Description

The ASM system can fill the /var/asmdata1 file system under certain conditions.
When this happens, you may notice that requests with violations are not written to the BIG-IP ASM Event Logs.
  • You will see error messages in the CLI indicating the available space in the disk partition is running out and disk space is not being returned.
    Disk partition /var/asmdata1 has only 0% free
     
  • You may also see messages in /var/log/ts/asmlogd.log similar to the following
    asmlogd|INFO|,,Starting asmlogd
    asmlogd|INFO|F5::IO::LrnPipe::init,,Pipe (type: PBRQL) could not be opened (error code = -1)
    asmlogd|ERR|,,asmlogd ended unexpectedly
    asmlogd|ERR|,,Can't call method "execute" on an undefined value at /usr/local/share/perl5/F5/DbUtils.pm line 200.
     
  • The output of df -h shows there is no space available
    /dev/mapper/vg--db--sda-app.asm.dat.asmdata1      4.0G  4.0G  0M  100% /var/asmdata1
     
  • The output of the following command in the CLI shows the PRX.REQUEST_LOG table as crashed:
    # mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'check table PRX.REQUEST_LOG'

    +-----------------+-------+----------+-------------------------------------------------------+
    | Table           | Op    | Msg_type | Msg_text                                              |
    +-----------------+-------+----------+-------------------------------------------------------+
    | PRX.REQUEST_LOG | check | warning  | Table is marked as crashed                            |
    | PRX.REQUEST_LOG | check | warning  | 1 client is using or hasn't closed the table properly |
    | PRX.REQUEST_LOG | check | error    | Found wrong record at 11173836                        |
    | PRX.REQUEST_LOG | check | error    | Partition p16400001 returned error                    |
    | PRX.REQUEST_LOG | check | error    | Corrupt                                               |
    +-----------------+-------+----------+---------------------------------------------------

Environment

  • BIG-IP ASM 
  • Event logging 

Cause
When the PRX.REQUEST_LOG is marked as crashed, the system cannot properly clean up the database. /var/asmdata1 becomes full as a result and a large amount of local event logging, such as when security log profiles set to "log all requests" are applied to virtual servers.

Recommended Actions

Impact: There is no impact by following below procedure.
  1. Login to BIG-IP ASM using cli mode.
  2. PRX.REQUEST_LOG database table shows corruption, so we should attempt to repair database table by using below command in bash: 
    # mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'repair table PRX.REQUEST_LOG'
  3.  Restart the BIG-IP ASM log daemon, which stores request logs. For more info on what asmlogd does see K14020: BIG-IP ASM daemons (11.x - 17.x) 
    # pkill -f asmlogd

Additional Information

This issue is often due to many virtual servers being configured with security log profiles to 'Log all requests'. Logging all is recommended for troubleshooting purposes only and should be switched to 'Log Illegal Requests' to reduce the amount of local logging. You can log all requests to a remote logging system if desired.
