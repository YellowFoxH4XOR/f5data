Known Issue

This is the result of a known issue. If a congested client or a client with a slow connection has a pipelined request queued, and the server closes the connection with a FIN while the last response is still being handled on the client-side, the server shutdown is delayed on the client-side until the response is completed. Instead of dropping the pipelined request, the system processes the client side information. This behavior is typically benign and results in the connection being aborted.

The behavior is different when an iRule is associated with the virtual server that causes the system process to handle the connection as though the server was still available. Since the proxy connection to the server has already been freed, the result is a signal segment violation causing TMM to crash.

F5 Product Development tracked this issue as CR69568 and CR69724 and it was fixed in BIG-IP LTM versions 9.1.3, 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM release notes.
