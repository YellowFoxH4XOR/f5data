Known Issue

The BIG-IP system may send corrupt IPv6 self-originated Link State Advertisements (LSA).

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to use OSPFv3.
  • One of the following events occur on the BIG-IP system:
     
    • The clear ipv6 ospf process command has been run.
    • A VIPRION primary blade fails over.
    • The OSPF6d process restarts.
  • BIG-IP exchanges Database Descriptor (DBD) packets with neighbor.
  • One of the following OSPFv3 events occur:
     
    • The BIG-IP system receives an LSA header from the neighbor for its own IPv6 self-originated LSA.
    • The BIG-IP system sends an LSA Request to the neighbor for all LSAs and receives a copy of the LSA for its own IPv6 self-originated LSA.
  • The BIG-IP system sends a corrupt update for its IPv6 self-originated LSA.

Impact

Routes from IPv6 self-originated LSAs may be missing in the OSPFv3 network.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice that routes for IPv6 self-originated LSAs are missing in the OSPFv3 network.
  • You notice the BIG-IP systems sends IPv6 self-originated LSAs with the wrong sequence number.

Workaround

To work around this issue, you can remove OSPFv3 from the OSPF routing domain until the corrupt Link LSA has been purged from the network, and then add OSPFv3 back to the OSPF routing domain. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the imish utility of the BIG-IP system that has advertised the corrupt LSA:

    imish

  2. To enable privileged mode, type the following command:

    enable

  3. To enter configuration mode, type the following command:

    config t

  4. To enter interface mode that has OSPFv3 enabled, use the following command syntax:

    interface <int_name>

    For example, to enter interface mode for the external interface, type the following command:

    interface external

  5. To remove OSPFv3 from the OSPF routing domain, use the following command syntax:

    no ipv6 router ospf area <id>

    For example, to remove OSPFv3 from the OSPF routing domain for area 1, type the following command:

    no ipv6 router ospf area 1

  6. Ensure that the corrupt LSA has been removed from the OSPF network.
  7. To add OSPFv3 back to the routing domain, use the following command syntax:

    ipv6 router ospf area <id>

    For example, to add OSPFv3 back to the OSPF routing domain for area 1, type the following command:

    ipv6 router ospf area 1

  8. To exit, type the following command:

    exit
