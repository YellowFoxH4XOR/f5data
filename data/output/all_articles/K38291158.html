Description

APM Reports showing only sessions for few days.

Environment

  • BIG-IP APM
  • APM Report

Cause

Usually root cause is some object dumping too many logs making all logdb tables to be full in little time.

By default there are 4 logdb tables with 250000 entries
# cat /etc/logmysqld.conf
{
   "db": {
       "name" : "logdb",
       "num_tables" : 4,
       "rows_per_table" : 250000,
       "query_interval" : 1
    },

# mysql -uroot -p`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw`
MariaDB [(none)]> SELECT table_name, table_rows FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA = 'logdb';
+------------------+------------+
| table_name       | table_rows |
+------------------+------------+
| log_data         |    1227021 |
| log_data_0       |     250203 |
| log_data_1       |     250147 |
| log_data_2       |     250437 |
| log_data_3       |     250226 |
| log_data_current |     226008 |
+------------------+------------+

For example:
A security dos profile where all "bot-signatures" categories are configured with "action=report".
APM ACLs where all entries are configured to log packets. Once access policy is passed, all traffic matches ACL rules so there can be lots of logs for each session.

Recommended Actions

You can increase "rows_per_table" from default 250000 to 500000, which means db will store 2 million records versus current 1 million. It is not recommend going beyond 500000.
Keep in mind that this change is not persisted in extremeDB and will be wiped out after an upgrade

Modify rows_per_table in /etc/logmysqld.conf
{
   "db": {
       "name" : "logdb",
       "num_tables" : 4,
       "rows_per_table" : 250000,   <====
       "query_interval" : 1
    },
[..]

For example: 500000
       
After that you will need to restart both "logmysqld" and "mysql"
# bigstart restart logmysqld
# bigstart restart mysql

You can try to adjust the log level to only what you need

You can check the content of logdb tables and find out the source of most of the logs

# mysql -uroot -p`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw`
MariaDB [(none)]> use logdb;
MariaDB [(none)]> SELECT DISTINCT * FROM log_data_current LIMIT 10;
MariaDB [(none)]> SELECT DISTINCT * FROM log_data_current ORDER BY time_stamp DESC LIMIT 10;


To export and restore the database
# mysqldump -uroot -p`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` logdb > logdb.sql
# mysql -uroot -p`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` logdb < logdb.sql

If you need to export and upload the database
# mysqldump -uroot -p`perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` logdb | gzip -9 > /shared/tmp/logdb.dump.gz
