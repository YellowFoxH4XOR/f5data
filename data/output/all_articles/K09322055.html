Issue

Old Behavior

In versions prior to BIG-IP 12.0.0, you must turn on debug logging for SSL for the BIG-IP system to log certain SSL errors to the /var/log/ltm file.

New Behavior

Beginning in BIG-IP 12.0.0, you no longer need to turn on debug logging for SSL for the BIG-IP system to log these SSL errors to the /var/log/ltm file. The system now automatically logs debug SSL errors through standard logging. The following provides an example list of some of these SSL errors that would be logged only if debug logging was turned on in previous versions, and are now logged through standard logging:

Note: The following list is not an exhaustive list.

  • Connection error: ssl_select_suite:6319: no shared ciphers (40)
  • Connection error: ssl_passthru:4015: not SSL (40)
  • Connection error: ssl_hs_rxhello:7284: unsupported version (40)
  • Connection error: ssl_hs_rxhello:3840: insecure renegotiation disallowed (40)
  • Connection error: ssl_shim_vfycerterr:3398: certificate revoked (44)
  • Peer cert verify error: ok (depth 0; cert /C=NO/CN=103.example.com)

F5 Product Development tracked this change as Bug ID 515009.

Impact

You do not need to turn on SSL debug logging to view certain SSL errors.

Recommended Actions

Reduce the amount of SSL messages

You can adjust the level of logging to "error" to reduce the amount of SSL messages. To do so, perform the following procedure:

  1. Log in to the BIG-IP Advanced Shell (bash).
  2. Check the current SSL log level settings by entering the following command:

    tmsh list /sys db log.ssl.level

  3. Modify this value to "error" by entering the following command:

    tmsh modify /sys db log.ssl.level value error

  4. Save the configuration by entering the following command:

    tmsh save /sys config
