Description

When upgrading an HTTP connection to WebSocket, authentication cookies or bearer tokens in headers can be lost or misapplied—especially when OneConnect or custom iRules are active. This can result in failed handshakes or unauthorized access to your WS backend.

Environment

  • BIG-IP LTM with an HTTP profile and WebSocket profile bound
  • OneConnect enabled on the Virtual Server
  • Custom iRules manipulating headers or using header-based security
  • Backend application relying on JSESSIONID cookie or Authorization header for WS authentication

Cause

WebSocket handshakes reuse TCP connections; OneConnect may pool and replay requests without original headers. Custom header rewrites, HTTP compression, or ASM policies can strip or alter authentication headers before the WS upgrade, causing the backend to reject the connection.

Recommended Actions

Below are some of the ways you can overcome the challenges of authentication persistence with websockets, these recommendations might not work for your specific case, but they are guidelines on how to tackle this issue for various scenarios:

Inspect tokens early and keep track of them:

when HTTP_REQUEST {

 if { [HTTP::cookie exists "JSESSIONID"] } {

  table set ws_token_[IP::client_addr] [HTTP::cookie "JSESSIONID"] 300

 }

}

Disable OneConnect for WS Paths

when HTTP_REQUEST {

 if { [HTTP::uri] starts_with "/ws/" } {

  TCP::disable reuse

 }

}

Reapply Cookies on Upgrade

when HTTP_REQUEST {

 if { [HTTP::header exists "Upgrade"] and

    [string tolower [HTTP::header "Upgrade"]] eq "websocket" } {

  set token [table lookup ws_token_[IP::client_addr]]

  if { $token ne "" } {

   HTTP::header replace "Cookie" "JSESSIONID=$token"

  }

 }

}

Additional Information

  • Use short TTLs (e.g. 300 s) in iRule tables to limit memory usage.
  • If you use ASM, remember that selective unmasking may still alter masked data; test your header logic end-to-end.
  • For JWTs, consider in-iRule HMAC validation or external introspection to offload backend verification.
  • Disable Compression/ASM for WS Handshake
  • Exclude /ws/ from HTTP compression or ASM unmasking so header-grab logic runs unaltered.
