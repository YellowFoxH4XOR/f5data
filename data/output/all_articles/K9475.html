Issue

When a redundant BIG-IP ASM configuration is unable to perform MySQL replication using the failover self IP address, the BIG-IP ASM configuration is not synchronized to the peer system during configsync operations. In addition, error messages similar to the following examples are logged to the /var/log/asm file every hour:

replication.pl[10911]: [ERR,2008-12-01 15:22:11 PST]10911,/ts/recovery/replication.pl,main::db_connect_remote,,Can't connect to database: Can't connect to MySQL server on '10.24.2.111' (111)

replication.pl[10911]: [ERR,2008-12-01 15:22:11 PST]10911,/ts/recovery/replication.pl,main::myexit,,do_config failed: SLAVE_TO_REMOTE_MASTER_ERROR

recovery_mngr.pl[4115]: [ERR,2008-12-01 15:22:11 PST]4115,/ts/recovery/recovery_mngr.pl,main::repl_cmd_complete,,failed to configure slave replication: SLAVE_TO_REMOTE_MASTER_ERROR (Unable to contact peer unit - make sure that both units are configured correctly for redundancy)

Note: F5 is working to eliminate exclusionary language in products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

This error message is commonly triggered when the self IP Port Lockdown settings are not configured properly for the BIG-IP ASM system. For example, in order for MySQL replication to succeed, the following TCP and UDP services should be enabled for the self IP:

  • TCP and UDP 3306
  • TCP 443

To determine whether the above TCP and UDP services are enabled for the self IP, type the following command:

bigpipe self <self_ip> allow show

For example:

bigpipe self 172.1.1.1 allow show

The following output indicates that the default set of TCP and UDP services are enabled for the self IP 172.1.1.1:

SELF 172.1.1.1 - self IP allowed services:
    DEFAULT

To add the TCP and UDP MySQL services to the default self IP allowed list, type the following command:

bigpipe self allow default tcp mysql udp mysql add

Note: For more information, refer to K7317: Overview of port lockdown behavior.
