Description

A tmsh process uses high CPU

Environment

  • tmsh process promoted to a process group leader
  • Closed SSH session 

Cause

As a result of Bug ID 760680, after closing interactive SSH session tmsh may remain active in an infinite loop using 100% CPU.

Recommended Actions

To prevent this issue, you should not promote tmsh to be a process group leader and avoid use of nested command line sessions.

To recover from this issue, you can kill the tmsh process  You can kill the tmsh process using the following procedure:

  1. Use the following command to identify the PID of the tmsh process:
    ps aux | grep tmsh

    In the following example output, the PID of the tmsh process is 2059:
    root 2059 89.1 3.7 274792 151224 pts/1 Sl 08:36 0:00 tmsh
     
  2. Kill the tmsh process with the following command syntax:
    kill -9 <tmsh pid>

    For example, the following command kills a tmsh process with a PID of 2059:
    kill -9 2059

Additionally, you can configure an idle-timeout for tmsh sessions using the following procedure:

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To configure an automatic logout idle time for tmsh sessions, use the following command syntax:

    modify /cli global-settings idle-timeout <minutes>

    For example, to configure a 15-minute automatic logout idle time, type the following command:

    modify /cli global-settings idle-timeout 15

  3. Save the change by typing the following command:

    save /sys config

Additional Information

    • Avoid the use of nested command line sessions, similar to the following example:
      tmsh --> bash --> tmsh --> bash
       
    • The pstree command can identify a nested command line session
      For example, this pstree output shows nested tmsh sessions:

      |-sshd---sshd---bash---tmsh-+-bash---tmsh-+-bash---pstree
      |                           |             `-2*[{tmsh}]
      |                           `-2*[{tmsh}]

    • Avoid using bash from within tmsh, use quit instead.
