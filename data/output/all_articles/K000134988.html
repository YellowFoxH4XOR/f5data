K000134988: Systemd-journal is suppressing log messages

Type
Support Solution
Published
2023-06-10

2023-06-10
Applies to
  • BIG-IP

Source
https://my.f5.com/manage/s/article/K000134988

Description

Systemd-journal is suppressing log messages

 

You are seeing log messages similar to the following in /var/log/ltm:

 

Jun 11 00:11:58 bigip1.example.com info systemd-journal[657]: Suppressed 8629 messages from /system.slice/runit.service

 

You may find messages in /var/log/gtm similar to the following:

 

Jun 11 00:33:59 bigip1.example.com debug big3d[13004]: 012b2007:7: BroadcastXMLMessage: Begin xml broadcast

Jun 11 00:33:59 bigip1.example.com debug big3d[13004]: 012b1003:7: Sending a message to ::ffff:0.0.0.0:13370

Jun 11 00:31:34 bigip1.example.com info big3d[13004]: 012b2002:6: IQM_TYPE_VIP2 --> IQM_CODE_MULTI_GET

 

Environment

BIG-IP

Cause

These are likely being caused by a logging level that is set to debug or greater for events

Recommended Actions

In a qkview or on a live system view the output of "tmsh list /sys db all-properties"

 

Search for the string value "debug"

 

For example for the messages in /var/log/gtm we can see that the big3d daemon had it's log level set to debug, but the default value was notice:

 

sys db log.big3d.level {

default-value "notice"

scf-config "true"

value "debug"

value-range "alert crit debug emerg err error info notice panic warn warning"

}

 

Change the log level back to notice with the commands:

 

tmsh modify /sys db log.big3d.level value notice

tmsh save /sys config
