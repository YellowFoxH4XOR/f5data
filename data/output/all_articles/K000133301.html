K000133301: Change pod logging level with one line commands

Type
Support Solution
Published
2023-03-31
Updated
2023-03-31
Applies to
  • NGINX Products
  • NGINX Controller: 3.22.8
Source
https://my.f5.com/manage/s/article/K000133301

Description

Changing pod logging levels can be useful when troubleshooting issues

Note: A log level will log at the specified level as well as at the levels above it

For example, log level error will log at level error, fatal and panic

  • panic (5)
  • fatal (4)
  • error (3)
  • warn (2)
  • info (1)
  • debug (0)

Environment

NGINX Controller

Cause

Troubleshooting

Recommended Actions

Set pod logging level to debug and watch the logging output from said pod

  • declarative-ext-api
kubectl patch cm $(kubectl get cm | grep declarative-ext-api | sed 's/ .*//') -p '{"data":{"LOG_LEVEL":"debug"}}' && kubectl delete pod -l app=declarative-ext-api && kubectl logs -l app=declarative-ext-api -f
  • dataplane-manager 
kubectl patch cm $(kubectl get cm | grep dataplane-manager | sed 's/ .*//') -p '{"data":{"LOG_LEVEL":"debug"}}' && kubectl delete pod -l app=dataplane-manager && kubectl logs -l app=dataplane-manager -f
  • platform-mgr 
kubectl patch cm $(kubectl get cm | grep platform-mgr | sed 's/ .*//') -p '{"data":{"LOG_LEVEL":"debug"}}' && kubectl delete pod -l app=platform-mgr && kubectl logs -l app=platform-mgr -f
  • clickhouse (changing logging level for clickhouse does not lend itself for a one liner)
    • Edit the clickhouse config map
    kubectl edit cm $(kubectl get cm | grep clickhouse | sed 's/ .*//')
    • Find the log level xml tag and change value to trace 
    <yandex>
    <logger>
        <level>trace</level>
    • Save changes
    • Delete the clickhouse pod
    kubectl delete pod -l app=clickhouse && kubectl logs clickhouse-0 -f
