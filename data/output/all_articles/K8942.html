Known Issue

This is the result of a known issue. The application language setting for the security policy specifies the default language encoding for the web application. The Policy Builder does not implement a time limit when detecting the default language for the web application

For example, when running the Deployment Wizard, the application language is set to auto detect. If the language encoding is not detected in the server response body or the headers, the language encoding for the security policy is not determined and no default encoding scheme is used.

Note: This issue affects BIG-IP ASM utilities that use the Policy Builder, such as the Deployment Wizard and the Policy Wizard.

F5 Product Development tracked this issue as CR100458 and it was fixed in BIG-IP ASM 9.4.6. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

If you have determined that the language encoding for the security policy was not determined by the Policy Builder, you can manually set the encoding. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Determine the Web Application for which the language encoding was not set, and click Set Language.
  5. Select the appropriate language encoding from the Application Language drop-down menu.
  6. Click Update.
