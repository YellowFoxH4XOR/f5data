K5351: 3-DNS may add an unrelated top level domain when you add a wide IP alias

Known Issue

This is the result of a known issue. If you use the Configuration utility to create a wide IP alias that uses a different top level domain than the wide IP, 3-DNS may create a zone for the top level domain of the alias.

For example, if you have a wide IP named askf5.com and you create an alias named askf5.net, the Configuration utility may add the zone .net to 3-DNS.

When 3-DNS creates this zone, it also defines it as authoritative. As a result, when the root server cache on 3-DNS expires, 3-DNS will refer to itself for all net queries. At a minimum, this results in a failure of all queries to the .net domain.

When this issue occurs, you may see the following error message logged in the /var/log/messages file:

named[<pid>]: sysquery: findns error (NXDOMAIN) on X.ROOT-SERVERS.NET?

3-DNS may also become unresponsive and report messages from a variety of processes. In the event 3-DNS becomes unresponsive, the following error message may appear in the /var/log/messages file:

Too many open files in system

F5 Networks Product Development tracked this issue as CR49888.

Workaround

To avoid this issue, use a command line text editor to configure wide IP aliases belonging to a different top level domain than the wide IP. For assistance with manually editing the wideip.conf file, contact F5 Networks Technical Support.
