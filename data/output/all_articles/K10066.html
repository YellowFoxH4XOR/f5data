Known Issue

When the ZoneRunner daemon (zrd) attempts to write the contents of an out-of-sync journal file to a zone, BIND responds with an error message indicating the journal is out of sync, and the zrd process exits. As a result, you cannot restart the zrd process, and any attempt to restart the process triggers the same error message.

The ZoneRunner utility included with the BIG-IP DNS (formerly known as BIG-IP GTM) system uses dynamic update to maintain the integrity of its DNS zone data. All changes you make to a zone using dynamic update are written to the zone's journal file. The system will flush the complete contents of the updated zone to its zone file approximately every 15 minutes, and when the named process is stopped normally. When you restart the system after an unclean shutdown, it replays the journal file to incorporate into the zone any updates that took place after the last zone file update.

If the replayed journal file is not synced with the contents of the zone file, BIND returns an error message that appears similar to the following example:

error: zone domain.com/IN/external: journal rollforward failed: journal out of sync with zone

The zrd process exits when it encounters this error message. Additionally, you cannot restart the zrd process until you resolve the error condition.

F5 Product Development tracked this issue as ID 264701.

Workaround

You can work around this issue by manually deleting the affected zone journal files from all affected BIG-IP DNS systems, and restarting the zrd and BIND processes on all systems. To do so, perform the following two procedures:

  • Manually deleting the zone journal files from the BIG-IP DNS system
  • Restarting the zrd and BIND processes

Manually deleting the zone journal files from the BIG-IP DNS system

To manually delete the zone journal files from a BIG-IP DNS system, perform the following procedure on each system in the sync group:

Impact of procedure: This procedure restarts the named service which may affect the BIG-IP system's ability to respond to DNS queries. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the affected BIG-IP system command line.
  2. Stop the zrd process by entering the following command:

    BIG-IP 11.x and later:

    tmsh stop /sys service zrd

    BIG-IP 10.x and earlier:

    bigstart stop zrd

  3. Stop the named process by entering the following command:

    BIG-IP 11.x and later:

    tmsh stop /sys service named

    BIG-IP 10.x and earlier:

    bigstart stop named

  4. Delete the journal files corresponding to the affected zones by using the following command syntax:

    rm /var/named/config/namedb/<zone>.jnl

    In this command, note the following:

    • <zone> is the name of the affected zone.

Important: You must remove the affected journal files from all of the BIG-IP DNS systems in the sync group before restarting the zrd and BIND processes on any system in the sync group. Configuring the BIG-IP DNS sync group to synchronize DNS zone files prevents the affected journal files from syncing back after you have deleted the files.

Restarting the zrd and BIND processes

After you have removed the affected zone files from all BIG-IP DNS systems, restart the zrd and BIND processes by performing the following procedure on each system in the sync group:

  1. Log in to the affected BIG-IP system command line.
  2. Restart the named process by entering the following command:

    BIG-IP 11.x and later:

    tmsh start /sys service named

    BIG-IP 10.x and earlier:

    bigstart startup named

  3. Restart the zrd process by entering the following command:

    BIG-IP 11.x and later:

    tmsh start /sys service zrd

    BIG-IP 10.x and earlier:

    bigstart startup zrd
