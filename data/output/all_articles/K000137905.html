K000137905: After upgrading BIG-IP to 15.1.10.3, some applications start getting Malformed HTTP Header errors

Description

After upgrading BIG-IP to 15.1.10.3 or installing Engineering HotFix (EHF) for ID1354253, some applications started getting errors.

  • Packet captures show that the RST cause: {peer} Malformed HTTP header error.
  • Some applications are getting reset due to this.

Environment

  • BIG-IP LTM 15.1.10.3 and later (OR) EHF for ID1354253.
  • http profile with "Enforce RFC Compliance" not enforced.
  • The issue no longer happens if BIG-IP is rolled back to an older version.

Cause

This is because the application in the backend server is sending HTTP header(s) that violate HTTP RFC and can be potentially vulnerable to attacks. ID1354253 starts enforcing HTTP RFC compliance strictly. This has been disclosed as part of Security Advisory https://my.f5.com/manage/s/article/K000137322

 

Recommended Actions

The best solution is to fix the backend application that is sending non-compliant HTTP headers. To find out what headers are being sent by the application, follow the steps below:

  1.  Take a tcpdump (and decrypt if required, K31793632)
  2. Analyze the response headers from the backend server that is causing the BIG-IP to RST the connection.
  3. Make sure the headers are in compliance with below conditions:
  • Value for Content-Length header should not cause integer overflow (allowed in multiple instances both in comma-separated lists and multiple Content-Length headers)
  • Transfer-Encoding header to allow only RFC-compliant combinations for this header.
  • No duplicate Transfer-Encoding headers.

 

It may be possible to remedy the issue by using an irule to remove non-rfc-compliant headers, but this is beyond the scope of F5 Technical Support. You can engage F5 Professional Services or the DevCentral Community site
