K000149680: Certificate validity stuck in "provisioning" for newly created load balancer

Type
Support Solution
Published
2025-02-06
Updated
2025-02-07
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud Web App & API Protection
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000149680

Description

The certificate status for a newly deployed load balancer remains in "provisioning" longer than expected following the initial setup. Normally, this process completes quickly.

Certificate status stuck in "provisioning" state despite proper DNS entries i.e. proper CNAME record added matching the one provided in the XC console.

❯ dig _acme-challenge.example.com -t CNAME @8.8.8.8

; <<>> DiG 9.10.6 <<>> _acme-challenge.example.com -t CNAME @8.8.8.8
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 14389
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 4096
;; QUESTION SECTION:
;_acme-challenge.example.com. IN CNAME

;; ANSWER SECTION:
_acme-challenge.example.com. 498 IN	CNAME randomnumbersandletters.autocerts.ves.volterra.io. ### this record value matches the info provided in the XC console

;; Query time: 84 msec
;; SERVER: 8.8.8.8#53(8.8.8.8)
;; WHEN: Fri Jan 31 16:04:44 CST 2025
;; MSG SIZE  rcvd: 140

 

The status object (under Actions, three dots, Show Status) shows an error message:

load-authorization bf8ff1f9-6fc7-4f99-9f37-18ffcfc1789a:tenant-name/namespace/ves-io-http-loadbalancer-name: unexpected authorization status invalid.
challenge error: (problem (type "urn:ietf:params:acme:error:dns") (instance"'') (id <nil>) (title '): (detail "DNS problem: NXDOMAIN looking up TXT for _acme-challenge.example.com - check that a DNS record exists for this domain"))

Environment

  • F5® Distributed Cloud
  • Web App & API Protection
  • HTTP Load Balancer
    • HTTPS with Automatic Certificate

Cause

The certificate generation process may have encountered issues while running.

Recommended Actions

  1. Add a TXT record with the same name and value as the CNAME record.
  2. Make a minor change to the load balancer configuration (e.g., modify the description) to re-trigger certificate creation.
  3. Monitor the auto-certification process post-deployment to ensure certificates are generated correctly.
  4. Please contact support if the certificate is not generated after following these steps.
