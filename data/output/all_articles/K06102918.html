Description

The BIG-IP configuration load fails with error "No user configuration is found" and the following symptoms occur:

  • All services stop working
  • Failed access to TMUI (Configuration utility)
  • Errors similar to the following are observed in /var/log/ltm:

    01420006:3: No user configuration is found. Loading process is aborted.
    /usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Unexpected Error: No user configuration is found. Loading process is aborted.
    01070422:3: Base configuration load failed.
  • An error similar to the following is shown while validating configuration using the TMSH command, tmsh load sys config verify:

    Unexpected Error: No user configuration is found. Validating process is aborted

Environment

  • In the /config directory, none of the following files exist or their size is 0 bytes:

    • /config/bigip_base.conf
    • /config/bigip_user.conf
    • /config/bigip.conf

Cause

Any of the following reasons might cause the issue:

  • Defective file system or damaged hard drive
  • Files were deleted or modified
  • Files might get corrupted after increasing resources to BIG-VE from the hypervisor.
  • ID 734557

Recommended Actions

  • Check the file system using the fsck tool. Refer to K73827442: Forcing a file system check on the next system restart.
  • Restore configuration files from UCS backup file. Refer to K13132: Backing up and restoring BIG-IP configuration files with a UCS archive.

Alternatively you can try the following procedure to bring the system to an accessible state.

  1. From the command line of the BIG-IP you can manually copy the backup copies of the files as the current configuration files using the following series of commands:

    cp /config/bigip_base.conf.bak /config/bigip_base.conf
    cp /config/bigip_user.conf.bak /config/bigip_user.conf
    cp /config/bigip.conf.bak /config/bigip.conf

  2. Force mcpd to reload the configuration. Refer to K13030: Forcing the mcpd process to reload the BIG-IP configuration.

  3. Once the device comes back online, reactivate the device license if necessary. Refer to K7752: Licensing the BIG-IP system.
