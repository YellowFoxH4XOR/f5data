Description

You are experiencing periodic alarms in /var/log/ltm indicating compression engine failure and client connections will be intermittently disconnected. 

You may see alarms similar to the following in /var/log/ltm:  
01010025:2: Device error: n5-compress2 Zip engine ctx eviction (comp_code=10): ctx dropped.


When running a packet capture, you may see a tcp Reset cause similar to [F5RST: Compression error (Unknown error)]

Environment

  • Can occur when Hardware acceleration is enabled and there is a compression profile applied to a virtual server leveraging the hardware acceleration chipset. 

Cause

The error code for the nitrox processor "Error code comp_code=10" means "The compress or decompress encountered an internal parity error. This is a fatal error, and all other outputs (bytes in the output stream and RWORDs) from the ZIP coprocessor are unpredictable and should not be used by the software."

Recommended Actions.

If the hardware chipset is reporting errors, first attempt to set the system to use software compression only.
  1. Log in to the Big-IP Command line and enter TMOS
    tmsh
  2. Determine the current compression strategy.
    list sys db compression.strategy value
  3. Update the compression strategy database variable to use software only.
    modify sys db compression.strategy value softwareonly
After the strategy has been updated, check again to see if the errors are continuing to populate in /var/log/ltm.
