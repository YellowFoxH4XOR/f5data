K000151888: Make sure the backend services are defined in the same backendrefs when using Canary releases in NGINX Gateway Fabric

Description

You're using NGINX Gateway Fabric and trying to gradually introduce a new version of your application to a subset of nodes in a controlled manner, splitting the traffic between the old are new (canary) release.

 

Environment

  • NGINX Gateway Fabric

Cause

None.

Recommended Actions

HTTPRoute allows multiple backendRefs defined inside with different rules, when you want to split the traffic by leveraging the 'weight' parameter between the backend applications, make sure the backend services are defined in the same backendrefs.

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: example
spec:
  parentRefs:
  - name: gateway
    sectionName: http
  hostnames:
  - "www.example.com"
  rules:
  - matches:
    - path:
        type: PathPrefix
        value: /
    backendRefs:
  - name: old-app
    port: 80
    weight: 80
  - name: new-app
    port: 80
    weight: 20
