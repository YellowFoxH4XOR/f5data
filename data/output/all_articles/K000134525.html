Description

  • Update.sh aborts and platform-mgr pod is down as 'CrashLoopBackOff'
  • Error messages
[ERROR] basic start/start.go:382 could not initialize auth providers api %!w(*fmt.wrapError=&{failed to fetch auth providers: system: failed to assign all query results to AuthProvider slice: bind failed to execute query: x509: certificate signed by unknown authority (possibly because of "crypto/rsa: verification error" while trying to verify candidate authority certificate "postgres-ca") 0xc000a8b1a0})

[FATAL] basic start/start.go:119 failed to fetch auth providers: system: failed to assign all query results to AuthProvider slice: bind failed to execute query: x509: certificate signed by unknown authority (possibly because of "crypto/rsa: verification error" while trying to verify candidate authority certificate "postgres-ca")

Environment

  • Nginx Controller

Cause

The mismatch between the postgres secret and the db-cert used by platform-mgr pod.

 Recommended Actions

1. Get the secret name from the output of the command below, it should be SecretName: controller-postgres-certs-xxxx

#kubectl describe pod controller-postgres-0 | grep postgres-certs: -A 4

2. Get the secret name from the output of the command below, it should be secretName: db-certs-yyyy

#kubectl get pod <platform-mgr-pod-name> -oyaml | grep "name: db-certs" -A 4

3. Display all the controller-postgres-certs and db-certs, and find if any controller-postgres-certs (say it's controller-postgres-certs-zzzz) is as old as db-certs-yyyy

# kubectl get secret -A | grep "controller-postgres-certs\|db-certs"

4. Edit the 'sts controller-postgres' to replace controller-postgres-certs-xxxx with controller-postgres-certs-zzzz

# kubectl edit sts -n nginx-controller controller-postgres
