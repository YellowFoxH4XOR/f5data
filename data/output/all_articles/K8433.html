Known Issue

This is the result of a known issue. When an administrator edits an SSL server certificate associated with a web service, a service restart is required before the edit takes effect. However, the FirePass Administrative Console does not indicate that a service restart is required. You can configure SSL server certificates on the Device Management: Configuration: Network Configuration page under the Web Services tab by selecting the Configure SSL Certificates link. Clicking the Edit link next to the certificate allows you to enter a new certificate. Once the certificate information (certificate, private key, and optional chain certificates) is entered and saved, the new certificate information will replace the old certificate information in the SSL Server Certificate section. A message at the top of the section will appear similar to the following example, stating the valid date range:

The certificate that you entered is valid from Feb-14-2008 till Oct-13-2008 !

However, FirePass does not indicate that services must be restarted. The old SSL server certificate will continue to be used until the next service restart.

F5 Networks Product Development is tracking this issue as CR88257.

Note: If the certificate is not currently associated with a web service, you can edit the certificate without restarting services. A service restart is only required if the certificate you edited is associated with a web service.

Workaround

You can work around this issue by manually restarting the FirePass services after editing an SSL certificate. You can restart the FirePass services on the Device Management : Maintenance : Restart Services page.
