Description

After rebooting the device unable to access the GUI. When checking the ltm logs in the SSH / console, it repeatedly prompts an error: failed to reset strict operations; disconnecting from mcpd

/var/log/ltm has similar to the below log:

emerg load_config_files[<PID>]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Error: failed to reset strict operations; disconnecting  from mcpd.  Will reconnect on next command.

notice mcpd[<PID>]: 0107165d:5: init_system_epsec_software_status: EPSEC:: loading of Epsec software status start
 

Environment

  • BIG-IP
  • Any version
  • APM provisioned
  • after reboot / upgrade (software or license) / ucs restore
  • OPSWAT EPSEC

Cause

Bug ID 997793
 

Recommended Actions

  • Update to a fixed BIG-IP version. Fixes  available at:
    • BIG-IP 17.1.2
    • BIG-IP 16.1.5
  • Follow workaround in Bug ID997793.
  • If workaround that does not work, try these commands in the CLI. Please note that the mcpd restart might be needed as well.
    rm -rf /var/apm/lib/rpm
    epsec -f refresh
    tmsh load sys config

Additional Information

  • Previous EPSEC packages that are still residing on the system from old BIG-IP versions is installing upon boot.
  • MCPD daemon takes too long to install EPSEC packages and exceeds its heartbeat timeout (5 minutes).
  • Overdog daemon sends a 'bigstart restart' each time MCPD fails to respond within the heartbeat timeout period which causes a restart loop.

Before upgrading, you should remove all unneeded EPSEC installations to reduce the chance of this happening. Removing the EPSEC installations does not affect the APM policies
