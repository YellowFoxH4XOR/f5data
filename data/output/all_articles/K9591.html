Known Issue

This is the result of a known issue. The gtm_add utility is an interactive script used to replace the local BIG-IP GTM system's configuration with the remote BIG-IP GTM system's configuration, and integrate the local BIG-IP GTM into the existing synchronization group.

Note: For more information about the gtm_add utility, refer to K8195: Overview of the BIG-IP GTM big3d_install, bigip_add, and gtm_add utilities.

One of the tasks of the gtm_add script is to copy the remote BIG-IP GTM system's device certificate (/config/httpd/conf/ssl.crt/server.crt) to the the local BIG-IP GTM system's list of trusted device certificates (/config/big3d/client.crt). If the remote BIG-IP GTM system's device certificate does not contain a newline character after the last line in the certificate file, the device certificate can be incorrectly added to the local BIG-IP GTM system's trusted device certificate file. When this occurs, the big3d process may not correctly parse the local BIG-IP GTM system's trusted device certificate file, resulting in big3d failing to start or iquery communication failures.

Additionally, when the big3d process is restarted, error messages are logged to the /var/log/gtm file that appear similar to the following example:

big3d[2957]: 012b0000:3: big3d started ===============================
big3d[2957]: 012b3003:3: SSL_CTX_load_verify_locations: SSL error:0906D066:PEM routines:PEM_read_bio:bad end line
big3d[2957]: 012b3003:3: SSL_CTX_load_verify_locations: SSL error:0B084009:x509 certificate routines:X509_load_cert_crl_file:PEM lib

Note: This issue has only been known to occur when the device certificate was updated using the Configuration utility or command line. Device certificates that are installed by default on the BIG-IP GTM device are correctly formatted.

F5 Product Development tracked this issue as CR113668 and it was fixed in BIG-IP GTM version 10.0.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Workaround

To work around this issue, perform one of the following two workarounds:

  • After running the gtm_add utility
  • Before running the gtm_add utility

After running the gtm_add utility

If you previously ran the gtm_add utility and the remote device certificate was incorrectly added to the local BIG-IP GTM system's trusted device certificate file (/config/big3d/client.crt), the -----END CERTIFICATE----- line and the -----BEGIN CERTIFICATE---- line may appear on the same line in the file.

You can resolve the issue by manually editing the /config/big3d/client.crt file using a text editor, and adding a line break.

For example:

-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----

Note: There should be five dashes at the beginning and end of the -----END CERTIFICATE----- line and the -----BEGIN CERTIFICATE----- line.

Before running the gtm_add utility

If you have not yet run the gtm_add script, you can ensure that the remote BIG-IP GTM system's device certificate (/config/httpd/conf/ssl.crt/server.crt) contains a newline character after the last line in the certificate file. To do so, perform the following procedure:

  1. Log in to the command line of the remote BIG-IP GTM system.
  2. Type the following command:

    cat /config/httpd/conf/ssl.crt/server.crt

    If the last line of the certificate file appears on the same line as your command prompt, the newline character is missing. For example:

    -----END CERTIFICATE-----[root@bigip:Active] config #
  3. To resolve the issue, type the following command:

      echo "" >> /config/httpd/conf/ssl.crt/server.crt
