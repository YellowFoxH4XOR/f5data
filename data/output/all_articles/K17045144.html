Vulnerable and outdated components

A software component is part of a system or application that extends the functionality of the application, such as a module, software package, or API. Component-based vulnerabilities occur when a software component is unsupported, out of date, or vulnerable to a known exploit. You may inadvertently use vulnerable software components in production environments, posing a threat to the web application. For example, an organization may download and use a software component, such as OpenSSL, and fail to regularly update or patch the component as flaws are discovered. Since many software components run with the same privileges as the application itself, any vulnerabilities or flaws in the component can result in a threat to the web application.

Using components with known vulnerabilities makes your application susceptible to attacks that target any part of the application stack. For example, the following attack types are a few that may target known component vulnerabilities:

  • Code injection
  • Buffer overflow
  • Command injection
  • Cross-site scripting (XSS)

Vulnerable and outdated components attack scenario

In the following scenario, the attacker exploits an unpatched system to execute malicious code on the server.

  1. The attacker gains access to an organization's internal network.
  2. The attacker runs a scanning tool to locate internal systems with unpatched or outdated components.
  3. The attacker exploits a flaw in the outdated component that allows them to install malicious code on the application server.

Secure F5 products against vulnerable and outdated components attacks

F5 products provide security features, such as attack signatures, that protect your web application against component-based vulnerability attacks. In addition, F5 provides tools, such as the F5 iHealth diagnostic tool, that allows you to audit BIG-IP software components and their dependencies, making sure that the components are up-to-date and do not contain known vulnerabilities.

Use BIG-IP APM to mitigate vulnerable and outdated component attacks

Vulnerable and outdated components attacks target both client and server side components. You can use BIG-IP APM to validate the security posture of incoming web connections from remote Windows and Mac clients.

Table 6.2 BIG-IP APM controls that protect against vulnerable and outdated components attacks

BIG-IP APM access policy Client-Side Endpoint Security lets you configure the BIG-IP system to continuously verify the security compliance of client devices accessing your applications. The end point checks include checking the status of operating system information from OS and browser versions and updates to details such as BIOS version, CPU vendor, and network adapter information.

Use BIG-IP Advanced WAF/ASM to mitigate vulnerable and outdated component attacks

You can use BIG-IP Advanced WAF/ASM to mitigate vulnerable and outdated component attacks by using the following guidance:

Table 6.3 BIG-IP Advanced WAF/ASM controls that protect against vulnerable and outdated components attacks
BIG-IP Advanced WAF/ASM protectionRecommendationsResource
Attack signaturesConfigure your BIG-IP Advanced WAF/ASM security policy with attack signatures that protects against vulnerable and outdated components of your application environment. You should regularly update the attack signature sets so that the system has the appropriate capabilities to mitigate the vulnerable components. In addition, you can filter the BIG-IP Advanced WAF/ASM Attack Signature List by a specific Common Vulnerabilities and Exposures (CVE) number if needed so that you can add it to your security policy. If you have a specific need unique to your application environment, you can develop custom attack signatures. Note that developing custom attack signatures is an advanced method that requires familiarity with a specific rule syntax.
  • The Assigning Attack Signatures to Security Policies chapter of the BIG-IP Application Security Manager: Attack and Bot Signatures manual
  • K82512024: Managing BIG-IP ASM Live Updates (14.1.x and later)
  • K8217: Managing BIG-IP ASM attack signatures (11.5.x - 14.0.x)
  • K45558510: Filtering the Attack Signature List by the referenced CVE
  • The Writing Custom Attack Signatures chapter of the BIG-IP Application Security Manager: Attack and Bot Signatures manual
Server TechnologiesUse the Server Technologies setting under the General Settings of the Policy Configuration to define the types of back-end server technology (operating system, web servers, programs, frameworks, server-side applications, and so on) that your application runs on. This allows the BIG-IP Advanced WAF/ASM to select and apply the signatures/signature sets that are specific to the defined server technology. This helps to mitigate known vulnerabilities for the defined server technology so that your application is being protected. In addition to the Server Technologies setting, you can also turn on the Enable Server Technology Detection setting to allow the BIG-IP Advanced WAF/ASM system to automatically detect the back-end server technology based on the responses it has processed and then suggest protections specific to the detected server technology. This is especially useful when new systems are added or when the back-end server technology changes or when an attack signature update includes new server technology that applies to the security policy.The Adding Server Technologies to a Policy chapter of the BIG-IP Application Security Manager: Implementations manual.
Vulnerability assessment policy buildingUse BIG-IP Advanced WAF/ASM to integrate with tools such as Qualys or WhiteHat Sentinel if you have performed vulnerability assessment of your web application.The Using Vulnerability Assessment Tools with a Security Policy chapter of the BIG-IP Application Security Manager: Getting Started manual.
