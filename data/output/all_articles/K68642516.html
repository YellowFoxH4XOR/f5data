Description

There is a power shutdown on the VCMP host and when the VCMP host is powered up, the VCMP guest is not accessible. In other words, VCMP guest was not properly shutdown.

You are not able to access the VCMP guest via GUI and SSH.

Ping the VCMP guest is not responsive.

You are able to access the VCMP guest via vconsole. Once you access the VCMP guest via vconsole, chmand is constantly restarting.

Further check shows kern.log having the following repeated error message:
slot1/vcmp-guest-01 info kernel: chmand[25196] trap divide error ip:5661bdc4 sp:ff94bdd0 error:0 in libhal_internal.so.1[561c8000+77f000]

Environment

  • VCMP guest not accessible
  • VCMP guest was not properly shutdown
  • VCMP host was power shutdown (could be in a power maintenance)
  • VCMP is not network reachable
  • Able to vconsole to the VCMP guest
  • chmand restarting constantly

Cause

The VCMP guest is facing a kernel panic which was due to the unexpected shutdown of the VCMP host.

To avoid this from happening in the future, shutdown the VCMP guest before shutting down the VCMP host. Refer to K20081511 on how so shutdown the VCMP guest.

Recommended Actions

The only way to resolve the issue is to rebuild the VCMP guest. The steps to rebuild the VCMP guest are:

  1. Delete the VCMP guest
  2. Delete the Virtual Disk of the VCMP guest
  3. Create the VCMP guest (rebuild)
  4. Restore from UCS and/or configure the device sync with the Active BIG-IP pair and sync the configuration
