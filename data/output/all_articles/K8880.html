Known Issue

This is the result of a known issue. Attempting to modify a child HTTP class profile with a pool or redirect location may result in an error message that appears similar to the following example:

01070731:3: An HTTP class object (c435596) may not specify both a pool name and redirect location.

The issue occurs after you successfully create a child class based on a parent profile, and then you attempt to change the child class to a Pool or Redirect option in the profile.

For example:

Note: The following examples are from a BIG-IP ASM system. However, this issue also affects the BIG-IP LTM and WebAccelerator systems, as they can use HTTP classes.

Example of an HTTP class parent profile:

profile httpclass testparent {
   defaults from httpclass
   pool testpool
   redirect none
   url rewrite none
   asm enable
}

In the following example, the HTTP class child profile is created successfully and inherits settings from the parent profile. However, instead of using the pool, a URI path and Redirect path is specified:

profile httpclass testchild {
   defaults from testparent
   pool none
   redirect "http://bar.com/foo.html"
   asm enable
   paths "/foo/*"
}

If you delete /foo/* from the Paths option and replace it with /bar/*, when you click the Update button, an error message that appears similar to the following example is displayed:

01070731:3: An HTTP class object (testchild) may not specify both a pool name and redirect location.

F5 Product Development tracked this issue as CR100404 and it was fixed in version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, and WebAccelerator release notes.

This issue still exists in the BIG-IP 9.4 software branch.

Workaround

The issue occurs only when you attempt to modify the child class within the Configuration utility. Modifying the child class from the command line does not cause this issue and allows the update or change to occur.

To work around this issue, and change the path from /foo/* to /bar/* using the command line, perform the following procedure:

  1. Log in to the command line.
  2. Type the following command:

    bigpipe httpclass testchild paths '"/bar/*"'

  3. Save the changes by typing the following command:

    bigpipe save
