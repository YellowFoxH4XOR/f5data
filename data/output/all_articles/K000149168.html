K000149168: NGINX Cache and Disk Usage

Type
Support Solution
Published
2025-01-02
Updated
2025-01-02
Applies to
  • NGINX Products
  • NGINX Plus: R29, R33, R31, R30, R32

  • NGINX App Protect DoS
Source
https://my.f5.com/manage/s/article/K000149168

Description

  • You configured Nginx to cache server response.
  • With caching enabled, NGINX saves server/s responses in a disk cache and uses them to respond to clients without having to proxy requests for the same content every time.
  • A cached response is stored/written/created to a temporary file in a specific directory, automatically.
  • By default, NGINX creates and uses "/var/cache/nginx" directory for caching and several subdirectories under it including "client_temp"
  • You have query in regard to cache and its disk utilization, in particular "client_temp" directory. 

Environment

  • NGINX Plus
  • Caching
  • Disk utilization

Cause

  • If NGINX is enabled with cache and left to use the default path, then this can overwhelm the specific disk location "/var/cache/nginx" .

Recommended Actions

  • If one wish to use a different directory other than the default path, it is possible to do so using "proxy_cache_path" directive
  • It is also possible to control/manage file size through the use of "keys_zone"
  • Customizing the configuration path using proxy_cache_path directive helps control and improve disk management.
  • And with this control, it is further possible to manage file size, allocate different file directory and run some cronjob.

Additional Information

  • In the below example,
    • NGINX is configured with proxy_cache_path directive from within the HTTP block pointing the location of cached directory
    • the path is /tmp/nginx/jweb/cache
    • the name of the cache is my-cache
    • the size of the cache is 500 megabyte

HTTP Block


              proxy_cache_path /tmp/nginx/jweb/cache levels=2:2:2 keys_zone=my-cache:500m use_temp_path=off inactive=3d max_size=1600g manager_files=1000000 loader_files=1000000 purger=on;

Server /or Location Block

                location / {

                    proxy_pass             http://backend;
                    proxy_set_header       Host $host;
                    proxy_cache            my-cache;
                    proxy_cache_valid      200 301 15m;
                    proxy_cache_valid      404 302 304 1m;
                    proxy_cache_revalidate on;
                    proxy_cache_use_stale  error timeout invalid_header updating
                    ...

                }
