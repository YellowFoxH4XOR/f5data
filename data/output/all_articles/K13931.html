Known Issue

The BIG-IP GTM Configuration utility allows a monitor type called none to be incorrectly associated with a wide IP pool.

Impact

  • In BIG-IP GTM 11.x, wide IP pools associated with the monitor type none are not marked down. However, the existence of the monitor type may cause confusion.
  • In BIG-IP GTM 9.x through 10.x, wide IP pools associated with the monitor type none are marked down.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP GTM 11.x:
    • The Configuration utility lists monitor type none as a configurable monitor.
  • BIG-IP GTM 9.x through 10.x:
    • The Configuration utility lists monitor type none as a configurable monitor.
    • Wide IP pools associated with monitor type none are marked down. This will occur when the none monitor type is used either alone or with other monitors.
    • Log messages similar to the following example appear in the /var/log/gtm file:

      gtmd[3900]: 011ae0f2:1: Monitor instance none <IP_ADDRESS>:<PORT> UNKNOWN_MONITOR_STATE --> DOWN from gtmd (no reply from big3d: timed out)
      gtmd[3900]: 011a4003:1: SNMP_TRAP: Pool <POOL_NAME> member /Common/<VIP_NAME> (ip:port=<VIP_IP>:<VIP_PORT>) state change green --> red (Pool pool_one member /Common/<VIP_NAME>: Monitor none from gtmd : no reply from big3d: timed out)
      gtmd[3900]: 011a1005:1: SNMP_TRAP: Pool <POOL_NAME> state change green --> red (Pool <POOL_NAME>: No enabled pool members available)
      gtmd[3900]: 011a3004:1: SNMP_TRAP: Wide IP <WIDE_IP_NAME> state change green --> red (Wide IP <WIDE_IP_NAME>: No enabled pools available)

Workaround

To work around this issue, do not select the none monitor type.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.
