Description

Website not working via Portal Access, but it is working when accessing directly.
 

Environment

  • BIG-IP APM
  • Portal Access
  • Rewrite

Cause

There can be many reasons why a website does not work via Portal Access, but it is most commonly due to dynamic content, that is loaded and run on the client. This means that the necessary modifications to the file objects by the Portal Access Rewrite module is unable to detect what needs to be modified to make the website work.
In these situations, the best action is to open a Service Request with F5 Support, where if applicable a custom fix for your implementation may be created for you.
 

Recommended Actions

Gather the following information before opening a service request with F5 Support:

  1. Accessing the website directly.
    • Using HTTP-Watch you will need to access the website
    • Before you start ensure that you use the option in HTTP-Watch to clear all cache and cookies, Tools -> Clear Cache and All Cookies.
    • Once you open HTTP-Watch is will start recording immediately, if it doesn't , click the red record button in the top left, and then access the website
    • Once you have reached the point where you would normally have an issue when accessing via the Portal Access you can stop recording, by clicking the stop button.
    • Open the browser Developer Tools (F12 or Ctrl-Shift-I), then open the Console Tab and verify that there are no Javascript errors, then right click and save the console output. If there are any errors while accessing the website directly, then these will need to be corrected before continuing.
       
  2. Accessing the website via the Portal Access.
    • Again using HTTP-Watch, you must access the website via the Portal.
    • Before you start ensure that you use the option in HTTP-Watch to clear all cache and cookies.
    • Start recording and then access the website via Portal Access.
    • Once you have hit the error with the website, you can stop the recording.  It is very important that the method of navigation through the website should be the same as when going direct.
    • Open the browser Developer Tools (F12 or Ctrl-Shift-I), then open the console tab and right click, and save the console output.
       
  3. If you are able to provide a screen recording of the direct access of the website, and also via Portal Access this would be useful to use as well. However, if you cannot do screen recording, then screen snapshots at key points would be useful to us.
     
  4. Generate a fresh Qkview
     
When saving with HTTP-Watch it is important that you capture the first web page as it loads, otherwise we will ask you to re-capture it again.
Once you have collected the data, please upload this to the Service Request via the F5 Support Portal. Please also ensure that the filenames of the files clearly identify which are for direct access and which are for Portal Access.
Its possible that we may ask you for packet captures as well at some point, but it is not necessary to save these unless we ask for them.

 

Additional Information

HTTP-Watch is available to download for free from https://www.httpwatch.com/download/
Only the Basic Edition is required and it does not need to be licensed to capture data.
If for some reason you are unable to use HTTP-Watch, you can use the F12 browser Developer Tools to capture the website, but please be aware that the information it saves is less detailed than HTTP-Watch, and if there is information missing, we may have to insist that you use HTTP-Watch.
