Description

A VELOS system controller upgrade fails to start and returns an HTTP 500 error for the RESTCONF set-version API:

Failure for data/openconfig-system:system/f5-system-controller-image:image/set-version API. The server or an underlying service is unreachable.

Original error: Request failed with status code 500.

The failure correlates with confd messages indicating that the UpgradeActionHandler daemon timed out or became unavailable:

Worker socket query timed out daemon 'UpgradeActionHandler'

Daemon UpgradeActionHandler timed out

action() error {external_timeout, ""} for callpoint upgradehdlr

Daemon UpgradeActionHandler died

Environment

  • Product: F5OS-C (VELOS)
  • System controller software upgrade
  • Two system controllers and compute blades
  • Target software image and ISO are present and show a ready status
  • OpenShift cluster, controllers, and blades are healthy and in the cluster
  • Controller redundancy mode is set to auto

Cause

The upgrade request fails when the confd UpgradeActionHandler daemon times out or becomes unavailable while processing the RESTCONF set-version request.

Unrotated or oversized logs under /var/confd/log/, particularly snmp.log, are a likely contributing condition. The exact reason for the UpgradeActionHandler timeout may not be conclusively isolated.

Recommended Actions

  1. On both controllers, check the sizes of the confd logs:
    ls -lh /var/confd/log/
  2. If snmp.log or another log file is excessively large, truncate the affected file. For snmp.log, use:
    truncate -s0 /var/confd/log/snmp.log
  3. On the active controller, apply the workaround associated with Bug ID 1962261.
  4. Monitor the workaround execution for more than five minutes. Record the console output if any command fails or reports an error.
  5. Before retrying the upgrade, confirm that:
    • The target image and ISO remain present and ready.
    • Both controllers are healthy.
    • The chassis cluster is operational.
    • Redundancy mode is set to auto.
  6. Retry the controller upgrade.
  7. If the failure recurs, collect updated diagnostic data and record the exact time of the failed upgrade attempt so the RESTCONF request can be correlated with the confd logs.

Additional Information

  • A controller reboot or failover may not provide a reliable resolution if the UpgradeActionHandler timeout condition recurs after the service restarts.
  • The prefer-2 redundancy-mode condition is not applicable when redundancy mode is set to auto.
  • Historical hooks_daemon died or similar messages following a confd restart or controller reboot should not, by themselves, be interpreted as proof of chronic confd instability.
  • Bug ID 2150853 tracks log-rotation issues under /var/confd/log/.
  • Review log rotation on the system controllers to help prevent excessive log growth.
