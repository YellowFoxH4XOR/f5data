Known Issue

BIG-IP APM network access sessions may not be able to access network resources.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured with a network access profile-enabled virtual server.
  • There is a standard or forwarding virtual server configured in the disabled state.
  • Users have established a network access session.

Impact

Network resources are not accessible.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Network access sessions are unable to resolve DNS queries to destination network resources.
  • Destination network resources do not respond to ICMP pings or other client-initiated requests.

Workaround

To work around this issue, you can enable or delete the disabled standard or forwarding virtual servers. To do so, perform the following procedure:

Impact of workaround: The impact of the work around is dependent on the selected remediation. Enabling a virtual sever will allow the virtual server to process traffic based on the virtual server configuration. If the virtual server is deleted, the virtual server configuration will not be available for future use in the BIG-IP configuration.

Enabling a disabled virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. In the Name box, click the name of the disabled virtual server.
  4. From the State pull down menu, select Enabled.
  5. Click Update.
  6. Repeat steps 2-5 for each disabled standard or forwarding virtual server.

Deleting a disabled virtual server

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. In the Name box, click the name of the disabled virtual server.
  4. Verify that the virtual server State is set to Disabled.
  5. Click Delete.
  6. Confirm the deletion of the virtual server by clicking OK in the deletion pop-up box.
  7. Repeat steps 2-6 for each disabled standard or forwarding virtual server.
