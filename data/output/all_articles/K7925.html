Topic

The default behavior of the BIG-IP ASM system is to block and report all Request for Comment (RFC) compliance violations. This behavior prevents requests with improper formatting or header content from being sent to the server. There are some situations in which an administrator would want to send such requests to the server, such as when a line feed (LF) will be used as a line separator. RFC compliance is controlled through the use of an enforcement mask.

Each bit in the bitmask represents a non_rfc_compliance case. For each bit, a value of 0 (zero) means that the case is RFC compliant; a value of 1 means that the case is not RFC compliant. The bit count determines whether the BIG-IP ASM issues a NO_RFC_COMPLIANCE parse status or not. Each case of non-RFC compliance will be checked against the bitmask to determine whether to issue non RFC-compliant violation message.

The DEFAULT_non_rfc_bitmask setting represents checks for the following cases:

  • Header name with no header value (0x0002)
  • Several Content-Length headers (0x08)
  • Chunked request with Content-Length header (0x0010)
  • Bad multipart/form-data request parsing (0x080)
  • No Host header in HTTP/1.1 request (0x0200)

Enabling cases

You can enable different cases by adding the hexadecimal values together and then converting the resulting value to a decimal to assign to the non_rfc_bitmask.

For example, you can configure the non_rfc_bitmask internal parameter to send a message to the forensics log on the following cases for non-RFC violations:

  • LF line separator (0x04)
  • Several Content-Length headers (0x08)

The non_rfc_bitmask value for the above cases is 12. This value is determined by adding the hexadecimal values of each case together, then converting the sum from hexadecimal to a decimal value that is used for the non_rfc_bitmask value, as follows:

Hex(0x04 + 0x08) = Hex(0x0c) = Dec(12)

You can also disable this violation completely.

Changing the non_rfc_bitmask parameter

To change the non_rfc_bitmask parameter, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Click the name of the web application you are using.
  5. From the Application Security menu on the left, select Options.
  6. Select Advanced Configuration from the top menu.
  7. In the Search By Parameter Name box, you can search on request or full name non_rfc_bitmask.

    Note: This allows you to change the values according to need.

  8. Click Save.
  9. Click OK, then click OK again.

You will need to restart the BIG-IP ASM system from the command line for this change to take effect. To do so, type the following command:

bigstart restart asm
