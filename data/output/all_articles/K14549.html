Topic

This article discusses the effects of the bigd.mgmtroutecheck database key on BIG-IP health monitors.

Description

The bigd.mgmtroutecheck database key determines whether the BIG-IP system prevents health monitors from sending probes using the management port.

When this key is set to disabled, the system performs no routing checks on health monitor probes, and health monitors can send probes using the management port.

When this key is set to enabled, the system performs routing checks on health monitor probes; if a probe attempts to route through the management port, the system blocks it and logs an error message in the /var/log/ltm file that appears similar to one of the following examples:

  • Health check would route via mgmt port, node <ip_address>. Check routing table.
  • Health check would route via mgmt port, IP <ip_address> port <port>. Check routing table.

By default, the bigd.mgmtroutecheck database key is set to disabled.

Recommendations

When configuring pool members/nodes and their associated monitors, you should consider the following factors:

  • Pool members and nodes must reside on a network that is reachable by the Traffic Management Microkernel (TMM). Routes must be defined to reach nodes on non-local networks.
  • Enable the bigd.mgmtroutecheck database key to prevent unintentional configuration of a health monitor that sends probes by way of the management port.
