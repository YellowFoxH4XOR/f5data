Description

This article covers the reasoning behind SSL handshake failure for client authentication along with the following ssl_shim_vfycerterr connection errors reported within /var/log/ltm:
01260009:4: <VIP>:<port> -> <Client-IP>:<port>: Connection error: ssl_shim_vfycerterr:4198: alert(46) unsupported certificate purpose

The format of these errors is covered extensively within K29346112: Error Message: 01260009:4: Connection error: <ssl_function>:<function_id>: <error_reason> (<reason_code>).

Environment

  • Client SSL profile configured for Client Authentication with Client Certificate option in the profile set to Require.

Cause

The unsupported certificate purpose error reported within /var/log/ltm when client authentication failure occurs indicates that the client is attempting to authenticate with a certificate that was not explicitly issued with the purpose of being used for client authentication. The following openssl command can be utilized to confirm that:

openssl x509 -in /path-to-file/<cert-name>.crt -purpose -noout

Here is an example of what that output would appear like:

[johnsmith@bigip ~]$ openssl x509 -in client.crt -purpose -noout
Certificate purposes:
SSL client : No            <--------
SSL client CA : No
SSL server : No
SSL server CA : No
Netscape SSL server : No
Netscape SSL server CA : No
S/MIME signing : No
S/MIME signing CA : No
S/MIME encryption : No

CRL signing : No

OCSP helper CA : No

Time Stamp signing CA : No 

Recommended Actions

The BIG-IP is rightfully terminating the connection in this case and the recommendation from us is to generate a valid certificate for the client that is appropriately built and intended for client authentication usage. Once the proper certificate is received, you can use the same openssl command above to verify that "SSL Client" is set to 'Yes' after which it is ready to be utilized for client authentication.
