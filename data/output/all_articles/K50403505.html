Description

Virtual server receives data in numerous small TLS records per TCP segment on the server-side. On the client-side, the BIG-IP sends TLS records out individually, one per TCP segment.

For example:

Server         BIG-IP         TCP Len  Info
10.10.10.180 → 10.101.78.165  1460     IN  s1/tmm0 : Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data, Application Data

Note 20 x TLS data records in the above packet.

VS             Client         TCP Len  Info
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
10.30.30.180 → 10.150.10.198  60       OUT s1/tmm0 : Application Data
...                           ^^
                               |___ Sent out individually on the client side

Environment

  • Standard virtual server
  • TLS
  • Client + Server SSL profiles

Cause

This is expected behaviour. The BIG-IP is individually decrypting the small TLS data records received server-side, and forwarding/releasing the data on the client-side as fast as possible to avoid delay.

Recommended Actions

This behaviour should be addressed on the server side, if possible. Sending many small TLS data records is very inefficient. TLS data record size should be maximized to achieve the best TLS performance.

The BIG-IP's TCP behaviour can be altered by enabling Nagle's Algorithm in the virtual server's TCP profile. With this configuration, the BIG-IP would be expected to aggregate data into larger segments, which may improve TCP performance in this scenario. However, the TLS performance would still be poor, since both the BIG-IP and client still need to decrypt many TLS records.
