Issue

If the ARX proxy-user account associated with a namespace does not have share permissions set to Full Control for the back-end filer share, an error message will be logged every five minutes on the ARX system. The error message will be logged in the syslog or traplog every five minutes on the ARX system:

The error message logged to the syslog appears similar to the following example:

2008-03-11T13:53:13.473+0000:SupARX1k4:1-1-ACM-1416:L2SW_LVL7-0-5-MSG5:: SNMP TRAP: shareWriteProbeFail (719) shr '<NAMESPACE>:/<VOLUME>:<SHARE>', name <EXTERNAL FILER NAME>, ip <IP ADDRESS OF EXTERNAL FILER>, : Write probe failure encountered

The error message logged to the traplog appears similar to the following example:

Tue Mar 11 13:53:13 2008 - shareWriteProbeFail (719) shr '<NAMESPACE>:/<VOLUME>:<SHARE>', name <EXTERNAL FILER NAME>, ip <IP ADDRESS OF EXTERNAL FILER>, : Write probe failure encountered.


    Note: The shareWriteProbeFail messages will not cause client access issues to the namespace virtual IP address or access to the back-end filer resources.

    The ARX proxy-user account information is listed in the proxy-user section of the global configuration. To view the global configuration, type the following command from the command line:

    show global-config

    For the specific steps required to set the share permissions for the proxy-user to Full Control on a back-end filer share, refer to the product documentation for the back-end filer. However, for general reference, perform the following procedure:

    1. Log on to the domain controller for the back-end filer.
    2. Open Computer Management.
    3. Select Connect to Another Computer.
    4. Select the back-end filer system that hosts the share.
    5. From System Tools select Shared Folders.
    6. Select Shares.
    7. Right-click the share to be modified and select Properties.
    8. Click the Share Permissions tab.
    9. Add the proxy-user account and allow Full Control permissions.
