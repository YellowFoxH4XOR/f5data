Description

This article explains how to adjust the vCPU allocation for tenants on F5OS rSeries appliances after initial deployment.

Environment

  • F5OS
  • BIG-IP tenants deployed on F5OS

Cause

Changing vCPU allocation for a deployed tenant requires the tenant to be in the "Provisioned" state. Attempting to change vCPU allocation while the tenant is in the "Deployed" state is not permitted through GUI and will result in an error on CLI.

Answer/Recommended Actions

It is safe and supported to increase the vCPU allocation for a tenant after it has been deployed. The process requires temporarily moving the tenant to the "Provisioned" state, updating the vCPU allocation, and then redeploying the tenant. The steps are as follows:

  1. Move the tenant to the "Provisioned" state:
    1. This stops the tenant and prepares it for resource changes.
  2. Update the vCPU allocation (and memory, if needed) for the tenant.
    1. Memory allocation is automatically adjusted based on the number of vCPUs
  3. Redeploy the tenant by setting its state back to "Deployed".
    1. The tenant will restart with the new resource allocation. 

Additional Information

  • You can allocate vCPU values only in multiples of 2 (e.g.,2, 4, 6, 8, 10, 12, 14, 16).
  • The combined vCPU allocation for all tenants must not exceed the platform maximum (e.g., 28 vCPUs for r10800).
  • If high availability (HA) is configured, ensure both tenants have identical vCPU and memory allocations for optimal failover behavior.
  • The tenant will experience a brief outage during this process.
