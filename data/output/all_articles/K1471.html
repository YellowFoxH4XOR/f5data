Topic

When the BIG-IP system is configured to use Secure Socket Layer (SSL) re-encryption, the system receives the SSL-encrypted packet on the SSL proxy, which is bound to an accessible interface.

The SSL proxy decrypts the packet and sends it to a virtual server (on the loopback interface, by default) that load balances the unencrypted connection to a node and applies any persistence that is configured on the virtual server's pool. The node that receives the connection should be configured to send the return traffic to the BIG-IP system, where it is intercepted by the virtual server.

For re-encryption, the virtual server sends the traffic to a special proxy process that is listening on the same port as the SSL proxy, but is configured on the loopback interface.

For example, if the external SSL proxy is listening on port 443, the traffic will be passed to 127.0.0.1:443 for re-encryption. If the proxy is listening on port 4567, the traffic would be passed instead to 127.0.0.1:4567 for re-encryption.

If you use the SSL proxy with a target server, rather than a target virtual server, the packet never leaves the SSL proxy; instead, it is received by the BIG-IP system on 205.229.151.10:443, is decrypted, then re-encrypted, and is sent directly to the server.
