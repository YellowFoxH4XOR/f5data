K10601146: Database certificates with an IP address or an invalid CN causes NGINX Controller to become unresponsive

Known Issue

When connecting to a database server that uses certificates with an IP address instead of a fully qualified domain name (FQDN), or a Common Name (CN) that is invalid, the NGINX Controller may become unresponsive. The system becomes unresponsive until a valid certificate is provided.

This issue occurs when one of the following conditions is met:

  • NGINX Controller connects to a database server that uses certificates with an IP address instead of an FQDN.
  • NGINX Controller connects to a database server that uses certificates with an invalid CN.

Impact

The NGINX Controller becomes unresponsive.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The API gateway process does not respond or process requests as expected.

Resolution

Status

Workaround

To work around this issue, you can use a database certificate that uses an FQDN instead of an IP address. You can also use a certificate where the IP address is mentioned in the Subject Alternative Name as DNS type.
