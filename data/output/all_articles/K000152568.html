K000152568: AS3 Updates Fail with Timeout Errors Due to Large Internal Data-Groups on BIG-IP LTM

Type
Support Solution
Published
2025-08-22
Updated
2025-08-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.6
Source
https://my.f5.com/manage/s/article/K000152568

Description

When attempting to submit AS3 (Application Services 3 Extension) updates to BIG-IP LTM, requests may fail with timeout errors. The following error messages can be observed in the logs:

  • Getting internal data-groups for state maintenance failed (timed out)

  • Error: GET .../mgmt/tm/ltm/data-group/internal?$filter=partition%20eq%20Common Getting internal data-groups for state maintenance failed (timed out)

  • PATCH .../mgmt/tm/ltm/data-group/internal/~Common~appsvcs~____appsvcs_lock Refreshing global lock failed (timed out)

  • [WARNING][RestOperation] Unable to generate error body for GET ... 400: java.lang.IllegalArgumentException: Message body size of XXXXX bytes exceeds the maximum allowed size of 33554432 bytes

AS3 POST requests may return HTTP status code 202 (Accepted) but never complete, and subsequent AS3 updates continue to fail until services are restarted.

Environment

  • Product: BIG-IP LTM
  • AS3 (Application Services 3 Extension) in use
  • Large number of internal data-group entries present (tmsh list ltm data-group internal output shows hundreds or thousands of lines)

Cause

Failed or stuck AS3 declaration data is left in LTM internal data-groups, specifically entries named ____appsvcs_declaration. These accumulate over time and cause the message body size for REST API operations to exceed the maximum allowed limit, resulting in timeouts and failures when processing new AS3 updates.

Recommended Actions

  1. Remove Stuck Data Group Entries
    In the BIG-IP GUI, navigate to Local Traffic > iRules > Data Group Lists. Identify and remove all data group entries named similar to ____appsvcs_declaration-<Epoch Timestamp>.
  2. Restart Services
    After removing these problematic data group entries, restart the following services:

    bigstart restart restjavad

    sleep 20

    bigstart restart restnoded


    Note: Restarting these services will temporarily interrupt REST API access but does not impact production traffic.
  3. Re-attempt AS3 Update
    Submit your AS3 declaration again and verify that it completes successfully.
  4. Monitor for Recurrence
    If this issue recurs, repeat the cleanup process.
    Review automation or AS3 workflows to ensure declarations are not leaving excessive or orphaned data group entries behind.
  5. Check Memory and Timeout Settings
    Ensure memory and timeout settings are appropriately configured.
    Note: Increasing these alone will not resolve issues if large or stuck data groups persist.
