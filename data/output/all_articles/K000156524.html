K000156524: SNI extension empty field

**Description:**

When configuring a BIG-IP LTM virtual server with multiple serverssl profiles for mutual TLS (MTLS), the SNI extension field may appear empty in SSL traffic analysis tools (such as ssldump). This results in BIG-IP always selecting the default serverssl profile (with "SNI Default" enabled) rather than the intended custom profile, preventing correct SNI-based profile selection.

 

**Environment:**

- Product: BIG-IP LTM

- Platform: F5-BIG-LTM-R5600, C129

- Version: 17.5.1

- Configuration details:

- Virtual server configured with multiple serverssl profiles

- MTLS required for backend communication

- SNI extension used to select appropriate serverssl profile

 - Example host: example.com.

- Example profile: serverssl_example_mtls

 

**Cause:**

The virtual server's serverssl-use-sni property is set to "disabled." This prevents BIG-IP from using the SNI value to select the correct serverssl profile, resulting in use of the default profile for all connections.

 

**Recommendations:**

1. Enable SNI-based serverssl profile selection on the virtual server:

```

tmsh modify ltm virtual <virtual_server_name> serverssl-use-sni enabled

tmsh save sys config

```

2. Ensure each custom serverssl profile has the "Server Name" field set to the expected backend hostname (e.g., "example.com") so that proper SNI matching occurs.

3. Apply and verify that the correct serverssl profiles are attached to the virtual server and confirm via SSL handshake inspection that SNI is populated and correct profiles are selected.
