Description

NGINX Ingress Controller configured for OpenID Connect (OIDC) authentication fails to refresh access tokens after expiration. Users experience repeated 401 Unauthorized errors after the initial token expires, even though the refresh process appears to be triggered. Log messages indicate:

expired JWT token

js: OIDC success, refreshing session

status=401

The same expired token is reused after the refresh attempt, resulting in failed access.

Environment

  • Product: NGINX Ingress Controller
  • Version: 5.3.0
  • OIDC authentication enabled via openid_connect.js
  • Key-value store used for session and token management
  • Custom configuration: oidc-refresh-tokens-timeout: 10m
  • JWT token expiration: 5 minutes
  • No changes to the OIDC refresh block except for client_max_body_size 100m;

Cause

A non-default value for oidc-refresh-tokens-timeout was set to 10 minutes. This setting controls the lifetime of refresh tokens in the internal key-value store. When set to 10 minutes, refresh tokens are deleted from the key-value store before they can be used for subsequent refresh operations, resulting in failed token refresh and persistent 401 errors after the initial token expires.

Answer/Recommended Actions

  1. Remove or comment out the custom oidc-refresh-tokens-timeout: 10m setting from your configuration.
  2. Allow the refresh token timeout to use the default value (24 hours).
  3. Only adjust the timeout if your identity provider issues tokens with a validity period longer than the default.
  4. After making this change, monitor the system to ensure that token refresh works as expected and users do not encounter 401 errors after the access token expires.

Additional Information

  • The default timeout values are 1 hour for access and ID tokens, and 24 hours for refresh tokens.
  • These settings are exposed to allow for increased timeouts if required by your identity provider.
  • Setting a shorter timeout than the token validity period can cause unexpected authentication failures.
