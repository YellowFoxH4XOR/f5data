K7132: BIG-IP buffers up to 62 packets of HTTP request header data for delayed-binding connections

Applies to

Topic

The BIG-IP system can buffer up to 62 packets (TCP segments) of HTTP request header data for delayed binding connections. In cases where the HTTP request header spans across more than 62 data packets for a connection, the BIG-IP system may fail to process the full contents of the header for the purpose of establishing a delayed binding load balancing decision. This is a known limitation of delayed binding virtual servers in BIG-IP version 4.x.

For example, if cookie persistence is configured for a pool, and the cookie is received by the BIG-IP after the 62nd packet is received in a connection, the BIG-IP system will fail to read the cookie header, and the persistent connection will fail. In this case, the request will be load balanced according to the load balancing method defined for the pool.
