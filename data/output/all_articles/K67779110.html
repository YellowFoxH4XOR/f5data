K67779110: Traffic not passing through forwarding virtual server after upgrading to BIG-IP AFM V15.1.0

Source

Description
Inbound listeners may cause traffic to fail through an IP Forwarding Virtual Server after software upgrade to BIG-IP AFM V15.1.0.

Environment

  • BIG-IP AFM V15.1.0
  • AFM NAT 
  • After Upgrade
  • Forwarding-IP Virtual Server 

Cause
In BIG-IP AFM V15.1.0, a new feature added called 'inbound listeners and hairpin' mode.
Inbound/hairpin configuration is enabled on a security NAT source translation object, which will cause inbound listeners to listen on NAT IP's.

For Example: 
ltm virtual /Common/vs_ip_forwarding {
    destination /Common/10.10.10.10:0
    ip-forward
    last-modified-time 2020-03-18:20:06:08
    mask 255.255.255.255
    profiles {
        /Common/routing { }
    }
    security-nat-policy {
        use-device-policy yes
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    translate-address disabled
    translate-port disabled
}

security nat source-translation /Common/NAT_translation {
    addresses {
        10.10.10.10 { }
    }
    egress-interfaces-disabled
    hairpin-mode enabled   
    icmp-echo enabled
    inbound-mode endpoint-independent-filtering
    ports {
        1024-65535 { }
    }
    traffic-group /Common/traffic-group-1
    type dynamic-pat
}

The connection is expected to reach the  vs_ip_forwarding Virtual server, however, due to higher priority on the inbound listener over the virtual server listener, the SSH connection is forwarded to NAT_translation, A source translation object, where inbound mode and the hairpin is enabled

Recommended Actions

To work around the issue you may follow any of the below procedures. 

  1. Disable both inbound mode and hairpin mode on NAT configuration.

  2. Use a different NAT IP which is not the same as Forwarding IP Virtual Address.
