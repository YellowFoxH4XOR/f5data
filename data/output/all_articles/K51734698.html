K51734698: Changes Pending after updating Device Certificate on HA pair

Type
Support Solution
Published
2022-01-23
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K51734698

Description

After successfully establishing the HA pair, update the device certificate on both peers. Afterwards, both show a sync status of "Changes Pending".

  • The Device Certificates were recently updated.
  • Syncing to the group, doesn't resolve the issue.
  • Reverting back to the original certificates resolves the issue, both now are "In Sync"

Environment

  • Big-IP
  • HA pair
  • Update the device certificate on each peer

Cause

The certificate name needs to match on both sides. The underlying certificate/key pair can be different, but the names need to be the same on both sides.

Recommended Actions

Rename the device certificate and key to match on both sides. Confirm that each are still unique using openssl.

  1. Create self signed certificate and key.

    Template:  
    openssl req -x509 -nodes -newkey rsa:<keysize> -keyout <key_path_and_name> -out <cert_path_and_name> -days <# of days>

    Example:
    openssl req -x509 -nodes -newkey rsa:2048 -keyout /config/ssl/ssl.key/devcert-bigip1.key -out /config/ssl/ssl.crt/devcert-bigip1.crt -days 3650
    openssl req -x509 -nodes -newkey rsa:2048 -keyout /config/ssl/ssl.key/devcert-bigip2.key -out /config/ssl/ssl.crt/devcert-bigip2.crt -days 3650
     
  2. Install the new SSL private key and self-signed certificate in the BIG-IP filestore on each device. Example:

    BIG-IP1
    tmsh install /sys crypto key devcert-bigip1.key from-local-file /config/ssl/ssl.key/devcert-bigip1.key
    tmsh install /sys crypto cert devcert-bigip1.crt from-local-file /config/ssl/ssl.crt/devcert-bigip1.crt

    BIG-IP2
    tmsh install /sys crypto key devcert-bigip2.key from-local-file /config/ssl/ssl.key/devcert-bigip2.key
    tmsh install /sys crypto cert devcert-bigip2.crt from-local-file /config/ssl/ssl.crt/devcert-bigip2.crt
     
  3. Copy to the Device Certificate location. Ensure the destination names are the same on each device.

    cp /config/ssl/ssl.key/devcert-bigip1.key /config/httpd/conf/ssl.key/newdevcert.key
    cp /config/ssl/ssl.crt/devcert-bigip1.crt /config/httpd/conf/ssl.crt/newdevcert.crt

    cp /config/ssl/ssl.key/devcert-bigip2.key /config/httpd/conf/ssl.key/newdevcert.key
    cp /config/ssl/ssl.crt/devcert-bigip2.crt /config/httpd/conf/ssl.crt/newdevcert.crt
     
  4. Install the newly created certificate & key pair as the device certificate for management on both BIG-IPs.

    tmsh modify sys httpd { ssl-certfile /etc/httpd/conf/ssl.crt/newdevcert.crt ssl-certkeyfile /etc/httpd/conf/ssl.key/newdevcert.key }
     
  5. Confirm the certificates are different on each BIG-IP. 

    openssl s_client -connect <mgmtIP>:443 -showcerts

    Though tmsh list sys httpd all-properties show the same name, newdevcert*, the openssl command shows the different CN names on each device.

    tmsh list sys httpd all-properties
    sys httpd {
    ...
        ssl-certfile /etc/httpd/conf/ssl.crt/newdevcert.crt
        ssl-certkeyfile /etc/httpd/conf/ssl.key/newdevcert.key
    ...
    }
