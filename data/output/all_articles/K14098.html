Known Issue

A virtual server may intermittently cause HTTP Keep-Alive connections to use a self IP address as the secure network address translation (SNAT) address.

This issue occurs when all of the following conditions are met:

  • The virtual server uses the OneConnect profile.
  • The virtual server uses the iRule CLIENT_ACCEPTED event with the snatpool command.

Impact

The connection from the BIG-IP system to the pool member may fail depending on the configuration of the intermediate devices between the BIG-IP system and the pool member.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H379835 on the Diagnostics > Identified > Low screen.
  • The source IP address for the connection from the BIG-IP LTM system may change intermittently between the affected VLAN's self IP address and the snatpool IP address.

Workaround

To work around this issue, you can modify the iRule to use the snatpool command at an event other than the CLIENT_ACCEPTED event, such as HTTP_REQUEST. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system. However, F5 recommends that you verify the modified iRule is applicable to your environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Select the name of the affected iRule to be modified.
  4. In the Definition text box, change the iRule CLIENT_ACCEPTED event to another applicable event.

    For example:

    HTTP_REQUEST
  5. Click Update.
