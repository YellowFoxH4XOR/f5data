Description

When an upgrade is completed, in rare circumstances you may run into a condition where your newly-upgraded BIG-IP Virtual Edition reports that your target version is not allowed.

Environment
  • BIG-IP Virtual Edition
  • Any type of license (lab, trial, production, etc.)
  • Upgrade is just finished and the new version has been booted

Cause

This is expected behavior. 

Historically, many Virtual Edition licenses had certain version restrictions in place; typically, this is found in licenses that were provided prior to around 2014.  

Recommended Actions

If you see this message, you must obtain a new license from F5 or your vendor of choice to upgrade to your desired target version.  Please contact your account team for assistance in obtaining a new license.

In the meantime, roll the upgrade back and upgrade to the maximum supported version that the license will allow.

Note: Downgrading your software is not recommended except in cases where an upgrade fails - at which point, one should roll back to the version they were running when the upgrade process was started.  For reference, please see K14568 for our support on downgrades.  To this end, if you are on a version that has reached its EoTS date and you have been running for some time, downgrading is extremely inadvisable due to the need to manually re-add configuration objects; the best bet is to simply contact your account team for a new license.

Important: The following example recommends you look inside the file bigip.license.  Under no circumstances whatsoever should you modify the contents of this file.  Modifying the file can result in malfunction.

To determine which versions are valid, you may look in /config/bigip.license using the tool of your choice (e.g., 'grep', 'less', 'more', 'cat', etc.).

Consider the example of running 13.1.0.2 - and you have upgraded to 16.1.2 and encountered this message.  To determine which versions are valid per the license, locate the word "version" in /config/bigip.license:  open /config/bigip.license in a text editor and you should see something like this somewhere in the file:

Exclusive_version :                10.*.*
Exclusive_version :                11.*.*
Exclusive_version :                12.*.*
Exclusive_version :                13.*.*
Exclusive_version :                14.*.*
Exclusive_version :                15.0.*
Exclusive_Platform :               Z100

In this example, the earliest version that is acceptable per the license is 10.0.0 and the latest is 15.0.1.4.  By contrast, you cannot install anything from 15.1.x or newer without replacing the license.

After you have found this, note which versions are still supported by F5 as per K5903. 

Back to the example, you will note that 15.0.x is the latest version supported on this license, and that 14.x is allowed implies that 14.0.x is also acceptable on this license - but neither 14.0.x or 15.0.x are supported by F5 any longer as per K5903, and as per K4918 no engineering hotfixes will be provided for versions that have reached their End of Technical Support (EoTS) dates.  So if one starts on 13.1.0.2 and with the given restrictions, the highest available and supported target version would be the latest of 14.1.x or 13.1.x.

Additional Information

Please note that F5 Support is unable to modify any license allowances whatsoever.  Even so, if you have any questions, do not hesitate to open a service request.

The text as excerpted in the example given above will not change in your license file when the license is reactivated under any conditions whatsoever; here, you can install 15.0.1.4 unimpeded, but please understand that any support for any version that has reached our end of technical support date (EoTS) is provided as reasonable effort and no engineering hotfixes will be provided as per K4918 to fix any known issues in such a version.  As a matter of best practice, then, do not install a version that is no longer supported by F5.
