Known Issue

In a high availability (HA) pair configuration, the BIG-IP system sends an RST to all incoming statemirror connections from its peer. This issue occurs when any of the following conditions are met:

  • The port lockdown Allow Default list is explicitly configured to include TCP 1028, and the self IP address uses the Allow Default port lockdown setting.
  • The port lockdown for a specific self IP address is explicitly configured to use the Allow Custom list that includes TCP 1028.

For example, if the port lockdown for the self IP address 192.168.1.1 is configured to use the Allow Custom list that includes TCP 1028, the BIG-IP system sends an RST to incoming statemirror connections received on 192.168.1.1:

self 192.168.1.1 {
netmask 255.255.255.0
vlan internal
allow {
tcp bgp
tcp https
tcp 1028
udp cap
}
}

Port 1028, which is used for connection and persistence mirroring (statemirror), is always allowed in an HA pair configuration, regardless of the port lockdown settings. For more information about port lockdown behavior, refer to K7317: Overview of port lockdown behavior (9.x).

Impact

The statemirror information between the HA pair is not exchanged; as a result, the standby unit will not be able to resume connections when a failover occurs.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H885537 on the Diagnostics > Identified > High page.
  • The standby unit does not have any mirrored connections in its connections table.
  • The standby unit does not have any mirrored persistence records.
  • You observe through the tcpdump command that the active unit sends an RST when the standby unit attempts to establish the statemirror connection.

Workaround

To work around this issue, you can configure port lockdown for the affected self IP address to remove TCP 1028 entry. To do so, perform the following procedures:

Impact of workaround: None

Removing entries from the Allow Default list

  1. Log in to the BIG-IP command line.
  2. Type the command appropriate for the version your BIG-IP system is running:

    BIG-IP 10.x and 11.x

    tmsh modify net self-allow defaults delete { tcp:1028 }

    BIG-IP 9.x

    bigpipe self allow default tcp 1028 delete

Removing entries from the Allow Custom list

  1. Log in to the Configuration utility.
  2. Navigate to Network > Self IPs.
  3. Click Self IP List.
  4. Click the affected self IP.
  5. From the TCP box under the Custom List section, remove the 1028 entry.
  6. Click Update.
