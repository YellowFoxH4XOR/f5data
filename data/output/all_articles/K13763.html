Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K13804: Enabling logging for BGP neighbor status changes (11.x - 12.x)

You should consider using this procedure under the following condition:

  • You want to enable logging for BGP neighbor status changes.

Description

When troubleshooting BGP neighbor adjacency issues, you may need to configure the BIG-IP system to log neighbor status events to the system log files. The status changes include some of the following events:

  • BGP notification received
  • Erroneous BGP update received
  • User reset request
  • Peer time-out
  • Peer closing down the session
  • Interface flap
  • Router ID changed
  • Neighbor deleted
  • Member added to peer group

To configure the BIG-IP system to log neighbor status events to the system log files, perform the following procedures:

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The system is licensed for the BGP advanced routing module.
  • You have familiarity with the Virtual TeletYpe Terminal (VTY) command-line environment.
  • You have command-line access to the BIG-IP system.

Procedures

Enabling the log-neighbor-changes BGP command

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To access the VTY command-line shell, type the following command.

    vtysh
  3. To enter enable mode, type the following command:

    enable
  4. From the prompt, to enter configuration mode, type the following command:

    config terminal
  5. To specify the logging priority type the following command:

    log record-priority
  6. Enable the BGP routing process by typing the following command:

    router bgp <ID>

    In this command, note the following:
    • <ID> is the autonomous system (AS) number.
  7. Enable log-neighbor-changes by typing the following command:

    bgp log-neighbor-changes
  8. Exit the current mode by typing the following command:

    end
  9. Save the configuration by typing the following command:

    copy running-config startup-config
  10. Log out of the vtysh shell by typing the following command:

    exit

Enabling syslog logging for BGP

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Determine whether the system has any existing syslog include configuration by typing the following command:

    bigpipe syslog include

    Note: If the system has existing syslog include configuration, you must back up the configuration prior to performing the following steps. You must then integrate the existing syslog configuration with the following configuration.

    For example, to save the existing syslog configuration, you would enter the following command:

    bigpipe syslog include > /var/tmp/existingsyslog.inc

  3. Use a text editor to create /var/tmp/bgpLog.inc:

    For example,

    vi /var/tmp/bgpLog.inc
  4. Copy the following syslog configuration to the bgpLog.inc file:

    Note: Integrate any existing syslog include configuration with the following configuration.

    syslog include "filter f_bgp_user {
    facility(user) and level (info,debug,warn,crit,alert,error,notice..emerg) and (match(\"NSM\") or match(\"BGP\"));
    };
    destination d_file {
    file(\"/var/log/zebos/bgp.log\" create_dirs(yes));
    };
    log {
    source(local);
    filter(f_bgp_user);
    destination(d_file);
    };"
  5. Import the syslog include configuration by typing the following command:

    bpsh < /var/tmp/bgpLog.inc

Enable log rotation for the /var/log/zebos/bgp.log file

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Determine if the system has existing logrotate include configuration by typing the following command:

    bigpipe logrotate include

    Note: If the system has existing logrotate include configuration, you must back up the configuration prior to performing the below steps. You must then integrate the existing logrotate include configuration with the following configuration. For example, to save the existing logrotate include configuration, type the following command:

    bigpipe logrotate syslog include > /var/tmp/existinglogrotate.inc

  3. Use a text editor to create the /var/tmp/bgpSyslogLogrotate.inc file:

    For example:

    vi /var/tmp/bgpSyslogLogrotate.inc
  4. Copy the following logrotate include configuration to the bgpSyslogLogrotate.inc file:

    Note: Integrate any existing logrotate include configuration with the following configuration.

    logrotate syslog include "/var/log/zebos/bgp.log
    {
    compress
    missingok
    notifempty
    sharedscript
    postrotate
    endscript
    }"
  5. Import the logrotate include configuration by typing the following command:

    bpsh < var/tmp/bgpSyslogLogrotate.inc
  6. Save the changes and sync to the peer device

    bigpipe save all

Viewing BGP logging

In the event that a BGP neighbor becomes unavailable, the BIG-IP system will create the /var/log/zebos/bgp.log file and generate neighbor status events. To review the log file, use a Linux command such as cat or less.
