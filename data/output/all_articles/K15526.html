Known Issue

Modifying the default stream profile may cause the mcpd process to enter a locked state.

This issue occurs when the following condition is met:

  • You have created a child profile based on the default stream profile.

Default profile configurations are stored in the /config/profile_base.conf file on the BIG-IP system. When you modify a default profile, the system creates a copy of that profile configuration in the /config/bigip.conf file, along with any changes to the profile. If at a later time you change the default profile to the default settings, the changes will be made to the appropriate profile configuration in the /config/bigip.conf file, but the profile configuration stanza will remain in the /config/bigip.conf file.

Note: F5 recommends that instead of modifying a default profile, you create a custom profile using the default profile as the parent profile. You can then modify some or all of the values defined in that profile, while leaving the parent profile settings at their default value.

Impact

The mcpd process becomes unresponsive after an upgrade or after loading the configuration, resulting in eventual restart of services and traffic failover in redundant BIG-IP systems.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Linux top command reports high CPU usage for the mcpd process, similar to the following example:

    PID USER      PR  NI  VIRT  RES  SHR S %CPU %MEM    TIME+  COMMAND
     5502 root      20   0  173m 113m  29m R 99.4  1.4   2:09.63 mcpd

  • The BIG-IP system periodically logs messages similar to the following example to both the terminal and to the /var/log/ltm file:

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all" - failed. -- Error: failed to reset strict operations; disconnecting  from mcpd.  Will reconnect on next command. The connection to mcpd has been lost, try again.

  • The BIG-IP system attempts to restart services to recover, and the system logs messages similar to the following example to the /var/log/ltm file:

    Aug 20 12:41:32 B6900-R21-S8 notice overdog[5754]: 01140029:5: HA daemon_heartbeat sod fails action is restart all.
    Aug 20 12:41:32 B6900-R21-S8 crit overdog[5754]: 01140106:2: Overdog daemon calling bigstart restart.
    Aug 20 12:41:32 B6900-R21-S8 warning diskmonitor: 011d0002: Can not access the database because mcpd is not running.

  • You can view continual restarts with the bigstart status mcpd command:

    mcpd         run (pid 5502) 4 minutes, 4 starts

Workaround

To work around this issue, you can edit the /config/bigip.conf file and remove the default stream profile configuration stanza. To do so, perform the following procedure:

Impact of workaround: You must reload the configuration for the changes to take effect, which may cause a brief interruption in traffic processing.

Removing the modified default stream profile configuration from the /config/bigip.conf file

  1. Log in to the BIG-IP command line.
  2. Create a backup copy of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.sol15526

  3. Edit the /config/bigip.conf file using the text editor of your choice.
  4. Delete the default stream profile configuration stanza.

    For example:

    ltm profile stream /Common/stream {
        app-service none
        source none
        target none
    }

  5. Save the changes and exit the text editor.
  6. Restart services on the BIG-IP system by typing the following command:

    bigstart restart
