Description

When attaching the port-list to virtual server dest:port-list, the route domain of the virtual server is changed to the default value of 0, and the port-list is not correctly applied. This is encountered in the GUI but not in the CLI.

 

Environment

  • Using port-list along with virtual server in non-default route domain using the GUI.
  • Virtual Server created via GUI
  • Shared Objects created via GUI – ports list
  • Multiple route domains created via GUI
  • You are unable to use the GUI to attach a port-list that uses a non-default route domain to a virtual server.

Cause

Bug ID 881065: Adding port-list to Virtual Server changes the route domain to 0


Recommended Actions

Configure the Virtual server and edit matching criteria via tmsh following the below procedure:

   1. From GUI level apply all required settings to desired VS, including the earlier defined ports list.
It will remove RD number from the source address. Also, it will create a traffic-matching-criteria <VS_name>_VS_TMC_OBJ assigned to this VS.


   2. From CLI execute the command:

tmsh list ltm traffic-matching-criteria <VS_name>_VS_TMC_OBJ

and ensure there is everything that it should be. RD will be not visible yet in source address.
 

   3. From CLI execute the command:

tmsh modify ltm traffic-matching-criteria <VS_name>_VS_TMC_OBJ source-address-inline 0.0.0.0%3/0


NOTE: In example above %3 is an ID of desired route domain. Please set the proper ID here.


   4. From CLI execute the command:

tmsh list ltm traffic-matching-criteria <VS_name>_VS_TMC_OBJ

and ensure there is everything that it should be. Now RD should be visible in the source IP.

   5. From CLI execute the command:

tmsh modify ltm traffic-matching-criteria <tmc obj name> route-domain <RD name>

NOTE: In example above <tmc obj name> is the name of traffic-matching-criteria object and <RD name> is the name of desired route domain. Important: <RD name> is the name, not the ID. Please set proper values here.
