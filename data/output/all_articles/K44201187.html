Description

When deleting an existing SSLO service, the expected behavior is for all the configuration objects that were created as part of the iApp should get deleted. However, there are some cases where some MCP objects are left behind, for some reason. When this happens, users might see a banner on the SSLO Configuration GUI with an error message similar to the following:

One or more SSL Orchestrator configurations are in an incorrect state. Look for errors in /var/log/restnoded/restnoded.log for corrective action to those configurations before making additional changes to avoid further errors.


In /var/log/restnoded/restnoded.log, an error message similar to the one below can be seen:

Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] ============================================
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] App Name: ssloN_from_dlp_v1512 App Type: null
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] Device 192.168.95.13 is having hanging MCP objects and need cleanup
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] Device 192.168.95.12 is having hanging MCP objects and need cleanup
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] App config corrupted, please resolve before proceed
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] ============================================
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] ============================================
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] App Name: ssloN_to_dlp_v1511 App Type: null
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] Device 192.168.95.13 is having hanging MCP objects and need cleanup
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] Device 192.168.95.12 is having hanging MCP objects and need cleanup
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] App config corrupted, please resolve before proceed
Tue, 12 May 2020 03:55:58 GMT - severe: [SSLO] ============================================

Environment

  • SSL Orchestrator

Cause

There are various causes why this error message will appear on the SSLO GUI.

In the case where the error appears after deleting an existing SSLO service, it was found out that while the respective iApp blocks have been deleted, some MCP objects are still present in the config. Due to this mismatch, the error message is being displayed.

Recommended Actions

To recover from the current state, the config objects that have been left behind needs to be manually deleted.

1. Review /var/log/restnoded/restnoded.log, as well as, your SSLO configuration to know which config objects were left behind, after the SSLO service deletion.

For example: In our restnoded.log example above, the culprit config objects are ssloN_from_dlp_v1512 and ssloN_to_dlp_v1511

2. For deployments that have an HA pair: Check the HA status for both boxes. Navigate to SSL Orchestrator  ››  Configuration on the top right corner beside the version.
     If the Overall Status is Good for both devices, proceed to the next steps. Otherwise, the HA needs to be fixed first.

NOTE: If the HA status is not good on both units, STOP HERE and DO NOT proceed with the rest of the steps. Take screenshots showing the SSLO HA status of both units and provide to F5 Support so they can check.

3. From CLI, execute the below tmsh command: (For HA pair deployments, run the command on both boxes)

          # tmsh delete sys application service <application_service_name>

    For example, to delete the 2 culprit objects we saw in our restnoded.log example above, run the following tmsh command:

          # tmsh delete sys application service ssloN_from_dlp_v1512.app/ssloN_from_dlp_v1512 ssloN_to_dlp_v1511.app/ssloN_to_dlp_v1511

4. Navigate back to the SSLO GUI & refresh the page. The error message should now be gone.
