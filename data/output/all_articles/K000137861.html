Description

You are receiving "Command bash with an unshared alias list" heuristic flag on ihealth

Environment

BIG-IP

Cause

The heuristic flagged on your BIG-IP in iHealth indicates that you have bash commands aliased with an unshared alias list. This can pose a security risk, as it allows users to execute arbitrary commands without proper authorization.

Recommended Actions

Here are the steps on how to fix this:

**1. Identify the aliased commands:**

To identify the aliased commands, you need to check the `.bashrc` file for each user account on your BIG-IP. You can do this by logging in to the BIG-IP via SSH and using the following command:

cat /etc/bashrc

This will display the contents of the global `.bashrc` file. You can then search for the keyword `alias` to find any aliased commands.

To view the `.bashrc` file for a specific user, you can use the following command:

cat ~user_name/.bashrc

**2. Verify the alias list:**

Once you have identified the aliased commands, you need to verify if the alias list is shared or unshared. Shared alias lists are prefixed with the `export` keyword, while unshared alias lists are not. Unshared alias lists are only accessible to the current user and are not inherited by other users.

For example, the following alias is **shared**:

export alias ls="ls -l"

While the following alias is **unshared**:

alias ll="ls -l"

**3. Remove unshared aliases:**

If you find any unshared aliases, you should remove them from the `.bashrc` file. This will prevent them from being used by other users.

You can use the following command to remove an alias:

unalias alias_name

For example, the following command removes the alias `ll`:

unalias ll

**4. Restart the shell:**

After removing the unshared aliases, you need to restart the shell for the changes to take effect. You can do this by logging out and logging back in, or by using the following command:

source ~/.bashrc

Additional Information

* It is recommended to avoid using unshared aliases altogether. If possible, you should use shared aliases or directly type the full command.

* You can review the F5 documentation for more information about bash aliases and security best practices: https://clouddocs.f5.com/products/orchestration/ansible/devel/modules/bigip_cli_alias_module.html
