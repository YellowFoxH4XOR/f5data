K000159951: Threat Campaign Update Failures Due to asm_config_server Memory Exhaustion on BIG-IP ASM 17.1.3

Source

Description

This article addresses an issue where ASM threat campaign updates fail to install on BIG-IP ASM systems running version 17.1.3 in a high availability configuration. The following symptoms may be observed:

  • Threat campaign updates do not complete successfully
  • Error messages in logs such as:

var/log/tomcat/liveupdate.log_truncated
...
2026-01-16 15:53:31 ERROR System:37 - Error executing the following command: '/usr/share/live-update/bin/apply_threat_campaigns {"filename":"/var/cache/tomcat/temp/Live-Update1665699593804409866/RPMS/packages/current_update_file.enc","payloadDirectory":"/var/cache/tomcat/temp/Live-Update1665699593804409866/PAYLOAD","isScheduled":false,"sigfile_status_update_mode":"Manual","staging":false,"update_type":"threat-campaigns","is_genesis_file":false} '.
Output:
Error: Fail handle payload files
...

var/log/ts/asm_config_server.log
...
asm_config_server.pl|INFO|Jan 16 15:53:31.035|6967|F5::ASMConfig::Handler::handle_error,,Code: 406, Error message = Process size (719093760) has exceeded max size (471859200)
...

Environment

  • Product: BIG-IP ASM
  • Version: 17.1.3
  • Features: ASM threat campaign updates enabled
  • Default asm_config_server memory allocation: 471 MB

Cause

The root cause is insufficient memory allocation for the asm_config_server process. By default, this process is limited to 471 MB, which can be exceeded during update operations, resulting in update failures and related error messages.

Answer/Recommended Actions

To resolve the issue, increase the memory allocation for the asm_config_server process and, if necessary, adjust management provisioning. Follow these steps during a maintenance window:

1.On the standby unit, edit the asm_config_server configuration file using a text editor (vi or nano):

    • vim /etc/ts/tools/asm_config_server.cfg

2.Locate and modify the following parameters:

    • Change MaxMemorySize=471859200 to MaxMemorySize=1073741824
    • Change AsyncMaxMemorySize=471859200 to AsyncMaxMemorySize=1073741824

3.Save the configuration file changes.

4.Restart the asm_config_server process:

    • pkill -f asm_config_server

5.Save the system configuration:

    • tmsh save sys config

6.Fail over to make the updated unit active and verify proper functionality with no traffic disruption.

7.Repeat steps 1–6 on the new standby unit.

8.Monitor system memory usage after the changes. If further memory is required for control plane processes, adjust the management provisioning as needed by modifying the provision.extramb database variable.

Additional Information

  • Only the ASM master in an HA pair will attempt to download and install updates by default.
  • The asm_config_server process restart does not cause the unit to go offline or disrupt traffic processing.
  • Management provisioning changes allow the system to allocate more memory to non-TMM (control plane) processes without impacting TMM memory allocation.
  • Monitor memory usage after changes to ensure system stability.
  • Changes to the asm_config_server.cfg file do not persist across upgrades. After upgrading, manually reapply these changes to the new volume before booting into it.
