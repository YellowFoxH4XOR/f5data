Known Issue

This is the result of a known issue. The BIG-IP Configuration utility does not correctly process configuration strings ending with an odd number of backslash characters ( \ ). If you define a monitor send string ending with a single backslash character, the Configuration utility saves the monitor. However, any subsequent attempt to load the configuration by using the bigpipe load command, or by performing a configsync operation will fail, resulting in a bigpipe parsing error message. For example, the following monitor contains a send string ending with a single backslash character:

monitor http_monitor {
   defaults from http
   recv "192.168.1.1"
   send "GET /index.htm HTTP/1.1\r\n\"
}

If you define the example monitor using the Configuration utility, and then attempt to load the BIG-IP configuration using the bigpipe load command, a bigpipe parsing error message similar to the following is output to the system console:

BIGpipe parsing error (Line <number>): 012e0010:3: The requested value (<value or text information>) is invalid ((<quoted string> | none)) for 'send' in 'monitor'

Note: The message reported will be different for each configuration, but will be similar in format to the example above.

F5 Product Development is tracking this issue as ID 247053 (formerly CR108588).
