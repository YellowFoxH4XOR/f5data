K000140187: No DHCP address after booting BIG-IP Next VE instance with more than one interface

Type
Support Solution
Published
2024-06-28
Updated
2025-09-02
Status
Legacy Content
Applies to
  • BIG-IP Next
  • BIG-IP Next LTM: 20.2.0
Source
https://my.f5.com/manage/s/article/K000140187

Description

Booting a BIG-IP Next VE instance with more than one interface results in no DHCP mgmt address being assigned. Instead, mgmt is addressed with 127.0.0.1 and there is no IP access to mgmt. When booting the same instance with all other interfaces disconnected excluding mgmt, the instance is reachable.

The address assigned to the Next instance can be seen at the console login screen.

 

Environment

  • BIG-IP Next
  • q35 on generic KVM or default Proxmox appliance
  • DHCP address assignment for management interface

The issue does not happen with hardware type pc on kvm, or VMware.

 

Cause

Legacy netplan files cause the interface to enter an unexpected state.

 

Recommended Actions

Use cloud-init to statically add an IP.

https://clouddocs.f5.com/bigip-next/latest/install/next_install_kvm_setup.html

 

Additional Information

The issue is tracked under ID1596385.
