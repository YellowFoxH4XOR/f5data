K000132773: Can't start apache after replacing TMUI SSL Cert

Applies to

Source

Description

Error when restarting httpd after generating new self-signed certificate 

The following error message was encountered when trying to restart httpd with command (bigstart restart httpd) :

httpd[26242]: [ssl:emerg] [pid 26242] (13)Permission denied: AH02201: Init: Can't open server certificate file /etc/httpd/conf/ssl.crt/server.crt

Environment

  • After device cert update
  • TMUI
  • httpd

Cause

In the case of the httpd daemon, if the security context of the device certificate and key uploaded to /var/tmp is set to "initrc_tmp_t" (which is the case in BIG-IP v14.1 and above), the httpd daemon won't allow access to the file when it is moved to the /config/httpd/conf/ssl.crt/ and /config/httpd/conf/ssl.key/ directories.

Recommended Actions

Use the restorecon command to resolve this issue:

# restorecon -RvF /config/httpd/conf/ssl.crt

# restorecon -RvF /config/httpd/conf/ssl.key

restorecon restores the default context of a file or directory by reading the default rules set in the SELinux policy.

If the wrong context is applied, restorecon automatically corrects it from the policy of the filesystem.
