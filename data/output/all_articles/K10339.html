Topic

During an intrusion, the intruder may modify the system time in an attempt to obscure log entries related to unauthorized activities on the system. As a result, whenever you suspect an intrusion attempt, you should audit the system for any changes made to the system time before attempting to perform further intrusion forensic analysis.

There are three ways the system time may be modified, each of which must be separately audited:

  • Modification of the system time zone
  • Modification of the system time using the date command
  • Automatic NTP clock corrections 

Auditing for modification of the system time zone

In order to audit changes to the time zone, MCP audit logging must have been enabled prior to the change. To enable MCP audit logging on the BIG-IP, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to System > Logs > Options.
  3. In the Audit Logging section, locate the MCP setting.
  4. Select Enabled from the drop-down dialog box.
  5. Click Update to save the configuration.

Time zone changes made to a system with MCP audit logging enabled are logged in the Audit log. You can view the relevant messages by browsing to System ->Logs ->Audit in the Configuration utility, or by viewing the the /var/log/audit file at the BIG-IP command prompt. Filter the relevant entries by searching for the database variable NTP.TimeZone. For example, the following log entries show a change of the time zone to Europe/Paris and then back to Europe/London:

mcpd[2103]: 01070417:5: AUDIT - user root - transaction #4043-1 - object 2676 - modify { db_variable { db_variable_name "ntp.timezone" db_variable_value "Europe/Paris" } }
mcpd[2103]: 01070417:5: AUDIT - user root - transaction #4210-1 - object 2676 - modify { db_variable { db_variable_name "ntp.timezone" db_variable_value "Europe/London" }

The /root/.bash_history file should also contain matching entries reflecting the changes. For example, the change of the time zone to Europe/Paris and then back to Europe/London produces the following log entries:

#1247149967
b db ntp.timezone "Europe/Paris"
#1247149980
b db ntp.timezone "Europe/London"

Note: Each entry in the .bash_history file is preceded by a line containing a number sign ( # ) followed by a timestamp indicating the time the command was invoked.The timestamps are expressed in UTC (Universal Time, Coordinated) using the Unix time format.

Auditing for modification of the system time using the date command

To audit manual changes to the system time, examine the contents of the /root/.bash_history file for any invocation of the date command with a parameter that would change the time. For example, the following log entries show the time advanced by 8 minutes:

#1247150520
date 07091550

Note: Each entry in the .bash_history file is preceded by a line containing a number sign ( # ) followed by a timestamp indicating the time the command was invoked.The timestamps are expressed in UTC (Universal Time, Coordinated) using the Unix time format.

To convert a Gregorian date to Unix time in UTC, type a command similar to the following:

date +%s -ud "Jul 9, 2009 15:50:00"

Note: Replace the date string Jul 9, 2009 15:50:00 with the date you want to convert.

The command displays the following output:

1247154600

To convert Unix time to a Gregorian date, type a command similar to the following:

perl -e 'print scalar gmtime(1247150520), "\n"'

Note: Replace the Unix time 1247150520 with the Unix time value you want to convert.

The command displays the following output:

Thu Jul  9 15:42:00 2009

Comparing the two Gregorian dates reveals the 8-minute discrepancy between the current time and the new system time set by the date command.

Note: For more information about the parameters that may be passed to the date command to manipulate or inspect the current system time, refer to the date command man page.

Auditing for automatic NTP clock corrections

To audit automatic clock corrections made by the NTP process on the BIG-IP, examine the /var/log/daemon.log file. The messages appear similar to the following examples.

The following entry is logged when NTP advances the time because the clock on the BIG-IP is running behind the actual time:

notice ntpd[6440]: time reset 299.046945 s

The following entry is logged when NTP retards the time because the clock on the BIG-IP is running ahead of the actual time:

ntpd[6825]: time reset -458.442974 s
