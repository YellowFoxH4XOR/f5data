Description

Abnormally high active connection counts may be observed on BIG-IP systems, with values increasing significantly (e.g., from ~100,000 to over 500,000) even though traffic patterns and new connection rates remain unchanged.

This anomaly is reflected in system metrics such as "Active Connections" and "New PVA Connections". No corresponding increase in CPU, memory, or throughput usage is seen. Connection tables do not clear as expected based on configured timeout settings; no error messages are generated. 

Environment

  • Virtual servers using "FastL4" profiles
    • PVA Acceleration option is set to "Full"
    • Offload State option is set to "SYN" or "embryonic"
  • LTM Module

Cause

This issue could be related to the known Bug ID 571333, where FastL4 virtual servers may not honor the TCP Handshake Timeout setting for hardware-accelerated flows (PVA offloaded). As a result, connections can remain active longer than intended and are not terminated according to the configured timeout values, causing an accumulation of active connections. 

Recommended Actions

To mitigate this Issue, you can follow the below recommended steps:

1. Update all affected FastL4 profiles by changing the "pva-offload-state" parameter from 'SYN' or 'embryonic' to 'establish'. This change ensures that hardware acceleration only occurs after the TCP handshake completes, allowing handshake timeouts to be enforced correctly.

# tmsh modify /ltm profile fastl4 <FastL4_profile_object> pva-offload-state establish

For example, to modify the FastL4 profile "My_FastL4_Profile", you can run the below sample command:

# tmsh modify /ltm profile fastl4 My_FastL4_Profile pva-offload-state establish

 

2. Save your configuration after making this change:

# tmsh save /sys config

 

Important Tip: The updated profile will apply immediately to new connections. Existing connections will continue with previous settings until they expire or are manually cleared. No reboot or service restart is required, unless you wish to clear all existing connections and enforce the new settings across all current sessions.
