Topic

This article applies to BIG-IP Next instances. For more information about other systems, refer to the following articles:

  • K05531172: Restoring the VELOS configuration to factory default settings
  • K20024872: Restore the rSeries configuration to factory default settings
  • K13127: Restoring the BIG-IP configuration to factory default settings (11.x - 17.x)
  • K000138126: Restore a BIG-IP Next Central Manager instance to factory default settings

You should consider using this procedure under the following conditions:

  • You have a BIG-IP Next instance managed by BIG-IP Central Manager
  • You want to restore the BIG-IP Next instance configuration to the factory default settings.

    Note: If your BIG-IP Next instance is not managed by BIG-IP Central Manager and you have lost or forgotten your password, you will need to delete the instance and re-deploy a new one.

Description

For BIG-IP Next instances managed by BIG-IP Next Central Manager, you can restore a BIG-IP Next instance to the factory default settings using the BIG-IP Next Central Manager webUI or API. This removes the instance's configuration and license and loads the default configuration onto the instance leaving the management IP configuration in place.

When you use the BIG-IP Next Central Manager webUI to restore a BIG-IP Next instance to factory default settings, you Delete the BIG-IP Next instance which removes the instance from inventory and resets the BIG-IP Next instance to factory default settings. All the data and content for the BIG-IP Next instance are removed, including the following:

  • QVKiew files
  • License
  • Backup files

When you use the BIG-IP Next Central Manager API, the BIG-IP Next Central Manager resets the BIG-IP Next instance to factory default settings but does not automatically remove the BIG-IP Next instance from inventory.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP Next Central Manager webUI and API.
  • You have access to a system with the curl and jq utilities installed.

Procedures

  • Use the BIG-IP Next Central Manager webUI
  • Use the BIG-IP Next Central Manager API

Use the BIG-IP Next Central Manager webUI

To restore a BIG-IP Next instance to factory default settings using the BIG-IP Next Central Manager webUI, perform the following procedure:

Impact of procedure: Performing the following procedure removes the BIG-IP Next instance from inventory, removes the instance's data, and resets the instance to factory default settings.

  1. Log in the BIG-IP Next Central Manager as an administrator.
  2. Go to Manage Instances.
  3. Select the check box next to the BIG-IP Next instance.
  4. Select ...Actions, then select Delete.
  5. Review the information, then select Delete Instance.
  6. Select Yes, Delete to confirm the action.

Use the BIG-IP Next Central Manager API

To restore a BIG-IP Next instance to factory default settings using the BIG-IP Next Central Manager API, perform the following procedure:

Impact of procedure: Performing the following procedure resets the BIG-IP Next instance to factory default settings.

The response will appear similar to the following example:

example

  1. Log in to the client system that has the curl and jq utilities installed.
  2. Save the BIG-IP Next Central Manager login token to a shell variable using the following syntax:

    <variable_name>=$(curl -sk -X POST -H "Content-Type:application/json" https://<bigip_next_cm_mgmt_address>/api/login -d '{"username":"<nextcm_admin>","password":"<nextcm_admin_password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -X POST -H "Content-Type:application/json" https://nextcm.example.com/api/login -d '{"username":"admin","password":"admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  3. Save the instance ID of the BIG-IP Next instance to a variable using the following syntax:

    <variable_name>=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://<bigip_next_cm_mgmt_address>/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="<bigip_next_instance_mgmt_ip>")| .id')

    For example, use this command to get the instance ID for the BIG-IP Next instance with management address 10.10.10.100 and save it to a variable named instance_id:

    instance_id=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://nextcm.example.com/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="10.10.10.100")| .id')

    You can use the echo $instance_id command to view the value of the instance_id variable.

  4. Set the BIG-IP Next instance configuration to factory default settings using the following syntax:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X PUT "https://<bigip_next_cm_mgmt_address>/api/device/v1/proxy/${<variable_name>}?path=/actions/factory-reset" -d '{"verify": true}'| jq

    For example,

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X PUT "https://nextcm.example.com/api/device/v1/proxy/${instance_id}?path=/actions/factory-reset" -d '{"verify": true}'| jq

    The example response indicates the status is PENDING:

    {
      "id": "7f687867-6446-4d93-ab9c-b7de8daaf6f8",
      "verb": "PUT",
      "uri": "/actions/factory-reset",
      "request": "{\"verify\":true}",
      "role": "FACTORY_RESET",
      "status": "PENDING",
      "message": {
        "code": "",
        "title": "",
        "detail": "",
        "links": null
      },
      "creationTime": "2023-09-20T19:39:10.418862Z",
      "updateTime": "2023-09-20T19:39:10.418862Z",
      "owner": "admin-cm",
      "authn": "local",
      "authz": "global"
    }

  5. To delete the BIG-IP Next instance and remove it from the BIG-IP Next Central Manager inventory, enter the following command:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X DELETE "https://nextcm.example.com/api/v1/spaces/default/instances/${instance_id}" -d '{"save_backup": false}'| jq

    The example response shows the path for the deletion task:

    {
      "_links": {
        "self": {
          "href": "/api/v1/spaces/default/instances/deletion-tasks/7b1f141d-2923-46f2-90eb-95a4de00a250"
        }
      },
      "path": "/api/v1/spaces/default/instances/deletion-tasks/7b1f141d-2923-46f2-90eb-95a4de00a250"
    }

  6. To confirm the instance was deleted, enter the following command to view the managed instances on the BIG-IP Next Central Manager to ensure the instance is no longer listed:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://nextcm.example.com/api/v1/spaces/default/instances" | jq
