K48366323: When clearing/deleting the SSL Orchestrator (SSLO) config sync may fail.

Support Solution
Published
2022-09-14
Updated
2024-04-04
Applies to
  • BIG-IP
  • F5 App Protect
  • F5 SSL Orchestrator: 17.X.X, 17.0.X, 16.1.X, 17.0.0, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K48366323

Description

When it is necessary to completely remove SSLO from a BIG-IP the  clear-rest-storage command is run. Afterwards when trying to sync it fails.

  • Sync fails
  • You may see an error message similar to this in /var/log/ltm:  01070712:3: Caught configuration exception (0), Values (/Common/ssloS_bluecoat.app/ssloS_bluecoat-t-4-connector) specified for Service Connect Agent (/Common/ssloP_dev_security_policy.app/ssloP_dev_security_policy_sslos_bluecoat_act_svc_connect_4_t_ag): foreign key index (connector_profile_FK) do not point at an item that exists in the database..

Environment

Relevant environmental factors specific to the topic

  • Deleting SSLO configuration
  • Topologies

Cause

The synchronization of SSLO has taken place outside of TMM using the REST mechanism. SSLO created TMM objects from a json file stored in SSLO. That has changed and they are now stored in iFiles within TMM.  So when only using clear-rest-storage command that may not clear the iFiles and the objects created from there.

Along with that just using clear-rest-storage alone may not work as desired. A SSLO Troubleshooting Guide has the complete steps to completely remove SSLO via the CLI.

In the SSLO configuration GUI there is also a Delete button when Topologies are created.

Recommended Actions

If the deletion fails...

  1. Look in the bigip.conf for sys application service. If present that will indicate that not all objects have been deleted.
    1. This is not to be confused with some objects that are created when SSLO is provisioned. For example you will see default APM access policies that are created. These will not bring about a sync issue because they are expected to be there and exist on all peers.
  2. If you see sys application service then run the following steps to clear the iFiles...
    1. Delete all blocks from iAppLX UI by going to iApps  ››  Application Services : Applications LX
    2. Enter the tmos shell by running: tmsh
    3. Delete all app services by running this command: delete sys application service recursive sslo*
    4. Restart the restnoded by running this command: restart sys service restnoded
    5. Wait 5 minutes.
    6. Review the bigip.conf to confirm objects have been deleted.
    7. Run a CMI sync from the BIG-IP these steps were performed on to the peer(s).
