Known Issue

This is the result of a known issue. Users may receive an HTTP 500 error when attempting to launch a Portal Access favorite. The connection may appear established; however, it will drop after a few seconds. This issue is triggered when the backend web server is running IIS 6.0 with the following settings:

  • Control Panel - Administrative Tools - IIS - Properties for website - Directory Security - Authentication and Access control - only Integrated windows authentication selected
  • Control Panel - Administrative Tools - Domain Security Policy:
    • Network security: LAN manager authentication level - Send NTLMv2 response only/refuse LM and NTLM
    • Network Security: Minimum session security for NTLM SSP based (including secure RPC) servers - Require NTLMv2 session security enabled
  • Registry key - HKLM/SYSTEM/CurrentControlSet/Control/Lsa/LMCompatibilityLevel = set to 5

F5 Networks Product Development tracked this issue as CR109751 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue has been fixed for FirePass version 6.0.2 in cumulative hotfix HF-602.10 and FirePass version 6.0.1 in cumulative hotfix HF-601-12. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
