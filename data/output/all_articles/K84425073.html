Description

HTTP GUI is inaccessible and the following message is repeatedly observed at the command line:

Re-starting tomcat

Environment

  • GUI (Configuration Utility)

Cause

The system is in a high memory usage state and the Linux OOM Killer utility is repeatedly killing tomcat's java process.

Recommended Actions

Perform the following steps to troubleshoot this issue:
  • Verifying that the system is in a high memory state
  • Identifying the reason for high memory usage

Verifying that the system is in a high memory state

The kernel log files will confirm if tomcat or other processes are being killed by OOM Killer. 

Execute the following command from bash to identify if processes have been killed by OOM Killer:

grep Killed /var/log/kern.log | tail

This example output indicates that java has been killed by OOM Killer:

err kernel: Killed process 28964 (java) total-vm:285788kB, anon-rss:178824kB, file-rss:1604kB, shmem-rss:0kB

Execute the following command to review the contents of the /proc/meminfo file, which displays information about the system's memory usage:

grep Mem /proc/meminfo

This example output indicates that there is only a small amount of memory available:

MemTotal:        4048888 kB
MemFree:           43516 kB
MemAvailable:       7060 kB

Note: The Linux top and free commands may also be used to monitor current memory usage.

Identifying the reason for high memory usage

Once a high memory condition has been identified, the best way to troubleshoot this issue is to review the kernel logs located at /var/log/kern.log*. Refer to the following article to interpret an OOM Killer log and identify the process or processes contributing to a memory issue:

  • K47241910: Interpreting an OOM killer log

In many cases, a persistent high memory usage condition is caused by many concurrent instances of smaller processes such as tmsh.

Once the memory issue has been resolved, tomcat will start without issue and continue to run.

Additional Information

tomcat's java process is often an innocent victim of OOM Killer since it is a reasonably large host process. After being killed once it has an increased chance of being killed again since OOM Killer also prefers to kill processes which have not been running for very long. In some high memory usage cases this results in tomcat constantly restarting.
