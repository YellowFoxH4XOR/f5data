K14010259: Accessing existing BIG-IP filesystems in single-user mode

Type
Support Solution
Published
2021-09-17
Updated
2026-09-25
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.4
Source
https://my.f5.com/manage/s/article/K14010259

Description
On certain occasions, it may be necessary to start the BIG-IP system in single-user mode to fix operating system issues, such as file system or root password issues. On occasions it may also be required to manually mount a particular volume in order to fix operating system issues.

Environment

  • BIG-IP
  • Single-user mode

Cause
The desired filesystem is not available in single-user mode

Recommended Actions

  1. Identify the volume set of the volume  to be mounted
    Each BIG-IP boot slot is identified by a numerical value, eg:

    switchboot -l

    Current boot image:
        HD1.1 - title BIG-IP 14.1.4 Build 0.0.11

    In the above example, boot slot HD1.1. We can correlate this to the appropriate volume set in the /dev/mapper directory:

    ls -al /dev/mapper/
    total 0
    drwxr-xr-x.  2 root root     240 Sep 17 06:14 .
    drwxr-xr-x. 19 root root    3220 Sep 17 06:15 ..
    crw-------.  1 root root 10, 236 Sep 17 06:14 control
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-dat.appdata -> ../dm-2
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-dat.log -> ../dm-3
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-dat.maint.1 -> ../dm-0
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-dat.share -> ../dm-1
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-dat.swapvol -> ../dm-4
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-set.1._config -> ../dm-7
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-set.1.root -> ../dm-5
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-set.1._usr -> ../dm-6
    lrwxrwxrwx.  1 root root       7 Sep 17 06:14 vg--db--vda-set.1._var -> ../dm-8

    The associated volume set in this example would be 
    vg--db--vda-set.1
     
  2.  Identify the volume to be mounted
    If, for example, we needed to access the filesystem containing the BIG-IP configuration files, we would mount the _config volume from the vg--db--vda-set.1 volume set
     
  3. Create a temporary mount point and mount the volume
    mkdir /K14010259
    mount /dev/mapper/vg--db--vda-set.1._config /K14010259
 

Additional Information

You can now work with the filesystem via the temporary mount point. For example, after the above steps are completed, to edit the /config/bigip.conf file of the HD1.1 boot slot

vi /K14010259/bigip.conf
