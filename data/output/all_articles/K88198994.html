Known Issue

While loading an iRule that contains HTTP::cookie without the value keyword, the iRule script validation logs an incorrect warning for the HTTP::cookie cookie-name command.

This issue occurs when all of the following conditions are met:

  • You are using an iRule that contains the HTTP::cookie command.
  • You use the HTTP::cookie command without the optional value keyword.

    For example:

    [HTTP::cookie $cookie_name]

Impact

The iRule will continue to load. There should be no impact due to this warning message.

Symptoms

As a result of this issue, you may encounter the one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H612368 on the Diagnostics > Identified > Low screen.
  • In the /var/log/ltm log file, you may observe a warning similar to the following example:

    warning: [The following errors were not caught before. Please correct the script in order to avoid future disruption. 'unexpected end of arguments;expected argument spec:COOKIE_NAME"160 25][HTTP::cookie $cookie_name]'.

Workaround

To work around this issue, you can modify the iRule to include the value keyword. 

Impact of workaround:  Performing the workaround should not have a negative impact on your system.

For example, take the following iRule syntax:

[HTTP::cookie $cookie_name]

You would change the previous iRule syntax to the following:

[HTTP::cookie value $cookie_name]
