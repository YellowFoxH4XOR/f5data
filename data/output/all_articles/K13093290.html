Description

When using the BIG-IP as a SAML Identity Provider (IdP), Service Providers (SP) may wish to update the certificate(s) for the SAML service.

Environment

  • BIG-IP APM
  • BIG-IP as IdP
  • External SP resource

Cause

Service Provider is changing certificates which would cause the IdP to fail to process SAML assertions without appropriate update.

Recommended Actions

Direct Adjustment in current BIG-IP SAML objects
In most cases, adjusting the IdP and SP SAML objects in the BIG-IP APM to include the new certificates will function. 
To exchange the certificates this is the process:

  1. Login to the Configuration Utility (GUI)
  2. Import the new certificate onto the BIG-IP system.  Details can be found here: 
    K14620: Managing SSL certificates for BIG-IP systems using the Configuration utility
  3. Navigate to Access ›› Federation ›› SAML Identity Provider ›› External SP Connectors
    BIG-IP 12.x and prior, Access Policy  ››  SAML : BIG-IP as IdP ›› External SP Connectors
  4. Select the SP connector that is bound to the desired IdP object from the list and click the Edit button
  5. Navigate to the Security Settings page
  6. Select your newly imported certificate from the Signing Certificate dropdown
  7. Click OK

This also requires the IdP and SP connectors to be rebound.  This process is detailed here:

  1. Login to the Configuration Utility (GUI)
  2. Navigate to Access ›› Federation ›› SAML Identity Provider ›› Local IdP Services
    BIG-IP 12.x and prior, Access Policy  ››  SAML : BIG-IP as IdP
  3. Select the desired IdP object from the list
  4. Click Bind/Unbind SP Connectors
  5. Ensure all SP connectors are unchecked, click OK
  6. Click Bind/Unbind SP Connectors
  7. Ensure any desired SP Connectors are checked, click OK
  8. Then Apply these changes for this access policy.

This rebinding does occasionally require a restart of several daemons on the BIG-IP, specifically apmd apd and tmm. 
If functionality is not immediately available after the previous process please use the following command:
tmsh restart sys service apmd tmm
Important: This process will interrupt traffic while the daemons are restarting and should be performed during a maintenance window.

Create a new IdP and SP object for the new Certificates

Choose the appropriate IdP instructions to create your new connectors
Using APM as a SAML IdP (SSO portal)
Using APM as a SAML IdP (no SSO portal)

When the certificate becomes valid replacing the old IdP and SP objects with the new ones will result in functionality with the new certificate.  This process will cause no outage.
