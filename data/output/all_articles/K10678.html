Known Issue

This is the result of a known issue. If the BIG-IP system processes SNMP requests on multiple local addresses, the BIG-IP system may occasionally use an incorrect source address when sending an SNMP response.

This issue occurs when the system receives one SNMP request, and then another request is received on a different local address before the response to the first request has been sent. When an SNMP request is received, the system saves the address to which the request was sent for use as the source address for the response. When a new request is received, the BIG-IP system overwrites the saved address with the address upon which the new request arrived. As a result, the source address intended for the second response is incorrectly used for the first response as well. When this occurs, the SNMP client that initiated the request never receives a response, and times out.

For example, if an SNMP request is received on the the management address, then another is received on a TMM self IP address before the response to the first has been sent, the BIG-IP system will use the TMM self IP address as the source address when replying to the request that was received on the management address.

Note: This issue is not limited to SNMP implementations, which are configured to use both the management address and a TMM address. It can also occur when accepting SNMP traffic on multiple TMM interfaces.

F5 Product Development tracked this issue as CR124819 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.8-396.1-HF3 issued for BIG-IP version 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by configuring your BIG-IP system to accept SNMP requests on only one IP address.
