Topic

Note: For more information about the gateway fail-safe feature, refer to the BIG-IP Network and System Management Guide or K5308: Configuring gateway failsafe from the command line.

When gateway fail-safe is configured, the BIG-IP system with a unit ID of 2 does not monitor the gateway pool of its peer. Consider the following example:

  • Two BIG-IP units forming a high availability pair are configured with the following pools:

    pool gateway_pool_unit_1 {
    min up members enable
    unit 1
    monitor all gateway_icmp
    members 10.0.0.10:any
    }
    pool gateway_pool_unit_2 {
    min up members enable
    unit 2
    monitor all gateway_icmp
    members 10.0.0.20:any
    }
  • The Configuration utility of the BIG-IP system with a unit ID of 1 displays both pools as available (green circle icon), and the bigpipe pool command returns:

    POOL gateway_pool_unit_1 LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    +-> POOL MEMBER gateway_pool_unit_1/10.0.0.10:any active,up
    | session enabled priority 1 ratio 1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    | requests (total) = 0
    POOL gateway_pool_unit_2 LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    +-> POOL MEMBER gateway_pool_unit_2/10.0.0.20:any active,up
    | session enabled priority 1 ratio 1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    | requests (total) = 0
  • The Configuration utility of the BIG-IP system with a unit ID of 2 displays its own gateway pool as available (green circle icon), and its peer's gateway pool as unchecked (blue square icon); the bigpipe pool command returns:

    POOL gateway_pool_unit_1 LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/0
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    +-> POOL MEMBER gateway_pool_unit_1/10.0.0.10:any active,unchecked
    | session enabled priority 1 ratio 1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    | requests (total) = 0
    POOL gateway_pool_unit_2 LB METHOD round robin MIN/CUR ACTIVE MEMBERS 0/1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    +-> POOL MEMBER gateway_pool_unit_2/10.0.0.20:any active,up
    | session enabled priority 1 ratio 1
    | (cur, max, limit, tot) = (0, 0, 0, 0)
    | (pkts,bits) in = (0, 0), out = (0, 0)
    | requests (total) = 0

This behavior is expected; it is the result of architectural constraints.

Beginning in BIG-IP 9.6.0 for the VIPRION platform and in version 10.0.0 for all other platforms, both units forming a high availability pair report the correct status of any gateway pool, regardless of the unit ID assigned to the pool.
