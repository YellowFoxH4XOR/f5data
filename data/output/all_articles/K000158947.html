Description

Multiple LTM pools on a BIG-IP system experience intermittent pool member flapping (UP/DOWN), which can cause virtual servers to become unavailable. LTM logs show monitor-related errors such as:

  • "No successful responses received before deadline"
  • "No members available for pool"
  • Pool member monitor status changing from up to down repeatedly

Environment

  • BIG-IP LTM
  • Multiple LTM pools using shared active health monitors (TCP/HTTP)
  • Health monitors configured with an up-interval value

Cause

Aggressive monitor scheduling creates excessive load on the bigd process.
When the up-interval (for example, 3 seconds) is configured lower than the interval (for example, 5 seconds), the system increases probe frequency while the pool member is UP instead of reducing it.

In environments with a large number of pools sharing this monitor, the monitoring process can become overloaded. This results in delayed or missed probes and false pool member DOWN events.

Recommended Actions

The up-interval setting is intended to reduce monitoring frequency for stable resources, not increase it.

F5 recommends that when configuring interval and up-interval, the greater value should be a multiple of the lesser value to allow even distribution of monitor checks. Monitors Settings Reference

- Correct the monitor up-interval configuration:

  • Set up-interval to 0 (to use the normal interval when the resource is UP), or
  • Set up-interval to a value greater than the interval value
  • Example: If interval is 5 seconds, set up-interval to 10 seconds or higher
  • Ensure the greater value is a multiple of the lesser value for even distribution

- Distribute monitoring load (if frequent checks are required):

  • Instead of applying a single aggressive monitor to hundreds of pools, create multiple monitors with reasonable intervals
  • Distribute pools across different monitors to reduce per-monitor load
