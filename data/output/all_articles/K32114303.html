Known Issue

BIG-IP server-side Secure Sockets Layer (SSL) connections may fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system initiates a server-side SSL connection to a pool member from a virtual server configured with a server-side SSL profile.
  • The destination SSL device is not capable of negotiating the SSL handshake at the lowest SSL record layer version number, which is set in the BIG-IP ClientHello message.

Impact

The server-side SSL handshake is reset prematurely by the pool member before the ServerHello message is received.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When viewing the SSL stream between the BIG-IP system and the destination device, the SSL record layer version number set by the BIG-IP ClientHello message is at the highest supported SSL version.

    For example, the BIG-IP SSL record ClientHello message appears similar to the following:

    Content Type: Handshake (22)
    Version: TLS 1.2 (3,3)
    Handshake Record:
    Handshake Type: Client Hello (1)
    Version: TLS 1.2 (3,3)

    The expected SSL record ClientHello message format is as follows:

    Content Type: Handshake (22)
    Version: <LOWEST_SUPPORTED_VERSION>
    Handshake Record:
    Handshake Type: Client Hello (1)
    Version:<HIGHEST_SUPPORTED_VERSION>>

    Note: The BIG-IP ClientHello message's lowest supported record layer version number and the highest supported record layer version number are set to the highest version number.
