Known Issue

VELOS blades may fail to establish backplane connectivity after a restart.

This issue occurs when all of the following conditions are met:

  • You run a VELOS system with multiple blades installed.
  • One or more of the blades in a chassis partition restart or turn on.
  • After starting, the blades fail to establish data plane connectivity to each other across the backplane.

Impact

The lack of backplane connectivity results in a complete loss of data plane traffic between the blades in the chassis partition.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Multi-blade tenants fail to cluster.
  • Blades within the partition cannot route traffic to each other.
  • When you run the tmctl command on the partition_fpga container, output shows the active_blades column in the vqf_cfg table has differing values for all assigned and enabled blades within a partition. On systems that are otherwise expected to be running in a good state, this indicates the system has likely experienced this issue. To run the tmctl command on the partition_fpga container and view the active_blades column, perform the following procedure for each blade in the partition:

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the active VELOS system controller CLI as the root user.
    2. Log in to the affected blade using the following syntax:

      ssh blade-<#>

      For example, to log in to blade number 1, enter the following:

      ssh blade-1

    3. View the tmctl output by entering the following command:

      docker exec -it partition_fpga tmctl -d blade -w 120 vqf_cfg

      The following example output shows two normally running blades in a partition with both blades showing the same values in the active_blades column:

      device version hg_type hg_cnt eth_type eth_cnt blade_idx op_mode voq_en active_blades
      ------ ------- ------- ------ -------- ------- --------- ------- ------ -------------
      vqf_0  8.6.17      100      2      100       3         0       1      1 00:00:00:03

      device version hg_type hg_cnt eth_type eth_cnt blade_idx op_mode voq_en active_blades
      ------ ------- ------- ------ -------- ------- --------- ------- ------ -------------
      vqf_0  8.6.17      100      2      100       3         1       1      1 00:00:00:03

Workaround

To work around this issue, you can attempt to restart the affected blades until the condition clears. To restart a blade in a partition, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the chassis partition webUI using an account with administrator access.
  2. Go to SYSTEM SETTINGS > General.
  3. Review the status of the blades in the partition.
  4. To restart a blade, select Reboot to the right of the slot that contains the blade. The status shows the current state of the blade during the start process.

    Note: The Reboot button is not available for slots that have no blades present or for blades that are currently starting.
