Description

When sending large amounts of ICMP Requests to a listener such as a virtual address or self IP, the BIG-IP fails to respond to ICMP Requests that exceed a rate limit.

Environment

  • Packet "drops" observed when pinging virtual addresses
  • The following log message is displayed in /var/log/ltm:

        warning tmm[20270]: 011e0001:4: Limiting icmp ping response from 501 to 500 packets/sec for traffic-group /Common/traffic-group-1

Cause

This behavior is expected when sending ICMP Requests to the BIG-IP that exceed a rate limit of 500 packets per second. 

Recommended Actions

No action is necessary. The max reject rate can be adjusted to a maximum of 1000 pps via tm.maxrejectrate , refer to K13151: Configuring the rate at which the BIG-IP system issues TCP RSTs or ICMP unreachable packets

Additional Information

  • tm.maxrejectrate prevents a denial of service condition in the event of an ICMP flood attack
  • It is not possible to disable this feature
  • It is not recommended to increase this value unless there is a good reason to do so
  • The actual number of ICMP requests allowed to succeed before they're dropped may be a multiple of  the value configured in tm.maxrejectrate
