Description

  • As BIG-IP APM is used as SAML Identity Provider [IDP], users are prompted with an error message in the browser, after they successfully enter their credentials.
  • Such difficulty may be experienced, even though no change has been implemented to the BIG-IP configuration.
  • The following pattern of records are seen in the /var/log/apm logs:
    <Access_Profile_Name>:<Partition_Name>:<Session_ID>:SAML SSO: Error creating signed message - failed to find certificate: <certificate_name>
    <Access_Profile_Name>:<Partition_Name>:<Session_ID>:SAML SSO: create signature element failed
    <Access_Profile_Name>:<Partition_Name>:<Session_ID>:SAML SSO: Error (12) creating signed SAML Assertion

Environment

  • APM is the SAML IDP
Cause

This may be due to an unexpected difficulty for the BIG-IP to retrieve the certificate and key, used to signed the SAML response. 

Recommended Actions

To resolve this issue, the Security Settings certificates of the SAML IdP object must be configured, followed by re-applying the Access Policy(ies) configured with the SAML IdP:
  1. From the Configuration Utility (GUI), navigate to Access > Federation > SAML Identity Provider > Local IdP Services
  2. Select the SAML IDP object in use here
  3. Click the Edit button at the bottom of the page
  4. In the left pane of the popup window, select Security Settings
  5. In the right pane, select /Common/default.key and /Common/default.crt for Signing Key and Signing Certificate,
  6. Open the Access Policy in the VPE and implement a minor change -> please click Apply Access Policy, on the top left corner of the window;
  7. Back to the SAML IDP popup window, revert the changes we performed at step #4: select the original key and certificate;
  8. Back to the VPE window, undo the minor change -> please click Apply Access Policy, on the top left corner of the window;
