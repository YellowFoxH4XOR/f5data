Known Issue

The FastL4 profile does not send a reset on idle timeout. This issue occurs when all of the following conditions are met:

  • B2100 blade in the VIPRION C2400 chassis, B4300 blade in the VIPRION C4400 or C4480 chassis
  • BIG-IP LTM virtual server configured with a FastL4 profile
  • FastL4 profile with the following configuration:
    • Reset on Timeout is enabled
    • Idle Timeout duration is shorter than the back-end server
    • PVA Acceleration is enabled
  • Client connects to a back-end server through the FastL4 virtual server
  • Idle Timeout threshold is reached
When the Idle Timeout threshold is reached, the BIG-IP system will clear the connection from the connection table, but does not send a reset to the back-end server.

Impact

This issue may result in port exhaustion on busy back-end servers.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Discrepancy between established connection statistics on the BIG-IP LTM system and the back-end server
  • Connections held open beyond the Idle Timeout threshold on the back-end servers

Workaround

To work around this issue, you can use a standard virtual server configured with a TCP profile, in place of the virtual server configured with a FastL4 profile.

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
