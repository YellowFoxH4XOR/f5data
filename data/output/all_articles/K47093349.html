Known Issue

The Traffic Management Microkernel (TMM) may restart when receiving connection resets during SERVER_CONNECTED iRule event processing.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured with a FastL4 profile.
  • An iRule includes commands that suspend execution in the SERVER_CONNECTED event temporarily.
  • The BIG-IP system receives TCP connection RSTs while execution in the SERVER_CONNECTED event is suspended.
For example, iRule execution may be suspended temporarily while data is accessed from the session table using the table command. If the BIG-IP system receives TCP RSTs, while execution of a SERVER_CONNECTED event is suspended, TMM may exit and restart.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. Systems configured for high availability (HA) may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If configured for HA, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core/ directory.
