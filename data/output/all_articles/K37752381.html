Issue

[DB::run_stored_proc, mysql_query_safe] Error executing SQL string : REPAIR TABLE <table name>#<other_parameter> Because : You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near <table name>#<other_parameter>  at line 1

In this error message, note the following:

  • <table name> is the MySQL table that has the syntax error
  • <other_parameter> is used internally for referencing the affected MySQL table

For example:

[DB::run_stored_proc, mysql_query_safe] Error executing SQL string : REPAIR TABLE /AVR/AVR_STAT_PROCESS_CPU_UTIL_D#P#D_2018_0322_000001_1521676801  Because : You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near '/AVR/AVR_STAT_PROCESS_CPU_UTIL_D#P#D_2018_0322_000001_1521676801' at line 1

Message Location

You may encounter this message in the following locations:

  • /var/log/ltm
  • /var/log/monpd.log

Description

This message occurs when one of the following conditions is met:

  • After an upgrade
  • After restoring the older version’s UCS file to a later version system

Impact

The local database may not update properly. As a result, recent data and statistics may fail to update as expected.

    Recommended Actions

    You can verify and attempt to repair the affected table. If the repair action does not recover the table, you may have to reset the BIG-IP AVR statistics database. To do so perform the following procedure:

    Impact of procedure: Verifying and repairing the affected table should not have a negative impact on the system. However, resetting the BIG-IP AVR statistics database removes all Analytics data and resets the MySQL database.

    1. Log in to the command line of the affected system.
    2. Verify that the affected table is listed as MyISAM under the Engine column by entering the following command syntax:

      mysql -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR -e "SHOW TABLE STATUS LIKE '<table name>';"

      Using the example error message in the Issue section, you should replace <table name> with AVR_STAT_PROCESS_CPU_UTIL_D:

      mysql -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR -e "SHOW TABLE STATUS LIKE 'AVR_STAT_PROCESS_CPU_UTIL_D';"

    3. Attempt to repair the affected table by entering the following command syntax:

      mysql -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR -e "REPAIR TABLE <table name>;"

      Using the example error message in the Issue section, you should replace <table name> with AVR_STAT_PROCESS_CPU_UTIL_D:

      mysql -uroot -p`perl -I/ts/packages -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw` AVR -e "REPAIR TABLE AVR_STAT_PROCESS_CPU_UTIL_D;"

    4. Repeat steps 2 and 3 for any other affected tables.
    5. If the repair action does not fix the affected table(s), you must reset the BIG-IP AVR statistics database by performing the steps described in K14956: Resetting BIG-IP AVR statistics.
