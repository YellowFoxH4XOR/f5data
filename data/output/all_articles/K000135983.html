Description

Environment

  • Same machineId 
  • CPU usage 

Cause

The BIG-IP HA peers through the REST framework exchange information and REST framework use the machineId as one of the identifications of identity, when the two HA BIG-IP have the same machineId, it will cause the REST framework into an abnormal status and will impact the restjavad process, And eventually lead to high control plane CPU usage. The following two scenarios may cause the device to have the same machineId, the BIG-IP VE is generated by cloning from another BIG-IP VE and loading the same UCS file on both BIG-IP.

 Recommended Actions

The machineId is stored in the file f5-rest-device-id, and you may through the following steps delete the same machineId and clear the wrong information from REST framework, then restart the restjavad process to generate a new machineId and rebuild the REST framework.
Impact of workaround: The following step don't impact the business traffic and  HA status.
1.Login device BIG-IP01 CLI, perform the following command 
rm -rf /config/f5-rest-device-id
restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices/
2.Login device BIG-IP02 CLI, perform the following command: 
rm -rf /config/f5-rest-device-id 
restcurl -X DELETE shared/resolver/device-groups/tm-shared-all-big-ips/devices/
3.Perform the following command on BIG-IP01 and BIG-IP02 CLI. 
tmsh restart /sys service restjavad
4.Wait two minutes, then check these device REST framework status. 
cat /config/f5-rest-device-id
restcurl shared/device-availability
restcurl shared/resolver/device-groups/tm-shared-all-big-ips/devices
