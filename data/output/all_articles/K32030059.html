Known Issue

Authentication, authorization, and accounting (AAA) pool member configurations may reference incorrect ports.

This issue occurs when all of the following conditions are met:

  • You use the Configuration utility to create a new Active Directory or RADIUS pool.
  • You specify the pool member ports.

Impact

AAA pool members are not created with the defined ports.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When reviewing a new AAA pool, the configured pool members reference port 0 (zero).
  • When using the pool members, authentication fails.
  • Users attempting to authenticate to the affected access profile receive an error message similar to the following example:

    Access was denied by the access policy. This may be due to a failure to meet access policy requirements.
  • Log messages similar to the following example are logged to the /var/log/apm file:

    info apd[11753]: 01490006:6: 79405ba6: Following rule 'fallback' from item 'Check Domain' to item 'AD Auth - <domain name>'
    err apd[11753]: 01490107:3: 79405ba6: AD module: authentication with '<user name>' failed: (1536494188)
    info apd[11753]: 01490017:6: 79405ba6: AD agent: Auth (logon attempt:0): authenticate with '<user name>' failed
    notice apd[11753]: 01490005:5: 79405ba6: Following rule 'fallback' from item 'AD Auth - <domain name>' to ending 'Deny'

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to manage the AAA pool member port configuration.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
