Description

After you deploy a large Application Services 3 Extension (AS3) declaration and save the configuration, a later configuration load from the text configuration files can fail. This occurs after an upgrade, after you install a hotfix or Engineering Hotfix, when you force the mcpd process to reload the configuration, or when you run tmsh load sys config.

The AS3 deployment itself succeeds. The failure appears only at the next full configuration load.

You observe the following symptoms:

  • The mcpd process exits and restarts repeatedly. The BIG-IP system cannot load its configuration, does not pass traffic, and management access is unavailable.
  • The /var/log/ltm file contains messages similar to the following on each restart: 
    err mcpd[<pid>]: 01070710:3: Database error (52), Can't write blob data, attribute:script status:52 - EdbBlobData.cpp, line 70.
err mcpd[<pid>]: 01070734:3: Configuration error: MCPProcessor::processRequestNow: mco_cursor_first failed, status code: 52
err mcpd[<pid>]: 01070596:3: An unexpected failure has occurred, Unique object lookup failed, class:module_allocation key:name_tree, status: 52 - EdbQueryEngine.cpp, line 562, exiting...
    Note: The line number in the messages may vary by BIG-IP version.

 

Environment

  • BIG-IP configured using AS3
  • The configuration contains a large cli script /Common/__appsvcs_update object, approximately 4 MiB or larger
  • The configuration was saved after the AS3 deployment, which writes the object to /config/bigip_script.conf
  • A full configuration load from the text configuration files occurs, such as after an upgrade, a hotfix installation, or a forced mcpd reload

 

Cause

AS3 applies each declaration by generating a Traffic Management Shell (tmsh) CLI script named /Common/__appsvcs_update. The script contains the commands that apply the changes from the most recent declaration to the system configuration. AS3 does not delete this script after the deployment completes, so it stays in the running configuration and is saved to /config/bigip_script.conf.

When the script is larger than 2 MiB, particularly around 4 MiB or more, the mcpd process may fail to store it while loading the configuration from the text files. The mcpd process then exits and restarts, and the failure repeats on every restart. This issue is tracked as Bug ID 2570321.

The trigger is the size of the script in bytes. The number of objects in the declaration affects the size only indirectly. For example, one large iRule adds much more to the script than a simple pool. For this reason, an object count is not a reliable guide.

 

Recommended Actions

Check whether a system is at risk

Before you upgrade, install a hotfix, or reboot a system that you configure with AS3, check the size of the retained script. Perform these steps from the BIG-IP command line.

  1. Log in to the command line of the BIG-IP system.
  2. Check the size of the saved script file: 
    ls -l /config/bigip_script.conf
  3. Check the size of the AS3 script object: 
    tmsh list cli script /Common/__appsvcs_update | wc -c

If the script object is several megabytes in size, apply one of the prevention options before the next upgrade, hotfix installation, or reboot.

Prevention option 1: Delete the retained AS3 CLI script

Impact of workaround: None to traffic or to the deployed AS3 applications. The script does not need to exist after the deployment completes, and AS3 creates a new script on the next deployment. You lose the script text as a reference for the most recent deployment.

  1. Confirm that no AS3 operation is running or pending.
  2. Optional: Save a copy of the script for reference: 
    tmsh list cli script /Common/__appsvcs_update > /var/tmp/__appsvcs_update.backup
  3. Delete the script and save the configuration: 
    tmsh delete cli script /Common/__appsvcs_update
tmsh save sys config
  4. Confirm that /config/bigip_script.conf is no longer several megabytes in size.

Important: AS3 creates the script again on each deployment. Repeat this procedure after each large AS3 deployment.

Prevention option 2: Make the last AS3 deployment small

The retained script contains only the changes from the most recent declaration. Split large deployments into multiple smaller declarations, and make sure that the last deployment before you save the configuration is small. After the deployment, save the configuration and check the script size again.

Recover a system that is already affected

Remove the large script from the text configuration and allow the configuration to load. Perform these steps from the BIG-IP command line.

  1. Stop the mcpd process to stop the restart loop: 
    bigstart stop mcpd
  2. Back up the script configuration file: 
    cp /config/bigip_script.conf /var/tmp/bigip_script.conf.backup
  3. Edit /config/bigip_script.conf and delete the complete cli script /Common/__appsvcs_update { ... } definition. Do not change the other script definitions in the file.
  4. Force the mcpd process to load the configuration from the text files, and reboot the system: 
    touch /service/mcpd/forceload
reboot
  5. After the system starts, confirm that the configuration loaded, and save the configuration: 
    tmsh save sys config

 

Additional Information

The size at which the failure occurs is approximate and is not a fixed limit. A script that loads successfully in one situation can fail in another.
