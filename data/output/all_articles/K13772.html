Known Issue

The BIG-IP GTM system incorrectly enables ARP for wildcard Listener IP addresses.

This issue occurs when the following condition is met:

  • You use the Configuration utility to create a wildcard Listener object

The Listener object represents the IP address on which the BIG-IP GTM system listens for DNS queries. When you create a BIG-IP GTM Listener object, the system creates a corresponding virtual address (located under Local Traffic > Virtual Servers > Virtual Address List). If you create a wildcard Listener object (for example, 0.0.0.0), the corresponding virtual address is created with ARP enabled.

Impact

Network communication may be disrupted between BIG-IP GTM and other devices on the same VLAN.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Network communication is disrupted between BIG-IP GTM and other devices on the same VLAN.
  • Packet captures show that BIG-IP GTM responds to addresses it does not own.
  • Devices on the network report IP address conflicts. For example, a BIG-IP system on the same VLAN may log an error message to /var/log/ltm file. The error message appears similar to the following example:

    tmm1 warning tmm1[6675]: 01190004:4: address conflict detected for 10.20.1.1 on vlan 0

Workaround

To work around this issue, you can disable ARP for the virtual server object. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click Virtual Address List.
  4. Click the wildcard virtual address that corresponds to the GTM Listener object.
  5. Clear the ARP check box.
  6. Click Update.
