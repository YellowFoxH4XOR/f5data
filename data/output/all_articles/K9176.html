Known Issue

This is the result of a known issue. By default, the BIG-IP system monitors various system services, and then takes some action if the BIG-IP system detects a heartbeat failure. For example, if the TMM daemon does not increment its heartbeat time in 10 seconds, the system fails over and restarts.

When a BIG-IP configuration is loaded (during a configsync operation or when running the bigpipe load command), TMM reloads all of the SSL certificates for every SSL profile. This behavior ensures that TMM is aware of updates to the certificate files. When a configuration containing a large number of SSL profiles and certificates (such as 75 or more) are loaded, TMM may fail to increment its heartbeat time in 10 seconds. As a result, the TMM heartbeat may fail.

F5 Product Development tracked this issue as CR103696 and it was fixed in BIG-IP LTM version 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIG-IP-9.4.5-HF2, which has been issued for BIG-IP version 9.4.5, and in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP version 9.3.1. You may download these hotfixes or a later versions of the hotfixes from the F5 Downloads site.
