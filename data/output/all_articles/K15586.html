Known Issue

SNAT Automap may select a source address that is not attached to the egress VLAN.

This issue occurs when all of the following conditions are met:

  • A virtual server uses SNAT Automap.
  • A static route exists that matches IP addresses in VLAN_A, but whose gateway resides in VLAN_B.
  • A more specific route exists, which matches a VLAN_A pool member, whose gateway resides in VLAN_A.

Example VLAN settings

VLANSelf IP AddressSubnet Mask / Bits
VLAN_A10.0.0.1255.255.254.0 or /23 (hosts 10.0.0.1 - 10.0.1.254)
VLAN_B10.0.2.1255.255.254.0 or /23 (hosts 10.0.2.1 - 10.0.3.254)

Example static routes

DestinationSubnet Mask / BitsGateway
10.0.1.0255.255.255.0 or /2410.0.3.254
10.0.1.10255.255.255.255 or /3210.0.1.254

The static routes in the previous configuration cause traffic destined for the 10.0.1.0/24 network to egress the VLAN_B by way of gateway 10.0.3.253 and traffic destined for host IP address 10.0.1.10 to egress the VLAN_A by way of gateway 10.0.1.254. However, due to internal logic, the BIG-IP system uses the self IP address of VLAN_B for the SNAT source address for traffic destined to host IP address 10.0.1.10 within VLAN_A.

As a result, traffic destined for IP address 10.0.1.10 egresses VLAN_A but has the source IP address of the self IP address on VLAN_B applied.

Impact

The system may not properly route response traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Asymmetric routing from a pool member may result in packet loss and connection timeouts. Concurrent packet captures taken from the BIG-IP system and you can use the pool member to identify this behavior.

Workaround

To work around this issue, you can configure a SNAT pool and assign that to your virtual server, instead of assigning a SNAT automap. To do so, perform one of the following procedures:

  • Configuring a SNAT pool (BIG-IP 11.3.0 and later)
  • Configuring a SNAT pool (BIG-IP 11.2.0 - 11.2.1)

Configuring a SNAT pool (BIG-IP 11.3.0 and later)

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > Address Translation > SNAT Pool List.
  2. Click Create.
  3. Enter a Name for your SNAT pool.
  4. For Member List, enter an IP Address and click Add. Repeat for each member of the SNAT pool.
  5. When you are finished adding members, click Finished.
  6. Navigate to Local Traffic > Virtual Servers.
  7. Click the name of the virtual server you want to modify.
  8. Under Configuration, in the Source Address Translation list, click the name of the SNAT pool you created in the previous steps.
  9. Click Update.

Configuring a SNAT pool (BIG-IP 11.2.0 - 11.2.1)

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > SNATs > SNAT Pool List.
  2. Click Create.
  3. Enter a Name for your SNAT pool.
  4. For Member List, enter an IP Address and click Add. Repeat for each member of the SNAT pool.
  5. When you are finished adding members, click Finished.
  6. Navigate to Local Traffic > Virtual Servers.
  7. Click the name of the virtual server you want to modify
  8. Under Configuration, in the SNAT Pool list, click the name of the SNAT pool you created in the previous steps.
  9. Click Update.
