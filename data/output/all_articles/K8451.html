Known Issue

This is the result of a known issue. When you create a client certificate on the FirePass controller after January 19, 2008, if 30 years is chosen as the expiration of the certificate (the valid to field of the certificate), the certificate will be created with an incorrect expiration date due to the "Year 2038 Problem". Because the data structure which stores time past January 1, 1970 will reach its maximum value and roll over, a certificate intended to have an expiration date beyond January 19, 2038 will instead be created with the "two's complement" year (1902 instead of 2038; 1903 for 2039, and so on).

A client certificate enables client certificate-based authentication between the FirePass controller and its remote access clients. The client certificate is issued to a user who installs the certificate in the browser used to access the FirePass controller. A self-signed client certificate is created using the FirePass controller's built-in public key infrastructure (PKI), either using a self-signed client root certificate or a third-party client root certificate and its associated private key. The FirePass PKI maintains the needed information to manage the certificates.

A client certificate with an expiration date beyond January 19, 2038 is created by selecting the 30-Year option for the Expiration under the Client Certificate section of a user's record on the Users: User Management page, then clicking the New Client Certificate button. Once the first client certificate with an expiration beyond January 19, 2038 is created, any attempt to issue client certificates to any other user will fail. Clicking the New Client Certificate button will result only in a page refresh, rather than the client certificate data being displayed in a table on the user's page. No certificate will be issued to the user. Deleting the 30-year client certificate will not remove the issue.

Some FirePass client certificate-related features function normally. Users with existing certificates will be able to authenticate, and users with existing certificates which are revoked on the FirePass controller will no longer be able to authenticate.

F5 Product Development tracked this issue as CR93025 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

Additionally, a hotfix has been issued for supported versions of FirePass software. You may download the hotfix for versions 5.5 and 5.5.1 of FirePass software from the F5 Downloads page. For versions 5.5.2, 6.0.1 and 6.0.2, you may contact F5 Technical Support to determine whether your situation requires the hotfix.

Installing the hotfix will repair the certificate database, and delete the client certificate that caused this issue. If the user for which this certificate was issued has received the certificate, you should instruct the user to delete the certificate and issue a new certificate with an earlier expiration date to the user. As with all hotfixes, a reboot is required to install the hotfix.

Important: The hotfix does not fix the "Year 2038 Problem". The hotfix returns the FirePass controller to the state prior to the time the problematic client certificate was created and the database was corrupted. If another client certificate is issued with an expiration date beyond January 19, 2038, the issue will appear again. In that circumstance, you may uninstall the hotfix and reinstall it to return to the unaffected state. To uninstall the hotfix, go to the Device Management: Current Settings page, click the link that represents the hotfix (for example, HF-93886-1) in the FirePass Hot-Fixes field, then click the Uninstall hot-fix>> link.

Note: The hotfixes for FirePass software versions 5.5 and 5.5.1 remove the option to create certificates of 30-year duration. For later versions of FirePass software, the option to create certificates of 30-year duration will be removed in future cumulative hotfixes.

Important: The hotfixes for FirePass software versions 5.5.2, 6.0.1 and 6.0.2 do not remove the option to create certificates of 30-year duration. The hotfix for these versions should not be applied if the FirePass controller is not experiencing a corruption of the certificate database because of the creation of a 30-year client certificate.

Workaround

If you cannot apply the hotfix, then depending on your circumstances, one of the following workarounds may resolve any problems encountered with this issue.

  • Delete the client root certificate

    Deleting the client root certificate that issued the client certificate will also purge the client certificate database. If you have not yet issued the client certificates to users, or have issued few certificates, this is the simplest way to work around the issue.  This does not require a reboot or a restart of web services.

    Note: You cannot delete the client root certificate, then reinstall the same certificate from the files you downloaded and saved at the time of the creation of the client root certificate. Deleting the client root certificate from the Administrative Console will also delete the certificate database. Reintstalling only the client certificate will not recreate the associated files needed for a fully functioning PKI.
  • Restore a backup

    If you have issued many client certificates to users already, the above workaround may be impractical. Under these circumstances, if you have taken a configuration backup prior to issuing the 30-year client certificate or certificates, you can restore the Users and Groups from the configuration backup. The client certificate database will be restored to the state at the time of the backup, and you will again be able to issue client certificates. Certificates issued since the backup date will not be valid, and users will require new certificates to be issued to them.  If the number of client certificates you have issued since the backup date is small, then this may be an acceptable workaround.

    To restore a backup, perform the following procedure:

    1. Log in to the Administrative Console.
    2. Click Device Management.
    3. Click Maintenance.
    4. Click Backup/Restore.
    5. Click the Browse button to navigate to your backup file.
    6. Click the Restore your saved configuration link.
    7. Select Restore Users and Groups Settings check box.
    8. Click the Restore button.

      This does not require a reboot or a restart of web services.
  • Restore a snapshot

    If you have taken a snapshot from the maintenance console prior to issuing a client certificate that expires after January 19, 2038, you can restore the snapshot from the maintenance console.  Restoring a snapshot is an excellent way to revert to a known configuration state, but does require downtime to restore the snapshot. For more information, refer to K3244: Backing up and restoring FirePass system software for more information on snapshots.

If none of these workarounds are feasible, please contact F5 Technical Support for further assistance.
