Topic

This article applies to BIG-IP 11.4.0 - 12.0.0. For information about other versions, refer to the following article:

  • K04597703: Overview of the Local Traffic Policies feature (12.1.0 and later)
  • K7280: Overview of the HTTP Class profile

This article covers the settings and usage of the Local Traffic Policies feature.

Description

In BIG-IP 11.4.0 - 12.0.0, the Local Traffic Policies feature provides a way to classify traffic based on a list of matching rules, and then to run specific actions, such as, directing all HTTP traffic to the BIG-IP ASM system for security checks based on the configured security policy, redirecting traffic received on an HTTP virtual server to an HTTPS virtual server, sending traffic to a load balancing pool based on header data, or refining the types of traffic to be collected for statistical analysis in BIG-IP Analytics, etc.

The local traffic policy settings are organized into the following sections and are described in the following tables:

  • General Properties
  • Rules

General Properties

SettingDescription
NameThis setting is required. To create a local traffic policy, you must specify a unique name for the policy.
Partition/PathThis setting displays the administrative partition to which the local traffic policy belongs. It is non-configurable and takes on the administrative partition in which the local traffic policy was created.
StrategyThis setting provides the strategy selection when more than one rule matches. The three predefined strategies are first-match, best-match, and all-match.
  • First-match: This strategy starts the actions from the first rule in the sorted Rule list that matches. The sort order uses the ordinal attribute and sorts the rules from the lowest ordinal value to the highest ordinal value.
  • Best-match: This strategy selects and starts the actions of the rule in the Rules list with the best match, as determined by the following factors
    1. A best-match strategy selects the rule that has the most conditions, ignoring details about the conditions.
    2. If a rule with the most conditions is not determined, the best-match strategy selects the rule with the highest priority operands (to check the priority of the operands: tmsh list ltm policy-strategy best-match). The best-match strategy sorts the operands, highest priority first, comparing one at a time until a higher priority is found. For example, a priority sequence of 0,1,3,4,6 wins over 0,1,3,5,7 because 4 is greater than 5.
    3. If a rule with the highest priority operands is not determined, the best-match strategy selects the rule with equal match types over other match types, such as starts-with, ends-with, or contains, and processes according to operand priority.
    4. If a rule of equal match types is not determined, the best-match strategy uses an ordinal.
                    Note: In a best-match strategy, when multiple rules match and specify an action, conflicting or otherwise, only the action of the best-match rule is implemented. A best-match rule can be the lowest ordinal, the highest priority, or the first rule that matches in the Rules list.
  • All-match: This strategy starts the actions for all rules in the Rules list that match.
                    Note: In an all-match strategy, when multiple rules match, but specify conflicting actions, only the action of the best-match rule is implemented. A best-match rule can be the lowest ordinal, the highest priority, or the first rule that matches in the Rules list.

If you require a best-match strategy customized for your application environment, F5 recommends that you create a new strategy based on the pre-defined best-match strategy, instead of modifying the pre-defined best-match strategy. For more information, refer to the Local Traffic Policies chapter of the BIG-IP Local Traffic Manager: Concepts guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

RequiresThis setting provides a list of available profile types such as http or tcp. Selecting a profile type defines the types of operands, conditions, and actions that you can use when configuring a rule. Additionally, this setting allows the local traffic policy to validate whether it can be applied to a virtual server.

For example, if you select http for this setting, then the system displays the HTTP-relevant operands, conditions, and actions, such as HTTP headers/events when configuring a rule. When assigning the local traffic policy to a virtual server, the system checks whether the virtual server is configured with the required HTTP profile, and if it is, applies the local traffic policy to the virtual server.

ControlsThis setting provides a list of available features such as compression or caching. Similar to the Requires setting, selecting a feature defines the types of operands, conditions, and actions that you can use when configuring a rule. Additionally, this setting detects and prevents conflicts between multiple policies on the same virtual server.
For example, if compression is selected when you are configuring a rule, then the system displays the compression-relevant operands, conditions, and actions, such as compress or decompress.

Rules

The Rules section displays the list of rules configured for the local traffic policy. Each rule is organized into the General Properties section and the Rule Properties section that make up the Conditions for matching and the Actions to be performed on the matching traffic.

General Properties

SettingsDescription
Policy NameThis setting displays the name of the local traffic policy to which the rule belongs. It is non-configurable and takes on the local traffic policy in which the rule was created.
Rule NameThis setting is required. To create a rule, you must specify a unique name for the rule. You can configure this only when creating the rule, and you cannot modify it after the rule has been created.

Rule Properties

The Rule Properties section is divided into two subsections, Conditions and Actions. The Conditions subsection provides the settings for configuring the matching part of the rule, while the Actions subsection provides the settings for configuring the actions you want the system to perform on the matching traffic.

Conditions

SettingsDescriptions
OperandThis setting provides a list of operands/attributes that you can use to match the traffic. The list is typically related to the profile types configured for the Requires setting in the local traffic policy. For example, if you have configured the local traffic policy with only http for the Requires setting, then the available operands will be http-host, http-method etc. For a detailed list of condition operands, refer to the Local Traffic Policies chapter of the BIG-IP Local Traffic Manager: Concepts guide.
EventThis setting provides the valid events to match the traffic request or response. The available events depend on the condition operand. For example, the http-version operand is valid in both the request and response events; the http-host operand is valid in only the request event, while the http-set-cookie operand is valid only in the response event.
SelectorThis setting provides a set of parameters specific to the condition operand to allow granularity for matching traffic. For example, the http-host operand provides the Selector setting all, host, or port. Selecting all allows the rule to match everything in the HTTP host header, while selecting host or port allows the rule to match either setting in the HTTP host header.
ParametersThis setting provides further granularity for matching traffic depending on the parameter selected for the Selector setting. This setting is available for only some operands like http-header, where you can specify the name of the HTTP header you want to match in the Parameters setting by entering it in Parameters Value and clicking Add to include it in the Parameters List. You can also remove a specific parameter by selecting it in the Parameters List and clicking Delete.
NegateThis setting, when checked, reverses the configured conditions. For example, if a condition is configured as follows, then the condition is true only if the HTTP host header in the incoming HTTP request is NOT equal to myweb.com:

Operand: http-host
Event: request
Selector: all
Negate: checked
Condition: equals
Values: myweb.com

ConditionThis setting provides a list of operators that you can use for matching. Multiple conditions use logical AND for evaluation. The list depends on the data type of the operand/selector. For example, the http-host operand with host selector is a string data type and the Condition setting displays the following selection: equals, starts-with, ends-with and contains. In another example, the http-host operand with port selector is a number data type and the Condition setting displays the following selection: equals, less, greater, less-or-equal, greater-or-equal.

Note: If you require case sensitivity for the condition that matches traffic, you can do so by selecting the case sensitive checkbox next to this setting.

ValuesThis setting allows you to enter the values for the operand to match against. If there is more than one value you want to match against, you must click Add to add the values to the Values List. To remove a specific value, select it in the Values List, and click Delete.
MissingThis setting allows you to specify whether the operand can be matched against a null value. For example, if a condition is configured as follows, then the condition is true if the HTTP host header in the incoming HTTP request is equal to myweb.com, or is empty.

Operand: http-host
Event: request
Selector: all
Condition: equals
Values: myweb.com
Missing: checked

Add/Edit/DeleteYou must use these buttons to add new conditions, or modify or remove existing conditions from the Conditions list. The rule matches traffic based on the rules that are defined in the Conditions list.

Important: If you made selections for various settings, but failed to click Add to add to the Conditions list, then the condition is not added to the rule, and the rule will not match traffic using the settings you have selected. Similarly, if you modify an existing condition and fail to click Add to add it back to the Conditions list, then the modified condition is not added to the rule, and the rule will not match traffic using the modified settings.

Actions

SettingsDescriptions
TargetThis setting provides the list of available action operands based on the Requires and Controls setting in the local traffic policy. For example, if you configure the Requires setting with http and Controls with compression, then the Target setting displays actions such as compress or decompress that the rule can use, as well as a set of HTTP objects (for example, http-cookie) on which you want the rule to perform an action.
EventThis setting provides the valid events for which the action operand can perform action on the matching traffic request or response. The available events depend on the action operand. For example, the http-header action operand is valid in both the request and response events; the http-host action operand is valid only in the request event, while the http-set-cookie action operand is valid only in the response event.
ActionThis setting provides the list of actions that the system can perform, depending on the action operand selected in the Target setting. For example, you can insert or remove cookies for the http-cookie action operand; you can enable or disable compression for the compress action operand. For a detailed list of actions available for each action operand, refer to the Local Traffic Policies chapter of the BIG-IP Local Traffic Manager: Concepts guide.
ParametersThis setting provides further granularity for the actions you can take, depending on the action operand selected in the Target setting. For example, you can select the security policy to enforce on matching traffic when you enable the asm action operand; you can select a list of BIG-IP objects such as pool or snat to send matching traffic to the forward action operand. If you want the action to have more than one parameter, you must click Add to add each parameter to the Parameters List. To remove a specific parameter, select the parameter in the List and click Delete.
Add/Edit/DeleteYou must use these buttons to add new actions or modify or remove existing actions to or from the Actions list. The rule takes action on matching traffic based on this Actions list.

Important: If you made selections for various settings but failed to click Add to add to the Actions list, then the action is not added to the rule, and the rule will not perform the action on matching traffic using the settings you have selected. Similarly, if you modify an existing action and fail to click Add to add it back to the Actions list, then the modified action is not added to the rule and the rule will not perform the action on matching traffic using the modified settings.

Known Behaviors

Certain combinations of the Requires setting and Controls setting require a default rule that has no conditions for the local traffic policy to function appropriately. For example, the Requires setting is set to http and the Controls setting is set to l7dos or asm. If you attempt to configure a default rule with conditions when the Controls setting is set to l7dos or asm, the system reports an error similar to the following example:

0107172c:3: Policy '/Common/test'; a policy controlling 'l7dos' must have a default rule.

If you require a rule that has specific conditions to send traffic to the l7dos or asm controls, you may have to create a default rule with no conditions where action is set to disable l7dos or asm, and a second rule with specific conditions where action is set to enable l7dos or asm.
