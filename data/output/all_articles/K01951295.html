Known Issue

Certain operational tasks may take longer to complete than the mcpd heartbeat timeout of 300 seconds. When this issue occurs, the system interprets the mcpd process as unresponsive.

This issue occurs when the following condition is met:

  • The BIG-IP system is loading a configuration file with many file objects, for example, 3,000 or more SSL keys and certificates.

Impact

The BIG-IP system temporarily stops processing traffic and may fail over if paired with other BIG-IP systems.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H686879 on the Diagnostics > Identified > Medium page.
  • The mcpd process restarts, which causes a system to go offline and restart services.
  • In the /var/log/ltm log file, you observe an error message similar to the following example:

    warning overdog[5648]: 01140029:4: HA daemon_heartbeat mcpd fails action is restart all.

Workaround

To work around this issue, you can temporarily disable the heartbeat timeout. To do so, perform the following procedure:

Impact of workaround: If the mcpd process legitimately becomes unresponsive, the system does not automatically restart mcpd to recover.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To disable the heartbeat timeout, type the following command:

    modify sys daemon-ha mcpd heartbeat disable
