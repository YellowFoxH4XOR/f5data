K000134615: Standard virtual server with verified-accept enabled stops responding to SYN packets

Type
Support Solution
Published
2023-06-05
Updated
2023-06-05
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source

Description

The Standard virtual server with verified-accept enabled in TCP profile processes connections on a packet-by-packet basis.

Expected packet-by-packet TCP behavior: The initial SYN request is sent from the client to the BIG-IP LTM virtual server, and the BIG-IP LTM system makes the load-balancing decision and passes the SYN request to the pool member.

 

When the issue happens, virtual server 10.1.20.100:80 stops sending [SYN] packets to the backend server.

Environment

Standard TCP virtual server with verified-accept enabled in TCP profile.

 

Cause

There is a global setting db variable connections.preestablished.threshold default value 8192. It defines the allowed total amount of outstanding SYNs waiting for verified accept to be complete. 

 

If the number of outstanding SYN connections from clients waiting for SYN responses from backend pool members exceeds this db value, tmm will not respond to SYNs from the client.

 

Use the below command to check the performance of the virtual server with verified accept as an option on the TCP profile:

 

# tmctl -d blade tmm/tcp4 -s pe_overflow,conndrops,pe_connects

Example output: 

pe_overflow conndrops pe_connects
----------- --------- -----------
7048373        7120067 120061

pe_connects = Is the number of outstanding SYN connections from clients that are waiting for SYN responses from backend pool members.

pe_overflows = Number of SYN connections from clients that have been dropped because SYN pe_connects is over the db variable or failed SYN/ACKs from backend pool members.

conndrops = number of connections that have been dropped for all reasons on the LTM device.

 

 

Recommended Actions

 

Increase the below db (double or even increase more)

sys db connections.preestablished.threshold {
  default-value "8192"
  scf-config "false"
  value "8192"
  value-range "unsigned_integer min:0 max:1000000"
}
