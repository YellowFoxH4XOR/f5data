Topic

You should consider using this procedure under the following conditions:

  • You are running an iWorkflow standalone instance and want to upgrade to a newer iWorkflow version.
  • You are running an iWorkflow cluster and want to upgrade to a newer iWorkflow version.

Description

When upgrading iWorkflow standalone systems and clusters to newer versions, perform the procedures outlined in this article.

Prerequisites

You must meet the following prerequisites to perform these procedures:

  • You must have administrative rights on the iWorkflow system.
  • You have recently made a user configuration set (UCS) backup of the iWorkflow system and copied it to a remote secure server for storage.
  • You have adequate disk space available to complete the installation.
  • The current environment is in sync and all managed devices are healthy.
  • You have copied the new iWorkflow release ISO file to the /shared/images directory.

Procedures

  • Upgrading a standalone iWorkflow system
  • Upgrading an iWorkflow cluster
    • Breaking apart the cluster by using a lead peer to evict the two sibling peers
    • Performing the upgrade for each virtual machine's software separately
    • Recreating the cluster using the lead peer to add the siblings peers to the cluster

Upgrading a standalone iWorkflow instance

During the upgrade process, the iWorkflow administrative interface is unavailable, but it will not impact the devices managed by iWorkflow. In most cases, you will need to update the representational state transfer (REST) framework on all managed BIG-IP devices after the iWorkflow upgrade is complete. When installing new iWorkflow software images, you must run the software installation from an active boot location and specify an inactive clean boot location as the target install location. This action is a result of the software installation copying the running configuration and license from the current boot location to the target install location.

It is possible to upgrade iWorkflow without importing the running configuration. For more information, refer to K13438: Controlling configuration import when performing software installations (11.x - 12.x).

Impact of procedure: During the upgrade process iWorkflow will be unable to make changes, updates, or additions to any of the managed BIG-IP systems.

  1. Log in to the iWorkflow command line.
  2. Log in to the Traffic Management Shell (tmsh) utility by typing the following command:

    tmsh

  3. Check the status of the currently installed iWorkflow software by typing the following command:

    show /sys software

    The command output displays similar to the following example:

    ------------------------------------------------------
    Sys::Software Status
    Volume Product Version Build Active Status
    ------------------------------------------------------
    HD1.1 iWorkflow 2.0.0 0.0.9631 yes complete
    HD1.2 none none none no complete

    If the command output displays only one volume, you can create a new volume during the installation process.

  4. Install iWorkflow onto an existing inactive volume using the following command syntax:

    install /sys software image <iworkflow-image.iso> volume <inactive volume>

    In this command, note the following:

    • <inactive volume> is the name of your inactive volume.

    For example:

    install /sys software image iworkflow.iso volume HD1.2

  5. Optional: Create a new volume and install iWorkflow into the new location and automatically reboot when complete using the following command syntax:

    install /sys software image <iworkflow-image.iso> create-volume volume <new volume> reboot

    In this command, note the following:

    • <new volume> is the name of your new volume.

    For example:

    install sys software image iWorkflow.iso create-volume volume HD1.3 reboot

  6. Exit the tmsh utility by typing the following command:

    quit

  7. Monitor the installation process by typing the following command:

    Note: By default, the watch command automatically refreshes every 2 seconds.

    watch tmsh show /sys software

    The command output displays similar to the following example:

    Every 2.0s: tmsh show /sys software Fri Sep 13 11:14:08 2016
    -------------------------------------------------------------------
    Sys::Software Status
    Volume Product Version Build Active Status
    -------------------------------------------------------------------
    HD1.1 iWorkflow 2.0.0 0.0.9631 yes complete
    HD1.2 iWorkflow 2.0.1 0.0.9855 no installing 10.000 pct

  8. If you did not use the reboot switch in your tmsh install command, you can manually reboot into the new volume once the installation is complete using the following command syntax:

    tmsh reboot volume <new iWorkflow volume>

    In this command, note the following:

    • <new iWorkflow volume> is the name of your new volume.
    For example:

    tmsh reboot volume HD1.2

  9. Once the system completes the installation and reboots into the new active volume, log in to the iWorkflow command line to review the status. Review the managed BIG-IP devices and confirm that the REST framework versions are current. The BIG-IP devices that are unhealthy will need to be rediscovered to force the REST framework update.

Upgrading an iWorkflow cluster

To upgrade the platform software on an iWorkflow cluster, perform the following procedures:

Impact of procedure: When upgrading an iWorkflow cluster, you will be unable to make changes, updates, or additions to the managed BIG-IP systems.

Breaking apart the cluster by using a lead peer to evict the two sibling peers

Before you can upgrade an iWorkflow cluster, you must break apart and recreate the cluster; the cluster members cannot communicate if their management layer components are not running the same iWorkflow software version. To break apart the cluster by using a lead peer to evict the two sibling peers, perform the following procedure:

  1. Log in to the iWorkflow administrative user interface with your administrator username and password.

    For example:

    https://10.10.99.5/ui/login

  2. Select the System module from the Top navigation menu.
  3. Locate the iWorkflow Cluster panel.
  4. Select the iWorkflow servers individually.
  5. To break the iWorkflow cluster, click Remove.

    Note: When you remove an iWorkflow cluster member from the cluster, iWorkflow removes all cluster state details from that device and resets it to the default state. The management IP and license details are not impacted by this update.

    If you want to perform this procedure using REST call from the command line, refer to K49398482: Managing F5 iWorkflow clusters.

Performing the upgrade for each virtual machine's software separately

Once you have separated the iWorkflow cluster and there is only a single standalone iWorkflow instance running and managing the BIG-IP system, you can perform the Upgrading a standalone iWorkflow system procedure. Perform this procedure on all iWorkflow instances.

Recreating the cluster by using the lead peer to add the sibling peers to the cluster

After you upgrade all three iWorkflow nodes, you can recreate the cluster. To do so, perform the following procedure:

Note: The iWorkflow peer leader is the preferred cluster member for managing the iWorkflow cluster and BIG-IP systems. You can use any of the cluster members for this purpose, but F5 recommends that once you have a cluster running you select one member of the cluster for administration and maintain that host until it is no longer preferred.

  1. Log in to the iWorkflow peer leader administrative user interface with your administrator username and password; this should be the only iWorkflow instance with knowledge of the BIG-IP systems at this time.

    For example:

    https://10.10.99.5/ui/login

  2. Select the System module from the Top navigation menu.
  3. Locate the iWorkflow Cluster panel.
  4. Click the plus (+) icon located in the iWorkflow Cluster header.
  5. In the New iWorkflow Cluster Member panel, enter the peer IP address, admin username, and admin password.
  6. When you are finished, click Add.
  7. Acknowledge the warning message that data on the peer will be overwritten by clicking OK.
  8. Repeat this procedure until you have returned all three iWorkflow cluster members to the cluster.

    If you want to perform this procedure using REST call from the command line, refer to K49398482: Managing F5 iWorkflow clusters.
