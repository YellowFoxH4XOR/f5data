Known Issue

Software SYN cookies without a TCP time stamp include TCP options that are not encoded.

This issue occurs when the following condition is met:

  • TCP time stamps are disabled by the client or in the TCP profile.

Impact

Users may experience poor connection performance.

Note: In one user-reported case, the client was Windows 7, which disables time stamps by default. The client assumes the BIG-IP system uses window scaling to scale up the advertised window. However, the BIG-IP system did not use window scaling. Instead it used the window size from the TCP header directly. As a result, the BIG-IP system sent small packets and waited for a response.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When sending a software SYN cookie with no TCP timestamp option, the Traffic Management Microkernel (TMM) sends back TCP options, such as window scaling and the SackOK option. The values for these options are encoded in the time stamp field, which is not sent. When the final ACK of the TCP 3-way handshake (3WHS) arrives without a time stamp, there is no way to know that the BIG-IP system negotiated the use of SACK, window scaling, and other options encoded in the time stamp. The client assumes that options are enabled and the BIG-IP system assumes that the options are not enabled.

Workaround

To prevent this behavior from occurring, do not disable TCP timestamps or alter the default receive window and send buffer values of 65535 bytes. These values are located in Memory Management in the TCP profile. To access in the Configuration utility, navigate to Local Traffic > Profiles > Protocol > TCP.

The timestamp option is located under Congestion Control as Timestamps Extension for High Performance (RFC 1323). The default value is enabled.
