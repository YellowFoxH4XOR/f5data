K000139935: Unable to move failover routes after upgrade CFEv2.1.0 on AWS

Type
Support Solution
Published
2024-06-11
Updated
2024-06-11
Source
https://my.f5.com/manage/s/article/K000139935

Description

Cloud failover extension failing to move failoverRoutes after upgrade to CFE v2.1.0. 

  • Logged error at /var/log/restnoded/restnoded.log
Thu, 30 May 2024 18:55:45 GMT - fine: [f5-cloud-failover] _discoverAddressOperations found Elastic IPs: undefined
Thu, 30 May 2024 18:55:45 GMT - severe: [f5-cloud-failover] error in _getFailoverDiscovery: TypeError: Cannot read property 'forEach' of undefined
  • The output of dry-run on the standby unit, 
# curl -su admin: -X POST -d '{"action":"dry-run"}' http://localhost:8100/mgmt/shared/cloud-failover/trigger | jq .
{
  "message": "Cannot read property 'forEach' of undefined"
}

Environment

  • AWS Cloud Provider.
  • Failover Across AZs without EIPs.
  • CFE v2.1.0.

Cause

The error occurs after CFE looks up for tagged EIPs, if none EIP is found CFE v2.1.0 will returns the value "undefined", such value is not properly handled generating an exception and causing routes not being moved. 

Recommended Actions

Above error can be ruled out by modifying CFE declaration in one of next two ways, 

1. Remove the failoveraddress definition on the declaration, next is the section that needs to be removed, 

"failoverAddresses": {
"enabled": true,
"scopingTags": {
"f5_cloud_failover_label": "bigip_high_availability_solution"
},
"requireScopingTags": false
},

2. Disabling the failoveraddress operations, value "enable":false,

"failoverAddresses": {
"enabled": false,
"scopingTags": {
"f5_cloud_failover_label": "bigip_high_availability_solution"
},
"requireScopingTags": false
},

Note that after disable the failoverAddresses operations or remove the definition, next error is noticed during the dry-run at standby unit, but, this does not prevent routes to be moved,

[admin@failover01:Standby:In Sync] ~ # curl -su admin: -X POST -d '{"action":"dry-run"}' http://localhost:8100/mgmt/shared/cloud-failover/trigger | jq .
{
"message": "Cannot read property 'disassociate' of undefined"
}
