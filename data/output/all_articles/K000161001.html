Description

BIG-IP DNS systems may generate thousands of syslog-ng configuration reload events daily, rapid log rotation, and high log volume. Symptoms include repeated log entries such as:

  • syslog-ng[4819]: Configuration reload request received, reloading configuration
  • audit_forwarder started.
  • Failed to open /var/IpRep/F5IpRep.dat
  • Failed to open /var/IpRep/F5IpV6Rep.dat
  • /var/log partition fills up quickly, triggering frequent log rotations.
  • Port exhaustion messages may also appear in the logs.

Environment

  • Product: BIG-IP 
  • IP Intelligence (IPI) policies configured on multiple virtual servers
  • IPI subscription expired or not licensed
  • High log volume from TMM process

Cause

id2218157

Expired IP Intelligence (IPI) subscription while IPI policies remain configured on one or more virtual servers causes TMM to log repeated errors about missing IPI database files at a high rate, rapidly filling the /var/log partition. The full log partition triggers early log rotation, which in turn causes syslog-ng to reload its configuration frequently.

Answer/Recommended Actions

  1. Remove IP Intelligence Policy from Virtual Servers
    • Back up the current configuration:
      tmsh save /sys ucs /var/tmp/pre_IPI_policy_removal.ucs
    • Remove the IPI policy from each affected virtual server:
      tmsh modify ltm virtual /Common/GLOBAL_ANYCAST_DNS ip-intelligence-policy none
      tmsh modify ltm virtual /Common/VIZ_DNS_Listener ip-intelligence-policy none
      tmsh modify ltm virtual /Common/VIZ_DNS_Listener2 ip-intelligence-policy none
    • Save the configuration:
      tmsh save sys config
    • Verify removal:
      tmsh list ltm virtual one-line | grep DNS_IPI_Policy
      Note: No output should be returned if the policy is fully removed.
  2. Clean Up /var/log
    • Remove old or unnecessary log files (especially tmm*.gz files) to free up space.
    • Manually truncate /var/log/pi_learning if it is excessively large.
  3. Upgrade Recommendation
    • Upgrade to BIG-IP version 17.5.1.6 or later when available, as this version includes a fix for this logging behavior.
  4. Optional: Renew IPI Subscription
    • If you wish to continue using IP Intelligence, renew your subscription to restore normal functionality and logging.

Additional Information

  • Removing the IPI policy will immediately stop excessive logging and syslog-ng reloads.
  • There is no impact to DNS traffic or other BIG-IP services; only IPI-based security actions are removed.
  • If you rely on IP Intelligence for security, ensure your subscription is valid before removing the policy.
  • If needed, you can restore the previous configuration using the UCS backup created in Step 1.
