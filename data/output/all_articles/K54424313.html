Description

  • During upgrade, the loading configuration process failed with error in cipher list.

Environment

  • Performed BIG-IP version upgrade or new configuration

  • Defined cipher strings for allowing access to the Configuration Utility

Cause

From version 14.x and later the BIG-IP system uses stricter cipher string validation not allowing to configure with invalid ciphers attributes.
In earlier versions (BIG-IP versions 12.x and 13.x), you can configure ciphers allowed by the configuration utility that may have an invalid ciphers attributes.

  • If you have invalid ciphers attributes and you are trying to upgrade to a later version (version 14.x and later) the configuration will failed to load due to a invalid cipher string error:
    47180005618544:error:140E6118:SSL routines:SSL_CIPHER_PROCESS_RULESTR:invalid command:ssl_ciph.c:1225:

  • If you are already in a version where stricter cipher string validation forced (version 14.x and later), you will not be able to configure ciphers allowed by the configuration utility with invalid ciphers attributes with the invalid cipher string error:
    47598177370992:error:140E6118:SSL routines:SSL_CIPHER_PROCESS_RULESTR:invalid command:ssl_ciph.c:1225:

Recommended Actions

Reconfigure the cipher list to be valid according to both the OpenSSL cipher list and the Client SSL / Server SSL cipher list expectations.
You can test your cipher strings by the openssl command and the relevant TMM commands as below.
To test your new cipher string you can use openssl ciphers -v or tmm --clientciphers or tmm --serverciphers to test what the BIG-IP will allow.

Syntax:

  • tmm --clientciphers '<cipherstring>'
  • tmm --serverciphers '<cipherstring>'
  • openssl ciphers -v '<cipherstring>'
