Topic

This article applies to BIG-IP Next Cloud-Native Network Functions (CNFs). For information about other products, refer to the following article:

  • K411: Overview of packet tracing with the tcpdump utility

Description

You can use the tcpdump utility to view traffic on the BIG-IP Next CNFs Traffic Management Microkernel (TMM) Proxy pod. The tcpdump utility is provided with other diagnostic tools within the debug sidecar in the BIG-IP Next CNFs TMM Proxy pod. The debug sidecar is deployed by default with BIG-IP Next CNFs. Running the tcpdump utility in the debug sidecar allows you to capture ingress and egress traffic to the TMM.

The tcpdump utility supports capturing additional internal TMM information by specifying the noise amplitude in the command. For more information about capturing internal TMM information, refer to K13637: Capturing internal TMM information with tcpdump.

Note: To save tcpdump capture files to a filesystem on a node, you must have a Kubernetes PersistentVolume available for binding and configure the debug container’s persistence parameter in the Helm values file. For more information, refer to F5 Cloud-Native Network Functions on F5 Cloud Docs.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • Have BIG-IP Next CNFs running in the Robin Cloud-Native Platform (CNP)

Procedures

Run the tcpdump utility

To run the tcpdump utility, you must access the debug sidecar container running in the TMM Proxy pod. The debug sidecar shares network namespace with TMM, which allows the tcpdump utility to capture ingress and egress TMM traffic.

To access the debug sidecar container and run the tcpdump utility, perform the following procedure.

Impact of procedure: Capturing traffic with the tcpdump utility has the potential to generate very large files. When capturing on interface 0.0, you should use filters to reduce the size of the capture.

  1. Locate the name of the TMM Proxy pod using the following syntax:

    kubectl get pods --selector app=f5-tmm -n <namespace>

    For example, if the TMM pod is running in the cnf-gateway namespace, enter the following command:

    kubectl get pods --selector app=f5-tmm -n cnf-gateway

    The following example output indicates that the name of the TMM pod is f5-tmm-6f4f5cb664-glg2w:

    NAME                      READY   STATUS    RESTARTS   AGE
    f5-tmm-6f4f5cb664-glg2w   5/5     Running   0          204d

  2. Access the debug sidecar container in the TMM proxy pod using the following syntax:

    kubectl exec -it <tmm_pod_name> -c debug -n <namespace> -- bash

    For example, if the TMM pod is named f5-tmm-6f4f5cb664-glg2w and resides in the cnf-gateway namespace, enter the following command:

    kubectl exec -it f5-tmm-6f4f5cb664-glg2w -c debug -n cnf-gateway -- bash

  3. From the debug container, you can list the available interfaces by entering the tcpdump -D command. The following example output shows the available interfaces, including tmm and the external VLAN:

    debuguser@f5-tmm-6f4f5cb664-glg2w:~$ tcpdump -D
    1.xeth0
    2.tmm
    3.eth0
    4.external
    5.net1
    6.net2
    7.any (Pseudo-device that captures on all interfaces)
    8.lo [Loopback]

  4. When running the tcpdump utility in the debug container, you can specify the interface or VLAN on which to capture traffic. You can also include filters to restrict the output to specified addresses, ports, and protocols. After capturing the traffic you want, enter ctl-c to stop the tcpdump utility.

    For example, to capture traffic on all TMM interfaces, enter the following command:

    Important: Running tcpdump on interface 0.0 has the potential to generate very large files. When capturing on interface 0.0, you should use filters to reduce the size of the capture. 

    tcpdump -ni 0.0 

    Note: The -n option disables name resolution.

    To capture only the external VLAN, enter the following command:

    tcpdump -ni external 

    To specify destination port 8080, enter the following command:

    tcpdump dst port 8080

    You can combine options and use the -w option to save the output to a file. This example captures traffic on the external VLAN with destination port 8080 and saves the output to the current directory on the debug container:

    tcpdump -ni external and dst port 8080 -w cnf_external.pcap

    For more information about using tcpdump filters to capture traffic, refer to K411: Overview of packet tracing with the tcpdump utility.

  5. After capturing the traffic you want, enter the following command to disconnect from the debug container:

    exit

  6. Copy the tcpdump output file to your workstation using the following syntax:

    kubectl cp <namespace>/<tmm_pod_name>:<tcpdump_file_name> ./<tcpdump_file_name> -c debug

    For example, if the TMM pod is named f5-tmm-6f4f5cb664-glg2w and resides in the cnf-gateway namespace, enter the following command to copy the cnf_external.pcap file:

    kubectl cp cnf-gateway/f5-tmm-6f4f5cb664-glg2w:cnf_external.pcap ./cnf_external.pcap -c debug

  7. Provide the tcpdump output file to F5 Support. To do so, refer to K000090853: Exchange files with F5 Support using MyF5.
