K000132338: Is it possible to synchronize connection mirroring information after a reboot or TMM restart?

Description

This article covers whether connection mirroring information gets pushed or synchronized to peer devices in the group when a failover occurs after one of the devices is rebooted or TMM restarts.

Environment

  • Connection mirroring configured for one or more virtual servers or SNATs.
  • BIG-IP systems part of a Device Service Clustering (DSC) group.

Cause

Standard virtual server

The connection and SSL mirroring data from a Standard virtual server gets flushed out when the TMM process restarts and does not get re-mirrored from the newly active device to the standby device. As part of rebooting the device, TMM gets restarted. 

Performance L4 virtual servers and SNATs

The mirroring data from Performance L4 virtual servers and SNATs get flushed out when the TMM process restarts; however, these local traffic objects re-mirror existing connection data from the newly active device to the standby device.

Recommended Actions

If you reboot or restart TMM on either device in the device group, it will teardown the mirrored connections that you see in the mirroring channel and you will no longer see it on the device where TMM restarted, so it isn't possible to mirror these existing connections any longer. That is because you cannot build the state and history of that connection because packets can no longer be mirrored on both devices on Standard virtual servers. Once the device in question is back online, new connections will get mirrored through this channel once again. As noted previously, existing connections are re-mirrored from Performance L4 virtual servers and SNATs.

With HA setup in place and connection mirroring enabled for your virtual server(s), when traffic goes through the active device in the traffic group, you will see the connections being mirrored in a packet-by-packet basis on the peer device (if you got a packet capture on both devices for that virtual server, you'll see them being mirrored). There are a couple of things to be aware of in this situation when traffic processing takes place:

(1) The mirrored connections handled through the mirroring channel can be viewed with the following command output (on both devices):

tmsh show sys connection type mirror


(2) Aside from this, the active device in the traffic group will continue to handle those connections and you can view them using this command:

tmsh show sys connection cs-server-addr <VIP>


Depending on which device you reboot, it will still continue to process the traffic for that VIP through whichever device is active in the traffic group (which can be viewed through #2 output on the device that is active) until it is gracefully closed. However, during the course of this, re-mirroring for that existing connection will not take place on Standard virtual servers.
