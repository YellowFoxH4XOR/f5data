Known Issue

The BIG-IP DNS (formerly known as BIG-IP GTM) system may fail to synchronize the configuration to its BIG-IP DNS sync group peer. This issue occurs when all of the following conditions are met:

  • The BIG-IP DNS sync group is comprised of two or more BIG-IP DNS systems.
  • The BIG-IP DNS sync group contains one or more sync group members with an iApps application service that includes wide IPs, BIG-IP DNS pools, and other BIG-IP DNS objects.

The BIG-IP DNS sync group synchronizes only BIG-IP DNS configurations among the BIG-IP DNS systems; it should not be confused with the BIG-IP device groups that perform configuration synchronizations on the BIG-IP system.

Impact

The BIG-IP DNS systems in a sync group are unable to synchronize their configuration.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP DNS configuration is inconsistent among the systems in the same BIG-IP DNS sync group.
  • The BIG-IP DNS system logs an error message to the /var/log/gtm file that appears similar to the following example:

    011ae104:3: Gtm config sync result from local mcpd: result {
    result_code 17237812
    result_message "01070734:3: Configuration error: The object (GTM pool /Common/test.app/test_gtm_pool) is owned by a non-existent application (/Common/test.app/test)."
    }

Workaround

A workaround is not available for this issue. However, to recover the BIG-IP DNS sync group configuration synchronization failure, you must identify the iApps application service that includes BIG-IP DNS objects and remove the service from the BIG-IP DNS system. To do so, perform the following two procedures:

  • Identifying the errant iApps application service
  • Removing the errant iApps application service from the BIG-IP DNS system

Identifying the errant iApps application service

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Locate the log entry in the /var/log/gtm file that appears similar to the following example:

    011ae104:3: Gtm config sync result from local mcpd: result {
    result_code 17237812
    result_message "01070734:3: Configuration error: The object (GTM pool /Common/MyTestApp.app/MyTestApp_gtm_pool) is owned by a non-existent application (/Common/MyTestApp.app/MyTestApp)."
    }

    In this example, note the following:

    • MyTestApp is the iApps application service

Removing the errant iApps application service from the BIG-IP DNS system

Impact of workaround: The BIG-IP objects created by the iApps application service will cease to exist when you remove the iApps application service.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to iApp > Application Services > Application Service List.
  3. Select the errant iApps application service that you identified in the Identifying the errant iApps application service procedure.
  4. Click Delete.
