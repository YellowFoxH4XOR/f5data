Topic

You should consider using this procedure under the following circumstances:

  • You want the BIG-IP APM system to use the origin webserver to authenticate each user's credentials using an HTTP form.
  • You want the BIG-IP APM system to inspect the response from the origin webserver for a redirect code to a specific URL when authentication is successful.

Description

Some organizations may want to have a webserver perform user authentication and then respond with a specific redirect URL if authentication was successful. The BIG-IP APM system can prompt the users for their credentials, pass those credentials back to the webserver, and then inspect the response from the webserver to see if it redirects the user to the expected URL. If the expected URL redirect is present, the BIG-IP APM system will recognize that the user is authorized to use the system and grant access.

Prerequisites

The webserver must meet the following prerequisites before you use this procedure:

  • The webserver is configured to authenticate users.
  • The webserver is configured to send users a URL redirect upon successful authentication.

    Note: For information regarding configuring your webserver, see your webserver vendor's documentation.

Procedures

Configuring HTTP form-based authentication using URL redirect

To configure HTTP form-based authentication using URL redirect, perform the following three procedures:

  • Creating the HTTP AAA server
  • Creating the access profile
  • Applying the access profile to your virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Creating the HTTP AAA server

  1. On the navigation pane, go to the following location:
    • BIG-IP 13.0.0 and later: Navigate to Access > Authentication > HTTP.
    • BIG-IP 12.1.2 and earlier: Navigate to Access Policy, AAA servers > HTTP.
  2. Click Create.
  3. Type a name for your server.
  4. For Authentication Type, click Form Based.
  5. Optionally, specify a Start URI.
  6. Specify the HTTP Form method configured on the webserver.
  7. For Form Action, enter the complete URL that returns the redirect code. Make sure to include the protocol, server, and port.

    For example:

    http://10.10.10.10/auth.php

    Note: If your configuration requires that you use HTTPS, you will need to configure a layered virtual server that listens on the server IP address and port (80), uses a Server SSL profile, and has a pool with your HTTPS AAA server as a pool member.

  8. In the Number of Redirects to Follow box, enter the number 1.

    Note: If your configuration requires more than one redirect, change this number accordingly.

  9. For Successful Logon Detection Match Type, click By Resulting Redirect URL.
  10. In the Successful Logon Detection Match Value box, enter the complete URL that the user should be redirected to when they successfully authenticate.

    For example:

    https://10.10.10.10/welcome.php

  11. Click Finished.

Creating the access profile

  1. Navigate to Access Policy > Access Profiles.
  2. Click Create.
  3. Type a name for your access profile.
  4. Click Finished.
  5. Click Edit for the access profile you just created.
  6. Click the (+) icon after the Start box.
  7. Under General Properties, click Logon Page.
  8. Click Add Item.
  9. Review the pre-populated information for the logon page and make any needed changes.
  10. Click Save.
  11. Click the (+) icon after the Logon Page action.
  12. Under Authentication, click HTTP Auth.
  13. Click Add Item.
  14. Click the AAA server you created from the list.
  15. Click Save.
  16. Click on the ending action box of the Successful branch (it is set to Deny by default).
  17. Click Allow.
  18. Click Save.
  19. Click Close.
  20. Select the check box for the access profile you just created.
  21. Click Apply Access Policy.

Applying the access profile to your virtual server

  1. Navigate to Local Traffic > Virtual Servers.
  2. Click the virtual server for which you want to use HTTP authentication.
  3. Under Access Policy, click your newly-created access profile.
  4. Click Update.
