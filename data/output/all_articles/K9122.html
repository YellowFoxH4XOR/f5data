K9122: The BIG-IP system uses an incorrect idle timeout for some load-balanced traffic, resulting in dropped sessions

Known Issue

This is the result of a known issue. A protocol profile Idle Timeout setting specifies the number of seconds that a flow can remain idle before the BIG-IP system removes the connection. On certain occasions, an uninitialized variable causes the BIG-IP system to replace the protocol profile idle timeout with the TCP handshake timeout of five seconds, resulting in dropped sessions.

For example, when processing a UDP session, the BIG-IP system erroneously replaces the UDP profile idle timeout value with the TCP handshake timeout value of five seconds, causing the UDP stream to be dropped. The following bigpipe conn command output displays that a UDP stream to the 10.100.100.1:any virtual server has been idle for 17 seconds, and is configured with an idle timeout of 100 seconds:

VIRTUAL 10.100.100.1:any <-> NODE 10.10.10.6:6972 TYPE any
CLIENTSIDE 10.120.120.120:29436 <-> 10.10.10.6:6972
(pkts,bits) in = (0, 0) out = (0, 0)
SERVERSIDE 10.100.100.1:29436 <-> 10.10.10.6:6972
(pkts,bits) in = (0, 0) out = (0, 0)
PROTOCOL udp UNIT 1 IDLE 17 (100)

The following bigpipe conn command output displays that a UDP stream to the same virtual server has been idle for one second, and has an idle timeout of five seconds:

VIRTUAL 10.100.100.1:any <-> NODE 10.10.10.6:6970 TYPE any
CLIENTSIDE 10.120.120.120:29436 <-> 10.10.10.6:6970
(pkts,bits) in = (4502, 3.593M) out = (82, 7187)
SERVERSIDE 10.100.100.1:29436 <-> 10.10.10.6:6970
(pkts,bits) in = (82, 7187) out = (4502, 3.671M)
PROTOCOL udp UNIT 1 IDLE 1 (5)

Note: This issue is not limited to UDP traffic.

F5 Networks Product Development tracked this issue as CR105697 and it was fixed in BIG-IP version 9.4.6 and version 10.0.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in BIGIP-9.6.1-839.0-HF3, which has been issued for BIG-IP version 9.6.1. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.
