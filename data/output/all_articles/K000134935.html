K000134935: Error while generating qkview on BIG-IQ

Type
Support Solution
Published
2023-06-06
Updated
2023-06-06
Source
https://my.f5.com/manage/s/article/K000134935

Description

You are trying to generate a qkview on your BIG-IQ CM and it fails everytime. You already ran "qkview -v" and still see errors like the ones below.

pg_dump: Dumping the contents of table "asm_cc_policies_signatures" failed: PQgetResult() failed.
pg_dump: Error message from server: ERROR:  canceling statement due to conflict with recovery
DETAIL:  User query might have needed to see row versions that must be removed.


Environment

BIG-IQ CM version 8.2
QKview utility


Cause

This occurs due to Bug ID1217269, but even after attempting to generate the qkview again, you will still see the errors described.


Recommended Actions

This involves a change in system variables and a reboot of your BIG-IQ so the changes take effect.
Impact of workaround: If your CM is standalone, you will temporarily stop collecting statistics and you will be unable to manage it while is coming up.

1. On CM
# cd /var/lib/pgsql/data/

2. Edit the postgresql.conf archive with the text editor of your convenience (vim or nano).

3. Look for the following variables and change the default value of 30 to 180.
  
max_standby_archive_delay = 180s       # max delay before canceling queries
max_standby_streaming_delay = 180s     # max delay before canceling queries

You can increase the value to be more than 180, but you mustn't set the value higher than 5 minutes (300 seconds).

4. Save the changes on exit.

5. Reboot your BIG-IQ.
# reboot

6. Attempt to generate the qkview again, it should finish without errors.
