Chapter 0: Guide introduction and contents

Introduction

About the OWASP Top 10

The Open Web Application Security Project (OWASP) Top 10 defines the most serious web application security risks, and it is a baseline standard for application security. For more information refer to the OWASP Top 10 - 2021.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

F5 products provide controls that enable you to secure your F5 products and applications against the OWASP Top 10 risks.

Secure F5 products against OWASP Top 10 security risks

This guide provides information about securing your F5 products against the OWASP Top 10 security risks.

Secure your applications against OWASP Top 10 risks with F5 products

This guide describes how to use the security controls available in F5 products to secure your applications against the OWASP Top 10 application security risks. Bear in mind that your configuration and the level of security protection you implement depend on the specifics of your application.

BIG-IP Advanced WAF/ASM

Security controls are available in the BIG-IP Advanced WAF/ASM system, which uses both positive and negative security models to secure your applications against OWASP Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and application response. The negative security model uses attack signatures to detect and thwart OWASP Top 10 application security attacks.

Note: For information about the recommendations on which attack signature sets to enable on your BIG-IP Advanced WAF/ASM system, refer to the BIG-IP Advanced WAF/ASM controls table of each OWASP Top 10 chapter listed in the Contents section in the later part of this article.

BIG-IP APM

You can enhance application security against OWASP Top 10 risks by using the BIG-IP APM system, which provides application authentication and API protection.

NGINX App Protect

Security controls are available in the NGINX App Protect system, which uses both positive and negative security models to secure your applications against OWASP Top 10 risks. The positive security model is based on a combination of validated user sessions, user input, and application response. The negative security model uses attack signatures to detect and thwart OWASP Top 10 application security attacks.

F5 Distributed Cloud

You can use F5 Distributed Cloud to mitigate the OWASP top 10. For more information on how to do so using  the different security controls available, for each of the OWASP top 10, and under different scenarios, refer to the Mitigating OWASP Web Application Security Top 10 – 2021 risks using F5 Distributed Cloud Platform for an overview and links to each chapter on DevCentral.

Contents

Chapter 1: Broken access control (A1)

Broken access control occurs when an issue with the access control enforcement allows a user to perform an action outside of the user's limits. An attacker may be able to exploit a broken access control flaw with the intention of gaining elevated access to a protected resource to which they are not entitled. As a result of the privilege escalation, the attacker can perform unauthorized actions.

  • Broken access control
  • Secure F5 products against broken access control attacks
  • Secure your applications against broken access control attacks with F5 products

Chapter 2: Cryptographic failures (A2)

Cryptographic failure occurs when an attacker targets sensitive data, such as passwords, credit card numbers, and personal information, when you do not properly protect them. Cryptographic failure is the root cause for sensitive data exposure. According to the Open Web Application Security Project (OWASP) 2021, securing your data against cryptographic failures has become more important than ever.

  • Cryptographic failures
  • Secure F5 products against cryptographic failures
  • Secure your applications against cryptographic failures with F5 products

Chapter 3: Injection (A3)

Injection attacks occurs when an attacker sends malicious data to make the application process it and do something it is not designed to do. Injection vulnerabilities are prevalent, especially in legacy code that does not validate or sanitize user-supplied input.

  • Injection attacks
  • Secure F5 products against injection attacks
  • Secure your applications against injection attacks with F5 products

Chapter 4: Insecure design (A4)

Insecure design is focused on the risks associated with flaws in design and architecture. To exploit insecure design, attackers can threat model workflows in the software to reveal a broad range of vulnerabilities and weaknesses.

  • Insecure design
  • Secure F5 products against insecure design
  • Secure your applications against insecure design with F5 products

Chapter 5: Security misconfiguration (A5)

Security misconfiguration vulnerabilities occur when a web application component is susceptible to attack due to a misconfiguration or insecure configuration option. Misconfiguration vulnerabilities make your application susceptible to attacks that target any part of the application stack.

  • Security misconfiguration
  • Secure F5 products against security misconfiguration
  • Secure your applications against security misconfiguration with F5 products

Chapter 6: Vulnerable and outdated components (A6)

Component-based vulnerabilities occur when a software component is unsupported, out of date, or vulnerable to a known exploit. Using components with known vulnerabilities makes your application susceptible to attacks that target any part of the application stack.

  • Vulnerable and outdated components
  • Secure F5 products against vulnerable and outdated components attacks
  • Secure your applications against vulnerable and outdated component attacks with F5 products

Chapter 7: Identification and authentication failures (A7)

Identification and authentication failures can occur when functions related to a user's identity, authentication, or session management are not implemented correctly or not adequately protected by an application.

  • Identification and authentication failures
  • Secure F5 products against identification and authentication failures
  • Secure your applications against identification and authentication failures with F5 products

Chapter 8: Software and data integrity failures (A8)

Software and data integrity failures relate to code and infrastructure that does not protect against integrity violations. Attackers can exploit these failures to introduce unauthorized access, malicious code, or complete system compromise.

  • Software and data integrity failures
  • Secure F5 products against software and data integrity failures
  • Secure your applications against software and data integrity failures with F5 products

Chapter 9: Security logging and monitoring failures (A9)

Security logging and monitoring failures are frequently a factor in major security incidents. Insufficient logging, monitoring, or reporting makes your application susceptible to attacks that target any part of the application stack.

  • Security logging and monitoring failures
  • Secure F5 products against security logging and monitoring failures
  • Secure your applications against security logging and monitoring failures with F5 products

Chapter 10: Server-side request forgery (SSRF) (A10)

Server-side request forgery (SSRF) flaws occur when a web application fetches a remote resource without validating the user-supplied URL. To execute an SSRF attack, the attacker abuses the functionality on the server to read or update internal resources. The attacker can then force the application to send requests to access unintended resources, often bypassing security controls.

  • Server-side request forgery (SSRF)
  • Secure F5 products against SSRF
  • Secure your applications against SSRF with F5 products
