K000160690: Understanding Monitor Logs for Forced Offline Members in BIG-IP LTM

Description

Monitor status logs (such as "monitor status down") may appear for pool members that have been administratively forced offline in BIG-IP LTM. For example:

Apr 3 23:34:12 notice mcpd[8410]: 01070638:5: Pool /Common/pool-x.x.x.x member /Common-/y.y.y.y:443 monitor status down. [ /Common/tcp_half_open: down; last error: /Common/tcp_half_open: No successful responses received before deadline. @2026/04/03 23:34:12. ] [ was node down for 888hrs:12mins:33sec ]

Environment

  • Pool members configured with health monitors (e.g., tcp_half_open)
  • Pool members and/or nodes administratively forced offline

Cause

When a default node monitor is configured, it continues to run and send probes to nodes even if the node or pool member is administratively disabled or forced offline. This can result in ongoing monitor status logs for those members.

Answer/Recommended Actions

Disabling or forcing offline a pool member or node does not automatically stop all monitoring activity if a default node monitor is configured.

  • To fully stop monitoring and related log entries for a node or pool member:
    • Remove the monitor from the node or pool member configuration, or remove the default node monitor from the global configuration if you do not want it applied to any node.
  • No traffic will be sent to a forced offline node or pool member, but monitoring and logging may continue until the monitor is removed.

Additional Information

  • This behavior is by design. Default node monitors are intended to always track node health unless explicitly removed.
  • The presence of monitor status logs does not indicate that traffic is being sent to the offline member; it only reflects ongoing monitoring activity.
  • You can check if the monitor is probing with the command 

    tmctl monitor_instance_stat -w300
