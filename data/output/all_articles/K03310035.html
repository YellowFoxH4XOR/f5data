Known Issue

The BIG-IP configuration may fail to load after you upgrade to BIG-IP 13.1.0 due to the system failing to validate SSL attributes in monitors.

This issue occurs when all of the following conditions are met:

  • You attempt to upgrade to BIG-IP 13.1.0 from an earlier release.
  • Your configuration contains a monitor object that has one of the following SSL attributes:
    • Invalid SSL attributes (For example, the certificate and key do not match.)
    • An encrypted SSL key

Beginning in BIG-IP 13.1.0, the system validates the SSL attributes of monitors. For monitors that contain SSL attributes, the BIG-IP system creates a new Server SSL profile based on the SSL attributes of the monitor before you upgraded. As a result, if your BIG-IP configuration contains a monitor object with invalid SSL attributes or an encrypted SSL key, the configuration fails to load after you upgrade the system.

For example, before the upgrade, the following configuration contains an HTTPS monitor object configured with the default.crt certificate without a matching key:

ltm monitor https /Common/monitor_name {
    adaptive disabled
    cert /Common/default.crt
    cipherlist DEFAULT:+SHA:+3DES:+EDH
    compatibility enabled
    defaults-from /Common/https
    destination *:*
    interval 5
    ip-dscp 0
    recv none
    recv-disable none
    send "GET /\r\n"
    time-until-up 0
    timeout 16
}

Impact

The BIG-IP system configuration fails to load after you upgrade the system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The configuration fails to load after you upgrade the system.
  • If the affected monitor contains a certificate and key that do not match, the system configuration fails to load and in the /var/log/ltm file, you observe an error message similar to the following example:

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- 01070315:3: profile /Common/example_ssl_profile's key and certificate do not match Unexpected Error: Loading configuration process failed.

    err mcpd[3738]: 01070425:3: Full configuration load failed.

  • If the affected monitor contains an encrypted key, the system configuration fails to load and in the /var/log/ltm file, you observe an error message similar to the following example:

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- 01070313:3: Error reading key PEM file /Common/<key_name>.key for profile /Common/<serverssl profile name>: error:0907B068:PEM routines:PEM_READ_BIO_PRIVATEKEY:bad password read Unexpected Error: Loading configuration process failed.
    err mcpd[<pid>]: 01070425:3: Full configuration load failed.

Workaround

To prevent this issue before you upgrade the system, or to correct this issue after you upgrade, perform one of the following procedures:

  • Prevent this issue before upgrading
  • Correct this issue after upgrading

Prevent this issue before upgrading

To prevent this issue, you can assign a certificate and a matching key that is not encrypted to the affected monitor object in the Configuration utility.

Impact of workaround: Configuring a monitor object with an incorrect certificate or key may cause the monitor to fail. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select the name of the affected monitor.
  4. For Configuration, select Advanced.
  5. For Client Certificate, select a certificate.
  6. For Client Key, select a matching key that is not encrypted.

Correct this issue after upgrading

If the issue is due to a certificate and key mismatch, to correct the issue after you upgrade the system, you can assign a matching certificate and key in the Server SSL profile by editing the /config/bigip.conf file and performing a manual configuration load.

Note: If the issue is due to a monitor containing an encrypted private key, this procedure is not applicable. Refer to Preventing this issue before upgrading.

Impact of workaround: Editing the /config/bigip.conf file and performing a manual configuration load disrupts service. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP command line.
  2. Make a copy of the /config/bigip.conf file by entering the following command:

    cp /config/bigip.conf /config/bigip.conf.K033100355

  3. Use a text editor to edit the /config/bigip.conf file.
  4. Locate the affected Server SSL profile that has the invalid SSL attributes and assign a matching certificate and key.

    For example, the following Server SSL profile has a certificate configured without a matching key.

    ltm profile server-ssl /Common/serverprofile_name {
        app-service none
        cert default.crt
        cipher-group none
        ciphers DEFAULT:+SHA:+3DES:+EDH
        defaults-from /Common/serverssl
    }

  5. Assign a matching key to the Server SSL profile, as in the following example:

    ltm profile server-ssl /Common/serverprofile_name {
        app-service none
        cert default.crt
        cipher-group none
        ciphers DEFAULT:+SHA:+3DES:+EDH
        defaults-from /Common/serverssl
        key default.key
    }

  6. Save changes to the file and exit the text editor.
  7. Reload the configuration using the TMOS Shell (tmsh) by entering the following command:

    tmsh load /sys config
