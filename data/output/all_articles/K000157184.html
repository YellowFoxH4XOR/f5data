K000157184: HTTP/2 HTTP::respond may doesn't work with the TCP::Close

Description

During migration of the Virtual Server from HTTP/1 to HTTP/2 by changing both client and server side to work with HTTP/2 as well as enabling MRF router you can encounter a problem with the iRule.

Environment

  • BIG-IP
  • HTTP/2
  • iRule

Cause

The observed behavior is expected in 17.1.x. The combination of HTTP::respond followed by reject will not send the HTTP response to the client. This is a product change, not a syntax error.

Recommended Actions

Recommend using TCP::close instead of reject if the goal is to send a response and then gracefully close the connection. TCP::close will allow the response to be sent before the connection is closed. If an abrupt connection reset is required, please be informed that the response will not be sent. This is by design in 17.x.
