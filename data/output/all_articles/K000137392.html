Description

Upon Big-IP upgrading the Protocol Inspection dashboard shows a new inspection event with ID equals to 1 without any description.

Environment

BIG-IP AFM configured for use Protocol Inspection.

Cause

This behaviour is expected.

Details

Aggregation takes place in device in order to keep memory consumption reasonable and not over-use memory that is not allocated to AVR. Aggregation takes place due to different reasons and one of this is when publishing data to DB.

There is aggregation after upgrading device because during this process all the data collected when previous version was running has to be published in the DB that is running in the upgraded BIG-IP version.

There is a limitation on how many records AVR supports per table. If an in-memory table from shared memory has more records than this number, AVR will sort the stats (by hit-count) and publish only the top records. All the rest will be aggregated to keep metrics correct and we will see an entry in Inspection Dashboard under Inspection Events widget.
 

Recommended Actions

This behaviour is expected.
