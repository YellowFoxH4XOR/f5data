K000133239: Device is INOPERATIVE mode after software upgrade from 15.1.8 or 15.1.8.1 to 16.x or 17.x

Description

After software upgrade from versions 15.1.8 or 15.1.8.1 to versions 16.x or 17.0.x , BIG-IP is in INOPERATIVE state and configuration load fails with following errors:

-- crit tmsh[16188]: 01420001:2: Can't load keyword definition (vlan.dag_adjustment) : framework/SchemaCmd.cpp, line 825
-- crit tmsh[25644]: 01420001:2: Can't load keyword definition (vlan.nti) : framework/SchemaCmd.cpp, line 825
-- Can't find matched schema tag for association's attribute fw_zone_log_profile.pzname during loading cli version syntax: 15.1.8
-- Can't find matched schema tag for association's attribute fw_protected_zone.pzname during loading cli version syntax: 15.1.8
-- Unexpected Error: "Can't load keyword definition (vlan.dag_adjustment)"
-- fatal: (Can't load keyword definition (vlan.nti)) (framework/SchemaCmd.cpp, line 825), exiting...
-- emerg load_config_files[16186]: "/usr/bin/tmsh -n -g -a load sys config partitions all base " - failed. -- Loading schema version: 15.1.8
-- err mcpd[10702]: 01070422:3: Base configuration load failed.

 

Environment

  • BIG-IP
  • Software upgrade from 15.1.8 or 15.1.8.1 to 16.x or 17.0.x

Cause

  • Bug ID1161913

Recommended actions

To solve this issue, you can apply workaround from bugtracker: ID1161913

However, in some cases you may not be able to to copy and paste workaround script (for example if VMware web console is used).
In this case, you can roll back the upgrade (reboot back to 15.1.8 or 15.1.8.1) and put workaround script into /config directory, so it is copied during software installation.

Here are the steps:

  1. After booting back to previous software, log in using command line to BIG-IP and create text file in /config directory (for example using vi text editor).
    1. Paste commands from workaround section from BugID: Bug ID 1161913: Upgrade from 15.1.8 or 15.1.8.1 to 16.x or 17.x fails, and leaves device INOPERATIVE
  2. After this, you will have to delete boot location with v16.x or v17.0.x software and install v16.x or v17.0.x software once again (to make sure that text file with workaround was copied into new boot location). 
  3. Reboot into the newly created volume.
  4. Have a console connection ready, wait for some time until config load process fails and device stuck in INOPERATIVE state
  5. Make sure you are in /config directory (you can check it by running pwd command)
  6. Make text file (which was created in step 1) executable by running chmod +x <filename>
  7. Perform workaround by running ./<filename> , it should return no errors 
  8. Load the configuration again:
# tmsh load sys config

Note: Configuration load will take some time, wait until it changes to Standby (Disconnected). Disconnected status is normal during upgrade, as ConfigSync does not work between different software versions. 

You can check if configuration loaded up correctly by running 'tmsh show sys mcp-state'. If configuration loaded correctly, output should be similar to this:
 

# tmsh show sys mcp-state
--------------------------------------------------------
Sys::mcpd State:       
--------------------------------------------------------
Running Phase          running
Last Configuration Load Status full-config-load-succeed
End Platform ID Received    true

Save the configuration by running 

# tmsh save sys config
