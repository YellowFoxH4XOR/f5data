Description

  • There are no ARPs coming from BIG-IP Virtual Server IP addresses.

Environment

  • BIG-IP LTM
  • Virtual server
  • ARP

Cause

ARP is not advertised by BIG-IP Virtual Server due to disabled arp option in virtual address.

Recommended Actions

Verify the address of the Virtual Server using the Configuration utility

  1. From the Configuration utility, click Local Traffic.
  2. Navigate to Virtual Servers > Virtual Address List.
  3. Click the Virtual Address to be modified.
  4. Check if State is Enabled from the drop-down list.
  5. Verify if the ARP check box is selected.
  6. Any changes submit using Update.

Verify the address of the Virtual Server using the tmsh utility

  1. Log in to the TMOS Shell (tmsh) by typing the following command:
    tmsh
  2. List properties of the affected Virtual address using the below command.
    list ltm virtual-address <virtual address> all-properties

    Example:
    list ltm virtual-address 192.0.2.41 all-properties
    ltm virtual-address 192.0.2.41 {
        address 192.0.2.41
        app-service none
        arp disabled          <<--- should be set to enabled
        auto-delete true
        connection-limit 0
        description none
        enabled no            <<--- should be set to yes
        floating enabled
        icmp-echo enabled
        inherited-traffic-group false
        mask 255.255.255.255
        metadata none
        partition Common
        route-advertisement disabled
        server-scope any
        spanning disabled
        traffic-group traffic-group-1
        unit 1
    }
  3. Modify values if are not expected for proper ARP advertising:
    modify ltm virtual-address <virtual address> { enabled yes arp enabled }

    Example:
    modify ltm virtual-address 192.0.2.41 { enabled yes arp enabled }

Capture traffic filtering specifically to catch ARP

  1. Use tcpdump capture to collect ARP traffic from specified IP address:
    tcpdump -nni 0.0:nnn -s0 -w /var/tmp/<file_name>.pcap arp
    Note: Captured file can be found in /var/tmp/ directory
     
  2. If the captured file contains ARP entries with the source address of BIG-IP's Virtual Server, then verify the environment in case of any ARP block in infrastructure.

Additional Information

If the problem remains and captures' traffic shows no ARP entries coming from BIG-IP, collect captured tcpdump along with a fresh Qkview file and open a Service Request by contacting F5 Networks Support.
