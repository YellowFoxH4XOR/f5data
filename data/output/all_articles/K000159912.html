Description

This article describes what you can do to troubleshoot when you observe issues with a VELOS system controller. 

Environment

One system controller is working while you observe any one of the following issues on the second one:

  • A system controller is unable to join the cluster.
  • You have no SSH connectivity to it.
  • You have no console connectivity to it.
  • Hardware issues

Cause

This can be due to both hardware or software issues.

Recommended Actions

Depending on the issue you are observing, use the following as a checklist to troubleshoot the issue.
Important: When rebooting, resetting, re-seating the affected system controller, always ensure you are working on the right one. Refer to the diagrams in the Platform guide.

Advanced

Troubleshoot container issues. For example, 

  • Verify platform-services-deployment and sw-mgmt logs using the command: 
    journalctl -u sw-mgmt -u platform-services-deployment -b
    The output may contain no entries, indicating no errors.
  • To list the 2 services with their status and a description of what they do, enter:
    systemctl list-units --all
  • To list all services that has has ever written a log entry to the journal files, enter:
    journalctl -F _SYSTEMD_UNIT 
  • Review /var/log/sw-mgmt.debug for the sw-mgmt service.
  • K000139791: Troubleshoot F5OS services with docker commands
Proceed to the next step (row). Reboot or reset or re-seat the affected system controller.

A system controller is unable to join the cluster

 

You have performed troubleshooting in the previous step (row), and the issue persists.

  • Login to the system controller to reboot it. Use K000151512: How to reboot velos system..
  • Re-seat the affected system controller. The procedure here describes how to physically replacing a system controller. Follow the same procedure, but instead of replacing, reseat your system controller.
  • Perform a PXE clean install of the affected system controller using K000152443: VELOS PXE clean install of system controller.
  • Use the following resources to rebuild the Openshift cluster:
    Note: This process typically takes around 90-110 mins.
    • Begin at step 5 of K000152701: How to reinstall the OpenShift cluster on VELOS systems.
    • K000139870: Troubleshoot the Openshift cluster installation in F5OS-C.
  • When you suspect a hardware issue with the controller, and have an additional system controller, refer to K000133249: Replacing VELOS system controller after a Return Materials Authorization.

No SSH access to the system controllerEstablish SSH connectivity to the affected controller:
To do so, login to bash on the healthy system controller and connect on SSH using one of the following:
  • Connect using hostname:
    • Syntax: ssh controller-#
      For example: ssh controller-1
  • Connect using IP address. If SSH fails with the hostname, try again on vlan5 starting with a ping test:
    1. Syntax: ping controller-#
      For example:
      ping controller-1
      PING controller-1.chassis.local (100.65.3.51) 56(84) bytes of data.
    2. The above connects to vlan3. Change the third octet in the IP address from 3 to 5. Connect to it.
      ssh 100.65.5.51
  • Directly connect to the console port of the suspect controller.
    • Enter Esc + Shift-F9 to access the AOM menu.
    • Type I to view the controller information. Verify that controller is powered ON.
    • Type Q to return to console.
    • Enter the return key to see if a prompt appears.
    • Wait 5-10 mins for activity as the controller could be rebooting.
    • If nothing displays, reset controller CPU, by entering AOM again followed by RC.
    • Type Q to return to console.
    • If nothing displays, re-seat the system controller.
No console access to the system controller

There are 2 methods to access the console of a system controller. Attempt both as described in K65442484: Overview of access to the F5 VELOS system.

Troubleshoot direct console access with  K000139067: Connecting to the serial console on the rSeries and VELOS.:

  • Try connecting from both workstation and console server.
  • Verify electrical connects including using correct RJ45 serial cables.
  • Verify baud rate.
  • Also try SSH access through the healthy system controller in the prior step above.
  • Physically unplug the power supply and re-seat the affected controller.
    The procedure here describes how to physically replace a system controller. Follow the same procedure, but instead of replacing, reseat your system controller.
  • When you are certain there is neither console nor SSH access, contact F5 support to request for an RMA.
