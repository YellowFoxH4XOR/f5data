Known Issue

This is the result of a known issue. In passive FTP mode, the FTP client initiates a control stream connection to the FTP server on port 21, and the FTP server replies to the client with a message containing the server's IP address and the port on which it is listening. The message appears similar to the following example:

227 Entering Passive Mode (A,B,C,D,x,y)

The server then waits for a data connection from the FTP client.

When a virtual server configured with an FTP profile processes a passive FTP connection, and the 227 Entering Passive Mode (A,B,C,D,x,y) response contains the pool member's IP address, the BIG-IP system translates the IP address to that of the virtual server and passes the response through to the client. The FTP client then initiates the data connection to the virtual server IP address.

When a virtual server configured with an FTP profile processes a passive FTP connection, and the 227 Entering Passive Mode (A,B,C,D,x,y) response does not contain the pool member IP address, but the IP address of an alternate server, the BIG-IP system does not translate the IP address to that of the virtual server, and instead passes the alternate IP address through to the client. As a result, the client attempts to initiate the data connection directly to the alternate IP address, causing the connection to fail.

Note: This issue does not occur in BIG-IP version 10.x. In version 10.x, when a virtual server configured with an FTP profile processes a passive FTP connection, and the 227 Entering Passive Mode (A,B,C,D,x,y) response does not contain the pool member IP address, but the IP address of an alternate server, the BIG-IP system will reset both the data channel and the control channel.

F5 Product Development is tracking this issue as CR117566.

Workaround

You can work around this issue by associating an iRule with the FTP virtual server. For a sample iRule, refer to the following DevCentral page:

https://devcentral.f5.com/wiki/iRules.iRule_for_passive_ftps_in_ccc_mode.ashx

Note: A separate DevCentral login is required to access this content.
