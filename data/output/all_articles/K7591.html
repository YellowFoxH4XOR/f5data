Known Issue

This is the result of a known issue. In BIG-IP LTM 9.x, you can run the tcpdump utility from the Configuration utility. When you run tcpdump from the Configuration utility, the BIG-IP system creates a memory file system that is used to store the tcpdump files. Once tcpdump has finished running, the tcpdump files are compressed and written to the /mnt/support ramfs partition. In certain cases, when the BIG-IP system is under heavy load, running tcpdump from the Configuration utility can cause a severe memory shortage and input/output (I/O) scheduling issues. As a result, the BIG-IP system can become unresponsive and core dump.

Note: In most cases, F5 recommends running the tcpdump utility from the command line.

For more information about packet tracing with the tcpdump utility, refer to K411: Overview of packet tracing with the tcpdump utility.

For recommended methods and limitations for running tcpdump on a BIG-IP 9.x system, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP version 9.x system.

F5 Product Development tracked this issue as CR79405 and it was fixed in BIG-IP 9.4.4. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator release notes.
