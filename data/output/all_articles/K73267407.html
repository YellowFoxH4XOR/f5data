Description

SSLO is not cross-version compatible between major version upgrades.
If you are upgrading from BIG-IP v14.x or v15.0, F5 recommends you follow the procedure shown below when upgrading to the newest version of SSL Orchestrator from a previous version.

Some sections are conditional and are based on your particular upgrade path.
Ensure that you review all instructions and conditions for which sections are optional, required, or can be skipped.

Environment

  • BIG-IP
  • v14.x or v15.0
  • SSLO module is provisioned
  • High Availability

Cause

If you are on 14.x or v15.0 and do not follow the recommended upgrade procedure to undeploy your previous SSL Orchestrator deployments, as well as uninstall your previous version of the application, further manual steps are required to reset your environment and undeploy the previous version.

Recommended Actions

The following is a summary of the upgrade steps.  For the fully detailed upgrade procedure, see K64003555: BIG-IP update and upgrade guide | Chapter 23: Update or upgrade the F5 SSL Orchestrator

  1. Take screenshots of the SSLO configuration for a reference.

  2. Before doing any changes/activities, create a fresh UCS of the BIG-IP device in question and copy it to a remote and secure connection as a precautionary measure; see K13132.

  3. Breaks device trust for ALL devices; see K42161405.

  4. Run the built-in "Delete Configuration" utility in the SSLO UI first, navigate to SSLO Config -> landing page -> "Delete Configurations".

  5. Delete any remaining objects under iApps -> Application Services -> Applications LX.

  6. Delete the SSL Orchestrator objects under iApps -> Templates -> Templates LX.

  7. Delete the SSL Orchestrator RPM under iApps -> Package Management LX.

  8. Verify to make sure all the application services are deleted for SSLO by running below commands:

    • List SSLO objects for applications:

      tmsh list sys application service

    • Use this if objects still remain for SSLO to delete:

      tmsh delete sys application service <service name>

  9. Clear rest database:

    clear-rest-storage -l

    Note: clear-rest-storage completely clears the stored state for the REST framework.
    Important: The -l option deletes the restjavad log files as well as the stored state. also, -l option will also wipe Access Guided Config data.

  10. Reboot

  11. Install ISO image of the desire software version to new volume and boot into new volume ( Active/Standby); see: K84554955.

  12. Install RPM for SSLO (Active/Standby).

  13. Rebuilding the trust for HA.

  14. Rebuild SSLO configuration.

Additional Information

Clearing Rest Storage will remove storage for all iAppLX applications. This step may be skipped or backup your iAppLX data. Also, failure to clear rest storage may create issues with SSLO after upgrade. If future modules released in future releases for BIG-IP use REST storage, clearing rest storage may impact them.  This should be taken into consideration before clearing REST storage.
