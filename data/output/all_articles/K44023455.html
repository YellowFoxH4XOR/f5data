Description

When the F5 BIG-IP initiates a HA failover to the peer BIG-IP, a race condition can cause the Cisco ACI platforms to end up with an incorrect Endpoint IP/port database.

For example: ltm-A is the active BIG-IP and is able to process traffic. After a fail-over to ltm-B, not all traffic are able to pass correctly.

This behavior is seen when using Cisco ACI (Cisco APIC).

When accessing the Cisco ACI GUI management, it is seen that MAC address are being learned from the initial active BIG-IP only. Some MAC addresses may not be learned from the new active BIG-IP.

Environment

  • BIG-IP in HA pair
  • BIG-IP pairs are connected to Cisco ACI (Cisco APIC)
  • After failover, newly active BIG-IP may not process some traffic

Cause

The Cisco ACI fabric path learning involves what is called Endpoint IPs, which is a combination of MAC address and IP address entry. These endpoints are associated with how Cisco leaf switches forwards traffic to its network ports.

When a BIG-IP system becomes a standby unit, it may still briefly send out traffic associated with old connections that are on the active unit. This causes a race condition between the active BIG-IP sending out GARPs and the standby sending out trailing packets belonging to the same IP address. This may lead to the Cisco ACI endpoint IP and MAC binding to be incorrect.

The Cisco White Paper: ACI Fabric Endpoint Learning describes this scenario (scroll down to the section under "IP Data-plane Learning use case" section which discusses about "a possibility that the ACI fabric receives traffics with the same-source IP address from different locations").

Note: There is another similar but different scenario which can cause BIG-IP HA failover failures. When a BIG-IP pair has large numbers of virtual servers, floating self-IPs and/or SNAT IPs, an HA failover will cause a large burst of GARPs, overwhelming some peer router/switches, which results in an incomplete failover. For more information about this scenario, refer to K7332: GARPs may be lost after a BIG-IP failover event.

Recommended Actions

Option 1
Important: Please consult with Cisco TAC or a Cisco certified engineer before making changes to the Cisco ACI configuration. The recommendations here are based on specific other past customer experiences and environments that is likely to be different to your own, therefore we cannot guarantee your results will be the same as your configuration requirements may vary.
In the long term, the Cisco White Paper states the following:
The IP data-plane learning option must be disabled if you have a possibility that the ACI fabric receives traffics with the same-source IP address from different locations, which causes endpoint IP and MAC binding updates that occur due to data plane traffic.
There are three different scopes and configuration levels in IP data-plane learning as shown below:
  • EPG Subnet- per host (/32 for IPv4 or /128 for IPv6)
  • BD Subnet- per subnet
  • VRF-per VRF"
Cisco recommends disabling IP data plane learning at the most granular level. For example, if the requirement applies to only a single IP address, it should be disabled at the EPG level.
In the short term, you can temporarily correct an affected IP address after an F5 fail-over, clear the endpoint database entry on Cisco ACI:

clear system internal epm endpoint key vrf VRFNAME_VRF ip <ip address>

Using IP address 10.1.2.3 as an example to replace <ip address> in the command above, 

clear system internal epm endpoint key vrf VRFNAME_VRF ip 10.1.2.3

Additionally, in order to ensure that large amounts of GARPs sent by the BIG-IP to the peer router/switch and Cisco ACI (Cisco APIC) are not dropped, please follow the recommendation in K7332 to ensure a successful failover.


Option 2
Alternatively, you can configure MAC masquerading on your BIG-IP HA pair. This ensures the active unit retains the same MAC address upon a failover, and moves any problems associated with IP/MAC address changes to the standby unit.
Note: For more information on MAC masquerading, refer to K13502: Configuring MAC masquerade (11.x - 15.x)
