K32551743: Unable to login to Secondary BIG-IQ with error: ''URI path not registered. Please verify URI is supported...''

Type
Support Solution
Published
2021-05-04
Updated
2024-03-27
Applies to
  • Virtual Editions
Source
https://my.f5.com/manage/s/article/K32551743

Description

After creating a new authentication provider and user group on the active BIG-IQ node and tested it successfully, it's not functioning on the standby node. The following error using the new auth provider shows on the standby node upon logging in:
"URI path not registered. Please verify URI is supported and wait for /available suffix to be responsive."

Environment

  • BIG-IQ Centralized Management
  • BIG-IQ HA establishment was performed before the provider was created in the Active BIG-IQ

Cause

It is working as designed. If the HA establishment was performed before the authentication provider was created, some of the unit's workers require a restart in order to load the data - one of these cases is the Authentication Provider. 

Recommended Actions

Force the latest config changes to be applied to the secondary unit by restarting restjavad daemon.
Impact: This will cause Java to restart on the BIG-IQ, impacting all Java communication

  1. Restart restjavad process

    bigstart restart restjavad

  2. Wait for restjavad to complete start up

  3. Confirm that logging in using TACACS credentials to the Secondary BIG-IQ is successful.
