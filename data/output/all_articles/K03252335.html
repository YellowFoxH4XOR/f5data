Description

After upgrade from v13.1.3.4 to v14.1.3. system may be lost due to an out-of-memory condition on the Linux host system and you may experience the following conditions. 

  • The system froze
  • The system is slow to respond due to overload. 
  • High memory usage by bigd because a lot of pool members are flapping.


Messages similar to the following may be found in /var/log/ltm:

notice mcpd[5184]: 01070727:5: Pool /Common/<pool_name> member /<pool_member_name> monitor status up. [ monitor: up ]  [ was down for 0hr:0min:6sec ]
notice mcpd[5184]: 01070727:5: Pool /Common/<pool_name> member /<pool_member_name> monitor status up. [ http_monitor: up ]  [ was down for 0hr:0min:6sec ]

warning bigd[12901]: 01060148:4: Bigd PID 12901, instance 0, over 95% load.
warning bigd[12901]: 01060148:4: Bigd PID 12901, instance 0, over 90% load.
warning bigd[12901]: 01060148:4: Bigd PID 12901, instance 0, over 95% load.
err bigd[12901]: 01060146:3: Bigd PID 12901, instance 0, overloaded.
err bigd[12952]: 01060146:3: Bigd PID 12952, instance 0, overloaded.
warning bigd[6314]: 01060148:4: Bigd PID 6314, instance 0, over 80% load.

Environment

  • BIG-IP
  • Upgrade from v13 to v14
  • High number of monitor instances are running
  • AVR Module is provisioned and may not be in use
Cause

High number of monitors configured and AVR module causing high use of resources.

Recommended Actions

  1. De-provision AVR if not required to release system resources.  
  2. Modify the system database variable provision.extramb to use a custom allocation of additional memory for Management (MGMT)
e.g.
tmsh modify sys db provision.extramb value XXX
You may replace XXX with 500 so it will be:

tmsh modify sys db provision.extramb value 500
This will add an additional 500 MB of memory from tmm to host subsystem.

For additional information on resources provisioning, please refer to the article below. 

K26427018: Overview of Management provisioning
