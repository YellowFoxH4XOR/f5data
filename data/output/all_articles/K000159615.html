K000159615: After upgrading to 17.5.x BIG-IP VE goes down if interfaces are enabled

Type
Support Solution
Published
2026-01-20
Updated
2026-01-20
Applies to
  • Virtual Editions
  • BIG-IP
  • Vmware ESXI and vCloud Director
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000159615

Description

  • BIG-IP VE upgraded to 17.5.x
  • Interfaces were disabled before upgrade and after upgrade if the interfaces are enabled, the BIG-IP VE just becomes unresponsive.
  • GUI drops, SSH drops, Console doesn't show anything.

Environment

  • BIG-IP VE on ESXi
  • BIG-IP LTM or other modules upgraded from 15.x to 17.5.x
  • Default VM virtual hardware in vSphere is set to anything less than v13

Cause

The VM virtual hardware version is lower than recommended VM virtual hardware version for BIG-IP 17.5.x.

Answer/Recommended Actions

This isn't a BIG-IP configuration. The Default VM virtual hardware version should be at least 13 or more. This should be set from vSphere and please refer to VMware/Broadcom documentation for this. For complete list of Default VM virtual hardware version for corresponding BIG-IP VE versions, please refer to K69120675
