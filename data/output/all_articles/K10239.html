Known Issue

This is the result of a known issue. The BIG-IP system may not use the intended source address or route when sending unsolicited traffic (for example, traffic generated by a daemon running on the host). This behavior may occur if the system starts the daemon before initializing the interface through which the system reaches the intended server. Depending on the BIG-IP system's network and routing configuration, the system may reach the intended server through the management interface or through a TMM VLAN. Since the system starts the daemon before initializing the TMM interfaces and routing, the daemon may fail to communicate with the intended server.

Some management processes, such as syslogd and snmpd, allow configuration of the source address or interface that the daemon uses to initiate traffic. In these cases, the management routes are used as expected. TMM routes are used only if no management routes match the destination.

Processes that do not allow the address to be specified, may not consistently use the intended address or route, and communication for the service provided by the process may be interrupted at system startup or upon subsequent restarts of the process.

Note: For more information regarding a similar issue with ntpd, refer to K7017: The BIG-IP ntpd process is unable to communicate with the NTP server.

F5 Product Development is tracking this issue as ID 321972 (formerly CR69765).

Workaround

Refer to one of the following sections that applies to the issue you are experiencing:

Incorrect source address selection

For processes that allow it, you can ensure that a service uses the intended source address by explicitly configuring the intended source address. For example, to specify the source address for the syslog-ng daemon, refer to: K12080: Configuring the source IP address for the syslog daemon. To modify the source address for SNMP traps, refer to: K7530: Configuring SNMPv1 traps to use a source IP address other than the management IP address.

Incorrect route selection

You can ensure that outbound traffic from management process is routed using the appropriate interface by explicitly managing the routing paths available for use by the affected traffic. Local daemons are able to communicate with remote servers, both at startup and upon subsequent restarts of the daemon, under any one of the following circumstances:

  • If the intended routing is using the management interface, local processes are able to communicate with a remote server at startup and upon subsequent restarts of a local process when the following is true:

    • The remote server is located directly on the management subnet, and routing is not required for communication.
    • The remote server is routable using the management interface, and a non-default static route toward the remote server is configured.
  • If the intended routing is using a TMM interface, local processes are able to communicate with the remote server at startup and upon subsequent restarts of a local process when the following is true:

    • The management interface has not been assigned an address, and the remote server is reachable through a TMM network, either directly or using a TMM route.
    • The management network has not been assigned a default gateway, no static management routes exist that match the remote server's address, and the remote server is reachable through a TMM network, either directly or using a TMM route.

If the intended routing is using a TMM interface and the system starts the local process before initializing the TMM interfaces and routing, the local process may fail to communicate with the remote server at startup. You may work around this issue by restarting the affected daemon. To do so, use the bigstart command.

For example:

bigstart restart snmpd

Important: Non-default static routes created on the management network create a GATEWAY entry in the /etc/sysconfig/network file. You must manually remove the GATEWAY entry in BIG-IP 9.0.0 through 9.2.5, and BIG-IP 9.4.0 through 9.4.1. For information about removing GATEWAY entries for non-default static routes, refer to K7814: Non-default static routes on the management network create a GATEWAY entry.

Note: For more information about configuring and troubleshooting routing entries for management traffic use, refer to K13284: Overview of management interface routing (11.x).
