Topic

This article applies to BIG-IP ASM 9.4.2 through 10.x. For information about other versions, refer to the following articles:

  • K14342: Preserving or modifying the Server HTTP response header for BIG-IP ASM (11.x)
  • K6752: Preserving or modifying the Server HTTP response header for BIG-IP ASM (9.2.0 through 9.4.1)

The Server HTTP header allows an HTTP server to provide information about the software that the server uses to handle HTTP requests. The Server HTTP header field may contain product and version information, as well as comments identifying the server and any significant sub-products. While this information may be useful for some clients, it is considered unnecessary information leakage. As a result, the BIG-IP ASM system removes the Server HTTP header from responses to increase application security.

In BIG-IP ASM 9.4.2 and later, you can preserve or modify the Server header value by saving it before the BIG-IP ASM system processes the response, and reinserting it after the BIG-IP ASM processing is complete. To accomplish this, you must configure two virtual servers: a non-BIG-IP ASM virtual server and a BIG-IP ASM virtual server, using your existing security policy. Both virtual servers use iRules to manage the connection flow and manipulate the response headers.

The high-level sequence of events for connection processing through both virtual servers is as follows:

Request

  • The client sends a request to a non-BIG-IP ASM virtual server.
  • The iRule on the non-BIG-IP ASM virtual server forwards the request to the BIG-IP ASM virtual server.
  • The BIG-IP ASM virtual server forwards the request to the origin server.

Response

  • The origin server responds with the Server header to the BIG-IP ASM virtual server.
  • The iRule on the BIG-IP ASM virtual server saves the origin server's Server header value to another header.
  • The BIG-IP ASM security policy strips the Server header from the response.
  • The BIG-IP ASM virtual server returns the response to the non-BIG-IP ASM virtual server.
  • The iRule on the non-BIG-IP ASM virtual server inserts a new Server header with the desired value.
  • The non-BIG-IP ASM virtual server forwards the response to the client.


Building the configuration

To build this configuration, perform the following four procedures:

  • Configuring the iRule for the non-BIG-IP ASM virtual server
  • Configuring the iRule for the BIG-IP ASM virtual server
  • Configuring the non-BIG-IP ASM virtual server
  • Configuring the BIG-IP ASM virtual server

Note: Before you can build the remainder of the configuration, your BIG-IP ASM security policy must be built and applied to an HTTP class profile.

Configuring the iRule for the non-BIG-IP ASM virtual server

The non-BIG-IP ASM virtual server uses iRules to forward requests to the BIG-IP ASM virtual server, and to restore or modify the Server header in the response that the BIG-IP ASM virtual server forwards. You can include the logic for both in the same iRule. To create the iRule in the Configuration utility, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the iRules menu option.
  3. On the iRules screen, click Create.
  4. In the Name field, type a name for the iRule.

    For example:

    ServerHeader_non-ASM-VS
  5. In the Definition field, paste the following iRule:

    Note: You can modify the following iRule to insert an alternate value if the origin server's supplied Server header value is not appropriate.

    when HTTP_REQUEST {
    virtual ASM-VS
    }
    when HTTP_RESPONSE {
    if { [HTTP::header exists "Xerver"] } {
    HTTP::header insert Server [HTTP::header value "Xerver"]
    HTTP::header remove Xerver
    }
    }
  6. To save the iRule, click Finished.


Configuring the iRule for the BIG-IP ASM virtual server

The BIG-IP ASM virtual server uses iRules to save the origin webserver's Server header value to a new header. This new header value is unmodified by the BIG-IP ASM system and will be available for reinsertion by the non-BIG-IP ASM iRule created in the previous section. To create the iRule in the Configuration utility, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the iRules menu option.
  3. On the iRules screen, click Create.
  4. In the Name field, type a name for the iRule.

    For example:

    ServerHeader_ASM-VS
  5. In the Definition field, paste the following iRule:

    when HTTP_RESPONSE {
    if { [HTTP::header exists "Server"] } {
    HTTP::header insert Xerver [HTTP::header value "Server"]
    }
    }
  6. To save the iRule, click Finished.


Configuring the non-BIG-IP ASM virtual server

The non-BIG-IP ASM virtual server must be configured to support the following functions:

  • Application Security must not be enabled.
  • The non-BIG-IP ASM virtual server requests are accepted directly from clients.
  • The non-BIG-IP ASM virtual server must use iRules to forward requests to the BIG-IP ASM virtual server.
  • The non-BIG-IP ASM virtual server receives responses that are forwarded from the BIG-IP ASM virtual server.
  • The non-BIG-IP ASM virtual server uses iRules to restore or modify the Server header to the response forwarded by the BIG-IP ASM virtual server.

To create the non-BIG-IP ASM virtual server, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the Virtual Server menu option.
  3. On the Virtual Server screen, click Create.
  4. In the Name field, type a name for the virtual server.

    For example:

    non-ASM-VS
  5. In the Address field, type an IP address for the virtual server.

    Note: Clients will connect to this address, so it must be a publicly routable address.
  6. In the Service Port field, type the port number to which clients will connect for this application.
  7. In the HTTP Profile field, select an HTTP profile.
  8. In the iRules dialog box, select the iRule from the Available list that you created in Step 4 of the Configuring the iRule for the non-BIG-IP ASM virtual server procedure.
  9. To move the iRule to the Enabled list, click the << button.
  10. In the HTTP Class Profiles dialog box, ensure that there are no HTTP classes in the Enabled list.

    The Default Pool value should be left at None.
  11. To save the virtual server, click Finished.


Configuring the BIG-IP ASM virtual server

The BIG-IP ASM virtual server must be configured to support the following functions:

  • The BIG-IP ASM virtual server must have Application Security configured and enabled in an HTTP class profile

    Note: Configure your HTTP class profile before configuring the virtual server.
  • The BIG-IP ASM virtual server accepts requests forwarded from the non-BIG-IP ASM virtual server.
  • The BIG-IP ASM virtual server receives responses from the origin server.
  • The BIG-IP ASM virtual server uses iRules to save the Server header from the origin server's response, so it can be restored by iRules on the non-BIG-IP ASM virtual server.

Note: The last bullet may not be necessary if you insert a custom Server header value independent of the original value.

To create the BIG-IP ASM virtual server, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the Virtual Server menu option.
  3. On the Virtual Server screen, click Create.
  4. In the Name field, type a name for the virtual server.

    For example:

    ASM-VS
  5. In the Address field, type the IP address to which clients will connect for this application.

    Note: Clients will not connect to this address; it can be a loopback or private address.
  6. In the Service Port field, type the port number on which this virtual server will accept connections.
  7. In the HTTP Profile field, select an HTTP profile.
  8. In the iRules dialog box, select the iRule from the Available list that you created in Step 4 of the Configuring the iRule for the BIG-IP ASM virtual server procedure.
  9. To move the iRule to the Enabled list, click the << button.
  10. In the HTTP Class dialog box, select your Application Security enabled HTTP class profile from the Available list.
  11. To move the profile to the Enabled list, click the << button.
  12. In the Default Pool box, select the appropriate server pool.
  13. To save the virtual server, click Finished.
