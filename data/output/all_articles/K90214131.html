Description

ASM and Advanced WAF policies can stop logging locally and remotely do to an issue with their child process.

  • This issue is usually isolated to a single ASM/Advanced WAF policy not logging or a couple ASM/Advanced WAF policies not logging
  • This solution will usually not apply when there is absolutely no logging for any ASM/Advanced WAF policies

Environment

  • ASM/Advanced WAF Local Logging Profiles
  • ASM/Advanced WAF Remote Logging Profiles 


Cause

This issue is commonly isolated to the child process asm_config_server. The asm_config_server process is responsible for all access and modifications to the policy configuration including the logging.

Recommended Actions

  1. Verify that the issue is isolated to individual policies and not to all policies. Again this solution will not usually apply when there is absolutely no logging happening for any policies. 
     
  2. Kill the asm_config_server daemon. This can be done with the following command: 

    #  pkill -f asm_config_server

    Please note that while the child services are down, no Configuration utility access to the policy configuration. Policy configuration also fails to update. That being said these child services should only be down for a few seconds. This action should not cause traffic impact but to be safe you can definitely run this in a maintenance window.
     
  3. After a few seconds, either wait for some traffic to be passed through the virtual server and check the event logs to confirm logging is now working again for the Security Policy. Please keep in mind that if you are only logging illegal requests then there will not be any requests logged unless the request was deemed illegal and was either alarmed or blocked.
