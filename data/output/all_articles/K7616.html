Note: For information about configuring the BIG-IP ASM version 10.0.1 and later to allow static web content requests to bypass the BIG-IP ASM, refer to  K10986: Configuring static web content to bypass BIG-IP ASM versions 10.0.1 and later.

You can configure the BIG-IP ASM to allow static web content requests, such as images, to bypass the BIG-IP ASM and the BIG-IP ASM security policy, and travel directly to the web server. To do so, perform the following three procedures:

  • Ensuring that the images Data Group contains the correct file types
  • Creating a static web content pool
  • Creating an iRule to cause static content to bypass the BIG-IP ASM

Ensuring that the images Data Group contains the correct file types

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Data Group List from the menu bar.
  5. Click the images Data Group.
  6. Verify that the file types listed represent the static image files on the web server.
  7. Click Update.


Creating a static web content pool

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click Create.
  5. Type a name for the pool.

    For example:

    static_content_pool

  6. Choose a monitor.
  7. Select a load balancing method from the Load Balancing Method drop-down menu.
  8. Add the pool members that serve static web content.
  9. Click Finished.

Creating an iRule to cause static content to bypass the BIG-IP ASM

Perform one of the following three procedures, depending on your version:

BIG-IP ASM versions 9.4.2 through 9.4.8

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. Enter the following iRule in the Definition box:

    Note: Replace STATIC_HOST_NAME with the name of the Host header you want to insert.

    when RULE_INIT {
set ::static_content_pool "SET_STATIC_POOL_NAME_HERE"
set ::static_host "SET_STATIC_HOST_NAME_HERE"
set ::max_uri_length "100"
}

when HTTP_CLASS_SELECTED {

PLUGIN::enable ASM
# Save a copy of the URI in lowercase for multiple tests
set test_uri [string tolower [HTTP::uri]]

if {[matchclass $test_uri ends_with $::images]}{

# Verify request is an HTTP GET, starts with a / and is of required length
if {([HTTP::method] eq "GET") and ([HTTP::uri] starts_with "/")and\
([string length [HTTP::uri]] < $::max_uri_length)}{

set test_uri2 [string range [HTTP::uri] 1 [expr [string last . [HTTP::uri]]-1]]

# verify request only contains allowable characters
if {[string is alnum\
[string map {%20 {} / {} $ {} _ {} - {}} $test_uri2 ] ]} {

# Remove all HTTP headers except Host and set static host
foreach header_name [HTTP::header names] {
                        while { [HTTP::header exists $header_name] } {
                                    HTTP::header remove $header_name
                        }
}
HTTP::header replace Host $::static_host

# Set the HTTP version
HTTP::version "1.0"
HTTP::header insert Connection close
PLUGIN::disable ASM
pool $::static_content_pool
}
}
}
}
  7. Click Finished.

You must now associate the iRule and Pool with the virtual server that manages traffic for the security policy.

BIG-IP ASM versions 9.4.0 through 9.4.1

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. Enter the following iRule in the Definition box:

    Note: Replace STATIC_HOST_NAME with the name of the Host header you want to insert.

    when RULE_INIT {
   set ::static_host "STATIC_HOST_NAME"
   set ::max_uri_length "100"
   }

  when HTTP_CLASS_SELECTED {
 # Ensure ASM is ebabled by default
 set asm_bypass 0
 # Save a copy of the URI in lowercase for multiple tests
 set test_uri [string tolower [HTTP::uri]]

  if {not ([matchclass $test_uri ends_with $::images])}{return}

  # verify request is using GET method, starts with a / and is of required length
 if {not (([HTTP::method] eq "GET") and ([HTTP::uri] starts_with "/")\
 and ([string length [HTTP::uri]] < $::max_uri_length))}{return}

  set test_uri2 [string range [HTTP::uri] 1 [expr [string last . [HTTP::uri]]-1]]
 # verify request only contains alphanumerics, periods, spaces,
 # forward slashes, dollar signs, underscores and dashes
 if {not ([string is alnum [string map {%20 {} / {} $ {} _ {} - {}} $test_uri2 ] ])} {return}

  # Remove all HTTP headers except Host and set static host
 foreach header_name [HTTP::header names] {
     while { [HTTP::header exists $header_name] } {
         HTTP::header remove $header_name
     }
 }
 HTTP::header replace Host $::static_host
 # Set the HTTP version
 HTTP::version "1.0"
 HTTP::header insert Connection close
 # Disable ASM for this request
 set asm_bypass 1
 }
  7. Click Finished.

You must now associate the iRule and Pool with the virtual server that manages traffic for the security policy.

BIG-IP ASM versions 9.2.0 through 9.3.0

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. Enter the following iRule in the Definition box:

    Note: Replace STATIC_POOL_NAME with the name of the static content pool you created.

    Note: Replace STATIC_HOST_NAME with the name of the Host header you want to insert.

    when RULE_INIT {
       set ::static_content_pool "STATIC_POOL_NAME"
       set ::static_host "STATIC_HOST_NAME"
       set ::max_uri_length "100"
       }

        when HTTP_REQUEST {
        # Ensure the HTTP classes will be evaluated by default
       event HTTP_CLASS_SELECTED enable
       # Save a copy of the URI in lowercase for multiple tests
       set test_uri [string tolower [HTTP::uri]]

        if {[matchclass $test_uri ends_with $::images]}{
        # Verify request is an HTTP GET, starts with a / and is of required length
       if {([HTTP::method] eq "GET") and ([HTTP::uri] starts_with "/")\
       and ([string length [HTTP::uri]] < $::max_uri_length)}{

        set test_uri2 [string range [HTTP::uri]\
       1 [expr [string last . [HTTP::uri]]-1]]

        # verify request only contains allowable characters
       if {[string is alnum\
       [string map {%20 \{\} / \{\} $ \{\} _ \{\} - \{\}} $test_uri2 ] ]} {

        # Remove all HTTP headers except Host and set static host
       foreach header_name [HTTP::header names] {
               while { [HTTP::header exists $header_name] } {
                   HTTP::header remove $header_name
               }
       }
       HTTP::header replace Host $::static_host

        # Set the HTTP version
       HTTP::version "1.0"

        # don't evaluate the HTTP class(es) if not going via ASM
       event HTTP_CLASS_SELECTED disable

        # specify the pool
       pool $::static_content_pool
       }
       }
       }
       }
  7. Click Finished.

You must now associate the iRule and Pool with the virtual server that manages traffic for the security policy.
