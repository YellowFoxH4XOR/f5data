Description

Virtual server is Enabled.
The virtual address is also Enabled.
Pool member has Available members.
However, the virtual server stopped working and resets all connections.

A packet capture shows reset cause of F5RST: VIP disabled (administrative).

Environment

  • v12.*-14.*
  • HA pair
  • Virtual server
  • Pool with Monitor

Cause

Bug ID 753805 and/or Bug ID 718790.

Important: This Bug will cause uneven load balancing. Some pool members do not receive any traffic due to this bug.

Recommended Actions

Check on GUI  Local Traffic  ››  Pools : Pool List  ››  <pool_name>  ››  Members  ››  <pool_member_name>  ›› Member Properties

This shows:

  • The pool member is Available
  • Health Monitors indicates Failure by red "♦"
Note: tmsh command does not tell this status, it only shows status up & monitor enabled. (further details please refer Additional Information)
 
There is two workaround (for fix, please upgrade to v15)
  1. On GUI, make this pool member Disabled then click Update. Then Enabled then click Update. 
     
  2. If standby does not show this situation, failover and then "Full" sync from Active unit to group.
    On CLI 
    Currently Active unit
    tmsh run sys failover standby 

    Then from newly promoted-to Active unit
    tmsh run cm config-sync force-full-load-push to-group <device_group_name>

This issue occurs only below specific situation.

  1. On Standby unit, a pool has pool member in monitor down state.
  2. On Active unit, the pool member is up
  3. On Active unit,  the pool config is changed.
  4. Incremental sync (auto or not)
  5. Active unit's pool member status (up) is also synced to Standby's.
