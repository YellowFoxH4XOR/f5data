Issue

Error Message

Configuration Utility

Unable to discover the device to be managed, reason(<reason>)

In this error message, note the following:

  • <reason> is the failure reason

For example:

Unable to discover the device to be managed, reason(Failed to get machine ID from 192.168.10.100: java.io.IOException: Connection reset by peer)

Log file

[<Level>][PID][Date][8100/shared/root-framework-upgrades/8b04dd48-c67b-4261-ac56-6501e019479e/worker RootAccessFrameworkUpgradeTaskWorker][handleFailure] com.jcraft.jsch.JSchException: java.net.ConnectException: Connection timed out

In this error message, note the following:

  • <Level> is the message logging level
  • <PID> is the numeric identifier for the process that generated the message
  • <Date> is the time the message was generated

For example:

[SEVERE][789][01 Jan 2015 12:00:00 UTC][8100/shared/root-framework-upgrades/8b04dd48-c67b-4261-ac56-6501e019479e/worker RootAccessFrameworkUpgradeTaskWorker][handleFailure] com.jcraft.jsch.JSchException: java.net.ConnectException: Connection timed out

Message Location

You may encounter this message in the following locations:

  • When you try to add a remote device using the Configuration utility.
  • You may view an accompanying error message in the /var/log/restjavad.0.log file.

Description

This message occurs when all of the following conditions are met:

  • You attempt to update the representational state transfer (REST) framework on a remote BIG-IP device.
  • Your BIG-IQ system has no route in place to reach the management port of the remote BIG-IP device.

Impact

The BIG-IQ system is unable to discover the remote BIG-IP system.

Recommended Actions

To work around this issue, you can either add the proper network routes to reach the remote BIG-IP system or perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IQ command line as the root user.
  2. To establish secure shell (SSH) trust between the BIG-IQ system and the managed BIG-IP device, use the following command syntax:

    Note: This step is optional. However, if you do not establish trust, you will be required to provide the BIG-IP system's root password multiple times.

    ssh-copy-id root@<BIG-IP Management IP Address>

    For example, to establish trust between the BIG-IQ system and a remote BIG-IP device with an IP address of 192.168.10.100, type the following command:

    ssh-copy-id root@192.168.10.100

  3. To navigate to the folder where the required files reside, type the following command:

    cd /usr/lib/dco/packages/upd-adc

  4. To run the installation script, use the following command syntax:

    ./update_bigip.sh –a admin –p <password> <BIG-IP Management IP Address>

    For example, to install the required files on the remote BIG-IP device using the examplepw admin password and an IP address of 192.168.10.100, type the following command:

    ./update_bigip.sh –a admin –p examplepw 192.168.10.100

  5. To revoke SSH trust between the BIG-IQ system and the remote BIG-IP device, use the following command syntax:

    Note: This step is not required if you did not establish trust in step 2.

    ssh-keygen –R <BIG-IP Management IP address>

    For example, to revoke SSH trust between the BIG-IP system and the remote BIG-IP device with an IP address of 192.168.10.100, type the following command:

    ssh-keygen –R 192.168.10.100
