Overview

This article describes how to configure remote role groups for administrative access on BIG-IP systems using LDAP authentication. Remote role groups allow you to assign specific roles and partition access to users based on their LDAP group membership.

Prerequisites

  • BIG-IP system with LDAP authentication already configured (see KB K11072: Configuring LDAP remote authentication for Active Directory).
  • LDAP server (such as Microsoft Active Directory) with user groups defined.
  • Administrative access to the BIG-IP GUI.

Important Notes

  • Only direct group membership is supported for administrative access. Nested groups are not supported. See KB K53524402: AD/LDAP Authentication does not support nested groups for remote authentication to BIG-IP.
  • The group name and value must match exactly what is returned in the memberOf attribute from your LDAP server.

Configuration Steps

  1. Navigate to Remote Role Groups
    • Log in to the BIG-IP Configuration utility.
    • Go to System > Users > Remote Role Groups.
  2. Create a New Remote Role Group
    • Click Create.
    • Enter the following details:
      • Group Name: The exact name of the LDAP group (e.g., AdminsGroup).
      • Attribute: For Active Directory, use memberOf.
      • Value: The full distinguished name (DN) of the group, e.g.,
        CN=NetworkAdmins,OU=Groups,DC=example,DC=com
      • Role: Select the desired administrative role (e.g., admin, auditor, etc.).
      • Partition Access: Choose the appropriate partition(s) for the group.
      • Console Access: Enable if you want users to have SSH access.
  3. Save the Configuration
    • Click Finished to save the remote role group.

Example

Suppose you have an AD group named AdminsGroup and want to grant admin access to its members:

  • Group Name: AdminsGroup
  • Attribute: memberOf
  • Value: CN=NetworkAdmins,OU=Groups,DC=example,DC=com
  • Role: admin
  • Partition Access: all-partitions
  • Console Access: enabled

Troubleshooting

  • Ensure the group DN matches exactly what is returned in the memberOf attribute for the user (use ldapsearch to verify).
  • If users cannot log in, confirm they are direct members of the specified group.
  • Nested group membership is not supported for administrative access (KB K53524402).
