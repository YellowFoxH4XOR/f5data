Description

Will BIG-IQ inform BIG-IP to send logs to another DCD when the current configured DCD is down

 

 

Environment

  • 1 CM
  • 2 DCD
  • 1 BIG-IP

 

  • CM - 10.1.1.7
  • DCD1 - 10.1.1.1
  • DCD2 - 10.1.1.2
  • when one of the DCD is unavailable

 

Cause

None

 

Recommended Actions

None.

 

By design CM will automatically appoint the next available DCD to serve the managed BIG-IP with its DCD is unavailable

 

analytics settings in BIG-IP before DCD1 is down

 

analytics global-settings {

  avrd-interval 30

  ecm-port 443

  enable-bigiq-configuration enabled

  offbox-protocol https

  offbox-tcp-addresses { 10.1.1.1 10.1.1.2 }

  offbox-tcp-port 443

  source-id e7d157c3-xxxx-xxxx-xxxx-4de2c7128528_10.1.1.7

  use-offbox enabled

}

CM will then update the analytics global settings of the managed BIG-IP and remove the DCD1 IP (10.1.1.1)

 

analytics settings in BIG-IP after CM update that DCD1 is unavailable

 

analytics global-settings {

  avrd-interval 30

  ecm-port 443

  enable-bigiq-configuration enabled

  offbox-protocol https

  offbox-tcp-addresses { 10.1.1.2 }

  offbox-tcp-port 443

  source-id e7d157c3-xxxx-xxxx-xxxx-4de2c7128528_10.1.1.7

  use-offbox enabled

}

 

After a few minutes, in the GUI, CM will update and you can see the appointed DCD is now DCD2

CM will then update the analytics global settings of the managed BIG-IP and add the DCD1 IP (10.1.1.1)

 

 

analytics global-settings {

  avrd-interval 30

  ecm-port 443

  enable-bigiq-configuration enabled

  offbox-protocol https

  offbox-tcp-addresses { 10.1.1.1 10.1.1.2 }

  offbox-tcp-port 443

  source-id e7d157c3-xxxx-xxxx-xxxx-4de2c7128528_10.1.1.7

  use-offbox enabled

}

 

 

CM will once again appoint DCD1 as the Data collection device for BIG-IP1
