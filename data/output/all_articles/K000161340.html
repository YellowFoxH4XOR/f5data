K000161340: BIG-IQ Fails to Discover BIG-IP Devices Configured with ssl-verify-client require — SSL Exception Error

Description

When attempting to add or re-discover BIG-IP devices from BIG-IQ Centralized Management, the following error is displayed in the BIG-IQ GUI:

"SSL exception on the connection to IP address <x.x.x.x>. Please see the logs for more information."

This error occurs when the target BIG-IP device has its httpd configuration set to ssl-verify-client require. Because BIG-IQ does not present a client certificate during the TLS handshake, the BIG-IP rejects the connection, preventing discovery and management.

This also applies to any remote API call system that is unable to present a trusted client certificate back to the BIG-IP with httpd ssl-verify-client set to “require”.

Environment

  • BIG-IQ Centralized Management: Version 8.4.0 / 8.4.1 (Virtual Edition)
  • BIG-IP: Any version with the following sys httpd configuration:
    • ssl-verify-client require
    • ssl-ocsp-enable on
    • Third-party or CA-signed certificates in use on the BIG-IP httpd
  • Authentication on BIG-IP: Remote – Client Certificate (e.g., CAC/PIV/Smartcard)
  • Discovery method: Management IP address
  • BIG-IQ SSL Certificate Verification: "Verify Hosts" is enabled K12743130 (not a factor in this issue)
  • Compliance context: STIG (Security Technical Implementation Guide) requirements mandating ssl-verify-client require

Cause

BIG-IQ does not have the capability to present a client certificate during the TLS handshake when communicating with managed BIG-IP devices. When a BIG-IP is configured with ssl-verify-client require, it demands a client certificate from any connecting system — including BIG-IQ. Since BIG-IQ cannot supply this certificate, the SSL handshake fails and the device cannot be discovered or managed.

This is a current product limitation, not a defect. A Request for Feature Enhancement (RFE) has been submitted to F5 Product Engineering.

RFE ID: 2337877
RFE ID: 1087749 

Answer/Recommended Actions

Step 1: Remove the "Managed by BIG-IQ" Status from BIG-IP (if applicable)

If a BIG-IP still shows "Managed by BIG-IQ" after a BIG-IQ rebuild or crash, run the following commands on the BIG-IP to reset its REST framework:

# rm -rf /var/config/rest/iapps/*
# rm -rf /var/config/rest/storage/*
# bigstart restart restjavad

Alternatively, use the supported command on the BIG-IP (not the BIG-IQ):

# clear-rest-storage

To verify the BIG-IP is no longer managed by any BIG-IQ:

# restcurl -u <username>:<password> /mgmt/shared/resolver/device-groups/cm-bigip-allDevices/devices

A 404 response confirms the device is not currently managed by BIG-IQ.

Step 2: Allow BIG-IQ to Bypass Client Certificate Requirement (Workaround)

To allow BIG-IQ to discover and manage a BIG-IP while keeping ssl-verify-client require for all other clients, add an ssl-include exception for the BIG-IQ CM IP address using tmsh edit:

On the BIG-IP, run:

1.     Edit sys httpd

# tmsh
# edit sys httpd

Add the following ssl-include line above the ssl-verify-client require line, replacing <BIG-IQ-CM-IP> with the actual BIG-IQ management IP:

ssl-include "<If \"%{REMOTE_ADDR} == '<BIG-IQ-CM-IP>'\"> SSLVerifyClient optional </If>"

The resulting sys httpd stanza should resemble:

sys httpd {
 auth-pam-dashboard-timeout on
 auth-pam-idle-timeout 600
 ssl-ca-cert-file /Common/new_admin_ca_bundle
 ssl-ocsp-enable on
 ssl-protocol "all -SSLv3 -TLSv1 -TLSv1.1"
 ssl-include "<If \"%{REMOTE_ADDR} == '<BIG-IQ-CM-IP>\">
 SSLVerifyClient optional
</If>"
 ssl-verify-client require
}

Save the configuration:

# tmsh save sys config

Note: This change does not require an httpd restart and takes effect immediately. All other clients (non-BIG-IQ) will continue to require a client certificate.

For multiple BIG-IQ IP addresses, use the || operator:

ssl-include "<If \"%{REMOTE_ADDR} == '<IP1>' || %{REMOTE_ADDR} == '<IP2>'\"> SSLVerifyClient optional </If>"

Or use CIDR notation:

ssl-include "<If \"%{REMOTE_ADDR} -ipmatch '<BIG-IQ-IP>/30'\"> SSLVerifyClient optional </If>"

Additional Information

  • The ssl-include configuration change survives upgrades when saved to the running configuration.
