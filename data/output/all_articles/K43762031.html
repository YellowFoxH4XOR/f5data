Known Issue

The BIG-IP system may remove Bidirectional Forwarding Detection (BFD) session statements from the ZebOS running configuration following a state transition.

This issue occurs when the following condition is met:

  • Your BIG-IP system is configured for dynamic routing.
  • Your BIG-IP system is configured to establish a BFD session with a peer device.
  • Your BIG-IP system is forced offline.
  • Your BIG-IP system is then brought back online.

A rare race condition may occur during the state transmission that causes the BIG-IP system to remove BFD session statements from the running configuration when the BIG-IP system transitions from offline to online.

Impact

The BIG-IP system removes BFD session commands from the ZebOS running configuration and will not establish the BFD session with the peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BFD sessions do not establish with the peer device
  • The ZebOS running configuration no longer matches the ZebOS.conf file.

    For example, the interface section of the running configuration may appear similar to the following example:

    !
    interface internal
    bfd interval 500 minrx 500 multiplier 3
    !

    However, the interface section of the /config/zebos/rd0/ZebOS.conf file appears similar to the following example:

    !
     interface internal
     bfd interval 500 minrx 500 multiplier 3
     bfd session  10.10.10.11  10.10.10.5
     bfd session  10.10.10.12  10.10.10.5
    !

Workaround

To work around this issue, you can disable and enable the BFD dynamic routing protocol using the Configuration utility. Alternatively, you can re-enter the missing BFD session commands using the IMI Shell (imish). To do so, perform one the following procedures:

Disabling and enabling the BFD dynamic routing protocol using the Configuration utility

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Route Domains.
  3. Select the affected route domain.
  4. From Dynamic Routing Protocols, select BFD from the Enabled box and move it to the Available box using the >> button.
  5. Click Update.
  6. From Dynamic Routing Protocols, select BFD from the Available box and move to the Enabled box using the << button.
  7. Click Update.

Re-entering BFD session commands using the imish shell

Impact of workaround: The impact of the suggested workaround will depend on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Open the imish shell by typing the following command:

    imish

  2. To enter Enable mode, type the following command:

    enable

  3. To enter Configuration mode, type the following command:

    configure terminal

  4. Select the desired interface to configure using the following command syntax:

    interface <interface_name>

    For example, to select the internal interface, type the following command:

    interface internal

  5. Configure the affected BFD session statement using the following command syntax:

    bfd session  <source_IP> <destination_IP>

    For example,

    bfd session  10.10.10.11  10.10.10.5

  6. Save the configuration by typing the following command:

    write

  7. Exit the interface configuration mode by typing the following command:

    exit

  8. Exit the imish shell by typing the following command:

    quit
