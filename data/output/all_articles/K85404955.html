Description

When configuring the BIG-IP it will accept the use of an "_" (underscore) as hostname or as part of the FQDN.
However when accessing the BIG-IP version v12.1.3, v13.1.1 and  v14.0.* using the FQDN returns "400 Bad request", and an error message similar to the following is logged to /var/log/httpd/httpd_errors:

Oct  2 11:44:25 F5_PROD err httpd[1885]: [error] [client 10.3.1.5] client sent HTTP/1.1 request without hostname (see RFC2616 section 14.23): /
Oct  2 11:44:25 F5_PROD err httpd[1887]: [error] [client 10.3.1.5] client sent HTTP/1.1 request without hostname (see RFC2616 section 14.23): /favicon.ico, referer: https://f5_prod.f5.com/


When accessing a BIG-IP running versions prior to v12.1.3, V13.1.0 Point Release 3 and  v14.1.* and higher, the BIG-IP will accept requests with FQDNs containing an underscore  "_".
Important: Though use of the underscore functions in these releases do not use any characters but the ASCII letters 'a' through 'z' (in a case-insensitive manner), the digits '0' through '9', and the minus sign ('-').

Recommended Actions

If the BIG-IP hostname of FQDN is using the underscore character "_" change the character to use the dash "-" character.

Changing hostname using the Configuration Utility
Impact of workaround: Performing the following procedures should not have a negative impact on your system.
  1. Access to Configuration Utility with IP address of the BIGIP, and log in with administrative account.
  2. Navigate to System >> Platfrom, and change Host Name.
  3. Click Update.
Changing hostname using the tmsh utility 
  1. Log on to the BIG-IP command line.
  2. Access the tmsh utility:

    tmsh
     
  3. Run the following tmsh command to change the hostname:

    tmsh modify sys global-settings hostname <hostname without "_">
    Note: Change <hostname without "_"> to the new hostname of the BIG-IP.
     
  4. Save the hostname change:
    save sys config
