Topic

This article applies to BIG-IP ASM 10.x - 11.1.x. For information about other versions, refer to the following article:

  • K32356471: Updating a BIG-IP ASM security policy when your web application changes (13.x - 14.x)

When your company changes a website that is protected by a security policy, you may need to update the security policy. You can configure the BIG-IP ASM system to automatically update the policy, or you can manually update it.

Note: For more detailed information about security policies, refer to the Configuration Guide for BIG-IP Application Security Manager.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Automated Policy Building

As of BIG-IP ASM 10.2.0, you can configure the system to automatically adjust the security policy as a result of site changes. If you know about a planned website update in advance, you can check the policy to make sure the Policy Builder is running and set up to perform automatic security policy updates. This way the Policy Builder can detect the changes and adjust the policy as needed with little administrator intervention required.

Setting up automated policy building

  1. Log in to the Configuration utility.
  2. On the Main tab, expand Application Security.
  3. Choose Automatic Policy Building > Configuration.
  4. Ensure that the current edited policy is set to the security policy you want to update.
  5. Set Automatically Build Policy to Enabled.
  6. Next to Automatically Build Policy, select Advanced.
    Additional settings are displayed on the screen.
  7. In the Security Policy Elements section, make sure the settings reflect the type of policy you want the Policy Builder to create.
  8. In the Rules section, under Track Site Changes, select the Enable Track Site Changes check box.
  9. Click Save to keep the configuration changes.
  10. On the Main tab, click Policy.
  11. Ensure that Enforcement Mode is set to Blocking.

When the application web site changes:

  • The Policy Builder detects that users are being blocked due to the site update and immediately loosens the policy to maintain user access.
  • The Policy Builder makes the necessary adjustments to the security policy, and temporarily puts new elements in staging, or adds wildcards.
  • The security policy re-stabilizes after the system analyzes sufficient traffic, from different sessions, over a period of time. Policy elements are moved out of staging and enforced as they meet the rule thresholds for stabilization.
  • After the changes are incorporated into the policy, Policy Builder removes any wildcards it added, takes elements out of staging, and enforces the new policy elements.

Reviewing automatic changes made to the security policy

In the Automatic Policy Building Log, you can review policy revisions to understand when and why the Policy Builder changed the security policy.

  1. Log in to the Configuration utility.
  2. On the Main tab, expand Application Security.
  3. Point to Automatic Policy Building.
  4. Click Log.
Manual Policy Building

You can manually adjust the security policy as a result of site changes by adding file types, URLs, and parameters. If you do not know all the changes that have been made, you can loosen the policy to learn what changed:

  1. Log in to the Configuration utility.
  2. Click Policy.
  3. Set the Enforcement Mode of the security policy to Transparent.
  4. Click Save.
  5. Ensure traffic is going to the application.
  6. Click Manual Policy Building > Traffic Learning and review the learning suggestions.
  7. Click Staging-Tightening Summary.
  8. Click the numbers in the Ready to Be Enforced column to see new entities, and enforce if appropriate.
  9. When you have added the new entities, click Policy and set the Enforcement Mode to Blocking.

Adding file types

For security policies that use file type entities to prevent the system from blocking users if the site update includes new file types, you can manually add specific file types, or add wildcards and let the system learn file types.

To add a wildcard for file types to prevent blocking if new file types were added as a result of the site update:

  1. Log in to the Configuration utility.
  2. On the Main tab, click File Types.
  3. Click Create.
  4. On the Add Allowed File Type screen, for File Type, select Wildcard.
  5. Type the wildcard.
    For example:

    *.gif

  6. Clear the Perform Staging check box.
  7. Select the Perform Tightening check box.
    This causes the system to include any new file types added as a result of the site update to be listed in the Manual Policy Building > Staging–Tightening Summary.
  8. Click Create.

To add specific file types:

  1. On the Main tab, click File Types.
  2. Click Create.
  3. On the Add Allowed File Type screen, type the file type and click Create.
  4. To update specific file type attributes (URL length, Request length, Query String length, or POST data length), in the File Types list, click the specific file type.
  5. Select the Perform Staging check box, and click Update.
  6. Make sure traffic is going to the application.
  7. Click Manual Policy Building > Traffic Learning and review the learning suggestions and add suggested file types, eliminating any false positives.
  8. Click Staging-Tightening Summary.
  9. Click the numbers in the Ready to Be Enforced column to see new file types, and enforce if appropriate.
    Depending on the traffic, it may take a couple of days for application users to try all of the new file types and attributes, and have them appear on the learning screens.
  10. When you finish the learning process, click the specific file types that were added in the File Types list, and then clear the Perform Staging check box, and click Update.
  11. To remove the wildcard for the added file types, in the File Types list, select the check box for the wildcard, then click Delete.

Adding URLs

For security policies that use URL entities to prevent the system from blocking users if the site update includes new URLs, you can add a wildcard so the system can learn the URLs, or you can add specific URLs, if you know them.

To add a wildcard for URLs (for example, *) to prevent blocking if new URLs were added as a result of the site update:

  1. Log in to the Configuration utility.
  2. On the Main tab, click URLs.
  3. Click Create.
  4. On the Create New Allowed URL screen, for URL, select Wildcard.
  5. Type the wildcard.
  6. Clear the Perform Staging check box.
  7. Select the Perform Tightening check box.
    This causes the system to include any new URLs added as a result of the site update to be listed in the Manual Policy Building > Staging–Tightening Summary.
  8. Click Create.

To add specific URLs:

  1. On the Main tab, click URLs.
  2. Click Create.
  3. On the Create New Allowed URL screen, type the URL and click Create.
  4. Make sure traffic is going to the application.
  5. Click Manual Policy Building > Traffic Learning and review the learning suggestions and add suggested URLs, eliminating any false positives.
  6. Click Staging-Tightening Summary.
  7. Click the numbers in the Ready to Be Enforced column to see new URLs, and enforce if appropriate.
    Depending on the traffic, it may take a couple of days for application users to try all new URLs and have them appear on the learning screen.
  8. After you finish the learning process, to remove the URL wildcard, in the URLs list, select the check box for the wildcard, then click Delete.

Adding parameters

For security policies that use parameter entities to prevent the system from blocking users if the site update includes new parameters, you can manually add specific parameters, or add wildcards and let the system learn parameters.

To add a wildcard for parameters (for example, *) to prevent blocking if new parameters were added as a result of the site update:

  1. Log in to the Configuration utility.
  2. On the Main tab, click Parameters.
  3. Click Create.
  4. On the Add Parameter screen, for parameter, select Wildcard.
  5. Type the wildcard.
  6. Clear the Perform Staging check box.
  7. Select the Perform Tightening check box.
    This causes the system to include any new parameters added as a result of the site update to be listed in the Manual Policy Building > Staging–Tightening Summary.
  8. Click Create.

To add specific parameters:

  1. On the Main tab, click Parameters.
  2. Click Create.
  3. On the Add Parameter screen, type the parameter and click Create.
  4. Make sure traffic is going to the application.
  5. Click Manual Policy Building > Traffic Learning and review the learning suggestions and add suggested parameters, eliminating any false positives.
  6. Click Staging-Tightening Summary.
  7. Click the numbers in the Ready to Be Enforced column to see new parameters, and enforce if appropriate.
    Depending on the traffic, it may take a couple of days for application users to encounter the new parameters, and have them appear on the learning screen.
  8. After you finish the learning process, click the specific parameter that was added in the parameters list, and then clear the Perform Staging check box.
  9. Click Update.
  10. To remove the wildcard for the added parameters, in the Parameters list, select the check box for the wildcard, then click Delete.

Modifying attack signatures

For parameter-based attack signatures, if staging is enabled on the added parameter, the Traffic Learning screen suggests attack signatures that you can enable.

Reviewing the policy log

To review all changes made to the security policy (including both manual and automatic changes), look at the policy log.

  1. Log in to the Configuration utility.
  2. On the Main tab, expand Application Security.
  3. Point to Policy.
  4. Click Log.
