Known Issue

This is the result of a known issue. Multiple and sequential enabled or disabled commands issued through an iRule where no server connection is attempted result in a 16 byte memory leak.

For example, an HTTP virtual server is configured with ServerSSL client enabled and the following iRule:

when HTTP_REQUEST {
  serverside { SSL::disable }
  serverside { SSL::disable }
  HTTP::redirect "http://www.example.com"
}

With this configuration, the client connection is automatically redirected by the iRule, but only after the iRule has issued two SSL disabled commands. Therefore, only the first command is acted upon and cleared from memory, which results in a 16 byte memory leak.

Each time the iRule is invoked by a client request, a 16 byte memory leak occurs.

F5 Product Development tracked this issue as CR95219 and it was fixed in BIG-IP LTM 9.4.5. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue has been fixed in Hotfix-BIG-IP-9.3.1-HF3 issued for BIG-IP 9.3.1, in Hotfix-BIG-IP-9.4.3-HF4 issued for BIG-IP 9.4.3, and in Hotfix-BIG-IP-9.4.4-HF1 issued for BIG-IP 9.4.4. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
