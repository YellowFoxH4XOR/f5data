Description

BIG-IP ASM/advanced WAF learning suggestions are not synchronized between peers. When a failover occurs within the device group, the newly active device does not have the learning suggestions from the previously active device. You would like to understand why this happens.

Environment

  • BIG-IP ASM/advanced WAF
  • Security Policy learning suggestions

Cause

This behavior is intentional and works as designed. Learning suggestions are generated based on the traffic observed by a specific device and are also influenced by platform characteristics. Because these suggestions are created solely from the traffic seen by a given unit, they are considered runtime/ephemeral data and are not synchronized across HA peers during failover or manual sync events.

However, when failover occurs, the new active device will generate its own learning suggestions. If these are similar to the previous ones, they will appear with a higher score. This is because the statistics of all learning suggestions are stored in a persistence file, which is synchronized between peers.

In other words, the new active device does not start learning from scratch but continues from where the previous active device left off. The only difference is that the exact list of suggestions from the previous device is not synced; instead, a new set of suggestions will appear, carrying higher scores based on the ongoing traffic.
