K15981044: In NGINX Controller error message under Instances > Overview ''Error Fetching Instances Request Failed with status code 502''

Applies to

  • NGINX Controller: 3.8.X, 3.8.0
Source
https://my.f5.com/manage/s/article/K15981044

Description

  • Unable to view the NGINX Instances under the Overview Tab in NGINX Controller
  • Message: "Error Fetching Instances Request Failed with status code 502"

Environment

  • Nginx Controller version 3.8 
  • After restarting of services

Cause

Corrupted data store: "/nats-datastore/clients.dat"

Recommended Actions

  1. Check if there are any pods that has CrashLoopBackOff status by executing the below command: 
    # kubectl -n nginx-controller get pods
     
  2. For example, the below pods have experienced CrashLoopBackOff:
    pod/cloud-mgr-78dbffb98b-w8brm
    pod/nats-streaming-556bddb5df-nnxtr
    pod/nats-streaming-worker-745795bc5d-qqbb6
    pod/stan-proxy-8cffd79c6-nccrg
     
  3. Fetch the details on those individual pods that has CrashLoopBackOff by executing the following pods: 
    # kubectl -n nginx-controller describe pod <pod name> 

    For example: 
    # kubectl describe pod nats-streaming-worker-745795bc5d-qqbb6
     
  4. Check the pod logs if the below error message was found, particularly in nats-streaming-worker-745795bc5d-qqbb6
    [1] 2020/11/20 01:33:39.427591 [FTL] STREAM: Failed to start: unable to recover client file "/nats-datastore/clients.dat": corrupted data, expected crc to be 0x453b6705, got 0x2d5a6f16
     
  5. Check the kubernetes persistent volume to which the file is located using the command below: 
    # kubectl -n nginx-controller get pv nats-streaming -o yaml | grep hostPath: -A2
    hostPath:
    path: /opt/nginx-controller/stan_data
    type: ""
     
  6. Move the file /opt/nginx-controller/stan_data/clients.dat out to a temporary folder.

  7. Check if the deployment brings it up.
