Known Issue

The Traffic Management Microkernel (TMM) may restart when a Transmission Control Protocol (TCP) Fast Retransmit follows a spurious retransmission timeout (RTO).

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server to process TCP traffic.
  • The virtual server has an associated TCP profile with the Early Retransmit option enabled; this option is disabled by default.
  • Due to significant packet reordering, the TCP profile triggers a Fast Retransmit following a spurious RTO.

Impact

TMM may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may fail to process traffic for a brief period.
  • The BIG-IP system may fail over to another host in the device group.
  • TMM generates a core file in /var/core directory.

Workaround

To work around this issue, you can disable the Early Retransmit option in the TCP profile.

Impact of workaround: There may be additional recovery time for connections that are receive-buffer or user-data limited.
