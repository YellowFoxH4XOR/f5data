Known Issue

This is the result of a known issue. When a BIG-IP system receives a response with an authorization argument from a Terminal Access Controller Access-Control System (TACACS)+ server and the argument consists of either an attribute-value pair that is not separated by an equal sign ( = ), or an attribute value only, with no equal sign, the authentication fails. When this event occurs, the BIG-IP system may write messages to the /var/log/secure file that appear similar to the following example:

sshd[2572]: fatal: PAM: authentication thread exited unexpectedly
httpd[581]: pam_tacplus: user not authenticated by TACACS+

According to the TACACS+ protocol, you can separate attribute-value pairs with either an equal sign or an asterisk ( * ). The ability to parse attribute-value pairs using the asterisk is supported in BIG-IP 11.2.0 and later. However, the BIG-IP configuration still requires the use of the equal sign when defining attribute-value pairs as part of the BIG-IP configuration.

Additionally, Cisco Secure ACS servers occasionally send responses with attributes that include neither an equal sign nor an asterisk. As mentioned, if the response does not contain an equal sign, authentication to the BIG-IP system fails.

Note: For more information about TACACS+ authorization arguments, refer to section 11.1 of The TACACS+ Protocol. This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

F5 Product Development is tracking this issue as ID 344706.

Workaround

You can work around this issue by configuring your TACACS+ server to send only attribute-value pairs separated by an equal sign. For more information about this procedure, refer to your TACACS+ server product documentation.
