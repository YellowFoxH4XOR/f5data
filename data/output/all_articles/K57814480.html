Known Issue

The BIG-IQ system may not discover devices running BIG-IP 13.1.0 or later.

This issue occurs when all of the following conditions are met:

  • The BIG-IQ system is running the versions listed in the Applies to (see versions) box, as well as BIG-IQ 5.4.0 HF1.
  • You have configured an external authentication provider on the BIG-IP device.
  • You have configured the BIG-IQ system to discover BIG-IP devices running 13.1.0 or later.

When you configure an external authentication provider to use a BIG-IP device running 13.1.0 or later, the BIG-IQ system representational state transfer (REST) request is forced to use the authentication provider that the BIG-IP device is configured to use, and the system does not fall back to local authentication.  As a result, the device discovery process cannot access the BIG-IP device.

The device discovery process for the BIG-IP device fails, and the BIG-IQ system cannot manage the BIG-IP device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IQ system cannot discover the BIG-IP devices running on the affected versions.
  • When the BIG-IP device discovery process fails, you may notice error messages logged to the BIG-IQ and the BIG-IP systems.
    • On the BIG-IQ system, you may observe an error message similar to the following example logged to the /var/log/restjavad.0.log file:

      [ERROR][27 Jun 2018 09:38:27 UTC][/cm/global/tasks/device-trust/e4340cg3-1265-8760-37h2-0g934sw562b9/worker BigIPTrustTaskWorker] Failed to post to group (my-bigipDevices) : java.lang.Exception: Authentication Failure to host 192.0.2.1. Please check the credentials provided.

    • On the BIG-IP device, you may observe an error message similar to the following example logged to the /var/log/restjavad.0.log file:

      [I][32][27 Jun 2018 09:38:27 UTC][8100/shared/authn/login AuthnWorker] User admin failed to login from 198.51.100.1 using the local authentication provider

Resolution

Status

F5 Product Development has assigned ID 703559 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can re-enable local authentication and have a valid user with Administrator credentials allow the device discovery process to complete and thereafter revert back to the external/remote authentication provider. To do so, perform the following procedure.

Note: For detailed steps on how to change the authentication provider for the BIG-IP system, refer to the BIG-IP Systems: User Account Administration manual.

For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Impact of workaround: The workaround is only a temporary fix. To permanently resolve the issue, F5 strongly encourages you to upgrade your BIG-IQ system to a fixed version or fixed hotfix.

  1. On the BIG-IP device, configure the authentication provider to local.
  2. On the BIG-IQ system, discover the device using the BIG-IP local admin user.
  3. After the BIG-IQ system discovers the device, on the BIG-IP device, configure the authentication provider back to the external/remote authentication provider you want.

    Important: With the valid authentication token, the communication between the BIG-IQ system and the BIG-IP device continues to work. The BIG-IQ system can rediscover the device, if required. However, if the BIG-IP device is removed from the BIG-IQ system, the new device discovery phase no longer works.
