K000148866: VIPRION with B4450 blades in HA are in Disconnected state after reboot

Type
Support Solution
Published
2024-12-05
Updated
2024-12-05
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.0, 15.1.9, 15.1.10, 16.1.4, 16.1.5, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000148866

Description

VIPRION with B4450 blades in HA are in Disconnected state, and /var/log/ltm continues to show messages like below.

err mcpd[<PID>]: 0107142f:3: Can't connect to CMI peer <ip_address>, TMM outbound listener not yet created

Environment

  • VIPRION with B4450 blades in HA
  • AFM module provisioned
  • Large AFM policy
  • DB variable provision.afm.extramb is set to large value like the max 40960

Cause

Due to an issue under investigation, TMM restarts early in boot up process. It in turn triggers a known issue ID 1014361.

Recommended Actions

Tune the value of provision.afm.extramb appropriately based on the current blob size and do not use the max.

  1. Find out the current blob size from /var/log/pccd.log

    BLOB Size: 2195634112 bytes, version 7      # <--- About 2GB

  2. Max blob size is calculated as follows. 

    max_blob_size = MIN(provision.memory.afm.host/4, pccd.maxblobsize) + (pccd.extramb/2)

    where

    provision.memory.afm.host = 4756 + provision.afm.extramb

    For example, having the DB variables configured as follows, blob size can increase up to about 6GB in size.
    • provision.afm.extramb = 20480
    • pccd.maxblobsize = 8192
    • pccd.extramb = 0

provision.memory.afm.host = 4756 + 20480 = 25236

max_blob_size = MIN(25236/4, 8192) + (0/2) = MIN(6309, 8192) = 6309
