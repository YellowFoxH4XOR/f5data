Known Issue

VIPRION B4450 blades may fail to process some connections due to a corrupt Layer 2 (L2) forwarding database (FDB) entry.

This issue occurs when all of the following conditions are met:

  • You have a VIPRION 4480 or 4800 chassis with one or more B4450 series blades installed.
  • The L2 FDB table learns and stores a new Media Access Control (MAC) address entry.
  • Multiple L2 FDB learning events occur for the same MAC address entry within a three-second period.

Impact

Traffic processing fails for connections associated with the corrupt L2 FDB entry.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for some connections.
  • The BIG-IP system fails to process some Address Resolution Protocol (ARP) replies.

Workaround

To work around this issue, you can delete the corrupt L2 FDB entry for the affected Virtual Local Area Network (VLAN). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Determine the affected VLAN. This is the ingress VLAN of the affected remote clients packets.
  3. To delete the corrupt L2 FDB entry, use the following command syntax:

    delete net fdb vlan <vlan_name>

    For example, to delete the corrupt L2 FDB entry on the VLAN named external, type the following command:

    delete net fdb vlan external

In addition, BIG-IP versions that contain the fix for this issue now include a new database variable, switchboard.l2.mitigation, that allows you configure the FDB behavior for corrupt entries. The switchboard.l2.mitigation database key can be configured using the following values:

  • enable allows packets to be forwarded in the case of corrupted L2 FDB entries. Packets are hashed on source and destination addresses. Enabling forwarding this way is only a temporary measure.
  • monitor does not forward packets but counts packets which are affected by corrupted L2 FDB entries. The stat table switch/l2_mitgation, updated every 11 seconds, reports packet counts. Differences in packet counts are logged to the /var/log/ltm file.
  • disable disables both forwarding and packet counting. Packet counts are reset.

To configure the switchboard.l2.mitigation database key, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Modify the switchboard.l2.mitigation database key using the following command syntax:

    modify /sys db switchboard.l2.mitigation value <enable | monitor | disable>

    For example, to set the switchboard.l2.mitigation database key to enable, type the following command:

    modify /sys db switchboard.l2.mitigation value enable
