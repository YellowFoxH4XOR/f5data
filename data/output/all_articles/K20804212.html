Description

After a major version upgrade of the BIG-IP, some or all IPsec tunnels will not start. These tunnels were working before the upgrade.

Log messages similar to the following may be seen in the /var/log/racoon file (IKEv1 example):

2020-08-27 14:22:00: ERROR: no suitable proposal found.
2020-08-27 14:22:00: ERROR: failed to get valid proposal.
2020-08-27 14:22:00: ERROR: failed to pre-process packet.
2020-08-27 14:22:00: ERROR: phase1 negotiation failed.


IKEv2 negotiation is logged in ipsec.log and may look similar to the following:

Sep 27 12:47:14 hostname info tmm[15228]: 017c0000 "name","192.0.2.1","0","09-27-2020 12:47:14","127.0.0.1","500","192.0.2.1","500","Peer terminated security association","Error"
Sep 27 12:47:14 hostname info tmm[15228]: 017c0000 "name","192.0.2.1","0","09-27-2020 12:47:14","127.0.0.1","500","192.0.2.1","500","Peer failed phase 1 initiation (proposal problem?)","Error"

Environment

The following conditions apply:

  • Upgrading a major software version, for example from v12.x to v14.x.
  • IPsec tunnels are configured and terminated on the BIG-IP.
 

Cause

There are some common causes.

One common cause is that some version upgrades change the default algorithms. For example, ff the tunnel previously used a sha1 algorithm, which is the default on v12.x software, then when upgrading to v14.x software the default algorithm will be changed to sha256. This problem will not affect upgrades from version 14.0.0 to a later version due to Bug ID673811 being fixed in v14.0.0.

Another common cause is a misconfiguration in the IPsec configuration. Sometimes a misconfigured can initially work, but when the config is re-read, such as after an upgrade, tunnels will not start. An example of this is ID 675772 where reusing the IPsec policy for traffic-selectors in IPsec interface mode is not a valid config.

The majority of IPsec tunnel problems after an upgrade are related to invalid config.

Recommended Actions

A careful check of the IPsec configuration should first be performed before contacting customer support. This includes checking that the algorithms configured on each tunnel are the same as that configured on the remote IPsec peers.The racoon (IKEv1) and ipsec.log (IKEv2) log files will guide you in finding where a tunnel is failing.

Enabling debug2 mode to get verbose detail on the tunnel negotiation will also help isolate problems.

# tmsh modify net ipsec ike-daemon ikedaemon log-level debug2

To revert logging to the default level:

# tmsh modify net ipsec ike-daemon ikedamon log-level notify
