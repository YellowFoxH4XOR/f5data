K000152670: Backend pool members respond to the active BIG-IP device for monitor traffic initiated by the standby BIG-IP device

Description

In a BIG-IP high availability (HA) pair, backend pool members may be seen responding to the MAC address of the active device’s floating self IP for traffic originating from the standby device’s local self IP. This behaviour causes health monitors or other connections initiated from the standby BIG-IP to fail, resulting in pool members being marked down on the standby unit. Packet captures reveal that SYN/ACK responses from pool members are sent to the MAC address of the floating (active) self IP rather than directly to the initiating standby device. The active BIG-IP may then respond with TCP RST packets because it did not initiate those connections.

Environment

  • BIG-IP Local Traffic Manager (LTM)
  • BIG-IP and pool members reside on the same broadcast domain
  • Pool member interfaces incorrectly configured with a longer subnet mask than configured on the BIG-IP devices
  • Pool member default gateway set to BIG-IP floating self IP

Cause

The issue arises due to a mismatch in subnet masks between the BIG-IP devices and backend pool members. Because of this mismatch, pool members do not recognise all BIG-IP self IPs as being within their local subnet and therefore do not perform ARP resolution for them. Instead, they send all return traffic, including SYN/ACKs, to their default gateway (the floating self IP), which always points to the currently active BIG-IP device. This results in asymmetric routing and connection failures for flows initiated by the standby device.

Recommended Actions

  • Configure all backend pool member interfaces connected to BIG-IP with the correct subnet mask, matching what is set on both local and floating self IPs of the BIG-IP devices.
  • After updating subnet masks, verify that ARP tables on each pool member contain entries for both floating and local self IP addresses of both HA units.
  • Confirm that health monitors and application traffic initiated from either active or standby BIG-IP units are correctly received and responded to by all pool members.
  • Ensure network documentation reflects consistent subnetting across all relevant devices.
