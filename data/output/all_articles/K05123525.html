Security Advisory Description

F5 BIG-IP and Enterprise Manager may expose sensitive information and allow the system configuration to be modified when using non-default ConfigSync settings. (CVE-2019-6649) 

Impact

The vulnerability is only present when the system is configured for high availability (HA) and either of the following settings are used:

  • ConfigSync is using a self IP with Port Lockdown configured as Allow All.

    Note: Port Lockdown defaults to Allow None.

  • ConfigSync is configured to use the management interface. The database variable configsync.allowmanagement must be set to enable to allow this configuration (default is disable). Check the configuration by typing the following command at the shell prompt:

    tmsh list /sys db configsync.allowmanagement

    Note: This is an uncommon configuration.

Systems that are not running with either configuration are not affected.

Note: BIG-IQ systems and iWorkflow systems are not affected.

In both of the previously described configurations, a malicious actor may be able to connect to the interface used for ConfigSync to extract and/or modify sensitive information on the system.

Additionally, when ConfigSync is configured to use the management interface, sensitive information may be transmitted unencrypted, risking information disclosure to and modification by anyone in the path of the traffic.

Security Advisory Recommended Actions

If you are running a version listed in the Versions known to be vulnerable column, you can eliminate this vulnerability by upgrading to a version listed in the Fixes introduced in column. If the table lists only an older version than what you are currently running, or does not list a non-vulnerable version, then no upgrade candidate currently exists.

Mitigation

F5 recommends upgrading to a fixed software version to fully mitigate this vulnerability. 

For customers leveraging public cloud marketplaces (AWS, Azure, GCP, and Alibaba) to deploy BIG-IP VE, F5 recommends upgrading to the latest releases of BIG-IP VE (12.1.5, 13.1.3, 14.0.1, 14.1.2, or 15.0.1) subject to their availability in those marketplaces.

Note: It is not possible to provide these fixes in an engineering hotfix for prior versions of software. A full upgrade to a fixed release version is required.

Note: ConfigSync is not compatible across versions with and without the fix, and all members of an HA pair or device cluster must be upgraded to provide continued functionality. For more information, refer to K13667: BIG-IP device group members must run the same software version.

If it is not possible to upgrade at this time the following may be used as an interim fix.

Self IP

Change port lockdown settings from Allow All to Allow None or Allow Default. If additional ports are required to be opened, use Allow Custom. F5 recommends avoiding the use of Allow All entirely.

Note: For more information, refer to K17333: Overview of port lockdown behavior.

Management interface

If the management interface is used for ConfigSync, F5 recommends changing the configuration to use the self IP instead, and setting the configsync.allowmanagement database variable to disable by typing the following command at the shell prompt:

tmsh modify /sys db configsync.allowmanagement value disable

If this is not possible and you must use the management interface for ConfigSync, there is no full mitigation available other than upgrading to a fixed software version. A partial mitigation is available from F5 Support, which can reduce the scope of the remote access exposure but does not eliminate it.

Note: There is no mitigation available for the data being transmitted unencrypted over the management interface other than upgrading to a fixed software version.

The scope of the exposure can also be reduced by limiting access to the network used for ConfigSync to only trusted users.
