Known Issue

The BIG-IP system incorrectly reports chassis error messages continuously to the /var/log/ltm log file. This issue occurs when all of the following conditions are met:

  • The affected BIG-IP system is running with Hotfix-BIGIP-10.2.2-852.0-HF1
  • The affected BIG-IP system is a VIPRION or BIG-IP appliance

    Note: This issue does not affect BIG-IP Virtual Edition.

This issue occurs because chassis debug level logging is incorrectly enabled in Hotfix-BIGIP-10.2.2-852.0-HF1.

Impact

The error messages are benign. However, the logging frequency increases the size of the /var/log/ltm file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The VIPRION system reports a log message that appear similar to the following example to the /var/log/ltm file:

    012a0005:5: ChassisAllSlotsReq - slots total: 4

  • All other BIG-IP platforms report log messages that appear similar to the following example to the /var/log/ltm file:

    012a0004:4: halGetChassisAllSlots: error 1
    00010038:3: Unknown HAL API error, returned (1) for request halGetChassisAllSlots

Workaround

To work around this issue, you can suppress these messages by configuring a custom syslog filter. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Configure the custom syslog filter by typing the following command:

    modify /sys syslog include "filter f_local0 { facility(local0) and not match(\"ChassisAllSlots\");};"

  3. Save the change by typing the following command:

    save sys config
