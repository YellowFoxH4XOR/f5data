K000135210: BIG-IP DNS is displaying BIG-IP LTM device virtual servers in the blue inactive state

Type
Support Solution
Published
2023-06-23

Applies to

Source
https://my.f5.com/manage/s/article/K000135210

Description

BIG-IP DNS is showing a BIG-IP LTM device virtual servers in the blue inactive state.
When running the command line utility iqdump for the configured sync group the following communication error is present:

SSL return code: SSL_ERROR_SYSCALL
 

Note: To check iQuery communication between GTM/DNS and other F5 devices, you can use the 'iqdump' command from the BIG-IP DNS command line.
iqdump -s <sync_group_name>  X.X.X.X

  • <sync_group_name> is the Group Name as defined in DNS > Settings > GSLB > General > Group Name

  • X.X.X.X is the self IP of the remote BIG-IP LTM system.



Environment

Relevant environmental factors specific to the topic
  • BIG-IP DNS
  • BIG-IP LTM
  • Virtual server(s)

Cause

The cause is a misconfiguration or connectivity issue between BIG-IP DNS and the BIG-IP LTM.
 

Recommended Actions

Very that the BIG-IP DNS device can route and access the self IP address(es) of the BIG-IP LTM.
Verify that the BIG-IP LTM port lockdown is configured to allow iQuery TCP and UDP on port 4353.
K17333: Overview of port lockdown behavior
Ensure that the SSL certificates required for communication with the BIG-IP LTM device have been pushed to the device (big3d_install and big3d_add).
K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities

In the event that the previous article to not resolve the issue refer to the following:
K13690: Troubleshooting BIG-IP DNS synchronization and iQuery connections
