Description

During troubleshooting, you may want to turn on debug logging for a specific SSL Orchestrator topology deployment. The system typically logs the debug logs in the /var/log/ltm and /var/log/apm files. To enable debug logging using the tmsh utility, perform the procedure described in the Recommended Actions section in this article.

Environment

  • SSL Orchestrator
  • Administrative access to the tmsh utility

Cause

None.

Recommended Actions

To enable debug logging for a specific SSL Orchestrator topology deployment, perform the following procedure:

Impact of procedure: Enabling debug logging consumes a huge amount of disk storage and must always be disabled once you no longer require it.

  1. Log in to the tmsh utility.
  2. For SSL Orchestrator prior to 16.1.x-9.x, you must disable strict updates for the specific topology deployment before enabling debug logging. To do so, enter the following command syntax:

    modify sys application service <topology deployment path/name> strict-updates disabled

    For example,

    modify sys application service sslo_example.app/sslo_example strict-updates disabled

  3. Enable debug logging for the access-per-request and ssl-orchestrator settings by entering the following command syntax:

    modify apm log-setting <topology deployment path/log-setting> access modify { general-log { log-level { access-per-request debug } } }
    modify apm log-setting <topology deployment path/log-setting> access modify { general-log { log-level { ssl-orchestrator debug } } }

    For example,

    modify apm log-setting sslo_example.app/sslo_example-log-setting access modify { general-log { log-level { access-per-request debug } } }
    modify apm log-setting sslo_example.app/sslo_example-log-setting access modify { general-log { log-level { ssl-orchestrator debug } } }

  4. For SSL Orchestrator prior to 16.1.x-9.x, you must re-enable strict updates after you have enabled debug logging. To do so, enter the following command syntax:

    modify sys application service <topology deployment path/name> strict-updates enabled

    For example,

    modify sys application service sslo_example.app/sslo_example strict-updates enabled

  5. When you no longer require debug logging for the specific topology, perform steps 2 through 4 as needed and replace debug with error for step 3 to turn off debug logging; for example,

    modify apm log-setting sslo_example.app/sslo_example-log-setting access modify { general-log { log-level { access-per-request err } } }
    modify apm log-setting sslo_example.app/sslo_example-log-setting access modify { general-log { log-level { ssl-orchestrator err } } }
