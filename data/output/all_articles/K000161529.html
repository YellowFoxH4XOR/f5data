K000161529: Kerberos Constrained Delegation does not work anymore

Type
Support Solution
Published
2026-08-18
Updated
2026-08-18
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161529

Description

BIG-IP APM Kerberos Constrained Delegation (KCD) can fail when Microsoft server updates prefer AES128/256 Kerberos encryption by default. In this condition, users may see authentication failures for portal access or BIG-IP LTM with BIG-IP APM applications, and APM logs may show messages such as:

Kerberos: can't decrypt S4U2Self ticket for user username@EXAMPLE.COM - Decrypt integrity check failed

Kerberos: Failed to get ticket for User: 'username@EXAMPLE.COM' accessing service: '''HTTP'/sso.example.com@EXAMPLE.COM'

Auth header null, Kerberos SSO failed

Environment

  • BIG-IP APM 17.5.1
  • Kerberos SSO profiles used for portal access and BIG-IP LTM with BIG-IP APM integration
  • Microsoft Active Directory delegation/service account configured for Kerberos Constrained Delegation
  • service account initially allowed both AES and RC4 encryption types
  • Microsoft server updates enforcing or preferring AES128/256 as default Kerberos encryption
  • Kerberos SSO profile account-name configured in HOST/hostname format and realm configured for the AD domain

Cause

Encryption type mismatch for the AD delegation/service account. After Microsoft updates caused AES to be used by default, leaving RC4 enabled on the service account caused BIG-IP APM to fail decrypting S4U2Self Kerberos tickets.

Answer/Recommended Actions

  1. On the Active Directory delegation/service account used by BIG-IP APM Kerberos SSO, disable RC4 encryption support.
  2. Ensure only AES128 and AES256 encryption types are enabled for that account.
  3. Reset the service account password after changing the allowed encryption types so the correct Kerberos keys are generated.
  4. Update the same password in the BIG-IP APM Kerberos SSO profile.
  5. Restart the BIG-IP websso service:
    bigstart restart websso
  6. Verify the Kerberos SSO profile configuration:
    • Confirm the account name matches the AD configuration exactly, including format and case.
    • Confirm the Kerberos realm is correct and consistently formatted.
  7. Retest Kerberos Constrained Delegation authentication.
