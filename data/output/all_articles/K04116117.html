Known Issue

Information is missing from power supply Bad status log messages.

This issue occurs when all of the following conditions are met:

  • You are running either BIG-IP 2000/4000/5000/7000/10000-series appliances or VIPRION B2100/B2200-series blades.
  • One or more installed power supplies triggers an internal hardware sensor alert indicating a Bad power supply status.

Impact

You are unable to diagnose the cause of the Bad power supply status at the default logging level to determine whether the probable cause is due to a power supply hardware fault or a possible external power source issue.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you receive an internal hardware sensor alert indicating a Bad power supply status, the alert includes no detail that indicates which characteristic of the power supply's state is resulting in a Bad overall status for the power supply.
  • In the /var/log/ltm file, you observe an error message with information similar to the following example:

    ... crit chmand[...]: 012a0013:2: Blade 0 hardware sensor critical alarm: Power Supply 2 GPIO status(SPAFFIV03G): Bad

Workaround

To work around this issue, you can change the log level to gather more information for further analysis. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. Set the libhal logging level to Debug by typing the following command:

    tmsh mod sys db log.libhal.level { value "Debug" }

  3. Let the system run in this configuration for at least a few minutes to collect a number of chmand error logs, such as the following:

    ... debug chmand[...]: 012a0007:7: Power Supply 1 alert objid:0x16f local:1 status:0x3 pin:0x2 action:0xd
    ... debug chmand[...]: 012a0007:7: Received Sensor Alert: sensor id 0x16f slot 0xff
    ... debug chmand[...]: 012a0007:7: Power Supply 1 alert objid:0x16f local:1 status:0x1 pin:0x2 action:0x3.

  4. Set the libhal logging level back to Notice by typing the following command:

    tmsh mod sys db log.libhal.level { value "Notice" }

  5. Take a qkview or an archive of /var/log/ltm, and contact F5 Technical Support for further analysis.
