K000163310: vCMP Guest and VIPRION bd.log Files Are Not Replicated Between Blades

Type
Support Solution
Published
2026-09-12
Updated
2026-09-12
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000163310

Description

On a multi-bladed vCMP guest, VELOS tenant, or VIPRION Adv WAF system, /var/log/ts/bd.log may contain different entries on each blade. This is expected behavior and does not indicate a synchronization problem.

The primary blade does not contain a complete copy of bd.log messages from all blades.

Environment

  • BIG-IP with Advanced WAF
  • Multi-bladed VIPRION or VELOS platform

Cause

bd.log is generated locally by the ASM bd process on each blade. The file is not replicated between blades through csyncd and log messages are not sent to each blade via syslog-ng. This is expected behavior.

Resolution

  1. Check /var/log/ts/bd.log on each relevant blade when troubleshooting
  2. Use clsh, when available, to search the log across blades
