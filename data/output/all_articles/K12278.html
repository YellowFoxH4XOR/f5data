Topic

You should consider using this procedure under the following condition:

  • You are unable to restore a user configuration set (UCS) archive due to insufficient free disk space.
  • You do not have any smaller UCS archives that you can restore.

Description

When you restore a UCS archive on the BIG-IP system, its contents are expanded and copied into their original directories. However, if the BIG-IP system does not have sufficient free disk space to store the expanded files, the operation will fail. When a UCS archive cannot be restored due to insufficient free disk space, the BIG-IP system returns error messages that appear similar to the following example:

# tmsh load sys ucs backup_one.ucs
Replace all configuration on the system? (y/n) y
Saving active configuration...
Current configuration backed up to /var/local/ucs/backup_one.ucs.
Product : BIG-IP
Platform: Z100
Version : 11.5.0
Edition : Final
Hostname: bigip1.f5.com
Installing --full-- configuration on host bigip1.f5.com
Installing configuration...
cp: writing `/root/bigfile': No space left on device
Fatal: executing: cp -frp /var/tmp/.install_ucs/root/bigfile /root/bigfile
Operation aborted.
/tmp/configsync.spec: Error installing package
Config install aborted.
Unexpected Error: UCS loading process failed.

Note: The BIG-IP system compresses UCS archives using gzip. A UCS archive increases in size after it is expanded.

This issue usually occurs when the UCS archive contains unnecessary large files and you may be able to reduce the size of the UCS archive in your possession by performing the following procedures.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have Advanced Shell (bash) access to the BIG-IP system.
  • You are proficient with basic Linux commands.

Procedures

Extracting the UCS archive to a temporary directory
Deleting all unnecessary large files from the UCS archive
Repacking the UCS archive
Installing the new UCS archive

Extracting the UCS archive to a temporary directory

  1. Log on to the BIG-IP system command line.
  2. Create a temporary directory by typing the following command:

    mkdir /shared/SOL12278

  3. Extract the UCS archive into the temporary directory by typing the following command:

    tar xzvf <full path to your UCS archive> -C /shared/SOL12278/

    For example:

    tar xzvf /shared/backup.ucs -C /shared/SOL12278/

Deleting all unnecessary large files from the UCS archive

  1. List the five largest files in the /shared/SOL12278/ directory by typing the following command:

    find /shared/SOL12278/ -xdev -type f | xargs du | sort -rn | head -5

  2. Investigate the output of the previous command for any unnecessary large files that might have been included in the UCS archive. For example, the following output indicates that the UCS archive includes an ISO image, a network capture and a qkview output file:

    150320  /shared/SOL12278/home/admin/Hotfix-BIGIP-10.2.0-1789.0-HF2.iso
    65924   /shared/SOL12278/home/admin/capture.pcap
    8892    /shared/SOL12278/home/admin/B1500.example.com.tgz
    660     /shared/SOL12278/config/ssl/ssl.crt/ca-bundle.crt
    84      /shared/SOL12278/config/BigDB.dat

    Respectively, these files occupy 150, 65, and 8 megabytes.

  3. Delete all the unnecessary large files that were included in the UCS archive. For example, you would type the following commands to delete the unnecessary large files discovered in the previous step:

    rm /shared/SOL12278/home/admin/Hotfix-BIGIP-10.2.0-1789.0-HF2.iso
    rm /shared/SOL12278/home/admin/capture.pcap
    rm /shared/SOL12278/home/admin/B1500.example.com.tgz

  4. Using a text editor, open the /shared/SOL12278/SPEC-Files file.
  5. This file lists the content that was included in the UCS archive. Locate the entries for the files that you deleted in Step 3 and delete these lines.

    For example:

    N /home/admin/capture.pcap  [series of strings omitted from this output]
    N /home/admin/Hotfix-BIGIP-10.2.0-1789.0-HF2.iso  [series of strings omitted from this output]
    N /home/admin/B1500.example.com.tgz  [series of strings omitted from this output]

  6. Save the file and exit the editor.
  7. Using a text editor, open the /shared/SOL12278/SPEC-Manifest file.
  8. This file also lists the content that was included in the UCS archive. Scroll down to the %files section, locate the entries for the files that you deleted in Step 3 and delete these lines.

    For example:

    /home/admin/capture.pcap
    /home/admin/Hotfix-BIGIP-10.2.0-1789.0-HF2.iso
    /home/admin/B1500.example.com.tgz

  9. Save the file and exit the editor.

Repacking the UCS archive

  1. Change directories to the /shared/SOL12278 directory by typing the following command:

    cd /shared/SOL12278

  2. Repack the UCS archive by typing the following command:

    tar czvf /shared/new_backup.ucs *

Installing the new UCS archive

Install the new UCS archive by running the following command:

tmsh load sys config ucs new_backup_ucs

Note: For more information on UCS archives, refer to K4423: Overview of UCS archives. If you no longer want to include the /home directory in your UCS archives, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive.

Note: Similarly to the content discussed in this Solution, a ConfigSync operation may also fail due to large files under the /home or /config directories. For more information, refer to K8522: The configsync process may fail due to large disk usage under the /home or /config directories.
