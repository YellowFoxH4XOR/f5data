Security Advisory Description

F5 has discovered a regression in BIG-IP 11.5.4 HF3, which has the potential to create a security exposure during the installation process. Operating with an abundance of caution, F5 has decided to remove 11.5.4 HF3 from the Downloads site. To correct the regression, F5 has released 11.5.4 HF4.

The potential security exposure involves the cipher suite configuration in the Secure Sockets Layer (SSL) profiles for virtual servers configured on the BIG-IP system. During the upgrade process, as the configuration is migrated to the new version, there is a script designed to validate the cipher configuration to ensure compatibility with the new software. In 11.5.4 HF3, we removed all DHE_DSS ciphers, and therefore the script should remove any ‘DHE_DSS’ keyword from cipher suite configurations as it is no longer valid. Unfortunately, a regression in this script removes valid cipher suite configuration keywords as well, altering the configuration and potentially reducing the configured level of security.

Any customer who has not customized their cipher suite configuration, and is therefore using the 'DEFAULT' configuration, is not affected. Customers who have customized their cipher suite configuration may be affected, depending on the configuration.

Cipher suites are configured using keywords such as AES, AES-GCM, !DES, -ADH, @STRENGTH, etc. The regression causes keywords beginning with at sign (@), plus sign (+), minus sign (-), and exclamation point (!) characters to be removed from the configuration.

A cipher suite configuration, before installing 11.5.4 HF3, may appear similar to the following example:

NATIVE:!SSLV2:!SSLV3:!MD5:!EXPORT:!LOW:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:AES-GCM+RSA:RSA+AES:RSA+3DES:!RC4:!ADH:!ECDHE_ECDSA:!ECDH_ECDSA:!ECDH_RSA:!DHE-RSA-DES-CBC3-SHA:!ECDHE-RSA-DES-CBC3-SHA:!DHE-RSA-AES128-SHA:+DES-CBC3-SHA

After installing 11.5.4 HF3, the example configuration appears similar to the following:

NATIVE:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:AES-GCM+RSA:RSA+AES:RSA+3DES

Note: Only the keywords beginning with special characters are removed, while the others are preserved.  

This results in a very different set of cipher suites being enabled for this SSL profile and an associated change in the level of security provided. As a simple example, the ‘DEFAULT:!TLSv1’ configuration uses the default cipher suite configuration, but disables any TLSv1.0 cipher suites. After an upgrade, this would become ‘DEFAULT,’ and TLSv1.0 would be enabled as it is present in DEFAULT on all supported versions.

Security Advisory Recommended Actions

This change happens silently during the upgrade process. If you have already installed 11.5.4 HF3, you can check if your cipher suite configuration is affected. To do so, perform either of the following actions:

  • Comparing your post-upgrade configuration to the pre-upgrade configuration
  • Checking the /var/log/liveinstall.log file

Comparing your post-upgrade configuration to the pre-upgrade configuration 

If the previous version is still installed, you can boot back into the previous version and check the configuration. Alternatively, you can compare your configuration against any previous backups or records that you have of the configuration before the upgrade. In any SSL profiles, locate the ‘ciphers’ configuration line.

Before an upgrade, the configuration may appear similar to the following example:

ltm profile client-ssl /Common/EXAMPLE_SSL_PROFILE {
    app-service none
    cert /Common/default.crt
    cert-key-chain {
        default {
            cert /Common/default.crt
            key /Common/default.key
        }
    }
    chain none
    ciphers NATIVE:!SSLV2:!SSLV3:!MD5:!EXPORT:!LOW:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:AES-GCM+RSA:RSA+AES:RSA+3DES:!RC4:!ADH:!ECDHE_ECDSA:!ECDH_ECDSA:!ECDH_RSA:!DHE-RSA-DES-CBC3-SHA:!ECDHE-RSA-DES-CBC3-SHA:!DHE-RSA-AES128-SHA:+DES-CBC3-SHA
    defaults-from /Common/clientssl
    inherit-certkeychain true
    key /Common/default.key
    passphrase none
}

After an upgrade, the previous configuration appears similar to the following example:

ltm profile client-ssl /Common/EXAMPLE_SSL_PROFILE {
    app-service none
    cert /Common/default.crt
    cert-key-chain {
        default {
            cert /Common/default.crt
            key /Common/default.key
        }
    }
    chain none
    ciphers NATIVE:ECDHE+AES-GCM:ECDHE+AES:DHE+AES-GCM:DHE+AES:AES-GCM+RSA:RSA+AES:RSA+3DES
    defaults-from /Common/clientssl
    inherit-certkeychain true
    key /Common/default.key
    passphrase none
}

Checking the /var/log/liveinstall.log file

The script that is altering the configuration writes entries into the /var/log/liveinstall.log file as it runs. Check the /var/log/liveinstall.log file for entries similar to the following examples:

info: WARNING:
info:     cipher !SSLV2 is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !SSLV3 is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !MD5 is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !EXPORT is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !LOW is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !RC4 is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !ADH is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !ECDHE_ECDSA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !ECDH_ECDSA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !ECDH_RSA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !DHE-RSA-DES-CBC3-SHA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !ECDHE-RSA-DES-CBC3-SHA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher !DHE-RSA-AES128-SHA is removed from profile /Common/EXAMPLE_SSL_PROFILE
info: WARNING:
info:     cipher +DES-CBC3-SHA is removed from profile /Common/EXAMPLE_SSL_PROFILE

These messages indicate which SSL profiles have been altered, as well as which keywords have been removed. For example purposes, this list is produced by the configuration example in the previous section.

If your SSL profiles are affected, you can recover by editing the profile configuration and restoring the proper cipher suite configuration string. As the regression issue exists only in the upgrade script, configuration changes made after upgrading to 11.5.4 HF3 are not altered. F5 does not recommend restoring a configuration backup taken from a previous TMOS version, as there may be other incompatibilities.

For questions related to 11.5.4 HF3, contact F5 Technical Support. F5 apologizes for any inconvenience or concern this may cause.
