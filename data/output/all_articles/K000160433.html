Description

The BIG-IP ASM module (v17.5.1) will fail to start if total_xml_memory is set too low. The ASM bd process enters a persistent restart loop, with the GUI displaying "ASM is not ready."

Logs showed repeated errors

BD_MISC|NOTICE|Mar 10 12:59:51.871|31701|temp_func.c:2064|max_raw_request_len = 5000 g_raw_request_umu_id = 7
 BD_XML|ERR  |Mar 10 12:59:51.881|31701|xml_validation.cpp:0133|Cannot allocate 221184 more bytes for XML parser. current memory size 106775 (in bytes)

F5xmlParserCreate: xml_parser_create() returned NULL

Environment

  • BIG-IP ASM module
  • ASM provisioned
  • ASM system variable total_xml_memory set to an extremely low value

 

Cause

If the total_xml_memory system variable for the ASM XML parser is set to an abnormally low value (under 8000000), the bd process cannot allocate sufficient XML processing memory, resulting in repeated restart loops and ASM module failure.

Note: values under the minimum value above (8000000) will generally result in an immediate ASM shutdown and restart. Low values of total_xml_memory above this value are unlikely to be sufficient for normal ASM operation. For the vast majority of customers, the default value (0) will allocate the appropriate amount of total_xml_memory for the platform. In some cases this may need to be increased due to inspecting large XML payloads. To determine the platform default value for total_xml_memory, set total_xml_memory to 0, restart ASM, and then run the following command at the BIG-IP bash prompt:

 # ps -ef | grep total_xml_memory
root     12750     1  0 15:46 ?        Sl     0:01 ./bd tmm_count 2 proc_cpuinfo_cpu_mhz 2445406 total_xml_memory 307200000 total_umu_max_size 952320

Answer/Recommended Actions

Reset the total_xml_memory parameter in the internal database to its default value (0, which allows ASM to use the platform default value)

# `mysql -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -D DCC -e "UPDATE INTERNAL_CONFIG_ITEMS SET current_value = 0 WHERE field_name = 'total_xml_memory';"`
# tmsh restart sys service asm

Then confirm ASM module starts successfully and monitor for further errors.
