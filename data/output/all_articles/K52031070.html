Issue

Old Behavior

In versions prior to BIG-IP 12.0.0, when using the HTTP::cookie insert iRules command within an HTTP_REQUEST event, the BIG-IP system inserts a new HTTP Cookie header in the request in addition to the existing Cookie header.

This behavior is by design; however, the resulting request does not conform to RFC 6265. Some web servers may not be able to parse the request or may attempt to link together the headers values, resulting in corruption.

For example, if the original request contains the header Cookie: name1=value1, an iRule similar to the following inserts another cookie:

when HTTP_REQUEST {
    HTTP::cookie insert name "Cookie" value "name2=value2"
}

The resulting request appears similar to the following example:

GET / HTTP/1.1
User-Agent: Mozilla/5.0
Host: example.host.com
Accept: */*
Cookie: name1=value1
Cookie: name2=value2

New Behavior

Beginning in BIG-IP 12.0.0, when using the HTTP::cookie insert iRules command within an HTTP_REQUEST event, the BIG-IP system appends the new cookie to the existing Cookie header. This results in a single HTTP Cookie header, which is in compliance with RFC 6265.

Using the previous example, the resulting request appears similar to the following example:

GET / HTTP/1.1
User-Agent: Mozilla/5.0
Host: example.host.com
Accept: */*
Cookie: name1=value1; name2=value2

Impact

Origin web servers may be unable to parse the request when using the HTTP::cookie insert command in versions prior to BIG-IP 12.0.0.

Recommended Actions

To insert cookies into a request in versions prior to BIG-IP 12.0.0, use the HTTP::header command to directly manipulate the HTTP Cookie header.

For example, the following iRule uses the HTTP:header replace command to replace the original Cookie header with one that contains the new cookie and logs the resulting value to the /var/log/ltm file:

when HTTP_REQUEST {
   set orig_cookie "[HTTP::header "Cookie"]"
   HTTP::header replace "Cookie" "$orig_cookie; name2=value2"
   log local0. "New cookie value: [HTTP::header "Cookie"]"
}
