Topic

You should consider using this procedure under the following conditions:

  • The network environment uses firewall network address translation (NAT) rules for resources that are configured with an internal, local, private network address but are accessed by a firewall NAT address.
  • The BIG-IP DNS system interfaces with BIG-IP systems that are configured with an internal, local, private network address but are accessed by a firewall NAT address.

Description

The BIG-IP DNS system uses iQuery to determine availability status and to gather load balancing metrics for objects, such as a virtual server on remote BIG-IP systems. iQuery communicates with the big3d process on remote BIG-IP systems over TCP port 4353. It is important to understand that iQuery communication, or probes, must follow the same network path as DNS clients to prevent BIG-IP DNS from providing incorrect DNS responses.

The BIG-IP DNS server object

When BIG-IP DNS and remote BIG-IP systems use public IP addresses, the BIG-IP DNS system requires only a single IP address for the server object's Address option. However, when BIG-IP DNS and remote BIG-IP systems reside behind a firewall and use private IP addresses, The BIG-IP DNS system requires two mapped IP addresses for the server object's Address (external/public address) and Translation (internal/private address) options. The following table describes the function of each IP address:

IP AddressDescription
AddressThis IP address represents the iQuery connection endpoint using TCP port 4353 and is the IP address configured on the firewall device. The BIG-IP DNS system connects through the firewall to the remote BIG-IP system using this IP address. This is also the IP address used by wide IP load balancing pools.
TranslationThis IP address represents configuration objects on the remote BIG-IP device, such as self IPs and virtual server IP addresses. The BIG-IP DNS system understands that the TCP connection is to the NAT firewall Address. It then translates the received iQuery information using the Translation IP addresses.

Establishing iQuery connectivity

After you add a BIG-IP device as a server in the BIG-IP DNS configuration, you must establish trust between the BIG-IP DNS system and the remote BIG-IP system using the bigip_add command line utility. After the two systems establish trust, the BIG-IP DNS system can probe the remote BIG-IP system using iQuery. For more information regarding the bigip_add command and the big3d process, see K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities (11.x - 13.x).

Important: The firewall NAT rule for the BIG-IP device must allow access from the BIG-IP DNS systems to the remote BIG-IP system on TCP port 4353.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP DNS and BIG-IP LTM Configuration utilities and command lines.
  • You have a general understanding of BIG-IP DNS and BIG-IP LTM configurations.
  • You have a comprehensive understanding of the network infrastructure and the deployment firewall NATs with respect to the BIG-IP GTM and BIG-IP LTM systems.

Procedures

  • Creating the BIG-IP server objects for BIG-IP devices that reside behind a firewall NAT
  • Establishing trust to allow iQuery probing between the BIG-IP DNS system and the BIG-IP device
  • Creating BIG-IP LTM virtual server objects for BIG-IP servers that reside behind a firewall NAT

Creating the BIG-IP server objects for BIG-IP devices that reside behind a firewall NAT

When you add a BIG-IP device as a server for the BIG-IP DNS configuration, the internet-facing address is defined as the server address, and the private network address (self IP address) is defined as the server's translation address.

For example, consider a case in which you have a BIG-IP LTM that you configured with a non-floating (self IP) private network address 10.0.0.100, and the firewall internet-facing NAT address is 65.61.115.222.

When you add the BIG-IP LTM as a server to the BIG-IP DNS system, you enter the IP addresses in the Address List of the server as follows:

Address: 65.61.115.222

Translation: 10.0.0.100

BIG-IP 13.x

For high availability (HA) BIG-IP LTM devices (servers), you repeat the process of adding devices by doing the following: 

  • For Address, you enter the non-floating (self IP) internet-facing firewall NAT address.
  • For Translation, you enter the private network address that is configured on the peer BIG-IP system..

To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.
  3. Click Create.
  4. In the Name box, type a unique name for the server object.
  5. In the Data Center list, select the data center that you created in the previous procedure.
  6. Under Devices, click Add.
  7. In the Device Name box, type a name of the BIG-IP LTM system.
  8. In the Address box, type the non-floating (self IP) internet-facing NAT address of the BIG-IP system.
  9. In the Translation box, type the non-floating (self IP) private network address of the BIG-IP system.
  10. In the Link list, click the appropriate ink. Click Auto-Select, if you are unsure.
  11. Click Add.
  12. Repeat steps 7 through 10 for each of the HA BIG-IP LTM systems.
  13. Click OK.
  14. Under Configuration, in the Health Monitors section, in the Available list, select the BIG-IP monitor that you want to assign to the server, and then click <<.
  15. Under Resources, in the Virtual Server Discovery list, click Disabled (see the Important note, following this procedure).
  16. In the Link Discovery list, click the appropriate value. Click Disabled, if you are unsure.
  17. Click Finished.

Important: The BIG-IP DNS system does not automatically discover virtual severs on the BIG-IP LTM devices that reside behind a firewall NAT. You must manually add the BIG-IP LTM virtual servers to the BIG-IP DNS configuration.

BIG-IP 11.x and 12.x

For a redundant pair of BIG-IP LTM devices, you repeat the concept for the Peer Address List section by doing the following:

  • For Address, you enter the non-floating (self IP) internet-facing firewall NAT address
  • For Translation, you enter the private network address that is configured on the peer BIG-IP LTM system.

To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers.

    Note: In BIG-IP 11.4.1 and earlier, navigate to Global Traffic > Servers.

  3. Click Create.
  4. In the Name box, type a name for the server.
  5. In the Product list, click the appropriate product type, either BIG-IP System (Single) or BIG-IP System (Redundant).
  6. In the Address List section, in the Address box, type the Internet-facing firewall NAT address of the BIG-IP LTM system.
  7. In the Translation box, type the private network IP address of the BIG-IP LTM system.
  8. Click Add.
  9. For redundant BIG-IP LTM systems, in the Peer Address List section, repeat steps 6 through 8.
  10. In the Link list, click Auto-Select (BIG-IP 12.0.0 and later).
  11. In the Data Center list, click the data center where the BIG-IP LTM devices reside.
  12. In the Prober Pool list, click Inherit from Data Center.
  13. In the Status list, click Enabled.
  14. Under Configuration, in the Health Monitors section, in the Available list, select bigip and then click <<.

    Note: Select the bigip health monitor for BIG-IP LTM and BIG-IP DNS server configurations.

  15. Under Resources, in the Virtual Server Discovery list, click Disabled (see the Important note, following this procedure).
  16. In the Link Discovery list, click Disabled, unless you specifically need this.
  17. Click Create.

    Important: The BIG-IP DNS system does not automatically discover virtual severs on the BIG-IP LTM devices that reside behind a firewall NAT. You must manually add the BIG-IP LTM virtual servers to the BIG-IP DNS configuration.

Establishing trust to allow iQuery probing between the BIG-IP DNS system and the BIG-IP device

You must configure a security trust on the destination BIG-IP LTM or BIG-IP DNS server to enable the BIG-IP DNS system to communicate with iQuery (big3d). You establish this trust by running the command line utility called bigip_add on the BIG-IP DNS system. For more information regarding the bigip_add command and the big3d process, refer to K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities (11.x - 13.x).

Important: You must run the bigip_add command for the BIG-IP DNS probes of BIG-IP LTM and BIG-IP DNS servers to function properly.

Creating BIG-IP LTM virtual server objects for BIG-IP servers that reside behind a firewall NAT

The IP address that you define as the virtual server address for a BIG-IP LTM virtual server is the internet-facing firewall NAT address that clients use to access the virtual server services. The translation address of a virtual server is the private network address defined as the virtual server on the BIG-IP LTM system.

For example, consider a case in which the BIG-IP LTM system's virtual server private network address is 10.0.0.111, and the firewall Internet-facing NAT address is 65.61.115.223.

When you add the BIG-IP LTM system's virtual server to the BIG-IP DNS system, you enter the IP addresses in the General Properties section, as follows:

Address 65.61.115.223

Translation 10.0.0.111

To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers > Server List.

    Note: In BIG-IP 11.4.1 and earlier, navigate to Global Traffic > Servers > Server List.

  3. Click the name of the BIG-IP LTM server that you created in the previous procedure.
  4. Click Virtual Servers.
  5. Click Create.
  6. In the Name box, type a name for the virtual server.
  7. Under Resources, in the Virtual Server List section, In the Address box, type the internet-facing firewall NAT address of the virtual server.
  8. In the Service Port box, type the appropriate, configured firewall port for the configured service of the virtual server.
  9. In the Translation box, enter the BIG-IP LTM-configured private address of the virtual server.
  10. In the Translation Port box, type the BIG-IP LTM-configured port of the virtual server.

    Note: You do not need to select a health monitor for the virtual server when you have defined the BIG-IP LTM as a BIG-IP DNS server object with an associated BIG-IP health monitor.

  11. Click Create or Finished.
