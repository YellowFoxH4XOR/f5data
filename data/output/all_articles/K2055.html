Topic

When a virtual server is configured with a OneConnect profile, the BIG-IP system is able to reuse open and idle server connections many times for many requests. When more open and idle server connections are available, the BIG-IP system creates fewer new connections. This may create the appearance that the BIG-IP system is not evenly distributing connections.

In addition, if OneConnect is in use and your network contains a mixture of slow and fast servers, the BIG-IP system may not load balance traffic evenly. OneConnect distributes connections on a per-request basis, enabling the BIG-IP system to reuse idle open server connections. When open and idle server connections are available, the BIG-IP system need not create new connections. Since fast servers complete requests more quickly, their connections quickly become idle and available for re-use. As a result, over time, the BIG-IP system opens fewer connections to the fast servers. Since slow servers take longer to complete requests, their connections are not as quickly idle and available for reuse. As a result, over time, the BIG-IP system may open more connections to slower servers.

When persistence is configured, the effect may be exaggerated; sessions persisted to a slow server may force the BIG-IP system to open new connections, if previously-used connections do not become idle quickly enough to reuse them in loading additional page elements or subsequent requests.

Note: For more information about the OneConnect profile, refer to K7208: Overview of the OneConnect profile.
