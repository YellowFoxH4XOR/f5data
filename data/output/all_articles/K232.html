Topic

Note: F5 recommends that you manage the 3-DNS Controller configuration through the Configuration utility. For specific instructions about how to define a host statement for the 3-DNS Controller through the Configuration utility, refer to the 3-DNS Controller Administrator Guide.

Host statements define essential information about each host that the 3-DNS Controller uses for load balancing. This information includes the IP address of the host, the protocol that the 3-DNS Controller should use to check the availability of the host, and the individual virtual servers that run on the host.

Host statement syntax

You can insert a host statement in a wideip.conf file anywhere between the globals statement and the first wideip statement. The syntax for a host statement is as follows:

Note: Each host statement can include multiple virtual servers, but must always include at least one virtual server.

host {
          address <host machine IP addr>
          probe_protocol <tcp | icmp>
          port <port>
          prober <IP addr of machine that pings the host>
          vs {
              address <IP addr>:<port>
              probe_protocol <tcp | icmp>
         }
         vs {
              address <IP addr>:<port>
              probe_protocol <tcp | icmp>
    }
}

Sample host statement

The following sample host statement defines a host that manages three virtual servers. Note that the statement defines IP addresses for both the host and the individual virtual servers, and also defines a probe protocol, which can be TCP or ICMP. The prober IP address points to either a BIG-IP or a 3-DNS Controller running the big3d utility, and probes the host and virtual servers to verify whether the host or a particular virtual server is currently available to accept connections.

host {
          address 10.0.0.1
          probe_protocol tcp
          port 80
          prober 192.168.1.1
          vs {
             address 10.0.0.5:80
             probe_protocol tcp
          }
          vs {
             address 192.168.100.200:23
             probe_protocol icmp
          }
          vs {
             address 10.0.0.4:80
             probe_protocol tcp >
     }
}

In the preceding example, the prober IP address is 192.168.1.1. The frequency at which the host is probed is defined by the global variable, timer_get_host_data. The host status, determined by the probe, is stored in the 3-DNS Controller cache for the period of time defined by the host_ttl global variable. Similarly, each virtual server is probed at the frequency defined by the timer_get_vs_data global variable, and its status is stored in the cache for the period of time defined by the vs_ttl global variable.
