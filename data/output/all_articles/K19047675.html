K19047675: Least connections (member) is not working, one member is taking more connections

Type
Support Solution
Published
2021-11-08
Updated
2025-04-02
Applies to
  • Virtual Editions
  • BIG-IP
  • BIG-IP LTM: 13.1.3
Source
https://my.f5.com/manage/s/article/K19047675

Description
Using least connections (member) as  load balancing method and one of the member is taking more connections than others.

Environment

  • Least connections (member)
  • Persistence profile in the Virtual Server with a high timeout

Cause
The persistence profile makes all the connections go to the same pool member, if timeout is high, for example 8 hours, and the same clients connects within 8 hours then the connection will go to the same pool member, no matter the load balancing method. Also timer will be renewed.

Recommended Actions

Use a lower persistence timeout. Default is 300 for most of them.
