Description

As described on K15062, you can associate multiple SSL certificate/key pairs of different algorithm types with a single SSL profile.
With multiple server certificates, user may want to have specific type of server certificate used more often. In other words, user may want to set higher preference to a specific type of certificate (i.e., user wants to get EC certificate more used than RSA certificate).

For example, 2 different types of certificate files are associated with single client-ssl profile as follows. Here, "web301ec.f5ss.local" is ECDSA (ECC) certificate and "web301rsa.f5ss.local" is RSA certificate. If administrators want to put higher priority to ECDSA certificate, how can they do that?

ltm profile client-ssl /Common/my_clientssl_profile {
    app-service none
    cert-key-chain {
        web301ec.f5ss_ecca1.f5ss_0 {
            cert /Common/web301ec.f5ss.local
            chain /Common/ecca1.f5ss.local
            key /Common/web301ec.f5ss.local
        }
        web301rsa.f5ss_rsaca1.f5ss_0 {
            cert /Common/web301rsa.f5ss.local
            chain /Common/rsaca1.f5ss.local
            key /Common/web301rsa.f5ss.local
        }
    }
    cipher-group /Common/my_cipher_group
    ciphers none
    defaults-from /Common/clientssl
    inherit-ca-certkeychain true
    inherit-certkeychain false
    options { dont-insert-empty-fragments no-dtlsv1.2 }
}
ltm cipher group /Common/my_cipher_group {
    allow {
        /Common/my_cipher_rule { }
    }
}
ltm cipher rule /Common/my_cipher_rule {
    cipher DEFAULT
}

Although server certificate selection actually depend on client's "signature_algorithms" extension inside client hello message as well, we can control certificate preference via cipher rule "Signature Algorithms" parameter, to some extent.

Environment

  • Different types of multiple certificates are used in single client-ssl profile.
  • Cipher group/rule in use.

 

Cause

None.

 

Recommended Actions

On cipher rule object, you can configure ordered "Signature Algorithms" parameter, so that ECDSA (ECC) certificate has higher precedence than RSA certificate.

First, to confirm currently configured "Signature Algorithms" value, you can use "tmsh show ltm cipher group [cipher-group-object]" command. On this specific example case, you can see "RSA-PSS-SHA256" located prior to "ECDSA-SHA384".

[root@bigip:Active:Standalone] config # tmsh show ltm cipher group my_cipher_group | grep 'Signature Algorithms'
Signature Algorithms Result  RSA-PKCS1-SHA256:RSA-PSS-SHA256:ECDSA-SHA256:RSA-PKCS1-SHA384:RSA-PSS-SHA384:ECDSA-SHA384:RSA-PKCS1-SHA512:RSA-PSS-SHA512:ECDSA-SHA512
[root@bigip:Active:Standalone] config #

 

On GUI, go to "Local Traffic" >> "Ciphers" >> [cipher-group-object], and you can see currently configured "Signature Algorithms" value.

Figure: cipher rule "Signature Algorithms" parameter

If you want to put higher preference on a certificate signed by "ecdsa-with-SHA384" algorithm, you can customize order of signature-algorithms parameter. On the following example, "ECDSA-SHA384" moved to the top of list.

[root@bigip:Active:Standalone] config # tmsh modify ltm cipher rule my_cipher_rule signature-algorithms "ECDSA-SHA384:RSA-PKCS1-SHA256:RSA-PSS-SHA256:ECDSA-SHA256:RSA-PKCS1-SHA384:RSA-PSS-SHA384:RSA-PKCS1-SHA512:RSA-PSS-SHA512:ECDSA-SHA512"
[root@bigip:Active:Standalone] config # tmsh show ltm cipher group my_cipher_group | grep Signature
Signature Algorithms Result  ECDSA-SHA384:RSA-PKCS1-SHA256:RSA-PSS-SHA256:ECDSA-SHA256:RSA-PKCS1-SHA384:RSA-PSS-SHA384:RSA-PKCS1-SHA512:RSA-PSS-SHA512:ECDSA-SHA512
[root@bigip:Active:Standalone] config #

Another example (this example is not practical use case. this example is just a PoC) . If you want to use RSA certificate only (despite the fact that 2 types of certificates are associated with client-ssl profile, though), you may put only one signature-algorithm as allowed signature-algorithm.

[root@bigip:Active:Standalone] config # tmsh modify ltm cipher rule my_cipher_rule signature-algorithms "RSA-PSS-SHA256"

 

With above configuration, If client comes in with ECDSA signature_algorithms which is not allowed by cipher rule, handshake will fail.

(TLSv1.3)

$ openssl s_client -connect 10.1.1.201:443 -tls1_3 -sigalgs "ECDSA+SHA384"

Feb 18 13:02:17 bigip.local warning tmm7[18950]: 01260009:4: 10.1.1.60:45702 -> 10.1.1.201:443: Connection error: ssl_basic_rx:1161: alert(80) input size error
