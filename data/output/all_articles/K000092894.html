Description

  • WebUI and SSH loading slowly.
  • After a restart, the WebUI/GUI and SSH are working properly but after several times the WebUI/GUI and SSH still loading slowly.
  • In the /var/log/tomcat/catalina.out log file, you may observe error messages similar to the follow example:
SEVERE: Caught exception (java.lang.OutOfMemoryError: Java heap space) executing           org.apache.jk.common.ChannelSocket$SocketAcceptor@f14c7c, terminating thread

Environment

  • BIG-IP VE
  • BIG-IP
  • GUI/WebUI

Cause

This issue has multiple causes including but not limited to:

  • Your BIG-IP system has a large number of virtual servers and pools configured (3000+).
  • If you notice the following messages in the var/log/tomcat/catalina.out file

# java.lang.OutOfMemoryError: Java heap space
# -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat"
# Executing /bin/sh -c "/usr/bin/restart_tomcat"

 Recommended Actions

Try the following steps in the order shown until its resolved:

1) Restart the following processes

  • httpd
  • restjavad
  • tomcat
  • restnoded

 To do so, perform the following procedure:
  bigstart restart tomcat httpd restjavad restnoded

2) Increase the amount of memory allocated to the tomcat process

If the tomcat process continues to encounter this issue and becomes unresponsive, you can increase the amount of memory allocated to the tomcat process.

To do so, perform the following procedure:

Impact of procedure: The following procedure requires that you restart the tomcat process. The Configuration utility will not be accessible while the tomcat process restarts.

  1. Log in to the tmsh utility by typing the following command:
    tmsh
  2. View the current value of the provision.tomcat.extramb database variable by typing the following command:
    list /sys db provision.tomcat.extramb
  3. The command output appears similar to the following example:
    sys db provision.tomcat.extramb {
         value "0"
    }
  4. A value of 0 (zero) indicates that no additional memory is currently allocated. This is the default value.
  5. Set the provision.tomcat.extramb database variable to the amount of additional memory that you want to allocate, using the following command syntax:
    modify /sys db provision.tomcat.extramb value <MB>
  6. In this command, note the following:
    • <MB> is the number of megabytes of additional memory you want to add to the default provisioned amount.
  7. For example, to allocate an additional 50 MB of additional memory, type the following command:
  8. modify /sys db provision.tomcat.extramb value 50
    Note: F5 recommends that you initially increase the amount of memory to 50 MB, but doing so may not resolve all instances of the error message. If the java.lang.OutOfMemoryError errors continue, repeat this procedure, gradually increasing the value of <MB> until you no longer view the error message.
  9. Restart the tomcat process by typing the following command:  restart /sys service tomcat

    Note: the provision.tomcat.extramb database variable is not synced to peer HA devices. The steps need to be performed on each HA devices.

3) Giving restjavad extra memory. This is a two-step process.

Impact of procedure: Service on a BIG-IP system is briefly interrupted the value of provision.extramb changes. F5 recommends performing this procedure during a maintenance window. provision.extramb must be set on each peer of a cluster as the value puposefully doesn't sync between peers. Change only one at a time.

Note: Restjavad may need increased memory also because some elements of the GUI use the REST API. Rule out ID 1826505 before increasing restjavad memory.
Use the  'Increase restjavad memory'  from K000133258 
Remember to check ltm log after restarting restjavad, as it will state what memory it will use.
