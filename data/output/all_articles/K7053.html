This Solution describes vulnerability issues reported in BIND where a remote user can cause denial of service conditions by sending specifically crafted packets to the BIND server. The dereferencing freed fetch context issue results from an issue where the named daemon dereferences a freed fetch context, which could be exploited and cause BIND to crash. The DNSSEC Validation issue results from an error when validating responses to type (*) (ANY) DNS queries that return multiple RRsets in the answer. These responses can be exploited by attackers to cause a denial of service.

F5 Product Development tracked this issue as CR73531 and it was fixed in BIG-IP versions 9.1.3, 9.3.0, and 9.4.1. For information about upgrading, refer to the LTM, GTM, ASM, Link Controller, or WebAccelerator Release Notes.

F5 Product Development tracked this issue as CR73531 and it was fixed in Enterprise Manager version 1.2.0. For information about upgrading, refer to the Enterprise Manager Release Notes.

Hotfix Download

You can download the BIND-9.3.4-Hotfix patch from the F5 Downloads site.

Note: The BIND-9.3.4-Hotfix patch will upgrade BIND to version 9.3.4. F5 is providing a standalone update to BIND version 9.3.4 as a precaution in this IM package, as these vulnerabilities are difficult to exploit without recursion enabled. MSM and some BIG-IP GTM and 3-DNS configurations require recursion.

Note: For more information about installing the hotfixes listed above, refer to the README file on the F5 Downloads site for your version-specific hotfix.

For information about how to download software, refer to K167: Downloading software from F5 Networks.

Workaround

It is possible to mitigate both issues by disabling recursion on the F5 device. For the DNSSEC Validation issue, you must also disable DNSSEC validation by removing trusted-keys from the named.conf file.

To disable DNS recursion for BIG-IP LTM versions 9.0 through 9.4, BIG-IP GTM and BIG-IP Link Controller versions 9.2.2 through 9.4, perform the following procedure:

If you are disabling recursion on a BIG-IP GTM system, refer to the procedure for manually editing the BIG-IP GTM BIND configuration file in K6963: Managing the BIG-IP GTM BIND configuration file.

  1. Log in to the command line.
  2. Using a text editor, edit the /var/named/config/named.conf file.
  3. Locate the options section of the file and change recursion to no.

    For example:

    recursion no;
  4. Save the file.
  5. Restart the named service by typing the following command:

    bigstart restart named
