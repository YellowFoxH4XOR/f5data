K73216787: SSLO does not translate scheme portion from https to http

Type
Support Solution
Published
2020-10-06
Updated
2023-02-21
Applies to
  • F5 App Protect
  • F5 SSL Orchestrator: 14.1.0
Source
https://my.f5.com/manage/s/article/K73216787

Description

When SSLO receives CONNECT HTTP request (eg: CONNECT www.f5.com:443 HTTP/1.1), SSLO is sending the request to security chain with absolute URI (eg: GET https://www.f5.com/) instead of the normal relative URI (GET /) and this request when send to security service chain, it refused with "HTTP/1.1 502 Connection refused" as it expects 'http://' instead of 'https://' in URI scheme in the decrypted traffic.

Environment

  • CONNECT request with absolute URI (eg: GET https://www.f5.com/) from a Proxy server to SSLo

Cause

  1. The request with HTTPS scheme in the URI (absolute URI) is behaving to align with RFC
  2. SSLO is working as expected as it's designed to decrypt the SSL traffic to services and not to modify content.

Recommended Actions

  1. The request with HTTPS scheme in the URI (absolute URI) is behaving to align with RFC but since the HTTP client doesn't, it's going to break sites that doesn't expect it.
    eg: irule that has '[HTTP::uri] starts_with "/index.html". This has been seen fairly frequently by F5 Support.

  2. It's okay to use within the enterprise, but when hitting the internet you should stick with general convention. The absolute URI is typically only for the proxy CONNECT requests. 

    Below is the iRule that can be used as a workaround, use the following settings when creating the iRule. 
    Note: While this iRule may have worked in some instances F5 Support has seen, Support cannot guarantee this will work for your specific environment.  If you are in need of comprehensive assistance for an iRule our Professional Services department is best suited to assist.
    Name: iRule_workaround
    Definition:

    when HTTP_REQUEST {
       #log local0. "HTTP_REQUEST in insert-header [HTTP::host]"
       if { [info exists httpHeaders] && [llength $httpHeaders] != 0 } {
            #log local0. "Adding headers: $httpHeaders"
            foreach {h_name h_value} $httpHeaders {
                HTTP::header insert "$h_name" "$h_value"
            }
       }
       #Replace HTTPS with HTTP workaround for 502 COnnection refused from Security Chain
       #log local0. "before uri : [HTTP::uri]"
       HTTP::uri [string map {https:// http://} [HTTP::uri]]
       #log local0. "after uri : [HTTP::uri]"
    }

  3. F5 doesn't recommend using iRule to fix the root cause because an iRule might address this specific problem but it's going to affect other sites for some reasons. The best practice and recommendation is not to modify the original request done by the end user by a device in path. This even more critical when we are hitting internet sites which are not in one's control.
