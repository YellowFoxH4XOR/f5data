Description

Best practice for creating vlans where more than one interface is desired.

 

Environment

Vlan configuration.

More than one interface required to be configured on the vlan.

Interfaces all set with default configuration or required to be processing traffic.

Cause

Vlans which have more than one interface attached can cause network failure when all attached interfaces are in forwarding state. Only a single interface can safely forward traffic implying other interfaces are redundant. If all interfaces forward traffic, this may result loops especially for broadcast and multicast traffic.

Recommended Actions

Vlans should not be created with more than one interface directly attached. If more than one interface is required it is recommended to create a trunk and attach all desired interfaces to the trunk. The trunk will then be attached to the vlan.

 

The purpose of a trunk is three fold:

- Increase bandwidth without needing higher capacity interfaces or upgrading hardware.

- Provide redundancy if one interface fails.

- Prevent network loops as compared to more than one interface directly attached to a vlan.

Additional Information

Important: Example of unrecommended configuration.

 

net vlan /Common/HA {

  interfaces {

    1.0 { }

    2.0 { }

  }

  tag 4093

}

 

Note: Both interfaces are in forwarding state implying traffic can be looped especially broadcast and multicast.

 

tmsh show net stp

Important: Example of recommended configuration.

  

Note: The recommended configuration will use both interfaces to carry traffic and will not loop received broadcast or multicast traffic.

  

 net trunk /Common/HA_Trunk {

   interfaces {

     1.0

     2.0

   }

   lacp enabled

}

 

net vlan /Common/HA {

  interfaces {

    HA_Trunk { }

  }

  tag 4093

}
