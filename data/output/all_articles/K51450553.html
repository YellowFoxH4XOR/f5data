K51450553: CPU on Hypervisor may not match observed load on Virtual Edition

Type
Knowledge
Published
2026-08-14
Updated
2026-08-14
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K51450553

Topic

In recent versions of Qemu, vCPU threads are kept awake after activity in case more activity follows.  When using a poll driver like TMM's native virtio driver this may result in the host keeping these threads alive indefinitely.  As a result CPU usage on the host will appear to be 100% even though the actual activity on the Virtual BigIP is near zero.

This is a side effect of the poll/sleep cycle on the driver and the optimization on Qemu and does not represent an actual problem with either the hypervisor or the guest.

Description

No action is required.  This is normal behavior.
