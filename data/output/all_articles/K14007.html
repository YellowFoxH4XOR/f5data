Known Issue

An iRules table command that includes a subtable key configured with an indefinite timeout may cause the session table to grow continuously.

For example, the following iRule causes this issue to occur due to the indefinite timeout configured for the subtable $i :

 when CLIENT_ACCEPTED {
        set i 0
        while { $i < 1000 } {
            table set -subtable "$i" "key" "value" indefinite 10
            incr i
        }
    }

Due to the indefinite subtable entries, the session table size and the associated memory allocated to the iRule, continuously increases.

Impact

Performance may degrade over time and the system may eventually become unresponsive due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Memory usage for iRules may continue to increase, and may fail to decrease when the affected iRule receives no new connections.

    For example, the following excerpt from the tmsh show sys memory command output shows memory usage before connections are processed by the affected iRule:
     

    Memory Used(bytes)  Current  Average  Max (since 12/11 15:02)
    ----------------------------------------------------------------------------------------
    Total Phys Memory     15.6G    15.6G                   15.6G
    OS Used Memory        15.5G    15.5G                   15.5G
    TMM Alloc Memory      13.5G    13.5G                   13.5G
    TMM Used Memory       33.8M    33.8M                   33.8M

    tcl (variable)        11.0M    11.0M                       1

    session                 320      320                     160


    After the affected iRule begins processing connections, the memory usage may increase, as shown in the following tmsh show sys memory command output example:

    Memory Used(bytes)  Current  Average  Max (since 12/11 15:02)
    ----------------------------------------------------------------------------------------
    Total Phys Memory     15.6G       15.6G                   15.6G
    OS Used Memory        15.5G       15.5G                   15.5G

  • Under extreme memory exhaustion, TMM may crash and dump core.

    Error messages that appear similar to the following example may be written to the /var/log/tmm file:

    Core files named similarly to the following example may be written to the /var/core/ directory:

    tmm.4.bld3372.0.core.gz

Workaround

To work around this issue, you can set a definite timeout for the subtable object. To do so, perform the following procedure:

Impact of workaround: None

Note: Completing the following procedure prevents only new subtable entries from being created with an indefinite timeout. To free up memory already allocated to subtable objects, refer to the Recovering from this issue procedure, later in the article.

Configuring an iRule to use subtable objects with a definite timeout

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click the affected iRule.
  4. To have a timeout value in seconds, modify the affected table command. For example:

    You can set a 10 second timeout for the following example table command:

    table set -subtable "$i" "key" "value" indefinite 10

    You would modify the command as shown in the following example:

    table set -subtable "$i" "key" "value" 10 10

  5. To save the changes, click Update.

Recovering from this issue

You can recover from this issue and free up memory used by the indefinite subtable objects by using an iRule to delete the subtables, or by restarting the device. To prevent the issue from reoccurring after the memory has been freed up using these processes, prior to using either of these procedures, you should modify your iRules as detailed in the previously listed Configuring an iRule to use subtable objects with a definite timeout section.

Deleting table entries with an iRule

Impact of workaround: Objects will be deleted from the session table, which may affect active connection processing. The full extent of the impact depends on the design of your specific iRule.

Note: This procedure provides a framework for removing indefinite table entries, and it is not a complete process. You must have complete knowledge of your iRule to complete the procedure. For assistance in designing a new iRule, or integrating this process with your existing iRule, refer to DevCentral. A DevCentral login is required to access this content.

To delete a table entry, you can use an iRule command similar to the following example:

table delete -subtable <name> -all

Where <name> represents the name of the affected table. (You must know the name of the affected tables to delete them directly.)

Rebooting the device

Impact of workaround: Service is interrupted.

To free up the memory used by the indefinite entries in the session table, you can reboot the device by performing the following procedure:

  1. Log in to the command line.
  2. Restart the device by entering the following command:

    reboot
