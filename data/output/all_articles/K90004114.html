Can you briefly explain my risk assessment?

If one or more of the following scenarios applies to your system, your system has a critical vulnerability (CVSS 9.0) on your data plane:

  • Your system is running BIG-IP 12.1.x or later using BIG-IP APM in any configuration or using a specific function in iRules or BIG-IP LTM policies or both.
  • Your system uses the URL categorization feature in either BIG-IP PEM or Secure Web Gateway.
  • Your system uses Advanced Web Application Firewall (WAF) Risk Engine (Early Access customers only).

Note: For more information about the data plane, refer to What is the difference between the control plane and the data plane? in this article.

What’s the best way to resolve these vulnerabilities?

F5 recommends installing a fixed version as soon as possible to eliminate the risk posed by these vulnerabilities. In the interim, you can apply the mitigations documented in the individual security advisories listed in this article.

Which version do I need to install to fix these vulnerabilities?

For BIG-IP products, this vulnerability is fixed in BIG-IP 12.1.5.3, 13.1.3.6, 14.1.4, 15.1.2.1, and 16.0.1.1.

Note: CVE-2021-22991 does not affect BIG-IP 11.6.x.

Note: According to commitments listed in K4602: Overview of the F5 security vulnerability response policy, F5 has not evaluated End of Technical Support (EoTS) versions.

What is the difference between the control plane and the data plane?

Control plane refers to management-related services and traffic flowing to them, such as the Configuration utility (TMUI), iControl REST, and SSH, either through the management IP address or a self IP address exposing the HTTPS or SSH ports (443 or 22). Data plane refers to any traffic handled by a virtual server, SNAT, NAT, or other non-control-plane-traffic handler.

Are you aware of any of these issues being publicly exploited?

No. At the time of publication, F5 is not aware of any public exploitation of these issues.

Is there a way to determine whether any of these CVEs have been exploited on my BIG-IP system?

Yes. The Diagnostics tab within F5 iHealth contains several heuristic tests designed to look for possible evidence of malicious activity within an uploaded QKView file, for example unknown processes or logins from public IP addresses. F5 is not aware of any indicators of compromise (IoCs) specific to these vulnerabilities.

Note: For more information, refer to the following documents:

  • K12878: Generating diagnostic data using the qkview utility
  • K27404821: Using F5 iHealth to diagnose vulnerabilities

Note: F5 Support is not trained to conduct forensic examination, and it is outside of F5 Support's scope to check whether your system has been compromised due to any of the CVEs listed here.

What steps should I take if I suspect that an attacker has exploited one of these vulnerabilities and compromised my BIG-IP system?

You should follow the guidance outlined in K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system.

What should I do if I am running an older platform, such as BIG-IP 6900, which is not compatible with the fixed software versions?

Most older platforms currently in use are in extended support, defined in K4309: F5 platform lifecycle support policy. If you are using such a platform, or one completely out of support, you should consider upgrading to a fully supported hardware platform.

F5 will not release engineering hotfixes on maintenance or point releases that were current when a platform passed platform End of Service Date (EoSD) and entered extended support. However, since you are already running a platform that is not fully supported, you may consider updating to a software release with the fixes. F5 does not take steps to break updates for platforms in extended support. So, in general, F5 expects that later maintenance and point releases issued after the platform entered extended support should work normally . For example, a system that was running BIG-IP 12.1.3 when it entered extended support will likely run 12.1.5.3 without issue, and updating will not change the support status. In the meantime, you can immediately apply the mitigations provided in the appropriate security advisory.

What are 'undisclosed requests'?

Undisclosed requests are correctly formatted, valid HTTP requests. In accordance with our policies outlined in K4602: Overview of the F5 security vulnerability response policy, F5 will not disclose the specifics required to trigger this vulnerability. F5 is aware that external resources may provide more details.

Does this vulnerability impact all HTTP virtual servers?

No. Only if you use the specific components listed in the security advisory is your system impacted by this vulnerability:

  • BIG-IP APM
  • BIG-IP ASM or Advanced WAF using the Risk Engine
  • BIG-IP PEM with URL Categorization
  • F5 Secure Web Gateway
  • F5 SSL Orchestrator with the Categorization macro
  • BIG-IP (all modules) Virtual Server with HTTP profile with the following configuration:
    •  iRule command HTTP::uri, or HTTP::path or HTTP::query with the "-normalized" switch
    • LTM Policy that uses HTTP URI or HTTP Referrer rule condition and uses the "Use normalized URI" option     

For complete details, refer to K56715231: TMM buffer-overflow vulnerability CVE-2021-22991.

Is there a mitigation available for this vulnerability?

Yes. To mitigate this vulnerability, you should install a version that includes a fix (refer to K56715231: TMM buffer-overflow vulnerability CVE-2021-22991). There are no other mitigation options available.

Does restricting access to the Configuration utility (TMUI) or iControl REST mitigate this vulnerability?

No, this vulnerability is exploited through the data plane and you cannot mitigate it by restricting access to the control plane.

Are there any necessary special considerations when installing a fixed version on a device with BIG-IP APM licensed and provisioned?

When upgrading the BIG-IP system, the version of the APM Clients ISO file that is shipped with the BIG-IP software ISO file automatically becomes the active APM Clients version.

For example, when you upgrade a system running BIG-IP 15.1.1 with APM Clients 7.2.1 active to BIG-IP 15.1.2, the active APM Clients version after the upgrade automatically becomes 7.1.8.4, the version that is shipped with BIG-IP 15.1.2. You should verify the active APM Clients version after a BIG-IP software upgrade and update your APM Clients version as appropriate.

For more information on BIG-IP and APM Clients version, refer to K13757: BIG-IP Edge Client version matrix. You may also want to review K15302: Understanding BIG-IP Edge Client Component Update behavior for Windows, macOS, and Linux CLI, and K52547540: Updating BIG-IP Edge Client for the BIG-IP APM system.

Is there a way to query my configuration to help me identify iRule or LTM Policy configurations that I should review?

To help identify iRules or BIG-IP LTM policy configurations for review, you can use one of the following TMOS Shell (tmsh) commands from the command line of your BIG-IP system:

Important: The following query commands return configurations based on a search string and any matching configurations should be reviewed independently to determine if the configuration matches the criteria of CVE-2021-22991.
  • To recursively query LTM rules across partitions for the key word normalize, enter the following command:

    tmsh -q -c "cd / ; list /ltm rule  recursive" | egrep 'ltm rule|normalize' | grep -B1 normalize

  • To recursively query LTM policies across partitions for the key word normalize:

    tmsh -q -c "cd / ; list /ltm policy  recursive" | egrep 'ltm policy|normalize' | grep -B1 normalize

    Note: The commands return the iRules or policy name followed by the line from the configuration that contains the search string.

The Security Advisory said that only BIG-IP ASM Risk Engine use cases are vulnerable. How do I tell if my Advanced WAF or BIG-IP ASM system is using the Risk Engine feature?

To verify the vulnerable conditions for these products and how to determine if the Risk Engine is enabled, refer to K22224021: Is Advanced WAF or BIG-IP ASM affected by CVE-2021-22991?.

Are any of the following iRule commands HTTP::uri, HTTP::query and HTTP::path vulnerable to CVE-2021-22991?

No, The iRule commands HTTP::uri, HTTP::query, and HTTP::path themself are not vulnerable to CVE-2021-22991. however, they will become vulnerable once the -normalized switch is added.
