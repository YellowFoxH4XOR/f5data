Topic

You should consider using these procedures under the following condition:

  • You want to display all resource records in a zone locally from the command line of the BIG-IP DNS (formerly GTM) system.

Description

You can use the dig or host utilities to display all resource records in a zone locally on the command line of the BIG-IP DNS system by performing a zone transfer. You can also use cat or less utilities on the command line of the BIG-IP DNS system to display the contents of a zone file to view all resource records.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the BIG-IP command line.
  • You have zone files stored on the BIG-IP system containing the resources records you want to display.

Procedures

  • Use ZoneRunner to allow zone transfers from localhost
  • Use the dig utility to display all resource records in a zone
  • Use the host utility to display all resource records in a zone
  • Display the contents of a zone file from the command line

Use ZoneRunner to allow zone transfers from localhost

The allow-transfer option in the BIND configuration file, /var/named/config/named.conf, defines what hosts are allowed to perform a zone transfer. The default setting on a BIG-IP DNS system is to only allow transfers to localhost. If you plan to use the dig or host utilities to display resource records using a zone transfer, you must ensure that localhost is allowed to make transfers. To do so, perform the following procedure:

Note: F5 recommends that you use ZoneRunner for this step; however, you can perform it from the command line. For more information about editing the BIND configuration file from the command line, refer to K6963: Managing the BIG-IP BIND configuration file.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to DNS > Zones > ZoneRunner > named Configuration.
  3. In the named Options box, look for the allow-transfer option in the options configuration stanza to determine what hosts are allowed. For example:

    allow-transfer {
        localhost;
    };

  4. If localhost is already allowed, which is the default, you can skip to the next procedure; otherwise, continue to step 5.
  5. Add localhost to allow-transfer using the syntax shown in the previous example.
  6. Select Update.

Use the dig utility to display all resource records in a zone

The following procedure describes how to perform a zone transfer to the localhost using the dig utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Display all resource records in a zone by using the following syntax:

    dig @localhost -t AXFR <zone name>

    In the previous syntax, note the following:
    • @localhost tells dig to query the localhost rather than the default DNS server.
    • -t AXFR tells dig to request a full zone transfer.
    • <zone name> is the name of the DNS zone stored on the BIG-IP system.

    For example:

    dig @localhost -t AXFR example.com

  3. Review the command output. The dig utility requests a zone transfer from the BIG-IP system and displays output similar to the following:

    ; <<>> DiG 9.11.5-P4 <<>> @localhost -t AXFR example.com
    ; (1 server found)
    ;; global options: +cmd
    example.com.            500     IN      SOA     bigip1.example.com. hostmaster.bigip1.example.com. 2018020101 10800 3600 604800 60
    example.com.            0       IN      NS      bigip1.example.com.
    ldap.example.com.       3600    IN      A       192.168.10.125
    www.example.com.        0       IN      A       172.16.1.120
    example.com.            500     IN      SOA     bigip1.example.com. hostmaster.bigip1.example.com. 2018020101 10800 3600 604800 60
    ;; Query time: 27 msec
    ;; SERVER: 127.0.0.1#53(127.0.0.1)
    ;; WHEN: Fri May 24 14:14:28 PDT 2019
    ;; XFR size: 5 records (messages 1, bytes 230)

Use the host utility to display all resource records in a zone

The following procedure describes how to perform a zone transfer to the localhost using the host utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. To display all resource records in a zone, use the following syntax:

    host -la <zone name> localhost

    In the previous syntax, note the following:

    • -la tells host to request a full zone transfer and print all records.
    • <zone name> is the name of the DNS zone stored on the BIG-IP system.
    • localhost tells host to query the localhost rather than the default DNS server.

    For example:

    host -la example.com localhost

  3. Review the command output. The host utility requests a zone transfer from the BIG-IP system and displays output similar to the following:

    Trying "example.com"
    Using domain server:
    Name: localhost
    Address: 127.0.0.1#53
    Aliases:

    ;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 10405
    ;; flags: qr aa; QUERY: 1, ANSWER: 6, AUTHORITY: 0, ADDITIONAL: 0

    ;; QUESTION SECTION:
    ;example.com.                   IN      AXFR

    ;; ANSWER SECTION:
    example.com.            500     IN      SOA     bigip1.example.com. hostmaster.bigip1.example.com. 2019052403 10800 3600 604800 60
    example.com.            0       IN      NS      bigip1.example.com.

Display the contents of a zone file from the command line

Regardless of the allow-transfer option in the BIND configuration file, you can use the cat or less utilities to display the contents of a zone file to view all resource records. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line
  2. Change the working directory to the BIND zone file directory by entering the following command:

    cd /var/named/config/namedb

  3. List the zone files in the directory to determine which file to display by entering the following command:

    ls

  4. To display all resource records in a zone file with cat or less, perform one of the following steps:

    • For cat, use the following syntax:

      cat <zone file>

      For example:

      cat db.external.example.com.

    • For less which allows for paging through text, use the following syntax:

      less <zone file>

      For example:

      less db.external.example.com.

  5. Review the command output. The contents of the zone file appears similar to the following example:

    $ORIGIN .
    $TTL 500        ; 8 minutes 20 seconds
    example.com             IN SOA  bigip1.example.com. hostmaster.bigip1.example.com. (
                                    2019052403 ; serial
                                    10800      ; refresh (3 hours)
                                    3600       ; retry (1 hour)
                                    604800     ; expire (1 week)
                                    60         ; minimum (1 minute)
                                    )
    $TTL 0  ; 0 seconds
                            NS      bigip1.example.com.
    $ORIGIN example.com.
    $TTL 3600       ; 1 hour
    ldap                    A       192.168.10.125
    $TTL 0  ; 0 seconds
    www                     A       172.16.1.120
