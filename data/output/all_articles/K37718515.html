Topic

You should consider using these procedures under the following conditions:

  • You want to investigate denial-of-service (DoS) events while the BIG-IP AFM system generates log messages to the /var/log/ltm file.
  • The BIG-IP system experiences a DoS or distributed denial-of-service (DDoS) attack, and you want to fine tune the BIG-IP AFM DoS attack vectors in the device DoS configuration or the Network Security-enabled DoS profile applied to a virtual server.

Description

The BIG-IP AFM system detects network-based attacks and rate-limit based on the number of packets per second (PPS) that are received as configured in the system's DoS configuration for the BIG-IP system-wide DoS protection and for virtual servers through the DoS profiles. To properly set a value in the following attack types and vectors, you need to have an idea about how many incoming packets of a DoS vector attack type that the BIG-IP system or the virtual server is receiving:

Device DoS configuration attack type

  • Detection Threshold PPS
  • Detection Threshold Percent
  • Rate/Leak Limit

Network Security-enabled DoS profile attack type

  • Threshold
  • Rate Increase
  • Rate Limit

The following sections discuss what you should look for when you review the log files and the BIG-IP Traffic Management Microkernel (TMM) statistics and show sample tunings for the various attack types and vectors that may apply to your platform.

Attack Count values

When the Detection Threshold PPS of an attack type is exceeded, the BIG-IP AFM DoS event is logged, the Attack Count value in the DoS statistic output is incremented, and the counter begins counting when the BIG-IP device is started. The DoS Statistics in the previous example output shows that the TCP SYN flood attack type was detected 22 times since the last BIG-IP system start.

Stats values

The Stats Rate value is the number of PPS the BIG-IP AFM system has received for the Attack Type. The Stats 1m value is the number of PPS the system received in the last minute the for the Attack Type.

From these DoS Stat values, you can observe how many packets of an Attack Type the BIG-IP AFM system has received, and you can use this figure as a baseline value for the Detection Threshold PPS of the Attack Type.

Understanding BIG-IP AFM DoS device configuration attack-type tuning

The threshold defined in the DoS Device Configuration is per-TMM. You need to know how many TMMs the BIG-IP device has so that you can set a value appropriate to the BIG-IP platform that you have. For more information, refer to K15023: The BIG-IP AFM system enforces configured thresholds and limits for each TMM.

To determine the number of TMMs for your system, type the following command:

tmsh show sys tmm-info | grep "Sys::TMM"

The following example shows a sample of the command output on a BIG-IP 5200 platform with four TMMs:

Sys::TMM: 0.0
Sys::TMM: 0.2
Sys::TMM: 0.4
Sys::TMM: 0.6

Configuring DoS Device Configuration Attack Type

To configure an attack type in the Configuration utility, perform the following procedure:

  1. Navigate to Security > DoS Protection > Device Configuration > Category/Attack Type.
  2. Under Manual Configuration, for TCP SYN Flood Attack Type on Dos Protection Device Configuration, review the definition of each of the options from the BIG-IP online help to understand what they are.

    For example:

    • Detection Threshold PPS specifies how many PPS the system must detect in traffic in order to detect this attack.
    • Detection Threshold Percent specifies the threshold percent that the system must detect in traffic to detect this attack.
    • Rate Limit specifies the rate of this type of the packet that the system must detect in traffic to detect this vector. The system drops packets after the traffic level exceeds the rate limit.

    Note: For BIG-IP AFM 13.x and later, the Detection Threshold EPS and Mitigation Threshold EPS are the equivalent configuration for the DoS Attack Type Detection Threshold PPS and Rate Limit in BIG-IP AFM 12.x DOS Protection Device Configuration respectively. In addition, in BIG-IP AFM 13.x and later, to manually configure DoS Attack type Thresholds, set the Threshold mode to Fully Manual.

    Using the DoS Stats from the previous example, the following shows a sample configuration for the values of Detection Threshold PPS, Detection Threshold Percent, and Rate Limit.

    Note: The values and thresholds used to demonstrate the calculation of the BIG-IP AFM attack type configuration are examples only. You should carefully assess, review, and configure these values based on your understanding of the amount and type of traffic the BIG-IP system is expected to receive.

    Important: You should review these values because they indicate the initial detection of an attack and its rate limiting. If values are set too low, detection happens too early and logs DoS events which may be false positives, and as such they may limit the traffic too early and unnecessarily. If values are set too high, the BIG-IP AFM system allows too many packets for the specific attack type and this may impact the device CPU and memory resource usage, and the system will not rate limit the attack, causing a false negative.

    For more version specific configuration options for BIG-IP AFM DoS Protection Device Configuration Attack types, you can refer to the Detecting and Preventing System DoS and DDoS Attacks chapter in BIG-IP System: DOS Protection and Protocol Firewall Implementations.

    Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

    • For the Detection Threshold PPS, if Stats Rate value is 4128, consider setting this value three or four times higher as a buffer for possible or expected increases in traffic. Note that the final value is a threshold that applies to a TMM.

      For example, Stats Rate: 4128 x 4 = 16512 Detection Threshold PPS is applied per-TMM.

      If the BIG-IP device has four TMMs, the device can possibly process 66048 pps until the attack is detected. However, once the Detection Threshold PPS is exceeded on a single TMM, a DoS event is logged.

    • For the Rate Limit value, if this value is exceeded, the BIG-IP AFM drops packets of this type. Therefore, if the value set in the Detection Threshold PPS is four times the value to add a buffer, you can possibly use the Stats Rate value times five the value, which is 20640 pps per-TMM.
    • For the Detection Threshold Percent, set a value to account for a sudden increase in percentage of these type of traffic to cause its detection. For example, you can set it to 500% or five times the normal traffic or statistics rate.

Drops statistics definitions

  • Drops Rate is the total number of PPS dropped by the BIG-IP AFM-DoS vector in the last second.
  • Drops is the total number of packets dropped by the BIG-IP AFM-DoS vector since the last system start.
  • Drops 1h is the total number of PPS dropped by the BIG-IP AFM-DoS vector in the last hour since the attack was detected.

Understanding BIG-IP AFM DoS profile Network Attack type tuning

You can review DoS statistics to gain an understanding of the amount of attack-type traffic a virtual server receives. You can also use these statistics as a baseline threshold for the BIG-IP AFM DoS Attack Type thresholds.

For example, if Stats Rate is at 644 for the attack type A query DOS, this is the number of PPS of this type received at the time when the following command syntax is run:

tmsh show /security dos profile <DoS-Profile-with-NetworkSecurity-enabled>

With this value known, you can use it as an estimate of how many packets for this type of traffic the BIG-IP system is allowed to receive before it detects the packets as an attack, as defined in the Attack Type Detection Threshold.

A Stats Rate value of 644 can be rounded to the nearest 1000 and allow three times the amount of the type of traffic before detecting it as an attack, and it can be defined in the Detection Threshold, set with a Rate Limit of 4000 packets. If the number of PPS exceeds 4000 for the attack type, new incoming packets of the same type are dropped. Similarly, if a sudden increase of packets is observed, the Rate Increase Threshold can be set to a percentage value to detect the attack, in which it compares the average rate over the last minute to the average rate over the last hour. A value of 250% means that, if the Stats 1h value is 519 pps and the Stats 1m value is 1300 pps, an attack will be detected and logged.

Note: For BIG-IP AFM 13.x and later, the Detection Threshold EPS and Mitigation Threshold EPS are the equivalent configuration for the DoS Attack Type Detection Threshold PPS and Rate Limit in the BIG-IP AFM 12.x DoS Profile configuration. In addition, in BIG-IP AFM 13.x and later, to manually configure DoS Attack type Thresholds, set the Threshold mode to Fully Manual.

For more version-specific configuration options for BIG-IP AFM DoS Protection profile configuration attack types, refer to BIG-IP System: DOS Protection and Protocol Firewall Implementations, specifically the following chapter name according to the version:

  • BIG-IP AFM 14.x and later: The procedure to configure a DoS profile against DoS attacks on protected objects appears in Detecting and Preventing Network DoS Attacks on a Protected Object.
  • BIG-IP AFM 13.x: The procedure to configure a DoS profile against network DoS attacks appears in Detecting and Preventing Network DoS Attacks on a Virtual Server.
  • BIG-IP AFM 12.x: The procedure for configuring a DoS profile against DoS sweep attacks appears in Detecting and Preventing Network DoS Attacks.
  • BIG-IP AFM 11.6.x: The procedure similar to detecting and protecting against DNS DoS attacks with a DoS profile appears in Detecting and Preventing DNS DoS Attacks.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

The BIG-IP AFM Configuration utility has evolved through various versions. The following procedures show how to navigate to the BIG-IP AFM DoS Protection Profile configuration in each major version release:

BIG-IP AFM 14.x and later

  1. Navigate to Security > DoS Protection > Protection Profiles.
  2. Click the name of the BIG-IP AFM Network Security-enabled DoS profile to modify it.
  3. Click Network to expand the Attack Vectors list.
  4. Click the attack vector you want to configure.
  5. For State, click Mitigate.
  6. For Threshold Mode, click Fully Manual.
  7. Configure Detection Threshold EPS, Detection Threshold Percentage, and Mitigation Threshold EPS parameters according to your environment.

BIG-IP AFM 11.x - 13.x

  1. Navigate to Security > DoS Protection > DoS Profiles.
  2. Click the Network Security Enabled DoS profile.
  3. Under Attack Types, for Detection Status, select the enabled check box and configure the Threshold, Rate Increase, and Rate Limit parameters according to your environment.

Observing the Packets In value of a virtual server

To help decide the baseline values for the Attack Type threshold, observing how many packets a virtual server receives can be useful.

You can use the following tmsh command to display a list the virtual servers receiving the greatest number of incoming packets:

tmsh show /ltm virtual raw field-fmt | awk '/ltm virtual/{ vs=$0; next} /clientside.pkts-in/{ print vs $0 }' | sed 's/ {//' | sort -rn -k 5 | head -10 | column -t

Output appears similar to the following:

ltm virtual vs1 clientside.pkts-in 487917
ltm virtual vs2 clientside.pkts-in 630
ltm virtual vs3 clientside.pkts-in 253
ltm virtual vs4 clientside.pkts-in 0
ltm virtual vs5 clientside.pkts-in 0
ltm virtual vs6 clientside.pkts-in 0

If there are multiple administrative partitions on the BIG-IP device, specify the administrative partition name to verify the number of incoming packets for virtual servers in that partition using the following command syntax:

tmsh show /ltm virtual /<Administrative-Partition-Name>/* raw field-fmt | awk '/ltm virtual/{ vs=$0; next} /clientside.pkts-in/{ print vs $0 }' | sed 's/ {//' | sort -rn -k 5 | head -10 | column -t

For example, to query the command on the administrative partition called test-1 type the following command:

tmsh show /ltm virtual /test-1/* raw field-fmt | awk '/ltm virtual/{ vs=$0; next} /clientside.pkts-in/{ print vs $0 }' | sed 's/ {//' | sort -rn -k 5 | head -10 | column -t

Output appears similar to the following:

ltm virtual /test-1/test clientside.pkts-in 2

In addition, to observe how many packets ingress a specific virtual server, use the following command syntax:

tmsh show ltm virtual <VirtualServer-Name> raw | grep -i 'traffic' -A 4 | awk 'NR==1;NR==4'

For example, to view the number of packets for a virtual server called vs_prod, type the following command:

tmsh show /ltm virtual vs_prod raw | grep -i 'traffic' -A 4 | awk 'NR==1;NR==4'

Output appears similar to the following:

Traffic ClientSide Ephemeral General
Packets In 31519 0 -

Running the previous command and observing the Packets In value periodically provides an estimate on the number of packets received for the specific virtual server.

With the values observed for the specific virtual server, you can set the BIG-IP AFM DoS Attack Type Threshold to the appropriate values.

For example, the Packets In value for a virtual server is observed to be 1886 at peak hours. Adding consideration to expected increase of traffic, you can configure this setting to four times that value (1886 x 4 = 7544). You can also use this resulting figure as the Detection Threshold for the Attack Type you are configuring.

Setting a Rate Limit of five times the Packets In value (1886 x 5 = 9430) causes the system to drop packets exceeding that number. For Rate Increase, configuring the setting to 250% of the value causes the system to detect an attack if the traffic increases to 250% of the value in the last minute, compared to the average value of the type of traffic an hour earlier. For example, if the traffic of the attack type observed was 5000 pps an hour ago and the value increased to 12,500 pps in the last minute, the attack is detected.

Note: The values and thresholds used to demonstrate the calculation of the BIG-IP AFM attack type configuration are examples only. You should carefully assess, review, and configure these values based on your understanding of the amount and type of traffic the BIG-IP system is expected to receive.

Important: You should review these values because they indicate the initial detection of an attack and its rate limiting. If values are set too low, detection happens too early and logs DoS events which may be false positives, and as such they may limit the traffic too early and unnecessarily. If values are set too high, the BIG-IP AFM system allows too many packets for the specific attack type and this may impact the device CPU and memory resource usage, and the system will not rate limit the attack, causing a false negative.
