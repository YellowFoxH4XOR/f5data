Known Issue

This is the result of a known issue. The BIG-IP GTM system allows you to refine topology load balancing by creating regions. A region contains one or more region member types such as countries, continents, or IP subnets that can be combined and added to a topology statement for load-balancing.

Note: For more information about topology load-balancing and regions, refer to the BIG-IP GTM Configuration Guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

If you define a region that has no member list criteria and add the region to a topology record, the BIG-IP GTM system matches all load-balancing requests to the defined region. If the BIG-IP GTM system does not find a region statement containing a positive match argument in the /config/gtm/region.user file, the system incorrectly assumes that the region statement contains a negative match argument.

For example, the following example is an empty region.user file containing a region named empty_region that contains no member list criteria:

region_db user {

region {
name "empty_region"
}
}

If the empty region definition is included in a topology statement referencing PoolA with a weight of 100, and the topology record also references a statement with a lower weight referencing PoolB, the BIG-IP GTM system incorrectly sends all requests to the wide IP to PoolA. The system should assume that the empty region statement does not match any request, and send all requests to PoolB.

For example:

topology { // 2 Items
// server ldns score
pool."PoolA" user."empty_region" 100
pool."PoolB" country."US" 1
}

F5 Product Development is tracking this issue as ID 225175 (formerly CR138719). BIG-IP iHealth may list Heuristic H384088 on the Diagnostics > Identified > Medium screen.

Workaround

You can work around this issue by specifying at least one member type criteria for the region statement.
