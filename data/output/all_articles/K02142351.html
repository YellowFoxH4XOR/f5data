Known Issue

The system may not roll forward the provision.tomcat.extramb database variable (DB key) after a version upgrade.

This issue occurs when all of the following conditions are met:

  • You have configured the provision.tomcat.extramb database variable with a non-zero value.
  • You have upgraded your BIG-IP software.
Under certain conditions, you can use the provision.tomcat.extramb database variable to increase the maximum amount of Java virtual memory available to the tomcat process. For more information, refer to K9719: Error Message: java.lang.OutOfMemoryError.

Impact

The tomcat process may not be configured with the additional memory resource required. As a result, you may have difficulty accessing the BIG-IP Configuration utility.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • You may have difficulty accessing the BIG-IP Configuration utility.
  • The tmsh list /sys db provision.tomcat.extramb command output displays the default value of zero:

    For example:
    tmsh list /sys db provision.tomcat.extramb

    sys db provision.tomcat.extramb {
    value "0"
    }

Workaround

To work around this issue, you can reconfigure the provision.tomcat.extramb database value to the value you want. Alternatively, you can restore the provision.tomcat.extramb database value to the last known value, using either the default UCS backup taken during the version upgrade (/var/local/ucs/config.ucs) or the UCS backup file you want to use. To do so, perform one of the following procedures:

Reconfiguring the provision.tomcat.extramb key

Impact of workaround: There will be a brief disruption to the BIG-IP Configuration utility while the tomcat process restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Set the provision.tomcat.extramb database variable to the amount of additional memory that you want to be allocated, using the following command syntax:

    modify /sys db provision.tomcat.extramb value <MB>

    In this command, note the following:
    • <MB> is the number of megabytes of additional memory that you had previously configured.
    For example, if you had previously configured an additional 20 MB of additional memory, type the following command:

    modify /sys db provision.tomcat.extramb value 20
  3. Restart the tomcat process by typing the following command:

    restart /sys service tomcat

Restoring BIG-IP configuration data

Impact of workaround: The BIG-IP system replaces any existing configuration with the UCS archive file configuration. F5 recommends that you perform this procedure during a scheduled maintenance window, as network traffic may be disrupted while the system loads the BIG-IP configuration.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Restore the UCS archive file by using the following command syntax. Replace <path/to/UCS> with the full path of the UCS archive file that you want to restore:

    load /sys ucs <path/to/UCS>

    If you do not specify the path, the BIG-IP system performs as if the UCS archive file is located in the default /var/local/ucs directory.
