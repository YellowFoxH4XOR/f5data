Topic

You should consider using this procedure under the following condition:

  • You want to filter BIG-IP log messages based on the message parameters.

Description

BIG-IP log messages include important diagnostic information about the events occurring on the BIG-IP system. Log messages that are specific to the BIG-IP operating system, such as those pertaining to local and global traffic events, include parameters that allow you to filter the messages and perform a logging action based on the filter.

You can configure a single log filter or multiple filters that perform several logging actions. For example, you may want to create a single log filter that specifies the message ID field as a filter parameter and send those messages to a pool of remote logging servers. Alternatively, you may want to create a filter that discards a subset of log messages and another filter sends all remaining messages to a pool of remote logging servers.

To filter BIG-IP log messages, perform the following procedures:

  • Identifying message parameters for log filtering
  • Creating filters for local logging
  • Creating filters for remote logging

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the Configuration utility.
  • You have configured a log destination consisting of one or more remote high-speed log servers (for remote logging filters).

Procedures

Identifying message parameters for log filtering

You can create log filters using one or more parameters of the log message that you want to filter. You can then define how the system processes the filtered log messages. The BIG-IP system supports the following filter parameters:

  • Severity: Filter log messages based on the log-level severity. The severity options range from Debug (least severe) to Emergency (most severe).
  • Source: Filter log messages based on the system process that generated the message.
  • Message ID: Filter log messages based on the 8-hexadecimal ID number that appears in the BIG-IP log message.

To identify these message parameters in a BIG-IP log message, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log into the BIG-IP command line.
  2. Change to the /var/log directory by typing the following command:

    cd /var/log

  3. Use a Linux utility, such as cat or less, to read the BIG-IP log file you want to review.

    For example, to view the ltm log file, type the following command:

    cat ltm

  4. Locate the BIG-IP log messages for which you want to create the log filter.
  5. Use the following information to identify the parameters to use in the filter:

    BIG-IP log messages use the following format:

    <time stamp> <host name> <severity_level> <process_name[pid]>: <message ID>:<code>: <message text>

    For example, in the following message, the severity level is notice, the process name is tmm, and the message ID is 01010029:

    Jun 15 08:34:57 bigip_2 notice tmm1[11208]: 01010029:5: Clock advanced by 486 ticks

  6. Repeat the previous steps for each log message for which you want to create a log filter.

Creating filters for local logging

You can create one or more filters for local logging. For example, you may want to create one filter that increases logging verbosity for a certain process and another filter that prevents specific BIG-IP log messages from being sent to the local log files. For information about creating filters for local logging, refer to the following examples:

Creating a filter that increases logging verbosity for a process

You can create a filter that increases logging verbosity for one or more processes and sends the messages to the local log files. For example, you may want to temporarily enable debug logging for a process when you are troubleshooting a problem on the BIG-IP system. To do so, perform the following procedure.

Impact of procedure: Debug logging generates verbose log output and you should disable it after you are done gathering troubleshooting data.

  1. Navigate to System > Logs > Configuration > Log Publishers.
  2. Click Create.
  3. Type a name for the log publisher.
  4. Under Log Destinations, in the Available list, click local-syslog move it to the Selected list.
  5. Click Finished.
  6. Navigate to System > Logs > Configuration > Log Filters.
  7. Click Create.
  8. In the Name box, type a name for the log filter.
  9. Under Configuration, in the Severity list, click an appropriate severity level, such as Debug.
  10. In the Source list, click an appropriate system process, such as mcpd.
  11. Leave the Message ID box blank.
  12. In the Log Publisher list, click the publisher that you created in steps 1 through 5.
  13. Click Finished.

    Note: To disable verbose logging, edit the filter you just created, click no-source in the Source list, and click Update.

Creating a filter that prevents specific messages from being sent to the local log files

You can create a filter that prevents the system from sending specific BIG-IP log messages to the local log files. You may want to perform this action to temporarily prevent the system from logging one or more messages. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Filters.
  2. Type a name for the log filter.
  3. In the Severity list, click the severity level that matches the error message that you want the system to filter.
  4. In the Source list, click all.
  5. In the Message ID box enter the 8-hexadecimal-digit message ID that appears in the log message.
  6. In the Log Publisher list, click None.
  7. Click Finished.

Creating filters for remote logging

Before you create filters for remote logging, you must configure the system to send log messages to a pool of remote log servers. You can then create one or more filters that direct some log messages to the remote log servers and others to the local log files. For example, you may want to create a filter that sends all log data for a certain process to a pool of remote log servers.

Creating a pool of remote log servers

You should identify the IP addresses and service port of the remote high-speed log servers to which the BIG-IP system sends the debug log messages, and then create a pool object on the BIG-IP system. To create a pool of remote log servers, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click Create.
  4. Type a name for the pool.
  5. Under Resources, in the Load Balancing Method list, click an appropriate load balancing method.
  6. For New Members, configure the settings as follows:
    • For Node Name, type a name.
    • For Address, type an IP address.
    • For Service Port, type a service port, such as 514.
    • Click Add.
    • Repeat the previous steps for each high-speed log server you want to add to the pool.
  7. Click Finished.

Creating a remote high-speed log destination

After creating the pool of remote high-speed log servers to which the BIG-IP system sends the debug log messages, create a log destination that specifies a pool of remote log servers. To do so, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Destinations.
  2. Click Create.
  3. Type a name for the log destination.
  4. For Type, click Remote High-Speed Log.
  5. Under Pool Settings, configure the settings as follows:
    • In the Pool Name list, click the existing pool of remote high-speed log servers.
    • In the Protocol list, click the protocol for the system to use to send logs to the pool of remote high-speed log servers.
    • In the Distribution list, click one of the following distribution methods used by the Remote High Speed Log destination to send messages to pool members:
      • adaptive: Connections to pool members are be added as required to provide enough logging bandwidth.
      • balanced: Sends each successive log to a new pool member, balancing the logs among them according to the pool's load balancing method.
      • replicated: Replicates each log to all pool members, for redundancy.

Creating a formatted remote high-speed log destination

If your remote syslog servers support a log formatting standard, you should create a formatted log destination in addition to the remote high-speed log destination. A formatted logging destination is appropriate for remote log servers, such as Remote Syslog, Splunk, or ArcSight servers. To create a formatted remote high-speed log destination, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Destinations.
  2. Click Create.
  3. Type a name for the log destination.
  4. For Type , click the formatted logging destination type you want to use, such as Remote Syslog, IPFIX, Splunk, or ArcSight.
    • If you selected Remote Syslog, define the following parameters:
      • In the Syslog Format list, click a format for the logs.
      • In the Forward To list, click the log destination that references the pool of remote syslog servers.
    • If you selected Splunk or ArcSight, define the following parameter:
      • In the Forward To list, click the log destination that points to the pool of high-speed log servers.
    • If you selected IPFIX, define the following parameter:
      • In the Pool Name list, click the pool of high-speed log servers.
  5. Click Finished.

Creating a log publisher

To create a log publisher to send logs to a set of specified log destinations, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Publishers.
  2. Click Create.
  3. Type a name for the log publisher.
  4. Under Log Destinations, in the Available list, click the appropriate log destination and move it to the Selected list.

    Note: If you are using a formatted log destination, choose the destination that matches your log servers, such as Remote Syslog, Splunk, or ArcSight.

  5. Click Finished.

Creating a log filter that sends messages of a certain type to a pool of remote log servers

You can create a log filter that sends messages of a certain type to the pool of high-speed log servers. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Filters.
  2. In the Name box, type a name for the log filter.
  3. Click Create.
  4. Type a name for the log filter.
  5. Choose one or more of the following filter options:
    • To filter log messages based on the log level severity, in the Severity list, click the alert level that you want the system to use. For example, if you want to send debug log messages to the pool of high-speed log servers, click Debug.
    • To filter log messages based on the system process that generated the message, in the Source list, click system process you want to use. For example, if you are troubleshooting a Traffic Management Microkernel (TMM) issue, click TMM.
    • To filter log messages based on the 8-hexadecimal ID number that appears in the BIG-IP log message, in the Message ID box, type or enter the message ID.

      Note: When you use the Log Filter to send logs to a remote logging server, the system no longer creates a local copy of those logs.

  1. In the Log Publisher list, click the publisher that you created in the previous procedure.
  2. Click Finished.

Disabling the log filter

You can disable the log filter by changing the source option in the log filter to no-source. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to System > Logs > Configuration > Log Filters.
  2. Click the name of the log filter that you created in the previous procedure.
  3. In the Source list, click no-source.
  4. Click Update.
