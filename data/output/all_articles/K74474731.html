Known Issue

In rare circumstances, some CMP-demoted FastL4 virtual servers may intermittently and incorrectly use the TCP handshake timeout value as the TCP idle timeout.

This issue occurs when all of the following conditions are met:

  • You have a FastL4 virtual server.
  • The FastL4 virtual server has been demoted from CMP.

Impact

The system may reset connections earlier or close connections at an unexpected time.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system randomly closes or resets FastL4 connections at unexpected times.

Resolution

Workaround

To work around this issue, you can ensure that the virtual server is not demoted from CMP.  For further information on possible reasons for a virtual server to be demoted from CMP, and techniques on preventing this, refer to the following articles:

  • K14358: Overview of Clustered Multiprocessing (11.3.0 and later)
  • K13033: Constructing CMP-compatible iRules

Impact of workaround: There should be no impact if your virtual server can be promoted to CMP.
