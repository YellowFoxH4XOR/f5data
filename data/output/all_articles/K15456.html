Known Issue

The BIG-IP system may incorrectly reorder packet filter rules. This issue occurs when all of the following conditions are met:

  • You use the Traffic Management Shell (tmsh) to modify the order value of an existing packet filter rule to 65535.
  • You then use the Configuration utility to configure a new packet filter rule with the Order option set to Last.

This issue occurs as the Configuration utility attempts to set the order value of the new rule to 65535 when the Order option is set to Last. Because there is already an existing packet filter rule with an order value of 65535, the BIG-IP system recalculates and wraps the order value of the new rule to 4, which effectively reorders the new rule to be before the existing rule.

Impact

Depending on the configuration, if configured to drop all traffic, the new packet filter rule may disrupt traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The new packet filter rule, with its Order option set to Last, is reordered to be first, as displayed in the Configuration utility.
  • The tmsh list /net packet-filter command shows the new packet filter rule has an order value of 4.
  • If you subsequently attempt to configure another new packet filter rule with its Order option set to First or Last in the Configuration utility, the Configuration utility fails to create the rule and reports an error similar to the following example:

    01070087:3: Packet filter rule '/Common/sctp1': order 4 already used for packet filter rule /Common/udp1

Workaround

There is no work around for this issue. However, you can avoid this issue by either using only the Configuration utility to configure/modify all packet filter rules, or by using only the tmsh utility if you require granular control over the order value. Additionally, if you have already set the order value of an existing packet filter rule to 65535, but have yet to create a new rule, you must change the order value of that existing packet filter rule to a value lower than 65530. To recover from this issue, you can manually modify the order value of the affected packet filter rules in the tmsh utility. To do so, perform the following procedure:

Impact of workaround: Ensure that the order values you wish to assign to the affected packet filter rules are applicable to your application environment, otherwise traffic may not be processed as expected.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Modify the order value of an affected packet filter rule using the following command syntax:

    modify /net packet-filter <packet filter rule name> order <new order value from 1-65535>

    For example, you would type the following command to reorder the ICMPDenyAll packet filter rule with order value 65529:

    modify /net packet-filter ICMPDenyAll order 65529

  3. Repeat the previous step for the remaining affected packet filter rules.
  4. Save the changes by typing the following command: 

    save /sys config
