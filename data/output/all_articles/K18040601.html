Description

You need to re-enable the root account after disabling it and losing access to an administrator account

Environment

  • BIG-IP Console
  • Disabled root account

Cause

You may need to re-enable access to the root account under some device boot recovery scenarios

Recommended Actions

  1. Start the system in single-user mode
    K14658: Determining the GRUB bootloader version on the BIG-IP, BIG-IQ, or Enterprise Manager system
    K4178: Restarting the BIG-IP system in single-user mode (GRUB 0.97)
    K14662: Restarting the BIG-IP system in single-user mode (GRUB2)

    Note: Some attempts at booting to single-user mode result in a forced FSCK and a request for the password. Per K14662, you can skip the file system check by appending the words 'single fastboot' instead of 'single'. However, you cannot put fastboot after rd.break.
     
  2. After the system boots into single-user mode, the command prompt appears similar to the following example:
     switch_root:/#
     
  3. Verify the current mounting path for later reference by entering the following command:
    # mount | grep /dev/mapper/vg--db

    The output will appear similar to the following example:
    /dev/mapper/vg--db--vda-set.1.root on /sysroot type ext3 (ro,relatime,errors=continue,barrier=0,data=ordered)
    /dev/mapper/vg--db--vda-set.1._usr on /sysroot/usr type ext3 (ro,noatime,errors=continue,barrier=0,data=ordered)

    Note: On some BIG-IP platforms, you may observe sda instead of vda in the output. For example, /dev/mapper/vg--db--sda-set.2.root. On such platforms, you must replace vda with sda for the commands in the rest of the procedure
     
  4. Remount both the /sysroot and /sysroot/usr directories to read-write mode by entering the following commands:
    # mount -o remount,rw /sysroot
    # mount -o remount,rw /sysroot/usr
     
  5. Mount the appropriate /sysroot/config and /sysroot/var directories using the mounting path and volume set references retrieved from step 2, taking careful note of which set you need to mount.

    Example: If step 2 shows that you have set 2 (which means you booted into HD1.2) already mounted, then in this step you need to mount the set.2._config and set.2._var volumes. Similarly, if you boot to HD1.3, you already have set.3.root and set.3._usr mounted and mount set.3._config and set.3._var here. For example, to mount additional HD1.1 volumes, enter the following commands:
    # mount /dev/mapper/vg--db--vda-set.1._config /sysroot/config
    # mount /dev/mapper/vg--db--vda-set.1._var /sysroot/var
    You can now cd into /sysroot/config
     
  6. Modify the DB variable that disables the root account is stored in /sysroot/config/BigDB.dat
      # vi /sysroot/config/BigDB.dat
    Change the value of SystemAuth.DisableRootLogin to "false" and save the change
    -----
      [SystemAuth.DisableRootLogin]
      default=false
      type=enum
      realme=common
      enum=|true|false|
      scf_config=true
      display_name=SystemAuth.DisableRootLogin
      value=true        <====== Change this to false
    -----

    Note: If the 'vi' utility isn't recognized by the system, please enter the command `chroot /sysroot` and then retry step (6).

  7. Force mcpd to reload on startup and ensure that the DB variables are read from /config/BigDB.dat on startup
    # rm /sysroot/var/db/mcpd*  
    Note: If this does not remove any files, proceed to next step
    # vi /sysroot/var/service/mcpd/forceload
    Save and close file without content in it
    Esc + :wq!   
     
  8. Reboot
    # reboot
