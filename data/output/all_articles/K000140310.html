Description

GTM Pools offline after the Upgrade


Environment

-route domain

-gtm servers down

-iQuery issue

-GTM servers and pools are offline after upgrade

-upgrade from 17.1.0 to 17.1.1

-Error: Unable to identify which gtm server represents the local device


GTM server is defined as following:


gtm server /Common/F5 {

datacenter /Common/sample-pci

devices {

F51 {

addresses {

10.xxx.xxx.3 { }

}

}

F52 {

addresses {

10.xxx.xxx.4 { }

}

}

}


But 10.xxx.xxx.4 is not in RD0.


net self /Common/vlan-xx {

address 10.xxx.xxx.4%1/24 <---!!!!!!

allow-service {

default

}

traffic-group /Common/traffic-group-local-only

vlan /Common/vlan-xx

}



That's why you see following messages:

debug gtmd[16446]: 011a5010:7: Unable to identify which gtm server represents the local device

Cause

GTM is not route-domain aware, which means for iQuery used self, it has to be in RD0.

Recommended Actions

Correct the configuration of the self IP to use the default route domain 0
