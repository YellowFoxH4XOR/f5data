Known Issue

This is the result of a known issue. Installing BIG-IP version 10.1.0 on a 6900 or 8900 platform fails and corrupts the bootloader. This issue only occurs when BIG-IP version 10.1.0 is installed on a 6900 or 8900 platform using the image2disk utility supplied with the --format=partitions option.

When these conditions are met, the image2disk utility does not return any warning messages and begins the installation immediately. Once the installer has rebooted the BIG-IP system into the Maintenance Operating System (MOS), wiped all the mass-storage devices and begun copying files, the following error messages are displayed:

  • EUD files cannot be copied to the boot partition

    info: Updating system diagnostics.
    info: Best available EUD release is 12.5.0.428.0

    warning: boot entry st.eud does not exist

Even though the installer returns several error messages, it does not cancel the installation. Instead, it completes all its tasks and then incorrectly reports a successful installation.

Once the installation is completed, the BIG-IP system reboots. However, because GRUB was not fully installed, it will fail to start. Without a working bootloader the BIG-IP system cannot boot from its internal mass-storage devices.

At this stage, instead of loading GRUB, the BIG-IP system displays the Boot Action Menu shown below:

Note: The Boot Action Menu is an extension of the BIOS of the appliance, and it is displayed because the system failed to find a working bootloader on any of the internal mass-storage devices.

The BIG-IP system will remain in this inoperative state until it is re-imaged as described in the workaround section below.

This issue occurs because the installer creates a boot partition of approximately 81megabytes, which is not large enough to host all the required components.

F5 Product Development tracked this issue as CR135258, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, WebAccelerator, Link Controller, APM, WAN Optimization or Edge Gateway release notes.

Important: Even though BIG-IP version 10.2.0 can be installed on a 6900 or 8900 platform using the image2disk utility supplied with the --format=partitions option, a different issue may prevent you from installing BIG-IP version 9.4.x on a partition created by the 10.2.0 installation. For more information, refer to K11283: In certain cases, BIG-IP version 9.4.x will fail to install on a 6900 or 8900 platform.

Workaround

If you are planning to image a BIG-IP 6900 or 8900 system with version 10.1.0, consider using the volumes disk-formatting scheme. F5 recommends using the volumes disk-formatting scheme as it offers many advantages over the legacy partitions disk-formatting scheme. You only need to use the partitions disk-formatting scheme if you intend to run both BIG-IP version 9.x and 10.x on the same system. Additionally, beginning in BIG-IP version 10.1.0, 6900 and 8900 systems formatted with the volumes disk-formatting scheme benefit from hard drive mirroring. For more information about hard drive mirroring, refer to K10856: Overview of hard drive mirroring.

BIG-IP 6900 and 8900 systems that are imaged with version 10.1.0 using the volumes disk-formatting scheme will not experience the issue described in this Solution.

If you require using the partitions disk-formatting scheme, or if you have already encountered the issue described in this Solution and the BIG-IP system is now failing to boot, perform a clean installation of version 10.1.0. To do so, refer to K10819: Performing a clean installation of BIG-IP version 10.x.
