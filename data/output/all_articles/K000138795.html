K000138795: SSL_do_handshake() failed (SSL: error:1408F10B:SSL routines:ssl3_get_record:wrong version number)

Type
Support Solution
Published
2024-03-02
Updated
2024-03-02
Applies to
  • NGINX Products
  • NGINX Plus: R28
Source
https://my.f5.com/manage/s/article/K000138795

Description

  • You configured NGINX to proxy client requests to application server/s
  • Application server listen on port 80
  • Nginx is configured to initiate SSL handshake between itself and upstream before proxying the request
  • In the example below, Nginx proxy the request using proxy_pass directive to upstream backend. 
  • However, NGINX throws the below error, even though, the client requests matches configured the server_name and location
  • Subsequently, NGINX responds with 502 Bad Gateway error

2024/03/02 12:44:43 [info] 197888#197888: *2680 recv() failed (104: Connection reset by peer) while waiting for request, client: 10.10.1.2, server: 0.0.0.0:80
2024/03/02 12:44:43 [error] 197888#197888: *2678 peer closed connection in SSL handshake (104: Connection reset by peer) while SSL handshaking to upstream, client: 172.18.22.134, server: my.example.com, request: "GET / HTTP/1.1", upstream: "https: //192.168.1.2:5000/", host: "my.example.com"

Example Nginx conf
          upstream backend
                  {
                  server 192 .168.1.2:5000;
                  }

          server {
                  listen  443 ssl;
                  server_name my.example .com;

                  location / {
                          proxy_pass https://backend;
                            }
                    }

Environment

  • Nginx Plus
  • SSL

Cause

  • Nginx proxy pass directive is configured to connect with the upstream on port 443 (HTTPs), on the other hand, the server is listening on HTTP.
  • The upstream is unable to negotiate SSL handshake or SSL is not configured on the upstream.
  • SSL version mismatch between Upstream and proxy_pass directive

Recommended Actions

  • Configure Nginx to proxy pass over HTTP.
  • In the example above,
    • update the configuration with "proxy_pass http://backend;"
    • Alternatively, configure the necessary SSL parameters on the application server so that it can connect securely with Nginx.
