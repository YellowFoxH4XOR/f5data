K000132262: Big-IP can merge client's final ACK from TCP handshake and client's first data segment in certain scenarios when LRO is enabled

Description

Big-IP can merge the client's final ACK from the TCP handshake and the client's first data segment in certain scenarios when Large Receive Offload (LRO) is enabled on the Big-IP, before processing the combined segments as a single incoming segment.

Although this is allowed in the TCP protocol (client sending data along with the final ACK from the TCP handshake in a single TCP segment), some specific server implementations have been seen to reset the TCP connection when this occurs.

Environment

  • BIG-IP LTM
  • Large Receive Offload (LRO)

Cause

This is likely due to the LRO logic triggering on the Big-IP's NIC hardware when the 2 segments are received in very quick succession on the Big-IP from the client.

The end result is that capturing on the Big-IP's pcap layer via tcpdump shows only a single incoming TCP segment which combines the ACK and the first data segment from the client, and the Big-IP then proceeds to behave as if exactly that had happened during further processing.

Recommended Actions

If the server implementation cannot be changed to accommodate this behavior (since the TCP protocol allows this), then as a workaround, LRO can be disabled on the Big-IP entirely. 

To disable LRO globally on a Big-IP system, the following can be run from a bash shell:
 # tmsh modify sys db tm.tcplargereceiveoffload value disable

Additional Information

LRO is enabled by default since v12 on Big-IP VE, and v13.1 on all other Big-IP platforms.

There will be a very small performance hit on the Big-IP as a result of disabling LRO, although the actual performance hit may be too small to measure. 

Disabling LRO as a workaround is considered safe because prior to v12 on Big-IP VE and v13.1 on all other Big-IP platforms, LRO was disabled by default anyway. 

This issue does not have to do with the TSO (TCP Segmentation Offload) setting, and it is seen to occur even with TSO disabled on the Big-IP.
