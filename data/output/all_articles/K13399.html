Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP system to support multiple Key Distribution Centers (KDCs) for a Kerberos realm.

Description

The BIG-IP system supports Kerberos delegation based on the MIT Kerberos V5 specification. By configuring multiple KDC entries in the krb5.conf configuration file on the BIG-IP system, you can create a redundant environment for Kerberos authentication from the BIG-IP system. In the event a KDC is not accessible by the BIG-IP system, it will try each KDC for the realm defined in the krb5.conf file until an active KDC is located. The KDCs are accessed in the order they are listed in the krb5.conf file.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a Kerberos realm that contains multiple KDCs.
  • You are running a BIG-IP APM system that is configured to delegate to a Kerberos realm.
  • You have Advanced Shell (bash) access to the BIG-IP system.
  • You understand how to use a vi text editor.

Procedures

Configuring krb5.conf for multiple KDC entries

This procedure adds KDC entries that BIG-IP Kerberos can use for redundancy. You can use DNS names or IP addresses for the kdc entries. Before adding a KDC to the configuration file, ensure that the KDC is accessible from the BIG-IP system. The default port for Kerberos is 88, using UDP and TCP protocols. For more information on configuring the local hosts file, refer to the following articles:

  • K13206: Configuring local hostname resolution for BIG-IP (11.x)
  • K8439: Configuring local hostname resolution for BIG-IP (9.4.2 - 10.x)

Note: If the BIG-IP system has a high volume of Kerberos traffic, using DNS names may result in a large number of DNS requests and performance degradation. To optimize the load, you can use the IP address of the KDC, or place the KDC entries in the local hosts file on the BIG-IP system.

Impact of procedure: Incorrectly editing the krb5.conf file may prevent the Kerberos daemon from loading and cause the Kerberos authentication to fail. This change is not synchronized across clusters and may revert during upgrades or other maintenance operations.

  1. Log in to the BIG-IP command line interface.
  2. Using the vi text editor, open the /etc/krb5.conf file by typing the following command:

    vi /etc/krb5.conf

  3. Locate the realm to which you want to add additional KDCs. The following example locates the SAMPLE.ORG realm:

    [realms]
     SAMPLE.ORG= {
      admin_server =kdc1.sampledomain.org
      kdc = kdc1.sampledomain.org
     }

  4. Position the cursor before the } brace.
  5. Enable the vi insert mode by pressing the i key.
  6. Add the KDC entry after the last kdc entry in the realm definition formatted as kdc = <host> where <host> is the IP address or DNS name of the KDC.

    For example:

    [realms]
     SAMPLE.ORG= {
      admin_server =kdc1.sampledomain.org
     master_kdc = kdc1.sampledomain.org
      kdc = kdc1.sampledomain.org
      kdc = kdc2.sampledomain.org
      kdc = 10.1.1.1
     }

    Note:  To prevent the BIG-IP system from performing continuous DNS lookups for _kerberos-master._udp.<domain name> and getting a response that it does not exist because Active Directory does not create it by default, you can specify the master KDC with the master_kdc entry.

  7. Repeat step 6 for each addition KDC to use for authentication.
  8. Press the Esc key to exit the vi insert mode.
  9. Save the file and exit vi by typing the following command:

    :wq

  10. Press Enter.
