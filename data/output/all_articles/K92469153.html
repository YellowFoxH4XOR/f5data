Description

In some situations, you may have a BIG-IP VE that is not accessible through traditional access methods over the management or data networks, and data needs to be copied from the device for support purposes.
Using a linux virtual machine that supports LVM2 volumes in the same hypervisor environment, you should be able to mount the BIG-IP volumes on the linux virtual machine filesystem, so you can copy files off for F5 Support or make config changes to restore access. 

Environment

  • BIG-IP Virtual Edition on a hypervisor
Cause

None

Recommended Actions

  1. Power down the BIG-IP VE and linux virtual machine.
  2. Attach the virtual storage device from the BIG-IP VE to the linux virtual machine.
  3. Boot the linux virtual machine and log on with suitable privileges.
  4. Check that the BIG-IP disk and partitions are available on /dev ...
    /# ls -la /dev/sd*
    brw-rw---- 1 root disk 8,  0 Aug 10 22:48 /dev/sda
    brw-rw---- 1 root disk 8,  1 Aug 10 22:48 /dev/sda1
    brw-rw---- 1 root disk 8, 14 Aug 10 22:48 /dev/sda14
    brw-rw---- 1 root disk 8, 15 Aug 10 22:48 /dev/sda15
    brw-rw---- 1 root disk 8, 16 Aug 10 22:48 /dev/sdb        <=== bigip disk
    brw-rw---- 1 root disk 8, 17 Aug 10 22:48 /dev/sdb1        <=== bigip / volume
    brw-rw---- 1 root disk 8, 18 Aug 10 22:48 /dev/sdb2        <=== bigip /swap volume
    brw-rw---- 1 root disk 8, 19 Aug 10 22:48 /dev/sdb3        <=== bigip LVM LV2 volume

    Note that the disk identifier (/dev/sdb*) may be different for different systems. 
     
  5. Display the LVM volume information
    # lvdisplay
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/dat.maint.1
      LV Name                dat.maint.1
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/dat.share
      LV Name                dat.share
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/dat.appdata
      LV Name                dat.appdata
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/dat.log
      LV Name                dat.log
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/dat.swapvol
      LV Name                dat.swapvol
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/set.1.root
      LV Name                set.1.root
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/set.1._usr
      LV Name                set.1._usr
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/set.1._config
      LV Name                set.1._config
      VG Name                vg-db-vda
    ...
      --- Logical volume ---
      LV Path                /dev/vg-db-vda/set.1._var
      LV Name                set.1._var
      VG Name                vg-db-vda
    ...

    Note that this BIG-IP storage device has a single boot location labeled "1" (i.e HD1.1)
    There may be more boot location identifiers.
     
  6. Create file-system mount points for the BIG-IP volumes you need to access
    /# cd /mnt
    /mnt# mkdir bigip.1
    /mnt# mkdir bigip.1/var
    /mnt# mkdir bigip.1/config
    /mnt# mkdir bigip.1/shared
    /mnt# mkdir bigip.1/usr
     

  7. Mount the BIG-IP volumes in the following order ...

    mount /dev/vg-db-vda/set.1._config /mnt/bigip.1/config
mount /dev/vg-db-vda/set.1._var /mnt/bigip.1/var
mount /dev/vg-db-vda/dat.log /mnt/bigip.1/var/log
mount /dev/vg-db-vda/set.1._usr /mnt/bigip.1/usr
mount /dev/vg-db-vda/dat.share /mnt/bigip.1/shared
  8. Copy relevant data to the local linux virtual machine filesystem, or upload to Support

    cp /mnt/bigip.1/var/core/tmm* ~/support
     

  9. Unmount the file systems

    umount /mnt/bigip.1/config
    umount /mnt/bigip.1/var/log
    umount /mnt/bigip.1/var
    umount /mnt/bigip.1/usr
    umount /mnt/bigip.1/shared
     

  10. Power down the linux virtual machine, and detach the BIG-IP virtual storage device from the linux virtual machine configuration.
