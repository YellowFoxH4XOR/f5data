Topic

You should consider using these procedures under the following condition:

  • You want to configure the BIG-IP system to mirror SSL connections to peer device group members.

Description

In BIG-IP 12.0.0 and later, you can configure the system to mirror SSL connections that are terminated by the BIG-IP system to peer device group members. When you enable connection mirroring on a virtual server that references an SSL profile, the BIG-IP system mirrors SSL-specific data to the appropriate device group member. This preserves SSL connections when failover occurs.

Review the following table to determine whether the listed configuration options are supported for virtual servers configured to mirror SSL connections.

Configuration optionSupported
UDP profilesNo
Other L7 featuresNo
SSL profiles configured with the default certificate and keyNo
HTTP profiles13.x and later
Server SSL profiles13.x and later
L7 features in iRules13.x and later

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have access to the TMOS Shell (tmsh).
  • You have configured a virtual server that references a Client SSL profile.

Procedures

  • Enabling the statemirror.secure database variable
  • Disabling SSL session caching
  • Configuring connection mirroring for the virtual server
  • Viewing SSL mirroring statistics
  • Increasing the state mirroring queue length

Enabling the statemirror.secure and the statemirror.verify database variables

Before you enable connection mirroring for a virtual server that references an SSL profile, you must enable the statemirror.secure and the statemirror.verify database variables. To do so, perform the following procedure:

Impact of procedure: Enabling the statemirror.verify database variable may significantly decrease performance. The amount of performance impact depends on the specific environment. F5 strongly recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable the statemirror.secure database variable, enter the following command:

    modify /sys db statemirror.secure value enable

  3. To enable the statemirror.verify database  variable, enter the following command:

    modify /sys db statemirror.verify value enable

Disabling SSL session caching

Important: SSL connection details are included in the information that is mirrored when Connection Mirroring is enabled for the virtual server. For BIG-IP versions that are affected by Bug ID 760406, to avoid conflict of SSL information and the cached SSL information, SSL caching must be disabled in the SSL profile(s) that are applied to a virtual server. Disabling SSL session caching is not required for BIG-IP versions with the fix of ID 760406. For more information, refer to: Bug ID 760406: HA connection might stall on Active device when the SSL session cache becomes out-of-sync.

To disable SSL caching, perform one of the following procedures

  • Disabling SSL caching using the Configuration utility
  • Disabling SSL caching using the TMOS Shell

Disabling SSL session caching using the Configuration utility

  1. Go to Local Traffic > Profiles > SSL > Client (or Server).
  2. Select the appropriate SSL profile.
  3. For Configuration select Advanced.
  4. For Cache Size, enter 0.
  5. Select Update.

Disabling SSL session caching using the TMOS Shell

  1. Log in to tmsh.
  2. Disable the SSL session cache using the following command syntax:

    modify /ltm profile <profile_type> <profile_name> cache-size 0

    Note: Replace <profile_type> with the SSL profile type of the Client SSL profile or Server SSL profile, and replace <profile_name> with the SSL profile name.

    For example, to disable the SSL caching for the Client SSL profile with the name Example_ClientSSL, enter the following command:

    modify /ltm profile client-ssl Example_ClientSSL cache-size 0

  3. Save the change by entering the following command:

    save /sys config

Configuring connection mirroring for the virtual server

You can configure connection mirroring for the virtual server using the Configuration utility or tmsh. To do so, perform one of the following procedures:

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the appropriate virtual server.
  4. In the Configuration list, select Advanced.
  5. Select the Connection Mirroring check box.
  6. For SSL profile, confirm that the appropriate SSL profile is in the Selected list.
  7. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To configure connection mirroring for the virtual server, use the following command syntax:

    modify /ltm virtual <virtual_name> mirror enabled

    For example, the following command enables connection mirroring for the virtual server named SSL-virtual:

    modify /ltm virtual SSL-virtual mirror enabled

  3. Save the change by entering the following command:

    save /sys config

Viewing SSL mirroring statistics

You can use tmsh to view SSL connection mirroring statistics, such as connection mirroring handshake failures and timeouts. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view SSL profile statistics, including SSL connection mirroring statistics, use the following command syntax:

    show /ltm profile client-ssl <profile_name>

    For example, the following command displays SSL profile statistics, including SSL connection mirroring statistics, for the MyclientSSL profile:

    show /ltm profile client-ssl MyclientSSL

    The SSL mirroring statistics appear similar to the following example:

    ...
    SSL Mirroring
    Session mirror success 0
    Session mirror failure 0
    Connection mirror peer ready 1
    Connection mirror context sent 1
    Connection mirror context receive 1
    Connection mirror handshake success 1
    Connection mirror failure 0
    Connection mirror timeout 0
    ...

    Note: When Connection Mirroring is enabled for the SSL profile of the virtual server, the SSL session information for connections to the virtual server are mirrored to the configured peer devices, mirrored SSL session information does not increment the Session mirror success statistics.

Increasing the state mirroring queue length

Depending on your specific environment, if you experience state mirroring failures after you enable connection mirroring for an SSL virtual server, you may need to increase the state mirroring queue length. To do so, perform the following procedure:

Impact of procedure: Increasing the statemirror.queuelen database variable may significantly increase the amount of Traffic Management Microkernel (TMM) memory consumed. The amount of performance impact depends on the specific environment. F5 strongly recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To increase the state mirroring queue length by modifying the statemirror.queulen database variable, use the following command syntax:

    modify /sys db statemirror.queuelen value [enter integer value min:1048576 max:1073741824]

    For example, you can increase the statemirror.queuelen value to 256 MB by entering the following command:

    modify /sys db statemirror.queuelen value 268435456

    Note: The default value is 8 MB (8388608 bytes). F5 recommends keeping this value as low as possible and does not recommend increasing this value greater than 256 MB (268435456 bytes).
