Known Issue

Setting the BIG-IP WebAccelerator or BIG-IP AAM logging levels to debug may output excessive logging and cause the TMM to stop responding.

This issue occurs when the following conditions are met:

  • Any of the following db keys are set to debug:

      acceleration.log.level
      acceleration.wam_assembly.loglevel
      acceleration.wam_bigdb.loglevel
      acceleration.wam_cache.loglevel
      acceleration.wam_event.loglevel
      acceleration.wam_log.loglevel
      acceleration.wam_mstor.loglevel
      acceleration.wam_mtags.loglevel
      acceleration.wam_parse.loglevel
      acceleration.wam_plugin.loglevel
      acceleration.wam_proxy.loglevel

Note:  You should not modify the BIG-IP WebAccelerator or BIG-IP AAM debug db keys unless directed to do so by F5 Technical Support.

Impact

The BIG-IP system may temporarily fail to process traffic and failover if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • In the /var/log/wamd.log file, you may observe excessive logging, including messages such as the following example:

    http_process_state_parse_header - Invalid action EV_BODY_COMPLETE during ST_HTTP_PARSE_HEADERS (Client side: vip=/Common/<Virtual_Server> profile=http pool=/Common/<Pool_Name>client_ip=<IP_Address>).

  • The TMM process stops responding and produces a core file in the /var/core directory.
