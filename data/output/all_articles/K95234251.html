Description
The Source Port: Preserve setting does not preserve source port. You may notice this change after upgrading from a previous version impacted by Bug ID 726176.

For TCP and UDP traffic the source port changes. For ICMP traffic, the ICMP ID changes.

Environment

  • BIG-IP on one of the following platforms:
    • VE (depends on hypervisor settings)
    • 2000 series
    • 4000 series
    • i2000 series
    • i4000 series
  • After upgrade to versions where Bug ID 726176 has been fixed:
    Bug ID 726176: Platforms using RSS and xor_fold DAG hash reuse source port too rapidly when the FastL4 virtual server is set to source-port preserve
  • Source Port set to Preserve

Cause

The fix for Bug ID 726176 modifies the behavior of these platforms so that the Preserve setting always changes the source port. This reduces the frequency of reusing source ports.

Recommended Actions

  • If you require BIG-IP to preserve source ports, set Source Port on affected Virtual Servers to Preserve Strict.
  • See   Bug ID 890229: Source port preserve setting is not honored
  • This is issue is fixed in 
  • V16.0.0 and later
  • V15.1.1 and later
  • V14.1.2.8 and later
  • V13.1.3.5 and later

Additional Information

  • BIG-IP uses the ICMP ID field for disaggregation, similar to ports in TCP and UDP. Therefore it is always changed as well.
