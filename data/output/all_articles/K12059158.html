Description

Configsync failed with error message on the device received config:

Config sync fails with error "Load failed from /Common/peer_device_name 01070726:3: Virtual Server /partition_name/VIP_name in partition partition_name cannot be referenced by sflow http data source * in partition Common

The virtual server in the message does not have sflow enabled http profile, but default http profile.
 

Environment

  • BIG-IP
  • v15.x
  • Config sync
     

Cause

  • Default http profile's default values are modified.
     

Recommended Actions

  1. Check if the default http profile exists in /config/bigip.conf on the BIG-IP host from which config is synced.

    The object name line should be  
    ltm profile http /Common/http {
    NOTE: The default profile should not be in /config/bigip.conf unless it has been modified. F5 recommend not modifying default profiles.
     
  2. Check to see if the sflow stanza defaults have been modified 
    ltm profile http /Common/http {
     ...
     server-agent-name BigIP
     sflow {  
          poll-interval 0         <<<---- default 0
          poll-interval-global no <<<---- default yes : can be modified only on CLI
          sampling-rate 0         <<<---- default 0
          sampling-rate-global no <<<---- default yes: can be modified only on CLI
     }
     ...
}
  3. Create a new custom http profile, with same settings as the modified /Common/http profile. Then modify all the non-F5 supplied http profiles which use the default http profile as their parent profile (on the GUI or the CLI) to use this new profile, if they don't already explicitly include or override the modified settings of the modified default http profile. If inheriting from other F5 supplied http profiles you'll need to follow similar procedure for them.
     
  4. Remove the default /Common/http profile stanza from /config/bigip.conf and save with your choice of text editor utility on CLI. Alternatively it should be possible to remove custom overrides from the modified default http profile in the GUI, and update to save.
     
  5. Verify the modification does not cause a config load failure 
    tmsh load sys config verify
     
  6. If there is no error (warnings can be ignored), load the config to memory
    tmsh load sys config
     
  7. Then config sync to the peer device
    tmsh run cm config-sync to-group <device_group_name>
