Known Issue

The Session Initiation Protocol (SIP) monitor may erroneously mark resources down.

This issue occurs when the following condition is met:

  • The SIP monitor is configured to monitor an IPv4 pool member in a non-zero route domain.

When monitoring an IPv4 pool member in a non-zero route domain, the SIP monitor internally uses a proprietary F5 IPv6 address that is an encoded form of the IPv4 address and route domain. SIP monitor queries to pool members incorrectly use the proprietary F5 IPv6 address for the Options and To headers of the request.

Impact

This issue may interrupt SIP traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The SIP monitor erroneously marks down a node in a pool.
  • When debug logging is enabled for the SIP monitor, the /var/log/SIP*.logs debug log file contains an IPv6 address in the NODE_IP= field instead of the proper IPv4 address.
