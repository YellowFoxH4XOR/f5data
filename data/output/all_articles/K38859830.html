Description

When opening a case for Content Ingress Services (CIS), please provide the following information:

Environment

Using F5 CIS to manage BIGIPs

Cause

To collect and provide diagnostic data for CIS/BIG-IP issues.

Recommended Actions

1. Configuration files

  • CIS deployment yaml file, IPAM deployment yaml files ( if using),
  • app ingress/configmap yaml, (when using configmap)
  • Customer Resource Definition  yaml files,  (when using CRD) 
  • CIS administrator should know the Configuration file location. 
    • Note that there is no standard F5 enforced location for these files.

2. container logs
You can use one of the following method to get CIS container log
  • Find the pod, and dump the pod log to a file.
root@host# kubectl get pods -A |grep k8s-bigip
kube-system    k8s-bigip-ctlr-deployment-59c8dc8659-r7jkh   1/1     Running   0                2d19h
root@host:~# kubectl logs k8s-bigip-ctlr-deployment-59c8dc8659-r7jkh -n kube-system > /var/tmp/cis.log

Then upload  /var/tmp/cis.log
  • If customer knows Container log file location e.g, /var/log/containers/. they can also tar and upload the log file.
# sudo  tar -cvzf  ~/pod-logs.tar.gz /var/log/containers/
Note: make sure these are the actual files, instead of symbolic links.

3. To enable cis debug log, if asked by F5 support
  • In CIS deployment yaml file,
apiVersion: apps/v1
kind: Deployment
metadata:
  name: k8s-bigip-ctlr-deployment
  namespace: kube-system
spec:
# DO NOT INCREASE REPLICA COUNT
  replicas: 1
  selector:
    matchLabels:
      app: k8s-bigip-ctlr-deployment
~~~~
            args: [
              "--bigip-username=$(BIGIP_USERNAME)",
              "--bigip-password=$(BIGIP_PASSWORD)",
~~~~
              # Logging level
              "--log-level=DEBUG",                   ########
              "--log-as3-response=true",           ########
              
  • delete / recreate the cis pod.          


4.  Also collect a fresh qkview from the target BigIP.
