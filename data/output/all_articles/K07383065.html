Description

VIPRION system reports that the /var filesystem is highly utilized.

Troubleshooting efforts reveal there are files similar to the following using most of the disk space in the /var/ts/var/cluster/send directory:

[root@VIP4800:/S2-green-S::Active:Changes Pending] send # ls -lh 
total 793M
-rw-r--r--. 1 root root 396M Jun 17 11:02 sync_20200617_110127__slot_1__full_update
-rw-r--r--. 1 root root 396M Jun 17 12:02 sync_20200617_120115__slot_1__full_update

There may also be an additional files of similar size in the /var/ts/var/cluster/temp directory.

Environment

  • Disk space
  • ASM provisioned

Cause

The files under /var/ts/var/cluster/send and /var/ts/var/cluster/temp are related to security policy history files. These full_update files are used for cluster sync between the primary and secondary blades every hour, or any time a security policy is applied.

If there are a large amount of history files across many policies, these files can grow quite large.

Note: These files are not related to ConfigSync in any way.

Recommended Actions

Versions 15.1.x and higher:
By going to Security  ››  Options : Application Security : Advanced Configuration : System Variables :: policy_history_max_total_size that can be used to control the maximum size of all the history files, along with a minimum number kept. To determine the minimum number kept the variable policy_history_min_retained_versions is used.

Most commonly setting this 100000000 bytes (100MB) is a good starting point.

Note: policy_history_min_retained_versions is enforced only when policy_history_max_total_size is not 0.

Versions 14.1.x and older:
There is a configuration file under /etc/ts/tools/policy_history.cfg that can be used to control the maximum size of all the history files, along with a minimum number kept.

/etc/ts/tools/policy_history.cfg
================================
[CleanPolicyHistory]
# maxSizeOfSavedVersions=100000000  <------ Note this is commented out by default, which doesn't impose a size limit
minRetainedFilesInDir=2

The file can be accessed using a text editor such as VI or Nano. To do so...

#nano /etc/ts/tools/policy_history.cfg

By uncommenting the maxSizeOfSavedVersions variable, the size of these update files can be reduced significantly.

Regardless of version after this change is made restart ASM:

clsh tmsh restart sys service asm

Important: Traffic may be disrupted while ASM restarts if done on the Active BIG-IP as restarting ASM will cause a failover.

These db variables will sync, but the ASM restart will need to be done on all the BIG-IPs in the Device Group. Doing the Standby first then failing over to it would minimize any possible disruptions.

Additional Information

  • You will need to plan for a minimum of 500 MB being used under the cluster sync directories for normal operation. So ensure there aren't any other large files under /var. Otherwise, you'll have to decrease the value of the maxSizeOfSavedVersions variable further.
  • The files under /var/ts/var/cluster/send/ can also be present on a single-slot system. This is because, if blades are  added in the future, these files are ready to sync.
