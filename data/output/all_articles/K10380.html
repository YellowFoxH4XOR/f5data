Known Issue

This is the result of a known issue. The image2disk utility erroneously validates the target location when the --format option is specified. As a result, you can specify a target location that will not exist after the disks are reformatted, and the installation will fail.

When the image2disk utility is invoked with the --format option, the disks are reformatted and a default set of boot locations is created. The image2disk utility validates the target location (specified in the --instslot parameter) against the current list of boot locations, rather than the list of boot locations that will be created after the disks are reformatted. If you specify a target location that will no longer exist after the disk is reformatted, the installation will fail.

For example, in version 10.x, the default boot locations are HD1.1 and HD1.2 for most platforms. A BIG-IP system has been configured with three additional boot locations: HD1.3, HD1.4, and 1.5. If you specify HD1.5 as the target location by entering a command that appears similar to the following example, the installation will fail because only the HD1.1 and HD1.2 locations exist after the format is complete:

image2disk --instslot=HD1.5 --format=partitions --setdefault --reboot BIGIP-10.0.1.283.0.iso

F5 Product Development tracked this issue as ID 222799 (formerly CR124558) and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or WOM release notes.

Note: The HD1.3 boot location is also created on certain platforms when the volumes disk formatting scheme is used.

Note: Beginning in BIG-IP version 10.1.0, if the image2disk utility is invoked with the --format=volumes option on a 6900 or 8900 platform, mirrored volume sets are created exclusively: MD1.1, MD1.2 and MD1.3. For more information, refer to K10856: Overview of hard drive mirroring.

Workaround

When using the image2disk utility to reformat the drives and reimage the unit, specify either HD1.1 or HD1.2 as the installation location specified by the --instslot option.

If you have already encountered the issue described in this Solution and the BIG-IP system is now inoperative, perform a clean installation of BIG-IP version 10.x. To do so, refer to K10819: Performing a clean installation of BIG-IP version 10.x.
