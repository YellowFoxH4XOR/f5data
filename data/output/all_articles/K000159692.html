Description

Sensitive HTTP headers are inconsistently masked in access logs despite proper "Mask Sensitive Parameters in Logs" configuration in the WAF policy. 

    Environment

      • HTTP Load Balancer
      • Web Application Firewall (WAF)
      • Sensitive parameters
      • Service policy exception

    Cause

    Parameter masking in access logs is performed by the WAF policy. When a Service Policy is configured with "Skip App Firewall Processing" action, WAF is completely bypassed for matching requests. Since the WAF is not processing these requests, the masking functionality configured in the WAF policy is also skipped, resulting in sensitive parameters appearing unmasked in the logs.

    Recommended Actions

    Instead of using "Skip App Firewall Processing" in the Service Policy, use "App Firewall Detection Control" with exceptions for all signatures and violations. This approach allows the WAF to remain active for masking purposes while preventing blocking actions.
