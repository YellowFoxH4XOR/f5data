K2211: Using last hop pools to correctly return traffic to upstream redundant devices

Topic

By default, the BIG-IP system auto_lasthop global variable is enabled, which allows the BIG-IP system to return packets to the MAC address from which they were sent. This configuration is essential if the device that is sending packets is a firewall or a router, because return packets are generally only allowed through the firewall or router that handled the connection request. However, if the firewall or router is part of a redundant configuration that does not implement virtual MAC addresses, the auto_lasthop feature will not be able to locate an alternative MAC address if the active firewall or router fails over.

If the MAC address of the device that sends inbound traffic to the BIG-IP system changes (such as when redundant firewalls or routers failover), the BIG-IP system will continue to send return traffic to the old MAC address. Because the network device owning the old MAC address will no longer be accepting return traffic, this situation causes all existing long-lived connections to fail.

You can resolve this issue by configuring the BIG-IP virtual servers to use a last hop pool. This configuration will override the auto_lasthop variable. The pool selected for last hop contains the firewall or router addresses, which enables the BIG-IP system to select an alternative IP address and, therefore, a new MAC address in the event that one of the firewall devices fails. A last hop pool is also useful as a security feature because return packets sent through this virtual server are restricted to the last hop pool members.

Note: For specific last hop pool configuration instructions, refer to the BIG-IP manual for your version and K8290: The 'TM.LHPNoMemberAction' variable allows control over routing behavior when last hop pools are used.

Note: Prior to BIG-IP 10.2.0, when connection rebinding is required for stateful firewalls, the BIG-IP system can load balance only two firewalls per virtual server using last hop pools. In BIG-IP 10.2.0 and later, this limitation was removed. For more information, refer to K6140: Last hop pools are no longer limited to two members when used in a firewall sandwich configuration.

Note: If your upstream redundant devices use Virtual Router Redundancy Protocol (VRRP) or Hot Standby Router Protocol (HSRP), refer to K9487: BIG-IP support for neighboring VRRP/HSRP routers for more detailed network design suggestions.
