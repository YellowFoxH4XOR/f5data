Description

The Network Firewall can use IP Intelligence categories as matching criteria in Firewall rules. For example, you can set a firewall rule to drop traffic from hosts IP Intelligence has categorized as spam_sources. The _whitelist_ category is an exception and can't be selected as a source or destination in Network Firewall rules.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

The _whitelist_ category is used for hosts that have been allowlisted (whitelisted). IP Intelligence presumes traffic should be allowed from any host so designated, so if host information received by IP Intelligence indicates the host should be allowlisted, that host goes in the special _whitelist_ category and not any other category you may expect. For example, a feed list entry may look like the following:

10.12.27.252,,WL,Botnets

The entry says the host should be allowlisted, as indicated by the WL, but the list also specifies that the category is Botnets. In the case of anything with WL, the category is overruled, and the host is added to _whitelist_ .

The Network Firewall does not have any special handling for the _whitelist_ category. Traffic from entries on _whitelist_ are not automatically allowed by the Network Firewall. You cannot select _whitelist_ as a source or destination in a Network Firewall rule.

Environment

There are a couple of configuration issues you may encounter:

The first is you may mistakenly rely on a category assignment for a WL entry. WL entries always go on _whitelist_, and any category assignment is ignored.

The second issue is that category assignments are not made for categories unless those categories are used in an active IP Intelligence policy. For example, consider a feed list entry such as the following:

10.12.27.252,,BL,Botnets

This entry does not result in host 10.12.27.252 being added to category Botnets unless Botnets is referenced in an IP Intelligence policy that is assigned to a virtual server or to the Global Context.

If you want to use IP Intelligence categories in Network Firewall rules but don't want to use IP Intelligence enforcement, simply use an IP Intelligence Policy action of Allow for all categories you want and assign at the Global Context. Since an active IP Intelligence policy makes use of the category, you can assign hosts that are assigned to that category and will match Network Firewall rules using that category.

Cause

None

Recommended Actions

Think of WL entries as hosts that IP Intelligence should pass without further thought. BL entries are hosts to be sorted into categories, which will be handled by policy. If you are going to use IP Intelligence categories in Network Firewall rules, consider creating your own category for explicitly allowing traffic from known-good hosts rather than relying on the implicit behavior of the _whitelist_ category. That is, import hosts you would otherwise allowlist with WL as BL entries instead, and add them to a user-created category such as Good-Hosts. The IP Intelligence policy action for category Good-Hosts would be Allow. Network Firewall rules can make use of the Good-Hosts category.
