K000135219: Troubleshooting down peers in SDC

Type
Support Solution
Published
2023-06-25
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000135219

Description

  • Peer status can be determined in the GUI Topology > Site > Peers > Status. 
  • SDC can either connect to a server peer or client peer. It will act as the client for the server peer and the server for the client peer.

Environment

  • Traffix SDC 5.x
  • FEP
  • Diameter Peer

Cause

When a peer shows status is down, the issue could be caused by a number of reasons. One of the common reasons are network related, diameter client/server peer issue and an issue with the FEP that the peer connects to.

 

 Recommended Actions

  1. First is to determine which peer you see is down.
  2. Determine what changes was made to the SDC before you observed the issue, and try to revert the change to see if that fixes it.
  3. Confirm if its a client peer or server peer.
  4. Check if there is there are any activity on the server/client side. This could cause to make the client/server unreachable temporarily. Check if there were changes made on the server/client side as well and revert if needed.
  5. Determine which FEP this client or server connects to, then check the specific logs for any error or alarm showing for this peer in the FEP logs. FEP logs are in /opt/traffix/sdc-<ver>/logs/Site_FEP/
  6. Perform a tcpdump capture to check the communication between the FEP and the client/server. TCPdump should show that the CER message from client peer is reaching the SDC device or the CER message from SDC device is responded with a CEA from the server peer.
  7. Generate a TTA log if you need to escalate the case to F5 support after your initial investigation. Please make sure to share the initial findings, status and details for quicker resolution.
