Known Issue

Note: As the bigpipe utility is removed in BIG-IP 11.0.0, the issue described in this article does not apply to BIG-IP 11.0.0 and later.

This is the result of a known issue. The bigpipe vlan show command output displays the masquerade Media Access Control (MAC) address configured for VLANs as the true MAC address instead of the MAC address assigned to the VLAN.

Consider the following configuration example. The my-test-vlan VLAN is assigned with the 00:01:D7:B3:8D:83 MAC address and configured with the 40:01:D7:01:02:03 masquerade MAC address:

vlan my-test-vlan {
tag 4094
mac masq 40:01:D7:01:02:03
interfaces 1.1
}

The bigpipe vlan my-test-vlan show command will display the 40:01:D7:01:02:03 masquerade MAC address as the true MAC address instead of the my-test-vlan VLAN configured with the 00:01:D7:B3:8D:83 MAC address:

VLAN my-test-vlan tag 4094 00:01:D7:B3:8D:83 (true: 40:01:D7:01:02:03) MTU 1500
+-> VLAN MEMBER my-test-vlan/1.1 untagged
+-> INTERFACE 1.1 00:01:D7:B3:8D:84 ENABLED up MTU 1500
| media auto (1000baseT full) aggregation: detached
| flow control tx rx (none)
| (pkts,bits,errs) in = (135521, 101.9M, 0), out = (4, 2880, 0)
| (drop,mcast) in = (135507, 133727), out = (0, 4) coll = 0

Note: This issue is cosmetic and does not affect the operational status of the BIG-IP system.

F5 Product Development is tracking this issue as ID 331690 (formerly CR133329) and ID 249361 (formerly CR133329-1).
