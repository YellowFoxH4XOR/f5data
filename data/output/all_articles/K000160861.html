Description

Accessing a SAML-authenticated website through a BIG-IP SSL Orchestrator (SSLO) deployment with Secure Web Gateway (SWG) in the service chain results in a failure to load the site. The browser displays a “page unable to load” error with “Err Connection Reset.” The issue is specific to the affected URL and does not occur when SWG is removed from the service chain or the traffic is bypassed.

Environment

  • Product: BIG-IP SSL Orchestrator
  • Version: 17.5.1, 21.x
  • SSLO Topology: Explicit Proxy
  • Service Chain: Includes Secure Web Gateway (SWG)
  • Security Policy: “All Traffic” rule applied
  • Target URL: SAML-authenticated
  • SAML IdP Domain: SAML authentication provider domain
  • The issue occurs only when SWG is present in the service chain

Cause

The issue is caused by a conflict between SWG’s per-session policy evaluation and the SAML authentication flow. When SWG is in the service chain, it injects a redirect to /vdesk/policy_done.php3 as part of its policy evaluation, which interferes with the SAML Service Provider’s redirect chain and prevents the authentication flow from completing. SSL interception and certificate re-signing can also disrupt SAML flows if the IdP or SP uses certificate pinning or strict session validation.

Answer/Recommended Actions

To resolve the issue:

  1. Bypass SSL Interception for SAML Domains:
    • Configure an SSL Bypass rule in the SSLO Security Policy for both the SAML Service Provider and its associated SAML IdP domain.
    • Use a Custom URL Category to group these domains for easier policy management.
  2. If SSL Interception Is Required:
    • Consider increasing the per-request policy timeout.
    • Review and tune SWG policy actions.
    • Note: Some SAML flows may not work with SSL interception due to certificate pinning or strict session validation.
  3. Professional Services:
    • For complex environments or if SSL interception is mandatory, consult F5 Professional Services for advanced policy tuning.

Additional Information

  • The issue is specific to SAML-authenticated sites when SWG is present in the service chain.
  • Without SWG, SSLO intercepts and re-signs the certificate, but the SAML authentication completes normally.
  • With SWG, the injected redirect collides with the SAML redirect chain, causing the failure.
