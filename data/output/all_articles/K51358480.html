Known Issue

The single Network Interface Card (NIC) BIG-IP Virtual Edition (VE) may erroneously revert to the default management httpd port after you reload the configuration.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP VE system version listed in the Applies to (see versions) box, located in the upper-right corner of this article.
  • You run the BIG-IP VE system in a single-NIC configuration with the default management httpd port (port 8443) configured.

    Note: Beginning in BIG-IP 13.0.0, the single-NIC BIG-IP VE system by default listens on TCP port 8443 for management (Configuration utility) traffic. For more information, refer to K31003634: The Configuration utility of the Single-NIC BIG-IP Virtual Edition now defaults to TCP port 8443.

  • You change the BIG-IP VE system configuration to listen for management traffic on TCP port 443 by typing the following command:

    tmsh modify /sys httpd ssl-port 443

    Important: This change takes effect immediately and interrupts management traffic using the default TCP port 8443. After this change, you have to reconnect to the Configuration utility using port 443.

  • You save the configuration and then reload it. For example, you restart the system.

Impact

The BIG-IP VE system fails to connect to the Configuration utility.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After you reload the configuration, the system fails to connect to the Configuration utility using TCP port 443.
  • You notice that the management httpd port is set to TCP port 8443. For example, you use the tmsh list /sys httpd ssl-port command and the system returns output that appears similar to the following example:

    sys httpd {
    ssl-port 8443
    }

  • You notice a message in the /var/log/kern.log file that appears similar to the following example:

    notice kernel: [ 4606.995936] [built:16:57:16][unic] handle_ioctl(856): UNIC: updated the httpd ssl-port to 8443

Resolution

Status

F5 Product Development has assigned ID 657459 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, after each time you reload the configuration, you can reconfigure the BIG-IP system to listen on TCP port 443 for management traffic. To do so, perform the following procedure:

Impact of workaround: Reconfiguring the management httpd port to TCP port 443 interrupts management traffic using TCP port 8443. To reconnect to the Configuration utility, enter the IP address of the BIG-IP system into your browser's address bar without specifying any port number. For example, https://<ip-address>.

  1. Log in to command line of the BIG-IP system.
  2. To reconfigure the BIG-IP system to listen on TCP port 443 for management traffic, type the following command:

    tmsh modify /sys httpd ssl-port 443

  3. To save the changes, type the following command:

    tmsh save /sys config
