K000133419: Wide IP's are not written to all views on disk

Type
Knowledge
Published
2023-04-06
Updated
2025-02-07
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP DNS
  • BIG-IP GTM
  • BIG-IP Link Controller
Source
https://my.f5.com/manage/s/article/K000133419

Description

Wide IPs are automatically created and flushed to the bind zone files on disk. Occasionally you may notice that not all of your views contain the A records for your Wide IPs.

For example, If there are multiple views configured in bind one view might have that A record from the Wide IP and the other view might not have any records.


Environment

  • Multiple view configuration within bind
  • Wide IPs in use


Cause

This happens because Wide IPs are only written to one view and they will not automatically write to both. The view that is written to will be the view that shows up closest to the top of the /var/named/config/named.conf file. 
Note: With large zones writing to disk may take up to 30 minutes.

Configuring views in bind assumes that the bind response may vary depending on where the client is located. For example internal clients might be using a VPN and bind responds with internal IPs for DNS requests but external clients not using a VPN can receive a publicly routable IP address in response.

Assuming both views in bind should have the same IP address and writing to both views automatically would likely be in error.

 

Recommended Actions

Configure the named.conf file such that Wide IPs write to the expected view and manually update any other views as needed.
