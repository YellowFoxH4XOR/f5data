Known Issue

SSL session ID reuse may fail if the Client SSL profile name is 32 characters or more.

Note: The 32-character limit includes the profile name and the characters that comprise the folder path (partition and folder). For example, the following profile name is 34 characters in length: /Common/client-ssl-profile-test123.

The BIG-IP SSL session cache allows clients to reuse SSL session ID information from previously negotiated SSL sessions. SSL session resumption increases performance by limiting processor-intensive SSL key exchange functions.

Impact

A full SSL handshake is executed rather than an optimized handshake.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • SSL session IDs are not reused appropriately.
  • New SSL session IDs are being presented during the SSL handshake, while the previous session ID is still valid.

Workaround

To work around this issue, you can recreate the Client SSL profile using a name that contains less than 32 characters (when combined with the folder path), and then re-associate the new Client SSL profile with the virtual server. To do so, perform the following procedure:

Impact of workaround: Re-associating the new Client SSL profile with a virtual server may affect current connections. F5 recommends that you perform this procedure during a scheduled maintenance window.

Recreating and re-associating the Client SSL profile

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. List the properties of the affected Client SSL profile by using the following command syntax:

    list ltm profile client-ssl <profile-name>

    For example:

    list ltm profile client-ssl client-ssl-profile-test123

    Output appears similar to the following example:

    ltm profile client-ssl client-ssl-profile-test123 {
    app-service none
    defaults-from clientssl
    }

  3. Copy and paste the Client SSL profile output to a plain text editor.
  4. In the text editor, change the profile name so that the folder path and profile name contain less than 32 characters.
  5. Copy the newly edited profile configuration from the text editor.
  6. Merge the new Client SSL profile with the BIG-IP configuration by typing the following command:

    load sys config merge from-terminal

    For example:

    load sys config merge from-terminal

    Output appears similar to the following example:

    Enter configuration. Press CTRL-D to submit or CTRL-C to cancel.
    ltm profile client-ssl client-ssl-profile {
    app-service none
    defaults-from clientssl
    }
    Loading configuration...

  7. Replace the affected Client SSL profile on the appropriate virtual server with the new Client SSL profile by using the following command syntax:

    modify ltm virtual <virtual-server-name> profiles add { new-profile-name } profiles delete { old-profile-name }

    For example:

    modify ltm virtual https-vs profiles add { client-ssl-profile } profiles delete { client-ssl-profile-test-34 }
  8. Save the change by typing the following command:

    save /sys config
