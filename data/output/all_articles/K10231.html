K10231: NTLM authentication fails if the Content-Length header is missing from 401 Unauthorized responses

Known Issue

This is the result of a known issue. If the origin web server responds to a client request with HTTP 401 (Unauthorized) but does not include a Content-Length header in the response, the BIG-IP WebAccelerator does not pass the response to the client. As a result, NTLM authentication fails.

Note: The HTTP 401 (Unauthorized) response indicates that the request requires authentication, and is the precipitating event for NTLM authentication transactions.

For example, SAP servers send HTTP 401 (Unauthorized) responses without including the expected Content-Length header. When the BIG-IP WebAccelerator is deployed in front of SAP, clients never see the HTTP 401 (Unauthorized) response and the SAP login dialog box is never displayed. As a result, no clients can log in to SAP.

F5 Networks Product Development tracked this issue as CR115080, and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Workaround

You can work around this issue by modifying the _sys_WA_serverside iRule to insert an appropriate Content-Length header into HTTP 401 (Unauthorized) responses that do not contain them. To do so, perform the following procedure:

Important: The following procedure will interrupt traffic flowing through the BIG-IP WebAccelerator for a few seconds.

  1. Log in to the BIG-IP command line.
     
  2. Open the /config/profile_base.conf in a text editor.
     
  3. Locate the _sys_WA_serverside iRule, which begins around line 1490 with the following line:

    rule _sys_WA_serverside {
  4. Modify the iRule to match the following example. To do so, insert the lines in bold:

    rule _sys_WA_serverside {
    ...
      when HTTP_RESPONSE {
        if {$tmm_wa_no_detach == 1} {
          # Don't detach or disable if NTLM authorization
          ONECONNECT::detach disable
          ONECONNECT::reuse disable
        } else {
          if {[HTTP::status] == 401} {
            # Force non-NTLM 401s to detach, due to WA connpool behavior
            ONECONNECT::detach enable
            if {not [HTTP::header exists "Content-Length"]} {
               HTTP::collect 10000000
            }
          }
          if {$tmm_wa_oc == 0} {
            # Don't return connections to the connpool
            ONECONNECT::reuse disable
          }
        }
      }

      when HTTP_RESPONSE_DATA {
        HTTP::header insert "Content-Length" [HTTP::payload length] 
      }

      when SERVER_CONNECTED {
    ...
  5. Exit and save the file.
     
  6. Load the new configuration by typing the following command:

    bigpipe load
     
  7. Clear the cache and restart the BIG-IP WebAccelerator by typing the following command:

    wa_clear_cache
