Known Issue

The BIG-IP system configuration may fail to load after you upgrade to BIG-IP 13.1.0 from a prior release when a you have a custom Session Initiation Protocol (SIP) or FirePass monitor configured.

This issue occurs when all of the following conditions are met:

  • You attempt to upgrade the system from a prior release to BIG-IP 13.1.0.
  • Your configuration contains a custom SIP or FirePass monitor.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The configuration fails to load after you upgrade the system.
  • You notice an error message similar to one of the following examples in the /var/log/ltm file:
    • If the BIG-IP system has only a Common partition, the initial configuration load succeeds but the configuration file is corrupted and subsequent attempts to load the configuration fail and the system logs an error with the following syntax:

      Syntax Error:(/config/bigip.conf at line: <line_number>) "user-defined" unknown property.

    • If the BIG-IP system has partitions in addition to the Common partition, the initial configuration load fails and the system logs an error with the following syntax:

      01070726:3: monitor /Common/<monitor_name> in partition Common cannot reference SSL profile monitor parameter /Common/<monitor_name> 1 SSL_PROFILE_NAME= in partition <non_Common partition_name>.

Workaround

To work around this issue, you can delete any custom SIP or FirePass monitors before the upgrade. After the upgrade, you can then re-create them manually. To do so, perform the following procedures:

  • Disassociating the monitor from any affected pools
  • Disassociating the monitor from any affected nodes
  • Deleting the custom SIP or FirePass monitor

Disassociating the monitor from any affected pools

If pools are using the monitor, you need to disassociate the monitor from the affected pools before you delete it.

Impact of workaround: Performing this procedure affects the incoming traffic to the virtual servers with pools that are using the affected monitors. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools.
  3. Note the names of all the affected pools using the monitor. You must re-associate them with the monitor after you upgrade the system.
  4. Click the name of the affected pool.
  5. For Health Monitors, in the Active box, click the name of the monitor you want to dissociate from the pool and move it to the Available box.
  6. Click Update.
  7. Repeat steps 4 through 6 for other affected pools.

Disassociating the monitor from any affected nodes

If nodes are using the monitor, you need to disassociate the monitor from the affected nodes before you delete it.

Impact of workaround: Performing this procedure affects the incoming traffic to the virtual servers with nodes that are using the affected monitors. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Nodes.
  3. Note the names of all the affected nodes using the monitor. You must re-associate them with the monitor after you upgrade the system.
  4. Click the name of the affected node.
  5. Under Configuration for Select Monitors, in the Active box, click the name of the monitor you want to dissociate from the pool and move it to the Available box.

    Note: Select Monitors is visible only if you set Health Monitors to Node Specific when you configured the monitor.

  6. Click Update.
  7. Repeat steps 4 through 6 for other affected nodes.

Deleting the custom SIP or FirePass monitor

After you disassociate the SIP or FirePass monitor from all pools and nodes, you can delete it.

Impact of workaround: Because the monitor is no longer associated to any pools and nodes, performing this procedure should not have any impact on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Monitors.
  3. Click the name of the monitor you want to remove.
  4. Note the monitor settings on the Properties tab because you must re-create the monitor after you upgrade the system.
  5. Click Delete.

After you have dissociated the monitor from affected pools and nodes and deleted it, you can upgrade the system. After you upgrade, use the information you noted in the previous procedures to recreate the monitor and re-associate it with the pools and nodes.
