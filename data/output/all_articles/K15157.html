Known Issue

Special characters may cause signed Security Assertion Markup Language (SAML) assertion to fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured as a SAML Identity Provider (IdP).
  • The BIG-IP APM IdP configuration contains any of the following special XML characters:

    • & ampersand
    • < less-than
    • > greater-than
    • " double quote
    • ' single quote

When you use any of these special characters in the BIG-IP APM IdP configuration, signed SAML assertions may be generated incorrectly or may fail to generate altogether.

Impact

SAML AuthnRequest and Assertion generation fails or is malformed.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • SSO logins fail when passwords contain special characters.
  • SAML SSO authentication fails.
  • SAML resources are inaccessible.
  • Messages appear in the /var/log/apm file similar to the following example:

    tmm0 err tmm0: 014d0002:3: 4c7897c8: SSOv2 Error creating signed SAML Assertion - canonicalization failed
    tmm0 err tmm0: 014d0002:3: 4c7897c8: SSOv2 Error(12) Creating Signed SAML Assertion
    tmm0 err tmm0: 014d0002:3: SSOv2 plugin error(12) in sso/sso.c:427

Workaround

To work around this issue, you can replace the offending characters with their entity references in the following table:

CharacterEntity ReferenceDescription
&&amp;ampersand
<&lt;less-than
>&gt;greater-than
"&quot;double quote
'&apos;single quote

For example, the Assertion Consumer Service URL in the External SP Connector is configured with the following URL:

https://www.company.com/saml/login?user=saml&password=passwd

You can change the previous URL to appear as follows:

https://www.company.com/saml/login?user=saml&amp;password=passwd
