Known Issue

Description

The iptables policy that is applied to non-default route domains may cause packet drops.

This issue occurs when the following condition is met:

  • A large amount of connections originates from the non-default route domain.

The BIG-IP system applies an iptables policy to all route domain objects. The system uses a policy for the default route domain (route domain 0) in which the connection tracking method is disabled. However, the BIG-IP system uses a policy for non-default route domains in which connection tracking is enabled. As a result, when a large amount of connections originates from the non-default route domain, the connection table may reach the maximum number of allowed connections, causing packet drops.

Impact

Monitor requests or other traffic originating from a non-default route domain may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H486702 on the Diagnostics > Identified > High screen.
  • The BIG-IP system logs error messages to the /var/log/kern file that appear similar to the following example:

    warning kernel: nf_conntrack: table full, dropping packet.

  • Monitor requests from non-default route domains may fail.

Workaround

To work around this issue, you can disable connection tracking for non-default route domains. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line.
  2. To disable connection tracking, use the following command syntax:

    rdexec <rdid> iptables -t raw -A PREROUTING -i ! eth0 -j NOTRACK

    rdexec <rdid> iptables -t raw -A OUTPUT -o ! eth0 -j NOTRACK

    For example, to disable connection tracking for a non-default route domain ID 1, type the following commands:

    rdexec 1 iptables -t raw -A PREROUTING -i ! eth0 -j NOTRACK

    rdexec 1 iptables -t raw -A OUTPUT -o ! eth0 -j NOTRACK

  3. Repeat the commands from step 2 for each non-default route domain on the system.
  4. The commands in previous steps do not persist across reboot. However, you can automatically run these commands after each reboot by performing the procedure described in K14397: Running a command or custom script based on a syslog message and inserting these commands in the /config/user_alert.conf file. The system will run these commands when it detects the Received links up - monitoring starts syslog message.

    Using the previous example in step 2, the commands appear similar to the following example:

    alert rd_notrack "Received links up - monitoring starts" {
    exec command="/usr/bin/rdexec 1 iptables -t raw -A PREROUTING -i ! eth0 -j NOTRACK";
    exec command="/usr/bin/rdexec 1 iptables -t raw -A OUTPUT -o ! eth0 -j NOTRACK";
    exec command="logger -p local0.notice Route Domain monitor tracking fixup for ID448787 done via user_base.conf edit";
    }
