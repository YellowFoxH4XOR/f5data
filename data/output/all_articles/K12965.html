Topic

Perform this procedure under the following conditions:

  • You want BIG-IP APM to use the origin web server to authenticate each user's credentials using an HTML form.
  • You want BIG-IP APM to inspect the cookie generated by the origin web server for a specific value.

Description

Some organizations may want to have a web server perform user authentication and then set a cookie specific value if the authentication was successful. BIG-IP APM is able to prompt the users for their credentials, pass those credentials back to the web server, and then inspect the response from the web server to see if the cookie is set to the expected value. If the expected cookie is present, BIG-IP APM identifies that the user is authorized to use the system and access is granted.

Prerequisites

To perform this procedure, you must meet the following prerequisites:

  • The web server is configured to authenticate users.
  • The web server is configured to set a cookie if the user is authenticated.

Procedures

Configuring HTTP form-based authentication using cookie matching

To configure HTTP form-based authentication using cookie matching, perform the following three procedures:

  • Creating the HTTP AAA server
  • Creating the access profile
  • Applying the access profile to your virtual server

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Creating the HTTP AAA server

  1. On the navigation pane, go to the following location:
    • BIG-IP 13.0.0 and later:

      Navigate to Access > Authentication > HTTP

    • BIG-IP 12.1.2 and earlier:

      Navigate to Access Policy, AAA servers and click the  HTTP tab.

  2. Click Create.
  3. Type a name for your server.
  4. For Authentication Type, click Form Based.
  5.  Optionally, specify a Start URI.
  6. Specify the HTTP Form method configured on the webserver.
  7. In the Form Action field, enter the complete URL that sets the cookie value. Make sure to include the protocol, server and port.

    For example:

    http://10.10.10.10/cookie.php

    Note: If your configuration requires that you use HTTPS, you will need to configure a layered virtual server that listens on the server IP address and port (80), uses a Server SSL profile, and has a pool with your HTTPS AAA server as a pool member.

  8. In the Number of Redirects to Follow box, type the number 1.

    Note: If your configuration requires more than one redirect, change this number accordingly.

  9. From the Successful Logon Detection Match Type list, click By presence of Specified Cookie.
  10. For Successful Logon Detection Match Value, enter the value of the cookie that is expected.
  11. Click Finished.

Creating the access profile

  1. Navigate to Access Policy > Access Profiles.
  2. Click Create.
  3. Enter a name for your access profile.
  4. Click Finished.
  5. Click Edit for the access profile you just created.
  6. Click the (+) icon after the Start box.
  7. Under General Properties, click Logon Page.
  8. Click Add Item.
  9. Review the pre-populated information for the logon page and make any needed changes.
  10. Click Save.
  11. Click the (+) icon after the Logon Page action.
  12. Under Authentication, click HTTP Auth.
  13. Click Add Item.
  14. In the list, click the AAA server you created.
  15. Click Save.
  16. Click the ending action box of the Successful branch (it is set to Deny by default).
  17. Click Allow.
  18. Click Save.
  19. Click Close.
  20. Select the check box for the access profile you just created.
  21. Click Apply Access Policy.

Applying the access profile to your virtual server

  1. Navigate to Local Traffic > Virtual Servers.
  2. Click the virtual server for which you want to use HTTP authentication.
  3. Under Access Policy, click your newly created access profile.
  4. Click Update.
