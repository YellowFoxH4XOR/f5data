Description

  • AS3 RPM installation fails or times out.
  • /var/log/restjavad.0.log shows:
    • WARNING: "Command execution process killed"
    • IappRpmSpecFileCreatorWorker.js onDelete failed with exception: Error: ENOENT: no such file or directory, unlink ...
    • RestOperation failed: ... ENOENT: no such file or directory, unlink '/var/config/rest/node/tmp/<UUID>.spec'
  • The installation process logs show the spec file is created, then cleanup begins, and the process is killed before completion.
  • The sys db variable iapplxrpm.timeout is set to the default (60 seconds).

Environment

  • BIG-IP (various platforms and versions, including 17.x)
  • AS3 (f5-appsvcs) RPM installation or upgrade

Cause

The AS3 RPM build process can take longer than the default timeout (60 seconds), especially on systems with limited resources or large configurations. If the build process exceeds this timeout, the system forcibly kills the process, resulting in incomplete installation and ENOENT (file not found) errors during cleanup. This is tracked under Bug ID 985329 and Bug ID 929213.

Solution / Workaround

Increase the iapplxrpm.timeout value and retry the installation:

  1. Increase the timeout:

    tmsh modify sys db iapplxrpm.timeout value 300
tmsh restart sys service restjavad
    • The value can be set up to 600 if needed. 300 seconds is usually sufficient.
    • Restarting restjavad is not traffic impacting.

  2. Remove any incomplete/corrupted AS3 RPM and spec files:

    • Delete the AS3 RPM from iApps > Package Management LX (GUI) or via CLI.
    • Remove any .spec files from /var/config/rest/node/tmp/: 
      rm /var/config/rest/node/tmp/*.spec
    • Remove any files in /var/config/rest/iapps/RPMS/ and /var/config/rest/iapps/RPMS.save/ if present.

  3. Re-download the AS3 RPM and verify its integrity (optional but recommended):

    • Use sha256sum to verify the RPM file matches the published checksum.

  4. Reinstall the AS3 RPM:

    • Use the GUI or CLI to upload and install the RPM.

  5. Verify installation:

    • Confirm that the AS3 package appears in iApps > Package Management LX and that REST API queries to /mgmt/shared/appsvcs/info return the expected version.

  6. If the issue persists, collect a new Qkview and review logs for further errors.

Additional Notes

  • If you see repeated ENOENT errors for spec files, it means the build process was killed before the spec file could be cleaned up.
  • This issue can also impact UCS backups and other iAppLX package operations.
