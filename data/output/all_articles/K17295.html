Known Issue

iControl REST queries for data-group objects may incorrectly return partition and subPath data.

This issue occurs when the following condition is met:

  • The BIG-IP configuration contains data-group string records that begin with the forward slash (/) character.

    For example:

    ltm data-group internal /Common/testing {
    records {
       /first {
          data test1
       }
       /first/second {
          data test2
       }
       /first/second/third {
          data test3
       }
    }
    type string
}

Impact

REST query results may incorrectly separate an object name into separate partition, subPath, and name objects.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • REST query results vary, depending on the format of the string record. The number of forward slash (/) characters in the string record will cause either the partition, subPath, or both elements to be present.

    For example, take the following configuration:

    records {
    /first {
       data test1
    }
    /first/second {
       data test2
    }
    /first/second/third {
       data test3
    }
    /first/second/third/forth {
       data test4
    }
       normal/string {
       data "normal behavior"
    }
}

    Based on the previous configuration, the REST query result contains the following output:

    "records": [
  {
    "name": "first",
    "subPath": "/",
    "data": "test1"
  },
  {
    "name": "second",
    "partition": "first",
    "data": "test2"
  },
  {
    "name": "third",
    "partition": "first",
    "subPath": "second",
    "data": "test3"
  },
  {
    "name": "forth",
    "partition": "first",
    "subPath": "second/third",
    "data": "test4"
  },
  {
    "name": "normal/string",
    "data": "normal behavior"
  }

    The last data-group string record called "normal/string" contains a forward slash (/) character, but does not begin with the character, so the object is displayed correctly.

    Important: The partition and subPath objects were never intended to be presented; therefore, when writing custom scripts, the scripts should not rely on those objects.
