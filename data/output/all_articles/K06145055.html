Description

Users of Skybox Security vendor with BIG-IP have reported /var partition filling up on BIG-IP.
Large temp files are left behind in /var/system/tmp/tmsh/
This occurs when the tmsh/ssh session is terminated abruptly before a command has had time to complete.
This commonly occurs when the Skybox client is running tmsh save /sys config file bigip.conf no-passphrase on BIG-IP
Temporary files are left behind and must be manually removed to free up disk space:

# du -sh /var/system/tmp/tmsh/*
12K     2Jmvm4
624K    3V0s9c
12K     5wkieR
346M    Lhuj82
12K     MAIsE0
12K     Nm3BlQ
12K     o0QNl9
345M    yxIN7v

Environment

  • BIG-IP
  • Large config
  • Skybox user is running tmsh save /sys config file bigip.conf no-passphrase
  • /var/system/tmp/tmsh filling up

Cause

Temp files are left behind if tmsh/ssh session is terminated before a command has successfully completed.

Recommended Actions

The client should wait for the command to finish executing on BIG-IP before closing the tmsh/ssh session:
  1. Identify the time it takes to complete a command using the time command:
    time tmsh save /sys config file bigip.conf no-passphrase
  2. Increase the save_config_timeout on Skybox so that exceeds the time it takes to complete the command.
  3. Remove the temp files:
    rm -rf /var/system/tmp/tmsh/*

Additional Information

Other log messages may be logged in /var/log/ltm that indicate /var is full, however the root cause is not related to the process (postgres) logging the warning:

warning postgres[5178]: [5-1] ERROR:  could not extend file "base/16384/12685": No space left on device
warning postgres[5178]: [5-2] HINT:  Check free disk space.
info postgres[17952]: [644-1] LOG:  could not close temporary statistics file "pg_stat_tmp/db_0.tmp": No space left on device
