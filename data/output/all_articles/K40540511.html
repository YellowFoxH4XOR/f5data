K40540511: Issue with master election process in AWS autoscale template

Type
Support Solution
Published
2020-08-07
Updated
2025-02-06
Status
Legacy Content
Applies to
  • Public Cloud
  • BIG-IP
  • BIG-IP Cloud Edition
  • Amazon Web Services
Source
https://my.f5.com/manage/s/article/K40540511

Description

  • If one working node remains in autoscale cluster, this node not always takes over master role.
  • AWS Autoscaling process is destructive when master is unavailable

Environment

  • BIG-IP VE on AWS
  • F5 AWS cloudformation autoscale template v5.5.0

Cause

Seen behavior is caused by a known issue tracked with the Bug ID 916605

Recommended Actions

Use latest AWS autoscale template

AWS autoscale template release 5.7.0 (https://github.com/F5Networks/f5-aws-cloudformation/tree/v5.7.0/supported/autoscale/waf/via-lb/1nic/existing-stack/bigiq) downloads and installs f5-cloud-libs v4.21.0 (with updated workflow used for electing primary host in autoscale solution).

Additional Information

None.
