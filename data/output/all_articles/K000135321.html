K000135321: Changes to sys db variable on primary blade does not propagate to secondary ones (platform.diskmonitor.limit[alert|warn])

Type
Support Solution
Published
2023-06-30
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 14.1.5
Source
https://my.f5.com/manage/s/article/K000135321

Description

Changes to the sys db variable on the primary blade do not get propagated to the secondary blades.

When you change a sys db variable with sync type private, changes stay with the primary blade:

 

<db_variable>

 <object_id>71606</object_id>

 <name>platform.diskmonitor.limitalert.vmdisk</name>

 <display_name>Platform.DiskMonitor.LimitAlert.vmdisk</display_name>

 <value></value>

 <default>25</default>

 <sync_type>private_internal</sync_type>

 <data_type>integer</data_type>

 <minimum>0</minimum>

 <maximum>100</maximum>

 <scf_config>false</scf_config>

 <transaction_id>351</transaction_id>

 <enumerated/>

 </db_variable>

 

Environment

  • Viprion
  • platform.diskmonitor.limitalert.vmdisk
  • sync type private

 

Cause

This is by design, as variables were defined as private, they are not propagated.

We have an open RFE (Request for Enhancement) in place to allow syncing private platform.diskmonitor.limit[alert|warn] variables between blades.

 

 Recommended Actions

None, as this is by design

 

Additional Information

A work-around is possible by doing the following to get the db change to secondary blades.

"realm" is what controls whether the changes are synced to non-primary blades. 

For "private_internal" the DB key values are not propagated to the non-primary blades in the chassis.

Instead of "realm=private_internal", use "realm=internal", so that the db change gets propagated to the non-primary blades in the chassis.

1. Create a test.dat file:

touch test.dat
 

2. Input the contents below inside test.dat file. Here is an example for 'Platform.DiskMonitor.LimitWarn.var':

# cat test.dat
[Platform.DiskMonitor.LimitWarn.var]
default=40
type=integer
realm=internal
min=0
max=100
scf_config=false
display_name=Platform.DiskMonitor.LimitWarn.var

3. Load the test.dat file using loaddb and then modify to desired value:
loaddb -local -forcevalue test.dat
tmsh modify sys db platform.diskmonitor.limitwarn.var value 10


4. Confirm new db value is the same across all blades:
clsh tmsh list sys db platform.diskmonitor.limitwarn.var
=== slot 2 addr 127.3.0.2 color green ===
sys db platform.diskmonitor.limitwarn.var {
    value "10"
}
=== slot 3 addr 127.3.0.3 color green ===
sys db platform.diskmonitor.limitwarn.var {
    value "10"
}
=== slot 4 addr 127.3.0.4 color green ===
sys db platform.diskmonitor.limitwarn.var {
    value "10"
}
=== slot 1 addr 127.3.0.1 color green ===
sys db platform.diskmonitor.limitwarn.var {
    value "10"
}

5. Save the running config to the config files, so that it survives reboots and upgrades:
clsh tmsh save sys config
