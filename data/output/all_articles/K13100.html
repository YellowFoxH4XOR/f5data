Known Issue

Load balancing may fail intermittently when a pool member in a priority group becomes newly available.

This issue occurs when all of the following conditions are met:

  • A pool has priority groups configured.
  • The same pool has the Slow Ramp Time setting enabled (set to a value greater than 0 seconds).
  • The active priority group is not the highest priority group.
  • A higher priority group is activated because a health monitor changes the status of a pool member in a higher-priority group to available.

When this issue occurs, the previously active priority group is erroneously phased out before the members of the new priority group are fully available. As a result, the system has no destination for some percentage of the traffic until the new priority group members are fully available. The system will retry requests for which the system cannot choose a destination, but some requests may eventually exceed the retry limit and fail.

Important: A change in behavior in BIG-IP 10.1.0 enables the Slow Ramp Time setting, by default, for all pools that do not have a value explicitly configured. For more information, refer to K13099: The Slow Ramp Time pool setting is enabled by default.

Impact

Load balancing may fail intermittently.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H847100 on the Diagnostics > Identified > High screen.
  • Load balancing may fail intermittently for the length of the configured slow ramp interval after a pool member comes back online.
  • When processing iRules, the system may repeatedly trigger the LB_FAILED event for the same request.

Workaround

To work around this issue, you can disable priority groups, or you can disable the Slow Ramp Time setting. F5 recommends that you disable the Slow Ramp Time setting for the workaround, unless the pool is configured to use an algorithm, such as Least Connection; you should disable priority groups for the pool instead.

To disable one of the conflicting features, perform one of the following procedures:

Disabling the Slow Ramp Time setting

Impact of workaround: If the pool member uses the Least Connections load balancing mode, newly-available servers may be flooded with traffic.

  1. Log in to the Configuration utility.
  2. Browse to Local Traffic > Pools > Pool List.
  3. Click the name of the pool you want to modify.
  4. When the Pool Properties screen opens, select Advanced from the Configuration menu.
  5. Change the value of the Slow Ramp Time to 0 (zero seconds).
  6. To save the change, click Update.

Disabling Priority Group Activation

Impact of workaround: The system will load balance traffic across all servers in the pool according to the configured load balancing algorithm.

  1. Log in to the Configuration utility.
  2. Browse to Local Traffic > Pools > Pool List.
  3. Locate the name of the pool you want to modify. Click the number in the Members column to open the Pool Member List.
  4. Change the value of the Priority Group Activation field to Disabled.
  5. To save the change, click Update.

Note: Disabling Priority Group Activation does not remove the Priority value that has been assigned to individual pool members. After upgrading to a version in which this issue has been fixed, you can restore the previously configured Priority values by re-enabling Priority Group Activation.
