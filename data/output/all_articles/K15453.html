Issue

This article applies to the BIG-IP APM system. For information about the FirePass controller, refer to the following article:

  • K8146: Error Message: Network Access Connection Device was not found

Error Message

Network Access Connection Device was not found.

Message Location

You may encounter this message in the following location:

  • BIG-IP Edge Client for Windows

Description

This message occurs when all of the following conditions are met:

  • A Windows client system attempts to establish a Network Access session with the BIG-IP APM system.
  • The Windows Telephony API (TAPI) service or the Remote Access Connection Manager service is not running on the Windows client system.

The Network Access service of the BIG-IP Edge Client for Windows is dependent on the TAPI service and the Remote Access Connection Manager service. If one of these services is disabled, corrupted, or unable to start, the Windows client system will be unable to establish a Network Access session with the BIG-IP APM system.

Impact

Windows client systems are unable to establish a Network Access session with the BIG-IP APM system.

    Recommended Actions

    Verify that the TAPI and Remote Access Connection Manager services are running

    The TAPI service and the Remote Access Connection Manager service are enabled by default on Windows systems. You can verify that both services are in a Running state using the F5 Component Troubleshooting Utility (CTU). To do so, perform the following procedure:

    Note: For information about the CTU, refer to K12444: Overview of the Client Troubleshooting Utility for Windows.

    Impact of procedure: Performing the following procedure should not have a negative impact on your system.

    1. Log in to the affected Windows client system.
    2. Log in to the BIG-IP APM Configuration utility.
    3. In the BIG-IP APM Configuration utility, navigate to the Downloads section of the Welcome page by clicking the F5 logo in the upper-left corner, or by clicking the About tab.
    4. Download the CTU by clicking Client Troubleshooting Utility for Windows in the Downloads section.
    5. Right-click the downloaded f5wininfo.exe file and click Run as administrator.
    6. In the CTU, navigate to File > Generate Report.
    7. Ensure MS System Information Report is selected, and click View to view the results or Save As to save the results to a file.
    8. View the report results and locate the Remote Access Connection Manager (RasMan) and Telephony (TapiSrv) services in the [Services] section of the report. If both services are in the Running state, the output appears similar to the following example:

      Remote Access Connection Manager RasMan Running Manual Share Process c:\windows\system32\svchost.exe -k netsvcs Normal localSystem 0

      Telephony TapiSrv Running Manual Share Process c:\windows\system32\svchost.exe -k networkservice Normal NT AUTHORITY\NetworkService 0

      If the services are in the Stopped state, the output will appear similar to the following example:

      Remote Access Connection Manager RasMan Stopped Manual Share Process c:\windows\system32\svchost.exe -k netsvcs Normal localSystem 0

      Telephony TapiSrv Stopped Manual Share Process c:\windows\system32\svchost.exe -k networkservice Normal NT AUTHORITY\NetworkService 0

    Starting the TAPI and Remote Access Connection Manager services

    If the Startup type for the Telephony service or the Remote Access Connection Manager service is set to Disabled on the client system, you can work around this issue by changing the Startup type to Automatic and then rebooting the Windows client system. If the Startup type for the Telephony service is not set to Disabled, manually start the Telephony service if it is not currently running, or restart the Telephony service if it is running. If the Startup type for the Remote Access Connection Manager service is not set to Disabled, manually start the Remote Access Connection Manager service if it is not currently running, or restart the Remote Access Connection Manager service if it is running.

    Note: Some or all of these actions may require Administrator privileges on the Windows client system. For more information about managing Windows services, refer to your Microsoft Windows documentation.
