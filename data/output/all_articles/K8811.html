Topic

You can configure the Terminal Access Controller Access-Control System Plus (TACACS+) protocol for authenticating BIG-IP administrative users. This feature is similar to the TACACS+ profile for application authentication, but it authenticates BIG-IP administrative connections and does not require a separate license for use.

Note: As with all remote authentication configurations, if the remote authentication server is unavailable to answer authentication requests, only locally defined user accounts, such as the default administrator account and the root command line account, can log in to the system.

Configure remote TACACS+ authentication for local BIG-IP administrative users

To watch a video demo of this procedure, go to Configure TACACS+ authentication for BIG-IP administrators using the Configuration utility.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Select Change.
  4. For User Directory, select Remote - TACACS+.
  5. For Servers, enter the IP address and port of the TACACS+ server and select Add.
  6. For Secret, enter the TACACS+ shared key.
    Note: The TACACS+ secret key does not support the pound sign (#) character.
  7. For Confirm Secret, re-enter the TACACS+ shared key.
  8. For Encryption, retain the default value (Enabled) or select Disabled.
  9. For Service Name, enter ppp for the name of the service. The entry in this field must be lowercase.

    Note: The TACACS+ server must be configured to respond to the appropriate Service Name configured on the BIG-IP system. F5 recommends that you use the ppp service.

  10. Optional: For Protocol Name, enter ip for the name of the protocol. The entry in this field must be lowercase.

    Note: The TACACS+ server must be configured to respond to the appropriate Protocol Name configured on the BIG-IP system. F5 recommends that you use the ip protocol.

  11. Optional: For Configuration, select Advanced. For Authentication, select Authenticate to first server or Authenticate to each server until success.
  12. Optional: For Configuration, select Advanced. For Accounting Information, select Send to first available server or Send to all servers.

    Note: This setting controls the sending of accounting START/STOP packets if multiple TACACS+ servers are defined and pluggable authentication module (PAM) session accounting is available. For more information, see ltm auth tacacs. To configure TACACS+ accounting Audit Logging, see K13762: Configuring remote RADIUS or TACACS+ accounting.

  13. For Debug Logging, when you select Enabled, the BIG-IP system logs debug information to the /var/log/secure file so that an administrator can troubleshoot communication or authentication problems with the TACACS+ server.
  14. For Role, select a user role that you want the BIG-IP system to assign as the default role for remote user accounts.

    Important: This is the role assigned by the BIG-IP system for a remote user account that does not match, or is not explicitly assigned, an F5-LTM-User-Role in the TACACS+ server response. The BIG-IP system does not fall back to use the TACACS+ role and permissions if the F5-LTM-User-Role is not specified. Ensure that you select a default role that provides the default permissions you want. For example, if you select a default role of administrator and a remote user with read-only TACACS+ role permissions is authenticated, and the TACACS+ server response does not specify an F5-LTM-User-Role, the default role (administrator) is used and the user is granted administrator role permissions.

  15. For Partition Access, select the partition or partitions to which you want users with remote accounts to have access.
  16. For Terminal Access, select the appropriate access option for your environment.
  17. Select Finished.

Repeat this step to add additional TACACS+ servers.

Route to the TACACS+ server

If you need to use the management interface to communicate with this server and it does not reside in the same subnet, you must add a static management route that is more specific than any TMM routes to this server. For more information, see K13284: Overview of management interface routing.
