Known Issue

Administrative users who authenticate to BIG-IP using remote authentication and remote roles may not be granted the correct access permissions when connecting to the BIG-IP command line.

This issue occurs when all of the following conditions are met:

  • A user account with administrator role permissions connects to the BIG-IP command line through SSH.
  • A user account with administrator role permissions is remotely authenticated.
  • Access permissions are defined using remote roles.

BIG-IP users with administrator role permissions are incorrectly assigned the UID value of 499 (f5_remoteuser) instead of UID 0 (root) when connecting through SSH. These users will be unable to perform command-line tasks that require root or administrator level permissions.

Impact

Remotely authenticated administrative command-line users will not be able to use system tools that require administrative access, such as tcpdump, and qkview.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The UID of affected users is 499, as shown in the output of the id command in the following example:

    uid=499(f5_remoteuser) gid=499(f5_remoteuser) groups=499(f5_remoteuser)
    context=user_u:system_r:unconfined_t
  • The effective userid of affected users is f5_remoteuser in the output of the whoami command.
  • Running the tcpdump command displays an error message that appears similar to the following example:

    bash: tcpdump: command not found
  • Running the qkview command displays an error message that appears similar to the following example:

    Another qkview is running.
    You can't run multiple instances of qkview at once.
  • Other actions that require root access display errors as though they were performed by a non-root user. For example:

    cp /config/bigip.conf /config/bigip.conf.bak

    cp: cannot create regular file `/config/bigip.conf.bak': Permission denied

Workaround

To work around this issue in the case of the tcpdump command, run the command from tmsh, or specify the complete path to the command. To do so, perform one of the following procedures:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Running tcpdump from tmsh

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

    Note: If you are currently logged in to tmsh, you can skip this step.
  2. Run tcpdump with the following command:

    run util tcpdump

Running tcpdump by specifying the full path

  1. Log in to the BIG-IP command line.
  2.  Run tcpdump with the following command:

    /usr/sbin/tcpdump

In the case of the qkview command, you can work around this issue by running the qkview utility from the Configuration utility. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Running qkview from the Configuration utility

  1. Log in to the BIG-IP Configuration utility.
  2. Click System > Support.
  3. Select the check box next to QKView.
  4. Click Start.
