K89724886: Disk partition / has only 0% free. Space used by files under '/.config.tmp'

Type
Support Solution
Published
2021-07-19
Updated
2025-02-07
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K89724886

Description
The root file system is at very high usage on the device and it is caused by files in sub directories under '/.config.tmp' are created

For example,
# df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/md4        427M  427M     0 100% /
 

# find / -xdev -type f -exec du {} \; | sort -rn | head -20
...
2144    /.config.tmp/G7G0BA/bigip_scf.conf
2141    /.config.tmp/8Gv8md/bigip_scf.conf
2141    /.config.tmp/9Jg7mc/bigip_scf.conf
2139    /.config.tmp/Luc9om/bigip_scf.conf

Environment

  • BIG-IP, v11,v12
  • Configuration saves
  • UCS backups
  • Config Syncs.

Cause

The sub directories under '/.config.tmp' are created whenever a configuration save or a UCS back up is performed.
Under normal circumstances, the sub directory used for the operation is deleted once the operation completes.
If the operation does not complete for whatever reason, the sub directory and it's contents are left behind.

One of the specific noted causes for this behavior is OOM Killer invocation with AS3 configuration being applied
K47241910: Interpreting an OOM killer log (out of memory)

Recommended Actions

It *is* safe to delete the sub directories under '/.config.tmp'.  But, because they have been left behind when operation does not complete for whatever reason, so this kind of files should be monitored and if it is growing fast customer can open a ticket with F5 support to understand why this is happening so can correct that situation.

Below commands to check the size of that sub directories and monitor the data the time when they were created,
Regular check the size:
#du -hs /.config.tmp/
Check the data and time when those files are created,
#ls -lR /.config.tmp/
