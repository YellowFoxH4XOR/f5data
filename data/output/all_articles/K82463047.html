K82463047: Retrieving missing files after an upgrade from an old boot location

Type
Support Solution
Published
2021-05-05
Updated
2025-02-07
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K82463047

Description

  • You have important files in the current boot location
  • You upgraded the BIG-IP to another boot location
  • You discover that the important files are no longer available from the new boot location
  • Booting the BIG-IP into the previous boot location in order to retrieve the files may be not be considered as a practical option

Environment
  • BIG-IP
  • Boot location

Cause

  • Files outside /config/ may not be copied automatically during the upgrade (e. g. backup UCS files)
  • Or the file was copied as a part of the upgrade, but its original contents overwritten by mistake later

Recommended Actions

  • You must have the privilege to access bash CLI
  • You must know the name and location of the file.
    E. g. the name of the boot location can be found in the output of tmsh show /sys software
To retrieve file(s) mount the volume
  1. Use lvscan to scan for all logical volumes

    The command output appears similar to the following example:

    ACTIVE '/dev/vg-db-sda/dat.share.1' [30.00 GB] normal
    ACTIVE '/dev/vg-db-sda/dat.log.1' [7.00 GB] normal
    ACTIVE '/dev/vg-db-sda/set.1.root' [256.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.1._usr' [1.34 GB] normal
    ACTIVE '/dev/vg-db-sda/set.1._config' [512.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.1._var' [3.00 GB] normal
    ACTIVE '/dev/vg-db-sda/set.2.root' [256.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.2._usr' [1.34 GB] normal
    ACTIVE '/dev/vg-db-sda/set.2._config' [512.00 MB] normal
    ACTIVE '/dev/vg-db-sda/set.2._var' [3.00 GB] normal
    ACTIVE '/dev/vg-db-hda/dat.maint.1' [200.00 MB] normal

    In the output of the above example:

    Files with names beginning with "set.1" most likely belong to boot location HD1.1:

    /dev/vg-db-sda/set.1.root
    /dev/vg-db-sda/set.1._usr
    /dev/vg-db-sda/set.1._config
    /dev/vg-db-sda/set.1._var

    Files with names beginning with "set.2" most likely belong to boot location HD1.2:

    /dev/vg-db-sda/set.2.root
    /dev/vg-db-sda/set.2._usr
    /dev/vg-db-sda/set.2._config
    /dev/vg-db-sda/set.2._var
     

  2. Based on the output of the previous command, determine which logical volume contains the files that you want to retrieve.

    For example, if you want to retrieve the /config/bigip.conf file from the HD1.2 boot location, you must mount the /dev/vg-db-sda/set.2._config logical volume.

    Note: Some directories on the BIG-IP system are symbolic links to other directories. For example, the /var/tmp directory is a link to the /shared/tmp directory. Therefore, if you want to retrieve a file from the /var/tmp directory, you must mount the logical volume for the /shared directory.

  3. To create a temporary directory in the current active boot location, type the following command:

    mkdir /mnt/temp

  4. To mount the appropriate logical volume, use the following command syntax:

    mount <logical volume> /mnt/temp

    For example:

    mount /dev/vg-db-sda/set.2._config /mnt/temp

  5. Copy all required files from the mounted logical volume.

    For example:

    cp /mnt/temp/bigip.conf /var/tmp/
    cp /mnt/temp/bigip_base.conf /var/tmp/

  6. To unmount the logical volume, type the following command:

    umount /mnt/temp

  7. Repeat this procedure until you have retrieved all necessary files from all logical volumes.
