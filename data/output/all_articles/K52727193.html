Description

Configuration changes, such as addition of Wide-IP, GSLB Pool, or GSLB monitors are failing to synchronize to the other BIG-IP DNS devices.

Events similar to the following are found in /var/log/gtm:

Oct 1 23:13:42 gtm2 err gtmd[24144]: 011ae044:3: Could not find monitor object 10.20.30.40:25 on server:vs /Common/serverX:virtualserverX
Oct 1 23:13:45 gtm2 notice gtmd[24144]: 011a001d:5: SYNC loading GTM config from: 100.200.30.40
Oct 1 23:13:46 gtm2 err gtmd[24144]: 011ae044:3: Could not find monitor object 10.20.30.41:25 on server:vs /Common/serverY:virtualserverY
Oct 1 23:13:47 gtm2 err iqsyncer[24560]: 011ae104:3: Gtm config sync result from local mcpd: result { result_code 17241961 result_message "01071769:3: Decryption of the field (pvalue) for object (/Com /MyGTMmonitor 2 PASSWORD=) failed." result_attribute monitor_param } 
Oct 1 23:13:48 gtm2 notice gtmd[24144]: 011a0006:5: hookOnChild: SYNC syncer exited with status == 0.(succes

Environment

  • BIG-IP DNS
  • 'f5mku -K' reveals the master keys do not match.

Cause

All BIG-IP DNS devices that are in the same synchronization group must have the same master key. Mismatched keys will prevent encrypted passwords in the configuration from being decrypted. When decryption fails, the configuration file will fail to load.

Recommended Actions

  1. Ensure the master keys match, by completing one of the procedures provided in: K11868: The master key is not synchronized after upgrading a BIG-IP GTM synchronization group.
