Description

When upgrading BIG-IP AFM systems with DoS profiles to newer versions (for example from v17.1.2.1 to 17.5.1), configuration load failures may occur with Error messages such as:

Aug  2 14:55:52 <Hostname> err mcpd[8212]: 01071aa6:3: DOS DNS query data (ptr): Dos DNS query data bad actor can not be enabled if per-source detection/limit pps is less than 0.1% of the Dos vector (ptr) rate threshold setting for sub-profile (<profile_name>) of Dos profile (<profile_path>).
Aug  2 14:55:53 <Hostname> err tmsh[11551]: 01420006:3: Loading configuration process failed.
Aug  2 14:55:53 <Hostname> emerg load_config_files[11549]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- Loading schema version: 17.1.2.1
Aug  2 14:55:54 <Hostname> err mcpd[8212]: 01070425:3: Full configuration load failed.

 

This occurs when "per-source-ip-detection-pps" and/or "per-source-ip-limit-pps" values for a DoS vector (e.g., DNS vector "PTR") are set below 0.1% of the vector’s rate-limit.

For example, when you run the command "tmsh list /security dos profile all-properties" to check the DoS vector values for any possible Inconsistency, you can see some unexpected values as below. Here, the "per-source-ip-detection-pps" and "per-source-ip-limit-pps" value was set to "10" PPS, while the "rate-limit" value was set to "4294967295" (Infinite), which leads to config load problem, due to wring ratio.

...
 ptr {
 allow-advertisement disabled
 app-service none
 auto-blacklisting enabled
 bad-actor enabled
 blacklist-category /Common/denial_of_service
 blacklist-detection-seconds 60
 blacklist-duration 14400
 packet-types none
 per-source-ip-detection-pps 10 <-------------------------- !!! [Must be modified]
 per-source-ip-limit-pps 10 <-------------------------- !!! [Must be modified]
 rate-increase 200
 rate-limit 4294967295 <-------------------------- !!! [Infinite]
 rate-threshold 4294967295
}
...

Environment

  • AFM Module
  • DoS Protection configured
  • Upgrade or Config load attempt

Cause

The configuration fails to load because the "per-source-ip-detection-pps" and "per-source-ip-limit-pps" values for a DoS vector are set below the minimum allowed threshold, which is enforced as "0.1%" of the vector’s rate-limit. This restriction is by design to prevent excessive resource consumption and false positives in bad actor detection logic.

If the rate-limit is set to "Infinite" (4294967295), any small per-source value will violate this ratio and trigger a config load failure.

Recommended Actions

To resolve this issue, you can follow either the below options, as a workaround:

1. If you already set any absolute value for "rate-limit" rather than "Infinite", you need to manually Increase the threshold value of both "per-source-ip-detection-pps" and "per-source-ip-limit-pps" parameters to at least 0.1% of the corresponding DOS vector's rate-limit.

Example: If rate-limit = 10000, minimum per-source value must be ≥10.

2. If the current value of "rate-limit" is set to "Infinite", you need to manually set both the parameters (per-source-ip-detection-pps, per-source-ip-limit-pps) to "4294967295" (i.e., Infinite). This disables bad actor detection for that vector.

Additional Information

How To Apply Changes via Console (CLI):

1. Make a copy of "/config/bigip.conf" file, before applying any changes:
# cp /config/bigip.conf /config/bigip.conf.backup

2. Edit "/config/bigip.conf" directly using a text editor like "vi":
# vi /config/bigip.conf

3. Adjust relevant lines under your affected DOS profile/vector, and press "i" on your keyboard to Enter the INSERT mode and apply the needed changes.

4. Once done, press ESC on your keyboard, and then press key sequence :qw for Saving the changes and Exit the "vi" Editor.

5. Verify the modified configuration and checking for any Error:
# tmsh load sys config verify

6. If there was no Error, you can run the below command to load the config into the Memory:

# tmsh load sys config
