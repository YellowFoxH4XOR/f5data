Description

NGINX Gateway Fabric (NGF) logs CRD not found, controller disabled for Gateway API resources such as ReferenceGrant, TCPRoute, UDPRoute, BackendTLSPolicy, TLSRoute, or ListenerSet when the corresponding Custom Resource Definitions (CRDs) are not installed in the cluster.

Example:

CRD not found, controller disabled
kind: TLSRoute

Environment

  • NGINX Gateway Fabric
  • OpenShift
  • NGINX Gateway Fabric Operator
  • Gateway API resources, including:
    • Gateway
    • HTTPRoute
    • ReferenceGrant
    • TCPRoute
    • UDPRoute
    • TLSRoute
    • BackendTLSPolicy
    • ListenerSet

Cause

NGINX Gateway Fabric supports multiple Gateway API installation profiles:

  • The standard installation provides the core Gateway API CRDs.
  • The experimental installation provides additional or newer Gateway API CRDs, including resources such as TCPRoute, UDPRoute, TLSRoute, BackendTLSPolicy, and ListenerSet.

The NGF Operator follows the standard NGINX Gateway Fabric installation path. Therefore, controllers that depend on CRDs not included in the standard installation are disabled.

OpenShift may also provide an older Gateway API implementation that does not include every resource supported by NGINX Gateway Fabric. Support for a resource in NGINX Gateway Fabric does not make that resource available unless its CRD is installed and supported by the platform.

Recommended Actions

  1. Identify the Gateway API resource required by the configuration. For example, a TLSRoute requires the TLSRoute CRD.
  2. Verify that the required CRD is installed:
    kubectl get crd | grep -E 'tlsroutes|tcproutes|udproutes|backendtlspolicies|listenersets'
  3. Use the standard installation when only the core Gateway API resources are required.
  4. Use the experimental installation and its matching CRD manifest when resources such as TLSRoute, TCPRoute, UDPRoute, BackendTLSPolicy, or ListenerSet are required.
  5. Ensure that the NGF deployment and CRD manifests come from the same supported release. Do not combine manifests from unrelated releases.
  6. Confirm that the OpenShift Gateway API implementation supports the requested resource. If the platform does not support the required Gateway API version, the resource cannot be used until the platform and NGF compatibility requirements are met.
  7. Restart or reconcile the NGINX Gateway Fabric deployment if required by the installation procedure, then review the pod logs:
    kubectl logs <ngf-pod>
    The CRD not found, controller disabled message should no longer appear for resources whose CRDs are installed and supported.

Additional Information

  • Installing a CRD alone does not guarantee that the resource is supported by the deployed NGINX Gateway Fabric version or the OpenShift platform.
  • The OpenShift Operator is intended for the standard installation path.
  • Features from newer Gateway API versions remain unavailable when the corresponding CRDs are not provided by OpenShift.
  • Use the experimental installation only when the required resources are supported and the deployment is configured accordingly.
