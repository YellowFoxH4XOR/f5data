Topic

To replace a failed BIG-IP system without interrupting service, perform the following procedure:

Note: If you are running BIG-IP 9.4.x using network failover instead of a serial failover cable, F5 recommends that you remove the peer connection table entry from the active system before proceeding with the replacement. For more information, refer to K11495: Connection table entry for the network failover heartbeat may cause undesired behavior when replacing a unit.

Important: As a result of an issue affecting BIG-IP 9.x through 11.0.0, you must disable connection mirroring or persistence mirroring prior to powering down the standby unit. For more information, refer to the Workaround section of K12370: Memory usage on an active unit may significantly increase when mirroring is enabled and the standby unit is offline. If neither connection mirroring nor persistence mirroring is enabled, or you are running BIG-IP 11.1.0 or later, proceed to the following procedure.

  1. Shut down the failed BIG-IP system.
  2. Disconnect all of the cables and set the BIG-IP system aside in preparation to return it to F5.
  3. Install the replacement BIG-IP system in place of the previous unit.
  4. If the two BIG-IP systems were using serial cable failover prior to the failure, connect the failover cable between the replacement unit and the remaining peer.

    Note: To verify the failover cable status, refer to the Verifying the failover cable status procedure in K95002127: Troubleshooting BIG-IP failover events.

    Important: If the failover cable is not connected properly (for example, it is plugged into the console port by accident), the replacement unit does not detect the peer BIG-IP system and attempts to become the active unit. This behavior disrupts traffic when the configuration has been restored on the replacement unit.

  5. Connect a serial terminal to the console port.

    Note: For more information, refer to K7683: Connecting a serial terminal to a BIG-IP system.

  6. Connect the power cable to the replacement BIG-IP unit.

    Do not connect any network cables at this time. You will connect the network cables in step 11.

  7. Start the replacement BIG-IP system.
  8. Log in to the replacement BIG-IP system using the serial console, and then run the config utility to configure the management interface.
  9. Enter the appropriate data to assign an IP address, netmask, and default management route to the management interface.
  10. Connect the management port to your network, as appropriate.

    Note: If you do not have serial access to the device, you can set the management network settings by using the LCD display and keypad on the front panel of the device. For more information, refer to the appropriate Platform Guide for your hardware platform.

  11. Optional: Connect a network cable to the management interface, and continue with step 10 from a remote workstation using secure shell (SSH).
  12. Restore the configuration to the replacement system using the user configuration set (UCS) archive from the failed BIG-IP system.

    To do so, refer to one of the following articles:

    • K13132: Backing up and restoring BIG-IP configuration files with a UCS archive
    • K11318: Backing up and restoring BIG-IP configuration files (10.x)
    • K3499: Backing up and restoring BIG-IP 9.x configuration files
    • K12880: Configuring a replacement BIG-IP device after a Return Materials Authorization
    • K13551: Configuring a replacement BIG-IP device after an RMA when no UCS archive is available

      Important: Following steps in K13551 may lead to an active-active condition and a potential interruption in service if the unit is not forced offline.

  13. After you verify that the restored configuration loads without errors, perform one of the following steps:
    • If the BIG-IP systems use serial cable failover, connect all of the network cables.
    • If the BIG-IP systems use network failover, shut down the replacement system, connect all of the network cables, and then restart the replacement system. This extra step reduces the likelihood of IP conflicts in the network until network failover traffic is restored between the two units.

Important: For BIG-IP 9.x through 11.0.0 systems, if you disabled mirroring prior to performing this procedure, you should now re-enable mirroring. For more information, refer to the Workaround section of K12370: Memory usage on an active unit may significantly increase when mirroring is enabled and the standby unit is offline.
