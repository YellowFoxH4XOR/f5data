Known Issue

This is the result of a known issue. An XML schema file can set length constraints on the value space of its elements using the length, minLength, or maxLength constraining facets. When the schema file sets length constraints in this manner, in order to validate client requests, the BIG-IP ASM system must calculate the length of constrained value spaces. For elements of the string data type or other data types derived from string, the BIG-IP ASM system should calculate the length of a value space by counting the characters present in the value space. However, the BIG-IP ASM system counts the number of bytes used by the value space. Generally, this behavior does not represent an issue because counting the characters in a value space or counting the bytes used by a value space produces the same number (1 character equals 1 byte). However, you can obtain two different results when using variable-length character encoding because certain characters are represented by two-byte values.

Consider the following example:

  • An XML schema file uses the UTF-8 character encoding.
  • The description element is a string data type and has a maxLength value of 23.
  • An XML request is sent to the BIG-IP ASM system that appears similar to the following example:

    <description>This is test request 1.</description>

    Although the BIG-IP ASM system incorrectly calculates the length of the description element value space in bytes, the request is still marked as legitimate. This behavior occurs because the description element value space is 23 characters in size and 23 bytes.
  • An XML request is sent to the BIG-IP ASM system that appears similar to the following example:

    <description>This is test request ö.</description>

    In this case, the description element value space is 23 characters in size, but 24 bytes. This behavior occurs because the UTF-8 character encoding represents the ö character with 2 bytes (c3 b6 in HEX). As a result, this request triggers a schema validation violation on the BIG-IP ASM system.

F5 Product Development tracked this issue as CR133477 and it was fixed in BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.
