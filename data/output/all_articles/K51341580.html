K51341580: Configuring the BIG-IP system to send BIG-IP APM syslog messages to the alertd process

Type
Knowledge
Published
2018-03-07
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K51341580

Topic

syslog filters out BIG-IP APM log messages and does not send them to the alertd process. You can modify the include statement in the syslog configuration to send BIG-IP APM syslog messages to the alertd process and trigger custom SNMP traps for BIG-IP APM messages.

Description

The alertd process triggers SNMP traps when messages that match an alert code are received from the syslog utility. Because of the potential amount of logging the BIG-IP APM system generates and because BIG-IP APM does not support enterprise-level SNMP traps, the syslog configuration filters out BIG-IP APM syslog messages before they reach the alertd process. As a result, custom SNMP traps based on BIG-IP APM syslog messages are not triggered by the alertd process.

To trigger custom SNMP traps for BIG-IP APM syslog messages, you can add a filter to the include statement in the syslog configuration and specify alertd as the destination.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have configured the BIG-IP system to send SNMP traps.
  • You have configured a custom SNMP trap based on a BIG-IP APM syslog message.
  • You have administrative access to the TMOS Shell (tmsh).

Procedures

  • Adding a custom filter to the syslog configuration
  • Reverting the changes to the default setting

Adding a custom filter to the syslog configuration

You can use tmsh to modify the syslog configuration in order to trigger custom SNMP traps for BIG-IP APM syslog messages. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh using the following command:

    tmsh

  2. To edit the syslog configuration, type the following command:

    edit /sys syslog all-properties

    The syslog configuration opens for editing in the vi text editor. Output appears similar to the following:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        clustered-host-slot enabled
        clustered-message-slot disabled
        console-log enabled
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include none
        iso-date disabled
        kern-from debug
        kern-to emerg
        local6-from notice
        local6-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }

  3. Locate the line with include none and modify the entry to include the following:

        include "
        filter f_alertd_apm {
            match(\": 0149[0-9a-fA-F]{4}:\");
        };

        log {
            source(s_syslog_pipe);
            filter(f_alertd_apm);
            destination(d_alertd);
        };
        "

  4. The resulting configuration appears similar to the following:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        clustered-host-slot enabled
        clustered-message-slot disabled
        console-log enabled
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
        filter f_alertd_apm {
            match(\": 0149[0-9a-fA-F]{4}:\");
        };

        log {
            source(s_syslog_pipe);
            filter(f_alertd_apm);
            destination(d_alertd);
        };
        "
        iso-date disabled
        kern-from debug
        kern-to emerg
        local6-from notice
        local6-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers none
        user-log-from notice
        user-log-to emerg
    }

  5. Save the changes and exit the editor by typing the following command:

    :wq!

  6. Type y to confirm the changes when presented with the following prompt:

    Save changes? (y/n/e)

  7. If the system encounters an error, continue editing to correct any syntax errors in the syslog configuration and confirm the changes.
  8. Save the changes to the configuration by typing the following command:

    save /sys config

     

Reverting the changes to the default setting

To remove the changes and revert the syslog include statement back to its default setting, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Revert the include statement back to its default setting by typing the following command:

    modify /sys syslog include none

  3. Save the configuration by typing the following command:

    save /sys config
