Description

Your system may experience the following symptoms:

  • Unable to discover ASM configuration on BIG-IQ.
  • ASM configuration cannot be imported to BIG-IQ.
  • Unable to deploy ASM configuration from BIG-IQ.
  • When deploying, discovering or importing ASM configuration from BIG-IQ an error message appears in the GUI:

    no message: java.lang.NullPointerException

  • Additional details of the warning message can be seen in /var/log/restjavad.0.log

    [ERROR][11 Feb 2020 13:08:02 MSK][/cm/asm/tasks/discover-config/8a2e2d91-d3cc-4113-9121-6fa3477fde0b/worker AsmDiscoveryTaskWorker] java.lang.NullPointerException
    at java.util.concurrent.ConcurrentHashMap.putVal(ConcurrentHashMap.java:1011)
    at java.util.concurrent.ConcurrentHashMap.put(ConcurrentHashMap.java:1006)

Verify one of the following symptoms before taking the steps in Recommended Actions:

  • On the BIG-IP, the output of restcurl -u example_user:example_password /mgmt/tm/asm/attack-types | jq '.items[] | select(.name == "Server-Side Request Forgery (SSRF)")' displays no value for id:
    {
      "kind": "tm:asm:attack-types:attack-typestate",
      "selfLink": "https://localhost/mgmt/tm/asm/attack-types",
      "name": "Server-Side Request Forgery (SSRF)",
      "id": ""
    }
  • On the BIG-IP, the output of mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'SELECT * FROM PLC.NEGSIG_ATTACK_TYPES WHERE attack_type_name = "Server-Side Request Forgery (SSRF)"' displays no value for rest_uuid:
    +----------------+------------------------------------+------------------------------------+-----------+
    | attack_type_id | attack_type_name                   | attack_type_display_name           | rest_uuid |
    +----------------+------------------------------------+------------------------------------+-----------+
    |             40 | Server-Side Request Forgery (SSRF) | Server-Side Request Forgery (SSRF) |           |
    +----------------+------------------------------------+------------------------------------+-----------+

Environment

  • BIG-IQ CM
  • BIG-IP ASM

Cause

Observed behavior is caused by a known issue tracked with the bug ID 853393

Recommended Actions

On BIG-IP ASM update to a newer ASU and delete the incorrect entry from the Attack Signatures:

  1. Install a newer ASU to reassociate the affected signatures with the correct attack type. If you are running the latest attack signature updates (recommended) or updates later than 17-Nov-2019, you can skip this step.
  2. Run the following mysql command on the affected BIG-IP ASM devices:

    mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'DELETE FROM PLC.NEGSIG_ATTACK_TYPES WHERE attack_type_name = "Server-Side Request Forgery (SSRF)"'

    Note: If you get the error, ERROR 1451 (23000) at line 1: Cannot delete or update a parent row: a foreign key constraint fails, verify if the iControl REST ID is missing as shown in the symptoms above. If the ID is present, there is likely another cause for the java.lang.NullPointerException error when working with ASM configuration on BIG-IQ.

On BIG-IQ CM correct the mistaken value for Attack Type (SSRF) :

  1. Run this command from BIG-IQ console:

    restcurl -X PATCH /cm/asm/attack-types/0083eb62-8086-366f-b776-5b309566161d -d '{bigipId:"AIPrYoCG9m83dlswlWYWHQ", bigipAttackTypeId:"40"}'

  2. Re-deploy, re-discover or re-import the ASM configuration.
