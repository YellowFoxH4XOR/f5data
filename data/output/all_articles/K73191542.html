K73191542: Unable to logout of APM session (/vdesk/undefined); script errors; resources don't display on APM webtop

Type
Support Solution
Published
2021-12-29
Updated
2023-10-16
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.4
Source
https://my.f5.com/manage/s/article/K73191542

Description

After upgrading to 15.1.4, you may encounter the following issues when using a browser to connect to the VPN:

1. Javascript errors when clicking on the Network Access resource to establish the VPN
2. when clicking Logout, it redirects to https://apm-virtual-server/vdesk/undefined (instead of the usual /vdesk/hangup.php3 URI)
3. after successful authentication, user resources may fail to display when utilizing a Full webtop

Environment

  • BIG-APM v15.1.4
  • browser-based VPN session
  • Access Profile utilizing a Full webtop

Cause

This is a bug caused by unexpected characters in responses to pages served by APM renderer
Bug ID 1027217: Script errors in Network Access window using browser

Recommended Actions

To fix this issue, you can either upgrade your BIG-IP software version to 15.1.4.1 or perform the below workaround

IMPORTANT: The workaround requires restarting TMM so recommend doing it in a maintenance window.

1. Log in to the BIG-IP CLI

2. Run this command to mount /usr in read/write mode:
    # mount -o remount,rw /usr/

3. Navigate to the file /usr/lib/tmm/tmm_base.tcl and open it in any text editor of your choice
Once this file is opened, add “response_chunking   2” to _tmm_apm_portal_http. Below is an example:

profile http _tmm_apm_portal_http {
    max_header_size     32768
    max_header_count    64
    known_methods       "CONNECT DELETE GET HEAD LOCK OPTIONS POST PROPFIND PUT TRACE UNLOCK"
    response_chunking   2    <--------- add this line!!!
}

Save the file and exit.

4. Restart tmm once the above line is added.
     # bigstart restart tmm

5. Run this command to revert /usr back to read only
    # mount -o remount,ro /usr/
