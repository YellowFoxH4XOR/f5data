Description

Explains how to Block all Traffic, including both legitimate and policy-violating requests, on a BIG-IP ASM system for security Incident Response. By default, ASM Policies in Blocking mode only Block Traffic that triggers violations, allowing legitimate Traffic to pass. To Block all Traffic, configuration at the LTM/virtual server level is required. 

Environment

  • BIG-IP LTM + ASM
  • ASM Policy in Blocking mode attached to a virtual server

Cause

The ASM Policy Engine Blocks only Traffic that violates defined security policies. There is no native ASM-only configuration to Block all Traffic, including legitimate requests, because ASM allows legitimate Traffic by design. Blocking all Traffic requires action at the LTM/virtual server layer. 

Answer/Recommended Actions

To block all Traffic immediately, use one of the following options:

1. Disable the Virtual Server (Recommended):

Via GUI:

  • Navigate to Local Traffic > Virtual Servers > [Virtual Server]
  • Change State to Disabled

Via tmsh command:

  • Run: tmsh modify ltm virtual <virtual_server_name> disabled
    Save configuration: tmsh save sys config

To restore normal operation, re-enable the virtual server:

  • Run: tmsh modify ltm virtual <virtual_server_name> enabled
  • Save configuration: tmsh save sys config

 

2. Attach a "Reject All" iRule to the Virtual Server

Create an iRule:

when CLIENT_ACCEPTED {
   reject
}
  • Assign the iRule to the target virtual server:
    • Go to Local Traffic > iRules > iRule List > Create
    • Name the iRule (e.g., block_all_traffic) and paste the code above
    • Assign it via Local Traffic > Virtual Servers > [VS Name] > Resources tab
  • To restore normal operation, remove the iRule from the virtual server.

Additional Information

  • The "Reject All" iRule operates at the connection level before ASM inspection, ensuring all Traffic is Blocked regardless of ASM policy state.
  • Disabling the virtual server is the most immediate and clean approach for incident response scenarios.
