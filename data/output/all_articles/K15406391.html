K15406391: Cannot delete previously installed Attack Signatures

Type
Support Solution
Published
2021-04-29
Updated
2024-10-15
Applies to
  • BIG-IP ASM: 15.X.X
Source
https://my.f5.com/manage/s/article/K15406391

Description

Signature Update installations using ASU files with the same name on versions prior to 14.1.0 block Live Update usage after upgrade to 14.1.0 or later.

Environment

  • BIG-IP ASM
  • Attack Signature updates using ASM Signature Update (ASU) files

Cause

  • The same Signature Update file is installed multiple times on the device when running a version prior to 14.1.0.

Recommended Actions

You can use the following workaround to resolve this issue:

Impact of workaround: You may lose pre-upgrade records for Signature Update and cannot access BIG-IP Configuration utility while services are restarting.

  1. Delete the file: /var/lib/hsqldb/live-update/live-update-import.yaml.*
  2. Restart tomcat: bigstart restart tomcat This causes pre-upgrade records for Signature Update to be lost, but does not have any other functional impact.

Alternatively, you can use the following procedure if the above workaround does not resolve your issue:

Impact of procedure: You may lose pre-upgrade records for Signature Update and cannot access BIG-IP Configuration utility while services are restarting.

  1. Stop the tomcat server using the following command:

    bigstart stop tomcat
     
  2. Clean the live update db :
     
    • cd /var/lib/hsqldb/live-update
    • rm -f liveupdatedb.*
       
  3. Remove all *.im files which are not genesis file (factory-default files):
     
    • Get the list of genesis files:
      less /etc/live-update-genesis.yaml | grep genes | cut -d":" -f 2
    • Go to update file directory:
      cd /var/lib/hsqldb/live-update/update-files
    • Manually remove the *.im files that are not genesis
       
  4. Restart the tomcat server using the following command:

    bigstart start tomcat
