Description

Restjavad process is frequently restarting

The following messages are logged on var/log/restjavad.0.log

[SEVERE][87][02 Jul 2020 06:06:33 UTC][DieOnUncaughtErrorHandler] Restjavad exiting immediately due to an uncaught Error
[SEVERE][88][02 Jul 2020 06:06:33 UTC][DieOnUncaughtErrorHandler] Uncaught Error causing restjavad to exit. Thread id 78, 'com.f5.rest.workers.storage.ThreadPoolStorageRequestProcessor_59': java.lang.OutOfMemoryError: Java heap space

The following messages are logged on var/log/daemon.log

emerg logger[31027]: Re-starting restjavad
emerg logger[31602]: Re-starting restjavad
emerg logger[32125]: Re-starting restjavad

Environment

  • BIG-IP system with high number of incoming REST API calls.
  • The configuration contains a large number of objects.

Cause

ID776393
ID1025261

Recommended Actions

First assess the memory utilisation on BIG-IP and review the articles in the Additional Information section to identify appropriate values for provision.extramb, provision.tomcat.extramb and provision.restjavad.extramb

Perform the following steps to re-allocate memory from TMM to management, tomcat and restjavad:

Note: Changing the Management (MGMT) size after initial provisioning causes a reprovision operation which will interrupt traffic as it recovers from a TMM restart and a failover will occur. F5 recommends changing the Management memory size allocation during a scheduled maintenance window.

  1. Apply suitable values for provision.extramb and provision.tomcat.extramb as per K26427018
  2. Identify current values for restjavad.useextramb and provision.restjavad.extramb
    tmsh list sys db restjavad.useextramb
    tmsh list sys db provision.restjavad.extramb
  3. Allocate Management memory to the restjavad process:
    1. If restjavad.useextramb is false, set to true. Otherwise skip to b):
      tmsh modify sys db restjavad.useextramb value true
      Note: 'restjavad.useextramb' was removed in 17.1.0, 16.1.4, 15.1.9
    2. provision.restjavad.extramb is only available on software versions greater than v14.1.5.1, v15.1.7, v16.1.3.1 and v17.0.0.1):
      tmsh modify sys db provision.restjavad.extramb value <MINIMUM VALUE 384> (Allocate more memory incrementally until restjavad stops restarting)
    3. Restart restjavad service to apply new value:
      tmsh restart sys service restjavad

Additional Information

K26427018: Overview of Management provisioning
K00505373: Automation Toolchain restjavad extra memory allocation guidance
K000137363: Overview of restjavad memory provisioning on BIG-IP and use of restjavad.useextramb, provision.extramb and provision.restjavad.extramb
ID1079705: Restjavad may restart repeatedly if sys db provision.extramb is high

Example Memory allocation for BIG-IP 17.1.1.1 with 8GB+ Memory and utilising DO/AS3 automation toolchain:

tmsh modify sys db provision.extramb value 2048
tmsh modify sys db provision.restjavad.extramb value 2022
tmsh modify /sys db provision.tomcat.extramb value 256
tmsh restart sys service restjavad tomcat
tmsh save /sys config

Note: These values are provided as an example only and should be tuned for your specific environment depending on your memory budget, modules provisioned, and REST API activity.
