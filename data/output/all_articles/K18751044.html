Description

IP Intelligence is dropping connections to questionable IP addresses. When using iprep_lookup, it will show what category the IP address is associate with.

Command:
iprep_lookup <IP address>

Example output would be:
# iprep_lookup 192.168.100.100
opening database in /var/IpRep/F5IpRep.dat
size of IP reputation database = 27190590
iprep threats list for ip = 192.168.100.100 is:
        bit 1 - Windows Exploits
        bit 4 - Scanners

This article will guide you on how to create an Allowlist for your IP Intelligence when using AFM.

Note: An AFM license is required for IP Intelligence to access the Allowlist functionality via a Feed Lists and Whitelists . If there is no AFM license, TMM deletes all the configured Allowlist and then applies IPI Intelligence. 

  • K000130273: AFM provisioning is required to use IP Intelligence Feed Lists and Whitelists

If IP Intelligence is being used with only an ASM license you can use the IP Address Exception list to exclude the IP/subnet.

  • K000138970: Malicious Source IP Addresses
  • Managing IP Address Exceptions

If the IP intelligence database is being used via an iRule for LTM it still has be licensed but a whitelist can be created using a Datagroup added to the iRule.

  • Enabling IP Address Intelligence
  • IP intelligence (reputation) blocking with whitelist support

Environment

  • BIG-IP AFM
  • IP Intelligence is dropping questionable IP addresses
  • You want to create an Allowlist to allow questionable IP addresses to access the Virtual Server

Cause

None.

Recommended Actions

To create the Allowlist, the BIG-IP AFM will need to pull a feed list (text file) which contains the IP address which you want to allow. To do so, perform one of the following procedures:

  • Host the feed list on a 3rd party server
  • Virtual Server with an iRule to host the feed list

Host the feed list on a 3rd party server

  1. The Feed List format is as below:
    <IP address>,<subnet mask>,<wl/bl>

    IP address - The questionable IP addresses
    subnet mask - Subnet mask of the IP
    wl/bl - Refers to whitelist or blacklist
    , - Each of the above objects are seperated with ','

    For example, you want to add 2 whitelisted IP addresses which are 192.168.100.100 and 192.168.100.200, the Feed List will look like this:
    192.168.100.100,32,wl
    192.168.100.200,32,wl

    Save the Feed List file as a text file. For example feed.txt.

    Host the Feed List file to a HTTP, HTTPS or FTP server.

    For example if the Feed List file name is feed.txt hosted on a HTTP server with IP 10.10.10.10, the URL should be:
    http://10.10.10.10/feed.txt

    You can test if the BIG-IP AFM can fetch the Feed List with the curl command. Based on the URL above, run this command:
    curl http://10.10.10.10/feed.txt
     
  2. Login in to the Configuration Terminal.
     
  3. Navigate to Security > Network Firewall > IP Intelligence > Feed Lists.
     
  4. Click Create.
     
  5. Enter a Name for the Feed List.
     
  6. Click Add.
     
  7. Enter a Feed Name.
     
  8. Under URL, enter the URL of where the Feed List is hosted. Refer to Step (1).
    Based on example in Step (1), the URL is:
    http://10.10.10.10/feed.txt
    Note: The Feed List can be hosted on the HTTP, HTTPS or FTP server.
     
  9. Under List Type change to Whitelist.
     
  10. Under Default Blacklist Category change to the category of the questionable IP addresses.
    For example in Description, Windows Exploits was displayed so change to Windows Exploits.
     
  11. If the URL requires a Username and Password, enter it in Username/Password.
     
  12. Click Done Editing.
     
  13. If the questionable IP addresses has more than one category listed, repeat Step (6) till (12).
     
  14. Once done editing, click Commit Changes to System.
     
  15. You will need to apply the Feed List to the IP Intelligence policy. Navigate to Security > Network Firewall > IP Intelligence > Policies.
     
  16. Click on the IP Intelligence Name such as ip-intelligence.
     
  17. Under Feed Lists, select the newly created Feed List.
     
  18. Click Commit Changes to System.


Virtual Server with an iRule to host the feed list

  1. Login in to the Configuration Terminal.
     
  2. Create a new iRule by navigating to Local Traffic > iRules > iRule List.
     
  3. Click Create.
     
  4. Enter a Name for the iRule.
     
  5. Enter the follow iRule where <IP address> is/are the questionable IP address(es).
    when HTTP_REQUEST {
      if { [HTTP::uri] eq "/feed.txt" } {
        set static::MY_WL {
        <IP address>,32,wl
        <IP address>,32,wl }
        HTTP::respond 200 content $static::MY_WL
      }
    }

    For example, you want to add IP address 192.168.100.100 and 192.168.100.200, the iRule code is:
    when HTTP_REQUEST {
      if { [HTTP::uri] eq "/feed.txt" } {
        set static::MY_WL {
        192.168.100.100,32,wl
        192.168.100.200,32,wl }
        HTTP::respond 200 content $static::MY_WL
      }
    }

    Note: Each new IP address will require a new line which ends with ,32,wl where 32 refers to the subnet mask and wl refers to whitelist
     
  6. Click Finished.
     
  7. Create a new Virtual Server by navigating to Local Traffic > Virtual Servers > Virtual Server List.
     
  8. Click Create.
     
  9. Enter a Name for the Virtual Server.
     
  10. Under Destination Address/Mask, enter a new unique IP address.
     
  11. Under Service Port, select HTTP.
     
  12. Under HTTP Profile (Client), select http
     
  13. Under iRules, Enable the new iRule from Step (4) to (6).
     
  14. Click Finished.
     
  15. You can test if the BIG-IP AFM can fetch the Feed List from the Virtual Server with the curl command.
    For example. if the Virtual Server's IP is 10.10.10.10, run this command:
    curl http://10.10.10.10/feed.txt

    Based on Step (5), the output would be:
        192.168.100.100,32,wl
        192.168.100.200,32,wl
     
  16. You will now create the Feed Lists. Navigate to Security > Network Firewall > IP Intelligence > Feed Lists.
     
  17. Click Create.
     
  18. Enter a Name for the Feed List.
     
  19. Click Add.
     
  20. Enter a Feed Name.
     
  21. Under URL, enter the URL of the Virtual Server IP. Refer to Step (15).
    Based on example in Step (15), the URL is:
    http://10.10.10.10/feed.txt
     
  22. Under List Type change to Whitelist.
     
  23. Under Default Blacklist Category change to the category of the questionable IP addresses.
    For example in Description, Windows Exploits was displayed so change to Windows Exploits.
     
  24. If the URL requires a Username and Password, enter it in Username/Password.
     
  25. Click Done Editing.
     
  26. If the questionable IP addresses has more than one category listed, repeat Step (19) till (25).
     
  27. Once done editing, click Commit Changes to System.
     
  28. You will need to apply the Feed List to the IP Intelligence policy. Navigate to Security > Network Firewall > IP Intelligence > Policies.
     
  29. Click on the IP Intelligence Name such as ip-intelligence.
     
  30. Under Feed Lists, select the newly created Feed List.
     
  31. Click Commit Changes to System.

Additional Information

You can confirm if IP Intelligence is dropping the packet using the packet-tester.

  1. Login to the Configuration Terminal
  2. Navigate to Security > Debug > Packet Tester
  3. Enter the needed information
    - Souce: IP Address is the questionable IP addresses
    - Destination: IP Address is the Virtual Server's IP address
  4. Click Run Trace
  5. The output will show which AFM component is dropping the packet
