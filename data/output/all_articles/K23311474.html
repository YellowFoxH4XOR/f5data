Description
With BIG-IP APM configured as a RDP Gateway, the remote desktop connection may intermittently fails to establish.
This can happen when making usage of the BIG-IP APM "NativeRDP" class of object.
When the connection fails to establish, you may be prompted with error messages such as: "Preparing the destination computer", "Initiating remote connection".
Alternatively, BIG-IP APM may also log messages in the /var/log/apm log files:

Error {e8.C} An exception is thrown: Unexpected RDG message: 8. Expected: A - N3Rdg11DataMessageE, D - N3Rdg16KeepAliveMessageE, 10 - N3Rdg19CloseChannelRequestE, 11 - N3Rdg20CloseChannelResponseE

Environment

  • You're using BIG-IP APM v13 and above;

  • You have configure resources such as "Remote Desktop Session Host" or "Remote Desktop Web Access".

  • You may have deployed you configuration by the help of the iApp "f5.microsoft_rds_remote_access", and/or with following the instructions from the Deployment Guide https://www.f5.com/content/dam/f5/corp/global/pdf/deployment-guides/microsoft-remote-desktop-gateway-dg.pdf

Cause
This may be due to some parameters set up by the iApp, that may no longer be needed with BIG-IP APM v13.x (and onward), when using the "NativeRDP" objects.

Recommended Actions

  1. Allow modification to the iApp deployment

    1. Navigate to iApp >> Application Services >> Applications

    2. Click the name of the application as deployed by the iApp

    3. Click the tab "Properties"

    4. For "Application Service:", please select "Advanced"

    5. Locate the parameter "Strict Updates", and uncheck it

    6. Click Update

  2. Changing the settings for the client-side TCP profile

    1. Navigate to Local Traffic >> Virtual Server

    2. Click the name of the Virtual Servers as created by the iApp

    3. Locate the parameter "Protocol Profile (Client)" and take note of the name of associated object

    4. Navigate to Local Traffic >> Profiles >> Protocols >> TCP

    5. Click the name of the object noted at step #2.3 above

    6. Scroll and locate the parameter "Nagle's Algorithm" -> set it to "Disabled"

    7. Click Update at the bottom of the page

  3. Changing the settings for the VDI profile

    1. Navigate to Local Traffic >> Virtual Server

    2. Click the name of the Virtual Servers as created by the iApp

    3. Scroll down and locate the parameter "VDI Profile"

    4. Select "vdi" (the default profile).

    5. Click Update

At the end of the procedure, please click the link "Apply Access Policy" on the top left of the screen, if any.
