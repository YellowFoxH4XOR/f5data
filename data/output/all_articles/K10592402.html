Description

ASM charts missing data at Security >> Reporting : Application : Charts

Message shown is:

There is no data to display either due to the lack of relevant traffic or due to the settings of the filter.

Data was previously displayed, and the AVR statistics have not been reset.

An error similar to the following can be found in /var/lib/mysql/mysqld.err:

[ERROR] mysqld: Can't open file: './AVR/AVR_CONF_SUMMARY_TABLES.frm' (errno: 24)

Environment

  • ASM reporting
  • AVR

Cause

Too many open file handles and possible AVR database corruption.

Recommended Actions

To resolve this issue, manually clear the AVR data and create the /var/avr/init_avrdb file. This causes /AVR/AVR_CONF_SUMMARY_TABLES.frm to be re-created on next AVR start.

Important: This procedure is traffic-disrupting.

  1. Stop the ASM processes:

    tmsh stop /sys service asm monpd avrd

    tmsh stop /sys service mysql

  2. Remove the AVR files:

    rm -rf /var/lib/mysql/AVR/*

  3. Create the /var/avr/init_avrdb file:

    touch /var/avr/init_avrdb

  4. Start the mysql process:

    tmsh start /sys service mysql

  5. Start monpd, avrd, asm:

    tmsh start /sys service monpd avrd asm

  6. Verify that the /var/lib/mysql/AVR/AVR_CONF_SUMMARY_TABLES.frm file exists:

    ll /var/lib/mysql/AVR/AVR_CONF_SUMMARY_TABLES.frm

You may also consider increasing open_files_limit in /etc/my.cnf, but this is optional unless the issue happens persistently.
