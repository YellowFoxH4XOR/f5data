Known Issue

This is the result of a known issue. The BIG-IP system fails to parse a time zone containing an offset that is not a whole number when querying the IP geolocation database.

Some regions listed in the IP geolocation database use a time zone offset that includes a decimal point ( . ) For example, some Asian timezones use a UTC/GMT offset of 5.5 hours. When the BIG-IP attempts to query the IP geolocation database for a time zone containing an offset that is not a whole number (such as 5.5), the system fails to parse the data.

For example:

geoip_lookup /shared/GeoIP/F5GeoIPISP.dat 203.200.200.67

After attempting to query the IP geolocation database for an IP address that resides in a time zone that uses a UTC/GMT offset of 5.5 hours, the example geoip_lookup command returns the following partial output:

opening database in ./F5GeoIP.dat
size of geoip database = 25981368, version = GEO-146 20091027 Build 1 Copyright (c) F5 Networks Inc All Rights Reserved
geoip_seek = 00c00000

Note: BIG-IP systems use an IP geolocation database to source data about the origin of an IP address. For more information about installing updates to the IP geolocation database, refer to K11176: Downloading and installing updates to the IP geolocation database.

F5 Product Development tracked this issue as ID 226789 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.
