Description

After enabling SSL encryption for the SMTP server used in the Email agent in the APM access policy VPE, the BIG-IP is unable to send emails. As a result, users do not receive the email containing the OTP to be used for MFA on the APM, and depending on how the access policy is configured, users might be denied log on to the APM.

An error message similar to the following can be seen in /var/log/apm for the session in question

 01490194:3: /Common/test_AP:Common:7f2fe5ea: Email Agent: Message send message send failed.

Email Module: Send message failed. curl_easy_perform() returned with error : 'Operation timed out after 0 milliseconds with 0 out of 0 bytes received'

Environment

  • BIG-IP APM

Cause

BIG-IP APM e-mail agent does not support SMTP over SSL/TLS. It does not work on port 465 as well.

Recommended Actions

Do not enable SSL encryption for the SMTP server used in the APM Email Agent in the access policy VPE:
(System  ››  Configuration : Device : SMTP)

Rather use TLS encryption on port 25.

APM email agent supports deterministic SMTP which runs on TLS port 25.
