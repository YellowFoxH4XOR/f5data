Source

Description

This is a day-1 issue affecting any PQC-supported BIG-IP build where the cipher rule ordering places hybrid KEM first. 
Client-side tools (e.g., OpenSSL, curl with OpenSSL backend) report:

root@test_ubuntu:~$ curl -skv --tlsv1.2 --tls-max 1.2 https://10.10.10.100/
Trying 10.10.10.100:443...
Connected to 10.10.10.100 (10.10.10.100) port 443
ALPN: curl offers h2,http/1.1
TLSv1.2 (OUT), TLS handshake, Client hello (1):
TLSv1.2 (IN), TLS handshake, Server hello (2):
TLSv1.2 (IN), TLS handshake, Certificate (11):
TLSv1.2 (IN), TLS handshake, Server key exchange (12):
TLSv1.2 (OUT), TLS alert, illegal parameter (559):
OpenSSL/3.0.13: error:0A00017A:SSL routines::wrong curve        ### <<<===---!!!  This is the problem. 
Closing connection

Environment

  • BIG-IP TMOS 17.5.1 or later (X25519MLKEM768 support requires 17.5.1+)
  • TLS 1.2 enabled on the Client-SSL profile
  • Virtual Server

Cause

When a cipher rule is configured with hybrid KEM (Post-Quantum) algorithms listed before their corresponding classic DH-group algorithms, BIG-IP incorrectly selects the DH group ID during TLS 1.2 handshakes. The BIG-IP sends an invalid/unknown elliptic curve value in the ServerKeyExchange message, causing the client to terminate the connection with a fatal illegal_parameter alert. Bug ID 2064505

Answer/Recommended Actions

Upgrade to version 21.x.x or apply the work around below.

Use the classic DH-group algorithms first, before the hybrid KEM algorithms.

  1. Navigate to Local Traffic > Ciphers > Rules
  2. Select the existing PQC Cipher Rule you configured
  3. Set DH Groups to: X25519:X25519MLKEM768
  4. Click Update

Additional Information

Failing configuration example:

ltm cipher rule group1 {
  cipher rule1
  dh-groups X25519MLKEM768:X25519       ### <<<===---!!! Hybrid KEM first = BUG TRIGGERED
}

Working configuration example:

ltm cipher rule group1 {
  cipher rule1
  dh-groups X25519:X25519MLKEM768       ### <<<===---!!! Classic first = No issue
}
