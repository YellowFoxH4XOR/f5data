Known Issue

This is the result of a known issue. If a virtual server does not have RAM Cache enabled in its HTTP profile, and an iRule applied to the virtual server calls the CACHE::disable command, the connection is reset.

F5 Networks Product Development is tracking this issue as CR131951.

Workaround

You can work around this issue by performing one of the following actions:

  • Remove the iRule from the virtual server
  • Remove the CACHE::disable command from the iRule
  • Enable RAM Cache in the HTTP profile applied to the virtual server
