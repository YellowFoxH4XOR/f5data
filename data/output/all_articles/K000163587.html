K000163587: BIG-IP Local Account Password Policy May Not Be Enforced with Remote Authentication

Type
Support Solution
Published
2026-10-16
Updated
2026-10-16
Applies to
  • BIG-IP
  • BIG-IP LTM: 21.0.0
Source
https://my.f5.com/manage/s/article/K000163587

Description

When a remote system authentication source, such as TACACS+, is configured on BIG-IP, the local BIG-IP password policy may not be enforced when passwords for local BIG-IP accounts are created or changed.

On affected releases, a local account password that does not meet the configured minimum length, required-character, or password-aging requirements may be accepted. This can affect local system accounts, including root and admin, as well as other locally defined accounts.

The root and admin accounts are local BIG-IP accounts. Their locally stored credentials remain relevant when remote authentication is configured. Locally defined accounts are also referenced in K15596: Troubleshooting TACACS+ authentication for BIG-IP administrative users .

Environment

  • Classic BIG-IP TMOS
  • BIG-IP system user authentication configured for TACACS+
  • A local BIG-IP password policy is configured
  • A local account password is created or changed
  • An affected or unfixed BIG-IP release is in use

The same underlying behavior can also apply to other remote authentication types, including LDAP and RADIUS. TACACS+-specific conditions are a subset of the broader issue described in Bug ID1217189: RFE: Remote auth password policy enforcement .

Cause

On affected releases, configuring a remote system authentication source prevents the normal BIG-IP local password-policy checks from being applied consistently to local account password changes.

This behavior can allow local passwords that do not meet the configured password complexity or password-aging requirements. See K52045411: Secure Password Enforcement is not working for the documented behavior with remote authentication configured.

Applicability by BIG-IP release

BIG-IP conditionApplicability
Release does not contain the Bug 1217189 fixThe database-variable procedure in this article does not apply. Upgrade or use the temporary workaround described below.

Recommended actions

1. Upgrade to a release containing the fix

The Bug 1217189 family identifies the following release targets:

  • BIG-IP 17.1.3.6
  • BIG-IP 17.5.1.10
  • BIG-IP 21.1.0.3
  • BIG-IP 22.0.0

Confirm the applicable release, exact build availability, and support status against the current F5 release documentation before publishing or implementing a version-specific recommendation. Do not infer the status of one major release from another.

The parent and child bug records are available in Bug ID1217189: RFE: Remote auth password policy enforcement .

2. Enable local password-policy enforcement on a fixed BIG-IP build

This procedure applies to the Classic BIG-IP/TMOS management layer. Do not use this procedure in the F5OS system controller, chassis partition, or tenant management layer.

On a BIG-IP build containing the fix, enable the following database variable:

tmsh modify sys db users.remoteAuth.enforcepasswordpolicy value enable

The variable is disabled by default. When enabled, BIG-IP applies the configured local password policy even when the system authentication source is remote.

The database variable and its default behavior are documented in Bug ID1217189 .

Important: Do not apply the command on a release that does not contain the fix. Verify the installed BIG-IP version and build before configuring the variable.

3. Configure the local BIG-IP password policy

In the BIG-IP Configuration utility, go to:

System > Users > Authentication

Configure the required settings under Password Policy, including:

  • Secure Password Enforcement
  • Minimum Length
  • Required Characters
  • Password Memory
  • Minimum Duration
  • Maximum Duration
  • Maximum Login Failures
  • Lockout settings, where available

The BIG-IP local password policy applies to locally stored BIG-IP system accounts. Passwords for remotely stored accounts are governed by the remote identity source's own password policy.

For more information, see K15497: Configuring a secure password policy for the BIG-IP system .

4. Change existing local passwords

Enabling the policy does not automatically replace or validate passwords that were previously created. Change the password for each applicable local account after enabling the policy.

The new policy takes effect when the password is changed. See K15497: Configuring a secure password policy for the BIG-IP system .

5. Configure the remote-account policy separately

For users whose credentials are stored in the TACACS+ backend or another remote identity source, configure password complexity, expiration, and rotation requirements in that remote identity system. The BIG-IP local password policy does not control those remotely stored credentials.

6. Verify enforcement

Test with a non-production local account or during a maintenance window:

  1. Attempt to set a password that intentionally violates the configured minimum length or required-character rules.
  2. Confirm that BIG-IP rejects the password.
  3. Set a password that complies with the configured policy.
  4. Confirm that the compliant password is accepted.
  5. Repeat the test for each local account type that must be protected, including admin and, where operationally appropriate, root.

Use the Configuration utility or a supported BIG-IP/TMOS user-management method for the test. Do not edit PAM files or operating-system account databases directly.

Fallback behavior

Fallback to Local controls whether BIG-IP can use local authentication when the remote authentication service is unavailable. It does not, by itself, enable local password-policy enforcement.

The root and admin accounts remain local BIG-IP accounts; they are not remote TACACS+ user accounts. For related TACACS+ authentication behavior, see K15596: Troubleshooting TACACS+ authentication for BIG-IP administrative users .

Workaround for releases without the fix

If an upgrade is not immediately possible, the temporary workaround documented in K52045411: Secure Password Enforcement is not working is:

  1. Temporarily change the BIG-IP user directory to Local.
  2. Create or change the required local account passwords while local authentication is selected.
  3. Re-enable remote authentication.

Perform this procedure during a maintenance window because changing the authentication source can affect administrative access. This workaround is not equivalent to continuous local password-policy enforcement while remote authentication remains configured.

Additional information

  • Existing passwords that do not comply with the new policy are not automatically changed.
  • Enabling Fallback to Local does not, by itself, enable password-policy enforcement.
  • Do not modify /etc/passwd, /etc/shadow, PAM configuration files, or other BIG-IP operating-system files to implement the policy.
  • Use supported BIG-IP configuration and user-management methods when changing local account passwords.
