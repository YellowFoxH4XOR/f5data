Description

This article provides examples of common commands that you may find useful, when administering a BIG-IP VIPRION system.

Environment

  • VIPRION
  • clsh utility
  • Multiple Blades

Cause

None

Recommended Actions

As an administrator for a BIG-IP VIPRION system, the following article contains a list of common commands and actions.

Viewing the configured vCMP Guest information

Accessing a specific slot via SSH
Forcing a Primary blade to Secondary
Setting Minimum Blades up

Showing the VIPRION Cluster member

  1. To obtain the Cluster members information, type the following command:
      tmsh show sys cluster
           Example:
       [root@vhost:/S1-green-P:Active:Standalone] config # tmsh show sys cluster

      -----------------------------------------

      Availability            available
      State                   enabled
      Reason                  Cluster Enabled
      Primary Slot ID         1
      Primary Selection Time  07/23/17 22:01:49

     ----------------------------------------------------------------------------
     | Sys::Cluster Members
     | ID  Address      Availability  State    Licensed  HA      Clusterd  Reason
     ----------------------------------------------------------------------------
     | 1   172.28.67.4  available     enabled  true      active  running   Run
     | 2   172.28.67.5  available     enabled  true      active  running   Run
     | 3   172.28.67.6  available     enabled  true      active  running   Run
     | 4   172.28.67.7  available     enabled  true      active  running   Run
  •  Address in the above output is the cluster management ip address. 
  •  The primary slot always represent with the letter P and secondary with S. 
  •  Cluster member ip-address is the management ip-address of the individual blade on respective slot #

For additional information on this subject, refer to K16727: Overview of the cluster shell utility (11.x - 12.x)

Shutting Down and Restarting a single VIPRION Blade

Restarting, powering off, and powering off VIPRION Blades can be done via the following commands:
  1. Reboot a single blade:
    bladectl -b <blade#> -r
    Example: bladectl -b 2 -r
     
  2. Power Down a single blade
    bladectl -b <blade#> -p 0
    Example bladectl -b 2 -p 0
     
  3. Power On a single blade
    bladectl -b <blade#> -p 1
    Example: bladectl -b 2 -p 1
   

Accessing a specific slot via SSH

To ssh to a specific slot in a cluster use the following steps:
  1. Identify the slot to SSH into
    tmsh show sys cluster
    Example:
    [root@vguest1:/S1-green-P:Active:Standalone] config # tmsh show sys cluster

    Sys::Cluster: default

  2. Use the following command to SSH into a specific slot:
    ssh <slot number>

    Example:

Forcing a Primary blade to Secondary

  1. Locate the primary slot# by running
    tmsh show sys cluster
  2. Disable the primary slot with the following command:
    tmsh modify sys cluster default members { 1 { disabled } }
    From the above command, the primary slot# is "1" 
     


Setting the Minimum Blades Up option 


Setting minimum blades up from Standby device to ensures, standby devices are not eligible to become active due to insufficient available blades in the chassis. 
You should consider this procedure if you want to rebuild a device trust for VIPRION devices or Virtual Clustered Multiprocessing (vCMP) guests running on VIPRION devices and avoid active-active situation.

tmsh modify /sys cluster default min-up-members 5 
tmsh modify /sys cluster default min-up-members-enabled yes 

For additional information on this subject, refer to K15757. 


Rebooting or Shutting down all blades on VIPRION systems

  1. Reboot all blades on VIPRION system:
    clsh shutdown -r now
  2. Shutdown all blades on VIPRION system:
    clsh shutdown -h now
