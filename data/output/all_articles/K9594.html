Known Issue

This is the result of a known issue. As a result of changes to the hardware abstraction layer (HAL) in BIG-IP version 9.4.5, the PVA2 chip can lock up on the BIG-IP 3400, 6400 and 6800 platforms when the internal interfaces process Layer 2 pause frames. Occasionally, when the pvad process is unable to restart the PVA chip, a switchboard failsafe event occurs.

When this issue occurs, the following symptoms are likely be present on the BIG-IP system:

  • Multiple instances where the PVA2 chip locks up.

    When the PVA locks up, error messages are logged to the /var/log/ltm file that appear similar to the following example:

    pvad[1785]: 01130003:6: No.3 regWait on STATUS bit 8 failed.
    pvad[1785]: 01130003:6: PVA2 incoherency detected; synchronization required.
    pvad[1785]: 01130003:6: three FE_TEST read result: 0x100, 0x7b000dc2, 0x4afc
    pvad[1785]: 01130003:6: PVA2 synchronization complete
  • LACP packets from the switch fail to reach the host subsystem.

    When the PVA2 chip locks up and is unable to transmit LACP failsafe packets to the host, the internal interface(s) tx counter will always be about 30 seconds higher that the rx counter just prior to a switchboard failsafe event. You can identify this behavior by reviewing the the lcpd tx/rx times in /var/log/tmm file. For example:

    lac0.1 rx[OK 11357 Bad 0] tx[OK 11412 Bad 3]
    Last good rx at: 1227648470.441156
    Last good tx at: 1227648500.911676
    lac0.2 rx[OK 11360 Bad 0] tx[OK 11411 Bad 4]
    Last good rx at: 1227648470.441790
    Last good tx at: 1227648500.911714
  • Switchboard failsafe instances following the PVA lock ups.

    In the event of an internal interface failure, the lacpd process notifies the failover daemon through the high availability (HA) table, and a switchboard failsafe event occurs. When switchboard failsafe occurs, error messages are logged to the /var/log/ltm file that appear similar to the following example:

    lacpd[1690]: 01160018:1: Internal link 0.1 is UNAVAILABLE.
    lacpd[1690]: 01160018:1: Non working internal trunk member 0.1 triggers switchboard failsafe take action.
    lacpd[1690]: 01160016:6: Interface 0.1, link admin status: enabled, link status: up, duplex mode: full, lacp operation state: down
    lacpd[1690]: 01160013:1: Switchboard FailSafe take action is set
    lacpd[1690]: 01160018:1: Internal link 0.2 is UNAVAILABLE.
    sod[1786]: 01140029:5: HA switchboard_failsafe lacpd_d fails action is failover and abort tm.
    sod[1786]: 010c0026:5: Failover condition, active attempting to go standby.

  • The BIG-IP system produces a TMM core file.

    The TMM core file is output to the /var/core/ directory due to the switchboard failsafe event.

Note: This issue has been known to occur on BIG-IP platforms containing the PVA2 chip. This issue has not occurred on BIG-IP platforms that do not contain a PVA chip. For example, this issue has not occurred on the following platforms:

  • 1500, 1600, or 3600 BIG-IP platforms
  • older platforms that contain the original PVA
  • newer platforms that contain the PVA10 chip (such as the 8400, and 8800).

F5 Networks Product Development tracked this issue as CR107486 and it was fixed in BIG-IP versions 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator Release Notes.

Workaround

To work around this issue, you can disable pause frames on the system on a per-interface basis, by performing the following procedures:

Important: The following changes are not persisted across a reboot and will not be saved to a BIG-IP configuration file after they are entered.

Disabling pause frames for interface 0.1 on the 3400 platform

To disable pause frames on the 3400 platform, type the following command:

bigpipe interface 0.1 pause rx -j

Disabling pause frames interfaces 0.1/0.2 on the 6400 or 6800 platforms

To disable pause frames on the 6400 or 6800 platforms, type the following commands:

bigpipe interface 0.1 pause rx -j
bigpipe interface 0.2 pause rx -j
