Description

Occasionally, new TCP connections (SYNs) can be unsuccessful when BIG-IP creates a new connection to highly loaded servers.

| Client             |      | BIGIP              |      | Server             |

                ACK ------------->

                                              SYN ------------> 
                                              SYN ------------> 
                                              SYN ------------>

Environment

  • BIG-IP
  • virtual server with a TCP profile
  • the pool member or server has a different TIME_WAIT timeout than the BIG-IP's TCP profile

 

Cause

This problem may happen if a connection that was previously used, is re-used too early.

A server will drop all new packets that belong to the same src/dst IP/port tuple as long as the server keeps the connection in the TIME WAIT state. The purpose of the TIME WAIT state is defined in the TCP standard RFC 793 to ensure that any packets belonging to that connection is drained from the network before allowing that connection to be re-used.

In this problem scenario, the BIG-IP may reuse the connection faster than the server times out the connection. This results in the server dropping the new connection SYN packet from the BIG-IP.

Some older systems use a long default TIME WAIT timeout of 240 seconds, newer servers may have a lower default value of 60 seconds. The BIG-IP's TCP profile has a default TIME WAIT timer of 2 seconds before allowing the connection to be re-used.

Therefore, if the BIG-IP reuses the connection within 2 seconds, and the server's time wait is at 60 seconds, then the server will drop any new packets from BIG-IP using that connection's src/dst IP:port tuple since it is still in a TIME WAIT state.
 

Recommended Actions

  1. Set the TIME WAIT state on the pool member servers to be lower than the BIG-IP TCP profile.
    Note: The TIME WAIT setting is dependent on the Operating System the application server is running on. To configure this setting, refer to the operating system's documentation.
    This will avoid servers from dropping new connections from the BIG-IP.
     
  2. Try using the same ports between the virtual servers and pool members.
    This problem may be seen more often when virtual servers use different ports than the pool members, as this causes the BIG-IP to try to change the source port more often, therefore increasing the probability of the new connection clashing with an exsiting connection in the TIME WAIT state. Refer to: K85447165: The serverside source port is not preserved when the virtual server and pool member use different ports


What is a good time wait state value?

The original purpose of the TIME_WAIT timeout in the TCP standard is 2*MSL, which aims to drain any remaining packet still floating in the network that belongs to the closed connection. The aim is to guarantee that packets from old connections cannot interfere with any newly created connections. The lower the network quality, the higher the probability these packets stay in the network. Older systems may see the default TIME WAIT timeout set to 240 seconds, newer servers can be seen to set this at 60 seconds.

As a general rule, a shorter TIME WAIT timeout may improve the efficiency of the systems.

  • A longer TIME WAIT state will reduce the number of connections per second capacity for each IP address that accesses the server.
    For example: 
    - using a 60 second timeout, the maximum sustainable rate could go to 1,075 connections per second, 
    - while a 240 second timeout lowers that to 268 connections per second.
     
  • A longer TIME WAIT setting on a system may require the server to use up more memory to store connections in a TIME WAIT state.
     
  • A shorter TIME WAIT setting on a server may improve server performance. Having a high amount of connections may reduce server performance as it will need to spend more time to match packets to connections.


You may wish to consult your server's documentation to fine tune your server's setting to either lower the TIME WAIT timeout timer, or enable earlier connection reuse.
 

Additional Information

In this case, if the server closes the connection first by sending a FIN, it will then enter the TCP TIME WAIT state. In a TIME WAIT state, the server it will drop any new SYNs sent from the BIG-IP using the same src port.
