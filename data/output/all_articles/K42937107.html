Description
When creating or modifying configuration for remote authentication of administrative users, attempts to log in with remote user accounts fail. You expect this traffic to the AAA server to use the management interface. You may observe in a packet capture that a TMM (data plane) VLAN is used for this communication instead.

You see in tmsh that there is no existing configuration for this management route other than the default route.
tmsh list /sys management-route all-properties

This command shows a TMM network route via a VLAN.
ip route get <new remote auth server IP>

Environment

  • BIG-IP device administrator user accounts are remotely authenticated
  • Remote authentication server not on same subnet as management IP
  • Most specific management route has same scope as a TMM route

Cause
TMM routes have a lower metric than management routes of the same scope, so the TMM default route is preferred over the default management route.

You must use the CLI to create a more specific management route for the new destination.

Recommended Actions

Add a more specific management route using tmsh commands as described in K13284: Overview of management interface routing (11.x and later). Note that you must save the tmsh configuration for this to persist across reboots.

Example:
tmsh create /sys management-route <name> network <destination network>/<netmask> gateway <management gateway>
tmsh save /sys config
