Issue

You should consider using this procedure under the following conditions:

  • Windows users connect to the BIG-IP APM system to establish access sessions.
  • You want to troubleshoot access session connection issues.

Symptoms

As a result of access session issues, you may encounter the following symptoms:

  • Access session users are unable to establish an access session.
  • Access session users are unable to access configured resources.

Recommended Actions

This article provides suggestions for troubleshooting common connectivity and logon issues that occur when you access a BIG-IP APM system as an access user from a Microsoft Windows system.

Important: F5 supports BIG-IP APM system software and F5 Access and BIG-IP Edge Client software. F5 does not support third-party software, such as the client operating system, third-party VPN applications that are installed on the client system or security software. For more information refer to K23653432: BIG-IP APM client feature matrix and K54542541: Compatibility testing for third-party VPN products.

Procedures

When you experience access session issues, you can use the following troubleshooting steps to determine the root cause:

  • Verifying the client system
  • Troubleshooting endpoint inspection and login failures
  • Common errors displayed on the client

Verifying the client system

  • For a client to establish network access, you must ensure that basic system requirements are met by performing the following actions:

    • Establish local system or user rights. F5 Access and BIG-IP Edge Client components may require that you have elevated privileges to properly install or update software on the Windows system. Other users of the device can access BIG-IP Edge Client components installed on the device and these users may run these components even if they do not have local administrator privileges. If you experience problems with the BIG-IP Edge Client connecting, installing updates, or completing endpoint inspection, verify that the proper rights are in place for the user who is logged in.

    • Verify basic TCP/IP connectivity on the client system using tools such as ping and tracert. For more information about troubleshooting TCP/IP connectivity, refer to the third-party websites related to the specific version of the Windows operating system.

    • Verify DNS resolution is correct for the fully qualified domain name (FQDN) of the BIG-IP APM virtual server in which network access connections are terminated using appropriate operating system utilities such as nslookup.

  • Attempt to reproduce the issue on other systems that run the same version of Microsoft Windows as the affected client system.
    • If possible, ensure the other systems have the same service packs and Windows hotfixes or updates as the affected client system.

    Important: Windows client systems that are members of a Windows domain may have a group policy that affects the operation of the network access (VPN) connection. F5 recommends you attempt to reproduce the issue using at least one system that is not a member of the Windows domain.

  • Ensure no processes are running that may interfere with a network access or application access connection, such as personal firewalls, which prohibit these connections or another vendor's VPN software. Temporarily disable all anti-virus, firewall, and other security software on the client system while troubleshooting the issue. You can use the tasklist command on a Windows command prompt to list the running processes on the client device.
  • Ensure the client system has sufficient available CPU and memory to launch additional processes, such as the BIG-IP Edge Client components.
  • Remove and re-install all F5 Access or BIG-IP Edge Client components on the client system. For more information about removing BIG-IP Edge Client components, refer to: K8253: Removing BIG-IP Edge Client components from Windows client systems.

Troubleshooting endpoint inspection and login failures

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  • To troubleshoot endpoint inspection failures, review client endpoint inspection data to determine if endpoint security checks are failing.

    • Session variable details for user access sessions can be viewed through the BIG-IP APM Configuration utility by navigating to Access > Overview > Access Reports (BIG-IP 13.x and later) or Access Policy > Reports > Session Reports (BIG-IP 11.x - 12.x) and viewing the individual access session information. For more information refer to: K11253: Session variable logging within an access policy.

    • Verify the third-party software installed on the client system and the type of endpoint inspection check being performed is supported by the OPSWAT SDK installed on the BIG-IP system. For more information refer to K12385: OPSWAT support chart and K11643: Troubleshooting with the OPSWAT OESIS Diagnose tool.

  • For more information on troubleshooting login failures, refer to K35932460: BIG-IP APM operations guide | Chapter 10: Troubleshooting.

Common Errors displayed on the client

The following errors may display on the client:

  • Failed to initialize local Tunnel Server
    • The Tunnel Server component handles the SSL connection between the BIG-IP APM system and the client for application tunnel and network access connections. The Tunnel Server component creates a local TCP socket so that it can communicate with the VPN driver. The Tunnel Server component then proxies communication back to the BIG-IP APM system. If the Tunnel Server service cannot start, network access connection attempts fail. Possible causes for Tunnel Server failure component failure include the following:
      • Local port conflict. For more information refer to K17372: Overview of ports used by the BIG-IP Edge Client for Windows and check for port conflicts on the local machine.
      • Corrupt installation. Remove and reinstall the BIG-IP Edge Client components. For more information refer to: K8253: Removing BIG-IP Edge Client components from Windows client systems.
  • Waiting to Connect to Server...
    • The BIG-IP Edge Client cannot resolve the server name.
  • Failed validation 
    • When the security software installed on the client system does not meet the security policy requirements configured on the BIG-IP APM system, the VPN establishment will fail.
      • On the client system, verify that your security software is installed and updated and meets the security policy requirements of your organization.
      • On the BIG-IP system, verify that the EPSEC (antivirus) version is updated, by typing the following command: 

        tmsh show /apm epsec software-status

        For more information, refer to K48955220: Installing an OPSWAT Endpoint Security update on BIG-IP APM systems (11.4.x and later)

      • On the client system, generate the antivirus (OESIS) logs to investigate if any antivirus packages are installed. Also verify whether any unknown or unnecessary security software packages are installed on the client system. For more information, refer to K11643: Troubleshooting with the OPSWAT OESIS Diagnose tool.

If you performed all of the troubleshooting steps outlined in this article but could not resolve the issue and the issue can only be reproduced on a single Windows system or a small group of Windows systems, you may need to reinstall the Windows operating system on the affected client systems.

Important: Perform this step at your own risk. F5 is not responsible for any issues arising from reinstalling the operating system. Some issues can only be resolved by reinstalling the operating system, especially in cases where the client system was corrupted due to malicious software, disk failure, or other hardware issues.
