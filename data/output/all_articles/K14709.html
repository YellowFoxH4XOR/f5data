Topic

This article applies to BIG-IP ASM 11.4.0 and later. For information about other versions, refer to the following articles:

  • K22021244: Bypassing the BIG-IP ASM system (12.1.0 and later)
  • K10479: Bypassing the BIG-IP ASM system with an iRule (10.x - 11.3.0)

You should consider using this procedure under the following condition:

  • You want to enable or disable BIG-IP ASM processing for certain requests.

Description

Beginning in BIG-IP ASM 11.4.0, you can use either the Local Traffic Policy feature or an iRule to enable or disable BIG-IP ASM processing for certain requests.

The Local Traffic Policy feature

By default, a BIG-IP ASM-enabled virtual server is associated with a local traffic policy containing only one rule that directs all traffic for BIG-IP ASM processing based on the assigned security policy. You can create additional rules to disable BIG-IP ASM processing for traffic that matches certain conditions. When you create additional rules in a local traffic policy, you should ensure that the rules are ordered so the more specific conditions are listed before the less specific conditions. The BIG-IP system processes local traffic policy rules sequentially in a prioritized list.

iRules

With the introduction of the Local Traffic Policy feature, the HTTP Class profile and the related iRule commands and events, such as HTTP_CLASS_SELECTED, are no longer available. To enable or disable the BIG-IP ASM processing for certain requests or connections using an iRule, you must use the following iRule commands in the HTTP_REQUEST iRule event, where <policy name> denotes the name of the desired BIG-IP ASM security policy:

  • ASM::disable
  • ASM::enable <policy name>

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP ASM system.
  • You have basic working knowledge of either iRules or the Local Traffic Policy feature.
  • You have an existing BIG-IP ASM virtual server.

Procedures

To disable BIG-IP ASM processing for certain requests using the Local Traffic Policy feature, perform the following procedure:

  • Configuring a Local Traffic Policy rule to bypass the BIG-IP ASM system

To enable or disable BIG-IP ASM processing for certain requests using an iRule, perform the following procedures:

  • Configuring an iRule to bypass the BIG-IP ASM system
  • Associating the BIG-IP ASM bypass iRule to the BIG-IP ASM virtual server

Configuring a Local Traffic Policy rule to bypass the BIG-IP ASM system

Impact of procedure: Reordering rules in an incorrect priority may yield unexpected results. Ensure the order of the rules meet the requirements for your application environment.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Virtual Server List.
  5. Under the Resources column for the desired ASM-enabled virtual server, click Edit.
  6. In the Policies section, click the name of the desired ASM-enabled local traffic policy.
  7. To create a new rule, in the Rules section, click Add.
  8. In the Rule Name section, enter a name for the new rule.
  9. In the Conditions section, select/enter the desired values for the Operand, Event, Selector, Condition and Values settings.

    For example, you would select/enter the following options for the described settings if you want the rule to match HTTP requests that contain the word bypass in the request URI:

    • Operand: http-uri
    • Event: request*
    • Selector: path
    • Condition: contains
    • Values: bypass
  10. For the Values setting, to add the desired value you have entered, click Add.
  11. In the Conditions section, to add the condition to the table, click Add.
  12. In the Actions section, select the desired values for the Target, Event and Action settings.

    For example, you would select the following options for the described settings to disable ASM processing for the condition that matches HTTP requests containing the word bypass in the request URI created in step 9:

    • Target: asm
    • Event: request
    • Action: disable
  13. To add the action to the table, in the Actions section, click Add.
  14. Click Finished.
  15. On the Local Traffic Policies List page, click the name of the ASM-enabled local traffic policy.
  16. In the Rules section, click Reorder.
  17. Drag the ASM bypass rule created in steps 7 to 14 to prioritize it over the default rule for the ASM-enabled local traffic policy.
  18. Click Update.

Configuring an iRule to bypass the BIG-IP ASM system

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. In the Name box, enter a name for the iRule.
  7. In the Definition box, enter the iRule syntax.

    Note: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment. Additionally, adding an iRule increases the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

    For example:

    when HTTP_REQUEST {
    if {[HTTP::uri] contains "/bypass/path" } {
    ASM::disable
    log local0. "ASM disabled."
    } else {
    ASM::enable /Common/myasmpol
    log local0. "ASM enabled. Current ASM policy is [ASM::policy]"
    }
    }

  8. Click Finished.

    Note: The 'contains'  function is a sub-string match that interprets the string value literally. Do not use wildcards or end the path with a forward slash (/). For example, use /bypass/path. Do not use /bypass/path/  or /bypass/*. Using incorrect strings prevents the iRule from functioning as intended.

Associating the BIG-IP ASM bypass iRule to the BIG-IP ASM virtual server

When you create the iRule, you must assign it to the desired BIG-IP ASM-enabled virtual server. To do so, perform the following procedure:

Impact of procedure: Depending on the type and volume of the connections, the iRule processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click Virtual Server List.
  5. Under the Resources column for the desired ASM-enabled virtual server, click Edit.
  6. Click Manage for the iRules section.
  7. In the Available box, select the iRule created in the previous procedure.
  8. Click << to move the desired iRule to the Enabled box.
  9. Click Finished.
