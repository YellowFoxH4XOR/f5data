Known Issue

The VIPRION system may fail to reconnect to the SafeNet hardware security module (HSM) after a system reboot.

This issue occurs when all of the following conditions are met:

  • You have a multiple blade VIPRION system.
  • The system uses the SafeNet HSM to protect Secure Sockets Layer (SSL) keys.
  • The system has rebooted, or all services have been restarted.

Impact

Client SSL connections will fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Client SSL connections fail for secure Web sites that use SafeNet HSM protected SSL keys.
  • In the /var/log/ltm file, you observe messages similar to the following example:

    err pkcs11d[12345]: 01680002:3: pkcs11 initialization error.
    err pkcs11d[12345]: 01680002:3: pkcs11 daemon needs to be restarted. error.

Workaround

There is no workaround for this issue. To restore connectivity to the remote SafeNet HSM, restart the pkcs11d process on all secondary blades. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the VIPRION system.
  2. To determine the secondary blades, run the following command:

    # tmsh show sys cluster

  3. In the command output, look for Primary Slot ID.

    Note: All blades other than the Primary Slot ID are the secondary blades.

    ---------------------------------------
    Sys::Cluster: default
    ---------------------------------------
    Address 172.24.21.35/24
    Availability available
    State enabled
    Reason Cluster Enabled
    Primary Slot ID 2
    Primary Selection Time 1440510513

    -----------------------------------------------------------------------------
    | Sys::Cluster Members
    | ID Address Availability State Licensed HA Clusterd Reason
    -----------------------------------------------------------------------------
    | 1 172.24.21.34 available enabled true active running Run
    | 2 172.24.21.33 available enabled true active running Run
    | 3 172.24.21.32 available enabled true active running Run
    | 4 172.24.21.31 available enabled true active running Run

  4. To restart pkcs11d on a secondary blade, use the following command syntax:

    ssh slot<secondary_blade_#> 'bigstart restart pkcs11d'

    For example, to restart pkcs11d on secondary blade 1, type the following command:

    ssh slot1 'bigstart restart pkcs11d'

  5. Repeat step 4 for all other secondary blades.
