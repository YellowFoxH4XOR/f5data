K000129555: Custom user associated with resource group is unable to deploy configuration changes to managed BIG-IPs

Type
Support Solution
Published
2022-12-11
Updated
2022-12-11
Source
https://my.f5.com/manage/s/article/K000129555

Description

A BIG-IQ user with custom role is unable to deploy configuration changes to BIG-IPs for objects in the associated resource group.


On BIG-IQ versions >= v7.0.0.1, BIG-IQ throws the following warning even if the user is associated with "Resource Group Deployer" role:

 

Access Denied Warning

1. You are not authorized for: Device Association

Details:

POST to /mgmt/cm/global/utility/device-association is unauthorized.

 

Environment

  • BIG-IQ
  • Custom user or role with associated resource group.

 

Cause

  • Feature is yet to be fully implemented in RFE ID 759383.

Recommended Actions

 

1. Perform the steps indicated in the workaround section of ID843305 to create 2 custom resource groups. Here are the Bash commands which should be executed as root on the BIG-IQ:


restcurl -X POST /shared/authorization/patch-resource-groups -d '{"resourceGroupName":"Relevant Devices Resource Group","resourceGroupDisplayName":"Relevant Devices Resource Group" ,"resourceGroupDescription":"Resource group containing relevant devices API for use with deployment","referenceExpressionsPatches":[{"targetKind":"cm:global:utility:device-association:deviceassociationstate" ,"referenceExpressions":[{"expression":"/cm/global/utility/device-association"}]}]}'


restcurl -X POST /shared/authorization/patch-resource-groups -d '{"resourceGroupName":"Deploy Configuration Resource Group" ,"resourceGroupDisplayName":"Deploy Configuration Resource Group","resourceGroupDescription":"Resource group containing relevant deploy API for use with deployment" ,"referenceExpressionsPatches":[{"targetKind":"cm:adc-core:tasks:deploy-configuration:deployconfigtaskstate","referenceExpressions":[{"expression":"/cm/adc-core/tasks/deploy-configuration/*"}]}]}'

 

2. Attach these resource groups ("Relevant Devices Resource Group" and "Deploy Configuration Resource Group")  to either a custom role which the user belongs to, or directly to the user together with the desired configuration objects' (ie. virtual servers, pools, etc.) resource groups.

 

Additional Information

None.
