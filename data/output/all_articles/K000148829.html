Description

A BIG-IP LTM device hosts Virtual Servers. The virtual-addresses are configured with route-advertisement selective (Route Health Injection). Router BGP configuration defines eBGP neighbor relationship to advertise Virtual Server addresses to external router network. 

However, the Virtual Server addresses are not being advertised to eBGP neighbors, which are typically a core router network.

Environment

  • BIG-IP LTM with Advanced Routing Module provisioned
  • Route Domain with BGP routing-protocol enabled
  • eBGP neighbor configuration (BIG-IP has different Autonomous System Number from router network) 
  • LTM virtual-addresses configured with Route Health Injection (RHI), or route-advertisement selective

Cause

Performed a routing policy configuration change on BIG-IP, such as a route-map or prefix-list, within imish on an affected version of BIG-IP. Did not reset BGP session to propagate the routing policy changes from LTM to an eBGP neighbor.

ID605966 (BGP route-map changes may not immediately trigger route updates) is fixed in 17.1.2 and 16.1.5. However, affected BIG-IP versions will not automatically advertise the updated route-map policy changes to eBGP neighbors, and manual intervention (BGP outbound soft reconfiguration) is required. 

Recommended Actions

BGP outbound soft reconfiguration (soft reset) will apply the BGP routing policy changes to BGP neighbor advertisements (RIB-OUT), without disrupting the network, and achieve a state of convergence. A hard reset would be a disruptive event, as the BGP session is torn down, and is not generally advised.

clear ip bgp [eBGP neighbor IP address] soft out

To perform a soft reconfiguration for the route policy updates to all BGP neighbors:

clear ip bgp * soft out

The advertised routes to a BGP neighbor can be seen in the show ip bgp neighbor x.x.x.x advertised-routes command output.

If there was a recent routing policy change, such as updating a route-map for outbound traffic to the eBGP neighbor, the following procedure will show the advertised routes before and after the routing policy change. 

show ip bgp neighbor x.x.x.x advertised-routes 
clear ip bgp x.x.x.x soft out
show ip bgp neighbor x.x.x.x advertised-routes

As an example, the prefix-list "prefix_example" is configured to filter route-map "TO_localhost3". The Virtual Server address will be defined as  host address 10.2.115.162 with /32 subnet mask (10.2.115.162/32) in the prefix-list on localhost2 (10.2.115.171 local self IP and 10.2.115.169 floating self IP, AS 255), and the route-map will only let allowed RHI addresses be advertised outbound to eBGP neighbor localhost3 (10.2.115.172, AS 365) .

Additional Information

When verifying any BGP routing policy changes, allow some time for BGP update messages to reach neighbors and process the latest NLRI (Network Layer Reachability Information) in their respective BGP RIB (Routing Information Base, as observed in command show ip bgp), neighbor (show ip bgp summary or show ip bgp neighbors) and routing tables (show ip route bgp). 

As BGP operates at Layer 7, there can be a noticeable delay after the soft reconfiguration and when the Virtual Server address is actually being advertised to the eBGP neighbor. Convergence should happen in seconds, possibly longer, depending on the size of the configuration and network topology.
