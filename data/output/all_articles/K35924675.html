Description

An Apple iPad that was previously working to connect to a F5 SSL VPN, will no longer connect.

Previously, F5 Access running on iPhone or iPad devices identified themselves as an “iOS” device (session variable session.client.platform is populated with “iOS” string); from this new version of F5 Access running on iPadOS it identifies itself as “iPad” (session variable session.client.platform will be “iPad”).

Environment

  • BIG-IP APM VPN
  • Access Policy has Client OS checking agent
  • Was running F5 Access for iOS 3.0.7 from the Apple Store
  • Upgraded to F5 Access for iOS 3.0.8 from the Apple Store

Cause

There has been a change of behaviour of the Access Policy to match Apple splitting iOS into iPadOS for the iPads and leaving iOS just for the iPhones

Recommended Actions

If an access policy has Client OS checking agent to distinguish iOS devices, as a BIG-IP APM administrator, you can re-configure the agent like below to get iPad treated identically to iOS:
 
VPE: Client OS -> Click change from iOS branch -> Advanced Tab:

  • current string: expr {[mcget {session.client.platform}] == "iOS"}
  • change it to:   expr {[mcget {session.client.platform}] == "iOS" || [mcget {session.client.platform}] == "iPad"}


There is no action required at the iPad, these changes need to be made by the APM administrator in the policy VPE. Once an iPad is upgraded, Apple provides no way to revert to a previous app version.

Additional Information

The change above allows you to keep the old behavior and make both devices follow the same path. You now also have the option of applying different policies to iPad and iPhone devices. If this is desired, add in an additional branch path for the 'iPad".
