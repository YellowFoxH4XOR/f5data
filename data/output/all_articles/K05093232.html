K05093232: Authentication for root or admin user accounts does not work after system boot

Type
Support Solution
Published
2021-07-04
Updated
2025-08-27
Applies to
  • BIG-IP Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K05093232

Description

Authentication for local only users such as root and admin accounts does not work when the remote authentication is available. You may experience this as the root and admin users can not log into the BIG-IP system after completing the boot cycle.

Environment

  • BIG-IP
  • User accounts
  • Remote authentication
  • User with admin role exists locally (not the default root and admin) i.e. test_admin
    auth user test_admin {   <<<
        description test_admin_user
        partition-access {
            all-partitions {
                role admin   <<<
            }
        }
        shell bash           <<<
    }

Cause

The BIG-IP system is configured local authentication only as a backup method for remote authentication.

Recommended Actions

You can enable local authentication for local only users by following the steps below.

  1. Log in to tmsh with admin role (i.e. test_admin) by typing the following command:

    tmsh

  2. Set the systemauth.nolocalonly database key to false by typing the following command:

    modify /sys db systemauth.nolocalonly value false

Local only users such as root and admin accounts of the BIG-IP system are now can use local authentication even the remote server is available.

Additional Information

As a part of configuring local authentication as a backup method for remote authentication, you might have completed the following tasks.

  • Configuring local authentication as a backup method when the remote authentication server is unavailable
  • Configuring the default BIG-IP root and admin accounts to use remote authentication

It is enforcing the root and admin accounts to use remote authentication by setting the systemauth.nolocalonly database key to true.
The default value of this database key is false. You can verify this by following the steps below.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. View the systemauth.nolocalonly database key value by typing the following command:

    list /sys db systemauth.nolocalonly value

  3. The value will be displayed similar to below:

    sys db systemauth.nolocalonly {
        default-value "false"
        value "false"
        value-range "false true"
    }
