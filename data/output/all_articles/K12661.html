Known Issue

This is the result of a known issue. Single Sign-On (SSO) configurations that use NTLMv2 as the authentication method may fail to authenticate properly against Windows 2008 servers.

The BIG-IP APM does not handle LMv2 responses in the manner that the Windows 2008 server expects. NTLMv2 sends two 16-byte responses to an 8-byte server challenge. The response consists of the HMAC-MD5 hash of the server challenge, a randomly generated client challenge, and an HMAC-MD5 hash of the user's password and other identifying information. The two responses differ in the format of the client challenge. The shorter response uses an 8-byte random value for this challenge. In order to verify the response, the server must receive the client challenge as part of the response. For this shorter response, the 8-byte client challenge appended to the 16-byte response makes a 24-byte package, which is consistent with the 24-byte response format of the previous NTLMv1 protocol. The shorter response is termed LMv2; the longer formatted response is termed NTv2. The Windows 2008 server expects a response formatted in the LMv2 format; however, the BIG-IP APM sends the longer response in the NTv2 format.

F5 Product Development tracked this issue as ID 225149 (formerly CR138652), and it was fixed in BIG-IP APM version 10.2.2.

This issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP APM version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
