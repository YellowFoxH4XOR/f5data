Description

IPsec phase 2 (Quick Mode (QM)) fails to start after upgrade to v16 or v17

Environment

  • BIG-IP terminating IPsec configured for ISAKMP version 1 (IKEv1)

  • IPsec traffic to remote peer not in route-domain (RD) 0
  • Upgrade to version 16.x or 17.x

Cause

No response by BIG-IP to QM packet from peer. Defect ID1812349 applies.

Answer/Recommended Actions

Use IKEv2, this will require that the remote peer is also reconfigured to IKEv2.

Alternatively, move IPsec peer traffic to use RD0.

Additional Information

If changing Ike version, be aware of K44102664: IPsec IKEv1 and IKEv2 tunnels must use a unique local IP

Issue was seen after upgrade from version 14.1.x, other upgrade paths will be similarly affected.
