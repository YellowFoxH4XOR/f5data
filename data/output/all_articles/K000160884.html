K000160884: Partition and Controller Backup File Deletions Are Not Propagated to Standby Controller

Type
Support Solution
Published
2026-04-19
Updated
2026-04-19
Applies to
  • F5OS
  • F5OS-C: 1.6.0, 1.8.X, 1.6.X, 1.8.2, 1.8.1, 1.8.0, 1.6.4, 1.6.2, 1.6.1
Source
https://my.f5.com/manage/s/article/K000160884

Description

When a controller or a partition backup is created on an F5OS VELOS system, the backup file is synchronized to both system controllers. However, when the backup file is deleted via the GUI, F5SH, or API, the file is only removed from the active controller. The corresponding file on the standby controller remains.

Environment

  • F5OS VELOS platform
  • Dual system controllers (one active, one standby)
  • Chassis Controller or Chassis Partition backups managed via GUI, F5SH, or API

Cause

The root cause is that synchronization mechanism for partition backup files does not propagate deletions from the active to the standby controller. The rsync process is configured without the --delete flag, so when a backup file is deleted on the active controller, the corresponding file on the standby controller is not removed. This results in stale backup files accumulating on the standby controller. This is being tracked by bug ID 2277993.

Answer/Recommended Actions

To remove stale backup files from the standby controller, manually SSH into the standby controller of the controller or partition HA and delete the files using the following command from Bash CLI:

 

For controller backups:

ssh controller-<standby_id> 'rm /var/confd/configs/<backup_name>'

 

For partition backups:

ssh controller-<standby_id> 'rm /var/F5/partition<N>/configs/<backup_name>'
