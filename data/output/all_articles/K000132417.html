Source

Description

Not able to access BIG-IQ GUI "Waiting for BIG-IQ services to become available":

  • Database not starting
  • Postgress generated core files in /shared/core/
  • /var/log/postgres/postgresql-<date>.log logs throws Cannot allocate memory errors:

2023-01-12 23:59:59.803 +04 [94072] FATAL: the database system is starting up

2023-01-12 23:59:59.992 +04 [94070] PANIC: could not flush dirty data: Cannot allocate memory

2023-01-13 00:00:00.810 +04 [94106] FATAL: the database system is starting up

  • /var/log/kern.log contains filesystem corruption errors:

Jan 22 12:03:08 localhost.local warning kernel: JBD2: Spotted dirty metadata buffer (dev = dm-2, blocknr = 0). There's a risk of filesystem corruption in case of system crash.

Environment

  • BIG-IQ Centralized Management
  • GUI not starting
  • Postgress cores
  • Postgress not starting
  • Disk Errors in kern.log

Cause

Filesystem corruption cause postgressql startup issue

Recommended Actions

Repair filesystem errors by running fsck from MOS

  1. Login via console and make sure you have access
  2. Run mosreboot to reboot into MOS
  3. Run fsck -f -y /dev/mapper/vg--db--vda-set*
  4. Run reboot to reboot back into TMOS
  5. Once the device comes up, login into the F5 and go this directory cd /var/log/
  6. Then, we have to review the /var/log/kernel.log file in order to verify that inode errors has been stopped
