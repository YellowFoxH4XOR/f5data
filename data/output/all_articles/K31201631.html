Description

TCP syn request is rejected with F5 reason code "Rejected by IPsec policy".

Environment

  • BIG-IP is terminating IPsec  using interface mode

Cause

TCP 4-tuple (source/destination IP/port) not matching configured traffic-selector (TS)

Recommended Actions

  1. Configure TS to include all traffic to be protected over the IPsec tunnel.
  2. Ensure that the IPsec peer is configured to match.
  3. You can only configure a single traffic-selector when using interface mode.

Or

  • Use NAT or SNAT to adapt the 4-tuple to fall within the configured TS

Or

  • Disable sys db ipsec.if.checkpolicy (see K31553030: Overview of the ipsec.if.checkpolicy database key)

Additional Information

If the routing table routes the SYN into the IPsec interface tunnel, but the request fails to match the traffic-selector then this reason code will be appended to the reset.

09:12:18.101293 IP 192.168.1.1.55290 > 172.16.1.1.443: Flags [S] ...
09:12:18.101331 IP 172.16.1.1.443 > 192.168.1.1.55290: Flags [R.] ... rst_cause="[0x2448036:5451] Rejected by IPsec policy."

You can see that the source IP 192.168.1.1 does not fit to the source traffic selector 10.0.0.0/16

net ipsec traffic-selector sample-TS {
    destination-address 172.16.1.0/24
    ipsec-policy sample-ipsec-policy
    order 1
    source-address 10.0.0.0/16
}
net route remote-site {
    interface /Common/ipsec-tunnel-interface
    network 172.16.1.0/24
}
