Topic

You should consider using this procedure under the following condition:

  • You want to use F5 SDK to deploy a BIG-IP configuration with a declarative onboarding (DO) declaration template.
  • You want to learn how to use DO declaration templates so you can apply the skill to your own DO declarations.

Description

When deploying a DO declaration using F5 SDK, it can be helpful to turn the declaration into a template for repeated deployments. You can do this with the Jinja2 python package. This article shows an example program for achieving this task. The example DO declaration deploys a network and DSC configuration on two BIG-IP systems to attain high availability (HA); however, after performing the procedures in this article you will have the skills to run the program with your own DO declaration templates.

Note: F5 recommends first running the example program on devices in a test environment to understand how it works.

Important:

  • This article is for demonstration purposes only because the Jinja2 Python package and the example Python module and script are not supported by F5. If you have questions about the content in this article, select Leave feedback on this article at the bottom of the page or post a comment to the companion DevCentral article, Create a declarative onboarding template to use with F5 SDK.
  • After you initially configure a BIG-IP device with DO, adding subsequent declarations to the same device that leave out properties you initially used will result in those properties being restored to the original values; however, DO never un-licenses a device, never deletes a user, and never breaks device trust.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You are proficient with the Python programming language.
  • Your workstation is running a Linux operating system.
  • Your workstation has Python 3.x installed. For more information, refer to the Python installation steps in K95000711: Setting up Ansible on a Linux host.
  • You have met the prerequisites outlined in Prerequisites and Requirements page of the DO documentation.
  • If you are using the example DO declaration, DSC_VLAN_template.json, you have two BIG-IP devices that you want to configure in a device group, also called a high availability (HA) pair. The devices must have network connectivity to each other and meet these requirements outlined in K8665: BIG-IP redundant configuration hardware and software parity requirements.

Clone the project and set up the Python virtual environment

In this procedure, you clone the GitHub repository containing the article code or download the code from the project page. You also set up the Python virtual environment and install the F5 SDK and Jinja2 packages.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your Linux workstation. The workstation must have internet connectivity.
  2. Change to an existing directory or create a directory where you want the project directory to be stored.
  3. Copy the K04414890 project to your workstation using one of the following methods:
    • Clone the K04414890 repository to your workstation by entering the following command:

      git clone https://github.com/askf5/K04414890.git

    • Go to the K04414890 project page, download the project files with your browser, and unzip the ZIP file.

      Note: This link takes you to a resource outside of AskF5.

  4. Change directories to the project directory by entering the following command:

    cd K04414890

    Note: Directory is named K04414890-main if you download from a browser.

  5. Create the Python virtual environment within the K04414890 directory. For more information, refer to Python venv documentation. In most situations you create the virtual environment with the following command syntax:

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

    python3 -m venv <virtual environment directory>

    For example:

    python3 -m venv my_env

  6. Activate the virtual environment using the following command syntax:

    source <environment dir>/bin/activate

    For example:

    source my_env/bin/activate

  7. Upgrade pip to the latest version with the following command:

    pip install --upgrade pip

  8. Install F5 SDK and Jinja2. In most situations you install the packages with the following commands in sequence:

    pip install f5-sdk-python
    pip install Jinja2

  9. To deactivate the environment enter the following command:

    deactivate

Review the example declaration template

The example declaration template configures networking (VLANs and self IP addresses), ConfigSync, and network failover IPs and creates a device group. The template replaces the values for self IPs, failover IPs, and device group members with variables using Jinja2 syntax. Specifically, the variables are: {{ int_self_ip }}, {{ ext_self_ip }}, {{ mgmt_ip }}, {{ mgmt_ip_1 }}, and {{ mgmt_ip_2 }}. The variables get assigned by user input from the command line.

Run the script

In this procedure you run the script and provide IP addresses collected from your BIG-IPs as the arguments.

Impact of procedure: The following procedure synchronizes the BIG-IP devices and triggers a failover if you use the example DSC_VLAN_template.json template.

  1. Gather the management IPs you want to use to connect to the BIG-IP device or devices.
  2. Gather the other details to use to assign to the variables in your template.
  3. Log in to your workstation and change directories to the project directory if you have not already done so.
  4. Activate the virtual environment using the following command syntax:

    source <environment dir>/bin/activate

    For example:

    source my_env/bin/activate

  5. Run the script. The first two arguments are positional and must be the target BIG-IP management address followed by the name of the template. This is followed by one or more key/value pairs in the format of key=value which will be assigned to variables in your template. The key is the name of the variable in the template and the value is the configuration content such as an IP address. Optionally, you can add the update key with the current DO version string as the value. If this option is omitted, the program uses the default value of 1.27.1-2. This does not update a currently installed DO package. Use the following syntax:

    ./deploy_template.py <target BIG-IP management address> <template name> <space delimited key=value pairs with values to insert into the template> [update=<DO version>]

    For example:

    ./deploy_template.py 10.155.19.176 DSC_VLAN_template.json int_self_ip=10.101.65.193/27 ext_self_ip=10.101.65.225/27 mgmt_ip=10.155.19.176 mgmt_ip_1=10.155.19.176 mgmt_ip_2=10.155.19.177 update=1.28.0-4

  6. Enter the administrative password for the device.

    Note: You may see the following error message repeat while the script configures the devices. f5sdk.utils.http_utils - WARNING: SSL Insecure request, recommend adding a valid certificate to the device. You can safely ignore the message.

  7. If the script terminates due to an error, after addressing the issue, you can run the script again without the need to remove any partial configuration on the devices.
  8. If you are using DSC_VLAN_template.json, you need to run the script again targeting the peer device to configure networking and complete the second half of the DSC configuration. The target IP in this example is now 10.155.19.177 and the key/value is mgmt_ip=10.155.19.177 to configure the management IPs as a failover IPs. For example:

    ./deploy_template.py 10.155.19.177 DSC_VLAN_template.json int_self_ip=10.101.65.194/27 ext_self_ip=10.101.65.226/27 mgmt_ip=10.155.19.177 mgmt_ip_1=10.155.19.176 mgmt_ip_2=10.155.19.177 update=1.28.0-4

  9. After the deployment successfully completes, deactivate the virtual environment by entering the following command:

    deactivate

Guidance for customizing the program

After completing the previous steps, you now have the skills to adapt the program for other onboarding scenarios. You create a declaration with the classes of your choosing and replace properties and values that you want to be a variable using Jinja2 syntax. Then you run the script with the values to assign to the template variables. A further example illustrates this:
For the following declaration template: Route_VLAN_template.json, you invoke the script with the following arguments:
./deploy_template.py 10.155.19.178 Route_VLAN_template.json int_self_ip=10.100.22.129/27 gw_ip=10.100.22.158 mtu=1500

When adapting the program for other deployments if you copy and rename the program files, ensure that you update the following:

  • The import line of deploy_template.py to reference the new name of the module. For example:

    from onboard2 import OnboardDSC
