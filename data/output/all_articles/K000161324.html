K000161324: BIG-IP HA ConfigSync Failure and HA Disconnected State, After Upgrade to Version 17.5.x

Type
Support Solution
Published
2026-05-19
Updated
2026-05-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000161324

Description

After upgrading a BIG-IP LTM HA Active/Standby pair to version 17.5.x, the devices enter a persistent "Sync Failed" state and ConfigSync connectivity is lost between the pair. Both devices log repeated mcpd Errors indicating the TMM outbound CMI listener was not created, preventing peer connectivity.

Error messages observed in logs [/var/log/ltm]:

0107142f:3: Can't connect to CMI peer <peer_IP>, TMM outbound listener not yet created
0107142f:3: Can't connect to CMI peer <peer_IP>, port:6699, Transport endpoint is not connected
01071aea:4: CMI heartbeat timer expired, status: <peer_IP>

ConfigSync error observed on the destination device [/var/log/ltm]:

01070712:3: Caught configuration exception (0), failed to sync files

Environment

  • Product: BIG-IP LTM
  • TMOS upgraded from earlier version to 17.5.x
  • HA Active/Standby pair
  • ConfigSync IPs: Correctly configured on both devices
  • Configuration state: No configuration load errors on either device post-upgrade ('tmsh load sys config verify' returns only non-critical deprecation and license warnings, no errors)

Cause

This Issue could be related to an Internal Bug-ID "2294317-3", where It causes TMM to lose its outbound CMI listener state after the upgrade, when mcpd is unable to establish CMI peer connectivity, resulting in the HA pair entering a "Sync Failed" / Disconnected state. Restarting TMM on the affected device re-establishes the listener and resolves the ConfigSync failure.

Answer/Recommended Actions

1- Restart TMM on the 'Standby' device first to minimize traffic impact:

# bigstart restart tmm

2- After the restart completes, verify that ConfigSync connectivity is restored and the "Sync Failed" state clears, either via GUI or CLI:

# tmsh show cm sync-status

3- If the 'Active' device also exhibits the same mcpd listener errors, perform a controlled failover and repeat the TMM restart on the newly 'Standby' device.

4- Monitor the HA pair post-restart to confirm ConfigSync completes successfully.

Additional Information

  • The 'tmsh load sys config verify' command returning only warnings (such as deprecated compliance entries or TurboFlex license notices) is expected behavior after this type of upgrade and does not indicate a configuration problem. These warnings do not cause ConfigSync failure.
  • The ConfigSync failure in this scenario is not caused by a configuration syntax error or misconfigured ConfigSync IP addresses — it is solely due to the TMM listener state loss.
  • Bug ID 882609 also describes similar CMI listener loss behavior and may be referenced for additional context.
  • Restarting TMM re-establishes the outbound CMI listener, immediately restoring HA connectivity without requiring a full system reboot or configuration change.
