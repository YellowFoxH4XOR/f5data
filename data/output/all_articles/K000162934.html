K000162934: NGINX Ingress Controller Reload Failure Due to Invalid Proxy Buffer Configuration

Type
Support Solution
Published
2026-08-14
Updated
2026-08-14
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 5.3.0
Source
https://my.f5.com/manage/s/article/K000162934

Description

NGINX Ingress Controller rejects a configuration reload when the effective proxy_busy_buffers_size is greater than or equal to the total size of proxy_buffers minus one buffer.

The error is:

"proxy_busy_buffers_size" must be less than the size of all "proxy_buffers" minus one buffer

A failed reload can prevent updated Kubernetes resources from being applied and may cause applications behind the ingress controller to become unavailable.

Environment

  • NGINX Ingress Controller
  • Kubernetes cluster
  • NGINX Ingress Controller ConfigMap
  • Proxy buffer settings:
    • proxy-buffering: "on"
    • proxy-buffer-size: "2m"
    • proxy-buffers: "32 \"2m\""

For proxy-buffers: 32 "2m":

Total buffer capacity = 32 × 2 MB = 64 MB

proxy_busy_buffers_size must be less than 62 MB

The effective proxy_busy_buffers_size may be defined by a ConfigMap, annotation, generated configuration, or another NGINX configuration source.

Cause

The effective NGINX configuration contained a proxy_busy_buffers_size value that did not satisfy the required relationship with proxy_buffers. NGINX configuration validation therefore failed and the reload was rejected.

The invalid value may originate from a configuration source that is not visible in a partial ConfigMap or resource definition.

Answer/Recommended Actions

  1. Inspect the complete effective NGINX configuration from an ingress controller pod:
    kubectl exec -n <namespace> <nginx-ingress-pod-name> -- nginx -T
  2. Review the effective values for:
    • proxy_buffers
    • proxy_buffer_size
    • proxy_busy_buffers_size
  3. Confirm that this condition is met:

    proxy_busy_buffers_size < total proxy_buffers size − one buffer

  4. For the following configuration:

    proxy_buffers 32 2m

    configure:

    proxy_busy_buffers_size < 62m

  5. Review all configuration sources that may define the directive, including:
    • NGINX Ingress Controller ConfigMaps
    • VirtualServer and other Kubernetes resource annotations
    • HTTP or server snippets
    • Generated NGINX configuration
  6. Correct the invalid proxy-busy-buffers-size value, or remove it if it is not required so that the default value can be used.
  7. Validate the configuration:
    nginx -t
  8. Consider enabling the NGINX Ingress Controller --enable-directive-autoadjust feature. This feature can automatically correct common proxy buffer configuration issues by:
    • Applying a default proxy_buffers value when none is specified
    • Reducing an excessive proxy_busy_buffers_size
    • Restricting the number of proxy buffers to the supported range
    • Correcting empty or invalid buffer settings
  9. Verify that the NGINX configuration reload completes successfully and that the affected Kubernetes resources show an applied configuration.

Additional Information

  • proxy_buffer_size and proxy_buffers may be valid individually while the combined effective configuration remains invalid.
  • Restarting the ingress controller may temporarily restore service if a valid configuration is loaded during startup, but a restart does not correct the invalid configuration source.
  • Use the complete generated configuration when investigating reload failures because a partial configuration excerpt may not show the effective proxy_busy_buffers_size.
  • The proxy_busy_buffers_size value must be strictly less than the total size of all proxy_buffers minus one buffer.
