K000158826: After upgrade to 17.5.x web page requests appear to hang in the browser when AVR profile is attached

Type
Support Solution
Published
2025-12-17
Updated
2025-12-17
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0, 17.5.1, 16.1.5, 16.1.6
Source
https://my.f5.com/manage/s/article/K000158826

Description

When using virtual server with an AVR (Analytics) profile, users may encounter issues where web page requests appear to hang in the browser, eventually timing out based on the timeout values configured and resetting the connection.

Packet captures show that backend server responds to the HTTP request on serverside ( between bigip and server ) but the response on the clientside ( client and bigip ) appears to be not delivered and eventually a reset after timeout.

Environment

  • BIG-IP LTM
  • upgrade to 17.5.x
  • AVR Profile with Collect-page-load-time enabled 
  • sys db key avr.cspm.inject.location is set to after_head

Cause

This is due to known issue as described in Bug ID 1937717: When "collect-page-load-time" is enabled in the AVR profile and avr.cspm.inject.location db key is set to "after_head", BIG-IP increases the Content-Length header but fails to inject the CSPM script into the payload causing browsers to wait and then connection get resets after timeout.

Recommended Actions

To resolve this issue, perform at least one of these actions:

1) On the HTTP profile for your virtual server, set "response-chunking" option to rechunk.

2) Set sys db key avr.cspm.inject.location to value  at_the_end which is default-value 

tmsh modify sys db avr.cspm.inject.location value at_the_end

3) On the AVR profile attached to your virtual server(s), disable "collect-page-load-time".
