Description

Systems configured to use SNMP v3 are required to have a unique SNMP engine ID. If the systems do not have a unique SNMP engine ID, SNMP v3 does not function properly and trap messages will not be transmitted.

You may want to test whether a specific engine id works with SNMP management platform by using snmptrap command. This command sends an SNMP notification to an SNMP manager.

Environment

  • SNMPV3

  • snmptrap

Cause

None

Recommended Actions

  • To obtain the BIG-IP system engine ID, type the following command:

cat /config/net-snmp/snmpd.conf | grep oldEngineID

The command output appears similar to the following example:
oldEngineID 0x80001f8880c6b6067fdacfb558

  • To test the BIG-IP system engine ID, type the following command:
snmptrap -v 3 -e <engine_id> -u <username> -a <authentication_hash> -A <authentication_password> -l <security_level> <IP_address_of_trap_destination> '' <SNMP_OID> <type_of_message> "<message>"

For example, an SNMPv3 user snmp3user is configured with authentication type MD5, password default, security level authNoPriv, engine id 0x80000d2f03005056ab2160, and send a string test to a SNMP trap destination 192.168.1.1:

snmptrap -v 3 -e 0x80000d2f03005056ab2160 -u snmp3user -a MD5 -A default -l authNoPriv 192.168.1.1 '' .1.3.6.1.4.1.8072.100 .1.3.6.1.4.1.8072.100.1 s "test"
