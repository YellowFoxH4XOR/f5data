K000151035: implemented http version 1.1 but if any request come with version 1.0, what will be the action from nginx ?

Description

When NGINX Plus is configured to use HTTP/1.1, it will still accept and process HTTP/1.0 requests by default due to HTTP/1.1’s backward compatibility. No error message is generated for HTTP/1.0 requests unless explicitly configured otherwise; NGINX will respond using HTTP/1.1 protocol. In some scenarios, there may be a requirement to block incoming HTTP/1.0 requests for security or compliance purposes.

 

Environment

- Product: NGINX Plus

- Version: R31

- Configuration:

- `proxy_http_version 1.1` set in the server block

- SSL enabled on port 443

- Reverse proxy deployment

 

Cause

NGINX supports backward compatibility with HTTP/1.0 when operating in HTTP/1.1 mode, meaning it does not natively reject or block client connections using the older protocol version. The `proxy_http_version` directive only sets the protocol version used between NGINX and upstream servers, not between clients and NGINX itself.

 

**Recommendations**

To prevent clients from making requests using HTTP/1.0, add a conditional check within your server block that inspects the `$server_protocol` variable and returns an error if the request uses HTTP/1.0:

 

server {
listen 443 ssl;
server_name _;
# ... other SSL and proxy settings ...

if ($server_protocol = "HTTP/1.0") {
return 400 "HTTP/1.0 is not supported.
";
}

location / {
proxy_pass http://backend;
proxy_http_version 1.1;
# ... other proxy settings ...
}
}

 

- This configuration returns a 400 Bad Request response for any client request using HTTP/1.0.

- The `proxy_http_version 1.1;` directive ensures backend communication uses HTTP/1.1 but does not affect how client protocols are handled.
