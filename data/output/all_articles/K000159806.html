K000159806: Parameter and URL not working for specific signatures for PUT.

Description

BIG-IP ASM version 17.1.2 blocked HTTPS PUT method requests containing JSON data due to attack signature "Unix special variable $0 (Parameter)" triggering on a specific parameter. The customer attempted to create exceptions using parameter-level and URL-level signature disabling for this specific signature, but these targeted exceptions did not prevent the blocking. Only disabling the signature globally at the policy level successfully allowed the PUT requests through. The same parameter configuration worked correctly for POST method requests.


 

Environment

BIG-IP ASM version 17.1.2

Platform: F5-VPR-LTM-C2400-AC, F100

ASM security policy with attack signature checking enabled

HTTPS PUT requests with Content-Type: JSON

The [HTTPS] * (Wildcard) URL was configured with "Apply value and content signatures and detect threat campaigns" instead of using a proper JSON profile

Same parameter configuration working correctly for POST method requests


 

Cause

The requests in question were being matched by the [HTTPS] * (Wildcard) URL, which was misconfigured to handle JSON requests. The URL was configured with "Apply value and content signatures and detect threat campaigns" instead of using a proper JSON profile. This misconfiguration prevented parameter-level and URL-level signature exceptions from working correctly for PUT method requests with JSON content, while POST requests with the same parameter configuration worked as expected.


 

Answer/Recommended Actions

Configure the [HTTPS] * (Wildcard) URL correctly to handle JSON requests:

Request Header Name: Content-Type

Request Header Value: json

Request Body Handling: Default JSON Profile (or a custom JSON profile)

This configuration change ensures that BIG-IP ASM properly processes JSON content in PUT requests and allows parameter-level and URL-level signature exceptions to function correctly
