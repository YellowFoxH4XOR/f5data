Description

You observe logs similar to the following in the /var/log/ltm log file, in association with Clock Advanced messages with a similar tick value

Jul 01 13:12:53 bigip1.local notice tmm3[19417]: 01010339:5: Virtual /Common/https_vs iRule /Common/slow_irule <HTTP_REQUEST_DATA> execution ran for 506 ticks (192.168.1.100:53069 -> 192.168.1.10:443 TCP)
Jul 01 13:12:54 bigip1.local notice tmm3[19417]: 01010029:5: Clock advanced by 507 ticks


Environment

  • BIG-IP
  • iRules


Cause

The iRule execution threshold log was introduced to help identify iRules that consume significant CPU and TMM descheduling. The logging threshold can be configured from the default value of 500 ticks, and disabled entirely with a value of 0.

sys db tmm.tcl.executionlimit {
    default-value "500"
    scf-config "true"
    value "500"
    value-range "unsigned_integer min:0 max:10000"
}

To modify the logging threshold to 300 ticks:

# tmsh modify /sys db tmm.tcl.executionlimit value 300
# tmsh save /sys config

  

Recommended Actions

If an iRule is consuming excessive CPU, then it may need to be reviewed and modified to reduce the CPU utilization.
TCL features that can increase CPU utilization include regular expressions, datagroup lookups and manipulating large strings.
