K000133787: NIM does not support NGINX native parameter "hostnames"

Type
Support Solution
Published
2023-05-03
Updated
2023-05-03
Applies to
  • NGINX Products
  • NGINX Agent: 2.25.X, 2.25.1, 2.25.0
Source
https://my.f5.com/manage/s/article/K000133787

Description

NIM does not support NGINX native map directive parameter "hostnames". If the "hostnames" parameter is in a map directive, NGINX Agent cannot start and shows errors. Example of NGINX Agent logs that occur:

time="<date/time>" level=warning msg="Unable to read config for NGINX instance b636d4376dea15405589692d3c5d3869ff3a9b26b0e7bb4bb1aa7e658ace1437, error reading config from /etc/nginx/nginx.conf, error: invalid number of parameters in /etc/nginx/conf.d/test.conf:2"
time="<date/time>" level=error msg="Unable to read nginx config /etc/nginx/nginx.conf: error reading config from /etc/nginx/nginx.conf, error: invalid number of parameters in /etc/nginx/conf.d/test.conf:2"
time="<date/time>" level=warning msg="Error uploading config: error reading config from /etc/nginx/nginx.conf, error: invalid number of parameters in /etc/nginx/conf.d/test.conf:2"

Environment

NIM

Cause

NIGNX Agent configuration validation erroneously rejects configuration

Recommended Actions

NA

Additional Information

F5 is aware of this issue and it was fixed in NGINX Agent release v2.26.0
