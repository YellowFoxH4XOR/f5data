Description

In some cases, the virtual server may demand an additional security level called client authentication, during the TLS handshake the server may demand a certificate request after the server certificate message forcing the client to identify itself by sending and verifying its certificate and public key. Its an optional feature and is used in high-security communications.

If the certificate is not correct from the client side (web browser for example), packet captures of the traffic durring the issue will show fatal error certificate unknown after the server hello.

If you try to access the VS with authentication enabled and wrong certificate on the client browser you will get the following error in the web browser:

ERR_BAD_SSL_CLIENT_AUTH_CERT

Environment

  • BIG-IP LTM 
  • client authentication

Cause

Wrong certificate or missing certificate on the client (web browser).

Recommended Actions

Check your Client SSL configuration to ensure the private Root CA certificate has been specified as a Trusted and Advertised Certification Authority.

Ensure you imported the Client Certificate into your web browser as a .pfx file.

Cert and Root CA can be verified using the OpenSSL command:

 openssl verify -purpose sslclient -CAfile /path/trusted-ca-bundle.crt /path/client.crt
