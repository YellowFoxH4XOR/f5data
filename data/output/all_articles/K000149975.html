Description

bigd may log errors

SSL_set_cipher_list:no cipher match.

and the HTTPS monitor fails as seen in monitor debug logs.


[1][28308] 2025-02-03 13:50:40.325346: ID 462  :(initialize_ssl) getting ciphers from profile '/Common/TEST_V1_server-ssl': TLS13-AES256-GCM-SHA384:TLS13-AES128-GCM-SHA256:TLS13-CHACHA20-POLY1305-SHA256 [ tmm?=false td=true tr=false addr=::ffff:10.65.206.136:9031 srcaddr=::ffff:10.45.32.5%0:56524 ]
[1][28308] 2025-02-03 13:50:40.325359: ID 462  :(initialize_ssl) legacy: false, compat: false, options: 0x1c000800 [ tmm?=false td=true tr=false addr=::ffff:10.65.206.136:9031 srcaddr=::ffff:10.45.32.5%0:56524 ]
[1][28308] 2025-02-03 13:50:40.325444: ID 462  :Open SSL error - error:1410F0B9:SSL routines:SSL_set_cipher_list:no cipher match. [ tmm?=false td=true tr=false srcaddr=::ffff:10.45.32.5%0:56524 ]

Environment

  • BIG-IP LTM
  • HTTPS monitor

Cause

The HTTPS monitor server SSL Profile implements F5 cipher strings for in-TMM monitors, and try to implement OpenSSL ciphers for bigd https monitors.
If the profile defines a cipher string that is not valid for OpenSSL, bigd will fail to configure the monitor cipher string.

For example:

ltm monitor https /Common/V1_TEST_https {
  cipherlist none
  compatibility none
  defaults-from /Common/https
  destination *:*
  interval 5
  partition Common
  password ***scrubbed***
  send "GET /http.ping"<
  ssl-profile /Common/TEST_V1_server-ssl
  time-until-up 0
  timeout 16
}

 

ltm cipher group V1_TLSv1.3_Rule_Group
{
  allow {
   V1_TLSv1.3_Rule { }
  }
  app-service none
  description none
  exclude none
  ordering default
  partition Common
  require none
}

 

ltm cipher rule V1_TLSv1.3_Rule
{
  app-service none
  cipher TLS13-AES256-GCM-SHA384:TLS13-AES128-GCM-SHA256:TLS13-CHACHA20-POLY1305-SHA256 <== F5 ciphersuite names
  description none
  partition Common
}

Recommended Actions

SSL profiles applied to bigd monitors can only contain cipher groups that are common to OpenSSL and F5 ciphers - DEFAULT or HIGH:@STRENGTH or similar
