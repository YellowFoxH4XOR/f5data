Known Issue

New TCP connections may occasionally be reset when the processing load is unevenly distributed among multiple Traffic Management Microkernels (TMMs).

This issue occurs when all of the following conditions are met:

  • Fast Flow Forwarding is enabled.

    Note: This is the default setting.

  • At least one TMM is experiencing a heavy processing load but has not reached the SYN cookie threshold.
  • At least one other TMM is experiencing less processing load but has reached the SYN cookie threshold.
  • Syncookie activation is recorded on only one tmm thread.

Impact

New client TCP connections that have valid SYN cookies are rejected with a TCP RST and must retry the connection.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • On rare occasions, new client connections receive a TCP RST and must retry the connection.

Workaround

To work around this issue, you can disable TMM fast forward flows. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure requires that you reboot the BIG-IP system. The tmm.ffwd.enable database variable allows a TMM at 100 percent capacity to forward connections to a TMM under less intensive CPU load.

  1. Log in to the command line of the BIG-IP system.
  2. To disable TMM's fast forward flow, type the following command:

    tmsh modify sys db tmm.ffwd.enable value false

  3. To reboot the BIG-IP system, type the following command:

    reboot
