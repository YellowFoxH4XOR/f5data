K000139401: NGINX Plus Ingress Controller with command -default-server-tls-secret fails to find certificate location

Description

  • You are using NGINX Plus Ingress Controller to expose/proxy poxy request to Kubernetes cluster 
  • You want to enable default SSL termination on NGINX Ingress Controller using command -default-server-tls-secret <string> and -wildcard-tls-secret <string>
  • These commands are mentioned here Command-line Arguments
  • However, when including these commands, NGINX Ingress Controller fails to come up with the below error  
           Event(v1.ObjectReference
              {
                Kind:"Ingress", Namespace:"example-ns", 
                Name:"my-example", 
                UID:"eadc03c-feef-4338-a3wb-f422fdddbffe2", 
                APIVersion:"networking.k8s.io/v1", 
                ResourceVersion:"111111861", 
                FieldPath:""
              })
              : type: 'Warning' reason: 'AddedOrUpdatedWithWarning' Configuration for <ingress-resource> was added or updated ; 
                        with warning(s): TLS secret example-secret is invalid: secret doesn't exist or of an unsupported type

Environment

  • NGINX Plus Ingress Controller
  • Kubernetes
  • Secret
  • TLS Termination
  • Ingress Resource

Cause

  • Secret used for TLS termination is of type INVALID or UNSUPPORTED.

Recommended Actions

  • Secret used for TLS must be of TYPE: kubernetes.io/tls
  • We recommend to revisit secret object used for TLS termination and make the necessary required adjustment
  • As an example, a secret manifest is included below with the expected secret type.
              apiVersion: v1
              kind: Secret
              metadata:
                name: default-server-secret
                namespace: nginx-ingress
              type: kubernetes.io/tls
              data:
                tls.crt: LS0tLS1CRUdJTiBDRVJUSUZJQ0FURS0tLS....
                tls.key: LS0tLS1CRUdJTiBSU0EgUFJJVkFURSBLRV....
