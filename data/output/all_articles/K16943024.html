K16943024: Device group unexpectedly in Changes Pending state but no changes have been done

Type
Support Solution
Published
2020-08-27
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K16943024

Description

On a system provisioned for ASM, you find that the device goes into an unexpected Changes Pending state, despite no changes being made.

You observe a log message similar to the following in /var/log/audit:

notice mcpd[7014]: 01070417:5: AUDIT - client Unknown, user root - transaction #662801239-2 - object 0 - modify { asm_policy { asm_policy_name "/Common/prod-sec-policy" asm_policy_object_id 904315 asm_policy_encoding "iso-8859-1" asm_policy_policy_template "" asm_policy_parent_policy "none" asm_policy_is_active_policy 0 asm_policy_policy_type 1 asm_policy_avr_publisher "" asm_policy_alternate_bit 0 asm_policy_dummy "" asm_policy_config_source 0 asm_policy_partition_id "Common" asm_policy_leaf_name "prod-sec-policy" asm_policy_folder_name "/Common" asm_policy_app_id "" asm_policy_strict_app_updates 0 asm_policy_transaction_id 1 } } [Status=Command OK]

A message similar to the following can also be observed in /var/log/asm:

info perl[15309]: 01310053:6: Active Policy Sweeper: asynchronously deactivated ASM security policy named '/Common/prod-sec-policy'

Environment

  • ASM provisioned
  • Inactive security policies

Cause

This is expected behaviour. The ASM policy sweeper will automatically deactivate unused policies if they are not assigned to a virtual server or LTM policy. This will result in a Changes Pending state for the Device Group.

Recommended Actions

No action is needed.

However, if you would like to prevent an unused policy from being deactivated, assign it to a Local Traffic Policy, like the following example:

ltm policy do_not_deactivate {
    controls { asm }
    rules {
        rule1 {
            actions {
                0 {
                    asm
                    client-accepted
                    enable
                    /Common/prod-sec-policy
                }
            }
        }
    }
    status published
    strategy first-match
}

Note: The traffic policy itself does not need to be assigned to a virtual server.

Additional Information

The policy sweeper deactivation is done to avoid overburdening bd with policy configuration that is not needed.
