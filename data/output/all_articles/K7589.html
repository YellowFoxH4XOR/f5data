Topic

 

Important: You can configure the WebAccelerator version 5.x and BIG-IP WebAccelerator version 9.4.x system to insert the Via HTTP header. However, for BIG-IP WebAccelerator systems, F5 recommends using an iRule to insert an X-Via HTTP header in order to identify HTTP connections that have passed through a proxy device. For more information, refer to K8912: Inserting an X-Via HTTP header to identify connections that have passed through the BIG-IP WebAccelerator.

You can configure the WebAccelerator system to identify HTTP connections that have passed through a proxy device by inserting a Via HTTP header into an HTTP request; you can also configure the WebAccelerator system to identify that the HTTP connection has passed through a WebAccelerator by inserting a Via HTTP header into an HTTP response.

The Via HTTP header will appears similar to the following examples:

Via: 1.1 wa-4500-1.bfs.wanopt.f5net.com:8081 (Pivia Performance Server 5.2.0 255163) \r\n

Via: : 1.1 wam1010.wanopt.es.f5net.com:8081 (BIG-IP Web Accelerator 10.2.0 ) \r\n

You can configure the WebAccelerator to insert the Via HTTP header into an HTTP request sent from the WebAccelerator to the server, and/or into an HTTP response sent from the WebAccelerator to the client.

The WebAccelerator system's Via HTTP header behavior is configured by modifying the sendProxyViaHeader entry in the pvsystem.conf file. The sendProxyViaHeader entry consists of the inRequest, inResponse, and hostName fields. 

inRequest and inResponse fields

BIG-IP WebAccelerator 9.4.7 through 9.4.8, 10.0.1 and later

The inRequest and inResponse fields can be set to the following values:

inRequest/inResponse ValuesBIG-IP WebAccelerator behavior
removeWhen the inRequest field is set to remove, the BIG-IP WebAccelerator removes any Via HTTP header from the client HTTP request as the request is sent from the BIG-IP WebAccelerator to the server. 

When the inResponse field is set to remove, the BIG-IP WebAccelerator removes any Via HTTP header from the server HTTP response as the response is sent from the BIG-IP WebAccelerator to the client.
preserveWhen the inRequest field is set to preserve, the BIG-IP WebAccelerator forwards any Via HTTP header from the client HTTP request as the request is sent from the BIG-IP WebAccelerator to the server. 

When the inResponse field is set to preserve, the BIG-IP WebAccelerator forwards any Via HTTP header from the server HTTP response as the request is sent from the BIG-IP WebAccelerator to the server.
appendIf the inRequest field is set to append and the client HTTP request does not contain any Via HTTP header, the BIG-IP WebAccelerator inserts its own Via HTTP header when the request is sent from the BIG-IP WebAccelerator to the server.

If the inRequest is set to append and the client HTTP request contains a Via HTTP header, the BIG-IP WebAccelerator appends its specific information to the existing Via HTTP header from the client HTTP request as the request is sent from the BIG-IP WebAccelerator to the server.

If the inResponse field is set to append and the server HTTP response does not contain any Via HTTP header, the BIG-IP WebAccelerator inserts its own Via HTTP header when the response is sent from the BIG-IP WebAccelerator to the client.

If the inResponse is set to append and the server HTTP response contains a Via HTTP header, the BIG-IP WebAccelerator appends its specific information to the existing Via HTTP header from the server HTTP response as the response is sent from the BIG-IP WebAccelerator to the client.

Note: If the sendProxyViaHeader entry is removed, and not specified in the pvsystem.conf file, the behavior is similar to <sendProxyVia inRequest="remove" inResponse="append" hostname=""/>. The Via HTTP header is removed from an HTTP request, and is inserted or appended into an HTTP response.

WebAccelerator 5.x and BIG-IP WebAccelerator 9.4.0 through 9.4.6

The inRequest and inResponse fields can be set to true or false. When the inRequest field is set to true, the Via HTTP header is inserted into the HTTP request as the request is sent from the WebAccelerator to the server. When the inResponse field is set to true, the Via HTTP header is inserted into the HTTP response as the response is sent from the WebAccelerator to the client.

If the fields are set to false, the WebAccelerator does not insert the Via HTTP header.

The default sendProxyViaHeader entry in the pvsystem.conf file appears similar to the following example:

<sendProxyViaHeader inRequest="false" inResponse="false" hostName=""/>

The Via HTTP header is not inserted into an HTTP response sent to client, or an HTTP request sent to the server.

Note: If the sendProxyViaHeader entry is removed, and not specified in the pvsystem.conf file, the behavior is similar to <sendProxyVia inRequest="false" inResponse="true" hostName=""/>. The Via HTTP header is insterted into an HTTP response, and not inserted into an HTTP request.

hostName field

Changing the hostName field in the sendProxyViaHeader entry allows you to specify a different host name to be displayed in the Via HTTP header.  However, specifying the host name using the hostName field will not remove the internal port number, and will not remove the legacy Pivia Performance Server information from the header.

Note: For information about inserting an X-Via HTTP header without disclosing the WebAccelerator host name, port, and the legacy Pivia branding when using a BIG-IP WebAccelerator version 9.4.x system, refer to K8912: Inserting an X-Via HTTP header to identify connections that have passed through the BIG-IP WebAccelerator.  

Modifying the sendProxyViaHeader configuration

  1. Log in to the WebAccelerator command line.
  2. Change to the directory that contains the pvsystem.conf file.

    Note: On WebAccelerator version 5.x systems, the pvsystem.conf file is located in the /opt/pivia/dac/conf directory. On BIG-IP WebAccelerator version 9.4.x systems, the pvsystem.conf file is located in the /config/wa directory.
  3. For WebAccelerator version 5.x systems, type the following command:

    cd /opt/pivia/dac/conf

    For BIG-IP WebAccelerator version 9.4.x systems, type the following command:

    cd /config/wa

  4. Back up the original pvsystem.conf file by typing the following command:

    cp pvsystem.conf pvsystem.conf.sol7589

  5. Using a text editor, edit the pvsystem.conf file.
  6. Modify the sendProxyVia value as necessary.
  7. Save the file.
  8. Restart the WebAccelerator by typing the following commands appropriate for your version:

    Important: Restarting the WebAccelerator process on any version will briefly interrupt connections and should be scheduled accordingly.

    BIG-IP WebAccelerator 9.x and 10.x

    bigstart restart pvac

    WebAccelerator 5.x

    service pivia stop_pvac

    service pivia start_pvac

Note: The WebAccelerator removes the Via header incorrectly in some circumstances. For more information, refer to K9917: The WebAccelerator removes the Via header incorrectly when sendProxyViaHeader is set to true.
