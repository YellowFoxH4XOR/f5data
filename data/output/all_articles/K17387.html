Known Issue

BIG-IP APM access sessions may be unexpectedly deleted.

This issue occurs when all of the following conditions are met:

  • The virtual server with an access policy is invoked through the iRule virtual command.
  • Users have established access sessions through the access policy.
  • A request made for a resource in the BIG-IP /public/ folder contains an existing lastMRHSession cookie, while the value of the MRHSession cookie value has been tampered.

    For example, a BIG-IP APM access session is established with the following cookies:

    MRHSession=6411b93b51712e72ff5c5d9cb512ac27
    LastMRH_Session=b512ac27

    Next, a request is made for a resource in the /public/ folder with the following cookies. Note that the MRHSession cookie is tampered:

    MRHSession=xx11b93b51712e72ff5c5d9cb512ac27
    LastMRH_Session=b512ac27

As a result, the established access session MRHSession=6411b93b51712e72ff5c5d9cb512ac27 will be deleted.

Impact

The BIG-IP APM system logs off established sessions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • An established BIG-IP APM access session is deleted when a request is made for a resource in the BIG-IP /public/ folder.
  • In the /var/log/apm file, when the session is deleted, you may observe an error message that appears similar to the following example:

    notice tmm[<pid>]: 01490501:5: <session-id>: Session deleted due to user logout request.

Workaround

You can work around this issue by using the following iRule to remove the access session cookies before accessing the /public/ folder.

Impact of Workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name for this iRule.

    For example:

    sol17387

  5. Copy the following iRule and paste it in the Definition box:

    when HTTP_REQUEST {
    if {[HTTP::path] contains "/public" } {
    HTTP::cookie remove "LastMRH_Session"
    HTTP::cookie remove "MRHSession"
    }
    }

  6. To save the iRule, click Finished.
  7. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  8. Click the Edit link under the Resources column for the affected virtual server you want to assign the iRule.
  9. Click Manage for the iRules section.
  10. In the Available box, select the iRule.
  11. To move the iRule to the Enabled box, click the << button.
  12. To save the modification, click Finished.
