Topic

You should consider using this procedure under the following conditions:

  • You have a BIG-IP APM system deployed in an environment in which you want to block users from unauthenticated access to the /public/download URL.
  • The environment pushes BIG-IP Edge Client download components to end-user client devices, such as Microsoft System Center Configuration Manager.

Important: Blocking access to the /public/download URL, and therefore these download components, prohibits client PCs from downloading client software updates from the BIG-IP system. Doing this may cause problems. You should only block client component downloads if you are not using BIG-IP Edge Client, VPN components, or Endpoint Inspection (EPS) components in your deployment.

Description

The BIG-IP APM uses a publicly available URL to allow the BIG-IP Edge Client to retrieve access policy and BIG-IP Edge Client components and software updates (Connectivity profile auto-updates) for Windows, MacOS, and Linux, as well as the Client Troubleshooting Utility and OPSWAT Diagnostics. The URL /public/download does not require end-user authentication to obtain the required files. In some environments, local policy restricts all unauthorized access to any content. The BIG-IP APM system does not currently allow you to configure authenticated-only access to the public downloads directory. To work around this limitation, you can create an iRule to the affected BIG-IP APM virtual server to block access to the URL /public/downloads.

Important: If you create and deploy this iRule, you must implement a secondary method of updating the BIG-IP Edge Client and supplying required components to an end user's device in the environment.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP APM Configuration utility.

Procedures

  • Creating the URL blocking iRule 
  • Applying the URL blocking iRule

Creating the URL blocking iRule  

Perform the following procedure to to create a custom iRule to apply to a virtual server to block access to the BIG-IP APM public downloads URL:

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter the Name you want for this custom iRule.

    For example:

    block_url_downloads

  5. For Definition , enter the following iRules syntax: 
    when CLIENT_ACCEPTED {
  ACCESS::restrict_irule_events disable
}

    when HTTP_REQUEST {
      if { [HTTP::uri] starts_with "/public/download" } { HTTP::close; HTTP::respond 404 content "Not Found" }
    }

    Note: In the iRules syntax the HTTP response is 404, you can modify the response to match the HTTP response you want. When using CLIENT_ACCEPTED be aware it is significantly more compute intensive and may impact other iRules attached to the same VIP.

  6. Select Finished.

Applying the URL blocking iRule

Perform the following procedure to apply the new iRule to a virtual server to block access to the public download URL:

Impact of procedure:  After you apply the iRule to the BIG-IP APM virtual server, access to the public downloads URL no longer functions.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the BIG-IP APM virtual server to which you want to apply the iRule.
  4. Select the Resources tab.
  5. For iRules, select Manage.
  6. In the Available list, select the iRule created in the previous procedure and move it into the Enabled list.
  7. Select Finished.
