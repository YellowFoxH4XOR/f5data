Description
When you do not want to use SNMPv1/2c and want to make sure that SNMP queries using these versions do not get responses, you will need to properly disable SNMPv1/2c. Also applicable to when Vulnerability scanners pick and up and detect SNMP v1/2c vulnerabilities and you want to mitigate them.

Environment

  • BIG-IP being managed through SNMP

Cause
SNMPv1 and v2c, along with v3 are all available and enabled by default, but secured environments prefer to use only v3. Vulnerability scans usually interpret tcp/udp port 161 as SNMP in general and may not be able to distinguish one from the other and will most likely flag as a vulnerability.

Recommended Actions
If you would like to allow only SNMPv3, there are different places to disable SNMP from and some might have to do just one or all of the steps outlined depending on your requirements.

Disabling SNMPv1/2c on TMM interfaces/ TMOS system

From the Configuration Utility:

  1. System  ››  SNMP : Agent : Access (v1, v2c)
  2. Delete the default Community:Source profile named "public"

To rollback:

  1. System  ››  SNMP : Agent : Access (v1, v2c)
  2. Create > Recod Properties
    Type: IPv4
    Community: Public
    Source: default
    OID:
    Access: Read Only
  3. Submit


Disabling SNMPv1/2c on Management interface/ Host system

# tmsh modify sys snmp snmpv1 disable
# tmsh modify sys snmp snmpv2c disable
# tmsh save sys config

To rollback:

# tmsh modify sys snmp snmpv1 enable
# tmsh modify sys snmp snmpv2c enable
# tmsh save sys config

Additional Information

To stop from getting a SYN-ACK, TCP port 161 should also be disabled:
# tmsh modify sys snmp agent-addresses delete { tcp6:161 }
# tmsh save sys config

To rollback:
# tmsh modify sys snmp agent-addresses add { tcp6:161 }
# tmsh save sys config
