Description

  • Traffic going through an HTTP virtual server with the default redirection iRule fails to successfully redirect to the HTTPS virtual server
  • Packet capture show that the connection gets reset
  • Traffic gets reset and user is unable to access the application

Environment

  • HTTP virtual with default HTTP to HTTPS redirect iRule
  • HTTP requests using methods other than GET

Cause

The HTTP to HTTPS redirect iRule sends an HTTP 302 response to the initial HTTP request, and by RFC this request can be then modified to use a GET method when it is sent back. This breaks requests using POST or PUT,  where there is data that needs to be sent to a form, for example.

Recommended Actions

To avoid this issue, please follow the steps below.

  1. Replace the redirection iRule to one that uses HTTP 307 or 308 instead, taking into consideration the compatibility requirements that these responses have with different user-agents.
  2. The iRule should look like one of the following examples:
  
when HTTP_REQUEST {
  HTTP::respond 307 Location https://[HTTP::host][HTTP::uri]
}

or

when HTTP_REQUEST {
  HTTP::respond 308 Location https://[HTTP::host][HTTP::uri]
}
