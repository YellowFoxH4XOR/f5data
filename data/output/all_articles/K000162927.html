K000162927: HTTP Load Balancer - Errors: HTTP 503 no_healthy_upstream

Description

After setup a TCP Health Check you start getting HTTP 503 no_healthy_upstream. If the TCP Health Check is removed, there are no issues and everything works correctly

Environment

  • HTTP Load Balancer

Cause

Check if:
- The Origin Server points to a CNAME (AWS ALB, Azure Frontdoor...)
- The Origin Pool has use_tls with use_host_header_as_sni

Health checks inherit the Origin Pool's TLS settings. So the "TCP" check must complete a full TLS handshake. But use_host_header_as_sni derives the SNI from the HTTP Host header, and a TCP check has no Host header. The probe fails, all endpoints are marked unhealthy, and the LB returns 503 before contacting the origin.

Production traffic is unaffected because it carries the Host header and negotiates SNI correctly. That is why removing the health check appears to fix it, with no health check, all endpoints are assumed healthy by default.

Recommended Actions

2 ways to fix it:

  1.  keep the TCP check attached, change one field on the Origin Pool. Replace use_host_header_as_sni with a static sni set to the application hostname. Endpoints should go healthy within healthy_threshold × interval seconds.
  2. replace the TCP health check with an HTTP health check.
    1. Use host_header with the application hostname, not use_origin_server_name, that would set the Host to the origin's DNS name and miss any host-based routing rule at the origin.
    2. Use 200-399, not 200 because many applications (especially SSO/auth services) return a 302 redirect on /.
    3. With an HTTP health check, use_host_header_as_sni works correctly and can be kept if you want to use it
