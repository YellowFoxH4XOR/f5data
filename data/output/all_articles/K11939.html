Topic

This article applies to BIG-IP 10.x. For information about other versions, refer to the following articles:

  • K37361453: Configuring network failover for redundant VIPRION systems (13.x - 16.x)
  • K13915: Configuring network failover for redundant VIPRION systems (11.x - 12.x)

You should consider using this procedure under the following condition:

  • You want to configure network failover for redundant VIPRION systems running 10.x.

Description

To ensure the most stable network failover configuration for redundant VIPRION systems, choose two channels for network failover communication. F5 considers it best practice to define a unicast and a multicast failover address for each VIPRION system in the device group. The unicast failover configuration uses a self IP address and Traffic Management Microkernel (TMM) switch port to communicate failover packets between each VIPRION system, and the multicast failover entry uses the management port to communicate failover packets between each VIPRION system. As an alternative to configuring the multicast failover option, you can define a unicast mesh using the management port for each VIPRION system. This is listed as an alternative option element, following.

To define both unicast and multicast failover addresses and provide additional failover redundancy, perform the following procedures on both VIPRION systems:

  • Creating an interface trunk dedicated for failover
  • Creating a dedicated failover VLAN
  • Creating a self IP address and associate the self IP with the failover VLAN
  • Defining a unicast entry specifying the local and remote self IP addresses
  • Defining a multicast entry using the management interface for each VIPRION system
  • Defining a full mesh of unicast entries (alternative option)

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the Configuration utility.

Procedures

Creating an interface trunk dedicated for failover

Impact of procedure: None

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click Trunks.
  4. Click Create.
  5. Enter a Trunk name.

    For example:

    HA_TRUNK

  6. Add at least one interface from each blade to the Trunk.
  7. Enable Link Aggregation Control Protocol (LACP) if appropriate for your environment.
  8. Click Finished.

Creating a dedicated failover VLAN

Impact of procedure: None

  1. Log in to the Configuration utility.
  2. Click Network.
  3. Click VLANs.
  4. Click Create.
  5. Enter a Virtual Local Area Network (VLAN) name.

    For example:

    HA_VLAN

  6. Select the Trunk created in the previous procedure as the interface to be used for the VLAN.
  7. Define the remaining VLAN parameters as appropriate for your environment.
  8. Click Finished.

Creating a self IP address and associate the self IP with the failover VLAN

Impact of procedure: None

  1. From the Main tab, click Network.
  2. Click Self IPs.
  3. Click Create.
  4. Enter the IP address and netmask for the failover network.
  5. Select the failover VLAN from the VLAN menu.

    For example:

    HA_VLAN

  6. Click Finished.

Defining a unicast entry specifying the local and remote self IP addresses

Impact of procedure: None

  1. From the Main tab, click System.
  2. Click High Availability.
  3. Click Network Failover.
  4. To use the Minimum blades up feature, select the Minimum blades up enabled check box and enter a value for the Minimum blades up setting.
  5. In the unicast section, enter the Configuration Identifier.

    For example:

    <hostname>_HA_VLAN

  6. In the Local Address field, enter the local self IP address that is associated with failover VLAN.
  7. In the Remote Address field, enter the remote self IP address that is associated with failover VLAN of the peer VIPRION system.
  8. In the Port field, type 1026.
  9. Click Add.
  10. Click Update.

Defining a multicast entry using the management interface for each VIPRION system

F5 recommends that you provide additional redundancy by defining both unicast and multicast failover addresses for each VIPRION system. As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the management port for each VIPRION system. The unicast mesh option is discussed later in the Define a unicast mesh (alternative option) section.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, navigate to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

Impact of procedure: None

  1. Log in to the BIG-IP Configuration utility.
  2. Click Main.
  3. Click System.
  4. Click High Availability.
  5. Click Network Failover.
  6. In the Multicast section, enter the Configuration Identifier.

    For example:

    Multicast_mgmt

  7. In the Remote Address field, enter the following address:

    224.0.0.245

  8. In the Port field, enter the following port:

    62960

  9. Click Add.
  10. Click Update.

Defining a full mesh of unicast entries (alternative option)

As an alternative to defining a multicast entry using the management port, you can define a mesh of unicast entries using the cluster member IP address of each blade for each VIPRION system. The full mesh of unicast entries includes the cluster member IP address for each slot on the VIPRION system configured to communicate with the cluster member IP address for each slot on the peer VIPRION system.

Important: This procedure requires that you configure a valid cluster member IP address for each slot on the VIPRION system. To do so, navigate to System > Clusters > Management IP Address. For more information, refer to K14392: Configuring a cluster member IP address for all slots on a VIPRION platform.

For example, using the unicast mesh option, a fully populated four slot VIPRION chassis requires configuring 17 unique unicast Configuration Identifiers per VIPRION System (17 unicast Configuration Identifiers includes the one created above in the Define a unicast entry using a TMM port for each VIPRION system section). A redundant VIPRION deployment containing three slots requires configuring 10 unicast Configuration Identifiers per VIPRION System. A redundant VIPRION deployment containing two slots requires configuring five unicast Configuration Identifiers per VIPRION System. And lastly, a redundant VIPRION deployment containing one slot requires configuring two unicast Configuration Identifiers per VIPRION System.

To define a full mesh of unicast entries using the cluster member IP addresses, navigate to System > High Availability > Network Failover and perform the following procedure:

Important: The cluster IP address is not the same as the cluster member IP address. Only use the cluster member IP addresses. Do not add the cluster IP address to the entries in the Failover Unicast Configuration. You can view the cluster member IP address by navigating to System > Clusters > Management IP Address.

Impact of procedure: None

Note: In the following steps, F5 assumes a redundant VIPRION deployment containing two slots. If your VIPRION system contains more than two slots, you must configure the necessary Configuration Identifiers.

Slot 1 to Slot 1

  1. In the Unicast Configuration Identifier box, enter a unique name that identifies the slot to slot communication.

    For example:

    Slot1_Slot1

  2. In the Local Address box, type the Cluster Member IP address for Slot 1 of the local VIPRION system.

    Note: You can view the cluster member IP address by navigating to System > Clusters > Management IP Address.

  3. In the Remote Address box, type the Cluster Member IP address for Slot 1 on the peer VIPRION system.
  4. In the Port box, type 1026.
  5. Click Add.

Slot 1 to Slot 2

  1. In the Unicast Configuration Identifier box, enter a unique name which identifies the slot to slot communication.

    For example:

    Slot1_Slot2

  2. In the Local Address box, type the Cluster Member IP address for Slot 1 of the local VIPRION system.
  3. In the Remote Address box, type the Cluster Member IP address for Slot 2 on the peer VIPRION system.
  4. In the Port box, type 1026.
  5. Click Add.

Slot 2 to Slot 1

  1. In the Unicast Configuration Identifier box, enter a unique name which identifies the slot to slot communication.

    For example:

    Slot2_Slot1

  2. In the Local Address box, type the Cluster Member IP address for Slot 2 of the local VIPRION system.
  3. In the Remote Address box, type the Cluster Member IP address for Slot 1 on the peer VIPRION system.
  4. In the Port box, type 1026.
  5. Click Add.

Slot 2 to Slot 2

  1. In the Unicast Configuration Identifier box, enter a unique name which identifies the slot to slot communication.

    For example:

    Slot2_Slot2

  2. In the Local Address box, type the Cluster Member IP address for Slot 2 of the local VIPRION system.
  3. In the Remote Address box, type the Cluster Member IP address for Slot 2 on the peer VIPRION system.
  4. In the Port box, type 1026.
  5. Click Add.

Repeat these steps on the peer VIPRION system.
