K00502149: Inserting content-security-policy in a 302 redirect

Type
Support Solution
Published
2024-08-23
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K00502149

Description
- You want to set the content-security-policy header in an HTTP 302 response.
- You have tried setting in the HTTP_RESPONSE event but neither the content-security-policy header is set nor the re-direct happens.

Environment

  • BIG-IP
  • HTTP Profile

Cause
The header set on the HTTP::redirect event is overwritten when the content-security-policy header is set. This causes the redirect to not happen.

Recommended Actions

  1. Create an irule with the appropriate event, normally:  HTTP_REQUEST.
  2. Add the content: HTTP::respond 302 noserver Location "https://<url>" "content-security-policy" "default-src 'self';"
replace <URL> accordingly.
Example:

when HTTP_REQUEST {
if { [HTTP::path] eq "/" }{
HTTP::respond 302 noserver Location "https://<url>" "content-security-policy" "default-src 'self';"
}
}
This will correctly redirect to https://<url>  and will maintain the "content-security-policy" header.
