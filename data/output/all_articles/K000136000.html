K000136000: Stopping tripo properly to solve tripo start issues

Type
Support Solution
Published
2023-08-29
Updated
2024-10-01
Applies to
  • Traffix SDC: 5.2.X, 5.2.0, 5.1.0
Source
https://my.f5.com/manage/s/article/K000136000

Description

  • There are instances where you might need to restart Tripo in order to solve certain issues with it.

  • Examples of these Tripo issues are(but not limited to) missing graphs and disconnections to CPF.

  • You might see in the tripo stdout logs that it has stopped but never started, this is an indication that the Tripo stop/start was not successful.

Environment

  • SDC 5.x
  • Tripo

Cause

Tripo has multiple dependent processes that needs to run together in order for it to function properly.

 Recommended Actions

1. Unmonitor tripo. This is to prevent monit from attempting to auto start the tripo process if it checked the process and found that it is down.

#monit unmonitor <tripo process name>
#monit summary

2. Switch to traffix userid and load the Tripo env

#su - traffix
#. ~/Tripo/env/linux/DefEnv Tripo

3. Check the status of tripo.

#status.sh

::Example::
[traffix@SDC Tripo]$ status.sh
ComSrv is up
LogSrv is up
RepMgr is up
Storage is up
SysWatchDog is up
WebStatMgr is up

4. If confirmed that not all tripo processes are up, then stop the tripo processes.

#stop.sh

::Example::
[traffix@SDC Tripo]$ stop.sh
ComSrv is down
LogSrv is down
RepMgr is down
Storage is down
SysWatchDog is down
WebStatMgr is down

5. Wait for all the tripo processes to stop, this can be confirmed with status.sh or ps command (most are down after 5min) 

#status.sh ; ps -ef | grep 'ComSrv\|LogSrv\|RepMgr\|Storage\|SysWatchDog\|WebStatMgr'

6. If after 5 mins tripo processes are still running, use the kill command to stop any existing tripo processes.

7. Repeat step 3 to confirm tripo process has stopped.

8. (Optional) Clear the files in /dev/shm/Tripo using command:

#cleansh

9. Switch back to root id.

#exit

10. Enable monitor tripo process:

#monit monitor <tripo process name>
#monit summary

11. monit will start the process in a few min

12. If monit does not start the Tripo process, Issue the monit start command.

#monit start <tripo process name>

13. After monit has started the process
13.1. Check and verify all process are up
#grep 'ComSrv\|LogSrv\|RepMgr\|Storage\|SysWatchDog\|WebStatMgr' 
13.2. Check /home/traffix/Tripo/log/traffix_tripo-default-stdout.log and make sure last state is start and not stop.

Additional Information

None.
