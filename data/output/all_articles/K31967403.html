Topic

You should consider using this procedure under the following condition:

  • You want to enable software SYN cookie protection for nPath (DSR) routing.

Description

With the Layer 3 nPath routing configuration, you can route outgoing server traffic around the BIG-IP system directly to an outbound router. Hardware SYN cookie protection is not supported for nPath routing configurations. However, starting in BIG-IP 11.4.1, you can use Software SYN cookie protection with nPath configurations. To do so, you must disable Hardware SYN Cookie Protection and enable Software SYN Cookie Protection as well as SYN Cookie White List in the FastL4 profile in addition to configuring other settings required for nPath routing.

Note: F5 is working to eliminate exclusionary language in our products and documentation. For more information, refer to K34150231: Exclusionary language in F5 products and documentation.

The feature operates as follows when you enable Software SYN cookie protection for the FastL4 profile:

  1. A client sends a TCP SYN request to the BIG-IP virtual server configured for nPath routing.
  2. The BIG-IP system proxies the initial TCP handshake and uses SYN cookies to validate the request.
  3. If the client responds appropriately, the BIG-IP system sends a TCP RST to the client and then adds the client's IP address to a white list.
  4. The BIG-IP system sends subsequent connections from the white-listed IP address to the server

Note: If you want, you can enable or disable the SYN Cookie White List feature in the FastL4 profile. For more information about configuring nPath routing, refer to the BIG-IP Local Traffic Manager: Implementations manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have configured nPath routing in your environment.
  • You have administrative access to the Configuration utility.
  • You have access to the BIG-IP Advanced Shell (bash) and the TMOS Shell (tmsh).

Procedures

Enabling software SYN cookie protection for nPath routing (15.1.0 and later)

You can use SYN Cookie DSR Flow Reset By setting under the FastL4 profile to reset the TCP connection either by the BIG-IP or a client. This setting is available when SYN Challenge Handling is set to Challenge and Remember. The Challenge and Remember option specifies whether SYN packets subsequent to a successful challenge from the same Source IP address, should be challenged or allowed to pass unchallenged (up to some timeout period). Enabling this feature prevents hardware acceleration for SYN challenges, but may be needed/useful in some deployments (direct server return (DSR) mode or when no hardware acceleration is available). To enable this option, modify the custom FastL4 profile you are using for your nPath setup by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > FastL4.
  3. Select the FastL4 profile currently assigned to the virtual server to which you want to allow SYN cookie protection.
  4. Enable the SYN Challenge Handling by selecting the custom check box.
  5. Select the Challenge and Remember option from the list.
  6. Enable the SYN Cookie DSR Flow Reset By setting by selecting the custom check box.
  7. Select the Bigip option from the list so that BIG-IP sends TCP reset to client upon receiving a TCP ACK. (Default is None for this setting).
  8. Select Update.

Enabling software SYN cookie protection for nPath routing (13.0.0 through 15.0.0)

You can use the syn-cookie-enable (enabled / disabled) option to enable or disable the hardware or software SYN cookie protection in the TCP and FastL4 profiles; this option is enabled by default in the TCP and FastL4 profiles. To enable this option, modify the custom FastL4 profile you are using for your nPath setup by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > FastL4.
  3. Select the FastL4 profile currently assigned to the virtual server to which you want to allow SYN cookie protection.
  4. Enable the SYN Challenge Handling by selecting the custom check box.
  5. Select the Challenge and Remember option from the list.
  6. Select Update.
  7. Log in to the Advanced Shell (bash) to modify database key.
  8. To modify the connection.dsrsynfloodprotect database key to enable software SYN Cookie protection for nPath routing, enter the following command:

    tmsh modify /sys db connection.dsrsynfloodprotect value enable

  9. Save the changes made to the configuration by entering the following command:

    tmsh save /sys config

Enabling software SYN cookie protection for nPath routing (11.4.1 through 12.1.5)

You can enable software SYN cookie protection for nPath routing using Configuration utility. When you configure this option, SYN traffic is challenged with an RST that only the BIG-IP device handles. When clients attempt to reconnect, the system accepts them. When a client completes the challenge, the system caches the client and allows traffic through to the configured pool. The TM.FlowState.Timeout system database variable controls how long entries are cached. To enable this option, modify the custom FastL4 profile you are using for your nPath setup by performing the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Protocol > FastL4.
  3. Select the FastL4 profile currently assigned to the virtual server to which you want to allow SYN cookie protection.
  4. Clear the Hardware SYN Cookie Protection check box.
  5. Select the Software SYN Cookie Protection check box.
  6. Select the SYN Cookie White List check box.
  7. Select Update.
  8. Log in to the Advanced Shell (bash) to modify database key.
  9. To modify the connection.dsrsynfloodprotect database key to enable software SYN Cookie protection for nPath routing, enter the following command:

    tmsh modify /sys db connection.dsrsynfloodprotect value enable

  10. Save the changes made to the configuration by entering the following command:

    tmsh save /sys config
