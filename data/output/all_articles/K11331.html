Known Issue

This is the result of a known issue. If a client fails an SSL handshake with a BIG-IP WebAccelerator virtual server, messages are logged to the /var/log/tmm file that appear similar to the following examples :

notice respond: [ 8eabd70] unhandled event after 3 events
notice respond: [ 8eabd70] HUDEVT_FLOW_INIT -> NONE in UNESTABLISHED_PROXY
notice respond: [ 8eabd70] HUDCTL_ENABLE -> NONE in UNESTABLISHED_PROXY
notice respond: [ 8eabd70] HUDEVT_EOF -> PEER_EOF in UNESTABLISHED_PROXY

notice respond: [ 8ec3e8c] unhandled event after 21 events
notice respond: [ 8ec3e8c] HUDCTL_ENABLE -> NONE in ESTABLISHED_PEER
notice respond: [ 8ec3e8c] HUDCTL_PERFORM_METHOD -> NONE in ESTABLISHED_PEER
notice respond: [ 8ec3e8c] HUDEVT_LISTENER_PICKED -> LB_RESPOND in ESTABLISHED_PEER
notice respond: [ 8ec3e8c] HUDEVT_ALT_DEST_PICKED -> NONE in RESPOND_PEER
notice respond: [ 8ec3e8c] HUDEVT_REQUEST -> REQUEST in RESPOND_PEER
notice respond: [ 8ec3e8c] HUDEVT_REQUEST_DONE -> REQUEST_DONE in RESPOND_WAIT_PEER
notice respond: [ 8ec3e8c] HUDEVT_EOF -> PEER_EOF in RESPONDING_PEER
notice respond: [ 8ec3e8c] HUDEVT_SHUTDOWN -> PEER_SHUTDOWN in RESPONDING_PEER_SHUTDOWN

These messages are benign and represent internal BIG-IP WebAccelerator states. You can ignore these messages because they are superfluous and should not be logged by the BIG-IP WebAccelerator.

F5 Products Development tracked this issue as CR137702, and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
