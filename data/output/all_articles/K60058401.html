Description

In the wake of a concern of a compromised BIG-IP system (for example: K52145254: TMUI RCE vulnerability CVE-2020-5902), you may want to have the BIG-IP system perform audit logging for URIs that are used to access Traffic Management User Interface (TMUI) or Configuration utility. This can offer helpful indicators and evidence in understanding whether the device has been compromised. This article covers information on how you can configure the BIG-IP system to log the HTTPS requests sent to the Configuration utility.

Note: Logging these requests locally can increase logging overhead on the device and F5 recommends having these messages logged off-the-box to a remote server.  Additionally, if the goal is to audit the system for incoming requests to look for potential sources of compromise, F5 strongly recommends enabling remote logging for this purpose. A skilled attacker could remove evidence of compromise, including log files, after successful exploitation.

Environment

  • BIG-IP
  • Software versions: 11.x, 12.x, 13.x, or 14.0.x

Cause

Beginning in BIG-IP 11.0.0, HTTPS requests to the Configuration utility are no longer logged to the /var/log/httpd/ directory, by default. However, in subsequent versions, you can change the log level for HTTPD (local6 facility) to Informational in order to perform audit logging for HTTPS requests used to access TMUI.

Recommended Actions

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Run the following command to view the default lowest level for messages from local6 facility (HTTPD specific messages) when it comes to syslog:

    list /sys syslog local6-from

  3. Modify the lowest log level for local6 facility to info using the following command:

    modify /sys syslog local6-from info

  4. Save the change by entering the following command:

    save /sys config partitions all

  5. The lowest logging level for messages from local6 facility should now be set to info level:

    (tmos)# list sys syslog local6-from
    sys syslog {
        local6-from info
    }

  6. After sending requests to TMUI by accessing it via browser, you can now observe the information logged to /var/log/httpd/ss_access_log with the URIs that were requested to load the page:
