K8494: Identification of binary data by the Policy Builder feature in file uploads

Topic

The Policy Builder feature identifies binary data, which is typically associated with file uploads, based on identifying a pattern in the data that indicates the information is not strictly text. An example of this behavior is the existence of certain characters (NULL) or certain byte sequences.

When the Policy Builder encounters patterns indicating that the information is binary data and not text, the Ignore value parameter value is given to the data. The Policy Builder requires a minimum number of uploaded files (200 Requests) before the parameter type is defined as Ignore Value. The decision to determine the request is a binary type can be performed using the MIME type parameter within a request.

When a file upload contains a MIME type parameter (including empty case) and the media value is not text, the Policy Builder assumes the specific parameter value is a binary file.

Note: By default, 80 percent of the file must be binary values in order for Policy Builder to flag the parameter input type as binary.

If the file upload MIME type is not defined or the MIME type is text, the Policy Builder assumes the specific parameter value is a text file.

The Policy Builder identifies the following MIME types as non-binary:

  • text/html
  • text/plain
  • text/xml
  • text/css

The Policy Builder identifies the following MIME types as binary:

  • image/gif
  • video/mpeg

Once the Policy Builder has received enough traffic to analyze, and the amount of traffic is above the lower threshold and crossed the heuristic thresholds defined for binary or text files, the parameter attributes will be set as follows:

  • Detected binary file values are assigned a parameter value type of Ignore Value
  • Detected text file values are assigned a parameter value type of User Input value and a Data Type of Binary (Length checks only)

Changing the lower threshold and the heuristic threshold

You can change the lower threshold (the minimum amount required to assign the parameter input type is binary) and the heuristic threshold (the minimum number of requests needed in order to analyze the data). To do so, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /ts/crawlers/plc_crawler/conf/ directory by typing the following command:

    cd /ts/crawlers/plc_crawler/conf/
  3. Use an editor to edit the pb.xconf file.
  4. To change the heuristic threshold, locate the following heading:

    <!-- *** Entities heuristics constants *** -->
    <!-- minimal number of requests containing the object/parameter -->
  5. Change the following default entry of 200:

    <min-object-traffic>200</min-object-traffic>
  6. To change the lower threshold, locate the following heading:

    <!-- Minimal portion of binary values in parameter to decide parameter input type is binary -->
  7. Change the following default entry of .80:

    <binary-file-criteria>0.80</binary-file-criteria>
  8. Save the changes to the file.
  9. Restart the BIG-IP ASM system by typing the following command:

    bigstart restart asm


Once the BIG-IP ASM system has been restarted, you must restart the Policy Builder, In order to load the new values, perform the following procedure:

Note: The Policy Builder will report Inactive if not restarted. For more information, refer to K8255: The Policy Builder does not become active after the BIG-IP ASM is restarted from the command line.

  1. Log in to the Configuration utility.
  2. Select Application Security.
  3. Select Web Applications.
  4. Select the Web Application for which you want to check the status.
  5. Select Policy.
  6. Select the Status option from the Policy Builder drop-down menu to verify the status of the Policy Builder.

    If the status reports Inactive, proceed to the next step.
  7. Click Apply Policy to restart the Policy Builder.
