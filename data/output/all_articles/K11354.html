Known Issue

This is the result of a known issue. When an ETag value for an object is updated due to an OWS expiration, the BIG-IP WebAccelerator by default logs a warning message to the pvac log. A flaw in the way the BIG-IP WebAccelerator generates the log message causes a segmentation fault, and error messages display in the pvac log that appear similar to the following example: 
 
WA Debug ( 7006): [             PvSysApp.cxx:1753      appHandleRequest ] Error [0x6d]
WA Debug ( 7001): [             PvSysApp.cxx:1753      appHandleRequest ] Error [0x6d]

When this behavior occurs, no further log messages are logged to the pvac log. These errors and the absence of subsequent errors indicate that a deadlock has occurred in the logging subsystem, and the system is unable to log further messages to the pvac log. The pvac process eventually hangs, and the BIG-IP WebAccelerator system stops processing traffic.

Note: It may take several hours for the logging deadlock to hang the pvac process.

F5 Networks Product Development tracked this issue as CR135114 and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator or Edge Gateway Release Notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing version 10.x hotfixes, refer to K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

This issue was fixed in an engineering hotfix issued for BIG-IP WebAccelerator version 10.1.0. Customers affected by this issue should contact F5 Networks Technical Support, referencing this Solution number and the associated CR number.

Workaround

You can work around this issue by preventing the BIG-IP WebAccelerator from logging warnings on ETag expiration. To do so, type the following command:

setDebugZone ZONE_SCRUB.error
