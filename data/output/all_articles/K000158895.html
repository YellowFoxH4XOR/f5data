K000158895: Non-sequential self IP assignment in F5BigNetVlan when more than 10 selfip_v4s are configured

Type
Support Solution
Published
2025-12-23
Updated
2025-12-23
Applies to
  • BIG-IP Next DNS CNF: 2.0.0
  • BIG-IP Next CNF
Source
https://my.f5.com/manage/s/article/K000158895

Description

When scaling TMM pods and assigning self IPs through the F5BigNetVlan custom resource (CR), self IPs may be assigned in an unexpected (non-sequential) order if the CR contains more self IPs than the number of running TMM replicas—particularly when the list exceeds 10 entries.

Symptoms can include:

  • TMM pods using an unexpected self IP from the provided list (for example, a “12th” IP being used even when only 10 replicas exist).
  • Neighbor network devices failing to communicate with the unexpected IP(s).
  • The f5ingress logs showing DP indices ordered lexicographically rather than numerically, for example:
    • DP-0, DP-1, DP-10, DP-11, DP-2, … DP-9

 

Environment

  • Product: BIG-IP Next DNS CNF
  • Version observed: 2.1.0
  • Configuration object: F5BigNetVlan CR
    • Parameters involved: spec.selfip_v4s (and potentially spec.selfip_v6s)
  • Conditions:
    • More self IPs configured in the CR than the number of existing TMM pods
    • Common trigger: configuring 11+ self IPs (DP-10/DP-11 introduces non-numeric ordering behavior)

Cause

ID2162853

Recommended Actions

  1. Ensure the number of IPs in spec.selfip_v4s and/or spec.selfip_v6s matches the intended number of TMM replicas (do not provide extra IPs beyond the current pod count if deterministic positional assignment is required).

  2. If you previously configured more IPs than replicas and observed unexpected assignment:
    1. Update the F5BigNetVlan CR to remove the extra self IP entries (reduce the list to the replica count).
    2. Scale/restart the affected components as needed so pods re-establish expected mappings (for example, scale down after removing extra IPs, then scale back up).
  3. Validate that none of the configured self IPs are invalid for use as host addresses (for example, do not configure a subnet broadcast address as a self IP). 

Additional Information

  • Intended behavior is positional assignment (first self IP to first TMM pod, second to second, and so on), but this order is not guaranteed when more self IPs are configured than the number of existing TMM pods.
  • When more than 10 self IPs are present, the DP key ordering can become lexicographic (string-based), which can result in mappings like DP-10 and DP-11 being placed between DP-1 and DP-2, leading to non-sequential assignment.
  • If an unexpectedly selected address is unusable in the network (for example, a broadcast IP), it can lead to an outage.
