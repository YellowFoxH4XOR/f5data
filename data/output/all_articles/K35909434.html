K35909434: Error: The system returned an unexpected error (400 Bad Request). Mounting external storage failed due to command execution timeout. Please ensure there is no network connectivity issues between external storage server and ES cluster.

Published

Updated
2025-02-06
Applies to

Description

In BIG-IQ Centralized Management, when trying to mount the external storage for snapshot backup, the following error are seen

The system returned an unexpected error (400 Bad Request). Mounting external storage failed due to command execution timeout. Please ensure there is no network connectivity issues between external storage server and ES cluster

Environment

  • BIG-IQ Centralized Management
  • BIG-IQ Snapshot backup
  • External storage server

Cause

This issue can trigger due to any or all of the below reasons. 

  1. If you are using BIG-IQ v7 or earlier it will allow only SMBv1, be sure the external storage SMB server is using SMBv1 protocol.
    NOTE: BIG-IQ v8.X now supports SMBv2 and SMBv3
  2. The external storage SMB server is not allowing SMB connections from the Big-IQ Centralized Management.
  3. The local snapshots folder (/var/config/rest/elasticsearch/data/essnapshot) is already mounted

Recommended Actions

  1. Make sure the SMB server is listening and negotiating properly on port TCP 139 or TCP 445.

  2. If the local snapshots folder (/var/config/rest/elasticsearch/data/essnapshot) is already mounted on SMB server, remove the mount using the command as below on the SMB server. 
    # umount /var/config/rest/elasticsearch/data/essnapshot

  3. Take a packet and verify if the SMB server is responding properly, to verify you can do the following:
    1. Open 2 SSH session on the BIG-IQ DCD '10.12.0.247', in one session run the tcpdump: (replace IP_STORAGE_SERVER with your storage server IP)
      tcpdump -vni eth0 host IP_STORAGE_SERVER -s0 -w /var/tmp/capture1.pcap
    2. While running the above tcpdump command, in the second SSH session from the bash run:
      mount -t cifs //IP_STORAGE_SERVER/<folder> /var/config/rest/elasticsearch/data/essnapshot -o uid=elasticsearch,gid=elasticsearch,rw,iocharset=utf8,noauto,sec=ntlm,user=<user>,password='<pass>',domain=<domain>
      (Replace <user>, <pass> and <domain> with the corresponding values)
    3. Stop the packet capture with CTRL+C and download it from the BIG-IQ DCD using any Secure FTP application like WinSCP or FileZilla. 
    4. Once you have the pcap file in your desktop open it with Wireshark and follow the sequence. 
    5. In this example we can see the SMB server is not responding accordingly:

Additional Information
Manual Chapter : Behavior Changes in BIG-IQ Version 8.0.0
BIG-IQ now supports DCD backup storage on SMB versions 1-3. The new default external storage settings are for version SMB3. SMB 1 is still supported, but this version is not recommended due to its security vulnerabilities.
