Known Issue

The lind process may continuously restart when installing software images with incorrect Linux file permissions.

This issue occurs when all of the following conditions are met:

  • You are logged in to either the BIG-IP system Advanced Shell (bash) or the Traffic Management Shell (tmsh) on a Virtual Clustered Multiprocessing (vCMP) guest. 
  • You are attempting to install a software image using following command syntax:

    tmsh install sys software block-device-image <software_image> volume <number>

    For example, the following command attempts to install BIG-IP-12.1.2.0.0.249.iso software image to volume HD1.2:

    tmsh install sys software block-device-image BIGIP-12.1.2.0.0.249.iso volume HD1.2

  • The software image stored in the /shared/images directory on the vCMP host has the wrong Linux file permissions. The correct Linux file permissions are 644.

Note: The issue of lind continuously restarting has been fixed as of BIG-IP 13.0.0 and later. However, the software installation still fails when the software image Linux file permissions are incorrect. Review this article's Symptoms and Workaround sections for additional information if you are running BIG-IP 13.0.0 and later.

Impact

The lind process continually restarts and the software image installation does not complete successfully.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP 12.1.2 and earlier:
    • You notice messages at the command prompt indicating the lind process is continuously restarting.
    • You notice the following error messages in the /var/log/ltm file of the vCMP guest:

      err lind[123456]: 013c0004:3: Fatal error: vcmp_media_insert failed
      notice mcpd[5678]: 01070410:5: Removed subscription with subscriber id lind

  • BIG-IP 13.0.0 and later:
    • You notice the following errors when you run the tmsh show sys software command on the vCMP guest:

      HD1.2      1   BIG-IP   13.0.0  0.0.1645      no  failed (Failure testing installer update status in /shared/images/BIGIP-13.0.0.0.0.1645.iso.)
      HD1.2      2   BIG-IP   13.0.0  0.0.1645      no  failed (Failure testing installer update status in /shared/images/BIGIP-13.0.0.0.0.1645.iso.)
      HD1.2      3   BIG-IP   13.0.0  0.0.1645      no  failed (Failure testing installer update status in /shared/images/BIGIP-13.0.0.0.0.1645.iso.)
      HD1.2      4   BIG-IP   13.0.0  0.0.1645      no  failed (Failure testing installer update status in /shared/images/BIGIP-13.0.0.0.0.1645.iso.)

    • You notice the following error message in the /var/log/ltm file of the vCMP guest:

      err lind[5678]: 013c0004:3: Insert failed: File not valid, likely bad permissions

Workaround

To work around this issue, you can correct the Linux file permissions from bash. To do so, perform the following procedure based on your software version:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash of the vCMP host.
  2. To ensure that all BIG-IP software images have the correct Linux file permissions, type the following command:

    chmod 644 /shared/images/BIGIP*

    For VIPRION systems with multiple blades, type the following command:

    clsh chmod 644 /shared/images/BIGIP*

  3. Log in to bash of the vCMP guest.
  4. To reinitialize the lind process, type the following command:

    Note: In BIG-IP 13.0.0 and later, the software image installation should resume.

    tmsh restart sys service lind

    For VIPRION systems with multiple blades, type the following command:

    clsh tmsh restart sys service lind

  5. In BIG-IP 12.1.2 and earlier, to complete the installation, use the following command syntax:

    tmsh install sys software block-device-image <software_image> volume <number>

    For example, to complete the installation of BIG-IP-12.1.2.0.0.249.iso software image to volume HD1.2, type the following command:

    tmsh install sys software block-device-image BIGIP-12.1.2.0.0.249.iso volume HD1.2
