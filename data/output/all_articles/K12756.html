Topic

You should consider using this procedure under the following conditions:

  • You experience disk errors or a failed disk in a RAID array.
  • You use a BIG-IP 6900, 7000s, 7200v, 7055, 7255, 8900, 8950, 10000s, 10200v, 11000, 10055, 10255, or 11050 platform.

Description

You can repair some disk errors and failing disks in RAID arrays from the command line using utilities found on the BIG-IP system. To do so, perform the following procedures as needed:

  • Repair disk errors on systems running BIG-IP 10.x with non-RAID storage
  • Repair disk errors on systems running BIG-IP 10.x through 13.x with RAID storage

Important: To prevent the loss of your BIG-IP configuration, back up the configuration as soon as you suspect a disk issue, and copy the resulting user configuration set (UCS) archive file to another system. For more information, refer to the following article that applies to your version:

  • K13132: Back up and restoring BIG-IP configuration files with a UCS archive
  • K11318: Back up and restoring BIG-IP configuration files (10.x)

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have administrative access to the command line on the BIG-IP system.

Procedures

Repair disk errors on systems running BIG-IP 10.x with non-RAID storage

Impact of procedure: Forcing a file system check and performing a clean installation involves rebooting the system, which will cause a traffic disruption or failover of an active system.

If only one disk is failing or suspect, force the fsck utility to run. For more information, refer to K10328: Forcing a file system check on the next system reboot (10.x - 11.x) or K73827442: Forcing a file system check on the next system reboot (12.x - 15.x)

If both disks are showing data loss, or you suspect other issues, F5 recommends that you perform a clean installation of the software. For more information, refer to K10819: Performing a clean installation of BIG-IP 10.x or Enterprise Manager 2.x

If errors persist, contact F5 Support for assistance.

Repair disk errors on systems running BIG-IP 10.x through 13.x with RAID storage

If both disks are showing data loss, or you suspect other issues, F5 recommends that you perform a clean installation of the software. For more information, refer to the following article that applies to your version:

  • K13117: Performing a clean installation of BIG-IP 11.x - 14.x or Enterprise Manager 3.x
  • K10819: Performing a clean installation of BIG-IP 10.x or Enterprise Manager 2.x

If errors persist, contact F5 Support for assistance.

For information about rebuilding RAID on BIG-IP WebAccelerator 4500 platforms, refer to K12223: Error Message: RAID monitor: RAID is degraded. Run 'rebuild_raid -s' for more information.

If only one disk in the RAID array is failing or suspect, you can repair the errors by first attempting a logical rebuild of the RAID array. If necessary, you can perform a physical rebuild. To do so, perform the following procedures:

  • Performing a logical rebuild of the RAID array
  • Performing a physical rebuild of the RAID array

Perform a logical rebuild of the RAID array

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To display the RAID information, type one of the following commands:

    From the BIG-IP command line:

    tmsh show sys raid array

    From the tmsh console:

    show sys raid array

    The command displays output that appears similar to the following example:

    Sys::Raid::Array: MD1
    --------------------
    Size (MB) 305245

    Sys::Raid::ArrayMembers
    Bay ID Serial Number Name Array Member Array Status
    ---------------------------------------------------------
    1 WD-WCAT18586780 HD2 yes failed
    2 WD-WCAT1E733419 HD1 yes ok

  2. Note the array label and the names of any drives associated with the array whose Array Status is failed. 

    In the example, the array is labeled MD1 and the problem disk is HD2.

    Note: A drive with an Array Status of missing can be caused by replacing the drive. For more information, refer to K12380: RAID capable BIG-IP platforms report the RAID status as degraded in the Configuration utility after a hard drive replacement.

  3. Logically remove the affected disk from the array by typing one of the following console commands:

    From the BIG-IP command line:

    tmsh modify sys raid array <array name> remove <disk name>

    From the tmsh console:

    modify sys raid array <array name> remove <disk name>

  4. After you have logically removed the disk from the array, add the disk to the array again by typing one of the following commands:

    From the BIG-IP command line:

    tmsh modify sys raid array <array name> add <disk name>

    From the tmsh console:

    modify sys raid array <array name> add <disk name>

Perform a physical rebuild of the RAID array

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To display the RAID information, type one of the following commands:

    From the BIG-IP command line:

    tmsh show sys raid array

    From the tmsh console:

    show sys raid array

    The command displays output that appears similar to the following example:

    Sys::Raid::Array: MD1
    --------------------
    Size (MB) 305245

    Sys::Raid::ArrayMembers
    Bay ID Serial Number Name Array Member Array Status
    ---------------------------------------------------------
    1 WD-WCAT18586780 HD2 yes failed
    2 WD-WCAT1E733419 HD1 yes ok

  2. Note the array label and the Bay ID of any drives associated with the array whose Array Status is failed. Note the serial number of the failed drive so you can verify that removed the correct drive.

    In the example, the array is labeled MD1 and the problem disk is in Bay 1.

    Note: A drive with an Array Status of missing can be caused by replacing the drive. For more information, see K12380: RAID capable BIG-IP platforms report the RAID status as degraded in the Configuration utility after a hard drive replacement.

  3. Shut down the device.
  4. Physically remove the affected drive from the chassis and check the serial number to verify that you removed the correct drive.

    Note: When looking at the front panel of a 6900, 7xxx, 89xx, 10xxx, or 11xxx series appliance, Bay 1 is the disk tray on the left and Bay 2 is the tray on the right.

  5. With the single drive remaining, start the device again. Allow time for the device to fully boot and for the RAID master to be assigned to the remaining drive, then shut down the device.

    Note: If you have to remove the fan tray in order to remove the hard drive, replace the fan before starting the device.

  6. Reinsert the drive into the appliance.
  7. Start the device.
  8. To monitor the system to verify that RAID begins rebuilding on the drive, type one of the following commands:

    From the BIG-IP command line:

    tmsh show sys raid

    From the tmsh console:

    show sys raid

    The command displays output that appears similar to the following example:

    Sys::Raid::Array: MD1
    --------------------
    Size (MB) 305245

    Sys::Raid::ArrayMembers
    Bay ID Serial Number Name Array Member Array Status
    ---------------------------------------------------------
    1 WD-WCAT18586780 HD2 yes replicating
    2 WD-WCAT1E733419 HD1 yes ok

    If the array status of the affected drive is identified as replicating, this indicates that the system is transforming the disk into a RAID mirror and restoring the data to the array.

    Note: You can also monitor the RAID rebuilding process using the Configuration utility. For BIG-IP 11.x and later, navigate to System > Disk Management. For BIG-IP 10.x, navigate to System > RAID Management. The Configuration utility displays an alert near the top banner indicating that the RAID array is degraded during the replication process. F5 expects this behavior.

  9. Verify that the RAID array has been rebuilt successfully using the method you selected in step 6 to monitor the status of the array. When the array is finished rebuilding, both disks display a status of ok, similar to the following example:

    Sys::Raid::Array: MD1
    --------------------
    Size (MB) 305245

    Sys::Raid::ArrayMembers
    Bay ID Serial Number Name Array Member Array Status
    ---------------------------------------------------------
    1 WD-WCAT18586780 HD2 yes ok
    2 WD-WCAT1E733419 HD1 yes ok

    Note: The array rebuilding process typically takes approximately 30 to 60 minutes to complete. However, if the BIG-IP system is actively passing traffic, the process may take a considerably longer time to complete.

  10. Monitor the RAID status over a period of several weeks to ensure that disk errors have been fully repaired.
