Known Issue

Note: The HA Group feature was introduced in BIG-IP 10.1.0. A high availability group uses a set of trunks, pools, clusters (or any combination of these) to calculate the health scores for units in redundant system configurations. For more information about configuring the HA Group feature on the BIG-IP system, refer to the Managing Failover chapter in the BIG-IP Device Service Clustering: Administration manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Note: Cluster objects in a high availability group are only available on clustered systems like VIPRION.

This is a result of a known issue. When you configure the HA Group feature with the Include Cluster option on a VIPRION, the configuration will not load the Include Cluster option after a reboot. However, all other options of the HA Group will load. For example, after a reboot, the following high availability group will not load the Include Cluster option, although the configuration remains intact in the bigip_local.conf (10.x) or bigip.conf (11.x) file:

ha group hagrp1 {
active bonus 0
clusters default {
scoring {
threshold 10
weight 10
}
}
pools test_pool {
scoring {
threshold 1
weight 30
}
}
trunks test_trunk {
scoring {
threshold 1
weight 20
}
}
}

You can verify whether the configuration loaded by typing the tmsh list sys ha-group (11.x) or bigpipe ha group list (10.x) command. Output will appear similar to the following example:

ha group hagrp1 {
active bonus 0
pools test_pool {
scoring {
threshold 1
weight 30
}
}
trunks test_trunk {
scoring {
threshold 1
weight 20
}
}
}

F5 Product Development tracked this issue as ID 337583 and it was fixed in BIG-IP version 11.2.1. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-11.2.0-2557.0-HF2, which has been issued for BIG-IP 11.2.0, and Hotfix-BIGIP-11.1.0-2268.0-HF5 which has been issued for 11.1.0. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

Workaround

You can work around this issue by reloading the BIG-IP configuration. To do so, type the following command appropriate for your BIG-IP version:

BIG-IP 11.x

tmsh load /sys config

BIG-IP 10.x

bigpipe load
