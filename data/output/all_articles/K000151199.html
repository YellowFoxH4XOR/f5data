Description

GSLB virtual server down on LTM even though there are successful ICMP queries to the virtual server IP address.

 

Environment

  • Big-IP DNS
  • Big-IP LTM
  • Pool has a bigip monitor
  • virtual server has an additional icmp_gateway monitor

 

Cause

The virtual server went offline because its pool members were offline according to their own monitors and so the bigip monitor and iquery are reflecting this correctly in GSLB.  The virtual server will still respond to icmp requests in this state though.

Recommended Actions

Restore virtual server's pool members that are failing to respond correctly to their specific monitor and the virtual server should come back up.

 

Additional Information

Decision matrix for determining root cause of a down GSLB virtual server:

Is GSLB down virtual server hosted on a BIG-IP?

Yes:

i) Check iQuery connection to the BIG-IP.

ii) If iQuery connection OK then problem likely on BIG-IP a) Check virtual server status, b) check pool status --> Both are up then iqdump

No:

i) Check if there is a prober pool to monitor --> if no then tough job to debug and identify BIG-IP probing

ii) If prober pool then big3d debug and pcap on on all prober ppool members.
