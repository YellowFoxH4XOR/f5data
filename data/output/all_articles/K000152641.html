Description

When configuring BIG-IP LTM to forward logs to a remote syslog server using High-Speed Logging (HSL) and a custom iRule, the logs may not appear on the syslog server.

  • The custom iRule you are using is similar to this article: K50040950: Configuring the BIG-IP system to send high-speed logs through the management interface
  • This occurs even when syslog configuration and pool settings are in place.
  • When you capture the traffic on both sides ( BIG-IP and Server), you see the logging information is being sent.

You might have the following configuration in an iRule:

when CLIENT_ACCEPTED {
   set hsl \[HSL::open -proto UDP -pool syslog\_server\_pool\]
}

However, the syslog server doesn't show the logs. 

Environment

  • LTM
  • HSL 
  • iRule

Cause

The iRule uses direct HSL::send to the syslog pool, which may send log payloads in a non-RFC 5424 syslog format. Many syslog servers (such as rsyslog or syslog-ng) will silently drop improperly formatted messages.

Answer/Recommended Actions

Instead of sending logs directly to a pool with HSL::open -proto TCP -pool <pool>, use a log publisher:

# Old method:

set hsl [HSL::open -proto TCP -pool <syslog_pool>]

# Recommended method:

set hsl [HSL::open -publisher <your_log_publisher_name>]

Additional Information

For troubleshooting, follow these steps:

1. Verify Pool Member Status. Make sure the pool members are UP.

2. Make sure the iRule is attached to the Virtual Server.

3. Use tcpdump for packet capture analysis to verify the messages are being sent:

  • On BIG-IP:
    • tcpdump -nni 0.0 port 514
  • On Syslog Server:
    • tcpdump -n -i any port 514
