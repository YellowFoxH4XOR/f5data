K000138588: Response of snmpwalk for F5-BIGIP-SYSTEM-MIB::sysProcPidStatProcName sometimes missing some processes

Type
Support Solution
Published
2024-02-13
Updated
2025-02-07
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000138588

Description

Response of snmpwalk for F5-BIGIP-SYSTEM-MIB::sysProcPidStatProcName sometimes misses some processes running on BIG-IP including zrd. When this issue happens, a log message like below is logged in /var/log/ltm.

warning snmpd[<PID>]: 010e0999:4: Duplicate oid index found: bigip_proc_pid_stat.c:283

Note: <PID> is the process ID for the snmpd process.

Environment

  • Running snmpwalk for F5-BIGIP-SYSTEM-MIB::sysProcPidStatProcName locally or remotely against BIG-IP

Cause

This issue is tracked as bug ID 1493869.

Recommended Actions

While the duplicate PID status would be cleared shortly after and the status would be resolved by itself, if this is not acceptable, you may create a custom MIB to monitor a process per K13596.

For example, the following definition allows to monitor zrd proc status.

/config/snmp/custom_mib.tcl

register_mib ".1" zrd_status string

proc zrd_status {}
{
    set status [catch {exec tmsh show sys service zrd} result]
    return $result
}

Running snmpwalk for the MIB receives a response like below.

# snmpwalk -Os -c public -v 1 localhost .1.3.6.1.4.1.3375.2.100.1
bigipTrafficMgmt.100.1.0 = STRING: "zrd                   run (pid 13371) 7 minutes, 1 start"
