K000150440: Unable to assign some license via automation from a FCP / CAT license pool

Type
Support Solution
Published
2025-03-18
Updated
2026-02-27
Source
https://my.f5.com/manage/s/article/K000150440

Description

When utilizing Declarative Onboarding or other API calls to assign licenses from BIG-IQ FCP/CAT, API struggles to differentiate between SKU names when the pattern given matches both. For example, if the SKU names are "F5-BIG-MSP-A-LTM-12" and "F5-BIG-MSP-A-LTM-12-R," the API chooses SKU name that appears first in the database, "F5-BIG-MSP-A-LTM-12-R," in such cases.

Environment

  • FCP / CAT license

  • BIG-IQ
  • Declarative Onboarding / API

Cause

When using Declarative Onboarding or other API calls to assign licenses from BIG-IQ FCP/CAT, the API relies on string matching to identify SKU names. You pass strings as values for "skuKeyword1" and "skuKeyword1".  When it creates the filter it uses the format "*skuKeyword1*skuKeyword2*". This was designed so if you needed a 1Gig LTM license you could set skuKeyword1 = LTM and skuKeyword2 = 1G and successfully be given a F5-BIG-MSP-A-LTM-1G License.

However, if one SKU name is a substring of another, such as "F5-BIG-MSP-A-LTM-12" and "F5-BIG-MSP-A-LTM-12-R," the filter matches both and the API chooses the first SKU in the database, as it does not have a mechanism to distinguish between SKUs that both match the filter. This results in the incorrect SKU being assigned in scenarios where both options are present.

Answer/Recommended Actions

At this time, there is no workaround or fix available for this behavior.
