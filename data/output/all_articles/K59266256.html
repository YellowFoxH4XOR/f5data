Description

We noticed that when implementing the cookie persistence profile as example below, we experienced a huge increase on tmm CPU usage. The CPU usage came back to normal values when it was removed from the virtual server.

ltm persistence cookie /Common/Persist_Cookie {
    cookie-name COOKIE_NAME
    defaults-from /Common/cookie
    method hash → Note
    timeout 7200
}

As soon as the profile is added, Idle enforcer logs start showing and tmm CPU increases:

/var/log/kern.log
info kernel: ltm driver: Idle enforcer starting - tid: 26085 cpu:
info kernel: ltm driver: Idle enforcer starting - tid: 26086 cpu:

The Virtual Server configuration is using Shared Addresses as destintion or source (address list):

ltm virtual /Common/Example_VS {
    ip-protocol tcp
    persist {
        /Common/Persist_Cookie {
            default yes
        }
    }
    pool /Common/Example_Pool
    traffic-matching-criteria /Common/Example_VS_VS_TMC_OBJ  → Note
}

Environment

  • High CPU tmm
  • Adding new persistence profile (cookie hash)

Cause

Bug ID 912293: Persistence might not work properly on virtual servers that utilize address lists.

Recommended Actions

Do not use this type of persistence (cookie-hash) together with Shared Addresses on the Virtual Server.
