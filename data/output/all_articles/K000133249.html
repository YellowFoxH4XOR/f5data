Description

You want to replace a system controller in a VELOS chassis.  The replacement system controller could be a Return Materials Authorization (RMA) replacement blade or a spare system controller that you have.

  • To replace an existing blade in a VELOS system that has only a single blade installed, refer to K19494503: Replacing a blade in a VELOS system that has only a single blade installed.
  • To replace an existing blade in a VELOS system that has multiple blades installed, refer to K08485448: Replacing a blade in a VELOS system that has multiple blades installed.

Environment

  • F5OS-C
  • Velos
  • RMA
  • System Controller

Cause

None

Recommended Actions

Note: If the replacement system controller has a different version (or unknown version) of F5OS-C, you will need to install the correct version of software on the system controller before it will cluster properly with the active controller.  This can be done by PXE booting the replacement system controller, which will automatically install the correct software, or by installing the F5OS software from a USB thumb drive.

Note: If the VELOS system is configured to use RFC1918 address space for the Internal Chassis Networking, attempting to PXE boot the replacement system controller will fail, and you will need to implement the workaround documented in Bug ID 1271417. Additionally, the replacement system controller will not cluster properly with the active system controller, and you will need to apply the workaround documented in K000138232: Replaced VELOS System Controller does not join cluster when Internal Chassis Networking configured to RFC1918.

Note: If performing a simultaneous replacement of both system controllers, you may need to trigger a reinstall of the Openshift cluster, as described in Bug ID 1682441.

Procedure

  1. (Optional) Set the VELOS system primary key to a known value and generate a configuration backup for the chassis as well as a configuration backup for each of the partitions, as described in K50135154: Back up and restore the F5OS-C configuration on a VELOS system.
  2. (Optional) Save the backup and salt/passphrase in safe location.
  3. Remove the old system controller and insert the replacement controller, following the instructions in the Replace a system controller section of the VELOS CX Series Platform Guide.
  4. Connect to the console of the replacement system controller.
  5. If the replacement system controller is already booted, then reboot it by running "reboot" or reset from the AOM menu (the "RC" option). Press Q to exit the AOM menu to be able to see the reboot process screen.
  6. While the replacement system controller is rebooting, when it displays A2 code in the bottom corner or "Press <c> to enter setup." 
     
  7. Select Continue to enter BIOS.
     
  8. Use the arrow keys to move to the Boot tab, followed by Boot Option #1 and press [Enter] to select.
  9. Select "PXE" entry when presented with the boot menu similar to the following, and press [Enter]
 
The replacement system controller should automatically install software to match the active system controller and reboot.  After the install completes and the controller boots into F5OS-C software, the active system controller will bring it into the cluster.
Note: If the VELOS system is configured to use RFC1918 address space for the Internal Chassis Networking, attempting to PXE boot the replacement system controller will fail, and you will need to implement the workaround documented in Bug ID 1271417. Additionally, the replacement system controller will not cluster properly with the active system controller, and you will need to apply the workaround documented in K000138232: Replaced VELOS System Controller does not join cluster when Internal Chassis Networking configured to RFC1918.
Note: This process may take about 1 hour. Do not reboot the active system controller during this process. While the new system controller is being brought into the cluster, you may be unable to log into the new controller as 'admin' or any user other than root.

You can monitor the progress of the installation from the active system controller:

show cluster | repeat
show components

For more details, log into the active system controller as root and watch the openshift log file:

tail -f /var/log/openshift.log

Once finished, confirm that both system controllers are running the same version, and that any enabled partitions are reported as "running-active" or "running-standby" on both controllers.

show system image
show partitions
