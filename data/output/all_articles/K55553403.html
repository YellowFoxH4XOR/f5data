Description

While accessing the website via BIG-IP, browser is creating and sending request to an incomplete URI. BIG-IP forwards the same request to pool member and pool member respond back with 404 error.

For example: browser is sending out request to https://example.com/example/image.pn instead of https://example.com/example/image.png. 

Browser was failing to send request to complete URI only when the traffic goes via BIG-IP.
If client access the pool member directly, browser does send request to complete URI and response was 200 OK.
Client to BIG-IP, connection was on 443/https and BIG-IP to pool member connection was on 80/http.

Environment

  • Browser
  • Incomplete URI
  • Stream profile
  • BIG-IP
  • Pool member
  • Virtual sever
  • 404 response

Cause

The stream profile used on the virtual server is causing HTTP responses from the pool member to be corrupted. This occurs because the stream profile is changing the length of the URI while rewriting (http:// -> https://), however, the URI is embedded within a special response structure that includes the length of the field. 

For Example:
Pool member sends a js file which includes the URI with header length of 36.
http://example.com/example/image.png    <------<<  Length of this URI is 36.

When it passes BIG-IP, stream profiles rewrite and send that js file to client.
https://example.com/example/image.png   <------<<  Length of this URI is 37.

Note: Stream profile rewrites the url from http to https, however, it does not update the uri length.  

Browser executes the JS file in the process of webpage rendering and it read only 36 letters as per the header length defined in JS file. This makes browser to send request to incomplete URI by missing the last letter "g".

Recommended Actions

You can follow either of the below mentioned workarounds. 

  1. Reconfigure the backend server to use 'https://' in all URIs

  2. Reconfigure the backend server to use 'http://'', but have a hostname that is one character longer (so that rewriting it to https://example.com' preserves the overall length of the field)

Additional Information

Stream profile performs a search and replace procedure for all occurrences of a string in a data stream.  You can use the Stream profile with any TCP traffic. You can apply the Stream profile to any Standard virtual server that is configured with the TCP protocol.
For more details refer, K39394712: Overview of the Stream profile

What is a JS file?

JS files are text documents that contain lines of JavaScript code. These JavaScript codes are referenced by Web pages when viewers implement an action on those Web pages that require the implementation of functionalities that have been programmed into the Web pages through the JavaScript codes found in the corresponding .js files in the Web server. These functionalities may include automatically closing or opening Web browser windows or tabs, mouseovers, form validation sequences and so on. These JavaScript codes can also be used to create dropdown boxes with interactive functionalities. Microsoft Notepad can be used to open and view the content of these .js files.
