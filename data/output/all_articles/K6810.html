Known Issue

This is the result of a known issue. In the event TMM is unable to communicate with the system or other services, the default behavior of the system is to initiate a Fail Over and Restart option for the TMM process.

This behavior does not currently function correctly resulting in a failover taking up to 1 minute to occur. The issue occurs when SOD (switch over daemon, or sod) is triggered by TMM to initiate a failover, but instead goes into a loop and does not initiate the action right away.

If sod does not initiate the failover when TMM initiates the Fail Over and Restart command and a core file is being written by TMM, the failover could be further delayed, causing sod to abort before failing over.

F5 Product Development tracked this issue as CR70892 and CR70961, and it was fixed in BIG-IP 9.2.4. For information about upgrading, refer to the LTM, GTM, ASM, or Link Controller Release Notes.
