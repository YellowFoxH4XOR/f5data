Description

Disabling TLSv1.1 in tomcat for compliance with security policy when required. This is because TLSv1.1 is now considered unsafe and the majority of websites are now using TLSv1.2 or even TLSv1.3. Because of this some BIG-IP administrators may need to disable support for TLSv1.1 in tomcat to be in compliance with their internal security policies.  

  • Some company security policies require the TLSv1.1 not be used anywhere in the BIG-IP. 
  • Having TLSv1.1 enabled in tomcat can cause PCI audit compliance issues.
  • TLS 1.0 and TLS 1.1 Are No Longer Secure

Environment

Running BIG-IP in customer environment where all TLSv1.1 ciphers are required to be disabled.

  • PCI Compliance to meet customer's security policy requirements.
  • Configuration utility disabled due to concerns with self-signed certificates.

Cause

Due to the insecurity in TLSv1.1 customers may need to remove this from not only the configuration utility, but also from tomcat.

Recommended Actions

-Steps related to disabling TLSv1.1 from tomcat:

1.) Use editor like vi to open the file /etc/bigstart/scripts/tomcat
vi /etc/bigstart/scripts/tomcat
2.) Locate the following string:
"-Dhttps.protocols=TLSv1.1,TLSv1.2"
2-a.) use the "/" key to search for the pattern in vi.
3.) Change the previously identified string to the following:
"-Dhttps.protocols=TLSv1.2"
3-a.) use the "i" key to make changes in vi.
3-b.) Press "Esc" key to return to management mode in vi.
4.) Exit the editor while saving the changes.
:wq!
5.) Restart the tomcat process using the following:
bigstart restart tomcat
