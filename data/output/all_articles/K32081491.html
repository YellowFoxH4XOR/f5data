Description

ASM blocked a request due to Attack Signatures triggered with Violation Context AMF body.

Environment

  • Violation Context is AMF body
  • Attack type is either XSS or SQL-Injection

Cause

Whenever ASM receives multipart form data it will try to parse it and extract all the parameter names and values.

When this parsing fails due to badly formatted data, ASM will put the entire content into a container called AMF body and then check if this content matches any of the signatures.

Recommended Actions

To avoid ASM blocking these requests, configure the affected URL with a header-based content profile and have request body handling set to 'Do Nothing' in order to simply inspect the request header details.

  1. Go to Security > Application Security > URLs > Allowed URLs.
  2. Select the affected URL.
  3. Select Header-Based Content Profiles.
  4. For Request Header Name, enter an explicit header name that must appear in requests for this URL.
  5. For Request Header Value, enter a simple pattern string for the header value that must appear in legal requests for this URL.
    For example, *multipart/form-data*.
  6. For Request Body Handling, select Do Nothing.
  7. Select Update
  8. Select Apply Policy

Additional Information

This feature was introduced in version 11.5 and the purpose is to prevent an attacker to bypass ASM protection with a badly crafted multipart payload.

Furthermore, starting from v15.1.0, confusing context name 'AMF Body' has been changed to 'HTTP Request Body Unparsed Payload' to more accurately describe the context. for more info, refer to Bug ID 786897: Rename of 'AMF Body' context to 'HTTP request body - unparsed payload' in request log

By setting Request Body Handling to Do Nothing, it also means that the request bypasses the Long Request Buffers.
