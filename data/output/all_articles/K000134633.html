K000134633: Newly created users can not be synced to standby when created on the active member

Type
Support Solution
Published
2023-06-12
Updated
2023-06-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0, 15.1.8, 16.1.3, 14.1.5
Source
https://my.f5.com/manage/s/article/K000134633

Description

You create some users in the active device but have problems syncing them to the standby device. When you remove them from the active peer and create them in the standby one and proceed with the sync you face the following error:

'01070101:3: Can't change the username for user example.user (user example.user has no UID)'

The reason why the configuration fails to load the first time is that there are many daemons that fail to stop, which occurs due to a discrepancy between the status reported by bigstart status and bigstart singlestatus, the latter of which is used by MCP. The delay in status reported introduces a race condition with MCP when two or more modules are provisioned (eg: LTM +ASM + AVR), and as a result, you see provisioning failure in /var/log/ltm.

MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'dwbld failed to stop.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'dwbld failed to stop.'
MMM DD HH:MM:SS hostname err mprov:6504:[6504]: 'dwbld failed to stop, provisioning may fail.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'fslogd failed to stop.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'fslogd failed to stop.'
MMM DD HH:MM:SS hostname err mprov:6504:[6504]: 'fslogd failed to stop, provisioning may fail.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'iprepd failed to stop.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'iprepd failed to stop.'
MMM DD HH:MM:SS hostname err mprov:6504:[6504]: 'iprepd failed to stop, provisioning may fail.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'logmysqld failed to stop.'
MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'logmysqld failed to stop.'
MMM DD HH:MM:SS hostname err mprov:6504:[6504]: 'logmysqld failed to stop, provisioning may fail.'

MMM DD HH:MM:SS hostname info mprov:6504:[6504]: 'pccd failed to stop.'


A reboot does not resolve the issue.


Environment

  • Creating users on active members that authenticate with LDAP.
  • Performing a ConfigSync


Cause

Bug ID1077533: BIG-IP fails to restart services after mprov runs during boot


Recommended Actions

Removing the lines of the affected users in /etc/shadow seems that solves the issue. You potentially need to perform this workaround every time you face this issue.

Important: Traffic processing is briefly interrupted while the BIG-IP system reboots. To avoid such scenarios, perform the activity in a maintenance window. It should be advisable to create a UCS backup prior to performing this procedure and a backup of /etc/shadow file.

1. Check if problematic users are defined in /etc/shadow. Modify manually and remove them if so:

vi /etc/shadow
grep -i "user1" /etc/shadow

2. Confirm that impacted users are not defined in /config/bigip_user.conf. Modify manually and remove problematic users if so:

vi /config/bigip_user.conf
grep -i "user1" /config/bigip_user.conf

3. Check the changes we have made:

cat /config/bigip_user.conf

4. Check if the home directory exists for the affected users.

5. Verify the configuration:

tmsh load sys config verify

6. Reboot the unit the first time:

reboot

7. If the system is not able to load properly after the first reboot and remained in the status INOPERATIVE:Disconnected.

[root@hostname:INOPERATIVE:Disconnected] #


Then reboot the system a second time:

reboot

8. After the second reboot, the system is able to load the configuration:

tmsh show /cm sync-status
