Known Issue

This is the result of a known issue. When performing a migration to a share farm, the ARX system may experience an internal IPC (Inter-Process Communication) timeout. When this issue occurs, the volume will go offline and the ARX system is unable to determine the target free space. As a result, the migration will fail with error messages that appear similar to the following example:

POLICY_PDP-3-ERR-POLICY_RULE_TARGET_STAGE_FSINFO:: Could not determine target free space
POLICY_PEP-3-INFO-RULE_SCAN_STATUS:: Rule [<sharename>]: Scan status is now [Could not determine target free space]
POLICY_PEP-3-INFO-SHARE_FREE_SPACE_QUERY_FAILED:: Free space query for share [<sharename>] failed. Connect failed [-13]
POLICY_PEP-3-INFO-VOLUME_FREE_SPACE_QUERY_FAILED:: Free space query for volume [<volumename>] failed. Connect failed [-13]

F5 Product Development tracked this issue as ID 38307 and it was fixed in ARX version 5.1.7. For information about upgrading, refer to the ARX release notes.

This issue has been fixed in ARX hotfix versions 5.1.0 HF4 (build 11933) and and 5.1.5 HF1 (build 11966). Customers affected by this issue can download these hotfixes or later versions of the hotfixes from the F5 Downloads site.

Workaround

Customers affected by this issue may perform a successful migration by disabling inline notification for the migration placement rule. However, in some instances it may be required to disable the migration placement rule completely. Customers can work around this issue by performing one of the following procedures:

Disabling inline notification for the migration placement rule

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode using the following command syntax:

    namespace <namespace>

    Replace <namespace> with the name of your namespace.

    For example:

    namespace ns1
  5. Enter volume configuration mode using the following command syntax:

    volume <volume>

    Replace <volume> with the name of your volume.

    For example:

    volume /vol1

    You are now in gbl-ns-vol mode.
  6. Enter placement rule configuration mode using the following command syntax:

    place-rule <place rule>

    Replace <place rule> with the name of your placement rule.

    For example:

    place-rule move2farm
  7. Disable inline notification for the placement rule by typing the following command:

    no inline notify
  8. Exit the placement rule configuration mode and return to privileged mode by typing the following command:

    end

Disabling the migration placement rule

If the ARX system continues to experience internal IPC timeouts and mark the volume offline, you must completely disable the migration placement rule by performing the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Enter global configuration mode by typing the following command:

    global
  4. Enter namespace configuration mode using the following command syntax:

    namespace <namespace>

    Replace <namespace> with the name of your namespace.

    For example:

    namespace ns1
  5. Enter volume configuration mode using the following command syntax:

    volume <volume>

    Replace <volume> with the name of your volume.

    For example:

    volume /vol1

    You are now in gbl-ns-vol mode.
  6. Enter placement rule configuration mode using the following command syntax:

    place-rule <place rule>

    Replace <place rule> with the name of your placement rule.

    For example:

    place-rule move2farm
  7. Disable inline notification for the placement rule by typing the following command:

    no enable
  8. Exit the placement rule configuration mode and return to privileged mode by typing the following command:

    end
