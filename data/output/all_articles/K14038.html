Known Issue

The TMM process may crash. This issue occurs when all of the following conditions are met:

  • An iRule contains either the event disable all or event <event name> disable iRule command.
  • The iRule also contains the RESOLV::lookup iRule command in the disabled iRule event.
  • The TMM process is processing traffic with this iRule that disables the event and executes the RESOLV::lookup command in the same flow.

    For example, the following iRule snippet illustrates an iRule that disables the HTTP_REQUEST event and then continues to execute the RESOLV::lookup command in the same flow:

    when HTTP_REQUEST {
           event HTTP_REQUEST disable
           set hostip [RESOLV::lookup @192.168.124.4 www.example.com]
    }

The RESOLV::lookup iRule command temporarily suspends the current connection in which it is executed to perform a DNS query to the indicated remote server. When the DNS query has completed, the system resumes iRules processing on the suspended connection. However, since the system has marked the event as disabled, the iRule is unable to further proceed. As a result, the TMM process crashes.

Impact

If configured as part of a high-availability system, the BIG-IP system may temporarily fail to process traffic, and failover.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H379805 on the Diagnostics > Identified > Medium screen.
  • The TMM process crashes with a SIGFPE fault and produces a stack trace in the /var/log/tmm file, which appears similar to the following:

    panic: ../modules/hudproxy/resolv/resolv.c:1240: Assertion "resolv_tclresult cleared" failed.

  • The BIG-IP system generates a TMM core file to the /shared/core directory
  • The BIG-IP system fails over to the peer system.

Workaround

To work around this issue, you can rewrite the affected iRule to avoid disabling the event that contains the RESOLV::lookup command and execute the command in the same flow. The following iRule snippet provides an example on how to do this. 

Impact of workaround: The following iRule may not apply to all environments. F5 recommends that you author an iRule that works best for your application environment, and that you test any such changes in an appropriate environment.

when HTTP_REQUEST {
       if { [HTTP::uri] starts_with "/example" }{
           event HTTP_REQUEST disable
       }
       else {
           set hostip [RESOLV::lookup @192.168.124.4 www.example.com]
       }
}
