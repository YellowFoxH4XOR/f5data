Description

When connecting the Office applications to a Sharepoint service, you may be using the "_sys_APM_MS_Office_OFBA_Support" iRule, to handle authentication from the applications.
In case the APM Access Policy is configured with SAML authentication, the process may enter a infinite loop.

Environment

  • APM Access Policy with SAML authentication;
  • iRule "_sys_APM_MS_Office_OFBA_Support" attached to the Virtual Server.

Cause
Such configuration is not currently supported.

Recommended Actions

We'll be updating the original code of the iRule:
  1. Navigate to Local Traffic >> iRule
  2. Click "_sys_APM_MS_Office_OFBA_Support"
  3. Copy the code to the clipboard;
  4. Navigate to Local Traffic >> iRule again, and click Create ...
  5. Give any name to the new iRule and paste the code from the clipboard;
  6. Locate the line "if { !($f_allow_session) && $http_path != $static::MS_OFBA_AUTH_REQ_URI && $http_path != "" } {" or the line "if { !($f_allow_session) && $http_path != $static::MS_OFBA_AUTH_REQ_URI } {" (depending the software version).
  7. Rewrite the line this way: "if { !($f_allow_session) && $http_path != $static::MS_OFBA_AUTH_REQ_URI && $http_path != "" && !( [HTTP::path] starts_with "/saml/sp/profile/post/acs" ) } {" or this way: "if { !($f_allow_session) && $http_path != $static::MS_OFBA_AUTH_REQ_URI && !( [HTTP::path] starts_with "/saml/sp/profile/post/acs" ) } {".
  8. Save the new iRule
  9. Navigate to Local Traffic >> Virtual Servers
  10. Click the name of the Virtual Server is use and click the tab "Resources" on the top of the page;
  11. Detach the iRule "_sys_APM_MS_Office_OFBA_Support" and attach the new iRule
  12. Click Update.
