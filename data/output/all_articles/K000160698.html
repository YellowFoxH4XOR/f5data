Description

When running the f5-system-scanner on a BIG-IP system, a mismatch is reported for the file /etc/avr/tmstat_tables.xml. The scanner output indicates a SHA512 hash mismatch. Example error message: MISMATCH etc/avr/tmstat_tables.xml sha512 expected: <expected_hash> sha512 actual: <actual_hash>

Environment

  • Product: BIG-IP (All Modules)
  • File: /etc/avr/tmstat_tables.xml
  • Scanner tool: f5-system-scanner
  • Device currently or previously sending statistics to BIG-IQ

Cause

Each flagged file must be reviewed to determine if the change is expected.

A common benign reason for /etc/avr/tmstat_tables.xml to be flagged as a mismatch can be if a BIG-IP device has ever sent statistics to a BIG-IQ device. The scanner tool compares the file to a default reference and flags any deviation, even if the change is expected and benign.

Validation that the Big-IP previously sent statistics to BIG-IQ is only by verifying the existence of the file /etc/avr/org_tmstat_tables.xml.  This file is automatically created on the Big-IP when the f5.bigiq-analytics iApp is created by the Big-IQ when statistics are enabled.  You can verify the Big-IP is currently sending statistics to a Big-IQ by using either of the following tmsh commands:

(Active)(/Common)(tmos)# list sys application service bigiq-analytics.app/bigiq-analytics template

sys application service bigiq-analytics.app/bigiq-analytics {
    template f5.bigiq-analytics
}

-OR-

(Active)(/Common)(tmos)# list analytics global-settings use-offbox
analytics global-settings {
    use-offbox enabled
} 

Answer/Recommended Actions

  • Each flagged file must be reviewed to determine if the change is expected.
  • The scanner highlights differences from the default configuration yet may not indicate a harmful or critical issue. 
  • A common difference in the /etc/avr/tmstat_tables.xml can occur if the BIG-IP device has ever sent statistics to a BIG-IQ device.
