Known Issue

TCP virtual server connections may fail intermittently.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is part of a high availability (HA) pair.
  • Your BIG-IP system is configured with a virtual server that uses a FastL4 profile.
  • You enable connection mirroring on the virtual server.
  • The virtual server actively processes traffic.

Impact

TCP connections processed by the virtual server may fail intermittently.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Established connections to the virtual server stop responding intermittently.
  • When viewing the network level TCP request, the virtual server does not reply to the client's ACK.
  • When viewing the network level TCP connections between the BIG-IP system and the destination resource, your BIG-IP system does not send the client-side SYN to the destination resource.

Workaround

To work around this issue, you can disable the tm.fastl4_ack_mirror database variable. To do so, perform the following procedure:

Impact of workaround: When the tm.fastl4_ack_mirror database key is disabled, the active BIG-IP system no longer waits for the peer to acknowledge a mirrored connection before completing the connection. As a result, the active system may have established connections that are not mirrored to the standby system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To disable the tm.fastl4_ack_mirror database variable, type the following command:

    modify /sys db tm.fastl4_ack_mirror value disable

  3. To exit tmsh, type the following command:

    quit
