Description

There is a migration script called chassisConfigUpgrade.pm that pulls the user configuration set (UCS) from an old blade and then copy and loads the configuration to a new blade. However the script can fail to run properly if the userID and password isn't set properly and it cannot be changed by executing the script again.

The issue is as below:

  • One of the steps of the script is to enter the user password in order to be able to access the slots.
  • The script will prompt the user to enter a username and password.
  • A mistake is made where the user enters the incorrect userid. As below.
############################################
#STEP 5: get userid and password to access other slots
############################################
userid default.
Password:
Password:
Password:
  • Then the userID and/or password that the script tries to use user named default which doesn't exist.
  • Re-running of the script no longer prompts for the userid and so it cannot be changed simply by executing the script again.
  • This means the upgrade script fails as it cannot access the other slots as the userID should be root.

Environment

  • BIG-IP
  • VIPRION
  • chassisConfigUpgrade.pm is run but the user presses enter several times which sets the incorrect userID and password.

Cause

UserID input is incorrect

Recommended Actions

Perform the below steps to resolve the issue:

  • The userid is cached in a file /var/tmp/upgradeScriptUsrId
  • Delete this file to allow the script to prompt for the userID again.
rm /var/tmp/upgradeScriptUsrId
  • Re-run the chassisConfigUpgrade.pm script and the user details can be entered again.
