K12552109: Insert OCSP host header (400 bad request)

Type
Support Solution
Published
2021-01-12
Updated
2024-06-25
Source
https://my.f5.com/manage/s/article/K12552109

Description

OCSP Responder setup on BIG-IP and gets 400 bad request from OCSP as host header is missing.

Environment

  • OCSP responder
  • LTM/APM

Cause

Host header is not sent by F5 LTM/APM

Recommended Actions

To workaround this issue, create a "dummy" virtual server:

The following procedure involves creating a virtual server, iRule and modifying the OCSP responder item of your access policy. Note that you may need to make changes to the iRule and OCSP responder item as appropriate for your environment.

  • Create a standard virtual server with an ip address that is currently not in use on device, listening on port 80.
    Note: The "dummy" virtual server MUST NOT share any existing subnet of the self IPs.

               For example : 1.1.1.1:80
               Ensure the default HTTP and TCP profiles are assigned to the virtual server.
               Ensure SNAT automap is enabled on the virtual server

  •     Create this iRule and apply it to the above virtual server. This will insert  Host Header while forwarding OCSP communication through the dummy virtual server

        ltm rule ocsp_insert_http_host {
           when HTTP_REQUEST {
             HTTP::header insert Host <OSCP_ip or FQDN>
           }
        }

  •      Create a new pool with a single pool member. The pool member should be the ip address of the actual OCSP responder listening on port  80. Apply this pool to the new virtual server created.
  •      Modify the OCSP Responder used in the Access Policy to point to the newly created dummy virtual server.

                This can be done by changing the URI in the OCSP Responder config to:
                http://<virtual server ip address>
                
                Using the example dummy virtual server, the OCSP Responder URI would be:
                http://1.1.1.1

                Review the OCSP Responder configuration and make any other changes as appropriate for your environment.
