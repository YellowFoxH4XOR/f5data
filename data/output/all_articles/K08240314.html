Known Issue

Using iControl to import certificates may fail with a key mismatch error.

This issue occurs when all of the following conditions are met:

  • You use an iControl Simple Object Access Protocol (SOAP) API call to import a certificate to your BIG-IP system.
  • An existing Secure Sockets Layer (SSL)/Transport Layer Security (TLS) key resides in the /config/ssl/ssl.key directory that matches the name of the certificate that you are importing.

Beginning in BIG-IP 11.0.0, your BIG-IP system stores user-imported certificates and keys in the system's /config/filestore directory, and stores only system supplied certificates and keys in the /config/ssl directory. F5 recommends that you do not use the /config/ssl directory to store certificates and keys.

Impact

Users cannot import certificates and keys using the iControl SOAP API.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Certificates fail to import when you use the iControl SOAP API.
  • The system logs error messages to the /var/log/daemon.log file that appear similar to the following example:

    err iControlPortal.cgi[1234]: Cannot test public key - invalid key type
    err iControlPortal.cgi[1234]: f5km_exchange: f5km_import() returns -14 -- Keys do not match

Workaround

To work around this issue, if the conflicting certificate and key are no longer needed, remove the files from within the subdirectories under the /config/ssl directory. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP command line.
  2. Change directories to /config/ssl/ssl.key by typing the following command:

    cd /config/ssl/ssl.key

  3. Locate the conflicting key by typing the following command:

    ls

  4. Remove the key by using the following command syntax:

    rm <key name>.key

    For example:

    rm exampleKey.key

  5. Change directories to /config/ssl/ssl.crt by typing the following command:

    cd /config/ssl/ssl.crt/

  6. Locate the conflicting certificate by typing the following command:

    ls

  7. Remove the certificate by using the following command syntax:

    rm <cert name>.crt

    For example:

    rm exampleCert.crt
