Topic

You should consider using this procedure under the following condition:

  • You want to change an existing access policy to provide authentication control to a virtual server without invoking an application proxy.

Description

There are situations where you want to provide authentication and single sign-on capabilities to a virtual server that does not need a reverse proxy for access (web application access). This is known as LTM+APM mode, as it is a combination of a BIG-IP LTM virtual server that is using the BIG-IP APM system as an authentication mechanism for access.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have a BIG-IP APM system configured with a web application access policy.

Procedures

Adding a pool

LTM+APM mode requires that you define, in a server pool, the servers being accessed. This procedure defines a pool for use with the BIG-IP LTM virtual server.

Note: This example has the following defaults defined: no health monitor, Round Robin load balancing, and no priority group. You may define health monitoring and alternative load balancing methods suited to your environment.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click Create.
  5. In the Name box, type a name for the server pool.

    For example:

    webapp

  6. Click the Address box.
  7. Enter the IP Address of the server to add to the pool.
  8. Click the Service Port box.
  9. Enter the port number for the service you are accessing.

    For example, to access HTTPS service, you would type the following:

    443

  10. Click Add.
  11. Repeat steps 6 through 10 for each additional server you want to add.
  12. Click Finished.

Modifying the virtual server

This procedure removes the rewrite and connectivity profiles and adds the pool previously created, to allow traffic to directly access the server pool.

Impact of procedure: This procedure resets all connections that are currently active on the virtual server.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Click the name of the virtual server to modify.
  5. Scroll to the Access Policy section.
  6. From the Connectivity Profile menu, select None.
  7. From the Rewrite Profile menu, select None.
  8. If checked, clear the Citrix and Java Support option.
  9. If checked, clear the OAM Support option.
  10. Click Update.
  11. Click Resources.
  12. From the Default Pool menu, select the pool you previously created.
  13. Click Update.

Modifying the access policy

This procedure removes the resource assignment action from the access policy.

Impact of procedure: This procedure resets all connections that are currently active on the virtual server.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. Click Edit next to the name of the access policy to edit.
  5. Click the x in the upper right corner of the resource assign action.
  6. Click Delete.
  7. Click Apply Access Policy.
  8. Click Close.
