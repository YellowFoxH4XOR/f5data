Known Issue

This is the result of a known issue. The BIG-IP ASM system schedules the purge_mysql_logs.pl script to run hourly, clearing unnecessary MySQL logs, and verifying that the signature file is up to date. When a BIG-IP LTM system has the BIG-IP ASM module installed, but a BIG-IP ASM license has not been activated on the system, the script is unable to communicate with the unlicensed BIG-IP ASM module. As a result, the following error messages are logged in the /var/log/asm file every hour:

purge_mysql_logs.pl -> /ts/tools/purge_mysql_logs.pl errors: Can't connect to database 'DBI:mysql:host=localhost': Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock' (2)
asm_update_sigfile -> /ts/tools/asm_update_sigfile errors iControlPortal.cgi[1686]: 01310027:2: ASM subsystem error (-e,Logger::error): ASM is not licensed/enabled.

Note: The error messages are informational only. If your system has been configured to generate SNMP traps, this log message also generates a trap. Both log messages and traps may be ignored until the ASM license has been activated.

F5 Product Development tracked this issue as ID 215861 (formerly CR104495) and it was fixed in BIG-IP 9.4.8 and BIG-IP 10.0.0. For information about upgrading, refer to the BIG-IP LTM or ASM release notes.

Workaround

F5 recommends you upgrade to BIG-IP 9.4.8 or later, or suppress these messages through your syslog server and SNMP trap server. However, you can work around this issue by deleting the symbolic links to the scripts that produce these error messages on the BIG-IP ASM.

Important: This workaround will result in a device that will be impaired and the BIG-IP ASM component will not function correctly without further user intervention if the BIG-IP ASM is subsequently enabled on the device. In order to use the BIG-IP ASM on a device that has undergone this workaround, you will need to re-create the symbolic links, or re-install the software.

To delete the links, perform the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. Delete the appropriate links by typing the following two commands:

    rm -rf /etc/cron.hourly/purge_mysql_logs.pl

    rm -rf /etc/cron.daily/asm_update_sigfile

  3. Restart the cron daemon by typing the following command:

    bigstart restart crond

To reverse the steps in the above workaround and restore the links on a device that needs to run BIG-IP ASM, perform the following procedure:

  1. Log in to the BIG-IP ASM command line.
  2. Create the symbolic links by typing the following two commands:

    ln -s /ts/tools/asm_update_sigfile /etc/cron.daily/asm_update_sigfile

    ln -s /ts/tools/purge_mysql_logs.pl /etc/cron.hourly/purge_mysql_logs.pl

  3. Restart the cron daemon by typing the following command:

    bigstart restart crond
