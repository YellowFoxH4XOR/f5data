K000136118: Invalid format of SNMPv3 engineID respond with error "security service 3 error parsing ScopedPDU"

Type
Support Solution
Published
2023-09-28
Updated
2023-09-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.0.0, 15.0.X, 15.0.1, 15.X.X, 15.1.X, 15.1.10, 15.1.9, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.0
Source
https://my.f5.com/manage/s/article/K000136118

Description

  • Customize engineID Data not conforming to RFC3411 makes the snmpd system reject the request with the error "security service 3 error parsing ScopedPDU" 
  • You customized the engineID in the "snmp include" configuration in the big-ip
  • The engineID should be in a string of hex format "engineID <STRING>"


Environment

  • LTM
  • SNMPv3
  • Customize engineID


Cause

Customize engineID data not conforming to RFC3411 makes the snmpd system reject the request with the error "security service 3 error parsing ScopedPDU" 


Recommended Actions

  • Change the engineID data conforming to RFC341
  • Viewing the current engineID configuration
    • tmsh list sys snmp include
Example
sys snmp {
    include "engineID 0x6d79656e67696e654944"
}
  • Modify the engineID
    • tmsh modify sys snmp include "engineID <string>"
Example
tmsh modify sys snmp include "engineID 6d79656e67696e654944"
tmsh list sys snmp include
sys snmp {
    include "engineID 6d79656e67696e654944"
}
  • Save the configuration
    • tmsh save sys config
