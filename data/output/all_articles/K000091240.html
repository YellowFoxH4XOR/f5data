K000091240: HTTP headers with underscores are not processed by Nginx Ingress Controller

Type
Support Solution
Published
2022-08-30
Updated
2022-08-30
Source
https://my.f5.com/manage/s/article/K000091240

Description

By default, Nginx doesn't consider HTTP headers with underscores(_) to be valid headers. If your application uses HTTP requests that contain underscores in the headers, you need to enable the Nginx directive "underscores_in_headers" through the use of snippets.

 

Environment

  • Nginx Ingress Controller
  • Kubernetes/containers

Cause

When the use of underscores is disabled, request header fields whose names contain underscores are marked as invalid and become subject to the "ignore_invalid_headers" directive.

 

 Recommended Actions

In order to allow this traffic, you will need to enable the nginx directive "underscores_in_headers" through the use of snippets.

  • This can be done at the global level through the Ingress Controller ConfigMap:
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: nginx-ingress
data:
  http-snippets: |
    underscores_in_headers on;

 

 

  • Or this can also be done at the server level by applying with "server-snippets" to an individual Virtual Server deployment:
apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
  name: cafe
  namespace: cafe
spec:
  server-snippets: |
    underscores_in_headers on;  
  host: cafe.example.com
  .... # the rest of the config is omitted for brevity

 

 

Additional Information
