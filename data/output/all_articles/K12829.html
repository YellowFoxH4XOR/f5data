Known Issue

The BIG-IP system may send TCP half open or UDP monitor traffic to nodes and pool members using the incorrect source IP address. This issue occurs when TMM routes are required to route the monitor traffic to the destination devices, and the routes are not loaded into memory when the monitoring daemon (bigd) initializes the monitor traffic. When the system subsequently loads the required routes, the bigd process does not re-establish the monitor traffic using the self IP address of the appropriate VLAN.

This may occur under the following conditions:

  • The BIG-IP system is configured to use dynamic routing

    This issue may occur when the BIG-IP configuration contains TCP half open or UDP monitors that rely on dynamic routes to send the monitor traffic. During system startup, the bigd process queries the kernel for a suitable IP address to use for sending monitor requests to pool members and nodes. Since the system has not yet learned the dynamic routes, the kernel returns the best available IP address to the bigd process (such as the mgmt IP address), which the bigd process temporarily uses to send the monitor traffic. When the system subsequently learns the dynamic routes, the bigd process fails to tear down the existing monitor and re-establish the monitor traffic using the correct IP address.

  • Static TMM routes are missing or were changed

    This issue may occur when the BIG-IP configuration contains TCP half open or UDP monitors that rely on static TMM routes to send the monitor traffic, and the routes are missing or were changed by an administrator. If the static routes are missing when the bigd process initializes the monitor traffic, the system uses the best available IP address to send the monitor traffic (such as the mgmt IP address). If the static routes are subsequently reconfigured, the bigd process fails to tear down the existing monitor socket and re-establish the monitor traffic using the correct IP address.

Impact

The BIG-IP system may incorrectly mark down pool members or nodes, potentially resulting in an interruption of traffic.

Symptoms

As a result of this issue, the BIG-IP system may experience the following symptoms:

  • The BIG-IP system incorrectly marks down pool members and/or nodes
  • Packet captures indicate that the BIG-IP system sends TCP half open monitor requests using an incorrect IP address such as the mgmt address instead of the self IP address of the VLAN

Workaround

To work around this issue, you can remove the TCP half open monitor from the pool or node and then add the monitor back. To do so, perform the following procedure:

Note: This workaround may need to be performed following each system reboot.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools or Nodes.
  3. Click the appropriate pool or node object.
  4. Remove the TCP half open monitor.
  5. Click Update.
  6. Re-add the monitor to the pool or node object.
  7. Click Update.
