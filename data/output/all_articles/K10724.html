Known Issue

This is the result of a known issue. Using the Ctrl+C keyboard combination or the kill command to terminate the qkview script may leave orphaned processes. This issue occurs if qkview stops responding and the user presses Ctrl+C or uses the kill command to terminate the process.

For example, if you run the qkview utility on a system with a large configuration, such as a large wideip.conf file, qkview may stop responding when executing a tmsh command. If you then press Ctrl+C to terminate the qkview process, the tmsh commands that were being executed by qkview remain in the process table as orphaned processes.

Note: The orphaned processes can be viewed using the top command.

Workaround

If you used Ctrl+C to terminate qkview, you can terminate any orphaned tmsh processes. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Use the ps command to display the PID numbers for any orphaned tmsh processes running on the system.

    For example:

    ps ax | grep -i tmsh | grep -v grep

    Output will appear similar to the following example:

    18137 pts/0 S 0:00 sh -c tmsh show gtm wideip detail 2>>/tmp/qkview_cmd.err
    18138 pts/0 S 0:00 tmsh show gtm wideip detail

  3. Use the kill command to terminate the qkview and tmsh processes.

    For example:

    kill -9 <tmsh_PID> <tmsh_PID>

Note: For more information about the qkview utility not responding when run from the command line, refer to K10723: The qkview utility may hang when run from the command line.
