K12587: Directories created on the target share may be missing the permissions, owner, and group information after migration

Topic

When using a place rule to migrate files for an NFS managed volume, if the source share has the unix-perm feature enabled, the target share should also have the unix-perm feature enabled.

If the unix-perm feature is enabled on the source share, but not on the target share, the permissions, owner, and group information will be missing for migrated directories on the target share. As a result, users will not be able to access the migrated directories. In addition, question mark ( ? ) characters will be displayed in place of the permissions, owner, and group information, similar to the following example:

-rw-r--r-- 1 owner group 0 Jan 1 12:00 123
?--------- ? ? ? ? ? file1.txt
?--------- ? ? ? ? ? file2.txt

Note: These question marks may also display due to other conditions. For example, the question marks may be an indication of a metadata skew resulting from a file/directory that has been lost (deleted) on the back-end filer directly, or the field handle has changed. In order to determine if a metadata skew has occurred, an inconsistency report should be performed on the path whose directory entries are showing the question marks. These inconsistencies should be resolved prior to restoring the missing permissions, owner, and group information after a migration.

To recover from this condition, you must restore the missing permissions, owner, and group information by setting the appropriate values through the VIP, not on the back-end filer directly. Setting the values through the VIP will cause the ARX system to set the values on all of the back-end shares that have a copy of the directory.

Note: Restoring the missing permissions, owner, and group information will most likely need to be scripted.

If the place rule was promoting directories, you must read the permissions, owner, and group information directly from the source back-end share. If the place rule was not promoting directories, you can read the correct permissions, owner, and group information for the affected directories using the VIP.
