Description

The speed of SQL query traffic processing is significantly slower than it should be. You can compare the speed by catching packet capture through BIG-IP, and the other directly between the client and the backend server.

 

Environment

  • BIG-IP LTM
  • Virtual Server with TCP Profile
  • MySQL traffic

Cause

When BIG-IP is using TSO (TCP segmentation offload) and LRO (large receive offload) where the segments are much larger than MSS, this may be a reason why the speed of transferring data is slower than expected. These two functions work a bit like TCP Nagle but at a NIC level (they merge ingress segments and egress segments to avoid sending many small segments).

 

Recommended Actions

To solve this problem, consider using this type of setting on a virtual server:

  1. Disable TSO on the BIG-IP using the following command:
    tmsh modify sys db tm.tcpsegmentationoffload value disable
  2. Disable LRO on the BIG-IP usign the following command:
    tmsh modify sys db tm.tcplargereceiveoffload value disable
  3. Use FastL4 on the BIG-IP virtual-server instead of TCP profile.
