Known Issue

The eventd process may produce a core file while processing event notifications when the blade's cluster state changes.

This issue occurs when all of the following conditions are met:

  • You are using two or more blades on a VIPRION system.
  • The cluster state of a Primary blade changes to Secondary.
  • The eventd process still has pending event notifications waiting to be processed while the system is shutting it down.

Impact

A segmentation fault occurs and causes the eventd process to produce a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice that the cluster state of the Primary blade changes to Secondary. For example, the system logs a message to the /var/log/ltm file that appears similar to the following:

    notice clusterd[25678]: 013a0024:5: Blade 2: Changing primary from 1 to 2

  • The eventd process generates a core file, and the system logs an error message to the /var/log/ltm file that appears similar to the following example:

    notice logger: Started writing core file: /var/core/eventd.bld4.0.420.core.gz for PID <PID>
