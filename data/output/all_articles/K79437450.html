K79437450: Commented closing braces are not taking into account in iRules

Description

If you comment a closing brace, the F5 does not throw any error about a missing brace.

For example,

If the iRule has commented closing braces "}", when saving the iRule, even though the count of none commented closing braces is less than the open braces, the F5 still accepts the iRule without throwing any error.

Environment

  • iRules
  • TCL

Cause

A property of Tcl comments is that curly braces inside comments are still counted for the purposes of finding matching brackets. The motivation for this odd feature was to keep the original Tcl parser simpler.

Recommended Actions

Use the recommended syntax to comment code on TCL. You can find some examples in the below links: 
- http://www.pearsonhighered.com/assets/samplechapter/0/1/3/0/0130385603.pdf
- https://wiki.tcl-lang.org/page/Why+can+I+not+place+unmatched+braces+in+Tcl+comments

Additional Information

If we use the following iRule as an example and we do not add the closing brack, the GUI sends the following message

01070151:3: Rule [/Common/test] error: /Common/test:1: error: [parse error: missing close-brace][{

when HTTP_REQUEST {

  set test [HTTP::host]

The above error is correct because we are missing the closing bracket, but if we add the closing bracket with a hash (aka comment)

when HTTP_REQUEST {

  set test [HTTP::host]
#}

The GUI does not send any error
