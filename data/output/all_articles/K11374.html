Known Issue

Important: The issue documented in this solution occurs when installing a BIG-IP ASM or BIG-IP WebAccelerator version 10.0.x hotfix or product image. The behavior occurs regardless of whether you are installing the hotfix from a 10.0.x or 9.4.x slot.

This is the result of a known issue. When installing a BIG-IP ASM or BIG-IP WebAccelerator product image or hotfix from the command line using the image2disk command, the system may save a unified computing system (UCS) archive that does not contain a configuration database. When this occurs, the system reports an error message to the console that appears similar to the following example:

info: mysqldump: Got error: 2002: Can't connect to local MySQL server through socket '/var/lib/mysql/mysql.sock' (2) when trying to connect
info: Failed to save: close pipe 'mysqldump': (512) at /usr/local/wa/scripts/wa_configsync.pl line 440.
info: Error executing 'pre-save' configsync script /tmp/cs_save_pre_script.

The error message appears after using the --nomoveconfig option in the image2disk command. For example, the following syntax is used in many installation-related procedures:

image2disk --hotfix --nomoveconfig --instslot=<version_10.x_slot> <HF.iso>

When you specify the --nomoveconfig option, the system is unable to access the configuration database, and the configuration database is not saved in the UCS file. As a result, all configured policies are lost.

F5 Product Development tracked this issue as ID 207422 (formerly CR120190) and it was fixed in BIG-IP ASM and BIG-IP WebAccelerator 10.1.0. For information about upgrading, refer to the BIG-IP ASM or WebAccelerator release notes.

Workaround

To work around this issue and prevent the loss of the database configuration during the hotfix installation, perform the following procedure:

  1. Boot into the install slot to which you will be applying the hotfix.
  2. To save a complete UCS backup, run the following command, where <UCS name> is the name you want to specify for the UCS file:

    bigpipe config save <UCS name>

    Note: Specifying a name for the UCS file is optional. If you do not want to specify a name for the UCS file, the system will default to config.ucs.

  3. Save the UCS file created in Step 2 to a safe, remote location.
  4. Reboot the system into the slot you will be using to install the hotfix.

    For example, boot to a 9.4.8 location to install the hotfix for your 10.0.x location:

    switchboot -b <9.x location>

    Reboot the system using the reboot command.
  5. Install the hotfix image to the target install slot using the following command syntax:

    image2disk --hotfix --nosaveconfig --instslot=<version_10.x_slot> <HF.iso>

    For example, if you are installing version 10.0.0 HF1 to the HD1.1 partition, you would type the following command:

    image2disk --hotfix --nosaveconfig --instslot=HD1.1 Hotfix-BIGIP-10.0.0-5460.0-HF1.iso

    The--nosaveconfig option notifies the installer to not create and save a UCS backup to install after the hotfix has been applied.
  6. After the hotfix installation has completed, set the default boot image to the 10.x installation location using the following command syntax:

    switchboot -b <10.x_location>

  7. Reboot the system to the version 10.x installation by typing the following command:

    full_box_reboot

  8. Once the system has rebooted into the 10.x installation, copy the UCS file created in Step 2 to the /var/tmp directory.
  9. Install the UCS file using the following command syntax:

    bigpipe config install <path to file> <name of ucs file>

    For example:

    bigpipe config install /var/tmp/myucs

  10. Log in to the Configuration utility and verify that all of your configured policies and settings are in place.
