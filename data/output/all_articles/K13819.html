Topic

You should consider using this procedure under the following condition:

  • You want to disable hardwired serial failover without physically removing the cable from the BIG-IP system.

Description

Customers in remote data centers may want to disable hardwired failover for diagnostic purposes. You can do this by disabling the failover.usetty01 database key and restart the sod process. To re-enable hardwired failover, you can enable the failover.usetty01 database key and restart the sod process. Restarting the sod process allows it to pick up the change in the hardwired failover configuration.

Note: You can use hardwired failover only when the device group contains a maximum of two devices. For a group with more than two devices, network failover is required. Also, if the hardware platform is a VIPRION platform, you must use network failover.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Have access to the TMOS Shell (tmsh) or the BIG-IP command line.

Procedures

Disable hardwired failover

You can disable hardwired failover and restart the sod process using tmsh.

Impact of procedure: Restarting the sod process brings down the links and the device goes offline, briefly interrupting traffic. With network failover configured, restarting the sod process causes a failover and results in a brief traffic interruption. If you do not have network failover configured, both systems may go into an active-active state. Additionally, while the sod process restarts, due to a change in behavior introduced in BIG-IP 11.5.3 HF2, 11.6.0 HF6, and 12.0.0, the bigd process will restart during the brief period the device is offline. For more information about the new bigd behavior, refer to K17252: The bigd process no longer sends monitor traffic to pool members when the BIG-IP is offline or a VIPRION blade is disabled.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the failover.usetty01 database key to disable, enter the following command:

    modify sys db failover.usetty01 value disable

    Note: By default, the failover.usetty01 database setting synchronizes between units in a high-availability pair during a configuration synchronization (ConfigSync) operation.

  3. Save the change by entering the following command:

    save /sys config

  4. To restart the sod process, enter the following command:

    restart sys service sod

Enable hardwired failover

You can enable hardwired failover and restart the sod process using tmsh.

Impact of procedure: Restarting the sod process brings down the links and the device goes offline, briefly interrupting traffic. With network failover configured, restarting the sod process causes a failover and results in a brief traffic interruption. If you do not have network failover configured, both systems may go into an active-active state. Additionally, while the sod process restarts, due to a change in behavior introduced in BIG-IP 11.5.3 HF2, 11.6.0 HF6, and 12.0.0, the bigd process will restart during the brief period the device is offline. For more information about the new bigd behavior, refer to K17252: The bigd process no longer sends monitor traffic to pool members when the BIG-IP is offline or a VIPRION blade is disabled.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the failover.usetty01 database key to enable, enter the following command:

    modify sys db failover.usetty01 value enable

    Note: By default, the failover.usetty01 database setting synchronizes between units in a high-availability pair during a ConfigSync operation.

  3. Save the change by entering the following command:

    save /sys config

  4. To restart the sod process, enter  the following command:

    restart sys service sod
