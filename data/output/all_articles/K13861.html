Known Issue

Certain UDP-based iRules commands may cause TMM to crash when receiving a NULL value.

This issue occurs when the following conditions are met:

  • An iRule references a UDP-based command. The following commands are known to be affected:
    • UDP::payload
    • RADIUS::avp
  • The UPD command is paired with one or more of the following iRules events:
    • CLIENT_CLOSED
    • SERVER_CLOSED
    • LB_FAILED
    • SIP_REQUEST
  • A packet triggers the iRules event and the corresponding UDP iRules command receives a NULL value.

Impact

TMM may crash and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H396797 on the Diagnostics > Identified > Medium|High screen.
  • TMM crashes and temporarily fails to process traffic.
  • The BIG-IP system sends a SIGSEGV signal to TMM, resulting in a stack trace and core file.
  • The BIG-IP system logs an error message to the /var/log/ltm that appears similar to the following example:

    notice sod[2046]: 01140045:5: HA reports tmm NOT ready.

Resolution

Status

F5 Product Development has assigned ID 388057 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Note: This issue does not affect BIG-IP 11.2.0 and later.

Workaround

You may be able to work around this issue by replacing the CLIENT_CLOSED / SERVER_CLOSED iRules events with events that are triggered only when data is received from the target node. For example, the CLIENT_DATA and SERVER_DATA iRules events are triggered when data is received from the target node.

For information about configuring iRules, refer to DevCentral or F5 Cloud Docs.
