Topic

Management provisioning allocates additional memory for the BIG-IP Linux host system. There are three default settings: Small (default), Medium, and Large.

When you use the Configuration utility to configure the Provisioning setting for Management (MGMT), the system allocates additional memory to the control plane using the following default values. These values are in addition to the base memory allocation for Management (MGMT):

  • Small memory allocation is 0 MB.
  • Medium memory allocation is 200 MB.
  • Large memory allocation is 500 MB.

You can also use the TMOS Shell (tmsh) to modify the system database variable provision.extramb to use a custom allocation of additional memory for Management (MGMT). For example, you can configure an additional memory value other than Small, Medium, or Large. Any additional memory configured for Management (MGMT) (control plane) is deducted from TMM (data plane).

Description

  • View the provisioned memory value using the Configuration utility
  • Modify the provisioned memory value using tmsh

View the provisioned memory value using the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Resource Provisioning.
  3. Note the value for Management (MGMT).

    Note: Under Current Resource Allocation, hover on Management (MGMT) to display the actual memory allocation in MB.

Modify the provisioned memory value using tmsh

Important: The BIG-IP system experiences a temporary traffic interruption as it recovers from the TMM restart, and devices configured as a high-availability (HA) pair may fail over. F5 recommends changing the Management memory size allocation during a scheduled maintenance window.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view the current configured extra system memory, enter the following command:

    list sys db provision.extramb all-properties

    Output appears similar to the following:

    sys db provision.extramb {
        default-value "0"
        scf-config "true"
        value "0"
        value-range "integer min:0 max:8192"
    }

    Note: The previous example outputs the value of 0, meaning that the current provisioning is set to small in the Configuration utility (the default setting) and that no additional memory is allocated to the Management system.

  3. To modify the provisioned memory value, use the following command syntax:
    Note: <numeric value> is the number of MB to additionally allocate to the host Management system.
    Note: Before applying the command consult     K92565345: Modifying DB key provision.extramb causes TMM to restart and failover.

    modify /sys db provision.extramb value <numeric value>

  4. (Optional) Log out of the TMOS shell by entering q then verify the configuration change by entering the following command on the Advanced Shell (bash):

    grep -B 8 display_name=Provision.extraMB BigDB.dat

    Note: You do not need to save the sys db change since its automatically saved to the BigDB.dat file. For more information, refer to K16953: BIG-IP system database variables are automatically saved when modified.

Recommendations

  • Before you modify BIG-IP system provisioning or add more memory to an existing Management setting, review the available system memory.
  • For large configurations containing more than 2000 configured objects, for Management (MGMT), in the Provisioning column, select Large.
  • For units with at least two provisioned modules (LTM+ASM+other, LTM+APM+other, and LTM+AVR+other), running on BIG-IP 14.1 or later and medium-large configurations (500+ configuration objects), select Large.
  • For units running on BIG IP 15.x or later, select Large.
  • For units provisioned with three or more software modules and running on BIG IP 15.x or later, set <numeric value>to 2048 (or even 4096 if enough resources are available), using command as previously described in step 3 of the "Modify the provisioned memory value using tmsh".

Modify the provisioned memory value using tmsh procedure.

  • For multiblade vCMP guests running BIG-IP ASM in addition to any other software module and BIG-IP 16.X or later, set <numeric value>to 2048 (or even 4096 if enough resources are available and depending on total blades number), using command as previously described in step 3 of the " Modify the provisioned memory value using tmsh"  procedure. This permits additional blades to load and start correctly.
  • If Management provisioning is increased to 1024, consider increasing tomcat's resources to 128; if increasing to 2048, increase tomcat's to 256.

Important: F5 strongly recommends that you conduct a thorough analysis of system resource before provisioning additional software modules, before upgrading to BIG-IP 14.1.x or BIG-IP 15.1.x or later, or both. If upgrading, you need to increase Management provisioning according to the available resources. If upgrading to BIG-IP 15.1.x or later, you may also need to increase the number of CPU cores to the device.
