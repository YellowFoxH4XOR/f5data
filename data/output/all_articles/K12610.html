Known Issue

This is the result of a known issue. In BIG-IP ASM 10.1.0 and later, the DoS Attacks reporting component may incorrectly display the values for Legitimate TPS and Detected TPS as 0 (zero), even if the system is otherwise reporting that it is mitigating a denial-of-service (DoS) attack. The BIG-IP ASM DoS Attack Prevention engine calculates these values as floating point numbers, however, the BIG-IP ASM reporting tool must round the fractional values down so they may be displayed as integers in the Configuration utility. If a DoS attack is detected at a rate of less than one transactions per second (TPS), the reporting component will display the Legitimate TPS and Detected TPS values as zeros due to rounding. This issue is cosmetic only, and the DoS Attack Prevention feature will work as expected when properly configured.

F5 Product Development tracked this issue as ID 348861 and it was fixed in BIG-IP ASM 11.0.0. For information about upgrading, refer to the BIG-IP ASM release notes.

Note: For more information about configuring the DoS Attack Prevention feature, refer to the Configuring Anomaly Detection section of the Configuration Guide for BIG-IP Application Security Manager.
