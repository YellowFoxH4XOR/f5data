Known Issue

This is the result of a known issue. If the system time is changed, the BIG-IP system may prematurely remove a persistence record. The BIG-IP system calculates persistence record timers using a reference from the system time (seconds since epoch). Therefore, if the system time is changed, the reference used to calculate persistence record timers will also change. As a result, existing persistence records will age prematurely or the BIG-IP system will remove them.

Note: When the system time is changed, leap second adjustments may also cause the BIG-IP system to remove a persistence record prematurely.

F5 Product Development tracked this issue as ID 222888, ID 328273, and ID 222888 (formerly CR125572) and it was fixed in BIG-IP version 10.2.3. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.2.2-852.0-HF1, issued for BIG-IP version 10.2.2, Hotfix-BIGIP-10.1.0-3402.0-HF2, issued for BIG-IP version 10.1.0, and Hotfix-BIGIP-9.4.8-429.0-HF5, issued for BIG-IP version 9.4.8. You may download these hotfixes or later versions of the hotfixes from the F5 Downloads site.
