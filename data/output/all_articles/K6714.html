Topic

The BIG-IP ASM web application allows you to view past requests that have passed through the BIG-IP ASM system.

Viewing the BIG-IP ASM web application Forensics / Reporting page

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Click the desired web application you want to view.
  5. Click Reporting from the menu.

    Note: In BIG-IP ASM versions prior to 9.4.2, click Forensics to view past requests.
Configuring the logging level for the BIG-IP ASM web application

In BIG-IP ASM 9.4.2 and later, you can configure logging profiles on the BIG-IP ASM system.

Note: For information about configuring logging profiles, refer to the Configuration Guide for BIG-IP Application Security Management.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

In BIG-IP ASM versions prior to 9.4.2, the following logging levels can be configured on the Forensics page:

  • All Request: Specifies the system logs all requests.
  • Illegal Requests Only: Specifies the system logs only those requests that violate the active security policy.

You can configure the logging level for the BIG-IP ASM web application by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click Web Applications.
  4. Click the desired web application you want to configure.
  5. Select the desired log level from the Set Request Logging drop-down menu.
  6. Click Update.

Adjusting the number of Forensics page request records stored in internal database tables

The Forensics page request data is stored in internal database tables. To prevent these tables from becoming too large, a clean script will clean the tables every 15 minutes. If a table has exceeded 20,000 request records, the clean script will delete the oldest request records first, until the size of the table has been reduced to 20,000 request records.

You can adjust the number of request records kept in the table by modifying the /ts/tools/clean_db.cfg configuration file. To adjust the number of request records stored in the table, perform the following procedure:

BIG-IP ASM 9.4.1 and earlier

Important: F5 Product Development recommends you do not configure the number of records to exceed 100,000 for version 9.4.1 and earlier.

  1. Log in to the BIG-IP ASM command line.
  2. Change directories to the /ts/tools directory by typing the following command:

    cd /ts/tools
  3. Using a text editor, modify the clean_db.cfg file.
  4. Modify the Limit value specified for the [PLC.LRN_REQUESTS] entry to reflect number of request records you want to store in the table, as shown in the following example:

    [PLC.LRN_REQUESTS]
    Limit=20000
  5. Save the file.
  6. Restart the BIG-IP ASM service with the following command:

    Important: This step will cause a brief traffic disruption.

    bigstart restart asm

BIG-IP ASM 9.4.2 10.x

You can adjust the number of forensic records kept in the table by modifying the /ts/tools/clean_db.cfg configuration file. To adjust the number of forensic records stored in the table, perform the following procedure:

Note: Beginning in version 9.4.2, the web application Forensics is now stored in a separate location to Learning Requests, and the default number of records kept is 3,000,000 rather than the 20,000 in earlier versions.

Important: There is no recommended maximum value for 9.4.2 and later as in previous versions; however, F5 Product Development does not recommend setting a limit higher than the default value of 3,000,000.

  1. Log in to the BIG-IP ASM command line.
  2. Change directories to the /ts/tools directory by typing the following command appropriate for your software version:

    For versions 9.4.2 through 10.0.1:

    cd /ts/tools

    For version 10.1.0 and later:

    cd /etc/ts/tools/
  3. Using a text editor, modify the clean_db.cfg file.
  4. Modify the Limit value specified for [PRX.PROXY_LOG] entry to reflect the number of request records you want to store in the table, as shown in the following example:

    [PRX.PROXY_LOG]
    Limit=150000
  5. Save the file.
  6. Restart the BIG-IP ASM service with the following command:

    Important: This step will cause a brief traffic disruption.

    bigstart restart asm

If the forensics entries are deleted too quickly and the number of records kept in the table does not increase, you may want to optimize the requests that are passed through the BIG-IP ASM. For example, you may want to bypass the BIG-IP ASM for image or multimedia requests that require the level of security provided by the BIG-IP ASM.

BIG-IP ASM 11.x

Due to changes made in the database tables the number of Forensics page request records should not be changed in BIG-IP ASM 11.x
