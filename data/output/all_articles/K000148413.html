K000148413: OOM killer being triggered continuously

Description

OOM killer being triggered continuously and top memory consuming processes do not show anything unexpected.

Environment

  • BIG-IP

Cause

Memory can be consumed by tmsh connections not being closed properly. By default, there is no timeout for tmsh shell sessions, which can lead to an issue if a user/script does not log out properly. Each of those can consume some amount of memory between 10 Mb and 40 Mb, depending on number of connections, it can lead to memory exhaustion, and will not be visible as top memory consumer as each of this process will be displayed separately. As the which will be killed by OOM killer is one that was calculated to have a greater impact on memory usage recently, based on a heuristic algorithm, it will most likely not kill multiple processes consuming small amount of memory.

Answer/Recommended Actions

Make sure that all users/scripts are ending connection properly.

You can also apply timeout for tmsh/ssh connections according to the below guide:
K9908: Configuring an automatic logout for idle sessions: https://my.f5.com/manage/s/article/K9908
