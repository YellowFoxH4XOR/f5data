K44544502: 'reset trust' option during UCS restore results in missing trust-domain

Description

Navigating within the GUI to Device management >> Device trust results in the error:
"No identifier specified in context".

'Reset Trust' option was selected during UCS restore

This will prevent administrator to rebuild trust domain via GUI due to missing trust certificates on new system


# ls -l /config/filestore/files_d/Common_d/

drwxrwxrwx. 2 root root 4096 2016-12-29 14:40 trust_certificate_d
drwxrwxrwx. 2 root root 4096 2016-12-29 14:40 trust_certificate_key_d

Environment

  • BIG-IP
  • RMA replacement
  • UCS restore
  • reset trust option

Cause

New unit might be missing trust-domain.

Recommended Actions

  1. Log on to the replacement BIG-IP command line.
  2. After the UCS restoration determine if the replacement BIG-IP has trust-domain certificates:

    tmsh list /cm trust-domain
     
  3. Compared contents of '/config/filestore/files_d/Common_d/' directories with working unit and saw that new unit is missing two 'trust_certificate' directories

    Example:
    Cert path:  /config/filestore/files_d/Common_d/

    Missing directories:
    drwxrwxrwx. 2 root root 4096 2016-12-29 14:40 trust_certificate_d
    drwxrwxrwx. 2 root root 4096 2016-12-29 14:40 trust_certificate_key_d
     
  4. To resolve the issue delete none existent trust-domain:
    tmsh delete /cm trust-domain Root
     
  5. Restart devmgmt service:
    bigstart restart devmgmtd

    Important: It is not recommended to select to Reset Trust during a UCS import
