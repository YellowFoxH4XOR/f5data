Known Issue

Configurations may not save correctly when the BIG-IP system attempts to save individual partitions.

This issue occurs when one of the following conditions is met:

  • When saving a configuration, you specify an individual partition to save.
  • When saving a configuration, you specify a list of partitions to save.

When you use the tmsh save /sys config partitions { partition_list } command to save a configuration for only specific partitions, the configuration is saved by appending the configuration files instead of overwriting them. As a result, the appended configuration may fail to load.

Impact

Saved configurations may fail to load during subsequent configuration loads.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H501701 on the Diagnostics > Identified > High screen.
  • Saved partition configuration files contain duplicate configuration entries.
  • After performing a configuration synchronization (ConfigSync), peer synchronization group members have duplicate configuration entries in the partition's configuration files.
  • Affected configurations fail to load as expected.

Workaround

To work around this issue, you should avoid specifying a partition list when saving a configuration. To do so, use the tmsh save /sys config command to save all administrative partitions.

Note: Beginning in BIG-IP 11.3.0, the tmsh save /sys config command saves all administrative partitions. For more information refer to K14564: The tmsh [save/load] /sys config command now saves/loads configurations in all administrative partitions.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
