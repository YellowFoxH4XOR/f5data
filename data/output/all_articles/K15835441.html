K15835441: OCSP Authentication stalling

Type
Support Solution
Published
2020-03-04
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.1
Source
https://my.f5.com/manage/s/article/K15835441

Description

OCSP Authentication stalling, SSL negotiation fails on the client-side.

  • SSL negotiation has delayed and eventually timed out.
  • TCP connection is being reset.
  • OCSP authentication request been sent after the connection been reset.
  • In the /var/log/ltm: warning tmm[7091]: 01260013:4: SSL Handshake failed for TCP 10.0.0.1:30000 -> 10.0.0.2:443

Environment

All the following conditions are met.

  • OCSP authentication is being used.
  • The Client Certificate is "require/request" and the Frequency is "Always" in the client-ssl profile.
  • The client-side has a high connection volume.

Cause

The tamd service has a performance issue while scaling up.

Recommended Actions

There is no workaround to mitigate this issue directly. However, you may consider either of the following options:

  • Set Frequency to "Once" in the client-ssl profile.
  • Enable "Session Ticket" in the client-ssl profile.
