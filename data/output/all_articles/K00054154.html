Known Issue

Traffic Management Microkernel (TMM) may restart and produce a core file when the session or table commands are used in an iRule.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server that uses an iRule.
  • You use a session or table command in the iRule.
  • The iRule contains CLIENT_CLOSED and SERVER_CLOSED events.

If a command in the iRule configuration suspends the iRule (sometimes referred to as 'parked'), when the iRule resumes, if the connection state is no longer the same as when the iRule was initially suspended, this known issue occurs. The iRules session and table commands are examples of suspending commands.

Note: For more information about the session and table commands and other iRules elements, refer to the iRules Home on F5 Cloud Docs.

Impact

If the BIG-IP system is a member in a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H486445 on the Diagnostics > Identified > Medium screen.
  • Your BIG-IP system fails over to another host in the device group.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system temporarily fails to process traffic while TMM restarts.
  • Messages similar to the following example are logged to the /var/log/tmm file:

    notice panic: ../dev/tcl/tcl.c:127: Assertion "not already queued" failed.
