Known Issue

IP address conflicts occur when client-side multihoming is enabled in the Stream Control Transmission Protocol (SCTP) profile.

This issue occurs when all of the following conditions are met:

  • You have multiple BIG-IP systems in a high availability (HA) configuration.
  • Your configuration includes one or more SCTP profiles with the following configuration:
    • Client-side multihoming is enabled.
    • Multiple secondary addresses are defined.

Impact

SCTP endpoints are created on the standby BIG-IP system, causing connectivity failures.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Only SCTP connections are failing through the BIG-IP system.
  • The system logs messages in the /var/log/ltm file that appear similar to the following example:

    01190004:4: address conflict detected for 192.168.10.100 (01:23:4a:5b:67:8c) on vlan 0

Workaround

To work around this issue, ensure the multihoming secondary IP addresses are not on the same IP subnets as the BIG-IP system self IP addresses. Instead, use IP addresses from another IP subnet and route SCTP endpoint connections to the floating self IP addresses of the BIG-IP systems.

Impact of workaround: Performing the recommended workaround should not have a negative impact on your system.
