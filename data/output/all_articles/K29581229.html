Topic

This article provides recommendations to help you configure the Trusted Certificate Authority (CA) when setting up your IPsec Internet Key Exchange (IKE) peer for negotiation in the IKE protocol.

Description

In IPsec IKE phase 1, two IPsec tunnel endpoints, also known as IKE peers, open a secure channel to initially negotiate the exchange of peer-to-peer authentication data. When configuring the IKE peer for IKE phase 1 negotiation, you should verify the peer certificate by specifying a Trusted CA. By doing so, you ensure that the peer certificate that the BIG-IP system receives from the IKE peer is signed by a Trusted CA that you specify and trust.

Note: When you use Preshared key as your authentication method, you do not have to verify the peer certificate and configure a Trusted CA, as doing so is not applicable.

When you configure an IKE peer in IPsec to use Trusted CA for peer authentication, F5 recommends the following:

  • Include only required CA certificates (multiple CAs in a CA bundle) that sign peer certificates with which you expect the BIG-IP system to negotiate. For example, if you only trust and need the BIG-IP system to negotiate with peers certified by the Nokia root CA, then select a CA bundle that contains only the Nokia root CA.
  • Include only CA certificates whose status you can track. The tracking includes dates, certificate revocation lists, and other security updates provided by the CA.
  • Do not include, in your CA bundle, any CAs that are not required. These CAs do not certify any peer certificates with which you expect the BIG-IP system to perform an IKE negotiation.

    For example, the BIG-IP default CA certificate bundle, ca-bundle.crt, contains certificates from most of the well-known CAs, some of which are not required to certify the certificates of the IKE peers. Using the full default CA bundle file increases the risk of an attacker using an unintended certificate to establish a connection with the BIG-IP system and increases the security exposure of the peer authentication.

Procedures

  • Configure the Trusted CA in the IKE peer negotiation using the Configuration utility
  • Configure the Trusted CA in the IKE peer negotiation using tmsh

Impact of procedures: These procedures configure the BIG-IP system to trust only peer certificates signed by the Trusted CA you specify. Negotiations with IKE peers without a valid peer certificate fail and an IPsec tunnel is not established. F5 recommends that you perform these procedures during a scheduled maintenance window.

Note: These procedures do not apply if you are using Preshared Key as your Authentication Method.

Configure the Trusted CA in the IKE peer negotiation using the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Network > IPsec > IKE Peers.
  3. Select the name of the IKE Peer resource to modify.
  4. If not already selected, select Verify Peer Certificate.

    The Trusted Certificate Authorities option displays only when you select this option.

    Note: In BIG-IP 11.6.x, select Verify Certificate.

  5. For Trusted Certificate Authorities, select an appropriate file.
  6. Select Update.

For a description of the meaning of each field, refer to the TMSH reference for IKE peer.

Configure the Trusted CA in the IKE peer negotiation using tmsh

  1. Use the following command syntax on the TMOS Shell (tmsh):

    modify net ipsec ike-peer <peer_name> ca-cert-file <ca file name> verify-cert true

    For example:

    modify net ipsec ike-peer example_peer ca-cert-file exampleCA.crt verify-cert true

  2. To verify the changes, enter the following command:

    list net ipsec ike-peer <peer_name>

For a description of the meaning of each field, refer to the TMSH reference for IKE peer.
