Topic

The Traffic Management Microkernel (TMM) may translate the port specified for File Transfer Protocol (FTP) data connections to a random port number.

Description

When processing FTP data connections through a Clustered Multiprocessing (CMP) enabled virtual server with an FTP profile applied, TMM may re-write/change the port specified in the PORT command and passive (PASV) response to a random port number. For example, when processing a passive FTP connection, TMM may change the port specified in the Entering Passive Mode response from the FTP server to the client to be a random port value. Similarly, when processing an active FTP connection, TMM may change the port specified in the PORT command sent from the client to the FTP server. This is expected behavior, intended to randomize ports and ensure connections are distributed across multiple TMMs.

Recommendations

If changes to the FTP data port are incompatible with other network devices in the connection flow, such as a firewall not accepting the FTP data port change, you can disable this behavior by disabling CMP on the virtual server. Alternatively, in BIG-IP 11.5.0 and later, you may be able to mitigate this behavior by using the FTP::port iRules command to set the range of FTP data port change available for the system to select.

For information about disabling CMP for a virtual server, refer to one of the following articles:

  • K14358: Overview of Clustered Multiprocessing (11.3.0 and later)
  • K14248: Overview of Clustered Multiprocessing (11.0.0 - 11.2.x)
  • K7751: Overview of Clustered Multiprocessing (9.x - 10.x)

Impact of recommendation: Disabling CMP for a virtual server limits processing of that virtual server to only one CPU core. This can adversely affect performance on multi-core BIG-IP systems, as only a fraction of the available CPU resources are available for the virtual server.

For information about the FTP::port iRules command, refer to the F5 Cloud Docs Wiki: iRules API FTP::port page.

Impact of recommendation: Depending on your application environment and FTP server configuration, you may still see a mismatch between the client-side and server-side FTP data ports. Additionally, adding an iRule increases the resources used by the associated virtual server. F5 recommends testing any such changes in an appropriate environment.
