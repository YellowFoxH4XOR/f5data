Description

When a user logs in to BIG-IP APM network access and connects to VPN, it causes another user VPN session to disconnect.
When a new user session connects, you may observe the following logs in /var/log/apm, in the following example:

notice tmm1[<PID>]: 01490549:5: /Common/<acccess profile>:Common:7e73cd66: Assigned PPP Static IPv4: 10.10.10.10 ID: 6b7ae132 Tunnel Type: VPN_TUNNELTYPE_TLS NA Resource: /Common/<Network access profile> Client IP: 192.0.2.100
err tmm1[<PID>]: 0149059c:3: /Common/<acccess profile>:Common:7e73cd66: User tmm.uuid./Common/<acccess profile>.<username> starting new session e64062431f04c04a4992fbf57e73cd66 Terminated old session 2784c9ad306385a63baa853c6e3a55ed

Environment

  • BIG-IP APM
  • Virtual server
  • Access policy
  • Network access profile
  • Static IP for account

Cause

When multiple users get the same static IP address for the PPP tunnel, the new VPN tunnel connection causes the existing VPN tunnel to disconnect.
Alternatively, this can also happen when multiple clients use the same account to connect to VPN and the account gets the same static IP address.

Recommended Actions

When configuring BIG-IP APM network access, ensure multiple accounts do not share the same static IP address when connecting to the VPN tunnel, and multiple clients do not share the same account with the same static IP address.
