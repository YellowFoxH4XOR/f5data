K91261927: ZoneRunner record has been deleted but still being displayed

Support Solution
Published
2021-08-03
Updated

Applies to

Source
https://my.f5.com/manage/s/article/K91261927

Description

You have deleted a ZoneRunner record but record is still visible from the BIG-IP GUI (Configuration Terminal).

The ZoneRunner record is deleted and viewed at DNS > Zones > ZoneRunner > Resource Record List.

When viewing the BIND file, the record has been deleted. The BIND file is located at var/named/config/namedb/ and the file name is based on the zone name.
For example if the zone name is example.com, the BIND file name would be:
var/named/config/namedb/db.external.example.com.

The issue can also happen for BIG-IP DNS/GTM systems which are in sync with Synchronize DNS Zone Files - Enabled.
For example:
  1. On GTM1 ZoneRunner record test.example.com has been deleted and it synchronizes other BIG-IP DNS/GTM systems.
  2. All other BIG-IP DNS/GTM systems will also delete test.example.com.
  3. However, it is noticed that on device GTM2, test.example.com is still being displayed.
  4. Viewing GTM2's BIND file, test.example.com has been deleted.
Environment
  • BIG-IP DNS/GTM
  • ZoneRunner record has been delete but still being displayed on the BIG-IP DNS/GTM GUI
  • BIND file shows the record has been deleted
  • Synchronized BIG-IP DNS/GTM might display the deleted ZoneRunner record even if it has been removed from their BIND file

Cause

Unknown at the time of publication.

Recommended Actions

To resolve the issue, you will need to restart the named and zrd daemons.

  1. Login to the BIG-IP DNS/GMT Command Line.
  2. Restart named and zrd daemons by typing:
    bigstart restart named zrd
