K000130515: BIG-IP LTM appliance shows NTP not in sync

Type
Support Solution
Published
2023-01-06
Updated
2025-05-13
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000130515

Description

When we check the NTP status using the command "ntpq -np" we are seeing status as INIT and NTP servers to BIG-IP communication is failing. As given in the below article.

ntpq -np

The following output will be seen: 

     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
 129.220.31.9    .INIT.          16 u    - 1024    0    0.000    0.000   0.000
 172.29.10.1     .INIT.          16 u    - 1024    0    0.000    0.000   0.000

In this example, the remote server information (refid, stratum, delay, offset, jitter) is not available. The value .INIT. in the refid column indicates that NTP is initializing, and the server has not yet been reached. The value of 0 (zero) in the reach column indicates that the server has not been reached during any of the last eight attempts. The absence of a value in the when column indicates that no data has been received from the remote peer since the local ntpd process started. The poll value of 64 is still at the MINPOLL value, which indicates that NTP was recently restarted.

Environment

  • BIG-IP LTM
  • NTP

Cause

BIG IP is taking a different route to communicate with the NTP server, validated using the below command:

ip route get <NTP server IP>

Recommended Actions

 Add a management route on BIG-IP to reach the NTP server network.

tmsh create /sys management-route <NTP server network> gateway <gateway IP address>

Additional Information

K15040: Configuring and displaying the management IP address for the BIG-IP system
