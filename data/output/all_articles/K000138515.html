K000138515: Deployed tenant not reachable via F5OS appliance

Type
Support Solution
Published
2024-02-07
Updated
2024-02-07
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000138515

Description

Deployed a BIG-IP tenant on an F5OS-A rSeries appliance, but the management IP of the tenant isn't reachable, even though the appliance itself is reachable.

Tenant is shown to be in a running state when viewing the output of show tenants.

Environment

  • Tenant
  • Management access

Cause

Tenant has been configured with a 32-bit prefix length.

For example:

tenants tenant ltm01
 config type            BIG-IP
 config image           BIGIP-17.1.0.2-0.0.2.ALL-F5OS.qcow2.zip.bundle
 config nodes           [ 1 ]
 config mgmt-ip         10.1.1.245
 config prefix-length   32                  <---
 config dag-ipv6-prefix-length 128
 config gateway         10.1.1.1
 config vlans           [ 4094 ]
 config cryptos         enabled
 config vcpu-cores-per-node 4
 config memory          12288
 config storage size 200
 config running-state   deployed
 config trust-mode      true
 config mac-data mac-block-size large
 config appliance-mode disabled
!

Recommended Actions

Re-configure the tenant's prefix length to ensure connectivity to and from the gateway is possible.

In the example shown in this article, a 24-bit prefix length is required to reach 10.1.1.1 from 10.1.1.245:

tenants tenant ltm01
 config type            BIG-IP
 config image           BIGIP-17.1.0.2-0.0.2.ALL-F5OS.qcow2.zip.bundle
 config nodes           [ 1 ]
 config mgmt-ip         10.1.1.245
 config prefix-length   24                  <---
 config dag-ipv6-prefix-length 128
 config gateway         10.1.1.1
 config vlans           [ 4094 ]
 config cryptos         enabled
 config vcpu-cores-per-node 4
 config memory          12288
 config storage size 200
 config running-state   deployed
 config trust-mode      true
 config mac-data mac-block-size large
 config appliance-mode disabled
!

Additional Information

Lack of management access has a variety of potential root causes. Further troubleshooting is required if your tenant is configured with the correct prefix length and there are still issues.
