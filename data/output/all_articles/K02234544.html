Topic

Using a device service clustering (DSC) configuration, also known as high availability (HA), ensures your BIG-IP system is always available to process application traffic. Multiple BIG-IP devices work together in a group to reliably process requests and responses from multiple applications, regardless of interruptions on any one device.

This example demonstrates the fast and complete path to manually configuring DSC. At the end, you have a sync-failover device group with two BIG-IP devices in an active-active configuration that uses configuration synchronization (ConfigSync).

You should consider using this procedure under the following conditions:

  • You want to manually configure DSC.
  • You want to use the minimum requirements to set up DSC.

Description

This article covers how to manually setup a DSC with two or more BIG-IP devices. 

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have the minimum environment and details to configure DSC.

Environment

This example uses:

  • Mac laptop
  • VMware Fusion
  • Two virtual machines
  • BIG-IP 15.1.0 on both devices with hard-coded management IP addresses

Minimum requirements for your initial device group

The minimal requirements to run DSC are as follows:

  • Two BIG-IP virtual editions (VEs) or BIG-IP devices running the same version of BIG-IP software
  • A network topology plan

Setting up the devices

Activating the BIG-IP licenses

This example uses a BIG-IP LTM license for both BIG-IPs devices. Perform the following steps on both BIG-IP devices.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. On the Setup Utility page, select Next.

    At this point, you must license your BIG-IP device. For more information, see K7752: Licensing the BIG-IP system.

  3. On the Resource Provision page, select Next.
  4. On the Device Certificates page, select Next.

Configuring the platform

Perform the following steps on both BIG-IP devices.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Platform page, under General Properties, in Management Config IPV4, select Manual.
  2. In IPV4 Config Details, in IP Address[/prefix], enter the management address for BIG-IP 1, which is 10.1.1.245 in this example.
  3. In Network Mask, use a 24 bit netmask.
  4. In Management Route, enter the host, which is 10.1.1.2 (your local computer running VMware in this example).
  5. In Host Name, enter a name.
  6. Under User Administration, in Root Account, in Password, enter a password.
  7. Select Next.

Configuring the network on both devices

Using the wizard to set up an HA network

Perform the following steps on both BIG-IP devices.

Impact of procedure: Performing any of the following procedures should not have a negative impact on your system.

  1. On the Network page, under Standard Network Configuration, select Next.

    Note: This selection enables you to use the HA wizard.

  2. In Config Sync, select Display configuration synchronization options.
  3. In High Availability, select Display failover and mirroring options, and in the Failover Method list, select Network.

Configuring the internal VLAN for BIG-IP 1

Perform the following steps on BIG-IP 1:

  1. On the VLANs page, under Internal Network Configuration, in Self IP, in Address, enter your internal VLAN self IP for BIG-IP 1, which is 10.11.17.241 in this example.
  2. In Netmask, enter a 24 bit netmask.
  3. In the Port Lockdown list, select Allow Default.

    Note: This option enables you to lock down the VLAN. Since it is an internal VLAN, presumably it is not externally accessible. When you select Allow Default, you keep open the TCP ports that the system uses to establish ConfigSync.

  4. In Floating IP, in Address, enter the SNAT IP address you want to use for configuring virtual servers, which is 10.11.17.240 in this example.
  5. In the Port Lockdown list, select Allow Default.
  6. Under Internal VLAN Configuration, in Interfaces, in the VLAN Interfaces list, select the VLAN interface for your internal VLAN, which is 1.2 in this example.
  7. In the Tagging list, select Untagged.
  8. Select Add.
  9. Select Next.

Configuring the external VLAN for BIG-IP 1

Perform the following steps on BIG-IP 1:

  1. On the VLANs page, under Internal Network Configuration, in Self IP, in Address, enter your external VLAN self IP for BIG-IP 1, which is 10.14.17.241 in this example.
  2. In Netmask, enter a 24 bit netmask.
  3. In Default Gateway, enter a gateway, which allows the BIG-IP system to route out, if needed.

    This example uses 10.14.17.2, which is your local computer.

  4. Under External VLAN Configuration, in Interfaces, in the VLAN Interfaces list, select the VLAN interface for your external VLAN, which is 1.1 in this example.
  5. In the Tagging list, select Untagged.
  6. Select Add.
  7. Select Next.

Configuring the HA VLAN for BIG-IP 1

This VLAN is a communication channel between the two Traffic Management Microkernel (TMM) processes on the two BIG-IP devices. When you use a device group, to avoid an active-active configuration, configure this VLAN for redundancy so that the BIG-IP communicates over the management address and through the HA VLAN.

Perform the following steps on BIG-IP 1:

  1. On the VLANs page, under Internal Network Configuration, in Self IP, in Address, enter your HA VLAN self IP for BIG-IP 1, which is 10.13.17.241 in this example.
  2. In Netmask, enter a 24 bit netmask.
  3. Under High Availability VLAN Configuration, in Interfaces, in the VLAN Interfaces list, select the VLAN interface for your HA VLAN, which is 1.3 in this example.
  4. In the Tagging list, select Untagged.
  5. Select Add.
  6. Select Next.

Configuring the NTP, DNS, ConfigSync, failover, and mirroring for BIG-IP 1

When you use clustering, the system uses ConfigSync to make changes, which is based on timestamps. Therefore, NTP is essential for HA.

When you use host names to communicate between the two BIG-IP systems, they need a resolver. However, it's good practice to configure DNS regardless of whether you use host names.

The ConfigSync setting defines the network address through which the system performs ConfigSync.

By default, in BIG-IP 12.0 and after, the system automatically selects the HA VLAN for failover, which is the best choice because it doesn't have network traffic other than HA.

By default, the system automatically selects the HA VLAN for mirroring. If you're using a basic HTTP environment in which the BIG-IP system is load balancing traffic to web servers, your HTTP connections are short-lived and you don't need mirroring. When your BIG-IP system is making more complex connections, such as SSH and other long-lived connections, mirroring becomes useful.

Perform the following steps on BIG-IP 1:

  1. Under Network Time Protocol Configuration, in Address, enter the NTP address, which is 10.1.1.2 (your local computer) in this example.
  2. Select Next.
  3. Under Domain Name Server Configuration, in DNS Lookup Server List, in Address, enter a DNS resolver, which is 10.1.1.2 (your local computer) in this example.
  4. Select Add.
  5. Select Next. 
  6. On the ConfigSync page, select Next (using the default option: internal).
  7. On the Failover page, select Next.
  8. On the Mirroring page, select Next.

Configuring the network for BIG-IP 2

Perform all of the procedures for BIG-IP 2 that you just performed for BIG-IP 1.

Establishing the device group on BIG-IP 1

Perform the following steps on BIG-IP 1:

  1. On the Active/Standby Pair page, select Next.
  2. On the Discover Peer page, select Next.
  3. Under Retrieve Device Credentials, in Device IP Address, enter the management address of BIG-IP 2, which is 10.1.1.246 in this example.
  4. In Administrator Username, enter the user name for BIG-IP 2.
  5. In Administrator Password, enter the password for BIG-IP 2.
  6. Select Retrieve Device Information.

    Step 2 displays, indicating that the system found the device and verified the certificate.

  7. Select Device Certificate Matches.

    Step 3 displays; you may want to change Sync-Failover Group Name to something more intuitive.

  8. Select Add Device.

    At this point, the BIG-IP systems connect and exchange certificates to establish a trust relationship and enable communication. You established the device group.

Syncing the devices

Manually syncing the traffic configuration from BIG-IP 1 to BIG-IP 2

Perform the following steps on BIG-IP 1.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Device Management > Overview.

    Under Device Groups, under Sync Issues, the name of the new device group displays with the message that it is Awaiting Initial Sync using a Manual Sync.

    Note: Under In Sync, the system lists the device_trust_group, which should have an In Sync message. If it does not, your group is broken and you must start over.

  2. To push the BIG-IP 1 traffic configuration to BIG-IP 2, under Sync Operations, select Push the selected device configuration to the group, and then select Sync.

    Notes:

    • The group message changes to Not All Devices Synced. Syncing takes a few moments and the message changes when the system finishes the sync.
    • If the sync fails, ensure that the system is trying to sync your group and not the device_trust_group. If the system is trying to sync the device_trust_group group, expand the row for your group and try again.

Checking your configuration and changing the sync from manual to automatic

Manually syncing your BIG-IP devices whenever you make a change to either one is cumbersome; therefore, change the sync from manual to automatic.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. To confirm the BIG-IP devices are present, on the Configuration utility for both devices, go to Device Management > Devices.

    Both devices display.

  2. To confirm the device group, on the Configuration utility for BIG-IP 1, go to Device Management > Device Groups.

    The name of the group displays and, under Type, the system indicates that it is a Sync-Failover group.

  3. Select the group name.

    Under Configuration, in Members, the names of the two devices display.

  4. To change the sync from manual to automatic, in the Sync Type list, select Automatic with Incremental Sync.

    From this point forward, a change on either device propagates automatically to the other one.

Changing the load balancing method

Adding a traffic group and creating an active-active configuration

By default, the BIG-IP system creates one traffic group. You can create additional traffic groups to allow all of your BIG-IPs to carry traffic at the same time.

In this example, the following steps configure the first traffic group to so that BIG-IP 1 is the preferred active device to carry that traffic group, and then you create a second group in which BIG-IP 2 is the preferred active device to carry that traffic group. In doing so, you essentially create an active-active configuration in which one devices carries traffic for the first group and one device carries traffic for the second group, and they act as back-ups for one another.

Perform the following steps on BIG-IP 1.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Device Management > Traffic Groups. 
  2. Select the name of the existing traffic group.
  3. Under Failover Configuration, in Failover Method, select Failover using Preferred Device Order and the Load Aware.
  4. In Failover Order, in the Load Aware box, select both BIG-IP devices, and then select Move left (<<).
  5. In Failover Method, select Always Fallback to First Device if it is Available, which better enables you to see how the mechanism works.
  6. Select Save.
  7. On the Traffic Groups page, select Create.
  8. Under General Properties, in Name, enter a name for the new traffic group.
  9. Under Failover Configuration, in Failover Method, select Failover using Preferred Device Order and the Load Aware.
  10. In Failover Order, in the Load Aware box, select the BIG-IP 2 device, and then select Move left (<<).
  11. In the Load Aware box, select the BIG-IP 1 device, and then select Move left (<<).
  12. In Failover Method, select Always Fallback to First Device if it is Available, which better enables you to see how the mechanism works.
  13. Select Save.

Note: The BIG-IP system automatically assigns a failover object to traffic-group-1, which it created automatically. That object is the the floating IP address, 10.11.17.240. If BIG-IP 1 fails over to BIG-IP 2, the address gets "ARPed" on BIG-IP 2, so that it can use that address. Network objects that need to "float" to the currently-active device get assigned to a traffic group.

Note: We recommend having floating IP even with active active deployment, if you decide to not configure floating IP, then some times failing over might not work. For BIG-IP redundant systems during a failover, the system taking over as the active unit does not advertise GARP requests for BIG-IP VS objects that are configured without floating self IP. When the BIG-IP system does not advertise GARP requests for a virtual address, the neighbouring network devices may continue to send traffic to the previously active unit. As a result, traffic may be disrupted. While it failing over can work for TCP, the problem can be more visible when traffic is UDP or unidirectional as the sending device doest have anyway to update its MAC address table.

Creating virtual servers that you can assign to a traffic group

The system assigns anything it uses to pass traffic, like virtual addresses, to a traffic group.

Perform the following steps on BIG-IP 1.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Local Traffic > Virtual Servers. 
  2. Select Create.
  3. Under General Properties, in Name, enter a name for your virtual server, which is vs1 in this example.
  4. In Destination Address/Mask, select Host and then enter the address, which is 10.14.14.30 in this example.
  5. In Service Port, select Port and then enter the port, which is 80 in this example.
  6. Under Configuration, in the Source Address Translation list, select Auto Map.

    This selection tells the system to use the floating internal self IP address on the VLAN.

  7. Under Resources, in the Default Persistence Profile list, select source_addr.
  8. To create a pool, in Default Pool select the Create (↑) icon.
  9. Under Configuration, in Name, enter a name for the pool, which is p80_pool, in this example.
  10. In Health Monitors, in the Available box, select gateway_icmp and then select Move left (<<).
  11. Under Resources, in New Members, in Address, enter the pool address, which is 10.11.17.11 in this example.
  12. In Service Port, enter 80.
  13. Select Add and add two more pools, which are 10.11.17.12 and 10.11.17.13 in this example.
  14. Select Finished.
  15. On the New Virtual Server page, select Save.

    Note: If you have not yet booted up the virtual machine running the webservers, the pool member status displays red until you do.

  16. Create a second virtual server using the steps above and the details from the plan for vs2 and p80_pool2.

    Note: The system automatically propagates the new virtual servers to BIG-IP 2.

Assigning a virtual server to a traffic group

The system maps the virtual IP address, not the virtual server, to a traffic group.

Perform the following steps on BIG-IP 1.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Local Traffic > Virtual Servers > Virtual Address List.

    The addresses for the virtual servers display, and the system assigned both virtual addresses to the first traffic group.

  2. To assign the second virtual address to the second traffic group, select the address for the second virtual server, which is 10.14.17.31 in this example.
  3. Under General Properties, in the Traffic Group list, select the second traffic group, which is traffic-group-2 (floating) in this example.
  4. Select Update.

Forcing a traffic group and BIG-IP device to fail over

At this point, the two traffic groups are on different BIG-IP devices, and both the traffic groups and the devices are Active. However, you can force a traffic group and the BIG-IP device it is on into Standby, thereby forcing the traffic to fail over.

Perform the following steps on BIG-IP 2.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Device Management > Traffic Groups.
  2. Select the second traffic group, which is traffic-group-2 in this example.
  3. At the bottom of the page, select Force to Standby, and then select Force to Standby again.

    BIG-IP 2 no longer has any traffic groups carrying traffic, so the overall status of BIG-IP 2 changes to Standby. At the same time, BIG-IP 1 now has both traffic groups and has the overall status Active.

  4. You can fail over the traffic group again by completing steps 1 - 3 again, which makes both devices Active again.

Assigning a floating self IP to a traffic group for a SNAT address

The first traffic group has two failover objects: the floating self IP and the virtual address. When you test the system with traffic, the first web server picks up the SNAT address for the floating self IP.

The second web server runs off the second traffic group, so it always uses the VLAN self IP, since it doesn't have a floating self IP. However, you an assign it one.

To assign a floating self IP to the second traffic group, perform the following steps on BIG-IP 1.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. On the Configuration utility, go to Network > Self IPs.
  2. Select Create.
  3. Under Configuration, in Name, enter a name for your internal floating self IP, which is 10.11.17.250 in this example.
  4. In IP Address, enter the address, which is 10.11.17.250 in this example.
  5. In Netmask, use a 24 bit netmask.
  6. In the VLAN/Tunnel list, select internal.
  7. In the Port Lockdown list, select Allow Default.
  8. In the Traffic Group list, select the second traffic group, which is traffic-group-2 (floating) in this example.

About rebooting the BIG-IP devices

When you reboot both devices at the same time:

  • The system goes to the Sync-Failover group, determines the members, and establishes a connection again.
  • Then, the traffic groups negotiate which device is going to pick up traffic, based on their settings.
    • The configuration in this example uses Preferred Order.
    • In the first traffic group, BIG-IP 1 is in first position.
    • In the second traffic group, BIG-IP 2 is in first position.
