Known Issue

A FastL4 virtual server stops processing traffic after a Hash persistence profile is applied.

This issue occurs when the following condition is met:

  • You configure a virtual server to use a Hash persistence in addition to a FastL4 profile.
Important: Beginning in 12.1.0 and later, the affected configuration may result in TMM producing a core file and has been classified as a possible denial-of-service (DoS) vulnerability. For more information, refer to the Security Advisory article K49440608: TMOS vulnerability CVE-2018-5509.

Impact

The affected virtual server stops processing traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the Hash persistence profile is applied to a FastL4 virtual server, the virtual server stops processing traffic.

  • When the Hash persistence profile is initially applied and during each subsequent configuration load, the BIG-IP system logs messages similar to the following to the /var/log/tmm file:
    local/B8800-1A notice hudfilter_init: 'HASH' is not a bottom-level filter.
    local/- notice MCP Message:
    local/B8800-1A notice create {
    local/B8800-1A notice virtual_server_persist {
    local/B8800-1A notice virtual_server_persist_vs_name "fl4_10.1.0.29"
    local/B8800-1A notice virtual_server_persist_profile_name "hash"
    local/B8800-1A notice virtual_server_persist_object_id 40198
    local/B8800-1A notice virtual_server_persist_partition_id "Common"
    local/B8800-1A notice virtual_server_persist_default 1
    local/B8800-1A notice }
    local/B8800-1A notice }
    local/B8800-1A notice mcp error: 1031000 in mcpmsg_to_database

  • Removing the newly applied Hash persistence profile from the affected virtual server does not resolve the issue.

Resolution

Status

F5 Product Development has assigned ID 223885 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Type of fixFixes introduced inRelated articles
Release13.1.0*K2200: Most recent versions of F5 software
Point release/hotfix12.1.3.2*K9502: BIG-IP hotfix and point release matrix

*To fix of this issue, additional configuration validation logic has been added to prevent this configuration from being applied to a virtual server.

Workaround

To work around this issue, you can restore traffic by deleting the affected FastL4 virtual server and recreating it using a different name.

Note:  When creating the new FastL4 virtual server, if persistence is required, you can use a universal persistence profile instead of a Hash persistence profile. For information about configuring a universal persistence profile, refer to K7392: Overview of universal persistence.

Alternately, if persistence it not required, you may remove the Hash profile from the affected FastL4 virtual server and restart the TMM process. However, this method is not recommended because it disrupts all production traffic on the BIG-IP system. If you want to proceed with this method, perform the following procedure:

Impact of workaround: The following procedure requires a restart of TMM. The BIG-IP system will temporarily fail to process traffic, as it recovers from TMM restart. If configured for high availability (HA), the affected BIG-IP device fails over to a configured peer device.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Virtual Servers.
  4. Select the name of the FastL4 virtual server you want to modify.
  5. Select the virtual server's Resources tab.
  6. In the Default Persistence Profile menu, select a universal persistence profile or None.
  7. In the Fallback Persistence Profile menu, select a universal persistence profile or None.
  8. Click Update.
  9. Log in to the command line.
  10. To restart the TMM process, type the following command:

    Important: Restarting TMM will temporarily interrupt all traffic processing.

    bigstart restart tmm
