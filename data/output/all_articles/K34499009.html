K34499009: BIG-IQ is not aggregating data as expected

Type
Support Solution
Published
2021-12-21
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K34499009

Description

When querying metrics from BIG-IQ via REST API, the returned data is not as expected per the configured retention policy.

The BIG-IQ Retention Policy can be found here:

GUI: System tab -> BIG-IQ DATA COLLECTION -> BIG-IQ Data Collection Cluster -> CONFIGURATION -> Statistics Data Collection -> Configure Retention

Global Properties
Keep real-time (raw) data up to 10 Hours
Keep hourly data up to 168 Hours
Keep daily data up to 31 Days
Keep monthly data up to 12 Months
Limit max storage to 80 % of available partition
Keep events up to 2 Days
Keep traffic capturing up to 7 Days

Environment

  • BIG-IQ
  • Metrics Query API
  • Low Disk space

Cause

  • Disk space limitation of /var partition on DCD's
  • Out of disk space event of /shared on BIG-IQ CM

Recommended Actions

Check available disk space on BIG-IQ CM and DCD's:
df -h

DCD's: /var should not be approaching close to the configured "Limit max storage" in the Retention Policy.
BIG-IQ CM: /shared should not be anywhere near 100% Use.  If /shared is full then stats will not be processed properly on BIG-IQ until disk space is available and the system may require a reboot.

Free up disk space or Increase the partition size as necessary. 
See K30902515: Resizing the /var, /var/log, or /shared file system on a BIG-IQ Virtual Edition

Additional Information

Review the following log files for any sign of problems:

BIG-IQ CM:
/var/log/appiq/configserver.log
/var/log/appiq/postaggregator.log

DCD:
/var/log/appiq/agentmanager.log
