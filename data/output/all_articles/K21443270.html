Description

After installing over the top of a previous version the Management GUI is inaccessible due to httpd service start failure, while SSH access works
You may see one or more of the following conditions

  • In /var/log/confpp.log you may see following error

    Syntax check command FAILURE for unix_config_httpd returned: '256'
    STDERR/STDOUT text begins
    httpd: Syntax error on line 96 of /var/run/config/httpd.conf: Cannot load modules/mod_auth_f5_auth_token.so into server: /etc/httpd/modules/mod_aut

  • Running "systemctl status httpd -l" for checking httpd status gives following error:

    Starting httpd: httpd: Syntax error on line 96 of /etc/httpd/conf/httpd.conf: Cannot load modules/mod_auth_f5_auth_token.so into server /etc/httpd/modules/mod_auth_f5_auth_token.so: cannot open shared object file: Permission denied

  • Starting httpd service fails

    bigstart restart httpd
    Stopping httpd:            [  OK  ]
    Starting httpd:            [FAILED]

Environment

  • Installation over previously used Boot Volume

Cause

During the installation the SELinux file permissions are not set correctly due to a bug ID759564

Recommended Actions

To restore Management GUI access SELinux permissions need to be relabeled running following command

touch /.autorelabel
tmsh reboot

If the issue persists then the upgrade will need to be performed again using a clean boot volume.
 

Perform the following procedures to boot back to the previous Boot Volume and remove the Boot Volume containing the failed install:

  First boot back to the previous Boot Volume
   
    Boot back to the previous boot volume with TMSH Access

  1. show sys software status
  2. Identify the Volume (ie: HD1.x) 
  3. To reboot to the previous volume run:
    • reboot volume HD1.x
  4. The system will automatically reboot 
  5. After reboot is complete verify Management GUI access is restored
    Boot back to the previous volume with Bash Access
  1. switchboot
  2. Select the previous volume and press enter
  3. Type reboot and press enter to boot to the previous volume


  Next remove the Boot Volume that contains the failed install

    Remove the failed install Boot Volume With Management GUI Access

  1. Log into the Management GUI
  2. Navigate to System > Disk Management
  3. Click HD1
  4. Under Contained Software Volumes select the checkbox of the boot volume containing the failed install
  5. Click Delete
  6. Perform software upgrade to a new boot volume
     Remove the failed install Boot Volume With TMSH Access
  1. show sys software status
  2. Identify the Boot Volume containing the failed install (ie: HD1.x) 
  3. delete sys software volume HD1.x
