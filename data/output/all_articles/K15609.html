Topic

Support for TCP Segmentation Offload (TSO) and Large Receive Offload (LRO) is introduced in BIG-IP 11.4.0.

Description

The BIG-IP system uses TSO to reduce CPU usage of fast, large throughput networks by having the interface controller break down large segments of data that it is going to send over the network into smaller segments. TSO reduces CPU overhead by relying on the network interface controller to segment the data, and then add the TCP, IP, and data link layer protocol headers to each segment. This process relieves the CPU from having to break the segments before sending the data to the NIC. The NIC must support TSO for this to work.

TSO is also referred to as large segment offload (LSO), which also includes large receive offload (LRO).

LRO works at the NIC level by aggregating multiple incoming packets within a buffer before passing them up. This process helps reduce CPU usage by eliminating CPU from having to process the incoming packets.

Note: Beginning in BIG-IP 11.5.0, LRO is broken out into a separate BigDB key: tm.tcplargereceiveoffload.

Recommendations

The BIG-IP system uses the tm.tcpsegmentationoffload BigDB key to enable or disable TSO. TSO is enabled, by default, in BIG-IP Virtual Edition (VE) 11.4.0 and later. Beginning in BIG-IP 11.5.0, TSO is enabled by default for all platforms.

To view the current status of the tm.tcpsegmentationoffload BigDB key, type the following command:

tmsh list sys db tm.tcpsegmentationoffload

To enable or disable TSO functionality, use the following command syntax:

tmsh modify sys db tm.tcpsegmentationoffload value <enable | disable>

The BIG-IP system uses the tm.tcplargereceiveoffload BigDB key to enable or disable LRO. LRO is disabled by default in BIG-IP 11.5.0 and later. Beginning in BIG-IP 13.1.0 for all platforms and BIG-IP 12.0.0 for Virtual Edition, LRO is enabled by default.

To view the current status of the tm.tcplargereceiveoffload BigDB key, type the following command:

tmsh list sys db tm.tcplargereceiveoffload

To enable or disable LRO functionality, use the following command syntax:

tmsh modify sys db tm.tcplargereceiveoffload value <enable | disable>

Note: After modifying the tm.tcpsegmentationoffload or the tm.tcplargereceiveoffload database variable, you must restart the Traffic Management Microkernel (TMM) daemon by running the bigstart restart tmm command. Restarting TMM temporarily interrupts traffic processing. F5 recommends that you run this command only during a maintenance window.
