K57518219: How to disable datasyncd obfuscation

Type
Support Solution
Published
2024-04-23
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K57518219

Description:

Datasync obfuscation is a process which obfuscates the JavaScript to protect against reverse-engineering.
It runs on a daily basis whenever any client-side integrity defense features are in use. 
These features include, but are not limited to, CAPTCHA challenges, pro-active bot defense, client-side integrity defense, session awareness and device ID.

Although it is possible to disable datasyncd obfuscation process it is not recommended if the client-side security features are deployed in critical parts of the application.


Environment:

- BIG-IP Advanced WAF
- Client-side integrity defense features in use


Cause:


To disable the obfuscation, this command can be used:

tmsh modify security datasync local-profile cs-asm-dosl7 max-gen-rows 1

And to bring it back:

tmsh modify security datasync local-profile cs-asm-dosl7 max-gen-rows infinite

Note: This is a local configuration - it does not sync across devices in the trust.


Recommended Actions:


Instead of disabling datasyncd obfuscation process, it is also possible to reduce the number of total rows being generated (which will reduce the time which datasyncd obfuscation process needs to complete).
The maximum is 1000, but this is automatically calibrated after startup based on the amount of provisioned memory for ASM on each BIG-IP device.

The current amount of rows to generate can be checked with command:

tmsh list security datasync local-profile cs-asm-dosl7

This can be overriden to a lower number to reduce the time for completion, e.g. to reduce to 100:

tmsh modify security datasync local-profile cs-asm-dosl7 max-gen-rows 100


Additional Information:


The large number of obfuscated versions (rows) of JavaScript increases the security. It makes it more difficult for experienced attackers to overcome the defense that our client-side features serve.
There is no definitive number on what it should be, but it is an advantage to have a large number of obfuscated versions.
In most of the cased the value which is automatically calibrated after a startup is the best choice.
In general, the recommendation is to keep it at least over 10, and preferably over 100.
