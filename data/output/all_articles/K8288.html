Issue

Note: This enhancement is currently not available in BIG-IP 9.4.x.

The number of TCP zero window probes the BIG-IP system sends when persisting a TCP connection is controlled through the TCP profile Maximum Segment Retransmissions option. The default value of this option is 8 with a maximum value of 12. With the maximum allowed value set, 11 window probes are sent by the BIG-IP system before the connection is reset.

This value may not accommodate clients with small buffer sizes, such as cell phone browsers.

Starting in BIG-IP 10.2.0, the Zero Window Timeout TCP profile option specifies the timeout in milliseconds for terminating a connection with an effective zero length TCP transmit window. The timeout starts when the peer advertises a zero length TCP window or when enough data has been sent to fill the previously advertised window. The timer is canceled when a non-zero length window is received. The default is 20000 milliseconds.

To configure the Zero Window Timeout, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Select TCP from the Protocol menu.
  5. Click Create.
  6. Enter a name for the TCP profile.
  7. Select the check box next to the Zero Window Timeout option and enter a value.
  8. Click Finished.
  9. Associate the profile with the virtual server.

In BIG-IP 10.1.0 BIGIP-10.1.0-3402.0-HF2, and 9.3.1 HOTFIX-BIG-IP-9.3.1-HF2, you can configure the TM.TCPMaxPersistIdle db variable. The TM.TCPMaxPersistIdle db variable allows the administrator to set the maximum TCP persist timeout allowed since the last data reception occurred when persisting TCP connections.

You must set the option from the command using the following syntax:

bigpipe db TM.TCPMaxPersistIdle <timeout value in milliseconds>

Note: The default value for this db variable is 0.

Setting the TM.TCPMaxPersistIdle variable manually

If you installed one of the above hotfixes and receive an error message indicating that the variable was not found after running the bigpipe command, you must complete the following steps to manually set the db variable:

Important: You must run this procedure on the standby system or during a maintenance window as it requires you to temporarily stops all services on the BIG-IP system.

  1. Log in to the command line.
  2. To temporarily shut down system services, enter the following command:

    bigstart shutdown
  3. Use a text editor to add the following entry to the end of the /config/BigDB.dat file:

    [TM.TCPMaxPersistIdle]
    default=0
    type=unsigned_integer
    min=0
    max=4294967296
    realm=common
    display_name=TM.TCPMaxPersistIdle
  4. Save the changes and exit the file.
  5. To restart system services, enter the following command:

    bigstart restart
