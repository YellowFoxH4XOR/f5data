Known Issue

A rewrite of unmatched quotes in CSS content may trigger the Traffic Management Microkernel (TMM) to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with a network access or portal access profile.
  • Content rewritten by the profile includes CSS code that ends without a matching closing quote in a stated value.

    Following is an example of CSS code:

    background-image: url ( ' /<path>/<value>'') !important;

Note: In the previous example, there is an unmatched quote (') character after the <value> closing quote.

Impact

The BIG-IP APM system temporarily fails to process traffic while the TMM process restarts. If the BIG-IP system is configured for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • TMM generates a core file in the /shared/core directory.
  • Your BIG-IP APM system logs an SIGFPE to the /var/log/tmm file at the same time TMM produces a core file and restarts.

Workaround

To work around this issue, you can create and apply a customized iRule to the affected virtual server that converts the rewritten HTML entities to their original characters. To do so, refer to the following example procedure:

Impact of workaround: F5 recommends that you perform the following procedure in a lab environment before implementing it into a production environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > Create.
  3. In the Name box, type a name for the iRule.
  4. In the Definition box, enter the following example text:

    when HTTP_REQUEST {
    # Correct CSS content containing unmatched quote in value
        if { [HTTP::path] ends_with "/<path>/<affected css>" } {
            set id629085 1
            HTTP::header remove Accept-Encoding
            if { [HTTP::version] eq "1.1" } {
                if { [HTTP::header is_keepalive] } {
                    HTTP::header replace "Connection" "Keep-Alive"
                }
                HTTP::version "1.0"
            }
        } elseif { [info exists id629085] } {
            unset id629085
        }
    }
    when HTTP_RESPONSE {
        if { [info exists id629085]} {
            if { [HTTP::header exists "Content-Length"] and \
                    [HTTP::header "Content-Length"] > 0 and \
                    [HTTP::header "Content-Length"] <= 1048576 } {
                HTTP::collect [HTTP::header Content-Length]
            } else {
                HTTP::collect 1048576
            }
        }
    }
    when HTTP_RESPONSE_DATA {
        if { [info exists id629085] } {
            set id629085 [string first {<object>'')} [HTTP::payload]]
            if { $id629085 > 0 && \
                $id629085 < [expr {[HTTP::payload length] - 6}]
            } {
                HTTP::payload replace $id629085 6 {<object>') }
            }
            unset id629085
        }
    }

    Note: In this example, the iRule corrects the unmatched extra quote (ASCII 39 characters) found in the pattern <object>''  to a single closing quote <object>'.

    Important: You must modify the iRules stanza to reference the affected application URL, and tune object search criteria and payload length.

  5. Click Finished.
  6. Click Virtual Servers.
  7. Click the name of the virtual server that is affected by this issue.
  8. Click the Resources tab.
  9. Under iRules, click Manage.
  10. In the Available list, select the iRule you previously created and move it to Enabled list.
  11. Click Finished.
