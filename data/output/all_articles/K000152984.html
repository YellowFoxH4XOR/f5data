K000152984: After an upgrade from 17.1.x to 17.5.x webUI shows "Error getting auth token from login provider" when navigating Device Management > Overview

Type
Support Solution
Published
2025-08-12
Updated
2025-10-23
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.5, 17.5.1, 17.5.0, 17.5.X, 16.1.6
Source
https://my.f5.com/manage/s/article/K000152984

Description

After an upgrade from v17.1.x to v17.5.x, when a remotely-authenticated user navigates into Device Management > Overview page, the UI throws an error similar to the following:

"Error getting auth token from login provider"

Inspecting the HAR capture would show that when the browser sends a POST request to /mgmt/shared/authn/login, the response would be a 400 Bad Request with the following payload:

{

 "code": 400,

 "message": "token creation failed; target user should only contain alphanumeric, -, _, ., @ and \\ (backslash) characters",

 "referer": "https://x.x.x.x/tmui/tmui/devmgmt/overview/app/index.html?ver=0.0.7.17.5.1",

 "restOperationId": 1093341,

 "kind": ":resterrorresponse"

}

This also occurs when requesting a token through iControl REST API.

$ curl --silent --insecure --location 'https://localhost/mgmt/shared/authn/login' --header 'Content-Type: application/json' --data '{ "username": "!f5testuser", "password": "supersecretpass", "loginProviderName": "tmos"}' | jq .

{

 "code": 400,

 "message": "token creation failed; target user should only contain alphanumeric, -, _, ., @ and \\ (backslash) characters",

 "referer": "127.0.0.1",

 "restOperationId": 283287,

 "kind": ":resterrorresponse"

}

Environment

  • BIG-IP

Cause

There were code changes introduced via ID1399477 and ID1710621 to mitigate iControl REST vulnerabilities . The change includes limiting the characters allowed to be use in the username.

Recommended Actions

Use only the allowed characters for BIG-IP username which are the following:

  • alphanumeric characters
  • -
  • _
  • .
  • @
  • \
