K000134908: Nginx Ingress Controller deployment could not start after redeployment via Openshift Operator

Type
Support Solution
Published
2023-06-03
Updated
2023-06-03
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 3.X.X, 3.0.0, 3.0.1, 3.0.2, 3.0.X, 3.1.0, 3.1.1, 3.1.X
Source
https://my.f5.com/manage/s/article/K000134908

Description

  • You running a supported version of OpenShift cluster
  • One of your deployments is Nginx-Plus Ingress Controller deployed through OpenShift Nginx Operator
  • Nginx Ingress Controller is deployed with Nginx App-Protect
  • You upgraded the operator but after the upgrade, Ingress controller pod fails to initialize and throws the below error
Could not get newest config version: could not get expected version: 0 after 0s

Environment

  • OpenShift
  • Nginx Ingress Controller
  • Nginx Operator
  • Nginx App-Protect
  • Upgrade

Cause

  • Nginx Ingress Controller version and that of OpenShift Operator are not matching.

Recommended Actions

  • When installing Nginx Ingress controller in Red Hat using Nginx Operator, the ingress Controller must corresponds to the correct operator version as stated here "Supported NGINX Ingress Controller Versions"

Additional Information

  • None
