K000156814: HTTP Response from WAF was dropped on the SSLO side

Type
Support Solution
Published
2025-10-06
Updated
2025-10-06
Applies to
  • F5 App Protect
  • BIG-IP SSL Orchestrator: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.0, 17.1.X, 17.1.1
Source
https://my.f5.com/manage/s/article/K000156814

Description

When using BIG-IP SSL Orchestrator to decrypt HTTPS traffic and forward it to a downstream Web Application Firewall (WAF), the expected block notification page may not be delivered to the client if the WAF blocks traffic with an HTTP Response and immediately resets (RST) the TCP connection. Packet captures show that the HTTP Response is dropped if the WAF sends a TCP RST immediately after the response, resulting in the client experiencing a connection reset or network error instead of receiving the block page.

Environment

  • BIG-IP SSL Orchestrator
  • Topology
  • WAF service

Cause

If the WAF sends an HTTP response and immediately issues a TCP RST, BIG-IP SSL Orchestrator may not have sufficient time to encrypt and forward the HTTP response to the client. If the RST is received before this process completes, the HTTP response is discarded and the client-side connection is reset, preventing the client from receiving the block notification page.

Recommended Actions

  • Configure the WAF to use a TCP FIN (graceful close) instead of an immediate RST after sending the HTTP response. This allows BIG-IP SSL Orchestrator to process and forward the response to the client before the connection is closed.
  • If a RST must be used, delay the RST by at least 1 millisecond after sending the HTTP response to ensure BIG-IP SSL Orchestrator has time to forward the response to the client.

Additional Information

This behavior is specific to Layer 7 proxy devices, which require time to process, encrypt, and forward HTTP responses. Immediate RSTs can result in data loss, as the response may be discarded before sending to the client. Using FIN for connection closure is generally safer in proxy environments to prevent loss of important response data such as block pages.
