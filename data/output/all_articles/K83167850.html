Topic

You should consider using this procedure under the following conditions:

  • You want to define a specific limit for the number of active SSL handshakes allowed by a virtual server.
  • You want to define a specific limit for the number of active SSL handshakes allowed by the BIG-IP system.

Description

By default, the number of active SSL handshakes allowed by the BIG-IP system is limited by the following elements:

  • The SSL transactions per second (TPS) limit specified in the license file.
  • The platform's hardware limitations.

Note: For more information about the BIG-IP system's SSL TPS enforcement, refer to K6475: Overview of SSL TPS licensing limits.

The BIG-IP license indicates the maximum SSL TPS allowed by the system. For example, the perf_SSL_total_TPS : 500 license key allows up to 500 client-side SSL TPS per Traffic Management Microkernel (TMM), and the perf_SSL_total_TPS [UNLIMITED] license key allows an unlimited number of client-side SSL TPS per TMM.

If your license file allows an unlimited or high number of SSL TPS and your system processes a high number of SSL connections or experiences spikes in SSL traffic, you may observe resource-related issues, such as high memory use and failover events.

You can mitigate the resource-related issues by defining a specific limit for the number of active SSL handshakes allowed by the BIG-IP system. You can do this by using one or both of the following configuration scenarios:

Limiting the number of active SSL handshakes for a virtual server

The Max Active Handshakes Client SSL profile setting limits the number of active SSL handshakes for the virtual server to which the profile is applied. When the number of active SSL handshakes reaches the specified limit, the system terminates the most recent SSL handshake. The default setting is Indefinite, which means that there is no limit. The Max Active Handshakes option is introduced in BIG-IP 12.1.0.

Limiting the number of active SSL handshakes globally for the BIG-IP system

The tmm.ssl.maxactivehandshakes database variable allows you to limit the number of active SSL handshakes for the BIG-IP system.

For example, if you want to limit the global number of active SSL handshakes to 64K for a system, you should set the database variable to 64,000.

Note: The value is global, if the system is running with multiple TMM instances, the value is divided by the number of TMM instances, and it applies to each TMM instance For example, on a system with four TMM instances, each TMM limits the active SSL handshakes at 16,000 (64,000/4).

Note: On VIPRION systems, the tmm.ssl.maxactivehandshakes database variable is applied per-blade. For example, setting a value of 64K on a VIPRION system with two blades means that the VIPRION enforces a total limit of 128,000 active SSL handshakes (64,000*2).

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the Configuration utility.
  • You have access to the TMOS Shell (tmsh).

Procedures

Limiting the number of active SSL handshakes for a virtual server

You can limit the number of active SSL handshakes for the virtual server by modifying the Max Active Handshakes Client SSL profile setting. You should consider changing the Max Active Handshakes setting for a single virtual server or a small number of virtual servers that experience periodic spikes in SSL traffic.

Impact of procedure: When the number of active SSL handshakes reaches the limit specified in the Max Active Handshakes setting, the system terminates the most recent SSL handshake.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select the Client SSL profile that is associated with the appropriate virtual server.
  4. For Configuration, select Advanced.
  5. Select the Custom check box next to Max Active Handshakes and select Specify.
  6. Enter the value you want for the Max Active Handshakes setting.
  7. Select Update.

Limiting the number of active SSL handshakes globally for the BIG-IP system

You can limit the number of active SSL handshakes globally for the BIG-IP system by modifying the tmm.ssl.maxactivehandshakes database key. You should consider changing the tmm.ssl.maxactivehandshakes database key when the BIG-IP system processes a high number of SSL connections and the traffic often exceeds the hardware limitations of the device. To limit the number of active SSL handshakes globally for the BIG-IP system, perform the following procedure:

Impact of procedure: When the number of active SSL handshakes reaches the limit specified in the tmm.ssl.maxactivehandshakes database key, the system terminates the most recent SSL handshake.

  1. Log in to the tmsh utility by entering the following command:

    tmsh

  2. To set the tmm.ssl.maxactivehandshakes database key, use the following command syntax:

    modify /sys db tmm.ssl.maxactivehandshakes value <number of active hs>

    For example, if you want to limit the global number of active SSL handshakes to 64 k for a BIG-IP system, set the database variable to 64,000 by entering the following command:

    modify /sys db tmm.ssl.maxactivehandshakes value 64000

    Note: Each TMM will be limited by 64000/Number of TMM's
