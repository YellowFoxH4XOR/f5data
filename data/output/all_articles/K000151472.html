Description

You want to redirect or switch traffic to another virtual server using the iRule event HTTP_REQUEST.

Redirect iRule example:

when HTTP_REQUEST {
   virtual "redirect_vs"
}

Virtual Server configuration example:

ltm virtual landing_vs_https {
    destination 100.100.100.1:https
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
        http { }
        tcp { }
        landing_vs_clientssl_profile {
            context clientside
        }
        landing_vs_serverssl_profile {
            context serverside
        }
    }
    rules {
        redirect_virtual
    }
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

ltm virtual redirect_vs {
    destination 10.10.10.2:https
    ip-protocol tcp
    mask 255.255.255.255
    pool pool_http  
    profiles {
        http { }
        tcp { }

    }
    source-address-translation {
        type automap
    }
    translate-address enabled
    translate-port enabled
}

The configuration above will not work as intended if you want to switch traffic from landing_vs_https to redirect_vs using the iRule, because the traffic between the two virtual servers will be encrypted due to the presence of a serverside SSL profile on landing_vs_https. The redirect_vs virtual server, as shown, does not have a client SSL profile to terminate the SSL handshake initiated by landing_vs_https. As a result, the SSL handshake will fail and the connection will not be established.

Environment

BIG-IP LTM
iRules
Virtual servers with SSL profiles

Cause

When a serverside SSL profile is attached to landing_vs_https, the traffic forwarded to redirect_vs is encrypted. If redirect_vs does not have a clientside SSL profile, it cannot terminate the SSL handshake, resulting in failed connections.

Recommended Actions

To resolve this, you have two options:

Option 1:

Remove the serverside SSL profile from landing_vs_https.

  • This will ensure that the communication between landing_vs_https and redirect_vs is in cleartext (unencrypted), allowing the iRule to successfully switch traffic.

Option 2:

Add a clientside SSL profile to redirect_vs.

  • This will allow redirect_vs to terminate the SSL handshake initiated by landing_vs_https, enabling successful communication.

Additional Information

  • Ensure that the SSL profiles (client and server) are correctly configured and match the intended traffic flow.
  • If you are using SNI or multiple domains, ensure that the appropriate SSL profiles are attached to handle all required hostnames.
  • Always test the configuration in a lab environment before deploying to production.
