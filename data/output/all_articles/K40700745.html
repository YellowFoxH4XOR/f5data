Description
MSSQL health monitor using TLSv1.0 is marking the 2016  SQL servers as down. 

Environment

  • MSSQL health monitor 
  • TLSv1.0
  • SQL servers running 2016

Cause
The Microsoft SQL server that is being monitored has disabled support for legacy security protocols and supports only versions TLSv1.1 and TLSv1.2.
MSSQL health monitor sends TLSv1.0 while the server is expecting TLSv1.2. This is addressed in ID608952. 

Recommended Actions

Workaround: 

This is a workaround for the MSSQL monitor so that BIG-IP can send a request on TLSv1.2. 
  1. Create a virtual server with a dummy IP address with MSSQL server as a pool, and a ServerSSL profile that uses TLSv1.2.

    Example: 

    ltm virtual ubuntu-mssql-vs {
        destination 3.2.3.2:ms-sql-s
        ip-protocol tcp
        mask 255.255.255.255
        pool ubuntu-mssql-server
        profiles {
            clientssl-insecure-compatible {
                context clientside
            }
            serverssl {                                           
                context serverside
            }
            tcp { }
            ubuntu-mssql { }
        }
        source 0.0.0.0/0
        translate-address enabled
        translate-port enabled
        vs-index 13
    }
     
  2. Create an alias monitor using mssql parent monitor.
    Example: 
    ltm monitor mssql ubuntu-mssql-monitor {
        count 0
        database TestDB
        debug no
        defaults-from mssql
        destination 3.2.3.2:ms-sql-s
        interval 30
        password $M$3H$pbjr5I1BV4cq4b2fcgI23Q==
        recv none
        send none
        time-until-up 0
        timeout 91
        username SA
    }
     
  3. Assign the alias monitor to the pool.
    Example: 
    ltm pool ubuntu-mssql-server {
        members {
            10.200.142.150:ms-sql-s {
                address 10.200.142.150
                session monitor-enabled
                state up
            }
        }
        monitor ubuntu-mssql-monitor
    }
     
  4. Check the pool status using CLI. 
    Example: 
    # show ltm pool ubuntu-mssql-server
    ---------------------------------------------------------------------
    Ltm::Pool: ubuntu-mssql-server
    ---------------------------------------------------------------------
    Status
      Availability : available
      State        : enabled
      Reason       : The pool is available
      Monitor      : ubuntu-mssql-monitor
      Minimum Active Members : 0
      Current Active Members : 1


The monitor associated with the pool uses an alias address as 3.2.3.2 and port 1433 from the above example. When the monitor sends the health probes, the layered virtual server receives them and applies the MSSQL profile, client ssl profile, and server ssl profile. It proxies the traffic to the backend pool member. Using these profiles you have the control to manage the TLS version.
