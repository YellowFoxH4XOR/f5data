Description
Trunk goes down on the BIG-IP and you see the lacpd and the lldpd process log the following message in the /var/log/ltm:

err lacpd[<PID>]: 01290003:3: HalmsgTerminalImpl_::sendMessage() Unable to send to any BCM56XXD address
err lacpd[<PID>]: 01160005:3: HalMsgHandler.cpp:125 - HAL send PDU request failed
err lacpd[<PID>]: 01160005:3: HalMsgHandler.cpp:241 - HAL send PDU failed
 

Environment

  • BIG-IP
  • Trunk with Link Aggregation Control Protocol (LACP)
  • No issues on the upstream switch
     

Cause

Unknown, tracked as Bug ID 1009337
 

Recommended Actions

Gather further data following procedure below:
  1. Fetch an initial QKview from CLI:
    qkview -s0 -f /var/tmp/qkview_start.tgz
     
  2. Enable debug logs: 
    tmsh modify sys db log.halmsg.level value debug
    tmsh modify sys db log.libhal.level value debug
    tmsh modify sys db log.bcm56xxd.debugmask value 0x20001fff
    tmsh modify sys db log.bcm56xxd.level value debug
    tmsh modify sys db log.lacpd.debugmask value 511
    tmsh modify sys db log.lacpd.level value debug
    tmsh modify sys db log.lldpd.level value debug
     
  3. Take a packet trace capturing LACP frames in Trunk ports. 
    e.g.  
    tcpdump -s0 -nni 2.1 'ether proto 0x8809' -w /var/tmp/lacp.pcap 
    Note: change interface number if necessary, example above makes use of interface 2.1
     
  4. Start an strace to lacpd process: 
    strace -s1024 -f -Tt -p `pidof lacpd` -o /var/tmp/strace_lacpd.txt
     
  5. Start an strace to bcm56xxd process: 
    strace -s1024 -f -Tt -p `pidof bcm56xxd` -o /var/tmp/strace_bcm56xxd.txt
     
  6. Leave all the above data collection running for a couple of minutes (at least around 5 minutes, if possible more) then stop strace and tcpdump
     
  7. Collect outputs below: 
    touch /var/log/uds_output.txt 
    ls -lhZ /var/run/uds_bcm* >> /var/log/uds_output.txt 
    ls -lh /var/run/bcm* >> /var/log/uds_output.txt
     
  8. Get final QKview from CLI:
    qkview -s0 -f /var/tmp/qkview_final.tgz
     
  9. Collect a bcm56xxd core file:  
    kill -v -s 6 `pidof bcm56xxd`
     
  10. Get a tarball with full logs, just in case logs are truncated 
    tar -czpf /var/tmp/"$HOSTNAME"_logfiles.tar.gz /var/log/*
     
  11. Disable debug logs  
    tmsh modify sys db log.halmsg.level value error 
    tmsh modify sys db log.libhal.level value notice 
    tmsh modify sys db log.bcm56xxd.debugmask value 0 
    tmsh modify sys db log.bcm56xxd.level value informational 
    tmsh modify sys db log.lacpd.debugmask value 0 
    tmsh modify sys db log.lacpd.level value informational 
    tmsh modify sys db log.lldpd.level value informational


It is also recommended to implement would be some kind of automatic failover mechanism (e.g., VLAN failsafe, HA groups with the trunk as member, gateway failsafe).  This will not prevent the problem, but would prevent an Active Guest from staying Active while LACP is down in the Host.

 

Additional Information

Restart services or reboot can fix this issue, please refer:
