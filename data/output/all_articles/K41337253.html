Known Issue

Over a period of time, the BIG-IP PEM system may experience a memory leak after forwarding the Dynamic Host Configuration Protocol (DHCP) IP address requests from clients. The client-side connection flows remain in the connection table after completing the DHCP IP address request process.

The BIG-IP PEM system can relay or forward the DHCP IP address request process to the target DHCP server. The DHCP IP address request process includes namely the following stages: DHCPDISCOVER, DHCPOFFER, DHCPREQUEST, and DHCPACK. This process is also known as the DHCP DORA process.

This issue occurs when all of the following conditions are met:

  • The BIG-IP PEM system is configured to relay or forward the incoming DHCP requests.
  • The client-side connection flow for the DHCP DORA process is completed.
  • The affected connection flow entry has expired.

Impact

The BIG-IP system uses more memory over time, which may eventually cause a decrease in performance or a system reboot due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system did not remove the expired connection flows from the connection table. Hence, over a period of time, with an increase in the number of client-side connection flows for the DHCP DORA process, the system consumed more memory.
  • You can observe the affected connection flows that have expired, but they remain in the connection table when you type the following command:

    tmsh show sys memory | grep connflow

  • You can observe the memory usage increases in the BIG-IP system using any of the following methods:
    • Using the top command.
    • From the Configuration utility, navigating to Statistic > Performance, and reviewing the charts.
  • You observe that various system processes experience restarts due to memory exhaustion.
