Description

Depending your environment and your requirements, you may have deployed an APM profiles with the following options or features enabled at the same time:

  • "Logout URI Include": this option will tell APM to put an end to a session if the URI matches a specific pattern;
  • "Persistent" cookie: this option tells APM to extent the lifespan of the cookies, when stored locally on the user's device

Doing so, you notice the APM sessions are not deleted on due time; or you notice the client still uses cookies that should have been deleted.

Environment

  • BIG-IP APM

Cause

Both options should be enabled together; or this will entice BIG-IP APM to generate conflicting "Set-Cookie" directives:

  • with using "Logout URI Include", the cookie may be marked with a limited lifespan: "Set-Cookie: MRHSession=6637ccfea400ae7fd29216173867dc58; Max-Age=2;path=/"
  • with "Persistent", the cookie is marked with a longer lifespan: "Set-Cookie: MRHSession=6637ccfea400ae7fd29216173867dc58; expires=Sat, 01 May 2023 12:10:00 GMT;path=/"

Recommended Actions

We may need to choose to use either options but not both at the same time.

With the objective to perform automatic session termination, we have the option to deploy some iRule code: K42052145: Configuring automatic session termination (logout) based on a URI-referenced file name
