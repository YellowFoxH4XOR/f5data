Known Issue

Description

TMM may incorrectly mark a pool member with the internal slow ramp time flag and send the member fewer new connections than expected.

This issue occurs when all of the following conditions are met:

  • The pool member has been continuously available in a given pool for more than 24.9 days with no state changes.
  • The pool has Slow Ramp Time enabled.

    Note: Beginning in BIG-IP version 10.1.0, Slow Ramp Time is enabled by default, with a value of 10 seconds.

  • You have modified one of the following two values:
    • The Slow Ramp Time value for the pool
    • The Priority Group value for an active member of the pool

The BIG-IP system uses a counter that resets every 24.9 days, causing an incorrect calculation of the pool member's internal slow ramp time state value. This incorrect value causes the LTM system to continually treat the pool member as if it were within the slow ramp time interval. As a result, the BIG-IP LTM system may not load balance any new connections to the pool member, or it may load balance much fewer connections than expected.

Impact

The pool member receives too few new connections, or no new connections.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H512937 on the Diagnostics > Identified > High screen.
  • When the number of pool members that have the internal slow ramp time flag set is less than half of the total number of active members in the pool, affected pool members receive no new connections.
  • When the number of pool members that have the internal slow ramp time flag set is at least half of the total number of active members in the pool, affected pool members receive fewer than their expected proportion of connections.
  • Pool statistics display an unexpected distribution of connection load among members of a pool.

    For example, an affected pool member may continually show a value of 0 for Current Connections even though the Availability and State are marked as available and enabled, as shown in this partial output from the tmsh show ltm pool members command:

Workaround

To work around this issue, you can disable the Slow Ramp Time setting. To do so, perform the following procedure:

Impact of workaround: Pool members may receive a disproportionately high number of connections when the pool members come back online.

Disabling the Slow Ramp Time setting

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pools List.
  3. Click the name of the pool you want to modify.
  4. Set the Configuration drop-down menu to Advanced.
  5. Set the value for the Slow Ramp Time option to 0 (zero).
  6. Click Update.

If the impact of the above procedure is not appropriate for your particular environment, you can mitigate the issue by resetting the counter on the affected pool members. This action will not work around the issue, but it will cause the BIG-IP system to load balance connections to the pool member once again. However, the issue may occur again once a pool member has been active for another 24.9 days.

You can reset the counter by performing the following procedure:

Disabling and re-enabling a pool member

Impact of procedure: If the pool member is being monitored, this may cause alerts because the pool member transitions between states.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pools List.
  3. Click the name of the pool you want to modify.
  4. Click the Members tab.
  5. In the Current Members list, select the check box for the pool member you want to modify.
  6. Click Disable.
  7. In the Current Members list, select the check box for the pool member again.
  8. Click Enable.
