Description

Using TMUI or tmsh list commands will indicate that the internal data group has records configured. However, the internal data-group entry in the bigip.conf file does not contain any records.

Environment

  • BIG-IP
  • Internal data group
  • External data group

Cause

Bug ID 759385: Records for an external data-group can be incorrectly managed

Recommended Actions

This procedure removes the internal data-group records that are incorrectly attached to an external data group.

Important: Do not forceload the system using K13030: Forcing the mcpd process to reload the BIG-IP configuration; this will result in data loss of internal data-group records.
  1. Complete a user configuration set (UCS) backup of the BIG-IP system.
    Note: The UCS backup will not contain internal data-group records.
     
  2. Compete a qkview of the BIG-IP system.
    Note: The QKView file will contain internal data-group records for reference, if needed.
     
  3. Locate external data groups that were modified with internal commands.
     
  4. To remove records added to external data groups, use the following syntax:
    tmsh modify ltm data-group internal <external dg name> records none
     
  5. To save the configuration, type the following command:
    tmsh save sys config

Additional Information

When you modify an external data group using an internal data-group record command, the internal data-group will be saved in the bigip.conf file with blank records. However, the running configuration will not be affected.

Contact F5 Support for assistance tracking down external data groups modified with internal commands commands.
