K1564: Configuring BIG-IP for compatibility with Microsoft Network Load Balancing

Topic

By default, BIG-IP's global auto_lasthop variable is enabled. This variable triggers BIG-IP to use the source MAC address as the destination MAC address and ignore the ARP table, which causes NLB to fail.

In the following example configuration, when the NLB server, nlb1, sends a packet to BIG-IP with the MAC address 02:01:c0:ff:ee, it then sends an Address Resolution Protocol (ARP) who-has request with the MAC address 02:bf:c0:ff:ee for the purpose of updating the BIG-IP's Ethernet destination to the cluster MAC address (rather than to the individual server's MAC address).

Once BIG-IP receives the ARP response from the destination, BIG-IP looks up the connection and finds the source MAC address for the nlb1 server is 02:01:c0:ff:ee, rather than the updated address of 02:bf:c0:ff:ee. This causes Microsoft's Network Load Balancing services to be ineffective.

Example configuration:

destination
|
bigip
|
+--nlb1 (02:b01:c0:ff:ee)
+--nlb2 (mac2)             > 02:bf:c0:ff:ee
+--nlb3 (mac3)            /

To resolve this issue, disable auto_lasthop, by typing the following command:

bigpipe global auto_lasthop disable

After you disable auto_lasthop, BIG-IP will use the updated MAC address from the ARP who-has request, rather than the source MAC address.

Important: Globally disabling auto_lasthop will affect how BIG-IP load balances any existing gateway devices (such as routers and firewalls). If you disable auto_lasthop, you must create the appropriate last hop pools. For specific information about configuring lasthop pools, refer to the BIG-IP Reference Guide.
