Known Issue

This is the result of a known issue. The stream profile is intended to support various special characters as delimiters to separate multiple search and replacement strings. However, in BIG-IP version 10.0.0 HF2, only the forward slash ( / ) character may be used as a delimiter.

In BIG-IP 10.0.0-HF2, a new configuration validation check introduced with CR115607 resulted in a change to the Stream expression syntax for multiple replacements. The new validation check was added to prevent invalid formatting of the Stream Source and Target fields which may cause TMM to crash. The check erroneously allows only sed-style syntax to support regular expressions in the Target field. Using this sed-style syntax, only the forward slash ( / ) character may be used as a delimiter. If other delimiters are used, the following error message is generated when the configuration is verified or loaded:

BIGpipe stream profile creation error:
01071048:3: Bad regular expression in stream profile name.

Note: For more information about configuring the Stream profile to perform multiple string replacements, refer to K7027: Replacing multiple strings using a Stream profile.

The BIG-IP functional specification defines the first character in the Target field of the Stream profile or Stream expression as the delimiter bounding each field for the replacement. The delimiter can be any one of the following characters:

Important: The delimiter must not appear anywhere else in the target string.

  • Period ( . )
  • Asterisk ( * )
  • Forward slash ( / )
  • Dash ( - )
  • Colon ( : )
  • Underscore ( _ )
  • Question mark ( ? )
  • Equals ( = )
  • At ( @ )
  • Comma ( , )
  • Ampersand ( & )

F5 Product Development tracked this issue as CR121384 and it was fixed in BIG-IP LTM version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by modifying your existing iRules and Stream profiles to use only the forward slash delimiter before applying HF2.

If your replacement expression includes a forward slash character, you must escape the replacement expression by prefixing it with two backslashes (\\). For example, the following expression will generate the error message:

@source/1@TARGET@ @source/2@TARGET@

Using forward slashes as delimiters (sed-style syntax), the following expression loads successfully:

/source\\/1/TARGET/ /source\\/2/TARGET/
