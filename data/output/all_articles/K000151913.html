K000151913: SR-IOV setup issue on VE deployed on VMware ESXi, VE becomes inoperable

Type
Support Solution
Published
2025-06-18
Updated
2025-06-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.0
Source
https://my.f5.com/manage/s/article/K000151913

Description

  • When Intel SR-IOV adapters are added to a BIG-IP Virtual Edition (VE) deployed on VMware ESXi, the VE may become inoperable. The Traffic Management Microkernel (tmm) process fails to start, repeatedly restarts, and generates core dumps with segmentation faults (SIGSEGV) in the clear_rx_cr function. System logs may display errors such as:

    iavf[0000:0b:00.0]: Failed to configure vsi queues
    xnet_lib [pci:0000:0b:00.0]: Error: Queue configuration failed
    xnet[0b:00.0]: Error: Command 2 failed: 1
    SIGSEGV Fault address: 0x10

  • Network interfaces associated with SR-IOV VFs may appear as uninit in interface status outputs.

Environment

  • Product: BIG-IP Virtual Edition (VE)
  • Version(s): 17.5.0 (may affect other versions)
  • Hypervisor: VMware ESXi (8.x)
  • Network Hardware/Driver: Intel E810 NICs using SR-IOV (icen driver)
  • Provisioned Modules: LTM, AFM
  • Configuration Detail: SR-IOV enabled and multiple VFs assigned to the VE

Cause

The issue is triggered by an outdated Intel E810 'icen' NIC driver on the ESXi host. When this driver is not current, the SR-IOV Virtual Functions cannot be properly initialized by BIG-IP VE, resulting in queue configuration failures and tmm process crashes (Bug ID1965549).

Recommendations

  1. Upgrade the Intel E810 'icen' NIC driver on your ESXi host to the latest supported version.
  2. Reboot the ESXi host after upgrading to ensure that the new driver is loaded.
  3. Verify that all assigned VFs are visible within BIG-IP VE and that tmm starts without error.
  4. Confirm network interfaces are initialized (show /net interface all-properties) and no further core dumps occur.
