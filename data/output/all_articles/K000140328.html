K000140328: Data to collect when oAuth Discovery not working.

Type
Support Solution
Published
2024-07-12
Updated
2024-07-15
Source
https://my.f5.com/manage/s/article/K000140328

Description

  • oAuth Token did not renew
  • JWK keys no match error
  • Invalid token
  • Error message: None of the configured JWK keys match the received JWT token

Environment

  • BIG-IP APM
  • oAuth Discovery not working
  • Token not updated

Cause

Undetermined

Recommended Actions

1. Please configure debug logging: Configure a log setting that has Per-Request Policy at least at Informational and Access Policy (apmd) at debug and oauth to Debug then attach that to the api protection configuration under the Access Control tab.

  •  Log into the BIG-IP and navigate to the APM Log Settings:
    •  "Access" > "Overview" > "Event Logs" > "Settings"
  •  Click the option on the top right for "Create" and use the following settings:
    • General Information
    •  Name: logs_CaseNumber
    •  Check the box for "Enable Access System Logs"
  •  Access System logs
    •  Access Policy:Set to "Debug"
    •  Oauth:Set to "Debug"
    •  Per Request:Set to "Informational"
  •   Access Profiles
    •  Select the Access Policy in question and click the left arrow to associate to the log profile.
    •  Click "OK"
      K45423041: Enabling APM Policy debug logging

2. Please enable restjavd logging to debug:
K15436: Configuring the verbosity for restjavad logs on the BIG-IP system

3. Please send me the output of the following command from both devices
   # restcurl /tm/access/oidc/discover

4. Please collect a Fiddler or httpwatch Capture while reproducing the issue. You can download Fiddler or httpwatch via the links below.
https://www.telerik.com/download/fiddler
https://www.httpwatch.com/download/

Within fiddler you will want to enable decryption: select Tools->Fiddler Options, and enable Decrypt HTTPS Traffic.
Configure Fiddler to Decrypt HTTPS Traffic
https://docs.telerik.com/fiddler/configure-fiddler/tasks/decrypthttps

When Capturing with httpwatch. Be sure to clear the cache and cookies prior to starting the capture as cached info will be of no use.
Open the HTTPWatch control panel and clear the cookies and cache in your browser by navigating to "Tools > Clear Cache and All Cookies" on the HTTPWatch toolbar.

5. Reproduce the trouble a couple of times making note of the following:

  • Time
  • Client IP
  • Session ID's.
  • Also lets make note of the Discovery Task State or Status. 

6. Generate a qkview
   # qkview -s0
K12878: Generating BIG-IP diagnostic data using the qkview utility

7. Collect a tar of /var/log. The following command from the command line will generated a tarball of logs in /var/tmp folder, i.e. /var/tmp/$HOSTNAME-logfiles.tar.gz.
   # tar -zcvf /var/tmp/$HOSTNAME-logfiles.tar.gz /var/log/*

8. Disable all debug logging enabled above.

9. Please upload the full logs via your support case or by uploading to or to securefiles.f5.com
K000138089: Security enhancements for F5 Secure Files
K000090853: Exchange files with F5 Support
K000138087: Give or receive access to a support case folder on Secure Files
