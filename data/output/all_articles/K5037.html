Topic

Note: For information about how to configure custom traps in BIG-IP version 9.x and later, refer to K3727: Configuring custom SNMP traps.

To add a custom SNMP trap, you must complete the following three procedures:

  • Locating the log message for which you would like to generate a trap
  • Determining which facility is associated with the log message and directing it to the trapper
  • Adding the Custom SNMP trap

Locating the log message for which you would like to generate a trap

  1. Log in to the command line.
  2. Change directories to the /var/log/ directory, by typing the following command:

    cd /var/log

  3. View the log files, by typing the following command:

    more <logfile>

  4. Replace <logfile> with the name of a log file. For example:

    more bigip

  5. When you find the log file that contains the message you wish to use, make note of the name of the log file and continue with Determining the facility and directing it to the trapper.

Determining which facility is associated with the log message and directing it to the trapper

  1. View the /etc/syslog.conf file, by typing the following command:

    more /etc/syslog.conf

    This command will return a number of lines in the following format:

    <facility>.<level> /var/log/<log file>

  2. Locate the facilities associated with the log file in which the message appears. There may be more than one facility that uses the log file. Make note of each facility.
  3. The /etc/syslog.conf file also contains a number of lines in the following format:

    <facility>.<level> /var/run/trapper

    Note: By default, the lines will appear near the end of the file.

  4. Locate any lines that match the facilities you noted in step 2 of this procedure.

    For example, if you are looking for the local0 facility, the line will appear as follows:

    local0.* /var/run/trapper

  5. Do one of the following:
    • If you locate the line, but it is prefixed with a hash mark (#), proceed to step 6.
    • If you do not find the line, proceed to step 11.
    • If you find the line in the correct format, go to Adding the Custom SNMP trap.
  6. Edit the /etc/syslog.conf file.
  7. Locate the line that begins with the hash mark.
  8. Remove the hash mark.
  9. Save the file and exit the editor.
  10. Edit the /etc/syslog.conf file.
  11. If applicable, go to the end of the file and add a new line in the following format:

    <facility>.* /var/run/trapper

    If you found more than one facility used by the log file, add an additional line for each facility in the format described above for each facility.

    For example, if you found that the log file uses the kern and local0 facilities, add the following lines at the end of the /etc/syslog.conf file:

    kern.* /var/run/trapper local0.* /var/run/trapper

  12. Save the file and exit the editor.

Adding the Custom SNMP trap

Before you can add an SNMP trap, you must add a new SNMP trap definition to the /etc/snmptrap.conf file. The SNMP definition options are described below:

  • OID

    The SNMP object ID that the new trap will use.

    F5 Networks recommends that you use traps in the range 1.3.6.1.4.1.3375.1.1.110.200 - 1.3.6.1.4.1.3375.1.1.110.999, in order to prevent conflict with official traps added by F5 in the future. For example, when you add your first custom SNMP trap, use OID 1.3.6.1.4.1.3375.1.1.110.200. When you add another SNMP trap, use 1.3.6.1.4.1.3375.1.1.110.201.
  • Regular Expression

    The regular expression that matches log file messages you wish to use to trigger traps. For example, to match the log message kernel: Pool test **added**, use the regular expression Pool.*added. This regular expression matches text that begins with Pool, ends with added, and contains any text in between.
  • Description

    The description that you want to be sent in the SNMP trap. For example, if you use the regular expression Pool.*added, a good description would be A new pool has been added.
  • Specific Problem

    This is an optional setting, used only with Nokia Netact. Use Specific Problem to define a unique code for the trap.
  • Perceived Severity

    This is an optional setting, used only with Nokia Netact. Use Perceived Severity to define the severity of the problem, based on the following table:
Value Severity 0 Unknown 1 Critical 2 Major 3 Minor 4 Warning 5 Clear
  • Error Type

    This is an optional setting, used only with Nokia Netact. Use Error Type to categorize the type of problem reported in the trap. The following table contains error types that are already configured:
    ValueError Type
    0Unknown
    2Communications
    3Environmental
    4Equipment
    10Processing
    11Quality of Service
  • Maps To

    This is an optional setting, used only with Nokia Netact. Use Maps To when referencing a higher level Specific Problem that is related to the Specific Problem reported in the trap.

Adding the SNMP trap definition and configuring a new trap

  1. Edit the /etc/snmptrap.conf file.

  2. At the end of the file, add the SNMP trap definition by inserting a new line in the following format:

    <OID> (<RegEx>) <Description> <SP> <PS> <ETY> <MT>

    Note: <SP>, <PS>, <ETY>, and <MT> are used only with Nokia Netact. If you do not use Nokia Netact, you may omit these options.

    For example, to add a new trap with the OID 1.3.6.1.4.1.3375.1.1.110.200, the Regular Expression Pool.*added, and the Description A new pool was added, add the following line:

    1.3.6.1.4.1.3375.1.1.110.200   (Pool.*added)   A new pool was added
  3. Save the file and exit the editor.
  4. Restart the snmpd process, by typing the following command:

    bigstart restart snmpd

The new SNMP trap is now configured.
