Known Issue

This is the result of a known issue. Beginning in BIG-IP ASM version 10.2.0, you can configure BIG-IP ASM to connect with an Internet Content Adaptation Protocol (ICAP) server to check requests for viruses.

You can configure the IP address and port of the destination ICAP server in the BIG-IP ASM Configuration utility; however, the URI is hard-coded and cannot be changed.

F5 Product Development is tracking this issue as ID 338760.
 
This issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP ASM version 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K6845: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

For information about F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

Workaround

You can work around this issue and configure an alternate URI on the target ICAP server by performing the following procedure:

  1. Install Hotfix-BIGIP-10.2.0-1789.0-HF2.
  2. Log on to the BIG-IP ASM command line.
  3. To specify the new URI, type the following command:

    /usr/share/ts/bin/add_del_internal add icap_uri <new_uri>

    For example, to specify the new URI of MY_REQMOD_URI, you would type the following command:

    /usr/share/ts/bin/add_del_internal add icap MY_REQMOD_URI

    With the ICAP URI parameter configured as in the above example, the IP address set to 10.10.10.1 through the Configuration utility, and antivirus checking enabled as detailed in the Configuration Guide for BIG-IP Application Security Manager, the BIG-IP ASM will now send appropriate requests to the following:

    icap://10.10.10.1/MY_REQMOD_URI
  4. Restart the BIG-IP ASM bd process by entering the following command:

    Important: This step will cause a brief traffic disruption.

    bigstart restart asm
