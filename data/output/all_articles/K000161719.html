K000161719: AS3 Application Deletion Fails with "Cannot delete referenced virtual address" When Using Shared Virtual Address Across Multiple Virtual Servers

  • F5 Application Services 3 Extension
  • F5 Modules for Ansible
Source

Description

  • Deleting an AS3 application or virtual server using a per-application DELETE request (e.g., DELETE /mgmt/shared/appsvcs/declare/<tenant>/applications/<app>) returns a HTTP 422 error with the message:

01070344:3: Cannot delete referenced virtual address /<partition>/<address>

  • This occurs when multiple virtual servers across different AS3 applications share the same virtual address, typically defined in a shared application. The error is logged in both /var/log/restnoded/restnoded.log and /var/log/ltm:

severe: [appsvcs] {"message":"Declaration failed: 01070344:3: Cannot delete referenced virtual address /<tenant>/<address>.","level":"error"}

err mcpd[<pid>]: 01070344:3: Cannot delete referenced virtual address /<tenant>/<address>.

Environment

  • Product: BIG-IP LTM with AS3 (Application Services 3 Extension)
  • BIG-IP Version: 17.5.1.6
  • AS3 Version: 3.57.0-8 (affected); 3.58.0-4 (fixed)
  • Configuration:
    •     Shared virtual address defined in a shared application
    •     Multiple virtual servers/applications referencing the same shared address
    •     AS3 creates traffic-matching-criteria (TMC) objects per virtual server, each pointing to the shared address
    •     Shared virtual addresses are auto-created from the address list entries with autoDelete: true
  • Automation: Ansible playbooks or direct AS3 REST API calls performing per-application deletions

Cause

  • A defect in AS3's per-application deletion logic caused it to attempt deletion of shared virtual addresses (auto-created from an address list with autoDelete: true) without first checking whether those addresses were still referenced by other applications' traffic-matching-criteria (TMC) objects.
  • When the delete was attempted, mcpd correctly blocked the deletion (since the address was still in use by another virtual server's TMC), resulting in the 01070344:3 error and a HTTP 422 response from AS3 — even though the target virtual server itself was successfully deleted.

Answer/Recommended Actions

  1. Upgrade AS3 to version 3.58.0-4 or later, which includes the fix for correct handling of shared virtual address deletion during per-application deletes.
  2. After upgrading, verify that per-application deletes succeed without triggering the referenced virtual address error.
  3. Continue to use a shared application for common virtual addresses and reference them using the "use" or "bigip" method as appropriate.

Additional Information

  • Despite the 422 error response, the target virtual server is successfully deleted. The error is generated because AS3 attempts to delete the underlying shared virtual address (which has autoDelete: true) after removing the virtual server and its associated TMC object — but mcpd blocks this deletion since the address is still referenced by another virtual server's TMC object. The shared virtual address itself remains intact and functional.
  • Workarounds such as setting autoDelete to false, always including the shared application block in every declaration, or using "use" vs. "bigip" reference methods do not resolve the issue.
  • When a virtual server uses an address list as its destination, AS3/BIG-IP creates a TMC object and auto-generates virtual address objects for each IP in the list. When one application is deleted, AS3's deletion logic triggers an attempt to remove these auto-generated virtual addresses without verifying whether other TMC objects (belonging to other applications) still reference them.
