Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP DNS deployment is configured with at least one BIG-IP server.
  • You want specific BIG-IP devices in your deployment to probe data center or server objects.
Description

The members of a DNS sync group dynamically determine the best BIG-IP device within the sync group configuration to use as the prober for the server or data center objects configured with Prober Preference set to Inside data center. Devices defined within the same data center as the probed object are preferred. If no local prober is available, a remote BIG-IP is delegated to be the prober of the server or data center objects. By default prober tasks are distributed in a round robin load balancing schema within each data center to the BIG-IP device that currently has the fewest probing tasks. This automatically distributes the prober load among all eligible devices.

Note: Prober Preference and Prober Fallback settings are available in BIG-IP DNS 13.0.0 and later.

Note: The term "BIG-IP device" may refer to a standalone BIG-IP device or a redundant HA (high availability) cluster.

You can configure BIG-IP DNS (formerly BIG-IP GTM) to use specific BIG-IP devices to probe data centers and servers through the use of prober pools.

The configuration of prober pools allows the grouping of specific BIG-IP devices for probing  of particular server or data center objects. You can then assign the prober pool to a server or data center object. Using a prober pool to monitor specific servers or data centers may be necessary where a firewall exists between some of the data center's BIG-IP systems and the monitored server or data center object. The prober pool can be populated with BIG-IP devices that are permitted through the firewall or are network adjacent and are able send and receive probes to the object without traversing the firewall.

Note: If the monitor probe type is "bigip"  or "bigip-link" (which simply takes the target status from mcpd), then there is only one big3d that can do this, which is the big3d running on the target device (or HA peers of that device).  For this type of monitor, prober-pools are not used or considered even if they are configured.

The intended use-case for a prober-pool is to force gtmd to select specific big3d agent(s) to run monitor types that are not bigip or bigip-link, for example in a situation where ICMP probes must originate from within the same data center, or from a specific location, in order to mark the target up.

Using a prober pool

When you assign a prober pool to a server or data center object, you specify which BIG-IP  systems monitor connectivity for that device. When you specify probing devices for the prober pool, F5 recommends that the BIG-IP device is a BIG-IP HA cluster, when possible. This style of configuration allows fault tolerance if one member of the HA pair becomes unavailable. The HA peer continues to perform probing for the given host, preventing the probing responsibility from being reassigned to another device.

If all configured prober pool BIG-IP devices become completely unavailable, the default behavior of BIG-IP DNS is to use the configured prober fallback (only available in BIG-IP DNS 13.0.0 and later) to probe the object until the configured prober pool members are available again. The Prober Fallback setting specifies the type of prober for the system to use to monitor the server resources when the preferred prober is not available.

Prober Fallback settings include the following:

  • Any Available uses any available prober.
  • Inside Data Center uses a prober inside the data center.
  • Outside Data Center uses a prober outside the data center.
  • Inherit From Data Center uses the prober assigned to the data center.
  • None uses no failback prober.
  • Specific Prober Pool provides a list from which you can select a prober pool.

Note: The default action for Prober Fallback is Any Available. If none of the BIG-IP devices in the prober pool or in the designated Prober Fallback selection are successful in probing the object, the probed object is marked down/unavailable.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have administrative access to the BIG-IP DNS systems.

Procedures

  • Creating a prober pool
  • Assigning a prober pool to an existing data center configuration
  • Assigning a prober pool to an existing server configuration

Creating a prober pool

The following procedure creates a new prober pool by adding configured BIG-IP server devices to the prober pool members:

Note: This procedure requires the BIG-IP DNS configuration to include BIG-IP server devices. If you do not have BIG-IP server devices configured as part of the BIG-IP DNS global server load balancing (GSLB) configuration, refer to the Integrating BIG-IP DNS Into a Network with BIG-IP LTM Systems chapter of the BIG-IP DNS Implementations manual. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Prober Pools > Prober Pool List.
  3. Click Create.
  4. Enter a prober pool name.
  5. For Load Balancing Method, click the method you want to use.  The load balancing methods work in the same manner as those used for WideIP pools.
  6. For Members, in the Available list, select the BIG-IP server device to add to the prober pool and move them to the Selected list.
  7. Click Finished.

Assigning a prober pool to an existing data center configuration

Impact of procedure: Performing the following procedure assigns the prober pool as the primary BIG-IP devices to monitor connectivity and gather statistics for server objects in the specified data center.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Data Centers.
  3. Click the name of the data center.

    Note: For versions earlier than BIG-IP DNS/GTM 13.0.0, skip steps 4 and 6 in this procedure.

  4. For Prober Preference, click Specific Prober Pool.
  5. For Prober Pool, click the name of the prober pool created in the previous procedure.
  6. For Prober Fallback, click the prober fallback method you want to use.
  7. Click Update.

Assigning a prober pool to an existing server configuration

Impact of procedure: Performing the following procedure assigns the prober pool as the primary BIG-IP devices to monitor connectivity and gather statistics for the specified server object.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Servers.
  3. Click the name of the server object.

    Note: For versions earlier than BIG-IP DNS/GTM 13.0.0, skip steps 4 and 6 in this procedure.

  4. For Prober Preference, click Specific Prober Pool.
  5. For Prober Pool, click the name of the prober pool created in the Creating a prober pool procedure.
  6. For Prober Fallback, click the prober fallback method you want to use.
  7. Click Update.
