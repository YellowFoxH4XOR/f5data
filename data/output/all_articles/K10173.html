K10173: Standalone VPN client disconnects if a user is assigned multiple Network Access resources

Known Issue

This is the result of a known issue. If a user runs the standalone VPN client in Simple Mode, FirePass may disconnect the user's session after the user connects. This issue occurs when all of the following conditions are met:

  • The Use Legacy Logon Prompt setting is enabled in the standalone VPN client
  • The user is assigned two or more Network Access connections
  • The user is assigned one or more Static Application Tunnels
 
When this issue occurs, an error message that appears similar to the following example may be reported:
 
Could not connect to remote server.
 
F5 Product Development is tracking this issue as CR104750 and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass release notes.
 
Additionally, this issue has been fixed in cumulative hotfix HF-603-3 issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
 
For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.
 
For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.
 
For a list of the latest hotfixes, refer to K10322: FirePass hotfix matrix.
 
Workaround
 
Users can work around this issue by running the standalone VPN client in Advanced Mode. To do so, users should select View >> Switch to Advanced Mode in the standalone VPN client.
