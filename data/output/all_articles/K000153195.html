K000153195: BGP Configuration Does Not Persist After Reboots

Type
Support Solution
Published
2025-08-28
Updated
2025-08-28
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000153195

Description

After license reactivations, upgrades, or reboots, any unsaved ZebOS configuration will be lost. The actual saved configuration is stored under config/zebos/rd0/ZebOS.conf.

The ZebOS running configuration is not automatically saved to disk unless the "write" command is explicitly issued in IMISH

example config: 

zebos -a cmd show running-config
=== route domain: 0 ===
!
no service password-encryption
!
log syslog
log file zebos.log
!
access-list 10 permit 0.0.0.0
!
bgp extended-asn-cap 
!
router bgp 3xx
 max-paths ebgp 2
 bgp log-neighbor-changes
 bgp graceful-restart restart-time 120
 network 11.11.11.0/24
 network 1.1.1.0/24
 <<<snip>>>


Saved config:config/zebos/rd0/ZebOS.conf shows network statement 1.1.1.0/24 missing

!
no service password-encryption
!
log syslog
log file zebos.log
!
access-list 10 permit 0.0.0.0
!
bgp extended-asn-cap 
!
router bgp 3xx
 max-paths ebgp 2
 bgp log-neighbor-changes
 bgp graceful-restart restart-time 120
 network 11.11.11.11/24
 <<<snip>>>


Environment

- BIG-IP LTM  
- BGP Configuration  
- Upgrade  
- IMISH

 

Cause

If changes are made in IMISH but not saved using the "write" command, they exist only in memory. These changes are lost after a reboot or upgrade.  


Recommended Actions

After making any changes in IMISH, always execute the command `write mem` to ensure configurations persist through reboots.
