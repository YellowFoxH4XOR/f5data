Description
The ecard_max_http_req_uri_len Application Security Module (ASM) setting can be adjusted to better meet the needs of your network. However, that brings about the question of what is the maximum setting that can be used.
Environment

  • ASM
  • Request logs
  • HTTP Protocol Compliance
  • The following message appears in the Security > Event Logs > Application > Requests under HTTP protocol compliance failed:
    Unparsable request content  - URL length: <URL> exceeded maximum limit of: 2048
  • You need to adjust the limit to meet the needs of your network.

Cause

  • The HTTP Request is greater than what has been set via the internal variable ecard_max_http_req_uri_len.
  • This is a global setting within the ASM module.

Recommended Actions
To properly set that limit consider the sizing that is needed in your environment.

  • The maximum value for the ecard_max_http_req_uri_len setting is 10000000 (bytes). However, we strongly recommend using an appropriate value of the internal parameter based on the expected traffic.

  • RFC7230 states the following:
    Various ad hoc limitations on request-line length are found in
    practice.  It is RECOMMENDED that all HTTP senders and recipients
    support, at a minimum, request-line lengths of 8000 octets.

  • Maximum URL length is 2,083 characters in Internet Explorer, but other browsers can support much longer URI lengths--even more than 64kB.
    Note: The above link brings you to a third party website not maintained by F5 Networks.

  • Follow K60450445: Configuring the maximum allowed URL length for an HTTP request to adjust the size of ecard_max_http_req_uri_len as needed to meet network requirements.

Additional Information
There can be an impact on memory and CPU when this variable is increased that will effect all ASM policies on the BIG-IP. This could also lead to a memory resource issue.
