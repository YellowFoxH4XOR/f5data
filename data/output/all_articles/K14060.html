Known Issue

The BIG-IP ASM system may report an error during the ASM Learning process. This issue occurs when all of the following conditions are met:

  • The ASM system is performing the ASM Learning either during automatic policy building or manual traffic learning.
  • The learning_manager process is using large amounts of CPU resources.

This issue occurs because the nwd process calculates the CPU usage without considering the number of CPUs on the system. As a result, the nwd process incorrectly determines that the learning_manager process has breached the CPU threshold, and triggers the ASM system to falsely report the error.

The nwd process monitors all other BIG-IP ASM system processes and attempts to restart them if they fail.

Impact

You can safely ignore the error message.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H380110 on the Diagnostics > Identified > Low screen.
  • The BIG-IP ASM system reports a certain error message to the /var/log/asm file. For example:

    01310027:2: ASM subsystem error (nwd.pl,F5::Logger::error): failed to verify: Can't use string ("1") as a HASH ref while "strict refs" in use at /usr/lib/perl5/site_perl/F5/NwdUtils/Nwd.pm line 187.

  • The nwd process may log a certain message to the /var/log/ts/nwd.log file. For example:

    /usr/share/ts/bin/nwd.pl,F5::NwdUtils::Nwd::verify,,learning_manager.pl: pid 7948 has CPU 364, exceeding cpu threshold(100) !
