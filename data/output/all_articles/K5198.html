K5198: The 3-DNS virtual server auto-discovery feature will not import virtual servers that are assigned to the loop back adapter

Type
Knowledge
Published
2007-01-13
Updated
2023-02-21
Status
Legacy Content
Applies to
  • Legacy Products
  • 3-DNS: 4.6.4
Source
https://my.f5.com/manage/s/article/K5198

Topic

When the virtual server auto-discovery feature is enabled on a 3-DNS system, the 3-DNS automatically collects all of the virtual server information from a BIG-IP system. In the event that the BIG-IP system has a virtual server configured on a subnet with no corresponding self IP addresses configured on the same subnet, the virtual server address will be assigned to a loopback address, such as 127.X.X.X. When this occurs, the BIG-IP system will not communicate the status of virtual servers on the loopback interface. The 3-DNS virtual server auto-discovery feature will not populate these virtual servers on the 3-DNS system. Additionally, if the virtual servers are added manually, iQuery will not communicate status of the virtual servers.

This behavior is by design.

You can work around this behavior by assigning an IP address from the same subnet as the virtual servers that reside on the loop back adapter, to the VLAN that will handle the traffic for the virtual servers. By doing so, the 3-DNS populates the virtual servers using the auto-discovery feature and allows iQuery to report the status of the virtual servers.
