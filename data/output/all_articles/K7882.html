K7882: Deflate incorrectly unchunks a response causing the connection to hang

Type
Known Issue
Published
2008-05-09
Updated
2023-02-21
Status
Legacy Content
Applies to
  • BIG-IP
  • BIG-IP LTM: 9.4.1, 9.4.0
Source

Known Issue

This is the result of a known issue. When the HTTP profile is configured with Compression enabled and Response Chunking set to selective, the response is unchunked before it is determined whether the content matches the requirements specified in URI Compression or Content Compression to be compressed. When the content is unchunked but determined that it cannot be compressed, the connection may stall. This issue specifically occurs when the content does not contain a Connection header or Connection: Keep-Alive header, because the response is returned correctly to the client but the connection never closes, due to the client not knowing the entire response has been received. The connection stays open on both the server and client side until the server times out and the BIG-IP system times out the idle connection.

F5 Product Development tracked this issue as CR80637, and it was fixed in BIG-IP LTM 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by disabling compression within the HTTP profile when the server is chunking data to prevent the BIG-IP from incorrectly unchunking data before it is checked against the compression rules specified.
