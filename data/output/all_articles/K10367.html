Known Issue

This is the result of a known issue. Gratuitous ARP replies sent from a node in response to BIG-IP ARP requests are dropped by the BIG-IP system and the BIG-IP ARP table is not updated.

Note: RFC2002: IP Mobility Support specifies the following:

A gratuitous ARP MAY use either an ARP Request or an ARP Reply packet. Any node receiving any ARP packet (Request or Reply) MUST update its local ARP cache with the Sender Protocol and Hardware Addresses in the ARP packet, if the receiving node has an entry for that IP address already in its ARP cache.

This issue may cause the BIG-IP monitor to mark the node down until the ARP entry is updated. The node will most likely respond with a unicast ARP reply, which results in the BIG-IP system updating its ARP table entry for the node.

F5 Product Development tracked this issue as CR121795 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator, or WAN Optimization release notes.
