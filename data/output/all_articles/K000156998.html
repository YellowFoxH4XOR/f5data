K000156998: WebSocket compression only on client side

Type
Support Solution
Published
2025-10-13
Updated
2025-10-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000156998

Description

When configuring BIG-IP LTM to enforce WebSocket compression only on the clientside (between BIG-IP and client), the server may still receive compressed messages. Standard WebSocket profile configuration does not allow independent control of compression for clientside and serverside connections. Attempts to use a single profile with compression enabled result in both clientside and serverside traffic being compressed if the permessage-deflate extension is negotiated.

Environment

  • WebSocket profile with compression enabled
  • Attempted use of separate profiles for clientside and serverside

Cause

The inability to independently enforce WebSocket compression on only the clientside is due to a product limitation addressed by Bug ID 1756697. Without the Engineering Hotfix (EHF) for this bug, BIG-IP cannot decouple compression negotiation between clientside and serverside connections.

Recommended Actions

  • To enable independent compression control for clientside and serverside WebSocket connections, request and apply the EHF for Bug ID 1756697 to BIG-IP version 17.5.1.2 (latest available).
  • After applying the EHF, configure two separate WebSocket profiles:
    • One profile for the clientside with compression enabled and set to end-to-end.
    • Another profile for the serverside with compression disabled and set to end-to-end.
