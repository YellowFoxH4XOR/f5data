Known Issue

An ARX system experiencing high memory utilization may unexpectedly issue a watchdog reboot and reload the active ARX switch.

This issue occurs when the following conditions are met:

  • You are running an ARX 4000.
  • The system is using 90 percent or more of its memory.

The reboot is caused by the system delaying an integral ARX component in updating a watchdog process, which causes the ARX watchdog process to proclaim the interfaces as down. When all of the ARX interfaces are marked down, the active device can no longer communicate to the quorum disk or the peer device. This communication breakdown causes the ARX system to issue a reload.

Impact

ARX services are unavailable until the failover completes.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • All ARX interfaces are marked as offline.
  • The ARX system unexpectedly reboots.
  • You see a string of error messages in the ARX procdat that appear similar to the following example:

    L2SW_DRV-0-DBG-MSG7::phy_fe_ge_link_get: Warning, PHY is held-in-reset? Regs=0xFFFF. myslot=2

    L2SW_DRV-0-DBG-MSG7::_soc_link_update: link=0x1f1fe000 m1=0x1f1fff3f m2=0x1f1fff3f pbm=0x1f1fe000

    L2SW_DRV-0-DBG-MSG7::_soc_link_update: Update !scm done, pbm=0x1f1fe000. myslot=2

    L2SW_DRV-0-DBG-MSG7::mac_ge_enable_set: port=12, enable=0, phyreset=0, myslot=2

    L2SW_DRV-0-DBG-MSG7::soc_drain_cells: Complete, due to link down (2/12)

    L2SW_DRV-0-DBG-MSG7:: **Port 12: link down [slotnum=2,unit=0]

    L2SW_DRV-0-DBG-MSG7:: SendIPC Link Down Event for slot 2 and port 13

    L2SW_LVL7-0-DBG-MSG7::Received Link status for slot 2 and port 13

    L2SW_LVL7-0-NOTE-MSG5::Link is down on slot 2 port 13.

    L2SW_LVL7-0-INFO-MSG6::Logging Link Transition Info done

    L2SW_LVL7-0-DBG-MSG7::afn_l7_flush_intf: ENTRY. unit=1, slot=1, port=12

    L2SW_DRV-0-DBG-MSG7::bcm_ipc_flush_fwdtbl_set_1_svc: Entry. slotNum=2,portNum=13. myslot=2

    L2SW_DRV-0-DBG-MSG7::afn_l2MgrFwdDbFlush_3: ENTRY. lagIdx=1, myslot=2

Note: The procdat log file is included in an ARX system diagnostic information file. The procdat log file is located in the /acopia/var/log directory of the diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Technical Support.
