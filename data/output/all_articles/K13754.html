Topic

You should consider using this procedure under the following condition:

  • You want to configure a trunk with redundant interfaces across VIPRION blades.

Description

In order to make use of the redundant capabilities of a multi-blade VIPRION system, network trunks should be cabled and configured to use interfaces across all available blades. In such a configuration, if one blade or interface fails, the trunk can remain available by using the interfaces on the remaining active blades.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have a VIPRION chassis with at least two blades.
  • You have a peer switch that is configured with a trunk that includes one interface from each VIPRION blade, and cabled to the appropriate VIPRION interfaces.

Procedures

Creating a trunk that spans multiple blades

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Trunks.
  3. Click Create.
  4. Enter a Name for the trunk.
  5. Select an appropriate interface from the first blade.

    For example:

    1/1.1
  6. Add the interface to the trunk by clicking <<.
  7. Select an additional interface, from a different blade.

    For example:

    2/1.1
  8. Repeat step 7 as necessary for each blade and interface that is configured and cabled on the switch to be part of the trunk.
  9. If the peer switch is configured to use Link Aggregation Control Protocol (LACP), you should enable the LACP option.
  10. Click Finished.

A trunk correctly configured for redundancy across blades would have a configuration that appears similar to the following example:

net trunk Example_Trunk {
interfaces {
1/1.1
2/1.1
3/1.1
4/1.1
}
}

After the trunk is created, you must create a Virtual Local Area Network (VLAN) that references the trunk, or assign the trunk to an appropriate existing VLAN.
