Description

  • I want to know if I should manually enter the ACME challenge records in your DNS zone.
  • I want to know what an ACME challenge is

Environment

  • F5® Distributed Cloud WAF
  • LetsEncrypt
  • HTTP Load Balancer (LB)

Cause

Our servers use "challenges," as defined by the ACME standard, to verify that the domain names included in a certificate you receive from Let us Encrypt belong to you. When you enable the wildcard SSL/TLS certificate for a domain, the _acme-challenge.mydomain DNS record is utilized. Using a challenge based on DNS, the system that converts domain names like www.f5.com into IP addresses, users will be able to demonstrate authority over a domain and obtain wildcard certificates from Let us Encrypt.

Changing a domain's DNS records is the best approach to demonstrate ownership from the standpoint of a Certificate Authority (CA) like Let us Encrypt, since controlling a domain is at the heart of DNS. So, what is the deal? Users can use ACME client software, such as Certbot, that supports the DNS challenge type to obtain a certificate from a CA in the DNS challenge. As part of the certificate request process, the CA may request that the client verify domain ownership by inserting a certain CNAME record into the client's DNS zone.

To be more precise, the CA offers the ACME client a one-of-a-kind random token, and whomever is in charge of the domain should add this text record to its DNS zone, specifically to the preset record called "_acme-challenge" under the user's actual domain name. To illustrate, "_acme-subdomain.f5.com" would be the validation subdomain for the *.f5.com domain. Upon adding the token value to the DNS zone, the client instructs the CA to validate the challenge. Subsequently, the CA will do a DNS query to locate the domain's authoritative servers.

Recommended Actions

The process of issuing certificates can proceed if the authoritative DNS servers respond with a DNS record that includes the right challenge token, proving control of the domain.

The Standard ACME Flow: This is the process that an ACME client would follow to ask a CA for an X.509 certificate:

1. After registering with an ACME CA server, the ACME client can place a request for a certificate. One way to look at an ACME account is as a repository for an individual client's open certificate requests. A series of challenges are issued by the CA in response. In order to finish the tasks, the client needs to show that it owns the domain names, IP addresses, or hardware device IDs that it is requesting in the certificate.

2. The CA checks the answers the client gave to the challenges.

3. A certificate signing request (CSR) is sent to the CA by the client once it has successfully completed the ACME challenges. Before approving a certificate request, the CA checks that the client is the only one with access to the private key.

4. The client receives a certificate from the CA.

 

DNS-01: The DNS Challenge For this particular domain, the ACME CA is challenging the client to create an arbitrary DNS CNAME record. By looking up the CNAME record in DNS, it confirms the challenge.

Delegated Domains vs Non-Delegated Domains. What you have to know.

  • Using Delegated Domains (F5 Primary DNS Zone):

    • F5 Distributed Cloud acts as the authoritative domain server, you must be pointing your DNS records to:
      ns1.f5clouddns.com
      ns2.f5clouddns.com
    • LB DNS records are automatically updated/managed if you enable the option "Allow Application Load Balancer Managed Records"  
    • In this scenario you would not need to manually manage ACME DNS records.

  • Using Non-Delegated Domains (Outside of F5 DNS):

    • You have to create 2 DNS records on your side:
      • A CNAME record for the ACME challenge provided by Let's Encrypt. (_acme-challenge.DOMAIN)
      • A CNAME record for the domain itself (see the example in the following paragraph with the domain "demo.f5lab.com) 
    • Once the initial configuration is ACME is done, there is no need for you to continuously update DNS records, it will auto-renew.

Your expected actions for Non-Delegated Domains:

Create a CNAME record for _acme-challenge.demo.f5lab.com with the value provided by F5 Distributed Cloud that you will find in the end of the HTTP Load Balancer configuration. It should look like:

_acme-challenge.demo CNAME XXXXXXXXXXXXXXXXXXXXX.autocerts.ves.volterra.io

Create another CNAME record for the domain demo.f5lab.com and the Host Name that you can also find in the section "Host Name" of the HTTP Load Balancer configuration. It should look like: 

    demo CNAME ves-io-XXXXXXXXXXXXXXXXXXXXX.ac.vh.ves.io

    Note: Distributed Cloud Services has deprecated the Delegated Domain capability, which means that new domains will need to be setup as a Primary DNS zone corresponding to your HTTP Load Balancer  and you must check the Allow HTTP Load Balancer Managed Records checkbox for the HTTP Load Balancer to work properly.

    (Location: Home > Dns Management > Manage > Dns Zone Management)

     

    Additional Information

    DNS Delegation, also known as DNS Zone Delegation, is the practice of giving many DNS servers control over a domain or subdomain in order to maintain records up to date. Recursively resolving the CNAME target or responding with a referral is how the zone's designated authoritative DNS server handles DNS requests. An organization can have additional control over the enabling and disabling of services, such mail exchange, hosted on a subdomain by assigning control over the subdomain to a different DNS server.

    In October 2023, the XC Delegated Domains feature was deactivated. Using Primary DNS in conjunction with the option to have your HTTP load balancer handle your DNS records is now the alternative to Domain Delegation.

    Why CNAME instead of TXT?
    A more automated, scalable, and managed alternative than manually establishing and updating TXT records is offered by using CNAME records to assign the ACME challenge response to F5 Distributed Cloud. It makes sure that, in order to issue and renew certificates, the domain validation procedure is completed quickly and with as little human participation as possible.
