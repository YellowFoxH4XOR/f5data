Known Issue

This is the result of a known issue. The Negative RegExp Policy: Server side code discloser 1 incorrectly flags XML output that has a properly formatted header as a violation. Negative RegExp is a type of built-in parameter that is included with the BIG-IP ASM system. Server side-code discloser 1 is one of three parameters available in the Negative RegExp policy.

The Negative RegExp policy was designed to catch and prevent PHP code from being disclosed. The following examples are PHP code tags designed to hide the information they contain:

  • <? ?>
  • <?php ?>
  • <?= ?>

Unfortunately, the Negative RegExp Policy: Server side code discloser 1 also captures properly formatted XML tags, <?xml ?>, flagging the XML as a violation. The following example XML header line is flagged as an XML violation:

<?xml version="1.0" encoding="utf-8"?>

Note: .Net configuration files also include the above header line, thus Server side code disclosure 1 will also block an attacker from downloading any configuration file that has been renamed or is accidentally exposed by the application.

Depending upon your configuration, it may be necessary to send responses that contain the <?xml?> header, triggering a violation. You must make the decision to include <?xml?> headers based on a risk assessment of your own application against the responses that this Negative Regular Expression (Negative RegExp) will catch.

F5 Product Development tracked this issue as CR74720 and was it fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP ASM release notes.

Workaround

You can perform one of the following workarounds, depending upon which procedure suits your security policy and the applications on which you want to preserve the highest level of security:

  • Creating a custom Negative RegExp
  • Removing the Negative RegExp Policy: Server-side code disclosure 1 from your policy
  • Disabling response checking for the relevant object type Direct requests for a specific resource to a separate ASM policy that has Check Response disabled
  • Directing requests for a specific resource to a separate ASM policy that has Check Response disabled

Creating a custom Negative RegExp

You can create a custom Negative RegExp that has been tuned to trigger only on PHP delimiters, and will not trigger on XML data (including .Net configuration files).

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Select Application Security.
  3. Click Options.
  4. Select RegExp Pool.
  5. Click Create.
  6. Enter a RegExp name.

    For example:

    Server side code disclosure (php)
  7. Enter the following text into the RegExp field:

    Important: Line breaks have been added to the following text to preserve page continuity. As such, you must remove line breaks when pasting into the RegExp field for this workaround.

    (?si)(?:\<|(?:%(?:25)?)(?:(?:%3)?3)(?:c|%[46]3))(?:\?|(?:%(?:25)?)(?:(?:%3)?3)(?:f|%[46]6))(?:(?:p|(?:%(?:25)?)(?:(?:%3)?[57])(?:(?:%3)?0))(?:h|(?:%(?:25)?)(?:(?:%3)?[46])(?:(?:%3)?8))(?:p|(?:%(?:25)?)(?:(?:%3)?[57])(?:(?:%3)?0))|(?:\=|(?:%(?:25)?)(?:(?:%3)?3)(?:d|%[46]4)))?((?!((?:x|(?:%(?:25)?)(?:(?:%3)?[57])(?:(?:%3)?8))(?:m|(?:%(?:25)?)(?:(?:%3)?[46])(?:(?:%3)?d))(?:l|(?:%(?:25)?)(?:(?:%3)?[46])(?:(?:%3)?c)))).)*(?:\?|(?:%(?:25)?)(?:(?:%3)?3)(?:f|%[46]6))(?:\>|(?:%(?:25)?)(?:(?:%3)?3)(?:e|%[46]5))

    Note: As an optional step, you can enter a description of the RegExp you entered.

  8. Click Save.
  9. Depending upon which BIG-IP ASM version you have installed, perform the following steps:

    BIG-IP ASM 9.2.x and 9.3.x:

    • Return to your Policy, then click the Negative RegExp Defaults tab.
    • Click Create.

    BIG-IP ASM 9.4.0 through 9.4.1:

    • Click the Policy Properties tab and then click Edit next to Negative RegExp.
    • Then click Add.
  10. From the RegExp Name menu, select the RegExp you created above.
  11. From the Apply menu, select Response.
  12. If you have BIG-IP ASM 9.2.x or 9.3.x, click Create. If you have BIG-IP ASM 9.4.0 through 9.4.1, click Add.
  13. Browse the RegExp list to find the existing Server side code disclosure 1 entry and select the check box next to the entry.
  14. Click Remove.

Removing the Negative RegExp Policy: Server-side code disclosure 1 from your policy

Note: Perform this procedure only if you are not concerned with exposing PHP or XML to the client.

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Select Web Applications.
  3. Select your Webapps Active Policy.
  4. Click Negative RegExp Edit.
  5. Enter Server side in the Search box.
  6. Click Go.
  7. Select the check box next to Server side code disclosure 1.
  8. Click Remove.
  9. Return to the Web Application.
  10. Click Set Active Policy.

Disabling response checking for the relevant object type

Note: After performing this procedure, no Negative RegExp will be applied to the responses generated by the selected object type.

  1. Select Web Applications.
  2. Select your WebApps Active Policy.
  3. Select Object Types.

    Note: If it has not already been created, you may need to create an object type for which you want to bypass.

  4. Clear the Check Response box for this object type.

Directing requests for a specific resource to a separate ASM policy that has Check Response disabled

  1. Create a new HTTPClass and assign it as the first class in the list on your virtual server.
  2. Ensure that the last HTTPClass against your VIP is a catch all class with no filters defined, so that no requests can bypass the BIG-IP ASM.
  3. Create a new policy against your new HTTPClass, ensuring that Check Response is turned off against the object type.
