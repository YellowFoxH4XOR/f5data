Description

DNS queries return NXDOMAIN or time out, even though the records exist as wideip's

Environment

  • Product: BIG-IP DNS (GTM)
  • Configuration:
    • GTM pool with load-balancing-mode return-to-dns
    • Global setting: failure-rcode nxdomain and failure-rcode-response enabled

    Cause

    When a GTM pool is configured with load-balancing-mode return-to-dns and global settings include failure-rcode-response enabled with failure-rcode nxdomain, any load-balancing failure—including those triggered by return-to-dns mode—results in an NXDOMAIN response, even if valid DNS records are present in DNS Express or Zonerunner.

    Recommended Actions

    • Review the GTM pool's load-balancing-mode. Using return-to-dns can trigger load-balancing failures that result in NXDOMAIN responses when combined with current global settings.
    gtm pool a /Common/wideip.example.com-pool {
    fallback-mode none
    load-balancing-mode return-to-dns
    members {
        /Common/server1:/Common/example_vs {
            member-order 1
        }
        /Common/server2:/Common/example_vs {
            member-order 0
        }
    }
}
    • To prevent undesired NXDOMAIN responses:
      • Change the pool's load-balancing-mode to one that does not trigger a load-balancing failure for valid records.
      • Alternatively, adjust global settings for failure-rcode-response or modify the value of failure-rcode to avoid returning NXDOMAIN in these scenarios.
    gtm global-settings load-balancing {
    failure-rcode nxdomain
    failure-rcode-response enabled
}
    • Ensure that your intended DNS response behavior matches your configured load-balancing and failure response policies.
