Description

Excessive DNS responses may be an indication of an attack to a DNS service. DNS queries may be sent for Non-Existent domains or resource records and DNS services are forced to process and provide a DNS response for these potentially bogus DNS requests. As a result, this consumes compute resources on DNS servers and network link capacity. UDP based DNS requests/queries and responses can be spoofed. DNS responses may also be unsolicited. DNS Response Flood Attack can be mitigated with BIG-IP AFM DNS Response Flood attack type configuration. BIG-IP AFM DNS Response Flood attack type can be configured in BIG-IP AFM DoS Protection Device Protection. DNS Response Flood attack type configuration is not available in BIG-IP AFM DoS Protection Protection Profiles.

Environment

BIG-IP AFM provisioned
BIG-IP AFM DoS Protection Device Protection

Cause

DNS Response Flood Attack

​​​​Recommended Actions

In BIG-IP Configuration Utility, navigate to Security  ››  DoS Protection : Device Protection, set DNS Response Flood Attack to Mitigate.
Set a Threshold mode per your organizations needs.
If Fully Manual Threshold mode is used, set Detection and Mitigation threshold values per your organizations needs.
Note: These thresholds will apply to all DNS responses that BIG-IP system will observe.  
 

Additional Information

DNS Response Flood Attack type is set to Fully Manual threshold mode and Mitigate by default in BIG-IP AFM Device Protection configuration.
The default Detection Threshold in Fully Manual mode is 10000 EPS (Events per Second). The default Mitigation threshold is set to Infinite. Therefore, DNS Response Flood Attack type will detect an attack, but will not mitigate. 
The Detection and Mitigation threshold values are applied per TMM. For example, when one of the BIG-IP TMM processes detects 10000 EPS of DNS responses, BIg-IP AFM will consider this event an Attack and will log in /var/log/ltm with an "attack start detected"

 err tmm1[22282]: 01010252:3: A DOS attack start was detected for vector DNS Response Flood, Attack ID <attack ID>

As needed, "Only Count Suspicious Events" can be enabled to consider only suspicious events - unsolicited packets .

Only Count Suspicious Events
Specifies that only suspicious events (i.e., unsolicited packets) are considered and counted.
Bad Actor Detection and Attacked Destination Detection options can also be enabled per your organizations needs, see K49869231: Denial of Service | BIG-IP AFM operations guide
