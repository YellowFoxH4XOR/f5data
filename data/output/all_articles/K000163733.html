K000163733: F5OS-C VELOS: Investigating High Partition Shared-Volume Utilization

Type
Support Solution
Published
2026-10-15
Updated
2026-10-15
Applies to
  • F5OS Products
  • F5OS-C: 1.8.X, 1.8.2, 1.8.1, 1.8.0
Source
https://my.f5.com/manage/s/article/K000163733

Description

A VELOS system may generate an alarm indicating that a partition's shared-volume utilization is growing rapidly. An example alarm is:

Partition-1 shared volume utilization growth rate is high

The alarm identifies the affected partition resource but does not identify the files consuming the storage. The partition shared volume stores diagnostic data, including QKViews, packet captures, and core files.

Important: The partition shared volume is separate from the tenant-image volume.

Environment

  • F5OS-C on a VELOS system
  • F5OS chassis partitions
  • Partition shared-volume storage
  • System-controller and partition management CLIs
  • SNMP monitoring of controller and partition storage

Cause

A full or nearly full shared partition can impair diagnostic-data collection. Insufficient disk space may also contribute to unexpected system behavior. The alarm should therefore be investigated, but diagnostic files must not be deleted indiscriminately.

Answer/Recommended Actions

1. Identify the affected partition and controller

  1. Log in to the VELOS system-controller CLI using an account with administrator access.
  2. In operational mode, run:
show system alarms
show partitions
show partitions volumes

Record the following information:

  • The exact alarm text and affected controller resource
  • The alarm creation time
  • The partition name associated with the affected partition ID
  • The partition ID
  • The controller that is running-active for the partition
  • The TOTAL SIZE and AVAILABLE SIZE of the shared volume on both controllers
Warning: Do not assume that the configured partition name is partition1. The partition's running-active controller may also differ from the chassis-active controller.

2. Inventory diagnostic files

Connect to the affected chassis partition's F5OS management CLI and run the following commands in operational mode:

system diagnostics qkview list
system diagnostics qkview status
file list path diags/shared/
file list path diags/shared/qkview/
system diagnostics core-files list

Review the returned filenames, dates, sizes, and controller locations. Confirm which controller holds each file before taking any cleanup action.

3. Preserve required diagnostic files

Before deleting any file:

  • Download diagnostic files that must be retained.
  • Do not delete a QKView while it is being collected.
  • Do not delete files required for an active troubleshooting investigation.
  • Do not delete files whose purpose or retention requirement is unknown.

To download a retained QKView through the partition web interface:

  1. Open SYSTEM SETTINGS → File Utilities.
  2. Navigate to diags/shared → qkview.
  3. Select the required QKView.
  4. Click Download.

For core files, retain the files until F5 Technical Support determines that they are unnecessary or analysis of the related issue is complete.

4. Delete only specifically identified, unnecessary files

Delete files only after confirming that they are no longer required for troubleshooting, auditing, or support analysis.

Delete a selected QKView

From the affected partition's operational CLI, use the exact filename returned by the QKView inventory:

system diagnostics qkview delete filename <filename>

If the file is located on another controller, use the controller-qualified filename when returned by the inventory. For example:

system diagnostics qkview delete filename controller-2:<filename>

Use the controller where the file actually resides.

Delete a selected core file

Use the complete identifier returned by the core-file inventory:

system diagnostics core-files delete files { <exact-entry-returned-by-list> }

The identifier includes the controller, path, and filename. Use the exact entry returned by system diagnostics core-files list. Do not construct a replacement path or remove the controller prefix.

Warning: Do not use wildcards, bulk filesystem cleanup, or manually constructed paths. If the space-consuming files cannot be identified safely, stop and contact F5 Support.

5. Verify the result

Return to the system-controller CLI and run:

show partitions volumes
show system alarms

Compare the affected partition's shared-volume rows on both controllers. Successful cleanup should:

  • Increase AVAILABLE SIZE
  • Leave TOTAL SIZE unchanged
  • Reduce the amount of retained diagnostic data

Review the alarm state separately. Freeing space does not by itself prove that the alarm has cleared or that continued storage growth has stopped.

Do Not Delete

  • Files required for an active F5 Support investigation
  • A QKView that is currently being collected
  • Files whose purpose or retention requirement is unknown
  • The tenant-image volume contents to resolve a shared-volume alarm
  • Chassis-controller images or partition ISO images for this purpose
  • Files using wildcard or bulk filesystem deletion commands

Additional Information

If the cause cannot be identified or safe cleanup cannot be determined, provide F5 Support with:

  • show system alarms output
  • show partitions output
  • show partitions volumes output
  • QKView inventory output
  • Shared-directory file listings
  • Core-file inventory output
  • The controller associated with each space-consuming file
  • The status of any active diagnostic collection
