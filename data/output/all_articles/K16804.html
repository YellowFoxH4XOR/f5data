Known Issue

The BIG-IP APM Network Access tunnel may fail to establish when you configure the Route Domain and SNAT Selection action.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM Network Access tunnel to use a secure network address translation (SNAT) pool.
  • You have configured the SNAT configuration for the Route Domain and SNAT Selection action in the visual policy editor as snatpool.

Impact

The BIG-IP APM Network Access tunnel fails to establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe error messages that appear similar to the following example:

    Initializing and Disconnected "Failed to Download configuration"

  • In the /var/log/ltm file, you observe an error message that appears similar to the following example:

    err tmm2[15357]: 01470000:3: iSession: Connection error: isession_handle_syn:7320: No peer:4

Workaround

To work around this issue, you can configure the SNAT configuration of the Route Domain and SNAT Selection action in the visual policy editor to use automap instead of snatpool. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Profiles > Access Profile List.
  3. To open the visual policy editor, click the Edit link to the right of the affected Access Profile.
  4. Click Route Domain and SNAT Selection.
  5. In the Properties tab, for SNAT, select automap.
  6. Click Save.
  7. In the upper-left corner of the visual policy editor, click Apply Access Policy.
  8. To exit the editor, click Close in the upper-right corner of the visual policy editor.
