Description

NTLM authentication with APM can fail when connecting with Chrome starting with version 85.x. When connecting for the first time to your VS with an APM policy, you get a "Connection Timeout" in the browser.

Environment

  • BIG-IP APM
  • NTLM authentication is configured in your APM policy
  • Beginning with Chrome version 85.x

Cause

The issue stems from a Chrome browser behavior where it sends the request headers first then posts body request data. APM responds with 401 after it receives the request headers, as expected, and the receipt of the post body after, this stalls NTLM as it expects the next request to contain authentication headers.

Recommended Actions

Use an iRule to pause post request from Chrome browser. For example:
when HTTP_REQUEST {
  if { [string tolower [HTTP::header User-Agent]] contains "chrome" && [string tolower [HTTP::method]] eq "post" && [HTTP::uri] eq "/saml/idp/profile/test/sso" } {
    #log local0. "Brief pause in milliseconds for BIG-IP to wait for Chrome to send the post body"
    after 10
  }
}
Note: In the above iRule,  the delay is set to 10 ms. If the solution requires more increment by 10, up to 1000 (1 second).
