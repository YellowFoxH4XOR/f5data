Description

You had experienced a disk-fill event for the /var filesystem. After solving this you tried to check the system configuration and run a tmsh load sys config verify in tmsh shell but notice that it takes a long time to complete (~1-2 minutes). Whilst this is running, you notice that the Web GUI hangs and becomes inaccessible.

At the same time as running the above command, entries similar to the following can be seen in /var/log/ltm:

May 21 12:27:56 bigip1.localdomain notice mcpd[4999]: 0107165d:5: init_system_epsec_software_status: EPSEC:: loading of Epsec software status start
May 21 12:28:50 bigip1.localdomain warning snmpd[13878]: 010e0004:4: MCPD query response exceeding 30 seconds.
May 21 12:29:20 bigip1.localdomain warning snmpd[13878]: 010e0004:4: MCPD query response exceeding 60 seconds.
May 21 12:29:50 bigip1.localdomain warning snmpd[13878]: 010e0004:4: MCPD query response exceeding 90 seconds.

Environment

  • BIG-IP
  • Web GUI
  • Disk space
  • EPSEC rpm database

Cause

When /var fills-up, the EPSEC rpm database can become corrupted.

Recommended Actions

Rebuild the rpm database with the following bash commands:

rm -rf /var/apm/lib/rpm

epsec -f refresh​​​

Delete unused EPSEC files following the next article: K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system
