Known Issue

IPsec IKEv1 negotiation may fail, causing secure traffic connections to fail.

This issue occurs when a subset of the following conditions are met:

  • Configure the BIG-IP system as an IPsec tunnel endpoint.
  • Configure the tunnel to use the IKEv1 protocol.
    • On appliance platforms, the issue occurs intermittently.
    • On VIPRION platforms, you have run the command bigstart restart in a secondary blade.

Impact

IPsec connections fail due to IKEv1 negotiation failures.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • IPsec connections intermittently fail.
  • In the /var/log/racoon.log file, you may observe error messages similar to the following example:

    INFO: IPsec-SA request for 192.168.100.1 queued due to no phase1 found.

Workaround

To work around this issue on a VIPRION systems, you can run the bigstart restart command on all blades. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure interrupts traffic processing and you should perform it only during planned maintenance.

  1. Log in to the command line of the BIG-IP system.
  2. Ensure that you are on the primary blade. (Notice the letter P after the green status.)

    [root@example:/S1-green-P:Active]
  3. To run bigstart restart on all blades, type the following command:

    clsh bigstart restart
