Known Issue

This is the result of a known issue. Using the Traffic Management Shell (tmsh) in batch mode allows you to submit a set of commands that the tmsh utility processes as a single transaction.

Note: For more information about using the tmsh utility, refer to the Traffic Management Shell (tmsh) Reference Guide.

In BIG-IP 10.2.0 through 10.2.1, if you use the tmsh utility in batch mode and the syntax includes double quotation ( " ) characters, the tmsh utility inappropriately interprets the double quotation characters, and causes the transaction to fail.

For example, the following tmsh command sequence places the shell in batch mode and includes a command containing double quotation characters:

(tmos)# create cli transaction
(tmos.cli.transaction)# create /gtm datacenter "a b c" location "Seattle, WA"
Command added to the current transaction
[batch mode]root@localhost(Active)(tmos.cli.transaction)# list cli transaction
1: (tmos.cli.transaction)# create /gtm datacenter a b c location Seattle, WA
[batch mode]root@localhost(Active)(tmos.cli.transaction)# submit cli transaction
transaction failed: "WA" unknown property

When you use the list command to display the current set of commands in the transaction queue, transaction ID 1 is missing the quotation marks, and the subsequent submit command fails with a transaction failed message.

F5 Product Development tracked this issue as ID 346640, and it was fixed in BIG-IP 11.5.0. For information about upgrading, refer to the BIG-IP release notes.

Workaround

You can work around this issue by escaping the double quotation characters with single quotation ( ' ) characters.

For example:

(tmos.cli.transaction)# create /gtm datacenter '"a b c"' location '"Seattle, WA"'
