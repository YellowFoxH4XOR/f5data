Topic

Starting in BIG-IP 15.x, several SNMP traps are added or enhanced to utilize the MRF Diameter statistics collected for per peer.

Description

The following table describes the added or enhanced SNMP traps.

SNMP Trap NameOIDDescription
Diameter peer-delay health changed.1.3.6.1.4.1.3375.2.4.0.202In the last second, if the time that the peer takes to process a request and send the response exceeds or is under the Peer Delay Critical Limit (peer-delay-critical-limit), the system generates the trap. The Peer Delay Critical Limit setting is under SNMP Trap Thresholds in the Diameter session profile. This trap is introduced in BIG-IP 15.1.0.

Example logs that trigger this SNMP trap:

  • 01cc0000:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) delay 918 ms exceeds the critical threshold 1 ms
  • 01cc0000:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) delay 0 ms is back under the critical threshold 1 ms
Diameter peer outgoing rate limit changed.1.3.6.1.4.1.3375.2.4.0.203In the last second, the number of messages sent to the peer exceeds or is under the Egress [Critical|Major] Message Rate Limit (egress-critical-message-rate-limit | egress-major-message-rate-limit), the system generates the trap. The Egress Critical Message Rate Limit and Egress Major Message Rate Limit settings are under the SNMP Trap Thresholds section in the Diameter session profile. If the rate limit on a single connection to a peer exceeds the configurable threshold, the system generates the trap. This trap is introduced in BIG-IP 15.0.0.

Example logs that trigger this SNMP trap:

  • 01cc0001:3: The number of messages sent to the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 4 msgs/sec exceeds the critical rate limit threshold 3 msgs/sec
  • 01cc0001:3: The number of messages sent to the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 2 msgs/sec is back under the critical rate limit threshold 3 msgs/sec
  • 01cc0001:3: The number of messages sent to the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 2 msgs/sec exceeds the major rate limit threshold 1 msgs/sec
  • 01cc0001:3: The number of messages sent to the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 1 msgs/sec is back under the major rate limit threshold 1 msgs/sec
Diameter peer incoming rate limit changed.1.3.6.1.4.1.3375.2.4.0.204In the last second, the number of messages received from the peer exceeds or is under the Ingress [Critical|Major] Message Rate Limit (ingress-critical-message-rate-limit|ingress-major-message-rate-limit), the system generates the trap. The Ingress Critical Message Rate Limit and Ingress Major Message Rate Limit settings are under the SNMP Trap Thresholds section in the Diameter session profile. If the rate limit on a single connection to a peer exceeds the configurable threshold, the system generates the trap. This trap is introduced in BIG-IP 15.0.0.

Example logs that trigger this SNMP trap:

  • 01cc0002:3: The number of messages from the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 4 msgs/sec exceeds the critical rate limit threshold 3 msgs/sec
  • 01cc0002:3: The number of messages from the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 2 msgs/sec is back under the critical rate limit threshold 3 msgs/sec
  • 01cc0002:3: The number of messages from the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 2 msgs/sec exceeds the major rate limit threshold 1 msgs/sec
  • 01cc0002:3: The number of messages from the peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) 1 msgs/sec is back under the major rate limit threshold 1 msgs/sec
Diameter peer errors health changed.1.3.6.1.4.1.3375.2.4.0.206In the last second, if the percentage of error answers returned from the peer exceeds or is under the Peer Errors Major Threshold (peer-errors-major-threshold), the system generates the trap. The Peer Errors Major Threshold setting is under the SNMP Trap Thresholds section in the Diameter session profile. This trap is introduced in BIG-IP 15.1.0.

An example log that triggers this SNMP trap:

  • 01cc0002:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) errors percentage 2 exceeds the major threshold 1 percentage
Diameter peer timeouts health changed.1.3.6.1.4.1.3375.2.4.0.207In the last second, if the percentage of peer timeouts exceeds or is under the Peer Timeouts Major Threshold (peer-timeouts-major-threshold), the system generates the trap. The Peer Timeouts Major Threshold setting is under the SNMP Trap Thresholds section in the Diameter session profile. This trap is introduced in BIG-IP 15.1.0.

An example log that triggers this SNMP trap:

  • 01cc0002:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) timeouts percentage 2 exceeds the major threshold 1 percentage
Diameter peer health changed.1.3.6.1.4.1.3375.2.4.0.208The system generates the trap in the last second if the peer health is changed due to any of the following conditions:
  • The time that the peer takes to process a request and send the response exceeds or is under the configured critical threshold.
  • The percentage of error answers returned from the peer exceeds or is under the configured major threshold.
  • The percentage of peer timeouts exceeds or is under the configured major threshold.

Example logs that trigger this SNMP trap:

  • 01cc0005:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) health exceeds the critical threshold
  • 01cc0005:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) health is back under the critical threshold
Diameter peer connection state changed.1.3.6.1.4.1.3375.2.4.0.209When the connection to peer terminates because the BIG-IP system initiated the disconnect or the peer initiates the disconnect, the system generates the trap.

Example logs that trigger this SNMP trap:

  • Diameter client:

    01cc0006:3: Peer (seagull158.ims.askf5.local at 192.168.1.1:18731) connection state has changed: disconnected

  • Diameter server:

    01cc0006:3: Peer (diasvr157.dia.askf5.local from pool /Common/mytestdia_pool1 at 192.168.22.157:3868) connection state has changed: disconnected

SCTP active path down.1.3.6.1.4.1.3375.2.4.0.210In a Stream Control Transmission Protocol (SCTP) association with multi-homing enabled, when the current active path goes down and an alternate path is selected, the system generates the trap.
SCTP path restored.1.3.6.1.4.1.3375.2.4.0.211In an SCTP association, when a path is restored, the system generates the trap.
