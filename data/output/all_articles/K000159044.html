Description

After successful TCP and TLS handshakes on the client side, the connection is established.

Transferring large files initially starts but then gets aborted

A packet capture shows that the transfer gets aborted because of the virtual server resetting the connection with the following reason [F5RST: Flow expired (sweeper) (bias oldest)]

Also, the following log entries may be found in:

    • The /var/log/ltm file

warning tmm[<PID>]: 01010290:4: TCP: Memory pressure activated
warning tmm[<PID>]: 01010291:4: TCP: Memory pressure deactivated. Dropped <#> packets, <#> bytes

In these messages, note the following:

    • <PID> is the process ID for the Traffic Management Microkernel (tmm) process.
    • <#> is the number of dropped packets or bytes.

For example:
warning tmm[8484]: 01010291:4: TCP: Memory pressure deactivated. Dropped 314 packets, 414263 bytes

This message can also be seen
warning tmm[<PID>]: 011e0003:4: Aggressive mode sweeper: <policy> (<context>) <#> Connections killed

In this error message, note the following:

    • <PID> is the process ID for the tmm process.
    • <policy> is the partition and name of the eviction policy that was triggered (BIG-IP 11.6.0 and later).
    • <context> is the context to which the eviction policy is associated (BIG-IP 11.6.0 and later).
    • <#> is the number of reaped connections.

For example:
warning tmm[12663]: 011e0003:4: Aggressive mode sweeper: /Common/default-eviction-policy (vs /Common/vs_http) 10 Connections killed

 

Environment

BIG-IP (VCMP or VE)

Large amount of data (large files)

Cause

Insufficient memory resources allocated to TMM in the BIG-IP. 

When memory utilization exceeds TCP memory pressure thresholds, the BIG-IP system activates aggressive connection reaping to free up memory resources. 

This causes the system to:
    • Drop ingress TCP packets
    • Terminate active connections prematurely via RST packets
    • Kill connections through the aggressive mode sweeper when global memory thresholds are exceeded
    
Recommended Actions


Assign more memory to the Virtual Edition BIG-IP device in order to increase the allocated memory in TMM.

If needed, refer to your hypervisor documentation for procedures to increase virtual machine resources.
