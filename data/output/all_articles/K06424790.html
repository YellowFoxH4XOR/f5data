Known Issue

The BIG-IP APM rewrite process may incorrectly handle HTTP responses that have an empty payload.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured for portal access.
  • Your BIG-IP APM system processes HTTP responses that do not have a payload: for example, responses with a status code of 1xx, 204, or 304.

Impact

Web applications may malfunction or fail to render properly for some web browsers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Web applications malfunction or fail to render properly for some web browsers.
  • Your BIG-IP APM rewrite process inserts a Transfer-Encoding: chunked header in HTTP responses that have a status code of 1xx, 204, or 304.

Workaround

To work around this issue, you can use an iRule to remove the Transfer-Encoding header or payload from HTTP responses that have status codes of 1xx, 204, or 304. For example, to remove the header and the payload for an HTTP response that has a status code of 304, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click Create.
  4. In the Name box, type a name.

    For example:

    rule_BZ671627

  5. In the Definition box, enter the following: 
    when HTTP_RESPONSE_RELEASE {
  if { [HTTP::status] == 304 }{
       HTTP::header remove Transfer-Encoding
       HTTP::header insert Content-Length 0
}
}
  6. Click Finished.
