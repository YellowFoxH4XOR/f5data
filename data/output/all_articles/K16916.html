Known Issue

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

The Traffic Management Microkernel (TMM) may produce a core file when it receives an out-of-band BIG-IP WebAccelerator or AAM response.

This issue occurs when all of the following conditions are met:

  • A BIG-IP WebAccelerator/AAM enabled virtual server is configured.
  • BIG-IP WebAccelerator/AAM is disabled during the request phase.
  • BIG-IP WebAccelerator/AAM is enabled during the response phase.

BIG-IP WebAccelerator/AAM is not able to handle responses without a valid transaction. This behavior may occur if you forcibly disable BIG-IP WebAccelerator/AAM during request processing and re-enable for the response.

Impact

The BIG-IP system may temporarily fail to process traffic, and may fail over if configured as part of a high availability (HA) system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system generates a TMM core file in the /var/core directory.
  • Your BIG-IP system fails over to the peer system in a HA configuration.

Workaround

To work around this issue, you can avoid disabling BIG-IP WebAccelerator or AAM during request processing, unless you will also disable the system during response processing.
