Known Issue

The Traffic Management Microkernel (TMM) may produce a core file. This issue occurs when any the following conditions are met:

  • For TCP virtual servers, the affected TCP virtual server is associated with an iRule that has an iRules command suspending responses (for example, the table command).
  • For User Datagram Protocol (UDP) virtual servers, the affected UDP virtual server has all of the following conditions:
     
    • The affected UDP virtual server is associated with an iRule that has an iRules command suspending responses (for example, the table command).
    • Datagram LB is disabled in a User Datagram Protocol (UDP) profile for the affected UDP virtual server.
    • The affected UDP virtual server receives multiple DNS requests from the same IP address and port within the UDP profile timeout.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high availability (HA) pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H457694 on the Diagnostics > Identified > Medium screen.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system fails over to the standby system, if configured as an HA pair.

Workaround

There is no workaround for TCP virtual server. However, in case of UDP virtual server, you can work around the issue by enabling Datagram LB for the affected UDP profile. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > UDP.
  3. Click on the name of the affected UDP profile.
  4. To enable Datagram LB mode for the UDP profile, check the Datagram LB setting.
  5. To save the change, click Update.
