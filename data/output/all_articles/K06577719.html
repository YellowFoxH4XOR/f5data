K06577719: After upgrading vCMP host, vCMP guest is unable to resolve ARP

Type
Support Solution
Published
2021-11-16
Updated
2023-02-21
Applies to
  • VIPRION Platforms
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP DNS: 16.1.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.X.X, 16.0.1, 16.0.0, 16.1.0
Source
https://my.f5.com/manage/s/article/K06577719

Description

After upgrading or rebooting the vCMP Host, vCMP guests start experiencing connectivity problems, like unhealthy iquery or HA connections.
In addition, "tmsh show net arp" command run on vCMP guest indicates that all or majority of entries are incomplete.

Environment
  • vCMP host upgrade or reboot
  • vCMP guest upgrade or reboot
  • "tmsh show net arp" shows incomplete ARP entries on vCMP guest

Cause

vCMP guest is having problems with ARP resolution process.
 

Recommended Actions

Reboot vCMP host system

Impact of procedure: BIG-IP system traffic processing is interrupted while the system restarts.
 
1. Log in to graphical user interface (GUI) of vCMP host that stores affected vCMP guests
2. Change the current state of all vCMP guests to "configured" (VCMP -> vCMP guest list)
3. Open SSH session to the same vCMP host
4. Instruct the BIG-IP system to rebuild mcp binary database on the next reboot by creating the following file :
 
touch /service/mcpd/forceload
On-multi blade viprion systems :
 
clsh touch /service/mcpd/forceload
5. reboot vCMP host system by typing the following command :
 
reboot
On-multi blade viprion systems :
 
clsh reboot
6. when the system comes up, under "VCMP -> vCMP guest list" select the checkbox next to every vCMP guest system and click "deploy" button.
 

 

Additional Information

If the problem persists despite performing the steps above, submit a new Service Request to F5 support.
