Topic

  • You are new to using the iControl representation state transfer (REST) application programming interface (API).
  • You want a basic example of using REST commands to create an app tunnel and portal access access profile and policy for use with a virtual server.

Description

The following REST command examples show you how to use REST commands to create a connectivity profile, access profile, and policy that include two app-tunnel configurations with launcher items (in the examples, SSH and Microsoft terminal service client remote desktop access and a basic portal access configuration with LDAP authentication).

The procedure steps are ordered to fulfill the access profile and access policy validation and creation requirements. For more information on using iControl REST API to create a virtual server refer to: K13225405: Common iControl REST API command examples. F5 recommends that you use a common base name for all objects and prefacing object names for profile, policy, agent, and policy item suffixes. This article uses <base_name> in command syntax and the example configurations use Tunnels-and-Portal as the base name. When you create an access policy, all objects are interdependent and there are a considerable number of objects used to create the SSL VPN access profile and policy. Keep in mind when using the iControl REST API to create an access profile and policy that nothing is assumed and you need to create each required configuration object using a REST API command.

The sections in this article use cURL with two distinct methods of HTTP POST. The first method is a standard HTTP post to the iControl REST API IP address. The second requires the additional POST parameters X-F5-REST-Coordination-Id:<ID>, where the ID must be generated prior using REST syntax. You use the transaction style POST when implementing (validating) the interconnecting configuration objects that create the access profile and policy as presented in the Virtual Policy Editor (VPE).

In most cases, you can view an object's configuration using the GET method and the Uniform Resource Identifier (URI) of the specific object. Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output. The '.' (period) parameter is optional in jq 1.5 and later.

curl -sk -u admin:admin GET https://10.95.0.55/mgmt/tm/apm/resource/app-tunnel | jq -M .

Note: The JSON output of the object configuration includes links to view additional nested configuration details.

When using the JSON links, replace localhost with the IP address of the BIG-IP system.

Typographic conventions

The following typographic conventions are used in the command syntax examples:

  • <POST> = curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<big-ip apm address>
  • <POST+ID> = curl -sk -X POST -u admin:<password> -H "X-F5-REST-Coordination-Id:<ID>" -H "Content-Type: application/json" https://<big-ip apm address>
  • <PATCH> = curl -sk -u admin:<password> -H "Content-Type: application/json" -X PATCH  https://<big-ip apm address>
  • <GET> = curl -sk -u admin:<password>   -H "Content-Type: application/json" -X GET https://<big-ip apm address>
  • <DELETE> = curl -sk -u admin:<password>   -H "Content-Type: application/json" -X DELETE https://<big-ip apm address>

    Note:  For example, to run <GET> /mgmt/tm/apm/policy/access-policy/~Common~Tunnels-and-Portal| jq -M, you enter curl -sk -u admin:<password> GET https://<big-ip_apm_address>/mgmt/tm/apm/policy/access-policy/~Common~Tunnels-and-Portal| jq -M, replacing <password> and <big-ip_apm_address> with the appropriate administrative password and BIG-IP APM management IP address.

    Note: POST+ID requires a previous generation of a transaction ID, which is covered in the Generating the Transaction ID section.

Viewing configured components

You can view configured BIG-IP APM objects using HTTP GET. To view a list of possible URLs you can send a GET request to the base URL /mgmt/tm/apm. From the JSON output you can find  reference links that point to additional configuration information. In the following example you can obtain a list of all configured BIG-IP APM component objects for each component type. Note lines that precede with "link":, change the destination from "localhost" to the hostname or IP address of your BIG-IP APM system and send a GET request to the URL retrieves specific configuration information for that URL configuration object.

curl -sk -u admin:admin -H "Content-Type: application/json" -X GET  https://10.95.0.55/mgmt/tm/apm | jq -M .

Impact of procedure: Using the following commands should not have a negative impact on your system.

  • To view a specific configuration type object use the following syntax:

    <GET> /mgmt/tm/apm/<component_type>/<object_name> | jq -M .

  • To expand on the subcollections for a configuration object you can append the statement ?expandSubcollections=true to the query:

    <GET> /mgmt/tm/apm/<component_type>/<object_name>?expandSubcollections=true | jq -M .

  • To view a specific configuration object that resides in a non-default partition, include the partition name prefixed and suffixed with the tilde (~) character:

    <GET> /mgmt/tm/apm/<component_type>/~<partition_name>~<object_name> | jq -M .

  • To view all current established access sessions, use the following syntax:

    <GET> /mgmt/tm/apm/access-info | jq -M .

Note: Change <component_type> to one of the following component types: aaa, client, configuration, ephemeral-auth, epsec, ntlm, oauth, policy, profile, report, resource, saml, sso, acl, apm-avr-config, application, application-family, application-filter, log-setting, risk-class, session, swg-content-type, and url-filter. Replace <partition_name> with the BIG-IP administrative partition name for the configuration object. Replace <object_name> with the name of the configuration object you want to view.

Generalized definitions of access profile and policy configuration definitions used in this article.

  • profile is access session type that is processed by the access policy.
  • access policy is the access session decision-making flow and resource assignment to an access session.
  • agent is an access policy interconnection to configuration objects that produce actionable results for use by the access policy.
  • policy-item denies a configuration object, such as a resource, to be declared in the access policy.
  • resource is a configuration object that exist outside of the access policy, a subroutine with expected results, or a defined resource to be assigned to the access session.

Creating a LDAP authentication profile

To create a LDAP authentication server configuration for use in an access policy, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/aaa/ldap -d  '{"name":"<base_name>_act_ldap_auth","partition":"<partition_name>","fullPath":"/<partition_name>/<base_name>","address":"<ldap_server_ip>","adminDn":"<ldap_admin_dn>","adminEncryptedPassword":"<ldap_password>","baseDn":"<ldap_base_dn>","cleanupCache":"none","groupCacheTtl":30,"isLdaps":"false","locationSpecific":"true","port":389,"schemaAttr": {"groupMember":"member","groupMemberValue":"dn","groupMemberof":"memberOf","groupObjectClass":"group","userMemberof":"memberOf","userObjectClass":"user"},"timeout":15,"usePool":"disabled"}'

Note: Replace <base name> with the chosen profile name, <partition_name> with the BIG-IP administrative partition name you want to use,<ldap_server_ip> with the IP address of the destination LDAP server, <password> with the LDAP administrative user password in relation to the adminDN, <port> with the LDAP server port value. For adminDN replace <ldap_admin_dn> with the appropriate LDAP configuration values (syntax: CN=<cn>,CN=<cn>,DC=<dc>,DC=<dc> where each common name <CN> and domain component <DC> is replaced with the appropriate values for your LDAP authentication requirements). Replace <ldap_base_dn> (syntax:DC=<dc>,DC=<dc>) with the appropriate LDAP configured base DN common name values.

For example, to create a LDAP authentication profile configuration with the destination authentication server configured as direct (configuration that does not reference a pool), enter the following:

<POST> /mgmt/tm/apm/aaa/ldap -d '{"name":"Tunnels-and-Portal_act_ldap_auth","partition":"Common","fullPath":"/Common/Tunnels-and-Portal","address":"192.168.1.119","adminDn":"CN=BIG-IP,CN=Users,DC=vmlab,DC=local","adminEncryptedPassword":"zentyal123!","baseDn":"DC=vmlab,DC=local","cleanupCache":"none","groupCacheTtl":30,"isLdaps":"false","locationSpecific":"true","port":389,"schemaAttr": {"groupMember":"member","groupMemberValue":"dn","groupMemberof":"memberOf","groupObjectClass":"group","userMemberof":"memberOf","userObjectClass":"user"},"timeout":15,"usePool":"disabled"}'

Creating a Webtop resource

To create a webtop resource to be used by an access policy where the intended webtop resources are app-tunnels and/or portal access, use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/resource/webtop -d '{"name":"<base name>","customizationGroup":"/<partition>/<base name>","webtopType":"full"}'

Note: Replace <base name> with the base name used for all objects created for the network access profile and policy.

For example, to create a new webtop for network access with the name of vpn-webtop in the Common partition, you enter the following:

<POST> /mgmt/tm/apm/resource/webtop -d '{"name":"Tunnels-and-Portal","customizationGroup":"/Common/Tunnels-and-Portal_customization","webtopType":"full"}'

Creating an app-tunnel resource

You create an app-tunnel resource in two or more REST commands. The first command creates the app-tunnel resource, and the subsequent commands add items to the app-tunnel resource. These items are specific app-tunnel configurations regarding the end user's operating system and application to launch when utilizing the app-tunnel. To create an app-tunnel resource use the following command syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

<POST> /mgmt/tm/apm/resource/app-tunnel -d '{"name":"<base_name>_desktop","partition":"<partition_name>","fullPath":"/<partition_name>/<base_name>","applicationLaunchWarning":"true","customizationGroup":"/<partition_name>/<base_name>_resource_desktop_customization","javaTunnel":"false","locationSpecific":"true","type":"app-tunnel"}'

Note: Replace <base profile name> with the base name, replace <leasepool start ip> and <leasepool end ip> to set the available IP address for distribution from the lease pool. For a singular IP address enter the single address.

For example:

<POST> /mgmt/tm/apm/resource/app-tunnel -d '{"name":"Tunnels-and-Portal_desktop","partition":"Common","fullPath":"/Common/Tunnels-and-Portal","applicationLaunchWarning":"true","customizationGroup":"/Common/Tunnels-and-Portal_resource_desktop_customization","javaTunnel":"false","locationSpecific":"true","type":"app-tunnel"}'

Creating ACL rules

To create ACL rules, you should uniquely name each rule set, followed by the rule entries as noted in the following syntax:

Impact of procedure: Using the following commands should not have a negative impact on your system.

ACL allowing specific TCP port:

<POST> /mgmt/tm/apm/acl -d '{"name":"<base_name>_<remote_desktop_port>","entries":[{"action":"allow","dstEndPort":<remote_desktop_port>,"dstStartPort":<remote_desktop_port>,"dstSubnet":"<acl_network_applied>","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"<acl_network_applied>"}]}'

Examples (allow ACL rule):

<POST> /mgmt/tm/apm/acl -d '{"name":"Tunnels-and-Portal_3389","entries":[{"action":"allow","dstEndPort":3389,"dstStartPort":3389,"dstSubnet":"10.0.19.0/24","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"10.0.19.0/24"}]}'

<POST> /mgmt/tm/apm/acl -d '{"name":"Tunnels-and-Portal_22","entries":[{"action":"allow","dstEndPort":22,"dstStartPort":22,"dstSubnet":"10.0.19.0/24","log":"none","protocol":6,"srcEndPort":0,"srcStartPort":0,"srcSubnet":"10.0.19.0/24"}]}'

Note: Replace  <base name> with the base name used for all objects created for the network access profile and policy. Replace <acl end port> with the last port number of the port range, and replace <acl start port> with the first port number of the port range. Replace <acl network applied> with the network/masq of the network to apply the ACL (typically the same network as the addresses used in the lease pool).

ACL denying (rejecting) all TCP ports

Generating the transaction ID

The system uses the transaction ID  when implementing (validating) the interconnecting configuration objects of the access profile and policy. Impact of procedure: Using the following commands should not have a negative impact on your system.
