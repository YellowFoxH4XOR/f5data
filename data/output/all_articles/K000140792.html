K000140792: After upgrading to 17.1.1, 16.1.5, 15.1.10 , BIG-IP AWAF is blocking request with violation 'Cookie is not RFC compliant (cookie has no value)'

  • BIG-IP ASM: 15.1.10, 16.1.5, 17.1.1

Description:

After upgrading BIG-IP to version 17.1.1, 16.1.5, 15.1.10, following requests are blocked due to violation "Cookie is not RFC-compliant" in BIG-IP AWAF

 

1. Refer below HTTP request. BIG-IP AWAF is blocking http request containing TS cookie with secure attribute 

Cookie: TS01610b8f=01aee676798ed4d05060248de6ad3506f8801f2bd78ed68d764784c783cc04b2bec20ae0fd5f85e0c18cc86e060a85df7; Secure;  TS011a2ebd=01aee67679e24f200874fce474bde08ea2927efe078ed68d764784c783cc04b2bec20ae0fd01cf49e977f90a20fd 08a; Secure; 

 

2. Refer below HTTP request. BIG-IP AWAF is blocking http request containing cookie with { }

Cookie: ABC.NET_SessionId=g2drnslasdasdady; {}; TS011ab22b=01ebdsf86s87f6sd76fs8b5f6d5d900feacce9ca7e45534e7104b814a8s7d68a76d5ed677b2068d9160ec7e1c37285; Path=/; Domain=test.com; 

Environment:

  • 'Cookie not RFC-compliant' is enabled in learning and blocking setting in BIG-IP AWAF Security Policy.
  • HTTP request.
  • TS Cookie.
  • RFC compliance.
  • Upgraded version to 17.1.1,16.1.5,15.1.10.

 

Cause:

Bug ID 1069441

This is caused by a change in behavior after upgrading to version 17.1.1 and 16.1.5 to comply with RFC 6265. 

 

Recommended Actions:

The behavior is expected. RFC 6265 should be followed for cookie handling and address the issue at application level.

  1. For the first request mentioned above, "Secure" should not be present in the cookie header of the request.
  2. For the second request mentioned above, there is no cookie name and cookie value instead cookie is set as { };
