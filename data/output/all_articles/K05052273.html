Known Issue

Gateway pool action may trigger the Traffic Management Microkernel (TMM) to produce a core file and restart.

This issue occurs in either one of the following circumstances:

  1. Your BIG-IP system is not configured to route traffic using a gateway pool and all of the following conditions are met:
    • Your BIG-IP system is configured with DNS resolver.
    • All pools are configured with the Action on Service Down option set to None.
  2. Your BIG-IP system is configured to route traffic using a gateway pool and all of the following conditions are met:
    • Your BIG-IP system is configured with DNS resolver.
    • The gateway pool is configured with the Action On Service Down option set to Reject or Drop.
    • There is an outstanding DNS request that is pending response.
    • The pool monitor marks all members of the gateway pool as unavailable.

Impact

The BIG-IP system temporarily fails to process traffic while TMM process restarts. If the BIG-IP system is configured for high availability (HA), the system fails over to a peer system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H658683 on the Diagnostics > Identified > Medium page.
  • TMM generates a core file in the /shared/core directory.
  • Your BIG-IP system logs a SIGFPE signal to the /var/log/tmm file at the same time TMM produces a core file and restarts.
  • In one of the /var/log/tmm log files, you observe error messages similar to the following example:

    notice panic: ../modules/hudfilter/hudfilter.c:1063: Assertion "valid node" failed.
    notice ** SIGFPE **

Workaround

  • There is no workaround for the first circumstance in which your BIG-IP system is not configured to route traffic using a gateway pool.
  • To work around the issue in the second circumstance, you can modify the gateway pool by setting Action On Service Down to None. To do so, perform the following procedure:

    Impact of workaround: The gateway pool no longer sends a TCP reject when all pool members are unavailable.

    1. Log in to the Configuration utility.
    2. Navigate to Local Traffic > Pools > Pool List.
    3. Click the name of the affected pool.
    4. For Configuration, click Advanced.
    5. For Action On Service Down, click None or Reselect.
    6. Click Update.
