K000091236: duplicate HTTP headers added to response

Type
Support Solution
Published
2022-10-19
Updated
2022-10-20
Source
https://my.f5.com/manage/s/article/K000091236

Description

When applying multiple virtual servers to Nginx Ingress Controller, the same directive can be applied multiple times through the use of the http-snippets option. For example:

  • If 5 different virtualservers each have the following
http-snippets: |
  add_header Header-name example-value;

 

  • we will see these add_header directives applied 5 times to each response:
HTTP/1.1 200 OK
Server: nginx/1.21.3
Date: Wed, 26 Jan 2022 21:56:22 GMT
Content-Type: text/html; charset=utf-8
Connection: keep-alive
Expires: Wed, 26 Jan 2022 21:56:21 GMT
Cache-Control: no-cache
Header-name: example-value
Header-name: example-value
Header-name: example-value
Header-name: example-value
Header-name: example-value

 

Depending on the application, or the nginx directive being added via http-snippets, this can have undesired effects.

 

Environment

Nginx Ingress Controller
Kubernetes 
 

Cause

Each virtual server is created as a sub file in the /etc/nginx/conf.d/ directory, so there can be multiple identical directives placed in the http context of the overall configuration. This can result in unwanted or unexpected behavior, such as the same header inserted multiple times in the response. Additionally, since this places the directive in the http context, it will impact applications that you didn't want the directive applied to.

 

Recommended Actions

Caution should be used anytime you want to use the http-snippets option within a virtual server declaration(yaml file).
We strongly recommend using server-snippets when trying to add a directive to a virtual server. Following this suggested practice helps to avoid these accidental overlaps.

Alternatively, http-snippets are better applied through the ingress controller ConfigMap because this is already a global configuration, and it makes the most sense to apply snippets in the http context here.
