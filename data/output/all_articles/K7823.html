Issue

When diagnosing issues with Enterprise Manager iControl communications, begin by ensuring that NTP communications are configured and operational according to K3122: Configuring the BIG-IP Configuration utility to add an NTP server, and by ruling out the known issues described in K6138: Enterprise Manager may fail to discover BIG-IP devices or mark them impaired. If your issue is still unresolved, use the following procedures to help locate the point of failure:

  • Establishing communications between the Enterprise Manager and the BIG-IP system
  • Verifying communications between the Enterprise Manager and the BIG-IP system using the curl utility
  • Using the curl utility to verify that iControl is available on the target BIG-IP system
  • Debugging the iControl flow

Note: If you need to open a case with F5 Technical Support to assist in troubleshooting your issue, refer to K7569: Information required when opening a support case for Enterprise Manager.

Establishing communications between the Enterprise Manager and the BIG-IP system

You must establish communication between the Enterprise Manager system and the BIG-IP system. The communication protocol is iControl over HTTPS (TCP port 443).

Enterprise Manager 3.x

In Enterprise Manager 3.x, you should use the BIG-IP system's self IP address when adding the device to the Enterprise Manager device database. If you use a management port IP address, some Enterprise Manager features, such as iControl Proxy, BIG-IP Analytics, and BIG-IP ASM policy management will not function correctly.

Enterprise Manager 1.x and 2.x

In Enterprise Manager 1.x and 2.x, you must use the BIG-IP system's management IP address when adding the device to the Enterprise Manager device database. If you use a self IP address, the Enterprise Manager system will be unable to communicate with the BIG-IP system while TMM is restarting. As a result, software updates and other operations initiated by the Enterprise Manager system may fail.

Verifying communications between the Enterprise Manager and the BIG-IP system using the curl utility

You can verify communications between the Enterprise Manager and BIG-IP system by using the curl utility. To do so, type the following command, where <x.x.x.x> is the management IP address of the target system and admin:admin is the correct username and password for the admin user on the target system:

curl -k -u admin:admin https://<x.x.x.x>

When running the command from the BIG-IP system, the target system is the Enterprise Manager; when running the command from the Enterprise Manager, the target system is the BIG-IP.

Note: If this command fails, you should verify the connection path between Enterprise Manager and the BIG-IP system or verify the authentication details.

Using the curl utility to verify that iControl is available on the target BIG-IP system

After you have verified connectivity, you can use the curl utility to verify that iControl is available on the target BIG-IP system. To do so, from the Enterprise Manager system type the following command, where <x.x.x.x> is the management IP of the target BIG-IP and admin:admin is the correct username and password for the administrative user on the BIG-IP system.

For example:

curl -k -u admin:admin -i https://<x.x.x.x>/iControl/iControlPortal.cgi

Note: If this command fails, you should troubleshoot iControl on the BIG-IP system.

Debugging the iControl flow

After you have verified iControl on the BIG-IP system, you can debug the iControl flow. To do so, open a command line session with both the Enterprise Manager and with the managed BIG-IP device, then perform one of the following three procedures:

  • BIG-IP 10.1.x and later
  • BIG-IP 9.4.2 through 10.0.1
  • BIG-IP 9.0.0 through 9.4.1

Debugging the iControl flow for BIG-IP 10.1.x and later

  1. Perform this step at the BIG-IP command line: Enable iControl debugging by typing the following command:

    tmsh modify sys db icontrol.loglevel { value debug }

  2. Perform this step at the BIG-IP command line: To ssldump the iControl traffic, change the cipher settings for iControl to only allow RC4+RSA by typing the following command:

    tmsh modify sys httpd ssl-ciphersuite NONE:RC4+RSA

  3. Perform this step at the BIG-IP command line: Save the configuration by typing the following command:

    tmsh save sys config

  4. Perform this step at the BIG-IP command line: Restart the httpd and syslog-ng daemons by typing the following command:

    tmsh restart sys service syslog-ng httpd

  5. Perform this step at the Enterprise Manager command line: Enable debugging by typing one of the following two commands:

    tmsh utility (Enterprise Manager 2.1.0 and later)

    tmsh modify sys db log.em.device.level { value debug }

    Note: Beginning in Enterprise Manager version 2.1.0, the db variable Log.EM.Discovery.Level is deprecated. The db variable Log.EM.Device.Level must be used instead.

    bigpipe command (Enterprise Manager versions prior to 2.1.0)

    bigpipe db Log.EM.Discovery.Level debug

  6. Perform this step at the Enterprise Manager command line: Depending on the Enterprise Manager version, restart the emdeviced or discoveryd process by typing one of the following commands:

    tmsh utility (Enterprise Manager 2.1.0 and later)

    tmsh restart sys service emdeviced

    Note: Beginning in Enterprise Manager version 2.1.0, the discoveryd process is deprecated. The emdeviced process has taken over all its functions.

    bigstart command (Enterprise Manager versions prior to 2.1.0)

    bigstart restart discoveryd

  7. Perform this step at the BIG-IP command line: Start a tcpdump to gather iControl traffic by typing the following command:

    tcpdump -ni eth0 -Xs0 -w/var/tmp/discovery.pcap host <EM-IP>

  8. Perform this step at the Enterprise Manager command line: Perform a manual discovery to the target BIG-IP system by typing the following command, where <x.x.x.x> is the management IP of the BIG-IP system and <username> <password> are the administrative username and password:

    empipe discovery addr <x.x.x.x> <username> <password>

  9. Perform this step at the BIG-IP command line: Wait three minutes to allow the discovery process to complete, then stop the tcpdump by pressing Control-C.

    Note: The capture file should be at least 200KB in size. If it is smaller, either the tcpdump command failed to capture the target traffic, or discovery may still be running. You can verify whether the discovery process is still running by running the empipe task list command at the Enterprise Manager command line and examining the output for incomplete discovery jobs. If necessary, repeat Steps 7 and 8 until discovery traffic is successfully captured. If a NAT exists between the Enterprise Manager system and the managed device, modify the tcpdump command in Step 7 to reflect the NAT address of the Enterprise Manager system as seen by the managed system. Alternatively, you can modify the command to capture all SSL traffic on the management port: Simply replace host <EM-IP> with port 443 in the tcpdump command string.

  10. Perform this step at the BIG-IP command line: Run ssldump against the tcpdump file collected by typing the following command:

    ssldump -AdneN -r/var/tmp/discovery.pcap -k/config/httpd/conf/ssl.key/server.key > /var/tmp/discovery.txt

    Note: Examine the /var/tmp/discovery.txt file for conversations between the Enterprise Manager and the BIG-IP system. The decoded data should include entries that appear similar to the following example:

    <E:Envelope
    xmlns:E="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:A="http://schemas.xmlsoap.org/soap/encoding/"
    xmlns:s="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:y="http://www.w3.org/2001/XMLSchema"
    xmlns:iControl="urn:iControl"
    E:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
    <E:Body>
    <m:certificate_import_from_pemResponse
    xmlns:m="urn:iControl:Management/KeyCertificate"></m:certificate_import_from_pemResponse>
    </E:Body>
    </E:Envelope>

    If the expected data is not displayed, repeat steps 8 through 10.
  11. Perform this step at the Enterprise Manager command line: Set the discovery log levels back to Notice by typing one of the following two commands:

    tmsh utility (Enterprise Manager 2.1.0 and later)

    tmsh modify sys db log.em.device.level { value notice }

    Note: Beginning in Enterprise Manager version 2.1.0, the db variable Log.EM.Discovery.Level is deprecated. The db variable Log.EM.Device.Level must be used instead.

    bigpipe command (Enterprise Manager versions prior to 2.1.0)

    bigpipe db Log.EM.Discovery.Level notice

  12. Perform this step at the BIG-IP command line: Set the iControl log levels back to None by typing the following command:

    tmsh modify sys db icontrol.loglevel { value none }

  13. Perform this step at the BIG-IP command line: Change the cipher settings for iControl back to default by typing the following command:

    tmsh modify sys httpd ssl-ciphersuite 'ALL:!ADH:!EXPORT56:!eNULL:!MD5:RC4+RSA:+HIGH:+MEDIUM:+LOW:+SSLv2:+EXP'

  14. Perform this step at the BIG-IP command line: Save the configuration by typing the following command:

    tmsh save sys config

  15. Perform this step at the BIG-IP command line: Restart the httpd and syslog-ng daemons by typing the following command:

    tmsh restart sys service syslog-ng httpd

  16. Perform this step at the Enterprise Manager command line: Inspect the /var/log/em file for debugging and troubleshooting information.
  17. Perform this step at the BIG-IP command line: Inspect the following files for debugging and troubleshooting information:
    • /var/log/ltm
    • /var/tmp/discovery.pcap
    • /var/tmp/discovery.txt

  1. Perform this step at the BIG-IP command line: Enable iControl debugging by typing one of the following two commands:

    bigpipe db iControl.LogLevel debug

  2. Perform this step at the BIG-IP command line: You must now set the filter for facility local4 to include Debug. Open the /etc/syslog-ng/syslog-ng.conf file in a file editor.
  3. Perform this step at the BIG-IP command line: Edit the local4 entry to appear as follows:

    # local4.* /var/log/ltm
    filter f_local4 {
    facility(local4) and level(debug..emerg);
    };

  4. Perform this step at the BIG-IP command line: Save the file.
  5. Perform this step at the BIG-IP command line: To ssldump the iControl traffic, you must change the cipher settings for iControl to only allow RC4+RSA. To do so, you must modify the /config/httpd/conf.d/ssl.conf file in a file editor.
