Issue

Description

You want to troubleshoot and test BIG-IP VIPRION  Link Aggregation Control Protocol (LACP) trunk interfaces under the following conditions:

  • VIPRION LACP trunk interfaces are down or out of sync.
  • Trunks show as disconnected.

Environment

  • VIPRION platform
  • Minimum of two ports configured for LACP in a trunk

Cause

The following is not an exhaustive list of potential causes:

  • LACP peer not responding to synchronization messages
  • Damaged hardware:
    • Cable
    • SFP+
    • QSFP+
    • Interface

Recommended Actions

Performing basic LACP trunk configuration checks

To perform basic LACP configuration checks on the BIG-IP system and LACP peer systems, refer to the following actions:

  • Confirm the BIG-IP LACP trunk/VLAN and port settings are correct. For more information, refer to: K13142: Configuring the BIG-IP system to interface with Cisco virtual PortChannel.
  • Confirm the remote LACP device uses the correct LACP settings and ports enabled.
  • Confirm if you can use alternate physical ports to establish a working LACP trunk; a bad switch port or interface can cause unexpected LACP symptoms.
  • Confirm the physical cables and any switch or BIG-IP hardware (GBIC) is correct and healthy, and not displaying errors, such as I/O errors.
  • If you suspect defective hardware, such as a bad interface, run an End User Diagnostics (EUD). Verify no errors or warnings are present for the ports and any modules installed (SFP, etc). For more information, refer to K7172: Overview of the End User Diagnostics software.
  • Verify that all member ports are marked up on the BIG-IP system.

    1. Determine the interfaces in the trunk using the following TMOS Shell (tmsh) command syntax:

      tmsh list net trunk <trunk_name> interfaces

      For example, to show the status of trunk mytrunk, type the following command:

      tmsh list net trunk mytrunk interfaces
      net trunk mytrunk {
          interfaces {
              1/1.1
              4/1.1
          }
      }

    2. Show the status of the trunk interfaces using the following command syntax:

      tmsh show net interface <interface_number> [<interface_number>]

      For example, to show the status of interfaces 1/1.1 and 1/4.1, type the following command:

      tmsh show net interface 1/1.1 4/1.1

Clearing interface statistics and verifying even load balancing between the ports

To clear interface statistics and verify even load balancing between the LACP ports, perform the following procedure:

  1. Log in to tmsh.
  2. Clear stats before traffic test by typing the following command:

    tmsh reset-stats net interface

  3. Use the following syntax from to verify even load balancing over the LACP ports:

    tmsh show net interface <interface_number>

    For example:

    tmsh show net interface 1/1.1 4/1.1

    -------------------------------------------------------------------
    Net::Interface
    Name Status Bits Bits Pkts Pkts Drops Errs Media
    In Out In Out
    -------------------------------------------------------------------
    1/1.1 up 47.9M 150.6M 35.0K 37.4K 11 0 10000SR-FD
    4/1.1 up 34.1M 106.1M 25.0K 26.5K 0 0 10000SR-FD

Enabling LACP debugging

If you have verified all network cabling connections and tested the physical ports, but failed to establish a working LACP trunk, you can enable LACP debugging to further troubleshoot the issue.

Impact of procedure: The LACP trunk will go offline briefly when the LACPD daemon is restarted, this will cause all traffic on any LACPD trunk on the BIG-IP to fail briefly. In addition, enabling LACP debug logging may degrade performance on high network traffic BIG-IP units due to increased logging, disk and cpu activity. F5 does note recommend leaving LACP debugging enabled on a production BIG-IP for extended periods of time.

  1. Log in to the Advanced Shell (bash).
  2. Enable lacpd debug by typing the following commands:
    • tmsh modify sys db log.lacpd.level value debug
    • tmsh modify sys db log.lacpd.debugmask value 511
    • tmsh save sys config
  3. Run a packet capture on the BIG-IP system for 30 seconds. To do so, use the following tcpdump syntax:

    Capturing on one specific interface in a trunk will automatically capture traffic on both interfaces configured in the trunk. For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.

    tcpdump -ni <slot>/<interface> -e ether proto 0x8809 -w /var/tmp/<file_name>.1.pcap

    For example, if the trunk is configured on Slot 1 Interface 1.1 (1/1.1), type the following command:

    tcpdump -ni 1/1.1 -e ether proto 0x8809 -w /var/tmp/lacp_k35281771.1.pcap

  4. Press Ctrl+c to stop the tcpdump capture.

  5. Generate a QKView file. For information, refer to: K12878: Generating diagnostic data using the qkview utility.

  6. Start a new tcpdump capture. To do so, use the following tcpdump syntax:

    Capturing on one specific interface in a trunk will automatically capture traffic on both interfaces configured in the trunk. For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.

    tcpdump -ni <slot>/<interface> -e ether proto 0x8809 -w /var/tmp/<file_name>.2.pcap

    For example, if the trunk is configured on Slot 1 Interface 1.1 (1/1.1), type the following command:

    tcpdump -ni 1/1.1 -e ether proto 0x8809 -w /var/tmp/lacp_k35281771.2.pcap

  7. While tcpdump is in the running, type the following command:
    Note: Leave the tcpdump running for at least 30 seconds after lacpd has restarted.

    clsh bigstart restart lacpd

  8. Press Ctrl+c to stop the packet capture:
  9. Type the following command to show the current trunk status:

    tmsh show net trunk detail

  10. Generate a second QKView file. For more information, refer to K12878: Generating diagnostic data using the qkview utility.
  11. Disable lacpd debugging by running the following commands:
    • tmsh modify sys db log.lacpd.level value Informational
    • tmsh modify sys db log.lacpd.debugmask value 0
    • tmsh save sys config
Reviewing debugging data

After you have gathered the debugging data, you can review the the packet capture and the debug log messages and verify whether the actor and partner keys match. The key should be identical as shown below:

  • In the following example from /var/log/ltm, the actor and partner are in sync, and the state key field is consistent:

    info lacpd[6509]:     Actor Key=0x1, PortId=0x1010101, State=0x3D     <-- this is the actor key, it matches the below partner key state value

    info lacpd[6509]:     Partner Key=0x4, PortId=0x80000102, State=0x3D  <-- this is the remote partner key

  • In the following example from /var/log/ltm, LACP is not in sync, as indicated by the inconsistent state key field:

    info lacpd[6509]:     Actor Key=0x3, PortId=0x1030103, State=0xD      <-- key does not match partner key
    info lacpd[6509]:     Partner Key=0x4, PortId=0x80000202, State=0x85

  • Review the packet capture for evidence of failure. Are actors sending and receiving messages from each other?

Should you require further assistance, upload both QVKiew and packet capture files to F5 Support for investigation. For more information, refer to K000090853: Exchange files with F5 Support using MyF5 and K623: Opening a new case with F5 Technical Support from AskF5.

Additional Information

The LACP protocol provides a method for the BIG-IP system to aggregate multiple physical ports into a single logical trunk link. Using LACP allows physical redundancy in the event of a port failure, and enhances link reliability. Refer to the following sections for more information about the LACP protocol.

LACP process overview

The LACP process start up and operation is defined as follows:

  1. Start.
  2. Clear sync, coll and dist flags.
  3. Is the link a member of the active sub-group?
  4. If link is a member of active sub-group, proceed to step 5 below, otherwise go to end.
  5. If the remote SysID and key does not match the local unit's current LACP SysID and key, then proceed to step 6, otherwise LAG looped and go to end.
  6. If the remote system advertises the local units SysID as its partner, proceed to step 7.  If no, then unidirectional link and go to end.
  7. If the remote SysID and key are consistent with other links in the LACP trunk (LAG), or this is the first link in the bundle, proceed to step 7. If no, then cabling fault and go to end.
  8. Set the sync flag and proceed to step 9.
  9. Is the link in sync on the LACP partner? If yes, proceed to step 10. If no, then config error or standby on partner and go to end.
  10. Set coll and dist flags, go to end.

LACP protocol flags

FlagDefinition
ActivitySet to indicate LACP active mode, cleared to indicate passive mode
TimeoutSet to indicate the device is requesting a fast (1s) transmit interval of its partner, cleared to indicate that a slow (30s) transmit interval is being requested.
AggregationSet to indicate that the port is configured for aggregation (typically always set)
SynchronizationSet to indicate that the system is ready and willing to use this link in the bundle to carry traffic. Cleared to indicate the link is not usable or is in standby mode.
CollectingSet to indicate that traffic received on this interface will be processed by the device. Cleared otherwise.
DistributingSet to indicate that the device is using this link transmit traffic. Cleared otherwise.
ExpiredSet to indicate that no LACPDUs have been received by the device during the past 3 intervals. Cleared when at least one LACPDU has been received within the past three intervals.
DefaultedWhen set, indicates that no LACPDUs have been received during the past 6 intervals. Cleared when at least one LACPDU has been received within the past 6 intervals. Once the defaulted flag transitions to set, any stored partner information is flushed.

LACP state

The LACP State field uses a bit LACP protocol field bit to identify what LACP flags the LACP frame includes.

For example:

        Partner State=0x3D
1/1.11 - Actor State=0x3C
        Partner State=0x3D
2/1.9 - Actor State=0xC   <--- the LACP actor is in sync
        Partner State=0x5 <--- the LACP partner is out-of-sync
2/1.11 - Actor State=0xC
        Partner State=0x5
