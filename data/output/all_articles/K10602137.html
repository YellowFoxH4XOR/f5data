Description:

The BIG-IP ASM may erroneously block requests with content type application/octet-stream.

This HTTP header is often used for POST and PUT methods. File uploads will sometimes use this content type.

Environment:

  • Content-Type: application/octet-stream

Cause:

The content type application/octet-stream is a binary file and since BIG-IP ASM does not know how to parse this content-type. This causes the traffic to be blocked by the ASM due to false positive when ASM runs attack signatures/policy on this content-type.

Recommended Actions:

Create a header-based content profile for the affected URI to bypass BIG-IP ASM.  For example, this configures the BIG-IP ASM to ignore requests when the Content-Type is application/octet-stream:

1.   Log in to the Configuration utility (GUI)
2.  Navigate to Security > Application Security > URLs > Allowed URLs > Allowed HTTP URLs.
3.   Click Create to build a new Allowed URL definition.
4.   For URL, enter /alpha/beta/gamma. [This is a hypothetical example of URL, replace with the URL for which you are seeing the false positive block requests]
5.   Click Advanced to display the Header-Based Content Profile.
6.   Click the Header-based Content Profiles tab and enter the following information:
  •         Request Header Name:  Content-Type
  •         Request Header Value:  *application/octet-stream*
  •         Body handling: Do nothing

  7.  Click Add.
  8.  Click Create to save.
  9.  Click Apply Policy to apply the changes to the policy.

None.
