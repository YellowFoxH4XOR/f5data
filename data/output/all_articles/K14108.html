Known Issue

The gtmparse -l command may overwrite pool fallback IP addresses with 0:0:0:0:0:0:0:0.

This issue occurs when the following conditions are met:

  • You configure the pool with the IPv4 or IPv6 fallback IP address.
  • You do not configure the pool LB method to use the fallback IP as one of the LB methods.
  • You enter the gtmparse -l command on the BIG-IP GTM system.

The gtmparse -l command will overwrite the pool fallback IP addresses to 0:0:0:0:0:0:0:0, if you do not configure the pool to use the fallback IP as one of the LB methods.

Impact

The gtmparse -l command will overwrite fallback IP addresses with 0:0:0:0:0:0:0:0.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Pool fallback IP fields contain 0:0:0:0:0:0:0:0 for an IP address.
  • You view an error message when attempting to update the pool LB method from the Configuration utility.

Workaround

To work around this issue, you can set one of the pool LB methods to the fallback IP address for a pool configured to use an IPv4 or IPv6 fallback address. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > Pools and choose the pool that you want to use Fallback IP as one of the LB methods.
  3. Click the Members tab.
  4. Update the Fallback IPv4 or IPv6 address with the IP address you want to use for the fallback IP.
  5. Choose Fallback IP as one of the Load Balancing methods.
  6. Click Update.
