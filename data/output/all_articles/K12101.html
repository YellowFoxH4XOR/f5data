Known Issue

This is the result of a known issue. The BIG-IP system may transition to offline and then standby state after enabling the network failover feature. This occurs when you select the check box to enable Network Failover and then configure the other Network Failover settings before clicking the Update button.

For example, if you select the check box to enable Network Failover on the active BIG-IP system using the Configuration utility, and configure the Peer Management Address setting along with a Unicast or Multicast Configuration Identifier, and then click Update, the system transitions to offline and then to standby state. When this occurs, the sod process logs messages to the /var/log/ltm file that appear similar to the following example:

sod[3745]: 01140029:5: HA config_not_received sod fails action is go offline.
sod[3745]: 010c003e:5: Offline
sod[3745]: 01140030:5: HA config_not_received sod is now responding.
notice sod[3745]: 010c0018:5: Standby

Note: This issue occurs regardless of whether the BIG-IP pair is configured to use hard-wired failover.

F5 Product Development tracked this issue as ID 337159 and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, WebAccelerator, PSM, APM, WOM, or Edge Gateway release notes.

This issue has been fixed in Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K10025: Managing BIG-IP product hotfixes (10.x).

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue and prevent the system from going offline and then standby by configuring either a Unicast or Multicast Configuration Identifier and clicking Update before enabling Network Failover. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. Click the Network Failover menu.
  5. Configure either a Unicast or Multicast Configuration Identifier and click Add.
  6. Click Update.
  7. Select the Network Failover check box.
  8. In the Peer Management Address box, type the management IP address of the peer system.
  9. Click Update.
