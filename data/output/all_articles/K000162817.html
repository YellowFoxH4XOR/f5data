BIG-IP LTM Cloud: Identify the Azure Storage Account used by Cloud Failover Extension

Description

When you deploy BIG-IP Virtual Edition in Microsoft Azure with the F5 Cloud Failover Extension (CFE) configured for a high-availability (HA) pair, CFE uses an Azure Storage Account to store and manage the failover state file, f5cloudfailoverstate.json. CFE reads and writes this state file during failover events.

When multiple Storage Accounts exist, each with an f5_cloud_failover_label tag for different BIG-IP deployments, you may be unable to determine which Storage Account a specific BIG-IP HA pair actively uses. This uncertainty can prevent you from safely applying network access restrictions or disabling public network access.

Environment

  • BIG-IP Local Traffic Manager (LTM) Virtual Edition
  • Microsoft Azure
  • F5 Cloud Failover Extension
  • BIG-IP active/standby HA pair with CFE configured
  • BIG-IP 14.1.0 and later
  • CFE 1.5.0 and later

Cause

CFE uses tag-based discovery through scopingTags or explicit naming through scopingName in its declaration to identify the Azure Storage Account that it manages. When multiple Storage Accounts exist across different BIG-IP deployments, you must match the value in the CFE declaration exactly against the tags on the Azure Storage Accounts to determine which account CFE uses.

Recommended Actions

Follow these steps in order. Each step progressively confirms the Storage Account that CFE uses.

Step 1: Query the CFE declaration on BIG-IP

  1. Log in to the BIG-IP bash shell and run the following command to retrieve the current CFE configuration:

    curl -su admin:<password> http://localhost:8100/mgmt/shared/cloud-failover/declare | python3 -m json.tool

  2. Locate the externalStorage section in the output.
    1. For tag-based discovery, look for a structure similar to the following: 
      
{
    "externalStorage": {
        "scopingTags": {
            "f5_cloud_failover_label": "connectivity-prod-f5-rg-n10"
        }
    }
}
    2. For explicit naming, look for a structure similar to the following: 
      
{
    "externalStorage": {
        "scopingName": "your-storage-account-name"
    }
}
    3. If the declaration uses scopingTags, record the exact tag value. CFE uses the Azure Storage Account that has this exact tag value.
    4. If the declaration uses scopingName, the Storage Account name is explicitly defined. No tag matching is required, but continue to Step 3 to confirm runtime discovery.

Important: The tag value is case-sensitive and must match exactly. For example, connectivity-prod-f5-rg-n10 and connectivity-prod-f5-rg-n01 are different values and resolve to different Storage Accounts.

Step 2: Match the tag against Azure Storage Accounts

Use the tag value from Step 1 to identify the matching Storage Account.

Using Azure Command-Line Interface

  1. Run the following command from Azure Cloud Shell or another system with Azure Command-Line Interface (CLI) access. Replace the tag value with the value retrieved in Step 1: 
    
az storage account list \
  --query "[?tags.f5_cloud_failover_label=='connectivity-prod-f5-rg-n10'].{Name:name, ResourceGroup:resourceGroup, Tag:tags.f5_cloud_failover_label}" \
  -o table
  2. The Storage Account returned in the output is the account that CFE is configured to use.

Using the Azure portal

  1. In the Azure portal, navigate to Storage accounts.
  2. Open each Storage Account and select Tags.
  3. Identify the Storage Account whose f5_cloud_failover_label tag value exactly matches the value from Step 1.

Note: If more than one Storage Account has the same f5_cloud_failover_label value, correct the duplicate tagging. Each BIG-IP HA deployment must use a uniquely tagged Storage Account.

Step 3: Confirm runtime discovery through the CFE inspect endpoint

  1. Run the following command from the BIG-IP bash shell to confirm which Storage Account CFE discovers at runtime:

    curl -su admin:<password> http://localhost:8100/mgmt/shared/cloud-failover/inspect | python3 -m json.tool

  2. Locate the externalStorage section. The name field identifies the Storage Account that CFE resolves and actively uses at runtime: 
    
{
    "externalStorage": {
        "discovered": [
            {
                "name": "dcf5new",
                "scopingTags": {
                    "f5_cloud_failover_label": "connectivity-prod-f5-rg-n10"
                }
            }
        ]
    }
}

Note: If the externalStorage section is absent or empty, CFE cannot discover a matching Storage Account at the time of the query. Verify that the Storage Account tag exactly matches the value in the CFE declaration and that the BIG-IP system can reach the Storage Account.

Step 4: Verify the state file in the Azure Storage browser

  1. In the Azure portal, navigate to the Storage Account identified in Steps 2 and 3.
  2. Go to the Storage browser and select Blob containers.
  3. Locate the f5cloudfailover container.
  4. Confirm that the container contains the f5cloudfailoverstate.json file.

The Storage Account containing this container and file is confirmed as the account that CFE uses for failover state management.

Additional Information

  • The f5_cloud_failover_label tag key is static and cannot be changed. You can customize only the tag value for each deployment.
  • Each BIG-IP HA deployment must use a uniquely tagged Storage Account. Multiple deployments that share the same tag value can cause unpredictable CFE behavior.
  • In environments with multiple BIG-IP HA pairs, each pair should have a separate CFE declaration with a unique tag value and a separate Storage Account.
  • CFE also caches the state file locally on BIG-IP in a data group named f5-cloud-failover-state and synchronizes the state between HA peers through BIG-IP ConfigSync.
  • CFE requires the BIG-IP Managed Service Identity (MSI) to have read and write permissions for the Storage Account Blob service. Refer to the F5 CFE Azure role-based access control (RBAC) role definition for the minimum required permissions.
  • For guidance about restricting public access to the CFE Storage Account while maintaining CFE functionality, refer to the F5 CFE in Isolated Environments documentation.
