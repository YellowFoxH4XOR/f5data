K000156658: gRPC Connections Fails to Work with NGINX Plus Ingress Controller

Description

gRPC traffic fails when routed through a reverse proxy to an NGINX Ingress Controller in a Google Kubernetes Engine (GKE) cluster. The failure is caused by HTTP/2/ALPN handshake negotiation issues, resulting in the connection being downgraded to HTTP/1.1, which breaks the gRPC handshake. Relevant error messages include:

  • Ingress Controller pod logs:

    grpc: failed to negotiate stream error: rpc error: code = Unavailable desc = connection closed before server preface received

  • NGINX reverse proxy logs:

    upstream prematurely closed connection while reading response header from upstream, client: <client_ip>, server: <server_name>, request: "PRI * HTTP/2.0"

Environment

  • NGINX Plus

  • NGINX Ingress Controller

  • Google Kubernetes Engine (GKE)

  • gRPC

  • HTTP/2

Cause

HTTP/2 is not enabled for upstream (server-side) connections in the NGINX Ingress Controller by default. As a result, ALPN negotiation fails between the reverse proxy and the Ingress Controller, causing the connection to downgrade to HTTP/1.1 and breaking gRPC communication.

Recommended Actions

  • Explicitly enable HTTP/2 for upstream connections in the NGINX Ingress Controller by setting the following in the NGINX ConfigMap:

apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config
  namespace: nginx-ingress
data:
  http2: "true"

  • Ensure that your Ingress resource includes this annotation:

nginx.ingress.kubernetes.io/backend-protocol: "GRPC"

  • For custom resources (VirtualServer), specify the upstream type as grpc and ensure HTTP/2 is enabled.
  • After applying these changes, reload or restart your NGINX Ingress Controller pods to apply the new configuration.
