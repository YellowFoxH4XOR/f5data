Known Issue

An iRule with a pool command may fail to pick a pool member, even if there are pool members active and marked up.

This issue occurs when all of the following conditions are met:

  • You have an iRule that uses the pool command to select a pool or pool member.
  • You change the BIG-IP configuration.

Impact

Traffic for the affected iRule is reset because load balancing fails to pick a pool member.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Clients see TCP resets indicating that there are no pool members available.
  • An LB_FAILED event is triggered.

Workaround

To work around this issue, you can call the pool using the format command. To do so, perform the following procedure:

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

Modify the pool command to include the format command. For example, consider the following iRule:

when CLIENT_ACCEPTED
{
pool http-respond
}

Changing the pool command to include the format command appears similar to the following example:

when CLIENT_ACCEPTED
{
pool [ format http-respond ]
}
