K000162866: BIG-IP HA mirroring channels failed, causing subscriber sessions to be lost during failover.

Type
Support Solution
Published
2026-09-03

2026-09-03
Applies to

Source

Description

After failover of a BIG-IP LTM high-availability pair, nearly all active subscriber sessions were lost. 

 

 

Environment

  • BIG-IP LTM
  • HA configuration: Two-device HA pair
  • Traffic groups: One traffic group shown in the evidence (traffic-group-1), with eight TMM mirroring channels 
  • Relevant HA function: State mirroring between TMM instances

Cause

The issue was caused by a combination of HA mirroring configuration and initialization problems:

  1. The mirror self IP service policy was reviewed and corrected to permit the required HA mirroring traffic. Allow All was used during recovery, but it should not be presented as the required permanent setting.
  2. The HA mirror configuration required reinitialization. In this case, toggling the configured mirror interface caused the mirroring channels to reinitialize.
  3. Secure state mirroring was made consistent on both devices and enabled where required. A mismatch in statemirror.secure can cause HA mirroring TLS handshake failures.

As a result, the HA mirroring channels were unable to initialize correctly. Because the standby device was not receiving connection state information from the active device, client sessions were lost during failover events.

The following evidence supported the diagnosis:

  • tmsh show sys ha-mirror showed most TMM channels as closed or delay.
    • Only TMM [0.2] had a connected primary mirroring channel.
    • The remaining TMM mirroring channels were in delay or closed states.

    • SSL Handshake failed

Recommended Actions

On both BIG-IP devices:

  1. Set the mirror self IP port lockdown to Allow All.
    1. Via CLI:
      1. Modify the mirror self IP. Replace <mirror_self_ip_name> with the self IP object name, not necessarily the IP address: 
        tmsh modify net self /Common/<mirror_self_ip_name> allow-service all
      2. Example: 
        tmsh modify net self /Common/ha-mirror-self allow-service all
      3. Save the configuration: 
        tmsh save /sys config
      4. Verify the setting: 
        tmsh list net self /Common/<mirror_self_ip_name> allow-service
      5. The output should include: 
        allow-service all
    2. Via GUI
      1. Log in to the BIG-IP Configuration utility.
      2. Go to Network > Self IPs.
      3. Click the self IP used for mirroring.
      4. Set Port Lockdown to Allow All.
      5. Click Update.
  2. Toggle the HA mirror interface by changing it to another interface and then changing it back. This forced the mirroring channels to reinitialize.
  3. Enable secure state mirroring: 
    tmsh modify /sys db statemirror.secure value enable
tmsh save /sys config


  1. Verify the mirroring status:

    tmsh show sys ha-mirror
    





After the changes, all eight TMM Primary mirroring channels for traffic-group-1 showed connected. This demonstrated recovery of the mirror-channel connection state. Because the abort and error counters were nonzero historical counters and had not been reset, continued monitoring and a controlled failover test were still required.

Additional Information




As this is an HA (High Availability) environment, a controlled failover should be performed during a scheduled maintenance window.


The configuration is deployed across two devices operating in an HA pair. The following steps are recommended for the controlled failover:


  1. Schedule a maintenance window for the failover test.
  2. Take a UCS backup of both devices.
  3. Confirm that all TMM mirroring channels are in a Connected state.

    tmsh show sys ha-mirror
    

  4. Verify the configured mirror IP addresses.

    tmsh show cm device | grep -E 'Device:|Mirror'
    

  5. Verify the active/standby distribution of the traffic groups.

    tmsh show cm traffic-group
    

  6. Confirm that secure mirroring is enabled and configured consistently on both devices.

    tmsh list sys db statemirror.secure
    

  7. Verify that device trust is healthy and synchronized.

    tmsh show cm trust-domain
    

  8. Perform the failover test and confirm the following:

    • Sessions are visible on the newly active device.
    • Mirroring channels remain connected after the failover.
    



If the mirroring channels become disconnected again after the failover, first verify mirror addresses, network reachability, software/hardware parity, and the statemirror.secure settings. If those checks are correct and the problem persists, rebuild the device trust relationship between the HA peers.
