K000163585: F5OS-C tenant deployment fails with “Insufficient memory on node” on a blade

Description

BIG-IP tenant deployment on a VELOS partition may remain pending with:

Insufficient memory on node, retrying tenant deployment 

Environment

  • VELOS partition
  • F5OS-C 1.8.x
  • Known affected blade: BX110

Cause

Bug ID 2160697: Rsync.log files on blades are not rotated

Large files can consume the blade’s /sysroot filesystem and cause disk pressure. Possible disk consumers include:

  • Unrotated rsync.log files.
  • Core files.
  • Platform logs.

When disk pressure is asserted, the blade may report: (On a partition show cluster)

 state disk-pressure-info disk-pressure true
 state disk-pressure-info message "kubelet has disk pressure"

Tenant deployment can then fail with the generic Insufficient memory on node message. This message does not by itself indicate a physical DIMM or DRAM failure.

Answer/Recommended Actions

Option 1: (Recommended) Upgrade the Controller and partition to F5OS-C version 2.0.0

Option 2: Follow these steps:

1. SSH to the blade from a controller's bash shell

ssh blade-<blade_number>

2. Check filesystem usage from the affected blade:

df -h -x overlay -x tmpfs

3. Identify large files

find /sysroot -xdev -type f -size +1G -exec du -h {} \; | sort -hr

Important: The VELOS administrator should not delete any large file(s). Engage F5 Support for further assistance if required.

4. If you see the rsync.log file on blades is not rotated and has a large size, use the following command to truncate it:

truncate -s0 /var/F5/partitionN/log/rsync.log

N is the ID of the partition with the large rsync.log file.

Note: This will remove all the contents of the rsync.log file.  If you wish to keep this data, back it up before performing this operation.
