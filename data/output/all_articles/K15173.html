Topic

vCMP guests running on the VIPRION B2100 blade do not support a certain provisioning combination.

Description

When you deploy a vCMP guest that is configured with 2 Cores Per Guest on the VIPRION B2100 blade, and you then attempt to configure the vCMP guest with the following provisioning level for the BIG-IP LTM and ASM module combination, the vCMP guest does not provision the module combination:

ModuleProvisioning level
ASMMinimum
LTMNominal

In addition, the vCMP guest reports an error message that appears similar to the following example:

err load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all base" - failed. -- Loading system configuration... /defaults/asm_base.conf /defaults/config_base.conf /defaults/low_profile_base.conf /defaults/policy_base.conf /defaults/wam_base.conf Loading configuration... /config/bigip_base.conf /config/bigip_user.conf 01071008:3: Provisioning failed with error 1 - 'Memory limit exceeded. 3326 MB are required to provision these modules, but only 3224 MB are available.' . Unexpected Error: Loading configuration process failed

This behavior is expected. The provisioning level for this module combination is not supported on a two vCPU vCMP guest running on the VIPRION B2100 blade.

Recommendations

When planning the provisioning level for this module combination on a two vCPU vCMP guest deployed on the VIPRION B2100 blade, you should consider one of the following options:

  • If you want to use the provisioning level for this module combination described previously, you should configure the vCMP guest with 4 Cores Per Guest.
  • If you are unable to allocate more vCPUs for the vCMP guest, you should configure the vCMP guest to use the following provisioning level:
ModuleProvisioning level
ASMNominal
LTMNominal
