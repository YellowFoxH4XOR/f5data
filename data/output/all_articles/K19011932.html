K19011932: Configuration Utility (GUI) not accessible

Type
Support Solution
Published
2022-02-21
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K19011932
Description

The device is not accessible via the configuration utility but able to connect to device on CLI (SSH)

The Daemons below not running or restarting:

  • unable to restart httpd
  • tomcat keep restarting
  • syslog-ng is down
No error found in httpd/httpd_errors or var/log/webui.log

Environment

  • BIG-IP LTM
  • remote Syslog server configured
  • Cannot access GUI
  • Can access CLI (SSH)
Cause

Unknown

Recommended Actions

  1. verify all the daemons(httpd, tomcat, syslog-ng) are up or down

    # tmsh show sys service all

  2.  Run below command to check the error why httpd is failed to restart

    # restcurl -u admin:<password> /tm/sys/service -X POST -d '{"name":"httpd", "command":"restart"}'

    For example it will show you similar like this

    [root@LTM1:Active:Standalone] config # restcurl -u admin:admin /tm/sys/service -X POST -d '{"name":"httpd", "command":"restart"}'
    {
    "kind": "tm:sys:service:restartstate",
    "name": "httpd",
    "command": "restart",
    "commandResult": "Stopping httpd: [  OK  ]\r\nStarting httpd: [FAILED]\r\n/bin/bash: line 1: 17155 Alarm clock             /usr/sbin/httpd -DTrafficShield -DAVRUI -DWebAccelerator -DSAM\n"
    [root@LTM1:Active:Standalone] config #
     
  3. confirm if the device has syslog configured
    If there is syslog configured in /config/bigip_base.conf, please remove the syslog configuration
    To remove syslog Reference
    K13080: Configuring the BIG-IP system to log to a remote syslog server (11.x - 16.x)
     
  4. Run command below to load configuration you have just modified

    # tmsh load sys config

  5. Run command below to restart httpd and tomcat and syslog-ng on bash

    # bigstart restart httpd tomcat syslog-ng

  6. Verify all the daemons are back up and show running status

    # bigstart status httpd tomcat syslog-ng

  7. Once confirm HTTPD is up and running, test to access Configuration Utility on Web browser
