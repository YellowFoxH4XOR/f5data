K10232: The pvac process logs a warning message when the Expires header value pre-dates the current Unix epoch

Known Issue

This is the result of a known issue. When the origin web server (OWS) sends a response that contains an Expires header whose value pre-dates the beginning of the current Unix epoch (00:00:00 UTC on January 1, 1970), the BIG-IP WebAccelerator logs a warning message in the /var/log/wa/pvac.log file that appears similar to the following example :

WA Debug: {...} Invalid Expires header received (<Expires_date>}, setting to {<setting_to_date>}

Note: The value of Expires_date is the human readable date set by the webserver in the Expires header. The setting_to_date is the date inserted in its place by the BIG-IP WebAccelerator. The value of the setting_to_date is typically a date far in the future, and is expressed in seconds since the Unix epoch.

For example, the BIG-IP WebAccelerator receives a response that includes the following header:

Expires: Wed, 31 Dec 1969 23:59:59 GMT

The BIG-IP WebAccelerator will then log the following warning message:

WA Debug: {...} Invalid Expires header received {Wed, 31 Dec 1969 23:59:59 GMT}, setting to {3709631057}

Note: The setting_to_date value of 3709631057 seconds since the Unix epoch equates to Mon, 21 Jul 2087 13:04:17 GMT.

Such logging with each response may add significant system overhead and consume excessive disk space.

F5 Product Development tracked this issue as CR117836 and it was fixed in BIG-IP WebAccelerator 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Note: For information about a related issue, refer to K8569: Expires HTTP headers with a non date value of 0 or -1 are logged as invalid.

Workaround

You can work around this issue by modifying the Expires date to be within the current Unix epoch. To do so, perform the following procedure depending on your software version:

WebAccelerator 10.0.x

  1. Log in to the command line.
  2. Enter the following text at the command line:

    bpsh <<END
    syslog include "
    filter f_pvac {
        facility(kern) and match(\"WA\") and not match(\"Invalid Expires header\");
    };"
    END
  3. Press the Enter key.
  4. To verify the syntax, enter the bigpipe syslog include command and compare with the output:

    SYSLOG - Include Data:
    filter f_pvac {
        facility(kern) and match("WA") and not match("Invalid Expires header");

    Note: To revert the changes, enter the bigpipe syslog include none command.

WebAccelerator 9.4.x

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Back up the original profile_base.conf file by typing the following command:

    cp /config/profile_base.conf /config/profile_base.conf.sol10232
  3. Open the /config/profile_base.conf file in a text editor.
  4. Locate the _sys_WA_serverside iRule, which begins approximately around line 1490 with the following line:

    rule _sys_WA_serverside {
  5. Modify the HTTP_RESPONSE section of the iRule to match the following example:

    rule _sys_WA_serverside {
    ...
      when HTTP_RESPONSE {
          if { [HTTP::header value "Expires"] <= "0" } {
            set exp_time [HTTP::header value "Expires"]
          } else {
            set exp_time [ clock scan "[ HTTP::header value "Expires" ]" ]
          }
           if {$exp_time <= 0 } {
             set header_date "Thu, 01 Jan 1970 00:00:01 GMT"
             HTTP::header replace "Expires" $header_date
          }
          if {$tmm_wa_no_detach == 1} {
            # Don't detach or disable if NTLM authorization
    }
    }
    ...
  6. Exit and save the file
  7. Load the new configuration by typing the following command:

    bigpipe load
  8. Clear the cache and restart the pvac process by typing the following command:

    wa_clear_cache

    Important: This operation will interrupt traffic flowing through the BIG-IP WebAccelerator for a few seconds.
