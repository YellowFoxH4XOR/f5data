K000162099: Resolving AWAF Attack Signature Count Discrepancies in BIG-IP HA Environments Due to ASM Synchronization Settings

Type
Support Solution
Published
2026-07-06
Updated
2026-07-06
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162099

Description

In BIG-IP Advanced WAF high-availability (HA) deployments, a significant difference in the number of attack signatures between Active and Standby devices can occur. This results in inconsistent security enforcement, where application traffic is rejected with AWAF security violations after a failover to the Standby device. The following error may be encountered when attempting to enable ASM synchronization on device groups:

 

0107142c:3: The device /Common/unit1.example.com cannot exist in more than one asm device group /Common/datasync-device-unit2.example.com-dg

 

Environment

  • Product: BIG-IP Advanced WAF
  • Version: 17.5.1
  • High-availability (HA) deployment with Active and Standby devices
  • Device group configuration with asm-sync initially disabled
  • Both devices have network connectivity to F5's update server (callhome.f5.com)

 

Cause

ASM synchronization (asm-sync) was disabled on the device groups, preventing attack signatures, security policies, and related metadata from being synchronized between Active and Standby devices. This led to inconsistent signature databases and enforcement behavior after failover.

Answer/Recommended Actions

To resolve AWAF attack signature discrepancies in HA environments:

1. Enable ASM Synchronization on Device Groups

  • On the Active device, enable ASM sync for the relevant device group:
    • tmsh modify cm device-group <device-group-name> asm-sync enabled
    • tmsh save sys config
  • If you encounter the error about a device existing in more than one ASM device group, revert the change and ensure each device is only a member of a single ASM-enabled device group. You may need to perform this step via the GUI if the CLI fails.

2. Verify ASM Sync Status

  • Run the following to confirm ASM sync is enabled:
    • tmsh list cm device-group <device-group-name> asm-sync
  • The output should show asm-sync enabled for the device group.

3. Trigger a Full ConfigSync

  • From the Active device, run:
    • tmsh run cm config-sync to-group <device-group-name>

4. Verify Attack Signature Counts

  • On both Active and Standby devices, check the signature counts:
    • restcurl -u admin: /mgmt/tm/asm/signature-sets?\$select=name,signatureCount
  • The counts should now be consistent across both devices.

5. Monitor Post-Sync Behavior

    • After synchronization, monitor the Standby device to confirm signature counts match and that no unexpected AWAF violations occur after failover.

 

Additional Information

The auto-sync enabled setting on device groups only applies to general BIG-IP configuration objects; ASM objects require asm-sync to be explicitly enabled.

Both devices must have network connectivity to F5's update server (callhome.f5.com) to receive attack signature updates, but this alone does not synchronize ASM objects between HA peers.

If you encounter issues enabling ASM sync via CLI, use the GUI to ensure device group membership and ASM sync settings are correct.
