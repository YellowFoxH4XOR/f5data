K000160576: OTEL collector sidecar container is missing in f5ingress controller pod

Type
Support Solution
Published
2026-04-01
Updated
2026-04-02
Applies to
  • BIG-IP Next
  • BIG-IP Next for Kubernetes: 2.2.0
Source
https://my.f5.com/manage/s/article/K000160576

Description

When upgrading to or installing CNF v2.2.x, the OTEL (OpenTelemetry) collector sidecar container is no longer present in the f5ingress controller pod. Instead, OTEL is deployed as a separate standalone pod due to an architectural change in CNF 2.2.0.

Environment

  • F5 CNF (BIG-IP Next for Kubernetes)
  • Kubernetes environment
  • Version: 2.2.0 and later

Cause

OTEL is having an Archiecture change. OTEL is now a seperate pod and no longer a side car like previous v2.0.

Answer/Recommended Actions

We recommend to enabled the following parameters within the override-values.yaml file

stats_collector.enabled=true

Additional Information

Example: override-values.yaml

```

tmm:

 customEnvVars:

  - name: OPENSHIFT_VFIO_RESOURCE_2

   value: "sriovEns1f0Mlx5NetdevPolicy"

  - name: OPENSHIFT_VFIO_RESOURCE_1

   value: "sriovEns1f1Mlx5NetdevPolicy"

  - name: PAL_CPU_SET

   value: 0,2

  - name: TMM_MAPRES_IGNORE_MEM_LIMIT

   value: "true"

 vxlan:

  enabled: false

 dynamicRouting:

  enabled: false

 debug:

  enabled: true

 cniNetworks: openbrackets/ob-dev-w0-ens2f0-vfio-3741,openbrackets/ob-dev-w0-ens2f1-vfio

 grpc:

  enabled: true

 icni2:

  enabled: true

 

 network:

  attachment:

   definitionName: "openbrackets/ob-dev-w0-ens2f1-vfio"

  vfio:

   enabled: false

 

f5-toda-logging:

 enabled: true         <----

 tmstats:

  enabled: true        <----

 type: stdout

 

controller:

 watchNamespace: openbrackets-app

 fluentbit_sidecar:

  enabled: true        <----

  fluentd:

   host: localhost

stats_collector:

 enabled: true        <----

 prometheus_nodePort: 30000. <----

 image:

  repository: artifactory.f5net.com/dockerhub-remote/otel

  name: opentelemetry-collector-contrib

  tag: 0.75.0

  pullPolicy: Always

grafana:

 enabled: true         <----

 port: 32000

prometheus:

 enabled: true         <----

 port: 30000

```

By default, stats_collector.enabled is set to false. You must explicitly set it to true to enable the OTEL collector pod.
