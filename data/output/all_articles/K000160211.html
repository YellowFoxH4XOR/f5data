K000160211: BIG-IP REST API Device Trust Fails with HTTP 400 and 500 Errors Due to Missing configsync-ip

Description

Adding a BIG-IP VE device to an orchestrator or device group using the F5 Trusted Device API can fail unless a configsync-ip is defined on the device being added. The process results in HTTP 400 or 500 errors, and the device state is reported as "POST_FAILED" in the orchestrator. REST API calls to retrieve device certificates either time out or return error codes. Key error messages and symptoms include:

  • REST API calls (GET/POST) to endpoints such as /mgmt/shared/device-certificate return 400 or 500 errors.
  • The orchestrator logs show the device being removed in "POST_FAILED" state.
  • restjavad logs on the BIG-IP device show exceptions such as java.lang.NullPointerException, AsyncContext timeout, and java.util.concurrent.TimeoutException.
  • The issue persists even after increasing REST timeouts, restarting restjavad/restnoded, and clearing REST storage.

Environment

  • Product: BIG-IP LTM
  • Features: F5 Trusted Device API, iControl REST, device trust/orchestration
  • configsync-ip may not be set on the affected device
  • clear-rest-storage procedure may have been run prior to experiencing this issue

Cause

The root cause is the absence of a configured configsync-ip address on the affected BIG-IP device. This results in the REST API's internal discovery address being null, which causes certificate retrieval operations to fail with 400 errors and leads to timeouts and "POST_FAILED" states in orchestrator workflows.

Answer/Recommended Actions

To resolve the issue, ensure that the BIG-IP device has a configsync-ip address configured. Follow these steps:

  1. Set the configsync-ip for the device:
    Run the following command, replacing <device_name> and <self_ip> with your device's name and the appropriate self IP address:

    tmsh modify cm device <device_name> configsync-ip <self_ip>

  2. Save the configuration:

    tmsh save sys config

  3. Restart the restjavad process to apply changes:

    bigstart restart restjavad

  4. (Optional) If the issue persists, also restart restnoded and httpd:

    bigstart restart restnoded

    bigstart restart httpd

  5. Re-attempt the device trust/orchestration operation.

Additional Information

  • The issue can be reproduced by making a REST API call to /mgmt/shared/device-certificate on the affected device, which will return a 400 or 500 error if configsync-ip is not set.
  • The problem may be triggered or exposed after running clear-rest-storage, but the underlying cause is the missing configsync-ip.
  • The workaround is persistent and survives subsequent clear-rest-storage operations as long as configsync-ip remains configured.
