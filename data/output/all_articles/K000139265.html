Description

You are trying to integrate LDAP with BIG-IP APM and you mat be performing authentication tests with commands similar to these ones:

adtest -t auth "example.com" -u john_smith
Please enter user password:

And you observe the following error:

ERROR: authentication with 'john_smith' failed: Failed to resolve KDCs by domain name (-1)
Test done: total tests: 1, success=0, failure=1

You take a packet from BIG-IP CLI to investigate the root cause of this behavior similar to this one:

tcpdump -nnvi 0.0:nnnp -s0 host <kerberos_kdc_ip_addr> -w /var/tmp/"$HOSTNAME"_kdc_"$(date +%H-%M-%S-%d-%m-%y)".pcap

And you notice DNS query responses similar to these ones:

Standard query response 0x4c67 No such name SRV _kerberos._udp SOA a.root-servers.net RRSIG NSEC aaa RRSIG OPT

Environment

  • APM

  • LDAP

  • DNS

Cause

The BIG-IP system is not responsible for this error.  Cross-domain authentication fails because the configured DNS in the BIG-IP does not know how to resolve the SRV records. 

This error signifies that during LDAP authentication attempts, the BIG-IP system cannot resolve the Key Distribution Center (KDC) through its domain name, even though the LDAP settings include a direct IP configuration. Packet captures from the authentication attempts reveal that DNS queries for SRV records related to Kerberos authentication receive 'No such name' responses, indicating that the DNS server lacks the necessary SRV records.

Recommended Actions

Confirm that the DNS settings on the BIG-IP APM are correct and the designated DNS server can resolve the domain's FQDN. Also Check your DNS server for the presence of Kerberos-related SRV records, such as _kerberos._tcp.dc._msdcs.<example.com>.
