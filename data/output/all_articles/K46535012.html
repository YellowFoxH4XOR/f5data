Known Issue

Reclaiming unused disk resources may fail on a Virtual Clustered Multiprocessing (vCMP) system.

This issue occurs when the following condition is met:

  • You attempt to reclaim unused space from a vmdisks volume by using the lvreduce command.

When vCMP is provisioned on the BIG-IP system, the system creates an application volume (vmdisks) that consumes the remaining available disk space. The next action that requires additional disk space, such as a software upgrade, may fail to run. For the software upgrade to run successfully, you may need to reclaim unused space from the file system by using the lvreduce command. For more information, refer to K15915: Reallocating disk resources when upgrading a vCMP system.

Impact

You cannot resize the vmdisks application volume to reclaim unused disk resources.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Attempts to run the lvreduce command fail with an error message similar to the following example:

    # lvreduce --resizefs --size -10G /dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks
    /usr/sbin/fsadm: line 225: blockdev: command not found
    fsadm: Cannot read size of device "/dev/mapper/vg--db--sda-app.vcmp.dat.vmdisks"
    fsadm failed: 1

Workaround

To work around this issue, you can copy the /sbin/blockdev executable file from a BIG-IP device running version 11.6.0-HF6 or 12.x and install it on the BIG-IP device affected by this issue. If you do not have an 11.6.0 HF6 or 12.x system to copy the /sbin/blockdev file from, you can contact F5 Support and request one.

Note: If the receiving system is a multi-blade VIPRION , you must install the file on each blade.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
