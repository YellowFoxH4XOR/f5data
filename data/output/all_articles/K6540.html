Known Issue

This is the result of a known issue. After you create an alias of a Windows File favorite, the correct icon will appear, but the name of the alias and the path to the shared folder are not displayed next to the icon. You will not be able to view the name of the alias and the path to the shared folder, even after refreshing or revisiting the Portal Access: Window Files: Resources page. The alias name, however, will appear correctly when you log in to the FirePass controller and view the Windows Files favorites on the Webtop, and the favorite will function correctly when activated.

F5 Product Development tracked this issue as CR68029 and it was fixed in FirePass version 6.0.1. For information about upgrading, refer to the FirePass release notes.

Additionally, this issue has been fixed in cumulative hotfix HF-600-3 for FirePass version 6.0.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing hotfixes.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

Workaround

You can work around this issue by changing the Type field from Alias to Favorite on the affected Windows Files favorite. To do so, perform the following procedure:

  1. Log in to FirePass controller as admin, or with an account that has administrator privileges.
  2. From the Portal Access : Windows File : Resources page, select the correct resource group from the Resource Group drop-down menu.
  3. Click the edit icon (I beam) for the Windows Files Alias you want to edit.
  4. From the Type: drop-down menu, select Favorite instead of Alias.
