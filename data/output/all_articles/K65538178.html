Description

Blade starts to fail suddenly. It reboots and comes up again. 

Environment

  • VIPRION
  • Hardware
  • Unexplained reboots

Cause

BIG-IP platform encountered Machine Check Exception (MCE) errors. You can find those log message alerts under /var/log/kern logs. Below are the examples.

Mar 22 13:24:24 device.mgmt info kernel: mce: [Hardware Error]: Machine check events logged
Mar 22 13:24:24 device.mgmt emerg kernel: mce: [Hardware Error]: CPU 0: Machine Check: 0 Bank 9: 8c000051000800c0
Mar 22 13:24:24 device.mgmt emerg kernel: mce: [Hardware Error]: TSC 0 ADDR 15bb9ef000 MISC 90840004000628c
Mar 22 13:24:24 device.mgmt emerg kernel: mce: [Hardware Error]: PROCESSOR 0:306f2 TIME 1647951864 SOCKET 0 APIC 0 microcode 3a

Some of these may be correctable errors but some may be actual hardware issues in the CPU, memory, or maybe even the connectors between them.

Recommended Actions

  1. In order to determine if those are correctable or non-correctable errors you can run the following command:
    zcat -f -- /var/log/kern.* 2>/dev/null | awk '{if($0 ~ /Machine Check:/){printf($1 " " $2 " " $3);if($4 ~/slot/){printf(" " $4);}printf(": " $(NF -2) " " $(NF -1 ": "));mce=gensub(/(.{8})(.{4})(.*)/, "[\\1][\\2][\\3]","g",$NF);printf(mce);if(mce ~ /\[0008\]/){print(" : Correctable : Action > None")}else{print(" : Non-Correctable : Action > RMA")}}else if($0 ~ "boot_marker"){print($1,$4)}}'

  2. If it turns out those are non-correctable errors 

    (Non-Correctable: Action > RMA)


    please create a service request to replace the unit following article:
    K12882: Overview of the F5 RMA process
