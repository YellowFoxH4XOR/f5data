Description

When F5 Distributed Cloud Customer Edge (CE) sites lose connectivity to the Regional Edge (RE) and the Global Controller (GC), services dependent on the Global Controller for certificate authority (CA) validation, routing, and load balancing decisions may become unavailable. CE Site Survivability addresses this by enabling the CE to assume local control plane responsibilities and maintain service availability for the duration of the outage.

  • How can F5 Distributed Cloud Customer Edge sites continue to serve traffic when connectivity to the Global Controller and Regional Edges is lost?
  • What is CE Site Survivability and how does it work?
  • How is CE Offline Survivability Mode enabled on a Customer Edge site?
  • How is a Site Mesh Group configured to support CE-to-CE survivability routing?
  • How does the CE handle SSL certificate validation and load balancing decisions when disconnected from the Global Controller?
  • How can CE Site Survivability be verified after configuration?

Environment

  • F5 Distributed Cloud (SaaS)
  • Customer Edge (CE) sites — AppStack or standard CE persona
  • Two or more deployed CE sites
  • Site Mesh Group configured with Full Mesh topology (Control and Data Plane Mesh)
  • CE sites experiencing or at risk of complete loss of connectivity to:
    • Regional Edge (RE) sites
    • Global Controller (GC)
    • Other CE sites within the Site Mesh Group
  • HTTP Load Balancers with multi-priority Origin Pools configured (optional, for local failover behavior)
  • AppStack (K8s workloads on CE) in use — optional, applicable to the Bookinfo distributed app example

Cause

By default, F5 Distributed Cloud CE sites rely on the Global Controller for certificate authority (CA) management, identity verification, and routing decisions. When connectivity between a CE site and the Global Controller is lost — whether due to planned network maintenance or an unintended outage — services requiring CA validation fail because the root CA is unreachable. Additionally, routing between CE sites in a Site Mesh Group fails due to the inability to verify identity management certificates. CE Site Survivability addresses these failure points by enabling each CE to stand up a local control plane and local CA when the Global Controller is unreachable.

Answer/Recommended Actions

Enable CE Offline Survivability Mode on each participating CE site and configure a Full Mesh Site Mesh Group to allow CE-to-CE routing and control plane continuity during upstream connectivity loss. The following steps walk through the full configuration.

Prerequisites

  • Two or more deployed F5 Distributed Cloud CE sites.
  • Appropriate permissions in the Distributed Cloud Console.

Step 1: Create a Virtual Site for CE Survivability

  1. Log in to the F5 Distributed Cloud Console and navigate to Shared Configuration → Virtual Sites → Add Virtual Site.
  2. Configure the Virtual Site with the following values:
    • Name: full-mesh-ce-sites
    • Site Type: CE
    • Selector Expression: ves.io/siteType = ves-io-ce
  3. Save the configuration.

Step 2: Enable Offline Survivability Mode on Each CE Site

  1. Navigate to Cloud & Edge Sites → Site Management → [your site type] → [Your Site] → Manage Configuration.
  2. Scroll to Advanced Configuration and click Show Advanced Fields.
  3. Enable Offline Survivability Mode.
  4. Save and apply the configuration. The CE site will restart to apply the setting.
  5. Repeat this process for each CE site identified by the Virtual Site Selector Expression configured in Step 1.

Note: The Offline Survivability status will display as Configured immediately after enabling the setting. It transitions to Enabled only after the CE restarts. Confirm the current status by navigating to the CE Site Dashboard and reviewing the Offline Survivability field within the Software Version frame.

Step 3: Create a Full Mesh Site Mesh Group

  1. Navigate to Cloud & Edge Sites → Networking → Add Site Mesh Group.
  2. Configure the Site Mesh Group with the following values:
    • Name: full-mesh-ce-group
    • Virtual Site: shared/full-mesh-ce-sites
    • Mesh Choice: Full Mesh
    • Full Mesh Choice: Control and Data Plane Mesh
  3. Save the configuration.

Step 4: Verify CE Survivability Configuration

  1. Navigate to Cloud and Edge Sites → Site Connectivity → Site Mesh Group.
  2. Select the Site Mesh Group created in Step 3.
  3. Click on each site within the group and confirm the following in the site detail panel:
    • Offline Survivability: Enabled (in the Detail panel)
    • Local Control Plane Status: Enabled (in the Health panel)

To confirm CE-to-CE L3 routing is operational through the Site Mesh Group tunnel:

  1. Open the Site Dashboard for a participating CE.
  2. Navigate to the Tools section and select Show Routes.
  3. Set the Virtual Network Type to VIRTUAL_NETWORK_SITE_LOCAL_INSIDE.
  4. Confirm that routes to origin servers at remote CE sites appear in the routing table, indicating that L3 routing between CE sites is functional without traversing the Global Network.

Configuring HTTP Load Balancers for Local Failover (Optional)

To take advantage of CE Survivability for HTTP Load Balancing, configure Origin Pools with priority levels:

  • Priority 1 (Primary): Remote origin pool (e.g., origin in AWS) — used under normal conditions.
  • Priority 0 (Backup): Local origin pool — used only when no higher-priority origin pool is available.

When the CE loses connectivity to the Global Controller and the primary origin becomes unreachable, the CE automatically shifts load balancing decisions to the local control plane and routes traffic to the Priority 0 local origin pool. An example HTTP Load Balancer YAML configuration for a multi-site deployment is shown below:

metadata:
  name: booking-ratings-multisite
  namespace: default
  labels:
    ves.io/app_type: bookinfo
  annotations: {}
  disable: false
spec:
  domains:
    - ratings.cluster.local
    - ratings
  http:
    dns_volterra_managed: false
    port: 9080
  advertise_custom:
    advertise_where:
      - site:
          network: SITE_NETWORK_INSIDE_AND_OUTSIDE
          site:
            tenant: default
            namespace: system
            name: azure-vnet-wus2
            kind: site
          use_default_port: {}
  default_route_pools:
    - pool:
        tenant: default
        namespace: default
        name: bookinfo-ratings-aws
        kind: origin_pool
      weight: 1
      priority: 1
      endpoint_subsets: {}
    - pool:
        tenant: default
        namespace: default
        name: bookinfo-ratings-local
        kind: origin_pool
      weight: 1
      priority: 0
      endpoint_subsets: {}
  routes: []

Note: Origin pools must be pre-configured before applying this Load Balancer configuration. To apply, navigate to Manage → Load Balancers → HTTP Load Balancers → Add HTTP Load Balancer, select JSON view, and switch to YAML config format.

SSL Certificate Handling During Outage

When a CE loses connectivity to the Global Controller, any SSL-backed services whose certificates can no longer be validated against the Global Controller's root CA are automatically re-issued using the CE's local internal CA. This preserves the SSL chain of authority for the duration of the outage, allowing encrypted services to continue operating without manual intervention.

Additional Information

CE Site Survivability addresses connectivity loss across the following scenarios:

  • Nodes within a multi-node Customer Edge site
  • Customer Edge site and Regional Edge (RE) sites
  • Customer Edge site and the Global Controller (GC)
  • Customer Edge sites within a Full Mesh Site Mesh Group
  • Hub/Spoke Site Mesh Group support and DC Cluster Group support are planned for future releases

When CE Survivability activates, two key functions are assumed locally by the CE:

  • Local Control Plane: A local CA is established under a new root CA trusted by services within the tenant. This enables certificate issuance and validation to continue locally without requiring connectivity to the Global Controller.
  • Local Routing: BGP is used to exchange routing information between nodes within the CE site and between CE sites within the Site Mesh Group, ensuring optimal connectivity is maintained during the outage.

Important limitations to be aware of:

  • A maximum of seven days is supported for a CE site to operate in survivability mode without connectivity to the Global Controller. After this period, certificates and routing may degrade.
  • While the CE is offline and isolated from the Global Network, request visibility in the Distributed Cloud Console will not be available. Local tooling (e.g., kubectl exec and curl within the cluster) can be used to confirm that traffic continues to be served locally.
  • To artificially simulate an offline scenario for testing without physically disconnecting the CE, security policies can be configured to block inbound connections from remote CE sites and outbound connections to F5 Global Network RE sites and the Global Controller. Since IPSEC and SSL tunnel connections can be long-lived, it may also be necessary to SSH into the CE site's CLI and soft-restart the ver, vpm, ike, and openvpn services.

The Bookinfo application (maintained by Istio) is a practical reference for validating CE Survivability in a distributed K8s workload context. For deployment instructions, refer to the Istio Bookinfo documentation.
