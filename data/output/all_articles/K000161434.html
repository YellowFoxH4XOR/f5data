K000161434: AS3 Fails with 4xx Errors on /mgmt/tm/util/bash After Upgrading BIG-IP to 17.5.1.6

Description

AS3 (f5-appsvcs) fails with 400-level errors after upgrading BIG-IP LTM to v17.5.1.6. AS3 receives a 403 response when attempting to POST to /mgmt/tm/util/bash, with the error message "Direct access to /mgmt/tm/util/ is not permitted." This prevents AS3 from executing bash commands for tenant configuration queries.

Relevant log messages (restnoded.log):

  • [RestOperationDispatcher] 'shared/service-discovery/task' not found.
  • [ErrorHandlingModule] RestOperation failed: "/shared/service-discovery/task?$filter=partition+eq+%27<tenant>%27". {"code":404,"message":"",...}
  • [appsvcs] {"message":"Unable to fetch state from /mgmt/shared/service-discovery/task","level":"warning"}
  • [appsvcs] {"message":"Error: POST .../mgmt/tm/util/bash execute bash command response=403 body={\"code\":403,\"message\":\"Direct access to /mgmt/tm/util/ is not permitted.\"}","code":"400","level":"error"}
  • [appsvcs] {"message":"Error: failure querying config for tenant <tenant> (POST .../mgmt/tm/util/bash execute bash command response=403 ...)","code":"400","level":"error"}

Environment

  • BIG-IP LTM
  • AS3 (f5-appsvcs) versions below 3.57.0 or later
  •  Upgraded to version 17.5.1.6 (or higher)

Cause

BIG-IP v17.5.1.6 introduced a security change as part of a jQuery upgrade addressing CVE-2020-11023. This change blocks direct REST access to /mgmt/tm/util/, which AS3 relies on internally via POST requests to /mgmt/tm/util/bash. With this endpoint now restricted, AS3 receives a 403 response and fails with 400-level errors when querying tenant configuration. This is a regression in AS3 compatibility introduced by v17.5.1.6.

Recommended Actions

  1. Upgrade AS3 to version 3.57.0 or later, which contains a fix for the blocked REST access introduced in BIG-IP v17.5.1.6.
  2. Install the updated AS3 RPM on the BIG-IP running v17.5.1.6.
  3. Verify AS3 operations complete successfully and tenant configuration queries no longer produce 403/400 errors.

Temporary Workaround:

  • Roll back BIG-IP to previouse version to restore AS3 functionality until the updated AS3 RPM (v3.57.0 or later) can be installed.

Additional Information

  • This issue affects all AS3 versions prior to 3.57.0 when running on BIG-IP v17.5.1.6. Upgrading or reinstalling AS3 to a version earlier than 3.57.0 does not resolve the problem, as the root cause is a REST access restriction introduced in BIG-IP v17.5.1.6.
  • The security change in v17.5.1.6 was intentional (addressing CVE-2020-11023), but it inadvertently broke AS3's internal communication pattern. AS3 3.57.0 was updated to work within these new restrictions.
