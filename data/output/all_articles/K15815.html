Known Issue

Endpoint Security Client-Side checks may cause the system to unexpectedly terminate user sessions.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy is configured with an Endpoint Security (Client-Side) check.
  • Users are running the Mac OS or Linux operating systems.
  • The Endpoint Security check is configured with the setting Continuously check the result and end the session if it changes set to Enabled.
  • The access policy uses logic similar to the following example for the Endpoint Security (Client-Side) check using the fallback branch:

    For example:

    The client-side Endpoint Security check expression uses syntax similar to:

    "vim OR scutil"

    When either process is detected the fallback branch is utilized.

Impact

The system logs the user off of the session.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The user's session unexpectedly terminates within seconds of establishing a session with the BIG-IP APM access profile.

Workaround

To work around this issue, you can configure a recurrent policy check expression to allow access based on the successful branch of the access policy. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Changing the logic used in the client-side access policy Endpoint Security check

  1. Log in to the BIG-IP APM Configuration utility.
  2. Navigate to Access Policy > Access Profiles > Access Profiles List.
  3. To open the VPE editor, click Edit to the right of the affected access policy.
  4. In the visual policy editor, click the (x) in the upper right corner of the affected Linux or Mac OS Process check that you want to delete.
  5. Click Delete.
  6. Click the (+) to the left of where the Client-Side endpoint security check previously existed.
  7. Select the Endpoint Security (Client-Side) tab.
  8. Select the button for Linux Process or Mac Process, depending on the OS process check you are implementing.
  9. Type negative logic syntax in the Process Checker Expression box.

    The following is an example of negative logic syntax:

    "NOT vim AND NOT scutil"

  10. In the Continuously check the result and end the session if it changes box, select Enabled.
  11. Click Save.
  12. Select the Deny ending box for the Successful branch.
  13. Click the Allow button.
  14. Click Save.
  15. In the upper-left corner of the page, click Apply Access Policy.
