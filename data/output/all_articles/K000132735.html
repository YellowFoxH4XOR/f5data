K000132735: BIG-IP Edge Client covpn64.sys file can be rolled back or forward during Windows RAS/PPP errors.

Type
Support Solution
Published
2023-02-23
Updated
2023-02-23
Applies to
  • BIG-IP
  • BIG-IP APM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000132735

Description

The BIG-IP Administrator may notice that the version of the BIG-IP Edge Client related covpn64.sys file (as part of urxvpn.cab) can be rolled back or rolled forward on the user's machine. F5 product engineering is tracking this behaviour as 1232593.

Environment

  • BIG-IP APM Edge Client
  • APM Clients iso
  • covpn64.sys
  • urxvpn.cab

Cause

The covpn64.sys version on the client can roll back or forward under the following sequence of events:

  1. You have multiple BIG-IP APM systems and not all of them are updated with the same APM Clients version.
  2. A Windows client device connects to a BIG-IP APM system that has a different BIG-IP Edge Client component version.
  3. The client device encounters Windows RAS/PPP errors. See K35554459 for more details.
  4. The client device updates its client component version using the covpn64.sys downloaded from the BIG-IP APM system.
  5. The version of the covpn64.sys is updated on the client, rolling back/forwards depending on the version difference between client-side (Windows) and server-side (BIG-IP APM).

Recommended Actions

  1. Ensure that all your BIG-IP APM gateways have the same APM Clients version. For more information on APM Clients version, refer to K81649656.
  2. If it is not possible to maintain all your BIG-IP APM systems at the same APM Clients version (such as when they are maintained by different organizations/departments and administrators), there is an option to configure the BIG-IP APM virtual server with an iRule to respond with a specific version of the covpn64.sys file, instead of the covpn64.sys file from the installed APM Client iso. This way you can prevent the covpn64.sys file version from rolling back or forward on the client side.

F5 would like to acknowledge Magnus Sandin, F5 BIGIP APM specialist at Valitron AB, for providing the iRule workaround. To implement the workaround, perform the following procedure:

Scenario: The client device has client components v7231 installed, but the BIG-IP APM gateway is running APM Client v7220.

a. Upload to the BIG-IP APM gateway as an iFile, the urxvpn.cab file you want client devices to download. You can do so on the BIG-IP Configuration utility at System > File Management > iFile and Local Traffic > iRules > iFile List.

The following illustrates an example of the iFile in the bigip.conf file:

ltm ifile /Common/URXVPN.CAB-7231.2022.1019.0458 {

  file-name /Common/URXVPN.CAB-7231.2022.1019.0458

}

b. Create an iRule using the following:

when CLIENT_ACCEPTED {

ACCESS::restrict_irule_events disable

}

# Mozilla/5.0 (compatible; MSIE 10.0; Windows NT 6.1; Trident/6.0; F5 Networks Client)

when HTTP_REQUEST {

set uri [HTTP::uri]

set ua [HTTP::header "User-Agent"]

if {$uri starts_with "/vdesk" || $uri starts_with "/pre"} {

set version ""

regexp -- {EdgeClient/(\d{4}\.\d{4}\.\d{4}\.\d{4})} $ua var version

if {$version != ""} {

table set -subtable vpn_client_ip_to_versions [IP::client_addr] $version 86400 86400

log local0.debug "Saving Client version $version for IP: [IP::client_addr]"

} else {

log local0.debug "Unable to parse version from: $ua"

}

} elseif {$uri == "/public/download/urxvpn.cab"} {

set version ""

regexp -- {EdgeClient/(\d{4}\.\d{4}\.\d{4}\.\d{4})} $ua var version

if {$version == ""} {

log local0.warning "Unable to parse version from: $ua, will search sessoin table"

set version [table lookup -subtable vpn_client_ip_to_versions [IP::client_addr]]

log local0.warning "Version in table: $version"

}

if {$version == ""} {

log local0.warning "Unable to find version session table"

HTTP::respond 404 content "Missing version in request" "Content-Type" "text/plain"

} else {

set out ""

catch {

set out [ifile get "/Common/URXVPN.CAB-$version"]

}

if {$out == ""} {

log local0.error "Didn't find urxvpn.cab file for Edge Client version: $version"

HTTP::respond 404 content "Unable to find requested file for version $version\n" "Content-Type" "text/plain"

} else {

log local0.debug "Sending urxvpn.cab for Edge Client version $version"

HTTP::respond 200 content $out "Content-Type" "application/vnd.ms-cab-compressed"

}

}

}

}

c. Associate the iRule to the BIG-IP APM VPN Virtual server

The next time a Windows client device connects to a BIG-IP APM gateway as described in the Cause section of this article, and requests /public/download/urxvpn.cab, the BIG-IP APM system responds with the urxvpn.cab that you uploaded as an iFile in step 2.a, instead of a urxvpn.cab that corresponds to the APM Client version of the BIG-IP system.
Caution: If two different clients connect from the same external IP address to the BIG-IP and those clients run different versions, then the wrong version of the urxvpn.cab may be installed on the clients.
