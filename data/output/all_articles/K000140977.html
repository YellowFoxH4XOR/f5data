K000140977: F5OS Can not Login to CLI/Console Using Any User But GUI Works Fine

Type
Support Solution
Published
2024-09-06
Updated
2024-09-06
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.8.X, 1.5.X, 1.8.0, 1.7.0, 1.5.2, 1.5.1, 1.5.0
Source
https://my.f5.com/manage/s/article/K000140977

Description

You can not log in to the SSH CLI and Serial Console with any users even if the password is correct, including the local admin and root user. The GUI can be logged in without any issue.

You may find it immediately closes the SSH connection when trying to log in via SSH, for example:

ssh root@192.168.1.2
Trying to connect 192.168.1.2 using root account...
Warning: Permanently added '192.168.1.2' (ED25519) to the list of known hosts.
root@192.168.1.2's password:
Connection closed by 192.168.1.2 port 22

 

For console access, it looks like：

Kernel 3.10.0-1160.71.1.F5.1.el7_8.x86_64 on an x86_64
appliance-1 login: root
Password:
Permission denied

 

When you are having this issue, you should have TACAS+ selected as one of the authentication methods for F5OS, AND, in the TACAS+ server group configuration, you have a blank character as the name.

For example:

For the Authentication Settings you have TACAS+ enabled:

For the corresponding TACAS+ server group, there is a blank in the name like "tacas server"

To trigger this issue, you might have re-configured the AAA passphrase and salt in the history by following the steps under the K47512994: Back up and restore the F5OS-A configuration on an rSeries system

Environment

  • F5OS
  • TACAS+
  • Passphrase and salt change 
  • F5OS backup and restore

Cause

This is identified as Bug ID 1635497.

Recommended Actions

To workaround the issue temporarily, you may consider reconfiguring the TACAS+ server group, especially, the server secret on each of the configured servers inside the group.

To avoid the issue completely, you should not involve any blank characters in the TACAS+ server group name.
