Topic

This article applies to BIG-IP 11.3.0 and later. For information about other versions, refer to the following article:

  • K13249: Access policy actions are processed for only the first authentication attempt (10.1.0 - 11.2.1)

Agent actions that are between a logon page agent and an authentication agent are not processed again after a failed authentication attempt. An access policy allows for creating actions that occur between the logon page action and the authentication action. These actions are processed only the first time the user submits their logon information for a session. If a logon attempt fails and the Max Logon Attempts authentication agent setting is greater than 1, the authentication actions processes the subsequent authentication attempts without returning to the logon page agent. This behavior is by design.

Recommended Actions

You can work around this behavior by creating or utilizing an existing Authentication and resources macro taking advantage of the Maximum Macro Loop Count feature of the macro. To use an existing Authentication and resources macro, perform one of the following procedures:

13.x and later

  1. Log in to the BIG-IP Configuration utility.
  2. Expand Access.
  3. Click Profiles/Policies.
  4. Click Edit next to the name of the access policy you are editing.

    The Access Policy editor opens in a new window.

  5. Adding an existing Authentication and resources macro to the access policy.
    1. Click Add New Macro.
    2. Select one of the authentication and resource assign macros that from the Select macro template drop-down menu.
    3. Click Save.
    4. Click Rename / Settings of the macro.
    5. Set the Maximum Macro Loop Count value from the drop-down menu (1 - 5 defaults to 1).
    6. Click Save.
    7. Click the + to the left of the macro you just created.
    8. Click the Authentication agent box.
    9. Configure the appropriate settings for your selected authentication agent.
    10. Set the authentication agent setting for Max Logon Attempts Allowed to 1 (one).

      Note: The following authentication agents support Max Logon Attempts Allowed: AD, LDAP, Radius, RSA SecurID, TACACS, Kerberos, and OAM.

    11. Click Save.
    12. Click the Resource Assign or Advanced Resource Assign box.
    13. Select the resources that you want to assign to the authenticated access session.
    14. Click Save.

      Important: Place any pre-authentication access policy agents inside the Authentication and resources macro.

  6. Remove all duplicated agents from the access policy that were recreated in the Authentication and resources macro by performing the following procedure:
    1. Click the x on the agent.
    2. Click the connecting the previous node to the proper output node option.
    3. Click delete.
    4. Repeat steps 1 through 3 for each agent that you want to delete from the access policy.
  7. Click the + at the point in the access policy flow where you want to insert the new Authentication and resources macro loop.
  8. Click the Macrocalls tab.
  9. Select Authentication and resources of the recently created macro.
  10. Click Add Item.
  11. Ensure that the Successful branch of the main access policy ending is set to Allow.
  12. Click the Apply Access Policy link in the upper-left corner of the Configuration utility.?
