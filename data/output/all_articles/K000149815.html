Description

BIG-IP randomly generates "DNScache: comm_point_tmm_recv_from failed: errno 103" error.

 

Feb 17 13:06:40 bigip.local err tmm5[18361]: DNScache: comm_point_tmm_recv_from failed: errno 103

K26157411 explains that 'errno 103' means "BIG-IP can not receive response, a connection expired, a connection aborted, or socket/data was unable to be read.". However, when capturing DNS packet between BIG-IP and name server, there was no problem found.

 

Environment

All of the following condition need to be met.

  • BIND (named) is not running on local BIG-IP and so not listening on 127.0.0.1:53.
  • Virtual server uses an iRule which calls "RESOLV::lookup" command.
  • No name server address is specified in "RESOLV::lookup" command inside iRule.

 

Cause

If no name server address is specified in "RESOLV::lookup" command (i.e., missing "@<IP>" option), TMM sends internal DNS traffic towards local BIND (named) 127.0.0.1:53. And if local BIND (named) is not running and 127.0.0.1:53 is closed, then ICMP port unreachable message is internally received by TMM. This ICMP port unreachable packet triggers "DNScache: comm_point_tmm_recv_from failed: errno 103" error.

 

Recommended Actions

First, consider using "RESOLVER::name_lookup" command instead of using "RESOLV::lookup" command. "RESOLV::lookup" command is deprecated. When "RESOLVER::name_lookup" command is used, even if there is no forwarder specified in dns-resolver, "DNScache: comm_point_tmm_recv_from failed: errno 103" error is not recorded.

 

Next, check if internal DNS traffic is really sent to 127.0.0.1:53 and ICMP unreachable packet is really received by TMM. To see internal DNS/ICMP traffic between TMM and local BIND (named), you can run tcpdump with "-i 0.0:h" modifier, as follows. The internal DNS traffic will not be captured unless we specify ":h" modifier.

Additionally, you may also want to research why BIND (named) is not running if you think BIND (named) should be locally running.

 

An example of BIND startup failure case is described in K000149370. Assume BIND options 'dnssec-lookaside' or 'dnssec-enable' were configured on named.conf before BIG-IP software upgrade. After BIG-IP software upgrade to 17.1.2+, BIND package was also upgraded to 9.18.28 from 9.16.33, and those BIND options are now invalid and those options prevent named from starting up on post-upgrade BIG-IP software version.
