Topic

This article describes BIG-IP Extended Application Verification (EAV) or external monitors, and provides a step-by-step procedure to implement a generic external monitor for an HTTPS pool member.

Description

External monitors let you create custom scripts that contain specific logic that is not available in built-in BIG-IP monitors to monitor the health of pool members and nodes. An external monitor contains the following three components:

  • A BIG-IP monitor that references a script.
  • A script that contains logic to determine the health of a back-end server.
  • A command in the script, such as cURL or Netcat, that interacts with the back-end server.

To create an external monitor, perform the following procedure:

Note: You should use an EAV external monitor only when the specific logic needed to determine the health of a pool member is not found in the built-in BIG-IP monitors. The external monitor you create in this procedure is for demonstration purposes only. It uses a basic curl command to probe an HTTPS pool member, which you can replace with the built-in BIG-IP HTTPS monitor. After successfully deploying this basic external monitor, you should customize your script further.

  • Create a custom script
  • Import the script to the BIG-IP system
  • Create a BIG-IP external monitor referencing the script
  • Configure a pool to use the external monitor to monitor its pool members

Create a custom script

Create a custom script that contains the logic to determine the health of your back-end server and save it to your client desktop. Use the sample monitor script found on the BIG-IP system as a template.

  1. Go to System > File Management > External Monitor Program File List.
  2. Select sample_monitor.
  3. Copy and paste the script onto a text editor on your client device.

    This sample script uses the nc command to probe a HTTP pool member at the following line:

    echo "GET /" | /usr/bin/nc $node_ip $2 2> /dev/null | grep -E -i $3 > /dev/null

    To monitor an HTTPS pool member, replace the line above in the script with the following line:

    curl -fNs -k https://${node_ip}:${2}${URI} | grep -i "${RECV}" 2>&1 > /dev/null

    The ${RECV} argument is the receive string you will specify when you create the BIG-IP monitor in the subsequent procedure. The script uses grep to compare the server response with this string to determine whether the service is up or down.

  4. Save this content on your client.

Import the script to the BIG-IP system

Import the script to the BIG-IP system through the Configuration utility or the command line. To import through the Configuration utility, perform the following procedure:

  1. Go to System > File Management > External Monitor Program File List.
  2. Select Import.
  3. Select Browse.
  4. Select the custom script you created.
  5. Enter a name for the script.

    For example:

    eav_custom_script

  6. Select Import.
  7. Some editors, such as Notepad on Windows, add trailing CR/LF new line characters to the script that causes the monitor to fail erroneously. For more information, refer to K14271: An imported external monitor may erroneously mark resources down. You can perform the following workaround:
    1. Select the name of the script, eav_custom_script, you just imported.
    2. Select Update.

The script is imported and saved at this location in the file system /config/filestore/files_d/Common_d/external_monitor_d. If you use a command line tool, such as scp, to import the script, ensure the system has at least 0700 and execute permissions to the script.

Create a BIG-IP external monitor referencing the script

  1. Go to Local Traffic > Monitors.
  2. Select Create.
  3. Enter a name.

    For example:

    eav_custom_monitor

  4. For Type, select External.
  5. For External Program, select the script you created in the previous procedure, eav_custom_script.
  6. In the Variable parameter, define the variable values used by the curl command that you added to the script in the previous procedure:

    curl -fNs -k https://${node_ip}:${2}${URI} | grep -i "${RECV}" 2>&1 > /dev/null

    To do so, supply the following Name and Value pairs to the Variable parameter:

    NameValue (Example)Description
    RECVWelcome to nginx!This is the string that the system will use to compare the server response with, to determine whether the service is up or down. For example, if the page you are requesting for is the NGINX default home page, define Welcome to nginx! 
    URI/index.htmlDefine the URI value that curl will request from your back-end server. You can leave this undefined if appropriate for your environment.

Configure a pool to use the external monitor to monitor its pool members

  1. Go to Local Traffic > Pools.
  2. Select the name of the pool to monitor.
  3. For Health Monitors, from the Available column, select eav_custom_monitor, the name of the monitor you created in the previous procedure.
  4. Select <<.
  5. Select Update.

Recommendations

When configuring a BIG-IP EAV external monitor, you should consider the following factors:

  • When a command in the script sends data or output to stdout, the script exits and the external monitor marks the pool member up. For example, if you include an echo up command at the top of your script, the rest of the code below the command does not run and the external monitor marks the pool member up.
  • A pool member is marked down when no data or output is sent to stdout.
  • External monitors fork a new process and shell to run your script for each pool member. This requires system resources and given that monitors run at short regular intervals, you should ensure your script is optimized.
  • By default, the arguments $0, $1 and $2 are predefined in the script as follows:
    • $0: The file location of the script on the BIG-IP system.

      For example:

      /config/filestore/files_d/Common_d/external_monitor_d/:Common:<script name>_94962_<version number>

    • $1: IP address of the pool member (IPv6 notation. IPv4 addresses are passed in the form ::ffff:w.x.y.z where "w.x.y.z" is the IPv4 address).

      For example:

      ::ffff:192.0.2.5

    • $2: port number of the pool member (decimal, host byte order).

      For example:

      80 or 443

  • You use the BIG-IP external monitor Arguments parameter to define more variables that you can access in the script. For example, if you enter -s -k -u in the Arguments field of your external monitor on the Configuration utility, the following arguments will be defined in the script as follows:
    • $3: -s
    • $4: -k
    • $5: -u
  • You use the BIG-IP external monitor's Variables parameter to define Name:Value pairs to use in the script. The most common examples are the URI and RECV strings described in the Create a BIG-IP external monitor referencing the script procedure.

The BIG-IP external monitor predefines further environment variables that you can access in the script for troubleshooting or other scripting purposes. The following table lists these variables:

  • For either operational or troubleshooting purposes, you can use the logger command in your custom script to log useful information to the /var/log/ltm file. For example, the following command logs the values of the arguments at the debug severity level:

    echo Arguments: $0, $1, $2, $3, $4 | logger -p local0.debug

  • F5 recommends that you modify your script on the BIG-IP Configuration utility. When you make modifications locally from the filesystem using an editor, such as vi, you will need to use the following tmsh command syntax to update the monitor:

    tmsh modify sys file external-monitor <script_name> source-path file:///config/filestore/files_d/Common_d/external_monitor_d/:Common:<filename>

  • For more recommendations and design considerations, refer to LTM External Monitors: The Basics on DevCentral.
