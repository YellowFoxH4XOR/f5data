iRule for XML Content-Based Routing Not Triggering Due to Missing Namespace Mapping in XML Profile

Description

When configuring XML content-based routing on BIG-IP LTM using an iRule and an XML profile, the iRule does not trigger as expected. The XML count variable is not populated, and log entries such as log local0.info "in XML_CONTENT_BASED_ROUTING" do not appear.

Environment

  • LTM

Cause

The root cause is a missing namespace mapping and prefix configuration in the associated XML profile. When XPath queries reference XML elements that use namespaces, the XML profile must explicitly define the namespace URI and associate it with a prefix. If this mapping is absent, XPath queries will not match any elements, resulting in the iRule never being triggered.

Recommended Actions

  1. Edit the XML profile associated with the Virtual Server to include the correct namespace mapping and prefix.
  2. Ensure that the prefix used in your XPath query matches exactly with what you define in your namespace mapping within the profile; this prefix is arbitrary but must be consistent between both places.
  3. Example configuration:
ltm profile xml example_xml_profile {
    app-service none
    defaults-from xml
    multiple-query-matches disabled
    namespace-mappings {
        { mapping-namespace <namespace-URI> mapping-prefix prefix }
    }
    xpath-queries {
        //prefix:ElementName
    }
}
  1. After updating the XML profile, verify that your iRule is now triggered as expected and that log entries appear.

Note: The namespace prefix (e.g., "ib") defined in your XML profile does not need to match any existing prefix within your actual XML document; it only needs to match what you use in your XPath expression inside the profile. If there is also a policy present on the Virtual Server for pool selection, remember that policies take precedence over iRules for pool selection logic.
