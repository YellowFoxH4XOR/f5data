BIG-IP Record Route feature

SIP Record Routing is a mechanism by which a proxy can inform user agents that it wants to stay on the path of all future messages. To ensure that the system routes the messages through the SIP element that the SIP URI identified, the caller and callee add a SIP URI that the system placed in a Record-Route field on a request, to the Route field of subsequent requests in the dialog. The BIG-IP SIP MRF can add a Record-Route field into a SIP header, but does not use the resulting Route field on subsequent messages. F5 has added functionality in BIG-IP 16.0.0 to allow SIP MRF to remove the top-most Route when that SIP URI matches the one that the SIP MRF added, and forward the message to the next SIP URI in the Route field. In cases where a BIG-IP system is a gateway between two networks, the system uses two Record-Routes or rewrites a Record-Route (user selected) to properly route the message on either side of the gateway.

New SIP profile Record Route settings

You can use the Record Route feature to configure SIP Record Routing by inserting a Record-Route header into SIP messages that contain the address of the BIG-IP system. To do so, beginning in BIG-IP 16.x, you can use the following settings in the SIP profile.

Note: You must first enable the Insert Record Route Header setting before the Record Route Mode, Honor Route Mode, and Honor Route Header settings are visible.

SettingsDescription
Record Route ModeSets insert-record-route-header operation to Single (based on RFC 3261) or Double (based on RFC 5658 and 3261). Single mode inserts a single Record-Route header matching the local IP/Port of the egress connection and re-writes the header on responses to match the local IP/Port for egress of the response. Double mode inserts two Record-Route entries: the local IP/Port of the incoming and outgoing connections. When Strict is set in honor-route-mode, only Single mode is possible.
Honor Route ModeSets honor-route operation to Loose (Route header processing based on RFC 3261) or Strict (Route header processing based on RFC 2543). When set to Loose, the inserted Route entries in the Request message include lr.
Honor Route HeaderIf persistence is enabled, persistence takes precedence in message routing. You must set the Persist Type to None for routing based on Route header. When this setting is enabled and Persist Type is None, the system routes requests using the top-most Route header entry after removing any entries matching those that the BIG-IP system added to the Record-Route header. If the Honor Route Header is enabled and the top-most entry in the Route header is unreachable, the connection is treated as a timeout (returns 408 Request Timeout).
Service PortIf not zero, the inserted Via and inserted Record-Route headers use the specified port. If zero, the inserted Via and inserted Record-Route headers use the connect-back-port if set by an iRule by the listener port of a virtual server specified as the alternate transport, or by the local port. Accepted values are 0 to 65535 (16-bits).
Allow Unknown methodsAvailable as of BIG-IP 15.1.0. If non-zero, SIP messages with unknown methods are parsed and routed.

SIP Request and Response Message processing

This section covers how the BIG-IP system processes request and response messages when you configure the different Record Route settings described in the previous section.

Request Message processing

The following table describes how BIG-IP processes request messages with respect to the settings in the Record Route feature.

Insert Record Route HeaderHonor Route HeaderRequest processing
EnabledEnabledA new top-most Record-Route header attribute is inserted into the message. The top-most route, if matching an entry that the BIG-IP system inserted into Record-Route, is removed.
  • Record Route Mode - Single: If secure network address translation (SNAT) is performed, encrypted details of the original connection are added to the Record-Route entry for re-writing on response.
  • Record Route Mode - Double: If SNAT is performed, two Record-Route headers are added with the first one corresponding to the ingress and the top-most corresponding to the egress.
  • Honor Route Mode - Strict: Replaces Request URI with the remaining top-most Route
  • Honor Route Mode - Loose: If Request URI matches an entry that the BIG-IP system inserted into Record-Route, re-writes Request URI with the last entry in the Route list.
EnabledDisabledA new top-most Record-Route header attribute is inserted into the message.
DisabledEnabledThe top-most route, if matching an entry that the BIG-IP system inserted into Record-Route, is removed.
  • Honor Route Mode - Strict: Replaces Request URI with the remaining top-most Route.
  • Honor Route Mode - Loose: If Request URI matches an entry that the BIG-IP system inserted into Record-Route, re-writes Request URI with last entry in the Route list.
DisabledDisabledNeither Route nor Record-Route headers are modified.

Response Message processing

In the Response message, the BIG-IP system looks for the presence of a BIG-IP-inserted Record-Route header. If a single BIG-IP Record-Route entry is found and the system is performing SNAT, the system re-writes the Record-Route entry with the contents of the encrypted details in the entry.

Recommendations

Load Balancing Precedence

When you configure SIP routing and load balancing, consider the order in which the system routes request and response messages.

If persistence is enabled, persistence takes precedence over the Route header feature in message routing. You must disable persistence for routing based on route header.

  • Request Messages are routed in the following order:
    1. Route set by the iRule command
    2. Persistence lookup 
    3. Top-most Route header IP
      (Beginning in 16.0.0 when Insert Record Route and Honor Route are enabled.)
    4. SIP route table lookup
  • Response Messages are routed in the following order:
    1. Last hop information is available in the branch parameter of the SIP Via header
    2. Top-most Via header IP (when the Honor Via setting is enabled)
