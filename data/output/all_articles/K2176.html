Topic

You can configure BIG-IP version 4.5 to use the headers contained within Multimedia Messaging System (MMS) and 3G applications to perform persistence.

Following is an example configuration using iRules. In this example, a header exists in each Multimedia Messaging System Center (MMSC) connection. One is alpha and the other is numeric. The iRule is configured to detect the characters contained within the header and then send the header to the appropriate MMSC. Connections received by an MMSC must be sent back to the same MMSC from which they came.

iRule Example:

Note: In this iRule example, server1 and server2 are both members of the pool both_server.

# first check first 3 bytes that match binary <8c8398>

if ( substr( http_content(4) , 0 ,3)  ==  decode_uri( "%8c%83%98" ) )  {

    # if first 3 bytes are equal to <8c8398> so this packet
    # is confirm message then check the fourth byte
    # suppose that first server contains only number and second
    # server contains only character a-z and A-Z
    # from ascii table 0 - 9 is hex 30-39 or dec 48-57.
    # so just check whether the 4th byte less than 58

    if ( substr( http_content(4),  3, 1 )  < 58 ) {

        # 0-9
        log ("use first server")
        use pool server1 
    } else {
        # a-z and A-Z
        log ("use second server")
        use pool server2 
    }
} 
else {
    # if first 3 bytes are not equal to <8c8398> so this packet
    # is send request
    # then balance the traffic and detecting for failover here
    log ("use second server")
    use pool both_server 
}
