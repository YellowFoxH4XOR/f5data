Issue

Old Behavior

In versions prior to 13.0.0, the Online Certificate Status Protocol (OCSP) profile is associated with the Certificate Key Chain setting in the Client SSL profile configuration. For example, the OCSP profile is associated with the cert-key-chain object in the following configuration:

ltm profile client-ssl /Common/my_cssl {
            cert-key-chain {
                    cert /Common/compact.crt
                    key /Common/compact.key
                    ocsp-stapling-params /Common/my_ocsp_stpl
                                 }
                                        }

New Behavior

Beginning in 13.0.0, the OCSP profile is directly associated with the certificate. For example, your OCSP profile is associated with the certificate instead of the Client SSL profile:

sys file ssl-cert /Common/compact.crt {
            cache-path /config/filestore/files_d/Common_d/certificate_d/:Common:compact.crt_38036_1
            cert-validators {
                /Common/my_ocsp_stpl { }
            }
            revision 1
        }
 

F5 Product Development tracked this change as ID 586628.

Impact

After upgrading to 13.0.0 or later, you are no longer able to associate the OCSP profile to a Client SSL profile. If your configuration has multiple OCSP profiles configured with the same certificate, the BIG-IP system chooses the first valid OCSP profile from the Client SSL profiles to associate with the certificate. The other OCSP profiles remain on the system, but will not be associated with this certificate.

Recommended Actions

You can reconfigure the OCSP profile and associate your OCSP stapling profile with the certificate. For more information, refer to K48359203: The configuration containing the OCSP stapling profiles may fail to load after an upgrade.
