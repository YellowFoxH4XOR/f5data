Known Issue

When you add a macrocall from the BIG-IP APM Configuration utility's Visual Policy Editor (VPE), the operation fails and produces an error message.

This issue occurs when all of the following conditions are met:

  • You are using the Configuration utility's Visual Policy Editor (VPE) to add a macrocall.
  • You are attempting to make a macrocall to a macro located in the Common partition.
  • The access policy or per-request policy you are attempting to modify is located in a folder.

For example, an access policy may be located in /Common/folder/test. However, it contains a macro that had previously been created in /Common. As a result, when you attempt to make a macrocall to this macro from the VPE, the system is unable to find the macro and returns an error.

Impact

You are unable to add a macrocall in an access policy or per-request policy.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  •  When you add a macrocall, the VPE displays an error message similar to the following example:

    Unable to execute transaction because of: 01070734:3: Configuration error: Can't associate Access Policy Item (/Common/folder/test/macro_name) folder does not exist

Workaround

To work around this issue, you can export the affected access profile and import it to the Common partition. After you import the access profile, you can add the macrocall in the access policy or per-request policy and associate the access profile with the virtual server. To do so, perform the following procedure:

  • Export the access profile and import it to the Common partition
  • Add the macrocall in the visual policy editor
  • Associate the new access profile with the affected virtual server

Export the access profile and import it to the Common partition

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  3. From the Partition menu, select the partition where the affected access profile is located.
  4. To the right of the affected access profile, click Export.
  5. After the access profile export download completes, navigate back to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  6. From the Partition menu, verify that Common is selected.
  7. Click Import.
  8. Enter a profile name in the New Profile Name box.
  9. Click Import.
  10. Click Apply Access Policy.

Add the macrocall in the visual policy editor

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

You can now successfully add the macrocall using the visual policy editor. For more information about macros and adding macrocalls, refer to the Visual Policy Editor chapter of the BIG-IP Access Policy Manager: Visual Policy Editor manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Associate the new access profile with the affected virtual server

Impact of workaround: Associating a new access profile to a virtual server may disrupt services on the virtual server. F5 recommends that you perform the following procedure during a scheduled maintenance window.

  1. Navigate to Local Traffic > Virtual Server List.
  2. Select the affected virtual server.
  3. In the Access Policy Access Profile section, select the imported access profile from the menu.
  4. Click Update.
