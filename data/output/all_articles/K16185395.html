Description

When attempting to transfer configuration from the running boot location to a new boot location using cpcfg, the process fails with the following output:

[root@VE-A:Active:Standalone] config # cpcfg --source=HD1.1 --reboot HD1.2
info: Getting configuration from HD1.1
info: Copying configuration to HD1.2
info: Applying configuration to HD1.2
error: status 256 returned by command: F5_INSTALL_MODE=install F5_INSTALL_SESSION_TYPE=hotfix chroot /mnt/tm_install/14288.Fg8Raz /usr/local/bin/im -force /var/local/ucs/config.ucs
info: >++++ result:
info: Extracting manifest: /var/local/ucs/config.ucs
info: /var: Not enough free space
info:   1856542720 bytes required
info:   1258917888 bytes available
info: /var/local/ucs/config.ucs: Not enough free disk space to install!   -->> !!!
info: Operation aborted.
info: >----
Configuration copy failed; Inappropriate ioctl for device   -->> !!!

Environment

  • BIG-IP VE
  • Transferring configuration to a new boot location using cpcfg

Cause

The cause could be related to one of the following issues:

  • Excessively large UCS file
  • Available /var space on the new boot location is not big enough for transferring configuration

Recommended Actions.

  1. Disable liveinstall.saveconfig to make sure when booting in to the new boot location config does not copy over. Use the following syntax below:

    1. tmsh modify /sys db liveinstall.saveconfig value disable
    2. tmsh save /sys config
     
  2. Change the boot location without transferring any configuration.

    tmsh reboot volume <a_new_bootlocation>

    Example:

    # tmsh reboot volume HD1.2
     
  3. Extend /var space, then reboot the system (how to extend disk space on VE, please refer to K14952). Use the following syntax below:

    1. tmsh modify /sys disk directory /var new-size <new_/var_space>
    2. tmsh save /sys config
    3. reboot

    Example, extending /var to 10GB:

    # tmsh modify /sys disk directory /var new-size 10485760
    # tmsh save /sys config
    # reboot
     
  4. After the BIG-IP rebooted (still booting on the new boot location), check /var space again, the space should show as the previous change.

    df -h
     
  5. Boot back to the previous boot location (the running one).

    tmsh reboot volume <previous_boot_location>

    Example:

    # tmsh reboot volume HD1.1
     
  6. Copy the configuration again from the running boot location to the new boot location and reboot the device to the new boot location.

    cpcfg --source=<running_boot_location> --reboot <new_boot_location>

    Example:

    # cpcfg --source=HD1.1 --reboot HD1.2
     
  7. After the BIG-IP boots to the new boot location, enabling liveinstall.saveconfig.

    tmsh modify sys db liveinstall.saveconfig value enable
    tmsh save sys config
