Known Issue

Running the QKView utility or certain Traffic Management Shell (tmsh) commands may consume all available CPU resources.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP GTM virtual servers are configured with the virtual server Dependency List setting.
  • You attempt to run one of the following:

    • The QKView utility from the Configuration utility, the tmsh utility, or the command line
    • The show /gtm datacenter detail command from the tmsh utility

Impact

The BIG-IP GTM system stops processing traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you attempt to run any of the listed commands, the BIG-IP GTM CPU utilization is maximized and the BIG-IP GTM system stops responding.
  • The BIG-IP GTM system fails over to a peer device, if configured for high availability (HA).
  • The system logs daemon restart messages to the /var/log/daemon.log file.

    For example, one type of daemon restart message may appear similar to the following example:

    emerg logger: Re-starting lind
    emerg logger: Re-starting stpd
    emerg logger: Re-starting bcm56xxd
    emerg logger: Re-starting mcpd
    emerg logger: Re-starting lind
    emerg logger: Re-starting stpd
    emerg logger: Re-starting tmrouted
    emerg logger: Re-starting named
    emerg logger: Re-starting bigd
    emerg logger: Re-starting cssd
    emerg logger: Re-starting bcm56xxd
