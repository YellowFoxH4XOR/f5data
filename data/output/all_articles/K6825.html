Topic

To find out what information F5 Support requires when you open a support case for other F5 products, refer to K2633: Instructions for submitting a support case to F5.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration. To help you gather all the required information, use the following guidelines to prepare for opening a case.

General Information

Provide the following information when you open a case with F5 Support:

  • A full description of the issue, including the following:
    • The symptoms of the issue
    • The approximate time the issue first occurred
    • The number of times the issue has recurred
    • Any error output provided by the system
    • Steps to reproduce the issue
    • Any changes you made to the system before the issue first occurred
    • Any steps you have taken in an attempt to solve the issue
    • Whether or not the implementation is new
    • If you have uploaded a QKView file to F5 iHealth:
      • Inform support of the QKView files that have been uploaded into iHealth and provide the links to them
      • Inform support of the search criteria used on the AskF5 knowledge base that did not render an article, if applicable
  • A description of the impact the issue is having on your site, using the following definitions:
    • Site Down

      Your network or application is down, or critical business functions have stopped due to the issue.

    • Site at Risk

      Your network or application is severely and negatively impacted by the issue.

    • Performance Severely Degraded

      The performance of your network or application has been severely reduced due to the issue.

    • General Assistance Required

      The subject of the case does not currently impact your network or application.

  • The hours that you are available to work on the issue, and any alternative contacts who can work on the issue if you are not available.
  • Remote access information, if possible.

    Remote access to your network environment is important, because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

The following product information is required when you open a support case:

For specific instructions about how to send this information to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

The qkview utility

If the BIG-IP ASM system is running as a licensed module on a BIG-IP system, you can run the qkview script to generate a diagnostic file.

A qkview diagnostic file contains the configuration files that F5 Support most frequently needs when troubleshooting an issue. A .tgz archive is created by the qkview utility in version 10.x and later.

For more information about qkview, refer to K12878: Generating diagnostic data using the qkview utility.

BIG-IP ASM 10.2.2 and later

Beginning in BIG-IP ASM 10.2.2, the qkview utility is automatically executed by the asmqkview utility. When collecting data for versions 10.2.2 or later, it is unnecessary to collect the output of both the qkview command and the asmqkview command separately, as that data is now automatically included in the output of the asmqkview utility. The new version of the diagnostic file created is also compatible with iHealth, and may be uploaded to iHealth for automatic system analysis. It is essential that you provide the output of the asmqkview utility whenever you open a BIG-IP ASM support case. You may enter the following command on the affected BIG-IP ASM system to generate the output:

asmqkview --add-request-log -s0 

Note: This command generates an asmqkview with unlimited (-s0) request logs. To include request logs in BIG-IP ASM 10.2.2 through 11.5.x, use --add-proxy-log instead of the --add-request-log option.

For more information about asmqkview, refer to K6824: Overview of the asmqkview script. For more information about the changes to the asmqkview script, refer to K13190: The asmqkview script is compatible with iHealth.

The asm_snapshot file

If the BIG-IP ASM system is running as a standalone system, you can run the asmqkview script to generate an asm_snapshot file.

The asm_snapshot file contains the configuration files that F5 Support most frequently needs when troubleshooting a BIG-IP ASM issue. An asm_snapshot file is produced by the asmqkview utility.

For more information about asmqkview, refer to K6824: Overview of the asmqkview script.

Security policy

If applicable, provide an example of the request that triggers the problem as well as its corresponding Support ID and the affected security policy. You should export the affected security policy so F5 Support can review it. To export the relevant security policy, perform one of the following procedures:

BIG-IP 11.3.0 and later

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Security > Application Security > Security Policies.
  3. Select the policy you want to export.
  4. Click Export.
  5. Follow the steps to download the policy.

BIG-IP 11.1.0 through 11.2.1

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Security Policies > Policies List.
  3. Select the policy you want to export.
  4. Click Export.
  5. Follow the steps to download the policy.

BIG-IP 10.2.0 through 11.0.0

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Policies List.
  3. Select the policy you want to export.
  4. Click Export.
  5. Follow the steps to download the policy.

BIG-IP 10.0.0 through 10.1.0

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Application Security > Web Applications > Policies List.
  3. Select the policy you want to export.
  4. Click Export.
  5. Follow the steps to download the policy.

Log files

The tech.out file contains the log files for the last day. If the issue has existed for more than a day, provide all the log files on the system by performing the following procedure:

  1. Log in to the command line.
  2. Change directories to the /var/log directory by typing the following command:

    cd /var/log

  3. Place all of the log files in a tar archive by typing the following command:

    tar -czpf /var/tmp/logfiles.tar.gz *

    This command creates a tar archive named logfiles.tar.gz in the /var/tmp directory.

Packet traces

If the issue involves the network, perform a packet trace while the issue is occurring and provide the packet trace when you open the case.

For more information about performing packet traces with tcpdump, refer to K4714: Performing a packet trace and providing the results to F5 Support.

You may want to use the following command syntax to perform the packet trace on the BIG-IP ASM system:

tcpdump –nni 0.0:nnn –s 0 host <VIP> or host <pool_member1> or host <pool_member2> and port <port_number> –w /var/tmp/tcpdump.pcap

The packet trace may be quite verbose depending on how much traffic is passing through the BIG-IP ASM system. You may want to use additional filters to limit the hosts captured but you should ensure that the traffic in question is not filtered out. You should also provide the IP addresses involved in packet trace (for example, the client IP, virtual server IP, pool members IP. etc.) when you provide the packet trace. If the traffic in question is encrypted, you should decrypt the packet trace using the ssldump utility.

For more information about decrypting encrypted traffic, refer to K10209: Overview of packet tracing with the ssldump utility.

HttpWatch

If the issue is reproducible only when ASM is enabled, you should perform an HttpWatch or equivalent capture on the affected traffic when ASM is enabled and perform another HttpWatch or equivalent capture when ASM is disabled. Provide all HTTP captures when you open the case. You can download a copy of the HttpWatch Basic Edition for free from the HttpWatch website.

XML cases

If the issue involves XML profiles, you should provide the XML schema files such as wsdl and xsd.

UCS archive

If you cannot give F5 Support remote access to your system, you must provide a UCS archive of the current configuration. For more information about UCS archives, refer to K4423: Overview of UCS archives.

Core files

Core files contain the contents of the system memory at the time the crash occurred. If the system has been configured to save core files, the files will be located in the /shared/core directory. Provide any existing core files when you open the case.
