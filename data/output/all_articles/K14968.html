Known Issue

Some BIG-IP LTM local policy options that F5 does not yet support are presented as drop-down configuration options in the BIG-IP Configuration utility. Although a policy configuration containing an unsupported option appears to be saved successfully, the system does not process, as expected, traffic that matches at or after an affected rule.

This issue occurs when the following condition is met:

  • A BIG-IP LTM local policy includes a rule that uses the following combination of Action options:

    • Target is set to forward
    • Event is set to request
    • Action is configured as select
    • Parameter is configured as node, clone-pool, member, nexthop, or rateclass

Impact

Traffic matched by the policy may not be processed as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H442965 on the Diagnostics > Identified > Medium|High screen.
  • Traffic matched by the policy at the affected rule or later is not processed as expected.
  • In the /var/log/ltm file, you may observe an error message similar to the following:

    err tmm[11363]: 016e0000:3: Could not bind action 'forward select policy=/Common/policy-name rule=rule-name action-id=0 node=/Common/10.1.2.3', reason ERR_NOT_SUPPORTED

Workaround

To work around this issue when Parameter is set to node, you can configure and refer to a single-member pool instead. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Note: For other Parameter values (clone-pool, member, nexthop, rateclass), you may be able to configure an iRule that performs the desired rule actions.

  1. Log in to the BIG-IP Configuration utility.
  2. Browse to Local Traffic > Pools > Pool List.
  3. Click Create.
  4. Enter a name for the new pool, and select a health monitor, if appropriate.
  5. In the Address box, enter the IP address of the node referenced by the affected policy rule.
  6. In the Service Port box, enter the service port required by the selected health monitor. If no monitor is configured, enter 0.
  7. To add the node to the pool, click Add.
  8. To save the pool, click Finished.
  9. Browse to Local Traffic > Policies > Policy List.
  10. Click the affected policy to open it.
  11. Click the affected rule to open it.
  12. In the Actions section, click the affected rule action.

    The Action dialog boxes are automatically populated with values from the selected rule action, including the node to which traffic should be forwarded.

    For example, node 10.0.0.1 is listed as:

    Node /Common/10.0.0.1.

  13. Delete the existing node reference by selecting it and then clicking the small Delete button that is located immediately below the dialog box.
  14. In the Parameter value list, click pool.

    The dropdown box immediately below is automatically populated with a list of configured pools.

  15. Select the pool that you previously created, then click the small Add button that is located to the right.
  16. To add the newly-created rule action to the existing rule, click the larger Add button that is located on the bottom left of the Action section.

    The rule actions now include the old action (forward-node) and the new action (forward-pool).

  17. Delete the affected rule action (forward-node) by selecting it again, then clicking the larger Delete button that is located below the box.
  18. To save changes, click the Update Rule button.
