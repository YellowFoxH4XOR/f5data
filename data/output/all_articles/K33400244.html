Description

/var/log/ltm logs similar to the following message:

   diskmonitor[<PID>]: 011d0004:3: Virtual Disk <vdisk_name>.img has only * % free

Also, while this message is logged, installing new version to Virtual Clustered Multiprocessing (vCMP) guest, installation does not progress and stays 0% on GUI, and you can see the status in the following command and stays 0% for more than 30 minutes.

# tmsh show /sys software
--------------------------------------------------------
Sys::Software Status
Volume  Product  Version   Build  Active  Status
--------------------------------------------------------
HD1.1    BIG-IP 14.1.2.1   0.0.4      no  installing 0.000 pct
HD1.2    BIG-IP   14.1.2  0.0.37     yes  complete

Environment

  • vCMP is provisioned
  • vCMP guest cannot install new version of BIG-IP OS
     

Cause

Lack of space to install new boot location.


Recommended Actions

recover virtual disk space following: K24156414: Increasing the disk space for a BIG-IP vCMP guest
 

    Additional Information

    When you configure and deploy vCMP guests, you should consider the following factors:

    • The disk space recovery procedure may be helpful if you are unable to create new vCMP guests due to disk space exhaustion on the vCMP host.
    • Virtual disk images remain, even after a vCMP guest has been deleted. For virtual disks no longer in use, consider either deleting or moving the virtual disk images to a backup storage server.
