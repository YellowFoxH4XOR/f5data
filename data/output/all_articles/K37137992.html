Known Issue

The BIG-IP AAM system erroneously inserts Smart Client Cache JavaScript into uncacheable error response code responses.

This issue occurs when all of the following conditions are met:

  • You use the BIG-IP AAM system to accelerate traffic.
  • You have a virtual server configured with an AAM acceleration policy.
  • The virtual server processes a request that matches a node with SCC enabled in the AAM acceleration policy.
  • The request results in a uncacheable response code from the origin web server (OWS), such as 404 Not Found or 206 Partial Content responses.

Only error response code responses that the acceleration policy is configured to cache should be passed to the AAM assembler.

Impact

The impact is dependent on how the client reacts to the unexpected SCC JavaScript. The client could ignore it, stop responding, or reset the connection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Error responses have SCC JavaScript inserted.
  • If you view an affected error response using tcpdump, or by viewing source on the client, the response will appear similar to the following example:
