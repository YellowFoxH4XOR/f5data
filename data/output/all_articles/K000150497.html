K000150497: LTM is rewriting source IP address (without SNAT or irule adjustment)

Type
Support Solution
Published
2025-03-27
Updated
2025-03-27
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000150497

Description

Source IP shown in server-side on a packet capture, shows different source IP than the client IP, with no SNAT configured nor iRule source IP modification.

 

See below example:

 

Client side Source IP -> Virtual server

10.10.10.10 -> 10.10.20.10

 

On the Server side with the following traffic flow, notice that the "Source IP" should be the same as the client side in a standard environment:

 

Server-side Source IP -> Pool member

10.30.10.10  -> 10.30.30.30

 

In this example, and with this device configuration, the IP shown as the Server-side Source IP is actually another node that is not part of this Virtual server's configuration, however since this connection was idle at the moment the new request arrived, the BIG-IP system applied the OneConnect source mask to the IP address in the request.

 

Environment

BIG-IP LTM

OneConnect

 

Cause

One connect profile may re-use an idle connection on the server-side.

 

Recommended Actions

In this configuration, we should not rely on the source IP address to be accurate when the HTTP request arrives at the pool member, because the use of oneconnect explicitly means that it won't be:

 

When a new connection is initiated to the virtual server, if an existing server-side flow to the pool member is idle, the BIG-IP system applies the OneConnect source mask to the IP address in the request to determine whether it is eligible to reuse the existing idle connection. If it is eligible, the BIG-IP system marks the connection as non-idle and sends a client request over it.

 

This behavior is expected and caused mainly because of the oneconnect profile, the way to test this is to disable this profile and analyze the behavior with a packet capture.
