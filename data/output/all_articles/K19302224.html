Description

Access Logs are enabled by default for all istio-proxy containers in the Aspen Mesh cluster and are written to the container’s standard output. You can then print the logs using the kubectl logs command from any proxy. You may want to customize the Access Logs format, the target log file or even disable logging. In this article we will describe how to configure Access Logs in Aspen Mesh.

Environment

  • Kubernetes: 1.17x, 1.18.x, 1.19.x, 1.20.x  
  • Aspen Mesh: 1.9.x  

Cause

None

Disable Access Logs

Access Logs in Aspen Mesh are enabled by default in all istio-proxies and are written to the container’s standard output (/dev/stdout).

To disable Access Logs in the whole mesh cluster, you can add or replace /dev/stdout in the log file with an empty string in your values.yaml file in the meshConfig section. To do so, perform the following procedure:

  1. Add the empty log file to the meshConfig section of your values.yaml file you used to install the istiod Helm Chart

    meshConfig:
      accessLogFile: ""

  2. Upgrade the Istiod chart configuration by using the following command syntax:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery \
    --namespace istio-system \
    --value <YOUR_VALUES_YAML_FILE>

Customize Access Logs format and fields

You can also customize the Access Logs format and fields. The following shows the default Access Logs format for proxies:

"[%START_TIME%] \"%REQ(:METHOD)% %REQ(X-ENVOY-ORIGINAL-PATH?:PATH)% %PROTOCOL%\" %RESPONSE_CODE% %RESPONSE_FLAGS% %RESPONSE_CODE_DETAILS% %CONNECTION_TERMINATION_DETAILS% \"%UPSTREAM_TRANSPORT_FAILURE_REASON%\" %BYTES_RECEIVED% %BYTES_SENT% %DURATION% %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)% \"%REQ(X-FORWARDED-FOR)%\" \"%REQ(USER-AGENT)%\" \"%REQ(X-REQUEST-ID)%\" \"%REQ(:AUTHORITY)%\" \"%UPSTREAM_HOST%\" %UPSTREAM_CLUSTER% %UPSTREAM_LOCAL_ADDRESS% %DOWNSTREAM_LOCAL_ADDRESS% %DOWNSTREAM_REMOTE_ADDRESS% %REQUESTED_SERVER_NAME% %ROUTE_NAME%\n

You can modify the Access Logs format and fields by adding the accessLogFormat field to your values.yaml file in the same meshConfig section. The different fields available are listed in the Access Logging section in the Envoy proxy documentation.

  1. The following shows an example of the accessLogFormat field:

    meshConfig
      accessLogFormat: "{ \"authority\": \"%REQ(:AUTHORITY)%\", \"bytes_received\": %BYTES_RECEIVED%, \"bytes_sent\": %BYTES_SENT%, \"downstream_local_address\": \"%DOWNSTREAM_LOCAL_ADDRESS%\", \"downstream_peer_cert_v_end\": \"%DOWNSTREAM_PEER_CERT_V_END%\", \"downstream_peer_cert_v_start\": \"%DOWNSTREAM_PEER_CERT_V_START%\", \"downstream_remote_address\": \"%DOWNSTREAM_REMOTE_ADDRESS%\", \"downstream_tls_cipher\": \"%DOWNSTREAM_TLS_CIPHER%\", \"downstream_tls_version\": \"%DOWNSTREAM_TLS_VERSION%\", \"duration\": %DURATION%, \"hostname\": \"%HOSTNAME%\", \"istio_policy_status\": \"%DYNAMIC_METADATA(istio.mixer:status)%\", \"method\": \"%REQ(:METHOD)%\", \"path\": \"%REQ(X-ENVOY-ORIGINAL-PATH?:PATH)%\", \"protocol\": \"%PROTOCOL%\", \"request_duration\": %REQUEST_DURATION%, \"request_id\": \"%REQ(X-REQUEST-ID)%\", \"requested_server_name\": \"%REQUESTED_SERVER_NAME%\", \"response_code\": \"%RESPONSE_CODE%\", \"response_duration\": %RESPONSE_DURATION%, \"response_tx_duration\": %RESPONSE_TX_DURATION%, \"response_flags\": \"%RESPONSE_FLAGS%\", \"route_name\": \"%ROUTE_NAME%\", \"start_time\": \"%START_TIME%\", \"upstream_cluster\": \"%UPSTREAM_CLUSTER%\", \"upstream_host\": \"%UPSTREAM_HOST%\", \"upstream_local_address\": \"%UPSTREAM_LOCAL_ADDRESS%\", \"upstream_service_time\": %RESP(X-ENVOY-UPSTREAM-SERVICE-TIME)%, \"upstream_transport_failure_reason\": \"%UPSTREAM_TRANSPORT_FAILURE_REASON%\", \"user_agent\": \"%REQ(USER-AGENT)%\", \"x_forwarded_for\": \"%REQ(X-FORWARDED-FOR)%\" } \n"

  2. After adding the log format in the values.yaml file, use the following command syntax to upgrade the istiod Helm chart:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery \
    --namespace istio-system \
    --value <YOUR_VALUES_YAML_FILE>

Modify accessLogEncoding

The last setting that you can modify in the values.yaml file is the accessLogEncoding which can be set to JSON or TEXT. By default you use TEXT encoding.
