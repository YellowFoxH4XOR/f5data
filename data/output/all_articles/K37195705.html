K37195705: Sync Failed A validation error occurred while syncing to a remote device when iApp was deleted.

Type
Support Solution
Published
2024-03-22
Updated
2024-03-22
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 16.1.X, 16.0.X, 16.1.0, 16.0.1, 16.0.0, 16.X.X, 16.1.2, 16.1.1, 16.1.3
Source
https://my.f5.com/manage/s/article/K37195705

Description

After the synchronization of the configuration, it may fail between big-IP devices with the below error.

show /cm sync-status
--------------------------------------------------------------------------------
CM::Sync Status
--------------------------------------------------------------------------------
Color    red
Status   Sync Failed
Mode     high-availability
Summary  A validation error occurred while syncing to a remote device
Details
        <remote device hostname>: connected
         <traffci-group name> (Sync Failed): A validation error occurred while syncing to a remote device
          - Sync error on <local device hostname>: Load failed from /Common/<remote device hostname> 0107134a:3: File object by             name (/Common/<iApp name>.app/myprofile) is missing.
          - Recommended action: Review the error message and determine corrective action on the device

Also, you may find this log error in var/log/ltm directory

var/log/ltm
<device hostname> err mcpd[6963]: 0107134a:3: File object by name (/Common/<iApp name>.app/autodiscover_eav) is missing.
<device hostname> notice mcpd[6963]: 0107168e:5: Unable to do incremental sync, reverting to full load for device group /Common/<device-group name> device %cmi-mcpd-peer-/Common/<remote device hostname> from commit id { 448896 7126371267851277431 /Common/<local device hostname> } to commit id { 485732 7128721860089269040 /Common/<local device hostname> }.

Environment

  • LTM module provisioned
  • An iApp was installed and then deleted
  • HA Cluster

Cause
The bigip.conf file got corrupted when the iApp was deleted without getting rid of all the references to it  .

Recommended Actions

  1. Make a backup of the bigip.conf file with the below command

         cp /config/bigip.conf <name of the backup file>.conf

  1. Check profiles that could have referenced iApp configuration like the below example

    ltm monitor https /Common/mymonitor{ 

    ssl-profile /Common/<deleted iApp name>.app/autodiscover_eav <<<<<<<<<<<<<<<<<<<< monitor_ssl_profile is in use
    time-until-up 0
    timeout 31
    }

         In the above example, the autodiscover_eav object is using SSL profile monitor_ssl_profile created by iApp, but,  due to this profile being referenced in another object, the profile was not disabled when the iApp was deleted.
 

  1.   Then run the below command in the active device to force a full synchronization

    run cm config-sync force-full-load-push to-group <traffic-group name>

 

Additional Information
None.
