Known Issue

Manually starting the BIG-IP APM websso service may trigger 100 percent CPU utilization.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is already running the websso service.
  • You manually start the BIG-IP APM websso service from the command line or from a script.

For example, if you run the /etc/bigstart/scripts/websso command from the command line or from a script while the websso service is already running, CPU utilization on the BIG-IP APM system can reach 100 percent. Using the bigstart utility is recommended when managing the websso service.

Impact

Users may not be able to access the system, and the BIG-IP APM system may experience a decrease in performance or stop responding.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • System CPU utilization increases over time and eventually consumes all available CPU.
  • Users experience decreased performance with single sign-on (SSO).
  • Dashboard CPU performance graphs show continually increasing consumption.
  • Messages are generated to the /var/log/ltm file, similar to the following examples:

    notice mcpd[24049]: 01070408:5: Deleting abandoned subscriber connection for mem://websso0
    notice mcpd[24049]: 01070408:5: Deleting abandoned subscriber connection for mem://websso1
    notice tmm[29001]: 01010029:5: Clock advanced by 502 ticks

Workaround

To work around this issue, you can restart the BIG-IP APM websso service. To do so, perform the following procedure:

Impact of workaround: This procedure may cause a temporary interruption in traffic processing while the websso service restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the websso service, type the following command:

    restart /sys service websso
  3. To exit the tmsh utility, type the following command:

    q
