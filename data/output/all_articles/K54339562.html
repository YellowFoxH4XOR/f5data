Known Issue

The BIG-IP system may fail to authenticate remote Lightweight Directory Access Protocol (LDAP) accounts.

This issue occurs when all of the following conditions are met:

  • You enabled LDAP for the BIG-IP remote account authentication.
  • An LDAP account that contains attributes longer than 255 characters attempts to access the BIG-IP management interface.

Impact

The remote LDAP authentication fails and the affected user accounts are unable to log in to the BIG-IP system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Some LDAP users cannot access the BIG-IP system through remote authentication.
  • In the /var/log/audit file, you observe failed login messages that appear similar to the following example:

    info httpd(pam_audit)[8484]: 01234567:8: AUDIT - user j.smith - RAW: httpd(pam_audit): User=j.smith tty=(unknown) host=10.10.10.10 failed to login after 1 attempts (start="Mon Jan 1 12:00:00 2019" end="Mon Jan 1 12:00:02 2019").

  • In the /var/log/secure file, you observe error messages that appear similar to the following example:

    crit httpd[28484]: pam_ldap(httpd:account): buffer 32 bytes too small

Resolution

Status

F5 Product Development has assigned ID 755254 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, you can ensure that the LDAP user accounts do not have attributes longer than 255 characters before accessing the BIG-IP management interface.
