Source

Description

  • I want to create a HTTPS Load Balancer (LB) with Automatic Certificate
  • The DNS changes required to complete the AutoCert provisioning process are unclear

Environment

  • F5® Distributed Cloud (XC) Console
  • HTTPS Load Balancer (LB) with Automatic Certificate
  • DNS

Cause

Selecting the Automatic Certificate option when creating an HTTPS LB invokes a process by which a cert is automatically provisioned from Let's Encrypt.

The provisioning process requires the creation of a DNS record within the zone for which the certificate is being requested.  This is a necessary validation step to prove to Let's Encrypt that the requestor actually owns the domain for which the cert is requested.

NOTE:

  • XC does not currently support changing from non-delegated to delegated (or vice versa) domains for existing Load Balancers. If you want to switch from non-delegated to delegated (or vice versa), please create a new LB.
  • XC does not currently support using both delegated and non-delegated domains in the same Load Balancer. You must choose one or the other.

Recommended Actions

The process for creating the requisite DNS record depends on whether you are also using XC for DNS management of the zone in which the record needs to be created.  If the zone has been delegated to XC DNS Management, the process is automated.

 

Method 1: Self-Managed DNS

IMPORTANT: You do NOT need to change any NS records with your DNS provider if you are not using XC-Managed DNS. The only record(s) that need to be modified are CNAME (see below procedure for full details).

  1. If you haven't already, create your HTTP Load Balancer as per HTTP Load Balancer | F5 Distributed Cloud Technical Knowledge
  2. Navigate to your HTTP Load Balancer in XC Console (WAAP > your-namespace > Manage > Load Balancers > triple dots on right of page > manage configuration > edit configuration at top right of page)
  3. Under Domains and LB Type > Load Balancer Type, select HTTPS with Automatic Certificate
  4. Under Domains and LB Type, type in your application domain name
  5. Click Save and Exit to save the configuration. 
  6. Obtain the ACME challenge record from the XC Console. This is shown in the HTTP LB configuration as per below screenshot. You have to click "DNS Information" on the left side of the page. Note there are two ACME challenge records shown below because this particular Load Balancer hosts two domains.
  7. Through whichever utility is used to managed your DNS environment, create a CNAME record pointing the ACME challenge domain name to the value obtained from XC Console in the previous step.  It will be of the format <UID>.autocerts.ves.volterra.io
  8. Wait some time (up to 24 hours) for Let's Encrypt to query the domain
  9. Verify the cert is issued and applied to the LB. You can verify this by observing Auto Cert State: Certificate Valid as per above screenshot
  10. Create a CNAME record pointing the application domain name to the hostname of the HTTP LB shown in XC Console like above screenshot, which will be formatted as ves-io-<UID>.ac.vh.ves.io

Method 2: XC-Managed DNS

Please reference the following articles for onboarding to XC Managed DNS and delegating a domain:

  • Manage DNS Zone
  • Domain Delegation
  • How do I migrate my Delegated Domains to Primary DNS?

IMPORTANT:

  1. Do NOT create any CNAME records with a separate DNS provider if you are using XC-Managed DNS. Instead, update your registrar (or parent zones) by changing the NS records with your DNS provider to ns1.f5clouddns.com and ns2.f5clouddns.com 
    • In general, do NOT attempt to manage subdomains of domains delegated to/managed by XC. If XC manages a domain, it will also manage DNS records for all subdomains.
    • Do NOT create duplicate DNS records in an XC-Managed DNS zone. This will cause inconsistent behavior and certificates often can't be issued.
  2. Ensure to check the option Allow HTTP Load Balancer Managed Records in your DNS Zone Configuration as shown below. This will grant XC permission to manage DNS records for the HTTP Load Balancer that pertains to the DNS zone.


 

The following steps assume that domain delegation has been successfully completed.

  1. If you haven't already, create your HTTP Load Balancer as per HTTP Load Balancer | F5 Distributed Cloud Technical Knowledge
  2. Navigate to your HTTP Load Balancer in XC Console (WAAP > your-namespace > Manage > Load Balancers > triple dots on right of page > manage configuration > edit configuration at top right of page)
  3. Under Domains and LB Type > Load Balancer Type, select HTTPS with Automatic Certificate
  4. Under Domains and LB Type, type in your application domain name
  5. Click Save and Exit to save the configuration. 
  6. Wait some time (up to 24 hours) for the auto cert to be issued by Let's Encrypt, followed by XC automatically creating an A record that points the domain name to the VIP of the HTTP LB.

Additional Information

  • Only first domain on the LB will be shown under auto_cert_subject.
  • 1 automatic certificate is provisioned per LB. If there are multiple domains, additional domains will be included as SAN entries on the certificate.
