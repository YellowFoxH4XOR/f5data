Description

TACACS authentication succeeds at the F5OS hypervisor level, but the user cannot access SSH or the WebUI because the TACACS-returned F5-F5OS-GID does not match the remote GID configured for the intended F5OS role. The user may be mapped to the nobody group (GID 99) and receive Permission denied.

Environment

  • F5OS hypervisor level (F5OS-A or F5OS-C)

  • TACACS+ remote authentication

  • F5OS role with a configured remote GID

Cause

F5OS requires the appropriate roles and Group IDs to be configured on the TACACS server. For remote role mapping, the remote GID configured for an F5OS role must match the F5-F5OS-GID value returned by the TACACS server. If the values do not match, F5OS cannot map the authenticated user to the intended role and may assign the user to the nobody group (GID 99).

Answer/Recommended Actions

  • Configure the required F5OS roles and Group IDs on the TACACS server.

  • Ensure that the returned F5-F5OS-GID matches the remote GID configured for the intended F5OS role.

  • To configure a remote GID from the F5OS CLI:

    1. Enter configuration mode:
      config

    2. Configure the remote GID for the required role:
      system aaa authentication roles role <role-name> config remote-gid

    3. Commit the configuration:
      commit

    4. Verify the configured role mappings:
      show system aaa authentication roles

  • For example, if the TACACS server returns F5-F5OS-GID=9000 for the admin role, configure the admin role remote GID as 9000.

  • Validate remote-user authentication through both SSH and the WebUI after updating the configuration.

Example TACACS+ configuration for tac_plus:

group = admin {

   service = ppp

   protocol = ip

   {

      default attribute=permit

      F5-F5OS-UID=1001

      F5-F5OS-GID=9000

      F5-F5OS-HOMEDIR=/tmp

      F5-F5OS-USERINFO=john_smith

   }

}

user = john_smith {

      global = cleartext "<password>"

      member = admin

}

Additional Information

A successful TACACS authentication does not confirm that the user has been assigned an F5OS role. If the returned F5-F5OS-GID does not match the configured role remote GID, the user may resolve to the nobody group (GID 99) and be denied access.
