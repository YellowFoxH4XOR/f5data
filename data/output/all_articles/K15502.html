Known Issue

The BIG-IP APM system may allow multiple policy items to refer to the same agent.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system uses access profiles configured with very long names.
  • The BIG-IP APM system automatically truncates the names, resulting in identical agent names.

For example, if access profiles use excessively long names, the BIG-IP APM system's name resolution process may truncate them, which also truncates agent names in the configuration. If the configured names of two or more agents are identical except for a few characters in the middle, these distinguishing characters may be removed during the truncation process and result in agents with identical names. This occurrence may result in multiple policy items referencing the same agent name, which prevents the configuration from loading properly.

Impact

The BIG-IP APM configuration may fail to load, or users may not be able to edit the access policy.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Administrators cannot edit the BIG-IP APM access policy.
  • The BIG-IP APM configuration fails to load properly.
  • Attempts to copy an access policy to use a longer name fail.
  • User configuration set (UCS) archives fail to load and the system generates messages similar to the following example:

    The access policy item (/Common/<policy-item 1 name>) cannot share an agent (/Common/<truncated agent name>) with other access policy item (/Common/<policy-item 2 name>). Unexpected Error: Loading configuration process failed

Workaround

To work around this issue, you can restore the original agent names within the access policy by deleting and recreating any affected policy items. If you cannot edit the policy due to this issue, you can manually edit the bigip.conf file to set the policy item references for agents limit to one (1), and then reload the configuration. To do so, perform the following procedure:

Note: After successfully restoring the configuration, the length of the offending access profile names should be shortened to avoid truncation by the BIG-IP APM system.

Impact of workaround: Traffic may be temporarily disrupted while the edited configuration loads. This procedure should be performed during a maintenance window.

agents {
/Common/example_policy-active_directory_group_query_resource_assignme_act_resource_assign_3 {
type aaa-active-directory
}
}

  1. Log in to the command line of the BIG-IP APM system.
  2. Create a backup copy of the /config/bigip.conf file by typing the following command:

    cp -p /config/bigip.conf /config/bigip.conf.sol15502

  3. Edit the /config/bigip.conf file using a text editor of your choice.
  4. Delete offending references to the affected agent in the configuration of the relevant policy items.

  5. Save the changes and exit the text editor.

    tmsh load /sys config

  7. Edit the access policy to restore the policy items to their original configuration.
  8. Save your changes.
