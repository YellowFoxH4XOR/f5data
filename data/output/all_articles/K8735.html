Known Issue

This is the result of a known issue. A large BIG-IP GTM configuration, consisting of 32,000 or more objects, can result in shared memory depletion.

A large configuration causes the mcpd process to use all available shared memory to create the corresponding object IDs. The depletion of the shared memory prevents communication between the gtmd and mcpd processes. As a result, the wide IP update status is prevented between the two daemons.

F5 Product Development tracked this issue as CR94736 and it was fixed in BIG-IP GTM 9.4.6. For information about upgrading, refer to the BIG-IP GTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF3 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
