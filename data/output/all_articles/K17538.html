Known Issue

The user configuration set (UCS) installation may fail after upgrading for configurations with a Request Logging profile.

This issue occurs when all of the following conditions are met:

  • The UCS file has a Request Logging profile configuration with at least one of the following conditions:
    • A Request Logging profile references a non-existent pool.
    • A Request Logging profile references a pool in a non-default administrative partition without specifying the path to the /<partition>/<pool>.
  • You upgrade from 11.0.0 or 11.1.0 to 11.2.0 or later and roll forward the configuration.
  • You attempt to load an affected UCS created on 11.0.0 or 11.1.0 to a system running 11.2.0 or later.

Configuration validation in 11.0.0 and 11.1.0 may incorrectly allow for a Request Logging profile to reference a non-existent pool. This behavior may occur with either of the following conditions:

  • You use the tmsh command to create a Request Logging profile that references a non-existent pool.
  • You create a Request Logging profile that references a valid pool and then subsequently delete the pool.

Beginning in 11.2.0, increased validation stringency will cause the configuration to fail.

Impact

UCS installation fails to load after an upgrade to 11.2.0 or later.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Following an upgrade to 11.2.0 or later, when you boot to the new boot location and roll forward the configuration, or install an affected UCS archive, messages may display in the Configuration utility that appear similar to the following example:

    This BIG-IP system has encountered a configuration problem that may prevent the Configuration utility from functioning properly.
  • The system may log messages to the /var/log/ltm file that appear similar to the following example:

    01070277:3: The requested Pool (/Common/pool1) was not found. Unexpected Error: Loading configuration

Workaround

If you encounter this issue after upgrading to 11.2.0 or later, F5 recommends that you reboot to the previous 11.1.0 or earlier boot location, reconfigure the affected Request Logging profile to reference an existing pool, and then reboot to the 11.2.0 or later boot location and roll forward the configuration again. Alternatively, you can edit the affected UCS file and modify the affected Request Logging profile. To modify the UCS file and the affected Request Logging profile, perform the following procedure:

Impact of workaround: If this procedure fails to resolve the issue, you may need to reboot to the previous 11.1.0 or earlier boot location, modify the affected Request Logging profile, and then roll the configuration forward to the desired boot location again.

Note: In this procedure, F5 assumes that the BIG-IP system is still booted into the 11.2.0 or later boot location following the upgrade operation.

  1. Transfer the UCS archive to the BIG-IP system.

    Note: For assistance transferring the UCS archive from another BIG-IP device using SCP, from a remote FTP server using FTP, or from an attached workstation using HTTPS, refer to K175: Transferring files to or from an F5 system.

    Note: For assistance transferring the UCS archive from your workstation to the BIG-IP system using SCP, refer to the manual of your chosen SCP application.

    For the purposes of this procedure, the example location and name of the UCS archive that has been transferred to the BIG-IP system is:

    /var/tmp/My_Archive.ucs
  2. Log in to the command line.
  3. Create a working directory by typing the following command:

    mkdir /var/tmp/UCS
  4. Extract the UCS archive to the working directory created in Step 3 using the following command syntax:

    tar -zxf <old archive> -C <working directory>

    For example:

    tar -zxf /var/tmp/My_Archive.ucs -C /var/tmp/UCS/
  5. Change to the working directory created in Step 3 using the following command syntax:

    cd <working directory>

    For example:

    cd /var/tmp/UCS/
  6. Change the permissions on the bigip.conf file from the archive to allow write access by typing the following command:

    chmod +w config/bigip.conf
  7. Using a text editor, open the extracted bigip.conf file.

    For example:

    vi config/bigip.conf
  8. Locate and edit the affected Request Logging profile so that it references a valid existing pool.

    For example:

    ltm profile request-log /Common/my_requestlog_profile {
            app-service none
            response-log-pool /Common/pool1        
    }
  9. Save and exit the file.
  10. Set the permissions for the extracted bigip.conf file back to the default (read-only), by typing the following command:

    chmod -w config/bigip.conf
  11. Create a new UCS Archive with the modified files by using the following command syntax:

    tar -czf <newarchive> *

    For example:

    tar -czf MyRebuiltArchive.ucs *
  12. Install the newly created UCS Archive using the following command syntax:

    tmsh load sys ucs /var/tmp/<working directory>/<newarchive>

    For example:

    tmsh load sys ucs /var/tmp/UCS/MyRebuiltArchive.ucs
