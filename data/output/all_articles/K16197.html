Topic

You should consider using this procedure under the following conditions:

  • You want to review current or archived log files that are generated by the BIG-IP system.
  • You want to understand the BIG-IP log message format.

Description

BIG-IP log files include important diagnostic information about the events that are occurring on the BIG-IP system. Some of the events pertain to the Linux host. For example, the Linux host generates system messages that pertain to the Linux host operating system, including messages that are logged during system startup, and information logged by the background daemons that run on the system. Other events are specific to the BIG-IP operating system. For example, the BIG-IP operating system generates messages that pertain to local and global traffic events, and configuration changes (audit logging).

Local logging

By default, the BIG-IP system logs events locally and stores messages in the /var/log directory. For BIG-IP events, the system routes messages from the errdefs subsystem through syslog-ng to the local log files. For non-BIG-IP events, the system routes messages directly through syslog-ng to the local log files. In addition, you can configure the system to use the high-speed logging mechanism (HSL) to store the logs in either the syslog or the MySQL database.

Remote logging

You can configure the system to use the HSL mechanism to log messages to a pool of remote log servers. If the BIG-IP system processes a high volume of traffic or generates an excessive amount of log files, F5 recommends that you configure HSL remote logging. Refer to the Configuring Remote High-Speed Logging chapter of the BIG-IP LTM External Monitoring of BIG-IP Systems: Implementations manual.
Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Alternatively, you can configure the system to log messages to remote syslog servers. For more information refer to K13080: Configuring the BIG-IP system to log to a remote syslog server.

Log message format

Log messages are formatted differently depending on the type of log and the component that generated the event messages. The log formats are discussed in the following sections.

Local traffic log message format

The local traffic (ltm) log messages generated by the BIG-IP system include the following types of information:

<time stamp> <host name> <level> <service[pid]> <message code> <message text>

  • <time stamp> is the time/date that the system logged the message.
  • <host name> is the host name of the BIG-IP system that generated the message.
  • <level> is the severity of the log message. For information about the severity levels, refer to the Levels section in K15934495: Configuring the level of information that syslog-ng sends to log files.
  • <service> is the name of the service (and process ID) that generated the message.
  • <message code> is the code that is associated with the message. The code is comprised of the following sub-codes:
    • Product Code: The first two hex digits form the product code. For example, 0x01 is the BIG-IP product code.
    • Subset Code: The third and fourth hex digits are the subset code. For example, 0x2a is the subset code for LIBHAL.
    • Message Number: The next four digits form the message number within a module.
    • Severity Level: The last digit between the colon symbols is the severity level, with 0 being the highest severity level.
  • <message text> is the description of the event that caused the system to log the message.

Linux host log message format

Most log messages generated by the Linux host include a format similar to the local traffic logs with the exception of the message code.

Audit log message format

The audit log messages generated by the BIG-IP system include the following types of information:

<time stamp> <host name> <level> <service[pid]> <message code> <user> <event>

  • <time stamp> is the time/date that the system logged the message.
  • <host name> is the host name of the BIG-IP system that generated the message.
  • <level> is the severity of the log message. For information about the severity levels, refer to the Levels section in K15934495: Configuring the level of information that syslog-ng sends to log files.
  • <service> is the name of the service (and process ID) that generated the message.
  • <message code> is the code that is associated with the message (refer to the previous Local traffic log message format section for message code sub-code definitions).
  • <user> is the name of the user who made the configuration change, the user's partition, and the user's permission level.
  • <event> is the description of the configuration change or event that caused the system to log the message.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You can access one or more of the following tools:
    • The Configuration utility
    • The TMOS Shell (tmsh)
    • The Advanced Shell (bash)

Procedures

You can view log files that are logged locally on the BIG-IP system by using the Configuration utility, tmsh, or bash. To do so, perform the following procedures:

  • Use tmsh to review log files
  • Use bash to review log files
    • Review current (unarchived) log files
    • Review archived log files
    • Use code expansion to view log files
  • Use the Configuration utility to review log files

Use tmsh to review log files

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view log files, use the following command syntax:

    show /sys log <log>

    For example, to view the ltm log file, enter the following command:

    show /sys log ltm

    Note: To conserve system resources, tmsh limits the maximum line count to 10,000 by default. If you want to view beyond the default 10,000 lines, add the lines option as described in step 4 of this procedure.

  3. You can also specify a date range when reviewing log files from tmsh. To do so, use the following command syntax:

    show /sys log <log> range <date range>

    • For example, to view ltm logs from three days ago until now, enter the following command:

      show /sys log ltm range now-3d

    • For example, to view all ltm logs from 2015-03-05, enter the following command:

      show /sys log ltm range 2015-03-05

    • For example, to view ltm logs from two to four days ago, enter the following command:

      show /sys log ltm range now-2d--now-4d

    • For example, to view ltm logs from 2015-03-02 through 2015-03-05, enter the following command:

      show /sys log ltm range 2015-03-02--2015-03-05

    Note: For more information about tmsh data/time formats, refer to the time help page. To do so, enter help time at the tmsh prompt.

  4. Alternatively, you can also specify the number of log lines you wish to review from tmsh. To do so, use the following command syntax:

    show /sys log <log> lines <maximum line count>

    For example, to view the 10,000 lines of ltm logs, enter the following command:

    show /sys log ltm lines 10000

    Note: To conserve system resources, tmsh limits the maximum line count to 10,000 by default if you do not specify the lines option. You should ensure your system has sufficient resources if you want to specify the maximum line count beyond 10,000.

    Additionally, you can combine the range and lines option together to limit the maximum line count within a specific date range. To do so, use the following command syntax:

    show /sys log <log> range <date range> lines <maximum line count>

    For example, to view ltm logs from ten days ago until now and limit the maximum line count to 11,000, enter the following command:

    show /sys log ltm range now-10d lines 11000

Use bash to review log files

Impact of procedure: Performing the following procedures should not have a negative impact on your system.

Review current (unarchived) log files

  1. Log in to the BIG-IP command line.
  2. To change to the /var/log directory, enter the following command:

    cd /var/log

  3. Use a Linux utility such as cat, or less, to review the log file.

    For example, to view the ltm log file, enter the following command:

    cat ltm

Review archived log files

By default, the BIG-IP system compresses log files on a daily basis and deletes archived copies that are older than eight days. Archived log files are stored in the /var/log directory and can be viewed by performing the following steps:

  1. Log in to the BIG-IP command line.
  2. To change to the /var/log directory, enter the following command:

    cd /var/log

  3. Use a Linux utility such as zcat, zless or zmore, to review the desired log file.

    For example, to view the ltm.2.gz log file, enter the following command:

    zcat ltm.2.gz

Use code expansion to view log files

You can view the details of the BIG-IP message codes when viewing log files. Doing so may provide more information about the message. To view log files using code expansion, perform the following steps:

  1. Log in to the BIG-IP command line.
  2. Change to the /var/log directory by entering the following command:

    cd /var/log

  3. To view log files using code expansion, use the following command syntax:

    cat <log> |bigcodes |less

    For example, to view the ltm log file using code expansion, enter the following command:

    cat ltm |bigcodes |less

    The following ltm log message example displays expanded message code:

    Mar 5 08:34:00 bigip_1 err mcpd[7430]: 01070366 (Product=BIGIP Subset=MCPD) :3: Bad password (abc123): BAD PASSWORD: it is WAY too short

Use the Configuration utility to review log files

The most commonly used log files (for example, system, local traffic, and audit) are displayed in the Configuration utility. To review log files using the Configuration utility, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs.
  3. Select the tab that corresponds to the type of logging category you want to review.
  4. Use Search to search for event strings or use the list to page through the available logs.
