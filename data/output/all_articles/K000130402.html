K000130402: The fipscardsync (fips-card-sync) command fails for BIG-IP devices configured in an HA pair after RMA.

Type
Support Solution
Published
2022-12-29
Updated
2023-06-20
Source
https://my.f5.com/manage/s/article/K000130402
Description
The fipscardsync (fips-card-sync) command fails for BIG-IP devices configured in an HA pair for ex. after RMA.
  
ERROR: Synchronization failed.
ERROR: Read error


 Environment
 
  • BIG-IP devices configured in an HA Pair
  • TMOS versions starting with 16.1.1, 15.1.5.1, 14.1.4.6, 13.1.5
  • FIPS hardware security module (HSM)

 Cause

Issue is related to ID1136081 and occurs when the FIPS HSM card has been initialized on an impacted version.

 Recommended Actions

Apply the following workaround steps on the impacted BIG-IP device to resolve the fipscardsync issue:
1. Download n3fipsutil tool from downloads.f5.com
  • Log in to downloads.f5.com and click Find a Download
  • In the Hardware-Specific area, click FIPS-firmware-upgrade
  • Select n3fips-firmware-upgrade - Hardware-Specific from the list.
  • Click the file name n3fipsutil to start the download.
  • Read the End User Software License and click I Accept
  • Click the file name n3fipsutil-< version-and-build-number>.im to start the download.
  • Download the corresponding checksum file and README file.
  • The corresponding checksum file has the same name as the IM file, except that .md5 is the file extension.
  • After the download completes, verify the integrity of the file by checking the MD5 checksum.

 NOTE: It must be performed in the maintenance window only as you need to stop all running services.

2. Before you can back up the FIPS key for the BIG-IP system, you must use SCP to move the n3fipsutil IM file to a directory on the system, such as /shared/images.

3. Connect to the system using the serial console or by opening an SSH session to the management IP address.
   
4. Log in to the command line of the system using an account with admin access.
   
5.   Stop all services.
    
 tmsh stop sys service all


   
6.  Create an empty directory for the backup in /shared/images/<backup directory>.
   
7.    Run the n3fipsutil tool:
    
 ./n3fipsutil -backup <directory_name >  -c 1


   
8. Once back up is successful, copy the back up to new device /shared/images/<backup directory> through scp.
 
9.  Restart all services:
    
 tmsh start sys service all


10. Use SCP to copy the entire backup directory, without modifying the contents of the directory, off site to a secure location and to active  device.
   
11. Restore the backup on the device with below command:

    
./n3fipsutil -restore <directory_name >  -c 1


    Enter security officer password:

Once the config is restored make sure this restore should not cause any issues to existing config on the active device.
 
12. Verify keys with help of below command:
   
 tmsh show sys crypto fips key

all keys should now exists.
