Known Issue

The Status LED for a VIPRION blade may incorrectly indicate the blade is not seated properly.

This issue occurs when the following condition is met:

  • The blade is installed in a VIPRION 2400 chassis.

If the lopd process loses connectivity with the LOP (Lights Out Processor) subsystem, a watchdog timeout may restart the LOP. When the LOP restarts, the four front panel LEDs (Primary, Secondary, Status and Alert) are reset to their default states. When connectivity is restored, the LEDs are not updated to reflect the correct current status.

The default state of the Status LED is amber (solid yellow), which is indicative of a blade that has not been seated properly.

Impact

The VIPRION blade status cannot be determined.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The Status LED is amber (solid yellow) for a VIPRION blade known to be seated properly.

Workaround

To work around this issue, you can restart the fpdd (front panel display daemon) process. To do so, perform one of the following procedures by using either the Traffic Management Shell (tmsh) or the command line:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

Using the tmsh utility

Restart the fpdd process using the Traffic Management Shell (tmsh) by performing the following procedure:

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To restart the fpdd process, type the following command:

    restart sys service fpdd

Using the command line

Restart the fpdd process by entering the following command from the BIG-IP command line:

bigstart restart fpdd
