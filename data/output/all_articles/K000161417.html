K000161417: ASM blocks requests due to "Illegal cross-origin request [1]"

Type
Support Solution
Published

Updated
2026-05-25
Applies to

Source

Description

BIG-IP ASM may block POST requests with the violation "Illegal cross-origin request [1]" even when the request is legitimate. This occurs when the HTTP request contains an Origin header set to null. The violation is logged as:

Illegal cross-origin request [1]

Environment

  • Product: BIG-IP ASM
  • Version: 16.x, 17.x, 21.x 
  • Configuration:
    • CORS enforcement enabled (globally or per URL)
    • POST requests with header:  Origin: null

Cause

This behavior is due to CORS enforcement in BIG-IP ASM. When CORS enforcement is enabled, ASM validates the Origin header. ASM does not allow a null value in the Origin header, resulting in the "Illegal cross-origin request [1]" violation.

Answer/Recommended Actions

To resolve the false-positive CORS violation, disable CORS enforcement using one of the following methods:

  • Option 1 – Disable CORS Enforcement Globally:
    1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    2. Find HTML5 Cross-Domain Request Enforcement.
    3. Set enforcement mode to Disabled.
    4. Save and apply the policy.
  • Option 2 – Disable CORS Enforcement Per URL:
    1. Go to Security > Application Security > URLs > Allowed HTTP URLs.
    2. Select the affected URL.
    3. Switch to Advanced View.
    4. Select the HTML5 Cross-Domain Request Enforcement tab.
    5. Set Enforcement Mode to Disabled.
    6. Save and apply the policy.
  • Option 3 – Use an iRule to Modify the Origin Header:
    • Deploy an iRule to intercept and modify the Origin null header before ASM inspection. See article, K41079106: Using iRules to modify HTTP headers for BIG-IP ASM for guidance.
