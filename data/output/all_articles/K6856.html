K6856: BIG-IP LTM connections using a SNAT through an iRule are forced to open new server side connections

Known Issue

This is the result of a known issue. When a client opens a connection to a BIG-IP LTM virtual server using a SNAT without a port specified within an iRule, the internal logic of the SNAT does not check to see if an existing and idle server-side connection is available. The SNAT incorrectly assumes that no idle connection exists, and opens a new server-side connection. As a result, multiple server-side connections are opened, which slows connections to the BIG-IP LTM system.

F5 Product Development tracked this issue as CR69087 and it was fixed in BIG-IP LTM 9.2.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
