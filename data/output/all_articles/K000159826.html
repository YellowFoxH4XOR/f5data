Description

The BIG-IP AFM system does not record the VLAN which the dropped packets occurred. This is evident in the related logs where VLAN ID is recorded as zero (0), for example,

TMM_New:2660:<13> Feb  6 11:03:51 slot1/bvl-tenant02.ptt notice AVR: DoS L3 API Call. Drop flag: 1, Attack type: 44, Attack ID: 0, VLAN ID: 0, VLAN GROUP: NULL, dest_ip NULL , sip NULL , vip name Device, Dos Profile: /Common/dos-device-config, Count: 307, Size of packets: 23946
TMM_New:13451:<13> Feb  6 11:03:52 slot1/bvl-tenant02.ptt notice AVR: DoS L3 API Call. Drop flag: 1, Attack type: 44, Attack ID: 0, VLAN ID: 0, VLAN GROUP: NULL, dest_ip NULL , sip NULL , vip name (null), Dos Profile: /Common/dos-device-config, Count: 499, Size of packets: 38921
TMM_New:27831:<13> Feb  6 11:03:54 slot1/bvl-tenant02.ptt notice AVR: DoS L3 API Call. Drop flag: 1, Attack type: 44, Attack ID: 0, VLAN ID: 0, VLAN GROUP: NULL, dest_ip NULL , sip NULL , vip name (null), Dos Profile: /Common/dos-device-config, Count: 5347, Size of packets: 417010

If you use the following example tmsh command in the tmsh utility to investigate the dropped packets for a specific VLAN, you may observe a mismatch in the dropped-requests statistics between the output of the tmsh command and the DoS Visibility report in the BIG-IP Configuration utility.

show analytics dos-l3 report view-by attack-id measures { dropped-requests } drilldown { { entity vlan values { /Common/services } } } range now-1w

However the observation is not accurate.

Environment

  • BIG-IP AFM is provisioned and configured.
  • The DoS Visibility report located on the Statistics > DoS Visibility page or the Security > Reporting > DoS > Dashboard page in the BIG-IP Configuration utility

Cause

The perceived mismatch is because the example tmsh command limits its statistics output to a specific VLAN, in this example /Common/services, while the DoS Visibility report includes all globally dropped requests.

Recommended Actions

If you would like to use the tmsh command to view the statistics for dropped-requests, you should include all VLANs by ensuring the drilldown parameter is set to none when you run the tmsh command. For example,

show analytics dos-l3 report view-by attack-id measures { dropped-requests-per-second dropped-requests allowed-requests-per-second allowed-requests total-requests-per-second } drilldown none range now-1w

This displays all attack-related request statistics, including those associated with hardware drops not mapped to a VLAN similar to the DoS Visibility report in the BIG-IP Configuration utility.
