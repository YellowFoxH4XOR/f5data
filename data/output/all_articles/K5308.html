Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K15367: Configuring gateway fail-safe using the tmsh utility (11.x)

The gateway fail-safe feature allows further redundancy between a failover pair of BIG-IP systems that point to different gateways. The gateway fail-safe feature allows each BIG-IP system to monitor the upstream gateway to which they are connected. If the gateway is marked down, the BIG-IP system can fail over to its partner system to prevent further disruption to traffic.

Before configuring the gateway fail-safe feature, you should consider the following information:

  • If the redundant BIG-IP systems reference the same virtual HSRP/VRRP gateway, specify the virtual router group IP address in the gateway fail-safe pool.
  • In most cases, the Failover action is the optimal gateway fail-safe action. The Reboot and Restart All actions can be used when upstream equipment requires the BIG-IP system to drop the links to clear out their ARP cache or cause a reset of their interfaces.
Configuring gateway fail-safe from the command line

Gateway fail-safe makes use of gateway pools for monitoring the gateway. Therefore, the gateway pools must be assigned to their corresponding units containing the gateway for that unit, since the pool information will be synchronized between the systems.

  1. Determine the unit ID of the system on which the pools will be created by using the following syntax:

    bigpipe db Failover.UnitId

    For example:

    bigpipe db Failover.UnitId
    Failover.UnitId = 1

    Note: You need to perform this step only once; the step is required to ensure that you associate the correct gateway with the correct unit.

    Once both pools are created and enabled with their respective unit IDs, the configuration will be synchronized.

  2. Create two gateway pools (one for each unit), with the respective gateways specified as the member, by using the following syntax:

    bigpipe pool <pool_name> { monitor all <monitor rule> member <ip address:port> }

    For example, if the BIG-IP systems reference the same virtual HSRP/VRRP gateway address, you would use syntax similar to the following example:

    bigpipe pool gateway_pool_unit1 {monitor all gateway_icmp member 10.0.0.1:0}
    bigpipe pool gateway_pool_unit2 {monitor all gateway_icmp member 10.0.0.1:0}

    For example, if the BIG-IP systems reference separate gateways, you would use syntax similar to the following example:

    bigpipe pool gateway_pool_unit1 {monitor all gateway_icmp member 10.0.0.1:0}
    bigpipe pool gateway_pool_unit2 {monitor all gateway_icmp member 10.0.0.2:0}

    Important: The gateways specified in the pools should contain only the gateway associated with the unit to which they are assigned. For example, the gateway pool for unit 1 should only contain the IP address of the upstream router to which unit 1 is connected. Failure to follow this rule can result in the units changing state from active to standby, or rebooting, as the respective units cannot communicate with the partner system's gateway.

    Typically, a gateway pool contains a single gateway, but can be configured with multiple gateways using the following syntax:

    bigpipe pool <pool_name> { monitor all <monitor rule> member <ip address:port> member <ip address:port> }

  3. Specify which pool belongs to which unit by using the following syntax:

    bigpipe pool <pool_name> unit <unit_number>

    For example:

    bigpipe pool gateway_pool_unit1 unit 1
    bigpipe pool gateway_pool_unit2 unit 2

    This command indicates to the BIG-IP system that the pool specified with the individual unit ID number will be used with only that unit configured with the specified ID. This command also allows changes to be made on either system, and changes synchronized to the peer system.

  4. Specify the minimum number of members that need to be marked UP by using the following syntax:

    bigpipe pool <pool_name> min up members <number>

    This command indicates that the system should take action if the minimum number of members falls below the specified value.

    For example:

    bigpipe pool gateway_pool_unit1 min up members 1
    bigpipe pool gateway_pool_unit2 min up members 1

  5. Specify the action that the system should take when the minimum number of members falls below the value set in Step 4 of this procedure, by using the following syntax:

    Note: In most configurations, failover is the optimal action. The reboot and restart all actions can be used when upstream equipment requires the links to drop to clear out their ARP cache or cause a reset of their interfaces.

    bigpipe pool <pool_name> min up members (reboot | failover | restart all)

    • reboot:

      The entire system will reboot resulting in a failover.

    • failover:

      The system will failover, but not reboot.

    • restart all:

      All BIG-IP-related daemons, as listed using bigstart status, will restart. This will cause a failover to occur.

    For example:

    bigpipe pool gateway_pool_unit1 min up members failover
    bigpipe pool gateway_pool_unit2 min up members failover

  6. Enable gateway fail-safe on the pools by using the following syntax:

    bigpipe pool <pool_name> min up members (enable | disable)

    For example:

    bigpipe pool gateway_pool_unit1 min up members enable
    bigpipe pool gateway_pool_unit2 min up members enable

    Note: If disable is specified, this turns gateway fail-safe off and the pool is viewed as a normal pool by the system.

    Important: The gateways specified in the pools must be connected to the respective units, and the gateways must be reachable by the system. Once gateway fail-safe is enabled, it can cause the system to take the action specified if the system is unable to communicate with the gateways.

  7. Save the gateway fail-safe pool configurations by typing the following command:

    bigpipe save

  8. Synchronize the configuration between the systems by typing the following command:

    bigpipe config sync min

  9. Reload the system configuration by typing the following command:

    bigpipe load

    Note: The bigpipe load command should be run on both BIG-IP systems in the high-availability pair.

  10. To verify that the gateway fail-safe is now enabled, type the following command:

    bigpipe ha table

    You should see the pool min up member line, which indicates that the gateway fail-safe feature is enabled on the system.
