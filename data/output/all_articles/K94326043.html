Description

A web application may have a flow that allows an attacker to target end users and steal their sessions or other requests on behalf of the victims. Although the attack is executed on the end user who visited the website, the actual flow is in the web application. There are many ways to execute a cross-site scripting (XSS) attack, including evasion and miscellaneous encoding, which makes the attack difficult to detect. The success of an XSS attack also depends on the end user browser type and version.

Environment

  • The application is under an XSS attack.
  • Your system is versioned for BIG-IP ASM/Advanced WAF 13.x and later.
  • A security policy is assigned to the virtual server.
  • The BIG-IP ASM request log is enabled by default to the illegal request.

Cause

None

Recommended Actions

BIG-IP ASM/Advanced WAF can mitigate XSS attacks using the attack signature feature or defined meta characters. These procedures list the steps needed to mitigate an XSS attack using the appropriate attack signatures and assumes the default configuration is defined.

Note: Default configuration means a security policy created using any of the policy templates with transparent and staging period on for the policy.

These procedures include steps about how to assign the relevant attack signature set, enable it, and configure it in blocking mode so that you can mitigate the XSS attacks. The final step is the mitigation verification, where the administrator can view the blocked XSS attack.

Impact of procedure: Adding attack signatures to the security policy can generate false positives. In such case, false positives should be removed using the Learning page. Adding the XSS attack signatures set includes various types of XSS technology, which allows protection regardless of the back-end infrastructure server.

  • Adding XSS attack signatures to the security policy
  • Enabling and enforcing the XSS attack signatures
  • Switching the security policy to Blocking mode
  • Verifying that the XSS attack is blocked

Adding XSS attack signatures to the security policy

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. In the upper-left corner, from the Current edited policy list, select the desired security policy.
  4. For BIG-IP ASM 15.x and later, skip to the next step. For BIG-IP ASM 13.x through 14.x, in the upper-right corner, select Advanced.
  5. Select Attack Signatures to reveal the settings.
  6. Under the Attack Signatures table, select Change.

    The Configuration utility displays the Select Policy Attack Signature Sets page.

  7. Select the Cross Site Scripting Signatures check box, and then select Change.
  8. In the Attack Signatures table, verify that the signature set is enabled for Learn, Alarm, and Block.
  9. Select Save, and then select Apply Policy.

Enabling and enforcing the XSS attack signatures

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. For BIG-IP ASM 15.x and later, skip to the next step. For BIG-IP ASM 13.x through 14.x, in the upper-right corner, select Advanced.
  4. To reveal the settings, select Attack Signatures.
  5. For the Cross Site Scripting Signatures set, select Change Signature Properties and then select Enforce and Enable all Attack Signatures in the Signature Set.
  6. Under the attack signatures list, clear the Enable Signature Staging check box.
  7. Select Save, and then select Apply Policy.

Switching the security policy to Blocking mode

BIG-IP ASM 15.x and later

  1. Log in to the BIG-IP Advanced WAF/ASM Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the desired security policy.
  4. Under the Learning and Blocking section in General Settings, locate the Enforcement Mode setting and select Blocking.
  5. Select Save, and then select Apply Policy.

BIG-IP ASM 13.x through 14.x

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Under General Settings, for Enforcement Mode, select Blocking.
  4. Select Save, and then select Apply Policy.

Verifying that the XSS attack is blocked

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select the Open filter (funnel or magnifying glass icon).
  4. For BIG-IP ASM 17.x, skip to the next step. For BIG-IP ASM 13.x through 16.x, select IP / Username / URL.
  5. For Attack Type, select Cross Site Scripting (XSS), and then select Apply Filter.

    The blocked request with cross-site scripting is listed in the request log.

    Note: In the request log, the violation name is attack signature detected.
