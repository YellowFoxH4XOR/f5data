Description
An unsuccessful initial sync can remove non-default locally defined BIG-IP users.
Corrupted local user passwords on Physical Node after synch with Virtual Node.
After joining a virtual node to the trust group while configured to offline mode, then synchronizing the physical active node and local user accounts on the physical active node got corrupted for some accounts.

Environment

  • BIG-IP
  • After adding a 3rd device to their device-group.
  • The config-sync operation fails to load the new configuration, for example, because it is performed in the wrong direction, and the new empty device tries to overwrite and remove the configuration from the existing ones, which is blocked by non-shared object references.

Cause

ID1145749

Recommended Actions

Note: Step 1-3 is for validation and investigation. Step 4 provides the fix. 

  1. Generate qkview for investigations. K12878: Generating diagnostic data using the qkview utility
  2. Collect a tarball of the logs for investigation. Run the command : # tar zcvf /var/tmp/$HOSTNAME-logs.tar.gz /var/log/*
  3. Confirm that config sync was performed and did not succeed.
    You will see Changes Pending on the GUI and you can run the command : # tmsh show cm sync-status 
    Example output : 
    show /cm sync-status
    --------------------------------------------------------------------------------
    CM::Sync Status
    --------------------------------------------------------------------------------
    Color    yellow
    Status   Changes Pending
    Mode     high-availability
    Summary  Changes pending
    Details
             example1.corp: connected
             example2.corp: connected
             Sync_Failover (Changes Pending): Changes pending   <-------------(shows the synchronization failure)
              - Recommended action: Synchronize example1.corp to group Sync_Failover
     
  4. Log in as admin or root, and manually reset the passwords on the affected local user accounts.  This will repopulate the users into the unix passwd and shadow files.

Additional Information
This can be triggered by syncing a new device in the wrong direction, and nearly wiped out the existing device-group's configuration.

Because the user accounts are only removed from the unix config files, and are still present in bigip_user.conf, they will still show up in the bigip configuration.  

To 're-activate' them you'll need to log in as admin or root and reset those account's passwords, as the password information is only stored in the shadow file and is lost as a result of this bug.  

User role assignments and shell settings are not lost, as they're stored in bigip*.conf
