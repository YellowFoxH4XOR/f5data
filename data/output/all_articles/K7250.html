Topic

The MIME standard provides a mechanism for combining one or more different sets of data within a single message body. For example, a multipart POST request is commonly used when a web form requires both binary and text data to be uploaded to the web server.

BIG-IP ASM is not designed to provide protection for binary uploads. Therefore, if your web application code requires multipart POST requests containing binary data, F5 recommends that you do not configure the BIG-IP ASM system to enforce any parameter checking on those elements.

By default, BIG-IP ASM blocks any multipart data that contains a NULL byte. However, if the blocking mask is changed to allow NULL characters in multipart data, the system will stop enforcing any parameter checks at the first NULL byte encountered in the file. Additionally, it is not possible to enforce a maximum parameter length for any parameters where you may expect a NULL character to appear in the data prior to the end of the actual data.

Note: BIG-IP ASM 9.4 will only generate a Value too long for pattern checks violation if the size set by max_length_for_parameter_checks is reached before the first NULL byte in the data. In version 9.2.4, BIG-IP ASM will stop processing parameter checks either when max_length_for_parameter_checks is reached or the first NULL byte is found.
