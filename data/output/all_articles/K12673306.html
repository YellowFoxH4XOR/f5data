Description

While performing an activity, one of the following behaviours is seen. This Results in the Management IP becoming inaccessible and access to the Appliance is limited to the Console:

  • Configuration fails to load.
  • Management IP is unreachable, even though it appears to be configured.
  • Management IP is inaccessible even if modified to a new IP address in the subnet.
  • Management IP may ping the Gateway and vice-versa but outside elements cannot reach it.

Environment

  • BIG-IP
  • Management IP
  • Self-IP

Cause

The BIG-IP configuration is not loaded properly, therefore it can lead to an issue with how the Management IP would respond.

Recommended Actions

If the Management IP is inaccessible, there are other ways you can try to access the appliance, for example, you can try loading the bigip_base.conf file, but, modify a Self-IP to allow both SSH and HTTPS to either access the appliance via GUI or CLI, for example:

  1. Select which Self-IP you would like to use from the bigip_base.conf file, for example:
    net self /Common/self-test {
        address xx.xx.xx.xx/24
        allow-service {
            tcp:4353
        }
        traffic-group /Common/traffic-group-local-only
        vlan /Common/VLAN_Test
    }
  2. Once the Self-IP is chosen, modify the Self-IP using the following sequence.
  3. On the CLI, type tmsh.
  4. Once prompted to tmsh, issue load /sys config merge from-terminal
  5. On the prompt paste the following, add the SSH and HTTPs ports to the Self-IP configuration:
     net self /Common/self-test{
        address xx.xx.xx.xx/24
        allow-service {
            tcp:22           
            tcp:4353
            tcp:443          
        }
        traffic-group /Common/traffic-group-local-only
        vlan /Common/VLAN_Test
    }
  6. Press CTRL-D to submit.

Access to the CLI or the Configuration Utility using the Self-IP should be successful.
