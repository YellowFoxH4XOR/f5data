Description

When traffic traverses the full proxy on the BIG-IP, in some cases TCP settings can be toggled to increase performance to better match direct connection performance.

Environment

  • BIG-IP LTM Virtual Server
  • TCP Profiles
  • Throughput
  • BIG-IP 12.x and prior

Cause

Every environment is different in the TCP settings that are used prior to introducing a BIG-IP Virtual Server into the environment. These are mere suggestions have been effective for F5 Support in prior cases to increase throughput on their virtual servers.

Recommended Actions

  • Starting in 13.x we introduced new optimized TCP profiles that increase the overall performance of the Virtual Server.

    A recommendation is copying the setting out of these updated 13.x and 14.x profiles and match them in 12.x to match the new settings and apply the new custom TCP lan/wan profiles to the virtual server.
    K37412295: Overview of the f5-tcp-lan profile (13.x - 15.x) Server side TCP profile
    K10281257: Overview of the f5-tcp-wan profile (13.x - 15.x) Client side TCP profile
     
  • If you would like to manually create these profiles via the CLI, please follow these instructions:
    Note: This will add in the 13.x optimized TCP profiles, Nagles in 13.x is Auto, for back-porting it must be 'enable/disable' it is enabled for this example.
    Note: F5 Support is not authoritative on manually editing configuration files.  If you are in need of comprehensive assistance for your environment, F5 Professional Services can assist.
     
  1. Open the command line to the BIG-IP:
    Edit the bigip.conf:
    vi bigip.conf
  2. Scroll to the bottom:
    PgDn to the end of the list
    Arrow back up to the last line
  3. Insert and add a line:
    Press i for insert.
  4. Go the end of the last line and press enter
    Copy the following into your clipboard:

        ltm profile tcp custom-tcp-wan {
            congestion-control woodside
            defaults-from /Common/tcp
            delayed-acks disabled
            init-cwnd 10
            init-rwnd 10
            minimum-rto 500
            nagle enabled
            proxy-buffer-high 262144
            proxy-buffer-low 196608
            rate-pace enabled
            receive-window-size 131072
            send-buffer-size 262144
            tail-loss-probe enabled
        }
        ltm profile tcp custom-tcp-lan {
            defaults-from /Common/tcp
            init-cwnd 16
            init-rwnd 16
            minimum-rto 200
            nagle enabled
            proxy-buffer-high 65535
            proxy-buffer-low 32768
            rate-pace enabled
            send-buffer-size 65535
            tail-loss-probe enabled
        }
     
  5. In the CLI, paste the above profiles by right clicking
  6. Press esc
  7. Type :wq!
  8. Load the new profiles:
    Note: This will cause system to reload configuration and should be completed in a maintenance window
    tmsh load sys config
  9. Apply the new profiles to the Virtual Server and test.

  • Possible further recommendations:

  1. Toggle Nagles Algorithm and see if this makes a difference in your environment.
     
  2. You could test with a Performance Layer 4 Virtual Server
    • A Performance (Layer 4) virtual server is associated with a FastL4 profile.
    • A Performance (Layer 4) virtual server increases the speed at which the virtual server processes packets.
      ?????K01155812: Overview of the Performance (Layer 4) virtual server
       
  3. Upgrade to 13.x where the TCP Profiles have the option for Auto Memory Management
    • ??Auto Proxy Buffer
    • Auto Receive Window
    • Auto Send Buffer
      Enabling these will scale Auto settings per connection
       
  4. Test with a SSL Pass through Virtual Server if applicable in your environment
    • In this configuration, the BIG-IP system forwards encrypted SSL traffic to the back-end servers without decryption.
    • This type of configuration is preferable when you do not want the BIG-IP system to do anything with encrypted traffic but simply load balance it to a pool of destination server(s) for processing.
    • The BIG-IP system processes SSL traffic at the TCP layer and does not interact with the contents of the packet.
    • You are not required to configure Client SSL or Server SSL profiles since your virtual server does not decrypt or encrypt the SSL traffic.
    • Taking the SSL load off the BIG-IP can increase throughput.
      K14343463: Configuring the BIG-IP system to pass through SSL traffic

Additional Information

Note that these are suggestions that have worked for F5 customers in the past. Schedule maintenance windows when testing.
