Description

Loading UCS backup on multi-blade Velos tenant may produce connectivity issues, exhibiting as unresolved MAC addresses or ICMP failures. This is typically observed in migrations from old platforms.

As an example, tenant is deployed on slots 1 and 2, and in 'tmsh show sys cluster' TMM state is not ready on slot2:

Environment

  • F5OS-C 1.6.X, 1.8.X
  • TMOS 17.1.X
  • Multi-blade Velos tenant
  • UCS backup from different platform loaded on the tenant

Cause

The reason for the communication issue is due to the tenant system db 'scheduler.splitplanes.ltm' being set to false, coming over from the old platform config by way of a UCS load.
In the example above, the tenant is given two cores per slot, so with split planes enabled (the default), it is 1 TMM per slot.
But since the config has the system variable set to false, TMM started without split planes and had double (2) the TMMs running per slot.

Recommended Actions

To work around the issue, set tenant system db 'scheduler.splitplanes.ltm' to true, and for good measure reset-to-default, and then reboot all slots.

tmsh modify sys db scheduler.splitplanes.ltm value true
tmsh modify sys db scheduler.splitplanes.ltm reset-to-default
clsh reboot
