Description

Setting a route specifying MTU size like:
 
net route /Common/custom_route_1 {
    description none
    gw 192.168.10.1
    mtu 1340
    network 172.168.1.0/24
    partition Common
}
Virtual server which uses this route is not using MTU configured in the route.
 

Environment

  • BIG-IP
  • any version
     

Cause

Virtual server's Auto Last Hop is set default/enabled.
When it is default/enabled, route lookup is bypassed.
NOTE: default is equal to Global Auto Last Hop settings. By default Global Auto Last Hop is enabled.
Please refer further detail about Auto Last Hop: K13876: Overview of the Auto Last Hop setting (11.x - 16.x)
 

Recommended Actions

  1. Configured MTU for the target host or network using a static route object
  2. Disable Auto Last Hop for the relevant Virtual Server(s)
     

Additional Information

It may sometimes be necessary to configure MTU values for specific hosts or networks when Path MTU discovery is not working reliably.
Configuring the MTU value in a route works without further action for server-side traffic (traffic initiated by the BIG-IP). The BIG-IP will by default ignore route entries for client-side traffic (traffic initiated by a remote client) since the Auto Last Hop feature returns traffic based on the original source MAC address. As a result the configured MTU value will not be used.
