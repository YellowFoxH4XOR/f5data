Description

The BIG-IP Next instance stops processing traffic after a reboot. The config does not load due to a validation error. A newly deployed App or piece of config may not be working before the reboot.

 

Environment

  • BIG-IP Next 20.0, 20.1, 20.2
  • Central Manager 20.0, 20.1, 20.2
  • A recent deployment or change was made to the Next instance from Central Manager.

 

Cause

Pushing a config from Central Manager that fails configuration validation on Next can, under certain conditions, lead to Central Manager and the managed Next instance being in an asynchronous state.

 

Recommended Actions

Remove the most recently deployed App or Next configuration item until the Next instance resumes functionality. This can be done while the Next instance appears inoperative, as long as Central Manager can still communicate with the Next instance.

 

Additional Information

In the problem scenario, the Next instance will have a copy of the failing config and will continue to try to deploy that config with every config change. Meanwhile, Central Manager will believe the config was deployed successfully. However, subsequent config changes will fail until the errant configuration is removed or resolved. If a reboot is attempted, no config will load and the Next instance will not pass traffic.

The issue is tracked by ID1591537.
