K000136187: VDI connection lost after upgrade of VMware Horizon Connection Servers from 8.6 to 8.10

Source

Description

  • After you've upgraded the Horizon Connection Servers there is yellow triangle on the Webtop link/icon
  • Popup message appear while trying to connect: 
    Connection to your resource failed. Please click the Try Again button to try again or CLose button to close this dialog.
  • Packet capture shows HTTP 421 Unknown response coming from the VMware Horizon Connection Server
  • POST request sent by the APM forwarded via LTM VS contains incorrect Host header (e.g.: IP address -> Host: 192.168.1.1\r\n)
  • The VMware Horizon Connection Servers' logs show: Rejecting request: Unexpected Host header: xxxxx error message
  • Only HTML5 webclient is affected the VMware standalone client connections are OK

Environment

  • APM+LTM deployment
  • VMware Horizon Connection Servers upgrade from 8.6 to 8.10
  • HTML5 client

Cause

VMware Horizon Connection Servers rejects requests with unexpected Host header.

In previous versions (than 8.10) it seems that it was allowed (disregarded) but not anymore since 8.10

 Recommended Actions

  1. Follow K000130245: Change HTTP host header from an IP address to an FQDN using iRule to replace the Host header with expected value
  2. Create similar iRule and attach it to the LTM VS used to load balance connections to the VMware Horizon Connection Servers
when HTTP_REQUEST {
    if { [HTTP::host] equals "xxxx" } {
        HTTP::header replace "Host" "yyyy"
    }
}

 

Note: make sure to replace xxxx and yyyy placeholders with actual values.

xxxx is usually the IP address / FQDN of the LTM VS

yyyy should the the Host VMware Horizon Connection Server expects
