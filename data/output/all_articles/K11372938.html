Topic

This article applies to BIG-IP Next instances. For information about other systems, refer to the following articles:

  • K411: Overview of packet tracing with the tcpdump utility
  • K12313135:  Overview of the tcpdump utility on the VELOS system
  • K80685750:  Overview of the tcpdump utility on rSeries systems

Description

You can use the tcpdump utility to view traffic on BIG-IP Next instances managed by the BIG-IP Next Central Manager. The tcpdump utility is provided with the BIG-IP Next Debug Console, which can be enabled using the BIG-IP Next Central Manager. Running the tcpdump utility allows you to capture ingress and egress traffic to the BIG-IP Next instance.

In order to start a debug session, you need to have an SSH Key Pair for the client workstation from which you will be debugging. You specify the SSH public key using BIG-IP Next Central Manager to enable the debug session, then use the provided SSH command to connect to the BIG-IP Next Debug Console from the client workstation.

The tcpdump utility supports capturing additional internal TMM information by specifying the noise amplitude in the command. For more information about capturing internal TMM information, refer to K13637: Capturing internal TMM information with tcpdump.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command line access to a client workstation that has the curl, jq, and ssh-keygen utilities installed.
  • The client workstation has network access to BIG-IP Next instance managed by the BIG-IP Next Central Manager.
  • You will need at least one SSH Key Pair for the client workstation from which you will be debugging.

Procedures

  • Run the tcpdump utility
  • Download the tcpdump output file

Run the tcpdump utility

To debug a BIG-IP Next instance and use the tcpdump utility, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your BIG-IP Next instance.

  1. Log in to the client workstation with the curl, jq, and ssh-keygen utilities installed.
  2. If you already have an SSH key pair to use, copy the contents of SSH public key file you want to use. If not, generate a new SSH key pair using the following syntax:

    ssh-keygen -t <key_type>  -b <bits>

    For example, to generate a 2048 bit RSA key, enter the following command:

    ssh-keygen -t rsa -b 2048

    The command prompts for the file in which to store the keys, or choose the defaults. By default, ssh-keygen on Linux systems stores the RSA public key in ~/.ssh/id_rsa.pub and the private key in ~/.ssh/id_rsa. Copy the contents of the SSH public key file.

  3. Log in to the BIG-IP Next Central Manager webUI.
  4. Go to Manage Instances.
  5. Select the name of the BIG-IP Next instance you want to debug.
  6. Under LOGS & TROUBLESHOOTING, select Debug.
  7. Select Proceed.
  8. Enter the SSH public key into the SSH Public Key box.
  9. Select Start Debug Session. The BIG-IP Next Central Manager will provide the SSH command to use to connect to the BIG-IP Next Debug Console.

    Note: Once the debug session is started, navigating away from the Debug settings page in BIG-IP Next Central Manager does not stop the debug session.

  10. Copy the command and run it from the client workstation terminal to begin debugging. Once in the Debug Console you will be presented with the following prompt:

    ****************************************
    *                                      *
    * Welcome to BIG-IP Next Debug Console *
    *                                      *
    ****************************************
    Last login: Thu Sep 21 15:42:13 2023 from 10.10.11.100
    /

  11. You can now enter the tcpdump command to start capturing traffic. 
  12. To exit the BIG-IP Next Debug Console, enter exit at the Console. To stop the debug session on the BIG-IP Next Central Manager select Stop Debug Session in the Debug section of the instance settings.

From the BIG-IP Next Debug Console, you can list the available interfaces by entering the tcpdump -D command. The following example output shows the available interfaces, including tmm and the internal-vlan and external-vlan VLANs:

tcpdump -D
1.eth0
2.tmm
3.tmm_bp
4.internal-vlan
5.external-vlan
6.any (Pseudo-device that captures on all interfaces)
7.lo [Loopback]

When running the tcpdump utility, you can specify the interface or VLAN on which to capture traffic. You can also include filters to restrict the output to specified addresses, ports, and protocols.

For example, to capture traffic on all TMM interfaces, enter the following command:

Important: Running tcpdump on interface 0.0 has the potential to generate very large files. You should use filters to reduce the size of the capture when capturing on interface 0.0.

tcpdump -ni 0.0

Note: The -n option disables name resolution.

To capture only the internal-vlan VLAN, enter the following command:

tcpdump -ni internal-vlan

To specify destination port 8080, enter the following command:

tcpdump dst port 8080

You can combine options and use the -w option to save the output to a file. This example captures traffic on the external VLAN with destination port 8080 and saves the output to the next_external.pcap file in the current directory on the BIG-IP Next Debug Console. To stop the capture, type ctl-c:

tcpdump -ni external-vlan and dst port 8080 -w next_external.pcap

For more information about using tcpdump filters to capture traffic, refer to K411: Overview of packet tracing with the tcpdump utility.

Download the tcpdump output file

After you stop the tcpdump with ctl-c, the resulting tcpdump output file will be available in the current directory on the BIG-IP Next Debug Console. You can copy the tcpdump file to your local workstation using the scp utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your BIG-IP Next instance.

  1. On the client workstation, return to the active debug session.
  2. Copy the tcpdump output file using the following syntax:

    scp ./<tcpdump_file_name> <user>@<server_address>:/var/tmp/<tcpdump_file_name>

    For example, to copy the next_example.pcap file to the /var/tmp/ directory on the host at 10.10.10.100, enter the following command:

    scp ./next_example.pcap user@10.10.10.100:/var/tmp/next_example.pcap

    Type the user's password and press Enter to copy the file.
