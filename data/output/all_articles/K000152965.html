K000152965: WebUI keeps restarting

Type
Support Solution
Published
2025-08-12
Updated
2025-08-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000152965

Description

WebUI keeps restarting, causing frequent disconnects and making it difficult to do things. Traffic does not appear to be impacted, and SSh works.

You also notice the following messages in the var/log/tomcat/catalina.out file

# java.lang.OutOfMemoryError: Java heap space

# -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat"

# Executing /bin/sh -c "/usr/bin/restart_tomcat"

 

Environment

BIG-IP with multiple traffic objects.

Possibly large amounts of API calls.

 

Cause

Tomcat may run out of memory allocated to it, which can lead to the above errors and cause Tomcat to restart.

 

Recommended Actions

Allocate additional memory to tomcat from the host.

Important: Make sure the Linux host has enough available memory before allocating additional resources to tomcat! Otherwise you may cause the system to become unstable.

 

Check the available memory on the Linux host:

grep memfree /proc/meminfo

 

This returns the amount of free memory you have on the Linux Host. If you have enough free memory you can proceed with the next steps. If not, you may need to release some memory from TMM. That process is outlined here: https://my.f5.com/manage/s/article/K26427018

 

Once you know you have enough free memory, run the following commands to add additional memory to tomcat:

 

Note: This process should have no impact on traffic.

 

tmsh list sys db provision.tomcat.extramb

This will show you the current amount of additional memory allocated to tomcat.

To allocate more memory, increase this number by the amount you want to add.

tmsh modify /sys db provision.tomcat.extramb value 128 (adjust as needed)

Example: if the first command show you "Value: 128" and you want to add 128 more, you would run tmsh modify /sys db provision.tomcat.extramb value 256 (128 + 128)

tmsh list sys db provision.tomcat.extramb

This will confirm the new value is correct.

bigstart restart tomcat

 

Check the logs and confirm that the "java.lang.OutOfMemoryError" no longer appears. If it does, go through the above process again but add an additional 56 MB. Continue adding 56 MB until the errors stop.
