Known Issue

BIG-IP APM AAA pool modifications may inadvertently alter member priority group settings.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP APM system with an AAA profile that utilizes a pool containing multiple AAA server members.
  • Using the Configuration utility, you modify the AAA pool by adding or changing the pool level health monitor.

Impact

The priority group association of the pool members is reordered.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Prior to modifying the AAA pool monitor configuration, pool members are associated with a priority group.

    For example:

    ltm pool AAA_Test_Pool {
        members {
            10.0.1.101:ldaps {
                address 10.0.1.101
                priority-group 1
                session monitor-enabled
                state up
            }
            10.0.1.102:ldaps {
                address 10.0.1.102
                priority-group 2
                session monitor-enabled
                state up
            }
        }
        min-active-members 1
        monitor gateway_icmp
    }

  • After modifying the AAA pool monitor configuration, pool members are associated with a priority group in a different order than originally configured.

    For example:

    ltm pool AAA_Test_Pool {
        members {
            10.0.1.101:ldaps {
                address 10.0.1.101
                priority-group 2
                session monitor-enabled
                state up
            }
            10.0.1.102:ldaps {
                address 10.0.1.102
                priority-group 1
                session monitor-enabled
                state up
            }
        }
        min-active-members 1
        monitor tcp
    }

  • AAA authentication pool member selection prioritizes a different pool member than expected.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to correct the priority group association of the pool members. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To list the current pool configuration, use the following command syntax:

    list /ltm pool <affected pool name>

    For example:

    list /ltm pool AAA_Test_Pool
    ltm pool AAA_Test_Pool {
        members {
            10.0.1.101:ldaps {
                address 10.0.1.101
                priority-group 2
                session monitor-enabled
                state up
            }
            10.0.1.102:ldaps {
                address 10.0.1.102
                priority-group 1
                session monitor-enabled
                state up
            }
        }
        min-active-members 1
        monitor tcp
    }

  3. To modify the priority group of a pool member, use the following command syntax:

    modify /ltm  pool <affected pool name> members modify { <pool member:port> { priority-group <priority group number> } }

    For example: 

    modify /ltm  pool AAA_Test_Pool members modify { 10.0.1.101:ldaps { priority-group 1 } }

    modify /ltm  pool AAA_Test_Pool members modify { 10.0.1.102:ldaps { priority-group 2 } }

  4. Repeat step 3 for each pool member.
  5. To save the pool configuration changes, type the following command:

    save /sys config
