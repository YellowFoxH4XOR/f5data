Known Issue

This is the result of a known issue. The dynamic routing subsystem (tmrouted) does not correctly handle VLAN names longer than 15 characters. As a result, if tmrouted encounters a VLAN name longer than 15 characters, tmrouted will restart indefinitely.

The tmrouted subsystem is responsible for updating the TMM routing table based on the kernel routing table. This behavior also affects dynamic routing, making it unusable because tmrouted is responsible for updating the kernel with route updates from the advanced routing module.

Note: The Advanced Routing Module (ARM), is a licensed feature. For more information about available protocols and changes between versions, refer to K6654: The BIG-IP Advanced Routing Module includes only some ZebOS Modules.

F5 Product Development tracked this issue as CR92808 and it was fixed in BIG-IP version 9.4.6 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

If you are unable to upgrade, you can prevent the tmrouted subsystem from restarting by keeping VLAN names to 15 characters or less.
