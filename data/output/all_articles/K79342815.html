Topic

Beginning in BIG-IP 16.1.2.2 and 17.0.0, the BIG-IP system supports RFC7919 Negotiated Finite Field Diffie-Hellman Ephemeral (FFDHE) parameters. 

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Description

With the support for the FFDHE groups defined in RFC7919, the system now supports DHE2048, DHE3072, DHE4096 keys, with the default being 2048 bits. This affects cipher suites that use Diffie–Hellman Ephemeral key exchange in TLS versions 1.0, 1.1, 1.2. You should take the following into consideration when you use this feature after updating or upgrading your BIG-IP system to a version listed in the Topic section.
  • The default DHE key size is 2048 bits. In BIG-IP versions prior to this, the default is 1024 bits. 
  • Due to this increase in default key size, when you use this feature, resource consumption can increase and the system may experience an impact to performance if the use of DHE is common on the system.
  • You can configure this default value by enabling or disabling the DB variable tmm.ssl.dh1024. To do so, use the following TMSH command syntax:

    modify sys db tmm.ssl.dh1024 value enable/disable

  • To use FFDHE2048, FFDHE3072, FFDHE4096 keys, you define them in a cipher rule, and use this rule in a cipher group before associating it to an SSL profile. Refer to the Additional Information section for the procedure. 

    Note: The DEFAULT DH Group defines the following: P256, X25519, P384, FFDHE2048, FFDHE3072, FFDHE4096 

Additional Information

To use this new feature, you define the new FFDHE groups in a cipher rule and use this rule in a cipher group that is associated to an SSL profile. To do so, perform the following procedures:

Impact of procedure: Using a larger DHE key size increases resource consumption and the system may experience an impact to performance if the use of DHE is common on the system.

  • Create a cipher rule defining FFDHE groups
  • Create a cipher group to use the new cipher rule
  • Associate the new cipher group to a SSL profile

Create a cipher rule defining FFDHE groups

To create a new cipher rule defining FFDHE groups, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Rules.
  3. Select Create.
  4. Enter a Name.
  5. For Cipher Suites, enter a value that includes DHE cipher suites. For example, enter 

    DHE

  6. For DH Groups, enter the DH groups introduced in this article. For example, enter:

    FFDHE2048:FFDHE3072:FFDHE4096

    If you are running a system that does not support this feature, you observe an error in Cryptographic Parameters similar to the following:

    'FFDHE2048' is not a valid DH Groups.

  7. For Signature Algorithms, enter a valid value. For example, enter:

    DEFAULT

  8. Enter Finished.
Create a cipher group to use the new cipher rule
  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Ciphers > Groups.
  3. Select Create.
  4. Under Available Rules, select the new cipher rule you created in the previous procedure and move it to Allow the following.
  5. Select Finished.
Associate the new cipher group to a SSL profile
  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL
  3. Select the name of the SSL Profile you want to use the new Cipher group.
  4. Under Configuration, select Advanced.
  5. Select Cipher Group
  6. Select the new cipher group you created in the previous procedure.
  7. Select Update.
