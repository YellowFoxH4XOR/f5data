Topic

In some cases, when a BIG-IP device performs in an unexpected manner you may want to have F5 Network Support review for root cause analysis (RCA). To help F5 Support in providing RCA for an issue, this article covers typical issue-related scenarios and the data F5 requires to determine root cause. The requested data may differ based on the reproducibility the behavior.

Note : When conducting RCA on high-availability peer systems, F5 requires data from both devices.

Description

Logging

For RCA, you need to provide F5 with logging pertinent to the issue, as well as audit logging. When the deployment environment permits, F5 recommend increasing the logging level to debug for the related services. In environments where debug logging is not practical, you should set the logging verbosity to the highest level practical for your environment. For more information, refer to related articles in the Supplemental section of this article. Note that log file information for the qkview utility may become truncated, depending on the density of the logging. F5 recommends that you capture a full log set by running the qkview utility using the unrestricted-length flag.

Important: The BIG-IP system stores a maximum of eight days' worth of log files unless you configure a different value. You should increase audit logging when troubleshooting your issue and configure logging levels for all services that are directly related to the issue to increase verbosity. Note that increasing log verbosity can cause additional I/O strain on the device depending on the amount of traffic being processed. For more information, refer to: K5532: Configuring the level of information logged for Traffic Management-related events.

Important: Increasing log verbosity can cause additional I/O strain on the BIG-IP device, depending on the amount of traffic being processed. To avoid additional I/O strain you can configure external logging. For more information on external logging refer to: K13080: Configuring the BIG-IP system to log to a remote syslog server (10.x - 14.x).

Important : In cases in which an issue cannot be reliably reproduced, the ability to determine RCA is significantly restricted.

Core files

When an issue occurs, check the /shared/core directory for any core files with timestamps relating to the time frame of the event and supply these to F5 Support.

For more information regarding core-file handling, refer to the following:

  • K10062: Overview of managing BIG-IP core files
  • K13002225: Producing a diagnostic core file for F5 Technical Support (12.x and later)
  • K7602: Splitting a core file into smaller files for easy transfer

RCA troubleshooting and environment impact

In some cases, a restart of BIG-IP services or a failover between BIG-IP devices and a possible restart of the BIG-IP device may be required to obtain sufficient data to determine RCA. These action may temporarily impact traffic processing.

Data gathering for RCA:

You must obtain data in a timely manner when an issue is identified as this is the most effective method of ensuring an accurate RCA.

Collecting the log set for affected BIG-IP systems

  1. Log in to the command line of an affected BIG-IP system and type the following command:

    tar -cvzpf /var/tmp/logs-$HOSTNAME.tgz /var/log/*

  2. When an issue includes affected network behavior, in anticipation of the issue, attempt to capture this behavior by using the following command syntax:

    tcpdump -s0 -nni 0.0:nnn -w /var/tmp/<file name>.pcap host <source ip address> and host <destination ip address> -vvv

    Note: Replace <source ip address> and <destination ip address> with the IP addresses that are experiencing the issue.

    For example, the following command captures TCP traffic from the source address of 172.16.10.15 and the destination address of 192.168.0.100:

    tcpdump -s0 -nni 0.0:nnn -w /var/tmp/example.pcap host 172.16.10.15 and host 192.168.0.100 -vvv

  3. Additionally, capture the current BIG-IP address resolution protocol (ARP) and route table information by typing the following commands:

    tmsh show /net arp

    tmsh show /net route

  4. Include IP addresses information obtained through DNS resolution by using command line utilities dig or nslookup to obtain details of each of the DNS records.
  5. Gather a full, unrestricted-size QKView file by using the following command:

    qkview -s 0

    Note: This command include tmstat information, the BIG-IP device full configuration, and any heuristic triggers. For more information, refer to For more information refer to: K12878: Generating diagnostic data using the qkview utility.

    Note: For some BIG-IP releases, running the qkview utility with an unrestricted length can cause truncation of tmstat information. For more information, refer to: K35595105: The BIG-IP system truncates the QKView tmstat snapshot file data.
