K11287: BIG-IP WebAccelerator returns 500 Internal Server Error if OWS response contains a non-compliant HTTP status line

Issue

In BIG-IP WebAccelerator 9.4.0 through 9.4.7 and version 10.0.0, when BIG-IP WebAccelerator receives an OWS response whose response line does not include a valid HTTP status, the BIG-IP WebAccelerator may log the following error message in the /var/log/wa/pvac.log file:

WA ERROR: PvAsyncFetcherHttpData::taskDone(), sts != E_OK,Error: Server timed out.

When this message is logged, the BIG-IP WebAccelerator discards the OWS response and the client connection eventually times out. In other cases, the BIG-IP WebAccelerator may instead process the response and send the requested object to the client without logging an error message.

Beginning in BIG-IP 9.4.8 and 10.0.1, when the BIG-IP WebAccelerator receives an OWS response with a non-RFC compliant HTTP response status, the BIG-IP WebAccelerator will replace the response with an HTTP "500 Internal Server Error" response that includes the following message body:

<html><body>The response does not have a valid protocol.</body></html>

This change in behavior is a result of CR119969 for the version 9.x branch and CR118238 for the 10.x branch.

If you are experiencing this issue as a result of malformed HTTP response lines, you can work around this issue by configuring the OWS to include only valid HTTP response status lines that comply with RFC2616.

If you are experiencing this issue as a result of accelerating HTTP requests for non-HTTP media streams, you should exclude those requests from BIG-IP WebAccelerator processing. For more information, refer to K11138: A non-HTTP response may cause BIG-IP WebAccelerator to exhaust memory resources and dump core.
