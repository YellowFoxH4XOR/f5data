Description

You may find the following message in /var/log/apm file:
0149030f:5:<Access Profile name>:<Partition>:<apm sessionID>: Client is not connected: executeOneAgent: Request dropped.

In this error message, note the following:

  • <Access Profile name> is the name of the access profile for which the BIG-IP APM session is experiencing the request drop.
  • <Partition> is the name of the partition for the access profiled configured. Default is Common.
  • <apm sessionID> is the BIG-IP APM session ID at which the request drop occurred.

For example:

  • Feb 7 06:32:26 APM1.localhost notice apmd[17136]: 0149030f:5: /Common/example-ap:Common:0a8c1406: Client is not connected: executeOneAgent: Request dropped.
  • Feb 7 06:32:26 APM1.localhost notice apmd[17136]: 0149030f:5: /Common/example-ap:Common:0a8c1406: Client is not connected: Response dropped.
  • Feb 7 06:35:30 APM1.localhost err apmd[17136]: 01490000:3: ApmD.cpp func: "sendAccessPolicyResponse()" line: 2726 Msg: 0a8c1406: duplicated request dropped

Environment

  • BIG-IP APM
  • Client access to a Virtual Server with Access Profile configured

Cause

The general cause is:
A client connected to the APM virtual server, and internal processing and communication occurred. When the internal response came back, it found no client-side connection.

Recommended Actions

  • Confirm if the client had already closed the connection.
  • Review if the certain policy item is taking too long to finish, which can result in the policy being timeout. If that is the case, adjust the policy or timeout value.
