Topic

When viewing the BIG-IP connection table by using the Traffic Management Shell (tmsh), the output may contain any6 entries in the server or client sections of the connection table. Because the BIG-IP system uses IPv6 internally, the connection table may display these any6 entries regardless of whether IPv4 or IPv6 addressing is configured for use on self IPs and virtual servers. The command output may display the connection table similar to the following example:

tmsh show sys conn command

Note: The tmsh command output may incorrectly display any6.0 instead of any6:any. For more information about this issue, refer to K13390: The tmsh connection table command output may display entries as 'any6.0'.

172.17.162.251:54941 172.29.24.156:80 any6.0 tcp 24 (tmm: 0)
172.17.162.251:54940 172.29.24.156:80 any6.0 tcp 25 (tmm: 0)
any6.0 172.29.24.156:80 10.0.0.66:80 tcp 1 (tmm: 2)
any6.0 172.29.24.156:80 10.0.0.66:80 tcp 0 (tmm: 3)

The any6 entry in the server section of the table occurs when a client connects to a virtual server, but a load balancing decision has not yet been made. The any6 entry refers to an undetermined IPv6 address. The :any or .0 entries refer to any port, even if the protocol being used does not use ports, such as ICMP.

An any6 entry referenced in the client section of the table occurs when a connection between the BIG-IP LTM system and a node is eligible for reuse using OneConnect. If you do not see any reference in the client section of the output table, no idle connections are available for reuse.
