Issue

Error Message

Error message: 01490576:5: <Access Profile name><apm sessionID>Session invalidated due to <scope type> mismatch (expected '<requested resource>', got '<resource granted>')

In this error message, note the following:

  • <Access Profile name in violation> is the name of the access profile for which the BIG-IP APM session is experiencing the violation.
  • <scope type> is the type of scope violation and can have the following values:
    • virtual-server scope
    • profile scope
    • scope type
  • <apm sessionID> is the BIG-IP APM session ID at which the scope violation occurred.
  • <requested resource> is the name of the resource that is being requested leading to the violation.
  • <resource granted> is the name of the resource for which permission is granted to access from another BIG-IP APM session ID before the violation.

The following examples list the error messages for each scope type:

  • 01490576:5: /Common/example-ap:Common:a946052b Session invalidated due to virtual-server scope mismatch (expected '/Common/vs-violation', got '/Common/vs-granted').
  • 01490576:5: /Common/example-ap:Common:dfac3408 Session invalidated due to profile scope mismatch (expected '/Common/example-ap', got '/Common/ap-granted').
  • 01490576:5: /Common/example-ap:Common:c51cd822 Session invalidated due to scope type mismatch (expected 'profile', got 'global').

Message Location

You may encounter this message in the following locations:

  • The /var/log/apm file
Description

This message may occur when the following conditions are met:

  • A BIG-IP session ID granted for one virtual server and access profile is presented to another virtual server or access profile violating access scope.

In BIG-IP APM 11.x, APM session IDs are global to the BIG-IP system and the system can present them to any BIG-IP APM virtual server with an attached access profile.

In BIG-IP APM 12.0 and later, the configurable Profile Scope settings establishe additional criteria to ensure that a user who has established a session on one virtual server or access profile cannot use that same session ID to access other virtual servers and the resources behind them. The following lists the three Profile Scope settings:

  • Virtual Server grants access only the resources behind the virtual server on which the session was established.
  • Profile grants access only to resources that are behind the same access profile on any virtual server. (Default.)
  • Global is equivalent to BIG-IP 11.x behavior. It grants access to resources behind any virtual server with an access profile for which scope is set to Global.

Impact

Users are unable to get access to the requested resource and the BIG-IP APM session is invalidated.

Recommended Actions

When you observe the error message, you can provide access by setting the Profile Scope to either Profile or Global. For security, you should set the minimum level of Profile Scope required for your applications to work. To set the Profile Scope, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Access > Profiles / Policies > Access Profiles (Per-Session Policies).

    Note: For BIG-IP 12.x and earlier, navigate to Access Policy > Access Profiles > Access Profiles List.

  3. Click the appropriate access profile.
  4. For Profile Scope, click the appropriate scope.
  5. Click Update.
