K000133780: tcpdump can capture extra unrelated traffic when using the 'p' flag

Type
Support Solution
Published
2023-05-03
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000133780

Description

Running tcpdump with the 'p' flag (to capture peer traffic, eg. "tcpdump -i 0.0:nnnp") on BIG-IP may occasionally capture unrelated peer flows on top of the related traffic.

 

Environment

BIG-IP, tcpdump with the 'p' flag specified on the interface to capture peer traffic flows.

 

Cause

This sometimes occurs when an IP being filtered for still has a peerid of 0 (eg. when serverside connection is not assigned yet), and thus since the tcpdump is configured to capture peer traffic with the 'p' flag, it begins to temporarily capture other traffic whose flowid is still 0 (eg. when the traffic is ARP or ICMP and stays with both peerid 0 and flowid 0).

 

Recommended Actions

This is generally not a cause for concern since the 'p' flag was built primary to try and include the peer traffic, rather than specifically exclude all other traffic.

If the admin wishes, after the pcap is saved they can remove the unwanted traffic with a display filter, and then export displayed packets in wireshark to only save the required traffic in a separate pcap.

 

Additional Information

https://my.f5.com/manage/s/article/K13637 contains some additional info about tcpdump parameters on BIG-IP.
