K000161408: How to Configure a BIG-IP Virtual Server for PQC

Type
Support Solution
Published
2026-05-25
Updated
2026-09-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161408

Description

Post-Quantum Cryptography (PQC) on BIG-IP uses hybrid key exchange mechanisms (e.g., X25519MLKEM768) that combine classical and quantum-resistant algorithms.

Important: Do NOT use traditional cipher strings (e.g., DEFAULT:!DHE:!TLSv1:!TLSv1_1) to configure PQC. TLS protocol exclusions (disabling TLS 1.0/1.1) must be handled via the Client-SSL profile Options, not the cipher string.

Environment

  • BIG-IP TMOS 17.5.1 or later (X25519MLKEM768 support requires 17.5.1+)
  • TLS 1.3 must be enabled on the Client-SSL profile
  • Virtual Server

Cause

PQC is only compatible with TLS 1.3 and requires the Cipher Rule + Cipher Group framework — it cannot be configured via traditional OpenSSL-style cipher strings.

Answer/Recommended Actions

Step 1: Create a Cipher Rule

GUI:

  1. Navigate to Local Traffic > Ciphers > Rules
  2. Click Create
  3. Set Name (e.g., PQC_CipherRule)
  4. Set Cipher Suites to DEFAULT
  5. Set DH Groups to: X25519:X25519MLKEM768
  6. Set Signature Algorithms to DEFAULT
  7. Click Finished

TMSH:

tmsh create ltm cipher rule PQC_CipherRule cipher DEFAULT dh-groups X25519:X25519MLKEM768 signature-algorithms DEFAULT

Step 2: Create a Cipher Group

GUI:

  1. Navigate to Local Traffic > Ciphers > Groups
  2. Click Create
  3. Set Name (e.g., PQC_CipherGroup)
  4. Under Group Creation > Available Rules, select PQC_CipherRule and move it to the Allow list
  5. Click Finished

TMSH:

tmsh create ltm cipher group PQC_CipherGroup allow add { PQC_CipherRule }

Step 3: Create a Client-SSL Profile

GUI:

  1. Navigate to Local Traffic > Profiles > SSL > Client
  2. Click Create (e.g., PQC_ClientSSL)
  3. Set Configuration to Set Configuration to Advanced
  4. Under Ciphers, select the Cipher Group radio button and choose PQC_CipherGroup
  5. Set Ciphers field to none (when using Cipher Group)
  6. Under Options, disable TLSv1,TLSv1.1 and TLSv1.2, and ensure TLSv1.3 is enabled
  7. Click Finished

TMSH:

tmsh create ltm profile client-ssl PQC_ClientSSL cipher-group PQC_CipherGroup ciphers none options { dont-insert-empty-fragments no-tlsv1.2 no-tlsv1 no-tlsv1.1 }

Note: Disabling TLS 1.2 (as shown above) is required to enforce TLS 1.3-only negotiation for this PQC-enabled virtual server, since TLS 1.2 has no mechanism to support hybrid PQC key exchange (see F5 Labs: The State of PQC on the Web) . However, disabling TLS 1.2 may cause compatibility issues for clients that do not yet support TLS 1.3, resulting in service disruption for those clients. Leaving TLS 1.2 enabled permits fallback for such clients, but any connection that falls back to TLS 1.2 will not use PQC. Evaluate your client base's TLS 1.3 support before disabling TLS 1.2 on this profile.

Step 4: Assign the Client-SSL Profile to a Virtual Server

GUI:

  1. Navigate to Local Traffic > Virtual Servers
  2. Select or create your HTTPS virtual server
  3. Under SSL Profile (Client), move PQC_ClientSSL to the Selected list
  4. Click Update

TMSH:

tmsh modify ltm virtual <VS_NAME> profiles add { PQC_ClientSSL { context clientside } }

Note: Disabling TLS 1.2 (as shown above) is required to enforce TLS 1.3-only negotiation for this PQC-enabled virtual server, since TLS 1.2 has no mechanism to support hybrid PQC key exchange (see F5 Labs: The State of PQC on the Web) . However, disabling TLS 1.2 may cause compatibility issues for clients that do not yet support TLS 1.3, resulting in service disruption for those clients. Leaving TLS 1.2 enabled permits fallback for such clients, but any connection that falls back to TLS 1.2 will not use PQC. Evaluate your client base's TLS 1.3 support before disabling TLS 1.2 on this profile.

Additional Information

Testing with Google Chrome

Note (Chrome 138+): As of Chrome 138.7204.49 (June 24, 2025), Kyber support was removed and X25519MLKEM768 (MLKEM) is enabled by default. The chrome://flags PQC options no longer exist. Simply browse to your virtual server with Chrome 138+ and MLKEM will be negotiated automatically if configured correctly.

Verification (updated Chrome versions):

  1. Browse to your virtual server (HTTPS)
  2. Go to More Tools > Developer Tools > Security
  3. Under Connection, you should see:
    • The connection to this site is encrypted and authenticated using TLS 1.3 X25519MLKEM768, and AES_128_GCM
