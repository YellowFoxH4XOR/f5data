Known Issue

This is the result of a known issue. If an iRule uses a command that temporarily suspends iRule processing within a CLIENTSSL_ DATA or SERVERSSL_DATA event, and the iRule is applied to a CMP-enabled virtual server, TMM may core when iRule processing resumes on the connection.

Note: For information about iRules commands that temporarily suspend iRule execution, refer to K12962: Some iRules commands may temporarily suspend iRule processing.

F5 Product Development tracked this issue as ID 204163 (formerly CR101506) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, or WebAccelerator release notes.

Workaround

If you need to use a suspending command within a CLIENTSSL_ DATA or SERVERSSL_DATA event, you can disable CMP for the virtual server that uses the iRule. To do so, type the following command, replacing <virtual_server_name> with the name of the virtual server:

bigpipe virtual <virtual_server_name> cmp disable
