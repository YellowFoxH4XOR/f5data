Description

When creating a new instance or updating the signature database that uses F5 WAF for NGINX (formerly called App Protect) version 5.10 or older it fails to load. An error message similar to the following can be found...root@f5_waf_for_nginx# cat /var/log/app_protect/compile_error_msg.json  | jq
{
  "completed_successfully": false,
  "event": "configuration_load_failure",
  "error_message": "Error calling /opt/app_protect/bin/config_set_compiler: signal: killed",
  "softwareVersion": "4.14.0",
  "componentVersions": {
    "wafEngineVersion": "11.336.0",
    "wafNginxVersion": "5.342.0"
  }
}

Environment

Update and/or create a new image using version 5.10 or older, and then update the older version with a 2026 attack signature package.

Cause

The error "Error calling /opt/app_protect/bin/config_set_compiler: signal: killed" means the config_set_compiler Perl script was forcibly terminated by the OS (via a SIGKILL signal) before it could complete. This is distinct from a permission error (exit status 13) or a missing binary — the process started but was killed externally.

This is likely WAFMC-13592: Increased signature compiler capacity to support larger signature sets

Answer/Recommended Actions

  1.  To fix this, an upgrade to WAF version 5.11 or higher is needed. Refer to F5 WAF for NGINX 5.11 for release details.
  2. There is a workaround...
    1. Using the editor of your choice Edit: /opt/app_protect/lib/perl/F5/NegativeSignatures/Collection/Compiler.pm
    2. Change LARGE_NUM_STATES to 150000
    3. Restart nginx

Additional Information

In some instances you may run into an issue after restarting nginx several times while troubleshooting this. The repeated failed restarts prior to applying the workaround may have left corrupted protobuf data files in /opt/app_protect/bd_config/tables/.
