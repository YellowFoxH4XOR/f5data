K000150436: Backend servers resets the connection after receiving a Client Hello packet from the BIG-IP

Applies to

Description

Backend servers resets the connection after receiving a Client Hello packet from the BIG-IP

 

Environment

  • BIG-IP LTM
  • Virtual server configured with Server SSL profile
  • HTTPS monitor with or without Server SSL profile
  • Backend server requires SNI header to establish secure session

Cause

Of course the are several reasons the backend server can reset the connection after Client Hello packet. One of them which is often omitted is that the backend server requires an SNI (Server Name Indication) header in the Client Hello packet to establish a secure session. By default the Server SSL profile does not use an SNI header.

 

Recommended Actions

To resolve this issue, configure the server-name field in the Server SSL profile with an appropriate value matching what is expected by the backend server:

 

Using the Configuration utility to configure an SNI header in Server SSL profile

 

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > SSL > Server.
  3. Edit or create a Server SSL profile 
  4. Set the server-name field to match the hostname or domain name expected by your backend servers
  5. Save and apply changes.

 

Note: The monitoring traffic is being processed by bigd and by default it does not send an SNI header even when configured in the Server SSL profile. Use of SNI in HTTPS health monitors is officially supported through the use of in-TMM monitoring only. More information can be found in the following article: SNI not sent by HTTPS monitoring
