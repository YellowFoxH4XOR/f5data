K10541: The ARX system may detect a NetApp NTFS qtree share as 'Asymmetric read-only' and drop ACL information

Known Issue

This is the result of a known issue. When importing a NetApp NTFS qtree share on an OnTap version 7.2.4 or later system to a multi-protocol namespace, if the filer is configured with the cifs.ntfs_ignore_unix_security_ops on option, the ARX system will incorrectly detect the share as a SAMBA share, drop the CIFS ACL information, and configure the share as Asymmetric read-only. As a result, migrations to the share will not contain the proper ACL information. 

The show namespace command will display the Asymmetric read-only share similar to the following example:

    Share share1
      Filer                       filer1 [10.10.11.101]
      NFS Export                  /share1
      CIFS Share                  share1$
      Features                    cifs-acls unix-perm shared-attr asymmetric-ro cifs-case-blind
      CIFS Maximum Request Size   33028
      SID Translation             No

Note: The cifs.ntfs_ignore_unix_security_ops on setting is a common best practice recommendation by NetApp to support Linux/Unix based clients accessing CIFS shares on the NetApp filer.

F5 Product Development tracked this issue as ID 36110 and it was fixed in ARX version 5.1.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in hotfix release 5.0.1 HF5 (build 11710) and 5.0.5 HF2 (build 11740). Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 36110.
