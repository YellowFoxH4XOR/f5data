Topic:
This article contains an overview for how the Return to DNS feature behaves in BIG-IP DNS.

Description:
Return to DNS effectively means "Go to the next DNS method in the answering order"; K14510 describes the order of precedence like this:

If the Recursion Desired (RD) flag is set in the request header and the Process Recursion Desired setting is enabled in the DNS profile, the system processes the packet as follows:
  • DNS iRules
  • DNSSEC key processing
  • Wide IPs
  • DNS Express
  • DNS profiles
  • The DNS cache feature

The Return to DNS order, flows like this:
  •  Big-IP DNS Listener (IP:port virtual server)
    • iRules
    • DNS Profile
      • DNSSEC
      • GSLB
      • DNS Express
      • DNS Cache
      • BIND
  • LTM Pool (if assigned to the listener, used to screen non WideIP requests to internal nameservers)
  • System/Linux listener (IP:port) - if all the above is not configured or fails
    • BIND (again, because at the system level, if the listener shares an IP (and port) with a Self IP, BIND automatically answers port 53). This is an outside case, but I think this helps to further understand the DNS answering order in Big-IP.

If we review only the portion related only to a WideIP/Pool configuration's flow, it looks like this:
  • GSLB WideIP
    • Return to DNS (effectively, lies here when a GTM pool uses it; this is the default Fallback Load Balancing method for a new pool)
      • DNS Express                        (if enabled in the GTM listener's DNS profile)
      • DNS Cache                           (if enabled in the GTM listener's DNS profile)
      • Use BIND Server on BIG-IP  (if enabled in the GTM listener's DNS profile)
