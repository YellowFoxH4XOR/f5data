Known Issue

This is the result of a known issue. Occasionally, the Cavium Nitrox SSL card driver fails to initialize within the Traffic Management Microkernel (TMM), causing Secure Sockets Layer (SSL) accelerated traffic to fail. Although this issue appears to be a hardware failure, it is actually a software-related issue, and can be addressed by upgrading the BIG-IP system or installing a hotfix.

Note: To obtain this hotfix, contact F5 Technical Support and reference the CR listed below.

The following symptoms indicate that the Nitrox card driver has not successfully initialized within TMM:

  • The TMM and bcm56xxd processes restart.
  • The End-User Diagnostics (EUD) report indicates that the SSL test has passed.
  • Error similar to the following example appear in the /var/log/ltm log file:

    tmm tmm[1513]: 01010025:2: Device failure: cn0: core data parity
    tmm tmm[1513]: 01010025:2: Device failure: cn1: core instruction parity

F5 Product Development tracked this issue as CR72837 and it was fixed in BIG-IP LTM 9.1.3, 9.2.5, 9.3.1, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue still exists in the BIG-IP 9.6 software branch.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.0-HF3 issued for BIG-IP 9.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
