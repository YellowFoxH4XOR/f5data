Known Issue

This is the result of a known issue. The snmpd process produces the following debug level log messages at regular intervals when attempting to bind the same IPv6 address to BIG-IP host subsystem interfaces eth0 and eth0.1. This behavior is intentional; it does not affect the operational status of the BIG-IP system, and the following log message is benign:

debug snmpd[PID]: error on subcontainer 'ia_addr' insert (-1)

Note: This syslog message is only observed on AOM-based platforms. For more information about the AOM, refer to K9403: Overview of the AOM subsystem.

Note: Debug level messages from snmpd are disabled by default. However, when a remote syslog server is configured on the BIG-IP system, the remote syslog server will receive all levels of snmpd logs. For more information, refer to K11723 : Configured log levels only apply to local logs. You can enable the snmpd debug level messages locally by modifying the daemon log level to debug using the bigpipe syslog command daemon from debug.

F5 Product Development is tracking this issue as ID 224317 (formerly CR135440) and it was fixed in BIG-IP 11.0.0.

Workaround

You can filter this log message from the configured remote syslog server by following the steps in K11723: Configured log levels only apply to local logs using the following remote syslog configuration.

Replace <remote syslog server IP> with the IP address of your remote syslog server:

syslog include "
filter f_remote_loghost {
level(notice..emerg);
};
destination d_loghost {
udp(\"<remote syslog server IP>\" port(514));
};
log {
source(s_syslog_pipe);
filter(f_remote_loghost);
destination(d_loghost);
};
"

For example, you would use the following remote syslog configuration to configure 172.28.31.40 as the remote syslog server:

syslog include "
filter f_remote_loghost {
level(notice..emerg);
};
destination d_loghost {
udp(\"172.28.31.40\" port(514));
};
log {
source(s_syslog_pipe);
filter(f_remote_loghost);
destination(d_loghost);
};
"
