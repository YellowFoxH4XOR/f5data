Description

When creating DNSSEC keys, only the object is created in the configuration but not the actual keys. Lack of generation data means that the key has not been successfully generated. No "generation" data exists in the following example:

ltm dns dnssec key /Common/example.com_zsk {
    algorithm rsasha256
    bit-width 2048
    expiration-period 30:0:0:0
    rollover-period 20:0:0:0
    use-fips external
}

Environment

  • BIGIP DNS
  • DNSSEC
  • Lack of generations data

Cause

  • A member with the gtm.peerinfolocalid database key variable designation of 0 is responsible for creating new generations of each DNSSEC key and distributing the keys to each sync group member.
  • DNS device certificates should have unique and meaningful subject data

Recommended Actions

  1. Ensure that you are trying to create DNSESEC keys from the correct device (with database key variable designation of 0) 
    #list sys db gtm.peerinfolocalid
  2. Ensure that device certificates have unique names. If they are using the same common name (localhost.localdomain) you will need to renew device certs with unique names and re-exchange them via "gtm_add <IP>" script. Refer to K16951115: Changing the BIG-IP system device certificate using the Configuration utility.
