Description
When you attempt to deploy an AFM Protocol Inspection update, Deployment Status shows the following error message:

Error: TMCTL IM doesn't match the active IM, falling back to FactoryDefaults

Environment

  • BIG-IP Virtual Edition (VE)
  • Deploy AFM Protocol Inspection update
  • The error is visible in the following places:
    • GUI: Security  ››  Protocol Security : Inspection Updates
    • CLI: tmsh show security protocol-inspection updates
  • /var/log/tmm logs following error:

    notice IPS: Starting hitless upgrade to '/shared/.pi_installed_updates/15.1.0-20220228.0818/libips.so.15.1.0-20220228.0715'.
    notice IPS: shared memory compilation failed: 'Signature compilation failed.'
    notice IPS: upgrade to library '/shared/.pi_installed_updates/15.1.0-20220228.0818/libips.so.15.1.0-20220228.0715' failed (ERR_INIT), falling back default.
     
  • Typically, it's known to occur in the following environments:
    • VMware vSphere cluster with an older EVC mode
    • BIG-IP VE is running on KVM hypervisor with the default CPU mode
    • Nested virtualization environment

Cause
SSSE3 is not available or not passed to the guest OS from the hypervisor, and BIG-IP VE does not see the CPU feature. The SSSE3 instruction sets are very critical to compile IPS compliance, and BIG-IP gives the error because it fails to compile it.

Some possible causes include:

  • When VMware vSphere ESXi cluster uses one of the older EVC modes, some CPU features are not available to a guest OS running in the cluster. For example, SSSE3 is only available starting from AMD Opteron Generation 4 mode in AMD EVC modes.
  • When BIG-IP VE is deployed on KVM with the default CPU mode, CPU features passed to the VM are limited and may not have the SSSE3 capability.
  • When a BIG-IP VE is deployed on a nested virtualization environment, the required instruction sets may not be passed to the BIG-IP VE.

Recommended Actions
Check if SSSE3 instruction sets are available in BIG-IP VE.

# grep 'ssse3' /proc/cpuinfo

If SSSE3 is available, you will see output similar to below. Otherwise, there will be no output, and it means SSSE3 capability is missing on the BIG-IP VE. Seek advice from your hypervisor vendor to pass SSSE3 capability to BIG-IP VE.
