Description

In your apm log you see "SAML assertion is invalid, error: Id of InResponseTo should match id of authentication request

 

Environment

You are using a SAML authenticated APM policy.

 

Cause

The Incoming Assertion is being assigned to the wrong session. The InResponseTo field will match an earlier session.

 

The APM  Session is not part of the SAML AUTHN or the Assertion. It is cookie that the user's browser sends with the SAML messages.

 

If the user starts a policy session, APM will send a AUTHN  for session "A". If the user then starts another session ("B") on another browser or tab, then completes the IDP for session "A", then the Assertion with be returned for session B, but it will have the SAML ID from session A.

 

Session A, meanwhile, will timeout.

 

Recommended Actions

This is not a BIG-IP issue. SAML cannot process this correctly.

 

Additional Information.

To clear the condition, the user should log out of APM and close the browser to delete all session cookies.
