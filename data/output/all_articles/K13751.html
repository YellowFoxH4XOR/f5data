Topic

Beginning in BIG-IP APM 11.0.0, you can use session variables to dynamically pass values to single sign-on (SSO) objects.

Description

BIG-IP APM supports the use of session variables to provide dynamic data to SSO objects based on the contents of the session variable. You can use an access policy to access external information, such as Active Directory group information or client data, such as the client platform. You can assign these session variables directly to a SSO object or you can manipulate and combine session variables into a custom session variable that can be assigned to a SSO object.

The following SSO object fields can use session variables to dynamically set properties of the object:

All SSO objects

  • Header insertion Name
  • Header insertion Value

Form-based SSO objects

  • Start URI
  • Form Action
  • Form Parameter for User Name
  • Form Parameter for Password
  • Hidden Form Parameters/Values
  • Successful Logon Detection Match Value

Certain fields use session variables the are not enclosed in %{}. The following fields do use %{} and are pre-populated with default SSO session variables:

  • Username Source
  • Password Source
  • Domain Source for NTLMV1, NTLMV2 SSO objects
  • User Realm Source for Kerberos SSO objects

When changing these fields do not enclose them in %{}.

For example:

session.sso.token.last.username

Header insertion

You can dynamically assign header insertion name-value pairs using session variables. You can use a session variable in both fields, or either individual field. The following example assigns a header, example-header, the value in the %{session.example.sso.header.value} session variable.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Single Sign-On.

    Note: For BIG-IP 12.x and earlier, navigate to: Access Policy > SSO Configurations.

  3. Click the name of the SSO configuration to which you are assigning a session variable.
  4. For General Properties, click Advanced.
  5. For Headers Name, type the following:

    example-header

  6. For Headers Value, type the following:

    %{session.example.sso.header.value}

  7. Click Add.
  8. Click Update.

Start URI

You can dynamically assign Start URI of a form-based SSO object using a session variable. The following example assigns the value of the %{session.example.sso.uri} session variable to Start URI.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Single Sign-On.

    Note: For BIG-IP 12.x and earlier, navigate to: Access Policy > SSO Configurations.

  3. Click the name of the form-based SSO configuration to which you are assigning a session variable.
  4. For Start URI, type the following:

    %{session.example.sso.uri}

  5. Click Update.

Hidden Form Parameters/Values

You can dynamically assign Hidden Form Parameters/Values of a form-based SSO object using a session variable. You can use a session variable in both the parameter, the value, or either of the parameter/value pair. The following example assigns a Hidden Form parameter, form-parameter, the value of the %{session.example.sso.form.hidden.value} session variable to Hidden Form Parameters/Value.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Single Sign-On.

    Note: For BIG-IP 12.x and earlier, navigate to: Access Policy > SSO Configurations.

  3. Click the name of the form-based SSO configuration to which you are assigning a session variable.
  4. For Hidden Form Parameters/Values, use the following syntax:

    <variable name> <variable value>

    For example,

    form-parameter %{session.example.sso.form.hidden.value}

  5. Click Update.

Successful Logon Detection Match Value

You can dynamically assign Successful Logon Detection Match Value of a form-based SSO object using a session variable. The following example assigns the value of the %{session.example.sso.form.success} session variable to Successful Logon Detection Match Value.

  1. Log in to the Configuration utility.
  2. Navigate to Access > Single Sign-On.

    Note: For BIG-IP 12.x and earlier, navigate to: Access Policy > SSO Configurations.

  3. Click the name of the form-based SSO configuration to which you are assigning a session variable.
  4. For Successful Logon Detection Match Type, click the appropriate logon detection type.
  5. For Successful Logon Detection Match Value, type the following:

    %{session.example.sso.form.success}

  6. Click Update.

Recommendations

The BIG-IP APM system must be configured with an SSO object of the type you want to assign a session variable.

The following example shows how to assign the value of the session variable to each SSO value. You must format the session variable in order for it to be properly evaluated by the resource object. When assigning a session variable to a resource object, use the following syntax:

%{<session-variable>}

In this example, note the following:

<session-variable> is the session variable you are assigning to the SSO object.

For example:

%{session.example.sso.uri}
