Topic

The multi-threaded architecture allows BIG-IP performance to scale over time, as hardware and network performance continues to increase.

Description

Beginning in BIG-IP 11.3.0, TMM uses a multi-threaded architecture. Under the threaded model, the basic context of execution becomes a thread. The CMP feature allows platforms that contain multiple CPUs to run a single TMM process for every CPU, and multiple TMM threads per processing core.

For example, starting in BIG-IP 11.3.0, the BIG-IP 8950 platform runs two TMM processes, one for each CPU. Each process creates four separate TMM threads.

The below ps output shows two separate TMM instances running on the BIG-IP 8950 system; each TMM is executing four thread contexts (-T 4):

ps T | grep tmm | grep T
11815 ? SLl 0:51 tmm.0 -T 4 --tmid 0 --npus 8 --platform Gemini -m -s 7050
11816 ? SLl 0:40 tmm.4 -T 4 --tmid 4 --npus 8 --platform Gemini -m -s 7050

The following tmsh output shows eight separate TMM instances (threads) running on the 8950 platform:

tmsh show sys tmm-info | grep Sys::TMM
Sys::TMM: 0.0
Sys::TMM: 0.1
Sys::TMM: 0.2
Sys::TMM: 0.3
Sys::TMM: 0.4
Sys::TMM: 0.5
Sys::TMM: 0.6
Sys::TMM: 0.7

In versions prior to BIG-IP 11.3.0, the Traffic Management Microkernel (TMM) is a single-threaded process. Under the single-threaded model, the basic context of execution is the process, and traffic management performance is enhanced by the Clustered Multiprocessing (CMP) feature. CMP allows platforms that contain multiple CPUs to run multiple TMM processes; one TMM instance per processing core.

For example, the BIG-IP 8950 platform contains dual quad-core CPUs, and can run eight separate TMM instances.

The following ps output shows eight separate (non-threaded) TMM instances running on the BIG-IP 8950 platform:

ps T | grep tmm
6899 ? SL 101:23 tmm.0 --tmid 0 --npus 8 --platform Gemini -m -s 1871
6900 ? RL 97:38 tmm.1 --tmid 1 --npus 8 --platform Gemini -m -s 1871
6901 ? SL 99:16 tmm.2 --tmid 2 --npus 8 --platform Gemini -m -s 1871
6903 ? SL 101:14 tmm.3 --tmid 3 --npus 8 --platform Gemini -m -s 1871
6904 ? SL 80:13 tmm.4 --tmid 4 --npus 8 --platform Gemini -m -s 1871
6905 ? SL 79:38 tmm.5 --tmid 5 --npus 8 --platform Gemini -m -s 1871
6907 ? SL 79:03 tmm.6 --tmid 6 --npus 8 --platform Gemini -m -s 1871
6908 ? SL 79:00 tmm.7 --tmid 7 --npus 8 --platform Gemini -m -s 1871

The following Traffic Management Shell (tmsh) output shows eight separate TMM instances (processes) running on the 8950 platform:

tmsh show sys tmm-info | grep Sys::TMM

Sys::TMM: 0.2
Sys::TMM: 0.3
Sys::TMM: 0.4

The single-threaded architecture does not scale well, as hardware and network performance continues to increase.
