Issue

Error Message

Access Policy Evaluation is already in progress for your current session

Message Location

You may encounter this message in the following location:

  • In the client browser when accessing the Microsoft Exchange Server 2013 or Microsoft Exchange Server 2016 Outlook Web App (OWA) application using a BIG-IP APM virtual server.

Description

This message occurs when all of the following condition are met:

  • A client accesses the Microsoft Exchange Server 2013 or Microsoft Exchange Server 2016 Outlook Web App (OWA) application using a BIG-IP APM virtual server.
  • After logging out from an initial connection to the OWA application, the client attempts a subsequent login during the same web browser session.

The OWA application caches information from the initial session and attempts to use this information when reconnecting and establishing subsequent OWA sessions. As a result, when reconnecting the browser attempts to create multiple BIG-IP APM sessions.

Note: This article outlines a single common condition. The system triggers this error message when the BIG-IP APM's user-facing URL /my.policy web rendering system receives an HTTP GET request from a browser using an existing session ID in the in-progress state, which is the state in which a login initiates but is not complete.

After the initial access request and session ID assignment, the BIG-IP APM expects the following browser behaviors:

  • The client browser sends a GET and receives a session ID and BIG-IP APM redirect.
  • The client browser sends a GET to the BIG-IP APM URL /my.policy to initiate authentication.
  • The client browser sends POST(s) to the BIG-IP APM virtual server to complete the authentication process.

The client browser can trigger this error when an out-of-order or repeat request is sent to the BIG-IP APM virtual server.
In most cases, the client browser triggers the error by sending a GET to the BIG-IP APM URL /my.policy to initiate authentication, as noted in the previous list.

Impact

Subsequent client login attempts to the OWA application fail.

Recommended Actions

To prevent the OWA application from caching information and to allow the subsequent OWA logins, you can use an iRule to set the OWA IsClientAppCacheEnabled cookie False. To do so, use the following procedure:

Impact of procedure: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the BIG-IP Configuration utility.
  2. Go to Local Traffic > iRules > iRule List.
  3. Enter a name for the iRule.
  4. In the Definition box, enter the following iRules syntax:
    when HTTP_REQUEST {
          if { [HTTP::cookie exists "IsClientAppCacheEnabled"] } {
          HTTP::cookie "IsClientAppCacheEnabled" False
          }
    }
  5. Select Finished.
  6. Go to Local Traffic > Virtual Servers > Virtual Server List.
  7. Select the Name link of the affected virtual server.
  8. Select the virtual server's Resources tab.
  9. Under iRules, select Manage.
  10. Select your newly created iRule and move it to the Enabled list.
  11. Select Finished.

Note: If you still receive the error after you apply the iRule, delete your browser cache and temporary files.

Important: To remove the workaround for this OWA login difficulty, remove the iRule you added to the virtual server during this procedure.
