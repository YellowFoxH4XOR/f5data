K000130551: Password expiration affecting login process when AD Query is used

Type
Support Solution
Published
2023-01-25
Updated
2023-01-25
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.3
Source
https://my.f5.com/manage/s/article/K000130551

Description

  • You have configured Access Policy with AD Query but there is no Logon Agent
  • When using NTLM front end auth and AD query the query returns all values from AD and is successful but the session variable "session.ad.last.queryresult" is 0 which is failed
  • You see error messages: AD module: Logon agent instance is not available to be scheduled
  • You see log:  
    Session variable 'session.logon.page.pwdDaysLeft' set to '6'
    which confirms that user has entered the last 7 days before expiration of password.

Environment

  • APM
  • Access Policy
  • AD Query

Cause

  • Due to design limitation lack of Logon Page agent in Access Policy while using Password Expiry Warning for AD agent results with AD Query agent failing when trying to schedule a Logon Page agent to display the Password Expiry Warning page.
  • Example:
apm policy agent aaa-active-directory /Common/AD_Server_act_active_directory_query_ag {
    fetch-nested-groups true
    fetch-primary-group true
    pwd-expiry-warn-days 7  
    query-filter "sAMAccountName=%{session.ntlm.last.username}"
    server /Common/Server
    type query
}

 Recommended Actions

  • Workaround is to use the login page before the AD query, or remove the password expiry configuration warning from AD agent.
