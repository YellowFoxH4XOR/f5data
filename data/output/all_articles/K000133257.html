Description

When checking source IP addresses inside Client IP addresses section in DoS Dashboard, you notice a high amount of traffic in N/A row.

Environment

  • BIG-IP AFM
  • Device DoS
  • DoS Profiles

Cause

There are two main possible scenarios which cause Client IP addresses shown as N/A:

  • AFM shows N/A for packets that match a DoS vector but they are not detected as an attack. This is expected, AFM will not save client IP addresses if they are not part of any attack. Saving thousands of legitimate IP addresses per minute in a DB would affect to performance and it would not provide any useful information from DoS perspective since we are interested in attackers.
  • AFM also shows N/A when packets are detected as part of an attack but DoS is offloaded in hardware. You can recognize this situation because row showing N/A also shows a value higher than 0 in Attacks column. For the time being AFM is only saving attacker IP addresses when attack is handled by software.

Note that you will still see some attacker IP addresses even when AFM is configured to handle DoS in Hardware. This is because there is a short delay, less than a second, between detecting an attack and activating hardware to mitigate an attack. During this short time AFM initially starts to drop packets in software, so AFM will save client IP addresses running the attack.

Recommended Actions

None

Additional Information

F5 is working on improving this behaviour in future releases.
