Known Issue

A case difference between the ARX filer share definition and the CIFS share name on the filer will cause an ARX subshare subsystem to fail if the ARX share is removed. The failure causes the ARX to reboot until the case matches.

This issue occurs when all of the following conditions are met:

  • There is a case difference between the ARX filer share definition and the CIFS share name
  • The ARX managed volume containing the filer share definition has filer-subshares enabled
  • The filer share definition is removed

Impact

The ARX system services will be unavailable.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The ARX subshare daemon cores
  • Syslog will contain an error message that appears similar to the following example:

    SUBSHRMGT-0-CRIT-MSG2:: Assertion "pos !=m_layers.end()" failed in void topo_cache::discard(layer_ptr&) at [topo_cache.cc:215]
  • The ARX system will continuously reboot until the case difference has been corrected, or until the three reboot bounce limit has been reached
  • This issue will affect both ARX systems in a redundant pair

Workaround

You can prevent this issue or recover from this issue by performing one of the following two procedures:

Preventing this issue

You can prevent this issue by renaming the share on the filer to match the case of the share name configured on the ARX. To do so, delete the share, then re-create the share using the same case as the ARX filer share definition. After completing the task, you may safely remove the ARX share, if desired.

Note: F5 recommends that you note the permissions for the file share before you delete it so you can apply the same permissions when you re-create the share.

Important: Once the filer share being renamed is deleted, it will be unavailable until it has been re-created.

Recovering from this issue

If your ARX system has encounterd this issue after attemting to remove an ARX share, you must rename the share on the filer as described in the Preventing this issue section. Additionally, you must reload the ARX using the following procedure:

  1. Log in to the ARX CLI.
  2. Enbable privileged mode by typing the following command:

    enable
  3. Reload the ARX by typing the following command:

    reload

When the ARX reloads, the share removal which triggered the issue will now complete.
