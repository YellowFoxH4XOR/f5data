Known Issue

The BIG-IP system may not honor the SQL monitor's connection count value.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP configuration that uses an SQL monitor to monitor the database server resources.
  • You want to change the SQL monitor's count value so the SQL monitor will re-use a database connection for only a specified number of health monitor probes.

By default, the BIG-IP system uses the same database connection for all of the SQL health monitor probes when the SQL monitor's count value is set to 0 (default value). If you want the BIG-IP system to close the database connection after a specified number of monitor probes, you can set the count value of the SQL monitor accordingly. For example, with the count value set to 5, the BIG-IP system should close the database connection after five monitor probes, after which a new database connection will be established on the next probe.

Impact

The BIG-IP system may not honor the SQL monitor's connection count value and may initiate a new database connection for each health monitor probe.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When the SQL monitor has debugging enabled, error messages similar to the following examples appear in the /var/log/DBDaemon-0.log file:

    2016-04-08 16:08:02.482: jdbc:oracle:thin:@192.168.20.199:1521:xe(Thread-447252): Current count: 101 Count : 5
    2016-04-08 16:08:02.482: jdbc:oracle:thin:@192.168.20.199:1521:xe(Thread-447252): Closing connection after 101 uses.
    2016-04-08 16:08:02.483: jdbc:oracle:thin:@192.168.20.199:1521:xe(Thread-447252): Closed DB connection.

Workaround

To work around this issue, you can add the value of 101 to the desired count value of the SQL monitor. For example, if you want the SQL monitor to close the database connection after every 5 monitor probes, enter a count value of 106, instead of 5.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window, and consider the possible impact on your specific environment.
