K000150754: After upgrading, no access to F5OS-A except with root user

Type
Support Solution
Published
2025-04-08
Updated
2025-04-08
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.8.X, 1.8.0, 1.7.0
Source
https://my.f5.com/manage/s/article/K000150754

Description

Can only log in to F5OS with the root user after an F5OS-A upgrade, and su admin does not work.

Messages similar to the following in /var/log/messages:

platform-deployment[3447]: The Compose file is invalid because:
platform-deployment[3447]: Service firewall-manager has neither an image nor a build context specified. At least one must be provided.
platform-deployment[3447]: Unexpected error encountered while starting platform services via docker-compose.
platform-deployment[3447]: Waiting 10 seconds and retrying (attempt 1 of 3).

Environment

  • F5OS-A upgrade
  • rSeries

Cause

The messages indicate that platform services haven't launched successfully, and docker compose is complaining about an invalid compose file.

There may be a platform.override.yml file with invalid content at /var/docker/config.

Recommended Actions

If you previously created a file at /var/docker/config/platform.override.yml, delete it and reboot the system.

If a file exists there and you are not sure of its origin, collect a diagnostic tarball and contact F5 Support for further assistance:

tar czf ~/f5-support-files.tgz /var/docker/config /var/F5/system/AFU* ~/.bash_history /var/log /var/F5/system/log

Additional Information

There may be other causes of su admin not working after an upgrade, but typically it indicates that platform services have not launched successfully. Investigating /var/log/messages is the first step.
