Topic

The BIG-IP ASM system locks a policy when it is being edited, in order to avoid simultaneous edits by multiple users. When a user edits a policy, the BIG-IP ASM system prevents other users from editing the same policy for ten minutes after the last change.

When a policy is locked and a user attempts to edit it, a warning message similar to the following example displays:

Warning: this policy is currently in read-only mode. It is in use by user <username>

Changing the policy lock timeout

  1. Log in to the command line.
  2. Edit the /ts/dms/policy/global.php file.
  3. Locate the following line:

    define("POLICY_LOCK_SESSION_EXPIRE", 600);

  4. Change the number at the end of the line, which indicates the number of seconds before the editing session expires, to the new timeout you want to use.

    The following example indicates a timeout of 20 minutes:

    define("POLICY_LOCK_SESSION_EXPIRE", 1200);

  5. Save the file and exit the editor.

Releasing a policy lock

You can release a policy lock before the timeout expires by performing the following procedure:

  1. Log in to the command line.
  2. Enter the MySQL command line.

    Note: For information about logging into the MySQL command line, refer to K6979: Managing the MySQL database password for the BIG-IP system.
  3. Delete the policy lock by typing the following command:

    DELETE FROM PLC.PL_POLICY_LOCK;

  4. Exit the MySQL command line by typing the following command:

    exit
