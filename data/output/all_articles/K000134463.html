K000134463: Nginx-Plus logs are not rotating

Type
Support Solution
Published
2023-05-04
Updated
2023-05-16
Applies to
  • NGINX Products
  • NGINX Plus: R25, R29, R28, R27, R26, R24
Source
https://my.f5.com/manage/s/article/K000134463

Description

  • You have deployed Nginx successfully.
  • You are concerned with system disk utilization due to increasing log files size.
  • You want to customize and manage Nginx logs rotation and retention. 

Environment

  • Nginx Plus
  • log rotation
  • logrotate

Cause

  • None

Recommended Actions

  • Nginx does not have a native feature to manage log rotation but relies on a system utility.
  • System utility Nginx utilizes is called "logrotate", which is located in directory /etc/logrotate.d with filename nginx and has the below configuration
/etc/logrotate.d/nginx 
/var/log/nginx/*.log {
        daily
        missingok
        rotate 52
        compress
        delaycompress
        notifempty
        create 640 nginx adm
        sharedscripts
        postrotate
                if [ -f /var/run/nginx.pid ]; then
                        kill -USR1 `cat /var/run/nginx.pid`
                fi
        endscript
}
  • The default configuration specifies that the system keeps 52 log files, equaling one for each day.
  • These values can be modified based on your requirements.
  • If you modify /etc/logrotate.d/nginx file, you do not have to do anything more. Since, logrotate runs as a cron job, it will consider the new configuration and take action on the changes, when it runs the next time.

Additional Information

  • If you have 52 files under /var/log/nginx/ and modified to reduced the number of files from 52, say to 15; existing files will NOT be removed by logrotate, the next time it runs. Files greater than 15, will simply be ignored and you have to manually remove/move them, if you want to reclaim some disk space.
  • Here is some description for the above configuration
  1. daily – rotate logs once a day. This value can be changed to weekly, which would then mean a rotation of file once each weekday
  2. missingok – do not throw error if log file is missing
  3. rotate 52 – defines the number of files that will be kept on the host system, which in this case is 52 log files. Roughly a two month worth of log data. Again this can be modified per your spec.
  4. compress – compress old log files to save space. After the log file has been rotated (but before the old version of the log has been compressed), the command /usr/bin/killall -HUP syslogd will be executed.
  5. notifempty – ensure that logrotate only writes to new files
  6. create – create new empty log file after each rotation
  7. sharedscripts – logrotate will only run once, irrespective of numerous match or the presence of many log files
  8. prerotate and postrotate – before and after log rotation a script is run, respectively
