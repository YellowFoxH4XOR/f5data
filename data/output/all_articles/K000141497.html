Description

Recent configuration changes are lost after rebooting an F5OS (rSeries / VELOS) tenant BIG-IP.

Environment

  • rSeries or VELOS tenant
  • BIG-IP
  • /shared logical volume is 100% utilized and filled by many /shared/tmp/rpm-tmp* files
  • /var/log/audit log has messages similar to below:
    01420002:5: AUDIT - pid=14907 user=root folder=/Common module=(tmos)# status=[Unexpected Error: Can't create temp directory, /var/tmp/.config.tmp/fZfqlA, errno 28] No space left on device] cmd_data=save / sys config partitions { Common }
  • May be seen more often in an environment, where UCS backup is automated

Cause

The issue could be due to combinations of two defects: ID 985329 and ID 1105021.

Due to ID 985329, /shared logical volume is 100% utilized and filled by many /shared/tmp/rpm-tmp* files. This prevents configurations to be saved on disk because saving configurations requires creating a temp directory like /var/tmp/.config.tmp/<random_name> (/var/tmp is symbolic linked to /shared/tmp). Due to another ID 1105021, F5OS tenant loads configurations from files instead of mcpd binary database after a reboot. This causes recent configuration changes to be lost after reboot of the tenant.

Recommended Actions

Refer to the following article for the recommended actions.

K90721117: The /shared/tmp directory is full of rpm-tmp files
