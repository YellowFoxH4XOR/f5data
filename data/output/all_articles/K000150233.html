Description

How can I monitor the current query rate per second for GTM/DNS requests?

Environment

  • Using BIG-IP GTM with a license limit
  • BIG-IP license limits number of DNS query rates per second
  • Need to monitor the current query rate per second

Cause

N/A

Recommended Actions

  1. Using the GUI: Troubleshooting a BIG-IP System with a Rate-Limited License 
    1. This will not give you real time RPS. This will give you a total. Meaning, you can check total DNS queries at xx:xx:20 then after 10 seconds at xx:xx:30. Subtract, divide by 10. You'll get average RPS on those 10 seconds.
  2. Using the CLI, you can do: 
    1. tmctl profile_dns_stat -q -c -s rps | awk '{s1+=$1} END {print s1}'
    2. This will give you real time RPS. It will basically sum RPS from all DNS profiles. It's probably the most reliable method.
  3. Using SNMP, you can use the OID "F5-BIGIP-LOCAL-MIB::ltmDnsProfileStatResponsesPerSec ", or the numeric equivalent .1.3.6.1.4.1.3375.2.2.6.14.2.3.1.4
    1. This will give you real-time RPS, but will break it down to individual RPS for each DNS profile. If you have multiple virtual-servers / multiple DNS profiles, you would need to sum the numbers in the output to get to total RPS for the entire box.
