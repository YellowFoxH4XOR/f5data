Description

After upgrading a vCMP Guest or vCMP Host, the vCMP Guest is stuck in an INOPERATIVE state.
  • ??????The following errors may be logged to /var/log/ltm:
    warning mcpd[7235]: 012a0004:4: halStorageRead: unable to read storage on this platform.
    notice mcpd[7235]: 01071038:5: Loading keys from the file.
Environment
  • vCMP guests 'INOPERATIVE' after upgrade
  • tmsh is very slow
  • Upgrade to BIG-IP 13.1.1.5 or 12.1.4.1 or a new guest is created
  • Virtual Clustered Multiprocessing (vCMP) is provisioned

Cause

  • Bug ID 769809
  • vCMP guests are sent a truncated unit key and fail to decrypt the master key needed to load the config.

Recommended Actions

Perform either of the following actions:

  • Upgrade to a version of code where ID 769809 has been resolved
  • Attempt to work around this issue

Upgrade to a version of code where ID 769809 has been resolved
This issue has been addressed and is fixed in the following versions.

  • 15.0.0
  • 14.1.0.6
  • 14.0.0.5
  • 13.1.3
  • 12.1.5

Important: To install any of these versions a boot back to the previous version of the major branch and then upgrade to the fixed version. 
Note: The command switchboot may not function as needed.
Note: You will need to know which volume to boot back to.
Note:  In cases where a rollback is not possible a rebuild of the guest will be necessary. This rebuild can be done with the use of a UCS backup or from scratch.
Note: Building the guest from a version that is in the list above is strongly recommended.
