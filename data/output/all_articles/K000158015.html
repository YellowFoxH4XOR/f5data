K000158015: Understanding "KERBEROS agent: No AAA server associated" Log Messages on BIG-IP APM 17.x

Type

Published

Applies to

Source

Description

This article explains the appearance of repeated log messages such as:

err apmd[16157]: 01490014:3: 00000000: KERBEROS agent: No AAA server associated with /Common/kerberos_auth_config_default_act_kerberos_auth_ag

on BIG-IP APM systems running version 17.x. These messages may be seen even when Kerberos authentication is not configured or used. The logs typically appear in system log files and are associated with the default access profile kerberos_auth_config_default. Customers may notice these messages after upgrading to BIG-IP 17.5.1 or later, and may be concerned about their meaning or impact.

Environment

  • BIG-IP APM module, version 17.5.1 and later
  • no Kerberos authentication configured
  • Default access profile: kerberos_auth_config_default
  • Recent upgrade to BIG-IP 17.5.1
  • Log messages observed in system log files (e.g., /var/log/apm*)))

Cause

The log messages are generated because the default, system-managed access policy kerberos_auth_config_default includes a Kerberos agent without an associated AAA server. This policy is present by default in BIG-IP APM 17.x to support internal features such as Windows Integrated Authentication. When the access policies are loaded, the APM daemon checks for a Kerberos AAA server and logs its absence as an error, even if Kerberos is not actively used.

Recommended Actions

  • No action is required if Kerberos authentication is not used in your environment; these log messages can be safely ignored.
  • Do not attempt to delete or modify the kerberos_auth_config_default access profile, as it is system-managed and cannot be edited or removed.
  • If Kerberos authentication is required in the future, ensure a valid AAA server is associated with any custom Kerberos agent in user-defined access policies.

Additional Information

  • The presence of these log messages is expected behavior in BIG-IP APM 17.x and does not indicate a misconfiguration or operational issue.
  • The kerberos_auth_config_default access profile is included by default and is used internally by features such as Windows Integrated Authentication.
  • The log messages may appear after upgrades or internal policy reloads, even if no changes were made to Kerberos configuration.
