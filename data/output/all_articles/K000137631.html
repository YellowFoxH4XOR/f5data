Topic

This article describes how you can determine if your BIG-IP system is running HTTP/2. And if your system is indeed running HTTP/2, how you can further understand the nature and profile of HTTP/2 traffic on the system.

Description

The BIG-IP system's control plane does not support HTTP/2. Therefore, in order to determine if your BIG-IP system is processing HTTP/2 traffic, you should examine and evaluate the system's data plane (client-side and server-side). To do so, perform the following procedures:

  • Determine from your BIG-IP configuration if any virtual servers support HTTP/2
  • Understand HTTP/2 traffic statistics and processing on your system
  • Examine and understand HTTP/2 traffic in detail with tcpdump
  • Use command line tools to verify HTTP/2 support

Determine from your BIG-IP configuration if any virtual servers support HTTP/2

To support HTTP/2, a virtual server requires a HTTP/2 profile, for example client-side only HTTP/2. And to support full proxy (client and server side) HTTP/2, the HTTP MRF router option is also required. In order to determine if your BIG-IP system has any HTTP/2 virtual servers, you can find out which virtual servers are configured with these attributes, To do so, refer to the procedure in K000092997: How to determine if any of my virtual servers are using a client-side HTTP/2 profile with the HTTP MRF router option?.

Note that not all virtual servers configured with the HTTP MRF router option are HTTP/2 virtual servers. For example, a HTTP/3 virtual server with a HTTP/3 profile also has HTTP MRF router enabled.

Understand HTTP/2 traffic statistics and processing on your system

You can determine if your BIG-IP system is processing HTTP/2 traffic by examining the traffic statistics of the HTTP/2 profiles. To do so, perform one of the following procedures:

  • Examine HTTP/2 traffic statistics on the Configuration utility
  • Examine traffic statistics for a specific HTTP/2 profile
  • Examine HTTP/2 traffic statistics on tmsh(tmos)

Note that the absence of HTTP/2 traffic and statistics does not indicate no HTTP/2 support. Your system may still be configured with a virtual server and may just not be processing HTTP/2 traffic due to various reasons such as an inaccessible virtual server IP address or no clients. You should still examine your BIG-IP configuration as described in the previous procedure.

Examine HTTP/2 traffic statistics on the Configuration utility

Perform the following procedure:

  1. Login to the Configuration utility
  2. Go to Statistics > Module Statistics > Local Traffic
  3. At Statistics Type, select Profiles Summary.
  4. At HTTP/2, select View

Examine traffic statistics for a specific HTTP/2 profile

Perform the following procedure:

  1. Login to the Configuration utility
  2. Go to Local Traffic > Virtual Servers > Statistics

    Note: Scroll to the right to observe the Message Routing Framework column. An active HTTP/2 virtual server should have statistics under this column

  3. Select your HTTP/2 virtual server. 
  4. Select Statistics
  5. Under Profiles, select your HTTP/2 profile

Examine HTTP/2 traffic statistics on tmsh (tmos)

Perform the following procedure:

  1. Login to the tmsh (tmos) shell
  2. Enter the following command to display statistics for all the HTTP/2 profiles on the system:

    show ltm profile http2

Examine and understand HTTP/2 traffic in detail with tcpdump

Once you have verified your BIG-IP system to have HTTP/2 virtual servers and processing traffic from the previous 2 procedures, you can use the tcpdump command to further understand or troubleshoot any issues. To do so, refer to K95032535: Detecting the use of and troubleshooting HTTP/2 traffic on the BIG-IP. 

Use command line tools to verify HTTP/2 support

When you need to determine if a web or IP address supports HTTP/2, there are several useful Linux commands that you can run from the BIG-IP system that can help you do so.

Note: F5 does not provide support for third party Linux commands. The following serve as examples and you may need to modify the switches in each command as appropriate. the For more information, refer to the commands' support (man) pages.

  • nghttp: Beginning in BIG-IP 14.1.0, you can use the nghttp tool to troubleshoot HTTP/2. nghttp makes direct HTTP/2 requests without using the Upgrade header method in HTTP/1.1. To do so, use the following command syntax:

    nghttp -nv https://<server_IP_address>

    When a server does not support HTTP/2, you may observe the following at the end of the output:

    [...]
    [  0.007] [ERROR] Remote peer returned unexpected data while we expected SETTINGS frame.  Perhaps, peer does not support HTTP/2 properly.
    Some requests were not processed. total=1, processed=0

    When a server supports HTTP/2, you may observe an output similar to the following:

    [...]
              user-agent: nghttp2/1.31.1
    [  0.012] send GOAWAY frame <length=8, flags=0x00, stream_id=0>
              (last_stream_id=0, error_code=NO_ERROR(0x00), opaque_data(0)=[])

  • curl: Use the following example command syntax:

    curl -vsko /dev/null https://<server IP address> 2>&1 | grep 'ALPN\|HTTP'

    When a server does not support HTTP/2, you may observe an output similar to the following:

    * ALPN, offering h2
    * ALPN, offering http/1.1
    * ALPN, server did not agree to a protocol
    > GET / HTTP/1.1

    When a server supports HTTP/2, you may observe an output similar to the following:

    * ALPN, offering h2
    * ALPN, offering http/1.1
    * ALPN, server accepted to use h2
    * Using HTTP2, server supports multi-use
    * Connection state changed (HTTP/2 confirmed)
    * Copying HTTP/2 data in stream buffer to connection buffer after upgrade: len=0
    > GET / HTTP/2

Additional Information

The article so far focuses on the client-side. You should note also that HTTP/2 traffic processing on the BIG-IP system can also occur on the server-side and may for example add to HTTP/2 statistics (A virtual server has a HTTP/2 Profile (Server) as well, and it may share the same profile as the HTTP/2 Profile (Client)). It is important to note that for the server-side of a virtual server, the BIG-IP system acts as the client communicating with a backend HTTP/2 server and security vulnerabilities that impact only HTTP/2 servers may not apply.

When you observe HTTP/2 traffic on the server-side of the BIG-IP system, the following objects may be contributing to it:

  • Virtual server traffic on the server-side: Beginning in BIG-IP 14.1.0, F5 provides full proxy (client-side and server-side) support for the HTTP/2 protocol.

  • BIG-IP monitors: Beginning in BIG-IP 15.1.0, support for HTTP/2 monitors is introduced. For more information, refer to K29224049: Overview of the BIG-IP HTTP/2 monitor.
    External monitors that check the health of HTTP/2 servers may also contribute to HTTP/2 traffic. For more information on external monitors, refer to K71282813: Overview of BIG-IP EAV external monitors.
