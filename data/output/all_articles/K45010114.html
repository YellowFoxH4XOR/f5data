Description

There are one or more of the symptoms like below:

  • All interfaces are marked disabled
  • tomcat service is continuously restarting
  • Logging to log files under /var/log directory is stopped
  • Manually restarting syslog-ng service fails

Environment

  • BIG-IP
  • Recently syslog include configuration has been updated either via tmsh, GUI, or UCS restore
  • BIG-IP software has been upgraded from an earlier version to 13.1.0 or later.

Cause

The issue is tracked via ID 1074841.

On versions where ID 740589 is fixed, an improper configuration will prevent syslog-ng from even starting so that the CPU does not spike. This will prevent tomcat service from starting so GUI access will fail. The syslog include configuration that was accepted in earlier versions may be rejected in the new version. The issue is that the invalid configuration may still pass validation and can be loaded successfully during configuration change due to the known issue.

One typical example of an invalid syslog configuration is a missing persist-name() in the destination configuration like below. Each destination syslog server IP and port combination needs to be unique (it does not matter what the localip is).

    destination d_remote_loghost {
        udp(<syslog_server_A> port(514) localip(<mgmt_ip_bigip1>));
        udp(<syslog_server_A> port(514) localip(<mgmt_ip_bigip2>));
    };

Recommended Actions

  1. Make sure sys syslog include configuration contains a valid syslog-ng configuration.
  2. For the example above, the configuration can be updated as follows by introducing persist-name() to make them unique. The string inside the parentheses (like "r1" and "r2" below) can be anything, but they must not be the same.
    destination d_remote_loghost {
        udp(<syslog_server_A> port(514) localip(<mgmt_ip_bigip1>) persist-name(r1));
        udp(<syslog_server_A> port(514) localip(<mgmt_ip_bigip2>) persist-name(r2));
    };
  1. If your system is already affected, you may follow the steps below to recover.
    1. Output current syslog configuration for later reference.
      # tmsh list sys syslog
    2. Remove the syslog include section and save the configuration to files.
      # tmsh modify sys syslog include none
      # tmsh save sys config
    3. Confirm logging starts automatically after step 2 (in /var/log/ltm for example) and tomcat restart stops. If not, reboot the system to see if it improves.
    4. Update syslog include configuration.
    5. Follow K26457459 to add a new syslog configuration.

Additional Information

While the syslog-ng service not running normally will prevent the system from logging normally, the systemd journal still contains the information that would otherwise be logged. This can be viewed and interpreted with the journalctl command in the bash shell. For example, to search for references to syslog-ng itself, run this:

journalctl -xe | grep syslog

This can help identify errors in syslog-ng configuration or other root causes of syslog-ng failing to start.
