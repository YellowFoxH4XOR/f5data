Description

When enabled, Auto Last Hop allows the BIG-IP system to send return traffic from pools to the MAC address that transmitted the request, even if the routing table points to a different network or interface. As a result, the BIG-IP system can send return traffic to clients even when there is no matching route. You may want to check which MAC address is being used by Auto Last Hop, in order to confirm whether this works as expected.

Environment
  • Auto Last Hop enabled

Cause

None

Recommended Actions

You may show connection entries with Auto Last Hop details: tmsh show sys connection all-properties
Note: Remember to use additional options to filter (cs-client-addr, cs-client-port) for specific connections. Depending on your environment and BIG-IP platform, your BIG-IP system may restart some processes, such as the Traffic Management Microkernel (TMM) or mcpd if a large number of connection records are returned. You may refer to K20234023 for more details.

For example, this connection is using 00:50:56:86:3f:f0 as the entry of Auto Last Hop.
root@(bigip-1)(cfg-sync Standalone)(Active)(/Common)(tmos)# show sys connection cs-client-addr 10.10.10.77 all-properties

Additional Information

  • Auto Last Hop records the source MAC address of the first packet that creates the connection entry and keeps using this MAC address to return the traffic. MAC address stored by BIG-IP does not get updated for the existing flows. If connection was started with source MAC A and subsequent packets are coming with source MAC B, BIG-IP will still use MAC A to return the traffic. Therefore, MAC address in the connections may be different than the one used by Auto Last Hop sometimes.

  • MAC used by Auto Last Hop may be different from ARP table, because ARP table is built from replies to ARP requests, recorded possibly before a packet is sent.

  • You may clear this Auto Last Hop entry, by either waiting for the connection expires with idle timeout, or deleting the connection: 
    tmsh delete sys connection cs-client-addr 10.10.10.77 cs-client-port 55129
    Note: Remember to use additional options to filter (cs-client-addr, cs-client-port) for specific connections.
