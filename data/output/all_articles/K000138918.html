K000138918: No Such Instance currently exists at this OID

Type
Support Solution
Published
2024-03-18
Updated
2024-03-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000138918

Description

The snmptranslate command can return an incorrect OID value if the double quotes are not escaped properly in the SNMP Object Name

# snmptranslate -On F5-BIGIP-SYSTEM-MIB::sysInterfaceStatus."1.1"

.1.3.6.1.4.1.3375.2.1.2.4.1.2.1.17.1.1

When you attempt to use this OID value, you will receive the following error:

# snmpget -v 2c -c public localhost .1.3.6.1.4.1.3375.2.1.2.4.1.2.1.17.1.1

F5-BIGIP-SYSTEM-MIB::sysInterfaceStatus."." = No Such Instance currently exists at this OID

Environment

  • BigIP LTM
  • SNMP

Cause

In bash, double quotes are not treated as literal characters but rather as special symbols that indicate grouping. When the SNMP Object Name contains unescaped double quotes, bash attempts to interpret the content within the quotes as a single entity, potentially leading to an incorrect OID value being returned .

Recommended Actions

Ensure that any quotes or other special characters in the command are escaped using backslashes:

snmptranslate -On F5-BIGIP-SYSTEM-MIB::sysInterfaceStatus.\"1.1\"
