Topic

The BIG-IP ASM Requests screen displays a list of all objects requested by users of the web application. When the BIG-IP ASM system processes a large number of requests over time, and the MySQL PROXY_LOG consumes over 200 megabytes of SQL data, the BIG-IP ASM Requests page may take a long time to load, or may time out and fail to load. If you are experiencing either of these issues, you may resolve the issue by performing one of the following two procedures, based on your issue:

The BIG-IP ASM Requests page takes a long time to load

When the BIG-IP ASM Requests page takes a long time to load, and eventually displays the requests list, you may mitigate the issue by selecting a more restrictive filter, and clearing extraneous request entries using the Configuration utility. To do so, perform the following procedure:

  1. From the Application Security Main tab, click Reporting.

    The Requests page displays.

  2. Click the Filter button.
  3. Define an appropriate filter to display a more limited number of requests.
  4. Click the Clear button to delete selected request entries from the system.

The BIG-IP ASM Requests page times out and fails to load

When the BIG-IP ASM Requests page times out and fails to load, you may mitigate the issue by using one of the following two options:

  • Setting the search filter back to the default of 10,000 entries from the command line
  • Clearing the PROXY_LOG from the command line

Setting the search filter back to the default of 10,000 entries from the command line

  1. Log in to the command line.
  2. Obtain the MySQL password.

    Note: For more information, refer to K6979: Managing the MySQL database password for the BIG-IP ASM.

  3. Verify that the current value of the filter_search_in_last table is 10000 by typing the following command:

    mysql -p<MySQL_password> DCC -e "SELECT filter_id,filter_item,item_value from FILTER_CUSTOM_DATA WHERE filter_item='filter_search_in_last';"

    The command should return the following table:

    +-------------+-----------------------------+----------------+
    | filter_id   | filter_item                | item_value |
    +-------------+-----------------------------+----------------+
    |        52   | filter_search_in_last | 10000       |
    +-------------+-----------------------------+----------------+
    • If the MySQL command returns the example table, proceed to Step 4.
    • If the MySQL command returns a table, but the filter_search_in_last entry contains a value other than 10000, reset the value to 10000 by typing the following command:

      mysql -p<MySQL_password> DCC -e "UPDATE DCC.FILTER_CUSTOM_DATA SET item_value = '10000' WHERE filter_item = 'filter_search_in_last';"

    • If the MySQL command does not return a MySQL table, you must insert a new column. To obtain the currently-selected filter, type the following command:

      mysql -p<MySQL_password> DCC -e "SELECT filter_id FROM FILTER_SELECTION WHERE page_id = '5';"

      Next, replace 52 in the following text with the filter_id found in the previous step:

      mysql -p<MySQL_password> DCC -e "INSERT INTO DCC.FILTER_CUSTOM_DATA (filter_id,filter_item,item_value) VALUES('52','filter_search_in_last','10000');"

  4. Refresh the ASM Requests page.

Clearing the PROXY_LOG from the command line

Note: For more information about clearing the PROXY_LOG or partially clearing the log and leaving the most current records, refer to K11370: Clearing the ASM PROXY_LOG from the command line.

If setting the search filter back to the default of 10,000 entries does not resolve the issue, you may need to clear the PROXY_LOG from the command line. To do so, perform the following procedure:

Note: Performing this procedure permanently clears the BIG-IP ASM request logs.

  1. Log in to the command line.
  2. Obtain the MySQL password.

    Note: For more information, refer to K6979: Managing the MySQL database password for the BIG-IP ASM.

  3. Start the MySQL CLI tool by entering the following command:

    mysql -p<password>

  4. Use the PRX database by typing the following command:

    use PRX;

  5. Clear the Proxy Log table by entering the following command:

    TRUNCATE TABLE PROXY_LOG;

  6. Exit the MySQL CLI tool by entering the following command:

    QUIT;

Mitigating ASM Requests page performance issues

It is possible to mitigate ASM Requests page performance issues by selecting a more restrictive filter, and clearing extraneous request entries using the Configuration utility. To do so, perform the following procedure:

  1. On the Main tab of the Application Security navigation pane, click Reporting.

    The Requests screen opens.

  2. On the Requests screen, to the left of the Filter list, click the Show/Hide Filter button.

    The Filter option expands to display the custom filter options.

  3. Specify the criteria by which you want the Filter option to filter the Requests List.

    In the Web Applications option, choose only the web application to display the requests.

    You may also specify a more restrictive filter by using the other options. For information regarding the various filter options available, refer to the Help section within the Configuration utility.

  4. Click the Save Filter button.

    A pop-up screen opens, where you provide a name for the custom filter.

  5. Type a name for the custom filter, and click OK.

    The screen refreshes, and you see the custom filter in the Filter list.

  6. From the Filter list, select the custom filter that you just created, and then click Go.

    The screen refreshes, and the Requests List displays only those events that match the specified criteria.
