K1502: Reasons why other 3-DNS Controllers will indicate that named is down on another 3-DNS Controller, after you change the IP address of the other Controller

Topic

3-DNS may detect that named has failed on another controller if it has actually failed. It may also detect that named has failed if you have changed the IP address of the other 3-DNS controller.

This issue is caused because the big3d agent, which checks the remote controllers, still contains outdated IP address information in its memory.

To resolve this issue, restart the named daemon by typing the following command:

Note: Restarting the named daemon will cause a momentary lapse in service for the 3-DNS Controllers. This lapse should be no more than 30 seconds for sites with a small number of wide IPs, records, and zones. For large configurations (for example, 1,500 zones) this could take up to a minute.

3ndc restart

This will reload the configuration files and force the old IP address out of memory.
