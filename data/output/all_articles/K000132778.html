K000132778: Lose All System Files After a Downgrade

Type
Support Solution
Published
2023-02-27
Updated
2023-02-27
Source
https://my.f5.com/manage/s/article/K000132778

Description

Downgrades are not supported by design and configuration is not imported in the older version installed. However, if you need to verify the configuration and/or device certificate from a higher version after a downgrade, you can mount the volume disk.

 

Environment

BIG-IP 16.1

Cause

Downgrade.

 

Recommended Actions

 

 

1.      Login into the BIG-IP CLI.

 

2.      From the command line, bash shell move the current directory to /dev/mapper using command:

cd /dev/mapper

 

3.      Verify the config files contained in the current directory:

 ls *_config*

 

The output should look similar to:

 

brw-rw----. 1 root disk 253, 01 2023-02-13 12:20 vg--db--sda-set.1._config

brw-rw----. 1 root disk 253, 01 2023-02-13 12:20 vg--db--sda-set.2._config

 

In the example above set.1 corresponds to HD1.1 and set-2 refers to HD1.2.

4.      Create a new directory in /tmp/ to mount the volume of interest

mkdir /tmp/mnt

5.      Mount the disk of interest in the volume created:

mount -o rw /dev/mapper/<vg--db--sda-set.2._config> /tmp/mnt

 

In this example for HD1.2, the command to use would be:

mount -o rw /dev/mapper/vg--db--sda-set.2._config /tmp/mnt

 

6.      Unmount the disk from the directory created:

umount /tmp/mnt

 

7.      Finally, you should be able to see a temporary holding place for the disk of interest in /tmp/mnt/
