Known Issue

This is the result of a known issue. If a BIG-IP LTM virtual server is configured using the Packet Velocity ASIC (PVA) Acceleration mode set to Full and a pool member MAC address changes (for example, a Sun Solaris IPMP setup), the PVA will not recognize the change. Instead, the PVA will direct traffic to the previous MAC address.

Note: This behavior only affects new connection flows. Existing connection flows will still be directed to the previous MAC address.

F5 Networks Product Development tracked this issue as CR91256 and it was fixed in BIG-IP LTM version 9.4.4 for the BIG-IP LTM 9.4 software branch. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.3.1-81.1-HF8, which was issued for version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

Workaround

To work around this issue, F5 Networks recommends that the PVA Acceleration mode is set to Assisted. This setting allows the system to use the software component of the PVA (controlled by the FastL4 profile), to track changes and still provide acceleration of traffic. To do so, perform the following procedure:

Note: F5 Networks recommends using a custom FastL4 profile for individual virtual servers and not changing the values of the default FastL4 profile.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Protocol.
  5. Select the FastL4 profile.
  6. Select Create.
  7. Provide a name for the custom profile.
  8. Select the PVA Acceleration check box.
  9. Select Assisted.

    Note: At this point in the procedure, you may make other optional configuration changes.
  10. Select Finished.

Once the custom FastL4 profile has been created, apply this new profile to the BIG-IP LTM virtual servers that make use of the pool members that change their MAC address for fault tolerance configurations.
