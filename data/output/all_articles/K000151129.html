K000151129: Modification or change of the TCP profile on a Virtual Server will reset tmsh show sys connection virtual <virtual server> statistics

Type
Support Solution
Published
2025-05-01
Updated
2025-05-01
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000151129

Description

When modifying or replacing a TCP profile associated with a virtual server on BIG-IP LTM (for example, using tmsh to change the TCP profile), the output of the tmsh show sys connection virtual-server <vs-name> command may show the connection count dropping to zero. However, existing connections are not terminated and continue to pass traffic. This can cause confusion, as it appears that all sockets have been cleared, but in reality, only the statistics table is affected. No specific error messages are generated; the connection table for the virtual server simply appears empty immediately after the profile change. 

Environment

  • Product: BIG-IP LTM
  • Configuration: Virtual servers with TCP profiles where the TCP profile is modified or replaced (e.g., switching from a profile based on tcp-wan-optimized to one based on tcp-lan-optimized).

 

Cause

This behavior is caused by a display bug ID1930841 in how statistics are presented for virtual servers. When a TCP profile is changed on a virtual server, the show sys connection virtual-server <vs-name> command may not accurately reflect active connections. The underlying connections remain intact; only their representation in this particular statistics view is affected. 

Recommended Actions

  • To verify active connections after changing a TCP profile, use tmsh show sys connection cs-server-addr, which correctly displays current connections.
  • Understand that seeing zero connections in show sys connection virtual-server <vs-name> after a profile change does not mean actual traffic has been dropped.
  • No configuration changes are needed to preserve existing sessions; this issue affects only display output.
  • For accurate confirmation of active sessions post-profile-change, rely on information from the cs-server-addr field rather than from virtual server statistics.

 

Additional Information

 None.
