Issue

When you start a BIG-IP system licensed with the Full-Box FIPS add-on license, the BIG-IP system performs a series of self-tests to validate its integrity and operation. If any of these self-tests fail, the system halts. In addition, the system regularly performs some self-tests and may force an immediate restart, which results in a halted system. For more information, refer to the following documents:

  • The release notes for your specific BIG-IP version
  • The FIPS Platform Setup chapter of the F5 Platforms: FIPS Administration manual

    Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

You should consider using this procedure under the following condition:

  • You have a BIG-IP system licensed with the Full-Box FIPS add-on, and the BIG-IP system fails to boot when it restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to boot to the active partition.
  • You observe an error similar to the following example on the console:

    FIPS or Common Criteria power-up self-test failure. This system has been placed in an error state.

    Note: If the error is long enough, this text may scroll past the console window. You may need to scroll up to see it.

Note: If your BIG-IP system is operating and you see a log entry for an integrity check failure, refer to K11402545: Troubleshooting FIPS self-test failure.

Recommended Actions

Determining whether your system is compromised

F5 may be unable to make a final determination whether a device is compromised if it requires deeper forensic analysis than F5 support procedures allow. In such cases, F5 recommends contacting a trusted forensic security firm for a final determination if it is necessary to determine whether the device is compromised.

For integrity check issues, you should base your final determination on whether your BIG-IP system is compromised based on your organization's security policy. If you are unable to determine any known administrative changes that happened during the failure time window, you should review and follow your organization's policies and procedures for suspected compromised devices.

For cryptographic and Traffic Management Microkernel (TMM) self-test issues, you should base your final determination on whether your system is compromised based on your organization's security policy; however, these issues are less likely to happen due to your system being compromised than due to other issues. In such cases, you should work with F5 Technical Support to determine whether the cause of the issue is due to a known issue or system bug.

Procedures

When your BIG-IP system fails to boot due to failed self-tests, perform the following procedures to recover the system:

  • Changing the system boot location and booting to an alternate partition
  • Performing a clean installation by re-imaging the BIG-IP system

Changing the system boot location and booting to an alternate partition

Important: As a prerequisite to this procedure, the BIG-IP system must have a backup partition available. If your system does not have a backup partition, you need to re-image the system.

  1. Immediately after you start the system, a screen displays asking you to select a boot partition to use. Select any partition other than the currently selected one.
  2. If you need to restore your system configuration from a backup, or if you intend to copy the configuration using the cpcfg command, make sure you have another available partition in case the issue is restored along with the backup configuration. For more information about the cpcfg command, refer to K14724: Using the cpcfg command to copy a configuration from one boot location to another.
  3. If necessary, perform a switchboot operation to make sure that the new partition becomes the default choice. For more information, refer to K5658: Overview of the switchboot utility.

Performing a clean installation by re-imaging the BIG-IP system

Impact of procedure: Re-imaging the BIG-IP system overwrites the entire hard drive. After you re-image the system, you cannot perform any further troubleshooting to determine the cause of the issue.

To perform a clean installation of the BIG-IP system, refer to K13117: Performing a clean installation of BIG-IP 11.x - 17.x.
