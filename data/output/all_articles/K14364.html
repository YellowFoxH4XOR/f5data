Issue

Note: This solution only applies when usage of the tmsh command resulted with this error message. For a similar error message that occurs when using bigpipe command, refer to K10284: Error Message: BIGpipe modification error: 01070826:3: Current Update Partition Error: The current update partition does not match the object's partition.

Error Message

01070826:3: Current Update Partition Error: The current update partition (<PartitionName-1>) does not match the object's partition (<Partition-2>) (<TypeOfObject>) (<ObjectIdentifier>)

In this error message, note the following:

  • <TypeOfObject> is the type of object. For example pool, VLAN, or virtual.
  • <PartitionName-1> is the name of the current update partition that is set on the user's shell partition write access.
  • <PartitionName-2> is the name of the partition to which the object belongs.
  • <ObjectIdentifier> is the name of the object failed to be modified.

For example:

01070826:3: Current Update Partition Error: The current update partition (ResourceA) does not match the object's partition (ResourceB) (pool) (BBpool-1)

Message Location

You may encounter this message in the following locations:

  • Command line
  • Traffic Management Shell (tmsh)

Description

This error message occurs when the current user's update-partition in the tmsh CLI setting does not match the administrative partition to which the object belongs.

When you use a tmsh command with the all option, the command may attempt to modify all objects that the system is able to read based on the user's query-partitions access in the tmsh CLI setting. The update-partition access of the tmsh CLI setting can only be set to one administrative partition at one time.

For the root user of the BIG-IP system, the default tmsh CLI setting is configured to have query-partitions access to all partitions, and have update-partition access to the /Common partition.

For a non-root user with advance shell access or tmsh shell access, the default shell partition setting is configured to have read access to all partitions, and write access to only one partition, depending on the user configuration setting.

To verify the current shell partition setting, perform one of the following actions:

  • From the command line prompt, type the following command:

    tmsh list /cli admin-partitions
  • From the tmsh shell prompt, type the following command:

    list /cli admin-partitions

For the root user, the output may appear similar to the following example:

cli admin-partitions {
    query-partitions all
    update-partition Common
}

Impact

When you encounter the error message, the execution of the tmsh command is aborted and no objects are modified.

Recommended Actions

  • If the user did not have the correct administrative partition set to the current update-partition in the tmsh CLI setting, you are required to modify it to the correct administrative partition before performing the tmsh command.

    To change write access (the update-partition setting) to the desired partition on tmsh, use the following command syntax:

    tmsh modify /cli admin-partitions update-partition <PartitionName>

    For example, to change the update-partition setting to the partition named ResourceB, type the following command:

    tmsh modify /cli admin-partitions update-partition ResourceB
  • If the user is unable to view the objects when this user has permission to query for > 1 administrative partitions, you may not have set the query permission to access the required administrative partition(s).

    To change the query access (ie. query-partitions setting) to 1 or more desired partition on tmsh, use the following command syntax:

    tmsh modify /cli admin-partitions query-partitions { <PartitionName-1> <PartitionName-2> ... }

    For example, to change the query-partitions setting to the partitions named ResourceA and ResourceB, type the following command:

    tmsh modify /cli admin-partitions query-partitions { ResourceA ResourceB }
