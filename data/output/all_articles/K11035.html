Known Issue

This is the result of a known issue. In rare cases, the alertd process on a VIPRION system may process only some of the messages it receives, or it may stop processing messages altogether. This issue is most likely to occur when alertd is processing a very high volume of messages. Although alertd may not send the configured alerts, syslogd is still able to process the messages and logs each message to its respective log destination.

Note: All alerts are affected by this issue, including custom alerts configured in the user_alert.conf file and all messages and SNMP traps that syslog sends to alertd.

F5 Product Development tracked this issue as CR130868, and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.

Workaround

You can work around this issue by restarting alertd when it no longer appears to be processing messages as expected. To do so, type the following command at the command line:

bigstart restart alertd

Alternatively, you can configure a remote logging profile, which sends events that are typically processed by the local alertd process to a remote syslog server instead.

Note: For information about configuring remote syslog logging, refer to K5527: Configuring the BIG-IP system to log to a remote syslog server (9.x).
