Known Issue

In a high availability (HA) configuration, the active BIG-IP system does not mirror its state information to the standby unit after the standby unit reboots. This issue occurs when all of the following conditions are met:

  • The HA pair is configured with both primary and secondary statemirror IP addresses
  • A specific virtual server on the HA pair is configured to perform connection mirroring
  • The standby unit is rebooted
  • The active unit successfully establishes a connection to the primary statemirror IP address of the standby unit

Note: You may want to verify if improperly configured packet filters that block traffic to port 1028 are configured on the HA pair.

Impact

Traffic may be disrupted when the standby unit takes over as the active unit.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Current Connections of the specific virtual server on the standby unit are reported to be less than that on the active unit using the tmsh show ltm virtual <vs name> command.

    For example, the myVS virtual server on the active unit is reported to have 10 connections by the tmsh show ltm virtual myVS command while the standby unit is reported to have 5 connections using the same command:

    Note: The example output has been truncated for brevity.

    On the Active unit
    Current Connections               10               0               -

    On the Standby unit
    Current Connections                5               0               -

  • Current connections may be disrupted when the standby unit takes over as the active unit.
  • The active unit attempts to establish a connection to the secondary statemirror IP address of the standby unit but receives a TCP RST.
