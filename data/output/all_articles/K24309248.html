Description

Under some specific circumstances you may see not all Events be logged in the Event Logs.

Environment

This can occur when:

  • BIG-IP ASM
  • Local logging
  • High traffic load

Cause

Your ASM is not configured to Guarantee Local Logging.

Your BIG-IP ASM is designed to be an optimal platform for protecting application layer traffic while not slowing that traffic down any further than necessary. Towards these ends network and computational performance are prioritized over writing to local disk. Therefore, unless configured to put logging locally first ("Guarantee Local Logging") your ASM will instead prioritize on moving and protecting the maximum amount of traffic. Towards this end, if given the choice whether to log events locally, or to handle the next customer query, your BIG-IP ASM will do the latter.

Recommended Actions

If local logs are needed (often useful for automatic learning) and you've not catching the event you need to see in the logs, you can turn on Guarantee Local Logging which will prioritize logging to disk over moving your network traffic. 

Note: This can cause impact in heavy load environments as it will put logging traffic first.

To enable Guarantee Local Logging modify your Logging Profile using the following steps:
  1. Log on to the BIG-IP ASM Configuration utility.
  2. Go to Security > Event Logs > Logging Profiles.
  3. Select your logging profile name.
  4. Change Application Security Configuration to Advanced.
  5. Select Guarantee Local Logging.
  6. Click Update.

Note: F5 recommends only using Guarantee Local Logging for a specific purpose and then if the system is in production that it turned off once no longer needed.
For long term verbose logging we recommend using remote logging. For more information on remote logging refer to: K37655278: BIG-IP ASM operations guide | Chapter 3: BIG-IP ASM event logging.
