Description

A slot in an F5 BIG-IP LTM vCMP cluster appears down or inoperative on a guest instance, despite being up from the host perspective and on other guest instances. The primary symptom is the slot not joining the cluster, with logs showing messages such as "Waiting for lind to send software status info," "SlotX is not loading, stuck with waiting for lind," and cluster member status showing "offline quorum Quorum: waiting for lind, HA TABLE offline."

Environment

VCMP

Cause

Services on the guest instance got stuck after the vCMP host upgrade, preventing the slot from joining the cluster. Specifically, the "lind" service did not provide software status info, resulting in the slot being offline for the affected guest.

Recommended Actions

To resolve the issue where a slot is down on a guest after a vCMP host upgrade:

  1. Put the guest into Configured mode:

    • Access the vCMP host management interface.
    • Change the affected guest's state to "Configured."

  2. Redeploy the guest:

    • Redeploy the guest instance from the vCMP host interface.
    • Monitor the cluster status to confirm the slot joins the cluster.

  3. If the slot does not join:

    • Reseat the blade physically (if possible).
    • If reseating does not resolve the issue, reboot the blade:
      • Log in to the blade using its management IP.
      • Run: bash reboot
    • After reboot, check cluster status and logs.

  4. If the issue persists:

    • Generate fresh QKView files from both the guest and vCMP host for further analysis.
