Description

The management GUI still presents an old certificate, after applying a new one.

This happens even when connecting directly from the BIG-IP command line, for example with openssl s_client:

openssl s_client -connect <mgmt IP>:443

This might be a problem if the new certificate was applied to mitigate issues identified in a vulnerability scan.

Environment

  • GUI
  • httpd

Cause

httpd was not restarted, so the older certificate was still in the running configuration.

Recommended Actions

Execute the following command to restart httpd and load the new certificate into memory:

tmsh restart /sys service httpd

Note: There is no impact to traffic.

Additional Information

You may see issues like the following when running a vulnerability scan against the management IP:

  • SSL Certificate Weak Public Key Strength
  • SSL Certificate Invalid Date
  • SSL Certificate Self-Signed
