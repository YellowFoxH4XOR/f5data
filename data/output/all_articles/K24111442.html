Description

No connection to the Management IP address \interface after upgrade.

Symptoms can be seen in command output:

tmsh list /sys management-ip all-properties
Unable to determine management-ip.

cm configuration in bigip_base.conf:

cm device /Common/f5ccc.xxx.cloudapp.azure.com {
    active-modules { "APM, Base, VE GBB (500 CCU, 2500 Access Sessions)|CLCCBES-CPHZQCY|Anti-Virus Checks|Base Endpoint Security Checks|Firewall Checks|Network Access|Secure Virtual Keyboard|APM, Web Application|Machine Certificate Checks|Protected Workspace|Remote Desktop|App Tunnel|APM, Base, VE GBB (500 CCU, 2500 Access Sessions)" "Best Bundle, VE-1G|ZASAZXW-UTPCIVH|Rate Shaping|DNSSEC|Routing Bundle, VE|ASM, VE|DNS-GTM, Base, 1Gbps|SSL, VE|Max Compression, VE|AFM, VE|DNS Rate Limit, 1000 QPS|GTM Rate, 1000|VE, Carrier Grade NAT (AFM ONLY)|PSM, VE|Best Bundle, VE-1G" }
    base-mac 00:0d:3a:18:56:c8
    build 0.0.10
    cert /Common/dtdi.crt
    chassis-id c***e
    configsync-ip 10.20.0.181
    edition "Point Release 1"
    hostname f5ccc.xxx.cloudapp.azure.com
    key /Common/dtdi.key
    management-ip 127.0.0.1 <----------------------------------!!
    marketing-name "BIG-IP Virtual Edition"
    mirror-ip 10.20.0.181


UCS from previous version contains configuration files, you can check the /config/bigip_base.conf file for management-ip that suppose to be assigned.

Environment

  • Azure
  • BIG-IP VE
  • After upgrade

Cause
Unknown

Recommended Actions

If the Management IP address should be static, please follow the below points:

Note: The following steps should be done in maintenance window, if it is an active peer.

1. Remove all possible mgmt addresses:
tmsh delete sys management-ip all

2. Change DHCP on mgmt to disabled:
tmsh modify sys global-settings mgmt-dhcp disabled

3. Create management IP, static:
tmsh create sys management-ip 10.20.0.18/<mask>

4. Review management route. [there is one for metadata now]
tmsh save sys config
