Known Issue

This is the result of a known issue. If a BIG-IP system is running on the VIPRION platform fails to copy class files contained in a subdirectory of the /config directory to the secondary cluster members. As a result, the configuration referencing the missing external class file fails to load on the secondary cluster members.

Note: For more information about this issue, refer to K10139: A configuration referencing a nonexistent external class file fails to load.

Note: Classes (Data Group Lists) can be configured to use data that is defined in an external file. This file may be located in the /var/class directory, the /config directory, or a subdirectory under the /config directory.

Note: This issue only affeccts systtems running on the VIPRION platform..

F5 tracked this issue as ID 207114 (formerly CR119471) and it was fixed in BIG-IP LTM version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by avoiding references to external class files located in subdirectories of the /config directory. External class files should instead be stored directly in the /config subdirectory or in the /var/class subdirectory.

Alternatively, you can manually create the specified subdirectory and copy the external class data files to the secondary cluster members before loading the configuration.
