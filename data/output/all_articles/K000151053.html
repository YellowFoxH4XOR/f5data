Description

 

When operating BIG-IP in Appliance Mode, replacing the device certificate via the GUI with a certificate that does not match the existing private key can result in loss of GUI access. Attempts to restart the httpd service via tmsh may produce errors about certificate/key mismatch, and the GUI will not start. Access to bash is unavailable in Appliance Mode, and standard CLI-based certificate recovery procedures that require file system access are not possible. The recommended steps below are useful specially if there are no known good UCS backups stored in the device.

 

Environment

  • BIG-IP
  • Appliance Mode

 

Cause

 

A new device certificate was imported via the GUI using the "certificate" option (not "certificate and key"), resulting in a mismatch between the certificate and the existing private key. This prevents the httpd service from starting, causing loss of GUI access.

 

Recommended Actions

 

To restore GUI access in Appliance Mode when a certificate/key mismatch prevents httpd from starting and only tmsh is available:

 

1.   Generate a new self-signed certificate and key pair using the gencert utility:

 

    (tmos)# gencert -p /config/httpd/conf/ -n recovery -k RSA 2048

 

   This creates a new certificate and key named "recovery" in /config/httpd/conf/ssl.crt/ and /config/httpd/conf/ssl.key/.

 

2.   Reconfigure httpd to use the newly generated certificate and key:

 

   (tmos)# modify sys httpd ssl-certfile /config/httpd/conf/ssl.crt/recovery ssl-certkeyfile /config/httpd/conf/ssl.key/recovery

 

3.   Save the config:

 

(tmos)# save sys config partitions all

 

4.   Restart the httpd service:

 

   (tmos)# restart sys service httpd

 

This should enable the user to regain GUI access and perform desired operations (eg. uploading and restoring latest UCS backup), etc.).
