Description

When BIG-IP APM is configured as an OIDC client with Microsoft Entra (formerly Azure AD) as the Identity Provider, generic memcache errors may appear in the APM logs during authentication. These errors occur when OIDC claims (such as group memberships or other attributes) sent by Microsoft Entra are excessively long and exceed internal buffer limits.

The following error messages may appear in /var/log/apm:

 

  • memcache.c func: "mc_rcv_set_cmd()" line: 3702 Msg: Error: Invalid response to set command: CLIENT_ERROR bad command line format
  • memcache.c func: "mc_rcv_set_cmd()" line: 3702 Msg: Error: Invalid response to set command: SERVER_ERROR invalid command
  • memcache.c func: "mc_finish_set_pipeline()" line: 735 Msg: Error: Set pipeline: While receiving response to <cmd_number> cmd set
  • memcache.c func: "mc_server_disconnect()" line: 2568 Msg: Error: bad memcache connection (tmm:X), (fd:XX)

These errors occur when APM attempts to store OIDC session variables (such as session.oauth.client.last.id_token.*) in memcache. Despite these errors, OAuth client authentication may succeed, but the session variable assignment fails due to claim size limitations.

Environment

  • BIG-IP APM configured as OIDC client
  • Microsoft Entra (Azure AD) as Identity Provider
  • Multiple applications protected by APM using OIDC authentication
  • Users with large OIDC claims (e.g., membership in many groups)

Cause

Unknown at time of publication.

Answer/Recommended Actions

  1. Verify that the issue is related to claim size by checking if affected users have unusually large OIDC claims (e.g., membership in many groups).
  2. Review Microsoft Entra configuration to determine if claims can be optimized:
    1. Microsoft Entra may limit the number of groups in a claim and provide a _claim_sources reference instead of including all groups directly in the token
    2. Consider filtering or reducing the number of claims sent in the OIDC token
  3. Upgrade to the latest maintenance release to ensure all relevant security and bug fixes are applied.

Additional Information

Current APM error messages for this scenario are generic and do not clearly indicate that the failure is due to claim length exceeding buffer limits. The OAuth client authentication may succeed (as indicated by log message 01490291:5: OAuth Client: succeeded), but subsequent memcache operations fail when storing session variables
