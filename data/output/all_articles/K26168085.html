Known Issue

Modifying a virtual server's route domain suffix may cause the secondary blades to restart.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is a multi-bladed VIPRION system.
  • You create a new partition, assign a new route domain to the new partition, and set this new route domain as the default route domain for the partition.
  • You modify the virtual server's route-domain suffix.

    For example, modify Source Address from 0.0.0.0/0 to 0.0.0.0%0/0 and Destination Address/Mask from 1.1.1.1 to 1.1.1.1%0

Impact

The VIPRION system temporarily fails to process traffic while the secondary blades restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Traffic processing may be disrupted temporarily on the affected VIPRION system.
  • The VIPRION system logs error messages to the /var/log/ltm file that appear similar to the following example:

    err mcpd[1255]: 0107004d:3: Virtual address (/test/1.1.1.1%0) encodes IP address (1.1.1.1) which differs from supplied IP address field (1.1.1.1%1)
