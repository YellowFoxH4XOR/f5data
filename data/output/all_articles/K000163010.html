K000163010: After Migration to Velos. F5 pool membres are down on the Trunk VLAN

Description

The BIG-IP tenant on the VELOS platform had pool members down on VLANs 1602 and 1603, and application traffic was not leaving the tenant because the VLANs were deployed without the expected VLAN tags. 

 

Environment

VELOS platform hosting a BIG-IP tenant

F5OS version 1.8.2

VLANs 1602 and 1603

BIG-IP tenant and partition configuration migrated from a previous platform

Multiple application pools affected

 

 

Cause

The tenant was assigned default VLAN tags 4080 and 4081 rather than the expected tags 1602 and 1603. This incorrect tenant VLAN mapping prevented traffic from leaving the tenant and caused the associated pool members to appear down. Correctly tagging and reassigning the VLANs to the tenant, followed by redeployment, resolved the issue. 

 

 

Answer/Recommended Actions

Ensure VLANs are created in the partition with the correct VLAN tags.

Confirm that the VLANs are assigned to the correct physical interface.

Before deployment, verify that the tenant displays the expected VLAN tags.

If VLAN assignments are incorrect:

Remove the tenant Self IPs and VLAN assignments.

Change the tenant to the Provisioned state.

Reassign the correctly tagged VLANs.

Deploy the tenant.

Validate Self IP connectivity and application traffic across VLANs 1602 and 1603.

Apply the same configuration validation and correction process to the remaining tenants affected by the migration.
