Known Issue

The Traffic Management Microkernel (TMM) process may restart when processing a CCA-T (Credit-Control-Answer Terminate) message.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is part of the device group for high availability.
  • A failover event occurs and the main BIG-IP PEM session moves to a new processing unit.
  • A RAR (Re-Authorization-Request) message from the Policy and Charging Rules Function (PCRF) system or the RADIUS accounting stop message marks the affected session for deletion.
  • The affected session is deleted before the Gx context moves to the new processing unit.
  • CCR-T (Credit-Control-Request Terminate) is sent out for the affected session.
  • The PCRF system sends the CCA-T message.

During a failover, the Gx context moves to the new processing unit when the session delete was initiated; therefore, the CCR-T processes on the new processing unit after the asynchronous lookup for the Gx context and frees the local message. When the BIG-IP system processes the CCA-T message, the main session is already deleted.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and failover may occur if you have configured the system as part of a high availability group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may generate a TMM core file to the /shared/core directory with a time stamp that correlates to the traffic interruption.
  • The BIG-IP system may unexpectedly fail over to another system in the device group.
