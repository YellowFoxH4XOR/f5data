Topic

The BIG-IP system provides a number of access control mechanisms to maintain secure access to the device, to ensure interoperability in a variety of environments with established requirements, and to assist in meeting industry standards, such as PCI compliance. These include a hierarchy of user accounts and access privileges, password enforcement options, and support for various authentication technologies.

System Accounts

The BIG-IP system includes two types of system accounts: system maintenance accounts and system user accounts. System maintenance accounts are predefined and have full access to all BIG-IP system maintenance interfaces, utilities, and functions. System user accounts are defined by a BIG-IP administrator and can be configured with more limited access to specific portions of the system, as needed, to suit their role.

System Maintenance Accounts

The BIG-IP system provides two default local accounts for system management and maintenance: the root user and the admin user. These users have full access to the system and can perform all administrative tasks. The root user has full access through the BIG-IP command-line interface, but not through the Configuration utility. The admin user has full access through the Configuration utility, but command-line access is disabled, by default. These accounts cannot be deleted, and their roles cannot be changed.

The admin user is maintained through the Configuration utility, on the Users page. The root user is maintained through the Configuration utility in the System menu, on the Platform page.

If a remote authentication method is specified for system user accounts, the BIG-IP local database still authenticates the system maintenance accounts mentioned above. This ensures that if the remote authentication device is unreachable, the system maintenance accounts can still access the BIG-IP system.

Note: For more information about system user accounts, refer to the following documentation:

  • BIG-IP 11.6.0 and later: The Introduction to User Account Management chapter of the BIG-IP System: User Account Administration manual
  • BIG-IP 11.4.0 through 11.5.4: The Users chapter of the BIG-IP TMOS: Concepts manual
  • BIG-IP 11.0.0 through 11.3.0: The BIG-IP User Accounts chapter of the BIG-IP TMOS: Concepts manual

    For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Important: In versions prior to BIG-IP 14.0.0, all BIG-IP products are installed with the same default passwords for the system maintenance accounts. F5 highly recommends that you change the passwords for the root, admin, and support accounts.

System User Accounts

You can create system user accounts to grant varying degrees of access to BIG-IP users. Access can be controlled by a combination of user roles and administrative partitions.

  • User roles control which actions a user can execute on the BIG-IP system, such as modifying another user's access privileges, writing and applying iRules, and enabling or disabling pool members.
  • Administrative partitions control the groups of objects to which a user can apply the actions allowed by their role.

This combination of roles and partitions allows certain users to perform a limited set of actions on a defined set of pools or virtual servers on the device, but not to all pools or virtual servers on the device, as needed.

Note: For more information about managing system user roles and partitions, refer to the following documentation:

  • The Administrative Partitions chapter of the BIG-IP System: User Account Administration manual (11.6.0 and later)
  • Working with Partitions and Working with Folders chapters in the BIG-IP TMOS: Concepts (11.0.0 through 11.5.4) manual

    For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

Local versus remote user management and authentication

The BIG-IP system supports both local and remote authentication schemas. You can configure only one user authentication scheme for the system. A BIG-IP administrator can use the Configuration utility or the TMOS Shell (tmsh) to create and delete BIG-IP user accounts, change passwords, and enforce a global password policy, which includes password strength, password aging, password re-use, allowed number of login failures, and other security settings. By contrast, when you use remote user accounts, the creation, management, and password policies for the system user accounts are maintained through a remote authentication server.

The BIG-IP system currently supports remote authentication through Active Directory or LDAP, RADIUS, and TACACS+. Using remote authentication methods allows the BIG-IP system to participate in a centrally located and managed access schema and use the password enforcement policies of the remote authentication server. However, if the remote authentication server experiences a failure, login attempts that use remotely authenticated system user accounts will fail, limiting access to system maintenance accounts that are locally authenticated.

Note: Beginning in BIG-IP 13.0.0, you can enable the Fallback to Local feature in the remote authentication settings to use local authentication when the remote authentication server is unreachable.

When using remote authentication, you must assign a BIG-IP-specific user role and administrative partitions to each remotely authenticated user account. To do this for an individual user, create a corresponding user name on the BIG-IP system, or for groups of users, use the remote-role component within the auth module of tmsh.
