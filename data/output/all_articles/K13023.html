Known Issue

The BIG-IP ASM Configuration utility may incorrectly prevent users from editing a security policy when another user is logged into the system.

This issue occurs when either of the following pairs of conditions are met:

BIG-IP ASM with a single web application

  • A user logs into the Configuration utility and accesses the Overview page under the Application Security menu
  • A second user logs into the Configuration utility and attempts to access the active security policy or any of the policy object menus under Application Security menu

BIG-IP ASM with multiple web applications

  • A user logs into the Configuration utility and accesses the Overview page under the Application Security menu
  • A second user logs into the Configuration utility and attempts to access the most recently activated security policy, or any of that policy's object menus, for the oldest web application on the system

Under normal operation, if a user edits a security policy, the BIG-IP ASM system will lock that policy to prevent a second user from editing it simultaneously. In the case of this known issue, the BIG-IP ASM system incorrectly considers a user as logged into the policy when the user is not actively editing the policy, and may not have clicked on any of the available policy or web application menus before navigating directly to the Overview page. In both pairs of conditions described above, the BIG-IP ASM system will lock the second user out of editing the policy, and the second user will experience the symptoms described below.

Impact

Users may be unable to make changes to policies and policy objects.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Messages that appear similar to the following example will display in the Configuration utility of the second user, where PolicyName is the name of the locked policy, and UserName is the name of the system user locking the policy:

    Policy Locked
    The security policy «PolicyName» is currently being used by the user «UserName»

  • When logged into the Configuration utility, buttons used to make changes to the policy or policy objects such as Update, Delete, Create, or Apply will be disabled for the second user.
