K4040: The vlans unique_mac global variable may not work when VLANs contain the same tagged interface

Known Issue

This is the result of a known issue. When the vlans unique_mac global variable is enabled, BIG-IP uses the MAC address of the first interface that is configured in the VLAN as the MAC address for the VLAN. However, the order in which interfaces are listed under VLANs in the bigip.conf file is not the same order in which BIG-IP evaluates the interfaces.

The BIG-IP system always evaluates tagged interfaces first. As a result, if multiple VLANs contain the same tagged interface, all of the VLANs may use the MAC address for that interface.

F5 Networks Product Development tracked this issue as CR32791.

Workaround

To work around this issue, add an unused interface to the VLAN and enable VLAN tagging, or configure MAC masquerading for the VLAN.
