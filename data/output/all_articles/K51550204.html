K51550204: AWS instance INOPERATIVE after upgrade, unable to license the system

Published

Source

Description
After upgrading an AWS instance, the command prompt indicates that the system is in INOPERATIVE state. You see error messages similar to the following in /var/log/ltm which indicate that the instance cannot be licensed because there is no route to the AWS metadata server endpoint at 169.254.169.254.

01170003:3: halGetDossier returned error (7): Dossier generation failed.

info plymouthd: .... - url_helper.py[WARNING]: Calling 'http://169.254.169.254/2009-04-04/meta-data/instance-id' failed [1/120s]: request error [HTTPConnectionPool(host='169.254.169.254', port=80): Max retries exceeded with url: /2009-04-04/meta-data/instance-id (Caused by <class 'socket.error'>: [Errno 113] No route to host)]

Messages similar to the following appear in /var/log/kern.log

err kernel: kernel: [   47.261935] VF could not set VLAN 1
err kernel: kernel: [   47.269080] ixgbevf 0000:00:03.0 eth0: failed to initialize vlan filtering on this port


You may see that the eth0 and mgmt interface MAC addresses are not the same in /var/log/boot.log

info plymouthd: ci-info: ++++++++++++++++++++++++++++Net device info++++++++++++++++++++++++++++

Environment

  • BIG-IP instance in AWS cloud
  • Version prior to 13.1.3.4
  • The virtual instance has a route to 169.254.169.254

Cause
ID 747099

Recommended Actions
Upgrade to BIG-IP version 13.1.3.4 or later

Additional Information
The expected mgmt route can be shown with the following command:
ip route get 169.254.169.254

The mgmt and eth0 MAC addresses can be shown with:
ifconfig -a
