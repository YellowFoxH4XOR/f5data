K000134772: TLS handshake failure in response to ClientHello initiated from istio-proxy (client) to server (java18 application): Illegal server name

Description

SNI is set automatically by Aspen Mesh to outbound_.8080_._.example.com causing TLS negotiation to fail.
Server running an application written in JAVA shows the following

javax.net.ssl|ERROR|D8|2023-05-24 09:47:25.913 CDT|TransportContext.java:363|Fatal (ILLEGAL_PARAMETER): Illegal server name, type=host_name(0), name=outbound_.8080_._.example.com, value={6F7574626F756E645F2E383038305F2E5F2E64616C6C61732D736370312D6970322E3567632E767A696D73746573742E636F6D} (

"throwable" : {

 javax.net.ssl.SSLProtocolException: Illegal server name, type=host_name(0), name=outbound_.8080_._.example.com


Istio-proxy container logs return a 503 HTTP status code and TLS errors

[2023-05-24T14:47:25.900Z] "GET /path/ HTTP/2" 503 UF,URX upstream_reset_before_response_started{connection_failure,TLS_error:_268436503:SSL_routines:OPENSSL_internal:SSLV3_ALERT_ILLEGAL_PARAMETER} - "TLS error: 268436503:SSL routines:OPENSSL_internal:SSLV3_ALERT_ILLEGAL_PARAMETER" 0 199 84 - "-" "-" "e9181af5-ac3a-4a33-80c9-ffbb6975ae84" "10.10.0.2:8080" "10.10.0.2:8080" outbound|8080||example.com - 10.10.0.2:8080 10.131.14.183:64998 - default


Environment

Aspen Mesh 1.x
 

Cause

DestinationRule used to route this traffic does not have SNI configuration set causing Aspen Mesh to use the default behavior.

apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: no-sni
  namespace: default
spec:
  host: example.com
  trafficPolicy:
    tls:
      mode: ISTIO_MUTUAL

 

Recommended Actions

Create/Update the DestinationRule to use the SNI expected by the server.
The below DR can be used as example:

apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: dr-sni
  namespace: default
spec:
  host: example.com
  exportTo:
  - "."
  trafficPolicy:
    tls:
      mode: ISTIO_MUTUAL
      sni: example.com

 

Additional Information

You can confirm the Destination Rule being used and SNI that will be presented by running these commands

istioctl pc c podname -n namespace --fqdn example.com

SERVICE FQDN                     PORT     SUBSET     DIRECTION     TYPE             DESTINATION RULE
example.com                      8080     -          outbound      ORIGINAL_DST     dr-name.ns-name

The DR used in the output above is dr-name.ns-name
