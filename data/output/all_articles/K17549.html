Known Issue

Reconfiguring certain iApps may cause the mcpd processes to restart on secondary blades.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system runs on a VIPRION platform configured with one or more secondary blades.
  • You have an existing iApp.
  • You attempt to perform one of the following actions:

    • You modify the iApp
    • You redeploy the iApp which results in the creation of a virtual server.

Impact

The secondary blades are temporarily unavailable for traffic processing while the affected services restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The mcpd process restarts on every secondary blade, causing other system services to restart.
  • When you redeploy the iApp, the BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example:

    01070734:3: Configuration error: Configuration from primary failed validation: 01020036:3: The requested virtual server (/Common/iapp.app/virtualserver) was not found.... failed validation with error 16908342.

  • When you modify the iApp, the BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example:

    01020036:3: The requested customization_group <object_name> was not found.

  • The BIG-IP system logs Master Control Program Daemon (MCPD) messages to the /var/log/ltm file that appear similar to the following example:

    013a0004:3: IO error on recv from mcpd - connection lost
    0153e0f7:3: Lost connection to mcpd.
    01100042:3: Failed with MCPD at: MCP msg receive (16908291).
    014e0006:3: MCP Failure: 1.
