Known Issue

The BIG-IP system may erroneously send an Internet Control Message Protocol (ICMP) "unreachable" network packet from a loopback IP address (for example, 127.1.1.4) to a client.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a Virtual Local Area Network (VLAN) group.
  • The VLAN group does not have a self IP address configured.
  • A virtual server is configured to listen on the VLAN group.
  • The client initiates traffic to the destination through the virtual server.

Impact

Network traffic destined for the virtual server may be rejected.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When reviewing the network packet capture, you notice that your BIG-IP system responds to the client with an ICMP "unreachable" network packet from a loopback IP address.

    The network packet capture output may appear similar to the following example:

    22:45:45.136241 IP 192.168.10.18.54005 > 192.168.10.12.http: Flags [S], seq 3359287833, win 14600, options [mss 1460,sackOK,TS val 3052089143 ecr 0,nop,wscale 7], length 0 in slot1/tmm1 lis=
    22:45:45.136285 IP 127.1.1.4 > 192.168.10.18: ICMP net 192.168.10.12 unreachable, length 36 out slot1/tmm1 lis=
    22:45:45.136291 IP 192.168.10.12.http > 192.168.10.18.54005: Flags [R.], seq 0, ack 3359287834, win 0, length 0 out slot1/tmm1 lis=/Common/vs1

Workaround

To work around this issue, you should assign a valid self IP address to the VLAN group. For more information, refer to the Self IP Addresses chapter of the BIG-IP TMOS: Routing Administration guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system. However, F5 recommends that you evaluate the impact of assigning a self IP address to your application environment.
