Known Issue

Support for long VLAN names introduced a subtle buffer overflow in the nsm process. As a result, the following issues have been observed:

  • If two or more VLANs are configured with exactly 14 character names, nsm will crash and tmrouted will start repeatedly
  • If a single VLAN with a 14 character name is configured, the VLAN is created as a pseudo-interface by ZebOS, and routing protocols may not operate correctly
  • If a VLAN is configured with a 15 character name, and its interface index (ifindex) is greater than 255, the ifindex is corrupted
  • If a VLAN is configured with a 15 character name, and its ifindex is exactly 256, nsm will crash and tmrouted will start repeatedly

Symptoms of this issue are the failure of configured dynamic routing, and multiple messages logged to the console and to the /var/log/user.log file that appear similar to the following example:

Dec 12 13:50:44 5100r64b LOGIN: Re-starting tmrouted

In addition, the bigstart status tmrouted command output will indicate excessive restarts that appear similar to the following example:

tmrouted run (pid 32177) 1 minutes, 1 starts, 42 restarts

F5 Product Development tracked this issue as CR110829 and it was fixed in BIG-IP 9.4.7 and 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator Release Notes.

Workaround

You can work around this issue and avoid the above configurations by reconfiguring VLANs to use longer or shorter names as required.
