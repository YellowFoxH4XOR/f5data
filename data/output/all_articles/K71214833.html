Description

On rare occasions, it may be helpful to enable additional debugging for ASM's pabnagd process.

Note: This article applies to BIG-IP ASM systems running 15.x and later.  For 14.x and later systems, use the procedure of K13653022: Enabling pabnagd debugging in 14.x and earlier.

Environment

  • ASM provisioned

Cause

Not applicable.

Recommended Actions

Note: The extra logging can cause some additional load (particularly I/O load) on the unit.

Enabling pabnagd debugging
  1. Raise Policy Builder debug level:
    sed -i "/config\|pbngmodel\|parameter\|suggestion/ s,INFO,TRACE," /etc/ts/pabnagd/logging.json
    sed -i "/account\|policy\|trafficevt/ s,INFO,DEBUG," /etc/ts/pabnagd/logging.json
  2. Raise ASM CP debug level:
    for db in `tmsh list sys db log.asm* one-line | cut -f3 -d' '`; do tmsh modify sys db ${db} value trace; done
  3. Restart pabnagd:
    killall -s SIGHUP pabnagd
  4. Restart ASM - Note: this will cause a brief outage as the device goes offline for about 5-10 minutes while ASM restarts:
    bigstart restart asm
    Wait until the GUI reports the device is back in an Online [Active or Standby] state before proceeding.
  5. Generate some traffic and confirm that there are still no learning suggestions.
  6. Generate and upload a qkview.
Disabling pabnagd debugging
  1. Lower PB debug level back:
    sed -i "/config\|pbngmodel\|parameter\|suggestion/ s,TRACE,INFO," /etc/ts/pabnagd/logging.json
    sed -i "/account\|policy\|trafficevt/ s,DEBUG,INFO," /etc/ts/pabnagd/logging.json
  2. Lower ASM CP debug level:
    for db in `tmsh list sys db log.asm* one-line | cut -f3 -d' '`; do tmsh modify sys db ${db} reset-to-default; done
  3. Restart ASM - Note: this will cause a brief outage as the device goes offline for about 5-10 minutes while ASM restarts:
    bigstart restart asm

Additional Information

When using the reset-to-default option with the "tmsh modify sys db log.asm.pabnagd.level" command, the pabnagd daemon has to be restarted (implied by the "bigstart restart asm").
