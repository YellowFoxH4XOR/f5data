Description

This article describes an issue when the connection between client and server is failing. You are seeing in the packet capture "TCP Retransmission TCP Port numbers reused" and RST from F5 to Client "TCP retransmit timeout"

Example connection between:
10.1.1.1 - client
10.2.2.2 - virtual server on BIG-IP
10.3.3.3 - pool member

=== client side ===

12:57:03,427198  10.2.2.2    10.1.1.1   OUT  s1/tmm0 : 25 → 62789 [SYN, ACK]
12:57:03,427500  10.1.1.1    10.2.2.2   IN   s1/tmm0 : 62789 → 25 [ACK] 

=== server side ===
12:57:03,427533  10.1.1.1    10.3.3.3   OUT  s1/tmm0 : 62789 → 2535 [SYN] 
12:57:04,427089  10.1.1.1    10.3.3.3   OUT  s1/tmm0 : [TCP Retransmission] [TCP Port numbers reused] 62789 → 2535 [SYN] 
12:57:05,427289  10.1.1.1    10.3.3.3   OUT  s1/tmm0 : [TCP Retransmission] [TCP Port numbers reused] 62789 → 2535 [SYN] 
12:57:06,427180  10.1.1.1    10.3.3.3   OUT  s1/tmm0 : [TCP Retransmission] [TCP Port numbers reused] 62789 → 2535 [SYN] 

=== client side ===
12:57:07,427197  10.2.2.2    10.1.1.1   OUT  s1/tmm0 : 25 → 62789 [RST, ACK] [F5RST(peer): TCP retransmit timeout]

=== server side ===
12:57:07,427207  10.1.1.1    10.3.3.3   OUT  s1/tmm0 : 62789 → 2535 [RST, ACK] [F5RST: TCP retransmit timeout] 
 

Environment

  • BIG-IP
  • virtual server

Cause

The pool member is not answering SYN packet, even after retransmitting the SYN Packet again (using same port number again, as it should -62789)

Recommended Actions

In most cases the issue is with a Pool member.
In rare cases it can be related to something blocks traffic.

Adding SNAT to the affected virtual server will extend the spectrum of available sockets and will fix the problem. For information about SNAT, refer to K7820: Overview of SNAT features.
