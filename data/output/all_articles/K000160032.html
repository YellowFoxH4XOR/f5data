K000160032: Retrieving Site Resource Utilization Metrics via F5 Distributed Cloud API

Description

When attempting to retrieve site resource utilization metrics (such as CPU, memory, and disk usage) using the F5 Distributed Cloud ves.io.schema.graph.connectivity API endpoint, users may find that only a subset of requested metrics are returned. Specifically, when requesting multiple metric instances including NODE_INSTANCE_CPU_USAGE, NODE_INSTANCE_MEMORY_USAGE, and NODE_INSTANCE_DISK_USAGE, the API response may only include NODE_INSTANCE_STATUS, NODE_INSTANCE_MEMORY_USAGE, and NODE_INSTANCE_DISK_USAGE, with CPU metrics missing from the results.

This occurs when using the graph connectivity API with a POST request to query node metrics across multiple sites or nodes.

Environment

  • F5 Distributed Cloud (SaaS)
  • API endpoint: ves.io.schema.graph.connectivity
  • Authorization: APIToken with appropriate permissions

Cause

The F5 Distributed Cloud API design pattern intentionally limits LIST operations (such as graph connectivity queries) to return summary information only. The ves.io.schema.graph.connectivity API endpoint is designed for querying connectivity and status information across multiple nodes, and does not return full detailed metrics for all requested metric types. Full metric details, including comprehensive CPU utilization data, are only available through individual GET operations on site-specific endpoints.

Answer/Recommended Actions

To retrieve complete site resource utilization metrics including CPU usage:

  1. Use site-specific API endpoints to retrieve detailed metrics for individual sites:
    • Query each site individually using the appropriate site-specific endpoint
    • This approach provides access to all available metrics including CPU utilization
  1. Implement a two-step approach for bulk metric collection:
    • Step 1: Use the ves.io.schema.graph.connectivity API to obtain a list of site names or node identifiers
    • Step 2: Query each site individually using site-specific endpoints to retrieve full metrics
  1. Alternative query methods:
    • Use query parameters such as ?report_fields or ?report_status_fields with LIST operations to obtain additional summary fields
    • Note that full detailed metrics are only available via individual GET requests to site-specific endpoints
  1. For troubleshooting missing metrics, verify:
    • Node health status
    • Metric collection services are running properly
    • Network connectivity to identityauthority.ves.volterra.io (required for metric collection)

Additional Information

  • This API behavior is intentional and designed for performance and scalability across distributed cloud environments
  • No additional configuration or permissions are required to access CPU metrics when using the correct endpoint
  • The graph connectivity API is optimized for querying relationships and status across multiple nodes, not for detailed metric retrieval
  • If metrics are missing even from site-specific endpoints, verify that the site's metric collection services are functioning correctly
  • Ensure that firewall rules allow access to identityauthority.ves.volterra.io and its resolved IP addresses, as this is required for proper metric collection
