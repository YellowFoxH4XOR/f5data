Known Issue

Domain Name System Security Extensions (DNSSEC) keys may not synchronize to group members.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP GTM system is configured as a member of a synchronization group.
  • The BIG-IP GTM configuration interacts with a Thales nShield Connect device.
  • The Thales nShield Connect architecture includes the Remote File System (RFS) feature.
  • A DNSSEC key is created by any member of the system's synchronization group.

Impact

The DNSSEC key is not synchronized to other members of the synchronization group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you create a zone-signing key, the key is synchronized with the synchronization group members.
  • When you create a key-signing key, the key is not synchronized with the synchronization group members.
  • When you view the /shared/nfast/log/rfs-sync.log file for RFS synchronization, you notice that synchronization was not triggered when the key-signing key was created.

Workaround

To work around this issue, you can trigger a synchronization of the DNS configuration and DNSSEC keys by creating a bogus data center. To do so, perform the following procedure:

Impact of workaround: This procedure triggers a synchronization of the local device DNS configuration to all synchronization group members.

  1. Log in to the Configuration utility.
  2. Navigate to DNS > GSLB > Data Center List.
  3. Click Create.
  4. In the Name box, type the name of the bogus data center.
  5. Click Finished.
  6. To remove the bogus data center, navigate to DNS > GSLB > Data Center List.
  7. To the left of the bogus data center name, select the check box.
  8. Click Delete.
  9. To confirm, click Delete again.
