K20711770: BIG-IQ CM GUI shows error ''Waiting for BIG-IQ services to become available'' during large LTM configurations import

Type
Support Solution
Published
2022-06-08
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K20711770

Description
BIG-IQ CM GUI shows error "Waiting for BIG-IQ services to become available" when attempt to import large LTM configurations from managed BIG-IPs.

The GUI may recovered by itself. You may find the daemon restjavad was restarted:

# tmsh show sys service | grep restjavad

You may also find kernel error message similar to "Out of memory: Kill process <pid>  (java) score <score> or sacrifice child" in log file /var/log/kern.log

Jun  9 12:48:58 bigiqtest1 err kernel: : [830454.422488] Out of memory: Kill process 32567 (java) score 560 or sacrifice child
Jun  9 12:48:58 bigiqtest1 err kernel: : [830454.518035] Out of memory: Kill process 32567 (java) score 562 or sacrifice child

Environment

  • BIG-IQ CM Virtual Edition provisioned with 32GB RAM or less
  • Attempt to import large LTM configurations from managed BIG-IPs

Cause
According to BIG-IQ Virtual Edition document (Manual Chapter : Getting Started with BIG-IQ Virtual Edition), a BIG-IQ CM instance needs 64GB or more RAM when it manages 80 or more BIG-IP devices with LTM (ADC) modules discovered and imported to the BIG-IQ.

But this is a rough approximation. Depending on the size of configuration objects on each BIG-IP device, the RAM requirement may increase even when the number of managed BIG-IP devices is below the suggested limit.

You can review the number of the discovered LTM configuration objects using the following commands on the BIG-IQ CM:

# psql -U postgres bigiq_db -c "select count(*) from bigiqworkingconfig.adc_core_wc_ltm_virtual;"
# psql -U postgres bigiq_db -c "select count(*) from bigiqworkingconfig.adc_core_wc_ltm_pool;"
# psql -U postgres bigiq_db -c "select count(*) from bigiqworkingconfig.adc_core_wc_ltm_pool_members;"
# psql -U postgres bigiq_db -c "select count(*) from bigiqworkingconfig.adc_core_wc_ltm_node;"

Recommended Actions

  1. Consider increasing BIG-IQ CM RAM size to 64GB if you failed to import more than 1,000 LTM configuration objects into the BIG-IQ, and you found restjavad or other BIG-IQ daemons were restarted due to "Out of memory" error during the import.
