Topic

This article applies to BIG-IP 13.x through 17.x. For information about other versions, refer to the following article:

  • K03546096: Configuring local authentication as a backup method for remote RADIUS authentication (12.1.x)

You should consider using these procedures under the following conditions:

  • You use remote authentication for users managing the BIG-IP system, and you want to configure local authentication as a backup method when remote authentication fails.
  • You want to configure remote authentication for the default BIG-IP root and administrative users.

Description

By default, if you configure a remote authentication method, such as RADIUS or TACACS authentication for BIG-IP administrative users or for application traffic and the remote authentication server is unavailable to answer authentication requests, remote authenticated users cannot log in, even when their accounts are configured in the local authentication list. Only the default admin and root accounts, can log in to the system. Starting in BIG-IP 13.0.0, the BIG-IP system attempts to authenticate all users using the configured remote authentication server. You can observe the following behaviors, based on the ability to interact with the remote authentication server:

  • When the remote authentication server accepts the authentication request and the user is authenticated, the system allows access.
  • When the remote authentication server rejects an authentication request, the system denies access.
  • When the remote authentication server is unavailable, the BIG-IP system either denies access for or falls back to local authentication when the user is configured on the local BIG-IP device.

If you use remote authentication, you can perform the following actions:

  • Configure local authentication as a backup method when the remote authentication server is unavailable to answer authentication requests.
  • Configure the default BIG-IP root and admin accounts to use local authentication with the systemauth.nolocalonly database key.

BIG-IP 12.1.0 (for RADIUS only) and BIG-IP 13.0.0 (all remote authentication methods) introduced the systemauth.nolocalonly database variable key, and supports the following options:

  • true

    If this database key is set to true, the root and admin accounts use remote authentication.

  • false

    If this database key is set to false (default), the root and admin accounts use local authentication at all times.

Note: In BIG-IP 12.1.0, this database key is only available for RADIUS remote authentication.

Note: In BIG-IP 13.x and later, this database key is available for all remote authentication.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the BIG-IP system.
  • You can access the TMOS Shell (tmsh).

Procedures

  • Configure local authentication as a backup method when the remote authentication server is unavailable
  • Configure the default BIG-IP root and admin accounts to use remote authentication

Note: To determine if a user login was authenticated locally or remotely, or if fallback to local authentication has occurred, observe the /var/log/secure log file.

Configure local authentication as a backup method when the remote authentication server is unavailable

To configure local authentication as a backup method for remotely stored user accounts in the event that remote authentication server is unavailable, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Verify that the User Directory values specifies a remote authentication method, such as LDAP.
  4. Select the Fallback to Local check box.
  5. Select Update.

The system now uses local authentication for remote authenticated-users as a backup method when the remote authentication server is unavailable. The default BIG-IP root and admin accounts use local authentication.

Configure the default BIG-IP root and admin accounts to use remote authentication

First, enable authentication to fall back to local authentication when the remote server is down using the Configuration utility. Second, configure the root and admin accounts to use remote authentication by setting the systemauth.nolocalonly database key to true. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Enable authentication to fall back to local by performing the previous Configure local authentication as a backup method when the remote authentication server is unavailable procedure.

    Note: Setting the systemauth.nolocalonly database key to true without fallback to local authentication enabled may lock out the root and admin accounts.

  2. Log in to tmsh by entering the following command:

    tmsh

  3. Set the systemauth.nolocalonly database key to true by entering the following command:

    modify /sys db systemauth.nolocalonly value true

All users that log in to the BIG-IP system, including the root and admin accounts, now use remote authentication and fall back to local authentication when the remote server is unavailable.

Note: To revert to the default setting and configure the root and admin accounts to use local authentication, you can use the tmsh modify /sys db systemauth.nolocalonly value false command.
