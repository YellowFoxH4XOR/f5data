Mass assignment

API endpoints that take in client input and bind them to code variables or internal object properties without proper filtering can result in mass assignment vulnerabilities. This allows users to change or overwrite object properties that they are not supposed to. Depending on the application logic and API design, these illegal inputs can be sent from the client within the API URL paths, HTTP headers, or in the HTTP body itself in different formats (for example, JavaScript Object Notation [JSON]), and so on. APIs are more susceptible to this vulnerability than web applications are, as they expose their underlying implementation along with property names by design.

Attackers can exploit this vulnerability to illegally modify object properties with object injection, resulting in data tampering, security mechanism bypass, and in some cases, privilege escalation. 

Mass assignment weakness enumeration (CWE)

The following common weakness may increase the likelihood of attacks against your APIs:

  • CWE-915: Improperly Controlled Modification of Dynamically-Determined Object Attributes

Mass assignment attack scenario

In the following scenario, an attacker manipulates the JSON content of the API request to add more parameters to their user object to escalate their privileges.

  1. An attacker sends a legitimate API request to update their contact details.
  2. The attacker adds the user.admin, user.role parameters to the JSON user object in the API request. 

These additional parameters escalate their privileges to an Administrator, and they expand their attack to perform actions in the application as an Administrator.

Secure your APIs against mass assignment attacks with F5 products

To protect your APIs, best practices recommend that you define a clear and comprehensive allow/deny list of all parameters, objects and properties and examine and validate all client inputs against the list to ensure all client requests conform to your application schema.
