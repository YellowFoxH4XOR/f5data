K40222952: Add blade to existing vcmp guest results in missing software issue

Type
Support Solution
Published
2020-10-16
Updated
2023-02-21
Applies to
  • VIPRION Platforms
Source
https://my.f5.com/manage/s/article/K40222952

Description
When expanding an existing vCMP guest on a Viprion system to use an additional blade one may get an error related to software missing on the new blade.

Environment

  • Viprion
  • vCMP
  • BIG-IP

Cause

Needed software .iso file is missing on the added blade.

Recommended Actions

  1.  On the vCMP host, move the VCMP guest status from deployed to configured state.
  2.  Add the new slot to the VCMP guest from the available list of slots.
  3.  Move the guest to provisioned state first and then to deployed state.
  4.  Once the guest is deployed, the new slot will be offline and the output of show sys software indicate that it was waiting for software image(s)
  5.  Execute the command for rsync to copy needed images to the new slot.
    Example:
    rsync -avpP /shared/images/BIGIP-11.6.5.2-0.0.10.iso  slot2:/shared/images/
  6.  Once the image(s) are copied, then do another reboot of the vCMP guest by moving from deployed state to provisioned state and back.
  7.  After the images were available, the new slot will reboot one or more times to be in Quorum with the other slots.
  8.  After the reboot, all the blades should be in cluster.

    If this is a High Availability group of guests, the procedure may need to be performed on the peer systems.
