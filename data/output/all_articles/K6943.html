K6943: The BIG-IP GTM system no longer loads BIND files containing syntax errors into memory following a synchronization with another BIG-IP GTM system

Issue

The BIG-IP GTM Synchronize DNS Zone Files setting allows the BIG-IP GTM system to synchronize DNS files among the members of a BIG-IP GTM synchronization group. With Synchronize DNS Zone Files enabled, the BIG-IP GTM system will synchronize changes made to the named.conf file, or DNS zone files to other BIG-IP GTM devices in the synchronization group.

Prior to BIG-IP GTM 9.3.0 and 9.4.0, if the Synchronize DNS Zone Files setting is enabled, and a user manually edits a DNS configuration file resulting in a syntax error, the DNS file will be synchronized to other members of the synchronization group, and the file will be loaded into memory on the receiving BIG-IP GTM systems.

For example, if a user manually edits the /var/named/config/named.conf file on a BIG-IP GTM system that is a member of a synchronization group, and the edit results in a syntax error, the named.conf file containing the syntax error will be synchronized to other members of the BIG-IP GTM synchronization group, and the receiving BIG-IP GTM systems will load the file into memory. This will result in the ZoneRunner process continually restarting on the receiving BIG-IP GTM system while it attempts to parse and load the named.conf file to memory.

In this case, the following error message will be logged in the /shared/log/gtm file on the BIG-IP GTM devices receiving the named.conf file with the incorrect syntax:

zrd: 01150205:3: Unable to parse named.conf file

Beginning with BIG-IP 9.3.0 and 9.4.0, the BIG-IP GTM system no longer loads BIND configuration files containing syntax errors into memory following a synchronization with another BIG-IP GTM system.

For information about manually editing the BIG-IP GTM system's DNS files, refer to K6963: Managing the BIG-IP BIND configuration files.
