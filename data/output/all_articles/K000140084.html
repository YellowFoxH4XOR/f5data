K000140084: After upgrading the http "discarded" metric is increasing

Type
Support Solution
Published
2024-06-21
Updated
2024-06-21
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 3.5.X, 3.4.0, 3.4.1, 3.4.2, 3.5.0, 3.5.1, 3.5.2, 3.4.X
Source
https://my.f5.com/manage/s/article/K000140084

Description

After upgrading NGINX Ingress Controller from <=3.3.2 to >=3.4.0 the "discarded" metric from api module's endpoint /api/(version)/http/server_zones increases.

For example:

$ curl cafe.example.com:9113/metrics 2> /dev/null | egrep 'nginx_ingress_nginxplus_server_zone_discarded{'
nginx_ingress_nginxplus_server_zone_discarded{class="nginx",resource_name="cafe",resource_namespace="helm-app",resource_type="virtualserver",server_zone="cafe.example.com"} 1828

Environment

NGINX Ingress Controller

Prometheus metrics enabled

Dynamic ssl reloading enabled

Cause

Starting in NGINX Ingress Controller 3.4.0 dynamic ssl certificates (reloading) feature is implemented by default. Essentially NGINX Ingress Controller implements a variable path for ssl certificate directives. 

For example:

map $nginx_version $secret_dir_path {
    default "/etc/nginx/secrets";
}
...
ssl_certificate $secret_dir_path/helm-app-cafe-secret;
ssl_certificate_key $secret_dir_path/helm-app-cafe-secret;

NGINX request processing of these variable values is what causes the "discarded" metric to increase. See Support Solution K000140044 for more information on this behavior: https://my.f5.com/manage/s/article/K000140044 

Recommended Actions

Disable dynamic ssl reload - https://docs.nginx.com/nginx-ingress-controller/configuration/global-configuration/command-line-arguments/#-ssl-dynamic-reload

Additional Information

Release note reporting implementation of dynamic ssl certificate: https://docs.nginx.com/nginx-ingress-controller/releases/#340
