Description

The User Datagram Protocol (UDP) event commands allow administrators to write iRules that control how UDP is handled or directed, based on parameters specified by the administrator.

The UDP CLIENT_DATA event does not behave like its TCP CLIENT_DATA event counterpart when used for making load-balancing decisions.

The UDP CLIENT_DATA event, when used in conjuction with pool and/or node commands, behaves differently than the TCP CLIENT_DATA event. The load-balancing decision is already made prior to the CLIENT_DATA event firing.

For example, consider the following iRule:

when CLIENT_DATA {
  if { [UDP::payload 50] contains "XYZ" } {
   pool xyz_servers
   persist uie "[IP::client_addr]:[UDP::client_port]" 300
  }
}

The example iRule specifies that it should collect and look at the first 50 bytes of the UDP payload for XYZ, direct the traffic to xyz_servers, and create a persistence entry for the specific client address and port.

The UDP event CLIENT_DATA operates differently than its TCP counterpart. The event appears to not work properly because data collection occurs after making a load-balancing decision.

When using UDP iRules to make load-balancing decisions, F5 recommends using the CLIENT_ACCEPTED event.
