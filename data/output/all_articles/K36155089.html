Known Issue

A FastL4 virtual server may not honor the TCP Handshake Timeout setting for hardware-accelerated flows.

This issue occurs when all of the following conditions are met:

  • A FastL4 profile with the following configuration is associated with a BIG-IP virtual server:
    • The PVA Acceleration option is set to Full.
    • The Offload State option is set to SYN in the Configuration utility, or embryonic in the TMOS Shell (tmsh).

    Note: These are the default values for the specified options.

  • The FastL4 virtual server offloads a TCP flow for hardware acceleration.

When a virtual server is configured as previously specified, the connection idle timeout during the TCP handshake is erroneously set to the Idle Timeout value for the FastL4 profile instead of for the TCP Handshake Timeout.

Impact

The TCP connection may remain in the half-open state longer than the time that is set in the TCP handshake timeout value.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Connections may appear in the connection table for longer than you expect.

Workaround

To work around this issue, you can set the Offload State to established in the affected FastL4 profile. To do so, perform one of the following procedures:

  • Using the Configuration utility to set the FastL4 Offload State to established
  • Using tmsh to set the FastL4 Offload State to established

Using the Configuration utility to set the FastL4 Offload State to established

Impact of workaround: The FastL4 profile's Offload State determines the TCP state at which the ePVA begins to process the connection. Setting this value to established causes the system to wait for the client TCP ACK before performing the hardware offload.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Protocol > FastL4.
  3. Select the affected FastL4 profile.
  4. Under Settings, for Offload State, select EST.
  5. Select Update.

Using tmsh to set the FastL4 Offload State to established

Impact of workaround: The FastL4 profile's Offload State determines the TCP state at which the ePVA begins to process the connection. Setting this value to established causes the system to wait for the client TCP ACK before performing the hardware offload.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To modify the Offload State of the affected FastL4 profile, use the following command syntax:

    modify /ltm profile fastl4 <name of FastL4 profile> pva-offload-state establish

    For example, to modify the Offload State for a profile named fastl4_example, enter the following command:

    modify /ltm profile fastl4 fastl4_example pva-offload-state establish

  3. To save the configuration, enter the following command:

    save /sys config
