Known Issue

This is the result of a known issue. If a Linux client accesses a CIFS share using CIFS VFS and attempts to copy a file to a CIFS share, and the destination file name already exists in the destination path, the copy fails with a permission denied error message. The correct behavior is for the ARX system to replace the existing file with the new file if the user account has sufficient privileges to overwrite the file.

Note: For information about CIFS VFS, refer to the following link, which will take you to a resource outside of AskF5. It is possible that the document may be removed without our knowledge:

http://linux-cifs.samba.org

F5 Product Development tracked this issue as ID 37229, and it was fixed in ARX 5.1.5. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in a hotfix available for ARX 5.0.6 and 5.1.0. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 37229.

Workaround

Users can work around this issue by accessing CIFS shares using smbfs instead of CIFS VFS. As an alternative, users can work around this issue by renaming or deleting the existing file before copying the new file with the same file name.
