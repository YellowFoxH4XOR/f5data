Description

High CPU and performance issues with IPsec

Environment

  • BIG-IP terminating IPsec

  • Small number of security associations (SAs) compared with number of tmm's
  • High traffic volumes

Cause

Traffic for each SA is handled by one tmm. Traffic will be received by a tmm as a result of disaggregation (DAG). If this traffic is then to be handled by IPsec, it will then be forwarded from the receiving tmm to the tmm owning the relevant SA. Having a large volume of traffic on a single SA will result in a single tmm handling most of the load.

Recommended Actions

Increase the number of SAs and configure such that traffic is balanced across SAs (tmms).

In tunnel mode this can be accomplished by splitting the traffic-selectors (TS) into smaller subnets. If necessary, increase the permitted number of TS per peer. 

In interface mode, increase the number of tunnels by adding more self-ips and using dynamic or static routing the control the balance of traffic per tunnel.

In either mode, benefit may be gathered from implementing dynamic load balancing of IPsec SAs.
