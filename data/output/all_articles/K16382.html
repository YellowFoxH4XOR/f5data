Known Issue

Configuration load may trigger the apd service to produce a core file.

This issue occurs when all of the following conditions are met:

  • You directly modify the BIG-IP APM configuration by editing the /config/bigip.conf file.
  • You add an extra terminal-out branch to an access policy macro configuration.
  • You attempt to load the modified configuration.

Impact

The configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • User access to the BIG-IP APM system is unavailable.
  • You observe repeating error messages in the /var/log/apm file that appear similar to the following example:

    notice apd[<pid>]: 01490000:5: ** SIGSEGV **
    notice apd[<pid>]: 01490000:5: ** STDERR **
    notice apd[<pid>]: 01490000:5: ** END STDERR **
    notice apd[<pid>]: 01490000:5: fault addr: <hex value>
  • The apd process produces a core file in the /shared/core directory.

Workaround

To work around this issue, use the Configuration utility visual policy editor to modify BIG-IP APM access policy macro.
