Known Issue

This is the result of a known issue. The Oracle or MSSQL monitor may mark healthy nodes as down after first having reported them as up. This issue is a result of socket exhaustion, which occurs when the db process fails to close sockets that were opened for monitoring. Once all sockets are exhausted, the db process is unable to restart. When this issue occurs, the BIG-IP system attempts to automatically restart the process, and the following error messages are repeatedly logged to the /var/log/db file:

Exception creating ServerSocket: java.net.BindException: Address already in use
Exception from accept(): java.net.SocketException: Too many open files
DBDaemon started!

Note: The db process cannot be restarted manually once socket exhaustion has already occurred.

F5 Product Development tracked this issue as CR91889 and it was fixed in BIG-IP LTM 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in HOTFIX-BIG-IP-9.3.1-HF2 issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You may be able to work around this issue by using an alternative monitor, such as the TCP monitor.

Note: Rebooting the system will temporarily relieve the issue, but socket exhaustion will eventually reoccur if the monitors are still running.
