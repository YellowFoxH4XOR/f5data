Topic

This article applies to BIG-IP GTM 11.x and BIG-IP DNS (formerly known as BIG-IP GTM) 12.x - 16.x. For information about other versions, refer to the following article:

  • K9655: Overview of the virtual server and link auto-discovery features (9.x - 10.x)

You should consider using this procedure under the following condition:

  • You want to configure a BIG-IP GTM 11.x system or a BIG-IP DNS 12.x - 16.x system to automatically discover virtual servers or link objects that are associated with defined BIG-IP systems.

Description

The virtual server and link auto-discovery feature allows BIG-IP DNS and BIG-IP Link Controller systems to automatically discover virtual servers and links that are associated with defined BIG-IP systems.

The auto-discovery feature uses the iQuery protocol to automatically discover objects on the remote BIG-IP system. If auto-discovery is enabled, the following actions take place:

  • The gtmd process running on the local BIG-IP DNS system reads the /config/bigip_gtm.conf file.
  • The gtmd process attempts to establish a Secure Sockets Layer (SSL) connection on port 4353 with the big3d process running on the remote BIG-IP system.
  • The BIG-IP DNS system sets the autoconf bit when sending the <getconfig> iQuery element.
  • The receiving big3d process includes the virtual server and link information in the <getconfig_elements> iQuery block data.
  • The gtmd process adds the discovered virtual servers and links to the configuration.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • The BIG-IP DNS configuration contains one or more BIG-IP server objects
  • TCP port 4353 is allowed between the BIG-IP DNS system and target BIG-IP systems
  • The target BIG-IP system's virtual server addresses must not employ network address translation
  • On the BIG-IP DNS, configured one or more server objects to represent the BIG-IP LTM systems with non-floating self-IPs

Configure global auto-discovery (BIG-IP 11.5.0 and later)

Impact of procedure: The following procedure should not have a negative impact on your system.

Configuring auto-discovery is a two-step process. You must first ensure that auto-discovery is enabled globally on the BIG-IP DNS system. Then you must enable virtual server and/or link auto-discovery for the appropriate BIG-IP server definitions. To configure global auto-discovery, perform one of the following procedures:

  1. Log in to the Configuration utility.
  2. Go to DNS > Settings > GSLB > General.
  3. Select the Auto-Discovery check box.
  4. Select Update.

Configure global auto-discovery (BIG-IP 11.0.0 through 11.4.1)

Impact of procedure: The following procedure should not have a negative impact on your system.

Configuring auto-discovery is a two-step process. You must first ensure that auto-discovery is enabled globally on the BIG-IP GTM system. Then you must enable virtual server and/or link auto-discovery for the appropriate BIG-IP server definitions. To configure global auto-discovery, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to System > Configuration > Global Traffic > General.
  3. Select the Auto-Discovery check box.
  4. Select Update.

tmsh

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To enable the global auto-discovery setting, enter the following command:

    modify /gtm global-settings general auto-discovery yes

  3. To save the configuration, enter the following command:

    save /sys config gtm-only

Note: When the bigip_link monitor is attached to a link object, you cannot disable global auto-discovery. Though you can toggle the auto-discovery global setting, it automatically reverts to the enabled state. In order to set global auto-discovery to disabled, all objects configured with the bigip_link monitor need to have the monitor setting use a different monitor type prior to changing the global setting.

Configure virtual server auto-discovery (BIG-IP 11.5.0 and later)

Impact of procedure: The following procedure should not have a negative impact on your system.

When you configure virtual server auto-discovery, the BIG-IP GTM system automatically discovers the virtual server objects associated with the BIG-IP server definition and adds them to the BIG-IP GTM configuration. To configure virtual server auto-discovery for a BIG-IP server definition, perform one of the following procedures:

  1. Log in to the Configuration utility.
  2. Go to DNS > GSLB > Servers > Server List.
  3. Select the BIG-IP server definition for which you want to enable virtual server auto-discovery.
  4. Select the Virtual Servers.
  5. For Virtual Server Discovery, select Enabled or Enabled (No Delete).

    Note: If you select the Enabled (No Delete) setting, the BIG-IP GTM system automatically adds and modifies virtual server settings in the configuration but does not delete them if they are removed from the BIG-IP system. This option is useful when you regularly take virtual servers in and out of service.

  6. Select Update.

Configure link auto-discovery (BIG-IP 11.5.0 and later)

Impact of procedure: The following procedure should not have a negative impact on your system.

When you configure link auto-discovery, the BIG-IP GTM system automatically discovers the link objects associated with the BIG-IP server definition and adds them to the BIG-IP GTM configuration. The system creates such link objects when the system has a default gateway that is a pool. If there is a self IP address that has a net mask enclosing the default gateway (either pool member or single IP address), that self IP address is also added to the BIG-IP GTM server object definition (even if no link is created). To configure link auto-discovery for a BIG-IP server definition, perform one of the following procedures:

  1. Log in to the Configuration utility.
  2. Go to DNS > GSLB > Servers > Server List.
  3. Select the BIG-IP server definition for which you want to enable link auto-discovery.
  4. Select Links.
  5. For Link Discovery, select Enabled or Enabled (No Delete).

    Note: If you select Enabled (No Delete), the BIG-IP GTM system automatically adds and modifies Link settings in the configuration but does not delete them if they are removed from the BIG-IP configuration.

  6. Select Update.

Enable auto-discovery for virtual servers in other route domains

Impact of procedure: The following procedure should not have a negative impact on your system.

Important: When setting the expose-route-domains option to yes, BIG-IP DNS discovers virtual servers in all route domains. However, since BIG-IP DNS system objects can only use the default route domain ID 0, non-default route domain IDs of discovered virtual servers will be converted to the default route domain ID 0. For this reason, all virtual servers must have unique names.

When a BIG-IP GTM system performs auto-discovery, the system discovers virtual servers within the route domain being queried. You can configure auto discovery to discover virtual servers for all route domains on the BIG-IP system by enabling the expose-route-domains option. To enable the expose-route-domains option for a BIG-IP server, perform the following procedure:

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To enable the expose-route-domains option for a BIG-IP server, use the following command syntax:

    modify /gtm server <server_name> expose-route-domains yes

    For example, to enable the expose-route-domains option for a BIG-IP server named BIG-IP-1, enter the following command:

    modify /gtm server BIG-IP-1 expose-route-domains yes

  3. To save the configuration, enter the following command:

    save /sys config gtm-only
