Known Issue

Importing a modified access policy may cause the Master Control Program daemon (mcpd) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • You manually edit an exported access policy configuration file.
  • The edit results in multiple policy items using the same agent.
  • You import the modified access policy.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the mcpd restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Importing an access policy causes the BIG-IP system to temporarily fail to process traffic, as it recovers from an mcpd restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates an mcpd core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.

Workaround

To work around this issue, you should avoid manually modifying the configuration file for an exported access policy, and use only the Configuration utility and Visual Policy Editor (VPE) to manage access policies.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
