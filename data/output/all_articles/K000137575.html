Description

In certain circumstances you may be wanting to verify the value of the X-Forwarded-For header inserted by the BIG-IP before passing the request to the backend server.

Environment

BIG-IP LTM
HTTP profile with Insert X-Forwarded-For setting enabled
Irule
 

Cause

You are unable to capture traffic on the BIG-IP or the relevant traffic may be encrypted and you are unable to decrypt. 

Recommended Actions

Use an irule similar to below to log in the /var/log/ltm file, the value of the X-Forwarded-For header which the BIG-IP has inserted in the server side request.

when HTTP_REQUEST_SEND {
  clientside {
   if {[IP::addr [IP::client_addr] equals 10.10.10.10] } {
    if { [HTTP::header exists "X-Forwarded-For"] } {
    log local0. "==============================="
    log local0. "Full XFF header: [HTTP::header X-Forwarded-For]"
         }  
       }
     }
  }

The resulting logs will look similar to below: 
 info tmm1[17508]: Rule /Common/my_Rule <HTTP_REQUEST_SEND>: ===============================
 info tmm1[17508]: Rule /Common/my_Rule <HTTP_REQUEST_SEND>: Full XFF header: 2.2.2.2
 
Note: The irule above only logs the X-Forwarded-For header if the client IP is 10.10.10.10. You need to modify the irule to reflect the correct Client Ip address.
