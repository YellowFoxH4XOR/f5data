Note: This solution assumes an understanding of BIND and canonical naming (CNAME records). If you are not familiar with BIND or CNAME records, refer to the 4th edition of DNS & BIND, by O'Reilly for additional information.

3-DNS load-balances wide-area traffic to ensure that it goes to the best possible datacenter, much like what BIG-IP does for individual servers.

The best way to integrate a 3-DNS Controller into an existing DNS environment is to delegate key sites to a sub-domain so that sub-domain can sub-delegate to the 3-DNS Controller for name resolution. This configuration would consist of an entire domain sub-delegated to the 3-DNS Controller, such as wip.mydomain.com, where mydomain.com is the customer-facing domain name.

In this configuration, queries for hosts within wip.mydomain.com are directed to the 3-DNS Controller for response, rather than the response coming directly from the primary DNS servers for domain.com.

For example, to load balance www.mydomain.com with the 3-DNS Controller being the primary nameserver for mydomain.com, you would create a sub-domain called wip.mydomain.com and sub-delegate that domain to the 3-DNS Controller. For this configuration, add the following lines in the mydomain.com zone file (where the IP address for the 3-DNS Controller is 192.168.33.75):

3dns.mydomain.com.    IN     A      192.168.33.75
wip.mydomain.com.     IN     NS     3dns.mydomain.com.

After you have assigned the sub-delegate wip.mydomain.com to the 3-DNS Controller, you can add a CNAME record that points to the specific sites that you want to load balance to the 3-DNS Controller. To load balance www.mydomain.com and customers.mydomain.com using a 3-DNS Controller, add the following lines in the mydomain.com zone file:

www           IN      CNAME     www.wip.mydomain.com.
customers     IN      CNAME     customers.wip.mydomain.com.

Note: A CNAME is an alias to another DNS record.

When in this configuration, if a query comes into the DNS server for the www.mydomain.com or customers.mydomain.com hosts, the DNS server will respond that the host has a CNAME record pointing to *.wip.mydomain.com and that the 3dns.mydomain.com 3-DNS Controller is authoritative for that domain. The LDNS will then re-query the 3-DNS Controller for www.mydomain.com or customers.mydomain.com, respectively.

The standard query process occurs as follows:

  1. The client, or LDNS, sends a query to the primary DNS server (this is not the 3-DNS Controller) that is registered as authoritative for domain.com. In this example the client is looking for www.domain.com.
  2. The primary DNS server responds to the client, providing the record for the query as the CNAME record that was delegated to another set of servers (the 3-DNS Controller), and to request that the 3-DNS Controller(s) responsible for wip.domain.com provide an answer to the client's request.
  3. The client queries the primary DNS server requesting the address for the 3-DNS Controller that is responsible for wip.domain.com.
  4. The primary DNS server returns the IP address for the 3-DNS Controller to the client.
  5. The client sends the query for www.wip.domain.com to the 3-DNS Controller IP that it received from the primary DNS server.
  6. In turn, the 3-DNS Controller responds with the IP address for the wide IP (in this example) of www.wip.domain.com.

This process illustrates that the 3-DNS Controller's wide IP and zone files are authoritative for any delegated domain that you add (in this example wip.mydomain.com), but is not authoritative for the parent domain (in this example, mydomain.com) unless you configure aliases on the 3-DNS Controller's wide IP (in the event that a client or LDNS queries the 3-DNS Controller directly for a DNS record that has been delegated to 3-DNS Controller).

If the client were to direct queries to the 3-DNS Controller for www.domain.com without the aliases, it would fail because the 3-DNS is not authoritative for the parent domain; however, if you add an alias for www.domain.com to the wide IP of www.wip.domain.com, the client will receive an answer.

Adding an alias to wide IP

To add an alias to a wide IP perform the following steps from the Configuration utility:

  1. From the navigation pane, click Wide IPs.
  2. From the list, click the wide IP to which you need to add the alias.
  3. Click Modify Alias.
  4. Add the alias for in FQDN format (for this example: www.domain.com) in the text field.
  5. Click the Add button.

    The screen will refresh and display the alias that you added.

    Note: You can assign multiple aliases for a single wide IP.

Note: For additional information about configuring 3-DNS Controller wide IPs, refer to the 3-DNS Controller Reference Guide.
