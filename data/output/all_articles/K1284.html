BIG-IP and 3-DNS use the standard UNIX logging utility, syslog, to deliver system messages to log files. While syslog most commonly sends information to log files, you can also configure it to send information to devices, user sessions, other syslog servers, or other programs.

The following facilities are available on BIG-IP and 3-DNS. Each facility handles messages for specific elements of the system, as described.

Facilities

The following facilities are available on BIG-IP and 3-DNS. Each facility handles messages for specific elements of the system, as described in the following table:

Levels

The following levels are available for each facility. The facilities are listed in order of the severity of the messages they handle. Generally, higher levels contain all the messages for lower levels. For example, the alert level will generally also report all messages from the emerg level. The debug level will generally also report all messages for all levels.

LevelDescriptionVerbosity
emergEmergency system panic messages.Minimum
alertSerious errors that require administrator intervention.Low
critCritical errors, including hardware and filesystem failures.Low
errNon-critical, but possibly very important, error messages.Low
warningWarning messages that should at least be logged for review.Medium
noticeMessages that contain useful information, but may be ignored.Medium
infoMessages that contain useful information, but may be ignored.High
debugMessages that are only necessary for troubleshooting.Maximum


 

Destination options

You can specify the following destinations for syslog messages.

DestinationSyntax
A device, such as the console./dev/<device>
A user shell.<username>
All user shells.*
Pipe to another program.|exec <program>
Send to SNMP trap generator./var/run/trapper
Another syslog server.@<hostname>

 

Adding new entries to syslog.conf file

You can configure the syslog utility by adding entries to its configuration file, /etc/syslog.conf.

Important: F5 Networks recommends that you do not change the entries contained in the syslog.conf file, because it already specifies the minimum amount of logging recommended. You can, however, increase the level of logging, or add additional log files.

Entries that you add to the syslog.conf file are cumulative. You cannot add a line to the file that will reduce the amount of logging from the default configuration. When adding entries to the syslog.conf file, you can use the wildcard character (*) in any of the fields. This allows you to choose multiple facilities at a specific level, multiple levels for a specific facility, or to log a message to multiple log files.

To add entries to the syslog.conf file, perform the following steps:

  1. Log in to the command line.

  2. Change directories to the /etc directory, by typing the following command:

    cd /etc

  3. Create a backup copy of the syslog.conf file, by typing the following command:

    cp syslog.conf syslog.conf.original

  4. Using a text editor, such as vi or pico, edit the syslog.conf file.

  5. At the end of the file, add new entries in the following format:

    <facility>.<level> <destination>

    Note: You must include at least one tab between <facility>.<level> and <destination>.

  6. Restart the syslog daemon, by typing the following command:

    Note: The following command includes back ticks, not single quotes.

    kill -HUP `pidof syslogd`

Sample configuration options

Following are sample configuration options for the syslog.conf file.

The following three entries will log the three most severe levels of BIG-IP messages (from local0) to the console:

local0.emerg   /dev/console
local0.alert  /dev/console
local0.crit   /dev/console

 

The following entry will send all messages from facilities, at all levels, to a remote syslog server:

*.* @mysyslog.askf5.com

 

The following entry will print messages at the emerg level, from all facilities, to the screen for all user sessions:

*.emerg *

 

The following entry will print messages from the daemon facility, at any level, to the screen for the root user:

daemon.* root

 

The following entry will send all kernel messages to the log2mail program:

kern.* |exec log2mail root

 

The following entries will send all emerg and alert level messages to the SNMP trap generator.

*.emerg      /var/run/trapper
*.alert      /var/run/trapper
