Topic

F5 Support requires information when you open a support case for other F5 products. For more information, refer to K2633: Instructions for submitting a support case to F5.

Note: If you are running BIG-IP 10.x or later, you can use F5 iHealth to diagnose a QKView file. iHealth enables you to verify the proper operation of your BIG-IP system. For more information, refer to the iHealth site.

F5 Support can help resolve issues more quickly when you provide a full description of the issue and the details of your configuration.

To help you gather all the required information, use the following guidelines to prepare for opening a case.

Issue description

  • The symptoms of the issue, including a brief description of any systems applicable to the configuration
  • The approximate time the issue first occurred
  • The number of times the issue has recurred
  • Any error output provided by the system
  • Steps to reproduce the issue
  • Any changes you made to the system before the issue first occurred
  • Any steps you took to attempt to resolve the issue
  • Whether this is a new implementation
  • Whether you have already uploaded a QKView to the iHealth portal

    Note: Ensure that you link QKViews to the support case when uploading to iHealth.

BIG-IP DNS information

  • How many data centers and devices are applicable to the configuration?
  • Which devices are affected by the issue?

Contact information

  • The hours that you are available to work on the issue and any alternative contacts that can work on the issue if you are not available

Remote access information

Provide remote access information whenever possible. Remote access to your network environment is important, because it is the most effective method for collecting information and troubleshooting technical issues. If you cannot provide remote access, F5 Support will work directly with you to resolve the issue over the phone; however, this method can often be more time consuming and may require file transfers, replication, and additional testing.

Product-specific information

Provide the following information when you open the case. For information about how to send information to F5, refer to K000090853: Exchange files with F5 Support using MyF5.

QKView file

A QKView file contains the configuration files that F5 Support most frequently needs when troubleshooting an issue. On BIG-IP 9.x, a TECH.OUT file is produced by the qkview utility and the terms TECH.OUT and qkview may be used interchangeably.

For more information about the qkview utility, refer to the following articles:

  • K1858: Overview of the qkview utility (9.x)
  • K12878: Generating BIG-IP diagnostic data using the qkview utility

Note: If you are running BIG-IP 10.x or later, you can use F5 iHealth to diagnose a QKView file. iHealth enables you to verify the proper operation of your BIG-IP system. For more information, refer to the iHealth site.

Log files

The BIG-IP 10.x qkview utility automatically gathers up to 5 MB of log files and includes them in QKView in a TAR output. For more information, refer to K12878: Generating BIG-IP diagnostic data using the qkview utility.

The TECH.OUT file contains the log files for the last day. If the issue persists for more than a day, provide all the log files on the system by performing the following procedure:

  1. Log in to the command line.
  2. Type the following command to create a TAR archive named logfiles.tar.gz in the /var/tmp directory that contains all the files in the /var/log directory:
    tar -czpf /var/tmp/logfiles.tar.gz /var/log/*

Packet traces

If the issue involves the network, perform a packet trace while the issue is occurring and provide the packet trace when you open the case.

For more information about performing packet traces with tcpdump, refer to K4714: Performing a packet trace and providing the results to F5 Support.

ssldump utility

If the issue involves SSL-encrypted packet streams managed by the BIG-IP system, you can use the ssldump utility to examine, decrypt, and decode the SSL-encrypted packets. For more information, refer to K10209: Overview of packet tracing with the ssldump utility.

UCS archive

If you cannot give F5 Support remote access to your system, you must provide a user configuration set (UCS) archive of the current configuration. For more information, refer to K4423: Overview of UCS archives.

Core files

Core files contain the contents of the system memory at the time a crash occurred. If you configured your system to save core files, they are in the following location:

  • BIG-IP 9.0–9.2.5: /var/savecore directory
  • BIG-IP 9.3 and later: /var/core directory

Provide any existing core files when you open the case.

For information about requirements when submitting core files to F5, refer to K10062: Submitting core files for analysis to F5 Support.
