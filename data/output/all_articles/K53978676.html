K53978676: LTM identify pool as UP while application is responding incorrectly

Type
Support Solution
Published
2022-01-26
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.X.X, 15.0.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.X, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 15.1.2
Source
https://my.f5.com/manage/s/article/K53978676
Description
  • VIP shows that he is up and running.
  • After some time there is an alert that indicate that the VIP is down and up again but despite the VIP is up the service behind it doesn't work.
  • ltm log:
    Jan 20 13:06:44 LTM1.example.com notice mcpd[6015]: 01071682:5: SNMP_TRAP: Virtual /Common/vip1_8080 has become unavailable
    Jan 20 13:06:58 LTM1.example.com notice mcpd[6015]: 01071681:5: SNMP_TRAP: Virtual /Common/vip1_8080 has become available
Environment
  • Pool is using built in http monitor that is only sampling HTTP's response - any response:

ltm monitor http http {
   <snip>
    destination *:*
    interval 5
    ip-dscp 0
    manual-resume disabled
    partition Common
    password none
    recv none <<<<<
    recv-disable none
    reverse disabled
    send "GET /\r\n"
<snip>
}

As result, any HTTP will be consider as pool member is up.
Thus will experience a VIP down and up but severe service impact

Cause

The root cause is that the while Apache Tomcat is up and running and port is listening.
Once the site is down, the BIG-IP will still consider the pool member up due to getting a HTTP response from the Tomcat

Recommended Actions

  • Create new http monitor that will sample the relevant uri and response code of 200 OK
    K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor
