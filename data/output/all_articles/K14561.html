Known Issue

The BIG-IP system may misdirect traffic sent to a self IP address after the primary blade restarts or fails.

Traffic destined for a self IP address on a chassis platform is always directed to the primary blade. If a self IP address on a non-primary blade initially receives the traffic, the BIG-IP system creates a forwarding flow to send the packets to the primary blade. If the primary blade fails, new self IP traffic received by non-primary blades may result in incorrect traffic flows before a new primary blade can be established.

Impact

The BIG-IP system drops affected self IP traffic, which may include network failover packets.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system drops affected self IP traffic.
  • Network failover traffic may may be disrupted, resulting in an active-active condition for redundant devices.

Workaround

To temporarily work around this issue, you can restart the TMM process. To do so, perform the following procedure:

Impact of workaround: Restarting TMM interrupts traffic processing, and you should perform this task in a maintenance window. In addition, restarting TMM temporarily mitigates the issue.

  1. Log in to the BIG-IP command line using the cluster management IP address.
  2. Type the following command:

    bigstart restart tmm
