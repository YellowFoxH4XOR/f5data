Description
Data plane CPU cores show significantly divergent load on a vCMP guest. TMMs may show different numbers of connections and/or different traffic counts when observed using show sys tmm-traffic in tmsh.

Environment

  • vCMP guest
  • B2250 blade

Cause
Bug ID 700827

Recommended Actions
Impact of actions: The system will be unavailable while TMM restarts, and while rebooting if upgrades are required.

  1. Ensure both host and guest are upgraded to a version where Bug ID 700827 is fixed.
  2. Configure the MHDAG algorithm.
    In tmsh, on the host, run:
    modify sys db mhdag.pu.table.size.multiplier value 2; save sys config
  3. Do one of the following:
    • Restart TMM on the host and all guests using the following command in bash:
      Important: Restarting tmm on the guests only does nothing; restarting on the host only means that the guests still use old DAG settings and have high inter-TMM forwarding traffic, resulting in a worse condition than originally experienced.
      clsh tmsh restart sys service tmm
    • Restart all blades of the host by following either of the following:
      • In TMUI navigate to System > Configuration > Device > General and click Reboot Chassis
      • In Advanced Shell (bash) run the following command:
        clsh reboot
      • In tmsh run the following command:
        reboot slot all
Additional Information
  • BIG-IP systems distribute traffic across TMMs using a CMP hash. The CMP hash specific to vCMP guests on B2250 blades, called MHDAG, can cause uneven distribution when the majority of source ports are evenly spaced - for example, if most or all source ports are even numbers. F5 tracked this as Bug ID 700827 and introduced an enhancement which allows you to configure the system to distribute traffic more evenly in these situations.
  • F5 has found 2 to be the most effective setting for mhdag.pu.table.size.multiplier for the most common situation where this occurs, which is an interval between ports (or port stride) of 2.
  • MHDAG was introduced in TMOS v12.1.0.
  • Linux kernel version 4.2 and later prefers even-numbered source ports for outgoing connections
