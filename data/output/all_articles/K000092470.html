K000092470: Configure Ingress Controller send traffic to service Cluster-IP instead of pod IP

Type
Support Solution
Published
2022-10-19
Updated
2022-10-19
Source
https://my.f5.com/manage/s/article/K000092470

Description

When using many non-f5 industry service mesh solutions, there is a requirement that upstream traffic is forwarded to the Kubernetes service IP itself instead of directly to the individual pod IPs.

 

Environment

Kubernetes
Service mesh(Kong, Istio)
Nginx Plus Ingress Controller


Cause

This is a requirement for routing when a service mesh other than our Nginx Service Mesh(NSM) is used in conjunction with our Nginx+ Ingress Controller.


Recommended Actions

We can route to the upstream service "ClusterIP" instead of the Individual pod IPs through the use of the "use-cluster-ip" option within our Virtualserver/Virtualserverroute CRDs.
The following example config shows where the "use-cluster-ip" option would go in a virtualserver yaml file:
 

apiVersion: k8s.nginx.org/v1
kind: VirtualServer
metadata:
  name: webapp
spec:
  host: "app.example.com"
  upstreams:
  - name: webapp
    service: app-svc
    port: 80
    use-cluster-ip: true
  routes:
  - path: /
    action:
      pass: webapp

 

 Additional Information

More details can be found here:
https://docs.nginx.com/nginx-ingress-controller/configuration/virtualserver-and-virtualserverroute-resources/#upstream
 

Note: When using this setting, you lose the ability to have Nginx perform any of the loadbalancing options since all the traffic is being forwarded to the Kubernetes service, and Kubernetes is now performing the loadbalancing to the individual pods.
