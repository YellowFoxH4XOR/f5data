Description

After removing a public snmp community and replacing the source with the "Default" value, the BIG-IP becomes unresponsive to snmp requests and snmpwalks on the localhost.

Environment

Receiving Timeout: No Response from localhost when trying to poll BIG-IP via snmpwalk or snmpget.

Cause

SNMP communities are case-sensitive. Using Default instead of default can prevent responses.

To remove the public snmp community that comes with a BIG-IP, this parameter should be default.

Recommended Actions

View the currently configured SNMP communities with the command:

tmsh list sys snmp communities

Example output containing this misconfiguration:

sys snmp {
    communities {
        itesting_1 {
            community-name testing
            source Default
        }
    }
}

If the results of this command show Default as the source on the failing snmp agent, reconfigure the snmp community to use default as the source. 

 

To make these changes using the Configuration Utility, navigate to System >> SNMP >> Agent >> Access (v1, v2c) or Access (v3). Then select the failing agent and replace the source value of Default with default.

 

To make these changes using TMSH, 

tmsh modify sys snmp communities modify { <enter agent name> { source default } }
