K52921535: Intermittent Kerberos authentication failures after upgrade

Type
Support Solution
Published
2019-10-22
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.1.1
Source
https://my.f5.com/manage/s/article/K52921535

Description

Intermittent Kerberos authentication failures after upgrade

Environment
  • APM
  • Multiple Kerberos AAA servers
  • Multiple keytab files
  • Multiple service accounts in the same realm
Cause

You are encountering errors similar to the following:

GSS-API error gss_accept_sec_context: 0 : Unknown error
GSS-API error gss_accept_sec_context: 70000 : No credentials were supplied, or the credentials were unavailable or inaccessible

This is caused by the issue outlined in K17371: BIG-IP APM may fail to authenticate when Kerberos AAA servers have different keytab files

Recommended Actions

  1. For each kerberos server object in the same authentication realm, find the keytab file associated with that object in bigip.conf:
    This will look similar to the following:
    apm aaa kerberos <Server object name> {
        auth-realm <REALM>
        keytab-file-obj <KEYTAB OBJECT NAME>
        service-name <SERVICE>
    }

  2. Find the cache path for each keytab file:
    apm aaa kerberos-keytab-file <KEYTAB OBJECT NAME> {
        cache-path <FILE LOCATION on the BIG-IP> <<=====
        revision 1
    }

  3. Log into the BIG-IP command line

  4. Run the following commands to merge keytab files in the same authentication realm:
    ktutil
    read_kt <keytab file 1 cachepath>
    read_kt <keytab file 2 cachepath>
    read_kt <keytab file 3 cachepath>

  5. You can list currently loaded entries with 'list'

  6. Write the contents of your existing keytab files to a new single file with the following command:
    write_kt <New keytab file path>

  7. To quit, use the following command:
    quit

After generating the keytab file in the previous procedure, download it to your computer. To upload it to the Kerberos authentication server object using the Configuration utility, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.

  2. Navigate to Access  > Authentication > Kerberos.
    Note: For versions prior to BIG-IP 13.x, navigate to Access Policy  > AAA Servers > Kerberos.

  3. Click the name of the Kerberos server

  4. For Keytab File, click Upload New File.

  5. Click Choose File, then browse to and choose the merged keytab file you created in the Merging the keytab files with the ktutil utility procedure.

  6. Click Update.

In general, it is recommended that you configure only one Kerberos AAA server per authentication realm.
