Known Issue

The BIG-IP ASM system may experience a memory leak in the asm_config_server process.

This issue occurs when one of the following conditions is met:

  • A pool member state changes frequently.
  • You set the affected policy's learning mode to Manual (12.x only).

Impact

BIG-IP ASM system performance may degrade over time and the system may become unresponsive or restart due to memory exhaustion.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The top utility indicates that the asm_config_server process memory allocation grows over time.

Workaround

To work around this issue, you can restart the asm_config_server process or restart the asm process. To do so, perform one of the following procedures:

  • Restarting the asm_config_server process
  • Restarting the asm process

Restarting the asm_config_server process

Impact of workaround: Performing the following procedure should not have a negative impact on your system. Restarting the asm_config_server process does not disrupt traffic processing.

  1. Log in to the BIG-IP ASM system command line.
  2. To restart the asm_config_server process, type the following command:

    pkill -f asm_config_server

    The BIG-IP ASM watchdog process automatically restarts the asm_config_server process within 10-15 seconds.

Restarting the asm process

Impact of workaround: Restarting the asm process causes the BIG-IP ASM system to fail over to the remaining members of the device group.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the BIG-IP ASM process, type the following command:

    restart /sys service asm
