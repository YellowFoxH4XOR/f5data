Known Issue

When you deploy NGINX Controller, the system creates the following rules:

NGINX Controller user interface access uses Destination Network Address Translation (DNAT) from port 443 to API gateway (apigw) port 8443. For example:

-A CNI-DN-2fd3a01d804b10ca8ef8d -s 10.244.0.0/24 -p tcp -m tcp --dport 443 -j CNI-HOSTPORT-SETMARK
-A CNI-DN-2fd3a01d804b10ca8ef8d -s 127.0.0.1/32 -p tcp -m tcp --dport 443 -j CNI-HOSTPORT-SETMARK
-A CNI-DN-2fd3a01d804b10ca8ef8d -p tcp -m tcp --dport 443 -j DNAT --to-destination 10.244.0.209:9443
-A CNI-DN-2fd3a01d804b10ca8ef8d -s 10.244.0.0/24 -p tcp -m tcp --dport 8443 -j CNI-HOSTPORT-SETMARK
-A CNI-DN-2fd3a01d804b10ca8ef8d -s 127.0.0.1/32 -p tcp -m tcp --dport 8443 -j CNI-HOSTPORT-SETMARK
-A CNI-DN-2fd3a01d804b10ca8ef8d -p tcp -m tcp --dport 8443 -j DNAT --to-destination 10.244.0.209:8443
-A CNI-HOSTPORT-DNAT -p tcp -m comment --comment "dnat name: \"cbr0\" id: \"b49b0a44de70f64eba8aa8e922898234578ff04a025b8735b3ed8141be38e068\"" -m multiport --dports 443,8443 -j CNI-DN-2fd3a01d804b10ca8ef8d

If you enter firewall-cmd --reload on Centos 7, all the CNI-DN* rules are deleted. 

This issue occurs when all of the following conditions are met:

  • You install NGINX Controller on Centos 7.
  • You enter the firewall-cmd --reload command on Centos 7.

Impact

All firewalld rules are deleted, which may result in a connectivity issue to NGINX Controller user interface or other controller pod services.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Your system experiences a connectivity issue to NGINX Controller user interface or other controller pod services.
  • You can confirm that CNI-DN* rules are deleted by entering the following command:

    iptables-save | grep -i "CNI"
