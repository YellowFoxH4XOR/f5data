Description

After upgrading the BIG-IP SSLO system, the following error message appears in the SSLO topology page:

The text is like:

!Unable to complete the cleanup. You must resolve the error (if any), delete the iAPP blocks in error state (if any) from the iApps menu on the left-hand side and perform CMI sync. Then resume the upgrade process: click upgrade. : Transaction failed:01070265:3 The Access Profile (/Common/sslo_<topology name>.app/sslo_<topology name>_accessProfile) cannot be deleted because it is in use by a virtual server profile (/Common/<Virtual server name> /Common/sslo_<topology name>app/sslo_<topology name>_accessProfile).

Environment

  • BIG-IP SSLO
  • Topology
  • Virtual server

Cause

The issue occurs because during an SSLO upgrade, all objects created by SSLO are deleted and re-created as part of the process. If these objects (e.g., access profiles, policies) are applied to other user-created virtual servers outside of their original virtual server, they cannot be deleted during this process, and SSLO will show this error.

Recommended Actions

Solution for Upgrade Error:

Option 1 – Rollback and Reconfigure Before Upgrade:

  • Roll back to the previous version of BIG-IP.
  • Modify all custom virtual server configurations that reference SSLO-created objects:
    • Remove references to SSLO-created profiles and policies from these virtual servers.
  • Sync configuration across devices.
  • Perform the upgrade again.
  • After a successful upgrade, reapply SSLO-created objects to custom virtual servers as needed.

Option 2 – Adjust Configuration During Current Version:

  • Edit all custom virtual server configurations that reference SSLO-created objects:
    • Remove references to these objects temporarily.
  • Sync configuration across devices.
  • Navigate to the SSLO configuration page and click on "Upgrade" at the top-right corner of the interface.
  • Once upgraded successfully, restore references to SSLO-created objects in custom virtual server configurations.
