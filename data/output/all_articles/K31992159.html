Description

After upgrading from BIG-IP 13.1.x to another 13.1.x version for example 13.1.3.4 to 13.1.3.6. You are not able to see configuration objects on the BIG-IP Configuration utility or command line due to a configuration load failure.

You observe log messages in /var/log/ltm similar to the following:
err mcpd[7659]: 01070312:3: Invalid keyword 'kedh' in ciphers list for profile /Common/myapp.app/myapp_https_monitor_ssl_profile
err tmsh[10459]: 01420006:3: Loading configuration process failed.
emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- Loading schema version: 13.1.3.4 Loading schema version: 13.1.3.6 01070312:3: Invalid keyword 'kedh' in ciphers list for profile /Common/myapp.app/myapp_https_monitor_ssl_profile Unexpected Error: Loading configuration process failed.
err mcpd[7659]: 01070425:3: Full configuration load failed.

Environment

  • BIG-IP 13.1.x
  • A BIG-IP Upgrade
  • HTTPS monitors
  • Server SSL profiles with kEDH in the ciphers list

Cause

The configuration load failure due to the invalid keyword in the ciphers list is caused by Bug ID 705730. A fix was introduced in BIG-IP 14.0.0.

The issue described in this article has similar symptoms to Bug ID 702792. However, Bug ID702792 should not prevent the configuration from loading; rather, it triggers an error message when you attempt to modify an affected Server SSL profile. Fixes were introduced in BIG-IP 13.1.1.4 and BIG-IP 14.0.0 for this bug. For more information refer to, K82327396: Upgrading to BIG-IP 13.1.0 or later creates a Server SSL profile with an invalid cipher string which contains additional details about ID 702792.

Recommended Actions

1. Refer to the Workaround section in Bug ID 705730 which lists several options.

2. If you choose the option to remove any unsupported +kEDH strings from Server SSL profiles, refer to the procedure below:

Impact of workaround: Performing a configuration load on an active device group member can potentially disrupt the service of the device. F5 recommends that you perform this procedure during a scheduled maintenance period.

  1. Log in to the BIG-IP Advanced shell (bash).
  2. Backup the existing configuration file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.K31992159

  3. Using a text editor such as vi, open the /config/bigip.conf file for editing.
  4. Locate the affected cipher string. The problematic cipher string may appear similar to the cipher string in the following example Server SSL profile:

    ltm profile server-ssl /Common/example_server_ssl_profile {
    cert none
    cipher-group none
    ciphers DEFAULT:+SHA:+3DES:+kEDH
    <snip>

  5. Edit the cipher string to remove the problematic keywords. Using the previous example, you could change the cipher string to the following:

    ciphers DEFAULT:+SHA:+3DES:+EDH

  6. Save the changes and exit the text editor. If using vi, type the following command:

    :wq

  7. Load the modification into the running configuration by typing the following command:

    tmsh load /sys config

Additional Information

Alternatively, you can run script to remove the offending keywords from configuration in multiple partitions. For more information, refer to K82327396: Upgrading to BIG-IP 13.1.0 or later creates a Server SSL profile with an invalid cipher string.
