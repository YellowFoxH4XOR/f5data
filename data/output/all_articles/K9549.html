Known Issue

This is the result of a known issue. If you configure multiple default domain suffixes on the Device Management : Configuration : Network Configuration page under the DNS tab, the DNS suffix search list may become corrupted on a Windows client system when a user launches a Network Access connection. Additionally, when this issue occurs, the domain suffix search list remains corrupted on the client system even after the user disconnects the Network Access connection.

This issue occurs when all of the following conditions are met:

  • You configured multiple default domain suffixes on the Device Management : Configuration : Network Configuration page under the DNS tab.
  • You configured at least one name server for the Network Access resource on the Network Access : Resources page under the DNS tab.
  • The Enforce DNS search option check box is enabled for the Network Access resource on the Network Access : Resources page under the DNS tab.
  • You did not enter a value in the Domain Suffix 0 field for the Network Access resource on the Network Access : Resources page under the DNS tab.

When this issue occurs, FirePass combines the default domain suffixes into a single string. For example, if you configured site1.example.com and site2.example.com as the default domain suffixes, approximately one minute after the user establishes the Network Access connection, the DNS suffix search list appears as follows on the client system:

site1.example.comsite2.example.com

Note: You can view the DNS suffix search list by typing ipconfig /all from the Windows command line on the client system.

If the user had one or more DNS suffixes configured prior to establishing the Network Access connection, those are also corrupted. For example, if the user had eng.example.com and sales.example.com configured prior to establishing the Network Access connection, the DNS suffix search list appears as follows after establishing the Network Access connection:

site1.example.comsite2.example.com.eng.example.comsales.example.com

F5 Networks Product Development tracked this issue as CR109492 it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

Additionally, cumulative hotfix HF-603-1 has been issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

If multiple domain suffixes are not required for the Network Access resource, you can work around this issue by configuring a single domain suffix in the Domain Suffix 0 field on the Network Access : Resources page under the DNS tab.
