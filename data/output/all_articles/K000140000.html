K000140000: [F5OS-A] Unable to Authenticate using remote users after upgrading to v1.5.2

Type
Support Solution
Published
2024-06-22
Updated
2024-06-22
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000140000

Description

After upgrading F5OS-A from an older version like v1.3.2 to v1.5.2, the pre-configured Remote Authentication for one or some users do not work, and you face "Authentication failed" or "Authentication Failure" Error message on WebUI or SSH Console respectively, while trying to login. The Issue only affects the remote user with the same username as the local F5OS user.

Also, you can find some smaple relevant logs as below in the "/var/log/secure" file:

<Timestamp> <Hostname> unix_chkpwd[28648]: password check failed for user (<username>)

<Timestamp> <Hostname> sshd[27447]: pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=<IP_ADDRESS> user=<username>

<Timestamp> <Hostname> sshd[27447]: tac_authen_read_timeout: short reply header, read 0 of 12: Operation now in progress

<Timestamp> <Hostname> sshd[27447]: PAM-tacplus: Not allowed to authenticate a remote user with the same username as the local user

Environment

  • F5OS-A (rSeries)
  • Upgrading from older versions like v1.3.2 to v1.5.2
  • Remote Authentication Server (RADIUS, TACACS+, or LDAP) configured

Cause

This changed behavior is an expected outcome from the Fix of Bug-ID 1332781.

Recommended Actions

Do not create a remote user with the same username as the local user. If you have created already, change the username for either the local user or the remote user. Removing the same Local username from the F5OS config also resolves the Issue.
