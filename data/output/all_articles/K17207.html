Known Issue

BIG-IP APM portal rewritten content may appear to load twice.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with portal access and a rewrite profile.
  • HTTP content rewritten by the BIG-IP APM system includes a URL header location that specifies a default server port.

    The client browser loads the rewritten page content containing the location header URL without a specified default port. However, when the browser receives the location header URL within the content that includes a specified default port, the browser initiates a load of the page content based on the location header.

Impact

The rewritten HTTP content may trigger the client's browser to load the content twice.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Automatic secondary loading of rewritten content may cause some applications to function in an unexpected manner.
