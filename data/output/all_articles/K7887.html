Known Issue

This is the result of a known issue. When a long HTTP response is sent to a slow client, the TCP window can fill up between the BIG-IP ASM process and TMM. When this occurs, the TMM will send up to three TCP window probes, followed by a TCP reset to close the connection if no response is received. This issue has been known to occur when end-users connect to a BIG-IP ASM-enabled virtual server over slow, dial-up connections.

F5 Product Development tracked this issue as CR81945 and it was fixed in BIG-IP ASM versions 9.3.1 and 9.4.2. For information about upgrading, refer to the BIG-IP ASM release notes.
