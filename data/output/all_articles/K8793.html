K8793: Intelligent Browser Referencing (IBR) functionality is not performed for tags modified by a Stream profile

Topic

If the BIG-IP LTM Stream profile is configured for a virtual server that has been enabled for WebAccelerator, the Intelligent Browser Referencing (IBR) functionality will not be performed for tags that the Stream profile has modified.

Note: IBR was referred to as Express Loader in versions prior to BIG-IP WebAccelerator version 9.4.2.

For information about the IBR feature, refer to the Specifying content assembly options section of the Configuring Assembly Rules chapter in the the Policy Management Guide for the BIG-IP WebAccelerator System.

Example HTML page:

<html>
<body>
This is the test image 1..
<img src="/pictures/image_1.gif">
<p>
This is the test image 2..
<img src="http://www.askf5.com/pictures/image_2.gif">
</body>
</html>

If a Stream profile is not applied to the virtual server, the IBR functionality will modify the image source tags (img src) in the HTML page by appending a unique pv tag.

For example:

<html>
<body>
This is the test image 1..
<img src="/pictures/image_1.gif;pv12345">
<p>
This is the test image 2..
<img src="http://www.askf5.com/pictures/image_2.gif;pv54321">
</body>
</html>

However, if a Stream profile similar to the following example is applied to the virtual server, the IBR functionality will not append a pv tag for the img src tag that matched the Stream profile:

profile stream test_stream {
   defaults from stream
   source "www.askf5.com"
   target "192.168.10.1"
}

The HTML page would appear similar to the following example:

<html>
<body>
This is the test image 1..
<img src="/pictures/image_1.gif;pv12345">
<p>
This is the test image 2..
<img src="http://www.askf5.com/pictures/image_2.gif">
</body>
</html>
