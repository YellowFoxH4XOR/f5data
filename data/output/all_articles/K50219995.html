Known Issue

The Master Control Program daemon (mcpd) is the messenger daemon that enables communication between userland processes and the Traffic Management Microkernel (TMM). In certain circumstances, such as immediately after a reboot, queries for system performance statistics before the statistics are available may cause the mcpd process to leak memory.

This issue occurs when all of the following conditions are met:

  • System performance statistics are not yet available which for example occurs immediately after a reboot.
  • You query for system performance statistics using the Configuration utility or the Traffic Management Shell (tmsh).

Impact

Over time, the mcpd process may exhaust memory resources until it restarts and produces a core file. If the BIG-IP system is a member in a device group, traffic may fail over to another device group member. If the BIG-IP system is not part of a device group, traffic will be interrupted until the mcpd process restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The amount of memory allocated for and used by the mcpd process will increase over time.
  • Over time, the mcpd process may exhaust memory resources. As a result, system performance may degrade and the system may eventually become unresponsive.
  • The mcpd process may restart and generate an mcpd core file to the /shared/core directory.
  • The BIG-IP system unexpectedly fails over to another system in the device group.
