Known Issue

The ZebOS route table may not update when you change the self IP vlan association.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with ZebOS routing.
  • Your BIG-IP system is configured with two or more IPv6 self IP addresses that match the following criteria:

    • The IPv6 address are configured with the same mask between 97 and 128.
    • The network portion of the IPv6 addresses only differ in the last 32 bits of the address.
  • You modify one of the IPv6 self IP address-associated vlans.

Impact

The system does not update the ZebOS route table to reflect the updated vlan association.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After modifying the IPv6 address vlan, the following commands show the IPV6 address aligned to different vlans.

    imish -e 'show interface internal'

    Note: The previous command shows the IPv6 address associated with the new/correct vlan.

    imish -e 'show ipv6 route'

    Note: The previous command shows the IPv6 address associated with the old/original vlan.

  • Routing for the affected IPv6 address does not function as expected.

Workaround

To work around this issue, you can restart the tmrouted service. To do so, perform the following procedure:

Impact of workaround: Dynamic routing will temporarily be interrupted while the tmrouted service restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To restart the tmrouted process, type the following command:

    restart /sys service tmrouted

  3. To exit the tmsh utility, type the following command:

    quit
