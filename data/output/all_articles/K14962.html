Known Issue

The BIG-IP system cannot establish IPv6 single-hop Bidirectional Forwarding Detection (BFD) sessions with some peer routers. When attempting to establish the connection, the BIG-IP system sends BFD INIT packets that include a recommended default hop limit that violates the specification defined by RFC 5881. This may cause the receiving router to reject the packet, thus preventing the system from establishing the BFD session.

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP Advanced Routing Module to use the IS-IS, OSPF, or BGP routing protocol.
  • The BIG-IP interface to which the affected peer is connected has an IPv6 address.
  • You enable the BFD protocol option for the dynamic routing protocol.
  • BFD peers are running recent versions of Cisco IOS, Juniper Junos, or another RFC 5881-compliant network operating system.

BFD is a protocol that detects faults between two forwarding engines connected by a link. On the BIG-IP system, you can enable the BFD protocol for the OSPF, BGP, and IS-IS dynamic routing protocols.

Impact

Convergence or re-convergence of affected links is slower than expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H436971 on the Diagnostics > Identified > High screen.
  • The system does not establish a BFD session with the peer router.
    • You can display the status of the BFD session on the BIG-IP system by typing the following command at the ZebOS Exec or Privilege Exec command prompt:

      show bfd session

      If the system cannot establish the session, the command output indicates that the Session State is Down, similar to the following example:

      Session Interface Index: 3 Session Index: 1
      Lower Layer: IPv6 Single Hop
      Session State: Down

    • You can display the status of the BFD session on the peer system using a command similar to the following:

      show bfd session

      If the system cannot establish the session, the command output indicates that the session state is Down, similar to the following example:

      Sess-Idx Remote-Disc Lower-Layer Sess-Type  Sess-State UP-Time Remote-Addr
      2        0           IPv6        Single-Hop Down      00:00:00 fe80::223:e 9ff:fe42:dac3/128

  • The BIG-IP system sends IPv6 BFD INIT packets that include a recommended default hop limit of 64.

    You can verify the presence of these packets by using the tcpdump or other packet trace utility.

  • The BFD neighbor does not respond to the INIT with the expected UP packets.

    You can verify the absence of these packets by using the tcpdump or other packet trace utility.

  • Debug logs on the peer router indicate dropped BFD packets.
