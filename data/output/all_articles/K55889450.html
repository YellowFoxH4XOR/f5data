Known Issue

BIG-IP APM NT LAN Manager (NTLM) authentication for Remote Desktop Protocol (RDP) client gateway and Microsoft Exchange Proxy are incompatible with the Microsoft workaround for MS17-010 (WannaCry / EternalBlue).

This issue occurs when all of the following conditions are met:

  • You configure the BIG-IP system either as a gateway for RDP clients, or as a proxy for Microsoft Exchange ActiveSync, or use NTLM authentication for SWG Explicit Forward Proxy, or use the ECA:: iRules commands.
  • You configure the BIG-IP APM system to use NTLM authentication.
  • You follow the Microsoft workaround for MS17-010 and disable Server Message Block 1.0 (SMBv1 / SMB1) on the Windows server.
Microsoft has released security bulletin MS17-010 announcing a recommended software security patch to fix multiple vulnerabilities in SMBv1. A procedure to disable SMBv1 is listed as a workaround. When this workaround is implemented, NTLM authentication in BIG-IP APM fails for RDP client gateway deployments, and Microsoft Exchange ActiveSync proxy deployments. 

Impact

The BIG-IP APM system is unable to successfully authenticate clients using NTLM.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users are unable to authenticate when accessing RDP or Exchange services using the BIG-IP APM system.
  • The BIG-IP APM system generates messages to the /var/log/apm file that appear similar to the following example:

    01620000:3: <0x55abeb70> nlclnt[129010a0a] init: Error [0xc0000011,NT_STATUS_END_OF_FILE] connecting to DC 10.10.10.10

Workaround

To work around this issue, you have the following options:

Impact of workaround: Performing the following workarounds require modifying the Windows systems. You should thoroughly test changes during a scheduled maintenance window.

  • Install the recommended security patch for your Windows servers, rather than disabling SMBv1 on the Windows servers. This workaround alleviates the issue for both RDP client gateway and Exchange ActiveSync deployments.
  • For Exchange deployments, reconfigure the Windows servers to use Kerberos constrained delegation single sign-On (SSO) authentication, rather than NTLM authentication.
  • For RDP client gateway deployments using BIG-IP APM 13.0.0 or later, you can configure BIG-IP APM to launch the native RDP clients by clicking Native for the Client Type setting in the RDP configuration.
