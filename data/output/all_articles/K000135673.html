K000135673: F5OS-A backup fails to restore on rSeries r5k RMA device - "Maximum tenant size on this variant is 434GB"

Type
Support Solution
Published
2023-07-31
Updated
2023-07-31
Applies to
  • F5OS
  • F5OS-A
Source
https://my.f5.com/manage/s/article/K000135673

Description

Attempted to restore F5OS backup file on rSeries RMA replacement device.

Restoration failed:

Error: Database transaction failed.

An error similar to the following is seen in /var/F5/system/log/devel.log:

confd[110]: devel-c validate error {application, "ltmtenant has invalid value for storage/size. Maximum tenant size on this variant is 434GB."} for path /f5-tenants:tenants/tenant{ltmtenant}/config

Environment

  • rSeries
  • RMA replacement

Cause

This could happen if the original device had a 733GB disk, and a tenant was configured with a 455GB storage size.

The replacement device has a smaller disk (e.g. 700GB), which results in a slightly smaller maximum tenant size.

This issue is tracked by bug ID1320853.

Recommended Actions

To work around this issue, modify the tenant's configuration in the F5OS backup file that you are attempting to restore, reducing the storage size as appropriate, based on the maximum tenant size in the error message.

For example:

<tenant>
  <name>ltmtenant</name>
  <config>
    <name>ltmtenant</name>
    --snip--
    <storage>
      <size>455</size>      <--- Change this value
    </storage>
    --snip--
</tenant>
