Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when the provisioning hold time database variable is set to a non-zero value.

This issue occurs when all of the following conditions are met:

  • The tmm.pem.session.radius.provisioning.hold.time database variable is set to a non-zero value.
  • Multiple RADIUS sessions are established with the BIG-IP system, and one or more of the sessions is closed (for example, with a stop record).

Impact

The BIG-IP system may temporarily fail to process traffic while TMM restarts, and systems configured as part of a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • If configured for HA, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates TMM core files to the /var/core directory, which include a time stamp that correlates with the traffic interruption.

Workaround

To work around this issue, you can disable the tmm.pem.session.radius.provisioning.hold.time database variable by setting the value to 0. To do so, use the following command:

tmsh modify /sys db mm.pem.session.radius.provisioning.hold.time value 0
