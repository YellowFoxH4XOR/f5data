Issue

This article goes over how the BIG-IP WebAccelerator and BIG-IP AAM systems behave when they receive a request that does not include a Host header. For more information, refer to the section that applies to your version:

  • BIG-IP WebAccelerator 11.0.0 - 11.3.0 and BIG-IP AAM 11.4.0 and later
  • BIG-IP WebAccelerator 10.1.0 - 10.2.4
  • BIG-IP WebAccelerator 10.0.x
  • BIG-IP WebAccelerator 9.4.x

Note: The HTTP specifications include the following details regarding the use of the Host header:

  • HTTP/0.9 requests do not include a Host header or any other header.
  • HTTP/1.0 requests may include a Host header, but it is not required.
  • HTTP/1.1 requests must include a Host header.

BIG-IP WebAccelerator 11.0.0 - 11.3.0 and BIG-IP AAM 11.4.0 and later

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

In BIG-IP WebAccelerator 11.0.0 through 11.3.0 and BIG-IP AAM 11.4.0 and later, when a request is received that does not include a Host header, regardless of the HTTP version specified in the request, the BIG-IP system sends a 403 Forbidden HTTP response back to the client and closes the connection. The response sent to the client appears similar to the following example:

HTTP/1.1 403 Forbidden
Connection: Close
Content-Type: text/html
Content-Length: 82
Cache-Control: private
X-WA-Info: [V2.S0.A0.P0.N0.RN0.U0].[OT/html.OG/pages]

<html><body>Access Denied by intermediary. Domain not recognized.</body></html>

BIG-IP WebAccelerator 10.1.0 - 10.2.4

In BIG-IP WebAccelerator 10.1.0 through 10.2.4, all requests that do not have a Host header (regardless of the HTTP version) bypass the BIG-IP WebAccelerator system. These requests are sent to the origin web server (OWS), which replies according to its configuration. For example, the OWS may serve the requested content or it may respond with an HTTP 400 Bad Request response. Regardless of the type of reply, it will come from the OWS. The BIG-IP WebAccelerator system adds an X-PvInfo HTTP header to the response with S code of S10413, indicating that the request bypassed the BIG-IP WebAccelerator system.

For example:

X-PvInfo: [S10413.C0.A0.R0.G0].[OT/plaintext.OG/documents]

For more information about S codes, refer to the Viewing X-PvInfo response headers section of the Policy Management Guide for the BIG-IP WebAccelerator System.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.

Additionally, in BIG-IP WebAccelerator 10.1.0, when a request without a Host header bypasses the BIG-IP WebAccelerator system, messages are logged to the /var/log/wa/pvac.log file that appear similar to the following example:

debug WA Debug ( 6544): [ TmPlugin.cxx:3483 populateHeadersFromPlugin ] handleHeadersEnd failed with [0x36]
debug WA Debug ( 6544): [ TmPlugin.cxx:3485 populateHeadersFromPlugin ] [GET /
debug WA Debug ( 6544): ]
debug WA Debug ( 6544): [ TmPlugin.cxx:3487 populateHeadersFromPlugin ] Index [0x0]
debug WA Debug ( 6544): [ TmPlugin.cxx:3496 populateHeadersFromPlugin ] Value [GET]
debug WA Debug ( 6544): [ TmPlugin.cxx:3487 populateHeadersFromPlugin ] Index [0x1]
debug WA Debug ( 6544): [ TmPlugin.cxx:3496 populateHeadersFromPlugin ] Value [/]
debug WA Debug ( 6544): [ TmPlugin.cxx:3487 populateHeadersFromPlugin ] Index [0x2]
debug WA Debug ( 6544): [ TmPlugin.cxx:3496 populateHeadersFromPlugin ] Value []

Note: These debug messages are superfluous and should not be logged by the BIG-IP WebAccelerator system. For more information, refer to K11340: The BIG-IP WebAccelerator logs superfluous messages when a client request does not include a Host header.

BIG-IP WebAccelerator 10.0.x

When a request that does not include a Host header (regardless of the HTTP version) hits a BIG-IP WebAccelerator virtual server, the system transmits the following reply:

HTTP/1.1 403 Forbidden
Content-Type: text/html
Content-Length: 80
Cache-Control: private
X-PvInfo: [S0.C0.A0.RA0.G0.U0].[OT/html.OG/pages]

<html><body>Access Denied by intermediary. Domain not recognized.</body></html>

The BIG-IP WebAccelerator system logs the following messages to the /var/log/wa/pvac.log file:

debug WA Debug: [ PvSysAppManager.cxx:1173 appManagerHandleRequest ] Error [0x0] [Error text not available.]
debug WA Debug: [ PvSysAppManager.cxx:1187 appManagerHandleRequest ] Error [0x3c] [Access Denied by intermediary. Domain not recognized.]

Note: The Error [0x0] [Error text not available.] message is superfluous because it does not provide any useful information. For more information, refer to K11341: The BIG-IP WebAccelerator logs a superfluous message when it receives a request for an unmapped host.

BIG-IP WebAccelerator 9.4.x

  • When an HTTP/0.9 request hits a BIG-IP WebAccelerator virtual server, the system transmits the following reply:

    <html><body>The Host header was not present in the request.</body></html>

    The BIG-IP WebAccelerator does not log any messages to the /var/log/wa/pvac.log file.

  • When an HTTP/1.0 or HTTP/1.1 request that does not include a Host header hits a BIG-IP WebAccelerator virtual server, the system transmits the following reply:

    HTTP/1.0 400 Bad Request
    Content-Type: text/html
    Content-Length: 73
    Cache-Control: no-cache
    X-PvInfo: [S0.C0.A0.RA0.G0.U0].[OT/html.OG/pages]
    Connection: close

    <html><body>The Host header was not present in the request.</body></html>

    The BIG-IP WebAccelerator system does not log any messages to the /var/log/wa/pvac.log file.
