Description

When configuring BIG-IP ASM/AWAF to allow dynamically generated URLs that follow a specific pattern, such as URLs with random alpha-numeric values separated by periods and ending with .js (e.g., /api/146.75f39e26d11.js), administrators may attempt to use regular expressions (regex) for precise matching. While ASM/AWAF includes a RegExp Validator tool that can test regex patterns, these patterns cannot be applied directly to Allowed URL objects. Attempts to configure a wildcard URL with regex syntax result in the URL not matching as expected, and requests are blocked with "Illegal URL" violations. This limitation requires the use of broad wildcards (e.g., *.js), which may not meet security requirements for restricting access to specific URL patterns. 

Environment

  • BIG-IP ASM or Advanced WAF module
  • Security policies with Allowed URL objects
  • Applications generating dynamic URLs with random values
  • Wildcard URL configuration attempts using regex patterns
  • ASM RegExp Validator (GUI ›› Security ›› Options : Application Security : RegExp Validator)

Cause

BIG-IP ASM's Allowed URL configuration does not support regular expression matching. Wildcards in ASM do not interpret regex patterns; they only support standard wildcard characters (* and ?). This is documented behavior as described in K8623. When a regex pattern is entered as a wildcard URL name, ASM treats it as a literal string rather than a pattern to match, resulting in no matches and blocked requests. 

Answer/Recommended Actions

Current Limitation:

  • ASM Allowed URL objects only support wildcard matching using '*' (matches any characters) and '?' (matches a single character)
  • Regular expressions (PCRE or RE2) cannot be used in Allowed URL or parameter name configurations
  • The RegExp Validator tool is for testing purposes only and does not enable regex functionality in URL objects

Available Options:

  1. Use Standard Wildcards (with security considerations):

    • Configure a wildcard URL such as the sample URL object '/api/*.js'
    • Be aware this sample URL allows any '.js' file matching the pattern, which may present security risks
    • Document the security trade-off with your information security team

  2. Implement iRule-Based Solution:

    • Use an iRule to perform regex matching and selectively disable or modify ASM processing
    • Reference K000149611 for examples of using iRules to relax ASM functionality based on regex conditions
    • Note: This adds processing overhead compared to native ASM functionality

  3. Use Local Traffic Policy:

    • Create an LTM traffic policy with conditions matching the desired URL pattern
    • Configure actions to disable ASM for matching requests
    • Test thoroughly in a non-production environment before deployment

  4. Submit Tracking Updates:

    • Monitor BIG-IP ASM/AWAF release notes for future versions
    • Contact your F5 Account Manager or Sales Engineer for RFE status updates. Reference RFE ID 2227329 when inquiring about regex support for wildcard URL/Parameter matching
    • Note: RFE ID 2227329 has been filed for this feature request
