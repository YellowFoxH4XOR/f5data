Description

A "Module communication error detected" on psu-controller-1 (or psu-controller-2) is showing an unhealthy state based on the output of the "show system health" command, even after the underlying condition has been resolved.

The error appears as an unhealthy state and may persist due to a stale event that is not automatically cleared.

Typical symptoms include:

Environment

  • F5OS-C - (1.8.1, 1.8.2)
  • VELOS Controller - (CX410) 

Cause

A transient LOP communication timeout between the system controller and the PSU controller triggered a persistent module-communication-error alarm on the PSU controller.

Defect ID 2285041: psu-controller-1 module-communication-error not cleared.

Answer/Recommended Actions

  1. To clear the stale event, run the command below on both the active and standby controllers as the root user. 
    # docker exec -it diag-agent psf run PATCH:components/attributes component="chassis/hardware/psu/vpc1" attribute="module:communication-error" severity=info data.value=false eval=true

Note: If the issue is respective to controller-2, then update the above commands replacing  'vpc1' with 'vpc2'.

Impact: No service impact is expected when running any of the commands provided.

Verify The Status:

   2. Run "show system health" to confirm that psu-controller-1 (or psu-controller-2) now reports as healthy.      

If the issue persists after attempting a manual clear, please collect additional diagnostic data from both controllers as the root user and share it with support for further analysis.

To collect communication attributes:
docker exec -it diag-agent psf run get:components/attributes | grep vpc1 | grep "communication"

To check vpc-health:
docker exec -it platform-hal psf run GET:lop/object/vpc-health destSlot=PsuCtrl1

Note: If the issue is respective to controller-2, then update the above commands replacing  'vpc1' and 'PsuCtrl1' with 'vpc2' and 'PsuCtrl12'.
