Known Issue

This is the result of a known issue. The RESOLV::lookup and NAME::lookup iRule commands do not allow the use of a variable to substitute the DNS server parameter. If you attempt to create an iRule using the RESOLV::lookup or NAME::lookup commands with a variable instead of an IP address or a virtual server name, the Configuration utility and command line will return an error message that appears similar to the following example:

01070151:3: Rule [<irule name>] error: line 2: [can't find virtual] [RESOLV::lookup @<variable name> <hostname for resolution>]

For example, in the following irule-243299 iRule, a user attempted to use the variable $bar for the DNS server parameter:

when HTTP_REQUEST {
RESOLV::lookup @$bar foo.com
}

In this situation, the BIG-IP system would return the following error message:

01070151:3: Rule [irule-243299] error: line 2: [can't find virtual] [RESOLV::lookup @$bar foo.com]

Note: For more information about the NAME::lookup and RESOLV::lookup commands, refer to DevCentral iRules Wiki. A DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

F5 Product Development tracked this issue as ID 243299 and ID 247863 (formerly CR136229), and it was fixed in BIG-IP LTM version 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by configuring the RESOLV::lookup and NAME::lookup commands with an IP address or virtual server name for the DNS server parameter.
