K30051040: How to bypass ASM local logging rate limit

Type
Support Solution
Published
2022-12-30
Updated
2022-12-30
Applies to
  • Virtual Editions
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K30051040

Description

There's a rate  limit of ASM while logging security events locally. By default, this is  200 requests per second. This is controlled by variable "PRXRateLimit".
This number is divided by number of bd threads.  That is, in case of a 4 core system, each tread can send 50 requests per second, 200/4(core).

When the limit is reached, a log similar as below would be seen in the /var/log/ts/bd.log

ECARD_POLICY|DEBUG |Jan 01 1999 12:00:00.000|XXXXX|proxy_log.c:XXXX|local filter: LRN/tightening RATE LIMITED: req in cur sec: 25 time: XXXXXXXX limit: 25 (RPS)
 

Environment

  • Virtual server with security log profile logging locally attached

Cause

  • Device is logging locally beyond its limits.

 

Recommended Actions

Some of the functionalities of BIG-IP are load balancing, persistence, mitigating attacks, etc.

There are limited resources available for logging and this varies if the BIG-IP is running on an appliance or a virtual edition.

It is recommended to take advantage of remote logging.

In some cases, it is desired to log locally and therefore, some adjustments can be made.

The following shows two options available:
 

  • Modify the variable PRXRateLimit

Note: To find the settings browse to Security > Options > Application Security > Advanced Configuration > System Variables > PRXRateLimit

  • Enable 'Guarantee Logging'. This option will cause you to bypass the rate limit variable completely and all requests will be logged locally.
Note: Enabling 'Guarantee Logging' on the logging profile may lead to a much higher resources usage in the system.
