Topic

You should not enable both SYN cookie protection and Loose Initiation together in a FastL4 profile.

Description

Enabling both the Loose Initiation feature and SYN cookie protection in a FastL4 profile may result in unexpected behaviors.

For example, you may encounter one or more of the following symptoms:

  • Servers receive raw data for a connection that is not established.

    When software SYN cookie protection is activated, the BIG-IP system will proxy the initial TCP handshake and use SYN cookies to validate the request before it connects to the server and attempts to send data. However, with hardware SYN cookie protection, the BIG-IP system passes the first piece of data after the TCP handshake to the back-end server without sending a SYN. As a result, servers may receive raw data for a connection that is not established.

  • Your BIG-IP system sends multiple RST packets to the client.

    If a client sends an ACK that fails a SYN cookie check, the BIG-IP system will create a flow and send client data to the server, even though no connection to the server has been established for the client. This may result in the system sending multiple RST packets to the client.

If you need to enable the Loose Initiation feature, you need to disable the SYN cookie protection feature.

Recommendations

When you need to configure a FastL4 profile to enable the Loose Initiation feature, you should ensure the SYN cookie protection feature is disabled. To do so, perform one of the following procedures:

  • Using the Configuration utility to disable SYN cookie protection
  • Using the tmsh utility to disable SYN cookie protection

Using the Configuration utility to disable SYN cookie protection

Impact of Procedure: BIG-IP does not activate the SYN cookie feature to protect the system against SYN flood attacks. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
Important: Using the Configuration utility to disable SYN cookie protection is not available for BIG-IP versions 15.0.0 and later. To disable FastL4 SYN cookie protection for BIG-IP versions 15.0.0 and higher use the steps outlined in the next section Using the tmsh utility to disable SYN cookie protection.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Protocol > FastL4.
  3. Select the FastL4 profile name you are configuring.

    Note: F5 recommends that you create a custom profile rather than edit a default profile. For more information, refer to K14488: Working with profiles.

  4. Disable the SYN Cookie Protection feature by performing one of the following actions as applicable to your specific version:
    • BIG-IP 13.x:

      For SYN Challenge Handling, select Disable Challenges.

    • BIG-IP 11.5.1 - 12.x:

      Clear the check boxes for Hardware SYN Cookie Protection and Software SYN Cookie Protection.

      Note: The Hardware SYN Cookie Protection option displays only on systems capable of performing hardware SYN cookie protection.

  5. Select  Update.

Using tmsh to disable SYN cookie protection

Impact of procedure: BIG-IP does not activate the SYN cookie feature to protect the system against SYN flood attacks. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. Disable SYN cookie protection for a FastL4 profile using the option for your specific version:

    Note: F5 recommends that you create a custom profile rather than edit a default profile. For more information, refer to K14488: Working with profiles.

    • BIG-IP 13.x and higher

      Disable both hardware and software SYN cookie protection with a single command. To do so, use the following tmsh command syntax:

      modify /ltm profile fastl4 <profile_name> syn-cookie-enable disabled

    • BIG-IP 11.5.1 - 12.x

      You must disable hardware and software SYN cookie protection separately.

      • To disable hardware SYN cookie protection, use the following command syntax:

        modify /ltm profile fastl4 <profile_name> hardware-syn-cookie disabled

      • To disable software SYN cookie protection, use the following command syntax:

        modify /ltm profile fastl4 <profile_name> software-syn-cookie disabled

  3. Save the configuration by entering the following command:

    save /sys config
