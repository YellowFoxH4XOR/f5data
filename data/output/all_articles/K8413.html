K8413: Passwordless certificate-based authentication fails when master group's users are external

Topic

Master groups that use passwordless client certificate authentication and have external users (as opposed to users that exist locally in the FirePass database) must assign users dynamically using dynamic group mapping. By design, use of fallback groups to assign users to the master group is not permitted. You must configure dynamic group mapping to assign users to a master group using passwordless client certificate authentication.

When creating a master group that will use passwordless client authentication, if you select External rather than Local in the Users in group: drop-down menu, you must enable dynamic group mapping, create a client certificate mapping method, and an entry in the master group mapping table in order for users to log in.  This requirement also applies to converting an existing master group with external users from a different type of authentication to passwordless client certificate authentication. 

If a master group that uses passwordless client certificate authentication does not have dynamic group mapping of users fully configured, the users in the master group will fail to log in, passwordlessly. Instead, the users will see the page, which is presented to authentication failures, and will not be able to log in to the FirePass controller. Records in the Reports: Logons page will indicate that no master group could be assigned.

For configuration tasks required to set up dynamic group mapping for master groups that use passwordless client certificate authentication, consult the FirePass Administrators Guide and the FirePass controller's online help.
