K659: Adding aliases to wide IPs can lead to NameSurfer zone corruption

Published

Known Issue

This is the result of a known issue. NameSurfer tracks wide IP and alias entries based upon the order in which they are reported by 3dnsd. 3dnsd reports the wide IP and the aliases to NameSurfer in alphabetical order. This does not cause a problem when the wide IP and any aliases are newly created, because this information is added to NameSurfer incrementally; however, when you add a new alias that supersedes an existing wide IP name in the alphabetical order, and then make a change to the new wide IP, it can cause numerous problems.

This issue occurs because NameSurfer assumes that the alias (which is now reported first) is the wide IP, so it applies the wide IP changes to the alias.

F5 Product Development tracked issue as CR37656 and CR41853.

Workaround

To avoid this issue, perform the following steps when adding a new alias:

  1. Remove the wide IP, which the new alias would supersede in alphabetical order.
  2. Add the desired alias.
  3. Recreate the wide IP.
