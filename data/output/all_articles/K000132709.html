K000132709: FEP process is not running on the SDC node but shows its running in Monit

Description

root@sdclab ~]# monit status sdclab_fep-local-tcp

Environment

  • SDC 5.1

Cause

The process that is responsible for the said SDC component is stuck and the file in /dev/shm for that process still exist and is hindering the start of a new process for the said SDC component.

Example : 

[root@sdclab shm]# ll
total 48
-rw-r--r-- 1 root  root    6 Jan 25 23:17 sdclab_cpf1.pid
-rw-r--r-- 1 root  root    6 Jan 25 23:20 sdclab_feb-l-connection-sctp.pid
-rw-r--r-- 1 root  root    6 Jan 25 23:20 sdclab_fep-geo-sync-tcp.pid
-rw-r--r-- 1 root  root    6 Jan 25 23:20 sdclab_fep-local-2-sctp.pid
-rw-r--r-- 1 root  root    6 Jan 25 23:19 sdclab_fep-local-sctp.pid
-rw-r--r-- 1 root  root    6 Jan 25 23:17 sdclab_fep-local-tcp-Gy.pid
-rw-r--r-- 1 root  root    6 Jun 3 2020 sdclab_fep-local-tcp.pid <<<<<

 Recommended Actions

To start a new process for the said SDC component we need to delete the file in /dev/shm and restart the SDC component in monit.

Steps : 
1. #cd /dev/shm/
2. #rm <file from /dev/shm>
3. #monit stop <SDC component>
4. #monit start <SDC component>
5. Then check if process come up , and check pid
  # monit status <SDC component>
  # jps -m

Example : 
1. #cd /dev/shm/
2. #rm sdclab_fep-local-tcp.pid
3. #monit stop sdclab_fep-local-tcp
4. #monit start sdclab_fep-local-tcp
5. Then check if process come up , and check pid
  # monit status sdclab_fep-local-tcp
  # jps -m
