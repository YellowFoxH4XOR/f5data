Description

Some virtual servers are showing down on active BIG-IP unit and same virtual servers are up on standby unit.

After failing over, both active and standby BIG-IP units health monitor checks marks pool-member UP.

However after some time, active unit again marks  pool members  down causing virtual servers to go down as well

 

Environment

  • BIG-IP HA
  • Link aggregation (LAG)  to cisco ACI switches
  • Health monitor

Cause

  • Cisco ACI switch connected to BIG-IP has multiple mac entries for a self-IP.

        For instance on Cisco switch you may see something similar to below :

        00:00:5E:00:53:00 10.27.226.68 >> vlan1
        00:00:5E:00:53:01 10.27.226.68 >> vlan2
        00:00:5E:00:53:02 10.27.226.68 >> vlan3

  • Having multiple mac entries of Self IP address on multiple vlans causing Pool members to flap.
  • Health monitor traffic initiating by BIG-IP on a specific vlan are returned on a different vlan causing health checks to fail.

Recommended Actions

  1. Deleting duplicate entries on the switch should probably fix the issue.
  2. If this is still re-occuring after a while, try capturing traffic on switch and BIG-IP and see where the duplicate arp entry is coming from
  3. If this issue cannot be reproduced in a short time where you cannot leave capture open for a while, try using SPAN ( Switch port Analyser ) on cisco switch interface to monitor for long hours.
  4. You may need to engage Cisco technical support to resolve this issue.
