Description

While using tenants, Migrated virtual servers are showing up in individual partitions, none of them are under /Common partition
For example, if you have 3 virtual servers configured and those are called "VIP_1", "VIP_2", "VIP_3" after migrating you will have the following partitions:
  • /Common
  • /TenantX/VIP_1
  • /TenantX/VIP_2
  • /TenantX/VIP_3
All of your Virtual Servers will be under individual TenantX partitions. X being a predefined value for the Tenant

Environment

  • BIG-IP LTM Licensed
  • Using tenants
  • Migration was done with Journeys per application.

Cause

Journeys does not offer to migrate virtuals to /Common partition.
By default, JOURNEYS creates one tenant per application.
Common is a special reserved name, representing objects shared between tenants.
Represented by partitions on the BIG-IP level.

Recommended Actions

  1. Review individual partitions to be sure all configurations were migrated successfully.
  2. If you have any issues or further questions please reach out to the Journeys team on GitHub

Additional Information

JOURNEYS - BIG-IP upgrade and migration utility
