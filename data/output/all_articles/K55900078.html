Known Issue

Creating Secure Sockets Layer (SSL) certificates, keys, Certificate Revocation Lists (CRL), or Certificate Signing Request (CSR) objects from the TMOS Shell (tmsh) or iControl representational state transfer (REST) do not automatically append file extensions to file objects.

This issue occurs when one of the following conditions is met:

  • You use the create sys file command to create an SSL certificate, key, CRL, or CSR object file.
  • You use iControl REST commands to create an SSL certificate, key, CRL, or CSR object file.

Impact

The BIG-IP Configuration utility is unable to consistently manage certificates.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Certificates, keys, CRL, or CSR object files are created with no extension if you do not explicitly specify one.
  • The BIG-IP Configuration utility reports an error message that appears similar to the following examples:

    An error has occurred while trying to process your request

    No Certificate

  • The BIG-IP Configuration utility is not able to create an SSL certificate list archive containing one of these files, and reports an error message that appears similar to the following example:

    Key management library returned bad status: -2, Not Found

Resolution

Status

F5 Product Development has assigned ID 535122 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can explicitly include the appropriate file extension when creating the object using tmsh or iControl REST.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
