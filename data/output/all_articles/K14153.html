Known Issue

The BIG-IP system may fail to renegotiate Secure Sockets Layer (SSL) sessions.

This issue occurs when all of the following conditions are met:

  • The virtual server references a Client SSL profile.
  • The Renegotiation setting is enabled in the profile.
  • A client that uses Java-based SSL libraries attempts to renegotiate an SSL session.

Impact

SSL connection failures may impact your application.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • SSL clients experience intermittent connection failures.
  • If SSL debug is configured, a message logs to the /var/log/ltm file. The message appears similar to the following example:

    debug tmm1[<pid>]: 01260009:7: Connection error: ssl_hs_cn_vfy_fin:1451: bad verify data (20)

    Note: For information about enabling SSL debug, refer to K10237: The log level for peer certificate verification messages is now set to 'debug'.

Workaround

To work around this issue, you can disable SSL renegotiation for the affected profile. To do so, perform the following procedure:

Impact of workaround: Your system may experience a varying performance impact, depending on the frequency of SSL renegotiated sessions.

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Local Traffic > Profiles > SSL > Client.
  3. Select the SSL profile associated with the affected virtual server.
  4. From the Configuration menu, select Advanced.
  5. Clear the Renegotiation option.
  6. Click Update.

All new SSL connections now use this new configuration.
