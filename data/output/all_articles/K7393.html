K7393: The BIG-IP ASM includes Attack table data in the configsync UCS file, causing the configsync operation to fail

Known Issue

This is the result of a known issue. The BIG-IP ASM attack tables, including ATTACKS and ATTACK_EVENTS, are used for logging and analysis, and they normally include a large amount of data. The BIG-IP ASM includes Attack table data in the configsync UCS file, causing the standby system to time out during the configsync operation.

F5 Networks Product Development tracked this issue as CR77865, and it was fixed in BIG-IP ASM version 9.4.1. For information about upgrading, refer to the BIG-IP ASM Release Notes.

Workaround

You can work around this issue by removing the Attack table data from the configsync UCS file on both the active and standby BIG-IP ASM units. To do so, perform the following procedure:

  1. Log in to the command line.
  2. Use a text editor to edit the /var/ts/tools/ts_configsync_my.cnf file.
  3. Change the following lines (starting at line 80) from: 
    


# CONFIG_SYNC:  DCC.ATTACKS

# CONFIG_SYNC:  DCC.ATTACK_EVENTS

    To:

    
ignore-table  = DCC.ATTACKS

ignore-table  = DCC.ATTACK_EVENTS
  4. Save the changes.

Note: Test the configsync operation several times to verify the configsync process was successful. The first attempt to perform the configsync may fail due to the original Attack table being truncated on the standby unit.
