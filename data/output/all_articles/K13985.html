Known Issue

BIG-IP Link Controller fails to create the necessary redundant server object when creating a high availability (HA) pair.

This issue occurs when all of the following conditions are met:

  • You attempt to create a high-availability pair of BIG-IP Link Controller systems.
  • You use the gtm_add command to copy the configuration from one BIG-IP Link Controller system to another.

Impact

The first BIG-IP Link Controller system configured will be unable to communicate with the peer, and the second BIG-IP Link Controller system configured will be unable to communicate with itself or the peer.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H402800 on the Diagnostics > Identified > Medium screen.
  • The server object contains the self IP address of only the first BIG-IP Link Controller system configured instead of both BIG-IP Link Controller self IP addresses.
  • iQuery communication between both BIG-IP Link Controller systems fails to establish.
  • The second BIG-IP Link Controller system reports an error message to the /var/log/gtm file that appears similar to the following example:

    011a001c:5: SYNC server.crt from 192.168.0.8 skipped. Reason: cannot find my box

Workaround

To work around this issue, you can manually add the peer self IP address on the first BIG-IP Link Controller system, and then run the gtm_add utility on the second BIG-IP Link Controller system. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) on the source BIG-IP Link Controller system by typing the following command:

    tmsh
  2. Add the peer self IP address to the BIG-IP GTM server object by using the following command syntax:

    modify /gtm server <server object name> addresses add { <peer self IP address 1> <peer self IP address 2>...{ device-name <peer object name> } }

    For example, to add a peer BIG-IP Link Controller system named lc2.example.com with self IP addresses 192.168.0.2 and 192.168.10.2 to the BIG-IP GTM mylc.example.com server object, you would type the following command:

    modify /gtm server mylc.example.com addresses add { 192.168.0.2 192.168.10.2 { device-name lc2.example.com } }
  3. Save the change by typing the following command:

    save /sys config gtm-only
  4. Log in to the command line of the peer BIG-IP Link Controller system.
  5. To replace the BIG-IP GTM configuration and add the peer BIG-IP Link Controller system to the BIG-IP GTM synchronization group, use the following command syntax:

    gtm_add <source BIG-IP LinkController IP address>

    For example, to add the peer using the source BIG-IP Link Controller with IP address 172.28.22.151, you would type the following command:

    gtm_add 172.28.22.151
  6. Follow the on-screen instructions to complete the process.
