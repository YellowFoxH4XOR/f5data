Description

GUI becomes un-responsive and doesn't load.

  • GUI is slow to load.
  • Loading configuration has long duration with no page loaded.
  • Tomcat has Out of Memory messages logged.

Environment

  • BIG-IP
  • Management access

Cause

If you notice the following messages in the var/log/tomcat/catalina.out file:

# java.lang.OutOfMemoryError: Java heap space
# -XX:OnOutOfMemoryError="/usr/bin/restart_tomcat"
# Executing /bin/sh -c "/usr/bin/restart_tomcat"

Recommended Actions

It's worth ruling out common issues. One such is ID 1856513 (see related content for more info)

 Often low free tomcat memory results in higher garbage collection activity, resulting in substantial CPU use by tomcat even when GUI is not in use. Typically it is possible to incrementally increase tomcat memory while observing tomcat CPU use in top to help judge when enough has been added. CPU use should lower and end up be close to zero when memory is adequate.
Tomcat appears as a java process but uniquely has the user 'tomcat' rather than 'root'. Note the pid of tomcat will change after each restart, restarts being necessary after giving it more memory. Give it a minute or so after restarts before assessing CPU, as it is busy shortly after a restart.

On LTM systems it should be rare to need more than 100 or 150 for provision.tomcat.extramb, unless there is extremely large config or high requirements for Guided Config/iAppsLX.

 Impact of procedure: The following procedure requires that you restart the tomcat process. The Configuration utility will not be accessible while the tomcat process restarts.

  1. To increase Tomcat memory run the following, with <value> starting at 50 or 100, increasing 50 at a time as necessary.
    tmsh modify /sys db provision.tomcat.extramb value <value>
  2. To view change run this command:
    tmsh list sys db provision.tomcat.extramb
  3. Restart the tomcat process by typing the following command 
    bigstart restart tomcat

Additional Information

Some parts of the GUI use the REST API, and it may be a problem with restjavad that is causing issues.
A common issue is ID 1826505 and it's worth removing that as a possible cause before increasing restjavad memory.

If you need to know more about increasing  restjavad memory the following article may be useful:

K000133258: Provisioning restjavad memory with provision.restjavad.extramb
