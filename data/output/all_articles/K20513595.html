Description

After upgrading from BIG-IP 12.x and earlier to BIG-IP 13.x or later, SYN Cookie protection may be re-enabled on FastL4 and TCP profiles after having been explicitly disabled prior to the upgrade.

Environment

  • FastL4 and TCP profile(s) which had SYN Cookie protection explicitly disabled prior to upgrade

Cause

When upgrading to BIG-IP 13.x or later, the parameters hardware-syn-cookie and software-syn-cookie are deprecated and replaced with syn-cookie-enable as described in K00164450: The syn-cookie-enable option replaces SYN Cookie Protection options. Due to an anomalous condition described in Bug ID 771173, the hardware-syn-cookie value is not properly honored and this can result in profiles having syn-cookie-enable set to enabled when it should be disabled (and thus re-enabling SYN Cookie Protection).

The hardware-syn-cookie and software-syn-cookie values in the configuration are accurate after upgrade to BIG-IP 13.x or later until the first time the running configuration is saved to disk and subsequently loaded with the tmsh load /sys config command. Those values, while deprecated, provide sufficient information to determine the intended value for syn-cookie-enable. Due to Bug ID 771173, syn-cookie-enable is set to enabled for all profiles; however, you can set it explicitly to disable for appropriate profiles, and this value persists.

Recommended Actions

After upgrading and prior to saving configuration, you should use the following procedure to determine which FastL4 and TCP profiles should have syn-cookie-enable disabled and to set the value to disable. Afterwards, you should save and load the configuration to ensure that both the running and written configuration are fully accurate and identical.

Important: If you have already modified or saved configuration after the upgrade to BIG-IP 13.x or later, you should not proceed with the following procedure. You should re-attempt the upgrade and then complete the following procedure before performing any actions to the configuration.

  1. If any FastL4 profiles are customized with hardware or software SYN values in the previous version, enter the following command to ensure they are updated correctly:

    tmsh -c 'cd /; list ltm profile fastl4 one-line recursive' 2>/dev/null | grep 'hardware-syn-cookie disabled' | grep -v 'software-syn-cookie enabled' | awk -F '[/{]' '{printf("Disabling Syncookie Challenge for fastL4 profile " $2 "\n"); system("tmsh modify ltm profile fastl4 " $2 " syn-cookie-enable disabled")}'

  2. If any TCP profiles are customized with hardware SYN values in the previous version, enter the following command to ensure they are updated correctly:

    tmsh -c 'cd /; list ltm profile tcp one-line recursive' 2>/dev/null | grep 'hardware-syn-cookie disabled' | awk -F '[/{]' '{printf("Disabling Syncookie Challenge for tcp profile " $2 "\n"); system("tmsh modify ltm profile tcp " $2 " syn-cookie-enable disabled")}'

  3. Save the customized syn-cookie-enable values to disk and then reload configuration to ensure the changes took correctly:

    tmsh save sys config > /dev/null && tmsh load sys config > /dev/null && echo "Workaround complete. Please review all fastl4 and/or tcp profiles to confirm desired Syncookie Challenge configuration."
