K000158991: After subscription renewal NGINX logs error "[notice] 2380#2380: renewed license does not match the original one; using original license"

Published
2026-01-03
Updated
2026-01-03
Applies to

  • NGINX Plus: R36
Source
https://my.f5.com/manage/s/article/K000158991

Description

  • You renewed NGINX Plus subscription.
  • After that, however, NGINX started to log error message "[notice] renewed license does not match the original one; using original license" despite updating the JWT token file at /etc/nginx/license.jwt.
  • You need clarification on whether the above error indicated a licensing problem and how to resolve the warning.

Environment

  • NGINX Plus R36
  • Auto-renewal feature enabled (introduced in R35)
  • JWT token manually updated at /etc/nginx/license.jwt
  • Auto-fetched license stored at /var/lib/nginx/state/nginx-mgmt-license

Cause

  • The warning message "renewed license does not match the original one; using original license" was triggered due to manually updating the JWT token at /etc/nginx/license.jwt with the new subscription credentials.
  • With NGINX Plus R35+ auto-renewal enabled, the system expects the original JWT file to remain unchanged while the auto-fetched renewed license is stored separately at /var/lib/nginx/state/nginx-mgmt-license.
  • When both files contained identical tokens, NGINX detected this mismatch in the expected renewal pattern and logged the warning, though it continued operating correctly using the valid license from /var/lib/nginx/state/nginx-mgmt-license.

Recommended Actions

There are a number of action one can take

  1. Leave everything as is and the error eventually resolved itself, or
  2. Re-apply old license JWT file at location /etc/nginx/license.jwt, or
  3. Move the file /var/lib/nginx/state/nginx-mgmt-license to a backup location: sudo mv /var/lib/nginx/state/nginx-mgmt-license /var/lib/nginx/state/mgmtLicense.bak
    • Validate and reload NGINX configuration to allow the system to re-fetch the license automatically.
  • For future subscription renewals with auto-renewal enabled (R35+), do not manually update the JWT token at /etc/nginx/license.jwt. The auto-renewal mechanism will fetch and store the new license at /var/lib/nginx/state/nginx-mgmt-license automatically.
  • Manually update only the repository certificate/key files (repo.crt and repo.key) when needed for package updates, as these are not covered by auto-renewal.
  • The original JWT file at /etc/nginx/license.jwt should remain unmodified to serve as the baseline reference for the auto-renewal process.
