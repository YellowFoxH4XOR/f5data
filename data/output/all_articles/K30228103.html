Issue

Error Message

err tmm[<TMM Number>][<PID>]: 014c0001:3: diameter <Diameter area encountering a problem> error <error>

In this error message, note the following:

  • <TMM Number> is the Traffic Management Microkernel (TMM)  number that is reporting a problem.
  • <PID> is the process ID for the TMM process.
  • <Diameter area encountering a problem> is the specific area within Diameter that is encountering the error.
  • <error> is the specific error encountered.

For example:

  • BIG-IP 12.0.0 and later
err tmm1[6286]: 014c0001:3: DIAMETER process ingress error Improper version
  • BIG-IP 11.6.x and earlier
err tmm1[6286]: 014c0001:3: diameter process ingress error Improper version

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file
Description

This message occurs when one of the following conditions is met:

  • The Diameter retransmit callback is called and the message cannot be retransmitted.
  • An egress message fails to write or the i/o queue fails to process.
  • The watchdog callback is called and a signal fails to be sent to the watchdog.
  • The Diameter event handler is called and one of 23 errors occurs.  The most common of these is Prerequisite operation not in progress, which usually occurs if handshake fails.
  • The input cannot be parsed, or the I/O queue cannot be processed on ingress.
  • An invalid attribute-value-pair (AVP) query is attempted.

Impact

In each condition, the system logs an error.  In all cases except the invalid AVP case, the system creates and handles a HUDEVT_ABORTED event.

Recommended Actions

When the system generates this error message, consider performing the following actions:

  • If the retransmit callback is called and the message cannot be retransmitted, there is no workaround.  To mitigate this problem, try increasing the retransmit attempt limit in the profile configuration.
  • If an egress message cannot be written, it's because an AVP is too big or cannot be parsed.  Make sure peer servers are sending well-formed AVPs.
  • If the watchdog callback fails, it's because of an out-of-memory error.  Try reducing traffic on this hardware, or try making changes to the configuration to free more memory, such as removing unneeded iRules or changing the persistence timeout.
  • If a handshake fails, check your network status and ensure proper configuration of the Diameter peer that failed the handshake.
  • If parsing the input fails, it means that the input is not properly formed or an out of memory error has occurred.  Check that you have adequate resources and ensure proper configuration of Diameter peers.  If the error message says "Improper version," make sure the version of TMOS your system is running supports the messages it's receiving.
  • If an invalid AVP query occurs, a peer has passed an invalid AVP, possibly maliciously.  Make sure the Diameter peer is properly configured.
