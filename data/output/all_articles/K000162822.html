K000162822: BIG-IP sends TLS generic alert 40 on the wire for ALPN mismatch, despite generic-alert disabled

Type
Support Solution
Published
2026-08-07
Updated
2026-08-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000162822

Description

When a BIG-IP LTM virtual server uses SNI-based client SSL profile selection with an HTTP/2 profile, an incompatible ALPN proposal can cause BIG-IP to transmit TLS alert 40 (handshake_failure) instead of TLS alert 120 (no_application_protocol). BIG-IP may log ssl_alpn_match:5640: alert(120) while a BIG-IP-side packet capture shows alert 40 on the wire, even when the SNI-specific client SSL profile has generic alerts disabled.

Environment

  • Product: BIG-IP LTM
  • Virtual server configured with:
    • An HTTP/2 profile
    • Multiple client SSL profiles selected through SNI
    • A default fallback client SSL profile
  • HTTP/2 profile settings:
    • ALPN activation enabled
    • Enforce TLS requirements enabled
  • Client SSL profile settings:
    • Generic alerts disabled on the SNI-specific profile
    • Generic alerts enabled on the default fallback profile
  • ClientHello includes an SNI value and an ALPN proposal that is not accepted by the HTTP/2 configuration, such as:
    • h
    • h3
    • An otherwise incompatible ALPN list

Cause

Bug ID 2441197.

During ALPN validation, BIG-IP processes the mismatch before the SNI-specific client SSL profile context is fully applied for alert generation. The alert is therefore generated using the generic-alert setting from the default fallback client SSL profile.

Answer/Recommended Actions

To have BIG-IP send TLS alert 120 (no_application_protocol) for the ALPN mismatch:

  1. Identify the default fallback client SSL profile assigned to the virtual server, such as /Common/default_clientssl.
  2. Disable generic alerts on the default fallback client SSL profile.
  3. Save and deploy the configuration.
  4. Retest using the same SNI value and incompatible ALPN proposal.
  5. Confirm the result with a BIG-IP-side packet capture. The transmitted TLS alert should be alert 120.

It is not necessary to disable generic alerts on every SNI-specific client SSL profile. The default fallback profile controls the alert generated in this ALPN/SNI processing path.

Additional Information

  • With only one client SSL profile configured and generic alerts disabled, BIG-IP sends alert 120 for an ALPN mismatch.
  • With SNI profile selection enabled, the same mismatch can result in alert 40 when generic alerts are enabled on the default fallback profile.
  • A valid SNI value and compatible ALPN proposal, such as h2, completes successfully.
  • The BIG-IP log message reporting alert 120 describes the internal ALPN validation result; it does not necessarily identify the alert value transmitted on the wire.
  • Disabling generic alerts on the default fallback profile changes the transmitted alert behavior for this processing path and may affect other connections that use that profile.
