Description

BIG-IP DNS provides dns responses for wideip where all associated pools are down. 
For example, a wideip www.example.com has two pools with a single pool member, 192.0.2.150 and respectively 192.0.2.151.

Sample wideip and pool status.

gtm wideip a www.example.lab {
    load-balancing-decision-log-verbosity { pool-selection pool-traversal pool-member-selection pool-member-traversal }
    pools {
        www.example.lab_pool1 {
            order 0
        }
        www.example.lab_pool2 {
            order 1
        }
    }
}

[dnsadmin@bigipA:Active:Standalone] config # tmsh show gtm pool a

When all pools are down, BIG-IP DNS still returns the answer:

# dig +short @192.0.2.1 www.example.com
192.0.2.150
192.0.2.151

Environment

  • BIG-IP DNS/GTM
  • Bind
  • DNS profile
  • WideIP Pool

Cause

This is by design.
When a wideip is created, all pool members are added in the BIND configuration as A records for the wideip domain name. Default DNS profile settings Unhandled Query Actions and Use BIND Server on BIG-IP are set to allow DNS queries to the local BIND database when all pools are down. In the case the default behaviour is undesirable in a given environment then follow steps under Recommended Actions for BIG-IP DNS to return a no error response with no DNS records.

Recommended Actions

Create a custom DNS profile associated with the DNS listener used to get wideip DNS records and set Unhandled Query Actions to No Err

  1. Local Traffic > Profiles > Services > DNS click create and provide desired DNS profile name
  2. Under DNS Features, locate Unhandled Query Actions and set it to No Err.
  3. Click Finished
  4. Attach the custom DNS profile to the DNS listener.

After the change, The BIG-IP will now return NOERROR response with empty DNS records.
