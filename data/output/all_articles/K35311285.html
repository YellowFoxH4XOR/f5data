Description

  • When a failover of AWS BIG-IP occurs, all Elastic IP's, routes etc. remain attached to the now standby device.

  • errors similar to the ones below might appear in /var/log/restnoded.log, but only if 'silly' logging level is in enabled.

finest: [f5-cloud-failover] Uploading data to: f5cloudfailover/f5cloudfailoverstate.json
finest: [f5-cloud-failover] Function error, retrying: Access Denied Retries left: 50

  • IAM role contains all policy actions described here.


Environment

  • BIG-IP is using the F5 Cloud Failover Extension
  • S3 bucket has AWS KMS encryption enabled.


Cause

If AWS KMS encryption has been enabled on the S3 bucket, additional policy actions need to be added to your IAM role.

Recommended Actions

  1. Add the kms:GenerateDataKey action to your IAM policy or, disable encryption on the S3 bucket. This is discussed in the link found in the Related Content section.

Additional Information

Enabling 'silly' logging level is described in the tips section for troubleshooting Cloud Failover extension. See link provided in the Relation Content section.
