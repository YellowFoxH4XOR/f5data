Known Issue

This is the result of a known issue. VLAN failsafe is a high-availability feature that allows the BIG-IP system to monitor for network failure on VLANs and take appropriate action. If the BIG-IP system detects a loss of network traffic, it will generate VLAN failsafe traffic in an attempt to elicit a response from a network device.

When the VLAN failsafe timeout is set to a low value (five seconds or less), the BIG-IP system creates connection flow and multicast listener objects to generate traffic and check the status of the network connected to the VLAN interface. The BIG-IP does not properly release the connection flow and listener objects. As a result, a memory leak occurs.

Important: F5 does not recommend setting the VLAN failsafe timer to a value lower than five seconds. For more information, refer to K7066: Overview of VLAN failsafe.

When this issue occurs, you may observe one or more of the following symptoms on the BIG-IP system:

  • Memory allocation for TMM, connection flow, and listener objects is high or at peak levels.

    For example, the following bigpipe memory output shows that memory allocation for connection flow and listener objects are both at peak levels; this may be the case even though the virtual server connection count for the system is low:

    MEMORY STATISTICS --
    | (Host) Total = 371.6MB Used = 103.3MB
    | (TMM) Total = 3.632GB Used = 2.883GB
    | SUBSYSTEM Alloc Max Obj size
    | connflow 1.383G 1.383G 192
    | laddr 19600 19600 56
    | listener 1.852G 1.852G 256
    | xfrag 6.140M 6.936M 2048

  • The BIG-IP system does not allow new connection requests. For example, once the system memory reaches the reaper high-water mark, connections are not allowed until the available memory reduces to the low-water mark threshold.

    When this behavior occurs, error messages similar to the following examples are logged to the /var/log/ltm file:

    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode activated. (117504/138240 pages)
    tmm tmm[<PID>]: 011e0002:4: sweeper_update: aggressive mode deactivated. (117503/138240 pages)

  • The BIG-IP system produces a core file.

F5 Product Development tracked this issue as CR100352, and it was fixed in BIG-IP version 9.4.6. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, or WebAccelerator release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2 issued for BIG-IP version 9.4.5. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

If you determine that your BIG-IP system is affected by this issue, you can immediately resolve the memory allocation issue by running the bigstart restart command at the command line.

Important: The bigstart restart command will temporarily interrupt traffic processing by the BIG-IP system.

If the VLAN failsafe timer is set to a value lower than five seconds, configure a higher timeout value by performing the following procedure:

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click High Availability.
  4. From the Failsafe drop-down menu, click VLANs.
  5. Click the VLAN name.
  6. Enter a higher timeout value in the Timeout field.
  7. Click Finished.
