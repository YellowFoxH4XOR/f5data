K000163185: F5 Distributed Cloud OpenAPI Validation Reports "empty value is not allowed" for an Empty HTTP Header

Type
Support Solution
Published
2026-09-02
Updated
2026-09-02
Source

Description

F5 Distributed Cloud OpenAPI Validation reports empty value is not allowed when an HTTP header is explicitly sent with an empty value, even though the header is defined as type: string and is not marked as required.

For example: x-token:

Environment

  • F5 Distributed Cloud Web App & API Protection.
  • HTTP Load Balancer with API Definition configured.
  • Imported or API Discovery-generated OpenAPI specification.
  • OpenAPI Validation enabled in Report or Block mode.
  • An HTTP header that can be sent with an explicitly empty value.

Cause

When an HTTP header is sent with an explicitly empty value, the header is still present in the request. F5 Distributed Cloud OpenAPI Validation decodes the empty primitive as a null value and performs the empty-value validation before evaluating the type: string definition.

As a result, the request can generate the following OpenAPI violation: empty value is not allowed

This can occur even when the header is not marked as required and does not have a minLength, pattern, or other non-empty constraint.

Answer/Recommended Actions

If the application is expected to send the affected header with an empty value, update the OpenAPI specification to explicitly permit the empty value.

  1. Locate the affected header in the OpenAPI specification.
  2. Add the following property to the header parameter: allowEmptyValue: true
  3. Apply the same change to every OpenAPI specification that declares the affected header.
  4. If the same endpoint is defined in multiple specifications, update all applicable definitions. An unchanged duplicate specification can continue to generate the validation violation.
  5. Update the API Definition with the modified specification or specifications.
  6. Retest the affected request.
  7. If OpenAPI Validation is currently in Report mode, confirm that the violation is no longer generated before changing enforcement to Block mode.

Additional Information

  • An explicitly empty HTTP header is different from an omitted header.
  • x-token: means the header is present with an empty value.
  • If x-token is not present in the request, the header is omitted.
  • A HAR file, browser Developer Tools, application logs, or another client-side request trace can be used to confirm whether the header is explicitly empty or omitted.
  • When API Discovery generates a specification that defines the header only as type: string, the specification may need to be updated manually if the application intentionally sends the header with an empty value.
