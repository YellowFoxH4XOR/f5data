Security Advisory Description

** DISPUTED ** OpenSSL before 0.9.8l, and 0.9.8m through 1.x, does not properly restrict client-initiated renegotiation within the SSL and TLS protocols, which might make it easier for remote attackers to cause a denial of service (CPU consumption) by performing many renegotiations within a single connection, a different vulnerability than CVE-2011-5094. NOTE: it can also be argued that it is the responsibility of server deployments, not a security library, to prevent or limit renegotiation when it is inappropriate within a specific environment. (CVE-2011-1473)

CVE-2011-1473 is classified as Disputed by NIST. F5 does not consider this a vulnerability, but a condition inherent to the processing resources required to negotiate a Secure Sockets Layer (SSL) connection.

Impact

There is no impact; F5 products are not affected by this vulnerability.

Security Advisory Status

F5 Product Development has evaluated the currently supported releases for potential vulnerability, and no F5 products were found to be vulnerable.

Security Advisory Recommended Actions

If you are concerned about the potential impact of high levels of SSL renegotiations, you can consider implementing one of the following options:

  • BIG-IP 11.6.0 and later
  • BIG-IP 11.x - 13.x
  • BIG-IP 10.x
  • FirePass
  • Enterprise Manager
  • ARX

BIG-IP 11.6.0 and later

Using Client SSL profile options

In environments where you use the Client SSL profile, you can modify the two profile options to limit the number of SSL renegotiations. Using the Max Renegotiation option, you can specify the maximum number of SSL renegotiation attempts per connection that the system can receive in one minute. Using the Max Aggregated Renegotiation option, you can specify the maximum number of aggregated SSL renegotiation attempts that the system allows per minute. After the system receives this number of aggregated SSL renegotiate records, it closes the connection.

Impact of workaround: Depending on the environment in which you use this workaround, if you set the options values too low, the connecting client may fail to establish a connection. F5 recommends that you set a suitable value for the renegotiation maximum during a scheduled maintenance window.

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Local Traffic > Profile > SSL.
  3. Select Client.
  4. Select the Client SSL profile name you want to modify.
  5. On the Configuration menu, click Advanced.
  6. For Max Renegotiations, select the Custom check box to enable customizing.
  7. Type a value for Max Renegotiations.
  8. For Max Aggregated Renegotiation, select the Custom check box to enable customizing.
  9. Click Specify.
  10. Type a value for Max Aggregated Renegotiation.
  11. To save your changes, click Update.

BIG-IP 11.x - 13.x

Implementing an iRule

Impact of workaround: iRules may increase processing overhead and require more system resources per connection.

For more information, refer to the SSL Renegotiation DOS attack – an iRule Countermeasure DevCentral article.

Disabling SSL renegotiation in your SSL profile

Impact of workaround: Individual SSL connections are controlled by the BIG-IP system cache timeout if the renegotiation option is disabled, and the connections are unable to stay open in the cache for more than 24 hours.

  1. Log in to the Configuration utility as the admin user.
  2. Navigate to Local Traffic > Profile > SSL.
  3. Select either Client or Server, depending on which profile type you want to modify.
  4. Select your SSL profile.
  5. In the Configuration menu, select Advanced.
  6. For the Renegotiation option, clear the Enabled check box.
  7. To save your changes, click Update.
