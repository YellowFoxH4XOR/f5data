Topic

You should consider using this procedure under the following condition:

  • You want to set the SNMP subagent cache setting to adjust how frequently the cached SNMP data is refreshed.

Important: You should perform this modification only if your SNMP management system requires real time data. Otherwise, F5 recommends that you use the default settings.
Important: This system modification might not survive a version upgrade.  Please check snmp settings after.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command line access to the BIG-IP system.
  • You are familiar with a Linux text editor.

Description

The BIG-IP system provides an SNMP subagent configuration file in situations where administrators can adjust how often cached SNMP data is refreshed. A shorter refresh time allows the system to retrieve more current data when queried more than once per 30 seconds (the default value).

BIG-IP 11.2.0 and later

The configuration file used by the SNMPD subagent is /config/snmp/bigipTrafficMgmt.conf, and it has the following three parameters:

  • hbInterval is the heartbeat interval, in seconds. SNMPD is restarted if the system is not responsive for more seconds than is indicated in the hbInterval setting. Heartbeat is disabled if hbInterval is set to 0. The default is 60 seconds.

Note: The default value was raised to 300 seconds beginning in BIG-IP 11.3.0.

  • cacheMaxAge is the maximum time for which the data is ever cached; typically, the data is cached per request. The default is 30 seconds.
  • cacheUpdateMs is the amount of time, in milliseconds, between each request for the same table. This is considered part of the same request and will not cause a cache update. The default is 2000 milliseconds.

BIG-IP 10.2.0 through 11.1.0

The configuration file used by all the subagents is /config/snmp/subagents.conf, and it has the following three parameters:

  • agentxPingInterval is the time interval for the subagent to ping the master agent. The default is 10 seconds.
  • cacheMaxAge is the maximum time for which the data is ever cached; typically, the data is cached per request. The default is 30 seconds.
  • cacheUpdateMs is the amount of time, in milliseconds, between each request for the same table. This is considered part of the same request and will not cause a cache update. The default is 2000 milliseconds.

The current default behavior of cacheMaxAge is 30 seconds, which allows a minimum of two polls per minute without receiving cached data. To decrease the cacheMaxAge value, the system allows polling at intervals faster than the default 30 seconds. You can achieve this by uncommenting the cacheMaxAge entry and entering a new value, in seconds. With the new value on cacheMaxAge, it allows for more frequent SNMP polls to occur and will not receive cached data.

Important: If you set the cacheMaxAge value to one second, you need to adjust the cacheUpdateMs value of 2000 to 500. This allows the cache to be updated each time a poll occurs using a one second interval.

Procedures

The following procedure enables the administrator to adjust how often they can refresh an SNMP cache.

Impact of procedure: A greater number of objects and amount of traffic flowing through the system, combined with a very rapid polling cycle, may result in requests timing out and increases in memory and CPU usage for mcpd. Also, this may result in excessive traffic on the management backplane, if SNMP information is polled using the management interface.

BIG-IP 11.2.0

The cacheMaxAge and CacheUpdateMs parameters are located in the /config/snmp/bigipTrafficMgmt.conf configuration file.

  1. Log in to the BIG-IP command line.
  2. Change directories to the /config/snmp directory by typing the following command:

    cd /config/snmp

  3. Create a backup of the existing subagent configuration file by typing the following command:

    cp -a bigipTrafficMgmt.conf bigipTrafficMgmt.conf_backup_sol13778

  4. Using a text editor, modify the bigipTrafficMgmt.conf file by uncommenting the cacheMaxAge variable and adjusting the value to match the interval at which your SNMP management system will be polling the BIG-IP system.
  5. You may need to adjust the cacheUpdateMs value. For example, if the cacheMaxAge variable is set to one second, then you must adjust cacheUpdateMs to 500 milliseconds.
  6. Save the changes and exit the text editor.
  7. For SNMPD to use the modified values, restart the daemon by typing the following command:

    bigstart restart snmpd

BIG-IP 10.2.0 through 11.1.0

The cacheMaxAge and cacheUpdateMs parameters are located in the /config/snmp/subagents.conf configuration file.

  1. Log in to the BIG-IP command line.
  2. Change directories to the /config/snmp directory by typing the following command:

    cd /config/snmp

  3. Create a backup of the existing subagent configuration file by typing the following command:

    cp -a subagents.conf subagents.conf_backup_sol13778

  4. Using a text editor, modify the subagents.conf file by uncommenting the cacheMaxAge variable and adjusting the value to match the interval at which your SNMP management system will be polling the BIG-IP system.
  5. You may need to adjust the cacheUpdateMs value. For example, if the cacheMaxAge variable is set to one second, then you must adjust cacheUpdateMs to 500 milliseconds.
  6. Save the changes and exit the text editor.
  7. For SNMPD to use the modified values, restart the daemon by typing the following command:

    bigstart restart snmpd
