Known Issue

A terminated User Datagram Protocol (UDP) connection flow may not be able to resume traffic processing.

This issue occurs when all of the following conditions are met:

  • The UDP virtual server uses an iRule command that parks the iRule.
  • The connection flow is terminated (for example, when an Internet Control Message Protocol (ICMP) unreachable message is received from the server side) while the iRule is in a parked state.

The terminated UDP virtual server connection flow remains in the connection table until the connection times out. However, subsequent incoming packets that match the connection flow are dropped. Additionally, the dropped subsequent packets reset the connection timeout counters and extend the outage.

Impact

A terminated UDP connection flow may be unable to resume traffic processing.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system drops incoming packets to a UDP virtual server for the affected connection flow.
  • The tmsh show sys connection command continues to display the connection flow for a terminated connection in the connection table.
  • Subsequent incoming packets to the terminated connection flow reset the connection timeout counter and prevent the affected connection from timing out naturally.

Workaround

There is no workaround for this issue. To clear an affected connection flow, you must allow the flow to time out. Alternatively, you can clear all connection flows by restarting the Traffic Management Microkernel (TMM).

Impact of workaround: Restarting TMM causes the BIG-IP system to drop the current connections. You should perform this workaround only during a maintenance window.

To restart the TMM processes, type the following command:

bigstart restart tmm
