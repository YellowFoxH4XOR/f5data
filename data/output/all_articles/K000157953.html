Description

Under specific conditions, even if BIG-IP receives proper HTTP2 response from pool member, BIG-IP may consider HTTP2 monitor failed. The problem can happen when HTTP2 monitor configured with HEAD method, as shown on "http2_head_f5" default http2 monitor below.

ltm monitor http2 http2_head_f5 {
    adaptive disabled
    defaults-from http2
    destination *:*
    interval 5
    ip-dscp 0
    recv Server\:
    recv-disable none
    send "HEAD /\r\n\r\n"	<=== !!! HEAD method set
    time-until-up 0
    timeout 16
}

 

Here is example of the failure HTTP2 monitor flow. At frame-18, BIG-IP sends HTTP2 request with HEAD method. Frame-20 is response from pool member server. Here, HTTP2 response frame contains both HEADERS frame (type 1) and DATA frame (type 0), and HEADERS frame contains "content-length" header. After receiving this HTTP2 response pkt, BIG-IP reset connection with rstcause text "flow teardown" and monitor fails.

Figure: HTTP2 monitor failure case

 

If pool member monitor logging was enabled, monitor debug log would say "tmm monitor failed to connect".

[1][10458] 2025-10-15 13:17:11.796514: ID 57    :TMM::handle_message(TMA_Message<tma_msg_args_notify>*): tmm monitor failed to connect [ tmm?=true td=false tr=true tmm_instance=4 all_tma_created=1 tma_created_count=3 tmm_mid_count=3 tmm_mids=1 2 3 addr=::ffff:10.1.1.50:443 srcaddr=none ]

 

Here is another example of the successful HTTP2 monitor flow. Same as failure case, at frame-17, BIG-IP sends HTTP2 request with HEAD method. Frame-21 is response from pool member server. This time, HTTP2 response contains only HEADERS frame (type 1).

Figure: HTTP2 monitor success case

 

Environment

All of the following conditions need to be met. Except for monitor configuration, it depends on pool member web application's behavior as to how http2 response is constructed.

 

  • HTTP2 monitor with HEAD method.
  • Pool member server returns HTTP2 HEADERS frame and DATA frame.
  • HTTP2 response HEADERS frame contains "content-length" header.

 

Cause

Bug ID 1353809.

 

Recommended Actions

Do not use HTTP2 monitor with HEAD method. Instead, use HTTP2 monitor with GET request method.

None.
