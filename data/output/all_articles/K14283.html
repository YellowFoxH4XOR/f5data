Known Issue

The vCMP host may report interfaces as missing. This issue occurs when all of the following conditions are met:

  • The vCMP host was upgraded from BIG-IP 11.2.0 or later to an affected version listed in the Applies To box
  • The vCMP host is booted into the upgraded slot for the first time
  • The vCMP host is running on one of the following platforms:
    • B2100 blade (A109)
    • B4200 blade (A107)
    • B4300 blade (A108)

Impact

The vCMP host fails to process traffic as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The vCMP host reports some interfaces as missing even though they were working as expected prior to the upgrade.

    For example, the vCMP host reports the status of interface 1/1.1 through 4/1.1 as up before the upgrade. Using the tmsh show net interface */1.1 command, you may observe the following output:

    ----------------------------------------------------------------
    Net::Interface
    Name   Status    Bits    Bits  Pkts  Pkts  Drops  Errs     Media
                       In     Out    In   Out
    ----------------------------------------------------------------
    1/1.1      up  383.2K  543.7K   280   531    299     0  1000T-FD
    2/1.1      up    3.5M  542.7K    21   530   6.9K     0  1000T-FD
    3/1.1      up    5.9M  542.7K    37   530  11.3K     0  1000T-FD
    4/1.1      up   22.4K  543.7K    22   531      3     0  1000T-FD

    After the upgrade, the vCMP host reports the status of interface 1/1.1 and 4/1.1 as miss:

    -------------------------------------------------------------
    Net::Interface
    Name   Status   Bits  Bits  Pkts  Pkts  Drops  Errs     Media
                      In   Out    In   Out
    -------------------------------------------------------------
    1/1.1    miss      0     0     0     0      0     0      none
    2/1.1      up  10.3M     0   688     0  17.7K     0  1000T-FD
    3/1.1      up   8.1M     0   599     0  13.9K     0  1000T-FD
    4/1.1    miss      0     0     0     0      0     0      none
  • The vCMP host reports the Fail status for some TMM instances in the HA status table as yes. Using the tmsh show sys ha-stat | grep 'ready\|Fail' command, you may observe the following output:

    Slot  Feature               Key          Action                        Fail
    1     ready-for-world       tmm1         none                          yes
    3     ready-for-world       tmm1         none                          yes
    4     ready-for-world       tmm1         none                          yes

Workaround

There is no work around for this issue. For a vCMP host that has already encountered this issue, you can recover the vCMP host by rebooting the vCMP host. To do so, perform the one of the following procedures:

Impact of workaround: If the vCMP host is the active member of a redundant system, rebooting will cause a failover. If the vCMP host is a standalone unit, rebooting will interrupt traffic processing.

Rebooting the vCMP host using the Configuration utility

  1. Log in to the BIG-IP Configuration utility.
  2. Click System.
  3. Click Configuration.
  4. Click Device.
  5. Click General.
  6. Click Reboot Chassis to reboot the vCMP host.
  7. Click OK.

Rebooting the vCMP host using the command line

  1. Log in to the command line.
  2. Reboot the vCMP host by entering the following command:

    clsh reboot
