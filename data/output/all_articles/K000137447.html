K000137447: GTM/DNS module doesn’t sync the configuration anymore

Type
Support Solution
Published
2023-11-09
Updated
2023-11-09
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.0
Source
https://my.f5.com/manage/s/article/K000137447

Description

BIG-IP DNS system does not sync the configuration after changing the BIG-IP system device certificates.
The new device certificate was configured and the iQuery connection was reinitialize based on article:
K16951115: Changing the BIG-IP system device certificate using the Configuration utility

DNS systems completed the SSL Handshake with new certificate, have green status in Data center and iQuery is in connected state, but still the synchronization between them is not working.

For example:

Oct 17 11:21:17 dns1.example.com notice gtmd[5874]: 011ae05f:5: SSL Context created with cipher list 'AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1:AES256-SHA' and minimum TLS version 'TLSv1'.
Oct 17 11:21:21 dns1.example.com notice gtmd[5874]: 011ae01c:5: Connection complete to 10.2.3.4 Starting SSL handshake
Oct 17 11:21:21 dns1.example.com notice notice gtmd[5874]: 011ae01a:5: SSL handshake complete to 10.2.3.4
Oct 17 11:21:21 dns1.example.com alert gtmd[5874]: 011a500b:1: SNMP_TRAP: Box 10.2.3.4 state change blue --> green
Oct 17 11:21:21 dns1.example.com alert gtmd[5874]: 011a5003:1: SNMP_TRAP: Server /Common/dns2.example.com (ip=10.2.3.4) state change blue --> green
Oct 17 11:21:21 dns1.example.com alert gtmd[5874]: 011ab003:1: SNMP_TRAP: Data center /Common/DC_TEST state change blue --> green

Environment

  • BIG-IP DNS/GTM systems in device sync group.
  • BIG-IP system device certificate change.

Cause

Unknown

Recommended Actions

Remove and re-add a BIG-IP DNS systems to an existing BIG-IP DNS synchronization group.
For more details, please follow:
K14044: Removing and re-adding a BIG-IP DNS system to an existing BIG-IP DNS synchronization group
