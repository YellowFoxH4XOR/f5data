K000150708: Masking data in NGINX App Protect event logs

Type
Support Solution
Published
2025-04-03
Updated
2025-04-03
Applies to

Source

Description

You wish to mask sensitive data, such as the `password`, in the NGINX App Protect event logs.

Environment

NGINX App Protect

Cause

By Default logging contains plain text of potentially sensitive data.

Recommended Actions

Use sensitive-parameter directive to mask this data in the log per NGINX App Protect WAF Configuration Guide | NGINX Documentation (https://docs.nginx.com/nginx-app-protect-waf/v4/configuration-guide/configuration/)

-------

- Based on documentation https://docs.nginx.com/nginx-app-protect-waf/v4/declarative-policy/policy/, the definitions of there are two possible configuration properties, which are as follow:

############

sensitiveParameter

Determines whether a parameter is sensitive and must be not visible in logs nor in the user interface. Instead of the actual value, a string of asterisks is shown for this parameter. Use it to protect sensitive user input, such as a password or a credit card number, in a validated request.

sensitive-parameters

This section defines sensitive parameters. The contents of these parameters are not visible in logs nor in the user interfaces. Instead of actual values a string of asterisks is shown for these parameters. Use these parameters to protect sensitive user input, such as a password or a credit card number, in a validated request. A parameter name of "password" is always defined as sensitive by default.

############

- looking further into how each of these properties/fields are defined within a policy from https://docs.nginx.com/nginx-app-protect-waf/v4/configuration-guide/configuration/:

############

sensitiveParameter - is defined within individual parameters.

sensitive-parameters - is defined at the policy level.

-------

Essentially, both properties achieve a similar outcome: “The contents of these parameters are not visible in logs nor in user interfaces.”

The key difference lies in their scope and application:

sensitiveParameter is defined within individual parameters, meaning its effect is limited to the specific parameter where it is set.

sensitive-parameters, on the other hand, is defined at the policy level, allowing the masking of all matching parameters globally across requests.

 

This distinction makes sensitiveParameter useful for fine-grained control, while sensitive-parameters provides a broader, policy-wide matching approach to protecting sensitive data.
