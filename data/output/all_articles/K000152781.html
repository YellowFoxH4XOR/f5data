K000152781: Portal Access fails to load external JavaScript resources

Source

Description

When accessing intranet web portals through BIG-IP APM Portal Access, users may experience issues where web pages fail to render correctly. Browser console logs may display errors such as:

Uncaught SyntaxError: Unexpected token '<' (at jquery-3.5.1.slim.min.js:1:1)

Uncaught SyntaxError: Unexpected token '<' (at popper.min.js:1:1)

Uncaught SyntaxError: Unexpected token '<' (at bootstrap.min.js:1:1)

These errors indicate that JavaScript files (such as jQuery, Popper, Bootstrap) are being returned as HTML content, due to HTTP 302 redirects or improper resource rewriting by the BIG-IP system. Additionally, when analyzing network traffic in Developer Tools, you may observe a redirect to the URI /vdesk/my.acl.php3?errorcode=3016.

This problem does not occur when accessing the same portals directly on the internal network.

Environment 

  • APM Portal Access with Portal Access Rewrite profile enabled 
  • Web applications using external JavaScript libraries from public CDNs (e.g., stackpath.bootstrapcdn.com, code.jquery.com, cdn.jsdelivr.net) 
  • Split tunneling and rewrite list configured in the Portal Access profile

Cause

The Portal Access rewrite profile is configured to rewrite all traffic—including requests for external JavaScript CDN resources. As a result, requests for these external resources are proxied and rewritten by BIG-IP, leading to HTTP 302 redirects and browsers receiving HTML content instead of the expected JavaScript files. This causes syntax errors in the browser and prevents proper portal functionality.

Recommended Actions

  1. Update the Portal Access rewrite profile
    - Add bypass rules for all external domains used for static resources such as JavaScript, CSS, fonts, etc., in the Portal Access rewrite profile.
    - Example domains to bypass:
    • xpath.bootstrapcdn.com
    • code.jquery.com
    • cdn.jsdelivr.net
    - In the BIG-IP GUI:
    Local Traffic ›› Profiles : Services : Rewrite ›› [Your Rewrite Profile]
    Add relevant domains or URL patterns to the Bypass List.
  2. Test after changes
    - After updating the bypass list, verify that affected portals load correctly and that browser console errors related to JavaScript resources are resolved.
  3. Best Practice
    - For any web application accessed via APM Portal Access that relies on external resources (CDNs), always include those domains in the bypass list to prevent similar issues.
