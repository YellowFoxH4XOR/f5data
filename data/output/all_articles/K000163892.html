K000163892: DNSSEC RRset and RRSIG TTL values differ across BIG-IP DNS units when DNS cache settings are inconsistent

Type
Support Solution
Published
2026-10-26
Updated
2026-10-26
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.1.3
Source
https://my.f5.com/manage/s/article/K000163892

Description

On BIG-IP DNS systems with DNSSEC enabled, MX-record responses can show different TTL behavior depending on DNS-cache configuration. Cache-enabled units return cached RRsets and RRSIGs with aging TTL values, while cache-disabled units serve local zone data with the configured TTL. DNSViz may report:

The TTL of the RRset (3457) exceeds the value of the Original TTL field of the RRSIG RR covering it (417). See RFC 4035, Sec. 2.2.

Direct dig queries show matching RRset TTL and RRSIG Original TTL values, with no DNS resolution failure.

Environment

  • BIG-IP DNS 17.1.3.
  • DNSSEC enabled on the DNS listener profile.
  • Multiple BIG-IP DNS units serve the same domain.
  • The affected MX record is served from local zone data and has no Wide IP.
  • DNS caching is enabled on some units and disabled on others.
  • Cache-enabled units may belong to an automatically synchronized device group.

Cause

Inconsistent DNS-cache configuration across BIG-IP DNS units. Cache-enabled units return responses whose TTL values age as cached data is served. Cache-disabled units generate responses from local zone data and retain the configured TTL. This is expected configuration-dependent behavior and does not indicate invalid DNSSEC signing or a BIG-IP DNS software fault.

Answer/Recommended Actions

  1. Query each BIG-IP DNS listener directly and compare the DNSSEC responses:
    dig +dnssec +multi example.com MX @210.242.36.227
  2. Confirm whether DNS caching is enabled in the DNS profile. Cache-enabled units can return aging TTL values, while cache-disabled units return the configured TTL from local zone data.
  3. To obtain consistent TTL behavior, standardize the DNS-cache setting across all applicable BIG-IP DNS units. Disabling caching on cache-enabled units aligns their behavior with units that serve local zone data directly.
  4. Make cache-setting changes during a maintenance window. Disabling caching does not change DNS availability, zone content, or the published TTL; queries previously served from cache are processed by the local DNS engine.
  5. Capture cache-utilization and system-resource baselines before the change. Afterward, verify DNS and DNSSEC responses and monitor resource utilization during normal traffic peaks.
  6. If the units are in an automatically synchronized device group, the shared DNS-profile change may propagate to both units. For staged, one-unit-at-a-time testing, temporarily disable automatic synchronization before changing the profile.
  7. Verify TCP responses because a large DNSSEC MX response can require a TCP retry. Recheck the DNSViz result after the configuration has operated under normal conditions.

Additional Information

Fixed TTL values from locally served zone data and aging TTL values from cached responses are both expected. The DNSViz message is a validator warning. Direct queries show matching RRset TTL and RRSIG Original TTL values, and no DNS resolution failure is observed.
