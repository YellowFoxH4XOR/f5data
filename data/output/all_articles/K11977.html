Known Issue

This is the result of a known issue. When adding a network address to a class, the mcpd process does not check that the address and mask are a valid combination. For example, the BIG-IP system incorrectly allows an administrator to add the 10.0.0.1/255.255.255.0 record to a class. This is an illegal operation as the 10.0.0.0 network address should be used instead.

This issue occurs regardless of whether the Configuration utility, the bigpipe utility, or the tmsh shell is used to add the record to the class.

Note: The Configuration utility and the tmsh shell refer to classes as data groups.

The invalid record is added to the class without any warning. Additionally, the BIG-IP system will later save and load the configuration without any warning. However, unlike the mcpd process, TMM checks that the address and mask are a valid combination, and silently omits any invalid class members. As a result, TMM behaves as if the invalid record was never added to the class, and any functionality dependent upon the record will not work.

The only user-visible sign of this issue (other than the traffic disruption) is when attempting to delete the invalid class member, as TMM cannot find and remove the element from its running configuration:

  • In BIG-IP version 10.x, an error message that appears similar to following example is logged to the /var/log/ltm file (one message per TMM):

    tmm: 01010007:3: Config error: class example_class error: removing IP element - Not found
  • In BIG-IP version 9.4.x, an error message that appears similar to following example is logged to the /var/log/ltm file (one message per TMM):

    tmm: 01010007:3: Config error: TCL ERROR - removing IP element from: example_class - Element 10.0.0.1/24 not found in class example_class

F5 Product Development tracked this issue as ID 226916 and ID 248044 (formerly CR142386), and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by removing the invalid class member and re-adding it using the correct network address and mask combination.
