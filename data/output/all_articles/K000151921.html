Description

Observing health monitor probes are sourced from IP address 127.1.1.254, while reviewing a packet capture.

Environment

  • LTM monitor probes
  • Packet capture taken with :h modifier (e.g., :hnnn)

Cause

TMM route that is used to reach the pool member points to a gateway pool.

For example:

net route /Common/default-route {
    network default
    pool /Common/gateway-pool
}
     
ltm pool /Common/gateway-pool {
    members {
        /Common/gw-10.1.1.1:0 {
            address 10.1.1.1
        }
        /Common/gw-10.1.1.2:0 {
            address 10.1.1.2
        }
    }
}

Traffic from the Linux host (bigd) towards TMM is sourced from 127.1.1.254. TMM then makes a load balancing decision and picks a pool member (one of the gateways).

A packet capture taken with :nnnh shows the Linux host <-> TMM traffic, before TMM's source address translation.

Traffic leaving the system towards the pool member from TMM (via the gateway) should be sourced from a self IP.

Recommended Actions

This is expected behaviour, so no action is required.

When viewing the output of the ip route command, you should see the kernel route in question. For example, a default route:

default via 127.1.1.253 dev tmm

Furthermore, output of ip r g <pool member IP> will confirm the Linux -> TMM traffic will be sourced from 127.1.1.254.

Note: If a non-0 route domain is in use, these commands must be used with rdexec.

Take a capture of monitor traffic without using the :h modifier to verify that the system is using a self IP for traffic leaving the system. In most cases, you should use :nnn when capturing health monitor traffic.
