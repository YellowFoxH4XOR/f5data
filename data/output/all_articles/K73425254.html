Known Issue

BIG-IP configuration files require that each monitor parameter consists of a single line. If you manually edit the configuration file, the system might insert a line break within a single monitor parameter, breaking the parameter across two lines.  Monitor parameters that contain these line breaks may silently load without error, but the configuration should fail to load. 

This issue occurs when all of the following conditions are met:

  • Due to a line break, the monitor parameter contains a single line broken across two lines of text.
  • The first line has an odd number of double quotes, regardless of the presence of backslash escaping.

    For example:

    send "GET http://path={\"checkDatabase\":\"true\"}<CR>\r\n"

    In the previous example, <CR> represents the hidden line break in the text file. This monitor parameter silently loads because the odd number of double quotes on the first line before the <CR> hides the new line in the text file, resulting in the system merging the first line with the second line when the configuration loads.

Impact

The monitor behaves correctly, even though the hidden line break implies that the file is non-conforming.  Configurations may fail to load after you upgrade the system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The configuration loads successfully, when the system should reject it as non-conforming.
  • An upgraded BIG-IP system with a non-confirming configuration may fail to load the upgraded configuration.

Workaround

To work around this issue, you can manually edit your configuration file and remove line-breaks.
