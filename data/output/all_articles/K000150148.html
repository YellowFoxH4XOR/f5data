K000150148: Malformed HTTP Header Error: Double 'Transfer-Encoding: chunked' header

Type
Support Solution
Published
2025-02-28
Updated
2025-05-12
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000150148

Description

After an upgrade, authentication failures are occurring on various applications. The issue is accompanied by a "Malformed HTTP Header" error, and the BIG-IP system sends a reset (RST) packet immediately after receiving the server response.

 

Example Request:

HTTP/1.1 200 \r\n

Access-Control-Allow-Origin: *\r\n

X-Frame-Options: DENY\r\n

Transfer-Encoding: chunked\r\n <------------------------------------------

Content-Type: application/json\r\n

Transfer-Encoding: chunked\r\n <------------------------------------------

\r\n

Environment

BIGIP ASM

Virtual Server with an HTTP profile applied.

Cause

The root cause of this issue is that the server response contains two Transfer-Encoding: chunked headers, which violates RFC9112 standards for HTTP/1.1 compliance. Specifically, RFC9112 Section 6.1 states:

"A sender must not apply the chunked transfer coding more than once to a message body (i.e., chunking an already chunked message is not allowed)."

When the BIG-IP system detects non-RFC-compliant behavior in the server response, it enforces strict HTTP header checks and resets the connection with a "Malformed HTTP Header" error.

Recommended Actions

A permanent solution is to modify the server response to ensure it adheres to RFC standards by removing one of the duplicate Transfer-Encoding: chunked headers.

As a temporary workaround you can use a transparent HTTP Profile on the Virtual Server, which will allow forwarding of invalid or non-RFC complient traffic.

Note: This workaround is incompatible with ASM policies because they require a standard HTTP profile.
