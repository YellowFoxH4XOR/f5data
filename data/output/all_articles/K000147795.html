Description

  • After creating the site, it is in failed state and you would like to know the reason behind it.
  • How to debug and resolve issues that arise due to Distributed Cloud published Terraform-related errors, networking and security misconfiguration or CE internal processes that are not running.

Important: When you open a case with F5 Support, mention any status error messages that display in your logs.

Attach the following information to the support ticket:

  1. Collect the Debug logs
  2. Collect the Diagnosis tool output
  3. Completed questionnaire

Environment

  • F5® Distributed Cloud
  • F5 Distributed Cloud Customer Edge (CE)

Answer/Recommended Actions

Using the Console UI

Navigate to:

  • Tools -> Collect log bundle
    • Select All Nodes and click Request Log Bundle Collection
    • Then Download and Save the file

On-prem site

For clusters, collect the logs from master node and issue node respectively:

    1. Access to local UI https://{{CE_local_IP}}:65500/debug-info -  (default credentials admin/Volterra123)
    2. Collect debug info
    3. Browse debug info files
    4. Download the tar.bz2 file

Cloud Site

Option 1: SSH to node with Public IP address:

$ssh admin@{{CE_IP}}
#Default password is Volterra123, or use the ssh key you created while create the site

Note: For cloud sites, use centos as the username for CentOS and use cloud-user as the username for RHEL OS.

  • Generate debug file: 
>>> collect-debug-info
Debug info /tmp/debuginfo/debuginfo-<date>-<site-name>.tar.bz2 file will be available in minute
Use 'exec ls /tmp/debuginfo/' to see produced file

Then you can download from local network 'curl https://admin:<password into local UI>@<IP address of CE>:65500/debug-info/files/debuginfo-<date>-<site-name>.tar.bz2 --insecure --output debuginfo-<date>-<site-name>.tar.bz2'  

>>> exec ls /tmp/debuginfo
file-azure debuginfo-2021-09-30T0646-shali-azure.tar.bz2
>>> exit

 

Option 2: Download from client

Run from a client (NOT the CE itself) and replace {{CE_IP}} with the current IP address of the CE and site_password.

    • curl --insecure --location --request GET 'https://admin:$site_password@{{CE_IP}}:65500/debug-info/files/debuginfo-2021-09-30T0646-shali-azure.tar.bz2' --output debuginfo-2021-09-30T0646-.tar.bz2

Option 3: Use SCP :

  1. SSH to the node and run exec ls /tmp/debuginfo/ to identify the file name
  2. SCP the file using the absolute path.
    • $ ssh -i ~/.ssh/id_rsa centos@CE_IP

WELCOME IN SITE CLI
This allows to:
- configure registration information
- factory reset of the Node
- collect debug information for support

>>> exec ls /tmp/debuginfo/
debuginfo-2024-10-09T2151-prod-test.tar.bz2  prod-test
>>>
Connection to CE_IP closed.

Additional Information

If debug file can't be collected, create an API token from the Console and run the following API call to retrieve VPM logs: 

curl -sv -H "Content-Type: application/json" -H "Authorization: APIToken <API Token>" "https://<tenant-name>.console.ves.volterra.io/api/operate/namespaces/system/sites/<CE name>/vpm/debug/<node name>/vpm/log"
  • Debug-info is a collection of logs to capture the current site's status for debugging
  • On-prem site, example: Virtual Machine/KVM etc.
  • Cloud site, example: AWS/Azure/GCP
  • During debug-info collection runs there will be another file named  "/tmp/DEBUG_COLLECTION_IN_PROGRESS"
    • After debug-info collection is done it will be removed.
