Description

In an SSLO deployment configured with Inline L3 service, the traffic fails when the IP address or port is modified by an inline WAF (Web Application Firewall) device. This behavior prevents SSLO from recognizing the original connection, leading to access failures. Packet captures reveal that the WAF changes the IP address or port of the traffic before returning it to SSLO. 

Environment

  • BIG-IP SSLO
  • Inline L3 service

Cause

The issue occurs because Inline L3 service is expected to operate at the network layer without altering IP address or port. When a WAF modifies the IP address or port, SSLO cannot correlate the returned traffic with its original session. This behavior violates Inline L3 service expectations and disrupts proper traffic flow.

Recommended Actions

To resolve this issue, reconfigure the affected service as follows:.

  1.  Remove the Inline L3 service from the service chain.
  2. Create new Inline HTTP service, transparent proxy type, apply to the service chain / topology.
