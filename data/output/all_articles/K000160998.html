Description

BIG-IP GUI Management interface becomes inaccessible, while CLI access and system uptime remain normal. Restarting 'httpd' and 'tomcat' services restores GUI access. Analysis shows repeated, slow REST API operations caused "icrd_child" processes to be killed by 'restjavad' due to exceeding the default timeout, leading to resource exhaustion and instability in 'restjavad', which made the GUI unresponsive. No disk, CPU, or memory exhaustion was observed, and no custom scripts, cron jobs, or iCall handlers were found to trigger the issue.

Symptoms and log messages:

  • GUI not loading or very slow, CLI access normal.
  • Tomcat logs show memory leak warnings and thread cleanup coinciding with service restarts.
  • Large numbers of suppressed messages from 'httpd.service', indicating high activity or stress.
  • 'restjavad' logs show repeated forced termination of "icrd_child" processes due to timeout.
  • No evidence of external automation, scripts, or iCall handlers causing the issue.

Environment

  • Product: BIG-IP LTM
  • Default configuration for "icrd.timeout", "restjavad.timeout", and "restnoded.timeout" set to 60 seconds
  • No custom iCall handlers or cron jobs identified
  • System memory usage moderate (less than ~50-60%), no swap usage

Cause

Repeated termination of "icrd_child" processes by 'restjavad' due to REST API operations exceeding the default 60-second timeout led to resource exhaustion and instability in 'restjavad', causing the GUI to become unresponsive. Restarting 'httpd' and 'tomcat' temporarily restored service, but the underlying issue was the insufficient timeout for icrd/restjavad under the observed workload. No evidence of external scripts, cron jobs, or iCall handlers was found, suggesting the issue was triggered by normal but heavy REST API usage. 

Answer/Recommended Actions

1. Increase the timeout values for 'icrd', 'restjavad', and 'restnoded' to 300 seconds to allow REST API operations sufficient time to complete:

# tmsh modify sys db icrd.timeout value 300
# tmsh modify sys db restjavad.timeout value 300
# tmsh modify sys db restnoded.timeout value 300

# tmsh save sys config

# bigstart restart restjavad && sleep 20 && bigstart restart restnoded

2. Monitor the system for several days after applying these changes to confirm stability.

3. [Optionally] Increase "provision.tomcat.extramb" if memory usage increases, but this is not required unless further symptoms appear. [K63328426]

4. Continue to use 'httpd' and 'tomcat' restarts as a temporary workaround if the issue recurs before applying the recommended changes.

bigstart restart httpd tomcat

Important: Perform any changes during a planned maintenance window to avoid unexpected behavior. You need to apply the above changes on each individual F5 instance within the Device-Group.

Additional Information

  • Restarting 'httpd' and 'tomcat' is a safe workaround and does not negatively impact traffic or memory, but it only resolves the symptom temporarily.
  • Increasing timeout values is considered preventive maintenance and is safe for environments with moderate memory usage.
  • The "icrd_child" process is managed by 'restjavad'; repeated kills can cause 'restjavad' to stall and stop logging, resulting in GUI/API unresponsiveness.
  • If the issue recurs, standard troubleshooting steps (QKview/log collection, analysis) can be repeated.
  • 'restjavad' stopped logging means the process was stalled or unable to process further requests, not necessarily that it was stopped.
