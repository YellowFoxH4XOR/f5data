Topic

You should consider using this procedure under the following condition:

  • You want to create a SNAT, automap SNAT, or SNAT pool using the TMOS shell (tmsh) or the Configuration utility.
  • You want to create a data group SNAT mapping using iRules.

For more information about SNAT and SNAT pools, refer to K7820: Overview of SNAT features.

Description

You can create Secure Network Address Translation (SNAT) and SNAT pool objects using the TMOS Shell (tmsh) or the Configuration utility.

For more information about SNAT and SNAT pools, refer to K7820: Overview of SNAT features.

Create a SNAT using tmsh

Impact: Performing this procedure should not have a negative impact on your system

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following tmsh syntax:

    For example:

    create /ltm snat /Common/test_snat origins add { 10.10.10.1/32 } translation 172.16.0.1

    Alternatively, you can translate addresses of a network range. To do so, use the following tmsh command syntax:

    create /ltm snat /Common/< snat name> origins add { <network range> }

    For example:

    create /ltm snat /Common/test_snat origins add { 10.10.0.0/16 }

    Note: To create a SNAT used in a route domain, be sure to include the route domain suffix of the origin and SNAT IP addresses when applicable.
    For example:  create /ltm snat /Common/test_snat origins add { 10.10.10.1%15/32 } translation 172.16.0.1. In this example %15 indicates the route domain 15.

Create a SNAT using the Configuration utility

Impact: Performing this procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go Local Traffic > Address Translation > SNAT List.
  3. Select Create.
  4. Enter a name for the SNAT
  5. For Translation, select IP Address and then enter the IP address.
  6. Leave the remaining settings at their default values.
  7. Select Finished.

Create a SNAT pool using tmsh

Impact: Performing this procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Use the following syntax to create a SNAT pool:

    create ltm snatpool members add { <snat address> <snat address> <snat address> }

    For example:

    create /ltm snatpool /Common/my_snatpool members add { 172.16.0.1 172.16.0.2 172.16.0.3 }

  3. Save the configuration by entering the following command:

    save /sys config

After you create a SNAT pool, you must associate it with a SNAT object. For example, the following SNAT configuration translates the address of connections that originate from the address 10.10.10.1 to one of the IP addresses in the SNAT pool:

create /ltm snat /Common/test_snatpool origins add { 10.10.10.1/32 { } } snatpool my_snatpool

Important: When using a SNAT pool with IP addresses from the egress VLAN (the VLAN for which the packet exits in the BIG-IP system) and non-egress VLAN networks, the egress VLAN network address is given higher priority. For example, egress VLAN external has a self IP of 172.16.0.254/24, and SNAT pool member addresses of 172.16.0.1/24 and 10.1.1.1/24. The BIG-IP system prefers the egress VLAN SNAT pool member address 172.16.0.1 and continues to use the same address until it becomes unavailable.

Create a SNAT pool using the Configuration utility

Impact: Performing this procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go Local Traffic > Address Translation > SNAT Pool List.
  3. Select Create.
  4. Enter a name for the SNAT pool.
  5. For Member List, for IP Address, enter the IP address to use as the server-side source IP address.
  6. Select Add.
  7. Select Finished.

Create an automap SNAT using tmsh

Impact: Performing this procedure should not have a negative impact on your system.

  • Log in to tmsh by entering the following command:

    tmsh

  • Use the following syntax to create an automap SNAT

    create /ltm snat /Common/<SNAT name> automap origins add { <IP address> }
    create /ltm snat /Common/<SNAT name> automap vlans add { <vlan name> }

    Note: Using SNAT automap for a VLAN origin employs SNAT for all IP addresses that egress the VLAN using a BIG-IP self IP address or when configured a specific IP address.

    For example

    create /ltm snat /Common/test_snat automap origins add { 10.10.10.1/32 }
    create /ltm snat vlan-snat automap vlans add { external }

    Alternatively, you can translate addresses of a network range using the following command syntax:

    create /ltm snat /Common/<SNAT name> automap origins add { <IP address range> }
    create /ltm snat /Common/test_snat automap origins add { 10.10.0.0/16 }

Create an automap SNAT using the Configuration utility

Impact: Performing this procedure should not have a negative impact on your system.

  • Log in to the Configuration utility.
  • Go Local Traffic > Address Translation > SNAT List.
  • Select Create.
  • Enter a name for the automap SNAT
  • For Translation, select Automap.
  • Leave the remaining settings at their default values.
  • Select Finished.

Create data-group SNAT mapping using tmsh

You can use the Data Group feature to create a list of known source IP address and a mapped SNAT address in conjunction with a custom iRule to SNAT request received by a virtual server.

Impact: Performing this procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Create a data-group using the following syntax:

    create /ltm data-group internal SNAT-Map type string records add { <origin> {data <snat>}  origin { data <snat>} origin { data <snat>} }

    Note: Replace <origin> with the origin IP address to be translated, and replace the data <snat> with the translation SNAT IP address.

    For example:

    create /ltm data-group internal SNAT-Map type string records add { 10.0.0.10 {data 172.16.0.1}  10.0.0.11 { data 172.16.0.2} 10.0.0.12 { data 172.16.0.3} }

  3. Create a custom iRule with the following syntax:

    create /ltm rule <rule name>

    Note: Replace <irule name> with the desire name for the iRule.

    For example:

    create /ltm rule snat-mapping

  4. The iRules definition opens in the vi text editor.
  5. Between the opening and closing braces, enter the definition syntax similar to the following example:

    when CLIENT_ACCEPTED {
        set sourceip [IP::client_addr]
        set mapped_snat [class lookup $sourceip <data-group>]
        snat $mapped_snat
        }

    Note: Replace <data-group> with the name of the data group created in the previous step.

    For example:

    when CLIENT_ACCEPTED {
        set sourceip [IP::client_addr]
        set mapped_snat [class lookup $sourceip SNAT-Map]
        snat $mapped_snat
        }

  6. To save the configuration and exit the vi text editor, enter the following command:

    Esc:wq

  7. To apply the iRule to the intended virtual server use the following syntax:

    modify /ltm virtual /<partition>/<virtual server name> rules { <irule name> } 
    Note: Replace <partition> with the name of the partition where the virtual server resides, replace <virtual server name> with the name of the virtual server you would like to apply the SNAT iRule. Replace <irule name> with the name of the iRule used in the previous step. 

    For example: modify /ltm virtual /Common/my_vs rules { snat_mapping_rule }
     
  8. Save the configuration changes with the following command:

    save /sys config partitions all
