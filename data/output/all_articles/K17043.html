Topic

When a user attempts to establish a BIG-IP APM access session while using the Microsoft Internet Explorer Content Advisor feature, the user may be unable to establish an access session.

This issue occurs when the Internet Explorer Content Advisor feature continues to query the initial access session logon page after the user has authenticated, and the BIG-IP APM system redirects to the access session webtop. When the BIG-IP APM access session logon page is accessed, the system deletes the MRHsession session cookie before creating a new session, thus removing the user's session information. Deleting the MRHsession cookie places the session in the expired state, which redirects the user to the session expired logoff page.

Recommendations

Internet Explorer users can work around this issue by disabling the Content Advisor, or the BIG-IP APM administrator can create and apply an iRule to the affected virtual server to retain the MRHsession cookie information during the redirect. To implement the iRule, perform the following procedure:

Impact of procedure: F5 recommends that you perform this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the Name box, type a name for the new iRule.
  5. In the Definition box, enter the following text:

    when HTTP_REQUEST {
        if { [HTTP::uri] eq "/" } {
            set apm_cookie [HTTP::cookie value "MRHSession"]
            if { $apm_cookie != "" && [ACCESS::session exists $apm_cookie] } {
                set back_link [HTTP::header value "Referer"]
                if { $back_link eq "" } {
                    set back_link "javascript:history.back()"
                }
    HTTP::respond 200 content "<html><head><title>BIG-IP session page</title></head><body>
    Your session is established.
    Seems you are using IE Content Advisor.
    <a href='/my.policy'>Click here</a> to start a new session, or <a href='$back_link'>go back</a>.
    </body></html>"
      }
     }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the affected virtual server.
  9. Click the Resources tab.
  10. Click the iRule Manage button.
  11. In the Available column, select the new iRule, and click the << button to move the iRule to the Enabled column.
  12. Click Finished.
