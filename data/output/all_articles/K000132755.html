Introduction

This introduction provides a brief overview. For details, refer to the following guides:

  • Software Installation and Upgrade Overview in VELOS Systems: Software Installation and Upgrade.1
  • Planning for VELOS Guide
  • VELOS manuals listed at the bottom of K000130285: F5 Product Manuals Index

The VELOS chassis system provides a platform layer known as F5OS which includes the following:

  • System controllers to manage the chassis and provide redundancy
  • Chassis partitions to manage logical groups of chassis blades
  • F5OS-C software for the system controllers and chassis partitions

Software images and releases

There are three layers of software images for the VELOS system:

  • System controller—Runs on system controllers only and includes the base OS and platform service components
  • Chassis partition—Runs on blades and controllers and includes the base OS and platform service components
  • Tenant—Runs on blades only

F5OS-C releases provide the operating system software for the VELOS system controllers and chassis partitions. The system controller and chassis partition software images contain the following components:

  • Base OS—Includes software, such as a full CentOS Linux distribution with Docker
  • Service —Includes software, such as KubeVirt, qkview, and the webUI

There are four types of software upgrade releases for the VELOS system:

  • Full system—Complete installation for system controllers and chassis partitions
  • Full component—Complete installation for either the system controllers or the chassis partitions (controller.iso and partition.iso)
  • Partial component —Sub-components of system controllers and chassis partitions (host.os or services.img)
  • Patch/Hotfix—Subset of container packages specific for a component

The ISO images for the system controllers and chassis partitions are available for download on MyF5 . For example, the following table shows the images available for F5OS-C 1.5.1.

F5OS-C 1.5.1 images available for download

VELOS image server

The VELOS system uses a built-in image server (PXE) to store imported software images. You use a PXE boot to update a system controller or blade that does not have an image or needs to have software completely re-installed.

Prepare

Check your BIG-IP tenant slot, boot location, and allocated storage availability

You may not be able to upgrade your BIG-IP tenant due to one of the following reasons:

  • You used the T1-VELOS image type to deploy your BIG-IP tenant (has only one slot or boot location).
  • The BIG-IP version you want to upgrade to requires more storage than the existing allocated storage on the BIG-IP tenant.

If you have this issue, refer to Back up, delete, and restore the BIG-IP tenant in K33251052: Considerations when performing an upgrade or update for a BIG-IP tenant on a VELOS system.

Download software for your VELOS system

For the remote host, F5 recommends you use one of the following and have a valid CA-signed certificate:

  • HTTPS server with PUT/POST enabled
  • Secure Copy (SCP) protocol server
  • SFTP server

This setup enables you to securely download image files and then import them into your VELOS system.

Download the latest F5OS-C image files for your system controller and partition

  1. On your management workstation, go to MyF5 Downloads.
  2. In Account, if you have more than one MyF5 account, select the account you want.
  3. Select the check box to agree with the End User License Agreement and Product Terms.

    Note: The check box displays only when F5 does not yet have a record of you accepting these agreements.

  4. In Group, select F5OS.
  5. In Product Line, select F5OS Platform Software for VELOS.
  6. In Product Version, select the version you want.

    For example, if you are upgrading to F5OS-C 1.5.1, you select 1.5.1.

  7. Under Select a product container, select either 1.5.x-CONTROLLER or 1.5.x-PARTITION.
  8. Under Select a download file, select the file you want to download.

    For example, if you want to download the controller image, you select F5OS-C-1.5.1-14085.CONTROLLER.iso.

    Notes:

    • You can download only one file at a time.
    • The file name consists of the platform family (-C indicates that this image is used for chassis-based VELOS systems) and the build number. The extension depends on the file image type (for example, .iso, .os, .img).
  9. At the bottom of the page, under Download locations, select the location nearest you.
  10. Select Download.
  11. After the system finishes downloading the first file you selected, return to the Select a download file section, and then select the next file you want to download. 
  12. Repeat steps 11 and 12 until you finish downloading all the files you want.
  13. Verify the image using MD5 checksum.

    Note: For more information, refer to K8337: Verifying the MD5 checksum for the downloaded F5 software file.

  14. Transfer the files to a web server in your infrastructure that supports HTTPS.

    Note: If you download a .tar file containing multiple files (rather than an .iso, .os, or .img file), you need to extract the images before you can import them onto the system.

Download the latest tenant image files

  1. On your management workstation, go to MyF5 Downloads.
  2. In Account, if you have more than one MyF5 account, select the account you want.
  3. Select the check box to agree with the End User License Agreement and Product Terms.

    Note: The check box displays only when F5 does not yet have a record of you accepting these agreements.

  4. In Group, select BIG-IP.
  5. In Product Line, select the BIG-IP branch you want.

    For example, if you want to download the latest 17.x release, you select BIG-IP v17.x / Virtual Edition with Traffic Management Operating System (TMOS).

  6. In Product Version, select the version. For example, select 17.1.0.
  7. Under Select a product container, select 17.1.0_Tenant_F5OS.
  8. Under Select a download file, select the appropriate tenant disk image.

    For example, if you want an image that supports all BIG-IP modules, you select BIGIP-17.1.0-0.0.16.ALL-F5OS.qcow2.zip.bundle.

    Notes:

    • You can download only one file at a time.
    • The file name—for example, BIGIP-15.x.x-x.x.x.<disk-size-tag>-F5OS.qcow2.zip.bundle—consists of the platform family, build number, and disk size tag (ALL, T1, T2, or T4).
  9. At the bottom of the page, under Download locations, select the location nearest you.
  10. Select Download.
  11. After the system finishes downloading the first file you selected, return to the Select a download file section, and then select the next file you want to download. 
  12. Repeat steps 11 and 12 until you finish downloading all the files you want.
  13. Verify the image using MD5 checksum.

    Note: For more information, refer to K8337: Verifying the MD5 checksum for the downloaded F5 software file.

  14. Transfer the files to a web server in your infrastructure that supports HTTPS.

Import software into to your VELOS system

You can import files from external servers into the system controller or chassis partition using either the command line, webUI, or API. If you want to import the contents of a .tar file, extract the contents first, before you import them into your VELOS system.

You can import files to the following directories.

Import F5OS-C image files using the command line

Import files to the images/staging directory on the system controller.

Note: The value for the remote-file and local-file options should not contain a leading slash (/).

  1. Log in to the command line of the system controller using the floating IP address and an account with admin access.

    Note: When you log in to the system, you are in user (operational) mode.

  2. Enter the following code syntax:

    file import [ remote-port <port-number> ] remote-host <ip-address-or-fqdn> remote-file <remote-file-path>/<filename> local-file <local-file-path>/<filename> username <user> [insecure]

    For example, the following command imports a system controller image file:

    file import remote-port 443 remote-host download.example.com remote-file F5OS-C/F5OS-C-1.5.1-14085.CONTROLLER.iso local-file images/staging/F5OS-C-1.5.1-14085.CONTROLLER.iso username admin insecure

    For example, the following command imports a chassis partition image file:

    file import remote-port 443 remote-host download.example.com remote-file F5OS-C/F5OS-C-1.5.1-14085.PARTITION.iso local-file images/staging/F5OS-C-1.5.1-14085-PARTITION.iso username admin insecure

    After entering the file import command, the system displays a message similar to the following example:

    File transfer is initiated.(images/staging/F5OS-C-1.5.1-14085-PARTITION.iso)

  3. After you initiate the file import for either the system controller or chassis partition image file, check its status by entering the following command:

    file transfer-status

    For example, when successfully importing the system controller image, the system displays a message similar to the following example:

    S.No.|Operation |Protocol|Local File Path |Remote Host |Remote File Path |Status |Time
    1 |Import file|HTTPS |images/staging/F5OS-C-1.5.1-14085.CONTROLLER.iso |download.example.com|F5OS-C/F5OS-C-1.5.1-14085.CONTROLLER.iso|In Progress (77.0%) Thu Jan 23 14:40:13 2023

Import F5OS-C image files using the webUI

You can use the Import option to download image files from a remote HTTPS server, or you can use the Upload option to upload an ISO file from a client machine. If you use the Import option, your remote HTTPS must allow downloads. This procedure uses the Import option.

  1. Log in to the system controller webUI using the floating IP address and an account with admin access.

    Note: The floating IP always selects the active system controller.

  2. Go to SOFTWARE MANAGEMENT > Controller Images or Partition Images.
  3. Select Import (or you can select Upload to upload from the local workstation).
  4. In URL, enter the URL of the remote image server.

    For example, you enter the following URL:

    https://download.example.com/F5OS-C/F5OS-C-1.5.1-14085.CONTROLLER.iso

    F5 recommends that you use an HTTPS server with PUT/POST enabled and have a valid CA-signed certificate for the remote host. You can select the Ignore Certificate Warnings check box if you want to skip the certificate check.

  5. In Username, enter the user name for an account on the remote image server, if required.
  6. In Password, enter the password for the account, if required.
  7. (Optional) Select Ignore Certificate Warnings to skip the certificate check.
  8. Select Import Image.

    The import may take a few minutes. When the import is successful, the system lists the software image in the webUI.

    Notes:

    • Under Image Import Status, you can watch the progress of the import and confirm when it is successful.
    • If an operation fails, hover over the warning icon to see the error that occurred.
    • When the system encounters an invalid operation, it displays a runtime error in the File Transfer status section.

Import tenant image files using the command line

  1. Log in to the command line of the chassis partition using an account with admin access.

    When you log in to the system, you are in user (operational) mode.

  2. Enter the following code syntax and include the image file you downloaded:

    file import remote-port <port-number> username <user> protocol [ https | scp | sftp ] remote-host <ip-address-or-fqdn> remote-file <remote-file-path>/<filename> local-file images/<filename> [insecure]

    F5 recommends that you use an HTTPS server with PUT/POST enabled and have a valid CA-signed certificate for the remote host. However, to ignore the certificate warnings, use the insecure option.

    For example, you enter the following command:

    file import remote-port 443 username admin protocol https remote-host 10.10.10.100 remote-file BIGIP/BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle local-file images/BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle insecure

    The system displays a message similar to the following example:

    File transfer is initiated.(images/BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle)

  3. After you initiate the the file import, check its status by entering the following command:

    file transfer-status

    The system displays a message similar to the following example:

    S.No.|Operation |Protocol|Local File Path |Remote Host |Remote File Path |Status |Time
    1 |Import file|HTTPS |images/BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle |10.10.10.100 |BIGIP/BIGIP-15.1.8-0.0.7.ALL-F5OS.qcow2.zip.bundle |In Progress (45.0%)|Thu Jan 23 21:10:36 2023

Note: If you are unable to import a tenant image file using the command line, you can use SCP the file by logging in to your client workstation and entering the following command from the directory containing the image file: scp BIGIP-1x.x.x-x.x.x.ALL-F5OS.qcow2.zip.bundle admin@<partition-ip-or-fqdn>:IMAGES/. Note the "IMAGES" directory uses all capital letters and includes a trailing slash (/).

Troubleshoot upgrade issues

In the F5OS-C 1.5.1 release, F5 fixed the the following F5OS issues related to upgrading:

  • Bug ID 1189013: Race condition in platform bringup can result in incorrect Openshift images in local registry after upgrade
  • Bug ID 1154089: After a controller upgrade, Kubevirt pods fail to upgrade due to leftover pods stuck in Unknown state
  • Bug ID 1144633: System controller components can hang during controller rolling upgrade
  • Bug ID 1135181: Controller rolling upgrade may cause blades to reboot into partition "none", deleting tenant data
