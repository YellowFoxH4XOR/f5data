Known Issue

This is the result of a known issue. Starting in BIG-IP version 9.4.2, basic syslog configuration is provided using the Configuration utility, and custom syslog configuration must be performed using the bigpipe command. The bigpipe command currently only allows the addition of one remote UDP syslog server; however, the syslog-ng utility allows for multiple remote syslog servers using either the UDP or TCP protocol.

You can use the bigpipe syslog remote server command to add a remote UDP syslog server to the BIG-IP configuration, but you cannot specify more than one remote syslog server, and you cannot specify the TCP protocol.

F5 Product Development tracked this issue as CR87475 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, PSM, or WebAccelerator release notes.

Note: The fix in BIG-IP version 10.0.0 resulted in a syntax change for the bigpipe syslog remote server command which is detailed in K10057: Change in Behavior: Syntax change for 'bigpipe syslog remote server' command.

Workaround

You can work around this issue and add multiple syslog servers using the protocol of your choice by performing the following procedure:

  1. Log in to the BIG-IP command line.
  2. To add the first remote UDP syslog server to the BIG-IP configuration, use the bigpipe syslog remote server command:

    bigpipe syslog remote server <syslog_ip_address>

    Note: If you are only adding remote TCP syslog servers, skip this step and continue with Step 3.

  3. To add a second remote syslog server, use the following bigpipe syntax:

    bigpipe syslog include '"destination <dest_name> { <protocol>(\"<syslog_ip_address>\" port(<syslog_port>));};log { source(local); destination(<dest_name>);};"'

    Replace <dest_name> with a unique name for the new log destination object, <protocol> with the desired transport protocol (UDP or TCP), <syslog_ip_address> with the IP address of the destination remote syslog server, and <syslog_port> with the port upon which the remote syslog service is listening. The tuple of <protocol>(\"<syslog_ip_address>\" port (<syslog_port>)) may be repeated as necessary, separated by semicolons, to configure multiple destinations.

    For example, the following bigpipe syslog include command adds a remote UDP syslog server with the IP address of 10.0.0.1:

    bigpipe syslog include '"destination d_udp { udp(\"10.0.0.1\" port(514));};log { source(local); destination(d_udp);};"'

    The following bigpipe syslog include command adds two remote TCP syslog servers:

    bigpipe syslog include '"destination d_tcp { tcp(\"10.0.0.1\" port(1468)); tcp(\"10.0.0.2\" port(1468));};log { source(local); destination(d_tcp);};"'

    Important: The include command replaces any previously included data, so only the most recently applied data set is retained. To add multiple destinations, you must construct a single include command following the example above.

  4. The syslog-ng service will automatically restart to initialize the new configuration.

    Note: Examine any console output for errors. A successful include operation will not produce any output to the console. (Benign errors may be observed in the /var/log/boot.log file as noted in K8549: Configuring an additional remote syslog server using the bigpipe syslog include command causes an error message. They may be safely ignored.)

  5. Save the configuration by typing the following command:

    bigpipe save all

If you want to remove the syslog include configuration, run the command bigpipe syslog include none.
