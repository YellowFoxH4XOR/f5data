Known Issue

Note: For information about the Service-Principal Name (SPN) discovery in a Windows cluster environment, refer to K10355: SPN discovery for a Windows cluster.

This is the result of a known issue. The ARX system does not rediscover the Service-Principal Name (SPN) for a node in a Windows cluster when a resource group is moved to a new node, or the node changes as a result of a cluster failover. The ARX system will continue to use the SPN of the original discovered node and the share will remain offline.

F5 Product Development tracked this issue as ARX ID 36847 and it was fixed in ARX version 5.0.6. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was partially fixed in a hotfix available for ARX version 5.0.5. The fix is partial because the hotfix will fix the issue and rediscover the SPN if the share is not used for metadata. However, the SPN is still not rediscovered for metadata shares. Customers affected by this issue can request the hotfix from F5 Technical Support, referencing this solution and ARX ID 36847.

Workaround

Important: This workaround requires the Windows virtual server to be joined to the domain. For environments where the Windows virtual server is not joined to the domain, a workaround is not available.

Use the spn command to configure the external filer on the ARX system to use the virtual server's SPN. The SPN configured with the spn command will override the discovered node SPN, and will ensure the share is available after a failover or if a resource group is moved to a new node.

Note: For information about using the spn command to configure an SPN, refer to the ARX CLI Reference Guide.
