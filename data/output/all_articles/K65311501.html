Known Issue

While monitoring fully qualified domain name (FQDN)-configured nodes or pool members, the bigd process logs the current or previous monitor status of checking or no address as unknown.

The checking state occurs if the DNS resolution of the FQDN node or pool member name is in progress. The no address state occurs if the DNS server returns no IP addresses for the configured FQDN node or pool member name. Other states for FQDN-configured nodes or pool members log monitor status correctly.

This issue occurs when the following condition is met:

  • The FQDN template node or pool member is in the checking or no address state.

Impact

You are unable to determine the correct state of FQDN nodes or pool members identified in these log messages.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You view messages in the /var/log/ltm file that appear similar to the following example:

    notice bigd[6747]: 01060141:5: Node /Common/node_name monitor status up [ 192.168.1.1: unknown ] [ was unknown for 0hr:29mins:48sec ]

    notice bigd[6747]: 01060145:5: Pool /Common/pool_name member /Common/member_name monitor status up. [ ] [ was unknown for 0hr:29mins:48sec ]
