Topic

You should consider using this procedure under the following condition:

  • You want to replicate certain configuration objects from one BIG-IP device on to another.

Description

If you want to replicate certain individual configuration objects on another BIG-IP system for purposes such as testing, troubleshooting, or adding devices, you can do so with iControl REST. Using iControl REST, you can replicate specific configuration objects from a source BIG-IP device to a target BIG-IP device. It is possible to replicate items using this method on BIG-IP devices that have dissimilar versions; however, due to configuration schema changes, you may not be able to do so in every instance.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have command line access to a system with the curl utility.
  • You have command line access to a system with the jq utility for some of the procedures. For more information about the jq utility, refer to the jq manual.

    Note: The previous link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

  • You have a system with network connectivity to both source and target BIG-IP systems.

    Note: You can perform this procedure from the source BIG-IP system, target BIG-IP system, or any other BIG-IP system; however, the jq utility is not available on systems running versions earlier than BIG-IP 12.0.0.

Overview of the basic syntax

The following one-line command shows the basic syntax for replicating configuration objects from one BIG-IP device on to another using curl and iControl REST:

curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/<iControl REST URI> | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/<iControl REST URI>

In the previous syntax, note the following:

  • <source BIG-IP hostname or IP address> is the source BIG-IP system that has the configuration object you want to copy to another BIG-IP system.
  • <target BIG-IP hostname or IP address> is the target BIG-IP system that you want to receive a copy of the configuration object.
  • | is the bash shell's pipe operator which redirects standard output from one curl command to standard input of another curl command.
  • -X POST tells curl to use the HTTP POST method for the request.
  • -d @- reads the data for the HTTP POST from standard input.

    Note: the dash (-) is required in @-

Important: Due to the API changes introduced by ID756979, if you want to clone a client or server SSL profile to a BIG-IP running 14.1.x or later, you'll need to request a response specifically from schema v14.0.0 from the source device. The v14.0.0 version of the schema outputs the tmOptions as an array which the target device is expecting from the POST API request.

For example:
curl -sku admin:admin -H "Content-Type:application/json" https://10.1.1.1/mgmt/tm/ltm/profile/server-ssl/~Common~testServerSSL?ver=14.0.0 | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://10.1.1.2/mgmt/tm/ltm/profile/server-ssl
 

Saving the configuration on the target device

After replicating the configuration from the source BIG-IP device to the target, you must save the configuration on the target. Save the configuration changes to disk using iControl REST. To do so, perform the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

To save the configuration, use the following syntax:

curl -sku <username>:<password> -H "Content-Type: application/json" -X POST https://<target BIG-IP hostname or IP address>/mgmt/tm/sys/config -d '{"command":"save"}'

For example:

curl -sku admin:admin -H "Content-Type: application/json" -X POST https://192.0.2.2/mgmt/tm/sys/config -d '{"command":"save"}'

Procedures

  • Replicating route configuration

You can use the syntax shown previously to replicate numerous types of configuration objects. The procedures in this section only cover some of the common configuration objects you may want to copy from one device to another. The procedures also show how to use the jq utility to remove properties from the source output when necessary and how to use an iControl REST query parameter to expand subcollections.

Replicating route configuration

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a device meeting the previously listed prerequisites.
  2. To replicate a route from one BIG-IP system to another, use the following syntax:

    curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/mgmt/tm/net/route/~<partition>~<route name> | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/mgmt/tm/net/route/

    For example:

    curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/net/route/~Common~example_route | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/net/route/

  3. Ensure that you save the configuration changes on the target device using the syntax shown in the Saving the configuration on the target device procedure.

Replicating monitor configuration

This procedure shows you how to replicate a monitor.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a device meeting the previously listed prerequisites.
  2. To replicate a monitor from one BIG-IP system to another, use the following syntax:

    curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/mgmt/tm/ltm/monitor/<monitor type>/~<partition>~<monitor name> | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/mgmt/tm/ltm/monitor/<monitor type>

    For example:

    curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/ltm/monitor/http/~Common~documentation_monitor | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/ltm/monitor/http

  3. Ensure that you save the configuration changes on the target device using the syntax shown in the Saving the configuration on the target device procedure.

Replicating node configuration

This procedure requires the jq utility. If you only want to replicate nodes to add to new pools on the target device, then perform this procedure, otherwise if you want to create a pool and its associated nodes, you can skip to the Replicating pool configuration procedure because the system automatically creates the associated nodes when you create the members of the pool.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a device meeting the prerequisites.
  2. To replicate a node from one BIG-IP system to another, use the following syntax:

    curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/mgmt/tm/ltm/node/~<partition>~<node name> | jq '. | del(.state,.session)' | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/mgmt/tm/ltm/node

    In the previous syntax, note the following:

    • jq '. | del(.state,.session)' deletes the state and session properties from the output of the source BIG-IP system, which are invalid when creating a node.

    For example:

    curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/ltm/node/~Common~10.0.2.1 | jq '. | del(.state,.session)' | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/ltm/node

    To replicate multiple nodes, using the syntax introduced previously you can place the curl command one-liner in a bash for loop to repeat it for multiple nodes. The following for loop example loops through a range of integers. A single integer is stored in the i variable during each iteration of the loop and the variable is used in a node IP address. The following example replicates nodes 10.0.2.1 through 10.0.2.8 on to the target BIG-IP system:

    for i in {1..8}; do curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/ltm/node/~Common~10.0.2.$i|jq '. | del(.state,.session)'| curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/ltm/node; done

  3. Ensure that you save the configuration changes on the target device using the syntax shown in the Saving the configuration on the target device procedure.

Replicating pool configuration

This procedure requires the jq utility. The system automatically creates the associated nodes when you create the members of the pool. You need to have replicated the monitor on the target system separately.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a device meeting the prerequisites.
  2. To replicate a pool from one BIG-IP to another, use the following syntax:

    curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/mgmt/tm/ltm/pool/~<partition>~<pool name>?expandSubcollections=true| jq '. | del(.membersReference.items[].state,.membersReference.items[].session)' | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/mgmt/tm/ltm/pool

    In the previous syntax, note the following:

    • ?expandSubcollections=true is the query parameter to display pool members when displaying the pool.
    • jq '. | del(.membersReference.items[].state,.membersReference.items[].session)' deletes the state and session properties from the output of the source BIG-IP as they are not valid when creating pool.

    For example:

    curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/ltm/pool/~Common~documentation_pool?expandSubcollections=true| jq '. | del(.membersReference.items[].state,.membersReference.items[].session)' | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/ltm/pool

  3. Ensure that you save the configuration changes on the target device using the syntax shown in the Saving the configuration on the target device procedure.

Replicating SSL profile configuration

This procedure requires the jq utility. To avoid errors when replicating the SSL profile, you will use the options and ver parameters in the iControl REST request.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of a device meeting the prerequisites.
  2. To replicate an SSL profile from one BIG-IP to another, use the following syntax:

    curl -sku <username>:<password> -H "Content-Type:application/json" https://<source BIG-IP hostname or IP address>/mgmt/tm/ltm/profile/<client-ssl|server-ssl>/~<partition>~<profile name>?options=non-default-properties\&ver=14.0.0 | curl -sku <username>:<password> -H "Content-Type: application/json" -X POST -d @- https://<target BIG-IP hostname or IP address>/mgmt/tm/ltm/profile/<client-ssl|server-ssl>/

    In the previous syntax, note the following:

    • ?options=non-default-properties\&ver=14.0.0 is the query string to output only non-default properties and to output in the v14.0.0 schema in case tmOptions is non-default. The tmOptions will be in an array which is expected by iControl REST to create the profile object.

    For example:

    curl -sku admin:admin -H "Content-Type:application/json" https://192.0.2.1/mgmt/tm/ltm/profile/client-ssl/~Common~doc_profile?options=non-default-properties\&ver=14.0.0 | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://192.0.2.2/mgmt/tm/ltm/profile/client-ssl/

    Changing the object name on the target with bash variables example:

    partition="Common" ; oldname="oldprofile" ; newname="newprofile" ; curl -sku admin:admin https://localhost/mgmt/tm/ltm/profile/client-ssl/~$partition~$oldname?options=non-default-properties\&ver=14.0.0 | jq ".name = \"$newname\" | .fullPath = \"\/$partition\newname\"" | curl -sku admin:admin -H "Content-Type: application/json" -X POST -d @- https://localhost/mgmt/tm/ltm/profile/client-ssl/

  3. Ensure that you save the configuration changes on the target device using the syntax shown in the Saving the configuration on the target device procedure.
