Description

  • When attempting to generate a QKView from the WebUI, it will stall, not update the elapsed time, and fail to complete..
  • When running the 'qkview' command from the Bash CLI, it will also stall and never complete.

Environment

  • BIG-IP 
  • QKView Utility

Cause

The QKView process get hung on collecting TMSH Memory statistics.

Recommended Actions

If you run into this issue, it is important to check where the QKView process get hung up.

  1. Confirm where the QKView process gets hung on.
    1. Run the following command from the Bash CLI
      # qkview -v
      This will run the command in Verbose mode and show what process/command it's hanging on.
      It will show an output similar to the following: 
      [admin@BIGIP:Active:In Sync] ~ # qkview -v
Gathering System Diagnostics: Please wait ...
	Executing /bin/date ...
	Result: [0] Elapsed: 0.023697
--- snip ---
	Executing /usr/bin/tmsh -a show net ipsec ipsec-sa all-properties ...
	Result: [0] Elapsed: 0.668869
	Executing /usr/bin/tmsh -a show net ipsec ike-sa all-properties ...
	Result: [0] Elapsed: 0.623979
	Executing /usr/bin/tmsh -a show sys memory ..
  2. Once confirmed, stop the QKView process using 'ctrl+z'
     
  3. To regain the ability to collect a QKView, run the following command to restart the statsd process.
    Note: The stats daemon collects statistics from the system and records them in the rrd files.

    # tmsh restart /sys service statsd
     
  4. After this command completes, you can confirm it resolved the issue by running the following command:

    # tmsh show /sys memory
     
  5. Once you get the above output, you should be able to run collect a QKView from both the Bash CLI or the WebUI.
