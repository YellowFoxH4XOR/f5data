Known Issue

One or more Traffic Management Microkernels (TMM) may fail to send log messages to a remote high-speed logging (HSL) server.

This issue occurs when all of the following conditions are met:

  • You have configured your BIG-IP system to send log messages to a remote HSL server.
  • During TCP connection termination between a TMM and the remote HSL server, the following order of events occurs:
     
    • TMM sends a TCP FIN (finish) message to the remote server and receives a TCP ACK (acknowledgement) from the remote server.
    • The remote server fails to send the expected TCP FIN message to TMM and the TCP connection remains in a hung or zombie state.

Impact

One or more TMMs will fail to send log messages to remote HSL logging servers.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Log messages that appear on the local BIG-IP system are missing on the remote HSL server.
  • Specific TMM instances no longer send messages to the remote HSL server.

Workaround

There is no workaround for this issue. To recover, you can restart TMM by performing the following procedure:

Impact of procedure: Restarting TMM will temporarily halt traffic processing. You should only perform this workaround during a scheduled maintenance period.

  1. Log in to the Advanced Shell (bash).
  2. To restart TMM, type the following command:

    bigstart restart tmm
