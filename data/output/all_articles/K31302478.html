Known Issue

The BIG-IP system may incorrectly use an ephemeral source port when responding to a Simple Network Management Protocol (SNMP) query.

This issue occurs when all of the following conditions are met:

  • You have configured the SNMP agent on the BIG-IP system to allow IPv6 protocol access from the BIG-IP Configuration utility > System > SNMP > Agent > Access (v1, v2c) page.
  • The BIG-IP system has an IPv6 self IP address configured on the Traffic Management Microkernel (TMM) interface.
  • The SNMP query from the client directs to the IPv6 self IP address of the BIG-IP system using a User Datagram Protocol (UDP).

Impact

The SNMP query to the BIG-IP system may fail.

Symptoms

As a result of this issue, you may encounter all of the following symptoms:

  • The SNMP query to the BIG-IP system may fail with an error message that appears similar to the following example:

    Timeout: No Response from udp6:[fe80::1:1:1:1].
  • When reviewing the network packet capture, the BIG-IP system sends out the SNMP response from the TMM interface using an ephemeral port instead of the default port (161). The network packet capture in the following example shows the BIG-IP system (fe80::1:1:1:1) responding to the SNMP query using UDP port 57013 instead of UDP port 161:

    00:03:19.203984 IP6 fe80::1:1:1:2.48375 > fe80::1:1:1:1.snmp: C=Public GetNextRequest(21) .0.1 in slot1/tmm2 lis=
    00:03:19.204665 IP6 fe80::1:1:1:1.57013 > fe80::1:1:1:2.48375: UDP, length 154 out slot1/tmm2 lis=

    For information about performing a TMM network packet capture, refer to K13637: Capturing internal TMM information with tcpdump.
