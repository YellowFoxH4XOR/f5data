K000137617: The functionality of Clientless-Mode in F5 APM

Type
Support Solution
Published
2023-11-17
Updated
2023-11-17
Source

Description

You are using or want to use Clientless-Mode for a connection to resources behind F5 APM and want to understand what it does.

Environment

Resources published behind a F5 APM policy
Usage of API/cURL calls

Cause

The idea and primary function of Clientless mode is to disable the 302 redirect to the /my.policy page upon access and to disable interactive elements in the actual policy itself, an example of such being logon pages. This is necessary for allowing non-interactive user agents (like an API/cURL calls), which cannot handle these interactive html elements, to pass through APM policies without being blocked or redirected. An example of such is cURL - it cannot handle the aforementioned interactive elements normally presented by APM, so the clientless-mode header tells APM to bypass these elements.
Additionally, instead of getting the APM session cookie in that initial 302 redirect to /my.policy, you get it on the first response from the server. Any subsequent requests from the client, assuming the client sends back the session cookie, will use the same session. If the client does not send back the session cookie, then a new APM session is created for each request. The existing sessions will be removed based on the timeout settings in the access policy.

Recommended Actions

If you wish to use Clientless-Mode, here is an example iRule element that would insert it:

when HTTP_REQUEST {
    HTTP::header insert "clientless-mode" 1
}
