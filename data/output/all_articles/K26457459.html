Description
Syslog messages are sent via management route, but source IP address of the syslog message uses self IP instead of management IP.

Environment

  • This occurs during system start-up if syslog-ng starts before the management IP and route are up.

Cause
The issue is due to ID 747676.

On versions where ID 740589 is fixed, an improper configuration will prevent syslog-ng from even starting so that the CPU does not spike. Incorrect syslog configurations will still need to be set properly. Such as, a duplicate destination IP without a unique persist-name is an invalid configuration. With an improper syslog configuration, you will experience issues described in K45010114: All interface are disabled and tomcat service is continuously restarting due to invalid syslog configuration, and GUI access will fail.

Recommended Actions
You may consider configuring Local IP for each remote syslog server to explicitly set which IP address to use as a source IP.

Standalone BIG-IP

From the Configuration Utility (WebUI):

  1. Access "System >> Logs >> Configuration >> Remote Logging".
  2. Either add new remote syslog servers with "Local IP" or edit any existing one and add "Local IP".
  3. Click Update.
  4. Restart syslog-ng service from CLI.

tmsh restart sys service syslog-ng

From CLI:
  1. List the current syslog config

tmsh list sys syslog

  1. Use following command to add a Local IP.

tmsh modify sys syslog { remote-servers modify { <syslog_server_name> { local-ip <source_ip> } } }

For example, following config allows the system to send syslog packets using the source IP 192.168.1.1.

tmsh modify sys syslog { remote-servers modify { remotesyslog1 { local-ip 192.168.1.1 } } }

  1. Use following command to add an additional syslog server with Local IP.

tmsh modify sys syslog { remote-servers add { <syslog_server_name> { host <syslog_server> local-ip <source_ip> } } }

For example, following config allows the system to send syslog packets to a syslog server 192.168.50.10 using the source IP 192.168.1.1.

tmsh modify sys syslog { remote-servers add { remotesyslog2 { host 192.168.50.10 local-ip 192.168.1.1 } } }

  1. Confirm local-ip has been added to the configuration.

tmsh list sys syslog

  1. Save the configuration.
    tmsh save sys config
     
  2. Restart the syslog-ng service.
    tmsh restart sys service syslog-ng

High Availability (HA) environment
In HA environment, syslog config will be synchronized between devices in a device group. Therefore, having a single syslog server configuration will not be enough because Local IP will be different on each device. Solution to the problem is to define two lines per destination syslog server, and it needs to be configured via CLI.

Removing the remote-servers syslog statement (if defined)
If you previously defined a remote syslog server using the tmsh modify /sys syslog remote-servers command, you must remove the remote-servers statement before you define the filter rule. To remove the remote-servers statement, perform the following steps:

  1. To remove the currently defined remote syslog servers, enter the following command.

    tmsh modify /sys syslog remote-servers none

  2. Save the change by entering the following command.

    tmsh save sys config

Defining a syslog rule that references the remote server with localip

To define the desired syslog filter that references the remote server, perform the following procedure:

Note: Modifications to the syslog configuration properties that are made by using this procedure may not be reflected in the Configuration utility.

  1. Run the multi-line command with the desired syslog server and local IP. Replace <syslog_server>, <mgmt_ip_bigip1>, and <mgmt_ip_bigip2>. The persist-name() part is required because the two lines both have the same destination IP and port combination (it does not matter what the localip is). The string inside parenthesis (like "r1" and "r2" below) can be anything, but they must not be the same, and syslog-ng may fail to start without it.

tmsh modify sys syslog include "
    filter error_binding_socket { message(\\\"Error binding socket.*Cannot assign requested address|Initiating connection failed, reconnecting\\\") };
    filter f_remote_loghost {
        level(warning..emerg) and
        not (filter(error_binding_socket));
    };
    destination d_remote_loghost {
        udp(<syslog_server> port(514) localip(<mgmt_ip_bigip1>) persist-name(r1));
        udp(<syslog_server> port(514) localip(<mgmt_ip_bigip2>) persist-name(r2));
    };
    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
    };
    "

Following example lets one device to send syslog packets from its management IP 10.155.124.99 and the other device from its management IP 10.155.124.118 to the same remote syslog server 10.0.10.15:514 in UDP protocol. Because the device with the management IP 10.155.124.99 does not have the other IP 10.155.124.118 and is unable to bind the address, there will be two lines of benign error messages. The syslog filter suppresses the messages before sending out to the remote syslog server.

tmsh modify sys syslog include "
    filter error_binding_socket { message(\\\"Error binding socket.*Cannot assign requested address|Initiating connection failed, reconnecting\\\") };
    filter f_remote_loghost {
        level(warning..emerg) and
        not (filter(error_binding_socket));
    };
    destination d_remote_loghost {
        udp(10.0.10.15 port(514) localip(10.155.124.99) persist-name(r1));
        udp(10.0.10.15 port(514) localip(10.155.124.118) persist-name(r2));
    };
    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
    };
    "

  1. Save the change by entering the following command.

tmsh save sys config

  1. Restart syslog-ng service by entering the following command.

tmsh restart sys service syslog-ng
