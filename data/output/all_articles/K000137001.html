Description

After upgrading the rSeries F5OS-A software, tenants fail to start. kube-flannel is stuck in ImagePullBackOffError status i.e.
kube-system kube-flannel-ds-erf123 0/1 Init:ErrImagePull 0 1d

 

Environment

  • F5OS-A upgrade to a version less than 1.7.0
  • The DaemonSet for kube-flannel is configured with the incorrect image tag "message" :

grep -i "image:" /tmp/omd/scripts/kube-flannel.yml

    image: localhost:2004/appliance-flannel:message

    image: localhost:2004/appliance-flannel:message

 

Cause

The exact conditions that lead to this can be varied but essentially come from incorrect error handling in a script. The issues are tracked as ID1196005 and ID1196017

 Recommended Actions

  1. Check the expected registry port for the current running image
    [root@appliance-1 ~]# ls -l /var/docker/config/platform.yml 
    lrwxrwxrwx. 1 root root 52 Feb 13 13:11 /var/docker/config/platform.yml -> /var/docker/config/appliance/1.4.0-7488/platform.yml

    [root@appliance-1 ~]# mount | grep "1.4.0" | grep "registry"
    /var/export/chassis/import/.mounts/services/R5R10/1.4.0-7488/volume.img on /var/export/chassis/import/.volumes/appliance-services-registry-2004-volume type squashfs (ro,relatime,context=system_u:object_r:container_file_t:s0)
     
  2. Check the expected flannel tag under the identified registry port (2004 from above example)
    [root@appliance-1 ~]# crictl images | grep flannel | grep 2004 
    localhost:2004/appliance-flannel 0.13.1 0a69e5ee8f6ef 20.7MB
     
  3. Edit the DaemonSet of kube-flannel and correct the image tag as applicable (should be 0.13.1 from above example)
    kubectl edit ds kube-flannel-ds -n kube-system 
    Edit all lines matching 'image: localhost:<port>/appliance-flannel:message' to reflect correct tag: 'image: localhost:2004/appliance-flannel:0.13.1'
     
  4. After editing the port or tag on the flannel DaemonSet, reboot the system
