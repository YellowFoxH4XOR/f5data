Description

This article provides a command-line procedure for renewing device trust certificates (dtdi.crt and dtdi.key) on BIG-IP systems. This is useful for automation workflows or scenarios where the GUI is not available. Previously, only GUI-based procedures were documented for this operation.

Renewing device trust certificates is required when the certificates are expiring or have become invalid, and you need to re-establish trust between devices in a BIG-IP high availability (HA) configuration.

Environment

  • BIG-IP (all versions supporting device trust)
  • High Availability (HA) configurations (Device Service Clustering, Sync-Failover, etc.)
  • Automation workflows requiring CLI-based certificate renewal

Cause

None

Recommended Actions

  1. Delete all trust domains to force regeneration of device trust certificates:
    tmsh delete /cm trust-domain all
    Important: This command is destructive. It removes all device trust relationships and associated trust certificates. You must reconfigure device trust and rejoin devices to trust domains after running this command.

Reconfigure device trust:
After running the command, use either the GUI or CLI to re-establish trust between devices. Refer to K13452: Configuring device trust for device service clustering (DSC) for detailed steps.Rejoin devices to trust domains and device groups as needed.Automation guidance:
For automation workflows, ensure that your scripts handle the removal and re-creation of trust domains, and that all devices are properly rejoined to their respective device groups.Best practices:
Perform this operation during a maintenance window, as device trust and HA functionality will be temporarily disrupted.

Additional Information

  • The tmsh delete /cm trust-domain all command is functionally equivalent to using the GUI option Device Management > Device Trust > Reset Device Trust.
  • Alternative syntax (to delete a specific trust domain):
    tmsh delete /cm trust-domain <domain_name>
