Known Issue

Note: For information about the ARX Secure Agent software, refer to K10026: Overview of the ARX Secure Agent software.

This is the result of a known issue. Domain controllers running ARX Secure Agent versions 5.1.0 and 5.1.5 may fail to authenticate usernames containing multibyte Unicode characters. The fgdump utility used by these versions of the ARX Secure Agent does not process Unicode character names properly. As a result, the user will fail to authenticate and receive an unknown user error. In addition, error messages are logged on the ARX system that appear similar to the following example:

: Verify 'NTLM' response for username 'john' domain 'test' using SA '172.16.23.193' clen:8 blen:0 rlen:24 sk_bufsz:64
: connection is alive
: Verification result for test\john from 172.16.23.193 is 15.
: Client authentication failure for service site03.test.selfip.com: user test\john from 172.16.1.186. Reason: user unknown.
: CIFS client 172.16.1.186:1259 connection with VIP:172.16.23.30:445 is disconnected (reason:Down).

F5 Product Development tracked this issue as ARX ID 38142 and it was fixed in ARX Secure Agent version 5.1.7. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was fixed in ARX Secure Agent hotfix versions 5.1.0 HF1 and 5.1.5 HF1. You may download these hotfixes or later versions of the cumulative hotfix from the F5 Downloads site.

Workaround

ARX Secure Agent versions prior to 5.1.0 do not use the fgdump utility and are not affected by this issue. You must uninstall ARX Secure Agent versions 5.1.x from the domain controller and install a prior version.

Important: This workaround does not apply to Microsoft Windows Server 2008 domain controllers; they are not supported by ARX Secure Agent versions prior to version 5.1.0. A workaround does not currently exist for Windows Server 2008 domain controllers.

Note: For information about installing the ARX Secure Agent software, refer to the ARX Secure Agent Installation Guide for the version you are installing.

Additionally, beginning in ARX version 5.2.0 this issue can be avoided by using constrained delegation. When using constrained delegation the ARX Secure Agent software is no longer required to support NTLM and NTLMv2 authentication. For infomation about constrained delegation, refer to K12239: Overview of constrained delegation.
