Known Issue

Renaming a virtual server with an attached plug-in may cause buffer overflow and result in the BIG-IP system producing a Traffic Management Microkernel (TMM) core file.

This issue occurs when all of the following conditions are met:

  • The mcpd.mvenabled database variable is set to true.
  • The new virtual server name is longer than the original one.
  • A Traffic Management Operating System (TMOS) plug-in such as ASM or AAM is associated with the virtual server.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system fails over to another system in the device group.
  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
  • Your BIG-IP system temporarily fails to process traffic while TMM restarts.

Workaround

To work around this issue, instead of renaming the virtual server you can delete and then re-create it.

Impact of workaround: Deleting a virtual server is a disruptive process that will impact new, current, and persisted connections utilizing that virtual server. F5 recommends that you perform this procedure only during a maintenance window.
