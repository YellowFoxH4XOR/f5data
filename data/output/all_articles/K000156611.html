What Happened?

  • You are seeking to understand the difference between TCP and HTTP idle timeouts.

Environment

  • F5 Distributed Cloud (XC) HTTP Load Balancer
  • F5 Distributed Cloud TCP Load Balancer

Resolution/Answer

TCP Idle Timeout

This timeout applies to the underlying TCP connection. It expires when there is no TCP level activity (e.g., packet transmission) for the configured duration.

HTTP Idle Timeout

There are two types of HTTP idle timeouts: 

  1. Request/Response or Stream Idle Timeout. Applies to a single HTTP request/response stream. It defines the maximum duration allowed for an HTTP transaction to complete. This timeout is independent of the TCP connection.

  2. Idle Timeout on Pooled Connections. Applies to pooled HTTP/1.1 connections maintained via keepalive. It defines how long an idle keepalive connection can remain open without any HTTP activity.

Cause

The terminology used in XC may cause confusion.

  • The HTTP Idle Timeout setting on an Origin Pool refers to the keepalive idle timeout (Type 2).
  • Other timeouts not explicitly labeled as “HTTP” typically refer to the Request/Response Idle Timeout (Type 1).

Additional Information

Understanding the distinction between TCP and HTTP idle timeouts is critical for configuring timeouts appropriately in XC environments. Misinterpreting these settings may lead to premature connection termination or inefficient resource usage.
