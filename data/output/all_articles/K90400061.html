Description

You have an HTTP monitor with a receive string that uses regex to parse the pool members' responses

Environment

  • BIG-IP LTM
  • Local Traffic Pool
  • HTTP/HTTPS monitor that uses 

Cause

The monitor's regex receive string may find a match when it shouldn't if the pool member fails to close the connection between responses

Recommended Actions

  1. Enable monitor logging on one of the affected pool members  Note: See K12531 in Related Content for steps on enabling monitor logging
  2. Review the logs in /var/log/monitors
  3. The (_recv_active_service_ping) log will include the pool member's response and logs regarding how bigd is evaluating the response. Review these lines to see if the pool member is responding as expected and is including protocol specified headers and to verify bigd is taking the appropriate action
