Description

After upgrading BIG-IP LTM, BGP (ZebOS) router configuration may be lost after a reboot if the configuration was not explicitly saved to disk. The configuration is present in the pre-upgrade UCS archive but missing from the system after the upgrade, potentially resulting in loss of BGP peering and routing until restored.

Environment

  • BIG-IP LTM
  • Upgrade
  • BGP configured via ZebOS (imish)
  • High Availability (HA) pair

Cause

ZebOS on BIG-IP does not automatically persist running configuration changes to disk unless the write memory or write command is issued within imish. Changes made interactively or via scripts remain only in RAM until explicitly saved; these unsaved changes are lost upon reboot or software upgrade.

Note: Standard BIG-IP backup procedures (tmsh save sys config, UCS archives) only capture the last written ZebOS configuration file, not any unsaved running state.

Recommended Actions

  1. Always execute write memory (or write) in imish after making any changes to BGP/ZebOS configuration to ensure persistence across reboots and upgrades.
  2. When using scripts that modify BGP settings via imish (e.g., called by tmsh run /util imish -f ...), include write memory at the end of each script or config file processed by imish.
  3. If write memory is included at the end of your imish config file (such as ZebOS-set-primary.conf or ZebOS-set-secondary.conf), it is not necessary to call it again separately in parent scripts.
  4. Do not use copy running-config startup-config; this command is not valid in ZebOS on BIG-IP.
  5. The write file command is optional and only required if saving to a non-default location; standard practice uses just write or write memory.
  6. Before performing upgrades or reboots, verify that all intended changes are present in the persistent ZebOS.conf file on disk.
  7. Refer to official F5 documentation for further details on managing and persisting ZebOS configurations.
