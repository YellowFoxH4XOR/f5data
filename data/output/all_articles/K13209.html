Topic

When you create configuration objects on BIG-IP systems, F5 recommends that the objects begin with an alphabetic character. Certain objects, such as virtual servers, pools, nodes, and monitors allow for an IP address as the name of the object. However the system generally does not allow special characters and numerals as the first character of an object name, and the system produces an error when you create such an object. In addition, if you use object names that begin with a numeral or special character when manually editing the BIG-IP configuration files, the configuration will fail to load. This may leave the device in an impaired state after an intentional configuration reload operation, configuration synchronization (ConfigSync), user configuration set (UCS) restore, reboot, or unexpected system reset. This restriction is by design and applies to all configuration object types.

Note: In BIG-IP 10.2.0 and later, some BIG-IP GTM wide IP objects, such as data centers, GTM servers, wide IPs, and pools, may allow names that start with a numeric value.

Attempting to create a virtual server with the name 1virtual would result in error messages that appear similar to the following examples:

  • BIG-IP 11.x and later Configuration utility, or TMOS Shell (tmsh):

    01070088:3: The requested object name (/Common/1virtual) is invalid.

  • BIG-IP 10.x Configuration utility:

    01070088:3: The requested object name (1virtual) is invalid.

  • BIG-IP 10.x command line (bigpipe):

    012e0017:3: The requested item (1virtual destination) is invalid (<virtual key> | show | list | help) for 'virtual'
