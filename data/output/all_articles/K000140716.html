K000140716: Using the Bot Defense "Bot Mitigation Settings".

Type

Published
2024-08-14
Updated
2024-08-14
Source

Description

A user opens a ticket stating that their application/traffic is being blocked and they are getting something called a Support ID.

Environment

  • Possible reasons can be due to a false/positive brought about by a change in traffic or the application.
  • A user gets an unexpected block or maybe an unexpected CAPTCHA after an upgrade.
  • A Bot Defense profile is attached to the virtual server
  • AdvWAF Bot Defense, Support ID

Cause

Mitigations are needed to provide a way to workaround an issue. Sometimes it is a false/positive, and sometimes it may be something with the traffic that is not right but it needs to be allowed so a "mitigation" is provided.

Recommended Actions

There are several ways that can be chosen to do the mitigation:

  • None: With a Trusted / Untrusted bot, all signatures of this class are disabled and are not checked. With a Suspicious browser / Malicious bot, all signatures and anomalies of this class are disabled and not checked. With an Unknown class, no action is performed.
  • Alarm: Detections are performed and logged but not mitigated.
  • CAPTCHA: A CAPTCHA challenge is sent.
  • Block: Blocking page is sent.
  • Honeypot Page: Honeypot page is sent
  • Redirect to Pool: The traffic is redirected to the selected pool.
  • TCP Reset: The connection is terminated

Along with each there are 3 additional settings:

  1. The first one is for how long the "alert level" is maintained for that possible Bot Attack. There has to be no further instances for that time period before the alert is stopped. It is 600 seconds by default. 
  2. The second is how many instances need to occur within a specified time for the mitigation to be invoked.
  3. The third is the time period that the number of instances must occur to be invoked.

The steps to steps to perform these are the same for all currently supported versions:

  1. Go to Security >> Event Logs : Bot Defense : Bot Traffic and search for the event that aligns with the Support ID provided.
  2. In that there is a section titled Bot Details. In most cases you will want to make the mitigation as small as possible. To do that the information in the block titled Detected Anomalies is needed.
  3. Now open the Bot profile that was listed in the Bot Traffic Log entry by going to Security >> Bot Defense >> [bot defense profile name]
  4. Click on the Bot Mitigation Settings
  5. In the section labeled Mitigation Settings Exceptions click on + Add Exceptions 
  6. In the search block enter the information you got from the Detected Anomalies and then click  Add .
  7. With the mitigation now in place you will need to decide the settings to use for it. In most cases the defaults work just fine. If adjustments are needed it is best to do so incrementally rather than just plugging in a big number. Remember you want the mitigation to work, but its effect should be as small as possible to avoid possible unintended consequences.
