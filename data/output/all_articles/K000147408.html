Description

  • I want to block a DDoS attack using TLS fingerprinting

Environment

  • F5® Distributed Cloud HTTP load-balancer

Cause

  • Under DDoS attack with a malicious and reliable TLS Fingerprint

Answer/Recommended Actions

Assumption: An attack has been carefully crafted that the incoming traffic is well randomized and difficult to isolate with traditional parameters (source IPs ranges, AS numbers, country...)

To find the TLS fingerprint of the attack

  1. Go to F5® Distributed Cloud Console
  2. Select the Distributed Apps icon as seen below:  
     

  3. Select the corresponding namespace, then you should see Home > Distributed Apps > "Your Account's Name Space" > Load Balancers

     

    Select Load Balancers (HTTP/TCP Load Balancers) as seen below:

     

  4. Click on the name of the load-balancer that's under attack, you're now presented with the dashboard:

     

  5. In the top right corner, a drop-down menu with a clock symbol reads Last 5 minutes, switch that to however long the attack has been going for.

     

  6. Find the "Top TLS fingerprints" section on the page

     

    Take this "SampleFingerprintValue" and store it somewhere where you can later use it

  7. Optionally, if you want more information about the requests matching the TLS fingerprint, click the Requests tab and use the setting cog at the top of the request list to show the TLS fingerprint.
  8. Click on a request to show the full list of parameters that was recorded.

     

To create a security policy matching this or these TLS fingerprint(s)

  1. In the same namespace, visit the Web App & API Protection >"Your Account's Namespace" > Manage > Service Policy

     

    Ensure that you are in the correct namespace, scroll down to Manage > Service Policies > Service Policies

     

  2. Click Add service policy, and give it a name in the form that pops up.

  3. - Do take note of the naming convention as seen above - (myfirstservicepolicy)
    - Field must consist of lower case alphanumeric characters or "-", start with an alphabetic character, and end with an alphanumeric character


  4. In that same form, select the Rules Section

     
  5. Click Configure

     

  6. Keep the default Denied sources/Deny policy rule in that section first drop-down menu

  7. Find the TLS fingerprint Classes item by scrolling down and click Add Item at the bottom to add the SampleFingerprintValue that you saved earlier
     
  8. Add as many item as you need, using the TLS fingerprint list you copied earlier, then apply and save the policy

To add this security policy to the load-balancer

  1. Navigate to your Load Balancer at Distributed Apps > Load Balancers > HTTP / TCP Load Balancers, and click on the three-dot menu on the right hand side.
  2. Select Manage Configuration

     

  3. Click Edit Configuration on the top right

  4. In the form that pops up, find the Common Security Controls and Service Policies section, and check that it has Apply Specified Service Policies selected in the top drop-down menu.


     
     
  5. Click on Edit Configuration, then Add item, and find the security policy/policies you created in the steps above.
  6. Click Apply, then click Save and Exit.

 

Additional Information

Mitigating a DDoS attack boils down to one thing: isolating a pattern in the attacker's network packets, and using that pattern to filter what traffic needs to be dropped from the incoming traffic. Attackers know this and try to diversify the source (IP address, AS, country...) and the nature (payload, protocol...) of their DDoS traffic as much as possible.

TLS fingerprinting is a new way of isolating the traffic that was generated by the same software. In essence a single piece of software typically has a unique way of negotiating an encrypted connection, and we can leverage on that when trying to find a pattern in attack traffic towards an HTTPS load-balancer.
