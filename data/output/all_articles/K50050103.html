Topic

You should consider using this procedure under the following condition:

  • You want to use the BIG-IP Next Central Manager for one or both of the following reasons:
    • You want to verify the proper operation of your BIG-IP Next instance by uploading a QKView file to F5 iHealth .
    • You want to provide a QKView file to F5 Support to aid in troubleshooting an issue with a BIG-IP Next instance.

Description

You can use the BIG-IP Next Central Manager to automatically collect configuration and diagnostic information in a QKView file from BIG-IP Next instances it manages.

The QKView diagnostic file contains machine-readable (XML) diagnostic data which is combined into a single compressed Tape ARchive (TAR) format file. You can upload this file, called a QKView file, to F5 iHealth, or give it to F5 Support to help them troubleshoot any issues.

Note: F5 Support requires a QKView file in all cases in which remote access to the product is not available.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to BIG-IP Next Central Manager.
  • The BIG-IP Next instance is currently managed by the BIG-IP Next Central Manager.
  • You have command line access to a client system that has the curl utility and the jq utility installed.
  • You have an F5 support account to access the F5 iHealth diagnostics server.
  • You have access to F5 Cloud Docs to review BIG-IP Next Central Manager API documentation.

Procedures

  • Generate a QKView diagnostic file for a BIG-IP Next instance using the BIG-IP Next Central Manager
  • Download a QKView diagnostic file using the BIG-IP Next Central Manager

 Generate a QKView diagnostic file for a BIG-IP Next instance using the BIG-IP Next Central Manager

When you generate a QKView diagnostic file for a BIG-IP Next instance using BIG-IP Next Central Manager, you specify your iHealth credentials and the BIG-IP Next Central Manager automatically attempts to upload the QKView diagnostic file to the iHealth diagnostic server. You can use the BIG-IP Next Central Manager webUI or API to generate a QKView diagnostic file for a managed BIG-IP Next instance.

  • Use the BIG-IP Next Central Manager webUI
  • Use the BIG-IP Next Central Manager API

Use the BIG-IP Next Central Manager webUI

To generate a QKView diagnostic file for a BIG-IP Next instance and automatically upload it to iHealth using the BIG-IP Next Central Manager webUI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Follow the steps in K000130498: Generating new iHealth API credentials using iHealth API token service to generate an iHealth Client ID and Client Secret as needed. Note the expiry date.
  2. Log in to the BIG-IP Next Central Manager webUI.
  3. Select Manage Instances.
  4. Select the name of the instance for which you want to generate a QKView file.
  5. Select QKView Files. You will see a list of the existing QKView files.
  6. Select +Create.
  7. For Client Id, enter your iHealth ClientID.
  8. For Secret, enter your iHealth Client Secret.
  9. For Expiry Date, enter the expiration date for your iHealth credentials.
  10. To save your iHealth credentials on the BIG-IP Next Central Manager, select Save Credentials.
  11. Select Submit, then select Yes, Continue. The screen will show Authenticated when the iHealth credentials are successfully validated.
  12. For QKView File Name, enter a name for the QKView file.
  13. Optional: For F5 Support Case Number, enter the F5 Support case number.
  14. Select Generate to run the QKView. The status is shown on the QKView Files page. 
  15. Once completed, you can select the name of the QKView file which links out to the QKView on iHealth.

Use the BIG-IP Next Central Manager API

When using the BIG-IP Next Central Manager API to generate a QKView diagnostic file for a BIG-IP Next instance, you can configure the iHealth credentials in the BIG-IP Next Central Manager beforehand, or you can specify it in the API request. If you configure the iHealth credentials in BIG-IP Next Central Manager beforehand, then you do not need to specify the iHealth Client Secret in the API request. To configure your iHealth credentials and generate a QKView diagnostic file using the BIG-IP Next Central Manager API, perform the following procedures:

  • Set your iHealth credentials using the BIG-IP Next Central Manager  API
  • Generate a QKView diagnostic file using the BIG-IP Next Central Manager API

Set your iHealth credentials using BIG-IP Next Central Manager API

To set your iHealth credentials on the BIG-IP Next Central Manager using the API, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Follow the steps in K000130498: Generating new iHealth API credentials using iHealth API token service to generate an iHealth Client ID and Client Secret as needed.
  2. Log in to the client system that has the curl and jq utilities installed.
  3. To set the iHealth credentials, you first need to get a login token from the BIG-IP Next Central Manager. You can get the token from the login endpoint and save it to a shell variable for future reference using the following syntax:

    <variable_name>=$(curl -sk -X POST -H "Content-Type:application/json" https://<bigip_next_cm_mgmt_address>/api/login -d '{"username":"<user>","password":"<password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -X POST -H "Content-Type:application/json" https://nextcm.example.com/api/login -d '{"username":"admin","password":"admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  4. Now you can use the token variable to authenticate to the BIG-IP Next Central Manager. To set the iHealth credentials on the BIG-IP Next Central Manager, use the following syntax:

    curl -sk -X POST -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://<bigip_next_cm_mgmt_address>/api/v1/ihealth/config" -d '{"client_id": "<your_ihealth_client_id>", "secret": "<your_ihealth_client_secret>"}' | jq

    For example:

    curl -sk -X POST -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://nextcm.example.com/api/v1/ihealth/config" -d '{"client_id": "d4b2j8u15mhmsle948e1", "secret": "rp7nb84us4mrderweyc7imcm5lbnxtw42dy8p87anio2ap1sfuegip5gc51f7jlg"}' | jq

    The following example response indicates the credentials were successfully saved.

    {
      "_links": {
        "self": {
          "href": "/api/v1/ihealth/config"
        }
      },
      "message": "Credentials for iHealth have been successfully saved",
      "status": 200
    }

  5. To view the iHealth credentials configured on the BIG-IP Next Central Manager, use the following syntax:

    curl -sk -X GET -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://<bigip_next_cm_mgmt_address>/api/v1/ihealth/config" | jq

    For example:

    curl -sk -X GET -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://nextcm.example.com/api/v1/ihealth/config" | jq

    The following example shows a single client is configured:

        "_links": {},
        "clients": [
            "d4b2j8u15mhmsle948e1"
        ],
        "total": 1
    }

Generate a QKView diagnostic file using the BIG-IP Next Central Manager API

To generate a QKView diagnostic file for a BIG-IP Next instance and automatically upload it to iHealth using the BIG-IP Next Central Manager API, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system that has the curl and jq utilities installed.
  2. If you did not save the BIG-IP Next Central Manager login token to a shell variable in the previous procedure, do so now using the following syntax:

    <variable_name>=$(curl -sk -X POST -H "Content-Type:application/json" https://<bigip_next_cm_mgmt_address>/api/login -d '{"username":"<user>","password":"<password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -X POST -H "Content-Type:application/json" https://nextcm.example.com/api/login -d '{"username":"admin","password":"admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  3. Save the instance ID of the BIG-IP Next instance for which you want to generate a QKView file to a shell variable using the following syntax:

    <variable_name>=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://<bigip_next_cm_mgmt_address>/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="<bigip_next_instance_mgmt_ip>")| .id')

    For example, use this command to get the instance ID for the BIG-IP Next instance with management IP 10.10.10.100 and save it to a variable named instance_id:

    instance_id=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://nextcm.example.com/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="10.10.10.100")| .id')

    You can use the echo $instance_id command to view the value of the instance_id variable.

  4. Generate a QKView diagnostic file for the BIG-IP Next instance using the following syntax:

    Note: You may omit the "secret" parameter if you previously configured the iHealth credentials in the BIG-IP Next Central Manager.

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X POST "https://<bigip_next_cm_mgmt_address>/api/v1/spaces/default/instances/<instance_id>/qkviews" -d '{"filename":"<qkview_name>","ihealth_client_id":"<your_ihealth_client_id>","secret":"<your_ihealth_client_secret>","visible_in_gui":true}' | jq

    For example, the following command generates a QKView file named qkview_example.tar.gz and automatically uploads it to iHealth:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X POST "https://nextcm.example.com/api/v1/spaces/default/instances/${instance_id}/qkviews" -d '{"filename":"qkview_example","ihealth_client_id":"d4b2j8u15mhmsle948e1","secret":"rp7nb84us4mrderweyc7imcm5lbnxtw42dy8p87anio2ap1sfuegip5gc51f7jlg","visible_in_gui":true}' | jq

    The following example response shows the job is RUNNING. Note the value for qkview_id, you will use this to check the progress and to download the QKView file:

    {
        "_links": {
            "self": {
                "href": "/api/v1/spaces/default/instances/4672a975-a6e0-4793-ae49-1e551151e93c/qkviews/6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a"
            }
        },
        "qkview_id": "6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a",
        "status": 202,
        "task_id": "415c25ea-4603-46ca-98bc-a58d940371cd",
        "task_status": "RUNNING"
    }

  5. Check the status using the following syntax where <qkview_id> is the value for the qkview_id parameter returned by the previous command:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://<bigip_next-cm_mgmt_address>/api/v1/spaces/default/instances/<instance_id>/qkviews/<qkview_id>" | jq

    For example:

    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://nextcm.example.com/api/v1/spaces/default/instances/${instance_id}/qkviews/6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a" | jq

    When the job is successful, the output will indicate a status of COMPLETED:

    ...                
                       ],
                    "id": "6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a",
                    "ihealth_client_id": "d4b2j8u15mhmsle948e1",
                    "instance_id": "4672a975-a6e0-4793-ae49-1e551151e93c",
                    "instance_ip": "10.10.10.100",
                    "name": "qkview_example",
                    "qkview_job_id": "3b944651-b881-4147-8491-25765b2fd9e2",

                }
    ...

  6. You can list all the QKView files currently on the BIG-IP Next instance using the following command where <bigip_next_cm_mgmt_address> is the management address of the BIG-IP Next Central Manager: 
    curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://<bigip_next_cm_mgmt_address>/api/v1/spaces/default/instances/${instance_id}/qkviews" | jq

    Output will include the complete information for all QKView files on the BIG-IP Next instance.

Download a QKView diagnostic file using BIG-IP Next Central Manager

You can download a QVView diagnostic file for a BIG-IP Next instance using the BIG-IP Next Central Manager webUI or API. The QKView file can then be used for troubleshooting or to upload manually to iHealth. 

  • Use the BIG-IP Next Central Manager webUI
  • Use the BIG-IP Next Central Manager API

Use the BIG-IP Next Central Manager webUI

To download a QKView file using the BIG-IP Next Central Manager webUI, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Next Central Manager webUI.
  2. Select Manage Instances.
  3. Select the name of the instance for which you want to generate a QKView file.
  4. Select QKView Files. You will see a list of the existing QKView files.
  5. Select the check box next to the QKView file you want to download.
  6. Select Download to start the file download.

 Use the BIG-IP Next Central Manager API

To download a QKView file using the BIG-IP Next Central Manager API, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system that has the curl and jq utilities installed.
  2. If you did not save the BIG-IP Next Central Manager login token to a shell variable in the previous procedure, do so now using the following syntax:

    <variable_name>=$(curl -sk -X POST -H "Content-Type:application/json" https://<bigip_next_cm_mgmt_address>/api/login -d '{"username":"<nextcm_user>","password":"<nextcm_password>"}' | jq -r '.access_token')

    For example, use this command to request a login token and save it to a variable named token:

    token=$(curl -sk -X POST -H "Content-Type:application/json" https://nextcm.example.com/api/login -d '{"username":"admin","password":"admin"}' | jq -r '.access_token')

    You can use the echo $token command to view the value of the token variable.

  3. If you did not save the BIG-IP Next Central Manager instance ID to a shell variable in the previous procedure, do so now using the following syntax:

    <variable_name>=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://<bigip_next_cm_mgmt_address>/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="<bigip_next_instance_mgmt_ip>")| .id')

    For example, use this command to get the instance ID for the BIG-IP Next instance with management IP 10.10.10.100 and save it to a variable named instance_id:

    instance_id=$(curl -sk -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" -X GET "https://nextcm.example.com/api/device/v1/inventory" | jq -r '._embedded.devices[] | select(.address=="10.10.10.100")| .id')

    You can use the echo $instance_id command to view the value of the instance_id variable.

  4. You can list the newly created QKView file using the following syntax:

    curl -sk -X GET -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://<bigip_next_cm_mgmt_address>/api/v1/spaces/default/instances/<instance_id>/qkviews/<qkview_id>" | jq

    Using the QKView file created in the previous example, the qkview_id is 6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a. To view the file, use the following command:

    curl -sk -X GET -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://nextcm.example.com/api/v1/spaces/default/instances/${instance_id}/qkviews/6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a" | jq

  5. You can download the QKView file using the following syntax where <qkview_id> is the id of the QKView file returned in the previous response and <qkview_file_name> is the QKView file name to download:

    curl -sk -X GET -H "Content-Type: application/json" -H "Authorization: Bearer ${token}" "https://<bigip_next_cm_mgmt_address>/api/v1/spaces/default/instances/<instance_id>/qkviews/<qkview_id>/files/<qkview_file_name>/download" -o <qkview_file_name>

    Using the output from above, the following example specifies the QKView's id as 6ddd5b5e-fce9-486d-8a8c-1b1c26c0c88a and the QKView file name as qkview_example.tar.gz:

    If successful, there is no output from the previous command. The QKView file will be located in current directory unless you specified another location.
