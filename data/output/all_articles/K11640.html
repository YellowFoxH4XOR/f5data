K11640: TMM may log an error message for some SSL clients that close their connection before receiving a response

Known Issue

This is the result of a known issue. When an SSL client issues a close_notify alert before receiving a response from the peer, TMM logs the following message to the /var/log/tmm file for the virtual server handling the SSL client connection:

Note: A close_notify alert is sent to the peer to notify intent of closing the connection.

unhandled event after 8 events HUDEVT_FLOW_INIT -> NONE in UNESTABLISHED_PROXY HUDCTL_ENABLE -> NONE in UNESTABLISHED_PROXY HUDCTL_ENABLE -> NONE in UNESTABLISHED_PROXY HUDEVT_LISTENER_PICKED -> LB_RESPOND in UNESTABLISHED_PROXY HUDEVT_ACCEPTED -> ESTABLISHED in UNESTABLISHED_PEER HUDEVT_REQUEST -> REQUEST in RESPOND_PEER HUDEVT_REQUEST_DONE -> REQUEST_DONE in RESPOND_WAIT_PEER HUDEVT_EOF -> PEER_EOF in RESPONDING_PEER

Note: This behavior is sometimes referred to as a half close, as the shutdown process requires both the client and the peer to issue a close_notify alert to close the connection entirely.

The error message is benign and will not affect connections. The error message reported by TMM is only reporting that the client closed its connection before TMM responded to the client's request.

F5 Product Development tracked this issue as CR135921 and it was fixed in BIG-IP 10.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3372.0-HF1 for BIG-IP 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
