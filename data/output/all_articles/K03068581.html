Description

When an interface is down or disabled on tmsh, like the following: 
root@(LTM01)(Active)(/Common)(tmos)# show net interface
------------------------------------------------------------------
Net::Interface
Name    Status    Bits    Bits   Pkts  Pkts  Drops  Errs     Media
                    In     Out     In   Out
------------------------------------------------------------------
1.1   disabled    2.9M  124.4K   7.6K   277      0     0      none
1.2         up   12.8M  231.6K  43.2K   255      0     0  40000-FD
mgmt        up  622.7K  237.0K    239   508      0     0  100TX-FD

The corresponding VLAN interfaces are still considered as 'UP' by imish. 
root@(LTM01)(Active)(/Common)(tmos)# imish -r 1
LTM01.telecom.tt[1]>en
LTM01.telecom.tt[1]#show ip int brief
Interface            IP-Address      Status                Protocol
lo                 127.0.0.1          up                    up
tmm                127.1.1.254        up                    up
Internet_2         10.10.10.103       up                    up
Internet_1         10.10.11.103       up                    up
INT_2              10.10.12.103       up                    up
Internal_1         10.10.13.103       up                    up
INT_1              10.10.14.103       up                    up

For instance INT_1 which is only configured on interface 1.1 should be down. 
root@(LTM01)(Active)(/Common)(tmos)# list net vlan INT_1
net vlan INT_1 {
    fwd-mode l7
    if-index 128
    interfaces {
        1.1 {
            tagged
        }
    }
    tag 4242
}

As a consequence, when an interface goes down, this is not seen by imish. This will cause a delay with routed traffic, since the expiry of the BGP timers for the BGP sessions to go down (Default value is 90 sec)

Environment

  • BIG IP
  • imish

Cause

This is expected behavior.
For instance, interface 1.1 and 1.2 can both be in VLAN test_VLAN. If 1.1 goes down, but 1.2 stays up, you would want test_VLAN in ZebOS to still be considered "up".

Recommended Actions

The behavior is as designed.

Additional Information

The "interfaces" in ZebOS are not physical interfaces that match up with the ports 1.1, 1.2, etc... ZebOS has no idea that the physical ports exist.
