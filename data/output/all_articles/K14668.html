Known Issue

The BIG-IP system incorrectly retransmits Diameter messages after a failover. This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a Diameter virtual server
  • The Diameter virtual server is enabled with Connection Mirroring
  • The BIG-IP system was previously the standby device of a highly available device group

This issue occurs because the BIG-IP system fails to remove the Diameter request message from its queue when the corresponding Diameter response message is included in a mirroring update. When the standby BIG-IP system transitions to active state, the system erroneously retransmits the old Diameter request message in its queue to the server. The retransmitted messages may disrupt the Diameter connection.

Impact

Diameter clients experience failed connections after a failover event.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H427312 on the Diagnostics > Identified > Medium screen.
  • Diameter connections fail on the BIG-IP system after a failover event.
  • A tcpdump capture of the affected traffic shows the BIG-IP system repeatedly sends Diameter request messages to the server using old session IDs.

Workaround

To work around this issue, you can disable the Maximum Retransmit Attempts for the Diameter profile assigned to the affected Diameter virtual server. To do so, perform the following procedure:

Impact of workaround: The BIG-IP system will not retransmit Diameter request messages.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Services > Diameter.
  3. Click on the name of the Diameter profile assigned with the affected Diameter virtual server.
  4. Select the Maximum Retransmit Attempts check box.
  5. For Maximum Retransmit Attempts, enter 0 (zero).
  6. Click Update.
