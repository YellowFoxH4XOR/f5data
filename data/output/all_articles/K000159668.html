K000159668: BIG-IP DNSSEC suddenly stops signing DNS records

Type
Support Solution
Published
2026-01-22
Updated
2026-01-22
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000159668

Description

BIG-IP DNS is not returning DNSSEC records (RRSIG, NSEC3, DNSKEY, etc.) for some DNS zones. The zone is configured with DNSSEC signing, but zone transfer requests return unsigned responses without any DNSSEC signatures.

 

Symptoms:

  • Zone transfers (AXFR) return DNS records without DNSSEC signatures
  • Other devices in the same DNS sync group return properly signed zones
  • DNS Express database contains correct zone data
  • The following error messages may appear in /var/log/ltm:
    • 01010373:3: DNSSEC: signing device is congested - rejecting dnssec request, capacity 1000, load 1000
    • 01010216:3: DNSSEC: Signature failed (signature creation) for RRSET

 

Environment

  • BIG-IP DNS
  • DNSSEC-enabled DNS zones with configured signing keys (KSK and ZSK)
  • DNS Express enabled for zone management
  • DNS profile with enable-dnssec yes and process-xfr yes
  • Multiple devices in DNS sync group

Conditions:

  • Crypto card detached from TMM (Traffic Management Microkernel)
  • All cryptographic operations being handled in software instead of hardware
  • Issue may occur after TMM crash or system instability

Cause

The crypto card becomes detached from TMM, causing all cryptographic operations (including DNSSEC signing) to be performed in software. This can lead to resource congestion and failure to sign DNS responses. The detachment may occur following a TMM crash or other system events.

 

Answer/Recommended Actions

Run End User Diagnostics (EUD) testing to rule out hardware issues:

  • Download the latest EUD package for your platform from https://my.f5.com/manage/s/downloads
  • Upload the EUD IM file to /var/tmp on the BIG-IP system
  • Install/upgrade EUD: im EUD_SF-<version>.im
  • Disconnect all network cables before running tests
  • Run EUD tests and review results
  • If any of the tests fail, create F5 support case for RMA.

K7172: Overview of the End User Diagnostics software - https://my.f5.com/manage/s/article/K7172

After performing the EUD/Rebooting the system should restore crypto card attachment to TMM.

 

Additional Information

  • When the crypto card is detached, DNSSEC signing operations may fail or become congested due to software-based cryptographic processing limitations
  • The DNS Express database may contain correct zone data, but DNSSEC signatures cannot be generated during zone transfers
  • EUD testing should show all tests passing if hardware is functioning correctly
  • The issue may affect only specific zones while others continue to function normally
