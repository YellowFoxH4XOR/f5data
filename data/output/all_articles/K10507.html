Known Issue

This is the result of a known issue. Under certain conditions, the BIG-IP WebAccelerator system may log an error message to the /var/log/wa/pvac.log file that appears similar to the following example:

WA Warning: WA RPD-Y: WARNING PvHds.cxx Line : 249, inHashLevel > 3
WA Warning: WA RPD-Y: WARNING PvHds.cxx Line : 249, inHashLevel > 3
WA Warning: WA RPD-Y: WARNING PvHds.cxx Line : 249, inHashLevel > 3

The issue is often caused by an excessively large disk cache. If the <hdPruneStartLevel> and <hdsPruneStopLevel> settings are inadequately defined for a system with a large /var partition, a large disk cache may result.

Note: For more information, refer to K9058: The BIG-IP WebAccelerator may experience degraded performance or system instability as a result of a large BIG-IP WebAccelerator disk cache and K9079: Overview of the BIG-IP WebAccelerator hds_prune process.

The issue can also be related to NTLM authentication, and occur when requested content does not require authentication and is cached by the BIG-IP WebAccelerator in the unauthenticated state. If the content expires and is later refreshed by a request that causes authentication to be completed, the BIG-IP WebAccelerator will send a conditional GET request for the content. If the origin web server (OWS) returns a 304 (Not Modified) response, the BIG-IP WebAccelerator attempts to refresh the content on disk, resulting in the existing content to be written out to the location of the current Unique Content Identifier (UCI).

F5 Product Development tracked this issue as CR114706 and it was fixed in BIG-IP WebAccelerator version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
