Known Issue

This is the result of a known issue. BIG-IP WebAccelerator versions 10.0.0 and 10.0.1 may send requests to a BIG-IP WebAccelerator-enabled HTTP class applied to the virtual server, even though they do not match the filters configured for that HTTP class.

For example, when the following HTTP classes are applied to your virtual server, the BIG-IP WebAccelerator may incorrectly send a request for the example.txt file to the BIG-IP WebAccelerator-enabled HTTP class named ImageClass:

HTTP ClassWebAcceleratorMatches
ImageClassEnabledall requests for files having standard image extensions
TextClassDisabledall requests for files having the .txt extension

Note: In versions that are not affected by this issue, you can use multiple HTTP class profiles to selectively bypass the BIG-IP WebAccelerator. For more information, refer to K9585: Using multiple HTTP classes to selectively bypass BIG-IP WebAccelerator.

F5 Product Development is tracking this issue as CR124774 for the BIG-IP WebAccelerator 10.0.x branch. This issue does not affect the 9.4.x and the 10.1.x branches.

This issue was fixed in Hotfix-BIGIP-10.0.1-402.7-HF4 issued for BIG-IP 10.0.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing version 10.x hotfixes on systems with a logical volume management (LVM) disk-formatting scheme, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about installing version 10.x hotfixes on systems with a partitioned disk-formatting scheme, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

You can work around this issue by using an iRule to bypass the BIG-IP WebAccelerator. To do so, refer to K10127: Bypassing the BIG-IP WebAccelerator with an iRule in version 10.x.
