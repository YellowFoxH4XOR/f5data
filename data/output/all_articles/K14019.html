Known Issue

The BIG-IP system resets the egress IP Type of Service (ToS) to zero (0).

This issue occurs when all of the following conditions are met:

  • A virtual server is configured with both a Session Initiation Protocol (SIP) and User Datagram Protocol (UDP) profile.
  • The IP ToS setting in the UDP profile is set to Pass Through.

The IP ToS setting controls the Differentiated Services Code Point (DSCP) values of the Differentiated Services (DS) field in the IP header. This information is used in Quality of Service (QoS) configurations to give specific traffic priority on the network. By resetting the DSCP values to zero, the SIP traffic egressing from the BIG-IP system does not receive the expected priority while traversing through the network.

Impact

SIP traffic egressing the BIG-IP system does not receive the expected priority. This issue may cause voice quality degradation.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A packet capture on the affected traffic shows the DSCP value in the DS field is set to zero for SIP packets egressing from your BIG-IP system.
  • Traffic priority failure for SIP traffic egressing from your BIG-IP system, which may also cause voice quality degradation.

Workaround

To work around this issue, you can set the IP ToS setting to a specific value in the affected UDP profile. Alternatively, you can use an iRule to preserve the DSCP values when passing through the BIG-IP system. To do so, perform either of the following procedures applicable for your environment:

  • Configuring the IP ToS setting to a specific value
  • Using an iRule to preserve the DSCP values

Configuring the IP ToS setting to a specific value

Impact of workaround: All traffic processed by this UDP profile will have their DSCP values set to the configured value instead of their original values.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Profiles.
  4. Click Protocol.
  5. Click UDP.
  6. Click on the name of the affected UDP profile.
  7. In the IP ToS box, enter a value.
  8. Click Update.

Using an iRule to preserve the DSCP values

Impact of workaround: The following iRule may not apply to all environments. F5 recommends you author an iRule that may work best for your application environment. Additionally, adding an iRule will increase the resources used by the associated virtual server. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends testing any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click iRule List.
  5. Click Create.
  6. Enter a name for the iRule.

    For example:

    sol14019-workaround

  7. Copy the following syntax:

    when CLIENT_ACCEPTED {
       set client_tos [IP::tos]
    }
    when SERVER_CONNECTED {
      IP::tos $client_tos
    }

  8. Paste the copied syntax into the Definition box.
  9. Click Finished.
  10. Assign this iRule to the affected virtual server.
