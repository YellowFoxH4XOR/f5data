K08952932: iqdump returns ''SSL_ERROR_SYSCALL'' error

Type
Support Solution
Published
2020-09-28
Updated
2025-04-01
Applies to
  • BIG-IP
  • BIG-IP GTM
  • BIG-IP DNS
Source
https://my.f5.com/manage/s/article/K08952932
Description

gtm_add fails with unspecific error but iqdump returns "SSL_ERROR_SYSCALL" error. 
Hence gtm syn will not function as result.

Error messages:

[root@bigip:Active:Standalone] config # gtm_add 10.10.10.14
WARNING: Running this script will wipe out the current configuration
...
...
Saving Ethernet mapping...done
Verifying iQuery connection to 10.10.10.14. This may take up to 30 seconds
iQuery connection to 10.10.10.14 failed.
Is big3d running?
Is tcp port 4353 access allowed?

Restarting gtmd

[root@bigip:Active:Standalone] config # iqdump 10.10.10.14
SSL return code: SSL_ERROR_SYSCALL

Environment

  • BIG-IP DNS
  • gtm_add
  • iqdump

Cause

Wrong MTU set on the Vlan used by iQuery communication. 

Recommended Actions

First of all, check out below articles and verify all the requirements are in place.

  • K13734: BIG-IP DNS synchronization group requirements
  • K13690: Troubleshooting BIG-IP DNS synchronization and iQuery connections (11.x - 15.x)


If gtm_add still failing despite no issue with certificate, allowed ports and the rest of requirements:

  1. Take a packet capture on port 4353
  2. Verify whether the configured MTU for the Vlan used for iQuery communication is larger than 1500 with 'don't frag' flag set

As a result, in a pcap file on the existing DNS system you will see no reply is received from new DNS in response to 'Server Hello, Certificate, Certificate Request, Server Hello Done' sent by existing DNS system. 

To resolve this issue, you will need to modify the MTU to 1500 or an appropriate value on the affected Vlan.
