Topic

If the BIG-IP Link Controller is not configured properly, the gateways for the Link Controller links will be marked red (unavailable), even though the gateways have been verified to be available. You can verify that the BIG-IP Link Controller links are configured correctly by performing the following procedures:

  • Defining a gateway for each link as a member
  • Ensuring all members of the gateway pool are available
  • Defining each member of the gateway pool as a gateway in the link object definitions
  • Ensuring the TMM default route uses the gateway pool
  • Ensuring the servers listed in the Link Definitions portion of the /config/gtm/wideip.conf file are not using the MGMT IP address

Defining a gateway for each link as a member

To ensure you have defined a gateway pool with the gateway for each link as a member, perform the following procedure:

  1. Log in to the BIG-IP Link Controller Configuration utility.
  2. From the Configuration utility, click Local Traffic.
  3. Click Pools.

    The Pools list is displayed.

  4. Verify that a gateway pool has been created. If a gateway pool has not been created, then create one with the gateway for each link as a member.

Ensuring all members of the gateway pool are available

To ensure that all members of the gateway pool are available, perform the following procedure:

  1. Log in to the BIG-IP Link Controller command line.
  2. Use the ping command to ensure that each member is available, by typing the following command:

    ping <member IP address>

  3. Repeat the ping command for each gateway pool member.

    Important: If the link gateway is not configured to respond to the ping command, you will need to ensure that ICMP is not used as a health monitor for the gateway pool members.

Defining each member of the gateway pool as a gateway in the link object definitions

To ensure that each member of the gateway pool is defined as a gateway in the link object definitions, perform the following procedure:

  1. Log in to the BIG-IP Link Controller Configuration utility.
  2. From the Configuration utility, click Link Controller.
  3. Click Links.

    The Link list is displayed.

  4. Verify that a link has been created for each gateway pool member.

Ensuring the TMM default route uses the gateway pool

To ensure that the TMM default route uses the gateway pool, perform the following procedure:

  1. Log in to the BIG-IP Link Controller Configuration utility.
  2. From the Configuration utility, click Network.
  3. Click Routes.

    The Routes list is displayed.

  4. Verify that the Default Gateway uses the gateway pool.

Ensuring the servers listed in the Link Definitions portion of the /config/gtm/wideip.conf file are not using the MGMT IP address

Ensure that the servers listed in the Link Definitions portion of the /config/gtm/wideip.conf file are using their TMM self IP address and are not using their MGMT IP address, by performing the following procedure:

  1. Log in to the BIG-IP Link Controller command line.
  2. Change directories to the /config/gtm directory by typing the following command:

    cd /config/gtm

  3. Create a backup copy of the wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.original

  4. Using a text editor, edit the wideip.conf file.
  5. Locate the Link Definitions section of the file and verify that the IP addresses used for the server definitions are the TMM Self IP addresses and not the MGMT IP address.
  6. Save the wideip.conf file, and exit the text editor.

Apply all of the changes that you made to the BIG-IP Link Controller, by typing the following command:

gtmload
