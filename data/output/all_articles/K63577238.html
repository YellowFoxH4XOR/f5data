Issue

You should consider using this procedure under the following condition:

  • You have an issue using F5 Modules for Ansible and want to gather data to troubleshoot on your own or for a F5 support case.

Recommended Actions

The following procedures can help you with troubleshooting F5 Modules for Ansible.

F5 Modules for Ansible employ the iControl REST API to configure the BIG-IP or BIG-IQ and the restjavad process provides the API functionality. F5 Modules for Ansible version 2 make use of AS3 and the restnoded process handles AS3 declarations. Therefore, many of the following procedures involve working with the iControl REST API or the restjavad and restnoded processes.

Procedures

When experiencing F5 Modules for Ansible issues, you can use the following troubleshooting steps to determine the root cause:

  • Enable verbose mode
  • Bypass Ansible
  • Review log files
  • Capture restjavad traffic
  • Run the Ansible task debugger

Enable verbose mode

When running the ansible-playbook command, you can enable verbose mode by including the -vvvv command line option.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine
  2. Change to the directory with your playbooks.
  3. Include the verbose option with the ansible-playbook command when executing a playbook by using the following syntax:

    ansible-playbook -vvvv <playbook file>

    For example:

    ansible-playbook -vvvv add_node.yml

Bypass Ansible

Bypassing Ansible and connecting to the iControl REST API directly when troubleshooting may help to isolate the issue.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

F5 Modules for Ansible version 1

If the playbook you're troubleshooting, creates a node similar to the following example:

- name: Create node1
  bigip_node:
      host: "10.2.3.4"
      name: "10.2.3.4"
      provider: "{{ provider }}"

You can use an HTTP client such as curl to access the iControl REST API to create a node. This is the curl equivalent to the Ansible task shown previously:

curl -sku admin:admin -H "Content-Type: application/json" https://10.154.210.217/mgmt/tm/ltm/node --data '{"name":"10.2.3.4","address":"10.2.3.4"}'

Observe the results to determine if going directly to iControl REST API produces a different outcome.

F5 Modules for Ansible version 2

If the playbook you're troubleshooting has an AS3 deployment task similar to the following where it deploys the declaration my_declaration.json from the files directory:

- name: Deploy or Update AS3
  f5networks.f5_bigip.bigip_as3_deploy:
      content: "{{ lookup('file', 'files/my_declaration.json') }}"

You can use an HTTP client such as curl to access the iControl REST API to deploy the AS3 declaration. This is the curl equivalent to the Ansible task shown previously:

curl -sku admin:admin -H Expect: https://10.154.210.217/mgmt/shared/appsvcs/declare --data @files/my_declaration.json

Observe the results to determine if going directly to iControl REST API produces a different outcome.

Review log files

When troubleshooting it may be helpful to review the log file for restjavad as this daemon provides the iControl REST API. Review the following files:

  • /var/log/restjavad.[0-9]*.log

Because the BIG-IP uses restnoded for AS3 functionality, you should also review the following file when working with F5 Modules for Ansible version 2:

  • /var/log/restnoded/restnoded.log

Enable restnoded debug logging for F5 Modules for Ansible version 2 troubleshooting

Impact of procedure: Features that make use of F5 REST Node.js will be interrupted while the service restarts. In addition, enabling debug logging can increase disk and CPU activity. F5 does not recommend leaving debugging enabled on a production device for extended periods of time.

  1. Log in to the BIG-IP command line.
  2. Create an empty debug file to notify the process to enter debug mode upon the next restart using the following command:

    touch /service/restnoded/debug

  3. Restart restnoded by entering the following the command:

    bigstart restart restnoded

  4. Leave debug mode on while you reproduce the issue.
  5. Review the contents of /var/log/restnoded/restnoded.log.
  6. Revert to standard logging by removing the debug file. To do so, enter the following command:

    rm /service/restnoded/debug

  7. Restart the service once more by entering the following command:

    bigstart restart restnoded

Capture restjavad traffic

You can analyze network traffic to and from the restjavad process to aid in troubleshooting. It is typically not necessary to also capture restnoded traffic; however, if desired you can capture on port 8105 to see traffic from this process.

Impact of procedure: Capturing network traffic can increase disk and CPU activity. F5 recommends only capturing traffic during active troubleshooting sessions.

  1. Log in to the BIG-IP command line.
  2. Use the tcpdump utility to capture restjavad traffic on the loopback interface and port 8100. To do so enter the following command:

    tcpdump -nni lo -s0 port 8100 -w /shared/tmp/restjavad-$(date +%H%M%S-%m%d%y).pcap

    Note: The date command will include the current time in hours, minutes and seconds followed by the current date in the capture file name for example: restjavad-173643-060322.pcap.

  3. Leave the capture running while you reproduce the issue.
  4. Stop the capture by entering Ctrl + C.
  5. Collect the file from the /shared/tmp directory.

For more information about packet capturing refer to K411: Overview of packet tracing with the tcpdump utility and K1893: Packet trace analysis.
