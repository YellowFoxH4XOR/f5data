Known Issue

Logging action in a BIG-IP APM Secure Web Gateway (SWG) per-request policy may cause the Traffic Management Microkernel (TMM) to continuously restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for an SWG Per-Request policy.
  • The SWG Per-Request policy is configured with a Logging action.
  • The Logging action is configured to log application lookup perflow session variables similar to the following example:

    perflow.application_lookup.result.families:  %{perflow.application_lookup.result.families}
    perflow.application_filter_lookup.result.action:  %{perflow.application_filter_lookup.result.action}
    perflow.application_lookup.result.effective_application:  %{perflow.application_lookup.result.effective_application}
    perflow.application_lookup.result.effective_family:  %{perflow.application_lookup.result.effective_family}
    perflow.application_lookup.result.names:  %{perflow.application_lookup.result.names}
    perflow.application_lookup.result.primary_application:  %{perflow.application_lookup.result.primary_application}
    perflow.application_lookup.result.primary_family:  %{perflow.application_lookup.result.primary_family}

  • The policy does not have an Application Lookup action configured for the system to perform before the Logging action.

When you configure an SWG Per-Request policy to log application lookup perflow session variables, you must precede the Logging action with an Application Lookup action.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system may temporarily fail to process traffic as it recovers from a TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp that correlates with the traffic interruption.

Workaround

To work around this issue, you can either add an Application Lookup action to the policy or remove the application lookup perflow session variables from the Logging action. To do so, perform either of the following procedures:

  • Add an Application Lookup action to the policy
  • Remove the application lookup perflow session variables from the Logging action

Add an Application Lookup action to the policy

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy > Per-Request Policies.
  3. Open the affected policy in the visual policy editor (VPE) by clicking Edit to the right of the policy name.
  4. Locate the Logging action that is configured to log perflow variables.
  5. Click the + (plus) icon to the left of the Logging action configured to log perflow variables.

    Note: If the policy contains multiple Logging actions configured to log perflow variables, you need to insert only a single Application Lookup action to the policy. However, the Application Lookup action must be located within the policy somewhere to the left of the first Logging action configured to log perflow variables.

  6. Click the General Purpose tab.
  7. Click the Application Lookup button to select the Application Lookup action.
  8. Click Add Item.
  9. Click Save.
  10. To close the VPE window, click Close.

Remove the application lookup perflow session variables from the Logging action

Impact of procedure: The removed application perflow variables will not be logged.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Access Policy > Per-Request Policies.
  3. Open the affected policy in the VPE by clicking Edit to the right of the policy name.
  4. Locate the Logging action and click the object that you want to edit.
  5. Remove any entries that log the application lookup perflow session variables.
  6. Click Save.
  7. To close the VPE window, click Close.
