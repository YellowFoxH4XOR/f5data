Known Issue

This is the result of a known issue. If the BIG-IP units forming a high availability pair are assigned a preferred redundancy state, and the preferred active unit is rebooted or its services are restarted, the preferred active unit may go active before the network interface drivers have fully initialized. As a result, the unit will be active, yet unable to receive traffic, resulting in a short-term site outage.

When this issue occurs, the command line prompt changes from Inoperative to Active. However, the bigstart status command reports the lacpd process as down, waiting on the interface driver to finish initializing:

lacpd down, waiting for bcm56xxd to release running semaphore

The situation resolves itself when the network interface driver is fully loaded and the lacpd process is able to start.

Note: This issue occurs regardless of whether network or hardwired failover is used.

Note: For more information about the Redundancy State Preference setting, refer to K8184: Overview of the Redundancy State Preference setting.

Note: For information regarding a related issue, refer to K10703: Using the Redundancy State Preference setting with network failover may cause both units to be active for a brief period of time.

F5 Product Development tracked this issue as CR127061 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, or Edge Gateway release notes.

Workaround

You can work around this issue by setting the Redundancy State Preference setting of both BIG-IP units to None. To do so, refer to K8184: Overview of the Redundancy State Preference setting.

Alternatively, if you are using network failover, you can work around this issue by raising the value of the Failover.TmmStartDelay database variable. Doing so delays the start of the TMM process until the network drivers have started, which allows each unit to properly configure its status. To increase the delay from the default 60 seconds to 90 seconds, enter the following command from the command line on each unit of the redundant pair:

bigpipe db Failover.TmmStartDelay 90

Note: Increase the value of the Failover.TmmStartDelay variable further if necessary to ensure the BIG-IP redundant system is able to pass traffic as expected after failover.
