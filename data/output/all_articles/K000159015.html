Description

It is often assumed that Sync-Failover and Sync-Only do pretty much the same thing. But that is not accurate. So what is the difference and when is each appropriate?

Environment

  • Traffic Management Objects, Non-traffic Management Objects
  • Device Groups, AdvWAF/ASM, APM

Cause

Sync-Failover creates a fully redundant, active-standby pair/group that synchronizes all configuration and traffic objects (like Virtual Servers, Pools, Floating IPs) for seamless application failover. Whereas Sync-Only only synchronizes non-traffic configurations (like APM policies, ASM policies, certain folders) without providing failover for LTM traffic, often used for sharing specific data across geographically diverse systems. Think of Sync-Failover for true HA and Sync-Only for data sharing/central management.

Recommended Actions

When is each appropriate?

  1.  Sync-Failover can be used for everything and it does simplify the sync configuration. 
  2. There are a few cases where Sync-Only should be considered:
    1. ASM requires its own sync setup. This is beneficial for a few reasons:
      1. This is in part due to all of the traffic that can be generated by the constant changes when policies are in Auto learning.
      2. Due to the size of some of the ASM sync's even when sync'd manually it can cause the BIG-IP to switch from an incremental sync to a full sync. Again causing a lot of resource and network overhead. Especially when done in conjunction with all of the traffic management objects when a Sync-Failover Group is used.
      3. It is also used in situations where responsibilities on the BIG-IP are separated. This separation often occurs when one group is in charge of traffic management (LTM, DNS, etc) and one is in charge of security. At times it is possible that if the same Sync-Failover group is used for both then one group may cause a sync that adversely affects the BIG-IP due to work the other group is doing but is not yet ready to sync.
      4. In this case it also helps to set ASM sync as Auto Sync with Save on Auto Sync also set. Auto sync is not often recommenced for traffic management objects. 
      5. K12200102: Enabling Application Security Synchronization on a device group
    2. APM  also has a requirement for its own sync.
