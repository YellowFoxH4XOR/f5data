Known Issue

The TMM process may produce a core file and restart when DNS cache sizes are set too high.

This issue occurs when one of the following conditions are met:

  • One or more of the following DNS cache settings are set higher than 150MB:

    • Message Cache Size
    • Resource Record Cache
    • DNSSEC Key Cache Size
  • The Name Server Cache Count is set to more than 1 million entries

DNS Cache settings are allocated on a per-TMM instance basis. For example, on a system with 8 TMM instances, with a Message Cache Size of 256 MB, the total allocation for Message Cache Size is 2 GB (8 * 256 = 2048). To determine the number of TMM instances for your platform, refer to K14358: Overview of Clustered Multiprocessing (11.3.0 and later).

Note: The BIG-IP system does not pre-allocate all of the DNS Cache allowed memory; the system allocates memory as needed.

Impact

If the BIG-IP system is a member of a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM process restarts.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H458844 on the Diagnostics > Identified > Medium|High screen.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system may temporarily fail to pass traffic.

Workaround

To work around this issue, you can lower DNS caching sizes for Message Cache Size, Resource Record Cache Size, and DNSSEC Key Cache Size to 150 MB or less, and configure the Name Server Cache Count to less than 1 million entries.
