Source

Description

Virtual server configured with a logging profile to send the log to a remote server


Environment

  • Logging profile
  • Remote server
  • ASM

Cause

The daemon bd connects to syslog through the management interface.
The connection to the syslog server is in TIME_WAIT.


Recommended Actions

If the connection to the syslog server is in TIME_WAIT, either remove the syslog server from all security logging profiles or restart bd to attempts to re-establish the connection.
After the syslog server is added or bd restarted, the following command should see the connection in status ESTABLISHED

 

# netstat -pan | grep "./bd" | grep "514"

tcp6 0 0 10.10.10.11:58011 10.20.20.10:514 ESTABLISHED 14407/./bd

 

Troubleshooting approach if the problem persists:

 

  1. Check that there is a route to the syslog server from management interface.
  2. Attempt to establish a connection to the syslog server:

 

For TCP port 514:

# nc 10.20.20.10 514 -v

Ncat: Version 6.40 ( http://nmap.org/ncat )

Ncat: Connected to 10.20.20.10:514.

 

For UDP port 514:

# nc 10.20.20.10 514 -vu

Ncat: Version 6.40 ( http://nmap.org/ncat )

Ncat: Connected to 10.20.20.10:514.

 

  1. Remove the syslog server from all security logging profiles or restart bd to attempt to re-establish the connection

 

POA to collect data:

  1. If the syslog server is removed, we shouldn't see any output:

# netstat -pan | grep "./bd" | grep "514"

 

  1. After the syslog server is added or bd restarted: the following command should show the connection in status ESTABLISHED

# netstat -pan | grep "./bd" | grep "514"

tcp6 0 0 10.10.10.11:58011 10.20.20.10:514 ESTABLISHED 14407/./bd

 

  1. If we do not see similar output, we need to collect a packet capture in the management interface:

# tcpdump -s0 -nni mgmt host <serverip>

 

  1. If the connection is established but there is no logs in the remote server: enable BD logger

# cp /etc/ts/bd/logger.cfg /etc/ts/bd/logger.cfg.backup

# vi /etc/ts/bd/logger.cfg

 

MODULE=IO_PLUGIN;

LOG_LEVEL=TS_INFO | TS_DEBUG;

FILE = 2;

 

MODULE=BD_PB;

LOG_LEVEL=TS_INFO | TS_DEBUG;

FILE = 2;

 

MODULE=BD_MISC;

LOG_LEVEL=TS_INFO | TS_DEBUG;

FILE = 2;

 

MODULE = ALL;

LOG_LEVEL = TS_ERR | TS_CRIT | TS_WARNING | TS_NOTICE;

FILE=2;

 

  1. Enforce bd logger

# /usr/share/ts/bin/set_active.pl --update_logger_cfg

 

  1. Collect a packet capture in the management interface.
  2. After the test, we should see the logs in var/log/ts/bd.log

 

BD_MISC|DEBUG |Sep 08 08:10:48.593|14514|LoggingAccount.cpp:3533|going to write to REMOTE_LOGGER :handle:0x7effe4470240 severity: 6 len: 1284 output: xxx

 

  1. Stop debug

# cp /etc/ts/bd/logger.cfg.backup /etc/ts/bd/logger.cfg

# /usr/share/ts/bin/set_active.pl --update_logger_cfg

 

  1. Collect ASMQkview:

# asmqkview -s0 --add-request-log --include-traffic-data

 

  1. Create a tarball of the Host logs by running the following commands:

# tar zcvf /var/tmp/$HOSTNAME-logs.tar.gz /var/log/*


Additional information 

Post this, we should have a tcpdump capture, ASM qkview and a tarball
