Description

After reboot, the system remains in INOPERATIVE mode, and messages similar to the following will be seen repeatedly in /var/log/ltm:

emerg chmand[7806]: 012a0000:0: FPGA firmware mismatch -  auto update, No Interruption!
emerg chmand[7806]: 012a0000:0:  No HSBe2_v4 PCIs found yet. possible restart to recover Dataplane.
emerg chmand[7806]: 012a0000:0: Dataplane INOPERABLE - Incorrect number of HSBs:0, Exp:1, TMMs: 2
err chmand[7806]: 012a0003:3: HAL exception publishing switch config: Dataplane INOPERABLE - Incorrect number of HSBs:0, Exp:1, TMMs: 2

Environment

  • iSeries
  • UCS load or reboot

Cause

Bug ID 795649: FPGA firmware fails to load on iSeries platform after loading UCS from dissimilar model

Recommended Actions

Follow the workaround in ID 795649 and update the symbolic link to point to the correct firmware version.

Alternatively, the following has also been known to resolve the issue:

unlink /config/firmware/hsb/current_version; reboot

Additional Information

This issue occurs when loading a UCS archive taken from one iSeries model onto another model, for example, from an i7800 onto an i11400-ds, or from an i2600 to an i5600. The issue does not always occur immediately after a UCS load, but may appear after a subsequent reboot.

You can determine the correct symbolic link to use prior to loading the UCS or alternatively by viewing the symbolic link on another BIG-IP of the exact same model type. The command to view the symbolic link is:
ls -l /config/firmware/hsb/current_version

The problem may appear to be caused by a hardware defect, but it is entirely caused by software conditions and easily fixed. Hardware replacement is not required.
