Known Issue

Virtual servers configured to use a TCP profile may retransmit initial TCP SYN packets at a slightly more aggressive rate than current RFC algorithms.

This issue occurs when all of the following conditions are met:

  • You have a virtual server configured with a TCP profile.
  • A remote device, such as a pool member, does not respond when the BIG-IP system attempts to create a new TCP connection.

Impact

Network congestion is slightly increased.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H501233 on the Diagnostics > Identified >Medium screen.
  • When inspecting network traffic, TCP SYN retransmissions may be slightly more aggressive than current RFC algorithms.

Workaround

To work around this issue, you can modify the TCP profile syn-rto-base option to a value other than 0 or 3000. To do so, perform the following procedure.

Note: The TCP profile syn-rto-base option is available only in BIG-IP 11.x.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the syn-rto-base option to 3001, use the following command syntax:

    modify ltm profile tcp <profile name> syn-rto-base <value 0 - 5000>

    For example, to set the TCP profile syn-rto-base option to 3001 for a profile named tcp_one, type the following command:

    modify ltm profile tcp tcp_one syn-rto-base 3001

  3. Save the modified configuration by typing the following command:

    save sys config
