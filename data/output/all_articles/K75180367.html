Description

Using source/destination mask of 0.0.0.0/0 should only be done with a wildcard IP address of 0.0.0.0 . Trying to use source/destination mask of 0.0.0.0 with a none 0.0.0.0 IP address , will result in unexpected / wildcard matching 

Example :

root@(localhost)(cfg-sync Standalone)(/Common)(tmos)# list ltm traffic-class case1 all-properties
ltm traffic-class case1 {
    app-service none
    classification case1
    description none
    destination-address 198.51.100.22
    destination-mask none ===================== > Same as 0.0.0.0 
    destination-port http
    partition Common
    protocol any
    source-address none
    source-mask none
    source-port any
}


In this example we try to match based on specific destination address of 198.51.100.22 , but without configuring the mask for the match . 
As a result, the default mask of 0.0.0.0 will be applied 

So sending traffic from 203.0.113.11 to 10.10.70.130 will show a MATCH to the traffic class, though the destination IP is not matching.
As explained that is due to the fact that the mask of none (e.g 0.0.0.0) effectively creates a match of 0.0.0.0/0.0.0.0 for the destination IP 

If we log it with an iRule that is what we will see:

info tmm[16592]: Rule /Common/_WAN_SLB_120_rule <CLIENT_ACCEPTED>: #### 0. lb class is case1
info tmm[16592]: Rule /Common/_WAN_SLB_120_rule <CLIENT_ACCEPTED>: #### 3. Forwaridng-120 203.0.113.11:48214 -> 10.10.70.130:80


The correct way to have a match to the destination address of 198.51.100.22 would be the following : 

root@(localhost)(cfg-sync Standalone)(/Common)(tmos)# list ltm traffic-class case1 all-properties
ltm traffic-class case1 {
    app-service none
    classification case1
    description none
    destination-address 198.51.100.22
    destination-mask 255.255.255.255
    destination-port http
    partition Common
    protocol any
    source-address none
    source-mask none
    source-port any
}


So trying to send same traffic from 203.0.113.11 to 10.10.70.130 will not produce a match:

info tmm[16592]: Rule /Common/_WAN_SLB_120_rule <CLIENT_ACCEPTED>: #### 0. lb class is             =============> no match 
info tmm[16592]: Rule /Common/_WAN_SLB_120_rule <CLIENT_ACCEPTED>: #### 3. Forwaridng-120 203.0.113.11:50335 -> 10.10.70.130:80


    Environment

    • LTM Traffic-Class
    • LTM iRule
    • The Source/Destination IP address configured in Traffic class is other than wildcard / 0.0.0.0
    • The source/Destination IP address Mask configured in traffic-class is none ( not configured ) or set to 0.0.0.0 

    Cause

    The Traffic class would match as a wildcard Source/Destination, although the actual Source/Destination IP address are not equal to 0.0.0.0.
    As a result of this issue, you may encounter:  Unexpected or Wildcard matches for a traffic-class 

    Recommended Actions

    Please use of Source/Destination Mask of 0.0.0.0 only in conjunction with 0.0.0.0 IP address.
