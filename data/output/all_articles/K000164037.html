Description

Bug ID 2567293 explains the denial log rotation logs. The workaround mentioned in the BugID does not survive a reboot.

This article provides a workaround that stays even after a reboot.

Environment

  • BIG-IP LTM 17.1.3, 17.5.1, 21.1.0 
  • Falcon Sensor Installed
  • Upgrade from version 17.5.1.8 to version 17.5.1.10.
  • In /var/log/messages there may be messages such as:
    • Oct 27 14:01:14 BIG-IP-DEVICE-NAME notice logrotate[28643]: ALERT exited abnormally with [1]

Cause

This is related to Bug ID 2567293.

Answer/Recommended Actions

The following workaround should stay even after a reboot.

From BIG-IP bash,

1. Check current status

# ls -Zd /shared/.tp_edr_mon_logs 

 drwx------. root root system_u:object_r:default_t:s0   /shared/.tp_edr_mon_logs

 

# ls -Z /shared/.tp_edr_mon_logs/tp_edr_mon.log 

 -rw-------. root root system_u:object_r:default_t:s0   /shared/.tp_edr_mon_logs/tp_edr_mon.log

 

2. SELinux rules

    2a. Add these from CLI:

# semanage fcontext -a -t var_log_t '/shared/\.tp_edr_mon_logs(/.*)?'

   2b. In case option 2.a fails - use the following:

# semanage fcontext -m -t var_log_t '/shared/\.tp_edr_mon_logs(/.*)?'

 

3. Relabel the directory

# restorecon -R /shared/.tp_edr_mon_logs

4. Check the label and status.

# stat -c '%C' "/shared/.tp_edr_mon_logs/tp_edr_mon.log" 2>/dev/null | cut -d: -f3

var_log_t

 

# ls -Zd /shared/.tp_edr_mon_logs

drwx------. root root system_u:object_r:var_log_t:s0   /shared/.tp_edr_mon_logs

 

# ls -Z /shared/.tp_edr_mon_logs/tp_edr_mon.log

-rw-------. root root system_u:object_r:var_log_t:s0   /shared/.tp_edr_mon_logs/tp_edr_mon.log

Additional Information

These changes will survive a reboot and have no impact on the system.

Important note: These will not survive a software upgrade and may need to be performed again after the software upgrade is completed
