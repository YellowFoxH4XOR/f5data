Issue

Beginning in 10.0.0, the BIG-IP WebAccelerator system proxies objects larger than the value of the maxResponseDataSize setting with an S-code of 10413, and the expected content is sent to the client.

Note: The 10413 S-code indicates that the transaction bypassed BIG-IP WebAccelerator processing. Exceeding the value configured for maxResponseDataSize is one reason that the transaction may be bypassed, but it is not the only reason.

In 9.4.x, the BIG-IP WebAccelerator manages server responses up to the maxResponseDataSize setting configured in the /config/wa/pvsystem.conf file. The default maxResponseDataSize setting is 67,108,864 bytes (64 megabytes). When the BIG-IP WebAccelerator receives an HTTP response from a server that is larger than the value of the maxResponseDataSize setting, the connection is terminated and the client will receive an HTTP 500 Internal Server Error message that appears similar to the following example:

The size of the response received by the server exceeds the permitted size.

Note: For more information about S codes, refer to the Viewing X-PvInfo response headers section of the Policy Management Guide for the BIG-IP WebAccelerator System.
