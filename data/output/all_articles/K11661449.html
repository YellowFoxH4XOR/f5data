Topic

This article contains considerations and recommendations for how to prepare for and perform a BIG-IP DNS software upgrade.

For more information related to a specific BIG-IP version, refer to the release notes for that version.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Important: This article discusses topics specific to BIG-IP DNS. For details about upgrading or updating BIG-IP software, refer to K84205182: BIG-IP upgrade guide | Chapter 1: Guide introduction and contents, and any version-specific guidelines detailed in the release notes for that version.

Description

When preparing to upgrade a BIG-IP DNS device, F5 recommends that you perform all of the following procedures to prepare the system for maintenance:

  1. Confirm DNSSEC keys in FIPS are synchronized (FIPS systems only)
  2. Disable synchronization and update the sync group name
  3. Stop the big3d and gtmd services
  4. Change the IP addresses for the GSLB server objects for BIG-IP DNS devices
  5. Verify the status of iQuery connections
  6. Reactivate the device license
  7. Put the BIG-IP device into Forced Offline mode
  8. Restart the BIG-IP DNS device and boot to the upgraded volume
  9. Change the IP addresses for the GSLB server objects for BIG-IP DNS devices back to the original addresses
  10. Verify the DNS configuration load
  11. Release the BIG-IP device from Forced Offline mode
  12. Update the big3d process on all BIG-IP devices
  13. Re-enable BIG-IP DNS synchronization for the devices of the synchronization group
  14. Repeat procedures 2-14 for the rest of the BIG-IP DNS devices in the synchronization group

1. Confirm DNSSEC keys in FIPS are synchronized (FIPS systems only)

Impact of procedure: Performing the following procedure should not have an impact on your system.

  1. Log in to the command line of each BIG-IP DNS device that is configured as a member of the configuration synchronization group.
  2. Use the following command to show the private keys in FIPS:

    tmsh show /sys crypto fips

    Output appears similar to the following example:

       === private keys (3)
       ID                                MOD.LEN(bits)
        35703E376A51733D1677D3C664C4A59   2048
        3D2F47506478264A2B783E40545D364   2048
        3F5E435169505C3E33286B252C70415   2048

  3. Compare the command output from each BIG-IP DNS device to confirm that the private keys are identical.
  4. If the private keys in the command output are different, synchronize the keys according to the procedure found in the FIPS manual for your BIG-IP version. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

2. Disable synchronization and update the sync group name

When upgrading BIG-IP DNS members in a DNS synchronization group, it is important to disable synchronization and change the DNS sync group name in order to reduce the possibility of an invalid configuration being synchronized to other members of the sync group during the upgrade process. However, if the BIG-IP DNS device is the only device in the sync group, you can safely ignore the recommendations regarding disabling and re-enabling synchronization.

Note: F5 recommends reviewing the BIG-IP DNS GSLB server settings for virtual server discovery. If Virtual Server Discovery is Enabled, you should change this setting to Enabled (No Delete) before starting the upgrade procedures. Doing so allows the BIG-IP DNS to retain the configured BIG-IP LTM virtual servers in the event of a BIG-IP LTM configuration load issue after you upgrade. You can set Virtual Server Discovery back to Enabled after you complete the post-upgrade configuration verification.

Disable DNS synchronization and change DNS sync group name on BIG-IP DNS device to be upgraded next

Impact of procedure: Performing the following procedure stops the BIG-IP DNS system from receiving any configuration updates from peer BIG-IP DNS devices.

  1. Log in to the Configuration Utility of BIG-IP DNS device to be upgraded next.
  2. Go to DNS > Settings > GSLB > General.
  3. Clear the Synchronize check box.
  4. Clear the Synchronize DNS Zone Files check box.
  5. Select Update.
  6. Note the current Group Name for later and change it so that it differs from the current value.

    For example, if the group name is default, change it to default_upgrade.

  7. Select Update.

Change DNS sync group name on the other BIG-IP DNS devices running older version

In order to avoid unexpected config sync when re-enabling sync after the upgrade, change the DNS sync group name of pre-upgrade devices to a temporary value.

Impact of procedure: Performing the following procedure briefly stops the BIG-IP DNS synchronization while the group name differs between devices in sync group.

  1. Log in to the Configuration Utility of one of the sync group members.
  2. Go to DNS > Settings > GSLB > General.
  3. Change Group Name to a temporary value.
    For example, if the group name is default, change it to default_tmp.
  4. Select Update.
  5. Repeat this procedure for each BIG-IP DNS sync group member.
    Note: If two or more devices in the sync group are on the same BIG-IP version, they may receive a configuration sync and not need the configuration update.

3. Stop the big3d and gtmd services

To disable global traffic functionality, including metrics collection and monitoring functions of the BIG-IP DNS system, perform the following procedure:

Impact of procedure: The following procedure disables global traffic and iQuery functionality on the BIG-IP DNS.

  1. Log in to the command line of BIG-IP DNS device to be upgraded next.
  2. Stop the big3d and gtmd services by entering the following command:

    tmsh stop /sys service big3d gtmd

  3. Verify the services are stopped by entering the following command:

    tmsh show /sys service big3d gtmd

    The output should appear similar to the following example:

    big3d        down 10 seconds, normally up
    gtmd         down 10 seconds, normally up

4. Change the IP addresses for the GSLB server objects for BIG-IP DNS devices

As a precautionary measure, F5 recommends changing the configured IP addresses assigned to the GSLB server objects that correspond to the remote BIG-IP DNS sync group members. This procedure is intended to isolate the BIG-IP DNS sync group member to be upgraded next and prevent the sync group from inadvertently communicating metrics information during the maintenance procedure. The IP addresses you assign to the GSLB server objects for BIG-IP DNS sync group members are temporary and should be unused and non-routable addresses on your network.

The following images show how IP addresses for GSLB server objects for BIG-IP DNS devices are changed.

Figure: IP address changes during the upgrade of the 1st BIG-IP DNS device

Figure: IP address changes during the upgrade of the 2nd BIG-IP DNS device

Impact of procedure: Performing this procedure temporarily isolates the BIG-IP DNS sync group member to be upgraded next and prevents the system from synchronizing metrics information during maintenance.

  1. Log in to the Configuration Utility of BIG-IP DNS device to be upgraded next.
  2. Go to DNS > GSLB > Servers : Server List.
  3. Select one of the GSLB server objects that corresponds to a remote BIG-IP DNS sync group member (not the self device).
    1. Select Devices tab.
    2. Select the name of the device.
    3. For Address List, select the IP address assigned to the device.
      Note: Take note of the assigned IP address as you will re-assign the original IP address to the GSLB server after the maintenance is complete.
    4. Select Edit.
    5. Enter an unused and non-routable IP address. For example, 192.0.1.2.
    6. Select Add.
    7. Select Update.
  4. Repeat the previous steps 2 and 3 for all GSLB server objects that corresponds to a remote BIG-IP DNS sync group member (not the self device).
  5. Save configuration change on the device with gtmd/big3d down by entering the following command because the save is not automatically triggered:

    tmsh save sys config gtm-only

  6. Log in to the Configuration Utility of one of the BIG-IP DNS sync group members that is NOT to be upgrade next.
  7. Go to DNS > GSLB > Servers : Server List.
  8. Select the GSLB server object that corresponds to the BIG-IP DNS device to be upgraded next. Perform the same operation as steps 3-a through 3-g.
  9. Repeat the previous steps 6 through 8 for all the rest of BIG-IP DNS devices.
    Note: If two or more devices in the sync group are on the same BIG-IP version, they may receive a configuration sync and not need the configuration update.

5. Verify the status of iQuery connections

Verify that there are no active iQuery connections between sync group members. To do so, perform the following steps:

  1. Log in to the command line of BIG-IP DNS device to be upgraded next.
  2. Enter the following command to verify iQuery status:

    tmsh show /gtm iquery

  3. Verify that there is no output on the device with gtmd down.

6. Reactivate the device license

Note: When you perform the software installation to upgrade the BIG-IP system, the installation process does not validate the service check date with the license check date of the version you're installing. If the service check date is missing or is earlier than the license check date, the system fails to load the configuration when you attempt to boot to the upgraded software slot. For more information, please refer to K7727: License activation may be required before a software upgrade for BIG-IP

Impact of procedure: The license reactivation process may reload the configuration and temporarily interrupt traffic processing by the BIG-IP DNS device.

  1. Log in to the Configuration Utility of BIG-IP DNS device to be upgraded next.
  2. Go to System > License.
  3. Select Reactivate.
  4. For Activation Method, select Automatic or Manual.
    Note: If your system does not have Internet access to the F5 license server, you must choose Manual.
  5. Select Next and follow the instructions.

7. Put the BIG-IP device into Forced Offline mode

When upgrading a BIG-IP DNS device, which shares the same DNS configurations with other BIG-IP DNS devices (although they are not in the same sync group at this step in the upgrade process), it is important to put the BIG-IP DNS device in a forced offline mode to have time to review upgraded config after booting from the new volume. However, if the BIG-IP DNS device does not share the same config with other devices, you can safely ignore the recommendations regarding putting into and releasing from forced offline mode.

Impact of procedure: The BIG-IP system terminates existing connections to local traffic objects and does not allow new connections.

  1. Log in to the Configuration Utility of BIG-IP DNS device to be upgraded next.
  2. Go to Device Management > Devices.
  3. Select the local device.

    For example, BIGIP-1.internal.net (Self).

  4. Select Force Offline.

8. Install a new software version and boot to the upgraded volume

Install a preferred version of BIG-IP OS (TMOS) on a new volume. For detailed instruction on software upgrade, please refer to K84554955: Overview of BIG-IP system software upgrades

After installing the upgrade to the selected volume, restart the BIG-IP DNS device and boot to the upgraded volume.

  1. Log in to the Configuration Utility as an administrator.
  2. Go to System > Software Management > Boot Locations.
  3. Select the boot location containing the newly upgraded software volume.
  4. To restart the system and boot into the specified boot location, select Activate.
    Note: Loading system software into a new volume includes copying the existing active configuration. If there have been no configuration changes since you installed the new software volume, you do not need to set the Install Configuration option to Yes when activating the new volume.
  5. To close the confirmation message, select OK.

9. Change the IP addresses for the GSLB server objects for BIG-IP DNS devices back to the original addresses

After booting the system to the upgraded volume, change the temporary IP addresses assigned to the GSLB server objects back to the original addresses.

The following images show how IP addresses for GSLB server objects for BIG-IP DNS devices are changed back.

Figure: IP address change back during the upgrade of the 1st BIG-IP DNS device

Figure: IP address change back during the upgrade of the 2nd BIG-IP DNS device

  1. Log in to the Configuration Utility of BIG-IP DNS device that was just upgraded.
  2. Go to DNS > GSLB > Servers : Server List.
  3. Select one of the GSLB server objects that corresponds to a remote BIG-IP DNS sync group member (not the self device).
    1. Select Devices tab.
    2. Select the name of the device.
    3. For Address List, select the IP address assigned to the device.
    4. Select Edit.
    5. Enter the original IP address that was assigned to this device.
    6. Select Add.
    7. Select Update.
  4. Repeat the previous steps 2 and 3 for all GSLB server objects that corresponds to a remote BIG-IP DNS sync group member (not the self device).
  5. Log in to the Configuration Utility of one of the BIG-IP DNS sync group members that are different from the recently upgraded device.
  6. Go to DNS > GSLB > Servers : Server List.
  7. Select the GSLB server object that corresponds to the BIG-IP DNS device that was just upgraded. Perform the same operation as steps 3-a through 3-g.
  8. Repeat the previous steps 5 through 7 for all the rest of BIG-IP DNS devices in sync group.
    Note: If two or more devices in the sync group are on the same BIG-IP version, they may receive a configuration sync and not need the configuration update.

10. Verify the DNS configuration load

  1. To verify that the expected objects appear in the shared and non-shared portions of the configuration, go to DNS > GSLB.
  2. Confirm that the expected objects are present.
  3. Go to Network > VLANs.
  4. Confirm that the expected objects are present.
  5. Optionally, you can use the QKView utility to create a qkview file and review it in the iHealth Diagnostics section for currently known issues.
  6. After you have completed all upgrades, create a new set of UCS files to retain backups of the new BIG-IP version configuration.

11. Release the BIG-IP device from Forced Offline mode

Impact of procedure: The BIG-IP system becomes available to process traffic.

  1. Log in to the Configuration Utility of BIG-IP DNS device that was just upgraded.
  2. Go to Device Management > Devices.
  3. Select the local device.

    For example, BIGIP-1.internal.net (Self).

  4. Select Release Offline.

12. Update the big3d process on all BIG-IP devices

To facilitate proper iQuery communication in your environment, you should be aware of the following big3d version management information:

  • F5 recommends that all devices communicating over iQuery run the same big3d version.

    When installing big3d on devices in the iQuery mesh, install the big3d agent from the BIG-IP DNS (formerly BIG-IP GTM) or Enterprise Management system that is running the latest software version to the other devices in the iQuery mesh. For example, if the devices in the iQuery mesh are running different BIG-IP software versions, install the big3d agent from the device running the newest BIG-IP version to the other devices. This ensures that a device in the mesh does not run a big3d version that is older than its installed software version.

  • BIG-IP DNS synchronization group communication

    Sync group members should run the same big3d version.

  • BIG-IP DNS communication

    Monitored BIG-IP systems must run the same or newer big3d version as the BIG-IP DNS/BIG-IP GTM devices that are monitoring them.

To ensure that all the BIG-IP device of the DNS synchronization group are running the latest big3d version, you can use the big3d_install command-line utility.

Note: For more information on updating big3d refer to K13312: Overview of the BIG-IP DNS big3d_install, bigip_add, and gtm_add utilities.

  1. Log in to the BIG-IP device command line as an administrator.
  2. Enter the following command syntax to run the big3d_install utility:

    big3d_install <BIG-IP_IP_address>

    Note: Replace <BIG-IP_IP_address> with the destination IP address of the BIG-IP device. If you do not specify an IP address, the script attempts to install the current version of the big3d process on all the BIG-IP devices listed in the bigip_gtm.conf file.

13. Re-enable BIG-IP DNS synchronization for the devices of the synchronization group

After confirming the upgraded BIG-IP DNS comes up healthy, the next step is to re-enable BIG-IP DNS synchronization.

The following images show how to re-enable DNS synchronization after software upgrade.

Figure: DNS sync group name change during the upgrade of the 1st BIG-IP DNS device

Figure: Running gtm_add script during the upgrade of the 2nd BIG-IP DNS device

There are two separate procedures to perform depending on which device is currently upgraded. Choose one of these options:

Option 1) When upgrading the 1st BIG-IP DNS device

This procedure enables DNS synchronization and changes sync group name on BIG-IP DNS device that was just upgraded.

Impact of procedure: Performing the following procedure enables the BIG-IP DNS system to synchronize configurations between BIG-IP DNS systems on the same version.

  1. Log in to the Configuration Utility of BIG-IP DNS device that was just upgraded.
  2. Go to DNS > Settings > GSLB > General.
  3. Select the Synchronize check box.
  4. Select the Synchronize DNS Zone Files check box.
  5. Select Update.
  6. Change Group Name to the original value.
  7. Select Update.

Option 2) When upgrading the rest of BIG-IP DNS devices

This procedure re-adds the upgraded BIG-IP DNS system to the same synchronization group using gtm_add script. Perform the following procedures only when there are two or more devices in the DNS sync group on the new version.

Note: This procedure does not apply to the first device upgraded because the BIG-IP DNS system on which you run the gtm_add script must be running the same version as the remote BIG-IP DNS system's sync group. If not, the gtm_add script may fail to properly add the BIG-IP DNS system.

Impact of procedure: The following procedure replaces the configuration from the BIG-IP DNS system on which it is run, with the configuration of the remote BIG-IP DNS system in the specified synchronization group.

  1. Log in to the command line of the BIG-IP DNS system that was just upgraded.
  2. To re-add the BIG-IP DNS system to the DNS synchronization group, type the following command:

    gtm_add <IP address of a member of the target DNS synchronization group>

    Note: Specify the IP address of the already-upgraded BIG-IP DNS device.

    Note: The synchronization group name on BIG-IP DNS will be updated with the existing synchronization group name.

14. Repeat procedures 2-13 for the rest of the BIG-IP DNS devices in the synchronization group

Repeat procedures 2-13 on subsequent BIG-IPs until all are at the new version and synchronized with each other.
