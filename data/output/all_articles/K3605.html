Topic

The BIG-IP system processes User Datagram Protocol (UDP) packets that are sent from the same IP address and port as part of a connection. The BIG-IP system sends those packets to the same node as long as the connection lives. In some instances, it is preferable to load balance UDP packets individually. Beginning in BIG-IP 9.0.3, the Datagram LB feature allows the BIG-IP system to accept these packets individually.

Configuring the BIG-IP system to load balance UDP packets individually

To use the Datagram LB feature, and enable the setting in an existing UDP profile used by the virtual server, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol tab, click UDP.
  4. Click the UDP profile that is associated with the desired Virtual Server.
  5. Select the Datagram LB check box.
  6. Click Update.

Similarly, if you are creating a new UDP profile to load balance UDP packets individually, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol tab, click UDP.
  4. Click Create to display the UDP profile creation page.
  5. Enter a name for the UDP profile in the Name setting.
  6. Select the custom check box to the right of the Datagram LB setting and then select the Datagram LB check box.
  7. Configure the rest of the settings as needed.
  8. Click Finished to save the new UDP profile.
  9. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  10. Select the desired UDP Virtual Server.
  11. Select the UDP profile you have created in steps 4 through 8 from the Protocol Profile (Client) and/or Protocol Profile (Server) settings as needed.
  12. Click Finished to save the change to the UDP Virtual Server configuration.

Important: With UDP Datagram LB set to Enabled, if you also set the Timeout to Immediate, UDP response traffic is forwarded to the client using the origin server's source IP address and port. As a result, response traffic may not appear to have originated from the virtual server to which the request was sent, and traffic disruption may occur when a client and/or routing expects the UDP source IP address to be the address other than the origin server. You can avoid this issue by setting the timeout to a value other than Immediate whenever possible.

For the profile changes to take effect, you must clear all UDP connection entries from the connection table. To do so, you can either allow the connection to timeout, or you can perform the following procedures.

  • Removing a specific connection entry
  • Removing all connection entries

Removing a specific connection entry  

BIG-IP 11.x through 16.x

  1. Log in to the BIG-IP command line.
  2. To remove a specific connection entry, use the following command syntax:

    tmsh delete sys connection cs-client-addr <client IP address> protocol <protocol>

    For example:

    tmsh delete sys connection cs-client-addr 1.2.3.4 protocol udp

BIG-IP 10.x  

  1. Log in to the BIG-IP command line.
  2. To remove a specific connection entry, use the following command syntax:

    bigpipe conn client <client IP address> protocol <protocol> delete

    For example:

    bigpipe conn client 1.2.3.4 protocol udp delete

Removing all connection entries  

BIG-IP 11.x through 16.x

  1. Log in to the BIG-IP command line.
  2. To remove all connection entries, type the following command:

    tmsh delete sys connection

BIG-IP 10.x  

  1. Log in to the BIG-IP command line.
  2. To remove all entries, type the following command:

    Important: This command clears all connection entries, TCP and UDP, from the connection table. Use caution when applying this command.

    bigpipe conn all delete
