Description

The db value tm.maxrejectrate is set 250: 

tmsh list sys db tm.maxrejectrate
sys db tm.maxrejectrate {
    value "250"
}

As K13151: Configuring the rate at which the BIG-IP system issues TCP RSTs or ICMP unreachable packets says, when ICMP exceeds the tm.maxrejectrate threshold, the BIG-IP system stops sending ICMP ping response packets in response to ping floods, and logs a message to the /var/log/ltm file that appears similar to the following example:

011e0001:4: Limiting icmp ping response from 299 to 250 packets/sec for traffic-group /Common/traffic-group-local-only

Howerver log is:

011e0001:4: Limiting icmp ping response from 501 to 500 packets/sec for traffic-group /Common/traffic-group-local-only
 

Environment

  • BIG-IP
  • tm.maxrejectrate
  • no ICMP response

Cause

  • K15003: Data and control plane tasks use separate logical cores when the BIG-IP system CPU uses Intel Hyper-Threading Technology


Recommended Actions

Hyper-Threading is enabled by default. To check the settings run the below commands:
 
 
tmsh list sys db scheduler.splitplanes.ltm

sys db scheduler.splitplanes.ltm {
    value "true"
}
NOTE:  "true" is default value and Hyper-Threading is enabled. F5 Networks recommend to change this value.
 

Additional Information

For additional error message examples and information about the BIG-IP system packet response rate limit, refer to:
