Description

Different monitors for random pool members show status DOWN, when the servers are confirmed to be UP. You can see logs like this example:

01070638:5: Pool /Common/https_pool member /Common/192.168.1.1:443 monitor status down.
01070638:5: Pool /Common/http_pool member /Common/192.168.1.2:80 monitor status down.

The ARP entries for the affected pool member IPs show as incomplete when displaying the ARP table with: tmsh show net arp

# show net arp | grep incomplete
192.168.1.1 192.168.1.1 incomplete /Common/VLAN-INTERNAL-3510 0 unknown
192.168.1.2 192.168.1.2 incomplete /Common/VLAN-INTERNAL-3510 0 unknown
192.168.1.3 192.168.1.3 incomplete /Common/VLAN-INTERNAL-3510 0 unknown

Issue gets temporarily resolved for some pool members, when forcing an ARP request to be sent out to the pool members by making any updates or configuration changes to it, or with tmsh delete net arp <ip address of impacted member>.

Environment

  • VIPRION with vCMP
  • ARP protocol

Cause

Unknown at the time of publication.

Recommended Actions

Delete the ARP entry for the affected pool member with tmsh delete net arp <ip address of impacted member>, for example:

tmsh delete net arp 192.168.1.1

If the issue keeps happening after deleting the ARP entry, for the specific pool member, keep troubleshooting to check if the ARP requests are going out of the BIG-IP and reaching the pool member, and if the ARP responses are reaching back the BIG-IP.

The ARP response coming from the pool member, might not be reaching the BIG-IP at all, and staying at an intermediate down stream device, for example a switch between BIG-IP and servers.

Take packet captures on vCMP Host level, on the physical interface related to the Vlan affected. This will help determine if the issue is F5 related or on a down stream network intermediate device. For the vCMP Host pcap, you can use a similar syntax to this example:

# tcpdump -s0 -nni 1/1.2 -c 100000 -w /var/tmp/host.pcap 'vlan 3510 and arp'

Note: You need to be connected to the specified blade to take this capture. In the above example is slot 1, interface 1.2.
