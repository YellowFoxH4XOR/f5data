Known Issue

Using the Configuration utility, you cannot unlock a local user account.

This issue occurs when all of the following conditions are met:

  • The access policy is configured to authenticate user access by using a local user database.
  • The access policy locked a user account.

    For example, when a user exceeds the configured limit for login attempts, the access policy locks the user's account.

Impact

You are unable to unlock the user account by using the Configuration utility.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Configuration utility's local user database displays a user account as locked out, and the Unlock User button is unavailable.
  • The Unlock User button is available for user accounts in the local user database that are not locked out.

Workaround

To work around this issue, you can unlock the user account from the command line. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line with administrative access.
  2. Type the following command, replacing <username> with the user name of the locked account, and replacing </partition/local_db_instance_name> with the full path and name of the local user database instance:

    ldbutil --update --uname=<username> --instance=</partition/local_db_instance_name> --locked_out=0 --lockout_start=0 --login_failures=0

    For example, you would type the following command for the user name Fred that is authenticated by the access policy using the local user database instance LabUsers in the administrative partition Common:

    ldbutil --update --uname=Fred --instance=/Common/LabUsers --locked_out=0 --lockout_start=0 --login_failures=0
