Topic

You should consider using this procedure under the following conditions:

  • The BIG-IP APM authentication, authorization, and accounting (AAA) profile references Microsoft Active Directory (AD) servers.
  • You plan to configure your BIG-IP APM system to proxy the Microsoft AD user password reset request.
  • You plan to configureyour BIG-IP APM system to query AD user primary group and nested groups.
  • You do not need your BIG-IP APM system to use a Microsoft AD account with full administrator privileges.

Description

For security reasons, F5 recommends that you not provide a Microsoft AD user with full administrator privileges to achieve user authentication and authorization (including fine-grained password policies) for BIG-IP APM AAA queries. The following procedures outline the necessary steps to configure Microsoft AD to create a new user with sufficient privileges for authentication, authorization, group membership queries, and the ability to reset user passwords for AD users who can integrate in to fine-grain password policy environments. The final procedure shows you how to configure the BIG-IP APM AD AAA server so you can use it within an Access Policy.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • AD is running on Microsoft Windows Server 2008, Windows Server 2008 R2, Windows Server 2012, or Windows Server 2012 R2.
  • The Windows AD has the Microsoft Management Console (MMC) snap-in Users and Computers.
  • You have administrative access to the Microsoft AD server.
  • You have a general understanding of Microsoft AD administration and configuration.
  • Windows AD is configured with default Permission Property Sets.
  • You have administrative access to the BIG-IP APM system.
  • You understand how to configure the BIG-IP APM AAA server profiles in conjunction with Microsoft AD.

Procedures

  • Adding an administrative Microsoft AD user who can use the BIG-IP APM system to authenticate users and reset passwords
  • Propagating the new AD user for large AD infrastructures
  • Configuring the BIG-IP APM Microsoft AD AAA server

Adding an administrative Microsoft AD user who can use the BIG-IP APM system to authenticate users and reset passwords

The following procedure outlines the steps to create a new Microsoft AD user with the minimum privileges required to authenticate users and reset passwords of other AD users.

The new AD user is assigned the following AD privileges:

  • The user is added to Domain Users group.
  • The user is granted the privilege to reset passwords of other AD users.
  • The user is added to the Group Policy Creator Owners group (this is required for fine-grained password policy checks).
  • The user is allowed to Read all properties (this is required for fine-grained password policy checks).

Impact of procedure: In very large Microsoft AD infrastructures, it could take up to an hour to propagate the following changes throughout the Microsoft AD environment.

  1. Log in to the Windows AD server.
  2. Open the Active Directory Users & Computers utility.
  3. In the Domain box, select the domain of the new BIG-IP APM authentication user.
  4. Right-click the domain name, and select New > Organizational Unit.
  5. In the Name box, type a name for the new Organizational Unit.
  6. Leave the check box for Protect container for accidental deletion as the selected default setting.
  7. Click OK.
  8. Proceed to the Configuring a new user procedure.

Configuring a new user

  1. Select the new Organizational unit.
  2. Right click, and then select New > User.
  3. In the First name box, type the user's first name, and in the Last name box, type the user's last name.
  4. In the User logon Name box, type the user's log-on name.
  5. Click Next.
  6. In the Password box, type the password for the user, and repeat the password in the Password Confirm box.
  7. Clear the User must change password at next logon check box.
  8. Select the check boxes for User cannot change password and Password never expires.
  9. Click Next.
  10. Click Finished.
  11. Proceed to the Delegating control to the new user procedure.

Delegating control to the new user

  1. Select the new Organizational unit.
  2. Right click, and from the pop-up menu, select Delegate Control.
  3. Click Next.
  4. Click Add.
  5. In the Enter the object names to select box, type the user name.
  6. Click Check names.

    The User name should show as user (user@domain).

  7. Click OK.
  8. Click Next.
  9. Select the Reset user passwords and force password change at next logon check box.
  10. Select the Read all user information check box.
  11. Click Next.
  12. Click Finished.
  13. Proceed to the Adding the new user to a group procedure.

Adding the new user to a group

  1. Select the new Organizational unit.
  2. In the right window, select the newly created user.
  3. Right-click the user, and then select Add to Group.
  4. In the Enter the object names to select field, enter Group Policy Creator Owners.
  5. Click Check Names.
  6. If the object name is correct, click OK.
  7. In the left window, select the domain.
  8. Right-click, and click Properties.
  9. Select the Security tab.
  10. Click Advanced.
  11. Select the Permissions tab.
  12. Click Add.
  13. In the Enter object name to select box, enter the user name.
  14. Click Check Names.
  15. If the object name is correct, click OK. The permissions selection pop-up box appears.
  16. Set the permissions Apply to pull down menu to This object and all descendant objects.
  17. In the Read all properties box, select Allow.
  18. Click OK.
  19. Click Apply.
  20. Click OK (The pop-up window closes.)
  21. Click OK.

Propagating the new AD user for large AD infrastructures.

In very large AD infrastructures, where multiple AD servers are synchronized, these changes could take up to 60 minutes to propagate. To help expedite propagation, run the following command from the CLI of the Domain controller on which you made the changes.

Impact of procedure: All AD servers within the synchronization configuration will be updated. Do not use the repadmin command if you are unfamiliar with the command syntax and impact.

  1. Log in to the Windows AD server.
  2. Open the command line utility.
  3. Type the following command:

    repadmin /SyncAll /AdeP

    Note: The repadmin /SyncAll command may take several minutes to complete, depending on the size of the AD infrastructure.

    Important: Please review the proper syntax of the repadmin command prior to use in your environment. For more information, refer to the Repadmin page. This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

  4. To exit the command line utility, type the following command:

    exit

Configuring the BIG-IP APM Microsoft AD AAA server

Complete the following steps to configure an AD AAA server to use with a BIG-IP APM access policy, where you specify the domain controllers and credentials to use when authenticating AD users.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > AAA Servers > Active Directory.
  3. Click Create.
  4. In the Name box, type a unique name for the authentication server.
  5. In the Domain Name box, type the name of the Windows domain.
  6. For the Server Connection setting, select one of the following options:
    • To configure multiple AAA servers for high availability, select Use Pool.
    • To configure a single AAA server for standalone functionality, select Direct.
  7. If you selected the Direct option, type the name of the domain controller in the Domain Controller box.

    If you selected the Use Pool option:

    a. Type a name in the Domain Controller Pool Name box.

    b. Type the IP address and hostname of each of the Domain Controllers for the pool.

    c. Click Add.

    d. If you want health monitoring of the AAA servers pool, select a health monitor preference.

  8. In the Admin Name box, type the name of the administrative user that you created earlier; this is case sensitive.
  9. In the Admin Password box, type the password associated with newly-created administrative user for the domain.
  10. In the Verify Admin Password box, re-enter the user password.
  11. In the Group Cache Lifetime box, enter the number of days that you want the group cache to live. (The default is 30 days.)
  12. For the Password Security Object Cache Lifetime box, enter the number of days that you want the password security object cache to live. (The default is 30 days.)
  13. From the Kerberos Preauthentication Encryption Type list, select an encryption type if Kerberos will be used (the default is None).
  14. (Optional) For the Timeout box, enter how many seconds you want the AAA server to stay up before timing out. (This setting is optional.)
  15. Click Finished.

You can now access the new AAA AD server configuration within an access policy configuration.
