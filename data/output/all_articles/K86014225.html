Description
The nsyncd is a java process that is responsible for LiveUpdate resources and and synchronization over CMI and Chassis conduits. This process was introduced in 14.1.0 where Live Updates feature were introduced to manually install or configure installation of updates to BIG-IP ASM / Advanced WAF components.

It is possible to observe high memory usage for nsyncd process that gradually keeps growing over time. 

Environment

  • BIG-IP ASM / Advanced WAF provisioned on 14.1.0 or higher release.

Cause
There is a known issue that results in a memory leak with the nsyncd process. F5 Product Engineering is tracking this as a known issue at ID1067589.

Recommended Actions

Open a support case with F5 Technical Support to request an Engineering Hotfix that contains a fix for ID1067589, until a fix is implemented in a GA release code. 

With the fix in place, a new parameter maxMemory is added to the nsyncd configuration file /usr/share/nsyncd/config/config.properties that dictates the memory limit for nsyncd process:

# 450 MB
maxMemory=450000000

The default limit is 450MB and, once that limit is exceeded, the device will automatically trigger a nsyncd restart. 

Modifying this limit requires mounting /usr file system into read-write mode described in K20330103: Mounting the /usr file system in read-write mode, before you modify the value by specifying it in bytes and then reverting /usr to read-only mode.
