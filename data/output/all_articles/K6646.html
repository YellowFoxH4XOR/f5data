Known Issue

This is the result of a known issue. The Network Access Only Webtop feature (also referred to as Alternate Webtop) allows an administrator to automatically launch a Network Access favorite without displaying a Webtop at the time a user logs in. Currently, FirePass only supports this feature for browsers running on Microsoft Windows platforms.

When a user attempts to log in from a Linux or Mac OSX system, and the user belongs to a FirePass master group that is configured to use the Network Access Only Webtop feature, the user will see a web page with the following error after supplying their login credentials:

Sorry. This functionality is not supported with your browser.

The user's Webtop will not be displayed, and the user will be unable to log in to the FirePass controller.

F5 Product Development tracked this issue as CR67522 and it was fixed in FirePass version 6.0.1. For information about upgrading, refer to the FirePass release notes.

Workaround

To work around this issue, you can configure FirePass so that users receive the Network Access Only Webtop when using Windows systems, and receive the full Webtop with only a Network Access Favorite (which users launch manually) when using non-Windows systems.

To implement this workaround, create and assign two resource groups with the same Network Access Favorite to the users' master group. One resource group will be configured for Windows clients, with the Autolaunch feature of the Network Access Favorite enabled. The other resource group will be configured for non-Windows clients, without the Autolaunch feature enabled.

Additionally, each resource group will be assigned a protected configuration. One protected configuration will detect Windows client systems and allow access only to the resource group for Windows clients, which will Autolaunch the Network Access Favorite. The other Protected Configuration will detect non-Windows clients and allow access only to the resource group for non-Windows clients, which will present the full Webtop with only the Network Access Favorite.

To assign two resource groups with protected configurations to the users' master group, perform the following procedure:

  1. Select the Network Access Only Webtop check box in the master group's User Experience.
  2. Create two resource groups with the same Network Access resource configuration, but one without Autolaunch based on endpoint protection.
  3. Assign both resource groups to the master group that uses the Network Access Only Webtop.
  4. Create two protected configurations: one protected configuration to detect Windows clients, and one protected configuration to detect non-Windows client systems.

    The protected configurations use the following Custom Checks.

    For Windows platforms:

    session.os.platform == "WinXP" OR session.os.platform == "Win2k" OR session.os.platform == "WinNT" OR session.os.platform == "Win95" OR session.os.platform == "Win98" OR session.os.platform == "Win98SE" OR session.os.platform == "WinME"

    For non-Windows platforms:

    session.os.platform == "MacOSX" OR session.os.platform == "Linux"

  5. Assign the Windows protected configuration to the resource group with the Autolaunch enabled, and assign the non-Windows Protected Configuration to the resource group without Autolaunch enabled.
  6. Create and enable an empty Pre-logon Sequence, using the Empty template, to activate client information collection needed by the protected configuration.

    Note: Non-Windows users will see a Security Warning icon on the Webtop, indicating that the Windows Protected Configuration check failed. This warning can be ignored.

If you configure the workaround and then find that users in the master group cannot log in, regardless of the type of client operating system they are using, your FirePass controller may require cumulative hotfix HF-600-4 or a later version of the cumulative hotfix for FirePass version 6.0.0. You can download the latest version of the cumulative hotfix from the F5 Downloads page.
