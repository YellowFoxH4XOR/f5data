Known Issue

After upgrading the BIG-IP system from version 9.0.x or version 9.1 to versions 9.1.1 or 9.2.2, traffic will not pass through the BIG-IP system, and the non-management interfaces are non-responsive and marked uninitialized, as shown in the following output:

[root@bigip:Standby] config # b interface showinterface  speed  pkts  pkts  pkts  pkts  bits  bits errors trunk     Mb/s    in   out  drop   coll   in    outMgmt UP   100 FD     0     2     0     0     0   1120     01.1  UN   1000 FD    0     0     0     0     0      0     0[root@bigip:Standby] config # b interface show allINTERFACE mgmt  00:01:D7:1F:B8:4F  ENABLED  UP  MTU 1500|    media auto (100baseTX full)   Aggregation detached|    flow control tx rx (none)|    (pkts,bits,errs) in = (0, 0, 0), out = (2, 1120, 0)|    (drop,mcast) in = (0, 0), out = (0, 0)    coll = 0INTERFACE 1.1  00:01:D7:1F:B8:42  ENABLED  UNINITIALIZED  MTU 1500|    media auto (none)   Aggregation detached|    STP instance 0   forward|    flow control tx rx (none)|    (pkts,bits,errs) in = (0, 0, 0), out = (0, 0, 0)|    (drop,mcast) in = (0, 0), out = (0, 0)    coll = 0

Additionally, messages similar to the following example are logged in the /var/log/ltm file:

Jan 1 12:00:01 sccp bcm56xxd[440]: 00010013:6: Waiting for Proxy HEARTBEAT start...Jan 1 12:00:01 sccp bcm56xxd[440]: 00010013:3: Proxy HEARTBEAT 60 second wait limit timeout. bcm56xxd.cpp(837)

This is most likely the result of a known issue, which was introduced in version 9.1.1 of the 9.1 branch, and version 9.2.2 of the 9.2 branch, as a result of a behavior change.

This issue can occur if the /etc/syslog-ng/syslog-ng.conf file was customized prior to the upgrade to version 9.1.1. If the /etc/syslog-ng/syslog-ng.conf file was customized, the upgrade process may not have updated the /etc/syslog-ng/syslog-ng.conf file with the following entries:

# capture output from bcm56xxd and put it in /var/log/bcm56xxxdsource s_bcm56xxd {pipe("/var/run/bcm56xxd.pipe");};destination d_bcm56xxd {file("/var/log/bcm56xxd" create_dirs(yes));};log {source(s_bcm56xxd);destination(d_bcm56xxd);};

In BIG-IP 9.1.1 and 9.2.2, the bcm56xxd daemon writes to a named pipe; therefore, these entries are required in order for the syslog-ng daemon to listen to the named pipe. If the syslog-ng daemon is not listening to the named pipe, the bcm56xxd daemon will not start.

Note: This behavior was also introduced in some version 9.1 hotfixes.

F5 Product Development tracked this issue as CR57698, CR58627, and CR58625, and it was fixed in BIG-IP 9.1.2 for the 9.1 software branch and in BIG-IP 9.2.3 for the 9.2 software branch. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, or Link Controller Release Notes.

Note: For additional information about these CRs, refer to K5879: BIG-IP does not pass traffic and non-management interfaces are non-responsive if syslog-ng fails to start.

Workaround

Warning: This procedure requires that you reboot the BIG-IP system. This procedure must be performed from the command line, through the console (accessed through the serial terminal), or using SSH connected through the management interface.

To work around this issue, perform the following steps:

  1. Log in to the command line.
  2. Change directories to the /etc/syslog-ng directory, by typing the following command:

    cd /etc/syslog-ng

  3. Using a text editor, such as vi or pico, edit the syslog-ng.conf file.
  4. Add the following lines at the end of the file: 
    # capture output from bcm56xxd and put it in /var/log/bcm56xxxdsource s_bcm56xxd {pipe("/var/run/bcm56xxd.pipe");};destination d_bcm56xxd {file("/var/log/bcm56xxd" create_dirs(yes));};log {source(s_bcm56xxd);destination(d_bcm56xxd);};
  5. Save the file and exit the editor.
  6. Reboot the BIG-IP system by typing the following command:

    reboot
