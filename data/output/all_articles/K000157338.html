Description

Attempts to create a new boot location for a software upgrade fail.

 

In the liveinstall.log, logs similar to the following can be seen:

error: status 256 returned by command: F5_INSTALL_SESSION_TYPE=install tmsh -f save sys ucs /var/tmp/UqV4hkT9up.ucs 

info: >++++ result: 

info: Unexpected Error: 01020036:3: The requested database variable (security.commoncriteria) was not found. 

info: >---- 

Terminal error: See /var/log/liveinstall.log

*** Live install end at 2025/10/29 14:30:49: failed (return code 255) ***

 

Environment

  • BIG-IP
  • software upgrade

 

Cause

The UCS save operation does not complete due to the missing security.commoncriteria DB variable in the BigDB.dat file. This, in turn, is causing the creation of the boot location to fail.

 

In general, missing DB variables are symptoms of the BigDB.dat being corrupted

 

Recommended Actions

To fix the corrupted BigDB.dat file, follow the workaround mentioned in https://cdn.f5.com/product/bugtracker/ID701341.html

 

Once the BigDB.dat is fixed, the UCS save operation / boot location creation should now complete successfully.

 

Additional Information

Missing or corrupted database variables can impact both GUI functionality and upgrade processes. Repairing or restoring BigDB.dat resolves these symptoms and restores normal operation.
