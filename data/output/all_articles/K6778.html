K6778: A single SNMP request to multiple subagents crashes the snmpd agent

Known Issue

This is the result of a known issue. If the BIG-IP or 3-DNS receives a single SNMP request that queries objects of multiple subagents, such as bigsnmpd and 3dnsd, the snmpd agent will access memory that was previously freed. As a result, the snmpd agent will crash.

Note: This issue most often occurs on a 3-DNS system, or a system licensed for a BIG-IP and 3-DNS combination.

To recover from this issue after the snmpd agent crashes, you must restart the snmpd agent by typing the following command from the command line:

bigstart restart snmpd

F5 Networks Product Development is tracking this issue as CR52902 and it is scheduled to be fixed in a future version. To monitor the status of this CR, refer to the BIG-IP, BIG-IP Link Controller, or the 3-DNS Release Notes.

Workaround

You can avoid the issue by ensuring that a single SNMP request does not query objects of multiple subagents.

Alternatively, you can configure the SNMP management station to perform an snmpwalk to query the BIG-IP or 3DNS. The snmpwalk is a series of GetNextRequest SNMP queries that request a single object per request.

Note: Querying for a single object for each request will increase the amount of network traffic required to query the BIG-IP or 3-DNS sytems.

If network traffic restrictions or other requirements dictate the need to query multiple objects in a single SNMP request, all of the objects need to use the same subagent.

For example, if you need to separately request the objects under the 3-DNS and BIG-IP subagents in order to query the following objects:

1.3.6.1.4.1.3375.1.2.1.1.7.2.0 (3DNS uptime since the last DNS reload)

1.3.6.1.4.1.3375.1.2.1.1.7.6.0 (3DNS requests received)

1.3.6.1.4.1.3375.1.1.1.2.1.0 (BIG-IP uptime since the last system reboot)

1.3.6.1.4.1.3375.1.1.1.2.11.0 (BIG-IP maximum connections serviced at one time)

1.3.6.1.4.1.3375.1.1.1.2.12.0 (BIG-IP total number of connections serviced)

You would configure your management station to make the following two requests:

  • 1.3.6.1.4.1.3375.1.2.1.1.7.2.0 (3DNS uptime since the last DNS reload)

1.3.6.1.4.1.3375.1.2.1.1.7.6.0 (3DNS requests received)
  • 1.3.6.1.4.1.3375.1.1.1.2.1.0 (BIG-IP uptime since the last system reboot)

1.3.6.1.4.1.3375.1.1.1.2.11.0 (BIG-IP maximum connections serviced at one time)

1.3.6.1.4.1.3375.1.1.1.2.12.0 (BIG-IP total number of connections serviced)

You will avoid crashing the snmpd agent by requesting objects from a single subagent within a single SNMP query.
