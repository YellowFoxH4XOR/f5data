Description

SNMP queries for the "DATA CPU" metric on BIG-IP LTM devices return a value of 0. Other metrics, such as "control" plane CPU usage, are reported correctly. The issue is observed when using SNMP MIBS/OID related to data-plane CPU utilization, such as F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurror

.1.3.6.1.4.1.3375.2.1.12.2.2.1.3.4.100.97.116.97

Environment

Platform: BIG-IP appliance and BIG-IP VE that not support Hyper-Threading technology

Configuration: SNMP monitoring enabled for CPU metrics

Cause

The BIG-IP platform that does not support Hyper-Threading (HT) technology, which is required to provide separate data-plane statistics via SNMP queries. As a result, any OID querying DATA CPU usage will consistently return a value of 0.

Recommended Actions

  1. Alternative Monitoring OID: Use the control-plane OID to monitor CPU utilization instead of relying on non-functional data-plane metrics.
F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurr."control"

 

  • Example MIBS command: 
snmpwalk -v2c -c public localhost F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurr
  • Expected MIBS output:
F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurr."data" = Gauge32: 0
F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurr."control" = Gauge32: [valid value]
F5-BIGIP-SYSTEM-MIBsysPlaneStatCpuRatioCurr."analysis" = Gauge32: 0
  • Example OID command: 
snmpwalk -v2c -c public localhost .1.3.6.1.4.1.3375.2.1.12.2.2.1.3.7.99.111.110.116.114.111.108
  • Expected MIBS output:
F5-BIGIP-SYSTEM-MIB::sysPlaneStatCpuRatioCurr."control" = Gauge32: [valid value]
  1. Verify Platform Capabilities: Confirm whether the device supports HT technology by running the following command:
tmsh show sys tmm-info
  • If HT is not supported, there will be no separate data-plane information available.
