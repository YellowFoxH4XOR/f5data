K13458146: Unable to Clone or Export ASM Policy

Type
Support Solution
Published
2021-05-25
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.X.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.X, 16.0.1, 16.0.0, 16.1.0
Source
https://my.f5.com/manage/s/article/K13458146

Description

Unable to Clone or Export ASM Policy.

Error message while exporting:

Can't call method "build_xml" on an undefined value at /usr/local/share/perl5/F5/NegativeSignatures/Set.pm line 519.

Error message while cloning:

Failed to insert to PLC.PL_POLICY_NEGSIG_SETS (DBD::mysql::db do failed: Cannot add or update a child row: a foreign key constraint fails (`PLC`.`PL_POLICY_NEGSIG_SETS`, CONSTRAINT `PL_POLICY_NEGSIG_SETS_ibfk_2` FOREIGN KEY (`set_id`) REFERENCES `NEGSIG_SETS` (`set_id`) ON DELETE CASCADE) at /usr/local/share/perl5/F5/BatchInsert.pm line 230.

Environment

  • Upgraded from 15.0.1.1 to 16.0.1.1
  • ASM MySQL database in healthy condition

Cause

Signature set in PLC.NEGSIG_SETS that is attached to policy is missing.

This has made the tables PLC.PL_POLICY_NEGSIG_SETS and PLC.NEGSIG_SETS inconsistent.

Note: The root cause of the inconsistency at the time of the article's publication is unknown.

Recommended Actions

The following provides the procedure to determine the signature set that is missing which caused the inconsistency and to delete it.

  1. Run the following command to list the policies and their associated signature set:

    mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` PLC -e "select *  from PLC.PL_POLICY_NEGSIG_SETS";

  2. Note the signatures sets allocated for the affected policy.
  3. Run the following command to list all the signature sets on the BIG-IP:

    mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` DCC -e "select * from PLC.NEGSIG_SETS";

    a- compare the output with the signature sets from step (1)

    b- identify the signature set that is missing from the signature sets table PLC.NEGSIG_SETS.

    For the purpose of the article, the missing signature set ID is "299999976" as an example.

  4. Run the following command to extract the rest_uuid of the affected policy from the PL_POLICIES table:

    mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` PLC -e "select * from PL_POLICIES";

    You can identify the affected policy from the name field of the command output; you may want to note the ID of the affected policy from the id field for the next step.

  5. Run the following command to extract the rest_uuid of the affected policy from the PLC.PL_POLICY_NEGSIG_SETS table:

    mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` PLC -e "select *  from PLC.PL_POLICY_NEGSIG_SETS";

    You can identify the affected policy from the policy_id field by using the ID of the affected policy noted in the previous step.

  6. To delete the missing signature set, replace the <rest_uuid1> and <rest_uuid2> in the following command with the results from the previous steps:

    restcurl -s -u admin:admin -X DELETE https://localhost/mgmt/tm/asm/policies/<rest_uuid1>/signature-sets/<rest_uuid2>

    Note that the <rest_uuid1> and <rest_uuid2> should be replaced by the results from step (4) and step (5) respectively. For the purpose of the article, the following command has been provided as an example:

    restcurl -s -u admin:admin -X DELETE https://localhost/mgmt/tm/asm/policies/9-NWeDLHPYCEY0Oi7Tceqg/signature-sets/a91sC4eNjYOoweIoex-V6g

  7. Run the following command to confirm the signature set has been deleted from PLC.PL_POLICY_NEGSIG_SETS table:

    mysql -uasm -p`perl -MF5::Cfg -e 'print F5::Cfg::get_mysql_password()'` PLC -e "select *  from PLC.PL_POLICY_NEGSIG_SETS";

Additional Information

PLC.NEGSIG_SETS stores signature sets attributes (id, name, learn/alarm/block flags, whether it is user defined, etc.) of all signature sets.

PLC.PL_POLICY_NEGSIG_SETS stores information which signature sets are assigned to each policy and which flags learn/alarm/block are enabled for each signature set (on policy level).

It's not allowed that there is a signature set assigned to policy in the PLC.PL_POLICY_NEGSIG_SETS table which does not exist in the PLC.NEGSIG_SETS table.
