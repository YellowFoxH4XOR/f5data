Known Issue

The configuration may fail to load after you run either the fipsutil init or fipsutil reset command and reboot the system.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has an internal FIPS hardware security module (HSM).
  • Your configuration includes one or more Client SSL profiles that reference FIPS-protected Secure Sockets Layer (SSL) keys.
  • You run either the fipsutil -f init or fipsutil reset command.
  • You reboot the BIG-IP system.

Impact

The BIG-IP system configuration fails to load.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system configuration fails to load.
  • The BIG-IP system command line status is INOPERATIVE and the Configuration utility device status is Offline.
  • The BIG-IP system logs the following series of log messages in the /var/log/ltm file:

    err mcpd[5678]: 010713e4:3: FIPS subsystem reported error while attempting file object operation: FipsMgr::get_handle_from_modulus error unable to obtain handle. Modulus(d2:fb:44...ee:78:a4), FIPS:ERR_HSM_NOT_INITIALIZED.
    err mcpd[5678]: 010713e4:3: FIPS subsystem reported error while attempting file object operation: fips_insert_masked_object error on import, ERR_HSM_NOT_INITIALIZED.
    err mcpd[5678]: 01070712:3: Caught configuration exception (0), unable to import FIPS 140 key (/Common/example) from key file.) - sys/validation/FileObject.cpp, line 3524.
    err tmsh[6789]: 01420006:3: Loading configuration process failed.

Workaround

To work around this issue, remove FIPS-protected keys from Client SSL profiles and then delete the FIPS keys before you attempt to run either the fipsutil -f init or fipsutil reset command. To do so, perform the following procedures:

Impact of workaround: Performing this workaround will cause SSL traffic protected by FIPS keys to fail. You should perform these procedures only during a scheduled maintenance period.

Deleting the FIPS keys

  1. Ensure you have removed FIPS-protected SSL keys from all Client SSL profiles.
  2. Log in to the Traffic Management Shell (tmsh):

    tmsh

  3. Delete each FIPS-protected SSL key using the following command syntax:

    delete sys crypto key <fips_key_name>

    For example, to delete the FIPS key named fips_example1.key, type the following command:

    delete sys crypto key fips_example1.key

  4. Repeat step 3 until all FIPS-protected SSL keys are deleted.
  5. To save the system configuration, type the following command:

    tmsh save sys config partitions all

Recovering from the configuration load failure

  1. Using a text editor, delete all FIPS keys referenced in the /config/bigip.conf file.
  2. Delete all FIPS keys in the /config/ssl/ssl.cavfips directory by typing the following command:

    rm -rf /config/ssl/ssl.cavfips/*

  3. Delete all FIPS keys referenced in the /config/filestore/files_d/partition-name/certificate_key_d/ directory.
  4. To load the system configuration, type the following command:

    tmsh load sys config partitions all

  5. To save the system configuration, type the following command:

    tmsh save sys config partitions all
