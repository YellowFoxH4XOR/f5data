K000156991: Virtual Servers with the same address as a Self IP do not receive traffic from host processes

Type
Support Solution
Published
2025-10-11
Updated
2025-10-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000156991

Description

You have created a Virtual Server (VIP) on the same address as a Self IP.

External traffic is processed correctly.

Traffic generated from processes in the host cannot connect to this VIP.

Modules other than LTM will not work.

Attempting to use a VIP to proxy host traffic (for example the OCSP responder) does not work.

A test with "curl" using the cli will always result in a failed connection.

Environment

The Virtual Server shares its address with a Self IP.

This configuration is more likely in a Virtual Edition with only MGMT and 1.1 interfaces where the Self IP network size is very small and you wish to economize on IP Addresses.

You may see this in a cloud deployment, however it is not a cloud issue.

Cause

The Self IP is created in the dataplane (tmm) and exported to the host.

if you run

ip address show

on the host you will see the Self IP.

This allows the host to originate traffic from the Self IP. Monitoring traffic is the main example.

However the the VIP's are not in the host, they are in tmm. The host traffic cannot access them, because it sees the exported Self IP

 

Recommended Actions

Redefine the VIP's so they are not using the Self IP address. Another address in the IP subnet will work.

Additional Information

None.
