K36612944: F5 SSL Orchestrator in a high availability configuration may fail to properly sync iAppLX

Known Issue

Updated

Applies to

Source

Known Issue

F5 SSL Orchestrator in a high availability (HA) configuration may fail to properly sync iAppLX.

This issue occurs when all of the following conditions are met:

  • You have two or more new Herculon platforms set up in an HA configuration.
  • You have configured SSL Orchestrator on one of the devices.
  • You have configured the other device or devices by copying or restoring configuration files.

Note: This issue should not occur when you instead use two BIG-IP systems licensed with the SSL Forward Proxy.

This issue occurs because the iAppLX process on the originating device attempts to create the f5-iapplx-ssl-orchestrator application on peer devices. Since this application already exists on the peer devices, the iAppLX process on the originating device fails in its attempts to create the application and waits indefinitely.

Impact

Updates made to the SSL Orchestrator on one device in an HA configuration do not replicate to the peer devices. Additionally, if you attempt to deploy or remove a deployment of the SSL Orchestrator on one device, the restnoded subsystem on that device may appear to hang and the SSL Orchestrator eventually times out.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Software version updates on one device do not replicate to peer devices. For example, if you update one device to SSL Orchestrator 13.0.0-2.3, the peer devices do not update to that version.
  • You observe error messages similar to the following example in the /var/log/restnoded.0.log file:

    [WARNING][81][<DATE/TIME>][RemoteStateCopier] Failed to post to http://localhost:8100/shared/iapp/global-installed-packages: java.lang.IllegalArgumentException: Duplicate item. Key already exists: appName : f5-iappslx-ssl-orchestrator
    [SEVERE][82][<DATE/TIME>][RemoteStateCopier] Failed to synchronize from <Peer IP address> to this host: /mgmt/shared/iapp/global-installed-packages

  • If you attempt to deploy or remove a deployment of the SSL Orchestrator, the system fails with a timeout error. If you then attempt to uninstall the iAppLX template, the uninstall fails and the system displays an error in the Configuration utility similar to the following example:

    Error retrieving template list: undefined.

Workaround

There is no workaround for this issue.

If you have already set up the devices in an HA configuration, you must first remove the affected devices from the device group, as well as the affected device trust member(s). Then, before you attempt to again set up the SSL Orchestrator devices in a device group, you must remove the SSL Orchestrator package from all but one of the devices. To remove the SSL Orchestrator package, you must uninstall it using the iApps > Package Management LX page in the Configuration utility. To do so, perform the following procedure:

Impact of procedure: During this process, you uninstall SSL Orchestrator on all but one of the devices in the HA group. The devices on which you uninstall SSL Orchestrator lose their configuration. Make sure to retain the deployed configuration on one SSL Orchestrator so that you can use it as the master to sync to the remaining devices.

  1. Log in to the Configuration utility.
  2. Navigate to iApps > Package Management LX.

    Note: If the Configuration utility on the SSL Orchestrator does not display the iApps menu, you need enable it. To do so, log in to the command line, use the touch /var/config/rest/iapps/enable command to install the menu, and then log out of the Configuration utility and log in again. You should then see the iApps menu in the Configuration utility.

  3. Select the f5-iappslx-ssl-orchestrator package and click Uninstall.
  4. Click Confirm to uninstall the SSL Orchestrator package.

    Note: If errors occur that prohibit you from uninstalling the f5-iappslx-ssl-orchestrator package from an SSL Orchestrator device and you do not have a backup configuration to restore the device to the state prior to the SSL Orchestrator configuration, you can reset the device to the factory default configuration. To do so, log in to the command line and use the clear-rest-storage -d command. Resetting a device to the factory default configuration removes all configurations from the device and requires you to set up the basic configuration using the initial setup wizard.

After you remove the SSL Orchestrator package from all but one of the devices, you can add the SSL Orchestrator devices back into the device group and then sync the SSL Orchestrator configuration to the newly added devices. For information on setting up device groups and HA configurations, refer to the BIG-IP Device Service Clustering: Administration manual.

Note: For information about how to locate F5 product manuals, refer to K12453464: Finding product documentation on AskF5.
