K000149097: Server-side connections fail intermittently when using shared object address list with persistence profiles

Description

You have a virtual server with source address persistence and are using traffic matching criteria to match more than one destination address. You observe intermittent failures establishing a server-side connection to the pool member when connecting to the virtual server.

Environment

  • BIG-IP LTM
  • Source address persistence
  • Traffic Matching Criteria

Cause

This is due to  ID912293 which describes an incompatibility between traffic matching criteria and certain persistence profiles.

Recommended Actions

Use a persistence profile other than the following:

  • Source Address (but not hash-algorithm carp)
  • Destination Address (but not hash-algorithm carp)
  • Universal + Cookie (only cookie hash)
  • Host
  • SSL session
  • SIP
  • Hash (but not hash-algorithm carp)

For example, updating the source address persistence profile to the hash algorithm carp will work around this issue.

Alternatively, you can update the persistence profile to enable matching across virtual servers.

Note: Enabling match-across-virtuals might affect the behaviour of other virtual servers in the configuration that utilise persistence. You can read K5837 for more information about the possible effects of the match across option.
