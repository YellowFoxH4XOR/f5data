K000162121: Remote ASM Security Event Logs truncated to 5 KB despite 64 KB Maximum Entry Length setting

Type
Support Solution
Published
2026-07-07

Applies to

  • BIG-IP ASM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000162121

Description

BIG-IP ASM may truncate remote security event logs sent to Splunk at approximately 5 KB, even when the logging profile is configured for a maximum entry length of 64 KB. This results in incomplete log data and impacts visibility for security monitoring. The truncation occurs regardless of HTTP method or request type, and changing the maximum entry length setting does not permanently resolve the issue.

Environment

  • BIG-IP ASM module running any of these versions:
    • v17.5.0 - v17.5.1.6
    • v17.1.0 - v17.1.3.2
  • Logging profiles configured with Remote Storage, Storage Format set to Splunk, and Maximum Entry Length set to 64k.
  • Security event logs sent to remote Splunk servers

Cause

A known issue tracked as Bug ID2337921 causes remote log messages to be truncated at 5 KB, regardless of the configured maximum entry length. This is distinct from, but related to, Bug ID911661.

Answer/Recommended Actions

To resolve this issue, please follow any one of the following recommendations:

  • Upgrade to BIG-IP version 17.5.1.7+ or 17.1.3.3+ releases in respective branches, as they include a fix for Bug ID2337921.
  • If upgrading is not possible, request an Engineering Hotfix for your current version that includes the fix, subject to F5 Product Engineering approval.
  • Other workarounds, such as toggling the maximum entry length, that was suggested for ID911661 are not permanent solutions.
