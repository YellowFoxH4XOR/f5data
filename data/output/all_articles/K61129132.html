Topic

You should consider using this procedure under the following conditions:

  • You would like to delete an event log snapshot on the BIG-IQ logging node.
  • You would like to import a set of event log files that was previously stored on a remote folder.

Description

The BIG-IQ logging node system enables you to easily view Web Application Security events. The BIG-IQ logging node stores the events from one or more BIG-IP system, and the BIG-IQ system can then retrieve and manage those events.

The Managing Event Logs for Web Application Security chapter of the BIG-IQ Centralized Management: Security manual is missing the procedure on how to delete a snapshot, so this article covers the topic.

This article also provides information on how to proceed when you have a set of event log files that was previously stored on a remote folder and you want to import the set as a snapshot in the BIG-IQ logging node system, and how you can accomplish this by adding a snapshot entry to the REST database. As the article indicates, you can then refer to the BIG-IQ Centralized Management: Security guide to restore the desired event log snapshot to the target system.

For more information on managing configuration snapshots, refer to the Managing Event Logs for BIG-IQ Web Application Security chapter of the BIG-IQ Centralized Management: Security guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have advance shell access to the BIG-IQ system as an administrator.
  • You have an existing logging node network configured in your environment.

    For more information about the logging node networks, refer to the BIG-IQ Centralized Management: Security guide.

    Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5

Procedures

  • Delete an event log snapshot
  • Import event log files to a snapshot entry

Delete an event log snapshot

The following procedure deletes both the event log snapshot reference in the REST database and the snapshot files in the shared resources. 

Impact of procedure: The target snapshot ID used in this procedure causes the system to delete all the snapshot files and snapshot references in the REST database, and you cannot reverse or recover the files or references. 

  1. Log in to the BIG-IQ system's advance shell as administrator.
  2. Delete both the snapshot reference entry in the REST database and the snapshot files in the shared resource by sending a DELETE request to the system using the appropriate command syntax, depending on your BIG-IQ version:
    • For BIG-IQ 5.1.0 and later, if the BIG-IQ system has HTTP basic authentication disabled, you have to request the authentication token before you can send the following DELETE request command syntax:

      curl -X DELETE -sk -H "X-F5-Auth-Token: <ACCESS_TOKEN>" https://<BIQ_IP>/mgmt/cm/shared/esmgmt/es-snapshots/<SNAPSHOT_ID>

      In the previous syntax, note the following: 

       - <ACCESS_TOKEN> refers to the BIG-IQ authentication token string value.
       - <BIQ_IP> refers to the BIG-IQ system that is peered to manage the BIG-IQ logging nodes.
       - <SNAPSHOT_NAME> refers to the name of the snapshot.

      Note: For more information about using the BIG-IQ authentication token, refer to K04452074: Overview of using the BIG-IQ system authentication token.

    • For BIG-IQ 5.0.0 or 5.1.0 with HTTP basic authentication enabled, use the following DELETE request command syntax:

      curl -X DELETE -sku <Admin_User>:<Password> https://<BIQ_IP>/mgmt/cm/shared/esmgmt/es-snapshots/<SNAPSHOT_ID>

      For example, sending the DELETE request to a BIG-IQ 5.0.0 system, the DELETE request appears similar to the following example:

      curl -X POST -sku admin:admin https://10.100.100.100/mgmt/cm/shared/esmgmt/es-snapshots/5ccd6848-b318-4b15-86ac-0647658b28a6

Import the event log files to a snapshot entry

If you have a set of event log files (for example, those retrieved from a remote folder) that you would like to import as a snapshot in the BIG-IQ system, you have to first add the desired event log snapshot reference into the REST database. You can then restore the desired event log snapshot into the target system. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Transfer the set of event log files from the remote folder to the target BIG-IQ system.

    For more information about transferring the files, refer to K175: Transferring files to or from an F5 system.

  2. Log in to the BIG-IQ system's advance shell as administrator.
  3. To add a snapshot reference to the REST database, send a POST request to the system using the appropriate command syntax, depending on your BIG-IQ version:
    • For BIG-IQ 5.1.0 and later, if the BIG-IQ system has HTTP basic authentication disabled, you have to request the authentication token before you can send the POST request, using the following command syntax:

      curl -X POST -sk -H "X-F5-Auth-Token: <ACCESS_TOKEN>" https://<BIQ_IP>/mgmt/cm/shared/esmgmt/es-snapshots/ -d'{ "snapshotName" : "<SNAPSHOT_NAME>" }'

      In the previous syntax, note the following: 

       - <ACCESS_TOKEN> refers to the BIG-IQ authentication token string value.
       - <BIQ_IP> refers to the BIG-IQ system that is peered to manage the BIG-IQ logging nodes.
       - <SNAPSHOT_NAME> refers to the name of the snapshot.

      Note: For more information about using the BIG-IQ authentication token, refer to K04452074: Overview of using the BIG-IQ system authentication token.

    • For BIG-IQ 5.0.0 or 5.1.0 with the HTTP basic authentication enabled, use the following command syntax:

      curl -X POST -sku <Admin_User>:<Password> https://<BIQ_IP>/mgmt/cm/shared/esmgmt/es-snapshots/ -d'{ "snapshotName" : "<SNAPSHOT_NAME>" }'

      In the previous syntax, note the following:

       - <ADMIN_USERID> refers to the system's default admin user ID  (that is, the primary admin user).
       - <ADMIN_PASSWORD> refers to the user's password. 
       - <BIQ_IP> refers to the BIG-IQ system that is peered to manage the BIG-IQ logging nodes.
       - <SNAPSHOT_NAME> refers to the name of the snapshot.

      For example, you would type the following command to send the POST request to a BIG-IQ 5.0.0 system:

      curl -X POST -sku admin:admin https://10.100.100.100/mgmt/cm/shared/esmgmt/es-snapshots/ -d'{ "snapshotName" : "my_snapshot_20161020" }'

  4. The system is now ready to restore the snapshot. Refer to the Restoring event log database snapshots section in the Managing Event Logs for BIG-IQ Web Application Security chapter of the BIG-IQ Centralized Management: Security guide.
