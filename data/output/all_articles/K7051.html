Topic

You can configure the BIG-IP system to use an alternate server if pool members are unavailable.

Note: For information about BIG-IP version 9.x and 10.x refer to solution K7065: Configuring the BIG-IP system to use an alternate server if pool members are unavailable.

Note: The BIG-IP version 4.x fallback host behavior can be emulated in version 9.x using an iRule. For information, refer to K6510: Change in Behavior: The Fallback Host is now used when a connection to a node fails.

In BIG-IP version 4.x the following methods are available:

  • Fallback Host
  • Priority load balancing

Fallback Host

Beginning with BIG-IP version 4.0, you can configure a fallback host. With this option, if the BIG-IP system cannot load balance traffic to a pool because all nodes are unavailable, the BIG-IP system will send an HTTP redirect to the client with an alternate resource that you have specified in the Fallback Host text box of the Pool Properties screen.

For the BIG-IP system to honor the priority levels, or the Fallback Host field, you must populate the Minimum Active Members field. This field defines how many servers in the priority three group must be available in order for the priority three group to be used. If the number of available servers falls below the number specified in the Minimum Active Members field, the next lowest priority (or fallback host) will be used.

Note: For information about configuring fallback hosts and HTTP redirects, refer to the BIG-IP Reference Guide.

Priority load balancing

You can use the Priority load balancing mode to configure the BIG-IP system to direct traffic to a specific system. This mode is ideal to use with standby servers.

The Priority mode allows you to create groups of nodes and assign a priority level to each group. The BIG-IP system equally distributes connections to all nodes in the highest priority group. If all nodes in the highest priority group are unavailable the BIG-IP system will pass connections to nodes in the next lower priority group.

The BIG-IP system continuously monitors the higher priority nodes. Each time a higher priority node becomes available, the BIG-IP system passes the next connection to the node with a higher priority.

Note: Priority load balancing does not work when minimum active members is set to 0 (zero). For more information, refer to K244: Known Issue: Priority load balancing does not work when minimum active members is set to 0.
