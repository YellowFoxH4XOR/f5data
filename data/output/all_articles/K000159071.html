K000159071: Manually created snatpool in AS3 Tenant refered in declaration cause deployment failure

Type
Support Solution
Published
2026-01-13
Updated
2026-01-13
Applies to
  • F5 Automation and Orchestration
  • BIG-IP
  • F5 Application Services 3 Extension
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000159071

Description

When deploying an AS3 declaration to a manually created partition with a pre-existing SNAT pool, the declaration failed with error "01070320:3: Snatpool /example_app/example-snat-pool is still referenced by a virtual server."

 

Environment

  • AS3
  • Manually created partition with route domain
  • SNAT pool manually configured in partition
  • AS3 per-app deployment

 

Cause

AS3's design principle is to manage partitions declaratively based solely on what is defined in the declaration. When AS3 processes a declaration for a partition, it removes all existing objects in that partition and recreates only those specified in the declaration. The manually created SNAT pool was being deleted during this process, causing the error when AS3 attempted to reference it. This is expected AS3 behavior - objects managed by AS3 must be declared within AS3, not created manually via tmsh or GUI.

 

Recommended Actions

  1. Create a "Shared" application within the tenant that declares the SNAT pool as a shared resource

Example implementation:

First, POST a declaration creating the shared SNAT pool in tenant example_app:

"example_app": {

"class": "Tenant",

"Shared": {

"class": "Application",

"template": "shared",

"CreateSnatPool": {

"class": "SNAT_Pool",

"snatAddresses": ["<addresses>"]

}

}

}

2. Reference the shared SNAT pool in per-app deployments using the "use" pointer syntax

"snat": {

"use": "/example_app/Shared/CreateSnatPool"

}

Do not manually configure objects via tmsh or GUI in partitions managed by AS3, as they will be removed during AS3 operations
