K16212: Managing the NSX connector without using BIG-IQ Cloud may cause a disparity issue for REST objects

Topic

Summary

You can manage the VMware NSX connector from the VMware NSX user interface or BIG-IQ Cloud. However, F5 recommends managing the VMware NSX connector using BIG-IQ Cloud.

Description

When you manage an NSX connector using the VMware NSX user interface, and not BIG-IQ Cloud, a REST storage disparity issue may occur.

For example, if you have deleted the service manager associated with an NSX connector from the VMware NSX user interface, you cannot create another VMware NSX connector from BIG-IQ Cloud unless you manually delete the related object instance from BIG-IQ Cloud REST storage.

Recommendations

When you want to manage the NSX connector, you should always use the BIG-IQ Cloud system interface.

For example, when you want to delete a provisioned resource from VMware NSX, you should delete the connector from BIG-IQ Cloud, rather than deleting the service manager associated with the connector from VMware NSX.

Manually deleting related object instances from BIG-IQ Cloud REST storage

If you have deleted the service manager from VMware NSX, you must remove the related object instance from BIG-IQ Cloud REST storage. To do so, perform the following procedure:

Impact of procedure: This procedure stops the main BIG-IQ system services; F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the BIG-IQ system advanced shell (bash) using Administrator credentials.
  2. Stop the restjavad service by typing the following command:

    tmsh stop sys service restjavad
  3. Remove the BIG-IQ system REST storage by typing the following command:

    rm -rf /var/config/rest
  4. Start the restjavad service by typing the following command:

    tmsh start sys service restjavad
