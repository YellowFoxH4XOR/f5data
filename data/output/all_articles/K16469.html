Issue

Old Behavior

In versions prior to BIG-IP ASM 11.5.0, for systems with Intel Hyper-Threading Technology (HT Technology) physical CPUs, each Traffic Management Microkernel (TMM) process shares a logical CPU core with non-TMM processes, including BIG-IP ASM processes.

In BIG-IP ASM 11.5.0 through 11.5.1 HF3, TMM processes and non-TMM processes use separate logical CPU cores on systems with HT Technology CPUs; the TMM processes use even-numbered logical CPU cores while non-TMM processes use odd-numbered logical CPU cores. For more information about this split plane behavior, refer to K15003: Data plane and control plane tasks use separate logical cores when the BIG-IP system CPU uses Hyper-Threading Technology.

For a list of BIG-IP platforms that include HT Technology, refer to K14358: Overview of Clustered Multiprocessing (11.3.0 and later).

New Behavior

Beginning in BIG-IP ASM 11.5.1 HF4, the following BIG-IP ASM control plane processes are pinned to the highest-numbered logical CPU core with their corresponding Linux nice values on systems with HT Technology physical CPUs:

BIG-IP ASM processLinux nice value
bd_agent-19
correlation-19
dcc-19
learning_manager10
logmysqld-19
monpd-19
mysqld, mysqld_safe-19
pabnagd-19

Note: The bd processes are unaffected by this new behavior, and continue to use the remaining logical CPU cores with the Linux nice value of 0 (zero).

The scheduler.splitplanes.asmopt database variable controls this behavior, which is set to true by default. This behavior improves the responsiveness of the BIG-IP ASM control plane processes without compromising the BIG-IP ASM data plane performance.

F5 Product Development tracked this change as ID 432080.

Impact

Responsiveness improves for the BIG-IP ASM control plane processes when systems are heavily utilized, without compromising the data plane performance. Users may observe heavy CPU utilization on the highest-numbered logical CPU core.

Recommended Actions

You should not revert to pre-11.5.1 HF4 behavior unless requested by F5 Support. However, if required, you can disable this new behavior and revert to pre-11.5.1-HF4 behavior by performing the following procedure:

Impact of procedure: This procedure may cause loss of performance and management response improvements, and requires a reboot of the system. Restarting services causes a brief traffic disruption.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the scheduler.splitplanes.asmopt database key to false, type the following command:

    modify sys db scheduler.splitplanes.asmopt value false

  3. To reboot the system, type the following command:

    reboot
