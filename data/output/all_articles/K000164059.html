K000164059: Large POST Uploads Fail Through a Distributed Cloud CDN Distribution

Published

Updated
2026-10-30
Applies to

Source

Description

Large file uploads using HTTP POST requests fail when sent through an F5 Distributed Cloud CDN Distribution. Uploads of approximately 50 MB or larger can fail with HTTP 413 (Content Too Large) at the CDN edge, before the request reaches the origin. The failure persists with WAF disabled. 

Environment

  • F5 Distributed Cloud CDN Distribution

Cause

  • CDN Distribution request payload limit: The CDN edge enforces a maximum client request payload of 50 MB. Uploads larger than this limit are rejected at the CDN edge, which can present as HTTP 413. CDN Distributions are designed to cache and accelerate cacheable content (static resources and downloads), not large POST uploads.

Answer/Recommended Actions

Migrate uploads from the CDN Distribution to an HTTP Load Balancer

  1. Create an HTTP Load Balancer for the application domain and route upload traffic (for example, the upload path) to the origin pool.
  2. Apply WAF, if required, on the HTTP Load Balancer rather than on the CDN Distribution.
  3. Keep the CDN Distribution only for cacheable content, such as static resources and downloads.
  4. If the CDN Distribution and the HTTP Load Balancer remain as separate objects, they cannot use the same domain configuration. Use separate hostnames as required.

Validation steps

  1. Upload a small file through the HTTP Load Balancer to confirm basic connectivity.
  2. Upload a representative file near the expected maximum size.
  3. Confirm in the origin server logs that the request reaches the origin.
  4. Confirm that static content still receives the expected CDN cache behavior, if the CDN Distribution is retained.
