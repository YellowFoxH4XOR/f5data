Description

When querying PTR or NS records, that belong to the shared address space documented in RFC6598, the response is returned from local BIG-IP GTM DNS server instead of the BIG-IP DNS pool that is specified in the configuration.

Example of such DNS query :

    QUESTIONS:
        10.77.69.100.in-addr.arpa, type = PTR, class = IN
    AUTHORITY RECORDS:
        69.100.in-addr.arpa
        ttl = 10800 (3 hours)
        primary name server = localhost  /// <--- symptom !!!!

Environment

  • DNS listener with associated pool and DNS profile
  • transparent cache

Cause

According to RFC (rfc6598), it appears the shared address space should be filtered, and this behavior is RFC compliant. DNS cache first verifies requested IP address, notes that it's not RFC compliant, and refuses to resolve the query.

F5 introduced the above behavior from the following versions and later:

v11.6.5.3
v12.1.6
v13.1.3.5
v14.1.2.7
v15.x
 

Recommended Actions

If your pool members are configured to resolve IP addresses from the shared address space, you may configure an iRule that will allow the potential client to bypass DNS cache for specific address range.
 
  1. Create an internal data-group that will include all the required IP address ranges.
Example taken from the bigip.conf configuration file :

ltm data-group internal /Common/shared_address {
    records {
       .64.100.in-addr.arpa { }
       .65.100.in-addr.arpa { }
       .66.100.in-addr.arpa { }
       .67.100.in-addr.arpa { }
       .68.100.in-addr.arpa { }
       .69.100.in-addr.arpa { }
    }
    type string
}
 
       2.  Create an iRule :

 

  • For PTR queries :

when DNS_REQUEST {
   if { ([DNS::question type] == "PTR") && ([class match [string tolower [DNS::question name]] contains shared_address]) } {
DNS::disable cache
pool DNS_pool
}


Where DNS_pool is name of your nameserver pool.

  • For NS queries :

when DNS_REQUEST {
   if { ([DNS::question type] == "NS") && ([class match [string tolower [DNS::question name]] contains shared_address]) } {
DNS::disable cache
pool DNS_pool
}

Where DNS_pool is name of your nameserver pool.

 

       3.  Assign newly created iRules to the DNS listener.
 

Additional Information

https://datatracker.ietf.org/doc/html/rfc6598

When running a single DNS infrastructure, Service Providers MUST NOT include Shared Address Space in zone files. When running a split DNS infrastructure, Service Providers MUST NOT include Shared Address Space in external-facing zone files. 

Reverse DNS queries for Shared Address Space addresses MUST NOT be forwarded to the global DNS infrastructure. DNS Providers SHOULD filter requests for Shared Address Space reverse DNS queries on recursive nameservers.
