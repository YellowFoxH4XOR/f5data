Description

When you run "sslofix" in repair mode (with '--force', or with a sync target '-D'/'-H'), the script prompts for BIG-IP admin credentials and then returns:

Please enter your BIG-IP Admin account credentials.
Enter Username: admin
Enter Password:
error: The credentials provided appear to be invalid

The prompt repeats, and the repair does not run. The same credentials are accepted by the BIG-IP.

Running the check manually returns a 500 error for the SSLO local endpoint:

[root@ABC-F5-001:Active:In Sync] config # restcurl -u root:<password> https://localhost/mgmt/shared/iapp/blocks
{
 "code": 500,
 "message": "java.security.cert.CertificateException: Could not find certificate in keystore",
 "restOperationId": 2,
 "kind": ":resterrorresponse"
}

**Note:replacing <password> with the root's password.

Environment

  • Product: F5 SSL Orchestrator (BIG-IP SSLO)
  • Access: Advanced Shell (root shell) enabled for the admin accounts used to run sslofix

Cause

Bug ID 2515245 describes a REST framework change. Outbound HTTPS calls now validate certificates by default ('VERIFY_OUT_OF_CLUSTER_SERVER_CERTIFICATES' changed from false to true). Localhost HTTPS calls fail because '/var/config/rest/javakeystore/sslcerts.keystore' is empty. The bug comments state: "this bug also breaks sslofix since it uses restcurl https:// when checking the credentials are valid."

Answer/Recommended Actions

A workaround for the sslofix script:. 

  1. Make a temporary copy of the script:
    cp /bin/sslofix /var/tmp/sslofix
  2. Edit the copy:
    nano /var/tmp/sslofix
  3. Locate the line that begins with SSLO_IAPP_REF="https://localhost/mgmt/shared/iapp"
  4. Change the value to:
    SSLO_IAPP_REF="/shared/iapp"
  5. Save the file and exit the editor.
  6. Run the modified copy with your SSLO trust group name and the peer device's management or config-sync IP address:
    /var/tmp/sslofix -D <SSLO trust group> -H <peer IP> --force

Additional Information

  • The SSLO_IAPP_REF workaround changes a default system script. Use the copy in /var/tmp and do not overwrite /bin/sslofix.
