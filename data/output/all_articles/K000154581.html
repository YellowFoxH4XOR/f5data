K000154581: F5OS may become inoperational due to lack of free space

Type
Support Solution
Published
2025-09-29
Updated
2026-02-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000154581

Description

On F5OS rSeries appliances hosting BIG-IP LTM tenants, the system may become unavailable if the /sysroot partition reaches 100% disk usage. This occurs when extremely large core files (e.g., >80GB) are generated by F5OS host processes, filling the partition and preventing normal operation. Error messages may include "no space left on device" and failures to generate diagnostic files due to disk exhaustion. Disk usage can be confirmed using CLI commands such as df -hl -t ext4 and du -sh.

Environment

  • F5OS rSeries appliance
  • Hosting BIG-IP LTM tenant(s)
  • /sysroot partition at 100% usage
  • Large core files present on the host
  • CLI access to F5OS host shell

Cause

Extremely large core files generated by F5OS host processes are not automatically deleted, filling the /sysroot partition and causing the appliance and all hosted tenants to become unavailable. Normal operations such as upgrades or diagnostics are blocked.

Recommended Actions

  • Identify large core files using CLI commands:
    • Check disk usage: df -hl -t ext4
    • List large files: find / -xdev -type f -size +300M | xargs ls -aslSkh
  • Safely remove large core files to restore disk space and system availability:
    • rm -f <large_core_file_path>
  • After cleanup, verify disk usage and confirm system operation is restored.
  • Monitor for recurrence by periodically checking for large core files and disk usage.
  • Review system logs to determine why core files are being generated and address underlying issues if possible.
  • Note: When the host disk is full, tenant upgrades and diagnostic operations may be blocked until space is restored.
