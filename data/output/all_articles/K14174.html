Known Issue

Running tcpdump instances on the BIG-IP system may affect TMM performance.

This issue occurs when the following condition is met:

  • You start, and then stop tcpdump instances using the command line or Configuration utility.

When you start, and then stop an initial tcpdump instance, the system may create an errant flow between the host subsystem and the TMM. If you start, and then stop another tcpdump instance, packets that the system needs to shut down the tcpdump proxy match the previous flow and fail to properly shut down the proxy. Each subsequent tcpdump instance that is started, and then stopped consumes more TMM resources and further degrades performance.

Impact

TMM processing may be severely impaired.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H409724 on the Diagnostics > Identified > Medium screen.
  • The errant flow between the host and TMM appears in the connection table. For example, the following tmsh command and resulting output shows the flow:

    # tmsh show /sys connection type self protocol icmp ss-server-port 3 cs-server-port 3

    Sys::Connections
    127.1.1.1:any  127.1.1.3:3  127.1.1.3:any  127.1.1.3:3  icmp  1  (tmm: 1)  none
    127.1.1.1:any  127.1.1.2:3  127.1.1.2:41201  127.1.1.2:3  icmp  0  (tmm: 0)  none
  • Command-line utilities, such as the top command, indicate high TMM CPU use.
  • The Configuration utility performance graphs indicate an increase in TMM CPU use.
  • The tmsh utility indicates a noticeable decrease in active connections and connections (/sec).

    For example, the tmsh show /sys performance connections command may show a decrease in active connections and connections (/sec).
  • The Configuration utility performance graphs indicate a noticeable decrease in active connections and connections (/sec).
  • The /var/log/ltm file contains messages indicating that the tcpdump command was started, and then stopped. The messages appear similar to the following example:

    notice tmm[29417]: 013e0001:5: Tcpdump starting bcast on <address:port> from <address:port>
    notice tmm[29417]: 013e0001:5: Tcpdump stopping bcast on <address:port> from <address:port>

Workaround

There is no workaround. However, instead of running tcpdump on the BIG-IP system, you can mirror traffic to a dedicated sniffing device.

If your system is currently experiencing the symptoms related to this issue, restore system resources to normal levels by deleting the errant flow from the connection table. To do so, perform the following procedure:

Impact of workaround: The following procedure should not have a negative impact on your system.

  1. Log in to the tmsh shell by typing the following command:

    tmsh
  2. Remove the errant flows from the connection table by typing the following command:

    delete /sys connection type self protocol icmp ss-server-port 3 cs-server-port 3
  3. Verify that the connections have been removed. The following command should show Total records returned: 0:

    show /sys connection type self protocol icmp ss-server-port 3 cs-server-port 3

     For example:

    Sys::Connections
    Total records returned: 0
