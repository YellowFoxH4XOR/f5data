Known Issue

The Automatic Policy Builder may incorrectly parse parameters in an HTTP response.

This issue occurs when all of the following conditions are met:

  • Automatic policy building is enabled
  • The policy builder Learn from responses option is enabled
  • The policy builder is configured to learn parameters

Impact

The policy building engine may incorrectly learn parameters.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Parameters present in HTTP response strings may not be added to the security policy.
  • Parameters that are constructed of concatenated parameter-value pairs may be incorrectly added to the security policy.

    For example, if the policy builder receives the following query string::

    resource_id=R74SON01PR574O23N8N78QNQO559739Q&login_type=1&site_name=mysite&secure=1&orig_url=https%3a%2f%2host.test.domain.tld

    The policy builder will learn the following parameter and add it to the security policy:

    parameter name: resource_id=R74SON01PR574O23N8N78QNQO559739Q&login_type=1&site_name=mysite&secure=1&orig_url=https%3a%2f%2host.test.domain.tld

    When correctly parsed, the policy builder should learn the following individual parameters from the query string:

    parameter name: login_type
    parameter name: orig_url
    parameter name: resource_id
    parameter name: secure
    parameter name: site_name

Workaround

To work around this issue, you can disable learning from responses. To do so, perform the following procedure:

Impact of workaround: The policy builder may take longer to learn all application parameters, as only requests will be evaluated.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Application Security.
  3. Click Policy Building.
  4. Click Automatic.
  5. Click Configuration.
  6. From the Automatically Build Policy menu, select Advanced.
  7. In the Options section, disable the Learn from responses option.
  8. Click Save.
  9. Click Apply Policy.
