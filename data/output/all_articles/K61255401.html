Known Issue

The bigd process may stop monitoring when it is unable to open the log file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured to monitor nodes, pools, or pool members.
  • Debug logging is enabled for the bigd process.
  • The log file for the bigd process (/var/log/bigdlog) is full.

Impact

In BIG-IP 11.6.1 and 12.0.0 with HF3 or later installed, this issue can cause the bigd process to stop monitoring, resulting in the system erroneously marking down monitored resources.

In BIG-IP 12.1.0 and later, the impact is negligible due to changes in the logging framework.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H697732 on the Diagnostics > Identified > Medium page.
  • The system is incorrectly marking down monitored nodes, pools, or pool members, preventing users from accessing resources.
  • In affected versions prior to BIG-IP 12.1.0, in the /var/log/ltm file, the system logs warning messages similar to the following example:

    01060154:4: Bigd PID <ID> throttling monitor instance probe because file descriptor limit 65436 reached.

  • The bigd process reports monitored resources as down.

Workaround

To work around this issue, you can remove the /var/log/bigdlog file and restart the bigd process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. To disable debug logging for the bigd process, type the following command:

    tmsh modify /sys db bigd.debug value disable

  3. To remove the /var/log/bigdlog file, type the following command:

    rm -f /var/log/bigdlog

  4. To restart the bigd process, type the following command:

    tmsh restart /sys service bigd

  5. Optional: To enable debug logging again, type the following command:

    Note:  The value for bigd.debug variable is set to disable by default.  You should enable debug logging only when you are actively troubleshooting, and you should disable it after troubleshooting is complete.

    tmsh modify /sys db bigd.debug value enable

To mitigate this issue, you can automate the log rotation process using the logrotate utility and prevent the /var/log/bigdlog file from becoming full.  You can create a file containing the parameters for log rotation and the logrotate utility rotates the logs based on the configured parameters.  For example, if you use the weekly option, the system rotates the log file on a weekly basis. If you set the size option to 1000M, the system rotates the log file when the file size exceeds 1 GB, regardless of whether the rotational interval is reached. To automate the log rotation for the /var/log/bigdlog file, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to bash.
  2. To create the /etc/logrotate.d/bigdlog file, type the following command:

    touch /etc/logrotate.d/bigdlog

  3. To configure a file size of 1 GB with a weekly rotation, open the newly created file for editing using text editor, such as the vi utility, and enter the following information:

    /var/log/bigdlog {
         compress
         missingok
         notifempty
         weekly
         create
         rotate 10
         size 1000M
         sharedscripts
         postrotate
             touch /var/log/bigdlog
         endscript
    }

  4. Save the changes and exit the editor.
  5. To test the file rotation, type the following command:

    logrotate -f bigdlog

    This rotates the logs based on the parameters in the /etc/logrotate.d/bigdlog file.
