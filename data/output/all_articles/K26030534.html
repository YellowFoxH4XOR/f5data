Description

  • Traffic which is expected to match a configured rule in a BIG-IP AFM policy is not getting hit.
  • Testing with BIG-IP AFM network tester shows the rule is in place. This can be verified from the CLI using a command similar to the one below:

tmsh show net packet-tester security protocol tcp syn src-addr 10.1.1.1 src-port 21233 dst-addr 172.16.1.1 dst-port 53 src-vlan External

  • When sending traffic that should hit this rule, it is seen the hit count does not increase. The 0 in the output below shows the hit-count for this rule.

tmsh show security firewall rule-stat raw | grep ZoneRule
global  global-firewall-rules  ZoneRule  -  ZoneRule    enforced    0   N/A  accept-decisively


Environment

  • BIG-IP AFM is provisioned.
  • AFM zones are configured
  • An AFM network firewall rule is configured with destination zones
  • The egress route for the destination IP addresses for this rule use gateway pools.


Cause

In BIG-IP AFM, zones made up of one or more VLANS can be configured. See Manual Chapter : About AFM Zones for more details. However, there is an issue when using destination zones which can result in that rule not getting hit as expected for incoming traffic. This happens when a network route is configured for a destination network or host that uses a gateway pool. To illustrate, the network route below for 172.16.0.0/16 is routed out via the LTM pool gateway_pool

net route gwPool {
    network 172.16.0.0/16
    pool /Common/gateway_pool
}
ltm pool gateway_pool {
    members {
        10.2.1.10:any {
            address 10.2.1.10
            session monitor-enabled
            state up
        }
    }
    monitor gateway_icmp
}

There is an AFM rule for this destination network that uses a destination zone.

        ZoneRule {
            action accept-decisively
            ip-protocol any
            log yes
            rule-number 1
            destination {
                addresses {
                   172.16.0.0/16 { }
                }
                zones {
                    Internal { }
                }
            }
            source {
                addresses {
                    0.0.0.0/0 { }
                }
            }

Using a gateway pool as the egress route for the destination address results in the destination Zone not being read correctly within the traffic flow. This results in the expected rule not getting hit. This unexpected behavior is being tracked under Bug ID 997169.


Recommended Actions

Workarounds can be either of the 2 options below.

  1. Use a gateway IP instead of a gateway pool in the egress network route.
  2. Do not use a destination zone in the AFM network firewall rule
