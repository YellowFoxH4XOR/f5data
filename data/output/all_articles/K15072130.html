Description

When the Client sends a SYN message as part of a TCP  three-way-handshake that does not include TSval and TSecr, in most cases, the BIG-IP will still send the TSval and TSecr via the serverside connection.

Environment

  • Timestamps Extension for High Performance (RFC 1323)" is enabled (BIG-IP default setting)
  • Client is not sending TSval and TSecr in  the SYN packet

Cause

With Timestamps Extension for High Performance (RFC 1323) enabled, the BIG-IP will always send timestamps on the serverside. There are however two exceptions:

  1. Proxy Options is enabled and there is no timestamps from the client.
  2. Proxy Maximum Segment is enabled, the client MSS matches the MSS value in the TCP profile, and there is no timestamps from the client. In that case, the BIG-IP will not add the timestamps on the server side.
For example if the client sends a segment with 1460 bytes on the server side, the BIG-IP needs to chop it into two segments:

TCP_header + 1448 and TCP_header + 12 (TCP Timestamps Option is 12 bytes long in total). 

Recommended Actions

Modify the behavior on the client or disable the Proxy Maximum Segment on the tcp profile

To disable Proxy Maximum Segment on the BIG-IP, follow the steps below:
  1. Navigate to Local Traffic > Profiles > Protocol > TCP
  2. Click on the Profile
  3. Under Connection Setup, check Proxy Maximum Segment custom button and uncheck the Enabled box
  4. Click on Update
