K000092547: [F5RST: Route domain not reachable (strict mode)] for some of the connections

Type
Support Solution
Published
2022-11-04
Updated
2022-11-04
Source
https://my.f5.com/manage/s/article/K000092547

Description

Some connections reset with cause [F5RST: Route domain not reachable (strict mode)].

Virtual server in question does not attempt to forward traffic to a destination in a different route domain.

Environment

  • TCP resets
  • Route domains

Cause

  • K17195: iRules may return incorrect data when the BIG-IP configuration has multiple administrative partitions or folders that contain objects with the same name

iRule load balances to a pool without specifying the full configuration path, while pool name exists in two different partitions, each with a different default route domain.

Example problematic configuration:

ltm rule /partition1/my_irule {
    when HTTP_REQUEST {
        pool my_http_pool
    }
}
ltm pool /partition1/my_http_pool {
    members {
        /partition1/10.10.10.1:80 {
            address 10.10.10.1
        }
    }
}
auth partition partition1 {
    default-route-domain 1
}
###################################
ltm rule /partition2/my_irule {
    when HTTP_REQUEST {
        pool my_http_pool
    }
}
ltm pool /partition2/my_http_pool {
    members {
        /partition1/10.10.10.1:80 {
            address 10.10.10.1
        }
    }
}
auth partition partition2 {
    default-route-domain 2
}

Recommended Actions

Specify both the partition and pool name in the iRule.

For example:

ltm rule /partition1/my_irule {
    when HTTP_REQUEST {
        pool /partition1/my_http_pool
    }
}
