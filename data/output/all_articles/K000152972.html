K000152972: [F5OS] Local user gets prompted to reset password after having it changed using set-password option

Type
Support Solution
Published
2025-08-12
Updated
2025-12-27
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.7.X, 1.8.0, 1.7.0
  • F5OS-C: 1.6.X, 1.8.X, 1.8.1, 1.8.0, 1.6.2, 1.6.1, 1.6.0
Source
https://my.f5.com/manage/s/article/K000152972

Description

Local user accounts get prompted to reset their password after recently having it changed by another user with Administrator privilege using the "set-password" option via ConfD CLI.

Environment

  • F5OS-A (rSeries) / F5OS-C (VELOS) device being used
  • User password changed using the "set-password" option via ConfD CLI

Cause

This is due to a behavior change introduced via ID1301357 in F5OS v1.6.0 and above releases (rSeries and VELOS). When the “set-password” command is used to change the password, it now sets the user’s “last-change” field to zero.

This triggers a forced password change at the next login, ensuring that the user sets their own password rather than relying on one set by another account, even if that account is an administrator.

Recommended Actions

If there is a desire to avoid forcing the user to change their password at next login, you can manually set the “last-change” field to the current date after using “set-password". This allows the user to log in directly with the new password without being prompted for a reset. The following procedure help accomplish that:

(1) Enter configuration prompt mode after logging in as a user with Administrator privilege:

config terminal

(2) Change the user's password using the set-password endpoint:

system aaa authentication users user johnsmith config set-password password

Note: Replace "johnsmith" with the desired username in the above command.

(3) Manually set the last-change field to the current date at the time of the change and then commit the change.

A difference in behavior exists between F5OS-A, where “last-change” field represents the date in the format YYYY-MM-DD, and F5OS-C, where "last-change" represents the days from the first unix epoch time (1970-01-01). This is being tracked by ID1038877 for F5OS-C to represent a date instead of a number of days.

For F5OS-A:

system aaa authentication users user johnsmith config last-change YYYY-MM-DD ; commit and-quit

Note: Replace "johnsmith" with the desired username and "YYYY-MM-DD" with the current date at the time the change is made.

For F5OS-C:

system aaa authentication users user johnsmith config last-change days ; commit and-quit

Note: Replace "johnsmith" with the desired username and "days" with a number different from zero, that represents the days elapsed since the epoch time.

Note: This article describes how to make this change possible through ConfD CLI, but this is also possible using F5OS REST API through an HTTP PATCH to the endpoints: F5OS-A, F5OS-C; following the same last-change value discussed for each platform.

(4) Confirm the last-change field got set accurately and reflects a non-zero value:

show system aaa authentication users user johnsmith
Note: Replace "johnsmith" with the desired username in the above command.

(5) Logging to a new session as this custom user should no longer prompt a password change after the successful authentication.

Additional Information

Similar behavior will be observed when a local user has their password changed by root using the "passwd" command.
