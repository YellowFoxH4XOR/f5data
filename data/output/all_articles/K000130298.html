Description

This article explains helps troubleshooting kvno mismatch issues when kerberos End User Logon feature is deployed.
Sometimes you may see that AAA kerberos authentication fails and such logs are seen under /var/log/apm:

Nov 12 16:30:00 bigip debug apmd[13733]: 01490266:7: /Common/AP_example:Common:96ab957b: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'display_status_1()': 94: 96ab957b : GSS-API error gss_accept_sec_context: d0000 : Unspecified GSS failure. Minor code may provide more information

Nov 12 16:30:00 bigip debug apmd[13733]: 01490266:7: /Common/AP_example:Common:96ab957b: modules/Authentication/Kerberos/KerberosAuthModule.cpp: 'display_status_1()': 94: 96ab957b : GSS-API error gss_accept_sec_context: 186a5 :

While these are pretty generic error messages which could also point to few different issues (time difference between BIG-IP and KDCs, difference in encryption or ciphers), it can also mean that there is a difference in the key version number (kvno) between the one from the service account on the AD and the one from the keytab file on the BIG-IP.
 

Environment

  • APM configured with AAA kerberos authentication (also known as End User Logon)

Cause

There are a few situations where the kvno will increase.

  1. The first one is when a new keytab is generated.
  2. The second one is if the password of the service account on the AD has been changed.
     

Recommended Actions

  1. Retrieve kvno from Active Directory service account:

PS> import-module ActiveDirectory
PS> get-aduser delegation -property msDS-KeyVersionNumber | Fl

DistinguishedName     : CN=service_example,CN=Users,DC=example,DC=com
Enabled               : True
GivenName             : service_example
msDS-KeyVersionNumber : 4 <---------------
Name                  : service_example
ObjectClass           : user
ObjectGUID            : 1d1358d4-046a-4570-9d90-6027287ee3f3
SamAccountName        : service_example
SID                   : S-1-5-21-882427465-4011647165-2960366939-1122
Surname               :
UserPrincipalName     : HTTP/vip.example.com@EXAMPLE.COM

In this case the kvno is 4.
 

  1. Retrieve kvno from the keytab file on the BIG-IP UI:

Navigate to "Access >> Authentication >> Kerberos", then edit the relevant AAA kerberos profile.
The kvno should appear under the "Keytab File Details" section.
 

  1. Retrieve kvno from the keytab file on the BIG-IP console:

[root@bigip:Active:Standalone] config # ktutil
ktutil:  rkt /config/filestore/files_d/Common_d/kerberos_keytab_file_d/:Common:vip_key_file_10
ktutil:  list –e
slot KVNO Principal
---- ---- ---------------------------------------------------------------------
   1    3 HTTP/vip.example.com@EXAMPLE.COM (AES-256 CTS mode with 96-bit SHA-1 HMAC)
ktutil:  

In this case the kvno is 3.

If kvno observed on Active Directory and BIG-IP are not matching, a new keytab must generated and then imported to the BIG-IP to replace the previous one.
