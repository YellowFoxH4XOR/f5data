K000133300: Repace nfs server with a new nfs server

Published
2023-03-31

Applies to

Source

Description

Replace existing nfs server with a new nfs server

Environment

NGINX Controller configured to store database data (clickhouse and postgres) on an external nfs server

Cause

NFS server needs to be replaced

Recommended Actions

Modify clickhouse

1. Scale down the clickhouse statefulset

kubectl scale --replicas=0 statefulset clickhouse

2. Export the current clickhouse pv and pvc to a yaml file

kubectl get pv clickhouse -o yaml > clickhouse-pv.yaml
cp clickhouse-pv.yaml clickhouse-pv-mod.yaml
kubectl get pvc clickhouse-clickhouse-0 -o yaml > clickhouse-pvc.yaml
cp clickhouse-pvc.yaml clickhouse-pvc-mod.yaml

3. Delete the clickhouse pv and pvc resources

kubectl delete pvc clickhouse-clickhouse-0
kubectl delete pv clickhouse --grace-period=0 --force

4. Modify clickhouse-pv-mod.yaml

  • change the values for “spec:nfs:path:” and “spec:nfs:server:” to the new nfs server and share path
  • delete "claimRef:"

5. Modify clickhouse-pvc-mod.yaml

  • delete "annotations:"
  • delete "uid:”

6. Apply both modified clickhouse resources

kubectl apply -f clickhouse-pv-mod.yaml
kubectl apply -f clickhouse-pvc-mod.yaml

7. Confirm STATUS on both clickhouse pv and pvc is Bound

kubectl get pv,pvc | grep clickhouse

8. Scale up the clickhouse statefulset

kubectl scale --replicas=1 statefulset clickhouse
  • If the clickhouse pod starts and is throwing db errors and exceptions then run update.sh from the controller install package
Modify postgres

1. Stop controller

/opt/nginx-controller/helper.sh controller stop

2. Export the postgres pv and pvc to a yaml file

kubectl get pv controller-postgres -oyaml > postgres-pv.yaml
cp postgres-pv.yaml postgres-pv-new.yaml
kubectl get pvc controller-postgres-controller-postgres-0 -oyaml > postgres-pvc.yaml
cp postgres-pvc.yaml postgres-pvc-new.yaml

3. Modify postgres-pv-new.yaml

  • modify nfs.path and nfs.server as needed.
  • delete "claimRef:"

4. Modify postgres-pvc-new.yaml

  • delete "annotations:"
  • delete "uid:"

5. Delete the current postgres pvc and pv

kubectl delete pvc controller-postgres-controller-postgres-0
kubectl delete pv controller-postgres
  • IF the postgres pvc is not deleting (stuck in STATUS "Terminating") then remove setting "finalizers" from the postgres pvc
kubectl patch pvc controller-postgres-controller-postgres-0 -p '{"metadata":{"finalizers":null}}'

6. Apply the new postgres pv and pvc resources

kubectl apply -f postgres-pv-new.yaml
kubectl apply -f postgres-pvc-new.yaml

7. Confirm STATUS on both postgres pv and pvc is BOUND

kubectl get pv,pvc | grep postgres

8. Start controller

/opt/nginx-controller/helper.sh controller start
