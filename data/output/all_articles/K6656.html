Known Issue

This is the result of a known issue. Certain configuration changes, such as changing a BIG-IP profile, may cause traffic to bypass BIG-IP ASM. When you make a configuration change, the BIG-IP ASM iRule is removed from the virtual server configuration. As a result, traffic bypasses the BIG-IP ASM and is directed to backend nodes. The virtual server remains in an unsecured state until you reload the configuration.

Workaround

You can work around this issue by reloading the configuration. To reload the configuration, type the following command:

bigpipe load

F5 Product Development tracked this issue as CR69123 and it was fixed in BIG-IP ASM 9.2.4. For information about upgrading, refer to the BIG-IP ASM release notes.
