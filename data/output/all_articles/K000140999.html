K000140999: Management IP may become unreachable after primary blade fails in vCMP environment

Type
Support Solution
Published
2024-09-09
Updated
2024-09-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.5
Source
https://my.f5.com/manage/s/article/K000140999

Description

vCMP system management IP may suddenly become unreachable.

Example environment:

VIPRION platform with at least 2 slots and vCMP guest/s deployed. To simplify, VIPRION blades are only in slot 1 and slot 2. Only management interface of slot 1 is UP.

As per "tmsh show sys cluster" output, the primary slot is 1 on both vCMP host and vCMP guests.


Example scenarios:

1) Primary slot 1 fails on vCMP guest. Slot 2 takes active role.

/var/log/ltm on vCMP guest indicates there was a new primary blade selected (various reasons, not the subject of this article). Slot 2 becomes primary and vCMP guest management IP becomes unreachable at this point. The guest can still be accessed via vconsole.

2) Primary slot 1 fails on vCMP host. Slot 2 takes active role.

All the guests that were running only on slot 1 as well as the guests which primary slot got changed to slot 2 (due to slot 1 failure on the hypervisor), become unreachable. Furthermore, the guests running on slot 1 only are down, traffic processing stops, or there was a failover. Guests running on slot 2 can still be accessed via vconsole.

Environment

  • Multi-blade VIPRION acting as vCMP host
  • vCMP guest running on multiple blades
  • Not all VIPRION management interfaces are UP/cabled

Cause

Expected behavior. Cluster floating management IP does not float to the other blade when the management interface of the primary blade is down. The blade needs to be rebooted or fail, so the floating management IP would float to the other blade, and the new primary blade would be selected.

Recommended Actions

  1. Make sure all the management interfaces are UP/cabled.
  2. Management IP connectivity can be recovered by making sure the vCMP guest primary blade is the one with management interface being UP.

Additional Information

None.
