Topic

The configuration synchronization (ConfigSync) feature allows you to synchronize configuration information from one device to other devices in the same device group. This article provides information about the ConfigSync compatibility between BIG-IP versions.

    Description

    Beginning in BIG-IP 11.0.0, the device service clustering (DSC) architecture provides the centralized management for BIG-IP systems in a high availability (HA) configuration. The ConfigSync feature runs on the DSC architecture to synchronize configuration information across devices in a device group. To synchronize configuration data among device group members, all members must be running the same major, minor, or maintenance version of the BIG-IP system software. By default, the point release and hotfix version numbers are not required to match among device group members when performing ConfigSync operations.

    For example:

    • A BIG-IP 16.0.0 device can synchronize its configuration information to another BIG-IP 16.0.0 device when they are configured in the same device group.
    • A BIG-IP 16.1.0 device will not synchronize its configuration information to a BIG-IP 16.0.1 or 16.0.0 device, even if they belong to the same device group.
    • A BIG-IP 16.0.1 device synchronizes its configuration information to a BIG-IP system running a different point release version, such as BIG-IP 16.0.1.1.

    When BIG-IP devices running different major, minor, or maintenance versions attempt to synchronize configuration information, the synchronization will fail. Additionally, the BIG-IP device may log error messages to the /var/log/ltm file that appear similar to the following examples:

    01070712:3: Caught configuration exception (0), Can't parse MCP message, can't parse atomic message element current message state: [modify tag:2908 state:1][cmi_peer_hello tag:13020 state:1] current CID [device_ip tag:13218] status:16908326 - msg++/MsgParser.h, line 342.

    01070712:3: Caught configuration exception (0), Can't parse MCP message, can't parse atomic message element current message state: [create_if tag:2911 state:1][sys_device tag:13105 state:4] current CID [mgmt_ip tag:13109] status:16908326 - msg++/MsgParser.h, line 342.

    01071482:3: Remote transaction for device group /Common/device_trust_group to commit id 1 5750816289405498368 /Common/www.example.com failed with error Can't parse MCP message, can't parse atomic message element current message state: [create_if tag:2911 state:1][sys_device tag:13105 state:4] current CID [mgmt_ip tag:13109] status:16908326 - msg++/MsgParser.h, line 342.

    Recommendations

    When upgrading a BIG-IP device in an HA configuration, F5 recommends that you upgrade the remaining devices belonging to the same device group as soon as possible to avoid configuration synchronization issues.
