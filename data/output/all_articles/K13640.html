Known Issue

The HTTPS health monitor may fail to complete an SSL handshake with the pool member.

This issue occurs when the following condition is met:

  • The monitor Send String value is left blank

The HTTPS monitor Send String setting specifies the text string that the monitor sends to the pool member. By default, the HTTPS monitor Send String value is GET /\r\n. If you remove the default value and leave the Send String blank, the monitor completes a TCP three-way handshake with the pool member, but does not attempt to establish an SSL handshake with the pool member or close the connection.

Impact

The monitor marks the pool member down, and the resource is unavailable for load-balancing.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A packet trace indicates that the monitor completes a TCP three-way handshake with the pool member, but does nothing further
  • The pool member re-transmits its SYN-ACK packet, and the HTTPS health monitor re-transmits the initial ACK packet
  • The monitor eventually marks the pool member down

Workaround

To work around this issue, you can configure a Send String value for the HTTPS monitor. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Monitors.
  4. Click the relevant HTTPS monitor.
  5. Define a Send String value appropriate for your environment.

    Note: For information about configuring requests for HTTP or HTTPS health monitors, refer to K2167: Constructing HTTP requests for use with the HTTP or HTTPS application health monitor.
  6. Click Update.
