Known Issue

Access policy Lightweight Directory Access Protocol (LDAP) queries may retrieve an incomplete authenticated user group member list.

This issue occurs when all of the following conditions are met:

  • You have configured the access profile access policy with the LDAP Query agent.
  • You have configured the LDAP Query agent with Fetch groups to which the user or group belong set to All.
  • You have configured the LDAP Query agent with the Required Attributes LDAP attribute set to memberOf.

Impact

When you submit the query, the system produces an incomplete list of LDAP groups to which the user is a member.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the access session variable session.ldap.last.memberOf for the query, the groups listed are only those of which the user is a direct member.
  • The access policy processes the user session where access or the specific LDAP group membership resources are not appropriately assigned to the user session.

Workaround

To work around this issue, you can add attributes to the LDAP Query agent Required Attributes configuration. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform the suggested procedure during a scheduled maintenance window.

  1. Log in to the BIG-IP APM Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. To open the VPE editor, click Edit to the right of the affected access policy name.
  5. Click the LDAP Query box.
  6. Click Add new entry.
  7. Enter each of the following LDAP attributes, separately, by repeating step 6.

    objectClass
    primaryGroupID

    Note: F5 recommends that you use the attribute primaryGroupID when the BIG-IP APM system communicates with LDAP for Microsoft Active Directory. Adding the primaryGroupID attribute causes the BIG-IP APM system to fetch all of the groups in Microsoft Active Directory.

  8. Click Save.
  9. Click Apply Access Policy.
  10. Click Close.
