K24204204: Problem with Linux and MAC client's host file entries being removed after connecting VPN tunnel

Type
Support Solution
Published
2020-10-15
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.X.X, 13.1.X, 13.0.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.0, 13.0.1, 13.0.0
Source
https://my.f5.com/manage/s/article/K24204204

Description

When a Linux or MAC client's host file contains entries whose hostname (or part of it) matches the static host added on DNS/Host settings of the Network access list then the client's host file entries gets removed when tunnel is connected. To elaborate:

For example customer's Linux client contains the following (note the hostname has "tiket" in it on both client and Network access list):

linux@linux-virtual-machine:~$ cat /etc/hosts
127.0.0.1    localhost
127.0.1.1    linux-virtual-machine
4.4.4.4        tiket.example.com   <--
2.2.2.2         tiket.example.com   <--
3.3.3.3         tiket.example.com   <--

The Network Access list configuration contained :

  static-host {
        {
            address 47.x.x.x
            hostname tiket.example.com   <--
        }

After tunnel is connected the client's host entries are removed and replaced with the static host entry defined the Network access list above:

linux@linux-virtual-machine:~$ cat /etc/hosts

127.0.0.1    localhost
127.0.1.1    linux-virtual-machine
# The following lines are desirable for IPv6 capable hosts
::1     ip6-localhost ip6-loopback
fe00::0 ip6-localnet
ff00::0 ip6-mcastprefix
ff02::1 ip6-allnodes
ff02::2 ip6-allrouters
47.x.x.x tiket.example.com   <----  all the local host entries containing "tiket" disappeared and replaced with ticket.example.com

Once the VPN is disconnected the client's host entries are restored back.
This only happens when the hostname in the fqdn is similar. i.e. if the static host entry on the profile had abc.testsite.com instead of tiket.testsite.com this issue does not happen.

Environment

  • BIG-IP
  • BIG-IP version 13.1.3.1,
  • APM client version 7183 and 7190

Cause

This was escalated to Product development team and ID924941 created for it.
Issue has been fixed and verified in APM client version 7210 .

Recommended Actions

Upgrade to APM client version 7210.
