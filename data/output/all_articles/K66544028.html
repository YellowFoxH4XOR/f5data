Known Issue

Stuck hardware-accelerator SSL queues cause the Traffic Management Microkernel (TMM) to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses Nitrox 3 encryption hardware to perform SSL encryption.
  • The crypto hardware accelerator receives invalid or corrupt SSL handshakes that result in a stuck request queue.

The Nitrox 3 encryption hardware fails to recover the stuck SSL request queues, causing TMM to eventually exhaust system memory resources, resulting in a TMM restart.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured for high availability (HA) fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe the BIG-IP system experiencing SSL connection failures.
  • In the /var/log/ltm file, you notice error messages that appear similar to the following example:

    : n3-cryptoX request queue stuck

  • You observe TMM exhausting system memory resources, resulting in a TMM restart.
  • The BIG-IP system temporarily fails to process traffic as it recovers from TMM restart.
  • If configured for HA, the affected BIG-IP device fails over to a configured peer device.
  • The BIG-IP system generates a TMM core file to the /shared/core directory, which includes a time stamp correlating with the traffic interruption.

Workaround

To work around this issue, you can disable crypto hardware acceleration. To do so, perform the following procedure:

Note: This workaround is applicable only if you are running BIG-IP 14.0.0 or later.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Disable crypto hardware acceleration by typing the following command:

    modify /sys db crypto.hwacceleration value disable
