Description

When attempting upgrade of a BIG-IP system in a Virtual Edition environment, the upgrade fails and instead of booting back to the previously working volume WITHIN the VE, a Snapshot is reinstated from the Hypervisor level.

This causes all logging of errors that occurred during the upgrade attempt to disappear as the Snapshot does not have this information.

Environment

  • BIG-IP VE
  • snapshot taken in the VE environment: such as
    • Amazon AWS [AMI]
    • Microsoft Azure
    • Google Cloud
    • Alibaba
    • ESX [snapshot]
  • BIG-IP version in the VE is upgraded, but fails to load configuration
  • Snapshot from before upgrade attempt is restored at the cloud or hypervisor control level

Cause

Restoring a Snapshot will NOT retain logs regarding the upgrade attempt.
Rolling back by booting a volume within the existing VE after upgrade does retain the logs pertaining to the upgrade (and can be used for troubleshooting)

Recommended Actions

  1. Do not use restore from snapshot to restore BIG-IP functionality but rather boot an existing working volume within the VE instead.
  2. If you are going to restore/rollback from a hypervisor level backup, take a qkview on the BIG-IP AND copy it from the instance before doing the restore/rollback.
