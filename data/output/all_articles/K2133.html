K2133: Reasons why BIG-IP last hop features may not work correctly with clustering schemes that work based on MAC address changes

Topic

Some third-party load balancing schemes use a method of connection control that redirects future packets for a specific MAC address to a different server. This is accomplished by the primary server of the cluster, which sends ARP requests on behalf of a member server, thereby redirecting traffic away from the primary server and distributing it to the member servers.

The BIG-IP auto_lasthop feature interrupts this form of server-side load balancing, because it bases each connection's destination on the server's MAC address, not an IP address; therefore, when the primary server sends out the ARP, the auto_lasthop table is not updated.

Note: The operating system (OS) level ARP table is updated, but auto_lasthop does not use the OS level ARP table.)

Example load balancing configuration:

client
|
bigip
|
+--nlb1 (primary)     > 02:01:c0:ff:ee
+--nlb2 (member)     > 02:bf:c0:ff:ee
+--nlb3 (member)     > 02:cf:c0:ff:ee

When auto_lasthop is enabled in this example configuration, BIG-IP uses the server's source MAC address as the destination MAC address for packets coming back from the client to that same connection and ignores the OS level ARP table.

nlb1 (primary) sends a packet to BIG-IP using the MAC address 02:01:c0:ff:ee:aa, then sends a who-has ARP with the MAC address of 02:01:c0:ff:ee:a5 to update the BIG-IP's Ethernet destination to the cluster MAC address, instead of the individual server's MAC address.

Once BIG-IP receives a response from the client, BIG-IP looks up the connection and finds that the source MAC address for the nlb1 server is 02:01:c0:ff:ee:aa instead of the cluster MAC address that the primary sent the ARP out for, which was 02:01:c0:ff:ee:a5.

To resolve this issue, use one of the following solutions:

  • Discontinue using the third-party load balancing schemes that utilize this method of connection control. BIG-IP is superior at load balancing and trying to use the BIG-IP auto_lasthop feature with a third party load balancing scheme can cause issues and make it impossible to use BIG-IP's advanced features.
  • Discontinue using the BIG-IP auto_lasthop feature. This will force BIG-IP to view the OS level MAC address associated with the destination IP address.
