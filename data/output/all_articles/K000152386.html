Description

If loose-init option is enabled in the protocol profile attached to the virtual server then a connection matching an IPS signature could be allowed for this virtual server.

 

Environment

  • BIG-IP AFM provisioned.
  • IPS profile attached to the virtual server.
  • IPS signature is configured for dropping.
  • Parameter loose-init enabled in the FastL4 protocol profile attached to the virtual server.

 

Cause

This happens because of the specific IPS requirements for parsing streams and how loose-init capability breaks it. loose-init specifies that the system has to initialise a connection when it receives any Transmission Control Protocol (TCP) packet, rather than requiring a SYN packet for connection initiation. On the other hand IPS is heavily dependent on the stateful nature of streams.

Under normal circumstances if a TCP IPS signature is matched and it's configured for dropping then this connection will not be allowed, so all packets related to it will be silently dropped. However under the described circumstances an IPS signature will drop the packet matching the signature, however if this packet is re-transmitted by the client then the BIG-IP will initialise the connection and it will forward the packet to the server. 

Let's see it through an example:

 

  • An IPS signature is configured to look for http connections and then dropping packets with the header 'attacker: yes'.
  • A client starts a http connection (TCP 3WHS and so on).
  • IPS starts to parse this connection trying to find a match against the configured http signatures.
  • A PSH packet is sent by client after TCP 3WHS with a http request including the header 'attacker: yes'.
  • IPS detects that this connection matches a signature, so it drops this PSH packet.
  • Client re-transmit the packet in the next second (default TCP timeouts).
  • IPS is not detecting this as a new http connection to parse and BIG-IP forwards the packet creating a new entry in connection table for it.

 

Recommended actions

There are two possible workarounds. 

 

  • Do not use IPS when the virtual server is using a FastL4 profile with loose-init enabled.
  • Configure IPS for rejecting the connection instead of dropping.
