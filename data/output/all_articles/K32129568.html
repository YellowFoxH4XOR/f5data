Details:

Description

When uploading a large size file, the following errors are displayed:
  • In PCAP capture file "413 Request Entity Too Large" header or response is captured.
  • In browser, "ERR_HTTP2_PROTOCOL_ERR" might be shown.
     

Environment

  • BIG-IP  LTM
  • HTTP Virtual Server
  • HTTP POST requests processing Virtual Server
  • HTTP2 protocol might be used
  • ASM policy applied to http Virtual Server  (*)
  • Apache pool member

Cause

Cause 1:

User uploads an object larger in size than max configured size in http application limit in pool member.

In PCAP capture, then following message is received from http application server:

Cause 2 (* when ASM policy is applied to http VS):

- ASM restricts HTTP Payload to 10MB by default.

-----------------------------------------------------------------------------

Cause 3:

HTTP 413 response code coming from the Apache pool member during file upload. It may come with the a similar body:

Line-based text data: text/html (8 lines)
    <!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">\n
    <html><head>\n
    <title>413 Request Entity Too Large</title>\n
    </head><body>\n
    <h1>Request Entity Too Large</h1>\n
    The requested resource does not allow request data with PUT requests, or the amount of data provided in\n
    the request exceeds the capacity limit.\n
    </body></html>\n

Apache server configured with default or too small values of the below parameters:

LimitRequestBody
LimitRequestFieldSize
SSLRenegBufferSize

The below messages might be logged in Apache log files:

request body exceeds maximum size (131072) for SSL buffer
could not buffer message body to allow SSL renegotiation to proceed

Recommended Actions

Impact of procedure: Performing the following procedure should not have a negative impact on your BigIP system. 

  1. Recommend http application to be correctly configured, regarding max object size, in affected pool member(s).
  2. If ASM policy is restricting file size, reconfigure to required size. K11434152: Configuring the BIG-IP ASM system to process large requests
  3. Modify Apache parameters accordingly to Apache logs. For example, if Apache tells about SSL buffer, then modify SSLRenegBufferSize.

Additional Information

From RFC 7231:


https://tools.ietf.org/html/rfc7231#section-6.5.11


6.5.11.  413 Payload Too Large

   The 413 (Payload Too Large) status code indicates that the server is
   refusing to process a request because the request payload is larger
   than the server is willing or able to process.  The server MAY close
   the connection to prevent the client from continuing the request.

   If the condition is temporary, the server SHOULD generate a
   Retry-After header field to indicate that it is temporary and after
   what time the client MAY try again.
