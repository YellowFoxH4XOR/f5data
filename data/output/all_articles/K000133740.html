K000133740: Getting 5xx response instead of 4xx after disabling configured servers

Type
Support Solution
Published
2023-04-29
Updated
2025-02-07
Applies to
  • NGINX Products
  • NGINX Plus: R26
Source
https://my.f5.com/manage/s/article/K000133740

Description

  • You configured and deployed Nginx as a proxy with proxy_pass directives pointing to an upstream.
  • You then proceeded to disable servers configured within the upstream.
  • In the above scenario
    •   While the request/path is valid along with a correctly configured virtual server, Nginx does not have a readily available end server to forward the request to.
    •   This results in Nginx responding with HTTP error 502 bad gateway response

Environment

  • Nginx Plus

Cause

  • None

Recommended Actions

  • None

Additional Information

  • However, Nginx will respond with 404 response, if the incoming request can not be serviced by Nginx and there arn't any valid server/;location block to process traffic.
  • on the other hand, if you configure Nginx to Authenticate clients during request and the client request is NOT accompanied with the required AUTH token, then you would expect Nginx to responds with either 401 or 403.
