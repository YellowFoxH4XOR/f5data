K09264213: Mount workload certificates to the application container filesystem in Aspen Mesh

Type
Support Solution
Published
2021-06-25
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K09264213

Description

Beginning in Aspen Mesh 1.6, Envoy proxies use the SDS (Secret Discovery Service) interface to fetch certificates from Istiod via the istio-agent service running inside the istio-proxy container. Due to security reasons the certificate is kept by the Envoy istio-proxy in memory and not stored in the filesystem. You can export the certificate using the istioctl proxy-config secret command but you cannot export keys. To export the keys from the Envoy istio proxy you have to use the proxyMetadata annotation. Following that, you can mount the certificates and keys to the application container using the volume shared between the istio-proxy and application container.

Environment

  • Kubernetes: 1.17x, 1.18.x, 1.19.x, 1.20.x  
  • Aspen Mesh: 1.6.x, 1.9.x  

Cause

None

Recommended Actions

None

Additional Information

To export the workload SDS certificate and key from the Envoy proxy memory, you have to add the proxyMetadata annotation to your pod manifest. Using this annotation, you tell istio-proxy to export the SDS certificate to the /tmp/istio-certs directory. To share this directory with the application container, you have to add 2 additional annotations to mount the Kubernetes volume named istio-certs on istio-proxy. This volume has to be defined in the pod or deployment specification and mounted on the application container. The following describes the configuration needed:

annotations:
        proxy.istio.io/config: |
          proxyMetadata:
            OUTPUT_CERTS: /tmp/istio-certs
        sidecar.istio.io/userVolume: '[{"name": "istio-certs", "emptyDir": {"medium": "Memory"}}]'
        sidecar.istio.io/userVolumeMount: '[{"name": "istio-certs", "mountPath": "/tmp/istio-certs"}]'

The following example shows the sleep application with SDS certificates mounted in the /tmp/istio-certs directory:

apiVersion: v1
kind: ServiceAccount
metadata:
  name: sleep
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sleep
spec:
  replicas: 1
  selector:
    matchLabels:
      app: sleep
  template:
    metadata:
      labels:
        app: sleep
      annotations:
        proxy.istio.io/config: |
          proxyMetadata:
            OUTPUT_CERTS: /tmp/istio-certs
        sidecar.istio.io/userVolume: '[{"name": "istio-certs", "emptyDir": {"medium": "Memory"}}]'
        sidecar.istio.io/userVolumeMount: '[{"name": "istio-certs", "mountPath": "/tmp/istio-certs"}]'
    spec:
      terminationGracePeriodSeconds: 0
      serviceAccountName: sleep
      containers:
      - name: sleep
        image: curlimages/curl
        command: ["/bin/sleep", "3650d"]
        imagePullPolicy: IfNotPresent
        volumeMounts:
        - mountPath: /tmp/istio-certs/
          name: istio-certs
      volumes:
      - emptyDir:
        medium: Memory
        name: istio-certs

If you connect to the sleep container and list the directory, you can see the certificates mounted in /tmp/istio-certs/:

$ ls -ls /tmp/istio-certs/
total 12
     4 -rw-r--r--    1 1337     1337          2319 Jun 21 22:30 cert-chain.pem
     4 -rw-r--r--    1 1337     1337          1675 Jun 21 22:30 key.pem
     4 -rw-r--r--    1 1337     1337          1099 Jun 21 22:30 root-cert.pem
