Topic

To configure PPTP connection load balancing you will need to perform the following procedures:

  • Creating a pool with PPTP servers to load balance
  • Creating an Any service or an All ports virtual server to allow key negotiation and GRE packets
  • Optional: Creating an iRule that passes only PPTP traffic to a secure Any service virtual server

The standard port for PPTP is TCP port 1723; however, TCP port 1723 is used only for the PPTP control connection. The data connections use GRE (IP protocol 47), which is not TCP or UDP. To pass the data connection GRE packets, the virtual server must be an * All Ports virtual server with the * All Protocols protocol enabled.

Creating a pool with PPTP servers to load balance

To create a pool with PPTP servers to load balance, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Click Pools.
  4. Select Create.
  5. Name the pool.
  6. Select tcp_half_open for the health monitor.
  7. Enter the address of the servers and enter the TCP port.

    Note: The standard port for PPTP is 1723.

  8. Add the members to the pool.
  9. Select Finished.

Creating an Any service virtual server to allow key negotiation and GRE packets

To create an Any service virtual server to allow key negotiation and GRE packets, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Virtual Servers.
  4. Select Create.
  5. Name the virtual server.
  6. Enter an IP address for the virtual server to listen on.
  7. Select * All Ports from the Service Port menu.
  8. In the Configuration section, select Performance (Layer 4) from the Type menu.
  9. Select * All Protocols from the Protocol menu.
  10. Select the pool that you created in the Creating a pool with PPTP servers to load balance procedure for the Default Pool.
  11. Select Finished.

Optional: Creating an iRule that passes only PPTP traffic to a secure Any service virtual server

Since the data connection uses Generic Routing Encapsulation (GRE), the virtual server must be configured with the * All Ports option and * All Services, which opens up the servers in the pool to all traffic. This behavior can be a security concern if no firewall is configured in front of the BIG-IP system.

Without a firewall protecting the PPTP servers, you can use an iRule to restrict traffic to allow only port 1723 (PPTP Control) or protocol 47 (GRE) packets. Any packet not matching will be discarded, preventing any access other than PPTP to the servers.

To create an iRule that passes only PPTP traffic to a secure Any service virtual server, perform the following procedure:

Important: This procedure is optional.

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select iRules.
  4. Select Create.
  5. Name the iRule as pptp_gre_filter.
  6. Copy the following iRule syntax into the Definition field, replacing <your_pool> with the pool name that contains the PPTP servers:
    when CLIENT_ACCEPTED { if { [IP::protocol] == 47 or [TCP::local_port clientside] == 1723 } {	pool <your_pool>    } else {        discard      } }
  7. Select Finished.
  8. Navigate to the virtual server that you created in the Creating an Any service virtual server to allow key negotiation and GRE packets procedure.
  9. Select the virtual server's Resources tab.
  10. Select the Manage button for the iRules section.
  11. Select the pptp_gre_filter iRule and move it to the Enabled box.
  12. Select Finished.
  13. Test to ensure that PPTP communication occurs correctly and that only PPTP traffic is allowed through.
