Known Issue

This is the result of a known issue. The HTTP::cookie remove command available in iRules allows the rule to remove a cookie by name that was set by either the client or server.

If the cookie specified to be removed exists at the top or middle of a list of multiple cookies, the iRule will remove the correct cookie from the list. If the cookie specified to be removed exists at the end of a list of multiple cookies, the iRule will remove all cookies in the list.

In the following example, the iRule is set to look at the server response to the client and remove the cookie, MYCOOKIE:

rule remove_cookie {
when HTTP_RESPONSE {
HTTP::cookie remove "MYCOOKIE"
   }
}

The following tests indicate the resulting cookie deletion behavior, depending upon where MYCOOKIE falls in the cookie list order:

Note: The Set-Cookie is located in the HTTP header and is set by the server.

Test 1

1 Set-Cookie: BigCookie
2 Set-Cookie: JSESSIONID
3 Set-Cookie: MYCOOKIE

In this test, all cookies are removed because MYCOOKIE is at the end of the cookie list. This is incorrect behavior—only the specified cookie, MYCOOKIE, should be removed. As a result, the client receives a response from the server with no cookies.

Test 2

1 Set-Cookie: BigCookie
2 Set-Cookie: MYCOOKIE
3 Set-Cookie: JSESSIONID

For this test, since MYCOOKIE is not at the end of the list, MYCOOKIE is correctly removed and the other cookies remain.

Test 3

1 Set-Cookie: MYCOOKIE
2 Set-Cookie: BigCookie
3 Set-Cookie: JSESSIONID

For this test, since MYCOOKIE is not at the end of the list, MYCOOKIE is correctly removed and the other cookies remain.

F5 Product Development tracked this issue as CR70528 and it was fixed in BIG-IP LTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
