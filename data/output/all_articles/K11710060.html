Description

Clients who establish a network access connection and then attempt to connect to a second Virtual Server that uses an access policy, may receive a TCP reset with a reset cause "F5RST: No server selected".

Environment

  • APM network Access resource and a layered virtual server with Access policy on the same device.
  • The second (layered) APM virtual server and Access policy has a Webtop assigned.
  • This issue occurs when you are trying to access the APM Policy protected virtual server after establishing the Network Access connection.
  • There is no session created for the second Virtual server and access policy connection.
  • Packet capture shows a reset with the following reset reason:
    F5RST: No server selected
    Note: You will not see the reset if the layered Virtual server has a pool assigned. In this case the user will just be allowed access to the pool (resource) without having to complete access policy evaluation.

Cause

This configuration is not currently supported. 

There is a Request for Feature Enhancement for this:
RFE: 647973 RFE: Allow a different access policy to be run on a layered virtual for traffic that comes in over a VPN tunnel


Recommended Actions

In order to work around this limitation you need to ensure that the layered Virtual server is not accessed via the network access tunnel.
