Issue

Starting in FirePass 6.0.3 and in FirePass 6.0.2 with Cumulative Hotfix HF-602-6, the Portal Access reverse-proxy engine supports the HTTP/1.1 protocol for communicating with back-end web application servers. Previously, the Portal Access reverse-proxy engine only supported the HTTP/1.0 protocol for communicating with back-end web application servers.

Note: The Portal Access reverse-proxy engine supports both the HTTP/1.0 and HTTP/1.1 protocols for client (front-end) requests with no additional hotfix required.
 
By default, back-end HTTP/1.1 support is not enabled in the reverse-proxy engine. To enable back-end HTTP/1.1 support in the reverse-proxy engine, perform the  following procedure:
  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Portal Access : Web Applications : Content Processing page.
  3. Click the Global Settings tab.
  4. In the Web Applications Global Settings section, select the Enable HTTP/1.1 support for back-end requests check box.
  5. Click the service restart link at the top of the page.
  6. Click the Restart button to restart the FirePass services.
 
Note: For more information about HTTP/1.1, refer to RFC2616.
 
F5 Product Development tracked this enhancement as CR44141. For information about upgrading, refer to the FirePass Release Notes.

Additionally, Cumulative Hotfix HF-602-6 has been issued for FirePass 6.0.2. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads site.
