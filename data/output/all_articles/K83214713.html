Description

You have added a URL to the Disallowed URL list in an ASM security policy, but the URL is not being blocked.

The configured disallowed URL is similar to the following:

/dev/testing/ApplicationAPI?name=ferret&color=purple&admin=1

However, you would still like to allow:

/dev/testing/ApplicationAPI?name=ferret&color=purple&admin=0

In this case, the specific portion of the URL you want to block is:

admin=1

You want to allow:

admin=0

Environment

  • Security Policy
  • Disallowed URL list

Cause

The configured URL to block is incorrect. The portion that should be disallowed is actually a parameter, that is part of the query string:

name=ferret&color=purple&admin=0

Note: The question mark in the original URL is a separator and not considered part of the query string.

In our example, the individual parameter is:

admin

The value of that parameter is:

1

The ASM URL is simply:

/dev/testing/ApplicationAPI

Recommended Actions

Remove the incorrect URL from the Disallowed URL list, then configure a Parameter instead.

When configuring a parameter, you must specify acceptable values for the parameter, such as a set of static values, user-input values, and so on.

In our example, if the only acceptable values for the application are 0 or 1, and you want to disallow 1, you configure a parameter so that the only acceptable value is 0.

You must also ensure that the relevant illegal parameter value violation is set to block in the Learning and Blocking Settings. The exact violation depends on which Parameter Value Type you use when configuring the parameter itself.

Additional Information

ASM considers a URL the requested directory and filename.

For example, this is considered an ASM URL:

/forum/questions/page.php

Whereas only part of this example is considered an ASM URL:

/app/auth/login?username=ferret&color=green
