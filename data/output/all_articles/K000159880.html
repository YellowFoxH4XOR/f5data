K000159880: SSLO Explicit Proxy Sends Premature Server-Side SYN Causing "F5RST: Detaching server side before server connect" Error

Type
Support Solution
Published
2026-02-04
Updated
2026-02-05
Applies to
  • F5 App Protect
  • BIG-IP SSL Orchestrator: 17.5.0
Source
https://my.f5.com/manage/s/article/K000159880

Description

When using BIG-IP SSL Orchestrator (SSLO) in explicit proxy mode, the system may send RST packets to destination servers with the error message "F5RST: Detaching server side before server connect" logged in the LTM logs. This behavior occurs when:

  • BIG-IP SSLO initiates a server-side TCP connection (sends SYN) before receiving and processing the Client Hello message containing the Server Name Indication (SNI) from the client
  • The SSLO security policy subsequently determines the connection should be rejected (e.g., destination not whitelisted)
  • Downstream security devices (such as firewalls) may flag these RST packets as "out-of-state" traffic and drop the connections

Error message observed in LTM logs:

01230140:3: RST sent from <source_ip>:<source_port> to <dest_ip>:443, [flow_id] Detaching server side before server connect

Packet capture shows the following sequence:

  • BIG-IP sends SYN to destination server
  • Client Hello with SNI arrives on client-side connection
  • BIG-IP sends RST to destination server before completing the three-way handshake

Environment

  • BIG-IP SSLO version 17.5.0 (behavior may occur in other versions)
  • Platform: BIG-IP platforms
  • Configuration:
    • SSLO explicit proxy topology deployment
    • SSLO security policy with URL category-based filtering
    • Destinations not included in the whitelist/allowed list

Cause

This is a design behavior in BIG-IP SSLO explicit proxy where the system initiates server-side connections before receiving and processing the Client Hello from the client-side connection. When SSLO subsequently evaluates the security policy and determines the connection should be rejected, it terminates the prematurely-initiated server-side connection with an RST packet. In most cases, establishing the server-side connection as early as possible can be considered an optimization however this early server-side connection attempt is unnecessary and has been identified as requiring a design change (RFE - Request for Enhancement).

Answer/Recommended Actions

This is a known design limitation with no immediate workaround to prevent the early server-side connection behavior in SSLO explicit proxy topology. Consider the following actions:

  1. Adjust downstream security device policies (temporary measure):
    • If RST packets are causing significant issues with downstream security devices, consider adjusting connection tracking policies to accommodate this BIG-IP behavior
    • Consult with your security device vendor for appropriate configuration changes.

Additional Information

Expected behavior:

  • In SSLO explicit proxy topology, BIG-IP may initiate server-side connections before fully processing client-side SSL/TLS handshake information
  • This behavior is by design but has been identified for improvement in future releases

Packet capture analysis:

  • The server-side SYN is sent before the Client Hello is received on the client-side connection
  • The RST is sent after SSLO processes the Client Hello and determines the connection should be rejected based on security policy
  • The time delta between SYN and RST is typically less than 2 milliseconds
