K000161386: Issue with Origin Server Port 80 Not Working with Virtual IP

Support Solution
Published
2026-05-22
Updated
2026-05-26
Applies to
  • BIG-IP

Source
https://my.f5.com/manage/s/article/K000161386

Description

In a new BIG-IP LTM deployment, web traffic to a virtual server listening on port 8012 (proxying to origin servers on port 80) returned a "Website not found – domain name not bound to website" error from the backend Nginx/aaPanel web servers. The issue was caused by an HTTP Host header mismatch between what the client sent and what the Nginx virtual host expected. A port 443 virtual server on the same device was functioning normally.

"Website not found

Sorry, Please confirm that this domain name has been bound to your website.
"

Environment

  • BIG-IP LTM, version 17.5.1, platform F5-BIG-BR-R5600
  • Active/Standby HA pair; issue observed only on the Active device
  • Virtual server configured with HTTP and TCP profiles, SNAT automap, translate-port enabled, listening on port 8012, forwarding to pool members on port 80
  • Two pool members (nginx/aaPanel web servers) in an active-active pool
  • An iRule using HTTP_REQUEST_SEND with clientside context was attached to the virtual server to rewrite the HTTP Host header

Cause

The root cause was a misconfigured iRule that used the HTTP_REQUEST_SEND event with a clientside { } context block to rewrite the HTTP Host header. The clientside context within HTTP_REQUEST_SEND applies to the client-facing side of the connection, not the server-side request being forwarded to the pool member. As a result, the Host header sent to the Nginx/aaPanel pool members retained the original client value:8012(the VIP address and client-facing port) rather than a hostname or IP matching the Nginxserver_name` directive.

(Host: 10.xx.xx.xx:8012), which did not match the server_name configured in the Nginx virtual host, causing the "Website not found" error. The correct approach is to use the HTTP_REQUEST event without a clientside context to rewrite the Host header on the server-bound request.

 

ltm rule /Common/HTTP_REQUEST_SEND {
when HTTP_REQUEST_SEND {
      clientside {
           # Force the host header to match what aaPanel expects
          HTTP::header replace Host "10.xxx.xx.xx"
  }
   }
}

Answer/Recommended Actions

Replace the existing iRule with one using the HTTP_REQUEST event (not HTTP_REQUEST_SEND) and without a clientside { } context block to correctly rewrite the Host header on the server-side request:


when HTTP_REQUEST {

HTTP::header replace Host "the-exact-server_name-from-nginx"

}

On each Nginx/aaPanel pool member, verify the exact server_name value configured in the virtual host:

 

grep -r "server_name" /www/server/panel/vhost/nginx/

 

Ensure the Host value used in the iRule exactly matches the server_name directive in the Nginx vhost configuration (use a domain name, not an IP address, if Nginx is configured with a domain).

For an active-active pool, ensure both pool members have the same server_name configured in their nginx vhosts, or use a per-member Host rewrite with LB::server addr in the HTTP_REQUEST event if different hostnames are required.

Confirm pool members are listening on port 80, as BIG-IP handles port translation from 8012 to 80 via translate-port enabled.
