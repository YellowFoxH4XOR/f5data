Topic

A pre-logon sequence can contain an external logon page action that redirects users to an external server with two HTTP POST variables. The two variables are client_data and post_url. The client_data variable contains encoded results of the pre-logon inspection. The post_url variable contains the URL that the external logon page must use as the form's action attribute.

In order to use this feature, the HTML form on the external page must use the POST method and send the following variables:

  • client_data
  • username
  • password
  • tzoffsetmin=1
  • mrhlogonform=1

As a security precaution, the value of the client_data variable can only be submitted to FirePass once. To prevent potential spoofing attempts, F5 recommends that you ensure that the value of the post_url variable matches a valid hostname or IP address of the FirePass controller.

The following example shows an external logon page written in PHP and HTML:

<?php

  // verify post_url is valid
  if(!preg_match("/^(http[s]?:\/\/)([^\/\<\>]+)\/([^\<\>]*)$/i", $_POST["post_url"], $host)) {
    echo(htmlentities($_POST["post_url"]).' is not a valid URL');
    exit;
  }
  // only POST to our firepass
  if ($host[2] != "10.10.190.10") {
    echo(htmlentities($host[2]). ' is not an authorized FirePass host.');
    exit;
  }
php?>

<!-- display a form with username and password fields that POST back to FirePass -->
<html><body>
<form action="<? echo(htmlentities($_POST["post_url"])) ?>" method="post">
  <input type="hidden" name="client_data" value="<?echo(htmlentities($_POST["client_data"])); ?>">
  <input type="hidden" name="mrhlogonform" value=1>
  <input type=”hidden” name=”tzoffsetmin” value=1>
  Username: <input type="text" name="username"><BR>
  Password: <input type="text" name="password">
  <input type="submit" value="login">
</form>
</body></html>

Performing client remediation

You can also use the external logon page to remediate client issues that may occur during a pre-logon inspection. To decode the client_data POST variable, set the form's action attribute to the https://firepass/admin/decodeClientData.php3 URL. This URL returns the decoded client_data variable in an XML format for parsing.

An example pre-logon sequence could require users to have a client SSL certificate, antivirus, firewall and the notepad.exe process before access is granted. In this sample scenario, the following code sample determines why the client failed the pre-logon inspection. The sample could be further extended to inform the user how to correct their inadequacies and provide instructions or contact information. The external logon can be combined with remediation, but the value of client_data that is sent to my.activation.php3 must be the new value decodeClientData.php3 provides in the XML:

<?php
  // verify post_url is valid
  if(!preg_match("/^(http[s]?:\/\/)([^\/\<\>]+)\/([^\<\>]*)$/i", $_POST["post_url"], $host)) {
    echo(htmlentities($_POST["post_url"]).' is not a valid URL');
    exit;
  }
  // only POST to our FirePass
  if ($host[2] != "10.10.190.60") {
    echo(htmlentities($host[2]). ' is not an authorized FirePass host.');
    exit;
  }

  $client_data = $_POST["client_data"];
  $post_url = $_POST["post_url"];

  // request pre-logon data for the session's client_data
  $fp = fsockopen("ssl://".$host[2], 443, $errno, $errstr, 30);
  if (!$fp) {
    echo $errno . $errstr;
  } else {
       $data = "client_data=$client_data";
    $out = "POST /admin/decodeClientData.php3 HTTP/1.0\r\n";
    $out .= "Host: $host[2]\r\n";
    $out .='Content-type: application/x-www-form-urlencoded'."\r\n";
    $out .='Connection: close'."\r\n";
      $out .="Content-Length: ".strlen($data)."\r\n";
      $out .="\r\n";
      $out .="$data";

    fwrite($fp, $out);
    $xml = stream_get_contents($fp);
    fclose($fp);
  }
 
  // separate xml from http headers and parse the returned xml
  $chunks = split ("\r\n\r\n", $xml);
  $parser = new SimpleXMLElement($chunks[1]);

  if ($parser->session->ssl->cert->exist==0) {
      print('No SSL Certificate');
  } else if ($parser->session->ssl->cert->valid==0) {
      print('Invalid Certificate');
  } else if ($parser->session->av->summary->count==0) {
      print('No AntiVirus software installed');
  } else if ($parser->session->av->summary->monitor==0) {
      print('AntiVirus software is disabled');
  } else if ($parser->session->fw->summary->count==0) {
      print('No Firewall software installed');
  } else if ($parser->session->fw->summary->enabled==0) {
      print('Firewall software is disabled');
  } else if ($parser->session->process_check->proc_check250->result==0) {
      print('Computer does not comply with system process check 250: notepad.exe must be running');
 }
php?>

FirePass returns XML containing three second-level elements:

  • <result>

    Contains code and description of client_data decode result, 0=success
  • <session>

    Contains data collected during pre-logon inspection
  • <client_data>

    Contains a new value for client_data
