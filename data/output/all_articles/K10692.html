Known Issue

This is the result of a known issue. When using a place-rule to migrate files and directories for a managed volume, the volume scan status may stall in a Scanning state during the migration and fail to complete. This issue may occur when the place-rule is paused or changed during times of heavy migration in the volume.

When this issue occurs, the show policy details command will display the following volume scan status for the place-rule as Scanning.

For example: 

   Place Rule:       toS2                                             
                                                                      
     Configuration:                                                   
       From fileset:                              AllFiles (files only)
       Target share:                              s2                  
       Migrate limit:                             0                   
       Volume Scan:                               Enabled             
       Inline Notifications:                      Enabled             
       Promote Directories:                       Disabled            
       Auto-Close Files:                          Disabled            
                                                                      
       Tentative:                                 No                  
       State:                                     Enabled             
                                                                      
     Status:                                                          
       Volume Scan Status:                        Scanning (1%)
       File Migration Status:                     Migrating           

F5 Product Development tracked this issue as ARX ID 34856 and 36275 and it was fixed in version 3.2.2 for the 3.x software branch, and in version 4.1.1 for the 4.x software branch. For information about upgrading, refer to the ARX release notes.

This issue was fixed in hotfix Build-11738 for ARX version 5.0.5 for the 5.x software branch. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.

Workaround

You can work around this issue by restarting the place-rule's volume scan and restarting the volume's namespace. To do so, perform the following procedure:

  1. Log in to the ARX command line.
  2. Enable privileged mode by typing the following command:

    enable

    The prompt will appear similar to the following example:

    [hostname]
  3. Restart the volume's namespace by typing the following command:

    restart namespace <Namespace> volume <Volume_Name>

    The prompt will appear similar to the following example:

    Do you wish to restart the VPU domain hosting
    namespace 'namespace', volume '/vol'? [yes/no]
  4. Confirm that you want to restart the volume's namespace by typing the following:

    yes
  5. After the volume's namespace restarts, verify the volume scan status by typing the following command:

    show policy details
