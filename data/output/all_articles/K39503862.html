K39503862: HTTP 500 Error when opening BIG-IP APM policies after upgrade due to PHP Memory exhaustion

Type
Support Solution
Published
2025-12-30
Updated
2026-01-20
Applies to
  • BIG-IP
  • BIG-IP APM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K39503862

Description

After upgrading BIG-IP APM to version 17.5.1.3, attempts to open APM policies containing a large number of resources result in the following error:

  • Error Message: "Server request for 'editActionDialogue' failed: Request status = 500"
  • Log Entry: "PHP Fatal error: Allowed memory size of 134217728 bytes exhausted (tried to allocate 36 bytes) in /var/sam/www/admin/vpe2/private/php/include/agentProperties""

Environment

  • APM policies with a large number of resources in Advanced Resources Assign agent
  • Issue occurs after upgrading to version 17.5.1.3

Cause

The default PHP memory_limit parameter (128MB) for the VPE process is insufficient to handle policies with a large number of resources. After the upgrade to version 17.5.1.3, the increased complexity or size of the policies causes the PHP process to exceed its memory allocation, resulting in a fatal error and HTTP 500 response when attempting to edit the policy.

 

Recommended Actions

Increase the PHP memory_limit parameter to allow the VPE process to handle larger policies:

Important: Perform these changes during a maintenance window to avoid service disruption.

 

  1. SSH to your BIG-IP system
  2. Remount /usr as read-write: 
    mount /usr -o rw,remount
  3. Edit the PHP configuration file (typically "/usr/local/www/php.ini or similar)
  4. Locate the line: 
    memory_limit = 128M
  5. Change it to a higher value: 
    memory_limit = 256M
    (or higher if needed, such as 512M)
  6. Save the file
  7. Restart the httpd service: 
    bigstart restart httpd

 

Additional Information

  • The error occurs only when opening policies with a large number of resources, not for all policies.
  • The PHP process exhausts memory during the policy loading or editing operation in the Visual Policy Editor.
  • After applying the memory limit increase, the affected policies should open successfully without the HTTP 500 error.
