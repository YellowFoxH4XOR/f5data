Topic

You should consider using this procedure under the following condition:

  • You want to configure the Spanning Tree Protocol (STP), Rapid Spanning Tree Protocol (RSTP) or Multiple Spanning Tree Protocol (MSTP) on the F5 r5000/r10000/r12000 hardware products using REST API.

Description

The three industry-standard spanning tree protocols namely STP (802.1d), RSTP (802.1w) and MSTP (802.1s) are supported on F5 r5000/r10000/r12000 hardware products; the r2000/r4000 hardware products do not support these spanning tree protocols.

The following settings are relevant to the three spanning tree protocols:

SettingsSTPRSTPMSTP
Region NameNot applicableThe name of a spanning tree region. A spanning tree region is a group of bridges with identical region name, MSTP revision number and VLANs assignment. The default is the bridge MAC address.
RevisionNot applicableA global revision number assigned to all bridges in a spanning tree region. The default value is 0 and valid range is 0 to 65535.
Max HopNot applicableThe maximum number of hops a spanning tree bridge protocol data unit (BPDU) can traverse before it is discarded. The default value is 20; valid range is 1 to 255.
Hello TimeThe time interval in seconds that the system transmits spanning tree information through BPDUs to adjacent bridge in the network. The range of valid value is 1 to 10.
  • For STP, the default value is 2.
  • For RSTP, the default value is 4.
  • For MSTP, the default value is 2.
Max AgeThe length of time in seconds that spanning tree information received from other bridges is considered valid. The range of valid value is 6 to 40.
  • For STP, the default value is 20.
  • For RSTP, the default value is 25. You should maintain this value for RSTP using the following formulas:
    • Max Age >= 2 * (Hello Time + 1)
    • Max Age <= 2 * (Forward Delay - 1)
  • For MSTP, the default value is 20.
Forwarding DelayThe amount of time in seconds that the system blocks an interface from forwarding network traffic when the spanning tree algorithm reconfigures a spanning tree. The range of valid value is 4 to 30. This has no effect when all the bridges in the network are running RSTP or MSTP.
  • For STP, the default value is 15.
  • For RSTP, the default value is 20.
  • For MSTP, the default value is 15.
Hold CountThe maximum number of spanning tree frames (BPDUs) that the system can transmit on a port within the Hello Time interval. The range of valid value is 1 to 10. The default value is 6 for all three protocols.
Instance IDNot applicableIdentification number (positive integer) for an MSTP instance.
VLANsNot applicableVLANs assigned to an MSTP instance.
Bridge PriorityThe bridge with the lowest relative priority becomes the root bridge. The root bridge is responsible for managing loop resolution on the network. The default value is 32768; valid range is 0 to 61440 in multiples of 4096. You should configure an appropriate value such that the F5 rSeries system never becomes the root bridge.
For MSTP, the bridge priority is specific to each configured MSTP instances and can only be configured at the instance level.
InterfacesSelect the interfaces and LAGs one at a time for which you want to configure the spanning tree protocol.
Interfaces - CostThe cost of sending spanning tree traffic through the interface to an adjacent bridge or spanning tree region based on the speed of the interface. The default value is 0 and valid range is 0 to 200000000.
Interfaces - Port PriorityThe port identifier used together with the port number. The default value is 128 and valid range is 0 to 240 in multiples of 16.
Interfaces - Edge PortWhen it is set to EDGE-ENABLE, it indicates the interface or LAG is an edge port that does not receive any BPDU. If the interface subsequently receives BPDU, the system disables the setting automatically because only non-edge interfaces can receive BPDUs. This setting is only needed for RSTP or MSTP. The valid values are EDGE-AUTO, EDGE-ENABLE and EDGE-DISABLE.
Interfaces - Link TypeThis setting specifies the type of optimization:
  • P2P: Optimizes for a point-to-point spanning tree link that connects two spanning tree bridges. Note that P2P is the only valid STP link type for a LAG.
  • Shared: Optimizes for a shared spanning tree link that connects two or more spanning tree bridges.

For information on how to configure them using the webUI and CLI, refer to the Spanning tree protocol (STP) overview section of the Network Settings chapter of the F5 rSeries Systems: Administration and Configuration guide.

Important: You cannot enable spanning tree protocols on individual link aggregation group (LAG) members; LAG is a logical group of interfaces that function as a single interface, like a trunk. Additionally, you cannot enable spanning tree protocols on interfaces that are configured as virtual networks.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the management interface of the F5 r5000/r10000/r12000 hardware products.
  • You should have a workstation with curl and jq utilities installed. If you do not have one, you can login to the F5 r5000/r10000/r12000 command line as the root user to use the curl and jq utilities as needed.

Enabling the spanning tree protocol on the r5000/r10000/r12000

To enable the spanning tree protocol on the r5000/r10000/r12000, perform the following procedure:

Impact of procedure: Enabling spanning tree protocol on your application network may cause a momentary disruption to your network while the spanning tree algorithm is performing its calculation. F5 recommends performing this change during an appropriate maintenance window.

  1. Login to the workstation that has the curl and jq utilities installed.
  2. To determine if the system is already enabled with spanning tree protocol, enter the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/global

    If the system is not enabled with spanning tree protocol, the command should not return any output.

  3. To enable the system with spanning tree protocol, enter the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X POST https://<management ip address>/api/data/openconfig-spanning-tree:stp/global/config -d '{"enabled-protocol": "[STP|RSTP|MSTP]"}'

    For example, you would enter the following command if you want to enable RSTP on the system:

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X POST https://localhost/api/data/openconfig-spanning-tree:stp/global/config -d '{"enabled-protocol": "RSTP"}'

    Note: This command syntax does not return any output. You would need to perform the next step to verify.

  4. When you have enabled the spanning tree protocol you want on the system, enter the command in step 2 to verify that it has been enabled. You should see an output similar to the following example:

    {
      "openconfig-spanning-tree:global": {
        "config": {
          "enabled-protocol": ["openconfig-spanning-tree-types:RSTP"]
        },
        "state": {
          "enabled-protocol": ["openconfig-spanning-tree-types:RSTP"]
        }
      }
    }

Modifying the spanning tree protocol settings on the r5000/r10000/r12000

To modify the spanning tree protocol on the r5000/r10000/r12000, perform the following procedure:

Impact of procedure: Modifying the spanning tree protocol settings may cause a momentary disruption to your network while the spanning tree algorithm is performing its calculation. F5 recommends performing this change during an appropriate maintenance window.

  1. Login to the workstation that has the curl and jq utilities installed.
  2. To determine the existing values for the spanning tree protocol settings, enter the following command syntax applicable to the spanning tree protocol:
    • STP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/f5-openconfig-spanning-tree:stp

    • RSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/openconfig-spanning-tree:rstp

    • MSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/openconfig-spanning-tree:mstp

    For example, you would enter the following command to determine the existing values for the RSTP settings:

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' https://localhost/api/data/openconfig-spanning-tree:stp/openconfig-spanning-tree:rstp

    • RSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X PATCH https://<management ip address>/api/data/openconfig-spanning-tree:stp/openconfig-spanning-tree:rstp/config -d '{"config": { "hello-time": <value>, "max-age": <value>, "forwarding-delay": <value>, "hold-count": <value>, "bridge-priority": <value> } }'

    • MSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X PATCH https://<management ip address>/api/data/openconfig-spanning-tree:stp/openconfig-spanning-tree:mstp/config -d '{"config": { "name": <region name>, "revision": <value>, "max-hop": <value>, "hello-time": <value>, "max-age": <value>, "forwarding-delay": <value>, "hold-count": <value> } }'

Configuring an MST instance on the r5000/r10000/r12000

This procedure is only applicable if you have enabled MSTP on the r5000/r10000/r12000 and you want to configure a new MST instance. To do so, perform the following procedure:

Impact of procedure: Configuring a new MST instance may cause a momentary disruption to your network while the spanning tree algorithm is performing its calculation. F5 recommends performing this change during an appropriate maintenance window.

  1. Login to the workstation that has the curl and jq utilities installed.
  2. To configure a new MST instance, enter the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X POST https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances -d '{"mst-instance": [{"mst-id": <value>, "config": {"mst-id": <value>, "vlan": [<value>, <value>,...], "bridge-priority": <value>}},...]}'

    For example, you would enter the following command to configure a single MST instance with ID 1 that comprises of VLANs 1448, 1328, 188:

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X POST https://localhost/api/data/openconfig-spanning-tree:stp/mstp/mst-instances -d '{"mst-instance": {"mst-id": 1, "config": {"mst-id":1, "vlan": [1448, 1328, 188], "bridge-priority": 32768}}}'

    In another example, you would enter the following command to configure two MST instances; ID 1 that comprises of VLANs 1448 and 1328 while ID 2 that comprises of VLAN 188:

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X POST https://localhost/api/data/openconfig-spanning-tree:stp/mstp/mst-instances -d '{"mst-instance": [{"mst-id": 1, "config": {"mst-id": 1, "vlan": [1448, 1328], "bridge-priority": 32768}}, {"mst-id": 2, "config": {"mst-id": 2, "vlan": 188, "bridge-priority": 32768}}]}'

    Note: This command syntax does not return any output. You would need to perform the next step to verify.

  3. To verify the newly-configured MST instance(s), enter the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances/mst-instance=<ID>

Configuring interfaces for the spanning tree protocol on the r5000/r10000/r12000

To configure an interface for the spanning tree protocol, perform the following procedure:

Impact of procedure: Configuring an interface for the spanning tree protocol may cause a momentary disruption to your network while the spanning tree algorithm is performing its calculation. F5 recommends performing this change during an appropriate maintenance window.

  1. Login to the workstation that has the curl and jq utilities installed.
  2. To configure an interface for the spanning tree protocol, enter the following command syntax applicable to the spanning tree protocol:
    • STP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X POST https://<management ip address>/api/data/openconfig-spanning-tree:stp/f5-openconfig-spanning-tree:stp/interfaces -d '{"interface": [{"name": <interface number>, "config": {"name": <interface number>, "cost": <value>, "port-priority": <value> } },...]}'

    • RSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X POST https://<management ip address>/api/data/openconfig-spanning-tree:stp/rstp/interfaces -d '{"interface": [{"name": <interface number>, "config": {"name": <interface number>, "cost": <value>, "port-priority": <value>}},...]}'

    • MSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X POST https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances/mst-instance=<ID>/interfaces -d '{"interface": [{"name": <interface number>, "config": {"name": <interface number>, "cost": <value>, "port-priority": <value>}},...]}'

    For example, you would enter the following command to configure interfaces 19.0 and 20.0 for RSTP:

    curl -sku admin:admin -H 'Content-Type: application/yang-data+json' -X POST https://localhost/api/data/openconfig-spanning-tree:stp/rstp/interfaces -d '{"interface": [{"name": "19.0", "config": {"name": "19.0", "cost": 200, "port-priority": 128}},{"name": "20.0", "config": {"name": "20.0", "cost": 400, "port-priority": 128}}]}'

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' https://<management ip address>/api/data/openconfig-spanning-tree:stp/f5-openconfig-spanning-tree:stp/interfaces

Removing spanning tree protocol configuration on the r5000/r10000/r12000

To remove the current spanning tree protocol configuration, you must first remove the interfaces configured for the protocol followed by disabling the spanning tree protocol itself. To do so, perform the following procedure:

Impact of procedure: Removing spanning tree protocol configuration may cause a momentary disruption to your network while the spanning tree algorithm is performing its calculation. F5 recommends performing this change during an appropriate maintenance window.

  1. Login to the workstation that has the curl and jq utilities installed.
  2. Remove the edge-port and link-type configuration for the interfaces by entering the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/interfaces

  3. Next, remove the interfaces from the spanning tree protocol by entering the following command syntax appropriate for the spanning tree protocol:
    • STP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/f5-openconfig-spanning-tree:stp/interfaces

    • RSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/rstp/interfaces

    • MSTP:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances/mst-instance=<ID>/interfaces

  4. If you have configured MSTP, you should remove the MSTP instance(s). To do so, enter the following command syntax:
    • Removing a single instance one at a time:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances/mst-instance=<ID>

    • Removing all instances at the same time:

      curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/mstp/mst-instances

  5. Finally, disable the global spanning tree configuration by entering the following command syntax:

    curl -sku <admin user name>:<admin user password> -H 'Content-Type: application/yang-data+json' -X DELETE https://<management ip address>/api/data/openconfig-spanning-tree:stp/global/config
