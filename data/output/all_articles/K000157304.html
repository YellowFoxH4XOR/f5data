K000157304: Connection limit does not enforce connection limits on pool members when OneConnect Profile is applied

Description

This article explains the behavior of connection limits for pool members in F5 BIG-IP environments when OneConnect profiles are used. You may notice that the number of active connections to a pool member exceeds the configured connection limit (for example, a limit of 1500 may result in 1600–1700 connections). This can cause confusion about whether connection limits are being properly enforced. Log messages such as "Warning, pool member IP <IP> port <port> for pool <pool> has reached its connection limit" may be observed, indicating that limits are being hit, but actual connection counts may still surpass the set values.

Environment

  • OneConnect Profile
  • Connection Limit
  • Pool Member
  • Node

Cause

The default configuration of the OneConnect profile is responsible for this behavior. When "Limit Type" is set to "None," OneConnect does not enforce connection limits on pool members, resulting in possible overages beyond configured thresholds. This is expected unless the profile's enforcement setting is changed.

Recommended Actions

To ensure proper enforcement of connection limits on pool members when using OneConnect profiles:

  1. Edit the relevant OneConnect profile assigned to your virtual server.
  2. Change the "Limit Type" from "None" to either:
      • Idle: Drops an idle connection when a new one comes in and the limit is reached.
      • Strict: Resets connections if a pool member reaches its limit, even if other members have capacity (may impact traffic flow).
  3. Save your changes and monitor active connections per pool member to confirm correct enforcement.
  4. Test these changes in a non-production environment before deploying them into production.
