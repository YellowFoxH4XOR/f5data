Topic

The BIG-IP Analytics and denial-of-service Layer 7 (DoS L7) modules may utilize up to 10 percent of physical memory when you provision both modules.

Description

When you provision the BIG-IP Analytics and DoS L7 modules together on the BIG-IP system, the system allocates up to 10 percent of physical memory to the avrd and dosl7d processes. This is expected behavior.

For the BIG-IP Analytics and DoS L7 modules, the system allocates large memory pages (HugeTlbFS) to the avrd and dosl7d processes to improve CPU performance store and share data between the daemons. The size of the HugeTlbFS structure is based on the total system memory of the platform and provisioned features. You can better understand the large pre-allocation of shared memory pages to avrd and dosl7d using the following Linux utilities:

# top -cb

PID   USER      PR  NI  VIRT   RES  SHR S %CPU %MEM    TIME+   COMMAND
30825 root      20   0  3094m  32m  18m S  2.3  0.1    0:00.08 /usr/bin/avrd -t 300

  • The VIRT memory size listed includes the memory mapped HugeTlbFS allocation, while the RES memory size does not. The VIRT size indicates the virtual size of the process (the sum of memory that the process is actually using), which includes memory mapped into itself, files on disk that have been mapped into memory (for example, shared libraries), and memory shared with other processes. The VIRT value is the sum total of all theoretical memory that the process can access at the current moment. Therefore, the VIRT size in the top output (or the VSZ size in the ps aux output) may not always be an accurate representation of memory leakage or actual memory utilization.
  • The RES size listed is the resident size of the program, which is an accurate representation of how much actual physical memory a process is currently consuming.
