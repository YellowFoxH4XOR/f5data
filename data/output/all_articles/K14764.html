Issue

You should consider using this procedure under the following condition:

  • You suspect possible hardware issues on the VIPRION backplane.

Symptoms

As a result of hardware issues on the VIPRION backplane, you may encounter the following symptoms:

  • The VIPRION blades fail to communicate through the backplane.
  • The configuration between the VIPRION blades in the cluster fails to synchronize.
  • The system reports that an internal interface on the backplane for a slot that has a blade installed is down or uninitialized.

    Important: The expected behavior is that, when a slot does not have a blade, it reports the internal interfaces for that slot as uninitialized with no media settings. When you initialize a cluster with multiple blades, the internal interfaces on the blades display as uninitialized, even when you subsequently remove the secondary blades. When you initialize a cluster with one or more empty slots, the internal interfaces for those blades do not display at all. For example, when you initialize a Viprion C2400 with two blades in the chassis, and you subsequently remove the second blade, 1/5.1 displays as down, while 2/5.1 displays as uninitialized. For information about internal interfaces mapping, refer to K13306: Overview of the manner in which the VIPRION chassis and blades interconnect.

  • The system reports the incorrect media settings for an internal interface for a slot with a blade that is located on the backplane.

Recommended Actions

The blades installed in a VIPRION chassis communicate through the internal interfaces on the chassis backplane. When a hardware issue occurs on the VIPRION backplane, the blades may not function properly as a cluster and affect traffic processing. You can troubleshoot and determine whether you have a hardware issue by performing the procedures in the Procedures section.

Procedures

When you experience possible hardware issues on the VIPRION backplane, use the following troubleshooting steps to determine the root cause:

  • Verifying the status and speed of the internal interfaces
  • Determining whether switches on corresponding blades are communicating properly over the back plane
  • Reseating the suspect blade
  • Rebooting the VIPRION chassis
  • Running the EUD on the VIPRION blade
  • Switching the suspect blade between slots

Verifying the status and speed of the internal interfaces

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected VIPRION chassis.
  2. Display the internal interfaces on the backplane by typing the appropriate command for your VIPRION chassis:

    VIPRION 4800 chassis

    tmsh show net interface all-properties -hidden | grep "[1-8]\/[56]\.[1-7]"

    VIPRION 4400 chassis

    tmsh show net interface all-properties -hidden | grep "[1-4]\/[56]\.[5-7]"

    VIPRION 2400 chassis

    tmsh show net interface all-properties -hidden | grep "[1-4]\/5\.[123]"

    VIPRION 2200 chassis

    tmsh show net interface all-properties -hidden | grep "[12]\/5\.[123]"

  3. Verify the list of internal interfaces and determine if an internal interface is reported as down or uninitialized.

    Important: The expected behavior is that, when a slot does not have a blade, it reports the internal interfaces for that slot as uninitialized with no media settings. When you initialize a cluster with multiple blades, the internal interfaces on the blades display as uninitialized, even when you subsequently remove the secondary blades. When you initialize a cluster with one or more empty slots, the internal interfaces for those blades do not display at all. For example, when you initialize a Viprion C2400 with two blades in the chassis, and you subsequently remove the second blade, 1/5.1 displays as down, while 2/5.1 displays as uninitialized. For information about internal interfaces mapping, refer to K13306: Overview of the manner in which the VIPRION chassis and blades interconnect.

    For example, the following output from a VIPRION 2400 chassis reports that internal interface 1/5.1 is uninitialized, while its corresponding peer interface 2/5.1 is down. This output indicates a possible hardware issue with the chassis backplane or blade 1 internal interface:

    1/5.1 uninit 0:1:d7:56:22:11 2048 66.2M 4.5G 77 840.8K 0 839.7K 0 0 0 0 0 20000T-FD tx-rx none detached
    1/5.2 up 0:1:d7:56:22:12 2048 61.0K 4.6G 94 949.7K 0 839.7K 0 0 0 0 0 20000T-FD tx-rx none detached
    1/5.3 up 0:1:d7:56:22:13 2048 23.0G 5.0G 17.9M 1.2M 17.5M 839.7K 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.1 down 0:1:d7:56:22:89 2048 0 22.2G 0 17.5M 0 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.2 up 0:1:d7:56:22:8a 2048 5.0G 23.0G 852.1K 17.9M 839.7K 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.3 up 0:1:d7:56:22:8b 2048 66.2M 22.2G 0 17.5M 0 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached

  4. If the system does report any internal interface as down or uninitialized, verify the list and determine if the system is reporting an internal interface with the incorrect media settings.

    For example, the following output from a VIPRION 2400 chassis reports that internal interface 1/5.1 has its media setting set to 2000T-FD instead of 20000T-FD. This output indicates a possible hardware issue with the chassis backplane or blade 1 internal interface:

    1/5.1 up 0:1:d7:56:22:11 2048 66.2M 4.5G 77 840.8K 0 839.7K 0 0 0 0 0 2000T-FD tx-rx none detached
    1/5.2 up 0:1:d7:56:22:12 2048 61.0K 4.6G 94 949.7K 0 839.7K 0 0 0 0 0 20000T-FD tx-rx none detached
    1/5.3 up 0:1:d7:56:22:13 2048 23.0G 5.0G 17.9M 1.2M 17.5M 839.7K 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.1 up 0:1:d7:56:22:89 2048 0 22.2G 0 17.5M 0 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.2 up 0:1:d7:56:22:8a 2048 5.0G 23.0G 852.1K 17.9M 839.7K 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached
    2/5.3 up 0:1:d7:56:22:8b 2048 66.2M 22.2G 0 17.5M 0 17.5M 0 0 0 0 0 20000T-FD tx-rx none detached

  5. If any of the internal interfaces report a status of down or uninitialized, or an incorrect media setting compared to the rest of the internal interfaces, proceed to the procedure Reseating the suspect blade.

Procedure back out: None

Determining whether switches on corresponding blades are communicating properly over the back plane

The status for a given internal interface should be reported as up only when media is present, which is indicated by speed and duplex settings being reported for that interface, under Media. For example, the following partial output from a VIPRION 4400 chassis reports normal operation for internal interfaces 2/5.6 and 2/5.7. Note that 2/5.6 Status is up and Media is 10000T-FD, while 2/5.7 Status is down and Media is none:

Note: If no media is present (Media is reported as none), and status is reported as up, this is an indication that the switches on the corresponding blades are not communicating properly.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected VIPRION chassis.
  2. To display any internal interfaces with a status of up, but without media, enter the following command:

    tmsh show /net interface all-properties -hidden | awk '$1~/\/(5|6)\./ && $16=="none" && $2=="up" {print $1,$2,$16,$17}'

    The output with a faulty blade in either slot 1 or slot 7 would look like the following example:

    1/5.5 up none tx-rx
    7/5.4 up none tx-rx

    Note: If there is no output from this command, then there are no internal interfaces reporting mismatched Status and Media.

  3. If any of the internal interfaces report its status as up with a media setting of none, proceed to the procedure Reseating the suspect blade, following.

Procedure back out: None

Reseating the suspect blade

When you have determined the suspect blades, you may proceed to reseat the blades. If there is more than one suspect blade, you must reseat each suspect blade one at a time. This step helps eliminate the possibility of loosely connected blades. For information about reseating the blades, refer to the respective platform guides:

Impact of procedure: Depending on the configuration of your VIPRION chassis, reseating a blade may disrupt traffic processing, and F5 recommends that you perform the procedure during a maintenance window.

  • The About installing blades section under the Platform Installation chapter of the Platform Guide: VIPRION 4800
  • The About installing blades section under the Platform Installation chapter of the Platform Guide: VIPRION 4400
  • The About installing blades section under the Platform Installation chapter of the Platform Guide: VIPRION 2400
  • The About installing blades section under the Platform Installation chapter of the Platform Guide: VIPRION 2200

After reseating each blade, you must perform the Verifying the status and speed of the internal interfaces procedure to determine if the VIPRION chassis is still reporting the internal interfaces as down or uninitialized, or incorrect media settings. If the VIPRION chassis continues to report the same symptoms, proceed to the next procedure.

Procedure back out: None

Rebooting the VIPRION chassis

If reseating the suspect blade does not clear the symptoms, proceed to reboot the entire VIPRION chassis. To do so, perform the following procedure:

Impact of procedure: If the VIPRION system is the active member of a redundant system, rebooting causes a failover. If the VIPRION system is a standalone unit, rebooting interrupts traffic processing.

  1. Log in to the command line of the primary blade on the affected VIPRION chassis.
  2. To reboot the VIPRION chassis, enter the following command:

    clsh reboot

  3. Wait for the VIPRION system to reboot each blade.
  4. When the VIPRION system has completed the reboot, log in to the command line.
  5. Perform the Verifying the status and speed of the internal interfaces procedure to determine if the VIPRION chassis is still reporting the internal interfaces as down or uninitialized, or reporting incorrect media settings. If the VIPRION chassis continues to report the same symptoms, proceed to the next procedure.

Procedure back out: None

Running the EUD on the VIPRION blade

If rebooting the entire VIPRION chassis does not clear the symptoms, proceed to run the End-User Diagnostics (EUD) on the suspect blades. For instructions about obtaining, installing, and running the EUD relevant for your suspect blade, refer to the following links in the Installing the software section of the current EUD release note:

  • Field Testing BIG-IP and BIG-IQ Hardware: 2000, 4000, 5000, 7000, 10000, 12000, and BIG-IQ 7000

Impact of procedure: To run the EUD, you must make sure that the VIPRION chassis is offline, and you must perform the procedure during a maintenance window.

Note: You must adhere to the specific requirements for running EUD on a VIPRION blade to prevent any possible false positives for the Internal Packet Path Test. For more information, refer to K12942: The EUD Internal Packet Path Test may generate false positive results on VIPRION platforms.

After running the EUD on the suspect blade, you should compare the EUD report with the output from the Verifying the status and speed of the internal interfaces procedure. Proceed to the next procedure to determine the source of the hardware issue.

Procedure back out: None

Switching the suspect blade between slots

To determine if the issue is with the blade or the chassis, you must switch the suspect blades between chassis slots. To do so, perform the following procedure:

Impact of procedure: Switching blades in a VIPRION chassis will disrupt traffic processing and you must perform the procedure during a maintenance window.

  1. To determine a suitable slot to switch the suspect blades, review the chassis and blades interconnect table in K13306: Overview of the manner in which the VIPRION chassis and blades interconnect.

    For example, the internal interface 1/5.1 is reported as down on blade 1 in a VIPRION 2400 chassis. Because this interface 1/5.1 interconnects to 2/5.1 through the backplane, the suitable slots available are slots 3 and 4.

  2. Switch the blades as determined in the previous step.
  3. Verify whether the chassis continues to report the internal interfaces as down or uninitialized, or continues to report incorrect media settings in the different slot by performing the Verifying the status and speed of the internal interfaces procedure.
    • If the internal interfaces are up with the correct media settings, then switch the suspect blade back to its original slot to confirm that the internal interface is reported as down or uninitialized, or that the incorrect media settings are in the original slot. Once you have determined this, contact F5 Support for further troubleshooting steps.

      For example, the internal interface 1/5.1 was reported as down on the blade while it was in slot 1. After the switch to slot 3, the same internal interface is now 3/5.1 and is reported as up with the correct media settings. However, switching the blade back to slot 1 results in internal interface 1/5.1 reporting as down again.

    • If the internal interfaces are reported as down or uninitialized; or have incorrect media settings, then the internal interfaces on the suspect blade and its corresponding peer may be faulty. To further troubleshoot this, replace the suspect blade with a spare blade or another blade that has been determined to exhibit no similar symptoms, and verify whether the replacement blade reports the same internal interfaces as down or uninitialized; or with incorrect media settings. If the replacement blade reports no similar symptoms, contact F5 Support for further troubleshooting steps.

      For example, the internal interface 1/5.1 was reported as down on the blade while it was in slot 1. After the switch to slot 3, the same internal interface is now 3/5.1 and continues to be reported as down. Replace this suspect blade with a spare blade that has been determined to have no faulty internal interfaces. If the replacement blade, which is now in slot 3, reports no faulty internal interfaces, then contact F5 Support for further troubleshooting steps.

      If the replacement blade reports the same internal interfaces as down or uninitialized, or with incorrect media settings, then switch the replacement blade with the suspect blade and re-verify the internal interfaces on the suspect blade. If the internal interfaces continue to exhibit similar symptoms, then contact F5 Support for further troubleshooting steps.
