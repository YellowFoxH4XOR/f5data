Description

BIG-IP ASM systems may encounter persistent "ASM out of memory error: event code P309" messages, resulting in transaction failures and potential service impact. Typical log entries include:

emerg perl[<pid>]: 01310003:0: ASM out of memory error: event code P309
IO_PLUGIN|ERR |trans_open: Not enough UMU memory to start a new trans.

This issue can occur even after increasing the ASM memory allocation.

Environment

  • ASM provisioned
  • System variable ecard_max_http_req_uri_len set to a very high value (e.g., 4,847,717 bytes)

Cause

Setting the ecard_max_http_req_uri_len system variable to an excessively large value causes the BD (blocking daemon) process to allocate a large buffer for every HTTP request URI—regardless of actual URI length. This leads to rapid consumption of UMU (User Memory Unit) memory and results in repeated out-of-memory errors and possible BD process crashes.

Recommended Actions

Steps that can be taken to reduce the memory consumption by bd:

  • Reduce the value of ecard_max_http_req_uri_len:
    • Default is 2048 bytes.
    • If required for business needs, increase only moderately (e.g., up to 4096 or 8192 bytes).
    • Avoid setting this value significantly higher due to severe memory impact.
  • Note that changing this variable requires an ASM restart; plan this change during a maintenance window as it will cause brief service interruption.
  • After reducing the value, monitor BD/UMU memory utilization for stability.
  • If requests with URIs longer than 8KB must be allowed, consider disabling the related protocol compliance sub-violation—but be aware this reduces some protections.
  • Review and disable "Learn from responses" in security policies if not required, as it increases system load and memory usage.
  • You can consider increasing UMU memory which can provide more headroom for ASM to handle traffic, but it does not address the root cause if there is an underlying configuration issue causing excessive memory allocation. This can be done by allocating memory to variable  total_umu_max_size.
