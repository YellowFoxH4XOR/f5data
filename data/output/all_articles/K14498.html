Known Issue

The mcpd connection with the Traffic Management Microkernel (TMM) may time out and cause TMM to restart.

This issue occurs when all of the following conditions are met:

  • The platform is running 12 or more TMM instances.
  • One of the following behaviors occur:
    • The mcpd process loads a large configuration with thousands of objects, either during startup or a manual configuration load.
    • You run the tmsh show sys connection command with a large connection table.

      Note: This issue may occur when the connection table has 600,000 connections.

The mcpd process is the BIG-IP messenger daemon that allows other processes to communicate with TMM. When loading a large configuration on a platform that has several TMM instances, the number of messages that the system publishes to the mcpd process may exceed the available connection buffer that the system uses to service the MCP connections with the TMM instances. As a result, the MCP connection with a TMM may experience a zero-window-timeout, end, and cause TMM to restart.

Impact

Traffic processed by the affected TMM instance is interrupted while TMM restarts. TMM may restart multiple times.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H424331 on the Diagnostics > Identified > High screen.
  • During startup, or when loading a large configuration, TMM restarts without producing a core file.
  • While running the tmsh show sys connection command with a large connection table, TMM restarts without producing a core file.
  • The system logs an error message to the /var/log/ltm file that appears similar to the following example:

  • LTM01 crit tmm11[28599]: 01010020:2: MCP Connection aborted, exiting

  • The system logs an error message to the /var/log/daemon file that appears similar to the following example:

    LTM01 emerg logger: Re-starting tmm

  • TMM enters a restart loop and restarts multiple times.

Resolution

Status

F5 Product Development has assigned ID 422460 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Note: The released fixes increase an internal buffer to provide sufficient time for most configurations. However, some configurations may require more time even after installing the released fix. If this occurs, in addition to installing the released fix, you may have to perform the workaround to increase the zero_window_timeout setting appropriate for your environment.

Workaround

To mitigate this issue, you can increase the time-out used for the MCP connection by adding a zero_window_timeout 300000 setting to the profile tcp _mcptcp stanza in the tmm_base.tcl file. To do so, perform the following procedure:

Impact of workaround: This workaround requires that you restart TMM, which will interrupt traffic processing. You will also be required to temporarily remount the /usr file system in read-write mode.

  1. Log in to the BIG-IP command line.
  2. To remount the /usr file system in read-write mode, type the following command:

    mount -o remount,rw /usr

  3. To change to the /usr/lib/tmm directory, type the following command:

    cd /usr/lib/tmm

  4. To back up the original tmm_base.tcl file, type the following command:

    cp tmm_base.tcl tmm_base.tcl.sol14498

  5. Edit the tmm_base.tcl file in a text editor.
  6. Locate the profile tcp _mcptcp stanza, which appears similar to the following example:

    profile tcp _mcptcp {
        time_wait_recycle enable
        delayed_acks enable
        selective_acks enable
        slow_start disable
        nagle disable
        ack_on_push enable
        keep_alive_interval 20
        sndbuf 4194304
        rcvwnd 4194304
        congestion_ctrl 3
        syn_maxrtx 3
        maxrtx 4
        fin_wait_timeout 5
        close_wait_timeout 5
    }

  7. Add the zero_window_timeout 300000 entry.

    Note: The value of 300000 for the zero_window_timeout setting is a suggested guide that will work for most environment. However, you may have to increase this value as needed to suit your application environment.

    For example:

    profile tcp _mcptcp {
        time_wait_recycle enable
        delayed_acks enable
        selective_acks enable
        slow_start disable
        nagle disable
        ack_on_push enable
        keep_alive_interval 20
        sndbuf 4194304
        rcvwnd 4194304
        congestion_ctrl 3
        syn_maxrtx 3
        maxrtx 4
        fin_wait_timeout 5
        close_wait_timeout 5
        zero_window_timeout 300000
    }

  8. Save the /usr/lib/tmm/tmm_base.tcl file.
  9. To remount the /usr file system in read-only mode, type the following command:

    mount -o remount,ro /usr

  10. To restart TMM, type the following command:

    bigstart restart tmm
