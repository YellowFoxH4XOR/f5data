Description
In HTTP 1.1 and earlier, the Content-Length header indicates the size in bytes of a payload that is received by a server (as in a POST request) or received from a server (as in a GET request).

Environment

  • BIG-IP LTM / ASM
  • HTTP Profile
  • Content-Length HTTP header

Cause
This is informational.

Recommended Actions
The following steps may help confirm the value of the Content-Length header by manually calculating the number of bytes in a request or response body:

  1. Obtain a packet capture that includes HTTP data (such as by specifying "-s0" in tcpdump).
  2. When viewing the packet capture in a tool such as Wireshark, display the HTTP request or response in a raw (hexadecimal) format (This can be accomplished in Wireshark using the "Follow TCP Stream" or "Follow HTTP Stream" option then selecting "Show data as: Raw"). Bytes are represented by two hexadecimal digits. For example, the ASCII text "F5" appears as "4635" in hexadecimal.
  3. Identify the specific request or response whose body you'd like to measure (In Wireshark, by default, requests and responses are contrasted in red and blue text colors within the Stream window). It may be helpful to first view the requests and responses in standard (ASCII) format.
  4. The HTTP headers section of a request or response ends with an empty line (carriage return and line feed) represented by the bytes, "0d0a0d0a". Therefore you can count the bytes that occur after "0d0a0d0a" to measure the content length of a body.

    For example:
    HTTP/1.1 200 OK
    Server: nginx
    Content-Type: text/plain
    Content-Length: 6

    Hello!

    The response above may appear as the following bytes: (The carriage return and line feed separating the HTTP headers with the HTTP body have been underlined.)

    485454502f312e3120323030204f4b0a5365727665723a206e67696e780a436f6e74656e742d547970653a20746578742f706c61696e0a436f6e74656e742d4c656e6774683a2036
      0d0a0d0a48656c6c6f21

      The bytes after "0d0a0d0a" will be used to calculate the content length. As bytes are represented with two hexadecimal digits, one can divide the number of digits by two to obtain the content length (There are 12 hexadecimal digits in "48656c6c6f21" which equates to six bytes, as indicated in the header "Content-Length: 6" sent from the server). While one may have merely counted the characters in the string, "Hello!", HTTP bodies frequently include non-printable characters (such as spaces and line-endings), compressed payloads, and other data.
