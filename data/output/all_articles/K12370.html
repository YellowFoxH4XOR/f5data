Known Issue

When you enable connection or persistence mirroring on a BIG-IP high availability pair, and connectivity to the standby system's stateful mirroring address is interrupted, the active unit stores in memory the changes made to the connection and persistence tables. Once the standby system's mirroring address is reachable, the active unit pushes those changes to the standby unit. Since the changes stored in memory are not cleared, even if the corresponding entries are removed from the connection and persistence tables, the active unit must use increasingly more memory the longer the standby system's mirroring address is inaccessible. This may lead to performance degradation on the active unit, including eventual memory exhaustion and the Traffic Management Microkernel (TMM) process dumping core. This issue may also be seen if no mirroring addresses are configured or if mirror addresses are misconfigured.

Note: Since the iRule session command uses the persistence table, the information in this Solution also applies to iRules that use the session command.

F5 Product Development tracked this issue as ID 247874 (formerly CR13661) and it was fixed in BIG-IP version 11.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.4-655.0-HF4, which has been issued for BIG-IP 10.2.4. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes (10.x).

Workaround

If a standby unit will be offline for a period of time, and connection or persistence mirroring is enabled, F5 recommends that you disable session mirroring and persistence mirroring until the standby unit is back online. To disable mirroring on the active unit once the standby unit is offline, perform the following procedure:

Version 11.0.0

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh utility, you can skip this step.

  2. To verify whether session mirroring is enabled, enter the following command:

    list /sys db statemirror.mirrorsessions

  3. To disable session mirroring, you must modify the StateMirror.MirrorSessions database key by typing the following command:

    modify /sys db statemirror.mirrorsessions value disable

  4. To disable persistence mirroring from an active persistence profile, use the following syntax:

    modify /ltm persistence <persistence type> <profile name> mirror disabled

    For example, to disable persistence mirroring from a hash persistence profile named MyHash, you would enter the following command:

    modify /ltm persistence hash MyHash mirror disabled

  5. Repeat step 4 for any other configuration objects that have persistence mirroring enabled.
  6. Save the change by typing the following command:

    save /sys config

Versions 10.1.0 HF1, 10.2.0, and later

  1. Log in to the command line with root privileges.
  2. To verify whether session mirroring is enabled, enter the following command:

    bigpipe db StateMirror.MirrorSessions

  3. To disable mirroring, you must modify the StateMirror.MirrorSessions dbatabase key by typing the following command:

    bigpipe db StateMirror.MirrorSessions disable

  4. Once the standby unit is back online, to re-enable mirroring, you must modify the same db key by typing the following command:

    bigpipe db StateMirror.MirrorSessions enable

  5. To disable persistence mirroring from an active persistence profile, use the following syntax:

    bigpipe profile persist <profile name> mirror disabled

    For example, to disable persistence mirroring from a hash persistence profile named MyHash, you would enter the following command:

    bigpipe profile persist MyHash mirror disabled

  6. Repeat step 5 for any other configuration objects that have persistence mirroring enabled.
  7. Save the change by typing the following command:

    bigpipe save

Versions 10.1.0 (no hotfixes) and earlier

  1. Log in to the command line with root privileges.
  2. To verify whether session mirroring is enabled, enter the following command:

    bigpipe db StateMirror.State

  3. To disable mirroring, you must modify the StateMirror.State database key by typing the following command:

    bigpipe db StateMirror.State disable

  4. Once the standby unit is back online, to re-enable mirroring, you must modify the same database key by typing the following command:

    bigpipe db StateMirror.State enable

  5. To disable persistence mirroring from an active persistence profile, use the following syntax:

    bigpipe profile persist <profile name> mirror disabled

    For example, to disable persistence mirroring from a hash persistence profile named MyHash, you would enter the following command:

    bigpipe profile persist MyHash mirror disabled

  6. Repeat step 5 for any other configuration objects that have persistence mirroring enabled.
  7. Save the change by typing the following command:

    bigpipe save
