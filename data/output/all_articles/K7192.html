K7192: The BIG-IP LTM system does not increment the server-side sequence number for certain HTTP POST data for fasthttp profile connections

Known Issue

This is the result of a known issue. When a client sends a POST request to a fasthttp virtual server with the POST body in a separate packet from the HTTP headers, the server replies with a single ACK packet in response. The next packets sent to the virtual server on that connection will not have their server-side TCP sequence numbers incremented properly by the BIG-IP system, causing the session to stall.

F5 Product Development tracked this issue as CR74825, and it was fixed in BIG-IP LTM 9.1.3, 9.3, and 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.
