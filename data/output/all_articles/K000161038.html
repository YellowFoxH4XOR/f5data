K000161038: Config processor TimeoutException during Guided Configuration API Security deployment on BIG-IP 21.0.0

Type
Support Solution
Published
2026-05-09
Updated
2026-05-09
Applies to
  • BIG-IP
  • BIG-IP ASM: 21.0.0
Source
https://my.f5.com/manage/s/article/K000161038

Description

Error message appears when deploying a second API Security Protection using Guided Configuration on BIG-IP Advanced WAF 21.0.0:

Config processor is not available: java.util.concurrent.TimeoutException: Unavailable: http://localhost:8100/mgmt/shared/iapp/processors/waf-openapispec-api-protection

  • The first deployment typically succeeds, but subsequent deployments fail with this error.
  • Increasing provision.extramb alone does not resolve the issue.
  • The error is consistent with insufficient management plane memory for Guided Configuration operations.

Environment

  • Product: BIG-IP Advanced WAF
  • Version: 21.0.0
  • High Availability (HA) pair
  • Guided Configuration for API Security Protection
  • Initial sys db values:
    • provision.extramb = 4096
    • provision.restjavad.extramb = 2048
    • provision.tomcat.extramb = 512

Cause

Insufficient JVM heap memory allocated to the restjavad process for Guided Configuration operations. The value of provision.restjavad.extramb directly controls the heap size, and the default or previously set value may be inadequate for multiple deployments.

Answer/Recommended Actions

  1. Increase restjavad Heap Memory
    On each BIG-IP unit, run:
    tmsh modify sys db provision.restjavad.extramb value 3200
    bigstart restart restjavad
    sleep 20
    bigstart restart restnoded
    Verify the new heap size:
    grep -i "Heap size" /var/log/ltm | tail -5
    You should see output similar to:

    Maximum JVM heap size is 3200 MB and Minimum heap size is 3200 MB

  2. Apply Changes Individually
    These settings do not sync between HA peers. Repeat the above steps on each unit.
  3. Retry Deployment
    After confirming the heap size increase, retry the API Security Protection deployment.
  4. If Issue Persists
    Check for stuck iApp blocks:
    restcurl /mgmt/shared/iapp/blocks -u admin:admin | jq '.items[] | select(.state == "ERROR" or .state == "BINDING") | {id, name, state}'
    Remove or correct any blocks in ERROR or BINDING state as appropriate.
    Restart REST services:
    bigstart restart restjavad
    sleep 20
    bigstart restart restnoded
  5. Collect Logs for Further Troubleshooting
    If the error continues, collect:
    tail -300 /var/log/restjavad.0.log
    tail -300 /var/log/restnoded
    tail -200 /var/log/restjavad-gc.log.0.current

Additional Information

  • Increasing provision.extramb alone does not affect the JVM heap size for restjavad on BIG-IP 21.0.0. The heap is controlled solely by provision.restjavad.extramb.
  • Do not exceed 4000 MB for provision.restjavad.extramb without further consultation.
  • Always perform these changes during a maintenance window, as service restarts are traffic-impacting and may trigger HA failover.
