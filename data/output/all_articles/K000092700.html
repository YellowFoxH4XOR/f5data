K000092700: Virtual server resest connections after modifying tcp profile with verified-accept enabled

Type
Support Solution
Published
2022-11-23
Updated
2022-11-23
Source
https://my.f5.com/manage/s/article/K000092700

Description

  • After modifying tcp profile with verified-accept enabled. Virtual server with iRules applied starts breaking the connections
  • On packet capture you can see the reset packet sent from BIG-IP with the reason "address in use"

Environment

  • BIG-IP LTM
  • Customer tcp profile
  • verified-accept enabled
  • VIrtual server with iRules assigned

Cause

Enabling Verified Accept changes the normal sequence of client and server events in the proxying of the connection. For example, LB_.* and SERVER_CONNECTED events fire before L7 events. Given the potential complexity and power of iRules to implement solutions, it is not possible to ensure that iRules executed when Verified Accept is enabled will operate as expected.


Recommended Actions

Depending on the content of your iRules you might need to change the order of some events so that they work as you expect.
