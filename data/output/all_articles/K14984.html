Known Issue

Modifying the interface resources on a VLAN does not immediately take effect.

This issue occurs when all of the following conditions are met:

  • The system is running the BIG-IP Virtual Edition (VE).
  • A VLAN is configured with at least one interface.
  • The interface is changed from tagged to untagged (or untagged to tagged).
  • The VLAN ID is not changed.

This issue affects only a VLAN when you move a previously added interface from tagged to untagged (or untagged to tagged). For example, if you have previously added an interface as tagged to a VLAN and move it to untagged, the change does not take effect until you restart the Traffic Management Microkernel (TMM) process.

Impact

Traffic may not flow as expected until you restart the TMM process.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After changing the interface tag attributes on a VLAN, traffic flow is not affected.
  • The interface tagged attributes on a VLAN do not take effect until you restart the TMM process.

Workaround

To work around this issue, you can restart the TMM process after modifying the interface tag attributes. To do so, perform the following procedure:

Impact of workaround: Restarting TMM interrupts traffic processing; you should perform this procedure in a maintenance window. If the system is configured as part of a high-availability pair, the device may fail over.

Restarting the TMM process

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the TMM process by typing the following command:

    restart /sys service tmm
