Description

You are attempting to reconfigure or upgrade an iApp. The error "The access policy item <name> is not referenced by any existing access policy" is observed from the logs.

Environment

  • iApp-deployment integrating APM parameters

Cause

You have disabled "Strict Updates" and made manual changes to various iApp generated objects.
The extent of the changes exceeds the ability of the iApp to reconfigure.

Recommended Actions

  1. The iApp must be manually deleted and recreated.
  2. In many cases, making changes to iApp objects can be avoided by creating them manually beforehand, then telling the iApp to use them.
  3. Ensure that Device Configuration autosync is disabled so changes will not propagate until you have recreated the iApp and proved it works correctly.
  4. Take UCS archives on all devices.
  5. Take and download a Support snapshot (QKView)
  6. Take screenshots of the configuration settings. If using HA, the peer device iApp settings can be used a guide (two tabs in your browser)
  7. Iterate through, manually deleting iApp created  objects and attempting to delete the iApp.
  8. Use the error messages displayed and the "Objects" listing in the iApp  as a  guide.
  9. Start by deleting the Virtual Servers.
  10. When it is deleted, redeploy the iApp
