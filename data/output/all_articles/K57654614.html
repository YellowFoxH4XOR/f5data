Known Issue

When you carry forward a configuration from a previous version, files may have the incorrect user ID (UID) associated with them.

This issue occurs when all of the following conditions are met:

  • As an administrator, you use an account other than the root account to create a /.ssh/authorized_keys file in your home directory.
  • You roll forward a configuration through an upgrade or using the cpcfg utility.

The sshd process will not use a key file if the active user ID does not match the user ID of the key file.

Note: This issue may also affect other files that are backed up and carried forward during an upgrade.

Impact

SSH access to the host may fail when you attempt to log in as an administrator without using the root account.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The /.ssh/authorized_keys file has a non-zero UID.
  • SSH sessions to your BIG-IP system may fail.

Workaround

To work around this issue, you can manually change the UID of the /.ssh/authrized_keys file after upgrade. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Advanced Shell (bash) as the root user.
  2. Use the following command syntax:

    chown 0 /home/<user>/.ssh/authorized_keys

    Note: Replace <user> with the administrator username instead of the root account username.
