Description

The BIG-IP can be overloaded with a sudden increase in SSL connections, which cause tmm to crash due to memory allocation failures. 

High CPU and memory usage correlates with high SSL connections can be seen in the Utilization Graphs.

tmm restarts and tmm core file generated and notice related to memory allocation can be generated in /var/log/tmm log:

notice panic: unable to alloc 88 bytes
notice ** SIGFPE **

Environment

  • BIG-IP
  • Increasing SSL traffic and amount of new connection
  • Increasing CPU and memory utilization
  • Unlimited SSL TPS license
  • TMM restarts

Cause
 
System is overloaded with SSL connections.  Each platform has a CPU and memory limitation.

Recommended Actions

Refer to K83167850: Defining a specific limit for the number of active SSL handshakes allowed by the system

Additional Information

See platform data sheet to set the proper value for the global number of active SSL handshakes. The tmm.ssl.maxactivehandshakes value should be less than the maximum number of active SSL handshakes supported for your platform.
