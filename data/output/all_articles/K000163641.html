Description

NGINX Plus logs a critical error indicating an event loop stall when a synchronous njs-based Prometheus metrics handler blocks a worker process:

[crit] event loop was stalled for XXXX ms

Disabling the njs-based /metrics endpoint stops the error, but removes Prometheus metrics collection.

Environment

  • NGINX Plus
  • Prometheus-njs module configured for Prometheus metrics generation:

js_import /path/to/prometheus.js;


location = /metrics {
    js_content prometheus.metrics;
}

Cause

The njs metrics handler executes synchronously inside the NGINX worker process. Gathering, parsing, and formatting metrics consumes sufficient CPU time to block the worker event loop, delaying client request processing until metrics generation completes.

Recommended Actions

Deploy the standalone NGINX Prometheus Exporter service instead of generating Prometheus metrics synchronously through prometheus-njs. This offloads metrics collection, parsing, and formatting outside the NGINX worker event loop.

  1. Enable the read-only NGINX Plus API
    Configure a local, read-only NGINX Plus API endpoint and restrict access to authorized sources:

    server {
        listen <LOCAL_IP_ADDRESS>:8080;

        location /api {
            api write=off;
            allow <LOCAL_IP_ADDRESS>;
            deny all;
        }
    }

    Validate and reload the NGINX configuration:

    sudo nginx -t
    sudo nginx -s reload

  2. Install the NGINX Prometheus Exporter
    Download the official release tarball for your system architecture, extract the binary, and install it to /usr/local/bin/:

    (You can find the latest nginx-prometheus-exporter release tarball at https://github.com/nginx/nginx-prometheus-exporter/releases)

    tar -zxvf nginx-prometheus-exporter_<VERSION>_linux_amd64.tar.gz
    sudo mv nginx-prometheus-exporter /usr/local/bin/
    sudo chmod 755 /usr/local/bin/nginx-prometheus-exporter
    sudo restorecon -v /usr/local/bin/nginx-prometheus-exporter

  3. Create a dedicated system account
    Create an unprivileged system user for the exporter service:

    sudo useradd --system --no-create-home --shell /sbin/nologin nginx_exporter

  4. Create the systemd service file
    Create /etc/systemd/system/nginx-prometheus-exporter.service with the following configuration:

    [Unit]
    Description=NGINX Prometheus Exporter
    After=network.target nginx.service

    [Service]
    Type=simple
    User=nginx_exporter
    Group=nginx_exporter
    ExecStart=/usr/local/bin/nginx-prometheus-exporter \
      --nginx.plus \
      --nginx.scrape-uri=http://<LOCAL_IP_ADDRESS>:8080/api
    Restart=always
    RestartSec=5s
    ProtectSystem=strict
    ProtectHome=true
    PrivateTmp=true

    [Install]
    WantedBy=multi-user.target

  5. Start and enable the exporter service
    Reload the systemd manager configuration, enable, and start the service:

    sudo systemctl daemon-reload
    sudo systemctl enable --now nginx-prometheus-exporter
    sudo systemctl status nginx-prometheus-exporter

    Verify the metrics endpoint (default port 9113):

    curl http://<EXPORTER_HOST>:9113/metrics

    A valid response returns standard Prometheus metrics starting with # HELP and # TYPE.

  6. Configure Prometheus scrape targets
    Update prometheus.yml to scrape the exporter endpoint:

    scrape_configs:
      - job_name: "nginx-plus"
        scrape_interval: 15s
        static_configs:
          - targets:
              - "<EXPORTER_HOST>:9113"

  7. Remove the legacy njs metrics endpoint
    After verifying that Prometheus scrapes metrics successfully, remove the njs-based /metrics block from the NGINX configuration and reload NGINX:

    location = /metrics {
        js_content prometheus.metrics;
    }

Additional Information

  • The stall_threshold directive configures the duration threshold for logging event-loop stall warnings; modifying it does not eliminate the underlying blocking workload.
  • Setting js_engine qjs; may improve execution performance in some environments, but does not eliminate synchronous execution within the worker thread.
  • An event-loop stall message indicates worker processing latency; it does not indicate a process crash or worker failure.
  • If event-loop stalls persist after offloading metrics collection, investigate third-party modules, synchronous health checks, or blocking network/DNS calls.
