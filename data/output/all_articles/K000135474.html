Description

Tenant stops receiving traffic, there is no evidence resource exhaustion. 
There is no specific virtual server affected, but overall traffic is not sending out.
You may observe some drops on particular tmm(s) only.
Similar to the below messages are logged on /var/log/tmm* on those tenants affected.

notice CLNG|EROR|set_orig_referer_cookie:2217|Failed to extract referrer
notice ipsec_ha_unit_mask_changed/194: PFKDB: Box becames STANDBY

 

When issue is started, similar to the below messages are logged in

F5OS-A : /var/F5/system/log/platform.log
F5OS-C (Blade): /var/F5/partition/log/velos.log

dma-agent[16]: priority="Alert" version=1.0 msgid=0x4201000000000129 msg="Health monitor detected DM Tx Action Completion ring hung." ATSE=1 DM=2 OQS=3.
dma-agent[16]: priority="Info" version=1.0 msgid=0x4201000000000135 msg="Health monitor DM register dump requested.".
dma-agent[16]: priority="Info" version=1.0 msgid=0x4201000000000137 msg="Health monitor DM register dump complete." FILE="agent-dump-1687423450.txt".

 

Environment

  • rSeries / Velos
  • F5OS-A / F5OS-C
  • Tenant
  • Random traffic failure for any virtual servers.
  • Mirroring also affecting.

Cause

  • Bug ID 1128765

Recommended Actions

Check the stats running commands Bug ID 1128765, if this is applying to your unit, then reboot.
Also consider upgrade to fixed version.

If this is not applied, then please escalate the case to F5 Support gathering qkviews from F5OS (Controller/Partition/rSeries) and Tenants.
