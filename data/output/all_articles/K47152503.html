Known Issue

The Traffic Management Microkernel (TMM) may restart when an iRule containing Bot Defense commands is enabled on a virtual server.

This issue occurs when all the following conditions are met:

  • The virtual server is configured with the following:
    • HTTP profile
    • HTTP Compression profile
    • Web Acceleration profile
    • DoS profile
    • iRule containing Bot Defense commands

      Note: You must enable proactive Bot Defense in the DoS profile to use Bot Defense commands in an iRule.

  • The virtual server receives traffic that triggers a Bot Defense iRules event.

Impact

The system interrupts traffic processing while TMM restarts, and a failover event occurs if the BIG-IP system is in a Device Service Clustering (DSC) configuration.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H716778 on the Diagnostics > Identified > Medium page.
  • Your BIG-IP system fails to process traffic for a brief period.
  • Your BIG-IP system fails over to another system in the device group.
  • TMM produces a core file in the /var/core directory.
