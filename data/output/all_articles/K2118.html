K2118: Reasons why SSL proxies fail if the sysctl variable net.inet.ip.sourcecheck is enabled

Topic

If the sysctl net.inet.ip.sourcecheck variable is set to 1, BIG-IP attempts to perform route lookups for each connection. If the interface address is not a direct route, the BIG-IP will perform a route lookup on the source IP. Since the SSL proxy changes the route's destination address to the loopback virtual server address, the route lookup to the source IP will fail. This causes BIG-IP to drop the packet, thereby breaking the connection.

If this is occurring, you will receive messages similar to the following:

Aug 8 01:58:00 bigip1 kernel: packet from x.x.x.x to y.y.y.y proto z received on A; expected B

Where x.x.x.x and y.y.y.y are actual IP addresses, Z is a number, usually either 6 or 17 (TCP or UDP respectively), and A or B is an interface name, like lo0, or vlanX (where X is a number ranging from 1 to 255).

For example:

Aug  8 01:58:00 bigip1 kernel: packet from 169.204.56.4 to 205.229.151.10
 proto 6 received on lo0; expected vlan1

To correct this issue, disable net.inet.ip.sourcecheck by changing the variable to 0. To do this, perform the following steps:

  1. Open the /etc/rc.sysctl file and search for the following line:

    sysctl -w net.inet.ip.sourcecheck=1

  2. Change the line to read:

    sysctl -w net.inet.ip.sourcecheck=0

  3. Save and close the /etc/rc.sysctl file.
  4. Type the following command:

    sh /etc/rc.sysctl

  5. Type the following command to confirm that net.inet.ip.sourcecheck has disabled:

    sysctl -a | grep sourcecheck

    You should see the following:

    net.inet.ip.sourcecheck = 0

    If net.inet.ip.sourcecheck is still set to 1, contact F5 Technical Support.
